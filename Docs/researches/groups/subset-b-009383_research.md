# sources/test-tools/stress-ng/stress-syscall.c

Purpose: implements the `syscall` stressor, a broad timing and throughput benchmark that exercises a large compile-time-selected table of system call wrappers. It uses safe local fixtures, short-lived children, temporary files, sockets, IPC objects, timers, memory mappings, and signal handlers to measure individual call latency (`t1`/`t2`) and full wrapper cost, then filters to the fastest or geomean-selected non-failing calls for the main stress loop.

Important APIs/types/functions: central types are `syscall_method_t`, `syscall_rank_t`, `syscall_func_t`, `syscall_t`, `syscall_shared_info_t`, and `syscall_stats_t`. Global fixture state includes `syscall_filename`, `syscall_tmp_filename`, `syscall_symlink_filename`, `syscall_fd`, `syscall_dir_fd`, `syscall_2_pages`, `syscall_mmap_page`, `syscall_brk_addr`, saved uid/gid/pid/session/umask/current-directory data, and the shared child timing page. Timing and ranking helpers are `syscall_time_now`, `syscall_shared_error`, `stress_syscall_reset_index`, `stress_syscall_reset_ignore`, `stress_syscall_shuffle_calls`, `stress_syscall_rank_calls_by_sort`, `stress_syscall_rank_calls_by_geomean`, `stress_syscall_rank_calls`, `stress_syscall_benchmark_calls`, and `stress_syscall_report_syscall_top`. `syscall_socket_measure` is a generic AF_UNIX parent/child benchmark for `accept`, `accept4`, `bind`, `connect`, `listen`, send/receive variants, `getpeername`, and `shutdown`. Signal helpers are `syscall_sigsegv_handler` and `syscall_sigusr1_handler`; `sigsetjmp` protects the benchmark loop from syscall tests that fault.

Control flow: `stress_syscall` resolves settings (`syscall-method`, `syscall-rank`, `syscall-top`), captures process identity and cwd, installs SIGSEGV/SIGUSR1/SIGXFSZ handlers, creates a stress-ng temp directory, opens a fixture file, writes two pages of randomized data, creates an optional symlink, maps shared timing state, and initializes per-syscall stats. After stress-ng synchronization it first benchmarks every non-ignored call once to identify calls that succeed and to capture maximum wrapper duration. It then ranks/filters by method: all, fastest 10/25/50/75/90 percent by wrapper duration, or geomean thresholds scaled 1/2/3. The main loop repeatedly calls `stress_syscall_benchmark_calls`, shuffles the syscall index, and stops on the common stress-ng continue/time-end checks. Instance zero reports how many calls were exercised and prints a configurable top-N timing table.

The syscall wrappers are grouped around real kernel interfaces: filesystem and descriptor calls (`open`, `openat`, `creat`, `close`, `dup*`, `stat*`, `chmod*`, `chown*`, `truncate`, `ftruncate`, `link*`, `symlink*`, `rename*`, `unlink*`, xattrs); buffered and vector I/O (`read`, `write`, `pread*`, `pwrite*`, `readv`, `writev`, `sendfile`, `copy_file_range`, `readahead`, `splice`, `tee`, `vmsplice`); memory and NUMA (`brk`, `mmap`, `munmap`, `mremap`, `mprotect`, `msync`, `mlock*`, `mincore`, `madvise`, `mbind`, `move_pages`, `migrate_pages`, `memfd_create`, `map_shadow_stack`, `userfaultfd`); process, signal, and scheduler APIs (`fork`, `vfork`, `clone`, `clone3`, `execve`, `execveat`, `exit`, wait variants, `kill`, `pause`, `sigsuspend`, `sigaction`, `sigaltstack`, `signalfd`, `sigprocmask`, `sched_*`, `set*uid/gid`, `setsid`, `setpgid`, `get*id`, `prctl`, `seccomp`, `rseq`); time and timer APIs (`clock_gettime`, `clock_getres`, `clock_nanosleep`, `clock_adjtime`, `clock_settime`, `nanosleep`, `gettimeofday`, `time`, `times`, POSIX timers, timerfd, itimers); IPC and message APIs (System V sem/shm/msg, POSIX mqueue, AIO, io_uring setup, eventfd, inotify/fanotify); and platform-specific direct syscalls such as keyrings, LSM attributes, `kcmp`, `lookup_dcookie`, `quotactl_fd`, RISC-V probes, ioperm/iopl, and cache flushes. Riskier or disruptive kernel interfaces are intentionally omitted in the table comments, including accounting, module load/unload, mount/pivot/root changes, reboot, swap, ptrace/perf interactions, deprecated sysfs/sysctl, and several time or hostname setters.

State and persistence behavior: the stressor creates only temporary files and symlinks under the stress-ng temp directory and removes them during cleanup. Most mutating wrappers restore state immediately: chmod/chown use saved uid/gid and reset modes; xattr calls remove test attributes; rename/link/symlink/unlink calls use the temp paths; rlimit, scheduler, pkey, timer, IPC, AIO, eventfd, inotify/fanotify, pipe/socket, and file-handle tests close or delete created resources. Some tests fork or clone to isolate side effects (`chroot`, `execve`, `exit`, wait-family calls, socket benchmark, `pause`, `sigsuspend`, `unshare`). `umask` is saved and restored, and cwd changes are restored to `syscall_cwd`. Persistent machine-wide effects are deliberately avoided where possible, though calls such as `sync`, `fsync`, `fdatasync`, `syslog`, keyring operations, quota sync, memory policy calls, and capability/system-time-sensitive setters can still interact with global kernel state or policy.

Dependencies and integration points: this file is heavily gated by build-time `HAVE_*`, architecture, libc, and kernel syscall-number macros. It depends on stress-ng core shims and helpers from `stress-ng.h`, `core-arch.h`, `core-cpu-cache.h`, `core-builtin.h`, `core-io-priority.h`, `core-signal.h`, and `core-clocks.h`; it also uses optional Linux headers for audit/filter/futex/io_uring/membarrier/mempolicy/rseq/seccomp/sysctl/userfaultfd, libaio, keyutils, POSIX mqueue, xattrs, fanotify/inotify, timerfd, SysV IPC, quota, and capabilities. It registers `stress_syscall_info` as `CLASS_OS` with options `syscall-method`, `syscall-rank`, and `syscall-top`; it uses stress-ng temp-dir, process-state, synchronization, random, metrics/logging, shim, and stress-loop infrastructure.

Risks: runtime behavior is intentionally platform- and privilege-sensitive. Many wrappers succeed only with capabilities or specific kernel features, while seccomp, namespaces, containers, LSMs, cgroups, rlimits, key quotas, IPC limits, syslog restrictions, and filesystem support can change success rates. The SIGSEGV long-jump path avoids process termination but means wrapper bugs may be recorded as skipped/segv rather than hard failures. Several tests fork/clone frequently and can hit PID or process limits. Some paths call `sync`/`fsync` or filesystem metadata operations and may perturb system I/O. The `syscall_mbind` wrapper references `syscall_pages_size`, while the file defines `syscall_page_size`; if that configuration path is compiled, it is a build risk unless another macro supplies the name. A few timing records depend on child/parent shared memory and signal delivery, so interrupted calls and scheduler delays can skew rankings.

Test signals: successful startup creates the temp directory, fixture file, data pages, shared timing mapping, and optional symlink. During execution, bogo ops increment once per wrapper attempt; instance zero logs the selected method, total compiled syscall tests, percentage exercised, and top fastest syscall table with average/min/max nanoseconds plus SIGSEGV notes. Failures surface as skip messages for temp/mmap/file setup, fewer successful/exercised calls, unexpectedly empty timing tables, persistent SIGSEGV annotations, or nonzero exit from resource setup. Good validation should cover multiple `--syscall-method` settings, `--syscall-rank`/`--syscall-top`, unprivileged and privileged/container runs, and builds with optional syscall families enabled.

# sources/test-tools/stress-ng/stress-sysfs.c

Purpose: implements the Linux `sysfs` stressor, recursively walking `/sys` and exercising readable sysfs files through open, read, zero-length read/write, mmap, select/poll/ppoll, lseek, ioctl, and a few controlled write probes. It is designed to stress kernel sysfs handlers while avoiding known-dangerous paths and adapting when accesses generate excessive kernel log output or fatal signals.

Important APIs/types/functions: `stress_ctxt_t` holds shared state for stressor args, `/dev/kmsg` fd, `CAP_SYS_ADMIN` status, current `sysfs_path`, and an opened-file counter. `stress_sysfs_wr_func_t` maps special writable paths to guarded handlers; currently `/sys/power/disk` writes `test_resume`. Key helpers are `path_sum`, `mixup_sort`, `stress_kmsg_drain`, `stress_sys_add_bad`, `stress_sys_bad`, `stress_sys_rw`, `stress_sys_rw_thread`, `stress_sys_skip`, `stress_sys_dir`, `stress_sysfs_bad_signal`, and `stress_sysfs`. Shared synchronization uses `shim_pthread_spinlock_t` locks for current path, open counter, and bad-path hash table.

Control flow: `stress_sysfs` maps a shared context, scans and prunes `/sys`, parses the kernel major/minor from `uname`, creates a hash table for bad paths, opens `/dev/kmsg` nonblocking, records whether the worker has `CAP_SYS_ADMIN`, initializes spinlocks, and enters the synchronized stress run. The main loop forks a child supervisor. The child starts up to four pthreads running `stress_sys_rw_thread`; these threads block signals and repeatedly operate on the current `ctxt->sysfs_path`. The child recursively traverses top-level `/sys` entries in a prime-step order, calling `stress_sys_dir` for each subtree. `stress_sys_dir` scans directories in hash-mixed order, skips dot entries, known bad paths, unreadable/unwritable mode combinations, and overly deep recursion; for each regular file it publishes the path under a spinlock, waits until either the per-file operation budget or time budget is reached, then increments bogo ops. Directories are recursed after regular files.

`stress_sys_rw` opens the published path with a timed `stress_try_open`, marks failing paths bad, and performs multiple random-sized reads until EOF, error, the per-file time threshold, or kmsg-drain pressure. It verifies `fstat` under `--verify`, performs a zero-length read, tries a one-page `mmap` and consumes one byte via `stress_put_uint8`, calls `select`, `poll`, and `ppoll`, seeks to offset zero, and issues simple `FIGETBSZ`/`FIONREAD` ioctls when available. If not running with `CAP_SYS_ADMIN`, it attempts only zero-length write opens; if privileged, it avoids broad writes except for explicit safe special cases. The parent waits for child exit and, if the child dies from SIGBUS/SIGILL/SIGSEGV/SIGTRAP/SIGSYS, reports the active path, adds it to the bad-path hash, and returns failure.

State and persistence behavior: persistent state is limited to the shared context mapping, pthread spinlocks, `/dev/kmsg` descriptor, and in-memory bad-path hash. It never creates files under `/sys`. It may read and mmap sysfs files, issue ioctls, and perform zero-length writes; the only nonzero write is the special `/sys/power/disk` `test_resume` probe. It throttles when `/dev/kmsg` output exceeds the drain threshold and records skipped path count via `hash_items`. Threads are canceled and joined by the child when traversal stops; the parent destroys locks, deletes the hash table, closes kmsg, frees dirents, and unmaps context.

Dependencies and integration points: compiled implementation requires Linux and pthread support; otherwise `stress_sysfs_info` registers `stress_unimplemented`. It depends on stress-ng core helpers for capabilities, hash tables, process killing, mmap, pthread shims, prime stepping, put sinks, signal names, temp/open retries, dirent pruning/freeing, filenames, and metrics. It uses Linux/sysfs-visible kernel behavior, `/dev/kmsg`, `uname`, `scandir`, `stat`, pthreads, fork/wait, `poll`, `select`, `mmap`, `ioctl`, and capability checks. It registers as `CLASS_OS` with optional verification and the `sysfs`/`sysfs-ops` help entries.

Risks: sysfs files are kernel driver entry points, so reads can block, produce large log volume, or trigger kernel/driver faults. The stressor mitigates with per-file timeouts, bad-path hashing, signal-supervised child restart, skip rules for zram hot-add, debugfs, Azure VMBUS paths, old TPM securityfs paths, and kmsg draining, but the design still intentionally probes fragile kernel surfaces. Privileged runs have more read/write visibility and therefore higher risk. Fork/pthread cancellation and shared spinlock state make cleanup correctness important if a child exits mid-operation.

Test signals: normal runs should report bogo ops as paths are exercised and set the metric `sysfs files exercised per sec`. Debug output reports skipped bad paths versus total accessed. Under `--verify`, failed `fstat` after a successful open is a failure signal. Severe signals should produce an informational line naming the signal and current sysfs path and should add that path to the bad hash. Skip behavior is expected on systems without `/sys`, without Linux pthread support, or where no usable entries remain after pruning.

# sources/test-tools/stress-ng/stress-sysinfo.c

Purpose: implements the `sysinfo` stressor, repeatedly fetching global system and filesystem information through `sysinfo`, Linux `statfs`/`fstatfs`, POSIX `statvfs`, legacy `ustat`, filesystem-label ioctls, and `times`. It stresses read-only kernel information paths across all currently discovered mount points and deliberately exercises some invalid inputs to cover error paths.

Important APIs/types/functions: the single stressor entry point is `stress_sysinfo`; registration is `stress_sysinfo_info`. It uses `stress_mount_get`/`stress_mount_free` for a bounded array of mount path strings, `stress_fs_bad_fd_get` for invalid-fd probes, `shim_stat`, `shim_ustat`, `sysinfo`, `statfs`, `fstatfs`, `statvfs`, `ioctl(FS_IOC_GETFSLABEL)`, `makedev`, and `times`. Verification is controlled by `OPT_FLAGS_VERIFY`.

Control flow: `stress_sysinfo` initializes a 128-entry mount array, fetches current mount points, logs the count on instance zero, synchronizes with other workers, and loops while stress-ng says to continue. In each iteration it conditionally calls `sysinfo`, then for each mount point calls `statfs`; if a mount disappears with `ENOENT`, it frees and clears that entry. It also probes invalid paths (`/invalid_stress_ng` and `""`), opens mount directories to optionally request the filesystem label via ioctl, calls `fstatfs`, and probes `fstatfs` on a known bad fd. Next it stats each mount to get `st_dev`, calls `shim_ustat`, and exercises an invalid `ustat` device using a likely-invalid major/minor. When available, it repeats the mount walk with `statvfs` and an invalid path. Finally it calls `times`, increments bogo ops, and exits on failure or stop conditions.

State and persistence behavior: the stressor is intended to be read-only. It allocates and later frees mount-point strings returned by `stress_mount_get`; it mutates only the local mount list by removing entries that disappear. It opens mount directories transiently and closes them after `fstatfs`. It does not create files, mount/unmount filesystems, or alter system limits. Invalid probes are intentionally ignored via `VOID_RET` except where verification treats unexpected errors as failures.

Dependencies and integration points: this file depends on stress-ng mount helpers and portability shims plus optional platform headers for Linux filesystem ioctls, `sysmacros`/`mkdev`, `statfs`, and `statvfs`. It is registered as `CLASS_OS` with `VERIFY_OPTIONAL`, and it follows stress-ng process-state transitions (`SYNC_WAIT`, `RUN`, `DEINIT`) and bogo-op accounting. The behavior is shaped by platform feature macros such as `HAVE_SYS_SYSINFO_H`, `HAVE_SYSINFO`, `HAVE_SYS_STATFS_H`, `HAVE_SYS_STATVFS_H`, and label ioctl availability.

Risks: results depend on a changing mount namespace. Mount points can disappear, become inaccessible, return network-filesystem errors, or require permissions while the loop runs. Verification allows expected transient/platform errors (`ENOSYS`, `EOVERFLOW`, `EACCES`, `ENOTCONN`, `EPERM`, selected `ustat` errors), but unexpected errno values cause failures. The fixed 128 mount array means very large mount namespaces are sampled rather than exhaustive. Opening mount roots and issuing label ioctls may be slow or unsupported on some filesystems.

Test signals: startup should find mount points or fail with an error. Instance zero debug logs the number of mounts. Under `--verify`, unexpected failures from `sysinfo`, `statfs`, `ustat`, `statvfs`, or `times` produce `pr_fail` messages and set `EXIT_FAILURE`; accepted invalid-input errors are ignored. Normal progress is bogo-op increments per full information-gathering pass and clean `DEINIT` with mount-list cleanup.
