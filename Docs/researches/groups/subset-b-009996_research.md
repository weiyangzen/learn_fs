# sources/user-network-fs/samba/source4/torture/smb2/bench.c

Purpose: This file implements the SMB2 torture benchmark suite. It measures sustained operation rate and latency for SMB2 echo keepalives, shared-path open/close contention, reads, writes, and repeated session setup/logoff cycles. It also registers an existing oplock benchmark under the same suite.

Important APIs and types: The file is built around Samba torture APIs (`struct torture_context`, `torture_suite_add_1smb2_test`, `torture_setting_int`, `torture_setting_bool`, `torture_comment`), SMB2 client APIs (`smb2_create_send/recv`, `smb2_close_send/recv`, `smb2cli_echo_send/recv`, `smb2cli_read_send/recv`, `smb2cli_write_send/recv`, `smb2_session_setup_spnego_send/recv`, `smb2_logoff_send/recv`, `smb2cli_ioctl`, `smb2cli_conn_set_max_credits`), and tevent async APIs (`tevent_create_immediate`, `tevent_schedule_immediate`, `tevent_add_timer`, `tevent_loop_once`, `tevent_req_set_callback`). Each benchmark has a state struct, per-connection struct, and per-loop struct: `test_smb2_bench_echo_state/conn/loop`, `test_smb2_bench_path_contention_shared_state/conn/loop`, `test_smb2_bench_read_state/conn/loop`, `test_smb2_bench_write_state/conn/loop`, and `test_smb2_bench_session_setup_shared_state/conn/loop`. `uint64_comma_str()` formats large counters for progress output.

Control flow: Each test allocates benchmark state under the torture context, derives `nprocs`, `qdepth`, `timelimit`, and sometimes `looplimit` or `io_size` from torture settings, opens one or more SMB2 connections, sets high client credit limits, and schedules one async loop per connection-depth slot. The echo/read/write loops issue one request, record `timeval_current()`, receive in a callback, validate the response, update per-loop latency/count statistics, then immediately issue the next request until the timer or loop limit stops the test. The path-contention loop alternates create and close callbacks against a configured `bench_path`. The session-setup loop repeatedly initializes a fresh session on an existing transport, performs SPNEGO setup, logs off, frees the session, and repeats. Every benchmark installs a one-second progress timer that aggregates per-loop counters into cumulative state, prints optional progress, and sets `state->stop` after `timelimit`; the main test spins with `tevent_loop_once()` until that flag is set.

State and persistence behavior: State is intentionally transient and talloc-owned. Read and write benchmarks create `bench_read_dir` or `bench_write_dir`, then create one delete-on-close test file per loop with size set to `io_size`; both cleanup with `smb2_deltree()`. Write uses one zeroed `data_buffer` shared by all write loops. Echo and session-setup do not create share files. Benchmark statistics are maintained in memory as per-second deltas plus total counters and min/max latency fields. The code mutates client transport credit limits and temporarily opens additional SMB2 sessions/connections, but frees the benchmark state at the end.

Dependencies and integration points: This file depends on Samba's libcli SMB2 stack, smbXcli transport/session/tcon handles, command-line credentials, GENSEC settings, tevent, torture helpers, security constants, and the `torture_smb2_connection()` test harness. The suite initializer `torture_smb2_bench_init()` registers `oplock1`, `echo`, `path-contention-shared`, `read`, `write`, and `session-setup`; `oplock1` is provided outside this file via the SMB2 torture proto declarations. Runtime behavior is shaped by torture settings: `nprocs`, `qdepth`, `timelimit`, `looplimit`, `io_size`, `bench_path`, and `progress`.

Risks: Progress callbacks divide by per-second counters and total counters without guarding a zero-operation interval, so a saturated, stalled, or failing server can produce invalid averages before assertion paths stop the test. The read/write benchmarks create many open handles and delete-on-close files, so large `nprocs*qdepth` or `io_size` values stress server credits, memory, and filesystem resources. The tests raise max credits to 8192 and issue pipelined async operations, which can expose server credit accounting bugs but also makes results environment-sensitive. Session setup repeatedly reuses transports and steals/free talloc ownership, so lifetime mistakes would show up as use-after-free or leaked sessions under stress. The suite measures behavior, not deterministic pass/fail timing; throughput numbers vary by server, network, and backend.

Test signals: Successful torture runs require all async sends to allocate, all recv calls to return `NT_STATUS_OK`, read/write byte counts to match `io_size`, and the event loop to run until `timelimit` or `looplimit`. Useful signals are stable per-second operation counts, nonzero min/average/max latency, no connection drops after the credit-warming ioctl, cleanup of benchmark directories, and no hangs in `tevent_loop_once()`. For session setup, setup/logoff counts should advance together; for path contention, open and close counts should both advance.

# sources/user-network-fs/samba/source4/torture/smb2/block.c

Purpose: This file provides helper routines for SMB2 torture tests that need to make an SMB2 transport stop acknowledging traffic. It can block client TCP output with iptables or ask a Samba server test hook to force unacknowledged timeout behavior, then adapts lease/oplock break handlers so higher-level tests observe expected unacknowledged-break failures.

Important APIs and types: Public functions are `torture_get_local_port_from_transport()`, `torture_block_tcp_output_port()`, `torture_unblock_tcp_output_port()`, `torture_block_tcp_output_setup()`, `torture_unblock_tcp_output_cleanup()`, `_test_block_smb2_transport()`, `_test_unblock_smb2_transport()`, `test_setup_blocked_transports()`, and `test_cleanup_blocked_transports()`. Internal helpers include `run_cmd()`, `iptables_command()`, `samba_chain_name()`, `iptables_setup_chain()`, `torture_block_tcp_output_port_internal()`, `test_block_smb2_transport_iptables()`, `test_unblock_smb2_transport_iptables()`, `torture_blocked_lease_handler()`, `torture_blocked_oplock_handler()`, and `test_block_smb2_transport_fsctl_smbtorture()`. It uses `struct smb2_transport`, `smbXcli_conn_local_sockaddr()`, `get_sockaddr_port()`, `smb2cli_ioctl_send/recv()`, and globals from `lease_break_handler.h` and `oplock_break_handler.h`.

Control flow: In iptables mode, setup creates an `SMBTORTURE_OUTPUT` chain under `OUTPUT`. Blocking a transport resolves its local TCP port, creates a per-transport `SMBTORTURE_<name>` chain under `SMBTORTURE_OUTPUT`, and inserts a drop rule matching `--sport <local_port>`; unblocking deletes the rule and removes the per-transport chain. In non-iptables mode, `_test_block_smb2_transport()` sends `FSCTL_SMBTORTURE_FORCE_UNACKED_TIMEOUT` over the target transport with no session or tcon. If the server accepts the ioctl, it copies the transport's current lease and oplock callbacks, then replaces them with wrappers that call the originals while suppressing acknowledgements and counting failures when an ack would otherwise be required. Cleanup is a no-op for the FSCTL path and deletes the root iptables chain for the iptables path.

State and persistence behavior: Iptables mode persists host firewall state outside the process until unblocked; chain names are shell-escaped and allocated under the torture context. The FSCTL mode mutates the live `struct smb2_transport` callback pointers and stores a talloc-owned shallow copy of the original handler fields under the transport. It also mutates global torture break state (`lease_break_info.lease_skip_ack`, `lease_break_info.failures`, `break_info.oplock_skip_ack`, `break_info.failures`, `break_info.failure_status`) while wrapper callbacks run.

Dependencies and integration points: The helpers integrate with tests that include `torture/smb2/block.h` and call the macro wrappers `test_block_smb2_transport()` or `test_unblock_smb2_transport()`. Runtime selection comes from the `torture:use_iptables` setting; the iptables executable can be overridden with `torture:iptables_command`, commonly to use sudo. The FSCTL path requires a Samba server with `smbd:FSCTL_SMBTORTURE = yes`. Network identity comes from smbXcli local socket state; command execution uses the host shell through `system()`.

Risks: Iptables manipulation is privileged, platform-specific, and persistent if cleanup is skipped or a process dies. The drop rule matches source port even though log text says destination port, so reviewers must preserve the client-local-port assumption. Chain names have iptables length limits; the code escapes names but does not enforce the 29-character limit described in the comment. The FSCTL path is Samba-specific and will fail against ordinary SMB2 servers. Temporarily replacing lease/oplock handlers relies on global break-state conventions, so nested or parallel tests can interfere.

Test signals: Good signals include successful creation/removal of `SMBTORTURE_OUTPUT` and per-transport chains, blocked transports causing expected disconnect or unacked-break behavior, cleanup leaving no firewall chains, and FSCTL failures producing the explicit configuration guidance. For handler wrapping, expected signals are incremented lease/oplock failure counters when acknowledgements were required and no unexpected callback failure from the original handler.

# sources/user-network-fs/samba/source4/torture/smb2/block.h

Purpose: This header declares SMB2 torture helper functions for blocking and unblocking transports and their backing TCP output paths. It is the small public contract implemented by `block.c`.

Important APIs and types: It declares `torture_get_local_port_from_transport(struct smb2_transport *)`, direct TCP helpers `torture_block_tcp_output_port()` and `torture_unblock_tcp_output_port()`, global iptables setup/cleanup helpers `torture_block_tcp_output_setup()` and `torture_unblock_tcp_output_cleanup()`, test lifecycle helpers `test_setup_blocked_transports()` and `test_cleanup_blocked_transports()`, and the lower-level `_test_block_smb2_transport()` / `_test_unblock_smb2_transport()` functions. Convenience macros `test_block_smb2_transport(_tctx, _t)` and `test_unblock_smb2_transport(_tctx, _t)` pass the expression name as the diagnostic transport name.

Control flow: Consumers call setup before tests that may use iptables, block one or more `struct smb2_transport` values during the scenario, unblock them if needed, and call cleanup afterward. The macros preserve a readable name without each caller manually passing a string.

State and persistence behavior: The header has no storage of its own. It exposes functions that can mutate host firewall state, SMB2 transport callback state, and global lease/oplock break tracking in the implementation.

Dependencies and integration points: This header assumes the including translation unit already sees Samba torture and SMB2 type declarations for `struct torture_context` and `struct smb2_transport`. It is used by SMB2 torture tests that need controlled transport failure or unacknowledged break behavior.

Risks: The macros stringify the transport expression, so complex expressions can produce long or awkward chain names in iptables mode. There is no include guard in this file; it relies on local include discipline. The API does not expose an error object, only boolean success/failure, so callers must rely on torture comments and assertions for diagnostics.

Test signals: Compile success in consumers validates visible type declarations. Runtime signals come from `block.c`: setup/block/unblock returning true, expected transport failure behavior, and cleanup restoring firewall state.

# sources/user-network-fs/samba/source4/torture/smb2/charset.c

Purpose: This file implements SMB2 charset torture tests that create files with specific Unicode names. It probes how the server handles composed characters, standalone diacritics, surrogate halves/pairs, and full-width Latin characters.

Important APIs and types: The central helper is `unicode_open()`, which converts an array of UTF-16 code units into a Unix string using `convert_string_talloc_handle()` and `lpcfg_iconv_handle()`, prefixes it with `BASEDIR`, then calls `smb2_create()` and closes the handle. Test cases are `test_composed()`, `test_diacritical()`, `test_surrogate()`, and `test_widea()`. The suite is registered by `torture_smb2_charset()`. It uses `struct smb2_create`, `smb2_util_setup_dir()`, `smb2_deltree()`, `smb2_util_close()`, and torture assertion helpers.

Control flow: Every test creates `chartest`, calls `unicode_open()` with one or more hard-coded UTF-16 code-unit arrays and `NTCREATEX_DISP_CREATE`, checks the expected NTSTATUS, then deletes the directory. `test_composed()` creates decomposed `a` plus combining diaeresis and precomposed `a-umlaut`. `test_diacritical()` creates one and two standalone combining-diaeresis names. `test_surrogate()` tries a high surrogate, a low surrogate, and a high+low pair. `test_widea()` creates ASCII `a`, full-width lowercase `a`, and expects full-width uppercase `A` to collide.

State and persistence behavior: Persistent filesystem state is limited to files under `chartest`; each test removes the tree in its `done` path. `unicode_open()` allocates temporary UTF-16 and converted-name buffers under the caller-provided talloc context and frees the UTF-16 parent before returning.

Dependencies and integration points: The tests depend on Samba charset conversion, configured iconv handles, SMB2 create/close semantics, and server-side Unicode normalization/casefolding behavior. They integrate as a normal one-tree SMB2 torture suite named `charset`.

Risks: The helper stores each `uint32_t` code point with `SSVAL`, so it is really writing UTF-16 code units; values outside 16 bits would be truncated if added later. `test_surrogate()` returns `true` unconditionally after cleanup instead of `ret`, which could hide a failure after an assertion path sets `ret = false`. Expectations are server/filesystem dependent because Unicode normalization, invalid surrogate acceptance, and wide-character casefolding vary across backends. The tests create names that may not be representable on all local or remote filesystems.

Test signals: Expected success is `NT_STATUS_OK` for composed, diacritical, and surrogate create attempts, and `NT_STATUS_OBJECT_NAME_COLLISION` for full-width uppercase `A` after ASCII and full-width lowercase `a` exist. Cleanup should delete `chartest` after every test. Conversion failures or unexpected create statuses identify charset mapping or filesystem normalization regressions.

# sources/user-network-fs/samba/source4/torture/smb2/compound.c

Purpose: This file implements SMB2 compound-request torture suites. It validates related and unrelated compounding, special related-handle substitution, invalid related-flag sequences, response padding, async/interim response behavior, compound find behavior, compound flush/read/write edge cases, lease-break interactions, and rename/getinfo positioning in compounds.

Important APIs and types: The file uses `smb2_transport_compound_start()` and `smb2_transport_compound_set_related()` to build compound chains, many async send/recv pairs (`smb2_create_send/recv`, `smb2_close_send/recv`, `smb2_read_send/recv`, `smb2_write_send/recv`, `smb2_ioctl_send/recv`, `smb2_notify_send/recv`, `smb2_find_send/recv`, `smb2_flush_send/recv`, `smb2_getinfo_send/recv`, `smb2_setinfo_file_send`, `smb2_setinfo_recv`), and low-level request helpers (`smb2_request_receive()`, `smb2_request_init_tree()`, `smb2_transport_send()`, `smb2_cancel()`). Lease and oplock checks use `torture_lease_handler`, `CHECK_BREAK_INFO`, `CHECK_LEASE_BREAK_ACK`, `smb2_lease_create()`, and `smb2_lease_break_ack()`. The static `break_info` struct and `torture_oplock_handler()` track and acknowledge oplock breaks for compound-break coverage.

Control flow: Most tests start with cleanup, prepare one or more `smb2_create` or file-info structures, call `smb2_transport_compound_start(tree->session->transport, n)`, submit the first request, optionally set the compound related flag, then submit additional requests using either `UINT64_MAX:UINT64_MAX` as the related handle placeholder or explicit handles. Receives are then checked in request order for exact statuses. Related tests verify handle propagation and error propagation: successful create+close chains, repeated close returning `NT_STATUS_FILE_CLOSED`, access-denied and object-not-found propagation, missing related-handle invalid-parameter cases, and related reads/writes with access-denied write in the middle. Unrelated and invalid tests verify that placeholders fail when the related flag is absent or set in invalid positions. Padding tests manually receive read responses to inspect `req->in.body_size` for 8-byte padding inside compounds versus no padding for a single read. Interim tests use notify requests and request states/cancel flags to verify Windows-compatible async compound behavior. Find tests cover repeated directory enumeration and a pending find that completes after the handle is closed. Async tests cover flush+close, flush+flush, write+write, and read+read behavior, including Samba-specific last-element async behavior under delayed AIO. Lease-break tests use two tree connections to ensure CREATE-triggered breaks produce pending responses while rename-triggered breaks do not.

State and persistence behavior: The file creates and deletes many named test files/directories such as `compound_related*.dat`, `compound_read.dat`, `compound_find_dir`, and lease/rename-specific names. It temporarily installs transport oplock or lease handlers, resets global break tracking state, requests larger credit windows for some compounds, changes `tree->smbXcli` and `tree->session->smbXcli` to synthetic invalid tcon/session values in selected tests, and restores them afterward. Async crash-regression tests intentionally sleep after unlink operations to let server-side fsync work finish before declaring success. All durable state should be removed with `smb2_util_unlink()` or `smb2_deltree()` in each `done` path.

Dependencies and integration points: The tests depend on Samba libcli SMB2 request construction, security descriptor helpers, lease-break test utilities, low-level smbXcli session/tcon manipulation, server capabilities (`SMB2_CAP_LEASING`), and torture settings such as `smbd` for Samba-specific async expectations. Suite initializers register three suites: `torture_smb2_compound_init()` for base compound semantics, `torture_smb2_compound_find_init()` for find-specific cases, and `torture_smb2_compound_async_init()` for async and lease/rename cases. Two-tree tests require independent SMB2 connections to trigger lease breaks.

Risks: The file deliberately exercises protocol gray areas and Windows-compatible deviations, so expected statuses are subtle and can vary by server implementation. Several tests call `smb2_tdis()` and `smb2_logoff()` inside cleanup, which can affect later use if the harness reuses the tree unexpectedly. The invalid-session/tcon tests temporarily replace live pointers; missing restoration would corrupt the connection. Global break state and installed transport callbacks are not isolated for parallel execution. Large find tests create 5000 files and request large response buffers, which can be expensive. There is a likely typo in `test_compound_getinfo_middle()` assigning `info.generic.in.file.handle.data[0]` twice instead of setting `data[1]`; the related-handle placeholder still intends both halves to be `UINT64_MAX`, so this line deserves review if the test behaves unexpectedly.

Test signals: Passing signals are exact NTSTATUS matches for every compound element, correct related-handle substitution, correct error propagation to later related requests, correct padded read body sizes (`24` in compounds and `19` for a single 3-byte read), expected request states and `cancel.can_cancel` flags around pending notify/read/write/create operations, no server crash after async flush/close races, successful lease-break ACKs, and cleanup of all temporary files/directories. Skips are expected when leasing is unsupported.

# sources/user-network-fs/samba/source4/torture/smb2/connect.c

Purpose: This file implements a basic SMB2 connection torture test plus reusable helpers for creating, writing, and closing an SMB2 file. It validates ordinary create/write/read/flush/close behavior and post-disconnect session/tree semantics.

Important APIs and types: Internal helpers are `torture_smb2_close()` and `torture_smb2_write()`. Public helper `torture_smb2_createfile()` creates or opens a file and returns its `struct smb2_handle`. The test entry point is `torture_smb2_connect()`. It uses `struct smb2_tree`, `struct smb2_request`, `struct smb2_create`, `struct smb2_write`, `struct smb2_read`, `struct smb2_flush`, `struct smb2_close`, `smb2_create()`, `smb2_write()`, `smb2_read()`, `smb2_flush()`, `smb2_close()`, `smb2_tdis()`, `smb2_logoff()`, `smb2_logoff_send/recv()`, `smb2_keepalive()`, and utility helpers such as `smb2_util_unlink()` and `torture_smb2_all_info()`.

Control flow: `torture_smb2_connect()` opens a test connection, unlinks `test9.dat`, opens the same file twice with `torture_smb2_createfile()`, writes a configured-size buffer through the first handle, closes both handles with full close information, verifies an additional close on the first handle returns `NT_STATUS_FILE_CLOSED`, disconnects the tree, verifies a second tree disconnect returns `NT_STATUS_NETWORK_NAME_DELETED`, logs off, sends another logoff with a deliberately cleared request session pointer, expects `NT_STATUS_USER_SESSION_DELETED`, and finally sends a keepalive on the transport. `torture_smb2_write()` writes deterministic byte data twice, prints all-info between writes, flushes, reads back the same length, and compares byte-for-byte. `torture_smb2_close()` requests full close information and optionally prints timestamps, sizes, and attributes.

State and persistence behavior: The test creates `test9.dat` in the target share and unlinks any prior copy before starting; it does not explicitly unlink after the final operations in this file. Temporary allocations use talloc contexts rooted under the tree or torture context. The control flow intentionally transitions server-side state from open handles to closed handles, disconnected tree connect, logged-off session, and a transport that should still answer keepalive.

Dependencies and integration points: This file depends on the SMB2 torture connection harness (`torture_smb2_connection()`), Samba SMB2 client calls, NT time formatting, debug-level-controlled diagnostics, and the `smb2maxwrite` torture setting for write size. `torture_smb2_createfile()` is a reusable symbol declared through the SMB2 torture proto header and may be used by other SMB2 tests.

Risks: `torture_smb2_connect()` allocates `mem_ctx` but otherwise roots most work under the tree; if an assertion aborts, `test9.dat` may remain. The explicit `req->session = NULL` manipulation is intentionally abnormal and depends on current request internals. A keepalive after logoff assumes the transport remains connected even though tree and session are invalidated. The write buffer size is configurable, so very large `smb2maxwrite` values can increase memory use and server load.

Test signals: Expected statuses are `NT_STATUS_OK` for connection, create, write, close, first tree disconnect, first logoff, and keepalive; `NT_STATUS_FILE_CLOSED` for closing an already closed handle; `NT_STATUS_NETWORK_NAME_DELETED` for disconnecting an already disconnected tree; and `NT_STATUS_USER_SESSION_DELETED` for logoff after the session is invalidated. Readback data must match the generated buffer exactly.
