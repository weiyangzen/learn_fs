# sources/distributed-fs/ceph-client/drivers/infiniband/hw/bnxt_re/qplib_res.h

Purpose: common resource-manager contract for the Broadcom NetXtreme-E RoCE qplib layer. It defines chip generation detection, hardware queue/PBL allocation metadata, PD/SGID/DPI/resource tables, doorbell addressing and write helpers, global context layout, capability helpers, and exported resource-management prototypes used by the slow-path, fast-path, and RCFW code.

Important APIs, types, and functions: `struct bnxt_qplib_chip_ctx` records chip identity, firmware interface version, HWRM timeout, hardware-stat size, and mode flags such as WQE mode, doorbell push, doorbell pacing, toggle bits, and RoCE mirror support. `struct bnxt_qplib_hwq`, `struct bnxt_qplib_pbl`, `struct bnxt_qplib_sg_info`, and `struct bnxt_qplib_hwq_attr` describe DMA-backed queues, page-list levels, queue depth/stride, user memory, producer/consumer positions, and page-size state. `struct bnxt_qplib_res` is the top-level resource bundle for PCI, netdev, bnxt_en, RCFW, PD table, SGID table, DPI table, priority/VF flags, and doorbell pacing data. `struct bnxt_qplib_ctx` groups QP/MRW/SRQ/CQ context tables, timer table, TQM context, stats, and VF resource limits. Inline helpers include chip predicates (`bnxt_qplib_is_chip_gen_p5()`, `_p7()`, `_p5_p7()`), queue accessors (`bnxt_qplib_get_base_addr()`, `bnxt_qplib_base_pg_size()`, `bnxt_qplib_get_qe()`, `bnxt_qplib_get_prod_qe()`), index movement (`bnxt_qplib_hwq_incr_prod()`, `bnxt_qplib_hwq_incr_cons()`), and doorbell writes (`bnxt_qplib_ring_db32()`, `bnxt_qplib_ring_db()`, `bnxt_qplib_ring_prod_db()`, `bnxt_qplib_armen_db()`, `bnxt_qplib_srq_arm_db()`, `bnxt_qplib_ring_nq_db()`). Capability helpers expose firmware flags for extended stats, hardware retransmit, host MSN table, unified MR allocation, relaxed ordering, optimized modify-QP, mandatory min-RNR behavior, CQ coalescing, extended SRQ counts, modify-QP rate limit, doorbell pacing, and RoCE mirror support. The file also declares allocation/free APIs for hardware queues, PDs, DPIs, resources, hardware contexts, DB BAR mapping, atomic support, and stats contexts.

Control flow: this header mostly supplies data layout and inline decision logic. Callers allocate and initialize `bnxt_qplib_res`, then allocate hardware contexts and queues through the declared implementation in `qplib_res.c`. Fast-path code uses `bnxt_qplib_get_qe()` and producer/consumer increment helpers to walk ring memory. Doorbell flow builds 64-bit DBC keys for newer P5/P7 chips and 32-bit completion doorbells for older chips, folding XID, path, type, valid bit, ring index, epoch flags, and optional toggle into the write value. `bnxt_qplib_ring_nq_db()` selects NQ versus legacy RoCE completion doorbell encoding by chip generation. Page-size flow maps software byte page sizes to HWRM page-size enum fields, and queue base-address helpers hand DMA PBL roots to firmware command builders.

State and persistence: all state is in kernel memory plus PCI BAR mappings and DMA memory described by PBL arrays. `prod`, `cons`, `cp_bit`, epoch/toggle fields, resource bitmaps, SGID/DPI/PD tables, stats DMA buffers, and pacing data are runtime state only. No on-disk state is used. Hardware-visible state persists only while queues, context tables, stats contexts, and firmware resources remain allocated. The PD and DPI bitmaps have mutexes declared in `struct bnxt_qplib_res`; `struct bnxt_qplib_hwq` has a spinlock, but many inline helpers expect callers to hold the proper queue-level synchronization.

Dependencies and integration points: depends on Linux PCI, DMA, page-size, MMIO, mutex/spinlock, RDMA `ib_umem`, Broadcom ULP definitions, and many firmware/doorbell constants from `roce_hsi.h`. It is included by `qplib_sp.c`, `qplib_fp.c`, `qplib_rcfw.c`, `qplib_res.c`, and upper driver code. `bnxt_qplib_base_pg_size()` feeds create-QP/SRQ/CQ and initialize-FW-context commands. Doorbell helpers are used by completion queues, notification queues, SRQs, SQs, RQs, and RCFW CREQ handling. Capability helpers gate main-driver features such as extended stats, DBR pacing, RoCE mirror flow creation, hardware retransmit, and rate limiting.

Risks: the ring macros assume power-of-two `max_elements` and correct queue-depth setup; violating that contract corrupts free-slot and wrap calculations. Doorbell epoch flags are bit-toggled in caller-visible state, so missed producer/consumer increments or unsynchronized ring access can desynchronize hardware and software. `bnxt_qplib_get_qe()` trusts `qe_ppg`, `pbl_ptr`, and index bounds and can produce invalid pointers if allocation metadata is wrong. `bnxt_qplib_base_pg_size()` silently falls back to 4K for unrecognized sizes, which can mask allocation bugs. The 64-bit doorbell format differs from the legacy 32-bit path and is highly sensitive to chip-generation predicates and firmware constants. SGID comments in the implementation note missing explicit locking; the resource structure itself does not provide a SGID lock. Capability helpers are thin flag tests and rely on `bnxt_qplib_get_dev_attr()` correctly populating `dev_cap_flags` and `dev_cap_flags2`.

Test signals: compile with all bnxt_re objects to catch struct/prototype drift, run sparse/smatch for MMIO, endian, and pointer arithmetic warnings, exercise P5, P7, and legacy chip paths for NQ/CQ/SQ/RQ/SRQ doorbells, validate queue wrap behavior at depth boundaries, test PD/DPI bitmap allocation under concurrency, verify PBL level/page-size combinations in create-QP/SRQ/CQ/MR flows, and check feature gating for extended stats, doorbell pacing, RoCE mirror, relaxed ordering, and rate-limit support on PF and VF configurations.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/bnxt_re/qplib_sp.c

Purpose: slow-path firmware command implementation for bnxt_re qplib. It translates RDMA driver operations into RCFW command queue messages for device discovery, function resource setup, SGID table programming, address-handle lifecycle, memory-region/window allocation and registration, fast-registration page-list allocation, RoCE statistics, extended statistics, congestion-control modification/query, context reads, and RoCE mirror flow enable/disable.

Important APIs, types, and functions: `bnxt_qplib_query_version()` sends `QUERY_VERSION` and stores four firmware version bytes in `bnxt_qplib_dev_attr`. `bnxt_qplib_get_dev_attr()` sends `QUERY_FUNC`, allocates a coherent side buffer, parses max QP/CQ/MR/MW/SRQ/GID/DPI/TQM/rate-limit values, caps or adjusts several fields by chip generation and WQE mode, and records atomic support from PCIe device control. `bnxt_qplib_set_func_resources()` programs per-function and per-VF QP/MRW/SRQ/CQ/GID resource limits from `struct bnxt_qplib_ctx`. SGID APIs `bnxt_qplib_get_sgid()`, `bnxt_qplib_add_sgid()`, and `bnxt_qplib_del_sgid()` manage software table entries and optionally send `ADD_GID`/`DELETE_GID` commands with VLAN, MAC, stats context, and firmware HW ID handling. `bnxt_qplib_create_ah()` and `bnxt_qplib_destroy_ah()` wrap `CREATE_AH`/`DESTROY_AH`. MRW APIs include `bnxt_qplib_alloc_mrw()`, `bnxt_qplib_free_mrw()`, `bnxt_qplib_reg_mr()`, and `bnxt_qplib_dereg_mrw()`, covering key allocation/deallocation, PBL HWQ allocation for user memory, unified-MR handling, access flags, VA/size, and cleanup on failure. `bnxt_qplib_alloc_fast_reg_page_list()` and `bnxt_qplib_free_fast_reg_page_list()` allocate/free page-list HWQs. Stats APIs `bnxt_qplib_get_roce_stats()` and `bnxt_qplib_qext_stat()` query base and extended counters through coherent side buffers. Congestion-control helpers `bnxt_qplib_fill_cc_gen1()`, `bnxt_qplib_modify_cc()`, `bnxt_qplib_read_cc_gen1()`, and `bnxt_qplib_query_cc_param()` map base and P5/P7 TLV-extended CC parameters. `bnxt_qplib_read_context()` reads arbitrary firmware contexts into caller memory. `bnxt_qplib_create_flow()` and `bnxt_qplib_destroy_flow()` toggle RoCE mirror configuration.

Control flow: every firmware operation prepares a command structure with `bnxt_qplib_rcfw_cmd_prep()`, fills a `bnxt_qplib_cmdqmsg` with request/response/optional side buffer metadata, and calls `bnxt_qplib_rcfw_send_message()`. Query operations allocate DMA-coherent side buffers, pass response size in command units, parse little-endian firmware fields, then always free the buffer on the exit path. SGID add scans for duplicates and the first zero GID slot, optionally programs firmware, then updates the software table, VLAN marker, active count, and returned software index. SGID delete scans for matching GID/VLAN, optionally deletes the firmware HW ID, zeroes the slot, clears VLAN state, decrements active count, and invalidates the HW ID. MR registration allocates or reuses an MR PBL HWQ when `num_pbls` is nonzero, builds level/page-size fields, sends the register command, updates unified keys when requested, and frees the HWQ on command failure. Congestion-control modification first builds the legacy command payload, then on P5/P7 wraps it in a primary TLV plus a Gen1 extension TLV and sends the larger request. Congestion-control query chooses legacy or TLV-extended response size by chip generation and merges high inactivity-threshold bits from the extension.

State and persistence: this file updates in-memory qplib resource state (`dattr`, SGID table contents, `hw_id`, VLAN markers, active count, MRW keys, MRW HWQ, CC parameter structs, RCFW out-of-sequence counter baseline). It allocates temporary DMA-coherent side buffers for firmware responses and frees them within each call. Firmware-visible state persists until explicitly removed: added GIDs, AH IDs, allocated keys, registered MRs, function resource limits, congestion-control settings, stats contexts, and RoCE mirror enablement. Base RoCE stats maintain `rcfw->oos_prev` and `rcfw->init_oos_stats` so `res_oos_drop_count` can be reported as a masked delta across calls.

Dependencies and integration points: depends on `roce_hsi.h` command/response formats, qplib RCFW message submission, qplib resource helpers, qplib TLV helpers, Linux DMA-coherent allocation, PCIe capability access, endian conversion helpers, and RDMA user memory passed into MR registration. Upper-layer call sites include `ib_verbs.c` for SGID/AH/MR/FRPL operations, `main.c` and `debugfs.c` for CC query/modify and context dumping, `qplib_rcfw.c` for RoCE mirror setup, and resource/context allocation code for function resources. Chip-generation helpers from `qplib_res.h` gate legacy versus P5/P7 behavior, P7 CQ sizing, P7 VF extended stats function-ID encoding, and TLV CC paths.

Risks: SGID add/delete contain comments asking whether a lock is needed; concurrent GID table updates could race active counts, duplicate detection, and slot reuse unless higher layers serialize calls. In `bnxt_qplib_add_sgid()`, duplicate detection compares `&sgid_tbl->tbl[i]` to `gid` for `sizeof(*gid)`, relying on `gid` being the first field of `struct bnxt_qplib_gid_info`; this is layout-sensitive. SGID add returns `-EALREADY` after setting `*index`, so callers must treat that as nonfatal where appropriate. `is_ugid` is accepted but unused, which may signal a stale API or missing behavior. MR registration frees any existing HWQ before re-registration and must be paired carefully with upper-layer state to avoid losing old mappings on partial failures. `bnxt_qplib_reg_mr()` initializes `pg_size` in both no-PBL and normal branches, then overwrites it with `buf_pg_size ? buf_pg_size : PAGE_SIZE`; this is intended but easy to misread when changing no-PBL behavior. Many commands accept a `block` parameter but most slow-path calls pass nonblocking zero; completion semantics depend on RCFW internals. Extended stats encode VF function IDs differently for P7 VFs, so fid validation is critical. RoCE mirror destroy zero-initializes the request then clears an already-zero enable bit, which relies on firmware interpreting zero flags as disable.

Test signals: mock or hardware-run RCFW command paths for success, timeout, and firmware error status; verify coherent side-buffer allocation failures return `-ENOMEM` and free all resources on later errors; test `QUERY_FUNC` parsing across legacy, P5, P7, PF, and VF devices; exercise SGID duplicate, full-table, invalid-HW-ID, VLAN/prio-tagged, and no-update paths; create/destroy AH with blocking and nonblocking calls; allocate/free PMR and MW type1/type2 keys; register/deregister MRs with zero PBLs, one-level, multi-level, unified-MR, and re-registration failure cases; validate FRPL limits above `MAX_PBL_LVL_1_PGS`; compare RoCE and extended stats against firmware counters, including out-of-sequence wrap; query/modify CC on legacy and P5/P7 TLV devices; read MRW/QPC/SRQ/CQ contexts from debug paths; and test RoCE mirror enable/disable only when capability flags advertise support.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/bnxt_re/qplib_sp.h

Purpose: public slow-path data-model header for bnxt_re qplib. It defines the driver-facing structures used to hold firmware-reported device attributes, protection domains, GIDs, address handles, memory regions/windows, fast-registration page lists, RoCE statistics, extended packet statistics, congestion-control parameters, and the prototypes implemented by `qplib_sp.c`.

Important APIs, types, and functions: `struct bnxt_qplib_dev_attr` stores firmware version, maximum SGID/QP/CQ/MR/MW/PD/AH/SRQ/PKEY/inline-data/DPI values, WQE/SGE limits, L2 doorbell size, TQM allocation requests, atomic support, capability flags, and rate-limit range. `struct bnxt_qplib_pd` holds a firmware PD ID. `struct bnxt_qplib_gid` is a 16-byte address and `struct bnxt_qplib_gid_info` pairs it with a VLAN ID. `struct bnxt_qplib_ah` contains destination GID/MAC, PD, firmware AH ID, SGID indexes, traffic class, flow label, hop limit, service level, VLAN ID, and network type. `struct bnxt_qplib_mrw` describes MR/MW type, access flags, lkey/rkey, VA, size, page count, firmware flags, handle, and backing HWQ. `struct bnxt_qplib_frpl` wraps a fast-registration page-list HWQ. `struct bnxt_qplib_roce_stats` and `struct bnxt_qplib_ext_stat` enumerate base error/traffic counters and extended TX/RX packet/byte/CNP/ECN counters. `struct bnxt_qplib_cc_param_ext` and `struct bnxt_qplib_cc_param` model base and Gen1 congestion-control knobs. Prototypes expose SGID, device-attribute, resource, AH, MRW, FRPL, stats, CC, context-read, version, and mirror-flow APIs. Constants define reserved QP WQEs, supported GID count, maximum outstanding RDMA atomics, CQ WQE cap, access flags, reserved lkey, variable-WQE limits, static SGE count, and receive queue WQE maximum.

Control flow: this header establishes the object contracts passed between upper RDMA verbs code and the qplib slow-path implementation. Upper layers populate PD/GID/AH/MRW/CC structs, call the declared qplib API, and expect IDs, keys, maximums, and counters to be filled or updated. `qplib_sp.c` owns firmware command execution for these declarations, while `ib_verbs.c`, `main.c`, `debugfs.c`, and resource/context code consume the resulting state. The header also advertises prototypes such as `bnxt_qplib_update_sgid()` and `bnxt_qplib_alloc_fast_reg_mr()` that are declared here but not implemented in the paired `qplib_sp.c` as read in this work item, so build coverage must account for whether another file supplies them or whether the declarations are stale.

State and persistence: structures defined here are runtime state containers. Device attributes persist in memory after `QUERY_FUNC` until the device is removed or requeried. AH/MRW/FRPL objects hold firmware IDs or DMA-backed HWQs that persist until corresponding destroy/free/deregister calls. Stats structs are snapshots supplied by query calls. CC structs are request/response carriers; changes sent through `bnxt_qplib_modify_cc()` persist in firmware until changed again or reset. No filesystem persistence is introduced by this header.

Dependencies and integration points: includes the RDMA bnxt_re ABI header and relies on types from `qplib_res.h` being visible to users for `struct bnxt_qplib_hwq`, `struct bnxt_qplib_res`, `struct bnxt_qplib_ctx`, and RCFW types. It is included by the slow-path C file and by upper bnxt_re modules that bridge Linux RDMA core objects into qplib commands. Values here are tightly coupled to firmware command fields in `roce_hsi.h`, qplib resource queue definitions, IIO-style no relation; this is RDMA kernel driver code. The access flags map upper-layer MR permissions into firmware command masks.

Risks: the header is a shared ABI within the driver, so structure field changes can break multiple modules or firmware command packing. Some fields have implicit units or split integer/fractional representation (`rate_limit_*`, CC thresholds, stats counters, `max_inline_data`) and need careful documentation at call sites. `bnxt_qplib_roce_stats` contains comments that mostly restate 64-bit width and do not clarify reset/delta behavior. `bnxt_qplib_dev_attr.max_mrw` is present but the implementation populates `max_mr` and `max_mw`, so users should verify whether `max_mrw` is obsolete. Declared-but-unimplemented prototypes are a maintenance hazard if no other translation unit defines them. `struct bnxt_qplib_ah` carries both firmware SGID index and host SGID index, making mismatches possible when software and hardware GID tables diverge.

Test signals: full bnxt_re module builds with `W=1` and modpost should catch stale prototypes and missing definitions; compile matrix should include static and variable WQE modes; run verbs tests for PD/AH/MR/MW/FRMR object lifecycle using these structs; validate reported device attributes against firmware on legacy, P5, P7, PF, and VF devices; exercise CC debugfs/sysfs paths for each field width; check stats readers for overflow/delta behavior; and run sparse for endian, struct padding, and access-flag type mismatches after any header change.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/bnxt_re/qplib_tlv.h

Purpose: TLV command wrapper support for bnxt_re qplib RCFW messages. It defines the RoCE TLV header layout, 16-byte chunk sizing helpers, accessors that make command-queue base fields work for both plain and TLV-encapsulated commands, and concrete TLV request/response wrappers for extended RoCE congestion-control commands.

Important APIs, types, and functions: `struct roce_tlv` wraps firmware `struct tlv`, a `total_size` field in 16-byte chunks, and alignment padding. `CHUNK_SIZE`, `CHUNKS(x)`, `TLV_SIZE`, and `TLV_BYTES` compute firmware command sizing. `__roce_1st_tlv_prep()` initializes the primary TLV header with `CMD_DISCR_TLV_ENCAP`, `TLV_TYPE_ROCE_SP_COMMAND`, payload length, required flag, optional MORE flag, and total chunk count. `__roce_ext_tlv_prep()` initializes extension TLV headers with caller-selected type, payload length, optional MORE flag, and optional REQUIRED flag. `HAS_TLV_HEADER()` detects TLV-encapsulated messages by command discriminator, and `GET_TLV_DATA()` returns the base command that follows the fixed TLV header. Getter/setter helpers for opcode, cookie, response address, response size, command size, and flags dispatch either to the outer/plain `cmdq_base` or to the embedded `cmdq_base` behind the TLV header. `struct bnxt_qplib_tlv_modify_cc_req` packages primary TLV header, base `cmdq_modify_roce_cc`, padding, and Gen1 CC extension TLV. `struct bnxt_qplib_tlv_query_rcc_sb` packages TLV query response layout with base CC response and Gen1 extension response.

Control flow: P5/P7 slow-path code builds a larger congestion-control command in `bnxt_qplib_modify_cc()`, writes the primary TLV header with `__roce_1st_tlv_prep()`, writes the extension TLV with `__roce_ext_tlv_prep()`, fills the base and extension payloads, then submits the whole structure through RCFW. The RCFW command queue code uses the generic `__get_cmdq_base_*()` and `__set_cmdq_base_*()` helpers when assigning cookies, response DMA addresses, response sizes, command sizes, and when looking up opcode/cookie for completions. For non-TLV messages, the helpers directly read/write the request's `cmdq_base`; for TLV messages with sufficient size, they operate on the embedded base command after the TLV header, except command size reads return the primary TLV total-size field.

State and persistence: this header has no standalone persistent state. It shapes transient command buffers and response side buffers passed to firmware. Correct cookies, response addresses, sizes, and flags are written into request memory before RCFW submission and persist only for the lifetime of that command buffer. Extended CC values sent through TLV commands can change firmware state, but the TLV helpers themselves only format transport envelopes.

Dependencies and integration points: depends on firmware TLV and command definitions from `roce_hsi.h`, endian helpers, and standard fixed-width integer types. `qplib_sp.c` uses the concrete TLV CC structures and preparation helpers. `qplib_rcfw.c` and `qplib_rcfw.h` use the generic accessors so the same RCFW send path can handle plain and TLV-encapsulated requests. Firmware constants such as `CMD_DISCR_TLV_ENCAP`, `TLV_TYPE_ROCE_SP_COMMAND`, `TLV_TYPE_MODIFY_ROCE_CC_GEN1`, `TLV_FLAGS_REQUIRED`, and `TLV_FLAGS_MORE` must remain aligned with the HSI definitions.

Risks: TLV detection casts arbitrary request memory to `struct tlv`, so callers must pass valid request buffers and correct sizes. The accessor guard is `size > TLV_BYTES`; a malformed TLV-sized request at exactly `TLV_BYTES` falls back to treating the TLV header as a plain command. `__set_cmdq_base_cmd_size()` writes the embedded base command's `cmd_size` for TLV messages, while `__get_cmdq_base_cmd_size()` reads the outer `total_size`; this split is intentional for RCFW submission but is easy to break. Header preparation does not clear structures; callers must zero-initialize command buffers before OR-ing flags in extension headers. Chunk counts are stored in `u8`, so future TLV structures must stay within 255 16-byte chunks. Padding and alignment are firmware-visible, so compiler packing assumptions and structure layout changes require careful review.

Test signals: build and run RCFW command submission for both plain and TLV commands, inspect command queue entries for correct cookie/resp_addr/resp_size/cmd_size placement, validate `CHUNKS()` and `total_size` against firmware HSI command lengths, query/modify RoCE CC on P5/P7 hardware, fuzz or unit-test accessor behavior for plain, TLV, too-small TLV, and malformed discriminator buffers, and run sparse/clang warnings for endian and pointer-cast issues after HSI structure updates.
