# sources/distributed-fs/coda/coda-src/venus/fso0.cc

Purpose: implements the top-level Venus file-system object database (`fsdb`) initialization, lookup, allocation, reclamation, flushing, callback invalidation, fid translation, and cache accounting. It is the entry point that turns persistent RVM fsobj metadata plus UFS container files into a live FSDB at Venus startup, and it is the main cache manager used by VFS operations when they call `FSDB->Get`.

Important APIs and flow: `FSOInit` creates or rehydrates `FSDB`, reconciles configured cache sizes and priority weights, resets transient structures, validates `CacheInfo`, creates preallocated `fsobj` slots on first initialization, validates every embedded `CacheFile`, calls each object's `ResetTransient` and `Recover`, resets freelist cache files, rebuilds parent-child links, attaches CML fid bindings through `VDB->AttachFidBindings`, writes a fresh data-version stamp, flushes/truncates RVM, and starts `FSOD_Init`. `fsdb::Find` searches by fid and has a special local-fid fallback for reintegration races, replacing stale kernel fids with `k_Replace`. `fsdb::Create` allocates a free/reclaimed fsobj, initializes it from a key/component, and optionally discovers or sets its parent. `fsdb::Get` is the central acquisition path: it handles volume context switching in `vproc`, creates missing objects after `VDB->Get`, waits for runt matriculation, performs GC, locks the object, updates component/parent metadata, fetches status with `GetAttr`, detects server/server conflict and fakeifies objects, decides whether data must be fetched or can be served stale, tries lookaside data, handles VASTRO container creation, launches ASR for repairable fake conflicts, updates replacement priority, and returns a read-locked fsobj.

State and persistence: persistent state includes `FSDB` fields stored in RVM, the hash table/free list, cache dimensions, priority weights, `LastRef`, and each fsobj's persistent metadata. Transient state is rebuilt in `fsdb::ResetTransient`: block usage, priority queue, deletion queue, open-for-write queue, cache statistics, recompute counters, and matriculation synchronization. Disk block accounting is centralized in `ChangeDiskUsage`, `AllocBlocks`, `FreeBlocks`, `DirtyBlockCount`, and `FreeBlockCount`, with special handling for open-for-write objects and VASTRO dirty data. Most mutating paths explicitly bracket RVM updates with `Recov_BeginTrans`/`Recov_EndTrans`.

Dependencies and integration points: depends on `fso.h` declarations, `CacheFile` validation, RVM recovery helpers, `VDB` volumes, `vproc` user/volume context, `worker` kernel purge/replace calls, `hdb` hoard bindings, `mariner` logs, local repair helpers, and Venus volume classes. It integrates with callback handling through `CallBackBreak`, with reintegration through `TranslateFid`, with global and volume-local cache flushes through `Flush`, and with the FSO daemon through priority/reclaim queues.

Risks and test signals: high-risk behavior includes startup recovery after partially fetched or open-for-write objects, cache block accounting drift, local fid translation races during reintegration, recursive flush while iterators are invalidated by object deletion, stale data access when objects are active or unreachable, ASR launch gating, and replacement priority ordering. Tests should cover cold start with mismatched `CacheInfo`, missing cache containers, local-fid lookup after translation, ENOSPC reclamation for fsobjs and blocks, callback demotion, global and per-volume flush, VASTRO-active flush behavior, server/server conflict fakeification, and `FSDB->Get` retry/error mapping for unreachable, resolving, dirty, and inconsistent volumes.

# sources/distributed-fs/coda/coda-src/venus/fso1.cc

Purpose: implements most `fsobj` lifecycle, status, rights, mount, priority, binding, data-discard, fake-object, synchronization, reporting, VASTRO selection, shadow-copy, ASR, and iterator behavior. Where `fso0.cc` manages the FSDB, this file defines how one cached filesystem object is allocated, recovered, invalidated, locked, prioritized, linked into directories/volumes, and made safe for replacement.

Important APIs and flow: custom `fsobj::operator new` allocates either new RVM storage or an object from the FSDB freelist. Constructors initialize preallocated slots or active objects; `ResetPersistent` clears recoverable object state, while `ResetTransient` rebuilds volume links, queue handles, locks/counters, replacement state, and bindings. `Recover` validates persistent state at startup, discards runts, queues dying objects, unmounts stale mount points, rebuilds priority, discards garbage from interrupted fetches, backs up unsafe open-for-write files into `SpoolDir`, drops invalid backup/non-root objects, and reconciles cache-file validity by type. `Matriculate`, `Demote`, `Kill`, `GC`, and `Flush` define the state transitions from runt to normal to dying/free-list return.

Status and access APIs include `UpdateStatus`, `StatusEq`, `ReplaceStatus`, replica-control rights (`SetRcRights`, `ClearRcRights`, `IsValid`), ACL cache handling (`CheckAcRights`, `SetAcRights`, `DemoteAcRights`, `PromoteAcRights`, `ClearAcRights`), `SetParent`, `MakeDirty`, and `MakeClean`. Mount support is handled by `TryToCover`, `CoverMtPt`, `UncoverMtPt`, `MountRoot`, and `UnmountRoot`, parsing `#`, `@`, and `$` mountlink formats and wiring mount points to volume roots. Parent/child and hoard bindings are maintained through `AttachChild`, `DetachChild`, `AttachHdbBinding`, `DetachHdbBinding`, and demotion helpers. CML dirty bindings are managed with `AttachMleBinding` and `DetachMleBinding`.

State and persistence: core persistent state includes fid, component, state, `VenusStat`, access rights, flags, parent fid, clean stat, shadow pointer, data descriptors, and the embedded `CacheFile`. Transient state includes volume pointers, linked-list handles, priority queue membership, mount union pointers, parent/child backpointers, locks and active counts, HDB/CML binding lists, active VASTRO segments, and ASR timestamps. `DiscardData` and `DiscardPartialData` update disk accounting and free file, directory, or symlink storage; VASTRO-active files preserve active ranges by extracting them to a `SegmentedCacheFile`, truncating, and injecting the ranges back.

Dependencies and integration points: depends on `FSDB`, `VDB`, `REALMDB`, `repvol`/`reintvol` volume behavior, `CacheFile`/`SegmentedCacheFile`, CML entries, hoard `namectxt` bindings, directory helpers, kernel purge functions, user tokens, server bandwidth/fetch-partial capability, RPC connection management, and ASR launcher configuration. `UpdateVastroFlag` integrates object size, free blocks, server partial-fetch support, bandwidth, and configured whole-file limits to decide whether the embedded cache file should switch into partial-cache mode.

Risks and test signals: risks include RVM/VM state mismatch during recovery, failure to detach all bindings before destruction, parent-child cycles or stale `pfso`, replacement queue corruption, mountpoint recursion and cross-realm rules, access-right promotion after token expiry, dirty-state/CML imbalance, VASTRO partial-data preservation under concurrent reads, shadow refcount leaks, and ASR token/process-group setup. Tests should exercise restart recovery for runt/fetching/owrite objects, mount/unmount/remount paths, callback demotion of hoard bindings, CML dirty attach/detach, lock promote/demote with waiters, `GetVattr` while writing, fake root/repair object creation, VASTRO threshold decisions, partial-data discard preserving active segments, and ASR launch failure cleanup.

# sources/distributed-fs/coda/coda-src/venus/fso_cachefile.cc

Purpose: implements the physical container-file abstraction used by Venus fsobjs. `CacheFile` maps an fsobj's cached data to a path under the cache directory, tracks logical length and valid data, validates ownership/mode/size, creates/truncates/copies/unlinks containers, and optionally maintains a bitmap of valid chunks for partial caching. `SegmentedCacheFile` is a temporary partial-cache helper used to extract and reinject active VASTRO ranges.

Important APIs and flow: constructors derive the container pathname from an integer slot, initialize length/valid-data/refcount/open count, and allocate a recoverable `bitmap7` plus lock when partial caching is enabled. `Validate` calls `ValidContainer` and resets invalid containers. `Create` builds parent paths with `mkpath`, opens/truncates the container, sets Coda ownership/mode, clears partial bitmaps, and initializes metadata. `Copy(CacheFile *)` copies both the UFS file and metadata/bitmap, while `Copy(char *, int)` writes the container to an arbitrary path, used for recovery/spool backup. `DecRef` clears partial metadata, resets length/valid-data, and unlinks when the refcount reaches zero. `Open`, `Close`, `FOpen`, and `FClose` track opener count around POSIX file descriptors.

Partial-cache behavior is controlled by `SetPartial`, `SetLength`, `SetValidData`, `UpdateValidData`, `ConsecutiveValidData`, `GetHoles`, `GetValidChunks`, and `CopySegment`. `SetPartial(false)` collapses valid data to the consecutive prefix so non-partial semantics remain consistent. `SetValidData(start,len)` marks whole cache-chunk blocks and the EOF tail valid; `UpdateValidData` recomputes byte totals from the bitmap, compensating for a short last block. `GetNextHole` scans bitmap ranges, `GetHoles` returns missing byte ranges, and `GetValidChunks` returns cached byte ranges. `CopySegment` aligns a range to chunk boundaries, copies only valid source chunks with `copyfile_seg`, copies bitmap ranges under a dual lock, and recomputes destination validity.

State and persistence: `length`, `validdata`, `refcnt`, `recoverable`, `isPartial`, and partial bitmap contents may be recoverable depending on constructor arguments. Container bytes live in UFS, so startup validation in `fso0.cc`/`fso1.cc` reconciles them with RVM metadata. `Truncate` optionally zeroes removed bytes under `option_isr`, persists metadata with `RVMLIB_REC_OBJECT`, updates or frees bitmap ranges, performs `ftruncate`, and leaves block accounting to callers.

Dependencies and integration points: depends on POSIX file APIs, `mkpath`, `copyfile`/`copyfile_seg`, RVM primitives, Venus cache constants (`V_UID`, `V_GID`, `V_MODE`, `option_isr`), `bitmap7`, LWP read/write locks, and chunk-size globals initialized elsewhere. It is embedded in `fsobj`, used by fetch/open/store/setattr paths, and cooperates with VASTRO read-intent and active-segment preservation.

Risks and test signals: risks include bitmap/validdata divergence, off-by-one chunk math in EOF tail handling, unit mistakes in `GetValidChunks` final `AddChunk`, races around partial bitmaps if callers miss locks, stale container ownership/mode after copy/create, fatal `CHOKE` on filesystem errors, and block-accounting drift because this class changes metadata but callers adjust FSDB usage. Tests should cover zero-length files, partial last chunks, sparse full-file fetch, partial fetch holes, shrink/extend transitions, `SetPartial` toggling with existing data, `CopySegment` over sparse holes, invalid container recovery, ISR truncation zeroing, refcount unlink behavior, and `SegmentedCacheFile` extract/inject round trips.

# sources/distributed-fs/coda/coda-src/venus/fso_cachefile.h

Purpose: declares the cache-container model used by Venus fsobjs, including cache-chunk geometry helpers, `CacheChunk`, `CacheChunkList`, `CacheFile`, and `SegmentedCacheFile`. The header documents the one-to-one static binding between an fsobj and its embedded `CacheFile`, while allowing the same descriptor to represent plain files or Unix-format directory containers at different times.

Important APIs and types: global chunk parameters (`CacheChunkBlockSize`, `CacheChunkBlockSizeBits`, `CacheChunkBlockSizeMax`, `CacheChunkBlockBitmapSize`) drive inline conversion/alignment helpers such as `bytes_to_ccblocks_ceil`, `align_to_ccblock_floor`, `ccblock_start`, `ccblock_end`, and `length_align_to_ccblock`. `CacheChunk` is a small dlist node with start, length, and validity flag. `CacheChunkList` wraps a `dlist` with an LWP read/write lock and exposes `AddChunk`, `ReverseCheck`, `ReverseRemove`, `ForEach`, `pop`, and lock primitives.

`CacheFile` exposes the main container API: construction/recovery, `Create`, POSIX open/close wrappers, `Validate`, `Reset`, file and metadata copy, refcounting, stat/utimes/truncate, metadata-only `SetLength`, valid-range updates, hole/valid-range discovery, name/length/valid-data accessors, `ConsecutiveValidData`, completeness/partial flags, `SetPartial`, and diagnostic printing. Protected `CopySegment` is shared with `SegmentedCacheFile`. `SegmentedCacheFile` derives from `CacheFile`, keeps an associated source/destination pointer, and provides `Associate`, `ExtractSegment`, and `InjectSegment` for temporary partial-cache preservation.

State and persistence: the header separates container pathname from metadata fields: logical length, valid-data bytes, refcount, open count, cached-chunk bitmap, recoverability flag, partial-cache flag, and read/write lock. The `REQUIRES_TRANSACTION` annotations identify methods that update recoverable state and must be called inside an RVM transaction, while `EXCLUDES_TRANSACTION` annotations identify validation/reset paths that open their own transactions or perform filesystem work outside active transactions.

Dependencies and integration points: depends on `bitmap7`, `dlist`, LWP locks, `FILE`/`stat` types from including translation units, and recovery annotations from the Venus build. It is included by `fso.h`, so the declarations are part of the core fsobj ABI. The chunk helpers are used by fetch, read-intent, and partial-cache paths to align user byte ranges to server/cache chunk ranges.

Risks and test signals: risks are API contract drift between inline chunk helpers and implementation, private inheritance from `dlist` making ownership easy to misuse, lock-order issues in dual-cache-file operations, unclear deletion ownership in `CacheChunkList::ReverseRemove`, and callers assuming `IsComplete` means contiguous data when partial bitmaps may encode non-contiguous validity. Tests should compile all consumers after chunk-size changes, verify boundary conversions at exact block edges and EOF tails, exercise list locking/removal/pop semantics, and validate that transaction annotations match actual call sites in fetch, open, setattr, recovery, and VASTRO segment code.

# sources/distributed-fs/coda/coda-src/venus/fso_cfscalls0.cc

Purpose: implements the first group of public/private CFS calls on `fsobj`: data fetch, status/ACL fetch and validation, local/disconnected store and setattr, connected setacl, and file creation. It bridges `fsdb::Get` object decisions to Vice RPCs, RPC2/SFTP transfer descriptors, replicated-volume mgroup collation, non-replicated connection handling, COP2 piggybacking, cache-file valid-data updates, CML logging, and local RVM state mutation.

Important APIs and flow: fetch support starts with `GetContainerFD`, `LookAside`, `FetchFileRPC`, `CheckTransferredData`, and `Fetch`. `Fetch` asserts the object is reachable, clean, non-local, non-fake, and has status. It computes an offset/length from VASTRO range requests or consecutive valid data, creates a SmartFTP descriptor to a file descriptor or VM/RVM directory/symlink buffer, marks `flags.fetching`, acquires either a replicated mgroup primary connection or a non-replicated connection, performs `ViceFetchPartial` when supported or `ViceFetch`, validates transferred byte counts and version/data-version, updates `cf.SetValidData`, updates status, records callbacks as replica-control rights when no callback break raced, and discards/demotes data on failed validation. `LookAside` uses the saved SHA to fill a container without RPC transfer and only promotes validity if callbacks did not change during the operation.

`GetAttr` and `GetACL` implement status and ACL acquisition. For read-write volumes, `GetAttr` builds common multi-RPC parameters, optionally piggybacks validation of other stale fsobjs in the same volume with `ViceValidateAttrsPlusSHA`, collates per-server validation flags, kills or demotes invalid piggybacked objects, calls `ViceGetAttrPlusSHA` or `ViceGetACL`, performs RVV/dominant-host checks on replicated responses, stores SHA for lookaside, updates status/access rights, handles volume callback state, schedules asynchronous resolution, and maps ENXIO/ENOENT/inconsistency into cache actions. For read-only/non-RW volumes it uses single RPC calls and DataVersion validation. `GetACL` returns a synthetic ACL for local objects and otherwise delegates to `GetAttr`.

Mutation APIs follow the local/disconnected split. `LocalStore` updates DataVersion, length, mtime, cache-file length/valid-data, SHA, and stats inside a transaction. `DisconnectedStore` logs a CML store on read-write replicated volumes and then calls `LocalStore`; public `Store` treats pioctl files locally and kills the object on unretryable failure. `LocalSetAttr`, `DisconnectedSetAttr`, and `SetAttr` compute changed size/time/owner/mode, create missing zero-length containers when needed, truncate open-for-write containers directly, log setattrs, update local metadata, clear SHA, and demote on failure. `SetACL` is connected-only for non-fake/non-local clean objects: it generates a store id, performs `ViceSetACL` via multi or single RPC, collates COP1/COP2 and volume callbacks, updates status with an update set, then demotes cached rights. `LocalCreate`, `DisconnectedCreate`, and `Create` allocate a new fid/fsobj, log creation, mutate parent directory data, initialize the new file object/container, set `CleanStat`, and clean up unmatriculated targets on failure.

State and persistence: persistent updates are wrapped in RVM transactions and include `flags.fetching`, `data.file`/`data.dir`/`data.symlink`, cache-file metadata, `VenusStat`, SHA, access rights, directory entries, clean stats, and CML records. Transfer bytes live in UFS containers or RVM/VM directory buffers. Callback race tracking uses `cbbreaks`; a callback break during fetch/lookaside/getattr prevents optimistic validity promotion. Cache statistics are updated for hits, writes, replacement, no-space, and creates.

Dependencies and integration points: depends on `ViceFetch`, `ViceFetchPartial`, `ViceGetAttrPlusSHA`, `ViceValidateAttrsPlusSHA`, `ViceGetACL`, `ViceSetACL`, RPC2/SFTP descriptors, `mgrpent` and `connent`, `repvol`/`volrep` collation and CML logging, COP2/COP1 helpers, `CacheFile` partial-range methods, `FSDB` block allocation/accounting, directory helpers, lookaside SHA support, Mariner progress logging, worker/vproc context, and kernel callback state.

Risks and test signals: risks include mismatched transfer lengths for partial fetches, EOF/chunk alignment errors, validity promotion after callback races, divergent handling between replicated and non-replicated volumes, piggyback validation killing active objects incorrectly, ENXIO volume-wide kill blast radius, failure cleanup leaving `flags.fetching` or open fds set, SHA not being recorded in the read-only branch because `SHAval` is not tied back to `mysha`, local setattr block delta signs, pioctl special cases, and CML log/local-state double-apply with `prepend`. Tests should cover full and partial fetches, VASTRO hole fetches, lookaside success with/without callback races, replicated RVV/DH mismatch, piggyback validation success/failure, read-only DataVersion mismatch, store and setattr CML logging, truncate while open for write, setacl conflict/retry mapping, create allocation rollback, and crash recovery during `flags.fetching`.
