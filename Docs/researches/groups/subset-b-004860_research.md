# sources/distributed-fs/ceph-client/drivers/net/wireless/mediatek/mt76/mt7996/init.c

Purpose: Initializes and registers the MediaTek mt7996/mt7992/mt7990 Wi-Fi device family with mt76 and mac80211. It publishes wiphy/mac80211 capabilities, configures per-band PHY capability data, initializes DMA/MCU/EEPROM/RRO/WED/NPU-facing resources, sets thermal and LED integration, and tears those resources down on unregister.

Important APIs, types, and functions: `mt7996_register_device()` is the main device registration path after PCI/MMIO setup. `mt7996_init_hardware()` performs low-level bring-up: interrupt cleanup, work/list/lock initialization, variant detection, DMA initialization, MCU initialization, RRO allocation, FEM/eeprom parsing, and global WCID allocation. `mt7996_init_wiphy()` and `mt7996_init_wiphy_band()` populate `struct ieee80211_hw`, `struct wiphy`, `struct wiphy_radio`, and supported band data. `mt7996_register_phy()` allocates and registers secondary radios. `mt7996_mac_init()`, `mt7996_txbf_init()`, `mt7996_init_txpower()`, `mt7996_set_stream_vht_txbf_caps()`, and `mt7996_set_stream_he_eht_caps()` configure MAC registers and advertised HT/VHT/HE/EHT capabilities. Thermal entry points expose hwmon attributes and `thermal_cooling_device_ops`. RRO/WED helpers include `mt7996_wed_rro_init()`, `mt7996_rro_hw_init()`, `mt7996_wed_rro_work()`, and `mt7996_wed_rro_free()`.

Control flow: Registration initializes embedded `dev->phy`, work items (`init_work`, reset/dump work elsewhere), rate-control and TWT lists, reset waitqueue, and dump mutex. Hardware bring-up first prepares DMA and MCU, then allocates host-side RRO memory before reading EEPROM and reserving global WCID 0. Wiphy setup advertises interface combinations, MLO, multi-BSSID, scan limits, offloads, radiotap timestamps, hardware queue counts, and per-band frequency ranges. Secondary PHY registration validates band availability, chooses HIF/WED context for the band, allocates an mt76 radio, derives MAC address from EEPROM with local fallback, configures band capabilities, initializes TX rings or shares an existing ring in selected mt7996/NPU modes, and registers with mt76. After device registration, thermal devices are attached per PHY, `init_work` pushes EEPROM, MAC, TXBF, and duplicate WTBL setup to firmware, and debugfs/coredump registration completes the path. Unregister cancels work, removes thermal/coredump hooks, unregisters mt76, frees RRO memory, exits MCU, releases tokens, cleans DMA, frees RRO page maps when needed, disables IRQ tasklet, and frees the mt76 device.

State and persistence behavior: The file mutates durable runtime driver state in `struct mt7996_dev`, `struct mt7996_phy`, and nested mt76 structures: variant type/FEM, `has_eht`, radio arrays, chain/antenna masks, wiphy feature flags, iface combinations, txpower per channel, WCID masks, WED RRO coherent allocations, RRO page cache/list heads, thermal throttle thresholds/states, cooling-device pointer, and LED callbacks. EEPROM-derived MAC addresses and power limits are read from device storage but only cached in runtime structures. DMA coherent RRO buffers persist until explicit unregister/free. Thermal sysfs writes update `phy->throttle_temp[]` and immediately send MCU thermal protection state.

Dependencies and integration points: The implementation sits between Linux mac80211/cfg80211 (`ieee80211_hw`, `wiphy`, bands, interface combinations, EHT/HE/VHT capabilities), mt76 core allocation/registration/DMA/token helpers, MediaTek WED/NPU acceleration, MCU command helpers from `mcu.h`, EEPROM accessors from `eeprom.h`, coredump support, hwmon/thermal subsystems, OF property parsing, and register macros in mt7996 headers. WED RRO setup passes physical addresses to WED/NPU when active and programs RRO host registers directly. Regulatory changes flow through `mt7996_regd_notifier()`, which updates alpha2/DFS region, tx power, DFS state, and radar detector programming.

Risks and edge cases: Bring-up is heavily ordered: DMA, MCU, WED RRO allocation, EEPROM, and WCID reservation must succeed before registration can continue. Error unwinds in `mt7996_register_phy()` clear `phys[band]` but rely on caller/device teardown for previously allocated resources. Capability publication is variant- and band-dependent; wrong `is_mt7996/is_mt7992/is_mt7990` branches can advertise unsupported MLO, EHT, 320 MHz, TXBF, or ring topology. RRO coherent allocation has multiple optional arrays whose hardware programming differs by HWRRO v3/v3.1, WED, and NPU mode. Thermal threshold validation enforces a 10 degree margin, so sysfs boundary tests matter. `mt7996_wed_rro_work()` resets session memory under spin/list coordination and must not race unregister or hardware reset. Global and per-phy interface combination limits must match firmware WTBL/resource limits.

Test signals: Useful validation includes probe/register/unregister on mt7996, mt7992, and mt7990 variants; secondary PHY registration for all valid/invalid band masks; WED active/inactive and NPU active/inactive paths; HWRRO v3 and v3.1 allocation and register programming; thermal hwmon reads/writes and cooling state changes; regulatory notifier with DFS unset/FCC/ETSI/JP; TX power recalculation from EEPROM/regulatory limits; LED blink/brightness callbacks; coredump/debugfs registration failure unwind; and module remove after active RRO sessions/tokens.

# sources/distributed-fs/ceph-client/drivers/net/wireless/mediatek/mt76/mt7996/mac.c

Purpose: Implements mt7996 MAC datapath and maintenance logic: RX descriptor decoding, TXWI/TXP construction, TX completion and status accounting, WED/NPU/RRO receive processing, station airtime/RSSI polling, MIB/noise/stat updates, reset recovery, coredump collection, DFS radar control, and TWT agreement scheduling.

Important APIs, types, and functions: RX path entry points are `mt7996_rx_check()`, `mt7996_queue_rx_skb()`, `mt7996_mac_fill_rx()`, `mt7996_mac_fill_rx_rate()`, and mesh/header translation helper `mt7996_reverse_frag0_hdr_trans()`. TX construction uses `mt7996_tx_prepare_skb()`, `mt7996_mac_write_txwi()`, `mt7996_mac_write_txwi_8023()`, `mt7996_mac_write_txwi_80211()`, and WED buffer initializer `mt7996_wed_init_buf()`. Completion/status handling uses `mt7996_mac_tx_free()`, `mt7996_txwi_free()`, `mt7996_mac_add_txs_skb()`, and `mt7996_mac_add_txs()`. RRO helpers include page cache/map functions, `mt7996_rro_msdu_page_add()`, `mt7996_rro_rx_process()`, `mt7996_rro_msdu_page_map_free()`, and token cleanup. Maintenance functions include `mt7996_mac_reset_work()`, `mt7996_mac_full_reset()`, `mt7996_mac_restart()`, `mt7996_reset()`, `mt7996_mac_dump_work()`, `mt7996_mac_work()`, `mt7996_mac_update_stats()`, and DFS/TWT helpers.

Control flow: Normal RX dispatch inspects packet type. TX-free, TX-status, MCU event, and firmware monitor packets are consumed internally; normal frames are parsed by `mt7996_mac_fill_rx()` and then passed to `mt76_rx()`. RX parsing selects PHY by descriptor band, validates running state and descriptor groups, resolves WCID including MLO link remapping, fills checksum/decrypt/FCS/MIC/radiotap/rate/AMPDU metadata, handles AMSDU and header-translation padding, reconstructs mesh fragment headers where hardware cannot, runs WED/NPU PPE checks for 802.3 frames, and sets reorder metadata for QoS data. TX preparation chooses the WCID/link for MLO and offchannel cases, consumes an mt76 token, optionally rewrites EAPOL link addresses in software, emits TXWI plus TXP descriptors, handles special AddBA TXP format, maps DMA buffer references, and leaves completion to token release. TX-free events clean DMA queues, parse WCID-pair and MSDU-ID records, update retry/fail stats, release tokens, complete skbs, poll station airtime/RSSI, and wake blocked TX. Reset control either performs L1 SER DMA stop/reinit or a full firmware crash recovery with coredump, queue stop, NAPI disable/enable, DMA reset, firmware reload, RRO/WED restart, and mac80211 restart.

State and persistence behavior: Runtime state spans `dev->mt76.token` IDR, TXWI caches, RX token cache, RRO `page_cache`/`page_map`, per-queue `rx_head`, `phy->rx_ampdu_ts`, `phy->ampdu_ref`, `phy->noise`, per-WCID tx stats/rate/AMPDU state, station poll lists, `dev->recovery` flags and counters, TWT list/table masks, MIB counters, and DFS state. No durable persistence is written, but the file maintains hardware-visible descriptor/token/order state and coherent RRO page ownership. Coredump work copies firmware memory regions into coredump buffers before submitting them. TWT agreement state is held in `dev->twt` and per-station link flow arrays until teardown.

Dependencies and integration points: The file depends on mt76 DMA/token/queue/page-pool helpers, mac80211 station/vif/TWT/AMPDU APIs, connac3 radiotap and PPE decode helpers, MCU commands for BA/rate/RDD/TWT/reset, WED/NPU acceleration hooks, register definitions for RXD/TXD/TXS/RRO/MIB/DFS, Linux NAPI/sk_buff/DMA sync primitives, coredump support, and DFS regulatory state from cfg80211. It integrates with `main.c` through station/TWT/AMPDU callbacks and with `init.c` through MAC/RRO/reset initialization and unregister cleanup.

Risks and edge cases: Descriptor parsing is field- and group-order sensitive; malformed RXD lengths are guarded but can still expose edge cases in padding/header translation. MLO link resolution must not dereference missing link structures; several paths rely on RCU. `mt7996_mac_sta_poll()` computes RSSI and airtime from WTBL registers and contains a suspicious fourth RSSI extraction mask (`GENMASK(31, 14)`) that should be reviewed against hardware layout. Token accounting is central: leaked tokens block TX, while premature release can complete the wrong skb. RRO processing mixes DMA sync, page-pool ownership, sequence-window signatures, and skb construction; bad length or missing token handling can leak buffers or corrupt `rx_head`. Reset work must avoid NAPI/worker races and has different skip rules for WED RRO and NPU queues. TWT scheduling assumes individual implicit agreements with 256 us duration units and simple gap placement in a shared list. DFS state transitions must match regulatory CAC/active/disabled states.

Test signals: Cover normal RX for legacy/HT/VHT/HE/EHT rates, checksum/decrypt flags, FCS/MIC errors, AMSDU and mesh A4 cases, header translation failures including VLAN, multicast fragment drops, WED/NPU PPE metadata, TXWI generation for 802.3/802.11/mgmt/beacon/AddBA/EAPOL/MLO, TX-free version 5/7 records, TXS rate/stat updates, AMPDU auto-start, RRO page add/process/free with multi-page MSDUs and bad signatures, L1 SER reset, full WDT coredump reset, DFS CAC/active/stop transitions, periodic MIB/noise updates, and TWT accept/reject/teardown flows.

# sources/distributed-fs/ceph-client/drivers/net/wireless/mediatek/mt76/mt7996/mac.h

Purpose: Provides the mt7996 MAC-facing header needed by the C files in this subset. It includes shared connac3 MAC definitions and defines packed DFS/radar pattern structures used when programming or interpreting radar detector parameters.

Important APIs and types: `struct mt7996_dfs_pulse` describes pulse constraints in host-friendly units and signed power thresholds: maximum width, maximum/minimum power, staggered PRI range, and constant-radar PRI range. `struct mt7996_dfs_pattern` is the packed hardware/firmware layout with enable/stagger flags, CR/STG pulse counts, pulse width, PRI ranges, reserved bytes, and minimum stagger PRI difference. The header includes `../mt76_connac3_mac.h`, exposing common RX/TX descriptor and radiotap decode definitions to mt7996 code.

Control flow: The header has no executable control flow. It shapes data passed to MAC/MCU radar handling code in `mac.c` and related mt7996 MCU implementation files. The `__packed` annotation on `mt7996_dfs_pattern` is a control-plane ABI decision: callers can serialize the structure without compiler-inserted padding.

State and persistence behavior: The header owns no runtime state. Its structures describe transient DFS/radar configuration or match data. Because the packed layout is part of the firmware/hardware command contract, changing fields or alignment would affect persistent driver-firmware compatibility even though the file itself stores nothing.

Dependencies and integration points: It is included by `init.c`, `mac.c`, and `main.c` in this subset, and by other mt7996 files that need connac3 MAC definitions or DFS pattern structures. The definitions integrate with cfg80211 DFS states, MCU RDD commands, and register/firmware layouts declared elsewhere.

Risks and edge cases: The structures use fixed-width integer fields and packed layout; any reordering, type widening, or removal of reserved bytes can break firmware interpretation. `mt7996_dfs_pulse` uses `int` for power values while `mt7996_dfs_pattern` uses small unsigned fields, so conversions must clamp and encode carefully in the producer code. The header guard is conventional and prevents duplicate definitions.

Test signals: Compile coverage of all mt7996 MAC/MCU files, static layout checks if available for `sizeof(struct mt7996_dfs_pattern)`, and runtime DFS/RDD tests that start radar detectors for FCC/ETSI/JP regions and verify firmware accepts the encoded pattern data.

# sources/distributed-fs/ceph-client/drivers/net/wireless/mediatek/mt76/mt7996/main.c

Purpose: Implements the mac80211 operation table for mt7996. It connects cfg80211/mac80211 callbacks to MCU/MAC/mt76 operations for starting radios, interface/link lifecycle, key programming, channel changes, filter settings, station state, TX selection, AMPDU, TSF, antenna/txpower, bitrate/rate-control updates, TWT, radar background detection, fast-forward path setup, MLO link changes, and reconfiguration.

Important APIs, types, and functions: `const struct ieee80211_ops mt7996_ops` is the exported callback table. Radio lifecycle functions include `mt7996_run()`, `mt7996_start()`, `mt7996_stop_phy()`, `mt7996_add_interface()`, and `mt7996_remove_interface()`. Link and vif management is handled by `mt7996_vif_link_add()`, `mt7996_vif_link_remove()`, `mt7996_vif_link_destroy()`, `mt7996_change_vif_links()`, `mt7996_vif_cfg_changed()`, and `mt7996_link_info_changed()`. Station management uses `mt7996_sta_state()`, `mt7996_mac_sta_add()`, `mt7996_mac_sta_init_link()`, `mt7996_mac_sta_change_links()`, `mt7996_mac_sta_event()`, and `mt7996_mac_sta_remove_link()`. Other important callbacks include `mt7996_set_key()`, `mt7996_set_channel()`, `mt7996_tx()`, `mt7996_ampdu_action()`, TSF helpers, ethtool stats helpers, `mt7996_set_radar_background()`, `mt7996_net_fill_forward_path()`, and `mt7996_set_eml_op_mode()`.

Control flow: Starting an interface can lazily run each radio in the interface radio mask; `mt7996_run()` enables noise-floor tracking, RTS threshold, radio, channel RX path, thermal throttling/protection, running state, watchdog work, and initial counters. VIF link add allocates mt76 vif index, OMAC, MLD ID, and reserved BMC WCID, tells firmware about dev/BSS/station state, installs existing group keys, initializes rate tables and beacon monitoring, and marks valid links. Link removal either destroys offchannel links immediately or, for AP active links, asks firmware to stop MLD operation and defers full destroy until interface removal. Station add/change/remove allocates per-link WCIDs, tracks primary/secondary MLO links for TX steering, updates WTBL/firmware station records, adjusts per-phy station counts, tears down TWT flows on disassociation, and cleans RCU pointers. TX path chooses a link-specific WCID/PHY under RCU, rewrites MLO link addresses in the 802.11 header when needed, handles remain-on-channel offchannel links, and calls `mt76_tx()`. Channel and BSS changes update firmware channel/RX path, txpower SKU, DFS detector state, beacons, protection, timing, BSS color, QoS/txcmd, OBSS, MU groups, in-band discovery, and station bandwidth records.

State and persistence behavior: Runtime state includes radio running bits, per-phy `rxfilter`, `slottime`, `txpower`, `coverage_class`, `omac_mask`, per-vif valid/default links, MLD group/remap masks, per-link WMM/basic/mcast/beacon rate indexes and bitrate masks, per-link BMC WCIDs, per-station primary/secondary link IDs, per-link WCID/key/rate/TWT state, beacon monitor intervals, ethtool/MIB snapshots, radar background PHY/chandef, and mac80211 active-link state. No durable storage is written; state is mirrored into firmware through MCU commands and into hardware registers for filters, TSF, MU groups, and coverage timing.

Dependencies and integration points: This file is the high-level integration layer for mac80211/cfg80211 callbacks, mt76 common channel context, scan, remain-on-channel, survey, antenna, TX queue, WED/NPU net path helpers, MCU commands, MAC helpers from `mac.c`, capability setup from `init.c`, Linux ethtool stats, netdev path offload (`DEV_PATH_MTK_WDMA`), thermal/radar behavior configured elsewhere, and optional debugfs/WED/NPU build features. It relies on `dev->mt76.mutex` for most firmware/hardware updates and RCU for live vif/station link lookups.

Risks and edge cases: Resource allocation spans several masks (`vif_mask`, `mld_idx_mask`, `mld_remap_idx_mask`, `omac_mask`, WCID mask), so error paths must avoid leaking IDs. `mt7996_vif_link_destroy()` initializes its key iterator with `SET_KEY` even on destruction; that deserves review because the helper name suggests key re-add rather than key removal, though surrounding firmware teardown may make it intentional. MLO TX steering uses primary/secondary links and TID parity; missing link structures fall back in several places and can drop frames if no PHY is available. Key programming has special BIGTK handling and intentionally falls back to software for some mesh/IBSS group keys and unsupported ciphers. `mt7996_stop()` is empty, so actual radio stop depends on interface removal and per-phy logic. Channel switch and radar background code must be correct during CAC and multi-radio operation. Ettool station stats primarily use the default link, which may underrepresent multi-link peers. Fast-forward path setup must choose correct WED instance for HIF2/NPU and reject invalid WCIDs.

Test signals: Exercise add/remove interface for AP/STA/mesh/monitor, multi-radio radio masks, VIF link add/remove/change for MLO and non-MLO, station add/assoc/authorize/disassoc/remove including multi-link changes, key add/remove for pairwise/group/BIGTK and unsupported ciphers, channel switch with DFS CAC and beacon reset, monitor filter toggling, tx path for MLO/offchannel/EAPOL/data/mgmt, AMPDU RX/TX start/stop, TSF read/write/offset, antenna mask changes and capability re-publication, ethtool stats size/value alignment, TWT setup/teardown, radar background busy/disable cases, WED/NPU forward path setup, and reconfig completion after reset.
