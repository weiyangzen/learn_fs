# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/gc/gc_9_4_1_offset.h

Purpose: generated AMDGPU GFX9.4.1 GC register-offset catalog. It gives the driver symbolic `mm*` register names and `*_BASE_IDX` segment selectors for the Arcturus-era GFX 9.4.1 graphics core, especially GRBM targeting/status registers and RAS/ECC counter registers used by `amdgpu/gfx_v9_4.c`.

Important APIs, types, and functions: this header exports preprocessor constants only. There are no C functions, types, or inline helpers. The important exported families are `mmGRBM_*` for graphics register bus manager control/status and instance selection, `mm*_EDC_*` registers for ECC/error detection counters across CP, GDS, SPI, SQ/SQC, TA/TD, TCP/TCI/TCC/TCA, GCEA, UTCL2/VML2, and RLC blocks, and the paired `*_BASE_IDX` constants. `mmGRBM_GFX_INDEX` is the key register for selecting SE/SH/instance views before indexed reads. `mmGCEA_ERR_STATUS` is the key fatal/status register consulted before reset. `mmATC_L2_*_DSM_*`, `mmVML2_*_ECC_*`, and `mmUTCL2_MEM_ECC_*` define indexed ECC status windows. The `*_BASE_IDX` values feed `SOC15_REG_ENTRY(ip, inst, reg)`, where `soc15.h` expands them into hardware IP, instance, segment, and register offset fields.

Control flow: the file itself has no executable control flow. Runtime flow is indirect: callers include this header, build `struct soc15_reg_entry` tables with `SOC15_REG_ENTRY(GC, 0, mm...)`, then use `RREG32_SOC15`, `WREG32_SOC15`, `SOC15_REG_ENTRY_OFFSET`, or RLC-shadowed writes to read or write the resolved MMIO address. In `gfx_v9_4.c`, `gfx_v9_4_edc_counter_regs[]` lists these offsets for reset/query walks, `gfx_v9_4_select_se_sh()` writes `mmGRBM_GFX_INDEX` to select a shader engine, shader array, or instance, and the RAS paths iterate the offset table to collect and reset ECC counters. For indexed UTCL2/VML2/ATC memories, the driver writes an `*_INDEX` register, reads the matching `*_CNTL`, then restores the index to 255.

State and persistence behavior: the header stores no state. The persistent state is the hardware MMIO register file and the graphics block counters/status bits those offsets address. Many exported registers are hardware counters for single-correctable and double-uncorrectable errors; writing or reading behavior is defined by the ASIC, not by this header. Software persistence is limited to compiled-in constants. A wrong offset or base index persists as a driver ABI bug until the generated header is fixed.

Dependencies: depends only on C preprocessing and the AMDGPU SOC15 register infrastructure. Consumers rely on `GC_HWIP` and the per-device `adev->reg_offset[hwip][inst][seg]` tables to turn these relative offsets into real addresses. The companion `gc_9_4_1_sh_mask.h` supplies field masks for many of the same registers. The register names are also coupled to AMD's generated ASIC register naming conventions; changing a name breaks `SOC15_REG_ENTRY` and `SOC15_REG_FIELD` users at compile time.

Integration points: directly included by `sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdgpu/gfx_v9_4.c` together with `gc_9_4_1_sh_mask.h`. There it backs GFX RAS ECC counter enumeration, counter reset/query, GRBM broadcast/index selection, UTCL2/VML2 memory ECC sweeps, and GCEA error-status harvesting before GPU reset. The same macro names also match cross-generation AMDGPU register helper patterns, so this file must stay aligned with `soc15.h` macros and with the generated mask header.

Risks and edge cases: register metadata is safety-critical because an incorrect offset can read the wrong hardware block, clear the wrong counter, or target only one segment instead of the intended broadcast/instance view. `mmTA_EDC_CNT` appears twice in two `gc_tpdec` address-block sections with the same value, which is harmless as an identical macro definition but is still a generated-header duplication to watch during regeneration. Base-index `0` versus `1` matters: GRBM scratch and many EDC counters use segment 0, while `gc_gfxudec` scratch/GRBM index and RLC counters use segment 1. Some registers are indexed windows, so tests must verify both index and data register offsets. Because this is generated metadata, manual edits are high-risk and should be avoided unless mirrored from the authoritative register source.

Test signals: strongest signals are build coverage of `gfx_v9_4.c`, compile-time resolution of every `mm*` macro used in `SOC15_REG_ENTRY`, and runtime RAS tests on GFX9.4.1 hardware or emulation. Useful runtime checks include successful GRBM broadcast restore to `0xe0000000`, correct per-instance counter traversal under `adev->grbm_idx_mutex`, ECC counter reset/query paths reading expected nonzero/zero values, and GCEA status warnings when `SDP_RDRSP_STATUS`, `SDP_WRRSP_STATUS`, or data-parity bits are injected. Static checks can diff the 101 register-offset definitions and their base indexes against the vendor-generated register database and against the companion mask file.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/gc/gc_9_4_1_sh_mask.h

Purpose: generated AMDGPU GFX9.4.1 GC bitfield catalog. It maps named register fields to `__SHIFT` and `_MASK` constants so AMDGPU code can extract, set, and report SEC/DED ECC counts, GRBM instance-selection fields, indexed memory ECC counts, and GCEA error status without open-coded bit arithmetic.

Important APIs, types, and functions: this header exports preprocessor constants only. There are no functions, structs, or storage. Its naming contract is `REGISTER__FIELD__SHIFT` plus `REGISTER__FIELD_MASK`. `soc15.h` consumes that shape through `SOC15_REG_FIELD(reg, field)`, which expands to the mask and shift pair used in `struct soc15_ras_field_entry`. Generic register helpers such as `REG_SET_FIELD()` and `REG_GET_FIELD()` also depend on the same names. Important register groups include CP/CPC/DC counters, GDS and SPI EDC counters, SQC/SQ counters, TA/TD/TCP/TCI/TCC/TCA counters, GCEA EDC and `GCEA_ERR_STATUS`, `GRBM_GFX_INDEX`, ATC L2 DSM selectors/counters, VML2/UTCL2 ECC selectors/counters, and RLC/RLC2 counters. The file contains 50 commented register sections with field definitions for most of the offsets in the companion file.

Control flow: the header itself has no executable flow. Runtime control is created by consumers. In `gfx_v9_4_select_se_sh()`, `REG_SET_FIELD(..., GRBM_GFX_INDEX, INSTANCE_INDEX/SE_INDEX/SH_INDEX/ *_BROADCAST_WRITES, ...)` uses these masks and shifts to construct a GRBM selector value before writing `mmGRBM_GFX_INDEX`. In the RAS field table, `SOC15_REG_FIELD(RLC_EDC_CNT2, RLC_SPM_SE0_SCRATCH_RAM_SEC_COUNT)` and similar entries expand to counter mask/shift pairs. Query paths read an EDC register and use the stored mask/shift to isolate SEC or DED subfields. The GCEA status query reads `mmGCEA_ERR_STATUS` and uses `REG_GET_FIELD()` with `SDP_RDRSP_STATUS`, `SDP_WRRSP_STATUS`, and `SDP_RDRSP_DATAPARITY_ERROR` to warn before reset.

State and persistence behavior: the file contains no mutable state. The fields describe hardware state inside GC registers: saturating or sticky ECC counters, status bits, broadcast selectors, and indexed memory selector fields. Some fields are read-only counters/status, while fields such as `GRBM_GFX_INDEX` selector and `GCEA_ERR_STATUS__CLEAR_ERROR_STATUS` are write-sensitive control/status bits; the header does not encode access permissions, clear-on-write semantics, or counter width behavior beyond the masks.

Dependencies: depends on the companion `gc_9_4_1_offset.h` for the actual register addresses and on AMDGPU helper macros that expect this exact generated naming convention. It integrates with `soc15.h` through `SOC15_REG_FIELD`, with register access helpers through `REG_GET_FIELD`/`REG_SET_FIELD`, and with the RAS infrastructure through `struct soc15_ras_field_entry`. It is also semantically tied to the ASIC register database for GFX9.4.1; cross-generation headers have similar but not identical fields.

Integration points: directly included by `amdgpu/gfx_v9_4.c`. That file uses the mask constants to build the human-readable RAS field table for ECC counters, to select GRBM instances safely, and to inspect GCEA fatal/error status. The UTCL2/VML2/ATC indexed ECC code relies on the matching `INDEX` and `CNTL` field definitions even when it mostly reads whole registers. The report path maps mask/shift pairs to named RAS fields such as `RLC_SPM_SE7_SCRATCH_RAM`, `EA_MAM_A*MEM`, `TCP_*`, and `SQC_*`, so field names are part of diagnostic output quality as well as bit extraction.

Risks and edge cases: field-name drift is the largest risk. `SOC15_REG_FIELD` creates symbol names by concatenation, so any generated rename breaks compilation; any wrong mask or shift silently misreports or mis-clears hardware state. Several hardware names use `SED` rather than `SEC` in places such as `DB_RAM_SED_COUNT` and GCEA page-memory fields; these should not be normalized by hand because the consumer symbols must match the generated header. `GCEA_ERR_STATUS` includes both status and control-like bits, so using a full-register write instead of field-aware access could clear or alter error state. The `GRBM_GFX_INDEX` broadcast bits occupy the top bits of the register; bad masks can leave the driver targeting a single instance instead of broadcast restore. The comment-only `ATC_L2_CNTL` marker has no field macros in this file, so code must use only actually defined fields.

Test signals: compile tests should cover every `SOC15_REG_FIELD`, `REG_GET_FIELD`, and `REG_SET_FIELD` use in `gfx_v9_4.c`. Static validation should compare each mask/shift pair with the vendor register source and with expected mask/shift consistency, especially for full-width two-bit counter lanes. Runtime signals include correct per-field SEC/DED extraction in RAS query output, successful reset of all counter fields, correct GRBM selector programming for broadcast and per-instance reads, and injected GCEA status bits triggering the warning path before GPU reset. Hardware or simulator tests should include indexed VML2/UTCL2/ATC memory ECC sweeps because those combine index-register offsets from the offset header with count-field masks from this header.
