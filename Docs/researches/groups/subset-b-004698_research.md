# sources/distributed-fs/ceph-client/drivers/net/plip/plip.c

Purpose: Implements the Linux PLIP network driver for LapLink-style parallel-port cables. It presents an Ethernet-like point-to-point netdev over the parport subsystem, using the Crynwr nibble protocol to transfer packet length, payload bytes, and checksum over five status/data lines.

Important APIs, types, and functions: `struct net_local` is the per-netdev state, holding parport ownership, delayed/immediate work items, send/receive `struct plip_local` protocol state, timeout tunables, connection state, and locking. `struct plip_local` tracks packet phase (`PLIP_PK_*`), nibble phase (`PLIP_NB_*`), length, checksum, byte index, and the active SKB. `plip_init_netdev()` sets point-to-point Ethernet-style netdev operations and default fake address. `plip_receive()` and `plip_send()` implement the two-nibble byte handshake. `plip_receive_packet()`, `plip_send_packet()`, `plip_connection_close()`, and `plip_error()` form the state-table driven bottom-half protocol engine. `plip_interrupt()` detects remote transmit triggers. Netdev entry points are `plip_open()`, `plip_close()`, `plip_tx_packet()`, `plip_hard_header()`, `plip_hard_header_cache()`, and `plip_siocdevprivate()`. Parport integration is in `plip_attach()`, `plip_preempt()`, `plip_wakeup()`, `plip_probe()`, and module init/exit.

Control flow: Module init registers a `parport_driver`; matching ports call `plip_attach()`, which allocates an Ethernet netdev, registers a parport device model with preempt/wakeup/IRQ callbacks, initializes the PLIP state machine, and registers the netdev. Opening claims the parport, clears the data lines, enables parport IRQs or starts a polling delayed work when no IRQ exists, initializes packet state, and starts the queue. TX claims the port if needed, stops the queue, stores the outgoing SKB in `snd_data`, marks `PLIP_PK_TRIGGER`, and schedules immediate work. The work item dispatches by `nl->connection`: send mode verifies idle status, triggers the peer, sends length/payload/checksum nibbles, closes the connection, and wakes the queue after a close delay; receive mode ACKs a trigger, reads length and payload, verifies checksum, calls `netif_rx()`, and then either resumes pending send or idles. IRQ or polling detects status `0xc0` as receive trigger and switches to receive mode. Error paths reset data lines, disable interrupts, stop the queue, and wait until the peer returns idle.

State and persistence behavior: All state is volatile per driver instance. `dev_plip[]`, module parameters `parport[]` and `timid`, and a static attach `unit` counter control runtime port binding. There is no durable persistence. Per-packet state lives in `snd_data` and `rcv_data`; partially transmitted SKBs are retained across delayed work retries and freed on error/close. Runtime timeout values are readable and writable through `SIOCDEVPLIP` except in compat syscalls. Port ownership is cooperative with other parport users via preempt and wakeup callbacks, with `should_relinquish` deferring release until an on-wire exchange completes.

Dependencies and integration points: Depends on kernel netdev, Ethernet header helpers, IPv4 address state for fake peer MAC rewriting, workqueues, completions, spinlocks, SKBs, `linux/if_plip.h`, and the parport API. It integrates with the network stack as `ARPHRD_ETHER`-style point-to-point/no-ARP device using custom header creation/cache rewrite logic, with parport IRQ or polling as receive trigger source, and with module/boot parameters for port selection.

Risks and edge cases: Timing is fragile: the protocol uses microsecond busy waits and short retry counters, so slow or noisy ports can drive `HS_TIMEOUT`, `TIMEOUT`, collision, or checksum paths. IRQ disable/enable balancing is explicitly delicate around send start and timeout handling. Port preemption during active transfer sets deferred release state and can starve other parport users if close/error paths miss release. Packet lengths are bounded by MTU plus Ethernet header and minimum size 8, but malformed peer lengths still allocate SKBs after validation. The file as checked out contains duplicated source lines around one receive branch and a duplicate `return ret;`, so build validation is an important signal for this snapshot. Compat ioctl is rejected, which avoids layout ambiguity but may surprise old 32-bit tooling.

Test signals: Build `CONFIG_PLIP` with parport enabled and with warnings as errors to catch source duplication/syntax issues. Runtime tests should cover IRQ and IRQ-less polling ports, open/close with active timers, parport preempt/wakeup while idle and while transferring, TX of over-MTU frames, receive bogus length/checksum, collision where receive interrupts a send, timeout recovery to idle, `SIOCDEVPLIP` get/set with and without `CAP_NET_ADMIN`, header cache rewrite after IPv4 address changes, module parameters for specific ports/timid/disabled boot setup, and unload after registered devices have been opened.

# sources/distributed-fs/ceph-client/drivers/net/ppp/Kconfig

Purpose: Defines the kernel configuration surface for PPP core support, PPP compression/encryption modules, PPP network transports, and tty line-disciplines. It controls which objects in `drivers/net/ppp` are available and selects required helper libraries.

Important configuration symbols: `PPP` is the parent tristate and selects `SLHC` for Van Jacobson TCP header compression. `PPP_BSDCOMP`, `PPP_DEFLATE`, and `PPP_MPPE` enable CCP compressor modules for BSD-Compress, Deflate, and MPPE respectively; Deflate selects `ZLIB_INFLATE` and `ZLIB_DEFLATE`, while MPPE selects `CRYPTO_LIB_ARC4` and `CRYPTO_LIB_SHA1`. `PPP_FILTER` enables classic BPF-based pass/active filters in `ppp_generic.c`. `PPP_MULTILINK` enables RFC 1990 bundle fragmentation/reassembly paths. Transport options include `PPPOATM` depending on `ATM`, `PPPOE`, `PPTP` depending on `NET_IPGRE_DEMUX`, and `PPPOL2TP` depending on `L2TP`. Under `if TTY`, `PPP_ASYNC` selects `CRC_CCITT` for async FCS handling and `PPP_SYNC_TTY` enables frame-oriented tty PPP.

Control flow and build effect: The menu is nested under `if PPP`, so compression modules, filters, multilink, and PPP transports cannot be configured without the generic PPP layer. The `if TTY` block prevents tty line discipline drivers from appearing when tty support is absent. The PPPoE hash-size choice is enabled only by `PPPOE`, emits one of four boolean selections, and derives integer `PPPOE_HASH_BITS` with default 4. Tristate choices flow into the Makefile object list and determine whether modules such as `ppp_generic`, `ppp_async`, `bsd_comp`, `ppp_deflate`, `ppp_mppe`, and `ppp_synctty` are built in or as modules.

State and persistence behavior: Kconfig does not hold runtime state, but it persists build-time feature selection in the kernel `.config`. These symbols materially change code compiled into `ppp_generic.c`: `CONFIG_PPP_FILTER` gates filter ioctls and BPF execution, and `CONFIG_PPP_MULTILINK` gates multilink state fields and code paths. The selected crypto/zlib/CRC dependencies ensure required helper APIs are present when modules are built.

Dependencies and integration points: Integrates with Kbuild, tty, ATM, L2TP, GRE demux, zlib, crypto library, and SLHC configuration. User-space integration is documented in help text: `pppd` for generic PPP and tty modes, RP-PPPoE tools for server mode, PPTP plugins/daemons, and L2TP/ATM stacks for tunneled variants.

Risks and edge cases: The help for `PPP_BSDCOMP` says the code will always be compiled as a module, while the symbol is a tristate and the Makefile uses normal `obj-$(CONFIG_PPP_BSDCOMP)`, so the text may be stale. Some help URLs are plain HTTP or old project locations. Misconfigured dependencies can produce a PPP core without the expected line discipline or compressor, which appears at runtime as failed ioctls or `ppp-compress-*` module requests. `PPP_FILTER` is bool rather than tristate because it changes core PPP code, so modular PPP builds still need this decided at kernel build time.

Test signals: Configuration tests should exercise `PPP=y/m`, each compressor as `y/m/n`, `PPP_FILTER` and `PPP_MULTILINK` toggles, TTY disabled builds, and transport dependency absence/presence. Build matrix checks should verify selected symbols produce the expected objects and module aliases, especially zlib/crypto/CRC dependencies and PPPoE hash-bit generated values.

# sources/distributed-fs/ceph-client/drivers/net/ppp/Makefile

Purpose: Maps PPP-related Kconfig symbols to object files under `drivers/net/ppp`. It is the build glue that turns the configuration choices in `Kconfig` into built-in objects or loadable modules.

Important entries: `obj-$(CONFIG_PPP) += ppp_generic.o` builds the generic PPP character device, netdev, channel, and compressor registry. `CONFIG_PPP_ASYNC`, `CONFIG_PPP_SYNC_TTY`, `CONFIG_PPP_BSDCOMP`, `CONFIG_PPP_DEFLATE`, and `CONFIG_PPP_MPPE` map to `ppp_async.o`, `ppp_synctty.o`, `bsd_comp.o`, `ppp_deflate.o`, and `ppp_mppe.o`. `CONFIG_PPPOE` builds both `pppox.o` and `pppoe.o`; `CONFIG_PPPOL2TP` builds `pppox.o`; `CONFIG_PPTP` builds `pppox.o` and `pptp.o`.

Control flow and build behavior: Kbuild expands each `obj-$()` line according to the tristate value. `y` links objects into the built-in driver aggregate, `m` builds modules, and empty values omit them. `pppox.o` is listed by multiple transports, relying on Kbuild object de-duplication/aggregation behavior so the generic PPP-over-X socket layer is available for PPPoE, PPPoL2TP, or PPTP users.

State and persistence behavior: The file has no runtime state. Its effects persist only in generated build artifacts and module availability. Module autoload behavior is provided inside the C files through `MODULE_ALIAS` declarations rather than in the Makefile.

Dependencies and integration points: Integrates directly with Kconfig symbols and Kbuild. It assumes `ppp_generic.o` exports channel/compressor symbols used by line discipline and compressor modules, and it assumes `pppox.o` provides common socket-family helpers used by transport-specific PPPoX modules.

Risks and edge cases: When multiple PPPoX transports are modular, `pppox.o` must be emitted in a way that satisfies all dependent modules. Any mismatch between Kconfig dependencies and this object list can surface as missing symbols or unavailable module aliases. Adding a new PPP compressor or transport requires touching both Kconfig and this Makefile, plus module aliases in the implementation for autoload.

Test signals: Verify object presence with representative configs: minimal `CONFIG_PPP=m`, async/sync tty modules, each compressor, PPPoE only, PPPoL2TP only, PPTP only, and combined PPPoX transports. Build logs should show exactly one usable `pppox` provider when more than one PPPoX transport is enabled.

# sources/distributed-fs/ceph-client/drivers/net/ppp/bsd_comp.c

Purpose: Implements the PPP BSD-Compress CCP compressor and decompressor using an LZW-style dictionary adapted for packetized PPP streams. It registers a `struct compressor` for `CI_BSD_COMPRESS` with the generic PPP layer.

Important APIs, types, and functions: `struct bsd_db` stores compressor/decompressor state: hash table sizing, code width, max code, sequence number, MRU, ratio/checkpoint counters, statistics, optional decompression code lengths, and dictionary pointer. `struct bsd_dict` stores hash entries and reverse code mapping. `bsd_alloc()`, `bsd_comp_alloc()`, and `bsd_decomp_alloc()` validate CCP options and allocate dictionary/lens tables. `bsd_init()`, `bsd_reset()`, and `bsd_clear()` initialize and reset stream dictionaries. `bsd_compress()` emits compressed PPP_COMP frames with two-byte sequence numbers, variable-width codes, CLEAR handling, and ratio-based dictionary reset. `bsd_incomp()` updates the receiver dictionary for incompressible packets by running compression without output. `bsd_decompress()` validates sequence numbers, decodes codes, reconstructs strings, updates the dictionary, and returns `DECOMP_ERROR` or `DECOMP_FATALERROR` according to PPP CCP expectations. Module init registers `ppp_bsd_compress` through `ppp_register_compressor()`.

Control flow: PPP userspace negotiates BSD-Compress through CCP, then `ppp_generic.c` calls allocation and init through the compressor registry. TX compression checks PPP protocol range, emits address/control/PPP_COMP/sequence header, compresses from the protocol field onward, updates dictionary entries on misses, conditionally emits CLEAR at packet boundary when compression ratio degrades, and returns zero if output is not smaller. RX decompression checks the packet sequence, reconstructs the PPP header and protocol byte, walks dictionary chains into the output buffer, handles the KwKwK special case, adds new dictionary entries, recognizes CLEAR only at the end of a packet, updates stats, and checks whether a peer-side clear should have happened. Incompressible frames keep the decompressor dictionary synchronized through `bsd_incomp()`.

State and persistence behavior: State is per negotiated compressor/decompressor instance and persists for the life of the CCP compression session. `seqno`, dictionary contents, code width, ratio counters, and stats survive across packets and are reset by CCP reset or close. No state is durable after module unload or compressor free. Allocations use `kzalloc_obj()` for control state and `vmalloc_array()` for potentially large dictionaries.

Dependencies and integration points: Depends on `linux/ppp_defs.h`, `linux/ppp-comp.h`, endian layout for dictionary hash keys, vmalloc/slab allocation, and `ppp_generic.c` compressor registration symbols. It is loaded by direct configuration or module alias `ppp-compress-CI_BSD_COMPRESS`, and called by generic PPP compression paths after CCP negotiation.

Risks and edge cases: Dictionary and bitstream code is sensitive to endian layout, code-width transitions, hash invalidation, and exact peer synchronization. Sequence mismatch returns recoverable `DECOMP_ERROR`, while malformed codes, bad CLEAR placement, and MRU overflow return fatal errors that bring compression down. Memory use grows steeply at 15-bit dictionaries. The source snapshot contains duplicated assignment lines in `bsd_check()` and `bsd_compress()`; they appear semantically harmless, but build/static-analysis checks should still flag unexpected duplication. Because `bsd_incomp()` calls `bsd_compress()` with null output, compressor changes must preserve that no-output mode.

Test signals: Unit-style vectors should cover option validation for versions and 9-15 bit sizes, compressible and incompressible packets, output-buffer-too-small paths, sequence mismatch, CLEAR at end and illegal CLEAR mid-packet, dictionary full ratio reset, MRU overflow, KwKwK decoding, incompressible dictionary synchronization, module register/unregister, and interoperability with pppd peers using BSD-Compress.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_async.c

Purpose: Implements the asynchronous PPP tty line discipline `N_PPP`. It frames PPP packets over byte-stream serial lines using flags, octet escaping, FCS, ACCM maps, protocol/address-control compression, and hands complete frames to `ppp_generic.c` as PPP channels.

Important APIs, types, and functions: `struct asyncppp` is per-tty state: tty pointer, flags, receive bit observations, MRU, transmit/receive locks, ACCM maps, current TX/RX SKBs, FCS, output buffer, receive queue, tasklet, refcount/completion, and embedded `struct ppp_channel`. `ppp_asynctty_open()` allocates state and registers the channel; close/hangup unregister and free it after refcount drain. TTY callbacks include read/write stubs, ioctl, receive, and write wakeup. Channel ops are `ppp_async_send()` and `ppp_async_ioctl()`. `ppp_async_encode()` generates async framing. `ppp_async_push()` writes encoded bytes to tty. `ppp_async_input()`, `scan_ordinary()`, and `process_input_packet()` parse received streams. `async_lcp_peek()` watches LCP configure traffic to update MRU and async maps early.

Control flow: Registering the module installs the tty line discipline. Opening a tty in PPP mode initializes ACCM defaults, creates the PPP channel with speed/MTU, stores it in `tty->disc_data`, and expands receive room. Incoming tty bytes are protected by `recv_lock`, decoded into `rpkt`, and complete/error frames are queued to `rqueue`; a tasklet then calls `ppp_input_error()` when needed and `ppp_input()` for each SKB. Outbound PPP frames arrive through `ppp_async_send()`, which accepts one `tpkt` at a time and calls `ppp_async_push()`. Push encodes into a 4096-byte staging buffer, handles tty backpressure with `TTY_DO_WRITE_WAKEUP`, and later wakes generic PPP with `ppp_output_wakeup()`. LCP Configure-Request/Ack frames are sent uncompressed/unescaped according to PPP rules and can update negotiated MRU/ACCM without waiting for userspace.

State and persistence behavior: Runtime state is tied to the tty line discipline lifetime. `xaccm`, `raccm`, `mru`, `flags`, receive clean-bit observations, partial TX position/FCS, partial RX packet, and queued complete frames persist across callbacks. `disc_data_lock` plus refcount/completion prevents close from freeing state while receive/ioctl/wakeup paths still hold references. No durable state exists beyond tty close/module unload.

Dependencies and integration points: Depends on tty line discipline APIs, CRC-CCITT/FCS helpers, SKBs, tasklets, spinlocks, PPP ioctl definitions, and the generic PPP channel API (`ppp_register_channel`, `ppp_input`, `ppp_output_wakeup`). It exposes `MODULE_ALIAS_LDISC(N_PPP)` for line discipline autoload and uses `tty_mode_ioctl()`/`n_tty_ioctl_helper()` for normal tty controls.

Risks and edge cases: Byte-stream parsing must handle escapes split across receive calls, bad FCS, MRU overflow, tty flag errors, XON/XOFF characters, zero-length frames, and LCP packets that must ignore compression options. TX has recursion/backpressure handling through `XMIT_BUSY`, `XMIT_FULL`, and `XMIT_WAKEUP`; pty-to-pty PPP can recurse through write wakeups. MRU setting clamps low values to `PPP_MRU` and rejects values above `U16_MAX`. The checked-out source has a duplicated `static ssize_t` line and duplicated comment text, so compile tests are required for this snapshot. Error frames are signaled by `skb->cb[0]` to the tasklet, so changes must preserve that convention.

Test signals: Build with `CONFIG_PPP_ASYNC` and `CONFIG_TTY`; verify `N_PPP` registration. Runtime tests should cover pppd over pty/serial, ACCM ioctls, MRU changes, protocol/address-control compression, escaped flag/escape/control bytes, FCS errors, receive overflow, tty error flags, XON/XOFF handling, write backpressure and wakeup, close racing receive/wakeup/ioctl, LCP Configure-Request/Ack peeking, and module unload after active line discipline use.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_deflate.c

Purpose: Adapts the kernel zlib Deflate/Inflate implementation to the PPP CCP compressor interface for RFC 1979 Deflate and the older draft Deflate option. It registers two compressor descriptors, `CI_DEFLATE` and `CI_DEFLATE_DRAFT`.

Important APIs, types, and functions: `struct ppp_deflate_state` holds sequence number, negotiated window size, PPP unit, MRU, debug flag, zlib stream, and compression stats. `z_comp_alloc()` and `z_decomp_alloc()` validate CCP options and allocate zlib workspaces with negative window sizes for raw Deflate streams. `z_comp_init()`, `z_decomp_init()`, `z_comp_reset()`, and `z_decomp_reset()` reset zlib stream history and sequence numbers. `z_compress()` emits PPP_COMP frames with a two-byte sequence number and zlib packet flush. `z_decompress()` validates sequence and inflates into a PPP frame while reconstructing one- or two-byte protocol fields. `z_incomp()` feeds incompressible packets into the inflate history. `deflate_init()` registers both compressor variants and unwinds cleanly if the second registration fails.

Control flow: CCP negotiation selects Deflate and supplies a window size/check sequence option. Generic PPP calls allocation and init for transmit and receive directions. TX skips unsupported protocols, writes address/control/PPP_COMP plus sequence, increments sequence, compresses from the protocol field with optional protocol-field compression behavior, and returns zero if the compressed frame is not smaller than the input. RX rejects too-short frames or sequence mismatches as recoverable errors, inflates with `Z_PACKET_FLUSH`, first obtains enough output to determine protocol-field compression, checks for MRU overflow using a one-byte overflow probe, updates stats, and returns the reconstructed length. Uncompressed frames in a Deflate session call `z_incomp()` so the decompressor history remains synchronized.

State and persistence behavior: zlib stream history, sequence number, and stats persist per CCP session. Reset ioctls/CCP reset reset history and sequence to zero. Workspaces are vmalloc-backed and released when compression state is freed. No state is persistent beyond the PPP session or module lifetime.

Dependencies and integration points: Depends on `linux/zlib.h`, PPP comp/defs headers, unaligned big-endian helpers, vmalloc/slab allocation, and compressor registration symbols exported by `ppp_generic.c`. Kconfig selects `ZLIB_INFLATE` and `ZLIB_DEFLATE`. Module aliases support autoload for both Deflate option numbers.

Risks and edge cases: Peer synchronization depends on strict sequence tracking and `z_incomp()` history updates. Output buffer sizing differs for compressed versus uncompressed frames and must account for PPP header/protocol reconstruction. `z_decompress()` treats inflate failures and MRU overflow as fatal errors, while short packets and sequence mismatch are recoverable CCP errors. `z_compress()` temporarily sets `next_out = NULL` with huge `avail_out` after local output fills to continue measuring compressed length, so zlib API expectations are important. The file snapshot contains a duplicated kernel-doc title line; not functionally significant but a useful lint signal.

Test signals: Build with `CONFIG_PPP_DEFLATE` and zlib selections. Exercise both `CI_DEFLATE` and `CI_DEFLATE_DRAFT`, min/max/invalid window sizes, sequence mismatch, incompressible packets, compressed output larger than input, MRU overflow, one-byte and two-byte protocol fields, reset handling, module registration unwind, and interop with pppd Deflate negotiation.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_generic.c

Purpose: Provides the generic Linux PPP layer: `/dev/ppp` control/data file operations, PPP net_device creation, PPP channel registration, compression registry, optional filters, optional multilink fragmentation/reassembly, VJ header compression integration, and rtnetlink support for PPP interfaces.

Important APIs, types, and functions: `struct ppp_file` abstracts file state for either an interface or channel. `struct ppp` is one PPP unit/netdev, with channel list, locks, MRU/flags, compression state, VJ state, NP modes, queues, stats, and optional multilink/filter fields. `struct channel` wraps a lower `struct ppp_channel`, file queues, namespace, RCU pointers to attached PPP or bridge peer, and locks. File ops `ppp_read()`, `ppp_write()`, `ppp_ioctl()`, and `ppp_poll()` implement the `/dev/ppp` ABI. Netdev ops include `ppp_start_xmit()`, private stats ioctls, stats64, and forward path fill. Exported channel APIs include `ppp_register_channel()`, `ppp_unregister_channel()`, `ppp_input()`, `ppp_input_error()`, and `ppp_output_wakeup()`. Compression APIs are `ppp_register_compressor()` and `ppp_unregister_compressor()`.

Control flow: Module init registers per-net PPP state, char device major 108, class/device `/dev/ppp`, and rtnetlink kind `ppp`. Userspace opens `/dev/ppp`, creates or attaches a unit with ioctls or rtnetlink, then attaches registered channels. Netdev TX maps Ethernet protocols to PPP protocols, pushes protocol bytes, applies NP mode, and enters `ppp_xmit_process()`. TX processing applies filters, VJ compression, CCP compression, demand-dial loopback, then sends through the first channel or multilink fragmentation. Channel backpressure queues SKBs and later drains them on `ppp_output_wakeup()`. RX from channels decompresses protocol fields, optionally bridges to another channel, queues unattached/control frames to pppd, or receives data frames through decompression, VJ handling, filters, NP mode, and `netif_rx()`. Multilink RX orders fragments by sequence, tracks missing fragments using per-channel `lastseq`/bundle `minseq`, reconstructs complete packets, and drops impossible or overlong sequences. CCP peeking updates compressor run/reset state based on Configure/Terminate/Reset packets.

State and persistence behavior: Per-net `struct ppp_net` uses IDRs/lists for units and channels. Units persist while referenced by `/dev/ppp`, netdev, and attached channels; channels persist while registered or referenced by files/bridges. Queues are bounded to `PPP_MAX_RQLEN` for pppd receive queues and `PPP_MP_MAX_QLEN` for multilink reconstruction. Compression state persists across packets until CCP closes or is reset. No disk persistence exists. RCU and refcounts protect channel/unit lifetime, while lock ordering is explicitly documented as `channel.upl -> ppp.wlock -> ppp.rlock -> channel.downl`.

Dependencies and integration points: Depends on netdev, rtnetlink, char device, per-net namespace, IDR, SKB, BPF filter, SLHC VJ compression, PPP channel API, PPP compressor API, optional multilink/filter Kconfig, module autoload for `ppp-compress-*`, and lower drivers such as async/sync tty, PPPoE, PPTP, L2TP, and ATM. It exports the core symbols consumed by those lower modules and compressor modules.

Risks and edge cases: This file is concurrency-heavy: file release can unregister netdevs, channels can unregister while queues drain, bridges use RCU and reciprocal refs, and multilink uses shared bundle/channel state under receive locks. Compression drops are security-sensitive for MPPE because a negative compressor result means "do not send unencrypted"; generic code honors that by dropping. Filters push two direction tag bytes, so SKB headroom and unclone behavior matter. Multilink sequence wrap, missing fragments, tiny MTUs, and queue pressure are subtle. The source snapshot contains duplicated declarations/braces in `ppp_read()` and `ppp_compat_ioctl()`, making build validation essential. `ppp_nl_newlink()` uses `mutex_trylock()` to avoid RTNL/PPP mutex inversion, surfacing `-EBUSY` to userspace.

Test signals: Build matrices should cover `CONFIG_PPP`, `CONFIG_PPP_FILTER`, `CONFIG_PPP_MULTILINK`, and compat ioctls. Runtime tests should exercise `/dev/ppp` create/attach/channel attach, rtnetlink newlink with valid/invalid PPP fds, open/read/write/poll EOF behavior, channel registration/unregistration races, channel bridging/unbridging, TX backpressure, demand mode loopback, NP mode pass/drop/queue, VJ compression, CCP compressor negotiation/reset/close, MPPE drop semantics, BPF pass/active filters, multilink fragmentation/reassembly/loss/wrap/over-MRRU, namespace teardown, stats ioctls, module unload with live refs, and lower channel drivers calling exported wakeup/input APIs.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_mppe.c

Purpose: Implements Microsoft Point-to-Point Encryption (MPPE) as a PPP CCP "compressor" for PPTP-style PPP links. Although wired into the compressor API, it encrypts/decrypts selected PPP protocol frames and expands each encrypted frame rather than compressing it.

Important APIs, types, and functions: `struct ppp_mppe_state` stores ARC4 context, SHA1 digest, master/session keys, key length, MPPE header bits, 12-bit coherency count, stateful/stateless mode, discard/sanity flags, unit/debug fields, and stats. `get_new_key_from_sha()` and `mppe_rekey()` implement RFC 3078/3079 key derivation and ARC4 rekeying, including 40-bit key prefix fixups. `mppe_alloc()` validates options, rejects FIPS mode, and stores key material appended to the CCP option. `mppe_init()` parses MPPE option bits, selects 40/128-bit mode and stateful/stateless behavior, generates the initial session key, and initializes coherency count. `mppe_compress()` encrypts outbound packets, writes PPP_COMP plus MPPE overhead, rekeys as required, and updates stats. `mppe_decompress()` validates MPPE bits/coherency count, handles stateful discard/recovery and stateless rekeying, decrypts payload, reconstructs protocol-field compression, and returns recoverable or fatal decompression errors. Module init registers `ppp_mppe`.

Control flow: PPP CCP negotiation passes options and key material to allocation/init. Outbound packets in protocol range `0x0021..0x00fa` are encrypted; other protocols are left uncompressed. TX increments coherency count, emits MPPE bits, rekeys every packet in stateless mode, on stateful flag packets, or after compressor reset, encrypts from the PPP protocol field, and returns a frame length larger than input. RX checks short frames, output space, encrypted/flushed bits, and coherency count. Stateless RX discards late packets and rekeys forward to the received count. Stateful RX detects packet loss, enters discard state, asks CCP for reset by returning `DECOMP_ERROR`, and resumes only on flushed packets with appropriate rekeys. Excess sanity errors escalate to `DECOMP_FATALERROR`.

State and persistence behavior: Key material and ARC4 state persist per CCP direction until compression is closed. Coherency count wraps in a 4096-packet space. `discard` tracks stateful packet loss recovery. `sanity_errors` decays after good packets and escalates repeated malformed traffic. Sensitive state is released with `kfree_sensitive()`. No state is persistent across sessions or module unload.

Dependencies and integration points: Depends on `crypto/arc4.h`, `crypto/sha1.h`, FIPS status, PPP comp/defs headers, unaligned helpers, `ppp_mppe.h` option macros, and the generic PPP compressor registry. Kconfig selects ARC4 and SHA1 library support. `comp_extra = MPPE_PAD` tells generic PPP to allocate transmit headroom for expansion. Module alias `ppp-compress-CI_MPPE` supports compressor autoload.

Risks and edge cases: MPPE is security-sensitive and uses ARC4/SHA1 legacy crypto; it is disabled when `fips_enabled`. Debug mode logs full master/session keys, which is dangerous outside controlled debugging. Off-by-one output sizing and protocol-field decompression are subtle because encrypted frames may use PFC. Generic PPP must respect negative compression return values to avoid sending plaintext when encryption is required. Stateful loss recovery depends on CCP reset behavior and peer interoperability. Repeated malformed headers intentionally take down compression/LCP after `SANITY_MAX`.

Test signals: Build with `CONFIG_PPP_MPPE` and crypto selections; verify FIPS mode rejects allocation/module init. Exercise 40-bit and 128-bit options, unsupported/no-key options, stateful and stateless modes, coherency wrap, stateless late-packet discard, stateful loss/discard/flushed recovery, compressor reset causing next-packet rekey, too-small output buffers, missing encrypted/flushed bits, encrypted PFC and non-PFC frames, MPPE_PAD sizing through generic PPP, sensitive free checks, and interop with PPTP/pppd MPPE peers.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_mppe.h

Purpose: Defines MPPE option constants and conversion macros shared by the MPPE compressor implementation. It translates between kernel-internal option flags and the four-octet MPPE CCP configuration information defined by RFC 3078.

Important APIs and constants: `MPPE_PAD` declares transmit growth used by `ppp_mppe.c` as compressor extra space. `MPPE_MAX_KEY_LEN` is 16 bytes for 128-bit keys. `MPPE_OPT_40`, `MPPE_OPT_128`, and `MPPE_OPT_STATEFUL` are supported internal options. `MPPE_OPT_56`, `MPPE_OPT_MPPC`, `MPPE_OPT_D`, `MPPE_OPT_UNSUPPORTED`, and `MPPE_OPT_UNKNOWN` classify unsupported or unknown peer bits. Wire bits include `MPPE_C_BIT`, `MPPE_D_BIT`, `MPPE_L_BIT`, `MPPE_S_BIT`, `MPPE_M_BIT`, and `MPPE_H_BIT`. `MPPE_OPTS_TO_CI(opts, ci)` writes the four-byte CCP CI from internal options; `MPPE_CI_TO_OPTS(ci, opts)` parses a CI into internal option flags and marks unknown/unsupported bits.

Control flow: During negotiation, PPP/MPPE code can build a CI with `MPPE_OPTS_TO_CI()` by setting H for stateless mode and S/L for 128/40-bit support. `ppp_mppe.c` uses `MPPE_CI_TO_OPTS()` in `mppe_init()` to determine key length and whether stateful mode is requested. Unsupported M/D/C bits and nonzero reserved octets are surfaced as option flags so negotiation code can reject or diagnose them.

State and persistence behavior: This header holds no runtime state. Its macros operate directly on caller-provided buffers and local option variables. The constants persist as ABI assumptions between negotiation code, MPPE implementation, and PPP CCP option layout.

Dependencies and integration points: Included by `ppp_mppe.c` and tied to `CI_MPPE` option handling in `linux/ppp-comp.h`. It assumes `u_char` and four-byte CI buffers. It integrates indirectly with generic PPP compression by influencing accepted options and the amount of compressor expansion advertised through `MPPE_PAD`.

Risks and edge cases: The H bit uses the same numeric value as C but in a different octet, so the macros deliberately cannot share internal bit names with wire bits. `MPPE_ALL_BITS` is used against the least-significant option octet even though the comment says it excludes H; because H is numerically identical to C but checked separately in `ptr[0]`, maintainers must be careful when editing these masks. The macros do not validate buffer length; callers must only use them after CCP option length checks. Unsupported 56-bit and MPPC bits should never be silently accepted.

Test signals: Test conversion round trips for 40-bit, 128-bit, stateful and stateless combinations; C/M/D unsupported bits; reserved octet bits; unknown high bits; and malformed caller usage in static analysis. Integration tests should verify `ppp_mppe.c` rejects unsupported/no-key options derived from these macros and applies correct key lengths.

# sources/distributed-fs/ceph-client/drivers/net/ppp/ppp_synctty.c

Purpose: Implements the synchronous PPP tty line discipline `N_SYNC_PPP` for frame-oriented tty devices such as synchronous HDLC adapters. Unlike async PPP, each receive callback is treated as a whole PPP frame and no byte stuffing/FCS framing is performed in this layer.

Important APIs, types, and functions: `struct syncppp` holds tty pointer, PPP flags, receive bit observations, MRU, transmit/receive locks, nominal async map fields for userspace compatibility, current TX SKB, receive queue, tasklet, refcount/completion, and embedded `struct ppp_channel`. TTY line-discipline callbacks are `ppp_sync_open()`, `ppp_sync_close()`, `ppp_sync_hangup()`, read/write stubs, `ppp_synctty_ioctl()`, `ppp_sync_receive()`, and `ppp_sync_wakeup()`. Channel ops are `ppp_sync_send()` and `ppp_sync_ioctl()`. `ppp_sync_txmunge()` handles protocol-field compression and address/control insertion. `ppp_sync_push()` writes whole SKBs to tty. `ppp_sync_input()` validates and queues received frames.

Control flow: Module init registers the `pppsync` line discipline. Open allocates state, initializes queue/tasklet/refcount, registers a PPP channel with two bytes of channel header room for address/control, and stores state in `tty->disc_data`. Outbound generic PPP frames enter `ppp_sync_send()`, which ensures only one pending `tpkt`, munges the packet according to negotiated flags, and pushes it to tty. TTY write wakeups schedule the tasklet to retry output and notify generic PPP with `ppp_output_wakeup()` when the channel can accept more. Receive callbacks allocate an SKB sized for MRU plus PPP header, optionally strip address/control bytes, verify a plausible protocol field, and queue the frame; the tasklet delivers non-empty SKBs with `ppp_input()` and zero-length error markers with `ppp_input_error()`.

State and persistence behavior: Per-tty state persists while the line discipline is active. `xaccm`/`raccm` are retained only to satisfy common PPP ioctls; synchronous mode does not use async maps for framing. `tpkt` stores a pending frame under backpressure. `rqueue` stores complete frames/errors until tasklet processing. `disc_data_lock`, refcounts, and completions protect close against concurrent callbacks. No durable state exists after close/unload.

Dependencies and integration points: Depends on tty line discipline APIs, SKBs, tasklets, spinlocks, completions/refcounts, PPP channel APIs, PPP ioctl definitions, and unaligned helpers. It exposes `MODULE_ALIAS_LDISC(N_SYNC_PPP)` and relies on `ppp_generic.c` for unit attachment, packet processing, and wakeup semantics.

Risks and edge cases: Because the lower tty is frame-oriented, partial writes and write wakeups must not corrupt frame boundaries; the driver keeps the whole SKB until fully written. `ppp_sync_txmunge()` must preserve LCP configure/code-reject frames uncompressed and ensure enough headroom for address/control insertion. Receive treats only the first `flags` byte as whole-frame error indication. Queueing a zero-length SKB as an error marker is an internal convention that tasklet processing must preserve. The checked-out source contains an extra `{` in `ppp_sync_read()`, so this snapshot needs compile validation. Async-map ioctls are accepted for user-mode compatibility but do not affect framing.

Test signals: Build with `CONFIG_PPP_SYNC_TTY` and `CONFIG_TTY`. Runtime tests should cover line discipline open/close/hangup races, channel registration/unregistration, full-frame receive with and without address/control bytes, invalid short frames, MRU overflow, error flag frames, protocol-field compression, LCP frames bypassing compression, partial tty writes and wakeup retry, TCFLSH output purge, PPPIOCGCHAN/UNIT and map/MRU ioctls, zero-length error delivery, and module unload after active channels.
