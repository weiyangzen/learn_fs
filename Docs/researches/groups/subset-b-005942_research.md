# Research: sources/distributed-fs/ceph-client/include/net/libeth/xdp.h

Purpose: `xdp.h` is the generic libeth XDP framework header. It gives Ethernet drivers a shared fast path for XDP buffer representation, XDPSQ selection and locking, `XDP_TX`, `.ndo_xdp_xmit()`, Rx-side XDP program execution, redirect flushing, metadata helpers, queue cleanup timers, and Tx completion. The header is heavily inline/macro based so driver-specific descriptor filling can compile down to direct ring writes.

Important APIs/types/functions: key verdict bits are `LIBETH_XDP_PASS`, `DROP`, `ABORTED`, `TX`, and `REDIRECT`. `struct libeth_xdp_buff` extends `struct xdp_buff` with a descriptor pointer and driver-private scratch area while remaining layout-compatible with `xdp_buff_xsk`. Stack helpers include `LIBETH_XDP_ONSTACK_BUFF()` and `LIBETH_XDP_ONSTACK_BULK()`. XDPSQ helpers include `libeth_xdpsq_num()`, `libeth_xdpsq_id()`, queue share locking helpers, and timer helpers. `struct libeth_xdp_tx_frame`, `struct libeth_xdp_tx_bulk`, `struct libeth_xdpsq`, and `struct libeth_xdp_tx_desc` are the central Tx abstractions. `libeth_xdp_tx_xmit_bulk()` is the generic ring-fill engine. Rx helpers include `libeth_xdp_init_buff()`, `libeth_xdp_process_buff()`, `libeth_xdp_run_prog()`, `libeth_xdp_run_pass()`, and `libeth_xdp_finalize_rx()`. Driver boilerplate is generated by `LIBETH_XDP_DEFINE_*` macros. Completion is handled by `libeth_xdp_complete_tx()`, and netdev feature publication by `libeth_xdp_set_features()` / `_noredir()`.

Control flow: for Rx, a driver initializes an on-stack bulk under RCU, builds a `libeth_xdp_buff` from page-pool FQEs, optionally stores descriptor metadata, runs the attached BPF program, and either returns/recycles the buffer, queues it to an XDPSQ for `XDP_TX`, redirects it, or converts it to an skb for GRO. At poll end, `libeth_xdp_finalize_rx()` flushes any queued `XDP_TX`, kicks the driver queue, flushes redirect maps, and releases the RCU read lock. For `.ndo_xdp_xmit()`, frames are DMA mapped, queued into a bulk, flushed through the same generic `libeth_xdp_tx_xmit_bulk()` path, and finalized depending on `XDP_XMIT_FLUSH`. The ring-fill engine asks the driver to prepare/clean a queue, writes descriptors linearly or in unrolled batches, wraps `next_to_use`, updates pending counters, and unlocks the XDPSQ.

State and persistence behavior: state is in memory and hardware-visible rings only. The header manipulates `xdp_buff` data pointers, page-pool ownership, DMA mapping/sync state, Tx SQEs, `next_to_use`, pending counts, XDP Tx counters, queue-share spinlocks, delayed cleanup work, and per-poll action masks. It deliberately nulls consumed buffer pointers to avoid double returns. No durable storage is touched, but mistakes affect packet ownership, DMA correctness, and device queue progress.

Dependencies and integration points: it depends on BPF/XDP core APIs, `xsk_buff_pool`, page pool/netmem helpers, libeth Rx/Tx queue types, `sk_buff` fragment metadata, DMA mapping, static keys, workqueues, NAPI/GRO, XDP metadata ops, and tracepoints such as `trace_xdp_bulk_tx`. Drivers integrate by supplying queue prep, descriptor xmit, completion polling, skb population, and finalization callbacks.

Risks: the highest-risk areas are layout compatibility with `xdp_buff_xsk`, flexible private-data sizing, correct DMA sync/unmap pairing, queue wrap handling, RCU lifetime for BPF programs, distinguishing head and fragment SQE types, and cleanup when only part of a multi-frag frame is queued. Queue sharing depends on a static key and per-queue `share` flag; missing locks can corrupt shared XDPSQs while unnecessary locks hurt hot-path performance. The `__LIBETH_WORD_ACCESS` packing path is endian-sensitive and must match descriptor consumers.

Test signals: useful signals include XDP_PASS/DROP/TX/REDIRECT functional tests, multi-frag XDP frames, `.ndo_xdp_xmit()` with and without `XDP_XMIT_FLUSH`, ring wrap and low-free-descriptor cases, page-pool recycling under NAPI and non-NAPI returns, DMA API debugging, KASAN/KCSAN/lockdep, redirect-map flush coverage, XDP metadata hash tests, and driver descriptor inspection for first/last/multi/checksum flags.

# Research: sources/distributed-fs/ceph-client/include/net/libeth/xsk.h

Purpose: `xsk.h` extends libeth XDP support for AF_XDP zero-copy sockets. It provides shared helpers for XSk `XDP_TX`, XSk user-space Tx descriptor submission, XSk Rx buffer processing, XDP program execution on zero-copy buffers, fill-queue refilling, wakeups, and pool setup.

Important APIs/types/functions: XSk Tx helpers include `libeth_xsk_tx_queue_head()`, `libeth_xsk_tx_queue_frag()`, `libeth_xsk_tx_queue_bulk()`, `libeth_xsk_tx_fill_buf()`, and `libeth_xsk_tx_flush_bulk()`. User-space Tx xmit helpers include `libeth_xsk_xmit_fill_buf()`, `libeth_xsk_xmit_do_bulk()`, and metadata support through `libeth_xsktmo_req_csum()` and `libeth_xsktmo`. Rx helpers include `libeth_xsk_tx_init_bulk()`, `libeth_xsk_process_buff()`, `libeth_xsk_run_prog()`, `libeth_xsk_run_pass()`, and `libeth_xsk_finalize_rx()`. `struct libeth_xskfq` and `libeth_xskfqe_alloc()` model/refill the XSk fill queue. Setup and wakeup entry points are `libeth_xskfq_create()`, `destroy()`, `libeth_xsk_init_wakeup()`, `libeth_xsk_wakeup()`, and `libeth_xsk_setup_pool()`.

Control flow: on XSk Rx, the driver allocates zero-copy buffers from an XSk pool, attaches received buffers as a head or frags, syncs DMA for CPU, runs the attached XDP program, and most often redirects the buffer back to AF_XDP. Non-redirect verdicts are handled by the slow path or by building an skb with `xdp_build_skb_from_zc()`. XSk `XDP_TX` mirrors the generic XDP bulk path but stores `libeth_xdp_buff` pointers for completion. User-space Tx uses `xsk_tx_peek_release_desc_batch()` to borrow descriptors from the pool, casts pool descriptors to `libeth_xdp_tx_frame`, fills hardware descriptors in an unrolled batch, finalizes the driver queue, and manages the need-wakeup bit around lazy cleaning.

State and persistence behavior: all state is transient queue and pool state: XSk pool descriptors, zero-copy buffer ownership, DMA addresses, need-wakeup flags, FQ `ntu`, pending refill counts, thresholds, NUMA node, and SQE completion state. It persists only for socket/queue lifetime, but incorrect ownership can leak UMEM frames or return buffers to the wrong pool.

Dependencies and integration points: the header depends on `net/libeth/xdp.h`, AF_XDP driver APIs in `xdp_sock_drv.h`, XDP Tx metadata ops, XSk need-wakeup semantics, and driver descriptor callbacks shared with generic XDP. It integrates with XSk pool attach/detach, NAPI poll loops, `.ndo_xsk_wakeup`, zero-copy skb building, and checksum-offload metadata.

Risks: metadata support assumes the caller passes compatible `xsk_tx_metadata_ops`; `libeth_xsktmo` uses a sentinel pointer and compile-time constant expectations. Multi-frag XSk frames need exact first/last SQE marking for completion accounting. `libeth_xsk_xmit_do_bulk()` assumes the queue is already locked and cleaned, and that the prep callback returns `U32_MAX`; violating that contract can race queue state. Need-wakeup transitions are subtle because lazy cleaning and interrupts are disabled for the queue.

Test signals: test AF_XDP zero-copy bind/unbind, Rx redirect, XSk `XDP_TX`, user-space Tx with and without metadata checksum requests, need-wakeup behavior, fill-queue wrap/refill thresholds, multi-buffer packets, skb fallback from XSk buffers, queue teardown with outstanding buffers, and DMA API/debug-page-owner signals for UMEM frame lifetime.

# Research: sources/distributed-fs/ceph-client/include/net/llc.h

Purpose: `llc.h` is the main internal header for the IEEE 802.2 LLC core. It defines LLC addressing, SAP state, SAP socket hash tables, packet dispatch hooks, SAP lifetime helpers, station initialization, and optional proc/sysctl integration.

Important APIs/types/functions: `struct llc_addr` stores an LSAP and MAC address. `struct llc_sap` stores SAP state, P/F bits, refcount, receive callback, local address, global SAP-list node, socket hash tables keyed by device or local address, lock, socket count, and RCU cleanup node. Hash helpers are `llc_sk_dev_hash()`, `llc_sk_laddr_hashfn()`, and `llc_sk_laddr_hash()`. Core entry points include `llc_rcv()`, `llc_mac_hdr_init()`, `llc_add_pack()`, `llc_remove_pack()`, `llc_set_station_handler()`, `llc_sap_open()`, `llc_sap_find()`, `llc_build_and_send_ui_pkt()`, `llc_sap_handler()`, `llc_conn_handler()`, `llc_station_init()`, and `llc_station_exit()`.

Control flow: Ethernet packet reception enters `llc_rcv()`, which classifies the PDU destination as SAP, connection, or station handling. SAPs are registered in the global `llc_sap_list`; callers open a SAP with a receive callback, bind sockets into per-SAP hash tables, and route Type 1 traffic through SAP handlers or Type 2 traffic through connection handlers. SAP refcounts are acquired with `llc_sap_hold()` / `hold_safe()` and released with `llc_sap_put()`.

State and persistence behavior: SAP state persists for the SAP lifetime and is protected by spinlocks, RCU, and refcounts. Socket lookup state is held in device and local-address hash tables. Optional sysctl variables persist runtime LLC2 timer settings for ack, busy, P, and reject timers. There is no disk persistence.

Dependencies and integration points: it depends on Ethernet address sizes, packet types, skb/net_device types, list/hlist/nulls lists, hash/jhash helpers, refcounting, RCU, procfs, sysctl, and the UAPI LLC option header. It integrates with AF_LLC sockets, LLC station code, the Ethernet receive path, `/proc` diagnostics, and LLC2 connection machinery.

Risks: risks include SAP refcount/RCU lifetime errors, socket hash corruption under concurrent bind/unbind, incorrect LSAP masking, stale device-index hash entries, and sysctl timer values that destabilize connection retransmission. Packet dispatch bugs can send Type 1 UI/XID/TEST traffic to connection logic or vice versa.

Test signals: useful tests include SAP open/find/close refcounting, concurrent socket bind/unbind under RCU lookup, UI packet send/receive, station handler registration, LLC proc/sysctl initialization with config on/off, packet fuzzing over DSAP/SSAP/control fields, and lockdep/KASAN during SAP teardown.

# Research: sources/distributed-fs/ceph-client/include/net/llc_c_ac.h

Purpose: `llc_c_ac.h` declares LLC Type 2 connection-component state-transition actions. These are the action functions referenced by the connection state table to send PDUs, notify upper layers, update sequence variables, start/stop timers, and modify connection flags.

Important APIs/types/functions: the file assigns numeric action IDs such as `LLC_CONN_AC_CONN_IND`, `SEND_DISC_CMD_Pb_SET_X`, `SEND_I_CMD_Pb_SET_1`, `SEND_REJ_RSP_Fb_SET_1`, `START_ACK_TMR`, `UPDATE_Nr_RECEIVED`, `Vr_INC_BY_1`, and `START_SENDACK_TMR_IF_NOT_RUNNING`. `llc_conn_action_t` is the action function signature over `struct sock *` and `struct sk_buff *`. Declarations cover indication/confirm actions, PDU send/resend actions, timer control callbacks, flag setters, retry and sequence updates, disconnect/reset helpers, transmit-window adjustment, and `llc_circular_between()`.

Control flow: the LLC connection state engine evaluates an event, checks qualifiers, then runs a NULL-terminated action list made of functions declared here. Actions may enqueue indications to the socket receive queue, construct outbound LLC PDUs, change `llc_sock` state variables, schedule timers, remove acknowledged PDUs, or retransmit queued I PDUs. Timer callbacks re-enter the same state machinery by producing timer-expiration events.

State and persistence behavior: actions mutate in-memory `struct llc_sock` fields such as P/F/S/data/remote-busy/cause flags, retry count, `vS`, `vR`, unacknowledged PDU queues, timers, and connection state. State persists for the socket lifetime and across timer callbacks but has no durable storage.

Dependencies and integration points: this header depends on `struct sock`, `sk_buff`, and timer infrastructure. Implementations integrate with `llc_conn.h` socket state, `llc_pdu.h` PDU construction, state tables in `llc_c_st.h`, event definitions in `llc_c_ev.h`, and upper-layer AF_LLC primitives.

Risks: the action numbers are table contracts; renumbering or missing entries can make state transitions execute the wrong behavior. Sequence-number arithmetic is modulo 128 and easy to get wrong. Timer start/stop order can cause duplicate expirations or missed retransmits. Multi-action transitions must keep skb ownership clear because some actions consume, clone, or requeue frames.

Test signals: exercise connection setup/disconnect/reset, I-frame send and ACK removal, retransmission on ack/P/rej/busy timer expiry, remote/local busy transitions, rejected/FRMR frames, circular sequence comparisons around wrap, and skb ownership under failure injection.

# Research: sources/distributed-fs/ceph-client/include/net/llc_c_ev.h

Purpose: `llc_c_ev.h` defines LLC connection-component event IDs, event qualifier IDs, event metadata stored in `skb->cb`, event detector function types, qualifier function types, and helper logic for connection receive-buffer space.

Important APIs/types/functions: event type constants distinguish simple, condition, primitive, PDU, ack timer, P timer, reject timer, busy timer, report-status, and send-ack timer events. Event IDs cover upper-layer primitives (`CONN_REQ`, `DATA_REQ`, `DISC_REQ`, `RESET_REQ`), local busy changes, bad PDUs, received DISC/DM/FRMR/I/REJ/RNR/RR/SABME/UA variants with P/F and validity qualifiers, timer expirations, and transmit-buffer-full. `struct llc_conn_state_ev` stores primitive, type, reason, status, indication, and confirmation fields in `skb->cb`. `llc_conn_ev()` casts skb control storage. The file declares event recognizers, qualifier functions, and `llc_conn_space()`.

Control flow: incoming PDUs or generated primitives are annotated in `skb->cb`, then the state engine probes event functions from transition tables. Qualifier callbacks refine a recognized event using connection state such as data flag, P flag, remote busy flag, retry count, S flag, cause flag, and status-setting side effects. Timer callbacks generate timer-specific event types that re-enter the same transition path.

State and persistence behavior: event metadata is transient per skb and lives in the packet control buffer. Qualifiers read and sometimes write LLC socket state, especially status fields used for upper-layer confirmations. `llc_conn_space()` samples socket receive memory accounting against `sk_rcvbuf`.

Dependencies and integration points: it depends on `net/sock.h`, skb control-buffer layout, LLC connection socket state, PDU parsing, timer callbacks, and connection state tables. It is tightly coupled to `llc_c_st.h` and action functions from `llc_c_ac.h`.

Risks: `skb->cb` sharing is fragile; overlapping users must not clobber `struct llc_conn_state_ev`. Event and qualifier numeric constants are table indexes/contracts. Misclassifying P/F bit, invalid Ns/Nr, or command/response state can drive wrong state transitions. `llc_conn_space()` uses receive memory accounting and must stay consistent with socket queueing behavior.

Test signals: packet-level tests should cover each supervisory/unnumbered/I-frame event family, invalid Ns/Nr handling, P/F bit variants, primitive request/confirm generation, timer-expiration transitions, receive-buffer-full paths, and control-buffer integrity under skb clone/queue operations.

# Research: sources/distributed-fs/ceph-client/include/net/llc_c_st.h

Purpose: `llc_c_st.h` defines the LLC Type 2 connection state machine schema and state IDs. It is the central contract between event detectors, qualifier arrays, action arrays, and the exported `llc_conn_state_table`.

Important APIs/types/functions: state constants include `LLC_CONN_STATE_ADM`, `SETUP`, `NORMAL`, `BUSY`, `REJ`, `AWAIT`, `AWAIT_BUSY`, `AWAIT_REJ`, `D_CONN`, `RESET`, `ERROR`, and `TEMP`, with `LLC_CONN_OUT_OF_SVC` and `NO_STATE_CHANGE` sentinel values. `struct llc_conn_state_trans` binds an event predicate, next state, qualifier list, and action list. `struct llc_conn_state` binds a current state to its transition table. `llc_conn_state_table[]` is the external table consumed by connection processing.

Control flow: `llc_conn_state_process()` uses the socket's current state to select a `llc_conn_state`, scans transitions, runs the event function, checks qualifiers, executes action functions, and applies `next_state` unless it is `NO_STATE_CHANGE`. The header itself defines only the data model and constants, not the engine.

State and persistence behavior: state is the `llc_sock.state` value and associated timers/queues declared elsewhere. Table data is static read-only protocol policy. There is no persistence beyond the connection socket lifetime.

Dependencies and integration points: it includes `llc_c_ac.h` and `llc_c_ev.h` for action, event, and qualifier function types. It integrates with the connection processor in `llc_conn.h` implementations and the generated/static state transition tables in LLC source files.

Risks: state numbering and `NBR_CONN_STATES` must match table dimensions and callers' expectations. Missing transitions can silently drop events; wrong `NO_STATE_CHANGE` usage can leave sockets stuck. Action ordering inside transition table entries is critical but not visible in this schema.

Test signals: run protocol conformance scenarios for every state, especially setup, normal, busy, reject, await, disconnect, reset, and error paths. Add transition-table coverage, invalid event fuzzing, and assertions that state numbers remain within table bounds.

# Research: sources/distributed-fs/ceph-client/include/net/llc_conn.h

Purpose: `llc_conn.h` declares the AF_LLC connection socket state (`struct llc_sock`) and connection-level operations for allocation, teardown, state-machine processing, PDU send/return/resend, ACK removal, established-socket lookup, SAP socket membership, and data-acceptance checks.

Important APIs/types/functions: `struct llc_timer` wraps a kernel timer and expiration value. `struct llc_sock` embeds `struct sock` first, then bound address, state, SAP pointer, local/remote LLC addresses, net device and tracker, sequence counters, retry/window parameters, four LLC2 timers, P/F/S/data/remote-busy/cause flags, unacknowledged PDU queue, link metadata, temporary state, cmsg flags, and hash node. Helpers include `llc_sk()`, `llc_set_backlog_type()`, and `llc_backlog_type()`. Functions include `llc_sk_alloc()`, `llc_sk_stop_all_timers()`, `llc_sk_free()`, `llc_sk_reset()`, `llc_conn_state_process()`, `llc_conn_send_pdu()`, `llc_conn_rtn_pdu()`, I-PDU resend helpers, `llc_conn_remove_acked_pdus()`, `llc_lookup_established()`, SAP socket add/remove, and `llc_build_offset_table()`.

Control flow: sockets are allocated as `llc_sock`, attached to a SAP and optionally a device, then process backlog packets or generated events through `llc_conn_state_process()`. Connection actions send PDUs, append unacknowledged I PDUs, arm timers, and remove acknowledged frames. Backlog type markers differentiate packet and event entries in `skb->cb`. Established lookup resolves incoming connection traffic by SAP, local/remote address pair, and network namespace.

State and persistence behavior: connection state persists for the lifetime of the socket. Timers continue across event processing until stopped during state transitions or socket teardown. Queued unacknowledged PDUs hold retransmission state. Device lifetime is tracked by `netdevice_tracker`; SAP references connect sockets to SAP lifetime.

Dependencies and integration points: it depends on timer APIs, AF_LLC UAPI address definitions, `net/sock.h`, `llc_if.h`, netdevice tracking, sk_buff queues, and LLC SAP hashing. It is consumed by LLC actions, events, socket operations, and packet receive dispatch.

Risks: `struct sock` must remain first for casting. Timer teardown must be synchronized correctly to avoid callbacks after free. `skb->cb` backlog marking shares space with event metadata. Sequence/window variables are small modulo fields and prone to wrap bugs. Device and SAP references must be released in all teardown paths.

Test signals: verify socket allocation/free under refcount debugging, all timer callbacks during close/reset, established lookup with namespace/device/address variants, backlog packet versus event handling, ACK removal across sequence wrap, device unregister while sockets exist, and retransmission queue cleanup.

# Research: sources/distributed-fs/ceph-client/include/net/llc_if.h

Purpose: `llc_if.h` defines the LLC interface exposed to the network-layer side of the LLC implementation. It names service primitives, primitive types, status/reason codes, and declares high-level connection/data/disconnect helpers.

Important APIs/types/functions: primitive constants include `LLC_DATAUNIT_PRIM`, `CONN_PRIM`, `DATA_PRIM`, `DISC_PRIM`, `RESET_PRIM`, `FLOWCONTROL_PRIM`, `DISABLE_PRIM`, `XID_PRIM`, `TEST_PRIM`, `SAP_ACTIVATION`, and `SAP_DEACTIVATION`. Primitive types are request, indication, response, and confirmation. Reason/status constants cover reset origin, disconnect due to DM/DISC/ACK timeout, and connection/data statuses such as connected, disconnected, failed, impossible, received, remote busy, refuse, conflict, and reset done. APIs are `llc_establish_connection()`, `llc_build_and_send_pkt()`, and `llc_send_disc()`.

Control flow: upper layers request connection establishment, data send, or disconnect using these primitives and helper functions. The LLC connection and SAP state machines encode primitive and primitive-type values into skb event metadata, execute transitions, and later report indications/confirmations back to sockets.

State and persistence behavior: the header itself has no state. It defines values stored transiently in event structures and persistently reflected in `llc_sock` connection state and socket queues.

Dependencies and integration points: it includes Linux LLC UAPI, ARP/etherdevice helpers, `net/llc.h`, and network interface definitions. It bridges AF_LLC socket operations with the internal SAP/connection state machines.

Risks: primitive/status numeric contracts must remain consistent with state table code and users of `skb->cb` event fields. Unsupported flow-control primitive is declared but noted unsupported, so callers must not assume full flow-control behavior.

Test signals: check connect/data/disconnect socket operations, status propagation to users, reset/disconnect reason reporting, unsupported flow-control handling, and packet send failures through `llc_build_and_send_pkt()`.

# Research: sources/distributed-fs/ceph-client/include/net/llc_pdu.h

Purpose: `llc_pdu.h` defines LLC PDU wire-format constants, packed header structures, decode helpers, and builders for Type 1 UI/XID/TEST PDUs plus declarations for Type 2 I/S/U command and response constructors.

Important APIs/types/functions: the header defines PDU lengths, well-known SAP values, DSAP/SSAP bit masks, command/response masks, PDU type tests, U-format commands (`UI`, `XID`, `TEST`, `SABME`, `DISC`, `UA`, `DM`, `FRMR`), S-format commands (`RR`, `REJ`, `RNR`), sequence helpers, XID constants, and FRMR info macros. Wire structs are `struct llc_pdu_sn`, `struct llc_pdu_un`, `struct llc_xid_info`, and `struct llc_frmr_info`. Inline helpers include `llc_pdu_header_init()`, MAC/SAP decode helpers, UI/TEST/XID builders, and header accessors. Declared builders cover DISC, I, REJ, RNR, RR, SABME, DM, FRMR, and UA variants.

Control flow: transmit code reserves LLC header space with `skb_push()`, resets the network header, sets DSAP/SSAP command-response bits, then initializes the control field and optional information fields. Receive code reads `skb_network_header()` as U or sequence-numbered headers, classifies type using low control bits, decodes P/F and sequence numbers, and drives SAP or connection events.

State and persistence behavior: no persistent state is stored here. The functions mutate skb packet bytes and length. XID/FRMR data becomes wire-visible protocol state; sequence numbers are read from or written into control bytes.

Dependencies and integration points: it depends on Ethernet header access, skb network-header manipulation, byte-order helpers, LLC state machines, and PDU constructors implemented in LLC source files. It integrates with SAP Type 1 actions, connection Type 2 actions, and packet receive classification.

Risks: packed wire structures require exact byte layout. Several macros manipulate unaligned control fields, and `FRMR_INFO_SET_REJ_CNTRL()` reads rejected control bytes as `u8` or `u16`; unaligned/endian assumptions must be validated. `PDU_GET_NEXT_Vr()` and modulo sequence behavior are subtle. TEST response copies payload length from the Ethernet length field, so malformed lengths can stress skb bounds if not validated earlier.

Test signals: decode/build round-trip tests for UI/XID/TEST and Type 2 PDUs, P/F bit variants, DSAP/SSAP masking, XID information fields, FRMR rejected-control encoding, malformed short skb handling, sequence-number wrap, and packet captures comparing generated bytes to IEEE 802.2 expectations.

# Research: sources/distributed-fs/ceph-client/include/net/llc_s_ac.h

Purpose: `llc_s_ac.h` declares SAP-component state-transition actions for LLC Type 1 service access point handling. These actions deliver unitdata, send UI/XID/TEST PDUs, report status, and notify upper layers about XID/TEST events.

Important APIs/types/functions: action IDs include `SAP_ACT_UNITDATA_IND`, `SEND_UI`, `SEND_XID_C`, `SEND_XID_R`, `SEND_TEST_C`, `SEND_TEST_R`, `REPORT_STATUS`, `XID_IND`, and `TEST_IND`. `llc_sap_action_t` is the common action signature over `struct llc_sap *` and `struct sk_buff *`. The header declares one function per action.

Control flow: the SAP state machine matches a SAP event, then executes an action list declared with these function pointers. Actions either pass indications upward, build and send Type 1 PDUs, or report status back to the requesting socket/SAP user.

State and persistence behavior: actions operate on SAP state and skb contents but this header stores no state. Implementations may enqueue skbs to sockets, consume request skbs, or update SAP P/F bits depending on the action.

Dependencies and integration points: it depends only on forward-declared `llc_sap` and `sk_buff`, and integrates with `llc_s_st.h` state tables, `llc_s_ev.h` events, `llc_pdu.h` builders, and `llc_sap.h` send helpers.

Risks: action IDs are state-table contracts. Incorrect skb ownership in indication/send actions can leak or double-free packets. XID/TEST response actions must preserve source/destination SAP and MAC semantics.

# Research: sources/distributed-fs/ceph-client/include/net/lwtunnel.h

Purpose: `lwtunnel.h` defines the kernel lightweight tunnel state and encapsulation-operations interface used by routes and nexthops. It lets tunnel modules build per-route state, redirect dst input/output/xmit paths, serialize encap attributes to netlink, compare states, and provide config-dependent stubs when lightweight tunnels are disabled.

Important APIs/types/functions: `struct lwtunnel_state` stores tunnel type, redirect flags, needed headroom, refcount, original dst output/input callbacks, RCU node, and variable-length private data. `struct lwtunnel_encap_ops` provides callbacks for `build_state`, `destroy_state`, `output`, `input`, `fill_encap`, `get_encap_size`, `cmp_encap`, and `xmit`, plus module owner. Helpers include `lwtstate_get()`, `lwtstate_put()`, redirect tests, `lwtunnel_headroom()`, ops registration, encap validation/build/fill/compare, `lwtunnel_state_alloc()`, `lwtunnel_output()`, `lwtunnel_input()`, `lwtunnel_xmit()`, `bpf_lwt_push_ip_encap()`, `lwtunnel_set_redirect()`, and `MODULE_ALIAS_RTNL_LWT()`.

Control flow: tunnel modules register encap ops by type. Route/nexthop netlink parsing validates an encap type and asks the module to build an `lwtunnel_state`. When the state requests redirect, `lwtunnel_set_redirect()` saves the original dst callbacks and replaces them with lwtunnel wrappers. Packet output/input/xmit then dispatch through the registered ops, which may consume the skb or return `LWTUNNEL_XMIT_CONTINUE` to continue normal forwarding. Netlink dump paths ask ops for encap size and fill attributes.

State and persistence behavior: lwtunnel state is per-route/nexthop in-memory state refcounted with `atomic_t` and freed through RCU-aware `lwtstate_free()`. Original dst callbacks are saved in the state so redirect wrappers can chain or restore behavior. No disk persistence exists; route configuration persists only as long as networking configuration does.

Dependencies and integration points: it depends on UAPI lwtunnel definitions, netdevice/skbuff/types, route/dst entries, netlink attributes/extack, module ownership, static keys for netfilter hooks, and optional BPF LWT encapsulation support. It integrates with rtnetlink route creation, IPv4/IPv6 route output/input, nexthops, MPLS/IP tunnels, BPF LWT programs, and netfilter LWT hooks.

Risks: refcount and RCU lifetime bugs can leave route dst entries pointing at freed state. Redirect callback replacement must preserve original callbacks exactly and use `READ_ONCE`/`WRITE_ONCE` safely. Headroom calculation must avoid exceeding MTU assumptions. Config-disabled stubs return success for some dump/validation helpers but `-EOPNOTSUPP` for build/xmit, so callers must handle both. Encapsulation comparison must be exact enough to share routes safely without merging different tunnel states.

Test signals: validate route add/delete with each lwt encap type, netlink dump/compare round trips, refcounting under route replacement and namespace teardown, packet output/input/xmit through redirect wrappers, BPF LWT push encap, CONFIG_LWTUNNEL=n builds, module unload after ops unregister, and KASAN/RCU stall checks during concurrent route lookup and delete.
