# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/oss/oss_1_0_d.h

Purpose: generated AMD OSS 1.0 register address header for Southern Islands era ASIC support. It exports numeric register indices for the OSS block, covering interrupt handler (IH), system register bus manager (SRBM), host data path (HDP), XDP peer/direct-to-HDP windows, semaphore/mailbox registers, older DMA engine registers, display/debug strap registers, and protected-key/client aperture registers.

Important APIs and data: the interface is entirely preprocessor macros. The file defines 264 `#define` constants under the `OSS_1_0_D_H` include guard. `mm*` names are MMIO register indices used by AMDGPU register helpers, while `ix*` names are indexed or indirect-style offsets. Major groups include `mmIH_RB_*`, `mmIH_CNTL`, `mmIH_STATUS`, `mmSRBM_*`, `mmHDP_*`, `mmHDP_XDP_*`, `mmDMA_*`, `mmSEM_*`, `mmUVD_CONFIG`, `mmVCE_CONFIG`, and `ixCLIENT[0-3]_*`/`ixK*` security or client slots. There are no C functions, structs, enums, storage objects, or inline helpers.

Control flow: none in this header. Runtime control flow is in consumers that include this file, such as `amdgpu/si.c`, `si_ih.c`, `dce_v6_0.c`, `gmc_v6_0.c`, `gfx_v6_0.c`, `si_dma.c`, `uvd_v3_1.c`, and `vce_v1_0.c`. Those drivers pass these constants to register-access macros, program IH rings and writeback addresses, poll SRBM status before reset or clock operations, configure HDP cache/tiling behavior, and initialize the legacy DMA ring and indirect buffer controls.

State and persistence: the macros are compile-time constants only. They name hardware-backed registers whose state persists in the device until reset or subsequent firmware/driver writes. IH ring base/read/write pointer registers track interrupt queue state; SRBM status, soft-reset, debug, interrupt, and perf registers expose live global-bus and block state; HDP/XDP registers hold cache, BAR, peer-to-peer, and direct-to-HDP routing state; DMA registers hold ring, IB, timer, power, and clock-gating state. The header does not cache or synchronize any of that state.

Dependencies and integration points: the address constants are intended to be used with `oss_1_0_sh_mask.h`, which supplies the field masks for the same registers. It is also part of the SI-era ASIC include stack, included directly by SI display, memory-controller, interrupt, graphics, DMA, UVD, and VCE code. Consumers depend on AMDGPU register helpers rather than on this header alone; the macro value must match the access path selected by the caller (`mm*` direct MMIO versus `ix*` indexed register addressing).

Version and layout notes: OSS 1.0 contains a compact legacy `mmDMA_*` block at `0x3400..0x3437`, rather than the later dual `SDMA0_*`/`SDMA1_*` layout in OSS 2.0. It lacks the OSS 2.0 `IH_VMID_*_LUT`, `XDMA_SLV_*`, multiple XDMA master pipe aliases, and explicit SDMA channel register families. It still shares many IH, SRBM, HDP, XDP, semaphore, and client/security offsets with OSS 2.0.

Risks: address constants are a hardware ABI. A wrong value can cause register writes to target a different block, hang reset sequences, corrupt interrupt rings, leave HDP cache invalidation ineffective, or program DMA rings at the wrong register addresses. The `ix*` client/key ranges are mostly represented by reserved masks in the companion file; their names look usable but require generation-appropriate access semantics. Copying OSS 2.0 SDMA or VMID-LUT assumptions into this header would be incorrect for SI-era code.

Test signals: compile coverage of all SI-era files that include `oss_1_0_d.h`; boot on Southern Islands ASICs without register read/write faults; IH ring initialization and interrupt delivery; GPU reset paths that poll SRBM idle/busy status; HDP flush and cache-invalidate correctness under CPU-GPU coherency tests; SI DMA ring and IB submission; UVD/VCE bring-up; and absence of timeouts in polling paths that use the listed SRBM, IH, HDP, or DMA registers.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/oss/oss_1_0_sh_mask.h

Purpose: generated AMD OSS 1.0 bitfield header. It defines `REG__FIELD_MASK` and `REG__FIELD__SHIFT` constants for the OSS 1.0 address map in `oss_1_0_d.h`, allowing SI-era driver code to pack and extract IH, SRBM, HDP/XDP, semaphore, display-debug, strap, DMA, UVD/VCE, and XDMA overflow fields.

Important APIs and data: the interface is only macros under `OSS_1_0_SH_MASK_H`. Most definitions use the AMD generated naming convention `REGISTER__FIELD_MASK` and `REGISTER__FIELD__SHIFT`. Large families are represented: device straps (`CC_DRM_ID_STRAPS`), render-backend disable fields, reserved client/key/security registers, command processor and UVD/VCE urgency fields, display test debug index/data, HDP address/tiling/cache/MEMIO/non-surface fields, XDP direct-to-HDP flush, BAR, P2P mailbox and sticky/debug fields, IH ring/control/status/perf/advanced-fault fields, semaphore mailbox fields, SRBM status/reset/debug/perf/read-error/interrupt/clock-enable fields, legacy DMA ring/IB/control/status/power fields, and XDMA master overflow fields.

Control flow: there is no executable control flow. The masks shape caller read-modify-write flow through helper patterns such as reading a register, clearing a field with the mask, inserting a shifted value, and writing it back. In practice these fields drive IH enablement and ring pointer writeback, SRBM soft-reset and status polling, HDP cache invalidation and MEMIO send/read/write strobes, XDP/P2P BAR setup and flush signaling, semaphore mailbox routing, and SI DMA ring/IB setup.

State and persistence: the macros are stateless, but the named fields describe live hardware state. IH fields include ring enable/size, overflow, writeback address, interrupt enable, FIFO credits, and status bits. SRBM fields include busy/request-pending bits, block soft-reset bits, read-error source flags, debug ready snapshots, and clock-domain override timing. HDP/XDP fields include cache invalidation, tiling parameters, nonsurface format, MEMIO command/status/error bits, peer BAR validity and address fragments, direct-to-HDP flush selectors, sticky write-one-clear status, and clock-gating delays. DMA fields include trap/semaphore interrupt enables, data/fence byte swapping, ring enable/size/writeback, IB enable/swap/VMID force, idle status, power override, and power-gating enable.

Dependencies and integration points: this header is paired with `oss_1_0_d.h` and is included by SI-era AMDGPU components (`si.c`, `si_ih.c`, `dce_v6_0.c`, `gmc_v6_0.c`, `gfx_v6_0.c`, `si_dma.c`, `uvd_v3_1.c`, `vce_v1_0.c`). It is consumed by register-field helper macros and by explicit bit operations in low-level hardware initialization. It has no external library dependency, but it is tightly coupled to the generated register names expected by AMDGPU code.

Notable field behavior: many `CLIENT*`, `KHFS`, `KSESSION`, `KSIG`, `EXP`, `LX`, `KEFUSE`, and seed registers expose only a full-width `RESERVED` field, so they should not be treated as documented software-owned bit layouts. `HDP_XDP_STICKY` separates current status and write-one-clear bits. `HDP_MEMIO_CNTL` has separate send, operation, byte-enable, read/write strobe, upper address, and clear-error bits. `SRBM_SOFT_RESET` contains block-specific resets for BIF, DC, GRBM, HDP, IH, MC, ROM, SEM, UVD, VCE, VMC, XDMA, and related internal blocks. The appended DMA block uses legacy `DMA_*` naming rather than `SDMA0_*`.

Risks: these masks are untyped and unchecked, so a typo or generation mismatch can compile while corrupting unrelated bits. Fields named `RESERVED` must not be used as stable control surfaces. Some masks include historical generated oddities such as doubled `_MASK_MASK` names; consumers must use the exact macro names available rather than inventing normalized names. Incorrect reset/status masks can make reset code wait on the wrong idle bit or assert the wrong soft reset. Incorrect HDP/XDP masks can produce subtle CPU-GPU coherency, peer access, or BAR update failures.

Test signals: compile coverage for SI-era ASIC files that include the header; register-field helper builds without missing macros; interrupt-handler tests showing IH ring pointer, overflow, and enable bits behave correctly; GPU reset tests where SRBM status and soft-reset bits transition as expected; HDP cache flush and MEMIO error clearing paths; DMA ring/IB submission and idle detection; UVD/VCE urgency programming; and peer/BAR/XDP paths on hardware configurations that exercise those registers.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/oss/oss_2_0_d.h

Purpose: generated AMD OSS 2.0 register address header for Sea Islands/CIK generation support. It maps symbolic OSS block names to MMIO or indexed register numbers for IH, semaphore, SRBM, security/client registers, display debug, XDMA, SDMA0/SDMA1, HDP, and XDP/P2P/direct-to-HDP register families.

Important APIs and data: the file exports 615 `#define` constants under `OSS_2_0_D_H`. It retains the common OSS 1.0 IH, SRBM, HDP, XDP, strap, display debug, and client/key register names, and expands the address map substantially. New or expanded families include `mmIH_VMID_0_LUT` through `mmIH_VMID_15_LUT`, per-client memory config registers for SDMA/SDMA1/UVD/VCE/ACP/CPG/CPC, `mmSEM_STATUS`, `mmSEM_EDC_CONFIG`, `mmSEM_CHICKEN_BITS`, `mmSRBM_SDMA_CLKEN_CNTL`, `mmSRBM_SAM_CLKEN_CNTL`, a large `mmXDMA_SLV_*` slave block, dual `mmSDMA0_*`/`mmSDMA1_*` engine blocks with GFX and RLC0/RLC1 ring contexts, and master XDMA pipe/channel aliases.

Control flow: none in this header. Runtime flow is in CIK-era consumers such as `amdgpu/cik.c`, `cik_ih.c`, `cik_sdma.c`, `dce_v8_0.c`, `gmc_v7_0.c`, `gfx_v7_0.c`, `amdgpu_amdkfd_gfx_v7.c`, `uvd_v4_2.c`, `uvd_v5_0.c`, `uvd_v6_0.c`, and `vce_v2_0.c`. These drivers use the constants to initialize IH and VMID/PASID routing, program SDMA microcode, ring bases, write/read pointers, doorbells and IBs, poll SRBM and SDMA idle state, configure HDP cache/tiling, and manage XDMA peer or transfer windows.

State and persistence: the macros are constant names only. The addressed registers hold live device state: IH VMID-to-PASID LUT entries, interrupt ring state, semaphore FIFO/mailbox status, SRBM reset and clock/debug state, SDMA microcode address/data and per-engine ring/context state, XDMA master/slave transfer state and NACK/error counters, HDP cache and MEMIO state, and XDP direct/P2P BAR state. Values persist in hardware until reset or until the driver/firmware updates them; this header supplies no software persistence or locking.

Dependencies and integration points: this file is paired with `oss_2_0_sh_mask.h`, which defines field masks for the same address map. CIK, GFX7, GMC7, DCE8, UVD, VCE, SDMA, and KFD code include it directly. AMDGPU register access macros supply the actual read/write behavior, while this header supplies only offsets. Alias definitions are intentional: for example, generic `mmXDMA_SLV_CHANNEL_CNTL` and channel-specific `mmSDMA_CHANNEL*_XDMA_SLV_CHANNEL_CNTL` names may resolve to the same or strided addresses, and `mmMDMA_PIPE*_XDMA_MSTR_*` names map master pipe registers at regular `0x10` strides.

Version and layout notes: compared with OSS 1.0, OSS 2.0 replaces the legacy `mmDMA_*` register naming with full dual SDMA engines and adds context rings for GFX/RLC queues. It also adds IH VMID LUTs, ACP/CPG/CPC request config, SEM status/EDC/chicken bits, SAM/SDMA SRBM clock gating, XDMA slave channels, XDMA master pipes, and more explicit high-address fields. The common HDP/XDP register ranges mostly remain compatible, though field masks in the companion header may differ.

Risks: wrong constants can break firmware-visible hardware bring-up without compile errors. SDMA0 and SDMA1 have parallel names at different offsets, so copy/paste mistakes can program the wrong engine. XDMA channel and pipe aliases can hide address sharing or stride assumptions. Using OSS 1.0 legacy `DMA_*` names in OSS 2.0 code, or using OSS 2.0 SDMA names in SI code, is a generation mismatch. Register addresses for microcode upload, ring bases, doorbells, and writeback pointers are especially high impact.

Test signals: compile coverage of all CIK/GFX7/GMC7/DCE8/UVD/VCE/SDMA/KFD consumers; CIK boot with IH interrupts and VMID/PASID routing; SDMA0/SDMA1 microcode load, ring setup, IB execution, context switching, doorbells, and idle polling; GPU reset paths observing SRBM and SDMA status transitions; HDP flush/coherency tests; UVD/VCE operation; KFD GFX7 queues; and any XDMA peer or transfer path that exercises the slave/channel/master pipe aliases.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/oss/oss_2_0_sh_mask.h

Purpose: generated AMD OSS 2.0 bitfield header. It provides the mask and shift constants that let CIK-era AMDGPU code encode and decode fields in the OSS 2.0 register address map defined by `oss_2_0_d.h`.

Important APIs and data: the file exports only macros under `OSS_2_0_SH_MASK_H`. Field groups cover IH VMID LUT PASID entries, IH ring/control/status/perf/advanced-fault registers, SEM MCIF/config/status/mailbox/EDC/chicken bits, request urgency/transaction fields for SDMA, SDMA1, UVD, VCE, ACP, CPG, CPC1 and CPC2, SRBM routing/status/reset/debug/perf/read-error/clock fields, device straps and backend disable/redundancy, client/key/security registers, DC test debug registers, XDMA slave and master fields, SDMA0/SDMA1 engine fields, HDP cache/tiling/MEMIO/non-surface fields, and XDP direct/P2P/BAR/debug/sticky fields.

Control flow: the header has no executable logic, but its masks drive many hardware-control paths. IH setup code uses ring-size, enable, writeback, overflow, interrupt-enable, and VMID/PASID fields. Reset and clock code reads SRBM busy/request-pending/debug snapshot fields and writes `SRBM_SOFT_RESET` and clock-enable delay fields. SDMA setup writes microcode address/data, engine control, clock/power, ring and IB, poll address, doorbell, virtual-address, context, watermark, and freeze fields for both engines and their GFX/RLC queues. HDP/XDP paths manipulate cache invalidation, MEMIO commands, nonsurface tiling, P2P BAR validity, direct-to-HDP flush, sticky write-one-clear, and debug/status fields.

State and persistence: macros are stateless; described fields are live device state. OSS 2.0 adds more asynchronous state than OSS 1.0: VMID-to-PASID LUT contents, dual SDMA engine microcode upload state, SDMA ring and context state, doorbell capture/error state, CE and SDMA status1 stall/idle bits, power-gating FSM state, EDC/ECC interrupt enables, XDMA channel active/stop/reset and NACK/latency counters, and ACP/SAM/SDMA readiness and reset bits. Firmware, interrupt delivery, queues, and reset flows may change these registers between reads.

Dependencies and integration points: this header is paired with `oss_2_0_d.h` and included by CIK-era driver files, including `cik.c`, `cik_ih.c`, `cik_sdma.c`, `dce_v8_0.c`, `gmc_v7_0.c`, `gfx_v7_0.c`, `amdgpu_amdkfd_gfx_v7.c`, `uvd_v4_2.c`, `uvd_v5_0.c`, `uvd_v6_0.c`, and `vce_v2_0.c`. It is normally consumed by `REG_SET_FIELD`/`REG_GET_FIELD` style helpers or by explicit mask/shift operations around AMDGPU register reads and writes.

Notable field behavior: `IH_VMID_0_LUT` through `IH_VMID_15_LUT` expose 16-bit PASID fields. `SRBM_GFX_CNTL` routes by pipe, ME, VMID, and queue. `SRBM_SOFT_RESET`, `SRBM_STATUS`, `SRBM_STATUS2`, `SRBM_DEBUG`, and `SRBM_DEBUG_SNAPSHOT` include generation-specific SDMA, SDMA1, ACP, SAM, CHUB, ROPLL, and SMU bits not present in OSS 1.0. SDMA0 and SDMA1 repeat nearly identical field groups for engine control, ring/IB, context, doorbell, virtual-address, APE1, watermark, perf, freeze, phase quantum, EDC, and status registers. Several XDMA channel and pipe registers use reusable field names because channel-specific address aliases in the `*_d.h` file map the same field layout onto repeated blocks.

Risks: this file is high-risk because incorrect masks can silently write valid but wrong bit patterns. Dual SDMA engines and multiple queue contexts make engine/channel mix-ups easy. Some fields are write-one-clear, status, or reserved; treating them as ordinary persistent configuration can drop error state or set reserved bits. Generated oddities such as doubled `_MASK_MASK` names must be preserved for source compatibility. Using OSS 1.0 masks on OSS 2.0 registers can miss new SDMA/ACP/SAM/VMID fields or mis-handle changed field widths such as `SRBM_CNTL__READ_TIMEOUT`.

Test signals: compile coverage for all CIK-era consumers; IH interrupt and PASID/VMID routing tests; SDMA0/SDMA1 microcode upload, ring, IB, doorbell, context switch, freeze, EDC/ECC, and power-gating tests; GPU reset tests that verify SRBM reset/status/debug bits for SDMA, ACP, SAM, UVD, VCE, HDP, IH, and MC; HDP cache/MEMIO/coherency tests; XDMA NACK/latency/pipe/channel diagnostics where available; KFD queue operation on GFX7; and no timeouts in polling loops that depend on these masks.
