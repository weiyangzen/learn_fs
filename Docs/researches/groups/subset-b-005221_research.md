# sources/distributed-fs/ceph-client/drivers/scsi/3w-xxxx.h

Purpose: defines the hardware ABI, protocol constants, lookup tables, command packet layouts, queue state, and per-adapter runtime structure for the legacy 3ware `3w-xxxx` SCSI storage-controller driver. It is a header-only contract consumed by the corresponding implementation file for PCI register access, firmware command formatting, asynchronous event reporting, ioctl payloads, and SCSI command bookkeeping.

Important APIs/types/functions: there are no functions, but the file exposes core driver data contracts. `tw_aen_string[]` maps firmware AEN codes to operator-facing messages. `tw_sense_table[][4]` maps ATA/3ware error bytes to SCSI sense key/ASC/ASCQ tuples. Register bit definitions cover control, status, response queue, PCI cleanup, command opcodes, and AEN codes. Register access macros such as `TW_CONTROL_REG_ADDR`, `TW_CLEAR_ALL_INTERRUPTS`, `TW_ENABLE_AND_CLEAR_INTERRUPTS`, `TW_SOFT_RESET`, and `TW_STATUS_ERRORS` are the implementation's low-level hardware operations. Packed structures include `TW_SG_Entry`, `TW_Command`, `TW_Ioctl`, `TW_New_Ioctl`, `TW_Param`, `TW_Response_Queue`, `TW_Passthru`, and the central `TW_Device_Extension`.

Control flow: the header does not execute by itself, but it dictates the driver's runtime flow. Commands are built in `TW_Command` or `TW_Passthru`, assigned request IDs from the extension queues, DMA addresses are written into SGL entries, and the command queue register is poked. Completion paths read `TW_Response_Queue` values and decode response IDs through `TW_RESPONSE_ID_MASK`/`TW_RESID_OUT`. Reset and interrupt paths use the control/status macros to mask/unmask interrupts, clear host/attention/error bits, and issue soft resets. Ioctl paths use `TW_Ioctl` and `TW_New_Ioctl` to wrap firmware parameter commands and user data buffers.

State and persistence: persistent state lives in hardware/firmware and on attached disks; this header only declares in-memory runtime state. `TW_Device_Extension` tracks MMIO/PIO base address, DMA command/alignment pools, unit presence, free and pending queues, per-slot `struct scsi_cmnd *`, slot states, posted/pending counters, SGL limits, reset and sector counters, AEN circular queue, ioctl lock/wait state, and adapter flags. Queue heads/tails are `unsigned char`, intentionally matching `TW_Q_LENGTH` 256 wraparound. Static lookup tables have internal linkage in each including translation unit.

Dependencies and integration: depends on Linux integer types and on kernel SCSI/PCI types used in `TW_Device_Extension`. It integrates with the SCSI midlayer through `struct Scsi_Host` and `struct scsi_cmnd`, with PCI through `struct pci_dev`, with wait queues/mutexes for ioctl serialization, and with architecture I/O through `outl()` used by macros. Constants such as `TW_MAX_SGL_LENGTH`, `TW_MAX_SECTORS`, `TW_MAX_CMDS_PER_LUN`, and `TW_MAX_IOCTL_SECTORS` are integration limits visible to queueing and ioctl behavior.

Risks: packed hardware structures and bit-masking macros are firmware ABI sensitive; field reordering or size changes can break I/O. The AEN and sense tables are `static` in a header and not `const`, so every includer gets mutable copies. Several hardware addresses and DMA fields are 32-bit, which reflects the controller generation but is a portability boundary. Queue counters rely on wraparound and fixed 256-entry arrays. Error mapping coverage is finite; unknown firmware codes need defensive fallback in the implementation.

Test signals: build coverage for the 3ware driver, probe/reset on supported PCI IDs, command completion under load, ioctl firmware commands, AEN queue decode, induced drive errors mapping to SCSI sense, interrupt masking/unmasking around reset, and SGL boundary tests near `TW_MAX_SGL_LENGTH`, `TW_ATA_PASS_SGL_MAX`, `TW_MAX_SECTORS`, and ioctl sector limits.

# sources/distributed-fs/ceph-client/drivers/scsi/53c700.c

Purpose: implements the reusable Linux SCSI core driver for NCR/Symbios 53c700, 53c700-66, and compatible 53c710 chips running in 700-compatible mode. Board-specific wrapper drivers provide the mapped register base, IRQ, clock, and bus wiring parameters; this file supplies SCSI host registration, DMA script setup, command queueing, interrupt-driven script/message handling, synchronous negotiation, tagged queue management, autosense, and error recovery.

Important APIs/types/functions: exported entry points are `NCR_700_detect()`, `NCR_700_release()`, and `NCR_700_intr()`. The SCSI host template is filled with `NCR_700_queuecommand`, `NCR_700_abort`, `NCR_700_host_reset`, `NCR_700_sdev_init`, `NCR_700_sdev_configure`, `NCR_700_sdev_destroy`, and `NCR_700_change_queue_depth`. Core helpers include `NCR_700_chip_setup()`, `NCR_700_chip_reset()`, `NCR_700_start_command()`, `process_script_interrupt()`, `process_message()`, `process_extended_message()`, `process_selection()`, `find_empty_slot()`, `free_slot()`, `NCR_700_scsi_done()`, and `NCR_700_data_residual()`. SPI transport hooks are `NCR_700_set_period()` and `NCR_700_set_offset()`.

Control flow: `NCR_700_detect()` allocates a coherent or noncoherent DMA block for the script, message buffers, status byte, and command slots; patches generated script labels and fixed DMA addresses; initializes slot free lists and host template callbacks; resets/configures the chip; attaches the SCSI host and SPI transport. `NCR_700_queuecommand_lck()` enforces untagged/tagged queue-depth rules, allocates a command slot, maps the command and data SGL, builds script move fragments, negotiates tag use, and calls `NCR_700_start_command()`. `NCR_700_start_command()` patches script command address/count, target ID, message count, and SG entry address, writes SXFER/TEMP/DSP registers, and starts or queues the command depending on host state. `NCR_700_intr()` serializes hardware access under `host_lock`, decodes SCSI/DMA interrupt causes, handles reset/selection timeout/phase mismatch/gross/parity/script interrupts, processes reselection, resumes scripts, and starts one queued slot when the host becomes free.

State and persistence: all state is volatile kernel runtime state. `struct NCR_700_Host_Parameters` owns the patched script memory, DMA addresses, message/status buffers, slot array, host busy/free state, current command, saved fairness cursor, sync clock/min period, free list, and EH completion pointer. Per-device `struct NCR_700_Device_Parameters` stores the internal REQUEST SENSE command buffer, current untagged command, and active depth. Per-target SPI flags store sync-negotiation and tag-negotiation bits. Hardware retains negotiated transfer behavior only until reset; the driver clears and renegotiates after resets, INQUIRY, REQUEST SENSE, and SPI transport parameter changes.

Dependencies and integration: depends on the SCSI midlayer, SCSI error handling, SPI transport class, DMA mapping APIs, generated `53c700_d.h` script symbols, and `53c700.h` register/script patch helpers. Board wrappers call `NCR_700_detect()`, request IRQs pointing at `NCR_700_intr()`, and call `NCR_700_release()` during teardown. The driver creates a per-device sysfs `active_tags` attribute and participates in SPI domain validation for fast chips.

Risks: this code is hardware-race sensitive because selection/reselection can interrupt script progress while the host is busy. Several impossible states use `BUG()`, so corrupted reselection/tag state can crash the kernel. Noncoherent DMA paths require correct sync direction around scripts, message buffers, status, SGLs, commands, and sense buffers. Autosense rewrites the command buffer and stores original status/length in private bytes, which is fragile around unusual CDB lengths. The tag bitmap is target-ID based and comments call out problems for multiple-LUN devices. Error recovery relies on reset completion interrupts and midlayer locking assumptions.

Test signals: compile with representative wrapper drivers, boot/probe on 53c700/53c700-66/53c710 hardware or emulator, run SCSI scan and tagged/untagged I/O, trigger disconnect/reselection under load, force CHECK CONDITION to verify internal autosense, exercise SPI period/offset sysfs changes and domain validation, inject phase mismatch and bus reset, run error-handler abort/host-reset paths, and validate noncoherent/big-endian configurations.

# sources/distributed-fs/ceph-client/drivers/scsi/53c700.h

Purpose: declares the public interface and low-level hardware contract for the 53c700 core driver. It defines command slot geometry, scatter/gather script fragments, per-device and per-host state structures, SCSI/SPI negotiation flags, DMA script memory layout, endian-aware register accessors, chip register offsets, and script patching macros used by `53c700.c` and board wrapper drivers.

Important APIs/types/functions: external entry points are `NCR_700_detect()`, `NCR_700_release()`, and `NCR_700_intr()`. Major types include `enum NCR_700_Host_State`, `struct NCR_700_SG_List`, `struct NCR_700_Device_Parameters`, `enum NCR_700_tag_neg_state`, `struct NCR_700_command_slot`, and `struct NCR_700_Host_Parameters`. Inline helpers manage the per-device sense command and depth, SPI flag bits, tag negotiation state, and register access: `NCR_700_readb()`, `NCR_700_readl()`, `NCR_700_writeb()`, and `NCR_700_writel()`. Script patch macros `script_patch_32`, `script_patch_32_abs`, `script_patch_ID`, and `script_patch_16` mutate generated script instruction words and synchronize them for DMA.

Control flow: board code fills the top portion of `NCR_700_Host_Parameters` with clock, MMIO base, device pointer, optional 710 bus settings, differential flag, and endian wiring. `NCR_700_detect()` then fills everything below the "nothing below here needs altering" boundary. Queueing code uses `NCR_700_command_slot` state transitions from FREE to BUSY or QUEUED, with `host_scribble` pointing back to the slot. Script patch macros are invoked before each command start and on reselection to update target ID, command buffer, message count, and SG script entry points.

State and persistence: this header describes volatile runtime state only. `TOTAL_MEM_SIZE` lays out one DMA allocation containing the generated script, message-out buffer, message-in buffer, status byte, and all command slots on cacheline boundaries. `NCR_700_Host_Parameters` stores current host state, active command, free list, slot count, reselection ID, negotiated tag bitmap, revision, sync clock, min period, and reset completion pointer. `NCR_700_Device_Parameters` is allocated per `scsi_device` and freed at device teardown.

Dependencies and integration: includes Linux interrupt and I/O APIs plus SCSI device/command types. It integrates with generated script symbols from `53c700_d.h`, endian configuration options `CONFIG_53C700_LE_ON_BE` and `CONFIG_53C700_BE_BUS`, architecture byte order, the SPI transport's `spi_flags`, `spi_period`, and `spi_offset` fields, and board-specific wrappers that know the physical register mapping.

Risks: the header is dense with register constants and ABI-sized structures; small mistakes can corrupt scripts or program the chip incorrectly. Register access uses XOR byte-lane adjustment and optional bus-endian swaps, so platform wiring assumptions must match the actual board. `BUG_ON((reg & 0x3) != 0)` in long accessors catches invalid register alignment but can panic. `to32bit`-style script addresses and `__u32 pScript` reflect 32-bit DMA script engines. The tag and sync flags share `spi_flags`, so bit allocation must not collide with transport changes.

Test signals: compile across little-endian, big-endian, and `CONFIG_53C700_LE_ON_BE`/`CONFIG_53C700_BE_BUS` combinations; inspect generated object sizes/layout assumptions; validate script patching with command start/reselection; test per-device depth accounting via `active_tags`; and run reset, sync-negotiation, and DMA paths on both coherent and noncoherent architectures.

# sources/distributed-fs/ceph-client/drivers/scsi/BusLogic.c

Purpose: implements the BusLogic MultiMaster and optional FlashPoint SCSI host adapter driver. It discovers adapters, parses `BusLogic=` options, interrogates firmware, configures queueing and transfer capabilities, allocates CCB/mailbox resources, registers SCSI hosts, submits SCSI commands, handles interrupts and completions, reports `/proc/scsi/BusLogic` statistics, and performs host-adapter reset recovery.

Important APIs/types/functions: module entry/exit are `blogic_init()` and `blogic_exit()`. The SCSI template uses `blogic_qcmd`, `blogic_sdev_configure`, `blogic_diskparam`, `blogic_hostreset`, `blogic_write_info`, `blogic_show_info`, and `blogic_drvr_info`. Detection/configuration functions include `blogic_init_probeinfo_list()`, `blogic_init_mm_probeinfo()`, `blogic_init_fp_probeinfo()`, `blogic_probe()`, `blogic_hwreset()`, `blogic_checkadapter()`, `blogic_rdconfig()`, `blogic_reportconfig()`, `blogic_getres()`, `blogic_initadapter()`, and `blogic_inquiry()`. I/O lifecycle functions include `blogic_alloc_ccb()`, `blogic_dealloc_ccb()`, `blogic_write_outbox()`, `blogic_scan_inbox()`, `blogic_qcompleted_ccb()`, `blogic_process_ccbs()`, `blogic_inthandler()`, `blogic_qcmd_lck()`, and `blogic_resetadapter()`.

Control flow: initialization parses module/boot options, builds a probe list from PCI devices and legacy addresses, probes each candidate I/O range, hard-resets and verifies the adapter, allocates a `Scsi_Host`, reads firmware configuration, acquires IRQs, allocates initial CCBs, initializes mailboxes/strict round-robin/extended LUN mode, performs target inquiry, registers the host, and scans devices. Command submission allocates a CCB, maps the SCSI data and sense buffer, fills CDB, target, LUN, data direction, SGL pointer, tag fields, and stats, then either writes a MultiMaster outgoing mailbox or calls the FlashPoint SCCB manager. Interrupt handling acknowledges hardware, scans incoming mailboxes or FlashPoint completions, queues completed CCBs, translates result codes, updates target state/statistics, unmaps DMA, calls `scsi_done()`, and initiates adapter resets for external bus resets or internal errors.

State and persistence: module globals store parsed options, probe list, global trace flags, and the registered adapter list. Each `struct blogic_adapter` in `hostdata` stores firmware-derived capabilities, queue limits, target flags, active command counters, reset timestamps, CCB lists, mailbox rings, DMA handles, statistics, and accumulated config text for proc output. Runtime statistics can be cleared through `write_info`. Hardware/firmware settings such as AutoSCSI, BIOS geometry translation, termination, and queue support are read but not persisted by this driver, except normal SCSI I/O changes device media.

Dependencies and integration: depends on PCI discovery, I/O port regions, shared IRQs, DMA mapping, SCSI midlayer, SCSI tagged command support, proc/seq reporting via the host template, MSDOS partition parsing for BIOS geometry inference, and `FlashPoint.c` when `CONFIG_SCSI_FLASHPOINT` is enabled. `MODULE_DEVICE_TABLE(pci, blogic_pci_tbl)` advertises supported BusLogic PCI IDs even though the driver uses its own module init probe loop rather than a modern `pci_driver`.

Risks: the driver is old hardware code with many synchronous polling loops and firmware-version branches. `blogic_inbox_to_ccb()` linearly scans all CCBs for each completion, which is inefficient and assumes CCB list integrity. DMA addresses and firmware fields are 32-bit. Some error handling deallocates active CCBs during reset without completing every command in the same function, relying on upper-layer reset behavior. Abort handling is compiled out. Option parsing mutates the option string and has limited validation. `blogic_msg()` uses static formatting state and appends to a fixed adapter message buffer, so message length and concurrency assumptions matter. FlashPoint support is tightly coupled through direct inclusion of `FlashPoint.c`.

Test signals: compile with and without `CONFIG_SCSI_FLASHPOINT`; test module and boot `BusLogic=` option parsing; probe PCI MultiMaster, non-compliant PCI, FlashPoint, and legacy-address cases; verify firmware config reporting, mailbox initialization, strict round-robin, and extended LUN setup; run tagged and untagged I/O with queue-depth changes; trigger REQUEST SENSE, selection timeout, external bus reset, internal error reset, and host reset paths; validate `/proc/scsi/BusLogic` statistics and clearing; and check BIOS geometry output for disks with and without partition-table geometry hints.

# sources/distributed-fs/ceph-client/drivers/scsi/BusLogic.h

Purpose: defines the BusLogic driver protocol and runtime data model. It contains adapter limits, firmware command opcodes, packed firmware reply/request structures, mailbox and CCB layouts, target statistics, option structures, the main `blogic_adapter` hostdata structure, I/O port access helpers, FlashPoint interface definitions, and internal function prototypes used by `BusLogic.c`.

Important APIs/types/functions: key constants include `BLOGIC_MAX_ADAPTERS`, `BLOGIC_MAXDEV`, `BLOGIC_SG_LIMIT`, tag-depth defaults, bus-settle time, mailbox count, and message-buffer sizes. Important enums model message levels, adapter type, bus type, BIOS geometry, firmware opcodes, ISA I/O ports, strict round-robin requests, CCB format, mailbox actions, completion codes, CCB opcodes, data direction, adapter status, target status, queue tag type, and CCB status. Major structures include `blogic_probeinfo`, `blogic_probe_options`, `blogic_global_options`, register unions, firmware reply structs, `blogic_autoscsi`, `blogic_ccb`, `blogic_outbox`, `blogic_inbox`, `blogic_drvr_options`, `blogic_tgt_flags`, `blogic_tgt_stats`, `fpoint_info`, and `blogic_adapter`.

Control flow: `BusLogic.c` uses this header to move through adapter discovery, firmware interrogation, command construction, mailbox execution, completion processing, and statistics reporting. Inline I/O helpers write reset bits and command parameters, read status/data/interrupt/geometry registers, issue mailbox execute commands, delay after resets, and update counters. CCB and mailbox structs are the shared memory protocol: outgoing mailboxes point firmware at CCB DMA addresses, incoming mailboxes return completion status, and CCBs carry CDBs, SGLs, sense DMA addresses, tag fields, and driver-owned linkage.

State and persistence: the header defines both transient driver state and firmware-reflected configuration. `blogic_adapter` is the durable in-kernel state for a registered host: PCI identity, bus resources, firmware strings, feature flags, queue depths, target masks, CCB free/all lists, mailbox rings, target flags/stats, reset counters, and config message buffer. The underlying adapter firmware persists its own AutoSCSI and BIOS settings, but these structures merely cache what was read during initialization.

Dependencies and integration: relies on packed C layout matching BusLogic firmware, Linux I/O port operations, PCI devices, SCSI host/device/command types, kernel lists, DMA-coherent memory, and optional FlashPoint SCCB manager callbacks. The header also declares the driver-facing SCSI template callbacks implemented in `BusLogic.c`.

Risks: many structs use C bitfields in packed firmware layouts, which are compiler and endian sensitive but historically tied to supported Linux targets. `virt_to_32bit_virt()` and multiple `u32` address fields assume 32-bit firmware-visible addresses. Static arrays such as message-level names and bus names live in the header, so every includer would get definitions. Limits such as `BLOGIC_CDB_MAXLEN` 12 and `BLOGIC_SG_LIMIT` 128 must align with midlayer expectations. The main adapter struct is large and mixes interrupt-time state, init-time configuration, proc text, and statistics, so locking discipline is critical.

Test signals: compile-time layout and warning checks, probe/resource tests on each adapter type, command submission with SGL counts near `BLOGIC_SG_LIMIT`, tagged queue enable/disable behavior, mailbox wraparound, reset and completion status translation for all firmware status enums, proc statistics formatting, and option-driven queue depth/tag masks across all 16 target IDs.
