# sources/storage-engines/wiredtiger/src/reconcile/rec_write.c

Purpose: implements the central reconciliation write path that turns a dirty in-memory `WT_PAGE` into one or more on-disk page images, writes or defers those images as needed, updates page/tree modification state, moves hidden updates to the history store, handles bulk-load output, and cleans up previous reconciliation results. It is the coordinating layer around page-type-specific reconciliation functions such as `__wti_rec_row_leaf`, `__wti_rec_row_int`, `__wti_rec_col_var`, and `__wti_rec_col_int`.

Important APIs and functions: `__wt_reconcile` is the public entry point. It validates flags, prevents re-entrant reconciliation with `WT_SESSION_NO_RECONCILE`, locks the page, rechecks eviction eligibility, calls `__reconcile`, and records success/failure bits on the page. `__reconcile` initializes `WTI_RECONCILE`, dispatches by page type, detects no-progress eviction, runs `__rec_write_wrapup`, sets page status, handles root-page splits through `__rec_root_write`, dirties parents, and records timing stats. `__rec_init`, `__rec_cleanup`, and `__rec_destroy` own the per-session cached reconciliation object. `__wti_rec_split_init`, `__wti_rec_split_crossing_bnd`, `__wti_rec_split_finish`, and `__rec_split_write` manage split chunks, page images, saved updates, and write decisions. `__rec_write`, `__rec_write_image`, and `__rec_write_delta` are the block-cache write paths. `__rec_write_wrapup` is the atomic handoff point where old block state is discarded and new `WT_PAGE_MODIFY` state is installed. `__wt_bulk_init` and `__wt_bulk_wrapup` reuse reconciliation machinery for bulk loads. `__wti_rec_cell_build_ovfl` writes overflow objects, and `__wti_rec_hs_clear_on_tombstone` truncates history-store content for timestamp-free tombstone removal.

Control flow: reconciliation starts with page and session invariants, then captures pinned transaction/timestamp state for visibility decisions. A page-type-specific builder walks keys and updates, writes cells into the current split chunk, saves updates that must remain in memory or move to the history store, and calls split helpers as page boundaries are crossed. Split processing keeps current and previous chunks so a too-small final page can be repaired by moving data from the previous chunk at the recorded minimum-split boundary. Each completed chunk is converted into a `WT_MULTI` entry containing a promoted key/recno, an address descriptor, optional saved updates, optional disk image copy, and optional disaggregated block metadata. After disk-image construction succeeds, wrapup moves saved updates into the history store if `WT_REC_HS` is active, frees or preserves previous block addresses according to the prior `rec_result`, installs the new result as empty, replacement, or multiblock split, and updates obsolete stop-time aggregates.

State and persistence behavior: the file mutates page-level state in `WT_PAGE_MODIFY` (`flags`, `page_state`, `rec_result`, `mod_replace`, `mod_multi`, `stop_ta`, `instantiated`) and btree/connection state (`modified`, `rec_max_txn`, `rec_max_timestamp`, disaggregated LSN maxima, compression adjustment sizes, reconciliation timing maxima). On durable writes it writes full page images, deltas, overflow records, and root checkpoints through the block manager/block cache. In-memory trees and update-restore cases may skip physical writes and keep a disk image copy for re-instantiation. Disaggregated trees can reuse prior page IDs for single-page replacements, write deltas when eligibility and size thresholds pass, skip writes when no newer material is used, and invalidate page IDs on failed replacement reconciliation to avoid stale delta chains. History-store wrapup inserts saved updates after disk-image construction but before old state is cleared; after that point failures become panic paths because HS and page state could diverge.

Dependencies and integration points: depends on `reconcile_private.h` and `reconcile_inline.h` for `WTI_RECONCILE`, chunk state, split macros, cell builders, and time-window helpers. It integrates with transaction visibility (`__wt_txn_oldest_id`, pinned timestamps, session snapshots), eviction (`WT_REC_EVICT`, no-progress stats, `WT_TXN_REFRESH_SNAPSHOT`), checkpoint (`wrapup_checkpoint`, block-manager checkpoint calls, precise checkpoint pinned IDs), history store cursors and insert/delete helpers, overflow tracking, block cache writes, page verification, page delta configuration, root-page handling, bulk cursors, and disaggregated storage metadata. Parent dirtying and root split recursion tie this leaf/internal page work back into the tree.

Risks and sharp edges: the function boundary around `__rec_write_wrapup` is a correctness cliff: failures before it can clean up, failures after it panic. Page locking differs between eviction and checkpoint paths, so fields like `stop_ta` require split-generation-safe freeing. Saved-update routing to split chunks depends on sorted keys and correct promoted boundary keys; an empty or stale boundary can attach restored updates to the wrong block. Delta writes must not mark updates durable too early, must reject zero-entry or oversized deltas, and must handle prepared tombstones differently from normal durable updates. Disaggregated skip-write and page-ID invalidation paths are subtle because old cookies, cumulative sizes, and delta-chain accounting must remain consistent across failures. Salvage cannot split, so page-size calculation deliberately over-allocates. Compression adjustment writes shared btree sizing without locks and intentionally tolerates races. The file also contains explicit diagnostic assertions and failpoints around reconciliation failure windows, history-store key deletion, and bulk split writes.

Test signals: useful coverage includes eviction with hidden updates and no-progress cases, checkpoint reconciliation of root and non-root pages, multiblock splits with saved updates crossing boundaries, update-restore/in-memory re-instantiation, overflow reuse/discard, bulk-load wrapup, history-store insertion/deletion for timestamped and timestamp-free tombstones, precise-checkpoint visibility, disaggregated full-image/delta/skip-write replacement, failed replacement cleanup, and recovery/salvage verification of write generations. Runtime signals are `rec_pages*`, `rec_page_delta_*`, `cache_write_hs`, `cache_write_restore_invisible`, `cache_eviction_blocked_no_progress`, prefix/suffix compression stats, block-byte saved-by-delta stats, reconciliation timing maxima, verbose split keys, and diagnostic disk-image verification.

# sources/storage-engines/wiredtiger/src/reconcile/reconcile.h

Purpose: declares the public reconciliation interface and shared reconciliation flags used by callers outside the private reconcile implementation. It is the stable include that lets eviction, checkpoint, bulk load, overflow handling, and other btree code invoke reconciliation without depending on the internals of `WTI_RECONCILE`.

Important APIs and types: `WT_REC_RESULT_MULTIBLOCK_SPLIT(page)` detects an existing page-modify result that references more than one replacement block. The `WT_REC_*` flag set describes caller intent and visibility mode: application eviction snapshot, urgent calls, checkpoint and checkpoint-running state, clean-after-reconciliation behavior, eviction, closing-time eviction, history-store eviction, in-memory operation, scrub, visibility-error reporting, and visible-without-snapshot reconciliation. Public prototypes include `__wt_reconcile`, `__wt_split_page_size`, `__wt_bulk_init`, `__wt_bulk_wrapup`, row/variable bulk insertion, and overflow discard/reuse cleanup APIs. Unit-test-only prototypes expose overflow tracking internals under `HAVE_UNITTEST`.

Control flow: callers combine flags and pass a `WT_REF` to `__wt_reconcile`; the implementation in `rec_write.c` interprets those flags to choose snapshot rules, page locking requirements, history-store behavior, in-memory write suppression, and checkpoint/root handling. Bulk cursors call the bulk init/insert/wrapup functions to feed records through the same split/write machinery. Overflow helpers declared here are called by page read/reconciliation cleanup paths to track blocks that can be reused or must be discarded.

State and persistence behavior: this header does not own state, but its flags directly control persistent outcomes. `WT_REC_CHECKPOINT` can turn a root-page reconciliation into a checkpoint write. `WT_REC_EVICT` can install replacement blocks and make a page clean or leave it dirty with saved updates. `WT_REC_HS` enables writing obsolete-but-needed updates into the history store. `WT_REC_IN_MEMORY` prevents disk writes and drives in-cache page reconstruction. `WT_REC_SCRUB` preserves disk images for scrub/materialization behavior.

Dependencies and integration points: included by reconciliation users that need only public entry points. It depends on core WiredTiger types (`WT_SESSION_IMPL`, `WT_REF`, `WT_CURSOR_BULK`, `WT_PAGE`, `WT_CELL`, `WT_SALVAGE_COOKIE`) supplied by `wt_internal.h`. The prototypes are automatically generated by `prototypes.py`, so function signature changes must be coordinated with the generated section.

Risks and sharp edges: flag combinations are constrained mostly in the implementation rather than by the type system. For example, eviction with transaction visibility needs a snapshot unless `WT_REC_VISIBLE_NO_SNAPSHOT` is set, and history-store eviction is invalid for the history store and metadata. Adding a new flag requires respecting the automatic flag generation range and auditing `rec_write.c`, page-type reconcilers, eviction, checkpoint, and tests for interactions.

Test signals: compile-time prototype generation catches signature drift. Behavioral validation comes from reconciliation callers: eviction/checkpoint tests should exercise each flag mode, bulk-load tests should cover the bulk API declarations, and overflow unit tests under `HAVE_UNITTEST` should continue to link against the test-only prototypes.

# sources/storage-engines/wiredtiger/src/reconcile/reconcile_inline.h

Purpose: provides small inline helpers for reconciliation cell construction, page-image copying, split accounting, time-window/stat tracking, dictionary compression replacement, obsolete time-window cleanup, and delta-key filtering. These helpers are shared by row-store, column-store, internal-page, leaf-page, and delta reconciliation code without turning them into out-of-line functions.

Important APIs and functions: `__rec_cell_addr_stats`, `__rec_delta_cell_addr_stats`, `__rec_cell_tw_stats`, and `__rec_delta_cell_tw_stats` collect time aggregate/window usage into the active `WTI_RECONCILE`. `__rec_page_time_stats`, `__rec_page_time_stats_clear`, `__rec_page_delta_stats_clear`, and `__rec_page_pfx_compression_stats_clear` publish and reset per-page statistics. `__wti_rec_need_split` decides whether the next cell crosses split/minimum boundaries, including saved-update memory pressure for row leaf pages. `__rec_incr`, `__wti_rec_kv_copy`, and `__wti_rec_image_copy` advance the disk-image buffer. `__wti_rec_cell_build_addr` packs child address cells and fast-truncate proxy metadata. `__wti_rec_cell_build_val` packs value cells or delegates oversized values to `__wti_rec_cell_build_ovfl`. `__wti_rec_dict_replace` converts repeated values to dictionary-copy cells. `__wti_rec_time_window_clear_obsolete` removes globally visible start timestamps/txn IDs before cell packing when safe. `__wti_rec_get_row_leaf_key` abstracts row key extraction, and `__rec_selected_key_changed` filters already-durable selected updates for delta construction.

Control flow: page-type reconciliation code builds `WTI_REC_KV` key/value pairs, asks whether the pending length needs a split, optionally rewrites values through dictionary compression, copies cells into the current chunk, and increments `first_free`, `entries`, `space_avail`, and minimum-boundary space through `__rec_incr`. Internal-page code builds address cells from either a fresh `WT_ADDR` or an unpacked on-disk address. Leaf-page update selection can clear obsolete time-window starts before cell construction so disk images omit unnecessary timestamp/txn payloads. Delta builders use the delta stat variants and `__rec_selected_key_changed` to avoid writing keys whose selected on-page update was already marked durable by an earlier successful reconciliation.

State and persistence behavior: these helpers do not write blocks by themselves except when `__wti_rec_cell_build_val` creates an overflow value through `__wti_rec_cell_build_ovfl`; otherwise they mutate only the active in-memory reconciliation buffers and counters. Their output controls persistent page layout: address cell type, value cell encoding, dictionary-copy offsets, time-window contents, page split points, and delta contents. Clearing obsolete time-window starts can permanently reduce future on-disk metadata for globally visible updates, except for garbage-collect ingest tables where timestamps are retained for step-up.

Dependencies and integration points: tightly coupled to `WTI_RECONCILE` and `WTI_REC_KV` from `reconcile_private.h`, WiredTiger cell packing helpers, time aggregate/window macros, btree prefix/dictionary/overflow configuration, row key extraction, collators, and page delta durability flags. `WT_REC_HAS_ON_DISK` and update-selection invariants connect it to `rec_visibility.c`-style update selection logic, while `WT_DELTA_*` callers depend on the durable/prepared durable flag checks.

Risks and sharp edges: `__rec_incr` and copy helpers assume the caller already performed correct split-boundary sizing; otherwise they can overrun the image buffer outside diagnostic builds. Dictionary replacement relies on offsets inside the current page image and avoids tiny values because copy cells could be larger than the original. Clearing time-window fields must not run for prepared updates or ingest/garbage-collect tables because those timestamps have semantic meaning. `__wti_rec_need_split` subtracts per-update overhead from saved-update memory; incorrect `supd_onpage_or_restore` accounting can skew split decisions. Delta filtering around prepared durable flags must distinguish start-prepare and stop-prepare cases to avoid dropping updates still needed after prepared rollback.

Test signals: split-boundary and image-buffer diagnostics should remain clean under large keys/values and update-heavy pages. Statistics tests can observe time-window and time-aggregate counters. Dictionary compression tests should verify repeated values and tiny values. Timestamp visibility tests should show obsolete starts being cleared only when globally visible and never for prepared/ingest cases. Disaggregated delta tests should verify already-durable updates are omitted and newly selected updates are included.

# sources/storage-engines/wiredtiger/src/reconcile/reconcile_private.h

Purpose: defines the private reconciliation data model shared by the reconcile implementation files. It describes split chunks, saved-update tracking, history-store cleanup queues, update-selection results, child-page reconciliation state, delta eligibility macros, pruning checks, and the large `WTI_RECONCILE` state object that carries one page reconciliation from initialization through write wrapup.

Important APIs and types: split macros `WTI_CROSSING_MIN_BND`, `WTI_CROSSING_SPLIT_BND`, and `WTI_CHECK_CROSSING_BND` drive boundary decisions. `WTI_REC_TW_START_VISIBLE_ALL` captures the start-time global visibility rule using reconciliation-start pinned state. `WTI_CHILD_MODIFY_STATE` reports whether an internal-page child is ignored, modified, original, or represented by a fast-truncate proxy. `WTI_REC_KV` stores a packed cell plus backing bytes. `WTI_REC_DICTIONARY` is the skip-list node for per-page dictionary compression. `WTI_REC_CHUNK` stores a pending disk image plus split-boundary key/recno and time aggregates. `WTI_DELETE_HS_UPD` records history-store updates that must be deleted. `WTI_RECONCILE` holds refs, pinned timestamps/IDs, max transaction/timestamp output, split sizing and buffers, counters, saved updates, `WT_MULTI` output, checkpoint wrapup image, compression state, fake cursor for modify reconstruction, and history-store cursor/cache flags. `WTI_UPDATE_SELECT` describes the update/tombstone and time window selected for a key. Macros such as `WT_REC_RESULT_SINGLE_PAGE`, `WT_BUILD_DELTA_LEAF`, `WT_BUILD_DELTA_INT`, and `WT_REC_CAN_PRUNE_UPD` centralize delta and pruning eligibility.

Control flow: `rec_write.c` initializes a `WTI_RECONCILE`, then page-type reconcilers fill its current chunk and update-selection fields. Internal-page reconciliation uses `WTI_CHILD_MODIFY_STATE` and child-release macros while walking children. Leaf reconciliation uses `WTI_UPDATE_SELECT` to decide what goes into the disk image, what is saved for the history store, what must be restored in memory, and what history-store entries should be deleted. Split helpers update `WTI_REC_CHUNK` aggregates through `WTI_REC_CHUNK_TA_UPDATE` and `WTI_REC_CHUNK_TA_MERGE`. At wrapup, the `multi` array becomes `WT_PAGE_MODIFY` replacement state or is cleaned up on error.

State and persistence behavior: this header itself is declarative, but its structures define the state that becomes persistent page layout. `WTI_REC_CHUNK.image` becomes a disk page image. `WTI_REC_CHUNK.ta` and per-block `WT_MULTI.addr.ta` become parent address time aggregates. `supd` entries are moved to history store or restored to memory. `delete_hs_upd` entries remove obsolete history-store content. `wrapup_checkpoint` is deferred until root checkpoint wrapup. `rec_start_pinned_ts`, `rec_start_oldest_id`, `rec_start_pinned_stable_ts`, and `rec_prune_timestamp` determine which transaction/timestamp metadata can be omitted or pruned.

Dependencies and integration points: depends on core page, ref, update, time-window, history-store, btree, and block metadata types. Prototype declarations connect to overflow tracking, row/column reconcilers, update selection, history-store insert/delete helpers, dictionary helpers, delta packing, split functions, and cell builders. The automatic prototype block is generated by `prototypes.py`, so additions should be made in source implementations and regenerated rather than manually edited.

Risks and sharp edges: `WTI_RECONCILE` is session-cached but not re-entrant; stale `ref` or uncleaned arrays can corrupt later reconciliations. Split chunks intentionally reuse `WT_ITEM` memory, so initialization must clear sizes without freeing backing buffers. The `ta_after_split_boundary` aggregate must stay consistent with full chunk aggregates for final-page repair. `WT_REC_RESULT_SINGLE_PAGE` looks at prior page-modify state and current page disk state; misuse can enable deltas for unsupported split states. Saved-update memory accounting and `supd_onpage_or_restore` affect split pressure and eviction progress. Prune and time-window visibility macros depend on pinned state captured at reconciliation start, not live global state.

Test signals: structure changes should trigger compiler failures across reconcile files and generated prototypes. Behavioral tests should cover child proxy states, saved update/history-store movement, time aggregate correctness across split repair, delta eligibility for leaf/internal pages, prune timestamp behavior, dictionary compression, and cleanup/reuse of session-cached reconciliation structures.

# sources/storage-engines/wiredtiger/src/rollback_to_stable/rts.c

Purpose: implements rollback-to-stable orchestration below the API layer: progress reporting, optional worker-thread lifecycle, metadata enumeration of btrees, queue draining, and the final history-store cleanup pass. It does not decide per-key rollback semantics itself; it coordinates `rts_btree_walk`, `rts_btree`, and `rts_history` helpers across all eligible btrees.

Important APIs and functions: `__wti_rts_btree_apply_all` is the exported orchestrator for all-file rollback to stable. It initializes progress state, counts metadata btree entries, starts helper threads, walks metadata to process or enqueue each btree via `__wti_rts_btree_walk_btree_apply`, lets the main thread help drain queued work, stops workers, and runs `__wti_rts_history_final_pass`. `__wti_rts_progress_msg_walk` emits per-btree progress and overall progress during page walks. `__rts_emit_overall_progress`, `__rts_progress_msg`, and `__rts_phase_string` format phase, throughput, and completion messages. `__rts_thread_create`, `__rts_thread_run`, `__rts_thread_stop`, and `__rts_thread_destroy` manage the RTS thread group and shared work queue.

Control flow: the all-file path first performs a metadata pass to compute `total_btrees`, then switches to `BTREE_APPLY` and starts the worker group if configured. During the second metadata pass, each non-metadata/non-history-store btree URI is handed to `__wti_rts_btree_walk_btree_apply`; that helper may process immediately or push a `WT_RTS_WORK_UNIT` for workers. If workers exist, the main thread enters `QUEUE_DRAIN`, temporarily renames its session to look like a worker in logs, and processes queue entries until empty. After worker destruction, non-in-memory connections enter `HS_FINAL_PASS` to remove unstable history-store entries left by checkpoint/eviction races. The phase is finally set to `COMPLETE`.

State and persistence behavior: the file mutates `S2C(session)->rts->progress` counters and phase fields, initializes and destroys `rts_lock`, sets and clears `WT_CONN_SERVER_RTS`, and uses the connection RTS queue `rtsqh`. Persistent data changes are delegated to btree walk/work-unit functions and the final history-store pass. Progress uses atomics for cross-thread counters and a CAS on `overall_last_report` so only one thread emits each periodic overall line.

Dependencies and integration points: depends on metadata cursors, connection thread-group infrastructure, condition variables, spin locks, RTS work-unit queue helpers (`__wti_rts_pop_work`, `__wti_rts_btree_work_unit`, `__wti_rts_work_free`), btree apply/walk code, history-store cleanup, verbose recovery progress logging, and the public progress callback. It also respects in-memory connections by skipping the history-store final pass.

Risks and sharp edges: metadata cursor cleanup and worker teardown must run on error to avoid leaked cursors, live helper threads, or a stuck `WT_CONN_SERVER_RTS` flag. The main thread queue-drain loop checks queue emptiness without holding the queue lock before popping; correctness relies on the pop helper and the fact that metadata production has ended. Session-name swapping must be restored on every error path. Progress percentages are approximate and depend on normalized page positions from btree walks. If worker count is zero, progress and apply still run synchronously, so code must not assume a thread group exists.

Test signals: all-file RTS tests should cover zero and nonzero worker counts, error paths during metadata walk and btree work, final history-store pass execution, in-memory skip behavior, progress logging under long btree walks, and queue draining with the main thread participating. Statistics/counters to watch include processed/skipped btree counts, pages walked, phase transitions, and final summary lines.

# sources/storage-engines/wiredtiger/src/rollback_to_stable/rts_api.c

Purpose: implements the rollback-to-stable API entry layer and connection initialization/reconfiguration hooks. It validates that the operation is safe to run, establishes the rollback timestamp from the stable timestamp, updates global transaction visibility state, opens an internal no-logging session, coordinates schema/checkpoint locks, optionally performs a forced checkpoint after rollback, and exposes single-object rollback for schema-worker style callers.

Important APIs and functions: `__wt_rollback_to_stable_init` installs function pointers into `conn->rts` and reads `rollback_to_stable.threads`. `__wt_rollback_to_stable_reconfig` updates the configured worker count. `__rollback_to_stable` parses per-call `dryrun` and `threads`, opens an internal session, sets RTS runtime config, records runtime stats, runs `__rollback_to_stable_int` under checkpoint and schema locks, logs a summary, finalizes RTS state, and closes the internal session. `__rollback_to_stable_int` performs active-session checks, updates oldest/pinned transaction state, chooses the rollback timestamp, invokes `__wti_rts_btree_apply_all`, updates the global durable timestamp when not dry-run, asserts pinned/stable timestamps did not move in diagnostic builds, and checkpoints when required. `__rollback_to_stable_one` rolls back one btree URI and sets the schema-worker skip flag for file objects. `__rts_check` and `__rts_check_callback` reject active transactions or open file cursors.

Control flow: API calls enter through the function pointer initialized on the connection. Runtime configuration is parsed defensively because internal callers can pass `NULL` config arrays. The operation then switches to an internal session to avoid handle caching and user-session concurrency surprises. `__rollback_to_stable_int` marks the session as RTS, checks for active user work, forces oldest transaction state forward with strict/wait flags, snapshots stable and pinned timestamps, logs the initial state, maps an unset stable timestamp to `WT_TS_MAX`, runs the all-btree RTS orchestrator, optionally rolls back the global durable timestamp to stable, and forces a checkpoint unless disabled, dry-run, or in-memory.

State and persistence behavior: mutates `conn->rts` runtime fields (`dryrun`, `threads_num`, progress), connection statistics (`txn_rollback_to_stable_running`), session flags (`WT_SESSION_ROLLBACK_TO_STABLE`, quiet corrupt file during single-btree apply), and global durable timestamp state. The rollback itself changes btree and history-store content through `__wti_rts_btree_apply_all`; a post-RTS forced checkpoint makes on-disk state match in-memory rollback results. Dry-run suppresses durable timestamp update and the final checkpoint while still exercising the traversal/reporting path configured by lower layers.

Dependencies and integration points: depends on session-array walking and `api_lock` for safety checks, checkpoint/schema locks for global exclusion, transaction global timestamp helpers, metadata search for single-object rollback, btree apply orchestration in `rts.c`, connection configuration parsing, verbose recovery logging, stats, internal session lifecycle, and the public WiredTiger checkpoint API.

Risks and sharp edges: `__rts_check` is best-effort; new cursors or transactions can appear after it returns unless higher-level locking and usage discipline prevent it. The function assumes callers hold checkpoint and schema locks in `__rollback_to_stable_int` and asserts that. Stable and pinned timestamps are read once and expected not to change; diagnostic assertions catch violations but production relies on external exclusion. Error handling must close the internal session and reset RTS runtime fields, but `txn_rollback_to_stable_running` is set back to zero only after the locked call returns, so panic/error paths should be reviewed carefully. Single-object rollback frees metadata config only on the normal path shown here; any added early return after metadata search must preserve cleanup.

Test signals: API tests should verify rejection with active transactions and active file cursors, behavior with stable timestamp unset, dry-run behavior, worker thread configuration parsing, forced-checkpoint suppression via `no_ckpt`/dry-run/in-memory modes, single-URI skip semantics, durable timestamp rollback to stable, reconfiguration of `rollback_to_stable.threads`, and diagnostic timestamp-stability assertions.
