# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_csr.h

This header is the register map backbone for the hinic3 PCI hardware interface. It defines the encoded register-space flags for configuration and management BAR access, the VF configuration offset, function attribute registers, mailbox registers, PPF election, DMA attribute table registers, MSI-X control bits, and AEQ/CEQ queue control and page-address registers. The main API surface is macro-only: `HINIC3_CSR_FUNC_ATTR*_ADDR`, `HINIC3_FUNC_CSR_MAILBOX_*`, `HINIC3_MSI_CLR_INDIR_SET`, `HINIC3_EQ_INDIR_IDX_ADDR`, and AEQ/CEQ physical address helpers. Control flow is indirect: `hinic3_hwif.c`, `hinic3_eqs.c`, `hinic3_mbox.c`, and `hinic3_hwdev.c` compose these macros into read/write sequences. State is persisted in device registers, not in this file. Key dependencies are Linux `BIT`, `GENMASK`, and `FIELD_PREP` conventions from including compilation units. Integration risk is high because all offsets and bit layouts are hardware ABI; wrong flags can route reads to the wrong BAR or corrupt queue/MSI state. Test signals are PCI probe success, mailbox send completion, EQ initialization, MSI-X masking/unmasking, and diagnostics from `hinic3_dump_aeq_info()`/`hinic3_dump_ceq_info()`.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_eqs.c

This file implements hinic3 asynchronous event queues and completion event queues. Important APIs are callback registration (`hinic3_aeq_register_cb`, `hinic3_ceq_register_cb`), lifecycle (`hinic3_aeqs_init/free`, `hinic3_ceqs_init/free`), and dump helpers. Initialization allocates queue pages, writes DMA page addresses into CSR MTT registers, configures AEQ registers directly or CEQ registers through a management command, arms the consumer index, requests MSI-X IRQs, and enables vectors after all queues are ready. Runtime control flow polls descriptors until the wrapped bit says no more work; AEQ events are copied/swabbed and dispatched from a workqueue, while CEQ events are processed in a threaded IRQ. State includes `cons_idx`, `wrapped`, DMA queue pages, callback arrays, IRQ IDs, and `soft_intr_jif`. Dependencies include `hinic3_queue_common`, CSR helpers, MSI-X helpers in `hinic3_hwif.c`, mailbox management calls, and cmdq/mgmt users of callbacks. Risks are endian mistakes, missing memory barriers around DMA descriptors, callback unregister races, queue overrun if `HINIC3_TASK_PROCESS_EQE_LIMIT` is exceeded repeatedly, and teardown ordering before freeing queue pages. Test signals are interrupt delivery, cmdq CEQ completion, mailbox/mgmt AEQ reception, forced dump output, and probe/remove leak checks.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_mbox.c

This file implements mailbox transport between driver, management CPU, and PF/VF functions. Initialization allocates message channels, sync/async DMA queues, a write-back status DMA buffer, a single-thread workqueue, and optional VF-to-PF channel.
