# Research: subset-b-006562

This grouped report covers the USB audio mixer core, its public mixer data contract, and the static mixer mapping tables. Each section preserves the source path in its title and is wrapped for deterministic reconciliation into per-file research documents.

## sources/distributed-fs/ceph-client/sound/usb/mixer.c

Purpose: implements the generic ALSA USB Audio mixer for UAC1, UAC2, UAC3, and UAC3 BADD devices. It parses class-specific AudioControl descriptors, creates ALSA mixer/card controls for feature, mixer, selector, processing, extension, clock-validity, and connector-insertion units, transports ALSA get/put operations over USB class control requests, handles status interrupt notifications, exposes a `/proc` mixer dump, and restores cached control values across suspend/resume.

Important APIs and types: `snd_usb_create_mixer()` is the entry point used by the USB audio card layer to allocate `struct usb_mixer_interface`, select protocol, build controls, create the status interrupt URB, apply creation quirks, register the mixer as an ALSA device, and link it into `chip->mixer_list`. `snd_usb_mixer_disconnect()`, `snd_usb_mixer_suspend()`, and `snd_usb_mixer_resume()` own lifecycle transitions. `snd_usb_mixer_notify_id()` invalidates cached values and emits ALSA control notifications for a changed unit. `snd_usb_mixer_add_list()` registers an ALSA `snd_kcontrol` and indexes the element under `mixer->id_elems[unitid]`. `snd_usb_mixer_set_ctl_value()`, `snd_usb_set_cur_mix_value()`, and `snd_usb_get_cur_mix_value()` are reusable helpers for quirk code and other mixer modules. The local `struct mixer_build` carries descriptor buffer, protocol-specific maps, visited bitmaps, and current output terminal context while recursively parsing topology. The local `struct usb_audio_term` is the normalized terminal description used for naming and routing decisions.

Control transfer flow: `get_ctl_value_v1()` sends UAC1 `GET_*` requests with `wValue=(control << 8) | channel` and `wIndex=(unit << 8) | interface`, retries non-timeout short failures, converts 1 or 2 byte payloads by signedness, and honors runtime PM locking through `CLASS(snd_usb_lock, pm)`. `get_ctl_value_v2()` maps legacy `UAC_GET_CUR/MIN/MAX/RES` calls onto UAC2/3 `CUR` and `RANGE` requests and reads the first range triplet. `snd_usb_mixer_set_ctl_value()` performs the matching SET path, translating UAC2/3 `SET_CUR` to `UAC2_CS_CUR`; non-current RANGE writes are explicitly unsupported. `snd_usb_get_cur_mix_value()` and `snd_usb_set_cur_mix_value()` maintain the per-channel cache in `usb_mixer_elem_info::cached/cache_val`, with `master_readonly` and `ch_readonly` suppressing writes on read-only UAC2/3 controls.

Descriptor parsing and control creation: `snd_usb_mixer_controls()` walks every output terminal descriptor in the AudioControl interface, records the current output terminal, then recursively calls `parse_audio_unit()` on source units and clock sources. `parse_audio_unit()` validates descriptors with `snd_usb_validate_audio_desc()` and dispatches by `(protocol, subtype)` to input terminal, mixer unit, clock source, selector, feature, processing, or extension parsers. `check_input_term()` follows feature-unit chains back to an input terminal or branched virtual unit, with loop protection via `termbitmap`. Feature units are expanded by `parse_audio_feature_unit()`, which decodes UAC1 bitmasks or UAC2/3 readable/writeable fields, applies device-specific master-volume quirks, and calls `build_feature_ctl()` for master and channel controls. `__build_feature_ctl()` performs map lookup, ignore filtering, type selection, channel counting, name construction, min/max/res probing, dB TLV setup, quirk hooks, insane-range warnings, and finally `snd_usb_mixer_add_control()`.

Other unit flows: mixer units use `uac_mixer_unit_get_channels()`, `mixer_bitmap_overflow()`, and the input/output control bitmap to create source volume controls through `build_mixer_unit_ctl()`. Selector units allocate an enumerated ALSA control with per-input names from device string descriptors, terminal names, or `usbmix_selector_map`; their stored min/max are 1-based USB selector values while ALSA exposes zero-based enum indexes. Processing and extension units share `build_audio_procunit()`, which uses static `procunit_info` tables for up/downmix, prologic, stereo extender, reverb, chorus, dynamic range, selected UAC3 units, and E-Mu extension-unit controls. Clock source parsing exposes a read-only "Validity" card control when UAC2 clock-validity is readable. UAC2/UAC3 connector insertion controls are reported as boolean card controls via `build_connector_control()`.

UAC3 BADD path: `snd_usb_mixer_controls_badd()` handles Basic Audio Device Definition profiles that lack normal class-specific topology descriptors. It infers capture/playback mono or stereo channel masks from alternate setting 1 endpoint `wMaxPacketSize` values in the interface association, validates those masks against `uac3_badd_profiles`, looks up profile-specific names in `uac3_badd_usbmix_ctl_maps`, and synthesizes feature controls with fixed BADD unit IDs. Headset-adapter profiles also receive input/output insertion controls.

State and persistence behavior: persistent runtime state lives in `struct usb_mixer_interface` and each `struct usb_mixer_elem_info`. `id_elems` is a 256-entry unit-id index used by notifications, proc output, cleanup, and resume. `usb_mixer_elem_info` stores USB request identity (`id`, `control`, `idx_off`, channel mask), ALSA exposure (`channels`, `max_exposed`, TLV dB bounds), hardware range (`min/max/res`), read-only masks, cache bits, and optional private data. The cache is invalidated on status interrupts and used on resume to restore only values that were known before suspend. `snd_usb_mixer_free()` kills URBs, unregisters ALSA controls before freeing `id_elems`, releases status and remote-control resources, invokes private cleanup through `snd_usb_mixer_disconnect()`, and frees the mixer.

Notifications and interrupts: `snd_usb_mixer_status_create()` installs an interrupt IN URB when the control interface exposes one. `snd_usb_mixer_interrupt()` decodes UAC1 status words or UAC2/3 interrupt data messages, ignores endpoint/vendor events in UAC2/3, delegates connector notifications through `delegate_notify()` when a static connector map redirects a jack unit to a terminal/FU, invalidates caches, and raises `SNDRV_CTL_EVENT_MASK_VALUE` through ALSA. UAC1 memory-change status is delegated to `snd_usb_mixer_rc_memory_change()` in the quirks layer. The URB is resubmitted unless it was killed or the device shut down.

Dependencies and integration points: this file depends on Linux USB descriptor and URB APIs, ALSA control/proc/TLV APIs, USB Audio descriptor helpers from `helper.h`, runtime power helpers from `power.h`, generic device/card state from `usbaudio.h`, and quirk extension points from `mixer_quirks.h`. It directly includes `mixer_maps.c`, so the static map structures declared there are part of this compilation unit rather than a separate object. It is called by `card.c` for creation, suspend, and resume, and is consumed by quirk modules such as `mixer_quirks.c`, Focusrite/Scarlett code, and vendor mixers through exported helpers and `snd_usb_feature_unit_ctl`.

Risks: descriptor parsing is intentionally tolerant, but malformed lengths, too many channels, or recursive loops can drop controls or abort mixer creation. Several hardware probes write temporary values to live controls to detect sticky mixers and actual resolution; bugs here can audibly change device state, so saved values must be restored reliably. `BIT(channel)` and `BIT(c)` are used with `MAX_CHANNELS` up to 64, so channel bounds and integer width assumptions are important. Static name maps can hide controls by setting a NULL name; a wrong map entry can remove user-visible functionality. UAC2/3 RANGE handling only reads the first range triplet and does not implement RANGE/MEM writes or interrupt dispatch. Error filtering under `QUIRK_FLAG_IGNORE_CTL_ERROR` can mask faulty devices. Connector fallback treats "Speaker" jack read errors as inserted, trading correctness for usability on known-broken hardware.

Test signals: useful signals include ALSA mixer control count and names from `amixer`, `alsactl` restore across suspend/resume, `/proc/asound/card*/usbmixer` contents, dB TLV ranges and min-mute flags, status interrupt driven notifications on hardware knob/jack changes, absence of duplicate control indexes, probe logs for invalid descriptors or skipped bogus volumes, and targeted USB device tests for mapped devices in `mixer_maps.c`. Regression tests should cover UAC1 feature units, UAC2 selector/clock/connector controls, UAC3 BADD profile synthesis, read-only UAC2 controls, cache invalidation after `snd_usb_mixer_notify_id()`, and quirk paths that alter ranges or names.

## sources/distributed-fs/ceph-client/sound/usb/mixer.h

Purpose: declares the USB audio mixer interface shared between the generic mixer core, mixer quirk modules, USB audio card lifecycle code, and vendor-specific mixer implementations. It defines the runtime mixer object, per-control metadata, value type enum, list traversal helpers, and exported functions needed to create, operate, notify, suspend, resume, and free USB mixer controls.

Important types and contracts: `struct usbmix_connector_map` maps a status-notification unit id to a delegated terminal or feature-unit id, with optional replacement control and channel values; `mixer_maps.c` populates arrays of these for Realtek motherboard jack layouts. `struct usb_mixer_interface` owns one AudioControl interface: its `chip`, `hostif`, list link, `ignore_ctl_error` flag, status `urb`, `id_elems` unit index, UAC protocol version, optional connector map, Sound Blaster remote-control fields, media-controller hook, disconnect bit, and quirk private callbacks. `struct usb_mixer_elem_list` is the common prefix for every mixer element tracked by unit id; it stores the parent mixer, next element under the same id, attached ALSA control, id, standard-info marker, optional proc dump callback, and resume callback. `struct usb_mixer_elem_info` extends that prefix for standard numeric controls with USB control number, channel mask, index offset, read-only masks, value type, range, dB range, cache, min-mute marker, and private data.

APIs: `snd_usb_create_mixer()` constructs and registers a mixer for a control interface; `snd_usb_mixer_disconnect()` kills URBs and private state; `snd_usb_mixer_suspend()` and `snd_usb_mixer_resume()` stop bus activity and restore cached values; `snd_usb_mixer_notify_id()` invalidates cached controls for a unit and raises ALSA notifications. `snd_usb_mixer_set_ctl_value()`, `snd_usb_set_cur_mix_value()`, and `snd_usb_get_cur_mix_value()` expose the generic USB control transport to quirk code. `snd_usb_mixer_add_list()` registers an element and inserts it into the unit-id index, with the `snd_usb_mixer_add_control()` macro marking normal ALSA mixer controls as standard-info elements. `snd_usb_mixer_elem_init_std()` initializes the common prefix with default dump/resume behavior. `snd_usb_mixer_vol_tlv()` is the shared TLV dB callback, and `snd_usb_mixer_elem_free()` is the private-free hook for standard element controls. `snd_usb_feature_unit_ctl` exposes the standard feature-unit control template to quirk builders.

Control flow and state behavior: the header codifies that every standard control is reachable from `mixer->id_elems[id]` and traversed with `for_each_mixer_elem()`. Notifications, proc dumps, cleanup, and resume depend on the list prefix being initialized correctly. State persists for the lifetime of the ALSA card device and is released by the mixer device-free path. The value cache is per `usb_mixer_elem_info`, not global, and uses `MAX_CHANNELS` as the maximum logical channel count.

Dependencies and integration: includes `<sound/info.h>` for proc dump types and relies on surrounding USB audio headers for declarations of `struct snd_usb_audio`, `struct snd_kcontrol`, URBs, wait queues, and list heads. It is included by `mixer.c`, `mixer_quirks.c`, vendor-specific USB mixer files, and card lifecycle code. The `media_mixer_ctl` forward declaration supports optional media-controller integration without requiring that header everywhere.

Risks: the structures are shared internal ABI inside the driver, so field semantics must stay synchronized with all quirk modules. `MAX_CHANNELS` must match all cache and bitmask users; widening channel support requires auditing `u64 cmask`, `BIT()` uses, and `cache_val`. `id_elems` is documented as `MAX_ID_ELEMS` sized but the constant is local to `mixer.c`, so other users rely on mixer.c allocation and bounds enforcement. Quirk callbacks in `usb_mixer_interface` must be safe during disconnect and suspend because the core invokes them while tearing down or stopping URBs.

Test signals: compile coverage from all USB mixer and quirk objects is the main contract test. Runtime signals include valid `/proc/asound/.../usbmixer` dumps for every registered `usb_mixer_elem_list`, working cache restore after resume, no stale notifications after disconnect, and quirk-created controls using `snd_usb_feature_unit_ctl` without double-free or missing `private_free` behavior.

## sources/distributed-fs/ceph-client/sound/usb/mixer_maps.c

Purpose: provides static mixer mapping data consumed by `mixer.c` to correct or suppress generic USB audio mixer controls for devices whose descriptors produce misleading names, unusable controls, bogus dB ranges, or connector notification IDs that do not match the user-facing terminal controls. The file is included directly into `mixer.c`, so its structures and arrays are private to that compilation unit.

Important types and data: `struct usbmix_dB_map` supplies corrected dB min/max values and optional min-mute semantics. `struct usbmix_name_map` maps a unit id and optional control selector to a replacement ALSA name, a disabled control (`name == NULL` with no dB map), and/or a corrected dB map. `struct usbmix_selector_map` supplies enum item names for selector units. `struct usbmix_ctl_map` ties a USB product id or UAC3 BADD subclass id to a name map, selector map, and connector map. The top-level `usbmix_ctl_maps[]` is matched against `chip->usb_id` in `snd_usb_mixer_controls()`, while `uac3_badd_usbmix_ctl_maps[]` is matched against a BADD function subclass in `snd_usb_mixer_controls_badd()`.

Device coverage: the maps cover older Creative devices such as Extigy, MP3+, Audigy 2 NX, and Live 24-bit External; M-Audio Fast Track C400/C600 selector labels; Maplin/Justlink, TerraTec Aureon, Maya44, Scratch Live, Ebox44, Hercules, Plantronics Gamecom 780, SCMS USB3318 based devices, Bose Companion/SoundLink, Sennheiser PC 8, Dell ALC4020 docks, Corsair Virtuoso/HS80, Microsoft USB Link, KTMicro, and multiple Realtek USB-audio motherboard designs from ASUS, Gigabyte, MSI, Asrock, and Lenovo. UAC3 BADD maps provide generic profile names for generic I/O, headphone, speaker, microphone, headset, headset adapter, and speakerphone profiles.

Integration flow: `mixer.c` calls `find_map()` with the selected `state.map` before creating feature, mixer, selector, processing, extension, and connector controls. If a matched map has no `name` and no dB map, `check_ignored_ctl()` suppresses the control entirely. If `name` is present, `check_mapped_name()` overrides generated names. If `dB` is present, `check_mapped_dB()` overwrites the probed dB min/max and min-mute flag. Selector maps are used by `check_mapped_selector_name()` to replace enum item names. Connector maps are stored in `mixer->connector_map`; `delegate_notify()` uses them to redirect status interrupts from connector unit ids to the ALSA controls whose caches and userspace notifications should be updated.

State and persistence behavior: the file contains only static immutable mapping tables. Runtime state is not stored here; the matched table pointers are copied into `mixer_build` or `usb_mixer_interface` during control construction. Because the arrays are direct C data, adding a new quirk changes kernel behavior at probe time without any firmware or userspace configuration.

Dependencies and integration points: the file relies on constants from Linux USB Audio headers and `mixer.h` because it is included after those declarations in `mixer.c`. It also relies on `USB_ID()` product matching and on UAC feature-control numeric constants. Names in these tables are ALSA user-visible control names, so they integrate with alsa-lib, PulseAudio/PipeWire policy, UCM profiles, and user scripts.

Risks: map entries are fragile because unit ids and control selectors are device-descriptor specific. A firmware revision that changes topology can make an entry hide the wrong control or rename an unrelated one. Several dB maps are documented as guesses, so ALSA TLV volume policy may still be inaccurate. Duplicate product ids or broad reuse of a map across related devices can unintentionally inherit stale quirks. Connector delegation maps must use the correct terminal/control/channel tuple; otherwise hardware jack interrupts will invalidate the wrong cache or fail to notify userspace. Since the file is included into `mixer.c`, type or symbol name changes in the core can break these tables at compile time.

Test signals: for each mapped USB id, compare `amixer` names, control counts, dB TLV values, selector enum labels, and jack notifications against expected hardware behavior. Disabled controls should be absent and should not be accessed during probe. Realtek motherboard connector maps should generate ALSA value notifications when physical jacks change. UAC3 BADD profile devices should expose profile-appropriate "Playback", "Capture", and "Sidetone Mixing" names rather than anonymous feature-unit names.
