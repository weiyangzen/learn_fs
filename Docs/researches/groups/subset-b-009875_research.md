# sources/user-network-fs/samba/source3/smbd/smb2_server.c

Purpose: implements the source3 SMB2/SMB3 server core: request parsing, dispatch, credit accounting, signing/encryption enforcement, compound request sequencing, async interim responses, socket read/write integration, multichannel transport shutdown, and server-originated oplock or lease break notification delivery. It is the central switchboard between decoded SMB2 PDUs and the per-command handlers in the rest of `source3/smbd`.

Important APIs, types, and functions: `smbd_smb2_table` describes every SMB2 opcode with session/tree requirements, file-id location, root impersonation, and modify semantics. `smb2_opcode_name()`, `smbd_is_smb2_header()`, `smbd_smb2_is_compound()`, and `smbd_smb2_is_last_in_compound()` are small exported helpers. `smbd_initialize_smb2()` converts an accepted transport to SMB2 mode, sets the initial credit window, installs the tevent fd handler, and configures blocking behavior. `smbd_smb2_inbuf_parse_compound()` splits an incoming transport payload into transform, header, fixed body, and dynamic iovecs, including SMB3 transform decryption through `smb2_signing_decrypt_pdu()`. `smbd_smb2_request_validate()`, `smb2_validate_message_id()`, and `smb2_validate_sequence_number()` enforce credit and message-id replay rules. `smbd_smb2_request_dispatch()` verifies session, tree, file id, signing, encryption, and channel sequence state before invoking the specific command processor such as `smbd_smb2_request_process_create()`, `..._setinfo()`, `..._tcon()`, or `..._sesssetup()`. `smbd_smb2_request_done_ex()` and `smbd_smb2_request_error_ex()` build final replies. `smbd_smb2_flush_send_queue()`, `smbd_smb2_io_handler()`, and `smbd_smb2_connection_handler()` drive network I/O. `smbd_smb2_send_oplock_break()` and `smbd_smb2_send_lease_break()` enqueue unsolicited break notifications and wait for TCP acknowledgement when required.

Control flow: after SMB1 negotiation hands an SMB2 negotiate PDU to `smbd_smb2_process_negprot()`, the file initializes SMB2 state, creates a request, validates message ids, builds default output vectors, dispatches the negotiate command, and schedules the next read. Normal reads start with a 4-byte NBT header, then read either the complete payload or a short prefix for possible receivefile-optimized SMB2 WRITE. A complete payload is parsed into one or more command iovec groups. Dispatch first enforces dialect phase rules, resolves session and tree context, validates allowed header flags, checks request signing or transform encryption, updates per-session/tcon crypto-use flags, verifies file ids and per-open channel sequence counters, changes impersonation as needed, and calls the opcode implementation. Replies advance through compound chains with tevent immediates so remaining compound elements are processed before unrelated incoming requests. Final reply setup recalculates compound offsets and padding, grants credits, signs or encrypts the response, updates SMB3 preauth hashes, moves the request from the active list to the send queue, and flushes through `sendmsg()` or the sendfile path.

State and persistence behavior: most state is in `struct smbXsrv_connection`, `struct smbXsrv_client`, `struct smbXsrv_session`, `struct smbXsrv_tcon`, and `struct smbd_smb2_request`. The file mutates volatile connection credit fields (`seq_low`, `seq_range`, `granted`, bitmap), send and ack queues, pending break lists, request lists, and transport status. It also persists selected changes indirectly through `smbXsrv_session_update()`, `smbXsrv_tcon_update()`, and `smbXsrv_open_update()` when crypto flags or SMB3 channel sequence fields change. Encryption nonce counters live in the session and must never wrap; `smb2_get_new_nonce()` returns `NT_STATUS_ENCRYPTION_FAILED` when the high nonce limit is reached.

Dependencies and integration points: depends on tevent, talloc, socket APIs, Samba bitmap/iovec helpers, GnuTLS hashing, SMB signing/encryption helpers, loadparm, SMB profile counters, smbXsrv session/tcon/open tables, VFS-facing `files_struct` lookup, and all per-opcode `smbd_smb2_request_process_*` implementations. It integrates with SMB3 multichannel by tracking per-connection channels, TCP ack progress, and channel sequence counters. It integrates with lease/oplock subsystems by sending break notifications and scheduling retry across available channels.

Risks: malformed compound offsets, dynamic lengths, transform headers, or receivefile shortcuts can desynchronize parsing from socket drain state. Credit-window bitmap handling is security-sensitive because duplicate or out-of-window message ids are replay signals. Signing and encryption decisions depend on subtle session, tcon, guest, transform, and channel binding state; regressions can either reject valid clients or accept unsigned/unencrypted traffic where policy requires protection. Async compound handling has protocol constraints and explicitly cancels disallowed async middle operations. Nonce wrap must terminate encrypted communication before reuse. Shutdown and tree disconnect paths wait for in-flight requests without cancelling in ways that would break replay detection, which is easy to regress.

Test signals: SMB torture coverage should include negotiate-only startup, invalid first commands, credit charge and duplicate message-id failures, compound chains with success and error continuation, async pending responses, cancellation by message id and async id, encrypted SMB3 transform input, signing-required and encryption-required sessions/tcons, SMB3.1.1 preauth hash continuity, receivefile write fallback cases, send queue backpressure, multichannel transport termination, lease/oplock break ack timeouts, and channel sequence behavior for modifying requests.

# sources/user-network-fs/samba/source3/smbd/smb2_service.c

Purpose: creates and tears down source3 `connection_struct` objects for SMB2 tree connects. It translates a selected share number and authenticated SMB2 session into a fully initialized service connection with canonical paths, access checks, forced user/group policy, VFS state, notifications, preexec hooks, and cleanup hooks.

Important APIs and functions: `set_conn_connectpath()` canonicalizes and stores the share root path and initializes `conn->cwd_fsp->fsp_name`. `canonicalize_connect_path()` resolves the path through `SMB_VFS_REALPATH()`. `chdir_current_service()` switches the process cwd to the share root through VFS and logs the current Unix token on failure. `share_sanity_checks()` validates local address restrictions, hosts allow/deny, device type, printable and IPC classification. `find_forced_group()` resolves `force group`, handles the leading `+` membership requirement, and maps the group SID to a gid. `create_connection_session_info()` copies or replaces the incoming session info, applying guest-only and guest-ok share policy. `set_conn_force_user_group()` applies `force user` and `force group` by replacing the connection session info and cached gid. `notify_init_sconn()` lazily initializes change notification state and messaging handlers. `make_connection_snum()` is the main constructor. `make_connection_smb2()` allocates a `connection_struct`, assigns the SMB2 tree id, and delegates to `make_connection_snum()`. `close_cnum()` closes open files, disconnects VFS, runs postexec hooks, and frees the connection.

Control flow: tree connect code has already resolved a service number and allocated an SMB2 tcon. `make_connection_smb2()` creates a connection, sets `cnum` from the tcon wire id, and calls `make_connection_snum()`. The constructor first performs root-level share sanity checks and builds per-connection session info from the SMB2 session. It sets type flags for printer and IPC shares, case options, encryption level, read-only status, forced user/group state, and the substituted connect path. It checks share ACL access with the original authenticated user, initializes VFS, references per-share profiling, runs the VFS connect hook, initializes notifications and kernel oplocks when appropriate, canonicalizes the path for preexec and later path containment, runs root and user preexec commands, optionally performs AFS login, returns to root, canonicalizes again through VFS realpath, loads veto and aio-write-behind name arrays, validates that the share path exists and is a directory, records filesystem capabilities, logs the effective identity, and marks `conn->tcon_done`. Error paths return as root, call VFS disconnect only after connect succeeded, unreference profiling when needed, and free temporary path state.

State and persistence behavior: the file mutates in-memory per-tree connection state: `conn->params->service`, `conn->session_info`, force-user/group flags, `conn->connectpath`, `conn->cwd_fsp`, access masks, encryption level, VFS handles, share capability fields, profiling references, notification context, and base device id. It can run administrator-configured preexec and postexec commands, which may have external side effects. It does not itself persist tcon records, but it attaches the compatibility `connection_struct` later persisted or tracked through the SMB2 tcon object.

Dependencies and integration points: depends heavily on loadparm share options, substitution helpers, auth session utilities, SID/name lookup, host access checks, VFS operations, notification messaging, printer and IPC classification, AFS optional support, and profiling. It is called from `smb2_tcon.c` and supplies the `connection_struct` consumed by later command dispatch via `req->tcon->compat` and `change_to_user_and_service()`.

Risks: forced user/group behavior is security-sensitive because it rewrites Unix credentials while preserving the original sanitized username for substitutions. Share ACLs intentionally use the incoming authenticated session rather than the forced user; changing that would alter access semantics. Preexec/root preexec hooks can deny connections or create paths, so path canonicalization order matters. Error cleanup must not call VFS disconnect before VFS connect succeeds and must return to root before cleanup. `conn->connectpath` must remain canonical, absolute, and suitable for later path containment checks. Encryption-level handling rejects required per-share encryption when global encryption is disabled; regressions here can silently weaken policy.

Test signals: cover guest-only, guest-ok denied, user token denied, forced user, forced group with and without `+` membership, bad device names for disk/print/IPC shares, hosts allow/deny and local-address restrictions, missing/non-directory share roots, VFS connect/stat failure, preexec close behavior, root preexec close behavior, notification initialization failure, per-share encryption required with global encryption disabled, close path postexec/root postexec execution, and cleanup after constructor failures at each staged resource acquisition.

# sources/user-network-fs/samba/source3/smbd/smb2_sesssetup.c

Purpose: implements SMB2 SESSION_SETUP and LOGOFF for source3. It drives SPNEGO/GENSEC authentication, creates or reauthenticates SMB2 sessions, handles SMB3 multichannel session binding, derives signing/encryption/application keys, updates preauthentication state, closes previous sessions when requested, and tears sessions down on logoff.

Important APIs and functions: `smbd_smb2_request_process_sesssetup()` parses the SMB2 fixed body and security blob, starts the wrapped session setup request, and suppresses STATUS_PENDING interim replies. `smbd_smb2_request_sesssetup_done()` formats the session setup response with session id, flags, and output security blob. `smbd_smb2_auth_generic_return()` finalizes a new authenticated session: computes SMB3.1.1 preauth hash, chooses signing and encryption policy, derives signing/encryption/decryption/application keys, sets nonce limits, moves `auth_session_info` into the session global, claims and updates the session, and enables response signing for non-guest users. `smbd_smb2_reauth_generic_return()` replaces the session auth info while preserving the established application key. `smbd_smb2_bind_auth_return()` validates multichannel binding identity and creates a channel signing key. `smbd_smb2_session_setup_send()` validates binding preconditions, creates or locates sessions/auth contexts, starts SPNEGO through `gensec_update_send()`, and updates session state. `smbd_smb2_session_setup_gensec_done()`, `..._previous_done()`, and `..._auth_return()` complete the state machine. The wrap layer `smbd_smb2_session_setup_wrap_*()` increments auth success/failure profile counters and cleans up failed sessions or failed channel bindings. `smbd_smb2_request_process_logoff()` and `smbd_smb2_logoff_send()` shut down and log off a session.

Control flow: a SESSION_SETUP request is size-checked, its security-buffer offset and length are validated, and its security blob is passed to the async wrapper. For a new session, `smbXsrv_session_create()` allocates a session and `smbXsrv_session_create_auth()` creates per-connection auth state if none exists. For a session bind, the request must name an existing session, be SMB3 or newer, have multichannel enabled, be signed, match dialect and cipher, not be a cross-process global placeholder, and either reuse an unauthenticated channel or add a new channel. GENSEC/SPNEGO then processes the client token. `MORE_PROCESSING_REQUIRED` returns an output token and preserves preauth state for the response. Success obtains `auth_session_info`; if `PreviousSessionId` is set and not equal to the new session id, the previous session is closed before finalizing. Finalization chooses among channel bind, reauth, or first authentication. LOGOFF asynchronously shuts down outstanding session state, removes remote architecture cache entries keyed by client GUID, calls `smbXsrv_session_logoff()`, and keeps the session talloc-owned by the request until the signed response is sent.

State and persistence behavior: this file mutates session globals: signing/encryption flags, signing algorithm, encryption cipher, signing/application/encryption/decryption key blobs, channel signing keys, nonce counters, `got_authenticated_session` on the connection, `auth_session_info`, auth sequence numbers, auth and expiration times, homes share number, and session status. It persists or publishes state through `smbXsrv_session_update()`, `session_claim()`, `smbXsrv_session_add_channel()`, `smbXsrv_session_remove_channel()`, `smb2srv_session_shutdown_send()`, and `smbXsrv_session_logoff()`. It clears the original session key and replaces it with the application key for downstream SMB semantics.

Dependencies and integration points: depends on GENSEC/SPNEGO, Samba auth session creation, SMB2 signing derivation helpers, GnuTLS SHA512 for SMB3.1.1 preauth, loadparm encryption/signing policy, session tables, multichannel channel tables, homes share registration, service reload, profile counters, remote architecture cache, and the core server reply/signing path in `smb2_server.c`.

Risks: preauth hash ordering and key derivation inputs are protocol-critical for SMB3.1.1. Guest sessions deliberately disable required signing and cannot be accepted when encryption is required; weakening that creates policy bypass. Multichannel binding validates identity by primary SID and requires a non-empty session key; missing any dialect, cipher, signing, or channel checks can permit invalid channel attachment. Failed authentication must clean up newly created sessions but keep enough session state to sign an error response when required. Reauth must refresh cached connection vuid state. Key dumping for debug encryption must remain gated by configuration.

Test signals: cover NTLM/Kerberos multi-leg setup with `MORE_PROCESSING_REQUIRED`, guest fallback, anonymous/guest with encryption required, signing-required negotiation, encryption desired and required, unsupported dialect/cipher for encryption, SMB3.1.1 preauth integrity, previous-session close, reauthentication of an existing session, failed authentication cleanup, session bind success and failures for unsigned bind, SMB2 dialect, disabled multichannel, wrong dialect/cipher, wrong user SID, empty session key, cross-process placeholder sessions, logoff with outstanding opens, and signed logoff response ownership.

# sources/user-network-fs/samba/source3/smbd/smb2_setinfo.c

Purpose: implements SMB2 SET_INFO for file, filesystem, security descriptor, and quota updates. It validates the incoming SMB2 request, maps SMB2 info classes to source3 trans2/setfileinfo levels, performs VFS-backed mutations, and coordinates lease-break waits for rename, delete-on-close, destination overwrite, and destination parent directory cases.

Important APIs and functions: `smbd_smb2_request_process_setinfo()` parses the SMB2 body, validates dynamic input buffer placement, max transaction size, credit charge, and file id, then starts `smbd_smb2_setinfo_send()`. `smbd_smb2_request_setinfo_done()` returns the 2-byte success body or an SMB2 error. `smbd_smb2_setinfo_send()` handles info-type dispatch. For `SMB2_0_INFO_FILE`, it maps file classes by adding 1000, maps SMB2 rename to `SMB2_FILE_RENAME_INFORMATION_INTERNAL`, validates the target `files_struct`, special-cases print-job delete-on-close cancellation, and enters lease-break checking. Filesystem info delegates to `smbd_do_setfsinfo()`, security info uses `set_sd_blob()`, and quota info parses `file_quota_information` and calls `vfs_set_ntquota()` when quotas are available. `smb2_parse_file_rename_information_dst()` parses SMB2 rename data, disables DFS pathname interpretation, handles alternate stream renames, and resolves destination directory/name. `smbd_smb2_setinfo_lease_break_check()` sequences rename-destination, destination-parent, and source-fsp lease checks before calling `smbd_do_setfilepathinfo()`.

Control flow: request processing creates a fake SMB1 request because lower source3 setinfo helpers use SMB1-era request structures. IPC tree connects are rejected. File information updates first ensure a path reference, stat directory handles, or fstat open files as appropriate. The asynchronous lease-break path is a staged state machine. For rename overwrite, it resolves the destination, opens the existing destination with internal-only access, waits for handle lease breaks, checks for other non-POSIX opens, closes the temporary destination fsp, and then continues. For non-stream renames, it also locks the destination parent directory, waits for leases with delete rights, checks delete opens and delete-pending state, and then continues. For source rename or delete-on-close, it obtains the source share mode lock and waits for handle lease breaks. After any async wait resumes, the code re-establishes the user/service impersonation before performing checks or the final mutation. The final mutation calls `smbd_do_setfilepathinfo()` under the share mode lock, then frees the lock and completes the tevent request.

State and persistence behavior: successful operations mutate filesystem metadata, namespace entries, security descriptors, quota records, or print-job state through VFS and lower smbd helpers. In-memory request state stores `fsp`, locks, temporary destination fsps, destination parent fsps, parsed input buffer, and booleans that prevent repeated staged checks after async callbacks. Share mode locks and temporary opens are deliberately talloc-scoped and freed on cleanup or after use. For print files, setting disposition with true marks `fsp->fsp_flags.delete_on_close` to cancel the job rather than invoking normal filesystem setinfo.

Dependencies and integration points: depends on share mode locking, lease break delay helpers, DB wrap watch infrastructure, generated quota NDR, security descriptor helpers, trans2 setinfo implementations, SMB filename conversion, VFS create/stat/quota/security operations, messaging, and the core SMB2 async pending mechanism. It integrates with `smb2_server.c` through file-id prevalidation, modify-call channel sequence accounting, and no-interim async handling for rename-triggered lease breaks.

Risks: rename semantics are race-prone because destination existence, overwrite permission, other opens, parent delete opens, and final rename are separated by async lease waits. Impersonation must be restored after every wait or lower VFS calls can run as the wrong user. Cleanup must close temporary destination fsps and release share mode locks on all error paths. Incorrect info-class mapping can expose the wrong lower setinfo behavior. Security descriptor updates rely on `CAN_WRITE(conn)` and supported secinfo flag masking. Quota support is build-dependent. Suppressing STATUS_PENDING for rename lease waits matches Windows behavior and avoids compound rename compatibility regressions.

Test signals: cover buffer offset/length validation, max transaction and credit-charge failures, closed file ids, IPC rejection, directory handle stat, open-file fstat failure, print-file delete-on-close cancellation and non-disposition rejection, filesystem info invalid level mapping, security descriptor access denied and success with masked flags, quota supported and unsupported builds, rename to stream, rename with DFS-like path disabled, destination missing race, destination exists without overwrite, destination open conflicts after lease break, parent delete-pending and sharing violation, source delete-on-close lease wait, async callback impersonation, cleanup on cancellation, and compound rename behavior without interim STATUS_PENDING.

# sources/user-network-fs/samba/source3/smbd/smb2_signing.c

Purpose: initializes server-side signing policy for a connection. For SMB2, signing is always permitted and desired by protocol behavior, so this file only records whether signing is mandatory according to smb.conf and delegates SMB1 signing initialization when the SMB1 server is compiled in.

Important API: `srv_init_signing(struct smbXsrv_connection *conn)` creates a temporary loadparm context with `loadparm_init_s3()`, calls `lpcfg_server_signing_allowed()` to populate `conn->smb2.signing_mandatory`, optionally calls `smb1_srv_init_signing()` under `WITH_SMB1SERVER`, unlinks the loadparm context, and returns whether initialization succeeded.

Control flow: connection setup calls this early in the SMB server lifecycle. If a loadparm context cannot be created, the function logs at debug level and returns false. Otherwise, SMB2 mandatory-signing state is obtained from configuration, SMB1 compatibility initialization is attempted when present, and the temporary context is removed from the connection talloc tree before returning.

State and persistence behavior: the only SMB2 state mutation is `conn->smb2.signing_mandatory`. No persistent database state is written. The loadparm context is temporary and explicitly unlinked. SMB1 initialization may mutate SMB1 signing state on the same connection when compiled.

Dependencies and integration points: depends on Samba loadparm helpers, the SMB signing configuration parser, `smb2_signing.h`, and optional SMB1 signing code. Later SMB2 negotiation and session setup code consume the mandatory signing flag when choosing security mode and signing requirements.

Risks: this small file is a policy bridge, so the main risk is interpreting smb.conf signing settings differently between SMB1 and SMB2. A failure to initialize loadparm rejects signing initialization entirely. Tests should ensure SMB2 mandatory signing follows `server signing` configuration, SMB2 signing remains allowed even when not mandatory, SMB1 builds still call SMB1 setup, non-SMB1 builds compile cleanly, and the temporary loadparm context does not leak under the connection.

# sources/user-network-fs/samba/source3/smbd/smb2_tcon.c

Purpose: implements SMB2 TREE_CONNECT and TREE_DISCONNECT. It parses UNC share paths, resolves and opens Samba services as SMB2 tree connections, enforces signing/encryption and share policy, reports share type/flags/capabilities, and tears down tcons after cancelling or waiting for outstanding work and handle lease breaks.

Important APIs and functions: `smbd_smb2_request_process_tcon()` validates the SMB2 fixed body, reads SMB3.1.1 tree-connect flags, converts the UTF-16 path to Unix charset, rejects embedded NUL length mismatches, starts `smbd_smb2_tree_connect_send()`, and suppresses STATUS_PENDING. `smbd_smb2_tree_connect()` performs the real service lookup and connection. It strips the server prefix from `\\server\share`, handles `[homes]`, finds services, blocks DFS proxy shares for non-DFS clients, computes encryption flags, enforces SMB3.1.1 signed or encrypted tree connect for non-guest sessions, checks max connections, creates an `smbXsrv_tcon`, calls `make_connection_smb2()`, and fills response share type, share flags, capabilities, maximal access, and tree id. `smbd_smb2_request_process_tdis()` and `smbd_smb2_tdis_send()` implement tree disconnect. `smbd_smb2_tdis_send()` marks the tcon deleted, cancels other in-flight requests on the same tcon, waits for those requests, waits for matching handle lease breaks, then disconnects and frees the tcon in `smbd_smb2_tdis_wait_done()`.

Control flow: TREE_CONNECT checks request shape and path buffer placement, converts the share path, and dispatches through a tevent request even though the current implementation completes synchronously. The worker function lowercases the service name, resolves homes or configured services, applies DFS proxy and encryption policy, rejects guests when share encryption is required, rejects required encryption when no cipher was negotiated, and clears optional encryption for guest sessions. It then creates the tcon under the session, creates the compatibility connection through `smb2_service.c`, determines disk/print/IPC share type, sets DFS and client-side caching flags, adds access-based enumeration flags, adds encrypt-data when desired, conditionally advertises SMB3 cluster/scaleout/asymmetric capabilities from loadparm parameters, and returns the tcon wire id. TREE_DISCONNECT validates its request, sets the tcon status to `NT_STATUS_NETWORK_NAME_DELETED` so new requests cannot use it, walks all client connections to cancel and wait for outstanding same-tcon requests, waits for handle lease breaks associated with the tcon's connection, then calls `smbXsrv_tcon_disconnect()` and frees the tcon.

State and persistence behavior: successful TREE_CONNECT creates an `smbXsrv_tcon` associated with the authenticated session and attaches a `connection_struct` as `tcon->compat`. It updates `req->last_tid` for compound request chaining and returns the tcon wire id in the SMB2 header. It records encryption flags in the tcon global so later dispatch can require or desire encryption. TREE_DISCONNECT marks the tcon deleted, cancels outstanding async subrequests on that tree, disconnects the tcon, closes the underlying connection through lower tcon/session code, and frees the tcon object. No direct on-disk persistence is performed here, but service open/close hooks can run configured external commands through `smb2_service.c`.

Dependencies and integration points: depends on loadparm service lookup and share options, auth session info, SMB2 session/tcon tables, tree-connect creation and disconnect helpers, `make_connection_smb2()`, DFS and cluster capability configuration, tevent queues, handle lease-break waiting, and the core dispatcher in `smb2_server.c`. Later request validation uses `smb2srv_tcon_lookup()` and `req->tcon->compat` populated by this file.

Risks: SMB3.1.1 requires signed or encrypted tree connects for non-guest sessions; this file disconnects on violation, so signing state from dispatch must be correct. Share encryption policy has several interacting inputs: session flags, per-share settings, negotiated cipher, guest status, and global config. Service-name normalization and `[homes]` lookup must preserve expected Samba behavior. Max connection checks occur before tcon creation but race with concurrent connects. Capability advertisement can influence client durable/persistent-handle behavior; continuous availability is intentionally not announced by default because persistent handles are not implemented. TDIS must avoid freeing a tcon while requests or lease-break state still reference it.

Test signals: cover valid and malformed path offsets/lengths, UTF-16 conversion failures, embedded NUL rejection, `\\server\share` stripping, homes share present and absent, missing service, DFS proxy refusal, guest and non-guest encryption-required policy, no negotiated cipher with required encryption, SMB3.1.1 unsigned tree connect disconnect, max-connections exceeded, disk/print/IPC share type reporting, DFS root flags, CSC policy flags, access-based enumeration flags, encrypt-data share flag, cluster capability parameter combinations, compound `last_tid`, tree disconnect cancelling outstanding requests, waiting for handle lease breaks, and preventing new requests after tcon status is marked deleted.
