# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxd.h

Purpose: Declares the public board-integration interface for the Micronas DRXD DVB-T demodulator frontend. It lets bridge/card drivers describe board-specific I2C addresses, oscillator/IF parameters, PLL wiring, MPEG transport output behavior, and optional oscillator-deviation persistence before calling `drxd_attach()`.

Important APIs/types/functions: `struct drxd_config` is the only configuration contract. It carries `index`, tuner PLL address/type (`DRXD_PLL_NONE`, `DRXD_PLL_DTT7520X`, `DRXD_PLL_MT3X0823`), oscillator clock, `insert_rs_byte`, demodulator I2C addresses/revision, `disable_i2c_gate_ctrl`, intermediate frequency `IF`, and an `osc_deviation(priv, dev, flag)` callback used by the hard driver to retrieve or save oscillator correction. `drxd_attach()` returns a `struct dvb_frontend *` when `CONFIG_DVB_DRXD` is reachable and otherwise compiles to a stub that logs that the driver is disabled.

Control flow: This header has no runtime flow of its own. A bridge driver fills `struct drxd_config`, passes private board state plus an `i2c_adapter` and `device` to `drxd_attach()`, then the implementation in `drxd_hard.c` allocates the demodulator state, checks register access, initializes the host interface enough for gate control, and returns a DVB frontend.

State and persistence: The header does not store state, but it defines which state the implementation persists in `struct drxd_state`: copied board configuration, private pointer, oscillator deviation callback, transport mode preference, I2C-gate policy, and IF/clock geometry. The `osc_deviation` callback is the only explicit persistence hook; `flag == 0` is used by the driver to read a saved deviation and `flag == 1` to save a measured correction.

Dependencies/integration: Includes Linux `types.h` and `i2c.h`, forward-uses DVB frontend types supplied by media callers, and depends on Kconfig symbol `CONFIG_DVB_DRXD`. It is consumed by card/bridge drivers that need to attach a DRXD demodulator, and by `drxd_hard.c` for the concrete attach implementation.

Risks and test signals: Validate callers set `disable_i2c_gate_ctrl` correctly when the tuner is not behind the demodulator bridge, because the comment warns a wrong setting can wedge the I2C bus. Exercise A2/B1 board variants, missing/disabled Kconfig behavior, oscillator callback read/write semantics, zero `IF` fallback to 36 MHz, and transport output options such as RS-byte insertion. ABI changes to `struct drxd_config` require auditing all board drivers that initialize it positionally or partially.

# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxd_firm.c

Purpose: Provides static DRXD firmware/register programming tables used by `drxd_hard.c` to initialize Micronas DRX3975D-A2 and DRX397xD-B1 DVB-T demodulator blocks. The file encodes host-interface patches, frontend/channel-processor/equalizer/error-correction/system-controller setup, diversity mode setup, and diversity delay profiles in a compact byte-table format consumed by `WriteTable()`.

Important APIs/types/functions: There are no functions; the exported objects are `u8` byte arrays declared in `drxd_firm.h`. Table-construction macros are `ADDRESS(x)`, `LENGTH(x)`, `DATA16(x)`, `WRBLOCK(a,l)`, `WR16(a,d)`, and `END_OF_TABLE`. Major arrays include `DRXD_InitAtomicRead`, `DRXD_HiI2cPatch_1`, `DRXD_HiI2cPatch_3`, `DRXD_ResetCEFR`, A2 tables (`DRXD_InitFEA2_1`, `DRXD_InitFEA2_2`, `DRXD_InitCPA2`, `DRXD_InitCEA2`, `DRXD_InitEQA2`, `DRXD_InitECA2`, `DRXD_ResetECA2`), B1 tables (`DRXD_InitFEB1_1`, `DRXD_InitFEB1_2`, `DRXD_InitCPB1`, `DRXD_InitCEB1`, `DRXD_InitEQB1`, `DRXD_InitECB1`), common `DRXD_ResetECRAM` and `DRXD_InitSC`, and diversity tables (`DRXD_InitDiversityFront`, `DRXD_InitDiversityEnd`, `DRXD_DisableDiversity`, `DRXD_StartDiversityFront`, `DRXD_StartDiversityEnd`, `DRXD_DiversityDelay8MHZ`, `DRXD_DiversityDelay6MHZ`).

Control flow: Runtime flow is driven by the hard driver. `SetDeviceTypeId()` selects A2 or B1 table pointers and optional diversity table pointers. `DRXD_init()` writes host-interface patches, resets processors, downloads external microcode, and then applies the selected FE/FT/CP/CE/EQ/EC/SC tables. `DRX_Start()` may reapply CP/CE/EQ/SC startup tables on every tune and `StartDiversity()` applies the diversity start/delay tables when diversity modes are active. Each table is parsed as repeated little-endian address, 16-bit word length, and little-endian 16-bit data words until `0xffffffff` or zero length.

State and persistence: The file's data is read-only firmware state compiled into the module. Hardware state is produced by writing these values into demodulator register/RAM blocks: host-interface RAM, FE AGC/IF/filter registers, CP/CE/EQ processing blocks, EC output and Reed-Solomon/Viterbi paths, SC RAM defaults, and B1 diversity delay/configuration registers. A comment says the file contains A2 firmware version 1.4.2, B1 firmware version 3.3.33, and settings from driver 1.4.23, while actual microcode loading in `drxd_hard.c` uses `request_firmware()` for `drxd-a2-1.1.fw` or `drxd-b1-1.1.fw`; the declared `DRXD_A2_microcode` and `DRXD_B1_microcode` symbols are not defined in this file.

Dependencies/integration: Includes `drxd_firm.h`, which supplies constants from `drxd_map_firm.h`. The arrays are tightly coupled to `WriteTable()` semantics in `drxd_hard.c`: lengths are instruction/data words, but `WriteTable()` converts them to byte counts and `WriteBlock()` advances addresses by half the byte count. The B-prefixed register constants target B1 layouts, while non-prefixed constants target A2-compatible layouts.

Risks and test signals: Table corruption is difficult to detect at compile time; validate every table ends with `END_OF_TABLE`, lengths match available data, and all addresses are defined for the selected chip revision. Test A2 and B1 initialization separately, B1 host-interface patch selection, PGA and non-PGA B1 variants, diversity front/end modes and 6/7/8 MHz delay tables, and tune-after-sleep reinitialization. The mismatch between declared embedded microcode symbols and the implementation's external firmware loading should be audited when changing firmware packaging. Because this file encodes hardware magic values, regression signals are mostly probe success, firmware download success, frontend lock under known DVB-T channels, MPEG TS output stability, and absence of I2C transfer errors during table writes.

# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxd_firm.h

Purpose: Declares the constants and firmware table symbols shared by `drxd_hard.c` and `drxd_firm.c`. It is the central firmware-contract header for driver version encoding, host-interface timing, DVB-T bandwidth constants, equalizer TPS power presets, AGC defaults, oscillator scan parameters, diversity impulse-response lengths, and all exported initialization table arrays.

Important APIs/types/functions: Version macros `VERSION_MAJOR`, `VERSION_MINOR`, and `VERSION_PATCH` are packed by `DRXD_init()` into `SC_RA_RAM_DRIVER_VERSION__AX`. `DRXD_MAX_RETRIES` bounds HI/SC command polling; `HI_I2C_DELAY` and `HI_I2C_BRIDGE_DELAY` seed host-interface timing. `EQ_TD_TPS_PWR_*` constants tune A2 equalizer TPS power per constellation/hierarchy. `DRXD_DEF_AG_PWD_*`, `DRXD_DEF_AG_AGC_SIO`, and `DRXD_FE_CTRL_MAX` constrain AGC setup. Bandwidth constants encode 8/7/6 MHz values used for IF-increment and system-clock calculations. Extern declarations expose all `DRXD_*` firmware tables and microcode-length symbols.

Control flow: This header has no executable flow. It influences initialization and tuning through constants read by `CDRXD()`, `DRXD_init()`, `HI_Command()`, `SC_WaitForReady()`, `CorrectSysClockDeviation()`, and `DRX_Start()` in `drxd_hard.c`. The extern table declarations let `SetDeviceTypeId()` bind `struct drxd_state` table pointers to chip-specific arrays from `drxd_firm.c`.

State and persistence: The header defines persistent driver identity, default hardware-control register values, and table symbol names. It does not own mutable state. The `DRXD_OSCDEV_*` constants participate in oscillator-deviation tracking by enabling/disabling SC sample-rate scans; the driver may persist measured oscillator deviation through the board callback declared in `drxd.h`.

Dependencies/integration: Includes Linux `types.h` and `drxd_map_firm.h`. It bridges generated/curated register-map constants with the hard driver and static firmware-table file. Any change to an extern declaration must match the actual table object and every pointer assignment in `SetDeviceTypeId()`.

Risks and test signals: Changing retry limits, timing delays, bandwidth constants, or version encoding can alter probe latency, I2C bridge reliability, lock acquisition, and reported firmware/driver compatibility. Validate command timeout behavior, oscillator correction, 6/7/8 MHz tuning, A2 hierarchy/constellation presets, and both consumer/pro AGC defaults. The `DRXD_A2_microcode` and `DRXD_B1_microcode` declarations lack definitions in the read source set and appear stale relative to external firmware loading; avoid adding uses without confirming link coverage.

# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxd_hard.c

Purpose: Implements the Micronas DRXD DVB-T demodulator frontend for DRX3975D-A2 and DRX397xD-B1 chips. It provides low-level I2C register access, firmware loading/downloading, chip-revision-specific initialization, DVB-T tune/start/stop logic, MPEG transport output control, lock/status reporting, signal-strength reporting, I2C gate control, and the exported `drxd_attach()` entry point used by bridge drivers.

Important APIs/types/functions: `struct drxd_state` owns the DVB frontend, copied `drxd_config`, firmware buffer, I2C adapter, mutex, host-interface configuration, chip type flags (`type_A`, `PGA`, `diversity`), demodulator lifecycle (`DRXD_UNINITIALIZED`, `DRXD_STOPPED`, `DRXD_STARTED`), oscillator/system-clock correction state, AGC/noise calibration, MPEG output settings, table pointers, and selected microcode. Core I2C helpers are `Read16()`, `Read32()`, `Write16()`, `Write32()`, `WriteBlock()`, and `WriteTable()`. Firmware/probe helpers include `load_firmware()`, `DownloadMicrocode()`, `SetDeviceTypeId()`, `DRXD_init()`, `CDRXD()`, `InitHI()`, `HI_Command()`, and `HI_CfgCommand()`. Runtime helpers include `DRX_Start()`, `DRX_Stop()`, `DRX_GetLockStatus()`, `DRXD_status()`, `SetCfgIfAgc()`, `SetCfgRfAgc()`, `SetFrequencyShift()`, `CorrectSysClockDeviation()`, `ConfigureMPEGOutput()`, and `DRX_ConfigureI2CBridge()`. DVB frontend operations are `drxd_init`, `drxd_sleep`, `drxd_i2c_gate_ctrl`, `drxd_set_frontend`, `drxd_get_tune_settings`, `drxd_read_status`, `drxd_read_signal_strength`, `drxd_read_ber`, `drxd_read_snr`, `drxd_read_ucblocks`, and `drxd_release`.

Control flow: `drxd_attach()` allocates state with `kzalloc_obj()`, copies configuration, verifies a basic read, disables MPEG output, initializes host-interface defaults through `CDRXD()` and `InitHI()`, then returns a `dvb_frontend`. The first frontend `.init` calls `DRXD_init()` once: it derives board defaults in `CDRXD()`, detects chip type via `CC_REG_JTAGID_L__A`, selects A2/B1 tables, loads external firmware `drxd-a2-1.1.fw` or `drxd-b1-1.1.fw`, resets HI/processors, configures clocks, applies oscillator correction, initializes the host interface and atomic-read patch, downloads microcode, writes FE/FT/CP/CE/EQ/EC/SC tables, applies AGC, writes the packed driver version, stops output, and marks the device stopped/initialized. A tune through `.set_frontend` copies `dtv_property_cache`, calls `DRX_Stop()`, lets tuner ops program RF parameters, closes the I2C gate, waits 200 ms, then calls `DRX_Start()`. `DRX_Start()` resets EC output/deinterleaver state, restarts chip blocks, restores AGC, maps DVB-T transmission mode/guard/hierarchy/modulation/code-rate/bandwidth into SC and EC/EQ registers, computes IF/frequency-shift increments, enables SC lock tracking, starts output control, starts diversity if selected, and marks the demodulator started. Status reads call `DRXD_status()`, which updates lock bits and enables MPEG output once FEC lock appears.

State and persistence: Mutable state lives in `struct drxd_state` and in hardware registers/RAM. `init_done` prevents repeated full firmware download; `drxd_state` gates start/stop; `cscd_state`, `sys_clock_freq`, `expected_sys_clock_freq`, and `osc_clock_deviation` track clock correction. The optional board `osc_deviation` callback reads saved deviation during init and saves new measured deviation after MPEG lock in `CorrectSysClockDeviation()`. `m_EcOcRegOcModeLop` and `m_EcOcRegSncSncLvl` cache output-control settings across `StopOC()`/`StartOC()`. The external firmware blob is copied with `kmemdup()` into `state->microcode`, but `drxd_release()` only frees `state`, so this path appears to leak the copied firmware buffer. BER, SNR, and uncorrected block counters are stubbed to zero.

Dependencies/integration: Depends on Linux module, firmware, delay, mutex, I2C, and DVB frontend APIs; on `drxd.h` for board configuration; and on `drxd_firm.h`/`drxd_map_firm.h` for firmware tables and register constants. It integrates with tuner drivers through `fe->ops.tuner_ops.set_params` and `i2c_gate_ctrl`, with userspace through standard DVB frontend ops/caps, and with firmware packaging through `request_firmware()` names `drxd-a2-1.1.fw` and `drxd-b1-1.1.fw`. Register access uses a custom four-byte address command format where flags can request broadcast, clear-CRC, and single-master modes.

Risks and test signals: High-risk areas are probe/init error unwinds, external firmware lifetime, I2C bridge toggling, the command-polling loops that treat a zero register read as ready, and extensive hardware magic values. `load_firmware()` allocates `state->microcode` without a matching free in `drxd_release()`, and `DRXD_init()` error exits after firmware load do not release it. `drxd_set_frontend()` ignores tuner `set_params()` return values and always starts with frequency offset zero. `DRX_Start()` computes detailed manual transmission parameters but then forces all operation-mode bits to auto under `#if 1`, so manual tuning expectations should be verified. Test signals include successful attach failure on absent hardware, A2 and B1 firmware request/download, I2C transfer error propagation during table writes, I2C gate disable policy, first init idempotence, repeated tune/stop/start cycles, 6/7/8 MHz bandwidth lock, auto and explicit DVB-T parameter combinations, FEC/MPEG lock transition enabling transport output, oscillator-deviation callback updates, suspend/sleep output mute, and leak checks across attach/init/release.

# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxd_map_firm.h

Purpose: Provides the curated DRXD register/RAM address map and bitfield constants required by the hard driver and firmware tables. It replaces a much larger original generated map with only the addresses and masks actually used by this driver, covering host interface, system controller, frontend, frequency/timing, channel/equalizer/error-correction/output-control, clock control, LC, and B1-prefixed variants.

Important APIs/types/functions: This header contains only `#define` constants. Major groups include HI command/config/user RAM registers, SC command/status/config/lock/operation parameter bits, FE AGC/IF/filter/control registers and masks, FT/CP/CE/EQ command and tuning registers, EC SB/VD/OD/RS/OC output and decoder registers, CC oscillator/PLL/JTAG/diversity registers, LC filter/IF increment registers, and B-prefixed aliases/constants for B1 hardware paths. Bit masks encode DVB-T mode/guard/constellation/hierarchy/code-rate, lock flags, AGC modes, MPEG output mode, diversity routing, clock update keys, and output-control states.

Control flow: There is no executable control flow. The constants are used by `drxd_firm.c` to build write tables and by `drxd_hard.c` for direct reads/writes during probe, initialization, tune, stop, output control, lock polling, oscillator correction, AGC, and diversity. Runtime selection between non-prefixed and B-prefixed constants is mostly determined by `state->type_A` and selected table pointers.

State and persistence: The header does not store state, but it defines the hardware state namespace. Persistent effects occur when the hard driver writes these addresses: SC RAM lock/operation state, FE IF increments, oscillator/PLL configuration, output-control mode, EC deinterleaver/RS memory reset points, diversity delays, and driver version RAM. The B1 definitions mirror many A2 names but sometimes with different addresses or initial masks, such as B1 EC OD sync and diversity controls.

Dependencies/integration: Included by `drxd_firm.h`, and therefore indirectly by both firmware tables and the hard driver. It is tightly coupled to Micronas firmware/hardware address conventions and to the table encoding used by `WriteTable()`. Because it intentionally omits unused generated lines, adding new hardware writes usually requires restoring or defining additional register symbols from hardware documentation or source history.

Risks and test signals: A wrong address, mask, or B/non-B selection can silently program the wrong demodulator block. Validate any map changes against hardware documentation or known-good source history, then test both A2 and B1 initialization, output-control stop/start, lock status decoding, AGC mode switching, bandwidth/IF increment writes, and diversity register routing. Compile coverage is useful for missing defines, but functional coverage requires hardware-level probe and tune tests because most constants are just numeric literals.

# sources/distributed-fs/ceph-client/drivers/media/dvb-frontends/drxk.h

Purpose: Declares the public board-integration interface for the Micronas/NXP DRX-K demodulator frontend. It lets bridge/card drivers describe DRX-K I2C address, transport-stream mode, dynamic clocking, bridge policy, antenna GPIO behavior, MPEG output drive strength, I2C chunk size, firmware name, and QAM demodulator command shape before calling `drxk_attach()`.

Important APIs/types/functions: `struct drxk_config` carries `adr`, `single_master`, `no_i2c_bridge`, `parallel_ts`, `dynamic_clk`, `enable_merr_cfg`, antenna GPIO polarity/bitmask fields (`antenna_dvbt`, `antenna_gpio`), `mpeg_out_clk_strength`, `chunk_size`, `microcode_name`, and `qam_demod_parameter_count`. `drxk_attach()` is declared when `CONFIG_DVB_DRXK` is reachable and otherwise becomes a stub that logs a Kconfig-disabled warning and returns `NULL`.

Control flow: This header has no runtime logic beyond the disabled-driver inline stub. In normal builds, callers construct `struct drxk_config`, call `drxk_attach(config, i2c)`, and receive a DVB frontend from the separate DRX-K implementation. The `qam_demod_parameter_count` comments document an attach/runtime detection path in the implementation: zero or negative lets the driver autodetect whether firmware uses the common two-parameter command or the four-parameter `drxk_a3.mc` exception.

State and persistence: The header itself owns no mutable state. The config fields become persistent demodulator state after attach in the implementation: I2C addressing, bridge mode, transport output mode, dynamic/static clock policy, antenna GPIO control, firmware filename, and QAM command compatibility. GPIO comments define semantic state for UIO bits and DVB-T/DVB-C antenna switching polarity.

Dependencies/integration: Includes Linux `types.h` and `i2c.h`, uses DVB frontend types from media callers, and is controlled by Kconfig symbol `CONFIG_DVB_DRXK`. It is independent from the DRXD hard driver in this work item except for residing in the same DVB frontend family/directory and following the same attach-stub pattern.

Risks and test signals: Validate board configs that set `no_i2c_bridge` or `single_master`, because wrong bridge/master policy can break tuner access. Test parallel versus serial TS output, dynamic clock on/off, `enable_merr_cfg`, antenna GPIO polarity, nondefault I2C chunk sizes, missing or custom `microcode_name`, and QAM parameter-count autodetection including the A3 four-parameter firmware case. ABI changes to `struct drxk_config` require auditing bridge drivers and any designated initializers.
