# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar5008_phy.c

Purpose: Implements the shared PHY operations for AR5008, AR9001, and AR9002-class ath9k hardware. It programs channel frequency synthesis, external radio banks, spur mitigation, INI register application, baseband and RF mode setup, chain masks, ANI controls, noise-floor extraction, radar configuration, PLL selection, and per-rate transmit-power cache layout. The file is the pre-AR9003 PHY vtable provider used by `ar9002_hw_attach_ops()`.

Important APIs and functions: `ar5008_hw_attach_phy_ops()` is the public attachment point and fills `struct ath_hw_private_ops` callbacks including `rf_set_freq`, `spur_mitigate_freq`, `set_rf_regs`, `set_channel_regs`, `init_bb`, `process_ini`, `set_rfmode`, `mark_phy_inactive`, `set_delta_slope`, `rfbus_req`, `rfbus_done`, `restore_chainmask`, `do_getnf`, `set_radar_params`, `ani_control`, `ani_cache_ini_regs`, and `compute_pll_control`. `ar5008_hw_set_channel()` converts 2 GHz and 5 GHz channel centers into synthesizer bit fields and handles the 2484 MHz Japan CCK bit. `ar5008_hw_process_ini()` applies mode, common, BB/RF gain, fast-clock, ADDAC, gain, channel, power, and RF-register tables during reset/channel setup. `ar5008_hw_set_rf_regs()` prepares and writes external radio banks for pre-AR9280 devices, including EEPROM OB/DB swizzling in `analogBank6Data`. `ar5008_hw_spur_mitigate()` and `ar5008_hw_cmn_spur_mitigate()` program pilot, channel, Viterbi, and spur masks from EEPROM spur entries. `ar5008_hw_ani_control_new()` implements OFDM weak signal, firstep, and spur immunity tuning. `ar5008_hw_init_rate_txpower()` maps EEPROM-derived rate power entries into `ah->tx_power`.

Control flow: Attach time calls `ar5008_hw_rf_alloc_ext_banks()` for legacy external radios, installs the callback table, selects the AR9160 PLL calculator for AR9100/AR9160-like chips, sets default NF bounds, initializes radar defaults, and copies the CCA NF register list. Reset/channel bring-up flows through `process_ini`: choose `modesIndex` and `freqIndex` from band and HT width, expose the external radio bus, allow EEPROM-specific ADDAC customization, write mode arrays with analog-shift delays where needed, write RX/TX gain arrays for supported silicon, write common arrays, optional BB/RF gain and fast-clock arrays, apply revision workarounds, set channel registers, chain masks, open-loop power-control state, TX power, and finally RF bank programming. Frequency tuning calls `rf_set_freq`, which calculates reversed-bit synthesizer fields, forces the AR5416 2 GHz bias workaround, writes `AR_PHY(0x37)`, and updates `ah->curchan`. ANI and calibration consumers later call the installed callbacks to update thresholds, read NF registers, or restore chain masks after special flows.

State and persistence: The file mutates hardware registers extensively and also updates persistent driver-side state in `struct ath_hw`: `ah->analogBank6Data` caches mutable bank-6 contents for external radios; `ah->curchan` records the active channel; `ah->ani.iniDef` snapshots post-INI ANI defaults; `ah->ani` levels track current noise-immunity state; `ah->tx_power[]` holds the per-rate power table; `ah->nf_2g`, `ah->nf_5g`, `ah->nf_regs`, and `ah->radar_conf` retain device defaults. Register writes persist until reset, channel reconfiguration, power-state transition, or a later calibration/ANI operation overwrites them. No filesystem or disk state is touched.

Dependencies and integration points: Includes `hw.h`, `hw-ops.h`, `../regd.h`, and `ar9002_phy.h`; it relies on register macros, silicon revision predicates, EEPROM callbacks, INI array helpers, and common ath9k helpers such as `ath9k_hw_get_channel_centers()`, `ath9k_hw_synth_delay()`, `ath9k_hw_wait()`, `ath9k_hw_set11nmac2040()`, `ath9k_olc_init()`, and `ath9k_hw_apply_txpower()`. `ar9002_hw.c` calls `ar5008_hw_attach_phy_ops()`. Reset, channel change, ANI, DFS/radar, TX power, and NF calibration paths consume the callbacks through `ath9k_hw_private_ops()`. The RF-bank tables are paired with initval data selected in `ar9002_hw_init_mode_regs()`.

Risks: This file is dominated by hardware ABI constants and timing-sensitive register order. Incorrect `modesIndex` or `freqIndex` selection can program the wrong band/width column. RF-bank swizzling depends on exact bit offsets and is only valid for legacy external radios; using it on single-chip devices or with a bad bank allocation would corrupt RF programming. Spur mitigation uses dense mask construction with fixed array indexes, so off-by-one errors alter pilot/channel/Viterbi masks. `ar5008_hw_force_bias()` intentionally `BUG_ON`s if called on AR9280+ despite being in a common path, making revision guards critical. Chainmask setup has special fallthrough behavior for 5416 1.0 and alternate 0x5 masks. ANI default restoration depends on caching INI values after full reset. Many writes are buffered, so missing flushes or added reads in the wrong place can change hardware sequencing.

Test signals: Build coverage should include ath9k with all referenced revision predicates and no sparse/compiler warnings around fallthrough or array bounds. Runtime signals include successful probe/reset on AR5416/AR9100/AR9160 and AR9280+ families, valid tuning on 2 GHz, 5 GHz, HT20, HT40, half-rate, and quarter-rate channels, correct handling of 2484 MHz, RF bus grant acquisition, no `ar5416SetRfRegs failed` logs, stable RX/TX after chainmask changes, expected noise-floor readings for HT20 and HT40, ANI debug counters changing under noisy conditions, spur EEPROM entries producing register mask writes without RX regressions, DFS radar registers enabled/disabled as configured, and rate TX power matching EEPROM-derived rate arrays.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9001_initvals.h

Purpose: Provides static initialization register tables for AR9001-era ath9k hardware, specifically AR9100 and AR9160/AR5416-derived variants. The tables encode mode-specific baseband/MAC/PHY values, common all-mode values, AR9100 bank-6 transmit-power-control radio values, and ADDAC shift-register sequences. These arrays are consumed by the AR9002 hardware initialization code through `INIT_INI_ARRAY()`.

Important APIs and data: The file exports only static data: `ar5416Modes_9100[][5]`, `ar5416Common_9100[][2]`, `ar5416Bank6TPC_9100[][3]`, `ar5416Addac_9100[][2]`, `ar5416Modes_9160[][5]`, `ar5416Common_9160[][2]`, `ar5416Addac_9160[][2]`, and `ar5416Addac_9160_1_1[][2]`. Mode tables use columns for register address plus `5G_HT20`, `5G_HT40`, `2G_HT40`, and `2G_HT20`. Common and ADDAC tables use address plus all-mode value. Bank6 TPC uses address plus 5 GHz and 2 GHz columns. The arrays cover register ranges across MAC DMA/QCU/DCU, PCU, PHY timing, AGC/CCA, analog, gain, TX power, baseband calibration, and radio shift-register programming.

Control flow: There is no executable code in this header. `ar9002_hw_init_mode_regs()` includes this file and selects these arrays by silicon revision: AR9160 uses `ar5416Modes_9160` and `ar5416Common_9160`, with `ar5416Addac_9160_1_1` for AR9160 1.1 and `ar5416Addac_9160` otherwise; AR9100 uses `ar5416Modes_9100`, `ar5416Common_9100`, and `ar5416Addac_9100`; non-5416 legacy chips can use `ar5416Bank6TPC_9100` as `iniBank6`. Later, `ar5008_hw_process_ini()` iterates the selected arrays during reset/channel setup, choosing the proper mode column from band and HT width and the proper bank-6 column from band.

State and persistence: The tables are immutable compiled-in constants. Their values become hardware-visible state only when copied into `struct ar5416IniArray` descriptors and written to registers. One integration wrinkle is that `ar9002_hw_init_mode_regs()` may allocate a mutable copy of `iniAddac` for AR9160 or pre-5416 2.2 chips, then patch an entry such as the CLKDRV override; this file remains read-only, but its selected data can seed mutable per-device init arrays. There is no filesystem persistence.

Dependencies and integration points: The header assumes `u32` and `STATIC/INIT_INI_ARRAY` consumers from ath9k headers but declares no includes itself. It is included by `ar9002_hw.c` together with `ar5008_initvals.h` and `ar9002_initvals.h`. `ar5008_phy.c` consumes the selected INI arrays through `ah->iniModes`, `ah->iniCommon`, `ah->iniAddac`, and `ah->iniBank6`. EEPROM operations and revision predicates in `ar9002_hw.c` determine which tables are active for a given device.

Risks: These are hardware ABI tables with little internal validation. A wrong register address, column value, row order, or column count can break reset, RF programming, calibration, TX power, or interrupt behavior in ways that are hard to trace. Because mode columns are selected by numeric index, inserting a column or changing order requires matching every `modesIndex` user. ADDAC and bank-6 tables contain repeated writes to the same analog shift-register addresses where order is semantically significant. The AR9160 1.1 ADDAC variant differs only in a few late rows, making accidental substitution plausible. Since the arrays are static and included in a C file, duplicate symbol risk is controlled, but moving them to a shared header without `static` would create linkage problems.

Test signals: Compile coverage should ensure all arrays have the expected row/column shape for `INIT_INI_ARRAY()` and no missing references from `ar9002_hw.c`. Runtime validation needs reset/probe on AR9100 and AR9160 revisions, successful INI writes without timeouts, stable RF bank programming on legacy non-single-chip devices, correct operation in all four mode columns, successful AGC/IQ/ADC calibration after reset, stable association and traffic in 2 GHz and 5 GHz, no baseband hang regressions, and no unexpected changes in EEPROM-driven TX power or CCA behavior.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9002_calib.c

Purpose: Implements AR9002-family calibration operations for ath9k. It covers periodic IQ mismatch, ADC gain, ADC DC offset, noise-floor coordination, PA offset calibration for AR9271/AR9285, open-loop temperature compensation for AR9280/AR9287, AR9285 carrier leakage calibration, and attachment of calibration callbacks into the shared ath9k hardware operation tables.

Important APIs and functions: `ar9002_hw_attach_calib_ops()` installs `init_cal_settings`, `init_cal`, `setup_calibration`, and `ops->calibrate`. `ar9002_hw_init_cal_settings()` selects single-sample or multi-sample per-calibration descriptors based on silicon revision. `ar9002_hw_init_cal()` performs initial offset/carrier leakage calibration, PA calibration, NF loading/start, and construction of the linked calibration list. `ar9002_hw_calibrate()` is the periodic calibration entry point; it advances per-calibration state, manages long calibration flags, reads/loads NF history, starts NF calibration, runs PA calibration, and performs OLC temperature compensation. `ar9002_hw_setup_calibration()` starts a selected IQ/ADC calibration in hardware. Collection and post-processing functions include `ar9002_hw_iqcal_collect()`, `ar9002_hw_iqcalibrate()`, `ar9002_hw_adc_gaincal_collect()`, `ar9002_hw_adc_gaincal_calibrate()`, `ar9002_hw_adc_dccal_collect()`, and `ar9002_hw_adc_dccal_calibrate()`. Device-specific helpers include `ar9271_hw_pa_cal()`, `ar9285_hw_pa_cal()`, `ar9285_hw_cl_cal()`, `ar9285_hw_clc()`, `ar9280_hw_olc_temp_compensation()`, and `ar9287_hw_olc_temp_compensation()`.

Control flow: During attach, calibration callbacks are registered. During hardware initialization, `init_cal_settings` chooses supported calibration data, then `init_cal` performs an immediate offset or carrier-leakage calibration path depending on revision, runs reset-time PA calibration, loads NF history, starts NF calibration, clears and rebuilds the per-calibration list, and invalidates `caldata->CalValid`. Periodic `calibrate` calls first observe any running hardware NF calibration and pending flags in `ah->caldata`, then continue a pending per-calibration when possible. A per-calibration cycle waits for `AR_PHY_TIMING_CTRL4_DO_CAL` to clear, collects measurement registers, repeats until enough samples exist, post-processes coefficients into correction registers, marks the calibration valid, and advances to the next waiting list entry. Long calibrations additionally consume previous NF results, load historical NF to hardware, start a new NF calibration, run PA offset calibration, and apply OLC temperature compensation.

State and persistence: The file maintains runtime calibration state inside `struct ath_hw`: measurement accumulators such as `totalPowerMeasI/Q`, `totalIqCorrMeas`, ADC gain/DC totals, `cal_samples`, `cal_start_time`, linked-list pointers `cal_list`, `cal_list_last`, `cal_list_curr`, supported bitmask `supp_cals`, `caldata->CalValid`, calibration flag bits `NFCAL_PENDING` and `LONGCAL_PENDING`, `pacal_info` skip/offset history, `initPDADC`, `PDADCdelta`, and `originalGain[]` for OLC updates. It writes persistent-until-reset correction fields in PHY timing, ADC DC/gain, TX gain, PA analog, CL calibration, NF, and AGC registers. The skip-count logic intentionally carries PA calibration history across periodic calls until reset.

Dependencies and integration points: Includes `hw.h`, `hw-ops.h`, and `ar9002_phy.h`. It depends on ath9k calibration macros and list helpers (`INIT_CAL`, `INSERT_CAL`, `ath9k_hw_reset_calibration()`), register access helpers, jiffies/time conversion, EEPROM callbacks for temperature slope, DAC high-power, and TX gain type, revision predicates for AR9100/9160/9271/9280/9285/9287, and shared NF helpers `ath9k_hw_getnf()`, `ath9k_hw_loadnf()`, and `ath9k_hw_start_nfcal()`. `ar9002_hw.c` calls the attach function; MAC/channel-reset code invokes the installed private and public callbacks.

Risks: Calibration sequencing is timing-sensitive and hardware-stateful. A stuck `DO_CAL` bit is handled by a 30 second timeout that clears the bit and retries later; shortening or bypassing this can leave calibration permanently wedged. IQ/ADC arithmetic must avoid divide-by-zero and must preserve signed interpretation of measurement registers. `numChains` is derived from `rxchainmask`, so mismatched chain masks can write wrong per-chain correction registers. PA calibration saves/restores many analog registers; any missed restore can degrade RF behavior. Skip-count state can suppress needed PA recalibration if offset comparisons are wrong. OLC temperature compensation modifies TX gain tables from `originalGain[]`; bad initial snapshots or deltas can clamp power incorrectly. The AR9285 carrier leakage retry path temporarily changes RF2G5 and must restore it even after failure.

Test signals: Build and static-analysis signals include no uninitialized calibration data, no division-by-zero paths, and valid callback registration. Runtime signals include successful initial calibration during reset, no repeated "offset calibration failed" or "calibration timeout" logs, `CalValid` bits becoming set for supported IQ/ADC calibrations, stable NF history updates on long calibration, correct behavior when long calibration is deferred and replayed, PA calibration skip counts evolving as expected on AR9271/AR9285, OLC compensation only after nonzero PDADC readings, AR9285 CLC retry only when I0/Q0 thresholds require it, and stable throughput/EVM/RSSI across HT20/HT40 and temperature changes.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9002_hw.c

Purpose: Provides general hardware-family setup for AR5008/AR9001/AR9002 ath9k devices. It selects revision-specific INI tables, configures RX/TX gain tables from EEPROM, handles PCIe power-save and workaround registers, claims and validates external radio revisions, enables async FIFO on supported AR9287 revisions, configures hardware hang-check flags, attaches the PHY/calibration/MAC operation sets, and loads AR9271 ANI register overlays.

Important APIs and functions: `ar9002_hw_attach_ops()` is the public family attachment point called from `hw.c`; it initializes mode INI arrays, assigns private and public ops, attaches AR5008 PHY ops, AR9002 PHY ops for AR9280 2.0+, calibration ops, and MAC ops. `ar9002_hw_init_mode_regs()` chooses `iniModes`, `iniCommon`, `iniAddac`, `iniPcieSerdes`, `iniBB_RfGain`, `iniBank6`, fast-clock, and AR9287 CCK FIR arrays by silicon revision and allocates a mutable ADDAC copy for revisions requiring patching. `ar9002_hw_init_mode_gain_regs()` selects RX/TX gain arrays using EEPROM `EEP_RXGAIN_TYPE` and `EEP_TXGAIN_TYPE`. `ar9002_hw_configpcipowersave()` writes SerDes and workaround registers for restore and D3/power-off transitions. `ar9002_hw_rf_claim()` validates radio major revisions after `ar9002_hw_get_radiorev()`. `ar9002_hw_enable_async_fifo()`, `ar9002_hw_init_hang_checks()`, and `ar9002_hw_load_ani_reg()` provide targeted revision-specific setup.

Control flow: Attach starts with `ar9002_hw_init_mode_regs()`; failure only occurs on ADDAC copy allocation. It then stores `init_mode_gain_regs` and `init_hang_checks` into private ops and `config_pci_powersave` into public ops. The AR5008 PHY callbacks are always attached; newer AR9280 2.0+ devices additionally get AR9002 PHY overrides from another file; calibration and MAC callbacks are attached last. Later reset/init paths call `init_mode_gain_regs()` after EEPROM is available to choose gain tables, then PHY `process_ini` applies the arrays. PCI suspend/resume paths call `config_pci_powersave()` with `power_off` selecting D3-entry versus restore behavior. AR9271-specific ANI reloads call `ar9002_hw_load_ani_reg()` to write a selected mode column while preserving unrelated bits in `AR_PHY_CCK_DETECT`.

State and persistence: This file primarily fills pointers and configuration fields in `struct ath_hw`: INI array descriptors, mutable `iniAddac` storage allocated with `devm_kzalloc()`, private/public operation callbacks, hang-check bit flags in `ah->config.hw_hang_checks`, and `ah->hw_version.analog5GhzRev` after RF claim. PCIe and WA register writes persist until power-state changes or reset. Selected INI arrays remain associated with the device for its lifetime. The mutable ADDAC copy is device-managed memory and persists until device teardown.

Dependencies and integration points: Includes Linux `moduleparam.h`, `hw.h`, `ar5008_initvals.h`, `ar9001_initvals.h`, `ar9002_initvals.h`, and `ar9002_phy.h`. It depends on EEPROM ops for revision and gain-type reads, silicon revision predicates, `INIT_INI_ARRAY()`, register buffering macros, PCIe workaround constants, and attach functions `ar5008_hw_attach_phy_ops()`, `ar9002_hw_attach_phy_ops()`, `ar9002_hw_attach_calib_ops()`, and `ar9002_hw_attach_mac_ops()`. `hw.c` selects this attach function for the family; reset, PCI power management, ANI, RF claim, and hang detection paths consume the installed callbacks and state.

Risks: Revision selection is the main correctness risk. A wrong branch selects incompatible initvals or gain tables, which can break reset, RF performance, or calibration. The ADDAC mutable-copy logic assumes row/column sizes match the selected table and patches a hard-coded row/column for older 5416 revisions. PCIe power-save programming differs between pre-AR9280 SerDes sequences and AR9280+ initval-driven sequences; wrong WA bits can cause D3/D0 resume hangs or L1 ASPM instability. `ar9002_hw_get_radiorev()` uses a specific shift-register read sequence, so ordering and delay assumptions matter. Optional callback layering means AR9280+ receives overrides after AR5008 callbacks; changing attach order can silently change behavior.

Test signals: Build should confirm all referenced initval arrays and attach functions resolve for configured ath9k variants. Runtime probe should verify `ar9002_hw_attach_ops()` succeeds across AR9271, AR9280, AR9285, AR9287, AR9160, AR9100, and AR5416-like paths where available. Reset logs should show correct gain/INI programming without allocation failures. PCIe suspend/resume/D3 tests should show no hangs and correct WA bit restoration. RF claim should accept known radio revisions and reject unsupported ones with `-EOPNOTSUPP`. AR9287 1.3+ async FIFO should be enabled only on matching revisions. Hang-check flags should match known problematic chips. AR9271 ANI reload should preserve non-weak-signal bits in `AR_PHY_CCK_DETECT`.
