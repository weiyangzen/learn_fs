# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/commsup.c

Purpose: implements the common AAC host/adapter communication layer used by the miniports. It owns FIB DMA allocation and setup, FIB allocation/free/init helpers, legacy producer/consumer queue helpers, generic FIB and native HBA send paths, adapter-originated FIB completion, firmware printf handling, asynchronous event notification processing, adapter reset/reinitialization orchestration, SAFW host scan synchronization, the per-adapter command/AIF kernel thread, host-time wellness commands, and IRQ allocation/free helpers for both legacy and SRC-style devices.

Important APIs/types/functions: `aac_fib_setup()`, `aac_fib_map_free()`, `aac_fib_alloc_tag()`, `aac_fib_alloc()`, `aac_fib_free()`, `aac_fib_init()`, `aac_queue_get()`, `aac_consumer_get()`, `aac_consumer_free()`, `aac_fib_send()`, `aac_hba_send()`, `aac_fib_adapter_complete()`, `aac_fib_complete()`, `aac_handle_aif()`, `aac_reset_adapter()`, `aac_scan_host()`, `aac_src_reinit_aif_worker()`, `aac_command_thread()`, `aac_acquire_irq()`, and `aac_free_irq()`. The file depends heavily on `struct aac_dev`, `struct fib`, `struct hw_fib`, `struct aac_queue`, `struct aac_entry`, AIF command structures, native HBA request/response structures, and the `dev->a_ops` adapter operation table supplied by `rx.c`, `sa.c`, or `src.c`.

Control flow: initialization calls `aac_fib_setup()`, which allocates coherent FIB memory, aligns it for PMC/SRC requirements, lays out transport headers and per-FIB DMA addresses, initializes completions and locks, assigns MSI-X vectors, and reserves the last `AAC_NUM_MGT_FIB` entries for management. SCSI or management code initializes a FIB, calls `aac_fib_send()` or `aac_hba_send()`, and the common layer sets handles, transfer state, callbacks, management-FIB accounting, and either queues the FIB through the miniport `adapter_deliver()` operation or serializes it through `sync_fib` when `sync_mode` is active. Completion arrives through `dpcsup.c` or SRC/RX interrupt code, then `aac_fib_complete()` clears reusable state and `aac_fib_free()` returns management FIBs to the free list.

State and persistence: persistent state is mostly shared host/controller memory: the coherent FIB pool, per-FIB transfer headers, queue producer/consumer indexes, command queue pending counters, host response wait completions, the `free_fib` list, and management counters. Runtime state also includes AIF sequencing flags in `dev->fsa_dev[]`, SAFW scan counters and HBA maps, command-thread timers, `adapter_shutdown`, `in_reset`, `sync_fib`, and MSI-X vector assignment. Hardware-visible state persists only until reset or driver teardown; the driver recreates it during `_aac_reset_adapter()`.

Dependencies and integration: integrates the SCSI midlayer through `scsi_add_device()`, `scsi_remove_device()`, `scsi_rescan_device()`, host blocking/unblocking, and `scsi_host_complete_all_commands()`. It integrates PCI DMA through coherent allocation/free, interrupt registration through `request_irq()`/`free_irq()`, timekeeping through `ktime_get_real_ts64()` and BCD wellness updates, and adapter firmware through FIB commands such as `AifRequest`, `SendHostTime`, `ScsiPortCommand64`, `ContainerCommand`, and reset/shutdown commands. It assumes miniports provide correct `adapter_notify`, `adapter_deliver`, `adapter_sync_cmd`, `adapter_restart`, and interrupt mask operations.

Risks and test signals: the reset path frees and rebuilds DMA, queue, FSA, and IRQ resources while completing outstanding waiters, so races around `in_reset`, `fib_lock`, command callbacks, and stopped `aac_command_thread` are high risk. `aac_queue_get()` spins until entries are available, so broken queue indexes or firmware stalls can livelock. Management FIB accounting must be balanced on every wait, timeout, reset, and interrupt path. AIF handling maps firmware events to SCSI add/remove/rescan and has timeout-based sequencing that can suppress or duplicate scans. Native HBA FIBs bypass normal `XferState` semantics and require different completion handling. Test signals include FIB pool shrink on allocation pressure, fast responses, timed-out and interrupted management commands, async callbacks that free FIBs, AIF add/delete/change/JBOD/enclosure events, SAFW scan retry, reset during outstanding sync and async I/O, kdump mode bus scan suppression, MSI-X vector allocation/free, and host-time/wellness command failure paths.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/dpcsup.c

Purpose: provides the deferred/interrupt-side processing glue for normal AAC command responses and adapter-initiated commands/AIFs. It translates queue entries or message-ring handles into `struct fib` completions, wakes synchronous waiters, invokes asynchronous callbacks, feeds AIFs into the command thread, and supports the newer SRC AIF request loop.

Important APIs/types/functions: `aac_response_normal()` drains legacy host response queues, `aac_command_normal()` drains adapter-to-host command queues, `aac_intr_normal()` is the common completion/AIF entry point used by message-mode interrupts, and `aac_aif_callback()` reissues asynchronous AIF requests for SRC firmware. It operates on `struct aac_queue`, `struct aac_entry`, `struct fib`, `struct hw_fib`, `struct aac_aifcmd`, FIB context flags, and global FIB counters in `aac_config`.

Control flow: producer/consumer-mode interrupts call `aac_response_normal()` for responses and `aac_command_normal()` for adapter commands. Response handling decodes the FIB handle from the queue entry, decrements outstanding command count, patches fast responses, normalizes some `NuFileSystem` status words, then either invokes the callback for async/no-response commands or completes `event_wait` for synchronous commands and decrements `management_fib_count`. Command handling wraps an adapter FIB in a temporary or heap `struct fib`; if the AIF thread exists, it queues the FIB to `HostNormCmdQueue.cmdq` and wakes `cmdready`, otherwise it immediately acknowledges the adapter. Message-mode interrupt handlers call `aac_intr_normal()` directly with a FIB index, AIF marker, fast-response flag, or copied AIF FIB.

State and persistence: the file mutates queue consumer indexes, `numpending`, per-FIB flags and `done` state, management FIB counters, AIF command queues, and FIB counter statistics. It does not own long-lived hardware resources; it consumes state allocated by `commsup.c` and hardware queues initialized by adapter-specific init.

Dependencies and integration: depends on `aac_consumer_get()`, `aac_consumer_free()`, `aac_fib_complete()`, `aac_fib_free()`, `aac_fib_send()`, `aac_fib_init()`, and `aac_intr_normal()` consumers in RX/SRC/SA interrupt paths. It integrates with the command thread by appending heap FIB wrappers to `q->cmdq` and waking `q->cmdready`.

Risks and test signals: callbacks may free the FIB, so code must not touch callback-owned FIBs after invocation. Timed-out FIBs must be completed and freed without double completion. `management_fib_count` is decremented in several branches and must remain balanced with send-side increments. AIF heap allocation failure falls back differently between old and new paths. Fast response bits synthesize success without a full FIB payload. Test legacy queue response drain, message-mode completion, fast response, no-response and async callbacks, synchronous waiter wake, interrupted waiter `done == 2`, AIF queueing with and without an AIF thread, SRC `AifReqEvent` reissue, and SA firmware AIF special handling.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/linit.c

Purpose: is the Linux SCSI/PCI entry module for the aacraid driver. It declares PCI IDs and adapter identity/quirk tables, registers the PCI driver and legacy `/dev/aac` char device, defines the SCSI host template, implements queueing and device configuration policy, exposes sysfs attributes, handles SCSI error recovery, probe/remove/shutdown, power management, and PCI error recovery.

Important APIs/types/functions: `aac_pci_tbl[]`, `aac_drivers[]`, `aac_queuecommand()`, `aac_get_driver_ident()`, `aac_biosparm()`, `aac_sdev_configure()`, `aac_change_queue_depth()`, `aac_ioctl()`, `aac_eh_abort()`, `aac_eh_dev_reset()`, `aac_eh_target_reset()`, `aac_eh_bus_reset()`, `aac_eh_host_reset()`, `aac_probe_one()`, `aac_acquire_resources()`, `aac_suspend()`, `aac_resume()`, `aac_remove_one()`, PCI AER callbacks, and module `aac_init()`/`aac_exit()`. It wires `struct scsi_host_template aac_driver_template` to the SCSI midlayer and selects miniport init functions such as `aac_rx_init`, `aac_rkt_init`, `aac_nark_init`, `aac_sa_init`, `aac_src_init`, and `aac_srcv_init`.

Control flow: module init registers the PCI driver, then registers the char device. Probe disables low-power PCIe link states, enables the PCI device, sets DMA masks according to quirks, allocates a `Scsi_Host` plus `struct aac_dev`, allocates FIB metadata, initializes locks/work, maps and initializes the adapter through the selected miniport, starts `aac_command_thread`, queries adapter information and containers, sets SCSI host limits, adds the host, scans devices, and saves PCI state. Runtime queueing marks command ownership and delegates CDB building/transport to `aac_scsi_cmd()`. Remove/shutdown block or remove SCSI devices, stop the AIF thread, send shutdown, disable interrupts, free IRQ/DMA/queue/FSA resources, unmap registers, delete the device list entry, and unregister the char device after the last adapter.

State and persistence: module-global state includes `aac_devices`, `aac_mutex`, `aac_cfg_major`, and the adapter identity tables. Per-host state includes `aac_dev` fields initialized during probe: PCI handle, card type, FIB array, queue and FSA state from miniport init, adapter info, quirk-derived limits, work items, command thread pointer, and flags for reset/shutdown/PCI error. Sysfs exposes adapter metadata derived from firmware and table entries. No durable disk metadata is written here; persistence is hardware and firmware-owned.

Dependencies and integration: depends on PCI core, SCSI host/device midlayer, block queue timeout/depth APIs, Linux PM and PCI AER, character device ioctls, capability checks, and numerous common aacraid helpers from `commsup.c`, `dpcsup.c`, and SCSI command-building files not in this work item. Adapter tables couple specific PCI IDs to miniport init functions and quirks such as 31-bit coherent DMA, 17/34 SG limits, SRC, master/slave, and SCSI-32 behavior.

Risks and test signals: the PCI ID driver-data index must stay aligned with `aac_drivers[]`; a mismatch selects the wrong miniport and quirks. Probe error unwinding spans char-device registration, SCSI host allocation, DMA memory, IRQs, kthreads, and register mappings. SCSI EH has separate native-HBA TMF paths and legacy FIB timeout marking, with several 15-second polling windows. Queue-depth policy depends on container counts, physical/JBOD exposure, SAFW `hba_map`, and target type. PCI AER recovery tears down interrupts and MMIO, then remaps and reacquires resources. Test signals include every miniport family probe, 31-bit and 32-bit DMA mask failures, SG quirk limits, char-device ioctl permission and hot-remove behavior, sysfs reset, suspend/resume, AER frozen/permanent paths, native abort/LUN reset/target reset, legacy abort of inquiry/read-capacity/TUR, host reset capability flags, and scan behavior for exposed physicals, JBOD, containers, and SAFW firmware.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/nark.c

Purpose: provides the minimal hardware interface for NEMER/ARK split-BAR AAC controllers. It adapts the RX miniport to controllers whose register and memory windows are exposed through different PCI BAR layout semantics.

Important APIs/types/functions: `aac_nark_ioremap()` maps and unmaps the split register windows and sets `dev->IndexRegs`; `aac_nark_init()` installs the ioremap and communication-selection operations before delegating to `_aac_rx_init()`. It uses `struct rx_registers`, `struct aac_dev`, PCI resource accessors, `ioremap()`, `iounmap()`, and RX common routines.

Control flow: `aac_nark_init()` sets `dev->a_ops.adapter_ioremap = aac_nark_ioremap` and `adapter_comm = aac_rx_select_comm`, then calls `_aac_rx_init()`. On map requests, the driver builds the RX register address from BAR0 and BAR1 values, maps enough for the RX registers excluding the inbound region, sets `base_start` from BAR2, maps the main base window, and points `IndexRegs` at the mapped base. On unmap requests, it releases both mappings and clears pointers.

State and persistence: it owns no protocol state beyond `dev->regs.rx`, `dev->base`, `dev->base_start`, and `dev->IndexRegs`. All queue, FIB, interrupt, and firmware state is initialized by the shared RX path.

Dependencies and integration: depends on RX miniport behavior from `rx.c`, common PCI BAR resources, and the `dev->a_ops` initialization contract used by `linit.c`.

Risks and test signals: the split address computation combines BAR0 and BAR1 into a 64-bit register address, so incorrect PCI resources or platform quirks can map the wrong region. The unmap path calls `iounmap()` on `dev->base` even though it is explicitly cleared during failed map handling, making pointer state important. Test BAR mapping success/failure, unmap after partial map failure, `IndexRegs` offset correctness, producer and message communication selection through RX, and probe/remove reset flows for NEMER/ARK IDs.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/rkt.c

Purpose: provides the Rocket/Drawbridge variant miniport shim for RX-based AAC controllers. It mainly supplies a simple BAR mapping implementation and caps message-mode command depth to the hardware limit.

Important APIs/types/functions: `AAC_NUM_IO_FIB_RKT` defines the Rocket I/O FIB limit, `aac_rkt_select_comm()` wraps `aac_rx_select_comm()` and adjusts `can_queue` plus `init->r7.max_io_commands`, `aac_rkt_ioremap()` maps/unmaps `struct rkt_registers`, and `aac_rkt_init()` installs operations before calling `_aac_rx_init()`.

Control flow: probe enters `aac_rkt_init()`, which sets `adapter_ioremap` and `adapter_comm`, then uses the common RX initialization sequence. When firmware communication mode is selected, `aac_rkt_select_comm()` delegates to RX and, for `AAC_COMM_MESSAGE`, clamps `scsi_host_ptr->can_queue` to `246 - AAC_NUM_MGT_FIB` if the negotiated or overridden value is too high.

State and persistence: persistent driver state is only the mapped register pointer (`dev->regs.rkt`/`dev->base`), `IndexRegs`, and potentially reduced SCSI queue depth and init-struct command count. FIB and hardware communication state remain in common RX/commsup structures.

Dependencies and integration: depends on `_aac_rx_init()` and `aac_rx_select_comm()` from `rx.c`, the adapter init structure allocated by common init code, and SCSI host queue-depth fields consumed by `linit.c`.

Risks and test signals: the command-depth adjustment happens after FIB setup has already occurred according to the comment, so it limits future OS submissions but cannot resize already allocated resources. A hard-coded FIB override or firmware misreport can still stress assumptions around pool size versus hardware capacity. Test producer and message communication modes, queue clamp when `can_queue` exceeds the Rocket limit, no clamp below the limit, BAR map/unmap, and error unwind after `_aac_rx_init()` failure.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/rx.c

Purpose: implements the RX/i960 AAC hardware miniport used by many older Adaptec, Dell, IBM, ICP, and related controllers. It handles doorbell and message interrupts, interrupt masks, mailbox synchronous commands, adapter notification, health checks including panic POST retrieval, FIB delivery through producer or message interfaces, register mapping, adapter restart, communication-mode selection, and shared RX initialization.

Important APIs/types/functions: `aac_rx_intr_producer()`, `aac_rx_intr_message()`, `aac_rx_disable_interrupt()`, `aac_rx_enable_interrupt_producer()`, `aac_rx_enable_interrupt_message()`, `rx_sync_cmd()`, `aac_rx_notify_adapter()`, `aac_rx_start_adapter()`, `aac_rx_check_health()`, `aac_rx_deliver_producer()`, `aac_rx_deliver_message()`, `aac_rx_ioremap()`, `aac_rx_restart_adapter()`, `aac_rx_select_comm()`, `_aac_rx_init()`, and `aac_rx_init()`. It uses RX register accessors, outbound/inbound doorbell bits, `MUnit` queues, `IndexRegs->Mailbox[]`, common queue/FIB helpers, and PCI MSI setup.

Control flow: initialization maps RX registers, optionally resets the adapter if masks or `init_reset` require it, checks panic/self-test/monitor status, waits for `KERNEL_UP_AND_RUNNING`, fills the adapter operation table, starts in producer mode to clear and enable interrupts, calls `aac_init_adapter()`, switches to negotiated communication mode, requests IRQ/MSI, enables interrupts, and sends the init structure address through `aac_rx_start_adapter()`. Runtime delivery either queues a FIB in the adapter normal command queue and rings the doorbell or waits for an inbound message slot and writes FIB DMA address/size. Interrupts either decode doorbells and call `aac_response_normal()`/`aac_command_normal()` or drain outbound message handles and call `aac_intr_normal()`.

State and persistence: RX state includes mapped registers (`dev->regs.rx`, `dev->base`, `IndexRegs`), cached outbound interrupt mask `OIMR`, selected communication mode via operation pointers, pending queue counters, and optional MSI enable state. Firmware state includes mailbox command/return words, doorbell bits, outbound/inbound message queues, kernel-up/panic/self-test status in OMR registers, and init-struct address.

Dependencies and integration: depends on common communication routines in `commsup.c`, completion/AIF routines in `dpcsup.c`, PCI IRQ/MSI APIs, coherent DMA for panic POST retrieval, and adapter info/init routines outside this file. RKT and NARK miniports reuse `_aac_rx_init()` with custom mapping or communication wrappers.

Risks and test signals: synchronous commands disable interrupts and poll doorbells for up to 30 seconds, so timeout recovery must restore masks. Message delivery busy-polls inbound slots for up to about 50 seconds and decrements `numpending` only on timeout. Health checking allocates DMA buffers while handling kernel panic information. Restart behavior falls back between `IOP_RESET_ALWAYS`, `IOP_RESET`, and an alternate method magic value. Test producer and message interrupts, spurious IRQs, printf doorbell, queue full/not-full notifications, sync command timeout and recovery, message inbound timeout, POST result parsing, reset fallback paths, MSI enable/disable, init-reset and panic-restart loops, and RX reuse by RKT/NARK.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/sa.c

Purpose: implements the SA/ARM-based AAC hardware miniport for older Drawbridge-style controllers. It provides doorbell interrupt handling, mailbox synchronous commands, adapter notification/start/health operations, register mapping, and initialization of the common AAC communication layer for SA hardware.

Important APIs/types/functions: `aac_sa_intr()`, `aac_sa_disable_interrupt()`, `aac_sa_enable_interrupt()`, `aac_sa_notify_adapter()`, `sa_sync_cmd()`, `aac_sa_interrupt_adapter()`, `aac_sa_start_adapter()`, `aac_sa_check_health()`, `aac_sa_ioremap()`, and `aac_sa_init()`. It uses SA register accessors, `SaDbCSR` interrupt masks, `DoorbellReg_p/s`, mailbox registers, `aac_command_normal()`, `aac_response_normal()`, `aac_rx_deliver_producer()`, and common adapter initialization.

Control flow: `aac_sa_init()` maps registers, checks self-test/panic/kernel-up state, waits up to `startup_timeout`, installs the adapter operation table, disables/enables supported interrupts, calls `aac_init_adapter()`, requests a shared IRQ, records debug mapping information, enables interrupts, and sends the init-struct base address with `aac_sa_start_adapter()`. Runtime IRQ handling reads primary doorbells and the inverted mask, handles firmware printf, adapter command-ready and response-ready events, and clears not-full doorbells. Synchronous commands write mailbox command/parameters, clear and ring doorbell 0, poll for completion for up to 30 seconds, then read mailbox return words.

State and persistence: the file owns mapped SA registers and the operation table. Hardware-visible state includes doorbell bits, interrupt mask bits, mailbox command/status words, and the init-structure base address. It does not implement restart support, returning `-EINVAL` from `aac_sa_restart_adapter()`.

Dependencies and integration: depends on common FIB/queue initialization from `aac_init_adapter()`, common RX producer delivery, SCSI/PCI setup in `linit.c`, and doorbell event definitions shared in `aacraid.h`.

Risks and test signals: restart is unsupported, so SCSI host reset cannot recover SA hardware through this miniport. `sa_sync_cmd()` polls with a 30-second timeout and returns no detailed firmware status on timeout. Interrupt handling uses an `else if` chain, so if multiple doorbell bits are set only the first recognized event is processed per interrupt. The `error_irq` path frees an IRQ even though it is reached from `aac_init_adapter()` failure before `request_irq()`, which should be audited in context. Test startup timeout, self-test and kernel-panic detection, doorbell priority when multiple bits are set, printf acknowledgment, command/response queue drains, sync command timeout, IRQ request failure, producer delivery, and shutdown/remove paths.

# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/src.c

Purpose: implements the PMC SRC/SRCv hardware miniport for newer aacraid controllers, including message-interface interrupt handling, MSI/MSI-X and INTx control, host response reply queues, native HBA and FIB delivery, sync command handling, BAR mapping for Tupelo/Denali-style layouts, IOP and hardware soft reset, soft-reset capability probing, communication selection, and SRC/SRCv initialization.

Important APIs/types/functions: `aac_src_intr_message()`, `aac_src_disable_interrupt()`, `aac_src_enable_interrupt_message()`, `src_sync_cmd()`, `aac_src_notify_adapter()`, `aac_src_start_adapter()`, `aac_src_check_health()`, `aac_src_deliver_message()`, `aac_src_ioremap()`, `aac_srcv_ioremap()`, `aac_set_intx_mode()`, `aac_clear_omr()`, `aac_src_restart_adapter()`, `aac_src_select_comm()`, `aac_src_init()`, `aac_src_wait_sync()`, `aac_src_soft_reset()`, `aac_srcv_init()`, `aac_src_access_devreg()`, and `aac_src_get_sync_status()`. It operates on SRC `MUnit` registers, inbound queues `IQ`/`IQN`, host RRQ arrays, MSI-X context records, FIB transport headers, native HBA command/TMF/reset structures, and adapter option bits.

Control flow: SRC initialization maps BARs, optionally resets on `init_reset`, handles panic/self-test/monitor status, waits for firmware up, installs operation pointers, clears interrupts, calls `aac_init_adapter()`, validates communication type, enables MSI or MSI-X as supported, requests IRQs, enables message interrupts, and starts the adapter unless in sync mode. SRCv adds soft reset probing on init reset, flash-update wait handling, larger BAR sizing, and support for message type 2/3. Runtime delivery selects a response vector, annotates native HBA reply queue/request IDs or FIB handles, increments per-vector outstanding counts, computes 128-byte size units, optionally emits an XPORT header, and writes the DMA address to the inbound queue. Interrupt handling distinguishes sync, AIF, and normal completion modes, drains host RRQ slots for the vector, clears AIF/sync bits when needed, and dispatches completions through `aac_intr_normal()`.

State and persistence: SRC state includes BAR0/BAR1 mappings, `IndexRegs`, `OIMR`, `msi_enabled`, `max_msix`, `host_rrq_idx[]`, `rrq_outstanding[]`, `msix_counter`, `vector_cap`, `sync_fib` and sync FIB list state managed with `commsup.c`, `in_soft_reset`, `sa_firmware`, and firmware-reported communication type. Hardware state includes OMR/ODR/IDR/IOAR bits, inbound queue registers, response ring entries, mailbox sync status, MSI-X/INTx enable bits, flash-update status, and reset control bits.

Dependencies and integration: depends on common send/completion logic, `aac_acquire_irq()` from `commsup.c`, PCI MSI/MSI-X vector allocation, SCSI host reset via `aac_reset_adapter()`, adapter initialization and info queries outside this file, and global module parameters such as `aac_sync_mode`, `aac_fib_dump`, `startup_timeout`, and `aac_commit`.

Risks and test signals: interrupt mode decoding is delicate because sync, AIF, and normal response bits share ODR/MSI state and differ between INTx and MSI/MSI-X. `aac_src_get_sync_status()` may switch `msi_enabled` based on sampled MSI status even when legacy mode was expected. Native HBA request IDs are modified with vector bits, so repeated delivery or reused FIBs must not accumulate stale vector state. Reset flow changes interrupt mode, may dump firmware FIBs, drops I/O, clears OMR while preserving MSI-X, and falls back from IOP reset to hardware soft reset only for SA firmware. Soft reset probes adapter properties using special five-second sync waits and leaves `sa_firmware` side effects. Test signals include INTx/MSI/MSI-X interrupt handling, multi-vector RRQ wrap, AIF and sync bit clearing, sync-mode FIB serialization, native HBA TMF/reset delivery, type1/type2/type3 communication validation, BAR map failures, flash update pending/success/failure, invalid OMR, init reset with soft-reset support and fallback, IOP reset and hardware soft reset, vector reassignment after EEH/resume, and `writeq` versus split 32-bit inbound writes.
