# sources/distributed-fs/ceph-client/drivers/net/ethernet/mellanox/mlx5/core/en_rx.c

Purpose: implements the mlx5e receive fast path for Ethernet, representor, IPoIB, AF_XDP, XDP, trap, striding RQ, and SHAMPO hardware GRO receive queues. It turns CQEs, including compressed mini-CQEs, into SKBs or XDP actions; maintains receive WQE/page-pool lifetime; posts cyclic and linked-list MPWQEs through regular RQs and ICO SQ UMRs; handles checksum, VLAN, timestamp, ECN, TLS/IPsec/MACsec/PSP offload annotations; and dispatches packets into NAPI GRO, representor TC receive, IPoIB child devices, or devlink traps.

Important APIs/functions: exported/global entry points are `mlx5e_rx_handlers_nic`, `mlx5e_rx_handlers_rep`, `mlx5i_rx_handlers`, `mlx5e_post_rx_wqes()`, `mlx5e_post_rx_mpwqes()`, `mlx5e_free_icosq_descs()`, `mlx5e_poll_ico_cq()`, `mlx5e_poll_rx_cq()`, `mlx5e_rq_set_handlers()`, `mlx5e_rq_set_trap_handlers()`, and `mlx5e_mpwqe_dealloc_linear_page()`. CQE compression is handled by `mlx5e_read_title_slot`, `mlx5e_decompress_cqe`, `mlx5e_decompress_enhanced_cqe`, `mlx5e_decompress_cqes_start`, and `mlx5e_decompress_cqes_cont`. Receive buffer allocation/release flows through `mlx5e_page_alloc_fragmented`, `mlx5e_page_release_fragmented`, `mlx5e_alloc_rx_wqe`, `mlx5e_refill_rx_wqes`, `mlx5e_alloc_rx_mpwqe`, and `mlx5e_free_rx_mpwqe`. Packet construction is split across `mlx5e_skb_from_cqe_linear`, `mlx5e_skb_from_cqe_nonlinear`, `mlx5e_skb_from_cqe_mpwrq_linear`, `mlx5e_skb_from_cqe_mpwrq_nonlinear`, and `mlx5e_skb_from_cqe_shampo`. Completion/metadata helpers include `mlx5e_build_rx_skb`, `mlx5e_handle_csum`, `mlx5e_complete_rx_cqe`, `mlx5e_shampo_complete_rx_cqe`, `mlx5e_lro_update_hdr`, and `mlx5e_shampo_update_hdr`.

Control flow: regular cyclic RQs are refilled by `mlx5e_post_rx_wqes()`, which determines missing WQEs, prevents newly posted WQEs from sharing a page with still-outstanding old WQEs, frees old fragments, allocates page-pool or AF_XDP frames, pushes WQEs, and updates the doorbell after `dma_wmb()`. Striding linked-list RQs are refilled by `mlx5e_post_rx_mpwqes()`: completed UMRs are posted to the RQ, missing WQEs are allocated through the ICO SQ, old MPWQE pages are freed lazily, UMR doorbells are rung once per bulk, and allocation failures can reclaim already allocated WQEs before reporting busy for AF_XDP fill-ring starvation. `mlx5e_poll_ico_cq()` consumes ICO SQ completions, increments `rq->mpwqe.umr_completed` for RX UMRs, calls TLS completion handlers when compiled, and schedules SQ recovery on bad CQEs.

Control flow continued: `mlx5e_poll_rx_cq()` exits if the RQ is disabled, chooses enhanced or basic compressed-CQE processing based on `MLX5E_RQ_STATE_MINI_CQE_ENHANCED`, dispatches each decompressed or normal CQE through the RQ's selected handler, flushes a pending SHAMPO GRO SKB at poll end, completes XDP RX polling when an XDP program exists, updates the CQ doorbell record, and uses a write barrier before returning. Normal receive handlers compute WQE/stride indices from CQEs, account consumed strides, drop error/filler CQEs, build SKBs through indirect-call-selected constructors, apply offload metadata, optionally update TC chain metadata, then submit to `napi_gro_receive()`. MPWQE handlers pop the linked-list WQE only after all strides have been consumed.

State and persistence: state is runtime-only and lives in `struct mlx5e_rq`, `struct mlx5e_cq`, `struct mlx5e_icosq`, per-channel statistics, page-pool netmem fragments, AF_XDP frame arrays, CQ decompression scratch (`rq->cqd`), MPWQE metadata (`consumed_strides`, `skip_release_bitmap`, `umr_in_progress`, `umr_completed`, `actual_wq_head`), SHAMPO hardware GRO state (`rq->hw_gro_data->skb`, flow keys, second IPv4 ID), and hardware WQ/CQ doorbell counters. Page lifetime is explicit: fragmented page-pool pages use a bias count and per-fragment `frags`; cyclic WQEs mark `MLX5E_WQE_FRAG_SKIP_RELEASE` to avoid double release on close/flush; MPWQEs use `skip_release_bitmap` so pages sent by XDP are not returned prematurely. No disk persistence exists.

Dependencies and integration: depends on Linux NAPI, SKB/GRO, XDP, AF_XDP, page_pool, DMA sync, VLAN, checksum, TCP/UDP/IP/IPv6 helpers, RCU, workqueues, and mlx5 core WQ/CQ/UMR primitives. It integrates with mlx5e profile handler tables, `en/xdp` and `en/xsk/rx` for XDP/AF_XDP, `en_tc` and representor TC receive, `en_accel` modules for kTLS/IPsec/MACsec/PSP receive metadata, PTP timestamp conversion, IPoIB child device lookup, devlink trap reporting, and health recovery work. Handler assignment in `mlx5e_rq_set_handlers()` binds queue type, packet-merge mode, XSK mode, and profile capabilities into the actual function pointers used on the hot path.

Risks: the file is memory-lifetime sensitive. A missed `frag_page->frags++`, stale `skip_release` bit, or wrong XDP consumed-page decision can leak pages or return DMA memory while the stack or XDP still owns it. CQE decompression must not split compression sessions incorrectly; enhanced decompression intentionally returns a full budget when mini-CQEs exceed the remaining budget to preserve NAPI busy semantics. SHAMPO GRO state is fragile because one pending SKB is accumulated across CQEs and flushed on mismatch, size limit, explicit flush, or poll end; header rewrite bugs would surface as bad GSO/checksum/IP ID behavior. Checksum handling has many fallbacks for short padded frames, SCTP, tunnels, PSP, TLS, and full-CQE checksum mode. Hardware-facing UMR, doorbell, and CQ owner updates require ordering barriers; moving them can create overrun or device visibility bugs. Representor/IPoIB/trap paths share constructors but diverge after completion, so changes to common completion must preserve their special metadata and drop semantics.

Test signals: useful validation includes traffic through cyclic and linked-list RQs, MPWQE linear and nonlinear modes, SHAMPO hardware GRO TCP/UDP IPv4/IPv6 with match/mismatch/flush cases, CQE compression basic and enhanced formats, AF_XDP zero-copy allocation starvation and XDP redirect/TX/drop paths, page-pool recycle counters, checksum offload with short padded frames/VLAN/tunnels/SCTP/PSP/TLS, LRO/GRO GSO metadata, RX timestamping, ECN marking from CQE CE bit, representor RX with VLAN pop and TC metadata, IPoIB child QPN mapping/drop behavior, devlink trap delivery, injected RX/ICO error CQEs with recovery work scheduling, and close/flush paths checked for page leaks or double release.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/mellanox/mlx5/core/en_selftest.c

Purpose: implements mlx5e ethtool self-tests. It provides link-state, link-speed, health, and optional IPv4 UDP loopback tests, exposes their names for ethtool string tables, and reports test failure through `ETH_TEST_FL_FAILED`.

Important APIs/functions: public entry points are `mlx5e_self_test()`, `mlx5e_self_test_fill_strings()`, and `mlx5e_self_test_num()`. Individual tests are `mlx5e_test_health_info()`, `mlx5e_test_link_state()`, `mlx5e_test_link_speed()`, and, under `CONFIG_INET`, `mlx5e_test_loopback()`. Loopback support is built from `mlx5e_test_get_udp_skb()`, `mlx5e_test_loopback_validate()`, `mlx5e_test_loopback_setup()`, `mlx5e_test_loopback_cleanup()`, and `mlx5e_cond_loopback()`. The table `mlx5e_sts[]` binds ethtool-visible names to test callbacks and optional condition callbacks.

Control flow: `mlx5e_self_test()` locks `priv->state_lock`, logs test start, iterates `mlx5e_sts[]`, skips any test whose condition callback returns nonzero, invokes the test callback into the next output slot, logs each result, unlocks, then marks `etest->flags` failed if any executed test returned nonzero. Link-state first checks `netif_carrier_ok()` then queries vport state and expects `VPORT_STATE_UP`. Link-speed also requires carrier and delegates to `mlx5e_port_linkspeed()`. Health reads `priv->mdev->priv.health.fatal_error`.

Control flow continued: the loopback test requires the netdev to be opened, allocates `struct mlx5e_lbt_priv`, temporarily enables NIC local loopback if it was disabled, modifies TIRs for loopback receive, installs a packet tap for IPv4 on the same device, builds a small Ethernet/IPv4/UDP discard-protocol packet with a private magic header, transmits it on queue 0, waits up to 200 ms for validation, then removes the packet tap and restores local loopback/TIR state. The validator linearizes the received SKB, checks destination MAC, IP protocol, UDP destination port 9, and the magic value, then completes the wait.

State and persistence: state is temporary and in-memory. `struct mlx5e_lbt_priv` stores the packet handler, completion, loopback result, and previous local-loopback setting. The setup mutates hardware/local vport loopback and TIR loopback configuration for the duration of the test, then cleanup restores local loopback only if this test enabled it. The packet handler exists only between setup and cleanup. There is no persistent storage.

Dependencies and integration: depends on ethtool self-test APIs, netdev carrier state, mlx5 vport state/query helpers, mlx5e port speed query, mlx5 core health state, packet handler registration (`dev_add_pack`/`dev_remove_pack`), SKB construction/checksum helpers, and local loopback/TIR programming helpers. The loopback test is compiled only with `CONFIG_INET` and is conditionally skipped in switchdev mode and when scalable devices are present.

Risks: loopback temporarily changes local-loopback and TIR behavior while holding `state_lock`, so failure paths must reliably restore hardware state. `dev_queue_xmit()` consumes the SKB even when it returns an error, and the code correctly avoids freeing it afterward; future changes must preserve that ownership rule. The packet tap is broad enough to see matching IPv4 packets on the device, so the magic and port checks are important to avoid false positives. The 200 ms timeout can produce false failures on heavily loaded systems. Skipped tests are not represented by placeholder output slots; string count and execution count must stay aligned through identical condition logic.

Test signals: run `ethtool -t` with link up/down, forced speed-query failure, injected core fatal health state, `CONFIG_INET` enabled/disabled, switchdev and scalable-device modes, device closed/opened, local loopback initially enabled and disabled, TIR modification failure injection, SKB allocation failure, and delayed loopback receive beyond the timeout. Verify test names/count match result slots exactly and that local-loopback state is restored after both success and failure.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/mellanox/mlx5/core/en_stats.c

Purpose: implements mlx5e statistics collection and export. It defines the NIC stats group registry used by ethtool and NDO stats updates, aggregates per-channel software counters into `priv->stats.sw`, queries firmware/hardware counter registers for qcounter, vNIC, vport, physical-port, PCIe, priority, FEC, module, TLS, PTP, QoS, and congestion stats, and fills string/value arrays for ethtool consumers.

Important APIs/functions: generic exported entry points are `mlx5e_stats_total_num()`, `mlx5e_stats_update()`, `mlx5e_stats_update_ndo_stats()`, `mlx5e_stats_fill()`, `mlx5e_stats_fill_strings()`, and `mlx5e_ethtool_put_stat()`. Structured ethtool helpers include `mlx5e_stats_pause_get()`, `mlx5e_stats_eth_phy_get()`, `mlx5e_stats_eth_mac_get()`, `mlx5e_stats_eth_ctrl_get()`, `mlx5e_stats_rmon_get()`, `mlx5e_stats_ts_get()`, `mlx5e_stats_fec_get()`, and `mlx5e_get_link_ext_stats()`. Group implementations are generated with `MLX5E_DECLARE_STATS_GRP_OP_*` for `sw`, `qcnt`, `vnic_env`, `vport`, `802_3`, `2863`, `2819`, `phy`, `eth_ext`, `pcie`, `per_prio`, `pme`, `tls`, `channels`, `per_port_buff_congest`, `ptp`, and `qos`. `mlx5e_nic_stats_grps[]` registers the group order.

Control flow: `mlx5e_stats_total_num()` sums `get_num_stats()` over the active profile's stats groups. `mlx5e_stats_update()` walks groups in reverse display order and invokes every update callback; `mlx5e_stats_update_ndo_stats()` does the same but only for groups tagged with `MLX5E_NDO_UPDATE_STATS`. Fill functions walk in display order so strings and values remain aligned. The `sw` update zeroes `priv->stats.sw`, refreshes page-pool stats for active channels, then aggregates all configured channel stats, RQ/SQ/XDP/XSK counters, PTP channel counters, and QoS SQ counters. The `channels`, `ptp`, and `qos` groups expose the raw per-channel/per-queue counters without issuing hardware queries.

Control flow continued: hardware-backed groups build command/register inputs, query device state, and store raw big-endian firmware layouts in `priv->stats`. Q counters call `MLX5_CMD_OP_QUERY_Q_COUNTER` across scalable-device peers and the optional drop RQ counter. vNIC/vport groups call `QUERY_VNIC_ENV` and `QUERY_VPORT_COUNTER`. Physical-port groups query `MLX5_REG_PPCNT` for IEEE 802.3, RFC 2863, RFC 2819/RMON, physical-layer, physical-layer statistical/recovery, Ethernet extended, per-priority, per-traffic-class, and FEC histogram groups. PCIe stats query `MLX5_REG_MPCNT`. FEC helpers determine active FEC mode, collect corrected/uncorrectable blocks, corrected bits, and optional RS histogram ranges via `MLX5_REG_PPHCR`.

State and persistence: persistent runtime state is stored in `priv->stats` (`struct mlx5e_stats`) and in per-channel stats referenced from `priv->channel_stats`, `priv->channels`, `priv->ptp_stats`, and QoS pointers. Hardware query outputs persist only until the next stats update. Capability-gated counters appear or disappear dynamically based on device features, active PFC/global pause settings, PTP open state, `priv->xsk.ever_used`, `priv->stats_nch`, `priv->max_opened_tc`, and `htb_max_qos_sqs`. Synchronization is lightweight: timestamp stats take `priv->state_lock`, QoS stat pointer/count reads use acquire/READ_ONCE patterns, and aggregation uses compiler barriers in loops to avoid a known GCC issue. No disk persistence exists.

Dependencies and integration: depends on `en_stats.h` descriptor macros and stats structures, mlx5 command/register access helpers (`mlx5_cmd_exec_inout`, `mlx5_core_access_reg`), firmware layout macros (`MLX5_GET`, `MLX5_GET64`, `MLX5_SET`, `MLX5_BYTE_OFF`), port helpers for pause/PFC/FEC, PTP channel data, kTLS stats helpers, page_pool stats, scalable-device iteration, module event counters, ethtool string/value helpers, and optional IPsec/MACsec/PCIe congestion groups declared elsewhere. Profiles integrate this through `priv->profile->stats_grps` and `stats_grps_num`; the NIC profile uses `mlx5e_nic_stats_grps`.

Risks: string count and value count must remain identical for every capability-gated branch; any mismatch corrupts ethtool output alignment. Hardware query failures are often ignored, leaving stale previous values in `priv->stats`; callers must not treat every value as freshly sampled. Dynamic PFC/global pause and QoS queue counts can change between `get_num_stats`, `fill_strings`, and `fill_stats` unless higher-level ethtool paths serialize consistently. `q_counter_any()` mutates the `i` loop variable both in the scalable-device macro and inside the loop body, which is subtle and sensitive to macro semantics. Aggregating 64-bit counters updated on data paths is not fully atomic on all architectures unless surrounding code provides protection, so transient torn or inconsistent snapshots are possible. FEC histogram validation relies on firmware-reported bin counts and uses `WARN_ON_ONCE` for oversized counts.

Test signals: validate `ethtool -S` string/value alignment across devices with and without qcounter, vNIC env, local loopback counters, PPCNT, physical statistical/recovery groups, Ethernet extended counters, PCIe performance/stall counters, PFC/global pause, PTP RX/TX, AF_XDP ever-used, HTB QoS SQs, TLS, IPsec, MACsec, and PCIe congestion. Compare software aggregate counters against per-channel raw counters under RX/TX/XDP/XSK/PTP/QoS traffic. Inject register/command failures and confirm stale values do not crash fills. Exercise FEC modes and RS histogram support. Run NDO stats update and full stats update to confirm only `MLX5E_NDO_UPDATE_STATS` groups are sampled in the former.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/mellanox/mlx5/core/en_stats.h

Purpose: defines the mlx5e statistics ABI used internally by the Ethernet driver. It provides counter descriptor/read macros, the stats-group callback interface, public stats function prototypes, concrete software and hardware stats structures, accessors for firmware register layouts, representor stats copying, and extern declarations for stats groups implemented in `en_stats.c` and optional acceleration modules.

Important APIs/types/functions: `struct counter_desc` maps an ethtool string format to a byte offset. `struct mlx5e_stats_grp` defines the group operations `get_num_stats`, `fill_strings`, `fill_stats`, `update_stats`, and an `update_stats_mask`. `mlx5e_stats_grp_t` is the group pointer type. Macros `MLX5E_DECLARE_STAT`, `MLX5E_DECLARE_RX_STAT`, `MLX5E_DECLARE_TX_STAT`, `MLX5E_DECLARE_XDPSQ_STAT`, `MLX5E_DECLARE_RQ_XDPSQ_STAT`, `MLX5E_DECLARE_XSKRQ_STAT`, `MLX5E_DECLARE_XSKSQ_STAT`, `MLX5E_DECLARE_CH_STAT`, `MLX5E_DECLARE_PTP_*`, and `MLX5E_DECLARE_QOS_TX_STAT` build descriptor entries. `MLX5E_DECLARE_STATS_GRP_OP_*` and `MLX5E_DEFINE_STATS_GRP` enforce group naming conventions. Public prototypes cover generic ethtool stats update/fill plus pause, FEC, Ethernet PHY/MAC/control, RMON, timestamp, and link extended stats.

Important structures: `struct mlx5e_sw_stats` is the aggregate software counter block for RX/TX, LRO/GRO/HDS, checksum, XDP, queue events, page_pool, TLS, AF_XDP, and channel events. `struct mlx5e_rq_stats`, `struct mlx5e_sq_stats`, `struct mlx5e_xdpsq_stats`, `struct mlx5e_ch_stats`, and `struct mlx5e_ptp_cq_stats` are per-queue/channel data-path counter layouts consumed by `en_stats.c` and updated elsewhere. Hardware/raw query containers are `struct mlx5e_qcounter_stats`, `struct mlx5e_vnic_env_stats`, `struct mlx5e_vport_stats`, `struct mlx5e_pport_stats`, and `struct mlx5e_pcie_stats`. `struct mlx5e_rep_stats` stores representor/vport counters, and top-level `struct mlx5e_stats` groups all persistent sampled stats under `priv->stats`.

Control flow: this header has no runtime control flow, but it shapes `en_stats.c` heavily. Descriptor macros combine string names and `offsetof()` so fill functions can iterate descriptor arrays and read the matching field from a stats structure. Register access macros wrap `MLX5_GET64`/byte offsets for PPCNT, VPORT, VNIC, and MPCNT layouts. `MLX5E_DEFINE_STATS_GRP` creates a `const struct mlx5e_stats_grp` whose function pointers point to the conventional generated names for a group. `mlx5e_stats_copy_rep_stats()` converts stored representor stats into `rtnl_link_stats64` fields for VF/vport reporting.

State and persistence: the header defines in-memory state layouts only. Counter fields are plain integer accumulators or raw firmware output buffers and persist for the lifetime of the owning `mlx5e_priv`, channel, queue, or representor object. Several fields are conditional on `CONFIG_MLX5_EN_ARFS` and `CONFIG_MLX5_EN_TLS`, so binary layout varies with kernel configuration. Cacheline alignment markers in SQ/XDPSQ stats separate completion-dirtied counters from transmit fast-path counters. No on-disk persistence is represented.

Dependencies and integration: depends on kernel networking types such as `ETH_GSTRING_LEN`, `rtnl_link_stats64`, and ethtool stats structs, mlx5 firmware layout macros and constants, and data-path structures declared elsewhere through `struct mlx5e_priv`. It integrates with `en_stats.c`, ethtool ops, representor/vport reporting, RX/TX/XDP/TLS/PTP data paths that update the counter fields, and optional stats groups from IPsec, MACsec, and PCIe congestion modules.

Risks: descriptor offsets are type-dependent; changing a counter structure without updating matching descriptor arrays in `en_stats.c` can silently expose wrong values. Conditional fields under ARFS/TLS must match conditional descriptors and aggregation code exactly across compile configurations. Plain 64-bit counters are updated by data paths and read by aggregation without a universal locking primitive in this header, so consumers must tolerate approximate snapshots. Raw firmware buffers are declared as `__be64` arrays but accessed via generated offsets for 32-bit and 64-bit fields; incorrect offset macros would yield endian or alignment errors. The group macro convention is rigid and can hide missing functions until compile time.

Test signals: compile with ARFS and TLS both enabled and disabled, and with optional acceleration groups enabled, to verify structure layouts and extern group declarations match implementations. Run ethtool stats on devices with different capabilities to validate descriptor offsets and names. Exercise representor stats copy into `rtnl_link_stats64`. Use build warnings/static analysis to catch wrong `offsetof()` target types, missing group op symbols, and raw register accessor type mismatches.
