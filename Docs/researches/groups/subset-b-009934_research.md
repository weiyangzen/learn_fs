# sources/user-network-fs/samba/source4/libcli/raw/rawsetfileinfo.c

Purpose: implements raw SMB1 set-file-info and set-path-info client operations, including passthrough binary encoders shared with SMB2 setinfo. Important APIs are `smb_raw_setfileinfo_passthru()`, `smb_raw_setfileinfo_send()`, `smb_raw_setfileinfo()`, `smb_raw_setpathinfo_send()`, and `smb_raw_setpathinfo()`. The control flow maps `union smb_setfileinfo` levels to fixed-format blobs, then sends either legacy `SMBsetatr`/`SMBsetattrE`, security descriptor helper, or TRANS2 `SETFILEINFO`/`SETPATHINFO` requests. State is request-scoped: temporary talloc contexts own generated `DATA_BLOB`s until the request send path copies or references them. Dependencies include raw date helpers, EA list packing, NDR security descriptor marshalling, `smb_raw_trans2_send()`, and request setup helpers. Integration points include SMB2 `setinfo.c`, which reuses the passthrough encoder and switches rename layout to `RAW_SFILEINFO_RENAME_INFORMATION_SMB2`. Risks are protocol-layout fragility, unsupported levels returning `false`, a stray `printf("num_eas=%d\n")`, and lifetime mistakes if future code stops copying blobs before freeing the temp context. Test signals should cover every info level, rename/link layouts, EA packing, security descriptor set, setattr fallbacks, path vs handle variants, and server rejection paths.

# sources/user-network-fs/samba/source4/libcli/raw/rawshadow.c

Purpose: queries shadow copy volume data via `FSCTL_GET_SHADOW_COPY_DATA` over raw SMB1 NT IOCTL. The exported API is `_PUBLIC_ NTSTATUS smb_raw_shadow_data(struct smbcli_tree *, TALLOC_CTX *, struct smb_shadow_copy *)`. Control flow builds a `RAW_IOCTL_NTIOCTL` request against the input FID, calls `smb_raw_ioctl()`, validates the returned blob header, then parses volume counts and UCS-2 snapshot names. State is held in the caller's `struct smb_shadow_copy` and talloc-allocated output name array. Dependencies include `libcliraw`, raw ioctl support, SMB constants, `smbcli_blob_pull_ucs2()`, and little-endian blob readers. Integration point is any client-side shadow-copy listing path that has an open file handle and wants snapshot names. Risks are malformed server responses: the code checks minimum 12-byte header and declared length but trusts `num_names` for allocation and iterates until string parsing fails. Test signals include short blob, overlarge declared data length, zero names, multiple UCS-2 names, nonterminated names, and FSCTL error propagation.

# sources/user-network-fs/samba/source4/libcli/raw/rawtrans.c

Purpose: provides raw SMB1 transaction wrappers for `SMBtrans`, `SMBtrans2`, and `SMBnttrans`. Important APIs are `smb_raw_trans_send/recv()`, `smb_raw_trans2_send/recv()`, and `smb_raw_nttrans_send/recv()`, plus synchronous wrappers. Control flow allocates a legacy `smbcli_request`, copies setup words, params, and data into the outgoing buffer, then delegates wire fragmentation/assembly to `smb1cli_trans_send()`. Completion callbacks call `smb1cli_trans_recv()`, map setup/param/data outputs into `req->trans2.out` or `req->nttrans.out`, update transport error state, and invoke user async callbacks. State is request-local but reaches into transport, session, and tcon `smbXcli` handles for signing, IDs, and timeout. Dependencies include tevent, `smbXcli_base`, raw request helpers, and talloc ownership transfer via `talloc_steal()`. Risks include mixed legacy/new-client ownership boundaries, correct setup word width conversion, and treating non-error NT statuses as completed responses. Test signals should exercise async and sync trans/trans2/nttrans, error statuses with and without returned data, pipe-name `SMBtrans`, timeout propagation, and ownership of returned blobs after request destruction.

# sources/user-network-fs/samba/source4/libcli/raw/request.h

Purpose: defines shared raw SMB request buffer contracts used by SMB1 and reused by SMB2 for range checking and string/blob parsing. Important types are `struct request_bufinfo` and `struct smb_request_buffer`; flags are `BUFINFO_FLAG_UNICODE` and `BUFINFO_FLAG_SMB2`. The buffer model stores the NBT-framed allocation, SMB header pointer, word vector pointer/count, data pointer/size, a moving append pointer, and a `request_bufinfo` view for pull/push helpers. State is entirely in-memory and request-owned; no persistence occurs. Dependencies are minimal except `signing.h` and the broader raw SMB helper macros that interpret the offsets. Integration points are raw request creation/parsing, signing code, and SMB2 request buffers which embed the same `request_bufinfo` shape. Risks are pointer invalidation when buffers are reallocated, incorrect alignment base, and consumers failing to respect `data_size` bounds. Test signals are indirect: fuzz malformed SMB buffers, exercise append growth, Unicode string pulls, and signing over resized buffers.

# sources/user-network-fs/samba/source4/libcli/raw/signing.h

Purpose: declares SMB1 signing state. The main type is `struct smb_signing_context`, with engine state `SMB_SIGNING_ENGINE_OFF`, `SMB_SIGNING_ENGINE_BSRSPYL`, and `SMB_SIGNING_ENGINE_ON`. It tracks MAC key material, next sequence number, local policy (`allow_smb_signing`, `mandatory_signing`), runtime behavior (`doing_signing`), and whether any valid peer signature has been seen. State is session/transport scoped and memory-only; `DATA_BLOB mac_key` owns secret key bytes until freed by signing shutdown. Dependencies include Samba `DATA_BLOB` and SMB signing implementation in `smb_signing.c`. Integration points include SMB1 negotiation/session setup and packet send/receive validation. Risks are sequence-number drift, confusing negotiated vs actively doing signing, and allowing unsigned traffic before a valid signature when signing is not mandatory. Test signals include mandatory signing enforcement, optional signing fallback, bad signature after a valid packet, and key cleanup when signing is disabled.

# sources/user-network-fs/samba/source4/libcli/raw/smb_signing.c

Purpose: implements SMB1 signing setup, outgoing MD5 signature generation, incoming signature verification, and signing-state transitions. Important APIs include `set_smb_signing_common()`, `mark_packet_signed()`, `signing_good()`, `sign_outgoing_message()`, `check_signed_incoming_message()`, `smbcli_set_signing_off()`, and `smbcli_simple_set_signing()`. Control flow writes sequence numbers into the signature field, marks the SMB header signed, hashes MAC key plus message bytes with GnuTLS MD5, and stores or compares the first 8 bytes. Incoming verification reconstructs the signature field from the expected sequence number and uses constant-time compare. State lives in `smb_signing_context`: signing policy, `doing_signing`, `seen_valid`, `next_seq_num`, and MAC key. Dependencies include raw request buffer layout, GnuTLS hash APIs, Samba crypto helpers, and `mem_equal_const_time()`. Risks include deprecated MD5 as required by SMB1, sequence mismatch, optional signing downgrade before a valid packet, silent return on GnuTLS hash errors in signing, and dumping key/signature material at debug levels. Test signals cover signed/unsigned negotiation, wrong sequence, empty key, malformed short packets, bad signature after `seen_valid`, and key construction from session key plus challenge response.
<!-- END_FILE_RESEARCH: sources/user-network-fs/samba/source4/libcli/raw/smb_signing.c -->

# sources/user-network-fs/samba/source4/libcli/resolve/dns_ex.c

Purpose: implements async DNS/host resolution by forking a child for blocking `getaddrinfo()`, raw DNS A/AAAA, or DNS SRV lookup. Important APIs are `resolve_name_dns_ex_send()` and `resolve_name_dns_ex_recv()`; helpers include `dns_lookup()`, `get_a_aaaa_records()`, `get_srv_records()`, `run_child_getaddrinfo()`, `run_child_dns_lookup()`, and `pipe_handler()`. State includes flags (`FORCE_NBT`, `FORCE_DNS`, `DNS_SRV`), requested port/name, child pid/fd, tevent FD, and output arrays. Dependencies include resolver libc, `res_search`, Samba DNS unmarshalling, AD DNS SRV lookup, socket utilities, tevent, and `smb_strtoul()`. Risks include fork cost, child cleanup correctness, parsing a private text protocol, truncation/format issues, SRV aggregation order, and rejecting `0.0.0.0`. Test signals include getaddrinfo success, fallback to raw DNS on CNAME/non-RFC names, forced DNS/NBT flags, SRV with A/AAAA records, malformed child output, no bytes for NXDOMAIN, IPv6 builds, and cancellation/destructor behavior.
