# sources/distributed-fs/ceph-client/fs/ntfs3/file.c

Purpose: implements the NTFS3 regular-file VFS surface: stat attributes, ioctl handling, mmap admission, truncate/extend, fallocate, read/write/splice, open/release, fiemap, fsync, and llseek. The file is the bridge between Linux VFS/iomap operations and NTFS-specific inode state such as valid data length, resident/nonresident data, sparse/compressed allocation, delayed allocation, and volume dirty/shutdown flags.

Important APIs/functions: exports `ntfs_ioctl`, `ntfs_compat_ioctl`, `ntfs_getattr`, `ntfs_setattr`, `ntfs_file_open`, `ntfs_fiemap`, `ntfs_file_fsync`, `ntfs_file_inode_operations`, and `ntfs_file_operations`. Key private helpers include `ntfs_should_use_dio`, `ntfs_ioctl_fitrim`, `ntfs_force_shutdown`, `ntfs_extend_initialized_size`, `ntfs_file_mmap_prepare`, `ntfs_extend`, `ntfs_truncate`, `ntfs_fallocate`, `check_read_restriction`, `ntfs_file_read_iter`, `ntfs_compress_write`, `check_write_restriction`, `ntfs_file_write_iter`, `ntfs_file_release`, and `ntfs_llseek`.

Control flow: ioctl dispatch validates the inode and routes FITRIM, label get/set, and forced shutdown commands through capability and user-copy checks. `getattr` augments generic stat data with NTFS creation time, cluster blksize, immutable/append/compressed/encrypted flags. Size-changing paths call `setattr_prepare`, wait for direct I/O, then either truncate through `attr_set_size_ex` or extend via `ntfs_set_size` plus valid-size zeroing. `fallocate` handles punch, collapse, insert, and preallocation by serializing with inode locks, direct-I/O wait, page-cache invalidation, and lower attribute range helpers.

Read control flow first rejects bad, shutdown, encrypted, unsupported external-compressed, and deduplicated inodes. Buffered reads delegate to `generic_file_read_iter`; aligned direct reads use `iomap_dio_rw`, force delayed allocations out of the way, and zero any range beyond `ni->i_valid` but within `i_size`. Splice reads reuse the same restriction helper and then `filemap_splice_read`. Write control flow locks the inode, runs generic write checks, removes privileges/updates timestamps through `file_modified`, extends allocation/size before data copy, then chooses compressed-frame writing, buffered iomap writing, or aligned direct iomap writing with buffered fallback on residual data or invalidation failure. Open rejects direct I/O for compressed/encrypted files and optionally decompresses WOF/LZX/Xpress files before write/truncate opens. Release of the last writer materializes delayed allocations and trims preallocation.

State and persistence: the file updates `ni->i_valid`, `i_size`, `ni->std_fa`, `NI_FLAG_UPDATE_PARENT`, delayed-allocation runs, and superblock dirty/shutdown bits. It marks inodes dirty after metadata-visible changes and uses `ntfs_sync_inode`, `write_inode_now`, `ni_write_parents`, `ntfs_update_mftmirr`, `sync_blockdev`, and block-device flushes to persist fsync/dirsync paths. mmap write-close can advance initialized size when the mapped range extends past the prior valid length. Forced shutdown freezes the block device, sets `NTFS_FLAGS_SHUTDOWN_BIT`, and thaws it.

Dependencies and integration points: depends on Linux VFS, iomap, folio/page-cache, direct I/O, fstrim, fileattr/statx, splice, block-device flush/discard, and capability/user-copy APIs. NTFS integration comes from `ntfs_iomap_ops`, `ntfs_iomap_folio_ops`, `attr_data_get_block`, `attr_set_size[_ex]`, `attr_punch_hole`, `attr_collapse_range`, `attr_insert_range`, `attr_force_nonresident`, `ni_allocate_da_blocks`, `ni_read_frame`, `ni_write_frame`, `ni_decompress_file`, `ni_seek_data_or_hole`, `ntfs_set_state`, `ntfs_set_label`, and ACL/xattr hooks. Operation tables wire the file into inode and file methods used by the VFS.

Risks: valid-data-length handling is security-sensitive because reads beyond initialized data must zero-fill and writes extending a file must zero gaps before exposing data. Direct I/O has alignment and delayed-allocation constraints; incorrect fallback can violate O_DIRECT expectations or leave stale page-cache state. Fallocate range operations combine page-cache invalidation, cluster deallocation/allocation, and i_size/valid-size changes, so ordering bugs can corrupt sparse/compressed files. Compressed writes operate a full compression frame at a time and depend on page-cache state, frame-size assumptions, and `ni_write_frame` correctness. Forced shutdown and fsync paths alter persistent volume state and can affect crash recovery semantics.

Test signals: exercise generic xfstests for truncate/extend, direct I/O alignment and fallback, mmap write faults, `SEEK_DATA`/`SEEK_HOLE`, splice, fsync, fallocate punch/collapse/insert/keep-size, FITRIM, label ioctls, immutable/append mode changes, and last-writer preallocation cleanup. NTFS-specific coverage should include resident-to-nonresident transitions, sparse holes, native compressed files, external compressed open-for-write decompression, delayed allocation materialization before DIO/release, forced shutdown returning `-EIO`, and verification that reads past valid size return zeroes.

# sources/distributed-fs/ceph-client/fs/ntfs3/frecord.c

Purpose: manages NTFS file-record state for an `ntfs_inode`: MFT subrecord caching, attribute lookup/enumeration/insertion/removal, attribute-list creation/expansion/collapse, whole-inode deletion, filename attribute and directory-index synchronization, sparse/compressed attribute flags, reparse interpretation, compressed frame I/O, external-compression decompression, dirty detection, inode writeback, parent duplicate-info propagation, and delayed allocation materialization.

Important APIs/functions: exported helpers include `ni_remove_mi`, `ni_std`, `ni_std5`, `ni_clear`, `ni_load_mi_ex`, `ni_load_mi`, `ni_find_attr`, `ni_enum_attr_ex`, `ni_load_all_mi`, `ni_add_subrecord`, `ni_remove_attr`, `ni_create_attr_list`, `ni_expand_list`, `ni_insert_nonresident`, `ni_insert_resident`, `ni_remove_attr_le`, `ni_delete_all`, `ni_fname_name`, `ni_fname_type`, `ni_new_attr_flags`, `ni_parse_reparse`, `ni_read_folio_cmpr`, `ni_decompress_file` when LZX/Xpress is enabled, `ni_read_frame`, `ni_write_frame`, `ni_remove_name`, `ni_remove_name_undo`, `ni_add_name`, `ni_rename`, `ni_is_dirty`, `ni_seek_data_or_hole`, `ni_write_parents`, `ni_write_inode`, `ni_allocate_da_blocks`, and `ni_allocate_da_blocks_locked`. Important internal routines are `ni_ins_mi`, `ni_find_mi`, `ni_ins_new_attr`, `ni_try_remove_attr_list`, `ni_ins_attr_ext`, `ni_insert_attr`, `ni_expand_mft_list`, `ntfs_lock_new_page`, `decompress_lzx_xpress`, and `ni_update_parent`.

Control flow: MFT subrecords are indexed by record number in `ni->mi_tree`; lookups load records with `mi_get` and cache them until `ni_clear`. Attribute lookup uses the primary record directly unless an attribute list exists; otherwise it finds a matching `ATTR_LIST_ENTRY`, loads the owning record, validates VCN coverage, and returns both attribute and record. Attribute insertion first tries the base record, then creates/uses an attribute list and external MFT records, with special handling for `$MFT::$DATA` so its first segment remains in the base record. Attribute-list maintenance can move attributes out of the primary record, split the `$MFT` data attribute, or collapse all external attributes back into the primary record when enough space exists.

Deletion and rename flows coordinate MFT attributes with directory indexes. `ni_remove_name` deletes the visible name from the parent index, removes the `ATTR_NAME`, and may remove paired DOS/Win32 names; `ni_remove_name_undo` can rebuild those entries on failure. `ni_add_name` validates Windows names, applies hide-dot-files policy, creates a resident `ATTR_NAME`, and inserts the directory entry. `ni_rename` prefers add-new-then-remove-old to reduce unrecoverable failure risk. `ni_delete_all` walks all attributes, removes object-id/reparse side effects, deallocates nonresident runs, frees attribute-list storage, writes freed subrecords, and frees the base MFT record.

Compression control flow: `ni_read_folio_cmpr` locks all folios in a compression frame and calls `ni_read_frame`. `ni_read_frame` handles resident data, native LZNT compressed frames, sparse frames, and optionally WOF LZX/Xpress external compressed data, mapping page arrays with `vmap` and zeroing beyond valid size. `ni_write_frame` compresses a full native LZNT frame, decides whether to store compressed, uncompressed, or sparse data, allocates frame clusters, and writes the resulting bytes. `ni_decompress_file` allocates normal data clusters, reads external compressed frames into page cache, writes decompressed bytes to normal data, removes `WofCompressedData` and reparse attributes, clears sparse/reparse/compressed flags, and switches address-space ops back to normal.

State and persistence: the file mutates `ni->mi`, `ni->mi_tree`, `ni->attr_list`, `ni->file.run`, `ni->file.run_da`, `ni->file.offs_folio`, `ni->std_fa`, `ni->i_valid`, inode mapping ops, MFT record `used`/`hard_links`/`next_attr_id` fields, nonresident size fields, runlists, reparse/object-id indexes, and directory indexes. Dirty state is tracked on base and child `mft_inode` records plus the attribute list. `ni_write_inode` updates standard-info timestamps/attributes, parent duplicate info in all filename entries and directory indexes, attribute-list storage, dirty child records, and the base record; failures mark the volume dirty-error. `ni_write_parents` is used by fsync to flush parent directories.

Dependencies and integration points: depends on NTFS record helpers (`mi_*`, `al_*`, `rec_find_attr_le`), runlist packing/unpacking/allocation, bitmap/window free-space accounting, directory index helpers (`indx_*`), object-id and reparse indexes, WSL permission persistence callers, compression libraries (`compress_lznt`, `decompress_lznt`, optional LZX/Xpress), folio/page-cache APIs, VFS inode writeback, and superblock mount options. It is called from file I/O, inode eviction, create/link/unlink/rename, reparse/symlink handling, compressed address-space operations, fsync, and log replay/update paths.

Risks: attribute-list surgery is high risk because it moves variable-sized records across MFT records while preserving IDs, list entries, VCN ordering, and `$MFT` bootstrap constraints. Error recovery in name removal/rename is partial and depends on undo data remaining valid. `ni_delete_all` permanently deallocates clusters and MFT records, so enumeration or run-unpack mistakes can leak or free wrong space. Compression paths map and manipulate multi-page frames; bad frame-size, valid-size, sparse-frame, or external-compression metadata handling can expose stale data or corrupt file contents. Parent duplicate-info updates can fail to lock directories and intentionally re-dirty the inode, so writeback/retry behavior matters. Delayed allocation conversion must coordinate `run_da`, sparse allocation, and `attr_set_size_ex` under locks.

Test signals: cover attribute lookup with and without `$ATTRIBUTE_LIST`, records spanning multiple MFT subrecords, resident/nonresident conversion, huge attributes that require external records, `$MFT` data splitting, deletion of files with reparse/object-id/nonresident attributes, rename with paired names and injected directory-index failures, parent timestamp/size propagation on fsync, compressed native LZNT read/write frames including sparse and uncompressed frames, optional WOF LZX/Xpress read and write-open decompression, `SEEK_DATA`/`SEEK_HOLE` across sparse/compressed mappings, delayed allocation flush for normal and sparse files, and writeback retry when parent directory locks are unavailable.

# sources/distributed-fs/ceph-client/fs/ntfs3/fslog.c

Purpose: implements NTFS `$LogFile` restart parsing and crash replay. It validates restart pages and log-record pages, reconstructs restart tables, analyzes transaction and dirty-page state, reopens affected attributes, performs redo for dirty pages, performs undo for active transactions, updates the MFT mirror, and writes a clean restart area so the mounted volume can proceed after an unclean shutdown.

Important APIs/types/functions: defines on-disk LFS structures such as `RESTART_HDR`, `CLIENT_REC`, `RESTART_AREA`, `LOG_REC_HDR`, `RESTART_TABLE`, `OPEN_ATTR_ENRTY`, `DIR_PAGE_ENTRY`, `TRANSACTION_ENTRY`, `NTFS_RESTART`, `LFS_RECORD_HDR`, `LFS_RECORD`, and `RECORD_PAGE_HDR`; runtime helpers `struct ntfs_log`, `struct lcb`, `struct OpenAttr`; and operation enum `NTFS_LOG_OPERATION`. The public entry point is `log_replay`; exported validation helper is `check_index_header`. Key internals include restart-table allocation/enumeration helpers, `read_log_page`, `log_read_rst`, `log_create`, `log_create_ra`, `last_log_lsn`, `read_log_rec_buf`, `read_rst_area`, `read_log_rec_lcb`, `read_next_log_rec`, record/index validators, `attr_create_nonres_log`, `update_oa_attr`, and the replay operation dispatcher `do_action`.

Control flow: `log_replay` allocates an `ntfs_log`, normalizes page/file sizing, reads one or two restart pages, chooses the newest valid restart area, or creates a new one for an uninitialized log. It initializes LSN arithmetic, calculates oldest/current/next log positions, scans log pages via `last_log_lsn`, validates supported log versions, ensures the `NTFS` client exists, and reads the client restart area. It then loads restart tables for transactions, dirty pages, attribute names, and open attributes, converting older table layouts where needed.

Replay has three major passes. The analysis pass starts at the checkpoint LSN, walks forward through client records, updates/allocates transaction table entries, records dirty page table LCNs, handles deleted dirty clusters and hotfixes, and tracks open nonresident attributes. It computes the redo LSN from dirty pages and transactions. The redo setup reopens all attributes named in the open-attribute table, builds runlists from actual inodes or fake attributes, merges dirty-page LCNs into those runs, and skips replay entirely on read-only mounts after setting `NTFS_FLAGS_NEED_REPLAY`. The redo pass walks forward from the redo LSN and applies only dirty-page-affecting operations whose page mappings still matter. The undo pass walks active transactions by `undo_next_lsn` and applies undo records until each transaction can be freed.

`do_action` is the central mutation engine. For MFT-record operations it loads the affected MFT record or parent-owned child record, validates LSN and record shape, then initializes/deallocates records, creates/deletes/resizes attributes, updates resident values, mapping pairs, nonresident sizes, root index entries, filename duplicates, and record tails. For allocation/index-buffer operations it reads the target run into memory, validates index buffers and offsets, mutates nonresident data/index pages/bitmaps, reapplies USA fixups, and writes the run back. Redo updates target page LSNs; undo passes `NULL` as the replay LSN. Validation failure marks `log->set_dirty` so the volume is dirtied for repair.

State and persistence: persistent state includes `$LogFile` restart pages, log-record pages, MFT records, index buffers, nonresident attribute data, bitmaps, transaction/dirty/open-attribute restart tables, client restart LSNs, `sbi->flags` (`NTFS_FLAGS_NEED_REPLAY`, log replaying elsewhere), MFT mirror state, and volume dirty/error state. In-memory state includes LSN sequence arithmetic, restart-area image, open attribute table entries with `OpenAttr` runlists and copied attribute headers, restart-table allocations, and log read-ahead. Successful replay clears `NTFS_FLAGS_NEED_REPLAY`, updates the MFT mirror, and writes two restart pages with no active client. Errors preserve `NEED_REPLAY`; read-only replay-needed mounts suppress `-EROFS` at exit but leave replay required.

Dependencies and integration points: depends on NTFS low-level run I/O (`ntfs_read_run_nb_ra`, `ntfs_read_run_nb`, `ntfs_sb_write_run`), USA fixup helpers, MFT load/write helpers (`mi_get`, `mi_write`, `mi_format_new`), inode lookup/loading (`ilookup`, `ntfs_iget5`, `iput`), runlist operations, bitmap bit operations, index validators/mutators, `$MFTMirr` update, dirty-state management, random open-log counts, and Linux allocation/byteorder APIs. It is invoked during mount against the `$LogFile` inode and coordinates with normal inode/file-record code by loading affected inodes and child MFT records.

Risks: this file parses attacker/corruption-controlled on-disk structures, so every size, offset, LSN, runlist, and restart-table calculation is security-sensitive. Multi-page log records, wraparound LSN arithmetic, restart-page selection, tail-copy repair, and version-0 table conversion are complex and easy to regress. `do_action` performs many `memmove` operations in MFT records and index buffers; missing validation can cause memory corruption or on-disk corruption. Fake open attributes allow replay to continue when target inodes are unavailable, but can hide mapping inconsistencies. Read-only mounts that need replay keep the volume unreplayed; callers must respect `NTFS_FLAGS_NEED_REPLAY`. Failure handling intentionally dirties the volume, so tests must distinguish recoverable dirty-volume paths from silent replay success.

Test signals: use crafted and real NTFS images with clean logs, uninitialized logs, CHKD restart signatures, one-page and two-page restart areas, v1.0/v1.1/v2.0 logs, wrapped logs, multi-page records, tail-copy replacement, dirty-page table duplicates, deleted dirty clusters, hotfix records, active and committed transactions, and older restart-table layouts. Operation-level replay tests should cover MFT record initialize/deallocate, attribute create/delete/update/mapping-pair/size changes, root and allocation index entry edits, bitmap set/clear, filename duplicate updates, redo LSN skip behavior, undo of active transactions, read-only replay-needed mounts, invalid offsets/sizes causing dirty-error state, and successful restart-page rewrite plus MFT mirror update.
