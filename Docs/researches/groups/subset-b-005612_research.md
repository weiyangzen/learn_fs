# sources/distributed-fs/ceph-client/fs/btrfs/extent-tree.c

## Purpose

`sources/distributed-fs/ceph-client/fs/btrfs/extent-tree.c` is the core Btrfs extent lifecycle implementation for this kernel tree. It owns extent item lookup and mutation, inline and keyed back-reference encoding, delayed reference execution, extent reservation and allocator fallback policy, reserved data/metadata extent materialization, extent free/pin/unpin commit behavior, snapshot/subtree drop walking, discard, trim, and block-group remapping completion. The source was read as a complete 6,921-line file for this report.

## Important APIs, Types, and Functions

Public entry points declared by the paired header include `btrfs_lookup_data_extent`, `btrfs_lookup_extent_info`, `btrfs_run_delayed_refs`, `btrfs_cleanup_ref_head_accounting`, `btrfs_pin_extent`, `btrfs_pin_extent_for_log_replay`, `btrfs_exclude_logged_extents`, `btrfs_alloc_tree_block`, `btrfs_free_tree_block`, `btrfs_alloc_reserved_file_extent`, `btrfs_alloc_logged_file_extent`, `btrfs_reserve_extent`, `btrfs_inc_ref`, `btrfs_dec_ref`, `btrfs_set_disk_extent_flags`, `btrfs_free_extent`, `btrfs_get_extent_owner_root`, `btrfs_free_reserved_extent`, `btrfs_pin_reserved_extent`, `btrfs_finish_extent_commit`, `btrfs_inc_extent_ref`, `btrfs_drop_snapshot`, `btrfs_drop_subtree`, `btrfs_error_unpin_extent_range`, `btrfs_discard_extent`, `btrfs_trim_fs`, `btrfs_handle_fully_remapped_bgs`, and `btrfs_complete_bg_remapping`.

Important internal helpers fall into several groups. Back-reference helpers include `btrfs_get_extent_inline_ref_type`, `hash_extent_data_ref`, `lookup_extent_data_ref`, `insert_extent_data_ref`, `remove_extent_data_ref`, `extent_data_ref_count`, `lookup_tree_block_ref`, `insert_tree_block_ref`, `extent_ref_type`, `lookup_inline_extent_backref`, `setup_inline_extent_backref`, `lookup_extent_backref`, `update_inline_extent_backref`, `insert_inline_extent_backref`, and `remove_extent_backref`. Delayed-ref execution is centered on `run_delayed_data_ref`, `run_delayed_tree_ref`, `run_one_delayed_ref`, `run_delayed_extent_op`, `cleanup_ref_head`, `btrfs_run_delayed_refs_for_head`, and `__btrfs_run_delayed_refs`. Allocation is centered on `find_free_extent`, `find_free_extent_update_loop`, `prepare_allocation_clustered`, `prepare_allocation_zoned`, `find_free_extent_clustered`, `find_free_extent_unclustered`, `do_allocation_clustered`, and `do_allocation_zoned`. Snapshot deletion uses `struct walk_control`, the `DROP_REFERENCE` and `UPDATE_BACKREF` stages, and helpers such as `visit_node_for_delete`, `walk_down_proc`, `do_walk_down`, `maybe_drop_reference`, `walk_up_proc`, `walk_down_tree`, and `walk_up_tree`.

## Control Flow

Extent allocation starts with `btrfs_reserve_extent`, which builds a `find_free_extent_ctl`, derives the allocation profile from the root, and calls `find_free_extent`. `find_free_extent` chooses clustered allocation for normal filesystems and zoned allocation for zoned filesystems, selects the relevant `space_info`, honors hints for tree-log/data-relocation block groups, scans block-group RAID classes, waits for caching progress when appropriate, optionally allocates a new chunk, relaxes size-class and empty-space constraints over loop phases, and returns an extent key with the selected logical address and byte count. Reserved extents become persistent extent-tree records through delayed references: file extents use `btrfs_alloc_reserved_file_extent` and eventually `alloc_reserved_file_extent`; metadata uses `btrfs_alloc_tree_block`, `btrfs_init_new_buffer`, `btrfs_add_delayed_tree_ref`, and later `alloc_reserved_tree_block`.

Delayed reference processing starts at `btrfs_run_delayed_refs`. It skips aborted transactions and free-space-tree creation, then repeatedly selects delayed-ref heads, merges compatible add/drop entries, runs individual data or tree refs, executes any delayed extent operation that sets flags or tree-block keys, releases reservation accounting, and cleans empty ref heads. Data adds either insert a reserved file extent or increment an existing backref; data drops call `__btrfs_free_extent`. Tree adds either insert a reserved tree block or increment an existing tree backref; tree drops free the extent or, for remap tree refs, return space through the free-space tree/block-group accounting path.

Freeing an extent flows through `btrfs_free_extent` or `btrfs_free_tree_block`, which queue delayed refs except for tree-log blocks that are pinned directly. `__btrfs_free_extent` locates the inline or keyed backref, validates extent item shape, decrements reference counters, removes inline/keyed backref items when counts reach zero, deletes the extent item on last reference, deletes checksums and RAID-stripe-tree records for data, updates simple quota deltas, adds the range back to the free-space tree, and updates block-group usage. Commit-time cleanup runs through `btrfs_finish_extent_commit`, which discards and unpins transaction-pinned ranges, returns free space to block groups or zoned-unusable accounting, schedules async discard when configured, and tears down deleted block groups.

Snapshot deletion uses an explicit tree walk. `btrfs_drop_snapshot` initializes or resumes from `root_item->drop_progress`, marks the root deleting, and alternates `walk_down_tree` and `walk_up_tree`. In `DROP_REFERENCE`, uniquely owned blocks are walked and eventually freed; shared blocks can be skipped by dropping a single ref, or, when `update_ref` requires it, transition into `UPDATE_BACKREF` so children are converted to full backrefs. Progress is persisted into `drop_progress` and `drop_level` between transactions, allowing long deletes to throttle or resume safely. `btrfs_drop_subtree` reuses the same walk logic for relocation subtrees bounded by a supplied parent.

Discard and trim flow is separate from extent-tree item mutation. `btrfs_discard_extent` maps logical ranges to device stripes, serializes against device replace with the bio counter, issues zone resets when possible, otherwise issues block-device discard while skipping superblock mirrors. `btrfs_trim_fs` trims free ranges inside block groups, then unallocated device ranges via `btrfs_trim_free_extents`, throttling long device trims and preserving interruptibility.

## State and Persistence Behavior

Persistent on-disk state handled here includes extent items, metadata items, tree block info, inline extent refs, keyed shared/data/tree backrefs, simple quota owner refs, free-space-tree records, checksum items, RAID-stripe-tree records, root `drop_progress`, and root drop level. In-memory transactional state includes delayed-ref heads and nodes, delayed extent operations, pinned extent trees, dirty page extent bits, block-group reservation/used/pinned counters, free-space-cache and cluster state, `space_info` aggregate counters, zoned allocation offsets, tree-log and data-relocation dedicated block-group hints, deleted/unused/fully-remapped block-group lists, and device allocation trim bits.

The file is careful about persistence boundaries. Reservation only marks block-group/free-space state until delayed refs create extent-tree items. Freed ranges are pinned until transaction commit so old superblocks cannot point to reallocated blocks. Snapshot drop progress is stored in the root item before ending a transaction. Log replay pins or excludes logged extents from allocation until the log is safely replayed. Simple quota accounting records owner roots on extent creation and uses owner refs on data deletion when delayed refs alone cannot identify the original owner.

It also uses Linux scheduler, block-device discard, sorting, RCU, kthread, slab, percpu counters, lockdep, and CRC32C facilities.

Major integration points are the transaction/delayed-ref subsystem, extent and checksum roots selected by logical bytenr, block-group and space-info accounting, free-space cache/tree, qgroup and simple quota accounting, ref-verify/tree-mod-log debugging, chunk allocation and device mapping, RAID56/raid-stripe-tree metadata, zoned block-group activation and write-pointer constraints, dev-replace mirroring during zone reset, tree-log replay, relocation/remap roots, orphan/root-tree cleanup, and cleaner throttling for snapshot deletion.

## Risks and Edge Cases

Corruption handling is a central risk: many paths abort transactions on impossible extent item sizes, zero refs, missing extent/csum roots, invalid inline ref types, mismatched tree owners, and missing backrefs. Inline backrefs are compact and ordered; overflow, hash collisions for data refs, and conversion between inline and keyed refs are high-risk areas. Skinny metadata compatibility requires fallback to old fat extent items. Delayed-ref locking is subtle because extent-tree leaves and delayed-ref heads must be locked in the right order to avoid missing refs while avoiding deadlock.

Allocator risks include stale `space_info->max_extent_size`, fragmented clusters, uncached block groups, read-only/remapped block groups, RAID-profile fallback, forced chunk allocation, and zoned active-zone limits. Zoned allocation has special constraints for dedicated tree-log and data-relocation block groups; mixing regular and relocation writes in one zone can break write-pointer ordering. Free/pin behavior is sensitive because prematurely returning space can allow reuse before the committing superblock boundary. Snapshot deletion must persist progress correctly, especially when resuming after interrupted drops or converting shared blocks to full backrefs. Discard must avoid superblock mirrors and tolerate unsupported devices, missing degraded devices, device replace, interrupts, and throttled no-progress cases.

High-value test signals include xfstests covering Btrfs snapshots, reflinks, qgroups/simple quotas, balance/relocation, log replay, ENOSPC, chunk allocation, trim/discard, device replace, zoned mode, degraded mounts, RAID56, and send/receive workloads that exercise shared extents. # sources/distributed-fs/ceph-client/fs/btrfs/extent-tree.h

## Purpose

`sources/distributed-fs/ceph-client/fs/btrfs/extent-tree.h` is the public interface for Btrfs extent-tree allocation, reference accounting, freeing, pinning, discard/trim, and remapping helpers implemented by `extent-tree.c`. It exposes the allocator control structure used internally by the extent allocator, reference type enums, and the cross-subsystem function prototypes needed by transaction, tree modification, logging, relocation, discard, and cleanup code. The source was read as a complete 169-line file for this report.

## Important APIs, Types, and Functions

`enum btrfs_extent_allocation_policy` selects `BTRFS_EXTENT_ALLOC_CLUSTERED` for normal clustered free-space allocation or `BTRFS_EXTENT_ALLOC_ZONED` for sequential zoned block groups. `struct find_free_extent_ctl` carries allocator inputs (`ram_bytes`, `num_bytes`, `min_alloc_size`, `empty_size`, `flags`, `hint_byte`, `delalloc`, tree-log/data-relocation booleans), block-group search state (`search_start`, RAID `index`, `loop`, caching booleans, retry state, hinted state), clustered allocator state (`empty_cluster`, `last_ptr`, `use_cluster`), result/diagnostic fields (`found_offset`, `max_extent_size`, `total_free_space`), selected policy, and preferred block-group size class. `enum btrfs_inline_ref_type` is used to validate whether an inline backref is block, data, any, or invalid.

Lookup/reference APIs include `btrfs_get_extent_inline_ref_type`, `hash_extent_data_ref`, `btrfs_lookup_data_extent`, `btrfs_lookup_extent_info`, `btrfs_cross_ref_exist`, and `btrfs_get_extent_owner_root`. Delayed-ref and ref mutation APIs include `btrfs_run_delayed_refs`, `btrfs_cleanup_ref_head_accounting`, `btrfs_inc_extent_ref`, `btrfs_inc_ref`, `btrfs_dec_ref`, `btrfs_set_disk_extent_flags`, and `btrfs_free_extent`. Allocation/free APIs include `btrfs_alloc_tree_block`, `btrfs_free_tree_block`, `btrfs_alloc_reserved_file_extent`, `btrfs_alloc_logged_file_extent`, `btrfs_reserve_extent`, `btrfs_free_reserved_extent`, and `btrfs_pin_reserved_extent`. Commit, snapshot, discard, and remap APIs include `btrfs_pin_extent`, `btrfs_pin_extent_for_log_replay`, `btrfs_exclude_logged_extents`, `btrfs_finish_extent_commit`, `btrfs_drop_snapshot`, `btrfs_drop_subtree`, `btrfs_error_unpin_extent_range`, `btrfs_discard_extent`, `btrfs_trim_fs`, `btrfs_handle_fully_remapped_bgs`, and `btrfs_complete_bg_remapping`.

## Control Flow

The header itself has no executable control flow, but it defines the API flow used by the rest of Btrfs. Callers reserve logical space through `btrfs_reserve_extent`, materialize reserved data or metadata through delayed refs and allocation helpers, mutate references with `btrfs_inc_ref`/`btrfs_dec_ref`/`btrfs_free_extent`, flush delayed refs with `btrfs_run_delayed_refs`, and complete commit-time unpin/discard cleanup through `btrfs_finish_extent_commit`. Snapshot and relocation callers enter long-running tree deletion through `btrfs_drop_snapshot` or `btrfs_drop_subtree`. Filesystem trim and explicit discard callers use `btrfs_trim_fs` and `btrfs_discard_extent`.

## State and Persistence Behavior

`struct find_free_extent_ctl` is transient allocator state, not persisted directly. Its fields mirror persistent and transaction state managed elsewhere: block-group profiles, free-space cache status, zoned allocation mode, cluster selection, delayed allocation locking, tree-log/data-relocation block-group selection, and the largest hole found for ENOSPC reporting. The function prototypes govern persistent extent-tree state indirectly: extent items/backrefs are changed inside transactions, delayed refs persist intent until flushed, pinned extents protect old transaction views until commit, and snapshot drop progress/remap completion updates durable root/block-group metadata in the implementation.

## Dependencies and Integration Points

The header includes `<linux/types.h>`, `block-group.h`, and `locking.h`, and forward-declares extent buffers, free clusters, roots, paths, delayed refs, generic refs, disk keys, and inline refs to minimize include coupling. It is included by code that needs extent allocation/reference operations without pulling in the full implementation. Integration points include Btrfs transaction handles, block groups and space-info accounting, free-space clustering, tree locking nests, qgroup/simple quota owner references, tree-log replay, relocation/remap roots, discard/trim, zoned block groups, and device/block-layer discard behavior.

## Risks and Edge Cases

The main header risk is contract drift between declared semantics and the implementation. `find_free_extent_ctl` is broad mutable state shared across many allocator helper phases, so adding fields or changing meanings can break clustered versus zoned allocation behavior. Boolean flags such as `delalloc`, `for_treelog`, `for_data_reloc`, `retry_uncached`, and `hinted` encode lock and search policy; misuse can cause deadlocks, wrong block-group selection, or ENOSPC regressions. The public prototypes expose transaction-sensitive operations where callers must pass valid roots, refs, extent buffers, sizes, and lock nesting. Inline ref type validation is part of on-disk format safety; wrong data-vs-block classification can turn corruption into incorrect accounting.

## Test Signals

Useful validation signals are compile coverage for all Btrfs users of this header, sparse/clang warnings for forward declaration and const mismatches, lockdep coverage for `enum btrfs_lock_nesting` callers, xfstests that allocate/free data and metadata extents, snapshot/drop and relocation tests, qgroup/simple quota tests, log replay tests, zoned allocation tests, ENOSPC/fragmentation tests, and trim/discard tests. ABI-like structure risk for `find_free_extent_ctl` is internal rather than on-disk, so tests should focus on allocator behavior, tracepoint field sanity, and no regressions in largest-hole reporting and fallback loop progression.
