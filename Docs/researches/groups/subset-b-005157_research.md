# sources/distributed-fs/ceph-client/drivers/power/supply/bq2415x_charger.c

Purpose: implements an I2C power-supply driver for the TI bq24150/bq2415x single-cell USB charger family. It registers one USB `power_supply`, exposes basic status/model/online properties, and keeps the chip in host-controlled mode by periodically resetting the charger safety timer. It also provides legacy driver-specific sysfs controls for charger mode, timer control, raw registers, current limits, voltage limits, termination, high-impedance, OTG pin, STAT pin, and fault/status bits.

Important APIs/types/functions: `struct bq2415x_device` holds the power-supply descriptor, delayed timer work, notifier state, platform/firmware init data, mode state, chip identity, unique ID, model/name strings, and timer error. `enum bq2415x_command` is the central command vocabulary used by `bq2415x_exec_command()`. The register helpers are hand-written around `i2c_transfer()`: `bq2415x_i2c_read()`, `bq2415x_i2c_write()`, `bq2415x_i2c_read_mask()`, and `bq2415x_i2c_write_mask()`. Configuration helpers translate between mA/mV and register encodings: `bq2415x_set_current_limit()`, `bq2415x_set_weak_battery_voltage()`, `bq2415x_set_battery_regulation_voltage()`, `bq2415x_set_charge_current()`, and `bq2415x_set_termination_current()`. Lifecycle and integration are handled by `bq2415x_probe()`, `bq2415x_power_supply_init()`, `bq2415x_set_defaults()`, `bq2415x_set_mode()`, `bq2415x_timer_work()`, and `bq2415x_remove()`.

Control flow: probe requires DT, platform data, or ACPI. It allocates a unique ID through `idr_alloc()`, builds a stable power-supply name, reads firmware properties such as `ti,current-limit`, `ti,weak-battery-voltage`, `ti,battery-regulation-voltage`, `ti,charge-current`, `ti,termination-current`, and `ti,resistor-sense`, resets the chip, registers the power supply with extra sysfs attributes, writes default charger values, optionally registers a power-supply notifier for USB charger detection, queries the initial supplier `CURRENT_MAX`, initializes delayed work, then enables the auto timer. Runtime mode changes disable charger/boost first, set the input current limit for off/none/host/dedicated/boost, then re-enable charger or boost and restore default weak-battery/regulation voltage. Supplier notifications update `reported_mode`; if automode is enabled, timer work applies that reported mode. Timer work also tracks charge-status changes and resets the chip timer every `BQ2415X_TIMER_TIMEOUT` seconds, shutting the charger off on timer/fault errors.

State and persistence: hardware configuration is volatile and deliberately reset on probe/remove. Runtime state is held in `mode`, `reported_mode`, `autotimer`, `automode`, `charge_status`, and `timer_error`; it is not persisted outside the chip. The chip itself may fall back to defaults unless the work item keeps resetting its timer. The global IDR and three global mutexes serialize ID allocation, timer state transitions, and raw I2C transfers across instances.

Dependencies and integration: depends on I2C, the power-supply class, sysfs attribute groups, delayed work, firmware properties, OF/ACPI matching, and optional power-supply notifier integration through `ti,usb-charger-detection` or platform `notify_device`. The driver’s public ABI is a mix of standard power-supply properties and custom sysfs files attached to the power-supply device.

Risks and test signals: `bq2415x_i2c_read()` does not verify that the two-message `i2c_transfer()` completed both messages, so short positive transfers could be treated as valid register values. `bq2415x_i2c_write_mask()` ORs `val << shift` without masking the shifted value, relying on callers to pass bounded encodings. The notifier can be registered before `INIT_DELAYED_WORK()`; a very early supplier event could call `mod_delayed_work()` on not-yet-initialized work. The sysfs `registers` writer permits arbitrary raw writes to charger registers, which is useful for debugging but bypasses policy. Useful tests include probe/remove with OF, ACPI, and platform data; missing required firmware property failures; notifier-driven automode; timer fault handling; sysfs read/write boundary values; I2C short-transfer fault injection; and ensuring remove unregisters notifiers, cancels work, resets the chip, drops OF references, and removes the IDR entry.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq24190_charger.c

Purpose: implements a TI bq24190/bq24192/bq24192i/bq24193/bq24196/bq24296/bq24297 I2C charger driver. It exposes a USB charger power supply, an optional deprecated battery power supply, optional sysfs access to detailed register fields, optional VBUS regulator support, extcon USB OTG state, IRQ-based status/fault notifications, runtime PM, and suspend/resume reinitialization.

Important APIs/types/functions: `struct bq24190_dev_info` stores I2C, extcon, charger/battery power supplies, delayed input-current-limit work, cached model/configuration, fault/status registers, runtime flags, and the selected `struct bq24190_chip_info`. `struct bq24190_chip_info` selects chip-family operations for PN checking, charge-config bit layout, OTG VBUS control, NTC fault mask, and charge-current table size. Register helpers are `bq24190_read()`, `bq24190_write()`, `bq24190_read_mask()`, `bq24190_write_mask()`, `bq24190_get_field_val()`, and `bq24190_set_field_val()`. Major behavior lives in `bq24190_get_config()`, `bq24190_register_reset()`, `bq24190_set_config()`, `bq24190_hw_init()`, `bq24190_check_status()`, charger/battery property handlers, and PM callbacks.

Control flow: probe validates SMBus byte-data support, allocates state, selects chip info from I2C/OF match data, requires an IRQ, registers an extcon device, enables runtime PM, registers the charger and optional battery supplies, reads DT/battery configuration, resets the charger unless `disable-reset` is present, disables the watchdog to force host mode, applies system-minimum/precharge/termination/current/voltage configuration, reads initial system status, configures extcon OTG state, requests the IRQ, optionally registers a VBUS regulator, enables IRQ wake, and drops the runtime PM reference. IRQ handling resumes the device, calls `bq24190_check_status()`, then autosuspends. `bq24190_check_status()` reads system status and fault registers, retries once to clear latched faults, masks a disconnect-related voltage fault, compares cached fields to decide whether charger and/or battery changed, clears HIZ after power removal, updates extcon USB state, and emits `power_supply_changed()` notifications.

State and persistence: cached configuration comes from DT and `power_supply_battery_info`; runtime user writes change hardware registers directly but are not persisted in driver config. Suspend and remove call `bq24190_register_reset()`, and resume resets/reapplies only cached config, so runtime property writes can be lost across sleep. The fault register is guarded by `f_reg_lock`; status is cached in `ss_reg`. The watchdog value seen before host-mode disable is cached in `watchdog`, but the driver normally keeps the WDT disabled.

Dependencies and integration: integrates I2C SMBus, power-supply core, firmware properties, `power_supply_get_battery_info()`, supplier current-limit propagation through `external_power_changed`, extcon, runtime PM, wake IRQs, optional sysfs register-field attributes, optional regulator framework support for OTG VBUS, and OF/I2C match tables. The charger supply is marked as supplying `"main-battery"`; the optional battery class can be suppressed with `omit-battery-class`.

Risks and test signals: the driver requires `client->irq > 0`; boards without IRQ cannot use polling fallback. System suspend resets registers, which can surprise users relying on runtime-tuned limits. `bq24190_check_status()` deliberately rereads the fault register because faults may clear-on-read, so tests need to cover latched fault behavior. The bq24296 family uses different OTG/config/NTC bit layouts through chip-info hooks; wrong match data produces bad property reporting. Useful tests include all chip IDs, `disable-reset`, `omit-battery-class`, DT battery-info boundaries, supplier `CURRENT_MAX` delayed work, OTG regulator enable/disable, extcon transitions, runtime resume on wake IRQ, suspend/resume reconfiguration, and sysfs field read/write when `CONFIG_SYSFS` is enabled.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq24257_charger.c

Purpose: implements an I2C/regmap power-supply driver for TI bq24250, bq24251, and bq24257 chargers. It registers one USB charger supply, configures charge current/voltage/termination/input limits from firmware properties, tracks charger state and faults, optionally uses a power-good GPIO, and can auto-select input current limit through D+/D- charger-type detection.

Important APIs/types/functions: `struct bq24257_device` stores I2C, regmap, per-field regmap handles, power-good GPIO, delayed input-current-limit work, init data, cached state, lock, and whether automatic input-current-limit selection is enabled. `struct bq24257_state` contains status, fault, and `power_good`. Register access goes through `bq24257_field_read()` and `bq24257_field_write()` over `regmap_field` objects declared in `bq24257_reg_fields`. Value maps translate register indexes into microamp/microvolt values for VBAT, ICHG, ITERM, IILIMIT, OVP, and VINDPM. Main routines are `bq24257_fw_probe()`, `bq24257_hw_init()`, `bq24257_get_chip_state()`, `bq24257_handle_state_change()`, `bq24257_irq_handler_thread()`, and the power-supply/sysfs property handlers.

Control flow: probe checks SMBus byte-data support, allocates state, matches chip info, initializes regmap and every regmap field, reads required firmware properties `ti,charge-current`, `ti,battery-regulation-voltage`, and `ti,termination-current`, then optional `ti,current-limit`, `ti,ovp-voltage`, and `ti,in-dpm-voltage`. If no fixed current limit is supplied, it enables autoset, except for bq24250. It optionally probes a `"pg"` GPIO for non-bq24250 chips, resets the chip, clears the reset bit in the regcache, disables the watchdog, writes initial charging parameters, initializes cached state, programs fixed input current or kicks D+/D- detection/autoset, registers the power supply with extra sysfs files, and requests a threaded IRQ. IRQ reads the new chip state, compares it to the cached state, handles power insertion/removal/fault transitions, updates cached state, and notifies the power-supply core. Suspend cancels pending autoset work and resets registers to standalone defaults; resume drops the regcache, clears reset in cache, reinitializes hardware, and notifies userspace.

State and persistence: `init_data` stores register indexes derived from firmware values. `state` is protected by `lock` and mirrors the last observed status/fault/power-good condition. Input-current autoset uses delayed work and may be canceled by manual `INPUT_CURRENT_LIMIT` writes. Hardware register state is volatile and explicitly reset on remove and suspend; resume reconstructs it from cached init data.

Dependencies and integration: depends on I2C, regmap/regmap-field, GPIO descriptors, firmware properties, delayed work, IRQs, PM sleep hooks, and the power-supply class. It integrates with standard power-supply properties for status, health, online, manufacturer/model, charge current/voltage, termination current, and input current limit, plus custom sysfs attributes for OVP, input DPM voltage, high-impedance, and system-off controls.

Risks and test signals: the driver unconditionally requests `client->irq`; platforms without a valid IRQ should fail rather than polling. Power-good fallback infers supply presence from fault codes, so non-input faults can mask actual power absence. The reset bit is special-cased in the regcache because hardware reads it back as set; regcache regressions can cause repeated resets during unrelated writes. Manual input-current writes while autoset is pending must reliably cancel delayed work. Tests should cover required/optional property parsing, bq24250 autoset disablement, GPIO and software power-good modes, insert/remove transitions, D+/D- autoset paths for SDP/CDP/DCP/nonstandard ports, safety-timer and no-battery faults, suspend/resume regcache restoration, and sysfs controls.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq24735-charger.c

Purpose: implements a compact SMBus charger driver for the TI bq24735 AC/mains charger. It registers a `POWER_SUPPLY_TYPE_MAINS` supply, programs charge current, charge voltage, and input current from platform data or DT, reports AC presence and charging state, and can react to AC-detect IRQs or periodic polling.

Important APIs/types/functions: `struct bq24735` stores the power supply, I2C client, platform data, lock, optional AC-detect GPIO, delayed poll work, poll interval, and desired `charging` state. `struct bq24735_platform` comes from `include/linux/power/bq24735-charger.h` and supplies name, current/voltage/input-current limits, external-control mode, and supplicant names. SMBus helpers are `bq24735_read_word()`, `bq24735_write_word()`, and `bq24735_update_word()`. Main control is in `bq24735_config_charger()`, `bq24735_enable_charging()`, `bq24735_disable_charging()`, `bq24735_charger_is_present()`, `bq24735_charger_is_charging()`, `bq24735_update()`, and `bq24735_charger_probe()`.

Control flow: probe allocates state, resolves platform data or parses DT properties `ti,charge-current`, `ti,charge-voltage`, `ti,input-current`, and `ti,external-control`, creates a power-supply descriptor name, obtains optional `"ti,ac-detect"` GPIO, checks AC presence through GPIO or the `CHARGE_OPT` AC-present bit, validates manufacturer ID `0x0040` and device ID `0x000b` when AC is present, enables charging if present, registers the mains power supply, then either requests a threaded IRQ or schedules delayed polling if `poll-interval` is configured. Property writes to `STATUS` toggle the desired charging state and call enable/disable. AC IRQ/poll calls `bq24735_update()`, which applies the desired charging state only when AC is present and notifies the power-supply core.

State and persistence: `charging` is the driver’s desired enable state and is protected by `lock` during hardware updates. Programmed limits live in chip registers but are not persisted by the driver beyond the platform/DT data used by `bq24735_config_charger()`. If `ti,external-control` is set, enable/disable/configuration functions become no-ops and an external agent owns charger configuration.

Dependencies and integration: depends on I2C SMBus word operations, power-supply class, OF property parsing, optional GPIO descriptors, threaded IRQs, delayed work, and platform data. The power-supply configuration exposes `supplied_to` names from platform data, so board files/DT decide downstream battery integration.

Risks and test signals: chip ID validation is skipped when AC is absent, so probe can succeed without proving the charger is reachable until later property reads. In external-control mode, reported status still reads hardware presence/config bits but writes intentionally do nothing, which can confuse tests expecting state changes. `bq24735_charger_is_present()` returns false on read errors, potentially treating bus failures as AC removal. Tests should cover DT and platform-data setup, no-AC probe, AC-present ID mismatch, GPIO and register-based presence detection, IRQ and polling paths, external-control behavior, status writes, SMBus read/write failures, and devm delayed-work cleanup.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq2515x_charger.c

Purpose: implements an I2C/regmap charger driver for TI bq25150 and bq25155 low-power battery chargers. It registers separate mains and battery power supplies, configures input current, charge current, precharge current, and regulation voltage, reports battery ADC voltage/current, maps charger/thermal/fault status to power-supply properties, and controls optional reset, powerdown, AC-detect, and charge-enable GPIOs.

Important APIs/types/functions: `struct bq2515x_device` stores mains/battery power supplies, regmap, GPIOs, chip info, model name, mains-online cache, and init data. `struct bq2515x_info` selects the variant regmap defaults and default input-current limit. Register defaults for bq25150 and bq25155 seed `REGCACHE_MAPLE`; `bq2515x_volatile_register()` marks status/flag/ADC registers volatile. Key routines are `bq2515x_wake_up()`, `bq2515x_update_ps_status()`, `bq2515x_disable_watchdog_timers()`, ADC readers, current/voltage limit setters, `bq2515x_charging_status()`, `bq2515x_charger_get_health()`, mains/battery property handlers, `bq2515x_hw_init()`, `bq2515x_read_properties()`, and `bq2515x_probe()`.

Control flow: probe allocates state, selects chip info, initializes regmap, reads `input-current-limit-microamp` or applies variant defaults, obtains optional GPIOs (`ac-detect`, `reset`, `powerdown`, `charge-enable`), registers mains and battery supplies, disables watchdog/reset timers, applies input current limit, reads battery info from firmware through the mains supply, falls back to defaults if missing, and writes charge current, battery regulation voltage, and precharge current. Mains properties expose online/status/health/input-current/model/manufacturer/current/voltage/precharge. Battery properties expose voltage/current now and configured max current/voltage. Current/voltage setters translate micro-unit properties into register codes; changing charge/precharge current disables charging through CE/register, updates the register, then re-enables charging.

State and persistence: `mains_online` is a cached view from AC-detect GPIO or `STAT0.VIN_GOOD`, refreshed by property reads. Init data stores selected limits from DT/defaults/battery info but there is no remove, suspend, or resume path to persist or restore state. Regmap cache contains defaults for nonvolatile registers, while status/flags/ADC are always live. GPIO-controlled wake from ship mode is transient and not represented in persistent driver state.

Dependencies and integration: depends on I2C, regmap, GPIO descriptors, power-supply class, firmware property APIs, and battery-info parsing. It exposes two supplies named `bq2515x-mains` and `bq2515x-battery`; both share the same driver data. Hardware measurement relies on charger ADC registers and optional wake GPIO sequencing.

Risks and test signals: `bq2515x_wake_up()` comments say it should wake the device if a STAT read fails, but the implementation returns the read error and only toggles GPIOs after a successful read. `bq2515x_get_charge_disable()` returns a `bool` but can return a negative regmap error as true, losing error detail. Several logical checks use bitwise `&` with boolean expressions, which works for 0/1 values but is fragile. There is no IRQ handling, so online/fault changes are visible only when properties are queried. Tests should cover missing battery info fallback, all GPIO-absent and GPIO-present combinations, ship-mode wake sequencing, ADC voltage/current conversion, charge-disable via CE and register bit, boundary values for input/charge/precharge/regulation limits, thermal/fault health mapping, and regmap error injection.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq256xx_charger.c

Purpose: implements a multi-variant I2C/regmap USB charger driver for TI bq25600, bq25600D, bq25601, bq25601D, bq25611D, bq25618, and bq25619 devices. It registers charger and battery power supplies, maps charger status/fault registers into standard power-supply properties, supports writable input current/voltage, charge current/voltage, precharge, termination, status, and charge type properties, handles optional USB PHY notifier events, and resets the charger on driver teardown.

Important APIs/types/functions: `struct bq256xx_device` stores I2C, regmap, charger/battery supplies, lock, USB2/USB3 PHY notifier state, model name, init data, selected chip-info table, cached state, and watchdog setting. `struct bq256xx_chip_info` is the variant dispatch table: it selects regmap defaults, getter/setter functions for ICHG/IINDPM/VBATREG/ITERM/IPRECHG/VINDPM, charge-type and thermistor-ignore support, default limits, maximums, and USB-detection capability. Major helpers include `bq256xx_get_state()`, variant current/voltage conversion functions, `bq256xx_set_charge_type()`, `bq256xx_charger_reset()`, `bq256xx_set_charger_property()`, `bq256xx_get_charger_property()`, `bq256xx_irq_handler_thread()`, `bq256xx_hw_init()`, `bq256xx_parse_dt()`, and `bq256xx_probe()`.

Control flow: probe allocates state, selects match data, initializes regmap with variant defaults, reads `ti,watchdog-timeout-ms`, `input-voltage-limit-microvolt`, `input-current-limit-microamp`, and `ti,no-thermistor`, installs a devm cleanup action that resets the chip and unregisters USB notifiers, optionally registers USB2/USB3 PHY notifiers for OTG reporting, registers charger and battery supplies, requests an optional threaded IRQ, and runs hardware init. Hardware init programs watchdog timeout, reads battery info, derives max charge current/voltage or default values, writes input voltage/current, charge current, precharge current, battery regulation voltage, termination current, and optionally TS-ignore. IRQ reads status/fault registers, compares the new state to cached state under the lock, updates the cache, and notifies the charger. Property gets read live status registers and dispatch through chip-info conversion functions.

State and persistence: `init_data` stores DT/default inputs and max limits; `state` is cached only for IRQ change detection. Register state is volatile; `bq256xx_charger_reset()` writes `BQ256XX_REG_RST` during device cleanup and unregisters USB PHY notifiers. Runtime property writes go directly to registers and are not persisted across reset/reprobe. The USB notifier only queues work and emits `power_supply_changed()` for `USB_EVENT_NONE`; it does not program OTG mode.

Dependencies and integration: depends on I2C, regmap with variant-specific defaults and volatile status registers, USB PHY notifier APIs, workqueues, threaded IRQs, firmware properties, power-supply core, and battery-info parsing. The charger supply reports USB types including SDP/CDP/DCP/ACA/UNKNOWN, with reduced type mapping for variants lacking BC1.2 detection. The battery supply exposes maximum charge current and voltage derived from battery info or chip defaults.

Risks and test signals: `bq256xx_hw_init()` appears to dereference `bat_info` in the missing-battery-info fallback path after `power_supply_get_battery_info()` returns an error other than `-ENOMEM`; compare with `bq2515x_hw_init()`, which uses defaults without touching a failed pointer. The health mapping switches on `state.chrg_stat` for `BQ256XX_CHRG_FAULT_*` cases, but those fault codes are stored in `state.chrg_fault`; this can misreport input, thermal, and safety-timer faults. `bq256xx_set_charger_property()` treats writable `STATUS` as a no-op that returns the initial `-EINVAL`, despite marking it writeable. If both USB2 and USB3 PHYs are present, the same notifier block/work item is registered twice and cleanup unregisters both. Tests should cover all chip-info variants, default and battery-info paths, thermistor-ignore only on supported variants, watchdog bounds, IRQ state change detection, USB type mapping with and without hardware detection, every writable property, register reset cleanup, and fault-to-health mapping.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq257xx_charger.c

Purpose: implements the charger child driver for the TI bq257xx MFD family, currently wired to bq25703-style registers and operations. It is a platform driver, not a direct I2C driver: the parent MFD supplies `struct bq257xx_device` and regmap. The driver registers a USB charger power supply, configures maximum input current, charge current, charge voltage, and minimum system voltage from battery/firmware data, reports ADC current/voltage and USB type, reacts to supplier changes, and puts hardware into low-power mode on shutdown.

Important APIs/types/functions: `struct bq257xx_chg` stores the chip operation table, parent MFD pointer, power supply, cached online/charge/fault flags, USB type, supplier status, and configured limits. `struct bq257xx_chip_info` supplies hooks for hardware init/shutdown, state reading, and limit setters. bq25703-specific helpers include `bq25703_get_state()`, `bq25703_get_min_vsys()`, `bq25703_set_min_vsys()`, `bq25703_get_cur()`, `bq25703_get_ichg_cur()`, `bq25703_set_ichg_cur()`, `bq25703_get_chrg_volt()`, `bq25703_set_chrg_volt()`, `bq25703_get_iindpm()`, `bq25703_set_iindpm()`, `bq25703_get_vbat()`, `bq25703_hw_init()`, and `bq25703_hw_shutdown()`. Power-supply integration is handled by `bq257xx_get_charger_property()`, `bq257xx_set_charger_property()`, `bq257xx_external_power_changed()`, and `bq257xx_charger_probe()`.

Control flow: probe inherits the OF node from the parent, obtains the parent MFD regmap state with `dev_get_drvdata(pdev->dev.parent)`, allocates charger state, registers the `bq257xx-charger` USB power supply, parses battery info for minimum system voltage, max charge voltage, and max charge current, reads optional `input-current-limit-microamp`, initializes hardware, and requests the parent I2C IRQ if present. Hardware init disables the watchdog, writes max charge current/voltage/min-system-voltage/input-current, disables low-power mode, enables and starts ADC conversions at full scale, and enables ADC channels. Property reads refresh state first, then map online/fast/precharge/fault bits to status and health, or read live ADC/config registers. Supplier changes query whether the charger is supplied, read supplier USB type, use supplier `CURRENT_MAX` for USB-PD-like types when present, and reprogram charge/input/voltage limits because removal can erase charger registers.

State and persistence: `online`, `fast_charge`, `pre_charge`, and fault booleans are refreshed from hardware by `bq25703_get_state()`. Limit fields are initialized from battery info and firmware defaults and reused when input power changes. Register state is hardware-volatile; the driver explicitly reprograms limits on supplier changes and enables low-power mode on shutdown. There is no suspend/resume callback in this file.

Dependencies and integration: depends on the parent bq257xx MFD/regmap definition from `<linux/mfd/bq257xx.h>`, platform bus, power-supply supplier APIs, firmware properties, bitfield helpers, and optional threaded IRQ from the parent I2C client. USB type reporting is supplier-derived rather than detected directly by this driver.

Risks and test signals: `bq25703_hw_init()` ignores return values from several `regmap_update_bits()` calls before and after the checked limit writes, so ADC/watchdog/low-power setup failures can be missed. The chip-info table is currently only bq25703-specific despite generic bq257xx naming. `bq257xx_parse_dt()` is called after power-supply registration because battery info lookup needs the supply, so probe ordering depends on that registration succeeding. Tests should cover parent MFD probe ordering, missing/invalid battery info, optional input-current defaulting, supplier absent/present transitions, USB-C/PD/PD_PPS current selection, IRQ-triggered supplier refresh, property writes for max current/voltage/input current, ADC value conversion, health mapping for ACOV/BATOC/ACOC faults, and shutdown low-power programming.
