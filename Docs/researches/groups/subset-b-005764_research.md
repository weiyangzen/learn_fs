# sources/distributed-fs/ceph-client/fs/smb/server/smb2pdu.c

## Purpose
`smb2pdu.c` is the ksmbd server-side SMB2/SMB3 protocol command core. It builds and validates SMB2 headers and compound responses, negotiates dialect/security/encryption/signing capabilities, authenticates sessions, connects shares, opens files and IPC pipes, maps SMB file information classes to VFS operations, performs reads/writes/locks/ioctls, handles oplock and lease break acknowledgments, and signs, hashes, encrypts, or decrypts SMB3 traffic.

## Important APIs, Types, and Functions
The externally visible handlers are the SMB2 command entry points declared in `smb2pdu.h`: `smb2_handle_negotiate`, `smb2_sess_setup`, `smb2_tree_connect`, `smb2_tree_disconnect`, `smb2_session_logoff`, `smb2_open`, `smb2_query_dir`, `smb2_query_info`, `smb2_close`, `smb2_echo`, `smb2_set_info`, `smb2_read`, `smb2_write`, `smb2_flush`, `smb2_cancel`, `smb2_lock`, `smb2_ioctl`, `smb2_oplock_break`, and `smb2_notify`. Protocol glue includes `init_smb2_rsp_hdr`, `init_smb2_neg_rsp`, `smb2_set_err_rsp`, `smb2_set_rsp_credits`, `smb2_allocate_rsp_buf`, `smb2_check_user_session`, `smb2_get_ksmbd_tcon`, `is_chained_smb2_message`, and `get_smb2_cmd_val`.

Negotiation helpers build and parse SMB 3.1.1 contexts: preauth integrity, encryption, POSIX extension, and signing capabilities. Session setup uses SPNEGO/NTLMSSP and optional Kerberos helpers, preauth hashing, channel lookup for multichannel, session state transitions, signing-key generation, and encryption-key generation. File create/open code centers on `smb2_open`, `smb2_create_open_flags`, `parse_durable_handle_context`, `smb2_creat`, `smb2_set_ea`, `smb2_create_sd_buffer`, DOS attribute xattr helpers, durable handle setup, lease/oplock grant integration, alternate stream xattrs, and POSIX create context support.

Query and set paths are split by SMB info type. Directory enumeration uses `smb2_query_dir`, `__query_dir`, `reserve_populate_dentry`, `process_query_dir_entries`, and `smb2_populate_readdir_entry`. File and filesystem metadata use `smb2_get_info_file`, `smb2_get_info_filesystem`, and `smb2_get_info_sec`, with many per-class encoders such as `get_file_all_info`, `get_file_stream_info`, `find_file_posix_info`, and `smb2_get_ea`. Metadata mutation flows through `smb2_set_info_file`, `set_file_basic_info`, `set_file_allocation_info`, `set_end_of_file_info`, `set_rename_info`, `set_file_disposition_info`, `set_file_position_info`, and `smb2_set_info_sec`.

Data path helpers include pipe-specific read/write/close routines, RDMA channel setup and transfer helpers, VFS read/write/fsync calls, and SMB byte-range locking helpers such as `smb_flock_init`, `smb2_set_flock_flags`, `smb2_lock_init`, and `smb2_remove_blocked_lock`. FSCTL handling includes copychunk, validate-negotiate-info, network-interface query, allocated-range query, pipe transceive, set sparse, request resume key, set zero data, get reparse point, and duplicate extents. Security and transport helpers include SMB2 and SMB3 signature verification/generation, SMB3 preauth response hashing, transform-header detection, `smb3_encrypt_resp`, `smb3_decrypt_req`, and final-session-setup detection.

## Control Flow
Request processing starts with response-buffer allocation and header initialization, then validates the user session and tree connection for commands that require them. Compound requests advance `work->next_smb2_rcv_hdr_off`, align each response to 8 bytes, carry related-operation FIDs through `work->compound_fid`, `work->compound_pfid`, and `work->compound_sid`, and update RFC1001 lengths and iov entries as each chained response is built. Credit accounting charges the current request, grants bounded credits, and defers the aggregate granted credit count until the last command in a compound request.

Negotiation parses dialect and negotiate-context bounds, selects the connection dialect, initializes dialect-specific server values, records client capabilities/security mode/GUID, emits GSS security buffer data, and sets connection state to need session setup. SMB 3.1.1 additionally initializes preauth state, parses contexts, computes the request preauth hash, and emits response negotiate contexts. Session setup creates, reuses, or binds a session; decodes SPNEGO tokens; runs NTLM negotiate/authenticate or Kerberos authentication; applies guest, signing, encryption, multichannel, and previous-session rules; and moves the connection/session into valid or expired state with SMB status mapping and delayed reconnect behavior on repeated bad-password cases.

Tree connect decodes the UNC path, extracts the share name, asks management code to create a tree connection, fills disk or IPC share capabilities, enables POSIX extensions when negotiated, and transitions the tree to `TREE_CONNECTED`. Disconnect and logoff close open FDs, mark tree/session state, and coordinate idle connection waits. Create/open validates names, stream syntax, create options/disposition/access masks, share writability, DACL permissions, POSIX contexts, EA and SD create contexts, durable reconnects, and delete-on-close semantics. It creates missing files/directories, opens a VFS file, allocates volatile and persistent IDs, initializes `ksmbd_file` access/share/create state, applies inherited ACLs or security descriptors, links the file into the inode file list, checks delete-pending state, grants oplocks/leases, performs truncation/allocation-size work, updates DOS attribute xattrs, and emits create contexts for leases, maximal access, disk id, durable handles, and POSIX create responses.

Directory query reserves dot entries when appropriate, iterates `iterate_dir`, pattern-matches and veto-filters names, reserves fixed-size entry slots first, then looks up dentries and populates metadata-rich SMB records. Query-info dispatches among file, filesystem, and security classes, sizes output against negotiated transaction limits, encodes stat/xattr/ACL/share data, and uses pinned response iovs or read-style iovs for security descriptors. Set-info dispatches to file metadata, security descriptor, EA, rename, link, allocation, EOF, delete-pending, position, and mode handlers, wrapping VFS mutations with permission checks, share writability, fsuid override/revert where needed, oplock breaks for data-affecting changes, and NTSTATUS mapping.

Read/write support normal file handles and IPC pipes. Normal reads validate FID, access, offset, length, minimum count, RDMA descriptors, and max negotiated size, then read into an auxiliary payload buffer or write the payload over RDMA. Writes validate share writability, FID, access, offsets, length, optional write-through, in-band or RDMA payload location, and then call `ksmbd_vfs_write`. Lock handling builds a batch of POSIX locks, rejects invalid flag ordering and intra-request conflicts, checks existing ksmbd connection lock lists for SMB-visible conflicts, can return immediate failures, or sets async state, sends `STATUS_PENDING`, waits, handles cancellation, retries, and rolls back earlier locks on later failure.

IOCTL dispatch validates FSCTL-only flags and input/output counts before calling the individual FSCTL helpers. Oplock and lease break acknowledgment dispatches by structure size, validates state transitions, updates oplock/lease state through `opinfo_*` helpers, wakes waiters, and emits acknowledgment or protocol-error statuses. Signing and encryption paths calculate the covered length for standalone or compound PDUs, zero signatures before verification, use SMB2 HMAC-SHA256 or SMB3 CMAC/AES signing keys, update preauth hashes for negotiate/session setup, build SMB3 transform headers, and convert encrypted request buffers back into plain SMB2 frames after successful decryption.

## State and Persistence
Persistent effects are indirect through the Linux VFS and ksmbd metadata helpers. The file creates and removes directories/files, truncates and fallocates data, performs reads/writes/fsyncs, renames and hardlinks files, zeroes ranges, clones/copies ranges, stores DOS attributes, create times, stream names, EAs, and NT security descriptors in xattrs, and applies POSIX ACL inheritance. Alternate data streams are represented by xattrs under ksmbd stream naming conventions. Durable and persistent handles survive disconnects through ksmbd durable FD state rather than through this file's own on-disk records.

Runtime state mutated here includes connection dialect/capabilities/security mode/GUID, preauth info, total and outstanding credits, request/response offsets for compounds, async request lists and async IDs, session state and session preauth hashes, multichannel channel xarray entries and signing keys, tree connection state and maximal access, open file table entries and inode file lists, file access/share/create options, cached DOS attributes, create/itime values, stream metadata, delete-pending flags, oplock/lease state, blocked lock lists, connection lock lists, response iov state, transform buffers, and RDMA invalidation keys. Locks used include connection locks, session/tree rwsems, channel rwsems, inode file-list locks, connection lock-list spinlocks, RPC locks, global connection-list locks, and VFS inode/file locks.

## Dependencies and Integration Points
This file is tightly integrated with the rest of ksmbd: authentication (`auth.h`, `asn1.h`, NTLMSSP/Kerberos helpers), connection/session/tree management, user/share configuration, VFS wrappers, VFS cache and FID tables, oplock/lease code, ACL/security descriptor code, NDR/RPC IPC transport, stats, TCP/RDMA transport, crypto/signing/encryption helpers, and SMB common status/protocol definitions. Kernel dependencies include VFS path lookup/open/statfs/getattr/truncate/fallocate/copy/clone/fsync/xattr/ACL APIs, file locks, idmapped mounts, network device and address enumeration, ethtool link settings, CRC32, random nonces, crypto constant-time comparison, xarrays, lists, rwsems, spinlocks, wait queues, and RFC1001/SMB buffer helpers.

The file is the command-handler implementation behind the server dispatch table declared elsewhere. It consumes structures and constants from common SMB2 headers, create-context helpers, FSCTL definitions, and filesystem-specific share/user configuration. It also integrates with ksmbd's response-iov pinning model: large reads and security descriptors can be attached as auxiliary payloads while normal responses are pinned from the response buffer.

## Risks
The highest-risk areas are wire-buffer bounds, compound-request offset accounting, and response iov length adjustments because malformed clients can exercise every boundary. SMB 3.1.1 negotiation context parsing, preauth hashing order, signing coverage lengths, transform-header decryption, and multichannel signing-key selection are security sensitive. Authentication state transitions must avoid leaking valid sessions across failed setup, binding, reconnect, or previous-session flows. Create/open mixes path lookup, DACL checks, idmapped credentials, file creation, inherited ACLs, SD xattrs, durable handles, stream xattrs, delete-on-close, share modes, and oplock breaks; partial failure cleanup must avoid leaked FDs, stale inode-list entries, or files left with unintended ACL/xattr state.

Other fragile areas include read/write RDMA descriptor validation, auxiliary payload lifetime, EOF/minimum-count status handling, lock rollback and async cancellation races, cross-connection byte-range lock conflict logic, xattr EA/stream iteration with variable-length entries, `FILE_ALL_INFORMATION` and directory-entry sizing, NTSTATUS-to-errno mappings, share veto and symlink rejection consistency, durable-handle replay/reconnect validation, sparse/DOS attribute xattr persistence, network-interface ioctl assumptions about device operations, and unimplemented notify/DFS paths returning the expected Windows-compatible statuses.

## Test Signals
Useful tests include SMB dialect negotiation for SMB2.1, SMB3.0, SMB3.0.2, and SMB3.1.1 with malformed and duplicate contexts; signing mandatory/optional modes; encrypted SMB3 sessions; multichannel binding with mismatched GUID, dialect, unsigned binding, guest session, expired session, and reconnect states; NTLM and Kerberos success/failure; compound create-query-close and create-read-close sequences with related FIDs; credit exhaustion and over-requested credits; tree connect/disconnect/logoff with open handles; durable handle request, replay, disconnect, reconnect, and CA-share cases.

File-operation signals should cover create dispositions and options, POSIX create context, ACL inheritance, SD create context, maximal access, EA create/query/set/delete, named streams, DOS attribute xattr persistence, delete-on-close, share violations, veto filenames, symlink rejection, truncation and allocation-size handling, query-dir restart/single-entry/pattern/large-directory behavior, all supported file and filesystem information classes, security descriptor buffer sizing, rename/link/delete-pending rules, readonly share denial, read/write length limits, minimum-count EOF, RDMA read/write, fsync, copychunk, duplicate extents, allocated ranges, sparse/zero-data, pipe transceive, byte-range locks with blocking cancellation and rollback, oplock and lease break acknowledgments, and fuzzing of every offset/length/count field under KASAN/KMSAN/lockdep.

# sources/distributed-fs/ceph-client/fs/smb/server/smb2pdu.h

## Purpose
`smb2pdu.h` defines ksmbd server-side SMB2/SMB3 PDU constants, response helper structures, query/set information payload structures, POSIX extension payloads, and the public function surface implemented by `smb2pdu.c` and consumed by the SMB server dispatcher, signing/encryption paths, and command validation code.

## Important APIs, Types, and Functions
The header defines create action values (`FILE_SUPERSEDED`, `FILE_OPENED`, `FILE_CREATED`, `FILE_OVERWRITTEN`), credit and I/O size limits (`SMB2_MAX_CREDITS`, SMB2/SMB3 default/min/max sizes), negotiate-context offset constants, session state bits and timeout, Apple create context tag `SMB2_CREATE_AAPL`, durable handle timeout, FSCTL flag `SMB2_0_IOCTL_IS_FSCTL`, file/FS information class response-size constants, directory query flags, compression constants, POSIX file type constants, and `FILE_MODE_INFO_MASK`.

Wire-format structures include `struct preauth_integrity_info`, create-context payloads for allocation size, durable response, POSIX response, EA buffer, and SD buffer, ioctl response payloads for socket addresses, file object IDs, and sparse state, file information payloads such as access, alignment, alternate name, stream, standard, EA, allocation, disposition, position, mode, compression, attribute tag, EA entries, and POSIX directory/query records, plus `struct fs_type_info` for filesystem-name support mapping. These structures are packed where they are directly serialized on the wire.

The function declarations expose dialect initializers, tunable setters for max read/write/trans/credits, request/response recognition helpers, response header and error helpers, session/tree validation, signing and encryption helpers, async work helpers, channel lookup, preauth hashing, transform-header handling, and every SMB2 command handler. The command-handler declarations form the server-side dispatch contract for negotiate, session setup, tree connect/disconnect, logoff, create/open, query/set info, query directory, close, echo, read/write, flush, cancel, lock, ioctl, oplock break, and notify.

## Control Flow
The header has no executable flow, but it organizes the protocol contract used by `smb2pdu.c`. A request dispatcher can use `get_smb2_cmd_val`, `init_smb2_rsp_hdr`, `smb2_allocate_rsp_buf`, `smb2_check_user_session`, `smb2_get_ksmbd_tcon`, `smb2_is_sign_req`, signing verification, and the command handlers to process a request. Response post-processing uses `smb2_set_rsp_credits`, SMB2/SMB3 signing helpers, SMB3 preauth hashing, and optional SMB3 encryption helpers before transport writeout.

The wire structures mirror SMB2 create contexts, query-info buffers, query-directory entries, ioctl payloads, and POSIX extension records, so callers can cast validated request or response buffer regions to the appropriate packed type and then use little-endian conversion helpers in the implementation. Session state constants guide setup, validation, expiration, and reconnect handling.

## State and Persistence
The header itself does not persist state. It defines constants and structures that describe persistent or externally visible state carried over the SMB protocol: session validity, create action results, durable handle timeout, DOS/NT file metadata fields, EA records, POSIX inode metadata, security/create contexts, filesystem capacity/attribute response sizes, and transform/signing/encryption protocol surfaces. Runtime state such as `struct ksmbd_work`, `struct ksmbd_conn`, `struct ksmbd_session`, and channel entries is declared elsewhere and manipulated through the function prototypes here.

## Dependencies and Integration Points
The header depends on `ntlmssp.h` and `smbacl.h` for authentication/security descriptor types and on common SMB2 protocol definitions included transitively by the server sources. It is included by SMB server command dispatch, message validation, signing/encryption code, and supporting ksmbd modules that need the SMB2 command-handler API or PDU layouts. The POSIX extension definitions align with the Samba SMB3 POSIX extension specification referenced in the file comments, while negotiate and transform helpers align with SMB3.1.1 preauth, signing, and encryption requirements.

## Risks
Risks are mostly ABI and wire-format correctness. Packed structure sizes, flexible-array placement, context offsets, and response-size constants must match the SMB2/SMB3 specifications and `smb2pdu.c` sizing logic. Incorrect constants can cause buffer under-allocation, truncated responses, client interoperability failures, or parser confusion. Conditional `OFFSET_OF_NEG_CONTEXT` changes with Kerberos support must remain consistent with the actual negotiate response layout. Public prototypes must stay synchronized with implementations and dispatch table expectations. POSIX extension structures encode SID buffer assumptions and file-type bit positions that must remain compatible with clients.

## Test Signals
Compile coverage should catch prototype drift, but runtime signals are needed for layout correctness: negotiate responses with and without Kerberos support, SMB3.1.1 negotiate contexts, create contexts for allocation/durable/POSIX/EA/SD, all query-info classes whose sizes are defined here, directory enumeration classes including POSIX info, FS information classes, sparse/object-id/ioctl payloads, compression and attribute-tag info, and POSIX file type encoding for regular files, directories, symlinks, character/block devices, FIFOs, and sockets. Packet capture or smbtorture validation should confirm structure sizes, offsets, endian fields, and padding/alignment.
