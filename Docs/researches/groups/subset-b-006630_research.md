# sources/distributed-fs/ceph-client/tools/perf/pmu-events/arch/x86/broadwellde/uncore-cache.json

Purpose: Defines Broadwell-DE x86 uncore cache-facing PMU event aliases for `perf`. The file is a JSON array of 382 event records consumed by `tools/perf/pmu-events/jevents.py` during perf build generation, not executable runtime code. It supplies the event names, encodings, counter constraints, package scope, units, short descriptions, and longer descriptions that become generated `pmu-events.c` table entries for the `GenuineIntel-6-56,v12,broadwellde,core` mapfile entry.

Important schema and event surface: Every record uses the perf PMU event table keys `EventName`, `BriefDescription`, `Counter`, `PerPkg`, and `Unit`; most records also carry `EventCode`, `UMask`, and `PublicDescription`. Two entries, `UNC_C_CLOCKTICKS` and `UNC_H_CLOCKTICKS`, intentionally lack `EventCode` because they describe unit clock ticks. The file is split across two units: 162 `CBOX` records for CBo/LLC/ring/cache-box activity and 220 `HA` records for home-agent, memory-controller-facing, directory, snoop, tracker, and ring activity. Most events can use counters `0,1,2,3`; 26 events are restricted to counter `0`, and eight events use counters `0,1,2`.

Important event families: `CBOX` families include LLC lookups, LLC victims, CBo miscellaneous conditions, QLRU age updates, ring AD/AK/BL/IV usage and bounce/starvation indicators, RxR queue occupancy/inserts/retry/starvation events for IPQ/IRQ/ISMQ, SBO credit acquisition/occupancy, TOR inserts and occupancy, and TxR insertion/starvation/ADS usage. `HA` families include request classifications, TAD request groups, directory lookup/update/latency controls, snoop cycles/responses/occupancy, local snoop response receipt, HITME lookups/hits/PV-bit hits, tracker occupancy/full/not-empty/pending occupancy, OSB/OSB EDR, BT-to-HT not-issued causes, IMC read/write/retry and bypass events, iMC RPQ/WPQ regular/special credit stalls per channel, ingress no-credit cycles, HA ring AD/AK/BL usage, SBO credit/stall events, and outbound TxR AD/AK/BL insertion/full/not-empty/starvation events.

Control flow and integration: At build time, `pmu-events/Build` invokes `jevents.py` over the architecture event tree. `jevents.py` parses each JSON record, lowercases `EventName` for the generated event name, maps fields such as `EventCode` and `UMask` into perf event terms, stores `BriefDescription`/`PublicDescription`, and emits static tables in generated `pmu-events.c`. At runtime, perf resolves the Broadwell-DE table through `arch/x86/mapfile.csv`; `perf list`, `perf stat`, and parser paths expose names such as `UNC_C_LLC_LOOKUP.ANY` or `UNC_H_IMC_WRITES.ALL` when the running CPU model matches and the kernel exposes the corresponding uncore PMU instances.

State and persistence behavior: This file has no mutable software state. Its persistent behavior is the checked-in JSON data and the generated C table derived from it. `PerPkg: "1"` marks these as package-scoped uncore events rather than per-logical-CPU core events. Counter availability, event code, umask, and unit fields persist into the generated alias table and influence how perf selects hardware PMUs and programs raw uncore counters.

Dependencies: Depends on perf's PMU event schema, `pmu-events/jevents.py`, `pmu-events/arch/x86/mapfile.csv`, and Linux kernel uncore PMU drivers that expose Broadwell-DE CBOX and HA PMU names/format files through sysfs. Semantic correctness also depends on Intel Broadwell-DE uncore event definitions because the JSON encodings are hardware contracts. Adjacent broadwellde JSON files provide complementary core, memory, IO, power, and metric-group event data but this file owns the cache/home-agent subset.

Risks and edge cases: Several events require non-obvious extra filtering. The LLC lookup descriptions warn that umask bit 0 and a matching CBo global state filter must be selected or the event can count nothing. NID-qualified events rely on Cn PMON box filter state, so an alias alone may be insufficient for a meaningful measurement. Occupancy events such as `UNC_C_COUNTER0_OCCUPANCY`, TOR occupancy, tracker occupancy, and queue occupancy require ratios against insert/allocation events to derive latency-like signals and can be misread as simple counts. Counter restrictions must match hardware support; incorrect `Counter` fields can cause scheduling failures or misleading multiplexing. Missing, stale, or typoed descriptions are user-facing in `perf list` and can also confuse metric authors who match by `EventName`.

Test signals: Run `jq empty` and schema checks to catch malformed JSON and missing required keys. Build perf with `JEVENTS_ARCH=all` or the x86 target and verify `pmu-events.c` generation succeeds. Use `tools/perf/tests/pmu-events.c` style checks for generated table integrity and mapfile matching. On Broadwell-DE hardware, `perf list` should show representative aliases from both units, and `perf stat -e` should resolve examples such as `UNC_C_LLC_LOOKUP.ANY`, `UNC_C_TOR_INSERTS.ALL`, `UNC_H_REQUESTS.READ`, and `UNC_H_IMC_WRITES.ALL`. Hardware validation should compare clocktick, insert, occupancy, read/write, and credit-stall events under controlled memory, LLC, and inter-socket traffic.

# sources/distributed-fs/ceph-client/tools/perf/pmu-events/arch/x86/broadwellde/uncore-interconnect.json

Purpose: Defines Broadwell-DE x86 uncore interconnect PMU event aliases for `perf`. The file is a JSON array of 70 event records for IRP and UBOX interconnect/message behavior, consumed by `jevents.py` into generated perf event tables for the Broadwell-DE model mapping.

Important schema and event surface: Records use the same perf PMU event schema as other `pmu-events` JSON files: `EventName`, `BriefDescription`, `Counter`, `PerPkg`, `Unit`, and usually `EventCode`, `UMask`, and `PublicDescription`. All 70 events are package-scoped with `PerPkg: "1"` and are programmable on counters `0,1`. The file has 48 `IRP` entries and 22 `UBOX` entries. `UNC_I_CLOCKTICKS` intentionally lacks an explicit event code, while every other record provides an event code; all records include a public description.

Important event families: `IRP` events cover aggregate cache total occupancy, coherent operations (`CLFLUSH`, `CRD`, `DRD`, PCI coherent reads/hints, RFO, WbMtoI), miscellaneous fast-path/cache-insert/prefetch timeout and transfer conditions, transaction classes (`ATOMIC`, `CLFLUSH`, `RD`, `WCILF`, `WIL`, `WR`), snoop responses, inbound BL queue inserts/full cycles/occupancy for DRS/NCB/NCS, AK inserts, outbound TxR request occupancy, outbound data inserts, and AD/BL stall-credit cycles. `UBOX` events cover virtual logical wire doorbells, thread-filter match modes, U2C monitor/event messages such as livelock, machine check, trap, and other system-management/PMI classes, PHOLD assert-to-ack cycles, and RACU outstanding register requests.

Control flow and integration: During perf builds, the JSON is parsed by `pmu-events/jevents.py` alongside the rest of `arch/x86/broadwellde`. The generated C table is selected through `arch/x86/mapfile.csv` for the Broadwell-DE CPU ID. Runtime lookup is data-driven: `perf list` and parse-events code expose aliases such as `UNC_I_COHERENT_OPS.RFO` or `UNC_U_U2C_EVENTS.CMC` when the matching PMU unit is present in sysfs. The `Unit` field tells perf which uncore PMU namespace the event belongs to, while `EventCode`, `UMask`, and any user-supplied extra terms form the actual hardware encoding.

State and persistence behavior: There is no in-process state, allocation, or persistence beyond the source-controlled JSON and generated perf event tables. The persistent hardware contract is the pair of unit-scoped event definitions and their counter constraints. Occupancy-style entries accumulate outstanding requests per cycle, so derived latency or pressure analyses require pairing with allocation/insert counters and elapsed clock events rather than treating the raw count as a transaction total.

Dependencies: Depends on the perf PMU event JSON schema, `jevents.py`, the x86 Broadwell-DE mapfile row, generated `pmu-events.c`, and kernel uncore PMU drivers exposing IRP and UBOX PMUs with compatible event/umask/filter formats. Semantics depend on Intel Broadwell-DE uncore documentation for IRP ordering queues, switch paths, snoop response encodings, UBOX thread filters, and U2C event routing.

Risks and edge cases: `UNC_I_CACHE_TOTAL_OCCUPANCY.SOURCE` depends on `IRP_PmonFilter.OrderingQ` selecting one source queue; the alias does not itself encode multi-queue selection and the description states that only one queue can be monitored at a time. UBOX filter-match and doorbell events depend on `NCUPMONCTRLGLCTR.ThreadID`/filter state, so raw alias use can produce broad or empty counts depending on filter programming. The file mixes transaction counters, occupancy counters, and stall-cycle counters; dashboards or metrics must avoid summing unlike units. Because all entries share only two counters, groups with many IRP/UBOX aliases can multiplex heavily or fail scheduling. Typos or stale hardware names in event records are user visible and can silently break metric expressions that match `EventName`.

Test signals: Validate JSON syntax and required fields with `jq` or the perf PMU event tests. Build perf with jevents enabled and confirm generated tables include both `IRP` and `UBOX` event families. On Broadwell-DE hardware, `perf list` should expose representative aliases including `UNC_I_COHERENT_OPS.RFO`, `UNC_I_TRANSACTIONS.RD`, `UNC_I_TxR_REQUEST_OCCUPANCY`, `UNC_U_EVENT_MSG.DOORBELL_RCVD`, and `UNC_U_U2C_EVENTS.UMC`. Runtime smoke tests should pair occupancy with insert/allocation counters, exercise PCIe or device traffic for IRP Tx/Rx queues, and check UBOX filter-dependent events with and without explicit thread/filter settings.
