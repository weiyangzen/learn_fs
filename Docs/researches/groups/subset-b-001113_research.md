## sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sdm845.c

Purpose: implements the Qualcomm SDM845 camera clock controller platform driver. It exposes the CAM_CC clock tree and camera GDSC power domains used by SDM845 camera blocks: BPS, IPE 0/1, IFE 0/1/lite, JPEG, LRME, ICP, CCI, CSI PHY timers, CSIPHY, MCLKs, CAMNOC, and shared AHB/system clocks.

Important APIs/types/functions: the file is built from static common-clock-framework descriptors. `clk_alpha_pll` objects define four Fabia PLLs at offsets `0x0`, `0x1000`, `0x2000`, and `0x3000`, with even postdiv outputs. `parent_map`, `clk_parent_data`, and `freq_tbl` arrays describe mux selectors and legal rates for each RCG. `clk_rcg2` sources such as `cam_cc_bps_clk_src`, `cam_cc_ife_0_clk_src`, `cam_cc_ipe_0_clk_src`, `cam_cc_mclk0_clk_src`, and `cam_cc_slow_ahb_clk_src` feed `clk_branch` gates. `gdsc` instances model `bps_gdsc`, `ipe_0_gdsc`, `ipe_1_gdsc`, `ife_0_gdsc`, `ife_1_gdsc`, and `titan_top_gdsc`. `cam_cc_sdm845_clocks`, `cam_cc_sdm845_gdscs`, `cam_cc_sdm845_regmap_config`, and `cam_cc_sdm845_desc` form the registration contract. `cam_cc_sdm845_probe()` maps registers, configures PLLs, and calls `qcom_cc_really_probe()`.

Control flow: device-tree matching on `qcom,sdm845-camcc` binds the platform driver. Probe calls `qcom_cc_map()` with the descriptor, programs Fabia PLL alpha/L values for PLL0 through PLL3, then registers all clocks and GDSCs with the Qualcomm common clock controller core. After registration, runtime clock operations are table-driven through CCF callbacks: RCGs choose parents and dividers from their `freq_tbl`, branch clocks toggle enable bits and poll halt registers, and GDSCs manage power-domain state. The file explicitly uses `clk_rcg2_shared_ops` for several camera RCGs that must switch to XO during disable so camera memories power down gracefully; other RCGs use normal `clk_rcg2_ops`.

State and persistence behavior: the driver has no persistent filesystem state. Static descriptors encode all clock topology, register offsets, parent choices, frequencies, halt checks, and GDSC topology. Runtime state persists only in hardware registers accessed through regmap: PLL configuration, RCG command registers, branch enable registers, halt status, and GDSC control/status. Child GDSCs are parented to `titan_top_gdsc`; BPS/IPE domains use `HW_CTRL | POLL_CFG_GDSCR`, while IFE domains and top use `POLL_CFG_GDSCR`.

Dependencies/integration points: depends on Linux CCF, regmap, platform device matching, `dt-bindings/clock/qcom,camcc-sdm845.h`, and Qualcomm helpers from `common.h`, `clk-alpha-pll.h`, `clk-branch.h`, `clk-rcg.h`, `clk-regmap.h`, and `gdsc.h`. Consumers are camera/media drivers and device-tree nodes that reference CAM_CC clock IDs and GDSC IDs. The regmap range is capped at `0xd004`, so all encoded offsets must stay within that MMIO region.

Risks: most behavior is hardware-table driven, so wrong register offsets, mux values, divider values, parent maps, or binding IDs can silently expose unusable clocks. `CLK_SET_RATE_PARENT` is needed only where PLL rates must follow child requests; missing it can cause rate failures, while overusing it can retune shared parents unexpectedly. The shared-RCG disable path is important for graceful camera-memory power-down. GDSC parent/flag mistakes can break camera power sequencing. Probe reuses one local `alpha_pll_config`; missed field clearing would matter if more than `l` and `alpha` were programmed later.

Test signals: build coverage should include this file with `CONFIG_SDM_CAMCC_845` or equivalent kernel config coverage, plus dt-binding checks for `qcom,sdm845-camcc`. Runtime signals are successful probe, registered clock names under debugfs, expected PLL rates via `clk_summary`, successful camera pipeline bring-up, clean enable/disable cycles for IFE/IPE/BPS/JPEG/LRME/ICP clocks, and GDSC transitions without timeout or halt-poll warnings.

## sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm4450.c

Purpose: implements the SM4450 camera clock controller. It registers SM4450 CAM_CC clocks, resets, and the top camera GDSC for BPS, CAMNOC, CCI 0/1, CRE, ICP, MCLKs, OPE, TFE 0/1, CSI PHY timers, CSIPHYs, CPAS/core AHB, and system timer clocks.

Important APIs/types/functions: this driver uses Lucid Evo and Rivian Evo PLL support. PLL0, PLL1, PLL3, and PLL4 are Lucid Evo PLLs; PLL2 is a Rivian Evo PLL. `alpha_pll_config` constants program nominal PLL rates including 1200 MHz PLL0, 600 MHz PLL1, 960 MHz PLL2, 600 MHz PLL3, and 700 MHz PLL4. PLL postdivs expose even and, for PLL0, odd outputs. Eight parent maps describe hardware mux values for XO and PLL outputs. `clk_rcg2` sources cover BPS, CAMNOC AXI, CCI, CPHY, CRE, CSI timers, fast/slow AHB, ICP, MCLK, OPE, and TFE clocks. Branch gates use `clk_branch2_ops` and halt registers. `cam_cc_camss_top_gdsc` models the single top power domain. `cam_cc_sm4450_resets` maps reset IDs to BCR offsets. `cam_cc_sm4450_probe()` configures all five PLLs and registers the descriptor.

Control flow: the platform driver binds to `qcom,sm4450-camcc`. Probe maps the CAM_CC MMIO range with `qcom_cc_map()`, configures PLLs using `clk_lucid_evo_pll_configure()` and `clk_rivian_evo_pll_configure()`, then calls `qcom_cc_really_probe()`. After registration, the clock framework handles rate requests by selecting the RCG entry, parent source, and divider. Most RCGs use `clk_rcg2_shared_ops`, reflecting a design where camera RCGs are shared and may need coordinated parent switching during disable.

State and persistence behavior: state is hardware register state only. Static tables define legal rates, mux values, enable registers, reset registers, and the descriptor arrays. The top GDSC at `0x14004` includes wait values and `POLL_CFG_GDSCR | RETAIN_FF_ENABLE`; it can retain flip-flop state across power collapse. Reset state is exposed through `qcom_reset_map` offsets and managed by the common reset support. No runtime PM state is explicitly acquired in this file.

Dependencies/integration points: depends on `dt-bindings/clock/qcom,sm4450-camcc.h`, Linux CCF/regmap/platform infrastructure, Qualcomm clock helpers, `gdsc.h`, and `reset.h`. Camera and media drivers consume the named clock IDs, reset IDs, and the `CAM_CC_CAMSS_TOP_GDSC` power domain from device tree. The regmap maximum is `0x16024`, matching the highest CRE/reset area used by the descriptors.

Risks: SM4450 has a dense reset map and multiple PLL types, so using the wrong configure helper or PLL register type would produce bad rates. MCLK entries depend on PLL2 main/even parents and fractional M/N settings, making sensor-clock accuracy sensitive to table mistakes. Several branch clocks use `BRANCH_HALT_DELAY` or regular halt polling; wrong halt policy can create false probe/runtime failures. Since only a top GDSC is exposed, consumers that expect per-block GDSCs must align with the binding. Reset offsets are hand-coded and can affect unrelated camera blocks if incorrect.

Test signals: compile coverage should include the SM4450 CAMCC object and binding header consistency. Runtime checks include probe on a `qcom,sm4450-camcc` node, successful reset controller registration, `clk_summary` rates matching BPS/OPE/TFE/MCLK tables, camera sensor MCLK measurement for 19.2/24/64 MHz paths, TFE/OPE/BPS enable-disable cycles without halt timeouts, and GDSC retention behavior during camera suspend/resume.

## sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm6350.c

Purpose: implements the SM6350 camera clock controller. It exposes camera clocks and GDSCs for BPS, IPE 0, IFE 0/1/2/lite, JPEG, LRME, ICP, CCI 0/1, CAMNOC AXI, CSIPHY, CSI timers, MCLK0-4, CPAS/core AHB, and system timer paths.

Important APIs/types/functions: the clock tree uses Fabia PLL0, PLL1, and PLL3 plus Agera PLL2. `camcc_pll2_out_early` is a fixed-factor half-rate hardware clock, while `camcc_pll2_out_main` is an Agera postdiv registered as a `clk_regmap`. Ten parent maps tie XO, PLL0 main/even, PLL1 main/even, PLL2 early/main, and PLL3 main to RCG mux values. RCG frequency tables cover the major camera engines: BPS, IFE, IFE lite, IPE, JPEG, LRME, ICP, CPHY, CCI, MCLKs, fast AHB, and slow AHB. Branch clocks expose the individual enable bits and halt polling registers. `camcc_sm6350_hws` registers the non-regmap fixed-factor early clock, `camcc_sm6350_clocks` registers regmap clocks, and `camcc_sm6350_gdscs` registers six GDSCs.

Control flow: the platform driver matches `qcom,sm6350-camcc`. Probe maps MMIO with `qcom_cc_map()`, programs PLL0/1/3 with `clk_fabia_pll_configure()`, programs PLL2 with `clk_agera_pll_configure()`, and hands the descriptor to `qcom_cc_really_probe()`. Clock rate changes are delegated to CCF RCG and branch ops. Most RCGs use regular `clk_rcg2_ops`; only selected high-performance engine clocks set `CLK_SET_RATE_PARENT`, so parent PLL retuning is limited to paths that need it.

State and persistence behavior: all persistent state is encoded in static tables or hardware registers. The driver writes PLL configuration and later enables/disables branch gates and GDSCs through regmap. BPS and IPE0 GDSCs are marked `VOTABLE` and parented to `titan_top_gdsc`; IFE0/1/2 are also parented to top but without `VOTABLE`; the top GDSC provides the root domain. GDSCs include enable/rest/disable wait values, so power-domain transitions depend on hardware polling rather than software-maintained state.

Dependencies/integration points: depends on `dt-bindings/clock/qcom,sm6350-camcc.h`, Linux CCF, regmap, platform devices, Qualcomm PLL/RCG/branch/GDSC helpers, and the camera subsystem's device-tree consumers. The descriptor includes both `.clk_hws` and `.clks`, which is important because fixed-factor hardware clocks are not `clk_regmap` entries. The regmap maximum is `0x16000`.

Risks: the split between `clk_hw` fixed-factor clocks and `clk_regmap` clocks must match the binding IDs; otherwise consumers may receive missing or wrong parents. MCLK0-4 derive from PLL2 early with fractional rates, so sensor-clock precision is sensitive to the M/N and parent-map entries. Votable GDSCs require correct power-domain voting semantics. SM6350 exposes IFE2 and MCLK4, so table omissions can break multi-camera pipelines. Overly narrow `CLK_SET_RATE_PARENT` use can prevent requested rates; overly broad use can disturb shared PLL users.

Test signals: expected tests include kernel build coverage, device-tree binding validation for `qcom,sm6350-camcc`, probe without regmap or GDSC errors, `clk_summary` visibility for fixed and regmap clocks including `CAMCC_PLL2_OUT_EARLY`, sensor MCLK rate checks through all five MCLKs, camera stream tests using IFE0/1/2 and IFE lite, and suspend/resume or power-collapse tests validating GDSC parent-child behavior.

## sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm7150.c

Purpose: implements the SM7150 camera clock controller. It registers CAMCC PLLs, fixed-factor/postdiv outputs, RCGs, branch gates, and GDSCs for BPS, CAMNOC, CCI, CSIPHY/CSI timers, FD core, ICP, IFE 0/1/lite, IPE 0/1, JPEG, LRME, MCLK0-3, sleep/XO support, and AHB/system clocks.

Important APIs/types/functions: SM7150 uses Fabia PLL0/1/3/4 plus Agera PLL2. Several PLL outputs are fixed-factor `clk_fixed_factor` clocks: PLL0 even/odd, PLL1 even, PLL2 early, PLL3 even, and PLL4 even; PLL2 also has AUX and MAIN postdiv outputs. Parent maps cover XO, always-on XO, chip sleep clock, PLL outputs, and the special PLL2 AUX path. RCGs include shared ops for BPS, CAMNOC, FD, ICP, IFE, IPE, JPEG, LRME, and slow AHB paths, while timer/MCLK/sleep/XO sources use regular ops. `camcc_sm7150_hws` registers fixed-factor outputs separately from `camcc_sm7150_clocks`. `camcc_sm7150_probe()` configures PLLs, forces the GDSC clock on, and registers the descriptor.

Control flow: device-tree matching on `qcom,sm7150-camcc` invokes probe. Probe maps registers, configures Fabia/Agera PLLs, calls `qcom_branch_set_clk_en(regmap, 0xc1a0)` to keep `CAMCC_GDSC_CLK` on, and then calls `qcom_cc_really_probe()`. From that point, CCF rate-setting follows frequency tables and branch enable calls poll halt registers. Power-domain requests flow through the GDSC framework with `camcc_titan_top_gdsc` as parent for the block domains.

State and persistence behavior: no filesystem or driver-private persistent state exists. Static tables define PLL configuration, rate tables, parent maps, branch registers, GDSC registers, and descriptor arrays. Hardware stores the live PLL, RCG, branch, and GDSC state. BPS and IPE domains use `HW_CTRL | POLL_CFG_GDSCR`; IFE domains and top use `POLL_CFG_GDSCR`. The always-on GDSC clock write at probe intentionally leaves a hardware branch enabled for correct power-domain operation.

Dependencies/integration points: depends on `dt-bindings/clock/qcom,sm7150-camcc.h`, CCF, regmap, platform devices, Qualcomm Fabia/Agera PLL support, branch/RCG helpers, and GDSC support. It integrates with camera/media nodes through clock IDs and GDSC power domains. The descriptor spans `.clk_hws`, `.clks`, and `.gdscs`; the regmap maximum is `0xd024`.

Risks: the probe configures `camcc_pll4` using `camcc_pll3_config`, which appears intentional only if PLL3 and PLL4 share identical parameters; future edits must not assume the local variable name is harmless. The always-on `CAMCC_GDSC_CLK` branch is critical for GDSC operation. Parent-map mistakes around `DT_BI_TCXO_AO`, chip sleep, and PLL2 AUX can break low-power and MCLK paths. Shared RCGs must safely transition during disable or camera memory shutdown can fail. Split `clk_hw` and `clk_regmap` arrays must preserve binding indices.

Test signals: build and dt-binding validation for `qcom,sm7150-camcc`; probe logs without PLL, regmap, or GDSC failures; debugfs confirmation that `CAMCC_GDSC_CLK` remains enabled; camera streaming through IFE/IPE/BPS/JPEG/LRME; sleep/XO clock behavior across suspend; MCLK measurement for sensor rates; and GDSC transition tests for BPS, IFE0/1, IPE0/1, and titan top.

## sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm8150.c

Purpose: implements the SM8150 camera clock controller. It exposes the CAM_CC clock tree, resets, and GDSCs for BPS, CAMNOC, CCI 0/1, CPAS, CSI PHYs and timers, FD, ICP, IFE 0/1, IFE lite 0/1, IPE 0/1, JPEG, LRME, MCLK0-3, slow AHB, and PLL outputs.

Important APIs/types/functions: this driver uses Trion PLLs for PLL0/1/3/4 and a Regera PLL for PLL2. It defines VCO tables, `alpha_pll_config` data, even/odd/main postdivs, and five parent maps. RCG tables cover BPS, CAMNOC AXI, CCI, CPHY, CSI timers, fast/slow AHB, FD core, ICP, IFE/IFE lite, IPE, JPEG, LRME, and MCLK. Branch clocks use `clk_branch2_ops` with halt registers; most high-level clocks set `CLK_SET_RATE_PARENT`. GDSCs cover titan top plus BPS, IFE0/1, and IPE0/1. `cam_cc_sm8150_resets` maps many camera block reset IDs. `cam_cc_sm8150_probe()` includes runtime-PM handling, PLL setup, an always-on GDSC clock, descriptor registration, and PM release.

Control flow: the platform driver matches `qcom,sm8150-camcc`. Probe enables runtime PM, resumes the device, maps CAM_CC registers, configures PLL0/1/3/4 with `clk_trion_pll_configure()` and PLL2 with `clk_regera_pll_configure()`, keeps `cam_cc_gdsc_clk` enabled through `qcom_branch_set_clk_en(regmap, 0xc1e4)`, registers clocks/resets/GDSCs through `qcom_cc_really_probe()`, then drops the runtime-PM reference. Normal clock control is then handled by CCF and the Qualcomm reset/GDSC frameworks.

State and persistence behavior: static tables define the entire topology and binding-visible ID arrays. Runtime hardware state includes PLL configuration, RCG choices, branch enable bits, reset lines, and GDSC state. The driver explicitly holds the device active during probe using runtime PM because register access depends on the device being powered. All GDSCs use `POLL_CFG_GDSCR` and are parented under `titan_top_gdsc` where appropriate. Resets are volatile register writes through the common reset controller.

Dependencies/integration points: depends on `<linux/pm_runtime.h>`, CCF, regmap, platform infrastructure, `dt-bindings/clock/qcom,camcc-sm8150.h`, Qualcomm Trion/Regera PLL helpers, branch/RCG helpers, reset support, and GDSC support. Camera/media drivers reference the clocks, resets, and power domains from SM8150 device trees. The regmap maximum is `0xe004`, which must cover all clock, reset, and GDSC offsets.

Risks: runtime-PM error handling is part of probe correctness; failed mapping must release the PM reference, and later register access assumes clocks/power are available. The always-on GDSC branch at `0xc1e4` is necessary for power-domain control. Reset offsets touch many camera blocks and can create broad failures if shifted. Trion/Regera PLL configuration fields are detailed and hardware-specific; wrong VCO/config values can destabilize rates. Shared RCGs and `CLK_SET_RATE_PARENT` affect multiple camera consumers, so parent retuning needs real hardware validation.

Test signals: build coverage with PM runtime enabled, dt-binding validation for `qcom,sm8150-camcc`, successful probe with balanced runtime-PM usage, reset-controller registration, `clk_summary` rates for Trion/Regera-derived outputs, confirmation that `cam_cc_gdsc_clk` is enabled, camera bring-up across IFE/IFE lite/IPE/BPS/JPEG/LRME, reset toggling for camera blocks, and suspend/resume tests that verify GDSCs and runtime PM interact correctly.
