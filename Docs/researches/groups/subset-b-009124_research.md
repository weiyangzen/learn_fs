# sources/sync-backup/git-annex/static/js/jquery.full.js

Purpose: vendored jQuery JavaScript Library v2.1.0, including Sizzle v1.10.16, packaged as a full browser utility layer for the git-annex static web interface. It provides the global `$`/`jQuery` function, CSS selector querying, DOM traversal/manipulation, events, data storage, queues, effects, form helpers, Ajax transports, JSONP/script loading, offsets, and dimensions.

Important APIs/types/functions: the file is wrapped in a UMD-style factory that exports `module.exports` for CommonJS environments with or without a supplied `window`, otherwise installs globals unless `noGlobal` is passed. Public core APIs include `jQuery()`, `jQuery.fn.init`, `jQuery.extend`, `jQuery.fn.extend`, `each`, `map`, `grep`, `merge`, `makeArray`, `proxy`, `type`, `isFunction`, `isArray`, `isPlainObject`, `isWindow`, `isNumeric`, `camelCase`, `globalEval`, and `noConflict`. Sizzle provides `jQuery.find`, `jQuery.expr`, `jQuery.unique`, `jQuery.text`, `jQuery.isXMLDoc`, and `jQuery.contains`, with internals such as `tokenize`, `compile`, `select`, `matcherFromTokens`, and `matcherFromGroupMatchers`. Collection methods cover `find`, `filter`, `not`, `is`, traversal (`parent`, `parents`, `closest`, `children`, `siblings`, `next*`, `prev*`, `contents`, `add`, `addBack`, `index`), callback primitives (`jQuery.Callbacks`, `jQuery.Deferred`, `jQuery.when`, `ready`), data APIs (`jQuery.data`, `removeData`, `_data`, `Data`), queues (`queue`, `dequeue`, `_queueHooks`, `.promise()`), events (`jQuery.event.add/remove/trigger/dispatch/handlers/fix/simulate`, `jQuery.Event`, `.on/.one/.off/.trigger/.triggerHandler`, shorthands, `bind/delegate/hover`), DOM APIs (`text`, `html`, `append`, `prepend`, `before`, `after`, `remove`, `empty`, `clone`, `replaceWith`, `detach`, `domManip`, `buildFragment`, `cleanData`, `parseHTML`), CSS/effects (`css`, `style`, `cssHooks`, `show/hide/toggle`, `Tween`, `Animation`, `animate`, `stop`, `finish`, `delay`, `fade*`, `slide*`), attributes/properties/classes/values (`attr`, `removeAttr`, `prop`, `removeProp`, `addClass`, `removeClass`, `toggleClass`, `hasClass`, `val`), Ajax (`ajax`, `ajaxSetup`, `ajaxPrefilter`, `ajaxTransport`, `get`, `post`, `getJSON`, `getScript`, `param`, `serialize`, `serializeArray`, `.load`), and layout (`offset`, `position`, `offsetParent`, `scrollTop`, `scrollLeft`, dimensions).

Control flow: load begins by selecting CommonJS export versus browser factory execution, then initializes private array method aliases, feature support storage, the main `jQuery` constructor, and the prototype stack API. Core extension utilities are defined first because later modules use `extend`, `each`, type detection, `camelCase`, and `access`. Sizzle is initialized next: it computes browser selector support with temporary DOM nodes, defines selector regexes, fast paths simple ID/tag/class selectors, uses `querySelectorAll` and native `matchesSelector` when safe, and falls back to tokenization, matcher compilation, combinator traversal, and unique sorting. jQuery then wires Sizzle into public filter/traversal methods and defines `init` so `$(html)`, `$("#id")`, `$(selector, context)`, DOM elements, arraylikes, and ready callbacks all normalize into jQuery collections. Callback and Deferred primitives are created before DOM ready and Ajax so asynchronous modules can share the same resolution model. The data module creates two `Data` stores, `data_priv` for framework state and `data_user` for public `.data()`, using expando IDs on accepted owners. The event module stores event tables in private data, builds a single per-element native handler, dispatches delegated handlers before direct handlers, normalizes native events through fix hooks, and uses special event definitions for focus/blur, click, beforeunload, mouseenter/leave, and focusin/focusout simulation. DOM manipulation parses fragments with tag-specific wrappers, copies event/data state when requested, cleans data before removal, and evaluates scripts only when inserted and not previously marked. CSS and effects compute browser support, normalize vendor property names and box models, manage display restoration in private data, and drive animations through `jQuery.timers` plus `setInterval`. Ajax builds normalized settings, applies prefilters, chooses transports, handles response type selection/conversion, updates Deferred state, fires global events, and exposes XHR, script, and JSONP transports. The file ends by registering named AMD module `jquery`, exposing globals, and returning `jQuery`.

State and persistence behavior: there is no durable persistence; state is in-memory browser process state. Persistent-looking state is attached to DOM nodes or objects via jQuery expando keys and module caches. `data_priv` stores framework internals including events, queue hooks, `olddisplay`, animation show/hide state, script global-evaluation flags, and focusin attachment counts. `data_user` stores `.data()` values and lazily imports `data-*` attributes once per element through the private `hasDataAttrs` flag. Sizzle caches tokenized and compiled selectors with a bounded cache length of 50 and stores temporary traversal caches on elements under a Sizzle expando for non-XML selector runs. `jQuery.Callbacks` retains `memory`, `fired`, `firing`, and `stack` state depending on options. `Deferred` stores pending/resolved/rejected state and callback lists. Ajax stores global counters (`jQuery.active`), `lastModified` and `etag` maps, JSONP callback reuse in `oldCallbacks`, and XHR unload abort callbacks. Effects store active timer functions in `jQuery.timers`, queue arrays under private data keys, and old display values used by `.show()`/`.hide()`. DOM cleanup paths are important because data/event expando caches otherwise persist after elements are removed.

Dependencies/integration: depends on a real browser-like `window` with `document`, DOM creation, `getComputedStyle`, events, `XMLHttpRequest`, `DOMParser`, timers, location, and optionally AMD/CommonJS loaders. The bundled Sizzle engine is an internal dependency and is exposed through jQuery selector APIs. jQuery UI modules in the same directory depend on this file for `$`, `$.fn`, selectors, data, events, CSS, dimensions, and plugin extension points. The static git-annex frontend likely treats this as infrastructure rather than application logic; replacing it impacts all legacy UI code using jQuery and jQuery UI.

Risks: jQuery 2.1.0 is old and intentionally does not support older IE versions that jQuery 1.x supported, while still containing many old browser workarounds. Security-sensitive areas include HTML string parsing/insertion, `.html()`, script evaluation through `globalEval`, script-tag Ajax transport, JSONP global callback installation, and `$.parseJSON`/`$.parseXML` error handling. Selector and DOM-manipulation paths trust caller-provided selectors and HTML strings; untrusted input must not be passed directly into `$()`, `.html()`, `.append()`, `.load()`, or JSONP/script Ajax. Event/data caches can leak if callers remove nodes outside jQuery without cleanup. Ajax behavior depends on same-origin/CORS browser policy, but JSONP and script transports bypass normal XHR response semantics. Effects use interval timers rather than requestAnimationFrame, so hidden tabs and heavy animations can be inefficient. Because this is vendored third-party code, local modifications are risky unless coordinated with upstream jQuery behavior and compatibility tests.

Test signals: expected tests are broad browser compatibility and integration tests rather than narrow unit tests in this repository. Useful signals include loading the git-annex web UI without console errors, selector queries matching expected DOM nodes, event delegation and teardown working after dynamic page updates, Ajax success/error/global events firing in the documented order, `.data()` reading `data-*` attributes once, `remove/empty/html` cleaning handlers to avoid leaks, form serialization matching expected query strings, CSS/dimension calculations matching layout in supported browsers, and animations resolving queues/promises. For this vendored file, checksum/version checks against upstream jQuery 2.1.0 and Sizzle 1.10.16 are also meaningful if the intent is to keep an unmodified third-party dependency.

# sources/sync-backup/git-annex/static/js/jquery.ui.core.js

Purpose: vendored jQuery UI Core 1.10.4 support module. It establishes the `$.ui` namespace, publishes shared constants, adds small jQuery plugins/selectors/back-compat shims, and exposes deprecated but still-used helpers that other jQuery UI widgets in the git-annex static UI can build on.

Important APIs/types/functions: `$.ui.version` is `"1.10.4"`, and `$.ui.keyCode` maps common keyboard key names to numeric codes. `$.fn.focus(delay, fn)` wraps jQuery focus to optionally delay focus and invoke a callback. `$.fn.scrollParent()` finds the nearest scrollable ancestor, with special handling for absolute/fixed positioning and IE. `$.fn.zIndex([value])` gets or sets z-index and walks positioned ancestors when reading. `$.fn.uniqueId()` assigns generated `ui-id-N` IDs, and `$.fn.removeUniqueId()` removes only IDs matching that generated pattern. Internal helpers `focusable(element, isTabIndexNotNaN)` and `visible(element)` support custom selectors. `$.expr[":"].data`, `focusable`, and `tabbable` add selectors used by widgets. Compatibility patches add size setter overloads for old jQuery `innerWidth/innerHeight/outerWidth/outerHeight`, add `$.fn.addBack` for jQuery before 1.8, and wrap `$.fn.removeData` for jQuery 1.6.1/1.6.2 dash-key behavior. Deprecated selection helpers include `disableSelection` and `enableSelection`. Deprecated `$.ui.plugin.add/call` allows option-gated plugin callbacks. `$.ui.hasScroll(el, a)` probes scrollability.

Control flow: the module runs immediately in an IIFE with `jQuery` passed as `$`. It initializes private counters and ID regexes, ensures `$.ui` already exists or creates it, then extends `$.ui` with version and key codes. It extends `$.fn` with focus, scroll parent, z-index, and generated-ID helpers. It defines `focusable`/`visible`, then installs Sizzle/jQuery expression pseudos, using `$.expr.createPseudo` when present and falling back to the older selector signature. After the core APIs, it conditionally applies backward-compatibility shims by probing the loaded jQuery version behavior. Finally it records the deprecated `$.ui.ie` flag from the user agent, detects `selectstart`, installs selection-disabling plugins, defines the deprecated plugin bridge, and adds `hasScroll`.

State and persistence behavior: module state is limited to the closure-local `uuid` counter, the generated-ID regex, `$.ui` namespace fields, and methods attached to `$.fn`/`$.expr`. `uniqueId()` mutates DOM elements by assigning an `id`; `removeUniqueId()` removes only generated IDs, preserving application IDs. `disableSelection()` attaches namespaced event handlers to elements; `enableSelection()` removes them. The old size setters and `removeData` wrapper mutate jQuery prototype methods when compatibility probes indicate they are needed. `hasScroll()` temporarily writes `scrollTop` or `scrollLeft` to probe scrollability and then resets it to zero, which can disturb existing scroll position in edge cases.

Dependencies/integration: depends on jQuery core, especially `$.extend`, `$.fn.extend`, selectors, `.parents()`, `.filter()`, `.eq()`, `.css()`, `.data()`, `.removeData()`, `.bind()`, `.unbind()`, and Sizzle pseudo extension points. Other jQuery UI modules depend on this file for `$.ui.keyCode`, `:focusable`, `:tabbable`, z-index/scroll helpers, selection disabling, and the deprecated plugin mechanism. It reads `navigator.userAgent` and `document.createElement`, so it assumes a browser DOM.

Risks: this is legacy jQuery UI code with browser sniffing (`$.ui.ie`) and shims for jQuery versions older than the bundled `jquery.full.js` 2.1.0. The delayed focus overload changes the semantics of `.focus()` when the first argument is numeric, which can surprise code expecting only native focus behavior. `scrollParent()` and `zIndex()` depend on CSS state and may produce different answers under modern layout contexts not covered by jQuery UI 1.10.4. `disableSelection()` prevents default `selectstart`/`mousedown`, which can interfere with accessibility and text selection if applied too broadly. The deprecated plugin API silently skips detached or fragment-contained elements, so plugin callbacks may not run in off-DOM rendering flows.

Test signals: load order should expose `$.ui.version`, key codes, and selectors after jQuery loads. Useful checks include `:focusable`/`:tabbable` results for disabled controls, anchors, maps, hidden ancestors, and tabindex values; `scrollParent()` for absolute, fixed, and normal elements inside scroll containers; `zIndex()` through positioned ancestors; `uniqueId()`/`removeUniqueId()` preserving non-generated IDs; `disableSelection()` preventing selection and `enableSelection()` restoring it; and jQuery UI widgets using `$.ui.plugin.call` still invoking option-enabled plugin callbacks.

# sources/sync-backup/git-annex/static/js/jquery.ui.mouse.js

Purpose: vendored jQuery UI Mouse 1.10.4 interaction base widget. It provides the shared mouse gesture lifecycle used by draggable, resizable, selectable, sortable, and similar widgets: capture on left-button mousedown, honor cancel/distance/delay thresholds, bind document-level move/up handlers during a gesture, and call overridable lifecycle hooks.

Important APIs/types/functions: defines `$.widget("ui.mouse", { ... })`, so it depends on jQuery UI Widget Factory. Public widget options are `cancel` (`"input,textarea,button,select,option"`), `distance` (`1`), and `delay` (`0`). Core methods are `_mouseInit`, `_mouseDestroy`, `_mouseDown`, `_mouseMove`, `_mouseUp`, `_mouseDistanceMet`, and `_mouseDelayMet`. Extension hooks intended for subclass overrides are `_mouseStart`, `_mouseDrag`, `_mouseStop`, and `_mouseCapture`. Closure-local `mouseHandled` prevents multiple mouse widgets from simultaneously claiming a single mousedown; a document `mouseup` handler resets it. The module uses `$.data(target, widgetName + ".preventClickEvent", true)` to suppress click events generated after a drag.

Control flow: when a concrete widget calls `_mouseInit()`, the widget element gets namespaced `mousedown.<widgetName>` and `click.<widgetName>` handlers. The click handler checks per-target jQuery data and stops immediate propagation for synthetic post-drag clicks. `_mouseDown()` exits if another mouse widget already handled the press, cleans up a missed previous mouseup, stores `_mouseDownEvent`, requires the left button, rejects events inside the cancel selector, and calls `_mouseCapture(event)` for subclass-specific eligibility. It starts a delay timer if configured, optionally calls `_mouseStart()` immediately if both distance and delay thresholds already pass, clears stale click-prevention data, creates bound document delegates for mousemove/mouseup, binds them, prevents the original event default, and sets `mouseHandled`. `_mouseMove()` first handles old IE missed-mouseup cases, then either calls `_mouseDrag()` for an active gesture or, when thresholds pass, calls `_mouseStart(_mouseDownEvent, event)` and immediately drags or cancels via `_mouseUp()`. `_mouseUp()` unbinds document delegates, records post-drag click suppression when mouseup targets the original mousedown target, calls `_mouseStop()`, and returns false. `_mouseDestroy()` removes element handlers and any active document delegates.

State and persistence behavior: gesture state is per widget instance and stored as object properties: `started`, `_mouseStarted`, `_mouseDownEvent`, `mouseDelayMet`, `_mouseDelayTimer`, `_mouseMoveDelegate`, and `_mouseUpDelegate`. Cross-instance state is the closure-local `mouseHandled`, reset on every document mouseup. Temporary click-suppression state is stored through jQuery data on the original event target using a key derived from the widget name. Document-level handlers persist for the duration of a gesture and are namespaced by `widgetName`; destruction attempts to remove them if delegates exist. No durable storage is used.

Dependencies/integration: depends on jQuery, `jquery.ui.widget.js`, and, for the old IE branch, `$.ui.ie` from jQuery UI Core. It uses jQuery event binding/unbinding, closest-selector matching, jQuery data, and widget instance properties such as `this.element`, `this.widgetName`, and `this.options`. Concrete jQuery UI interactions subclass this widget by overriding capture/start/drag/stop hooks and by calling `_mouseInit()` during widget initialization and `_mouseDestroy()` during teardown.

Risks: only mouse events are supported; touch/pointer events are absent in this 1.10.4 base. The shared `mouseHandled` means overlapping widgets rely on document mouseup for reset; missed or synthetic event sequences can block another handler until mouseup occurs. `_mouseDestroy()` notes a TODO that destroying one mouse instance could affect others because document handlers are namespaced only by widget name, not unique instance. Delay timers are not explicitly cleared on destroy or mouseup in this file, so subclasses should avoid assuming timer cleanup beyond the boolean gate. `event.preventDefault()` on mousedown prevents text selection and native dragging once a widget captures. The click-suppression key is attached to the event target and must be removed by the click handler; unusual event ordering can leave stale data briefly. Old IE missed-mouseup handling depends on `$.ui.ie` browser sniffing.

Test signals: subclass-based tests should verify that `_mouseCapture` can veto gestures, non-left buttons and cancel-selector descendants are ignored, distance and delay thresholds gate `_mouseStart`, `_mouseDrag` fires on moves after start, `_mouseStop` fires exactly once on mouseup, document handlers are removed after mouseup/destroy, post-drag click events on the original target are suppressed once, multiple mouse widgets do not start from one mousedown, and old-IE-style mousemove with no button triggers cleanup. Integration tests for draggable/resizable/sortable cover most behavior indirectly.
