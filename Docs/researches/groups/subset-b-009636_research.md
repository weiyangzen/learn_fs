# sources/user-network-fs/impacket/impacket/smb3.py

## Purpose
`smb3.py` is the low-level SMB2 and SMB3 client implementation used by Impacket. It owns NetBIOS transport setup, dialect negotiation, NTLM and Kerberos session setup, signing and encryption key derivation, SMB packet send/receive handling, tree connections, file opens, reads/writes, directory enumeration, IOCTLs, file metadata operations, named-pipe helpers, and SMB1 compatibility aliases expected by older Impacket transport code. The module follows the MS-SMB2 state-machine vocabulary closely through mutable `Connection`, `Session`, `TreeConnect`, `File`, and `Open` dictionaries.

## Important APIs, Types, and Functions
The module defines state templates `TREE_CONNECT`, `FILE`, `OPEN`, `REQUEST`, and `CHANNEL`; `WIN_VERSIONS` for NTLM challenge version decoding; `SessionError`; and the main `SMB3` class. Construction initializes the connection/session dictionaries, optional strict hostname validation, credentials cache fields, and a `NetBIOSTCPSession` or supplied existing NetBIOS session. `negotiateSession()` advertises SMB 2.0.2 through 3.1.1, emits SMB 3.1.1 negotiate contexts for preauth integrity and encryption capabilities, records server limits/capabilities, switches `self.SMB_PACKET` from `SMB2Packet` to `SMB3Packet` for SMB3 dialects, and processes negotiate contexts through `processContextList()`.

`login()` performs SPNEGO-wrapped NTLMSSP, parses AV pairs into server identity fields, optionally validates reported hostnames, records Windows version data, computes session/signing/application/encryption/decryption keys, and enables encryption when the server supports SMB3 encryption and the session is not anonymous or guest. `kerberosLogin()` builds a Kerberos AP-REQ inside SPNEGO, optionally handles AP-REP mutual authentication, and derives the same SMB3 key material. `sendSMB()` assigns message IDs and credits, signs packets when required, maintains SMB 3.1.1 preauth hashes, wraps encrypted packets in `SMB2_TRANSFORM_HEADER`, and writes to NetBIOS. `recvSMB()` receives clear or encrypted responses, handles `STATUS_PENDING`, tracks out-of-order responses by message ID, and updates credits.

File and share APIs include `connectTree()`, `disconnectTree()`, `create()`, `close()`, `read()`, `write()`, `queryDirectory()`, `ioctl()`, `flush()`, `lock()`, `queryInfo()`, `setInfo()`, `rename()`, `listPath()`, `mkdir()`, `rmdir()`, `remove()`, `retrieveFile()`, `storeFile()`, and `waitNamedPipe()`. Compatibility aliases expose SMB1-style names such as `connect_tree`, `tree_connect_andx`, `read_andx`, `write_andx`, `nt_create_andx`, `stor_file`, `retr_file`, and named-pipe transact helpers.

## Control Flow
A normal SMB3 path starts in `__init__()`, which opens or reuses a NetBIOS session and negotiates the dialect. Negotiation sends an SMB2 NEGOTIATE unless a wildcard negotiation response was already supplied by `smbconnection.py`; the response seeds connection limits, signing requirements, dialect, encryption support, and SMB3 feature flags. Authentication then sends one or more SMB2 SESSION_SETUP requests. NTLM uses a type 1 request, parses `STATUS_MORE_PROCESSING_REQUIRED`, emits type 3, then finalizes keys after `STATUS_SUCCESS`. Kerberos sends AP-REQ directly and finalizes on success, with an optional AP-REP branch when mutual auth is requested.

After authentication, callers connect to a share through `connectTree()`, which normalizes the share name, constructs a UNC path from the server IP, records DFS/CA/encryption/scale-out properties, and stores the same tree entry under both share name and tree id. `create()` normalizes paths, sets DFS flags when needed, creates lease bookkeeping in `GlobalFileTable`, builds an SMB2 CREATE with optional create contexts and 8-byte alignment, and records returned file ids in `_Session['OpenTable']`. IO methods validate tree and open tables before constructing SMB2 READ, WRITE, QUERY_DIRECTORY, IOCTL, QUERY_INFO, and SET_INFO packets. Higher-level helpers compose these primitives: `listPath()` opens a directory and loops over `queryDirectory()` until `STATUS_NO_MORE_FILES`; `retrieveFile()` queries size and repeatedly reads chunks into a callback; `storeFile()` repeatedly calls a producer callback and writes chunks; delete and rename operations open handles and send set-info or delete-on-close requests.

## State and Persistence Behavior
The object is stateful and connection-oriented. `_Connection` stores transport and negotiated capability state: outstanding responses, sequence window, max sizes, server GUID, security modes, dialect, capability booleans, preauth hash material, selected cipher, server name/IP, and GSS options. `_Session` stores current SMB session state: session id, tree table, session/signing/application/encryption/decryption keys, open table, session flags, server identity strings, preauth hash state, and signing activation. `TreeConnectTable` is keyed by both tree id and share name, with `NumberOfUses` acting as a lightweight reference count. `OpenTable` is keyed by raw `FileID` bytes; `GlobalFileTable` is keyed by normalized path and stores lease state.

There is no durable local persistence. Credentials and Kerberos material are retained in private fields for `getCredentials()` and reconnect-style callers in the wrapper. Network state persists until `logoff()` or `close_session()` clears selected session fields and closes NetBIOS. Some teardown paths clean only local tables; for example `disconnectTree()` removes associated opens from `OpenTable`, and `close()` removes `GlobalFileTable` and `OpenTable` entries for one file.

## Dependencies and Integration Points
The implementation depends on `impacket.nmb` for NetBIOS sessions, `impacket.smb3structs` for all SMB2/3 constants and `Structure` encoders, `impacket.ntlm` and `impacket.spnego` for NTLM/SPNEGO negotiation, `impacket.krb5` modules for Kerberos, `impacket.crypto` for AES-CMAC and KDF counter mode, `Cryptodome.Cipher.AES` for AES-CCM packet encryption, `impacket.nt_errors` for status handling, and `impacket.uuid` for lease keys. It integrates upward with `smbconnection.py`, DCE/RPC SMB transports, ntlmrelayx clients, secretsdump, and any code expecting SMB1-compatible method names on an SMB2/3 object.

## Risks and Edge Cases
Encrypted response integrity is not verified because `cipher.verify(transformHeader['Signature'])` is commented out in both encrypted receive paths. The code advertises/uses AES-CCM only and does not implement AES-GCM or compression despite constants existing in `smb3structs.py`. Multi-channel, persistent handles, resilient operation buckets, oplock break handling, create-context processing, validate-negotiate, and several SMB1 compatibility paths are marked TODO or incomplete. `read()` and `write()` are recursive for multi-part transfers and explicitly warn that large direct calls can exhaust memory; higher-level helpers chunk manually and are safer. `create()` has a directory-leasing branch where `parentDir` can be referenced before assignment for shallow paths when directory leasing is enabled. SMB3 open bookkeeping incorrectly assigns `DesiredAccess`, `ShareMode`, `CreateOptions`, `FileAttributes`, and `CreateDisposition` from `oplockLevel`, which weakens local state fidelity for any later feature depending on those fields. Signing is applied to outbound packets, but response signature verification is not implemented here. Out-of-order response handling is simple recursion over `recvSMB(packetID)` and can grow stack depth under unusual response ordering. Password-protected share parameters are present on several high-level methods but are TODO. Hostname validation only runs after NTLM AV pairs are parsed; Kerberos path does not populate the same NTLM-derived identity fields.

## Test Signals
Useful tests should exercise dialect negotiation for explicit SMB2.0.2, SMB2.1, SMB3.0, SMB3.0.2, and SMB3.1.1, including preauth hash updates and negotiate context parsing. Authentication coverage should include NTLM success, NTLM failure cleanup, guest/anonymous sessions disabling encryption, Kerberos with and without supplied TGT/TGS, Kerberos mutual authentication, signing-required servers, and strict hostname validation with present, absent, and mismatched AV hostnames. Transport tests should cover signing decisions for tree and session packets, encrypted send/receive, pending responses, out-of-order message ids, credit charge behavior for large reads/writes, and connection timeout context management. File-operation tests should cover tree reference counting, DFS flag setting, create contexts, open/close table cleanup, read/write chunking, directory enumeration until `STATUS_NO_MORE_FILES`, query/set info, rename/delete/mkdir/rmdir, snapshots through `@GMT-`, named-pipe wait/transceive, IOCTL no-answer mode, and invalid tree/file id errors. Security-sensitive tests should assert encrypted response tag verification behavior once fixed.

# sources/user-network-fs/impacket/impacket/smb3structs.py

## Purpose
`smb3structs.py` is the SMB2/SMB3 constants and wire-structure catalog for Impacket. It maps MS-SMB2 command numbers, flags, dialects, access masks, share flags, create options, IOCTL control codes, information classes, compression/encryption identifiers, and packet payload formats into Python constants and `impacket.structure.Structure` subclasses. The file has little business logic; its primary role is deterministic binary packing/unpacking for `smb3.py`, `smbconnection.py`, and higher-level SMB/DCE/RPC consumers.

## Important APIs, Types, and Functions
The top half defines protocol constants: SMB2 command ids, header flags, negotiate security modes and contexts, compression algorithms, global and share capabilities, dialect ids, session flags, share types, create oplock/lease values, impersonation levels, file attributes, share access flags, create dispositions/options, desired access masks, create context tags, IOCTL codes, query directory classes, change-notify filters, query-info classes, filesystem classes, security-information masks, and transform-header encryption ids.

`SMBPacketBase` provides shared packet behavior and `isValidAnswer()`, which raises `smb3.SessionError` when a response status differs from the expected status. `SMB2Packet`, `SMB3Packet`, `SMB2PacketAsync`, and `SMB3PacketAsync` model the 64-byte SMB2/3 sync and async headers. Request and response classes model every main operation used by `smb3.py`: `SMB2Negotiate`, `SMB311ContextData`, `SMB2Negotiate_Response`, `SMB2NegotiateContext`, `SMB2PreAuthIntegrityCapabilities`, `SMB2EncryptionCapabilities`, `SMB2CompressionCapabilities`, `SMB2SessionSetup`, `SMB2TreeConnect`, `SMB2Create`, `SMB2Create_Response`, `SMB2Close`, `SMB2Read`, `SMB2Write`, `SMB2Lock`, `SMB2Ioctl`, `SMB2QueryDirectory`, `SMB2ChangeNotify`, `SMB2QueryInfo`, and `SMB2SetInfo`.

Support structures include create contexts for leases, durable handles, timewarp/snapshot tokens, maximal access, allocation size, app instance id, and on-disk id; file information structures such as `FILE_BASIC_INFORMATION`, `FILE_STANDARD_INFORMATION`, `FILE_ALL_INFORMATION`, and `FILE_RENAME_INFORMATION_TYPE_2`; IOCTL payloads such as `FSCTL_PIPE_WAIT_STRUCTURE`, copy-chunk and hash structures, network interface info, snapshot arrays, resume keys, and mount-point reparse data; and transform/compression headers such as `SMB2_TRANSFORM_HEADER` and `SMB2_COMPRESSION_TRANSFORM_HEADER`.

## Control Flow
There is no standalone protocol flow. Control flow is mostly inside `Structure` field expressions. Many structures calculate offsets from the 64-byte SMB2 header plus structure sizes and alignment pads, then expose variable-length buffers through `_Field` length expressions. Constructors for request classes that carry variable buffers initialize `AlignPad` to an empty value for fresh outbound structures. `SMBPacketBase.isValidAnswer()` is the main behavioral hook: response consumers call it after `recvSMB()`, and it converts raw NT status mismatches into `smb3.SessionError` with the original packet attached.

## State and Persistence Behavior
Instances of these classes are transient packet encoders/decoders. They hold raw packet fields and any `rawData` inherited from `Structure`, but they do not persist state outside their object lifetime. Module-level constants are immutable by convention and imported broadly. Dynamic field definitions persist as class-level `structure` tuples, which means correctness of offsets, lengths, and defaults is shared across all SMB3 operations.

## Dependencies and Integration Points
The only direct dependency is `impacket.structure.Structure`, with a lazy import of `.smb3` inside `SMBPacketBase.isValidAnswer()` to avoid a top-level cycle. The module is consumed heavily by `smb3.py` through wildcard import and selectively by `smbconnection.py` for dialect constants, file options, IOCTLs, snapshot arrays, and reparse-point structures. Other Impacket modules can use these classes to build SMB2/3 create contexts, file information blobs, or IOCTL payloads without depending on the full `SMB3` client.

## Risks and Edge Cases
Because field offsets are encoded as string expressions, errors tend to appear at runtime while packing or parsing specific packets. Several structures are partial or marked TODO, including security descriptor create context support and quota details. Some constants and classes exist for features not implemented in `smb3.py`, such as compression transforms, AES-GCM, oplock break handling, durable handle flows, and multi-channel related details. `SMBPacketBase.addCommand()` is intentionally unimplemented, so compound request support is not available through these packet classes. There are compatibility rough edges from mixed string and bytes defaults, for example empty-string defaults in binary fields and the typo-like `ReparseDataLenght` field in `SMB2ErrorSymbolicLink`; these match existing callers but can surprise new code. `FILE_FULL_EA_INFORMATION` uses `self["EaValue"]` in a length expression where a length field would be expected, which deserves targeted validation before use. The module does not validate semantic constraints such as legal dialect/context combinations; callers must set fields consistently.

## Test Signals
Unit tests should round-trip representative request and response structures for negotiate, session setup, tree connect, create with and without contexts, read/write, IOCTL, query directory, query/set info, transform headers, snapshot arrays, and reparse data. Offset/alignment tests should verify buffer offsets against MS-SMB2 values for empty and non-empty buffers, especially UTF-16 paths and create-context lists. Negative tests should confirm `isValidAnswer()` raises `smb3.SessionError` with the correct status and packet. Compatibility tests should exercise both `SMB2Packet` and `SMB3Packet` headers and ensure constants imported by `smbconnection.py` keep their expected numeric values.

# sources/user-network-fs/impacket/impacket/smbconnection.py

## Purpose
`smbconnection.py` provides the public version-neutral SMB client facade. It hides whether the underlying implementation is SMB1 (`smb.SMB`) or SMB2/3 (`smb3.SMB3`) and exposes a stable API for negotiation, authentication, tree connections, file and directory operations, named-pipe operations, snapshots, reparse-point helpers, reconnect, timeout/session-key management, and cleanup. Most application and tool code imports `SMBConnection` instead of instantiating `smb.SMB` or `smb3.SMB3` directly.

## Important APIs, Types, and Functions
`SMBConnection.__init__()` records connection options, accepts an existing SMB/SMB3 instance, optionally negotiates immediately, and tracks Kerberos/cache/NTLM fallback settings for reconnects. `negotiateSession()` resolves `*SMBSERVER` behavior, performs either explicit dialect construction or wildcard negotiation, and instantiates `smb.SMB` or `smb3.SMB3` depending on the response. `negotiateSessionWildcard()` sends an SMB1 negotiate containing SMB1 and SMB2 dialect strings, then returns the raw response trailer so the wrapper can detect `0xfeSMB` and transfer the existing NetBIOS session into `SMB3`.

Authentication methods are `login()` for NTLM and `kerberosLogin()` for Kerberos. The Kerberos wrapper can use `CCache.parseFile()`, disables cache when explicit TGT/TGS are supplied, and retries with computed LM/NT hashes when the KDC reports AES enctype unsupported and no hash/key material was already supplied. Delegating operation methods include `connectTree()`, `disconnectTree()`, `listShares()`, `listPath()`, `createFile()`, `openFile()`, `writeFile()`, `readFile()`, `closeFile()`, `deleteFile()`, `getFile()`, `putFile()`, `queryInfo()`, `setInfo()`, `createDirectory()`, `deleteDirectory()`, `waitNamedPipe()`, `transactNamedPipe()`, `writeNamedPipe()`, `readNamedPipe()`, `rename()`, `reconnect()`, `setTimeout()`, `getSessionKey()`, `setSessionKey()`, `setHostnameValidation()`, `close()`, and `getFileEx()`. SMB2/3-only helpers include `listSnapshots()`, `createMountPoint()`, and `removeMountPoint()`. A wrapper `SessionError` normalizes `smb.SessionError` and `smb3.SessionError`.

## Control Flow
Construction either adopts an existing connection or negotiates. With no preferred dialect, wildcard negotiation creates a NetBIOS TCP session, sends SMB_COM_NEGOTIATE with dialects `NT LM 0.12`, `SMB 2.002`, and `SMB 2.???`, retries once with broader flags after a NetBIOS error, and chooses SMB3 if the response begins with the SMB2 protocol byte. With an explicit dialect, the wrapper directly instantiates the matching implementation. For SMB1, negotiated Unicode support is reflected back into flags.

Most operation methods are dispatch shims with exception normalization. When SMB1 and SMB2/3 diverge, the wrapper translates. `connectTree()` builds a UNC path for SMB1 but passes share names through for SMB2/3. `createFile()` and `openFile()` manually build SMB1 `NT_CREATE_ANDX` commands when the dialect is SMB1 and delegate to `smb3.SMB3.create()` for SMB2/3. `readFile()` performs a loop over the underlying `read_andx()` and stops on requested length, EOF, zero-length read, or `singleCall`; this avoids the low-level recursive read behavior in `smb3.py`. `queryInfo()` and `setInfo()` adapt SMB1 query/set file info calls to SMB2/3 query/set info. VSS snapshot listing opens the target path, sends `FSCTL_SRV_ENUMERATE_SNAPSHOTS` once for size and again for the full buffer, then decodes UTF-16 snapshot names. Mount-point helpers open reparse points and send `FSCTL_SET_REPARSE_POINT` or `FSCTL_DELETE_REPARSE_POINT`.

## State and Persistence Behavior
The wrapper stores the active low-level connection in `_SMBConnection`, any wildcard NetBIOS session in `_nmbSession`, original target names/host/port/timeout/dialect settings, Kerberos flags and KDC/cache choices, and NTLM fallback preference. It does not keep its own tree or file tables; those live in the low-level object. `getCredentials()` delegates to the underlying connection and `reconnect()` uses those credentials plus the wrapper's original negotiation options to create and authenticate a fresh low-level connection. `close()` best-effort logs off and then closes the low-level NetBIOS session. No local files are written by this module.

## Dependencies and Integration Points
This facade depends on `impacket.smb`, `impacket.smb3`, `impacket.smb3structs`, `impacket.nmb`, `impacket.nt_errors`, and `impacket.ntlm` hash helpers. `listShares()` integrates with DCE/RPC SRVS through `impacket.dcerpc.v5.transport.SMBTransport` using the current `SMBConnection` instance. Kerberos login integrates with `impacket.krb5.ccache`, `kerberosv5`, and constants. Public constants for dialects, create dispositions/options, access masks, and share modes are re-exported so callers can import them from `smbconnection.py`.

## Risks and Edge Cases
The facade deliberately catches only SMB session errors; NetBIOS/socket errors can still escape directly. Many methods accept `password` parameters for password-protected shares, but SMB3 low-level code marks that behavior TODO. `negotiateSessionWildcard()` performs only two attempts and can raise a generic `Exception('No answer!')`; explicit unknown dialect also raises a generic exception with an unformatted `%s`. `writeNamedPipe()` ignores the caller's `waitAnswer` for SMB2/3 because it delegates to `writeFile()`, which always waits through the underlying low-level method. `transactNamedPipe()` passes `waitAnswer` through to an SMB3 compatibility method whose `noAnswer | waitAnswer` logic is easy to misread and can invert expectations. `listSnapshots()`, `createMountPoint()`, and `removeMountPoint()` gate dialect lists manually; they omit SMB3.0.2 in some checks even though the lower layer supports that dialect. `createMountPoint()` and `removeMountPoint()` lack `try/finally` around every IOCTL path, so some exceptions can leave the opened handle unclosed. `close()` suppresses all logoff errors, which is convenient for cleanup but can hide server-side teardown failures. Reconnect relies on the underlying connection retaining credentials, so externally supplied existing connections with incomplete credential state may not reconnect as expected.

## Test Signals
Tests should verify wildcard negotiation chooses SMB1 or SMB3 based on response bytes and preserves the existing NetBIOS session, while explicit dialect negotiation creates the intended implementation. Authentication tests should cover NTLM exception normalization, SMB1 NTLM fallback propagation, Kerberos ccache use, explicit TGT/TGS disabling cache, and RC4 hash fallback on `KDC_ERR_ETYPE_NOSUPP`. Operation tests should run against fake or integration SMB1 and SMB2/3 servers for tree connect path translation, create/open differences, read chunking and EOF handling, query/set info adaptation, get/put callbacks, delete and directory operations, named-pipe reads/writes/transacts, share enumeration over SRVS, VSS snapshot enumeration, mount-point create/remove, reconnect, timeout/session-key methods, hostname validation forwarding, and close cleanup. Error tests should assert that low-level SMB session errors are wrapped into `smbconnection.SessionError` with preserved status code and packet.
