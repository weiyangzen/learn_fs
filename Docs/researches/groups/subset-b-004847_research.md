# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sdio.c

Purpose: Implements the mwifiex SDIO bus backend for Marvell/NXP WiFi-Ex devices. It binds SDIO device IDs to chipset-specific register/firmware descriptors, probes/removes the card, downloads firmware, initializes SDIO ports and interrupts, moves command/data/event packets between host and firmware, handles multi-port aggregation, supports suspend/resume and wakeup, and provides firmware/register dump plus card reset hooks through `mwifiex_if_ops`.

Important APIs, types, and functions: The file defines per-chip `mwifiex_sdio_card_reg` tables, per-chip `mwifiex_sdio_device` capability records, the `mwifiex_ids` SDIO match table, the `mwifiex_sdio` driver, and the `sdio_ops` interface table consumed by core mwifiex. Bus lifecycle entry points are `mwifiex_sdio_probe()`, `mwifiex_sdio_remove()`, `mwifiex_sdio_suspend()`, `mwifiex_sdio_resume()`, `mwifiex_register_dev()`, `mwifiex_unregister_dev()`, `mwifiex_init_sdio()`, and `mwifiex_cleanup_sdio()`. Transport primitives include `mwifiex_read_reg()`, `mwifiex_write_reg()`, `mwifiex_read_data_sync()`, `mwifiex_write_data_sync()`, `mwifiex_sdio_card_to_host()`, and `mwifiex_sdio_host_to_card()`. Interrupt and port flow is handled by `mwifiex_sdio_interrupt()`, `mwifiex_interrupt_status()`, `mwifiex_process_int_status()`, `mwifiex_get_rd_port()`, and `mwifiex_get_wr_port_data()`. Firmware and diagnostics flow through `mwifiex_prog_fw_w_helper()`, `mwifiex_check_fw_status()`, `mwifiex_sdio_fw_dump()`, `mwifiex_sdio_generic_fw_dump()`, `mwifiex_sdio_reg_dump()`, `mwifiex_sdio_device_dump()`, and `mwifiex_sdio_card_reset()`.

Control flow: Probe allocates `sdio_mmc_card`, copies the matched chipset capabilities, enables the SDIO function, validates optional device-tree compatibility, and calls `mwifiex_add_card()` with `sdio_ops` and a firmware completion. Core initialization later sets block size, selects SDIO or SDIO-UART firmware from host strap registers, records firmware dump mapping mode, initializes IO ports/new-mode command-port registers, acknowledges the bootloader interrupt, allocates MP register and aggregation buffers, and enables interrupts. Firmware download polls card-ready bits, reads block sizes from base registers, retries CRC-indicated chunks, writes firmware blocks over CMD53, and then waits for firmware-ready status. Runtime interrupt handling reads a snapshot of SDIO MP registers, ORs firmware interrupt bits into `adapter->int_status`, and drives `mwifiex_main_process()`. `mwifiex_process_int_status()` clears the latched status, marks command/data download completion, reads command-port packets in new mode, updates write/read bitmaps, loops available read ports, validates lengths, and hands packets to `mwifiex_sdio_card_to_host_mp_aggr()`.

State and persistence: Durable runtime state lives in `sdio_mmc_card` and `mwifiex_adapter`. `sdio_mmc_card` retains the `sdio_func`, firmware names, register map, feature flags, MP read/write bitmaps, current read/write ports, data-port mask/end port, MP register buffer, TX/RX aggregation state, firmware completion, and deferred work flags. Adapter state updated here includes `ioport`, `tx_buf_size`, `host_mlme_enabled`, `auto_tdls`, `ext_scan`, `cmd_sent`, `data_sent`, `int_status`, `event_cause`, `event_body`, `event_skb`, `devdump_data`, power-save flags, and debug ring entries for SDIO MP writes. Firmware dump buffers are allocated into `memory_type_mapping` entries and later handed to common dump upload code. Suspend sets `MWIFIEX_IS_SUSPENDED` only after host sleep and MMC keep-power are established; resume clears it and cancels host sleep.

Dependencies and integration points: This file depends on Linux SDIO/MMC APIs (`sdio_claim_host`, `sdio_enable_func`, `sdio_claim_irq`, CMD53 read/write helpers, `mmc_hw_reset`), firmware loading infrastructure, device-tree matching, kernel workqueues, completions, skbs, and cfg80211-visible mwifiex core callbacks. It integrates with common mwifiex files through `mwifiex_add_card()`, `mwifiex_main_process()`, command/event completion, firmware helpers, RX packet handling, power-save/host-sleep helpers, 11n aggregation state, shutdown/reinit paths, and device dump upload. The `MODULE_FIRMWARE` declarations tie this bus driver to named firmware blobs under `mrvl/`.

Risks: SDIO register offsets and capability flags are chipset-specific; wrong match data can corrupt IO port setup or firmware selection. Multi-port aggregation relies on synchronized bitmaps, port wrap logic, and buffer length accounting; off-by-one errors can drop packets, send on unavailable ports, or desynchronize firmware. Packet length validation is critical because firmware-supplied lengths determine skb allocation and CMD53 transfer sizes. Host-claimed SDIO sections call helpers that also claim in some paths, so lock context must remain as intended. Firmware dump paths allocate large vmalloc buffers and depend on firmware-side control-register handshakes. Suspend/resume must coordinate with in-flight firmware loading, host sleep, wake IRQ configuration, and `MWIFIEX_IS_SUSPENDED`; failed host sleep leaves traffic and wake state sensitive.

Test signals: Useful coverage includes SDIO probe/remove on each supported device ID, firmware download success and CRC retry, new-mode and legacy IO port initialization, interrupt-driven command response/event/data RX, TX under full and empty write bitmaps, MP aggregation with port wrap and single-packet fallback, SDIO single-port RX aggregation enablement via station init, suspend/resume with MMC keep-power, firmware dump/coredump triggering, and hardware reset/reinit. Runtime debug signals include `mwifiex_dbg()` interrupt/data logs, `adapter->dbg.last_mp_*`, command timeout paths, cfg80211 disconnect/scan notifications, and successful non-empty device dump uploads.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sdio.h

Purpose: Defines the SDIO-specific constants, firmware names, register/capability structures, aggregation state structures, and inline helpers shared by the mwifiex SDIO implementation. It is the contract between `sdio.c` and common mwifiex adapter code for SDIO port numbering, command-port mode, multi-port aggregation, firmware dump registers, and card runtime state.

Important APIs, types, and functions: Firmware constants include default image names for SD8786, SD8787, SD8797, SD8801, SD8887, SD8897, SD8977, SD8978 SDIO-UART, SD8987, and SD8997 variants. Register and bit definitions cover byte/block mode, IO-port masks, control and command ports, host interrupt masks/status bits, card-ready bits, new-mode command-port controls, configuration/wakeup registers, and aggregation buffer sizes. Key structures are `mwifiex_sdio_mpa_tx`, `mwifiex_sdio_mpa_rx`, `mwifiex_sdio_card_reg`, `sdio_mmc_card`, and `mwifiex_sdio_device`. Inline helpers include `mwifiex_sdio_cmdrsp_complete()`, `mwifiex_sdio_event_complete()`, `mp_rx_aggr_port_limit_reached()`, `mp_tx_aggr_port_limit_reached()`, and `mp_rx_aggr_setup()`.

Control flow: The macros in this header are used by `sdio.c` to decide whether TX/RX aggregation is in progress, whether aggregation buffers have room, when packet limits are reached, and how to reset aggregation state. `MP_TX_AGGR_BUF_PUT()` copies outgoing packets into the aggregate buffer and computes the encoded port bitmap differently when the current port wrapped around the firmware's port window. `mp_rx_aggr_setup()` records RX aggregate length, start port, encoded port bits, per-packet lengths, and packet count. Port-limit helpers stop aggregation when legacy devices reach aggregate packet count or new-mode devices cross half of the configured MP end-port window.

State and persistence: `sdio_mmc_card` is the persistent per-device state allocated at probe time and retained by SDIO driver data. It holds immutable match-derived fields, live adapter/card pointers, firmware completion, current MP read/write bitmaps, current ports, data port mask, allocated MP register and aggregation buffers, feature flags, and a work item with bit flags for dump/reset work. `mwifiex_sdio_card_reg` persists the per-family register layout used to interpret firmware bitmaps and dump scratch registers. `mwifiex_sdio_device` is the static match-time template that seeds each `sdio_mmc_card`.

Dependencies and integration points: Includes Linux completion, MMC/SDIO core headers, SDIO IDs, and mwifiex `main.h`. The only external function prototypes are `mwifiex_bus_register()` and `mwifiex_bus_unregister()`, while most definitions are consumed directly by `sdio.c`. The command/event completion inlines integrate SDIO with common mwifiex command cleanup by freeing response/event skbs. Constants such as `CMD_PORT_SLCT`, `SDIO_MPA_ADDR_BASE`, and `CONFIGURATION_REG` must match firmware behavior.

Risks: Aggregation macros mutate complex state without bounds checks beyond caller-provided room/limit predicates, so callers must validate lengths and packet counts before use. Port bitmap encoding differs between legacy and new-mode devices; regressions here can break only specific chips or wrap conditions. `func1_spec_reg_table` has a fixed maximum and must be filled consistently with `func1_spec_reg_num`. Firmware names are module-visible ABI for hotplug firmware loading. The inline completion handlers always free skbs, so callers must not reuse response/event buffers after completion.

Test signals: Compile coverage of `sdio.c` is the main test for structure and macro compatibility. Runtime signals include correct MP aggregation enable/disable behavior, stable port wrap under sustained TX/RX, successful command/event skb freeing without leaks, firmware load using the expected firmware string per device ID, and diagnostic register dumps that show coherent function0/function1/scratch ranges.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_cmd.c

Purpose: Builds station-mode firmware commands for the mwifiex core. It translates driver, cfg80211, security, power-save, regulatory, TDLS, scan, aggregation, and device-tree/calibration requests into little-endian `host_cmd_ds_command` payloads and provides the station firmware initialization sequence.

Important APIs, types, and functions: Public entry points are `mwifiex_sta_prepare_cmd()`, `mwifiex_sta_init_cmd()`, `mwifiex_dnld_dt_cfgdata()`, and `mwifiex_send_rgpower_table()`. Command builders cover RSSI (`mwifiex_cmd_802_11_rssi_info()`), MAC control/address/multicast, SNMP MIBs, get-log, TX rate/power/RF antenna, host sleep, deauthentication and adhoc stop, key material v1/v2, 11d domain info, IBSS coalescing, memory/register/EEPROM access, PCIe descriptor setup, event subscription, MEF filters, calibration/config data, multi-channel policy, robust coexistence, GTK rekey offload, channel-region query, coalescing filters, TDLS config/oper, SDIO single-port RX aggregation, wakeup reason, and channel info. Module parameters `drcs` and `disable_auto_ds` affect multi-channel policy and auto deep sleep setup.

Control flow: `mwifiex_sta_prepare_cmd()` first rejects adhoc-only commands if firmware capability bits do not support adhoc, then dispatches by command number to a specific builder or inline payload fill. Builders set `cmd->command`, `cmd->size`, action fields, TLV headers, and endian-converted values. Many builders append variable TLVs by advancing a byte pointer and increasing `cmd->size`; examples include rate scope/drop pattern, host-sleep PS parameters and ARP filter, subscribe-event RSSI thresholds, coalescing rules, TDLS peer capabilities, config/calibration data, and key material. `mwifiex_sta_init_cmd()` issues the post-firmware sequence: optional PCIe host descriptors, function init, device-tree wake/caldata and firmware config data, hardware spec query, optional SDIO single-port RX aggregation command, TX buffer reconfiguration, station power save, optional DRCS policy, channel-region query, TX rate/power queries, AMSDU enable, MAC control, optional auto deep sleep, 11d enablement, optional packet aggregation, and 11n TX config.

State and persistence: This file mostly writes transient command buffers, but it also deliberately mutates driver state that persists beyond command submission. It resets RSSI averages before RSSI queries; updates `adapter->hw_status` for function init/shutdown; reads device-tree wakeup GPIO into `adapter->hs_cfg.gpio`; releases `adapter->cal_data` after config download; sets `adapter->ps_mode`, `adapter->drcs_enabled`, and requested auto deep sleep behavior during init; records WAPI group-key state in `priv->sec_info.wapi_key_on`; sets `adapter->hs_activated_manually` for manual host sleep activation; and uses `priv->sta_params`, security fields, WEP slots, and rate bitmaps as sources for outgoing firmware state.

Dependencies and integration points: Depends heavily on host command structures and constants from `fw.h`, mwifiex adapter/private state in `main.h`, helper command builders from scan/join/11n/11ac/WMM code, Linux cfg80211 types for keys and TDLS station parameters, device-tree property access for calibration data, and firmware command submission via `mwifiex_send_cmd()`. SDIO integration appears in `HostCmd_CMD_SDIO_SP_RX_AGGR_CFG`, which cooperates with `sdio.c` RX aggregation and `sta_cmdresp.c` response parsing. PCIe-specific setup is also present, so this station command dispatcher is shared across bus backends.

Risks: Variable-length TLV construction is sensitive to command buffer size, endian conversions, and exact firmware ABI layout. Key material handling has multiple branches for WEP, WAPI, TKIP, AES, CMAC/IGTK, unicast/multicast/default keys, UAP versus STA behavior, and firmware key API versions; subtle flag mistakes can break association or leak traffic before port opening. `mwifiex_send_rgpower_table()` parses raw hostcmd text and sends opaque firmware commands, so syntax and size checks are important. Some builders assume non-null `data_buf` for SET actions. Station initialization order is significant: MAC control is intentionally last among core init commands, and SDIO aggregation depends on firmware capability plus host allocation fallback state.

Test signals: Good signals include successful firmware initialization on SDIO and non-SDIO buses, expected command sizes and endian fields under sparse or maximal TLV input, key installation for WEP/WPA/WPA2/WAPI/IGTK paths, host-sleep configuration with and without ARP filters, device-tree and config-file calibration download, DRCS enablement only when supported, SDIO single-port RX aggregation command only when capability and host memory permit, TDLS create/config/delete commands with complete station parameters, and command rejection for adhoc operations when firmware lacks adhoc support.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_cmdresp.c

Purpose: Parses station-mode firmware command responses and commits returned state into `mwifiex_private`, `mwifiex_adapter`, caller data buffers, cfg80211-visible state, and bus-specific hooks. It is the response half of `sta_cmd.c` and the central station command-result dispatcher.

Important APIs, types, and functions: Public entry point is `mwifiex_process_sta_cmdresp()`. Error handling is centralized in `mwifiex_process_cmdresp_error()`. Response handlers include RSSI info, SNMP MIB, get-log stats, TX rate configuration/query, TX power/RF antenna, MAC address, deauthentication/adhoc stop, key material v1/v2, 11d domain info, version extension, remain-on-channel, P2P mode, memory/register/EEPROM access, IBSS coalescing, TDLS operation, event subscription, UAP station list, config data, SDIO RX aggregation config, robust coexistence, channel-region regulatory data, packet aggregation control, and STA channel info. It delegates scan, association, adhoc, 11n, WMM, host-sleep, wakeup reason, and hardware-spec responses to helpers in neighboring files.

Control flow: `mwifiex_process_sta_cmdresp()` retrieves `adapter->curr_cmd->data_buf`, checks `resp->result`, routes failures through `mwifiex_process_cmdresp_error()`, and switches on the command number for success parsing. Many handlers convert little-endian firmware fields to CPU values, copy values into output buffers, and update cached driver state. Some response handlers queue follow-up commands: rate config can issue a TX rate query when fixed-rate mode is active, RSSI threshold events resubscribe after a low/high threshold event, and bad hardware revision detection in version extension sends an auto-deep-sleep disable command. Reconfigure-TX-buffer responses update adapter buffer sizing and call `if_ops.update_mp_end_port()` so SDIO can adjust the port window.

State and persistence: Persistent updates include RSSI/NF averages, rate bitmaps and fixed/auto data-rate flags, current TX rate/HT info, TX power min/max/current levels, RF antenna modes, current MAC address, WPA GTK/port-open/scan-block state, cached AES key material, memory/register readback caches, IBSS BSSID/beacon/ERP/adhoc state, TDLS node setup status, UAP station RSSI, SDIO RX aggregation enable/block size, custom regulatory domain pointer in `adapter->regd`, bus aggregation parameters and interface header length, TX buffer size/current size, UAP BSS started flag, power-save and host-sleep state through delegated handlers, and command wait status on failures.

Dependencies and integration points: Depends on the current command node owned by common command/event code, cfg80211 scheduled scan notifications, regulatory structures (`ieee80211_regdomain` and reg rules), mwifiex station tables, TDLS helpers, WMM/11n/11ac/scan/join response helpers, and bus `if_ops` for MP end-port updates. It directly integrates with `sdio.c` through `HostCmd_CMD_SDIO_SP_RX_AGGR_CFG` response parsing and through `HostCmd_CMD_RECONFIGURE_TX_BUFF`, which changes SDIO TX buffer and port mask behavior.

Risks: Response parsing trusts firmware-provided sizes enough to walk TLVs, so underflow/overflow checks around `resp->size`, TLV lengths, key lengths, EEPROM byte counts, and channel lists are critical. Regulatory-domain synthesis groups channel rules from firmware attributes; malformed or excessive channel data can fail allocation or produce wrong cfg80211 restrictions. Error handling recycles `adapter->curr_cmd` and clears it; callers must not use command data after failure. Key response handling only caches AES material for certain key types and opens the port on multicast key set, so security state depends on firmware flags matching expectations. Reconfigure-TX-buffer has bus-specific behavior and can affect SDIO aggregation immediately.

Test signals: Exercise success and failure responses for scan, PS mode, SDIO aggregation unsupported, key installation, TX rate fixed versus auto, TX power query/set, EEPROM length limits, channel-region TLV parsing, TX buffer reconfiguration and MP end-port update, TDLS failure reasons, UAP station list RSSI updates, RSSI CQM threshold resubscription, and command wait queue status on firmware errors. Integration traces should show `adapter->curr_cmd` cleanup on errors and expected follow-up commands after rate/RSSI/version responses.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_event.c

Purpose: Handles asynchronous station-mode firmware events for mwifiex. It converts firmware event causes and event bodies into driver state transitions, cfg80211 notifications, queued commands, TDLS/11n/WMM/coexistence updates, power-save transitions, disconnect handling, and firmware dump collection.

Important APIs, types, and functions: Public functions are `mwifiex_reset_connect_state()`, `mwifiex_process_multi_chan_event()`, `mwifiex_process_tx_pause_event()`, `mwifiex_bt_coex_wlan_param_update_event()`, and `mwifiex_process_sta_event()`. Internal helpers include `mwifiex_check_ibss_peer_capabilities()`, `mwifiex_parse_tdls_event()`, `mwifiex_process_uap_tx_pause()`, `mwifiex_process_sta_tx_pause()`, and `mwifiex_fw_dump_info_event()`. Event families covered include link/deauth/disassoc/link-loss, power-save sleep/awake/deep-sleep/host-sleep activation, MIC failures, background and extended scan reports, RSSI/SNR/CQM thresholds, IBSS coalescing and peer connect/disconnect, ADDBA/DELBA/BA timeout, AMSDU control, remain-on-channel expiry, channel switch/radar/channel reports, TDLS, TX pause/status, multi-channel info, Bluetooth coexistence parameter change, RXBA sync, and firmware dump info.

Control flow: `mwifiex_process_sta_event()` switches on `adapter->event_cause`, with event payloads already stored in `adapter->event_body`/`adapter->event_skb` by the bus layer. Link and disconnect events update carrier/queues or call `mwifiex_reset_connect_state()`. Power-save events transition `adapter->ps_state`, clear wakeup flags, delete wake timers, and may send null packets or host-sleep activation commands. Scan and WMM events queue query commands. RSSI threshold events notify cfg80211 and request RSSI info so response handling can resubscribe thresholds. IBSS peer events add/remove station records and parse HT/VHT capabilities from embedded management-frame TLVs. TDLS and TX pause events parse TLVs and update station/RA-list pause state. Firmware dump info events accumulate USB dump chunks until an end marker or buffer limit, then upload the dump.

State and persistence: `mwifiex_reset_connect_state()` clears media/security/rate/TDLS/RSSI/current-BSS state, saves previous SSID/BSSID for reassociation, stops queues, drops carrier, clears power-save TX locks, optionally notifies host-MLME or cfg80211 disconnect, zeroes `cfg_bssid`, and removes GTK rekey offload when firmware supplicant support is present. Event handling updates `adapter->ps_state`, `tx_lock_flag`, `pps_uapsd_mode`, wake flags, coexistence window and scan timing, USB multi-channel status and port assignment, devdump buffer and length, TDLS node states, station `tx_pause` flags, IBSS peer 11n/11ac capabilities, `adapter->tx_buf_size`, scheduled-scan state, CSA state, and debug event counters.

Dependencies and integration points: Integrates with cfg80211 notifications (`cfg80211_disconnected`, CQM RSSI, MIC failure, scheduled scan, remain-on-channel, TDLS requests), netdev carrier/queue control, mwifiex command submission, WMM RA-list management, TDLS helpers, 11n BA/reorder helpers, 11h channel/radar handlers, host MLME workqueues, firmware dump upload, USB multi-channel resync, and bus wakeup completion through `adapter->if_ops.wakeup_complete()`. It relies on bus files such as `sdio.c` to deliver event skbs and cause/body fields correctly.

Risks: Event payload parsing is length-sensitive; TLV loops must reject short or inconsistent buffers before touching embedded fields. Disconnect handling has many side effects and must not run during command-timeout states where current command cleanup is pending. Host MLME link-loss handling defers disconnect through workqueue state and can diverge from direct cfg80211 reporting. Power-save awake/sleep transitions depend on `data_sent`, port readiness, last-packet indication, and wake timers, so races can leave traffic locked or the card asleep. Firmware dump accumulation can overflow fixed dump buffers and intentionally uploads partial data on timeout or end marker. IBSS capability parsing manipulates skb headroom with pull/push and assumes the fixed event layout.

Test signals: Useful event tests include deauth/disassoc/link-loss with and without host MLME, WPS-session suppression, PS_SLEEP/PS_AWAKE/deep-sleep awake transitions, host-sleep activation request command, background scan report and stopped notifications, RSSI low/high CQM resubscription path, IBSS peer connect/disconnect with HT/VHT capability TLVs, ADDBA/DELBA/BA timeout, AMSDU buffer-size change, remain-on-channel expiry during host MLME auth and normal ROC, CSA-triggered deauth, TDLS channel switch result/status changes, TX pause TLVs for STA/UAP/multicast/TDLS peers, USB multi-channel resync, coexistence TLVs, RXBA sync, and firmware dump chunk upload on end or timeout.
