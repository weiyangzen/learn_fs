# sources/distributed-fs/openafs/src/viced/callback.c

Purpose: implements the OpenAFS fileserver callback manager. It tracks which cache-manager hosts have promises for which file identifiers, breaks those promises when files or volumes change, reclaims callback memory under pressure, times out stale entries, supports alternate client addresses, and, when demand-attach fileserver support is compiled in, saves/restores callback state across restart.

Important APIs/functions: `InitCallBack` allocates indexed `FileEntry` and `CallBack` pools and a dynamically sized file-entry hash table. `AddCallBack1`/`AddCallBack1_r` install normal, volume, bulk, or delayed callbacks and return the client-visible expiration time. `BreakCallBack`, `DeleteCallBack`, `DeleteFileCallBacks`, `DeleteAllCallBacks_r`, `BreakDelayedCallBacks_r`, `BreakVolumeCallBacksLater`, `BreakLaterCallBacks`, and `CleanupTimedOutCallBacks_r` are the main mutation paths. `MultiBreakCallBack_r`, `XCallBackBulk_r`, `MultiBreakCallBackAlternateAddress_r`, and `MultiProbeAlternateAddress_r` perform callback RPCs, including multi-Rx fanout and alternate-interface recovery. `DumpCallBackState` and the `INTERPRET_DUMP` build mode provide binary dump/debug tooling. Under `AFS_DEMAND_ATTACH_FS`, `cb_stateSave`, `cb_stateRestore`, `cb_stateRestoreIndices`, `cb_stateVerify`, `fe_OldToNew`, and `cb_OldToNew` serialize and validate callback records.

Core types/state: live callback state is stored in two one-based arrays, `FE` and `CB`, with `FE[0]`/`CB[0]` intentionally unused so zero can mean null. `struct FileEntry` represents a `(Volume,Vnode,Unique)` object and links into `HashTable` by `fnext`; it owns a per-file singly linked callback list through `firstcb`/`cnext`. `struct CallBack` links simultaneously into the file list, a per-host circular list (`hhead`, `hprev`, `hnext`), and a timeout circular list (`thead`, `tprev`, `tnext`). `timeout[CB_NUM_TIMEOUT_QUEUES]` is a 128-bucket wheel in 128-second units; `tfirst` records the oldest unexpired bucket. `cbstuff` records operational counters, allocation counts, space-reclaim statistics, and active callback breakers.

Control flow: initialization pre-fills free lists and chooses `FEhashsize` so expected chains stay near `FE_CHAIN_TARGET`. Adding a callback first preallocates a callback and file-entry slot, computes a timeout from callback type and existing sharer count, creates a file entry if needed, and either refreshes an existing host callback or links a new callback into the file, host, and timeout lists. Breaking a file callback marks matching callbacks with `CBFLAG_BREAKING`, batches up to `MAX_CB_HOSTS`, removes normal callbacks from local state before RPC, and calls cache managers via `multi_Rx`; failures try alternate addresses, then mark hosts `VENUSDOWN` and re-add delayed callbacks. Volume breaks are staged by marking matching FEs `FE_LATER` and host flags `HFE_LATER`; the fsync thread later unchains one volume's entries and performs batched host notifications.

State and persistence behavior: callback state is memory-resident during normal operation and is reclaimed by timeouts or host purges. When demand-attach serialization is enabled, the file writes callback headers, timeout queues, a placeholder FE-hash header, and each FE plus its CB records. Restore allocates old-to-new index maps, reconstructs FEs/CBs from disk, rebuilds the FE hash table dynamically instead of trusting the on-disk table, then translates all stored FE, CB, host, timeout, and list indices. Verification walks FE hash chains, per-FE CB lists, per-host CB lists, and timeout queues to detect loops, out-of-range indices, broken back-links, and count mismatches. Non-DAFS builds still support an opaque callback dump at `AFSDIR_SERVER_CBKDUMP_FILEPATH`.

Dependencies and integration: depends on `host.h`/`host.c` for host structures, host index mapping, per-host callback lists, alternate-interface mutation, and host enumeration. Uses Rx and generated cache-manager RPCs from `afscbint` (`RXAFSCB_CallBack`, `InitCallBackState`, `ProbeUuid`, etc.). Uses fileserver logging/panic paths (`ViceLog`, `ViceLogThenPanic`, `ShutDownAndCore`), fsync synchronization for deferred volume breaks, and DAFS state helpers from `serialize_state.h`.

Risks: correctness depends on maintaining three intrusive list families in sync under `H_LOCK`; a missed `TDel`, `HDel`, or `CDel` corrupts timeout cleanup, host cleanup, or per-file lookup. Many paths intentionally drop `H_LOCK` around network RPCs and then reacquire/re-find state, so races around deleted hosts, reused entries, and delayed callbacks are the dominant risk. `AddCallBack1_r` has complicated preallocation and host-lock comments; its existing-condition path is subtle because unused preallocated entries must be returned exactly once. `MultiBreakCallBack_r` sorts hosts by index to avoid multi-Rx channel deadlock, so changes to batching/order need lock-order review. Alternate-address recovery mutates callback connections and host address tables after RPC success; stale or malicious client interface data can cause wrong-host risk if UUID checks regress. Serialization compatibility is also sensitive: newer dumps intentionally write an empty FE-hash section, which older tools may not understand.

Test signals: meaningful tests include callback add/delete/break lifecycle, timeout wheel expiry, callback-space exhaustion and `GetSomeSpace_r` host selection, multi-host break failure with delayed callback reinsertion, volume deferred-break processing, alternate address failover with UUID mismatch/removal, DAFS save/restore/index translation/verification, and dump interpreter compatibility for MAGIC/MAGICV2/MAGICV3. Runtime signals include `PrintCallBackStats`, callback/host dumps, `ViceLog` messages for `BCB`, `GSS`, `CCB`, and DAFS verification warnings.

# sources/distributed-fs/openafs/src/viced/callback.h

Purpose: declares the core callback data structures, constants, status bits, list-index macros, and timeout-wheel arithmetic used by `callback.c` and host integration code. It is the in-memory ABI for fileserver callback bookkeeping.

Important APIs/types/macros: `MAX_CB_HOSTS` caps one multi-break batch at 1024 hosts and `MAXCBT` caps single callback break time. `struct cbcounters` exposes counters in the global `cbstuff`. `struct cbstruct` carries a held host pointer plus timeout head for batched breaks. `struct FileEntry` records vnode, unique, volume, hash-chain link, callback count, first callback index, and flags. `struct CallBack` stores file-list, host-list, and timeout-list indices plus status and flags. `struct VCBParams` is the host-enumeration accumulator for volume callback breaks. `CB_NORMAL`, `CB_DELAYED`, `CB_VOLUME`, and `CB_BULK` classify callback entries; `CBFLAG_BREAKING` protects in-progress scans. `itocb`/`cbtoi` and `itofe`/`fetoi` translate between one-based array indices and pointers.

Control flow support: the header does not execute logic, but its macros drive callback.c control flow. Timeout macros convert Unix time to 128-second callback time (`CBtime`, `UXtime`), round expiration times (`TimeCeiling`), select timeout duration by sharer count (`TimeOut`), choose a wheel bucket (`TIndex`, `THead`), normalize wrapped wheel indices (`TNorm`), and convert a bucket back to expiration time (`TIndexToTime`). Host and file operations rely on zero index as null; all list fields store indices, not pointers, so callback entries can be serialized and remapped.

State and persistence behavior: `struct FileEntry` and `struct CallBack` are explicitly required to be multiples of 8 bytes because callback.c casts free entries to `struct object` and because dump/restore code treats these layouts as serialized records. The index-based representation is the persistence boundary for demand-attach state: disk records contain copies of these structures and restore paths translate stored FE/CB/host indices into new in-memory indices.

Dependencies and integration: the header references `struct host`, `VolumeId`, and `AFSFid`-related types supplied by fileserver/OpenAFS headers included by users. `host.h` consumes this header indirectly for callback API prototypes and uses host indices in `h_itoh`/`h_htoi`, which callback structures store in `hhead`. Timeout macros depend on `timeout`, `tfirst`, `TimeOuts`, and `MinTimeOut` globals defined in `callback.c`, so they are tightly coupled to that implementation.

Risks: the array-index macros perform no bounds checking and assume `CB`/`FE` globals have been initialized and shifted so index 1 maps to the first real allocation. Any layout change to `FileEntry` or `CallBack` can break DAFS serialized state and dump readers. Timeout math assumes 128 buckets and 128-second granularity; using timeout values that are not compatible with that granularity can expire callbacks earlier/later than intended. `MAX_CB_HOSTS` must remain consistent with fixed-size stack arrays in callback.c.

Test signals: compile-time coverage should catch missing type definitions, but behavioral validation belongs in callback.c tests: index round trips, timeout bucket wraparound through `TNorm`, callback serialization/deserialization across platforms, and multi-break batches at `MAX_CB_HOSTS`.

# sources/distributed-fs/openafs/src/viced/check_sysid.c

Purpose: implements a small diagnostic command, `check_sysid`, that reads an OpenAFS fileserver sysid file and prints its version stamp, server UUID, and recorded IP addresses. It is meant for verification and inspection, not for modifying state.

Important APIs/functions: `main` is the only function. It validates the command line (`check_sysid <sysid_file>`), opens the file read-only, reads a local `struct versionStamp`, reads an `opr_uuid_t`, converts the UUID with `opr_uuid_toString`, reads an address count, then reads and prints each IPv4 address after `ntohl`. Constants `SYSIDMAGIC` and `SYSIDVERSION` define the expected file stamp.

Control flow: errors are handled immediately with printed diagnostics and distinct exits for open failure, UUID read failure, entry count read failure, address read failure, and UUID formatting failure. Magic/version mismatches are reported inline but do not abort parsing. The tool trusts the `nentries` value enough to iterate that many times and stops only on short reads.

State and persistence behavior: no persistent state is written. The file format fields are interpreted exactly as documented in comments: magic/version and number-of-addresses are in host byte order, UUID contains network-order portions as defined by UUID layout, and each address is stored in network byte order. The only dynamic allocation is the UUID string buffer returned by `opr_uuid_toString`, freed with `opr_uuid_freeString`.

Dependencies and integration: includes OpenAFS config/param headers, roken portability wrappers, VLDB integer types, and `opr/uuid.h`. The sysid format mirrors fileserver/volume-server identity state used elsewhere in OpenAFS server startup and registration code. The source contains a local copy of `struct versionStamp` noted as stolen from `afs/volume.h`, which keeps the utility lightweight but couples it to that layout.

Risks: the tool does not validate negative or huge `nentries`, so a corrupt file can cause long reads/printing until EOF. The magic mismatch message says `(should be 0x88aabbc)`, missing one `c` compared with `SYSIDMAGIC` `0x88aabbcc`. It uses `int` for addresses and sizes, which is adequate for the legacy format but not a general binary parser pattern. Host byte order fields mean sysid files are not portable across endian architectures without special handling.

Test signals: create fixture sysid files with valid stamp/UUID/address lists, truncated version/UUID/count/address sections, wrong magic/version, zero addresses, and multiple addresses. Verify exit status and printed dotted-quad output. Static-analysis signals include unchecked continuation after a short version-stamp read and unbounded `nentries`.

# sources/distributed-fs/openafs/src/viced/fs_stats.h

Purpose: defines the fileserver performance-statistics data contract used by the xstat interface and by fileserver request instrumentation. It describes overall counters, detailed per-RPC timing records, transfer-size histograms, time-manipulation macros, global stats objects, server identity globals, and helper function prototypes implemented in `fsstats.c`.

Important APIs/types/macros: `struct afs_PerfStats` is the overall xstat payload, containing vnode-cache, directory, Rx, host/client, sysname, busy, capability, and spare counters. `FS_STATS_RPCIDX_*` assigns stable indices to 28 fileserver RPC operations; `FS_STATS_XFERIDX_*` assigns indices for fetch/store data transfers. `struct fs_stats_opTimingData` records operation counts, successes, sum/square/min/max times. `struct fs_stats_xferData` records transfer counts, byte totals, min/max bytes, timings, and nine byte-size buckets. `struct fs_stats_DetailedStats` and `struct fs_stats_FullPerfStats` combine detailed and overall data. `struct fsstats` is the per-call scratch object passed to start/finish helpers.

Control flow support: the header is mostly declarative, but its time macros are invoked by `fsstats.c` to compute elapsed time, update sums, compare min/max values, and add squared timing samples. The `FS_STATS_RPCIDX_*` constants are used by RPC handlers to select the correct timing slot, while transfer handlers use `FS_STATS_XFERIDX_FETCHDATA` or `FS_STATS_XFERIDX_STOREDATA` plus bucket thresholds from `FS_STATS_MAXBYTES_BUCKET*`.

State and persistence behavior: statistics are process-memory counters exposed through xstat collections, not durable storage. `afs_FullPerfStats` backs `AFS_XSTATSCOLL_FULL_PERF_INFO`; `afs_perfstats` backs `AFS_XSTATSCOLL_PERF_INFO`. `FS_HostName`, `FS_HostAddr_NBO`, and `FS_HostAddr_HBO` provide the fileserver identity/address values consumed by host statistics and classification logic. `struct timeval` fields retain accumulated microsecond-level timing until reset or process restart.

Dependencies and integration: depends on `afs/param.h` for platform and integer definitions. Included by `host.h` for fileserver stats packaging and by `fsstats.c` for helper implementations. The field ordering in `afs_PerfStats` and the RPC index constants are externally visible through xstat clients, so compatibility matters.

Risks: the macros evaluate arguments multiple times and mutate their operands; callers must pass lvalues with care. `fs_stats_GetDiff` modifies its `t2` argument while normalizing microseconds, which is safe for local variables but dangerous if reused unexpectedly. `sumBytes`, min/max bytes, and several counters are 32-bit, so high-throughput servers can wrap. `fs_stats_SquareAddTo` uses mixed integer/floating-point arithmetic and casts to `int`, which can lose precision or overflow for long timings. Adding/removing RPCs without synchronizing `FS_STATS_NUM_RPC_OPS` and xstat consumers would break ABI assumptions.

Test signals: unit tests can exercise time comparison, diff, add, and square macros across microsecond borrow/carry boundaries. Integration tests should verify each fileserver RPC uses the intended index, transfer sizes map to expected buckets, xstat collection sizes remain stable, and counters remain protected by the fileserver stats lock in implementations.

# sources/distributed-fs/openafs/src/viced/fsprobe.c

Purpose: implements a minimal command-line probe that contacts an AFS fileserver and invokes `RXAFS_GetTime`, printing the server time or the RPC error. It is a simple connectivity/Rx smoke-test utility.

Important APIs/functions: `pxclient_Initialize` initializes Rx on local port 2115, creates a null-security Rx connection to the target server on port 7000 and service 1, and wraps it in a ubik client structure. `main` parses `fsprobe <serverHost>`, resolves numeric or DNS host input, initializes the client, and calls `RXAFS_GetTime` on `cstruct->conns[0]`. `GetArgs` tokenizes a space-delimited line into an argv-style array, though it is unused by `main`.

Control flow: command-line validation exits on missing host. Host parsing first tries `inet_addr`; if that returns `-1`, it falls back to `gethostbyname`. Initialization failures abort with diagnostics. The actual probe is one RPC; success prints seconds/useconds, failure prints the returned code.

State and persistence behavior: the utility uses process-global `cstruct`, `serverconns`, and `args`, but writes no persistent state. Rx and ubik client state live only for the process lifetime. Security is always null because `noAuth` is initialized to 1 and `pxclient_Initialize` ignores the `auth` parameter.

Dependencies and integration: includes generated AFS RPC interfaces from `afs/afsint.h`, Rx globals, and ubik client support. It talks to the fileserver service port directly, so it can validate that the server is reachable and responds to core AFS RPCs without involving normal cache-manager code. `AFS_component_version_number.c` embeds build version metadata.

Risks: `inet_addr` ambiguity means `255.255.255.255` is treated as invalid and sent to DNS fallback. The `auth` argument and `noAuth` comment conflict with behavior; authenticated probing is not implemented here. `ubik_ClientInit` is unusual for a single fileserver connection and may be unnecessary complexity. There is no cleanup path for Rx security objects/connections, which is acceptable for a short-lived tool but not reusable library code. Legacy `gethostbyname` limits IPv6 and thread-safety.

Test signals: smoke-test against a local test fileserver, invalid hostname, unreachable IP, and server returning an RPC error. Build warnings around unused globals/parameters and legacy resolver APIs are relevant. Packet/Rx logs can confirm the null-security call to port 7000 and service 1.

# sources/distributed-fs/openafs/src/viced/fsstats.c

Purpose: implements the helper functions declared in `fs_stats.h` for recording fileserver RPC operation timings and fetch/store transfer statistics. It abstracts counter updates so individual RPC handlers can bracket operations with start/finish calls.

Important APIs/functions: `fsstats_StartOp` validates an RPC index, records the target `rpcOpTimes` slot, increments `numOps` under `FS_LOCK`, and captures start time. `fsstats_FinishOp` records stop time and, only on success (`code == 0`), increments successes and updates sum, squared sum, min, and max elapsed times. `fsstats_StartXfer` validates transfer index, records start time, and selects the transfer slot. `fsstats_FinishXfer` always increments `numXfers`; on success, it increments successes, adds transferred bytes in KiB using a caller-maintained remainder, updates min/max bytes, buckets by requested object size, and updates elapsed timing aggregates.

Control flow: callers create a `struct fsstats` scratch object and invoke start/finish around RPC or transfer work. Operation finish ignores failed operations for timing aggregate purposes except for the initial `numOps` count. Transfer finish increments total transfer attempts even on failure, but all byte/timing aggregates are success-only. Bucket selection is a straight threshold cascade from <=128 bytes through <=1 MiB, with the last bucket for larger transfers.

State and persistence behavior: updates mutate the global `afs_FullPerfStats.det` structure in memory. There is no durable persistence. Locking is via `FS_LOCK`/`FS_UNLOCK` around shared counter mutations; start times are stored in the caller-owned `struct fsstats`. `remainder` carries sub-KiB bytes between transfer accounting calls so `sumBytes` tracks whole KiB while preserving fractional leftovers externally.

Dependencies and integration: includes fileserver internals (`viced.h`), OpenAFS/Rx/NFS headers, and `fs_stats.h`. The helpers are called from fileserver RPC implementations using the `FS_STATS_RPCIDX_*` and `FS_STATS_XFERIDX_*` constants. The xstat path later reads the same global structures.

Risks: `assert` index validation can disappear in release builds depending on `NDEBUG`, leaving out-of-range indexes unchecked. `fsstats_FinishOp` assumes `stats->opP` and start time were initialized by `fsstats_StartOp`; same for transfer fields. Min-time/min-byte fields must be initialized to large values elsewhere or first samples may not update correctly. `bytesXferred` and byte min/max are `afs_sfsize_t` but stored into 32-bit fields, which can truncate large transfers. Time macros mutate local elapsed values but are safe here because stop/start are local copies.

Test signals: focused tests can initialize stats records, run successful and failed operation/transfer finish paths, verify lock-protected counters, bucket boundaries, remainder carry behavior, min/max initialization behavior, and no timing updates on failed operations. Integration signals are xstat collection values after known RPC workloads.

# sources/distributed-fs/openafs/src/viced/host.c

Purpose: implements the OpenAFS fileserver host/client registry. It maps Rx connections to cache-manager hosts and authenticated clients, manages callback connections and host identity, resolves address/UUID changes, caches CPS membership, supports host/client enumeration and diagnostics, performs periodic liveness cleanup, and serializes host state for demand-attach restart.

Important APIs/functions: allocation helpers `GetHT`, `FreeHT`, `GetCE`, and `FreeCE` manage pooled host/client entries. Protection-server wrappers `hpr_Initialize`, `hpr_GetHostCPS`, `hpr_GetCPS`, `hpr_NameToId`, and `hpr_IdToName` provide per-thread ubik PR clients. Host lookup and lifecycle APIs include `h_Lookup_r`, `h_LookupUuid_r`, `h_GetHost_r`, `h_Alloc_r`, `h_TossStuff_r`, `h_Enumerate`, `h_Enumerate_r`, `h_CheckHosts`, and hash-table add/delete functions. Address/identity helpers include `initInterfaceAddr_r`, `addInterfaceAddr_r`, `removeInterfaceAddr_r`, `removeAddress_r`, `reconcileHosts_r`, and TMAY cache helpers. Client APIs include `h_FindClient_r`, `GetClient`, `PutClient`, `h_ReleaseClient_r`, `h_UserName`, and `h_EnumerateClients`. DAFS APIs include `h_stateSave`, `h_stateRestore`, `h_stateRestoreIndices`, `h_stateVerify`, and `h_OldToNew`.

Core types/state: global `hostList`, `hostCount`, `hostAddrHashTable`, and `hostUuidHashTable` form the active host registry. `hosttableptrs` supports index-to-host mapping used by callback state. `HTBlocks`/`HTs` and `CEBlocks`/`CEs` account pooled allocations. Each host carries a callback Rx connection, primary address/port, host flags, CPS data, interface list, callback list head, TMAY cache, and clients. Each client records connection id/epoch, ViceId, CPS, token expiration, auth class, deleted bit, and reference count. `rxcon_ident_key` stores probed host identity per Rx connection and `rxcon_client_key` stores the active client.

Control flow: `h_GetHost_r` is the central path. It first looks up by incoming address/port, verifies new connections with `TellMeAboutYourself`/`WhoAreYou` or cached TMAY results, handles UUID mismatch by removing stale addresses and retrying, swaps callback connections when a client moves address/port, merges duplicate hosts by UUID, initializes callback state for new hosts, and marks failures `VENUSDOWN`. `h_FindClient_r` first reuses connection-specific clients when valid, otherwise authenticates the Rx peer, obtains/creates the host, finds or allocates a client by connection id/epoch, refreshes CPS, resolves races with an existing connection-specific client, and attaches the client to Rx-specific data. `h_CheckHosts` periodically probes idle hosts, marks idle clients deleted, and marks long-idle hosts deleted or down.

State and persistence behavior: normal state is in-memory and protected primarily by `H_LOCK`, host locks, and client locks. Host deletion is lazy: `HOSTDELETED`/`CLIENTDELETED` flags are set first, and `h_TossStuff_r` frees callback connections, CPS arrays, TMAY capabilities, callbacks, hash entries, interface lists, clients, and host pool entries once references and locks allow. DAFS serialization skips busy hosts, deletes callbacks for skipped hosts, writes host disk entries plus interface and host-CPS vectors, restores callback connections/hash tables/UUID tables/list membership, and builds old-to-new host index maps. `h_stateVerify` checks address hashes, UUID hashes, and per-host callback lists.

Dependencies and integration: tightly integrated with `callback.c` through host callback list heads, callback connection resets, `DeleteAllCallBacks_r`, `MultiProbeAlternateAddress_r`, and callback state index mapping. Uses generated cache-manager RPCs (`RXAFSCB_TellMeAboutYourself`, `WhoAreYou`, `ProbeUuid`, `InitCallBackState3`), Rx connection-specific storage, ubik PR server RPCs for CPS/name lookup, fileserver config/auth (`afsconf_*`), and xstat/network stats globals from `fs_stats.h`. The host lock order documented in `host.h` is essential: client lock, host lock, then `H_LOCK` for blocking-order reasoning, with explicit drops around network I/O.

Risks: this file is concurrency-sensitive. Many paths drop `H_LOCK` around Rx or PR RPCs and then resume against structures that may have been deleted, rehashed, or had callback connections swapped. Refcount/lock ordering in `h_TossStuff_r`, `h_FindClient_r`, and `h_GetHost_r` is delicate. Address reconciliation must defend against NAT, stale client-reported interfaces, clients changing port, and UUID conflicts; regressions can attach callbacks or clients to the wrong host. CPS caching failures can temporarily deny group-based access or retry under load. `h_UserName` returns a static buffer and is unsuitable for concurrent long-lived use. Demand-attach save skips busy hosts, so callers must tolerate missing restored host/callback state.

Test signals: high-value tests include concurrent new connections from the same host, TMAY caching with waiters, host UUID mismatch and address migration, NAT port changes, duplicate host merge by UUID, alternate address probe success/failure, host/client lazy deletion under references, CPS failure retry behavior, token expiry through `GetClient`, DAFS host save/restore/index verification, and periodic `h_CheckHosts` transitions. Runtime diagnostics include host/client dumps, `ViceLog` messages for `CB`, `FindClient`, `reconcileHosts_r`, and hash verification warnings.

# sources/distributed-fs/openafs/src/viced/host.h

Purpose: declares the fileserver host/client data model, lock macros, host table sizing, callback-facing APIs, protection-server wrappers, enumeration helpers, state-serialization entry points, address helpers, and host/client flag bits used by `host.c`, `callback.c`, and fileserver RPC handlers.

Important APIs/types/macros: `H_LOCK`/`H_UNLOCK` wrap the global `host_glock_mutex`; `h_Lock`, `h_Lock_r`, `h_NBLock_r`, and `h_Unlock` wrap per-host locking. `struct Identity`, `AddrPort`, and `Interface` describe cache-manager identity and addresses. `struct host_to_zero` contains all host fields cleared on allocation, including callback connection, refs, address, flags, CPS, clients, interface list, callback list head, and TMAY cache; `struct host` adds stable index, host lock, and condition variable. `struct client_to_zero`/`struct client` model per-Rx-client authentication and CPS state. Callback add macros map to `AddCallBack1`.

Control flow support: the header documents the lock order and the rule that `H_LOCK` must be dropped before network I/O, `rx_NewCall`, or blocking locks. Refcount macros `h_Hold_r`, `h_Decrement_r`, and `h_Release_r` enforce host lifetime and call `h_TossStuff_r` when a deleted host/client has no references. List macros `h_InsertList_r` and `h_DeleteList_r` maintain `hostList` and `hostCount`. `h_htoi` and `h_itoh` translate between host pointers and stable host indices for callback records and DAFS state.

State and persistence behavior: only the `z` substructures are zeroed/reused for pooled host/client entries; fields outside them, such as locks, condition variables, and host index, survive allocation block setup. Under `AFS_DEMAND_ATTACH_FS`, `h_SaveState`/`h_RestoreState` are declared as package-level state serialization hooks. Host index tables are global so callback restore can translate stored host IDs back to host pointers.

Dependencies and integration: includes `fs_stats.h`, Rx globals, and pthreads. Prototypes expose callback functions implemented in `callback.c`, host functions implemented in `host.c`, and PR wrapper functions used by authentication/CPS code. Fileserver RPC handlers use `GetClient`/`PutClient`, callback add/delete/break routines, host stats accessors, and dump/check functions through this header.

Risks: macros mutate global structures without local locking checks, so callers must already hold the right lock. `h_itoh` performs unchecked pointer arithmetic into `hosttableptrs`, so invalid host indices can crash or corrupt state. `h_Release_r` may synchronously call `h_TossStuff_r`, so callers must understand side effects when decrementing the last reference. Flag bits such as `ALTADDR`, `VENUSDOWN`, `HOSTDELETED`, `HWHO_INPROGRESS`, and `HCBREAK` are shared across host and callback packages; inconsistent semantics between files can produce lost callbacks, VBUSY storms, or stale host mappings.

Test signals: compile and integration tests should cover lock-order-sensitive APIs, host index round trips, reference release/deletion behavior, callback macro expansion paths, flag transitions during host initialization and callback break, and DAFS save/restore declarations in demand-attach builds. Static review should verify all `_r` functions are called with `H_LOCK` as intended.
