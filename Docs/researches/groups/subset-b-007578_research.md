## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/RoleModel.java

Purpose: small Jackson model for constructing simple IAM policy JSON for S3A tests and delegation-token policy restriction. Important APIs are `Policy`, `Statement`, `Effects`, `policy()`, `statement()`, `resource()`, `directory()`, `pathToKey()`, and `toJson()`. Control flow is mostly builder-style: callers create statements with allow/deny, actions, and resources, assemble policies, validate mandatory fields, then serialize through Hadoop `JsonSerialization`. State is in policy/statement lists plus a JVM-local `SID_COUNTER` used to assign unique statement IDs; no durable state exists except generated JSON. Dependencies are Jackson, Hadoop `Path`, S3A path conventions, and `Preconditions`. Integration points include `RolePolicies`, `RoleTokenBinding`, and `S3ADelegationTokens` when building restrictive STS role policies. Risks include intentionally incomplete IAM-model coverage, S3 key derivation that assumes standard S3A URI shapes, and wildcard/directory ARN subtleties. Tests are signaled by limited-private test audience plus auth role/delegation integration tests.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/RolePolicies.java

Purpose: central catalog of S3, S3 Express, and KMS action/resource constants plus helpers for constructing common allow statements. Important APIs are action constants, `STATEMENT_ALLOW_KMS_RW`, `STATEMENT_S3EXPRESS`, `STATEMENT_ALL_S3_GET_BUCKET_LOCATION`, `allowS3Operations()`, `bucketObjectsToArn()`, and `bucketToArn()`. Control flow in `allowS3Operations()` emits bucket-level list/location permissions and object-level read or read/write permissions, always adding S3 Express support. State is immutable constants and unmodifiable lists; no persistence. Dependencies are `RoleModel` builders and Hadoop utility `Lists`. Integration points include policy providers that assemble delegation-token role policies and tests validating assumed-role access. Risks include policy drift as AWS adds permissions, broad wildcard statements, comments noting the S3 Express ARN wildcard came from AWS guidance with uncertainty, and split bucket-vs-object ARN requirements. Test signals include `RoleTestUtils`, restricted-read, assume-role, and delegation-token integration suites.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/STSClientFactory.java

Purpose: build AWS SDK v2 STS clients from Hadoop S3A configuration and wrap STS calls in S3A retry/exception translation. Important APIs are overloaded `builder()` methods, `createClientConnection()`, inner `STSClient`, `requestSessionCredentials()`, and `requestRole()`. Control flow loads endpoint/region, HTTP, retry, and proxy settings via `AWSClientConfig`, configures credentials, and enforces endpoint/region consistency before building. `STSClient` translates requests into `GetSessionTokenRequest` or `AssumeRoleRequest`, optionally attaching policy JSON, and executes through `Invoker.retry`. State is limited to the wrapped `StsClient` and `Invoker`; close delegates to the AWS client. Dependencies include AWS SDK STS, Apache HTTP client, S3A retry policy, and delegation constants. Integration points are `SessionTokenBinding` and `RoleTokenBinding`. Risks include misconfigured endpoint/region pairs, proxy secret loading failures, duration truncation to int seconds, and AWS STS availability. Test signals are session/role delegation integration tests and assumed-role commit tests.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/SignerFactory.java

Purpose: global registry and instantiation layer for AWS SDK request signers and HTTP auth schemes used by S3A. Important APIs are signer constants, `registerSigner()`, `isSignerRegistered()`, `createSigner()`, `createAuthScheme()`, and `createHttpSigner()`. Control flow checks unsupported v2 signer use, validates a signer type exists in the concurrent registry, reflects the signer instance through `S3AUtils`, and injects Hadoop configuration when the signer is `Configurable`. HTTP signer creation reads `fs.s3a.http.signer.class.name` and wraps a `HttpSigner` in an SDK auth scheme. State is the static concurrent `SIGNERS` map containing built-in signer classes and runtime custom registrations; no persisted state. Dependencies include AWS SDK signer APIs, Hadoop reflection utilities, and `InstantiationIOException`. Integration points are `SignerManager`, S3A client creation, and custom HTTP signer tests. Risks include global registry lifetime, deprecated `newInstance()` for HTTP signers, classpath/configuration errors, and deliberate rejection of removed S3 v2 signing. Test signal: `TestSignerManager` covers predefined, custom, missing, and configurable signer paths.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/SignerManager.java

Purpose: per-filesystem lifecycle manager for custom S3A signer configuration. Important APIs are constructor, `initCustomSigners()`, private `maybeRegisterSigner()`, and `close()`. Control flow reads `fs.s3a.custom.signers`, parses entries as `name`, `name:SignerClass`, or `name:SignerClass:InitializerClass`, registers signer classes if absent, instantiates optional `AwsSignerInitializer`s, and calls `registerStore()` with bucket, configuration, delegation-token provider, and owner UGI. On close it invokes `unregisterStore()` for all initializers. State is per-manager initializer list plus bucket/config/UGI/provider references; global signer state is delegated to `SignerFactory`. Dependencies include Hadoop `ReflectionUtils`, `UserGroupInformation`, `DelegationTokenProvider`, and AWS signer interface. Integration points are S3A filesystem initialization and custom auth plugins. Risks include malformed colon-delimited config, unchecked casts, global registration races mitigated only around insertion, and cleanup depending on `close()`. Test signal: `TestSignerManager` exercises predefined signers, custom signers, multiple initializers, unregister behavior, UGI/bucket scoping, and missing class failures.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/delegation/AWSPolicyProvider.java

Purpose: minimal extension point for services that can describe the AWS IAM policy needed to access their data. Important API is `listAWSPolicyRules(Set<AccessLevel>)`; `AccessLevel` enumerates `READ`, `WRITE`, and `ADMIN` from an S3A filesystem-operation perspective rather than raw AWS service actions. Control flow is caller-driven: `S3ADelegationTokens` asks the bound store operations for read/write policy statements and wraps them into a `RoleModel.Policy` when issuing role tokens. State and persistence are absent. Dependencies are only Java collections and `RoleModel.Statement`. Integration points are `DelegationOperations`, S3A store context callbacks, and `RoleTokenBinding` policy minimization. Risks are semantic drift between high-level access levels and concrete S3/KMS/S3 Express operations, and implementers returning incomplete rules that create tokens which authenticate but fail later on data access. Test signals come from role delegation and restricted-read integration tests that validate generated policies against real operations.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/delegation/AbstractDTService.java

Purpose: common Hadoop `AbstractService` base for S3A delegation-token services and bindings. Important APIs are `bindToFileSystem()`, getters for canonical URI, owner, store context, policy provider, `requireServiceState()`, `requireServiceStarted()`, and `serviceInit()`. Control flow enforces lifecycle ordering: construct, bind to filesystem while not initialized, initialize, start, operate, stop. Binding captures the canonical S3A URI, owner UGI from `StoreContext`, callback `DelegationOperations`, and store context before normal service initialization. Dependencies are Hadoop service lifecycle, UGI, `StoreContext`, and preconditions. Integration points are `S3ADelegationTokens` and every concrete `AbstractDelegationTokenBinding`. Risks include misuse of lifecycle order, double binding, and invoking getters before bind/init. Test signals are delegation integration helpers that instantiate token support and assert double-bind/start behavior.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/delegation/AbstractDelegationTokenBinding.java

Purpose: pluggable base class that maps one S3A delegation-token kind to AWS credential providers and token identifiers. Important APIs are `getKind()`, `getOwnerText()`, `getTokenIssuingPolicy()`, `createDelegationToken()`, abstract `createTokenIdentifier()`, `deploy()`, `deployUnbonded()`, `bindToTokenIdentifier()`, `createEmptyIdentifier()`, `getDescription()`, and `getUserAgentField()`. Control flow starts the service to create a simple secret manager, then `deploy()` chooses unbonded credentials or token-bound credentials depending on whether an identifier was supplied. Token creation wraps the subclass identifier in Hadoop `Token` and assigns the binding kind. State includes token kind and a secret manager; credential state is subclass-owned. Persistence is through identifiers written by Hadoop tokens. Dependencies are Hadoop token APIs, `RoleModel.Policy`, `EncryptionSecrets`, and `AWSCredentialProviderList`. Integration points are `S3ADelegationTokens`, session/full/role bindings, and token service loader decoding. Risks include strict class equality in `convertTokenIdentifier()`, intentionally constant secret-manager password, and subclasses needing to honor retry/serialization contracts. Tests cover identifier round trips and binding failures.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/delegation/AbstractS3ATokenIdentifier.java

Purpose: common Hadoop delegation-token identifier payload for S3A token kinds. Important APIs are constructors for concrete identifiers, `write()`, `readFields()`, `validate()`, `getBucket()`, `getUri()`, `getOrigin()`, `getCreated()`, `getExpiryTime()`, `getUuid()`, `getEncryptionSecrets()`, and `createDefaultOriginMessage()`. Control flow serializes superclass token fields, canonical URI, origin, UUID, encryption secrets, and creation timestamp; deserialization limits text sizes and reconstructs encryption state. Dependencies are Hadoop token identifier base class, `Text`, `EncryptionSecrets`, `NetUtils`, and `Time`; it deliberately avoids AWS SDK classes. Integration points are session/full/role identifiers, `S3ADelegationTokens.extractIdentifier()`, and UGI credential loading. Risks include token wire compatibility, URI null validation, log exposure limited by sanitized encryption output, and equality/hashCode using UUID/URI asymmetrically. Test signals include `TestS3ADelegationTokenSupport` round-trip/decode tests and filesystem delegation integration tests.

## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/auth/delegation/EncryptionSecrets.java
