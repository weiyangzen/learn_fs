# sources/distributed-fs/ceph-client/drivers/scsi/qla2xxx/qla_inline.h

Purpose: provides small, performance-sensitive inline helpers shared across the qla2xxx Fibre Channel driver. The file covers IOCB sizing, register polling, byte-order conversion, SRB allocation/release, fcport discovery state tracking, mailbox completion, retry-delay throttling, qpair CPU affinity, firmware resource accounting, PCI-disconnect detection, and miscellaneous queue/resource predicates.

Important APIs/types/functions: `qla24xx_calc_iocbs()` sizes type-7 command plus continuation IOCBs for DSD counts. `qla2x00_debounce_register()`, `qla2x00_poll()`, `host_to_fcp_swap()`, and `host_to_adap()` wrap hardware reads and wire-format conversions. `qla2xxx_init_sp()`, `qla2xxx_get_qpair_sp()`, `qla2xxx_rel_qpair_sp()`, `qla2x00_get_sp()`, and `qla2x00_rel_sp()` manage `srb_t` lifetime through qpair/base-vha busy markers and mempools. `qla2x00_set_fcport_disc_state()` atomically records discovery-state transitions. `qla2x00_hba_err_chk_enabled()`, `qla2x00_reset_active()`, and `qla2x00_chip_is_down()` gate protection and queueing behavior. `qla_get_fw_resources()` and `qla_put_fw_resources()` account IOCB and exchange usage per qpair and optionally per HBA.

Control flow: most helpers are leaf routines called from SCSI/NVMe/target paths. Allocation first marks the qpair busy, takes an SRB from the qpair mempool, initializes common SRB fields and a `kref`, and clears the busy mark on allocation failure. Base-vha allocation also marks the VHA busy and unwinds it if qpair allocation fails. Release reverses this order by clearing VHA busy state, resetting SRB callbacks to warning stubs, freeing to the mempool, and marking the qpair idle. Firmware resource acquisition checks per-qpair, aggregate qpair, and optional HBA-global limits before incrementing counters; release decrements with saturation for global atomics and qpair counters.

State and persistence: this header mutates runtime-only driver state: queue busy flags, `fcport->disc_state`, `fcport->shadow_disc_state`, retry-delay timestamps in jiffies, qpair CPU IDs and hint records, qpair/HBA firmware-resource counters, `ha->qp_cpu_map`, and DSD tracking lists. No durable storage is written. The discovery shadow packs historical states by shifting four bits per transition, so it is a compact runtime trace rather than a persistent log.

Dependencies and integration: depends on qla2xxx core definitions from `qla_target.h` and surrounding driver headers, Linux atomics, lists, DMA pools, PCI IRQ affinity, MMIO register helpers, SCSI protection helpers, and module parameters such as `ql2xenablehba_err_chk` and `ql2xenforce_iocb_limit`. It integrates directly with `qla_iocb.c` queue submission, `qla_nvme.c` qpair selection and IOCB sizing, target mode qpair hints, EEH recovery scheduling, and mailbox interrupt completion.

Risks: inline code runs in atomic and interrupt-sensitive paths, so lock ordering and balanced busy/resource accounting matter. `qla2x00_set_fcport_disc_state()` assumes discovery states fit in four bits and indexes `port_dstate_str[state]` without validating the new state. `qla_get_fw_resources()` uses rough unlocked aggregate qpair totals before incrementing under the caller's queue lock, so it is a throttle rather than a precise reservation protocol. `qla_put_fw_resources()` defensively saturates counters, which prevents underflow but can hide mismatched acquire/release paths. CPU mapping uses `raw_smp_processor_id()` and affinity hints, so hotplug and affinity changes need careful coverage.

Test signals: build with multiple qla2xxx hardware families enabled; exercise SRB allocation failure, qpair busy rejection, and release paths with debug warnings enabled; run SCSI/NVMe I/O while forcing `ql2xenforce_iocb_limit` modes; validate DIF/T10 PI combinations against `qla2x00_hba_err_chk_enabled()`; check mailbox interrupt wait completion; simulate PCI disconnect reads of `0xffffffff`; and confirm CPU-affinity qpair mapping is populated and freed across queue creation/removal.

# sources/distributed-fs/ceph-client/drivers/scsi/qla2xxx/qla_iocb.c

Purpose: builds and submits qla2xxx firmware IOCBs for SCSI I/O, DIF/T10 protection I/O, asynchronous login/logout/discovery/control commands, ELS/CT BSG traffic, NVMe LS, bidirectional requests, task management, aborts, markers, and hardware-family-specific queue doorbells. It is the main command marshaling layer between Linux SCSI/FC abstractions and QLogic ISP request queues.

Important APIs/types/functions: `qla2x00_calc_iocbs_32()`, `qla2x00_calc_iocbs_64()`, `qla2x00_prep_cont_type0_iocb()`, and `qla2x00_prep_cont_type1_iocb()` size and allocate continuation entries. `qla2x00_build_scsi_iocbs_32()`, `qla2x00_build_scsi_iocbs_64()`, `qla24xx_build_scsi_iocbs()`, and `qla24xx_build_scsi_type_6_iocbs()` serialize scatter-gather lists into command and continuation DSDs. `qla2x00_start_scsi()`, `qla24xx_start_scsi()`, `qla2xxx_start_scsi_mq()`, `qla82xx_start_scsi()`, and `qla_start_scsi_type6()` submit normal I/O for legacy, FWI2, multiqueue, P3P/82xx, and type-6 long-CDB/large-DSD paths. `qla24xx_dif_start_scsi()` and `qla2xxx_dif_start_scsi_mq()` handle protection operations through `cmd_type_crc_2` and CRC contexts. `qla2x00_start_sp()` dispatches non-SCSI SRB types to IOCB builders for login, PRLI, logout, ADISC, CT, ELS, TMF, abort, mailbox, notify-ack, NVMe LS, virtual-port control, PRLO, security association, and marker commands.

Control flow: SCSI submission paths follow a common sequence: send a marker if required, take the hardware or qpair lock, allocate an outstanding-command handle, DMA-map data and optional protection scatterlists, compute IOCB/DSD resources, reserve firmware resources, refresh request-queue free space from shadow registers or MMIO, fill the command packet, assign handle and `host_scribble`, build DSDs and continuation entries, publish the entry with `wmb()`, advance `ring_index`/`ring_ptr`, set DMA-valid flags, ring the firmware doorbell, optionally drain pending response queue entries, and release the lock. Error paths unmap DMA when locally mapped, release firmware resources, restore queue accounting after late failures, and leave some DIF cleanup to the caller's normal SRB teardown.

State and persistence: state is runtime queue and command state: request ring pointers/counts, outstanding-command arrays, command handles, `cmd->host_scribble`, SRB flags for DMA/CRC/FCP context ownership, qpair command counters, firmware IOCB/exchange counters, DSD pool lists, CRC/DIF context lists, timers and completions for async SRBs, fcport discovery/login flags, and statistics counters. Firmware-visible state is advanced through MMIO doorbells and IOCB contents; persistent fabric/device state changes can result from login/logout, PRLI/PRLO, ELS, and virtual-port control commands, but this file itself stores no durable configuration.

Dependencies and integration: integrates Linux SCSI commands, scatterlists, DMA mapping, protection information (`scsi_get_prot_op()`, protection SG lists, guard/ref-tag flags), FC BSG payloads, qla2xxx request/response queues, mailbox/firmware registers, EEH disconnect detection, qla_target notify-ack and TMF handling, EDIF secure I/O redirection, NVMe-over-FC LS handling, and hardware-family operations from `ha->isp_ops`. It relies on helpers and structures from `qla_def.h`, `qla_target.h`, `qla_inline.h`, target-mode files, NVMe code, EDIF code, and firmware-specific register definitions.

Risks: queue accounting is delicate because handles, `req->cnt`, DMA mappings, firmware resources, timers, and outstanding-command slots are acquired in stages and unwound differently across paths. DIF/T10 PI paths build nested DMA DSD lists and local DIF bundling buffers; allocation failures, page-boundary handling, and cleanup flags are high-risk. Type-6 paths preallocate qpair DSD chains and FCP_CMND DMA buffers and require CDB lengths greater than 16 bytes to be 4-byte aligned and bounded by `QLA_CDB_BUF_SIZE`. Some builders use base queue maps for continuations, so call-site queue selection must match the locked request queue. Hardware-specific doorbells and shadow-register reads require correct family detection, especially for 82xx/P3P, FX00, 83xx, 27xx, and 28xx adapters. Async ELS timeout paths remove outstanding commands and can race completion, making kref/timer behavior important.

Test signals: compile-test with legacy, FWI2, multiqueue, target, NVMe-FC, EDIF, and DIF/DIX options. Runtime coverage should include normal read/write with zero, small, and many SG segments; queue-full paths and outstanding-handle exhaustion; marker-needed submission; EDIF-enabled fcports; DIF read/write insert, strip, and pass modes with protection SG DMA failures; long CDB/type-6 I/O; 82xx doorbell verification; async login/logout/PLOGI timeout and completion; CT/ELS BSG requests with multi-segment request/reply payloads; NVMe LS originator/responder paths; task management and abort commands; PCI disconnect register reads; and resource-throttle behavior under `ql2xenforce_iocb_limit`.
