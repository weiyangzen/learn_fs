## sources/compression/zstd/lib/legacy/zstd_v07.c

Purpose: Implements the legacy Zstandard v0.7 decompressor as a mostly self-contained compatibility unit. It embeds old MEM, bitstream, FSE, and Huffman decoding support, then layers v0.7 frame/block decompression, dictionary loading, direct context decompression, and buffered streaming APIs exposed by `zstd_v07.h`. This file is selected only when legacy support asks for v0.7 frames, allowing the current library to decode historical streams without mixing old format rules into the main decoder.

Important APIs and types: Public entry points include `ZSTDv07_decompress()`, `ZSTDv07_decompressDCtx()`, `ZSTDv07_createDCtx()`, `ZSTDv07_freeDCtx()`, `ZSTDv07_decompress_usingDict()`, `ZSTDv07_createDDict()`, `ZSTDv07_freeDDict()`, `ZSTDv07_decompress_usingDDict()`, `ZSTDv07_getFrameParams()`, `ZSTDv07_getDecompressedSize()`, `ZSTDv07_findFrameSizeInfoLegacy()`, the buffer-less streaming pair `ZSTDv07_nextSrcSizeToDecompress()` and `ZSTDv07_decompressContinue()`, and the buffered `ZBUFFv07_*` API. Internal state is centered on `ZSTDv07_DCtx_s`, which owns FSE tables for literal length, match length, and offsets, a Huffman table, prior-output history pointers, repeat offsets, frame parameters, checksum state, decode stage, literal buffers, and frame header buffers. `ZSTDv07_DDict_s` stores an owned dictionary copy and a prepared reference decompression context.

Control flow: One-shot decompression creates or reuses a `ZSTDv07_DCtx`, initializes it with an optional dictionary, verifies the v0.7 frame header, then loops over 3-byte block headers until `bt_end`. Compressed blocks run `ZSTDv07_decompressBlock_internal()`, which decodes the literal section, builds or reuses sequence FSE tables, decodes sequence states from a reverse bitstream, executes literal/match copies, and appends the last literal run. Raw blocks copy directly, and RLE blocks generate repeated bytes in the one-shot path. Header parsing supports skippable frames in the streaming path, validates magic numbers, reserved bits, window size, content size, dictionary ID, and checksum flag. The buffer-less streaming API is stage-driven: read the minimal frame header, complete the full frame header, read block headers, decode block payloads, optionally skip skippable frame content, and reset to the initial stage when a frame completes. The `ZBUFFv07_*` wrapper buffers partial input and output around this exact-size streaming core.

State and persistence behavior: All persistent decode state lives in allocated contexts, not global mutable storage. `ZSTDv07_decompressBegin()` resets stage, history pointers, entropy flags, dictionary ID, Huffman table descriptor, and repeat offsets. Dictionary initialization may load entropy tables and repeat offsets from a v0.7 dictionary header, or reference raw dictionary content as external history. History continuity is tracked through `previousDstEnd`, `base`, `vBase`, and `dictEnd`; non-contiguous output forces external-dictionary style address translation. `DDict` creation copies dictionary bytes and precomputes a reusable reference context. No file or external persistence is performed.

Dependencies and integration points: Includes the legacy public header, `../common/xxhash.h` for content checksum verification, `../common/compiler.h` for compiler helpers and `MEM_STATIC`, and `../common/error_private.h` for shared error-code encoding. It is pulled into libzstd through `libzstd.mk` when `ZSTD_LEGACY_SUPPORT` is nonzero and less than 8. The exported names are version-suffixed (`ZSTDv07_`, `ZBUFFv07_`, `FSEv07_`, `HUFv07_`) to avoid collisions with the modern implementation and other legacy decoders.

Risks: This is security-sensitive parser and decompressor code for untrusted legacy inputs. The code relies on exact input sizes, reverse bitstream end marks, bounded FSE/Huffman table logs, window limits, and careful wildcopy overlength padding. Some paths intentionally permit fast over-copy into internal buffers after capacity checks, so off-by-one changes are high risk. `ZSTDv07_freeDDict()` assumes `ddict` is non-null. The buffer-less streaming path returns `ERROR(GENERIC)` for RLE data blocks, while the one-shot frame path handles RLE blocks; this difference is an integration compatibility hazard. `ZSTDv07_decompressBlock()` updates `previousDstEnd` using the returned size even when the returned value is an encoded error, so callers must treat block API errors immediately. Checksum verification is implemented in the streaming block-header end path; one-shot frame decompression updates the checksum but does not compare a checksum value at frame end in this legacy implementation, which should be preserved or deliberately tested before changing.

Test signals: Use v0.7 golden frames for one-shot, DCtx reuse, dictionary, DDict, buffer-less streaming, and ZBUFF streaming. Cover skippable frames, truncated minimal and full headers, bad magic, reserved frame bits, unsupported oversized windows, dictionary-ID mismatch, raw-content dictionaries, dictionary header entropy failures, repeat literal blocks without prior entropy, raw/RLE/compressed/end blocks, malformed literal sizes, sequence-table modes, long sequence counts, offset-before-history corruption, non-contiguous output buffers, checksum success/failure in streaming mode, exact-size source requirements, and memory-allocation failure through custom allocators where reachable.

## sources/compression/zstd/lib/legacy/zstd_v07.h

Purpose: Declares the public compatibility interface for decoding Zstandard v0.7 frames. It gives callers a stable way to detect frame sizes, create decompression contexts, use dictionaries, and stream legacy payloads without including the large implementation file directly.

Important APIs and types: Simple APIs are `ZSTDv07_getDecompressedSize()`, `ZSTDv07_decompress()`, and `ZSTDv07_findFrameSizeInfoLegacy()`. Error helpers are `ZSTDv07_isError()` and `ZSTDv07_getErrorName()`. Explicit-memory APIs expose opaque `ZSTDv07_DCtx`, `ZSTDv07_createDCtx()`, `ZSTDv07_freeDCtx()`, and `ZSTDv07_decompressDCtx()`. Dictionary APIs include `ZSTDv07_decompress_usingDict()`, opaque `ZSTDv07_DDict`, `ZSTDv07_createDDict()`, `ZSTDv07_freeDDict()`, and `ZSTDv07_decompress_usingDDict()`. `ZSTDv07_frameParams` reports `frameContentSize`, `windowSize`, `dictID`, and `checksumFlag`, and `ZSTDv07_getFrameParams()` probes frame headers without consuming input. Streaming APIs expose opaque `ZBUFFv07_DCtx`, init functions with or without dictionary, `ZBUFFv07_decompressContinue()`, error helpers, and recommended input/output buffer sizes.

Control flow: Callers choose between one-shot decompression, reusable DCtx decompression, prepared DDict decompression, or ZBUFF streaming. Header probing is two-step for partial inputs: `ZSTDv07_getFrameParams()` returns zero on success, a positive required byte count when more source is needed, or an error code. ZBUFF callers initialize a context, repeatedly pass available source and destination capacity by pointer, and use the return value as the next input-size hint until zero signals frame completion.

State and persistence behavior: The header only declares opaque context ownership. `ZSTDv07_DCtx` and `ZBUFFv07_DCtx` are reusable after reinitialization. `ZSTDv07_DDict` owns digested dictionary state so the original dictionary buffer may be released after creation. No static application state is exposed except constants and function symbols.

Dependencies and integration points: Depends only on `<stddef.h>` for `size_t` and C linkage guards for C++. `ZSTDLIBv07_API` enables Windows DLL export when `ZSTDv07_DLL_EXPORT=1`. The implementation is `zstd_v07.c`, and build inclusion is controlled by legacy-support settings in `libzstd.mk`. The v0.7 magic constant is `ZSTDv07_MAGICNUMBER`.

Risks: `ZSTDv07_getDecompressedSize()` returns zero both for unknown content size and for errors, so callers must use `ZSTDv07_getFrameParams()` for precise diagnostics and must still enforce application output limits because the header size can be malicious. `ZSTDv07_decompress()` requires exact compressed size and sufficient destination capacity. Streaming output buffers are overwritten at each call, so callers must persist flushed bytes before the next call. The header comment for `ZSTDv07_findFrameSizeInfoLegacy()` references `ZSTDv01_isError()`, which is a stale documentation typo and not a symbol contract.

Test signals: Compile C and C++ consumers, Windows export/import builds, one-shot decompression with exact and inexact source sizes, frame-param partial-header probing, DDict reuse, ZBUFF partial input/output loops, skippable frame reporting with `windowSize==0`, and error helper behavior for implementation-returned codes.

## sources/compression/zstd/lib/libzstd.mk

Purpose: Provides the included Makefile fragment that discovers libzstd source files and centralizes compilation flags for projects building the library through make. It sets source/build directories, version variables, optimization knobs, compiler warning flags, assembly inclusion, legacy source selection, build-directory hashing, vpaths, and install OS integration.

Important variables and rules: Input variables include `LIB_SRCDIR`, `LIB_BINDIR`, `ZSTD_LIB_MINIFY`, `ZSTD_LEGACY_SUPPORT`, `ZSTD_LEGACY_MULTITHREADED_API`, `ZSTD_NO_ASM`, `ZSTD_LIB_EXCLUDE_COMPRESSORS_DFAST_AND_UP`, and `ZSTD_LIB_EXCLUDE_COMPRESSORS_GREEDY_AND_UP`. Version values are parsed from `zstd.h` into `LIBVER_MAJOR`, `LIBVER_MINOR`, `LIBVER_PATCH`, `LIBVER`, and `ZSTD_VERSION`. Source lists are `ZSTD_COMMON_FILES`, `ZSTD_COMPRESS_FILES`, `ZSTD_DECOMPRESS_FILES`, `ZSTD_DICTBUILDER_FILES`, `ZSTD_DEPRECATED_FILES`, and conditionally `ZSTD_LEGACY_FILES`. The fragment exports `CPPFLAGS`, `CFLAGS`, `ASFLAGS`, `LDFLAGS`, `FLAGS`, `TARGET_SYSTEM`, `GREP`, `HASH`, `HASH_DIR`, `ZSTD_SUBDIR`, and vpath declarations for `.c` and `.S`.

Control flow: The whole file is guarded by `LIBZSTD_MK_INCLUDED` so repeated includes are no-ops. Defaults are established first, then minify mode rewrites decompressor choices and error-string behavior and switches to `-Oz` or `-Os` if available. Common `CPPFLAGS` add the zstd XXH namespace and debug level, with MinGW stdio compatibility on Windows. Compiler probes add `-z noexecstack`, assembler `--noexecstack` variants, and CET reporting only when the current compiler accepts them. Source discovery uses `wildcard` and `sort`; assembly files are added unless `ZSTD_NO_ASM` disables them. Feature flags append preprocessor definitions. Legacy support selects `legacy/*.c` files matching v0N through v07 when `ZSTD_LEGACY_SUPPORT < 8`. Finally it includes `install_oses.mk`, chooses copy/link tools, computes a configuration hash-based object directory unless `BUILD_DIR` is already set, and registers vpaths.

State and persistence behavior: This fragment mutates Make variables in the including build. It has no runtime state. `ALREADY_APPENDED_NOEXECSTACK` is exported to prevent repeated noexecstack probing across recursive make invocations. `HASH_DIR` persists within the make evaluation as a deterministic object subdirectory derived from compiler and flag state, reducing collisions between incompatible builds.

Dependencies and integration points: Designed to be included after the default target in top-level makefiles. It reads `zstd.h`, includes sibling `install_oses.mk`, relies on standard shell utilities (`sed`, `grep`, `ls`, `md5sum`/`md5`), compiler probe commands, and the lib directory layout (`common`, `compress`, `decompress`, `dictBuilder`, `legacy`, `deprecated`). It controls whether `zstd_v07.c` and other legacy decoders join the build.

Risks: Version parsing depends on the exact macro names in `zstd.h`. The legacy file selection shells out to `ls` and `grep` with a regex containing `$(ZSTD_LEGACY_SUPPORT)-7`; unusual values or filenames could change selected files, so callers should use documented numeric support levels. Compiler feature probes execute the configured `CC` during makefile evaluation, which can be slow or problematic for cross-compilation. `CFLAGS ?= -O3` only applies when unset, but many later feature flags append unconditionally. Minify mode disables stack protector and frame pointer, which is size-oriented but security/debugging relevant.

Test signals: Run make variable dumps and real builds for default, `ZSTD_LIB_MINIFY=1`, `ZSTD_NO_ASM=1`, compressor-exclusion modes, Windows/MinGW `TARGET_SYSTEM`, cross-compile compilers that reject linker probes, absent hash utilities, explicit `BUILD_DIR`, and `ZSTD_LEGACY_SUPPORT` values 0 through 7. Verify selected source lists include the expected legacy files and that recursive includes do not duplicate flags.

## sources/compression/zstd/lib/libzstd.pc.in

Purpose: Template for generating the `libzstd.pc` pkg-config metadata file used by downstream build systems to discover include paths, link flags, version, URL, description, and license for libzstd.

Important fields: Substitution variables are `@PREFIX@`, `@EXEC_PREFIX@`, `@INCLUDEDIR@`, `@LIBDIR@`, `@VERSION@`, `@LIBS_MT@`, and `@LIBS_PRIVATE@`. The generated package is named `zstd`, describes the library as a fast lossless compression algorithm, points to `https://facebook.github.io/zstd/`, emits `Libs: -L${libdir} -lzstd @LIBS_MT@`, `Libs.private: @LIBS_PRIVATE@`, and `Cflags: -I${includedir} @LIBS_MT@`.

Control flow: This file is not executed directly. The install/configure or make install flow substitutes placeholders with installation directories, the libzstd version, and platform-specific threading/private libraries, then installs the resulting `.pc` file for pkg-config consumers.

State and persistence behavior: The template itself has no runtime state. The generated `.pc` file becomes persistent installation metadata and affects every downstream compile or link command that uses `pkg-config --cflags --libs zstd`.

Dependencies and integration points: Consumed by libzstd packaging/install scripts. Downstream build tools read the generated file through pkg-config. `@LIBS_MT@` integrates thread flags into both compile and link lines when needed, while `@LIBS_PRIVATE@` supports static-link-only dependencies.

Risks: Incorrect substitution of prefix/libdir/includedir breaks downstream discovery. Putting `@LIBS_MT@` in `Cflags` may be necessary for some threading models but can leak linker-like flags into compile commands if substituted poorly. License text says `BSD-3-Clause OR GPL-2.0-only`, while the surrounding source comments often describe a BSD-style license plus GPLv2 choice; packaging checks should confirm the intended SPDX expression for this vendored version.

Test signals: After install, run `pkg-config --modversion zstd`, `--cflags`, `--libs`, and `--static --libs`; compile and link a tiny zstd consumer with shared and static settings; verify relocated prefix values and platform-specific thread/private libraries.

## sources/compression/zstd/lib/zdict.h

Purpose: Declares libzstd's dictionary builder API. It documents when dictionaries help, exposes stable public training/finalization helpers, and gates experimental static-link-only tuning APIs for COVER, fastCover, and the legacy trainer.

Important APIs and types: Public symbols use `ZDICTLIB_API` visibility. `ZDICT_trainFromBuffer()` trains a dictionary from concatenated samples and sizes. `ZDICT_params_t` carries `compressionLevel`, `notificationLevel`, and optional `dictID`. `ZDICT_finalizeDictionary()` converts custom raw content plus representative samples into a zstd dictionary with header, dictionary ID, and entropy tables. Helper APIs include `ZDICT_getDictID()`, `ZDICT_getDictHeaderSize()`, `ZDICT_isError()`, and `ZDICT_getErrorName()`. Static-link-only declarations behind `ZDICT_STATIC_LINKING_ONLY` include `ZDICT_DICTSIZE_MIN`, deprecated `ZDICT_CONTENTSIZE_MIN`, `ZDICT_cover_params_t`, `ZDICT_fastCover_params_t`, `ZDICT_legacy_params_t`, `ZDICT_trainFromBuffer_cover()`, `ZDICT_optimizeTrainFromBuffer_cover()`, `ZDICT_trainFromBuffer_fastCover()`, `ZDICT_optimizeTrainFromBuffer_fastCover()`, `ZDICT_trainFromBuffer_legacy()`, and deprecated `ZDICT_addEntropyTablesFromBuffer()`.

Control flow: Normal consumers allocate an output dictionary buffer, concatenate representative samples in one input buffer, provide parallel sample sizes, and call `ZDICT_trainFromBuffer()` or `ZDICT_finalizeDictionary()`. Advanced static-link users can specify COVER/fastCover parameters directly or ask optimization functions to search parameter combinations and write selected values back into the parameter struct. Error returns are `size_t` values checked by `ZDICT_isError()` and named by `ZDICT_getErrorName()`.

State and persistence behavior: The header declares pure buffer-oriented APIs. Training writes dictionary bytes into caller-provided memory and may log to stderr based on `notificationLevel`; it does not allocate persistent application state through the public contract. The dictionary bytes produced by these APIs are the persistent artifact intended for later compression and decompression through `zstd.h` dictionary-loading APIs.

Dependencies and integration points: Depends only on `<stddef.h>` and C linkage guards. Visibility is controlled by `ZDICTLIB_VISIBLE`, `ZDICTLIB_HIDDEN`, `ZSTD_DLL_EXPORT`, `ZSTD_DLL_IMPORT`, and `ZDICTLIB_STATIC_API`. The generated dictionaries are consumed by `ZSTD_CCtx_loadDictionary()`, `ZSTD_DCtx_loadDictionary()`, and related zstd APIs declared elsewhere. Implementations live in the `dictBuilder` source files selected by `libzstd.mk`.

Risks: Dictionary training quality depends heavily on representative samples; too few, too small, identical, or incompressible samples can fail or produce ineffective dictionaries. Static-link-only APIs are explicitly experimental and unsafe to rely on across dynamic-library boundaries. `dictID` collisions are possible when auto-generated and low/high ID ranges are reserved for future public use. Memory use can be high: the comments document roughly 6 MB for default training, about 9 bytes per input byte for COVER, and `6 * 2^f` bytes per thread for fastCover. If an attacker controls the decompression dictionary, they can influence decoded bytes just as with compressed data.

Test signals: Compile public-only and `ZDICT_STATIC_LINKING_ONLY` consumers, including C++ and DLL visibility configurations. Train dictionaries with valid samples, too few samples, tiny samples, identical samples, incompressible samples, small and large capacities, explicit and automatic dict IDs, and notification levels. Exercise COVER and fastCover parameter validation (`k`, `d`, `f`, `accel`, `steps`, `nbThreads`, split/shrink settings), static versus dynamic linking boundaries, deprecated-warning suppression, `ZDICT_getDictID()`, and `ZDICT_getDictHeaderSize()` on valid dictionaries, raw content, truncated buffers, and corrupt headers.
