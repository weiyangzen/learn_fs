# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_rlock.c

This file implements ZFS range locking over byte ranges. It exposes `rangelock_init()`, `rangelock_fini()`, `rangelock_enter()`, `rangelock_exit()`, and `rangelock_reduce()`, using an AVL tree ordered by starting offset to coordinate readers, writers, append writes, and temporary whole-file locks used during block-size growth.

Writer and append acquisition is handled by `rangelock_enter_writer()`. A caller-provided callback may rewrite `RL_APPEND` into an `RL_WRITER` at EOF and may enlarge a writer range, commonly to `UINT64_MAX` for whole-file exclusion while growing a file block size. Writers wait on overlapping tree nodes and reset their requested offset, length, and type after each wakeup because the callback may have changed them.

Reader locking supports overlapping shared ranges through proxy locks. `rangelock_proxify()` replaces an original reader lock in the tree with a proxy node; `rangelock_split()` divides a proxy range at an interior offset; `rangelock_new_proxy()` creates proxy segments for gaps. `rangelock_add_reader()` walks overlapping reader ranges, splits them as needed, and increments per-segment reference counts so overlapping reader ranges can be represented as disjoint AVL spans.

`rangelock_enter_reader()` blocks readers behind active writers and behind queued writers on overlapping ranges. This avoids continuous reader arrivals starving a waiting writer. Waiters lazily initialize per-node read and write condition variables and mark `lr_read_wanted` or `lr_write_wanted`.

Unlocking preserves the proxy model. `rangelock_exit_reader()` removes ordinary reader locks directly, but for proxy-backed original handles it finds the start proxy and decrements every contiguous proxy segment covering the original range, freeing zero-count segments and broadcasting waiters. Writer unlocks remove the single writer node, wake waiters, and free the handle.

`rangelock_reduce()` shrinks a whole-file writer lock to a caller-specified subrange after block-size growth has completed. It asserts that the tree contains only the whole-file writer, then updates the range and broadcasts waiters. The main correctness risks in this file are off-by-one overlap checks, proxy split/refcount consistency, waiter CV lifecycle, and the callback contract for append and block-growth conversion.

# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_sa.c

This file connects ZPL znodes to the ZFS System Attribute framework. Its global `zfs_attr_table[]` registers native ZPL attributes such as time fields, generation, mode, size, parent, links, xattr object, flags, UID/GID, ACL data, symlink data, scanstamp, and project ID.

`zfs_sa_readlink()` reads symlink contents from either the old znode bonus-buffer layout or from block zero of the object if the link does not fit in the legacy bonus area. `zfs_sa_symlink()` performs the corresponding write path: short symlinks are stored after `ZFS_OLD_ZNODE_PHYS_SIZE` in the bonus buffer, while longer symlinks grow the file block size, hold block zero, dirty it, and copy the target there.

`zfs_sa_get_scanstamp()` and `zfs_sa_set_scanstamp()` bridge the antivirus scanstamp optional attribute across both SA and legacy znode layouts. For SA znodes they use `sa_lookup()` or `sa_update()` on `SA_ZPL_SCANSTAMP`; for legacy znodes they store the scanstamp after the old znode physical structure and track presence with `ZFS_BONUS_SCANSTAMP` in `z_pflags`.

`zfs_sa_upgrade()` migrates an old-style znode bonus layout into SA form when possible. It skips symlinks and znodes without cached ACLs, avoids deadlocking on `z_lock`, bulk-reads old attributes, fills a new SA attribute template, transforms older ACLs to FUID-aware form if needed, preserves xattr and scanstamp data, changes the bonus type to `DMU_OT_SA`, replaces all SA attributes, frees any external ACL object, and marks `z_is_sa`.

`zfs_sa_upgrade_txholds()` adds the transaction holds needed for a possible SA upgrade: a general SA hold and, if an external ACL exists, a free hold for that object. This helper is used by mutation paths before they touch legacy znodes. Correctness depends on matching the SA registration table offsets expected by quota/project-accounting code and on upgrade callers taking adequate DMU transaction holds.

# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_vfsops.c

This file implements the ZFS VFS layer for illumos: filesystem registration, mount and mountroot, unmount, statvfs, root lookup, fid-to-vnode lookup, sync, suspend/resume around rollback or receive, ZPL version upgrades, property callbacks, user/group/project quota interfaces, and module initialization/finalization.

The VFS operation table wires `zfs_mount`, `zfs_mountroot`, `zfs_umount`, `zfs_root`, `zfs_statvfs`, `zfs_sync`, `zfs_vget`, `zfs_freevfs`, and `zfs_syncfs`. `zfs_sync()` skips panic writes, ignores `SYNC_ATTR`, commits a mounted filesystem’s ZIL for per-vfs syncs, and calls `spa_sync_allpools()` for global sync. `zfs_syncfs()` accepts only zero flags and delegates to `zfs_sync()`.

Mount setup centers on `zfsvfs_create()`, `zfsvfs_create_impl()`, `zfsvfs_init()`, `zfsvfs_setup()`, and `zfs_domount()`. These own the objset, initialize locks/lists/range state, read ZPL properties from the master node, set up SA, root object, unlinked set, FUID/shares/quota objects, assign a unique synthetic device, set VFS fsid/features, open the ZIL, drain unlinked objects, replay the intent log when mounting writable datasets, attach `zfsvfs` to the objset user pointer, cache the root vnode, and create the `.zfs` control directory for non-snapshots.

Live property behavior is handled by callback registration in `zfs_register_callbacks()`. It registers callbacks for `atime`, `xattr`, `recordsize`, `readonly`, `devices`, `setuid`, `exec`, `snapdir`, ACL mode/inherit/implicit, and `vscan`. Temporary mount options are saved before registration and then re-applied so mount-time overrides can shadow persistent properties. `nbmand` is handled specially at mount time but is not registered as a live property.

Quota and accounting helpers map user/group/project quota properties to ZAP objects, enumerate usage with `zfs_userspace_many()`, read one accounting/quota value with `zfs_userspace_one()`, and set quotas with `zfs_set_userquota()`. `zfs_space_delta_cb()` decodes old znodes and SA bonus data to extract user, group, and project IDs for DMU accounting. `zfs_id_overblockquota()`, `zfs_id_overobjquota()`, and `zfs_id_overquota()` enforce block and object quotas, triggering quota feature upgrades when possible.

Mount policy covers ordinary mounts, remounts, snapshots, zones, delegation, and MAC labels. `zfs_mount()` validates mountpoint type and busy state, rejects old `MS_DATA` payloads, checks privilege or delegated mount permission, enforces local-zone dataset visibility, applies label policy, refreshes callbacks on remount, and calls `zfs_domount()` otherwise. `zfs_mount_label_policy()` compares dataset labels to zone labels and may force readonly access for dominated labels. `zfs_mountroot()` imports the root pool from boot properties, parses bootfs object-number paths into dataset names, mounts root, handles remount and root unmount, and coordinates early boot disk path discovery.

Unmount and teardown are split between `zfs_umount()` and `zfsvfs_teardown()`. The unmount path checks privilege/delegation, purges DNLC entries, unmounts snapshots under `.zfs`, rejects busy non-forced unmounts after accounting for root and control-directory holds, marks `VFS_UNMOUNTED`, tears down ZIL/property/dbuf state, detaches the objset user pointer, disowns the objset, and destroys the control directory. `zfsvfs_teardown()` also supports non-unmount suspension, returning with teardown locks held so rollback/recv code can later call `zfs_resume_fs()`.

`zfs_statvfs()` reports space and object counts from `dmu_objset_space()`, maps project quotas into statvfs fields when the root project inheritance state requires it, and fills standard VFS fields. `zfs_vget()` converts short and long ZFS fids back into vnodes, including `.zfs` control-directory fids and snapshot objset lookups, then validates generation numbers. `zfs_root()` returns the cached root vnode unless forced unmount has cleared it.

Initialization is split across `zfs_vfsinit()`, `zfs_init()`, and `zfs_fini()`. VFS init installs VFS and vnode op tables and initializes synthetic device numbering. Runtime init creates `.zfs` and znode infrastructure and registers the ZFS object accounting callback. `zfs_set_version()` upgrades a filesystem’s ZPL version, creates the SA master object when enabling SA, logs pool history, updates cached version state, and refreshes VFS feature flags. High-risk areas include mount/remount option precedence, teardown lock ordering, quota feature-upgrade races, root import boot-property handling, and suspend/resume reattachment of active znodes.

# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_vnops.c

This file is the main ZPL vnode-operation implementation for illumos ZFS. It implements regular-file, directory, symlink, xattr-directory, share-file, and error vnode operation tables, plus the supporting logic for data I/O, namespace mutation, attributes, ACLs, mmap/page-cache integration, zero-copy buffers, ZIL replay data extraction, and file identity.

The opening comment documents the core ordering rules: each vnode op must enter the filesystem with `ZFS_ENTER()`, verify znodes, acquire range/ZPL locks before `dmu_tx_assign()`, avoid blocking transaction assignment while holding ZPL locks unless using NOWAIT/retry, log successful operations before dropping locks, always commit or abort DMU transactions, and commit the ZIL after locks are released when synchronous semantics require it. Much of the file follows this retry-on-`ERESTART` transaction pattern.

Basic operations include `zfs_open()` and `zfs_close()`, which enforce append-only opens, vscan policy, synchronous-open accounting, and process lock/share cleanup. `zfs_ioctl()` supports sync, directio compatibility, seek-data/seek-hole, filled-block count, and project-xattr get/set. `zfs_access()` delegates ACL/RWX checks to ZFS access helpers. `zfs_seek()`, `zfs_frlock()`, `zfs_pathconf()`, `zfs_fid()`, `zfs_getsecattr()`, and `zfs_setsecattr()` provide VFS-facing metadata, locking, pathconf, fid, and ACL services.

Read/write paths are centered on `zfs_read()` and `zfs_write()`. Reads validate offsets, mandatory locks, quarantine state, optional FRSYNC behavior, acquire a reader rangelock, limit reads to EOF, support zero-copy xuio initialization, and choose between mapped-page reads and DMU dbuf reads. Writes validate readonly/immutable/append-only state, mandatory locks, resource limits, append semantics, block and project quotas, then write in block-sized transactions. The write path can borrow ARC buffers for full-block writes, assign loaned buffers, grow znode block size under an over-wide range lock, update cached pages, update size and timestamps, clear setuid/setgid when required, and log TX_WRITE records.

`zfs_get_data()` is the ZIL callback used to obtain data for write log records. It handles immediate writes by range-locking and reading file data into the log buffer. For indirect writes it locks the full file block, holds a dbuf, calls `dmu_sync()`, and defers cleanup to `zfs_get_done()`. It also handles truncation, removed znodes, debug fault injection, and the `EALREADY` case that converts a TX_WRITE into TX_WRITE2 with a zeroed block pointer.

Namespace operations include `zfs_lookup()`, `zfs_create()`, `zfs_remove()`, `zfs_mkdir()`, `zfs_rmdir()`, `zfs_rename()`, `zfs_symlink()`, `zfs_readlink()`, and `zfs_link()`. Lookup uses a DNLC fast path for case-sensitive non-xattr names, supports xattr-directory lookup, validates UTF-8 when configured, and returns specfs vnodes for device files. Create handles both new object creation and existing-file open/truncate, including ACL/FUID creation, quota checks, xattr-directory restrictions, ZAP insertion, and TX_CREATE logging.

Removal distinguishes immediate deletion from placing objects in the unlinked set. `zfs_remove()` decides based on link count, vnode holds, cached pages, file size, xattr object, and external ACL state; it may remove xattr references, delete the znode immediately, or add it to the unlinked set. `zfs_rmdir()` locks the target directory’s name and parent locks, rejects cwd removal and non-directories, destroys the directory entry, and logs TX_RMDIR. Both paths account for `.zfs`, xattrs, DNLC invalidation, vnode events, and synchronous dataset policy.

`zfs_rename()` is one of the most sensitive paths. It enforces same-ZFS-instance and non-control-node constraints, validates UTF-8 and case-folding behavior, orders source/target directory-entry locks by object id/name, blocks moves between normal and xattr space, enforces project-inheritance compatibility, performs access checks, prevents moving a directory into its own descendant via `zfs_rename_lock()`, handles replacement target removal, creates the target link, destroys the source link, repairs failed partial renames, updates path information, emits vnode events, and logs TX_RENAME.

Attribute handling is implemented by `zfs_getattr()`, `zfs_setattr()`, and `zfs_setattr_dir()`. `zfs_getattr()` maps FUID IDs, bulk-loads timestamps, performs optimized ACL checks, fills standard vnode attributes, and returns optional xvattrs such as archive, readonly, hidden, immutable, append-only, quarantine, scanstamp, createtime, generation, sparse, project inherit, and project ID. `zfs_setattr()` validates masks, readonly state, immutable constraints, timestamp limits, project quota support, permissions, ownership changes, mode/ACL updates, size truncation through `zfs_freesp()`, xattr-directory ownership/project propagation, FUID dirtiness, SA layout upgrades for project IDs, timestamps, xvattr flags, ZIL setattr logging, and synchronous commit policy.

Page-cache and mmap integration is handled by `zfs_map_page()`, `zfs_unmap_page()`, `update_pages()`, `mappedread()`, `zfs_putapage()`, `zfs_putpage()`, `zfs_inactive()`, `zfs_fillpage()`, `zfs_getpage()`, `zfs_map()`, `zfs_addmap()`, and `zfs_delmap()`. Writes keep mapped pages coherent with DMU data, reads prefer mapped pages when present, putpage clusters dirty pages to file block boundaries, getpage fills page clusters from DMU reads, mmap rejects immutable/append-only writable mappings and quarantined readable/executable mappings, and map counts are maintained for mandatory-lock checks. Forced-unmount inactive paths drop pages with `zfs_null_putapage()`.

Space and directory enumeration support includes `zfs_space()` for `F_FREESP` truncate/free behavior, `zfs_freesp()` integration through setattr/create/space, and `zfs_readdir()` for translating ZAP directory entries into `dirent64` or extended dirent records. Readdir reserves cookies for `.`, `..`, and `.zfs`, serializes ZAP cursors into offsets, supports access filtering, normalization-conflict flags, sysattr conflict checks, and prefetches child znodes.

Zero-copy support is exposed through `zfs_reqzcbuf()` and `zfs_retzcbuf()`. For writes, ZFS loans ARC buffers when the write is large enough and aligned to the current max block size, splitting preamble/full-block/postamble regions. For reads, it permits loaned buffers only above tunable block-size thresholds and when no cached pages are present. `zfs_retzcbuf()` returns unused ARC buffers and finalizes xuio state.

The vnode operation templates at the end map directories, regular files, symlinks, share files, xattr directories, and error vnodes to the appropriate handlers. Regular files get read/write/page/mmap/zero-copy operations; directories get namespace operations and readdir; symlinks get readlink; xattr directories intentionally reject mkdir and symlink while reusing most directory behavior. The main risk surfaces are transaction retry lock ordering, rename/link/unlink consistency, SA upgrade holds, ACL/FUID/project quota propagation, mmap/page-cache coherency, and ZIL logging order.
