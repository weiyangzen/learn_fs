# sources/cloud-native/ostree/ci/gh-build.sh

Purpose: GitHub CI build driver for libostree. It runs codestyle checks, bootstraps autotools with `NOCONFIGURE=1 ./autogen.sh`, creates an out-of-tree `ci-build`, configures with `--enable-always-build-tests` plus caller flags, builds, runs `make check`, runs `make distcheck`, and installs into a local `DESTDIR` for file listing.

Important APIs/functions: shell variables `srcdir`, `make="make V=1 VERBOSE=1"`, forwarded configure arguments `"$@"`, and `DISTCHECK_CONFIGURE_FLAGS="$*"`. The script relies on autotools targets generated by `configure.ac` and `Makefile.am`.

Control flow: strict bash mode and tracing fail on errors, run static analysis first, configure once, build once, test twice through `check` and `distcheck`, then run a staged install. `SOURCE_DATE_EPOCH` is exported only for `distcheck`, intentionally exercising both normal and reproducible-build environments.

State and persistence: creates `ci-build/` and `ci-build/DESTDIR`; no cleanup is done because CI logs use the build tree as evidence. Installation output persists only inside the workspace.

Dependencies and integration: integrates `ci/codestyle.sh`, `autogen.sh`, autotools, make, generated tests, source tarball checks, and install manifests. It is consumed by GitHub-style CI and by container builds that need the same path.

Risks and test signals: risks include argument flattening in `$*` for distcheck flags, stale `ci-build` directories, environment-sensitive distcheck behavior, and missing generated tools. Strong signals are successful codestyle, `make check`, `make distcheck`, and the final `DESTDIR` file list.

# sources/cloud-native/ostree/ci/gh-install.sh

Purpose: installs CI build dependencies on Debian and Ubuntu runners. It reads `/etc/os-release`, builds an apt package list matching libostree's build/test surface, adds distro-conditional packages, and installs any caller-supplied extra packages.

Important APIs/functions: `ID` and `VERSION_CODENAME` from `/etc/os-release`; `PACKAGES` bash array; positional package arguments; apt commands `apt-get -y update` and `apt-get -y install`. FUSE package selection is influenced by caller-supplied `libfuse-dev` or `libfuse3-dev`.

Control flow: only Debian/Ubuntu are supported. The script defaults to `libfuse3-dev` if no FUSE package was requested, appends common build/test packages, chooses `bsdmainutils` vs `bsdextrautils`, conditionally adds old FUSE 2 packages for older releases, then installs everything plus extras.

State and persistence: mutates the host package database and apt cache. It sets `DEBIAN_FRONTEND=noninteractive` to avoid blocking CI.

Dependencies and integration: aligns CI packages with Debian/Ubuntu packaging metadata and libostree optional features such as GPGME, libsoup3, curl, systemd, gtk-doc, gobject introspection, fsverity, SELinux, and JS installed tests.

Risks and test signals: unsupported distro IDs hard-fail. Risks include stale package names across distro releases, old FUSE availability assumptions, and comments noting TODO packaging sync. Test signals are successful apt resolution and subsequent `gh-build.sh` configure/test coverage.

Dependencies and integration: supports RPM/Packit source builds and release workflows that need a complete tarball rather than a partial git archive.

Signals are successful `tar -tf` with submodule paths and RPM source build consumption.
