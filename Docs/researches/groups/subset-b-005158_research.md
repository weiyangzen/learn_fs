# sources/distributed-fs/ceph-client/drivers/power/supply/bq25890_charger.c

Purpose: implements the Texas Instruments BQ25890/BQ25892/BQ25895/BQ25896 switch-mode charger as an I2C power-supply driver. It exposes charger status, limits, ADC-backed voltage/current/temperature values, charger enable/HiZ control, optional USB OTG VBUS regulator support, USB PHY ID notifications, and BQ25892 Pump Express high-voltage request handling.

Important APIs/types/functions: `struct bq25890_device` owns the I2C client, regmap fields, power supplies, optional USB PHY, work items, firmware-derived `bq25890_init_data`, cached `bq25890_state`, and the state mutex. `bq25890_reg_fields` maps bitfields to `regmap_field` handles; `bq25890_find_idx()` and `bq25890_find_val()` translate hardware table encodings. Power-supply operations are `bq25890_power_supply_get_property()`, `bq25890_power_supply_set_property()`, and `bq25890_power_supply_property_is_writeable()`. Runtime hardware paths include `bq25890_get_chip_state()`, `__bq25890_handle_irq()`, `bq25890_hw_init()`, `bq25890_pump_express_work()`, `bq25890_usb_work()`, and regulator ops for `usb_otg_vbus` and `vsys`.

Control flow: probe allocates device state, initializes regmap and fields, reads chip ID/revision, parses firmware properties, resets or enables charging, disables the watchdog, writes or reads initial limits, reads initial state, configures ADC conversion, obtains IRQ from the client or a named GPIO, registers optional regulators, registers a `bq25890-charger-%d` power supply, requests a threaded falling-edge IRQ, and optionally registers a USB PHY notifier. Property reads refresh state under `bq->lock`, compensate for lost interrupts by calling `__bq25890_handle_irq()`, and trigger a one-shot ADC conversion for offline/HiZ ADC properties. IRQ handling refreshes cached online/HiZ/status/fault bits, restores forced HiZ across cable replug, toggles continuous ADC conversion when online state changes, and emits `power_supply_changed()`. External power changes on BQ25892 derive input current from supplier USB type and may queue Pump Express work for DCP chargers. Remove unregisters USB notifications and optionally resets the chip; shutdown disables OTG boost unless the legacy USB PHY path is active.

State and persistence: runtime state lives in `bq25890_state`, `force_hiz`, regulator/USB work state, and the IDR-assigned name. Initial charge current/voltage, termination/precharge, boost, thermal, ILIM, compensation, Pump Express, secondary charger, and reset behavior are sourced from device properties. Register values are volatile hardware state; `force_hiz` is remembered only in memory and re-applied after cable replug. `linux,read-back-settings` turns firmware or bootloader-programmed register values into the driver's init cache instead of overwriting them.

Dependencies and integration: depends on I2C, regmap fields, GPIO descriptors for `bq25890_irq`, power_supply core, optional regulator framework, optional USB PHY notifier, firmware properties from OF/ACPI, and the system power-efficient workqueue. It can coordinate with a named secondary charger by driving its `POWER_SUPPLY_PROP_ONLINE` property during OTG boost and Pump Express.

Risks and test signals: ADC reads depend on conversion-rate transitions and one-shot polling; failures are mostly logged but can leave stale sysfs values. `bq25890_update_state()` invokes IRQ logic during property reads, so state locking and regmap side effects need coverage. Pump Express temporarily disables a secondary charger and must always clear `F_PUMPX_EN`; error paths currently do not re-enable the secondary charger. Firmware tables silently clamp values to nearest hardware encoding. Shutdown has a documented USB PHY compatibility exception that can leave boost enabled. Test with chip ID variants, DT/ACPI property combinations, IRQ loss, cable replug with forced HiZ, supplier USB type changes, Pump Express success/failure, regulator enable/disable, suspend/resume ADC behavior, and optional secondary charger probe deferral.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq25980_charger.c

Purpose: implements the TI BQ25980/BQ25975/BQ25960 switched-capacitor charger family. It registers a mains-like charger power supply plus a small battery power supply, applies device-tree current/voltage/watchdog limits, reports ADC values, and controls bypass, HiZ, and charge-enable modes over I2C/regmap.

Important APIs/types/functions: `struct bq25980_device` stores the I2C client, regmap, model name, `bq25980_chip_info`, `bq25980_init_data`, cached `bq25980_state`, and watchdog setting. `struct bq25980_chip_info` carries per-model scaling, offsets, default limits, and regmap defaults. Limit helpers include `bq25980_get/set_input_curr_lim()`, `bq25980_get/set_input_volt_lim()`, `bq25980_get/set_const_charge_curr()`, and `bq25980_get/set_const_charge_volt()`. State and user API are handled by `bq25980_get_state()`, `bq25980_get_charger_property()`, `bq25980_set_charger_property()`, `bq25980_get_battery_property()`, and `bq25980_irq_handler_thread()`.

Control flow: probe selects chip metadata from the I2C ID, initializes regmap using the model-specific default table, parses DT properties for watchdog timeout, switched-capacitor and bypass OVP/OCP limits, and initial bypass mode, registers charger and battery supplies, requests an optional threaded IRQ, then programs watchdog, battery-info-derived max charge values, initial bypass/current/voltage limits, and ADC enable. Charger property reads lock around `bq25980_get_state()` before converting status, health, online, charge type, limit, and ADC registers. Property writes clamp and program OVP/OCP/BATOVP/BATOCP registers, toggle bypass, toggle charger enable, or enter/leave HiZ by writing `CHRGR_CTRL_2`. IRQ refreshes state, compares to the cached snapshot, updates the cache under lock, and notifies only the charger supply.

State and persistence: state is split between hardware registers, cached `bq25980_state`, DT-derived initialization limits, and battery-info maxima obtained through `power_supply_get_battery_info()`. The driver programs both fault and alarm threshold registers for most limits. Runtime property writes persist only until hardware reset; there is no remove/shutdown path restoring defaults. The regmap uses a maple cache with status, flag, control, and ADC ranges marked volatile.

Dependencies and integration: depends on I2C, regmap, power_supply core, firmware properties, optional IRQ, and `monitored-battery` data available through the registered charger supply. OF compatibles and I2C IDs cover `ti,bq25980`, `ti,bq25975`, and `ti,bq25960`.

Risks and test signals: model-specific scaling is central; a wrong min/max/offset produces unsafe thresholds. `bq25980_set_input_curr_lim()` appears to use the switched-capacitor max when `state.bypass` is true and bypass max otherwise, which deserves hardware review. The DT parser rejects out-of-range values, while runtime writes clamp; test both behaviors. `bq25980_power_supply_init()` returns `-EINVAL` instead of the underlying `PTR_ERR()`, reducing diagnostics. `bq25980_set_bypass()` returns `1` when enabling bypass, so `bq25980_set_charger_property()` treats a successful enable as an error. IRQ notifications cover the charger but not the separate battery supply. Test probe with missing battery info, each chip ID, watchdog edge values, bypass and switched-capacitor limits, ADC sign handling for currents, IRQ state transitions, and charge-type/status writes.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq25980_charger.h

Purpose: defines the register map, bit masks, ADC scaling constants, watchdog values, and per-model electrical limits shared by the BQ25980 charger implementation.

Important APIs/types/functions: the header declares register addresses from `BQ25980_BATOVP` through `BQ25980_CHRGR_CTRL_6`, thresholds for BUS OCP/OVP, BAT OVP/OCP across BQ25980/BQ25975/BQ25960 variants, control bits such as `BQ25980_EN_BYPASS`, `BQ25980_CHG_EN`, `BQ25980_EN_HIZ`, and `BQ25980_ADC_EN`, status masks for OVP/OCP/thermal/watchdog/presence, ADC step constants, and watchdog configuration constants used by `bq25980_charger.c`.

Control flow: this header has no direct runtime flow. Its constants drive regmap default tables, device-tree validation, property conversion, health/status decoding, and register bit updates in the C file.

State and persistence: no independent state. The values are compile-time contracts for interpreting persistent charger hardware registers and volatile status/ADC registers.

Dependencies and integration: depends on kernel bit macros such as `BIT()` and `GENMASK()` through the including C file. It is private to the BQ25980 driver and intentionally not an exported UAPI.

Risks and test signals: any datasheet mismatch here propagates to unsafe charge limits or incorrect status reporting. Several constants are model-specific but similarly named, so tests should cover all three chip table entries, especially min/max boundaries, ADC sign polarity, watchdog disable/max encoding, and bypass versus switched-capacitor OVP/OCP conversions.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq27xxx_battery.c

Purpose: provides the shared TI BQ27xxx fuel-gauge core for many battery monitor chips. Bus-specific adapters supply read/write callbacks, while this file maps chip variants to registers/properties, maintains cached capacity/status flags, exposes battery properties, optionally updates data-memory battery parameters from firmware battery info, and provides suspend/resume/polling support.

Important APIs/types/functions: `bq27xxx_chip_data[]` binds each `enum bq27xxx_chip` to register maps, data-memory register metadata, unseal key, options, and property arrays. Core exported entry points are `bq27xxx_battery_setup()`, `bq27xxx_battery_teardown()`, `bq27xxx_battery_update()`, and `bq27xxx_battery_battery_pm_ops`. Bus abstraction is through `di->bus.read`, `write`, `read_bulk`, and `write_bulk`. Data-memory helpers include `bq27xxx_battery_unseal()`, `bq27xxx_battery_read_dm_block()`, `bq27xxx_battery_update_dm_block()`, `bq27xxx_battery_write_dm_block()`, and `bq27xxx_battery_set_config()`. Property helpers convert SOC, current, voltage, temperature, time-to-empty/full, energy, health, capacity level, and design voltage/capacity.

Control flow: setup initializes delayed polling work and locks, assigns chip-specific register/property tables, registers a battery power supply, optionally applies `power_supply_battery_info` into supported gauge data memory, performs an initial update, and links the device into a global list used by the `poll_interval` module parameter. Updates read flags and SOC, derive status from signed current for non-BQ27000 devices, notify userspace when capacity/flags/status changed, cache the snapshot, and requeue polling when enabled. `get_property()` refreshes stale cache entries older than five seconds, rejects most properties when flags indicate a read failure, and dispatches to direct register reads or cached values. External power changes schedule a half-second delayed update. Teardown removes the device from the global list, marks it removed to prevent requeue, and cancels delayed work.

State and persistence: runtime state lives in each `bq27xxx_device_info`: register cache, last status, last update timestamp, cached design voltages/capacity, chip options, data-memory tables, delayed work, and removal flag. The global device list and `poll_interval` module parameter coordinate polling for all instances. Data-memory updates can persist to gauge RAM or NVM/flash depending on chip option and `dt_monitored_battery_updates_nvm`; the code explicitly warns and refuses flash/NVM updates when configured not to write them. Cache state is transient, while successful data-memory writes and optional reset/soft-reset affect the gauge.

Dependencies and integration: depends on power_supply core, device firmware battery info, delayed work on `system_percpu_wq`, jiffies, module parameters, and the bus-specific I2C/HDQ files through exported symbols. It includes `linux/power/bq27xxx_battery.h` for shared structures and chip IDs.

Risks and test signals: this file spans many chips with different register layouts and flag meanings, so variant coverage is essential. Data-memory writes unseal gauges, rely on checksums, avoid checksum verification for BQ27425 corruption risk, and can permanently update NVM if enabled. The driver caches some design values forever after first successful read. `get_property()` performs on-demand refresh under lock but then does direct register reads outside the lock for many properties, so bus removal and concurrent updates are relevant. Test with each bus adapter, representative legacy BQ27000 and modern BQ274xx/BQ27Z561 chips, missing registers (`INVALID_REG_ADDR`), bad flags reads, `poll_interval` changes, external-power-triggered updates, suspend/resume work cancellation, battery-info data-memory update allowed/refused paths, and health/status flag decoding.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq27xxx_battery_hdq.c

Purpose: adapts the shared BQ27xxx battery core to HDQ/1-wire BQ27000-style devices. It registers a 1-wire family, creates a `bq27xxx_device_info` for each slave, and supplies a read-only HDQ bus callback to the core.

Important APIs/types/functions: `w1_bq27000_read()` performs the low-level HDQ read command under the 1-wire master bus mutex. `bq27xxx_battery_hdq_read()` reads one-byte or stable two-byte registers, retrying when high-byte samples change. `bq27xxx_battery_hdq_add_slave()` and `bq27xxx_battery_hdq_remove_slave()` bridge 1-wire add/remove events to `bq27xxx_battery_setup()` and teardown. `bq27xxx_battery_hdq_family` supplies `w1_family_ops`; `F_ID` can override the default family ID.

Control flow: module init optionally replaces the family ID, then registers with the w1 core. When a matching slave appears, add allocates device info, sets chip type `BQ27000`, names it `bq27000-battery`, installs only the read callback, and invokes shared setup. Reads issue HDQ command bytes; two-byte reads sample upper/lower/upper until the upper byte is stable or retries expire. Module exit unregisters the family.

State and persistence: driver-local state is limited to the optional family ID parameter and per-slave devm allocation. All battery cache and polling state is owned by `bq27xxx_battery.c`. The HDQ adapter provides no write or block operations, so persistent data-memory updates are not available through this path.

Dependencies and integration: depends on the 1-wire subsystem, `w1_slave`/`w1_family`, and the shared BQ27xxx core. It has a module alias for the default BQ27000 family ID.

Risks and test signals: two-byte consistency relies on only three high-byte retries; fast-changing registers can return `-EIO`. The low-level read returns an unsigned byte and cannot distinguish all bus-level failures from valid `0xff`; the core has a BQ27000-specific flags check for `0xff`. Test family-ID override, add/remove lifecycle, stable and unstable two-byte reads, absent write support, polling teardown, and 1-wire bus mutex behavior under concurrent reads.

# sources/distributed-fs/ceph-client/drivers/power/supply/bq27xxx_battery_i2c.c

Purpose: adapts the shared BQ27xxx battery core to I2C fuel-gauge devices. It provides byte/word and block read/write callbacks, maps many I2C IDs and OF compatibles to BQ27xxx chip IDs, handles optional IRQ-driven updates, and manages unique battery names.

Important APIs/types/functions: `bq27xxx_battery_i2c_read()` performs register-address write plus one- or two-byte read with limited `-EBUSY` retry and little-endian conversion. `bq27xxx_battery_i2c_write()`, `bq27xxx_battery_i2c_bulk_read()`, and `bq27xxx_battery_i2c_bulk_write()` implement the core bus callbacks. `bq27xxx_battery_i2c_probe()` allocates an IDA number, creates a name like `<id>-<num>`, fills `bq27xxx_device_info`, calls `bq27xxx_battery_setup()`, schedules initial polling, and requests an optional threaded IRQ. `bq27xxx_battery_i2c_remove()` frees the IRQ and tears down the core.

Control flow: module registration binds the I2C driver. Probe sets up the bus abstraction before invoking the shared core; after setup it schedules a delayed update about one minute later and installs the IRQ handler if `client->irq` is present. IRQ handling simply calls `bq27xxx_battery_update()`. Remove reverses IRQ registration and shared core setup. PM operations are provided by the shared core through the driver's `.pm` pointer.

State and persistence: local state is the global IDA for names and the per-client `bq27xxx_device_info`. I2C write and bulk-write support lets the shared core update gauge data memory on chips that advertise data-memory tables. Workqueue/cache state is in the shared core.

Dependencies and integration: depends on I2C transfers, SMBus block reads, unaligned little-endian helpers, interrupts, module device tables, and `linux/power/bq27xxx_battery.h`. The OF table is compatible-only; chip selection for OF-probed devices depends on I2C ID matching behavior.

Risks and test signals: `bq27xxx_battery_i2c_read()` does not verify that `i2c_transfer()` returned exactly two messages, so short positive transfers could be misinterpreted. Bulk writes use a 33-byte stack buffer and assume the core's 32-byte data-memory blocks. The IRQ is requested with non-devm `request_threaded_irq()`, so remove and probe-error teardown must remain correct. Test all ID mappings, busy-retry behavior, short-transfer failure behavior, block read/write lengths, optional IRQ update path, shared PM suspend/resume, and probe failure after `bq27xxx_battery_setup()`.

# sources/distributed-fs/ceph-client/drivers/power/supply/chagall-battery.c

Purpose: implements an I2C/regmap fuel-gauge and power LED driver for Pegatron Chagall EC hardware. It exposes a battery power supply backed by EC registers and registers amber/white power LEDs with charging/full default triggers.

Important APIs/types/functions: `struct chagall_battery_data` stores regmap, two `led_classdev`s, power supply, delayed poll work, and last status. `chagall_battery_get_value()` reads two little-endian EC registers for most properties. `chagall_battery_get_property()` converts raw status, temperature, voltage, current, and charge values to power_supply units. `chagall_battery_poll_work()` polls status and emits `power_supply_changed()` when it changes. LED callbacks write brightness to `CHAGALL_REG_LED_AMBER` and `CHAGALL_REG_LED_WHITE`.

Control flow: probe allocates state, initializes an 8-bit regmap, registers the battery supply, registers amber and white LEDs, forces both LEDs off, initializes autocancel delayed work, and starts periodic status polling every five seconds. Property reads directly fetch the corresponding EC register pair and convert units. Suspend cancels poll work; resume schedules it again. The I2C driver binds to `pegatron,chagall-ec`.

State and persistence: `last_state` is the only cached battery state and is used to suppress duplicate change notifications. LED brightness writes affect EC LED registers until firmware/hardware changes them. Battery measurements are read on demand; there is no persistent configuration or writable power-supply property.

Dependencies and integration: depends on I2C, regmap, LED class, devm delayed work helpers, power_supply core, and OF matching. The battery supply uses `external_power_changed = power_supply_changed`, so charger changes can notify the supply without driver-local processing.

Risks and test signals: `regmap_bulk_read()` is asked to read two values into a `u32 *` while the regmap has 8-bit values; reviewers should confirm the intended byte packing across regmap implementations. Status ignores `BATTERY_FULL_DISCHARGED` and treats any non-full/non-discharging state as charging. Polling only detects status changes, not capacity/voltage changes. LED writes ignore regmap errors. Test register endianness, status bit precedence, unit conversions, LED registration and brightness writes, suspend/resume work cancellation, and repeated EC read failures.

# sources/distributed-fs/ceph-client/drivers/power/supply/charger-manager.c

Purpose: implements the generic charger-manager platform driver. It aggregates one fuel gauge, one or more charger status power supplies, regulator-controlled chargers, optional extcon cable events, optional thermal-zone data, polling, alarm-based suspend monitoring, and sysfs controls into a managed battery/charger power_supply.

Important APIs/types/functions: global state includes `cm_list`, `cm_list_mtx`, `cm_timer`, suspend flags, polling state, and the charger-manager workqueue. Core decisions are made by `is_batt_present()`, `is_ext_pwr_online()`, `is_charging()`, `is_full_charged()`, `cm_check_thermal_status()`, `check_charging_duration()`, `cm_get_target_status()`, `_cm_monitor()`, and `try_charger_enable()`. Power-supply exposure uses `charger_get_property()` with `psy_default` and dynamic optional properties. Extcon integration is in `charger_extcon_init()`, `charger_extcon_notifier()`, `charger_extcon_work()`, and `charger_manager_register_extcon()`. Sysfs regulator controls are prepared by `charger_manager_prepare_sysfs()`. DT parsing is in `of_cm_parse_desc()`.

Control flow: late init creates a freezable workqueue and registers the platform driver. Probe obtains platform data or parses DT, validates charger/fuel-gauge references, configures optional RTC alarm, discovers optional fuel-gauge properties and temperature source, prepares per-regulator sysfs groups, registers the charger-manager power supply, obtains charger regulators and extcon notifiers, adds the instance to the global list, enables wakeup plumbing, runs an initial monitor pass, and schedules polling. Monitoring computes a target status from external power, battery presence, thermal bounds with hysteresis, full thresholds, and charge/discharge duration limits; it enables/disables non-external regulators and notifies userspace on status changes. Extcon work updates cable online/current-limit state and reruns monitoring. Suspend prepare cancels polling and arms an alarm when possible; complete cancels the alarm, accounts elapsed suspend duration, restarts polling, and monitors once.

State and persistence: per-manager state includes current `battery_status`, `charger_enabled`, `emergency_stop`, charge start/end timestamps, extcon cable states, regulator external-control flags, and optional thermal-zone pointer. Global polling state chooses the shortest required polling interval among managers. Sysfs `charger.N/externally_control` changes runtime ownership of individual regulators but does not persist. Hardware regulator enable state is changed directly and may outlive driver state until remove disables managed chargers.

Dependencies and integration: depends on power_supply core for fuel gauge and charger status supplies, regulator consumers for charger control, extcon for cable state/current limits, thermal zones, alarmtimer/RTC for suspend monitoring, workqueues, sysfs groups, and OF/platform data described by `linux/power/charger-manager.h`.

Risks and test signals: the driver coordinates many external providers by name; probe ordering and missing supplies are common failure points. `is_full_charged()` returns early after voltage threshold without `power_supply_put(fuel_gauge)`, which is a reference leak risk. `charger_get_property()` and monitor paths repeatedly look up supplies and must handle disappearing providers. Forced regulator disable on emergency stop can surprise shared regulator users. Extcon text-to-type parsing accepts deprecated names and DT errors can silently map no cable. Suspend alarm behavior depends on RTC availability and global state shared by all managers. Test missing fuel gauge/charger/regulator/extcon, all polling modes, thermal overheat/cold hysteresis, full voltage/SOC/capacity thresholds, duration limits, sysfs external-control transitions, multiple managers sharing global polling, suspend/resume with and without RTC alarm, and regulator failure paths.

# sources/distributed-fs/ceph-client/drivers/power/supply/collie_battery.c

Purpose: implements battery and charging support for the Sharp SL-5x00 "Collie" platform through the UCB1x00 companion chip. It registers main and backup battery power supplies, samples voltage/temperature through UCB ADC channels gated by GPIOs, controls the main charge GPIO, and reacts to the main-full GPIO interrupt.

Important APIs/types/functions: `struct collie_bat` describes one battery's status, power_supply, full-charge voltage cache, GPIOs, ADC channels/dividers, technology, and work lock. `collie_read_bat()` and `collie_read_temp()` serialize GPIO/ADC access through `bat_lock`. `collie_bat_get_property()` exposes status, technology, voltage, design limits, cached max voltage, temperature, and presence. `collie_bat_update()` decides charging/full/discharging and toggles `gpio_charge_on`. `collie_bat_probe()` obtains machine GPIOs and UCB-owned descriptors, registers both supplies, and requests the full IRQ.

Control flow: module init registers a UCB1x00 driver. Probe rejects non-Collie machines, stores the UCB pointer, obtains main battery full/low/charge GPIOs plus UCB GPIOs for main battery, main temperature, and backup battery measurement enables, initializes work, registers power supplies, requests both-edge IRQ on the full GPIO, enables device wakeup, and schedules the first update. The update work only processes the main battery: it checks presence, external supply state, full GPIO, and previous status to charge, stop charging, or mark discharging. Property reads perform synchronous ADC sampling. Suspend flushes work and may enable IRQ wake while charging; resume disables wake and schedules an update. Remove unregisters IRQ and power supplies, releases descriptors, and cancels work after event sources are gone.

State and persistence: global static battery descriptors and state hold runtime status and cached `full_chrg`; there is no persistent storage. `full_chrg` captures the measured voltage when the main battery first reaches full. GPIO output state controls charging hardware directly. Backup battery status is mostly static because shared work only updates `collie_bat_main`.

Dependencies and integration: depends on UCB1x00 MFD/ADC/GPIO, legacy machine detection and Collie platform GPIO lookup, power_supply core, interrupts, wakeup IRQ support, and global workqueue scheduling.

Risks and test signals: global state means only one device instance is supported. Backup battery registration exposes properties but update work never refreshes its status. ADC reads hold a global GPIO/ADC mutex and sleep while GPIOs are enabled; failure paths must turn GPIOs back off. `collie_bat_update()` assumes charge/full GPIOs are valid and only main battery has the full/charge-control hardware. Test on actual Collie machine detection, GPIO acquisition failures at each step, ADC scaling, full IRQ rising/falling, external power changes, suspend wake enable/disable, remove after pending work, and backup battery property reads.

# sources/distributed-fs/ceph-client/drivers/power/supply/cpcap-battery.c

Purpose: implements the Motorola CPCAP PMIC battery driver. It combines PMIC regmap coulomb-counter readings, IIO voltage/current/temperature channels, nvmem battery identification, charger interaction, low-battery interrupts, and power_supply properties to report and calibrate battery state on CPCAP-based phones.

Important APIs/types/functions: `struct cpcap_battery_ddata` owns the regmap, IIO channels, power_supply, IRQ descriptors, selected battery config, sampled state slots, coulomb-counter LSB scale, active flag, full-charge estimate, vendor, and NVMEM retry flag. Measurement helpers include `cpcap_charger_battery_temperature()`, `cpcap_battery_get_voltage()`, `cpcap_battery_get_current()`, `cpcap_battery_read_accumulated()`, and `cpcap_battery_cc_get_avg_current()`. State logic is in `cpcap_battery_update_status()`, `cpcap_battery_full()`, and `cpcap_battery_low()`. User API is `cpcap_battery_get_property()`, `cpcap_battery_set_property()`, and `cpcap_battery_property_is_writeable()`. Hardware setup uses `cpcap_battery_init_iio()`, `cpcap_battery_init_interrupts()`, and `cpcap_battery_calibrate()`.

Control flow: probe allocates state, tries to detect battery type from a fixed nvmem device and selects EB41, BW8X, or safe generic config, obtains parent CPCAP regmap and vendor, computes coulomb-counter scale, initializes IIO channels, registers the battery supply, registers PMIC interrupts, enables battery-detect bits, marks the device active, and calibrates the coulomb counter. Property reads call `cpcap_battery_update_status()` unless the last sample is too recent, refresh NVMEM detection when previously unavailable, and then derive status, capacity, charge, power, voltage/current, temperature, and design properties from latest/previous/full/empty samples. IRQ handling identifies the descriptor, logs calibration/low/poweroff events, may call `orderly_poweroff(true)` for critical low voltage while discharging, and notifies the battery supply. Writes allow constant charge voltage within design limits and manual charge-full calibration.

State and persistence: sampling state is stored in previous/latest/empty/full slots with timestamps and coulomb-counter snapshots. `charge_full` is learned from empty/full counter deltas or set by userspace, but it is not persisted by this driver. Battery configuration starts from nvmem ID defaults and can be overridden by `power_supply_battery_info`. Constant charge voltage writes update driver config and attempt to push a lower/equal value into the `"usb"` charger power supply. PMIC coulomb-counter calibration writes hardware registers; battery-detect interrupt enable is cleared on remove.

Dependencies and integration: depends on the CPCAP MFD regmap/vendor API, IIO channels named `battdetb`, `battp`, `chg_isense`, and `batti`, nvmem, power_supply core, a charger power supply named `"usb"`, orderly poweroff, platform IRQ names, and OF compatible `motorola,cpcap-battery`.

Risks and test signals: `cpcap_battery_detect_battery_type()` is called before `ddata->dev` is assigned in probe, so early logging can dereference a null device pointer if nvmem lookup/read fails. Capacity is unavailable until the driver observes empty/full anchors or userspace writes `CHARGE_FULL`; negative or excessive charge-now values reset calibration. `cpcap_battery_low()` uses a static `is_low`, so low-state history is shared across devices. Interrupt handler uses latest sampled state, which may be stale when deciding orderly poweroff. Temperature-probe ignore mode changes presence and TEMP semantics. Test vendor scale differences, nvmem present/missing/read-failure paths, IIO channel failures, coulomb calibration timeout/restore, full/empty learning, charger `"usb"` interactions, writable property bounds, all IRQ actions including low-poweroff thresholds, remove disabling BPEOL, and multi-instance assumptions.
