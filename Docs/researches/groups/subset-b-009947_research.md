# sources/user-network-fs/samba/source4/rpc_server/netlogon/dcerpc_netlogon.c

## Purpose

`sources/user-network-fs/samba/source4/rpc_server/netlogon/dcerpc_netlogon.c` implements Samba source4's server side for the NETLOGON DCE/RPC pipe. The file was read as a complete 5,411-line endpoint implementation. It handles secure-channel challenge/authentication, machine/trust password changes, SAM logon validation, workstation domain-info updates, DC locator requests, site lookup, trust enumeration, forest trust information, RODC-specific SAM and DNS update paths, and a long list of unsupported or intentionally faulting NETLOGON opnums. The generated server boilerplate is pulled in at the end via `ndr_netlogon_s.c`, so the static `dcesrv_netr_*` handlers are the operation bodies used by the generated dispatch table.

## Important APIs, Types, and Functions

Important endpoint integration is defined by `DCESRV_INTERFACE_NETLOGON_BIND`, `DCESRV_INTERFACE_NETLOGON_FLAGS`, and `dcesrv_interface_netlogon_bind()`. The bind hook warns once for dangerous global settings related to ZeroLogon and CVE-2022-38023 (`allow nt4 crypto`, `reject md5 clients`, `server schannel`, and `server schannel require seal`) before delegating to the common bind rejection/connection helper. The interface flags declare that NETLOGON does not use context handles, allowing invalid association groups to be accepted because no handle state needs cross-process coordination.

Secure-channel establishment is centered on `dcesrv_netr_ServerReqChallenge()`, `dcesrv_netr_ServerAuthenticateGeneric()`, `dcesrv_netr_ServerAuthenticate3_check_downgrade()`, `dcesrv_netr_ServerAuthenticateNTHash_cb()`, `dcesrv_netr_ServerAuthenticate3()`, `dcesrv_netr_ServerAuthenticate()`, `dcesrv_netr_ServerAuthenticate2()`, `dcesrv_netr_ServerAuthenticateKerberos_cb()`, and `dcesrv_netr_ServerAuthenticateKerberos()`. `netlogon_server_pipe_state` stores the request challenge on the DCE/RPC connection, while `schannel_save_challenge()`, `schannel_get_challenge()`, `schannel_delete_challenge()`, and `schannel_save_creds_state()` persist handshake data and final credentials in the schannel store. Authentication supports NT hash based trust secrets and, when configured, Kerberos-authenticated NETLOGON with DCERPC privacy and SID matching.

Password and trust-secret APIs are implemented by `dcesrv_netr_ServerPasswordSet()`, `dcesrv_netr_ServerPasswordSet2()`, `dcesrv_netr_ServerPasswordGet()`, `dcesrv_netr_ServerTrustPasswordsGet()`, and `dcesrv_netr_ServerGetTrustInfo()`. These validate the credential chain with `dcesrv_netr_creds_server_step_check()`, decrypt incoming password buffers with `netlogon_creds_decrypt_*()`, update SAM passwords through `samdb_set_password_sid()`, retrieve current and old NT hashes from either the user account or trusted-domain object, and encrypt returned hashes with `netlogon_creds_encrypt_samr_Password()`.

SAM logon flow is shared by `struct dcesrv_netr_LogonSamLogon_base_state`, `dcesrv_netr_LogonSamLogon_check()`, `dcesrv_netr_LogonSamLogon_base_call()`, `dcesrv_netr_LogonSamLogon_base_auth_done()`, `dcesrv_netr_LogonSamLogon_base_krb5_done()`, `dcesrv_netr_LogonSamLogon_base_reply()`, `dcesrv_netr_LogonSamLogonEx()`, `dcesrv_netr_LogonSamLogonWithFlags()`, and `dcesrv_netr_LogonSamLogon()`. It validates logon and validation levels, requires privacy for validation level 6, decrypts the supplied logon union, builds `auth_usersupplied_info`, verifies NTLMv2 responses for trust and RODC cases, and dispatches either to the auth subsystem or the KDC IRPC server for generic Kerberos validation.

Domain-control and locator APIs include `dcesrv_netr_LogonControl_base_call()` plus wrappers for `LogonControl`, `LogonControl2`, and `LogonControl2Ex`; `dcesrv_netr_GetDcName()`; `dcesrv_netr_GetAnyDCName()`; `dcesrv_netr_DsRGetDCName_base_call()` plus `DsRGetDCName`, `DsRGetDCNameEx`, and `DsRGetDCNameEx2`; `dcesrv_netr_DsRGetSiteName()`; `dcesrv_netr_DsRAddressToSitenamesExW()`; `dcesrv_netr_DsRAddressToSitenamesW()`; and `dcesrv_netr_DsrGetDcSiteCoverageW()`. The DC locator path validates MS-NRPC flag combinations, answers locally when possible, and otherwise forwards to winbind over IRPC.

Trust and forest helpers include `fill_our_one_domain_info()`, `fill_trust_one_domain_info()`, `fill_trusted_domains_array()`, `dcesrv_netr_LogonGetDomainInfo()`, `dcesrv_netr_DsrEnumerateDomainTrusts()`, `dcesrv_netr_DsRGetForestTrustInformation()`, and `dcesrv_netr_GetForestTrustInformation()`. RODC-specific helpers include `sam_rodc_access_check()`, `dcesrv_netr_NetrLogonSendToSam()`, `dcesrv_netr_DsrUpdateReadOnlyServerDnsRecords()`, and `netr_dnsupdate_RODC_callback()`. Many legacy opnums intentionally call `DCESRV_FAULT(DCERPC_FAULT_OP_RNG_ERROR)` or return `NT_STATUS_NOT_IMPLEMENTED`.

## Control Flow

The typical secure-channel setup begins with `netr_ServerReqChallenge`: existing connection pipe state is freed, a new `netlogon_server_pipe_state` is allocated, the client challenge is copied, a random server challenge is generated, the response credential is returned, connection state is stored, and the challenge pair is saved in the schannel challenge cache keyed by computer name. Authentication then enters `dcesrv_netr_ServerAuthenticateGeneric()`, which recovers the connection challenge or falls back to the global schannel challenge cache, computes the intersection of client and server negotiate flags, validates secure-channel type, locates the SAM or trusted-domain account, runs downgrade policy, checks account-control bits against the requested channel type, derives the client SID, and invokes the selected credential callback. The NT-hash callback verifies request credentials against current and sometimes previous trust secrets. The Kerberos callback requires KRB5 privacy on the DCE/RPC connection and an authenticated PAC SID matching the account SID. Successful credentials are saved to the schannel credential store for subsequent calls.

Password changes are credential-chain protected. `ServerPasswordSet` decrypts an OWF password and calls `samdb_set_password_sid()`. `ServerPasswordSet2` decrypts the 516-byte crypt-password buffer, extracts optional trust password version metadata for domain trust channels, decodes plaintext, rejects empty or all-zero values, and explicitly checks that length, confounder, and password bytes actually changed under encryption for AES/ARCFOUR paths before updating SAM. Trust password retrieval validates that request account name, channel type, and computer name match the stored credentials before reading and encrypting current/old trust hashes.

SAM logon wrappers normalize three public RPC shapes into `netr_LogonSamLogonEx`. The base call enforces schannel for the Ex shape unless Kerberos-authenticated credentials allow another path, rejects currently unsupported forest-routing flags, decrypts the logon union, and branches by logon type. Interactive and service logons pass password hashes into `auth_check_password_send()`. Network logons set the challenge on the auth context, pass LM/NT responses, and call `dcesrv_netr_NTLMv2_RESPONSE_verify()` to enforce trust and RODC constraints before async password validation. Generic Kerberos logons are forwarded asynchronously to the `kdc_server` IRPC endpoint. Async completions convert `auth_user_info_dc` into `netr_SamInfo2`, `netr_SamInfo3`, or `netr_SamInfo6`, encrypt the validation structure with netlogon credentials, copy the result status back to the wrapper's output, and call `dcesrv_async_reply()`.

Logon control validates old and new function/level combinations, handles query levels 1 and 3 locally, enforces administrator privileges for mutating controls, validates domain arguments for rediscovery, trust-controller, and password-change controls, and then forwards supported operations to the `winbind_server` IRPC endpoint with a 60-second timeout. DC locator flow validates all major MS-NRPC flag conflicts, normalizes an all-zero domain GUID to NULL, determines whether the requested domain/site/features can be answered locally, and either fills a local `netr_DsRGetDCNameInfo` from `fill_netlogon_samlogon_response()` or delegates to winbind. The winbind callback maps timeout and lookup failure statuses into WERROR values, verifies usable returned data, fixes missing UNC prefixes, overrides the client site with the local domain's site mapping, and replies asynchronously.

Domain info flow starts with credential-chain validation, reconnects to SAM as the workstation account so audit attribution reflects the machine, updates OS version, service pack, DNS hostname, and generated HOST SPNs when the client does not handle SPN updates itself, then returns local domain information, trusted-domain information, supported encryption types, LSA policy defaults, and workstation flags. Forest trust flow returns local xref forest trust info directly when no trusted domain is specified, but forwards remote forest-trust requests to winbind and requires root-domain, forest functional level, and optional PDC constraints. RODC SendToSam decrypts an opaque `netr_SendToSamBase`, supports reset of `badPwdCount`, and checks the RODC reveal/cache policy before permitting an RODC to reset arbitrary object state. RODC DNS updates are forwarded to the `dnsupdate` IRPC service after confirming the secure channel is `SEC_CHAN_RODC`.

## State and Persistence Behavior

The file uses several layers of state. Per-DCE/RPC-connection state stores the current challenge through `dcesrv_iface_state_store_conn()` under `NETLOGON_SERVER_PIPE_STATE_MAGIC`. The schannel challenge cache persists challenge material across connections for clients that authenticate on a different DCE/RPC connection, but entries are fetched/deleted to avoid reuse and are also deleted after downgrade policy completes. Final credential state is stored with `schannel_save_creds_state()` and read by later operations with `schannel_get_creds_state()` or advanced with `dcesrv_netr_creds_server_step_check()`.

Directory persistence is through SAMDB/DSDB. Machine and trust passwords are changed with `samdb_set_password_sid()`. Workstation attributes such as `operatingSystem`, `operatingSystemServicePack`, `operatingSystemVersion`, `dNSHostname`, and `servicePrincipalName` are replaced during `LogonGetDomainInfo`. `NetrLogonSendToSam` wraps the bad-password-count reset in an LDB transaction and commits only after GUID lookup, RODC access validation, message update, and `dsdb_replace()` succeed. Trust and domain information is mostly read-only in this file, pulled from trusted-domain objects, xref forest info, local TDO info, object SIDs, and account-control attributes.

Asynchronous state is explicitly held in talloc-owned state structs for SAM logon, logon control, DC locator, forest trust, and RODC DNS update requests. These structs retain the original `dcesrv_call_state`, normalized request, output pointers, and any wrapper back-pointers until callback completion. The code marks `DCESRV_CALL_STATE_FLAG_ASYNC` before returning from async send paths and completes the original RPC with `dcesrv_async_reply()`.

## Dependencies and Integration Points

Major dependencies are Samba's DCE/RPC server framework (`dcerpc_server.h`, generated NDR server stubs), auth subsystem (`auth/auth.h`, `auth_sam_reply.h`, `auth_context_create_for_netlogon()`, `auth_check_password_send()`), schannel/netlogon credential helpers (`schannel.h`, `schannel_util.h`, `netlogon_creds_*`), SAMDB/DSDB (`samdb.h`, trust parsing/search helpers, password setters, RODC replication policy helpers), loadparm configuration, IRPC messaging, KDC IRPC, winbind IRPC, dnsupdate IRPC, socket address helpers, and LSA/SAMR/NETLOGON generated NDR types.

Integration points are security-sensitive: schannel policy knobs drive downgrade rejection and warning behavior; generated NETLOGON NDR maps opnums to the static handlers; winbind supplies remote DC locator, logon control, and forest trust operations; kdc_server validates generic Kerberos logons; dnsupdate performs RODC DNS record updates; auth logging receives `auth_usersupplied_info` for NETLOGON secure-channel authentication; SAMDB audit attribution is deliberately switched to the workstation session for workstation metadata writes.

## Risks and Edge Cases

This file is security-critical because a missed credential, downgrade, or encryption check can affect domain trust, machine-password, and logon validation semantics. The explicit CVE-related warnings and downgrade detection show that weak crypto negotiation is a primary risk area. Challenge reuse is another risk, mitigated by connection-state replacement and schannel challenge deletion. `ServerPasswordSet2` has careful checks for unencrypted length, confounder, and password regions; regressions there would be high impact.

Compatibility behavior is intentionally Windows-like in several places, including returned negotiate flags on failure, special faults for invalid `LogonGetCapabilities` levels, ignored parameters such as old `DsRGetDCName` site GUID, unsupported replication opnums, and local assumptions that Samba is currently the forest root or only returns the default covered site. These compatibility choices are easy to break with seemingly cleaner validation. Async IRPC paths depend on timeout and callback handling; missing `DCESRV_CALL_STATE_FLAG_ASYNC`, stale output pointers, or callback status mapping bugs would surface as hung or malformed RPC replies.

RODC and trust paths have additional edge cases. RODC requests must not reset or cache arbitrary accounts outside allowed replication policy. Trust authentication can use current or previous secrets and must distinguish user-account data from trusted-domain object data. `DsRGetDCName` must reject invalid flag combinations before access checks and must decide carefully whether to answer locally or forward to winbind when feature flags exceed the local DC functional level.

## Test Signals

High-value test signals include NETLOGON secure-channel handshake tests covering same-connection and cross-connection challenge use, challenge deletion/reuse rejection, bad account type, disabled account, and trust account lookup failures; downgrade-policy tests for DES, MD5, AES, weak-crypto-disallowed, per-account overrides, Kerberos auth bypass of NT-hash requirements, and returned-negotiate-flag compatibility; password-set tests that verify encrypted buffer checks reject plaintext or zero buffers and that domain-trust password version extraction works; SAM logon tests for interactive, network, validation levels 2/3/6, privacy requirement, NTLMv2 trust verification, generic Kerberos IRPC success/failure, and encrypted validation replies; DC locator tests for each invalid flag combination, local answer versus winbind forwarding, site mismatch, UNC prefix normalization, and feature-level forced remote lookup; domain-info tests that assert workstation audit context, OS/SPN/DNS attribute updates, and trusted-domain output; RODC tests for SendToSam access policy and DNS update forwarding; and regression tests for intentionally unsupported opnums returning the expected fault or not-implemented status.

# sources/user-network-fs/samba/source4/rpc_server/remote/dcesrv_remote.c

## Purpose

`sources/user-network-fs/samba/source4/rpc_server/remote/dcesrv_remote.c` implements Samba source4's generic "remote" DCE/RPC endpoint server. The file was read as a complete 526-line proxy implementation. Instead of implementing a particular RPC interface itself, it registers configured local endpoints whose calls are decoded locally and forwarded to a configured upstream DCE/RPC binding using the matching NDR interface table. It preserves association-group state so multiple proxied interface connections can remain in the same remote association group and supports concurrent multiplexing when the incoming connection requires it.

## Important APIs, Types, and Functions

The private state types are `struct dcesrv_remote_assoc`, which stores the upstream `assoc_group_id` at association scope under `DCESRV_REMOTE_ASSOC_MAGIC`, and `struct dcesrv_remote_private`, which stores the connected upstream `struct dcerpc_pipe *c_pipe` at connection scope under `DCESRV_REMOTE_PRIVATE_MAGIC`. `remote_get_private()` is the main setup routine: it finds or creates connection and association state, reads `dcerpc_remote:binding`, optional configured `user`, `password`, and `domain`, `use_machine_account`, and `allow_anonymous_fallback`, chooses credentials, parses and decorates the binding, connects to the upstream pipe, checks multiplexing support, stores the upstream association group, and caches the pipe for later calls.

RPC operation hooks are `remote_op_bind()`, `remote_op_ndr_pull()`, `remote_op_dispatch()`, `remote_op_dispatch_done()`, `remote_op_reply()`, and `remote_op_ndr_push()`. `remote_op_ndr_pull()` validates opnum range, rejects calls with NDR pipes, allocates the call structure based on the interface table's generated `struct_size`, and pulls input NDR. `remote_op_dispatch()` obtains the upstream pipe, optionally prints input NDR debug, sets `DCERPC_NDR_REF_ALLOC`, sends the same opnum through `dcerpc_binding_handle_call_send()`, and marks the server call async. `remote_op_dispatch_done()` receives the upstream call, copies `last_fault_code` into the local call state, optionally prints output NDR, and uses `_dcesrv_async_reply()` to finish the local call. `remote_op_ndr_push()` pushes the output NDR back to the original caller.

Endpoint-server registration is handled by `remote_fill_interface()`, `remote_op_interface_by_uuid()`, `remote_op_interface_by_name()`, `remote_register_one_iface()`, `remote_op_init_server()`, `remote_op_shutdown_server()`, and `dcerpc_server_remote_init()`. The init function registers the `remote` endpoint server with the DCE/RPC subsystem and calls `ndr_table_init()` so all generated interface tables are available. `remote_op_init_server()` reads the configured `dcerpc_remote:interfaces` list, resolves each by name through the wrapped endpoint server, fills a proxy `dcesrv_interface`, and registers every endpoint name listed in the NDR table.

## Control Flow

Server startup calls `dcerpc_server_remote_init()`, which registers a static `dcesrv_endpoint_server` named `remote`. During endpoint initialization, `remote_op_init_server()` parses the configured interface list. For each interface name it asks the endpoint server for the NDR interface definition, fills a local proxy interface with remote operation hooks, and registers all endpoint names advertised by that interface. If no interfaces are configured, startup succeeds without registering proxied endpoints.

At call time, local DCE/RPC dispatch first runs `remote_op_ndr_pull()`, which uses the wrapped interface table to decode the incoming request into the generated request/response structure. `remote_op_dispatch()` then calls `remote_get_private()`. On the first call for a connection, `remote_get_private()` parses the upstream binding, sets any existing association group id, sets the abstract syntax to the current interface UUID/version, enables `DCERPC_CONCURRENT_MULTIPLEX` if the incoming connection is multiplexed, and connects with selected credentials. If the incoming call was multiplexed but the upstream pipe does not return multiplex support, the call fails with `NT_STATUS_INVALID_NETWORK_RESPONSE`. If this is the first upstream pipe for the association, the returned association group id is stored for later connections.

Once the upstream pipe exists, `remote_op_dispatch()` forwards the generated call structure to the upstream binding handle with the same opnum and interface table. The local call becomes asynchronous. `remote_op_dispatch_done()` receives completion, propagates upstream DCERPC fault codes if present, logs failures, leaves successful output in the original call structure, and replies asynchronously. Finally, the DCE/RPC server framework invokes `remote_op_ndr_push()` to encode the output side of the same generated structure for the original client.

## State and Persistence Behavior

The proxy keeps only in-memory DCE/RPC state. Connection-scoped state caches the upstream `dcerpc_pipe`, avoiding a new upstream connection for each call on the same local connection. Association-scoped state caches the upstream association group id so later upstream bindings can join the same association group. Both are talloc-owned through the server call/connection state store and are not file-backed. Credentials created inside `remote_get_private()` are temporary: configured user/password, machine-account, and anonymous credentials are allocated for connection setup and freed after `dcerpc_pipe_connect_b_recv()` completes; delegated credentials are borrowed from `dcesrv_call_credentials()`.

The module reads persistent Samba configuration through loadparm parametric options, but does not write configuration or database state. The only long-lived state it creates is the active upstream pipe and association id for the lifetime of the server connection/association.

## Dependencies and Integration Points

Direct dependencies include the DCE/RPC server framework, auth credentials, client DCE/RPC binding APIs, generated NDR interface tables, tevent/composite async primitives, and loadparm configuration. Runtime integration depends on `dcerpc_remote` smb.conf parameters: `binding` is mandatory, `interfaces` controls what local endpoints are proxied, `user` and `password` force explicit credentials, `use_machine_account` selects server machine credentials, and `allow_anonymous_fallback` permits anonymous proxying when no delegated credentials exist. The code also attempts to read a `domain` parameter, but the key string is spelled `"dceprc_remote"` rather than `"dcerpc_remote"`, so configured domains under the expected section may not be applied.

The interface discovery layer integrates with Samba's global generated NDR registry through `ndr_table_list()` and `ndr_table_by_name()`. Each proxied local `dcesrv_interface` keeps the real NDR table in `private_data`, so pull/dispatch/push use exactly the same generated marshalling routines as a normal endpoint implementation.

## Risks and Edge Cases

The proxy is intentionally generic, so it relies heavily on generated interface metadata being correct and compatible with the upstream server. Calls with in or out NDR pipes are rejected because the proxy does not support pipe semantics. Opnum range failures and NDR pull/push failures are translated into DCE/RPC faults. A mismatch between the local interface table and remote server implementation can produce decode failures, upstream faults, or subtly wrong output data.

Credential selection and configuration are high-risk operational areas. If no binding is configured, setup fails. If no explicit, machine, delegated, or anonymous credentials are available, setup fails. The apparent typo in the domain parameter section can cause explicit credentials to omit the intended domain. Enabling anonymous fallback can expose surprising access behavior depending on the upstream server. The proxy also must reject multiplexed local calls when the upstream binding does not negotiate `DCERPC_CONCURRENT_MULTIPLEX`, otherwise concurrent callers could be multiplexed onto a pipe that cannot safely handle them.

Association-group preservation is important for interfaces that rely on related context across binds even though this proxy does not own application handles itself. Failure to store or reuse the upstream association id would change behavior for clients that open related proxied connections. The async callback must preserve the original request structure until completion because the upstream call writes output into it before local NDR push.

## Test Signals

Useful tests include startup with no configured interfaces, invalid interface names, and interfaces with multiple endpoint names; missing or malformed `dcerpc_remote:binding`; explicit credentials, machine-account credentials, delegated credentials, anonymous fallback, and no-credential failure paths; configured domain handling that would expose the `dceprc_remote` typo; forwarding success for a simple no-pipe interface with input and output NDR debug flags; opnum out-of-range and NDR pull/push fault mapping; rejection of interfaces or calls with NDR pipes; association-group reuse across multiple proxied connections; multiplexed incoming calls against an upstream server that supports and one that rejects concurrent multiplexing; upstream DCE/RPC fault propagation through `last_fault_code`; and async lifetime tests ensuring the original call structure remains valid until `_dcesrv_async_reply()`.
