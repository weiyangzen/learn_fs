# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_bin.c

Purpose: validates normal `.bin` coefficient patch loading for `cs_dsp` across ADSP2 and Halo DSP address models. The file builds mock WMFW and WMDR/bin firmware, powers up a mock DSP, and verifies that coefficient patch blocks land in the expected cached regmap addresses without extra writes.

Important APIs/types/functions: the local fixture is `struct cs_dsp_test_local`, holding the mock bin builder, mock WMFW builder, and generated WMFW firmware. `struct bin_test_param` parameterizes memory type, word offset, algorithm index, and the patch-builder function. `bin_test_mock_algs` defines four mock algorithms used to exercise algorithm lookup. Core helpers include `_num_words_to_num_packed_regs()`, `cs_dsp_bin_test_common_init()`, the Halo/ADSP2 suite init functions, and KUnit parameter description functions. The test cases cover `bin_patch_one_word()`, `bin_patch_one_multiword()`, ordered and unordered multi-payload tests, sparse writes, multi-memory and multi-algorithm writes, many packed-memory boundary combinations, mixed packed/unpacked random writes, and `bin_patch_name_and_info()`.

Control flow: each case starts from a KUnit fixture whose init path allocates `struct cs_dsp_test`, registers a dummy KUnit device, initializes the mock regmap, writes a mock XM header into the regmap, creates a bin builder with a WMDR version, creates a minimal WMFW, initializes `cs_dsp` through `cs_dsp_adsp2_init()` or `cs_dsp_halo_init()`, and registers `cs_dsp_remove()` cleanup. Test bodies generate random payload data, compute the target algorithm base from the XM header, add one or more bin patch blocks through `cs_dsp_mock_bin_add_patch()` or `cs_dsp_mock_bin_add_patch_off32()`, convert the builder to a `struct firmware`, and call `cs_dsp_power_up()`. After load, they read back cached mock regmap content at computed addresses and compare it with expected payload bytes, then drop expected cache ranges and check `cs_dsp_mock_regmap_is_dirty()` to detect unexpected writes.

State and persistence behavior: all state is KUnit-scoped and memory-resident. The mock regmap is intentionally cache-only so test results are visible as cached writes. The XM header represents persistent DSP algorithm layout for the duration of one test. Random payloads make each run independent of fixed constants while equality checks preserve deterministic pass/fail behavior. Cleanup is registered with KUnit actions for device reference release and `cs_dsp_remove()`. The static stub for `cs_dsp_can_emit_message()` suppresses most logging unless built with `DEBUG`, which keeps the very large parameter matrix from flooding KUnit output.

Dependencies and integration points: depends on KUnit, KUnit devices/resources/static stubs, Linux firmware and regmap APIs, `cs_dsp` public and private headers, WMFW/WMDR format constants, and the Cirrus test utility builders from `cs_dsp_test_utils.h`. It integrates directly with the production load path through `cs_dsp_power_up()` and checks production address conversion through the mock memory-region helpers. It also exercises WMDR v1 and v3 behavior, including the v3 long-offset block builder.

Addressing coverage: the file explicitly distinguishes DSP-word offsets, regmap register addresses, unpacked register windows, and Halo packed register windows. ADSP2 suites cover 16-bit stride, 32-bit stride, and ZM availability. Halo suites cover unpacked XM/YM and packed XM/YM, including the packed conversion rule of three 32-bit registers for four DSP words. Packed tests verify aligned packed blocks, one/two/three trailing unpacked words, one/two/three leading unpacked words, contiguous and sparse packed blocks, unordered payload order, multiple algorithms, multiple memory regions, and mixed packed/unpacked offsets chosen by packed-boundary alignment.

Risks: because payloads are random, failures show up as equality mismatches but are not tied to stable fixture bytes for postmortem unless the failing KUnit log captures the values. The tests rely heavily on mock address helpers matching production assumptions; a shared bug in both helper and implementation could reduce detection. Cache cleanliness checks are a strong signal for unexpected writes, but each case must drop the correct expected ranges, so off-by-one errors in the test's drop range could either hide or falsely report dirty state. The long-offset cases intentionally use large offsets such as `0x10000` and `0x2f000`, so mock region sizing and address arithmetic must remain compatible.

Test signals: the registered suites are `cs_dsp_bin_halo`, `cs_dsp_bin_halo_wmdr_v3`, `cs_dsp_bin_adsp2_32bit`, and `cs_dsp_bin_adsp2_16bit`, all marked `KUNIT_SPEED_SLOW`. Passing signals include successful `cs_dsp_power_up()`, correct `regmap_raw_read()` values for every generated payload, clean mock regmap after expected writes and XM header cache entries are removed, correct handling of name/info blocks before patch data, and identical behavior for short and long offset patch encodings where applicable.

# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_bin_error.c

Purpose: validates `.bin` parser error handling for `cs_dsp` while preserving one positive behavior: unknown block types are skipped and later valid payload blocks still load. It focuses on malformed WMDR/bin headers, truncated files, invalid core versions, truncated blocks, and impossible block payload lengths.

Important APIs/types/functions: `struct cs_dsp_test_local` stores the bin builder, XM header, WMFW builder, generated WMFW firmware, and WMFW version. `struct cs_dsp_bin_test_param` parameterizes block type for block-level corruption tests. `cs_dsp_bin_err_test_mock_algs` defines the single mock algorithm needed by the generated XM header. Main cases are `bin_load_with_unknown_blocks()`, `bin_err_wrong_magic()`, `bin_err_too_short_for_header()`, `bin_err_bad_header_length()`, `bin_err_bad_core_type()`, `bin_too_short_for_block_header()`, `bin_too_short_for_block_payload()`, and `bin_block_payload_len_garbage()`.

Control flow: common init allocates the fixture, registers a KUnit device, initializes the mock regmap, creates a mock XM header and places its data block in a mock WMFW, creates a bin builder tied to the XM header firmware version, initializes ADSP2 or Halo `cs_dsp`, and suppresses production error logging through a static stub. Most negative tests first sanity-check that `cs_dsp_power_up()` succeeds with the WMFW alone, power the DSP down, mutate the generated bin firmware, and then require `cs_dsp_power_up()` with the bad bin to return a negative error. Truncation tests repeatedly shrink `bin->size` to sweep all shorter lengths around the header or block boundary.

State and persistence behavior: all mutated firmware objects are KUnit-owned and intentionally modified in place, including `bin->data`, `bin->size`, `struct wmfw_coeff_hdr`, and `struct wmfw_coeff_item` fields. This file does not persist DSP runtime state beyond a single case; the DSP is powered down after the positive WMFW sanity load before corrupt bins are tried. The static message hook avoids excessive error logs unless `DEBUG` is enabled.

Dependencies and integration points: depends on KUnit, static stubs, firmware/regmap APIs, Cirrus mock WMFW/bin/XM-header builders, WMFW coefficient header/item layouts, and `cs_dsp_power_up()` parser behavior. The block-type parameter set includes normal metadata/info-like values shifted into coefficient block space, real memory block types (`WMFW_ADSP2_PM`, `WMFW_ADSP2_XM`), and illegal values such as `0x33`, `0xf500`, and `0xc000`.

Positive parser behavior: `bin_load_with_unknown_blocks()` prepends unknown raw blocks, then appends a YM payload for the mock algorithm. It expects power-up success and verifies that the valid payload is written to the YM base address. This test is the signal that unsupported block types are not fatal when the file still contains valid patch content.

Negative parser behavior: wrong magic tests corrupt each byte of the expected `WMDR` marker plus all-zero magic. Header length tests sweep lengths below the real header length, just above it, and extreme values including `0xffffffff`, `0x80000000`, and `0x7fffffff`. Core type tests reject zero, one, a mismatched type relative to `priv->dsp->type`, and `0xff`. Block truncation tests distinguish files too short for a block header from files too short for the declared payload. Garbage length tests overwrite `wmfw_coeff_item.len` with large positive and sign-bit values that must be rejected.

Risks: direct mutation of `struct firmware` size and data relies on the mock builder returning writable KUnit memory, which is valid here but not representative of real firmware storage. The test asserts only negative return for malformed bins, not a specific errno, so it detects rejection but not error classification regressions. Because logging is suppressed outside `DEBUG`, diagnostic coverage must come from KUnit failures rather than emitted parser messages.

Test signals: the registered suites are `cs_dsp_bin_err_halo`, `cs_dsp_bin_err_adsp2_32bit`, and `cs_dsp_bin_err_adsp2_16bit`, each marked `KUNIT_SPEED_SLOW`. Passing signals are successful WMFW-only sanity loads, success for unknown-block skipping with valid YM payload readback, and negative `cs_dsp_power_up()` results for every malformed header, core type, truncation, block type, and payload-length parameter.

# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_callbacks.c

Purpose: verifies that `cs_dsp` invokes optional client callbacks at the right lifecycle points and safely handles empty or NULL callback tables. It covers coefficient-control add/remove callbacks, run/stop callbacks, and watchdog-expired callbacks for ADSP2v2 and Halo.

Important APIs/types/functions: `struct cs_dsp_test_local` records the mock WMFW builder, callback counters, passed coefficient-control pointers, and last passed DSP pointer. `struct cs_dsp_callbacks_test_param` parameterizes the client ops table. Callback implementations include `cs_dsp_test_control_add_callback()`, `cs_dsp_test_control_remove_callback()`, `cs_dsp_test_pre_run_callback()`, `cs_dsp_test_post_run_callback()`, `cs_dsp_test_pre_stop_callback()`, `cs_dsp_test_post_stop_callback()`, and `cs_dsp_test_watchdog_expired_callback()`. The full ops table is `cs_dsp_callback_test_client_ops`; `cs_dsp_callback_test_empty_client_ops` exercises an all-empty table.

Control flow: common init allocates fixture state, creates a dummy KUnit device, initializes the mock regmap, writes a mock XM header to the regmap, builds a WMFW with matching XM header data, assigns `dsp->client_ops` from the current parameter, initializes the DSP type, and registers `cs_dsp_remove()` cleanup. Runtime tests call `cs_dsp_power_up()`, `cs_dsp_run()`, `cs_dsp_stop()`, and `cs_dsp_remove()` and then inspect callback counters and captured pointers. Watchdog tests run the DSP, synthesize a watchdog condition, and call the ADSP2 or Halo watchdog/bus-error entry point.

State and persistence behavior: callback state is held in per-test counters and pointer arrays. Control callbacks store up to 16 `struct cs_dsp_coeff_ctl *` values so tests can compare callback order with `priv->dsp->ctl_list`. `passed_dsp` is reset between run/stop phases to verify that each callback supplies the active DSP pointer. Tests that explicitly call `cs_dsp_remove()` remove the registered KUnit cleanup action afterward to prevent double removal.

Dependencies and integration points: depends on KUnit, `kunit_get_current_test()` from callback context, KUnit device helpers, mock WMFW/XM-header builders, regmap, `cs_dsp` lifecycle APIs, and production interrupt helpers `cs_dsp_adsp2_bus_error()` and `cs_dsp_halo_wdt_expire()`. Coefficient control tests build WMFW algorithm-info blocks and coefficient descriptors using `cs_dsp_mock_wmfw_start_alg_info_block()`, `cs_dsp_mock_wmfw_add_coeff_desc()`, and `cs_dsp_mock_wmfw_end_alg_info_block()`.

Callback coverage: `cs_dsp_test_run_stop_callbacks()` verifies pre-run/post-run are called once per successful run and pre-stop/post-stop once per stop over two cycles. `cs_dsp_test_ctl_v1_callbacks()` creates ZM, YM, and XM controls for WMFW v1 and expects add/remove callbacks for each. `cs_dsp_test_ctl_v2_callbacks()` creates 16 short-named controls for WMFW v2/Halo and validates add/remove callback counts and order. `cs_dsp_test_no_callbacks()` runs power-up, run, stop, and remove with either an empty ops table or NULL ops and expects no counters to change. Watchdog tests verify callback dispatch when an ops table provides `watchdog_expired` and no dispatch when callbacks are absent.

Platform coverage: suites cover Halo with WMFW v3, ADSP2v2 32-bit with WMFW v2, ADSP2v1 32-bit with WMFW v2, ADSP2 16-bit with WMFW v1, ADSP2v2 watchdog handling, and Halo watchdog handling. ADSP2 watchdog synthesis writes `ADSP2_WDT_TIMEOUT_STS_MASK` to `base + ADSP2_LOCK_REGION_CTRL` before calling `cs_dsp_adsp2_bus_error()`. Halo watchdog synthesis calls `cs_dsp_halo_wdt_expire()` directly.

Risks: callbacks use `kunit_get_current_test()`, so these tests assume callbacks execute synchronously in the KUnit test context. The pointer-order checks depend on `ctl_list` traversal order and current control insertion behavior, making them useful regression signals but sensitive to intentional list-order refactors. The fixed `passed_ctl[16]` array matches the generated v2 control count; adding more controls without resizing would corrupt test-local state.

Test signals: registered suites are `cs_dsp_callbacks_halo`, `cs_dsp_callbacks_adsp2v2_32bit_wmfwv2`, `cs_dsp_callbacks_adsp2v1_32bit_wmfwv2`, `cs_dsp_callbacks_adsp2_16bit_wmfwv1`, `cs_dsp_watchdog_adsp2v2_32bit`, and `cs_dsp_watchdog_halo`. Passing signals include exact callback counts, correct DSP/control pointers, no callbacks for empty or NULL ops, successful lifecycle transitions, and one watchdog callback only when the client ops table supplies it.
