## sources/distributed-fs/openafs/src/afs/afs_daemons.c

Purpose: Implements long-running OpenAFS cache-manager daemons and the background request queue. It covers periodic client maintenance (`afs_Daemon`), server probing (`afs_CheckServerDaemon`), root volume discovery, queued background fetch/store/path operations, legacy AIX biod handling, and platform-specific SGI dcache-slot flushing.

Important APIs and functions: `afs_CheckServerDaemon` probes down servers at `afs_probe_interval` and all servers at `afs_probe_all_interval`. `afs_Daemon` is the main periodic maintenance loop, coordinating callbacks, dcache truncation wakeups, RX packet checks, token/cache cleanup, interface address changes, volume-name checks, root-volume checks, PAG GC, exporter GC, and shutdown progression. `afs_CheckRootVolume` resolves the root fid from dynroot or the configured/local `root.afs` volume with readonly fallback. `afs_BQueue`, `afs_BRelease`, `afs_BBusy`, and `afs_BackgroundDaemon` implement the `struct brequest` queue. Static workers `BPath`, `BPrefetch`, `BPrefetchNoCache`, `BStore`, `BPartialStore`, and `BInvalidateSegments` execute queued operations.

Control flow: Startup waits for `afs_initState >= 101`; the main daemon then runs timed blocks for sub-minute, 1-minute, 3-minute, 5-minute, 10-minute, and 60-minute work. Root volume initialization is retried until `afs_initState` reaches 300. `afs_CheckServerDaemon` can run separately; when absent, `afs_Daemon` performs server checks itself. Background callers allocate a request with `afs_BQueue`; background daemons select the unstarted request with the smallest timestamp, mark `BSTARTED`, run the matching operation, release held vnode/credential references, and wake waiters through `BUVALID`/`BUWAIT`. Under `AFS_NEW_BKG`, userspace operations such as Darwin `BOP_MOVE` can be returned to afsd and completed on re-entry via timestamp matching.

State and persistence: Global process/kernel state includes `afs_brs`, `afs_xbrs`, waiter counts, daemon counts, request timestamps, wait handles, probe intervals, PAG GC knobs, and init/termination state transitions. Requests hold vcache and credential references until `brequest_release`. No durable on-disk data is owned here; persistence is indirect via dcache writes, volume metadata, callbacks, and cache-manager state maintained in other modules.

Dependencies and integration points: Depends on cache-manager globals from `afsincludes.h`, callback queues, RX, volume lookup, vcache/dcache APIs, vnode lookup, credential reference helpers, exporter ops (`root_exported`, `EXP_GC`), dynamic root (`afs_GetDynrootEnable`, `afs_GetDynrootFid`), and platform OSI layers. `afs_BQueue` is used by vnode read/write/open/remove/rename and pioctl paths for prefetch, store, path prefetch, no-cache fetch, invalidate, and Darwin move work.

Risks: The daemon loops are shutdown-state machines, so incorrect term-state sequencing can hang teardown. Background request lifetime is subtle: vnode and credential refs must pair exactly with release paths, and `BUVALID` waiters need both raw and checked errors. Queue fairness depends on `afs_brs_count` monotonic ordering and bounded `NBRS` capacity. `BPrefetch` assumes the wakeup dcache pointer remains valid until the request releases it. The main daemon performs many unrelated maintenance jobs while holding the global lock except where explicitly dropped, so long-running work can affect latency. Platform-specific AIX/SGI sections have independent locking and signal behavior and are easy to regress accidentally.

Test signals: Exercise root fid discovery with dynroot enabled, explicit root volume, readonly fallback, missing primary cell, and truncated root names. Queue multiple background requests and verify timestamp ordering, waiter wakeups, `dontwait` behavior, vnode/cred reference release, and raw/checkcode propagation for store failures. Test shutdown transitions through AFS, check-server, truncate, background, and RX callback states. Cover separate and non-separate check-server daemon modes, cache-bypass prefetch, Darwin `AFS_NEW_BKG` re-entry, and periodic maintenance hooks with mocked time.

## sources/distributed-fs/openafs/src/afs/afs_dcache.c

Purpose: Implements the OpenAFS client data cache. It manages dcache lookup by fid/chunk, dslot allocation, LRU eviction, split-cache bucket accounting, persistent `CacheItems` slot I/O, memory-cache and UFS-cache backends, network fetch population, dynroot-backed synthetic data reads, write preparation, shadow directories for disconnected mode, and cache truncation/drain behavior.

Important APIs and functions: Hashing and bucket helpers include `DCHash`, `DVHash`, `afs_DCGetBucket`, `afs_DCAdjustSize`, `afs_DCMoveBucket`, and `afs_DCWhichBucket`. Cache pressure is handled by `afs_MaybeWakeupTruncateDaemon`, `afs_MaybeWaitForCacheDrain`, `afs_CacheTruncateDaemon`, `afs_GetDownD`, `afs_FreeDiscardedDCache`, and `afs_MaybeFreeDiscardedDCache`. Public lookup/write paths are `afs_FindDCache`, `afs_GetDCache`, `afs_IsDCacheFresh`, `afs_ObtainDCacheForWriting`, `afs_PopulateDCache`, `afs_TryToSmush`, and `afs_DCacheMissingChunks`. Slot persistence uses `afs_MemGetDSlot`, `afs_UFSGetDSlot`, `afs_WriteDCache`, `afs_WriteThroughDSlots`, `afs_InitCacheFile`, `afs_dcacheInit`, and `shutdown_dcache`. Disconnected helpers are `afs_MakeShadowDir` and `afs_DeleteShadowDir`.

Control flow: `afs_GetDCache` first computes the chunk, tries the vcache hint, then scans the fid/chunk hash chain. On miss it wakes or invokes eviction, allocates from the free or discarded lists, initializes the dcache, links it into both hash tables, and then checks freshness. Stale entries are write-locked, text/pages are flushed when needed, cache-drain thresholds can force retry, expected fetch size is computed from file length/truncation state, and data is fetched either from dynroot memory or via `afs_CacheFetchProc`. Successful fetches update chunk size, data version, status/callback fields, LRU time, and hints; failures zap/truncate the slot and stale the vcache. `afs_ObtainDCacheForWriting` wraps this for writes, marking `IFDataMod` and `DWriting`.

State and persistence: Core state is global: dcache hash tables (`afs_dchashTbl`, `afs_dvhashTbl`), next arrays, index-to-dcache table, unique/time/flag arrays, LRU queue, free and discarded dcache lists, free in-memory dslot list, block counters, discarded block counters, split-cache bucket counters, cache geometry, and the active cache backend. Persistent state is the UFS `CacheItems` file, written by `afs_WriteDCache`, plus per-cache chunk files addressed through `afs_cacheType` operations. Memory cache avoids `CacheItems` writes but shares the same logical dcache state.

Dependencies and integration points: Integrates with vnode operations for reads/writes/directory ops, `afs_segments.c` for stores/truncation, `afs_fetchstore.c` for network fetches, `afs_buffer.c` directory buffer I/O, dynroot for synthetic `/afs` data, disconnected replay for shadow dirs and fake fids, OS VM page invalidation hooks, RX connection analysis, stats/tracing, and OS-specific cache inode/path helpers. `afs_cacheOps` abstracts UFS versus memory cache backends.

Risks: This file is lock-order-sensitive: `afs_xdcache`, dcache `tlock`, dcache data locks, vcache locks, and VM locks are combined in many paths. Eviction drops and reacquires `afs_xdcache` while holding candidate references, so refcount and flag rechecks are essential. Hash corruption is possible if zero-volume or stale-fid entries are written as active. Cache-size sanity checks deliberately ignore some RW/local sparse-file cases; changing them can cause false corruption reports or stale reads. Discarded entries reuse space before truncation, so block accounting and wait wakeups must stay consistent. `afs_MakeShadowDir` allocates and hashes a fresh dcache before copying data; partial-copy failures can leave cleanup-sensitive state. Persistent UFS slot reads tolerate invalid entries differently for `DSLOT_NEW`, `DSLOT_UNUSED`, and `DSLOT_VALID`, and panics are intentional for impossible states.

Test signals: Validate cache initialization for UFS and memory backends, bad cache file detection, `CacheItems` read/write errors, and shutdown cleanup. Exercise hit, hint hit, miss, stale DV, dynroot fetch, network fetch, fetch error, disconnected stale miss, whole-chunk overwrite, sparse write extension, and cache-drain retry paths. Stress eviction with active refs, dirty pages, dirty data, split-cache buckets, discarded lists, and truncate-daemon wake/sleep behavior. Test shadow-dir create/delete and disconnected fake-fid lookup. Add instrumentation or assertions around hash-chain membership, refcounts, `IFDataMod`/`IFDiscarded`/`IFFree`, block counters, and LRU timestamps.

## sources/distributed-fs/openafs/src/afs/afs_disconnected.c

Purpose: Implements disconnected-mode dirty-state reconciliation for the OpenAFS cache manager. It tracks dirty vcaches and shadow directories, generates local fake fids/status for offline creates, resolves names and parents from cached directories, replays create/remove/rename/status/store operations to fileservers, and discards or preserves local changes according to conflict policy.

Important APIs and functions: `afs_FindDCacheByFid` locates the first dcache for an exact fid. `afs_ResyncDisconFiles` is the main replay loop. Operation-specific replay is split into `afs_ProcessOpCreate`, `afs_ProcessOpRemove`, `afs_ProcessOpRename`, and `afs_SendChanges`. Local metadata helpers include `afs_GenStoreStatus`, `afs_GetParentDirFid`, `afs_GetVnodeName`, `afs_GetParentVCache`, `afs_CheckDeletedChildren`, `afs_FixChildrenFids`, `afs_GenShadowFid`, `afs_GenFakeFid`, and `afs_GenDisconStatus`. Cleanup APIs are `afs_DisconDiscardAll`, `afs_DisconDiscardAllShadows`, and debug listing via `afs_DbgListDirEntries`.

Control flow: Offline vnode operations mark `ddirty_flags` and may create shadow dirs via dcache code. On reconnection, `afs_ResyncDisconFiles` processes `afs_disconDirty` from the tail while dropping the dirty-list lock to acquire each vcache lock. Removes replay first and terminate further work for that vnode. Creates allocate server objects, then rewrite the parent directory entry, vcache hash membership, dcache hash membership, `afs_indexUnique`, and the vnode fid from fake to server-assigned fid. Renames recover old names from shadow directories and new names from current directories. For existing objects, the code fetches server status, compares data version/modtime, applies `CLIENT_WINS`/`SERVER_WINS`/created-file policy, then sends attributes and data changes.

State and persistence: Dirty state is in process/kernel memory: circular queues `afs_disconDirty` and `afs_disconShadow`, `afs_disconDirtyLock`, per-vcache `ddirty_flags`, old-parent and shadow fid fields, and the fake-vnode counter `afs_DisconVnode`. Shadow directories are persisted as dcache chunks with generated fids until replay/discard. Conflict policy defaults to `SERVER_WINS`. There is no independent durable journal; correctness depends on cached vcache/dcache metadata and shadow directory copies surviving long enough for reconciliation.

Dependencies and integration points: Uses dcache hash tables and slot APIs, directory enumeration/change helpers, vcache hash queues, RXAFS RPCs (`CreateFile`, `MakeDir`, `Symlink`, `RemoveFile`, `RemoveDir`, `Rename`, `FetchStatus`, `StoreStatus`), `afs_Analyze`, `afs_UpdateStatus`, `afs_StoreAllSegments`, and vnode operation code that marks disconnected dirty flags. `discon.h` exposes key entry points to VNOPS code.

Risks: Replay ordering is hard: children of locally created directories must wait for the parent to get a server fid, and removed non-empty directories with dirty deleted children are deferred with `EAGAIN`. Fake-to-real fid promotion rewrites vcache and dcache hash chains while holding global locks; missed dcaches or stale uniques can make data unreachable or alias wrong files. Name recovery depends on cached parent/shadow directory entries, so missing dcaches return network-like errors and abort reconciliation. Conflict handling is incomplete for `LAST_CLOSER_WINS`/`ASK`, and `SERVER_WINS` resets local state. Symlink target extraction reads cached data and caps at 1024 bytes. Several TODO/printf comments indicate partial error handling.

Test signals: Build disconnected scenarios for create file/dir/symlink, write, truncate, chmod/mtime, rename same-dir and cross-dir, remove file/dir, nested creates, and dirty deleted children. Verify fake fid uniqueness, vcache/dcache hash rewrites, parent fid updates in child vcaches and `..` entries, shadow-dir creation/deletion, and queue reordering on `EAGAIN`. Test conflict policies with matching DV, server-changed DV, server-changed mtime, and created files. Simulate missing parent/shadow dcaches and RPC failures to ensure dirty state remains recoverable.

## sources/distributed-fs/openafs/src/afs/afs_dynroot.c

Purpose: Implements dynamic `/afs` root support. Instead of requiring a real `root.afs` volume, it synthesizes a dynroot cell/volume, builds an in-memory directory containing configured cells, aliases, a dynamic mount directory, and root-created temporary symlinks, and maps synthetic vnodes to symlink or directory statuses.

Important APIs and functions: Initialization/control functions are `afs_InitDynroot`, `afs_SetDynrootEnable`, `afs_GetDynrootEnable`, and `afs_dynrootCellInit`. Fid/type predicates and constructors include `afs_IsDynrootVolume`, `afs_IsDynrootFid`, `afs_IsDynrootMountFid`, `afs_IsDynrootAnyFid`, `afs_GetDynrootFid`, `afs_GetDynrootMountFid`, `afs_IsDynroot`, `afs_IsDynrootMount`, and `afs_IsDynrootAny`. Directory generation is handled by `afs_RebuildDynroot`, `afs_RebuildDynrootMount`, `afs_dynroot_computeDirEnt`, and `afs_dynroot_addDirEnt`. Consumers call `afs_GetDynroot`, `afs_GetDynrootMount`, `afs_PutDynroot`, and `afs_DynrootNewVnode`. Mutating VOP hooks are `afs_DynrootVOPSymlink` and `afs_DynrootVOPRemove`.

Control flow: Enabling dynroot creates a synthetic `dynroot` cell and records its cell number. `afs_DynrootInvalidate` increments a version/high-version timestamp and stales the root vcache. `afs_GetDynroot` rebuilds the directory lazily when no buffer exists or the directory version lags. Rebuild first computes required pages by walking cells, aliases, and dynamic symlinks, then allocates a directory blob, initializes directory page/header structures, inserts `.`, `..`, `.:mount`, cell names, dot-cell variants, aliases, dot-alias variants, and user symlinks with encoded vnode numbers. `afs_DynrootNewVnode` recognizes root, mount directory, cell/alias/mount/symlink vnode types, fills `AFSFetchStatus`, allocates `linkData` for synthetic symlinks, and sets vcache type.

State and persistence: Process/kernel state includes enable/init flags, synthetic cell number, dynroot directory buffers and lengths, link count, directory version counters, dynroot mount directory buffer, and a linked list of temporary symlinks with monotonically increasing indexes. Locks are split between `afs_dynrootDirLock` and `afs_dynSymlinkLock`. There is no on-disk persistence for user-created dynroot symlinks; they live only in memory until shutdown.

Dependencies and integration points: Integrates with cell/cell-alias registries, volume/root fid discovery (`afs_CheckRootVolume`), dcache fetches for dynroot directory data, vcache creation (`afs_DynrootNewVnode` is called from vcache code), lookup invalidation from cell changes, directory blob layout from `afs/dir.h`, access bits from `prs_fs.h`, and VNOPS symlink/remove paths for privileged temporary entries.

Risks: `afs_InitDynroot` initializes locks but leaves `afs_dynrootInit` as 0, so callers repeatedly run initialization logic; this appears intentional or historical but is worth guarding in refactors. Directory rebuild holds the symlink read lock while allocating/filling the directory and assumes cell/alias indexes stay meaningful between compute and fill passes. Vnode numbers encode cell/alias indexes, so deleted/reordered cell tables can produce stale vnode inconsistencies logged as warnings. Root-only symlink creation/removal checks uid but temporary links are not durable. `afs_DynrootNewVnode` may allocate `linkData`; ownership must match vcache cleanup.

Test signals: Enable/disable dynroot, verify root fid and mount fid, and fetch `/afs` and `.:mount` through dcache. Add/remove cells and aliases and confirm invalidation/version/status changes. Lookup normal and dot-cell entries, aliases with and without real names, user-created symlinks, and mount vnodes by volume id. Test non-root symlink/remove rejection, collisions with cells/aliases, stale vnode indexes, shutdown buffer freeing, and fakestat behavior for symlink-to-directory presentation.

## sources/distributed-fs/openafs/src/afs/afs_dynroot.h

Purpose: Defines the vnode-number encoding contract used by dynamic `/afs` root support. The header is intentionally small but central: `afs_dynroot.c`, vcache creation, and lookup code depend on these macros to interpret synthetic vnodes as cells, aliases, temporary symlinks, or dynamic mount points.

Important APIs and definitions: Vnode type constants are `VN_TYPE_CELL`, `VN_TYPE_ALIAS`, `VN_TYPE_SYMLINK`, and `VN_TYPE_MOUNT`. `VNUM_TO_VNTYPE` extracts the high 8-bit type, `VNUM_TO_VNID` extracts the low 24-bit payload, and `VNUM_FROM_TYPEID` creates an encoded vnode. Cell/alias helpers map payload bits: `VNUM_TO_CIDX`, `VNUM_TO_RW`, `VNUM_FROM_CIDX_RW`, and `VNUM_FROM_CAIDX_RW`. `AFS_DYNROOT_MOUNTNAME` defines the synthetic mount directory name `.:mount`.

Control flow: Header-only macros have no runtime flow. They define how `afs_RebuildDynroot` assigns vnode numbers for directory entries and how `afs_DynrootNewVnode` decodes those vnode numbers later to construct symlink targets and statuses.

State and persistence: No state is stored here. The encoded vnode format is persistent within live vcaches and directory blobs for the current client runtime. It is not a disk format in this file, but changing it can invalidate assumptions across cached dynroot entries.

Dependencies and integration points: Included by `afs_dynroot.c`; the values correspond to `struct cell` indexes, `struct cell_alias` indexes, dynamic symlink indexes, and dynroot mount handling. The bit layout relies on OpenAFS vnode numbers being wide enough for an 8-bit type plus 24-bit id.

Risks: The macros do not mask inputs in `VNUM_FROM_TYPEID`, so oversized type/id values can overlap fields. Cell and alias indexes are encoded, not stable names; stale vcaches after cell-table changes can decode to missing objects and trigger inconsistency warnings. `VNUM_TO_RW` uses one bit to distinguish readonly/dot entries, limiting future payload expansion unless the layout is revised carefully.

Test signals: Static/unit tests should round-trip type/id, cell index/readwrite flag, and alias index/readwrite flag values. Dynroot integration tests should assert that entries generated by `afs_RebuildDynroot` decode to the expected branch in `afs_DynrootNewVnode`, including `.:mount` and user symlink entries.

## sources/distributed-fs/openafs/src/afs/afs_error.c

Purpose: Normalizes AFS, unified-AFS, volume, network, and request-state errors into OS-facing errno-style values for vnode and pioctl callers. It also initializes and copies per-request error state used by `afs_Analyze` and higher-level operations.

Important APIs and functions: `init_et_to_sys_error` populates a 512-entry table from unified-AFS error constants (`UAE*`) to local errno values. `et_to_sys_error` maps an error-table value back to system errno when possible. `afs_FinalizeReq` initializes a `struct vrequest` error state. `afs_CopyError` transfers server skip/error arrays and aggregate flags between requests. `afs_CheckCode` is the central finalizer that traces raw errors and applies request-context overrides.

Control flow: `afs_CheckCode` first logs non-zero codes, translates unified error-table values, and returns immediately if no initialized request is supplied. Initialized request flags take precedence over raw code: network errors become `ETIMEDOUT`, access errors become `EACCES`, volume errors map to `ENODEV`, `EWOULDBLOCK`, or `EIO`, and selected server codes (`VNOVNODE`, `VDISKFULL`, `VOVERQUOTA`, `VNOSERVICE`) map to OS errors. Otherwise the raw/translated code is returned.

State and persistence: The only module state is the static `et2sys` mapping table, populated at initialization. `struct vrequest` carries transient per-operation state: skipserver/lasterror arrays, busy count, idle/token/access/volume/network/perm-write flags, and `initd`. No durable state is written.

Dependencies and integration points: Depends on generated/defined unified-AFS error constants, errno availability, OpenAFS volume error constants, stats/tracing, and `struct vrequest` semantics. `afs_CheckCode` is used broadly by platform vnode ops, VNOPS implementations, pioctl handling, background stores, Linux exporter paths, and cache-bypass reads.

Risks: `init_et_to_sys_error` assumes every referenced `UAE* - ERROR_TABLE_BASE_uae` index fits within 512 entries; new constants outside that range would write out of bounds unless guarded. `afs_CheckCode` intentionally hides raw errors when request flags are set, which can reduce diagnostic specificity. Some mappings are platform-conditional (`EDQUOT`) or historical (`VNOSERVICE` as timeout), so cross-platform behavior can differ.

Test signals: Verify every populated unified-AFS mapping, unmapped in-range values, and out-of-range passthrough. Exercise `afs_CheckCode` with no request, uninitialized request, network/access/volume flags, quota/full/no-service/vnovnode codes, and combined flags to confirm precedence. Callers that wait on background stores should check both raw and checkcode values.

## sources/distributed-fs/openafs/src/afs/afs_exporter.c

Purpose: Maintains the cache-manager registry of "AFS exporters", such as the NFS exporter. Exporters provide operation vectors that other cache-manager code can discover and periodically garbage collect.

Important APIs and functions: `exporter_add` lazily initializes `afs_xexp`, allocates an exporter object of caller-specified size or `sizeof(struct afs_exporter)`, appends it to `root_exported`, and fills operation, state, data, and type fields. `exporter_find` scans the registry for a matching type. `shutdown_exporter` frees the linked list and resets initialization state.

Control flow: The registry is append-only during normal operation. On first add, the lock is initialized. Adds walk to the tail under the write lock, link the new node, release the lock, then initialize fields. Finds take the read lock and return the matching pointer after releasing the lock. Shutdown walks `root_exported` and frees nodes without taking the exporter lock.

State and persistence: Global state is `root_exported`, `afs_xexp`, and `init_xexported`. Entries are heap allocations with caller-owned `exp_data` and operation-vector pointers. There is no on-disk persistence.

Dependencies and integration points: Uses `struct afs_exporter` and `struct exporterops` from AFS headers, OSI allocation/free, locks, stats, and the daemon maintenance loop. `afs_nfsclnt.c` registers the NFS exporter; `afs_pioctl.c` discovers exporters for exporter-related pioctls; `afs_Daemon` iterates `root_exported` and calls `EXP_GC` every ten-minute cycle.

Risks: `exporter_add` links the new node before fully initializing its fields, so concurrent readers could observe a partially initialized exporter. `exporter_find` returns an unlocked raw pointer with no refcount, so lifetime must be controlled by subsystem shutdown ordering. `shutdown_exporter` frees every node as `sizeof(struct afs_exporter)` even when `exporter_add` allocated a larger caller-specific size. It also does not clear `root_exported`, leaving a stale pointer after shutdown unless cold shutdown ordering prevents reuse.

Test signals: Register one and multiple exporters, find by existing/missing type, and verify daemon GC sees entries. Stress concurrent add/find if supported by target platforms. Test shutdown after variable-size allocations and ensure callers do not dereference stale exporter pointers. Static review should confirm `exp_data` ownership and cleanup responsibilities outside this file.
