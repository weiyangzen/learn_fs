# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_fcp.c

Purpose: implements libfc's Fibre Channel Protocol SCSI command path. It converts Linux `scsi_cmnd` requests into FCP command exchanges, receives transfer-ready, data, status, and BLS frames, maps FCP/transport outcomes back into SCSI results, and provides SCSI error-handling hooks for abort, LUN reset, and host reset. It also manages direct data placement, sequence recovery with REC/SRR, queue-depth backoff on allocation or target congestion, and cleanup when local or remote ports disappear.

Important APIs/types/functions: `struct fc_fcp_internal` is per-lport FCP private state containing the mempool, active packet list, queue lock, and adaptive `can_queue` timestamps. `fc_fcp_pkt_alloc()`, `fc_fcp_pkt_release()`, `fc_fcp_pkt_hold()`, and `fc_fcp_pkt_destroy()` manage `struct fc_fcp_pkt` lifetime. `fc_queuecommand()` is the SCSI host-template queue entry. `fc_fcp_pkt_send()` builds the command IU and inserts it into `scsi_pkt_queue`; `fc_fcp_cmd_send()` sends the unsolicited FCP command frame through the exchange layer. `fc_fcp_recv()`, `fc_fcp_recv_data()`, `fc_fcp_send_data()`, and `fc_fcp_resp()` implement the receive/send fast path. `fc_fcp_timeout()`, `fc_fcp_rec()`, `fc_fcp_srr()`, and their response/error handlers implement recovery. `fc_io_compl()` translates libfc status codes into `scsi_cmnd->result`. Exported SCSI EH hooks are `fc_eh_abort()`, `fc_eh_device_reset()`, `fc_eh_host_reset()`, and `fc_sdev_init()`. Layer setup/teardown is via `fc_setup_fcp()`, `fc_destroy_fcp()`, `fc_fcp_init()`, and `fc_fcp_destroy()`.

Control flow: SCSI calls `fc_queuecommand()`, which validates remote-port readiness, checks lport/link/queue state, allocates an FCP packet, records transfer direction and byte counters, then calls `fc_fcp_pkt_send()`. The packet is linked into the active queue before the transport-template `fcp_cmd_send()` sends the command. Incoming frames are dispatched by `fc_fcp_recv()`: BLS frames are ABTS responses, transfer-ready frames call `fc_fcp_send_data()` for writes, solicited data frames call `fc_fcp_recv_data()` for reads, and command-status frames call `fc_fcp_resp()`. Completion converges through `fc_fcp_complete_locked()` and `fc_io_compl()`, which clear timers, release DDP resources, remove the active-list entry, null `libfc_cmd_priv(scsi_cmnd)->fsp`, call `scsi_done()`, and drop the initial packet reference.

State and persistence: state is in memory only. Per-command state includes the `FC_SRB_*` bitmask, `seq_ptr`, optional `recov_seq`, DDP XID, transferred/contiguous lengths, residuals, SCSI/FCP status, recovery retry count, timer function/delay, wait-for-completion flag, and a packet refcount. Per-lport FCP state tracks active packets and queue-depth ramp timing. Hardware-visible state is transient exchange/sequence traffic, optional lower-level DDP setup, and abort/reset exchanges. No persistent storage exists.

Dependencies and integration: depends on SCSI midlayer APIs, `scsi_transport_fc`, libfc exchange/sequence/template operations, `fc_frame` allocation and SG-copy helpers, FC ELS/BLS/FCP protocol structures, CRC helpers, mempools/slab, timers, completions, and lport/rport private state. Low-level drivers can override `tt.fcp_cmd_send`, `tt.fcp_cleanup`, `tt.fcp_abort_io`, `ddp_setup`, and `ddp_done`.

Risks and test signals: high-risk areas are lock/refcount ordering between command completion, timers, exchange callbacks, and SCSI EH; cleanup intentionally drops `scsi_pkt_lock` around exchange teardown. DDP fallback treats unexpected data frames as transport errors. REC/SRR recovery relies on remote support flags, in-order assumptions, and correct contiguous-offset tracking. Queue-depth ramping mutates `host->can_queue` under pressure and should be exercised under allocation failure and `qfull`. Test reads/writes/control commands, transfer-ready overrun, data underrun/overrun, CRC unchecked paths, response-before-data ordering, FCP confirmation, REC unsupported/rejected/timeouts, SRR accept/reject/timeouts, ABTS success/reject/race with completion, LUN reset cleanup by ID/LUN, link-down cleanup, host reset readiness polling, DDP setup/done, and destroy-time leak detection.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_frame.c

Purpose: provides the small frame allocation and CRC helper layer used by libfc. It creates transmit `fc_frame` objects backed by sk_buffs with libfc headroom/tailroom and verifies received frame CRCs when hardware or the lower layer has left the CRC unchecked.

Important APIs/types/functions: `fc_frame_crc_check()` clears `FCPHF_CRC_UNCHECKED`, recomputes the Fibre Channel CRC over the header plus payload rounded to a 4-byte fill boundary, and returns the XOR error value. `_fc_frame_alloc()` allocates an fclone skb with `FC_FRAME_HEADROOM`, `FC_FRAME_TAILROOM`, and `NET_SKB_PAD`, initializes it as an `fc_frame`, and sizes it for the FC header plus payload. `fc_frame_alloc_fill()` adds zero fill for non-4-byte payloads, allocates through `_fc_frame_alloc()`, then trims the visible skb length back to the requested header plus payload length.

Control flow: callers normally use higher-level `fc_frame_alloc()` or `fc_frame_alloc_fill()` from protocol code. For transmit, allocation reserves headroom, casts the skb storage to `struct fc_frame`, initializes frame metadata, and grows the skb to include header and payload. For receive validation, `fc_frame_crc_check()` assumes a linear frame, computes CRC from `fr_hdr(fp)` over padded length, compares it to `fr_crc(fp)`, and returns zero on match.

State and persistence: there is no persistent or global state. The functions manipulate per-frame skb length, metadata flags, and fill bytes. Allocations are atomic (`GFP_ATOMIC`) because frames are often created from softirq or protocol callback contexts.

Dependencies and integration: depends on Linux sk_buff/fclone allocation, CRC32, and `scsi/fc_frame.h` accessors. It is used by the FCP path, ELS/CT builders, exchange code, and response helpers that need correctly padded Fibre Channel frames.

Risks and test signals: `_fc_frame_alloc()` warns on unaligned payload sizes, while `fc_frame_alloc_fill()` handles unaligned payloads by padding and trimming; callers must choose the right helper. CRC checking warns if the skb is non-linear, so lower layers must linearize before asking software to verify CRC. Test zero-length payloads, non-4-byte payload fill, allocation failure paths, CRC success/failure with fill bytes, and callers that pass fragmented frames with `FCPHF_CRC_UNCHECKED`.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_libfc.c

Purpose: provides libfc module initialization, global FC-4 provider registration, lport notifier/list management, and shared utility routines for scatterlist copying and Fibre Channel header construction. It is the central glue file tying FCP, exchange manager, rport, lport, and optional FC-4 providers together.

Important APIs/types/functions: module state includes `fc_debug_logging`, `fc_prov_mutex`, `fc_local_ports`, `fc_lport_notifier_head`, `fc_active_prov[]`, and `fc_passive_prov[]`. `libfc_init()` initializes FCP packet cache, exchange manager, and rport event queue; `libfc_exit()` tears them down. `fc_copy_buffer_to_sglist()` copies a linear buffer into a scatterlist and can update a CRC over copied bytes. `fc_fill_hdr()` and `fc_fill_reply_hdr()` construct FC headers and handle end-sequence fill/eof decisions. Provider management is through `fc_fc4_register_provider()`, `fc_fc4_deregister_provider()`, and `fc_fc4_conf_lport_params()`. Lport visibility is handled by `fc_fc4_add_lport()`, `fc_fc4_del_lport()`, and exported `fc_lport_iterate()`.

Control flow: module load calls setup in dependency order: FCP cache first, exchange manager second, rport queue last; failures unwind in reverse for the initialized pieces. Module exit destroys FCP, exchange manager, and rport resources. Protocol code uses `fc_fill_reply_hdr()` to start a response sequence if the request frame has an active sequence, then delegates to `fc_fill_hdr()`. Provider registration selects the active table when `prov->recv` is absent and passive table when it is present; deregistration clears the selected slot under `fc_prov_mutex` and waits for RCU readers. Lports are added to `fc_local_ports` and broadcast to a blocking notifier chain so providers can attach per-lport behavior.

State and persistence: global provider tables, the local-port list, notifier chain, and debug bitmask live for the module lifetime only. Per-copy state in `fc_copy_buffer_to_sglist()` is the caller-owned SG pointer, remaining entry count, offset, and optional CRC accumulator. No configuration is persisted outside module parameters.

Dependencies and integration: depends on libfc setup functions from FCP, exchange, and rport code; Linux scatterlist, kmap_atomic, CRC32, RCU, mutexes, and notifier chains; and Fibre Channel frame/header structures. `fc_lport.c` registers local ports here, `fc_rport.c` consumes provider tables for PRLI/PRLO, and upper FC-4 modules can register active or passive providers.

Risks and test signals: `fc_copy_buffer_to_sglist()` mutates `nents` and `offset`, maps only one page at a time, and silently stops at SG exhaustion, so callers must validate returned length. `fc_fill_hdr()` calls `skb_put_zero()` for end-sequence fill and warns for non-last unaligned frames; fragmented skb assumptions are noted as a TODO. Provider registration has a single slot per type/direction and returns `-EBUSY` on collision. Test module init unwind at each failure point, provider register/deregister under concurrent `fc_lport_recv()` RCU readers, lport notifier add/delete ordering, SG copy across page and SG boundaries, CRC accumulation, and header fill for first/middle/last sequences.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_libfc.h

Purpose: declares libfc-private logging controls, FC-4 provider globals, setup/teardown hooks, DDP helpers, lport/provider utility functions, and the shared SG-copy helper. It is an internal coordination header for libfc implementation files, not a userspace or low-level-driver public ABI.

Important APIs/types/functions: logging bit definitions include `FC_LIBFC_LOGGING`, `FC_LPORT_LOGGING`, `FC_DISC_LOGGING`, `FC_RPORT_LOGGING`, `FC_FCP_LOGGING`, `FC_EM_LOGGING`, `FC_EXCH_LOGGING`, and `FC_SCSI_LOGGING`. Debug macros `FC_LIBFC_DBG`, `FC_LPORT_DBG`, `FC_DISC_DBG`, `FC_RPORT_ID_DBG`, `FC_RPORT_DBG`, `FC_FCP_DBG`, `FC_EXCH_DBG`, and `FC_SCSI_DBG` gate formatted `pr_info()` output on `fc_debug_logging`. The header declares provider arrays `fc_active_prov[]` and `fc_passive_prov[]`, `fc_prov_mutex`, built-in providers `fc_rport_t0_prov`, `fc_lport_els_prov`, and `fc_rport_fcp_init`, setup functions for FCP/exchange/rport, `fc_fcp_ddp_setup()`, `fc_fcp_ddp_done()`, lport registration helpers, and `fc_copy_buffer_to_sglist()`.

Control flow: there is no executable control flow, but the macros influence runtime logging paths throughout libfc. `FC_CHECK_LOGGING()` wraps debug commands in an `unlikely()` branch. `FC_FCP_DBG()` additionally inspects the packet's active sequence to include exchange XIDs when present. The declarations encode module initialization ordering and cross-file dependencies used by `fc_libfc.c`, `fc_fcp.c`, `fc_lport.c`, and `fc_rport.c`.

State and persistence: the header declares global runtime state but owns no storage. `fc_debug_logging` is module parameter-backed in `fc_libfc.c`; provider arrays and `fc_prov_mutex` are also defined there. No persistent state is introduced by the header.

Dependencies and integration: assumes libfc structures from `scsi/libfc.h` and FC frame/exchange types are visible to including C files. It integrates private implementation units and exposes built-in FC-4 provider symbols so provider tables can be initialized centrally.

Risks and test signals: debug macros dereference fields such as `lport->host`, `pkt->rport`, and `pkt->seq_ptr`; callers should only use them with fully initialized objects. `FC_FCP_DBG()` obtains an exchange from `seq_ptr`, so use after exchange teardown would be risky. Compile coverage should include all libfc files with logging enabled, and runtime tests should toggle `debug_logging` masks while exercising lport, rport, FCP, exchange, and SCSI EH paths.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_lport.c

Purpose: implements libfc local-port state management. It drives fabric login/logoff, point-to-point setup, name-server registration, optional FDMI management-server registration, SCR registration, transition to discovery-ready state, lport reset/link handling, host attribute/statistic reporting, inbound ELS dispatch, and BSG ELS/CT passthrough.

Important APIs/types/functions: state names cover `LPORT_ST_DISABLED`, `RESET`, `FLOGI`, `DNS`, name-server states `RNN_ID`/`RSNN_NN`/`RSPN_ID`/`RFT_ID`/`RFF_ID`, `FDMI`, FDMI states `RHBA`/`RPA`/`DHBA`/`DPRT`, `SCR`, `READY`, and `LOGO`. Exported entry points include `fc_fabric_login()`, `fc_linkup()`, `fc_linkdown()`, `fc_fabric_logoff()`, `fc_lport_destroy()`, `fc_set_mfs()`, `fc_lport_set_local_id()`, `fc_lport_recv()`, `fc_lport_reset()`, `fc_lport_config()`, `fc_lport_init()`, `fc_lport_bsg_request()`, `fc_get_host_port_state()`, `fc_get_host_speed()`, and `fc_get_host_stats()`. `struct fc_bsg_info` tracks asynchronous passthrough replies.

Control flow: `fc_fabric_login()` moves a disabled/logged-out port into reset, and `__fc_linkup()` starts FLOGI if the link is up in reset. `fc_lport_enter_flogi()` sends FLOGI or FDISC, unless point-to-multipoint already has a local ID. `fc_lport_flogi_resp()` validates LS_ACC, negotiates MFS and timeouts, records NPIV support, and either enters point-to-point setup or creates/logs in to the directory-server rport. Directory-server READY callbacks start name-server registrations in order: `RNN_ID`, optional symbolic node/port names, `RFT_ID`, and `RFF_ID`. After name-server registration, the lport optionally logs into the management server and sends FDMI, then sends SCR, enters READY, updates vports, and starts discovery. Link-down/reset/logoff paths stop discovery, log off DNS/point-to-point rports, reset exchanges, clear fabric/port IDs as appropriate, and abort or clean up FCP I/O.

State and persistence: lport state is in `struct fc_lport`: mutex, link flag, fabric/local port ID, WWNs, MFS, timeouts, retry counters, delayed retry work, vport list, discovery object, DNS/MS/PTP rport pointers, NPIV and point-to-multipoint flags, FC-4 type maps, and SCSI host attributes. Statistics are aggregated from per-CPU counters into `host_stats` on demand. State is volatile and rebuilt after link reset/login; persistent values come from driver-provided WWNs, service parameters, and host attributes.

Dependencies and integration: depends on libfc exchange, discovery, rport, FC-4 provider registry, SCSI FC transport attributes, vport support, BSG jobs, ELS/CT frame encoders, and low-level transport-template functions such as `elsct_send`, `frame_send`, `disc_start`, `disc_stop`, `disc_stop_final`, `exch_mgr_reset`, and optional `lport_set_port_id`. Inbound frames are dispatched through passive FC-4 providers using RCU and module references.

Risks and test signals: lock hierarchy is explicit (`lport > disc/rport`), and callbacks from rport/discovery can re-enter lport state changes. Retry work can restart state-specific requests after allocation, reject, or timeout errors. FDMI v2 fallback mutates host FDMI version on rejects/timeouts. Point-to-point FLOGI chooses local/remote FIDs based on WWPN ordering and must avoid duplicate IDs. Test fabric FLOGI/FDISC success and rejects, P2P crossed FLOGI, point-to-multipoint local-ID bypass, MFS shrink reset, DNS and FDMI registration failures and retry exhaustion, SCR failure, RSCN routing to discovery, LOGO from fabric controller, vport link-state propagation, BSG ELS/CT multi-frame replies and errors, linkdown during every login state, and destroy with outstanding discovery/rport/FCP work.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_npiv.c

Purpose: implements libfc helper functions for NPIV virtual ports. It allocates VN_Port local-port instances, associates them with `fc_vport`, resolves received fabric IDs to the parent N_Port or a VN_Port, and propagates parent link/fabric capability changes to child virtual ports.

Important APIs/types/functions: exported `libfc_vport_create()` allocates a child `fc_lport` through `libfc_host_alloc()`, stores it in `vport->dd_data`, and links it onto the parent N_Port `vports` list. `fc_vport_id_lookup()` maps an FC_ID to the parent N_Port, the fabric-login ID in point-to-point mode, or a matching VN_Port. `fc_vport_setlink()` updates one VN_Port from its parent. `fc_vports_linkchange()` updates all children when the parent changes. Internal `__fc_vport_setlink()` handles state decisions while both mutexes are held. `enum libfc_lport_mutex_class` gives lockdep a nested class for VN_Port locking.

Control flow: virtual port creation starts from a transport `fc_vport`, obtains the parent host/lport, allocates the VN_Port host-private object, sets back-pointers, then appends it under the parent `lp_mutex`. When the parent enters READY, `fc_vports_linkchange()` locks each VN_Port with the nested class and either calls `__fc_linkup()` with `FC_VPORT_INITIALIZING` if NPIV was accepted by the fabric, or marks `FC_VPORT_NO_FABRIC_SUPP` and drives linkdown. When the parent is not READY, children are marked linkdown and `__fc_linkdown()` is called. `fc_vport_setlink()` performs the same update for a single child.

State and persistence: state is in the parent `fc_lport->vports` list, each VN_Port `fc_lport`, and the `fc_vport` transport object state. There is no persistent storage. Parent `npiv_enabled`, lport state, child disabled state, and FC_ID assignments determine runtime behavior.

Dependencies and integration: depends on the SCSI FC transport vport API, libfc host allocation, lport mutex/link helpers from `fc_lport.c`, and kernel list/mutex facilities. It is invoked by low-level drivers or transport callbacks that create/delete virtual ports and by lport state transitions.

Risks and test signals: nested locking must always use the VN_Port lock class to avoid false lockdep recursion and real inversion. `libfc_vport_create()` links the VN_Port before full driver-specific initialization may be complete, so callers must finish setup carefully. `fc_vport_id_lookup()` returns the parent for `FC_FID_FLOGI`, which is point-to-point-specific behavior. Test NPIV accepted versus not accepted after FLOGI, parent linkdown/reset/logoff propagation, disabled VN_Port no-op behavior, FC_ID lookup collisions, concurrent vport creation with link changes, and correct cleanup by caller-owned vport teardown.

# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_rport.c

Purpose: implements libfc remote-port lifecycle and login state machines. It owns `fc_rport_priv` allocation, lookup, reference counting, PLOGI/PRLI/RTV/ADISC/LOGO flows, inbound ELS handling for logged-in and not-yet-logged-in peers, transport-class `fc_rport` add/delete, FC-4 PRLI provider negotiation, and I/O termination for a remote target.

Important APIs/types/functions: exported functions include `fc_rport_lookup()`, `fc_rport_create()`, `fc_rport_destroy()`, `fc_set_rport_loss_tmo()`, `fc_rport_login()`, `fc_rport_logoff()`, `fc_rport_recv_req()`, `fc_rport_flush_queue()`, `fc_setup_rport()`, `fc_destroy_rport()`, and `fc_rport_terminate_io()`. The state machine uses `RPORT_ST_INIT`, `FLOGI`, `PLOGI_WAIT`, `PLOGI`, `PRLI`, `RTV`, `READY`, `ADISC`, and `DELETE`. `rport_event_queue` serializes callbacks and transport add/delete work. Built-in providers are `fc_rport_fcp_init` for FCP initiator PRLI and `fc_rport_t0_prov` for type 0.

Control flow: discovery or lport code creates an `fc_rport_priv` under the discovery mutex and calls `fc_rport_login()`. Login sets `FC_RP_STARTED` and enters FLOGI for point-to-multipoint or PLOGI otherwise. PLOGI response records WWPN/WWNN, service features, max sequences, and max payload, then PRLI negotiates FCP roles, retry/confirmation flags, and provider-specific service parameters. RTV opportunistically updates timeout values and then READY queues `RPORT_EV_READY`, where `fc_rport_work()` creates or updates the SCSI transport `fc_rport` and invokes lport/LLD callbacks. Existing READY ports are verified by ADISC on relogin. Logoff resets exchanges, sends LOGO, and enters DELETE; delete events reset outstanding exchanges, notify providers via PRLO callbacks, delete the transport rport, and either restart for bounded major retries or remove the private object from discovery.

State and persistence: `fc_rport_priv` is kref-counted and freed by RCU. It stores identities, state, event, flags (`FC_RP_STARTED`, REC/SRR retry support, FCP confirmation), retry counters, local-port pointer, optional transport `rport`, provider callbacks, timeouts, max frame/sequence, supported classes, roles, and delayed/event work. The transport `fc_rport` receives a copy of max frame/classes and libfc private state when READY. State is runtime only and is recreated by discovery/relogin.

Dependencies and integration: depends on `scsi_transport_fc` remote-port add/delete/loss timeout APIs, libfc lport/discovery lock ordering, exchange-manager reset, ELS/CT frame helpers, provider tables in `fc_libfc.c`, workqueues, RCU lists, krefs, and low-level `elsct_send`/`frame_send` operations. FCP I/O uses `fc_rport_libfc_priv` from the transport rport for timeouts and recovery capabilities.

Risks and test signals: lifecycle is complex because `fc_rport_priv` and transport `fc_rport` have different lifetimes. Event work drops krefs, cancels retry work, invokes callbacks without holding rport mutex, resets exchanges in both directions, and may restart deleted ports if discovery still wants them. Crossed PLOGI/FLOGI behavior depends on WWPN ordering. Inbound ELS requests are accepted, busy-rejected, or PLOGI-required-rejected based on state. PRLI provider negotiation must handle active/passive providers and malformed SPP lengths. Test lookup under RCU while deleting, kref balance for ELS sends/retry/event work, PLOGI/PRLI/RTV success and rejects, point-to-multipoint FLOGI crossing, ADISC identity mismatch, LOGO/PRLO inbound, well-known address login skipping PRLI/RTV, provider registration combinations, major retry restart limits, rport loss timeout setting, remote port delete while FCP commands are active, and `fc_rport_terminate_io()` exchange reset coverage.
