# sources/storage-engines/wiredtiger/src/reconcile/rec_hs.c

Purpose: implements the reconciliation side of history store maintenance. It moves older versions from data-store update chains into WiredTigerHS, repairs mixed timestamp ordering cases, clears history-store records hidden by no-timestamp tombstones, and removes history-store entries when a version is selected back into the data store. This file is central to eviction/checkpoint correctness for timestamped history.

Important APIs/types/functions: exported entry points are `__wti_rec_hs_insert_updates`, `__wti_rec_hs_delete_key`, and `__wti_rec_hs_delete_updates`. Internal helpers include `__rec_hs_insert_record` for one history-store row, `__rec_hs_delete_reinsert_from_pos` for timestamp-order fixups, `__rec_hs_cursor_pos` for positioning on future history-store records for the same key, `__rec_hs_collect_upd_chain` for building the per-key work stack, and `__rec_hs_flush_upd_chain` for emitting records. `WT_REC_HS_KEY_STATE` tracks newest history-store candidate, tombstone pairing, no-timestamp update state, reverse-modify eligibility, squash state, and whether an existing HS/delta update was seen. `WT_REC_HS_STAT` batches history-store insert and squash counters. Constants `WT_MAX_CONSECUTIVE_REVERSE_MODIFY` and `MAX_REVERSE_MODIFY_NUM` cap reverse-modify encoding.

Control flow: `__wti_rec_hs_insert_updates` opens a committed-read history-store cursor for the current btree, iterates the `WT_MULTI.supd` saved-update list produced by visibility selection, packs row/column keys, and skips globally visible or already-history-stored chains. For each key, it enables reverse modifies only for string/byte formats and non-prepared on-page writes, records no-timestamp tombstones, calls `__rec_hs_collect_upd_chain`, optionally truncates old HS content when the oldest collected item is a globally visible no-timestamp tombstone, then flushes the collected stack. Flush starts from the oldest full value, reconstructs full values through standard/modify updates, builds `WT_TIME_WINDOW` start/stop pairs, writes either reverse modifies or full values through `__rec_hs_insert_record`, and marks updates/tombstones with `WT_UPDATE_HS` or `WT_UPDATE_HS_MAX_STOP`. `__rec_hs_insert_record` searches before/after the desired `(btree_id,key,start_ts,counter)`, increments counters for duplicate timestamps, validates duplicate values under diagnostics, removes/reinserts later records if ordering must be fixed, and finally inserts the new HS row.

State and persistence behavior: persistent state is the WiredTigerHS table content keyed by `(btree_id, user_key, start_ts, counter)` with durable/start/stop timestamps, txn ids, update type, and value. In-memory state includes flags on `WT_UPDATE` objects, `r->cache_write_hs`, `btree->hs_entries`, `r->hs_cursor`, saved-update arrays, and statistics. No-timestamp tombstones can cause deletion or zero-timestamp reinsertion of existing HS records. Prepared updates without a stop counterpart can be written with max stop visibility so checkpoint garbage collection does not remove them prematurely. The file also enforces configured HS file maximum size by checking `WiredTigerHS` block-manager size after insertion.

Dependencies and integration points: consumes saved update chains from `rec_visibility.c`, key packing and page context from `WTI_RECONCILE`, update vectors from common update utilities, history-store cursor APIs (`__wt_curhs_open`, search-near helpers, `__wt_hs_upd_time_window`), modify reconstruction/packing helpers, time-window macros, verbose/statistics subsystems, and btree block manager sizing. It is called after row/column reconciliation split decisions have built `WT_MULTI` boundaries and before reconciliation finalizes page state. `__wti_rec_hs_delete_updates` is the counterpart for update selection paths that pull HS content back to the data store.

Risks and edge cases: timestamp-order repair is delicate during concurrent checkpoint; `error_on_ts_ordering` intentionally returns `EBUSY` in unsafe cases. Reverse modifies are not idempotent, so duplicate insertion or incorrect full-value reconstruction can corrupt reads. No-timestamp tombstone behavior intentionally sacrifices some older timestamped visibility guarantees and must keep HS order valid. Prepared updates can race commit/rollback, so code relies on flags, max-stop records, and diagnostic assertions. Reusing a history-store cursor across btrees must handle `EINVAL` and reopen. If the function reinserts records already in HS after writing new records, it panics to avoid clearing newer history.

Test signals: stress suites should cover eviction concurrent with checkpoint, rollback-to-stable, prepared commit/rollback, no-timestamp deletes over timestamped history, duplicate timestamp counters, reverse-modify reconstruction, HS max-size panic, and history-store validation diagnostics. Useful stats include `cache_hs_insert`, `cache_hs_insert_full_update`, `cache_hs_insert_reverse_modify`, `cache_hs_write_squash`, `cache_hs_order_reinsert`, `cache_hs_order_remove`, and `eviction_fail_checkpoint_no_ts`.

# sources/storage-engines/wiredtiger/src/reconcile/rec_row.c

Purpose: reconciles row-store internal and leaf pages into disk images, including key/value cell construction, prefix/suffix compression, page splitting, overflow handling hooks, dictionary compression, row-store deltas, and interaction with update selection/history-store cleanup. It is the row-store page writer for both bulk-load and normal reconciliation.

Important APIs/types/functions: exported functions are `__wt_bulk_insert_row`, `__wti_rec_pack_delta_row_leaf`, `__wti_rec_row_int`, and `__wti_rec_row_leaf`. Key helpers are `__rec_key_state_update`, `__rec_cell_build_int_key`, `__rec_cell_build_leaf_key`, `__rec_pack_delta_row_int`, `__rec_row_merge`, `__rec_build_delta_int`, `__rec_row_leaf_insert`, `__rec_cell_repack`, `__rec_row_zero_len`, and `__rec_row_garbage_collect_tw_eligible`. The file works through `WTI_RECONCILE` buffers `r->k`, `r->v`, `r->cur`, `r->last`, `r->delta`, split state, compression flags, and counters.

Control flow: bulk insert builds a leaf key and value from the bulk cursor, splits if needed, copies cells to the image, optionally dictionary-compresses values, updates time aggregate and key compression state, and frees newly created overflow blocks on error. Internal-page reconciliation initializes split/delta state, truncates the first internal key to one byte, walks child refs, asks `__wti_rec_child_modify` whether each child is ignored/modified/original/proxy, merges multiblock child splits, builds address cells or reuses existing cells, merges time aggregates including fast-truncate page-delete state, optionally packs an internal delta entry, and finishes the split. Leaf reconciliation writes insert-list records before the first on-page key, then for each on-page row key reconstructs prefix-compressed keys as needed, selects an update with `__wti_rec_upd_select`, decides whether to keep, repack, replace, or delete the on-page value, handles overflow value/key discard, applies no-timestamp tombstone HS clearing, writes key/value cells, and writes insert-list records after the key.

State and persistence behavior: persistent output is one or more row-store disk pages and optional delta buffers. The code updates page image time aggregates, tracks whether all/any values are empty, may reuse on-page key/value cells directly, writes overflow cells or tracks overflow removal, and mutates reconciliation counters for removed keys and delta updates/deletes. It can omit zero-length globally visible values from the disk image and relies on `WT_TIME_WINDOW` to decide when this is safe. Internal deltas store key/value pairs or `WT_CELL_ADDR_DEL_VISIBLE_ALL` delete cells; leaf deltas pack a custom value with delta flags plus the reconciled value.

Dependencies and integration points: depends on reconciliation split/cell helpers in `reconcile_inline.h` and other reconcile files, row-store page macros, update selection from `rec_visibility.c`, history-store clearing from `rec_write.c`/`rec_hs.c`, overflow tracking from `rec_track.c`, dictionary replacement, modify reconstruction, child reconciliation state, salvage skip input, and WiredTiger time-window/time-aggregate APIs. `__wti_rec_row_leaf` and `__rec_row_leaf_insert` are the row-store consumers of `WTI_UPDATE_SELECT`, while `__wti_rec_pack_delta_row_leaf` consumes saved updates for delta construction.

Risks and edge cases: prefix compression must be disabled and keys rebuilt across split boundaries so promoted split keys are complete. Overflow removed markers must never be copied into new images. Dictionary cells must be repacked when their source may be discarded. Internal deltas are disabled when split history or first-key truncation would make the delta ambiguous. Concurrent child dirtiness can abort delta creation. Tombstones without timestamps must trigger HS cleanup only for real data-store keys. Preserve-prepared mode prevents leaking prepared on-page values. Salvage can skip leading records, which complicates key reconstruction. Empty values are only omitted when the time window is globally visible and has no stop.

Test signals: page image verification should cover prefix-compressed keys, overflow keys/values, dictionary values, bulk-load split boundaries, internal page split merge, fast-truncate proxy cells, row leaf insert lists before/after disk keys, modify reconstruction, garbage-collection pruning, leaf/internal delta creation and abort conditions, salvage skip, and prepared/no-timestamp tombstone interactions. Counters such as `keys_removed_from_disk_image_count`, `count_internal_page_delta_key_deleted`, `count_internal_page_delta_key_updated`, prefix-compression byte counters, and overflow statistics give runtime signals.

# sources/storage-engines/wiredtiger/src/reconcile/rec_track.c

Purpose: tracks overflow values/keys across reconciliation so blocks can be discarded after a successful rewrite, reused while building a replacement image, or rolled back safely after an error. This file owns the per-page overflow tracking structure lifecycle and skiplist of reusable overflow records.

Important APIs/types/functions: public functions are `__wt_ovfl_discard_add`, `__wt_ovfl_discard_free`, `__wti_ovfl_reuse_search`, `__wti_ovfl_reuse_add`, `__wt_ovfl_reuse_free`, `__wti_ovfl_track_wrapup`, and `__wti_ovfl_track_wrapup_err`. Static helpers initialize tracking, emit verbose diagnostics, wrap up discard lists, search/insert reuse skiplist nodes, and handle success/error cleanup. `WT_OVFL_SIZE` estimates cache footprint for one `WT_OVFL_REUSE` plus skiplist/address/value storage.

Control flow: callers lazily allocate `page->modify->ovfl_track`. Discard tracking appends `WT_CELL *` entries for overflow cells that should be freed only after the replacement page is written. On success, `__ovfl_discard_wrapup` iterates those cells and calls `__wt_ovfl_discard`; on error it only frees the tracking array. Reuse tracking stores old overflow address/value pairs in a skiplist sorted by value bytes. During page image construction, `__wti_ovfl_reuse_search` returns the first matching not-in-use node and marks it in use. New reusable entries are allocated with address and value payloads inline and flags `WT_OVFL_REUSE_INUSE | WT_OVFL_REUSE_JUST_ADDED`. On success, `__ovfl_reuse_wrapup` frees unused old overflow blocks, clears in-use flags for retained ones, and asserts that just-added records are not freed as dirty overflow. On error, `__ovfl_reuse_wrapup_err` frees just-added overflow blocks and clears in-use on older entries.

State and persistence behavior: persistent effects are delayed block frees through `__wt_ovfl_discard` and `__wt_btree_block_free`. In-memory state lives under `WT_PAGE_MODIFY.ovfl_track` and includes the discard array, reuse skiplist, per-node flags, copied address cookies, copied value bytes, and cache footprint adjustments through `__wt_cache_page_inmem_incr/decr`. Success and error paths intentionally differ: successful reconciliation commits the new image and frees unreferenced old overflow; failed reconciliation frees only overflow blocks created during the failed attempt and preserves old ones.

Dependencies and integration points: used by row/column reconciliation when old overflow keys or values are removed or when large new values may reuse old overflow blocks. Depends on block manager free/discard APIs, page memory accounting, skiplist depth selection, verbose overflow logging, cell unpacking, and page modify structures. Unit-test wrappers under `HAVE_UNITTEST` expose core static helpers.

Risks and edge cases: freeing overflow blocks before the page image is safely written can corrupt readers or checkpoints, so wrapup ordering is critical. The reuse skiplist handles duplicate values and must not return an in-use node. Address sizes are stored in single-byte fields and assume WiredTiger address cookies stay within that limit. Error handling must free `JUST_ADDED` blocks but not old blocks still referenced by the original page. Cache footprint accounting is approximate and tied to skiplist depth assumptions.

Test signals: overflow-heavy reconciliation should validate reuse hits, duplicate-value reuse behavior, discard-on-success, rollback-on-error, cache footprint stability, and verbose/debug paths. Unit-test builds can call `__ut_ovfl_track_init`, `__ut_ovfl_discard_wrapup`, `__ut_ovfl_reuse_wrapup`, and `__ut_ovfl_reuse_wrapup_err`. Runtime assertions catch attempts to free dirty just-added overflow records.

# sources/storage-engines/wiredtiger/src/reconcile/rec_visibility.c

Purpose: selects which update from a key's update chain reconciliation may write to the data-store page, builds the selected `WT_TIME_WINDOW`, decides whether update chains must be saved/restored, records history-store deletions, handles prepared-update preservation, validates timestamp ordering, and marks selected updates for later reconciliation stages. It is the visibility policy layer used by row and column reconciliation.

Important APIs/types/functions: the exported entry point is `__wti_rec_upd_select`. Key helpers are `__rec_upd_select` for normal btrees, `__rec_upd_select_inmem` for in-memory/ingest btrees, `__rec_fill_tw_from_upd_select`, `__rec_update_save`, `__rec_delete_hs_upd_save`, `__rec_append_orig_value`, `__rec_save_delete_hs_upd_and_free_obs_updates`, `__rec_need_save_upd`, `__timestamp_no_ts_fix`, `__rec_validate_upd_chain`, and `__rec_calc_upd_memsize`. The file populates `WTI_UPDATE_SELECT` and appends `WT_SAVE_UPD` / `WTI_DELETE_HS_UPD` records to `WTI_RECONCILE`.

Control flow: `__wti_rec_upd_select` initializes selection, finds the update chain from either a `WT_INSERT` or row-store `WT_ROW`, then dispatches to normal or in-memory selection. Normal selection walks newest-to-oldest updates, skips aborted updates unless preserve-prepared requires special handling, refuses metadata self-transaction eviction, handles application eviction snapshots, tests visibility against the reconciliation snapshot or pinned id, applies precise-checkpoint stable timestamp rules, and decides whether to write prepared updates. In-memory selection prefers globally visible non-tombstones or the oldest committed update while supporting ingest garbage collection and rollback timestamp pruning. After an update is selected, `__rec_fill_tw_from_upd_select` derives start/stop time windows, pairs tombstones with underlying values, appends original on-page values when needed, and handles prepared tombstone fallbacks. The top-level function then saves HS-delete records, validates ordering, flags no-timestamp tombstones, saves update chains for history-store/update-restore work, marks selected updates with `WT_UPDATE_DS`, clears obsolete time-window fields, and adjusts disaggregated durability flags.

State and persistence behavior: this file does not write disk images directly; it determines what later row/column/history-store reconciliation persists. It mutates `WTI_RECONCILE` state (`supd`, `delete_hs_upd`, `leave_dirty`, `update_used`, `cache_write_restore_invisible`, max transaction/timestamp fields, obsolete/update counters), appends restored on-page values and tombstones to update chains, increments page memory footprint for appended updates, clears obsolete updates, and sets flags such as `WT_UPDATE_DS`, `WT_UPDATE_DURABLE`, and `WT_UPDATE_PREPARE_DURABLE`. Saved updates become history-store input for `rec_hs.c` and update-restore input for eviction.

Dependencies and integration points: called by `rec_row.c` and `rec_col.c` for every insert/on-page key. It depends on transaction visibility APIs, prepare state atomics, time-window macros, rollback-to-stable/precise checkpoint stable timestamps, history-store flags, disaggregated btree durability semantics, in-memory garbage-collection settings, page/cell unpacking, and update allocation/free helpers. It also coordinates with `rec_hs.c` via `WT_SAVE_UPD` and `WTI_DELETE_HS_UPD` and with `rec_write.c` through reconciliation flags such as `WT_REC_HS`, `WT_REC_EVICT`, `WT_REC_CHECKPOINT`, `WT_REC_CHECKPOINT_RUNNING`, and `WT_REC_CLEAN_AFTER_REC`.

Risks and edge cases: concurrent commit/rollback can change update visibility while reconciliation is running, so the code uses cached visibility, atomics, dirty-page fallback, and conservative `EBUSY`. Prepared update preservation has many fallback paths; leaking a prepared value or dropping its rollback fallback can make a key remain prepared or unrecoverable. No-timestamp updates during checkpoint can violate HS ordering and force eviction failure. Appending original overflow/on-page values is required before overflow blocks are removed; missing it loses reader-visible history. Metadata eviction is stricter because metadata can be written with read-uncommitted semantics. Disaggregated durable flags must be cleared when prepared updates are overwritten so future deltas still include needed state.

Test signals: targeted tests should cover normal eviction, checkpoint, precise checkpoint, prepared commit/rollback, preserve-prepared mode, metadata self-transaction `EBUSY`, application eviction snapshots, in-memory and ingest garbage collection, no-timestamp tombstone fixups, overflow original-value append, history-store restore/delete, obsolete update freeing, and disaggregated durable-flag transitions. Runtime signals include `leave_dirty`, `update_used`, `cache_write_restore_invisible`, `has_upd_chain_all_aborted`, stats for no-timestamp checkpoint races, HS removal races, obsolete updates removed, and ingest garbage-collection counters.
