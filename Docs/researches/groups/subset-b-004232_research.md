# sources/distributed-fs/ceph-client/drivers/message/fusion/lsi/mpi_cnfg.h

Purpose: defines the LSI Fusion MPT MPI configuration-message ABI and the full set of standard and extended configuration page layouts used by the legacy Fusion SCSI, FC, SAS, LAN, RAID, BIOS, and manufacturing paths. It is a protocol contract header rather than executable code: driver code fills `MSG_CONFIG`, sends it through `mpt_config()`, and interprets the returned page buffers using the `CONFIG_PAGE_*` structures and `MPI_*` bit definitions in this file.

Important APIs, types, and structures: the common page wrappers are `CONFIG_PAGE_HEADER`, `CONFIG_PAGE_HEADER_UNION`, and `CONFIG_EXTENDED_PAGE_HEADER`. `MSG_CONFIG` and `MSG_CONFIG_REPLY` define the request/reply envelope, including action, function, context, page address, normal or extended header fields, and an SGE pointing at the page buffer. Action constants cover page header fetch, current/default/NVRAM reads, current writes, and NVRAM writes. Page type constants cover IO Unit, IOC, BIOS, SCSI Port, SCSI Device, FC Port, FC Device, LAN, RAID Volume, Manufacturing, RAID PhysDisk, Inband, and Extended pages; extended page types cover SAS IO Unit, SAS Expander, SAS Device, SAS PHY, Log, and Enclosure. Page-address macros encode SCSI bus/target and target-mode forms, FC port and device addressing, physical disk numbers, SAS expander/device/PHY/enclosure handles or table indexes, and get-next traversal forms. The page families include `CONFIG_PAGE_MANUFACTURING_0` through `_10`, `CONFIG_PAGE_IO_UNIT_0` through `_4`, `CONFIG_PAGE_IOC_0` through `_6`, `CONFIG_PAGE_BIOS_1`, `_2`, and `_4`, `CONFIG_PAGE_SCSI_PORT_0` through `_2`, `CONFIG_PAGE_SCSI_DEVICE_0` through `_3`, `CONFIG_PAGE_FC_PORT_0` through `_10`, `CONFIG_PAGE_FC_DEVICE_0`, `CONFIG_PAGE_RAID_VOL_0` and `_1`, `CONFIG_PAGE_RAID_PHYS_DISK_0` and `_1`, `CONFIG_PAGE_LAN_0` and `_1`, `CONFIG_PAGE_INBAND_0`, `CONFIG_PAGE_SAS_IO_UNIT_0` through `_3`, `CONFIG_PAGE_SAS_EXPANDER_0` and `_1`, `CONFIG_PAGE_SAS_DEVICE_0` through `_2`, `CONFIG_PAGE_SAS_PHY_0` and `_1`, `CONFIG_PAGE_SAS_ENCLOSURE_0`, and `CONFIG_PAGE_LOG_0`.

Control flow: this header does not execute control flow itself, but it defines the firmware transaction sequence used throughout the Fusion driver. Callers normally initialize a page header with page type, page number, and optionally extended page type, issue `MPI_CONFIG_ACTION_PAGE_HEADER` through `mpt_config()` to learn the page length/version, allocate or point `cfg.physAddr` at a page buffer, then issue `MPI_CONFIG_ACTION_PAGE_READ_CURRENT`, `READ_NVRAM`, `READ_DEFAULT`, `WRITE_CURRENT`, or `WRITE_NVRAM`. In `mptbase.c`, `mpt_config()` copies these fields into `MSG_CONFIG`, special-cases extended headers by filling `ExtPageLength` and `ExtPageType`, writes `PageAddress`, sets the SGE, and waits for the reply. Protocol drivers use the resulting page types directly: `mptspi.c` reads and writes SCSI device/port pages for negotiation settings, `mptsas.c` reads SAS IO Unit, PHY, Device, Expander, Enclosure, RAID Volume, and RAID PhysDisk pages for topology and RAID state, `mptfc.c` reads FC Device and FC Port pages for rport registration and link information, `mptctl.c` exposes manufacturing and SCSI device page access to control paths, and `mptbase.c` reads IO Unit, IOC, LAN, manufacturing, RAID, and SCSI inventory pages during adapter bring-up.

State and persistence behavior: the header defines firmware state surfaces, not kernel-owned state. Page attributes identify read-only, changeable, persistent, and read-only persistent pages. Runtime reads observe current IOC state such as discovered SAS topology, negotiated SCSI parameters, FC link counters, LAN status, RAID volume/physical disk state, and log entries. Persistent/NVRAM writes can change adapter behavior across resets, including IO Unit flags, BIOS boot preferences, manufacturing RAID policy defaults, SCSI negotiation policy, FC port behavior, and SAS persistent mapping settings. Several variable-length pages intentionally declare one-element arrays or flexible arrays with `__counted_by`; host code is repeatedly instructed to leave local maximum defines at one and trust `Header.PageLength`, `NumPhys`, `NumActiveVolumes`, `NumPhysDisks`, `NumPersistentIDsUsed`, or similar runtime counts when allocating and parsing buffers.

Dependencies and integration points: depends on base MPI scalar types (`U8`, `U16`, `U32`, `U64`), `MPI_POINTER`, MPI SGE unions (`SGE_IO_UNION`, `SGE_SIMPLE_UNION`), version structs, and protocol constants from sibling Fusion headers such as `mpi.h`, `mpi_ioc.h`, and `mpi_sas.h`. It is included by `mptbase.h`, which makes the page definitions available to the base adapter layer and all Fusion protocol drivers. It integrates with kernel DMA/SGL handling through config page buffers, with libata/SAS/SCSI/FC transport integration through the protocol drivers that consume SAS/FC/SCSI pages, and with RAID management through IOC, RAID Volume, RAID PhysDisk, manufacturing, BIOS, enclosure, and SEP-related config data.

Risks and edge cases: structure layout is a firmware ABI, so field type, order, width, and implicit padding changes can break hardware communication even if the C compiler accepts them. Endianness conversion is the responsibility of callers when filling request fields and parsing page data; the header's raw integer fields are not self-converting. Page length and count fields must be trusted over local placeholder array sizes to avoid truncating variable-length pages. Extended pages require `PageType` set to `MPI_CONFIG_PAGETYPE_EXTENDED` and the correct `ExtPageType`; confusing normal and extended headers produces invalid requests. Page-address bit packing is easy to get wrong, especially get-next forms for FC/SAS discovery and bus/target forms for SCSI and FC devices. Persistent writes are high impact because `WRITE_NVRAM` can alter boot, mapping, RAID, and negotiation behavior across resets. Some definitions contain historical/legacy aliases and misspellings that are part of the ABI surface; cleanups must not change numeric values or names used by old code. Flexible arrays and `__counted_by` annotations improve bounds reasoning but require allocation from firmware-reported lengths in all callers.

Test signals: build coverage should include the Fusion base, SPI, SAS, FC, and ctl paths that include `mptbase.h`. Runtime signals include successful `mpt_config()` header/read cycles for normal pages, extended SAS pages, and variable-length pages; correct handling of zero or larger-than-one counts; successful SCSI negotiation reads/writes in `mptspi`; SAS topology discovery and enclosure/PHY/device page reads in `mptsas`; FC rport discovery from FC Device Page 0 and link speed logging from FC Port Page 0 in `mptfc`; and RAID volume/physdisk inventory through IOC and RAID pages. Negative tests should include invalid page addresses, unsupported page numbers, timeout paths in `mpt_config()`, and ensuring NVRAM write paths are not reached except through explicit configuration changes.

# sources/distributed-fs/ceph-client/drivers/message/fusion/lsi/mpi_fc.h

Purpose: defines the LSI Fusion MPT MPI Fibre Channel direct-access message ABI. It covers low-level FC link-service buffer posting and responses, extended link service sends, FC aborts, common transport sends, and primitive sends. Like the other `lsi/mpi_*.h` files, it is a firmware-facing wire-format header consumed by the base driver and FC-capable control paths rather than a standalone implementation.

Important APIs, types, and structures: `MSG_LINK_SERVICE_BUFFER_POST_REQUEST` posts one or more buffers for incoming link-service frames with `BufferPostFlags`, `BufferCount`, message context, and a transfer SGL. `MSG_LINK_SERVICE_BUFFER_POST_REPLY` returns the received frame metadata, including transfer length, transaction context, packed `Rctl_Did`, `Csctl_Sid`, `Type_Fctl`, sequence fields, OXID/RXID, parameter, and `WWNFORMAT`. `MSG_LINK_SERVICE_RSP_REQUEST` and `MSG_LINK_SERVICE_RSP_REPLY` describe responses to link-service frames, with immediate response support and a returned initiator index. `MSG_EXLINK_SERVICE_SEND_REQUEST`/`REPLY` send ELS payloads to a DID with an alias index and command code. `MSG_FC_ABORT_REQUEST`/`REPLY` abort posted buffers or outstanding CT/ELS sends by transaction context. `MSG_FC_COMMON_TRANSPORT_SEND_REQUEST`/`REPLY` send FC Common Transport payloads with CT command code and FS type. `MSG_FC_PRIMITIVE_SEND_REQUEST`/`REPLY` ask firmware to transmit primitive ordered sets or reset/stop primitive sending. Macros define port-mask bits, `NO_RSP_NEEDED`, packed DID/RCTL/SID/CSCTL/FCTL/TYPE masks and shifts, abort types, CT send masks, and primitive send modes such as send once, send around, until full, forever, stop send, reset link, and ML reset link.

Control flow: this header supplies message formats used when a caller needs direct FC management rather than normal SCSI FCP IO. A buffer-post flow allocates a message frame, fills the post request with a function code, context, count, port flag, and SGL, and firmware completes with a reply that identifies the FC exchange and payload metadata. If a response is required, the caller mirrors exchange fields into `MSG_LINK_SERVICE_RSP_REQUEST` and supplies a response SGL or immediate payload length. ELS and CT sends pack destination DID and message flags into `MsgFlags_Did`, attach a payload SGL, and consume the returned response length. Abort requests use `AbortType` and `TransactionContextToAbort` to cancel posted buffers, CT sends, or ELS sends. Primitive sends are control-plane operations that may run once, continuously, or until stopped, depending on the send flags.

State and persistence behavior: no persistent kernel state is declared here. Runtime state exists in firmware queues, posted FC buffers, outstanding FC transactions, and message-frame contexts owned by the Fusion base layer. `TransactionContext` and `MsgContext` are the important correlation handles: they connect an incoming LS buffer or outstanding send to a later response or abort. The header does not define NVRAM or durable settings; durable FC port behavior is represented instead by FC config pages in `mpi_cnfg.h`.

Dependencies and integration points: depends on base MPI types, `MPI_POINTER`, and SGE unions for DMA payloads. `mptbase.h` includes this file for FC-capable builds, and `mptctl.c` recognizes FC Common Transport Send, FC Primitive Send, and FC Abort function codes in user/control message paths. The normal Linux FC SCSI transport integration in `mptfc.c` primarily uses `mpi_cnfg.h` FC Port/Device pages and `mpi_init.h` SCSI IO, but this header remains the low-level ABI for direct FC link-service and management exchanges. It also shares IOC status values and function codes with `mpi.h`.

Risks and edge cases: the packed FC header fields combine an 8-bit control/type field with 24-bit IDs in one `U32`; callers must apply masks and shifts consistently and perform endian conversion at the message boundary. Aborting the wrong transaction context can cancel unrelated link-service or CT/ELS work. `MPI_LS_BUF_POST_REPLY_FLAG_NO_RSP_NEEDED` must be honored to avoid sending invalid responses. Continuous primitive send modes such as `FOREVER` or `UNTIL_FULL` require explicit stop/reset handling to avoid leaving a link in a disruptive state. Alias index and port flag handling is small but important on adapters with aliases or multiple FC ports. Since the structures are firmware ABI layouts with SGLs embedded at fixed offsets, padding or type changes would corrupt message frames.

Test signals: compile FC-capable Fusion paths and control passthrough handling. Runtime validation should include posting LS buffers, receiving a login or link-service frame, honoring no-response-needed completions, sending a link-service response, issuing CT or ELS requests with expected response lengths, aborting an exact posted buffer or outstanding send, and using primitive stop/reset paths without leaving the link wedged. Useful error signals are `MPI_IOCSTATUS_FC_ABORTED`, nonzero `IOCLogInfo`, mismatched `TransferLength` or `ResponseLength`, and link/rport behavior in `mptfc` after FC management activity.

# sources/distributed-fs/ceph-client/drivers/message/fusion/lsi/mpi_init.h

Purpose: defines the LSI Fusion MPT MPI initiator-mode message ABI for SCSI IO, extended 32-byte/EEDP-capable SCSI IO, SCSI task management, and SCSI Enclosure Processor slot-status operations. It is the central request/reply contract used by the Fusion SCSI host path when translating Linux `scsi_cmnd` objects and error-handling requests into firmware message frames.

Important APIs, types, and structures: `MSG_SCSI_IO_REQUEST` is the standard initiator IO request with target ID, bus, CDB length, sense length, message flags, context, 8-byte LUN, `Control`, 16-byte CDB, data length, sense buffer address, and IO SGL. `MSG_SCSI_IO_REPLY` returns SCSI status, SCSI state, IOC status/log info, transfer count, sense count, response info, and task tag. Macros define sense width/location, command-determined data direction, LUN addressing masks, control bits for read/write/no-data, additional CDB length, task attributes, and embedded task-management bits. Status macros include SAM status codes plus FC-specific extended statuses such as device logged out and no link. `MSG_SCSI_IO32_REQUEST` extends the request format for 32-byte CDB/EEDP and bidirectional cases, including CDB/EEDP unions, bidirectional length, reference/application tags, EEDP flags, block size, SCSI ID or WWID device address forms, SGL offsets, and sense address; `MSG_SCSIIO32_IO_REPLY` adds bidirectional transfer count. `MSG_SCSI_TASK_MGMT` and `MSG_SCSI_TASK_MGMT_REPLY` define abort task, abort task set, target reset, bus reset, logical unit reset, clear task set, query task, and clear ACA flows with response codes and termination counts. `MSG_SEP_REQUEST` and `MSG_SEP_REPLY` define enclosure slot status read/write operations and the large slot-status bitmaps used for fault, rebuild, identify, insert/remove, bypass, power, and swap state.

Control flow: the normal SCSI command path in `mptscsih.c` allocates a message frame, casts it to `SCSIIORequest_t`, fills target, bus, LUN, CDB, data length, direction/task attribute bits, sense buffer location, and SGL, then posts the frame to firmware. Completion handlers cast replies to `SCSIIOReply_t`, inspect `IOCStatus`, `SCSIStatus`, `SCSIState`, `TransferCount`, `SenseCount`, and `ResponseInfo`, and map them back to Linux SCSI result and sense handling. Error handling paths in `mptscsih.c`, `mptsas.c`, and `mptctl.c` allocate `SCSITaskMgmt_t`, set `TaskType`, target/bus/LUN, optional task message context, and wait for `SCSITaskMgmtReply_t`. SEP control in `mptscsih.c` fills `SEPRequest_t` to push slot status such as predicted fault or identify state to enclosure management. `mptctl.c` can also build SCSI IO and task-management frames for control passthrough, applying the same direction and qtag constants.

State and persistence behavior: this header declares transient initiator messages only. Per-command state is correlated through `MsgContext`, firmware request indexes, sense buffer DMA addresses, SGL chains, and optional `TaskTag`. SCSI IO replies expose device and transport state for a single command, while task-management replies report how many commands were terminated. SEP slot status represents enclosure-visible state and may persist in enclosure hardware or firmware until changed, but this header itself contains no storage or policy. EEDP fields in SCSI IO32 describe per-request protection-information behavior, not a global setting.

Dependencies and integration points: depends on base MPI types, `MPI_POINTER`, `SGE_IO_UNION`, and `SGE_SIMPLE_UNION`. It is included by `mptbase.h` and used heavily by `mptscsih.c`, `mptsas.c`, `mptspi.c`, `mptfc.c`, and `mptctl.c`. The Linux SCSI mid-layer provides `scsi_cmnd`, queue tags, CDBs, data direction, sense buffers, and error-handler entry points; the Fusion base layer provides message frames, DMA SGL construction, reply dispatch, and timeout handling. FC initiator mode uses these SCSI IO messages for FCP commands, while FC-specific link management is separated into `mpi_fc.h`.

Risks and edge cases: `Control` bit packing is central to IO correctness; an incorrect data direction or task attribute can cause DMA in the wrong direction or bad queue semantics. Sense buffer width/location bits must match the allocated sense DMA address size and firmware expectation. Additional CDB length, SCSI IO32 large-CDB mode, SGL offset chains, bidirectional IO, and EEDP flags all expand the ABI surface and are easy to under-test. Task-management requests are disruptive and must target the correct LUN, target, bus, or message context; soft reset/LIP reset options have transport-specific effects. Reply interpretation must distinguish IOC transport failures from SCSI device statuses and from valid autosense. SEP request/reply slot-status bits are similar but not identical, so using request constants on replies or vice versa can misreport enclosure state. As with all MPI headers, struct layout and endian handling are firmware ABI critical.

Test signals: compile and boot-test Fusion SCSI host paths with SPI, SAS, and FC variants enabled. Runtime IO tests should cover read, write, no-data commands, tagged and untagged queueing, CHECK CONDITION with valid autosense, queue full, residual/short transfer behavior, and FC extended status cases where applicable. Error-injection or fault tests should cover abort task, LUN reset, target reset, bus reset, query task, and timeout handling with correct termination counts. SEP tests should verify identify, predicted-fault, rebuild, hot-spare, insert/remove, and bypass indicators on supported enclosures. If SCSI IO32/EEDP is enabled by hardware, add large CDB, bidirectional, protection check/strip/insert/replacement, and SGL-offset chain coverage.
