# sources/distributed-fs/ceph-client/drivers/nvme/host/core.c

Purpose: This is the Linux NVMe host core framework implementation. It supplies shared controller lifecycle, request setup/completion, namespace discovery and block-disk registration, Identify/log/feature helpers, keep-alive and async-event handling, queue freeze/quiesce helpers, controller and namespace character devices, command effects handling, APST/timestamp configuration, and module-level workqueue/class setup used by PCI, fabrics, and other NVMe transport drivers.

Important APIs, types, and functions: Module parameters expose admin/I/O/shutdown timeouts, retry count, APST policy, and PI offset compatibility. Exported controller lifecycle APIs include `nvme_init_ctrl()`, `nvme_add_ctrl()`, `nvme_init_ctrl_finish()`, `nvme_start_ctrl()`, `nvme_stop_ctrl()`, `nvme_reset_ctrl()`, `nvme_try_sched_reset()`, `nvme_delete_ctrl()`, `nvme_uninit_ctrl()`, and `nvme_remove_namespaces()`. Request APIs include `nvme_init_request()`, `nvme_setup_cmd()`, `nvme_complete_rq()`, `nvme_complete_batch_req()`, `nvme_execute_rq()`, `__nvme_submit_sync_cmd()`, `nvme_submit_sync_cmd()`, `nvme_cancel_tagset()`, `nvme_cancel_admin_tagset()`, and `nvme_fail_nonready_command()`. Admin helpers include `nvme_set_features()`, `nvme_get_features()`, `nvme_set_queue_count()`, `nvme_enable_ctrl()`, `nvme_disable_ctrl()`, `nvme_command_effects()`, `nvme_passthru_start()`, and `nvme_passthru_end()`. Namespace and queue helpers include `nvme_find_get_ns()`, `nvme_alloc_admin_tag_set()`, `nvme_alloc_io_tag_set()`, freeze/quiesce/sync helpers, and block-device operations in `nvme_bdev_ops`. Key internal types are `struct nvme_ns_info`, `struct async_scan_info`, `struct nvme_core_quirk_entry`, `struct nvme_ctrl`, `struct nvme_ns`, `struct nvme_ns_head`, and `struct nvme_subsystem`.

Control flow: Module init verifies NVMe command/Identify structure sizes, allocates three global workqueues (`nvme_wq`, `nvme_reset_wq`, `nvme_delete_wq`), registers controller/subsystem/namespace classes and chrdev ranges, and initializes auth support. A transport first calls `nvme_init_ctrl()` to initialize state, locks, SRCU, work items, keep-alive command, discard page, instance IDs, auth/multipath, and the controller device, then `nvme_add_ctrl()` registers the controller cdev/device and debugfs fault injection. After a transport brings up admin access, `nvme_init_ctrl_finish()` reads VS/CAP-derived fields, performs Identify Controller, creates or joins a subsystem, initializes command effects, applies quirks, validates fabrics-specific Identify fields, sets APST/timestamp/host behavior/OPAL/hwmon, and starts keep-alives. `nvme_start_ctrl()` enables AENs, handles persistent discovery reconnect notification, queues namespace scanning once I/O queues exist, unquiesces I/O, updates multipath, and emits a connected uevent.

Request flow starts with `nvme_setup_cmd()` translating block operations into NVMe commands: flush, zone management, write-zeroes, discard/DSM, read/write, zone append, and passthrough. It handles PI/app/ref tags, metadata, FUA/LR hints, write streams/FDP placement IDs, atomic write validation, special discard payload allocation, and command IDs. Completion runs through `nvme_complete_rq()` or batch completion, cleans special payloads, updates keep-alive traffic accounting, decides between complete/retry/failover/authenticate in `nvme_decide_disposition()`, logs errors, updates zone append sectors, and hands status to block-mq or multipath. Sync admin/passthrough helpers allocate requests, map kernel buffers, execute them, and return either Linux errno or NVMe status.

Namespace scan flow is driven by `nvme_scan_work()`. It refreshes non-MDTS limits, clears changed-namespace AEN logs, then scans either the active namespace list or a sequential namespace range depending on version/quirk behavior. Each `nvme_scan_ns()` gathers namespace descriptors, command-set-independent data or legacy Identify data, removes detached namespaces, ignores not-ready namespaces, validates existing namespace IDs, or calls `nvme_alloc_ns()`. Allocation creates a blk-mq disk, namespace head, cdev, multipath disk/path state, block queue limits, integrity metadata, zones, FDP write streams, capacity/read-only flags, and debugfs fault injection. Removal clears readiness, tears down multipath/sysfs/cdev/gendisk links, removes from controller/subsystem lists under SRCU/mutex protection, and releases references.

State and persistence behavior: Runtime state lives in kernel memory: controller state bits, work items, queue/tagset pointers, Identify-derived fields, APST and keep-alive configuration, command effects xarray, subsystem list membership, namespace lists, namespace heads, queue limits, multipath state, debugfs fault injection attributes, and char-device IDs. There is no durable on-disk state; Host/controller/namespace devices are reconstructed on probe/reconnect/scan. The global subsystem list and ID allocators persist only while the module is loaded. Keep-alive, failfast, firmware activation, scan, async-event, reset, and delete work serialize many state transitions. Freeze/quiesce flags guard queue state during reset, passthrough commands with execution effects, firmware activation, and namespace mutation.

Dependencies and integration points: This file is central glue for Linux block-mq, gendisk/cdev/class/sysfs/uevent APIs, SRCU, workqueues, xarrays, IDA, PM QoS, blk-integrity, zone block support, SED OPAL, NVMe auth, NVMe multipath, NVMe fabrics helpers, tracepoints, debugfs fault injection, hwmon, persistent reservations, passthrough/io_uring ioctls, and transport callbacks in `struct nvme_ctrl_ops`. Transports provide register access, queue submission, async-event submission, tagset ops, reset/delete/stop callbacks, metadata and PCI P2PDMA capabilities, and transport-specific attributes.

Risks: This file has a high concurrency and lifecycle risk surface. Controller state transitions intentionally allow only selected paths; changing them can wedge reset/delete/reconnect or allow I/O during teardown. Namespace scan/remove uses multiple locks plus SRCU; ordering regressions can deadlock reset versus scan, expose removed namespaces, or corrupt multipath current-path selection. Request completion must preserve retry, failover, authentication, keep-alive, and DNR semantics or it can cause data loss, hung I/O, or excessive reconnects. Queue limit and metadata/PI calculations are sensitive to NVMe version, command-set, fabrics-vs-PCIe capabilities, and compatibility module parameters. APST quirks and firmware activation paths can brick or stall problematic hardware if policy is changed casually. Duplicate namespace ID handling is deliberately conservative for shared/fabrics devices because incorrect acceptance can corrupt data through wrong by-id or multipath association.

Test signals: Build with PCI and fabrics transports, `CONFIG_NVME_MULTIPATH`, `CONFIG_BLK_DEV_ZONED`, `CONFIG_BLK_DEV_INTEGRITY`, `CONFIG_NVME_HOST_AUTH`, `CONFIG_BLK_SED_OPAL`, and fault injection variants. Exercise controller probe/reset/delete/surprise removal, namespace add/remove/rescan/AEN changed namespace, admin and namespace char-device ioctls, passthrough command effects that freeze queues, read/write/flush/discard/write-zeroes/zone append, PI metadata layouts including PI offset compatibility, FDP write streams, APST latency tolerance sysfs, keep-alive failures, firmware activation AER, fabrics failfast/reconnect, duplicate namespace ID rejection, multipath shared namespace add/remove, and debugfs fault-injected status with and without DNR.

# sources/distributed-fs/ceph-client/drivers/nvme/host/fabrics.c

Purpose: Implements the common NVMe over Fabrics host library. It manages fabric transport registration, host identity objects, `/dev/nvme-fabrics` controller creation, option parsing/validation, fabrics Property Get/Set commands, admin and I/O queue Connect commands, reconnect policy, queue count/map helpers, and module-level class/miscdevice setup.

Important APIs, types, and functions: Exported APIs are `nvmf_get_address()`, `nvmf_reg_read32()`, `nvmf_reg_read64()`, `nvmf_reg_write32()`, `nvmf_subsystem_reset()`, `nvmf_connect_admin_queue()`, `nvmf_connect_io_queue()`, `nvmf_should_reconnect()`, `nvmf_register_transport()`, `nvmf_unregister_transport()`, `nvmf_set_io_queues()`, `nvmf_map_queues()`, `nvmf_ip_options_match()`, and `nvmf_free_options()`. Internal flow uses `nvmf_host_add()`, `nvmf_host_default()`, `nvmf_lookup_transport()`, `nvmf_parse_options()`, `nvmf_check_required_opts()`, `nvmf_check_allowed_opts()`, `nvmf_create_ctrl()`, and the miscdevice file operations. Shared state is stored in `struct nvmf_ctrl_options`, `struct nvmf_host`, and registered `struct nvmf_transport_ops`.

Control flow: Module init creates a generated default host NQN/host ID pair, registers the `nvme-fabrics` class, creates a `ctl` device, and registers the `nvme-fabrics` miscdevice. Userspace writes comma-separated options to the miscdevice. `nvmf_dev_write()` serializes creation with `nvmf_dev_mutex`, duplicates the user buffer, and calls `nvmf_create_ctrl()`. Creation allocates options, parses generic and security/TLS/auth/queue/reconnect values, request-loads `nvme-$transport`, validates generic required options, looks up a registered transport under `nvmf_transports_rwsem`, pins the transport module, validates transport-required and allowed options, then calls `ops->create_ctrl()`. On success the file's seq private pointer holds the created controller until release drops its reference; reads before creation show option token syntax, while reads after creation return instance and cntlid.

Fabrics command helpers build NVMe fabrics capsules and submit them through core synchronous command APIs. Property reads and writes use `ctrl->fabrics_q`, reserved tags, and return the command result as controller register data. Admin Connect uses qid 0, `ctrl->fabrics_q`, AQ depth, KATO, generated connect data, and stores the returned controller ID. I/O Connect uses `ctrl->connect_q`, the target qid, and the cntlid assigned by admin connect. Both connect paths decode NVMe connect errors for targeted diagnostics and negotiate/wait for DH-CHAP authentication when the result advertises authentication; admin connect can accept secure concatenation only if requested, while I/O connect rejects ASCR because secure concatenation is not implemented there.

State and persistence behavior: Registered transports live in the `nvmf_transports` list under an rwsem. Host identities live in the `nvmf_hosts` list under a mutex and are refcounted; the code rejects reusing a host NQN with a different host ID or a host ID with a different NQN. The default host is generated at module load, not persisted by this file across reboot. Each successful parse owns dynamically allocated strings, secrets, key references, and a host reference in `struct nvmf_ctrl_options`; `nvmf_free_options()` releases them, using `kfree_sensitive()` for DH-CHAP secrets. Reconnect state is evaluated from `opts->max_reconnects`, `ctrl->nr_reconnects`, DNR statuses, and key errors.

Dependencies and integration points: Integrates with the NVMe core request helpers, NVMe auth, optional TCP TLS keyring support, Linux parser match tables, module autoloading, miscdevice/seq_file/class/device APIs, key retention, blk-mq hardware context maps, and fabric transport modules such as TCP/RDMA/FC that register `struct nvmf_transport_ops`. `core.c` calls fabrics register access and connect helpers through transport setup, while transport drivers call queue mapping helpers and option match helpers for duplicate connection detection.

Risks: Option parsing is security- and lifecycle-sensitive because it accepts root-facing device writes containing secrets, key IDs, transport names, queue counts, and reconnect policy. Incorrect mask handling can allow unsupported transport options or reject valid ones. Host NQN/host ID uniqueness is target-visible identity state; weakening it can create ambiguous authentication/authorization on targets. Connect result handling must preserve DNR, authentication, and secure-concatenation semantics or reconnect loops and auth failures become hard to diagnose. Queue splitting/mapping must match allocated controller queues; off-by-one or offset errors can route requests to nonexistent queues. `nvmf_ip_options_match()` intentionally treats local address/interface asymmetry as non-match, which is important for duplicate connection handling but easy to regress.

Test signals: Test `/dev/nvme-fabrics` create/read/release flows with valid and invalid option strings; missing required options; unknown/transport-disallowed options; discovery controller defaults; queue size/count bounds; ctrl_loss_tmo and fast_io_fail_tmo combinations; DH-CHAP secret validation; TLS key/keyring lookup with and without `CONFIG_NVME_TCP_TLS`; secure concatenation constraints; transport module autoload and unregister races; admin and I/O connect success, invalid parameter, invalid host, busy, auth required/failure, and DNR status; queue maps for shared, read/write split, and poll queues; duplicate IP option matching with and without host_traddr/host_iface.

# sources/distributed-fs/ceph-client/drivers/nvme/host/fabrics.h

Purpose: Declares the common NVMe over Fabrics host contract shared between the fabrics library, the NVMe core, and individual fabrics transports. It defines queue defaults, reconnect defaults, parsed controller options, target-visible host identities, transport registration operations, inline matching/utility helpers, and the exported common fabrics APIs.

Important APIs, types, and functions: Constants include `NVMF_MIN_QUEUE_SIZE`, `NVMF_MAX_QUEUE_SIZE`, `NVMF_DEF_QUEUE_SIZE`, `NVMF_DEF_RECONNECT_DELAY`, `NVMF_DEF_CTRL_LOSS_TMO`, and `NVMF_DEF_FAIL_FAST_TMO`. `struct nvmf_host` stores a refcounted Host NQN and UUID. The `NVMF_OPT_*` enum defines parser mask bits for transport, NQN, addresses, queue counts, KATO, host identity, duplicate connect, SQ flow control, TCP digests/TOS/TLS/keyring, discovery, DH-CHAP secrets, and secure concatenation. `struct nvmf_ctrl_options` stores all parsed connection policy and security state. `struct nvmf_transport_ops` is the registration ABI for transport modules, including required/allowed option masks and `create_ctrl()`. Inline helpers include `nvmf_ctlr_matches_baseopts()`, `nvmf_ctrl_subsysnqn()`, `nvmf_complete_timed_out_request()`, `nvmf_nr_io_queues()`, and `nvmf_get_virt_boundary()`.

Control flow: This header has no standalone execution, but it shapes fabric connection flow. Userspace options parsed in `fabrics.c` populate `struct nvmf_ctrl_options`, transport modules register a static `struct nvmf_transport_ops`, and `ops->create_ctrl()` receives validated options. Matching helpers allow duplicate-connect detection by comparing subsystem NQN, host NQN, host ID, and controller state. Queue count helpers sum requested default/read/write/poll queue counts while capping each group at online CPUs. Timed-out request completion sets host-aborted status and completes a started, not-yet-completed block request.

State and persistence behavior: The header describes volatile in-kernel state only. Host identities can provide cross-controller continuity while the module is loaded, but persistence across boot must come from userspace-provided hostnqn/hostid options or another layer. `struct nvmf_ctrl_options` owns allocated strings, key references, secret buffers, and a host reference until `nvmf_free_options()` releases them. The registered transport ops are expected to be statically allocated so module references keep their memory valid.

Dependencies and integration points: Includes Linux IPv4/IPv6 address headers and depends on NVMe core types from including translation units. It is consumed by `core.c`, `fabrics.c`, and fabric transports. It also exposes optional security/TLS/auth configuration fields used by NVMe TCP/TLS and NVMe host authentication code, plus blk-mq mapping helpers used during transport tagset setup.

Risks: The option mask enum is a shared ABI between parser, transport allowed/required masks, and user-facing token display; changing bits or forgetting to update masks can silently alter accepted connection syntax. `struct nvmf_ctrl_options` contains sensitive secret pointers, so ownership and cleanup must remain clear. `nvmf_ctlr_matches_baseopts()` intentionally rejects deleting/dead controllers and requires host identity equality; loosening it can create duplicate or unsafe connections. Queue count calculations cap by online CPUs per queue class, so transports must still validate against controller-provided queue counts. `nvmf_get_virt_boundary()` currently returns zero for fabrics, which is part of the DMA mapping contract exposed to queue limits.

Test signals: Build all fabrics transports against this header; validate parser token masks against displayed `/dev/nvme-fabrics` syntax; test duplicate connection matching for state, subsystem NQN, host NQN, host ID, address, and interface combinations; exercise timeout completion on started versus already completed requests; verify queue count totals for default, write, and poll combinations on systems with varying online CPU counts; run auth/TLS builds to catch missing key/secret field handling.

# sources/distributed-fs/ceph-client/drivers/nvme/host/fault_inject.c

Purpose: Provides NVMe host fault injection support when enabled. It creates per-controller or per-namespace debugfs fault injection controls and lets request completion paths synthesize NVMe status codes, optionally with the DNR bit, for targeted retry/error-path testing.

Important APIs, types, and functions: `nvme_fault_inject_init()` initializes a `struct nvme_fault_inject` for a device name, creates a debugfs parent directory, creates a standard `fault_inject` fault attribute directory, and adds writable `status` and `dont_retry` controls. `nvme_fault_inject_fini()` removes the debugfs tree. `nvme_should_fail()` selects namespace-level fault injection for disk requests or controller-level fault injection for admin/no-disk requests and writes the configured status into `nvme_req(req)->status` when `should_fail()` triggers. The boot/module parameter `nvme_core.fail_request=<interval>,<probability>,<space>,<times>` seeds the default fault attributes.

Control flow: Core initialization calls `nvme_fault_inject_init()` for controllers in `nvme_add_ctrl()` and for namespaces in `nvme_alloc_ns()`. The init function optionally parses the module parameter into a static default fault attribute, copies that default into the instance attribute, creates debugfs entries, and initializes status to `NVME_SC_INVALID_OPCODE` with `dont_retry=true`. Transport completion paths call the inline fault hook from `nvme.h`, which reaches `nvme_should_fail()` before normal NVMe completion handling. If the request has a disk, the namespace's fault controls apply; otherwise the controller's controls apply. On teardown, namespace and controller removal call `nvme_fault_inject_fini()`.

State and persistence behavior: All state is in memory and debugfs. Each `struct nvme_fault_inject` stores its copied `fault_attr`, debugfs parent dentry, configured NVMe status, and DNR policy. The global `fail_default_attr` and `fail_request` module parameter provide defaults for subsequently initialized instances, but runtime debugfs modifications are not persistent across removal/reload/reboot.

Dependencies and integration points: Depends on Linux fault injection support, debugfs, module parameters, block request/gendisk state, and NVMe request metadata. It is integrated by `core.c` at controller and namespace creation/removal and by the request completion inline in `nvme.h`. Testers control behavior under `/sys/kernel/debug/<device>/fault_inject/` plus `status` and `dont_retry` files.

Risks: Fault injection must never run as production behavior unless explicitly configured; accidental boot/module parameters or debugfs writes can make real devices report synthetic failures. The function only sets `nvme_req(req)->status`; callers must still follow normal completion flow for retry/DNR/failover semantics to be exercised. Namespace lookup assumes `disk->private_data` is an NVMe namespace and warns if absent. Debugfs creation failures are nonfatal, so tests must confirm entries exist before assuming injection is active. The DNR default makes injected errors non-retryable unless tests clear `dont_retry`.

Test signals: Build with NVMe fault injection enabled, boot with and without `nvme_core.fail_request`, verify controller and namespace debugfs trees appear and disappear on add/remove, set status values such as invalid opcode, path error, and media/protection errors, toggle `dont_retry`, and confirm request completion logs/retries/failover match the injected NVMe status. Include admin/no-disk requests to exercise controller-level injection and normal block I/O to exercise namespace-level injection.
