# sources/distributed-fs/ceph-client/net/mac80211/rx.c

## Purpose
`rx.c` is the central mac80211 receive path for frames delivered by low-level wireless drivers. It validates driver RX metadata, mirrors frames to monitor interfaces with radiotap metadata, updates scan/BSS state from beacons and probe responses, selects the target virtual interface/link/station, performs duplicate detection, A-MPDU reorder release, decryption, defragmentation, A-MSDU conversion, mesh forwarding, data delivery, management/action dispatch, and optional fast RX/802.3 decapsulation. It also exposes driver-facing entry points for normal NAPI RX, hard-IRQ-safe queued RX, power-save notifications, and BA reorder-buffer maintenance.

## Important APIs, Types, and Functions
Driver-facing receive APIs are `ieee80211_rx_list()`, `ieee80211_rx_napi()`, and `ieee80211_rx_irqsafe()`. `ieee80211_rx_list()` is the main 802.11/802.3 entry point, validates `struct ieee80211_rx_status`, handles monitor delivery, starts KCOV remote coverage, and calls either `__ieee80211_rx_handle_packet()` or `__ieee80211_rx_handle_8023()`. `ieee80211_rx_napi()` wraps receive processing in RCU and forwards the completed skb list through GRO or `netif_receive_skb_list()`. `ieee80211_rx_irqsafe()` queues hard-IRQ RX skbs onto `local->skb_queue` for tasklet processing.

Monitor/radiotap helpers include `ieee80211_rx_radiotap_hdrlen()`, `ieee80211_add_rx_radiotap_header()`, `ieee80211_make_monitor_skb()`, `ieee80211_rx_monitor()`, `ieee80211_clean_skb()`, `should_drop_frame()`, `ieee80211_validate_monitor_radio()`, and `ieee80211_handle_mu_mimo_mon()`. These account for FCS, driver-provided VHT/HE/HE-MU/L-SIG/TLV data, per-chain antenna signals, timestamps, zero-length PSDUs, monitor radio masks, and MU-MIMO follow-address copies.

Core receive state is carried in `struct ieee80211_rx_data`: `local`, `sdata`, `link`, `link_sta`, `sta`, `link_id`, `skb`, `seqno_idx`, `security_idx`, key/decryption fields, and optional output list. Link and station binding is centralized in `ieee80211_rx_data_set_sta()`, `ieee80211_rx_data_set_link()`, `ieee80211_rx_for_interface()`, and `ieee80211_prepare_and_rx_handle()`, with MLO address translation performed before slow-path handlers.

Slow-path handlers are organized through `ieee80211_invoke_rx_handlers()` and `ieee80211_rx_handlers()`. Important handlers are `ieee80211_rx_h_check_dup()`, `ieee80211_rx_h_check()`, `ieee80211_rx_h_check_more_data()`, `ieee80211_rx_h_uapsd_and_pspoll()`, `ieee80211_rx_h_sta_process()`, `ieee80211_rx_h_decrypt()`, `ieee80211_rx_h_defragment()`, `ieee80211_rx_h_michael_mic_verify()` from TKIP support, `ieee80211_rx_h_amsdu()`, `ieee80211_rx_h_data()`, `ieee80211_rx_h_ctrl()`, `ieee80211_rx_h_mgmt_check()`, `ieee80211_rx_h_action()`, `ieee80211_rx_h_userspace_mgmt()`, `ieee80211_rx_h_action_post_userspace()`, `ieee80211_rx_h_action_return()`, `ieee80211_rx_h_ext()`, and `ieee80211_rx_h_mgmt()`.

A-MPDU reorder support is implemented by `ieee80211_rx_reorder_ampdu()`, `ieee80211_sta_manage_reorder_buf()`, `ieee80211_sta_reorder_release()`, `ieee80211_release_reorder_frame()`, `ieee80211_release_reorder_frames()`, `ieee80211_release_reorder_timeout()`, and exported `ieee80211_mark_rx_ba_filtered_frames()`. Fragment cache support is exposed through `ieee80211_init_frag_cache()` and `ieee80211_destroy_frag_cache()` and internally uses `ieee80211_reassemble_add()`, `ieee80211_reassemble_find()`, and `requires_sequential_pn()`.

Data delivery and fast RX are handled by `__ieee80211_data_to_8023()`, `ieee80211_frame_allowed()`, `ieee80211_deliver_skb()`, `ieee80211_deliver_skb_to_local_stack()`, `ieee80211_rx_mesh_data()`, `ieee80211_rx_mesh_fast_forward()`, `ieee80211_check_fast_rx()`, `ieee80211_clear_fast_rx()`, `ieee80211_check_fast_rx_iface()`, `ieee80211_invoke_fast_rx()`, and `ieee80211_rx_8023()`. Power-save exports are `ieee80211_sta_ps_transition()`, `ieee80211_sta_pspoll()`, and `ieee80211_sta_uapsd_trigger()`.

## Control Flow, State, and Persistence
The top-level driver path validates band, bitrate encoding, NSS, GI, link id, local quiescing/suspend/reconfiguration/started state, and then clears `status->rx_flags`. Non-802.3 frames pass through `ieee80211_rx_monitor()`, which can clone frames to all matching monitor interfaces while returning a cleaned original skb for normal processing. Beacons, S1G beacons, and probe responses are handed to `ieee80211_scan_rx()` before interface delivery so scan/BSS tables are updated independently of whether a data or management consumer accepts the frame.

`__ieee80211_rx_handle_packet()` linearizes management frames, ensures headers are pulled, parses QoS into `seqno_idx/security_idx`, then first tries STA-directed delivery for data frames. If a `pubsta` is supplied, it uses that station directly; otherwise it iterates station entries keyed by transmitter address and copies the skb for all but the final consumer. If no station path consumes it, the function iterates running non-monitor, non-AP-VLAN interfaces and calls `ieee80211_rx_for_interface()` for each candidate. Unconsumed frames are freed.

`ieee80211_accept_frame()` is the per-interface admission gate. It enforces BSSID/address/DS-bit rules for station, IBSS, OCB, mesh, AP/AP-VLAN, P2P device, NAN, and NAN data interfaces. It rejects self-originated, malformed, wrong-BSSID, multicast data-to-AP, TDLS-peer, and unexpected robust-management cases, and triggers IBSS/OCB no-STA discovery where appropriate. MLO paths can infer link id from status, link station address, or channel frequency.

The slow path starts with duplicate and class checks, then routes QoS data through the reorder buffer. Reorder state persists in `struct tid_ampdu_rx`: `head_seq_num`, `ssn`, `buf_size`, `stored_mpdu_num`, per-slot `reorder_buf`, `reorder_time`, `reorder_buf_filtered`, timers, timeout values, and flags such as `auto_seq` and `removed`. BAR frames and timeout callbacks release buffered MPDUs into the same handler chain, with `IEEE80211_RX_DEFERRED_RELEASE` marking delayed frames.

Security state is selected before decryption. `ieee80211_rx_h_decrypt()` chooses PTK/STK, GTK, IGTK, or BIGTK according to unicast/multicast, Protected bit, MMIE key id, beacon protection, IV stripping, and MFP rules. It calls cipher-specific helpers for WEP, TKIP, CCMP, GCMP, AES-CMAC, and AES-GMAC, marks frames decrypted, and reports unprotected beacon/MLME events to cfg80211. `ieee80211_drop_unencrypted_mgmt()` then enforces MFP, protected dual action, robust action, encrypted association, and beacon protection policy. Fragment reassembly persists pending fragments in per-sdata or per-station fragment caches and validates sequential CCMP/GCMP PN plus key color to prevent mixed-key fragment attacks.

Data frames are converted to Ethernet by `__ieee80211_data_to_8023()`, checked against authorization/encryption/control-port policy, optionally forwarded in mesh mode, and then delivered locally or bridged back to wireless peers in AP mode. Control port frames may be diverted to `cfg80211_rx_control_port()`, and PAE group destinations are rewritten to the interface address before local stack delivery to avoid bridge leakage. TDLS channel-switch requests/responses are queued to interface work rather than delivered as ordinary data.

Management/action control flow validates frame sizes by category and action. Known actions are either handled immediately, queued to the interface workqueue, passed to userspace through `cfg80211_rx_mgmt_ext()`, answered locally, or returned to the sender as rejected action frames. Covered categories include HT, VHT, BACK/ADDBA/DELBA/NDP BA, spectrum management, self-protected mesh peering, mesh path selection, S1G TWT, protected EHT TTLM/link reconfiguration/EPCS/EML OMN, public/protected dual channel-switch actions, and SA Query.

Fast RX is a cached station optimization. `ieee80211_check_fast_rx()` builds `struct ieee80211_fast_rx` only for supported interface types, authorized stations, compatible powersave/offload settings, no unsupported software reorder requirements, and supported ciphers. `ieee80211_invoke_fast_rx()` requires duplicate validation, PN/decryption validation when keyed, no fragments, expected DS bits, unicast-to-interface address, and ordinary RFC1042 payloads. After it commits past punt points it trims MIC/ICV, handles A-MSDU if needed, converts headers in place, optionally mesh-forwards, updates per-link or per-CPU stats, and delivers without the full handler chain.

Persistent side effects include station/link RX counters, EWMA signal state, last rate/last RX timestamps, duplicate sequence caches, multicast sequence cache for MLD station mode, AP power-save flags and buffered TID bitmaps, reorder buffers/timers, fragment cache entries, mesh path/proxy updates, fast RX RCU pointers, BSS/color-collision notifications, interface skb queues, local dynamic power-save timer, LED triggers, and netdev software RX statistics.

## Dependencies and Integration Points
This file sits between low-level mac80211 drivers, cfg80211/nl80211, the Linux networking stack, and other mac80211 subsystems. It depends on `ieee80211_i.h`, `driver-ops.h`, `led.h`, `mesh.h`, `wep.h`, `wpa.h`, `tkip.h`, `wme.h`, and `rate.h`, plus kernel skb, RCU, timer, bitops, netdevice, radiotap, and unaligned-access helpers.

Driver integration uses `drv_*` callbacks for station notifications, TWT setup/teardown, event callbacks, decap offload, and scan/management side effects in other files. cfg80211 integration includes BSS reporting via scan code, management RX delivery, unprotected MLME reporting, control-port delivery, OBSS beacon reporting, BSS color collision notifications, spurious/unexpected frame notifications, and scheduled userspace management handling. Net stack integration uses `netif_receive_skb()`, `netif_receive_skb_list()`, `napi_gro_receive()`, `eth_type_trans()`, `dev_queue_xmit()`, and software netstats.

`scan.c` is called directly through `ieee80211_scan_rx()`. `s1g.c` is used through `ieee80211_s1g_use_ndp_ba()` and the S1G TWT action queueing path. `spectmgmt.c` is used through `ieee80211_process_measurement_req()` and channel-switch action validation. Mesh behavior integrates with mesh path, proxy, HWMP, MPS, and fast TX helpers. Crypto helpers maintain key replay state and decrypt/verify frame payloads.

# sources/distributed-fs/ceph-client/net/mac80211/s1g.c

## Purpose
`s1g.c` contains mac80211 support for IEEE 802.11ah/S1G-specific station setup and Target Wake Time handling. It initializes S1G rate/statistics representation, recognizes and processes S1G TWT action frames, builds S1G TWT setup/teardown management responses, translates S1G capability IEs into station capability state, and decides when S1G NDP BlockAck should be used.

## Important APIs, Types, and Functions
Public mac80211 helpers are `ieee80211_s1g_sta_rate_init()`, `ieee80211_s1g_is_twt_setup()`, `ieee80211_s1g_rx_twt_action()`, `ieee80211_s1g_status_twt_action()`, `ieee80211_s1g_cap_to_sta_s1g_cap()`, and `ieee80211_s1g_use_ndp_ba()`.

Internal frame-building helpers are `ieee80211_s1g_send_twt_setup()` and `ieee80211_s1g_send_twt_teardown()`. Internal receive/status helpers are `ieee80211_s1g_rx_twt_setup()`, `ieee80211_s1g_rx_twt_teardown()`, and `ieee80211_s1g_tx_twt_setup_fail()`. Key protocol structures are `struct ieee80211_mgmt`, `struct ieee80211_twt_setup`, `struct ieee80211_twt_params`, `struct ieee80211_s1g_cap`, and `struct ieee80211_sta_s1g_cap`.

## Control Flow, State, and Persistence
`ieee80211_s1g_sta_rate_init()` marks a station's default-link last TX/RX rate state as S1G so generic rate/stat reporting does not expose legacy bitrates for S1G peers. `ieee80211_s1g_is_twt_setup()` is a small classifier for action frames with S1G category and TWT setup action code.

For received TWT action frames, `ieee80211_s1g_rx_twt_action()` asserts the wiphy lock, finds the BSS station by source address, and dispatches setup or teardown. Setup handling clears the requester bit, rejects broadcast TWT negotiation by rewriting the setup command to reject, marks TWT information as RX-disabled because it is not supported yet, calls `drv_add_twt_setup()` for accepted unicast setup, and sends a TWT setup response back to the station. Teardown handling calls `drv_twt_teardown_request()` with the flow id carried in the action body.

For TX status of TWT action frames, `ieee80211_s1g_status_twt_action()` finds the station by destination address and treats failed setup transmission as a reason to tear down the negotiated flow. `ieee80211_s1g_tx_twt_setup_fail()` extracts the flow id from `req_type`, notifies the driver teardown hook, and sends an S1G TWT teardown frame.

`ieee80211_s1g_cap_to_sta_s1g_cap()` clears and fills the public station S1G capability from the S1G capability IE, marks `s1g = true`, updates `agg.max_amsdu_len` according to the S1G max-MPDU bit, and recalculates aggregate limits. `ieee80211_s1g_use_ndp_ba()` returns true only when the vif is configured for S1G, hardware advertises NDP BlockAck support, and the peer has S1G capability.

Persistent side effects include station rate/stat fields, station S1G capability bytes, aggregate maximum A-MSDU length, driver-owned TWT flow state through callbacks, and transmitted management action skbs.

## Dependencies and Integration Points
The file includes Linux/mac80211 IEEE 802.11 definitions plus `ieee80211_i.h` and `driver-ops.h`. It integrates with driver callbacks `drv_add_twt_setup()` and `drv_twt_teardown_request()`, transmit helper `ieee80211_tx_skb()`, station lookup `sta_info_get_bss()`, aggregate recalculation `ieee80211_sta_recalc_aggregates()`, and RX/BLOCKACK logic in `rx.c` through `ieee80211_s1g_use_ndp_ba()`.

## Risks and Test Signals
Risks include insufficient length validation before dereferencing TWT bodies if callers do not prefilter correctly, incorrect flow-id extraction on failed setup, mismatch between driver TWT state and response/teardown frame transmission failures, unsupported broadcast TWT negotiation being represented accurately as a rejection, and stale aggregate limits after capability updates. Tests should cover S1G station init, S1G/non-S1G action classification, TWT setup acceptance and broadcast rejection, teardown request flow ids, TX-status setup failure teardown, S1G capability conversion for both max-MPDU values, aggregate recalculation, and NDP BA selection for all combinations of vif S1G, hardware support, and peer capability.

# sources/distributed-fs/ceph-client/net/mac80211/scan.c

## Purpose
`scan.c` implements mac80211 scan receive processing, BSS table updates, active/passive software scan state machines, hardware scan setup/completion, deferred scan execution, IBSS internal scans, cancellation, and scheduled scan start/stop/result callbacks. It is the bridge between cfg80211 scan requests, low-level driver hardware scan capabilities, mac80211 offchannel behavior, and RX-side beacon/probe-response discovery.

## Important APIs, Types, and Functions
Public/internal scan APIs include `ieee80211_rx_bss_put()`, `ieee80211_inform_bss()`, `ieee80211_bss_info_update()`, `ieee80211_scan_rx()`, `ieee80211_scan_completed()`, `ieee80211_run_deferred_scan()`, `ieee80211_scan_work()`, `ieee80211_request_scan()`, `ieee80211_request_ibss_scan()`, `ieee80211_scan_cancel()`, `__ieee80211_request_sched_scan_start()`, `ieee80211_request_sched_scan_start()`, `ieee80211_request_sched_scan_stop()`, `ieee80211_sched_scan_results()`, `ieee80211_sched_scan_end()`, `ieee80211_sched_scan_stopped_work()`, and `ieee80211_sched_scan_stopped()`.

BSS update helpers are `is_uapsd_supported()`, `ieee80211_inform_bss()`, and `ieee80211_bss_info_update()`. Scan setup/state helpers are `ieee80211_prepare_scan_chandef()`, `ieee80211_prep_hw_scan()`, `__ieee80211_scan_completed()`, `ieee80211_start_sw_scan()`, `__ieee80211_can_leave_ch()`, `ieee80211_can_scan()`, `ieee80211_send_scan_probe_req()`, `ieee80211_scan_state_send_probe()`, `__ieee80211_start_scan()`, `ieee80211_scan_get_channel_time()`, `ieee80211_scan_state_decision()`, `ieee80211_scan_state_set_channel()`, `ieee80211_scan_state_suspend()`, and `ieee80211_scan_state_resume()`.

Important state lives in `struct ieee80211_local`: RCU pointers `scan_req`, `scan_sdata`, `sched_scan_req`, `sched_scan_sdata`; bitmask `scanning`; `scan_work`; `scan_info`; `hw_scan_req`; `hw_scan_band`; `hw_scan_ies_bufsize`; `scan_addr`; `scan_channel_idx`; `scan_chandef`; `leave_oper_channel_time`; `next_scan_state`; and the internal IBSS scan request/SSID. Scan state bits include hardware/software/on-channel scanning, completion/abort, hardware cancellation, beacon wait/done, and related deferred flags.

## Control Flow, State, and Persistence
RX-side scan processing starts in `ieee80211_scan_rx()`, which accepts probe responses, regular beacons, and S1G beacons. It validates minimum header length, upgrades passive scans to active after receiving a beacon/probe response on a no-IR/radar channel by setting `SCAN_BEACON_DONE`, resolves the channel from RX status frequency, filters probe responses by destination/randomization/OCE/6 GHz/MLO link addresses, rejects non-broadcast non-S1G beacons, skips BSS updates when only monitor interfaces are open, and updates cfg80211/mac80211 BSS state through `ieee80211_bss_info_update()`.

`ieee80211_bss_info_update()` builds cfg80211 BSS metadata from RX status, including signal, channel, boot time, and optional parent TSF/BSSID for associated station scans with RX timestamps. `ieee80211_inform_bss()` parses beacon/probe-response IEs and stores device timestamps, corruption flags, ERP, supported rates, WMM/UAPSD support, beacon rate, and VHT capability info in `struct ieee80211_bss`. BSS references returned by cfg80211 are released through `ieee80211_rx_bss_put()`.

Starting a scan is centralized in `__ieee80211_start_scan()`. It rejects concurrent scans, validates MLO TSF-report link ids, checks radar/CAC/remain-on-channel/connection-poll blockers, and either defers by storing `scan_req/scan_sdata` or starts immediately. Hardware scans allocate `local->hw_scan_req`, size/build probe request IEs, handle `SINGLE_SCAN_ON_ALL_BANDS` versus per-band scan chunks, copy request addressing and 6 GHz parameters, set `SCAN_HW_SCANNING`, and call `drv_hw_scan()`. If a driver returns `1`, non-P2P-GO scans fall back to software scanning.

Software scans use either on-channel scanning for single operating-channel requests or a state machine driven by `ieee80211_scan_work()`. Normal software scan starts with `drv_sw_scan_start()`, offchannel stop for vifs, queue flush, filter reconfiguration, max-power channel configuration, and `SCAN_SW_SCANNING`. The worker cycles through `SCAN_DECISION`, `SCAN_SET_CHANNEL`, `SCAN_SEND_PROBE`, `SCAN_SUSPEND`, `SCAN_RESUME`, and `SCAN_ABORT`. It limits offchannel dwell while associated, suspends when latency or pending TX demands it, sends active probe requests after probe delay unless passive rules apply, waits passive/active dwell times, and completes when channels are exhausted.

Completion is split between driver API `ieee80211_scan_completed()` and internal `__ieee80211_scan_completed()`. Driver completion sets `SCAN_COMPLETED` and optionally `SCAN_ABORTED`, stores scan info, and queues work. Internal completion can advance multi-band hardware scans by preparing the next band and invoking `drv_hw_scan()` again; otherwise it frees `hw_scan_req`, clears scan RCU pointers and state, synchronizes RCU, calls `cfg80211_scan_done()` for external requests, restores normal channel/power/filter/offchannel state, recalculates idle, notifies MLME/IBSS, requeues interface work, and restarts remain-on-channel work if needed.

Cancellation distinguishes deferred/software scans from hardware scans. `ieee80211_scan_cancel()` sets `SCAN_HW_CANCELLED` and calls `drv_cancel_hw_scan()` for active hardware scans but relies on the driver to report completion; it directly cancels work and completes aborted software/deferred scans. `ieee80211_run_deferred_scan()` starts a stored request once blockers clear. `ieee80211_request_ibss_scan()` constructs an internal request over allowed non-6GHz/non-S1G channels or caller-supplied allowed channels, fills the SSID, and uses the same start path.

Scheduled scans are driver-offloaded. `__ieee80211_request_sched_scan_start()` builds per-band probe IEs and calls `drv_sched_scan_start()`, storing RCU request/sdata pointers on success. Stop clears the request pointer first to prevent restart, calls `drv_sched_scan_stop()`, and clears the sdata pointer on success. Results and stopped notifications call cfg80211 directly or through `sched_scan_stopped_work`, while in-reconfig stopped notifications are ignored so reconfiguration can restore state.

Persistent side effects include cfg80211 BSS cache entries, mac80211 `ieee80211_bss` metadata, scan request pointers, generated random scan source address, hardware scan request allocation, scan channel index/chandef, scan state bits, offchannel/idle/power/filter state, delayed work scheduling, and scheduled scan RCU pointers.

## Dependencies and Integration Points
The file depends on cfg80211 scan/BSS APIs, mac80211 driver callbacks from `driver-ops.h`, probe request builders and IE builders, offchannel helpers, channel context configuration, regulatory/CAC checks, MLME and IBSS notifications, mesh header inclusion, qdisc state for latency decisions, and net/wiphy delayed work infrastructure. It is invoked by `rx.c` for beacons/probe responses and by cfg80211/mac80211 request paths for scan operations.

Low-level drivers integrate through `drv_hw_scan()`, `drv_cancel_hw_scan()`, `drv_sw_scan_start()`, `drv_sw_scan_complete()`, `drv_sched_scan_start()`, and `drv_sched_scan_stop()`, then report hardware scan completion via exported `ieee80211_scan_completed()` and scheduled scan events via exported `ieee80211_sched_scan_results()`/`ieee80211_sched_scan_stopped()`.

## Risks and Test Signals
Risks include races between hardware completion/cancel/work processing, RCU lifetime of scan requests and scan interfaces, memory sizing for hardware scan IE buffers across multiple bands, deferred scan requests stranded behind remain-on-channel/CAC/connection-poll blockers, incorrect passive-to-active upgrade on radar/no-IR channels, wrong probe-response filtering with randomized or MLO link addresses, and inconsistent cleanup when hardware scan falls back to software scan or multi-band hardware scan chunking fails.

Protocol and regulatory risks include scanning channels disallowed for the wdev, treating 6 GHz broadcast probe responses correctly, S1G beacon minimum-length handling, offchannel dwell exceeding latency limits, low-priority scan abort behavior under TX load, and scheduled scan stale pointer handling during reconfiguration. Tests should cover BSS updates for valid/corrupt beacon/probe responses, UAPSD/WMM/rates/ERP/VHT fields, parent TSF reporting for MLO and non-MLO, active/passive/on-channel software scans, radar/no-IR beacon-wait upgrade, hardware scan per-band sequencing, cancellation before and after driver completion, IBSS internal scan channel filtering, scheduled scan start/stop/results/stopped callbacks, random MAC/random sequence probe requests, and failure injection for allocations and driver callbacks.

# sources/distributed-fs/ceph-client/net/mac80211/spectmgmt.c

## Purpose
`spectmgmt.c` implements mac80211 spectrum-management helpers for channel switch announcement parsing and measurement request refusal. It converts channel-switch IEs into validated cfg80211 channel requests, checks advertised bandwidth against station connection capabilities and bandwidth limits, handles 6 GHz HE/EHT operating encodings, captures mesh CSA parameters, and sends a measurement report refusing unsupported measurement requests.

## Important APIs, Types, and Functions
The primary exported/internal APIs are `ieee80211_parse_ch_switch_ie()` and `ieee80211_process_measurement_req()`. Internal helpers are `wbcs_elem_to_chandef()`, `validate_chandef_by_ht_vht_oper()`, `validate_chandef_by_6ghz_he_eht_oper()`, and `ieee80211_send_refuse_measurement_request()`.

Important data structures include `struct ieee802_11_elems`, `struct ieee80211_csa_ie`, `struct cfg80211_chan_def`, `struct ieee80211_conn_settings`, `struct ieee80211_wide_bw_chansw_ie`, `struct ieee80211_bandwidth_indication`, `struct ieee80211_ext_chansw_ie`, `struct ieee80211_sec_chan_offs_ie`, `struct ieee80211_he_6ghz_oper`, `struct ieee80211_eht_operation_info`, and `struct ieee80211_msrment_ie`.

## Control Flow, State, and Persistence
`ieee80211_parse_ch_switch_ie()` begins by clearing the output `csa_ie`, selecting channel switch, extended channel switch, secondary-channel-offset, wide-bandwidth-channel-switch, and EHT bandwidth-indication elements from parsed IEs. It disables HT/VHT bandwidth elements when the current connection mode or bandwidth limit cannot use them. Extended channel switch IEs supply operating class, channel, count, and mode when understood; otherwise ordinary CSA supplies the channel/count/mode. Mesh channel switch parameters add TTL, mode flags, precedence value, and optional reason code.

The parser converts the new channel number and band to a frequency, rejects unsupported or disabled channels, derives an initial operating chandef from secondary channel offset or non-HT/5/10 MHz state, and stores that as both operating and AP channel request. It then tries richer bandwidth encodings in priority order: EHT bandwidth indication, VHT wide bandwidth channel switch, operating class chandef, or the initial CSA chandef. For 6 GHz it validates by synthesizing HE 6 GHz and optional EHT operation elements; for other bands it validates by synthesizing HT and VHT operation elements. Invalid capability-derived chandefs are ignored by nulling `chan`.

When a valid new chandef remains, the function records the AP-advertised chandef, downgrades it until it fits `conn->bw_limit`, verifies compatibility with the initial CSA chandef, and stores it as `csa_ie->chanreq.oper`. It also parses maximum channel switch time from its three-byte little-endian field. Return values distinguish no understood CSA data (`1`), valid parsed data (`0`), and fatal unsupported/inconsistent channel data (`-EINVAL`).

`wbcs_elem_to_chandef()` handles VHT WBCS encodings, including deprecated 160/80+80 forms and the modern 80 MHz encoding where `ccfs1` disambiguates 160 versus 80+80. `validate_chandef_by_ht_vht_oper()` reconstructs HT/VHT operation elements from a candidate chandef and lets core mac80211 validate against VHT capability. `validate_chandef_by_6ghz_he_eht_oper()` reconstructs HE 6 GHz and EHT operation state, including 320 MHz, 160 MHz, 80+80, 80, 40, and 20 MHz encodings, then validates with `ieee80211_chandef_he_6ghz_oper()`.

Measurement request handling is intentionally minimal. `ieee80211_process_measurement_req()` always sends a refusal report through `ieee80211_send_refuse_measurement_request()`. The refusal helper allocates an action management frame, fills addresses, spectrum-management category, measurement report action, dialog token, measurement report IE, request token/type, and refused mode bit, then transmits it with `ieee80211_tx_skb()`.

Persistent side effects are limited to the caller-provided `struct ieee80211_csa_ie` output and transmitted refusal skbs. The file does not maintain its own long-lived state.

## Dependencies and Integration Points
The file depends on cfg80211 channel/frequency/chandef helpers, mac80211 connection mode and bandwidth-limit definitions, parsed-element output from the IE parser, local wiphy channel tables, and TX skb helpers. `rx.c` calls `ieee80211_process_measurement_req()` for 5 GHz station measurement requests and queues channel-switch actions for station, IBSS, and mesh processing after basic validation. MLME/IBSS/mesh code consumes `ieee80211_parse_ch_switch_ie()` results to perform channel switch decisions.

## Risks and Test Signals
Risks include accepting inconsistent CSA/WBCS/BWI information, mishandling operating class to band conversion, incorrect bandwidth downgrades versus disconnection decisions, 6 GHz HE/EHT synthetic operation mismatches, 320/160/80+80 center-frequency errors, disabled-channel handling, and silent behavior differences for unprotected action frames where logging is suppressed. Measurement handling is spec-incomplete by design and only refuses requests.

Tests should cover CSA-only, ECSA, mesh CSA parameters, invalid operating classes, disabled/unsupported channels, secondary channel offsets, 5/10 MHz preservation, WBCS 40/80/160/80+80 encodings, EHT bandwidth indication with puncturing, 6 GHz HE/EHT validation including 320 MHz, bandwidth-limit downgrade loops, incompatible chandef rejection, max channel switch time parsing, unprotected action logging behavior, and measurement request refusal frame contents/allocation failure.
