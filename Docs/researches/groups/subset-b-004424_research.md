# sources/distributed-fs/ceph-client/drivers/net/ethernet/freescale/gianfar.c

## Purpose
`gianfar.c` is the main Freescale/NXP Gianfar, TSEC, eTSEC, and FEC Ethernet MAC driver. It binds OF platform devices, maps queue-group register blocks, configures MAC/DMA/filer hardware, attaches phylib, registers a `net_device`, and implements the normal Linux data path for TX, RX, NAPI, interrupts, MTU changes, feature toggles, timestamping, suspend/resume, and wake-on-LAN.

## Important APIs, types, and functions
The public driver entry points are the platform driver `gfar_driver`, `gfar_probe()`, `gfar_remove()`, the `gfar_netdev_ops` table, and the exported helpers `startup_gfar()`, `stop_gfar()`, and `gfar_mac_reset()` used by ethtool support. Device-tree and resource setup is handled by `gfar_of_init()` and `gfar_parse_group()`. Runtime open/close flows use `gfar_enet_open()`, `init_phy()`, `gfar_request_irq()`, `startup_gfar()`, `gfar_close()`, `stop_gfar()`, and `gfar_free_irq()`. TX is centered on `gfar_start_xmit()` and `gfar_clean_tx_ring()`. RX is centered on `gfar_receive()`, `gfar_poll_rx_sq()`, `gfar_clean_rx_ring()`, `gfar_get_next_rxbuff()`, `gfar_process_frame()`, and `gfar_alloc_rx_buffs()`. Error, reset, and PM paths use `gfar_error()`, `gfar_interrupt()`, `gfar_timeout()`, `gfar_reset_task()`, `reset_gfar()`, `gfar_suspend()`, `gfar_resume()`, and `gfar_restore()`.

## Control flow
Probe starts by parsing the OF node to decide single-queue/single-group versus multi-queue/multi-group mode. It allocates an `alloc_etherdev_mq()` netdev, creates per-TX and per-RX queue objects, maps register blocks, parses IRQs, reads MAC/PHY/TBI and hardware capability properties, detects errata, initializes NAPI instances, assigns netdev and ethtool operations, enables supported checksum/VLAN/headroom features, programs default ring sizes and interrupt coalescing values, initializes the hardware, registers the netdev, records WOL capabilities, names IRQs, and seeds the receive filer table.

Opening the device attaches to the PHY, requests IRQs, resets the MAC, allocates coherent descriptor rings plus software skb/page tracking arrays, initializes descriptors, writes descriptor base registers, clears `GFAR_DOWN`, starts DMA, enables interrupts, starts phylib, enables NAPI, and wakes TX queues. Closing cancels pending reset work, stops netdev queues, marks the device down, disables NAPI, halts DMA, stops and disconnects the PHY, frees DMA/skb/page resources, and releases IRQs.

The TX path maps the skb head and fragments into one or more TxBDs, optionally prepends the hardware frame control block for checksum/VLAN/timestamp work, works around checksum errata by falling back to `skb_checksum_help()`, updates byte queue limits, publishes descriptors with `gfar_wmb()`, stores the skb in the software ring, updates free descriptor counts under the per-queue lock, and pokes `TSTAT` to restart DMA. TX completion runs from NAPI, waits for the final descriptor to lose `TXBD_READY`, unmaps DMA, extracts hardware TX timestamps when requested, frees the skb, advances dirty indices, restores descriptor availability, and wakes stopped subqueues.

The RX path masks RX interrupts and schedules NAPI. The poller clears RX events, drains ready RxBDs up to budget, builds skbs from page-backed buffers, reuses the free half of reusable pages when possible, handles multi-descriptor frames, accounts and drops malformed frames, removes FCB/padding/FCS, attaches RX checksum, VLAN, and timestamp metadata, submits packets through GRO, replenishes descriptors in batches, updates last-free-RxBD flow-control pointers, completes NAPI, and unmasks RX interrupts.

## State and persistence behavior
All state is in kernel memory and scoped to the platform device and netdev lifetime. `struct gfar_private` stores hardware capability flags, errata flags, PHY/TBI nodes, queue arrays, group register mappings, RMON overflow state, hash register pointers, WOL settings, cached filer tables, pause/autoneg flags, timestamp flags, and reset/down state bits. Each TX queue keeps descriptor pointers, skb ring indices, free counts, BQL accounting data, coalescing config, stats, and a spinlock. Each RX queue keeps descriptors, page buffers, clean/use/allocation indices, an in-progress skb for fragmented receives, coalescing config, stats, and the last-free-BD register pointer. There is no disk persistence; settings survive only until driver removal, though WOL and ethtool state may be visible across suspend/resume while the netdev exists.

## Dependencies and integration points
The file integrates Linux platform/OF probing, phylib and fixed PHY support, net_device operations, NAPI, IRQ core, DMA mapping, skb/page APIs, VLAN acceleration, checksum offload, hardware timestamping, byte queue limits, GRO, power management, and optional netpoll. It consumes register and structure definitions from `gianfar.h` and exposes `gfar_ethtool_ops` from `gianfar_ethtool.c`. Device-tree properties such as model, `queue-group`, `phy-handle`, `tbi-handle`, `bd-stash`, `rx-stash-len`, `rx-stash-idx`, `fsl,magic-packet`, and `fsl,wake-on-filer` determine much of the runtime shape.

## Risks and edge cases
The highest-risk areas are descriptor ownership, DMA ordering, and reset coordination. The driver relies on power-of-two rings, wrap bits, `gfar_wmb()`, and careful software ring indices; mistakes can corrupt DMA ownership or leak mappings. Reset, MTU, coalescing, feature, and timestamp changes all serialize through `GFAR_RESETTING` and may stop/start the whole device. RX page reuse depends on page reference counts and pfmemalloc checks. TX timestamping changes descriptor layout and DMA unmap length. Errata workarounds alter checksum behavior and DMA halt polling. WOL filer programming temporarily replaces the normal filer table, so resume must restore cached rules. Error interrupts can schedule asynchronous reset while the normal close path is running.

## Test signals
Useful coverage includes OF probe for `gianfar` and `fsl,etsec2`, one and two queue-group devices, PHY attach failures, fixed PHY, SGMII/TBI setup, open/close loops, TX with linear and fragmented skbs, checksum and VLAN offload on/off, hardware TX/RX timestamp enable/disable, jumbo MTU changes, RX fragmented frames, RX errors and allocation failure counters, interrupt coalescing, netpoll, multicast/promiscuous changes, TX timeout recovery, suspend/resume with no WOL, magic-packet WOL, filer unicast WOL, and RMON overflow accounting.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/freescale/gianfar.h

## Purpose
`gianfar.h` is the shared hardware and driver-state contract for the Gianfar Ethernet driver. It describes register offsets and bit fields, descriptor formats, frame control blocks, RMON counters, queue/group/private structures, feature and errata flags, helper accessors, and prototypes shared between `gianfar.c` and `gianfar_ethtool.c`.

## Important APIs, types, and functions
Hardware-facing types include `struct gfar` for the memory-mapped register layout, `struct txbd8` and `struct rxbd8` for DMA descriptors, `struct txfcb` and `struct rxfcb` for transmit/receive frame control blocks, and `struct rmon_mib` plus `struct rmon_overflow` for hardware statistics. Driver state types include `struct gfar_private`, `struct gfar_priv_tx_q`, `struct gfar_priv_rx_q`, `struct gfar_rx_buff`, `struct gfar_priv_grp`, `struct gfar_irqinfo`, `struct gfar_extra_stats`, `struct ethtool_flow_spec_container`, `struct ethtool_rx_list`, `struct gfar_filer_entry`, and `struct filer_table`. Helper APIs include `gfar_has_errata()`, `gfar_read()`, `gfar_write()`, `gfar_write_filer()`, `gfar_read_filer()`, `gfar_write_isrg()`, `gfar_is_dma_stopped()`, `gfar_is_rx_dma_stopped()`, `gfar_wmb()`, `gfar_clear_txbd_status()`, `gfar_rxbd_unused()`, and `gfar_rxbd_dma_lastfree()`.

## Control flow
The header itself has no executable top-level flow, but its definitions drive the main driver flow. `struct gfar_private` anchors probe, open, data-path, ethtool, and PM code. Queue/group structures determine how `gfar_parse_group()` assigns queues to interrupt groups and how the NAPI pollers locate their TX/RX rings. Register constants are consumed by reset, MAC configuration, DMA start/stop, interrupt masking, checksum/VLAN/timestamp setup, filer programming, multicast hash programming, and WOL. The inline accessors provide the consistent big-endian MMIO and descriptor ordering used throughout the implementation.

## State and persistence behavior
The header defines volatile runtime state, not persistent storage. Persistent-within-lifetime fields include hardware capability flags, errata flags, current PHY link cache, pause settings, WOL settings, ring sizes, coalescing values, cached filer table entries, RX classification list entries, hash register mappings, queue stats, extra atomic stats, and RMON overflow counters. Descriptor rings and RX pages are allocated at device start and freed at stop. The `ftp_rqfpr` and `ftp_rqfcr` arrays are important in-memory persistence for restoring filer rules after WOL and for coordinating ethtool classifier updates.

## Dependencies and integration points
The header connects the driver to Linux netdevice, phylib, ethtool, workqueue, skb, spinlock, DMA, IRQ, and MMIO APIs. It assumes big-endian hardware register access through `ioread32be()` and `iowrite32be()`. It encodes the hardware ABI for eTSEC/TSEC register layout, queue control, interrupt bits, filer PIDs, RMON counters, TxBD/RxBD status bits, and FCB fields. It also publishes `startup_gfar()`, `stop_gfar()`, `gfar_mac_reset()`, `gfar_set_features()`, and `gfar_ethtool_ops` across the two C files.

## Risks and edge cases
Because this file defines hardware layouts and shared private structures, small changes have wide blast radius. `struct gfar` padding and offsets must remain aligned with hardware. Descriptor and FCB endianness must match DMA expectations. Ring sizes must stay powers of two because wrap masks use `size - 1`. `MAXGROUPS`, `MAX_TX_QS`, `MAX_RX_QS`, and default queue mapping constants constrain multi-queue behavior. `gfar_wmb()` intentionally uses weaker PowerPC ordering than `wmb()`, so replacing it can affect performance or correctness. The `struct gfar_extra_stats` size is used to derive exported stat counts, so changing member types or order affects ethtool output.

## Test signals
Any header change should trigger build coverage for PowerPC and non-PowerPC, PM and non-PM, netpoll and non-netpoll, single-queue and multi-queue configurations, and ethtool classifier support. Runtime signals include successful register dumps, correct ethtool statistics string counts, correct NAPI queue assignment, DMA halt detection, RX ring refill behavior, interrupt steering on multi-group devices, WOL filer restore, and stable TX/RX under checksum, VLAN, timestamp, and jumbo-frame workloads.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/freescale/gianfar_ethtool.c

## Purpose
`gianfar_ethtool.c` implements the Gianfar driver's ethtool interface. It exposes driver information, register dumps, coalescing, ring sizing, pause parameters, private/RMON statistics, message level, wake-on-LAN, RX classifier rules, RX hash-field programming, RX ring count, timestamping capabilities, and phylib link settings.

## Important APIs, types, and functions
The exported operation table is `gfar_ethtool_ops`. Stats support uses `stat_gstrings`, `gfar_gstrings()`, `gfar_fill_stats()`, and `gfar_sset_count()`. Register and driver identity support uses `gfar_gdrvinfo()`, `gfar_reglen()`, and `gfar_get_regs()`. Coalescing uses `gfar_gcoalesce()`, `gfar_scoalesce()`, `gfar_usecs2ticks()`, and `gfar_ticks2usecs()`. Ring and pause operations use `gfar_gringparam()`, `gfar_sringparam()`, `gfar_gpauseparam()`, and `gfar_spauseparam()`. Feature reconfiguration is exported as `gfar_set_features()`. WOL uses `gfar_get_wol()` and `gfar_set_wol()` when PM is enabled. RX flow classification and filer programming use `gfar_set_nfc()`, `gfar_get_nfc()`, `gfar_add_cls()`, `gfar_del_cls()`, `gfar_get_cls()`, `gfar_get_cls_all()`, `gfar_process_filer_changes()`, `gfar_convert_to_filer()`, `gfar_write_filer_table()`, and many field translation helpers. RX hash-field programming uses `gfar_set_rxfh_fields()`, `gfar_ethflow_to_filer_table()`, and `ethflow_to_filer_rules()`. Timestamp reporting uses `gfar_get_ts_info()`.

## Control flow
Read-only ethtool operations mostly copy current software or hardware state: stats combine atomic extra counters with optional RMON registers, register dumps iterate over `struct gfar`, coalescing reads queue interrupt-coalescing fields, ring parameters read queue sizes, pause reads stored pause flags, NFC queries walk the software classifier list, and timestamp info locates the QorIQ PTP device when available.

Mutating operations validate capabilities and inputs, serialize against resets or classifier mutations, update in-memory driver state, and then either reset/restart the hardware or rewrite the relevant registers. Coalescing validates max usecs and frames, updates all queue `rxic`/`txic` values, then stops/starts a running device or resets MAC config when down. Ring changes require power-of-two sizes, update all queue ring sizes, and rebuild rings if running. Feature changes for VLAN and RX checksum stop/start or reset to rebuild RX FCB expectations. Pause changes update phylib advertised pause and optionally write MACCFG1 immediately for forced pause.

RX classifier insertion copies the ethtool rule, inverts masks into the form expected by local conversion code, checks support, inserts the rule in location order, converts the full ordered list into a temporary filer table, and writes the hardware table. Deletion removes the list node and rewrites the table. RX hash-field changes find the parse-rule cluster for a flow class and splice hash rules into the cached hardware filer arrays.

## State and persistence behavior
Ettool state persists only while the driver instance exists. Coalescing values live in each queue. Ring sizes live in each queue and take effect on the next ring allocation. Pause and WOL settings live in `struct gfar_private`. RX classifier rules persist in `priv->rx_list` and are replayed into hardware whenever rules change. The active hardware filer image is cached in `priv->ftp_rqfpr` and `priv->ftp_rqfcr`; this cache is also used by PM WOL restore. Stats are split between atomic software counters and volatile hardware RMON counters. There is no on-disk persistence or firmware storage.

## Dependencies and integration points
This file integrates ethtool core, phylib link settings, PHY pause validation, netdev feature toggles, the main driver's stop/start/reset helpers, the Gianfar receive filer hardware, VLAN field definitions, OF platform lookup, and the `fsl,etsec-ptp` QorIQ PTP driver. It depends on `gianfar.h` for register bits, filer PIDs, queue structures, stats lengths, and private state. Its classifier support is tightly coupled to the default filer table initialized by `gfar_init_filer_table()` in the main driver.

## Risks and edge cases
The classifier path is the most complex and highest risk. It rewrites the entire hardware filer table from a software list, uses inverted ethtool masks, has limited hardware table capacity, and supports only selected flow types and fields. Unsupported masks are often warned rather than rejected, so user expectations can differ from hardware behavior. `gfar_ethflow_to_filer_table()` must find expected parse-rule clusters in the cached filer table; if default filer initialization changes, hash-field programming can fail. Coalescing conversions depend on current PHY speed, so reported usecs can shift with link speed. Ring changes and feature toggles stop/start live hardware and must not race with reset or classifier changes. WOL accepts magic packet preferentially over unicast filer WOL when both are requested.

## Test signals
Useful tests include `ethtool -S`, `-d`, `-c/-C`, `-g/-G`, `-a/-A`, `-s` through phylib link settings, `-k/-K` for VLAN and RX checksum toggles, `-sopass`-free WOL magic/unicast settings, `-n/-N` classifier insert/delete/list for TCP/UDP/SCTP/IP_USER/ETHER with VLAN extension, RX hash-field changes for supported IPv4/IPv6 TCP/UDP classes, and `ethtool -T` with and without the QorIQ PTP device. Negative tests should cover overlarge coalescing values, non-power-of-two ring sizes, invalid ring cookies, full filer tables, unsupported flow types, missing PHY, and concurrent reset-state rejection.
