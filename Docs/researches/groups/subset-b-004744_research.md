# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/debugfs_htt_stats.h

Purpose: Defines the debugfs-facing HTT extended statistics ABI for ath12k. It is a large schema header for target-to-host HTT stats confirmations, debugfs request bookkeeping, reset bitmaps, and the packed TLV payload structures used by the debugfs stats parser/formatter.

Important APIs and types: `ath12k_debugfs_htt_stats_register()` registers per-radio HTT stats controls, and `ath12k_debugfs_htt_ext_stats_handler()` is the T2H stats confirmation entry point when debugfs is enabled, with a no-op inline stub otherwise. `struct debug_htt_stats_req` tracks one debugfs stats request: completion, type, pdev, config words, optional peer address, output buffer length, and flexible text buffer. `struct ath12k_htt_extd_stats_msg` describes the HTT extended-stats confirmation framing with echoed cookie and stats length/done bits. The core enums are `ath12k_dbg_htt_ext_stats_type` for requested stats families and `ath12k_dbg_htt_tlv_tag` for returned TLV tags. The remaining packed structs model firmware counters for TX/RX pdev, HW queues, scheduler, TQM, DE classification, self-generated frames, SRNG, SFM, MU/OFDMA, CCA, sounding, latency profiles, UL trigger/MUMIMO, FSE, TXBF, DL pager, PHY counters/resets/TPC, AST, puncturing, scheduling algorithms, TDMA, MLO, RTT, RX firmware, channel-switch, and related areas.

Control flow: This header has no executable control flow, but it defines the wire contracts consumed by `debugfs_htt_stats.c` and reached from `dp_htt.c` on `HTT_T2H_MSG_TYPE_EXT_STATS_CONF`. A userspace debugfs read/write request selects an `ath12k_dbg_htt_ext_stats_type`, optional config parameters, and a cookie. Firmware returns one or more `ath12k_htt_extd_stats_msg` segments. The handler uses `ATH12K_HTT_T2H_EXT_STATS_INFO1_LENGTH` to bound the segment payload and `ATH12K_HTT_T2H_EXT_STATS_INFO1_DONE` to complete `debug_htt_stats_req.htt_stats_rcvd`.

State and persistence: The header defines transient request state and firmware counter snapshots. No state is persisted beyond debugfs request lifetime, but the statistics describe persistent target-side counters until firmware reset or an explicit `ATH12K_DBG_HTT_EXT_STATS_RESET` request. All TLV structs are `__packed` and mostly little-endian, so parser code must convert fields before presentation.

Dependencies and integration points: Includes `dp_htt.h` for HTT transport definitions and shares cookies/config structures with `ath12k_dp_tx_htt_h2t_ext_stats_req()`. It depends on kernel bitfield helpers, flexible arrays, sk_buff declarations through included driver headers, debugfs support, and the firmware HTT ABI. The reset bitmap helpers and default config constants line up with firmware reset/config parameter expectations.

Risks: This file is firmware-ABI dense: a wrong enum value, field size, endian conversion expectation, array bound, or `__packed` layout will corrupt parsing or display misleading diagnostics. Many structs contain flexible arrays where the caller must validate HTT length before indexing. Several counters have large dimensional arrays, so output formatting can overflow smaller buffers if it ignores `ATH12K_HTT_STATS_BUF_SIZE`. Naming typos such as `DGB`/`FLASG`-style symbols are part of the local ABI surface and should not be silently "fixed" unless every user is updated. Debugfs-only stubbing means callers must not assume stats handling exists in non-debugfs builds.

Test signals: Build with and without `CONFIG_ATH12K_DEBUGFS`; request representative stats families from debugfs, including pdev TX/RX, TX rate, RX rate/ext, SRNG, TQM, scheduler, PHY, AST, RTT, MLO, and reset; inject multi-segment responses and verify done/cookie matching; fuzz/truncate TLV lengths; validate endian-decoded counters against firmware logs; verify large outputs do not exceed the 512 KiB buffer; and confirm non-debugfs builds compile with the inline handler.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/debugfs_sta.c

Purpose: Adds per-link station debugfs files for ath12k extended RX peer statistics. It formats rate, packet, byte, preamble, TID, RU, duration, and L4 counters from `ath12k_rx_peer_stats`, and exposes a write-only reset control.

Important APIs and functions: `ath12k_debugfs_link_sta_op_add()` creates `rx_stats` and `reset_rx_stats` under a station link debugfs directory when extended RX stats are enabled. `ath12k_dbg_sta_dump_rx_stats()` is the read handler for `rx_stats`. `ath12k_dbg_sta_reset_rx_stats()` parses a boolean write and resets peer RX stats. `ath12k_dbg_sta_dump_rate_stats()` formats EHT/HE/VHT/HT/legacy MCS, NSS, GI, BW, and per-BW/GI/NSS/MCS rate matrix counters. `fops_rx_stats` and `fops_reset_rx_stats` wire these handlers into debugfs.

Control flow: The add path runs under the wiphy lock, resolves the `ath12k` radio for the vif/link, checks `ath12k_debugfs_is_extd_rx_stats_enabled()`, and creates the files. The read path guards the wiphy, validates that the link still belongs to the station, dereferences the link STA, allocates a 16 KiB buffer, gets the device DP object, locks `dp->dp_lock`, finds the DP link peer by address, and copies formatted counters into userspace with `simple_read_from_buffer()`. The reset path parses `true`/`false` from userspace, rejects false, locks the wiphy, validates link liveness, resolves the DP object, calls `ath12k_dp_link_peer_reset_rx_stats()`, and returns the written byte count.

State and persistence: Reads do not mutate counters. Reset clears per-peer RX statistics stored under the DP link peer. The debugfs file private data is `struct ieee80211_link_sta *`, so link teardown races are controlled through wiphy locking plus DP locking. The stats are runtime-only and disappear with peer removal, radio teardown, or driver reload.

Dependencies and integration points: Depends on mac80211 link station/vif structures, ath12k MLO link maps, `ath12k_sta_to_ahsta()`, `ath12k_get_ar_by_vif()`, DP peer lookup/reset helpers from `dp_cmn.h`, debugfs gating from `debugfs.h`, and RX stats structures populated by the RX data path. It integrates with mac80211 station debugfs callbacks via the exported `ath12k_debugfs_link_sta_op_add()`.

Risks: The `he_rates_avail` parameter is computed but not used by `ath12k_dbg_sta_dump_rate_stats()`, suggesting stale formatting logic. The fixed 16 KiB buffer may truncate if counter formatting grows, because `scnprintf()` prevents overflow but not loss of data. The code indexes `pream_cnt[6]` for 11BE while other preambles use lower indices, so it relies on HAL enum layout. Returning `-ENOENT` while holding scoped guards depends on cleanup attributes behaving as expected. Counter formatting under `dp_lock` can hold a spinlock while doing many `scnprintf()` calls, which is safe for memory but can increase softirq-off latency.

Test signals: Enable extended RX stats and verify per-link `rx_stats` appears only for live ath12k links; read while traffic exercises EHT/HE/VHT/HT/legacy rates, TIDs, RU allocation, and L4 counters; reset with `1` and verify counters clear; write `0` and malformed data and expect errors; remove a station/link while reading/resetting and expect `-ENOENT` without crashes; test MLO stations with multiple link IDs; and inspect output for truncation under maximum populated rate matrices.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/debugfs_sta.h

Purpose: Declares the station-link debugfs hook for ath12k and defines the buffer size used to format per-station RX stats.

Important APIs and definitions: `ATH12K_STA_RX_STATS_BUF_SIZE` is 16 KiB. Under `CONFIG_ATH12K_DEBUGFS`, `ath12k_debugfs_link_sta_op_add()` is declared for mac80211/debugfs integration. The header includes `net/mac80211.h` and `core.h` to expose `struct ieee80211_hw`, `struct ieee80211_vif`, `struct ieee80211_link_sta`, and ath12k core types.

Control flow: The header owns no runtime flow. Its compile-time `CONFIG_ATH12K_DEBUGFS` guard controls whether consumers can call the station debugfs add hook.

State and persistence: No state is stored in the header. The size macro bounds transient formatting buffers allocated by `debugfs_sta.c`.

Dependencies and integration points: Used by `debugfs_sta.c` and by ath12k mac80211/debugfs station setup code. It depends on debugfs-enabled builds providing the implementation; no fallback stub is declared here, so callers must be similarly guarded or only compiled when debugfs support is present.

Risks: Prototype visibility is conditional, which can cause build errors if a caller is not under the same config guard. The buffer-size macro is a silent contract with formatter complexity in `debugfs_sta.c`; increasing displayed stats may require increasing the size or moving to seq_file-style streaming.

Test signals: Build ath12k with `CONFIG_ATH12K_DEBUGFS=y` and disabled; verify station debugfs code only references the function in debugfs builds; and read maximum-populated RX stats to confirm 16 KiB remains sufficient.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp.c

Purpose: Implements common ath12k data-path device setup and teardown: peer default routing and TID setup, SRNG DMA allocation, MSI programming, TX bank profile management, WBM idle link descriptor provisioning, per-pdev RX/monitor allocation, vdev TX metadata attachment, cookie-converter setup, REO queue LUT setup, and DP hardware group assignment.

Important APIs and functions: Peer lifecycle uses `ath12k_dp_peer_setup()` and `ath12k_dp_peer_cleanup()`. SRNG management is through `ath12k_dp_srng_setup()` and `ath12k_dp_srng_cleanup()`, with `ath12k_dp_srng_msi_setup()` and `ath12k_dp_srng_calculate_msi_group()` mapping HAL rings to MSI groups. Link descriptor management is `ath12k_wbm_idle_ring_setup()`, `ath12k_dp_link_desc_setup()`, and `ath12k_dp_link_desc_cleanup()`. Per-radio state is allocated/freed by `ath12k_dp_pdev_alloc()`, `ath12k_dp_pdev_pre_alloc()`, and `ath12k_dp_pdev_free()`. TX vdev state is attached in `ath12k_dp_vdev_tx_attach()`. Cookie converter helpers include `ath12k_dp_cc_init()`, `ath12k_dp_cc_desc_init()`, `ath12k_dp_get_rx_desc()`, `ath12k_dp_get_tx_desc()`, and `ath12k_dp_partner_cc_init()`. Device-level entry points are `ath12k_dp_cmn_device_init()`, `ath12k_dp_cmn_device_deinit()`, `ath12k_dp_cmn_hw_group_assign()`, and `ath12k_dp_cmn_hw_group_unassign()`.

Control flow: Device init enters `ath12k_dp_setup()`: initialize locks/lists, create the link-peer rhashtable, set up the WBM idle ring, allocate/populate link descriptors, initialize the cookie converter, allocate TX bank profiles, create common TX/RX/REO SRNGs, optionally set up REO queue LUTs, allocate TX status arrays, program DSCP-TID maps, and allocate RX resources. Failures unwind through ordered labels. Peer setup first configures firmware default RX routing via WMI, then creates RX TID queues for all QoS TIDs plus legacy TID and sets up defrag; partial failure deletes TIDs already created under `dp_lock`. SRNG setup allocates aligned coherent DMA memory, programs HAL ring parameters and MSI data, assigns interrupt thresholds by ring type, and calls HAL setup. Link descriptor setup calculates descriptor banks and either uses scatter idle lists for large WBM idle memory or writes descriptors into the SRNG directly. Cleanup reverses peer tables, link descriptors, cookie converter, REO LUTs, bank profiles, SRNGs, REO command lists, TX status arrays, and RX allocations.

State and persistence: Mutates the central `struct ath12k_dp`: `ab`, `ag`, `device_id`, ring descriptors, bank profiles, peer lists/rhashtable, REO command lists, cookie-converter SPT pages, RX/TX descriptor pointer tables, free/used descriptor lists, REO LUT DMA memory, and device stats. Per-pdev state is published through RCU in `dp->dp_pdevs[]`. Hardware-visible state includes DMA ring memory, CMEM PPT entries, HAL SRNG registers, WBM idle link descriptors, REO routing hash map, DSCP-TID map, and optional REOQ LUT base registers. Runtime state is not durable across reset, but firmware/hardware rings must be explicitly torn down or reinitialized.

Dependencies and integration points: Depends on `core.h`, `dp_tx.h`, `hif.h`, `hal.h`, `peer.h`, `dp_cmn.h`, RX/TID helpers, WMI peer parameters, QMI CMEM device memory, hardware params/profile params, HAL ring and REO APIs, HTC/HTT setup indirectly, and mac80211 pdev/vdev objects. It provides common services for TX, RX, monitor, peer mapping, and MLO multi-device groups.

Risks: Error unwinds are complex; `ath12k_dp_srng_setup()` currently returns without freeing allocated DMA memory if `ath12k_hal_srng_setup()` fails, and `ath12k_dp_setup()` has a FIXME about TX status memory not being fully freed on allocation failure. Cookie bounds check uses `spt_idx > ATH12K_MAX_SPT_ENTRIES`, which permits `spt_idx == ATH12K_MAX_SPT_ENTRIES` even though valid indexes are 0..511. Any mismatch in `rx_ppt_base`, device ID, or partner CMEM initialization can make hardware cookies resolve to the wrong descriptor. Link descriptor scatter setup is sensitive to bank sizes, alignment, and off-by-one handling of scatter buffers. TX bank profiles have TODOs around IDR/error handling and rely on balanced put calls. RCU publication of `dp_pdevs[]` requires readers to hold RCU and teardown to wait for grace periods.

Test signals: Probe/reset/remove with allocation-failure injection at every DP setup stage; run traffic through all TX rings and REO destination rings; validate MSI group assignment against ring masks; test peer setup cleanup when individual TID/frag setup fails; verify cookie-to-descriptor lookup for first/last RX and TX descriptors and invalid cookies; exercise multi-device MLO partner CMEM init; enable/disable monitor mode and RX resources; run KASAN/KMSAN/dma-debug for ring and descriptor memory leaks; and check REOQ LUT programming on devices with and without support.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp.h

Purpose: Defines the common ath12k data-path object model, ring sizing, cookie-converter layout, monitor state, descriptor metadata, per-pdev data-path state, architecture operation callbacks, device statistics, inline dispatch wrappers, and exported DP setup APIs.

Important APIs and types: Core structs include `dp_srng`, `dp_tx_ring`, `dp_rxdma_ring`, `dp_rxdma_mon_ring`, `dp_link_desc_bank`, `ath12k_mon_data`, `ath12k_pdev_dp`, `ath12k_rx_desc_info`, `ath12k_tx_desc_info`, `ath12k_spt_info`, `ath12k_reo_q_addr_lut`, `ath12k_dp_arch_ops`, `ath12k_device_dp_stats`, and `ath12k_dp`. Important macros define ring sizes, RX/TX buffer sizes, WBM link descriptor cookies, RXDMA buffer cookies, TX descriptor ID bitfields, PPT/SPT cookie-converter geometry, REOQ LUT size, and bank/profile constants. Inline wrappers dispatch through `dp->ops` for service SRNG, TX bank config, REO commands, PN check setup, RX TID deletion, cache flush, link descriptor return, fragment cleanup, TID REO update, REO queue assignment, qref setup/reset, and TID delete handling. Public prototypes expose vdev TX attach, pdev alloc/free, peer setup/cleanup, SRNG/link-descriptor setup/cleanup, and RX/TX cookie lookup.

Control flow: The header's executable content is inline dispatch and pointer conversion. Most DP control flow is implemented by `dp.c` and architecture-specific RX/TX files through `ath12k_dp_arch_ops`. `ath12k_dp_to_pdev_dp()` requires an RCU read-side critical section and dereferences `dp->dp_pdevs[pdev_idx]`. `ath12k_dp_get_mac_addr()` reconstructs a MAC address from HTT low/high words.

State and persistence: `struct ath12k_dp` is the long-lived per-device DP root containing DMA rings, descriptor memory references, peer table/list state, REO command queues, TX bank profiles, RX/TX descriptor lists, monitor rings, optional REOQ LUTs, hardware params, device pointers, MLO group pointers, and aggregate device stats. `ath12k_pdev_dp` stores per-radio queue counters, ppdu stats state, monitor data, rx status, and RCU-published backpointers. None is durable across driver teardown, but most fields mirror hardware-visible DMA state and must remain coherent while firmware owns descriptors.

Dependencies and integration points: Includes `hw.h`, `dp_htt.h`, `dp_cmn.h`, and `linux/rhashtable.h`. It is a high-fanout header used by DP TX/RX, HTT, monitor, peer, debugfs, and mac80211 integration code. Its op table is the boundary between common DP code and hardware-generation-specific behavior.

Risks: Ring-size and descriptor-count macros pull from runtime profile params, so invalid profile values can under-size rings or descriptor tables. Cookie-converter constants define a hardware ABI; changing page counts, offsets, or masks can break TX/RX completion lookup. The comment says SPT pages are divided RX first and TX remaining, while macros place TX at offset 0 and RX after TX; readers must follow the macros, not the stale comment. Inline op wrappers do not guard `dp->ops` or individual function pointers. `ath12k_dp_to_pdev_dp()` warns without RCU and can return NULL during teardown. Packed/bitfield stats and counters need care on endian and atomicity.

Test signals: Compile all files that include this high-fanout header; boot/probe with different `profile_param->dp_params`; validate RX/TX descriptor counts are multiples of `ATH12K_MAX_SPT_ENTRIES`; exercise all architecture op wrappers; run RCU lockdep for `ath12k_dp_to_pdev_dp()`; check ring occupancy and low-threshold interrupts with configured sizes; and inspect debugfs/device stats for expected increment paths under traffic and error injection.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp_cmn.h

Purpose: Provides common DP definitions shared across ath12k devices and links, especially MLO-aware DP hardware grouping, vif/link-vif TX metadata, per-peer TX stats, peer creation parameters, rate-info export, and common peer/device lifecycle prototypes.

Important APIs and types: `MAX_DP_PEER_LIST_SIZE` sizes DP peer arrays to 16,384 to cover regular and MLO peer IDs. `struct ath12k_dp_hw` stores RCU peer pointers, a peer lock, and peer list. `struct ath12k_dp_hw_group` maps device IDs to DP roots. `struct ath12k_dp_link_vif` stores vdev ID, HAL address search flags, pdev/lmac IDs, AST info, TCL metadata, vdev-ID check state, and bank ID. `struct ath12k_dp_vif` stores TX encapsulation, key cipher, multicast/broadcast global sequence number, and per-link DP vif state. `struct ath12k_per_peer_tx_stats`, `ath12k_dp_peer_create_params`, and `ath12k_dp_link_peer_rate_info` carry peer stats and setup/rate data. Prototypes cover common DP device init/deinit, hardware-group assign/unassign, link-peer assign/unassign, rate-info fetch, and RX-stats reset. `ath12k_dp_vif_to_dp_link_vif()` maps a shared vif DP object plus link ID to link-specific state.

Control flow: No complex flow lives here; it defines storage and function contracts. Callers allocate/init common DP through `ath12k_dp_cmn_device_init()`, attach DP objects to an `ath12k_hw_group`, assign/unassign link peers as firmware peer map/unmap and mac80211 station events occur, and query/reset per-peer stats from debugfs/mac80211 paths.

State and persistence: Defines runtime state for DP peer tables, MLO hardware groups, link-vif TX configuration, multicast global sequence numbers, and per-peer rate/stat summaries. These are reconstructed on device/peer/vif setup and are not durable, but peer IDs and MLO group mappings must stay consistent with firmware while peers exist.

Dependencies and integration points: Includes `cmn_defs.h` and uses `ATH12K_MAX_DEVICES`, `ATH12K_NUM_MAX_LINKS`, mac80211 station/rate types, and ath12k DP peer structures declared elsewhere. It is included by `dp.h`, `dp.c`, `debugfs_sta.c`, and peer/RX/TX code that needs common MLO-aware DP state.

Risks: `MAX_DP_PEER_LIST_SIZE` is a memory and bounds contract; firmware peer IDs beyond it or incorrect MLO assumptions would cause lookup failures. `ath12k_dp_vif_to_dp_link_vif()` does no link ID bounds checking. Peer table updates require the documented locks/RCU discipline in implementation files. The per-peer TX stats TODO notes that stats placement may be temporary, increasing coupling.

Test signals: Assign/unassign single-link and MLO peers; validate peer IDs near regular and ML ranges; exercise per-link vif metadata for STA/AP/IBSS modes; read link peer rate info under traffic; reset RX stats through debugfs; and run lockdep/KCSAN around peer table updates and RCU readers.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp_htt.c

Purpose: Implements ath12k HTT control transport over HTC for data-path setup, firmware version negotiation, SRNG and monitor filter configuration, PPDU stats parsing, per-peer TX rate/stat updates, extended debug stats requests, peer map/unmap event dispatch, and MLO timestamp offset handling.

Important APIs and functions: `ath12k_dp_htt_connect()` connects the HTT data service and registers TX/RX HTC callbacks. `ath12k_dp_htt_htc_t2h_msg_handler()` dispatches all target-to-host HTT messages. `ath12k_dp_htt_tlv_iter()` is the generic TLV walker. H2T setup calls include `ath12k_dp_tx_htt_h2t_ver_req_msg()`, `ath12k_dp_tx_htt_srng_setup()`, `ath12k_dp_tx_htt_h2t_ppdu_stats_req()`, `ath12k_dp_tx_htt_h2t_ext_stats_req()`, `ath12k_dp_tx_htt_rx_filter_setup()`, `ath12k_dp_tx_htt_rx_monitor_mode_ring_config()`, `ath12k_dp_tx_htt_monitor_mode_ring_config()`, and `ath12k_dp_tx_htt_tx_filter_setup()`. PPDU stats helpers include `ath12k_htt_tlv_ppdu_stats_parse()`, `ath12k_htt_pull_ppdu_stats()`, `ath12k_update_per_peer_tx_stats()`, `ath12k_htt_update_ppdu_stats()`, and delay-BA copy/restore helpers.

Control flow: HTT connect binds the service and stores the endpoint ID in `dp->eid`. Version request sends `HTT_H2T_MSG_TYPE_VERSION_REQ`, waits up to three seconds for `VERSION_CONF`, and rejects unsupported major versions. SRNG setup reads HAL ring params and remote head/tail pointer addresses, maps HAL ring type/id to HTT ring type/id, packs base DMA/MSI/threshold fields, and sends the command over HTC. T2H dispatch decodes the message type from the first dword: version confirms complete a wait; peer map variants extract vdev, peer ID, MAC, AST hash, and HW peer ID and call peer map handlers; peer unmap calls unmap; PPDU stats are parsed and accumulated; ext stats are delegated to debugfs; MLO timestamp offsets update pdev timestamp fields under `ar->data_lock`; unknown messages are debug logged. PPDU stats parsing stores TLVs by peer ID, caps list depth, validates payload sizes and num_users, handles delayed BA/BAR rate TLV restoration, and updates mac80211 `rate_info` plus retry/duration counters under DP locking. Monitor RX filter config builds `htt_rx_ring_tlv_filter` values differently for monitor enable vs reset/default debugfs stats, then programs destination/status/refill rings based on hardware RXDMA layout.

State and persistence: Mutates HTT endpoint ID, target version fields, completion state, per-pdev PPDU stats lists and depth, per-peer TX rate/retry/duration/delay-BA fields, pdev timestamp offset data, and debugfs-request responses indirectly. H2T commands program firmware-visible ring, filter, PPDU stats, ext stats, and monitor configuration; this state persists in target firmware until reset or reconfiguration.

Dependencies and integration points: Depends on HTC service connection/send, HAL SRNG params, DP rings, peer map/unmap helpers, mac80211 rate conversion helpers, debugfs HTT stats, debugfs RX filter state, monitor status defaults, WMI preamble/rate constants, RCU-protected pdev/peer lookups, and firmware HTT ABI definitions in `dp_htt.h` and `debugfs_htt_stats.h`. It bridges DP ring setup in `dp.c` and RX/monitor setup code to target firmware.

Risks: TLV parsing and PPDU payload lengths are firmware-controlled; all new tags must validate length before copying. `ath12k_get_ppdu_user_index()` only scans `HTT_PPDU_STATS_MAX_USERS - 1`, leaving the last slot unused. `ath12k_dp_htt_tlv_iter()` ignores non-ENOMEM iterator errors and continues, which may mask parse failures. PPDU list pruning updates stats only when depth exceeds the max, so stale entries can remain until enough new PPDUs arrive. Ring ID/type mapping has hardware-specific branches and pdev ID conversion rules; wrong mapping breaks firmware ring ownership. Monitor filter setup changes behavior when extended RX stats are enabled and must be reset accurately. Version negotiation frees the skb only on send failure; normal ownership is handed to HTC.

Test signals: Connect HTT service and verify endpoint callbacks; version request success, timeout, and wrong-major handling; SRNG setup for RXDMA, monitor, and destination rings with expected pdev/ring IDs; PPDU stats TLVs for common/rate/completion/ack-BA including invalid lengths, too many users, delayed BA and BAR flows; peer map/unmap variants 1/2/3; ext stats request/confirmation through debugfs; monitor mode enable/reset on RXDMA1 and non-RXDMA1 hardware; MLO timestamp offset updates; and fault injection for HTC allocation/send failures.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp_htt.h

Purpose: Defines the ath12k HTT host-target protocol constants, bitfields, command/event structs, PPDU stats TLVs, RX/TX monitor filter formats, peer map/unmap messages, MLO timestamp offset message, extended stats request format, and function prototypes implemented by `dp_htt.c`.

Important APIs and types: H2T definitions include TCL metadata fields, `htt_h2t_msg_type`, version request options, `htt_srng_ring_type`, `htt_srng_ring_id`, `htt_srng_setup_cmd`, `htt_ppdu_stats_cfg_cmd`, `htt_rx_ring_selection_cfg_cmd`, `htt_rx_ring_tlv_filter`, `htt_tx_ring_selection_cfg_cmd`, `htt_tx_ring_tlv_filter`, and `htt_ext_stats_cfg_cmd`. T2H definitions include `htt_t2h_msg_type`, version/peer map/unmap messages, `htt_resp_msg`, vdev periodic stats structs, `ath12k_htt_ppdu_stats_msg`, generic `htt_tlv`, PPDU common/user/rate/completion/ack-BA structs, `htt_ppdu_stats_info`, and `ath12k_htt_mlo_offset_msg`. Public prototypes expose HTT connect, SRNG setup, T2H handler, TLV iterator, version/PPDU/ext stats requests, RX/TX filter setup, and monitor ring config.

Control flow: The header itself is declarative. It provides the binary layouts that `dp_htt.c` packs before `ath12k_htc_send()` and unpacks after HTC RX. Message IDs drive dispatch: H2T setup/config messages go host-to-firmware, while T2H version, peer map/unmap, PPDU stats, ext stats, and MLO offset messages return to host handlers. Bitfield macros are used to encode/decode little-endian dwords without ad hoc shifts.

State and persistence: No direct runtime state is owned here. The structures model firmware-visible persistent configuration for rings and filters, transient HTT request/response packets, and PPDU/vdev stats snapshots. TCL metadata constants influence every transmitted frame's metadata and therefore must remain stable with firmware expectations.

Dependencies and integration points: Used by `dp.h`, `dp.c`, `dp_htt.c`, TX/RX datapath code, debugfs stats, monitor setup, peer mapping, and mac80211 rate reporting. It depends on kernel bitfield helpers, endian types, sk_buff/base type declarations from including files, and the Qualcomm firmware HTT ABI.

Risks: This is another firmware ABI header; bit positions, enum values, struct packing, and endian annotations are critical. Several filter macro names contain legacy misspellings (`FLASG`) that are referenced by code. Ring size in `htt_srng_setup_cmd` is encoded in 4-byte words and loop-count disabling differs for SW-to-HW rings; confusing bytes versus words breaks target setup. `HTT_PPDU_STATS_MAX_USERS` and PPDU tag bitmasks must match firmware or parser list indexing fails. Duplicate macro definitions for TX ring info0 fields increase maintenance risk. The HTT target major version is pinned to 3.

Test signals: Compile all HTT users; static assert or runtime validate struct sizes against firmware interface docs where possible; run SRNG setup and RX/TX filter setup on supported chips; verify TCL metadata version negotiation for normal and FTM modes; parse PPDU stats with all supported tag combinations; confirm peer map v1/v2/v3 decode; exercise MLO offset events; and compare HTT command dumps against firmware traces.
