# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/file_ops.c

Purpose: implements the user-space character device for HFI1 PSM contexts. It provides `/dev/hfi1_<unit>` file operations for context assignment, SDMA request submission, mmap token generation/validation, receive polling, expected receive TID ioctls, PKEY selection, context reset, and device node creation/removal.

Important APIs and functions: `hfi1_file_ops` wires `.open`, `.release`, `.write_iter`, `.unlocked_ioctl`, `.poll`, and `.mmap`. `hfi1_file_open()` allocates `struct hfi1_filedata`, initializes SRCU and locks, and takes `dd->user_refcount`. `hfi1_file_ioctl()` dispatches `HFI1_IOCTL_ASSIGN_CTXT`, context/base info, SDMA credit update, expected receive setup/free/invalidate, receive control, poll type, event ack, PKEY set, context reset, and user ABI version. `hfi1_write_iter()` submits user SDMA requests through `hfi1_user_sdma_process_request()`. `hfi1_file_mmap()` maps PIO buffers, PIO credit pages, receive header/eager buffers, user registers, event/status pages, receive tail, subcontext shared memory, and SDMA completion queues. `assign_ctxt()`, `allocate_ctxt()`, `find_sub_ctxt()`, `setup_base_ctxt()`, and `complete_subctxt()` implement user context allocation and sharing. `hfi1_set_uevent_bits()` broadcasts user event bits to active contexts. `hfi1_device_create()` and `hfi1_device_remove()` expose/remove the unit character device.

Control flow: open only validates device presence and prepares per-file state; the real hardware allocation is deferred until `HFI1_IOCTL_ASSIGN_CTXT`. Assignment validates the user ABI major version and subcontext count, serializes under `hfi1_mutex`, either attaches to a matching base context by UUID/J_KEY/subcontext metadata or allocates a new receive context, send context, CPU affinity, and shared-subcontext metadata. Base context setup initializes PIO, receive header queue, eager buffers, optional subcontext vmalloc areas, receive groups, user SDMA queues, expected receive state, and receive control bits. Subcontexts wait for `HFI1_CTXT_BASE_UNINIT` to clear, then allocate their per-file queues and expected receive state. Runtime operations then use ioctl, write, poll, and mmap against `fd->uctxt`; close drains SDMA, releases CPU affinity and expected receive state, clears event bits and subcontext membership, disables receive/send context state when the last subcontext exits, clears J_KEY/PKEY state, frees receive groups, and drops the context kref.

State and persistence: persistent per-open state is `struct hfi1_filedata`, including SRCU-protected SDMA packet queue, completion queue, context pointer, subcontext id, CPU affinity, expected receive pinning/accounting, and invalid TID array. Shared hardware/software state lives in `struct hfi1_ctxtdata`: receive header queue, eager buffers, send context, flags, J_KEY, UUID, subcontext bitmaps, event flags, and waitqueue. User-visible mmap cookies encode magic/type/context/subcontext/offset; mapped pages remain valid while the context exists. Device state affected here includes `dd->freectxts`, ASPM enable state, `hfi1_stats.sps_ctxts`, receive control CSR bits, context PKEY/J_KEY tables, and `dd->events` bitmaps.

Dependencies and integration points: depends on `hfi.h`, PIO/send-context helpers, receive context allocation from `init.c`, user SDMA (`user_sdma.h`), expected receive/TID logic (`user_exp_rcv.h`), MMU notifier/RB support, ASPM controls, RDMA user ABI structs, Linux `mmap`, `poll`, `iov_iter`, DMA coherent mapping, vmalloc fault handling, and cdev registration in `device.h`. It integrates with interrupt handling through `event_flags` and `handle_user_interrupt()`, with link events through `hfi1_set_uevent_bits()`, and with PCI removal through `dd->user_refcount`/`user_comp`.

Risks: ioctl size and ABI-version checks must stay exact or user libraries can corrupt kernel interpretation. mmap token validation prevents mapping another context's resources; any token or size mistake can expose device memory. Context sharing relies on serialized assignment plus bitmap updates under `uctxt_lock`; errors must clear bits and drop krefs. `ctxt_reset()` explicitly trusts user space to quiesce writers, so misuse can damage that context. Close ordering is critical because cleanup helpers use `fdata->uctxt` before it is nulled. Expected receive invalidation has multiple copy-to-user rollback paths that must not leak pinned pages or stale TIDs.

Test signals: open/close under concurrent users, assignment failures for bad ABI and exhausted contexts, shared subcontext attach/detach, mmap size/protection checks for every token type, SDMA write request queue saturation, poll wakeups for urgent and receive-available interrupts, link-down event bit delivery and ack, PKEY rejection/acceptance, context reset after halted/frozen send contexts, and remove waiting for `user_refcount` to drain.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/firmware.c

Purpose: manages HFI1 firmware acquisition, authentication, download, SBus/SerDes programming, 8051 access, platform configuration parsing, GUID reads, and shared ASIC resource locking. It is the low-level bridge between Linux firmware blobs, on-chip security/RSA hardware, 8051 firmware, SBus microcode, PCIe/fabric SerDes firmware, and platform tuning tables.

Important APIs and functions: public entry points include `hfi1_firmware_init()`, `load_firmware()`, `dispose_firmware()`, `read_8051_data()`, `wait_fm_ready()`, `sbus_request()`, `sbus_request_slow()`, `fabric_serdes_reset()`, `load_pcie_firmware()`, `acquire_hw_mutex()`, `release_hw_mutex()`, `acquire_chip_resource()`, `release_chip_resource()`, `check_chip_resource()`, `init_chip_resources()`, `finish_chip_resources()`, `set_sbus_fast_mode()`, `clear_sbus_fast_mode()`, `parse_platform_config()`, `get_platform_config_field()`, and `read_guid()`. Important internal helpers are `obtain_one_firmware()`, `__obtain_firmware()`, `retry_firmware()`, `verify_css_header()`, `load_security_variables()`, `run_rsa()`, `load_8051_firmware()`, `load_fabric_serdes_firmware()`, `load_sbus_firmware()`, and `load_pcie_serdes_firmware()`.

Control flow: `hfi1_firmware_init()` selects which firmware classes apply to ASIC, FPGA, RTL, or simulator devices, assigns default names, and calls `obtain_firmware()`. Firmware acquisition is module-global and protected by `fw_mutex`; the first device requests all enabled blobs, validates CSS headers and augmented RSA material, and leaves state in `FW_TRY`, `FW_FINAL`, or `FW_ERR`. `load_firmware()` downloads fabric SerDes firmware under the SBus chip resource, then downloads and starts 8051 firmware, retrying with alternate debug names when `retry_firmware()` decides the previous authorization/load failed. Firmware download loads RSA security variables, streams firmware into 8051 RAM or SBus receiver registers, runs the RSA engine, releases resets, and waits for firmware readiness. PCIe firmware loading similarly sequences SBus master firmware before PCIe SerDes firmware. Platform config parsing validates magic, size, per-table inverted headers, table type, CRC, metadata version, and then caches table and metadata pointers for later field extraction.

State and persistence: module-level state includes `fw_state`, `fw_err`, firmware names, load-enable flags, and four `struct firmware_details` objects; these persist across devices until module unload or error. Hardware state persists in CSRs: 8051 RAM/reset state, RSA modulus/r2/mu/header/signature registers, SBus fast mode, SerDes broadcast groups, ASIC scratch resource bits, firmware version/status registers, and local GUID register contents. `dd->pcfg_cache` persists parsed platform config pointers for the device. `dd->dc8051_ver` and `dd->base_guid` cache firmware version and GUID. Resource ownership is recorded in ASIC scratch bits and serialized with both `dd->asic_data->asic_resource_mutex` and the hardware mutex CSR.

Dependencies and integration points: uses the Linux firmware loader, mutexes, delays, CRC32, PCI device parent for firmware requests, CSR accessors from chip/common code, platform config definitions, QSFP/SerDes constants, and HFI1 logging/trace helpers. It is called from PCI probe/chip init and by link-management paths that need fabric SerDes reset, platform tuning, I2C/QSFP resource ownership, or PCIe firmware transition.

Risks: firmware authentication is strict: non-augmented firmware is rejected because the driver cannot generate `r2`/`mu`; bad CSS sizes or CRCs abort loading. `fw_state == FW_TRY` means one device may be deciding between normal and alternate blobs while others wait up to 40 seconds. SBus operations require correct fast-mode and chip-resource pairing; missing `release_chip_resource()` can block the other HFI or OS. `acquire_hw_mutex()` forcibly clears a stuck mutex on first timeout, which is pragmatic but risky if another agent is genuinely active. Platform config parsing stores pointers into `dd->platform_config.data`, so that backing memory must outlive cache use. Field extraction assumes metadata alignment/length conventions and can truncate if table metadata changes.

Test signals: successful firmware request and CSS validation logs, RSA success/failure bits, 8051 ready state and host interface version write, SBus/fabric/PCIe firmware version dumps, SerDes reset during link transitions, chip resource acquire/release under dual-HFI stress, platform config CRC/magic/version rejection tests, integrated scratch-config field reads, GUID read, and probe behavior on simulator/FPGA/ASIC variants with missing firmware.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/hfi.h

Purpose: central HFI1 kernel header defining the driver's core data model, constants, inline helpers, and cross-file prototypes. It describes receive contexts, packets, physical port state, shared ASIC state, per-device state, user file private data, link/receive-control flags, packet header helpers, partition checks, MTU helpers, device flags, and PCI/module integration points.

Important APIs and types: key types are `struct hfi1_ib_stats`, `struct ctxt_eager_bufs`, `struct exp_tid_set`, `struct tid_queue`, `struct hfi1_ctxtdata`, `struct hfi1_packet`, `struct hfi1_pportdata`, `struct hfi1_asic_data`, `struct hfi1_devdata`, and `struct hfi1_filedata`. Important helpers include `rcvhdrq_size()`, 16B header accessors/builders, `hfi1_get_rc_ohdr()`, `incr_cntr64()`, context accessors and sequence helpers, `generate_jkey()`, `active_egress_rate()`, `egress_cycles()`, `sc_to_vlt()`, ingress/receive PKEY checks, `dd_from_*()`/`ppd_from_*()` conversions, ECN detection, GUID/PKEY accessors, receive-tail helpers, send/SDMA integrity-mask builders, multicast/LID conversion helpers, GRH construction, and `flush_wc()`. It also declares exported driver functions such as `hfi1_init()`, context allocation/free, interrupt handlers, device create/remove, PCIe helpers, platform config helpers, user page pinning, and link/port operations.

Control flow role: this header is not a runtime flow by itself; it is the contract that lets `init.c`, `file_ops.c`, `firmware.c`, interrupt handling, verbs, SDMA, PIO, MAD, netdev, and platform code share state safely. Receive packet paths use `struct hfi1_packet` and inline header/PKEY/ECN helpers. User paths use `struct hfi1_filedata`, `uctxt_offset()`, receive-tail helpers, context flags, and mmap-visible event/status state. Probe/teardown paths allocate and initialize `struct hfi1_devdata`, `struct hfi1_pportdata`, and `struct hfi1_ctxtdata` according to the layouts defined here.

State and persistence: `struct hfi1_devdata` is the lifetime owner for PCI mappings, cdevs, send/receive contexts, SDMA engines, workqueues, locks, firmware/platform state, counters, IRQ state, status/event pages, user refcount, ASPM state, RSM/IPoIB state, and physical ports. `struct hfi1_pportdata` owns per-port link state, GUIDs, PKEYs, QSFP data, work items, congestion control state, VL arbitration, counters, link-down reasons, and status pointer. `struct hfi1_ctxtdata` owns per-receive-context DMA queues, eager buffers, send context, interrupt handlers, TID queues, wait/event flags, subcontext shared memory, J_KEY, and packet sequencing. Most state is volatile kernel/hardware state, but some mappings are shared read-only or event-bit pages to user processes until device removal.

Dependencies and integration points: includes Linux PCI/DMA/cdev/interrupt/mutex/kref/I2C/xarray/rhashtable facilities, RDMA core and `rdma_vt`, HFI1 chip/register/common/verbs/PIO/MAD/QSFP/platform/affinity/MSI-X headers. It is included by most HFI1 source files and forms the compile-time integration layer with the RDMA core, PCI driver, sysfs/debugfs, cdev user ABI, and hardware register helpers.

Risks: because this file defines shared layout and inline policy, small changes have wide blast radius. `struct hfi1_devdata` begins with `struct hfi1_ibdev` and `struct hfi1_ipoib_rdma_netdev` similarly relies on first-member layout elsewhere; reordering can break container conversions. Bit masks for capabilities, receive control, link states, PKEY membership, and packet headers must match hardware and ABI. Inline PKEY/ECN/LID helpers run in hot paths and must stay cheap and correct. `hfi1_packet_present()` differs by DMA tail mode, so receive-tail memory ordering and volatile access matter. User-visible structures and event/status pages depend on stable semantics.

Test signals: full HFI1 build coverage after any structure/prototype change, sparse/lockdep for RCU and seqlock helpers, receive packet tests covering 9B/16B header parsing and PKEY checks, user ABI mmap/status/event tests, link state and MTU tests, send/SDMA integrity programming on A0 vs non-A0 hardware, and probe/remove tests that exercise allocation/free of every major state object.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/init.c

Purpose: owns HFI1 module initialization, PCI probe/remove/shutdown, device allocation/free, port initialization, receive context allocation, kernel context setup, workqueue creation, chip initialization/reinitialization, orderly shutdown, and receive buffer allocation. It is the lifecycle spine that turns a PCI function into a registered RDMA/HFI1 device with kernel/user receive contexts and device nodes.

Important APIs and functions: module parameters define user context count, kernel receive queues, receive array split, eager buffer size, receive header count, header entry size, and user credit threshold. Public functions include `hfi1_create_kctxts()`, `hfi1_create_ctxtdata()`, `hfi1_free_ctxt()`, `set_link_ipg()`, `hfi1_init_pportdata()`, `hfi1_init()`, `hfi1_lookup()`, `hfi1_free_ctxtdata()`, `hfi1_free_devdata()`, `hfi1_disable_after_error()`, `hfi1_create_rcvhdrq()`, and `hfi1_setup_eagerbufs()`. PCI/module functions include `hfi1_mod_init()`, `hfi1_mod_cleanup()`, `init_one()`, `remove_one()`, and `shutdown_one()`. Internal helpers manage context krefs, RCD array allocation, reset initialization, chip enablement, workqueues, timers, shutdown, ASIC-data release, and post-init cleanup.

Control flow: module init validates global parameters, initializes common device infrastructure, OPFN/debug support, and registers the PCI driver. Probe locks capabilities, validates PCI IDs and module parameters, allocates `hfi1_devdata` through `rvt_alloc_device()`, initializes PCI/chip-specific state, creates per-port workqueues, runs `hfi1_init()`, registers the IB device, creates debugfs and `/dev` nodes, and starts SDMA. `hfi1_init()` sets send handlers and A0 drop behavior, clears linkup state, performs reset/load-time setup, allocates kernel receive header/eager buffers and expected receive state, allocates user event/status pages, initializes MTU/status, enables kernel receive contexts and PIO, enables interrupts, initializes QSFP interrupts, and starts SerDes. Remove tears down in reverse: debugfs, cdev, wait for users, IB unregister, netdev RX free, hardware shutdown, workqueue/timer cleanup, postinit cleanup, and devdata free.

State and persistence: `hfi1_dev_table` xarray maps unit numbers to `hfi1_devdata`. `hfi1_devdata` persists for the PCI device lifetime and owns locks, counters, per-cpu counters, receive contexts, send contexts, SDMA state, status/event pages, and shared ASIC data. Receive contexts are kref-counted; `dd->rcd[]` is protected by `uctxt_lock` and entries are nulled in `hfi1_rcd_free()`. `hfi1_create_ctxtdata()` computes receive array bases, eager/expected TID counts, header queue geometry, NUMA placement, and kernel-context opcode stats. `hfi1_setup_eagerbufs()` allocates coherent eager buffers, may repartition to smaller TID sizes on allocation failure, programs RcvArray TIDs, and records thresholds/base/counts. Shutdown clears initialized flags/status bits, masks interrupts, flushes send contexts, disables receive/PIO, quiets SerDes, flushes workqueues, and exits SDMA without freeing all structures until cleanup.

Dependencies and integration points: depends on PCI, netdevice, vmalloc, xarray, module/param APIs, hrtimers, NUMA, RDMA VT allocation/registration, HFI1 device/common/chip/PIO/SDMA/MAD/debugfs/verbs/ASPM/affinity/expected-receive/netdev helpers. It integrates firmware/chip init through `hfi1_init_dd()`, PCIe helpers, MSI-X cleanup, IB registration, `/dev` creation in `file_ops.c`, user refcount waiting, and work items used by link/freeze/QSFP handlers.

Risks: probe has many staged resources; unwind ordering must match initialization or leave cdevs, IB devices, workqueues, IRQs, DMA buffers, or xarray entries live. `hfi1_init()` allocates user event/status pages even on some error paths to support diagnostics, so cleanup must handle partially initialized devices. Receive context krefs and `dd->rcd[]` updates must be correct under concurrent interrupts/user close. Eager buffer allocation dynamically halves/repartitions buffers; off-by-one or group-size mistakes corrupt TID programming. Shutdown uses hardware delays and flushes to let sends drain; insufficient ordering can race DMA/interrupt handlers. Module parameter validation protects hardware limits and interrupt mitigation from invalid combinations.

Test signals: module load/unload, PCI probe/remove/shutdown, failed-probe injection at each stage, reset/reinit, kernel context receive setup, user context allocation via `file_ops.c`, SDMA start/exit, cdev creation/removal, IB registration/unregistration, xarray lookup, workqueue flush/destroy, eager buffer allocation under memory pressure, context kref leak checks, and status/event page visibility to diagnostics after partial init failures.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/intr.c

Purpose: handles non-hardirq completion work for link-up/link-down transitions and user receive/urgent interrupts. It updates port neighbor/management state, signals RDMA core port events, and wakes user processes waiting in `poll()`.

Important APIs and functions: `handle_linkup_change()` is called outside interrupt context to finish physical link up/down changes. `handle_user_interrupt()` handles receive-available or urgent interrupts for user contexts. Internal helpers `set_mgmt_allowed()`, `add_full_mgmt_pkey()`, and `signal_ib_event()` read neighbor firmware state, install the full management PKEY when allowed, and dispatch `ib_event` notifications if the IB device is registered.

Control flow: on link-up, quick-linkup/simulator paths synthesize verify-cap setup, the driver reads neighbor GUID/type/port/security CSRs, waits `LINK_UP_DELAY`, reads `MgmtAllowed` from 8051 config for switch neighbors or allows HFI neighbors, optionally installs `FULL_MGMT_P_KEY`, marks `ppd->linkup`, clears offline-disabled reason, and reads active link widths. On link-down, it clears linkup and operational VLs, resets link credits, starts freeze handling, sets user link-down event bits, marks the neighbor non-normal, and dispatches `IB_EVENT_PORT_ERR`. User interrupt handling locks `dd->uctxt_lock`, ignores unused shared contexts, clears either `HFI1_CTXT_WAITING_RCV` or `HFI1_CTXT_WAITING_URG`, wakes the context waitqueue, disables receive-available interrupts for receive waiters, or increments `rcd->urgent`.

State and persistence: modifies `hfi1_pportdata` neighbor fields, `mgmt_allowed`, `pkeys[2]`, `linkup`, `offline_disabled_reason`, `actual_vls_operational`, and `neighbor_normal`. It modifies user-context `event_flags` and `urgent` counters and uses `dd->events` indirectly through `hfi1_set_uevent_bits()`. No persistent storage beyond in-memory port/context state and hardware PKEY/link programming.

Dependencies and integration points: uses CSR/8051 helpers, link setup helpers (`set_up_vau()`, `set_up_vl15()`, `assign_remote_cm_au_table()`), MAD/PKEY configuration via `hfi1_set_ib_cfg()` and `hfi1_event_pkey_change()`, freeze handling, RDMA core `ib_dispatch_event()`, receive-control operations, and the user polling bits defined in `hfi.h` and used in `file_ops.c`.

Risks: `signal_ib_event()` must not run before IB registration, hence the `HFI1_INITTED` guard. Management PKEY insertion assumes index 2 is free or already correct and warns otherwise. Link-up handling depends on firmware-updated neighbor CSRs being valid after a short delay. User interrupt ordering must clear wait bits under lock to avoid missed poll wakeups or leaving receive interrupts enabled.

Test signals: physical or simulated link up/down, management-allowed switch neighbor behavior, full management PKEY installation and PKEY change event, IB port error event on link down, user `poll()` waking for receive and urgent packets, receive-available interrupt disable after wake, and no wakeups for contexts whose `in_use_ctxts` bitmap is empty.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/iowait.c

Purpose: implements the non-inline portions of the HFI1 I/O wait helper used by QPs/PQs and IPoIB queues to track SDMA/PIO resource waits, queued work, flags, and starvation priority.

Important APIs and functions: `iowait_set_flag()`, `iowait_flag_set()`, and `iowait_clear_flag()` manipulate wait flags with tracepoints. `iowait_init()` initializes the embedded wait structure, callback pointers, waitqueues, counters, list heads, and two send-engine work items. `iowait_cancel_work()` synchronously cancels IB and TID RDMA work items. `iowait_set_work_flag()` marks whether the IB or TID send engine has pending work. `iowait_priority_update_top()` compares starvation-adjusted priorities and returns the index of the higher-priority waiter.

Control flow: callers embed `struct iowait`, call `iowait_init()` with workqueue callbacks and resource callbacks, then use inline helpers from `iowait.h` and the functions here to schedule work, queue SDMA txreqs, mark pending legs, wait for drains, and wake waiters when resources become available. Cancellation is used during teardown to ensure queued restart work no longer references the parent object.

State and persistence: state lives entirely in the caller-owned `struct iowait`: flags, SDMA/PIO busy atomics, tx limit/count/descriptor count, priority/starvation counters, callback pointers, waitqueues, and per-send-engine `struct iowait_work` entries. `iowait_priority_update_top()` treats one priority unit as sixteen starvation-count units.

Dependencies and integration points: includes `iowait.h` and `trace_iowait.h`, depends on Linux workqueues/list/waitqueue/atomics through the header, and integrates with SDMA tx request lists and higher-level QP/PQ/IPoIB scheduling. The TID RDMA leg is optional; `iowait_cancel_work()` checks whether its work function is initialized.

Risks: flag bit `IOWAIT_PENDING_IB` is 0, so users must consistently use bit operations and not treat zero as "no flag". Work cancellation must happen before parent memory is freed. Priority comparison uses `u8` arithmetic after shifting priority; large values would wrap if callers exceed expected ranges. Callback locking rules from the header matter because sleep/wakeup callbacks may run with locks held.

Test signals: tracepoints for set/clear, scheduling of IB and TID work, pending flag selection from `iowait_set_work_flag()`, drain wait completion after SDMA/PIO decrements, cancellation during QP teardown, and fairness tests showing starved waiters rise in priority.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/iowait.h

Purpose: declares the HFI1 I/O wait abstraction embedded in QP/PQ/IPoIB state to manage waits for SDMA ring space, PIO credits, queued transmit requests, workqueue restarts, drain synchronization, and fairness priority across the normal IB and TID RDMA send engines.

Important APIs and types: `struct iowait_work` wraps a work item, queued `sdma_txreq` list, and parent pointer for one send engine. `struct iowait` owns the waiter list node, sleep/wakeup/drained/priority callbacks, waitqueues, SDMA/PIO busy counters, queued descriptor/request counters, flags, priority/starvation fields, and two `iowait_work` entries (`IOWAIT_IB_SE`, `IOWAIT_TID_SE`). Public functions from `iowait.c` initialize, set/test/clear flags, cancel work, and set pending-work flags. Inline helpers schedule work, wait for drains, increment/decrement busy counters, wake drains, inspect tx heads/descriptors, update priority, queue overflow requests, clear starvation, test queued packets, account wait count, and convert between child and parent structures.

Control flow: transmit paths try to send immediately; on SDMA/PIO shortage they call `iowait_queue()` or callback-specific sleep paths to put the containing object on a wait list, append txreqs to the relevant send-engine list, increment descriptor/request counts, and set pending work. Resource-available paths call the waiter's `wakeup()` or schedule the relevant work item on a target CPU. Completion paths decrement SDMA/PIO busy counters and call `iowait_drain_wakeup()` when all pending work drains. Priority helpers let wait-list selection account for static priority plus starvation.

State and persistence: all state is memory-resident and embedded in a larger owner object. `sdma_busy` and `pio_busy` are atomics used by drain waitqueues. `count` tracks total queued descriptors; `tx_count` tracks queued tx entries; each `iowait_work.tx_head` holds prebuilt packets for that engine. `lock` records the seqlock protecting the wait-list head so destroy/unwait code can remove entries safely. Flags encode pending IB/TID work and any caller-defined wait bits.

Dependencies and integration points: depends on Linux list/workqueue/wait/sched primitives and `sdma_txreq.h`. It is used by verbs/TID RDMA/IPoIB transmit code that supplies callbacks and workqueue functions. The helper does not own the SDMA engine or QP; it is a coordination object between HFI1 send scheduling and upper-layer protocol state.

Risks: callbacks are documented as potentially invoked with locks held, so they must not sleep or submit txreqs directly if that would deadlock. `iowait_pio_drain()` uses a one-second timeout, unlike SDMA drain which waits indefinitely; callers must tolerate possible timeout return behavior hidden by the void helper. The descriptor accounting assumes every queued txreq eventually decrements through the same abstraction. Queueing with `pkts_sent` changes starvation behavior, so wrong values can reduce fairness. TID work may be absent and must be checked before cancellation/scheduling.

Test signals: compile coverage for all inline users, SDMA and PIO drain tests, wait-list removal under teardown, descriptor/count accounting under queue overflow, two-engine scheduling for IB and TID RDMA, starvation priority evolution, and lockdep coverage of sleep/wakeup callbacks.

# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/ipoib.h

Purpose: defines HFI1 IP-over-InfiniBand netdev private structures and function prototypes. It connects RDMA netdev/IPoIB operations to HFI1 SDMA transmit queues, receive preparation, NAPI, and per-device queue state.

Important APIs and types: `union hfi1_ipoib_flow` packs transmit queue and 5-bit service-channel flow data. `struct ipoib_txreq` wraps an `sdma_txreq`, SDMA header/status/completion state, owning private data, tx queue, and skb. `struct hfi1_ipoib_circ_buf` is a cacheline-conscious circular buffer for completed/sent txreq accounting with stop/full/no-desc counters. `struct hfi1_ipoib_txq` owns a NAPI object, SDMA engine pointer, pending tx list, flow tracking, queue index, packet-sent flag, embedded `struct iowait`, and tx ring. `struct hfi1_ipoib_dev_priv` owns HFI1 device/netdev/IB device pointers, tx queues, original netdev ops, QP, Q_Key, PKEY/index, and port number. `struct hfi1_ipoib_rdma_netdev` embeds `struct rdma_netdev` first followed by HFI1 private data. Prototypes cover send, txreq init/deinit, rxq init/deinit, TX NAPI enable/disable, SKB preparation, RDMA netdev parameter reporting, and tx timeout handling.

Control flow: RDMA netdev allocation uses `hfi1_ipoib_rn_get_params()` to size/configure the netdev. The inline `hfi1_ipoib_priv()` converts from `net_device` private memory to HFI1 private state. TX setup allocates per-queue tx request/ring state, send paths build `ipoib_txreq` objects and submit them through SDMA/iowait, NAPI reaps completed txreqs from `hfi1_ipoib_circ_buf`, and RX paths convert HFI1 netdev receive queue data into SKBs via `hfi1_ipoib_prepare_skb()`.

State and persistence: per-netdev state persists in `hfi1_ipoib_dev_priv` for the netdev lifetime. Per-TX-queue state includes SDMA engine assignment, flow-change tracking, wait state, NAPI state, and circular completion ring indices/counters. Per-request state is held in `ipoib_txreq` until SDMA completion and NAPI cleanup. Q_Key/PKEY/port fields mirror RDMA/IPoIB addressing configuration.

Dependencies and integration points: includes Linux netdevice, skb, slab, list, if_infiniband, RDMA verbs, and HFI1 `hfi.h`, `iowait.h`, and `netdev.h`. It integrates with `ipoib_main.c`, `ipoib_tx.c`, `ipoib_rx.c`, HFI1 SDMA engines, RDMA core `rdma_netdev`, and netdev NAPI/timeout hooks.

Risks: `struct hfi1_ipoib_rdma_netdev` requires `struct rdma_netdev` to remain first for core casting. Ring head/tail and cacheline layout are performance-sensitive and must be updated with correct producer/consumer ordering. Flow packing uses a small union with a packed struct; users must preserve endian/layout expectations. The tx queue's embedded `iowait` inherits the locking/callback constraints documented in `iowait.h`. PKEY/Q_Key mismatches can produce network-level drops rather than local errors.

Test signals: IPoIB netdev creation/destruction, TX queue allocation and NAPI completion, SDMA descriptor shortage handling through iowait, tx timeout recovery, RX SKB preparation, multi-queue flow selection, PKEY/Q_Key configuration, and RDMA netdev parameter validation.
