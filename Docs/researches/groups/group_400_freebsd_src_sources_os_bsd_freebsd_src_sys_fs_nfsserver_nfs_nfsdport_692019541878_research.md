# File Research: sources/os/bsd/freebsd-src/sys/fs/nfsserver/nfs_nfsdport.c

This file is the FreeBSD-specific VFS and kernel-service port layer for the in-kernel NFS server. It translates NFS server operations into FreeBSD vnode, mount, namei, credential, mbuf, extended-attribute, syscall, sysctl, and module-lifecycle operations. It also contains the server-side pNFS metadata-server glue that creates, finds, removes, and proxies I/O to data-server files stored on NFS-mounted DS backends.

Key behavior:
- Defines global NFS server state, per-vnet state, mutexes, public/root file handles, NFSv4 root pseudo-mount state, pNFS stripe sizing, and server tunables under `vfs.nfsd`.
- Implements sysctl handlers for DS directory fanout, server maximum I/O size, local lock acquisition, pNFS stripe count, and pNFS stripe unit. Several handlers reject changes while nfsd threads are running or from jailed credentials, and `srvmaxio` validates socket-buffer capacity.
- Maintains a small sequential-I/O heuristic table keyed by vnode pointer. `nfsvno_read()` and `nfsvno_write()` use it to set `IO_SEQSHIFT` hints before calling `VOP_READ()` or `VOP_WRITE()`.
- Provides core vnode wrappers: `nfsvno_getattr()`, `nfsvno_getfh()`, `nfsvno_accchk()`, `nfsvno_setattr()`, `nfsvno_readlink()`, `nfsvno_read()`, `nfsvno_write()`, `nfsvno_fsync()`, `nfsvno_statfs()`, `nfsvno_updfilerev()`, and `nfsvno_fillattr()`.
- Provides name lookup helpers. `nfsvno_setpathbuf()` and `nfsvno_relpathbuf()` manage `namei` buffers, while `nfsvno_namei()` performs server-controlled lookups, handles public-filehandle symlink traversal, enforces cross-mount rules, and cleans up vnode references on all paths.
- Implements create and namespace mutation helpers: `nfsvno_createsub()`, `nfsvno_mknod()`, `nfsvno_mkdir()`, `nfsvno_symlink()`, `nfsvno_removesub()`, `nfsvno_rmdirsub()`, `nfsvno_rename()`, and `nfsvno_link()`. These functions mediate VFS operations, NFSv2/v3/v4 protocol differences, delegation checks, write-mount coordination, pNFS DS-file cleanup, and path-buffer cleanup.
- Implements NFSv4 `OPEN` file creation/existing-file handling in `nfsvno_open()`, including exclusive create verifier handling, delayed attribute fixing, truncation checks, and `nfsrv_opencheck()` state validation.
- Builds READDIR and READDIRPLUS/NFSv4 READDIR replies in `nfsrvd_readdir()` and `nfsrvd_readdirplus()`. These functions read native `struct dirent` records with `VOP_READDIR()`, filter invalid/whiteout entries, handle UFS cookie behavior, perform per-entry vnode acquisition by `VFS_VGET()` or `VOP_LOOKUP()`, cross mount points for NFSv4 when enabled, emit post-op attributes/file handles, support referrals, and trim partially-built mbuf replies when size limits are exceeded.
- Parses settable attributes for NFSv2, NFSv3, and NFSv4 in `nfsrv_sattr()` and `nfsv4_sattr()`. NFSv4 parsing covers size, ACLs, archive/hidden/system flags, mode, owner/group name mapping, time fields, `mode_set_masked`, `mode_umask`, and POSIX draft ACL attributes.
- Handles export and credential checks through `nfsd_excred()`, `nfsvno_checkexp()`, `nfsvno_fhtovp()`, `nfsd_fhtovp()`, `nfsvno_v4rootexport()`, `nfsrv_v4rootexport()`, and `nfsvno_testexp()`. This includes jail export checks, anonymous/root credential mapping, managed AUTH_SYS group replacement, NFSv4-only exports, RPCSEC_GSS security flavor matching, and TLS/certificate export requirements.
- Implements the in-kernel `nfssvc` server path. `nfssvc_nfsd()` handles adding server sockets, starting nfsd worker threads, configuring pNFS DS state, and dispatching other server control calls. `nfssvc_srvcall()` handles public file handles, v4 root exports, stable restart setup, client/lock dumps, administrative revoke, backup-stable signaling setup, and nfsd suspend/resume.
- Creates and initializes the FreeBSD fake NFSv4 root mount in `nfsd_mntinit()`, runs the one-second nfsd callout timer in `nfsd_timer()`, and tears per-vnet state down in `nfsrv_cleanup()`.
- Provides server local locking with `nfsvno_advlock()`, using a fixed NLM sysid for all NFSv4 server-held local locks when `vfs.nfsd.enable_locallocks` is enabled.
- Provides NFSv4.2 local operations: `nfsvno_seek()` via `VOP_IOCTL(FIOSEEK*)`, `nfsvno_allocate()` via repeated `VOP_ALLOCATE()`, and `nfsvno_deallocate()` via repeated `VOP_DEALLOCATE()`.
- Provides user extended-attribute operations: `nfsvno_getxattr()`, `nfsvno_setxattr()`, `nfsvno_rmxattr()`, and `nfsvno_listxattr()`, including MAC checks where compiled, mbuf/iovec conversion, response size checks, fallback removal via empty setextattr, fsync after mutation, and pNFS DS metadata updates after xattr changes.
- Contains module load/unload glue in `nfsd_modevent()`, registering `nfsd_call_nfsd`, initializing global mutexes and vnode delegation callbacks, rejecting unload while nfsd threads exist, and declaring module dependencies on `nfscommon`, `nfslockd`, `krpc`, and `nfssvc`.

pNFS behavior:
- pNFS is represented on the metadata file through system extended attributes: `pnfsd.dsfile` stores one or more `pnfsdsfile` records with DS socket address, DS file handle, DS filename, stripe count/size, and DS directory; `pnfsd.dsattr` stores cached DS attributes such as file revision, size, access/modify times, and bytes used.
- `nfsrv_pnfscreate()` selects DS directories in round-robin order, accounts for MDS-specific DS assignments, mirror counts, stripe counts, and stripe sizes, then creates DS data files through `nfsrv_dscreate()`. Additional mirror/stripe creations can be queued through `nfs_pnfsio()`.
- `nfsrv_dscreate()` creates the actual DS file in the selected DS directory, applies ownership/mode attributes, verifies the created file is on an NFS mount with a native-size file handle, records the DS file handle/socket/filename, and optionally returns initial DS attributes.
- `nfsrv_pnfsremovesetup()` finds DS directories and filenames before the MDS file is removed, only for exported regular files with a final hard link. `nfsrv_pnfsremove()` then removes all DS copies and frees layouts after the MDS remove/rename succeeds.
- `nfsrv_dsgetsockmnt()` is the central resolver for `pnfsd.dsfile`. It decodes current and older DS-file xattr formats, validates mirror/stripe counts, finds live DS mounts by socket address, optionally selects a destination DS for mirror copy, locks DS directory vnodes, returns DS file handles/device ids, handles zero file handles by looking up the DS file by name, and can return all DS directories for deletion.
- `nfsrv_proxyds()` is the central MDS-to-DS proxy dispatcher. For regular exported files on pNFS-enabled mounts, it resolves DS state and calls DS RPC helpers for reads, writes, setattrs, and getattrs. It retries read/getattr after mirror failure, disables failed DS mounts through `nfsrv_deldsnmp()`, cancels outstanding RPCs with `nfsrv_killrpcs()`, and unlocks all DS directory vnodes before returning.
- `nfsrv_readdsrpc()` handles striped DS reads. It splits a requested range across stripe boundaries, runs read RPCs in parallel when pNFS I/O threads exist, joins returned mbuf chains in order, and reports the failed stripe/mirror position for failover.
- `nfsrv_writedsrpc()` handles mirrored and striped DS writes. It copies the relevant mbuf ranges for each DS write, sends all writes as filesync, retrieves updated size/change/time/space attributes, and refreshes `pnfsd.dsattr` from the selected reply.
- `nfsrv_setattrdsrpc()` applies metadata-driven setattr operations to every stripe/mirror and records the largest resulting size in `pnfsd.dsattr`.
- `nfsrv_getattrdsrpc()` performs getattr on every stripe when necessary because only the DS holding the final bytes knows the real size; it selects the largest size returned and refreshes the metadata xattr when the MDS vnode is exclusively locked.
- `nfsrv_pnfsstatfs()` sums DS `statfs` values, converting block counts across differing block sizes, so clients see aggregate pNFS space values.
- `nfsrv_checknospc()` periodically revisits DS devices marked no-space and clears the marker once `f_bavail` is positive.
- Some DS proxy paths for NFSv4.2 `ALLOCATE`, `DEALLOCATE`, `SEEK`, and DS ACL propagation are present under `#ifdef notnow`, documenting intended behavior but not compiled in this file as-is.

Important interactions:
- Uses FreeBSD vnode/VFS entry points heavily: `VOP_GETATTR`, `VOP_SETATTR`, `VOP_ACCESSX`, `VOP_CREATE`, `VOP_MKNOD`, `VOP_MKDIR`, `VOP_SYMLINK`, `VOP_REMOVE`, `VOP_RMDIR`, `VOP_RENAME`, `VOP_LINK`, `VOP_FSYNC`, `VOP_READ`, `VOP_WRITE`, `VOP_READDIR`, `VOP_READLINK`, `VOP_IOCTL`, `VOP_ALLOCATE`, `VOP_DEALLOCATE`, `VOP_GETEXTATTR`, `VOP_SETEXTATTR`, `VOP_DELETEEXTATTR`, `VOP_LISTEXTATTR`, `VFS_FHTOVP`, `VFS_VGET`, `VFS_ROOT`, `VFS_STATFS`, and `VFS_CHECKEXP`.
- Relies on common NFS mbuf/XDR helpers from the shared NFS code, including `NFSM_DISSECT`, `NFSM_BUILD`, `nfsm_strtom()`, `nfsm_fhtom()`, `nfsm_trimtrailing()`, `nfsv4_fillattr()`, `nfsv4_loadattr()`, `nfscl_reqstart()`, `newnfs_request()`, and `nfsrv_putattrbit()`.
- Coordinates with NFSv4 state/delegation/layout code through functions such as `nfsrv_opencheck()`, `nfsrv_checkremove()`, `nfsd_recalldelegation()`, `nfsrv_removedeleg()`, `nfsrv_freefilelayouts()`, `nfsrv_checkdsattr()`, `nfsrv_throwawayallstate()`, and layout/device data structures.
- Uses per-vnet global state for nfsd worker counts, reply caches, client/session/lock hashes, v4 root file handle, fake v4 root mount, callout timer, and suspend lock.
- Uses DS-device global state protected by `nfsrv_dslock_mtx`/`NFSDDSLOCK()`, particularly the `nfsrv_devidhead` list, device ids, DS directories, MDS-specific DS mappings, and no-space flags.
- Uses kernel memory and mbuf APIs directly. Read, readlink, and xattr get paths allocate mbuf chains plus iovec arrays; large TLS replies may use external-page mbufs.
- Uses Capsicum rights for nfsd add-socket file descriptors and `copyin`/`copyout`/`copyinstr` for nfssvc user-kernel ABI structures.
- Uses MAC Framework hooks for user extended attributes when `MAC` is enabled.

Edge cases and invariants:
- Access checking deliberately differs from plain `vn_writechk()`/`VOP_ACCESSX()` because exports can be read-only even when the local mount is not, and NFS open-owner compatibility requires owner/root override options in selected cases.
- Many operations must clean up `nameidata` path buffers and vnode references differently depending on whether lookup succeeded, whether parent and child are identical, and whether VFS calls consumed locked references.
- `nfsvno_namei()` rejects degenerate public absolute paths and only follows symlinks for public lookups; non-public symlink traversal through this path returns `EINVAL`.
- `nfsvno_rename()` performs extensive protocol-specific validation before calling `VOP_RENAME()`, including type mismatch mapping for NFSv2, mount-point/root checks, cross-mount rejection, same-source/destination no-op handling, delegation recall/checks, and a nonblocking rename-lock attempt that can return `ERELOOKUP`.
- Readdir paths must handle `VOP_READDIR()` returning records before the requested UFS cookie and can loop when a buffer contains no useful entries. They also trim whiteouts and zero-fileid entries.
- Readdirplus/NFSv4 READDIR must fall back from `VFS_VGET()` to `VOP_LOOKUP()` for filesystems such as ZFS snapshot directories, and must handle mount traversal, referrals, `RDATTRERROR`, and `EOPNOTSUPP` from unexportable filesystems.
- NFSv4 attribute parsing continues advancing through the XDR stream even after `nd_repstat` is set, so malformed sizes and unsupported attributes do not desynchronize later parsing.
- `nfsv4_sattr()` rejects ambiguous or unsupported combinations such as ACL plus POSIX ACL bits, `MODE` with `MODESETMASKED`, `MODEUMASK` outside NFSv4.2 create, empty POSIX access ACLs, and default POSIX ACLs on non-directories.
- pNFS DS file creation, removal, read/write, and setattr tolerate partial mirror failure by disabling the failed DS mount and cancelling outstanding RPCs. Read/getattr can retry on another mirror; write/setattr generally do not retry because surviving mirrors may already have been modified.
- pNFS `GETATTR` can serve cached `pnfsd.dsattr` unless configured to query DS attributes or state indicates a client may hold write-capable layout/open/delegation state.
- `nfsrv_pnfssetfh()` only persists a newly discovered DS file handle when the metadata vnode is exclusively locked and the call is not merely serving a device-id/name query.
- `nfsvno_getxattr()` does a size probe before reading and returns NFS xattr protocol errors for no attribute or oversized responses; `nfsvno_listxattr()` has a hard 10 MiB allocation sanity limit.
- `nfsvno_updateds()` intentionally toggles the DS file mode `S_ISGID` bit twice to force DS ctime/change updates after xattr mutations, a documented hack that can leave harmless intermediate state only if the DS setattr path fails.
- Module unload rejects active nfsd threads and frees pNFS layout hashes only on unload, while per-vnet cleanup destroys vnet-owned caches, locks, sessions, and the fake v4 root mount.
