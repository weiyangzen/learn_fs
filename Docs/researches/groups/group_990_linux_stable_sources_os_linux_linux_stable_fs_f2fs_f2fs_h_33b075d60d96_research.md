# File Research: sources/os/linux/linux-stable/fs/f2fs/f2fs.h

`f2fs.h` is the central private header for the Linux stable F2FS implementation. It defines the shared in-memory data model, mount and feature flags, accounting helpers, inline helpers, fault-injection wrappers, compression contexts, checkpoint/discard/GC state, and the cross-file prototypes used by the rest of `fs/f2fs/`.

The header starts with fault handling and mount configuration. `f2fs_bug_on()` either panics under `CONFIG_F2FS_CHECK_FS` or warns and marks `SBI_NEED_FSCK`; the fault-injection enum covers allocation, block, checkpoint, discard/write/read I/O, lock timeout, and consistency failure sites. `struct f2fs_mount_info` owns parsed mount options such as active logs, reserved root blocks/nodes, quota files, fsync/allocation/GC/memory modes, discard policy, dummy encryption, checkpoint-disable unusable caps, and compression defaults.

It defines on-disk compatibility feature bits, basic block and node ID types, zoned/allocation policy enums, lock names, checkpoint reasons, checkpoint timing phases, and metadata/data validation classes. Checkpoint support includes `struct cp_control`, `struct cp_stats`, asynchronous checkpoint request control, inode-number tracking lists, orphan/update/append/flush inode entries, and summary-journal accessors for NAT and SIT journal entries.

Discard and flush infrastructure is modeled through `discard_entry`, `discard_info`, `discard_cmd`, `discard_policy`, `discard_cmd_control`, `flush_cmd`, and `flush_cmd_control`. These structures describe pending discard ranges, rb-tree/list organization, synchronous wait/completion state, queued/in-flight counts, discard granularity, ordered discard behavior, and background issue threads. The helper macros encode default discard intervals, granularities, pending-list bucketing, and discard states.

Directory and inline-data definitions include `struct f2fs_filename`, `struct f2fs_dentry_ptr`, inline dentry layout helpers, inline data/xattr sizing macros, and filename advice bits. `f2fs_filename` bridges user names, encrypted on-disk names, hashes, optional fscrypt buffers, and optional Unicode casefolded names. `make_dentry_ptr_block()` and `make_dentry_ptr_inline()` abstract regular dentry blocks versus inline dentry storage so `dir.c` and inline directory code can share scanning and update routines.

The inode model is centered on `struct f2fs_inode_info`, which embeds the VFS inode and adds F2FS inode flags, file advice, directory depth or GC failure count, parent inode number, dirty-page counters, lookup/create task tracking, xattr node ID, last on-disk size, quota state, dirty/donation lists, open count, extent cache pointers, atomic-write/COW inode linkage, GC and xattr semaphores, extra inode attribute state, project ID, creation/disk times, compression parameters, writeback count, atomic-write counters, original atomic-write size, and fscrypt state.

Extent and block mapping support is defined by `extent_info`, `extent_node`, `extent_tree`, `extent_tree_info`, and `f2fs_map_blocks`. Read extents map file offsets to physical blocks, optionally including compressed physical length; age extents track allocation age and last allocation counters for temperature decisions. `f2fs_map_blocks` is the common map result/request object for buffered I/O, direct I/O, bmap, fiemap, precache, and preallocation callers, carrying logical/physical ranges, flags, segment type, multidevice DIO eligibility, and next-hole/extent hints.

The node and segment managers are represented by `f2fs_nm_info`, `dnode_of_data`, log-type constants, and `f2fs_sm_info`. Node-manager state covers NAT layout, NAT/free-NID radix trees, clean/dirty/reclaimable NAT counters, free-NID bitmaps, NAT block bitmaps, NAT bits, and checkpoint NAT bitmaps. Segment-manager state covers SIT/free/dirty/curseg managers, curseg locking, segment layout addresses and counts, overprovision/reserved/prefree thresholds, IPU policy knobs, flush command control, and discard command control.

I/O state is standardized through count types, page types, temperature types, iostat types, `f2fs_io_info`, `bio_entry`, `f2fs_bio_info`, and `f2fs_dev_info`. These definitions carry logical F2FS I/O class, block operation flags, old/new block addresses, folio/page pointers, encrypted or compressed pages, compression block counts, lock/submission state, iostat classification, writeback control, and merged BIO state. Multidevice support stores per-device block ranges, paths, block devices, total segments, and zoned-device sequential-zone bitmaps.

`struct f2fs_sb_info` is the largest contract in the file and owns the mounted filesystem runtime state. It links the VFS superblock, raw superblock, node/segment managers, write BIO arrays, checkpoint metadata, checkpoint locks and timers, inode-management trees, fsync node lists, extent-cache roots, block/section geometry, summary geometry, valid/reserved/unusable block counts, quota state, page and block counters, mount options, GC state, statistics, sysfs/debug objects, shrinker membership, multidevice state, error/stop-reason state, compression cache/runtime statistics, and optional iostat latency counters.

The inline helper layer provides typed accessors and invariants for the rest of F2FS. It includes `F2FS_I()`, `F2FS_SB()`, `F2FS_CKPT()`, `F2FS_NODE()`, `F2FS_INODE()`, `NM_I()`, `SM_I()`, `SIT_I()`, `META_MAPPING()`, and `NODE_MAPPING()`, plus helpers for checkpoint flags, current checkpoint pack addresses, NAT bits, superblock feature tests, CRC/checksum seeding, block/section geometry, raw node data addresses, F2FS big-endian-style bitmaps, and validity checks for data block addresses.

The header also defines accounting helpers that are more than simple accessors. `inc_valid_block_count()`, `dec_valid_block_count()`, `inc_valid_node_count()`, and `dec_valid_node_count()` coordinate quota reservation/claiming, reserved-root or reserved-node policy, checkpoint-disabled unusable blocks, total valid block/node counters, inode block accounting, percpu allocation counters, and `SBI_NEED_FSCK` marking on inconsistencies. Dirty-page helpers update per-inode dirty counts and superblock page counters, while atomic-write helpers track current and peak atomic-write block usage.

Page-private handling is encoded in macros that generate folio/page test, set, and clear helpers for F2FS private bits. F2FS uses a tagged `folio->private` layout that distinguishes non-pointer flag payloads from wrapped pointer private data. The flags track ongoing migration, inline inode data, referenced resources, and atomic-write pages; `folio_get_f2fs_data()` and `folio_set_f2fs_data()` pack additional F2FS-private data behind the flag bits.

The inode flag/advice helpers bridge in-memory flags and on-disk inode state. They cover cold/hot data hints, lost parent inode numbers, encryption/name encryption flags, keep-size/truncate advice, verity state, inline xattr/data/dentry state, compressed-file state, pinned files, mmap files, atomic/COW files, and dirty/autorecover inode handling. Size, link, block, directory-depth, GC-failure, xattr-nid, and parent-nid write helpers centralize inode dirtying and recovery marking.

The prototype section exposes the internal module boundaries. It declares interfaces implemented by `file.c`, `inode.c`, `namei.c`, `dir.c`, `super.c`, `hash.c`, `node.c`, `segment.c`, `checkpoint.c`, `data.c`, `gc.c`, `recovery.c`, `debug.c`, `inline.c`, `shrinker.c`, `extent_cache.c`, `sysfs.c`, `verity.c`, and `compress.c`. This header is therefore the primary dependency hub for F2FS, tying VFS operations, checkpointing, node/NAT management, SIT/segment allocation, data I/O, garbage collection, recovery, inline files, compression, fscrypt, fsverity, debugfs, sysfs, and shrinkers together.

Debug and statistics definitions are conditional on `CONFIG_F2FS_STAT_FS`. When enabled, `struct f2fs_stat_info` snapshots layout, extent-cache hits, dirty page/inode counts, NAT/SIT/free-NID state, I/O pressure, discard/flush/checkpoint queues, inline/compression/swap/atomic-file counts, valid/free/prefree segment counts, curseg positions, GC counts, metadata counts, allocation mode counts, memory footprint, and per-device segment/section stats. When disabled, the stat macros compile to no-ops.

Compression support includes algorithm and flag enums, compressed data headers, compression/decompression context structures, compressed write I/O context, and many conditional prototypes. The active helpers decide whether a file may be compressed, initialize default compression context from mount options, update saved-block accounting, and disable compression only when the file has no mmap/writeback/data-block conflicts. Without `CONFIG_F2FS_FS_COMPRESSION`, stubs preserve call-site buildability while rejecting actual compressed-file operation.

Device, zoned, discard, quota, and error helpers near the end encode policy decisions used throughout the implementation. They detect multidevice volumes, bdev indexes, discard support and granularity, realtime discard eligibility, readonly devices, LFS mode, sequential-zone areas, low-memory mode, multidevice direct-I/O eligibility, journalled quota, quota system files, block-unit discard mode, killable schedule timeouts, repeated page-EIO checkpoint stopping, and invalidation of internal meta/compress caches.

Key invariants established by this header are: F2FS block addresses remain 32-bit on disk; valid block/node counters must stay in sync with quota and inode `i_blocks`; checkpoint flags and NAT bits require `cp_lock` when mutated; inline inode/dentry layout depends on extra attribute and inline xattr sizing; extent-tree state must stay per-type and per-inode; compressed-file operations are gated by feature/config/runtime state; page-private payloads must preserve the non-pointer tag convention; multidevice and zoned decisions must route through the target-device helpers; and serious consistency anomalies mark the filesystem for fsck or stop checkpointing.
