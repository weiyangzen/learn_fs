## sources/distributed-fs/ceph-client/fs/btrfs/space-info.c

Purpose: Implements Btrfs logical space accounting, reservation admission, ENOSPC ticket handling, asynchronous metadata/data reclaim, zoned reclaim hooks, and reclaim-threshold accounting for block groups. It is the runtime policy layer behind `struct btrfs_space_info`: callers reserve data or metadata bytes, update counters as extents move from reservation to allocation to persistent use, and reclaim workers flush delayed work or allocate chunks when reservations cannot be immediately satisfied.

Important APIs/types/functions: The private `struct reserve_ticket` records a blocked reservation, error, steal eligibility, list linkage, wait queue, and per-ticket lock. Public entry points include `btrfs_init_space_info()`, `btrfs_add_bg_to_space_info()`, `btrfs_find_space_info()`, `btrfs_reserve_metadata_bytes()`, `btrfs_reserve_data_bytes()`, `btrfs_try_granting_tickets()`, `btrfs_can_overcommit()`, `btrfs_dump_space_info()`, `btrfs_init_async_reclaim_work()`, `btrfs_account_ro_block_groups_free_space()`, `btrfs_calc_reclaim_threshold()`, `btrfs_reclaim_sweep()`, and `btrfs_return_free_space()`. Key internal routines are `reserve_bytes()`, `handle_reserve_ticket()`, `flush_space()`, `do_async_reclaim_metadata_space()`, `do_async_reclaim_data_space()`, `btrfs_preempt_reclaim_metadata_space()`, `maybe_fail_all_tickets()`, `steal_from_global_rsv()`, and `shrink_delalloc()`.

Control flow: Mount/open initialization calls `btrfs_init_space_info()` to create SYSTEM, METADATA, DATA, mixed DATA+METADATA, and optional remap/zoned sub-group space infos. Block groups are attached through `btrfs_add_bg_to_space_info()`, which updates logical and mirrored disk counters, adds the block group to its RAID-profile list, and rechecks pending tickets. Reservation callers enter `reserve_bytes()`: it calculates current used bytes, honors pending ticket ordering, admits the reservation if allocated space or metadata overcommit permits it, handles emergency metadata reservations specially, otherwise queues a ticket. Normal data/metadata tickets are served by async workers; priority tickets run bounded reclaim synchronously in the caller. A successful ticket increments `bytes_may_use`; failure removes the ticket with `-ENOSPC`, `-EINTR`, or a filesystem abort error.

Reclaim flow: `flush_space()` maps `enum btrfs_flush_state` values to concrete actions: run delayed inode items, flush delalloc and optionally wait for ordered extents, run delayed refs, allocate chunks, reclaim or reset zones, run delayed iputs, or commit the current transaction. Metadata async reclaim walks progressively stronger states, skips overly aggressive passes on the first cycle, uses ticket progress as its reset signal, and fails tickets after repeated commit cycles with no progress. Data async reclaim first tries forced chunk allocation while the data space is not marked full, then cycles through full delalloc flush, delayed iputs, commit, zoned reclaim/reset, and chunk allocation. Preemptive metadata reclaim runs before tickets exist when delayed reservations or pinned space exceed a clamped threshold.

State and persistence behavior: `space_info->lock` protects byte counters, ticket lists, reclaim sizing, `full`, `flush`, preemptive `clamp`, and periodic reclaim readiness. `groups_sem` protects block-group lists. The counters track volatile reservations (`bytes_may_use`, `bytes_reserved`), committed logical use (`bytes_used`), transaction-pinned frees (`bytes_pinned`), readonly and zone-unusable bytes, and mirrored disk accounting (`disk_used`, `disk_total`). Persistent state is indirect: reclaim and commit operations write delayed metadata, update free-space structures, delete/reset zoned block groups, allocate chunks, and commit transactions; the space-info object itself is in-memory state rebuilt during mount.

Dependencies and integration points: This file integrates with block-group management, chunk allocation, delayed refs/items/iputs, ordered extents and delalloc writeback, transactions, free-space cache dumping, sysfs allocation kobjects, tracepoints, zoned block-group reclaim/reset, global and per-purpose block reserves, device free-chunk accounting, and mount options such as `ENOSPC_DEBUG`. It depends on the helper contracts in `space-info.h`, allocation profiles in `volumes.h`, and transaction safety rules that forbid full flushing while a transaction handle is held.

Risks: ENOSPC behavior is sensitive to ticket ordering, counter underflow, interrupt races, and progress detection. Deadlocks are possible if callers use flush modes that can commit while holding a transaction handle, which is guarded by assertions. Metadata overcommit can admit reservations based on unallocated device space and must keep enough data-chunk slack. Global reserve stealing must not hide transaction aborts. Zoned mode has distinct final reclaim states and alignment requirements; wrong chunk-size or threshold math can overcommit and surface late ENOSPC. Preemptive reclaim that is too eager hurts allocation locality; too lax pushes users onto blocking ticket paths.

Test signals: Exercise metadata and data reservations under no-flush, normal flush, priority flush, evict, free-space-inode, all-steal, and emergency modes; fatal-signal interruption of ticket waits; transaction-abort propagation; ENOSPC debug dumps; large leading tickets with smaller following tickets; global reserve stealing; remount/closing suppression of preemptive reclaim; delalloc-heavy versus ordered-heavy workloads; mixed block groups where overcommit is forbidden; zoned reclaim/reset paths; dynamic and fixed block-group reclaim thresholds; readonly block-group free-space accounting; and counter underflow warnings from `DECLARE_SPACE_INFO_UPDATE` helpers.

## sources/distributed-fs/ceph-client/fs/btrfs/space-info.h

Purpose: Declares the Btrfs space-info contract shared by allocation, block-group, transaction, and superblock code. It defines reservation flush policies, reclaim state ordering, zoned sub-groups, the central `struct btrfs_space_info`, counter update helpers, and exported functions for reserving, freeing, dumping, and reclaiming filesystem space.

Important APIs/types/functions: `enum btrfs_reserve_flush_enum` describes how aggressively a caller may reclaim space, from `BTRFS_RESERVE_NO_FLUSH` through bounded, evict, data, all, all-steal, free-space-inode, and emergency modes. `enum btrfs_flush_state` fixes the metadata async reclaim order used by `space-info.c`. `enum btrfs_space_info_sub_group` identifies primary, data relocation, and tree-log sub-groups, with `BTRFS_SPACE_INFO_SUB_GROUP_MAX` currently allowing one child. `struct btrfs_space_info` carries byte counters, ticket lists, block-group lists, sysfs kobjects, reclaim statistics, reclaim thresholds, and flags. Inline helpers include `btrfs_mixed_space_info()`, generated `btrfs_space_info_update_bytes_may_use/pinned/zone_unusable()`, `btrfs_space_info_used()`, `btrfs_space_info_free_bytes_may_use()`, and `btrfs_space_info_type_str()`.

Control flow and state: Callers hold `space_info->lock` before using generated update helpers or `btrfs_space_info_used()`, which lets lockdep catch unsafe counter inspection. Reservation users call `btrfs_reserve_metadata_bytes()` or `btrfs_reserve_data_bytes()` with an allowed flush policy; when reserved bytes are returned from block reserves, `btrfs_space_info_free_bytes_may_use()` decrements `bytes_may_use` and immediately grants queued tickets. Block-group lifecycle code attaches groups with `btrfs_add_bg_to_space_info()`, while lookup users locate the relevant info by block-group type flags.

State and persistence behavior: The structure is volatile mount state, but it mirrors persistent allocation reality: `total_bytes`, `bytes_used`, `bytes_reserved`, `bytes_pinned`, `bytes_readonly`, and `bytes_zone_unusable` represent what can be allocated, what is committed to extents, what is transiently reserved, and what cannot currently be reused. `disk_total` and `disk_used` account mirrored/profile cost. Reclaim counters and sysfs kobjects expose operational state to userspace. The header also encodes that tickets and readonly block-group lists are protected by the same spinlock and that block-group arrays are protected by `groups_sem`.

Dependencies and integration points: Includes tracepoint declarations, kernel list/lock/wait/kobject primitives, and Btrfs volume profile definitions. The exported API is consumed by extent-tree/block-reserve code, chunk allocation, sysfs allocation reporting, statfs, transaction abort dumping, cleaner reclaim, and zoned support. `btrfs_space_info_type_str()` is intentionally limited to primary type combinations, so sub-group identity is tracked separately by `subgroup_id`.

Risks: The flush enum ordering and comments are part of behavior, especially `enum btrfs_flush_state`, whose order is walked directly by metadata reclaim. Counter helpers warn and zero on underflow, but callers still need correct locking and signed deltas. `BTRFS_RESERVE_FLUSH_EMERGENCY` deliberately ignores `bytes_may_use`, so misuse can over-admit reservations. The sub-group array size is one despite multiple enum values beyond primary, so adding simultaneous sub-groups requires a structural change, not just a new enum.

Test signals: Compile coverage should catch enum/API drift, but behavior needs runtime tests around every flush policy, counter update under lockdep, `bytes_may_use` return waking tickets, mixed DATA+METADATA detection, sysfs allocation stats, readonly block-group accounting, zoned sub-group creation, and underflow assertions in debug builds.

## sources/distributed-fs/ceph-client/fs/btrfs/subpage.c

Purpose: Implements Btrfs subpage folio state for filesystems whose sectors or metadata nodes are smaller than the kernel folio/page. It provides sector-granular uptodate, dirty, writeback, ordered, checked, and locked bitmaps so multiple Btrfs blocks can safely share one folio without relying only on page-level flags.

Important APIs/types/functions: Public functions include `btrfs_attach_folio_state()`, `btrfs_detach_folio_state()`, `btrfs_alloc_folio_state()`, `btrfs_folio_inc_eb_refs()`, `btrfs_folio_dec_eb_refs()`, `btrfs_folio_set_lock()`, `btrfs_folio_end_lock()`, `btrfs_folio_end_lock_bitmap()`, all generated `btrfs_subpage_*`, `btrfs_folio_*`, `btrfs_folio_clamp_*`, and `btrfs_meta_folio_*` operations, plus `btrfs_subpage_clear_and_test_dirty()`, `btrfs_meta_folio_clear_and_test_dirty()`, `btrfs_folio_assert_not_dirty()`, `btrfs_subpage_dump_bitmap()`, and `btrfs_get_subpage_dirty_bitmap()`.

Control flow: Folio setup attaches `struct btrfs_folio_state` only when metadata nodesize or data sectorsize requires subpage handling and no private state already exists. Metadata folios track `eb_refs` under the mapping private lock so an extent buffer being allocated cannot race with private-state detachment. Data folios track `nr_locked`, with `btrfs_folio_set_lock()` populating locked bits for a range that was originally locked at the folio level; unlock paths clear range bits and unlock the folio only when the last subpage lock is gone. Bitmap state setters mark the relevant sectors and then synchronize the aggregate folio flag when all sectors are set or clear.

State and persistence behavior: `struct btrfs_folio_state` is attached to `folio->private`, protected by its own IRQ-safe spinlock for bitmap mutations, and freed on detach. No on-disk state is written here directly; the bitmaps drive read/writeback correctness for metadata and data I/O. Dirty and writeback helpers bridge sector-granular Btrfs state to VFS folio flags, including preserving the writeback TOWRITE tag for dirty folios to avoid WB_SYNC_ALL completion ordering bugs. Clamp helpers restrict arbitrary ranges to the folio boundary for data paths that scan wider ranges.

Dependencies and integration points: Integrates with the folio API, extent buffers, Btrfs inode helpers, page private state, bitmap helpers, writeback internals, lockdep assertions, and debug `dump_page()` diagnostics. Metadata callers use `btrfs_meta_folio_*` because dummy extent buffers may not have a mapping, while data callers use `btrfs_folio_*` or clamp variants. The implementation assumes metadata large folios are not supported and documents the 64K-page oriented constraints.

Risks: Range alignment and boundary checks are critical; incorrect start/length values corrupt unrelated sectors in the same folio. Dirty/writeback aggregation can violate sync semantics if folio flags are cleared too early. The locked bitmap is explicitly transitional for async delalloc/compression, so races around randomly completing async extents are a known pressure point. Metadata detachment races are controlled by `eb_refs`; missing private-lock coverage can free state while an extent buffer is still forming. Deprecated ordered/checked flags remain for COW fixup and are likely future churn points.

Test signals: Run subpage metadata read/writeback on 64K page kernels with smaller nodesize, data read/write paths with sectorsize smaller than folio size, compression async delalloc locking/unlocking, folio clamp paths that partially overlap or miss a folio, dirty clearing where other sectors remain dirty, WB_SYNC_ALL with dirty plus writeback sectors, extent-buffer allocation/free races, dummy extent buffer metadata helpers, debug assertion builds for bitmap dumps, and non-subpage fallback paths used by extent-io selftests.

## sources/distributed-fs/ceph-client/fs/btrfs/subpage.h

Purpose: Declares the Btrfs subpage folio-state interface. It describes how per-sector bitmaps are packed, defines the private state attached to folios, separates metadata and data users, and generates declarations for the bitmap operations implemented in `subpage.c`.

Important APIs/types/functions: The anonymous bitmap enum defines ordered bitmap slots for `uptodate`, `dirty`, `writeback`, `ordered`, `checked`, and `locked`. `struct btrfs_folio_state` contains the bitmap spinlock plus either metadata `eb_refs` or data `nr_locked`. `enum btrfs_folio_type` selects metadata versus data allocation semantics. `btrfs_meta_is_subpage()` checks `nodesize < PAGE_SIZE`; `btrfs_is_subpage()` checks `sectorsize < folio_size(folio)` and asserts mapped folios are data inodes. `DECLARE_BTRFS_SUBPAGE_OPS()` declares subpage, folio, clamped folio, and metadata helpers for each status bit. The header also exposes attach/detach/allocation, lock helpers, dirty bitmap diagnostics, and `btrfs_folio_clamp_finish_io()`.

Control flow and state: Callers attach state before using sector-granular helpers, then invoke operations at the narrowest semantic level: raw `btrfs_subpage_*` when a validated range is inside a subpage folio, `btrfs_folio_*` when code should transparently fall back to normal folio flags, clamp variants when the requested data range may cross folio boundaries, and metadata helpers for extent-buffer based operations. `btrfs_folio_clamp_finish_io()` is an error cleanup helper that clears dirty, sets writeback, and immediately clears writeback for a clamped range.

State and persistence behavior: The header defines in-memory state only. It controls how VFS folio flags summarize Btrfs sector states and how metadata extent-buffer references prevent premature private-state detachment. The bitmap order is ABI-like within the implementation because macros calculate offsets as `blocks_per_folio * bitmap_nr`.

Dependencies and integration points: Includes kernel spinlock, atomic, sizes support, and `btrfs_inode.h`; forward declares `address_space` and `folio`. The declarations are used throughout extent I/O, metadata extent buffers, data writeback, compression/delalloc, and selftests. The metadata comment states that no clamp variants are needed for metadata because folios are never larger than nodesize when nodesize is at least page size.

Risks: Macro-generated APIs multiply the surface area, so name or signature drift can break many call sites. The `btrfs_is_subpage()` assertion assumes mapped folios reaching it are data inodes; misuse with metadata mappings would trip debug builds. The packed bitmap layout depends on `blocks_per_folio` being representable for bitmap operations; diagnostics assert `<= BITS_PER_LONG` when exporting bitmaps. Large-folio metadata support would invalidate several current assumptions.

Test signals: Build all generated helper declarations against implementation macros, cover metadata and data attach/detach, verify fallback behavior when `fs_info` is NULL in selftests, exercise clamped finish-I/O cleanup, inspect dirty bitmap export, and run debug kernels to catch inode-type and alignment assertions.

## sources/distributed-fs/ceph-client/fs/btrfs/super.c

Purpose: Implements Btrfs VFS superblock integration: mount option parsing, fs-context lifecycle, subvolume mounting, remount/reconfigure, sync/statfs/freeze/shutdown operations, `/dev/btrfs-control` ioctls, and module init/exit sequencing. It is the front door from VFS and userspace into Btrfs filesystem state.

Important APIs/types/functions: Core types are `struct btrfs_fs_context`, `btrfs_super_ops`, `btrfs_fs_type`, `btrfs_ctl_fops`, and `mod_init_seq`. Mount parsing is handled by `btrfs_fs_parameters`, `btrfs_parse_param()`, and `btrfs_parse_compress()`. Mount/open flow uses `btrfs_init_fs_context()`, `btrfs_get_tree_subvol()`, `btrfs_get_tree_super()`, `btrfs_fill_super()`, `mount_subvol()`, and `btrfs_kill_super()`. Reconfiguration uses `btrfs_check_options()`, `btrfs_reconfigure()`, `btrfs_remount_rw()`, `btrfs_remount_ro()`, and option copy helpers. Runtime super operations include `btrfs_sync_fs()`, `btrfs_show_options()`, `btrfs_statfs()`, `btrfs_freeze()`, `btrfs_unfreeze()`, `btrfs_remove_bdev()`, and `btrfs_shutdown()`.

Control flow: `btrfs_init_fs_context()` allocates the private context, initializes defaults, and installs fs-context operations. Parameter parsing mutates the context, handling option interactions such as compression disabling nodatacow/nodatasum, nodatacow disabling compression and datasum, rescue aliases, discard modes, free-space-cache versions, ACL flags, device scans, and debug options. `btrfs_get_tree_subvol()` creates a temporary duplicated fs context with a newly initialized `btrfs_fs_info`, gets or creates the real superblock via `sget_fc()`, opens devices and calls `open_ctree()` on first mount, reconfigures a reused read-only superblock if a writable subvolume mount requires it, then mounts the requested subvolume path or object id.

Remount/reconfigure flow: `btrfs_reconfigure()` snapshots old options, synchronizes the filesystem, marks remounting, validates read-only-only rescue options and feature compatibility, applies parsed context into `fs_info`, resizes worker pools, limits free-space-tree toggling to RO-to-RW, transitions RW/RO as needed, updates POSIX ACL flags, emits changed options, wakes the transaction thread, cleans up discard/defrag/free-space-cache side effects, clears one-shot options, and restores old state on failure. `btrfs_remount_ro()` drains reclaim workers, discard, uuid rescan, cleaner, delayed iputs, device replace, scrub, balance, qgroup rescan, and commits the superblock. `btrfs_remount_rw()` rejects error states, missing writable devices, non-degradable profiles, and pending log replay before opening RW state.

State and persistence behavior: The file bridges ephemeral mount context into persistent filesystem state. `open_ctree()` populates on-disk-derived settings; `btrfs_set_free_space_cache_settings()` translates superblock features and user options into active free-space-cache mode, forcing free-space-tree for subpage sector/page mismatches and clearing v1 cache generation on zoned filesystems. `btrfs_sync_fs()` flushes btree mappings for non-wait sync and commits transactions for wait sync. Freeze commits the current transaction and sets `BTRFS_FS_FROZEN`; unfreeze rereads primary device superblocks, validates checksum/fsid/generation, and forces filesystem error state if devices changed while frozen.

Dependencies and integration points: This file integrates with nearly every Btrfs subsystem: disk-io/open-close, transactions, delayed inodes, direct I/O, compression, dev replace, free-space cache/tree, qgroups, scrub, discard, zoned support, raid56, export operations, xattrs, verity, ioctl feature reporting, sysfs, shrinkers, workqueues, and tracepoints. It also depends heavily on VFS fs_context, superblock, mount, dentry, freeze, statfs, miscdevice, and block-device APIs.

Risks: Mount option interactions are user-visible ABI and can regress compatibility, especially deprecated `norecovery/usebackuproot`, empty `subvol=`, and per-subvolume ro/rw behavior under the new mount API. The duplicated fs-context handoff carefully transfers `source`, `fs_info`, and `fs_devices` ownership; mistakes can leak or double-free devices. Reconfigure paths must clear `BTRFS_FS_STATE_REMOUNTING` on every failure, preserve old options, and avoid writes before RW safety checks. Statfs is approximate for mixed RAID and must avoid over-reporting when metadata/global reserve is exhausted. Freeze/unfreeze must detect external modification without preventing VFS thaw.

Test signals: Cover mount option matrix parsing, compression levels and force behavior, nodatacow/nodatasum interactions, device option scanning, rescue options requiring read-only, free-space-cache v1/v2 transitions, zoned mount options, default subvolume lookup, subvol path/id mismatch races, repeated subvolume mounts with different ro/rw mount flags, remount RO and RW failure paths, ACL remount toggling, discard async toggles, statfs on RAID/mixed/metadata-full filesystems, freeze/hibernate-style external modification detection, `/dev/btrfs-control` ioctls, missing-device removal degradability, shrinker callbacks, and module init unwind after partial failure.

## sources/distributed-fs/ceph-client/fs/btrfs/super.h

Purpose: Provides the small public header for Btrfs superblock-facing helpers shared outside `super.c`. It exposes option validation, sync, subvolume-name reconstruction, free-space-cache initialization, and inline accessors for `btrfs_fs_info` and read-only state transitions.

Important APIs/types/functions: Declares `btrfs_check_options()`, `btrfs_sync_fs()`, `btrfs_get_subvol_name_from_objectid()`, and `btrfs_set_free_space_cache_settings()`. Defines `btrfs_sb()` as the canonical cast from `struct super_block` to `struct btrfs_fs_info`. Defines `btrfs_set_sb_rdonly()` and `btrfs_clear_sb_rdonly()` to update both `sb->s_flags` and `BTRFS_FS_STATE_RO` together.

Control flow and state: Callers use `btrfs_sb()` throughout Btrfs superblock operations to reach filesystem-global state. Remount and error paths call the read-only helpers instead of manipulating `SB_RDONLY` alone so VFS-visible state and internal Btrfs state remain synchronized. Mount/open code calls the exported option and free-space-cache helpers from disk-io and reconfigure paths.

State and persistence behavior: The header itself has no persistence, but its read-only helpers gate whether later operations may start write transactions or background cleaners. `btrfs_get_subvol_name_from_objectid()` returns allocated memory or an error pointer, so callers own the returned string. `btrfs_sync_fs()` is the VFS sync bridge that can commit persistent transactions.

Dependencies and integration points: Includes Linux type/fs declarations and `fs.h` for `struct btrfs_fs_info` state bits. It is included by superblock, disk open, mount, and other filesystem code that needs a stable way to validate options or update superblock read-only status.

Risks: Directly setting `sb->s_flags` elsewhere without these helpers can desynchronize `BTRFS_FS_STATE_RO`. The header includes `fs.h`, so dependency cycles must be watched when moving declarations. The exported subvolume-name helper allocates up to `PATH_MAX`; callers must free successful results and handle `ERR_PTR`.

Test signals: Build coverage for all external declarations, remount tests that compare `SB_RDONLY` and `BTRFS_FS_STATE_RO`, sync tests through VFS, subvolume show-options tests that free returned names, and mount-option validation tests for callers outside `super.c`.
