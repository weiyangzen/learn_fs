# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/tc358767.c

Purpose: implements the Toshiba TC358767/TC358867/TC9595 DRM bridge over I2C. The driver supports several hardware topologies selected from device-tree graph ports: DPI input to DP/eDP output, DSI input to DP/eDP output, and DSI input to DPI output. It owns bridge registration, optional connector creation, DP AUX/EDID access, DP/eDP link training, MIPI DSI host attachment for DSI input mode, register access via regmap, HPD handling, GPIO reset/shutdown sequencing, and PLL/video timing programming.

Important APIs/types/functions: `struct tc_data` is the lifetime state object: `regmap`, `drm_dp_aux`, `drm_bridge`, fallback `drm_connector`, optional `panel_bridge`, DSI device, current mode, eDP link data, refclk, GPIOs, HPD pin, and mode flags. `tc_aux_transfer()` implements `drm_dp_aux` transactions through the bridge AUX registers. `tc_pxl_pll_calc()` searches pre/post/div/mul combinations for DPI/eDP pixel PLL programming; `tc_pxl_pll_en()` and `tc_pxl_pll_dis()` apply it. `tc_aux_link_setup()` powers DP PHY/AUX and initializes the AUX adapter. `tc_get_display_props()` reads DPCD caps, clamps rate to 1.62/2.7 Gbps and lanes to at most two, and records downspread/ASSR state. `tc_main_link_enable()` programs source controls, DP PHY, DPCD link settings, two-phase link training, ASSR fallback, and final link-status validation. `tc_set_common_video_mode()`, `tc_set_dpi_video_mode()`, and `tc_set_edp_video_mode()` convert DRM timings into bridge video path, DPI, and DP main-stream registers. The DRM bridge entry points are split between `tc_dpi_bridge_funcs` and `tc_edp_bridge_funcs`.

Control flow: probe first infers the hardware mode from OF graph endpoints (`port@0` DSI input, `port@1` DPI input/output, `port@2` DP/eDP output), allocates a mode-specific bridge, finds an output panel/bridge if present, enables the reference clock, toggles shutdown/reset GPIOs, initializes regmap, configures HPD and IRQ handling, validates the chip ID, performs software reset when no reset GPIO is available, sets GPIO debounce/interrupt bits for HPD, and sets up AUX for DP/eDP outputs. If DSI is an input, it creates and attaches a child `mipi_dsi_device`. During atomic mode check it recalculates the pixel PLL and adjusts the CRTC clock, then rejects clocks above 100 MHz for DSI-to-DPI or 154 MHz for DP/eDP modes. For eDP enable it reads display properties, trains the main link, then starts the stream. For DPI output it sets the stream and enables the DSI receiver without DP link training.

State and persistence: persistent software state is held in `tc_data`: DPCD-derived link rate/lane/spread/scrambler/ASSR values, current adjusted mode, pre-emphasis settings from DT, HPD/IRQ presence, and DSI/DPI input selection. Hardware state persists in bridge registers programmed through regmap, including reset enable bits, DP PHY/PLL/AUX state, DP0 link-training controls, video timing registers, GPIO interrupt debounce, and PPI/DSI lane enables. The regmap uses a maple cache with explicit readable/writeable/volatile/precious tables, big-endian register addresses, and little-endian 32-bit values.

Dependencies and integration points: integrates with DRM bridge, connector, atomic helper, EDID, DP AUX helper, OF graph, DRM panel bridge, MIPI DSI attach APIs, Linux regmap, I2C, clocks, GPIO descriptors, and KMS hotplug helper. DP/eDP output exposes `DRM_BRIDGE_OP_EDID` and optionally detect; when attached without `DRM_BRIDGE_ATTACH_NO_CONNECTOR`, it registers the AUX adapter and creates a DP/eDP connector. MIPI DSI input is configured as RGB888 video burst, low-power capable, non-continuous clock.

Risks: link training is hardware-sensitive and only supports one or two lanes at 1.62 or 2.7 Gbps; higher sink caps are deliberately clamped. `tc_dpi_stream_enable()` appears to return `tc_dsi_rx_enable()` even though it is named DPI output, so topology assumptions need careful review when modifying stream setup. Several DSI RX register writes ignore individual return codes. PLL calculation adjusts the CRTC clock, so mode validation depends on exact refclk and topology. HPD requires correct `toshiba,hpd-pin` and IRQ wiring, otherwise polling or unknown connector status is used. The AUX transfer caps payload to `DP_AUX_MAX_PAYLOAD_BYTES - 1`, and address-only I2C write handling relies on special status interpretation. `tc_edp_mode_valid()` uses cached link values; those must be populated before reliable bandwidth validation.

Test signals: boot/probe for all supported graph topologies; DSI host deferral and attach; DP/eDP EDID read over AUX; HPD interrupt and polling behavior; link training success/failure logs for both phases; ASSR mismatch fallback; mode checks around 100 MHz, 154 MHz, and link bandwidth limits; suspend/remove bridge cleanup; regmap read/write access table coverage; and visual validation with DPI panels, eDP panels, and DP sinks at one- and two-lane link rates.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/tc358768.c

Purpose: implements the Toshiba TC358768/TC358778 DPI-to-DSI bridge as an I2C device that also registers a local MIPI DSI host. It accepts a parallel DPI input, generates a DSI video stream to a downstream DSI panel/bridge, handles panel command transfers while powered, and programs the bridge PLL and D-PHY timing from the active DRM mode.

Important APIs/types/functions: `struct tc358768_priv` stores device/regmap, reset GPIO, three regulators, refclk, enabled/error flags, local `mipi_dsi_host`, DRM bridge, downstream DSI output, input bus width, DSI lane/bpp parameters, PLL dividers, and cached DSI/pixel clocks. `tc358768_write()`, `tc358768_read()`, and `tc358768_update_bits()` wrap mixed-width regmap bulk accesses and accumulate the first error in `priv->error`; `tc358768_clear_error()` returns and clears it. `tc358768_calc_pll()` searches PRD/FBD/FRS values for the target DSI PLL clock. `tc358768_bridge_atomic_pre_enable()` is the main programming routine, deriving DSI byte timings, VSDLY, D-PHY counters, packet mode, data format, and control register state. `tc358768_dsi_host_transfer()` sends short or up-to-8-byte long write packets through `DSICMD_*` registers.

Control flow: I2C probe obtains regulators, refclk, optional reset GPIO, regmap, initializes the DSI host, sets bridge timings, and registers the host. When a downstream DSI device attaches, `tc358768_dsi_host_attach()` validates lanes, video mode, and RGB888 format, finds the downstream panel/bridge on `port@1`, records DSI bpp/lanes, reads the DPI input bus width from `port@0`, adds the DRM bridge, and waits for an upstream encoder to attach. Atomic pre-enable powers clocks/regulators/reset, software-resets the chip, obtains the adjusted mode from atomic state, programs the PLL, converts DPI horizontal timing into DSI byte counts, computes event or pulse mode timing, sets D-PHY counters and lane enables, starts the DSI transmitter, and configures `DSI_CONTROL`. Atomic enable clears frame stop/reset pointer and enables the parallel port; disable stops frame generation, clears PP enable, resets pointers, and post-disable powers the chip off.

State and persistence: `enabled` tracks power state across bridge and host-transfer paths. `error` batches write/read failures during programming so long register sequences can be checked once. PLL fields (`fbd`, `prd`, `frs`, `dsiclk`, `pclk`) persist after calculation and are used for timing conversions. Hardware state includes PLL registers, D-PHY counters, DSI timing registers, command FIFO registers, and PP/DSI control bits. Regmap has no cache and uses big-endian 16-bit register/value formatting, with helper logic treating some register ranges as 32-bit.

Dependencies and integration points: depends on DRM bridge atomic helpers, MIPI DSI host/device APIs, OF graph panel/bridge lookup, regulator bulk APIs, refclk, reset GPIO, regmap over I2C, Linux unit macros, and videomode conversion. It attaches downstream panels through `drm_bridge_attach()` and exposes input bus format based on `bus-width` or `data-lines`.

Risks: non-continuous DSI clock is warned and silently forced to continuous; only RGB888 is accepted in attach even though pre-enable contains switch cases for other formats. Horizontal timing/VSDLY formulas are explicitly heuristic, with comments noting uncertainty and possible underflows. Host transfers fail unless the bridge is currently enabled, which may affect panel command timing. Error aggregation can hide which individual register write failed. Regulator/clock enable failures are logged but `tc358768_hw_enable()` still sets `enabled = true`, so later register programming may proceed after a partial power-up. Mode support depends on exhaustive PLL search and refclk values.

Test signals: DSI host attach deferral; RGB888 video mode attach; command writes before/after enable; PLL calculation around supported clock ranges; event and sync-pulse DSI modes; VSDLY underflow warnings; regulator/refclk/reset sequencing on enable/disable; input bus format negotiation for 16/18/24-bit DPI; and visual stability across panels with short horizontal blanking.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/tc358775.c

Purpose: implements Toshiba TC358765/TC358775 DSI-to-LVDS bridges. The driver attaches to an upstream MIPI DSI host, powers the bridge through regulators and reset/standby GPIOs, programs DSI RX/PPI, video timing, LVDS PHY, LVDS bit mapping, and single/dual-link LVDS output, then attaches a downstream panel bridge.

Important APIs/types/functions: `struct tc_data` stores I2C device, DRM bridge, panel bridge, upstream DSI host node/device, regulator and GPIO handles, lane count, LVDS link mode, bits per component, and chip type. `d2l_read()` and `d2l_write()` implement raw big-endian-address/little-endian-value I2C register access. `tc358775_parse_dt()` reads DSI lane count with an old-DTB fallback to the host endpoint and detects dual-link LVDS by checking whether `LVDS_OUT1` has an available remote. `tc_attach_host()` creates the child DSI device, sets lane count, RGB888 video burst/LPM flags, and chip-specific HS rate. `tc_bridge_atomic_enable()` performs the bridge register programming and LVDS mux selection.

Control flow: probe allocates a DRM bridge, identifies TC358765 versus TC358775 from OF match data, finds the LVDS output panel bridge, parses DT, obtains `vddio`, `vdd`, optional standby GPIO, required reset GPIO, adds the bridge, and attaches to the MIPI DSI host. Atomic pre-enable enables `vddio` then `vdd`, deasserts standby, then releases reset with fixed delays. Atomic enable reads chip ID, resets internal blocks except I2C slave, programs DSI/PPI lane/timing setup, starts PPI and DSI RX, computes DRM timing fields, configures event mode for TC358765 only, selects 8 bpc or 6 bpc/FRC, computes `vsdelay` from DSI/LVDS clock ratios, writes video timing, selects VESA/SPWG or JEIDA LVDS bit mapping from connector bus format, and enables LVDS with divide-by-3 or divide-by-6 clocking. Atomic post-disable asserts reset/standby and disables regulators in reverse order.

State and persistence: software state is mostly static DT-derived state: lane count, chip type, LVDS link count, and `bpc` selected during mode validation from downstream bus format. Hardware state persists in bridge registers until reset or power-down. No regmap cache or detailed software mirror exists; raw I2C helper errors are logged but not propagated through the enable sequence.

Dependencies and integration points: integrates with DRM bridge atomic helpers, MIPI DSI host/device registration, OF graph, `devm_drm_of_get_bridge()`, regulator framework, GPIO descriptors, and media-bus LVDS formats. It exports a bridge with `pre_enable_prev_first = true`, so downstream sequencing is significant. DSI rates are fixed to 800 Mbps for TC358765 and 1 Gbps for TC358775 with a 10 Mbps LP rate.

Risks: `tc_bridge_atomic_enable()` does not propagate most I2C write/read failures, so display programming can silently continue after bus errors. The `vsdelay` math uses 16-bit intermediates and several divisions that depend on lane count, bpc, and link mode; unusual modes may overflow or underflow. `tc->bpc` is set in `mode_valid()` from `info->bus_formats[0]`, so missing or reordered downstream formats can reject or misprogram the mode. Only the first LVDS output bridge is attached even when dual-link is detected; second-link handling is hardware configuration only. Power sequencing uses fixed sleeps.

Test signals: single-link and dual-link panels; TC358765 event-mode bit versus TC358775 behavior; SPWG and JEIDA LVDS bus formats at 6/8 bpc; old and new DT lane-count layouts; mode clocks near 135 MHz and 270 MHz limits; regulator/GPIO failure paths; DSI attach deferral; and I2C bus failure logging during atomic enable.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/tda998x_drv.c

Purpose: implements the NXP TDA998x/TDA1998x HDMI transmitter bridge over I2C. It provides paged HDMI register access, CEC companion setup, HPD and EDID handling, optional connector creation, HDMI mode programming, AVI/vendor infoframes, I2S/SPDIF HDMI audio codec integration, and CEC oscillator calibration through a companion TDA9950-style I2C device.

Important APIs/types/functions: `struct tda998x_priv` contains HDMI/CEC I2C clients, page-access mutex and cached page, revision, audio/EDID/HPD state, video input mux settings, TMDS clock, bridge/connector objects, wait queues, EDID delay timer, detect work, audio codec platform device, audio settings, CEC glue, calibration GPIO, and CEC notifier. `set_page()`, `reg_read_range()`, `reg_write_range()`, `reg_read()`, `reg_write()`, `reg_set()`, and `reg_clear()` serialize the paged register protocol. `tda998x_reset()` performs hardware reset and default PLL/mux setup. `read_edid_block()` drives the chip DDC engine with IRQ or polling completion. `tda998x_bridge_mode_set()` is the core HDMI mode program path, converting DRM timings into transmitter sync/window registers, selecting serializer divisors, setting RGB quantization/color matrix, enabling HDMI/infoframes, and reconfiguring audio if supported. Audio entry points are `tda998x_audio_hw_params()`, `tda998x_configure_audio()`, mute/shutdown/ELD helpers, and `tda998x_audio_codec_init()`.

Control flow: probe checks I2C functionality, allocates the bridge, initializes mutexes/timer/work queues, derives the CEC address from the HDMI I2C address, wakes the device, resets it, reads and validates revision, enables DDC, configures clock and I2C-master quirks, clears interrupts, optionally requests threaded IRQ, registers a CEC notifier and companion TDA9950 client, parses DT video/audio port properties, optionally registers an HDMI codec platform device, sets bridge OF node/type/ops, and adds the DRM bridge. Attach creates a local HDMI-A connector unless the upstream requests `DRM_BRIDGE_ATTACH_NO_CONNECTOR`. HPD IRQ starts a 100 ms EDID delay on connect, schedules hotplug work on disconnect, invalidates CEC physical address, and wakes EDID waiters on block-read completion. Mode-set updates timing, output format, infoframes, and audio under the audio mutex; enable/disable only gate video ports and keep audio controlled separately.

State and persistence: `current_page` avoids redundant page writes and is protected by `mutex`. `is_on` tracks video port enables. `supports_infoframes`, `sink_has_audio`, `rgb_quant_range`, `tmds_clock`, and `audio` persist across mode and audio callbacks. EDID state uses `wq_edid_wait`, an EDID delay timer, wait queues, and workqueue scheduling to avoid DDC reads immediately after HPD. Hardware state includes HDMI timing generator, PLL/serializer, video input mux, matrix/quantization, DDC engine, audio ports/CTS/N/channel status, and CEC clock/calibration registers.

Dependencies and integration points: integrates with DRM bridge, optional DRM connector fallback, EDID helpers, HDMI infoframe helpers, KMS hotplug work, hdmi-codec ASoC glue, CEC notifier, TDA9950 platform data, Linux I2C, IRQ, GPIO, mutex/timer/workqueue/waitqueue APIs, and DT bindings for `video-ports` and `audio-ports`. The bridge exposes EDID, detect, and optional HPD ops; legacy connector helpers call the same EDID path.

Risks: paged register access is non-atomic outside `priv->mutex`; all new register paths must use the helpers. EDID read sequencing is fragile around HPD and signals; `tda998x_edid_delay_wait()` can return no modes if interrupted. Audio depends on sink audio detection and CEA revision; it is configured only when infoframes are supported and `sink_has_audio` is true. Several register writes are fire-and-forget, so failures are logged but not surfaced to atomic callers. CEC calibration disables IRQs and busy-waits with local IRQs off for 10 ms, making GPIO/IRQ correctness important. Mode programming has many timing offsets for interlace, double-clock, HSKEW, and RGB quantization; off-by-one changes can break HDMI sync or color range.

Test signals: supported revision detection for TDA9989/TDA19989/TDA19988 variants; HPD connect/disconnect with and without IRQ; EDID block reads via IRQ and polling; connector and bridge-ops EDID paths; mode clocks above 150/165 MHz rejection; interlaced and double-clock modes; AVI/vendor infoframes; RGB full/limited range selection; I2S and SPDIF codec hw_params/mute/shutdown/ELD; CEC notifier physical address update/invalidation; CEC companion registration and calibration GPIO paths; and remove cleanup for timers, work, IRQ, CEC client, notifier, and audio platform device.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/th1520-dw-hdmi.c

Purpose: provides the T-Head TH1520 platform wrapper for the Synopsys DesignWare HDMI bridge. The file supplies TH1520-specific PHY programming tables, a mode-valid limit, clock/reset acquisition, and `dw_hdmi_probe()` / `dw_hdmi_remove()` integration for the SoC HDMI encoder.

Important APIs/types/functions: `struct th1520_hdmi_phy_params` stores max pixel clock and six PHY register values. `th1520_hdmi_phy_params[]` maps clock ceilings up to 594 MHz to PHY opmode, PLL current, divider, clock-symbol, voltage, and termination settings. `struct th1520_hdmi` stores `dw_hdmi_plat_data`, `dw_hdmi` handle, pixel clock, and main/APB resets. `th1520_hdmi_mode_valid()` rejects modes above 594 MHz. `th1520_hdmi_phy_set_params()` writes the PHY I2C registers through DesignWare helper APIs. `th1520_hdmi_phy_configure()` selects the first table row whose max clock covers the requested pixel clock.

Control flow: probe allocates the wrapper, enables the `pix` clock, obtains and deasserts `main` and `apb` resets, fills `dw_hdmi_plat_data` with output port 1, mode-valid callback, PHY configuration callback, and private data, calls `dw_hdmi_probe()`, and stores driver data. Remove retrieves driver data and calls `dw_hdmi_remove()`.

State and persistence: persistent state is minimal: the enabled clock and deasserted reset controls are devm-managed, and the `dw_hdmi` pointer represents the registered DesignWare HDMI instance. PHY register values persist in hardware until reconfigured or reset. No mode or connector state is stored by this wrapper.

Dependencies and integration points: depends on the DRM `dw_hdmi` bridge library, platform devices, managed clocks, reset controls, OF compatible `thead,th1520-dw-hdmi`, and the DesignWare PHY I2C write API. Most HDMI protocol, connector, EDID, and atomic behavior is delegated to the shared DesignWare HDMI implementation.

Risks: the probe error check after `dw_hdmi_probe()` tests `IS_ERR(hdmi)` instead of the returned `hdmi->dw_hdmi`, which can miss a failed DesignWare probe and store an error pointer. Remove retrieves driver data as `struct dw_hdmi *`, but probe stores `struct th1520_hdmi *`, so `dw_hdmi_remove()` may receive the wrong pointer type. PHY table selection is ceiling-based and must remain sorted by `mpixelclock`. Clocks below the first table entry use the 35.5 MHz row; clocks above 594 MHz are rejected by mode validation and by PHY configure fallback.

Test signals: platform probe/remove on TH1520 DT; failure injection for `pix` clock, `main` reset, `apb` reset, and `dw_hdmi_probe()`; 594 MHz mode acceptance and higher-clock rejection; PHY register writes for common CEA modes; and runtime remove/unbind to catch driver-data pointer type issues.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/thc63lvd1024.c

Purpose: implements a simple platform DRM bridge for the Thine THC63LVD1024 LVDS-to-parallel RGB decoder. It discovers the downstream RGB bridge, detects single- versus dual-link LVDS input from OF graph wiring, controls one regulator and optional powerdown/output-enable GPIOs, and enforces the chip pixel clock range.

Important APIs/types/functions: `struct thc63_dev` stores device, `vcc` regulator, optional `pdwn` and `oe` GPIOs, DRM bridge, and bridge timings. `thc63_parse_dt()` finds the downstream bridge from RGB output port 2 and detects dual-link input if LVDS input port 1 has an available remote device. `thc63_mode_valid()` applies 8-135 MHz limits for single-link input and 40-150 MHz for dual-link input. `thc63_enable()` enables the regulator, deasserts powerdown, and enables output. `thc63_disable()` reverses output enable, powerdown, and regulator state.

Control flow: probe allocates the bridge, obtains `vcc`, optional GPIOs, parses graph links, fills bridge private/timing/OF fields, and adds the bridge. Attach chains to `bridge.next_bridge`. Enable/disable are non-atomic legacy bridge callbacks that perform only power and GPIO operations; the chip has no register interface in this driver.

State and persistence: `timings.dual_link` is the main persistent software state and is exposed through `bridge.timings`. Hardware state is only regulator and GPIO level state. There is no runtime cache, no mode storage, and no remove-time power cleanup beyond bridge removal.

Dependencies and integration points: depends on platform driver/OF graph, DRM bridge, `of_drm_find_and_get_bridge()`, regulator consumer API, and GPIO descriptors. Downstream output integration is through a single `next_bridge` on RGB output port 2.

Risks: optional GPIOs may be absent; `gpiod_set_value()` tolerates NULL descriptors, but board power sequencing must be valid without them. The driver only supports one downstream output and derives dual-link input solely from the availability of LVDS input port 1. Dual-in/dual-out mode is explicitly not supported; mode limits are derived only from input mode. Enable errors after regulator failure leave the bridge disabled without retry state.

Test signals: probe deferral until downstream bridge is available; single-link and dual-link DT topologies; mode validation at 8/40/135/150 MHz boundaries; regulator enable/disable failure logging; GPIO polarity validation for `oe` and `powerdown`; attach chaining to downstream panel/bridge; and unbind while disabled/enabled.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/ti-dlpc3433.c

Purpose: implements a TI DLPC3433 MIPI DSI display-controller bridge. It powers the controller, attaches to an upstream DSI host and downstream bridge, programs DLPC command registers over I2C/regmap for DSI external video, image size/crop/display size, LED enablement, and exposes RGB888 input bus negotiation to DRM.

Important APIs/types/functions: `struct dlpc` stores device, DRM bridge, next bridge, DSI host node/device, current mode, enable GPIO, interface/flash regulators, regmap, and DSI lane count. The command register enum names the controller commands such as input source, external format, image crop, RGB LED enable, DSI clock, and port enable. `dlpc_atomic_pre_enable()` asserts the enable GPIO, waits for boot, enables regulators, and delays before register access. `dlpc_atomic_enable()` verifies device ID, freezes image, enables DSI port, writes crop/display/input image size with no-increment regmap writes, selects external DSI video, unfreezes image, and enables RGB LEDs. `dlpc3433_parse_dt()` obtains GPIO/regulators, downstream bridge, DSI data-lane count, and upstream host node. `dlpc_host_attach()` registers and attaches a child DSI device.

Control flow: probe allocates the bridge, initializes regmap, parses DT, records client data, adds the bridge, and attaches to the MIPI DSI host. The host attach path creates a DSI peripheral with burst mode, RGB565 format, and DT-derived lane count. `mode_set()` stores the adjusted mode used later by `dlpc_atomic_enable()`. Attach chains the bridge to `next_bridge`. Post-disable disables flash and interface regulators, delays, and lowers the enable GPIO.

State and persistence: persistent state includes the stored adjusted mode, DSI lane count, host node reference until remove, DSI device pointer, and regulator/GPIO handles. Regmap uses a maple cache with 8-bit command/value registers and marks 0x10-0xbf volatile; no-increment writes are enabled for multi-byte command payloads. Hardware state includes input source, DSI port state, image geometry, freeze state, and LED enable bits.

Dependencies and integration points: integrates with DRM bridge atomic helpers, OF graph, `devm_drm_of_get_bridge()`, MIPI DSI, regmap over I2C, GPIO, regulators, media bus formats, and downstream bridge chaining. It expects DSI input on graph port 0 and downstream output on port 1.

Risks: host attach configures `MIPI_DSI_FMT_RGB565` while the bridge bus-format callback advertises RGB888 input, a potential format mismatch for upstream negotiation. `of_property_count_u32_elems()` returns a signed error but is assigned to unsigned `dsi_lanes`, so the subsequent `< 0` check is ineffective; invalid lane properties may be mishandled. `err_put_host` calls `of_node_put(dlpc->host_node)` when host-node acquisition failed and the pointer may be NULL, which is harmless but indicates fragile cleanup. Device ID mismatch in atomic enable logs and returns without powering down. Most regmap writes are unchecked, so command failures are not reported to DRM.

Test signals: DSI host deferral and lane-count parsing, including malformed `data-lanes`; downstream bridge attach; device ID readback; power-up delays and regulator/GPIO polarity; geometry writes for multiple modes; RGB565 versus RGB888 pipeline behavior; no-increment write payload correctness; and remove cleanup of `host_node`.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/ti-sn65dsi83.c

Purpose: implements TI SN65DSI83 and SN65DSI84 DSI-to-LVDS bridges. The driver attaches to an upstream MIPI DSI host, attaches a downstream LVDS panel bridge, programs the bridge PLL, DSI/LVDS format/timing registers, supports single-link and SN65DSI84 dual-link LVDS, configures LVDS termination and voltage swing from DT, and monitors link errors through IRQ or polling with automatic pipe reset.

Important APIs/types/functions: `struct sn65dsi83` stores DRM bridge, device/regmap, DSI device, panel bridge, enable GPIO, vcc regulator, dual-link flags, per-channel VOD/termination configuration, IRQ, delayed monitor work, and reset work. `sn65dsi83_get_lvds_range()`, `sn65dsi83_get_dsi_range()`, and `sn65dsi83_get_dsi_div()` compute register encodings from mode clock, format bpp, lanes, and dual-link state. `sn65dsi83_atomic_pre_enable()` powers the chip, deasserts reset, reads bridge-state bus format, writes PLL/DSI/LVDS/video timing registers, waits for PLL lock, triggers soft reset, and registers a devm cleanup action. `sn65dsi83_atomic_enable()` clears startup IRQ status and enables IRQ or polling. `sn65dsi83_handle_errors()` reads IRQ status, ignores known noisy PLL-unlock-only reports, disables IRQ if needed, and schedules `sn65dsi83_reset_work()` to reset the DRM pipe. `sn65dsi83_parse_dt()` handles LVDS endpoint properties and dual-link pixel order.

Control flow: probe allocates the bridge, initializes work items, detects model from OF or I2C ID, obtains optional enable GPIO and holds reset low, parses LVDS/panel/regulator DT, initializes regmap, optionally requests IRQ, adds the bridge with LVDS connector type and `pre_enable_prev_first`, then registers and attaches a child DSI device from input port 0. Atomic pre-enable programs clocks and timing from the adjusted CRTC mode and output bus config; atomic enable activates runtime error detection. Atomic disable releases the pre-enable devm action, which disables IRQ or polling, lowers enable, disables the regulator, and marks regcache dirty.

State and persistence: DT-derived persistent state includes dual-link mode, even/odd channel swap, LVDS termination, and VOD swing values. Runtime hardware state includes PLL enable/lock, DSI lane/range/divider, LVDS format/termination/swing, video timing, IRQ enables, and reset state. Error monitoring state is held in delayed work or IRQ and reset work; bridge enter/exit is used to avoid races with unplug/removal. Regmap uses maple caching with readable/writeable/volatile tables and marks cache dirty on power-down.

Dependencies and integration points: depends on DRM bridge atomic helpers, DRM bridge reset helper, MIPI DSI, OF graph/LVDS dual-link helpers, regmap, regulator, GPIO, workqueues, IRQs, and media bus formats. DSI host attach configures RGB888 video burst with omitted HFP/HBP/HSA and no EOT packets. The downstream LVDS panel bridge is acquired from port 2.

Risks: the VOD swing selector compares table min/max against requested ranges in a way that appears inverted for common "range contains candidate" semantics; DT validation should be checked with real bindings. `sn65dsi83_parse_lvds_endpoint()` calls property readers on an endpoint pointer that can be NULL if the channel endpoint is missing. Pre-enable always calls `devm_add_action()` even after PLL-lock failure, so cleanup is registered for partial setup. IRQ/poll reset deliberately resets the whole CRTC pipe and may be disruptive under intermittent link errors. SN65DSI85 and two-single-link LVDS modes are not supported. The driver ignores PLL unlock-only status because known hardware can report it while working.

Test signals: SN65DSI83 single-link and SN65DSI84 dual-link panels; SPWG24, JEIDA24, and SPWG18 bus formats; dual-link odd/even and even/odd pixel order; LVDS termination/VOD DT property combinations; PLL lock timeout handling; IRQ and polling error recovery; noisy PLL-unlock-only systems; mode clock limits 25-154 MHz; DSI lane counts and host attach deferral; and runtime unplug/remove with delayed work pending.
