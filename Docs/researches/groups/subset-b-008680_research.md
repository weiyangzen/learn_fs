# Research: sources/storage-engines/rocksdb/table/cuckoo/cuckoo_table_reader.cc

- **Purpose:** Implements `CuckooTableReader`, a mmap-only `TableReader` for RocksDB cuckoo table SSTs, plus its file-local `CuckooTableIterator`. The reader reconstructs fixed-size bucket layout from table properties, performs point lookups by hashing the user key into cuckoo buckets, prefetches a first cuckoo block for batched reads, and exposes sorted iteration over occupied buckets.
- **Important APIs/types/functions:** `CuckooTableReader::CuckooTableReader`, `Get`, `Prepare`, `NewIterator`, `ApproximateMemoryUsage`; file-local constants `CACHE_LINE_MASK`, `kInvalidIndex`; file-local `CuckooTableIterator` with `SeekToFirst`, `SeekToLast`, `Seek`, `Next`, `Prev`, `PrepareKVAtCurrIdx`; `BucketComparator` for sorting bucket ids by user key.
- **Control flow:** Construction rejects non-mmap reads, calls `ReadTableProperties`, extracts cuckoo-specific user properties (`num_hash_func`, empty key, user/value length, hash table size, last-level flag, hash behavior, cuckoo block size), computes bucket sizes, then reads the whole file into `file_data_`. `Get` asserts the incoming key length, extracts the user key, probes each hash candidate and each bucket inside the cuckoo block, stops on an unused bucket, and saves matching values through `GetContext`. Iterator initialization scans all buckets, filters non-empty buckets, sorts bucket ids by comparator order, and then movement methods update cached `IterKey`/value slices from the mmap image.
- **State and persistence behavior:** The reader owns `RandomAccessFileReader`, `TableProperties`, status, property-derived layout fields, comparator/hash callbacks, and an mmap-backed `Slice file_data_`. It does not persist new data; it reads table metadata and the full SST contents once during construction. Returned slices point into `file_data_` or iterator-owned `IterKey` storage. `ApproximateMemoryUsage` returns zero even though the mapping and property objects exist.
- **Dependencies:** Depends on `CuckooHash` and property names from cuckoo table factory/builder code, `ReadTableProperties` from meta block support, `GetContext` for DB point lookup state, `ParsedInternalKey` helpers from dbformat, `InternalIterator`, `Arena`, and platform `PREFETCH`/cache-line constants.
- **Integration points:** Created by cuckoo table factory readers and used by table cache/DB Get paths through the `TableReader` interface. The `Get` path integrates with `GetContext::SaveValue` for both last-level user-key-only cuckoo entries and internal-key entries. `NewIterator` returns either heap-allocated or arena-allocated internal iterators for DB iterators/compaction callers.
- **Risks:** The implementation uses `reinterpret_cast` directly on user property string data, so malformed or unaligned properties can cause undefined behavior before corruption is detected. It assumes mmap data remains valid and reads the whole file, which is unsuitable for non-mmap or very large tables. `Get` relies on an assert for key length and can index into `file_data_` without explicit bounds checks if metadata is corrupt. Last-level files use `kMaxSequenceNumber`, which is explicitly risky for TransactionDB locking. `SeekForPrev` is unsupported and asserts false. Iterator initialization assumes bucket count fits `uint32_t` and that non-empty bucket count equals table property `num_entries`.
- **Test signals:** Covered by `cuckoo_table_reader_test.cc` for mmap rejection, found/not-found point lookups, collisions, last-level keys, bytewise and uint64 comparators, forward/reverse/seek iteration, arena iterator destruction, and optional read-performance paths. Corruption paths for missing properties are visible in construction but not directly exercised in the listed test file.

# Research: sources/storage-engines/rocksdb/table/cuckoo/cuckoo_table_reader.h

- **Purpose:** Declares `CuckooTableReader`, the `TableReader` implementation for fixed-size cuckoo table SST files.
- **Important APIs/types/functions:** Constructor accepting immutable options, a `RandomAccessFileReader`, file size, user comparator, and optional hash callback; overrides `GetTableProperties`, `Get`, `NewIterator`, `Prepare`, `ApproximateMemoryUsage`, `ApproximateOffsetOf`, `ApproximateSize`, and `SetupForCompaction`; exposes `status()`.
- **Control flow:** The header establishes the object contract: callers construct the reader and must inspect `status()`, then use normal `TableReader` entry points. Unsupported estimation/compaction hooks are implemented as inert methods returning zero or doing nothing. `CuckooTableIterator` is a friend so the implementation can access private layout and mmap fields.
- **State and persistence behavior:** Private fields hold the file reader, mmap slice, table status, table properties, cuckoo layout flags, fixed key/value/bucket lengths, table size, comparator, and hash callback. No write persistence is exposed; all state describes an already-built table.
- **Dependencies:** Includes RocksDB file/env/options APIs and `table/table_reader.h`; forward-declares `Arena`, `TableReader`, and `ImmutableOptions`.
- **Integration points:** Used by cuckoo table factory code to instantiate a table reader and by tests to construct readers directly. It conforms to the shared `TableReader` interface consumed by table cache, DB point lookups, and internal iteration.
- **Risks:** The public API exposes only `status()` rather than throwing or factory-returning errors, so callers must remember to check construction status before use. Approximate offset/size are placeholders, so features depending on size estimation get no useful cuckoo-table signal. The private `LoadAllKeys` declaration has no implementation in this file set, suggesting stale API surface.
- **Test signals:** Directly included by `cuckoo_table_reader_test.cc`, which checks construction status and exercises `Get`, `Prepare`, and `NewIterator` through this declaration.

# Research: sources/storage-engines/rocksdb/table/external_table.cc

- **Purpose:** Adapts the public `ExternalTableFactory`, `ExternalTableReader`, `ExternalTableIterator`, and `ExternalTableBuilder` extension interfaces to RocksDB's internal `TableFactory`, `TableReader`, `InternalIterator`, and `TableBuilder` contracts.
- **Important APIs/types/functions:** `NewExternalTableFactory`; file-local adapters `ExternalTableFactoryAdapter`, `ExternalTableReaderAdapter`, `ExternalTableIteratorAdapter`, `ExternalTableBuilderAdapter`; metrics wrappers `ExternalTableMetricsFileSystem` and `ExternalTableMetricsRandomAccessFile`; helper `GetExternalTableFileReadHistogram`.
- **Control flow:** Reader creation rejects ingested files with positive sequence numbers and user-defined timestamps, optionally wraps the filesystem for statistics/listener instrumentation, then asks the inner external factory to open a reader by file name. Iterators convert internal seek targets to parsed user keys and rewrap external user keys as internal value keys with sequence zero. Point `Get` parses the internal key, calls the external reader by user key, maps NotFound to OK/no value, and saves a found value into `GetContext`. Builder creation wraps `WritableFileWriter` as an `FSWritableFile`, parses internal keys in `Add`, rejects non-value records, forwards user-key/value pairs to the external builder, collects table properties, and writes a properties block before `Finish` when supported.
- **State and persistence behavior:** The adapters hold unique ownership of external readers/builders/iterators and a writable-file wrapper. Builder state accumulates `TableProperties`, raw key/value sizes, collector outputs, file checksum information from the external builder, and status. Metrics wrappers do not persist table data but record histogram/ticker stats and notify listeners for each read.
- **Dependencies:** Depends on `rocksdb/external_table.h`, internal key parsing, listener/statistics APIs, block property parsing, property block builder, table builder/reader abstractions, `GetContext`, and `ReifyDbHostIdProperty` from `format.cc`.
- **Integration points:** Used when `NewExternalTableFactory` wraps a plugin-style external table implementation for flush, ingestion, reads, iteration, and property reporting. It bridges RocksDB's sequence-numbered internal key model to external user-key-only tables with sequence zero and value-only support.
- **Risks:** External tables do not support nonzero sequence numbers, timestamps, deletes, merges, blob indexes, or wide-column entities in this adapter. `Clone()` returns null, which can surprise code expecting cloneable factories. `GetTableProperties` falls back to minimal copied properties if raw property block retrieval fails, losing some exact metadata. Metrics `MultiRead` reports one shared start/finish timestamp for all requests. `ExternalTableBuilderAdapter::Finish` returns the external finish status but does not assign it to `status_`, so subsequent `status()` relies on the inner builder. The not-supported message for value type lacks a space before "not supported".
- **Test signals:** No direct test file is listed here. Indirect signals should come from external table factory tests, ingestion tests, table property validation, listener/statistics assertions, and DB Get/iterator behavior over externally built SSTs.

# Research: sources/storage-engines/rocksdb/table/format.cc

- **Purpose:** Implements shared SST table-format primitives: block handle/index value encoding, footer build/decode/read logic, checksum helpers, decompression helpers, detailed-time decisioning, unsupported-format test hook, and DB host id reification.
- **Important APIs/types/functions:** `ShouldReportDetailedTime`; `BlockHandle::{EncodeTo,DecodeFrom,DecodeSizeFrom,ToString}`; `IndexValue::{EncodeTo,DecodeFrom,ToString}`; `FooterBuilder::Build`; `Footer::DecodeFrom`, `Footer::ToString`; `TEST_AllowUnsupportedFormatVersion`; `ReadFooterFromFile`; `ComputeBuiltinChecksum`, `ComputeBuiltinChecksumWithLastByte`; `DecompressBlockData`, `DecompressSerializedBlock`; `ReifyDbHostIdProperty`.
- **Control flow:** Block handles encode/decode varint offset/size pairs. Index values optionally delta-encode block sizes relative to a previous block and optionally include a first key. Footer building lays out legacy/versioned footer parts, handles format >= 6 extended magic, base context checksum, metaindex size, reserved padding, and footer checksum. Footer decoding detects legacy magic, rejects old block-based magic, validates enforced magic/version/checksum type, verifies extended magic and contextual checksum for v6+, reconstructs metaindex handles, and decodes legacy handles for older formats. Footer reads verify the open-file size, read the tail via prefetch/direct/non-direct paths, decode, and optionally retry with `verify_and_reconstruct_read` on supported filesystems after corruption. Decompression extracts uncompressed size, allocates normal or read-scoped buffers, decompresses, records stats/perf counters, and exposes sync points.
- **State and persistence behavior:** Functions are mostly stateless except for `TEST_AllowUnsupportedFormatVersion` static bool and output objects. Footer encode/decode defines durable SST tail metadata. `BlockContents` outputs own or reference block bytes. `ReifyDbHostIdProperty` may replace `"__hostname__"` in table properties with the environment hostname or clear it on error.
- **Dependencies:** Uses file readers, prefetch buffers, filesystem size helpers, block-based table trailer constants, persistent cache helpers, compression/decompressor APIs, CRC32C/xxHash/XXH3, statistics/perf counters, coding utilities, `unique_id_impl`, and string/status utilities.
- **Integration points:** Called by all table readers/builders that need block handles, footers, checksums, decompression, and table property host identifiers. Cuckoo and plain table support is represented in magic/version checks even though most block/trailer logic is block-based-table specific.
- **Risks:** Many invariants are enforced with asserts, so release builds rely on callers and file validation to prevent impossible states. Footer v6+ assumes metaindex adjacency and <4GB metaindex size. `ComputeBuiltinChecksumWithLastByte` allocates xxHash streaming state for some checksum types. Decompression asserts that serialized block trailers agree with the supplied compression type. Filesystem-size mismatch returns corruption, which is correct for DB-open manifest validation but sensitive to stale metadata. `BlockContents::usable_size` FIXME notes it does not account for trailers.
- **Test signals:** Expected coverage comes from format/footer/block checksum/decompression tests elsewhere. This file provides sync points for footer input and decompression tampering and stats counters for corruption retry and decompression.

# Research: sources/storage-engines/rocksdb/table/format.h

- **Purpose:** Declares core SST table-format data structures and helpers shared by RocksDB table implementations.
- **Important APIs/types/functions:** Magic constants; `ReadScopedBlockBufferProviderRef`; `ShouldReportDetailedTime`; `BlockHandle`; `EncodedBlockHandle`; `IndexValue`; `ChecksumModifierForContext`; format-version predicates; `Footer`; `FooterBuilder`; `TEST_AllowUnsupportedFormatVersion`; `ReadFooterFromFile`; checksum functions; `BlockContents`; decompression overloads; `ReifyDbHostIdProperty`.
- **Control flow:** The header codifies supported read/write format versions for block-based, plain, and cuckoo tables; whether versions use context checksums, footer index handles, and compression manager names; and how callers pass footer/read/decompression arguments. Inline constructors and helpers provide cheap block-handle initialization and context checksum modifiers.

# Research: sources/storage-engines/rocksdb/table/get_context.cc

- **Purpose:** Implements `GetContext`, the point-lookup state machine used by table readers to report found values, deletions, merge operands, blob indexes, wide-column entities, timestamps, replay logs, sequence numbers, and cache/stat counters.
- **Important APIs/types/functions:** Constructors; `appendToReplayLog`; `MarkKeyMayExist`; wide-column helpers `SaveWideColumnEntityToPinnable`, `SaveWideColumnEntityToColumns`, `PushWideColumnEntityDefaultOperand`; `SaveValue` overloads; `ReportCounters`; merge helpers `PostprocessMerge`, `MergeWithNoBaseValue`, `MergeWithPlainBaseValue`, `MergeWithWideColumnBaseValue`; `GetBlobValue`; `push_operand`; `replayGetContextLog`.
- **Control flow:** A table reader calls `SaveValue` for candidate internal keys. The parsed-key overload first checks user-key equality without timestamps and read-callback visibility, records sequence/timestamp state, logs replay entries, folds range tombstones into effective type when applicable, then switches on value type. Plain values, preferred-seqno values, blob indexes, and wide-column entities either populate `PinnableSlice`/`PinnableWideColumns`, append operands for `GetMergeOperands`, or merge with existing operands. Deletions stop lookup as deleted or trigger merge with no base. Merge records push operands and may eagerly full-merge when the merge operator says so. Blob and wide-column paths resolve external blobs when a fetcher is available and convert incomplete IO into key-may-exist state. Replay log decoding rebuilds synthetic internal keys and feeds them back through `SaveValue` until terminal.
- **State and persistence behavior:** `GetContext` mutates `state_`, optional output value/columns, timestamp, sequence, blob-index flag, value-found flag, replay log, merge context, pinned iterator manager, and per-get stats. It does not persist to disk, but replay logs can be stored in row cache and replayed into another context.
- **Dependencies:** Depends on blob fetcher/index, merge helper/operator, pinned iterators, read callbacks, wide-column serialization/helpers, perf/statistics, file-read sampling, system clock, and DB internal key/value-type helpers.
- **Integration points:** Table readers call `SaveValue` during point lookup; table cache/block cache call `MarkKeyMayExist` for no-IO uncertainty; DB Get, MultiGet, GetEntity, GetMergeOperands, row cache replay, blob DB, and wide-column APIs consume its state and outputs.
- **Risks:** Many correctness invariants are assert-only, including timestamp sizing, expected state transitions, non-null merge context for merges, and replay decode success. The simplified `SaveValue(Slice, seq)` assumes no timestamps and put-only data. Blob-backed wide columns require a blob fetcher or return corruption/incomplete. `GetBlobValue` has an explicit FIXME for untested incomplete-IO handling. Merge and timestamp behavior is subtle around range tombstones, callbacks, and `do_merge_`. Replay logs use asserts for parsing rather than returning corruption on malformed logs.
- **Test signals:** Expected signals include DB Get/MultiGet, merge-operator, blob, wide-column, timestamp, row-cache replay, and cache-stat tests elsewhere. This file exposes sync points for simple save and pin-self behavior.

# Research: sources/storage-engines/rocksdb/table/internal_iterator.h

- **Purpose:** Defines `InternalIteratorBase<TValue>`, the internal iterator abstraction used throughout RocksDB table, merging, level, and DB iterator code, plus factory declarations for empty/error internal iterators.
- **Important APIs/types/functions:** `InternalIteratorBase<TValue>` virtual interface; `SetRangeDelReadSeqno`, `Valid`, seek methods, `Next`, `NextAndGetResult`, `Prev`, `key`, `user_key`, `value`, `status`, `PrepareValue`, bound-check methods, pinning methods, `GetProperty`, readahead transfer methods, `IsDeleteRangeSentinelKey`, `Prepare(MultiScanArgs)`, protected `SeekForPrevImpl`; aliases/factories `InternalIterator`, `NewEmptyInternalIterator`, `NewErrorInternalIterator`.
- **Control flow:** Implementations expose cursor movement and value preparation. Default `NextAndGetResult` calls `Next`, then fills an `IterateResult` with key, unknown upper-bound status, and unprepared value. `SeekForPrevImpl` provides a generic seek-then-back-up implementation for comparators.
- **State and persistence behavior:** The base class stores no cursor state; concrete iterators own state and backing storage. It inherits `Cleanable`, allowing iterators to register cleanup callbacks and pin resources. Readahead state can be extracted and restored across file-boundary iterator switches.
- **Dependencies:** Depends on internal key formatting, readahead file info, advanced iterator result/bound types, comparator, public iterator/status APIs, and table format `IndexValue`.
- **Integration points:** Base type for table readers, block iterators, merging iterators, range tombstone iterators, level iterators, external/cuckoo adapters, and empty/error iterators. The `IndexValue` template specialization is used by index iterators.
- **Risks:** The interface has many optional methods with conservative defaults; performance-sensitive iterators should override `NextAndGetResult`, `PrepareValue`, and bound checks when possible. `user_key()` assumes keys are internal keys by default. Callers must respect `PrepareValue` before `value()` when unprepared values are allowed.
- **Test signals:** Iterator tests should cover forward/reverse seeks, invalid status propagation, value preparation, bound checks, pinned key/value flags, readahead transfer, delete-range sentinels, multi-scan prepare, and empty/error factories.

# Research: sources/storage-engines/rocksdb/table/iter_heap.h

- **Purpose:** Provides comparator functors for using `IteratorWrapper*` entries in `std::priority_queue` heaps for merging iterators.
- **Important APIs/types/functions:** `MaxIteratorComparator` and `MinIteratorComparator`, each constructed with an `InternalKeyComparator` and implementing `operator()(IteratorWrapper* a, IteratorWrapper* b)`.
- **Control flow:** The max comparator returns true when `a` is smaller than `b`, causing the largest key to be on top. The min comparator returns true when `a` is larger than `b`, causing the smallest key to be on top.
- **State and persistence behavior:** Each comparator stores only a raw pointer to the `InternalKeyComparator`; no persistent state or ownership is involved.
- **Dependencies:** Depends on internal key comparison from `db/dbformat.h` and cached iterator access through `IteratorWrapper`.
- **Integration points:** Used by `MergingIterator`-style code to select the next child iterator in forward or reverse order while merging multiple sorted sources.
- **Risks:** Assumes input wrappers are valid and positioned; `IteratorWrapper::key()` asserts validity. Comparator lifetime must outlive heaps using it. Tie behavior is delegated entirely to `InternalKeyComparator`.
- **Test signals:** `merger_test.cc` indirectly exercises min/max heap behavior through merged forward and reverse iteration equivalence against a single sorted vector iterator.

# Research: sources/storage-engines/rocksdb/table/iterator_wrapper.h

- **Purpose:** Defines `IteratorWrapperBase<TValue>`, a lightweight cache around an `InternalIteratorBase` pointer that stores the latest validity, key, bound-check result, and value-prepared flag to reduce virtual calls and improve locality.
- **Important APIs/types/functions:** Constructors, `Set`, `DeleteIter`, `Valid`, `key`, `value`, `status`, `PrepareValue`, movement methods, `NextAndGetResult`, bound/pinning/readahead/sentinel/multi-scan forwarding, private `Update`, aliases `IteratorWrapper`, and arena declaration `NewEmptyInternalIterator(Arena*)`.
- **Control flow:** `Set` swaps the underlying iterator and updates cached state. Movement methods forward to the child iterator, then either use `NextAndGetResult` or call `Update` to refresh cached validity/key/bound/value-prepared state. `PrepareValue` forwards only once per movement and refreshes cached key if value preparation succeeds. `DeleteIter` deletes or manually destructs the child depending on arena mode and can enforce status-checked-after-invalid assertions under `ROCKSDB_ASSERT_STATUS_CHECKED`.
- **State and persistence behavior:** Stores a non-owning/owning-by-convention iterator pointer, cached `IterateResult`, validity flag, and optional debug status-check flag. It persists no table data and relies on the underlying iterator for cleanup registration and resource ownership.
- **Dependencies:** Depends on `InternalIteratorBase`, `IterateResult`, sync/test point infrastructure, readahead state, pinning manager, and `MultiScanArgs`.
- **Integration points:** Used by merging iterators and other iterator orchestration code to avoid repeated virtual calls to `Valid()`/`key()`. `iter_heap.h` comparators operate on `IteratorWrapper*`.
- **Risks:** Wrapper validity can become stale if the underlying iterator is mutated outside the wrapper. `DeleteIter` must be called with the correct arena flag. Many methods assert `iter_` or `Valid()`, so misuse is fatal in debug builds and undefined in release. `PrepareValue` assumes child invalidates itself and sets non-OK status on failure.
- **Test signals:** Indirectly covered by merging iterator tests, table iterator tests, and debug builds with status-check assertions. Value-preparation and upper-bound caching need dedicated iterator tests in implementations that support them.

# Research: sources/storage-engines/rocksdb/table/merger_test.cc

- **Purpose:** Tests `NewMergingIterator` by comparing merged output from many child `VectorIterator`s against a single `VectorIterator` over the same accumulated keys.
- **Important APIs/types/functions:** Test fixture `MergerTest`; helpers `GenerateStrings`, `AssertEquivalence`, `SeekToRandom`, `Seek`, `SeekToFirst`, `SeekToLast`, `Next`, `Prev`, `NextAndPrev`, `Generate`; tests `SeekToRandomNextTest`, `SeekToRandomNextSmallStringsTest`, `SeekToRandomPrevTest`, `SeekToRandomRandomTest`, `SeekToFirstTest`, `SeekToLastTest`.
- **Control flow:** `Generate` creates random internal keys per child iterator, stores all keys, builds a merging iterator over child iterators, and builds one vector iterator over all keys. Tests seek both iterators to identical targets or endpoints, then step forward, backward, or randomly while `AssertEquivalence` compares validity, key, and value after each movement.
- **State and persistence behavior:** Fixture owns comparator, deterministic random generator, unique pointers to the merging and reference iterators, and accumulated key strings. No filesystem or durable state is used.
- **Dependencies:** Depends on `table/merging_iterator.h`, RocksDB test harness, `VectorIterator`, `Random`, and internal key encoding/comparison.
- **Integration points:** Indirectly validates `IteratorWrapper`, `iter_heap` comparators, and merging iterator child selection across many sorted internal sources.
- **Risks:** `all_keys_` is appended in generation order and relies on `VectorIterator` to sort or otherwise interpret the input consistently; if `VectorIterator` semantics change, the oracle may weaken. Random keys can duplicate, so comparator tie handling is exercised but not explicitly reasoned about. The test stresses movement counts but does not inject child iterator errors or unprepared values.
- **Test signals:** Assertions compare merged/reference validity, key, and value for large fan-in forward scans, reverse scans, endpoint seeks, random seeks, small-key collision-prone strings, and mixed next/prev movement. `main` installs stack tracing and runs all gtests.
