## sources/distributed-fs/ceph-client/drivers/net/ethernet/emulex/benet/be_main.c

Purpose: this is the main PCI/netdev implementation for the Emulex/Broadcom be2net Ethernet driver covering BE2, BE3, Lancer, and Skyhawk adapters. It owns PCI probe/remove, BAR mapping, firmware initialization, netdev registration, queue allocation, interrupt/NAPI handling, TX/RX data paths, filtering, SR-IOV VF policy, VXLAN offloads, statistics, suspend/resume, PCI error recovery, and integration with the companion RoCE driver.

Important APIs, types, and functions: the exported/runtime-facing entry points are the `pci_driver` callbacks (`be_probe`, `be_remove`, suspend/resume, shutdown, EEH handlers, `be_pci_sriov_configure`), `net_device_ops` (`be_open`, `be_close`, `be_xmit`, `be_set_rx_mode`, MAC/VLAN/VF operations, bridge mode, feature checks, stats, timeout), NAPI poll (`be_poll`), queue update (`be_update_queues`), firmware load (`be_load_fw`), and support functions exported to other be2net files such as `be_cq_notify`, `be_eqd_update`, `be_parse_stats`, `be_detect_error`, and `be_link_status_update`. Core state is in `struct be_adapter`, whose fields are populated and consumed here: PCI resources, doorbells, interface handle, queue arrays, RSS state, filter caches, VF configuration, firmware/mailbox DMA memory, work items, error recovery, RoCE doorbell mapping, and flow-control/PHY/statistics state.

Control flow: module init validates `rx_frag_size`, creates the command and error-recovery workqueues, then registers the PCI driver. Probe enables PCI, requests regions, allocates a multi-queue Ethernet device, sets a 64-bit DMA mask, maps device BARs, allocates mailbox/filter/statistics coherent buffers, and runs `be_setup`. Setup waits for firmware, optionally resets the function, initializes mailbox command capability, queries FW/profile/resources, enables MSI-X when possible, creates the firmware interface, creates EQ/TX/RX-CQ/MCC queues, programs MAC/flow-control/SR-IOV state, schedules the periodic worker, initializes netdev features, registers the netdev, and advertises the adapter to RoCE. Open creates RX queues, enables filters, registers IRQs, arms CQs/EQs, enables async mailbox completions/NAPI, queries link, starts TX queues, and notifies the UDP tunnel core. Close disables filters, NAPI, async commands and TX queues, drains completions, destroys RX queues, cleans event queues, and unregisters IRQs. Remove reverses probe, unregistering RoCE and netdev before firmware cleanup and PCI release.

TX/RX data path: `be_xmit` applies hardware workarounds, derives WRB offload parameters for checksum, TSO/TSO6, VLAN, VXLAN, and OS-to-BMC paths, DMA maps the SKB head and frags into WRBs, records the SKB at the header WRB, updates software stats, stops the subqueue near ring exhaustion, and rings the TX doorbell when required. Completion handling parses TX CQ entries, records hardware error classes, unmaps DMA buffers, frees SKBs, subtracts WRB usage, and wakes stopped subqueues. RX setup allocates big pages, splits them into `rx_frag_size` fragments, DMA maps them, posts RX descriptors, and rings the RX doorbell. RX completions parse v0/v1 completion formats, account for VLAN/QinQ, RSS hash, checksum, tunneled state, port filtering, and partial DMA quirks, then either builds an SKB or feeds GRO fragments. RX refill is done in NAPI for normal low-watermark cases and by the worker after allocation starvation.

State and persistence: hardware queue state persists in coherent descriptor rings plus firmware queue IDs; software state tracks head/tail/used counters, SKB/page ownership, pending WRB counts, RSS indirection/key, VLAN bitmap, programmed PMAC IDs, multicast/unicast caches, VF handles/MAC/VLAN/rate/spoof/link settings, FW versions and privileges, adaptive interrupt coalescing history, flow control, and error recovery progress. The driver also has module-global workqueues and shared module parameters. Persistent periodic behavior comes from `be_worker`, which refreshes temperature/statistics, processes mailbox completions while down, refills starved RX queues, adjusts EQ delay, and logs SFP misconfiguration details. The separate error-detection workqueue repeatedly polls hardware error state and runs the recovery state machine.

Dependencies and integration points: the file depends heavily on local `be.h`, `be_cmds.h`, ethtool code, mailbox command helpers, hardware descriptor definitions, and RoCE hooks from `be_roce.c`. Kernel integrations include PCI/MSI-X/INTx, DMA mapping/coherent memory, NAPI, rtnetlink-guarded queue count changes, netdev feature negotiation, VLAN and unicast/multicast list sync, SR-IOV sysfs, bridge mode netlink, UDP tunnel NIC notifications, hwmon, firmware loader, power management, and PCI EEH/AER recovery. RoCE integration reserves MSI-X vectors, maps the RoCE doorbell region, calls `be_roce_dev_add/remove/shutdown`, and includes RoCE counters in stats on supported adapters.

Risks: the file is highly stateful and hardware-specific. Queue cleanup and error paths must preserve DMA ownership; mistakes can leak SKBs/pages, double-unmap DMA, or leave firmware rings armed. `be_xmit_restore`, dummy WRB insertion, pending WRB accounting, and TX completion draining are particularly sensitive. RX page splitting relies on `last_frag` and DMA sync/unmap discipline across fragments from a larger page. Feature checks must stay aligned with chip errata for IPv6 extension headers, small packets, VLAN insertion, VxLAN-only tunnel offloads, and Lancer TSO constraints. SR-IOV resource redistribution can disrupt PF/VF queue counts and RSS capabilities if run while VFs are assigned. Recovery paths run through workqueues and RTNL/netdev state; races with close, remove, RoCE users, or EEH can cause repeated recovery failure or use-after-free if ordering is changed. Several functions return firmware-specific status values that are later converted with `be_cmd_status`, so unwinding must preserve the expected error domain.

Test signals: compile with BE2/BE3/Lancer/Skyhawk, SR-IOV, hwmon, netpoll, MSI-X and INTx fallback paths enabled where possible. Runtime signals include PCI probe/remove, `ip link set up/down`, carrier changes, MAC changes on PF/VF, VLAN add/remove beyond hardware filter limits, multicast/unicast list pressure, TSO/TSO6/checksum/VXLAN traffic, fragmented SKBs, short packets, QinQ/PVID modes, MTU boundaries, NAPI interrupt moderation, `ethtool -S/-k/-K/-i`, firmware flashing while up, hwmon temperature reads, SR-IOV enable/disable with VF MAC/VLAN/rate/spoof/link controls, bridge VEB/VEPA operations, suspend/resume, TX timeout diagnostics, DMA mapping failure injection, RX allocation starvation, and PCI EEH/error-recovery exercises.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/emulex/benet/be_roce.c

Purpose: this file is the be2net-to-ocrdma registration bridge. It lets the Ethernet driver publish compatible NIC functions to the out-of-tree or separately built `ocrdma` RoCE driver, and lets the RoCE driver register callbacks that are invoked for already-probed and future NIC adapters.

Important APIs, types, and functions: `be_roce_register_driver` and `be_roce_unregister_driver` are exported symbols used by the RoCE driver. `be_roce_dev_add`, `be_roce_dev_remove`, and `be_roce_dev_shutdown` are called from the NIC lifecycle in `be_main.c`. `_be_roce_dev_add` builds a `struct be_dev_info` with PCI device, netdev, MAC, SLI family, doorbell mapping, optional Skyhawk DPP BAR information, interrupt mode, and MSI-X vector list before invoking `ocrdma_driver->add`. `_be_roce_dev_remove` calls the registered remove callback and clears `adapter->ocrdma_dev`.

Control flow: when a supported NIC adapter is probed, `be_roce_dev_add` initializes the adapter list node, adds it to a module-global list under `be_adapter_list_lock`, and attempts callback registration if an ocrdma driver is already present. When ocrdma later calls `be_roce_register_driver`, the file stores the singleton driver pointer and walks the existing adapter list, adding each adapter. Unregister reverses that by removing all active RoCE devices and clearing the singleton pointer. NIC remove deletes the adapter from the list after invoking RoCE remove. Shutdown sends `BE_DEV_SHUTDOWN` through the RoCE state-change callback if present.

State and persistence: state is limited to the singleton `ocrdma_drv`, a global list of RoCE-capable `be_adapter` objects, each adapter's list entry, and `adapter->ocrdma_dev`. The mutex serializes registration, adapter add/remove, and shutdown notifications. No hardware state is programmed directly here; this file passes already-established NIC resources to the RoCE layer.

Dependencies and integration points: depends on `be_roce_supported`, `msix_enabled`, PCI resource helpers, adapter queue/MSI-X fields, and `adapter->roce_db` populated in `be_main.c`. The ABI is defined by `BE_ROCE_ABI_VERSION` in `be_roce.h`; `_be_roce_dev_add` refuses to call ocrdma if the ABI version differs. OC_DEVICE_ID5 requires MSI-X and passes BAR2 DPP resource details. The interrupt vector list combines NIC and RoCE-reserved vectors but caps the exported count at `MAX_MSIX_VECTORS`.

Risks: this bridge assumes one registered ocrdma driver at a time and no duplicate adapter list insertion. Callback pointers are partially optional: `add` is assumed present when a driver registers, while `remove` and `state_change_handler` are checked. ABI mismatch silently disables RoCE for the adapter except for a warning. MSI-X vector accounting must remain consistent with `be_msix_enable`; bad counts or start indices can hand ocrdma unusable vectors. Because callbacks run under `be_adapter_list_lock`, RoCE callbacks must avoid re-entering registration or NIC teardown paths that would deadlock on the same mutex.

Test signals: build with be2net and ocrdma modules, load NIC before and after ocrdma to exercise both registration orders, verify ABI mismatch warning using a deliberately incompatible module, confirm RoCE add receives correct netdev/MAC/doorbell/MSI-X data, remove ocrdma while NICs are present, unload NIC while ocrdma is present, and test shutdown/EEH paths for state-change delivery without stale `ocrdma_dev` pointers.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/emulex/benet/be_roce.h

Purpose: this header defines the ABI shared between the be2net Ethernet driver and the ocrdma RoCE driver.

Important APIs, types, and functions: `BE_ROCE_ABI_VERSION` is the compatibility gate. `enum be_interrupt_mode` describes MSI-X, INTx, and MSI modes, though the implementation only supplies MSI-X or INTx. `struct be_dev_info` is the resource handoff object containing MMIO doorbell pointer, unmapped doorbell address and size, optional DPP region, PCI and net devices, MAC address, device family, interrupt mode, and up to `MAX_MSIX_VECTORS` vector numbers plus start index. `struct ocrdma_driver` is the callback table with driver name, ABI version, `add`, `remove`, and `state_change_handler`. `enum be_roce_event` currently exposes `BE_DEV_SHUTDOWN`. Exported APIs are `be_roce_register_driver`, `be_roce_unregister_driver`, and the mailbox helper declaration `be_roce_mcc_cmd`.

Control flow and integration: ocrdma fills `struct ocrdma_driver` and registers it with be2net. The NIC side supplies `struct be_dev_info` when adapters are added, then uses the callback table during remove and shutdown. `be_roce_mcc_cmd` is declared here so RoCE can issue mailbox commands through the NIC driver without depending on the wider private be2net command interface.

State and persistence: the header itself has no state; it defines the data copied or referenced across the driver boundary. The embedded `net_device`, `pci_dev`, and doorbell pointers remain owned by be2net and are valid only for the active NIC lifecycle.

Dependencies and integration points: includes Linux PCI and netdevice headers and relies on `ETH_ALEN`. It must stay synchronized with `be_roce.c` and the ocrdma consumer. The size and semantics of `struct be_dev_info` are ABI-sensitive because both drivers use this layout.

Risks: any field reorder, semantic change, or version mismatch can break RoCE initialization. `MAX_MSIX_VECTORS` caps what the NIC can expose even if more vectors are enabled. The declaration of `be_roce_mcc_cmd` means consumers may compile against a mailbox interface whose implementation must remain available elsewhere in the be2net source set.

Test signals: compile both be2net and ocrdma against the header, verify `BE_ROCE_ABI_VERSION` matches on module load, confirm MSI-X and INTx handoff structures are populated as expected, and run RoCE attach/detach and shutdown tests while the netdev is registered and while it is being removed.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/engleder/Kconfig

Purpose: this Kconfig file exposes the Engleder Ethernet vendor menu and the TSN endpoint driver options.

Important APIs, types, and functions: it defines `NET_VENDOR_ENGLEDER` as a boolean vendor gate, `TSNEP` as a tristate "TSN endpoint support" driver option, and `TSNEP_SELFTESTS` as an optional boolean for driver self tests.

Control flow and state: Kconfig selection controls build-time inclusion only. If `NET_VENDOR_ENGLEDER` is disabled, the TSNEP questions are hidden. Selecting `TSNEP` requires `HAS_IOMEM`, `HAS_DMA`, and `PTP_1588_CLOCK_OPTIONAL`, and selects `PHYLIB` plus `PAGE_POOL`. `TSNEP_SELFTESTS` depends on `TSNEP` and gates the optional self-test object in the Makefile.

Dependencies and integration points: the symbol names are consumed by the local Makefile and the wider Ethernet Kbuild tree. The selected dependencies match the driver code: MMIO register access, DMA descriptor rings, PHYLIB link management, optional PTP hardware timestamping, and page_pool-backed RX.

Risks: missing dependencies would surface as compile failures in less common configurations, especially PTP/page-pool/XDP paths. Because `PTP_1588_CLOCK_OPTIONAL` is a dependency rather than a select, configurations without optional PTP support will not expose the driver. `NET_VENDOR_ENGLEDER` defaulting to `y` only controls menu visibility; it does not build TSNEP by itself.

Test signals: run `make olddefconfig` or menuconfig with and without `NET_VENDOR_ENGLEDER`, build `CONFIG_TSNEP=m` and `=y`, build with `CONFIG_TSNEP_SELFTESTS=y`, and compile-test on non-target architectures that satisfy `HAS_IOMEM` and `HAS_DMA`.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/engleder/tsnep.h

Purpose: this is the shared private header for the Engleder TSN endpoint driver. It defines ring geometry, device/queue/descriptor software state, gate-control and RX classification state, and cross-file prototypes for PTP, traffic control, RXNFC, XDP, ethtool, IRQ coalescing, and AF_XDP support.

Important APIs, types, and functions: constants define a 256-entry ring, ring masks/refill/reuse thresholds, and descriptor page layout. `struct tsnep_gcl` stores one hardware gate control list image with base/cycle timing, operations, change/start times, and change state. RXNFC state is represented by `struct tsnep_rxnfc_filter` and list-backed `struct tsnep_rxnfc_rule`. `struct tsnep_tx_entry` and `struct tsnep_rx_entry` are per-descriptor software shadows with descriptor/writeback pointers, descriptor DMA address, owner flag/properties, SKB/XDP/page ownership, lengths, and DMA unmap information. `struct tsnep_tx`, `struct tsnep_rx`, and `struct tsnep_queue` hold per-ring and per-NAPI/IRQ state. `struct tsnep_adapter` is the persistent device context containing netdev, MAC, MDIO/PHY, platform/MMIO resources, gate control, PTP, RXNFC list, XDP program, TX/RX ring arrays, and combined queue array.

Control flow and integration: implementation files allocate/fill `tsnep_adapter`, initialize queues and rings, then use the header's fields to coordinate netdev I/O, ethtool, PTP clock operations, taprio/gate control, RX flow classification, and XDP/AF_XDP. Queue objects may have TX, RX, or both; ethtool walks the queue array to map user queue indices to queues with TX/RX capability. Selftest hooks compile to real functions only under `CONFIG_TSNEP_SELFTESTS`; otherwise inline stubs return unsupported/no-op.

State and persistence: all long-lived driver state is rooted in `tsnep_adapter`. TX/RX descriptor state persists across NAPI polls in ring arrays with `write`, `read`, owner counters, page pools, XSK pools, and packet counters. Gate control state is protected by `gate_control_lock`; PTP time state is protected by `ptp_lock`; RX classification rules are protected by `rxnfc_lock`. The header carries no persistence itself but defines the ownership model for pages, SKBs, XDP frames, DMA mappings, and hardware gate lists.

Dependencies and integration points: includes platform, DMA, etherdevice, PHY, ethtool, timestamping, PTP, miscdevice, and XDP headers plus `tsnep_hw.h`. Prototypes tie this header to `tsnep_ptp.c`, `tsnep_tc.c`, `tsnep_rxnfc.c`, `tsnep_xdp.c`, `tsnep_ethtool.c`, and the main driver. Kconfig selections for PHYLIB, PAGE_POOL, and optional PTP match these dependencies.

Risks: the header is the private ABI across all TSNEP objects. Ring geometry and descriptor constants must match `tsnep_hw.h`; changing them can corrupt hardware descriptor traversal. The unions in TX/RX entries require the type/properties fields to be maintained correctly or cleanup may free the wrong object. Queue arrays are statically capped at `TSNEP_MAX_QUEUES`, so hardware queue-count parsing must clamp correctly. Locking comments identify required synchronization domains but enforcement is in the implementation files.

Test signals: compile with selftests on and off, run queue bring-up with one and multiple TX/RX queues, stress RX refill/reuse thresholds, exercise XDP and AF_XDP setup/teardown, run PTP timestamp configuration, add/delete RXNFC rules, configure taprio/gate control, and verify ethtool stats/coalescing map to queues with TX/RX members correctly.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/engleder/tsnep_ethtool.c

Purpose: this file implements the TSNEP ethtool operations for driver identity, register dumps, message level, statistics, optional selftests, RX flow classification, channel reporting, timestamp capabilities, interrupt coalescing, per-queue coalescing, and PHY-backed link settings.

Important APIs, types, and functions: static stats name arrays define global, RX queue, and TX queue stat strings. Local aggregate structs (`tsnep_stats`, `tsnep_rx_queue_stats`, `tsnep_tx_queue_stats`) define the exact `u64` layout copied to ethtool. Key callbacks include `tsnep_ethtool_get_drvinfo`, `get_regs_len`, `get_regs`, `get_strings`, `get_ethtool_stats`, `get_sset_count`, `get_rxnfc`, `set_rxnfc`, `get_channels`, `get_ts_info`, `get_coalesce`, `set_coalesce`, `get_per_queue_coalesce`, and `set_per_queue_coalesce`. The public object is `const struct ethtool_ops tsnep_ethtool_ops`.

Control flow: ethtool info returns driver name `tsnep` and platform bus name. Register length is `TSNEP_MAC_SIZE` plus one `TSNEP_QUEUE_SIZE` for each queue pair beyond queue 0; the dump is a raw `memcpy_fromio` from MMIO. Stats collection first aggregates software counters from all RX/TX rings, reads global MAC/ECM RX error counters from `ECM_STAT`, then appends per-RX queue software counters plus queue hardware RX statistics from `TSNEP_RX_STATISTIC`, followed by per-TX queue software counters. RXNFC operations dispatch to `tsnep_rxnfc_*` helpers based on the ethtool command. Coalescing helpers find the first queue with RX/TX for global get, program every queue for global set, and resolve sparse TX/RX queue membership for per-queue operations.

State and persistence: this file reads and updates `adapter->msg_enable`, reads software packet counters stored in `adapter->rx[]` and `adapter->tx[]`, reads hardware counters from MMIO, reports RXNFC counts from `adapter->rxnfc_count` and `adapter->rxnfc_max`, and programs per-queue interrupt delay through `tsnep_set_irq_coalesce`. It does not allocate persistent data; all state is owned by `struct tsnep_adapter` and queue objects.

Dependencies and integration points: depends on `tsnep.h` and hardware register definitions in `tsnep_hw.h`. PHY link settings delegate to `phy_ethtool_get_link_ksettings`, `phy_ethtool_set_link_ksettings`, and `phy_ethtool_nway_reset`. Timestamp reporting depends on PTP clock registration and `ptp_clock_index`. Optional selftest callbacks are resolved through the inline or compiled selftest functions from `tsnep.h`. RXNFC and coalescing are implemented in sibling driver files.

Risks: ethtool stats depend on struct layout matching the number of strings; adding fields requires changing names and count calculations together. Hardware RX statistic registers are read as packed byte counters, so wrap/clear-on-read behavior must be understood by tests. Raw register dumps expose a contiguous MMIO range sized from queue counts; wrong queue counts could read outside the mapped register block. Per-queue coalescing uses logical queue indices filtered through queues with RX/TX capability, so mismatches between `num_*_queues` and `queue[]` composition can report or program the wrong queue. `get_ts_info` only sets `phc_index` if a PTP clock exists; consumers must handle absent PHC.

Test signals: run `ethtool -i`, `ethtool -d`, `ethtool -S`, `ethtool -l`, `ethtool -c/-C`, per-queue coalescing netlink calls, RXNFC add/list/delete, `ethtool -T`, and PHY link setting changes. Generate RX/TX traffic, multicast, allocation pressure, and RX descriptor starvation to confirm software and hardware counters move. Build and run `ethtool -t` with `CONFIG_TSNEP_SELFTESTS=y`, and verify unsupported selftest behavior without it.

## sources/distributed-fs/ceph-client/drivers/net/ethernet/engleder/tsnep_hw.h

Purpose: this header is the TSNEP/EtherCAT MAC hardware contract. It defines register offsets, bit masks, queue address calculations, hardware limits, gate-control list encoding, descriptor layouts, descriptor ownership bits, timestamp/writeback formats, and RX inline metadata.

Important APIs, types, and data: ECM definitions cover type/revision/version/queue count/gate-control capability, system time registers, clock-rate adjustment, interrupt enable/active/acknowledge bits, reset bits, counters, interrupt delay encoding, link status/mode, MDIO control/status, and packed MAC statistics. TSNEP definitions cover MAC and per-queue register window sizes, `TSNEP_QUEUE(n)` address calculation, maximum queues, frame size, descriptor size/offset, queue control bits, descriptor base registers, RX statistics, MAC address/filter registers, gate control registers, GCL memory offsets, RX assignment registers, and EtherType filter slots. Hardware structures include `struct tsnep_gcl_operation`, `struct tsnep_tx_desc`, `struct tsnep_tx_desc_wb`, `struct tsnep_rx_desc`, `struct tsnep_rx_desc_wb`, and `struct tsnep_rx_inline`.

Control flow and integration: runtime code uses these constants to map hardware capabilities, reset common/channel/TX/RX blocks, program system time and clock rate, configure interrupts and interrupt delay, access MDIO, set MAC address and RX filters, program traffic-control gate lists, assign RX flows to queues, initialize TX/RX descriptor rings, and parse descriptor writebacks for counters, timestamps, DMA delay, and errors.

State and persistence: no software state is stored here, but the definitions describe hardware state that persists in MMIO registers and DMA descriptor memory. Descriptor ownership is encoded with owner-counter bits in properties; TX writeback can include a counter, timestamp, DMA delay, and underrun flag; RX inline metadata carries a counter and timestamp. Gate-control state persists in two hardware GCL banks with explicit active/change/open bits.

Dependencies and integration points: includes Linux integer types and is included by `tsnep.h`. It must match the hardware IP exactly and coordinate with `tsnep_main.c`, `tsnep_ptp.c`, `tsnep_tc.c`, `tsnep_rxnfc.c`, `tsnep_xdp.c`, and `tsnep_ethtool.c`. `TSNEP_MAC_SIZE`, `TSNEP_QUEUE_SIZE`, `TSNEP_MAX_QUEUES`, and descriptor constants are consumed by both register dump and ring-management code.

Risks: incorrect offsets or masks can cause silent hardware misprogramming. `TSNEP_DESC_SIZE` and `TSNEP_DESC_OFFSET` are defined twice with the same values; future edits must keep duplicates consistent or remove them carefully across all users. `TSNEP_MAX_FRAME_SIZE` is set to 2 KiB even though the comment says hardware supports 16 KiB, so MTU-related changes must account for driver policy versus hardware capacity. The statement-expression `TSNEP_QUEUE(n)` is GNU C specific and evaluates to queue 0 at offset 0 while later queues live after the MAC window; callers must pass a side-effect-safe queue index despite the local temporary. Descriptor ownership/counter bit handling is sensitive to endianness and wrap behavior.

Test signals: validate probe capability parsing from `ECM_TYPE`, MMIO register dumps sized by queue count, MDIO reads/writes, interrupt enable/ack/delay programming, link mode reporting, PTP clock read/rate adjustment, MAC address/filter programming, gate control/taprio list activation, RX assignment filters, TX/RX descriptor ring DMA under load, timestamp writebacks, RX inline metadata, and descriptor error bits such as TX underrun, TX/RX DMA error, and descriptor error.
