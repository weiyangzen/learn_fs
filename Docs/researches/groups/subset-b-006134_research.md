# sources/distributed-fs/ceph-client/mm/memcontrol.c

Purpose: implements the Linux memory cgroup controller for this Ceph-client kernel tree. It owns cgroup v2 memory limits, accounting, events, statistics, OOM behavior, per-node LRU vectors, kernel-memory/object charging, socket accounting, swap/zswap accounting, writeback integration, and cgroup lifecycle hooks. It also bridges v1 compatibility through `memcontrol-v1.h` helpers where `CONFIG_MEMCG_V1` is enabled.

Important APIs/types/functions: global controller state includes `memory_cgrp_subsys`, `root_mem_cgroup`, per-CPU `int_active_memcg`, static keys `memcg_kmem_online_key`, `memcg_bpf_enabled_key`, and `memcg_sockets_enabled_key`. Core lookup APIs include `get_mem_cgroup_from_mm()`, `get_mem_cgroup_from_current()`, `get_mem_cgroup_from_folio()`, `mem_cgroup_from_task()`, `mem_cgroup_iter()`, and `mem_cgroup_iter_break()`. Charge APIs include `__mem_cgroup_charge()`, `mem_cgroup_charge_hugetlb()`, `mem_cgroup_swapin_charge_folio()`, `try_charge_memcg()`, `charge_memcg()`, `commit_charge()`, `__mem_cgroup_uncharge()`, `__mem_cgroup_uncharge_folios()`, `mem_cgroup_replace_folio()`, and `mem_cgroup_migrate()`. Kernel-object accounting revolves around `struct obj_cgroup`, `obj_cgroup_alloc()`, `obj_cgroup_release()`, `current_obj_cgroup()`, `obj_cgroup_charge()`, `obj_cgroup_uncharge()`, `__memcg_kmem_charge_page()`, `__memcg_kmem_uncharge_page()`, slab hooks `__memcg_slab_post_alloc_hook()` and `__memcg_slab_free_hook()`, and per-CPU `memcg_stock_pcp`/`obj_stock_pcp` caches. User-facing cgroup files are registered in `memory_files`, `swap_files`, and `zswap_files`, with handlers for `memory.current`, `memory.peak`, `memory.min`, `memory.low`, `memory.high`, `memory.max`, `memory.events`, `memory.events.local`, `memory.stat`, `memory.numa_stat`, `memory.oom.group`, `memory.reclaim`, `memory.swap.*`, and `memory.zswap.*`.

Control flow: initialization starts in `mem_cgroup_init()`, which creates CPU hotplug hooks, the per-CPU workqueue, charge-drain work items, and memcg slab caches. Cgroup creation runs through `mem_cgroup_css_alloc()` and `mem_cgroup_alloc()`, allocating vmstats, per-CPU stats, per-node lruvec state, writeback domains, peak lists, vmpressure, deferred split queues, and private IDs. `mem_cgroup_css_online()` enables kmem accounting, allocates shrinker info and per-node `obj_cgroup`s, queues periodic stats flushing for the root, publishes the private ID, and onlines LRU generation state. Offline/free paths reset protections, clean zswap and kmem state, reparent object cgroups, shrinkers, deferred split queues and writeback, drain all stocks, remove IDs, wait for foreign writeback completions, drop static keys, cancel high-work, and free memory.

Control flow: memory charging first resolves the target memcg from an mm, folio, swap entry, current task, or active memcg scope. `try_charge_memcg()` consumes per-CPU stock when possible, otherwise attempts hierarchical `page_counter_try_charge()` on memory and possibly memsw, triggers reclaim when over limit, drains stocks once, retries boundedly, invokes memcg OOM if needed, and force-charges only for no-fail/high-priority contexts. Successful charges are attached to folios via `commit_charge()` and v1 commit hooks. Uncharging batches folios by `obj_cgroup` in `uncharge_gather`, clears `folio->memcg_data`, refunds page counters, updates v1 pgpgout/oom recovery, and drops object-cgroup references.

Control flow: `memory.high` and `swap.high` are non-fatal throttling controls. Charges that push a hierarchy over high record `current->memcg_nr_pages_over_high`, schedule return-to-userspace handling, or queue `high_work` from interrupt/non-task contexts. `__mem_cgroup_handle_over_high()` reclaims via `try_to_free_mem_cgroup_pages()`, computes exponential delay with `calculate_overage()` and `calculate_high_delay()`, observes task death, and sleeps in PSI memstall when reclaim cannot keep up. `memory.max` writes synchronously drain/reclaim and finally invoke memcg OOM if the new limit cannot be met. OOM flow uses `mem_cgroup_oom()`, `mem_cgroup_out_of_memory()`, `mem_cgroup_get_oom_group()`, and event counters.

State and persistence: primary state is in `struct mem_cgroup`: page counters for memory/swap/kmem/tcpmem, per-cgroup and per-node vmstats, per-node lruvecs, object-cgroup roots, private ID refcounts, event counters, configured limits/protections, peak watcher lists, writeback domains, socket pressure state, zswap limits, and v1 compatibility state. Per-CPU charge stocks deliberately make enforcement approximate until flushed by drain work, CPU hotplug, limit changes, or subtree drains. Stats are also approximate until rstat flushing; `flush_memcg_stats_dwork` periodically flushes every two seconds, while readers force or rate-limit flushes depending on need. No on-disk persistence is provided by this file; state lives in kernel memory and cgroupfs configuration and is destroyed or reparented when cgroups go offline.

Dependencies and integration: depends on cgroup core, page counters, reclaim/vmscan, folios and page cache, slab object extensions, per-CPU refs, RCU, workqueues, CPU hotplug, PSI, OOM killer, cpuset nodemasks, swap cgroups, zswap, hugetlb accounting, writeback, LRU generation, list_lru/shrinker infrastructure, networking sockets, BPF accounting static keys, tracepoints, and v1 memcg helpers. It exposes symbols used by other mm, fs, net, writeback, slab, swap, and procfs paths. In this subset, `memfd_luo.c` relies on `mem_cgroup_charge()` during restore before inserting recovered folios into shmem page cache.

Risks: correctness is concurrency-sensitive. Folio memcg ownership must be stable under locks, isolation, or exclusive refs; lruvec locks retry when folio memcg changes; object-cgroup reparenting must run after list_lru and deferred split reparenting; private IDs must remain pinned for swap and shadow entries but be recycled after offline; per-CPU stocks create temporary overage and must be drained for precise limit enforcement. OOM/reclaim paths must avoid recursion through `PF_MEMALLOC`, not stall dying tasks indefinitely, and honor GFP flags. Stats can be stale or briefly negative on SMP until flushed. Kernel-object accounting depends on slab object extensions and correct objcg refcount transfer on alloc/free/split. Socket and zswap accounting are guarded by static keys and cgroup mode differences, so mixed v1/v2 builds carry policy risk.

Test signals: useful coverage comes from kernel memcg selftests for `memory.max`, `memory.high`, `memory.low/min`, `memory.reclaim`, OOM group killing, stats/events, swap and zswap cgroup files, hugetlb accounting, socket memory, kmem/slab charging, CPU hotplug drains, cgroup deletion/reparenting, and cgroup writeback. Runtime signals include `memory.events`, `memory.events.local`, `memory.swap.events`, `memory.stat`, `memory.numa_stat`, OOM logs from `mem_cgroup_print_oom_meminfo()`, tracepoints under `trace/events/memcg.h` and `trace/events/vmscan.h`, PSI memstall behavior, and leak/refcount warnings from objcg release and folio ownership assertions.

# sources/distributed-fs/ceph-client/mm/memfd.c

Purpose: implements `memfd_create(2)` support and file sealing helpers shared by tmpfs/shmem and hugetlbfs-backed anonymous files. It creates anonymous volatile files, validates memfd flags and execution policy, exposes fcntl seal operations, enforces mmap restrictions for write seals, and includes a GUP-facing folio allocation helper for pinned memfd ranges.

Important APIs/types/functions: `SYSCALL_DEFINE2(memfd_create)` is the syscall entry. `sanitize_flags()` validates `MFD_*` flags and hugepage size encodings, while `check_sysctl_memfd_noexec()` applies pid-namespace `vm.memfd_noexec` policy. `alloc_name()` prepends `memfd:` and copies the user name. `memfd_alloc_file()` constructs the shmem or hugetlb file, initializes anonymous inode security, file modes, large-file flags, and default seals. Seal APIs are `memfd_add_seals()`, `memfd_get_seals()`, `memfd_fcntl()`, `memfd_check_seals_mmap()`, and the internal `memfd_file_seals_ptr()`. Pin-handling helpers are `memfd_alloc_folio()`, `memfd_tag_pins()`, `memfd_wait_for_pins()`, and `memfd_folio_has_extra_refs()`.

Control flow: `memfd_create` sanitizes flags, copies and prefixes the name, derives `O_CLOEXEC`, then installs the result of `memfd_alloc_file()` through `FD_ADD`. Allocation uses `hugetlb_file_setup()` when `MFD_HUGETLB` is set and `shmem_file_setup()` otherwise, then applies LSM anonymous-inode initialization. `MFD_NOEXEC_SEAL` clears executable mode bits and installs `F_SEAL_EXEC`; `MFD_ALLOW_SEALING` clears the default `F_SEAL_SEAL` so later fcntl calls may add seals.

Control flow: `memfd_add_seals()` requires write mode, rejects unknown seals, locks the inode, checks that sealing is supported and not already sealed by `F_SEAL_SEAL`, then handles `F_SEAL_WRITE` specially. For write sealing it calls `mapping_deny_writable()` to block new writable mappings and `memfd_wait_for_pins()` to detect outstanding elevated folio references from GUP/direct I/O; failure restores writable permission. `F_SEAL_EXEC` implies shrink, grow, write, and future-write seals when executable mode bits are set. Mmap checks read current seals and, for shared mappings, reject new writable mappings or clear `VM_MAYWRITE` on read-only mappings when write/future-write seals exist.

Control flow: `memfd_wait_for_pins()` scans the mapping xarray, marks folios with extra references using a reused pagecache tag, drains local/all LRU additions, waits with increasing killable timeouts across `LAST_SCAN`, and returns `-EBUSY` if pins remain on the last scan. `memfd_alloc_folio()` is used by GUP memfd pinning when a page-cache folio is absent: for hugetlb files it reserves, allocates non-highmem/non-movable huge folios, zeroes and marks them uptodate, serializes page-cache insertion with the hugetlb fault mutex, installs subpool metadata, and unreserves on error; non-hugetlb files delegate to `shmem_read_folio()`.

State and persistence: state is held in the created anonymous file, its inode, shmem or hugetlb seal word, file mode/flags, file position, mapping page cache, and transient xarray marks for pinned folios. Seals are monotonic and inode-wide but not persistent to disk. Names are transient kernel names prefixed with `memfd:`. Execution policy is applied at creation from flags and pid namespace sysctl state; `FD_CLOEXEC` is an fd flag rather than a file property.

Dependencies and integration: depends on VFS files/inodes, shmem/tmpfs, hugetlbfs, page cache/xarray, folios, GUP memfd pinning, LRU drain APIs, scheduler timeouts, LSM `security_inode_init_security_anon()`, pid namespaces/sysctl, and uapi constants from `linux/memfd.h`. `memfd_fcntl()` is called from fcntl handling, `memfd_check_seals_mmap()` from mmap/mprotect policy, `memfd_alloc_file()` is reused by LUO restore in `memfd_luo.c`, and `memfd_add_seals()` is reused there to reapply preserved seals.

Risks: write sealing is race-sensitive and relies on callers preventing new writable references while pins are checked. Extra-reference detection can conservatively reject sealing with `-EBUSY` and uses a reused pagecache tag that must remain unused by tmpfs/hugetlbfs for other semantics. Hugetlb allocation must correctly pair reservation/unreservation and page-cache insertion error paths to avoid leaks. `MFD_EXEC` versus `MFD_NOEXEC_SEAL` policy depends on namespace sysctl and flag validation. Seal implications, especially `F_SEAL_EXEC` forcing write/grow/shrink/future-write seals, are security-sensitive. The name copy path rejects names longer than `MFD_NAME_MAX_LEN` and must handle bad user pointers.

Test signals: kernel selftests around memfd creation, sealing, noexec sysctl modes, `F_ADD_SEALS`/`F_GET_SEALS`, mmap/mprotect with `F_SEAL_WRITE` and `F_SEAL_FUTURE_WRITE`, hugetlb memfd creation, GUP pins blocking write seals, and LSM anonymous inode initialization should exercise this file. Runtime failures surface as syscall errno values such as `-EINVAL`, `-EACCES`, `-EPERM`, `-EBUSY`, `-ENOMEM`, and hugetlb reservation errors.

# sources/distributed-fs/ceph-client/mm/memfd_luo.c

Purpose: adds Live Update Orchestrator file preservation support for shmem-backed memfds across kexec handover. It serializes selected memfd properties and page-cache folios into KHO-preserved memory before kexec, freezes the file, and reconstructs a new anonymous memfd with the same contents, size, file position, and supported seals in the next kernel. Hugetlb-backed memfds are intentionally unsupported because `can_preserve` only accepts `shmem_file(file)`.

Important APIs/types/functions: the preservation pipeline is implemented by `memfd_luo_preserve()`, `memfd_luo_freeze()`, `memfd_luo_unpreserve()`, `memfd_luo_finish()`, `memfd_luo_retrieve()`, `memfd_luo_can_preserve()`, and `memfd_luo_get_id()` in `memfd_luo_file_ops`. Folio helpers include `memfd_luo_preserve_folios()`, `memfd_luo_unpreserve_folios()`, `memfd_luo_discard_folios()`, and `memfd_luo_retrieve_folios()`. Serialized ABI structures come from `linux/kho/abi/memfd.h`, notably `struct memfd_luo_ser`, `struct memfd_luo_folio_ser`, `MEMFD_LUO_ALL_SEALS`, `MEMFD_LUO_FOLIO_DIRTY`, and `MEMFD_LUO_FOLIO_UPTODATE`. Registration happens in `memfd_luo_init()` with `liveupdate_register_file_handler()`.

Control flow: preservation locks the inode, calls `shmem_freeze(inode, true)`, allocates preserved metadata with `kho_alloc_preserve()`, reads and validates memfd seals with `memfd_get_seals()`, records file position, size, and seals, rejects files whose page count would exceed `memfd_pin_folios()` limits, and calls `memfd_luo_preserve_folios()`. The folio preserve helper pins all folios from byte 0 to size - 1 using `memfd_pin_folios()`, which also allocates pages for holes and swaps pages back in. It then preserves each folio with `kho_preserve_folio()`, locks it, marks it dirty, zeroes and marks non-uptodate folios uptodate, records PFN/index/flags, preserves the serialized folio array with `kho_preserve_vmalloc()`, and returns the array as private data while leaving it in preserved memory.

Control flow: freeze runs later and updates only `ser->pos`, because file position may have changed after prepare. Unpreserve is the abort path in the old kernel: it unlocks shmem freeze, unpreserves the vmalloc array and every preserved folio, unpins folios, frees serialized metadata, and unlocks the inode. Finish is a post-kexec cleanup path in the new kernel for entries not retrieved; it restores the serialized vmalloc array, discards preserved folios via `kho_restore_folio()` and `folio_put()`, frees the array, and releases serialized metadata.

Control flow: retrieval maps serialized metadata with `phys_to_virt()`, validates seal compatibility, creates a fresh memfd with `memfd_alloc_file("", MFD_ALLOW_SEALING)`, reapplies seals through `memfd_add_seals()`, restores file position with `vfs_setpos()`, and writes inode size. If folios are present, it restores the serialized vmalloc array and calls `memfd_luo_retrieve_folios()`. Retrieval of each folio restores it from its PFN, sets locked and swapbacked state, charges it with `mem_cgroup_charge()`, inserts it into shmem page cache with `shmem_add_to_page_cache()`, restores uptodate/dirty flags, accounts inode blocks via `shmem_inode_acct_blocks()`, adds it to LRU, unlocks and drops the temporary reference, and finally recalculates shmem inode accounting. On error it removes the current folio from cache if inserted and releases not-yet-added preserved folios.

State and persistence: the only preserved properties are file contents, file size, file position, `O_RDWR|O_LARGEFILE` status from the recreated memfd, and seals supported by `MEMFD_LUO_ALL_SEALS`. Sparse holes are not preserved as holes; they are materialized as zeroed folios during preservation. Clean folios are deliberately marked dirty to prevent post-restore reclaim from dropping user data, and non-uptodate folios are zeroed and marked uptodate. `FD_CLOEXEC`, original name, hugetlb backing, link state beyond anonymous shmem, and other file properties are reset. Serialized metadata lives in KHO-preserved memory addressed by physical pointers across kexec.

Dependencies and integration: depends on Live Update/KHO file handler APIs, KHO preserved allocation/vmalloc/folio APIs, shmem freeze and page-cache helpers, memfd creation and sealing helpers from `memfd.c`, memcg charging from `memcontrol.c`, VFS file position/size helpers, folio locking/dirty/uptodate/LRU APIs, dcache flushing for zeroed folios, and the `linux/kho/abi/memfd.h` compatibility contract. It registers a late-init liveupdate file handler with compatibility string `MEMFD_LUO_FH_COMPATIBLE`, and identifies preservable files by inode pointer.

Risks: preservation intentionally densifies sparse files, which can cause memory spikes and alter hole behavior after restore. Dirtying every folio protects data but may increase reclaim/writeback pressure after live update. File mutation windows are subtle: preserve locks and freezes shmem, while freeze updates only position later; any property not explicitly frozen or serialized is reset. Restore must correctly charge memcg and account shmem blocks or the new kernel can see leaked pages, bad memory accounting, or reclaim anomalies. Error paths are complex because ownership transitions from KHO-preserved folios to page cache; failures after partial insertion rely on file teardown for inserted folios and explicit `folio_put()` for the rest. Seal compatibility is versioned and rejects unknown bits with `-EOPNOTSUPP`. The handler currently excludes hugetlb memfds despite generic memfd support elsewhere.

Test signals: targeted tests should preserve and retrieve empty, small, multi-page, sparse, dirty, and fallocated-but-not-uptodate memfds across LUO/kexec; verify file size, contents, position, and supported seals; confirm unsupported seals and huge files fail; confirm hugetlb memfds are rejected by `can_preserve`; inject failures in KHO allocation, folio preservation, memcg charging, page-cache insertion, and block accounting; verify abort paths unfreeze and unpin; and inspect memcg/shmem accounting and LRU state after restore. Runtime diagnostics include `pr_err()` for pin, file setup, seal, folio restore, charge, page-cache, and block-accounting failures plus rate-limited warnings for discard failures.
