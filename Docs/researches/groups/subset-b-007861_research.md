## sources/distributed-fs/orangefs/src/kernel/linux-2.6/dir.c

Purpose: Implements OrangeFS/PVFS2 directory file operations for Linux VFS, including `readdir`, optional `readdirplus`, directory open/release, synthetic `.` and `..` entries, and decoding of userspace client-core directory trailers returned through shared memory.

Important APIs and functions: `pvfs2_readdir` is the main VFS directory iterator, mapped as `.readdir` or `.iterate` depending on kernel feature macros. `decode_dirents`, `readdir_handle_ctor`, and `readdir_handle_dtor` unpack and own `pvfs2_readdir_response_t` trailer data. Under `HAVE_READDIRPLUS_FILE_OPERATIONS`, `pvfs2_readdirplus_common`, `pvfs2_readdirplus`, `pvfs2_readdirplus_lite`, `decode_sys_attr`, and `decode_readdirplus_from_buffer` add attribute-bearing directory reads. `pvfs2_dir_open` allocates a per-open `PVFS_ds_position` token in `file->private_data`; `pvfs2_dir_release` flushes inode metadata and frees it. `pvfs2_dir_operations` exports the VFS operation table.

Control flow: `pvfs2_readdir` reads the current VFS position, exits on `PVFS_READDIR_END`, creates a `PVFS2_VFS_OP_READDIR` operation, populates the parent object reference from `PVFS2_I(inode)->refn` or from inode-derived fallback handle data, obtains a readdir shared-memory index, and calls `service_operation`. If the operation is purged after client restart, it retries with a new buffer index. Successful downcalls are decoded from `downcall.trailer_buf`, `.` and `..` are emitted for positions 0 and 1, and server-provided entries are emitted with inode numbers derived from PVFS handles. Once a batch is fully consumed, the independent PVFS token in `file->private_data` is advanced and `file->f_pos`/`ctx->pos` is set to `PVFS_ITERATE_NEXT`; when the server token reaches `PVFS_READDIR_END`, atime is marked dirty. `readdirplus` follows the same client-core upcall pattern but also decodes per-entry status and attributes, fills or initializes inodes in the VFS inode cache, and passes `kstat`/`kstat_lite` records to the callback.

State and persistence: Persistent filesystem state lives in OrangeFS servers and client-core; this file manages transient kernel state. Per-open directory traversal state is the `PVFS_ds_position` stored in `file->private_data`. Shared-memory buffer ownership is guarded by `readdir_index_get`/`readdir_index_put`, with trailer buffers freed via `vfree`. Decoded arrays are `kmalloc`-owned and freed by handle destructors. Successful reads update in-memory inode atime and mark the inode dirty so OrangeFS time-flush logic can later persist it.

Dependencies and integration points: Depends on `pvfs2-kernel.h`, `pvfs2-bufmap.h`, `pvfs2-sysint.h`, and `pvfs2-internal.h`; uses kernel VFS `file_operations`, `filldir`/`dir_emit`, optional `filldirplus`, inode cache APIs, and OrangeFS helpers such as `op_alloc`, `service_operation`, `op_state_purged`, `PVFS2_I`, `PVFS2_SB`, `PVFS_khandle_from`, `pvfs2_khandle_to_ino`, `copy_attributes_to_inode`, `pvfs2_iget_locked`, `SetAtimeFlag`, and gossip logging. It shares downcall trailer layouts with `downcall.h` and the userspace client protocol.

Risks: Trailer decoding trusts client-provided counts and serialized string layout; malformed trailers can drive large allocations or decode-length mismatches. `kmalloc(HANDLESTRINGSIZE)` debug buffers are not checked before `memset` in the main path. Directory position logic is subtle because VFS positions, `PVFS_ITERATE_NEXT`, and PVFS distributed-directory tokens are intentionally decoupled; partial user buffers and callback failures are high-risk cases. Several `readdirplus` paths appear fragile or stale: the `PVFS_khandle_from(&refn.khandle)` references use an undeclared-looking `refn`, `pvfs2_khandle_to_ino(khandle)` passes a value where the header declares a pointer, `graceful_termination_path` is referenced but not visible in this file, and the `while` statement near the end of `pvfs2_readdirplus_common` appears syntactically incomplete. Because these paths are feature-macro gated, build coverage must include the relevant `readdirplus` variants before relying on them. Readdirplus also admits it is untested for distributed directories and rejects reentry after `pos > 2`.

Test signals: Compile with and without `HAVE_READDIR_FILE_OPERATIONS`, `HAVE_READDIRPLUS_FILE_OPERATIONS`, and `HAVE_READDIRPLUSLITE_FILE_OPERATIONS`. Exercise empty directories, single-batch and multi-batch distributed directories, partial `getdents` buffers, callback-stop paths, client-core restart/purged-op retry, trailer-size mismatch, malformed or huge dirent counts, atime dirtying, `.`/`..` inode values, and readdir after `PVFS_READDIR_END`. For readdirplus, test stat-error entries, symlink link-target attributes, inode-cache population for new and existing inodes, lite masks, and all feature-macro builds.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/downcall.h

Purpose: Defines the kernel-module side of OrangeFS/PVFS2 downcall response structures, the typed payloads that userspace client-core returns to completed VFS upcalls.

Important APIs and types: `pvfs2_downcall_t` is the top-level response envelope containing `type`, `status`, optional trailer size/buffer, and a union of operation-specific responses. Key payloads include `pvfs2_io_response_t`, `pvfs2_iox_response_t`, `pvfs2_lookup_response_t`, `pvfs2_create_response_t`, `pvfs2_symlink_response_t`, `pvfs2_getattr_response_t`, `pvfs2_readdir_response_t`, `pvfs2_readdirplus_response_t`, `pvfs2_statfs_response_t`, `pvfs2_fs_mount_response_t`, xattr responses, parameter/performance/fs-key responses, and `pvfs2_features_response_t`. `struct pvfs2_dirent` duplicates enough system-interface dirent shape for trailer decoding without extra allocations.

Control flow: This header has no executable control flow. It establishes the memory contract read by operation-specific kernel code after `service_operation` returns. Inline response fields are used directly for small fixed-size results, while large variable-size results such as readdir and readdirplus are represented by `trailer_size` and `trailer_buf` and decoded by callers such as `dir.c`.

State and persistence: No state is stored by the header itself. Instances are embedded in `pvfs2_kernel_op_t` objects and live only for the lifetime of an in-flight operation. The definitions are ABI-sensitive between kernel module and client-core; field order, padding fields, and alignment wrappers are part of that transient IPC contract.

Dependencies and integration points: Includes `pvfs2-sysint.h` for `PVFS_object_kref`, `PVFS_sys_attr`, `PVFS_error`, `PVFS_ds_position`, `PVFS_fs_id`, and size/name constants. The response union is consumed across file I/O, name lookup/create, inode getattr/setattr, directory reads, superblock mount/statfs, xattr handling, fsync, cancellation, feature negotiation, and perf counter paths.

Risks: This is a protocol layout header, so accidental field reordering or size changes can break 32/64-bit interoperability with client-core. Some responses are commented out of the union because they are blank or trailer-only; code must not assume those payloads exist inline. Fixed-size buffers for xattrs, performance counts, and fs keys require caller-side length validation. Readdirplus comments explicitly warn not to change field order unless the base readdir layout changes.

Test signals: Validate kernel/client-core structure-size and offset compatibility on 32-bit and 64-bit builds. Exercise every union member through its corresponding VFS operation, including blank-response operations. Add trailer-size mismatch tests for readdir/readdirplus and boundary tests for maximum xattr, listxattr, perf-count, and fs-key payload lengths.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/file.c

Purpose: Implements OrangeFS/PVFS2 regular-file VFS operations: open, read/write/readv/writev, non-contiguous readx/writex, optional AIO, ioctl flags, mmap, release, fsync, llseek, optional sendfile, and the direct shared-memory I/O path to userspace client-core.

Important APIs and functions: `pvfs2_file_operations` exports the VFS operation table. `pvfs2_file_open`, `pvfs2_file_read`, `pvfs2_file_write`, `pvfs2_file_readv`, `pvfs2_file_writev`, `pvfs2_file_readx`, `pvfs2_file_writex`, `pvfs2_ioctl`, `pvfs2_file_mmap`, `pvfs2_file_release`, `pvfs2_fsync`, `pvfs2_file_llseek`, and `pvfs2_lock` are the externally visible file behaviors. Internal orchestration centers on `struct rw_options`, `do_readv_writev`, `wait_for_direct_io`, `split_iovecs`, `bound_max_iovecs`, `precopy_buffers`, and `postcopy_buffers`. Non-contiguous I/O uses `construct_file_offset_trailer`, `split_xtvecs`, `bound_max_xtvecs`, `wait_for_iox`, and `do_readx_writex`. Optional AIO uses `do_aio_read_write`, `pvfs2_aio_retry`, `pvfs2_aio_cancel`, `pvfs2_aio_dtor`, and `fill_default_kiocb`.

Control flow: Open installs OrangeFS address-space operations and, for `O_APPEND`, refreshes file size before positioning at EOF. Normal read/write wrappers populate `rw_options` and call `do_readv_writev`. That routine validates inode/PVFS state, computes total count and required splits against `pvfs_bufmap_size_query`, runs kernel write checks, splits large iovecs, and loops in chunks. Each chunk goes through `wait_for_direct_io`: allocate a `PVFS2_VFS_OP_FILE_IO`, obtain a bufmap index, stage write data into shared memory, call `service_operation`, retry with a fresh buffer after purged `-EAGAIN`, copy read data back out, return `amt_complete`, and wake the daemon with `wake_up_daemon_for_return`. The readx/writex path mirrors this but also serializes file extents into an upcall trailer and uses `PVFS2_VFS_OP_FILE_IOX`. AIO submits at most one bufmap-sized request asynchronously, stores `pvfs2_kiocb` state in both `iocb->private` and `op->priv`, and completes later through retry/cancel/destructor paths. Fsync waits on pagecache writeback, sends `PVFS2_VFS_OP_FSYNC`, then flushes inode metadata.

State and persistence: File contents persist on OrangeFS servers through client-core operations; this file manages kernel-visible staging and metadata hints. Bufmap indices represent shared-memory slots and must be put exactly once. `pvfs2_kernel_op_t` lifetimes are split between kernel callers and the device daemon; after `wake_up_daemon_for_return`, the synchronous path deliberately stops touching the op. Reads and writes increment `g_pvfs2_stats`; successful reads/writes set atime/mtime flags, update inode timestamps, and mark inodes dirty for later metadata flush. `FS_IOC_GETFLAGS`/`FS_IOC_SETFLAGS` persist Linux file flags through the `user.pvfs2.meta_hint` xattr. Release flushes inode state and drops page/readahead cache pages.

Dependencies and integration points: Depends on Linux VFS file, address-space, pagecache, mmap, ioctl, AIO, sendfile, and locking APIs, with extensive compatibility macros for kernel-version differences. OrangeFS integration points include `pvfs2-bufmap` copy helpers, `op_alloc`/`op_alloc_trailer`, `service_operation`, operation state helpers, `pvfs2_inode_getattr`, `pvfs2_inode_read`, xattr default handlers, `pvfs2_flush_inode`, `pvfs2_truncate_inode`, `pvfs2_cancel_op_in_progress`, gossip logging, and handle conversion utilities.

Risks: This file has complex ownership rules across bufmap slots, operation refs, trailers, and AIO callbacks; cancellation and client-core restart paths are the most race-prone. Several parameter checks compare unsigned segment counts against zero, which does not reject bad counts. Debug buffers allocated with `kmalloc(HANDLESTRINGSIZE)` are generally not checked before `memset`. The cached-read/pagecache path is present but effectively disabled for ordinary reads with comments saying it breaks unless user buffers are page-size multiples. AIO rejects transfers larger than one bufmap block and does not implement the splitting used by synchronous I/O. `do_aio_read_write` has a suspicious overflow test form around `unlikely(((ssize_t)count)) < 0`. Sendfile bypasses the pagecache manually and must be checked carefully for page allocation/free balance. `pvfs2_lock` returns `-ENOSYS`, so POSIX locking is not implemented.

Test signals: Cover open with and without `O_APPEND`, EOF and short I/O, iovec splitting at bufmap boundaries, read/write larger than bufmap size, client-core restart with purged `-EAGAIN`, interrupted operations, bufmap get/copy failures, metadata time dirtying, fsync behavior, llseek `SEEK_END` getattr refresh, mmap readpage integration, release cache truncation, ioctl flag round trips through xattrs, readx/writex with mismatched memory/file lengths, AIO sync versus async paths, AIO cancellation before and during daemon service, sendfile if enabled, and kernel-feature builds for old vector/AIO/ioctl signatures.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/inode.c

Purpose: Implements OrangeFS/PVFS2 inode and address-space operations: page reads, optional readpages/direct-IO stubs, invalidate/release page hooks, truncate/setattr/getattr, file inode operation tables, and inode-cache lookup/initialization by PVFS object handle.

Important APIs and functions: `pvfs2_address_operations` exports `.readpage`, optional `.readpages`, `.invalidatepage`, `.releasepage`, and `.direct_IO`. `read_one_page`, `pvfs2_readpage`, and `pvfs2_readpages` back pagecache reads through `pvfs2_inode_read`. `pvfs2_truncate`, `pvfs2_setattr`, `pvfs2_getattr`, `pvfs2_getattr_lite`, and `convert_to_pvfs2_mask` map VFS metadata operations to OrangeFS client operations. `pvfs2_file_inode_operations` provides file inode operations and xattr/ACL hooks. `pvfs2_handle_hash`, `pvfs2_set_inode`, `pvfs2_test_inode`, `pvfs2_iget_common`, and `pvfs2_get_custom_inode_common` control inode identity, cache lookup, and operation-table assignment.

Control flow: Page reads map the page, issue `pvfs2_inode_read` at the page offset, zero any unread part, flush dcache, set uptodate or error, unmap, and unlock. Readpages iterates the supplied list, adds pages to the cache, and invokes `read_one_page`. Setattr first runs VFS permission/size checks, updates local inode fields through the kernel helper appropriate to the target version, adjusts ctime/mtime for truncate semantics, calls `pvfs2_inode_setattr`, and performs ACL chmod if needed. Getattr propagates mount `noatime`/`nodiratime` flags, refreshes all attributes via `pvfs2_inode_getattr`, fills `kstat`, and marks bad inodes on non-interrupt failures. `pvfs2_iget_common` uses `iget5_locked`/`iget4_locked` when available so the inode cache is keyed by PVFS handle+fsid rather than only by a potentially colliding scalar inode number; new unlocked inodes are read from OrangeFS before use. `pvfs2_get_custom_inode_common` obtains an inode, initializes ownership/times/block fields, attaches file/dir/symlink operation tables, and initializes ACLs for newly created objects.

State and persistence: In-memory inode state mirrors persistent OrangeFS object attributes. Size, mode, timestamps, owner/group, block size, rdev, mapping operations, PVFS handle/fsid private data, and ACL state are initialized or refreshed here. Persistence occurs through `pvfs2_inode_setattr`, `pvfs2_inode_getattr`, and `pvfs2_truncate_inode`; dirty timestamps are coordinated with code in file and directory operations. `pvfs2_backing_dev_info` advertises no dirty accounting/writeback, matching the module's explicit client-core I/O model.

Dependencies and integration points: Depends on Linux pagecache/address-space APIs, `generic_fillattr`, `setattr_copy`/`inode_setattr`, truncate helpers, `iget*` APIs, xattr/ACL hooks, and backing-device interfaces. OrangeFS dependencies include `pvfs2_inode_read`, `pvfs2_inode_getattr`, `pvfs2_inode_setattr`, `pvfs2_truncate_inode`, `copy_attributes_to_inode` indirectly through lookup paths, `PVFS2_I`, `pvfs2_inode_initialize`, handle conversion helpers, and file/dir/symlink operation tables from neighboring modules.

Risks: Direct I/O is advertised through an address-space hook but always returns `-EINVAL`; this may only exist to let the kernel accept `O_DIRECT`, but callers expecting actual direct-IO semantics will fail. Readpages ignores individual read errors and returns 0 after processing the list. The fallback non-`iget4/5` branch appears stale: `pvfs2_khandle_to_ino(ref->khandle)` passes a value where the header expects a pointer and lacks a visible semicolon. `pvfs2_get_custom_inode_common` returns `inode` after the `error:` label without always dropping a partially initialized unsupported-mode inode. Debug handle strings are allocated without consistent NULL checks. Marking bad inodes on getattr failures is intentionally avoided for `-EINTR` but aggressive for other transient-looking errors.

Test signals: Test page reads for full, short, EOF, and error pages; readpages list handling; mmap-triggered faults; invalidate/release hooks; setattr size changes, truncates, chmod with ACLs, and timestamp edge cases; getattr with mount noatime/nodiratime propagation and `-EINTR`; inode-cache collisions across different handles with identical scalar hashes; creation of regular files, directories, and symlinks through `pvfs2_get_custom_inode_common`; unsupported mode handling; and builds across all `iget*`, truncate, invalidatepage, xattr, and ACL feature macros.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/khandle-util.h

Purpose: Provides `k2s`, the shared debug-formatting helper that converts a `PVFS_khandle` into a printable string for gossip logging.

Important APIs and functions: `k2s(PVFS_khandle *khandle, char *s)` is the only function in this header. For handles that look like the legacy 64-bit encoding, it rearranges selected bytes into `struct ihash` and prints the integer form. For 128-bit handles, it emits a UUID-like uppercase hexadecimal string with dashes. Callers are expected to allocate at least `HANDLESTRINGSIZE` bytes, as declared in `khandle.h`.

Control flow: The function scans bytes 4 through 11; if they are all zero it treats the handle as the 64-bit legacy layout, otherwise as a full 128-bit handle. The 64-bit path copies bytes 0-3 and 12-15 into an `ihash` union and formats `ihash.ino`. The 128-bit path converts each byte into two hex digits using a local lookup table and inserts dashes after selected byte positions.

State and persistence: No persistent state. It writes only into the caller-provided output buffer and reads the supplied handle. The function is used primarily in logging paths, so failures would affect diagnostics more than filesystem semantics unless a NULL pointer is passed.

Dependencies and integration points: Depends on `PVFS_khandle`, `struct ihash`, and `HANDLESTRINGSIZE` definitions from the surrounding OrangeFS kernel headers. Integrated broadly by `dir.c`, `file.c`, `inode.c`, `namei.c`, and other modules for consistent handle diagnostics.

Risks: This is an implementation in a header, not a `static inline`; including it in multiple translation units would create duplicate global definitions unless the build includes it in exactly one C file or uses special rules. It uses `sprintf` repeatedly with no length argument and assumes `s` is valid and large enough. It assumes a particular 64-bit handle encoding and byte ordering. The UUID dash positions appear to insert after byte indexes 4, 6, 8, and 10, which differs from the canonical 4-2-2-2-6 byte grouping described in the comment if interpreted literally from zero-based indexes.

Test signals: Unit-test formatting for legacy 64-bit handles, full 128-bit handles, all-zero handles, and boundary byte values. Build-test inclusion patterns to catch duplicate symbol issues. Run with small or NULL buffers only under defensive/fuzz tests to confirm callers enforce `HANDLESTRINGSIZE`.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/khandle.h

Purpose: Declares and implements small helpers for comparing, copying, formatting, and hashing OrangeFS/PVFS kernel handles used as VFS inode identifiers and debug values.

Important APIs and functions: Declares `k2s(PVFS_khandle *, char *)` and `HANDLESTRINGSIZE`. `PVFS_khandle_cmp` lexicographically compares 16 handle bytes from high index to low. `PVFS_khandle_to` copies a handle into an arbitrary-size destination buffer after zeroing it. `PVFS_khandle_from` copies an arbitrary-size source buffer into a zeroed 16-byte `PVFS_khandle`. `pvfs2_khandle_to_ino` maps a 16-byte handle to an `ino_t` by combining bytes 0-3 and 12-15 through `struct ihash`.

Control flow: All helper logic is local and synchronous. Copy helpers zero the target and copy up to the smaller of 16 bytes and the supplied size. The inode-hash helper deliberately discards the middle eight bytes, matching the comment that the kernel module always uses first four and last four bytes as the scalar inode number.

State and persistence: No persistent state. The helpers influence persistent-looking VFS behavior because the generated inode number/hash is exposed through stat output and used as the hash key for inode-cache lookup before full handle comparison.

Dependencies and integration points: Depends on `PVFS_khandle`, `struct ihash`, `ino_t`, and C library/kernel primitives such as `memset`. Used by inode-cache code in `inode.c`, directory entry inode-number generation in `dir.c`, name lookup fallback paths in `namei.c`, and debug logging via `k2s`.

Risks: The comparison comment says it assumes little endian, and the inode hash intentionally collapses 128-bit handles to 64 bits, so collisions are possible and must be resolved by full handle+fsid checks where available. Some legacy fallback code elsewhere calls `pvfs2_khandle_to_ino` as if it accepted a value rather than a pointer, indicating stale compatibility branches. `PVFS_khandle_to/from` accept arbitrary sizes and raw `void *` pointers without NULL validation. Exposing the hash as `i_ino` can confuse tools if many 128-bit handles share first/last bytes.

Test signals: Test compare ordering, equality, copy-to/from with sizes 0, 8, 16, and larger than 16, inode-hash stability across 64-bit and 128-bit handles, and collision handling in `iget5_locked`/`iget4_locked` paths. Compile all legacy fallback branches that call the helper to catch signature drift.

## sources/distributed-fs/orangefs/src/kernel/linux-2.6/namei.c

Purpose: Implements OrangeFS/PVFS2 directory inode operations for pathname creation, lookup, unlink/rmdir, symlink, mkdir, rename, and explicit unsupported hard-link/special-file behavior.

Important APIs and functions: `pvfs2_dir_inode_operations` exports directory inode operations. `pvfs2_create`, `pvfs2_symlink`, and `pvfs2_mkdir` delegate object creation to `pvfs2_create_entry` with operation types `PVFS2_VFS_OP_CREATE`, `PVFS2_VFS_OP_SYMLINK`, and `PVFS2_VFS_OP_MKDIR`. `pvfs2_lookup` performs `PVFS2_VFS_OP_LOOKUP` and attaches dentry operations. `pvfs2_unlink` removes files and directories via `pvfs2_remove_entry`. `pvfs2_rename` constructs and services `PVFS2_VFS_OP_RENAME`. `pvfs2_link` and `pvfs2_mknod` return `-EOPNOTSUPP`.

Control flow: Create-like operations call `pvfs2_create_entry`, and on returned inode success update the parent directory mtime flag, refresh inode time, mark the directory dirty, and return 0. Lookup validates name length, allocates an op, sets no-follow symlink lookup semantics, chooses the parent object reference from `PVFS2_I(dir)->refn` or a root/fallback handle, copies the target name, and calls `service_operation`. `-ENOENT` produces a negative dentry with OrangeFS dentry operations so later cached lookups can revalidate. Successful lookups call `pvfs2_iget` on the returned object reference and splice aliases into the dcache. Bad inodes are converted to the stored OrangeFS error code when possible. Rename obtains old/new parent references, copies old/new names, services the rename op, updates overwritten target ctime, releases the op, and on old kernels moves the dentry manually.

State and persistence: Namespace changes persist through client-core operations such as create/remove/rename. The kernel-side state updated here includes dcache positive/negative entries, dentry operations, inode link counts for unlink, parent directory mtime flags, dirty inode marking, and ctime for replaced dentries. Directory hard-link counts are intentionally not fully maintained for distributed clients; related code is disabled with comments.

Dependencies and integration points: Depends on Linux VFS inode/dentry operation contracts, dcache aliasing, kernel feature macros for changing operation signatures, and OrangeFS helpers from `pvfs2-kernel.h`/`pvfs2-internal.h`: `pvfs2_create_entry`, `pvfs2_remove_entry`, `op_alloc`, `service_operation`, `PVFS2_I`, `PVFS2_SB`, `PVFS_khandle_from`, `pvfs2_iget`, `pvfs2_d_splice_alias`, `pvfs2_dentry_operations`, `SetMtimeFlag`, and `pvfs2_update_inode_time`.

Risks: `pvfs2_lookup` allocates a debug buffer and uses it without checking for NULL in several paths. Rename does not perform the explicit `PVFS2_NAME_LEN - 1` length check that lookup performs before `strncpy`; long names risk truncation unless VFS validation always catches them earlier. Symlink creation uses `mode = 755`, which is decimal rather than octal `0755`, and may not represent intended permissions if the mode is consumed directly. Directory nlink maintenance is mostly disabled, so local link counts are approximate in distributed scenarios. Rename updates local ctime and may alter local dcache state even if subtle remote errors are returned through status conventions not captured by `ret`; service/downcall-status handling should be verified. Fallback parent-handle logic is unsafe with `iget4/5` and intentionally returns `-EINVAL` where inode numbers cannot be trusted.

Test signals: Exercise create/open-exclusive races, lookup hit/miss and negative-dentry revalidation, interrupted lookups, bad-inode error propagation, long names in lookup and rename, symlink target creation and mode, mkdir/rmdir/unlink parent timestamp updates, hard-link and mknod `-EOPNOTSUPP`, rename over files and directories across parents, dcache alias splicing, root/fallback parent references, and all signature variants controlled by kernel feature macros.
