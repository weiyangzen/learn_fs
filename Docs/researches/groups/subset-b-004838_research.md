# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/mvm/tx.c

Purpose: Implements the iwlwifi MVM mac80211 transmit path. It builds firmware TX commands for legacy and new TX APIs, chooses rates/antennas/queues, handles checksum and crypto offload metadata, segments TSO traffic into MPDUs or A-MSDUs, submits frames through the transport, consumes TX/BA firmware notifications, updates mac80211 TX status, and reclaims transport queue entries.

Important APIs/functions: `iwl_mvm_set_tx_cmd()` fills old `iwl_tx_cmd_v6_params` fields such as ACK policy, TID, PM timeout, RTS/protection, lifetime, station id, and offload assist. `iwl_mvm_set_tx_cmd_rate()` and helpers convert mac80211 rate control or injected rates into firmware `rate_n_flags`. `iwl_mvm_set_tx_params()` allocates an `iwl_device_tx_cmd` and writes either old v6 or new v9/v10-style TX command payloads. `iwl_mvm_tx_skb_non_sta()` sends management/control/non-station frames through aux/P2P/AP/monitor queues. `iwl_mvm_tx_skb_sta()` is the station data entry point and delegates to `iwl_mvm_tx_mpdu()` or `iwl_mvm_tx_tso()`. Completion and reclaim are handled by `iwl_mvm_rx_tx_cmd()`, `iwl_mvm_rx_ba_notif()`, `iwl_mvm_tx_reclaim()`, and flush helpers `iwl_mvm_flush_tx_path()`, `iwl_mvm_flush_sta_tids()`, and `iwl_mvm_flush_sta()`.

Key helper behavior: `iwl_mvm_tx_csum()` translates `CHECKSUM_PARTIAL`, IPv4/IPv6 TCP/UDP, A-MSDU, MAC-header padding, and IV placement into `offload_assist`, falling back to `skb_checksum_help()` for unsupported protocols or IPv6 extension headers. `iwl_mvm_set_tx_cmd_crypto()` inserts IV/PN state for CCMP/TKIP/WEP/GCMP/CCMP-256 paths and can use firmware key table slots for stronger ciphers. `iwl_mvm_get_tx_ant()` honors BT shared-antenna restrictions, station TX antenna state, and `mvm->mgmt_last_antenna_idx`. `iwl_mvm_probe_resp_set_noa()` appends P2P notice-of-absence data from RCU-protected probe-response state.

Control flow: outgoing non-station frames first classify the vif/offchannel mode to pick aux, P2P, AP/IBSS broadcast/multicast, or monitor queues, then build a TX command and call `iwl_trans_tx()`. Station frames copy the skb control block, reject invalid stations and forbidden probe/nullfunc cases, optionally segment GSO traffic, then for each MPDU take `mvmsta->lock`, derive TID and AMPDU state, update old-API sequence control, select `tid_data[tid].txq_id`, prepare status driver data, copy data to CSME when needed, and submit to transport. On success, per-TID sequence numbers and TCM packet counters advance; on failure the TX command is freed and the skb is consumed/dropped according to path.

Completion flow: single-frame TX responses reclaim up to the firmware SSN, free TX command allocations stored in `info->driver_data[1]`, translate firmware status to `IEEE80211_TX_STAT_ACK`, `TX_FILTERED`, or `AMPDU_NO_BACK`, update retry/rate/antenna/airtime fields, toggle management or pre-authorized station antennas on failures, handle time-sync frames specially, and notify mac80211. Aggregate TX responses cache rate/time/color in `mvmsta->tid_data`. BA notifications differ by API: new compressed BA notifications may reclaim multiple TFD entries across TIDs, while old notifications reclaim one queue/TID using `scd_flow` and `scd_ssn`.

State and persistence: Mutates per-station `tid_data` fields (`seq_number`, `next_reclaimed`, `state`, `rate_n_flags`, `tx_time`, `lq_color`, `txq_id`), queue timestamps and shared queue status in `mvm->queue_info`, TCM counters in `mvm->tcm`, sleep/EOSP counters, `mvm->mgmt_last_antenna_idx`, and skb status/control memory. Crypto PN state persists in `keyconf->tx_pn`. Probe-response NoA data is read under RCU. Firmware-facing persistent state includes transport queue write/read indexes and firmware TX/BA queues.

Dependencies/integration: Depends on mac80211 skb control blocks, station/vif/private structures from `mvm.h` and `sta.h`, transport APIs (`iwl_trans_alloc_tx_cmd`, `iwl_trans_tx`, `iwl_trans_reclaim`, `iwl_trans_free_tx_cmd`), rate conversion helpers in `utils.c`, firmware API constants for TX status and rate formats, BT coexistence, MEI/CSME mirroring, time-sync, debug trigger collection, and firmware capability checks for old/new TX APIs.

Risks: The file sits on hot TX paths, so locking and ownership mistakes are high impact. Risks include unsupported checksum offload silently changing skb contents via software fallback, PN/key race noted for table-based GCMP/CCMP-256 rekeying, old/new TX API divergence, invalid TID/queue ids, BA notifications arriving after station RCU invalidation, compressed BA code writing `mvmsta->tid_data[i].lq_color` using loop index instead of TID-shaped data, sequence/SSN wrap differences across generations, skb ownership on TSO partial failure, and queue-empty/AddBA state transitions depending on exact reclaim indexes.

Test signals: Build both `CONFIG_INET` and non-INET paths, old and new TX API firmware, station and non-station TX, injected fixed rates, 2.4 GHz no-CCK/no-shared-antenna cases, P2P probe response NoA insertion with small tailroom, CCMP/TKIP/WEP/GCMP encryption, TSO with and without A-MSDU in A-MPDU, invalid aggregation state warnings, single TX success/failure/filter/flush statuses, compressed and legacy BA notifications, station removal during BA, flush response validation, AddBA empty-queue continuation, EOSP/uAPSD handling, and debug trigger firing for BAR/TX failures.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/mvm/utils.c

Purpose: Provides shared MVM helpers for firmware command submission, rate-index conversion, firmware error logging, antenna selection, link-quality commands, SMPS aggregation of requests, statistics collection, RX diversity policy, low-latency/quota updates, interface lookup, traffic condition monitoring, synchronization time reads, vif/link activity checks, and firmware rate-format conversion.

Important APIs/functions: `iwl_mvm_send_cmd()`, `iwl_mvm_send_cmd_pdu()`, `iwl_mvm_send_cmd_status()`, and `iwl_mvm_send_cmd_pdu_status()` wrap transport command submission and normalize RFKILL/EHOSTDOWN behavior. Rate helpers include `iwl_mvm_legacy_hw_idx_to_mac80211_idx()`, `iwl_mvm_legacy_rate_to_mac80211_idx()`, `iwl_mvm_mac80211_idx_to_hwrate()`, `iwl_mvm_v3_rate_from_fw()`, and `iwl_mvm_v3_rate_to_fw()`. Policy helpers include `iwl_mvm_update_smps()`, `iwl_mvm_update_smps_on_active_links()`, `iwl_mvm_rx_diversity_allowed()`, `iwl_mvm_update_low_latency()`, `iwl_mvm_low_latency()`, `iwl_mvm_low_latency_band()`, and the TCM family (`iwl_mvm_recalc_tcm()`, `iwl_mvm_tcm_work()`, pause/resume/add/rm vif helpers).

Command/status control flow: Synchronous commands must hold `mvm->mutex`; async commands are allowed without it. `iwl_mvm_send_cmd()` returns success for RFKILL/EHOSTDOWN unless the caller requested a response skb. Status commands force `CMD_WANT_SKB`, parse a fixed `iwl_cmd_response`, and leave caller-provided success status unchanged on RFKILL. Statistics requests first prefer `SYSTEM_STATISTICS_CMD` when available, otherwise switch between old direct response and newer notification-wait flows based on notification version.

Traffic and power policy flow: SMPS requests are stored per link and per request type, with static taking precedence over dynamic and automatic as fallback, then mac80211 is asked to apply the merged mode. Low latency is a per-vif bitset by cause; changes send `LOW_LATENCY_CMD`, update quotas, notify BT coexistence, and refresh power policy. TCM accumulates RX/TX airtime and packet counts per MAC, periodically computes per-MAC/global/per-band load, toggles traffic-driven low latency based on VO/VI packet thresholds, clears counters with memory barriers, schedules delayed re-evaluation, and may reconfigure scan when UMAC scan is supported.

State and persistence: Mutates `mvm->statistics_clear`, accumulated radio stats, `mvmvif->link[*]->smps_requests`, low-latency cause bits in each `iwl_mvm_vif`, `mvm->tcm.data/result/timestamps/paused`, U-APSD non-aggregation detector state and ring buffer of problematic BSSIDs, `mvm->ps_disabled` during synchronized time reads, and no persistent storage outside driver memory. Work items (`tcm.work`, per-vif `uapsd_nonagg_detected_wk`) persist across traffic intervals and vif lifetime.

Dependencies/integration: Uses mac80211 interface iteration and SMPS APIs, firmware command/notification frameworks, PRPH/CSR register access, firmware rate constants from `fw/api/rs.h`, firmware image capability lookup, power/quota/BT coexistence/scan helpers, debug trigger collection, RCU mappings from firmware MAC/station ids to mac80211 objects, and kernel timekeeping (`jiffies`, `ktime_get_*`).

Risks: RFKILL command normalization can hide real failures from callers that do not request response skbs. Several helpers depend on `mvm->mutex`, RCU, or spinlocks and rely on callers to satisfy those contexts. TCM races are mitigated but not eliminated by timestamp rechecks and barriers. `iwl_mvm_get_sync_time()` temporarily disables power save and must restore exactly. Rate conversion has many format-version branches; unsupported HE-to-old-fw conversion returns 0 with a warning. `iwl_mvm_low_latency_band()` indexes by caller-supplied band without local bounds checks.

Test signals: Exercise command wrappers under success, RFKILL, EHOSTDOWN, response-length mismatch, and status response paths. Test statistics command version 1, legacy notification pre/post v15, timeout, and clear accumulation. Cover SMPS with multiple request types and MLO active links, single-antenna and firmware-RLC-offload no-ops, RX diversity with CAM/non-CAM power schemes, low-latency cause transitions and quota/power side effects, TCM load thresholds and delayed disable, U-APSD non-aggregation disconnect detection, interface lookup duplicates, GP2 sync time for boot/realtime clocks, and v1/v2/v3 rate round trips.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/mvm/vendor-cmd.c

Purpose: Registers Intel cfg80211 vendor commands/events for MVM and implements host userspace access to CSME connection information, CSME ownership transfer, and roaming-forbidden notifications.

Important APIs/functions: `iwl_mvm_vendor_cmds_register()` installs command and event arrays into `mvm->hw->wiphy`. `iwl_mvm_vendor_get_csme_conn_info()` returns CSME connection attributes in a vendor reply skb. `iwl_mvm_vendor_host_get_ownership()` asks MEI/CSME support code to transfer ownership to the host. `iwl_mvm_send_roaming_forbidden_event()` emits an async vendor event with vif address and forbidden flag.

Control flow: Vendor commands are selected by Intel OUI and subcommand id. The CSME info command locks `mvm->mutex`, calls `iwl_mvm_get_csme_conn_info()`, allocates a reply skb, appends auth mode, SSID, pairwise cipher, channel, and BSSID attributes, unlocks, and sends the reply. The ownership command only locks around `iwl_mvm_mei_get_ownership()`. Roaming events allocate a vendor event skb for the given wdev, append attributes, and call `cfg80211_vendor_event()`.

State and persistence: This file stores no private persistent state. Registration mutates `wiphy` vendor command/event pointers and counts. Runtime commands read CSME connection state and may mutate MEI/CSME ownership through called helpers. Events consume short-lived skbs allocated with `GFP_ATOMIC`.

Dependencies/integration: Depends on `linux/nl80211-vnd-intel.h` attribute/subcommand definitions, cfg80211 vendor command/event APIs, netlink attribute policies, mac80211 `wiphy_to_ieee80211_hw()`, MVM private object lookup, and MEI/CSME helper functions from the MVM layer.

Risks: `iwl_mvm_send_roaming_forbidden_event()` calls `ieee80211_vif_to_wdev(vif)` during allocation before checking `WARN_ON(!vif)`, so a null `vif` caller would already be unsafe. The reply skb size is fixed at 200 bytes and depends on the bounded SSID/BSSID attributes remaining small. Policy covers more attributes than each command consumes and does not validate command-specific required inputs because current commands are effectively getters. Command registration overwrites wiphy vendor pointers, so ordering matters if other code also sets them.

Test signals: Validate vendor command discovery, CSME info success and missing-info `-EINVAL`, reply allocation failure, netlink `nla_put` failure cleanup, ownership transfer return propagation, event emission with valid vif, event allocation failure, attribute encoding lengths, and lockdep coverage for `mvm->mutex`.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/ctxt-info-v2.c

Purpose: Builds, kicks, and frees PCIe context-info v2 firmware self-load structures for newer Intel devices, including PRPH scratch/control data, PRPH info, IML image DMA, debug monitor destinations, PNVM payload DRAM, and reduced-power payload DRAM.

Important APIs/functions: `iwl_pcie_ctxt_info_v2_alloc()` allocates and initializes PRPH scratch, firmware sections, PRPH info, context-info v2, and IML DMA. `iwl_pcie_ctxt_info_v2_kick()` writes context/IML addresses and size to CSR registers and enables automatic boot. `iwl_pcie_ctxt_info_v2_free()` tears down IML, firmware image DMA, and optionally context/scratch/info memory depending on whether firmware is alive. PNVM/reduced-power paths are `iwl_trans_pcie_ctx_info_v2_load_pnvm()`, `iwl_trans_pcie_ctx_info_v2_set_pnvm()`, `iwl_trans_pcie_ctx_info_v2_load_reduce_power()`, and `iwl_trans_pcie_ctx_info_v2_set_reduce_power()`.

Debug and allocation behavior: `iwl_pcie_ctxt_info_dbg_enable()` chooses early debug destination from legacy destination TLVs or INI allocation config, supporting internal SRAM, NPK/TB22DTF, or DRAM monitor buffers, and sets scratch debug flags plus DRAM base/size/token when applicable. A DMI allowlist for Dell/Alienware gates `IWL_PRPH_SCRATCH_SCU_FORCE_ACTIVE` on GL MAC type. Control flags encode RX buffer size, MTR mode/format, IMR debug, top reset, URM policy, and external 32 kHz clock validity.

Control flow: Allocation rejects default RX buffer size, derives command queue size, allocates scratch first, fills version/control/RBD/STEP/debug fields, calls shared `iwl_pcie_init_fw_sec()` to copy LMAC/UMAC/paging firmware sections into DMA and write scratch DRAM pointers, allocates a page for PRPH info plus dummy tail pointers, allocates context-info v2 and points it to scratch/info/RX/TX command ring structures, then allocates and copies the IML image. Kick enables context-info load interrupts, writes `CSR_CTXT_INFO_ADDR`, `CSR_IML_DATA_ADDR`, `CSR_IML_SIZE_ADDR`, and sets `CSR_AUTO_FUNC_BOOT_ENA`.

PNVM/reduced-power flow: Payloads are loaded only once and only for AX210 or newer. Fragmented-capable firmware gets a descriptor-array DMA object plus one DMA block per chunk; non-fragmented firmware expects exactly two payload chunks and concatenates them into one DMA block with overflow checks. Setters write either descriptor-array base plus total region size or contiguous base/size into PRPH scratch `pnvm_cfg` or `reduce_power_cfg`.

State and persistence: Mutates `trans_pcie->ctxt_info_v2`, `prph_info`, `prph_scratch`, `iml`, associated DMA addresses/lengths, `trans->init_dram`, `trans_pcie->pnvm_data`, `trans_pcie->reduced_tables_data`, and flags `trans->pnvm_loaded`/`trans->reduce_power_loaded`. When firmware reaches alive, context-info v2 and PRPH scratch are intentionally retained for later PNVM load; non-alive free releases them. PRPH info is documented as lifetime-needed.

Dependencies/integration: Uses shared DMA helpers from `ctxt-info.c`, context-info v2 firmware structs, PCIe transport private state from `gen1_2/internal.h`, firmware capabilities, PNVM image structures, DMI matching, debug/INI state, CSR/PRPH register helpers, and firmware image section layout.

Risks: Error paths in allocation free the top-level scratch/info/context objects but rely on later shared cleanup for firmware-section DMA already allocated by `iwl_pcie_init_fw_sec()`. PNVM setters assume successful prior load and valid scratch. Fragmented descriptor arrays must be large enough for `n_chunks` as defined by firmware structs. The non-fragmented path hard-requires two chunks. `control_flags_ext` is tested for `IWL_PRPH_SCRATCH_EXT_EXT_FSEQ` but this file does not set that bit. Lifetime split in `iwl_pcie_ctxt_info_v2_free(alive)` is subtle and can leak or use-after-free if call sites pass the wrong alive state.

Test signals: Cover RX buffer sizes, AX210 gating, DMI SCU force-active match/non-match, top reset, debug destinations for legacy and INI configs, allocation failures at each DMA stage, IML copy, CSR kick register writes, alive vs non-alive free, fragmented PNVM/reduced-power load with multiple chunks, contiguous two-chunk load and overflow, no-payload `-EINVAL`, duplicate-load no-op, busy scratch config `-EBUSY`, and PRPH scratch base/size fields after setters.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/ctxt-info.c

Purpose: Implements the original PCIe context-info firmware self-load setup and shared DMA helpers used by both context-info generations. It allocates 4 GB-boundary-safe coherent memory, copies firmware LMAC/UMAC/paging sections into DMA, initializes context-info RX/TX/DRAM descriptors, kicks firmware load, and frees context/paging/firmware DMA memory.

Important APIs/functions: `iwl_pcie_ctxt_info_dma_alloc_coherent()` wraps coherent allocation with retry logic to avoid crossing a 2^32 boundary. `iwl_pcie_ctxt_info_alloc_dma()` allocates and copies one firmware/data block into `struct iwl_dram_data`. `iwl_pcie_ctxt_info_free_paging()` frees self-init paging blocks. `iwl_pcie_init_fw_sec()` splits a `fw_img` into LMAC, UMAC, and paging sections using separator markers and populates `trans->init_dram` plus firmware-visible DRAM pointer arrays. `iwl_pcie_ctxt_info_init()` builds the legacy `iwl_context_info`; `iwl_pcie_ctxt_info_free()` tears it down.

Control flow: The DMA allocator recursively retries at most two levels when a coherent allocation crosses a 4 GB boundary, freeing the unsuitable allocation after a replacement is obtained. Firmware section initialization counts LMAC sections until `CPU1_CPU2_SEPARATOR_SECTION`, UMAC sections after one separator, and paging sections after two separators, then allocates arrays for firmware and paging DMA records and copies each section. Legacy context init allocates the context, writes version/MAC/size, encodes RX buffer and completion-buffer sizes, points RBD/used/status addresses at the initialized RX queue, points the command queue address/size at the transport TX command queue, initializes firmware sections, enables load interrupts, applies debug destination if present, and writes `CSR_CTXT_INFO_BA`.

State and persistence: Mutates `trans->init_dram.fw`, `fw_cnt`, `paging`, and `paging_cnt`; `trans_pcie->ctxt_info`, `ctxt_info_dma_addr`; and hardware CSR registers. Firmware section DMA is freed at alive or failure by `iwl_pcie_ctxt_info_free_fw_img()` from `internal.h`; paging memory has different lifetime and is freed by `iwl_pcie_ctxt_info_free_paging()`.

Dependencies/integration: Depends on Linux DMA coherent APIs, firmware image section layout, context-info firmware structs, RX/TX queue DMA addresses in `iwl_trans_pcie`, `iwl_pcie_get_num_sections()` and `iwl_txq_crosses_4g_boundary()` from `internal.h`, interrupt/debug helpers, and CSR/PRPH register writes.

Risks: If `dram->paging` allocation fails after `dram->fw` allocation, the function returns without local cleanup; callers must later clean partially initialized state. Similar partial failures during section copy can leave DMA allocations in `trans->init_dram`. The retry allocator can still fail if repeated allocations cross the boundary. RX buffer size mapping treats 12K as 16K context encoding. Command queue and RX queue pointers must already be allocated and DMA mapped. Section counting assumes separators exist in the expected order.

Test signals: Exercise 4 GB boundary retry, allocation failure after each stage, firmware images with expected and missing separators, LMAC/UMAC/paging counts, RX buffer sizes 2K/4K/8K/12K/default warning, completion-buffer size clamp, debug destination application, CSR context base write, freeing context twice, paging free with null/non-null arrays, and leak checks after partial init failures.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/drv.c

Purpose: Provides the top-level Linux PCI driver binding for Intel iwlwifi PCIe devices. It defines the supported PCI ID table, maps hardware IDs/subsystem/RF characteristics to detailed device configs and marketing names, probes/removes gen1/gen2 PCIe transports, handles sleep/resume/restore, exposes coredump forwarding, and registers/unregisters the `pci_driver`.

Important APIs/data: `iwl_hw_card_ids[]` is the PCI device-id match table used by the kernel module loader. `iwl_dev_info_table[]` is the richer device-info table used after hardware/RF discovery to select `struct iwl_cfg`, name, device/subdevice masks, RF type/id, CDB, bandwidth limit, and discrete/integrated matching. `iwl_pci_find_dev_info()` searches that table from the end so more specific or newer entries override earlier fallbacks. `iwl_pci_probe()`, `iwl_pci_remove()`, `_iwl_pci_resume()`, `iwl_pci_register_driver()`, and `iwl_pci_unregister_driver()` are the lifecycle entry points.

Table/macro behavior: `IWL_PCI_DEVICE()` stores a compile-time type-checked pointer to `struct iwl_mac_cfg` in `driver_data`. `IWL_DEV_INFO()` defaults device/subdevice to wildcard and subdevice mask to all 16 bits. `SUBDEV_MASKED()` includes compile-time checks for contiguous masks and stores low/high mask bit positions. Match macros represent RF type, RF id, CDB capability, bandwidth limit, and discrete/integrated form-factor constraints. Conditional compilation divides legacy DVM, MVM, and MLD devices.

Probe/control flow: `iwl_pci_probe()` repairs invalid BAR0 caused by possible runtime PM races, enables the PCI device with managed APIs, sets bus mastering, requests all BARs, maps BAR0, reads `CSR_HW_REV` directly before a transport exists, rejects `0xffffffff`, and delegates to `iwl_pci_gen1_2_probe()` with the selected `mac_cfg`, mapped base, and hardware revision. Remove fetches the transport from PCI driver data and delegates to `iwl_pcie_gen1_2_remove()`.

Power-management flow: Suspend intentionally does nothing because WoWLAN may need the NIC alive. Resume/restore clears PCI retry timeout, skips work when no opmode exists, detects whether the device was powered off using BZ+ scratch bits or older NIC-access probing, resets transport state and notifies opmode on restore/power loss, leaves WoWLAN-enabled devices to D3 resume if still enabled, otherwise reconfigures MSI-X mapping and reenables RF-kill interrupts under the transport mutex.

State and persistence: Static tables persist for module lifetime and are exported for KUnit where configured. Probe stores transport state through downstream gen1_2 setup, maps BAR memory with device-managed lifetime, and sets PCI master. Resume mutates PCI config byte `PCI_CFG_RETRY_TIMEOUT`, `trans->state`, NIC activation state, MSI-X masks, RF-kill interrupt state, and opmode power-loss notification state.

Dependencies/integration: Integrates with Linux PCI/module/PM/coredump APIs, ACPI firmware helpers indirectly through included headers, iwlwifi config objects declared elsewhere, CSR register definitions, PCIe gen1_2 transport probe/remove and resume helpers, opmode callbacks, RF-kill handling, NIC access helpers, and KUnit visibility macros.

Risks: The correctness of device identification depends on enormous manually maintained tables and reverse-order matching. Wildcard entries can shadow specific entries if ordering is wrong. Mask macros assume nonzero contiguous masks. Resume power-loss detection is family-specific and must avoid disrupting WoWLAN. Direct BAR0 reassignment is a workaround for runtime PM races but can fail early. `iwl_pci_dump()` assumes a valid transport/opmode path from coredump invocation.

Test signals: KUnit table tests for `iwl_pci_find_dev_info()` precedence, wildcard fallback, subdevice masks, RF/CDB/BW/discrete filters, and empty table behavior. Probe tests should cover BAR0 invalid reassignment, enable/request/iomap/read failures, `CSR_HW_REV=0xffffffff`, and delegation arguments. PM tests should cover BZ scratch powered-off/alive states, old NIC access success/failure, restore vs resume, WoWLAN status enabled, MSI-X reconfiguration, RF-kill interrupt rearm, and retry-timeout register writes.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/internal.h

Purpose: Defines the private internal contract for the gen1/gen2 iwlwifi PCIe transport. It contains RX/TX descriptor structures, allocator state, interrupt/debug/reset enums, the large `iwl_trans_pcie` transport-private state object, inline queue/interrupt/DMA helpers, and prototypes shared across PCIe RX, TX, IRQ, firmware-load, debug, D3, and probe/remove implementation files.

Important APIs/types: RX types include `iwl_rx_mem_buffer`, `iwl_rx_transfer_desc`, completion descriptors, `iwl_rxq`, and `iwl_rb_allocator`. TX types include `iwl_pcie_txqs`, TSO header/page metadata, queue-index helpers, TFD/TB helpers, and command allocation wrappers. `struct iwl_trans_pcie` stores almost all PCIe transport state: RX queues and pools, context-info v1/v2 pointers, PRPH scratch/info/IML DMA, transport pointer, NAPI device, ICT, IRQ masks/vectors, register locks, PNVM/reduced-power DRAM regions, TX queues, firmware/reset/imr wait states, ME presence work, command pool, power-management flags, and coredump/debug fields.

Inline control behavior: `IWL_TRANS_GET_PCIE_TRANS()` accesses transport-private memory; `iwl_pcie_clear_irq()` clears MSI-X automask bits; `iwl_get_closed_rb_stts()` abstracts old vs AX210+ receive status formats; queue helpers wrap/decrement indexes according to max TFD queue size and gen2 command windowing; `iwl_txq_stop()` and `iwl_trans_pcie_wake_queue()` update stopped bits and notify opmode; `iwl_txq_crosses_4g_boundary()` detects hardware-sensitive DMA spans; TSO helpers recover DMA addresses from page trailers.

Interrupt control flow: `_iwl_disable_interrupts()` clears `STATUS_INT_ENABLED`, masks and acknowledges legacy INTx/MSI interrupts or writes MSI-X FH/HW masks and clears cached masks. `_iwl_enable_interrupts()` sets status and restores initial masks for legacy or MSI-X. `iwl_enable_fw_load_int()`, `iwl_enable_fw_load_int_ctx_info()`, and `iwl_enable_rfkill_int()` select the minimal interrupt causes needed for firmware copy, context-info alive/reset, or RF-kill wake. Public wrappers take `irq_lock` with BH disabled.

State and persistence: The header declares persistent state rather than owning executable storage. Important persisted fields include RX free/used lists and status DMA, queue used/stopped bitmaps, context-info and firmware-load DMA pointers, PRPH scratch/info, PNVM/reduced-power data regions, interrupt masks and vector topology, transport/opmode down flags, firmware reset and IMR state machines, wait queues, RF-kill debug override, ME/CSME detection, command allocation cache, and PM/LTR capability flags.

Dependencies/integration: Includes Linux spinlock/interrupt/skbuff/wait/pci/timer/cpu headers plus iwlwifi FH/CSR/transport/debug/IO/opmode/driver/context-info headers. Prototypes connect to RX, ICT, TX/HCMD, error dump, debugfs, firmware monitor, D3 suspend/resume, NIC access, PRPH/MMIO access, firmware start/alive/stop, PCI probe/remove, MSI-X configuration, PNVM DMA cleanup, and gen2 command enqueue implementations.

Risks: Because this is a shared private header, structure layout or semantic changes can break many transport files. Locking expectations are implicit for `irq_lock`, `reg_lock`, `mutex`, allocator locks, wait queues, and NIC access release annotations. Interrupt mask polarity differs between legacy and MSI-X paths. RX status interpretation differs by device family. Queue index wrapping assumes power-of-two max queue sizes. DMA boundary constraints matter even with 32-bit `dma_addr_t`. Several documentation comments contain stale wording (`ctxt_info_v2` comment says v1 devices, duplicate `ctxt_info_dma_addr`), so comments are not always authoritative.

Test signals: Compile all PCIe transport variants, sparse/lockdep for NIC access and interrupt locking, KUnit or fault-injection for queue index helpers, 4 GB boundary detection, RX status format selection, interrupt enable/disable masks for legacy/MSI-X/context-info/RF-kill, queue stop/wake opmode callbacks, TSO page DMA address calculation, firmware section counting/free helpers, RF-kill debug override, PM/LTR getters, and ABI-sensitive struct initialization paths in probe/start/stop/free code.
