# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-sdm660.c

## Purpose
`gcc-sdm660.c` is the Qualcomm Global Clock Controller provider for Snapdragon 630/660-class SoCs. It describes the GCC register block as Linux common clock framework objects, exposes clock IDs from `dt-bindings/clock/qcom,gcc-sdm660.h`, and provides reset and GDSC power-domain control for the major on-chip peripheral islands. The modeled clock tree covers the XO and sleep inputs, GPLL0/GPLL1/GPLL4 and their early/divided paths, BLSP1/BLSP2 I2C/SPI/UART roots, general-purpose clocks, HMSS/RBCPR roots, QSPI, PDM, SDCC/eMMC/ICE, UFS, USB2/USB3, GPU/MMSS/MSS fabric clocks, and voted LPASS/Turing SMMU clocks.

## Important APIs, Types, And Functions
The file is almost entirely declarative data consumed by the qcom clock-controller helpers. Important object types are `struct clk_fixed_factor` for `xo` and early GPLL dividers, `struct clk_alpha_pll` for early PLL instances, `struct clk_alpha_pll_postdiv` for consumer-facing GPLL outputs, `struct clk_rcg2` plus `struct freq_tbl` for rate-programmable roots, `struct clk_branch` for gateable leaves, `struct gdsc` for power domains, `struct qcom_reset_map` for reset-controller lines, and `struct qcom_cc_desc` for final provider registration.

Parent maps encode the hardware parent selector values for XO, sleep, GPLL0, GPLL1, GPLL4, and divided early PLL paths. The main export arrays are `gcc_sdm660_hws[]`, `gcc_sdm660_clocks[]`, `gcc_sdm660_gdscs[]`, and `gcc_sdm660_resets[]`; they are gathered into `gcc_sdm660_desc`. `gcc_sdm660_probe()` is the only custom runtime function. It maps the GCC MMIO block with `qcom_cc_map()`, sets the HMSS AHB sleep-enable bit via `regmap_update_bits()`, and registers clocks, resets, and GDSCs with `qcom_cc_really_probe()`.

## Control Flow
Driver registration happens through `core_initcall_sync(gcc_sdm660_init)`, so the GCC provider is available early for platform devices. Device-tree matching accepts both `qcom,gcc-sdm630` and `qcom,gcc-sdm660`. At probe, qcom CC code creates the regmap using the descriptor's `regmap_config` (`32` bit registers, stride `4`, max register `0x94000`, fast I/O). The one SoC-specific probe action is setting bit 21 at register `0x52008`, allowing `hmss_ahb_clk` to be turned off by hardware during selected low-power modes. After that, all behavior is handed to the shared qcom CC registration path.

Runtime clock operations are table-driven. RCG2 frequency tables provide legal rates and parent/divider/MND settings for serial, storage, USB, UFS, HMSS, and general-purpose roots. Branch clocks refer to those roots with `CLK_SET_RATE_PARENT` where a leaf should propagate rate requests upward. Halt checks vary by hardware block: ordinary clocks use `BRANCH_HALT`, voted branches use `BRANCH_VOTED` or `BRANCH_HALT_VOTED`, slow/pipe-style clocks sometimes use delayed or skipped halt checks, and a small set carries `CLK_IS_CRITICAL` or `CLK_IGNORE_UNUSED` for boot-sensitive paths.

## State And Persistence
There is no filesystem or nonvolatile persistence. Static C descriptors define the expected hardware topology; live state is held in GCC registers and in the common clock framework's registered clock tree. Probe-time writes to `0x52008` persist only for the current boot. PLL enable state, parent selection, divider values, M/N/D values, branch gates, reset assertions, and GDSC power state are all hardware-backed. GDSCs for UFS, USB3, PCIe, and voted LPASS/Turing ADSP domains use `PWRSTS_OFF_ON`, so consumers can power those domains through Linux power-domain APIs. Reset state is exposed through reset-controller consumers and is not cached as durable state by this file.

## Dependencies And Integration Points
The driver depends on Linux platform-driver, OF match, regmap, CCF, reset-controller, and qcom-specific helpers in `common.h`, `clk-regmap.h`, `clk-alpha-pll.h`, `clk-rcg.h`, `clk-branch.h`, `reset.h`, and `gdsc.h`. External parent clocks are supplied by firmware/device tree under names such as `xo` and `sleep_clk`; internal parents are the in-file GPLL hardware clocks. Consumers integrate by referencing the SDM660 binding IDs for BLSP serial controllers, SDCC/eMMC and ICE, QSPI, PDM, USB2/USB3 controllers and PHYs, UFS controller/PHY, GPU/MMSS/MSS fabrics, HMSS RBCPR, LPASS/Turing SMMU votes, PCIe power domain, and modem restart reset.

## Risks
Parent-map correctness is the main maintenance risk. Hardware selector values are sparse and not identical across maps, especially for GPLL0 early divider, GPLL1/GPLL4, and sleep-clock alternatives. A plausible parent-data change can silently program the wrong source. Clock-critical flags should be changed conservatively: `gcc_gpu_cfg_ahb_clk` and MMSS/GPU related GPLL branches include critical or ignore-unused behavior that can affect boot or display/GPU handoff. UFS and USB symbol/pipe clocks use skipped or delayed halt checks; replacing those with strict halt polling can cause false timeouts. Reset offsets are close to live controller blocks, and the reset table includes storage, USB PHY, USB controller, and MSS restart lines, so offset or binding-ID mistakes have broad hardware impact.

## Test Signals
Expected boot signals are a successful `gcc-sdm660` platform probe, no `qcom_cc_really_probe()` errors, and clock/reset/power-domain providers visible to device-tree consumers. `clk_summary` should show XO, GPLL0/GPLL1/GPLL4 early and postdiv outputs, BLSP1/BLSP2 QUP and UART roots, HMSS GPLL/RBCPR roots, SDCC1/SDCC2 and ICE clocks, UFS AXI/Unipro/AUX/symbol clocks, USB20/USB30 master/mock/sleep/pipe clocks, and voted LPASS/Turing SMMU clocks. Hardware validation should cover serial console and I2C/SPI, eMMC/SD including ICE where present, UFS attach, USB2 and USB3 enumeration, QSPI, GPU/display/MMSS clients, modem restart handling, low-power entry exercising the HMSS AHB sleep bit, and reset assert/deassert tests for representative storage, USB, PHY, and MSS lines.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-sdm845.c

## Purpose
`gcc-sdm845.c` is the Qualcomm GCC provider for Snapdragon 845 and Snapdragon 670-class SoCs. It registers the central clock, reset, and GDSC power-domain provider for high-speed storage, USB, PCIe, QUPv3 serial engines, CPU subsystem support clocks, camera/display/video fabric votes, GPU and modem fabric clocks, voltage-sensor/control clocks, and optional LPASS links. The same source supports two compatible strings, `qcom,gcc-sdm845` and `qcom,gcc-sdm670`, with separate clock and GDSC descriptor arrays where the SoCs differ.

## Important APIs, Types, And Functions
The driver uses modern qcom clock framework descriptors: `struct clk_alpha_pll` for FABIA GPLL0/GPLL4/GPLL6, `struct clk_alpha_pll_postdiv` for `gpll0_out_even`, `struct clk_rcg2` and `struct freq_tbl` for root generators, `struct clk_init_data` for repeated QUPv3 source initialization, `struct clk_branch` for leaf gates, `struct gdsc` for power domains, `struct qcom_reset_map` for reset lines, `struct clk_rcg_dfs_data` for dynamic frequency scaling registration, and `struct qcom_cc_desc` for provider registration.

The major arrays are `gcc_sdm670_clocks[]`, `gcc_sdm845_clocks[]`, `gcc_sdm670_gdscs[]`, `gcc_sdm845_gdscs[]`, `gcc_sdm845_resets[]`, `gcc_sdm670_desc`, and `gcc_sdm845_desc`. `gcc_sdm845_probe()` maps the regmap, programs two MISC registers to disable the GPLL0 active input to MMSS/GPU, registers DFS metadata for all sixteen QUPv3 serial RCGs, selects the match-specific descriptor with `of_device_get_match_data()`, and calls `qcom_cc_really_probe()`.

## Control Flow
Initialization uses `core_initcall(gcc_sdm845_init)`, and module metadata declares a soft dependency on `rpmhpd` so RPMh power domains are available first. Probe initially maps the GCC block using `gcc_sdm845_desc` because SDM670 and SDM845 share the same register map (`max_register = 0x182090`). It then writes `0x3` to mask `0x3` at registers `0x09ffc` and `0x71028`, a hardware workaround/commented setup for MMSS and GPU GPLL0 active input behavior. DFS support is registered for `gcc_qupv3_wrap{0,1}_s{0..7}_clk_src` before the provider is published. The final descriptor comes from the OF match data, which selects SDM670-specific or SDM845-specific clock and GDSC arrays.

Most runtime behavior is generic CCF/qcom CC behavior. Frequency tables describe CPUSS AHB/RBCPR, GP clocks, PCIe auxiliary and refgen roots, QSPI, PDM, QUPv3 serial rates, SDCC1/2/4, TSIF, UFS card and UFS PHY paths, USB3 primary/secondary paths, voltage sensor/control clocks, and related fabric clocks. Branches gate the leaf clocks, often using `CLK_SET_RATE_PARENT` to let consumers request rates on underlying RCGs. Some branches are critical, including selected camera/display/video XO/fabric paths, CPUSS/sysnoc paths, and optional LPASS clocks under `CONFIG_SDM_LPASSCC_845`.

## State And Persistence
State is held in static descriptors and live GCC registers. There is no disk persistence. Probe-time MISC register writes and DFS registration affect the current boot only. PLLs use fixed FABIA ops and are exposed as common clock providers; branch gates, parent selections, dividers, and MND values are programmed through regmap-backed qcom clock ops. GDSCs for PCIe, UFS card/PHY, USB3 primary/secondary, and HLOS-voted TBU/MMU domains use `PWRSTS_OFF_ON`, with several hardware-domain entries also using `POLL_CFG_GDSCR`. SDM670 omits several SDM845-only domains while sharing the reset table because it can function without exclusive reset definitions.

## Dependencies And Integration Points
The file depends on platform/OF/regmap/CCF support, `dt-bindings/clock/qcom,gcc-sdm845.h`, and qcom helpers `common.h`, `clk-regmap.h`, `clk-pll.h`, `clk-rcg.h`, `clk-branch.h`, `clk-alpha-pll.h`, `gdsc.h`, and `reset.h`. Parent clocks are supplied by firmware/device tree as `bi_tcxo`, `bi_tcxo_ao`, `sleep_clk`/`core_pi_sleep_clk`, `aud_ref_clk`, and `core_bi_pll_test_se`; internal parents are GPLL0, GPLL0 even output, GPLL4, and GPLL6. Integration points include QUPv3 serial drivers, SDHCI/eMMC/SD and ICE, UFS host/PHY/card, USB3 primary/secondary controllers and PHYs, PCIe controllers and PHYs, QSPI, PDM/PRNG/TSIF, GPU/display/camera/video clock consumers, modem subsystem fabric clocks, voltage sensor/control drivers, HLOS SMMU/TBU power votes, and optional LPASS clocking.

## Risks
This file has high risk from variant handling. SDM670 and SDM845 share many binding IDs and reset entries but differ in clock arrays, SDCC/CPUSS frequency tables, PCIe/UFS-card/USB-secondary availability, and GDSC coverage; adding a clock to one array but not the other can expose an invalid ID or hide a valid consumer clock. QUPv3 DFS registration must stay in sync with the sixteen QUP source clocks or serial frequency scaling can fail after probe. Parent maps use multiple sparse encodings for `bi_tcxo`, GPLL0 main/even, GPLL4, GPLL6, sleep, and audio reference parents. The probe-time MISC writes are unchecked, so incorrect offsets or masks would not be reported unless downstream hardware fails. Critical clock flags and LPASS conditional compilation are boot-sensitive, and changing GDSC `POLL_CFG_GDSCR` behavior can alter power-domain sequencing.

## Test Signals
Basic validation is successful probe for both `qcom,gcc-sdm845` and `qcom,gcc-sdm670` device trees, no DFS registration errors, and visible clock/reset/GDSC providers. `clk_summary` should show FABIA GPLL0/GPLL4/GPLL6, `gpll0_out_even`, QUPv3 wrap0/wrap1 source and branch clocks, CPUSS AHB/RBCPR, SDCC clocks, USB3 primary/secondary paths as applicable, UFS PHY/card clocks as applicable, PCIe clocks for SDM845, QSPI, PDM, TSIF, voltage sensor/control clocks, and critical camera/display/video fabric clocks. Hardware tests should cover UART/I2C/SPI on QUPv3, SD/eMMC, UFS, USB3, PCIe link training, GPU/display/camera/video client probe, modem subsystem boot, low-power suspend/resume with GDSCs, and reset assertion for QUP, storage, USB PHY, PCIe, TSIF, PRNG, and MMSS lines.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-sdx55.c

## Purpose
`gcc-sdx55.c` is the Qualcomm GCC provider for the SDX55 modem/platform SoC. It registers central clocks, resets, and GDSC power domains for BLSP1 serial controllers, CPUSS support clocks, Ethernet/EMAC, PCIe, USB3, SDCC1, crypto engine CE1, PDM, general-purpose clocks, and a small set of always-on/fabric paths. Compared with the SDM phone SoC drivers in this group, SDX55 is narrower and modem/networking oriented, with explicit EMAC and PCIe support and only one USB3/SDCC path.

## Important APIs, Types, And Functions
The driver uses `struct clk_alpha_pll` and `struct clk_alpha_pll_postdiv` with LUCID PLL ops for GPLL0, GPLL4, GPLL4 even, and GPLL5, plus a `pll_vco` table defining the supported LUCID VCO range. `struct clk_rcg2` and `struct freq_tbl` define rate roots for BLSP I2C/SPI/UART, CPUSS AHB/RBCPR, EMAC/RGMII/PTP, GP clocks, PCIe auxiliary/refchange PHY, PDM, SDCC1, USB3 master/mock/AUX, and related paths. `struct clk_branch` gates leaf clocks with normal, voted, delayed, or rate-parent-aware behavior. The provider is described through `gcc_sdx55_clocks[]`, `gcc_sdx55_resets[]`, `gcc_sdx55_gdscs[]`, and `gcc_sdx55_desc`.

The only custom function is `gcc_sdx55_probe()`. It maps the GCC regmap with `qcom_cc_map()`, forces selected system NoC/CPUSS clocks on with `qcom_branch_set_clk_en()` and `regmap_update_bits()`, and then registers the provider through `qcom_cc_really_probe()`. Driver registration is via `subsys_initcall(gcc_sdx55_init)`, and matching is for `qcom,gcc-sdx55`.

## Control Flow
At boot, the platform driver probes the GCC node, maps registers with a `regmap_config` covering 32-bit registers up to `0x9b040`, and performs three keep-on writes at register `0x6d008`: branch enable for `GCC_SYS_NOC_CPUSS_AHB_CLK`, bit 21 for `GCC_CPUSS_AHB_CLK`, and bit 22 for `GCC_CPUSS_GNOC_CLK`. These writes preserve critical CPU/fabric connectivity before the clock framework begins unused-clock management. After registration, CCF consumers drive all rate, parent, and gate changes through the shared qcom clock ops.

The declarative clock tree starts with `bi_tcxo`, `bi_tcxo_ao`, sleep, GPLL0 main/even, GPLL4 even, and GPLL5 parents. RCGs provide selectable rates for serial buses, Ethernet, PCIe, SDCC, USB3, and general-purpose outputs. Branches gate BLSP QUP/UART clocks, CE1, EMAC/ETH AXI/PTP/RGMII/AHB, PCIe link/master/slave/pipe/ref clocks, PDM, SDCC1, USB30 master/mock/AXI/AHB/sleep/PHY clocks, and XO/NoC helper clocks.

## State And Persistence
There is no persistent state outside hardware registers and CCF registration. Static descriptors define the clock topology; live hardware state tracks PLL enable, post-divider selection, RCG parent and divider programming, branch gates, reset lines, and GDSC power domains. Probe-time keep-on writes persist for the current boot and are not re-applied after a full hardware reset except by a new probe. GDSCs for USB30, PCIe, and EMAC use `PWRSTS_OFF_ON`, allowing power-domain consumers to sequence those blocks through Linux. Reset lines cover EMAC, PCIe core/link/PHY/PHY common, QUSB2PHY, USB30, USB3 PHY, USB3PHY PHY, and USB PHY CFG AHB2PHY.

## Dependencies And Integration Points
The driver depends on Linux platform, module, regmap, CCF, `dt-bindings/clock/qcom,gcc-sdx55.h`, and qcom common headers `common.h`, `clk-alpha-pll.h`, `clk-branch.h`, `clk-pll.h`, `clk-rcg.h`, `clk-regmap.h`, `gdsc.h`, and `reset.h`. Parent clocks are firmware-provided `bi_tcxo`, `bi_tcxo_ao`, and `sleep_clk`, plus in-file GPLLs. Integration points include BLSP1 I2C/SPI/UART controllers, CPUSS low-level bus support, CE1 crypto, EMAC/Ethernet MAC and PTP/RGMII clock consumers, PCIe controller and PHY, SDCC1, USB3 controller/PHY, PDM audio, and reset-controller clients for the same high-speed peripheral blocks.

## Risks
The explicit keep-on sequence is boot-sensitive. Removing or moving the `0x6d008` writes can allow unused-clock cleanup or early handoff to disable CPU/fabric clocks needed by the SoC. Parent-map encodings are sparse, with GPLL4 even and GPLL5 occupying different selector values from GPLL0 main/even; copying SDM-style maps into SDX55 can select incorrect Ethernet, PCIe, or USB rates. Ethernet has distinct source, PTP, RGMII, AXI, and AHB clocks plus an EMAC GDSC/reset, so partial enablement may probe but fail traffic or timestamping. Several PCIe and USB branches use voted or delayed halt checks; stricter polling can create false failures during PHY/link transitions. Reset offsets include PCIe link-down and PHY common resets, which are easy to misuse from consumers if binding IDs drift.

## Test Signals
Expected signals are successful `qcom,gcc-sdx55` probe, visible GPLL0/GPLL4/GPLL5 clocks, and no errors from `qcom_cc_really_probe()`. `clk_summary` should show the always-on system NoC/CPUSS paths enabled, BLSP1 QUP/UART roots, CPUSS RBCPR, EMAC source/PTP/RGMII/AXI/AHB clocks, PCIe aux/refchange/pipe/master/slave/link clocks, SDCC1 clocks, USB30 master/mock/sleep/AXI/AHB/PHY clocks, PDM, and CE1. Hardware validation should cover serial buses, Ethernet link and PTP timestamping, PCIe link training and link-down reset behavior, USB3 enumeration, SDCC1, CE1 crypto, suspend/resume with USB30/PCIe/EMAC GDSCs, and reset assert/deassert tests for EMAC, PCIe, and USB PHY/controller lines.
