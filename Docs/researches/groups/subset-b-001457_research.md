# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/display/dc/resource/dcn315/dcn315_resource.c

Purpose: implements the DCN 3.1.5 display resource pool for AMDGPU Display Core. It binds DCN315 register tables, ASIC capability constants, constructor/destructor routines, DML pipe population, bandwidth hooks, link encoder creation, and DMUB-backed panel features into the generic `struct resource_pool` used by mode validation and hardware programming.

Important APIs/types/functions: the public entry point is `dcn315_create_resource_pool()`, which allocates `struct dcn315_resource_pool` and calls `dcn315_resource_construct()`. The file defines `res_cap_dcn31`, `plane_cap`, `debug_defaults_drv`, `config_defaults`, `panel_config_defaults`, `res_create_funcs`, `dcn315_res_pool_funcs`, and many static register/shift/mask tables for BIOS scratch, clock sources, ABM, audio, VPG/AFMT/APG, stream/link encoders, HPO DP, DPP, OPP, AUX/I2C, DWB/MMHUBBUB, DSC, MPC, OPTC, HUBP, HUBBUB, DCCG, HWSEQ, VMID, and DIO. Object constructors include `dcn31_dpp_create()`, `dcn31_opp_create()`, `dcn31_aux_engine_create()`, `dcn31_i2c_hw_create()`, `dcn31_mpc_create()`, `dcn315_dio_create()`, `dcn31_hubbub_create()`, `dcn31_timing_generator_create()`, `dcn31_link_encoder_create()`, `dcn31_link_enc_create_minimal()`, `dcn31_panel_cntl_create()`, `dcn31_create_audio()`, `dcn31_vpg_create()`, `dcn31_afmt_create()`, `dcn31_apg_create()`, `dcn315_stream_encoder_create()`, `dcn31_hpo_dp_stream_encoder_create()`, `dcn31_hpo_dp_link_encoder_create()`, `dcn31_hwseq_create()`, `dcn31_hubp_create()`, `dcn31_dsc_create()`, and `dcn31_clock_source_create()`.

Control flow: construction installs the DC BIOS register table, attaches `res_cap_dcn31` and `dcn315_res_pool_funcs`, hard-codes display caps/debug defaults, queries VBIOS LTTPR caps, initializes VM helper state, and then allocates resources in dependency order: five PLL clock sources plus DP DTO, DCCG, DCN315 IRQ service, HUBBUB, DIO, per-pipe HUBP/DPP, OPP, timing generator, DMUB PSR, DMUB Replay, per-pipe ABM, MPC, three DSCs, DWB/MMHUBBUB, AUX/I2C engines, and common audio/stream/HPO/virtual encoder/LUT resources through `resource_construct()`. It then constructs the DCN31 hardware sequencer, publishes plane caps, max ODM factor, cap functions, and `dc->dcn_ip->max_num_dpp` from `dcn3_15_ip`. Any allocation or constructor failure jumps to `create_fail`, destructs all partially-created resources, and returns false so the public creator can free the pool.

State and persistence behavior: persistent state is the allocated resource pool and the `dc` capability/debug/config fields set during construction. Hardware state is represented through register offsets and object instances; the file itself has no disk persistence. `dcn315_resource_destruct()` releases stream encoders and their VPG/AFMT children, HPO stream/link encoders and VPG/APG children, DSCs, MPC, HUBBUB, DIO, DPP/IPP/HUBP pipes, IRQ service, DDC/AUX/I2C engines, OPPs, timing generators, DWB/MMHUBBUB, audio blocks, clock sources, MPC 3D LUT/shaper references, DP clock source, ABMs, PSR, Replay, and DCCG. Runtime validation mutates `context->bw_ctx.dml` fields such as DET size, DCC fractions, DSC input bpc, immediate flip, and unbounded request mode.

Dependencies and integration points: integrates with DC core resource management (`resource_construct`, link encoder config, pipe acquire/release, stream add/remove), DCN31/DCN30/DCN20 block constructors, DMUB ABM/PSR/Replay, DML/FPU helpers from `dcn31_fpu`, BIOS LTTPR callbacks, IRQ service `dal_irq_service_dcn315_create()`, VM helper initialization, and generic bandwidth/watermark entry points (`dcn31_validate_bandwidth`, `dcn31_calculate_wm_and_dlg`). Register definitions are DCN 3.1.5 and DPCS 4.2.2 specific, while several functional blocks reuse DCN31 constructors.

Risks and test signals: the destructor calls `dal_irq_service_destroy()` inside the pipe loop, so review should confirm repeated NULL-guarded destruction is intentional and safe. The file relies on many parallel resource counts; mismatches between `res_cap_dcn31` and array sizes can lead to out-of-bounds register-table access. The pixel-rate CRB path in `dcn315_populate_dml_pipes_from_context()` is narrowly gated to two-stream eDP/no-scaling/no-MPO scenarios and adjusts DET overrides by segment counts, so regressions show up as bandwidth validation failures, unexpected pipe splits, or p-state flicker. Test signals include successful DCN315 probe, AUX/I2C/HPD operation on all five DDC engines, DP HPO and HDMI/PCON link bring-up, PSR/Replay/ABM DMUB interactions, DSC allocation for three compressors, MPO/ODM transitions, validation of immediate flip without underflow, and dual-stream eDP CRB behavior with and without scaling.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/display/dc/resource/dcn315/dcn315_resource.h

Purpose: declares the DCN315 private resource-pool wrapper and factory used by the Display Core resource selection layer.

Important APIs/types/functions: defines `TO_DCN315_RES_POOL(pool)` for converting a base `struct resource_pool *` to `struct dcn315_resource_pool *`, declares external DML/IP parameter block `dcn3_15_ip`, defines `struct dcn315_resource_pool { struct resource_pool base; }`, and declares `dcn315_create_resource_pool(const struct dc_init_data *init_data, struct dc *dc)`.

Control flow: no runtime control flow in the header. Inclusion enables chip-family selection code to call `dcn315_create_resource_pool()` and lets the implementation recover the enclosing allocation during destruction.

State and persistence behavior: the only state shape introduced is a thin wrapper around the generic `resource_pool`; all persistent runtime state is owned by the constructed base pool in the `.c` file.

Dependencies and integration points: includes `core_types.h` for `struct resource_pool`, `struct dc_init_data`, and `struct dc`. The external `dcn3_15_ip` symbol connects this resource file to DCN315 DML/IP bounding-box data used when publishing `dc->dcn_ip->max_num_dpp`.

Risks and test signals: because the wrapper contains only `base`, lifetime and layout correctness depend on using the matching `TO_DCN315_RES_POOL` macro in the DCN315 destroy path. Build coverage should catch missing `dcn3_15_ip` or factory symbols; runtime probe should verify DCN315 selects this factory rather than a neighboring DCN31 variant.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/display/dc/resource/dcn316/dcn316_resource.c

Purpose: implements the DCN 3.1.6 resource pool. It is a close DCN31-family variant of DCN315 with DCN316 register headers, DPCS 4.2.3 tables, DCN316 DML/IP parameters, a DCN31 IRQ service, and slightly different bandwidth/debug/capability defaults.

Important APIs/types/functions: the public entry point is `dcn316_create_resource_pool()`, backed by `dcn316_resource_construct()` and `dcn316_resource_destruct()`. Static capability and config objects include `res_cap_dcn31`, `plane_cap`, `debug_defaults_drv`, `config_defaults`, `panel_config_defaults`, `res_create_funcs`, `cap_funcs`, and `dcn316_res_pool_funcs`. Constructor helpers mirror the DCN31 stack: DPP, OPP, AUX, I2C, MPC, `dcn316_dio_create()`, HUBBUB, timing generator, link encoders, panel control, audio, VPG/AFMT/APG, `dcn316_stream_encoder_create()`, HPO stream/link encoders, HWSEQ, HUBP, DSC, DWB/MMHUBBUB, and clock sources. DML customization lives in `dcn316_populate_dml_pipes_from_context()` and the bounding-box update wrapper `dcn316_update_bw_bounding_box()`.

Control flow: construction sets the BIOS register table, resource caps, and function table; publishes ASIC/display caps; queries LTTPR support; installs production debug defaults; initializes VM helper state; then creates clock sources, DCCG, IRQ service through `dal_irq_service_dcn31_create()`, HUBBUB, DIO, HUBP/DPP/OPP/TG blocks, DMUB PSR, ABMs, MPC, three DSCs, DWB/MMHUBBUB, AUX/I2C engines, and the common audio/stream/HPO/virtual encoder resources via `resource_construct()`. It completes by constructing the DCN31 hardware sequencer, copying plane caps, setting max ODM combine to four, assigning cap funcs, and setting `dc->dcn_ip->max_num_dpp` from `dcn3_16_ip`. Failure follows a single `create_fail` path through the destructor.

State and persistence behavior: persistent runtime state is the resource pool plus the configured `dc->caps`, `dc->debug`, and DML fields. The DML pipe population path wraps `dcn31x_populate_dml_pipes_from_context()` in FPU guards, marks immediate flip required, disables unbounded requests by default, programs vfront porch, zeroes DCC fractions, derives DSC input bpc from timing color depth, and computes DET buffer size from `config_return_buffer_size_in_kbytes - DCN3_16_MIN_COMPBUF_SIZE_KB`, clamped to `DCN3_16_MAX_DET_SIZE` and asserted not below the default. Single-pipe Z9/MPC cases shrink DET for small dual-plane formats or set 192 KB plus unbounded mode for non-dual-plane formats.

Dependencies and integration points: depends on DCN 3.1.6 offset/mask headers, DPCS 4.2.3 definitions, BIOS scratch registers using the BIF_BX1 naming variant, DCN31/DCN30/DCN20 block constructors, DMUB ABM/PSR, DML/FPU helpers, VM helper, link encoder config, and common DC resource callbacks. Unlike DCN315, this file does not construct DMUB Replay and does not use the DCN315-specific IRQ service.

Risks and test signals: DCN316 differs subtly from DCN315: HDCP I2C speed defaults to 5 kHz, Replay is absent from the pool/destructor, no `no_native422_support` assignment appears here, DML population lacks the DCN315 pixel-rate CRB redistribution path, and the MPC register table includes DCN3AG RMU entries. Those differences are easy to regress during copy-forward edits. Test signals include DCN316 probe, correct IRQ registration through the DCN31 service, stable PSR/ABM without Replay allocation, expected low HDCP I2C speed workaround, DML DET assertions never firing, DSC bpc selection across 8/10/12 bpc modes, DP HPO link training, and successful teardown after partial-construction failure injection.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/display/dc/resource/dcn316/dcn316_resource.h

Purpose: declares the DCN316 private resource-pool wrapper and creation API for Display Core.

Important APIs/types/functions: defines `TO_DCN316_RES_POOL(pool)`, declares external DML/IP parameter block `dcn3_16_ip`, defines `struct dcn316_resource_pool { struct resource_pool base; }`, and declares `dcn316_create_resource_pool(const struct dc_init_data *init_data, struct dc *dc)`.

Control flow: no executable flow. The header supports family-specific factory dispatch and lets the implementation recover the enclosing allocation from the generic base pool pointer during destruction.

State and persistence behavior: introduces only the wrapper type around `struct resource_pool`; all runtime state is allocated and filled by `dcn316_resource_construct()` in the implementation.

Dependencies and integration points: includes `core_types.h` and exposes the `dcn3_16_ip` symbol used by the resource implementation to synchronize DC caps with the DCN316 DML/IP description.

Risks and test signals: the type is intentionally minimal, so accidental expansion or macro mismatch would affect destruction casts. Build signals are successful inclusion from DCN316 resource-selection code and resolution of `dcn316_create_resource_pool`/`dcn3_16_ip`; runtime signal is that DCN316 ASIC initialization lands on this factory and returns a populated base pool.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/display/dc/resource/dcn32/dcn32_resource.c

Purpose: implements DCN 3.2 resource construction and resource-management callbacks. Compared with the DCN31.x files, DCN32 adds runtime register-offset initialization from context arrays, pipe-harvest/fuse handling, DML2 option wiring, SubVP phantom stream/pipe support, MALL/CAB sizing, cursor limits under SubVP, and pipe-allocation heuristics for windowed MPO/ODM transitions.

Important APIs/types/functions: the public factory is `dcn32_create_resource_pool()`. Key resource functions are collected in `dcn32_res_pool_funcs`, including `dcn32_validate_bandwidth()`, `dcn32_calculate_wm_and_dlg()`, `dcn32_populate_dml_pipes_from_context()`, `dcn32_acquire_free_pipe_as_secondary_dpp_pipe()`, `dcn32_acquire_free_pipe_as_secondary_opp_head()`, `dcn32_add_phantom_pipes()`, `dcn32_calculate_mall_ways_from_bytes()`, and `dcn32_get_max_hw_cursor_size()`. The file defines `res_cap_dcn32`, `plane_cap`, `debug_defaults_drv`, `config_defaults`, `cap_funcs`, `res_create_funcs`, and constructor helpers for DCN32 AUX/I2C, clock sources, DIO, HUBBUB, HUBP, DPP, MPC, OPP, OPTC, link encoders, panel control, audio, VPG/AFMT/APG, stream encoders, HPO stream/link encoders, HWSEQ, DWB/MMHUBBUB, and DSC.

Control flow: `dcn32_resource_construct()` initializes mutable register tables with macros like `bios_regs_init()`, `clk_src_regs_init()`, `abm_regs_init()`, and `dccg_regs_init()`, assigns BIOS regs, reads `CC_DC_PIPE_DIS` fuses, reduces pipe counts, asserts unexpected pipe-0 or full-DCN harvest cases, and updates `dcn3_2_ip.max_num_dpp/max_num_otg`. It then sets resource functions and caps, computes MALL/CAB capacity from VRAM channel count, configures SubVP timing margins, color and ODM capabilities, DC config flags, LTTPR caps, debug defaults, and VM helper state. Resource creation proceeds through clock sources, DCCG, `dml_init_instance()`, DCN32 IRQ service, HUBBUB, DIO, non-fused per-pipe HUBP/DPP/OPP/TG/ABM instances, DMUB PSR, MPC, four DSCs, DWB/MMHUBBUB, AUX/I2C, common audio/stream/HPO/virtual encoder resources, hardware sequencer initialization, plane caps, optional OEM I2C DDC service, and DML2/DC-power option setup. Failure destructs all partially-created resources.

State and persistence behavior: construction persists a pool sized by live pipe count, not simply by static hardware maximum. It mutates global-ish DML IP parameters for the detected pipe count, `dc->caps` MALL/SubVP/cursor/link/color fields, `dc->config` flags such as windowed MPO ODM and pipe-context sync logic, `dc->debug` production defaults, `dc->dml2_options`, and `dc->dml2_dc_power_options`. `dcn32_resource_destruct()` releases all allocated display blocks and optional `oem_device`. Validation state is per `dc_state`: DML1 allocates temporary pipe arrays, recalculates watermarks/DLG, and overrides min memory/DCF clocks; DML2 validation uses either AC or DC-power contexts. SubVP validation may set stream cursor limits and retry without SubVP when hardware cursor attributes cannot be supported.

Dependencies and integration points: integrates with DCN32 block constructors, DCN32 IRQ service, DML1 (`dcn32_internal_validate_bw`) and DML2 wrapper/configuration, DC FPU guard macros, DC state phantom stream/plane helpers, link service DDC creation/destruction, BIOS VRAM/LTTPR information, resource pipe-search helpers, MALL/CAB constants, and shared DC resource functions for stream/DSC/writeback/tile handling. Register access uses context-provided DCN/NBIO offsets rather than only fixed constants, which ties this file closely to ASIC discovery.

Risks and test signals: pipe fuse handling rewrites `dcn3_2_ip` limits and compacts resource arrays while using physical register instances, so harvested-SKU testing is important. `dcn32_enable_phantom_plane()` continues when phantom plane allocation fails without advancing to the next pipe in that iteration, which should be scrutinized for accidental infinite looping if allocation can fail repeatedly. SubVP cursor fallback depends on a second validation pass and may produce user-visible changes if cursor limits are stale. MALL sizing has ASIC-revision-specific channel heuristics; wrong channel data can overstate CAB allocation. Secondary pipe selection intentionally minimizes topology churn, so regressions show as delayed flips, glitches during MPO/ODM transitions, or unnecessary pipe power toggles. Test signals include DCN32 probe on full and harvested pipe SKUs, DML1 and DML2 validation paths, SubVP phantom stream/plane creation and cursor fallback, MALL way calculations for GC 11.0.0/11.0.2/11.0.3 channel counts, DP HPO and DSC operation across four compressors, OEM I2C service creation/destruction, windowed MPO/ODM pipe acquisition stability, and clean resource teardown under allocation-failure injection.
