# sources/distributed-fs/ceph-client/drivers/ata/libata-eh.c

Purpose: This is libata's central error-handling engine. It bridges SCSI EH callbacks into ATA port recovery, classifies failed queued commands, records rolling error history, performs resets and revalidation, handles hotplug and suspend/resume transitions, and finishes or retries commands back into the SCSI midlayer. It is the recovery coordinator used by the standard ATA/SATA port operations and by PMP-specific recovery.

Important APIs, types, and functions: exported entry points include `ata_scsi_error`, `ata_scsi_cmd_error_handler`, `ata_scsi_port_error_handler`, `ata_port_wait_eh`, `ata_std_sched_eh`, `ata_std_end_eh`, `ata_port_schedule_eh`, `ata_link_abort`, `ata_port_abort`, `ata_port_freeze`, `ata_eh_freeze_port`, `ata_eh_thaw_port`, `ata_dev_disable`, `ata_eh_autopsy`, `ata_eh_reset`, `ata_eh_recover`, `ata_eh_finish`, and `ata_std_error_handler`. It also exports description helpers (`ata_ehi_push_desc`, `ata_port_desc`, `ata_port_pbar_desc`), internal command timeout helpers, and command-name reporting. Core state is carried in `struct ata_eh_info`, `struct ata_eh_context`, `struct ata_ering`, `struct ata_ering_entry`, per-link `classes[]`, per-device retry counters, `cmd_timeout_idx`, and port flags such as `ATA_PFLAG_EH_PENDING`, `ATA_PFLAG_EH_IN_PROGRESS`, `ATA_PFLAG_FROZEN`, `ATA_PFLAG_RESETTING`, `ATA_PFLAG_UNLOADING`, `ATA_PFLAG_PM_PENDING`, `ATA_PFLAG_SUSPENDED`, and `ATA_PFLAG_RESUMING`.

Control flow: SCSI EH calls `ata_scsi_error`, which drains `host->eh_cmd_q`, runs `ata_scsi_cmd_error_handler` to identify timed-out or already-completed commands, and only enters full port EH when timeouts or scheduled EH exist. Full EH in `ata_scsi_port_error_handler` acquires host-level EH ownership, snapshots and clears `link->eh_info` into `link->eh_context`, marks EH in progress, calls the low-level `ap->ops->error_handler`, handles repeat requests up to `ATA_EH_MAX_TRIES`, ends EH through `ap->ops->end_eh`, flushes completed SCSI commands, clears flags, and schedules SCSI hotplug rescans when needed. The standard handler runs `ata_eh_autopsy`, `ata_eh_report`, `ata_eh_recover`, then `ata_eh_finish`.

Autopsy and recovery behavior: `ata_eh_link_autopsy` reads and interprets `SCR_ERROR`, delegates NCQ analysis to `ata_eh_analyze_ncq_error`, fetches successful-command sense when required, inspects failed taskfiles with `ata_eh_analyze_tf`, chooses retry versus completion, promotes per-device actions, records error-ring entries, and may request speed-down. `ata_eh_reset` executes the reset sequence using `struct ata_reset_operations`: optional `prereset`, hard reset preferred over soft reset, optional follow-up soft reset, post-reset classification checks, SError cache clearing, thawing, retry backoff, and speed-limit fallback. `ata_eh_recover` then re-enables links, probes missing devices, parks and unparks heads, revalidates existing devices, attaches newly detected devices including PMPs, configures transfer modes, clears ATAPI unit attention, sets active power state, retries eligible FLUSH failures, and restores target LPM policy.

State and persistence behavior: Most state is volatile kernel runtime state attached to `ata_port`, `ata_link`, and `ata_device`; persistent user-visible effects are SCSI device hotplug/offline state, transfer-mode and link-speed limits, NCQ/LPM flags, and device power mode changes. The error ring stores recent errors with jiffies timestamps and is cleared after successful probe, explicit speed-down decisions, suspend/resume, or device disable. Internal EH command timeout escalation persists only in the current EH context through `cmd_timeout_idx`. Device disable frees libata resources, forces transfer limits down to PIO0, increments class generation, and clears accumulated error history. Suspend and unload paths explicitly transition devices to standby, freeze ports, update ACPI state, and set flags that alter later EH entry.

Dependencies and integration points: This file depends on the SCSI EH midlayer (`scsi_eh_finish_cmd`, `scsi_eh_flush_done_q`, `scsi_check_sense`, `scsi_schedule_eh`), block timeout abortion, libata core command allocation/completion, SATA SCR helpers from `libata-sata.c`, PMP helpers from `libata-pmp.c`, ATAPI/SCSI sense translation, ACPI hooks, ZPODD hooks, tracepoints, and low-level driver callbacks in `ata_port_operations`. Reset, freeze/thaw, cable detection, LPM, lost interrupt recovery, and transfer-mode programming are intentionally callback-driven so chipset drivers can supply hardware-specific behavior.

Risks and edge cases: EH is concurrency-sensitive: command completion, SCSI timeout, interrupt handlers, deferred queued commands, fast-drain timers, hotplug, and PM transitions all meet under `ap->lock` and the host EH mutex. Reset and hotplug races are explicitly mitigated by link onlineness/classification cross-checks, but misclassification still degrades to warnings after retry exhaustion. Sense-data fetch failures for successful commands are treated as I/O errors to avoid silent data corruption. Speed-down heuristics can reduce link or transfer mode after repeated ambiguous errors, while media errors are intentionally not retried. PMP and slave-link recovery paths depend on careful action transfer between links. LPM failures may permanently mark a link `NO_LPM` when retries are low.

Test signals: There are no unit tests in this file; validation signals are kernel integration behavior: SCSI timeout recovery, NCQ log-page parsing through `ata_eh_analyze_ncq_error`, reset fallback paths, hotplug and PMP recovery, sysfs-triggered park/unpark, suspend/resume, and driver callback coverage. Useful fault-injection tests would force SCSI timeouts, frozen ports, failed SCR reads, failed hardreset/softreset, NCQ errors with and without autosense, FLUSH retry outcomes, repeated probe failures causing speed-down, and LPM transition failures.

# sources/distributed-fs/ceph-client/drivers/ata/libata-pata-timings.c

Purpose: This helper library computes PATA timing register values from ATA transfer modes and device IDENTIFY timing fields. Low-level PATA drivers use it to turn mode choices such as PIO4, MWDMA2, or UDMA6 into bus-clock counts that satisfy ATA timing constraints.

Important APIs, types, and functions: The static `ata_timing[]` table records nanosecond timing requirements for PIO 0-6, single-word DMA 0-2, multi-word DMA 0-4, and UDMA 0-6 in `struct ata_timing` fields. Exported functions are `ata_timing_merge`, `ata_timing_find_mode`, and `ata_timing_compute`. `ata_timing_quantize` converts nanosecond timings to controller clock units using `T` for normal cycles and `UT` for UDMA cycles. The `ENOUGH` and `EZ` macros implement round-up conversion from nanoseconds to clock counts.

Control flow: `ata_timing_compute` finds the base mode row, copies it into the output, merges device-supplied EIDE PIO or MWDMA cycle minima when IDENTIFY word validity allows it, quantizes all fields, recursively merges the selected DMA/UDMA timing with the device's current PIO timing for commands still issued via PIO, and then lengthens active/recovery windows so the combined cycle constraints are met. `ata_timing_merge` is a field-selective maximum merge, allowing callers to enforce the slower of two timing sources. `ata_timing_find_mode` scans the ordered timing table and warns if no row exists.

State and persistence behavior: The file is stateless. It reads `adev->id` and `adev->pio_mode`, writes only the caller-provided `struct ata_timing`, and has no allocation, global mutation, hardware I/O, or persistent storage. Its results become persistent only if a low-level driver programs chipset timing registers from the returned structure.

Dependencies and integration points: It depends on `linux/libata.h` for transfer-mode constants, `struct ata_device`, IDENTIFY word indexes, CFA detection, and timing masks. It is typically integrated with driver `set_piomode`, `set_dmamode`, or `set_mode` callbacks and with libata mode selection performed during EH recovery in `ata_eh_set_mode`.

Risks and edge cases: The timing table must remain ordered by mode because `ata_timing_find_mode` advances while `xfer_mode > t->mode`. Bad or missing device IDENTIFY fields can cause conservative fallback to table timings but not runtime validation against hardware limits. Recursive PIO merging assumes `adev->pio_mode` is valid for DMA/UDMA modes. Rounding via clock periods can produce active plus recovery values larger than cycle, so the final correction expands `cycle`; controller drivers must tolerate these rounded values.

Test signals: Good coverage would compare computed timing structures against ATA/ATAPI and CFA reference values for each mode, including EIDE overrides, DMA merged with PIO fallback timing, non-divisible controller clock periods, invalid mode lookup returning `-EINVAL`, and the final cycle correction when quantization makes active plus recovery exceed cycle.

# sources/distributed-fs/ceph-client/drivers/ata/libata-pmp.c

Purpose: This file implements SATA Port Multiplier support for libata. It provides PMP register access, SCR forwarding for fan-out links, command-switching queue deferral, PMP discovery/configuration, vendor-specific PMP quirks, attach/detach, revalidation, disabled-link handling, and PMP-aware error recovery.

Important APIs, types, and functions: `sata_pmp_port_ops` inherits `sata_port_ops`, supplies PMP reset operations, and installs `sata_pmp_error_handler`. Exported functions are `sata_pmp_qc_defer_cmd_switch` and `sata_pmp_error_handler`, with `sata_pmp_scr_read`, `sata_pmp_scr_write`, `sata_pmp_set_lpm`, and `sata_pmp_attach` used by the broader libata SATA/EH code. Internal helpers include `sata_pmp_read`, `sata_pmp_write`, `sata_pmp_read_gscr`, `sata_pmp_configure`, `sata_pmp_init_links`, `sata_pmp_quirks`, `sata_pmp_detach`, `sata_pmp_revalidate`, `sata_pmp_revalidate_quick`, `sata_pmp_eh_recover_pmp`, `sata_pmp_eh_handle_disabled_links`, `sata_pmp_handle_link_fail`, and `sata_pmp_eh_recover`.

Control flow: PMP register operations are ATA internal commands (`ATA_CMD_PMP_READ` and `ATA_CMD_PMP_WRITE`) issued to the PMP device on the host link, with the target PMP port encoded in the taskfile device field. Fan-out SCR reads and writes validate the PSCR register number and then call those PMP register operations. Attach requires host PMP support, host-link placement, and device zero; it reads the GSCR block, configures notification/error masks and quirks, allocates `SATA_PMP_MAX_PORTS` links if needed, sets `ap->nr_pmp_links`, invokes the optional low-level `pmp_attach` callback, and initializes fan-out link speeds.

Recovery behavior: `sata_pmp_error_handler` reuses generic libata autopsy/report/finish but inserts `sata_pmp_eh_recover`. Recovery first uses normal `ata_eh_recover` until a PMP appears, then recovers the PMP itself through hard/soft reset and GSCR revalidation. After PMP recovery it disables NOTIFY while recovering downstream links, clears disabled-link `SError.N`, runs generic recovery with PMP reset operations over fan-out links, clears `SNotification`, conditionally re-enables NOTIFY, checks `GSCR_ERROR`, marks changed fan-out links hotplugged, and repeats as needed. Failed downstream links are retried per-link, then disabled and their devices are disabled; repeated PMP failures eventually detach or disable the PMP.

State and persistence behavior: Runtime PMP state lives in `ap->pmp_link`, `ap->nr_pmp_links`, host-link `link->pmp`, per-link flags such as `NO_LPM`, `NO_SRST`, `ASSUME_ATA`, `ASSUME_SEMB`, `DISABLED`, and `NO_RETRY`, and the PMP device's `gscr` array. Attach allocates transport links and stores GSCR identity/configuration. Detach clears `ap->nr_pmp_links`, resets host-link PMP addressing, detaches downstream devices, and may offline the PMP device. No data is persisted outside kernel state, but visible SCSI device topology changes occur through libata hotplug handling.

Dependencies and integration points: This file depends on generic EH in `libata-eh.c`, SATA SCR/LPM helpers in `libata-sata.c`, libata transport link registration, ATA internal command execution, `ata_port_operations` callbacks (`pmp_attach`, `pmp_detach`, reset hooks), and PMP GSCR macros from libata headers. Command switching integrates with libata queue deferral by using `ap->excl_link`, `ap->nr_active_links`, `ATA_QCFLAG_CLEAR_EXCL`, and `ata_std_qc_defer`.

Risks and edge cases: PMP recovery is retry-heavy and intentionally disables links that cannot be recovered after bounded attempts, so transient fan-out failures can remove devices until a manual scan. Vendor quirks are identity-specific and can force assumptions about ATA/SEMB class, disable SRST/LPM, or mark pseudo ports no-retry; incomplete quirk coverage risks failed detection or reset loops. NOTIFY and `GSCR_ERROR` handling must avoid races with recovery, because PHY events can arrive while links are being reset. Nested PMPs and nonzero-device PMPs are rejected. PMP register access failure maps to broad `-EIO`, losing some detail from the ATA error mask.

Test signals: Integration tests should cover PMP attach with valid and invalid GSCR port counts, vendor quirk application, command-switching deferral across multiple fan-out links, SCR read/write error propagation, PMP revalidation identity mismatch, downstream link retry-to-disable behavior, NOTIFY disable/re-enable around recovery, and hotplug reporting via `SNotification` and `GSCR_ERROR`.

# sources/distributed-fs/ceph-client/drivers/ata/libata-sata.c

Purpose: This file contains SATA-specific libata helpers: SCR access dispatch, SATA FIS/taskfile conversion, PHY debounce/resume/hardreset, link speed limiting, link power management, slave-link setup, sysfs-facing LPM and NCQ priority controls, enclosure-management attributes, SCSI queue-depth handling, SAS/libata glue, SATA asynchronous notification, NCQ error log analysis, and the default `sata_port_ops`.

Important APIs, types, and functions: Exported timing arrays are `sata_deb_timing_normal`, `sata_deb_timing_hotplug`, and `sata_deb_timing_long`. Exported core helpers include `sata_scr_valid`, `sata_scr_read`, `sata_scr_write`, `sata_scr_write_flush`, `ata_tf_to_fis`, `ata_tf_from_fis`, `sata_link_debounce`, `sata_link_resume`, `sata_link_scr_lpm`, `sata_set_spd`, `sata_down_spd_limit`, `sata_link_hardreset`, `sata_std_hardreset`, `ata_qc_complete_multiple`, `ata_slave_link_init`, `sata_lpm_ignore_phy_events`, `ata_change_queue_depth`, `ata_scsi_change_queue_depth`, `ata_sas_sdev_configure`, `ata_sas_queuecmd`, `sata_async_notification`, `ata_eh_get_ncq_success_sense`, `ata_eh_analyze_ncq_error`, and `sata_port_ops`. It also exports sysfs attributes for LPM, NCQ priority, enclosure management, and software activity.

Control flow: SCR helpers dispatch host-link operations to low-level `scr_read`/`scr_write` callbacks when SATA is supported and dispatch fan-out link operations through PMP SCR helpers. Hard reset starts by applying any pending speed limit, drives SControl DET through COMRESET, resumes and debounces the link, optionally waits for readiness, and returns `-EAGAIN` for host links with PMP support to force follow-up soft reset. `sata_std_hardreset` wraps that behavior for libata reset operations. Queue completion compares a low-level driver's active mask with `ap->qc_active`, rejects illegal transitions, optionally fills NCQ result taskfiles, and completes all newly finished tags.

LPM, speed, and sysfs behavior: `sata_link_scr_lpm` updates SControl IPM/SPM fields for max, medium, and minimum power policies, respects host flags that forbid partial/slumber/devsleep, powers off empty links in low-power policies, clears `PHYRDY_CHG`, and records EH SError state. Sysfs `link_power_management_policy` validates policy names, checks support while holding `ap->lock`, stores `ap->target_lpm_policy`, and schedules EH so policy changes occur in EH context. Speed limiting uses `link->sata_spd_limit`, current or cached SPD, and upstream PMP speed caps to lower allowed link generations; the actual SControl update is applied later by `sata_set_spd`.

SCSI, SAS, and notification integration: NCQ priority helpers read and update `ATA_DFLAG_NCQ_PRIO_ENABLED` under `ap->lock`, rejecting enable when unsupported or CDL is enabled. Queue-depth changes cap the requested depth to libata, host, and IDENTIFY limits, and toggle `ATA_DFLAG_NCQ_OFF` when depth one or no NCQ support requires queueing off. SAS glue configures libata-backed SCSI devices and queues SCSI commands through `__ata_scsi_queuecmd` when the ATA device is enabled. `sata_async_notification` handles ATAPI media-change notifications and PMP PHY-change notifications through `SCR_NOTIFICATION`, scheduling EH when PMP topology changes are reported.

NCQ error and sense behavior: `ata_eh_read_log_10h` reads SATA NCQ log page 10h, validates checksum, extracts the failed tag and taskfile fields, and stores NCQ autosense information when present. `ata_eh_analyze_ncq_error` runs during EH autopsy for unfrozen links with active NCQ and device error; it reads log page 10h, identifies the offending queued command, marks it `AC_ERR_DEV | AC_ERR_NCQ`, installs autosense when valid, marks sibling commands for retry, and clears the link-level device error. `ata_eh_get_ncq_success_sense` reads the successful NCQ commands sense log, validates its header, copies per-tag sense/taskfile data, marks `ATA_QCFLAG_SENSE_VALID`, and invokes SCSI sense disposition.

State and persistence behavior: State changes are runtime kernel state on `ata_link`, `ata_port`, `ata_device`, and `scsi_device`: SCR register contents, `sata_spd_limit`, cached `sata_spd`, `lpm_policy`, `last_lpm_change`, `ATA_LFLAG_CHANGED`, NCQ priority flags, NCQ-off state, queue depth, and SCSI sense buffers. Sysfs writes persist only until device/driver lifetime but have immediate behavioral effects through EH scheduling or SCSI queue reconfiguration. The file performs no filesystem persistence.

Dependencies and integration points: It integrates with low-level driver SCR callbacks, PMP helpers, EH recovery in `libata-eh.c`, SCSI sysfs and queue-depth APIs, SCSI command completion, libata device lookup and queueing, unaligned log parsing helpers, and ATA/SATA protocol constants. `sata_port_ops` inherits `ata_base_port_ops`, supplies standard QC defer, and installs `sata_std_hardreset` as the default SATA hardreset.

Risks and edge cases: SCR access is optional and `-EOPNOTSUPP` drives fallback behavior in EH. Debounce returns `-EPIPE` on unstable links to trigger link speed reduction; incorrect timing or controller quirks can lead to slow hotplug or false offline states. Speed limiting avoids forcing 1.5Gbps when current speed is unknown, which prevents unsafe downgrades but can leave marginal links unchanged. LPM can mask PHY events, so `sata_lpm_ignore_phy_events` suppresses spurious events after policy changes. NCQ log parsing relies on valid device logs and active-tag consistency; invalid checksums are warned but not fatal, while inactive reported tags abort deeper analysis. Queue-depth and NCQ-priority sysfs writes must coordinate with CDL and device capabilities.

Test signals: Useful coverage includes SCR host-link and PMP-link dispatch, FIS round-trip conversion, hardreset return cases for offline, online, PMP follow-up SRST, and SCR failures; debounce timeout to `-EPIPE`; speed-limit downgrades with and without cached/current SPD; LPM policy sysfs writes and EH scheduling; NCQ priority enable failure with CDL; queue-depth caps and NCQ-off transitions; async notification for ATAPI and PMP; log page 10h NCQ error analysis; and successful-NCQ sense log parsing.
