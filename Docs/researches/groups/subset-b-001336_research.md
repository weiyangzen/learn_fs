# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdgpu/gfx_v7_0.c

Purpose: this file implements the AMDGPU GFX7/CIK graphics IP block for Bonaire, Hawaii, Kaveri, Kabini, and Mullins class GPUs. It owns firmware discovery/loading, ASIC graphics configuration, tiling and render-backend setup, graphics and compute command processor bring-up, RLC save/restore and clear-state setup, GDS/VMID programming, ring packet emission, IRQ handling, clock/power gating, soft reset, and registration of the GFX 7.1/7.2/7.3 `amdgpu_ip_block_version` descriptors.

Important APIs, types, and data: the exported IP descriptors are `gfx_v7_1_ip_block`, `gfx_v7_2_ip_block`, and `gfx_v7_3_ip_block`, all using `gfx_v7_0_ip_funcs`. Key function tables are `gfx_v7_0_ip_funcs`, `gfx_v7_0_ring_funcs_gfx`, `gfx_v7_0_ring_funcs_compute`, `gfx_v7_0_gfx_funcs`, `gfx_v7_0_rlc_funcs`, and the three IRQ source tables. Firmware entry points include `gfx_v7_0_init_microcode`, `gfx_v7_0_cp_gfx_load_microcode`, `gfx_v7_0_cp_compute_load_microcode`, and `gfx_v7_0_rlc_resume`. Hardware setup is split across `gfx_v7_0_gpu_early_init`, `gfx_v7_0_tiling_mode_table_init`, `gfx_v7_0_constants_init`, `gfx_v7_0_setup_rb`, `gfx_v7_0_get_cu_info`, and GDS helpers backed by `amdgpu_gds_reg_offset`. Ring operations include fence, IB, VM flush, HDP flush, GDS switch, context-control, memory-sync, read/write-pointer, ring test, IB test, and soft-recovery helpers. Compute queue state is represented by CIK MQDs (`struct cik_mqd`) and initialized through `gfx_v7_0_mqd_init`, `gfx_v7_0_mqd_deactivate`, `gfx_v7_0_mqd_commit`, and `gfx_v7_0_compute_queue_init`.

Control flow: `early_init` fixes the GFX ring count, computes the number of kernel compute queues, installs GFX/RLC/ring/IRQ/GDS callbacks, and sets one XCC. `sw_init` configures MEC counts, registers EOP and illegal-access IRQ IDs, requests PFP/ME/CE/MEC/RLC firmware, allocates RLC and MEC buffers, initializes the single graphics ring, allocates enabled compute rings horizontally across MEC pipes and queues, initializes early ASIC geometry, and records supported reset masks. `hw_init` programs constants and tiling tables, populates the clear-state buffer, resumes RLC, then loads CP firmware and resumes graphics and compute queues. Graphics resume programs CP RB0 registers and starts the ring with CE partition and clear-state packets. Compute resume initializes all pipe EOP areas, creates and commits MQDs for owned queues, enables MECs, and runs ring tests. Suspend/resume reuse `hw_fini`/`hw_init`; `hw_fini` drops IRQs, halts CP, stops RLC, and disables power gating.

State and persistence: persistent driver state lives in `adev->gfx` firmware pointers/version fields, geometry/config arrays, ring objects, MEC metadata, RLC BOs, clear-state/save-restore/CP table GPU addresses, CU information, IRQ sources, and GDS sizing. Hardware state is programmed through MMIO register writes for GB tiling/macrotile modes, raster config, SH memory apertures, GDS VMID windows, CP ring/HQD/MQD registers, RLC scratch/ucode/control registers, clock-gating and power-gating controls, and interrupt enable bits. Ring pointers persist through writeback memory for rptr and, for compute, wptr plus doorbell writes. `sw_fini` releases rings, MQD BOs, RLC BOs, MEC EOP BOs, clear-state/CP-table BOs, and firmware references.

Dependencies and integration points: the file depends on AMDGPU core objects (`amdgpu_device`, `amdgpu_ring`, `amdgpu_job`, `amdgpu_ib`, IRQ, firmware, RLC, GFX, GMC, GDS, and BO helpers), CIK register and packet headers, firmware header formats from `amdgpu_ucode.h`, clear-state data from `clearstate_ci.h`, Linux firmware loading, DMA fences, DRM scheduler fault reporting, and ASIC selection in `cik.c`. GFX IP registration integrates with the AMDGPU IP block lifecycle, the scheduler through ring function tables, VM/TLB management via `amdgpu_gmc_emit_flush_gpu_tlb`, KFD/compute queue ownership through `amdgpu_gfx_compute_queue_acquire` and MEC queue masks, and interrupt processing through the legacy IH client IDs.

Risks and edge cases: most logic is register-sequence sensitive; ordering errors around CP/RLC halt, SRBM/GRBM selection, and CG/PG toggles can hang hardware. Firmware is mandatory and ASIC-name specific, with Kaveri requiring a second MEC image. Tiling tables and GB address configuration are hard-coded per ASIC and memory row size, so new revisions or misdetected memory geometry can corrupt surface layout. Harvested RB/CU handling relies on masks, broadcast selection, and fixed SE/SH assumptions. Compute MQD programming disables wptr polling and writes register ranges by structure offset, which is layout-sensitive. Ring packet sizes in the ring function tables must stay in sync with emitted packet sequences. The header declares `gfx_v7_0_mqd_commit` as external while this file defines it `static`, so external users of the declaration would not link unless the symbol visibility is changed or the declaration removed. Several paths use timeout polling, but some helper behavior assumes functioning hardware and firmware; failures surface as ring test, IB test, or resume errors.

Test signals: useful coverage includes kernel builds for CIK ASIC configurations, firmware-missing and firmware-version boot logs, cold boot and suspend/resume on Bonaire/Hawaii/Kaveri/Kabini/Mullins, `amdgpu_ring_test_helper` and IB test success for GFX and compute rings, command submission and fence completion on graphics and compute queues, VM fault and VM flush tests, GDS switch tests, KFD queue ownership coexistence, illegal register/instruction interrupt injection, soft-reset recovery after forced hangs, clock/power-gating enable/disable with runtime PM, and graphics workloads that exercise tiling, harvested RB/CU masks, clear-state restore, and cache flushes.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdgpu/gfx_v7_0.h

Purpose: this header exposes the GFX7 AMDGPU IP block descriptors used by CIK device discovery and declares the CIK MQD commit helper associated with GFX7 compute queue programming.

Important APIs and types: it declares `gfx_v7_1_ip_block`, `gfx_v7_2_ip_block`, and `gfx_v7_3_ip_block` as `struct amdgpu_ip_block_version` instances, forward-declares `struct amdgpu_device` and `struct cik_mqd`, and declares `int gfx_v7_0_mqd_commit(struct amdgpu_device *adev, struct cik_mqd *mqd)`. The IP block descriptors are consumed by ASIC setup code to add the correct GFX IP version while sharing the implementation in `gfx_v7_0.c`.

Control flow: include guards make the declarations available to CIK setup and any GFX7-adjacent code without pulling in the full AMDGPU or CIK MQD definitions. Device initialization code can reference the declared IP block descriptors and pass them to AMDGPU IP block registration. The MQD commit declaration describes a helper that programs HQD/MQD registers from a prepared CIK MQD, though in the current C file the implementation is private to that translation unit.

State and persistence: the header itself owns no state. It publishes access to const IP block descriptors and a helper signature that operates on caller-owned `amdgpu_device` and `cik_mqd` state. The actual persistent state lives in the GFX7 implementation and in the device's IP block list, ring/MQD BOs, and hardware queue registers.

Dependencies and integration points: consumers need compatible definitions of `struct amdgpu_ip_block_version`, `struct amdgpu_device`, and `struct cik_mqd` from AMDGPU and CIK headers. `cik.c` references the IP block descriptors during ASIC-specific IP block assembly for GFX 7.1, 7.2, and 7.3 devices. The MQD helper declaration implies potential integration with compute queue programming or KFD/KGD code, but the current implementation in `gfx_v7_0.c` is `static` and only called internally.

Risks and edge cases: the declared MQD commit helper does not currently match external linkage in the C implementation, creating a stale or misleading public declaration if any other file tries to call it. Changes to descriptor names or IP version declarations can break CIK device registration. Because the header uses forward declarations, signature drift in the real structures will be caught only at implementation or call sites that include full definitions.

Test signals: compile coverage that includes `cik.c` and `gfx_v7_0.c` is the primary signal. Link coverage should confirm the three IP block descriptors resolve. A targeted check should verify no external call site relies on `gfx_v7_0_mqd_commit` while it remains static, or else the declaration and implementation linkage must be reconciled.
