# File Research: sources/os/bsd/netbsd-src/sys/sys/swap.h

## Purpose
Defines the user/kernel ABI for NetBSD swap device control and reporting. This header is consumed by `swapctl(2)` callers and kernel swap management code.

## Key Interfaces
- `struct swapent`: user-visible swap device status record.
  - Includes device id, flags, total/in-use block counts, priority, path, bad-page count, and reserved padding.
  - `__CTASSERT(sizeof(struct swapent) == 1184)` makes this a fixed ABI contract.
- Swap control commands:
  - `SWAP_ON`, `SWAP_OFF`, `SWAP_NSWAP`, `SWAP_CTL`
  - `SWAP_DUMPDEV`, `SWAP_GETDUMPDEV`, `SWAP_DUMPOFF`
  - compatibility/stat variants: `SWAP_STATS13`, `SWAP_STATS50`, `SWAP_STATS110`, `SWAP_STATS`
- Swap flags:
  - `SWF_INUSE`, `SWF_ENABLE`, `SWF_BUSY`, `SWF_FAKE`

## Dependencies
Includes `sys/syslimits.h` for `PATH_MAX`, which sizes `se_path`.

## Filesystem / Storage Relevance
This is directly storage-facing: it exposes the kernel’s swap backing devices to userland and controls enabling/disabling swap and crash dump devices. The fixed path buffer and reserved fields show the ABI is expected to survive future kernel changes without resizing the public structure.

## Notes
The command numbering preserves old ABI variants. Any tooling interpreting swap state should prefer `SWAP_STATS` while recognizing older command names may exist for compatibility layers or old binaries.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syncobj.h

## Purpose
Defines NetBSD kernel synchronization object descriptors used by the scheduler/sleep queue machinery to abstract how different blocking primitives wake, reprioritize, and report ownership.

## Key Interfaces
- `typedef struct syncobj ... syncobj_t`: const operation table for waitable synchronization objects.
  - `sobj_name[16]`: short object name.
  - `sobj_flag`: sleep queue behavior flags.
  - `sobj_boostpri`: priority boosting value.
  - `sobj_unsleep(struct lwp *, bool)`: remove an LWP from sleep.
  - `sobj_changepri(struct lwp *, pri_t)`: change priority.
  - `sobj_lendpri(struct lwp *, pri_t)`: priority inheritance/lending.
  - `sobj_owner(wchan_t)`: owner lookup.
- `syncobj_noowner(wchan_t)`: helper for primitives with no owner.
- Sleep queue flags:
  - `SOBJ_SLEEPQ_SORTED`
  - `SOBJ_SLEEPQ_LIFO`
  - `SOBJ_SLEEPQ_NULL`
- Declared kernel sync objects:
  - `callout_syncobj`, `cv_syncobj`, `kpause_syncobj`, `lwp_park_syncobj`
  - `mutex_syncobj`, `rw_syncobj`, `sched_syncobj`, `select_syncobj`, `sleep_syncobj`

## Dependencies
Includes `sys/wchan.h` and forward-declares `struct lwp`. Visible only to `_KERNEL` or `_KMEMUSER`.

## Filesystem / Storage Relevance
Filesystem and VFS code frequently sleeps on locks, condition variables, I/O wait channels, and vnode-related synchronization. This header is part of the kernel substrate that lets those waits integrate with priority inheritance, sleep queue ordering, and wakeup semantics.

## Notes
This file contains declarations only; behavior lives in scheduler/synchronization implementations. The operation-table design is important for reasoning about lock wait behavior without coupling every primitive to scheduler internals.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syscall.h

## Purpose
Generated NetBSD syscall number table. It maps syscall symbolic names to numeric ABI slots and defines syscall table bounds.

## Generation
Header states it is generated by `makesyscalls.sh` from `syscalls.master`. It should not be edited directly.

## Key Constants
- `SYS_MAXSYSARGS 8`: maximum argument registers/slots.
- `SYS_MAXSYSCALL 507`: highest syscall number currently named.
- `SYS_NSYSENT 512`: syscall table entry count.

## Content Shape
The file is a linear list of `#define SYS_<name> <number>` entries plus comments documenting each syscall’s return type and argument signature. It includes:
- Core POSIX process/file calls: `read`, `write`, `open`, `close`, `fork`, `execve`, `wait`, `poll`, `fcntl`.
- VFS/filesystem calls: `mount`, `unmount`, `stat`, `lstat`, `fstat`, `getvfsstat`, `statvfs`, `fhopen`, `fhstat`, `getfh`, `quotactl`, `pathconf`, `lpathconf`.
- Directory and path operations: `link`, `unlink`, `rename`, `mkdir`, `rmdir`, `symlink`, `readlink`.
- Modern *at variants: `openat`, `fstatat`, `mkdirat`, `mknodat`, `linkat`, `renameat`, `unlinkat`, `utimensat`.
- Extended attributes and ACLs: `extattr_*`, `setxattr`, `getxattr`, `listxattr`, `removexattr`, `__acl_*`.
- Storage-adjacent calls: `swapctl`, `fsync`, `fdatasync`, `fsync_range`, `posix_fallocate`, `fdiscard`.
- Event and Linux-compatible APIs: `kqueue`, `kevent`, `eventfd`, `timerfd_*`, `epoll_*`, `memfd_create`.
- Many compatibility syscalls preserving old ABI layouts: `compat_09`, `compat_12`, `compat_13`, `compat_20`, `compat_30`, `compat_40`, `compat_43`, `compat_50`, `compat_60`, `compat_90`, `compat_100`.

## Filesystem / Storage Relevance
This table is central for userland entry into VFS and filesystem behavior. File descriptor operations, pathname operations, mount/statvfs APIs, LFS control calls, swap control, xattrs, ACLs, and discard/fallocate are all enumerated here.

## ABI Notes
Numeric values are ABI-stable. Obsolete, ignored, and excluded slots remain documented so newer kernels do not renumber existing syscalls. Conditional entries such as NTP and non-LP64 compatibility preserve architecture/configuration-specific syscall surfaces.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syscall_stats.h

## Purpose
Provides optional kernel syscall counting and timing instrumentation macros.

## Key Interfaces
Enabled under `SYSCALL_STATS`:
- `syscall_counts[SYS_NSYSENT]`: per-syscall counters.
- `syscall_count_user`, `syscall_count_system`, `syscall_count_interrupt`: aggregate timing buckets.
- `SYSCALL_COUNT(table, code)`: increments a syscall counter.

Enabled under `SYSCALL_TIMES && __HAVE_CPU_COUNTER`:
- `syscall_times[SYS_NSYSENT]`: per-syscall accumulated time.
- `SYSCALL_TIME()`: reads `cpu_counter32()` when available.
- LWP lifecycle and transition hooks:
  - `SYSCALL_TIME_LWP_INIT`
  - `SYSCALL_TIME_SYS_ENTRY`
  - `SYSCALL_TIME_SLEEP`
  - `SYSCALL_TIME_WAKEUP`
  - `SYSCALL_TIME_SYS_EXIT`
  - interrupt entry/exit hooks are present under `_notyet`.

## Dependencies
Includes `opt_syscall_stats.h` when `_KERNEL_OPT` is defined. Includes `sys/syscall.h` for `SYS_NSYSENT` and may include `machine/cpu_counter.h`.

## Behavior
When instrumentation options are not enabled, all macros compile to no-ops and `SYSCALL_TIMES` is undefined. This keeps syscall fast paths clean in default builds.

## Filesystem / Storage Relevance
Useful for profiling syscall-heavy filesystem workloads. File, directory, VFS, xattr, ACL, swap, and sync calls can be counted/timed by syscall number with no per-filesystem code changes.

## Notes
Timing uses a 32-bit CPU counter and delta arithmetic, so consumers should treat it as low-level kernel profiling data rather than portable wall-clock accounting.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syscallargs.h

## Purpose
Generated NetBSD syscall argument and prototype header. It defines the C structures used to marshal syscall arguments from trap/register state into typed kernel syscall handlers.

## Generation
Generated by `makesyscalls.sh` from `syscalls.master`; not intended for manual edits. It must stay synchronized with `syscall.h` and syscall dispatch tables.

## Core Mechanics
- `SYS_MAXSYSARGS 8`: maximum syscall argument slots.
- `syscallarg(x)`: union wrapper around each argument.
  - Provides register-sized padding.
  - Contains little-endian and big-endian layouts so kernel handlers can access `SCARG`-style fields consistently across architectures.
- `check_syscall_args(call)`: compile-time assertion that each syscall argument struct fits within `SYS_MAXSYSARGS * sizeof(register_t)`.

## Header Dependencies
When not building `RUMP_CLIENT`, includes `sys/idtype.h`, `sys/mount.h`, `sys/sched.h`, and `sys/acl.h`. Always includes `sys/socket.h`. Forward-declares `struct lwp`.

## Content Shape
The first large section defines `struct <syscall>_args` for syscall handlers. The second large section declares prototypes:
`int sys_name(struct lwp *, const struct sys_name_args *, register_t *);`

Some no-argument syscalls use `const void *` instead of an args struct. Many definitions are hidden under `#ifndef RUMP_CLIENT`, and some compatibility calls are conditional on `_LP64`, `NTP`, or `_KERNEL_OPT`.

## Filesystem / Storage-Relevant Argument Structs
Important structs include:
- Basic file I/O: `sys_read_args`, `sys_write_args`, `sys_pread_args`, `sys_pwrite_args`, `sys_readv_args`, `sys_writev_args`, `sys_preadv_args`, `sys_pwritev_args`.
- Path and directory operations: `sys_open_args`, `sys_link_args`, `sys_unlink_args`, `sys_rename_args`, `sys_mkdir_args`, `sys_rmdir_args`, `sys_symlink_args`, `sys_readlink_args`.
- Descriptor/path metadata: `sys_stat` compatibility variants, `sys___stat50_args`, `sys_fstatat_args`, `sys___getdents30_args`.
- Mount and VFS: `sys___mount50_args`, `sys_unmount_args`, `sys___getvfsstat90_args`, `sys___statvfs190_args`, `sys___fstatvfs190_args`, `sys___fhstatvfs190_args`.
- File handles: `sys___getfh30_args`, `sys___fhopen40_args`, `sys___fhstat50_args`.
- Sync/storage controls: `sys_fsync_args`, `sys_fdatasync_args`, `sys_fsync_range_args`, `sys_posix_fallocate_args`, `sys_fdiscard_args`, `sys_swapctl_args`.
- Extended metadata: `sys_extattr_*`, `sys_setxattr_args`, `sys_getxattr_args`, `sys_listxattr_args`, `sys_removexattr_args`, and ACL argument structs.
- Modern relative path APIs: `openat`, `linkat`, `renameat`, `mkdirat`, `mknodat`, `faccessat`, `fchmodat`, `fchownat`, `utimensat`, `unlinkat`.

## ABI Notes
The explicit `PAD` fields before `off_t`/`dev_t` arguments preserve alignment across architectures. Compatibility structs preserve historical user ABI layouts, especially for old stat, statfs/statvfs, time, semaphore, message queue, and file-handle syscalls.

## Research Takeaway
This file is not algorithmic, but it is a critical ABI contract. Any syscall addition or signature change must update the generator input, not this file, and must preserve argument-size constraints.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syscallvar.h

## Purpose
Defines kernel-only syscall dispatch helpers and syscall table registration APIs.

## Key Interfaces
- `struct syscall_package`
  - `sp_code`: syscall number.
  - `sp_flags`: syscall flags.
  - `sp_call`: syscall implementation function pointer.
- Registration lifecycle:
  - `syscall_init(void)`
  - `syscall_establish(const struct emul *, const struct syscall_package *)`
  - `syscall_disestablish(const struct emul *, const struct syscall_package *)`
- `extern struct emul emul_netbsd`: native NetBSD emulation descriptor.

## Dispatch Helpers
- `sy_call(...)`
  - Sets `l->l_sysent` to the active syscall entry.
  - Calls `sy->sy_call(l, uap, rval)`.
  - Clears `l->l_sysent` afterward.
- `sy_invoke(...)`
  - Handles tracing and DTrace entry/return hooks.
  - Clears return registers before invocation, except for MIPS and m68k special handling.
  - Calls `trace_enter` and `trace_exit` when tracing is enabled and syscall is not indirect.

## Dependencies
Kernel-only header; emits an error outside `_KERNEL`. Includes `opt_dtrace.h`, `sys/systm.h`, and `sys/proc.h`.

## Filesystem / Storage Relevance
All VFS and filesystem-facing syscalls eventually pass through these helpers. This is the layer where tracing observes operations such as `open`, `read`, `write`, `mount`, `statvfs`, `fsync`, xattr calls, ACL calls, and `swapctl`.

## Notes
The helper is small but sensitive: return register initialization, trace behavior, and `l_sysent` lifetime affect every syscall. Filesystem syscall implementations rely on this wrapper for uniform tracing and error-return handling.

# File Research: sources/os/bsd/netbsd-src/sys/sys/sysctl.h

## Purpose
Defines the NetBSD `sysctl(3)/(2)` namespace, public data structures returned by sysctl nodes, and kernel machinery for dynamic sysctl tree creation and dispatch.

## Public Sysctl Model
- Names are integer MIB paths with up to `CTL_MAXNAME` components.
- Node names are limited by `SYSCTL_NAMELEN`.
- Node types:
  - `CTLTYPE_NODE`, `CTLTYPE_INT`, `CTLTYPE_STRING`, `CTLTYPE_QUAD`, `CTLTYPE_STRUCT`, `CTLTYPE_BOOL`, `CTLTYPE_LONG`.
- Access/behavior flags:
  - read/write flags, private/permanent/owndata/immediate/hidden/alias/mmap/unsigned flags.
- Meta identifiers:
  - `CTL_QUERY`, `CTL_CREATE`, `CTL_CREATESYM`, `CTL_DESTROY`, `CTL_MMAP`, `CTL_DESCRIBE`.

## Top-Level Namespaces
Defines `CTL_KERN`, `CTL_VM`, `CTL_VFS`, `CTL_NET`, `CTL_DEBUG`, `CTL_HW`, `CTL_MACHDEP`, `CTL_USER`, `CTL_DDB`, `CTL_PROC`, `CTL_VENDOR`, `CTL_EMUL`, and `CTL_SECURITY`.

## Filesystem / Storage-Relevant Nodes
- `CTL_VFS`: root namespace for filesystem-specific MIBs.
- `KERN_MAXVNODES`, `KERN_VNODE`: vnode limits and vnode reporting.
- `KERN_FILE`, `KERN_FILE2`: open file reporting.
- `KERN_BUF`: buffer cache reporting.
- `HW_DISKNAMES`, `HW_IOSTATS`, `HW_IOSTATNAMES`: disk/device statistics.
- `KERN_ROOT_DEVICE`, `KERN_ROOT_PARTITION`: root storage identity.
- Helper prototypes include `sysctl_kern_vnode` and `sysctl_vfs_generic_fstypes`.

## Exported Structures
Important stable-ish userland structures include:
- `struct clockinfo`
- `struct ki_pcred`, `struct ki_ucred`
- `struct eproc`, `struct kinfo_proc`
- `struct kinfo_proc2`: fixed-size process export with explicit 64-bit pointer fields and append-only guidance.
- `struct kinfo_lwp`
- `struct kinfo_drivers`
- `struct buf_sysctl`: buffer cache export with 32/64-bit compatibility layout.
- `struct kinfo_file`: open file/vnode/descriptor export.
- `struct evcnt_sysctl`
- `struct hashstat_sysctl`
- `struct kinfo_vmentry`: VM map entries, including vnode-backed mapping metadata and path.

## Kernel Sysctl Infrastructure
Under `_KERNEL`, declares:
- `sysctl_root`
- `struct sysctllog`
- `SYSCTL_SETUP` registration macros with module and rump constructor variants.
- Dispatch and locking functions: `sysctl_lock`, `sysctl_dispatch`, `sysctl_unlock`, `sysctl_relock`.
- Tree operations: `sysctl_locate`, `sysctl_query`, `sysctl_create`, `sysctl_destroy`, `sysctl_lookup`, `sysctl_describe`.
- Variadic creation/destruction: `sysctl_createv`, `sysctl_destroyv`.
- Type verification wrappers for `sysctl_createv`.

## Userland API
Declares:
- `sysctl`
- `sysctlbyname`
- `sysctlgetmibinfo`
- `sysctlnametomib`
- `proc_compare`
- allocation helpers `asysctl`, `asysctlbyname`
- `__learn_tree`

## ABI Notes
`struct sysctlnode` uses `__sysc_pad` and `__sysc_unpad` to preserve layout across 32/64-bit and endian combinations. Descriptions use variable-length `struct sysctldesc` records with `NEXT_DESCR`.

## Research Takeaway
This is both a user ABI header and a kernel registration framework. For filesystem research, it is the primary bridge from VFS/kernel state to tools such as `sysctl`, `ps`, `fstat`, `vmstat`, and storage-monitoring utilities.

# File Research: sources/os/bsd/netbsd-src/sys/sys/syslog.h

## Purpose
Defines NetBSD syslog priorities, facilities, openlog option flags, reentrant syslog state, and user/kernel logging prototypes.

## Key Constants
- `_PATH_LOG "/var/run/log"`
- Priorities:
  - `LOG_EMERG` through `LOG_DEBUG`
  - `LOG_PRIMASK`, `LOG_PRI(p)`
- Facilities:
  - `LOG_KERN`, `LOG_USER`, `LOG_MAIL`, `LOG_DAEMON`, `LOG_AUTH`, `LOG_SYSLOG`, `LOG_LPR`, `LOG_NEWS`, `LOG_UUCP`, `LOG_CRON`, `LOG_AUTHPRIV`, `LOG_FTP`

  - `LOG_NFACILITIES`, `LOG_FACMASK`, `LOG_FAC(p)`

## Logging Options
For `openlog`:
- `LOG_PID`, `LOG_CONS`, `LOG_ODELAY`, `LOG_NDELAY`, `LOG_NOWAIT`, `LOG_PERROR`, `LOG_PTRIM`, `LOG_NLOG`

For masks:
- `LOG_MASK(pri)`
- `LOG_UPTO(pri)`

## Userland API
Declares:
- `closelog`, `openlog`, `setlogmask`, `syslog`
- NetBSD extensions: `vsyslog`, reentrant `_r` variants, structured `syslogp`/`vsyslogp`, and `_ss` variants.
- `struct syslog_data` and `SYSLOG_DATA_INIT` support reentrant logging state.

## Kernel API
Under `_KERNEL`, declares:
- `LOG_PRINTF`
- `logpri`
- `log`, `vlog`
- `addlog`
- `logwakeup`

## Filesystem / Storage Relevance
Filesystem and storage code use kernel logging for mount failures, device errors, metadata corruption, I/O warnings, and recovery messages. Userland filesystem tools and daemons use the same priority/facility encoding when reporting operational events.

## ABI/API Notes
Priority occupies the low three bits and facility is shifted by three. Facility/priority string tables are only emitted when `SYSLOG_NAMES` is defined, which avoids unintentional global data in normal consumers.
