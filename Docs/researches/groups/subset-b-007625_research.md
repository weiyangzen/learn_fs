# sources/distributed-fs/lizardfs/src/common/richacl.h

Purpose: declares the `RichACL` model used to represent NFSv4/RichACL permissions, POSIX-derived file masks, inheritance flags, and ACE lists. Important APIs/types: `RichACL::Ace` contains compact bitfield `type`, `flags`, `mask`, and `id`; top-level methods expose mode conversion, permission checks, mask application, POSIX ACL conversion, inheritance, string conversion, and serialization through `LIZARDFS_DEFINE_SERIALIZE_METHODS`. Control flow: callers build or deserialize an ACL, optionally mutate masks or ACEs, then use `checkPermission`, conversion helpers, or inheritance helpers. State/persistence: persistent state is owner/group/other masks, ACL flags, and `ace_list_`; the serialized wire/storage order is fixed by the macro. Dependencies: `AccessControlList`, `serialization_macros.h`, `sys/stat.h`, and exception support. Integration points: used by ACL xattr converters, POSIX ACL translation, string parsing, metadata serialization, and permission checks. Risks: bitfield widths silently truncate unsupported flags/masks, ACE order is semantically significant, and `checkPermission` uses goto labels to model owner/everyone matching. Test signals: direct coverage comes through `richacl_string_unittest.cc`; deeper permission/inheritance behavior depends on tests outside this subset.

# sources/distributed-fs/lizardfs/src/common/richacl_compat.cc

Purpose: implements compatibility transformation that applies RichACL file masks to an ACE list so standard NFSv4 permission evaluation gives the same result as mask-aware RichACL evaluation. Important APIs/functions: `RichACL::applyMasks`, `changeMask`, `moveEveryoneAcesDown`, `propagateEveryone`, `applyMasks2AceList`, `setOtherPermissions`, `setOwnerPermissions`, `isolateOwnerClass`, and `isolateGroupClass`. Control flow: `applyMasks` exits unless `kMasked` is set, moves EVERYONE entries downward, propagates inherited permissions into specific identities, clips allow ACEs by owner/group/other masks, synthesizes explicit allow/deny entries, clears `kWriteThrough`/`kMasked`, and shrinks storage. State/persistence: mutates `ace_list_`, ACE flags, ACE masks, and ACL flags in place; no external persistence except serialized ACL state later. Dependencies: `richacl.h` and assertions. Integration points: called by `objectToNFSXattr` before exporting ACLs as NFS xattrs. Risks: algorithms assume meaningful ACE ordering and often special-case the last EVERYONE ACE; mutation while iterating is subtle; one branch appears to clear `kInheritOnlyAce` from `last_ace.mask` rather than `last_ace.flags`, which deserves review. Test signals: no direct unit test in this subset; string tests do not validate mask compatibility semantics.

# sources/distributed-fs/lizardfs/src/common/richacl_converter.cc

Purpose: converts `RichACL` objects to and from on-disk RichACL xattr format and NFSv4 ACL xattr format. Important APIs/functions: `extractObjectFromNFS`, `extractObjectFromRichACL`, `objectToRichACLXattr`, `objectToNFSXattr`, plus helpers for padded NFS names, uid/gid lookup, and wrapper structs matching xattr layouts. Control flow: NFS extraction reads an ACE count, parses big-endian packet fields using datapack helpers, maps OWNER/GROUP/EVERYONE names or uid/gid strings into ACE identifiers, then recomputes masks from ACL decisions. RichACL extraction reads little-endian wrapper fields and converts an incompatible special-who flag bit to LizardFS `kSpecialWho`. Export builds either little-endian RichACL wrappers or NFS records after `applyMasks(owner_id)`. State/persistence: produces byte vectors for xattrs and reconstructs transient ACL state; uses platform user/group databases when available. Dependencies: `portable_endian.h`, `datapack.h`, `pwd.h`, `grp.h`, `richacl_converter.h`. Integration points: bridges metadata ACL objects to filesystem xattrs and NFS clients. Risks: C-style casts over unaligned buffers, lookup-dependent uid/gid name conversion, inconsistent use of padded owner length as serialized length in NFS export, and limited validation of ACE type/flags. Test signals: no direct converter test in this subset.

# sources/distributed-fs/lizardfs/src/common/richacl_posix_convert.cc

Purpose: translates between POSIX ACLs and RichACLs, including default/inheritable POSIX ACLs. Important APIs/functions: `appendPosixACL`, `appendDefaultPosixACL`, `convertToPosixACL`, `convertToDefaultPosixACL`, and `hasGroupEntry`. Control flow: minimal POSIX ACLs become mask-only RichACLs with `kMasked|kWriteThrough`; extended ACLs create owner/group/named user/named group/everyone allow ACEs, isolate POSIX classes using deny entries, compute masks, and simulate POSIX mask entries through `group_mask_`. Reverse conversion derives mode bits from masks or `allowedToWho`, creates named user/group entries on first occurrence, and optionally emits POSIX mask. State/persistence: mutates the target ACL's masks, flags, and ACE list; no direct disk I/O. Dependencies: `AccessControlList`, `RichACL` helpers from `richacl.cc`, POSIX mode conversion constants. Integration points: metadata ACL storage, client chmod/setfacl behavior, default ACL inheritance. Risks: reverse conversion is approximate by design, duplicate ACEs after first named identity are ignored, and files strip `kDeleteChild` while directories keep it. Test signals: no direct unit test in this subset; should be covered by ACL conversion/integration tests elsewhere.

# sources/distributed-fs/lizardfs/src/common/richacl_string.cc

Purpose: implements compact textual serialization and parsing for RichACLs and ACEs. Important APIs/functions: `RichACL::toString`, `RichACL::Ace::toString`, `RichACL::fromString`, plus local parsers for ACL flags, ACE flags, masks, types, and identifiers. Control flow: `toString` emits `FLAGS|OWNER|GROUP|OTHER|ACE/...` with masks/flags in canonical table order; parsing walks delimiter-separated fields, accepts unsorted but recognized flag/mask characters, converts `O/G/E/uN/gN` identifiers, and throws `FormatException` on missing fields or unknown symbols. State/persistence: text is a stable diagnostic/config representation of masks, flags, and ACE list; parsing creates a new ACL. Dependencies: `richacl.h`, static lookup arrays derived from RichACL constants. Integration points: tests, debugging, config-like representations, and round-trip validation. Risks: `writeType` appends numeric `type` as a char-like value on unknown types, numeric identifier parsing uses `substr(start, delim)` rather than length but still usually stops at delimiters through `stoull`, and unsupported flags are not preserved. Test signals: `richacl_string_unittest.cc` validates canonical string output, unsorted input normalization, round-trip equality, and malformed input throws.

# sources/distributed-fs/lizardfs/src/common/ring_buffer.h

Purpose: provides a fixed-capacity circular FIFO-style container with random access by logical offset. Important APIs/types: `RingBuffer<T, Capacity>`, `push_back`, `pop_front`, `front`, `back`, `operator[]`, `size`, `capacity`, `empty`, and `full`. Control flow: the buffer stores `Capacity + 1` elements to distinguish full from empty; `start_` points at the front and `end_` at the next insertion slot; helper functions wrap indices modulo `N`. State/persistence: all state is in the embedded `std::array<T, N>` plus integer cursors; no heap allocation beyond `T` internals and no serialization. Dependencies: `array`, `cassert`, `platform.h`. Integration points: useful for bounded queues in hot paths. Risks: preconditions are enforced only by `assert`, so release builds can overrun logical constraints; capacity is compile-time only; no iterator API or thread safety. Test signals: `ring_buffer_unittest.cc` covers basic fill, full detection, FIFO pop, and empty detection.

# sources/distributed-fs/lizardfs/src/common/rotate_files.cc

Purpose: implements numbered backup rotation for a base file. Important APIs/functions: public `rotateFiles` and local `rotateFile`. Control flow: `rotateFiles` asserts `byNumber > 0`, then for `storedPreviousCopies > 0` walks from the highest retained copy down to 2, renaming `file.(n-byNumber)` to `file.n`, then renames the base file to `file.byNumber`; individual renames can be skipped if the source does not exist. State/persistence: mutates filesystem entries through `fs::rename`; failures are logged but not thrown. Dependencies: LizardFS filesystem wrapper `cwrap`, `FilesystemException`, `massert`, and `slogger`. Integration points: used by components that rotate changelogs, metadata backups, or logs. Risks: by-number gaps can produce surprising source names, failed renames leave partially rotated sets, and there is no atomic multi-file transaction. Test signals: no direct unit test in this subset.

# sources/distributed-fs/lizardfs/src/common/serialization.h

Purpose: central binary serialization/deserialization framework for primitive types, strings, STL containers, LizardFS small/compact/flat containers, pairs, arrays, unique pointers, and user-defined serializable objects. Important APIs/types: `serializedSize`, pointer-based `serialize`/`deserialize`, vector-buffer `serialize(std::vector<uint8_t>&, ...)`, `deserialize(buffer, ...)`, `deserializeAndIgnore`, and `IncorrectDeserializationException`. Control flow: serialization computes total size, resizes an empty output vector, then writes fields sequentially through datapack `put*` helpers. Deserialization verifies size before primitive reads, rejects invalid booleans, enforces a 32 MiB top-level byte cap and 1M element cap, requires strings to be null-terminated, and expects output strings/containers/pointers to be empty before filling. State/persistence: defines stable packet/storage byte layout for many common types; container sizes are serialized as `uint32_t`. Dependencies: `datapack.h`, `massert`, `small_vector`, `compact_vector`, `flat_set`, `flat_map`, `Exception`. Integration points: packet macros, metadata records, RichACL serialization, tape structs, goals, and many protocol types. Risks: output buffer must be empty, deserialization into non-empty objects asserts or throws, aggregate `serializedSize` can overflow `uint32_t`, and maps/sets silently drop duplicate serialized keys through insert. Test signals: `serialization_unittest.cc` covers strings, vectors, nested maps/sets, custom allocators, unique pointers, arrays, sets, maps, and non-empty string rejection.
