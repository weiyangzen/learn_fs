# sources/distributed-fs/ceph-client/drivers/net/usb/hso.c

Purpose: Implements the Option/GlobeTrotter HSO USB mobile broadband driver. It exposes supported vendor-specific USB interfaces as a mix of raw IP WWAN net devices, ttyHS serial ports for modem/control/diagnostic channels, and rfkill control for WWAN radio state.

Important APIs and types: Core state is split across `struct hso_device`, `struct hso_net`, `struct hso_serial`, `struct hso_shared_int`, and `struct hso_tiocmget`. The USB driver is `hso_driver`; the tty driver is allocated in `hso_init()` and uses `hso_serial_ops`. Network entry points are `hso_net_open()`, `hso_net_close()`, `hso_net_start_xmit()`, `read_bulk_callback()`, and `packetizeRx()`. Serial entry points include `hso_serial_open()`, `hso_serial_close()`, `hso_serial_write()`, `hso_kick_transmit()`, `hso_std_serial_read_bulk_callback()`, `hso_std_serial_write_bulk_callback()`, `ctrl_callback()`, and the modem-control helpers `hso_serial_tiocmget()`, `hso_serial_tiocmset()`, `hso_wait_modem_status()`, and `hso_get_count()`. Device creation and destruction are driven by `hso_probe()`, `hso_create_net_device()`, `hso_create_bulk_serial_device()`, `hso_create_mux_serial_device()`, `hso_free_interface()`, and the shared interrupt helpers.

Control flow: Probe accepts only vendor-specific interfaces, derives a `port_spec` from static `driver_info` arrays or from device config command `0x86`, optionally switches altsetting 1, and creates either a network device, a bulk serial tty, or a mux network plus several mux serial ttys discovered from descriptor extra bytes. Network open resets the IP stream parser, starts four bulk RX URBs, and enables the net queue. TX copies a raw IP frame into a preallocated mux bulk buffer, submits a bulk URB with `URB_ZERO_PACKET`, and wakes the queue on completion. RX treats USB bulk data as a stream of IPv4 packets: it accumulates an IP header, validates `tot_len` against `DEFAULT_MRU`, allocates an skb, copies payload bytes until complete, injects with `netif_rx()`, and uses `WAIT_SYNC` until an end-of-packet boundary after malformed lengths. Serial open takes runtime-PM, applies fixed raw 115200 termios, starts either bulk RX URBs or a shared mux interrupt URB, and starts modem-status interrupt tracking where available. Mux serial reads are triggered by the shared interrupt bitmap and performed via vendor CDC encapsulated control transfers; mux writes use the matching send command. Bulk serial ports use ordinary bulk in/out URBs. Suspend stops all matching serial and network URBs; resume restarts only open tty ports and net ports that appear up, then kicks pending TX.

State and persistence behavior: Persistent module state includes `serial_table[256]`, `network_table[10]`, `tty_drv`, and module parameters `debug`, `tty_major`, and `disable_net`. Runtime state is held in registered netdev and tty-port private objects, URBs, buffers, parser fields, modem line counters, rfkill object, and shared interrupt use/ref counts. No on-disk persistence exists. Lifetime is guarded by `kref` for serial devices, `serial_table_lock`, per-device mutexes, serial/net spinlocks, tty port references, and USB runtime-PM work items (`async_get_intf`, `async_put_intf`). Disconnect marks serial devices `usb_gone`, hangs up tty ports, cancels PM work, unregisters tty/netdev/rfkill objects, kills URBs, and frees private buffers.

Dependencies and integration points: Integrates directly with Linux USB core, tty core, netdev core, rfkill, runtime PM/autosuspend, ethtool link reporting, CDC request constants, ARPHRD_NONE raw-IP networking, and kernel work/tasklet infrastructure. Device matching covers many Option vendor/product IDs and two static interface maps. The serial side exports dynamic `/dev/ttyHS*` devices with an `hsotype` sysfs attribute. The network side registers `hso%d` WWAN devices and an `hso-N` rfkill switch.

Risks and test signals: High-risk areas are multi-interface lifetime handling, shared mux interrupt reference counting, tty throttling/unthrottling, parser resynchronization after malformed raw IP lengths, PM work racing disconnect, `skb_tx_buf` resume replay, and error paths during partial probe creation. `hso_resume()` checks `hso_net->flags & IFF_UP`, but `hso_net->flags` is a private bitset where `HSO_NET_RUNNING` is bit 0; this deserves regression coverage because it differs from netdev flag semantics. Tests should cover probe with static and device-reported port maps, `disable_net=1`, mux interrupt bitmap fanout, tty open/write/close while autosuspended, modem `TIOCMIWAIT`/`TIOCGICOUNT`, malformed or fragmented IP stream RX, CRC-bug devices, suspend/resume with queued TX, disconnect with open tty/netdev, rfkill block/unblock, and failures in URB allocation or endpoint discovery.

# sources/distributed-fs/ceph-client/drivers/net/usb/huawei_cdc_ncm.c

Purpose: Provides a Huawei-specific CDC NCM usbnet wrapper for WWAN devices that look like vendor-specific interfaces and carry an embedded AT/control channel alongside NCM data transport.

Important APIs and types: `struct huawei_cdc_ncm_state` is stored in `usbnet->data` and tracks the `cdc_ncm_ctx`, runtime-PM reference count, registered cdc-wdm subdriver, and control/data interfaces. Main hooks are `huawei_cdc_ncm_bind()`, `huawei_cdc_ncm_unbind()`, `huawei_cdc_ncm_manage_power()`, `huawei_cdc_ncm_wdm_manage_power()`, `huawei_cdc_ncm_suspend()`, and `huawei_cdc_ncm_resume()`. `huawei_cdc_ncm_info` wires the driver into usbnet with `cdc_ncm_rx_fixup()` and `cdc_ncm_tx_fixup()`.

Control flow: `usbnet_probe()` calls bind through `driver_info`. Bind forces CDC NCM altsetting 1 and enables `CDC_NCM_FLAG_NDP_TO_END` plus `CDC_NCM_FLAG_PREFER_NTB32`, then delegates descriptor and endpoint setup to `cdc_ncm_bind_common()`. If a status endpoint exists, it registers a `cdc-wdm` WWAN AT port on the NCM control interface with a 1024-byte command buffer and installs a power-management callback. It then clears `usbnet_dev->status` so usbnet itself does not consume the same interrupt/status descriptor. Unbind disconnects the cdc-wdm subdriver before `cdc_ncm_unbind()`. Suspend first suspends usbnet and then the subdriver for the control interface, rolling usbnet back on subdriver failure. Resume calls the subdriver first when applicable, then usbnet, and re-suspends the subdriver if usbnet resume fails.

State and persistence behavior: State is transient per USB interface. `pmcount` reference-counts power users and toggles `needs_remote_wakeup`; there is no persistent storage. The cdc-wdm subdriver pointer is nulled on unbind to avoid stale callbacks. The code assumes `drvstate->ctx` has been populated by `cdc_ncm_bind_common()` through the usbnet data area.

Dependencies and integration points: Depends on usbnet, cdc_ncm common binding and frame fixups, cdc-wdm, WWAN port typing (`WWAN_PORT_AT`), USB autosuspend, and Huawei vendor/interface IDs for class `0xff` subclasses/protocols. The module disables hub-initiated LPM and supports autosuspend.

Risks and test signals: The most important risks are sharing the status endpoint correctly between NCM and cdc-wdm, balancing PM reference transitions for concurrent data/control users, and suspend/resume rollback ordering. Test signals include successful AT port registration, no usbnet status URB conflict after bind, NTB32 operation on devices refusing NTB16, NDP-at-end framing, autosuspend with active wdm users, disconnect while `huawei_cdc_ncm_wdm_manage_power()` runs, and resume failure paths for both subdriver and usbnet.

# sources/distributed-fs/ceph-client/drivers/net/usb/int51x1.c

Purpose: Implements a compact usbnet minidriver for Intellon INT51x1 USB powerline adapters, adding the device's two-byte length framing around Ethernet packets.

Important APIs and types: The driver has no private state beyond usbnet. Key functions are `int51x1_bind()`, `int51x1_rx_fixup()`, and `int51x1_tx_fixup()`. `int51x1_netdev_ops` delegates normal netdev operations to usbnet helpers, and `int51x1_info` provides fixed endpoint numbers, `FLAG_ETHER`, the RX/TX fixups, and `usbnet_cdc_update_filter()` for receive filter updates.

Control flow: Probe is handled by `usbnet_probe()`. Bind reads the Ethernet address from string/index 3 via `usbnet_get_ethernet_addr()`, adds the private two-byte header to `hard_header_len`, recomputes `hard_mtu`, swaps in the driver's netdev ops, and asks usbnet to discover endpoints. RX fixup verifies at least a two-byte header is present, reads a little-endian length from the trailing two bytes of the received skb, trims the skb to that length, and lets usbnet continue. TX fixup ensures room for a two-byte little-endian length prefix plus any tail padding needed to avoid short packet/ZLP ambiguity, expands or compacts the skb if needed, pushes the header, stores the masked packet length, appends zero padding, and returns the adjusted skb to usbnet.

State and persistence behavior: There is no persistent device state. Packet framing state is entirely per skb. Statistics, queueing, suspend/resume, disconnect, and endpoint URB handling are owned by usbnet.

Dependencies and integration points: Integrates with usbnet, MII/ethtool headers through usbnet conventions, Ethernet address helpers, CDC receive filter helper, and one USB device ID pair (`0x09e1:0x5121`). It sets endpoint numbers `.in = 1` and `.out = 2` rather than scanning descriptors in the driver itself.

Risks and test signals: RX trusts the device-provided trailing length after only ensuring a minimum frame size; tests should include malformed lengths larger than skb length, tiny frames, and padded frames. TX risk is in headroom/tailroom reshaping and the exact padding rules around `dev->maxpacket`, especially packets shorter than 64 bytes or exact multiples of maxpacket. Build and runtime coverage should exercise MTU changes, multicast filter updates, MAC address setting, suspend/resume through usbnet, and SKB cloned/non-cloned TX paths.

# sources/distributed-fs/ceph-client/drivers/net/usb/ipheth.c

Purpose: Implements the Apple iPhone USB Ethernet/tethering driver for paired iOS devices using a vendor-specific USB interface. It supports legacy RX framing and a limited iOS NCM-like RX mode while sending TX frames as plain Ethernet payloads.

Important APIs and types: `struct ipheth_device` owns the USB device/interface, netdev, one TX URB, one RX URB, coherent TX/RX buffers, a control buffer, endpoint addresses, delayed carrier work, pairing confirmation, the chosen RX parser, and RX buffer length. Main functions are `ipheth_probe()`, `ipheth_disconnect()`, `ipheth_open()`, `ipheth_close()`, `ipheth_tx()`, `ipheth_rx_submit()`, `ipheth_rcvbulk_callback()`, `ipheth_rcvbulk_callback_legacy()`, `ipheth_rcvbulk_callback_ncm()`, `ipheth_sndbulk_callback()`, `ipheth_carrier_set()`, `ipheth_get_macaddr()`, and `ipheth_enable_ncm()`.

Control flow: Probe allocates an Ethernet netdev, locates altsetting 1 and reverse common bulk endpoints, allocates a control buffer, requests the MAC address with vendor request `0x00`, attempts vendor request `0x04` to enable NCM RX, selects either a legacy 1516-byte RX buffer/parser or a 64 KiB NCM parser, allocates coherent URB buffers, registers the netdev, and leaves carrier and TX queues off until device traffic confirms pairing. Open sets interface number 2 to altsetting 1, performs a carrier query if pairing has been confirmed, submits one RX URB, and schedules periodic carrier polling. RX callback ignores empty URBs and a known four-byte control frame, parses data through the selected parser, marks pairing confirmed, and resubmits RX. Legacy parsing skips two bytes of IP alignment before building an skb. NCM parsing validates fixed iOS NTH16/NDP16 headers, walks up to 22 DPE entries until a null DPE, validates datagram bounds, and emits each Ethernet frame. TX copies skb data into the coherent TX buffer, submits one bulk OUT URB, stops the queue until completion, and updates software stats. Carrier work sends vendor request `0x45`; positive carrier wakes TX when no TX URB is in progress, otherwise it stops queue/carrier.

State and persistence behavior: Runtime state is per netdev and not persisted. The `confirmed_pairing` flag gates carrier checks until at least one valid bulk-in event has arrived, preventing noisy checks before pairing. One TX URB serializes transmit by stopping the queue; one RX URB is continuously resubmitted while open. Disconnect unregisters the netdev, kills URBs, frees coherent buffers and control buffer, and clears interface data.

Dependencies and integration points: Integrates directly with USB core, netdev/etherdevice APIs, ethtool link reporting, delayed work, and CDC NCM header definitions. It matches Apple vendor-specific interface class/subclass/protocol, not product IDs, and disables hub-initiated LPM.

Risks and test signals: Important risks are NCM bounds validation, queue recovery on URB errors, delayed carrier work racing close/disconnect, single-URB TX serialization, and devices that require pairing before any control request succeeds. Tests should cover paired versus unpaired devices, legacy mode when NCM enable fails, NCM multi-datagram URBs, malformed signatures/DPE indices/lengths, zero-length and control-frame RX drops, TX timeout unlink, carrier on/off transitions, open/close without killing RX in close, and disconnect while work or URBs are active.

# sources/distributed-fs/ceph-client/drivers/net/usb/kalmia.c

Purpose: Provides a usbnet minidriver for Samsung Kalmia LTE USB modems such as GT-B3730/GT-B3710, handling their proprietary packet header/trailer format and initialization exchange while modem control is handled by a separate ACM/option port.

Important APIs and types: The driver is built around usbnet callbacks with no custom private structure. Key functions are `kalmia_bind()`, `kalmia_init_and_get_ethernet_addr()`, `kalmia_send_init_packet()`, `kalmia_tx_fixup()`, and `kalmia_rx_fixup()`. `kalmia_info` supplies `FLAG_WWAN`, bind, RX fixup, and TX fixup to usbnet.

Control flow: Bind rejects non-vendor-specific interfaces to avoid claiming the AT command interface, verifies bulk endpoints `0x81` and `0x02`, stores fixed pipes, disables status handling, adds the six-byte Kalmia header to `hard_header_len`, sets `hard_mtu` to 1400 and RX URB size to ten times that value, then sends two empirically derived bulk initialization packets. The second response contains the modem MAC address at offset 10. TX fixup ensures headroom/tailroom, pushes a six-byte header beginning `0x57 0x44`, writes the little-endian payload length, copies the Ethernet type bytes into header bytes 4-5, and pads the skb to a four-byte boundary. RX fixup walks one or more proprietary records in a single usbnet skb, validates expected `0x57 0x44` data headers or two known non-data headers, reads the payload length, strips the header, checks for the `0x57 0x5a ...` end marker when present, returns the final frame in the original skb, and clones/returns earlier frames through `usbnet_skb_return()`.

State and persistence behavior: No persistent state is stored. Initialization packets are synchronous per bind and only the MAC address is retained in the netdev. Per-packet state is kept in skb offsets and optional clones. usbnet owns normal queues, URBs, stats, and PM callbacks.

Dependencies and integration points: Depends on usbnet, USB bulk messaging, Ethernet helpers, unaligned little-endian accessors, and vendor/product IDs for both unswitched and modem modes. The unswitched ID lets the module autoload, while the switched ID carries `kalmia_info` for usbnet binding after userspace mode switching.

Risks and test signals: The framing parser is empirically derived and must handle multiple frames, missing small-packet trailers, unknown headers, clone allocation failures, and inconsistent payload lengths. TX risks are skb head/tail expansion, four-byte alignment padding, and preserving Ethernet type metadata in the private header. Tests should cover mode-switched versus unswitched IDs, init response length errors, MAC extraction, short RX headers, multiple frames per URB, expected unknown headers, missing end marker cases, malformed length/trailer, cloned and non-cloned TX skb paths, and DHCP/WWAN bring-up after AT connection.

# sources/distributed-fs/ceph-client/drivers/net/usb/kaweth.c

Purpose: Implements the KL5KUSB101/Kawasaki USB Ethernet driver for a large set of early USB Ethernet adapters. It handles firmware download/triggering, vendor control setup, custom two-byte RX/TX packet length headers, interrupt-based link state, multicast/promiscuous filter programming, autosuspend, and low-memory URB resubmission.

Important APIs and types: `struct kaweth_device` owns status flags, endpoint URBs, coherent RX and interrupt buffers, TX skb, firmware/control scratch buffers, packet filter bitmap, delayed low-memory work, configuration descriptor data, link/open state, and locks. Firmware and control helpers include `kaweth_download_firmware()`, `kaweth_trigger_firmware()`, `kaweth_reset()`, `kaweth_read_configuration()`, `kaweth_set_urb_size()`, `kaweth_set_sofs_wait()`, and `kaweth_set_receive_filter()`. Data path and lifecycle functions include `kaweth_probe()`, `kaweth_disconnect()`, `kaweth_open()`, `kaweth_close()`, `kaweth_start_xmit()`, `kaweth_usb_receive()`, `kaweth_usb_transmit_complete()`, `kaweth_set_rx_mode()`, `kaweth_async_set_rx_mode()`, `kaweth_suspend()`, and `kaweth_resume()`.

Control flow: Probe verifies required bulk and interrupt endpoints, allocates the netdev/private state, resets the USB configuration, and either downloads four firmware blobs plus a trigger command when firmware is absent or continues if firmware is already resident. The firmware path intentionally returns `-EIO` after triggering because the device is expected to disconnect and re-enumerate. For a live firmware device, probe reads the Ethernet configuration, rejects an all-broadcast MAC, programs URB size, SOF wait, and an initial directed/broadcast/multicast filter, allocates TX/RX/IRQ URBs and coherent buffers, initializes netdev properties from the device segment size/MAC, and registers the netdev. Open runtime-resumes the interface, submits RX and interrupt URBs, marks the device open, starts the queue, and flushes pending RX filter state. RX callback reads a little-endian packet length from the first two bytes, validates it against actual USB length, allocates an skb with alignment reserve, copies the Ethernet frame, updates stats, and resubmits RX unless blocked or fatal status occurs. TX prepends a two-byte length header in the skb, submits the bulk OUT URB, stops the queue until completion, and frees the skb in the completion callback. Interrupt callback decodes link state from the interrupt buffer and resubmits the interrupt URB. Close/suspend set blocking flags and kill URBs; resume clears suspend state and resubmits RX/interrupt URBs if opened.

State and persistence behavior: No on-disk persistence exists. Firmware loaded into the adapter persists across the forced re-enumeration signaled by `bcdDevice` high byte. In-kernel state persists per netdev while the USB interface is bound: status bits (`BROKEN`, `CLOSING`, `SUSPENDING`), `opened`, linkstate, low-memory retry flags, packet filter bitmap, and allocated DMA buffers. `device_lock` protects status-sensitive TX/RX/suspend interactions. `lowmem_work` retries RX or interrupt URB submissions after `-ENOMEM`, unless the device is closing or suspending.

Dependencies and integration points: Integrates with Linux firmware loading (`request_firmware()` with four declared `MODULE_FIRMWARE()` files), USB vendor control transfers, coherent DMA URB buffers, netdev/etherdevice APIs, ethtool link reporting, delayed work, runtime PM, and a broad USB ID table for KL5USB101-based adapters.

Risks and test signals: High-risk areas are firmware download sequencing, expected disconnect/re-enumeration behavior, partial probe unwind, RX length validation from device-provided headers, multicast/promiscuous filter deferral through `packet_filter_bitmap`, queue recovery after TX timeout, and races among low-memory retry work, close, suspend, and disconnect. The interrupt link-state expression should be scrutinized because it ORs `STATE_MASK` before shifting, which may force link state rather than mask it. Tests should cover firmware missing/oversized/corrupt cases, already-loaded firmware, all-broadcast MAC rejection, control transfer failures, open/close PM balance, RX short and overlong packets, TX skb head expansion failure, low-memory resubmit paths, multicast/promiscuous mode updates while TX holds the lock, suspend/resume while open and closed, and disconnect after active URBs.
