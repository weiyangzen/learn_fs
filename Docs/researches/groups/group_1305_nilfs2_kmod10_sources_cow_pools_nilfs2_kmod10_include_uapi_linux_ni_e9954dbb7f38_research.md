# File Research: sources/cow-pools/nilfs2-kmod10/include/uapi/linux/nilfs2_ondisk.h

## Purpose

`nilfs2_ondisk.h` is the NILFS2 on-disk format contract exposed through UAPI. It defines the little-endian disk layouts, magic values, inode numbers, feature flags, segment-summary records, checkpoint metadata, segment-usage metadata, and small endian-aware flag helpers used by the NILFS2 kernel module and compatible userspace tooling.

This header is layout-critical. Most definitions describe persistent filesystem bytes, not in-memory policy. Changes to structure order, field width, padding, offset macros, or flag bit assignment can break mounted filesystems, recovery, cleaner behavior, and compatibility with userspace NILFS tools.

## Major Definitions

The file begins with UAPI/kernel type dependencies: `linux/types.h`, `linux/magic.h`, and `asm/byteorder.h`. The endian annotations are part of the contract: persistent numeric fields are mostly `__le16`, `__le32`, or `__le64`, and inline helpers convert through `__le32_to_cpu`, `__cpu_to_le32`, and `__cpu_to_le64`.

Core on-disk structures:

- `struct nilfs_inode`: fixed on-disk inode body with block count, size, timestamps, uid/gid, mode, link count, flags, a seven-entry block map array, xattr pointer, generation, and padding. `i_device_code` aliases `i_bmap[0]` for special-device inodes. `NILFS_MIN_INODE_SIZE` is 128 bytes.
- `struct nilfs_super_root`: super-root checksum/size/flags/time plus embedded raw inodes for the DAT, checkpoint file, and segment usage file. `NILFS_SR_*_OFFSET()` and `NILFS_SR_BYTES()` compute inode-size-dependent offsets.
- `struct nilfs_super_block`: primary on-disk superblock format, including revision, magic, CRC fields, geometry, log cursor, free block count, mount/check metadata, creator OS, reserved ownership defaults, metadata record sizes, UUID, volume name, segment-construction tunables, feature masks, and reserved tail. `NILFS_SB_BYTES` computes the CRC-covered length up to `s_reserved`.
- `struct nilfs_dir_entry`: ext2-style directory record with 64-bit inode, record length, name length, file type, name buffer, and padding. `NILFS_DIR_REC_LEN()` rounds directory record lengths to 8-byte boundaries.
- `struct nilfs_finfo`, `struct nilfs_binfo_v`, `struct nilfs_binfo_dat`, and `union nilfs_binfo`: segment-summary payload records linking file/checkpoint/block information to virtual blocks or DAT node blocks.
- `struct nilfs_segment_summary`: per-segment summary header with data checksum, summary checksum, magic, flags, sequence, creation timestamp, next segment, block counts, summary byte count, and checkpoint number.
- `struct nilfs_btree_node` and `struct nilfs_direct_node`: on-disk headers for block-map btree/direct representations.
- `struct nilfs_palloc_group_desc`: persistent allocator group descriptor containing the free-entry count.
- `struct nilfs_dat_entry`: DAT entry mapping virtual blocks to physical block numbers and checkpoint lifetime range.
- `struct nilfs_snapshot_list`, `struct nilfs_checkpoint`, and `struct nilfs_cpfile_header`: checkpoint-file records, snapshot list links, counters, checkpoint flags, and the embedded ifile inode. The comment on `cp_ifile_inode` explicitly forbids changing its byte offset.
- `struct nilfs_segment_usage` and `struct nilfs_sufile_header`: segment usage records and sufile header counters for clean/dirty segments and the last allocation cursor.

Important constants and macros:

- Filesystem states: `NILFS_VALID_FS`, `NILFS_ERROR_FS`, `NILFS_RESIZE_FS`.
- Mount flags: error handling mode bits, barrier, strict ordering, no-recovery, and discard.
- Revision/features: current/min supported revision 2, read-only compatible block-count feature, no supported compat or incompat features.
- Special inode numbers: root, DAT, cpfile, sufile, ifile, reserved atime/xattr, sketch, and first user inode.
- Geometry and limits: superblock offset 1024 bytes, secondary superblock offset calculation, minimum segment and partial-segment block counts, minimum reserved segments, link max 32000, name length 255, block size range 1024 to 65536.
- Segment-summary magic and flags: log begin/end, has super root, synchronous data-only update, and cleaner-generated segment.
- Btree constants: root flag and level bounds.
- Metadata-entry minimum sizes and first-entry offset calculations for cpfile and sufile.

Inline helpers generated by macros:

- `nilfs_checkpoint_set_snapshot`, `nilfs_checkpoint_clear_snapshot`, `nilfs_checkpoint_snapshot`.
- `nilfs_checkpoint_set_invalid`, `nilfs_checkpoint_clear_invalid`, `nilfs_checkpoint_invalid`.
- `nilfs_checkpoint_set_minor`, `nilfs_checkpoint_clear_minor`, `nilfs_checkpoint_minor`.
- `nilfs_segment_usage_set_active`, `nilfs_segment_usage_clear_active`, `nilfs_segment_usage_active`.
- `nilfs_segment_usage_set_dirty`, `nilfs_segment_usage_clear_dirty`, `nilfs_segment_usage_dirty`.
- `nilfs_segment_usage_set_error`, `nilfs_segment_usage_clear_error`, `nilfs_segment_usage_error`.
- `nilfs_segment_usage_set_clean` and `nilfs_segment_usage_clean`.

The enum value `NILFS_CHECKPOINT_SKETCH` is defined but does not get helper functions in this header, unlike snapshot, invalid, and minor.

## Integration Points

This header is included by NILFS2 kernel internals such as `fs/nilfs2/bmap.h`, and its structures are consumed across the implementation:

- Superblock parsing, validation, updates, and secondary-superblock placement use `struct nilfs_super_block`, `NILFS_SB_BYTES`, and `NILFS_SB2_OFFSET_BYTES` in superblock and NILFS core code.
- Segment construction and recovery use `struct nilfs_segment_summary`, `struct nilfs_finfo`, `union nilfs_binfo`, and `struct nilfs_super_root` to write and scan NILFS log segments.
- Inode read/write paths map between VFS inode state and `struct nilfs_inode`; block-map code serializes the raw `i_bmap` region.
- Directory code uses `struct nilfs_dir_entry`, file-type constants, `NILFS_DIR_REC_LEN`, and `NILFS_MAX_REC_LEN` for lookup, insertion, deletion, and validation.
- DAT, cpfile, and sufile code use `struct nilfs_dat_entry`, `struct nilfs_checkpoint`, `struct nilfs_cpfile_header`, `struct nilfs_segment_usage`, and `struct nilfs_sufile_header`.
- Cleaner and segment allocator behavior depends on root metadata classification through `NILFS_ROOT_METADATA_FILE()` and on segment-usage flag helpers.

Because this is under `include/uapi/linux`, compatible userspace consumers can also depend on these layouts and constants. That makes the file both a kernel-internal persistence contract and a userspace ABI surface.

## Data Flow and Behavior

There is no standalone runtime control flow beyond inline flag manipulation. The behavioral role is declarative:

1. Mount/read code reads superblock bytes from the fixed superblock offset, validates magic/revision/features/CRC fields, derives filesystem geometry, and locates current log/super-root positions.
2. Recovery and segment scanning interpret segment summaries. A segment summary points to finfo records and binfo payloads that describe which file blocks or DAT node blocks are represented in the segment.
3. Super-root records supply raw inodes for the root metadata files: DAT, cpfile, and sufile. These metadata files are not version-retained by GC like ordinary files.
4. Inode and bmap code serialize per-file persistent state through `struct nilfs_inode`, using either direct or btree block-map forms.
5. Checkpoint-file code stores checkpoint records, snapshot list links, counts, flags, and ifile inode snapshots.
6. Sufile code records clean/dirty/error/active segment state and maintains global clean/dirty counters.

The inline helpers always update or read little-endian flag fields through conversion helpers, which avoids host-endian flag corruption on non-little-endian architectures.

## Invariants and Compatibility Constraints

The most important invariant is structure layout stability. Persistent filesystems and userspace tooling assume the exact field sizes, ordering, and computed offsets in this header.

Notable invariants:

- On-disk integer fields are little-endian unless explicitly plain byte arrays or character data.
- `NILFS_MIN_INODE_SIZE`, `NILFS_MIN_DAT_ENTRY_SIZE`, `NILFS_MIN_CHECKPOINT_SIZE`, and `NILFS_MIN_SEGMENT_USAGE_SIZE` define lower bounds used to validate format geometry.
- `NILFS_SR_BYTES(inode_size)` depends on the configured inode size, so super-root size must be computed with the mounted filesystem’s inode size, not hardcoded to `sizeof(struct nilfs_inode)`.
- `NILFS_SB_BYTES` excludes `s_reserved` from superblock CRC calculation.
- `cp_ifile_inode` must retain its byte offset inside `struct nilfs_checkpoint`; new checkpoint fields must be appended after it.
- Directory record lengths must stay 8-byte aligned and fit the 16-bit record-length maximum.
- Unknown incompatible feature bits should cause mount refusal; read-only compatible features can constrain writable mounting.
- `NILFS_ROOT_METADATA_FILE(ino)` classifies only DAT, cpfile, and sufile inode numbers as root metadata files.

## Risks and Edge Cases

The highest-risk area is ABI drift. Any modification to exported structures or constants can silently corrupt disk interpretation or break old/new kernel and userspace interoperability.

Specific risks:

- Offset macros use null-pointer structure member address idioms rather than `offsetof`. This is traditional kernel style, but any refactor should preserve compile-time offset semantics and type widths.
- `NILFS_SB2_OFFSET_BYTES(devsize)` assumes a device size large enough for the shift/subtract calculation. Callers must validate device size and resulting placement.
- Directory parsing depends on `rec_len` validation against `NILFS_DIR_REC_LEN(name_len)` and block boundaries; corrupted directory entries can otherwise cause bad iteration.
- Flag helpers preserve unrelated flag bits, so callers must ensure unsupported or reserved bits are validated elsewhere.
- `nilfs_segment_usage_clean()` treats a zero `su_flags` value as clean; it does not inspect `su_nblocks` or `su_lastmod`. Code that needs full consistency must validate those fields separately.
- Feature support constants currently permit no compatible/incompatible feature bits and one read-only compatible feature. Adding feature bits requires mount-policy updates outside this header.
- `struct nilfs_dir_entry` includes a fixed `name[255]` buffer and padding, but actual on-disk entries are variable length through `rec_len`; callers must not treat the full C struct size as each directory entry’s actual serialized length.

## Summary

This file is the NILFS2 persistent-format and UAPI schema. It does not implement filesystem algorithms directly; instead it defines the exact bytes that superblocks, super roots, inodes, directory entries, segment summaries, checkpoints, DAT entries, and segment usage records occupy on disk. The main engineering concern is preserving on-disk ABI compatibility while keeping endian conversion and validation responsibilities clear in the consuming NILFS2 code.
