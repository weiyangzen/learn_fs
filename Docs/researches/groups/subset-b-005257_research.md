# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/atvda.h

Purpose: defines the packed ATTO VDA firmware ABI shared by the `esas2r` host driver and controller firmware. It is the contract for SCSI, flash, diagnostic, async-event, CLI, IOCTL, configuration, management, and generic-service requests, plus the response and payload structures the rest of the driver DMA-maps to the adapter.

Important APIs/types/functions: this header is data-only but central. Key types include `atto_dev_addr`, `atto_dev_addr2`, `atto_vda_sge`, `atto_vda_devinfo`, `atto_vda_devinfo2`, `atto_vda_grp_info`, `atto_vdapart_info`, device-health and metrics payloads, `atto_vda_ae_*` event structures, `atto_vda_cfg_init`, `atto_physical_region_description`, all request variants under `union atto_vda_req`, response unions under `union atto_vda_func_rsp`, `atto_vda_ob_rsp`, and `union atto_vda_rsp_data`. Important constants are VDA function codes, `RS_*` request statuses, flash subfunctions, management subfunctions, device/group state values, async-event types, SGE flags, and PRD flags.

Control flow: no executable flow lives here, but the structure layout drives every runtime path. `esas2r_vda.c` builders populate these request headers, `esas2r_io.c` writes request DMA addresses into inbound-list entries, firmware writes `atto_vda_ob_rsp` entries to the outbound list, and `esas2r_int.c` copies `func_rsp` data and dispatches callbacks. Discovery uses management payloads for scan, RAID-group, partition, and pass-through device information. Flash and NVRAM paths use `atto_vda_flash_req`. Async-event requests return `atto_vda_ae_data`, which is parsed into typed event unions.

State and persistence behavior: the header defines transient DMA message state rather than owning state. Some structures describe persistent controller state, especially NVRAM-adjacent configuration, RAID group/partition metadata, flash content, and device addresses, but actual persistence is performed by firmware and by `esas2r_flash.c`. All wire-format fields are packed and many are little-endian on the DMA interface, so users must convert multi-byte values at boundaries.

Dependencies and integration points: included by `esas2r.h`, which exposes the ABI to all driver implementation files. It depends on Linux fixed-width integer types and `__packed`. It integrates with SCSI command formatting, ATTO HBA IOCTL tunneling, flash firmware update tooling, target database discovery, async firmware event delivery, and management/status translation in the driver.

Risks and test signals: the primary risk is ABI drift or layout mismatch with firmware. Packed structures, unions, endianness, SGE/PRD bit fields, fixed buffer lengths, and versioned replacements such as `atto_vda_devinfo2` are sensitive. Test signals include compile-time structure size/alignment checks, firmware request/response traces for every VDA function used by the driver, big-endian and little-endian field conversion review, malformed async-event lengths, invalid management statuses, flash error statuses, and SGE/PRD chain boundary cases.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r.h

Purpose: provides the main private interface for the ATTO ExpressSAS R6xx/ThunderStream `esas2r` driver. It collects Linux SCSI/Pci includes, module-wide parameters, hardware register definitions, firmware image/NVRAM/request structures, adapter state, public internal prototypes, and inline helpers used by the implementation files.

Important APIs/types/functions: central types are `struct esas2r_adapter`, `struct esas2r_request`, `struct esas2r_sg_context`, `struct esas2r_target`, `struct esas2r_flash_context`, `struct esas2r_disc_context`, `struct esas2r_mem_desc`, `struct esas2r_sas_nvram`, flash image headers, firmware event work items, and inbound-list source entries. Important flags include `AF_*` adapter state bits for reset, discovery, flashing, power management, heartbeat, degraded mode, interrupt scheduling, and SGE mode, plus `AF2_*` feature/status bits. Inline helpers include `esas2r_alloc_sgl()`, `esas2r_sgc_init()`, `esas2r_rq_init_request()`, `esas2r_rq_destroy_request()`, interrupt enable/disable helpers, tasklet scheduling, heartbeat enable/disable, local reset setup, interrupt-pending detection, AE request start, and completion-list draining.

Control flow: this header defines the shared state machine vocabulary. Requests are initialized with `esas2r_rq_init_request()`, assigned a unique handle in `req_table`, formatted as SCSI by default, then specialized by builder functions. SG contexts are initialized against the embedded request SGE area and later consumed by legacy SGE or PRD builders. Interrupt handlers drain completions through `esas2r_comp_list_drain()`. Reset paths set `AF_CHPRST_NEEDED`, `AF_CHPRST_PENDING`, and `AF_DISC_PENDING`; tasklets and timer ticks observe those bits and call the implementation functions declared here.

State and persistence behavior: `struct esas2r_adapter` is the driver’s in-memory authority for hardware mappings, DMA memory, target database, request queues, request-handle table, async-event requests, firmware/NVRAM caches, flash metadata, wait queues, workqueue, timer, tasklet, and sysfs file state. Persistent settings are represented by `struct esas2r_sas_nvram` and written through flash/NVRAM routines, while firmware and flash revisions are cached in adapter strings/fields. Runtime state is protected by spinlocks, mutexes, semaphores, atomics, and bit flags.

Dependencies and integration points: depends on Linux PCI, DMA, workqueue, interrupt, module, timer, SCSI midlayer, `esas2r_log.h`, ATTO IOCTL definitions, and `atvda.h`. Prototypes connect to `esas2r_main.c`, `esas2r_vda.c`, `esas2r_ioctl.c`, target database code, discovery, init, flash, interrupts, and I/O. The adapter struct bridges the SCSI host, PCI device, sysfs binary attributes, firmware event queue, and firmware communication rings.

Risks and test signals: this header concentrates cross-file invariants. Request handle reuse, `req_table` cleanup, DMA alignment, SGL list ownership, interrupt disable-count balancing, and flag transitions are high-risk. Test signals include lockdep on queue/memory/SGL locks, request allocation/free stress, reset during active discovery or flashing, heartbeat enable policy, legacy SGE versus PRD firmware API selection, NVRAM defaulting, and build coverage across kernel API changes.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_disc.c

Purpose: implements device discovery for the `esas2r` adapter. It waits for firmware/device readiness, issues VDA management scans, discovers RAID partitions and pass-through devices, handles LU async-event changes, and reconciles deferred requests against the target database after topology changes.

Important APIs/types/functions: external entry points are `esas2r_disc_initialize()`, `esas2r_disc_start_waiting()`, `esas2r_disc_check_for_work()`, `esas2r_disc_check_complete()`, `esas2r_disc_queue_event()`, `esas2r_disc_start_port()`, and `esas2r_disc_local_start_request()`. Internal state handlers include `esas2r_disc_continue()`, `esas2r_disc_block_dev_scan()`, `esas2r_disc_raid_grp_info()`, `esas2r_disc_part_info()`, `esas2r_disc_passthru_dev_info()`, `esas2r_disc_passthru_dev_addr()`, `esas2r_disc_dev_remove()`, `esas2r_disc_dev_add()`, and `esas2r_disc_fix_curr_requests()`.

Control flow: initialization clears discovery flags, derives wait time/count from NVRAM, and extends waits after chip reset or power management. Completion checks either wait for a target count/time or schedules a full scan. `disc_queue_event()` records `DCDE_DEV_SCAN` or `DCDE_DEV_CHANGE`, and `disc_start_port()` starts a serialized state machine using `a->general_req`. Scan flow is `DCS_BLOCK_DEV_SCAN` to get a scan generation, then iterates RAID groups, partitions, and pass-through device records. RAID partitions call `esas2r_targ_db_add_raid()`. Pass-through devices first query management device info, then tunnel an HBA IOCTL to retrieve SAS and unique identifiers before calling `esas2r_targ_db_add_pthru()`. Device-change flow removes targets marked not-present, then adds targets marked present from saved LU events. Interrupt-driven discovery continues from callbacks; polled discovery waits in init code and calls `disc_check_for_work()`.

State and persistence behavior: mutable discovery state lives in `a->disc_ctx`, `a->disc_buffer`, `a->general_req`, `AF_DISC_*`, `AF2_DEV_SCAN`, `AF2_DEV_CNT_OK`, `disc_wait_*`, and target database entries. It has no disk persistence, but it mirrors firmware-visible topology and controls SCSI target reporting. Deferred SCSI requests are fixed after discovery by rewriting their firmware virtual target IDs or completing them with selection failure if their target disappeared.

Dependencies and integration points: depends on VDA management requests built by `esas2r_build_mgt_req()`, HBA IOCTL requests built by `esas2r_build_ioctl_req()`, request submission in `esas2r_io.c`, completion in `esas2r_int.c`, target database helpers in `esas2r_targdb.c`, async LU events from `esas2r_int.c`, and NVRAM wait policy. It coordinates with reset/flashing by deferring discovery requests while `AF_CHPRST_PENDING` or `AF_FLASHING` is set.

Risks and test signals: scan-generation changes restart portions of discovery, so stale topology and loops are key risks. Deadlock risk exists around polled discovery and ISR-driven starts, which is why work is deferred through flags and locks. Other risks include mis-handled pass-through identifier lengths, missing `VDAAE_LU_PHYS_ID`, target ID changes after hibernate, and completing deferred requests incorrectly. Test signals include initial boot with delayed devices, reset/power-management rediscovery, full scan with invalid groups/partitions/devices, pass-through address failures, LU present/not-present events, timeouts that trigger local reset, and deferred I/O during topology change.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_flash.c

Purpose: owns flash, firmware-image, flash-script IOCTL, and SAS NVRAM operations for the `esas2r` adapter. It validates firmware images, adjusts boot images for the installed PCI device, sequences VDA flash requests, reads flash metadata, and reads/writes cached NVRAM.

Important APIs/types/functions: public functions include `esas2r_process_fs_ioctl()`, `esas2r_read_flash_block()`, `esas2r_read_flash_rev()`, `esas2r_print_flash_rev()`, `esas2r_read_image_type()`, `esas2r_nvram_read_direct()`, `esas2r_nvram_write()`, `esas2r_nvram_validate()`, `esas2r_nvram_set_defaults()`, `esas2r_nvram_get_defaults()`, and `esas2r_fm_api()`. Important internals are checksum helpers, `build_flash_msg()`, `load_image()`, `fix_bios()`, `fix_efi()`, `fw_download_proc()`, `chk_cfg()`, `chk_boot()`, `verify_fi()`, `esas2r_flash_access()`, and NVRAM/FM callbacks.

Control flow: firmware download begins in `esas2r_fm_api()` by taking `AF_FLASH_LOCK`, copying the caller SG context into `a->flash_context`, validating image version/type/action, verifying component headers and checksums, patching BIOS/EFI device IDs, recalculating checksum, disabling heartbeat, and starting a task sequence. `fw_download_proc()` erases the boot region, writes BIOS/MAC/EFI/CFG components if present, reads each component back into a scratch buffer, compares it, marks component status, updates flash/image revision fields, and releases the flash lock. FS IOCTL processing validates adapter type, command, driver version, degraded mode, and SGL needs, then sends one VDA flash command. Direct flash reads acquire firmware flash access via doorbells, map the data window over serial or parallel flash, copy bytes, and release access. NVRAM reads copy flash content into `a->nvram` and validate it; writes validate SAS address/version, update checksum, disable heartbeat, issue BEGINW/WRITE/COMMIT, and re-enable heartbeat in the callback.

State and persistence behavior: persistent state is controller flash and NVRAM. In-memory state includes `default_sas_nvram`, `a->nvram`, `AF_NVR_VALID`, `AF_FLASH_LOCK`, `AF_FLASHING`, flash/image revision strings, `a->flash_context`, semaphores/mutexes, and request callback fields. Invalid NVRAM falls back to defaults with a fabricated SAS address based on time, bus, and devfn; this default is cached but not automatically persisted unless a write is requested.

Dependencies and integration points: depends on VDA flash request builders, SG builders, request submission/completion, heartbeat/reset flags, PCI IDs and subsystem IDs from `esas2r.h`, doorbell registers, memory-window mapping in `esas2r_main.c`, and sysfs/IOCTL callers that pass firmware or flash-script buffers. It must coordinate with normal I/O because flash commit sets `AF_FLASHING` and deferred processing stops most requests.

Risks and test signals: flash writes are high-risk because failures can affect boot images and controller configuration. Important risks are unchecked image length/offset arithmetic, endian mistakes in ROM headers, checksum updates after device-specific patching, timeout while holding flash access, heartbeat imbalance, concurrency around `AF_FLASH_LOCK`, and NVRAM checksum/SAS-address validation. Test signals include valid and invalid firmware image downloads, component omission, read-back compare failure, degraded-mode rejection, FS read/write/commit/cancel commands, flash-access timeout, serial versus parallel flash paths, NVRAM invalid signature/checksum/version fallback, and write callback sequencing through BEGINW/WRITE/COMMIT.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_init.c

Purpose: implements adapter allocation, PCI/DMA setup, firmware communication-list initialization, interrupt claiming, hardware initialization, power management, chip reset, and teardown for the `esas2r` driver.

Important APIs/types/functions: public functions include `esas2r_init_adapter()`, `esas2r_kill_adapter()`, `esas2r_set_degraded_mode()`, `esas2r_get_uncached_size()`, `esas2r_init_adapter_struct()`, `esas2r_check_adapter()`, `esas2r_init_msgs()`, `esas2r_init_adapter_hw()`, `esas2r_reset_adapter()`, `esas2r_reset_chip()`, `esas2r_power_down()`, `esas2r_power_up()`, `esas2r_is_adapter_present()`, `esas2r_get_model_name()`, and `esas2r_get_model_name_short()`. Internal helpers allocate/free aligned coherent memory, allocate VDA request buffers, map BARs, select interrupt mode, claim IRQs, initialize PCIe config space, format CFG init messages, and notify firmware of power-down.

Control flow: `esas2r_init_adapter()` validates the adapter index, initializes the adapter struct in `host->hostdata`, sets DMA mask, creates locks/wait queues/workqueue/lists, allocates VDA requests, maps PCI regions, sets reset/discovery/first-init flags, selects legacy SGE defaults, configures interrupts, allocates uncached coherent memory, partitions it via `esas2r_init_adapter_struct()`, initializes the tasklet, disables chip interrupts, checks firmware readiness, initializes hardware, claims IRQ, enables interrupts, marks init done, and starts the timer when not degraded. `esas2r_check_adapter()` forces a firmware interrupt to discover firmware API version, configures inbound/outbound list DMA addresses and ring registers, resets pointers/toggle state, and enables outbound queue/doorbell interrupt sources. `esas2r_init_adapter_hw()` reads NVRAM, sends CFG init/get-init messages, posts AE requests, reads flash metadata, runs discovery, reports target changes, and enables heartbeat. Teardown reverses sysfs, IRQ/MSI, DMA, workqueue, PCI, and SCSI host resources.

State and persistence behavior: adapter state is anchored in `esas2r_adapters[]` and `struct esas2r_adapter`. Hardware state includes BAR mappings, PCI config, DMA masks, message-unit registers, communication-list pointers, interrupt mode, and doorbell capabilities. Persistent data is not directly authored except through NVRAM/flash helpers, but init reads and caches NVRAM, firmware revision, flash revision, and boot image type. Power down stores `prev_dev_cnt`, removes target state, sets reset/discovery flags, and allows power up to rediscover.

Dependencies and integration points: integrates with PCI core, DMA coherent allocation, SCSI host lifecycle, Linux IRQ/MSI, tasklets, timers, workqueues, sysfs binary attributes, VDA CFG request builders, flash/NVRAM code, discovery, target database, and interrupt/I/O modules. It also depends on hardware register constants and adapter PCI/subsystem IDs in `esas2r.h`.

Risks and test signals: resource lifetime and error unwinding are the main risks. DMA alignment bookkeeping must free the original allocation, request handles must be unique and table-backed, IRQ enable/disable counts must balance, and reset/power paths must not race with tasklets or timers. Hardware risks include firmware API mismatch, communication-list init timeout, BAR mapping failure, MSI fallback, coredump preservation, and repeated reset disabling the adapter. Test signals include probe failure at each allocation/mapping stage, 32-bit and 64-bit DMA masks, legacy versus MSI interrupts, firmware ready timeout, CFG init failure, first-init polled discovery, suspend/resume, remove during active I/O, chip panic/reset recovery, and model-name mapping by subsystem device.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_int.c

Purpose: handles adapter interrupts, outbound response completion, deferred queue processing, chip/bus reset tasklet work, async firmware events, SCSI sense copying, and final request completion dispatch.

Important APIs/types/functions: public entry points are `esas2r_polled_interrupt()`, `esas2r_interrupt()`, `esas2r_adapter_interrupt()`, `esas2r_msi_interrupt()`, `esas2r_do_deferred_processes()`, `esas2r_process_adapter_reset()`, `esas2r_do_tasklet_tasks()`, `esas2r_force_interrupt()`, `esas2r_ae_complete()`, `esas2r_send_reset_ae()`, `esas2r_dummy_complete()`, and `esas2r_complete_request()`. Internal helpers include `esas2r_get_outbound_responses()`, `esas2r_handle_outbound_rsp_err()`, `esas2r_process_bus_reset()`, chip-reset tasklet helpers, `esas2r_doorbell_interrupt()`, `esas2r_lun_event()`, and `esas2r_check_req_rsp_sense()`.

Control flow: legacy interrupts first test and mask pending causes, set `AF2_INT_PENDING`, and schedule a tasklet; MSI handles causes directly and then runs tasklet tasks. Polled mode disables interrupts, reads causes, drains outbound responses, handles doorbells, re-enables interrupts, and runs deferred work. Response draining reads the firmware write pointer, walks outbound entries from `last_read`, validates handles against `req_table`, removes active requests, copies status/function response data, queues completions, updates `last_read`, and drains completion callbacks outside the queue lock. Deferred processing decides whether normal, discovery-only, or no requests can start based on reset/flashing/discovery flags, then starts eligible deferred requests or completes already-failed ones. Tasklet work handles chip resets, bus resets, and port-change reporting. AE completion parses packed event lists, queues user-visible firmware events, updates LU target states, and reposts the AE request.

State and persistence behavior: runtime state includes interrupt masks/status, outbound ring pointers, active/deferred/completion lists, request statuses, reset/discovery/flashing flags, heartbeat flags, target pending states, firmware event work items, and sense buffers. No disk persistence is performed. Reset handling deliberately aborts or completes in-flight requests, resets ring pointers and toggles, removes target database entries, and may mark the adapter degraded/disabled after repeated failures.

Dependencies and integration points: depends on MMIO register helpers, request rings from init, request start functions in `esas2r_io.c`, discovery and target database code, firmware event queueing in `esas2r_main.c`, SCSI midlayer bus reset notification, VDA async-event endian conversion, and SCSI status/sense constants. It is the central bridge between firmware responses and higher-level completion callbacks.

Risks and test signals: high-risk areas are interrupt masking races, shared versus MSI behavior differences, stale or invalid firmware handles, response ring pointer corruption, request callback re-entry when `req_stat` returns to `RS_PENDING`, and reset interactions with active/deferred queues. AE parsing must reject invalid lengths before walking the buffer. Test signals include legacy shared IRQ returning `IRQ_NONE`, MSI retrigger workaround, outbound no-op and wraparound cases, invalid handle/reset trigger, SCSI error with good status normalization, sense copy and Report LUNs changed detection, AE event length validation, LU present/lost events, firmware panic/reset doorbells, bus reset during flashing, and repeated chip reset disable behavior.

# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_io.c

Purpose: implements request submission to the firmware communication rings, scatter/gather list construction for both legacy SGE and newer PRD firmware APIs, timer-driven heartbeat/reset/discovery maintenance, task-management request submission, bus reset scheduling, and I/O abort marking.

Important APIs/types/functions: public functions are `esas2r_start_request()`, `esas2r_local_start_request()`, `esas2r_start_vda_request()`, `esas2r_build_sg_list_sge()`, `esas2r_build_sg_list_prd()`, `esas2r_timer_tick()`, `esas2r_send_task_mgmt()`, `esas2r_reset_bus()`, and `esas2r_ioreq_aborted()`. Internal helpers are `esas2r_build_prd_iblk()` and `esas2r_handle_pending_reset()`.

Control flow: `esas2r_start_request()` validates adapter mode, power-down state, target presence, and firmware virtual target ID before either completing immediately or enqueueing/starting the request. If reset, flashing, discovery, or existing deferred work blocks the request, it is added to `defer_list`; otherwise `esas2r_local_start_request()` adds it to `active_list` and calls `esas2r_start_vda_request()`. Starting a VDA request advances the inbound-list write pointer with toggle handling, writes the request DMA address and size into the inbound source entry, and updates the hardware write register. Legacy SGE building emits 64-bit VDA SGEs, splits large segments, allocates chained SGL pages, and marks the final entry. PRD building groups SCSI read/write payloads by RAID interleave/I-block boundaries for non-pass-through RAID targets, builds PRD chains per I-block, and sizes the request accordingly. Timer ticks age chip uptime, poll pending chip reset readiness, drive discovery completion, and run heartbeat force-interrupt checks. Task management aborts eligible deferred commands, formats a SCSI task-management request, and either starts it or reports busy during flashing.

State and persistence behavior: state is volatile: request status/list membership, `active_list`, `defer_list`, inbound-list `last_write`, communication toggle bit, SGL page ownership, target virtual IDs, chip uptime/reset timestamps, heartbeat state, and reset flags. It does not persist data, but it enforces ordering around flash and discovery so firmware-visible persistent operations do not race ordinary I/O.

Dependencies and integration points: depends on adapter/request/SG context definitions in `esas2r.h`, VDA SGE/PRD flags from `atvda.h`, target database fields, SCSI CDB opcodes, firmware API mode selected by init, interrupt completion in `esas2r_int.c`, discovery completion in `esas2r_disc.c`, and request builders in `esas2r_vda.c`. It is the low-level producer side of the firmware inbound ring consumed by interrupt completion.

Risks and test signals: risks include inbound ring overflow assumptions, toggle-bit errors, DMA address truncation in legacy SGE paths, SGL exhaustion resume behavior, PRD chain count/length mistakes, I-block math with unusual block/interleave sizes, request deferral starvation during discovery/flash, and heartbeat-triggered reset races. Test signals include zero-length commands, invalid/missing targets, deferred queue draining after reset/discovery, flash commit blocking normal starts, inbound pointer wrap, large SG entries split at `SGE_LEN_MAX`/`PRD_LEN_MAX`, chained SGL allocation failure, READ/WRITE 6/10/12/16 PRD I-block partitioning, heartbeat failure recovery, task management for LUN and target resets, and bus reset suppression while degraded or discovery-pending.
