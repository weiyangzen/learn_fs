# sources/distributed-fs/lustre-release/lnet/utils/lnetconfig/liblnetconfig_netlink.c

Purpose: implements the liblnetconfig bridge between libyaml documents and Lustre LNet generic netlink messages. It lets callers read kernel LNet replies as YAML and write YAML requests as netlink operations, while keeping kernel code free of YAML formatting. The file also centralizes netlink socket setup, multicast group subscription, extended ACK handling, parser/emitter cleanup, and richer YAML error logging.

Important APIs/types/functions: `yaml_parser_set_input_netlink()` is the public parser setup entry point; it registers the netlink socket, allocates the receive buffer, and installs libnl callbacks. `yaml_emitter_set_output_netlink()` and `yaml_emitter_set_streaming_output_netlink()` are the public output entry points; they resolve the generic netlink family and attach a custom YAML writer. `yaml_netlink_setup_emitter()` and `yaml_netlink_complete_emitter()` are used by streaming import paths to start/finish one netlink-backed YAML document per command. `yaml_parser_get_reader_error()` and `yaml_parser_get_reader_proto_version()` expose netlink-side failure details and protocol version. `yaml_emitter_cleanup()` and `yaml_parser_cleanup()` must be used instead of raw libyaml delete calls when these adapters are installed.

Key internal types are `struct yaml_netlink_input`, which tracks parser state, input buffer pointers, socket, protocol version, async mode, completion state, and the current key-table tree; `struct yaml_nl_node`, which stores a netlink/YAML key table node and child collection; and `struct yaml_netlink_output`, which stores emitter state, netlink socket/control socket, family id, command, version, flags, and local port. The key-table metadata is represented through `struct ln_key_list` and `struct ln_key_props` from the LNet netlink ABI.

Control flow: the read side starts in `yaml_parser_set_input_netlink()`, which calls `lustre_netlink_register()` to connect generic netlink, enable broadcast errors, enable extended ACK where supported, and disable sequence/auto-ACK behavior for async streams. Libyaml then calls `yaml_netlink_read_handler()` whenever it needs bytes. That handler receives netlink messages through `nl_recvmsgs_report()`, whose `NL_CB_VALID`, `NL_CB_FINISH`, and error callbacks are bound to `yaml_netlink_msg_parse()`, `yaml_netlink_msg_complete()`, and `yaml_netlink_msg_error()`. Messages with `NLM_F_CREATE` carry a nested key table and are parsed by `yaml_parse_key_list()` into the local `yaml_nl_node` tree. Data messages are parsed against the cached key table, converted by `yaml_parse_value_list()` into textual YAML, and copied from the adapter buffer into libyaml's buffer. Completion frees the key tree and, for async mode, appends YAML document markers so multiplexed event streams remain parseable.

The write side starts when libyaml emits bytes into `yaml_netlink_write_handler()`. The handler duplicates the output buffer, normalizes quotes with `yaml_quotation_handling()`, treats top-level YAML keys as netlink multicast groups via `lustre_netlink_add_group()`, creates a generic netlink message, and translates mappings/sequences/scalars into nested `LN_SCALAR_ATTR_LIST` attributes. `yaml_format_type()` classifies block, flow, sequence, and mapping syntax using indentation and delimiters. `yaml_create_nested_list()` recursively builds nested attributes, and `yaml_fill_scalar_data()` encodes key strings or numeric/bool values into scalar netlink attributes. At the end, either a full message is sent with `nl_send_auto()` or an empty/simple command is sent with `genl_send_simple()`.

State and persistence behavior: no durable state is written. Runtime state is held in parser/emitter handler data, the receive buffer, cached key-table tree, libnl socket callbacks, and optional multicast membership. Kernel-side state changes happen only through emitted netlink commands. The input buffer starts at 64 KiB and is doubled when less than 1 KiB remains. The cached key table is replaced when a create message arrives with `NLM_F_REPLACE`, and it is freed at message completion.

Dependencies/integration points: depends on libyaml, libnl generic netlink, Linux netlink options `NETLINK_BROADCAST_ERROR` and `NETLINK_EXT_ACK`, and Lustre headers such as `linux/lnet/lnet-nl.h` and `liblnetconfig.h`. It is consumed by `lnetctl.c` netlink-backed command paths and any liblnetconfig caller that wants YAML import/export over netlink. It integrates with the LNet generic netlink family (`LNET_GENL_NAME`, `LNET_GENL_VERSION`) and commands such as routes, nets, peers, ping, recovery, and CPT-of-NID.

Risks: YAML string generation is pointer-arithmetic heavy and must maintain correct buffer accounting; the `yaml_parse_value_list()` branch that advances `*size` after output appears suspicious because most other branches subtract consumed size. Flow-style parsing uses destructive string edits and `strsep()`, so malformed flow YAML can mis-nest data or produce generic writer errors. `yaml_quotation_handling()` assumes paired quotes and can dereference a missing closing quote if input is malformed. Extended ACK messages obtained with `nla_strdup()` can replace static libnl error strings and need careful ownership expectations. Consumers must use the custom cleanup functions or the handler data leaks. Async streams intentionally disable sequence checking, which is required for events but weaker for strict request/response validation.

Test signals: parser tests should feed synthetic key-table and value netlink messages for mappings, sequences, empty nested lists, flow mappings/sequences, flags, numeric types, null-string key updates, and key-table replacement. Emitter tests should round-trip representative LNet YAML into expected scalar/nested netlink attributes and verify group subscription failures, missing top-level groups, malformed flow syntax, quoted strings, bool/numeric coercion, and empty/simple commands. Error-path tests should cover kernel extended ACK text, normal netlink errors, `-NLE_INTR`, unsupported `NETLINK_EXT_ACK`, buffer growth, async start/end document markers, and cleanup after parser/emitter initialization failures.

# sources/distributed-fs/lustre-release/lnet/utils/lnetconfig/liblnetconfig_udsp.c

Purpose: implements liblnetconfig support for LNet UDSPs, user-defined selection policies. It parses user NID/net criteria, marshals UDSP rules into the ioctl ABI used by the kernel, demarshals kernel replies back into userspace structures, and presents show output as cYAML.

Important APIs/types/functions: exported entry points are `lustre_lnet_add_udsp()`, `lustre_lnet_del_udsp()`, and `lustre_lnet_show_udsp()`. `lnet_udsp_alloc()` initializes a `struct lnet_udsp` and all embedded list heads. `lnet_udsp_free()` and `lnet_udsp_nid_descr_free()` release parsed criteria, with separate handling for normal parsed lists versus single bulk allocations created during demarshal. `lnet_get_udsp_size()`, `lnet_size_marshaled_nid_descr()`, `lnet_udsp_marshal()`, and `copy_nid_range()` calculate and write the ioctl bulk layout. `lnet_udsp_demarshal()`, `copy_ioc_udsp_descr()`, and `copy_range_info()` read the kernel bulk layout into ordinary `cfs_expr_list` and `cfs_range_expr` lists. `lustre_lnet_nid_descr2str()` converts a UDSP criterion back to `addr@net[num]` style strings for display. `yaml_add_udsp_action()` adds the action subtree, currently priority.

Control flow: adding a rule starts in `lustre_lnet_add_udsp()`. It validates action type (`priority` or preferred-list alias), requires at least one of src/dst/rte, rejects unsupported src+rte and src+dst+rte combinations, allocates a UDSP, parses each provided criterion through `cfs_parse_nid_parts()`, applies the priority/default-action rules, computes the exact ioctl buffer size, marshals the rule into a contiguous `struct lnet_ioctl_udsp` plus descriptor bulk, and sends `IOC_LIBCFS_ADD_UDSP` to `LNET_DEV_ID`. Deleting initializes `struct lnet_ioctl_udsp`, stores the requested index, and sends `IOC_LIBCFS_DEL_UDSP`.

Showing rules iterates index-by-index unless a specific index was requested. For each rule it first issues `IOC_LIBCFS_GET_UDSP_SIZE`, allocates the returned size, then issues `IOC_LIBCFS_GET_UDSP`. The returned bulk is demarshaled into a temporary `struct lnet_udsp`, converted into a cYAML sequence item with `idx`, optional `src`, `dst`, `rte`, and `action`, and then freed. Iteration stops when the size ioctl reports `ENOENT`; other errors are reported through cYAML.

State and persistence behavior: this file does not persist anything itself. UDSP state lives in the kernel and is modified through ioctls. Userspace state is short-lived: parsed criteria lists, a transient contiguous ioctl buffer, demarshaled display structures, and cYAML output trees. Marshal size calculations are deterministic and based on expression/range list lengths. Demarshal allocates one contiguous userspace block per NID descriptor and links list nodes into it, so the free path must know whether it is freeing parsed lists or a bulk-demarshal allocation.

Dependencies/integration points: depends on Lustre libcfs ioctl helpers, `linux/lnet/lnetctl.h`, `linux/lnet/lnet-dlc.h`, NID expression parsing (`cfs_parse_nid_parts()`, `cfs_expr_list_*`, `cfs_expr2str()`), network-name helpers (`libcfs_net2str()`, `LNET_MKNET()`), cYAML builders, and the LNet kernel ioctl commands `IOC_LIBCFS_ADD_UDSP`, `IOC_LIBCFS_DEL_UDSP`, `IOC_LIBCFS_GET_UDSP_SIZE`, and `IOC_LIBCFS_GET_UDSP`. `lnetctl.c` calls these functions for direct UDSP CLI operations and YAML import/export handling.

Risks: the marshaled layout is manually maintained with pointer increments, explicit sizes, and repeated `bulk_size` decrements; ABI drift between userspace and kernel structs can corrupt parsing. The descriptor type check compares the first four bytes of string literals such as `"SRC"` through `*(__u32 *)type`, which is compact but endian/alignment-sensitive. Demarshal free behavior depends on `net_range->next` or `ud_addr_range.next` pointing to the base of the contiguous allocation. `lustre_lnet_del_udsp()` builds its cYAML error under `ADD_CMD`, which may be a reporting bug for delete failures. `yaml_add_udsp_action()` lacks an explicit `break` after priority but intentionally falls through to default return; new action types could be lost if this is extended carelessly.

Test signals: add tests should cover missing criteria, unsupported criterion combinations, bad action strings, priority defaults for single-ended src/dst rules, explicit insertion index, and parse failures for src/dst/rte. Marshal/demarshal tests should cover empty criteria, net-only criteria, address-only and address+net-range expressions, multiple address expression dimensions, undersized buffers, descriptor type mismatch, and exact size accounting. Show tests should simulate multiple rules, a single index, `ENOENT` termination, non-ENOENT ioctl failures, cYAML tree merging into an existing result, and buffer-too-small output from `lustre_lnet_nid_descr2str()`.

# sources/distributed-fs/lustre-release/lnet/utils/lnetctl.c

Purpose: implements the `lnetctl` command-line utility for configuring, querying, importing, exporting, debugging, and fault-testing Lustre LNet. It maps top-level commands and subcommands to either newer generic-netlink YAML paths or older liblnetconfig ioctl/cYAML APIs when netlink is unsupported.

Important APIs/types/functions: `main()` initializes liblnetconfig with `lustre_lnet_config_lib_init()` and dispatches through `cfs_parser()` using `cmd_list`. Command tables define the CLI surface for `lnet`, `route`, `net`, `routing`, `set`, `import`, `export`, `stats`, `debug`, `global`, `peer`, `ping`, `discover`, `service-id`, `udsp`, `fault`, `setup-mrrouting`, `setup-sysctl`, and `cpt-of-nid`. `check_cmd()` provides common help/minimum-argument handling, and `parse_long()` provides simple integer parsing.

Core netlink builders include `yaml_lnet_route()`, `yaml_lnet_config_ni()`, `yaml_lnet_peer()`, `yaml_lnet_ping()`, `yaml_debug_recovery()`, and `yaml_lnet_cpt_of_nid()`. These allocate a libnl socket, set up a netlink-backed YAML parser for replies, create a netlink-backed YAML emitter for a specific LNet command, emit a YAML request document, close the emitter, parse/display the reply, and fall back to old APIs if setup reports `-EOPNOTSUPP`. Import/export support is centered around `jt_import()`, `jt_export()`, `complete_and_setup_emitter()`, `find_command_mapping()`, `handle_net_config_sequence()`, `handle_udsp_sequences()`, `handle_global_parameter()`, and the tunable/list parsers. Fault injection support uses `yaml_lnet_fault_rule()` through `jt_fault_add()`, `jt_fault_del_common()`, `jt_fault_reset_common()`, and `jt_fault_show_common()`.

Control flow: command dispatch is table driven. Top-level wrappers such as `jt_net()`, `jt_route()`, `jt_peers()`, `jt_fault()`, and `jt_set()` validate and then recurse into a subcommand table. Setter commands parse a single numeric value and call matching `lustre_lnet_config_*` functions. Route commands parse net/gateway/hop/priority, build a route YAML document for netlink, and fall back to `lustre_lnet_config_route()`, `lustre_lnet_del_route()`, or `lustre_lnet_show_route()`. Network commands parse interface/NID/ip2net/CPT/tunable options into `struct lnet_dlc_network_descr`, `struct lnet_ioctl_config_lnd_tunables`, and `cfs_expr_list`, emit netlink YAML, and then optionally run multi-rail Linux route setup. Peer commands parse primary NID, peer NID ranges, Multi-Rail flags, health/state fields, and list/show verbosity, then emit peer YAML or call old peer APIs. Ping and discover expand NID ranges into YAML flow sequences and display kernel replies with enhanced errno descriptions.

Import control flow is the most complex. `jt_import()` reads YAML from a file or stdin, chooses add/delete/show/exec mode, and by default streams the YAML through netlink. It scans scalar events to detect top-level blocks mapped by `cmd_mappings`, starts a command-specific streaming emitter, forwards events into it, and completes the emitter when switching operations. It special-cases `udsp`, `ip2nets`, `net`, `CPT`, and `global` because those need local parsing or old APIs. `handle_net_config_sequence()` parses each net/ip2nets sequence item, enforces first-key expectations (`net type` or `net-spec`), parses interfaces, IP ranges, common tunables, LND tunables, and CPT expressions, resolves ip2nets rules, skips duplicate ip2nets networks, and calls `yaml_lnet_config_ni()` for each resolved network. `--old-api` reads the whole file into memory and calls legacy YAML config/delete/show/exec functions.

Export control flow writes current configuration to stdout or a file. It first tries netlink dumps for nets, routes, and peers, then falls back to old show APIs where needed. It always appends routing, global settings, and UDSP show data through cYAML. Backup mode sets `NLM_F_DUMP_FILTERED` and requests less verbose data needed for reconfiguration.

State and persistence behavior: `lnetctl` keeps no daemon state. It mutates persistent runtime LNet kernel state through netlink and ioctl calls, including LNet configured/unconfigured status, routes, local NIs, peers, UDSP rules, global tunables, routing buffer settings, recovery settings, and fault-injection rules. Import reads YAML files or stdin; export writes YAML to stdout or a user-specified file. In-memory state includes cYAML result trees, libyaml parser/emitter objects, libnl sockets, parsed network/interface lists, NID range expansion lists, CPT expression lists, and transient tunables. Resource cleanup is mostly explicit through `cYAML_free_tree()`, `yaml_parser_cleanup()`, `yaml_emitter_cleanup()`, `yaml_document_delete()`, `nl_socket_free()`, `lustre_lnet_free_list()`, and `cfs_expr_list_free()`.

Dependencies/integration points: depends on libc getopt, libyaml, libnl through the netlink adapter, libcfs parser/ioctl utilities, cYAML, `liblnetconfig.h`, LNet DLC structs, LND-specific tunables, and optional KFILND support. It is the main user-facing integration point for the liblnetconfig library functions implemented across the `lnet/utils/lnetconfig` directory. It integrates with the kernel generic netlink LNet family and legacy LNet ioctls, plus host networking setup helpers `lustre_lnet_setup_mrrouting()` and `lustre_lnet_setup_sysctl()`.

Risks: many command handlers silently ignore unparsable numeric options by resetting to sentinel values, which can hide user mistakes. Several paths use global getopt state and must reset `optind` correctly. Netlink and old-API fallback behavior can produce different output shapes or partial effects if a command succeeds in one path and later setup fails. Import uses event streaming and top-level scalar detection, so malformed YAML or unexpected key ordering can route a block to the wrong handler. `handle_udsp_sequences()` chooses the add action string from `prio ? "priority" : ""`, so priority `0` may be treated as no action despite being documented as highest priority. `fault_attr_ptl_parse()` accepts a `ptl_str` parameter but parses global `optarg`, coupling it to getopt state. In `jt_fault_del_common()`, the `case 'a'` branch lacks a `break` and falls through to the destination handling branch, which is risky for `--all`. File import old-API mode sizes stdin with `fstat()` and assumes a useful `st_size`, which is fragile for pipes. The code contains many manual cleanup branches, so initialization failures need leak testing.

Test signals: CLI tests should cover help/min-argument behavior for every command table, invalid options, parse failures, and sentinel/default behavior. Netlink tests should mock unsupported netlink and verify fallback to old APIs for configure, route, net, peer, ping/discover, recovery, and export. YAML import tests should cover add/delete/show/exec modes, command switching, global parameters, net and ip2nets blocks, duplicate ip2nets networks, tunables, LND tunables, CPT scalar and sequence formats, UDSP blocks, and malformed event sequences. Export tests should cover normal and backup output, file output, partial netlink fallback, and cYAML tree cleanup. Functional integration tests should exercise route add/del/show, NI add/del/show/set with NID/interface/ip2net/CPT/tunables, peer add/del/show/list/set, UDSP add/del/show, ping/discover with NID ranges and source NID, fault drop/delay add/del/reset/show validation, and global show/set round-trips.
