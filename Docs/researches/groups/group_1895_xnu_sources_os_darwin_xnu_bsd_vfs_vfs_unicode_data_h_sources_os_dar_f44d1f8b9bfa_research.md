# File Research: sources/os/darwin/xnu/bsd/vfs/vfs_unicode_data.h

## Purpose

`vfs_unicode_data.h` is a generated Unicode normalization, validation, combining-class, and case-folding data header used by Darwin/XNU VFS Unicode support. It contains no executable functions. Instead, it defines constants and static lookup tables consumed by `vfs_unicode.c`, especially the `normalizeCaseFoldU32Code` path referenced in the file comments.

The data supports mapping one Unicode scalar to one of several outcomes: invalid/unassigned/noncharacter, NFD-normalized sequence, case-folded form, nonzero combining class, algorithmic Hangul handling marker, or no special handling.

## Trie Design

The header documents and implements a three-stage trie over a reduced lookup-codepoint space:

- `nfTrieHi[806]`: high-stage lookup for bits 8 and above.
- `nfTrieMid[153][16]`: middle-stage lookup for bits 4-7 when a high entry points to another stage.
- `nfTrieLo[448][16]`: low-stage lookup for bits 0-3 when a middle entry points to another stage.

The trie compresses Unicode space by treating common ranges directly and by shifting `E0000-E01FF` down into a compact lookup range following `0000-323FF`. Ranges above that are partly handled by code rather than table lookup.

## Encoded Value Model

The enum defines the trie value tags and masks:

- `kInvalidCodeFlag`: marks invalid, unassigned, surrogate, or noncharacter code points.
- `kHangulMask`: marks composed Hangul syllables that use algorithmic decomposition.
- `kCombClassFlag`: stores a nonzero combining class in the low byte.
- `kInvMaskFlag`: points to invalid-code bitmasks for 16-codepoint runs.
- `kToU16Seq2Mask`, `kToU16Seq3Mask`, `kToU16SeqMiscMask`: point to BMP decomposition/folding sequence tables.
- `kToU32CharMask`, `kToU32SeqMiscMask`: point to non-BMP mapping tables.
- `kToSeqCaseFoldMask`: marks sequence mappings relevant to case folding.
- `kSimpleCaseFoldLimit`: bounds the direct simple case-fold table.

The special value space deliberately uses parts of `AC00-F8FF` because the comments assert those ranges are not produced by decomposition/folding and do not need non-algorithmic normalization metadata.

## Generated Tables

The generated data block contains:

- `nfU16InvMasks[139]`: bitmasks for mid-stage ranges where only selected code points are invalid.
- `nfU16Seq2[773][2]`: two-BMP-codepoint decomposition or folding sequences.
- `nfU16Seq3[222][3]`: three-BMP-codepoint sequences.
- `nfU16SeqMisc[198]`: variable BMP sequences up to length 4, with length and first-character combining class encoded in the prefix word.
- `nfU32Char[954]`: single non-BMP result code points, including simple folds and compatibility mappings.
- `nfU32SeqMisc[151]`: variable non-BMP sequences up to length 4.
- `nfBasicCF[1280]`: direct simple case-folding table through code point `0x04FF`.

The table-size comments list the generated byte footprint for each table, making this header useful for auditing memory impact as well as normalization coverage.

## Unicode Range Semantics

The leading comment is the main contract for consumers. It states that:

- ASCII is normally not trie-looked-up because it has no decomposition and combining class zero, though some ASCII-range values are represented in simple folding.
- Hangul syllables `AC00-D7A3` are decomposed algorithmically rather than by table.
- Surrogates `D800-DFFF` are invalid scalar values.
- Private-use ranges have no decomposition, case folding, or combining class except invalid noncharacter endings.
- Large invalid ranges such as `32400-DFFFF` and `E0200-EFFFF` are expected to be handled by code.

## Filesystem Relevance

This header is part of the VFS filename comparison and normalization substrate. It gives XNU compact, in-kernel Unicode data for case-insensitive and normalization-aware filesystem behavior without depending on user-space Unicode libraries. The split between trie flags, algorithmic Hangul, invalid masks, BMP sequences, non-BMP sequences, and simple case folding is tuned for fast per-codepoint normalization in kernel paths.

## Research Notes

The complete 1311-line header was read. Most of the file is generated data; the durable engineering content is the documented encoding format and the relationship between the trie stages and the mapping tables.

# File Research: sources/os/darwin/xnu/bsd/vfs/vfs_utfconv.c

## Purpose

`vfs_utfconv.c` implements Darwin/XNU VFS UTF-8 and UTF-16 conversion helpers, strict UTF-8 validation, UTF-8 normalization to NFC/NFD, Unicode 3.2 decomposition/precomposition support derived from Core Foundation data, Hangul algorithmic decomposition/composition, canonical combining-character ordering, and Services for Macintosh private-use conversions for NTFS/SMB/MSDOS-style filenames.

It is a filename-oriented conversion layer. The code handles slash/null substitutions, endian flags, surrogate pairs, illegal UTF-8 escaping, and filesystem interoperability quirks rather than being a general-purpose Unicode library.

## Public Conversion APIs

- `utf8_encodelen()`: computes the UTF-8 byte length for a UTF-16 input string, optionally replacing slash, alternate-null, endian-swapping, and decomposing precomposed characters.
- `utf8_encodestr()`: encodes UTF-16 to UTF-8, supports optional NFD output, optional null termination, slash substitution, alternate null mapping to `U+2400`, surrogate-pair encoding, and SFM private-use decoding.
- `utf8_decodestr()`: decodes UTF-8 to UTF-16, supports NFD or NFC behavior, illegal-sequence percent escaping, endian swapping, slash restoration, alternate null restoration, canonical sorting of combining sequences, and SFM private-use encoding.
- `utf8_validatestr()`: validates UTF-8 byte sequences without producing output.
- `utf8_normalizestr()`: normalizes UTF-8 to either NFD or NFC by fast-copying all-ASCII input and falling back to decode/re-encode for non-ASCII input.

## UTF-8 Validation Rules

The decoder and validator enforce shortest-form UTF-8:

- 1-byte ASCII is accepted directly.
- 2-byte sequences must decode to at least `0x80`.
- 3-byte sequences must decode to at least `0x800`.
- Surrogate scalar values are rejected.
- `0xFFFE` and `0xFFFF` are rejected.
- 4-byte sequences are decoded into UTF-16 surrogate pairs and checked for valid high/low surrogate ranges.
- Invalid lead bytes or malformed continuation bytes produce `EINVAL`, unless decoding with `UTF_ESCAPE_ILLEGAL`, in which case illegal bytes are emitted as `%HH`.

The `utf_extrabytes[32]` table drives byte-count classification from the high bits of the first byte.

## Normalization And Combining Behavior

The file includes `vfs_utfconvdata.h` and uses Core Foundation-style tables for Unicode 3.2 decomposition/precomposition:

- `unicode_combinable()` checks combining characters, including Hangul Jamo.
- `unicode_decomposeable()` checks whether a BMP character has a decomposition.
- `get_combining_class()` returns combining class values.
- `unicode_recursive_decompose()` recursively resolves table-based decompositions.
- `unicode_decompose()` adds algorithmic Hangul syllable decomposition.
- `unicode_combine()` supports NFC-style recomposition, including Hangul Jamo composition.
- `prioritysort()` canonicalizes runs of combining characters by combining class.

`push()` centralizes writing UTF-16 output while tracking combining-character runs and sorting them when the run ends.

## Hangul Handling

The code defines the standard Hangul constants:

- `HANGUL_SBASE`, `HANGUL_LBASE`, `HANGUL_VBASE`, `HANGUL_TBASE`
- `HANGUL_SCOUNT`, `HANGUL_LCOUNT`, `HANGUL_VCOUNT`, `HANGUL_TCOUNT`, `HANGUL_NCOUNT`

Hangul syllables are decomposed into leading consonant, vowel, and optional trailing consonant Jamo. NFC recomposition handles both two-character `L + V` and three-character `LV + T` sequences.

## SFM Filename Mappings

The bottom of the file implements Services for Macintosh mappings for illegal NTFS filename characters:

- Control characters `0x01-0x1f` map to `0xf001-0xf01f`.
- Characters such as `"`, `*`, `/`, `<`, `>`, `?`, `\`, and `|` map into private-use values.
- Trailing space and trailing period map to `0xf028` and `0xf029`.
- Darwin treats slash/colon historically: the table maps SFM slash behavior through the Mac filename colon convention.

`ucs_to_sfm()` encodes problematic ASCII into private-use Unicode for SFM-compatible backends. `sfm_to_ucs()` decodes private-use SFM values back to Mac/Darwin filename characters.

## Buffer And Error Behavior

The conversion functions carefully report output lengths excluding terminators, while optionally appending a null terminator. Common errors are:

- `ENAMETOOLONG` when the destination buffer cannot fit the converted output.
- `EINVAL` when input contains illegal Unicode or illegal UTF-8 and escaping is not enabled.

`utf8_normalizestr()` rejects invalid flag combinations, rejects in-place normalization by contract, caps non-ASCII input processing at `MAXPATHLEN`, uses a small stack UTF-16 buffer for short names, and allocates with `kalloc_data()` for larger names.

## Filesystem Relevance

This file is a core Darwin VFS filename interoperability utility. It bridges UTF-16 disk or protocol names and UTF-8 kernel/user-facing names while preserving historical HFS Plus decomposition behavior, network filesystem precomposition needs, strict UTF-8 validation for extended attribute names, and Windows/SFM filename character compatibility.
