# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/rx.c

Purpose: Implements the PCIe receive path and interrupt receive-side handling for Intel `iwlwifi` gen1/gen2 transport. It owns receive-buffer descriptor lifecycle, page allocation/reuse, RX DMA setup for legacy single-queue and RFH multi-queue hardware, NAPI polling, firmware response dispatch, command-completion reclaim, ICT interrupt-table support, RF-kill/error interrupt handling, and MSI-X shared-vector receive interrupt routing.

Important APIs, types, and functions: The core state is `struct iwl_rxq`, `struct iwl_rx_mem_buffer`, `struct iwl_rb_allocator`, `struct iwl_trans_pcie`, NAPI state, DMA coherent descriptor tables, and `trans->status` bits. Public transport entry points include `iwl_pcie_rx_stop()`, `iwl_pcie_rxq_alloc_rbs()`, `iwl_pcie_rx_allocator_work()`, `iwl_pcie_rx_init()`, `iwl_pcie_gen2_rx_init()`, `iwl_pcie_rx_free()`, `iwl_pcie_rx_napi_sync()`, `iwl_pcie_irq_rx_msix_handler()`, `iwl_pcie_irq_handler()`, `iwl_pcie_isr()`, `iwl_pcie_msix_isr()`, `iwl_pcie_irq_msix_handler()`, and ICT helpers `iwl_pcie_alloc_ict()`, `iwl_pcie_reset_ict()`, `iwl_pcie_disable_ict()`, `iwl_pcie_free_ict()`. Internal helpers split along hardware generation: `iwl_pcie_rx_hw_init()` programs legacy FH single-queue registers; `iwl_pcie_rx_mq_hw_init()` programs RFH multi-queue descriptors; `iwl_pcie_restock_bd()`, `iwl_pcie_rxmq_restock()`, and `iwl_pcie_rxsq_restock()` publish fresh buffers to firmware. `iwl_pcie_rx_handle()` is the NAPI receive engine, and `iwl_pcie_rx_handle_rb()` parses one receive buffer into one or more `iwl_rx_packet` objects.

Control flow: Initialization starts in `_iwl_pcie_rx_init()`, which allocates queue descriptors if needed, resets allocator counters/lists, frees old pool pages, initializes each RX queue, attaches/enables NAPI, assigns virtual RB IDs into `global_table`, and allocates pages into the default queue. `iwl_pcie_rx_init()` then programs FH/RFH hardware and restocks queue 0; `iwl_pcie_gen2_rx_init()` only initializes software state because gen2 firmware later configures RFH and the alive interrupt triggers restock. On receive interrupt, legacy IRQ handling disables/acknowledges interrupt causes, schedules queue 0 NAPI, and leaves final re-enable to poll completion. MSI-X routes per-RSS queues to `iwl_pcie_irq_rx_msix_handler()` and shared/default vectors to `iwl_pcie_irq_msix_handler()`. The NAPI poll function calls `iwl_pcie_rx_handle()`, which reads the closed read index from shared status, loops until the hardware index or budget is reached, maps used descriptors back to `iwl_rx_mem_buffer` objects, drops unsupported multi-RB fragments, dispatches packets to opmode via `iwl_op_mode_rx()` or `iwl_op_mode_rx_rss()`, completes host commands through `iwl_pcie_hcmd_complete()`, recycles or re-allocates pages, and finally restocks descriptors.

State and persistence behavior: RX state is mostly volatile kernel/PCIe runtime state backed by DMA memory. Descriptor rings (`bd`, `used_bd`, `rb_stts`) are coherent DMA allocations; actual packet pages are DMA-mapped and recycled through `rx_free`, `rx_used`, allocator `rbd_empty`, and allocator `rbd_allocated` lists. `rxb->vid` is the stable firmware-facing virtual buffer ID and indexes `global_table`; `rxb->invalid` prevents stale completion descriptors from reusing an already consumed buffer. Queue pointers (`read`, `write`, `write_actual`) persist across interrupt processing until reset/reinitialization. The background allocator persists pending/ready request counters in atomics and posts work to `rba.alloc_wq`. The ICT table is a coherent 4 KiB interrupt cause ring with `ict_index` and `use_ict` state. Interrupt statistics persist in `trans_pcie->isr_stats` until reset/debugfs clear.

Dependencies and integration points: The file depends on Linux DMA, pages, NAPI, IRQ threading, spinlocks, workqueues, wait queues, and the iwlwifi opmode/transport contracts. Hardware register access goes through CSR, FH, RFH, UMAC PRPH, and HBUS helpers from `iwl-io.h`, `iwl-prph.h`, and local transport internals. RX packet delivery integrates with mac80211-facing opmode callbacks; command responses integrate with the TX command queue and `wait_command_queue`. Error paths call `iwl_trans_fw_error()`, `iwl_force_nmi()`, `iwl_trans_schedule_reset()`, and opmode rfkill/error hooks. Gen2 startup in `trans-gen2.c` relies on `iwl_pcie_gen2_rx_init()` and alive-time restock; non-gen2 startup in `trans.c` relies on `iwl_pcie_rx_init()`.

Risks and edge cases: The code is highly sensitive to descriptor ring arithmetic, power-management races, and device-family register differences. `rxq->lock`, `rba->lock`, `irq_lock`, and NAPI context must be respected because buffers can move among queue, allocator, firmware, and opmode ownership. Page-stealing by opmode is tracked through `rxcb._page_stolen`; incorrect handling would double-free pages or reuse buffers still owned by upper layers. Emergency allocation paths exist when allocator backlog reaches half the queue; mistakes there can leak RBDs or strand them outside allocator accounting. Invalid VIDs force NMI because they indicate firmware or descriptor corruption. Multi-RB fragments are intentionally discarded because upper layers are not prepared for them. Interrupt handlers must avoid device access after APM stop, must re-enable the right interrupt subset depending on firmware-load/RF-kill/alive state, and must handle hardware-gone values without dereferencing invalid device state.

Test signals: Useful validation comes from RX traffic under legacy MSI and MSI-X/RSS modes, firmware boot alive notification with gen2 RFH restock, RF-kill toggles while opmode is up/down, suspend/resume wake interrupts, forced firmware/hardware error interrupts, and high-throughput receive with allocator pressure. Debug signals include `IWL_DEBUG_RX`, `IWL_DEBUG_ISR`, `IWL_DEBUG_TPT`, `isr_stats`, debugfs RX queue counters from `trans.c`, NAPI budget behavior, command response completion wakeups, ICT table index movement, and absence of DMA mapping/unmapping warnings or invalid VID NMIs.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/trans-gen2.c

Purpose: Provides the gen2-specific PCIe transport lifecycle for Intel iwlwifi devices. It starts and stops basic NIC/APM functionality, performs firmware reset handshakes, initializes gen2 RX/TX command queues, handles context-info based firmware boot, configures boot latency workarounds, processes firmware-alive transition, and coordinates opmode leave for newer hardware families.

Important APIs, types, and functions: Exported entry points include `iwl_pcie_gen2_apm_init()`, `iwl_trans_pcie_fw_reset_handshake()`, `iwl_trans_pcie_gen2_stop_device()`, `iwl_trans_pcie_gen2_fw_alive()`, `iwl_trans_pcie_gen2_start_fw()`, and `iwl_trans_pcie_gen2_op_mode_leave()`. Key internal helpers are `iwl_pcie_gen2_apm_stop()`, `_iwl_trans_pcie_fw_reset_handshake()`, `_iwl_trans_pcie_gen2_stop_device()`, `iwl_pcie_gen2_nic_init()`, `iwl_pcie_get_rf_name()`, `iwl_pcie_set_ltr()`, and `iwl_pcie_spin_for_iml()`. The file manipulates `struct iwl_trans`, `struct iwl_trans_pcie`, `fw_reset_state`, `is_down`, `opmode_down`, interrupt masks, RX/TX queues, context-info allocations, and RF-name cache.

Control flow: `iwl_trans_pcie_gen2_start_fw()` is the primary boot path. It locks the transport mutex, prepares/owns the card, enables then disables interrupts to quiesce pending RF-kill handling, checks RF-kill policy, clears firmware handshake bits, initializes the NIC through `iwl_pcie_gen2_nic_init()`, allocates/kicks context information depending on AX210-or-newer versus older context-info format, applies LTR/IML boot workaround, starts ROM/CPU execution, handles optional TOP reset completion/retry, and rechecks RF-kill before returning. `iwl_pcie_gen2_nic_init()` performs APM init, opmode NIC config, software RX init without RFH programming, command queue init through gen2 TX, and shadow register enablement. Firmware-alive flow calls `iwl_pcie_reset_ict()`, clears queue stopped/used bitmaps, frees context-info boot memory while preserving paging, enables interrupts, updates RF-kill, caches RF name, and reads BZ URM state. Stop flow optionally performs a firmware reset handshake if firmware is running, marks the device down, disables interrupts/ICT, synchronizes IRQs and NAPI, frees gen2 TX queues, stops RX DMA, frees context/paging info, stops APM, retakes ownership, reconfigures MSI-X IVAR after reset, clears status bits, and leaves RF-kill interrupt enabled.

State and persistence behavior: This file mainly transitions runtime state rather than storing persistent data. `STATUS_DEVICE_ENABLED`, `STATUS_INT_ENABLED`, `STATUS_SYNC_HCMD_ACTIVE`, `STATUS_TPOWER_PMI`, `STATUS_RFKILL_*`, `is_down`, `opmode_down`, `fw_reset_state`, `do_top_reset`, `request_top_reset`, and `step_urm` are the important state flags. `rf_name` is cached after first construction from `hw_rf_id` and optional CNVI version. Context-info, paging, RX, TX, and ICT allocations are created elsewhere but freed or reset here at firmware/stop boundaries. Firmware reset and TOP reset state is synchronized with wait queues and interrupt handlers in `rx.c`.

Dependencies and integration points: The file relies on common PCIe transport helpers from `trans.c` (`iwl_pcie_prepare_card_hw()`, `iwl_trans_activate_nic()`, `iwl_pcie_apm_config()`, `iwl_pcie_apm_stop_master()`, `iwl_trans_pcie_sw_reset()`, `iwl_pcie_conf_msix_hw()`, `iwl_pcie_check_hw_rf_kill()`, `iwl_trans_pcie_handle_stop_rfkill()`), RX helpers from `rx.c`, and TX helpers from `tx-gen2.c`. It integrates with context-info v1/v2 code, firmware debug timepoints, opmode RF-kill/error callbacks, interrupt reset handling, and device-family specific CSR/UMAC registers. Firmware reset ACKs are delivered by interrupt paths that update `fw_reset_state` and wake `fw_reset_waitq`.

Risks and edge cases: Start and stop run under `trans_pcie->mutex`; violating that would race opmode, RF-kill, interrupt, and firmware-reset paths. The start path has multiple family-specific boot mechanisms: legacy UREG CPU run, AX210 UMAC CPU init, and BZ CSR ROM start. TOP reset retry intentionally loops back through hardware start and context setup; failure to reset state correctly could recursively boot stale context. `iwl_pcie_set_ltr()` returns false for AX210 devices that need the IML polling workaround; missing this can expose boot latency ROM issues. Stop flow accesses hardware only while `STATUS_DEVICE_ENABLED` is valid and must synchronize NAPI/IRQs before freeing queues. RF-kill is re-enabled after stop even though most interrupts are disabled, so masking and IVAR restoration order matters.

Test signals: Exercise firmware boot on 22000, AX210, and BZ-family devices, including RF-kill boot refusal versus `run_in_rfkill`, context-info allocation failures, IML polling path, TOP reset requests, firmware reset handshake timeout/error, and opmode leave. Useful logs include `"Init card's basic functions"`, reset-handshake timeout diagnostics, `"TOP reset successful"`, RF name detection, shadow register enablement, and firmware-alive interrupt progression. Integration tests should confirm TX/RX queues are freed on stop and reinitialized on restart without stale queue-used bits.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/trans.c

Purpose: Implements the main PCIe transport layer for gen1/gen2 iwlwifi devices. It covers PCI transport allocation/free, hardware preparation/activation, classic firmware loading, APM and power-management sequencing, interrupt capability selection, MSI-X cause mapping, NIC access locking, suspend/resume handshakes, RF-kill handling, reset/removal orchestration, debugfs surfaces, firmware error dump collection, product reset ACPI integration, CRF/RF ID discovery, and PCI probe/remove glue.

Important APIs, types, and functions: Public transport entry points include `iwl_trans_pcie_sw_reset()`, `iwl_pcie_apm_config()`, `iwl_pcie_apm_stop_master()`, `iwl_pcie_prepare_card_hw()`, `iwl_pcie_apply_destination()`, `iwl_pcie_check_hw_rf_kill()`, `iwl_pcie_conf_msix_hw()`, `iwl_pcie_synchronize_irqs()`, `iwl_trans_pcie_start_fw()`, `iwl_trans_pcie_fw_alive()`, `iwl_trans_pcie_stop_device()`, `iwl_trans_pcie_rf_kill()`, D3 suspend/resume, `_iwl_trans_pcie_start_hw()`, `iwl_trans_pcie_start_hw()`, opmode enter/leave, CSR/PRPH read/write wrappers, PNVM/DRAM cleanup, `iwl_trans_pcie_free()`, reset functions, NIC access functions, memory/config reads, TX queue wait helpers, dump/debugfs functions, IMR copy helpers, `iwl_pci_gen1_2_probe()`, `iwl_pcie_gen1_2_remove()`, and `iwl_pcie_gen1_2_activate_nic()`. Core state is `struct iwl_trans`, `struct iwl_trans_pcie`, `struct iwl_trans_info`, `struct iwl_mac_cfg`, PCI/MSI-X entries, TX/RX queue arrays, DMA pools, wait queues, firmware monitor buffers, and status/reset bitfields.

Control flow: Probe calls `iwl_trans_pcie_alloc()` to allocate the transport, command pool, TSO per-CPU pages, byte-count pool, dummy NAPI netdev, locks, wait queues, RX allocator workqueue, DMA masks, IRQ mode, invalid command buffer, and debug TLV state. It then checks product reset ACPI state, prepares/activates the card enough to read CRF/RF IDs, maps RF ID if OTP is blank, resolves the device configuration, computes RX buffer count and PCIe link info, checks ME ownership, starts the higher driver with `iwl_drv_start()`, and registers debugfs. Hardware start (`_iwl_trans_pcie_start_hw()`) prepares ownership, clears persistence, software-resets, optionally force power-gates integrated 22000, runs APM init, configures MSI-X, enables RF-kill interrupts, marks opmode up, and reports RF-kill state. Classic firmware start (`iwl_trans_pcie_start_fw()`) prepares hardware, masks interrupts, checks RF-kill, initializes NIC/RX/TX, enables firmware-load interrupt, loads firmware sections through FH DMA, starts the CPU, and rechecks RF-kill. Stop disables interrupts/ICT, synchronizes IRQ/NAPI if not from IRQ, stops TX and RX DMA, powers down DMA clocks, releases MAC access requests, stops APM, retakes ownership, restores IVAR, clears status bits, and re-enables RF-kill interrupt.

State and persistence behavior: The file maintains transport runtime state across opmode operations: `is_down`, `opmode_down`, RF-kill flags, `csme_own`, `me_present`, `pm_support`, `ltr_enabled`, MSI-X masks, IRQ vector allocation, `sx_state`, `imr_status`, `ucode_write_complete`, TX/RX memory pools, firmware monitor DMA, PNVM/reduced-table DRAM regions, and debugfs monitor read cursors. D3 suspend uses persistence bits and VAUX power selection; resume reactivates NIC, reconfigures IVAR/ICT, restores power source, optionally resets TX/RX queues, and detects NEVO reset. Product reset state is mediated through ACPI DSM and scheduled removal work; once reset is scheduled, `STATUS_TRANS_DEAD` prevents further use.

Dependencies and integration points: This file is the central integration point among Linux PCI/MSI/MSI-X/ACPI/debugfs/DMA APIs, iwlwifi opmode callbacks, firmware image descriptors, TX/RX implementations, context-info code, MEI ownership detection, device configuration lookup, debug TLV/error-dump code, and platform reset mechanisms. It calls into `rx.c` for RX allocation/stop/NAPI sync/ICT, into non-gen2 and gen2 TX code for queue lifecycle, into firmware debug helpers for monitor destinations and dumps, and into opmode for NIC config, RF-kill, reset/error notifications, and driver start/stop.

Risks and edge cases: Hardware-family branching is dense: pre-8000 firmware loading differs from 8000 secured loading and gen2 context-info loading; BZ changes reset, MAC-access, SW-error, byte-count, and RF/CNV step handling. Register access must hold NIC access or `reg_lock` where required, and `iwl_trans_pcie_release_nic_access()` intentionally keeps bottom halves disabled across the access window. Firmware loading relies on FH_TX interrupts and wait queues; if interrupts are masked incorrectly the load times out. Stop and D3 paths must avoid accessing PRPH after APM stop and must synchronize interrupts before freeing NAPI/queues. Product reset work removes PCI devices asynchronously and may also remove BT sibling functions; module references and bus locks are essential. Debugfs monitor reads can go out of sync with firmware wrap counters and deliberately restart at buffer beginning.

Test signals: Probe/remove tests should cover MSI-X and MSI fallback, DMA mask fallback, blank OTP RF-ID mapping, ME-present product-reset downgrade, config lookup failure, WiFi7-without-IWLMLD rejection, and debugfs registration. Runtime tests should cover classic firmware load success/timeout, RF-kill during start and stop, D3 suspend/resume with and without reset, NEVO reset detection, queue flush timeout logging, firmware error dump generation with TXCMD/CSR/FH/RB/paging/monitor masks, IMR copy completion/error, and reset modes through debugfs. Diagnostic outputs include CSR dumps, host monitor dump on wake failure, interrupt/debugfs counters, firmware monitor data, and `iwl_trans_pcie_dump_regs()` on DMA/FH timeouts.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/tx-gen2.c

Purpose: Implements gen2 PCIe transmit queues for data frames and host commands. It builds TFH transmit frame descriptors, maps skb/head/fragments/TSO pages to DMA transfer buffers, handles a 4 GiB boundary hardware workaround, maintains scheduler byte-count tables, advances hardware write pointers, allocates/frees dynamic firmware-managed queues, and enqueues firmware host commands on the command queue.

Important APIs, types, and functions: Key public functions are `iwl_txq_space()`, `iwl_txq_gen2_set_tb()`, `iwl_txq_gen2_tfd_unmap()`, `iwl_txq_gen2_tx()`, `iwl_txq_dyn_alloc()`, `iwl_txq_dyn_free()`, `iwl_txq_gen2_tx_free()`, `iwl_txq_gen2_init()`, and `iwl_pcie_gen2_enqueue_hcmd()`. Internal helpers include `get_workaround_page()`, `iwl_txq_gen2_set_tb_with_wa()`, A-MSDU builders, fragment builders, `iwl_pcie_gen2_update_byte_tbl()`, `iwl_txq_gen2_free_tfd()`, `iwl_txq_gen2_unmap()`, queue DMA allocation/free helpers, and firmware queue-allocation response parsing. Core types are `struct iwl_txq`, `struct iwl_tfh_tfd`, `struct iwl_tfh_tb`, `struct iwl_cmd_meta`, `struct iwl_device_tx_cmd`, `struct iwl_host_cmd`, `struct iwl_tx_queue_cfg_cmd`, `struct iwl_scd_queue_cfg_cmd`, skb fragments, and TSO page metadata.

Control flow: Data TX enters `iwl_txq_gen2_tx()`, validates queue range/use, linearizes excessive fragments, locks the queue, stops it when free space drops below high watermark, optionally parks packets in `overflow_q` if fewer than three slots remain, assigns skb/cmd metadata and firmware sequence, builds a TFD through `iwl_txq_gen2_build_tfd()`, updates byte-count table with command length and number of TBs, starts the stuck timer when transitioning from empty, advances `write_ptr`, and writes `HBUS_TARG_WRPTR`. TFD building splits into regular frame and GSO A-MSDU paths. Regular frames map first-TB command memory, command/header remainder, skb head payload, skb frags, and nested skb frags. GSO A-MSDU builds per-subframe Ethernet/SNAP/IP/TCP headers in TSO pages and maps payload pieces from the scatter-gather table. Host commands enter `iwl_pcie_gen2_enqueue_hcmd()`, calculate copied versus NOCOPY/DUP chunks, reserve command queue space, fill a wide command header, copy the debug-visible payload prefix, map copied and nocopy command buffers into TBs, set metadata, trace the command, and advance the command queue write pointer under `reg_lock`.

State and persistence behavior: TX queue state persists in circular `read_ptr`/`write_ptr`, `n_window`, `entries`, `tfds`, `first_tb_bufs`, byte-count table DMA memory, stopped/used bitmaps, overflow queue, watchdog timer, and per-entry `meta`/`skb`/`cmd`/`free_buf`. DMA mappings are recorded implicitly in each TFD TB plus metadata bits distinguishing page mappings from single mappings; `meta->sg_offset` marks TSO/SG ownership. `get_workaround_page()` chains temporary workaround pages through `skb->cb` using per-page `iwl_tso_page_info` reference counts. Dynamic queues are firmware-visible only after an SCD queue config command responds with a queue number/write pointer; `queue_used` prevents duplicate ownership. Command queue entries own allocated command buffers and sensitive duplicate buffers until reclaim/free.

Dependencies and integration points: The file depends on Linux skb, TCP segmentation offload helpers, DMA mapping APIs, queue timers, and iwlwifi transport internals. It integrates with `iwl_pcie_prep_tso()`, `iwl_pcie_free_tso_pages()`, shared TX queue allocation/init helpers, firmware SCD queue config APIs, opmode skb free callbacks, tracepoints, reset/error scheduling, and command completion from the RX path. Queue write pointers are written through HBUS target registers and byte-count tables consumed by firmware scheduler hardware.

Risks and edge cases: The biggest correctness risks are DMA lifetime and descriptor shape. The first TB is bidirectional command memory and is never unmapped by `iwl_txq_gen2_tfd_unmap()`, while later TBs require correct single/page unmap decisions. The 4 GiB boundary workaround copies small TBs to a separate page and has different cleanup semantics depending on whether the original mapping should be unmapped immediately or later. `iwl_txq_gen2_set_tb()` warns on boundary crossing and enforces `max_tbs`; callers that ignore errors can corrupt cleanup, so most paths unwind immediately. Host command NOCOPY chunks must not be followed by normal copied chunks, and DUP is allowed only once. Queue space logic reserves an empty slot and uses overflow behavior under pressure; incorrect high/low watermark behavior can stop queues permanently or overrun the ring. BZ A-step forces 4096-entry dynamic queues, while other hardware retries with smaller power-of-two queue sizes.

Test signals: Validate normal data TX, fragmented skb TX, nested skb frags, GSO A-MSDU, DMA mapping failure unwinds, 4 GiB boundary workaround path, queue high-water stop and overflow queue behavior, watchdog timer start/cancel, dynamic queue allocation command versions 0 and 3, queue allocation response validation, command queue full reset scheduling, NOCOPY/DUP host commands, and TX queue free while non-empty. Useful signals include `IWL_DEBUG_TX`, `IWL_DEBUG_TX_QUEUES`, `IWL_DEBUG_HC`, tracepoints for TX/TB/HCMD, byte-count table contents, queue-used bits, and absence of DMA unmap or too-many-TB warnings during teardown.
