# sources/distributed-fs/ceph-client/arch/riscv/mm/physaddr.c

Purpose: implements RISC-V virtual/physical address conversion helpers exported to the rest of the kernel. Important APIs: `__virt_to_phys`, `__phys_addr_symbol`, `linear_mapping_va_to_pa`, and `linear_mapping_pa_to_va`. Control flow is intentionally small: validate the address class, then delegate the actual arithmetic to `__va_to_pa_nodebug` or `kernel_map.va_pa_offset`. State comes from the global `kernel_map` established during boot; no persistence is owned here. Dependencies include `asm/page.h`, `asm/sections.h`, linear/kernel mapping predicates, `WARN`, `BUG_ON`, and export symbol plumbing. Integration points are memory management, DMA/cache code, and callers of `virt_to_phys`/`__pa_symbol`. Risks are misuse on vmalloc/ioremap/module-like addresses, boundary errors around `kernel_map.size`, and boot-time calls before `va_pa_offset` is valid. Test signals: boot with debug virtual checks, invalid-address WARN coverage, KASLR mapping conversions, and exported helper use by modules.

# sources/distributed-fs/ceph-client/arch/riscv/mm/pmem.c

Purpose: provides the RISC-V persistent-memory cache maintenance hooks required by libnvdimm/DAX code. Important APIs are `arch_wb_cache_pmem` and `arch_invalidate_pmem`, both GPL-exported. Control flow first prefers platform `noncoherent_cache_ops` callbacks when `CONFIG_RISCV_NONSTANDARD_CACHE_OPS` supplies them, otherwise emits architecture CMO alternatives through `ALT_CMO_OP` using `riscv_cbom_block_size`. State is external: the global noncoherent cache operation table and probed cache block size. There is no persistence, but correctness directly affects durability of persistent memory writes. Dependencies include `linux/libnvdimm.h`, `asm/cacheflush.h`, `asm/dma-noncoherent.h`, `virt_to_phys`, and RISC-V alternative patching. Risks are missing cache operation support on noncoherent platforms, incorrect physical address conversion for non-linear addresses, and block-size mismatches. Test signals: pmem flush/invalidate tests, DAX fsync/powerfail validation, nonstandard ops platforms, and CMO-disabled fallback behavior.

Test signals: read `kernel_page_tables`, EFI table dumping, `CONFIG_DEBUG_WX`, KASAN/Svpbmt/NAPOT configs, and boot logs from `ptdump_check_wx`.

# sources/distributed-fs/ceph-client/arch/riscv/mm/tlbflush.c

Purpose: provides architecture TLB invalidation for local, remote, mm, page, range, hugepage, kernel, THP, and batched unmap paths. Important APIs include `flush_tlb_all`, `flush_tlb_mm`, `flush_tlb_mm_range`, `flush_tlb_page`, `flush_tlb_range`, `flush_tlb_kernel_range`, THP range helpers, and `arch_tlbbatch_*`. Control flow chooses local flush when the current CPU is the only target, SBI remote rfence when available, or synchronous IPIs otherwise. Range flushing compares the number of invalidated PTEs against `tlb_flush_all_threshold`, using SvINVAL instructions when supported or per-page `sfence.vma` otherwise. State is minimal: `tlb_flush_all_threshold` and batch CPU masks; ASID comes from `mm->context.id`. Dependencies include SBI rfence, CPU masks, hugepage size, NAPOT rules, mmu notifiers, and RISC-V ISA extension detection. Risks are stale translations from wrong stride/ASID/cpumask, overly broad flushes hurting performance, and secondary TLB notifier omissions. Test signals: mmu_gather stress, hugetlb/THP unmap, ASID rollover, SBI vs IPI systems, SvINVAL-capable CPUs, and TLB shootdown tracing.

# sources/distributed-fs/ceph-client/arch/riscv/net/bpf_jit_comp32.c

Purpose: implements the RV32G eBPF JIT backend by representing each 64-bit BPF register as high/low 32-bit RISC-V storage, with some callee-saved BPF registers spilled in a scratch area. Control flow translates each BPF opcode to RV32 instruction sequences, handles long branches with extra jumps, stores BPF R6-R9/AX on stack, emits helper calls through fixed `lui/jalr` sequences, and implements tail calls by decrementing the tail-call counter then jumping to `prog->bpf_func + 4`. State is held in `rv_jit_context` and stack layout: saved registers, BPF scratch registers, BPF stack, and call stack. Dependencies include BPF helper address resolution, verifier zext metadata, RISC-V instruction encoders, `struct bpf_array`, and kernel calling convention. Risks include carry/borrow mistakes in 64-bit arithmetic, unsupported 64-bit div/mod and 8-byte atomics, branch range convergence issues, stack spill offset errors, and tail-call prologue assumptions. Test signals: BPF selftests on RV32, arithmetic/branch/endian tests, helper-call and tail-call programs, stack-depth tests, atomic rejection paths, and JIT convergence failures.

# sources/distributed-fs/ceph-client/arch/riscv/purgatory/purgatory.c

Purpose: verifies kexec-loaded segments before transferring control to the new RISC-V kernel. Important data/functions are `purgatory_sha256_digest`, `purgatory_sha_regions`, `verify_sha256_digest`, and `purgatory`. Control flow initializes a SHA-256 context, iterates all `KEXEC_SEGMENT_MAX` regions, updates the digest from each `start/len`, compares with the patched expected digest, and loops forever on mismatch. State is the `.kexec-purgatory` data patched by the kexec loader; there is no persistence beyond the loaded image. Dependencies include freestanding SHA-256, `linux/purgatory.h`, string/memcmp support, and the assembly entry. Risks include trusting malformed region descriptors, lack of diagnostics on failure, digest mismatch causing an intentional silent hang, and region list entries with zero length still being processed. Test signals: kexec with valid/invalid segment hashes, maximum segment count, purgatory relocation patching, and failure-path observation under emulation.

Purpose: implements the APPLDATA memory statistics provider. Important type/function are the packed `appldata_mem_data` record, `appldata_get_mem_data`, module init/exit, and static `appldata_ops`. Control flow allocates one DMA-capable data record, registers with the base, and on each callback increments `sync_count_1`, samples VM events, `si_meminfo`, file page cache, swap info, TOD timestamp, then increments `sync_count_2`. State is the binary record consumed by z/VM; the layout is compatibility-sensitive and versioned through APPLDATA product/modification metadata. Dependencies include VM event counters, sysinfo, swap, page state, TOD clock, and base registration APIs. Risks include changing packed layout, counter truncation/semantic drift, static `sysinfo` reuse relying on serialized callbacks, underflow in cached calculation, and z/VM reading while Linux updates. Test signals: module load/unload, APPLDATA start/stop sysctl, memory pressure and swap activity, sync count consistency, and record-size validation.

# sources/distributed-fs/ceph-client/arch/s390/appldata/appldata_os.c

Purpose: implements the APPLDATA OS statistics provider for CPU time, load, runnable/thread counts, and per-online-CPU data. Important types/functions include packed `appldata_os_per_cpu`, flexible `appldata_os_data`, `appldata_get_os_data`, module init/exit, and static `appldata_ops`. Control flow allocates a maximum-sized record for possible CPUs, registers it, then each callback updates sync count, scheduler/load statistics, per-online-CPU jiffies converted from `kcpustat`, CPU IDs, record size, and timestamp. If active CPU count changes while monitoring, it starts a new record with the new size and stops the old size. State is the allocated record plus `ops.size`, both visible to z/VM through DIAG. Dependencies include scheduler statistics, loadavg, CPU iteration, TOD clock, APPLDATA base, and record-size limits. Risks are packed ABI changes, hotplug-size update ordering, DIAG failure during size transition, max record size exceeding 4024 bytes, and z/VM reads during update. Test signals: CPU hotplug, load generation, APPLDATA start/stop, sync count checks, max CPU config, and DIAG failure logging.
