# sources/distributed-fs/ceph-client/kernel/rcu/rcutorture.c

Purpose: this file implements the kernel RCU torture-test module. It is a stress and correctness harness for multiple RCU-like flavors, including normal RCU, SRCU/static SRCU/dynamic SRCU, deliberately broken variants, Tasks RCU variants when configured, and trivial RCU variants. It repeatedly publishes and retires protected objects, drives many grace-period APIs, runs readers from task and timer contexts, exercises callback barriers, forward-progress behavior, priority boosting, CPU stalls, CPU hotplug/on-offline support through the torture framework, NOCB offload toggling, read-then-exit cases, SRCU lockdep scenarios, debug-object duplicate callback detection, and grace-period wrap lag handling.

Important APIs/types/functions: `struct rcu_torture_ops` is the central flavor abstraction. It supplies read-side locking, deferred free, synchronous/expedited/conditional/polling grace-period operations, callback enqueue/barrier operations, force-quiescent-state hooks, diagnostics, boost/stall helpers, GP sequence formatting, NOCB/gpwrap knobs, and capability flags. `struct rcu_torture` is the protected object moved through the callback pipeline, with `rtort_pipe_count`, `rtort_mbtest`, and a memory-ordering check pointer. `struct rcu_torture_reader_check` coordinates cross-reader global ordering checks. `struct rt_read_seg` records the first failing or close-call read-side segment. Main worker functions include `rcu_torture_writer()`, `rcu_torture_reader()`, `rcu_torture_fakewriter()`, `rcu_torture_fqs()`, `rcu_torture_boost()`, `rcu_torture_fwd_prog()`, `rcu_torture_barrier()`, `rcu_torture_updown()`, `rcu_nocb_toggle()`, `rcu_torture_stall()`, `rcu_torture_read_exit()`, `rcu_torture_preempt()`, `rcu_torture_stats_print()`, `rcu_torture_init()`, and `rcu_torture_cleanup()`.

Control flow: module initialization calls `torture_init_begin()`, chooses an ops vector by `torture_type`, normalizes module parameters, initializes flavor-specific state, sets up the `rcu_tortures[]` freelist, resets counters, computes enabled writer synchronization types with `rcu_torture_write_types()`, and starts fake writers, readers, the writer, optional up/down, NOCB, stats, shuffle/stutter, FQS, boost, shutdown, on/offline, stall, forward-progress, barrier, read-exit, preempt, debug-object, slow-GP, and gpwrap-lag facilities. The writer repeatedly allocates a test object, publishes it with `rcu_assign_pointer()`, advances the old object through either asynchronous callback or synchronous GP pipeline updates, randomly selects among normal, expedited, conditional, polling, and full-state primitives, validates polling cookies under active readers, updates the published version, and occasionally toggles dynamic GP expediting. Readers enter randomized overlapping critical sections via `rcutorture_one_extend()`, dereference `rcu_torture_current`, validate memory-ordering markers, increment per-CPU pipe/batch counters, optionally test polling cookies, and record detailed segment data on close calls.

Reader extension behavior: `RCUTORTURE_RDR_*` bits model combinations of local BH disabling, IRQ disabling, preemption disabling, `rcu_read_lock_bh()`, `rcu_read_lock_sched()`, nested flavor-specific RCU reads, and SRCU up/down handoff. `rcutorture_one_extend()` deliberately changes protection without leaving a gap by adding new protection before removing old protection, then removes old protections in an order that avoids illegal BH/IRQ/preemption transitions. `rcutorture_one_extend_check()` validates the resulting execution state when configured. `rcu_torture_updown()` starts SRCU read-side sections in a kthread using `down_read` operations and ends them in hrtimer context through matching `up_read`, specifically testing cross-context SRCU APIs.

State and persistence behavior: all state is runtime-only kernel memory. The object pool is a fixed static array (`rcu_tortures`) plus a freelist guarded by `rcu_torture_lock`; retired objects move through callback or synchronous pipeline state before returning to the freelist. Global and per-CPU counters track allocations, frees, reader pipe depth, batch GP deltas, memory-ordering failures, boost failures, barrier successes/errors, timers, NOCB toggles, read-exit episodes, and gpwrap events. Kthread pointers, hrtimers, wait queues, notifier blocks, and callback-flood allocations are created at init and torn down in cleanup. No data is persisted to disk; evidence is emitted through kernel logs, tracepoints, warnings, and torture-framework status.

Dependencies and integration points: the file depends on the core RCU API (`rcupdate`, `rcupdate_wait`, `rcu_notifier`, internal `rcu.h`), SRCU, Tasks RCU, Tasks Trace RCU, CPU hotplug, scheduler/RT priority controls, timers/hrtimers, work/torture helpers, NOCB controls, OOM notifiers, debug objects, mem_dump_obj, lockdep, nohz tick dependencies, trace clocks, and module parameters. Integration with the shared torture framework is extensive: `torture_param`, `torture_create_kthread`, `torture_stop_kthread`, `torture_shuffle_init`, `torture_stutter_init`, `torture_shutdown_init`, `torture_onoff_init`, `stutter_wait`, and `torture_must_stop` coordinate lifecycle and workload pacing.

Risks: this code intentionally stresses fragile concurrency paths, so the largest risks are false positives from invalid parameter combinations, hangs during stall/deadlock tests, priority inversions caused by boost testing, memory pressure during callback flood tests, and cleanup races among callbacks, timers, hrtimers, and kthreads. The pipe-count invariant is security-relevant for RCU correctness: a protected object observed too far through the retirement pipeline signals a too-short grace period or reader protection gap. The reader-extension state machine is sensitive to PREEMPT_RT, IRQ/BH context rules, and flavor-specific readlock return encodings. Forward-progress callback flooding can hit OOM, so the OOM notifier tries to stop and free callbacks. Built-in runs can power off the machine on shutdown paths, and deliberate `busted` flavors intentionally violate RCU semantics.

Test signals: useful signals are kernel log lines ending in `End of test: SUCCESS`, zero `n_rcu_torture_error`, zero barrier/boost/memory-ordering failures, `Reader Pipe` counts not exceeding pipe depth 1 for correct flavors, successful callback barrier ratios, forward-progress histograms with enough laundered callbacks, absence of unexpected WARN splats outside deliberately requested negative tests, and clean shutdown after `rcu_torture_cleanup()`. Negative signals include `!!!` in stats output, `Cookie check` warnings, duplicated callback debug-object failures not matching the debug-object test, reader segment dumps, writer stall diagnostics, boost inversion failures, OOM during forward progress, or mismatched up/down hrtimer counts.

# sources/distributed-fs/ceph-client/kernel/rcu/refscale.c

Purpose: this file implements the RCU reference-acquisition scalability benchmark module. Unlike `rcutorture.c`, it focuses on measuring read-side/reference-acquisition overhead rather than proving grace-period correctness. It compares normal RCU, SRCU variants, Tasks/Trace RCU where configured, atomic reference counts, per-CPU increment forms, rwlocks/rwsems/spinlocks, acquire-release memory operations, clock/jiffies reads, preemption/BH/IRQ disable sections, and `SLAB_TYPESAFE_BY_RCU` lookup patterns.

Important APIs/types/functions: `struct ref_scale_ops` abstracts each benchmarked mechanism with optional `init`/`cleanup`, `readsection`, `delaysection`, `enable_irqs`, and `name`. `struct reader_task` tracks each reader kthread, start flag, wait queue, and measured duration. `ref_scale_init()` selects an ops vector by `scale_type`, creates readers and the main orchestrator, and registers optional shutdown. `main_func()` drives experiments and prints per-run averages. `ref_scale_reader()` performs synchronized reader-side timing. `rcu_scale_one_reader()`, `rcu_scale_warm_cool()`, `process_durations()`, and `reset_readers()` implement the measurement loop. Typesafe tests use `struct refscale_typesafe`, `typesafe_init()`, `typesafe_cleanup()`, `typesafe_delay_section()`, and acquisition/release variants based on refcount, spinlock, or seqlock.

Control flow: initialization calls `torture_init_begin()`, matches `scale_type` against a static `scale_ops[]` table, runs the selected init hook, prints parameters, sets shutdown handling, normalizes `nreaders`, `loops`, and `nruns`, allocates `reader_tasks`, starts one reader kthread per reader, then starts `main_func()`. The main task waits for all readers, performs warm/cool loops, and for each run sets shared atomics (`nreaders_exp`, `n_started`, `n_warmedup`, `n_cooleddown`), publishes each reader's `start_reader` flag with release ordering, wakes readers, waits for completion, collects durations, and prints average nanoseconds per loop. Readers bind to deterministic CPUs, wait for the start flag, synchronize start/warm/cool phases through atomics, optionally disable interrupts around the timed region, execute the selected read section once for timing, store `last_duration_ns`, and keep doing load-maintenance work until all readers cool down.

Benchmark mechanisms: RCU and SRCU sections loop over lock/unlock pairs, with delay variants inserting micro/nanosecond waits. Refcount tests use `atomic_inc/atomic_dec`; per-CPU tests cover `this_cpu_inc/dec`, raw `this_cpu_ptr` updates, preempt-disabled updates, BH-disabled updates, and IRQ-save updates. Lock tests cover read-side rwlock, rwsem, raw spinlock, and raw spinlock with IRQ save/restore. Other comparison points measure acquire-release stores, `sched_clock()`, `ktime_get_real_fast_ns()`, `jiffies`, preempt disable/enable, BH disable/enable, IRQ disable/enable, and IRQ save/restore overhead. Typesafe tests allocate a `SLAB_TYPESAFE_BY_RCU` cache, keep an RCU-protected pointer array, retry when validation fails, and verify stable object fields while using refcount, lock, or seqlock acquisition.

State and persistence behavior: all benchmark state is in memory and exists only during the module run. Module parameters control scale type, verbosity, holdoff, guest OS delay, lookup instance count, loop count, reader count, run count, read delay, and shutdown behavior. Results are emitted to the kernel log with per-reader durations and per-run averages; there is no file output. `reader_tasks`, `result_avg`, temporary print buffers, and typesafe slab/pointer arrays are dynamically allocated and freed in cleanup. The selected `cur_ops` may hold global helper state such as `srcu_ctlp`, `refcnt`, `test_acqrel`, locks, or `typesafe_kmem_cachep`.

Dependencies and integration points: the module uses the RCU/SRCU/Tasks Trace APIs, atomic/per-CPU primitives, scheduler CPU affinity and clock APIs, raw spinlocks/rwlocks/rwsems, `seq_buf` formatting, slab allocation with `SLAB_TYPESAFE_BY_RCU`, and the torture framework for parameters, thread creation, lifecycle, and optional shutdown. Its output is intended for `rcuscale`/torture automation and kernel log parsing rather than a formal pass/fail result.

Risks: benchmark validity depends on synchronized start, CPU affinity, interruption control, and avoiding measurement skew during warmup/cooldown. Disabling interrupts around timed sections reduces noise but is unsafe for mechanisms that require IRQs, so `enable_irqs` must be correct. Integer normalization protects against `nreaders * loops` overflow, but extreme parameters can still create long-running or noisy tests. Typesafe tests are intentionally subtle: stale or recycled objects must be validated correctly with refcount/lock/seqlock acquisition, and cleanup must destroy every allocated slab object and cache. Some per-CPU variants explicitly can lose counts on preemptible kernels; they are comparison baselines, not safe generic reference algorithms.

Test signals: expected signals are startup parameter logs, per-experiment `THREAD-NUM:Total loop time in ns` lines, final `Runs Time(ns)` average output, and clean module cleanup. Useful validation includes running several `scale_type` values, checking that invalid names list available types with `-EINVAL`, verifying that `loops`, `nreaders`, and `nruns` are clamped when nonpositive, confirming no negative durations, and enabling typesafe variants under stress to catch `WARN_ONCE(a != b)` or `WARN_ON_ONCE(a * a != b)` consistency failures.

# sources/distributed-fs/ceph-client/kernel/rcu/srcutiny.c

Purpose: this file implements the tiny SRCU backend for non-preemptible single-CPU configurations. It provides the exported SRCU lifecycle, callback, synchronize, and polling APIs using a compact two-counter scheme, one callback list, one work item, and an irq_work bridge for safe workqueue scheduling.

Important APIs/types/functions: exported entry points include `init_srcu_struct()` or `__init_srcu_struct()` with lockdep enabled, `cleanup_srcu_struct()`, `__srcu_read_unlock()`, `srcu_drive_gp()`, `srcu_tiny_irq_work()`, `call_srcu()`, `synchronize_srcu()`, `get_state_synchronize_srcu()`, `start_poll_synchronize_srcu()`, `poll_state_synchronize_srcu()`, `rcu_scheduler_starting()` for non-tree RCU builds, and `srcu_init()`. Internal helpers include `init_srcu_struct_fields()` and `srcu_gp_start_if_needed()`. Important `srcu_struct` fields used here are `srcu_lock_nesting[2]`, `srcu_wq`, `srcu_cb_head`, `srcu_cb_tail`, `srcu_gp_running`, `srcu_gp_waiting`, `srcu_idx`, `srcu_idx_max`, `srcu_work`, and `srcu_irq_work`.

Control flow: initialization zeros both reader counters, initializes the wait queue, empty callback list, GP flags, index state, work item, and irq_work. `call_srcu()` stores the callback function, appends the callback under local IRQ save while preemption is disabled, then calls `srcu_gp_start_if_needed()`. That helper computes a target cookie from `get_state_synchronize_srcu()`, raises `srcu_idx_max`, and either queues irq_work after SRCU init or records the work item on `srcu_boot_list` during early boot. `srcu_tiny_irq_work()` schedules `srcu_work`, avoiding direct workqueue locking from potentially scheduler-sensitive contexts.

Grace-period behavior: `srcu_drive_gp()` exits if a GP is already running or the current index has reached `srcu_idx_max`. Otherwise it marks a GP running, detaches the current callback list, selects the old reader counter from `srcu_idx`, advances `srcu_idx` into the waiting phase, sets `srcu_gp_waiting`, and waits until the selected nesting counter reaches zero. Because `__srcu_read_unlock()` cannot always wake unconditionally without deadlock risk, the worker uses `swait_event_timeout_exclusive()` polling. After readers drain, it clears waiting, advances `srcu_idx` again to mark completion, invokes detached callbacks with BH disabled, clears `srcu_gp_running`, and reschedules itself if another cookie is pending.

State and persistence behavior: state is per-`srcu_struct` and runtime-only. Early boot callbacks persist temporarily on the global `srcu_boot_list` until `srcu_init()` marks `srcu_init_done` and schedules their work. `srcu_idx` is the compact phase/counter selector; `srcu_idx_max` records the furthest requested completion cookie. `srcu_cb_head` and `srcu_cb_tail` own pending callbacks until detached by the worker. Cleanup synchronizes irq_work, flushes work, and warns if readers, callbacks, GP flags, or index state remain active. No filesystem or durable state is written.

Dependencies and integration points: this tiny backend depends on SRCU public structures and helpers, `irq_work`, workqueues, simple wait queues, completions via `rcu_synchronize`, preemption controls, local IRQ controls, lockdep maps, and RCU scheduler state. `synchronize_srcu()` integrates with lockdep by warning against deadlocking same-domain SRCU or RCU read-side contexts, returns immediately before the scheduler is active, and otherwise implements synchronous waiting by enqueuing `wakeme_after_rcu` and waiting for completion.

Risks: the implementation relies on single-CPU/non-preemptible assumptions and carefully scoped preemption/IRQ disabling. Misusing it in a configuration with real concurrent CPUs would make the simple counters and callback list unsafe. Wakeup logic is intentionally conservative, so missed rescheduling or stale `srcu_idx_max` handling can stall callbacks. Cookie comparisons must handle unsigned wrap correctly. Cleanup warnings indicate serious lifetime bugs: outstanding readers, callbacks, running work, or mismatched `srcu_idx` state. The early-boot path must avoid scheduling work before workqueues are ready while still ensuring callbacks eventually run.

Test signals: useful signals include SRCU API selftests on tiny configurations, boot-time callback tests before and after `srcu_init()`, `synchronize_srcu()` completion tests, callback ordering tests through `call_srcu()`, polling API checks for `get/start/poll` cookies including wrap cases, lockdep diagnostics for illegal synchronize-in-read-side use, cleanup tests that leave no warnings, and rcutorture/srcutorture runs using `CONFIG_TINY_SRCU` paths.
