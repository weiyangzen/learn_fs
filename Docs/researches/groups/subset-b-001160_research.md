# sources/distributed-fs/ceph-client/drivers/clk/rockchip/clk-rk3562.c

Purpose: RK3562 clock-controller driver for the Rockchip common clock framework. It describes the RK3562 CRU, PMU0/PMU1, DDR/sub-DDR, peripheral, media, GPU/NPU, PHY, and display clock topology as static PLL/rate/branch tables and wires that topology into OF clock providers, reset handling, and restart support.

Important APIs, types, and functions: the driver is almost entirely data-driven through Rockchip clock helper types from `clk.h`: `rockchip_pll_rate_table`, `rockchip_pll_clock`, and `rockchip_clk_branch`. `rk3562_pll_rates` lists supported RK3036/RK3328-style PLL parameters. `rk3562_pll_clks` registers APLL/GPLL/VPLL/HPLL/CPLL/DPLL, with DPLL marked critical and APLL/VPLL/HPLL allowing power-down. `PNAME()` arrays define parent mux names. `rk3562_clk_branches` uses `COMPOSITE`, `COMPOSITE_NODIV`, `COMPOSITE_NOMUX`, `COMPOSITE_FRACMUX`, `MUX`, `GATE`, `FACTOR`, `FACTOR_GATE`, and `MMC` macros to describe all child clocks. `rk3562_clk_init()` is the OF init entry, and `clk_rk3562_probe()` lets the same init run through the built-in platform driver.

Control flow: early init or platform probe calls `rk3562_clk_init()`. It computes `clk_nr_clks` from the maximum branch ID, maps the CRU register range with `of_iomap()`, allocates a Rockchip clock provider, registers PLLs with `rockchip_clk_register_plls()`, registers all branch clocks with `rockchip_clk_register_branches()`, initializes resets with `rk3562_rst_init()`, registers the global soft-reset restart notifier, and finally publishes the OF clock provider. Runtime clock operations are delegated to generic Rockchip/common-clock implementations created from the static branch descriptors.

State and persistence: persistent state is hardware register state in CRU/PMU/DDR clock select, gate, PLL, reset, GRF, and MMC tuning registers. The software state is the provider context and registered `clk_hw` objects. There is no filesystem or NVRAM persistence and no local suspend/resume syscore implementation despite including `syscore_ops.h`. `CLK_IS_CRITICAL` and `CLK_IGNORE_UNUSED` entries preserve clocks required for boot, buses, PMU, DDR, GRF, GIC, timers, and selected always-on/debug paths.

Dependencies and integration points: depends on `dt-bindings/clock/rockchip,rk3562-cru.h`, Rockchip clock/reset helpers, common clock framework, OF address mapping, and the RK3562 reset implementation. Device-tree compatible `"rockchip,rk3562-cru"` is served both by `CLK_OF_DECLARE()` and `builtin_platform_driver_probe()`. Consumers use the generated clock IDs for UART, SAI/SPDIF, I2C/SPI/PWM/CAN, SDMMC/eMMC/SFC, USB/PCIe PHY, GMAC, GPU/NPU, RGA/VPU/VENC/VDEC, VI/VO/display, PMU, and DDR domains.

Risks and test signals: most risk is descriptor accuracy: parent lists, register offsets, mux widths, divider widths, gate bits, and clock IDs must match the RK3562 TRM and DT binding. Critical-clock flags are safety-sensitive because disabling bus/PMU/DDR/reset/GRF paths can hang the system. Fractional muxes for SAI, SPDIF, UARTs, and RTC32K need rate-change tests because they combine parent propagation and fractional registers. Test signals include boot without clock lookup failures, `/sys/kernel/debug/clk/clk_summary` parent/rate sanity, successful reset-controller users, UART baud accuracy, audio sample-rate generation, SD/MMC tuning clocks, GMAC reference clocks, display pixel clocks with `CLK_SET_RATE_NO_REPARENT`, and restart notifier behavior.

# sources/distributed-fs/ceph-client/drivers/clk/rockchip/clk-rk3568.c

Purpose: RK3568/RK3566 clock-controller driver. It registers two related clock-controller blocks: the main CRU and the PMUCRU. The main CRU supplies CPU, bus, GPU/NPU, DDR, multimedia, storage, PCIe/SATA/USB, GMAC, UART/I2C/SPI/PWM/CAN, and top-level derived clocks; the PMUCRU supplies always-on PMU, oscillator/reference, GPIO0, UART0/I2C0/PWM0, WiFi, USB/MIPI/PCIe PHY reference, HDMI reference, and PMU PLL clocks.

Important APIs, types, and functions: `rk3568_pll_rates` is the shared RK3036-style PLL rate table. `rk3568_pmu_pll_clks` defines PPLL/HPLL under PMUCRU; `rk3568_pll_clks` defines APLL/DPLL/GPLL/CPLL/NPLL/VPLL under CRU. CPU frequency handling uses `rockchip_cpuclk_rate_table`, `rk3568_cpuclk_rates`, and `rk3568_cpuclk_data`, then registers `armclk` with `rockchip_clk_register_armclk()`. `rk3568_clk_branches` and `rk3568_clk_pmu_branches` describe the main and PMU branch graphs with Rockchip macros. Dedicated fracmux descriptors cover I2S, SPDIF, audio PWM, UART0-9, and RTC32K. `rk3568_cru_critical_clocks` and `rk3568_pmucru_critical_clocks` are protected after registration.

Control flow: compatible `"rockchip,rk3568-pmucru"` invokes `rk3568_pmu_clk_init()`, which maps the PMUCRU, initializes `CLKPMU_NR_CLKS`, registers PMU PLLs and PMU branches, installs one PMU soft-reset bank, protects PMU critical clocks, and publishes the provider. Compatible `"rockchip,rk3568-cru"` invokes `rk3568_clk_init()`, which maps the main CRU, sizes the onecell table from the branch IDs, registers main PLLs, registers `armclk` CPU-rate support, registers all main branches, installs 30 soft-reset banks, registers restart, protects critical clocks, and publishes the provider. The platform-driver probe dispatches to the same init functions from OF match data.

State and persistence: state lives in main CRU and PMUCRU MMIO registers: PLL mode/configuration, clock muxes, dividers, fractional dividers, gate bits, MMC delay controls, soft-reset registers, and selected GRF muxes. Software state is provider memory and registered `clk_hw` objects. No disk state exists. There are no local suspend/resume callbacks even though `syscore_ops.h` is included. The driver relies on common-clock enable counts plus explicit critical-clock protection for always-on buses, PMU, CPU, top, USB, PHP, secure-flash, VI/VO, and PLL paths.

Dependencies and integration points: depends on `dt-bindings/clock/rk3568-cru.h`, Rockchip clock/reset helpers, OF MMIO mapping, common clock CPU clock support, and platform/OF matching. It integrates with PMU and main reset controllers, global restart, and clock consumers across CPUfreq, serial, audio, storage, network, display, camera, crypto, USB, PCIe/SATA, GPU/NPU, VPU/RGA/VDEC/VENC, and PHY drivers. `MUXGRF()` is used where clock selection is mediated by system GRF fields.

Risks and test signals: risks include split-provider ordering between PMUCRU and CRU, exact clock ID sizing, CPU clock divider transitions, critical-clock omissions, GRF mux semantics, and descriptor errors in large repeated UART/audio/storage/network blocks. The parent string `"xin_osc0_half "` in the I2S2 parent list includes a trailing space, which is suspicious because it may not match the intended registered fixed factor parent. Test signals include boot/probe of both compatibles, `clk_summary` for PMU and main providers, CPU frequency transitions across the table, UART0 through PMU and UART1-9 through CRU baud checks, I2S/SPDIF fractional rate accuracy, MMC/eMMC sample/drive phase clocks, GMAC0/1 RGMII/RMII speed mux behavior, PCIe/SATA/USB reference clocks, reset-controller users, and restart.

# sources/distributed-fs/ceph-client/drivers/clk/rockchip/clk-rk3576.c

Purpose: RK3576 clock-controller driver. It models a newer, larger RK3588-style Rockchip clock tree with core PLLs, separate big/little CPU clocks, top/bus/center/DDR roots, GPU/NPU, NVM/storage, USB/UFS/PHP/PCIe/SATA/PHY, secure non-secure, VI/VO/display, VPU/VDEC/VEPU/JPEG/RGA/EBC, audio/SAI/SPDIF/PDM/ASRC, GMAC/SDIO/SDMMC/DSMC/HSGPIO, PMU, and external/reference clock routing.

Important APIs, types, and functions: `rk3576_pll_rates` and `rk3576_ppll_rates` use RK3588-style PLL parameters. `rk3576_pll_clks` registers BPLL, LPLL, VPLL, AUPLL, CPLL, GPLL, and PPLL, with BPLL/LPLL using `pll_rk3588_core` and PPLL using `pll_rk3588_ddr`. CPU frequency support is split into `rk3576_cpubclk_rates`/`rk3576_cpubclk_data` for `armclk_b` and `rk3576_cpulclk_rates`/`rk3576_cpulclk_data` for `armclk_l`; little-core transitions include CCI pre/post mux programming. `rk3576_clk_branches` is the central branch table, using normal Rockchip branch macros plus `COMPOSITE_DIV_OFFSET`, `MUXGRF`, and `GATE_GRF` for registers spread across CRU, PMU, PHP, secure, and auxiliary GRF spaces. `rk3576_clk_init()` performs all registration.

Control flow: `rk3576_clk_init()` computes the maximum clock ID, obtains PMU0 GRF and IOC GRF regmaps with `syscon_regmap_lookup_by_compatible()`, maps the CRU, creates the provider, allocates `rockchip_aux_grf` entries for PMU0 and IOC GRF, and hashes them into `ctx->aux_grf_table` so GRF-backed muxes/gates can resolve their register maps. It then registers PLLs, registers `armclk_l` and `armclk_b`, registers all branches, initializes resets through `rk3576_rst_init()`, registers the global restart notifier, and publishes the OF provider. The platform-driver probe invokes the same init path for `"rockchip,rk3576-cru"`.

State and persistence: state is hardware register state across CRU, PMU, PHP, secure-ns, PMU0-GRF, IOC-GRF, PLL, reset, and clock-gate/register blocks. Software state consists of the clock provider, aux-GRF table entries, and registered clock hardware. Allocation failure paths unmap the CRU and free the first aux-GRF entry where needed, but successful init is intentionally permanent like most early SoC clock providers. There is no persistent storage and no local suspend/resume syscore implementation despite the include. Critical flags keep core roots, PMU roots, top/bus/center/DDR, secure, selected PHY/reference, display, VPU, SDGMAC, and other essential paths available.

Dependencies and integration points: depends on `dt-bindings/clock/rockchip,rk3576-cru.h`, Rockchip RK3576 reset helpers, common clock framework, OF/platform matching, syscon/regmap for PMU0/IOC GRFs, and Rockchip aux-GRF support. Integration points include CPUfreq for big/little clusters, CCI interconnect clocks, display pixel clocks from HDMI PHY or PLL paths, audio fractional/int clock pools, SAI MCLK-to-IO gates, PMU oscillator/reference routing, PCIe/UFS/USB/PHY references, storage, network, video/camera/display, secure crypto/OTP/TRNG, and restart/reset consumers.

Risks and test signals: risk is dominated by topology size and cross-register routing. Missing PMU0-GRF or IOC-GRF syscon compatibles aborts the whole provider, so DT ordering and compatible names are critical. Aux-GRF memory allocated on the success path is permanent; on the failure path after `ioc_grf_e` allocation failure only `pmu0_grf_e` is freed, which is adequate because `ioc_grf_e` was not allocated, but later registration failures are not handled because helpers are expected not to fail fatally during early init. CPU clock tables must match safe divider/mux sequences, especially CCI pre/post mux changes for little cores. Test signals include provider creation with both GRFs present, `clk_summary` coverage for all large domains, big/little CPU frequency transitions, CCI clock behavior, SAI MCLK GRF gates to IO, PMU/PHY reference muxes, USB/UFS/PCIe/SATA clocks, display pixel clock reparent/no-reparent behavior, secure-ns crypto/OTP/TRNG gates, reset-controller users, and system restart.
