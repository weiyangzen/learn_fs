# sources/distributed-fs/ceph-client/fs/erofs/super.c

Purpose: Implements EROFS filesystem registration, mount-context parsing, superblock loading, device-table setup, internal inode lifetime, export support, sysfs/shrinker/xattr integration, and module init/exit. This file is the main bridge between VFS mount operations and the EROFS on-disk format.

Important APIs, types, and functions: `_erofs_printk()` formats device-aware messages. `erofs_read_metadata()` reads variable-length 4-byte-aligned metadata records across block boundaries. `erofs_read_superblock()` validates the primary superblock magic, block size, feature bits, checksum, root nid, 48-bit fields, metabox fields, xattr-prefix fields, compression config, and device table. `erofs_fc_parse_param()` handles mount options such as `user_xattr`, `acl`, `cache_strategy`, `dax`, extra `device`, `fsid`, `domain_id`, `directio`, `fsoffset`, and `inode_share`. `erofs_fc_fill_super()` builds the active `super_block`; `erofs_fc_get_tree()` selects block-device, fscache nodev, or file-backed mount paths; `erofs_put_super()` and `erofs_kill_sb()` tear down mounted state. `erofs_module_init()` creates the inode slab, shrinker, compressed-data subsystem, sysfs, inode-share subsystem, and filesystem registration.

Control flow: Mounting starts with `erofs_init_fs_context()`, which allocates `struct erofs_sb_info` plus an `erofs_dev_context` IDR and installs `erofs_context_ops`. Parameter parsing mutates only the pending context. `erofs_fc_get_tree()` first tries normal block-device mounting, optionally retries file-backed mounting after `-ENOTBLK`, or uses nodev mode for fscache on-demand mounts. `erofs_fc_fill_super()` sets read-only/noatime VFS flags, validates DAX/inode-sharing constraints, configures backing device information, reads the superblock, adjusts block size, initializes compression cache state, loads packed/metabox/root inodes, registers the shrinker, initializes xattr prefixes, registers per-superblock sysfs, and publishes the root dentry. Teardown unregisters sysfs, shrinker, xattr prefixes, internal inodes, fscache cookies, DAX references, opened device files, and heap strings.

State and persistence behavior: Persistent state comes from the EROFS superblock and optional device/xattr/compression metadata. Runtime state lives in `erofs_sb_info`: mount options, feature flags, device IDR, DAX handles, fscache cookies, file-backed source, total block count, root/packed/metabox inodes, sysfs kobject, shrinker list node, and optional fsid/domain strings. Inodes are allocated from `erofs_inode_cachep`; `erofs_free_inode()` releases fast-symlink storage and per-inode shared xattr arrays. The filesystem is always mounted read-only, but runtime caches and kobjects persist until unmount.

Dependencies and integration points: Integrates with fs_context, VFS super operations, exportfs file handles, block devices, file-backed IO, fscache, DAX, sysfs, EROFS xattr/ACL handlers, compressed EROFS (`z_erofs_*`), shrinker registration, tracepoints, and optional page-cache sharing/on-demand features. Export operations encode 64-bit EROFS nids and generation numbers for NFS-style lookup.

Risks: Superblock parsing is security-critical because feature flags, 48-bit block counts, xattr prefix indices, metabox nid, and device-table slots come from disk. Cleanup paths are split between failed fs_context setup, `put_super`, and `kill_sb`, so leaks or double releases are possible if ownership transfer changes. DAX is disabled dynamically when unsupported; tests must cover fallback behavior. File-backed mounts intentionally avoid stacked filesystems to prevent recursion and stack-depth problems.

Test signals: Exercise valid and corrupted superblocks, checksum mismatch, unsupported incompatible features, non-page block sizes, fsoffset alignment, extra device count mismatches, file-backed mount rejection on stacked filesystems, DAX fallback, fscache/nodev mode, xattr-prefix init failure, packed/metabox inode loading, export handle round trips, remount/reconfigure of ACL options, module init failure unwinding, and unmount cleanup under active cached compressed data.

# sources/distributed-fs/ceph-client/fs/erofs/sysfs.c

Purpose: Provides EROFS sysfs exposure under `/sys/fs/erofs`, including global feature-advertisement files and per-mounted-superblock tunables.

Important APIs, types, and functions: `struct erofs_attr` extends `struct attribute` with an attribute ID plus an offset into either `struct erofs_sb_info` or `struct erofs_mount_opts`. Macro families such as `EROFS_ATTR_RW_UI`, `EROFS_ATTR_FUNC`, and `EROFS_ATTR_FEATURE` declare attributes. `erofs_attr_show()` renders supported features, unsigned integer fields, boolean fields, and optional compression acceleration engines. `erofs_attr_store()` updates integer/boolean tunables, handles `drop_caches`, and optionally configures zip acceleration engines. `erofs_register_sysfs()` and `erofs_unregister_sysfs()` attach and detach a per-superblock kobject. `erofs_init_sysfs()` registers the root kset and feature kobject; `erofs_exit_sysfs()` releases them.

Control flow: Module init calls `erofs_init_sysfs()`, which names and registers the `erofs_root` kset under `fs_kobj`, then adds a `features` kobject with static read-only feature attributes. During mount, `erofs_register_sysfs()` initializes `sbi->s_kobj`, assigns the EROFS kset, adds the kobject under the superblock sysfs name, and waits on `s_kobj_unregister` if initialization fails. Attribute reads map the requested `erofs_attr` to either a constant response or an in-memory field. Attribute writes parse input with `kstrtoul()`, validate range, and store directly into runtime mount state. Unmount removes the kobject only if it reached sysfs, then waits for release completion.

State and persistence behavior: Sysfs stores no on-disk state. Runtime writes modify fields such as `sync_decompress` and `dir_ra_bytes` in the mounted `erofs_sb_info`; `drop_caches` causes immediate cache invalidation rather than storing a value. Feature files always print `supported` for features compiled into this source table. The release path uses a completion embedded in `erofs_sb_info` to prevent freeing superblock-private memory while sysfs still owns a kobject reference.

Dependencies and integration points: Depends on the EROFS superblock layout in `internal.h`, compression helpers in `compress.h`, kobject/kset sysfs APIs, the managed compressed-data mapping (`MNGD_MAPPING`), `z_erofs_shrink_scan()`, and optional acceleration hooks (`z_erofs_crypto_*`). It is called from `super.c` during module init/exit and mount/unmount.

Risks: Offset-based attribute access is compact but brittle if an attribute is declared with the wrong struct type or field type. Writable attributes are updated without additional locking, so consumers must tolerate racy reads of simple scalar tunables. `drop_caches` can trigger broad cache invalidation and shrinker activity, so it needs coverage under concurrent reads. Acceleration store disables all engines before enabling the requested list; a later parse failure can leave all engines disabled.

Test signals: Verify `/sys/fs/erofs/features/*` content, per-mount kobject names, mount/unmount races, rejected invalid `sync_decompress` and boolean values, `dir_ra_bytes` round trips, `drop_caches` values 1 through 3, invalid `drop_caches` ranges, and acceleration-engine parsing when `CONFIG_EROFS_FS_ZIP_ACCEL` is enabled.

# sources/distributed-fs/ceph-client/fs/erofs/xattr.c

Purpose: Implements EROFS extended attribute lookup, listing, long-prefix tables, POSIX ACL retrieval, xattr-name filtering, and optional inode fingerprint extraction for page-cache sharing.

Important APIs, types, and functions: `struct erofs_xattr_iter` carries the metadata buffer, current on-disk position, destination buffer, lookup key, and dentry context. `erofs_init_inode_xattrs()` lazily reads the per-inode xattr ibody header and shared xattr ID array. `erofs_xattr_iter_inline()` scans inline xattr entries; `erofs_xattr_iter_shared()` scans shared entries from the global xattr block area. `erofs_getxattr()` and `erofs_listxattr()` are the primary VFS-facing operations. `erofs_xattr_prefixes_init()` loads long-prefix descriptors at mount time, while `erofs_xattr_prefixes_cleanup()` frees them. Optional `erofs_get_acl()`, `erofs_inode_has_noacl()`, and `erofs_xattr_fill_inode_fingerprint()` support ACL and page-cache-share configurations.

Control flow: First access to an inode's xattrs calls `erofs_init_inode_xattrs()`. It returns `-ENODATA` if no xattrs exist, otherwise serializes initialization with `EROFS_I_BL_XATTR_BIT`, validates `xattr_isize` and shared-count bounds, reads `h_name_filter`, allocates `xattr_shared_xattrs`, fills shared IDs, then publishes initialized fields with an `smp_mb()` before setting `EROFS_I_EA_INITED_BIT`. Lookup uses the optional xattr-name Bloom-style filter to skip impossible names, then scans inline entries and falls back to shared entries. Each entry validates index/long-prefix infix/name length, compares names across block boundaries, and either reports value length, copies the value, or returns `-ENODATA`. Listing builds full VFS xattr names from base prefixes, optional long-prefix infixes, and entry names while enforcing caller buffer size.

State and persistence behavior: On-disk state includes per-inode inline xattr areas, shared xattr references, global shared xattr entries, and optional long-prefix metadata. Runtime state is cached per inode in `xattr_name_filter`, `xattr_shared_count`, and `xattr_shared_xattrs`, guarded by inode flag bits. Superblock-level `xattr_prefixes` stores heap-allocated prefix records until unmount. Data remains read-only; mutation paths only allocate/free caches and produce ACL/fingerprint objects.

Dependencies and integration points: Installs handlers through `erofs_xattr_handlers` for user, trusted, and optional security namespaces. Uses VFS xattr handler helpers, Linux capabilities for trusted listing, POSIX ACL conversion, `xxhash` filtering, metadata-buffer helpers from EROFS core, metabox/packed-inode selection, and optional page-cache-sharing fingerprint fields. `super.c` installs the handler array and initializes prefix tables after mount.

Risks: On-disk bounds checks are critical: malformed `xattr_isize`, shared counts, long-prefix indices, and entry sizes can otherwise overrun metadata. Lazy initialization relies on memory barriers and bit locks; missing the barrier can expose partially filled per-inode fields. The xattr filter is inverted by format convention, so false rejection would hide real attributes. Listing silently skips unsupported or unauthorized prefixes, which is correct but can mask malformed long-prefix indices. Fingerprint extraction treats unexpected value lengths as corruption.

Test signals: Cover inodes with no xattrs, inline-only xattrs, shared-only xattrs, cross-block names/values, long-prefix xattrs, unknown long-prefix IDs, xattr-name filter hits and misses, buffer-size probes versus `-ERANGE`, user-xattr mount option disabled, trusted xattrs with and without `CAP_SYS_ADMIN`, POSIX ACL access/default retrieval, malformed shared counts and entry sizes, metabox/packed prefix storage, and inode-share fingerprint success and corruption cases.

# sources/distributed-fs/ceph-client/fs/erofs/xattr.h

Purpose: Declares the EROFS xattr, ACL, and inode-fingerprint interfaces consumed by the rest of the filesystem while providing no-op fallbacks when xattr or ACL support is not compiled in.

Important APIs, types, and functions: With `CONFIG_EROFS_FS_XATTR`, it exports `erofs_xattr_handlers`, `erofs_xattr_prefixes_init()`, `erofs_xattr_prefixes_cleanup()`, and `erofs_listxattr()`. Without xattr support, prefix init/cleanup become inline no-ops, while `erofs_listxattr` and `erofs_xattr_handlers` are defined as `NULL` so VFS setup can remain simple. With `CONFIG_EROFS_FS_POSIX_ACL`, it declares `erofs_get_acl()`; otherwise the macro resolves to `NULL`. It also declares `erofs_xattr_fill_inode_fingerprint()` and `erofs_inode_has_noacl()`.

Control flow: `super.c` includes this header and unconditionally assigns `sb->s_xattr = erofs_xattr_handlers`, calls xattr-prefix init/cleanup around mount lifetime, and relies on compile-time fallbacks to do the right thing when features are disabled. Inode operation tables can similarly use `erofs_get_acl` as either a function pointer or `NULL`.

State and persistence behavior: The header owns no state. Its main persistence impact is compile-time feature selection: enabling xattrs adds runtime superblock prefix tables and per-inode xattr caches from `xattr.c`; disabling xattrs removes those behaviors without changing call sites.

Dependencies and integration points: Includes `internal.h`, POSIX ACL xattr definitions, and VFS xattr declarations. It is a small but important integration contract between EROFS superblock setup, inode operations, xattr implementation, and optional page-cache sharing.

Risks: The unconditional declarations for fingerprint/noacl helpers require compatible stubs or definitions elsewhere for configurations that disable the underlying feature. Macro-to-NULL fallbacks are convenient, but call sites must not call them as real functions when the feature is disabled. Any signature drift between this header and `xattr.c` would break multiple mount and inode-operation paths.

Test signals: Build matrix coverage is the key signal: xattrs on/off, POSIX ACL on/off, security xattrs on/off, and page-cache sharing on/off. Runtime smoke tests should mount with `user_xattr`, `nouser_xattr`, `acl`, and `noacl` under supported configurations and verify that disabled-feature configurations still mount and expose no xattr handlers.

# sources/distributed-fs/ceph-client/fs/erofs/zdata.c

Purpose: Implements compressed EROFS data I/O: pcluster allocation and reuse, managed compressed-page caching, read_folio/readahead frontend scanning, BIO submission, decompression queue dispatch, synchronous/asynchronous worker execution, and pcluster shrink/reclaim hooks.

Important APIs, types, and functions: `struct z_erofs_pcluster` represents one compressed physical cluster with lockref lifetime, physical position, algorithm, input/output offsets, compressed bvecs, output bvec list, and state flags. `struct z_erofs_frontend` builds a chain of pclusters for a read. `struct z_erofs_decompressqueue` tracks a pcluster chain plus pending BIO count. `z_erofs_init_subsystem()` initializes decompressors, pcluster slab pools, and the workqueue; `z_erofs_init_super()` creates the managed compressed-cache inode and XArray. `z_erofs_scan_folio()`, `z_erofs_pcluster_begin()`, `z_erofs_submit_queue()`, `z_erofs_runqueue()`, `z_erofs_decompress_pcluster()`, `z_erofs_read_folio()`, and `z_erofs_readahead()` are the core read path.

Control flow: A page-cache read enters `z_erofs_read_folio()` or `z_erofs_readahead()`, resolves the real inode, expands approximate readmore windows, and scans folios from logical end toward start. `z_erofs_scan_folio()` maps the logical range with `z_erofs_map_blocks_iter()`, handles fragments and holes immediately, or starts/continues a pcluster. `z_erofs_pcluster_begin()` finds an existing pcluster in `managed_pslots` or registers a new one, binds cached compressed folios, and prepares output bvec iteration. `z_erofs_attach_page()` records output pages or in-place input candidates. After scanning, `z_erofs_runqueue()` splits chains into bypass and submit queues, submits BIOs for compressed pages that are not already cached, handles inline metadata pclusters directly, and either waits for completion for synchronous decompression or schedules workqueue/per-CPU kthread execution. `z_erofs_decompress_pcluster()` parses output and input bvecs, invokes the selected decompressor, finishes all folios, releases short-lived pages, resets pcluster state, and drops pcluster references.

State and persistence behavior: Persistent inputs are compressed extents mapped by `zmap.c`. Runtime state includes slab-allocated pclusters keyed by physical address in `sbi->managed_pslots`, a managed cache inode for compressed folios, per-request page pools, workqueues, optional per-CPU workers, and global shrink accounting. Pclusters can outlive a single read when cached folios keep them reclaimable; they are eventually removed by direct refcount release or shrinker scans. Inline metadata pclusters are not inserted into the managed XArray and are freed immediately after decompression.

Dependencies and integration points: Depends on `compress.h` decompressor tables, `z_erofs_map_blocks_iter()` from `zmap.c`, device mapping and BIO submission helpers for block, fscache, and file-backed modes, online-folio accounting helpers, PSI memstall instrumentation, optional CPU hotplug/kthread workers, managed-cache shrinkers from `zutil.c`, tracepoints, and VFS address-space operations via `z_erofs_aops`.

Risks: This file is concurrency-heavy. Pcluster reuse combines mutexes, lockrefs, XArray locking, RCU freeing, and folio private pointers. In-place decompression overlaps compressed and output pages and must correctly detect invalidated or managed folios. Error paths must end every online folio exactly once and avoid leaving pcluster `next` links or bvec pages stale. Synchronous decompression policy changes dynamically after atomic-context scheduling. Cache reclaim must not detach folios still needed by in-flight decompression.

Test signals: Test compressed reads with cold cache, warm managed cache, readahead, partial folio reads, fragments, holes, inline tailpacking, metadata-compressed input, file-backed/fscache/block backends, allocation failure fallbacks, BIO I/O errors, decompressor corruption errors, concurrent reads of the same pcluster, shrinker races, CPU hotplug with per-CPU workers, sysfs `sync_decompress` modes, and invalidation/eviction while decompression is active.

# sources/distributed-fs/ceph-client/fs/erofs/zmap.c

Purpose: Maps compressed EROFS logical file offsets to compressed physical extents, decompressed lengths, fragment/inline-tail locations, and compression algorithm formats. It feeds both actual compressed reads and FIEMAP/iomap reporting.

Important APIs, types, and functions: `struct z_erofs_maprecorder` caches current logical cluster metadata during a map operation. `z_erofs_load_full_lcluster()` reads full lcluster indexes. `z_erofs_load_compact_lcluster()` decodes compact 2-byte/4-byte packed indexes. `z_erofs_extent_lookback()` resolves NONHEAD entries back to their HEAD cluster. `z_erofs_get_extent_compressedlen()` and `z_erofs_get_extent_decompressedlen()` determine physical and logical extent lengths. `z_erofs_map_blocks_fo()` maps legacy full/compact index formats; `z_erofs_map_blocks_ext()` maps newer extent records. `z_erofs_fill_inode()` lazily initializes compressed-inode fields, and `z_erofs_map_blocks_iter()` is the exported iterator used by read and iomap paths.

Control flow: `z_erofs_map_blocks_iter()` handles post-EOF holes, then ensures compressed metadata has been initialized with `z_erofs_fill_inode()`. Initialization reads the compressed map header, detects fragment-only files, records lcluster bits, advice flags, algorithms, extents, fragment offsets, inline pcluster sizes, and tail extent metadata. Mapping then uses either extent-record binary search/iteration or full/compact lcluster decoding. For lcluster formats, it loads the cluster covering the requested offset, looks back from NONHEAD records to the pcluster head when needed, computes logical length, recognizes tailpacking and fragment pclusters, computes physical address and compressed length, chooses algorithm format, and optionally expands to full decompressed extent length for FIEMAP or readmore. Final sanity checks validate algorithm support, compressed/plain length relationships, max pcluster limits, and 48-bit physical address bounds.

State and persistence behavior: The source of truth is immutable on-disk compressed map metadata following the inode and xattr area. Runtime state is lazily cached in `struct erofs_inode`: `z_advise`, `z_lclusterbits`, `z_algorithmtype[]`, `z_fragmentoff`, `z_idata_size`, `z_tailextent_headlcn`, and `z_extents`. Initialization is guarded by `EROFS_I_BL_Z_BIT` and published via `EROFS_I_Z_INITED_BIT` with memory barriers.

Dependencies and integration points: Used by `zdata.c` for reads and by `z_erofs_iomap_report_ops` for extent reporting. It depends on EROFS metadata-buffer helpers, on-disk compression constants, unaligned little-endian decoding, tracepoints, inode metabox selection, and superblock feature flags such as big pcluster, fragments, 48-bit addressing, and available compression algorithms.

Risks: Compact-index decoding is dense and sensitive to bitfield layout, special last-entry encoding, and big-pcluster CBLKCNT rules. Corrupt images can supply bogus lookback distances, cluster offsets, compressed block counts, fragment offsets, or extent records. Lazy inode initialization must not expose partially initialized compression fields. Sanity checks are the last line of defense before `zdata.c` submits I/O, so missing a check can become out-of-bounds reads or decompressor misuse.

Test signals: Cover full indexes, compact 4-byte and compact 2-byte indexes, HEAD/NONHEAD lookback, HEAD1/HEAD2 algorithms, PLAIN shifted/interlaced extents, big pclusters, fragments, ztailpacking, extent-record formats with and without high 32-bit fields, FIEMAP post-EOF handling, readmore expansion, unsupported algorithms, length corruption, invalid lookback distances, invalid compact bit patterns, and 48-bit physical address overflow.

# sources/distributed-fs/ceph-client/fs/erofs/zutil.c

Purpose: Provides shared utilities for compressed EROFS: global temporary decompression buffers, a reserved page pool, pagepool allocation/release helpers, and the global shrinker that reclaims compressed pcluster cache entries across mounted superblocks.

Important APIs, types, and functions: `struct z_erofs_gbuf` owns a spinlock, vmapped buffer, backing page array, and page count. `z_erofs_gbuf_init()`, `z_erofs_gbuf_growsize()`, `z_erofs_get_gbuf()`, `z_erofs_put_gbuf()`, and `z_erofs_gbuf_exit()` manage per-CPU-like global buffers. `__erofs_allocpage()` and `erofs_release_pages()` allocate from a request pagepool, optional reserved pool, or the page allocator. `erofs_shrinker_register()` and `erofs_shrinker_unregister()` add/remove mounted superblocks from the shrinker list. `erofs_init_shrinker()` installs the kernel shrinker, whose count and scan callbacks are `erofs_shrink_count()` and `erofs_shrink_scan()`.

Control flow: Module init allocates the global buffer descriptors, initializes spinlocks, and registers the shrinker. Buffer growth is serialized by a mutex, allocates pages for each buffer, vmaps them, then swaps each buffer under its spinlock; old vmaps are released after the pointer swap. A decompressor caller disables migration, selects a buffer by CPU modulo buffer count, locks it, and receives the pointer only if large enough. Page allocation first consumes a caller pagepool, then the reserved global pool if allowed, then `alloc_page()`. Releasing pages preferentially refills the reserved pool. Mounted superblocks are added to a global list; shrink scans iterate fairly, trylock each superblock's unmount mutex, and call `z_erofs_shrink_scan()` until enough pclusters are freed.

State and persistence behavior: All state is runtime-only. Module parameters `global_buffers` and `reserved_pages` size the global buffer/reserved-page behavior. `erofs_global_shrink_cnt` tracks globally reclaimable pcluster objects. `erofs_sb_list`, `shrinker_run_no`, and each superblock's `shrinker_run_no` coordinate fair scanning. Superblocks remain on the shrink list only while mounted.

Dependencies and integration points: Supports decompressor implementations that need global work buffers, `zdata.c` pagepool and pcluster reclaim, sysfs `drop_caches`, superblock mount/unmount in `super.c`, and the kernel shrinker API. Uses vmalloc/vmap, bulk page allocation, migration disabling, spinlocks, mutexes, and list iteration.

Risks: `z_erofs_get_gbuf()` assumes a nonzero global-buffer count and pairs migration disable with spinlock ownership; misuse can deadlock or corrupt per-CPU buffer selection. Buffer growth has partial-allocation cleanup complexity. Reserved pages are shared globally, so accounting bugs can leak or double-put pages. Shrinker unregister loops until the superblock XArray is empty; if pcluster references never drop, unmount can spin with reschedules. Shrinker scans must not race with unmount list removal.

Test signals: Validate module parameters at zero and nonzero values, buffer growth before/after decompression starts, concurrent `get_gbuf`/`put_gbuf`, allocation failure during growth, reserved-page refill/drain, pagepool LIFO behavior, global shrink count transitions, sysfs drop-caches invoking shrink, unmount with cached pclusters, and concurrent shrink scans across multiple mounted EROFS filesystems.

# sources/distributed-fs/ceph-client/fs/eventfd.c

Purpose: Implements the Linux `eventfd` counter file descriptor, including syscall creation, read/write semantics, poll readiness, kernel-side signaling APIs, waitqueue integration, fdinfo reporting, and context reference management.

Important APIs, types, and functions: `struct eventfd_ctx` contains a kref, wait queue, 64-bit counter, flags, and an IDA-assigned id. `eventfd_signal_mask()` is the exported non-sleeping kernel producer API. `eventfd_ctx_do_read()` consumes either one token in semaphore mode or the full count. `eventfd_ctx_remove_wait_queue()` atomically removes a wait entry and drains the counter for in-kernel users. `eventfd_read()`, `eventfd_write()`, and `eventfd_poll()` implement file operations. `eventfd_fget()`, `eventfd_ctx_fdget()`, and `eventfd_ctx_fileget()` validate and pin eventfd objects for other kernel subsystems. `do_eventfd()` backs `eventfd2()` and legacy `eventfd()`.

Control flow: Creation validates flags, allocates and initializes the context, creates an anonymous inode file with `eventfd_fops`, assigns an ID, and publishes the fd. Writes copy one `u64` from userspace, reject `ULLONG_MAX`, wait unless nonblocking when the counter lacks space, add to `count`, and wake readers with `EPOLLIN`. Reads wait unless nonblocking when `count` is zero, drain according to semaphore mode, wake writers with `EPOLLOUT`, then copy the result to userspace. Poll registers with the waitqueue and reports readable, writable, and overflow/error states based on a lock-ordered counter read. Release wakes waiters with `EPOLLHUP` and drops the context kref.

State and persistence behavior: The only durable per-fd state is the in-memory counter and flags; it persists while the anonymous file or exported context references exist. All counter mutations happen under `ctx->wqh.lock`. The IDA id is used for fdinfo diagnostics and is freed when the final kref drops. `current->in_eventfd` guards against recursive waitqueue wakeups during eventfd signaling and read/write wakeups.

Dependencies and integration points: Exports GPL APIs used by kernel producers such as AIO, io_uring, KVM, and other notification paths. Integrates with anon inodes, fd allocation helpers, poll/epoll waitqueues, proc fdinfo, user-copy helpers, krefs, and IDA allocation.

Risks: Wakeup recursion can deadlock or overflow stacks if callers signal eventfds from nested wake paths without checking `eventfd_signal_allowed()`. Counter saturation has special semantics: kernel signaling may leave the counter at `ULLONG_MAX` and poll reports `EPOLLERR`, while userspace writes reject `ULLONG_MAX` and block before overflow. Poll relies on waitqueue locking barriers to avoid missed wakeups. Copy-to-user failures after draining the counter are observable and must match ABI expectations.

Test signals: Cover `eventfd` and `eventfd2` flag validation, semaphore versus normal reads, blocking and nonblocking reads/writes, write rejection of `ULLONG_MAX`, near-overflow behavior and `EPOLLERR`, poll readiness transitions, epoll integration, fdinfo count/id/semaphore output, exported fdget/fileget error paths, release `EPOLLHUP`, signal interruption, NOWAIT reads, and recursive signal warning behavior.

# sources/distributed-fs/ceph-client/fs/eventpoll.c

Purpose: Implements Linux epoll: creation of epoll file descriptors, interest-set management, wakeup callbacks attached to target files, ready-list delivery to userspace, nested-epoll loop/path checks, file-release cleanup, optional busy-poll controls, and proc/sysctl observability.

Important APIs, types, and functions: `struct eventpoll` owns the mutex, wait queues, ready list, overflow list, RB tree of interests, watched user, owning file, reverse refs, refcount, wakeup source, and optional busy-poll parameters. `struct epitem` represents one watched file/fd pair with RB node, ready-list link, per-file hlist link, waitqueue registrations, event mask/data, and optional wakeup source. `ep_poll_callback()` is installed on target wait queues. `ep_insert()`, `ep_modify()`, and `ep_remove()` implement control operations. `ep_send_events()` and `ep_poll()` implement event transfer and waiting. `do_epoll_ctl()`, `do_epoll_wait()`, `do_epoll_pwait()`, and syscall wrappers expose the ABI. `eventpoll_release_file()` cleans up watches when target files close.

Control flow: `epoll_create*()` allocates `eventpoll`, initializes locks/lists/RB tree, creates an anonymous inode file, and publishes the fd. `epoll_ctl(ADD)` validates the epoll fd and target pollability, checks EPOLLEXCLUSIVE constraints, locks the target epoll graph when needed, prevents cycles and excessive wakeup paths, allocates an `epitem`, attaches it to the target file's `f_ep` hlist, inserts it into the epoll RB tree, registers poll waitqueue callbacks, and queues it ready if the target is already readable/writable. Wakeups from target files enter `ep_poll_callback()`, filter by interest mask, queue the item on `rdllist` or `ovflist`, manage wakeup sources, and wake epoll waiters. `epoll_wait()` first tries ready delivery, then optionally busy-polls, installs an exclusive wait entry under `ep->lock`, sleeps with timeout slack, and retries until events, timeout, or signal. `ep_send_events()` steals `rdllist`, sets `ovflist` active to catch concurrent callbacks, re-polls each item, copies events to userspace, applies ONESHOT/edge/level-trigger rules, and merges overflow events back.

State and persistence behavior: Interest state persists in the epoll anonymous file until explicit `DEL`, epoll fd release, or watched file release. The RB tree is protected by `ep->mtx`; ready and overflow lists are protected by `ep->lock`. Target files maintain reverse links through `file->f_ep` so close can remove all epoll watches. `ep->refcount` keeps eventpoll objects alive while epitems reference them. Per-user watch counts enforce `max_user_watches`, initialized from low memory and exposed via sysctl.

Dependencies and integration points: Integrates with VFS `->poll`, waitqueue callbacks, anon inodes, fd helpers, user-copy helpers, signals/timeouts, proc fdinfo, sysctl, RCU, SLAB_TYPESAFE_BY_RCU file lifetime rules, wakeup sources for `EPOLLWAKEUP`, capabilities, optional network busy poll and NAPI IRQ control, `KCMP` target lookup, and compat syscall variants.

Risks: Lock ordering is central: `epnested_mutex`, then `ep->mtx`, then `ep->lock`; callback paths can run in IRQ context and cannot sleep. Ready-list transfer relies on `ovflist` to avoid lost events while copying to userspace. Nested epoll needs both loop detection and reverse path limits to avoid deadlocks and wakeup storms. File teardown races require careful `file_ref_get()` and reverse-link removal. `POLLFREE` requires RCU-safe waitqueue handling. ONESHOT, EPOLLET, EPOLLEXCLUSIVE, and EPOLLWAKEUP each alter wakeup semantics and are easy to regress.

Test signals: Cover add/mod/del duplicate and missing fd cases, self-add rejection, nested epoll cycles and depth limit, reverse path limit, level-trigger requeue, edge-trigger one-shot delivery, ONESHOT disable and MOD rearm, EPOLLEXCLUSIVE validation and wake-one behavior, EPOLLWAKEUP capability filtering, concurrent close of watched files, POLLFREE waitqueue destruction, userspace copy faults during delivery, timeout and signal behavior for wait/pwait/pwait2, compat syscalls, fdinfo listing, sysctl watch limit enforcement, busy-poll ioctls and permission checks, and stress with many watched descriptors.
