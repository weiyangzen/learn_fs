# sources/compression/zstd/lib/legacy/zstd_v01.c

Purpose: self-contained decoder implementation for Zstandard legacy frame format v0.1.x. It exists so the legacy dispatch layer can decode the oldest supported zstd streams without depending on current-format internals. The file embeds historical FSE, Huff0, bitstream, block, sequence, frame-size, one-shot decompression, and streaming decompression logic for this format generation.

Important APIs/types/functions: exported entry points are `ZSTDv01_isError()`, `ZSTDv01_decompressDCtx()`, `ZSTDv01_decompress()`, `ZSTDv01_findFrameSizeInfoLegacy()`, `ZSTDv01_resetDCtx()`, `ZSTDv01_createDCtx()`, `ZSTDv01_freeDCtx()`, `ZSTDv01_nextSrcSizeToDecompress()`, and `ZSTDv01_decompressContinue()`. Internally, the decoder is built around `FSE_DStream_t`, `FSE_DState_t`, `FSE_decode_t`, `HUF_DElt`, `blockProperties_t`, `seq_t`, `seqState_t`, and `ZSTDv01_Dctx_s`/`dctx_t`. Key helpers include `FSE_readNCount()`, `FSE_buildDTable()`, `FSE_decompress_usingDTable_generic()`, `HUF_readDTable()`, `HUF_decompress_usingDTable()`, `ZSTDv01_getcBlockSize()`, `ZSTDv01_decodeLiteralsBlock()`, `ZSTDv01_decodeSeqHeaders()`, `ZSTD_decodeSequence()`, `ZSTD_execSequence()`, `ZSTD_decompressSequences()`, and `ZSTD_decompressBlock()`.

Control flow: one-shot decode starts in `ZSTDv01_decompress()`, initializes a stack context with `base = dst`, and calls `ZSTDv01_decompressDCtx()`. The frame decoder requires the 4-byte big-endian v0.1 magic, then iterates 3-byte block headers until a `bt_end` block. Each compressed block first decodes a literals sub-block, then sequence headers, then an FSE-coded bitstream of sequences. Sequence execution copies literals, resolves repeat offsets through `prevOffset`, and copies matches from the current history base. Raw blocks are direct `memcpy()`. Top-level RLE blocks return `ERROR(GENERIC)`, while RLE literals and RLE FSE sequence tables are supported. Frame-size discovery mirrors block walking without decompression and reports `nbBlocks * BLOCKSIZE` as the decompressed bound.

State and persistence: the reusable context stores FSE decode tables for LL, offset, and ML symbols, plus streaming fields `previousDstEnd`, `base`, `expected`, `bType`, and `phase`. `ZSTDv01_decompressContinue()` is a strict pull state machine: phase 0 consumes exactly the frame header, phase 1 consumes exactly a block header, and phase 2 consumes exactly the announced block payload. If caller-provided output is contiguous with the previous output end, matches may refer to prior blocks; otherwise `base` is reset to the new destination. No dictionary state is accepted and no durable state is persisted outside the caller-owned context.

Dependencies and integration points: includes `zstd_v01.h`, `../common/compiler.h`, and `../common/error_private.h`, while carrying its own historical FSE/HUF/MEM-compatible code. `sources/compression/zstd/lib/legacy/zstd_legacy.h` includes this header when `ZSTD_LEGACY_SUPPORT <= 1`, recognizes `ZSTDv01_magicNumberLE`, dispatches version 1 frames to `ZSTDv01_decompress()`, and calls `ZSTDv01_findFrameSizeInfoLegacy()` for legacy frame-size probing. Build project files and CMake legacy lists compile this file as part of the zstd legacy library.

Risks: this is safety-sensitive decompression code that manually handles untrusted lengths, pointer arithmetic, overlapping copies, and reverse bitstreams. Notable risk points include comments around 32-bit address-space overflow, match underflow checks, `ZSTD_wildcopy()` copying past requested lengths by design, v0.1-specific literal layout reading bits from `ip[-3]`, and the need for exact `srcSize` accounting. Error-code conversion is mixed: historical FSE errors are sometimes collapsed to generic zstd errors. Top-level RLE block rejection is intentional in code but can surprise compatibility callers. Streaming callers must obey exact `nextSrcSizeToDecompress()` sizes and provide output buffers that preserve block history when cross-block matches are expected.

Test signals: useful tests include golden v0.1 frames covering compressed, raw, end, compressed literals, raw literals, RLE literals, raw/RLE/FSE sequence tables, repeat-offset cases, multi-block history, non-contiguous streaming output, truncated headers, wrong magic, malformed FSE/HUF tables, too-small destinations, top-level RLE block rejection, and frame-size probing on complete and incomplete frames. Fuzz tests should emphasize block header sizes, dumps lengths, max LL/ML extension paths, offset underflow, and 32-bit overflow-sensitive pointer math.

# sources/compression/zstd/lib/legacy/zstd_v01.h

Purpose: public legacy header for decoding Zstandard v0.1.x frames. It exposes the one-shot, frame-size, error-test, context, and streaming APIs implemented in `zstd_v01.c`, plus the v0.1 magic constants used by the legacy dispatcher.

Important APIs/types/functions: declares `ZSTDv01_decompress()`, `ZSTDv01_findFrameSizeInfoLegacy()`, `ZSTDv01_isError()`, opaque `ZSTDv01_Dctx`, `ZSTDv01_createDCtx()`, `ZSTDv01_freeDCtx()`, `ZSTDv01_decompressDCtx()`, `ZSTDv01_resetDCtx()`, `ZSTDv01_nextSrcSizeToDecompress()`, and `ZSTDv01_decompressContinue()`. It defines `ZSTDv01_magicNumber` as `0xFD2FB51E` for the v0.1 big-endian stream value and `ZSTDv01_magicNumberLE` as `0x1EB52FFD` for little-endian detection by `zstd_legacy.h`.

Control flow: consumers either call `ZSTDv01_decompress()` with the exact compressed frame size and a destination capacity at least as large as the expected decompressed size, or create/reset a `ZSTDv01_Dctx` and alternate `ZSTDv01_nextSrcSizeToDecompress()` with `ZSTDv01_decompressContinue()`. The streaming contract reports zero-byte progress for headers and positive sizes for decoded block payloads. `ZSTDv01_findFrameSizeInfoLegacy()` scans a frame and returns the compressed byte count plus a decompressed upper bound through output parameters.

State and persistence: the header intentionally keeps `ZSTDv01_Dctx` opaque. Context allocation, reset, and free are owned by the caller, but all internal decode state is hidden in `zstd_v01.c`. The API carries no dictionary parameter and exposes no stable serialized state. The frame-size helper assumes non-NULL `cSize` and `dBound` pointers.

Dependencies and integration points: includes only `<stddef.h>` for `size_t` and uses `extern "C"` guards for C++ consumers. It is conditionally included by `zstd_legacy.h` when the build enables support down to v0.1. That dispatcher uses the magic macros for version detection, the one-shot function for legacy decompression, and the frame-size helper for legacy frame probing.

Risks: the comments contain copy/paste references to `ZSTDv01_isError()` in places that matter for v0.1 but mirror other legacy headers; callers still must use the matching `ZSTDv01_isError()` declared here. The API requires exact compressed sizes and caller-allocated output capacity, so misuse tends to surface as generic error codes rather than partial decompression. Streaming misuse is easy if callers ignore the exact requested source size or assume decoded output is produced for every call.

Test signals: compile/link tests should verify C and C++ inclusion, opaque context lifecycle, one-shot decode, streaming decode parity with one-shot decode, magic-number routing through `ZSTD_isLegacy()`, and frame-size helper behavior on valid, truncated, and wrong-prefix inputs.

# sources/compression/zstd/lib/legacy/zstd_v02.c

Purpose: self-contained decoder implementation for Zstandard legacy frame format v0.2.x. It embeds period-correct memory, bitstream, error, FSE, Huff0, and zstd block/sequence/frame logic, then exposes a thin `ZSTDv02_*` wrapper API. Compared with v0.1, this file reflects the newer little-endian v0.2 frame magic, a separate `BIT_*` bitstream layer, v0.2 literal block packing, a persistent literal buffer, and adaptive Huffman decoder selection.

Important APIs/types/functions: exported wrappers are `ZSTDv02_findFrameSizeInfoLegacy()`, `ZSTDv02_isError()`, `ZSTDv02_decompress()`, `ZSTDv02_createDCtx()`, `ZSTDv02_freeDCtx()`, `ZSTDv02_resetDCtx()`, `ZSTDv02_nextSrcSizeToDecompress()`, and `ZSTDv02_decompressContinue()`. Core internal types include `BIT_DStream_t`, `FSE_DState_t`, `FSE_decode_t`, `HUF_DEltX2`, `HUF_DEltX4`, `HUF_DDescX6`, `HUF_DSeqX6`, `blockProperties_t`, `seq_t`, `seqState_t`, and `struct ZSTDv02_Dctx_s`. Important helpers include `MEM_readLE*()`, `BIT_initDStream()`, `FSE_readNCount()`, `FSE_buildDTable()`, `HUF_readStats()`, `HUF_decompress4X2()`, `HUF_decompress4X4()`, `HUF_decompress4X6()`, `HUF_decompress()`, `ZSTD_getcBlockSize()`, `ZSTD_decodeLiteralsBlock()`, `ZSTD_decodeSeqHeaders()`, `ZSTD_decodeSequence()`, `ZSTD_execSequence()`, `ZSTD_decompressSequences()`, `ZSTD_decompressBlock()`, and `ZSTD_decompressDCtx()`.

Control flow: public `ZSTDv02_decompress()` delegates to internal `ZSTD_decompress()`, which creates a stack `ZSTD_DCtx`, sets `base = dst`, and calls `ZSTD_decompressDCtx()`. Frame parsing checks little-endian `ZSTD_magicNumber` (`0xFD2FB522`), then loops over 3-byte block headers. Compressed blocks decode literals into either `dctx->litBuffer` or a direct source pointer, decode the sequence tables, initialize the sequence bitstream, execute matches, and append the final literal run. Literal block mode is encoded in the low two bits and supports compressed, raw, and RLE literal forms. Raw frame blocks copy through, end blocks terminate, and top-level RLE blocks return `ERROR(GENERIC)`.

State and persistence: `struct ZSTDv02_Dctx_s` stores LL/offset/ML FSE tables, streaming fields `previousDstEnd`, `base`, `expected`, `bType`, and `phase`, plus `litPtr`, `litSize`, and a `BLOCKSIZE + 8` literal buffer used to support wildcopy margins. Streaming decode follows the same strict three-phase pull contract as v0.1: exact frame-header size, exact block-header size, then exact block-content size. Cross-block match history depends on contiguous output; non-contiguous output resets `base` to the new destination. There is no dictionary persistence or external state serialization.

Dependencies and integration points: includes `zstd_v02.h`, `../common/compiler.h`, and `../common/error_private.h`, but most needed support code is embedded directly. `zstd_legacy.h` conditionally includes this header when `ZSTD_LEGACY_SUPPORT <= 2`, recognizes `ZSTDv02_magicNumber`, routes version 2 frames to `ZSTDv02_decompress()`, and calls `ZSTDv02_findFrameSizeInfoLegacy()`. Build and IDE project files list this source alongside the other legacy decoders.

Risks: decompression is dominated by manual bounds checks around attacker-controlled streams. Risk areas include reverse bitstream reload states, Huffman jump-table length arithmetic, direct raw-literal references into the input, wildcopy overreads guarded by the literal buffer margin, sequence offset validation, and pointer arithmetic comments noting overflow hazards. The adaptive Huffman selector uses a timing table to choose X2/X4/X6 table layouts, so regressions can be algorithm-specific. The code masks RLE offset table symbols with `MaxOff`, which treats out-of-range data as corrupted later rather than rejecting at the table header point. Top-level RLE blocks are still unsupported even though RLE literals and RLE FSE tables exist.

Test signals: golden v0.2 corpus tests should cover all literal modes, all Huffman decoder choices, raw and compressed frame blocks, multi-block history, repeat offsets, long LL/ML dump paths, frame-size probing, streaming parity, and non-contiguous streaming output. Negative tests should include bad little-endian magic, truncated block headers, bad literal sizes, malformed Huffman stats, jump-table overflows, corrupted FSE normalized counts, destination-too-small cases, impossible offsets, top-level RLE block rejection, and exact end-of-bitstream validation. Fuzzing should focus on compressed literal headers and sequence dumps because those drive most pointer-sensitive branches.

# sources/compression/zstd/lib/legacy/zstd_v02.h

Purpose: public legacy header for decoding Zstandard v0.2.x frames. It presents the same API shape as the v0.1 header while naming the v0.2-specific entry points and exposing the v0.2 magic number used by legacy format detection.

Important APIs/types/functions: declares `ZSTDv02_decompress()`, `ZSTDv02_findFrameSizeInfoLegacy()`, `ZSTDv02_isError()`, opaque `ZSTDv02_Dctx`, `ZSTDv02_createDCtx()`, `ZSTDv02_freeDCtx()`, `ZSTDv02_decompressDCtx()`, `ZSTDv02_resetDCtx()`, `ZSTDv02_nextSrcSizeToDecompress()`, and `ZSTDv02_decompressContinue()`. It defines `ZSTDv02_magicNumber` as `0xFD2FB522`.

Control flow: callers can use one-shot decompression by providing an exact compressed size and a preallocated destination, or use the streaming API by creating/resetting a context and alternating source-size queries with continuation calls. Header and block-header calls can return zero decoded bytes by design. Frame-size probing is exposed through output parameters, returning the consumed compressed size and a conservative decompressed bound.

State and persistence: `ZSTDv02_Dctx` is opaque and allocated/freed through the header’s lifecycle functions. Internal state includes history tracking and literal buffering, but the header exposes only the streaming pull contract. No dictionary argument or persisted state handle is available. `ZSTDv02_findFrameSizeInfoLegacy()` assumes non-NULL result pointers.

Dependencies and integration points: includes `<stddef.h>` and wraps declarations in `extern "C"` for C++ compatibility. `zstd_legacy.h` includes it when support down to v0.2 is enabled, uses the magic constant to return legacy version 2, dispatches decompression to `ZSTDv02_decompress()`, and uses the frame-size helper during legacy frame scanning.

Risks: documentation comments contain copy/paste references to testing failures with `ZSTDv01_isError()` even though this header declares `ZSTDv02_isError()`. Consumers should use the version-matched error predicate. As with v0.1, the API depends on exact source chunk sizes in streaming mode and sufficient destination capacity in both streaming and one-shot modes. The declared `ZSTDv02_decompressDCtx()` is part of the advanced surface, so ABI users can bind to the context-based path directly.

Test signals: compile/link coverage should include C and C++ consumers, one-shot decompression, context lifecycle, direct context decompression, streaming decompression, frame-size helper routing, and magic-number detection through the legacy dispatcher. Header-level regression tests should catch accidental prototype drift because the legacy dispatcher relies on these names under `ZSTD_LEGACY_SUPPORT <= 2`.
