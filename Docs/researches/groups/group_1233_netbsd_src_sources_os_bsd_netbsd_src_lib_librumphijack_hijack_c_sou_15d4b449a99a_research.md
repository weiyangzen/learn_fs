# File Research: sources/os/bsd/netbsd-src/lib/librumphijack/hijack.c

Read completely: 2880 lines.

## Purpose
Implements `librumphijack`, an `LD_PRELOAD`/symbol-interposition layer that routes selected libc/syscall-style operations either to the host kernel or to a connected rump kernel via `librumpclient`.

## Main Responsibilities
- Builds a dual syscall table mapping each intercepted operation to both the host symbol and the `rump_sys_*` symbol resolved with `dlsym(RTLD_NEXT, ...)`.
- Parses `RUMPHIJACK` configuration for path prefix routing, blanket path routing, socket protocol-family routing, VFS operation routing, sysctl/modctl routing, and the rump fd offset.
- Classifies paths as host, rump-prefixed, or rump blanket paths, translating configured rump prefixes such as `/rump` back to rump-internal paths.
- Maintains a file descriptor namespace split: host fds must stay below `hijack_fdoff`, while rump fds are presented as `rumpfd + hijack_fdoff`.
- Tracks special `dup2()` mappings for standard descriptors 0-2 so programs can redirect stdin/stdout/stderr to rump-backed descriptors.
- Interposes common socket, file, directory, VFS, metadata, polling, process, and descriptor operations.
- Preserves rump current-working-directory and dup2 mapping state across `execve()` using internal `RUMPHIJACK__*` environment variables.

## Key Implementation Notes
- Default hijack policy is `path=/rump,socket=all:nolocal`, meaning paths under `/rump` and non-local sockets are routed to the rump kernel unless overridden.
- `rcinit()` is a constructor. It resolves all host/rump call targets, initializes the rump client, parses environment variables, sets retry policy, and restores exec-inherited state.
- The macro wrappers `FDCALL`, `PATHCALL`, `ATCALL`, and `VFSCALL` generate most simple routing functions after the hand-written special cases.
- `open()`, `socket()`, `accept()`, and `paccept()` translate newly returned descriptors into the host-visible fd namespace; host returns are checked for collisions with the rump fd range and dup2 aliases.
- `chdir()`, `fchdir()`, and NetBSD `__getcwd()` keep `pwdinrump` coherent so relative paths route to the currently selected kernel.
- `link()` and `rename()` reject cross-host/rump moves with `EXDEV`; NetBSD `linkat()` only supports a limited `AT_FDCWD` + `AT_SYMLINK_FOLLOW` case.
- `fcntl()` handles `F_DUPFD`, `F_DUPFD_CLOEXEC`, `F_CLOSEM`, and `F_MAXFD` specially because descriptor ranges span two kernels.
- `close()` notifies `librumpclient` before host close/dup2/closem paths and carefully tears down dup2 aliases for rump descriptors.
- `sendmsg()` and `recvmsg()` convert `SCM_RIGHTS` descriptors between external and raw fd values, rejecting attempts to pass descriptors belonging to the other kernel.
- `select()` is implemented on top of `pollts`/`ppoll`; mixed host+rump `poll()` splits descriptors into two vectors, runs host poll in a helper thread and rump poll in the caller, wakes the losing side with notification pipes, and merges results.
- `kevent()` rejects filters that target rump fds because split host/rump kqueue handling is not implemented.
- `mmap()` refuses `MAP_FILE` mappings from rump fds with `ENOSYS`.
- NetBSD-specific hooks cover versioned syscall names, file handles, statvfs/getvfsstat, mount/unmount, `nfssvc`, `__sysctl`, `modctl`, quota, chflags, and fsync_range where available.

## Filesystem Relevance
High. This file is the userspace bridge that lets unmodified programs access rump-kernel filesystems and VFS services through normal libc entry points. Its path and fd routing rules directly determine whether operations hit the host VFS or the rump VFS.

## Reliability Notes
- The fd namespace split relies on host fd values remaining below `hijack_fdoff`; host descriptors at or above the offset are closed and reported as `ENFILE`.
- Mixed-kernel polling is inherently approximate: whichever side wakes first can suppress activity from the other side in that call.
- `sendmsg()` mutates caller-supplied control messages when converting rump fds for send, with an in-code comment noting a safer copy-and-restore design.
- Linux support is explicitly described as lower quality than NetBSD support and omits many NetBSD-only calls.
- The intercepted symbol list is manually maintained and includes comments noting it would benefit from autogenerated synchronization with libc/rump symbols.

## Dependencies
- Internal header: `hijack.h`.
- Rump APIs: `rump/rumpclient.h`, `rump/rump_syscalls.h`, `rump/rumpuser_port.h`.
- Host libc/dynamic linker: `dlsym`, syscall-compatible libc entry points, pthreads, fd and path APIs.
- NetBSD platform headers for VFS, statvfs, file handles, kqueue, quotas, NFS service, and versioned syscall interfaces.

## Purpose
Provides an out-of-line `dlsym()` wrapper for `librumphijack` and `librumpclient` preload scenarios.

## Main Responsibilities
- Includes `rumpuser_port.h`, `<dlfcn.h>`, and `hijack.h`.
- Implements a `__noinline` `bouncer()` that calls `dlsym(handle, symbol)`.
- Implements `rumphijack_dlsym()` as a call through `bouncer()`.

## Key Implementation Notes
- The source comments say this is called from `librumpclient` when using `LD_PRELOAD` to ensure the correct `RTLD_NEXT` behavior.
- The file is intentionally compiled with `-O0` so the wrapper is not optimized into a tail call or otherwise transformed in a way that changes dynamic-linker stack semantics.
- A comment notes the extra indirection is required for PowerPC.

## Filesystem Relevance
Indirect. It makes the syscall-interposition layer robust enough to find host symbols while routing filesystem and socket calls through `hijack.c`.

## Dependencies
- `dlsym(3)` from the dynamic linker.
- Local declaration in `hijack.h`.

## Purpose
Builds `librumpuser`, the userspace support layer used by rump kernels.

## Main Responsibilities
- Disables full RELRO and sets warning level 5 by default.
- Adds the rump include path so `rumpuser.h` can be installed from `sys/rump/include/rump`.
- Selects the implementation source set based on `RUMPUSER_THREADS`: `pthread`, `none`, or `fiber`.
- For pthread mode, depends on `libpthread` and builds `rumpuser.c`, `rumpuser_pth.c`, `rumpuser_bio.c`, and `rumpuser_sp.c`.
- For no-thread mode, builds the dummy pthread implementation.
- For fiber mode, enforces `RUMP_CURLWP=hypercall` if `RUMP_CURLWP` is set, then builds fiber-specific sources.
- Always builds component, random, file, memory, error translation, and signal translation sources.
- Adds optional dynamic-loading and daemonization sources.
- Installs `rumpuser_component.h` and `rumpuser_port.h` under `/usr/include/rump`.
- Defines `LIBRUMPUSER` and `_REENTRANT`.

## Filesystem Relevance
High indirect relevance. `librumpuser` supplies the host-facing services, file/memory helpers, threading, and error/signal translation that rump filesystem kernels need to run in userspace.

## Dependencies
- `bsd.own.mk` and `bsd.lib.mk`.
- Optional `../libpthread`.
- Rump public include files from `sys/rump/include/rump`.

## Purpose
Vendored portable `install` replacement compatible with BSD-style install usage.

## Main Responsibilities
- Supports installing one file to another, multiple files into a directory, `-t DIRECTORY`, `-T`, and directory creation with `-d`.
- Supports options for group, owner, mode, stripping, copy-on-change, and dry-run through `DOITPROG`.
- Allows command overrides through environment variables such as `CHGRPPROG`, `CHMODPROG`, `CHOWNPROG`, `CMPPROG`, `CPPROG`, `MKDIRPROG`, `MVPROG`, `RMPROG`, and `STRIPPROG`.
- Computes safe umasks for file copies and directory creation.
- Tests for working POSIX `mkdir -p` behavior and falls back to step-by-step directory creation when needed.
- Copies to a temporary file in the destination directory, applies ownership/group/strip/mode changes, optionally skips replacement when `-C` detects no content/metadata changes, then renames into place.
- Uses traps to clean temporary files on interrupt or exit.

## Filesystem Relevance
Build/install-only. It performs portable file and directory installation during builds but is not part of runtime filesystem implementation.

## Reliability Notes
- Handles old or nonconforming `mkdir`, `mv`, and shell behavior with conservative fallbacks.
- Uses temporary names based on `$$` in the destination directory; normal for this class of historical build helper, but not designed as a security boundary.

## Dependencies
- POSIX shell plus standard file utilities: `cp`, `mv`, `rm`, `mkdir`, `chmod`, `chown`, `chgrp`, `cmp`, `strip`, `ls`, `dirname`, `basename`, `expr`, `sed`.

Vendored Automake helper that runs optional maintainer tools and prints useful advice when those tools are missing or too old.

## Main Responsibilities
- Supports `--help`, `--version`, `--is-lightweight`, and legacy `--run`.
- Runs the requested program and exits successfully if it succeeds.
