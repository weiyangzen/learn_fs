## sources/distributed-fs/beegfs/client_module/source/common/nodes/MirrorBuddyGroup.h

**Purpose:** Declares the kernel-client mirror buddy group state used to sequence mirrored writes and track acknowledged/finished sequence numbers for a pair of storage targets. **APIs/types:** `MirrorBuddyGroup` stores `groupID`, primary/secondary target IDs, the current `sequence`, a slot semaphore, in-flight `BuddySequenceNumber` heap/backlink handles, a finished sequence ring/buffer, mutex, kref, and rb/list linkage; exported operations construct from target IDs, acquire/release sequence numbers, set the sequence base, and drop refs. **Control flow/state:** callers acquire a sequence number before mirrored operations and later release a handle so the group can advance selective or contiguous acknowledgements; `slotsAvail`, heap handles, and finished buffers limit concurrent in-flight work. **Dependencies/integration:** consumed by `MirrorBuddyGroupMapper` and `MessagingTk` for buddy-mirrored target RPCs, with Linux `semaphore`, `mutex`, `kref`, and rb-tree/list embedding. **Risks/tests:** correctness depends on the implementation maintaining heap back-links, semaphore balance, and refcounts across mapper unlock/retry paths; test signals are concurrent acquire/release, seq-base updates after `GenericRespMsgCode_NEWSEQNOBASE`, and mapper removal while waiters hold refs.

## sources/distributed-fs/beegfs/client_module/source/common/nodes/MirrorBuddyGroupMapper.c

**Purpose:** Implements an RW-lock protected rb-tree mapping mirror buddy group IDs to `MirrorBuddyGroup` objects and provides atomic synchronization/update helpers. **Important APIs/functions:** generated rb helpers back `MirrorBuddyGroupMapper_getPrimaryTargetID`, `getSecondaryTargetID`, `acquireSequenceNumber`, `syncGroups`, `__syncGroupsUnlocked`, `addGroup`, and `__getBuddyGroupIDUnlocked`. **Control flow:** lookups take the read lock and return target ID 0 when missing; sequence acquisition first tries nonblocking under the mapper read lock, treats `ENOENT` from an unset sequence base as success, then krefs the group and waits outside the mapper lock if slots are exhausted. `syncGroups` builds a temporary list, reuses existing groups by updating target IDs and moving them out of the old tree, clears removed groups, then reinserts new/reused groups. `addGroup` rejects ID 0, duplicate groups when updates are disallowed, unknown storage targets via `TargetMapper`, and targets already assigned to another group. **State/persistence:** state is volatile kernel memory populated from management messages; updates replace the in-memory tree and free old kref objects. **Dependencies/integration:** integrates with `Config.connMaxInternodeNum`, `TargetMapper`, `TargetStateStore` atomic state/group sync, and `MirrorBuddyGroup` sequence management. **Risks/tests:** lock ordering must match `TargetStateStore` (`targetStates` then `buddyGroups`); add/sync tests should cover replacement, target reuse rejection, removed group ref cleanup, unset sequence base, and wait-acquire after mapper unlock.

## sources/distributed-fs/beegfs/client_module/source/common/nodes/NodeConnPool.c

**Purpose:** Implements pooled TCP/RDMA stream connections to one node, including connection creation, RDMA NIC priority, fallback routing, socket options/control messages, invalidation, and connection statistics. **Important APIs/functions:** construction/uninit, `NodeConnPool_acquireStreamSocketEx`, release/invalidate/disconnect helpers, local/remote interface updates, stats, first peer name reporting, RDMA NIC stat loading/priority, pre-connect and connected socket option application, and error-log suppression state. **Control flow:** acquire first handles fatal signals, lazy RDMA stats initialization, waits when `maxConns` are all in use, chooses an RDMA source NIC when possible (including NVFS GPU priority under `BEEGFS_NVFS`), reuses a matching available pooled socket, or increments established counters and tries cloned remote NICs in order. Successful connects apply TCP/RDMA options, send optional auth, indirect-channel, and `PeerInfoMsg`, append the unavailable pooled socket, and update last-success state; failures destroy sockets, update RDMA last-error/fallback data, decrement counters, and signal waiters. Release marks a socket available unless fallback expiration or `closeOnRelease` requires invalidation. Invalidation uses a two-stage path for available sockets so the pool mutex is not held during shutdown/disconnect. **State/persistence:** all state is volatile: NIC lists, RDMA stat objects kept for live IB sockets, connection list, counts, semaphore limiting concurrent attempts, local NIC capabilities, and log error state. **Dependencies/integration:** tightly integrated with `App`, `Config`, `Logger`, `NetFilter`, `RDMASocket`, `StandardSocket`, `NicAddressStatsList`, `Thread`, `ListTk`, channel control messages, and optional NVFS/RDMA priority. **Risks/tests:** counter balance across interrupted connects, RDMA fallback, `connSemaphore` release, `PooledSocket` pool membership, and lock boundaries are high-risk; tests should cover TCP-only filters, RDMA unavailable, max connection wait/wakeup, interface changes closing available streams and marking in-use streams `closeOnRelease`, auth/control-message send failures, and stats consistency after invalidation.
