# sources/distributed-fs/ceph-client/fs/nfsd/nfs4callback.c

Purpose: implements the server side of NFSv4 callback RPCs used by `nfsd` to contact clients. It encodes callback COMPOUND requests, decodes callback replies, manages v4.1 backchannel sequencing and slots, creates and refreshes callback `rpc_clnt` instances, and queues asynchronous callback work for delegation recalls, layout recalls, lock notification, offload completion, recall-any, and callback GETATTR.

Important APIs/types/functions: the local `struct nfs4_cb_compound_hdr` tracks callback COMPOUND metadata while XDR encoders fill the op array count later. `nfs4_cb_errtbl` and `nfs_cb_stat_to_errno()` translate NFS status codes to Linux errors for higher recovery logic. Encode/decode helpers cover `nfs_fh4`, `stateid4`, `sessionid4`, `CB_SEQUENCE`, `CB_RECALL`, `CB_RECALL_ANY`, `CB_GETATTR`, `CB_LAYOUTRECALL`, `CB_NOTIFY_LOCK`, and `CB_OFFLOAD`. The `nfs4_cb_procedures[]` table maps NFSD callback op IDs to SUNRPC procedure descriptors. Exported entry points include `nfsd4_probe_callback()`, `nfsd4_probe_callback_sync()`, `nfsd4_change_callback()`, `nfsd41_cb_referring_call()`, `nfsd41_cb_destroy_referring_call_list()`, `nfsd4_shutdown_callback()`, `nfsd4_init_cb()`, `nfsd4_run_cb()`, `nfsd_net_cb_init()`, and `nfsd_net_cb_shutdown()`.

Control flow: callback payload construction starts with `encode_cb_compound4args()`, optionally adds `CB_SEQUENCE` for minorversion greater than 0, appends the operation-specific body, and patches `nops` with `encode_cb_nops()`. Reply decode validates the COMPOUND status, decodes `CB_SEQUENCE` where present, verifies each returned op number with `decode_cb_op_status()`, then stores callback status on `struct nfsd4_callback`. `nfsd4_run_cb()` increments the client's in-flight callback counter and queues work on `cl_callback_wq`. `nfsd4_run_cb_work()` serializes callback-channel updates, creates or tears down the RPC client if client flags require it, prepares operation-specific state, and submits `rpc_call_async()`. `nfsd4_cb_prepare()` obtains a backchannel slot for v4.1+ and starts the RPC. `nfsd4_cb_done()` handles RPC and protocol status, advances slot sequence numbers only after a valid `CB_SEQUENCE`, marks callback state down or faulty on transport/session errors, and invokes the operation-specific `done` callback. `nfsd4_cb_release()` either requeues or destroys the callback context.

State and persistence behavior: the file maintains no stable storage. Runtime state lives in `struct nfs4_client`, `struct nfsd4_session`, and `struct nfsd4_callback`: callback RPC client pointer, callback credentials, backchannel transport, available slot bitmap, sequence IDs, callback flags, held slot, and referring-call lists. Per-net callback program state is allocated in `nfsd_net_cb_init()` and freed in `nfsd_net_cb_shutdown()`. Slot sequence state is deliberately conservative: on suspicious `CB_SEQUENCE` replies, the backchannel is marked faulty and callbacks are requeued or force session recovery rather than assuming client state.

Dependencies and integration points: the code sits between NFSD state management and SUNRPC client infrastructure. It uses `xdr_stream` helpers, generated XDR helpers for delegated times, `rpc_create()`, `rpc_call_async()`, backchannel transports from `svc_xprt`, per-net `nfsd_net`, and tracepoints in `trace.h`. Layout recall paths are compiled under `CONFIG_NFSD_PNFS` and are driven by `nfs4layouts.c`. Offload completion callbacks are driven by NFSv4.2 copy handling in `nfs4proc.c`. Delegation, lock, and client structures come from `state.h`.

Risks: XDR bounds and op-number validation are critical; malformed replies return `-EIO` or mark the channel faulty. v4.1 slot handling is subtle because sequence IDs must not be advanced after failed `CB_SEQUENCE` operations. Callback client replacement relies on single-threaded `cl_callback_wq` serialization rather than broad locking around `cl_cb_client`. Transport shutdown and callback requeue races are managed through flags, in-flight counters, and workqueue flushing; regressions here can leak slots, leave callbacks permanently running, or use freed RPC clients. Callback GETATTR caps decoded attribute length to expected fields; extending delegated attributes requires updating that bound.

Test signals: useful coverage includes delegation recall and recall-any interoperability, pNFS layout recall timeout and client fencing paths, v4.1 backchannel slot/sequence error injection, GSS callback credential setup, callback connection replacement via `BACKCHANNEL_CTL` or session transport changes, async COPY completion with `CB_OFFLOAD`, and shutdown paths that flush callback work while RPCs are in flight. Tracepoints such as `trace_nfsd_cb_*` provide runtime observability.

# sources/distributed-fs/ceph-client/fs/nfsd/nfs4idmap.c

Purpose: provides NFSv4 owner and group id mapping for the server. It translates wire-format owner/group strings to local `kuid_t`/`kgid_t` values and local ids back to owner/group strings, using SUNRPC caches backed by userspace upcalls. It also supports the common AUTH_SYS fast path where numeric ids are used directly when `nfs4_disable_idmapping` is true.

Important APIs/types/functions: `struct ent` is the shared cache entry for both directions, holding cache metadata, idmap type, numeric id, mapped name, authentication domain name, and RCU reclamation. Two `cache_detail` templates define `nfs4.idtoname` and `nfs4.nametoid`. The id-to-name side is implemented by `idtoname_hash()`, `idtoname_request()`, `idtoname_parse()`, `idtoname_lookup()`, and `idtoname_update()`. The name-to-id side mirrors this with `nametoid_hash()`, `nametoid_request()`, `nametoid_parse()`, `nametoid_lookup()`, and `nametoid_update()`. Exported APIs are `nfsd_idmap_init()`, `nfsd_idmap_shutdown()`, `nfsd_map_name_to_uid()`, `nfsd_map_name_to_gid()`, `nfsd4_encode_user()`, and `nfsd4_encode_group()`.

Control flow: initialization creates and registers two per-network-namespace caches on `struct nfsd_net`. On name-to-id lookup, `nfsd_map_name_to_uid()` or `nfsd_map_name_to_gid()` validates the owner string, optionally accepts a numeric string for AUTH_SYS, otherwise builds a cache key with the request's auth domain and calls `idmap_lookup()` on the nametoid cache. If the cache misses, SUNRPC cache code performs a pipe upcall and retries once if a timeout lookup races with a new entry. The result is converted through `make_kuid()` or `make_kgid()` in the request's user namespace. On id-to-name encoding, `nfsd4_encode_user()` or `nfsd4_encode_group()` converts kernel ids to namespace-local integers, optionally emits ASCII numbers for AUTH_SYS, otherwise looks up the idtoname cache and XDR-encodes the returned name. Negative id-to-name cache entries intentionally fall back to ASCII numeric ids.

State and persistence behavior: mappings are volatile SUNRPC cache entries, not kernel-owned stable storage. Userspace idmapd supplies responses with expiry times; cache validity and negative state are represented by cache flags. Entries are freed with `kfree_rcu()` via `ent_put()`, so lookups can be RCU-safe. Per-net cache pointers live in `nfsd_net`. The module parameter `nfs4_disable_idmapping` changes runtime behavior for AUTH_SYS requests and is writable through sysfs.

Dependencies and integration points: this code depends on `linux/sunrpc/cache`, `svc_rqst` request credentials, `auth_domain`, `nfsd_user_namespace()`, XDR stream encoding, and the NFSv4 XDR encoder/decoder paths that need owner/group attributes. It integrates with `rpc_pipefs` userspace cache channels through `sunrpc_cache_pipe_upcall_timeout()`. It also relies on `idmap.h` constants such as `IDMAP_NAMESZ`, `IDMAP_TYPE_USER`, and `IDMAP_TYPE_GROUP`.

Risks: cache parser strictness matters because malformed userspace replies can otherwise poison owner mapping. The code rejects non-newline-terminated records, oversized names, missing expiry fields, and invalid ids. `rqst_authname()` scopes mappings by GSS client or auth domain; incorrect auth domain selection could cross-contaminate mappings. NFSv4 requests must not be deferred, so `nfsd_map_name_to_uid()` and `nfsd_map_name_to_gid()` warn if `RQ_USEDEFERRAL` is set. Numeric AUTH_SYS fallback is compatibility-sensitive: disabling idmapping improves legacy behavior but can surprise deployments expecting domain-qualified names.

Test signals: exercise both cache files through rpc_pipefs/idmapd, including positive and negative mappings, expiry, malformed upcalls, GSS versus AUTH_SYS auth domains, user namespace id validity, numeric owner strings, and owner/group attribute encode/decode in GETATTR, SETATTR, CREATE, and OPEN. Operational warnings from `warn_no_idmapd()` indicate missing userspace support.

# sources/distributed-fs/ceph-client/fs/nfsd/nfs4layouts.c

Purpose: implements server-side pNFS layout state management for NFSD. It tracks granted layout segments, allocates layout stateids, assigns device IDs to exports, processes layout returns, recalls conflicting layouts, and integrates file leases with recall timeout and fencing behavior.

Important APIs/types/functions: `struct nfs4_layout` records a granted segment and links it to a `struct nfs4_layout_stateid`. `nfsd4_layout_ops[]` dispatches layout-driver operations for flexfile, block, and SCSI layouts depending on build configuration. Device ID helpers include `nfsd4_alloc_devid_map()`, `nfsd4_find_devid_map()`, `nfsd4_set_deviceid()`, and `nfsd4_setup_layout_type()`. Stateid helpers include `nfsd4_alloc_layout_stateid()`, `nfsd4_preprocess_layout_stateid()`, `nfsd4_insert_layout()`, `nfsd4_return_file_layouts()`, `nfsd4_return_client_layouts()`, `nfsd4_return_all_client_layouts()`, and `nfsd4_return_all_file_layouts()`. Callback and lease integration are provided by `nfsd4_cb_layout_ops` and `nfsd4_layouts_lm_ops`. Lifecycle functions are `nfsd4_init_pnfs()` and `nfsd4_exit_pnfs()`.

Control flow: exports opt into layout types in `nfsd4_setup_layout_type()` based on export flags and filesystem capabilities. `LAYOUTGET` handling in `nfs4proc.c` calls `nfsd4_preprocess_layout_stateid()` with create enabled; this resolves an existing layout stateid or creates one from open, lock, or delegation state, installs a file lease, links it on client and file lists, and locks the layout mutex. After the layout driver produces content, `nfsd4_insert_layout()` recalls layouts owned by other clients on the same file if needed, merges compatible adjacent/overlapping segments for the same stateid, or allocates a new `nfs4_layout`. `LAYOUTRETURN` calls remove matching segments, trim segment bounds, update the stateid generation when layouts remain, or mark the layout stateid closed when the list becomes empty. Client or file cleanup splices all layouts onto a reap list and drops stateid references outside spinlocks.

State and persistence behavior: layout state is in memory only. Device ID mappings are global in a hashed RCU list keyed by generated `idx`, with each export caching `ex_devid_map`; the mapping is not persisted across server restart. Layout stateids are refcounted NFSD state objects and carry per-client, per-file, and per-state segment lists, recall state, fence delayed work, and a lease-backed `nfsd_file`. The file lease keeps local VFS lease breaking tied to layout recalls. Fencing retry delay is stored per layout stateid and backs off up to `MAX_FENCE_DELAY`.

Dependencies and integration points: this file depends on `pnfs.h`, layout-driver implementations, NFSD state objects, `nfsd_file`, Linux file leases, workqueues, block device fencing operations, SUNRPC address formatting, and callback support from `nfs4callback.c`. It is invoked by the pNFS operation handlers in `nfs4proc.c`, while callback completion and lease break paths can asynchronously reclaim or fence layouts.

Risks: layout segment arithmetic must handle `NFS4_MAX_UINT64` and overflow correctly; `layout_end()` saturates wrapped ranges. The code intentionally does not split retained layouts on middle returns, which can leave broader-than-requested layout segments until later recall/return. Lock ordering across client lock, file lock, layout lock, and layout mutex is delicate. Recall conflicts must avoid granting overlapping layouts during recall. Fencing is high risk: if a block/SCSI client fails to return a layout, the worker retries indefinitely to avoid data corruption, requiring administrative intervention if fencing cannot complete. Device ID map lifetime uses RCU lookup but final cleanup frees maps only at pNFS exit.

Test signals: pNFS tests should cover layout type negotiation, `GETDEVICEINFO`, `LAYOUTGET`, overlapping grants, segment merge and return behavior, client-wide and file-wide return cleanup, recall conflict generation, callback timeout handling, lease-break initiated recalls, and block/SCSI fencing retry messages. Tracepoints such as `trace_nfsd_layout_*` are the main in-kernel observability points.

# sources/distributed-fs/ceph-client/fs/nfsd/nfs4proc.c

Purpose: implements NFSD's NFSv4 service procedures, especially the COMPOUND dispatcher and operation handlers for NFSv4.0, v4.1, and v4.2. It bridges decoded protocol operations to VFS helpers, state management, sessions, pNFS, xattrs, server-side copy, and response sizing.

Important APIs/types/functions: `nfsd4_proc_compound()` is the central dispatcher for `NFSPROC4_COMPOUND`; `nfsd4_proc_null()` handles NULL. The `nfsd4_ops[]` descriptor table maps each `OP_*` number to its handler, flags, response-size function, release function, and current-stateid hooks. Major handlers in this file include filehandle ops (`nfsd4_putfh()`, `nfsd4_putrootfh()`, `nfsd4_savefh()`, `nfsd4_restorefh()`), namespace and attribute ops (`nfsd4_lookup()`, `nfsd4_create()`, `nfsd4_getattr()`, `nfsd4_setattr()`, `nfsd4_remove()`, `nfsd4_rename()`), I/O ops (`nfsd4_read()`, `nfsd4_write()`, `nfsd4_commit()`), OPEN/create helpers (`nfsd4_open()`, `do_open_lookup()`, `nfsd4_create_file()`), NFSv4.2 copy/offload helpers, pNFS handlers, and xattr handlers. The exported service version is `nfsd_version4`.

Control flow: RPC decode creates `nfsd4_compoundargs`; `nfsd4_proc_compound()` initializes response XDR state, current and saved filehandles, minorversion state, and clears request deferral. It validates minorversion support, enforces v4.1 first-op ordering, marks stale source filehandles allowed for inter-server COPY, and iterates operations until an error or op count exhaustion. For each op it honors decode-time status, checks filehandle availability and migrated exports, clears weak cache attrs, prechecks reply space for non-idempotent operations, imports current stateid through descriptor hooks, invokes the handler, exports current stateid on success, optionally clears current stateid, performs deferred WRONGSEC checks after put-filehandle-like ops, encodes the result or replay, updates stats, and clears replay state. On exit it drops current and saved filehandles and stores final COMPOUND status.

State and persistence behavior: the dispatcher carries per-compound state in `struct nfsd4_compound_state`, including current filehandle, saved filehandle, session/client pointers, current stateid, saved stateid, replay owner, and flags. Durable protocol state is mostly managed in `state.c`, while this file creates, consumes, or cleans it through state APIs. Server-side async COPY stores per-client copy objects on `clp->async_copies`, tracks pending async copy count in `nfsd_net`, creates copy stateids, and later sends `CB_OFFLOAD`. Inter-server copy maintains delayed unmount list entries on `nfsd_net`. pNFS state changes are delegated to `nfs4layouts.c`. No standalone on-disk persistence is implemented here.

Dependencies and integration points: this file depends heavily on `vfs.h` for local filesystem operations, `state.h` APIs for opens, locks, sessions, delegations, replay, and copy state, `xdr4.h` for protocol encode/decode contracts, `current_stateid.h`, `acl.h`, `pnfs.h`, SUNRPC request/transport data, and tracepoints. It is the registered NFSv4 RPC version through `nfsd_procedures4[]` and `nfsd_version4`. pNFS handlers call `nfsd4_layout_ops` and layout-state helpers. Copy offload integrates with `nfs4callback.c` for `CB_OFFLOAD` and with the NFS client module for inter-server source mounts when enabled.

Risks: COMPOUND handling must not execute non-idempotent operations when there is insufficient reply space; the `op_rsize_bop` estimates and `warn_on_nonidempotent_op()` protect this. Current filehandle and current stateid rules are protocol-sensitive and descriptor flags must stay consistent with handler behavior. OPEN create paths implement guarded, unchecked, exclusive, and exclusive4_1 semantics, including verifier storage in timestamps; small changes can break replay or cross-client create behavior. Async COPY has concurrency risks around kthreads, cancellation, client teardown, callback completion, and superblock shutdown. Inter-server COPY is gated by a module parameter and has mount lifetime and stale filehandle special cases. pNFS operation handlers must validate layout type, iomode, range overflow, grace rules, and recall conflicts.

Test signals: broad NFSv4 connectathon/pynfs coverage should exercise COMPOUND ordering, replay cache behavior, filehandle save/restore, OPEN create modes, delegation-aware SETATTR, current stateid propagation, grace and reclaim behavior, WRONGSEC sequencing, response-size pressure, xattr operations, v4.2 READ_PLUS/SEEK/ALLOCATE/DEALLOCATE/CLONE/COPY, async COPY cancellation/status/callback, pNFS `GETDEVICEINFO`/`LAYOUTGET`/`LAYOUTCOMMIT`/`LAYOUTRETURN`, and exported `nfsd4_spo_must_allow()` machine-credential logic. Tracepoints around compound operations, reads, writes, copy, and layouts give useful regression signals.

# sources/distributed-fs/ceph-client/fs/nfsd/nfs4recover.c

Purpose: implements NFSv4 client recovery tracking for NFSD so clients that held state before a server restart can reclaim during the grace period. It abstracts several stable-storage mechanisms behind `struct nfsd4_client_tracking_ops`: legacy recovery directories, `nfsdcld` rpc_pipefs upcalls, versioned cld upcalls with principal hashes, and a usermode-helper `nfsdcltrack` fallback when legacy tracking is enabled.

Important APIs/types/functions: `struct nfsd4_client_tracking_ops` defines backend `init`, `exit`, `create`, `remove`, `check`, and `grace_done` hooks plus protocol version and message length. Legacy tracking centers on `nfs4_make_rec_clidname()`, `nfsd4_create_clid_dir()`, `nfsd4_remove_clid_dir()`, `nfsd4_recdir_load()`, `nfsd4_recdir_purge_old()`, and `nfsd4_check_legacy_client()`. cld tracking uses `struct cld_net`, `struct cld_upcall`, `cld_pipe_upcall()`, `cld_pipe_downcall()`, `nfsd4_cld_create()`, `nfsd4_cld_create_v2()`, `nfsd4_cld_remove()`, `nfsd4_cld_check*()`, `nfsd4_cld_grace_start()`, and `nfsd4_cld_grace_done*()`. UMH tracking uses `nfsd4_umh_cltrack_upcall()` and wrapper create/remove/check/gracedone functions. Exported wrapper APIs are `nfsd4_client_tracking_init()`, `nfsd4_client_tracking_exit()`, `nfsd4_client_record_create()`, `nfsd4_client_record_remove()`, `nfsd4_client_record_check()`, `nfsd4_record_grace_done()`, `register_cld_notifier()`, and `unregister_cld_notifier()`.

Control flow: `nfsd4_client_tracking_init()` first tries modern `nfsdcld` tracking. It creates reclaim hashtables, sets up a rpc_pipefs pipe under `nfsd/cld`, waits briefly for the daemon to open it, negotiates upcall version, and asks userspace to send reclaimable clients with `Cld_GraceStart`. If this fails with a non-timeout, it tries old v0 cld operations. With legacy support enabled, it then tries UMH `nfsdcltrack`, and finally the legacy recovery directory. During normal operation, `nfsd4_client_record_create()` records confirmed clients on stable storage, `nfsd4_client_record_remove()` removes expired clients, and `nfsd4_client_record_check()` verifies whether a reclaiming client has a stable record. At grace completion, the active backend purges old reclaim data or sends a grace-done upcall, then releases the in-memory reclaim table.

State and persistence behavior: legacy mode persists client records as MD5-hashed directory names under `/var/lib/nfs/v4recovery` by default, with root fs credentials temporarily overridden for filesystem access. cld and UMH modes outsource persistence to userspace daemons, while the kernel keeps an in-memory reclaim hash table populated during grace. v2 cld records can include a SHA-256 hash of the client principal, and reclaim checks require the current principal to match. Per-net state includes `client_tracking_ops`, `reclaim_str_hashtbl`, `cld_net`, reclaim counters, and grace flags. rpc_pipefs mount and unmount events dynamically register or unlink the cld pipe.

Dependencies and integration points: the file uses VFS directory creation/removal, credential override, MD5 and SHA-256 helpers, rpc_pipefs, SUNRPC pipe upcalls, nfsd network namespace state, and reclaim helpers from `state.h`. It integrates with client lifecycle and grace-period handling elsewhere in NFSD. The notifier connects cld tracking to rpc_pipefs mount lifecycle. Legacy and UMH code are conditional on `CONFIG_NFSD_LEGACY_CLIENT_TRACKING`.

Risks: stable recovery tracking is correctness-critical: false negatives deny legitimate reclaim, while false positives can allow stale clients to reclaim state. Legacy directory mode is restricted to `init_net` and depends on a writable recovery directory. cld upcalls block waiting for userspace and must handle pipe reopen races (`-EAGAIN`), in-progress downcalls, unmatched XIDs, and daemon absence without hanging startup excessively. Principal-hash checks in v2 improve security but can fail clients without matching principal data. The code has several fallback paths; misconfiguration can silently move to less capable legacy behavior if enabled. Cleanup must avoid leaving stale records after grace.

Test signals: test startup with and without `nfsdcld`, cld version negotiation, `Cld_GraceStart` in-progress downcalls that populate reclaim records, v2 principal-hash matching and mismatch, rpc_pipefs remount notifier behavior, legacy recovery directory load/purge, UMH helper environment construction, client create/remove/check under v4.0 and v4.1+, and grace completion releasing reclaim tables. Kernel logs around "Using nfsdcld", "Using legacy", and "Unable to initialize client recovery tracking" are important operational signals.
