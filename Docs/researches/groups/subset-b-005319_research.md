# sources/distributed-fs/ceph-client/drivers/scsi/ncr53c8xx.c

Purpose: implements the reusable Linux SCSI low-level core for the NCR/Symbios 53C8xx family after this copy was narrowed to the 53C720-era path. It is not a standalone PCI probe driver; bus-specific frontends provide `struct ncr_device` and call `ncr_attach()`, while this file owns controller allocation, SCRIPTS program construction, SCSI command queueing, DMA mapping, target/lun/tag state, interrupt decoding, transfer negotiation, autosense, bus reset, and SPI transport registration.

Important APIs/types/functions: exported/integration entry points are `ncr_attach()`, `ncr53c8xx_release()`, `ncr53c8xx_intr()`, `ncr53c8xx_init()`, and `ncr53c8xx_exit()`. Linux SCSI callbacks installed by `ncr_attach()` are `ncr53c8xx_queue_command`, `ncr53c8xx_sdev_init()`, `ncr53c8xx_sdev_configure()`, and `ncr53c8xx_bus_reset()`. SPI transport hooks are `ncr53c8xx_set_period()`, `ncr53c8xx_set_offset()`, `ncr53c8xx_set_width()`, and `ncr53c8xx_get_signalling()`. Core controller helpers include `ncr_prepare_setting()`, `ncr_init()`, `ncr_chip_reset()`, `ncr_reset_scsi_bus()`, `ncr_script_fill()`, `ncr_script_copy_and_bind()`, `ncr_queue_command()`, `ncr_get_ccb()`, `ncr_free_ccb()`, `ncr_alloc_lcb()`, `ncr_setup_lcb()`, `ncr_scatter()`, `ncr_complete()`, `ncr_exception()`, `ncr_int_ma()`, `ncr_int_sir()`, `ncr_int_par()`, `ncr_int_sto()`, `ncr_timeout()`, `ncr_wakeup_done()`, and `ncr_detach()`.

Control flow: initialization starts with `ncr53c8xx_init()` attaching an SPI transport template; bus code then calls `ncr_attach()` with a SCSI host template and hardware descriptor. `ncr_attach()` fills host callbacks and limits, allocates the host-private `struct ncb`, default `struct ccb`, and coherent SCRIPTS buffers from the private DMA allocator, maps registers, derives register settings in `ncr_prepare_setting()`, patches SCRIPTS relocation tokens to bus addresses, initializes target reselection jump tables, verifies cache/snoop behavior, resets the bus, processes the reset exception, starts the periodic timer, and returns the allocated `Scsi_Host`.

Command flow: `ncr53c8xx_queue_command_lck()` initializes per-command private mapping state and serializes on `np->smp_lock`. `ncr_queue_command()` rejects invalid target/lun/self-selection, defers commands during settle time or CCB exhaustion onto `np->waiting_list`, allocates or reuses a `struct ccb`, builds IDENTIFY/tag/negotiation messages, maps the scatterlist through `scsi_dma_map()`, fills CCB `dsb` table moves, computes SCRIPTS `savep/lastp/goalp` pointers for input, output, bidirectional, or no-data commands, copies the CDB, sets host/scsi/parity/extended status fields, and activates the CCB. `ncr_start_next_ccb()` and `ncr_put_start_queue()` patch the SCRIPTS `tryloop` start queue and wake the chip by writing `SIGP` to `nc_istat`.

Completion flow: the hardware SCRIPTS program writes CCB pointers into the done queue or raises `SIR_INTFLY`. `ncr53c8xx_intr()` calls `ncr_exception()` under the driver lock, snapshots `np->done_list`, drops the lock, and calls `scsi_done()` through `ncr_flush_done_cmds()`. `ncr_wakeup_done()` drains the hardware done queue, calls `ncr_complete()` for finished CCBs, or moves skipped CCBs to `skip_ccbq`. `ncr_complete()` translates host status to SCSI midlayer result bytes, copies autosense data, logs parity/extended errors, updates per-target byte/transfer counters, grows tag depth after many good completions following queue-full throttling, frees the CCB, requeues waiting commands, and appends the command to `done_list`. Data is always unmapped before the final callback.

SCRIPTS program behavior: the large `script0` and `scripth0` tables encode the chip-side state machine: selection, message out, command, data dispatch, status, message in, disconnect, reselection, nexus lookup by target/lun/tag, completion signaling, phase mismatch recovery, parity handling, negotiation messages, autosense data transfer, reset/abort messages, and a snoop test. `ncr_script_fill()` expands compile-time-sized tryloop, done queue, and scatter/gather transfer loops. `ncr_script_copy_and_bind()` copies the program into DMA memory and resolves `NADDR`, `PADDR`, `PADDRH`, and register relocations to controller, script, high-script, or MMIO bus addresses, while stripping `SCR_NO_FLUSH` for chips without prefetch support.

Interrupt/error control flow: `ncr_exception()` first handles interrupt-on-the-fly completions, then reads SCSI and DMA interrupt status. Clean cases dispatch to bus mode change (`ncr_int_sbmc()`), parity (`ncr_int_par()`), phase mismatch (`ncr_int_ma()`), or programmed interrupt (`ncr_int_sir()`). Reset interrupts reinitialize the chip with all active CCBs completed as `HS_RESET`. Selection timeout marks the matching CCB `HS_SEL_TIMEOUT` and restarts the queue. Hard DMA, gross, abort, illegal-instruction, or handshake errors log register/script context and generally start a SCSI bus reset. Unexpected disconnect patches `HS_UNEXPECTED` into the SCRIPTS cleanup path. `ncr_int_ma()` is especially delicate: it computes residual bytes including FIFO/latch state, validates the interrupted SCRIPTS instruction, patches one of the CCB local `patch[]` mini-scripts for the remaining bytes, and resumes at dispatcher, or resets if the interrupted context cannot be trusted.

Negotiation and queueing state: target control blocks track current synchronous factor, period, wide status, user limits, quirks, and an in-flight negotiation CCB. LUN control blocks maintain free/busy/wait/skip queues, tag circular buffers, tag bitmaps, queue depth, queue-full recovery state, and the reselection jump table. `ncr_prepare_nego()`, `ncr_negotiate()`, `ncr_setsync()`, and `ncr_setwide()` coordinate SPI transport capabilities with target limits and hardware register fields. `ncr_int_sir()` validates SDTR/WDTR responses or target-initiated messages, falls back to async/narrow on reject/protocol failure, and patches all active CCBs for the target after a new agreement. `ncr_sir_to_redo()` handles `TASK_SET_FULL`, `CHECK_CONDITION`, and `COMMAND_TERMINATED`: queue-full reduces tag depth and requeues the command, while check-condition rewrites the CCB for REQUEST SENSE and restarts it.

State and persistence: all state is volatile kernel runtime state. Long-lived state is in the host-private `struct ncb`, including mapped register base, coherent script buffers, target array, queues, hardware settings, done queue, timer, reset settle time, SCSI mode, and saved BIOS register values. Per-target `struct tcb`, per-lun `struct lcb`, and per-command `struct ccb` represent negotiated transfer settings, tag allocation, active queues, SCSI command descriptors, DMA tables, sense buffers, and chip-visible headers. The private memory allocator keeps per-device coherent DMA pools and virtual-to-bus translation tables; it frees unused pools immediately when possible. There is no disk persistence; hardware state is reconstructed on attach, reset, bus mode change, and transport parameter changes.

Dependencies and integration points: depends on the Linux SCSI midlayer, block request timeout fields, SPI transport class, scatterlist and DMA mapping APIs, timers, spinlocks, kernel MMIO accessors, and SCSI message/status constants. It includes `ncr53c8xx.h` for register layout, SCRIPTS opcodes, feature flags, setup defaults, device descriptors, and external prototypes. Integration is by bus wrapper: the wrapper owns hardware discovery, IRQ request/free, and `struct ncr_device` population; this file mutates the supplied `scsi_host_template` and later exposes a `revision` host sysfs attribute plus SPI transport attributes.

Risks: the code is hardware-race sensitive and heavily self-modifying: start queues, done queues, reselection jumps, and phase-mismatch patch scripts are shared with the chip and rely on memory barriers and coherent DMA. `host_scribble` is reused for both waiting and done list linkage, so list ownership bugs can corrupt command flow. The custom allocator and `vtobus()` translation assume allocations come from the driver pools. Several paths use `BUG_ON()` for impossible CCB/nexus/relocation states and can panic on corruption or unexpected hardware behavior. Phase mismatch, parity, queue-full redo, and autosense all rewrite active CCB/script state and are the highest-risk behavior. The attach error path frees internal allocations but relies on the bus wrapper for external mappings/IRQs, and `ncr_detach()` waits for the timer through `release_stage` polling rather than `del_timer_sync()`. The file also contains legacy assumptions around 64-bit done queue validity, big-endian register addressing, old SCSI message behavior, and broken interrupt polling.

Test signals: build coverage should include this driver with the bus frontends that call `ncr_attach()` and with representative endian/MMIO options. Runtime signals are successful host attach, `revision` sysfs read, SPI transport attributes, SCSI scan after the configured settle delay, simple and tagged I/O, disconnect/reselection under load, queue-full throttling/recovery, CHECK CONDITION autosense, SDTR/WDTR negotiation and sysfs period/offset/width changes, selection timeout, parity/phase mismatch injection if hardware or emulator permits, bus reset through SCSI error handling, release/unload without timer or DMA leaks, and snoop/cache test success during attach.

# sources/distributed-fs/ceph-client/drivers/scsi/ncr53c8xx.h

Purpose: declares the public and internal contract used by the NCR/Symbios 53C8xx low-level driver and its bus-specific frontends. It combines Kconfig-derived setup defaults, endian-safe MMIO helpers, chip feature bits, user setup structures, the complete NCR register map, SCRIPTS opcode-building macros, script-visible table formats, attach-time device descriptors, command-private DMA state, and exported function prototypes.

Important APIs/types/macros: configuration defaults include `SCSI_NCR_MAX_TAGS`, `SCSI_NCR_SETUP_DEFAULT_TAGS`, `SCSI_NCR_SETUP_DEFAULT_SYNC`, `SCSI_NCR_SETUP_DISCONNECTION`, parity defaults, `SCSI_NCR_CAN_QUEUE`, `SCSI_NCR_CMD_PER_LUN`, `SCSI_NCR_SG_TABLESIZE`, and reset settle timing. Register access macros include `INB/INW/INL`, `OUTB/OUTW/OUTL`, `OUTON*`, `OUTOFF*`, `OUTL_DSP()`, and `OUTONB_STD()`. Chip description is `struct ncr_chip` with `FE_*` feature bits. User/setup state is `struct ncr_driver_setup` with `SCSI_NCR_DRIVER_SETUP` and `SCSI_NCR_DRIVER_SAFE_SETUP`. Hardware layout is `struct ncr_reg`. Script vocabulary includes `ncrcmd`, phase constants, `SCR_MOVE_*`, `SCR_SEL_*`, `SCR_WAIT_*`, `SCR_COPY*`, register-operation builders, load/store builders, jump/call/return/int encodings, condition macros, and `ncr_build_sge()`. Frontend descriptors are `struct ncr_slot` and `struct ncr_device`. Command-private state is `struct ncr_cmd_priv`. External functions are `ncr_attach()`, `ncr53c8xx_release()`, `ncr53c8xx_intr()`, `ncr53c8xx_init()`, and `ncr53c8xx_exit()`.

Control flow enabled by this header: bus frontends construct a `struct ncr_device` with MMIO base addresses, optional mapped virtual addresses, IRQ, chip feature description, host ID, and differential mode, then pass it with a `scsi_host_template` to `ncr_attach()`. The C file uses the setup defaults to initialize global driver options, uses feature bits to choose register settings and SCRIPTS features, uses MMIO macros for all chip access, uses SCRIPTS builders to define and relocate the chip-side program, and uses `struct ncr_cmd_priv` through `scsi_cmd_priv()` to track whether a command has an active DMA mapping. During unload, frontends call `ncr53c8xx_release()` after unregistering/request cleanup, and module-level setup calls `ncr53c8xx_init()`/`exit()` around SPI transport registration.

State and persistence behavior: this header does not store runtime state by itself, but it defines the shapes of state persisted for the lifetime of the loaded driver. `struct ncr_driver_setup` is initialized from compile-time defaults and optionally overridden by module or boot options in the C file. `struct ncr_chip` describes immutable chip capabilities supplied by probe code. `struct ncr_slot` and `struct ncr_device` are attach-time handoff records. `struct ncr_cmd_priv` is per-SCSI-command transient state used to ensure mapped scatter/gather data is unmapped exactly once. Register values, SCRIPTS tables, queue state, CCBs, TCBs, and LCBs are defined in the C file but depend on the opcodes, register offsets, endianness conversion macros, and constants declared here.

Dependencies and integration points: depends on `<scsi/scsi_host.h>` for `struct Scsi_Host` and the SCSI host template integration. It assumes Linux byte-order definitions and MMIO primitives are available before macro use through the including C file. It encodes NCR/Symbios register definitions originally carried from FreeBSD `ncrreg.h` and therefore must remain aligned with hardware manuals and the C file's `offsetof(struct ncr_reg, ...)` relocation logic. It also integrates with SPI transport by exposing `struct ncr_device` fields and prototypes consumed by wrapper drivers such as 53C720/Zalon style frontends.

Risks: many macros are low-level hardware contracts rather than type-safe functions. Incorrect `struct ncr_reg` offsets, endian lane macros, or SCRIPTS opcode encodings can cause direct hardware misprogramming. `SCSI_NCR_DRIVER_SETUP` and `SCSI_NCR_DRIVER_SAFE_SETUP` are positional initializers for `struct ncr_driver_setup`; field reordering requires updating both. `struct scr_tblsel` changes layout under `SCSI_NCR_BIG_ENDIAN`, so CCB construction and script selection depend on matching CPU/chip addressing mode. Feature bits such as `FE_PFEN`, `FE_RAM`, `FE_DFS`, `FE_EHP`, `FE_MUX`, and `FE_EA` directly gate code paths in the C file; a wrong chip descriptor can enable unsafe hardware behavior. `OUTL_DSP()` and `OUTONB_STD()` include memory barriers because the chip consumes driver-owned DMA structures asynchronously; bypassing those wrappers is a race risk.

Test signals: compile checks are important because many interfaces are macro-expanded `offsetof()` expressions. Useful validation includes building on little-endian and supported big-endian architectures, checking that `sizeof(struct ncr_reg)` and key register offsets match hardware expectations, probing a frontend that fills `struct ncr_device`, verifying `cmd_size >= sizeof(struct ncr_cmd_priv)` at attach, running SCSI scan and SPI transport sysfs operations, exercising sync/wide/tag negotiation to validate SCRIPTS table structures, and performing reset/release paths to confirm register access and command-private mapping state remain consistent.
