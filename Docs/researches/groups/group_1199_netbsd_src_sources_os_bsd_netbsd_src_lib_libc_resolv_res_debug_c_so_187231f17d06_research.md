This file implements DNS/resolver debug and presentation helpers. It provides packet printing through `res_pquery`, section rendering through `do_section`, compressed-name printing helpers, DNS class/type/rcode/section symbol tables, resolver option/time/socket-address string helpers, DNS LOC RDATA text/wire conversion, DNS label counting, DNSSEC-style timestamp formatting, and text-to-class/type parsers.

Key behavior: `res_pquery` parses a DNS message with `ns_initparse`, prints header opcode/status/flags/counts according to resolver print flags, then delegates question, answer, authority, and additional sections to `do_section`. `do_section` uses `ns_parserr` and `ns_sprintrr`, with explicit EDNS OPT pseudo-RR printing including NSID option display. `p_type`, `p_class`, `p_rcode`, and `p_section` translate numeric DNS values to mnemonics, with `TYPE####`/`CLASS####` fallbacks.

Important interactions: used by resolver debug paths in `res_send.c` and by legacy BIND resolver APIs expected by callers and other libc resolver files. The symbol tables and formatting helpers support DNS packet diagnostics and RR presentation elsewhere in the resolver library.

Security/reliability notes: many helper functions return pointers to static buffers and are not reentrant. The EDNS option loop resets its RDATA cursor each iteration and does not validate `optlen` against remaining RDATA before reading option bytes, making malformed OPT records a sensitive area. `p_sockun` writes `'0'` instead of `'\0'` as the output terminator, which appears to be a bug.

This file initializes, reloads, and destroys resolver state. Entry points include `res_ninit`, `__res_vinit`, `res_check`, `res_nclose`, `res_ndestroy`, `res_get_nibblesuffix`, `res_get_nibblesuffix2`, `res_setservers`, `res_getservers`, `res_rndinit`, and `res_nrandomid`.

Key behavior: `__res_vinit` resets resolver defaults, allocates the private extension object, seeds random DNS ID state, installs default IPv4/IPv6 nameservers, parses `LOCALDOMAIN`, `/etc/resolv.conf`, and `RES_OPTIONS`, builds domain search lists, sort lists, nameserver arrays, IPv6 reverse suffixes, and kqueue tracking for resolver configuration changes. `res_check` uses saved `resolv.conf` mtime and vnode kqueue events to reinitialize state after configuration changes. `res_nclose` closes cached TCP and UDP sockets; `res_ndestroy` also closes config/kqueue fds and frees extension/random allocations.

Security/reliability notes: environment-controlled `LOCALDOMAIN` and `RES_OPTIONS` remain part of the resolver API surface. Random IDs are generated by hashing time/pid seed material with MD5, suitable for legacy DNS ID generation but not a modern strong RNG. The extension-allocation failure path is intended to defer failure through `h_errno`, but later config-file handling assumes the extension exists, which is a sensitive low-memory path. `res_setservers` closes cached sockets before replacing server addresses, so callers must expect connection cache invalidation.

This file constructs DNS query packets. `res_nmkquery` creates QUERY, NS_NOTIFY_OP, and legacy IQUERY messages. When EDNS0 is enabled, `res_nopt` appends an OPT pseudo-RR and `res_nopt_rdata` appends option RDATA while updating the OPT RDLEN field.

Security/reliability notes: functions return `-1` on short buffers or unsupported opcodes. `res_nopt_rdata` checks that the RDATA pointer is within the message, but correctness still depends on callers passing the pointer that follows the OPT RDLEN field.
