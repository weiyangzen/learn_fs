# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtlwifi/btcoexist/halbtc8723b2ant.c

Purpose: RTL8723B two-antenna Bluetooth/Wi-Fi coexistence policy implementation. It consumes Wi-Fi lifecycle events and Bluetooth firmware C2H reports, classifies active BT profiles, and programs Realtek coexistence hardware, firmware H2C commands, antenna routing, power save, rate retry behavior, and aggregation limits.

Important APIs/functions: exported callbacks are `ex_btc8723b2ant_init_hwconfig`, `ex_btc8723b2ant_power_on_setting`, `ex_btc8723b2ant_pre_load_firmware`, `ex_btc8723b2ant_init_coex_dm`, `ex_btc8723b2ant_display_coex_info`, `ex_btc8723b2ant_ips_notify`, `ex_btc8723b2ant_lps_notify`, `ex_btc8723b2ant_scan_notify`, `ex_btc8723b2ant_connect_notify`, `ex_btc8723b2ant_media_status_notify`, `ex_btc8723b2ant_special_packet_notify`, `ex_btc8723b2ant_bt_info_notify`, `ex_btc8723b2ant_halt_notify`, `ex_btc8723b2ant_pnp_notify`, and `ex_btc8723b2ant_periodical`. Core helpers include RSSI hysteresis (`btc8723b2ant_bt_rssi_state`, `btc8723b2ant_wifi_rssi_state`), BT/Wi-Fi counter readers, BT-info query H2C `0x61`, profile classification, coexistence table programming for registers `0x6c0/0x6c4/0x6c8/0x6cc`, antenna path setup, PS-TDMA H2C `0x60`, ignore-WLAN-active H2C `0x63`, DAC swing and BT power H2Cs, and profile-specific action routines.

Control flow: initialization backs up RF state, configures local firmware antenna metadata, sets the antenna switch path, enables PTA statistics, and resets coexistence decision-manager state. BT-info notifications copy C2H bytes into `coex_sta`, parse profile bits, retry count, BT RSSI, A2DP bitpool, remote-name/inquiry flags, update `btcoexist->bt_link_info`, derive `coex_dm->bt_status`, publish BT-busy and limited-DIG flags, then call `btc8723b2ant_run_coexist_mechanism`. The run mechanism short-circuits manual control and IPS, handles inquiry/page, Wi-Fi scan/link/roam, and multi-port/P2P before selecting an algorithm from SCO/HID/A2DP/PAN combinations. Common idle/non-connected cases turn coexistence off or into low-impact tables; busy profile cases program table, TDMA, LPS/RPWM, DAC swing, BT power reduction, and low-penalty RA.

State and persistence: file-local static globals `glcoex_dm_8723b_2ant` and `glcoex_sta_8723b_2ant` persist across callbacks for the device/module lifetime. `coex_dm` stores previous/current hardware policy, TDMA bytes, auto-TDMA adjustment state, algorithm, LPS/RPWM, Wi-Fi channel info, and two-antenna switch threshold offsets. `coex_sta` stores observed BT link/profile status, IPS/LPS flags, BT counters, C2H payload history, retry/RSSI/ext fields, CRC counters, AP count, and A2DP bitpool. Hardware persistence is volatile register state plus firmware state reached through H2C commands; power-on/pre-load firmware functions write local registers so firmware learns antenna topology.

Dependencies and integration: depends on `halbt_precomp.h` for `struct btc_coexist`, `btc_get`/`btc_set` selectors, H2C/MMIO/RF accessors, `struct rtl_priv`, debug macros, bit masks, profile enums, and constants such as `BTC_PS_*`, `BTC_GET_*`, `BTC_SET_*`, `BTC_ANT_*`, and Wi-Fi bandwidth/link status values. It integrates with rtlwifi BT coexistence dispatch, firmware C2H/H2C plumbing, debugfs or seq-file diagnostics, and Wi-Fi power-management notifications.

Risks: the code is register- and firmware-version-sensitive; changing constants around `0x948`, `0x765`, `0x76e`, `0x6c*`, or H2C IDs can break antenna grants or PTA arbitration. `btc8723b2ant_tdma_duration_adjust` uses static adjustment counters shared by all invocations, so multi-adapter use would not be isolated. BT-info parsing assumes payload bytes up to index 6 when source is not Wi-Fi firmware, while the callback only receives a length argument and copies up to the reported length into fixed 10-byte rows. Many state changes avoid writes when previous/current values match; missed force-exec paths can leave stale firmware state. Several action paths depend on AP count even though comments say Linux may not know it, reducing coverage of some branches.

Test signals: build with the rtlwifi/rtlwifi BT coexistence objects catches API drift. Runtime validation should observe BT C2H reports, H2C writes `0x60/0x61/0x63/0x64/0x65/0x66/0x68/0x69/0x6e`, changing debug display fields for algorithm/TDMA/coex table/counters, stable Wi-Fi throughput during A2DP/HID/SCO/PAN, clean IPS/LPS/halt/PNP transitions, and correct recovery after BT reset requests Wi-Fi channel re-send via BT info ext bit 1.

# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtlwifi/btcoexist/halbtc8723b2ant.h

Purpose: public/private interface for the RTL8723B two-antenna coexistence module. It defines BT-info bit meanings, RSSI thresholds, BT-status and coexistence-algorithm enums, the persistent decision/observation structs used by the C file, and the external notification entry points called by the rtlwifi coexistence core.

Important APIs/types/functions: `BT_INFO_8723B_2ANT_B_*` maps firmware BT profile and busy bits. `enum BT_INFO_SRC_8723B_2ANT` identifies C2H sources: Wi-Fi firmware, BT response, and BT active auto-report. `enum BT_8723B_2ANT_BT_STATUS` normalizes BT state into non-connected idle, connected idle, inquiry/page, ACL busy, SCO busy, and ACL+SCO busy. `enum BT_8723B_2ANT_COEX_ALGO` names the policy branches for SCO, HID, A2DP, PAN EDR/HS, and combined profiles. `struct coex_dm_8723b_2ant` stores current/previous coexistence mechanism settings, and `struct coex_sta_8723b_2ant` stores measured BT/Wi-Fi state. The `ex_btc8723b2ant_*` prototypes form the file's integration contract.

Control flow: the header has no executable logic, but it defines the event-driven lifecycle: power-on/pre-load firmware setup, hardware config, coexistence DM init, notifications for IPS/LPS/scan/connect/media/special packets/BT info/halt/PNP, periodic maintenance, and diagnostic display. The enums constrain the C file's switch statements for algorithm selection and BT status.

State and persistence: `coex_dm_8723b_2ant` persists policy outputs such as BT power reduction, firmware DAC swing level, ignore-WLAN-active state, PS-TDMA type and bytes, auto TDMA flags, RF/BB register shadows, coexistence table values, current algorithm, Wi-Fi channel info, LPS/RPWM, and antenna switch state. `coex_sta_8723b_2ant` persists status inputs including profile booleans, IPS/LPS state, priority counters, BT RSSI and retry count, C2H history/counters, inquiry/remote-name flags, AP count, CRC counters, force-LPS state, display-version counter, and A2DP bitpool.

Dependencies and integration: uses kernel integer/bool types and bit macros supplied through the enclosing Realtek BT coexistence headers. All function prototypes take `struct btc_coexist *`; the display callback also depends on `struct seq_file`. The header is included through `halbt_precomp.h` and must stay consistent with the dispatcher that calls the `ex_btc8723b2ant_*` hooks.

Risks: struct field names are directly consumed by the C file, so reordering is safe for C but changing meaning or deleting fields can silently alter policy persistence. C2H arrays are fixed at 10 bytes per source, so firmware message length assumptions must remain aligned with parser behavior. The `BT_8723B_2ANT_COEX_ALGO_MAX` value is part of debug/range expectations and should track enum additions.

Test signals: compile all rtlwifi coexistence code to verify prototypes and enum names. Runtime debug output should show stable interpretation of BT-info bits, correct algorithm names, nonzero C2H counters per source, and coherent `coex_dm` current/pre fields after policy changes.

# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtlwifi/btcoexist/halbtc8821a1ant.c

Purpose: RTL8821A one-antenna Bluetooth/Wi-Fi coexistence policy implementation. Because Wi-Fi and BT share one antenna path, this file coordinates antenna ownership, PTA tables, PS-TDMA, Wi-Fi rate/retry/AMPDU limits, aggregation, and power-save behavior across Wi-Fi lifecycle and BT firmware status events.

Important APIs/functions: exported callbacks are `ex_btc8821a1ant_init_hwconfig`, `ex_btc8821a1ant_init_coex_dm`, `ex_btc8821a1ant_display_coex_info`, `ex_btc8821a1ant_ips_notify`, `ex_btc8821a1ant_lps_notify`, `ex_btc8821a1ant_scan_notify`, `ex_btc8821a1ant_connect_notify`, `ex_btc8821a1ant_media_status_notify`, `ex_btc8821a1ant_special_packet_notify`, `ex_btc8821a1ant_bt_info_notify`, `ex_btc8821a1ant_halt_notify`, `ex_btc8821a1ant_pnp_notify`, and `ex_btc8821a1ant_periodical`. Key internals cover RSSI hysteresis, rate mask and retry programming (`0x430`, `0x434`, `0x42a`, `0x456`), RX aggregation control, BT counter monitoring, BT-info query H2C `0x61`, profile algorithm selection, coexistence table writes, ignore-WLAN-active H2C `0x63`, PS-TDMA H2C `0x60`, antenna path setup through `0x4c`, `0x765`, `0xcb4`, `0xcb7`, and profile/Wi-Fi-state action functions.

Control flow: hardware init optionally backs up Wi-Fi rate/retry/AMPDU registers, configures the 1-antenna switch, coex table, PTA counters, and antenna path based on 2.4 GHz vs 5 GHz. BT-info notifications parse C2H bytes, retry count, RSSI, ext bits, BT TX/RX mask, and profile flags, update global link info and BT-busy state, then run the coexistence mechanism. The run mechanism exits for manual/stop/IPS, handles 5 GHz with BT-side antenna and no TDMA, increases scan device number when BT is busy, handles multi-port/P2P, applies TX/RX limits, runs software profile selection, then prioritizes inquiry/page, HS mode, Wi-Fi scan/link/roam, high-priority special packets, connected idle/busy, and non-connected states. Scan/connect/media/special-packet callbacks often act immediately rather than waiting for the periodic path.

State and persistence: static `glcoex_dm_8821a_1ant` and `glcoex_sta_8821a_1ant` hold module-lifetime policy and observation state. `coex_dm` tracks previous/current ignore-WLAN-active, TDMA, LPS/RPWM, low-penalty RA, coexistence tables, backed-up ARFR/retry/AMPDU values, algorithm, Wi-Fi channel info, rate mask, ARFR/retry/AMPDU types, ARP count, and error condition. `coex_sta` tracks BT-disabled/link/profile flags, IPS/LPS, high-priority task flag, C2H history/counters, inquiry/page, retry/RSSI/ext fields, BT TX/RX mask, and special packet period count. Register backups are volatile but critical for restoring normal Wi-Fi behavior after coexistence constraints.

Dependencies and integration: depends on the same Realtek `btc_coexist` callback table and rtlwifi debug infrastructure as the 8723B module. It integrates with mac80211 event notifications via the coexistence dispatcher, firmware H2C/C2H transport, BT register writes, and seq-file diagnostics. It also publishes coex-derived settings through `btc_set`, including BT traffic busy, TX/RX mask, scan-device-number increase, aggregation controls, and one-antenna RSSI adjust value.

Risks: one-antenna paths are very order-sensitive; wrong antenna state can starve either radio. The code has multiple early returns when `manual_control`, `stop_coex_dm`, `bt_disabled`, or 5 GHz is active, so callers must understand that some events are intentionally ignored. `ex_btc8821a1ant_halt_notify` sets `stop_coex_dm` before calling media disconnect; because media notify returns when stopped, BT may not receive disconnect channel info in that path. The callback stores C2H bytes into fixed 10-byte rows based on `length` without an explicit visible clamp. `btc8821a1ant_action_wifi_multi_port` tests `a2dp_exist` before `a2dp_exist && pan_exist`, making the combined branch unreachable in that block. The header also declares `ex_btc8821a1ant_pnp_notify` twice with different parameter names.

Test signals: compile coverage catches prototype drift and duplicate declaration tolerance. Runtime signals include H2C `0x60/0x61/0x63/0x65/0x66/0x69`, correct restore of backed-up ARFR/retry/AMPDU values, debug display showing TDMA case/coex table/BT counters/rate mask, successful scan/connect/DHCP/EAPOL/ARP under BT load, 5 GHz path leaving Wi-Fi unaffected, and clean sleep/wake/halt with antenna returning to BT or PTA as expected.

# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtlwifi/btcoexist/halbtc8821a1ant.h

Purpose: interface and state definition header for the RTL8821A one-antenna coexistence module. It defines BT firmware bitfields, RSSI tolerance, BT and Wi-Fi status enums, coexistence algorithm IDs, persistent decision/status structs, and external notification callbacks.

Important APIs/types/functions: `BT_INFO_8821A_1ANT_B_*` decodes BT C2H profile and busy flags. `BT_INFO_8821A_1ANT_A2DP_BASIC_RATE()` interprets extension bit 0. `enum _BT_INFO_SRC_8821A_1ANT`, `enum _BT_8821A_1ANT_BT_STATUS`, and `enum _BT_8821A_1ANT_WIFI_STATUS` define normalized source/state values. `enum BT_8821A_1ANT_COEX_ALGO` mirrors the profile-combination decision tree. `struct coex_dm_8821a_1ant` stores firmware, software, algorithm, TX-limit, and error state; `struct coex_sta_8821a_1ant` stores observed BT/Wi-Fi status. The `ex_btc8821a1ant_*` prototypes expose the callback surface, including debug control.

Control flow: no executable logic, but the declarations describe the one-antenna lifecycle: initialize hardware and coexistence DM, react to IPS/LPS/scan/connect/media/special packet/BT-info/halt/PNP/periodic events, and display debug state. The Wi-Fi status enum gives the C file labels for connected scan, special packet, idle, busy, and non-connected association/authentication policy branches.

State and persistence: `coex_dm_8821a_1ant` persists previous/current TDMA, ignore-WLAN-active, BT auto-report, LPS/RPWM, low penalty RA, coex table values, backed-up Wi-Fi ARFR/retry/AMPDU registers, algorithm, Wi-Fi channel info, current rate mask, ARFR/retry/AMPDU limit types, ARP count, and last error condition. `coex_sta_8821a_1ant` persists BT disabled/link/profile booleans, IPS/LPS, high-priority Wi-Fi task state, priority counters, BT RSSI, BT TX/RX mask, C2H history/counters, inquiry/page, retry count, and BT extension info.

Dependencies and integration: relies on common Realtek coexistence types and constants included before this header, especially `struct btc_coexist`, `struct seq_file`, `BIT*`, and Linux fixed-width integer aliases. The callback names are consumed by the rtlwifi coexistence operation table for RTL8821A 1-ant devices.

Risks: the file lacks an include guard in the visible content, unlike the 8723B header, so repeated direct inclusion would depend on higher-level include structure. `ex_btc8821a1ant_pnp_notify` is declared twice with different parameter names; this is harmless for C type checking but signals maintenance drift. Fixed 10-byte BT-info storage in the struct must match firmware C2H lengths. Enum additions must be synchronized with C switch statements and debug display expectations.

Test signals: compile all rtlwifi BT coexistence variants to verify declarations. Runtime debug output should expose coherent BT-info source counters, Wi-Fi/BT status values, TDMA case, ignore-WLAN-active state, rate mask, aggregation settings, and backed-up register values after init and during BT profile changes.
