## sources/control-plane/rook/pkg/operator/ceph/cluster/osd/volumes.go
Purpose: constructs Kubernetes volumes and mounts for PVC-backed OSDs, udev, device-mapper, and OSD encryption material. APIs include bridge mount helpers, `getDeviceMapperVolume()`, `getDataBridgeVolumeSource()`, `getPVCOSDVolumes()`, `getUdevVolume()`, and `Cluster.getEncryptionVolume()`. Control flow builds data, metadata, and WAL PVC volumes conditionally from `osdProperties`. Persistence behavior is security-sensitive: provisioning uses memory `emptyDir` bridge volumes, while running OSDs use hostPath bridge directories under `configDir/namespace/claimName` so Ceph lock files are shared between same-OSD pods and prevent concurrent corruption. Encryption uses a Secret volume by default with 0400 mode, but KMS-enabled clusters switch to memory `emptyDir` and writable mount. Dependencies include Kubernetes core volume APIs, KMS secret naming, Ceph config paths, and OSD property helpers. Risks include wrong bridge backing mode, KMS read-only mistakes, and hostPath path collisions.

Important APIs include `changedOrDeleted`, node, hot-plug ConfigMap, operator ConfigMap, floating-mon ConfigMap, and CephCluster watch predicates. ## sources/control-plane/rook/pkg/operator/ceph/config/probes.go
Purpose: applies user-configured health probe settings while preserving Rook-generated daemon-specific probe handlers. APIs include `ConfigureLivenessProbe()`, `ConfigureStartupProbe()`, and `GetProbeWithDefaults()`. Control flow leaves containers unchanged for nil probe specs, removes the corresponding probe when disabled, and otherwise merges desired probe values with the current default probe. The merge copies the desired probe, replaces its `ProbeHandler` with the current probe's handler, and fills zero-valued threshold/timing fields from the current probe. If current probe is nil, desired values are used and a warning is logged. State is only the returned container/probe spec; no persistence beyond eventual pod templates. Dependencies include Ceph API ProbeSpec and Kubernetes core Probe types. Risks include inability for users to override handler commands, zero values being interpreted as unspecified, and nil current probe losing generated daemon health checks.
