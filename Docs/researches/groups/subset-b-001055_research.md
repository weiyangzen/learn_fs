# sources/distributed-fs/ceph-client/drivers/block/drbd/drbd_receiver.c

## Purpose
Implements the DRBD receiver side of the replication protocol. This file owns connection establishment, feature/authentication negotiation, data-socket packet dispatch, meta-socket ack handling, incoming peer write/read/resync I/O, write-ordering epochs, bitmap exchange, UUID based resync decisions, split-brain recovery policy application, and connection teardown cleanup. It is the bridge between the wire protocol in `drbd_protocol.h`, request state transitions in `drbd_req.c`, lower block-device I/O, the resync bitmap/activity log, and the DRBD connection state machine.

## Important APIs, Types, And Functions
- `struct packet_info` is the decoded packet header carrier: command, payload size, volume number, and pointer to packet-specific data in the receive buffer.
- `enum finish_epoch` records whether `drbd_may_finish_epoch()` left an epoch alive, destroyed a non-current epoch, or recycled the current epoch.
- `drbd_alloc_pages()`, `drbd_alloc_peer_req()`, `drbd_free_peer_req()`, and `drbd_submit_peer_request()` allocate and submit peer-originated I/O buffers. Peer requests carry block id, interval, page chain, flags such as `EE_WRITE`, `EE_APPLICATION`, `EE_TRIM`, `EE_ZEROOUT`, `EE_SEND_WRITE_ACK`, and callbacks used after lower I/O completion.
- `drbd_try_connect()`, `prepare_listen_socket()`, `drbd_wait_for_connect()`, `conn_connect()`, `drbd_do_features()`, and `drbd_do_auth()` establish the data and meta sockets, resolve crossed connection attempts, negotiate protocol/features, and optionally run CRAM-HMAC authentication.
- `decode_header()`, `drbd_recv_header_maybe_unplug()`, `drbdd()`, and `drbd_cmd_handler[]` implement data-socket receive framing and command dispatch.
- `receive_Data()`, `receive_DataReply()`, `receive_RSDataReply()`, `receive_DataRequest()`, `receive_Barrier()`, `receive_bitmap()`, `receive_protocol()`, `receive_SyncParam()`, `receive_sizes()`, `receive_uuids()`, `receive_state()`, and `receive_sync_uuid()` are the main data-socket packet handlers.
- `drbd_may_finish_epoch()`, `drbd_flush()`, and `drbd_bump_write_ordering()` enforce or degrade write ordering across mirrored writes.
- `drbd_uuid_compare()`, `drbd_sync_handshake()`, `drbd_asb_recover_0p()`, `drbd_asb_recover_1p()`, and `drbd_asb_recover_2p()` decide whether to connect, resync, full-sync, or drop the link after UUID comparison and split-brain policy evaluation.
- `drbd_ack_receiver()`, `ack_receiver_tbl[]`, `got_BlockAck()`, `got_NegAck()`, `got_BarrierAck()`, `got_OVResult()`, `got_RqSReply()`, and `drbd_send_acks_wf()` process meta-socket pings, write/read acknowledgements, state-change replies, barrier acks, verify results, and delayed peer-request acks.

## Control Flow
The receiver thread starts in `drbd_receiver()`, repeatedly calls `conn_connect()` until a valid connection, unrecoverable incompatibility, or shutdown, then runs `drbdd()` on the data socket. `conn_connect()` opens both outgoing and listening sockets, assigns one to data and one to meta by exchanging `P_INITIAL_DATA` and `P_INITIAL_META`, handles simultaneous crossed connects with random retry, configures socket priorities/timeouts, negotiates features and authentication, sends protocol/configuration/state for every volume, transitions to `C_WF_REPORT_PARAMS`, starts the ack receiver, and creates the ordered ack-sender workqueue.

Data receive dispatch is table driven. `drbd_recv_header_maybe_unplug()` first tries a nonblocking header read; on empty receive buffers it quick-acks TCP and unplugs backend queues to reduce latency, then completes the read. `drbdd()` validates command number, fixed header size, optional payload allowance, and volume lookup before calling the relevant handler. Unknown non-optional packets or inconsistent lengths move the connection to protocol error.

Incoming mirrored writes enter `receive_Data()`. The handler verifies local disk access, receives the payload and optional integrity digest with `read_in_block()`, associates the request with the current write epoch, derives local bio flags from wire flags, sends early receive acks for protocol B semantics, handles two-primary sequence ordering/conflict resolution, queues the peer request on `active_ee` unless it is a synchronous trim/zeroout, waits for overlapping resync writes when sync target, protects local-only data by marking bitmap/activity-log state when peer disk is not usable, and submits the peer request. Completion later calls `e_end_block()` via `drbd_finish_peer_reqs()` to send `P_WRITE_ACK`, `P_RS_WRITE_ACK`, or `P_NEG_ACK`, remove interval-tree entries, restart postponed local conflicts, and release epoch activity.

Remote reads and resync reads are symmetric but distinct. `receive_DataReply()` finds a local application read request by block id and interval tree, receives the data directly into the original `master_bio`, validates optional digest, and raises `DATA_RECEIVED` in the request state machine. `receive_RSDataReply()` writes resync data to the local disk as a `sync_ee` peer request and sends `P_RS_WRITE_ACK` or `P_NEG_ACK` in `e_end_resync_block()`. `receive_DataRequest()` allocates a read peer request, handles application data requests, resync data requests, checksum resync requests, and online-verify requests, optionally throttles based on lower-device activity, calls `drbd_rs_begin_io()` for resync/verify extents, then submits lower read I/O whose worker callback sends the reply.

Write ordering uses epochs. Each incoming write increments `current_epoch->epoch_size` and `active`; `receive_Barrier()` records the peer barrier number and calls `drbd_may_finish_epoch()`. An epoch can be acknowledged only after all active writes complete and a barrier number is known, or during cleanup. Depending on configured ordering, the receiver may wait for all active peer I/O and submit lower-device flushes before acknowledging. If flush fails, `drbd_bump_write_ordering()` falls back from flush to drain or none according to backing-device capabilities.

Handshake and resync setup flow through protocol, sync params, sizes, UUIDs, state, bitmap, and sync-UUID packets. `receive_protocol()` verifies compatible protocol choices and split-brain policies, swaps a new RCU `net_conf`, and installs peer integrity digest state. `receive_SyncParam()` updates resync rate/planning fields and digest algorithms. `receive_sizes()` reconciles peer and local capacity, queue limits, online grow/shrink, and resize-triggered resync. `receive_uuids()` stores peer UUIDs and handles special initial-sync skip cases. `receive_state()` converts peer state into local perspective, invokes `drbd_sync_handshake()` when negotiation is needed, commits state via `_drbd_set_state()`, and persists metadata. `receive_bitmap()` merges plain or compressed peer bitmap data, sends the local bitmap when target, and starts resync when source.

The meta socket runs in `drbd_ack_receiver()`. It manages idle and ping timeouts, sends pings on demand, incrementally reads headers and fixed payloads, decodes commands through `ack_receiver_tbl[]`, and maps acks to request events. `got_BlockAck()` turns peer write/read/resync acks into `WRITE_ACKED_BY_PEER`, `RECV_ACKED_BY_PEER`, `CONFLICT_RESOLVED`, or `POSTPONE_WRITE`; `got_NegAck()` and negative reply handlers fail requests or resync I/O; `got_BarrierAck()` releases transfer-log epochs; state-change reply handlers wake waiters.

Teardown is centralized in `conn_disconnect()` and `drbd_disconnected()`: stop ack threads/workqueues, release sockets, wait for `active_ee`, `sync_ee`, and `read_ee`, cancel resync, flush sender work, finish queued peer requests, clear or keep the transfer log depending on suspension, sync metadata and bitmap, free peer UUIDs, and assert peer-request lists and page-pool counters are empty.

## State And Persistence
Persistent device/connection state touched here includes `connection->agreed_pro_version`, `agreed_features`, data/meta sockets, `net_conf` RCU pointer, digest transform/buffers, `current_epoch`, epoch list, `transfer_log` side effects through acks, `req_next`/ack tracking through request state, `p_uuid`, `p_size`, peer disk/role/connection state, bitmap bits, resync counters, online-verify counters, request timers, and metadata written by `drbd_md_sync()`.

Peer-request state is transient but critical: `active_ee`, `sync_ee`, `read_ee`, and `done_ee` lists track submitted incoming writes, resync writes, lower reads for peer replies, and completed requests awaiting ack-sender context. Page chains use `page->private`; `pp_in_use` counts receiver buffer pages. The code relies on `resource->req_lock`, `epoch_lock`, `peer_seq_lock`, RCU read sections, state mutexes, and workqueue context boundaries to keep these structures coherent.

Persistence-sensitive behavior includes setting out-of-sync bits on failed or unsafely replicated writes, clearing in-sync bits after acknowledged resync writes, writing the bitmap on disconnect, syncing metadata after state/size/UUID changes, preserving activity-log extents until both local and network sides are safe, and preventing thaw/resend when a peer reboot means old transfer-log assumptions are invalid.

## Dependencies And Integration Points
This file depends on kernel sockets, TCP options, bio submission, flush/discard/zeroout helpers, crypto shash/HMAC APIs, block queue limits, partition stats, mempools, workqueues, timers, RCU, wait queues, and DRBD interval trees. Internally it integrates with `drbd_req.c` via `req_mod()`/`__req_mod()` request events, with `drbd_main.c` for send helpers, transfer-log release/clear, bitmap send, socket allocation, and ack packets, with `drbd_worker.c` for lower-I/O completions and send/read callbacks, with `drbd_state.c` for state transitions and resync start/finish, with `drbd_bitmap.c` and `drbd_actlog.c` for bitmap/activity-log persistence, and with debug counters exposed elsewhere.

## Risks And Edge Cases
Packet-size validation, volume lookup, and digest handling are protocol-critical; a short read or malformed packet usually tears down the connection. Two-primary mode is especially sensitive: sequence-number waiting must order data and meta packets without deadlock, and conflict handling must correctly choose supersede, retry, postpone, or fail. Epoch/barrier handling is persistence-sensitive because acknowledging a barrier too early can allow activity-log extents to be dropped before data is stable on the peer.

Memory pressure is deliberate and dangerous: page allocations use `GFP_NOIO`/`GFP_TRY` to avoid recursive writeout in cross-replicated setups, but allocation failure usually forces reconnect. Discard/zeroout support has compatibility branches for older peers and unreliable backends. UUID comparison contains many historical protocol rules; wrong rule ordering can cause unnecessary full sync, missed split-brain, or connection to unrelated data. Teardown must drain multiple work/list paths in the right order or leave stale peer requests, page counters, or transfer-log requests.

## Test Signals
Useful signals include protocol feature negotiation across old/new header formats, authentication success/failure, simultaneous crossed data/meta connects, malformed packet lengths causing protocol error, mirrored write completion under protocols A/B/C, barrier ack after lower flush, fallback from flush to drain ordering, data-integrity digest mismatch, remote read retry completion, resync write ack and negative ack, compressed and plain bitmap receive, UUID rules for no-sync/bitmap-sync/full-sync/split-brain, two-primary conflicting writes producing superseded or retry acks, connection loss while suspended vs not suspended, and post-disconnect assertions that `active_ee`, `sync_ee`, `read_ee`, `done_ee`, `pp_in_use`, and `pp_in_use_by_net` are drained.

# sources/distributed-fs/ceph-client/drivers/block/drbd/drbd_req.c

## Purpose
Implements the lifecycle of DRBD primary-node application requests originating from the block layer. It creates `struct drbd_request` objects, decides local versus remote service paths, inserts requests into transfer-log and interval-tree structures, submits cloned local bios, queues network send work, processes all local/network completion events through a centralized state machine, completes upper-layer bios, updates dirty/in-sync bitmap state, manages activity-log references, performs congestion pull-ahead decisions, and enforces request timeouts.

## Important APIs, Types, And Functions
- `drbd_req_new()` allocates and initializes a request from an incoming `bio`, including interval metadata, operation flags (`RQ_WRITE`, `RQ_UNMAP`, `RQ_ZEROES`), lists, completion ref, and kref.
- `drbd_req_destroy()` is the terminal destructor. It validates that no local/network/completion references remain, removes transfer-log and interval-tree membership, updates bitmap state for writes, completes activity-log I/O when needed, and frees the request mempool object.
- `complete_master_bio()` and `drbd_req_complete()` decide when and how to complete the upper bio, including success if either local or remote path succeeded, read retry via `RQ_POSTPONED`, statistics, transfer-log epoch rollover, and marking the interval completed.
- `mod_rq_state()` is the reference-accounting core. It applies state-bit changes, increments or decrements completion refs/krefs/ap counters, updates cached transfer-log cursors, records ack/done timestamps, and calls completion/destruction when possible.
- `__req_mod()` is the request event state machine. It maps events such as `TO_BE_SENT`, `QUEUE_FOR_NET_WRITE`, `HANDED_OVER_TO_NETWORK`, `WRITE_ACKED_BY_PEER`, `BARRIER_ACKED`, `DATA_RECEIVED`, `POSTPONE_WRITE`, `RESEND`, and local I/O completions to state-bit transitions and worker queueing.
- `drbd_request_prepare()`, `drbd_send_and_submit()`, `__drbd_make_request()`, and `drbd_submit_bio()` form the block-layer submission path.
- `do_remote_read()`, `drbd_may_do_local_read()`, `remote_due_to_read_balancing()`, `drbd_should_do_remote()`, and `drbd_process_write_request()` decide whether a request needs local disk, peer I/O, or out-of-sync notification.
- `complete_conflicting_writes()` and `maybe_pull_ahead()` manage multi-primary local write ordering and congestion-driven ahead/behind behavior.
- `do_submit()`, `submit_fast_path()`, `prepare_al_transaction_nonblock()`, and `send_and_submit_pending()` are the submitter worker path for requests that need activity-log transaction preparation or discard/zeroout handling.
- `request_timer_fn()` monitors oldest local and network requests and triggers disk detach or connection timeout state changes.

## Control Flow
The block layer calls `drbd_submit_bio()`, which splits to queue limits, increments application bio accounting, and delegates to `__drbd_make_request()`. `drbd_request_prepare()` allocates the DRBD request, starts I/O accounting, optionally clones a private bio for the local backing device, assigns `drbd_request_endio`, and tries the fast activity-log path for non-empty writes. Discards and write-zeroes, or writes that cannot enter the activity log immediately, are queued to the submit worker with `drbd_queue_write()` and return without synchronous send/submission.

Fast-path requests enter `drbd_send_and_submit()`. Under `resource->req_lock`, writes first wait for overlapping local writes to complete and may trigger congestion handling. Suspended I/O causes `RQ_POSTPONED` and drops any private bio. Reads are failed early if neither local nor remote good data is available; otherwise `do_remote_read()` may drop the local clone for remote-only reads or keep it based on bitmap validity and read-balancing policy. Non-empty requests are added to the transfer log with the current transfer-log epoch; writes increment the current epoch write count. Writes queue remote data, out-of-sync notification, or no remote path via `drbd_process_write_request()`. Reads queue `P_DATA_REQUEST` if remote-only, otherwise local submission is enough. Local private bios are added to pending-completion lists and marked `TO_BE_SUBMITTED` before submission outside the lock.

All significant changes go through `__req_mod()`. Events set intention bits (`RQ_LOCAL_PENDING`, `RQ_NET_PENDING`), queue bits (`RQ_NET_QUEUED`), sent/done/ok bits, protocol expectation bits, and special bits such as `RQ_EXP_BARR_ACK`, `RQ_POSTPONED`, or `RQ_COMPLETION_SUSP`. Network queue events install worker callbacks (`w_send_dblock`, `w_send_read_req`, `w_send_out_of_sync`) on `connection->sender_work`. Handoff events clear queued state and, for protocol A writes, optimistically set `RQ_NET_OK`. Peer ack events clear pending state and set network success; barrier ack finalizes network done for writes. Negative acks and connection loss clear success/pending and/or set done. Frozen I/O restart events requeue disk I/O through `w_restart_disk_io`.

Completion requires both local and network paths to be no longer pending/queued and no completion suspension. `drbd_req_complete()` reports success if either local or remote side succeeded; failed non-readahead reads with transfer-log membership are marked postponed for retry instead of completing the upper bio. Writes may close the current transfer-log epoch before completion. `drbd_req_put_completion_ref()` is the gate that calls completion only when the completion ref hits zero, restarts postponed requests, or drops the final kref.

Slow-path submitter flow batches activity-log work. `do_submit()` drains `device->submit.writes`, tries fast-path AL entry, otherwise waits for nonblocking AL transaction slots, handles busy extents separately, commits the AL transaction, then submits and sends pending requests under a block plug. This keeps AL persistence grouped without starving cold extents behind busy ones.

Timeout flow runs in `request_timer_fn()`. It reads current network timeout/ko-count and disk timeout, identifies oldest pending local read/write and oldest network request waiting for ack or barrier, checks jiffies wrap-safe windows and recent reconnect/reattach grace periods, transitions the connection to `C_TIMEOUT` on peer timeout, forces local detach on disk timeout, and reschedules itself for the nearest relevant deadline.

## State And Persistence
Request state is encoded in `req->rq_state` bits declared in `drbd_req.h`. Important persistent side effects include transfer-log epoch membership (`req->epoch`, `connection->current_tle_nr`, `current_tle_writes`), interval-tree membership in `device->write_requests` or `device->read_requests`, activity-log membership (`RQ_IN_ACT_LOG`), bitmap dirty/in-sync updates in `drbd_req_destroy()`, and pending counters (`ap_pending_cnt`, `ap_in_flight`, `ap_actlog_cnt`, local pending lists, master completion lists).

Reference lifetime is split between `completion_ref` and `kref`. Each local pending, network pending, network queued, completion suspension, and initial caller path owns completion references; `RQ_EXP_BARR_ACK` owns an extra kref until network done. `mod_rq_state()` is intentionally the single place that should change these references. The upper bio pointer is nulled only when completion is handed to `complete_master_bio()` outside the spinlock.

Local persistence safety depends on delaying `drbd_al_complete_io()` until both local and network obligations for mirrored writes are complete. Failed or only partially replicated writes set out-of-sync bits before destruction; successful writes that the peer marked in-sync can clear bits. Suspended or postponed writes avoid bitmap mutation until the request really progresses or fails.

## Dependencies And Integration Points
This file depends on Linux bio APIs, block plugging, timers, mempools, krefs, atomic counters, interval trees, RCU configuration reads, wait queues, workqueues, and jiffies time helpers. DRBD dependencies include `drbd_req.h` state/event definitions, `drbd_int.h` structures and counters, sender callbacks in `drbd_worker.c`, local bio completion `drbd_request_endio()`, transfer-log cleanup/restart in `drbd_main.c`, state helpers in `drbd_state.c`, bitmap and activity-log helpers in `drbd_bitmap.c`/`drbd_actlog.c`, and receiver ack handlers in `drbd_receiver.c` that call `req_mod()` events.

## Risks And Edge Cases
The highest risk is incorrect reference accounting in `mod_rq_state()`, which can leak a request, complete an upper bio too early, or destroy a request while local endio or ack handling can still arrive. Protocol differences are subtle: protocol A marks network success on send handoff, protocol B waits for receive ack plus barrier, and protocol C waits for write ack plus barrier. Suspended I/O, `RQ_POSTPONED`, and read retry paths deliberately keep requests alive without completing the original bio.

Other edge cases include overlapping multi-primary writes, congestion pull-ahead entering `C_AHEAD` and switching from full remote writes to out-of-sync notifications, empty flushes mapped to DRBD barriers, local disk loss after private-bio clone creation, discard/zeroout local errors not detaching the disk, bitmap-valid local reads from otherwise inconsistent disks, and jiffies wrap behavior in timeouts. Any list membership change must stay under `req_lock` because cleanup, sender cancellation, local endio, and ack_receiver can race.

## Test Signals
Useful signals include local-only reads/writes, remote-only reads, mirrored writes under protocols A/B/C, local read error followed by remote retry, failed readahead without retry, local write error with peer success, peer negative ack with local success/failure, empty flush completion through `QUEUE_AS_DRBD_BARRIER`, discard/write-zeroes slow path, AL-busy submitter batching, overlapping primary writes waiting or restarting, suspended I/O then `RESEND`/restart, connection loss transfer-log cleanup, congestion threshold entering ahead/disconnecting behavior, and request timer transitions for peer and disk timeouts.

# sources/distributed-fs/ceph-client/drivers/block/drbd/drbd_req.h

## Purpose
Defines the DRBD request event vocabulary, request state-bit encoding, completion helper structure, and public request-state APIs used by the primary request path, receiver ack handling, transfer-log cleanup, and timers. The header documents the intended lifetime of `struct drbd_request`: creation on a primary, optional local and/or remote submission, transfer-log/list membership, conflict handling, local and peer completion, bitmap/activity-log cleanup, and final upper-bio completion/destruction.

## Important APIs, Types, And Functions
- `enum drbd_req_event` lists all state-machine inputs accepted by `__req_mod()`: creation/intention events, network queue/send/ack/failure events, conflict events, local completion/error events, disk abort/restart events, resend/frozen-I/O events, and no-op.
- `enum drbd_req_state_bits` defines bit positions for local state, network state, operation kind, activity-log membership, unplug hints, conflict postponement, completion suspension, and expected ack types.
- `RQ_LOCAL_*`, `RQ_NET_*`, `RQ_WRITE`, `RQ_UNMAP`, `RQ_ZEROES`, `RQ_IN_ACT_LOG`, `RQ_POSTPONED`, `RQ_COMPLETION_SUSP`, `RQ_EXP_RECEIVE_ACK`, `RQ_EXP_WRITE_ACK`, and `RQ_EXP_BARR_ACK` are the public bit masks manipulated by `drbd_req.c`, sender callbacks, receiver ack handlers, and cleanup paths.
- `MR_WRITE` and `MR_READ` are return flags used when transfer-log restart logic needs to count affected requests by operation type.
- `struct bio_and_error` is a stack carrier used by state transitions to return a bio plus final errno after dropping `req_lock`.
- `__req_mod()`, `_req_mod()`, and `req_mod()` are the state-transition entry points. The inline wrappers handle locking and delayed `complete_master_bio()`.
- Exported declarations connect request state to transfer-log epoch management (`start_new_tl_epoch()`, `tl_restart()`, `_tl_restart()`, `tl_abort_disk_io()`), destruction (`drbd_req_destroy()`), request timeout (`request_timer_fn()`), request retry (`drbd_restart_request()`), and remote-path eligibility (`drbd_should_do_remote()`).

## Control Flow
Callers that already hold `resource->req_lock` use `__req_mod()` directly when they also handle the returned `bio_and_error`, or `_req_mod()` when they want the wrapper to complete any returned bio after the state update. Callers outside the lock use `req_mod()`, which takes `req_lock` with IRQ save/restore, invokes `__req_mod()`, releases the lock, and then completes the master bio if requested.

The event and state-bit definitions encode the legal progression that `drbd_req.c` enforces. Local bits move from no local path to pending, completed ok/error, or aborted. Network bits move from no network path to pending, queued, sent, ok/failed, and done, with protocol-specific expectations for receive ack, write ack, and barrier ack. Operation bits distinguish reads from writes and special write operations so completion, bitmap, discard, and timeout behavior can branch without inspecting the original bio repeatedly.

## State And Persistence
The header itself stores no runtime state, but its bit layout is the persistence contract for in-memory request objects and transfer-log cleanup. `RQ_IN_ACT_LOG` means the activity log must be completed later; `RQ_NET_SIS` records that a peer set the range in-sync; `RQ_POSTPONED` suppresses final completion/destruction so retry logic can re-enter make-request; `RQ_COMPLETION_SUSP` prevents upper-bio completion while I/O is suspended; `RQ_EXP_BARR_ACK` accounts for an extra lifetime reference while a network write waits for its epoch barrier.

Because the comments define which bit combinations mean freeable, pending, failed, or acknowledged, changes to this header directly affect bitmap dirtying, upper-layer completion, transfer-log replay/cleanup, and whether local activity-log extents can be safely dropped after crashes.

## Dependencies And Integration Points
The header includes Linux module/slab/DRBD public headers and `drbd_int.h` for core structures. It is included by `drbd_req.c` for implementation, `drbd_receiver.c` for ack-to-event mapping, and `drbd_main.c` for transfer-log release/clear paths. The inline wrappers depend on `complete_master_bio()` being safe outside `req_lock` and on `__req_mod()` initializing `bio_and_error` before returning.

## Risks And Edge Cases
The state encoding is compact but non-obvious. Adding or reusing bits without auditing `RQ_LOCAL_MASK`, `RQ_NET_MASK`, destructor checks, and protocol-specific transitions can make requests complete early or never free. The wrapper comment that `__req_mod()` may free `req` is important: callers must not touch a request after invoking `_req_mod()`/`req_mod()` unless they hold another valid reference. Completion outside the spinlock is required because `bio_endio()` can re-enter block-layer paths and must not run under DRBD's request lock.

## Test Signals
Useful signals are compile-time coverage of every `enum drbd_req_event` switch case, lockdep-clean use of `req_mod()` from IRQ/BH/thread contexts, no use-after-free after `_req_mod()`, correct delayed bio completion outside `req_lock`, transfer-log cleanup handling `MR_WRITE`/`MR_READ`, and state-bit combinations observed in protocol A/B/C write completion, read retry, suspended I/O, barrier ack, and negative ack paths.
