# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8994.c

## Purpose
`wm8994.c` is the ALSA SoC codec component driver for the MFD-backed Wolfson WM8994 family, including WM8994, WM8958, and WM1811 variants. It binds to the `wm8994-codec` platform device created by the parent MFD, exposes three DAIs, builds the DAPM audio graph, manages audio interface clocks and FLLs, applies platform data for analogue routing and DSP/EQ/DRC presets, and handles headset/microphone/accessory detection.

## Important APIs, Types, and Functions
The driver state is `struct wm8994_priv`, declared in `wm8994.h`, and includes hub analogue state, parent `struct wm8994`, MCLK handles, AIF/FLL clock state, VMID and active reference counters, playback sample-rate state for ReTune Mobile, firmware pointers, and delayed work for accessory detection. Local helper tables include VU-bit register masks, DRC and EQ base registers, mic/jack detection rates, sample-rate values, fs ratios, BCLK divisors, and OPCLK divisors.

Clock and FLL APIs are centered on `configure_aif_clock()`, `configure_clock()`, `wm8994_get_fll_config()`, `_wm8994_set_fll()`, `wm8994_set_fll()`, `wm8994_set_mclk_rate()`, and `wm8994_set_dai_sysclk()`. DAI operations are `wm8994_set_dai_fmt()`, `wm8994_hw_params()`, `wm8994_aif3_hw_params()`, `wm8994_aif_mute()`, `wm8994_set_tristate()`, and `wm8994_aif2_probe()`. Bias and power sequencing flows through `wm8994_set_bias_level()`, `vmid_reference()`, `vmid_dereference()`, `wm8994_vmid_mode()`, `active_reference()`, and `active_dereference()`.

Control-plane callbacks include `wm8994_put_drc_sw()`, `wm8994_set_drc()`, DRC enum get/put handlers, `wm8994_set_retune_mobile()`, ReTune Mobile enum handlers, `wm8994_put_class_w()`, `wm8994_check_class_w_digital()`, and `wm8994_update_vu_bits()`. Accessory APIs exported to machine drivers are `wm8994_mic_detect()` and `wm8958_mic_detect()`. Component and platform registration use `wm8994_component_probe()`, `wm8994_component_remove()`, `wm8994_probe()`, `wm8994_remove()`, `wm8994_suspend()`, and `wm8994_resume()`.

## Control Flow
The platform probe allocates `wm8994_priv`, gets optional `MCLK1` and `MCLK2`, enables runtime PM, and registers the ASoC component with three DAIs. Component probe attaches the parent's regmap, initializes delayed work and completions, configures revision-specific hub quirks, requests FIFO/thermal/mic/jack/FLL/DC-servo IRQs, reads GPIO state to decide whether AIF LRCLKs are shared, latches volume-update bits, enables variant-specific defaults, applies platform data, adds controls/widgets/routes, and initializes WM8958 DSP2 where applicable.

At runtime, machine drivers select the DAI clock source with `.set_sysclk()` and optional FLL settings with `.set_pll()`. `_wm8994_set_fll()` validates the requested FLL, refuses to reconfigure an FLL currently supplying SYSCLK, disables and reprograms FLL registers, optionally enables an external MCLK parent, manages active/VMID references during FLL startup or shutdown, waits for an IRQ-backed FLL lock completion when available, updates cached FLL state, then recomputes AIF and SYSCLK routing. `configure_clock()` programs both AIF clocks and picks the higher AIF clock as `CLK_SYS`, triggering DAPM sync if the SYSCLK source bit changes.

DAI format setup writes master/slave, serial format, BCLK/LRCLK inversion, and WM8958/WM1811 AIF3 mirror settings. `wm8994_hw_params()` selects word length, sample rate field, closest AIFCLK/fs ratio, BCLK divisor, LRCLK divider, mono DSP mode when needed, split or shared LRCLK registers, channel clocking limits from platform data, and ReTune Mobile presets for playback rates. DAPM supply events turn MCLKs on and off, enable AIF ADC/DAC paths according to channel-source settings, update VU bits after power-up, and handle older revision late-clock ordering through deferred flags and post events.

Accessory detection follows different paths per variant. WM8994 `wm8994_mic_detect()` configures MICBIAS pins, enables MICD, and schedules `wm8994_mic_work()` from mic detect/short IRQs to read raw interrupt state and report headset/headphone/button status. WM8958/WM1811 `wm8958_mic_detect()` can use jackdet first, then delayed `wm1811_mic_work()` starts impedance detection; `wm8958_mic_irq()` debounces valid MICD readings, rejects transient removals, queues `wm8958_mic_work()` for mic identification, or reports button events. `wm1811_jackdet_irq()` manages mechanical insertion/removal, debounce, MICBIAS discharge, delayed mic detection, and forced jack report refreshes.

## State and Persistence
Persistent runtime state is stored in `wm8994_priv` and the MFD regmap. Clock state includes selected SYSCLK source per AIF, current MCLK rates, computed AIF clocks, saved AIF divider overrides used for very low SYSCLK detection, channel counts, FLL source/input/output, suspend copies of FLL settings, and FLL lock completions. Power state includes VMID and active reference counts, VMID mode, jackdet mode, `clk_has_run`, and late AIF clock enable/disable flags. Audio processing state tracks DRC, ReTune Mobile, MBC, VSS, HPF, enhanced EQ and firmware selections.

Register persistence is split between the parent MFD regmap and ASoC/DAPM state. The component probe writes hardware defaults and latches VU bits. Suspend saves active FLL configurations, shuts FLLs down, and forces component bias off; resume restores saved FLLs. Runtime PM references are taken around VMID use and jack/mic work. Firmware pointers are released in component remove, and `cur_fw` is cleared when bias transitions from standby to off.

## Dependencies and Integration Points
The driver depends on ASoC core, DAPM, jack reporting, runtime PM, the common clock framework, firmware loading, workqueues, completions, tracepoints, and the WM8994 MFD core/register/pdata/GPIO headers. It integrates with `wm_hubs` for analogue controls/routes, Class W, VMID, and DC servo handling, and with WM8958 DSP helpers declared in the local header. Machine drivers interact through DAI ops, exported mic detection helpers, exported VMID mode control, platform data (`struct wm8994_pdata`), optional external mic IRQs, optional MCLK clocks, and the parent MFD IRQ/regmap services.

## Risks
The file is highly variant-sensitive: many branches depend on chip type, revision, customer ID, GPIO function, and platform data, so regressions can be board-specific. `wm8994_mic_detect()` appears to force or disable `"MICBIAS1"` in both the MICBIAS1 and MICBIAS2 cases, which may be intentional legacy behavior or a copy/paste risk for MICBIAS2 users. Accessory detection uses multiple delayed works and IRQs; it has explicit deadlock avoidance around `cancel_delayed_work_sync()`, but stale work during remove or rapid unplug paths is still a high-risk area. FLL reconfiguration must avoid active SYSCLK users and balances MCLK, active, and VMID references; failures after disabling an old MCLK or before updating cached FLL state can be delicate. `wm8994_hw_params()` picks the nearest AIFCLK/fs ratio and the closest non-underflowing BCLK divisor, which can silently produce approximate clocks if board clocks are imprecise. Several platform-data enum handlers index configuration arrays by user-selected values and depend on platform-provided names/rates being consistent.

## Test Signals
Useful tests include probing all supported variants and revisions, verifying MFD regmap attachment, exercising MCLK1/MCLK2/FLL1/FLL2/OPCLK selections, FLL start/stop/bypass/lock-timeout paths, suspend/resume FLL restore, DAI formats I2S/left/right/DSP_A/DSP_B with valid and invalid inversion combinations, word widths 16/20/24/32 and unsupported widths, 8 kHz through 96 kHz rates, shared versus split LRCLK GPIO configurations, one/two/four-channel clocking constraints, DAPM AIF clock power sequencing on old and new revisions, VMID normal/force transitions, ReTune Mobile and DRC platform controls, mic/headphone/button detection with jack insertion/removal races, thermal/FIFO IRQ logging, and component remove cleanup of IRQs, work, firmware, and allocated text arrays.

# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8994.h

## Purpose
`wm8994.h` is the private interface shared by the WM8994-family codec implementation and companion WM8958 DSP/accessory code. It defines clock and FLL identifiers used by DAI ops, public helper prototypes consumed by machine or sibling codec code, callback types for custom WM1811/WM8958 mic detection, and the full private state structure used by `wm8994.c`.

## Important APIs, Types, and Functions
The clock constants define MCLK indexes (`WM8994_MCLK1`, `WM8994_MCLK2`), SYSCLK sources for `.set_sysclk()` (`WM8994_SYSCLK_MCLK1`, `WM8994_SYSCLK_MCLK2`, `WM8994_SYSCLK_FLL1`, `WM8994_SYSCLK_FLL2`, and `WM8994_SYSCLK_OPCLK`), FLL IDs (`WM8994_FLL1`, `WM8994_FLL2`), and FLL reference sources (`WM8994_FLL_SRC_MCLK1`, `MCLK2`, `LRCLK`, `BCLK`, `INTERNAL`). `enum wm8994_vmid_mode` exposes normal and force modes for VMID handling.

Exported declarations are `wm8994_mic_detect()`, `wm8958_mic_detect()`, `wm8994_vmid_mode()`, `wm8958_aif_ev()`, and `wm8958_dsp2_init()`. The callback typedefs `wm1811_micdet_cb` and `wm1811_mic_id_cb` let board-specific code replace default mic/accessory identification. `struct wm8994_micdet` stores a jack pointer and transient detecting flag for each mic bias. `struct wm8994_fll_config` stores the source, input rate, and output rate for an FLL. `struct wm8994_priv` is the central private state object for the codec component.

## Control Flow
The header itself has no executable control flow, but it defines the contracts used by `wm8994.c`. Machine drivers pass these clock/FLL constants into ASoC DAI callbacks; `wm8994.c` stores the selections in `struct wm8994_priv`, computes register programming, and restores FLL state across suspend. Accessory detection setup stores jack pointers and optional callbacks in the private object, then IRQ and delayed-work paths consume that state to report jack events. DSP helper functions declared here are called from DAPM events and component probe to coordinate WM8958-specific DSP behavior.

## State and Persistence
`struct wm8994_priv` persists nearly all runtime codec state. It embeds `struct wm_hubs_data`, references the parent MFD `struct wm8994`, carries optional `clk_bulk_data` entries for two MCLKs, records per-AIF SYSCLK selection/rates, MCLK rates, derived AIF clocks, low-clock divider saves, active channel counts, live and suspend FLL configs, FLL lock completions, and flags for FLL IRQ availability, bypass support, and clock bootstrap status.

Power and routing state includes VMID reference count, active reference count, selected VMID mode, DAC playback rates, LRCLK sharing flags, and late AIF clock enable/disable bits. Audio enhancement state includes arrays for DRC, ReTune Mobile, MBC, HPF, VSS, and enhanced EQ enable/configuration plus associated `soc_enum` structures and text arrays. Accessory state includes an accessory-detection mutex, two micdet slots, delayed works, cached mic status, mic/jack booleans, button masks, jackdet state/mode, IRQ number, callbacks, and callback data. Firmware state is protected by `fw_lock` and includes active DSP count plus firmware pointers for current, MBC, MBC+VSS, and enhanced EQ images.

## Dependencies and Integration Points
The header depends on Linux clock, firmware, completion, workqueue, and mutex APIs plus ASoC declarations and local `wm_hubs.h`. It exposes interfaces used across `wm8994.c`, WM8958 DSP support, and board or machine drivers that configure jack detection or VMID mode. It also couples private state to the parent MFD definitions through the forward-declared `struct wm8994`.

## Risks
Because `struct wm8994_priv` is shared across clocking, DAPM, firmware, and accessory detection paths, field ownership is implicit and concurrency-sensitive. Many members are protected only by higher-level ASoC serialization, runtime PM, `accdet_lock`, or `fw_lock`; misuse from sibling code can race delayed work or DAPM transitions. The exported clock constants are ABI-like for machine drivers, so renumbering them would break board code. Text-array pointers for platform EQ/DRC controls mix devm-managed, heap-managed, and platform-owned memory, requiring remove paths to free only what the driver owns.

## Test Signals
Tests should compile both built-in and module configurations, verify all exported prototypes match definitions, exercise external users of mic detection and VMID mode, validate FLL suspend/restore copies, run lockdep around accessory detection and firmware paths, and probe with and without optional MCLKs, jack callbacks, platform EQ/DRC presets, and external mic IRQs.

# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8995.c

## Purpose
`wm8995.c` is the standalone ALSA SoC codec driver for the Wolfson WM8995. Unlike the MFD-backed WM8994-family driver, it owns its I2C/SPI regmap setup directly, manages codec regulators, exposes three DAIs, defines mixer controls and DAPM routes, programs AIF clocking and FLLs, and sequences headphone, Class W, bias, and register-cache behavior.

## Important APIs, Types, and Functions
`struct wm8995_priv` stores the regmap, per-AIF SYSCLK selections, MCLK input rates, derived AIF clocks, live and suspend FLL configs, eight regulators, disable notifiers, and the active component pointer. `wm8995_reg_defaults[]`, `wm8995_readable()`, `wm8995_volatile()`, and `wm8995_regmap` define the 16-bit register map and `REGCACHE_MAPLE` policy. Regulator disable callbacks are generated by `WM8995_REGULATOR_EVENT(n)` and mark the regcache dirty when a supply is disabled.

Audio control and power helpers include `wm8995_update_class_w()`, `wm8995_put_class_w()`, `hp_supply_event()`, `hp_event()`, and `dc_servo_cmd()`. Clocking and DAI callbacks include `configure_aif_clock()`, `configure_clock()`, `clk_sys_event()`, `wm8995_aif_mute()`, `wm8995_set_dai_fmt()`, `wm8995_hw_params()`, `wm8995_set_tristate()`, `wm8995_get_fll_config()`, `wm8995_set_fll()`, `wm8995_set_dai_sysclk()`, and `wm8995_set_bias_level()`. Bus entry points are `wm8995_spi_probe()`, `wm8995_i2c_probe()`, `wm8995_modinit()`, and `wm8995_exit()`.

## Control Flow
Module init registers the I2C driver when I2C is enabled and the SPI driver when SPI master support is enabled. Each bus probe allocates private state, initializes a bus-specific regmap using the shared regmap config, stores driver data, and registers the ASoC component and three DAI drivers. Component probe requests regulator supplies, registers supply-disable notifiers, enables supplies, reads and validates the device ID, resets the chip, latches volume update bits, and initializes Class W state.

Machine drivers configure AIF1 or AIF2 via `.set_sysclk()`, `.set_pll()`, `.set_fmt()`, and `.hw_params()`. `configure_aif_clock()` selects MCLK1/MCLK2/FLL1/FLL2 for an AIF, halves clocks at or above 13.5 MHz, writes AIF clock source/divider bits, and caches the resulting AIF clock. `configure_clock()` updates both AIF clocks and switches `CLK_SYS` to the higher one, then asks DAPM to resync if the source changed. `wm8995_set_fll()` validates FLL ID/source, recomputes dividers, gates both AIF clocks, disables and reprograms the target FLL, optionally enables it, updates cached FLL state, restores previously enabled AIF clocks, and recomputes SYSCLK.

`wm8995_set_dai_fmt()` programs codec/provider mode, I2S/left/right/DSP formats, and legal inversion combinations. `wm8995_hw_params()` chooses register targets for AIF1/AIF2 and playback/capture LRCLK, calculates BCLK from PCM params, validates 16/20/24/32-bit widths and supported sample rates, picks the closest AIFCLK/fs ratio, selects the highest BCLK divisor that does not under-clock the target BCLK, computes LRCLK ratio, and writes word-length, BCLK, LRCLK, and sample-rate fields. DAPM routes connect DMICs, analogue IN1 PGAs, AIF mixers, sidetone, DAC mixers, headphone output, PDM speaker drivers, and clock supplies. Headphone DAPM events enable the charge pump, headphone stages, DC servo startup, output shorts removal, and shutdown sequencing.

## State and Persistence
The regmap cache holds register state while supplies are off; regulator disable notifiers mark it dirty and `wm8995_set_bias_level()` syncs it when transitioning from off to standby after enabling supplies. Bias off disables the bandgap and all supplies. The driver stores live FLL source/input/output but does not implement component suspend/resume restoration despite having `fll_suspend` fields in `struct wm8995_priv`. AIF clocks and MCLK rates are cached in memory and recomputed during DAPM clock events or sysclk/FLL changes. Headphone and DC servo state is programmed directly by DAPM events and observed via a volatile DC servo readback register.

## Dependencies and Integration Points
The driver depends on Linux module, I2C, SPI, regmap, regulator, delay, slab, and ASoC APIs plus the generated local `wm8995.h` register definitions. It integrates with machine drivers through three DAIs named `wm8995-aif1`, `wm8995-aif2`, and `wm8995-aif3`. AIF1/AIF2 support sysclk, format, hw_params, mute, FLL, and tristate callbacks; AIF3 exposes only tristate. It depends on board descriptions providing the eight named regulators and suitable MCLK/FLL clock rates through DAI configuration.

## Risks
`wm8995_set_dai_fmt()` always writes AIF1 format and master registers, even when called for DAI id 1/AIF2, which is a notable behavioral risk if AIF2 format is expected to be independently configurable. `wm8995_hw_params()` divides by `lrclk` for debug output without checking that `bclk_rate / params_rate()` is nonzero; bad or missing AIF clocks can therefore risk divide-by-zero or invalid LRCLK programming. `wm8995_modinit()` can overwrite an I2C registration failure with the SPI registration result, and if SPI registration fails after I2C succeeds it returns failure without unregistering I2C. Component probe error handling disables regulators on ID/reset failure, but if `regcache_sync()` fails in a later standby transition the regulators remain enabled. Capture rates are limited to 48 kHz while playback allows 96 kHz; tests must ensure machine constraints reflect this. The unused `fll_suspend` fields may indicate missing suspend/resume handling or legacy residue.

## Test Signals
Test signals include I2C and SPI probe success/failure, invalid device ID and reset failures, missing regulator handling, regulator disable notifier dirtying and regcache sync after off-to-standby, DAI format calls for both AIF1 and AIF2, all supported sample widths and rates plus unsupported values, zero or unconfigured AIFCLK handling, FLL1/FLL2 start/stop/reconfiguration from MCLK/LRCLK/BCLK, AIF clock restoration after FLL programming, mute and tristate callbacks for all DAIs, headphone DAPM power-up/down with DC servo timeout handling, Class W enable/disable when DAC mixer routes diverge, readable/volatile register coverage, and module init cleanup behavior when only one bus backend is enabled or one registration path fails.
