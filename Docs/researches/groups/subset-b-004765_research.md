# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_eeprom.c

Purpose: Implements the AR9300/AR9003 EEPROM backend for ath9k. It owns compiled-in EEPROM templates, restore/decompression from flash/EEPROM/OTP, EEPROM parameter accessors, board-value programming, regulatory target power calculation, open-loop calibration, PAPRD power adjustment, debugfs EEPROM dumping, and the `eep_ar9300_ops` vtable consumed by common ath9k hardware code.

Important APIs and functions: The exported integration surface is `const struct eeprom_ops eep_ar9300_ops`, with callbacks for `check_eeprom`, `get_eeprom`, `fill_eeprom`, `dump_eeprom`, version/revision, `set_board_values`, `set_addac`, `set_txpower`, `get_spur_channel`, and `get_eepmisc`. Externally visible helpers include `ar9003_hw_ant_ctrl_common_get()`, `ar9003_hw_ant_ctrl_common_2_get()`, `ar9003_get_spur_chan_ptr()`, `ar9003_get_paprd_rate_mask_ht20()`, `ar9003_get_paprd_rate_mask_ht40()`, `ar9003_get_paprd_scale_factor()`, `ar9003_hw_internal_regulator_apply()`, `ar9003_hw_tx_power_regwrite()`, `ar9003_hw_get_tx_gain_idx()`, and `ar9003_hw_get_rx_gain_idx()`. Major internal paths include `ar9300_eeprom_restore_internal()`, `ar9300_compress_decision()`, `ath9k_hw_ar9300_set_board_values()`, `ath9k_hw_ar9300_set_txpower()`, `ar9003_hw_set_power_per_rate_table()`, and `ar9003_hw_calibration_apply()`.

Control flow: EEPROM fill starts in `ath9k_hw_ar9300_fill_eeprom()`, which calls `ar9300_eeprom_restore_internal()` into `ah->eeprom.ar9300_eep`. If flash-backed storage is selected, the restore path reads the raw structure and accepts it when `txrxMask` is neither zero nor all ones. Otherwise it seeds the destination with `ar9300_default`, probes EEPROM base addresses and then OTP base addresses, walks compressed blocks backward, validates each header and checksum, and either copies uncompressed payloads or applies block deltas against a referenced compiled-in template. `ath9k_hw_ar9300_get_eeprom()` maps common `enum eeprom_param` queries to MAC address, regulatory domain, op flags, masks, PAPRD, antenna diversity, and antenna gain fields. Board-value setup is channel driven: `ath9k_hw_ar9300_set_board_values()` selects 2 GHz or 5 GHz modal data, then programs XPA timing/bias, antenna switch tables, drive strength, XLNA bias, attenuation, quick-drop, internal regulator, tuning capacitors, min CCA power thresholds, TX end-to-XPA timing, thermometer, and OTP therm calibration. TX power setup first interpolates target powers from EEPROM frequency piers, applies CTL/regulatory/MCI limits per rate class, adjusts PAPRD rate masks and scale, updates regulatory max power, writes PHY TX power registers, applies calibration, stores PAPRD target power, sets self-generated frame power, and optionally enables TPC tables.

State and persistence: Persistent source data comes from device EEPROM, OTP, or flash and is restored into `ah->eeprom.ar9300_eep`; compiled-in templates (`ar9300_default`, `ar9300_x112`, `ar9300_h116`, `ar9300_h112`, `ar9300_x113`) are fallback/reference state for compressed deltas. Runtime hardware state is written through register macros for PHY, RTC, PMU, antenna, TPC, PAPRD, and power tables. Driver state mutations include `ah->nf_2g`/`ah->nf_5g` calibration and power arrays, `ah->paprd_target_power`, `ah->paprd_ratemask`, `ah->paprd_ratemask_ht40`, `ah->paprd_table_write_done`-dependent power choices, and `ath_regulatory(ah)->max_power_level`. No durable state is written by this file, but the restored EEPROM image and register programming must remain coherent across channel resets.

Dependencies and integration points: Depends on `hw.h`, `ar9003_phy.h`, `ar9003_eeprom.h`, `ar9003_mci.h`, unaligned access helpers, ath9k register macros (`REG_READ`, `REG_WRITE`, `REG_RMW_FIELD`), EEPROM/NVRAM access (`ath9k_hw_nvram_read`, `ath9k_hw_use_flash`), OTP registers, regulatory helpers (`ath9k_hw_get_scaled_power`, `ath9k_hw_update_regulatory_maxpower`), channel helpers, MCI coexistence power limits, PAPRD predicates, and debugfs print macros. `ar9003_hw.c` uses the tx/rx gain index accessors to choose init tables, PHY calibration code consumes spur and PAPRD getters, and common ath9k init/reset code calls the EEPROM ops.

Risks: The compressed EEPROM parser trusts compact hardware blobs; header length, checksum, and bounds checks are critical because bad `length` or `reference` values can select wrong templates or write outside expected restore regions. Several callbacks are stubs or placeholders (`ath9k_hw_ar9300_check_eeprom()` always succeeds, `ath9k_hw_ar9300_get_eeprom_rev()` returns zero, `ath9k_hw_ar9300_get_spur_channel()` returns no spur, `set_addac` is empty), so callers must not assume full validation or spur filtering from this layer. Power-limit logic combines EEPROM targets, CTL edges, regulatory scaled power, MCI caps, PAPRD adjustments, and TPC; off-by-one rate indexes or wrong 2 GHz/5 GHz center frequencies can violate regulatory constraints. Register programming is silicon-revision-specific and many paths branch on `AR_SREV_*`, making unsupported revision combinations risky. Some PMU/internal regulator waits loop until fields change and can delay if hardware does not settle.

Test signals: Exercise EEPROM restore from flash, EEPROM, and OTP; compressed-none and compressed-block records; bad headers, bad checksums, invalid template references, and length boundaries including AR9485's shorter data length. Validate `get_eeprom` parameters, tx/rx gain index extraction, antenna switch programming for 1/2/3-chain and BT antenna diversity configurations, internal regulator paths across AR9330/AR9485/AR9462/AR9550/AR9565/QCA9561, and tuning/quick-drop/min-CCA feature bits. For TX power, test 2 GHz CCK/OFDM/HT20/HT40 and 5 GHz OFDM/HT20/HT40 channels, CTL exact and inband edge matches, `SD_NO_CTL`, MCI caps, PAPRD enabled/disabled, TPC enabled/disabled, and calibrated noise floor updates.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_eeprom.h

Purpose: Defines the packed AR9300 EEPROM binary layout and constants used by the AR9003 ath9k EEPROM implementation. It describes regulatory domains, modal headers, calibration piers, target power tables, CTL edge tables, base extensions, OTP register addressing, PAPRD masks, rate indexes, and exported EEPROM helper prototypes.

Important APIs and types: Key constants include `AR9300_EEP_VER`, `AR9300_EEP_START_LOC`, calibration pier counts, target power counts, CTL counts, `AR9300_MAX_CHAINS`, `AR9300_EEPROM_SIZE`, base EEPROM addresses, OTP register selectors, PAPRD mask/scale fields, and noise power conversion macros. Rate enumerations map EEPROM target-power slots to legacy, CCK, HT20, HT40, and combined `ar9300RateSize` indexes. Main packed structs are `ar9300_base_eep_hdr`, `ar9300_modal_eep_header`, `ar9300_cal_data_per_freq_op_loop`, `cal_tgt_pow_legacy`, `cal_tgt_pow_ht`, `cal_ctl_data_2g`, `cal_ctl_data_5g`, `ar9300_BaseExtension_1`, `ar9300_BaseExtension_2`, and the top-level `ar9300_eeprom`. Prototypes expose gain index lookups, antenna common values, spur pointers, PAPRD masks/scale, internal regulator application, and TX power register writes.

Control flow: The header has no executable flow, but its layout drives `ar9003_eeprom.c` restore, board application, calibration interpolation, regulatory power calculation, and debug dumping. The top-level `ar9300_eeprom` order mirrors the serialized EEPROM image: version/MAC/customer data, base header, 2 GHz modal and calibration/target/CTL data, then 5 GHz modal and calibration/target/CTL data. The OTP register macros pick different register blocks for AR9340/AR9550 versus other AR9300-family chips.

State and persistence: This file defines persistent on-device EEPROM schema, including little-endian fields stored in packed structs and hardware-calibration arrays. `featureEnable`, `miscConfiguration`, `txrxgain`, modal antenna fields, power targets, and calibration pier data persist in EEPROM/OTP/flash and are copied into `ath_hw`. The header itself owns no mutable state.

Dependencies and integration points: Includes Linux integer types and relies on ath9k shared constants such as `AR_EEPROM_MODAL_SPURS`, `FREQ2FBIN`, CTL edge macros, and silicon revision predicates supplied through including C files. It is consumed by `ar9003_eeprom.c`, `ar9003_hw.c` for gain indexes, PHY/PAPRD code for rate masks and spur channels, and common ath9k EEPROM interfaces.

Risks: Packed struct layout is an ABI with EEPROM blobs; field reordering, type-size changes, endian mistakes, or count changes would corrupt reads. Rate enumerations and `ar9300RateSize` must remain aligned with TX power arrays and register writes. OTP address macros are revision-sensitive. The comment for `misc_enable` bits in `ar9300_BaseExtension_1` is operationally important because several board-value paths gate min-CCA and checksum behavior on those bits.

Test signals: Compile-time size/layout checks against known EEPROM blobs, endian conversion review for every `__le16` and `__le32` field, restore/dump comparison against template data, validation of all rate indexes through `ar9003_hw_tx_power_regwrite()`, and silicon-revision tests for OTP base/status/read-data address macros.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_hw.c

Purpose: Provides AR9003-family hardware attachment setup for ath9k. It selects revision-specific INI register tables, chooses EEPROM-driven TX/RX gain tables, configures PCIe power-save SerDes settings, enables hardware hang checks, detects MAC hangs, and attaches AR9003 PHY, calibration, MAC, and AIC operation sets.

Important APIs and functions: The external entry point is `ar9003_hw_attach_ops(struct ath_hw *ah)`. Important internal helpers are `ar9003_hw_init_mode_regs()`, `ar9003_hw_init_mode_gain_regs()`, `ar9003_tx_gain_table_apply()`, `ar9003_rx_gain_table_apply()`, the per-mode gain table selectors, `ar9003_hw_configpcipowersave()`, `ar9003_hw_init_hang_checks()`, `ath9k_hw_verify_hang()`, and `ar9003_hw_detect_mac_hang()`. The file sets private ops `init_mode_gain_regs`, `init_hang_checks`, `detect_mac_hang` and public op `config_pci_powersave`.

Control flow: During attach, `ar9003_hw_attach_ops()` first calls `ar9003_hw_init_mode_regs()` to bind `ath_hw` INI arrays based on silicon revision. The large revision cascade covers AR9330 1.1/1.2, AR9340, AR9485, AR9462 2.0/2.1, AR9550, QCA9531, QCA9561, AR9580, AR9565 1.0/1.1, and default AR9300 2.2. It selects MAC, baseband, radio, SOC, fast-clock, DFS, Japan CCK FIR, PCIe SerDes, additional crystal, and default gain tables. Later reset/init paths call `init_mode_gain_regs`, which reads EEPROM tx/rx gain indexes through `ar9003_hw_get_tx_gain_idx()` and `ar9003_hw_get_rx_gain_idx()` and swaps in the matching gain table. PCIe power-save writes selected SerDes rows, with an AR9462 ASPM L1 fix and restore/power-off distinction. Hang detection samples DMA debug registers for queues stuck in `WAIT_FRDONE` with complete state `0x1`, then re-reads up to `NUM_STATUS_READS` times to verify a stable signature.

State and persistence: Mutates many `ath_hw` INI array descriptors (`iniMac`, `iniBB`, `iniRadio`, `iniSOC`, `iniModesRxGain`, `iniModesTxGain`, fast-clock/DFS/additional/SerDes arrays), operation tables, `ah->config.hw_hang_checks`, `ah->bb_watchdog_timeout_ms`, `ah->WARegVal` application, and PCIe/SerDes registers. The state is runtime hardware configuration, reconstructed on attach/reset, not durable persistence.

Dependencies and integration points: Includes all AR9003-family initval headers for supported revisions plus `hw.h` and `ar9003_mac.h`. It depends on silicon revision macros, `INIT_INI_ARRAY`, EEPROM gain index helpers from `ar9003_eeprom.c`, register access macros, PCIe power-save config flags, DMA debug register definitions, and attach functions from PHY, calibration, MAC, and AIC modules. It is the bridge that binds this family into common ath9k hardware ops.

Risks: Revision ordering is critical; a broader `AR_SREV_*` branch before a narrower one would load wrong init tables. Missing `iniPcieSerdes` arrays for PCOEM chips are guarded only by warnings. Gain table indexes outside the mode array fall back to mode 0 for TX but RX uses a switch default; bad EEPROM gain fields can silently select conservative defaults. PCIe power-save writes raw init arrays and the AR9462 ASPM fix rewrites a magic config register. MAC hang detection relies on debug-state signatures and can false-positive if sampled during a legitimate long TX state, although repeated reads reduce that risk.

Test signals: Probe/reset each supported silicon revision and verify selected INI arrays, crystal-frequency additional arrays, fast-clock/DFS/Japan FIR tables, and PCIe SerDes arrays. Test EEPROM tx/rx gain modes 0-7 and fallback handling. Exercise PCIe power-save enter/restore with PLL power-save flags. For hang detection, inject or observe DMA debug states for stuck and non-stuck TX queues, including queues 0-5 from `AR_DMADBG_4` and 6-9 from `AR_DMADBG_5`.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_mac.c

Purpose: Implements AR9003 MAC/EDMA descriptor operations for ath9k. It builds TX control descriptors, updates descriptor links and checksums, decodes interrupt status, processes TX status-ring entries, decodes EDMA RX status descriptors, programs RX data pointers and buffer size, and sets up the TX status ring.

Important APIs and functions: `ar9003_hw_attach_mac_ops()` installs MAC callbacks into `ath_hw_ops`: `rx_enable`, `set_desc_link`, `get_isr`, `set_txdesc`, `proc_txdesc`, and `get_duration`. Exported symbols are `ath9k_hw_set_rx_bufsize()`, `ath9k_hw_addrxbuf_edma()`, `ath9k_hw_process_rxdesc_edma()`, and `ath9k_hw_setup_statusring()`. Key internal helpers include `ar9003_set_txdesc()`, `ar9003_calc_ptr_chksum()`, `ar9003_hw_set_desc_link()`, `ar9003_hw_get_isr()`, `ar9003_hw_proc_txdesc()`, and `ar9003_hw_get_duration()`.

Control flow: TX descriptor setup writes descriptor metadata, link and up to four buffer pointers/lengths, computes the pointer checksum, fills rate retries and rate codes for first/last descriptors, handles non-first aggregate continuation descriptors, then writes frame length, key index, frame type, NoAck/RTS/CTS, aggregation flags, LDPC, PAPRD chain mask, packet durations, rate flags, chain selections, RTS/CTS rate, sounding flag, and per-series TX powers. Link updates recompute the pointer checksum in `ctl10`. Interrupt handling reads async cause first, conditionally reads `AR_ISR`, decodes beacon miscellaneous secondary bits, handles RAC versus explicit-clear hardware, maps RX/TX/gentimer/common/fatal bits to `ath9k_int`, handles MCI interrupts, logs/clears sync fatal causes, and reads BB watchdog state when signaled. TX status processing consumes `ah->ts_ring[ah->ts_tail]` only after `AR_TxDone`, verifies descriptor identity, fills `ath_tx_status`, updates trigger level on underruns, clears the consumed status entry, and advances the ring tail. RX EDMA processing validates `AR_RxDone`, vendor ID, and descriptor kind, fills `ath_rx_status` with data length, timestamp, RSSI, key index, rate, aggregate flags, antenna, GI/STBC/bandwidth, EVMs, delimiter flags, decrypt-busy, CRC/decrypt/MIC/PHY/key-miss errors, and special-cases OFDM restart with post-delimiter CRC on non-final aggregate subframes.

State and persistence: Mutates DMA-visible TX control descriptors and status descriptors, `ah->ts_tail`, `ah->ts_ring`, `ah->ts_size`, `ah->ts_paddr_start`, `ah->ts_paddr_end`, interrupt timer trigger/threshold fields, RX buffer-size and RXDP registers, ISR clear registers, and TX trigger level through `ath9k_hw_updatetxtriglevel()`. This is volatile ring/register state shared with hardware; correct ordering is enforced with `WRITE_ONCE()`/`READ_ONCE()` in descriptor paths.

Dependencies and integration points: Depends on `hw.h`, `ar9003_mac.h`, `ar9003_mci.h`, AR register/bitfield macros, common ath9k descriptor helpers (`set11n*`), interrupt enums, `ath_common` debug logging, MCI ISR integration, and Linux export infrastructure. Higher-level ath9k TX/RX paths call through installed ops and exported EDMA helpers.

Risks: Descriptor bit packing and checksum calculation are hardware ABI-sensitive; missing a checksum update after changing a pointer can break DMA. First/middle/last aggregate handling must match how upper TX code segments frames. ISR handling differs for RAC and non-RAC hardware; incorrect clearing can lose interrupts or storm. Status-ring tail accounting assumes hardware writes complete status entries in order. RX descriptor error handling intentionally suppresses one OFDM restart case for A-MPDU delimiters; changing that can alter packet loss behavior. The exported RX status decoder reads DMA memory supplied by callers and assumes descriptor alignment/layout from `ar9003_mac.h`.

Test signals: Build and run TX for single-frame, multi-buffer, encrypted, RTS/CTS, NoAck, LDPC, PAPRD, and aggregate first/middle/last descriptors; update descriptor links after creation and verify checksum fields. Exercise TX completion statuses for success, retries, filtered, FIFO/data/delimiter underruns, BA bitmap, and descriptor config errors. Test RX EDMA descriptors for valid frames, aggregates, key indexes, GI/STBC/HT40, delimiter CRC flags, CRC/decrypt/MIC/PHY/keymiss errors, and incomplete descriptors. Exercise interrupt paths for RXLP/RXHP/TX, mitigation, beacon misc, gentimer, BB watchdog, MCI, PCI fatal/PERR, local timeout, and RAC/non-RAC clearing.

# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_mac.h

Purpose: Defines AR9003 MAC descriptor layouts and bit masks used by the AR9003 EDMA TX/RX implementation, and declares the MAC operation attach and EDMA helper APIs.

Important APIs and types: Descriptor identity and control masks include `AR_DescId`, `AR_CtrlStat`, `AR_TxRxDesc`, `AR_TxQcuNum`, `AR_BufLen`, `AR_TxDescId`, `AR_TxPtrChkSum`, `AR_LowRxChain`, `AR_Not_Sounding`, and `AR_PAPRDChainMask`. ISR secondary-bit mapping constants translate AR_ISR_S2 bits into ath9k interrupt bits. `struct ar9003_rxs` describes 12 dwords of RX status, `struct ar9003_txc` describes the 128-byte TX control descriptor with four data pointers and control words `ctl3` through `ctl23`, and `struct ar9003_txs` describes TX status-ring entries. Prototypes expose `ar9003_hw_attach_mac_ops()`, RX buffer-size/RXDP programming, EDMA RX status processing, and TX status-ring setup/reset.

Control flow: The header has no executable flow. Its structs are filled and consumed by `ar9003_mac.c`: TX setup writes `ar9003_txc`, hardware writes `ar9003_txs` and `ar9003_rxs`, and descriptor/status fields are decoded through the masks defined here.

State and persistence: No owned state. The packed, 4-byte-aligned structs define DMA-visible in-memory state shared between driver and hardware. The 128-byte TX control descriptor padding is intentional cache-line sizing.

Dependencies and integration points: Included by `ar9003_mac.c` and `ar9003_hw.c`, and indirectly tied to common ath9k types from `hw.h` such as `struct ath_hw`, `struct ath_rx_status`, and `enum ath9k_rx_qtype`. The bit definitions complement register/status field macros from shared ath9k hardware headers.

Risks: Layout, packing, alignment, and bit positions are hardware ABI. Changing `struct ar9003_txc` size, removing padding, or altering status dword order would corrupt DMA. `AR9003TXC_CONST()` is a raw cast helper, so callers must pass a true AR9003 TX descriptor. ISR map constants encode shifts in both directions and are easy to misuse if AR_ISR_S2 definitions change.

Test signals: Compile-time size/alignment checks for descriptor structs, TX/RX DMA tests on EDMA hardware, descriptor checksum verification, interrupt decode tests for beacon misc bits, and sparse/static analysis for casts through `AR9003TXC_CONST()`.
