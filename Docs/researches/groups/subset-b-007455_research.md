## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-rbf/src/test/java/org/apache/hadoop/hdfs/server/federation/router/TestRouterQuota.java

Purpose: JUnit 5 integration coverage for Router-based Federation quota behavior. It starts a `StateStoreDFSCluster` with two nameservices and a Router configured with state store, admin, quota, and RPC services, then verifies namespace quota, storage space quota, storage-type quota, quota synchronization to backing NameNodes, cache refresh, stale cleanup, and global inherited quota semantics.

Important APIs and types include `StateStoreDFSCluster`, `RouterContext`, `MountTableResolver`, `MountTableManager`, `MountTable`, `RouterQuotaUsage`, `RouterQuotaUpdateService`, `RouterQuotaManager`, `Quota`, `ClientProtocol`, `DFSClient`, `QuotaUsage`, and HDFS exceptions such as `NSQuotaExceededException`, `DSQuotaExceededException`, `QuotaByStorageTypeExceededException`, and `AccessControlException`. Helper methods wrap mount-table admin operations (`addMountTable`, `updateMountTable`, `removeMountTable`, `getMountTable`), append bytes through `DFSClient`, and prepare quota inheritance or storage-type fixtures.

Control flow is fixture-heavy: `setUp()` builds the federated cluster, sets a small quota cache interval and block size, starts routers, and captures two NameNode contexts plus the mount resolver. Each test creates real destination directories, installs mount entries with quotas, calls router or NameNode APIs, invokes `periodicInvoke()` when deterministic quota refresh is needed, and asserts both router-visible and underlying NameNode state. The suite distinguishes direct mount-point operations from non-mount child operations, verifies that unrelated metadata operations are not blocked after quota violations, and tests missing-destination behavior by deleting or omitting backing paths.

State and persistence behavior centers on two stores: the Router local quota cache and mount-table records in the state store. Some tests confirm admin updates persist quota definitions into mount entries and propagate to NameNodes; `testRouterQuotaUpdateService` explicitly asserts that periodic cache refresh updates local `RouterQuotaManager` usage without mutating state-store usage fields. Removal tests assert stale cache entries and remote quota definitions are cleared.

Dependencies and integration points are the Router admin protocol, mount-table resolver cache reloads, HDFS quota APIs, state-store driver reads, and real MiniDFS filesystem mutations. Risks covered include stale quota entries, path-prefix confusion, inherited global quota computation, storage type array handling, failed destination lookups, and quota exceptions leaking into unrelated operations. Test signals are direct exception interception, quota counter equality checks, state-store record inspection, and backend NameNode quota validation.

## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-rbf/src/test/java/org/apache/hadoop/hdfs/server/federation/router/TestRouterQuotaManager.java

Purpose: unit-level coverage for `RouterQuotaManager`, focused on in-memory path lookup behavior rather than full Router integration. The test constructs a fresh manager per test and clears it afterward.

Important APIs and types are `RouterQuotaManager`, `RouterQuotaUsage`, `RouterQuotaUsage.Builder`, `HdfsConstants.QUOTA_RESET`, and `Set<String>`. `testGetChildrenPaths()` stores quota entries at sibling and nested paths and verifies `getPaths(parent)` returns the parent plus true descendants while excluding prefix-only paths such as `/path3-subdir`. `testGetQuotaUsage()` verifies null behavior for missing entries and no-quota entries, then confirms lookup of the nearest ancestor with an actual namespace or space quota.

Control flow is simple: populate the manager map with synthetic paths, call the lookup method under test, and assert returned values. The second test mutates a reusable builder through unset quota, quota set on a parent, no-quota child, and quota-set child to exercise ancestor precedence.

State and persistence behavior is in-memory only. There is no state store, cluster, or filesystem. The manager cache is reset in `@AfterEach`, so tests guard against path lookup regressions without persistence side effects.

Dependencies and integration points are minimal but important because the full Router quota service depends on these semantics when evaluating quotas for child operations and mount-table descendants. Risks covered include accidental prefix matching, returning unset quota definitions as active quota, and choosing a farther ancestor over the closest quota-bearing path. Test signals are exact set size/content checks and quota field assertions.

Purpose: integration tests for Router RPC client retry behavior and Namenode metrics caching under unavailable or slow subclusters. The suite uses a two-nameservice `StateStoreDFSCluster`, independent datanodes, short datanode report cache expiry, and reduced IPC retry settings to make retry counts deterministic.

State and persistence behavior is resolver/cache driven. The tests deliberately mutate membership cache validity and Namenode metrics cache contents; no durable state-store assertions are made beyond resolver registration effects. Dependencies include federation metrics, NameNode simulation utilities, MiniDFS shutdown/restart behavior, IPC retry config, and JSON node counting.

Risks covered include over-retrying dead nameservices, failing to continue when one nameservice is usable, stale metrics cache behavior, and slow subclusters blocking aggregate metrics. Test signals are retry counter equality, expected remote exception text, successful lease renewal, cached JSON changes, and datanode count assertions.
