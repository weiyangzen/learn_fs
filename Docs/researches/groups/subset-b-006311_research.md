## sources/distributed-fs/ceph-client/rust/kernel/sync/condvar.rs

Purpose: exposes Linux `wait_queue_head` as a pinned Rust `CondVar` for condition-variable style waits that atomically drop a `Lock` guard, sleep, and reacquire the lock. Important APIs are `new_condvar!`, `CondVar::new`, `wait`, `wait_interruptible`, `wait_interruptible_freezable`, `wait_interruptible_timeout`, `notify_sync`, `notify_one`, `notify_all`, and `CondVarTimeoutResult`.

Control flow: construction calls `__init_waitqueue_head` with a static lock class. `wait_internal` initializes a stack `wait_queue_entry`, calls `prepare_to_wait_exclusive`, releases/relocks the provided guard through `Guard::do_unlocked` around `schedule_timeout`, then calls `finish_wait`. Timeout results are classified by returned jiffies and `current!().signal_pending()`. State is the embedded wait queue; notifications are not sticky. Dependencies include `lock::Guard`, task sleep constants, `Jiffies`, `Opaque`, `pin_init`, and C wait/scheduler bindings. Integration points are kernel Rust locks, poll wait queues via `PollCondVar`, and any code that loops around predicates. Risks are missed wakeups if callers do not recheck predicates, sleeping with inappropriate lock types or contexts, freezable waits while holding unrelated locks, and jiffies conversion saturation to `MAX_SCHEDULE_TIMEOUT`. Test signals: doc examples, lockdep assertions through guards, interruptible signal paths, timeout zero/nonzero branches, and wake-one/wake-all behavior.

## sources/distributed-fs/ceph-client/rust/kernel/sync/lock.rs

Purpose: provides the generic pinned lock abstraction used by mutexes, spinlocks, and global locks. Important APIs/types are unsafe trait `Backend`, `Lock<T, B>`, `Lock::new`, `Lock::from_raw` for ZST data, `lock`, `try_lock`, and `Guard` with `lock_ref`, `do_unlocked`, `as_mut`, `Deref`, `DerefMut`, and `Drop`.

Control flow: `Lock::new` pin-initializes protected data and asks the backend to initialize the C lock state. `lock` and `try_lock` call backend acquisition functions, then create a `Guard` after `assert_is_held`. Dropping the guard calls backend `unlock`. `do_unlocked` temporarily unlocks, installs a `ScopeGuard` to relock with backend `relock`, then runs a callback; this is central to condvar waits. State is the C lock object plus `UnsafeCell<T>`, with pinning required conservatively for C lock internals and protected pinned data. Dependencies are `LockClassKey`, `Opaque`, `ScopeGuard`, `pin_init`, and backend modules. Integration points include `Mutex`, `SpinLock`, `CondVar`, `LockedBy`, global locks, and any C-initialized lock via `from_raw`. Risks concentrate in unsafe backend implementations, relock symmetry, `from_raw` layout assumptions, non-`Send` guard enforcement, and `DerefMut` only for `Unpin`. Test signals include backend-specific lockdep assertions, try-lock success/failure, `do_unlocked` relock on panic-like exits, and pinned data access through `as_mut`.

## sources/distributed-fs/ceph-client/rust/kernel/sync/lock/global.rs

Purpose: supports statically allocated kernel locks whose C lock state is initialized later by module init. Important APIs/types are `GlobalLockBackend`, `GlobalLock`, `GlobalLock::new`, `init`, `lock`, `try_lock`, `GlobalGuard`, `GlobalLockedBy`, and macros `global_lock!`/`global_lock_inner!`.

Control flow: `global_lock!` creates a zero-variant marker enum implementing `GlobalLockBackend`, then a `static GlobalLock` constructed by unsafe `GlobalLock::new`. Runtime module init must call `init` exactly once, which invokes the selected backend initializer on the embedded `Lock`. Locking delegates to the inner lock and wraps the resulting guard. `GlobalLockedBy` stores data guarded by the globally unique lock, granting access only when a `GlobalGuard` proves the lock is held. State is persistent static data and an embedded uninitialized C lock until explicit init. Dependencies include generic lock backends, `LockClassKey`, `LockedBy` thread-safety rules, `Opaque`, and macro-generated C strings. Integration points are module-level counters, singleton registries, and object fields protected by a global mutex/spinlock. Risks are using the static before `init`, calling `init` twice, reusing the backend marker with another lock, assuming global lock uniqueness incorrectly, and mutable access for pinned/`!Unpin` data through `DerefMut`. Test signals: module init ordering, lockdep class creation, `try_lock` behavior, and owner-guard mismatch tests for `GlobalLockedBy`-like access.

## sources/distributed-fs/ceph-client/rust/kernel/sync/lock/mutex.rs

Purpose: adapts Linux `struct mutex` to the generic `Lock` abstraction. Important APIs are `new_mutex!`, type aliases `Mutex<T>` and `MutexGuard<'a, T>`, and backend type `MutexBackend`.

Control flow: `new_mutex!` supplies a value initializer, optional name, and static lock class to `Mutex::new`. `MutexBackend::init` calls `__mutex_init`; `lock` calls `mutex_lock`; `try_lock` calls `mutex_trylock` and returns `Some(())` on nonzero; `unlock` calls `mutex_unlock`; `assert_is_held` calls the lockdep assertion binding. State is the embedded C `mutex` stored inside `Lock` plus protected data. Dependencies are the generic lock module, pin-init construction, static lock classes, and C mutex bindings. Integration points include sleepable shared state, condvars, `LockedBy`, and global locks. Risks are blocking in atomic context, deadlocks from lock ordering, misuse of `try_lock` results, or backend safety regressions that violate exclusive access. Test signals include doc examples, lockdep held assertions, contention tests, `try_lock` failure while held, and smoke tests that `CondVar::wait` can unlock/relock a mutex safely.

## sources/distributed-fs/ceph-client/rust/kernel/sync/lock/spinlock.rs

Test signals are lockdep assertions, try-lock behavior under contention, Send/Sync trait boundaries, and architecture/config builds where spinlock layout may be self-referential or debug-heavy.

## sources/distributed-fs/ceph-client/rust/kernel/sync/locked_by.rs

Purpose: represents data protected by a lock that is not physically wrapping that data. Important APIs are `LockedBy<T, U>`, `new`, `access`, and `access_mut`.

Control flow: `new` records the address of the owner lock's protected data (`owner.data.get()`) and stores the payload in `UnsafeCell`. `access` and `access_mut` require references to the owner data, compare their address to the stored owner pointer, panic on mismatch, and then return shared or mutable access to the payload. State is the payload plus a raw, never-dereferenced owner identity pointer. Dependencies are `Lock`, backend trait, `build_assert`, `UnsafeCell`, pointer equality, and size checks forbidding zero-sized owners/locks where identity would be ambiguous. Integration points are aggregate structures where one lock protects fields in child objects, and `GlobalLockedBy` mirrors the same concept for global locks. Risks include owner memory reuse causing logical but memory-safe mistaken access, panics on mismatched owners, ZST misuse caught at build time, and readers assuming the owner pointer preserves lifetime. Test signals include correct-owner access, mismatched-owner panic, mutable exclusivity through guards, and compile-time failures for ZST owner cases.
<!-- END_FILE_RESEARCH: sources/distributed-fs/ceph-client/rust/kernel/sync/locked_by.rs -->

## sources/distributed-fs/ceph-client/rust/kernel/sync/poll.rs

Purpose: connects Rust condition variables to Linux `poll_table` wait registration. Important APIs/types are `new_poll_condvar!`, `PollTable::from_raw`, `PollTable::register_wait`, and pinned `PollCondVar`.

Control flow: `PollTable` wraps a possibly null raw `poll_table` with a lifetime. `register_wait` calls `poll_wait(file, cv.wait_queue_head, table)`. `PollCondVar` derefs to `CondVar`, so normal notification methods wake poll waiters. On pinned drop it calls `__wake_up_pollfree` and then `synchronize_rcu` so epoll/poll users stop referencing the wait queue before storage is invalidated. State is the inner condvar wait queue and borrowed poll table pointer. Dependencies include `File`, `CondVar`, RCU synchronization, pin-init, and C poll bindings. Integration points are file operation `poll` implementations and epoll teardown. Risks include constructing `PollTable` from an invalid pointer, dropping a condvar without pollfree/RCU semantics, registering waiters against unpinned storage, and misunderstanding null poll tables. Test signals: file poll implementations that register and receive notifications, teardown under epoll, RCU grace-period behavior, and Miri-style lifetime checks are not available because the core safety relies on kernel C contracts.
<!-- END_FILE_RESEARCH: sources/distributed-fs/ceph-client/rust/kernel/sync/poll.rs -->

## sources/distributed-fs/ceph-client/rust/kernel/sync/rcu.rs

Purpose: provides RAII evidence for holding the RCU read-side lock. Important APIs are `Guard::new`, `Guard::unlock`, `Default`, `Drop`, and free function `read_lock`.

Control flow: creating a `Guard` calls `rcu_read_lock`; dropping it calls `rcu_read_unlock`. `unlock(self)` consumes the guard and relies on normal drop at the end of the method call. State is not stored beyond `NotThreadSafe`; the real state is per-thread/per-CPU kernel RCU state. Dependencies are `bindings` and `NotThreadSafe`. Integration points include accessors that require proof of RCU read-side protection and code borrowing RCU-protected kernel objects. Risks include assuming the guard is `Send` or can cross task contexts, because it intentionally is not thread-safe; nesting is delegated to kernel RCU semantics. Test signals are compile-time non-`Send` behavior, balanced lock/unlock in simple paths, and use with APIs that assert RCU protection.

## sources/distributed-fs/ceph-client/rust/kernel/sync/set_once.rs

Purpose: implements a thread-safe container that can be populated once and then read for the lifetime of the container. Important APIs are `SetOnce::new`, `Default`, `as_ref`, `populate`, `copy`, `Drop`, and `Send`/`Sync` impls.

Control flow: `init` is an atomic state machine: `0` uninitialized, `1` one writer owns initialization, `2` initialized for shared reads. `populate` does `cmpxchg(0, 1, Relaxed)`, writes `T`, then publishes with `Release` store to `2`. `as_ref` uses `Acquire` load and returns a reference only for state `2`. Drop destroys the value only if initialized. State persists in `MaybeUninit<T>` and the monotonic atomic flag. Dependencies are kernel atomic ordering wrappers, `UnsafeCell`, and `MaybeUninit`. Integration points are one-time global or per-object initialization without full `Once` blocking semantics. Risks include failed populators dropping their input immediately, readers seeing `None` while another thread is in state `1`, no retry/blocking primitive, and requiring `T: Send + Sync` for shared use because drop may happen on any thread. Test signals include racing `populate` calls, acquire/release visibility, drop of initialized vs empty containers, and `copy` for `Copy` values.
<!-- END_FILE_RESEARCH: sources/distributed-fs/ceph-client/rust/kernel/sync/set_once.rs -->

Test signals: compile-time non-`Send` current references, refcount balance, signal pending paths, pid namespace null/non-null behavior, and debug atomic sleep warnings.

Purpose: defines typed time primitives for Rust kernel code: clock-specific `Instant<C>` and signed duration `Delta`. Risks include overflow/underflow when manipulating instants without overflow checks, negative deltas passed to APIs that require nonnegative durations, and choosing wall-clock time where monotonic time is required. Purpose: wraps kernel delay/sleep helpers with `Delta` inputs. Important APIs are `fsleep(delta)` and `udelay(delta)`.

Control flow: `fsleep` clamps invalid or too-large deltas to `i32::MAX` microseconds, rounds up to microseconds, and calls C `fsleep`; it is for nonatomic contexts. `udelay` debug-asserts that the delta is nonnegative and within `MAX_UDELAY_MS`, clamps otherwise, rounds up, and calls busy-waiting `udelay`. ## sources/distributed-fs/ceph-client/rust/kernel/transmute.rs

Purpose: defines explicit byte-transmutation traits for types safe to read from arbitrary bytes or expose as initialized bytes. Important APIs are unsafe traits `FromBytes` and `AsBytes`, methods for exact/prefix/shared/mutable/copy conversions, and primitive/array impl macros.

Control flow: `FromBytes::from_bytes` checks exact size and alignment before returning `&Self`; prefix variants split slices first; mutable variants require `Self: AsBytes`; copy variants use `read_unaligned` after size checks. `AsBytes::as_bytes` and `as_bytes_mut` expose initialized memory as byte slices, with mutable requiring `FromBytes` so writes of arbitrary bytes remain valid. State is none. Dependencies are `size_of`, slice split checked APIs, and unsafe implementer invariants. Integration points are uaccess typed reads/writes, ioctl structures, device protocol parsing, and DMA/user buffer serialization. Risks include implementing `FromBytes` for types with invalid bit patterns or interior mutability, implementing `AsBytes` for padded structs or kernel-pointer-containing data intended for userspace, endian assumptions, and alignment failures returning `None`. Test signals: primitive conversion examples, unaligned copy path, prefix remainder behavior, padding audits for custom impls, and fuzzing byte inputs for protocol structs.

## sources/distributed-fs/ceph-client/rust/kernel/types.rs

Purpose: collects core FFI and utility types: foreign ownership transfer, scope cleanup, opaque C storage, and not-thread-safe markers. Important APIs/types are unsafe trait `ForeignOwnable`, its unit impl, `ScopeGuard::{new_with_data,new,dismiss}`, `Deref`/`DerefMut`/`Drop`, `Opaque::{new,uninit,zeroed,ffi_init,try_ffi_init,get,cast_into,cast_from}`, `Wrapper<T> for Opaque<T>`, and `NotThreadSafe`.

Control flow: `ForeignOwnable` transfers Rust values to C as aligned non-null `*mut c_void`, with unsafe borrow/reclaim methods. `ScopeGuard` stores `(data, cleanup)` in an `Option`, runs cleanup on drop unless `dismiss` consumes it. `Opaque` wraps `MaybeUninit<T>` in `UnsafeCell` and exposes raw pointers so C-owned invariants are not represented as Rust references; pin initializers call closures with uninitialized storage. State varies by utility: foreign pointers are external, scope guard owns optional cleanup data, opaque storage may be uninitialized/zeroed/initialized. Dependencies include `PinInit`, `Wrapper`, `Zeroable`, `UnsafeCell`, and FFI `c_void`. Integration points are nearly all kernel wrappers around C structs, lock/timer/workqueue initialization, callback data ownership, and current-task non-send markers. Risks include double `from_foreign`, overlapping foreign borrows, scope guard cleanup panics, reading uninitialized opaque storage, assuming `Opaque<T>` is `Sync`, and losing `NotThreadSafe` markers in wrappers. Test signals: ownership round trips, drop/dismiss behavior, pin-init FFI constructors, layout casts, and compile-time Send/Sync expectations.

## sources/distributed-fs/ceph-client/rust/kernel/uaccess.rs

Purpose: provides safe-positioned wrappers for userspace memory access. Important APIs/types are `UserPtr`, `UserSlice`, `UserSliceReader`, `UserSliceWriter`, reader methods `skip/clone_reader/len/is_empty/read_raw/read_slice/read_slice_partial/read_slice_file/read<T>/read_all/strcpy_into_buf`, writer methods `len/is_empty/write_slice/write_dma/write_slice_partial/write_slice_file/write<T>`, and helper `raw_strncpy_from_user`.

Control flow: `UserSlice::new` records an unchecked user address and length; actual validation happens in copy functions. Creating readers/writers consumes the slice to discourage accidental double fetch. Reads and writes check remaining length, call `copy_from_user`, `_copy_from_user`, `copy_to_user`, or `_copy_to_user`, then advance pointer and reduce length only on success. File-offset helpers reject negative offsets and update offsets by transferred bytes. `strcpy_into_buf` bounds by slice length, uses `strncpy_from_user`, adds/validates NUL termination, and returns `&CStr`. DMA writes copy from coherent memory by raw pointer without forming a normal slice. State is the current user pointer and remaining length. Dependencies include allocator vectors, `Coherent`, file offsets, `KnownSize`, `FromBytes`, `AsBytes`, `CStr`, and uaccess bindings. Integration points are syscall/ioctl/file read-write paths and drivers exposing buffers to userspace. Risks include TOCTOU when cloning or recreating readers, partial modification on error, typed reads requiring valid-any-bit-pattern `FromBytes`, writes leaking padding unless `AsBytes` is correct, offset overflow assumptions, and kernel threads without a current userspace mm. Test signals: bad address `EFAULT`, short buffers, partial offset behavior, NUL string edge cases, DMA range errors, and race-oriented tests that validate copied data after every read.

## sources/distributed-fs/ceph-client/rust/kernel/usb.rs

Purpose: implements Rust abstractions for USB driver registration, device IDs, interfaces, and USB devices. Important APIs/types are `Adapter<T>`, `DeviceId` constructors, `RawDeviceId`/`RawDeviceIdIndex` impls, `IdTable<T>`, `usb_device_table!`, trait `Driver`, `Interface<Ctx>`, internal `Device<Ctx>`, refcount impls, and `module_usb_driver!`.

Control flow: `Adapter<T>` describes `usb_driver` layout and registration ops. Registration fills name, probe, disconnect, and id table, then calls `usb_register_driver`; unregister calls `usb_deregister`. The C probe callback wraps `usb_interface`, casts the matched ID to `DeviceId`, gets per-ID info, calls `T::probe`, and stores pinned driver data in device drvdata. Disconnect retrieves drvdata and calls `T::disconnect`. `DeviceId` constructors build common USB match records with zeroed remaining fields. `Interface` converts to generic `device::Device` and to its parent USB `Device`; both wrappers are `AlwaysRefCounted`. State is kernel-owned USB core objects and driver private data stored in device drvdata. Dependencies include driver/device frameworks, device-id tables, `Opaque`, `PinInit`, `ThisModule`, USB bindings, and refcounting. Integration points are Rust USB modules and modpost alias generation. Risks include ABI/layout offset mistakes, probe storing wrong drvdata type, disconnect assumptions after partial probe failure, `DeviceId` match flag correctness, and private `Device` limiting external USB-device methods. Test signals: module registration/unregistration, modpost table output, probe failure cleanup, disconnect after successful probe, refcount get/put balance, and ID table index mapping.

## sources/distributed-fs/ceph-client/rust/kernel/workqueue.rs

Purpose: provides raw and safe Rust abstractions for Linux workqueues, including delayed work and intrusive work items. Important APIs/types are `new_work!`, `new_delayed_work!`, `Queue::{from_raw,enqueue,enqueue_delayed,try_spawn}`, `RawWorkItem`, `RawDelayedWorkItem`, `WorkItemPointer`, `WorkItem`, `Work<T, ID>`, `HasWork`, `impl_has_work!`, `DelayedWork<T, ID>`, `HasDelayedWork`, `impl_has_delayed_work!`, pointer impls for `Arc<T>`, `Pin<KBox<T>>`, `ARef<T>`, and system queue accessors.

Control flow: `Work::new` initializes a C `work_struct` with the pointer type's `run` function. `DelayedWork::new` initializes both `work` and an IRQ-safe timer using `delayed_work_timer_fn`. Queue methods call the pointer type's `__enqueue` with closures wrapping `queue_work_on` or `queue_delayed_work_on`. `Arc`/`ARef` enqueue paths convert to raw references and reclaim on enqueue failure or in `run`; `Pin<KBox<T>>` transfers box ownership and treats enqueue failure as unreachable because exclusive ownership means it cannot already be queued. `run` reconstructs the smart pointer from the embedded work pointer via `HasWork::work_container_of` and calls `T::run`. `try_spawn` allocates `ClosureWork` that consumes and executes an `FnOnce`. State is embedded `work_struct`/`delayed_work`, smart-pointer ownership while queued, and global C workqueue pointers. Dependencies include `Arc`, `ARef`, `AlwaysRefCounted`, `KBox`, `Pin`, `LockClassKey`, `Jiffies`, `Opaque`, and workqueue bindings. Integration points are asynchronous driver tasks, delayed jobs, bottom-half workqueues, and simple closure spawning. Risks include wrong `HasWork` offsets, multiple IDs mapped incorrectly, queueing already queued `Pin<KBox>` causing unreachable UB assumptions, TODO safety comments for box impls, delayed-work pointer requirements, lifetime-sensitive raw implementations, and choosing an inappropriate system queue for long/blocking work. Test signals: enqueue success/failure for Arc/ARef, delayed work execution after jiffies delay, closure work drop/run once, multiple work fields with different IDs, queue selection, and cancellation/flush behavior in users of this API.
