# sources/distributed-fs/ceph-client/drivers/tty/serial/omap-serial.c

Purpose: OMAP high-speed UART driver. It provides a serial-core `uart_driver` for up to ten TI OMAP UART instances, separate from 8250 because OMAP needs platform-specific register programming, wakeup handling, runtime PM, errata handling, hardware/software flow control, and RS-485 direction control.

Important APIs/types/functions: `struct uart_omap_port` wraps `struct uart_port` with OMAP register shadows (`ier`, `lcr`, `mcr`, `fcr`, `efr`, `dll`, `dlh`, `mdr1`, `scr`, `wer`), PM state, feature/errata flags, wake IRQ, RS-485 GPIO state, and latency QoS work. `serial_omap_pops` is the serial-core callback table. `serial_omap_probe()` maps MMIO, resolves OF or platform IDs, enables runtime PM, derives revision features via `omap_serial_fill_features_erratas()`, configures RS-485, and registers the port. `serial_omap_set_termios()` computes 13x/16x baud mode, divisor registers, FIFO trigger registers, hardware CTS/RTS, XON/XOFF, and read/ignore masks. `serial_omap_irq()` decodes `UART_IIR` interrupt causes and dispatches to RX, line-status, modem-status, and TX helpers. PM restore is handled by `serial_omap_restore_context()` and runtime suspend/resume callbacks.

Control flow: module init registers `serial_omap_reg` and the platform driver. Probe allocates the port, maps resources, initializes PM/QoS, reads hardware revision, stores the port in `ui[]`, and calls `uart_add_one_port()`. Open flows through `serial_omap_startup()`, which requests the main IRQ, optionally installs a dedicated wake IRQ, powers the device with runtime PM, clears FIFOs/status, sets modem control, enables RX/line interrupts, and programs wake-enable bits. Data receive path is IRQ -> `serial_omap_rdi()`/`serial_omap_rlsi()` -> `uart_insert_char()` -> `tty_flip_buffer_push()`. TX path is `start_tx()` enabling THRI, then IRQ -> `transmit_chars()` -> `serial_omap_put_char()`. Close disables interrupts, clears break/FIFOs, drops runtime PM, frees IRQs, and clears wake IRQ.

State and persistence: most hardware state is mirrored in `uart_omap_port` so termios, runtime resume, and context-loss recovery can reprogram the controller. `context_loss_cnt` detects lost register context. `port_activity` is updated on interrupts. `pm_qos_request` is updated from baud-derived latency. RS-485 state uses `rts_gpiod` plus `rs485_tx_filter_count` to suppress self-received bytes when RX-during-TX is disabled. Hardware wakeup and WER state persist while the device is powered but are rewritten on startup/resume.

Dependencies and integration points: Linux serial core, TTY flip buffers, OF compatibles `ti,omap2-uart`, `ti,omap3-uart`, and `ti,omap4-uart`, optional legacy `omap_uart_port_info`, runtime PM, wake IRQ helpers, GPIO descriptors for RS-485 RTS, CPU latency QoS, and OMAP feature callbacks for wake/context-loss. Console integration includes normal console, earlycon, and polling hooks when configured.

Risks: register programming is order-sensitive across OMAP config modes, especially EFR/TCR/TLR/MCR access and MDR1 errata i202. Runtime PM restore relies on platform context-loss reporting when available and otherwise restores conservatively. RS-485 direction timing uses blocking `mdelay()` under serial operations. Missing `clock-frequency` falls back to 48 MHz, which can silently produce wrong baud rates. The RX path handles only one received byte per RDI interrupt iteration, bounded by the outer 256 loop.

Test signals: probe success for DT and legacy platform data, alias line bounds, wake IRQ present/absent, register restore after runtime suspend with changed context count, termios coverage for 13x/16x baud selection and hardware/software flow control, RS-485 RTS polarity and TX-complete direction changes, console write while interrupts are disabled, RX line-status errors and sysrq/break handling, and i202 MDR1 timeout warning behavior.

# sources/distributed-fs/ceph-client/drivers/tty/serial/owl-uart.c

Purpose: Actions Semi Owl family UART driver. It implements a platform/OF serial-core driver for S500/S900 UARTs with memory-mapped control/status registers, clock-driven baud selection, console/earlycon support, and optional polling.

Important APIs/types/functions: `struct owl_uart_port` contains the `uart_port` and UART clock. `struct owl_uart_info` supplies per-compatible FIFO size. `owl_uart_ops` provides serial callbacks for modem control, TX/RX start/stop, startup/shutdown, termios, resource request/release, and console polling. `owl_uart_probe()` uses the `serial` OF alias as the line number, maps the MMIO resource through serial-core request logic, gets/enables the clock, selects FIFO size from match data, and registers a port with `owl_uart_driver`. `owl_uart_irq()` handles RX/TX pending bits. `owl_uart_set_termios()` programs data width, stop bits, parity, automatic flow control, and baud by setting the clock to `baud * 8`.

Control flow: module init registers the UART driver then the platform driver. Probe prepares one `owl_uart_port`, stores it in `owl_uart_ports[]` for console lookup, and calls `uart_add_one_port()`. Startup requests the IRQ, clears sticky status bits, enables RX/TX interrupts and the UART. RX interrupt handling switches the FIFO direction away from TX, reads until RX FIFO empty, records basic overrun/frame-parity style counters, handles sysrq, inserts chars into the TTY flip buffer, and pushes. TX interrupt handling writes while TX FIFO is not full through `uart_port_tx()`. Shutdown masks TX/RX interrupts, disables RX/TX and the UART, then frees the IRQ.

State and persistence: software state is small: the global `owl_uart_ports[]`, per-port clock, serial-core state, and the current hardware control register bits. Termios state is persisted in hardware `OWL_UART_CTL`; baud is represented by the clock rate rather than divisor registers. Remove unregisters the port and disables the clock.

Dependencies and integration points: platform driver with OF matches `actions,s500-uart` and `actions,s900-uart`, `clk` API, serial core, TTY flip buffers, `readl_poll_timeout_atomic()` for poll output, console registration through `console_initcall`, and early console via `OF_EARLYCON_DECLARE("actions,owl-uart")`.

Risks: `to_owl_uart_port(prt)` uses `container_of(prt, struct owl_uart_port, prt)`, which appears to name a non-existent member instead of `port`; this is a compile-time risk unless hidden by local tree changes. RX error reporting cannot distinguish exact error type and maps status to parity/frame counters broadly. Baud changes depend on clock provider accuracy and willingness to set `baud * 8`. Interrupt handler always returns handled once invoked and clears both RX/TX pending bits after processing, so unexpected/shared interrupt behavior should be tested. Probe enables the clock before `uart_add_one_port()`, and error cleanup after failed add clears only the global slot.

Test signals: build coverage for the `container_of` macro, S500/S900 FIFO sizes, invalid or duplicate alias IDs, zero clock rate rejection, termios matrix for CS5-CS8/parity/CMSPAR/CRTSCTS, RX FIFO drain and sysrq handling, TX FIFO full polling timeout, console and earlycon writes with interrupts masked, and remove-time clock disable and port slot cleanup.

# sources/distributed-fs/ceph-client/drivers/tty/serial/pch_uart.c

Purpose: PCI UART driver for Intel EG20T PCH and ROHM/LAPIS ML7213/ML7223/ML7831 devices. It exposes up to four `ttyPCH` serial ports, supports FIFO variants, optional PCH DMA, MSI, debugfs register dumps, DMI/OF/module-parameter UART clock selection, console, and polling.

Important APIs/types/functions: `struct eg20t_port` wraps `uart_port` with PCI device, mapped register addresses, FIFO size/trigger state, RX staging buffer, cached modem/FCR/MCR state, optional DMA channels/descriptors/scatterlists, coherent RX DMA buffer, and IRQ name. `drv_dat[]` maps PCI IDs to port type and line number. HAL helpers such as `pch_uart_hal_set_line()`, `pch_uart_hal_set_fifo()`, `pch_uart_hal_read()`, and interrupt enable/disable functions encapsulate 16550-like register accesses. `pch_uart_interrupt()` decodes IIR causes and dispatches to PIO/DMA RX/TX, line-status, and modem-status logic. `pch_uart_init_port()` enables MSI/mastering, allocates buffers, initializes `uart_port`, installs console lookup, registers the port, and creates debugfs.

Control flow: module init registers the serial driver then the PCI driver. PCI probe enables the device and calls `pch_uart_init_port()`. Serial-core open invokes `pch_uart_startup()`, which disables interrupts, sets default baud/8N1, configures FIFO/trigger level, requests a shared IRQ, optionally requests DMA, enables RX and RX error interrupts, and updates timeout. Interrupt RX can read directly into a page buffer and push to TTY, or arm a DMA slave transfer and push in `pch_dma_rx_complete()`. TX can write the FIFO in PIO or build scatterlists from `xmit_fifo`, map them, and advance the FIFO in `pch_dma_tx_complete()`. Shutdown masks interrupts, resets/disables FIFOs, frees DMA, and frees the IRQ. Remove unregisters the port, removes debugfs, disables MSI/device, and frees allocations.

State and persistence: persistent software state includes `start_tx`, `start_rx`, `tx_empty`, `trigger_level`, DMA-in-use flags, cached `fcr`/`mcr`, and module globals `default_baud` and `user_uartclk`. Hardware line/FIFO/modem registers persist until shutdown or device reset. `port_show_regs()` exposes a debugfs snapshot, temporarily toggling DLAB to read divisor latches. DMA state is dynamically allocated and released around startup/shutdown or verify-port DMA mode changes.

Dependencies and integration points: PCI core and ID table, serial core, TTY, optional `CONFIG_PCH_DMA`/DMAengine with `pch_dma_slave`, DMI board matching for UART clocks, optional OF `clock-frequency`, debugfs, console and poll console code, MSI, and module parameters. Supported devices are keyed by Intel and ROHM PCI vendor/device IDs.

Risks: DMA TX has several partial-failure paths after allocation/mapping/prep where `tx_dma_use`, allocated scatterlists, or mappings may not be unwound immediately. `pch_request_dma()` assigns `chan_rx` before checking coherent RX allocation success. `pch_uart_set_mctrl()` writes MCR only when `mctrl` is nonzero, which may make clearing outputs surprising. DMI clock assumptions and module overrides directly affect baud accuracy. Debugfs creation is not checked and names are global. FIFO/trigger math must remain aligned with port type; only UART0-like 256-byte FIFOs get auto hardware flow.

Test signals: PCI ID to line/type mapping, DMI and `user_uartclk` clock selection, startup/shutdown in PIO and DMA mode, DMA request failure fallback, RX timeout and RX error paths, TX wakeup and `tx_empty` behavior, `verify_port()` low-latency toggle semantics, debugfs register dump around DLAB restore, suspend/resume through `uart_suspend_port()`, console setup before/after PCI probe, and cleanup after `uart_add_one_port()` or IRQ request failures.

# sources/distributed-fs/ceph-client/drivers/tty/serial/pic32_uart.c

Purpose: Microchip PIC32 integrated UART driver. It registers up to six `ttyPIC` serial ports for `microchip,pic32mzda-uart` devices, handling separate fault/RX/TX IRQ lines, PIC32 SET/CLR register accessors, optional CTS GPIO, console support, and clock-gated startup/shutdown.

Important APIs/types/functions: `struct pic32_sport` contains `uart_port`, index, three IRQ numbers/names, TX IRQ enable tracking, optional CTS GPIO, clock, and device pointer. `pic32_uart_ops` provides the serial-core callbacks. `pic32_uart_probe()` resolves the `serial` alias, parses three IRQs with `irq_of_parse_and_map()`, gets the clock and optional `cts` GPIO, fills `uart_port`, and calls `uart_add_one_port()`. `pic32_uart_startup()` enables the clock, clears mode/status, programs default BRG, allocates and requests three no-auto-enable IRQs, enables RX, and starts the UART. `pic32_uart_set_termios()` reprograms stop/parity/flow-control/BRG and forces 8-bit data.

Control flow: `arch_initcall()` registers the UART driver and platform driver. Probe creates a port but hardware is mostly initialized on open. Startup disables the UART, sets default baud, requests fault/RX/TX IRQs with generated names, programs RX/TX interrupt selection, enables UART RX/TX, and enables only RX IRQ initially. RX IRQ drains up to the FIFO depth into the TTY layer, handling overrun/parity/framing and sysrq. TX IRQ fills the hardware FIFO from `xmit_fifo`, handles `x_char`, wakes writers, and disables TX IRQ when empty. Stop/start TX are guarded by `enable_tx_irq` to avoid IRQ depth imbalance. Shutdown disables hardware, gates the clock, frees all IRQs, and frees IRQ names.

State and persistence: `enable_tx_irq` tracks software IRQ enable state. Hardware state lives in MODE, STA, BRG, TX, and RX registers and is cleared/rebuilt on startup and termios. CTS state is read through `gpiod_get_value()` rather than a UART modem register. The console path may enable the clock early; probe disables it again when the registered console owns the port.

Dependencies and integration points: OF aliases and compatible, three interrupt specifiers per UART, platform resources, clock API, optional GPIO descriptor named `cts`, PIC32 platform register macros `PIC32_SET()`/`PIC32_CLR()`, serial core, TTY flip buffers, console registration at console/core initcall stages.

Risks: `irq_of_parse_and_map()` return values are not explicitly validated before request time, so bad DT IRQ cells surface later. Startup error labels call `free_irq()` for IRQs that may not have been successfully requested on some allocation-failure paths. `pic32_uart_stop_rx()` disables RX IRQ without tracking whether it is enabled. `pic32_uart_set_termios()` always forces CS8 and clears CMSPAR, which is correct for hardware limits but observable to users. `pic32_uart_tx_empty()` returns `1` rather than `TIOCSER_TEMT`, relying on truthiness rather than the usual bit value.

Test signals: DT alias bounds and three-IRQ parsing, optional/missing CTS GPIO behavior, startup unwind for name allocation and each IRQ request failure, TX IRQ enable/disable balance under stop/start and empty FIFO, RX overrun clearing, parity/framing counters and ignore masks, termios mutation to CS8/no-CMSPAR, BRG divisor calculations at edge baud rates, console setup clock handling, and remove-time port/global-slot cleanup.

# sources/distributed-fs/ceph-client/drivers/tty/serial/pmac_zilog.c

Purpose: PowerMac Z85c30/ESCC serial driver for MacIO-based PowerMacs and non-PMAC SCC platform devices. It supports early probing for serial console, paired channel A/B interrupt handling, internal modem and IrDA variants, SCC power control on PowerMac, console/polling, and software register shadows for the Zilog chip.

Important APIs/types/functions: global `pmz_ports[MAX_ZS_PORTS]` stores pre-probed port structures before serial-core registration. `pmz_uart_reg` is the `uart_driver`. `pmz_pops` supplies callbacks. `pmz_load_zsregs()` writes the full Zilog register shadow safely. `pmz_maybe_update_regs()` defers reprogramming while TX is active. `pmz_interrupt()` reads channel-A `R3` pending bits and services both channels via status, RX, and TX helpers. `pmz_startup()` powers/initializes hardware, requests the shared IRQ, handles modem delay and IrDA reset, then enables interrupts. `pmz_convert_to_zs()` translates termios/baud into Zilog register values. `pmz_probe()` pre-discovers ESCC channel nodes or platform devices before driver registration.

Control flow: console init may call `pmz_probe()` early and register the console. Module init probes if needed, sets `pmz_uart_reg.nr`, registers the UART driver, then registers either a MacIO or platform driver. OF probing finds `escc` nodes, extracts `ch-a`/`ch-b`, sets mate pointers and line numbers, maps channel registers, detects modem/IrDA from device-tree properties, and initializes register shadows. Attach later binds actual MacIO/platform devices and calls `uart_add_one_port()`. Runtime interrupts service channel A and B under their respective port locks. RX reads status/data until no character is available, handles break/sysrq/parity/frame/overrun, and pushes flip buffers. TX sends one byte per interrupt and acknowledges when idle. Shutdown disables interrupts, disables RX/TX for non-console ports, frees IRQ, and powers down non-console hardware.

State and persistence: driver state is heavily shadowed in `uart_pmac_port.curregs[]` and flags such as console, open, channel A, regs-held, TX-stopped, TX-active, IrDA, internal modem, external clock, and break. `prev_status` tracks DCD/CTS transitions because the chip reports only external-status interrupts. Register writes persist on the SCC until power-down; non-console ports are powered down immediately on close. Console ports stay powered and initialized.

Dependencies and integration points: serial core, TTY flip buffers, sysrq, OF address/IRQ parsing, MacIO driver model and PM callbacks under `CONFIG_PPC_PMAC`, `pmac_call_feature()` for SCC/modem power, optional non-PMAC platform devices, console subsystem, and the register definitions in `pmac_zilog.h`.

Risks: early probing and later MacIO attach split ownership, so ordering and cleanup must remain precise. `pmz_interrupt()` pushes using `uap->port.state` after handling each channel; shared IRQ and closed-channel behavior are explicitly defensive but fragile. Register update deferral during TX is required to avoid corrupting transmit, and bugs can leave stale termios state held until the next TX interrupt. IrDA setup has long polling/delay sequences and limited FIR support. The driver intentionally powers down immediately on close despite a TODO to defer.

Test signals: early console before MacIO attach, OF channel discovery with missing channel nodes, channel mate interrupt handling, internal modem 2.5 second power delay, IrDA baud setup/reset paths, termios changes during active TX causing deferred register loads, modem status edge tracking for inverted CTS, break/sysrq handling, suspend/resume through `uart_suspend_port()`, and module exit disposal of mapped nodes/resources.

# sources/distributed-fs/ceph-client/drivers/tty/serial/pmac_zilog.h

Purpose: private header for the PowerMac Zilog ESCC driver. It defines the runtime port structure, register accessors, baud conversion macros, Z85c30/ESCC register numbers and bit masks, and flag helpers used by `pmac_zilog.c`.

Important APIs/types/functions: `struct uart_pmac_port` embeds `uart_port`, channel mate pointer, MacIO or platform device identity, OF node, port type, `curregs[NUM_ZSREGS]` register shadow array, driver flags, parity mask, previous status byte, MMIO control/data register pointers, and IRQ name. `pmz_get_port_A()` returns the A channel for paired interrupt status reads. `read_zsreg()`, `write_zsreg()`, `read_zsdata()`, `write_zsdata()`, and `zssync()` provide low-level MMIO access. `BRG_TO_BPS()` and `BPS_TO_BRG()` convert between baud and Zilog baud-rate-generator constants. Macros define registers R0-R15/R7P, command bits, RX/TX enables, parity/stop/data-width settings, clocking, modem/status interrupts, read-status bits, and helper macros such as `ZS_CLEARERR()` and `ZS_CLEARFIFO()`.

Control flow: this header has no standalone runtime flow, but it shapes all driver paths. Startup and termios code build `curregs[]` with the masks here, then `pmz_load_zsregs()` writes the values through the accessors. Interrupt code reads R3/R0/R1 bits defined here to decide channel, RX, TX, external status, and line-error handling. Console and polling paths use data/control accessors directly.

State and persistence: `curregs[]` is the software source of truth for most Zilog write registers because many hardware registers are write-only or mode-dependent. Flag macros define persistent driver state for console/open/IrDA/modem/TX/register-update behavior. The accessors directly manipulate MMIO registers; persistence is in the SCC hardware until reset or power loss.

Dependencies and integration points: depends on Linux `struct uart_port`, PowerMac MacIO/device-tree types when `CONFIG_PPC_PMAC` is enabled, platform device type otherwise, and the Zilog ESCC hardware register model. It is included only by the PowerMac Zilog driver in this subset.

Risks: register constants must remain exactly aligned with Z85c30 semantics; incorrect bits can corrupt channel programming globally. `read_zsreg()` writes the register selector before reading nonzero registers, so callers must respect SCC access ordering. `ZS_CLEARFIFO()` blindly reads data three times as a drain primitive. The `to_pmz(p)` cast assumes `struct uart_pmac_port` embeds `uart_port` as its first field; changing structure layout would break it.

Test signals: compile coverage for PPC_PMAC and non-PMAC branches, register shadow initialization against expected bit values for common 9600/38400/115200 termios, channel A/B pairing through `pmz_get_port_A()`, direct accessor behavior in console/polling paths, and static review of any changes to flag or register bit definitions against the ESCC data sheet.

# sources/distributed-fs/ceph-client/drivers/tty/serial/pxa.c

Purpose: legacy PXA/MMP UART platform driver. It implements a separate serial-core driver for up to four PXA UART ports, including PXA-specific FIFO trigger programming, clock handling, console/poll support, and errata workarounds.

Important APIs/types/functions: `struct uart_pxa_port` embeds `uart_port` and stores cached `ier`, `lcr`, `mcr`, break flag, clock, and name. `serial_pxa_pops` is the `uart_ops` table. `serial_pxa_probe()` resolves MMIO/IRQ/clock, picks the port line from OF `serial` alias or platform ID, maps registers, fills `uart_port`, stores the port in `serial_pxa_ports[]`, and calls `uart_add_one_port()`. `receive_chars()` drains RX with PXA27x receiver-timeout errata handling. `serial_pxa_set_termios()` computes divisor/FIFO trigger thresholds and programs line control, baud divisor, hardware flow control, and masks. Console helpers save/restore IER and clock around synchronous writes.

Control flow: `device_initcall()` registers the UART driver then the platform driver. Probe prepares and registers a port; there is no remove function because this is a non-hotplug platform-style driver. Startup sets HWUART auto-flow for line 3, refreshes `uartclk`, requests IRQ, clears FIFOs/status, sets 8N1 and modem control, then enables RX/line/status/UUE interrupts. The IRQ handler reads IIR/LSR, receives data if present, processes modem deltas, transmits when THRE is set, and checks sysrq on unlock. Shutdown frees IRQ, disables interrupts, clears OUT2, clears break, and resets FIFOs.

State and persistence: cached `ier`, `lcr`, and `mcr` are the software mirrors used by interrupt, break, termios, and console paths. `lsr_break_flag` preserves break status observed during console transmit. Clock state is managed through the uart `pm` callback and console write enable/disable. Hardware FIFO, divisor, LCR/MCR/IER settings persist until reprogrammed or powered down.

Dependencies and integration points: serial core, TTY, clocks, platform resources, OF compatibles `mrvl,pxa-uart` and `mrvl,mmp-uart`, `serial_reg.h` 16550-style definitions plus PXA-specific FIFO trigger bits, console and console-poll options. The code comments state that the 8250 PXA serial driver should be used, so this driver is likely legacy compatibility.

Risks: no platform-driver remove path means unload/hot-unbind cleanup is absent. Probe uses manual `ioremap()`/`kzalloc()` rather than devm, and after `uart_add_one_port()` failure there is no immediate cleanup path. Errata handling in RX temporarily disables RTO interrupts and must always re-enable them after draining. The PXA27x divisor readback `WARN_ON()` can fire on hardware errata or bus issues. `serial_pxa_get_poll_char()` busy-waits until data is ready, which is expected for polling but risky if used incorrectly.

Test signals: DT alias and platform-ID line selection, out-of-range line rejection, clock prepare/pm transitions, startup/shutdown FIFO and interrupt state, PXA27x errata #20 RX timeout re-enable, errata #75 divisor readback warning, termios FIFO trigger thresholds across low/mid/high baud, HWUART line 3 auto-flow, console write with `oops_in_progress`, poll get/put behavior, and resource cleanup review on `uart_add_one_port()` errors.
