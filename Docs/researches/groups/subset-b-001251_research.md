# sources/distributed-fs/ceph-client/drivers/dma/amd/qdma/qdma.c

Purpose: implements the AMD Queue-based DMA Subsystem dmaengine platform driver for memory-mapped H2C and C2H slave transfers. It registers a private DMA device, allocates one queue per direction per platform channel, programs QDMA context RAM through indirect registers, feeds 32-byte MM descriptors into hardware rings, and completes dmaengine cookies from QDMA interrupt aggregation entries.

Important APIs and functions: `amd_qdma_probe()` maps MMIO, creates a regmap, verifies the QDMA identifier, reads queue count/function ID, sets up FMAP/ring-size/MM engine state, initializes error and queue interrupts, and registers `dma_async_device_register()`. `qdma_alloc_queue_resources()` clears queue context, allocates a coherent descriptor ring from `pdata->dma_dev`, picks an interrupt aggregation ring, and programs SW descriptor context. `qdma_prep_device_sg()`, `qdma_tx_submit()`, `qdma_fill_pending_vdesc()`, `qdma_hw_enqueue()`, and `qdma_issue_pending()` form the dmaengine submission path. `qdma_queue_isr()` parses aggregated completion entries, updates completion index, completes virtual descriptors, refills hardware descriptors, and re-arms PIDX. `qdma_error_isr()` logs and clears global error status, then re-arms the error interrupt.

Control flow: probe initializes static register metadata from `qdma-comm-regs.c`, enables the MM engines, creates H2C/C2H virtual channels, and registers callbacks for `DMA_SLAVE`/`DMA_PRIVATE`. A client configures device address with `qdma_device_config()`, prepares an SG transaction, submits it, and calls issue-pending. Submit assigns a cookie and opportunistically copies SG segments into the queue ring, splitting any segment above `QDMA_MM_DESC_MAX_LEN`. Issue-pending writes the producer index with `QDMA_QUEUE_ARM_BIT`. Hardware writes aggregated completion records; the ISR consumes records while the color bit matches, computes descriptor deltas, completes cookies whose pending descriptor count reaches zero, advances CIDX, and may enqueue more descriptors from submitted/issued lists.

State and persistence behavior: persistent device state is in `struct qdma_device` with platform device, regmap, context mutex, register field/offset tables, H2C/C2H queue arrays, interrupt rings, queue IRQ range, function ID, and channel count. Per-queue state includes the coherent descriptor ring, DMA base, qid, PIDX/CIDX registers, index mask, cached slave config, and active virtual descriptor pointers. Per-transfer state in `struct qdma_mm_vdesc` tracks SG pointer, remaining SG count, SG offset, device address, hardware PIDX, and pending hardware descriptor count. No on-disk persistence exists; suspend/resume hooks are absent, so hardware state is only initialized at probe/resource allocation.

Dependencies and integration points: depends on dmaengine and `virt-dma`, coherent DMA allocation, Linux regmap MMIO, platform data from `linux/platform_data/amd_qdma.h`, QDMA register offsets/fields from `qdma-comm-regs.c`, threaded IRQs, and a platform-provided DMA device for coherent allocations. Integration with consumers is through dmaengine filter mapping (`pdata->device_map`) and `qdma_filter_fn()` selecting H2C versus C2H channels.

Risks and edge cases: queue context programming is serialized, but the file warns that modifying enabled contexts is unsafe; allocation paths rely on clearing contexts before use. `qdma_get_desc()` reserves one descriptor and uses `ring_size - 2` as the wrap mask for a `BIT(10)+1` ring, which is subtle and should be covered by wrap tests. `qdma_fill_pending_vdesc()` assumes `issued_vdesc` is meaningful when issued descriptors exist. `qdma_queue_isr()` trusts hardware QID/type fields enough to index queue arrays, so malformed completion entries could address the wrong queue. `qdma_free_queue_resources()` frees `desc_base` without a visible NULL guard. There is no PM restore path, and error ISR reports only aggregate status rather than poisoning active descriptors.

Test signals: probe should reject invalid identifiers and insufficient hardware queues, register exactly two directions per `max_mm_channels`, and allocate at least `QDMA_MIN_IRQ` vectors through platform resources. Functional tests should cover H2C and C2H SG transfers, SG splitting above the 28-bit length limit, ring-full backpressure with later completion-driven refill, completion across interrupt ring color wrap, global error interrupt clear/re-arm, channel resource free/reallocate, and no cookie completion before all split descriptors for a transaction finish.

# sources/distributed-fs/ceph-client/drivers/dma/amd/qdma/qdma.h

Purpose: private header for the AMD QDMA dmaengine driver. It defines register identifiers, bitfield identifiers, queue/context enums, descriptor wire formats, interrupt aggregation entry masks, software queue/transfer/device state, logging helpers, and extern declarations for the default register maps.

Important APIs and types: `enum qdma_reg_fields` and `enum qdma_regs` index SoC register field and offset tables. `struct qdma_reg_field` and `struct qdma_reg` describe bit positions and register spans consumed by `qdma_get_field()`, `qdma_set_field()`, `qdma_reg_read()`, and `qdma_reg_write()` in `qdma.c`. Context structs (`qdma_ctxt_sw_desc`, `qdma_ctxt_intr`, `qdma_ctxt_fmap`) model payloads for QDMA indirect context RAM. `struct qdma_mm_desc` is the packed 32-byte hardware memory-mapped descriptor. `struct qdma_mm_vdesc`, `struct qdma_queue`, `struct qdma_intr_ring`, and `struct qdma_device` are the driver's core runtime objects.

Control flow role: the header does not execute code, but it fixes the ABI used by `qdma.c` to verify hardware, create queues, program context, build descriptors, and decode completion entries. The `QDMA_INTR_MASK_*` macros define how `qdma_queue_isr()` extracts PIDX/CIDX, descriptor color/state/error/type, QID, and ring color from each 64-bit aggregated interrupt entry. `QDMA_VDESC_QUEUED()` treats `sg_len == 0` as fully copied into hardware descriptors.

State and persistence behavior: all structures are in-memory driver state. Hardware-facing values include coherent descriptor addresses, interrupt ring bases, function ID, qid, register offsets, and context fields. The header contains no persistence mechanism; lifetime is managed by platform probe/remove, dmaengine resource allocation/free, and devm/dmam allocations in the implementation.

Dependencies and integration points: includes Linux bitfield, dmaengine, kernel, platform device, and regmap headers plus `../../virt-dma.h`. It depends on `linux/platform_data/amd_qdma.h` indirectly through `qdma.c` for filter map and queue info. The extern arrays `qdma_regos_default` and `qdma_regfs_default` are supplied by the companion common-register source and are required before any field or register access can work.

Risks and edge cases: this header encodes hardware ABI constants, so incorrect field ranges silently corrupt context programming or completion decoding. The generic names `ENABLE`, `DISABLE`, and `QDMA_DEFAULT_*` are private only because the header is local. `QDMA_MIN_DMA_ALLOC_SIZE` and several interrupt ring members are currently not central in `qdma.c`, so drift between declared state and active implementation is possible. `struct qdma_mm_desc` must remain packed and 32 bytes; any layout change breaks hardware descriptor consumption.

Test signals: compile coverage should include `BUILD_BUG_ON`-style validation for descriptor size/alignment if added, successful linkage with `qdma-comm-regs.c`, sparse/endian checks for little-endian descriptor members, and runtime smoke tests that validate register field extraction against known context values and interrupt entries.

# sources/distributed-fs/ceph-client/drivers/dma/apple-admac.c

Purpose: implements the Apple ADMAC audio DMA controller driver for Apple SoCs such as t8103. It exposes private cyclic DMA channels to audio clients, with hardwired even-channel TX and odd-channel RX directions, small hardware descriptor/report rings, and per-channel SRAM cache carveouts.

Important APIs and functions: `admac_probe()` reads `dma-channels`, maps MMIO, obtains an optional shared reset, initializes dmaengine cyclic callbacks, creates one `struct admac_chan` per channel, resets hardware, requests the selected IRQ output, registers the DMA device, and registers OF translation. `admac_prep_dma_cyclic()` creates an `admac_tx` with buffer and period metadata. `admac_issue_pending()` moves submitted work to issued, starts the current cyclic transfer, writes initial descriptors, and starts the hardware channel. `admac_device_config()` programs bus word width, frame width, and FIFO threshold/limit. `admac_interrupt()`, `admac_handle_status_desc_done()`, `admac_drain_reports()`, and `admac_chan_tasklet()` drain period reports and invoke cyclic callbacks.

Control flow: clients obtain a specific channel through `admac_dma_of_xlate()`, configure port width/frame size, prepare one cyclic buffer, submit it, then issue pending. The driver resets descriptor/report rings, writes one descriptor before start, enables per-channel descriptor-done/error interrupts, starts TX or RX using the channel pair bit, and writes up to four ring slots as space allows. On descriptor-done IRQ, it clears status, drains up to four report entries, advances reclaimed position, writes more descriptors to keep the cyclic ring full, and schedules a tasklet to issue one callback per acknowledged period.

State and persistence behavior: `struct admac_data` stores the dmaengine device, MMIO base, reset control, selected IRQ output index, channel count, and TX/RX SRAM allocation bitmaps. `struct admac_chan` stores lock-protected current transfer, submitted/issued/to-free lists, period-ack count, and SRAM carveout value. `struct admac_tx` stores cyclic buffer address range, length, period length, submitted and reclaimed positions. State is volatile; remove unregisters OF/dmaengine, frees IRQ, and rearms reset. There is no system PM handling.

Dependencies and integration points: depends on dmaengine cyclic APIs, OF DMA controller registration, platform IRQ/MMIO helpers, reset framework, tasklets, spinlocks, and Apple ADMAC device-tree compatibles `apple,t8103-admac` and `apple,admac`. It is tailored to audio peripheral use through `DMA_PRIVATE`, cyclic-only capability, and bus/frame controls derived from `dma_slave_config`.

Risks and edge cases: only cyclic transfers are supported, and the usual path assumes one long-lived cyclic transaction per channel. SRAM cache allocation uses one 2 KiB block per channel and a 32-bit bitmap, so cache sizes above the documented 64 KiB field assumption would not be representable. Residue calculation samples report-ring and residue registers non-atomically and uses heuristics around descriptor-load races. Error handling logs and clears ring errors but does not mark the active dmaengine transaction failed. `admac_synchronize()` splices `to_free` before killing the tasklet, so callers must follow terminate/synchronize ordering. No suspend/resume means active audio DMA is not preserved across power loss.

Test signals: useful signals include OF channel index bounds, reset/IRQ registration success, TX and RX cyclic playback/capture with period callbacks matching hardware reports, correct residue monotonicity during cyclic operation, pause/resume stop/start behavior, terminate-all followed by synchronize freeing descriptors, SRAM allocation exhaustion returning `-EBUSY`, bus width rejection for unsupported widths/window sizes, and ring-error interrupt logging without interrupt storms.

# sources/distributed-fs/ceph-client/drivers/dma/arm-dma350.c

Purpose: implements the Arm DMA-350 dmaengine driver for memory-to-memory copy and, when all channels support wrap/fill, memset. It uses per-channel command-link descriptors represented as register write command arrays and virtual DMA channels.

Important APIs and functions: `d350_probe()` verifies IIDR implementer/product, discovers channel count, data width, address width, trigger count, DMA coherency, and per-channel capabilities, then registers a dmaengine device. `d350_prep_memcpy()` builds a command array that writes CTRL, source/destination addresses, transfer size, memory attributes, increments, and link termination. `d350_prep_memset()` builds a fill transfer command when memset is enabled. `d350_start_next()` loads the command array into channel registers and enables the channel. `d350_irq()` handles DONE/ERR interrupts, maps AXI error info into dmaengine result codes, completes the current cookie, and starts queued work.

Control flow: probe clears each channel, skips channels without command-link support, records IRQ and feature bits, initializes `virt_dma_chan`, and optionally enables DMA_MEMSET only if every usable channel has wrap support. A client prepares memcpy/memset; `vchan_tx_prep()` queues a `d350_desc`. `d350_issue_pending()` moves pending descriptors into the issued list and starts the next descriptor when idle. Completion IRQ reads/acknowledges channel status, completes the active descriptor, updates status/residue, and chains to the next queued descriptor.

State and persistence behavior: `struct d350` stores the dmaengine device and discovered channel/request counts. Each `struct d350_chan` stores a virtual channel, active descriptor pointer, channel MMIO base, IRQ, dmaengine status, active cookie, residue, transfer size shift, feature flags, and coherency. `struct d350_desc` stores the command array and transfer size metadata. State is volatile and probe-time only; remove unregisters dmaengine but there are no explicit PM suspend/resume hooks.

Dependencies and integration points: uses dmaengine memcpy/memset APIs, `virt-dma`, OF compatible `arm,dma-350`, platform per-channel IRQs, MMIO register access, and DMA mask/coherency discovery. Memory attributes in command descriptors are chosen from device coherency (`TRANSCFG_WB` versus `TRANSCFG_NC`) and Arm shareability/memory attribute encodings.

Risks and edge cases: the driver is intentionally narrow and does not expose slave/cyclic/triggered transfers despite hardware trigger-related fields. `d350_irq()` assumes `dch->desc` is valid when an interrupt fires; unexpected shared IRQs before a descriptor could be hazardous. `d350_get_residue()` retries split high/low transfer-size reads only three times. `d350_tx_status()` calls `dma_set_residue(state, residue)` without a local null check after `dma_cookie_status()`, relying on normal dmaengine usage. Channels without command-link support are skipped, but the registered `chancnt` behavior depends on `vchan_init()` only for usable channels.

Test signals: probe should reject non-DMA-350 IIDR values, set DMA mask from address width, and expose DMA_MEMSET only when wrap/fill is available. Functional tests should verify memcpy across byte/halfword/word/dword-aligned sizes, memset pattern byte replication, chained descriptor execution, pause/resume state changes, terminate-all completion cleanup, read/write/abort error result mapping from `CH_ERRINFO`, and residue accuracy while running and paused.

# sources/distributed-fs/ceph-client/drivers/dma/at_hdmac.c

Purpose: implements the legacy Atmel AHB HDMA Controller dmaengine driver for AT91 SoCs. It supports platform-dependent memcpy, interleaved memory transfers, memset/memset SG, slave SG, and cyclic slave DMA, using hardware linked-list items allocated from DMA pools.

Important APIs and functions: `at_dma_probe()` selects SoC platform data, maps registers, enables the DMA clock, disables/reset hardware, creates LLI and memset DMA pools, initializes virtual channels, registers dmaengine, and optionally registers OF DMA translation. Descriptor preparation is split across `atc_prep_dma_memcpy()`, `atc_prep_dma_interleaved()`, `atc_prep_dma_memset()`, `atc_prep_dma_memset_sg()`, `atc_prep_slave_sg()`, and `atc_prep_dma_cyclic()`. `atc_dostart()` programs the first descriptor pointer and channel PIP registers, then enables the channel. `at_dma_interrupt()` dispatches BTC/error bits to `atdma_handle_chan_done()`. PM paths include `at_dma_prepare()`, `at_dma_suspend_noirq()`, and `at_dma_resume_noirq()`.

Control flow: prepared operations allocate an `at_desc` with one or more `struct atdma_sg` entries, each backed by a hardware `struct at_lli`. LLIs encode source/destination address, control A/B fields, and descriptor chaining via `dscr`; `set_lli_eol()` terminates non-cyclic chains, while cyclic prep loops the final `dscr` back to the first LLI. Submit and issue use `virt-dma`; when idle, `atc_dostart()` points the channel at the first LLI and enables it. Interrupt handling completes non-cyclic descriptors, calls cyclic callbacks without removing the descriptor, and starts queued work when hardware is idle.

State and persistence behavior: `struct at_dma` holds dmaengine registration, MMIO base, clock, saved interrupt mask, all-channel mask, descriptor pools, and channel array. `struct at_dma_chan` holds virtual channel, register base, interface IDs, status bits, saved CFG/DSCR for PM, slave config, and active descriptor. `struct at_desc` stores total length, SG count, interleaved PIP fields, optional memset buffer, and flexible SG array. Suspend blocks non-cyclic active transfers, preserves cyclic DSCR and channel CFG, disables the controller/clock, then restores interrupt mask, CFG, and cyclic channel state on resume.

Dependencies and integration points: depends on dmaengine/virt-dma, Atmel DT bindings from `dt-bindings/dma/at91.h`, clock framework, DMA pools, OF DMA translation, platform IDs `at91sam9rl_dma`/`at91sam9g45_dma`, and compatibles `atmel,at91sam9rl-dma`/`atmel,at91sam9g45-dma`. Slave users receive controller-specific `struct at_dma_slave` state via `chan->private` from `at_dma_xlate()`.

Risks and edge cases: many paths allocate per-LLI pool objects under GFP_NOWAIT/GFP_ATOMIC and must unwind partially built chains correctly. Error handling logs a critical bad descriptor but then pretends completion succeeded, so clients may not receive a DMA error result. `atc_terminate_all()` busy-waits without timeout for channel disable. Residue calculation reads DSCR/CTRLA with retry heuristics and can return `DMA_ERROR` if a stable DSCR is not observed. `atc_config()` requires `chan->private`, so non-OF or mem-only clients must avoid slave-only configuration. `BUG_ON()` in resource paths can crash on unexpected private data mismatch or freeing an enabled channel.

Test signals: cover probe for both SoC variants and capability masks, OF `dma_spec` parsing of interface/peripheral/FIFO fields, memcpy chunking at `ATC_BTSIZE_MAX`, interleaved identical-chunk validation and PIP fields, memset alignment and temporary pattern buffer cleanup, slave SG in both directions with burst/width conversion, cyclic callback continuity across suspend/resume, residue accuracy under active cyclic RX, channel pause/resume bits, terminate-all disable wait, and descriptor-pool leak checks on allocation failures.

# sources/distributed-fs/ceph-client/drivers/dma/at_xdmac.c

Purpose: implements the Atmel/Microchip Extended DMA Controller dmaengine driver for SAMA5D4/SAMA7G5-style XDMAC hardware. It supports cyclic, interleaved, memcpy, memset, memset SG, and slave SG transfers with descriptor recycling, per-channel tasklets, runtime PM, and system sleep restore for cyclic transfers.

Important APIs and functions: `at_xdmac_probe()` reads channel count from GTYPE or DT, obtains MMIO/IRQ/clock/layout data, creates a descriptor DMA pool, initializes dmaengine callbacks, runtime PM, channels, tasklets, and OF translation, then registers the controller. `at_xdmac_prep_slave_sg()`, `at_xdmac_prep_dma_cyclic()`, `at_xdmac_prep_interleaved()`, `at_xdmac_prep_dma_memcpy()`, `at_xdmac_prep_dma_memset()`, and `at_xdmac_prep_dma_memset_sg()` build linked descriptors. `at_xdmac_start_xfer()` programs CNDA/CNDC/CC, enables interrupts, and starts a channel. `at_xdmac_interrupt()` snapshots per-channel status and schedules `at_xdmac_tasklet()`, which completes cookies, recycles descriptors, handles errors, and starts queued transfers.

Control flow: channel resources preallocate a free descriptor list. Prep functions pop descriptors with `at_xdmac_get_desc()`, fill LLD fields (`mbr_sa`, `mbr_da`, `mbr_ubc`, `mbr_cfg`, strides/block counts), chain descriptors via `mbr_nda`, and return the first descriptor as the dmaengine transaction. Submit adds the transaction to `xfers_list`; issue-pending calls `at_xdmac_advance_work()`, which starts the first inactive transfer if hardware is idle. Completion interrupts are filtered by global/channel masks; the tasklet handles cyclic callbacks on block interrupts or non-cyclic list-complete/error handling on LIE/error bits.

State and persistence behavior: `struct at_xdmac` stores dmaengine registration, MMIO base, IRQ, clock, saved global mask/status, descriptor pool, and layout variant. `struct at_xdmac_chan` stores channel registers, mask, computed config, DT peripheral/interface IDs, saved channel registers for PM, last IRQ status, status bits, tasklet, slave config, lock, active transfer list, and free descriptor list. `struct at_xdmac_desc` stores a hardware LLD, direction, dmaengine descriptor, descriptor node, active flag, transfer size, list of descriptors in the transaction, and transaction list node. Runtime PM refs are acquired for active transfers and released on completion/terminate/pause; system suspend saves active cyclic state and restores CC/CNDA/CNDC/CIE and enabled state on resume.

Dependencies and integration points: depends on dmaengine, OF DMA, Atmel DMA DT bindings, clocks, runtime PM, DMA pools, tasklets, and platform compatibles `atmel,sama5d4-dma` and `microchip,sama7g5-dma`. Layout structs abstract register offsets and whether source/destination interface fields and AXI priority configuration are used. `at_xdmac_axi_config()` selects memory-to-memory or peripheral priority policy on SAMA7G5 based on DT `dma-requests`.

Risks and edge cases: several allocation-failure paths splice partially built descriptor lists back to the free list, so list integrity is critical. `at_xdmac_prep_dma_cyclic()` sets the cyclic bit before computing config and does not clear it on all early failures. `at_xdmac_tx_status()` assumes `xfers_list` has an entry when status is in progress and uses FIFO flush/busy-wait loops without timeouts. Error handling logs bus/request errors and disables the channel but does not propagate a rich dmaengine result to clients. Runtime PM reference balancing is complex across start, completion, pause/resume, terminate, suspend, and remove. `at_xdmac_prep_dma_memset_sg()` has intricate merge logic and should be tested for one-entry and failed-descriptor cases.

Test signals: cover both layout compatibles, channel-count validation, OF xlate extraction of memif/perif/perid, runtime PM autosuspend/resume under active transfers, memcpy splitting near `AT_XDMAC_MBR_UBC_UBLEN_MAX`, interleaved stride/block-count behavior, memset and memset SG descriptor merging, slave SG both directions with maxburst/address-width validation, cyclic period callbacks and suspend/resume restoration, residue calculation during peripheral RX with FIFO flush, pause/resume PM ref balance, terminate-all descriptor recycling, and bus/request-overflow error logging without list corruption.
