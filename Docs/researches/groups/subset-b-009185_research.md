# sources/sync-backup/syncthing/gui/default/assets/lang/lang-it.json

Purpose: provides Italian translations for Syncthing's default AngularJS web GUI. It is a generated static locale table served from `assets/lang/lang-it.json` when locale key `it` is selected, negotiated, or restored, and it localizes user-visible labels, dialogs, warnings, status text, tooltips, versioning text, device/folder configuration text, network text, and theme names.

Important APIs/types/functions: the file is a JSON object used as an angular-translate translation table; it exports no executable functions. Keys are the English source strings used by `translate` directives, translate filters, and `$translate.instant(...)` calls. Values are Italian strings, with nested `theme.name.black`, `theme.name.dark`, `theme.name.default`, and `theme.name.light` values under the `theme` object. The inspected table has 551 top-level keys and 554 flattened leaves versus 558 English top-level keys. It contains 25 interpolation-bearing keys and preserves all placeholder variables with Angular interpolation syntax in values, including `{{foldertype}}`, `{{name}}`, `{{label}}`, `{{count}}`, `{{file}}`, `{{device}}`, `{{address}}`, `{{receiveEncrypted}}`, `{{url}}`, `{{devicename}}`, `{{version}}`, `{{otherFolder}}`, `{{otherFolderLabel}}`, `{{syncthingInotify}}`, `{{folder}}`, `{{folderlabel}}`, and `{{reintroducer}}`.

Control flow: `syncthing/app.js` configures `$translateProvider.useStaticFilesLoader({ prefix: 'assets/lang/lang-', suffix: '.json' })`, sets English fallback, and wires available locales through `LocaleServiceProvider`. `LocaleService.autoConfigLocale()` selects a language from `?lang=`, localStorage key `SYN_LANG`, or `/rest/svc/lang` browser preference negotiation. Because `it` is listed in `valid-langs.js` and `prettyprint.js` names it `Italian`, normal locale discovery and UI selection can reach this file. After `$translate.use('it')` resolves, Angular directives and filters read entries from this JSON table; missing keys fall back through the configured English language.

State and persistence behavior: this file is immutable runtime data. The only related persisted state is the user's selected language in browser localStorage under `SYN_LANG`; the active runtime state is Angular's selected translation table plus `document.documentElement.lang = 'it'`. The source file itself is generated from Weblate, as stated by `assets/lang/README.txt`, and should not be hand-edited because upstream translation pulls will overwrite local changes.

Dependencies and integration points: depends on valid JSON parsing by angular-translate's static files loader, the `pascalprecht.translate` Angular module, `ngSanitize` with escape sanitization, Syncthing's `/rest/svc/lang` endpoint for browser preference detection, and `valid-langs.js`/`prettyprint.js` for availability and display. It also depends on the GUI's extraction/update tooling (`script/translate.go` for English source-key extraction and `script/weblatedl.go` for generated translation downloads) to keep key coverage aligned with templates and JavaScript.

Risks: the main risk is coverage drift: 7 English keys are absent (`Block Indexing`, `Device Group`, `Folder Group`, the block-indexing explanatory sentence, both optional group explanatory strings, and `Starting`), so those UI fragments will display in English when Italian is active. Nine values equal their English keys (`Debug`, `Default`, `Info`, `LDAP`, `Log`, `No`, `OK`, `Password`, `file`); some are acceptable technical labels, but they are signals for translator review. Runtime breakage risk from interpolation is low in the inspected version because placeholder names match their keys. Layout risk remains for longer Italian warning and settings strings in compact controls.

Test signals: `jq -e 'type == "object"'` parses the file successfully. Structural checks found no empty values, no keys outside `lang-en.json`, 7 missing English keys, and zero placeholder mismatches. Useful UI checks are loading `?lang=it`, opening device/folder edit dialogs, exercising receive-encrypted folder warnings, pending device/folder share notifications, upgrade text, versioning settings, and theme selector labels to catch fallback, interpolation, and wrapping regressions.

UI checks should select `?lang=ja`, walk the settings and advanced dialogs where fallback is likely, and exercise pending device/folder notifications, delete/restore confirmation dialogs, path-warning dialogs, and update buttons to verify interpolation and Japanese line wrapping.

# sources/sync-backup/syncthing/gui/default/assets/lang/lang-ne.json

Purpose: provides a very small Nepali translation fragment for Syncthing's default AngularJS web GUI. It contains only core labels such as About, Actions, Add, Add Device, Add Folder, Address, Advanced, All Data, Close, Command, Compression, Configured, Connection Error, Connection Type, copied-from labels, Danger, and LDAP. Unlike the other files in this work item, it is not advertised in `valid-langs.js`, so it is not a normal selectable or browser-negotiated locale despite the JSON file existing.

Important APIs/types/functions: the file is a JSON object consumed by angular-translate if locale key `ne` is explicitly used. It has 26 top-level keys and 26 leaves, no nested `theme` object, and no interpolation-bearing entries. It exports no functions or classes; the only contract is valid JSON with English translation IDs mapped to Nepali strings.

Control flow: the global translation loader in `app.js` can technically request `assets/lang/lang-ne.json` when `$translate.use('ne')` is called, because it builds URLs from the requested locale key. However, `LocaleServiceProvider.setAvailableLocales(validLangs)` receives a list that does not include `ne`, and `prettyprint.js` does not provide a display name. That means browser preference matching and the normal language list will skip Nepali. A direct `?lang=ne` can still call `useLocale('ne', true)` and attempt to load the static file, after which nearly all GUI strings will fall back to English due to missing keys.

State and persistence behavior: the JSON itself has no mutable state. If explicitly selected with the query parameter flow, `LocaleService.useLocale('ne', true)` may persist `SYN_LANG=ne` in localStorage after a successful load and set the document `lang` attribute to `ne`. Because `ne` is not in `validLangs`, that persisted state can select an otherwise hidden partial locale on subsequent loads. The file is generated translation data according to the language directory README.

Dependencies and integration points: depends on angular-translate's static JSON loader, English fallback, and the general locale service. Its integration is incomplete because `valid-langs.js` omits `ne` and `prettyprint.js` has no Nepali display name. It still shares the same maintenance path as other language files: English key extraction through `script/translate.go` and generated language pulls through `script/weblatedl.go` or translation automation.

Risks: this file is only a fragment. It is missing 532 English keys, has no theme-name translations, and covers almost none of the advanced, security, versioning, sharing, ignore-pattern, logging, ownership, or network text. Because it is not advertised, the user-facing risk in normal operation is low; the risk appears when a user manually selects `?lang=ne` or has stale `SYN_LANG=ne`, producing a heavily mixed English/Nepali interface. One value equals English (`LDAP`), which is likely acceptable as an acronym. There are no placeholder mismatches because there are no placeholder-bearing translations.

Test signals: `jq` validates the file as an object. Structural checks found 26 keys, 532 missing English keys, zero extra keys, no empty values, and no placeholder mismatches. Integration tests should verify whether `?lang=ne` is intended to be supported, whether `SYN_LANG=ne` persistence should be allowed when the locale is absent from `validLangs`, and whether Weblate generation should either publish Nepali in `valid-langs.js` or remove the hidden fragment from shipped assets.
