# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/agn.h

Purpose: Central public header for the legacy iwlwifi DVM/AGN opmode. It collects device constants, status-bit definitions, mac80211 entry points, firmware command send helpers, RXON/channel/scan/station/rate/calibration prototypes, small inline helpers, and debugfs registration stubs used across the DVM implementation.

Important APIs and definitions: The file exports `iwlagn_hw_ops`, DVM configuration objects for 1000/2000/5000/6000 families, queue constants such as `IWLAGN_FIRST_AMPDU_QUEUE`, `IWL_AUX_QUEUE`, and `IWL_INVALID_STATION`, and status bit indexes including `STATUS_READY`, `STATUS_ALIVE`, `STATUS_SCANNING`, `STATUS_FW_ERROR`, and `STATUS_POWER_PMI`. `iwl_set_calib_hdr()` initializes firmware calibration command headers. Command APIs are `iwl_dvm_send_cmd()` and `iwl_dvm_send_cmd_pdu()`. Runtime/probe APIs include `iwl_alloc_all()`, `iwlagn_mac_setup_register()`, `iwlagn_mac_unregister()`, `iwl_down()`, `iwl_cancel_deferred_work()`, `iwlagn_prepare_restart()`, and `iwl_rx_dispatch()`. RXON and association configuration are exposed through `iwl_connection_init_rx_config()`, `iwlagn_commit_rxon()`, `iwlagn_set_rxon_chain()`, `iwlagn_mac_config()`, `iwlagn_bss_info_changed()`, `iwl_set_rxon_ht()`, and related band/channel helpers. TX and aggregation entry points include `iwlagn_tx_skb()`, `iwlagn_tx_agg_start()`, `iwlagn_tx_agg_oper()`, `iwlagn_tx_agg_stop()`, `iwlagn_tx_agg_flush()`, `iwlagn_rx_reply_tx()`, and `iwlagn_rx_reply_compressed_ba()`. Station/key/rate helpers include `iwl_add_station_common()`, `iwl_send_add_sta()`, `iwl_remove_station()`, `iwl_set_dynamic_key()`, `iwl_remove_dynamic_key()`, `iwl_send_lq_cmd()`, `iwl_sta_rx_agg_start()`, `iwl_sta_rx_agg_stop()`, `iwl_sta_id()`, `iwl_ant_idx_to_flags()`, `iwl_hw_get_rate()`, and `iwl_hw_set_rate_n_flags()`.

Control flow: This header does not implement the driver lifecycle, but it defines the call graph shared by probe, mac80211 callbacks, firmware boot, scan, station management, TX/RX completion, calibration, and debugfs code. Status helpers gate operations on `priv->status`: `iwl_is_ready()` requires `STATUS_READY` and no `STATUS_EXIT_PENDING`, `iwl_is_alive()` checks firmware alive state, `iwl_is_rfkill()` and `iwl_is_ctkill()` distinguish hardware RF kill and critical-temperature kill, and `iwl_is_ready_rf()` combines readiness with RF-kill exclusion. `iwl_tx_status_to_mac80211()` maps firmware TX status codes to mac80211 ACK/filtered reporting, while `iwl_is_tx_success()` centralizes the firmware success predicate.

State and persistence: The header defines symbolic access to runtime state stored in `struct iwl_priv`: status bits, station IDs, NVM/EEPROM data, hardware bands, transport PMI state, RXON contexts, and per-station private data. `iwl_dvm_set_pmi()` mutates both `STATUS_POWER_PMI` and transport PMI state through `iwl_trans_set_pmi()`. No durable persistence is implemented here, but declared EEPROM/NVM parsing routines shape how persistent device configuration is imported into runtime state.

Dependencies and integration points: Includes `iwl-config.h`, `dev.h`, and indirectly the DVM private structures and firmware ABI from `commands.h`. The APIs bridge Linux mac80211, cfg80211 WoWLAN, transport command submission, firmware image loading, EEPROM/NVM parsing, station/key management, scan scheduling, Bluetooth coexistence, rate scaling, power management, and optional `CONFIG_IWLWIFI_DEBUGFS` registration. The inline debug helpers depend on `CONFIG_IWLWIFI_DEBUG` and route RF-kill-sensitive errors to quieter log modes.

Risks: Because this is a high-fanout header, prototype drift can break many DVM translation units. Status-bit constants must remain consistent with code that sets and tests `priv->status`. The TX status mapping intentionally treats only destination power-save and passive-no-RX failures as filtered; changing it can affect mac80211 retry/accounting behavior. `iwl_sta_id()` trusts mac80211 station private data after a `WARN_ON(!sta)`, so callers must not pass stale station pointers. `iwl_dvm_set_pmi()` has side effects beyond the bitset and must be used only when the transport can accept PMI changes.

Test signals: Build all DVM-supported device families with and without `CONFIG_IWLWIFI_DEBUG` and `CONFIG_IWLWIFI_DEBUGFS`; exercise mac80211 registration/unregistration, firmware alive/restart, RF-kill and CT-kill transitions, scan start/cancel/timeout, RX dispatch, normal TX and aggregation, station add/remove/key update, rate table updates, calibration result replay, EEPROM/NVM parsing, and PMI toggles.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/calib.c

Purpose: Implements DVM initialization-calibration result storage/replay and runtime receiver calibration. Runtime calibration has two main responsibilities: tune receiver sensitivity from firmware statistics so false alarms stay in target ranges, and run one-time chain-noise calibration after association to detect disconnected antennas and balance RX-chain gain.

Important APIs and functions: `iwl_send_calib_results()` replays saved `REPLY_PHY_CALIBRATION_CMD` payloads from `priv->calib_results`. `iwl_calib_set()` stores or replaces an opaque calibration result by operation code using `kmalloc_flex()`. `iwl_calib_free_results()` releases the saved list. `iwl_init_sensitivity()` initializes `priv->sensitivity_data` from `priv->hw_params.sens` and sends either a legacy or enhanced `SENSITIVITY_CMD`. `iwl_sensitivity_calibration()` consumes firmware statistics and updates sensitivity. `iwl_chain_noise_calibration()` accumulates beacon signal/noise samples and sends chain-noise gain calibration. `iwl_reset_run_time_calib()` clears runtime calibration state and requests fresh statistics. Static helpers include `iwl_sens_energy_cck()`, `iwl_sens_auto_corr_ofdm()`, `iwl_prepare_legacy_sensitivity_tbl()`, `iwl_sensitivity_write()`, `iwl_enhance_sensitivity_write()`, `find_first_chain()`, `iwl_find_disconn_antenna()`, and `iwlagn_gain_computation()`.

Control flow: Init calibration results are captured as opaque firmware commands, keyed by `cmd.hdr.op_code`, and later replayed in list order with `iwl_dvm_send_cmd()`. Runtime sensitivity begins with `iwl_init_sensitivity()`, which aborts if sensitivity calibration is disabled or no sensitivity range table is present, initializes OFDM/CCK thresholds, zeroes rolling histories, and writes the starting table. During association, `iwl_sensitivity_calibration()` checks that the device is associated, locks `priv->statistics.lock`, validates `INTERFERENCE_DATA_AVAILABLE`, copies RX enable time, false alarm, PLCP error, beacon RSSI, and beacon energy fields, unlocks, differences monotonic counters with wrap/reset handling, computes normalized OFDM/CCK false alarms, updates OFDM auto-correlation thresholds, updates CCK energy and auto-correlation thresholds, then sends a changed sensitivity table asynchronously.

State and persistence: Calibration results persist in memory on `priv->calib_results` until freed, surviving firmware image transitions long enough to be replayed. Sensitivity state is stored in `priv->sensitivity_data`, including last false-alarm/PLCP counters, auto-correlation thresholds, energy threshold, rolling 10-beacon energy and 20-beacon silence histories, and current/previous false-alarm state. Cached command tables in `priv->sensitivity_tbl` and `priv->enhance_sensitivity_tbl` suppress duplicate firmware writes. Chain-noise state is stored in `priv->chain_noise_data`, including accumulated beacon signal/noise, disconnected-chain flags, active chain mask, delta gain codes, radio-write flag, and calibration state. Firmware statistics are shared under `priv->statistics.lock`.

Dependencies and integration points: Depends on firmware ABI definitions from `commands.h`, private driver state from `dev.h`, command helpers from `agn.h`, Linux allocation/list helpers, mac80211 association state through `iwl_is_any_associated()`, NVM antenna masks, Bluetooth coexistence config, RXON context state, power management via `iwl_power_update_mode()`, chain flag update via `iwl_update_chain_flags()`, and transport command submission. Calibration command IDs, sensitivity table indexes, false-alarm thresholds, and antenna masks all come from the DVM firmware contract.

Risks: The sensitivity algorithms depend on monotonically increasing firmware counters and correct endian conversion. Bad `rx_enable_time` handling can cause divide/scale errors, so zero RX time is explicitly ignored. CCK energy values are inverted, making min/max use easy to break. `iwl_calib_set()` uses `GFP_ATOMIC`, so large or frequent calibration results can fail under memory pressure. Chain-noise calibration assumes a single BSS RXON context and only accumulates statistics from the associated channel; multi-channel operation is explicitly marked as needing fixes. Incorrect active-chain detection can disable usable antennas or enable absent ones, so the result is masked by `valid_rx_ant` and forced to keep at least one valid TX chain connected. Command writes are asynchronous in several paths, so callers must tolerate delayed firmware application.

Test signals: Verify init-calibration storage replacement by op code, replay ordering, and free paths. Exercise sensitivity init for legacy and enhanced tables, disabled calibration masks, missing ranges, duplicate table suppression, too-many/too-few/good false-alarm paths for OFDM and CCK, firmware counter wrap/reset behavior, zero RX enable time, and statistics unavailable. For chain noise, test accumulation over exactly `IWL_CAL_NUM_BEACONS`, channel/band mismatch rejection, advanced-BT bypass, all-zero RSSI handling, disconnected-chain detection, gain-code sign/magnitude encoding, one-time radio write, RXON chain update, and power mode refresh.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/calib.h

Purpose: Small public header for DVM runtime calibration entry points. It exposes sensitivity and chain-noise calibration routines to the RX/statistics and device lifecycle code without exposing the implementation details in `calib.c`.

Important APIs and types: Declares `iwl_chain_noise_calibration()`, `iwl_sensitivity_calibration()`, `iwl_init_sensitivity()`, and `iwl_reset_run_time_calib()`. It includes `dev.h` for `struct iwl_priv` and calibration state, and `commands.h` for firmware calibration and sensitivity command definitions.

Control flow: Callers initialize sensitivity after firmware/device setup with `iwl_init_sensitivity()`, reset runtime calibration state with `iwl_reset_run_time_calib()` around association or firmware restart boundaries, and invoke `iwl_sensitivity_calibration()` plus `iwl_chain_noise_calibration()` when firmware statistics notifications provide the beacon/interference data needed by the algorithms.

State and persistence: The header owns no state directly. Its functions mutate `priv->sensitivity_data`, `priv->chain_noise_data`, cached sensitivity command tables, and firmware calibration state through the implementation in `calib.c`.

Dependencies and integration points: Used by DVM RX/statistics handling, association/RXON paths, and firmware initialization code. It binds DVM private state to firmware command structures such as `struct iwl_sensitivity_cmd`, `struct iwl_enhance_sensitivity_cmd`, and `struct iwl_calib_chain_noise_gain_cmd`.

Risks: Because this header hides no locking contract in the prototypes, callers must rely on the implementation to take `priv->statistics.lock` where needed and must call these routines only when firmware statistics and association state are meaningful. Prototype drift would break calibration invocation across DVM files.

Test signals: Compile coverage for every caller, runtime coverage for association setup, statistics-notification processing, firmware restart/runtime calibration reset, and builds with calibration-related firmware command structures changed.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/commands.h

Purpose: Defines the legacy iwlwifi DVM firmware/uCode ABI. The file is intentionally limited to command IDs, packed command payloads, notification payloads, bit masks, endian-tagged fields, and protocol documentation for AGN firmware interactions; implementation state belongs in `dev.h` and hardware register definitions belong in hardware-specific headers.

Important APIs and definitions: The top-level command enum assigns IDs for alive/error, RXON, QoS, station, TX/RX, coexistence, calibration, 802.11h, power, scan, beacon, statistics, RF-kill, Bluetooth coexistence, PAN/WiPAN, and WoWLAN commands. Queue/FIFO constants define command queue selection, PAN queues, AUX scan TX queue, and SCD masks. Common rate fields are described by `RATE_MCS_*` masks and antenna masks. Firmware lifecycle structures include `struct iwl_alive_resp`, `struct iwl_error_event_table`, and `struct iwl_error_resp`. RXON/channel structures include `struct iwl_rxon_cmd`, `struct iwl_rxon_assoc_cmd`, `struct iwl_rxon_time_cmd`, channel switch commands for 5000/6000, and CSA notifications. Station/security structures include `struct iwl_addsta_cmd`, `struct iwl_keyinfo`, WEP key commands, add/remove station responses, and TID/aggregation flags. TX structures include `struct iwl_tx_cmd`, `struct iwl_tx_cmd_hdr`, `struct iwlagn_tx_resp`, `struct iwl_compressed_ba_resp`, and `struct iwl_link_quality_cmd`. RX/statistics structures include `struct iwl_rx_phy_res`, `struct iwl_rx_mpdu_res_start`, `struct iwl_notif_statistics`, `struct iwl_bt_notif_statistics`, and the nested RX/TX/general statistics layouts. Calibration structures include sensitivity commands, calibration config, generic calibration headers, crystal/temperature commands, and chain-noise reset/gain commands. Later sections define LED, WiMAX coexistence, Bluetooth coexistence, D3/WoWLAN security material, WiPAN slots, P2P channel switch, and NoA notifications.

Control flow: This header describes firmware-driven workflows rather than executing them. RXON commands tune channel/radio state and, when sent without association, clear firmware station and TX power tables, forcing the driver to rebuild station and power state before normal TX. TX commands are DMA-owned firmware descriptors; firmware retries according to flags and link-quality tables, reports TX status, and sends compressed block-ack notifications for aggregation. Scan commands drive a firmware scan state machine that leaves and returns to the service channel, emits start/result/complete notifications, and enforces timing constraints. Statistics commands and notifications feed runtime calibration and debugfs reporting. Calibration config selects firmware and driver calibrations, while sensitivity and chain-noise commands apply driver-derived RX thresholds and gain codes. Power, RF-kill, CT-kill, BT/WiMAX coexistence, WoWLAN, and WiPAN command structures define side-channel state machines used by other DVM modules.

State and persistence: The file owns no C runtime state, but it defines firmware-resident state that persists until firmware reset, RXON retune, RF-kill, or explicit commands: station tables, key tables, TX power tables, rate retry tables, scheduler queues, scan ownership, statistics counters, calibration tables, power-save configuration, coexistence tables, WoWLAN replay counters/patterns, and WiPAN schedules. Many fields are `__le16`, `__le32`, or `__le64`, and many structures are `__packed`, so byte layout and endian conversion are part of the persistent hardware/firmware contract.

Dependencies and integration points: Includes Linux IEEE 802.11 and type definitions, and is consumed by DVM modules for RXON, TX, scan, station, power, Bluetooth coexistence, WoWLAN suspend, debugfs statistics, calibration, and event handling. It integrates with mac80211 concepts such as EDCA access categories, QoS TIDs, A-MPDU block ack, channel flags, beacon timing, security ciphers, and WoWLAN pattern/rekey state. Transport command senders use these structures as payloads for `iwl_dvm_send_cmd()` and `iwl_dvm_send_cmd_pdu()`.

Risks: This is an ABI header; changing field order, packing, widths, endian annotations, command IDs, or bit positions can break firmware communication. Several command IDs are shared or versioned, such as old TX power and TX antenna configuration on `0x98`, so call sites must select the correct payload for device family. RXON side effects can silently wipe station and TX power tables. Firmware statistics counters are documented as monotonic with wrap/reset behavior, and consumers must compute deltas carefully. Flexible-array command structures require correct allocation and length calculation. Rate, TX status, aggregation, sensitivity, WoWLAN key material, and BT UART bitfields are dense and easy to mis-mask.

Test signals: Compile with all DVM device families and static layout assertions where available. Exercise firmware boot alive/error parsing, RXON/association transitions and table rebuilds, station add/remove/key commands, WEP/TKIP/CCMP paths, normal TX and aggregation status decoding, compressed BA handling, link-quality table updates, scan start/result/complete/abort, statistics request/notification parsing, missed-beacon handling, sensitivity and chain-noise command emission, power-save commands and notifications, RF-kill/CT-kill, BT/WiMAX coexistence commands and notifications, WoWLAN pattern/rekey/status flows, and WiPAN/NoA handling.

# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/debugfs.c

Purpose: Implements DVM debugfs support. It creates `data`, `debug`, and `rf` debugfs directories and exposes runtime driver state, firmware SRAM/NVM snapshots, station/TID state, firmware statistics, calibration internals, power-save state, Bluetooth coexistence state, and multiple debug/control knobs for diagnostics and fault injection.

Important APIs and functions: `iwl_dbgfs_register()` is the public registration entry point and installs all files with `debugfs_create_file()`. Macro-generated file operations wrap read, write, and read/write handlers. Data readers include `iwl_dbgfs_sram_read/write()`, `iwl_dbgfs_wowlan_sram_read()`, `iwl_dbgfs_nvm_read()`, `iwl_dbgfs_stations_read()`, `iwl_dbgfs_channels_read()`, `iwl_dbgfs_status_read()`, `iwl_dbgfs_rx_handlers_read/write()`, `iwl_dbgfs_qos_read()`, `iwl_dbgfs_thermal_throttling_read()`, `iwl_dbgfs_temperature_read()`, `iwl_dbgfs_sleep_level_override_read/write()`, and `iwl_dbgfs_current_sleep_command_read()`. Statistics readers include `iwl_dbgfs_ucode_rx_stats_read()`, `iwl_dbgfs_ucode_tx_stats_read()`, `iwl_dbgfs_ucode_general_stats_read()`, `iwl_dbgfs_ucode_bt_stats_read()`, and `iwl_dbgfs_reply_tx_error_read()`. Calibration/RF/debug knobs include `iwl_dbgfs_sensitivity_read()`, `iwl_dbgfs_chain_noise_read()`, `iwl_dbgfs_clear_ucode_statistics_write()`, `iwl_dbgfs_ucode_tracing_read/write()`, `iwl_dbgfs_missed_beacon_read/write()`, `iwl_dbgfs_plcp_delta_read/write()`, `iwl_dbgfs_rf_reset_read/write()`, `iwl_dbgfs_txfifo_flush_write()`, `iwl_dbgfs_protection_mode_read/write()`, `iwl_dbgfs_echo_test_write()`, `iwl_dbgfs_calib_disabled_read/write()`, `iwl_dbgfs_fw_restart_write()`, and optional `iwl_dbgfs_log_event_read/write()`.

Control flow: Registration stores `priv->debugfs_dir`, creates the three subdirectories, then adds files with permissions matching read-only status views, writable knobs, and read/write controls. Read handlers generally allocate a formatted buffer, snapshot driver or firmware state, and return via `simple_read_from_buffer()`. SRAM reads require `iwl_is_ready_rf()`, default to the firmware data section when no offset/length is configured, handle unaligned byte extraction from `iwl_trans_read_mem32()`, and use a special single-word device format when the write side provides only an offset. Statistics readers require firmware alive state, lock `priv->statistics.lock`, format current/cumulative/delta/max values, and unlock before returning. Write handlers parse small numeric inputs from userspace and mutate debug settings or invoke driver actions such as statistics clear, power-mode update, RF reset, TX FIFO flush, echo command, event-log tracing timer toggles, calibration disable masks, or firmware restart fault injection.

State and persistence: The file reads and mutates many `struct iwl_priv` fields: SRAM debug offset/length, WoWLAN SRAM buffer, EEPROM blob/NVM data, station tables and TID aggregation state, RX handler counters, QoS data, thermal throttle state, `disable_ht40`, temperature, power debug override and sleep command, firmware statistics snapshots and accumulated/delta/max statistics, BT state, TX error counters, sensitivity and chain-noise calibration state, missed beacon and PLCP thresholds, RF reset counters, event-log tracing state and timer, RXON active flags, calibration disable mask, and global `iwlwifi_mod_params.fw_restart` during firmware restart injection. Most changes are runtime-only debug state; some writes immediately command firmware or alter driver behavior until reset or later debug writes.

Dependencies and integration points: Depends on Linux debugfs, user-copy helpers, memory allocation, mac80211 channel structures, iwl transport memory/register access, command submission, DVM status helpers from `agn.h`, firmware ABI structures from `commands.h`, calibration state from `dev.h`, power management, RF reset, TX FIFO flush, event-log dump support under `CONFIG_IWLWIFI_DEBUG`, and optional advanced Bluetooth coexistence. The symlink to mac80211 debugfs depends on `priv->mac80211_registered` and `hw->wiphy->debugfsdir`.

Risks: Debugfs write handlers are privileged but can change live behavior: disabling HT40, overriding sleep level, clearing statistics, forcing RF reset, flushing TX FIFOs, changing aggregation protection, disabling calibrations, triggering echo commands, and injecting firmware restart. Several handlers parse tiny fixed buffers, so input is intentionally narrow but malformed input returns `-EFAULT` or `-EINVAL` inconsistently. SRAM reads touch device memory and depend on readiness and correct offset/length; bad offsets can produce misleading diagnostics or transport failures. Statistics snapshots may already be stale by design. Some readers allocate buffers sized by current station/NVM/stat structures and must avoid overflow by consistent `scnprintf()` use. The mac80211 symlink is explicitly not robustly removed by this file and relies on broader teardown ordering.

Test signals: Build with `CONFIG_IWLWIFI_DEBUGFS` and with/without `CONFIG_IWLWIFI_DEBUG`; verify directory and file permissions under `data`, `debug`, and `rf`; read SRAM default/custom/single-word forms; read WoWLAN SRAM absent/present; dump NVM with valid and invalid lengths; inspect station/TID, channel, status, QoS, thermal, temperature, power-save, RXON, sensitivity, chain-noise, BT, and TX-error outputs; reset RX handler counters; reject HT40 changes while associated; apply sleep override and confirm `iwl_power_update_mode()`; clear statistics; toggle uCode tracing timer; set missed-beacon and PLCP thresholds inside/outside ranges; force RF reset; flush TX FIFO with and without RF-kill; switch protection mode; run echo test; read/write event log in debug builds; set calibration disable masks; trigger firmware restart injection and validate reset recovery.
