# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/pcie.c

Purpose: Implements the mwifiex PCIe bus backend for Marvell/NXP Wi-Fi devices. It binds PCI IDs for 88W8766P, 88W8897, and 88W8997 devices, maps BARs, allocates DMA rings, downloads firmware, moves command/data/event traffic between the common mwifiex core and firmware, handles power-management wake/suspend, supports PCI reset recovery, and exposes PCIe-specific firmware/register dump hooks.

Important APIs and functions: The file installs `pcie_ops`, a `struct mwifiex_if_ops` consumed by the common core. Core lifecycle entry points are `mwifiex_init_pcie()`, `mwifiex_cleanup_pcie()`, `mwifiex_register_dev()`, `mwifiex_unregister_dev()`, `mwifiex_pcie_up_dev()`, and `mwifiex_pcie_down_dev()`. PCI driver callbacks are `mwifiex_pcie_probe()`, `mwifiex_pcie_remove()`, suspend/resume hooks, shutdown, coredump, and PCI error reset callbacks. Data path helpers include `mwifiex_pcie_host_to_card()`, `mwifiex_pcie_send_data()`, `mwifiex_pcie_send_data_complete()`, `mwifiex_pcie_process_recv_data()`, `mwifiex_pcie_send_cmd()`, `mwifiex_pcie_process_cmd_complete()`, `mwifiex_pcie_process_event_ready()`, and `mwifiex_pcie_event_complete()`. Firmware/reset helpers include `mwifiex_prog_fw_w_helper()`, `mwifiex_extract_wifi_fw()`, `mwifiex_check_fw_status()`, `mwifiex_pcie_card_reset()`, `mwifiex_pcie_reg_dump()`, and `mwifiex_pcie_fw_dump()`.

Control flow: Probe allocates `struct pcie_service_card`, copies chip-specific register/device metadata from `driver_data`, validates an optional device-tree compatible string, initializes platform quirks, and calls `mwifiex_add_card()` with `pcie_ops`. Interface init enables PCI, sets bus mastering and 32-bit coherent DMA, requests/iomaps BAR 0 and BAR 2, allocates TX/RX/event rings plus command response and optional sleep-cookie buffers, then records 8897 Bluetooth coexistence behavior. Firmware download disables host interrupts, polls boot-helper command size, maps a staging skb, writes command DMA address/size scratch registers, rings `CPU_INTR_DOOR_BELL`, waits for acknowledgement, retries CRC-indicated blocks, and handles the FLR scratch marker by extracting the Wi-Fi subimage from combo firmware. Runtime IRQ handling records interrupt status in `adapter->int_status`, queues mwifiex main work, then `mwifiex_process_int_status()` dispatches download completion, upload data, events, and command responses.

State and persistence: `pcie_service_card` owns all PCIe state: PCI device, adapter pointer, chip register profile, completion for firmware load, coherent ring bases, software ring pointers, skb arrays, command/response buffers, sleep cookie DMA memory, BAR mappings, MSI/MSI-X state, deferred work flags, reset state, and DMI quirk bits. Ring ownership is split with firmware: the driver advances TX write/RX read/event read pointers while firmware advances the complementary pointers. TX and RX descriptors use either legacy `mwifiex_pcie_buf_desc` or PFU `mwifiex_pfu_buf_desc` layout based on chip metadata. DMA mappings are stored in skb control metadata and are unmapped only when firmware consumes or returns the buffer. Adapter state touched here includes `data_sent`, `cmd_sent`, `cmd_resp_received`, `event_received`, `event_skb`, `tx_hw_pending`, `rx_pending`, power-save state, firmware dump buffers, and scan capability advertised via `adapter->ext_scan`.

Dependencies and integration points: This backend depends on Linux PCI, DMA, IRQ, firmware, PM sleep, and cfg80211-facing mwifiex core infrastructure. It uses mwifiex common helpers from `decl.h`, `main.h`, `fw.h`, `wmm.h`, `11n.h`, and `util.h`; common core calls into `pcie_ops` for bus work while this file calls back into core functions such as `mwifiex_add_card()`, `mwifiex_remove_card()`, `mwifiex_send_cmd()`, `mwifiex_write_data_complete()`, `mwifiex_handle_rx_packet()`, `mwifiex_process_sleep_confirm_resp()`, `mwifiex_shutdown_sw()`, and `mwifiex_reinit_sw()`. PCI reset integrates with `pcie_quirks.c` through `QUIRK_FW_RST_D3COLD` and `mwifiex_pcie_reset_d3cold_quirk()`.

Risks and edge cases: The highest-risk areas are ring pointer wrap semantics differing by chip, DMA mapping lifetime for skb buffers handed to firmware, command-response buffer ownership transfer to `curr_cmd`, and event buffer recycling delayed until event completion. Several paths return after allocation or mapping failures with partially consumed ring entries, so cleanup symmetry matters. The wake path relies on firmware interrupts appearing after writing `fw_status`, with a long retry path for 88W8897 firmware. Firmware parsing has overflow guards, but malformed combo images and command-size values are fatal. Reset cleanup avoids `cancel_work_sync()` during reset failure because it can deadlock. The MSIX error unwind appears delicate because it frees previous vectors while indexing context storage, and firmware dump reallocation must avoid overrunning preallocated memory.

Test signals: Build with PCI, PM sleep, MSI, and non-MSI paths. Exercise probe/remove for each PCI ID, firmware name selection by revision/magic/version, firmware download retry and FLR combo-image extraction, suspend/resume host-sleep transitions, wake from sleep-cookie and non-cookie devices, shared IRQ/MSI/MSI-X interrupt processing, TX ring full and flush behavior, RX invalid-length rejection, command completion with and without `curr_cmd`, event recycling, coredump work, firmware dump for 8897/8997 memory maps, PCI FLR reset, D3cold Surface quirk reset, and cleanup after every ring/buffer allocation failure.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/pcie.h

Purpose: Defines the PCIe bus contract used by `pcie.c`: firmware filenames, PCI vendor/device IDs, chip revisions, register offsets, interrupt bits, descriptor flags, buffer descriptor formats, chip capability records, and the long-lived `struct pcie_service_card` state object.

Important APIs and types: `struct mwifiex_pcie_card_reg` describes chip-specific scratch registers, host/CPU interrupt registers, ring masks, rollover bits, descriptor flag encodings, sleep-cookie support, firmware dump registers, and MSI-X support. `struct mwifiex_pcie_device` binds a register profile to firmware block size, TX buffer size, firmware-dump memory mapping, and extended scan support. Descriptor layouts are `mwifiex_evt_buf_desc`, `mwifiex_pcie_buf_desc`, and PFU-specific `mwifiex_pfu_buf_desc`. `struct pcie_service_card` stores PCI device/adapter links, ring pointers, coherent ring memory, skb ownership arrays, command and event buffers, sleep cookie DMA memory, BAR mappings, interrupt mode state, work item, reset flag, and quirk bits. Inline helpers `mwifiex_pcie_txbd_empty()` and `mwifiex_pcie_txbd_not_full()` encode device-specific TX ring fullness rules.

Control flow and state behavior: The header does not run control flow directly, but its fields define the invariants used by `pcie.c`. Ring pointer fields include both index bits and rollover bits; for 8766 the empty/full interpretation differs from 8897/8997, so the inline helpers switch on `card->dev->device`. Register profiles decide whether legacy or PFU descriptors are initialized, how TX/RX/event wrap is detected, whether a sleep cookie is allocated and polled, and whether firmware dump is available. The card object persists from probe through remove and is the shared state bridge between PCI callbacks, mwifiex core callbacks, IRQ context, and deferred work.

Dependencies and integration points: Includes Linux completion, PCI, and interrupt headers plus mwifiex `decl.h` and `main.h`. Constants such as `HOST_INTR_*`, `CPU_INTR_*`, `MWIFIEX_PCIE_FLR_HAPPENS`, and firmware names are consumed by `pcie.c`; `QUIRK_FW_RST_D3COLD` in `pcie_quirks.h` depends on the `pcie_service_card` declaration here. The firmware declarations in this header must stay aligned with module firmware tags and chip selection code.

Risks and test signals: The ring helpers are compact but critical; a wrong mask, rollover bit, or device-specific condition can deadlock TX or corrupt descriptor reuse. Descriptor structs are `__packed` firmware DMA ABI and must not change without firmware compatibility review. Tests should cover wraparound at `MWIFIEX_MAX_TXRX_BD`, both legacy and PFU descriptors, 8766 versus 8897/8997 full/empty behavior, firmware dump-capable and non-dump devices, sleep-cookie and non-cookie devices, and builds with/without PCI MSI-X definitions.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/pcie_quirks.c

Purpose: Provides platform-specific PCIe recovery quirks for mwifiex devices. It currently detects selected Microsoft Surface systems by DMI and enables a firmware reset workaround that power-cycles the Wi-Fi function and its upstream bridge through D3cold before returning them to D0.

Important APIs and functions: `mwifiex_initialize_quirks()` scans `mwifiex_quirk_table` with `dmi_first_match()` and stores quirk bits in `card->quirks`. `mwifiex_pcie_reset_d3cold_quirk()` is called from PCI reset prepare when `QUIRK_FW_RST_D3COLD` is set. Internal helpers `mwifiex_pcie_set_power_d3cold()` and `mwifiex_pcie_set_power_d0()` save/restore PCI state, disable/re-enable the function, and transition PCI power state. The DMI table covers Surface Pro 4, Surface Pro 5 including LTE SKU, Surface Pro 6, Surface Book 1/2, and Surface Laptop 1/2.

Control flow and state behavior: During probe, the quirk initializer sets `card->quirks` from DMI `driver_data` and logs the selected behavior. During reset prepare, `pcie.c` checks that bit before normal reinitialization. The reset quirk first puts the Wi-Fi function into D3cold, then also power-cycles the upstream bridge because some Surface systems report or handle bridge power state incorrectly. It then brings the bridge back to D0 before enabling/restoring the Wi-Fi function.

Dependencies and integration points: Depends on Linux DMI and PCI power-management APIs plus `pcie_quirks.h` and `pcie.h` for `struct pcie_service_card`. Its only caller is the PCIe backend reset path; it complements `mwifiex_shutdown_sw()` and `mwifiex_reinit_sw()` rather than replacing them. The bridge handling uses `pci_upstream_bridge()`, so behavior depends on valid PCI topology.

Risks and test signals: The quirk is intentionally platform-scoped because D3cold bridge cycling is intrusive. Adding systems requires exact DMI matches to avoid resetting unrelated hardware. `pci_upstream_bridge()` is assumed to return a usable bridge; defensive testing should include topology edge cases. Tests should verify DMI match/no-match logging, reset recovery on listed Surface devices, failure propagation from `pci_enable_device()`, preserved PCI config state after D0 restore, and non-Surface devices continuing through standard FLR reset.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/pcie_quirks.h

Purpose: Declares the PCIe quirk interface shared between `pcie.c` and `pcie_quirks.c`.

Important APIs and types: Defines `QUIRK_FW_RST_D3COLD` as bit 0 and declares `mwifiex_initialize_quirks(struct pcie_service_card *card)` plus `mwifiex_pcie_reset_d3cold_quirk(struct pci_dev *pdev)`. It includes `pcie.h`, so consumers receive both the PCI device type and `struct pcie_service_card`.

Control flow and state behavior: The header itself is declarative. The quirk bit is stored in `pcie_service_card.quirks` and later tested by reset code. A single bitmask leaves space for future independent platform quirks without changing the card structure.

Dependencies and integration points: Tightly coupled to the mwifiex PCIe backend; not a general quirk registry. It depends on Linux `BIT()` availability through included headers and on PCI declarations imported by `pcie.h`.

Risks and test signals: Since `QUIRK_FW_RST_D3COLD` is a public bit between two C files, new quirk bits must avoid collisions and callers must test bits rather than compare exact masks. Compile tests should include this header from both implementation files, and reset tests should verify behavior when no quirk bits are set.

# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/scan.c

Purpose: Implements mwifiex scan command construction, scan response parsing, BSS descriptor update, security compatibility checks, cfg80211 scan completion, hidden-SSID follow-up scans, background scheduled scan configuration/query, and current-BSS beacon persistence.

Important APIs and functions: Public entry points include `mwifiex_scan_networks()`, `mwifiex_request_scan()`, `mwifiex_cmd_802_11_scan()`, `mwifiex_cmd_802_11_scan_ext()`, `mwifiex_ret_802_11_scan()`, `mwifiex_ret_802_11_scan_ext()`, `mwifiex_handle_event_ext_scan_report()`, `mwifiex_cmd_802_11_bg_scan_config()`, `mwifiex_cmd_802_11_bg_scan_query()`, `mwifiex_stop_bg_scan()`, `mwifiex_queue_scan_cmd()`, `mwifiex_cancel_scan()`, `mwifiex_update_bss_desc_with_ie()`, `mwifiex_check_network_compatibility()`, `mwifiex_cmd_append_vsie_tlv()`, `mwifiex_save_curr_bcn()`, and `mwifiex_free_curr_bcn()`. Internal helpers build channel/rate/SSID/random-MAC TLVs, split large scans into firmware-sized channel groups, parse legacy and extended scan buffers, track hidden SSID channels, and update channel survey statistics.

Control flow: `mwifiex_request_scan()` serializes with `priv->async_mutex` and delegates either a specific SSID scan or a full scan. `mwifiex_scan_networks()` rejects concurrent/blocked/bad-state scans, marks `adapter->scan_processing`, allocates a max-sized scan config union and channel list, calls `mwifiex_config_scan()`, then `mwifiex_scan_channel_list()` queues one or more firmware scan commands. That splitter limits channels per command, avoids CSA-closed channels, enforces `MWIFIEX_MAX_TOTAL_SCAN_TIME`, appends a band-appropriate rates TLV, and chooses legacy or extended scan command based on `adapter->ext_scan`. Scan responses parse firmware BSS records into cfg80211 BSS entries through `mwifiex_parse_single_response_buf()`. Completion logic in `mwifiex_check_next_scan_command()` drains queued scan commands, handles abort/block cases, triggers active scans for hidden SSIDs found on passive channels, completes internal waits, and calls `cfg80211_scan_done()`.

State and persistence: Adapter-level state includes `scan_processing`, `scan_pending_q`, command queues, `scan_wait_q_woken`, `survey_idx`, `chan_stats`, `active_scan_triggered`, `nd_info`, and extended scan support. Per-interface state includes `scan_request`, `scan_aborting`, `scan_block`, `hidden_chan`, `sched_scanning`, saved vendor-specific IEs, current BSS parameters, and `curr_bcn_buf`. `mwifiex_save_curr_bcn()` copies the current BSS beacon buffer into persistent storage and rewrites all internal IE pointers to offsets in the saved buffer so the descriptor remains valid after temporary parse buffers are freed.

Dependencies and integration points: The file depends on cfg80211 for scan requests/results, channel definitions, BSS lifetime, scheduled scan notification data, and scan completion. It depends on mwifiex command infrastructure for queuing and waiting on firmware commands, 11h helpers for CSA-closed channels, band/rate helpers, HT capability filling, and common BSS descriptor helpers. The PCIe backend advertises `adapter->ext_scan`, which changes command format and completion flow.

Parsing and compatibility behavior: `mwifiex_update_bss_desc_with_ie()` walks beacon/probe IEs with bounds checks and stores pointers/offsets for SSID, rates, FH/DS/CF/IBSS, ERP, 11h, WPA/WMM vendor IEs, RSN/RSNX/WAPI, HT/VHT, 20/40 coexistence, extended capabilities, and operating mode. Security matching checks WAPI, open, static WEP, WPA, WPA2, ad-hoc AES, and dynamic WEP. WPA/WPA2 HT compatibility disables 11n when only TKIP is present and rejects networks without acceptable pairwise cipher. Scan parsing validates returned AP counts, BSS descriptor sizes, TLV lengths, per-entry beacon lengths, and channel presence before calling `cfg80211_inform_bss()`.

Risks and edge cases: Firmware response parsing is the most sensitive area because malformed lengths can otherwise desynchronize pointer arithmetic. Legacy scan TLV size is computed from firmware response size and BSS descriptor size, so underflow or bad firmware sizes must be guarded by the existing length checks. Extended scan events contain nested TLVs and update both global `bytes_left` and per-entry `bytes_left_for_tlv`; changes here can easily break multi-result parsing. Scan completion is stateful and can race with aborts, association scan blocking, hidden-SSID follow-up scans, and queued command promotion. Background scan command building writes variable TLVs into firmware command space and depends on caller-provided maximum array sizes. Current beacon pointer persistence relies on saved offsets being correct for every pointer field.

Test signals: Exercise normal, specific SSID, BSSID-filtered, random-MAC, current-channel-only, passive, DFS/radar, CSA-closed-channel, and hidden-SSID follow-up scans. Test both legacy and extended scan command/response paths, multiple queued scan command chunks, scan abort while commands remain pending, scan blocked during association, internal synchronous scans, cfg80211 scan completion status, scheduled/background scan start/stop/query, WoWLAN network-detect match allocation, malformed TLV and beacon-length responses, missing DS channel IE, too many APs, WPA/WPA2 TKIP-only compatibility, WEP disabling HT, vendor IE passthrough length limits, channel statistics overflow protection, and current-BSS beacon save/free pointer adjustment.
