## sources/distributed-fs/ceph-client/fs/smb/client/cifssmb.c

Purpose: implements the SMB1/CIFS wire-PDU construction and response parsing layer for the Linux SMB client. It covers negotiate, tree connect/disconnect, echo/logoff, path and handle based create/open/read/write/lock/close, rename/link/symlink, reparse point FSCTLs, SMB1 file compression FSCTL, POSIX and CIFS ACL helpers, path/file/fs queries, directory enumeration, DFS referrals, EOF/allocation updates, attributes, Unix extension metadata, and EA get/set. The file is the SMB1 counterpart to the SMB2 PDU layer and is wired through `smb1proto.h` and the SMB1 ops tables.

Important APIs, types, and functions: public entry points include `CIFSSMBNegotiate()`, `CIFSTCon()`, `CIFSSMBTDis()`, `CIFSSMBEcho()`, `CIFSSMBLogoff()`, `CIFSPOSIXCreate()`, `SMBLegacyOpen()`, `CIFS_open()`, `cifs_async_readv()`, `CIFSSMBRead()`, `CIFSSMBWrite()`, `cifs_async_writev()`, `CIFSSMBWrite2()`, `cifs_lockv()`, `CIFSSMBLock()`, `CIFSSMBPosixLock()`, `CIFSSMBClose()`, `CIFSSMBFlush()`, `CIFSSMBRename*()`, `CIFSUnixCreate*Link()`, `CIFSCreateHardLink()`, `CIFSSMBUnixQuerySymLink()`, `cifs_query_reparse_point()`, `cifs_create_reparse_inode()`, `CIFSSMB_set_compression()`, ACL helpers, `CIFSSMBQ*Info()` query families, `CIFSFindFirst()`, `CIFSFindNext()`, `CIFSFindClose()`, `CIFSGetDFSRefer()`, `CIFSSMBSet*()` metadata mutators, `CIFSSMBQAllEAs()`, and `CIFSSMBSetEA()`. Core local helpers are `cifs_reconnect_tcon()`, `small_smb_init()`, `small_smb_init_no_tc()`, `smb_init()`, `smb_init_no_reconnect()`, `validate_t2()`, `smb_init_nttransact()`, `validate_ntransact()`, and conversion helpers for open disposition, access mode, ACLs, and Unix set-info payloads.

Control flow: most operations first call `small_smb_init()` or `smb_init()`, which perform reconnect handling, allocate a small or large CIFS buffer, assemble the SMB header, and increment per-tree sent counters. The caller then fills SMB word parameters, byte count, path strings in Unicode or local codepage form, transaction offsets, data areas, and command-specific flags before sending with `SendReceive()`, `SendReceive2()`, `SendReceiveNoRsp()`, or `cifs_call_async()`. Many path operations use a retry label on `-EAGAIN`, while handle based operations generally return `-EAGAIN` to the caller because the file/search handle may be stale after reconnect. Response parsing validates Trans2 or NT_TRANSACT offsets and byte counts, copies payloads into VFS-facing structs, and releases the CIFS buffer unless ownership is intentionally transferred to a search or reparse caller.

State and persistence behavior: the file updates in-memory session/server/tree state during negotiate and tree connect, including dialect, security mode, max request/IO sizes, capabilities, signing, crypt keys or extended security blobs, `tcon->tid`, share flags, native filesystem strings, Unix/fs/device/attribute info caches, and stats counters. Reconnect flow serializes session setup under `session_mutex`, marks opens invalid before reconnecting a tree, can swap to an alternate password on authentication-related reconnect failures, and returns `-EAGAIN` for handle-sensitive commands. Server-persistent effects include create/delete/rename/link/symlink, writes, locks, ACL/EA/attribute/time/EOF/Unix metadata changes, reparse point creation, and `FSCTL_SET_COMPRESSION`; the code itself writes no local persistent storage.

Dependencies and integration points: depends on CIFS core headers (`cifsglob.h`, `cifsproto.h`, `smb1proto.h`, `smb1pdu.h` transitively), SMB FSCTL constants, VFS inode/dentry/statfs/ACL/xattr types, Linux netfs subrequest APIs, fscache/smbdirect plumbing, DFS referral parsing, signing helpers, NLS conversion, tracepoints, and CIFS buffer/transport helpers. It is consumed through SMB1 operation tables in `smb1ops.c`, by higher-level VFS paths in inode/file/xattr/acl code, and by transport/session code for negotiate, reconnect, and async MID completion.

Risks: this is security-sensitive wire parsing code. Offset, ByteCount, data-count, and Unicode padding mistakes can lead to out-of-bounds reads/writes or malformed SMBs, so `validate_t2()` and `validate_ntransact()` checks are critical. Retry behavior is subtle because path commands can usually reissue after reconnect but handle commands must not silently reuse stale FIDs. Async read/write callbacks must release MIDs and credits exactly once, update netfs subrequest state, and preserve signature verification semantics. Directory search state transfers ownership of response buffers across calls and can leak, double-free, or expose stale entries if `psrch_inf` fields are mishandled. Protocol fallback paths, such as set-path-info falling back to open-by-handle, must not change access rights or object lifetime unexpectedly. SMB1 file compression here is `FSCTL_SET_COMPRESSION` on an opened file and is unrelated to SMB3 message compression in `compress.c`.

Test signals: negotiate against SMB1 servers with and without extended security/signing/Unicode/Unix extensions; reconnect tests that cover path retry versus stale-handle `-EAGAIN`; sync and async read/write with large-file offsets, short writes, signing, malformed responses, and credit accounting; Trans2/NT_TRANSACT fuzzing of offsets/counts/BCC; create/open disposition and access-mode matrix tests; lock, oplock-break, and POSIX lock flows; directory enumeration resume-name corruption and close behavior; DFS referral parsing over IPC tcon; reparse point get/create including cleanup on failure; `FSCTL_SET_COMPRESSION`; POSIX and CIFS ACL get/set; xattr list/get/set, including named EA misses and buffer-size `-ERANGE`; statfs/fs-attribute/device/Unix info queries; and Unix metadata set paths for uid/gid/mode/device/time.

## sources/distributed-fs/ceph-client/fs/smb/client/compress.c

Purpose: implements SMB 3.1.1 client-side message compression decisions and transmit wrapping for READ/WRITE traffic when compression was negotiated and enabled for the share. It contains a write-data compressibility heuristic, a request-level `should_compress()` gate, and `smb_compress()` which builds an SMB2 compression transform around an LZ77-compressed write payload or falls back to sending the original request.

Important APIs, types, and functions: exported functions are `should_compress(const struct cifs_tcon *, const struct smb_rqst *)` and `smb_compress(struct TCP_Server_Info *, struct smb_rqst *, compress_send_fn)`. Local heuristic helpers include `collect_sample()`, `is_compressible()`, `has_repeated_data()`, `is_mostly_ascii()`, `calc_byte_distribution()`, `has_low_entropy()`, and `cmp_bkt()`. `struct bucket` stores sampled byte frequency counts. `smb_compress()` depends on `lz77_compressed_alloc_size()` and `lz77_compress()` from `compress/lz77.c`.

Control flow: `should_compress()` rejects missing tcon/session/server, disabled negotiated compression, shares without `SMB2_SHAREFLAG_COMPRESS_DATA`, and commands other than SMB2 WRITE/READ. READ requests are allowed after the negotiation/share gates because the server response may be compressed. WRITE requests must be at least `SMB_COMPRESS_MIN_LEN` and pass `is_compressible()`. The heuristic samples 2 KiB chunks with 2 KiB gaps at page-size cadence up to 4 MiB, first accepting repeated half-sample data and mostly ASCII data, then sorting byte buckets by frequency and classifying byte distribution, using approximate Shannon entropy only for the ambiguous middle case.

State and persistence behavior: no persistent state is stored. `is_compressible()` copies from a temporary `iov_iter` clone and does not advance the caller's iterator. `smb_compress()` copies the original write data into a temporary source buffer, allocates a worst-case destination buffer, compresses with LZ77, and sends a stack-local `struct smb_rqst` containing compression header, original SMB2 write request iov, and compressed payload. On LZ77 failure with `-EMSGSIZE` or non-beneficial output length, it sends the original uncompressed request.

Dependencies and integration points: integrates with SMB2 write send paths in `smb2pdu.c` and low-level transport in `transport.c`, using `compress_send_fn` so the transport can pass `__smb_send_rqst()`. It depends on SMB2 compression header definitions in common `smb2pdu.h`, CIFS server/tcon state in `cifsglob.h`, I/O iterators, kernel allocation helpers, sorting, and the LZ77 implementation. Negotiation state is populated by SMB2 negotiate context parsing, and share compression state comes from tree connect flags.

Risks: the heuristic intentionally trades CPU for avoiding wasted compression, but bad thresholds can either waste CPU on incompressible writes or miss useful compression. `smb_compress()` currently validates that the first iov is exactly an SMB2 write request, so call sites must not pass transformed/chained layouts. Large writes allocate full source and worst-case destination buffers with `kvzalloc()`, which can be expensive under memory pressure. The compression header `Offset` assumes the uncompressed SMB2 write request iov precedes the compressed data exactly as built. Compression plus encryption is disabled by the caller today; changing that ordering would require careful transform stacking validation.

Test signals: mount with `compress` against SMB 3.1.1 servers that negotiate LZ77 and set share compression; write tests below and above `PAGE_SIZE`; incompressible random/encrypted-like data should fall back to plain send; repeated, sparse, and ASCII-heavy data should compress; short-copy and allocation-failure fault injection should return `smb_EIO` or `-ENOMEM`; verify the original iterator remains reusable; inspect transform header fields and offset on the wire; confirm READ requests pass the gate without local compression; and confirm encrypted requests are not routed through this path until supported.

## sources/distributed-fs/ceph-client/fs/smb/client/compress.h

Purpose: declares the SMB client message-compression API and constants for SMB 3.1.1 compression support. It centralizes the compile-time `CONFIG_CIFS_COMPRESSION` boundary so callers can invoke compression helpers without open-coding feature guards.

Important APIs, types, and functions: defines `SMB_COMPRESS_HDR_LEN`, `SMB_COMPRESS_PAYLOAD_HDR_LEN`, and `SMB_COMPRESS_MIN_LEN` (`PAGE_SIZE`). Under `CONFIG_CIFS_COMPRESSION`, it defines `compress_send_fn`, declares `smb_compress()` and `should_compress()`, and provides `smb_compress_alg_valid(__le16 alg, bool valid_none)`. Supported negotiated algorithms in this client-side check are `SMB3_COMPRESS_LZ77` and `SMB3_COMPRESS_PATTERN`; `SMB3_COMPRESS_NONE` is conditionally accepted only when the caller explicitly allows it. When compression is disabled at build time, inline stubs return `-EOPNOTSUPP` or `false`.

Control flow: callers use `should_compress()` to decide whether a request or response path is eligible, then use `smb_compress()` to wrap a write request before send. Negotiation parsing can use `smb_compress_alg_valid()` to reject unsupported or protocol-invalid algorithms while optionally accepting `NONE` in contexts where a sentinel value is legal.

State and persistence behavior: the header stores no state. Its constants affect runtime behavior by defining the minimum write length considered for compression and by exposing transform header sizing assumptions. The disabled stubs make compression a no-op capability at runtime while preserving build compatibility.

Dependencies and integration points: includes Linux `uio`/kernel types, common SMB2 PDU definitions for algorithm constants, and CIFS global types for `TCP_Server_Info`, `cifs_tcon`, and `smb_rqst`. It is included by transport and SMB2 PDU code as the boundary between generic send logic and the compression implementation.

Risks: `smb_compress_alg_valid()` supports LZ77 and PATTERN but `compress.c` currently emits LZ77 for outbound write compression; callers must not assume every valid negotiated algorithm has a full local compressor/decompressor path here. The non-compression stub for `smb_compress_alg_valid()` returns an `int` error value despite the enabled helper being used as boolean-like truth, so disabled-build callers should treat it as unavailable rather than a normal validator. Header-length constants omit `OriginalPayloadSize` by design and must stay synchronized with the protocol structs.

Test signals: build coverage with `CONFIG_CIFS_COMPRESSION=y` and disabled; negotiation tests for LZ77, PATTERN, NONE-valid, NONE-invalid, and unsupported algorithms; call-site tests that disabled builds fall back cleanly; and transform header sizing assertions against the SMB2 compression structures.

## sources/distributed-fs/ceph-client/fs/smb/client/compress/lz77.c

Purpose: implements the "plain" LZ77 compression algorithm used by SMB compression according to MS-XCA. It is a performance-oriented in-kernel encoder that produces an SMB-compatible compressed byte stream using 32-bit literal/match flags, match-distance/length encodings, and a hash table for recent positions.

Important APIs, types, and functions: exported function is `lz77_compress(const void *src, u32 slen, void *dst, u32 *dlen)`. Local helpers include unaligned little-endian read/write helpers (`lz77_read8/32/64()`, `lz77_write8/16/32()`), `lz77_match_len()`, `lz77_encode_match()`, `lz77_encode_literals()`, and `lz77_hash()`. Key constants are `LZ77_MATCH_MAX_DIST` (8 KiB), `LZ77_HASH_LOG`/`LZ77_HASH_SIZE` (32K entries), 4-byte read step/minimum match, 8-byte match-extension step, `LZ77_SKIP_TRIGGER`, and 32 tokens per flag word.

Control flow: `lz77_compress()` first validates that `*dlen` is at least `lz77_compressed_alloc_size(slen)`, sets source/end/read-limit pointers, reserves the first flag word, allocates a zeroed hash table, seeds the first hashes, and enters a hot main loop. The loop uses adaptive skipping to search for a recent hash match within the 8 KiB window, flushes pending literals, measures the full match length, emits a match code and any extra length nibbles/bytes, advances the anchor, and writes a flag word after every 32 literals/matches. At exit, it emits remaining literals, finalizes the last flag word with terminal one bits, stores the compressed length in `*dlen`, frees the hash table, returns 0 only if the output is smaller than the input, and otherwise returns `-EMSGSIZE`.

State and persistence behavior: all state is per-call and temporary: source/destination cursors, current flag accumulator/count/address, pending nibble pointer for packed match lengths, and a `kvcalloc()` hash table of source offsets. No global or persistent state is modified. The destination buffer is intentionally written without per-write bounds checks after the initial allocation-size contract is verified.

Dependencies and integration points: included by `compress.c` through `compress/lz77.h`; depends on kernel allocation, size constants, count-zero helpers, and unaligned access helpers. The caller supplies source and destination buffers and interprets `-EMSGSIZE` as "send the original uncompressed request." The emitted format must match SMB/MS-XCA consumers on the server side.

Risks: the implementation is intentionally order- and branch-sensitive; small changes to the hot loop can cause major performance regressions or alter compression ratio. Safety depends on the worst-case destination size calculation in `lz77_compressed_alloc_size()` and the caller honoring it. The function assumes the input is large enough for initial 32-bit and match-limit reads; current call paths only compress writes at least `PAGE_SIZE`, but direct unit tests must avoid tiny inputs or add guards. Match distance and length encoding must remain protocol-compatible, including the alternating extra-length nibble packing. Returning `-EMSGSIZE` for larger output is part of normal control flow and must not be logged as a hard failure by callers.

Test signals: known-answer LZ77 streams for literals, short matches, long matches requiring nibble/byte/16-bit/32-bit length encodings, alternating match/literal flag boundaries at 32 tokens, match distances near 1 and 8 KiB, incompressible data returning `-EMSGSIZE`, small and exact allocation-size validation, allocation-failure injection, cross-server decompression interoperability, and performance regression tests on repeated, sparse, text, and random data.

## sources/distributed-fs/ceph-client/fs/smb/client/compress/lz77.h

Purpose: declares the SMB compression LZ77 encoder and exposes the destination-buffer sizing contract required by the encoder's bounds-check-free hot loop.

Important APIs, types, and functions: `lz77_compressed_alloc_size(u32 size)` returns `size + (size >> 3) + 8`, accounting for worst-case all-literal data plus 4-byte flag metadata at the start, every 32 tokens, and possible stream end. `lz77_compress(const void *src, u32 slen, void *dst, u32 *dlen)` compresses into a caller-provided destination buffer and updates `*dlen` with the actual compressed length.

Control flow: callers compute the allocation size with `lz77_compressed_alloc_size()`, allocate at least that many bytes, set `*dlen` to the allocation size, and call `lz77_compress()`. The C implementation checks this contract once at entry, writes the compressed stream, and reports success only when compression shrinks the payload.

State and persistence behavior: no state is defined by the header. The inline sizing helper directly affects allocation and safety for every compression call because `lz77_compress()` relies on the exact overprovisioning guarantee.

Dependencies and integration points: used by `fs/smb/client/compress.c` for outbound SMB3 write compression. It includes only kernel types and intentionally keeps the algorithm details private to `lz77.c`.

Risks: changing the allocation formula without proving the encoder's maximum output can reintroduce buffer overruns, while excessive overprovisioning increases memory pressure for large writes. The helper uses `u32`; callers must keep source lengths within SMB/client limits that fit this type. Consumers must treat `-EMSGSIZE` from `lz77_compress()` as a non-fatal "not worth compressing" result.

Test signals: allocation-size unit checks for zero, small, page-sized, and large SMB write lengths; compression calls with exactly the helper's returned size; incompressible all-literal data near 32-token boundaries; and build coverage that the header remains independent of SMB transport internals.
