# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf.h

Purpose: central private header for the QLogic/Cavium `qedf` FCoE offload driver. It binds libfc/libfcoe, SCSI mid-layer, QED LL2/FCoE firmware APIs, debug helpers, firmware HSI definitions, and driver-wide state structures used by discovery, FIP, ELS, SCSI I/O, task management, recovery, sysfs, and debugfs.

Important APIs/types/functions: `struct qedf_ctx` is the adapter context with the libfcoe controller, libfc local port, PCI/QED handles, link/DCBX/VLAN state, queues, BDQ buffers, workqueues, timers, command manager, firmware task memory, debug state, GRC dump storage, tracing ring, and statistics counters. `struct qedf_rport` represents an offloaded remote FC port and owns session flags, firmware connection IDs, SQ producer indices, free SQE and active I/O counters, and libfc rport pointers. `struct qedf_ioreq` is the per-task/TID object for SCSI commands, ELS, ABTS, cleanup, sequence cleanup, and task management; it stores XID, SCSI command backpointer, flags, atomic state, kref, firmware task pointers, timers/completions, middle-path buffers, FCP response fields, SGE path classification, REC/SRR offsets, and callback data. `struct qedf_mp_req`, `struct qedf_els_cb_arg`, `struct qedf_cmd_mgr`, `struct io_bdt`, `struct qedf_fastpath`, `struct global_queue`, `struct qedf_io_log`, and `struct fip_vlan` define the main memory/control surfaces. Inline helpers include `qedf_priv()`, `qedf_get_task_mem()`, and `qedf_stop_all_io()`. The header also declares the cross-file driver entry points such as `qedf_queuecommand()`, FIP send/receive helpers, ELS REC/SRR/RRQ/ADISC helpers, completion handlers, ABTS/cleanup/TMF flows, sysfs/debug hooks, and hardware error/recovery helpers.

Control flow: this file does not execute a standalone flow; it defines the shared contracts. SCSI submission allocates a `qedf_ioreq` from `qedf_cmd_mgr`, binds it to an offloaded `qedf_rport`, maps SGEs through an `io_bdt`, initializes firmware task context from `qedf->tasks`, rings the rport doorbell, and later returns through one of the declared completion/error/recovery paths. ELS and task-management paths share the same TID/request object but use `qedf_mp_req` DMA buffers and callbacks rather than a SCSI command. Adapter lifetime flows through `qedf_ctx` fields: probe sets up queues, timers, BDQ, command manager, debug/sysfs state, and QED handles; link/discovery set flags and libfcoe state; unload/recovery set `QEDF_UNLOADING`, drain/flush active I/Os, and release resources.

State and persistence: all state is in kernel memory and hardware/firmware queues, with no disk persistence. Key mutable state includes `qedf_ctx::flags`, `qedf_rport::flags`, `qedf_ioreq::flags`, `qedf_ioreq::state`, krefs, completions, queue producer/consumer indices, BDQ producer index, retry-delay timestamps, GRC dump buffer, and trace/stat counters. `task_retry_identifier` is incremented when a TID is released to help firmware distinguish reused tasks. `QEDF_GRCDUMP_CAPTURE`, `QEDF_DBG_STOP_IO`, reset/uploading flags, and command dirty/error bits are important recovery latches.

Dependencies and integration: depends on libfc/libfcoe transport structures and exchange handling, SCSI mid-layer private command storage, QED common/FCoE/LL2 operations, firmware task initialization helpers from `drv_fcoe_fw_funcs.h`, kernel DMA APIs, workqueues, timers, completions, debugfs/sysfs, PCI, and atomic/bit operations. `qedf_hsi.h` must be included before QED headers because it defines firmware CQE/CMDQ layouts used by the rest of the driver.

Risks and test signals: this header concentrates concurrency-sensitive contracts; mistakes in flags, kref ownership, SQE/TID accounting, or structure layouts can cause double completion, leaked tasks, stale SCSI command pointers, or firmware memory corruption. Queue limits (`FCOE_PARAMS_NUM_TASKS`, `NUM_RW_TASKS_PER_CONNECTION`, `GBL_RSVD_TASKS`, `QEDF_MAX_BDS_PER_CMD`) should be exercised under high I/O, abort, target reset, LUN reset, unload, and link flap. Build tests should catch HSI/API drift; runtime signals include active I/O/free-list balance, no dirty TIDs on reuse, correct debugfs/sysfs state, and clean recovery from ABTS/cleanup/TMF timeouts.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_attr.c

Purpose: implements QEDF host sysfs attributes and the binary GRC dump control/readback interface. It exposes the derived FCoE MAC address, selected FCF keep-alive period, and a `grcdump` binary file used to trigger, clear, and read firmware diagnostic dumps.

Important APIs/types/functions: `qedf_is_vport()` detects NPIV virtual ports. `qedf_get_base_qedf()` maps a vport context back to the physical/base QEDF context so shared FCF/GRC state is read from the owning port. `fcoe_mac_show()` derives an FCoE MAC from the current FC port ID via `fc_fcoe_set_mac()`. `fka_period_show()` returns the selected FCF `fka_period` or `-1`. `qedf_host_groups[]` registers the read-only host attributes. `qedf_capture_grc_dump()` calls `qedf_get_grc_dump()` through QED common ops, sets `QEDF_GRCDUMP_CAPTURE`, and emits a uevent. `qedf_sysfs_read_grcdump()` copies captured dump bytes to userspace with `memory_read_from_buffer()`. `qedf_sysfs_write_grcdump()` parses `0` to clear the dump and `1` to capture one. `qedf_create_sysfs_ctx_attr()` and `qedf_remove_sysfs_ctx_attr()` attach/detach the binary attributes from the SCSI host.

Control flow: read-only attributes resolve `Scsi_Host -> fc_lport -> qedf_ctx`, then format current in-memory values into the page buffer. GRC capture first normalizes vports to the base context, refuses duplicate capture if `QEDF_GRCDUMP_CAPTURE` is already set, asks the QED debug operation to fill the preallocated dump buffer, records the captured state, and notifies userspace. The binary write path only accepts writes at offset zero, truncates parsing to the first byte plus terminator, and dispatches to clear or capture. The binary read path returns data only after the capture bit is set.

State and persistence: the attributes persist only while the SCSI host exists. GRC dump contents live in `qedf_ctx::grcdump` and `grcdump_size`, allocated elsewhere; clearing zeroes the buffer and clears the capture bit. The selected FCF and FKA period are libfcoe controller runtime state. Uevents are transient notifications to userspace.

Dependencies and integration: integrates with SCSI host device sysfs, libfc/libfcoe vport and FCF data, QED common debug dump operations declared in `qedf_dbg.h`, and QEDF context flags from `qedf.h`. The sysfs binary helper functions are generic wrappers implemented in `qedf_dbg.c`.

Risks and test signals: `qedf_sysfs_write_grcdump()` writes `buf[1] = 0`, so it assumes the kernel sysfs write buffer is at least two bytes; malformed one-byte writes are a boundary risk. GRC capture assumes `grcdump` has already been allocated and sized. Vport access must always use the base context for physical dump/FCF state. Useful tests include reading attributes before and after FCF selection, triggering GRC capture/clear/read through sysfs, repeated capture attempts, vport-triggered capture, and teardown while attributes exist.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_dbg.c

Purpose: provides non-debugfs diagnostic primitives for QEDF: log formatting helpers, GRC dump buffer allocation/free/get wrappers, GRC uevent emission, and generic sysfs binary attribute create/remove loops.

Important APIs/types/functions: `qedf_dbg_err()`, `qedf_dbg_warn()`, `qedf_dbg_notice()`, and `qedf_dbg_info()` implement the `QEDF_ERR/WARN/NOTICE/INFO` macros with function, line, PCI device name, and host number context. Warning, notice, and info logs are gated by the global `qedf_debug` bitmask; errors always print. `qedf_alloc_grc_dump_buf()` and `qedf_free_grc_dump_buf()` manage vmalloc-backed dump storage. `qedf_get_grc_dump()` validates the buffer and calls `common->dbg_all_data()`. `qedf_uevent_emit()` constructs the `GRCDUMP=<host_no>` environment entry for `KOBJ_CHANGE`. `qedf_create_sysfs_attr()` and `qedf_remove_sysfs_attr()` iterate `struct sysfs_bin_attrs` arrays.

Control flow: logging helpers build a `va_format`, check the optional debug mask, and print through the kernel log with either PCI/host context or a placeholder PCI BDF when no context is available. GRC helpers are thin allocation and QED-common wrappers. Sysfs creation iterates until a null `name`, attempts each binary file, logs failures, and returns the last error encountered.

State and persistence: mutable state is limited to the global `qedf_debug` read by log gates and caller-owned GRC dump pointers. The helpers do not persist data; buffers remain attached to `qedf_ctx` until freed by driver teardown. Uevents are transient.

Dependencies and integration: depends on kernel printk, vmalloc, kobject uevents, SCSI host generic device kobject, QED common debug ops, and the declarations in `qedf_dbg.h`. It is used by core driver, sysfs, and debugfs code without requiring `CONFIG_DEBUG_FS`.

Risks and test signals: log-mask changes affect runtime observability and can hide warning/notice/info diagnostics. `qedf_get_grc_dump()` returns `-EINVAL` if called before allocation but otherwise trusts QED to fill the supplied buffer size. Sysfs creation can partially succeed if a later file fails; teardown must tolerate that. Test signals include dynamic debug-mask writes, GRC dump allocation/capture failure paths, uevent content, and sysfs binary file create/remove on probe failure unwind.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_dbg.h

Purpose: declares QEDF logging categories, debug context, logging macros, GRC/sysfs diagnostic helper APIs, and debugfs operation contracts.

Important APIs/types/functions: log bits include discovery, LL2, connection, events, timers, middle path, SCSI task management, unsolicited frames, I/O, multiqueue, BSG, debugfs, lport, ELS, NPIV, session, TID tracking, notices, and warnings. `struct qedf_dbg_ctx` carries host number, PCI device, and optional debugfs dentry. `QEDF_ERR`, `QEDF_WARN`, `QEDF_NOTICE`, and `QEDF_INFO` inject `__func__` and `__LINE__` into the logging helpers. `struct sysfs_bin_attrs` describes binary sysfs files. `struct qedf_debugfs_ops`, `struct qedf_list_of_funcs`, and the `qedf_dbg_fileops*` macros define the debugfs file table and file-operation boilerplate. It declares lifecycle hooks `qedf_dbg_host_init()`, `qedf_dbg_host_exit()`, `qedf_dbg_init()`, and `qedf_dbg_exit()` under `CONFIG_DEBUG_FS`.

Control flow: this header provides macros and declarations only. Runtime users call the macros; `qedf_dbg.c` performs log filtering and printing, while `qedf_debugfs.c` consumes the debugfs operation arrays to create per-host files.

State and persistence: the global `qedf_debug` bitmask controls logging at runtime. `qedf_dbg_ctx::bdf_dentry` persists for the lifetime of a debugfs host directory when debugfs is enabled. No on-disk persistence exists.

Dependencies and integration: includes kernel types, PCI, fs/debug support, SCSI transport, and QED common interfaces. The header is included from `qedf.h`, so these diagnostic contracts are visible across the driver. Debugfs declarations are compiled conditionally, but stub prototypes are still provided by `qedf_debugfs.c` when disabled.

Risks and test signals: because log categories are bitmasks used across many files, collisions or incorrect defaults can make diagnostics noisy or silent. The `QEDF_TRACK_CMD_LIST` value overlaps tracking bits intentionally and should not be treated as an independent single bit. Function signatures must stay aligned with `qedf_dbg.c` and debugfs file tables. Build tests with and without `CONFIG_DEBUG_FS`, plus runtime checks of log mask writes and debugfs host creation/removal, are the key signals.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_debugfs.c

Purpose: implements QEDF debugfs support when `CONFIG_DEBUG_FS` is enabled. It creates a driver root, per-host directories, and files for fastpath interrupt counts, I/O trace dump, debug-mask control, stop-I/O-on-error control, driver/session stats, stat clearing, and firmware offload stats.

Important APIs/types/functions: `qedf_dbg_init()` and `qedf_dbg_exit()` create/remove the root debugfs directory. `qedf_dbg_host_init()` and `qedf_dbg_host_exit()` create/remove `host<N>` directories and files from `qedf_debugfs_ops[]` and `qedf_dbg_fops[]`. File handlers include `qedf_dbg_fp_int_cmd_read()`, `qedf_dbg_debug_cmd_read/write()`, `qedf_dbg_stop_io_on_error_cmd_read/write()`, `qedf_io_trace_show()`, `qedf_driver_stats_show()`, `qedf_dbg_clear_stats_cmd_write()`, and `qedf_offload_stats_show()`. The static state-name arrays render libfcoe FIP and libfc rport states.

Control flow: host initialization walks the ops/fops arrays in parallel and creates each file with private data pointing at `qedf_dbg_ctx`. Simple read handlers allocate or fill a buffer and use `simple_read_from_buffer()`. Seq-file handlers open with `single_open()` and render live adapter state. Writes parse user data to set `qedf_debug`, set/clear `qedf->stop_io_on_error`, trigger `QEDF_DBG_STOP_IO` with `now`, or clear local SGE counters. Offload stats allocate a `qed_fcoe_stats`, call `qed_ops->get_stats()`, print firmware counters, and free the buffer.

State and persistence: debugfs entries persist while the module/host is loaded. Runtime mutable state includes the global debug mask, `qedf->stop_io_on_error`, `QEDF_DBG_STOP_IO`, `qedf->slow_sge_ios`, `qedf->fast_sge_ios`, the circular `io_trace_buf`, and firmware stats sampled on demand. No debugfs setting is persisted across module reload.

Dependencies and integration: depends on debugfs, seq_file, user-copy helpers, QEDF context/debug structures, libfcoe/libfc state, firmware stats via `qed_ops`, and the I/O trace records populated by `qedf_io.c`. The file is compiled out when debugfs is disabled, leaving only empty prototypes.

Risks and test signals: debugfs exposes powerful control knobs: writing `now` stops all I/O on the host, and a broad debug mask can flood logs. `qedf_dbg_stop_io_on_error_cmd_write()` copies exactly six bytes regardless of `count`, so short writes deserve boundary testing. State-name arrays assume enum values remain within range. `qedf_driver_stats_show()` traverses rports under RCU and prints live counters; stale rdata or enum drift can misreport. Useful tests include debugfs on/off builds, create/remove under probe failure, writes to `debug` and `stop_io_on_error`, I/O trace wraparound, stats clearing, and firmware stat allocation failure.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_els.c

Purpose: implements QEDF middle-path ELS operations and sequence recovery flows, including generic ELS send, ELS completion normalization, RRQ after ABTS, ADISC forwarding between firmware and libfc, rport restart, REC/SRR recovery for tape devices, sequence cleanup, and I/O requeue for lost exchanges.

Important APIs/types/functions: `qedf_initiate_els()` allocates a `QEDF_ELS` request, initializes middle-path DMA resources, fills FC headers/payload, initializes firmware task context, arms optional timeout, and rings the rport doorbell. `qedf_process_els_compl()` handles firmware ELS completions and invokes the registered callback. Public send helpers are `qedf_send_rrq()`, `qedf_send_adisc()`, and `qedf_send_rec()`. Callback helpers include `qedf_rrq_compl()`, `qedf_l2_els_compl()`, `qedf_srr_compl()`, and `qedf_rec_compl()`. `qedf_restart_rport()` forces libfc logout/relogin after selected timeout cases. `qedf_process_seq_cleanup_compl()` bridges firmware sequence cleanup to SRR. `qedf_requeue_io_req()` moves a SCSI command to a new XID and aborts the old exchange without completing the command upward.

Control flow: all ELS sends validate rport, lport readiness, link state, and `QEDF_RPORT_SESSION_READY`; then they allocate request/callback state and post one SQE under `rport_lock`. Completion clears outstanding state, cancels timers, copies firmware response headers/payload to libfc `fc_frame` objects when needed, and releases krefs. ABTS success queues RRQ after `R_A_TOV`; RRQ completion releases the original aborted request. REC recovery sends REC for tape warning CQEs, interprets LS_RJT/LS_ACC, requeues lost commands, sends SRR directly when a response is lost, or issues sequence cleanup before SRR when data/XFER_RDY is lost. ADISC timeouts restart the rport so libfc can renegotiate through the LL2 path.

State and persistence: state is transient per `qedf_ioreq` and `qedf_els_cb_arg`: callbacks hold original request references, opcodes, libfc OXID, offsets, and R_CTL. The code mutates `cmd_type`, `QEDF_CMD_OUTSTANDING`, `QEDF_CMD_SRR_SENT`, `event`, `rx_buf_off`, `tx_buf_off`, `rx_id`, SCSI command ownership, and rport reset flags. No persistent storage exists.

Dependencies and integration: integrates with `qedf_io.c` command allocation, timers, cleanup, ABTS, SQ doorbells, task memory, and kref release; with libfc frame allocation/exchange receive/rport login/logout; with firmware middle-path task setup through `qedf_init_mp_task()`; and with SCSI command retry behavior when requeueing a command onto a new exchange.

Risks and test signals: ELS recovery is reference-count and race sensitive. Timeout, flush, ABTS completion, RRQ delayed work, REC/SRR completion, and target/LUN reset can all touch the same original request. `qedf_requeue_io_req()` initializes `rc` to false and does not set it true on success, so callers cannot distinguish successful requeue from failure by return value. Response length must stay within `QEDF_PAGE_SIZE` before copying. Useful tests include ADISC timeout, ABTS ACC/RJT, RRQ timeout, tape REC_TOV with read/write lost data and lost response cases, LS_RJT command-lost requeue, sequence-cleanup timeout, target reset while ELS is outstanding, and kref leak/double-completion instrumentation.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_fip.c

Purpose: handles FIP VLAN discovery transmit/receive, driver-side FIP frame transmit over QED LL2, incoming FIP filtering, Clear Virtual Link validation, handoff of ordinary FIP frames to libfcoe, and source-MAC lookup for libfcoe.

Important APIs/types/functions: `qedf_fcoe_send_vlan_req()` builds a VLAN request containing Ethernet, FIP, MAC, and WWNN descriptors and sends it with `QED_LL2_XMIT_FLAGS_FIP_DISCOVERY`. `qedf_fcoe_process_vlan_resp()` parses VLAN descriptors from a FIP VLAN notification, updates the driver's VLAN ID via `qedf_set_vlan_id()`, and completes `fipvlan_compl`. `qedf_fip_send()` is the libfcoe send hook; it tags outgoing FIP frames with `qedf->vlan_id` and sends through `qed_ops->ll2->start_xmit()`. `qedf_fip_recv()` validates destination MACs, handles VLAN notifications and CVL frames in-driver, and passes other frames to `fcoe_ctlr_recv()`. `qedf_get_src_mac()` returns `qedf->data_src_addr`.

Control flow: VLAN request allocation fills descriptors, checks physical link state, and hands the skb to LL2 or frees it on failure. Receive first parses headers and optionally dumps frames, drops packets not addressed to the adapter, all-ENode multicast, or the data-source MAC, then dispatches by FIP op/subcode. VLAN notes are consumed locally. CVL frames are parsed for FCF MAC, switch WWN, and optional VN_ID match against local WWPN, fabric ID, or data-source MAC; a full match triggers `qedf_ctx_soft_reset()`. All other FIP frames have the Ethernet header pulled and are delivered to libfcoe.

State and persistence: runtime state includes current `vlan_id`, `prio`, `data_src_addr`, `mac`, link state, selected FCF, and completion state for VLAN discovery. No persistent storage. skb ownership transfers to LL2/libfcoe on success and is freed locally on local handling or error.

Dependencies and integration: depends on Linux Ethernet/VLAN skb helpers, FC/FIP descriptor definitions, libfcoe controller receive path, QED LL2 transmit operations, QEDF link/VLAN helpers, and QEDF debug/dump-frame module parameters.

Risks and test signals: descriptor parsing trusts FIP descriptor lengths enough to advance through the packet; malformed FIP frames should be fuzzed for bounds behavior. VLAN tagging uses the stored VLAN ID, including fallback/null states, so discovery and link-up sequencing matter. CVL matching must avoid resetting on unrelated fabrics while still honoring switch-initiated clears. Useful tests include link-down VLAN request, LL2 transmit failure, VLAN notification with changed/zero VID, destination-MAC mismatch, CVL with matching and nonmatching descriptors, and libfcoe handoff for ordinary discovery/keepalive frames.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_hsi.h

Purpose: defines the QEDF-facing FCoE hardware/software interface layouts shared with QED firmware: command queue elements, completion queue elements, response information, unsolicited/warning/error payloads, error code enums, slow-path error codes, and task transmit states.

Important APIs/types/functions: `struct fcoe_cmdqe_control` and `struct fcoe_cmdqe` describe control and payload command queue entries. `struct fcoe_cqe` is the central completion entry with `cqe_data` fields for task ID and CQE type plus a `union fcoe_cqe_info`. Completion payloads include `fcoe_cqe_rsp_info` for FCP response status/residual/sense metadata, `fcoe_err_report_entry` for error detection, `fcoe_warning_report_entry` for REC/RR timer warnings, `fcoe_abts_info` for ABTS responses, `fcoe_cqe_midpath_info` for ELS/TMF response placement, and `fcoe_unsolic_info` for BDQ-backed unsolicited packets. Enums `fcoe_cqe_type`, `fcoe_fp_error_warning_code`, `fcoe_sp_error_code`, and `fcoe_task_tx_state` define firmware event and state values consumed by completion dispatch and recovery code.

Control flow: no executable code. Runtime code in `qedf_io.c` and `qedf_els.c` decodes CQEs using these structures, tests bit fields with the provided masks/shifts, extracts XIDs and CQE types from `cqe_data`, and maps error/warning bits to ABTS, REC/SRR, cleanup, or unsolicited frame handoff.

State and persistence: structures represent DMA/shared-memory protocol state produced or consumed by firmware. They are transient queue entries and task states, not persisted. Endianness annotations (`__le16`, `__le32`) define how drivers must convert firmware values.

Dependencies and integration: includes QED common/storage/FCoE HSI headers and must be included before other QED headers from `qedf.h`. The layouts are tightly coupled to firmware task initialization helpers and QED FCoE ops.

Risks and test signals: layout drift between driver and firmware is catastrophic, causing bad task IDs, wrong residuals, missed errors, or invalid DMA addresses. Several fields are bit-packed and endian-sensitive; consumers must convert before comparing or logging. Build/API compatibility with QED headers, firmware CQE decoding tests, unsolicited BDQ index validation, ABTS response handling, residual/sense parsing, and warning/error bitmap coverage are critical signals.

# sources/distributed-fs/ceph-client/drivers/scsi/qedf/qedf_io.c

Purpose: implements the main QEDF SCSI/FCoE I/O engine: command manager allocation/free, TID/request allocation, SCSI queuecommand, SG/DMA mapping, firmware task initialization, SQ doorbells, normal completions, warning/error completions, ABTS, cleanup, task management, active-I/O flushing, unsolicited frame completion, tracing, and timeout handling.

Important APIs/types/functions: allocation/lifetime functions are `qedf_cmd_mgr_alloc()`, `qedf_cmd_mgr_free()`, `qedf_alloc_cmd()`, and `qedf_release_cmd()`. Submission functions are `qedf_queuecommand()`, `qedf_post_io_req()`, `qedf_map_sg()`, `qedf_build_bd_list_from_sg()`, `qedf_build_fcp_cmnd()`, `qedf_init_task()`, `qedf_init_mp_task()`, `qedf_get_sqe_idx()`, and `qedf_ring_doorbell()`. Completion/error functions include `qedf_scsi_completion()`, `qedf_scsi_done()`, `qedf_process_warning_compl()`, `qedf_process_error_detect()`, `qedf_process_abts_compl()`, `qedf_process_cleanup_compl()`, `qedf_process_tmf_compl()`, and `qedf_process_unsol_compl()`. Recovery and control functions include `qedf_initiate_abts()`, `qedf_initiate_cleanup()`, `qedf_flush_active_ios()`, `qedf_execute_tmf()`, `qedf_initiate_tmf()`, `qedf_init_mp_req()`, `qedf_drain_request()`, `qedf_cmd_timer_set()`, and the timeout work handler `qedf_cmd_timeout()`.

Control flow: `qedf_queuecommand()` validates SG count, unload/stop flags, MSI-X, remote-port readiness, drain/link/session state, retry-delay throttling, then allocates a `QEDF_SCSI_CMD` and posts it under `rport_lock`. Posting records direction/stat counters, maps the SCSI SG list into firmware BDs, obtains an SQE and task context, initializes the FCP command/task, rings the doorbell, marks the request outstanding, and optionally traces it. Normal CQE completion validates the request is still outstanding and not in cleanup/abort, ignores completions during target/LUN flush, parses FCP response and sense/residuals, unmaps DMA, handles firmware underrun and retry-delay qualifiers, clears outstanding, detaches SCSI backpointers, calls `scsi_done()`, and drops the kref. Error/warning CQEs either start REC/SRR for tape REC_TOV or initiate ABTS; stop-on-error can set a global stop-I/O flag. ABTS reuses the original task, posts abort, waits via completion/timeout, can schedule RRQ after BA_ACC, and optionally returns the SCSI command with DID_ERROR. Cleanup posts a firmware cleanup task, waits synchronously, may request a QED drain on timeout, completes SCSI/TMF state, and records cleanup success/failure. TMF allocates a task-management request, waits for TM completion, checks FCP response, then flushes active I/Os for a LUN or target. Unsolicited CQEs copy BDQ data into an `fc_frame`, schedule deferred libfc processing, and advance BDQ producer indices.

State and persistence: all state is volatile. The command manager owns a fixed array of 2048 `qedf_ioreq` objects and per-TID BD tables, tracked by `alloc`, rotating `idx`, `free_list_cnt`, krefs, and per-rport `num_active_ios/free_sqes/ios_to_queue`. Per-request flags (`QEDF_CMD_OUTSTANDING`, `QEDF_CMD_IN_ABORT`, `QEDF_CMD_IN_CLEANUP`, `QEDF_CMD_SRR_SENT`, `QEDF_CMD_DIRTY`, `QEDF_CMD_ERR_SCSI_DONE`) gate race-prone transitions. Timers/completions (`timeout_work`, `rrq_work`, `abts_done`, `cleanup_done`, `tm_done`) synchronize timeout, EH, and completion contexts. Driver counters record input/output/control requests, aborts, allocation failures, resets, busy/task-set-full statuses, SGE path counts, and trace entries. DMA mappings and coherent buffers are explicitly mapped/unmapped/freed.

Dependencies and integration: integrates with the SCSI mid-layer queuecommand/scsi_done contract, libfc rport readiness and blocking, QED firmware task memory and init helpers, QED LL2/common drain, PCI DMA APIs, workqueues, timers, completions, mempools, FC frame helpers, and the HSI structures in `qedf_hsi.h`. It calls into ELS recovery (`qedf_send_rec()`, `qedf_send_rrq()`, `qedf_restart_rport()`) and is called by the driver's CQ processing path outside this file.

Risks and test signals: this file is the highest-risk area. Request reuse and completion can race with ABTS, cleanup, RRQ delayed work, target/LUN reset, upload, timeout, and unload; missed kref transitions can leak or double-free TIDs. Some paths return without dropping references if validation fails late, so fault injection is valuable. `qedf_map_sg()` does not explicitly check `dma_map_sg()` failure before iterating; zero mapped entries surface as `-ENOMEM` later. `qedf_scsi_done()` uses `virt_addr_valid()` on SCSI pointers, which is an unreliable lifetime guard compared with ownership. Active-I/O flush scans the whole 2048-entry pool and marks dirty tasks if upload drain cannot quiesce. Test signals should cover queue full and SG limit, link down/drain/unload, retry-delay BUSY/TASK_SET_FULL, normal read/write residual and sense handling, firmware underrun, DMA map/unmap balance, ABTS timeout/ACC/RJT, cleanup timeout and drain, TMF success/failure with LUN and target flush, REC/SRR tape recovery, unsolicited frame BDQ bounds, I/O trace wraparound, and stress with concurrent completions and resets.
