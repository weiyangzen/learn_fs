# sources/storage-engines/rocksdb/db/db_test_util.cc

Purpose: This file implements the shared RocksDB DB test harness declared in `db_test_util.h`. It is not product-path storage-engine code; it is a dense support layer used by many DB unit tests to create isolated databases, vary option configurations, simulate environments, inspect LSM state, generate deterministic SST shapes, and validate public and internal read paths. The implementation turns `DBTestBase` into a reusable fixture with a `SpecialEnv`, per-thread DB directories, optional memory/encrypted envs, option-matrix helpers, column-family reopen helpers, CRUD wrappers, compaction/file layout probes, and data verification utilities.

Important APIs and functions: `SpecialEnv::SpecialEnv()` initializes all fault-injection and counting state used by the inline wrappers in the header. `DBTestBase::DBTestBase()` constructs the base env from system config, optionally wraps it in `MockEnv` or encrypted env based on `MEM_ENV`/`ENCRYPTED_ENV`, creates a `SpecialEnv`, destroys stale paths, opens a DB, and resets deterministic random state. `~DBTestBase()` clears sync points, closes handles, destroys DB directories unless `KEEP_DB` is set, releases `sst_file_manager`, and deletes the env. The option-selection APIs are `ShouldSkipOptions()`, `ChangeOptions()`, `ChangeCompactOptions()`, `ChangeWalOptions()`, `ChangeFilterOptions()`, `ChangeOptionsForFileIngestionTest()`, `CurrentOptions()`, `GetDefaultOptions()`, and `GetOptions()`. `GetOptions()` is the central option matrix, covering hash/plain/block table variants, direct IO, merge-as-put, filters and partitioned filters, universal/FIFO compaction, row cache, WAL modes, subcompactions, pipelined writes, concurrent WAL writes, checksums, partitioned indexes, latest block-based format, and ASAN-specific tiny cache behavior.

Control flow: The fixture constructor always builds an env stack first, derives `dbname_`, `alternative_wal_dir_`, and `alternative_db_log_dir_`, destroys old directories with both default and alternate WAL settings, and opens using `CurrentOptions()`. Reopen paths follow a consistent pattern: close existing column-family handles, build descriptors if needed, copy or assign `last_options_`, call `MaybeInstallTimeElapseOnlySleep()`, then call `DB::Open`, `DB::OpenForReadOnly`, or `DB::Open` with descriptors. `Change*Options()` methods mutate `option_config_`, destroy/reopen, and return whether another configuration remains. CRUD helpers translate fixture-level shortcuts into DB calls; notably `Put()` uses `Merge()` when the current option config is `kMergePut`, and `TimedPut()` writes through a `WriteBatch` with per-key write time. Inspection helpers mostly read properties or metadata from `DBImpl`, `VersionSet`, `ColumnFamilyMetaData`, and `LiveFileMetaData`. Data-generation helpers write deterministic key ranges, wait for flush/compaction unless `nowait` is requested, and then tests use file-count/level probes to assert shape.

State and persistence behavior: Persistent state is the temporary RocksDB database under `dbname_`, optional WAL/db-log directories, and optional DB paths such as `dbname_ + "_2"`. The fixture deliberately destroys and recreates this state across option changes. `last_options_` records the options used for destruction/reopen and for internal iterator comparators. `handles_` owns live column-family handles until `Close()` destroys them. `SpecialEnv` state is runtime-only but directly affects persistence outcomes: skipped fsyncs, dropped writes, no-space errors, manifest/WAL write failures, write slowdowns, read counters, fake time, direct-IO sync-point setup, and file operation counters can change whether RocksDB creates, syncs, or observes files. `SetTimeElapseOnlySleepOnReopen()` permanently switches the fixture into mock-elapsed-time behavior on a later reopen and disables stats dumping/persistence to avoid timed-wait deadlocks.

Dependencies and integration points: This implementation depends on RocksDB internals (`DBImpl`, `VersionSet`, `ColumnFamilyData`, `VersionStorageInfo`, internal iterators, `TEST_CompactRange`, `TEST_WaitForFlushMemTable`, `TEST_WaitForCompact`), public APIs (`DB`, `Options`, `ColumnFamilyHandle`, `CompactRangeOptions`, `CompactionOptions`, `WriteBatch`, `Iterator`, `SstFileManager`, `Statistics`), table/cache helpers, `MockEnv`, read-only FS wrappers, encryption env creation, sync points, and GoogleTest assertions. It integrates with a large set of DB tests by hiding setup and making assertions compact, but it also means test semantics are tightly coupled to internal property names and test-only DBImpl hooks.

Important utility behavior: `Contents()` verifies forward and reverse iterator ordering while producing `(key->value)` strings. `AllEntriesFor()` uses an internal iterator at `kMaxSequenceNumber` to render all internal records for one user key, including values, merges, deletions, and single deletions. `CheckAllEntriesWithFifoReopen()` verifies internal entries before, during, and after a FIFO-compaction reopen. `NumSortedRuns()`, `TotalSize()`, `SizeAtLevel()`, `TotalLiveFiles()`, `NumTableFilesAtLevel()`, `CompressionRatioAtLevel()`, `FilesPerLevel()`, `GetBlobFileNumbers()`, `GetLevelFileMetadatas()`, and `GetSstSizeHelper()` expose LSM/file state used in compaction tests. `MakeTables()`, `FillLevels()`, `MoveFilesToLevel()`, `GenerateNewFile()`, and `GenerateNewRandomFile()` build predictable LSM layouts. `VerifyDBFromMap()` validates `Get`, `MultiGet`, normal iterator forward/reverse/seek, optional tailing iterator, and optional not-found keys over the same expected map. `VerifyDBInternal()` validates the internal iterator stream. `VerifySstUniqueIds()` asserts all table properties expose unique SST IDs.

Risks and edge cases: The harness intentionally uses internal APIs and property strings, so RocksDB internal refactors can break many tests at once. Several helpers encode assumptions about generated file sizes, flush triggers, level counts, and handle indices; for example `Size()` and `TotalTableFiles()` use fixed handle indices in some branches. `CountFiles(size_t*)` only writes `*count` when a separate WAL dir is used, which is surprising if callers expect a count for the default path case. `Close()` assumes `db_` is valid when handles exist. Time-elapse-only sleep is intentionally one-way within a fixture. The option matrix must be kept in sync with table factory, prefix extractor, memtable, direct-IO, and compaction behavior changes; otherwise broad option-iteration tests may report failures unrelated to the feature under test. The ASAN tiny block cache is useful for UAF detection but can change cache-sensitive timing and performance.

Test signals: This file is itself a test support implementation. Its direct signals are GoogleTest `ASSERT_*`/`EXPECT_*` failures embedded in helpers, sync-point callbacks, DB property reads, internal iterator validation, and deterministic data-shape assertions. Downstream tests rely on it for isolated DB creation/destruction, option iteration, fault injection through `SpecialEnv`, compaction waiting, exact file counts per level/path, and multi-read/iterator consistency checks.

# sources/storage-engines/rocksdb/db/db_test_util.h

Purpose: This header declares and partly implements the common RocksDB DB test utility surface. It provides the fixture base class and test doubles needed by DB tests: a fault-injecting `EnvWrapper`, a file-system wrapper that tracks SST temperature, event listeners, a merge operator used for failure-scope tests, a cache wrapper that tracks cache-charge peaks, and the `DBTestBase` fixture API. Much of `SpecialEnv` and `FileTemperatureTestFS` is implemented inline because the wrappers define nested file classes specialized to each file creation call.

Important APIs and types: `anon::AtomicCounter` wraps a mutex/condition variable counter with `Increment()`, `Read()`, `WaitFor()`, and `Reset()`. `anon::OptionsOverride` lets tests override filter policy, partition filters, metadata block size, skip policy, block-cache behavior, and `level_compaction_dynamic_level_bytes`. `SkipPolicy` supplies small bitmasks for cross-feature test skipping. `SpecialEnv` is the most important test double: it subclasses `EnvWrapper`, intercepts writable, random-access, sequential, directory, delete, rename, sleep, and time operations, and exposes many atomics/flags for fault injection and counters. `FileTemperatureTestFS` subclasses `FileSystemWrapper` and records requested/current SST temperatures by parsed table file number. `OnFileDeletionListener` and `FlushCounterListener` are small `EventListener` implementations. `TestPutOperator` is a merge operator that behaves like put but can fail on special operand strings. `TargetCacheChargeTrackingCache<R>` tracks cache charge for a target `CacheEntryRole`. `DBTestBase` is the shared `testing::Test` base with option enums, skip masks, DB lifecycle helpers, operation wrappers, LSM inspection helpers, file-generation helpers, verification helpers, and in-place update callbacks. `VerifySstUniqueIds()`, `kKnownTemperatures`, and `RandomKnownTemperature()` are free helper APIs.

Control flow: `SpecialEnv::NewWritableFile()` first enforces no-overwrite and random/non-writable failure injection, disables mmap/direct writes for MANIFEST and log files, delegates file creation to the target env, and then wraps the result by filename category. `.sst` files become `SSTableFile`, which can invoke a table-write callback, drop writes, return no-space, count bytes, block `Sync()` while `delay_sstable_sync_` is set, count syncs, optionally skip fsync, and publish sync-point callbacks. MANIFEST files become `ManifestFile`, which can fail append or sync. WAL/log files become `SpecialWalFile`, which counts open WALs, can fail or slow appends, can inject corruption during `Sync()`, respects `skip_fsync_`, and reports configurable sync-thread-safety. Other files only wrap sync skipping. `NewRandomAccessFile()` can wrap reads with counters/byte accounting or random read failures and records compaction readahead. `NewSequentialFile()` can wrap sequential reads with counters. Sleep and time methods either pass through to the target env or advance `addon_microseconds_`, enabling tests to simulate elapsed time cheaply.

State and persistence behavior: The header declares runtime state used to simulate persistence failures: `drop_writes_`, `no_space_`, manifest/WAL error flags, `skip_fsync_`, `corrupt_in_sync_`, no-overwrite, non-writable counters/rates, random read failure odds, and rename errors. These flags are not persisted, but they alter the actual on-disk DB artifacts created during a test. Counters such as `bytes_written_`, `sync_counter_`, `random_read_counter_`, `sequential_read_counter_`, `sleep_counter_`, `delete_count_`, `rename_count_`, and `num_open_wal_file_` expose observed behavior. `FileTemperatureTestFS` persists nothing independently, but it mirrors RocksDB SST file lifecycle in `current_sst_file_temperatures_`, removes entries on delete, and can reject reads that request a non-matching known temperature. `DBTestBase` owns temporary DB paths, env wrappers, `DB` handle, column-family handles, current option config, and last options; its implementation uses these to create and destroy real DB state between tests.

Dependencies and integration points: The header includes RocksDB public APIs (`db.h`, options, env, file system, cache, compaction filter, SST writer, statistics, table), internal DB and filename utilities, mock table support, sync points, test harness assertions, compression/string/cast/mutex helpers, and merge operators. It is included by many DB test translation units. `DBTestBase::dbfull()` intentionally exposes `DBImpl*`, making downstream tests internal-implementation-aware. `SpecialEnv` integrates with `TEST_SYNC_POINT` names used across tests to coordinate file close/sync/range-sync/WAL append/preallocation behavior.

Important `DBTestBase` surface: `OptionConfig` enumerates the cross-product of configurations many tests run through: block-based index styles, plain tables, memtable reps, merge-put, filters, uncompressed, reduced level count, alternate WAL/log dirs, manifest rollover, perf options, universal/FIFO compaction, row cache, recycled logs, direct IO, subcompactions, unordered/pipelined/concurrent writes, partitioned filters/indexes, and latest table formats. `OptionSkip` and `kRangeDelSkipConfigs` let tests exclude incompatible configs. Lifecycle helpers cover create/reopen/destroy/read-only/enforced-read-only and column-family variants. Operation helpers cover put/timed put/merge/delete/single delete/get/multiget/flush/compact. Introspection helpers cover snapshots, contents, internal entries, sorted runs, live files, table files per level/path, compression ratio, blob file numbers, approximate size, SST listing, and table properties. Generation/verification helpers build test files and verify DB contents through multiple read APIs.

Risks and edge cases: The header exposes a large mutable test surface, so tests can accidentally depend on fixture internals or leave flags/callbacks set. `SpecialEnv` detects file category by substring matching (`.sst`, `MANIFEST`, `log`), which is adequate for RocksDB test filenames but brittle for unusual paths. Atomic comments mention pointers in a few places even though the fields are atomics, suggesting historical drift. `AtomicCounter::WaitFor()` requires a non-null `env_` and uses mockable env time; incorrect env setup can lead to misleading timeouts. `FileTemperatureTestFS` assumes table filenames can be parsed from the basename and that file numbers are stable keys. `TestPutOperator` uses magic operand strings to control failure scope, so tests must avoid those values unless failure is intended. The fixture API has many overloads using integer CF indexes; misuse can silently test the wrong column family.

Test signals: The utilities provide direct assertions in listeners, filters, temperature wrappers, merge operator contexts, and helper methods. They also provide observable counters and property helpers that downstream tests assert against: file counts, per-level layout strings, cache-charge peaks, read counts/bytes, sync/delete/rename counts, requested SST temperatures, flush reasons, deletion notifications, and exact logical/internal DB contents.

# sources/storage-engines/rocksdb/db/db_universal_compaction_test.cc

Purpose: This translation unit is RocksDB's universal-compaction regression and behavior test suite. It verifies universal compaction across single-level and multi-level configurations, manual compaction modes, dynamic option changes, filter behavior, size/read amplification triggers, trivial moves, parallel scheduling, output-path selection, column-family paths, bottom-priority compactions, compact-files conflicts, deletion-triggered compaction, ingest-behind, and periodic/off-peak compaction. It uses `DBTestBase` heavily to generate deterministic SST layouts and inspect LSM shape.

Important APIs, fixtures, and helpers: `CompressibleString()` creates 80-percent-compressible values through test utilities. `DBTestUniversalCompactionBase` derives from `DBTestBase` and parameterizes each test by `(num_levels_, exclusive_manual_compaction_)`. `DBTestUniversalCompaction` uses `/db_universal_compaction_test`; `DBTestUniversalCompaction2` is a non-parameterized fixture for collector/periodic tests; `DBTestUniversalCompactionMultiLevels`, `DBTestUniversalCompactionParallel`, and `DBTestUniversalManualCompactionOutputPathId` are specialized parameterized fixtures. `VerifyCompactionResult()` checks compacted input file names no longer appear in metadata in debug builds. `KeepFilter` keeps all keys, while `KeepFilterFactory` optionally asserts `CompactionFilter::Context` fields for full/manual compactions. The suite uses `INSTANTIATE_TEST_CASE_P` to run main tests over `num_levels` values such as `1`, `3`, `5`, `8`, `10`, `20` and both manual-compaction exclusivity settings where applicable.

Control flow by test cluster: Early tests validate trigger mechanics. `UniversalCompactionSingleSortedRun` sets invalid trigger `0`, verifies RocksDB normalizes it to `1`, and repeatedly generates files that compact into one sorted run. `OptimizeFiltersForHits` blocks background compaction, builds L0 files with bloom filters, verifies `BLOOM_FILTER_USEFUL` increments for L0 negative lookups, then unblocks compaction and verifies optimized filters stop being used for the compacted output. `UniversalCompactionTrigger` walks staged L0 sorted-run growth under size-ratio rules and checks compaction-filter full-compaction context. `UniversalCompactionSizeAmplification`, `DynamicUniversalCompactionSizeAmplification`, and `DynamicUniversalCompactionReadAmplification` verify size-amplification and read-amplification triggers, including live `SetOptions()` changes to `compaction_options_universal` and mutable CF option propagation.

Control flow for compaction operations and levels: `CompactFilesOnUniversalCompaction` creates many universal L0 files, verifies `CompactFiles()` rejects non-L0 output, compacts selected L0 files, and verifies chosen files disappear; selecting first and last files forces all files into one output. `UniversalCompactionTargetLevel` manually compacts universal files to a requested target level with `change_level`. Multi-level tests verify universal compaction with many keys, allow-trivial-move behavior via sync-point counters, and correctness after reopen. Parallel tests use sync points around `CompactionJob::Run()` and universal picker returns to prove multiple compactions can run concurrently and that the picker recalculates score/file-number state correctly instead of over-scheduling stale work.

Control flow for compression and path placement: `UniversalCompactionOptions`, `UniversalCompactionStopStyleSimilarSize`, `UniversalCompactionCompressRatio1`, and `UniversalCompactionCompressRatio2` exercise compression-size-percent and stop-style behavior using generated files and `TotalSize()` thresholds. `UniversalCompactionTrivialMoveTest1/2` check trivial and non-trivial moves for larger multi-level layouts when not in restricted Valgrind runs. `UniversalCompactionFourPaths`, `UniversalCompactionCFPathUse`, and `UniversalCompactionSecondPathRatio` configure DB paths or CF paths with different size budgets and assert SST counts per path after each generated-file stage, then verify all keys before and after reopen. `ManualCompactionOutputPathId` explicitly compacts to target path IDs, verifies persistence across reopen, and checks invalid path IDs return `InvalidArgument`.

Control flow for scheduling and conflicts: `ConcurrentBottomPriLowPriCompactions` runs only for multi-level universal compaction. It toggles `reduce_file_locking`, coordinates bottom-priority forwarding/repicking through sync-point dependencies, generates files while the first compaction is blocked, and asserts one output remains in L0 while another reaches the bottom level. `RecalculateScoreAfterPicking` uses a small `max_merge_width` and counts `BackgroundCompaction:Start` callbacks to ensure only one compaction is attempted once the score drops below one. `FinalSortedRunCompactFilesConflict` starts a `CompactFiles()` call on the final sorted run while a background size-amplification compaction is picked, verifying no conflict or deadlock when non-exclusive manual compaction is enabled.

Control flow for deletion-triggered and periodic compaction: `BasicL0toL1`, `MultipleLevels`, `OverlappingL0`, and conditional `SingleLevel` use `NewCompactOnDeletionCollectorFactory()` to compact files with dense tombstone windows under universal compaction, checking level placement and overlapping L0 behavior. `IngestBehind` verifies global and CF-specific ingest-behind options alter bottommost placement, and that another CF without CF-specific ingest-behind can still use the last level. `PeriodicCompactionDefault` verifies default periodic-compaction seconds derived from compaction filters and TTL. `PeriodicCompaction` uses `SpecialEnv` mock sleep and a sync-point callback from `PickPeriodicCompaction` to confirm old flushed/compacted files trigger periodic compaction to output level `4`. `PeriodicCompactionOffpeak` uses `MockSystemClock`, preset and dynamically changed `daily_offpeak_time_utc`, and many current-time cases to verify periodic compaction waits for off-peak policy or eventually triggers after another day.

State and persistence behavior: Tests persist real temporary RocksDB DB state, then repeatedly destroy/reopen or reopen with column families to verify MANIFEST and file-layout durability. Generated key/value data is deterministic from `Random(301)` or `test::RandomSeed()` for off-peak jitter. Compaction state is observed through sorted-run count, table files per level, live file metadata, path-specific SST counts, options/mutable CF options, bloom-filter statistics, and sync-point counters. Manual compaction options such as `target_level`, `target_path_id`, `exclusive_manual_compaction`, and `change_level` directly affect persisted SST placement. Mock time is runtime-only but affects periodic compaction selection through file ages and off-peak windows.

Dependencies and integration points: The suite depends on `db_test_util.h`, RocksDB stack-trace setup, compact-on-deletion table properties collectors, `MockSystemClock`, sync points, test utilities, and random generation. It reaches into DB internals through `DBImpl` test hooks, `VersionSet::offpeak_time_option()`, compaction picker sync-point names, write-controller pressure tokens, and property strings such as `rocksdb.num-files-at-levelN`. It validates integration among universal compaction picker, DBImpl background scheduler, compaction filter factories, table properties collectors, bloom filters, path picker, CF path handling, mutable options, manual compaction, and periodic compaction.

Risks and edge cases: Many assertions rely on exact generated file sizes, flush cadence, level counts, and picker heuristics; comments explicitly call out magic numbers and memtable flush assumptions. Several tests are disabled or conditional under Valgrind/Snappy/single-level-DTC feature macros, so coverage varies by build. Sync-point dependency tests are sensitive to internal sync-point names and background scheduling changes. Path-count assertions assume cleanup of auxiliary DB paths and deterministic path selection. The conditional `ENABLE_SINGLE_LEVEL_DTC` block contains a malformed-looking `ASSERT_OK(Flush()(;` statement in the current source, so enabling that macro would likely expose a compile-time issue unless patched elsewhere. Off-peak periodic tests involve time arithmetic and dynamic DB option updates; failures can indicate either compaction policy bugs or clock/off-peak interpretation drift.

Test signals: The file is executable through its `main()` with RocksDB stack traces and GoogleTest. Primary signals are exact `ASSERT_EQ`/`ASSERT_GT`/`ASSERT_LT` checks for sorted-run counts, table files per level/path, total sizes/compression thresholds, ticker counts, compaction reason counters, mutable option values, key-value correctness before/after reopen, and error statuses from invalid operations. Sync-point callbacks validate compaction reason, start/output level, trivial versus non-trivial paths, preallocation limits, and scheduling concurrency.
