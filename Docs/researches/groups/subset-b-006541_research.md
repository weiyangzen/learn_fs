# sources/distributed-fs/ceph-client/sound/soc/soc-core.c

Purpose: this is the central ALSA System-on-Chip core implementation. It owns global component discovery, sound-card registration and rebinding, DAI-link to runtime binding, component/DAI registration, card suspend/resume/poweroff handling, control creation, debugfs/sysfs exposure, and several device-tree parsing helpers used by ASoC machine drivers. In this source tree it is infrastructure code rather than a hardware driver: codec, CPU, platform, and machine drivers register data into this core, then the core instantiates ALSA cards and PCM/compress devices from those registrations.

Important APIs/types/functions: the file maintains the global `component_list`, `unbind_card_list`, and `client_mutex`. Exported entry points include `snd_soc_register_card()`, `snd_soc_unregister_card()`, `snd_soc_register_component()`, `snd_soc_add_component()`, `snd_soc_component_initialize()`, `snd_soc_unregister_component_by_driver()`, `snd_soc_register_dai()`, `snd_soc_unregister_dai()`, `snd_soc_add_pcm_runtimes()`, `snd_soc_remove_pcm_runtime()`, `snd_soc_runtime_set_dai_fmt()`, `snd_soc_find_dai()`, `snd_soc_find_dai_with_mutex()`, `snd_soc_lookup_component*()`, `snd_soc_get_pcm_runtime()`, `snd_soc_close_delayed_work()`, `snd_soc_suspend()`, `snd_soc_resume()`, `snd_soc_poweroff()`, and `snd_soc_pm_ops`. Device-tree helpers include `snd_soc_of_parse_card_name()`, `snd_soc_of_parse_audio_simple_widgets()`, `snd_soc_of_parse_pin_switches()`, `snd_soc_of_parse_tdm_slot()`, `snd_soc_of_parse_audio_routing()`, `snd_soc_of_parse_aux_devs()`, `snd_soc_daifmt_*()`, `snd_soc_get_dlc()`, `snd_soc_of_get_dlc()`, and the CPU/CODEC DAI-link array parsers.

Control flow: component registration starts in `snd_soc_register_component()`, which allocates and initializes a `struct snd_soc_component`, then `snd_soc_add_component()` registers DAI objects, adds the component to `component_list`, and attempts to rebind cards waiting on `unbind_card_list`. Card registration starts in `snd_soc_register_card()`: it allocates the card DAPM context, initializes list heads and locks, stores the card in device drvdata, and calls `snd_soc_bind_card()` under `client_mutex`. Binding fills dummy links, initializes card DAPM, applies topology FE/BE overrides, binds aux devices, creates `snd_soc_pcm_runtime` objects for each DAI link, creates the ALSA `snd_card`, creates card and component DAPM widgets, probes the machine card, probes link components and DAIs in configured order, initializes each runtime with link ops, auto/explicit DAI format setup, compress or PCM creation, adds controls/routes, normalizes card names, runs late probe, registers the ALSA card, marks endpoints dirty, and performs an initial DAPM sync. Failures unwind through `soc_cleanup_card_resources()`.

Runtime binding is performed by `snd_soc_add_pcm_runtime()`: after link sanity checks it creates an rtd device with sysfs groups, resolves CPU and CODEC DAIs via `snd_soc_find_dai()`, gathers matched platform components, compensates the channel-connection map for 1:1, 1:N, N:1, or explicit N:M mappings, and assigns stable PCM ids. `soc_init_pcm_runtime()` then initializes link-specific state, auto-selects a shared DAI format when all DAIs provide `auto_selectable_formats`, programs formats on CODEC and CPU sides with clock-provider polarity flipped for CPU DAIs, creates compress or PCM devices, and calls per-DAI `pcm_new()`.

State and persistence behavior: global registration state is persistent in `component_list`; cards that could not bind because a component was missing are preserved on `unbind_card_list` until a later component registration calls `snd_soc_rebind_card()`. Each card owns persistent lists for DAPM widgets, DAPM paths, DAPM contexts, aux components, component devices, and runtimes. Each runtime has its own child `struct device`, devm-managed rtd storage, a `delayed_work` item for playback powerdown, per-stream DPCM client lists, a `pmdown_time` copied from the module parameter, and sysfs attributes. Component and DAI allocations are devm-managed against the component device, while card teardown disconnects/freezes the ALSA card, shuts DAPM down, removes link resources, DAIs, components, rtd devices, aux bindings, debugfs entries, and `snd_card`.

Power-management integration: suspend blocks userspace via ALSA power state, mutes active playback DAIs, suspends PCMs, flushes delayed powerdown, sends DAPM suspend events, syncs endpoint state, and suspends components only when DAPM bias indicates they are idle enough. Resume is deferred to workqueue context, resumes suspended components, sends DAPM resume events, unmutes active playback, resyncs DAPM, and restores ALSA power state. Poweroff flushes delayed work, forces DAPM shutdown, and selects sleep pinctrl states.

Dependencies/integration points: this file is tightly coupled to `sound/soc.h`, DAPM (`soc-dapm.c`), DAI wrapper APIs (`soc-dai.c`), PCM/compress creation (`soc-pcm`, `soc-compress`), DPCM locking/debugfs, component/card/link callback helpers, topology overrides, OF and OF graph helpers, DMI long-name generation, pinctrl, regmap cache dirtying, debugfs, sysfs device groups, platform-driver registration for legacy `soc-audio`, and tracepoints in `trace/events/asoc.h`. Machine drivers and generic card parsers depend on the exported OF helpers and card/component registration entry points.

Risks: most global operations depend on `client_mutex`; callers using nolocked lookup APIs must already hold it. Card binding/unbinding has a large unwind surface, so missing list initialization, duplicate component matches, or partially initialized rtds can produce leaks or double removals. `snd_soc_lookup_component_by_name()` uses substring matching and returns the first match, which can be ambiguous. DAI link sanity checks intentionally defer probe when components are absent, so driver-visible errors may surface only as repeated `-EPROBE_DEFER`. The automatic DAI-format negotiation only works when all DAIs advertise formats and can silently leave manually specified fields unchanged. Device-tree parser helpers transfer node references in several places; callers must use the matching put helpers for CPU and CODEC arrays. Suspend/resume is asynchronous, so card removal and system PM must keep work flushing and ALSA power-state ordering intact.

Test signals: useful coverage includes component registration/unregistration with multiple components per device, card probe with missing components followed by late component registration, DAI-link validation for invalid name/of_node combinations, explicit and default channel maps, auto DAI-format negotiation, OF parsing for widgets/routes/aux-devs/TDM slots/clock-provider flags, probe-failure unwind at each stage, devres deferrable card rebinding, suspend/resume while streams are active, delayed playback powerdown behavior, debugfs `asoc/dais` and `asoc/components`, sysfs `pmdown_time`, and module init/exit of the legacy `soc-audio` platform driver.

# sources/distributed-fs/ceph-client/sound/soc/soc-dai.c

Purpose: this file is the ASoC DAI operation wrapper layer. It normalizes calls into `struct snd_soc_dai_driver` callbacks, provides fallback to component-level clock/PLL callbacks where appropriate, tracks which startup/hw_params/trigger/compress-startup calls succeeded so rollback paths do not over-unwind, and fans PCM operations across all CPU and CODEC DAIs in a runtime.

Important APIs/types/functions: exported configuration APIs include `snd_soc_dai_set_sysclk()`, `snd_soc_dai_set_clkdiv()`, `snd_soc_dai_set_pll()`, `snd_soc_dai_set_bclk_ratio()`, `snd_soc_dai_set_fmt()`, `snd_soc_dai_set_tdm_slot()`, `snd_soc_dai_set_tdm_idle()`, `snd_soc_dai_set_channel_map()`, `snd_soc_dai_get_channel_map()`, `snd_soc_dai_set_tristate()`, `snd_soc_dai_prepare()`, `snd_soc_dai_digital_mute()`, `snd_soc_dai_stream_valid()`, `snd_soc_dai_action()`, and `snd_soc_dai_active()`. Runtime helpers include `snd_soc_pcm_dai_probe()`, `snd_soc_pcm_dai_remove()`, `snd_soc_pcm_dai_new()`, `snd_soc_pcm_dai_prepare()`, `snd_soc_pcm_dai_trigger()`, and `snd_soc_pcm_dai_delay()`. Compressed-audio wrappers include `snd_soc_dai_compr_startup()`, `shutdown()`, `trigger()`, `set_params()`, `get_params()`, `ack()`, `pointer()`, `set_metadata()`, and `get_metadata()`. `snd_soc_dai_get_fmt_max_priority()` and `snd_soc_dai_get_fmt()` support automatic DAI format selection used by `soc-core.c`.

Control flow: most public functions check whether the target DAI has driver ops and the requested callback, then call it and return through `soc_dai_ret()` so errors are consistently logged with device, function, and DAI name context. `snd_soc_dai_set_sysclk()` and `snd_soc_dai_set_pll()` fall back to component-level callbacks when DAI callbacks are absent; many other setters return `-ENOTSUPP`, `-EOPNOTSUPP`, or `-EINVAL` if unsupported. TDM setup first synthesizes default TX/RX masks when masks are zero, records the masks per PCM stream, and then calls optional driver `set_tdm_slot()`. PCM startup/hw_params/trigger paths mark the substream on success; matching shutdown/hw_free/stop paths honor a `rollback` flag and skip unrolling DAIs that were never successfully advanced.

For active playback start/resume/pause-release triggers, `snd_soc_pcm_dai_trigger()` iterates all runtime DAIs, calls the DAI trigger callback, unmutes DAIs whose driver requests mute control at trigger time, and marks trigger success. For stop/suspend/pause-push, it optionally filters by the rollback mark, mutes first when required, calls the trigger callback, stores the last trigger error, and clears the mark. Delay reporting computes separate maximum delays for CPU-side and CODEC-side DAIs rather than taking a single max across all DAIs.

State and persistence behavior: this layer does not allocate long-lived objects, but it mutates DAI runtime fields. `snd_soc_dai_action()` increments or decrements per-stream active counters and the owning component active counter. The mark macros store the current substream or compressed stream in DAI fields such as `mark_startup`, `mark_hw_params`, `mark_trigger`, and `mark_compr_startup`, giving rollback code idempotent behavior after partial failures. TDM masks are stored per stream through `snd_soc_dai_tdm_mask_set()`. `dai->probed` tracks whether the optional driver `probe()` callback has run.

Dependencies/integration points: the file depends on `sound/soc.h`, `sound/soc-dai.h`, and `sound/soc-link.h`; it is called from core card/runtime setup, PCM open/hw_params/trigger/free paths, compressed-audio paths, DAPM codec-to-codec event code, and simple-card clock/TDM helpers. It is intentionally callback-centric and leaves hardware-specific validation to DAI drivers.

Risks: default TDM mask generation uses `(1 << slots) - 1`, so very large slot counts relative to `unsigned int` width would be unsafe unless constrained by callers/drivers. Many unsupported callbacks are not fatal to all call sites because callers may treat `-ENOTSUPP` as acceptable; tests need to distinguish optional and required callbacks. The rollback marks store a single substream/cstream pointer per DAI, so unusual concurrent use of the same DAI in multiple streams must follow the broader ASoC locking and active-stream model. Trigger-stop returns the last error while continuing to unwind later DAIs, which is good for cleanup but can obscure the first failure. `snd_soc_dai_stream_valid()` treats nonzero `channels_min` as stream support, so malformed DAI stream descriptors can disable callbacks unexpectedly.

Test signals: exercise DAI drivers with missing callbacks, component-level sysclk/PLL fallback, default and driver-provided TDM mask translation, invalid RX idle-zero mode, rollback after startup/hw_params/trigger failure in the middle of a multi-DAI runtime, mute-on-trigger behavior for playback and capture with `no_capture_mute`, active counter balance through open/close and compressed streams, probe/remove order handling, and CPU/CODEC delay aggregation.

# sources/distributed-fs/ceph-client/sound/soc/soc-dapm.c

Purpose: this is the Dynamic Audio Power Management engine for ASoC. It models card and component audio paths as widgets and routes, computes whether each widget should be powered based on connected endpoints, stream activity, pin state, mixer/mux controls, supplies, suspend state, and bias policy, then sequences power changes in an order intended to avoid pops while minimizing register writes. It also owns DAPM kcontrols, DAI-link widget connection, pin APIs, debugfs/sysfs reporting, regulator/pinctrl/clock supply widget events, and DAPM shutdown.

Important APIs/types/functions: the private `struct snd_soc_dapm_context` records bias level, idle-bias policy, parent card/component, target bias, context list membership, route lookup caches, and debugfs root. Exported context helpers include `snd_soc_dapm_alloc()`, `snd_soc_dapm_to_dev()`, `snd_soc_dapm_to_card()`, and `snd_soc_dapm_to_component()`. Bias APIs include `snd_soc_dapm_force_bias_level()`, `snd_soc_dapm_init_bias_level()`, `snd_soc_dapm_get_bias_level()`, `snd_soc_dapm_get_idle_bias()`, and `snd_soc_dapm_set_idle_bias()`. Graph construction APIs include `snd_soc_dapm_new_control()`, `snd_soc_dapm_new_controls()`, `snd_soc_dapm_new_widgets()`, `snd_soc_dapm_add_routes()`, `snd_soc_dapm_del_routes()`, `snd_soc_dapm_new_dai_widgets()`, `snd_soc_dapm_link_dai_widgets()`, and `snd_soc_dapm_connect_dai_link_widgets()`. Runtime APIs include `snd_soc_dapm_sync()`, `snd_soc_dapm_sync_unlocked()`, `snd_soc_dapm_stream_event()`, `snd_soc_dapm_stream_stop()`, `snd_soc_dapm_update_dai()`, pin enable/disable/force/status/ignore-suspend helpers, and mixer/mux kcontrol get/put functions.

Control flow: widget creation duplicates a template, applies component name prefixes, acquires resources for regulator/pinctrl/clock supply widgets, assigns endpoint flags and a power-check function based on widget type, initializes edge lists and endpoint caches, defaults pins to connected, and adds the widget to the card. Route addition resolves source and sink widgets, favoring the current DAPM context while allowing cross-context routes, validates dynamic-control rules, creates a `snd_soc_dapm_path`, initializes static or control-dependent connection state, links the path into global and per-widget lists, updates endpoint flags, marks both endpoints dirty, and invalidates cached path counts when needed.

DAPM sync is centered on `dapm_power_widgets()`. It starts by choosing a default target bias for each context, resetting cached widget power state, and walking the dirty list. For each dirty widget, `dapm_power_one_widget()` calls its power-check function: generic widgets require both an input endpoint path and output endpoint path; supply widgets power when a dependent sink is powered; always-on widgets follow their connected state; forced widgets override the check. Widgets whose state changes are inserted into ordered power-up or power-down lists using `dapm_up_seq` or `dapm_down_seq`, subsequence, register, and context order. The engine then computes final target bias levels, moves card and component contexts through STANDBY/PREPARE/ON or OFF using async callbacks, runs WILL events, powers down first, applies pending kcontrol register updates, powers up, completes async operations, notifies components of stream events, and applies optional pop delays.

Power sequencing details: `dapm_seq_run()` batches adjacent widgets with the same DAPM context, register, sort level, and subsequence. `dapm_seq_run_coalesced()` updates cached `w->power`, runs PRE events, combines masks/values into a single register write via `dapm_update_bits()`, then runs POST events. Pre/post widgets are handled specially as event-only sequence points. Bias changes use `snd_soc_card_set_bias_level*()` and component bias callbacks, with runtime PM references taken when a context leaves OFF and dropped when it returns to OFF.

Control and route mutation: DAPM mixer and mux kcontrols store `struct dapm_kcontrol_data`, including cached value, associated widget list, associated paths, and optional autodisable supply widgets. Mixer/mux put callbacks update cached values, test hardware bits, mark connected paths changed via `dapm_connect_path()`, run `dapm_power_widgets()` with an optional register update, and request DPCM runtime updates when paths changed. Pin switch callbacks call `__dapm_set_pin()`, which updates `w->connected`, clears force on disable, marks widgets dirty, invalidates both endpoint directions, and then syncs. DAI channel updates during hw_params connect or disconnect AIF paths based on channel count.

DAI integration: `snd_soc_dapm_new_dai_widgets()` creates per-DAI playback/capture widgets from DAI stream names. `snd_soc_dapm_link_dai_widgets()` links widgets sharing stream names inside a DAPM context. `snd_soc_dapm_connect_dai_link_widgets()` connects CPU and CODEC DAI widgets for each non-dynamic runtime and channel map. Codec-to-codec links can get an intermediate `snd_soc_dapm_dai_link` widget with optional configuration kcontrol; its event callback opens both directions, activates DAIs, builds synthetic hw_params from `c2c_params`, calls DAI hw_params/prepare/mute/hw_free/shutdown, and frees the temporary runtime on powerdown.

State and persistence behavior: persistent state lives in card widget/path lists, per-context DAPM lists, per-widget edge lists, power state (`power`, `new_power`, `power_checked`, `active`, `connected`, `force`, `is_ep`, `endpoints[]`), path connection state (`connect`, optional `connected` callback, `is_supply`, walking flags), kcontrol private data, and per-rtd codec-to-codec widgets. Endpoint path counts are cached in widgets and invalidated selectively on route, pin, stream, and path-control changes. Dirty widgets live on `card->dapm_dirty` until sync processing removes them. DAPM resources are freed by `snd_soc_dapm_free()`, widget removal unlinks all paths, and shutdown explicitly powers down currently powered widgets and bias contexts.

Dependencies/integration points: DAPM depends on ALSA controls, ASoC card/component/DAI callbacks, DAI wrapper APIs from `soc-dai.c`, PCM params, DPCM runtime updates, regulator, pinctrl, clocks, runtime PM, async work domains, debugfs, sysfs via `snd_soc_dapm_dev_attrs`, tracepoints, and the broader card lifecycle in `soc-core.c`. It also exposes widget state through debugfs files and the runtime device `dapm_widget` sysfs attribute.

Risks: route lookup and prefixing use fixed 80-byte buffers for prefixed source/sink/pin names, so very long names may be truncated. Control-route removal is intentionally unsupported, which matters for dynamic topologies. Endpoint-cache invalidation is performance-sensitive and correctness-sensitive; missed invalidation can leave stale power decisions, while over-invalidation increases graph walks. Recursive graph walks use `path->walking` to break cycles and sometimes return connected, so cyclic graphs should be tested. Kcontrol sharing is based on pointer identity of control templates within a DAPM context, making template lifetime and duplication important. Several APIs require DAPM/card mutexes and assert only after the card is instantiated. Codec-to-codec event setup mutates a synthetic substream and allocates a runtime, so failures after partial DAI startup/hw_params must rely on later event/unwind paths. Supply widgets call into regulator/clk/pinctrl providers during power sequencing; provider failures are logged but may leave partial hardware state.

Test signals: build with and without `CONFIG_DEBUG_FS`; create cards with mixers, muxes, demuxes, supplies, regulator/pinctrl/clock supplies, component prefixes, cross-component routes, and fully-routed cards; verify initial widget power from registers, route addition/deletion, shared kcontrols, autodisable controls, mixer/mux register writes and path changes, pin switch get/put, force-enable pins, ignore-suspend endpoints, delayed playback stream stop, DAI channel route updates for different channel counts, codec-to-codec link power-up/down, suspend/resume path preservation, shutdown powerdown order, debugfs widget output, sysfs `dapm_widget`, and DPCM runtime update notifications after path changes.

# sources/distributed-fs/ceph-client/sound/soc/soc-devres.c

Purpose: this file provides resource-managed registration wrappers for ASoC components, ASoC cards, deferrable cards, and, when enabled, generic dmaengine PCM devices. It converts explicit unregister calls into devres release callbacks tied to the lifetime of the parent `struct device`.

Important APIs/types/functions: exported functions are `devm_snd_soc_register_component()`, `devm_snd_soc_register_card()`, `devm_snd_soc_register_deferrable_card()`, and under `CONFIG_SND_SOC_GENERIC_DMAENGINE_PCM`, `devm_snd_dmaengine_pcm_register()`. Release callbacks are `devm_component_release()`, `devm_card_release()`, and `devm_dmaengine_pcm_release()`, each storing just enough pointer state for the matching unregister function.

Control flow: each devm wrapper allocates a small devres record first. Component registration calls `snd_soc_register_component()`; on success it stores the component driver pointer and adds the devres record, while on failure it frees the record. Card registration follows the same pattern around `snd_soc_register_card()`. Deferrable card registration is special: it sets `card->devres_dev` to the managing device and directly calls `snd_soc_register_card()`, relying on the core card bind/rebind path to install a devres binding record even when initial binding returns `-EPROBE_DEFER`. The dmaengine wrapper calls `snd_dmaengine_pcm_register()` and adds a record containing the parent device on success.

State and persistence behavior: this file stores only tiny devres payloads: a component driver pointer, a card pointer, or a device pointer. The real persistent state is owned by the ASoC core or dmaengine PCM layer. On device teardown, devres invokes the release callback in managed order, unregistering the component by driver, unregistering the card, or unregistering dmaengine PCM.

Dependencies/integration points: it depends on `sound/soc.h` for core component/card APIs and `sound/dmaengine_pcm.h` for optional dmaengine PCM management. It is used by platform, codec, CPU DAI, and machine drivers that want probe error handling and remove paths to be shorter and less error-prone. The deferrable-card path integrates with `soc-core.c`'s `card->devres_dev`, `devm_snd_soc_bind_card()`, and `unbind_card_list` behavior.

Risks: devres release ordering matters when a driver registers multiple related resources; managed unregister must occur after dependent allocations remain valid. `devm_snd_soc_register_component()` unregisters by device plus component-driver name, so multiple components sharing a device/driver are all relevant to that core lookup behavior. The deferrable card wrapper does not add devres state directly in this file, so its correctness depends on the core bind path adding/removing the managed card binding during successful or deferred card binding. Drivers must not also manually unregister the same managed resource unless they understand devres lifetime, or double unregister paths can result.

Test signals: probe-failure tests should verify no devres leak when core registration fails; remove/unbind tests should confirm managed component/card/dmaengine unregister calls occur once; deferred-card tests should register a card before all components exist, then add the missing component and verify managed rebind and managed teardown; configuration tests should compile both with and without `CONFIG_SND_SOC_GENERIC_DMAENGINE_PCM`.
