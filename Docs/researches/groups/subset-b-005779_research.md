# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap.c

Purpose: Implements the core XFS block mapping engine for inode forks. It translates file offsets to filesystem blocks, allocates and frees mapped extents, converts delayed allocations and unwritten extents, manages transitions between local, extent-list, and bmap-btree fork formats, maintains reverse mappings and quota/block accounting, and provides deferred map/unmap intent processing used by reflink and metadata repair style operations.

Important APIs, types, and functions: The file centers on `struct xfs_bmalloca`, `struct xfs_bmap_intent`, bmbt cursor helpers, and the `xfs_bmbt_irec` extent record shape. Public entry points include `xfs_bmap_compute_maxlevels()`, `xfs_bmap_compute_attr_offset()`, `xfs_bmap_add_attrfork()`, `xfs_bmap_local_to_extents_empty()`, `xfs_bmap_local_to_extents()`, `xfs_iread_extents()`, `xfs_bmap_first_unused()`, `xfs_bmap_last_before()`, `xfs_bmap_last_offset()`, `xfs_bmapi_read()`, `xfs_bmapi_write()`, `xfs_bmapi_convert_delalloc()`, `xfs_bmapi_remap()`, `xfs_bunmapi()`, `xfs_bunmapi_range()`, `xfs_bmap_collapse_extents()`, `xfs_bmap_can_insert_extents()`, `xfs_bmap_insert_extents()`, `xfs_bmap_split_extent()`, `xfs_bmap_map_extent()`, `xfs_bmap_unmap_extent()`, `xfs_bmap_finish_one()`, `xfs_bmap_validate_extent_raw()`, `xfs_bmap_validate_extent()`, `xfs_bmap_query_all()`, `xfs_get_extsz_hint()`, and `xfs_get_cowextsz_hint()`. Key internal routines are `xfs_bmap_extents_to_btree()`, `xfs_bmap_btree_to_extents()`, `xfs_bmap_add_extent_delay_real()`, `xfs_bmap_add_extent_unwritten_real()`, `xfs_bmap_add_extent_hole_real()`, `xfs_bmap_btalloc()`, `xfs_bmap_del_extent_delay()`, `xfs_bmap_del_extent_real()`, and `__xfs_bunmapi()`.

Control flow: Mount setup calls `xfs_bmap_compute_maxlevels()` to size future bmap btrees from extent-count limits and btree fanout. Lookup-only callers use `xfs_bmapi_read()`, which validates the fork, loads btree extents into the in-core extent tree with `xfs_iread_extents()`, scans `xfs_iext` records, synthesizes holes, trims records to the requested range unless `XFS_BMAPI_ENTIRE` is set, and coalesces adjacent returned mappings. Write callers use `xfs_bmapi_write()`, which scans from the requested logical offset, detects holes or delayed allocations, calls `xfs_bmapi_allocate()` for real block allocation, optionally converts unwritten extent state, updates the return map, and finally shrinks btree forks back to extent format when possible. Allocation chooses data versus realtime allocators, applies extent-size and CoW-size hints, tries locality and EOF/stripe alignment, falls back to low-space algorithms, then inserts or merges the new extent through one of the add-extent helpers.

State and persistence: Persistent fork state is the dinode fork format and its extent records or bmap btree root; real btree blocks and freed extents are logged through transactions and deferred free items. In-memory state is the inode fork extent cache (`xfs_iext`), the optional bmbt cursor, delayed allocation counters, inode block counts, transaction block reservations, and quota reservations. Delayed allocation is represented by null startblocks carrying reserved indirect-block counts; real mappings use physical startblocks; holes use `HOLESTARTBLOCK`; caller-visible delayed mappings are normalized to `DELAYSTARTBLOCK`. Functions update `if_nextents`, `i_nblocks`, `i_delayed_blks`, dquot counters, free-block counters, rmap/refcount records, and inode log flags together so the logged dinode and metadata btrees remain synchronized.

Dependencies and integration points: This file integrates with XFS transaction logging, inode locking, the generic XFS btree engine, bmap btree format helpers from `xfs_bmap_btree.c`, allocation groups and realtime groups, filestream allocator policy, reverse mapping (`xfs_rmap_*`), refcount/reflink CoW tracking, quota accounting, deferred operation infrastructure, buffer verification, health marking, iomap conversion, directory/symlink local-to-remote conversion, superblock feature bits, error tags, and tracepoints. It is reached from buffered and direct write paths through iomap, truncation and hole punching through `bunmapi`, fallocate/collapse/insert operations through extent shifting, attribute creation through attr-fork addition, and repair/remap flows through deferred bmap intents.

Risks and test signals: Highest risks are extent tree and btree divergence, wrong `if_nextents` changes after merge/split cases, stale or missing rmap/refcount updates, quota and delayed-indirect reservation leaks, realtime extent alignment mistakes, partial transaction error paths that fail to log dirty inode state, and corruption handling that leaves a cursor positioned on invalid metadata. Test signals should include mapping holes, real extents, unwritten extents, delayed extents, and CoW fork extents; ENOSPC and low-space allocation with btree splits; local-to-extent and extent-to-btree/btree-to-extent format transitions; attr fork addition to local, extent, and btree data forks; realtime files with partial unmaps; reflink remap/unmap without quota or refcount double accounting; collapse/insert range shifting across mergeable and non-mergeable extents; large extent-count inodes; shutdown and error-tag injection; fsync after unwritten conversion; and scrub/repair validation of returned bmap records.

# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap.h

Purpose: Declares the public interface, flags, special values, allocation argument structure, and deferred-intent types for XFS block mapping operations implemented mostly by `xfs_bmap.c`. It is the contract used by inode, iomap, reflink, attribute, truncate, repair, and transaction code to request file-block mapping changes.

Important APIs, types, and functions: Defines `struct xfs_bmalloca` for allocation state, `XFS_BMAP_MAX_NMAP`, `XFS_BMAPI_*` request flags, `DELAYSTARTBLOCK`, `HOLESTARTBLOCK`, `BMAP_*` internal extent-manipulation state bits, `enum xfs_bmap_intent_type`, and `struct xfs_bmap_intent`. Inline helpers include `xfs_bmapi_aflag()`, `xfs_bmapi_whichfork()`, `xfs_bmap_is_real_extent()`, `xfs_bmap_is_written_extent()`, `xfs_valid_startblock()`, and `xfs_bmap_fork_to_state()`. Declared operations cover attribute fork creation, local fork conversion, maxlevel calculation, extent search, read/write mapping, unmapping, delayed/CoW extent deletion, extent shifting and splitting, delalloc conversion, remapping, deferred map/unmap completion, extent validation, btree range query callbacks, and extent-size hint extraction.

Control flow: Callers choose a target fork with `XFS_BMAPI_ATTRFORK` or `XFS_BMAPI_COWFORK`, derive the fork with `xfs_bmapi_whichfork()`, and pass flags to `xfs_bmapi_read()`, `xfs_bmapi_write()`, `xfs_bmapi_remap()`, or `xfs_bunmapi()`. The implementation uses `struct xfs_bmalloca` across allocation, btree cursor, neighbor extent, accounting, and logging stages. Deferred users enqueue `struct xfs_bmap_intent` through `xfs_bmap_map_extent()` or `xfs_bmap_unmap_extent()` and later finish the operation with `xfs_bmap_finish_one()`.

State and persistence: The header itself owns no runtime or persistent state except the exported `xfs_bmap_intent_cache` declaration. Its constants encode state conventions that are persisted indirectly in transactions: special startblock sentinels distinguish holes and delayed allocations, `XFS_BMAPI_REMAP` suppresses normal quota/free/refcount behavior for block ownership transfers, and fork state bits select data, attr, or CoW extent-cache handling.

Dependencies and integration points: Depends on XFS core types such as `xfs_inode`, `xfs_trans`, `xfs_ifork`, `xfs_btree_cur`, and `xfs_bmbt_irec`. The API is consumed throughout XFS by iomap writeback and reads, quota-aware allocation, xattr and directory conversion, truncation and punch-hole paths, reflink remap and CoW completion, deferred operation logging, scrub/repair btree queries, and mount initialization.

Risks and test signals: Risk concentrates in flag combinations and sentinel interpretation. Invalid combinations such as zeroing metadata, remapping with allocation conversion, using CoW fork in btree-only paths, or treating delayed/null startblocks as real can corrupt accounting or metadata. Test public entry points with each fork selector, all meaningful `XFS_BMAPI_*` combinations, sentinel startblocks, deferred bmap intent replay, and extent validation for data, attr, CoW, and realtime files.

# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap_btree.c

Purpose: Implements the XFS block mapping btree (`bmbt`) format and its binding to the generic XFS btree engine. It packs and unpacks extent records, converts inode-root formats, allocates and frees bmbt blocks, verifies bmbt buffers, manages in-core root resizing, initializes btree cursors, commits staged btrees, changes btree owners, computes geometry, and manages the cursor slab cache.

Important APIs, types, and functions: Exports `xfs_bmbt_init_block()`, `xfs_bmdr_to_bmbt()`, `xfs_bmbt_disk_get_all()`, `xfs_bmbt_disk_get_blockcount()`, `xfs_bmbt_disk_get_startoff()`, `xfs_bmbt_disk_set_all()`, `xfs_bmbt_to_bmdr()`, `xfs_bmbt_get_maxrecs()`, `xfs_bmap_broot_realloc()`, `xfs_bmbt_init_cursor()`, `xfs_bmbt_commit_staged_btree()`, `xfs_bmbt_maxrecs()`, `xfs_bmbt_maxlevels_ondisk()`, `xfs_bmdr_maxrecs()`, `xfs_bmbt_change_owner()`, `xfs_bmbt_calc_size()`, `xfs_bmbt_init_cur_cache()`, and `xfs_bmbt_destroy_cur_cache()`. It defines `xfs_bmbt_ops` for the generic btree layer and `xfs_bmbt_buf_ops` for metadata buffer verification.

Control flow: Record conversion routines translate between the compact two-word disk `xfs_bmbt_rec` and unpacked `xfs_bmbt_irec` fields for start offset, start block, block count, and unwritten state. Root conversion routines copy keys and pointers between the on-disk dinode root (`xfs_bmdr_block`) and the in-memory long-format btree root (`xfs_btree_block`). Generic btree operations call the local callbacks to duplicate/update cursors, allocate new one-block bmbt nodes near a start pointer, free bmbt nodes later through deferred frees, compute min/max records, initialize keys from records, compare keys, test ordering, and resize inode roots. Cursor initialization sizes the cursor by fork or staging fork and records inode/fork context; staged commit destroys the old fork, installs the fake fork, logs the correct root or extent fields, and asks the staging layer to commit root metadata.

State and persistence: Persistent state includes bmbt blocks on disk, the dinode btree root, record bit layout, block owners, sibling pointers, CRC-enabled metadata UUIDs, and btree block frees scheduled by transactions. In-memory state includes cursor allocation from `xfs_bmbt_cur_cache`, cursor allocation counts used by bmap accounting, root buffer sizing (`if_broot_bytes`), and staging fake-root state. Allocating a bmbt block increments inode `i_nblocks` and dquot block counts; freeing decrements both and schedules block release, preserving transaction ordering.

Dependencies and integration points: Builds on the generic XFS btree engine (`xfs_btree_ops`, staging cursors, record/key callbacks), allocation and free-extent code, inode fork utilities, transactions, quota accounting, reverse-map owner information, buffer verifiers, CRC helpers, tracepoints, and mount geometry calculated in `xfs_bmap.c`. It is used directly by `xfs_bmap.c` when loading btree-format forks, inserting or deleting extent records, converting fork formats, and rebuilding/committing staged block maps.

Risks and test signals: Key risks are bitfield packing overflows, wrong root pointer offsets when root size changes, incorrect max-record calculations for CRC versus non-CRC formats, owner verification gaps, lost quota/accounting updates for bmbt block allocation or free, low-space btree split behavior, and staged commit losing old fork resources. Test bmbt record pack/unpack boundaries, CRC and non-CRC filesystems, tiny inode fork roots, btree growth and shrink, allocation with `t_highest_agno` and low-space mode, owner changes for fork swaps and recovery, staged rebuild commit, verifier rejection of bad magic/level/numrecs/CRC, and mount-time `xfs_bmbt_maxlevels_ondisk()` sizing.

# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap_btree.h

Purpose: Defines the public bmap-btree geometry helpers and function prototypes shared by `xfs_bmap.c`, inode fork code, repair/staging code, and the bmbt implementation. It codifies how to address records, keys, and pointers in in-memory btree blocks and on-disk dinode roots.

Important APIs, types, and functions: Declares `XFS_BM_MAXLEVELS()`, bmbt record conversion helpers, root conversion helpers, cursor initialization, staged commit, owner change, btree size calculation, cursor cache lifecycle, block initialization, and root reallocation. Inline geometry helpers include `xfs_bmbt_block_len()`, `xfs_bmbt_rec_addr()`, `xfs_bmbt_key_addr()`, `xfs_bmbt_ptr_addr()`, `xfs_bmdr_rec_addr()`, `xfs_bmdr_key_addr()`, `xfs_bmdr_ptr_addr()`, `xfs_bmap_broot_ptr_addr()`, `xfs_bmap_broot_space_calc()`, `xfs_bmap_broot_space()`, `xfs_bmdr_space_calc()`, and `xfs_bmap_bmdr_space()`.

Control flow: Callers use the address helpers after determining block header length and max record count. In-memory bmbt blocks store records immediately after the btree header for leaves; internal roots place keys after the header and pointers after the key array sized by `maxrecs`. On-disk dinode roots use the compact `xfs_bmdr_block` header and parallel key/pointer arrays. Space helpers compute whether a root fits in an inode fork and how much memory to allocate before root conversion or resize.

State and persistence: No standalone mutable state is stored here. The header describes persistent layout constraints for dinode btree roots and in-memory representations that later serialize back to disk. Its size and address calculations must match the disk ABI, CRC block header selection, inode fork capacity, and btree cursor expectations.

Dependencies and integration points: Depends on XFS format types (`xfs_bmdr_block`, `xfs_bmbt_rec`, `xfs_bmbt_key`, `xfs_bmbt_ptr_t`), mount feature checks, and generic btree declarations. It is included by the bmap engine and bmbt implementation, and indirectly supports inode fork logging, btree verification, staged btree rebuilds, and bmapbt owner changes.

Risks and test signals: The most important risk is layout drift: a wrong `sizeof`, header-length choice, pointer offset, or max-record calculation can make roots unreadable or corrupt adjacent fork data. Test with CRC and non-CRC filesystems, data and attr fork root conversion, minimum inode sizes, maximum root record counts, grow/shrink of `if_broot`, endian-safe record conversion through the `.c` implementation, and xfs_db/scrub validation of bmapbt roots.
