# sources/distributed-fs/ceph-client/fs/btrfs/compression.c

Purpose: implements the shared Btrfs compression engine around compressed bios, compressed folio allocation, per-filesystem compression workspaces, inline/extent decompression dispatch, and the sampling heuristic used to decide whether writeback should attempt compression. It is algorithm-neutral glue for zlib, lzo, zstd, and the "heuristic" pseudo-workspace, while algorithm-specific transforms live in the matching compression backends.

Important APIs/types/functions: `btrfs_compress_type2str()` and `btrfs_compress_is_valid_type()` map and validate mount/user strings. `struct compressed_bio` instances are allocated by `alloc_compressed_bio()`, `btrfs_alloc_compressed_write()`, and `btrfs_compress_bio()`, then completed by `end_bbio_compressed_read()` or `end_bbio_compressed_write()`. Read submission is `btrfs_submit_compressed_read()`, encoded-write submission is `btrfs_submit_compressed_write()`, full-bio decompression is `btrfs_decompress_bio()`, inline decompression is `btrfs_decompress()`, and decompressed buffer copying is `btrfs_decompress_buf2page()`. Workspace management is `btrfs_alloc_compress_wsm()`, `btrfs_free_compress_wsm()`, `btrfs_get_workspace()`, `btrfs_put_workspace()`, and zstd-specific manager hooks. The global compressed folio pool is served by `btrfs_alloc_compr_folio()`, `btrfs_free_compr_folio()`, `btrfs_compr_pool_count()`, and `btrfs_compr_pool_scan()`. Heuristic code uses `struct heuristic_ws`, `heuristic_collect_sample()`, `byte_set_size()`, `byte_core_set_size()`, `shannon_entropy()`, `sample_repeated_patterns()`, and `btrfs_compress_heuristic()`.

Control flow: compressed reads arrive as a normal `btrfs_bio` targeting file-cache folios. `btrfs_submit_compressed_read()` looks up the compressed extent map, allocates a separate compressed `compressed_bio`, allocates enough compression folios for the on-disk payload, optionally extends the original bio with speculative readahead pages from the same compressed extent, and submits the compressed bio at the original disk sector. Completion calls `end_bbio_compressed_read()`, which runs `btrfs_decompress_bio()`, copies decompressed bytes into the original bio through the algorithm backend and `btrfs_decompress_buf2page()`, zero-fills any remaining original bio range on success, ends the original bio, and returns compressed folios to the pool. Compressed writeback calls `btrfs_compress_bio()`, allocates a write bio, chooses a clamped compression level, gets the right workspace, invokes the selected algorithm compressor, and returns a `compressed_bio` whose size is the compressed payload. Completion finishes the ordered extent, optionally clears page-cache writeback over the original file range, frees compressed folios, and drops the bio.

State and persistence: persistent process-wide state includes `btrfs_compressed_bioset` and the global `compr_pool` shrinker-backed list of order-0 folios. Per-filesystem state is the `fs_info->compr_wsm[]` array of workspace managers, with one pseudo-manager for the heuristic and algorithm managers for zlib/lzo/zstd. Each `compressed_bio` records the original inode range, compression type, writeback behavior, optional original read bio, embedded `btrfs_bio`, and ordered extent pointer. Compression does not create durable metadata by itself; durable effects happen through ordered extent completion, extent items written elsewhere, file data checksums, and incompat bits set by users of compression such as defrag. The folio pool is deliberately transient and drainable by the shrinker and module exit.

Dependencies and integration: depends on Btrfs bio helpers, extent maps, ordered extents, extent-IO state bits, subpage helpers, filemap/folio APIs, memalloc NOFS handling, PSI memstall accounting, shrinkers, biosets, and zlib/lzo/zstd backend APIs declared in `compression.h`. It integrates with mount/remount compression choices through type/level validation, with inline extent reads through `btrfs_decompress()`, with normal read IO through `btrfs_submit_compressed_read()`, with writeback through `btrfs_compress_bio()`, and with defrag compression through the same type and level validation.

Risks: read readahead for compressed extents is conservative and disabled for current subpage and block-size-greater-than-page-size cases, so behavior differs by sectorsize and folio order. `btrfs_compress_is_valid_type()` accepts strings with a valid prefix, which is intentional for option parsing but risky if reused as exact validation. Workspace acquisition never returns allocation failure and can wait indefinitely, relying on preallocation and bounded compression time; failed initial preallocation is only warned and retried. `heuristic_collect_sample()` assumes pages exist in the mapping and uses `find_get_page()` without local NULL handling, so it depends on callers invoking it only for prepared page-cache ranges. The compressed folio pool caches only order-0 folios and has global thresholds, so memory pressure and large-folio/block-size paths must be tested separately. Completion paths are sensitive to inode lifetime: after ordered extent finish or writeback clearing, comments note the inode may be gone.

Test signals: build with zlib, lzo, and zstd enabled; mount with each compression type and several levels; exercise regular writeback compression, encoded compressed writes through `btrfs_submit_compressed_write()`, inline compressed reads, random reads inside compressed extents, and speculative readahead. Check low-memory paths by forcing workspace allocation failures and shrinker scans, verify no compressed folio leaks after bio errors, and test subpage and block-size-greater-than-page-size configurations where readahead/pooling is disabled. Heuristic signals include highly repetitive data, text-like data, encrypted/random data, sparse/hole-adjacent data, and boundary ranges smaller than the sample interval. Error-injection should cover failed extent-map lookup, failed compressed folio allocation, failed bio add, decompressor errors, and ordered-extent completion with writeback errors.

# sources/distributed-fs/ceph-client/fs/btrfs/compression.h

Purpose: declares the Btrfs compression interface shared by the core filesystem, algorithm backends, read/write IO paths, and defrag. It defines compression size limits, the compressed bio wrapper, workspace manager ABI, compression level metadata, and public entry points for compression, decompression, workspace lifetime, folio caching, and heuristic decisions.

Important APIs/types/functions: constants `BTRFS_MAX_COMPRESSED`, `BTRFS_MAX_COMPRESSED_PAGES`, `BTRFS_COMPRESSION_CHUNK_SIZE`, and `BTRFS_MAX_UNCOMPRESSED` cap on-disk compressed payloads, per-worker input chunks, and in-memory decompressed ranges. `struct compressed_bio` embeds `struct btrfs_bio` and stores the inode offset, uncompressed length, compression type, writeback flag, and original read bio. `struct workspace_manager` tracks idle workspaces, free/total counts, locking, and waiters. `struct btrfs_compress_levels` describes algorithm min/max/default levels. Public functions include init/exit (`btrfs_init_compress()`, `btrfs_exit_compress()`), per-fs workspace allocation/free, type and level helpers, compressed read/write submission, inline decompression, buffer-to-page decompression copy, heuristic evaluation, folio allocation/free, workspace get/put, and backend hooks for zlib/lzo/zstd.

Control flow: callers allocate or receive `compressed_bio` objects through this API, fill algorithm-specific compressed pages, and submit them through Btrfs bio plumbing. Read paths pass an original `btrfs_bio` to `btrfs_submit_compressed_read()`, while write paths call `btrfs_compress_bio()` or `btrfs_alloc_compressed_write()` plus `btrfs_submit_compressed_write()`. Algorithm backends implement the declared `*_compress_bio()`, `*_decompress_bio()`, `*_decompress()`, workspace allocation, and workspace release hooks. `cleanup_compressed_bio()` is the common error cleanup helper for callers that allocated compressed folios but did not submit successfully.

State and persistence: the header exposes the layout of transient in-memory state only. `compressed_bio` persists for one compressed IO and owns the embedded bio plus compressed folio references until completion or cleanup. Workspace managers persist for the mounted filesystem lifetime, not on disk. Constants here influence durable extent layout indirectly by limiting compressed extent sizes to 128 KiB and default zlib level to 3, but no on-disk structures are defined in this header.

Dependencies and integration: includes Linux memory, list, workqueue, waitqueue, pagemap, and size headers plus Btrfs `bio.h`, `fs.h`, and `btrfs_inode.h`. It is consumed by compression backends, read/write file paths, defrag, inline extent readers, and mount-option parsing. It also relies on UAPI/metadata compression type values such as `BTRFS_COMPRESS_ZLIB`, `BTRFS_COMPRESS_LZO`, and `BTRFS_COMPRESS_ZSTD`.

Risks: size-limit constants are part of broad IO behavior, so changing them affects memory pressure, random-read amplification, compressed extent compatibility, and backend assumptions. `cleanup_compressed_bio()` assumes all folios in the embedded bio came from `btrfs_alloc_compr_folio()`. The workspace-manager contract promises forward progress rather than propagating allocation errors, so backend workspace hooks must avoid unbounded or reclaim-unsafe behavior. The `BTRFS_NR_WORKSPACE_MANAGERS` definition maps the heuristic to compression type 0, making enum order significant.

Test signals: compile all compression backend combinations, run compressed read/write tests for zlib/lzo/zstd, validate level parsing and clamping, verify compressed extents never exceed declared limits, and run error cleanup paths under kmemleak or folio leak detection. Header/API changes should be checked by building algorithm backends, defrag, inline extent reads, and encoded write support together.

# sources/distributed-fs/ceph-client/fs/btrfs/ctree.c

Purpose: implements the central Btrfs copy-on-write B-tree engine. It manages path allocation/release, root node references, key comparison and binary search, tree searches over current and historical versions, COW of metadata blocks, node/leaf splitting and balancing, item insertion/extension/truncation/deletion, forward/backward iteration, and initialization of the path slab cache.

Important APIs/types/functions: path lifetime is `btrfs_alloc_path()`, `btrfs_release_path()`, and `btrfs_free_path()`. Root and block access include `btrfs_root_node()`, `btrfs_read_node_slot()`, `btrfs_copy_root()`, `btrfs_block_can_be_shared()`, `btrfs_force_cow_block()`, and `btrfs_cow_block()`. Search and iteration are `btrfs_bin_search()`, `btrfs_search_slot()`, `btrfs_search_old_slot()`, `btrfs_search_slot_for_read()`, `btrfs_search_backwards()`, `btrfs_search_forward()`, `btrfs_find_next_key()`, `btrfs_next_old_leaf()`, `btrfs_next_old_item()`, `btrfs_previous_item()`, and `btrfs_previous_extent_item()`. Mutation helpers include `btrfs_set_item_key_safe()`, `btrfs_extend_item()`, `btrfs_truncate_item()`, `btrfs_split_item()`, `btrfs_duplicate_item()`, `btrfs_insert_empty_items()`, `btrfs_insert_item()`, `btrfs_del_ptr()`, and `btrfs_del_items()`. Internal balancing is handled by `balance_level()`, `push_nodes_for_insert()`, `split_node()`, `push_leaf_left()`, `push_leaf_right()`, `split_leaf()`, and `insert_new_root()`.

Control flow: a normal lookup or mutation starts with `btrfs_search_slot()`. It locks or references the root, walks down by binary-searching keys in each node, reads child blocks with parent checks, optionally performs readahead, and releases upper locks when safe. For mutations, it raises the write-lock level as needed, COWs blocks before modification, splits full nodes/leaves for insertions, and balances underfull nodes/leaves for deletions. If a blocking child read or stronger locking is required, the path is released and the search restarts from the current root. Leaf-level insertion first reserves space during the search, then `setup_items_for_insert()` shifts item headers and data. Deletion compacts leaf data, updates low keys, and may remove an empty or sparse leaf after pushing items to siblings. Historical searches use tree modification logs through `btrfs_search_old_slot()` and old-root/rewind helpers, while commit-root searches can clone the lowest buffer under `commit_root_sem` when the caller cannot pin transaction commits.

State and persistence: durable state is the Btrfs metadata tree itself: extent buffers, root items, node pointers, leaf items, item data offsets, generation fields, backref flags, and root used-byte accounting. In-memory state includes `struct btrfs_path` arrays of nodes/slots/locks, root dirty-list membership, path slab cache `btrfs_path_cachep`, extent-buffer references and locks, tree modification log records, and qgroup relocation traces. COW allocates new tree blocks, copies old contents, updates generations/owners/fsids, updates parent pointers or `root->node` via RCU, marks buffers dirty, adjusts delayed refs/backrefs, frees stale blocks, and records dirty roots for transaction commit. No standalone persistence is added outside the normal transaction system.

Dependencies and integration: integrates with transaction handling, disk IO and extent-buffer cache, tree locking, delayed refs and extent-tree allocation/free, qgroups, relocation, tree checker, tree modification log, file-item helpers, and Btrfs error reporting/tracing. It exposes core APIs declared in `ctree.h` and is used by almost every metadata subsystem: inode items, extent items, checksums, directory items, relocation, logging, send, defrag, and mount/recovery paths. Error injection is explicitly allowed for `btrfs_cow_block()` and `btrfs_search_slot()`.

Risks: this file encodes core B-tree invariants, so slot arithmetic, low-key propagation, and item data offset movement are high-risk. Locking is subtle: searches may restart after dropping locks; slot 0 requires parent key updates; `keep_locks`, `lowest_level`, `skip_locking`, `search_commit_root`, `need_commit_sem`, and `nowait` change lock and lifetime rules. COW correctness depends on transaction identity matching `fs_info->running_transaction` and generation, backref conversion for shared/reloc blocks, qgroup tracing, and tree-mod-log recording before pointer changes. Leaf split/double-split and push-left/right paths manipulate overlapping item headers and data areas; corruption checks catch some sibling key-order problems but many bugs would be structural. Some corruption responses still use `BUG()` after printing tree context, so invalid caller assumptions can panic.

Test signals: run Btrfs xfstests and sanity tests with error injection on `btrfs_cow_block()` and `btrfs_search_slot()`, plus fsck/tree-checker validation after heavy metadata churn. Important workloads are snapshot creation/deletion, relocation/balance, qgroup-enabled writes, log replay, send using old tree versions, directory and xattr insertions with key collisions, checksum item splitting, file extent split/merge/truncate, deletion causing leaf/node underflow, and ENOSPC during splits. Locking tests should cover nowait searches, commit-root searches with concurrent relocation/commit, concurrent insert/delete around slot 0, and stress with small nodesize to force frequent splits and merges.

# sources/distributed-fs/ceph-client/fs/btrfs/ctree.h

Purpose: defines the in-memory Btrfs tree/path/root interface and declares the core B-tree operations implemented by `ctree.c`. It is a central private filesystem header for navigating and mutating Btrfs metadata trees.

Important APIs/types/functions: `enum` values `READA_NONE`, `READA_BACK`, `READA_FORWARD`, and `READA_FORWARD_ALWAYS` configure tree-search readahead. `struct btrfs_path` records extent buffers, slots, lock modes, readahead mode, lowest search level, and behavior flags such as split search, lock retention, commit-root search, no-wait search, and extension insertion. `BTRFS_PATH_AUTO_FREE` and `BTRFS_PATH_AUTO_RELEASE` provide scoped cleanup wrappers. `enum` root state bits include transaction setup, shareability, dirty tracking, orphan/log/drop/qgroup/swapfile/relocation state, defrag running, force COW, and deletion. `struct btrfs_root` is the large root state container holding root/commit/log/reloc nodes, root item/key, dirty lists, inode and delayed-node xarrays, delalloc/ordered extent tracking, logging state, qgroup reservations, relocation state, swapfile count, and synchronization primitives. The header also declares `struct btrfs_replace_extent_info`, `struct btrfs_drop_extents_args`, `struct btrfs_file_private`, item batch insertion support, key comparison/search APIs, COW APIs, item mutation APIs, and iteration helpers.

Control flow: users allocate or stack-initialize a `btrfs_path`, call search helpers to position it at a tree slot, inspect or mutate the leaf/node, then release the path. Mutating callers pass a transaction and request COW through `btrfs_search_slot()` or explicit COW helpers. Insertion callers can use `btrfs_item_batch` and `btrfs_insert_empty_items()` for one or more sorted items, while deletion callers use `btrfs_del_items()` or `btrfs_del_item()`. Iteration uses `btrfs_next_item()`, `btrfs_next_leaf()`, `btrfs_for_each_slot()`, and backward search helpers. Inline root helpers provide READ_ONCE/WRITE_ONCE access to log and transaction fields that are sometimes observed without their primary mutex.

State and persistence: the header describes long-lived in-memory root state that mirrors durable root items and metadata trees. `struct btrfs_root` fields such as `root_item`, `root_key`, `node`, `commit_root`, `defrag_progress`, `defrag_max`, dirty-list membership, log state, delalloc lists, ordered extents, and qgroup reservations persist for the lifetime of the root object and are flushed or reconciled by transaction code. `struct btrfs_path` is transient and owns references/locks only while a caller navigates a tree. Inline size helpers derive leaf/item capacity from `fs_info->nodesize`, which affects durable tree layout.

Dependencies and integration: includes Btrfs locking and accessor headers plus Linux spinlock, rb-tree, mutex, waitqueue, list, atomic, xarray, and refcount primitives. It depends on UAPI tree constants from `uapi/linux/btrfs_tree.h`. It is included throughout Btrfs code, including transaction, extent tree, inode, file-item, relocation, logging, send, qgroup, compression-adjacent defrag, and disk-IO paths.

Risks: `struct btrfs_root` is broad shared state with many fields protected by different locks, atomics, or transaction rules; adding fields or changing accessors requires clear locking ownership. Root state bits have semantic conflicts, for example shareable roots versus dirty tracking, and are consumed by COW, balance, relocation, and transaction code. Path flags drastically affect search locking and lifetime semantics, so callers must initialize them deliberately and release paths on every exit. `btrfs_item_batch` requires sorted keys and correct total size; the tree code assumes these preconditions. Size macros derive capacities from nodesize and item structures, so structure layout changes can alter metadata limits.

Test signals: compile all Btrfs configurations, especially sanity-test builds, and exercise metadata-heavy xfstests. API-level checks should cover scoped path cleanup, commit-root searches, nowait read paths, batch insertion, item split/duplicate/truncate/extend, root dirty tracking, shareable/non-shareable roots, and defrag progress fields. Static review should verify new users of `struct btrfs_path` set `lowest_level`, `keep_locks`, `skip_locking`, `need_commit_sem`, and `skip_release_on_error` consistently with the lock contract.

# sources/distributed-fs/ceph-client/fs/btrfs/defrag.c

Purpose: implements Btrfs automatic inode defragmentation, explicit file defragmentation, and metadata tree leaf reallocation. File defrag identifies fragmented or compression-target file extents, prepares page-cache folios, marks selected ranges delalloc/defrag so writeback rewrites them, and optionally forces compression or no-compression. Root defrag COWs metadata leaves so logical key order is closer to disk order.

Important APIs/types/functions: auto-defrag uses `struct inode_defrag`, `btrfs_add_inode_defrag()`, `btrfs_pick_defrag_inode()`, `btrfs_cleanup_defrag_inodes()`, `btrfs_run_defrag_inode()`, and `btrfs_run_defrag_inodes()`. Metadata defrag uses `close_blocks()`, `btrfs_realloc_node()`, `btrfs_defrag_leaves()`, and `btrfs_defrag_root()`. File extent discovery uses `defrag_get_extent()`, `defrag_lookup_extent()`, `defrag_check_next_extent()`, and `defrag_collect_targets()`. Page and range preparation use `defrag_prepare_one_folio()`, `struct defrag_target_range`, `defrag_one_locked_target()`, `defrag_one_range()`, and `defrag_one_cluster()`. Public lifecycle is `btrfs_auto_defrag_init()` and `btrfs_auto_defrag_exit()`, and the main file entry point is `btrfs_defrag_file()`.

Control flow: auto-defrag callers enqueue an inode in an rbtree keyed by root objectid and inode number when the mount option is enabled and the filesystem is not closing. The worker loops through queued records, gets the root and inode, clears the runtime in-defrag bit, builds a full-range defrag request with an extent threshold, and invokes `btrfs_defrag_file()` in batches of `BTRFS_DEFRAG_BATCH` sectors under `super_write`. File defrag validates range and compression options, aligns to sectorsize, processes 256 KiB clusters, locks the inode, rejects swapfiles/inactive superblocks, sets temporary defrag compression fields, collects target extents, reads/prepares folios, locks extent state, recollects targets under the lock, reserves delalloc space, marks selected ranges `EXTENT_DELALLOC | EXTENT_DEFRAG`, dirties folios, and lets writeback create replacement extents. Metadata root defrag repeatedly starts transactions, searches forward through shareable roots, COWs level-1 children that are not physically near siblings, records progress in `root->defrag_progress`, and repeats on `-EAGAIN` until done, closing, or cancelled.

State and persistence: auto-defrag state lives in `fs_info->defrag_inodes`, `fs_info->defrag_inodes_lock`, `fs_info->defrag_running`, per-inode `BTRFS_INODE_IN_DEFRAG`, and `struct inode_defrag` records containing root, ino, transid, and extent threshold. File defrag persists its effect by converting existing extents into dirty delalloc ranges that later writeback persists as new file extent items and data extents; it also updates `range->start` for resumable batched operation. Temporary compression state is stored in `inode->defrag_compress` and `inode->defrag_compress_level` and reset after the run. Metadata defrag persists by COWing tree blocks inside transactions and updating root progress/max keys until complete. The inode-defrag slab cache persists from init to exit.

Dependencies and integration: depends on `ctree.c` search/COW APIs, transaction start/end, disk-IO/root lookup, extent maps, file extent item conversion, extent state locking, ordered extents, page-cache read/writeback, delalloc reservation, dirty throttling, subpage folio helpers, compression type/level validation, superblock write guards, mount options, and Btrfs cancellation through pending signals. It integrates with ioctl defrag arguments, autodefrag mount behavior, writeback, compression incompat feature bits for lzo/zstd, and transaction wait queues during unmount.

Risks: defrag races with writeback, hole punching, delalloc, ordered extents, eviction, remount, unmount, and transaction commits; much of the code revalidates after locking to avoid stale extent decisions. `defrag_lookup_extent()` suppresses errors from `defrag_get_extent()` by returning NULL for `ERR_PTR`, which can make metadata lookup failures look like "no target" to upper logic. Target selection for non-compress defrag depends on the next extent being mergeable and below thresholds; wrong thresholds can add IO without reducing extent count. `defrag_prepare_one_folio()` rejects large folios unless experimental support is enabled, so behavior differs with read-only THP for files. Metadata defrag only handles shareable roots and uses progress keys across transactions; cancellation returns `-EAGAIN`, so callers must distinguish pause from fatal failure. Compression flag handling has both legacy `compress_type` and newer typed level fields, and incompat bits are set from `range->compress_type`, so level-style requests need careful coverage.

Test signals: run ioctl defrag and autodefrag xfstests over fragmented files, compressed files, inline extents, holes, prealloc extents, delalloc-adjacent ranges, and files with concurrent writes/hole punching. Verify range alignment, `range->start` resume behavior, max-sector batching, cancellation by signal, swapfile rejection, inactive superblock handling, and immediate writeback with `BTRFS_DEFRAG_RANGE_START_IO`. Compression tests should cover zlib/lzo/zstd, explicit levels, no-compress, invalid types/levels, and resulting incompat feature bits. Metadata defrag tests should use snapshot/shareable roots, small nodesize, relocation/qgroup-enabled filesystems, remount/unmount interruption, and validation that tree-checker/fsck sees correct key order and references after repeated COW reallocation.

# sources/distributed-fs/ceph-client/fs/btrfs/defrag.h

Purpose: declares the Btrfs defragmentation interface for file defrag, automatic inode defrag queueing/running, root metadata defrag, cleanup, and init/exit of the autodefrag slab cache. It is a small private header connecting ioctl/writeback/autodefrag callers to `defrag.c`.

Important APIs/types/functions: `btrfs_defrag_file()` is the public file-range defrag entry point taking a `btrfs_inode`, readahead state, ioctl range args, minimum generation, and optional maximum sectors. `btrfs_add_inode_defrag()` queues an inode for autodefrag with an extent-size threshold. `btrfs_run_defrag_inodes()` drains queued auto-defrag records for a filesystem. `btrfs_cleanup_defrag_inodes()` frees pending records, typically during teardown. `btrfs_defrag_root()` defragments metadata leaves for a root. `btrfs_auto_defrag_init()` and `btrfs_auto_defrag_exit()` manage the inode-defrag cache. `btrfs_defrag_cancelled()` currently maps cancellation to `signal_pending(current)`.

Control flow: higher layers call `btrfs_add_inode_defrag()` when write patterns indicate fragmentation and autodefrag is enabled. Worker or transaction contexts call `btrfs_run_defrag_inodes()` to process the queue. User ioctl paths call `btrfs_defrag_file()` directly with range/compression flags. Metadata maintenance can call `btrfs_defrag_root()` for root leaf reallocation. Long loops periodically call `btrfs_defrag_cancelled()` to stop on pending signals.

State and persistence: this header owns no state. It exposes functions that operate on `fs_info` defrag queues, inode runtime flags, root defrag progress fields, dirty page-cache/delalloc state, and transaction-persisted metadata COW. The cancellation helper does not store cancellation state and currently ignores its `fs_info` argument.

Dependencies and integration: includes Linux types/compiler annotations and forward-declares file readahead, Btrfs inode/root/fs/trans types, and ioctl defrag range args. It is included by code that needs to schedule or execute Btrfs defrag without depending on the full implementation details.

Risks: the cancellation policy is minimal and signal-based only; future filesystem-wide cancellation would require changing `btrfs_defrag_cancelled()` semantics. Callers must provide a valid `file_ra_state` to `btrfs_defrag_file()` and must understand that non-negative returns are sector counts, not just boolean success. Because many structs are forward-declared, compile errors will only appear in C files that dereference fields without including fuller headers.

Test signals: compile all autodefrag/ioctl/root-defrag users, verify init/exit ordering around mount/unmount/module teardown, and run cancellation tests that deliver signals during long file and root defrag loops. API behavior checks should verify `btrfs_defrag_file()` return values, `range->start` updates, and queue cleanup on unmount.
