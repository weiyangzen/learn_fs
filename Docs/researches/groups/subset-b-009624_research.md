# sources/user-network-fs/impacket/impacket/examples/secretsdump.py

Purpose: `secretsdump.py` is Impacket's reusable implementation for extracting Windows credential material from local registry hives, remote registry hives, NTDS.dit, DRSUAPI replication calls, and RODC key-list requests. It supports SAM hashes, cached domain logons, LSA secrets, DPAPI machine/user keys, service/default-password secrets, machine-account Kerberos keys, NTDS NTLM hashes, NTDS Kerberos keys, cleartext supplemental credentials, password history, optional SAM hash editing, and resumable domain dumping. The module is library-like despite living under `examples`: other tools import these classes and provide callbacks, output names, SMB/LDAP connections, and execution-mode choices.

Important APIs, types, and functions: Registry and binary layout types are modeled as `Structure` subclasses such as `SAM_KEY_DATA`, `SAM_HASH`, `SAM_KEY_DATA_AES`, `SAM_HASH_AES`, `DOMAIN_ACCOUNT_F`, `DOMAIN_ACCOUNT_V`, `USER_ACCOUNT_F`, `USER_ACCOUNT_V`, `BUILTIN_GROUP_C`, `NL_RECORD`, `SAMR_RPC_SID`, `LSA_SECRET_BLOB`, `LSA_SECRET`, and `LSA_SECRET_XP`. `openFile()` centralizes UTF-8 output file creation and optional custom open callbacks. `RemoteFile` wraps a remote `ADMIN$` temp file as a seek/read/close object and deletes the remote file on close. `RemoteOperations` owns remote RPC/SMB/DCOM operations: service control, Remote Registry enable/restore, hive saving, boot key extraction, SAMR/DRSUAPI binding, domain user enumeration, LDAP-filtered user enumeration, VSS snapshot copy, WMI shadow-copy download, and command execution through `smbexec`, `wmiexec`, or `mmcexec`. `CryptoCommon` provides RID-derived DES keys and AES-CBC helpers. `OfflineRegistry` adapts Impacket registry hive parsers. `SAMHashes` decrypts local SAM hashes, statuses, local admin membership, password-last-set data, AES-protected history, and can `edit()` a user's hash in a hive. `LSASecrets` decrypts cached logons and LSA secrets and classifies callback events with `SECRET_TYPE`. `ResumeSessionMgrInFile` persists DRSUAPI resume SIDs. `NTDSHashes` handles both offline/VSS ESENT parsing and online DRSUAPI replication, including PEK decryption, per-account hash decryption, supplemental Kerberos and cleartext extraction, skip/user/LDAP filters, and output splitting. `LocalOperations` extracts boot key and NoLMHash policy from local SYSTEM hives. `KeyListSecrets` implements the RODC `KERB-KEY-LIST` flow.

Control flow: Remote dumping first builds a `RemoteOperations` around an authenticated `SMBConnection`, calls `enableRegistry()` when registry hive extraction is needed, obtains the boot key from the SYSTEM LSA class values, saves SAM/SECURITY hives via `BaseRegSaveKey`, and optionally locates/copies NTDS.dit through VSS. Remote service state is checked before starting Remote Registry; disabled/stopped services are restored by `finish()`. SAM processing calls `getHBootKey()`, enumerates `SAM\Domains\Account\Users`, decodes user metadata and group membership, decrypts LM/NT hashes using RC4 or AES plus RID DES layers, emits optional history/status/password-age fields, and stores exportable lines. LSA processing obtains the LSA key from `PolEKList` or `PolSecretEncryptionKey`, decrypts `NL$KM`, then iterates cache records and policy secrets. NTDS VSS parsing opens the ESENT datatable, searches for `pekList`, decrypts PEKs, queues account rows found before the PEK, then decrypts hashes and supplemental credentials row-by-row. NTDS DRSUAPI mode binds DRS, enumerates users through SAMR or LDAP filters, uses SID lookups with GUID fallback, decrypts replicated attributes through `drsuapi.DecryptAttributeValue`, writes the current SID to a resume file after each user, and clears the resume file after successful full traversal. `KeyListSecrets.dump()` enumerates users allowed for RODC replication, creates partial TGTs encrypted with the RODC key, requests a full TGT with key-list padata, and prints returned keys.

State and persistence behavior: The module intentionally touches remote state. It can start Remote Registry, change a disabled service to demand-start, create temporary services, create and delete VSS snapshots, save registry hives and NTDS copies under `%SYSTEMROOT%\Temp`, write command output to `Temp\__output`, download files to local paths, and delete remote temp files on `RemoteFile.close()`. Cleanup is best-effort and split across `RemoteOperations.__restore()`, `finish()`, `RemoteFile.close()`, VSS deletion, and exception handlers. Local persistent outputs include `.sam`, `.secrets`, `.cached`, `.ntds`, `.ntds.kerberos`, `.ntds.cleartext`, and `sessionresume_*` files. `SAMHashes.edit()` mutates a local SAM hive via `setValue()`. Long-running DRSUAPI dumps persist progress by SID so interrupted runs can resume. Internal collections such as `__itemsFound`, `__historyItems`, `__cachedItems`, `__secretItems`, `__kerberosKeys`, `__clearTextPwds`, `__tmpUsers`, and `__PEK` buffer export and ordered callback output.

Dependencies and integration points: This file is tightly coupled to Impacket's SMB, DCERPC, DCOM/WMI, registry, ESENT, NTLM, DPAPI, Kerberos, LDAP, SAMR, RRP, SCMR, WKST, EPM, DRSUAPI, ASN.1, and crypto layers. It requires `pycryptodomex` and `pyasn1` for real operation. Callers supply authenticated `SMBConnection` objects, optional LDAP connections, callbacks for per-secret output, and options such as Kerberos, KDC host, VSS method, WMI snapshot method, `justUser`, `skipUser`, LDAP filter, history, status, and output base names. The module integrates with command-line wrappers but also acts as a service library for other Impacket examples.

Risks: This code handles highly sensitive secret material and logs or writes it through callbacks and output files. Remote cleanup is fragile under connection loss, permission failures, localization changes in `vssadmin` output, service-control errors, or process interruption, so services, snapshots, temp files, or output files can remain. Broad `except` blocks intentionally continue through partial failures but can hide cleanup or parsing defects. DRSUAPI and ESENT attribute parsing depends on Windows-version-specific layouts, PEK header formats, prefix-table mappings, and SID normalization quirks. Some operations require high privileges and can trigger endpoint security controls. AES history extraction uses heuristic scanning fallback paths, which may miss or misclassify unusual SAM history blobs. `RemoteFile.close()` deletes its remote file as a side effect, so consumers must not assume it is a passive file handle.

Test signals: Useful coverage should include offline fixture hives for SAM RC4 and AES boot-key paths, empty hashes, disabled/locked/admin status, password history, SAM edit round trips, LSA cached credentials, DPAPI_SYSTEM, machine-account Kerberos key salt in remote and offline modes, SECURITY question secrets, and NTDS PEK/hash/supplemental parsing for old and AES formats. Remote/integration tests should mock or exercise RRP, SCMR, SAMR, DRSUAPI, LDAP paging, VSS command output, WMI shadow copies, and cleanup after exceptions. Resume tests should verify SID persistence, append-mode output, and `clearResumeData()` after successful traversal. Callback tests should assert `SECRET_TYPE` values and output file suffixes.

# sources/user-network-fs/impacket/impacket/examples/serviceinstall.py

Purpose: `serviceinstall.py` provides `ServiceInstall`, a helper used by remote execution examples such as psexec-style flows and relay tooling. Given an established SMB session and an executable or file-like object, it finds a writable share, uploads a service binary, creates and starts a Windows service that points at that binary, and later removes the service and uploaded file.

Important APIs, types, and functions: `ServiceInstall.__init__()` normalizes an existing `smb.SMB`/`smb3.SMB3` object into `SMBConnection`, chooses random service and binary names unless supplied, and stores the executable source. `serviceName`, `binaryServiceName`, and `getShare()` expose installation details to callers. `getShares()` binds `srvsvc` over SMB transport and calls `NetrShareEnum`. `findWritableShare()` probes disk and special shares by connecting trees and attempting a directory open with `FILE_WRITE_DATA`. `copy_file()` uploads either a path or file-like object via `putFile`. `openSvcManager()` binds `svcctl` and opens the SCM. `createService()` deletes any pre-existing service with the chosen name and calls `hRCreateServiceW`. `install()` orchestrates share discovery, upload, SCM open, service creation, service start, and error cleanup. `uninstall()` reopens the service, stops it, deletes it, closes handles, and removes the uploaded binary.

Control flow: Installation refuses guest sessions, enumerates shares, selects the first writable candidate, uploads the binary to the share root, opens the SCM, builds the service binary path as `%systemroot%\binary.exe` for `ADMIN$` or as a UNC path for other shares, creates the service, starts it, closes service/SCM handles, and returns `True`. On any exception after partial progress, it tries to stop the service, delete the uploaded file, and delete the service before returning `False`. Uninstall follows the reverse path: open SCM, open service by stored name, stop, delete, close handles, then delete the uploaded file from the stored share.

State and persistence behavior: The helper modifies remote SMB shares and the remote Service Control Manager. Its main persistent artifacts are the uploaded executable and created service; both are intended to be temporary. The instance persists `share`, generated names, RPC transport, `rpcsvc`, and the normalized SMB connection. Cleanup is best-effort and depends on the same session remaining usable. `copy_file()` closes caller-supplied file-like objects after upload, which is a meaningful ownership side effect.

Dependencies and integration points: The module depends on Impacket SMB/SMB3, `SMBConnection`, DCERPC `transport`, `srvsvc`, `scmr`, and SMB3 access constants. It expects the caller to have already authenticated and to provide credentials with enough share-write and service-control rights. It is designed to be imported by higher-level remote execution examples that need a temporary service launcher.

Risks: The code catches broad exceptions and may leave remote services or files if cleanup also fails. `install()` references `service` in exception cleanup even if service creation failed before assignment, though the cleanup call is guarded by broad `except`. Writable-share probing logs critical messages for expected non-writable shares, which can be noisy. Random service names are short enough that collisions are unlikely but not impossible. Upload path handling places the binary at the share root and assumes the SCM can resolve the selected `%systemroot%` or UNC path. Guest sessions delete the connection object after logoff, which may surprise callers retaining the instance.

Test signals: Tests should mock `SMBConnection`, `srvsvc`, and `scmr` to cover guest refusal, share enumeration failure, no writable share, successful ADMIN$ path construction, non-ADMIN$ UNC construction with and without server name, existing-service deletion, upload failure cleanup, start-service failure tolerance, and uninstall idempotence. Integration tests need a controlled Windows target or SMB/SCMR simulator because correctness depends on remote access rights and service handle lifecycle.

# sources/user-network-fs/impacket/impacket/examples/smbclient.py

Purpose: `smbclient.py` implements `MiniImpacketShell`, an interactive or socket-backed command shell over an Impacket `SMBConnection`. It exposes SMB session management, share browsing, file transfer, recursive download/listing, local shell commands, server/session information via SRVSVC/SAMR, shadow snapshot listing, mount point operations, and file ACL display/modification.

Important APIs, types, and functions: `MiniImpacketShell.__init__()` configures `cmd.Cmd` input/output, redirects stdio for `tcpShell`, stores SMB credentials, tracks current share/tree/path, and optionally logs command output to a file. Command methods include `do_open`, `do_reconnect`, `do_login`, `do_kerberos_login`, `do_login_hash`, `do_logoff`, `do_password`, `do_info`, `do_who`, `do_shares`, `do_use`, `do_cd`, `do_lcd`, `do_pwd`, `do_ls`, `do_lls`, `do_tree`, `do_rm`, `do_mkdir`, `do_rmdir`, `do_put`, `do_mget`, `do_rget`, `do_get`, `do_cat`, `do_list_snapshots`, `do_mount`, `do_umount`, `do_acl`, and `do_exit`/`do_EOF`. `complete_get()` and `complete_cd()` reuse the cached directory listing for tab completion. `_resolve_share_type()` renders SRVSVC share type flags. `do_listFiles()` is a recursive-listing helper for `do_tree()`.

Control flow: The shell starts from an existing SMB client and marks itself logged in. `open` replaces the connection and resets share/path/login state. Login commands authenticate with password, Kerberos, or LM/NT hashes and update stored credentials. `use` connects to a share and initializes `pwd` to root. Directory navigation normalizes Windows-style paths and verifies directories by opening them with directory/list access. Listing fills `self.completion`; subsequent completion and multi-get commands consume that state. File transfer commands build remote paths relative to `pwd`, use `putFile` or `getFileEx`, and write local files using basename or a preserved relative tree for `rget`. RPC-backed commands create SMB transports to `srvsvc` or `samr`. ACL commands instantiate `SMBFileACL`, either read permissions or grant/revoke requested rights, and always close the ACL helper connection in `finally`.

State and persistence behavior: The shell mutates remote state through uploads, deletes, directory creation/removal, mount point creation/removal, password changes, and ACL changes. It mutates local state by changing the process working directory (`lcd`), running local shell commands (`shell`), writing downloaded files/directories, appending command traces and selected output to `outputfile`, and globally redirecting `sys.stdin/stdout/stderr` when socket-backed. It keeps session state in `self.smb`, `tid`, `share`, `pwd`, `loggedIn`, credentials, `completion`, and `last_output`. Error paths in downloads remove partial files for `get`, `mget`, and `rget`.

Dependencies and integration points: The module depends on Python `cmd`, `os`, `ntpath`, `BytesIO`, `charset_normalizer`, Impacket `SMBConnection`, SMB dialect constants, `SessionError`, SMB access/share constants, DCERPC `samr`, `srvsvc`, `transport`, `NULL`, and `SMBFileACL`. It is intended for Impacket command-line examples and for `ntlmrelayx` interactive sockets through `tcpShell`.

Risks: Commands do limited argument validation; for example empty `cd`, `mount`, or `list_snapshots` inputs can leave local variables undefined or index empty strings. `do_shell()` executes arbitrary local commands. `lcd` changes global process state. Socket mode rewires global stdio, which can affect embedding applications. Recursive tree walking appends to the list it is iterating and catches broad exceptions, so large or cyclic namespace structures can be slow or incomplete. Local output filenames use basenames and can overwrite existing files. The ACL and mount commands require privileges and can make significant remote changes. Output logging opens files repeatedly and may mix command traces with data-oriented rows.

Test signals: Unit tests can mock `SMBConnection` to verify state resets, path normalization, dialect logging, share type rendering, login modes, completion behavior, partial-download cleanup, recursive `rget` directory creation, and ACL close-on-error. Integration tests should cover SMBv1/SMB2/SMB3 dialects, authenticated and guest sessions, share enumeration, snapshot listing, password change failure modes, mount/umount privilege failures, and outputfile formatting for `shares`, `pwd`, `ls`, and `cat`.

# sources/user-network-fs/impacket/impacket/examples/utils.py

Purpose: `utils.py` collects shared helpers for Impacket example scripts: target and credential parsing, identity prompting/hash handling, LDAP session creation, Impacket LDAP login fallback, Kerberos-over-ldap3 SASL bind construction, SMB-derived machine-name discovery, and IPv4/IPv6 socket helpers.

Important APIs, types, and functions: `parse_target()` parses `[domain/]username[:password]@host` and preserves `@` inside passwords by reparsing the remote-name tail. `parse_credentials()` parses `[domain/]username[:password]`. `_get_machine_name()` anonymously connects to SMB to read NetBIOS or FQDN server identity and provides a specific error when NTLM is likely disabled. `ldap3_kerberos_login()` obtains or reuses TGT/TGS material, builds SPNEGO `NegTokenInit` with a Kerberos AP-REQ, sends an ldap3 SASL bind, and marks the connection bound. `_init_ldap_connection()` chooses ldap3 NTLM, NTLM-with-hashes, or Kerberos login. `init_ldap_session()` resolves the target DC name/IP/host depending on Kerberos and LDAPS flags. `ldap_login()` uses Impacket's LDAP client, chooses ldap/ldaps URL, performs NTLM or Kerberos auth, retries with LDAPS on `strongerAuthRequired`, and emits targeted logging for NTLM negotiation or KDC host/IP mismatches. `parse_identity()` combines credential parsing, optional password prompt, hashes, AES key, and Kerberos flag. `get_address()` builds IPv4 or IPv6 socket address tuples including scoped IPv6 handling. `get_connected_socket()` connects and returns a socket.

Control flow: Parsing helpers are pure regex wrappers except for password-tail repair in `parse_target()`. LDAP setup first resolves the target host; Kerberos paths prefer `dc_host`, then `_get_machine_name(dc_ip)`, then `_get_machine_name(domain)`, while NTLM paths connect to `dc_ip` or domain directly. The ldap3 Kerberos bind optionally reads ccache entries, gets missing TGT/TGS values, decodes the TGS, creates an authenticator encrypted with key usage 11, wraps it in SPNEGO, and posts a bind request. `ldap_login()` performs an Impacket LDAP bind, catches LDAP session errors, retries with SSL only for stronger-auth-required, and re-raises other failures after logging. Socket helpers compute address-family-specific tuples and perform a blocking connect.

State and persistence behavior: Most helpers are stateless. Side effects include interactive password prompting, network connections to SMB/LDAP/KDC/socket endpoints, LDAP connection bind state changes, and environment-dependent ccache use through `CCache.parseFile()`. `get_connected_socket()` returns an open connected socket that the caller must close. No files are written by this module.

Dependencies and integration points: The module depends on `re`, `ssl`, `socket`, `ldap3`, Impacket `SMBConnection`, `SessionError`, SPNEGO helpers, Impacket LDAP, Kerberos ccache/asn1/crypto functions, and optional `getpass`. It is used by many example scripts as a common parser and authentication bootstrap, especially scripts that support `-k`, `-aesKey`, `-hashes`, `-dc-ip`, `-dc-host`, and LDAPS modes.

Risks: Regex parsing is permissive and returns empty strings for many malformed inputs, leaving validation to callers. `_get_machine_name()` relies on anonymous SMB behavior that may be blocked. `ldap3_kerberos_login()` has a complex hand-built AP-REQ path where time, ccache, SPN, realm, and key usage mismatches surface as late bind failures. `parse_identity()` uses `hashes.split(':')` without validating component count. `ldap_login()` only retries stronger-auth failures with LDAPS and otherwise depends on string matching in exception text. IPv6 scope parsing can raise if an interface name is unknown. Socket connects are blocking and have no timeout at this layer.

Test signals: Tests should cover target parsing with passwords containing `@`, empty credentials, hash parsing with missing LM hash, AES key forcing Kerberos mode, no-pass behavior, IPv6 scope IDs and interface names, and LDAPS fallback on mocked `strongerAuthRequired`. Kerberos LDAP tests need mocks around ccache, TGT/TGS acquisition, ASN.1 encoding, and ldap3 bind responses to verify success and nonzero-result failure handling.

# sources/user-network-fs/impacket/impacket/helper.py

Purpose: `helper.py` provides a small metaclass-based framework for defining protocol packet fields on top of `impacket.ImpactPacket.ProtocolPacket`. Packet classes can declare field descriptors in the class body and automatically receive getters, setters, properties, field tracking, and a useful representation.

Important APIs, types, and functions: `rebind()` wraps descriptor getter/setter methods so generated methods can receive custom names and docs. `Field` is the base descriptor factory; `Field.__call__()` injects `get_<field>`, `set_<field>`, and a property into the class namespace. `Bit` reads/writes one bit in a header byte. `Byte` reads/writes a byte. `Word` reads/writes a 16-bit value with configurable byte order. `Long` reads/writes a 32-bit value with configurable byte order. `ThreeBytesBigEndian` reads/writes a 24-bit big-endian field through a padded 32-bit operation. `ProtocolPacketMetaklass` scans class attributes for `Field` instances, applies them, records sorted `_fields`, and injects `_fields_repr()` and `__repr__()`. `ProtocolPacket` is the metaclass-enabled base that initializes the parent `ProtocolPacket` with subclass-provided `header_size` and `tail_size`, then optionally loads a packet buffer.

Control flow: At class creation time, `ProtocolPacketMetaklass.__new__()` copies the class dictionary, ensures `object` is among bases for old Python compatibility, finds every `Field`, asks each field to bind generated accessors/properties, sorts the field names, and creates repr helpers. At instance creation time, subclasses of `ProtocolPacket` allocate the underlying ImpactPacket header/tail, then parse an optional buffer. Runtime field access goes through the generated property, which delegates to `o.header.get_*` or `o.header.set_*` methods.

State and persistence behavior: The module has no durable persistence. It mutates class dictionaries during metaclass construction and mutates packet header bytes when generated setters are used. Instance state lives in the underlying ImpactPacket header, tail, and child packet chain.

Dependencies and integration points: It depends on `struct`, `functools`, `six.add_metaclass`, and `impacket.ImpactPacket` helper methods such as `get_byte`, `set_byte`, `get_word`, `set_word`, `get_long`, `set_long`, `get_bytes`, `array_tobytes`, `load_packet`, and `child()`. It is intended for older Impacket packet definitions that prefer declarative field descriptors over manual getter/setter boilerplate.

Risks: `rebind()` calls `functools.wraps(f)` without applying the returned decorator, so wrapper metadata preservation is ineffective apart from manual `__name__`/`__doc__` assignment later. `ProtocolPacketMetaklass` modifies `bases` by appending `object`, which is unusual in modern Python and can interact poorly with complex inheritance. `ThreeBytesBigEndian.setter()` uses masking and shifted writes that should be tested carefully for adjacent-byte preservation. Field descriptors are replaced by generated properties, so code expecting descriptor objects after class creation will not find them. The framework assumes subclasses define valid `header_size` and `tail_size`.

Test signals: Tests should define small packet subclasses with each field type, verify generated methods and properties, check byte-order behavior, confirm `_fields` sorting and `repr` output, and round-trip `ThreeBytesBigEndian` values without corrupting neighboring bits. Buffer-load tests should confirm `ProtocolPacket.__init__()` delegates to ImpactPacket parsing correctly.
