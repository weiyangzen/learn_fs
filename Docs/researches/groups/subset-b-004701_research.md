# sources/distributed-fs/ceph-client/drivers/net/tun.c

Purpose: Implements the Linux universal TUN/TAP driver. It exposes `/dev/net/tun` as a misc character device, creates TUN point-to-point or TAP Ethernet netdevices through `TUNSETIFF`, and bridges packet movement between userspace file descriptors, kernel netdevice TX/RX, socket-like operations, XDP, BPF steering/filtering, NAPI, and virtio-net header offload metadata.

Important APIs, types, and functions: `struct tun_file` represents one open file/queue and owns the synthetic socket, `ptr_ring tx_ring`, NAPI state, queue index, XDP RX queue info, and detached-queue state. `struct tun_struct` is the netdevice private state with queue array, flags, owner/group, vnet header size, offload feature mask, TAP filter, classic socket filter state, flow table, disabled queue list, XDP program, eBPF steering/filter programs, ethtool settings, and security blob. Major entry points are `tun_chr_open()`, `tun_chr_close()`, `tun_chr_read_iter()`, `tun_chr_write_iter()`, `__tun_chr_ioctl()`, `tun_set_iff()`, `tun_attach()`, `__tun_detach()`, `tun_net_xmit()`, `tun_get_user()`, `tun_put_user()`, `tun_sendmsg()`, and `tun_recvmsg()`. Exported integration helpers are `tun_get_socket()` and `tun_get_tx_ring()`.

Control flow: Userspace opens `/dev/net/tun`, then `TUNSETIFF` either attaches the file to an existing matching TUN/TAP device or allocates and registers a new multi-queue or single-queue netdevice. Kernel-to-userspace traffic enters `tun_net_xmit()`, selects a queue via flow hashing or eBPF steering, applies TAP multicast and socket/eBPF filters, queues an skb or XDP frame into the selected file's `tx_ring`, then wakes poll/read/fasync waiters. Userspace-to-kernel traffic enters `tun_chr_write_iter()` or `tun_sendmsg()`, parses optional packet information and optional virtio-net metadata, builds an skb from copied, fragmented, zerocopy, or page-frag memory, runs XDP if configured, derives TUN protocol or TAP Ethernet protocol, then injects through GRO/NAPI, batched receive, `netif_receive_skb()`, or `netif_rx()`. Socket `sendmsg` can also accept `TUN_MSG_PTR` arrays of `xdp_buff` objects for XDP-oriented injection.

State and persistence: Device state is runtime kernel state attached to the registered netdevice. Persistent devices set `IFF_PERSIST`, hold a module reference, and survive file close until persistence is cleared or the netdevice is unregistered. Queue attachment state is RCU-published, with disabled queues kept on `tun->disabled` for later `TUNSETQUEUE` reattach. Flow steering state is a timer-aged RCU hash table capped by `MAX_TAP_FLOWS`. The TAP transmit filter and socket filter are stored on `tun_struct` so they can be restored when a file attaches to a persistent device. Owner, group, flags, and queue counts are visible through sysfs and rtnetlink fill-info.

Dependencies and integration: Depends on miscdevice registration, rtnetlink link ops, netdevice operations, `ptr_ring`, Linux socket callbacks, RCU, RTNL locking, NAPI/GRO, XDP, BPF socket-filter programs, LSM hooks (`security_tun_*`), network namespaces, ethtool, proc fdinfo, compat ioctls, virtio-net helpers from `tun_vnet.h`, skb zerocopy, and notifier events for TX queue length and device-up changes. TAP uses Ethernet helpers and supports XDP NDO transmit; TUN uses IP tunnel header ops and point-to-point link metadata.

Risks and test signals: Highest-risk areas are RCU queue publication/detach ordering, persistent device lifetime, queue index rewriting during detach, `ptr_ring` resize and purge correctness, virtio header bounds/endian handling, zerocopy completion paths, NAPI-frags locking, XDP page ownership, eBPF program replacement lifetime, and ioctl permission checks. Test signals should include TUN and TAP create/delete, persistent close/reopen, multi-queue attach/detach, poll/fasync wakeups, read/write truncation, `sendmsg`/`recvmsg`, vnet header size/endian ioctls, TSO/USO/tunnel offloads, BPF steering/filtering, XDP PASS/DROP/TX/REDIRECT, NAPI and NAPI_FRAGS, TX queue length resize, owner/group permissions, compat ioctl paths, and namespace cleanup.

# sources/distributed-fs/ceph-client/drivers/net/tun_vnet.h

Purpose: Provides inline helpers used by `tun.c` to parse, emit, convert, and validate virtio-net headers for TUN/TAP userspace ABI support. It centralizes vnet header size ioctls, endianness mode flags, tunnel-offload header sizing, and conversion between virtio metadata and skb offload state.

Important APIs, types, and functions: Public inline helpers include `tun_vnet_ioctl()`, `tun_vnet_is_little_endian()`, `tun_vnet16_to_cpu()`, `cpu_to_tun_vnet16()`, `tun_vnet_hdr_get()`, `__tun_vnet_hdr_get()`, `tun_vnet_hdr_put()`, `__tun_vnet_hdr_put()`, `tun_vnet_hdr_to_skb()`, `tun_vnet_hdr_tnl_to_skb()`, `tun_vnet_hdr_from_skb()`, `tun_vnet_hdr_tnl_from_skb()`, and `tun_vnet_hdr_guest_features()`. ABI flags `TUN_VNET_LE` and `TUN_VNET_BE` occupy high bits in `tun->flags`; `TUN_VNET_TNL_SIZE` is the extended `virtio_net_hdr_v1_hash_tunnel` size.

Control flow: Vnet ioctls dispatch through `tun_vnet_ioctl()`, which gets/sets the configured header size and little/big-endian flags after copying scalar values to/from userspace. On userspace writes, `__tun_vnet_hdr_get()` verifies the iov has the configured size, copies the parsed portion, expands `hdr_len` when checksum start/offset implies a larger required header, checks that the packet body contains that header, and advances across any unparsed padding. On reads, `__tun_vnet_hdr_put()` copies the parsed portion of the virtio header and zero-fills the remaining configured ABI bytes. Conversion helpers call the core virtio-net routines to move GSO/checksum/tunnel metadata between headers and skbs.

State and persistence: The header itself stores no independent state. It mutates `tun->vnet_hdr_sz` and vnet endian bits through pointers supplied by `tun.c`. Endian behavior depends on runtime flags and `CONFIG_TUN_VNET_CROSS_LE`; when cross-endian support is disabled, big-endian get/set ioctls return `-EINVAL`. Guest tunnel features are inferred from configured vnet header size rather than a negotiated virtio feature set.

Dependencies and integration: Depends on UAPI TUN ioctls, `struct virtio_net_hdr`, `struct virtio_net_hdr_v1_hash_tunnel`, virtio endian conversion helpers, iov iterators, skb VLAN/GSO helpers, `NETIF_F_GSO_UDP_TUNNEL`, and diagnostic netdevice logging. `tun_get_user()`, `tun_put_user()`, and XDP message paths use these helpers before injecting or returning packets.

Risks and test signals: Risks include accepting inconsistent vnet header sizes, endian flag regressions across cross-LE builds, incorrect `hdr_len` checks for checksum-needed packets, tunnel offload metadata truncation when userspace configures only the legacy header size, and skb conversion failures for unsupported GSO types. Test vnet header get/set, minimum header rejection, LE/BE ioctls with and without `CONFIG_TUN_VNET_CROSS_LE`, checksum-needed hdr length expansion, short iov failures, tunnel GSO/CSUM metadata with extended headers, legacy headers without tunnel features, VLAN-tagged skb header generation, and unsupported GSO ratelimited diagnostics.

# sources/distributed-fs/ceph-client/drivers/net/usb/Kconfig

Purpose: Defines build-time configuration for USB networking drivers. It gates the USB network adapter menu on `USB && NET`, defines the shared `USB_USBNET` framework, exposes many vendor/class minidrivers, and declares dependency/select relationships for the ASIX and Aquantia drivers researched in this group.

Important options: `USB_NET_DRIVERS` is the enclosing tristate menu. `USB_USBNET` enables the common usbnet framework. `USB_NET_AX8817X` selects the ASIX AX88xxx USB 2.0 driver, depends on `USB_USBNET`, selects `CRC32`, `PHYLINK`, and `AX88796B_PHY`, implies `NET_SELFTESTS`, and defaults to `y`. `USB_NET_AQC111` selects Aquantia AQtion USB to 5/2.5GbE controller support, depends on `USB_USBNET`, and selects `CRC32`. The file also defines surrounding drivers such as CATC, Pegasus, RTL815x, LAN78xx, CDC Ethernet/NCM/MBIM, QMI WWAN, SMSC, SR9700/SR9800, and RTL8153 ECM fallback.

Control flow: Kconfig has no runtime execution; it controls which objects kbuild will compile as built-in, module, or not at all. Dependency clauses prevent driver selection without required core infrastructure, while `select` clauses pull in helper libraries and PHY/phylink support that the C files assume are present. Help text documents user-facing device support and module names.

State and persistence: The file contributes persistent kernel build configuration only. Resulting `.config` symbols determine whether `asix.o`, `aqc111.o`, `usbnet.o`, and other objects are linked into vmlinux or emitted as modules.

Dependencies and integration: Integrated with the adjacent USB net Makefile, the USB core, networking stack, `drivers/net/usb/usbnet.c`, PHYLIB/PHYLINK, CRC helpers, and class-specific CDC/RNDIS/WWAN dependencies. For this subset, `USB_NET_AX8817X` maps to `asix_devices.o`, `asix_common.o`, and `ax88172a.o`; `USB_NET_AQC111` maps to `aqc111.o`.

Risks and test signals: Risks are stale dependency expressions, missing selected symbols for code paths added in drivers, default-y surprises on small builds, and invalid built-in/module combinations around PHYLINK or usbnet. Test by building `USB_NET_DRIVERS=n`, `USB_USBNET=m/y`, `USB_NET_AX8817X=m/y`, `USB_NET_AQC111=m/y`, and combinations with `NET_SELFTESTS`, PHYLINK, and CRC32. Confirm module names, modpost dependencies, and that ASIX/AQC111 cannot be enabled without `USB_USBNET`.

# sources/distributed-fs/ceph-client/drivers/net/usb/Makefile

Purpose: Maps USB networking Kconfig symbols to kbuild object files. It is the build integration point that turns enabled USB net driver symbols into built-in objects or modules.

Important entries: `obj-$(CONFIG_USB_USBNET) += usbnet.o` builds the common framework. `obj-$(CONFIG_USB_NET_AX8817X) += asix.o` builds the ASIX composite object, and `asix-y := asix_devices.o asix_common.o ax88172a.o` defines its constituent translation units. `obj-$(CONFIG_USB_NET_AQC111) += aqc111.o` builds the Aquantia driver. Other mappings cover CDC, RNDIS, Realtek, SMSC, LAN78xx, QMI, MBIM, Zaurus, and many older adapters.

Control flow: kbuild expands each `obj-$(CONFIG_...)` assignment according to the symbol value. `y` links into the built-in kernel object for this directory, `m` builds a module, and empty omits it. The `asix-y` aggregate means all three ASIX source files are linked together into the single `asix` driver module/object.

State and persistence: There is no runtime state. The file persists object composition and module naming. For this group, changing the ASIX source split requires keeping the `asix-y` list in sync; changing Kconfig symbol names requires matching edits here.

Dependencies and integration: Depends on symbols defined by `drivers/net/usb/Kconfig` and on kbuild composite-object conventions. The driver registration functions in each C file (`module_usb_driver`) become module init/exit for the corresponding object produced here.

Risks and test signals: Risks are symbol/object drift, leaving a new source file out of a composite object, accidentally changing module names, or building a source without its declared Kconfig dependency. Test by compiling ASIX and AQC111 as modules and built-ins, confirming `asix.o` includes `asix_devices.o`, `asix_common.o`, and `ax88172a.o`, and checking `modules.order`/modpost for expected names and unresolved symbols.

# sources/distributed-fs/ceph-client/drivers/net/usb/aqc111.c

Purpose: Implements the Aquantia/ASIX AQC111U/AQC112 USB multi-gigabit Ethernet driver on top of the usbnet framework. It handles vendor control transfers, MAC/PHY programming, link mode and WoL ethtool operations, VLAN and checksum offloads, jumbo MTU configuration, RX/TX descriptor framing, suspend/resume, and USB product matching.

Important APIs, types, and functions: Device state is `struct aqc111_data` from `aqc111.h`, stored in `usbnet->driver_priv`; it tracks RX control bits, checksum enablement, link speed/link state, autonegotiation, advertised speed, firmware version, PHY config, and WoL flags. USB register helpers include `aqc111_read_cmd[_nopm]()`, `aqc111_read16_cmd[_nopm]()`, `aqc111_write_cmd[_nopm]()`, `aqc111_write16/32_cmd[_nopm]()`, and async variants. Main lifecycle and data hooks are `aqc111_bind()`, `aqc111_unbind()`, `aqc111_reset()`, `aqc111_stop()`, `aqc111_status()`, `aqc111_link_reset()`, `aqc111_rx_fixup()`, `aqc111_tx_fixup()`, `aqc111_suspend()`, and `aqc111_resume()`. Netdev/ethtool hooks cover MTU, MAC address, VLAN add/kill, RX mode, feature toggles, WoL, and link settings.

Control flow: Probe is delegated to `usbnet_probe()`, which calls `aqc111_bind()` from `driver_info`. Bind verifies the device is in vendor configuration 1, resets USB configuration, discovers endpoints, allocates private state, reads the permanent MAC and firmware version, sets URB sizes/headroom/tailroom, enables feature flags, and installs netdev/ethtool ops. Reset powers the PHY, writes the MAC address, masks interrupts, clears monitor bits, marks carrier down, and advertises the configured speeds. USB interrupt status packets update `link` and `link_speed`, then defer `EVENT_LINK_RESET`. Link reset programs RX bulk queue timing, pause watermarks, VLAN control, DMA controls, medium mode, checksum offloads, multicast filters, RX control start, and carrier state. TX fixup prepends a 64-bit descriptor with length, MSS, VLAN, padding/drop-pad metadata; RX fixup validates a trailing descriptor header and per-packet descriptors, splits multi-packet URBs into skbs, applies checksum and VLAN metadata, and returns each packet to usbnet.

State and persistence: Runtime state lives in `aqc111_data` and hardware registers. The driver preserves user link settings (`autoneg`, `advertised_speed`), WoL flags, RX control mode, firmware version, and PHY config while bound. VLAN filter state is programmed into a 256-entry hardware bitmap by add/kill and feature toggles. Suspend either configures magic-packet wake and leaves a minimal RX path armed, or powers down the PHY and disables receive. Resume restores PHY power, RX control, advertised speed, medium receive enable, and RX path readiness before calling `usbnet_resume()`.

Dependencies and integration: Depends on usbnet framing (`FLAG_FRAMING_AX`, `FLAG_MULTI_PACKET`, `FLAG_AVOID_UNLINK_URBS`), USB vendor control messages, Ethernet helpers, VLAN acceleration, ethtool link mode APIs, netdevice feature negotiation, CRC32 multicast hashing, CDC/vendor-interface USB IDs, runtime PM-safe no-PM command variants, and constants from `aqc111.h`.

Risks and test signals: Risks include descriptor bounds validation, endianness of 16/32/64-bit register and descriptor fields, inconsistent hardware checksum enable semantics, VLAN bitmap programming failures being ignored, MTU/URB size changes during traffic, link speed programming on non-SuperSpeed USB, suspend/resume register ordering, and memory lifetime in bind/unbind failure paths. Test probe at vendor and CDC-compatible interfaces, 100M/1G/2.5G/5G links, SuperSpeed and HighSpeed caps, MTU up to 16334, RX multi-packet aggregation, malformed descriptors, TX padding at maxpacket boundaries, VLAN filter add/remove, RX/TX checksum toggles, multicast/promiscuous/allmulti modes, WoL suspend/resume, unplug during control transfer, and module device table matching.

# sources/distributed-fs/ceph-client/drivers/net/usb/aqc111.h

Purpose: Defines the register map, feature masks, descriptors, private state, and tuning tables used by the AQC111/AQC112 USB Ethernet driver. It is the hardware contract for `aqc111.c`.

Important APIs, types, and constants: Core command selectors include `AQ_ACCESS_MAC`, `AQ_FLASH_PARAMETERS`, `AQ_PHY_POWER`, `AQ_WOL_CFG`, and `AQ_PHY_OPS`. MAC register constants cover RX control, node ID, multicast filter array, medium status, monitor mode, PHY reset/power, VLAN table control/data, RX bulk-in queue controls, checksum offload controls, DMA controls, pause watermarks, firmware version, MAC path, and bulk-out control. Feature masks define supported netdev features: `AQ_SUPPORT_FEATURE`, `AQ_SUPPORT_HW_FEATURE`, and `AQ_SUPPORT_VLAN_FEATURE`. `struct aqc111_wol_cfg` is the packed hardware WoL command payload. `struct aqc111_data` is the per-device driver state. Descriptor constants define TX length/drop-pad/VLAN/MSS fields, RX packet descriptor checksum/VLAN/drop/length bits, and RX descriptor header packet-count/offset fields.

Control flow: The header is not executable, but its constants drive all register control flow in `aqc111.c`. Reset and link reset program SFR registers with these bit definitions; RX/TX fixups decode or emit descriptors with the masks and shifts here; ethtool feature changes map to checksum and VLAN bits; suspend/resume uses monitor, WoL, RX path, DMA, and PHY config bits.

State and persistence: `struct aqc111_data` persists while the USB interface is bound and stores software shadows for hardware RX control, PHY capabilities/power/WoL configuration, current link speed, autonegotiation state, advertised speed, checksum status, and firmware version. `AQC111_BULKIN_SIZE[]` is a static table of RX bulk queue control settings selected for normal high-speed rates, 100M, and jumbo-packet operation.

Dependencies and integration: Depends on netdevice feature flags, bit operations, packed structure layout, virt-independent little-endian handling in the C file, VLAN constants, and Linux Ethernet MTU conventions. The header is included only by `aqc111.c`, so changes are tightly coupled to that driver's register programming.

Risks and test signals: Risks include incorrect masks/shifts corrupting descriptors or PHY config, static bulk queue tuning table mismatch with firmware expectations, feature masks advertising unsupported hardware offloads, and layout drift in the packed WoL configuration. Test signals include compile checks for all bit definitions used by `aqc111.c`, descriptor round trips for representative packet lengths/VLAN/MSS values, WoL payload size verification, MTU-dependent bulk-in table selection, and feature negotiation tests that compare advertised software features with actual register writes.

# sources/distributed-fs/ceph-client/drivers/net/usb/asix.h

Purpose: Provides the shared register definitions, data structures, and function declarations for ASIX AX8817x/AX88772/AX88178/AX88172A USB Ethernet drivers. It is consumed by `asix_common.c`, `asix_devices.c`, and `ax88172a.c`.

Important APIs, types, and constants: Register command constants cover MII access, EEPROM read/write, RX control, node ID, PHY ID, medium mode, monitor mode, GPIO, software reset, PHY selection, and QCT control. Bit definitions cover chip codes, PHY selection, WoL monitor bits, medium mode flags, RX control flags and maximum frame buffer sizes, GPIO pins, EEPROM magic/length, embedded PHY address, and ASIX software reset modes. `struct asix_data` is a compact legacy per-device storage area overlaid on `usbnet->data`. `struct asix_rx_fixup_info` stores cross-URB RX framing state. `struct asix_common_private` holds common AX88772 state including reset/suspend/resume callbacks, saved PHY registers, RX fixup state, MDIO bus, PHY devices, phylink handle/config, PHY address, embedded-PHY flag, and chip code.

Control flow: This header does not execute code. It defines the command and state vocabulary used by shared helpers and device-specific bind/reset/link operations. TX/RX framing helpers use the RX fixup structure and headroom/tailroom assumptions. MDIO, EEPROM, WoL, multicast, and MAC-address helpers exported from `asix_common.c` are declared here for reuse by the ASIX device variants.

State and persistence: `asix_data` persists in the fixed usbnet `data` field for older device-specific state such as multicast filter bytes, MAC address shadow, PHY mode, and LED mode. `asix_common_private` or AX88172A private state persists via `driver_priv` for newer devices and owns resources that must be released on unbind. `asix_rx_fixup_info` can hold a partially assembled skb across URBs and must be reset/freed when framing loses synchronization or the device is unbound.

Dependencies and integration: Includes module, netdevice, ethtool, MII, USB, usbnet, PHY, phylink, CRC32, VLAN, workqueue, and net selftest headers. Declares the externally defined `ax88172a_info` so `asix_devices.c` can include AX88172A products in the same `asix` module.

Risks and test signals: Risks include the explicit size constraint on `struct asix_data`, mismatch between header prototypes and helper implementations, chip/reset bit confusion across similar ASIX variants, and partial-frame state leaks. Test compile coverage for all ASIX objects, static size expectations for `asix_data`, RX fixup reset/free behavior, MDIO/EEPROM/WoL helper calls from each device family, and module builds where `ax88172a_info` is linked into `asix.o`.

# sources/distributed-fs/ceph-client/drivers/net/usb/asix_common.c

Purpose: Implements reusable ASIX usbnet helpers for vendor control transfers, AX framing TX/RX fixups, PHY/MDIO access, reset and register writes, multicast filtering, WoL, EEPROM access, and MAC address changes. It is the shared support layer for the device-specific ASIX drivers.

Important APIs and functions: USB helpers are `asix_read_cmd()`, `asix_write_cmd()`, and `asix_write_cmd_async()`, with `in_pm` selecting normal or no-PM usbnet control transfers. MII/PHY helpers include `asix_set_sw_mii()`, `asix_set_hw_mii()`, `asix_check_host_enable()`, `asix_mdio_read()`, `asix_mdio_write()`, bus wrappers, and no-PM variants. Framing helpers are `asix_rx_fixup_internal()`, `asix_rx_fixup_common()`, `asix_rx_fixup_common_free()`, and `asix_tx_fixup()`. Register helpers cover PHY address read, software reset, RX control, medium mode/status, GPIO, multicast filter, WoL, EEPROM get/set, and `asix_set_mac_address()`.

Control flow: RX fixup parses the ASIX 32-bit data header, including split headers and Ethernet frames spanning multiple URBs. It validates the complemented length field, rejects over-MTU frames, allocates a target skb when possible, copies payload in even-aligned chunks, returns completed skbs through `usbnet_skb_return()`, and resets framing state on bad headers or length mismatches. TX fixup ensures 4 bytes of headroom for the length/complement header and optional 4 bytes of tail padding when the USB transfer would otherwise end on a maxpacket boundary, then sets usbnet TX stats. MDIO operations switch to software MII, perform register I/O under `phy_mutex`, then restore hardware MII. EEPROM writes enable write mode, preserve unaligned boundary words, write 16-bit words with delays, then disable writes.

State and persistence: Cross-URB RX state is held in `struct asix_rx_fixup_info`, including a partially assembled skb, current header, bytes remaining, and split-header flag. Multicast and MAC address shadows use `struct asix_data` inside `usbnet->data`. EEPROM writes persist to device nonvolatile memory only when ethtool supplies the correct magic. WoL monitor bits persist in device registers while powered. MDIO operations do not keep state beyond hardware mode transitions and mutex serialization.

Dependencies and integration: Depends on usbnet control APIs, `dev->phy_mutex`, CRC32 multicast hashing, MII/PHY register definitions, ethtool EEPROM/WoL ABI, skb allocation/copy helpers, unaligned little-endian helpers, and async usbnet writes. Device-specific files call these helpers from bind, reset, link-change, ethtool, multicast, suspend/resume, and RX/TX data paths.

Risks and test signals: Risks include RX stream desynchronization after truncated URBs, leaking a partially assembled skb, bad length complement handling, maxpacket padding regressions, PM-context USB command misuse, MDIO host-enable timeouts, EEPROM corruption on unaligned writes or wrong magic validation, and changing MAC while running. Test malformed and split AX headers, multi-URB frames, maxpacket-aligned TX, cloned skb head/tailroom cases, multicast filter hashing, MDIO read/write under normal and no-PM contexts, EEPROM read/write boundaries, WoL get/set, and unbind cleanup with an incomplete RX frame.

# sources/distributed-fs/ceph-client/drivers/net/usb/asix_devices.c

Purpose: Implements most ASIX AX8817x/AX88772/AX88178 USB Ethernet device variants and registers the `asix` USB driver. It provides device-specific bind/reset/link operations, phylink/MDIO integration for AX88772-class devices, legacy MII support for older devices, gigabit PHY setup for AX88178, ethtool/netdev ops, suspend/resume handling, driver_info tables, and USB product IDs.

Important APIs, types, and functions: `struct ax88172_int_data` describes legacy interrupt status packets. Important helpers include `asix_status()`, `asix_set_netdev_dev_addr()`, `asix_get_phyid()`, `ax88172_bind()`, `ax88172_link_reset()`, `asix_phy_reset()`, `ax88772_hw_reset()`, `ax88772a_hw_reset()`, `ax88772_bind()`, `ax88772_reset()`, `ax88772_init_mdio()`, `ax88772_phylink_setup()`, `ax88772_init_phy()`, `ax88772_suspend()`, `ax88772_resume()`, `ax88178_bind()`, `ax88178_reset()`, `ax88178_link_reset()`, `ax88178_change_mtu()`, and PHY-specific `marvell_phy_init()` / `rtl8211cl_phy_init()`. Static `driver_info` records select the right hooks for each product.

Control flow: `module_usb_driver(asix_driver)` registers a usbnet-based USB driver. On probe, usbnet selects the matched product's `driver_info` and calls its bind hook. AX88172 bind toggles model-specific GPIOs, reads the MAC, initializes legacy `mii_if_info`, resets the PHY, and starts autonegotiation. AX88772 bind allocates `asix_common_private`, reads MAC from device tree, EEPROM, or node ID, identifies PHY and chip code, performs chip-specific hardware reset, sets 2 KiB AX framing URB size, registers an MDIO bus, creates phylink, connects the PHY, and holds a PM usage reference to avoid runtime-PM/RTNL deadlock. AX88772 reset rewrites MAC/RX/medium registers and starts phylink. AX88178 bind initializes GMII-capable MII and private state; reset reads EEPROM PHY mode/LED mode, powers the external PHY via GPIO, initializes Marvell or Realtek PHY quirks, resets/autonegotiates, and programs medium/RX registers. Link reset updates medium mode and LED state based on negotiated speed/duplex.

State and persistence: Per-device state is split between `usbnet->data` (`struct asix_data`) and `driver_priv` (`struct asix_common_private` for AX88772/AX88178). AX88772 owns an MDIO bus, phylink object, primary/internal PHY devices, chip code, embedded-PHY flag, and PM usage reference. AX88178 stores PHY mode and LED mode decoded from EEPROM. RX fixup state persists across URBs and is freed on unbind for variants using shared framing. Hardware state includes GPIO, RX_CTL, medium mode, IPG, PHY registers, and EEPROM-derived settings.

Dependencies and integration: Depends on the shared helpers in `asix_common.c`, the AX88172A `driver_info` from `ax88172a.c`, usbnet core callbacks, PHYLIB, PHYLINK, MDIO bus registration, ethtool selftests (`NET_SELFTESTS` implied by Kconfig), runtime PM, device tree MAC address lookup, and USB link power management disabling. The product table maps many vendor/product IDs to common driver_info records.

Risks and test signals: Risks include rollback leaks in multi-step bind paths, PM usage reference imbalance, phylink/RTNL ordering, MDIO bus lifetime, reset timing sensitivity, chip-code-specific reset differences, EEPROM MAC endianness, external/internal PHY handling, AX88178 jumbo MTU/maxpacket `-EDOM` behavior, and product table regressions. Test representative AX88172, AX88772, AX88772A/B, AX88178, AX88172A demo-board, and EEPROM-MAC devices; phylink connect/disconnect; suspend/resume; runtime PM refusal; link up/down at 10/100/1000 where supported; jumbo MTU on AX88178; multicast/WoL/EEPROM ethtool paths; net selftest hooks; and unbind after partial bind failures.

# sources/distributed-fs/ceph-client/drivers/net/usb/ax88172a.c

Purpose: Adds support for ASIX AX88172A USB 2.0 Ethernet devices with phylib-managed internal or external PHYs. It is linked into the `asix` composite driver and exports `ax88172a_info` for the product table in `asix_devices.c`.

Important APIs, types, and functions: `struct ax88172a_private` owns the MDIO bus, connected PHY device, PHY name string, PHY address, last programmed medium mode, embedded-PHY selection, and AX framing RX state. Main functions are `ax88172a_bind()`, `ax88172a_reset()`, `ax88172a_stop()`, `ax88172a_unbind()`, `ax88172a_adjust_link()`, `ax88172a_init_mdio()`, `ax88172a_remove_mdio()`, `ax88172a_reset_phy()`, `ax88172a_rx_fixup()`, and no-op interrupt `ax88172a_status()`. It installs `ax88172a_netdev_ops` and `ax88172a_ethtool_ops`.

Control flow: Bind discovers endpoints, allocates private state, reads the MAC address, installs netdev and ethtool ops, reads `AX_CMD_SW_PHY_STATUS` to determine internal versus external PHY mode, reads the selected PHY address, resets the PHY/MAC path, sets 2 KiB RX URB size for AX framing, and registers an MDIO bus. Reset repeats PHY reset, clears RX control, writes IPG defaults, rewrites the MAC address, restores default RX control, logs medium state, builds a PHY name from the MDIO bus ID and PHY address, connects phylib with `ax88172a_adjust_link()`, resumes the PHY, and starts it. Link adjustment computes ASIX medium mode from phylib speed/duplex and writes it only when changed. Stop stops and disconnects the PHY; unbind unregisters MDIO and frees private state.

State and persistence: The private state persists while the USB interface is bound. `oldmode` avoids redundant medium-mode writes. `phydev` is connected only after reset succeeds and is disconnected during stop. RX framing state is stored per device and passed to `asix_rx_fixup_internal()` so partial AX-framed packets can span URBs. Hardware state includes selected PHY path, software reset mode, RX_CTL, IPG registers, node ID, and medium mode.

Dependencies and integration: Depends on `asix_common.c` for register access, MDIO bus read/write wrappers, RX/TX AX framing, multicast, EEPROM, WoL, and MAC address helpers. Integrates with usbnet through `struct driver_info ax88172a_info`, phylib through `mdiobus_register()`, `phy_connect()`, `phy_start()`, and `phy_do_ioctl_running`, and the ASIX product table through an extern declaration in `asix.h`.

Risks and test signals: Risks include unsupported PHY selection values, MDIO registration cleanup after bind failures, repeated reset connecting multiple PHY instances if stop was not called, missing cleanup of partial RX fixup state on unbind, reset timing sensitivity, and medium-mode mismatch for unusual PHY speed/duplex reports. Test internal and external PHY modes, invalid PHY selection, bind failure at MAC/PHY/MDIO stages, reset then stop/unbind, phylib link polling and speed/duplex changes, RX AX framing shared with common helper, WoL/EEPROM ethtool operations inherited from common code, and module linkage through the ASIX demo-board USB ID.
