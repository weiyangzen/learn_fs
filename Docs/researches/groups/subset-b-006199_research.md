# sources/distributed-fs/ceph-client/net/ipv4/inet_connection_sock.c

Purpose: implements shared helpers for IPv4/dual-stack connection-oriented INET sockets, especially bind conflict checks, ephemeral port selection for listeners, accept queue handling, request-socket lifetime, child socket cloning, listener shutdown, and route/PMTU update helpers used primarily by TCP.

Important APIs/functions: exports `inet_sk_get_local_port_range`, `inet_rcv_saddr_equal`, `inet_csk_get_port`, `inet_csk_accept`, `inet_csk_route_child_sock`, `inet_reqsk_alloc`, `__reqsk_free`, `inet_csk_reqsk_queue_drop*`, `inet_csk_reqsk_queue_hash_add`, `inet_csk_clone_lock`, `inet_csk_destroy_sock`, `inet_csk_prepare_forced_close`, `inet_csk_listen_start`, `inet_csk_reqsk_queue_add`, `inet_csk_complete_hashdance`, `inet_csk_listen_stop`, and PMTU/update helpers. Core types are `struct inet_connection_sock`, `struct inet_bind_bucket`, `struct inet_bind2_bucket`, `struct request_sock`, `struct request_sock_queue`, `struct inet_request_sock`, `struct sock`, `struct flowi4`, and `struct dst_entry`.

Control flow: bind processing starts by comparing socket receive addresses with IPv4/IPv6 wildcard semantics, then `inet_csk_get_port()` either validates a requested port or calls `inet_csk_find_open_port()` to scan the effective local port range. The scan skips reserved ports, alternates parity away from active connect users, honors per-socket `IP_LOCAL_PORT_RANGE`, checks `bhash`/`bhash2` conflicts including address-any buckets, and creates bind buckets only under the relevant hash locks. Successful binds update fast-reuse hints and link the socket into both bind tables. Accept flow locks the listening socket, optionally waits on the accept queue with wake-one semantics, removes a completed request, handles TCP Fast Open requests specially, initializes child locks, and returns the established child. Request timers retransmit SYN-ACKs, age/defer requests, migrate requests to another reuseport listener when possible, and drop timed-out requests. Child creation clones listener state, installs request addresses/ports, resets listener-only state, and applies ULP/security clone hooks. Listener start initializes the request queue, moves to `TCP_LISTEN`, validates/gets the port, and hashes the listener; listener stop drains accepted children, attempts reuseport migration, destroys abandoned children, and frees Fast Open reset requests.

State and persistence: persistent kernel state is held in bind buckets (`icsk_bind_hash`, `icsk_bind2_hash`), request queues, timers, socket state, route caches, and refcounts. Locking is central: bind table updates require `bhash` and sometimes `bhash2` spinlocks with bottom halves disabled; accept queue operations use the listener socket lock or queue spinlocks; request timers rely on timer refcounts and ehash ownership. RCU protects reuseport callbacks, request options, and route-visible state. The code is memory-order aware around `icsk_pending`, request publication, and timer state using acquire/release stores and barriers.

Dependencies and integration: depends on `inet_hashtables`, `inet_timewait_sock`, TCP state/timer helpers, route lookup, XFRM, IPv6 address helpers, security hooks, and reuseport/BPF migration. TCP calls these helpers for `bind()`, `listen()`, `accept()`, SYN-RECV request handling, child socket creation, PMTU updates, and cleanup.

Risks: bind correctness depends on matching `bhash`/`bhash2` lock ordering and preserving wildcard conflict semantics across IPv4, IPv6, v4-mapped, and `IPV6_V6ONLY` sockets. Request migration is refcount-sensitive and can leak or double-free if timer, ehash, listener, and child ownership are not updated in the expected order. Fast Open paths carry special `req->sk == NULL` meaning. Ephemeral port scanning affects port exhaustion behavior and privacy; changes can regress `SO_REUSEADDR`, `SO_REUSEPORT`, `IP_BIND_ADDRESS_NO_PORT`, connect-bind, or autobind reuse behavior.

Test signals: useful coverage includes TCP bind/listen/accept selftests, reuseport migration tests, IPv4/IPv6 dual-stack bind conflict cases, Fast Open accept/listener close tests, port exhaustion/reserved-port tests, PMTU/strict-source-route route failure paths, syzkaller socket lifetime reports, and lockdep/KCSAN around bind/request timer races.

# sources/distributed-fs/ceph-client/net/ipv4/inet_diag.c

Purpose: provides the AF_INET/AF_INET6 SOCK_DIAG netlink implementation for inspecting and, where supported, destroying INET protocol sockets. It dispatches protocol-specific diagnostic handlers, formats common socket attributes, filters dump results with inet_diag bytecode, and registers compatibility support for the older TCPDIAG interface.

Important APIs/functions: exports `inet_diag_msg_common_fill`, `inet_diag_msg_attrs_fill`, `inet_sk_diag_fill`, `inet_diag_bc_sk`, `inet_diag_register`, and `inet_diag_unregister`. Internal entry points include `inet_diag_lock_handler`, `inet_diag_cmd_exact`, `inet_diag_bc_run`, `inet_diag_bc_audit`, `__inet_diag_dump`, `inet_diag_handler_cmd`, and `inet_diag_handler_get_info`. Key types are `struct inet_diag_handler`, `struct inet_diag_msg`, `struct inet_diag_req_v2`, `struct inet_diag_dump_data`, `struct inet_diag_entry`, `struct inet_diag_bc_op`, and netlink `nlattr`/`sk_buff`.

Control flow: requests parse optional netlink attributes, resolve the target protocol, module-load a diagnostic handler if needed, and take a module reference under RCU. Exact requests call handler `dump_one` or `destroy`; dump requests allocate callback data, audit bytecode and BPF storage filters, then repeatedly call the handler's `dump`. `inet_sk_diag_fill()` constructs one netlink message: it writes IDs, address/cookie fields, common attributes, memory info, timers, congestion control details, handler-specific info, optional auxiliary info, BPF socket storage data, and adjusts `cb->min_dump_alloc` when one socket does not fit. Bytecode filtering builds a normalized `inet_diag_entry` for full sockets, timewait sockets, and SYN-RECV requests and evaluates port, address prefix, device, mark, cgroup, and auto-bound predicates.

State and persistence: global `inet_diag_table` is an RCU array indexed by IP protocol and populated by protocol modules. Netlink dump state persists in `cb->data` for the life of a dump and is released by the dump `done` callback. The code reads socket state locklessly with `READ_ONCE`, `data_race`, and RCU where diagnostic output tolerates concurrent socket changes. No socket state is modified except through protocol handler `destroy` callbacks.

Dependencies and integration: integrates with `sock_diag` registration for AF_INET/AF_INET6, protocol modules such as TCP/UDP/RAW through `inet_diag_handler`, BPF socket storage diagnostics, cgroup/classid data, netlink capability checks, IPv6 address support, and congestion-control callbacks. User space tools such as `ss`, `iproute2`, and socket monitoring agents consume this API.

Risks: netlink attribute sizing and retry behavior are fragile because one oversized socket dump must either expand the skb or fit partial output only for the first message. Bytecode validation is security-sensitive: malformed jumps, length fields, mark filters without `CAP_NET_ADMIN`, or cgroup predicates must be rejected before evaluation. Handler registration uses lockless RCU/module references; missing `try_module_get` or unregister ordering bugs can become use-after-free. Diagnostic reads can race socket changes, so fields must remain best-effort rather than assuming consistency.

Test signals: validate with `ss -tiem`, inet_diag selftests, netlink fuzzing, bytecode filter tests for address/port/device/mark/cgroup, BPF socket storage diagnostic tests, compat `TCPDIAG_GETSOCK` dumps, socket destroy permission tests, and syzkaller netlink reports for malformed attributes and dump resizing.

# sources/distributed-fs/ceph-client/net/ipv4/inet_fragment.c

Purpose: implements protocol-neutral fragment queue infrastructure shared by IPv4 and IPv6 reassembly. It owns fragment queue allocation, rhashtable lookup, namespace fragment-directory teardown, memory accounting, overlap/duplicate insertion policy, rb-tree/run representation, and reassembly list construction.

Important APIs/functions: exports `ip_frag_ecn_table`, `inet_frags_init`, `inet_frags_fini`, `fqdir_init`, `fqdir_pre_exit`, `fqdir_exit`, `inet_frag_kill`, `inet_frag_queue_flush`, `inet_frag_destroy`, `inet_frag_find`, `inet_frag_queue_insert`, `inet_frag_reasm_prepare`, `inet_frag_reasm_finish`, and `inet_frag_pull_head`. Key types are `struct inet_frags`, `struct fqdir`, `struct inet_frag_queue`, `struct ipfrag_skb_cb`, `struct sk_buff`, `struct rhashtable`, and rb-tree nodes embedded in skbs.

Control flow: fragment subsystem initialization creates a slab cache for protocol queue objects. Per-net `fqdir_init()` creates an rhashtable and takes a reference on the owning `inet_frags`. `inet_frag_find()` rejects new queues when thresholds are exceeded or the directory is exiting, looks up an existing queue, or creates one with a timer and hash-table reference. Insertions use a tail fast path for in-order adjacent fragments and an rb-tree search for out-of-order fragments, returning explicit OK/duplicate/overlap results. Reassembly preparation ensures the selected head fragment is at offset zero, clones or morphs skbs when the desired head differs from the first tree node, preserves socket write-memory accounting for TX reassembly, and sets a `frag_list` insertion pointer. Finish walks all rb-tree runs in order, coalesces when allowed, updates checksum and timestamps, removes memory accounting, and leaves a single skb containing the reassembled payload. Teardown marks directories dead, flushes queues, frees rhashtable entries, waits for RCU callbacks, and eventually frees the `fqdir`.

State and persistence: fragment queues persist in per-net rhashtables until completed, timed out, flushed, or namespace teardown. Each queue owns a timer reference and a hash-table reference; `inet_frag_kill()` marks `INET_FRAG_COMPLETE`, cancels the timer, removes from rhashtable if the directory is live, or records `INET_FRAG_HASH_DEAD` during teardown. Memory usage is accounted through `add_frag_mem_limit`/`sub_frag_mem_limit` for queue objects and skb truesize. Queue fragment state is stored in skb `cb`, rbnode, `next_frag`, and `frag_run_len`; this overlaps with other skb fields and requires careful handoff by callers.

Dependencies and integration: used by IPv4 `ip_fragment.c`, IPv6 reassembly, and netfilter conntrack reassembly paths. Depends on rhashtable, timers, delayed work, RCU, skb memory helpers, ECN logic, net namespace lifetime, and protocol-specific constructors/destructors/expire callbacks supplied in `struct inet_frags`.

Risks: overlapping fragments are security-sensitive and must preserve RFC5722-style discard behavior where required by callers. skb field aliasing (`rbnode` versus `dev`) and skb control block usage can corrupt packet metadata if callers do not reset fields at the right time. Namespace teardown has several races between timers, rhashtable destruction, RCU freeing, and queue refs. Reassembly must keep socket memory accounting balanced or TX paths can leak accounting references. Threshold enforcement is best-effort and sensitive to truesize changes.

Test signals: fragment reassembly selftests, IPv4/IPv6 overlap and duplicate fuzzing, namespace teardown under active fragments, memory-pressure tests for high/low thresholds, ECN combination tests, syzkaller fragment reports, KASAN/KCSAN/lockdep around queue flush and timer expiry, and packetdrill/scapy tests for ordered and out-of-order fragments.

# sources/distributed-fs/ceph-client/net/ipv4/inet_hashtables.c

Purpose: implements generic INET socket hash tables for bound ports, listeners, established sockets, timewait/request sockets, connect-time port selection, reuseport listener selection, and per-net ehash allocation.

Important APIs/functions: exports `inet_ehashfn`, `inet_bind_bucket_create`, `inet_bind_bucket_destroy`, `inet_bind_bucket_match`, `inet_bind2_bucket_create`, `inet_bind2_bucket_destroy`, `inet_bind_hash`, `inet_put_port`, `__inet_inherit_port`, `inet_lookup_reuseport`, `__inet_lookup_listener`, `sock_gen_put`, `sock_edemux`, `__inet_lookup_established`, `inet_ehash_insert`, `inet_ehash_nolisten`, `inet_hash`, `inet_unhash`, `inet_bind2_bucket_match_addr_any`, `inet_bind2_bucket_find`, `inet_bhash2_addr_any_hashbucket`, `inet_bhash2_update_saddr`, `inet_bhash2_reset_saddr`, `inet_hash_connect`, `inet_hashinfo2_init`, `inet_ehash_locks_alloc`, `inet_pernet_hashinfo_alloc`, and `inet_pernet_hashinfo_free`.

Control flow: bound-port state is split between legacy port buckets and address-aware `bhash2` buckets. Bind creation initializes buckets, links sockets into `owners`, and maintains fast reuse hints. Listener lookup first gives BPF `sk_lookup` a chance, then searches address-specific `lhash2`, then INADDR_ANY, scoring candidates by netns, port, address, device binding, family, and incoming CPU; SO_REUSEPORT can select an alternate listener. Established lookup hashes the four-tuple, walks a nulls hlist under RCU, takes a refcount, and revalidates the match. Established insertion and connect collision checks use ehash locks; timewait sockets may be recycled through `tcp_twsk_unique`. Connect-time ephemeral port selection follows RFC6056-style double hashing with a perturb table, reserved-port skips, optional randomized scan stride, bind-bucket checks, ehash uniqueness checks, and insertion into bind and ehash tables. Source-address updates move sockets between bhash2 buckets while holding the old/new bucket locks around address changes.

State and persistence: persistent state lives in `struct inet_hashinfo` tables (`bhash`, `bhash2`, `lhash2`, `ehash`) and in sockets' bind/hash nodes. Hash secrets and the `table_perturb` array persist globally after initialization. Ehash and listener lists use nulls hlist RCU traversal with per-bucket spinlocks for mutation. Bind bucket fastreuse fields cache whether later binds/connects can skip expensive conflict scans. Per-net hashinfo allocations can clone global table metadata but own their ehash and locks.

Dependencies and integration: tightly coupled to TCP hashinfo/death-row state, IPv6 hashtable helpers, BPF socket lookup, SO_REUSEPORT groups/programs, secure sequence/ephemeral-port generation, L3 master device indexing, timewait/request socket freeing, and net namespace accounting. It is the core lookup substrate for TCP, UDP-like lookups that use INET helpers, early demux, and incoming packet demultiplexing.

Risks: socket identity is spread across address, port, device, family, v4/v6 mapped state, and netns; missing one dimension causes incorrect delivery or bind conflicts. RCU/nulls-list restarts and refcount revalidation are required to avoid use-after-free while sockets move chains. Connect-time port selection changes can create privacy regressions, port starvation, or unexpected interactions with `ip_local_reserved_ports`, `ip_local_port_range`, `ip_local_port_step_width`, and timewait recycling. Bhash2 address moves must not leave a socket linked to a bucket that no longer matches its source address.

Test signals: TCP/UDP bind/connect/listen selftests, SO_REUSEPORT and BPF `sk_lookup` tests, dual-stack wildcard binding tests, timewait reuse/recycle tests, ephemeral port distribution tests, network namespace teardown, early demux packet tests, lockdep around bhash/ehash locks, and syzkaller reports for hash insertion/removal races.

# sources/distributed-fs/ceph-client/net/ipv4/inet_timewait_sock.c

Purpose: manages generic INET TIME_WAIT sockets: allocation from protocol slabs, transition from full sockets to timewait entries, timer scheduling/descheduling, bind/ehash removal, freeing, and purging non-full sockets during network namespace teardown.

Important APIs/functions: exports `inet_twsk_bind_unhash`, `inet_twsk_put`, `inet_twsk_deschedule_put`, `__inet_twsk_schedule`, and provides `inet_twsk_alloc`, `inet_twsk_hashdance_schedule`, `inet_twsk_free`, and `inet_twsk_purge`. Key types are `struct inet_timewait_sock`, `struct inet_timewait_death_row`, `struct inet_hashinfo`, `struct inet_bind_bucket`, and `struct inet_bind2_bucket`.

Control flow: `inet_twsk_alloc()` checks the death-row bucket limit, allocates a timewait object, copies identity and policy fields from the full socket, initializes the timer and zero refcount, takes a protocol module reference, and initializes protocol-specific PSP state. `inet_twsk_hashdance_schedule()` links the timewait socket into the bind hash while the original socket remains bound, sets a three-reference model for bind, ehash, and timer, publishes it by replacing the full socket in ehash under the ehash lock, decrements protocol in-use accounting for the full socket, and arms the timer. Timer expiry calls `inet_twsk_kill()`, which removes from ehash, unhashes bind buckets, decrements death-row accounting, and drops refs. Early descheduling synchronizes with hashdance via the ehash lock before shutting down the timer, then kills if the timer was active. Purge scans all ehash slots for `TCP_TIME_WAIT` and `TCP_NEW_SYN_RECV` sockets belonging to dead netns and removes them safely.

State and persistence: timewait sockets persist in ehash and bind hash until timer expiry, early recycle, or namespace purge. Refcounts encode published ownership and are deliberately zero until fully initialized. The death row keeps aggregate `tw_refcount` and `sysctl_max_tw_buckets` limit state. Timer state is synchronized with ehash locks to avoid races where a purger shuts down a timer before hashdance arms it.

Dependencies and integration: works with `inet_hashtables` for ehash/bhash locks and bucket destruction, TCP timewait destructor and uniqueness logic, request-socket drop helpers for purging SYN_RECV entries, protocol module ownership, PSP initialization, and net namespace lifetime checks.

Risks: callers must not touch `tw` after `inet_twsk_hashdance_schedule()` because ownership is transferred to hash/timer refs. Refcount and timer ordering are critical; a missed synchronization can leak a timer ref or free a published object. Bind unhash requires bind hash locks held by callers. Purge must restart RCU walks when nulls markers change and must recheck netns after taking a ref.

Test signals: TCP close/timewait stress tests, timewait bucket limit tests, net namespace teardown while sockets are in TIME_WAIT/SYN_RECV, timewait recycle/connect tests, lockdep around ehash and bhash lock ordering, KASAN/KCSAN timer race reports, and `ss`/inet_diag visibility checks for timewait sockets.

# sources/distributed-fs/ceph-client/net/ipv4/inetpeer.c

Purpose: maintains long-lived per-peer IP state independent of routes, including redirect/rate-limit metadata and peer metrics storage, using an rb-tree per peer base rather than hash buckets to avoid collision attacks under bottom-half-disabled lookups.

Important APIs/functions: exports or provides `inet_peer_base_init`, `inet_initpeers`, `inet_getpeer`, `inet_putpeer`, `inet_peer_xrlim_allow`, and `inetpeer_invalidate_tree`. Important globals are `inet_peer_threshold`, `inet_peer_minttl`, `inet_peer_maxttl`, and the `peer_cachep` slab. Key types are `struct inet_peer_base`, `struct inet_peer`, and `struct inetpeer_addr`.

Control flow: initialization sizes the peer threshold to about one percent of RAM, clamps it, and creates the peer slab. Lookup first performs a seqlock-protected lockless rb-tree search under RCU; if a peer is found and the sequence did not change, the caller receives it without a refcount change. On miss or concurrent modification, the code takes the base write seqlock, repeats lookup while stacking visited peers for possible GC, allocates and inserts a new peer if still absent, and then garbage-collects old unreferenced peers. GC computes a TTL that becomes more aggressive as the tree approaches the threshold, removes peers with refcount one and stale `dtime`, and frees them by RCU. `inet_peer_xrlim_allow()` implements token-bucket rate limiting over peer fields. Tree invalidation erases all rb-tree nodes and drops their refs.

State and persistence: peers live in `inet_peer_base.rb_root` until their refcount reaches zero, GC removes them, explicit invalidation drops the tree, or final RCU freeing completes. Fields such as `daddr`, redirect count, metrics, rate tokens, and recent-use time persist across route cache changes. `base->total` is updated under the seqlock. Rate-limit fields are updated with `READ_ONCE`/`WRITE_ONCE` and are intentionally lightweight rather than strongly serialized.

Dependencies and integration: used by IPv4 fragment max-distance tracking, ICMP/ICMPv6 rate limiting, route metrics/redirect users, and per-net IPv4 peer bases. Depends on RCU, seqlock, rb-tree helpers, jiffies, secure sequence/rate helpers, and sysctl-exposed peer TTL/threshold tunables.

Risks: callers must understand that `inet_getpeer()` does not automatically increment a reference; code that persists a peer must use `refcount_inc_not_zero()` where appropriate. GC relies on `refcount_dec_if_one()` to avoid removing active peers. Rate limiting is shared by source and destination uses, so changing token semantics can alter ICMP behavior globally. Invalidating the tree without appropriate external serialization could race readers that expect RCU protection.

Test signals: ICMP rate-limit tests, route metrics persistence tests, IPv4 fragment `ipfrag_max_dist` behavior, peer sysctl tuning under memory pressure, namespace cleanup tests, and concurrency stress with KCSAN/lockdep around seqlock and refcount handling.

# sources/distributed-fs/ceph-client/net/ipv4/ip_forward.c

Purpose: implements IPv4 packet forwarding after routing has selected an output route. It enforces forwarding policy, TTL, strict source-route rules, PMTU/DF behavior, redirect generation, priority updates, netfilter forwarding hooks, and final output.

Important APIs/functions: central public entry point is `ip_forward(struct sk_buff *skb)`. Helpers are `ip_exceeds_mtu()` and `ip_forward_finish()`. Key types are `struct sk_buff`, `struct iphdr`, `struct rtable`, `struct ip_options`, `struct net`, and `struct dst_entry`.

Control flow: `ip_forward()` drops non-host packets, skb-owned packets, LRO packets, and packets failing XFRM forward policy. Router-alert packets are handed to `ip_call_ra_chain()`. The function updates checksums for forwarding, rejects TTL <= 1 with ICMP time exceeded, validates XFRM route forwarding, rejects strict source-route packets whose route uses a gateway, increments forwarding stats, and records `IPSKB_FORWARDED`. It computes forward MTU and, if DF/GSO rules require, sends ICMP fragmentation-needed and drops. Before changing the packet it copies writable headroom with `skb_cow()`, decrements TTL, sends redirects when requested and safe, optionally maps TOS to priority, then invokes the `NF_INET_FORWARD` hook. `ip_forward_finish()` applies forward options, clears timestamps, handles switchdev offload-consumed packets, and calls `dst_output()`.

State and persistence: no long-lived state is created; the function mutates per-packet skb/IPCB fields, TTL, checksum, priority, timestamps, and statistics. It depends on route state already attached to the skb and may emit ICMP side effects. Net namespace sysctl `ip_fwd_update_priority` affects priority mutation.

Dependencies and integration: sits between `ip_input` route resolution and `dst_output`, and integrates with XFRM, netfilter IPv4 forwarding, routing/PMTU, ICMP, source-route option handling, switchdev L3 forwarding offload, and IP statistics.

Risks: MTU/DF logic must preserve RFC behavior for fragments, GSO, `ignore_df`, and `frag_max_size`; mistakes can blackhole PMTU discovery or forward oversize packets. The packet must be copied writable before TTL/checksum mutation. Router-alert and source-route behavior intersects with security policy. Redirect generation must not run for source-routed or IPsec path packets.

Test signals: forwarding selftests with TTL expiry, PMTU/DF and GSO cases, strict and loose source-route packets, router-alert delivery, XFRM forward policy drops, netfilter forward hook behavior, switchdev offload marks, and SNMP counter checks for forwarded, header-error, and fragment-failure paths.

# sources/distributed-fs/ceph-client/net/ipv4/ip_fragment.c

Purpose: implements IPv4 fragment reassembly on top of the generic `inet_fragment` infrastructure, including IPv4 queue keys, ECN handling, distance-based anti-DoS behavior, ICMP timeout reporting, sysctls, per-net fragment directories, and packet reconstruction.

Important APIs/functions: exports `ip_defrag` and `ip_check_defrag`; initialization is `ipfrag_init`. Internal functions include `ip4_frag_init`, `ip4_frag_free`, `ip_expire`, `ip_find`, `ip_frag_too_far`, `ip_frag_reinit`, `ip_frag_queue`, `ip_frag_reasm`, and pernet/sysctl register helpers. Key types are `struct ipq`, `struct frag_v4_compare_key`, `struct inet_frag_queue`, `struct inet_frags`, `struct inet_peer`, and `struct sk_buff`.

Control flow: `ip_defrag()` increments reassembly request stats, finds the ingress L3 master vif, looks up or creates an `ipq`, locks it, and queues the fragment. `ip_frag_queue()` rejects completed queues, optionally flushes and reinitializes when fragments are too far apart per peer RID tracking, derives offset/end/MF/DF/ECN state, validates final-length consistency, pulls to the payload, trims to fragment length, inserts into the generic queue, updates `meat`, timestamps, max fragment sizes, interface index, and first/last flags, and triggers reassembly when the first and last fragment are present and all bytes are covered. Reassembly kills the queue, validates ECN combinations, prepares/finishes skb reassembly, enforces IPv4 max length, restores header length/TOS/DF/fragment metadata, recalculates the checksum, clears queue fragment roots, and returns the reassembled skb to the caller. Timer expiry kills stale queues, optionally pulls the first fragment to route and send ICMP fragment timeout, and drops buffered fragments. `ip_check_defrag()` is a safe helper for callers that may receive raw Ethernet skbs and only defrag if the packet is valid IPv4 and fragmented.

State and persistence: per-net `net->ipv4.fqdir` stores thresholds, timeout, max distance, and the rhashtable of active queues. Each `ipq` stores ECN accumulation, maximum DF fragment size, ingress ifindex, peer pointer, and RID snapshot. Sysctls expose high/low thresholds, timeout, and `ipfrag_max_dist`; the deprecated secret interval remains only as a compatibility knob. Active queues persist until completion, timeout, memory/too-far flush, or namespace exit.

Dependencies and integration: depends on `inet_fragment.c`, `inetpeer.c`, IPv4 routing for timeout ICMP decisions, L3 master device indexing, ECN helpers, netfilter defrag users, local delivery, router-alert delivery, conntrack bridge/in hooks, and pernet/sysctl infrastructure. IPv6 reassembly is expected to stay logically parallel.

Risks: overlap, duplicate, zero-length, inconsistent final-length, and oversize fragments must be rejected consistently to avoid reassembly ambiguity and memory pressure attacks. `max_dist` depends on peer refcounting and may flush legitimate sparse fragments under stress. Reassembled DF/PMTU metadata is subtle: the code sets DF only when the largest fragment had DF to avoid forwarding invalid packet sizes. Timer timeout ICMP must avoid sending for conntrack/AF_PACKET users or non-local reassembly contexts.

Test signals: scapy/packetdrill fragment tests for normal, out-of-order, duplicate, overlap, zero-length, oversize, ECN combinations, DF/PMTU propagation, timeout ICMP generation, conntrack defrag users, `ipfrag_*` sysctl behavior, namespace teardown, and memory-threshold stress.

# sources/distributed-fs/ceph-client/net/ipv4/ip_gre.c

Purpose: implements GRE over IPv4, gretap, and ERSPAN tunnel devices and protocol receive handling. It registers the GRE protocol handler, rtnetlink link kinds, per-net tunnel tables, transmit/receive paths, metadata-mode support, tunnel parameter validation, and ERSPAN-specific header handling.

Important APIs/functions: module entry/exit are `ipgre_init` and `ipgre_fini`. Public export is `gretap_fb_dev_create`. Major internal functions include `gre_rcv`, `gre_err`, `ipgre_err`, `erspan_rcv`, `__ipgre_rcv`, `ipgre_rcv`, `__gre_xmit`, `gre_fb_xmit`, `erspan_fb_xmit`, `ipgre_xmit`, `erspan_xmit`, `gre_tap_xmit`, `ipgre_tunnel_ctl`, `ipgre_header`, `ipgre_tunnel_init`, `ipgre_netlink_parms`, `erspan_netlink_parms`, `ipgre_newlink`, `erspan_newlink`, `ipgre_changelink`, `erspan_changelink`, `ipgre_fill_info`, and `erspan_fill_info`. Key types are `struct ip_tunnel`, `struct ip_tunnel_net`, `struct tnl_ptk_info`, `struct ip_tunnel_info`, `struct metadata_dst`, `struct rtnl_link_ops`, and `struct net_device_ops`.

Control flow: receive starts in `gre_rcv()`, parses the GRE header, drops multicast loopback when configured, dispatches ERSPAN packets to `erspan_rcv()` or regular GRE/gretap packets to `ipgre_rcv()`, and sends ICMP port unreachable when no tunnel accepts the packet. Tunnel lookup selects the per-net table by protocol (`gre`, `gretap`, or `erspan`), matches flags, addresses, link ifindex, and key, pulls GRE/ERSPAN headers, builds metadata destination data when the tunnel is collect-md or wildcarded, resets MAC headers appropriately, and calls `ip_tunnel_rcv()`. Error handling parses returned GRE headers from ICMP payloads, updates PMTU/redirect state for frag-needed/redirects, and records tunnel error counters for relevant ICMP errors. Transmit paths validate pullability/headroom, choose metadata-mode or configured tunnel parameters, handle GRE offloads, build GRE and optional ERSPAN headers, trim ERSPAN mirrored packets when needed, and call `ip_tunnel_xmit()` or `ip_md_tunnel_xmit()`. Netlink create/change parses GRE flags, keys, local/remote, TTL/TOS, PMTUDISC, collect metadata, ignore-DF, fwmark, encapsulation, and ERSPAN version/options before delegating to generic tunnel link helpers.

State and persistence: persistent state lives in per-net tunnel registries for `gre`, `gretap`, and `erspan`, each backed by `struct ip_tunnel_net`. Each netdevice stores `struct ip_tunnel` parameters, GRE header length, encapsulation length, sequence counter, fwmark, collect-md flag, ignore-DF flag, ERSPAN version/index/dir/hwid, feature bits, MTU/headroom, and optional multicast group membership. Module state includes rtnetlink ops, GRE protocol registration, pernet IDs, and `log_ecn_error` module parameter.

Dependencies and integration: integrates with generic IP tunnel core, GRE parser/builder, rtnetlink, netdevice operations, ERSPAN helpers, metadata destinations used by Open vSwitch/TC, XFRM/routing/ICMP PMTU and redirect handling, netfilter IPv4, multicast group management for broadcast GRE, and offload/GSO infrastructure.

Risks: GRE flag conversion between legacy big-endian GRE bits and internal tunnel flags is easy to break and affects user ABI. Metadata mode must reject non-IPv4 tunnel info and correctly populate source address after route lookup. ERSPAN versions have different header lengths and option sizes; wrong validation can misparse mirrored packets or expose out-of-bounds reads. Offload support changes with checksum, sequence, and encapsulation flags. PMTUDISC and ignore-DF are mutually constrained. Receive fallback between gretap and collect-md GRE affects OVS deployments.

Test signals: `ip link add gre/gretap/erspan` netlink tests, collect-metadata OVS/TC tunnel tests, PMTU/ICMP frag-needed and redirect tests, GRE checksum/key/sequence combinations, ERSPAN v0/v1/v2 metadata encode/decode tests, gretap fallback device creation, multicast GRE open/close tests, GSO/offload checks, namespace create/delete cycles, and packet fuzzing of malformed GRE/ERSPAN headers.

# sources/distributed-fs/ceph-client/net/ipv4/ip_input.c

Purpose: implements the IPv4 receive path from packet-type entry through header validation, prerouting, route resolution, option handling, early demux, local delivery, protocol dispatch, router-alert delivery, and batched receive optimization.

Important APIs/functions: exports `ip_call_ra_chain`, `ip_local_deliver`, and provides `ip_protocol_deliver_rcu`, `ip_rcv`, and `ip_list_rcv`. Important helpers include `ip_local_deliver_finish`, `ip_rcv_options`, `tcp_v4_early_demux`, `ip_rcv_finish_core`, `ip_rcv_finish`, `ip_rcv_core`, `ip_extract_route_hint`, `ip_list_rcv_finish`, and `ip_sublist_rcv`. Key types are `struct sk_buff`, `struct iphdr`, `struct net_protocol`, `struct ip_ra_chain`, `struct rtable`, and `struct inet_skb_parm`.

Control flow: `ip_rcv_core()` drops other-host frames, updates input stats, ensures skb writability/share safety, validates minimum IP header, version, header checksum, total length, pulls full options header, trims padding, sets transport header, clears IPCB, records ingress ifindex, and orphans non-prefetched sockets. `ip_rcv()` then runs the `NF_INET_PRE_ROUTING` hook and `ip_rcv_finish()`, which handles L3 master devices, resolves/validates route state, optionally early-demuxes TCP/UDP established sockets, processes IP options, accounts multicast/broadcast, and calls `dst_input()`. Local delivery defragments fragmented packets, runs `NF_INET_LOCAL_IN`, pulls the IP header, and dispatches to raw sockets and protocol handlers under RCU. Protocol dispatch can resubmit to a new protocol when a handler returns a negative protocol number; otherwise it sends ICMP protocol-unreachable when no handler and no raw socket consumed the packet. Batched receive groups skbs by device/net, runs netfilter list hooks, uses route hints for repeated flows, and dispatches sublists with common dst.

State and persistence: mostly per-packet state mutation: skb length/headroom, transport header, IPCB, dst, socket early-demux reference/destructor, packet stats, and drop reasons. Router-alert delivery walks the per-net `ra_chain` under RCU and may clone skbs for multiple raw sockets. Early demux attaches an established socket reference to the skb and may borrow a cached RX dst.

Dependencies and integration: integrates with netfilter prerouting/local-in hooks, routing/FIB and route hinting, XFRM policy, raw sockets, protocol handlers registered in `inet_protos` (TCP/UDP/ICMP/etc.), IPv4 defrag, IP options, L3 master devices, multicast routing-related router alert sockets, skb orphaning/tproxy behavior, and SNMP/drop statistics.

Risks: header validation ordering is security-critical: checksum and total length must be verified before protocol access, and skb trimming must preserve checksum state. Early demux uses socket refs and cached dsts; stale references require destructor/refcount correctness. Option processing may rewrite packets and source-route decisions. Batched route hinting must avoid custom-rule, broadcast, zeronet, and multipath cases. Raw socket delivery and protocol handler resubmit paths affect skb ownership and must avoid double frees.

Test signals: IPv4 receive selftests, malformed header/checksum/length packet fuzzing, prerouting/local-in netfilter tests, TCP/UDP early-demux tests, raw socket delivery and unknown-protocol ICMP tests, fragment local delivery, source-route/router-alert option tests, L3 master device tests, batched GRO/list receive tests, and drop counter assertions.

# sources/distributed-fs/ceph-client/net/ipv4/ip_options.c

Purpose: parses, validates, builds, echoes, fragments, undoes, and forwards IPv4 header options, including source route, record route, timestamp, router alert, and CIPSO options.

Important APIs/functions: exports `ip_options_compile`/`__ip_options_compile`, `ip_options_rcv_srr`, and provides `ip_options_build`, `__ip_options_echo`, `ip_options_fragment`, `ip_options_undo`, `ip_options_get`, and `ip_forward_options`. Important types are `struct ip_options`, `struct ip_options_rcu`, `struct sk_buff`, `struct rtable`, and `struct iphdr`.

Control flow: `ip_options_build()` copies compiled option data into an outgoing IP header and fills source-route destination, record-route address, and timestamp fields after routing. `__ip_options_echo()` constructs reply options by copying RR/TS/CIPSO, reversing source-route entries, validating pointer space, and padding to a 4-byte boundary. `ip_options_fragment()` turns non-copied options into NOPs before fragmenting and clears transient RR/TS state. `__ip_options_compile()` walks option bytes, normalizes EOL padding, validates option length/pointers, enforces uniqueness for SRR/RR/TS/CIPSO, handles capability checks for user-supplied privileged options, fills RR/TS fields for received packets, records offsets and flags in `struct ip_options`, validates CIPSO, and returns ICMP parameter-problem info on error. `ip_options_get()` copies user socket option data, pads it, compiles it without an skb, and installs a new RCU options object. Forwarding updates RR/TS/SRR fields and recalculates the header checksum when changed. Received source-route handling reroutes successive nexthops, validates strict-route/local/unicast constraints, and records the next hop for forwarding.

State and persistence: compiled options are stored either in skb IPCB for received/forwarded packets or in `struct ip_options_rcu` for socket-level persistent options. The code mutates option pointer bytes, inserted addresses/timestamps, IP destination for source-route progression, and `is_changed` flags. `ip_options_undo()` restores compiled user options by reversing source-route shifts and clearing inserted RR/TS data.

Dependencies and integration: used by IPv4 output, forwarding, input option validation, raw/socket option handling, route lookup/source address selection, ICMP parameter-problem reporting, CIPSO validation, and source-route sysctls in `ip_input.c`.

Risks: option pointer arithmetic is directly exposed to untrusted packets and user socket options; off-by-one errors can become memory corruption or incorrect ICMP parameter pointers. Source routing changes packet destination and route state and must respect strict-route and local delivery constraints. Capability checks differ for received packets versus user-supplied options. Any mutation requires checksum recomputation. CIPSO validation can update the parsing pointer on failure and must be reflected in error reporting.

Test signals: packet fuzzing for malformed option lengths/pointers, RR/TS/SRR echo and forward tests, source-route enable/disable behavior, strict-route gateway failure tests, CIPSO validation tests, socket `IP_OPTIONS` set/get tests, fragment option-copy tests, ICMP parameter-problem checks, and checksum validation after option mutation.
