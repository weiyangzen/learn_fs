## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477.c

Purpose: implements the main DSA operations for the Microchip KSZ9477-family switch core. It programs global and per-port registers for reset/setup, CPU-port tagging, VLAN filtering, FDB/MDB table management, MIB counters, PHY and SGMII/PCS access, mirroring, ageing, queue split, CBS credit increment, STP reserved multicast forwarding, and HSR acceleration.

Important APIs, types, and functions: public entry points include `ksz9477_setup()`, `ksz9477_reset_switch()`, `ksz9477_switch_init()`, `ksz9477_config_cpu_port()`, `ksz9477_port_setup()`, `ksz9477_change_mtu()`, `ksz9477_get_caps()`, `ksz9477_pcs_create()`, `ksz9477_r_phy()`, `ksz9477_w_phy()`, `ksz9477_port_vlan_filtering()`, `ksz9477_port_vlan_add()`, `ksz9477_port_vlan_del()`, `ksz9477_fdb_add()`, `ksz9477_fdb_del()`, `ksz9477_fdb_dump()`, `ksz9477_mdb_add()`, `ksz9477_mdb_del()`, `ksz9477_port_mirror_add()`, `ksz9477_port_mirror_del()`, `ksz9477_set_ageing_time()`, `ksz9477_enable_stp_addr()`, `ksz9477_hsr_join()`, and `ksz9477_hsr_leave()`. Local helpers wrap 8-bit and 32-bit `regmap_update_bits()`, poll VLAN/ALU busy bits, move ALU values between four hardware registers, and access the SGMII PCS through indirect MMD registers.

Control flow: switch setup starts with `ksz9477_switch_init()` and `ksz9477_reset_switch()` clearing serial-edge selection, interrupt masks, LUE defaults, and optional refclock output. `ksz9477_setup()` enables VLAN boundary behavior, jumbo/MTU support, egress rate-limit mode, and MIB freeze support. `ksz9477_config_cpu_port()` discovers the CPU port, resolves its phy-mode from DT or hardware, calls `ksz9477_port_setup()` for the host, then disables user ports until DSA opens them. Per-port setup enables tail tags for CPU ports, queue split, back pressure, broadcast storm limit, flow control for non-PHY ports, VLAN membership, ACL initialization, wake-reason clearing, and WoL PME reset. VLAN add/delete read the hardware VLAN table, mutate untagged/member/default VID fields, write the table back, and update the VLAN cache on successful writes. FDB operations address the dynamic ALU by MAC/FID, read or build the four-word entry, update port maps, and write the entry. MDB operations scan the static ALU table for a matching or empty slot and update static multicast forwarding maps. FDB dump starts an ALU search and repeatedly polls `ALU_VALID`/`ALU_START`, converts table words to `struct alu_struct`, and invokes the DSA callback for entries forwarding to the requested port.

State and persistence: most state persists in switch registers and hardware tables: VLAN table rows, ALU and static ALU entries, port membership maps, mirror bits, reserved multicast entries, HSR port map, MIB counters, ageing timers, MTU, queue split, and PCS state. Software state includes `dev->port_mask`, `dev->cpu_port`, `dev->vlan_cache[vid].table[]`, per-port `freeze`, `link`, `speed`, `duplex`, `sgmii_adv_write`, and `pcs`. The VLAN and ALU paths are serialized by `dev->vlan_mutex` and `dev->alu_mutex`; MIB freeze/read uses `mib.cnt_mutex`.

Dependencies and integration points: this file depends on Linux DSA, phylink, PCS/XPCS, switchdev VLAN/FDB/MDB objects, bridge flags, netdevice HSR features, `regmap`, `ksz_common.h` register helpers, and constants from `ksz9477_reg.h`. It is called by the KSZ common driver through the per-chip ops table and by the bus-specific probe layers after `ksz_switch_register()`. ACL initialization comes from `ksz9477_acl.c`; tc-flower offload relies on that ACL state after port setup.

Risks: hardware access is largely poll-with-timeout; VLAN, ALU, static ALU, and MIB paths can return stale or partial behavior if a poll times out after writes have partially landed. FDB/MDB table mutation is port-map based and can unintentionally delete an entry when the last port bit is cleared. `ksz9477_port_vlan_filtering()` toggles global VLAN enable while also changing a per-port bit, so mixed filtering expectations require care. `ksz9477_port_mirror_add()` enforces one sniffer port and returns `-EBUSY` when any other sniffer exists. PCS read/write simulates IDs and rewrites SGMII state for XPCS compatibility, so regressions can appear as phylink negotiation failures. The half-duplex errata monitor only warns and reports critical resource limits; it does not recover the hardware.

Test signals: useful signals include DSA probe with the expected CPU port and phy-mode log, successful MTU changes only on the CPU port, VLAN membership/PVID behavior under bridge VLAN add/delete, FDB/MDB add/delete/dump consistency, dynamic-table flush after topology changes, MIB counters that freeze and resume without losing software accumulation, phylink operation on SGMII and non-SGMII ports, mirror add/delete with a single sniffer, ageing-time boundary tests for 1 second and the 1785 second maximum, reserved multicast delivery for STP/PTP addresses to the CPU port, and HSR join/leave feature flags plus forwarding membership restoration.

## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477.h

Purpose: declares the KSZ9477-family public interface shared by the core switch code, bus front ends, ACL implementation, tc-flower offload code, and common KSZ infrastructure. It is the local contract for switch setup, port setup, PHY/MIB/VLAN/FDB/MDB/mirror/HSR operations, ACL lifecycle, and PCS creation.

Important APIs, types, and functions: the header declares core operations such as `ksz9477_setup()`, `ksz9477_reset_switch()`, `ksz9477_switch_init()`, `ksz9477_switch_exit()`, `ksz9477_config_cpu_port()`, `ksz9477_port_setup()`, `ksz9477_get_port_addr()`, `ksz9477_get_caps()`, `ksz9477_change_mtu()`, and `ksz9477_pcs_create()`. Data-plane management declarations cover PHY read/write, MIB reads/freezing, VLAN filtering/add/delete, FDB/MDB add/delete/dump, mirror add/delete, dynamic MAC flush, ageing, queue split, CBS credit increment, STP reserved multicast, and HSR join/leave. ACL declarations include `KSZ9477_ACL_ENTRY_SIZE`, `KSZ9477_ACL_MAX_ENTRIES`, `struct ksz9477_acl_entry`, `struct ksz9477_acl_entries`, `struct ksz9477_acl_priv`, ACL allocation/free/write/sort/removal helpers, L2 match construction, action construction, processing-rule linkage, and tc-flower add/delete entry points.

Control flow: this header does not execute code, but it shapes the cross-file call graph. `ksz9477.c` provides most switch operations and calls ACL initialization/free. `ksz9477_acl.c` implements the ACL cache and hardware write helpers exposed here. `ksz9477_tc_flower.c` consumes the ACL helpers to translate `flow_cls_offload` rules into cached ACL entries. Bus files such as `ksz9477_i2c.c` do not include this header directly in the inspected version, but they eventually enter this API through `ksz_switch_register()` and the common chip-data operation table.

State and persistence: the header defines the persistent per-port ACL software model. `struct ksz9477_acl_entry` stores the 18-byte hardware image plus the tc cookie and priority used for deletion and sorting. `struct ksz9477_acl_entries` contains a fixed 16-entry table and `entries_count`. `struct ksz9477_acl_priv` wraps that table and is attached to `dev->ports[port].acl_priv` by `ksz9477_port_acl_init()`.

Dependencies and integration points: depends on `<net/dsa.h>` and `ksz_common.h` for `struct dsa_switch`, `struct ksz_device`, `struct ksz_port`, switchdev types, and common helpers. It integrates the KSZ9477 register-specific implementation with the common Microchip DSA driver and exposes prototypes expected by chip operation tables.

Risks: the ACL structures expose a fixed hardware limit of 16 entries and 18 bytes per entry; callers must maintain `entries_count` correctly or risk writing stale/zeroed entries to hardware. Many prototypes accept raw port indices and hardware-facing values, so validity checking is distributed across callers. Header changes have a broad blast radius because this file is included by the core, ACL, and tc-flower implementations.

Test signals: compile coverage is the main signal for declaration/definition drift. Runtime signals include successful ACL allocation on every initialized port, tc-flower add/delete resolving all declared helpers, and common KSZ operation tables linking against each declared switch operation.

## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477_acl.c

Purpose: implements KSZ9477 per-port Access Control List support. It maintains a 16-entry software cache mirroring hardware ACL table entries, validates and sorts simple or complex L2 match blocks, programs byte-enabled hardware ACL entries, enables/disables per-port ACL priority/authentication behavior, and provides helper functions used by tc-flower offload.

Important APIs, types, and functions: exported functions are `ksz9477_port_acl_init()`, `ksz9477_port_acl_free()`, `ksz9477_acl_write_list()`, `ksz9477_acl_remove_entries()`, `ksz9477_sort_acl_entries()`, `ksz9477_acl_action_rule_cfg()`, `ksz9477_acl_processing_rule_set_action()`, and `ksz9477_acl_match_process_l2()`. Internal helpers include `ksz9477_acl_is_valid_matching_rule()`, `ksz9477_acl_get_cont_entr()`, `ksz9477_acl_update_linkage()`, `ksz9477_acl_move_entries()`, `ksz9477_sort_acl_entr_no_back()`, `ksz9477_acl_wait_ready()`, `ksz9477_acl_entry_write()`, `ksz9477_acl_port_enable()`, `ksz9477_acl_port_disable()`, `ksz9477_acl_set_reg()`, and `ksz9477_acl_matching_rule_cfg_l2()`.

Control flow: `ksz9477_port_acl_init()` allocates `acl_priv`, marks every cached entry with byte-enable bits so zeroes can be written, and calls `ksz9477_acl_write_list()` to clear hardware. tc-flower add calls `ksz9477_acl_match_process_l2()` to append one or two matching entries, then calls action and processing-rule helpers against the first entry in the rule block. Sorting uses `ksz9477_sort_acl_entries()`, which backs up the cache, bubble-sorts valid contiguous ACL blocks by priority, and restores on failure. The block movement helpers shift entries and update action/ruleset linkages so complex rules remain contiguous and internally consistent. `ksz9477_acl_write_list()` enables ACL on the port, writes populated entries and pending zeroed removals via `ksz9477_acl_entry_write()`, clears removal byte-enable sentinels after successful writes, and disables ACL again if the table becomes empty.

State and persistence: long-lived state lives in `dev->ports[port].acl_priv->acles`: the cached hardware bytes, tc cookie, priority, and current entry count. Hardware persistence is per-port ACL table contents plus `P_PRIO_CTRL` and `REG_PORT_MRI_AUTHEN_CTRL` bits. Byte-enable bytes at offsets `0x10` and `0x11` are both cache state and hardware-write selectors. Deletion sets trailing zeroed entries with full byte-enable sentinels so the next write pass removes stale hardware rows.

Dependencies and integration points: depends on `ksz9477.h` for shared ACL structures, `ksz9477_reg.h` for register names and port priority/authentication bits, and `ksz_common.h` for `ksz_pwrite8()`, `ksz_prmw8()`, and device/port storage. It is initialized from `ksz9477_port_setup()` and consumed by `ksz9477_tc_flower.c`.

Risks: ACL hardware supports only 16 entries, and complex rules that match both source and destination MAC consume two entries. The driver intentionally does not support fragmented RuleSets; any unexpected hardware/cache linkage returns errors and may block sorting or deletion. `ksz9477_acl_update_linkage()` can fail if moving a block would shift RuleSet bits out of range. Sorting is in-place but protected by a backup restore path; a missed edge case could still leave cache and hardware diverged until the next successful write. ACL write waits for both read and write done bits with a 10 ms timeout, so slow or stuck hardware surfaces as failed offload. Initialization failure frees `acl_priv`, causing later flower offload attempts to return unsupported.

Test signals: add single L2 type-only, source-MAC, destination-MAC, and source-plus-destination rules; verify two-entry complex rules have correct RuleSet bits and action linkage. Fill exactly 16 entries and confirm the next rule returns `ACL entry limit reached`. Add rules with different priorities and verify hardware/cached order after sorting. Delete by cookie and confirm trailing hardware rows are zeroed and ACL disables when empty. Inject unsupported or malformed cached RuleSet layouts in tests to exercise restore and error logs. Verify `P_PRIO_CTRL` gets ACL priority with OR priority while active and clears ACL priority after the last rule is removed.

## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477_i2c.c

Purpose: provides the I2C bus front end for KSZ9477-family switches. It allocates a common `ksz_device`, initializes the regmap instances over I2C, binds OF compatible strings to chip-data entries, and hands the device to the common KSZ DSA registration path.

Important APIs, types, and functions: `KSZ_REGMAP_TABLE(ksz9477, not_used, 16, 0, 0)` declares the register map layout for 16-bit register addresses. `ksz9477_i2c_probe()` allocates and registers the switch. `ksz9477_i2c_remove()` calls `ksz_switch_remove()`. `ksz9477_i2c_shutdown()` calls `ksz_switch_shutdown()` and clears client data. `ksz9477_i2c_id[]`, `ksz9477_dt_ids[]`, `ksz_i2c_pm_ops`, and `ksz9477_i2c_driver` provide device matching, PM hooks, and module registration via `module_i2c_driver()`.

Control flow: the I2C core invokes probe for a matching device. Probe calls `ksz_switch_alloc(&i2c->dev, i2c)`, obtains `struct ksz_chip_data` from `device_get_match_data()`, stores the chip ID before common probing, initializes every `dev->regmap[i]` from `ksz9477_regmap_config[i]` with `dev->regmap_mutex` as the lock argument, copies optional platform data, stores the IRQ, and calls `ksz_switch_register()`. Only after successful registration does it set I2C client data. Remove and shutdown retrieve that client data and delegate lifecycle cleanup to the common driver.

State and persistence: persistent software state is the allocated `ksz_device`, its regmap pointers, chip ID, platform data pointer, IRQ number, and I2C client data association. Hardware state is not directly programmed here beyond regmap-mediated accesses performed later by the common switch driver.

Dependencies and integration points: depends on Linux I2C, regmap, module, device-tree matching, simple PM ops, and common KSZ functions from `ksz_common.h`. The compatible table maps `microchip,ksz9477`, `ksz9896`, `ksz9897`, `ksz9893`, `ksz9563`, `ksz8563`, `ksz8567`, `ksz9567`, and `lan9646` to entries in `ksz_switch_chips[]`.

Risks: probe fails with `-EINVAL` if no match data is present, so non-DT or mismatched ID-table-only use needs scrutiny. Regmap initialization must match chip register width and endian expectations; an incorrect regmap config breaks all later switch access. `i2c_set_clientdata()` is called only after successful registration, so partial probe failures rely on devm cleanup and common registration failure behavior. Shutdown clears client data after common shutdown, which prevents later remove from double-removing if the shutdown path ran first.

Test signals: OF modalias autoload for every compatible string, successful creation of all `__KSZ_NUM_REGMAPS` regmaps, clean error from intentionally bad match data, probe deferral or failure propagation from `ksz_switch_register()`, suspend/resume through `ksz_switch_suspend()` and `ksz_switch_resume()`, and shutdown/remove sequences without duplicate cleanup.

## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477_reg.h

Purpose: defines the KSZ9477-family register map and bit fields used by the switch core, ACL implementation, PTP/HSR support, PHY/SGMII access, QoS, VLAN, ALU, MIB, mirroring, policing, shaping, and queue-management code. It is definitions-only, but it is the hardware contract for the implementation files in this subset.

Important APIs, types, and functions: the key macro API is register constants plus masks/shifts, including chip IDs and revision fields, global interrupt masks, serial/refclock controls, operation/MTU/LUE/MAC controls, VLAN table controls, ALU and static ALU controls, HSR ALU and port map controls, PTP clock/trigger/timestamp registers, `PORT_CTRL_ADDR(port, addr)`, per-port default VID/control/status/PHY/SGMII/MAC/MIB/ACL/MRI/QM/LUE/PTP registers, and aliases such as `P_BCAST_STORM_CTRL`, `P_PRIO_CTRL`, `P_MIRROR_CTRL`, `S_MIRROR_CTRL`, and `S_FLUSH_TABLE_CTRL`.

Control flow: no control flow executes in this header. The macro layout structures caller behavior by splitting global blocks and per-port blocks. Core code uses `PORT_CTRL_ADDR()` and aliases to address per-port registers, polls busy bits such as `VLAN_START`, `ALU_START`, `ALU_STAT_START`, `MIB_COUNTER_READ`, `PORT_ACL_WRITE_DONE`, and `PORT_ACL_READ_DONE`, and uses masks/shifts to compose table entries and mode fields.

State and persistence: all definitions refer to hardware state. Persistent areas include the VLAN table at `0x0400`, dynamic and static ALU entries at `0x0410` through value registers, HSR tables, PTP clock/timestamp state, per-port PHY registers, MIB counters, ACL tables, priority/authentication controls, mirroring, policing/WRED, shaping, queue membership, and port LUE state. The header itself stores no software state.

Dependencies and integration points: depends on common kernel bit macros such as `BIT()`, `GENMASK()`, and field helpers used by C files. `ksz9477.c`, `ksz9477_acl.c`, and `ksz9477_tc_flower.c` include it directly; common KSZ code also consumes many aliases and constants when building chip data.

Risks: mask/shift mistakes are high impact because they silently program wrong hardware fields. Several constants are reused across related hardware concepts, such as ACL byte-enable/action/ruleset fields and ALU static/direct controls, so semantic drift can break multiple subsystems. `PORT_CTRL_ADDR(port, addr)` assumes the KSZ9477 per-port window addressing pattern; using it for global registers would target the wrong address. The register file spans features not fully implemented in this subset, so definitions can be stale without compile-time detection if unused.

Test signals: build coverage for all users of renamed or changed macros, register-level tests or hardware traces showing correct addresses for global versus per-port accesses, VLAN/ALU/ACL busy-bit polling completion, correct MIB counter indexes and queue limits, SGMII MMD access with expected device/register addresses, and feature tests for ACL priority, mirroring, HSR, PTP, and queue split using the defined masks.

## sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477_tc_flower.c

Purpose: translates a restricted subset of Linux tc-flower rules into KSZ9477 ACL entries. It supports L2/basic matches and priority-changing actions, then sorts and writes the per-port ACL cache to hardware.

Important APIs, types, and functions: public entry points are `ksz9477_cls_flower_add()` and `ksz9477_cls_flower_del()`. Internal helpers are `ksz9477_flower_parse_key_l2()`, `ksz9477_flower_parse_key()`, and `ksz9477_flower_parse_action()`. It uses flow-dissector keys `FLOW_DISSECTOR_KEY_BASIC`, `FLOW_DISSECTOR_KEY_ETH_ADDRS`, and `FLOW_DISSECTOR_KEY_CONTROL`, action `FLOW_ACTION_PRIORITY`, `flow_cls_offload_flow_rule()`, netlink extack error reporting, and ACL helpers from `ksz9477_acl.c`.

Control flow: add first checks that `dev->ports[port].acl_priv` exists, records the current `entries_count` as the action entry index, parses keys, parses actions into that first entry, sorts the ACL cache by priority, and writes the full list to hardware. Key parsing rejects unsupported dissector keys and control flags. L2 parsing accepts a full-mask EtherType and full-mask source and/or destination MAC address; source plus destination consumes two ACL entries because the hardware supports only one MAC address per matching entry. Action parsing rejects `classid` hardware traffic-class use, accepts only `skbedit priority` style priority actions from 0 through 7, and programs action/processing linkage in the selected ACL entry. Delete finds entries by `cls->cookie`, compacts the cache through `ksz9477_acl_remove_entries()`, and rewrites hardware.

State and persistence: software state is the per-port ACL cache inherited from `ksz9477_acl.c`, with each offloaded rule identified by `cls->cookie` and ordered by `cls->common.prio`. Hardware persistence is the rewritten ACL table and ACL enable/priority bits after `ksz9477_acl_write_list()`. Failed parsing before mutation leaves the cache unchanged; failures after key parsing but before write can leave appended cache entries that callers need to consider because rollback is not explicit in this file.

Dependencies and integration points: depends on DSA switch private data, Linux flow-rule/tc offload APIs, Ethernet address helpers, netlink extack reporting, and the KSZ9477 ACL builder/writer. It is exposed through declarations in `ksz9477.h` and relies on `ksz9477_port_acl_init()` having run during port setup.

Risks: the offload surface is intentionally narrow: no IPv4/IPv6/L4 keys, no partial MAC or EtherType masks, no drop/trap/redirect/mirror/police actions, and no `hw_tc` classid mapping. Capacity accounting handles one- versus two-entry L2 rules but does not perform rollback if action parsing or sorting fails after key entries were appended. Priority sorting changes table order, so action and ruleset linkage correctness depends on ACL move helpers. Returning `-EOPNOTSUPP` with extack messages is expected for many valid software flower rules that the hardware path cannot represent.

Test signals: add rules for EtherType-only, source MAC, destination MAC, and combined source/destination MAC; verify combined rules consume two entries and still match only when both conditions are true. Try partial masks, unsupported keys, unsupported actions, priority above 7, and `hw_tc` classid and confirm extack messages. Fill the ACL table and confirm capacity rejection. Delete rules by cookie and verify hardware ACL disable when the last rule is removed. Exercise failure after key parsing to detect stale cached entries.
