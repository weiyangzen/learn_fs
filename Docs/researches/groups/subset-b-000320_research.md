## sources/compression/zstd/lib/legacy/zstd_v03.c

Purpose: Implements the standalone legacy decoder for zstd v0.3 frames (`0xFD2FB523`). The file is a frozen compatibility snapshot: it embeds low-level little-endian memory helpers, a backward bitstream reader, local error helpers, Finite State Entropy decompression, Huff0 literal decompression, and the v0.3 frame/block/sequence decoder. Its public surface is the `ZSTDv03_*` wrapper layer consumed by `zstd_legacy.h`.

Important APIs, types, and functions: Public wrappers defined in this C file are `ZSTDv03_decompress()`, `ZSTDv03_findFrameSizeInfoLegacy()`, `ZSTDv03_isError()`, `ZSTDv03_createDCtx()`, `ZSTDv03_freeDCtx()`, `ZSTDv03_resetDCtx()`, `ZSTDv03_nextSrcSizeToDecompress()`, and `ZSTDv03_decompressContinue()`. The decoder context `ZSTDv03_Dctx_s` stores FSE decode tables for literal lengths, offsets, and match lengths, prefix history pointers (`base`, `previousDstEnd`), streaming state (`expected`, `phase`, `bType`), and a 128 KiB literal buffer with an 8-byte wildcopy margin. Core helpers include `ZSTD_getcBlockSize()`, `ZSTD_decodeLiteralsBlock()`, `ZSTD_decodeSeqHeaders()`, `ZSTD_decodeSequence()`, `ZSTD_execSequence()`, `ZSTD_decompressSequences()`, `ZSTD_decompressBlock()`, and the internal static `ZSTD_decompressDCtx()`. Embedded entropy code exposes local `BIT_*`, `FSE_*`, and `HUF_*` helpers but they are file-local implementation details.

Control flow: One-shot decompression validates a 4-byte frame header, then loops over 3-byte block headers until an end block. Compressed blocks decode a literal section first, using Huff0 for compressed literals, direct references or copies for raw literals, and memset for RLE literals. Sequence headers then build three FSE tables for literal length, offset code, and match length, initialize three FSE states from a backward bitstream, and repeatedly decode sequences into the caller's destination. Each sequence copies literals, resolves repeat offsets, checks match bounds against `base`, and copies matches with special handling for offsets below eight. Raw blocks are copied directly. RLE blocks are recognized but return a generic error in v0.3. The direct streaming API is a strict pull model: `nextSrcSizeToDecompress()` returns exactly the number of bytes expected for the next call, `decompressContinue()` alternates frame header, block header, and block content phases, and returns zero for metadata-only steps.

State and persistence behavior: There is no persistent external state. A one-shot call uses a stack context and sets `base` to the output buffer. A heap context created by `ZSTDv03_createDCtx()` persists entropy tables, literal buffer, phase, and prefix tracking across streaming calls until reset or free. Streaming history depends on output contiguity: if `dst` is not exactly `previousDstEnd`, the decoder resets `base` to the new destination, so callers using non-contiguous buffers lose access to prior block history. `findFrameSizeInfoLegacy()` does not decompress; it walks block headers, returns the compressed frame size, and estimates a decompressed upper bound as `nbBlocks * BLOCKSIZE`.

Dependencies and integration points: Includes `zstd_v03.h`, `../common/compiler.h`, and `../common/error_private.h`; also uses standard `stddef.h`, `stdint.h` or fallback typedefs, `string.h`, `stdlib.h`, and compiler intrinsics for byte/bit operations. `sources/compression/zstd/lib/legacy/zstd_legacy.h` dispatches magic version 3 to `ZSTDv03_decompress()` and `ZSTDv03_findFrameSizeInfoLegacy()`. Generic legacy streaming intentionally does not support versions 1-3, so this file's direct streaming functions are available to specialized callers but are not used by the modern `ZSTD_decompressLegacyStream()` wrapper.

Risks: This decoder uses performance-oriented wildcopy and pointer arithmetic from an old format implementation; correctness depends on conservative prechecks before copying. Some comments explicitly acknowledge late corruption detection around dump overreads. RLE data blocks are not implemented even though RLE literals are. The v0.3 frame has no content size, so frame-size reporting is only an upper bound by block count. `ZSTDv03_decompressDCtx()` is declared in the header but this source only defines the internal static `ZSTD_decompressDCtx()`, so external callers expecting the header symbol would fail to link unless another compatibility layer supplies it. Error-code naming in comments still references older helper names, but actual error detection routes through local `ERR_isError()` from `error_private.h`.

Test signals: Exercise magic mismatch, too-small frame headers, truncated block headers, compressed-size-over-remaining errors, end block with trailing bytes, raw blocks, compressed blocks with raw/RLE/Huff0 literals, unsupported RLE blocks, malformed FSE/Huff0 tables, offset-before-base corruption, too-small destination buffers, non-contiguous streaming buffers, exact `expected` sizes in streaming mode, and frame-size-info results for complete and truncated frames. Integration tests should verify `ZSTD_isLegacy()` dispatch for magic `0xFD2FB523` and `ZSTD_findFrameSizeInfoLegacy()` conversion of `nbBlocks * BLOCKSIZE` into the common legacy metadata.

## sources/compression/zstd/lib/legacy/zstd_v03.h

Purpose: Declares the public compatibility API for zstd v0.3 frame decompression. It is the include used by the legacy dispatcher when `ZSTD_LEGACY_SUPPORT <= 3`.

Important APIs and types: The simple API is `ZSTDv03_decompress(dst, maxOriginalSize, src, compressedSize)`. Frame sizing is exposed through `ZSTDv03_findFrameSizeInfoLegacy(src, srcSize, cSize, dBound)`, which reports compressed frame length and an upper decompressed bound. Error probing is `ZSTDv03_isError(size_t code)`. Advanced/direct streaming declarations use the opaque `ZSTDv03_Dctx` with `ZSTDv03_createDCtx()`, `ZSTDv03_freeDCtx()`, `ZSTDv03_decompressDCtx()`, `ZSTDv03_resetDCtx()`, `ZSTDv03_nextSrcSizeToDecompress()`, and `ZSTDv03_decompressContinue()`. `ZSTDv03_magicNumber` is the version-detection constant `0xFD2FB523`.

Control flow and integration: Callers either provide an entire v0.3 frame to `ZSTDv03_decompress()` or drive the direct streaming state machine by repeatedly asking for the next exact input size and passing that amount to `ZSTDv03_decompressContinue()`. `zstd_legacy.h` includes this header conditionally, detects the magic number, dispatches one-shot decompression to `ZSTDv03_decompress()`, and dispatches frame-size queries to `ZSTDv03_findFrameSizeInfoLegacy()`.

State and persistence behavior: The header exposes an opaque context, so callers do not own internal tables or history buffers directly. A context can be reused after `ZSTDv03_resetDCtx()`. Streaming callers are responsible for retaining output history in the layout expected by the implementation when matches refer to previous blocks.

Dependencies and integration points: Only includes `<stddef.h>` and is C++ compatible through `extern "C"`. The actual error-code values come from the implementation's shared legacy error scheme. It is part of the legacy decoder family selected by `ZSTD_LEGACY_SUPPORT`.

Risks: The comment for error checking references `ZSTDv01_isError()` even though the declared checker is `ZSTDv03_isError()`. `ZSTDv03_decompressDCtx()` takes `void* ctx`, making the type contract weaker than the opaque context declarations around it, and the corresponding public wrapper is not present in `zstd_v03.c`. The API cannot report an exact decompressed content size for v0.3 frames, only the implementation's upper-bound estimate.

Test signals: Compile C and C++ includers, verify the magic number in `ZSTD_isLegacy()`, check one-shot and context-based decompression paths on known v0.3 samples, verify `findFrameSizeInfoLegacy()` outputs on valid/truncated frames, and ensure version 3 is rejected by the generic legacy streaming wrapper while the direct `ZSTDv03_*Continue()` API still works.

## sources/compression/zstd/lib/legacy/zstd_v04.c

Purpose: Implements the standalone legacy decoder for zstd v0.4 frames (`0xFD2FB524`). It carries the same embedded MEM/bitstream/FSE/Huff0 decoder stack as v0.3, adds a v0.4 frame-parameter header with `windowLog`, supports dictionary/prefix continuity in the block decoder, and provides both direct `ZSTDv04_*` streaming and buffered `ZBUFFv04_*` streaming APIs used by the generic legacy streaming bridge.

Important APIs, types, and functions: Public zstd wrappers defined in this C file are `ZSTDv04_decompress()`, `ZSTDv04_decompressDCtx()`, `ZSTDv04_createDCtx()`, `ZSTDv04_freeDCtx()`, `ZSTDv04_resetDCtx()`, `ZSTDv04_nextSrcSizeToDecompress()`, and `ZSTDv04_decompressContinue()`, plus `ZSTDv04_findFrameSizeInfoLegacy()`. Exported buffered APIs are `ZBUFFv04_createDCtx()`, `ZBUFFv04_freeDCtx()`, `ZBUFFv04_decompressInit()`, `ZBUFFv04_decompressWithDictionary()`, `ZBUFFv04_decompressContinue()`, `ZBUFFv04_isError()`, `ZBUFFv04_getErrorName()`, `ZBUFFv04_recommendedDInSize()`, and `ZBUFFv04_recommendedDOutSize()`. `ZSTDv04_Dctx_s` stores FSE tables, prefix/dictionary pointers (`base`, `vBase`, `dictEnd`, `previousDstEnd`), frame params, stage, block type, literal state, and a 5-byte header buffer. `ZBUFFv04_DCtx_s` wraps a `ZSTD_DCtx`, input/output ring buffers, dictionary reference, header assembly state, and buffered-decompression stage.

Control flow: The v0.4 frame header is five bytes: magic plus a descriptor byte. `ZSTD_decodeFrameHeader_Part1()` validates magic and returns the fixed header size; `ZSTD_getFrameParams()` extracts `windowLog` from the low nibble and rejects reserved high bits; part 2 rejects overly large windows on 32-bit builds. One-shot decompression resets the context, optionally inserts a dictionary as an external prefix, decodes the frame header, then loops over block headers and content. Compressed block flow is literals then FSE-coded sequences, as in v0.3. The sequence executor can satisfy matches from the current prefix or an external dictionary segment by translating through `vBase` and `dictEnd`. Direct streaming is a four-stage state machine: get frame header size, decode frame header, decode block header, decompress block. Buffered streaming first accumulates enough header bytes to determine `windowLog`, allocates or grows `inBuff` to one block and `outBuff` to `1 << windowLog`, optionally inserts a dictionary, then alternates direct reads, buffered loads, and flushing decoded output to the caller.

State and persistence behavior: One-shot calls can allocate the decode context on heap when `ZSTD_HEAPMODE == 1`, otherwise on stack. Direct contexts persist frame stage, expected byte count, entropy tables, literal buffer, and dictionary/prefix history across calls. `ZSTD_checkContinuity()` updates prefix bookkeeping when the destination pointer is not contiguous with prior output, allowing matches across an external dictionary and current prefix. `ZBUFFv04_DCtx` persists heap buffers across frames and only grows them; `ZBUFFv04_freeDCtx()` releases the wrapped zstd context and both buffers. `ZBUFFv04_decompressWithDictionary()` stores a borrowed dictionary pointer, so the dictionary must remain valid through decompression. Frame-size-info again scans block headers and reports `nbBlocks * BLOCKSIZE` as a decompressed bound, not an exact size.

Dependencies and integration points: Includes `zstd_v04.h`, `../common/compiler.h`, `../common/error_private.h`, and `../common/debug.h`, plus standard allocation and memory headers. `zstd_legacy.h` dispatches one-shot version 4 decompression to `ZSTDv04_decompress()`, frame-size queries to `ZSTDv04_findFrameSizeInfoLegacy()`, and generic legacy streaming to the `ZBUFFv04_*` buffered API. The generic streaming bridge creates/reuses `ZBUFFv04_DCtx`, initializes it with the caller's dictionary, passes `ZSTD_inBuffer`/`ZSTD_outBuffer` windows into `ZBUFFv04_decompressContinue()`, and propagates the returned input-size hint.

Risks: RLE blocks are still rejected even though RLE literals are decoded. The buffered path allocates output history based on untrusted `windowLog`, bounded only by format checks and 32-bit restrictions. Dictionary support is borrowed-reference based and has no lifetime enforcement. The direct streaming API requires exact input sizes; the buffered API hides that but has more state transitions and partial-consumption behavior to test. Pointer arithmetic in prefix/dictionary match resolution is subtle, especially when matches span dictionary and current output. `ZSTDv04_isError()` is declared in the header but no matching definition appears in this source, while `ZBUFFv04_isError()` is defined. Some static analyzer appeasement changes differ from v0.3, so maintaining both snapshots mechanically can introduce behavior drift.

Test signals: Cover frame-header reserved-bit rejection, 32-bit large-window rejection, `windowLog`-driven buffer sizing, magic mismatch, truncated header/block cases, end block with trailing input, raw blocks, compressed blocks, unsupported RLE blocks, dictionary-only matches, matches spanning dictionary and prefix, non-contiguous direct streaming output, buffered streaming with tiny input and output slices, header split across calls, output flush backpressure, dictionary lifetime assumptions in integration tests, and `ZSTD_decompressLegacyStream()` dispatch for version 4.

## sources/compression/zstd/lib/legacy/zstd_v04.h

Purpose: Declares the public compatibility API for zstd v0.4 decompression, including one-shot, direct streaming, and buffered streaming entry points. It is the legacy header selected by `ZSTD_LEGACY_SUPPORT <= 4`.

Important APIs and types: The simple API is `ZSTDv04_decompress(dst, maxOriginalSize, src, compressedSize)`. Frame sizing is `ZSTDv04_findFrameSizeInfoLegacy(src, srcSize, cSize, dBound)`. Error probing is `ZSTDv04_isError()`. Direct streaming uses opaque `ZSTDv04_Dctx` with create/free/reset, `ZSTDv04_decompressDCtx()`, `ZSTDv04_nextSrcSizeToDecompress()`, and `ZSTDv04_decompressContinue()`. Buffered streaming uses opaque `ZBUFFv04_DCtx` with create/free, `ZBUFFv04_decompressInit()`, `ZBUFFv04_decompressWithDictionary()`, `ZBUFFv04_decompressContinue()`, `ZBUFFv04_isError()`, `ZBUFFv04_getErrorName()`, and recommended input/output size helpers. `ZSTDv04_magicNumber` is `0xFD2FB524`.

Control flow and integration: One-shot callers provide an entire frame and preallocated destination. Direct streaming callers alternate exact-size input requests with decode calls. Buffered streaming callers can pass arbitrary input and output sizes; the API updates both size pointers with consumed and produced byte counts and returns a hint for the next preferred input size, or zero at frame completion. `zstd_legacy.h` uses the one-shot APIs for whole-frame legacy decompression and uses `ZBUFFv04_*` for the common streaming compatibility path.

State and persistence behavior: `ZSTDv04_Dctx` owns direct decoder state and can be reset. `ZBUFFv04_DCtx` owns buffered state and reusable heap buffers; `ZBUFFv04_decompressWithDictionary()` records a dictionary reference that must remain accessible during decompression. The header documents that buffered output is overwritten each call, so callers must consume or persist produced bytes before reusing the output buffer.

Dependencies and integration points: Only includes `<stddef.h>` and wraps declarations in `extern "C"` for C++ callers. The header bridges old zstd v0.4 format support into the current legacy dispatcher and exposes recommended sizes matching the implementation's 128 KiB block model (`BLOCKSIZE + 3` input and `BLOCKSIZE` output).

Risks: The simple API comment again references `ZSTDv01_isError()` instead of `ZSTDv04_isError()`, and `zstd_v04.c` does not define the declared `ZSTDv04_isError()` symbol. Buffered streaming prototypes use in/out size pointers, so caller mistakes can silently lead to retry loops or dropped data if updated sizes are ignored. The dictionary API does not copy dictionary content. The exact decompressed size is not available from v0.4 frame headers, so sizing remains caller- or bound-driven.

Test signals: Compile C and C++ includers, verify magic-number detection, test one-shot and direct-streaming known v0.4 samples, exercise `ZBUFFv04_decompressContinue()` with split headers and constrained output, confirm dictionary-backed streaming through `zstd_legacy.h`, validate error-name/error-probe helpers, and check recommended buffer sizes.
