# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc-sm8550.c

Purpose: platform Common Clock Framework driver for the Qualcomm SM8550-family display clock controller. The same implementation also binds `qcom,sm8650-dispcc` and `qcom,sar2130p-dispcc`, exposing MDSS display clocks, DP/DSI link and pixel roots, two display PLLs, reset controls, and two MDSS GDSCs through the Qualcomm clock-controller framework.

Important APIs/types/functions: the file is mostly declarative data consumed by `drivers/clk/qcom` helpers. `struct clk_alpha_pll` objects `disp_cc_pll0` and `disp_cc_pll1` use Lucid OLE PLL registers and `clk_alpha_pll_reset_lucid_ole_ops`. `struct parent_map` and `struct clk_parent_data` arrays encode DT parent indices for TCXO, always-on TCXO, sleep clock, DSI PHY PLL outputs, and four DP PHY PLL link/div clocks. `struct clk_rcg2` roots cover MDSS AHB, byte, DP AUX/link/pixel, ESC, MDP, pixel, vsync, sleep, and XO sources. `struct clk_regmap_div` exposes byte and DP link dividers. `struct clk_branch` gates the exported functional clocks, including MDP/LUT, PCLK, DPTX, byte, AHB, RSCC, sleep, and XO paths. `disp_cc_sm8550_desc` packages clocks, resets, GDSCs, and regmap layout for `qcom_cc_really_probe()`.

Control flow: `disp_cc_sm8550_probe()` enables runtime PM, resumes the controller, maps the MMIO resource with `qcom_cc_map()`, applies compatible-specific data mutations, programs both PLLs via `clk_lucid_ole_pll_configure()`, sets the MDP clock-gating bit in `DISP_CC_MISC_CMD`, forces the XO branch on with `qcom_branch_set_clk_en()`, and registers the whole descriptor. On SM8650 it raises the shared Lucid OLE VCO maximum to 2.1 GHz, swaps the MDP source frequency table, and reparents the DPTX1 USB-router interface clock to the DPTX1 link divider. On SAR2130P it retunes PLL0, enables user control on both PLL configs, and restricts MDP rates to the SAR table. Error paths drop the runtime PM reference with `pm_runtime_put_sync()`.

State and persistence: the driver keeps no dynamic heap state of its own; persistent state is hardware register state plus static C objects registered with CCF, reset, and genpd. Probe mutates static PLL configuration structures and the `lucid_ole_vco` table for compatible variants before registration, so this driver assumes only one matching controller instance is bound. Hardware state includes PLL programming at offsets `0x0` and `0x1000`, root clock generator command registers, branch enable/halt registers, reset registers at `0x8000`, `0xa000`, and `0xc000`, and GDSCR state for `mdss_gdsc` and `mdss_int2_gdsc`. Runtime PM is used only to power access during probe; normal clock state is subsequently managed by CCF consumers and GDSC framework.

Dependencies and integration: depends on platform-device probing, DT compatible strings and `dt-bindings/clock/qcom,sm8550-dispcc.h`, regmap, runtime PM, the Qualcomm common clock helper layer (`common.h`, RCG, branch, alpha PLL, reset, GDSC, dividers, muxes), and external parent clocks supplied by XO/sleep/DSI/DP PHY providers. DRM/MSM display, DSI, DP, RSCC, and power-domain consumers use the numeric binding IDs exported through the descriptor.

Risks: the compatible-specific mutation of global static tables is fragile if a system ever contains more than one compatible variant or probe is retried after partial mutation. Parent maps and array indices must match the DT binding order exactly; a mismatch silently routes display clocks to the wrong PHY or PLL source. SM8650's runtime reparenting writes through a `const struct clk_init_data` object, which is unusual and should be checked carefully when refactoring. The MDP clock-gating register write and always-on XO branch are raw offsets outside descriptor validation. Rate tables include SoC-specific differences, so adding another compatible by copy-paste can produce invalid MDP rates or PLL limits.

Test signals: build with `CONFIG_SM_DISPCC_8550`, boot on SM8550, SM8650, and SAR2130P device trees, verify `/sys/kernel/debug/clk/clk_summary` includes all binding IDs and expected parents, exercise DSI0/DSI1 byte and pixel clocks, DP0-DP3 link/pixel clocks, MDP rate changes, reset controls, and `MDSS_GDSC`/`MDSS_INT2_GDSC` transitions. Probe deferral should be tested when DP/DSI PHY parent clocks are unavailable. There are no local unit tests; meaningful validation is boot/display bring-up plus clock summary and suspend/resume coverage.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc-sm8750.c

Purpose: platform CCF driver for the Qualcomm SM8750 display clock controller. It registers the SM8750 MDSS clock tree, including DSI/DP PHY-facing roots, MDP and pixel clocks, esync clocks, an internal oscillator path, three alpha PLLs, reset lines, and two MDSS GDSCs.

Important APIs/types/functions: `disp_cc_pll0` and `disp_cc_pll1` are Taycan ELU alpha PLLs backed by `clk_alpha_pll_taycan_elu_ops`; `disp_cc_pll2` is a Pongo ELU PLL sourced from `DT_SLEEP_CLK` and used as a 38.4 MHz oscillator source. Parent maps select between TCXO, DSI byte/DSI clocks, DP0-DP3 link and VCO-div outputs, and internal PLL outputs. RCGs define esync0/1, MDSS AHB, byte0/1, DPTX0-DPTX3 AUX/link/pixel, ESC, MDP, pclk0/1/2, vsync, oscillator, sleep, and XO sources. Branches gate functional outputs, including `DISP_CC_MDSS_ACCU_SHIFT_CLK`, three pclk branches, esync branches, DP crypto clocks, and RSCC clocks. `disp_cc_sm8750_desc` exports clocks, three resets, and two GDSCs.

Control flow: `disp_cc_sm8750_probe()` enables runtime PM, resumes the hardware, maps the controller with `qcom_cc_map()`, configures PLL0/PLL1 with `clk_taycan_elu_pll_configure()`, configures PLL2 with `clk_pongo_elu_pll_configure()`, enables MDP clock gating through `DISP_CC_MISC_CMD`, then forces sleep, XO, RSCC AHB, and RSCC vsync branches on. Finally it calls `qcom_cc_really_probe()` and releases the runtime PM reference. Failure after resume uses a shared `err_put_rpm` path.

State and persistence: all exported state is represented by static clock objects and hardware registers. PLL0/PLL1 are high-frequency display PLLs with Taycan ELU VCO range up to 2.5 GHz; PLL2 is a fixed 38.4 MHz Pongo ELU oscillator. The regmap caps accessible registers at `0xf004` because later addresses such as `0x10000` and `0x10004` are reserved for TrustZone or other secure firmware. Branch enable bits and PLL programming persist in hardware after probe, while CCF manages subsequent enables, parent changes, and rates. Runtime PM is used to make probe-time register access safe and is not otherwise customized by the file.

Dependencies and integration: depends on the SM8750 display clock DT binding, platform resources, runtime PM, regmap, Qualcomm clock helpers, and external parent providers for TCXO, sleep, DSI PHY PLLs, and DP PHY PLLs. It integrates with display drivers through numeric `qcom,sm8750-dispcc.h` IDs, reset-controller IDs for MDSS core/INT2/RSCC, and genpd IDs for `MDSS_GDSC` and `MDSS_INT2_GDSC`.

Risks: PLL2 and the oscillator tree add another dependency path compared with SM8550; wrong sleep-clock parenting can break `DISP_CC_OSC_CLK`. The comment about downstream Cesta voting on the MDP source means the upstream driver may not match downstream power/performance policy for MDP votes. Several always-on branches are enabled by literal offsets, so register-map drift would not be caught by compiler checks. The secure-register `max_register` limit must remain correct or regmap debug/clock code could touch protected addresses. As with other generated-style Qualcomm clock drivers, binding ID order and parent-map order are high-risk maintenance points.

Test signals: boot on SM8750 hardware or emulator with display DT enabled, inspect `clk_summary` for PLL0/PLL1/PLL2, esync, pclk2, oscillator, RSCC, and DP/DSI roots, exercise MDP rates from 85.714286 MHz through 575 MHz, validate DSI byte clocks with `CLK_OPS_PARENT_ENABLE`, test reset controls and GDSC transitions, and verify no secure-address regmap access warnings occur. Suspend/resume and probe deferral of PHY parent clocks are useful integration checks.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc-x1e80100.c

Purpose: display clock-controller driver for Qualcomm X1E80100 platforms. It registers the MDSS display clock tree for laptop-class Snapdragon hardware, including two Lucid-style display PLLs, DSI and DP roots for up to four DP PHY paths, MDP/pixel/vsync/AHB clocks, reset controls, and MDSS power domains.

Important APIs/types/functions: `disp_cc_pll0` and `disp_cc_pll1` are defined as Lucid OLE register layouts but are configured in probe with `clk_lucid_evo_pll_configure()`, with a shared VCO range up to 2.3 GHz. Parent maps include TCXO, always-on TCXO, sleep, DSI byte/DSI outputs, DP0-DP3 link clocks, DP VCO-div clocks, and PLL0/PLL1 main/even outputs. RCGs expose MDSS AHB, byte, DPTX AUX/link/pixel, ESC, MDP, pclk, vsync, sleep, and XO roots. Dividers model byte and read-only DPTX link dividers. Branch clocks gate ACCU, AHB, byte, DP link/pixel/USB-router, ESC, MDP/LUT, pclk, RSCC, and vsync outputs. `disp_cc_x1e80100_resets` additionally provides ARES resets for DPTX0/1/2 USB-router link interface clocks.

Control flow: `disp_cc_x1e80100_probe()` enables runtime PM, resumes the controller, maps registers, configures both PLLs with `clk_lucid_evo_pll_configure()`, enables the MDP clock-gating bit in `DISP_CC_MISC_CMD`, forces sleep and XO branches on, then registers the descriptor with `qcom_cc_really_probe()`. The platform driver is registered with `subsys_initcall()` rather than `module_platform_driver()`, making it available earlier in boot; module exit unregisters the driver if built as a module.

State and persistence: persistent state is hardware register programming plus static CCF/reset/GDSC registrations. The controller regmap uses 32-bit registers, stride 4, maximum register `0x11008`, and fast I/O. The GDSCs at `0x9000` and `0xa000` retain flip-flop state and are hardware-controlled with CFG polling. The driver forces sleep and XO clocks on at offsets `0xe074` and `0xe054` before registration. No private runtime data is allocated beyond framework-managed registrations.

Dependencies and integration: depends on `dt-bindings/clock/qcom,x1e80100-dispcc.h`, platform DT compatible `qcom,x1e80100-dispcc`, runtime PM, regmap, Qualcomm clock helpers, reset framework, and GDSC/genpd. It integrates with X1E display consumers, DSI/DP PHY clock providers, USB-router DP interface reset consumers, and MDSS power-domain consumers.

Risks: the PLL declaration names Lucid OLE register arrays while probe uses Lucid EVO configuration helpers; this may be intentional for shared register layout, but it is easy to break during cleanup. Early `subsys_initcall()` ordering can expose more probe-deferral paths if parent PHY clocks are not available. DPTX USB-router ARES reset entries are bit-level resets inside clock branch registers, so incorrect register offsets can impact active display links. The X1E DP parent maps differ from phone SoCs by allowing DP0 link on more paths; copy-paste from SM8550/SM8750 would be unsafe.

Test signals: boot X1E80100 with display DT, verify early driver registration, inspect `clk_summary` for all MDSS, DPTX0-DPTX3, MDP, pclk, sleep, and XO clocks, exercise DP USB-router interface resets, validate the MDSS core/INT2/RSCC resets, and confirm `MDSS_GDSC`/`MDSS_INT2_GDSC` power-domain control. Runtime PM error paths and parent-clock deferral should be covered because the driver probes early.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc0-sa8775p.c

Purpose: first SA8775P display clock-controller instance driver, binding `qcom,sa8775p-dispcc0`. It exposes one MDSS display clock island with two Lucid EVO PLLs, two DSI PHY inputs, two DP PHY inputs, DP crypto/link/pixel paths, MDP/pixel/vsync/AHB roots, resets, and two MDSS core GDSCs.

Important APIs/types/functions: the namespace is `mdss_0_disp_cc_*`. `mdss_0_disp_cc_pll0` and `mdss_0_disp_cc_pll1` use `CLK_ALPHA_PLL_TYPE_LUCID_EVO` and `clk_alpha_pll_lucid_evo_ops`; PLL0 is configured around the high MDP rates while PLL1 feeds AHB and other display roots. Parent data includes DT interface clock placeholder `DT_IFACE`, TCXO/AO TCXO, sleep, DP0/DP1 link and VCO-div clocks, and DSI0/DSI1 byte/DSI outputs. RCGs cover AHB, byte0/1, DPTX0/1 AUX/crypto/link/pixel0-3 where applicable, ESC0/1, MDP, pclk0/1, vsync, sleep, and XO. Dividers expose byte and read-only DPTX link divides. Branches gate the complete MDSS set plus `mdss_0_disp_cc_sm_obs_clk`. `disp_cc_0_sa8775p_desc` registers the clock table, two reset lines, and two GDSCs.

Control flow: `disp_cc_0_sa8775p_probe()` enables runtime PM, resumes hardware, maps registers with the descriptor, configures PLL0 and PLL1, forces the sleep and XO branches on by register offset, calls `qcom_cc_really_probe()`, drops the runtime PM reference, and returns the framework registration result. If mapping fails, it puts runtime PM and returns the mapped error. Unlike some newer DISPCC drivers, this probe does not explicitly set an MDP gating bit.

State and persistence: the driver stores no instance-private state. Hardware state persists in the mapped register block through PLL programming, RCG/divider registers, branch enable bits, reset registers, and GDSC registers at `0x9000` and `0xd000`. The regmap allows up to `0x12414`. The two GDSCs use `PWRSTS_OFF_ON`, `POLL_CFG_GDSCR`, `RETAIN_FF_ENABLE`, and `HW_CTRL`, so power switching is delegated to hardware and genpd after registration. The always-on sleep/XO writes keep low-frequency roots available for downstream display and retention behavior.

Dependencies and integration: depends on `dt-bindings/clock/qcom,sa8775p-dispcc.h`, compatible `qcom,sa8775p-dispcc0`, runtime PM, regmap, Qualcomm clock helpers, reset and GDSC frameworks, and parent clocks from GCC/TCXO/sleep, DSI PHYs, and DP PHYs. Consumers use shared `MDSS_DISP_CC_*` binding IDs, so this instance is distinguished by provider phandle rather than unique numeric IDs.

Risks: `dispcc0` and `dispcc1` are almost identical source files, so fixes can easily land in only one instance. Shared binding IDs require DT to reference the correct provider; swapping phandles can make a display pipeline control the wrong clock island. Several DPTX0 pixel roots expose four pixel clocks while DPTX1 exposes two; consumers must match the hardware lane/stream layout. The probe's map-failure path uses `pm_runtime_put()` rather than `pm_runtime_put_sync()`, unlike some neighboring drivers. Parent-map and static-name copy-paste errors are the main maintenance risk.

Test signals: boot SA8775P with the `dispcc0` node enabled, verify all `mdss_0_disp_cc_*` clocks in `clk_summary`, test MDP rates at 375/500/575/650 MHz, DSI byte/pixel roots, DP0 four-pixel and DP1 two-pixel paths, DP crypto/link clocks, reset lines for MDSS core and RSCC, and both GDSCs. Cross-test with `dispcc1` active to ensure providers remain independent and clock names do not collide unexpectedly.

# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc1-sa8775p.c

Purpose: second SA8775P display clock-controller instance driver, binding `qcom,sa8775p-dispcc1`. It mirrors the `dispcc0` hardware model for the second MDSS display island and exports a namespaced set of display clocks, PLLs, resets, and GDSCs.

Important APIs/types/functions: the namespace is `mdss_1_disp_cc_*`. The PLLs, parent maps, RCGs, dividers, branch clocks, reset map, regmap config, and GDSC definitions are structurally the same as `dispcc0`, but all clock names and static symbols are suffixed with `1`. `mdss_1_disp_cc_pll0` and `mdss_1_disp_cc_pll1` are Lucid EVO alpha PLLs with the same VCO range and configuration values as instance 0. The exported clock table maps shared `MDSS_DISP_CC_*` binding IDs to instance-1 clock objects. The match table contains only `qcom,sa8775p-dispcc1`.

Control flow: `disp_cc_1_sa8775p_probe()` follows the same sequence as `dispcc0`: enable runtime PM, resume, map with `qcom_cc_map()`, configure PLL0/PLL1 using `clk_lucid_evo_pll_configure()`, force sleep and XO branches on at offsets `0xc070` and `0xc054`, register the descriptor with `qcom_cc_really_probe()`, then release runtime PM. The driver is registered with `module_platform_driver()`.

State and persistence: static objects represent all CCF, reset, and power-domain nodes. Hardware state persists in the second controller's MMIO range, not in any software cache. GDSCs at `0x9000` and `0xd000` retain state and are hardware-controlled. Reset entries cover MDSS core BCR at `0x8000` and RSCC BCR at `0xa000`. The only notable source-level divergence from `dispcc0` is symbol/name substitution, including `disp_cc_1_parent_data_7_ao` for the sleep parent data despite it carrying `DT_SLEEP_CLK`.

Dependencies and integration: depends on the same SA8775P display binding header and Qualcomm clock stack as `dispcc0`, but integrates through the second DT provider node. Display pipelines, DP/DSI PHYs, and MDSS power domains must reference the `dispcc1` phandle when controlling the second display controller instance.

Risks: because this file is generated or cloned from `dispcc0`, drift is both the main risk and the main review signal. Any functional fix to clock rates, reset offsets, GDSC flags, or branch halt behavior should be applied to both files unless hardware documentation says otherwise. The `_7_ao` parent-data name for a sleep-clock parent is harmless to C but can mislead reviewers and automated audits. Shared binding IDs make provider selection in DT critical. Runtime PM and map-failure behavior has the same caveats as `dispcc0`.

Test signals: boot SA8775P with both display clock-controller nodes, confirm `mdss_1_disp_cc_*` clocks register separately from instance 0, validate MDP, DSI, DP0/DP1, ESC, AHB, vsync, PLL lock-monitor, sleep, XO, reset, and GDSC behavior for the second display island, and run simultaneous or alternating display-pipeline tests to catch accidental cross-provider use. No direct in-tree unit tests exist for this file.
