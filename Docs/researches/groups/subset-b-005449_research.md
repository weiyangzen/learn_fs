## sources/distributed-fs/ceph-client/drivers/tty/n_gsm.c

Purpose: this file implements the GSM 07.10 / 3GPP 27.010 tty multiplexor line discipline (`N_GSM0710`) and the dynamic `gsmtty` virtual tty driver used for demultiplexed DLCI channels. It frames bytes on an underlying tty into GSM mux frames, opens and closes DLCIs, carries virtual modem status, exposes ioctls for mux/DLCI configuration, and can turn selected DLCIs into point-to-point IP netdevices.

Important types and APIs: `struct gsm_mux` is the per-ldisc mux object containing the underlying tty, receive parser state, tx work item, timers, DLCI table, tx queues, config, and counters. `struct gsm_dlci` is each logical channel with a tty port, kfifo or skb queue, state machine, modem bits, flow-control flags, and optional `net_device`. `struct gsm_msg` is the queued transmit frame representation, and `struct gsm_control` serializes one outstanding DLCI0 control command. The registered ldisc is `tty_ldisc_packet`; virtual tty operations are `gsmtty_ops`; tty port callbacks are `gsm_port_ops`; netdevice operations are created by `gsm_mux_net_init()`.

Control flow: `gsmld_open()` requires `CAP_NET_ADMIN`, allocates a mux, attaches it to the underlying tty, disables normal tty XON/XOFF handling, and waits for userspace configuration. `GSMIOC_SETCONF` calls `gsm_config()`, validates timing/MRU/MTU/encoding/adaption/initiation fields, activates the mux through `gsm_activate_mux()`, registers dynamic `gsmtty` devices, and optionally begins DLCI0 opening with SABM. Incoming bytes go through `gsmld_receive_buf()` into `gsm0_receive()` for basic framing or `gsm1_receive()` for advanced framing; valid frames enter `gsm_queue()`, which handles SABM/DISC/UA/DM and dispatches UI/UIH payloads either to DLCI0 command processing or to a DLCI data callback. Outgoing virtual tty writes enter a per-DLCI kfifo via `gsmtty_write()`, are swept by `gsm_dlci_data_sweep()`, encoded in `__gsm_data_queue()`, and serialized by `gsmld_write_task()` through the underlying tty. Control commands such as MSC, PN, TEST, FCON/FCOFF, and CLD are encoded on DLCI0, with retry and timeout handling on `t2_timer`.

State and persistence: mux lifetime is managed by `gsm_mux[]` plus a kref, and DLCI lifetime is tied to `tty_port` references. DLCIs move through `DLCI_CLOSED`, `DLCI_WAITING_CONFIG`, `DLCI_CONFIGURE`, `DLCI_OPENING`, `DLCI_OPEN`, and `DLCI_CLOSING`; T1 retransmits SABM/DISC/PN setup paths, T2 retransmits control commands, and the keep-alive timer sends TEST probes when configured. Persistent runtime state includes per-DLCI tx FIFOs/skb queues, modem_rx/modem_tx bits, remote/local flow-control flags named `constipated`/`throttled`, outstanding tx byte counts, and optional network-mode adaption changes. No on-disk persistence exists; all state is ldisc, tty, timer, and netdev state.

Dependencies and integration points: the driver integrates with the tty ldisc registry, tty core dynamic driver registration, tty ports, kfifo, skbuff/netdevice APIs, `linux/gsmmux.h` ioctls and structures, timers, workqueues, wait queues, and user copy helpers. It expects an underlying tty driver with a working `.write` path. Userspace configures the mux with `GSMIOC_*` ioctls, opens `/dev/gsmtty*` channels, and may enable a `gsm%d` point-to-point IP interface with `GSMIOC_ENABLE_NET`.

Risks: the file is concurrency-heavy: ldisc close, virtual tty close, timers, workqueues, receive callbacks, ioctls, and netdevice callbacks share mux/DLCI state. Comments still flag lifetime and tx-locking review areas. Some close paths intentionally skip proper DISC on ldisc shutdown because tty core has already locked/closed the port. `gsmld_attach_gsm()` appears to preserve only `IXON | IXOFF` bits rather than clearing them, despite the comment saying normal XON/XOFF handling should be turned off. The tx scheduler can starve higher-numbered DLCIs because it scans from low DLCI numbers and breaks after each successful send. Basic-mode modem status via MSC waits synchronously for a single outstanding control command and can time out. Netdevice mode mutates the DLCI data callback and adaption while tty state still exists, so mutex coverage around enable/disable matters. Parser robustness depends on FCS, MRU, and state checks; malformed or overlong frames increment counters but are not otherwise exposed.

Test signals: useful coverage includes ldisc registration/unregistration, `GSMIOC_GETCONF/SETCONF` and extended config validation, DLCI open/close for initiator and responder modes, PN negotiation success/failure, SABM/DISC retry timeout behavior, basic and advanced receive parser tests with bad FCS/size/escaping, XON/XOFF and FCON/FCOFF flow-control paths, MSC modem-bit propagation including `TIOCMIWAIT`, virtual tty write/read/hangup/throttle/unthrottle/break behavior, keep-alive timeout closure, `GSMIOC_ENABLE_NET` transmit/receive/disable, repeated ldisc attach/detach under active ports, and race testing with close while timers/work/netdev activity are pending.

## sources/distributed-fs/ceph-client/drivers/tty/n_hdlc.c

Purpose: this file implements the generic `N_HDLC` tty line discipline for synchronous HDLC-style devices. It preserves frame boundaries across the tty API: each write is one transmit frame, each receive callback is one received frame, and each read returns one complete frame or a partial continuation through the tty read cookie.

Important types and APIs: `struct n_hdlc` is the per-tty ldisc state with pending tx/rx lists, free-buffer lists, a deferred write work item, and `tbusy`/`woke_up` reentrancy flags. `struct n_hdlc_buf` stores a single frame, and `struct n_hdlc_buf_list` wraps a list, count, and spinlock. The registered `tty_ldisc_ops` is `n_hdlc_ldisc`, with `.open`, `.close`, `.read`, `.write`, `.ioctl`, `.poll`, `.receive_buf`, `.write_wakeup`, and `.flush_buffer` callbacks.

Control flow: `n_hdlc_tty_open()` allocates state, initializes work, sets `TTY_NO_WRITE_SPLIT`, sets `receive_room` to 65536, and flushes driver receive data. Receive callbacks validate against the module `maxframe`, obtain or allocate an rx buffer, copy the received frame, queue it, and wake readers/SIGIO. Reads wait on `tty->read_wait`, pop one queued frame, copy from the requested offset, keep the frame in `*cookie` for continuation when the caller buffer is smaller than the frame, and return the buffer to the free list or free excess rx buffers. Writes wait for a free tx buffer, clamp oversized frames to `maxframe`, copy the frame, enqueue it, and call `n_hdlc_send_frames()`. The send loop calls the underlying `tty->ops->write()` only with complete frame buffers, returns unaccepted frames to the head of the tx queue, and uses write wakeups/workqueue scheduling to resume later.

State and persistence: all state is per-line-discipline and in memory. Default allocations are ten rx buffers and three tx buffers sized by `maxframe`, with receive buffers allowed to grow up to `MAX_RX_BUF_COUNT`. `maxframe` is a module parameter clamped during init to 4096..65535. Queue state is protected by per-list spinlocks; write reentrancy is managed by `tbusy` and `woke_up`. Close wakes blocked readers/writers, cancels the work item, frees all queues, clears `TTY_NO_WRITE_SPLIT`, and drops `tty->disc_data`.

Dependencies and integration points: depends on tty ldisc registration, tty wait queues, tty write wakeup flags, `n_tty_ioctl_helper()` for common tty ioctls, `tty_chars_in_buffer()`, list/spinlock helpers, workqueues, and user-copy wrappers indirectly through tty core. The intended lower-level device must provide frame-oriented receive callbacks and a write method that accepts a whole frame or rejects it; otherwise frame semantics degrade.

Risks: oversized writes are silently truncated to `maxframe` rather than rejected, which may surprise HDLC users expecting frame atomicity. The receive path allocates with `GFP_ATOMIC` after the free list is exhausted and drops frames on allocation failure or overlength input. Poll checks list emptiness without taking list locks, so it relies on benign races for readiness hints. The code assumes the low-level driver's write method follows the all-or-nothing frame convention documented in the header; a driver returning a short positive count causes the entire frame to be requeued after bytes may already have left the device. `tty_for_write_work` stores a tty pointer for the work item, so close must continue to cancel work synchronously before freeing state.

Test signals: attach/detach `N_HDLC`, blocking and nonblocking reads/writes, frame preservation with small read buffers and cookie continuation, `FIONREAD` returning the next frame size, `TIOCOUTQ` including queued frame bytes, `TCFLSH` tx flush behavior, write wakeup resumption after an initial `-ENOSPC`/short write, receive drops for oversize frames and exhausted rx buffers, module parameter clamp behavior, and close while readers/writers/work are pending.

## sources/distributed-fs/ceph-client/drivers/tty/n_null.c

Purpose: this file implements the minimal `N_NULL` line discipline used as a failure-path placeholder. It accepts registration as a tty ldisc but provides no data transport.

Important APIs and functions: `n_null_read()` and `n_null_write()` both return `-EOPNOTSUPP`. `null_ldisc` sets `.owner`, `.num = N_NULL`, `.name = "n_null"`, `.read`, and `.write`. Module lifecycle is `n_null_init()` registering the ldisc and `n_null_exit()` unregistering it.

Control flow: module init calls `tty_register_ldisc(&null_ldisc)` and uses `BUG_ON()` if registration fails. Once selected, tty read or write attempts immediately fail with operation-not-supported. There are no receive, open, close, poll, ioctl, or buffer callbacks.

State and persistence: there is no per-tty private state, no buffering, no timers, and no persistent state. The only state is global registration of the ldisc with the tty core while the module is loaded.

Dependencies and integration points: depends only on the tty ldisc registration API and standard Linux module infrastructure. It integrates with tty fallback/error handling by providing a named ldisc number that can be installed when a real ldisc cannot be used.

Risks: `BUG_ON()` during module init turns registration failure into a kernel bug rather than a recoverable error, which is consistent with a core fallback discipline but still severe. Because no `.open`/`.close` methods exist, the tty core must not expect private state. Any caller assuming reads/writes behave like `/dev/null` would be wrong; this discipline rejects I/O rather than discarding writes or returning EOF.

Test signals: build and module load/unload, successful registration under `N_NULL`, read and write returning `-EOPNOTSUPP`, and fallback selection paths that install `N_NULL` without dereferencing missing callbacks.

## sources/distributed-fs/ceph-client/drivers/tty/n_tty.c

Purpose: this file implements the default `N_TTY` line discipline: canonical and noncanonical terminal input processing, echoing, job-control signal generation, input/output termios transformations, software flow control, packet-mode notifications for ptys, read/write/poll/ioctl behavior, and inheritance support for ldisc subclasses.

Important types and APIs: `struct n_tty_data` holds circular read and echo buffers, producer-published `read_head`/`commit_head`/`canon_head`, consumer `read_tail`, canonical line flags, echo operation cursors, termios-derived mode booleans (`raw`, `real_raw`, `icanon`), flow lookahead count, overrun counters, column state, and `atomic_read_lock`/`output_lock`. Key registered callbacks are in `n_tty_ops`: `n_tty_open()`, `n_tty_close()`, `n_tty_receive_buf()`/`receive_buf2`, `n_tty_lookahead_flow_ctrl()`, `n_tty_read()`, `n_tty_write()`, `n_tty_poll()`, `n_tty_ioctl()`, `n_tty_set_termios()`, and `n_tty_flush_buffer()`. `n_tty_inherit_ops()` exports the operation table to related line disciplines.

Control flow: open allocates `n_tty_data`, initializes locks, installs it in `tty->disc_data`, recomputes termios-derived mode state, and unthrottles the tty. Receive processing enters `n_tty_receive_buf_common()`, computes safe ring-buffer room, applies throttling decisions, and dispatches to real raw, raw, closing, or standard character processing. Standard mode handles strip/lowercase conversion, EXTPROC, signal chars, CR/LF mapping, canonical erase/word erase/kill/reprint/lnext/EOF/EOL handling, PARMRK expansion, and echo buffering. Canonical line delimiters set read flags and publish `canon_head`; noncanonical/raw paths publish `commit_head`. Reads serialize with `atomic_read_lock`, enforce job-control checks, honor VMIN/VTIME, handle pty packet status, copy canonical lines or raw bytes from the circular buffer, publish `read_tail`, and kick/unthrottle input when room opens. Writes perform TOSTOP job-control checks, flush pending echoes, optionally apply OPOST transformations through `process_output_block()`/`process_output()`, and wait for write room when needed.

State and persistence: all state is per-open ldisc and volatile. The read buffer is 4096 bytes with separate bit flags for canonical delimiters and EOF markers; the echo buffer is another 4096-byte ring using encoded operations for cursor movement, tab erasure, canonical-column updates, and escaped control display. Memory ordering is explicit: producers use release stores for `commit_head`/`canon_head`, consumers use acquire loads and release stores for `read_tail`, and echo byte publication uses a write/read barrier pair. Termios changes rebuild the special-character bitmap and may synthesize an EOF push when switching into canonical mode with pending data. Packet-mode flush state is stored in the linked pty's `ctrl.pktstatus`.

Dependencies and integration points: depends on tty core locking (`termios_rwsem`, write locks, tty ports), wait queues, fasync SIGIO, process/job-control helpers, termios macros from `tty.h`, tty audit hooks, flip-buffer work restart/flush helpers, pty packet mode, user-visible ioctls (`TIOCINQ`, `TIOCOUTQ`), and low-level tty driver `.write`, `.flush_chars`, throttle/unthrottle, and write-room behavior. As the default line discipline, other tty paths rely on `n_tty_open()` being robust and on `n_tty_init()` registering successfully during tty initialization.

Risks: this is a high-concurrency core path where producer receive callbacks, consumer reads, writes, termios changes, ldisc close, throttling, and pty packet notifications share ring-buffer state. Canonical overflow behavior intentionally processes but may stop storing excess line data until a delimiter arrives, so regressions can silently drop input. Echo handling is subtle because echo operations are generated without `output_lock` and later interpreted atomically. Signal processing temporarily upgrades from read to write `termios_rwsem` to flush buffers, which is delicate. VMIN/VTIME and packet-mode read interactions are easy to regress. `TIOCINQ` uses a write lock to compute canonical counts and skip EOF markers; changes to read flags can affect user-visible byte counts. Because this is default tty behavior, even small ordering or wakeup bugs can manifest as terminal hangs, lost wakeups, or data exposure; the code explicitly zeroes canonical no-echo input as a privacy measure.

Test signals: canonical read lines with newline/EOL/EOL2/EOF, erase/word erase/kill/reprint/lnext including UTF-8 continuation handling, echo modes (`ECHO`, `ECHOE`, `ECHOK`, `ECHOKE`, `ECHOPRT`, `ECHOCTL`, `ECHONL`), raw and real-raw throughput, VMIN/VTIME combinations, CR/LF and OPOST mappings, IXON/IXOFF/IXANY software flow control and lookahead, signal generation with and without `NOFLSH`, pty packet-mode flush/status bytes, `TIOCINQ`/`TIOCOUTQ`, poll readiness, throttle/unthrottle thresholds for ptys and real drivers, hangup while blocked in read/write, termios switches between canonical/noncanonical/EXTPROC, and stress tests with concurrent receive/read/write/termios changes.

## sources/distributed-fs/ceph-client/drivers/tty/nozomi.c

Purpose: this file implements the PCI tty driver for Option/GlobeTrotter Nozomi HSDPA cards. It maps the card's shared memory/register interface, performs a two-phase card configuration handshake, exposes up to four user tty ports per card (`noz*`), and moves data between tty FIFOs and card uplink/downlink buffers using interrupt-driven flow control.

Important types and APIs: `struct nozomi` is per-card state with BAR mapping, FCR/IIR/IER register pointers, cached interrupt-enable mask, card type, config table, PCI device, five internal ports, send buffer, spinlock, tty minor base, state, and open tty count. `struct port` wraps a `tty_port`, uplink FIFO, card buffer addresses/sizes/toggles, control-line state, wait queue, and async modem counters. `struct config_table`, `struct toggles`, `struct ctrl_dl`, and `struct ctrl_ul` mirror card-provided little- or big-endian shared-memory layouts. PCI lifecycle is `nozomi_card_init()`/`nozomi_card_exit()` in `nozomi_driver`; tty operations are in `tty_ops`; tty-port callbacks are `noz_tty_port_ops`.

Control flow: module init allocates and registers a dynamic tty driver, then registers the PCI driver. Probe finds a free minor range, enables PCI, requests regions, determines card memory size (`F32_2` or `F32_8`), maps BAR0, allocates the temporary send buffer and per-port uplink FIFOs, initializes register pointers, requests the shared IRQ, creates sysfs files, records the card in `ndevs[]`, enables the RESET interrupt, and registers four tty devices. Interrupt handling masks IIR by `last_ier`, handles RESET by reading the config table, handles control uplink/downlink, then handles downlink and uplink tokens for modem, diagnostic, app1, and app2 channels. Downlink data is read from the active toggle buffer into the tty flip buffer and acknowledged via FCR; uplink data is pulled from a kfifo into card memory and acknowledged when the card can accept it. Tty writes enqueue bytes into the per-port FIFO and enable uplink interrupts; open/close enable or disable downlink tokens for that port.

State and persistence: hardware-visible state lives in the card's shared memory window and interrupt registers. Software state includes `last_ier`, per-port uplink/downlink toggles, per-port control-line snapshots, FIFO contents, async line-change counters, and `open_ttys`. Card initialization moves through `NOZOMI_STATE_ENABLED`, `NOZOMI_STATE_ALLOCATED`, and `NOZOMI_STATE_READY`; tty install rejects opens until READY. Sysfs exposes `card_type` and `open_ttys`. There is no persistent storage beyond PCI device state and module globals.

Dependencies and integration points: depends on PCI core, tty driver/port/flip-buffer APIs, kfifo, shared IRQ handling, MMIO accessors, sysfs device attributes, serial modem ioctls/counters, and Linux wait queues. Users interact through `/dev/noz*`, modem-control ioctls (`tiocmget`, `tiocmset`, `TIOCMIWAIT`, `get_icount`), and normal tty read/write. Card protocol integration uses config-table offsets, FCR acknowledgements, IER masking, and CTS/DTR/RTS-style control messages exchanged on the control channel.

Risks: much of the driver runs under one spinlock while doing MMIO, FIFO movement, and tty flip-buffer insertion; this can increase interrupt latency and makes sleep safety important. `tty_exit()` busy-waits for `open_ttys` to drop and the source comment calls the area racy. Several paths print with `printk()` rather than device-scoped logging. Flow-control and toggle synchronization are fragile: mismatched tokens log errors and can leave a channel disabled or out of sync. `read_mem32()`/`write_mem32()` cast buffers between `u32 *` and `u16 *`, which can be alignment-sensitive. Only modem uplink has special two-buffer toggle handling in `handle_data_ul()`; other ports use simpler paths. Tty installation depends on `NOZOMI_STATE_READY`, so a failed or delayed config handshake makes registered devices unusable. Removal writes a control token to request reset before freeing resources; failures there are not checked.

Test signals: PCI probe/remove with repeated load/unload, config-table first-phase and second-phase handling, sysfs attribute creation/removal, READY transition after APP2 flow control, interrupt masking/acknowledgement for every token bit, modem and diagnostic downlink with both toggle buffers, uplink FIFO draining under CTS on/off, tty open/close/hangup while interrupts arrive, throttle/unthrottle RTS behavior, `TIOCMIWAIT` and line-counter updates for CTS/DSR/RI/DCD, card removal during IRQ/read/write, multi-card minor allocation up to `NOZOMI_MAX_CARDS`, and stress with high-rate data to verify no flip-buffer/FIFO/toggle stalls.
