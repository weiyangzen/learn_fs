# sources/distributed-fs/ceph-client/drivers/gpu/drm/drm_drv.c

Purpose: implements the DRM core's device-instance lifecycle, minor-node allocation/registration, hot-unplug protection, internal pseudo-filesystem inode support, device wedged uevents, cgroup memory-region registration, and module-level DRM core initialization/exit. It is the central bridge between bus-specific DRM drivers, userspace character devices, sysfs/debugfs, accel nodes, GEM initialization, modeset registration, and managed `drm_device` cleanup.

Important APIs/types/functions: global state includes `drm_minors_xa`, `drm_core_init_complete`, `drm_unplug_srcu`, the pseudo-fs mount counters `drm_fs_cnt`/`drm_fs_mnt`, and the DRM char-device stub fops. Minor helpers `drm_minor_get_xa()`, `drm_minor_get_slot()`, `drm_minor_alloc()`, `drm_minor_register()`, `drm_minor_unregister()`, `drm_minor_acquire()`, and `drm_minor_release()` manage `struct drm_minor` objects for primary, render, and accel nodes. Public lifecycle APIs include `drm_put_dev()`, `drm_dev_enter()`, `drm_dev_exit()`, `drm_dev_unplug()`, `drm_dev_set_dma_dev()`, `__devm_drm_dev_alloc()`, `__drm_dev_alloc()`, `drm_dev_alloc()`, `drm_dev_get()`, `drm_dev_put()`, `drm_dev_register()`, and `drm_dev_unregister()`. Support APIs include `drm_dev_wedged_event()`, `drmm_cgroup_register_region()`, and compat-control symlink creation/removal. Module entry/exit are `drm_core_init()` and `drm_core_exit()`.

Control flow: core init initializes connector IDs and memcpy helpers, creates the DRM sysfs class/debugfs root, registers the DRM major with `drm_stub_fops`, initializes accel/panic/privacy/RAS support, then marks the core ready. Device init requires that flag, takes references on the parent device, initializes krefs/lists/locks/managed resources, rejects drivers that claim both compute accel and graphics features, allocates an anonymous inode from the internal pseudo-fs, allocates required minors, initializes GEM when requested, stores `dev->unique`, and initializes per-device debugfs. Minor allocation reserves legacy primary/render ranges first and falls back to extended minors, while accel uses its own range; registration adds debugfs, adds the sysfs device, then publishes the xarray entry so opens can find it. Device registration validates modeset config for non-legacy load drivers, registers debugfs, registers render/primary/accel minors, creates the legacy `controlD*` symlink for modeset primary nodes, marks the device registered, optionally invokes deprecated `driver->load`, registers all modeset objects, and registers panic/sysrq clients. Unregistration reverses those user-visible registrations, invokes unload when present, unregisters minors, removes links, and finalizes debugfs. The char-device open path acquires a minor by inode minor number, grabs the driver's real fops, replaces the file fops, and delegates to the driver's open callback. Hot-unplug sets `dev->unplugged`, synchronizes SRCU readers, unregisters the device, and invalidates CPU mappings from `dev->anon_inode`.

State and persistence: `struct drm_device` lifetime is kref-managed and commonly embedded in driver-private containers freed through `drmm_add_final_kfree()`. Managed resources attached with `drmm_*` live until final `drm_dev_put()`, which is distinct from bus-device devres lifetime and is important for userspace-visible objects that may outlive physical unbind. Minor objects are allocated as managed resources and stay tied to device lifetime, but their xarray entries are set to `NULL` when inactive. The xarrays, DRM major registration, sysfs/debugfs roots, accel state, panic/privacy/RAS state, pseudo-fs mount, connector ID allocator, and `drm_core_init_complete` are module-global state. `dev->unplugged`, `dev->registered`, `dev->unique`, `dev->anon_inode`, `dev->dma_dev`, minor slots, locks, and lists persist across normal operation until managed release. The pseudo-fs inode gives DRM a real `address_space` for mmap tracking; it is freed in the device init release action.

Dependencies and integration: depends on Linux xarray, kref, device model, sysfs/debugfs, pseudo-fs/VFS, SRCU, cgroup device-memory registration, uevents, module init/exit, and DRM subsystems such as GEM, modeset, connector IDs, panic, privacy screen lookup, RAS generic netlink, accel, sysrq client support, managed resources, and debug logging. Driver-facing integration is through `struct drm_driver` feature bits, fops, optional `load`/`unload`/`release`, GEM and modeset helpers, `devm_drm_dev_alloc()`/Rust allocation wrappers, and bus-specific probe/remove paths. Userspace integration is through `/dev/dri/*` and accel char devices, sysfs minor devices and compatibility control symlinks, debugfs, kobject uevents for wedged devices, and mmap invalidation on unplug.

Risks: registration ordering is security- and race-sensitive because xarray publication makes nodes openable; publishing before full initialization or failing to unpublish on error can expose inconsistent driver state. Deprecated `driver->load` runs after device nodes are visible, so legacy users must tolerate userspace races. Hot-unplug correctness depends on every hardware-touching path using `drm_dev_enter()`/`drm_dev_exit()` and avoiding devres-managed hardware resources outside protected regions. Minor allocation must preserve legacy numbering expectations while handling extended minors and accel-major separation. Error unwinds must remove debugfs/sysfs/minors/control links symmetrically. `drm_dev_wedged_event()` assumes a primary minor/kdev for the uevent target. The pseudo-fs and anonymous inode bookkeeping must pair every pin/allocation with release. Lifetime mistakes around `dev->dev`, `dev->dma_dev`, managed resources, and final kfree can produce use-after-free or leaks, especially with open files during unbind.

Test signals: build `CONFIG_DRM` with and without `CONFIG_DRM_ACCEL`, GEM, modeset, debugfs, panic, RAS, privacy screen, and cgroup dmem support. Probe/remove representative display, render-only, and accel drivers; verify `/dev/dri/card*`, `/dev/dri/renderD*`, accel minors, sysfs devices, debugfs directories, and `controlD*` symlinks appear and disappear correctly. Exercise open while unregistering, open after unregistering, hot unplug with active mmap/open files, driver probe error unwinds at each minor/debugfs/sysfs stage, deprecated `load` failure, and modeset registration failure. Validate reference leaks with kref/debug object tooling, lockdep/SRCU coverage, `WARN_ON(!xa_empty(&drm_minors_xa))` on module exit, wedged uevent payloads for valid/unknown recovery flags, DMA device reference replacement, and cgroup region unregister on final device release.

# sources/distributed-fs/ceph-client/drivers/gpu/drm/drm_dumb_buffers.c

Purpose: provides the DRM/KMS common dumb-buffer ioctl helpers used for simple scanout-capable framebuffer allocation, mmap offset creation, and destruction. It standardizes a minimal userspace path for early boot graphics and generic DRM clients while still delegating actual backing-object allocation to driver callbacks.

Important APIs/types/functions: `drm_mode_align_dumb()` validates and rounds pitch/size after a driver/helper has determined an initial pitch. `drm_mode_size_dumb()` is exported for drivers to calculate pitch and total allocation size from width, height, color mode, and hardware alignment. `drm_mode_create_dumb()` validates ioctl arguments, clears output fields, and calls `dev->driver->dumb_create`. `drm_mode_create_dumb_ioctl()` wraps create and clears outputs on failure. `drm_mode_mmap_dumb()` calls `dev->driver->dumb_map_offset` or falls back to `drm_gem_dumb_map_offset()`. `drm_mode_mmap_dumb_ioctl()` clears `offset` on failure. `drm_mode_destroy_dumb()` checks dumb-buffer support and deletes the GEM handle through `drm_gem_handle_delete()`. `drm_mode_destroy_dumb_ioctl()` exposes destroy to ioctl dispatch. Key data types are `struct drm_mode_create_dumb`, `struct drm_mode_map_dumb`, `struct drm_mode_destroy_dumb`, `struct drm_device`, `struct drm_file`, `struct drm_driver`, and `struct drm_format_info`.

Control flow: size calculation first maps the requested `bpp` color-mode constant to a driver-supported fourcc through `drm_driver_color_mode_format()`. If a valid format exists, it obtains format metadata and minimum pitch for plane 0; otherwise it accepts legacy/deprecated bpp values and computes `width * ceil(bpp/8)`, warning once for unknown modes. The helper rejects zero or overflowing pitch, stores a 32-bit pitch, rounds pitch to hardware alignment, defaults size alignment to `PAGE_SIZE`, rejects non-page-aligned custom size alignment, checks `height * pitch` overflow, aligns size, and rejects zero size. Create rejects drivers without `dumb_create`, zero dimensions, arithmetic overflow in the legacy 32-bit stride/size precheck, and page-align wraparound; then it clears `handle`, `pitch`, and `size` before invoking the driver callback. Mmap rejects drivers without dumb-buffer support and delegates offset allocation to the driver or GEM default. Destroy rejects unsupported devices and deletes the handle from the caller's file handle table.

State and persistence: this file owns no persistent global state. Persistent effects are produced by delegated callbacks: successful create returns a GEM or driver-specific handle in the caller's `drm_file`, mmap offset allocation records an mmap token in the device/GEM address space, and destroy removes the handle reference. The ioctl wrappers deliberately scrub output fields on failure so userspace does not observe stale kernel stack or caller-provided garbage. Size/pitch fields in the argument structure are transient outputs and must be trusted only after a zero return.

Dependencies and integration: integrated with DRM ioctl dispatch through declarations in `drm_crtc_internal.h` and UAPI structs in `drm_mode.h`. It depends on driver callbacks in `struct drm_driver`, DRM format helpers (`drm_driver_color_mode_format()`, `drm_format_info()`, `drm_format_info_min_pitch()`), overflow/alignment helpers, GEM handle and dumb-map helpers, page-size constraints required by mmap, and DRM logging. Drivers such as shmem, DMA, VRAM, simple display, and hardware-specific KMS drivers commonly call `drm_mode_size_dumb()` from their `.dumb_create` implementations, then allocate the actual object through their memory manager.

Risks: dumb buffers are intentionally simple scanout buffers, not a portable acceleration allocation API; using them for GPU rendering can select memory with unsuitable tiling, caching, or placement. Format handling preserves compatibility with legacy userspace that passes arbitrary `bpp`, so unknown values may over-allocate rather than fail after a one-time warning. Alignment handling currently rejects non-page-aligned size alignment, which may matter for hardware with unusual constraints. The create path's precheck uses legacy cpp/stride arithmetic before the driver callback, so drivers still need their own validation for format-specific or multi-plane requirements. Destroy assumes GEM handles via `drm_gem_handle_delete()` even though the overview notes non-GEM drivers need a destroy operation; this tree's current implementation therefore fits GEM-backed dumb handles. Failure paths must keep output clearing behavior intact to avoid userspace confusion or information exposure.

Test signals: exercise `DRM_IOCTL_MODE_CREATE_DUMB`, `DRM_IOCTL_MODE_MAP_DUMB`, mmap, framebuffer creation, page flip/scanout, and `DRM_IOCTL_MODE_DESTROY_DUMB` on drivers with GEM default mapping and drivers with custom `dumb_map_offset`. Fuzz zero dimensions, huge dimensions, large/unknown `bpp`, overflow boundaries near `U32_MAX`, hardware pitch alignment, custom size alignment, and page-align wraparound. Verify failure returns clear `handle`/`pitch`/`size` or `offset`, valid creates return page-aligned nonzero size and usable pitch, repeated destroy/invalid handle paths fail cleanly, and generic DRM clients/fbdev emulation can allocate and tear down dumb buffers without leaks.
