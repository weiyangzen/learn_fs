# sources/distributed-fs/ceph-client/arch/x86/kvm/vmx/nested.c

Purpose: Implements KVM's Intel VMX nested virtualization engine for an L1 hypervisor running an L2 guest. The file emulates VMX root/non-root state for L1, exposes virtual VMX capability MSRs, manages VMCS12 and VMCS02 state, performs VM-entry consistency checks, handles VMX instructions executed by L1, reflects selected L2 exits to L1, and serializes nested state for migration. It is the concrete backend behind `vmx_nested_ops` for Intel VMX.

Important APIs/types/functions: The public entry points include `nested_vmx_hardware_setup()`, `nested_vmx_hardware_unsetup()`, `nested_vmx_setup_ctls_msrs()`, `nested_vmx_set_vmcs_shadowing_bitmap()`, `nested_vmx_free_vcpu()`, `vmx_leave_nested()`, `nested_vmx_enter_non_root_mode()`, `nested_vmx_reflect_vmexit()`, `__nested_vmx_vmexit()`, `nested_sync_vmcs12_to_shadow()`, `vmx_set_vmx_msr()`, `vmx_get_vmx_msr()`, `get_vmx_mem_address()`, `nested_vmx_check_io_bitmaps()`, and `nested_vmx_check_restored_vmcs12()`. Static instruction handlers implement `VMXON`, `VMXOFF`, `VMCLEAR`, `VMPTRLD`, `VMPTRST`, `VMLAUNCH`, `VMRESUME`, `VMREAD`, `VMWRITE`, `INVEPT`, `INVVPID`, and `VMFUNC`. The exported `struct kvm_x86_nested_ops vmx_nested_ops` wires nested VMX into common x86 KVM callbacks for events, state get/set, page mapping, dirty logging/PML, and Hyper-V eVMCS hooks.

Important state: `struct vcpu_vmx::nested` is the main persistence point. It tracks VMXON state, SMM VMX state, `vmxon_ptr`, `current_vmptr`, cached `vmcs12`, cached shadow VMCS12, VMCS02, shadow/eVMCS mappings, nested VPID, posted interrupt state, preemption timer state, dirty/sync flags, MSR bitmap recalc flags, PML-full state, and migration-only markers such as `EVMPTR_MAP_PENDING`. VMCS12 is the L1-owned virtual VMCS for L2. VMCS02 is the hardware VMCS used by L0 to actually run L2 after merging L0's VMCS01 requirements with L1's VMCS12 controls. Shadow VMCS and Hyper-V enlightened VMCS paths provide alternate acceleration/synchronization forms of VMCS12.

Control flow: Hardware setup calls `nested_vmx_setup_vmcs12_fields()`, constructs virtual VMX MSR defaults with `nested_vmx_setup_ctls_msrs()`, optionally allocates VMREAD/VMWRITE shadow bitmaps, initializes shadow-field metadata, and installs VMX instruction exit handlers. L1 enters VMX operation through `handle_vmxon()`, which checks CR4.VMXE, CPL, fixed CR0/CR4 bits, `IA32_FEATURE_CONTROL`, VMXON pointer validity, and revision id before `enter_vmx_operation()` allocates VMCS02, cached VMCS12 structures, shadow VMCS, timer state, and a nested VPID.

Nested VM entry starts in `nested_vmx_run()`. It validates that L1 is in VMX operation, handles Hyper-V enlightened VMPTRLD, copies eVMCS or shadow VMCS fields into VMCS12, checks launch state, checks controls, address-size/host state, and sets `nested_run_pending`. `nested_vmx_enter_non_root_mode()` switches to VMCS02, prepares early controls, maps required guest pages, checks late controls and guest state, enters guest mode, merges guest/host state in `prepare_vmcs02()`, loads entry MSRs, schedules event reevaluation, and starts the emulated VMX preemption timer if requested. Failures are split into VMfail, consistency-check VM-exit, or KVM internal error according to Intel VMX semantics.

VMCS02 construction is split by cost/frequency. `prepare_vmcs02_constant_state()` initializes VMCS02 once with L0-owned invariant fields: VE info, VMFUNC disablement, MSR bitmap physical address, PML disabled state, ENCLS bitmap, notify window, MSR autoload/autostore addresses, and host state. `prepare_vmcs02_early()` merges execution, pin, entry, and exit controls, intentionally taking some controls only from VMCS12 and some from VMCS01. `prepare_vmcs02_rare()` writes expensive guest segment, descriptor, PDPTR, APIC, page-fault, EOI, TSC-autostore, CET, and CR mask state. `prepare_vmcs02()` then updates DR7/DEBUGCTL/CET/MPX/PAT/TSC scaling, MMU context, CR0/CR4 read shadows, EFER, CR3, PDPTRs, PMU MSRs, RSP/RIP, and eVMCS clean-field state.

Nested VM exit flows through `nested_vmx_reflect_vmexit()` and `__nested_vmx_vmexit()`. L0 first decides whether it must consume an exit itself via `nested_vmx_l0_wants_exit()`; this includes host page faults/APF, EPT violations/misconfigurations, external interrupts, MCE, preemption timer, VMFUNC, PML full, bus locks, some debug paths, and Hyper-V L2 TLB flush hypercalls. If L0 does not require the exit, `nested_vmx_l1_wants_exit()` consults VMCS12 controls, exception bitmap, IO/MSR bitmaps, CR masks, VMCS shadow bitmaps, APIC controls, SGX ENCLS bitmap, and instruction-specific rules. Reflected exits update VMCS12 with exit reason, qualification, interrupt information, vectoring information, guest state, MSR store list values, and launch state; then KVM switches back to VMCS01, unmaps nested pages, reloads L1 host state from VMCS12, and requests event injection if L1 has pending interrupts/NMIs.

Event flow: `vmx_has_nested_events()` reports nested preemption timer, MTF, and virtual interrupt delivery work. `vmx_check_nested_events()` implements a detailed Intel event-priority order across INIT, SIPI, exceptions, MTF, preemption timer, SMI, NMI, external interrupts, interrupt-window exits, and posted interrupts. It blocks events while VM-entry or reinjection is pending, records pending debug exceptions for VMCS fields, performs NMI/INTR VM-exits when L1 requested them, handles ACK-on-exit semantics, and treats nested posted interrupts as PIR-to-RVI updates rather than normal injected events.

VMX instruction emulation: `nested_vmx_succeed()`, `nested_vmx_failInvalid()`, and `nested_vmx_failValid()` implement VMX instruction flag and error-field conventions. `get_vmx_mem_address()` decodes VMX memory operands from VM-exit qualification and instruction info, including address-size truncation, FS/GS long-mode treatment, LAM untagging, canonical checks, and protected-mode segment checks. VMREAD/VMWRITE operate on VMCS12, shadow VMCS12, or eVMCS fields depending on guest mode and eVMCS state; VMWRITE honors read-only fields unless the virtual MISC MSR allows writing any supported field, strips reserved AR-byte bits, and marks VMCS12 dirty. INVEPT and INVVPID validate operands against exposed virtual capabilities and invalidate KVM MMU roots or VPIDs. VMFUNC supports EPTP switching by reading the L1 EPTP list, validating the new EPTP, updating nested EPT MMU context, and flushing when VPID is unavailable.

Capability MSR behavior: `nested_vmx_setup_ctls_msrs()` synthesizes the virtual VMX capability MSR image from host `vmcs_config`, KVM policy, and emulated features. It exposes some capabilities even when software emulates them, including MSR bitmaps, VMCS shadowing, PML with EPT A/D support, EPTP switching, unrestricted guest, APIC access virtualization, SGX ENCLS exiting, and VPID invalidation extents. `vmx_set_vmx_msr()` and helper restore functions validate userspace-provided nested VMX MSRs during migration, rejecting unsupported or unsafe feature/reserved bits, anti-feature constraints, mismatched VMCS revision/size, invalid control MSR masks, and capability changes while VMXON is active. `vmx_get_vmx_msr()` returns the current virtual capability MSR values, including compatibility non-true control MSRs.

Memory/MMU behavior: Nested EPT uses `nested_ept_init_mmu_context()` to switch the vCPU to `guest_mmu`, set `get_guest_pgd` to VMCS12's EPTP, and install `nested_ept_inject_page_fault()` for EPT violation/misconfiguration injection back to L1. EPTP validation enforces memory type, page-walk level, GPA legality, reserved bits, and A/D capability. INVEPT frees matching nested EPT roots. INVVPID syncs effective `vpid02` and, without host EPT, frees guest-mode shadow roots. VM entry and exit transitions use `nested_vmx_transition_tlb_flush()` to emulate VPID-disabled flushes, VPID changes, Hyper-V nested flush requests, and cases where L1/L2 lack distinct TLB tags.

Shadow and enlightened VMCS behavior: Shadow VMCS support is controlled by `enable_shadow_vmcs` and CPU support. VMREAD/VMWRITE bitmaps are derived from `vmcs_shadow_fields.h`, filtered for fields present in VMCS12 and hardware-dependent fields such as PML/preemption timer. `copy_shadow_to_vmcs12()` and `copy_vmcs12_to_shadow()` synchronize writable/readable fields. Hyper-V eVMCS support maps an enlightened VMCS page, validates its version or VMCS12 revision workaround, copies clean-field groups into VMCS12 only when dirty, copies VMCS12 back into eVMCS for migration or sync, and maintains Hyper-V assist metadata. eVMCS paths are especially migration-sensitive because the mapped page may be restored after VMCS12 state.

State and persistence behavior: VMCS12 state persists in guest memory at `current_vmptr` and in KVM's `cached_vmcs12`. `nested_release_vmcs12()` flushes cached VMCS12 to guest memory and frees nested MMU roots. `vmx_get_nested_state()` serializes VMXON status, current VMCS pointer, eVMCS flag, SMM nested flags, guest-mode/run-pending/MTF flags, preemption timer deadline, VMCS12, and optional shadow VMCS12 to userspace. `vmx_set_nested_state()` validates the userspace nested-state header, tears down old nested state, re-enters VMX operation, restores VMCS12/eVMCS/shadow state, handles SMM nested flags, validates restored controls/host/guest state, and optionally re-enters non-root mode without reloading entry MSRs. `vmx_leave_nested()` forces an L2-to-L1 synthetic exit before freeing all nested allocations.

Dependencies and integration points: The file depends on VMX core helpers in `vmx.h`, VMCS12 layout helpers in `vmcs12.h`, common x86 KVM state in `x86.h`/`x86_ops.h`, MMU helpers in `mmu.h`, CPUID policy, PMU MSRs, Hyper-V nested/eVMCS support, APICv/posted interrupt support, SGX ENCLS controls, SMM state, tracepoints, objtool/percpu helpers, and x86 register/MSR definitions. It integrates with vCPU run loops through VM-exit handlers and `vmx_nested_ops`, with userspace ABI through `KVM_GET_NESTED_STATE`/`KVM_SET_NESTED_STATE`, with migration through VMX MSR restore and nested state serialization, and with dirty logging through PML emulation.

Risks: This is a high-risk correctness and security file because it emulates hardware-defined VMX behavior at privilege boundaries. Missed consistency checks can produce hardware VMfail after KVM has partially mutated software state; the file contains `warn_on_missed_cc` paths and explicit unwind logic for this. Incorrect VMCS12/VMCS02 synchronization can corrupt L1-visible guest state, lose injected events, or leak L0-only state to L1. Event priority and vectoring state are subtle and can break interrupt/NMI/exceptions under nested guests. MSR bitmap merging must preserve L0 userspace MSR filters while respecting L1's intent. EPT/VPID invalidation mistakes can produce stale translations across L1/L2. eVMCS clean-field handling can lose state during migration. Host-state load checks, CET/MPX/PAT/EFER handling, and segment canonical checks are security-sensitive because they control transitions between virtual privilege domains.

Test signals: Important signals include KVM selftests for VMXON/VMPTRLD/VMCLEAR/VMREAD/VMWRITE/VMLAUNCH/VMRESUME failure modes, nested state migration tests, Hyper-V eVMCS tests, nested EPT and EPTP switching tests, INVEPT/INVVPID tests, APICv/posted interrupt tests, PML dirty logging tests, preemption timer/MTF tests, event priority tests for NMI/IRQ/#PF/#DB/INIT/SIPI, PMU and MSR load/store tests, SGX ENCLS exiting coverage, CET state tests, and L1 hypervisors such as KVM-on-KVM or Hyper-V-on-KVM booting and migrating real L2 guests. Runtime warnings for missed consistency checks, VMX aborts, internal emulation exits, or unexpected VM-instruction errors are strong regression signals.

# sources/distributed-fs/ceph-client/arch/x86/kvm/vmx/nested.h

Purpose: Declares the nested VMX interface used by the VMX backend and provides small inline helpers for inspecting VMCS12 controls, virtual VMX capabilities, nested EPT state, and CR fixed-bit validity. It is the local contract between `nested.c`, VMX core code, VMCS12 layout code, Hyper-V eVMCS support, and common x86 KVM nested callbacks.

Important APIs/types/functions: `enum nvmx_vmentry_status` classifies nested VM-entry outcomes as success, VMfail, VM-exit, or KVM internal error. The main function declarations cover lifecycle (`vmx_leave_nested()`, `nested_vmx_free_vcpu()`), hardware setup/teardown (`nested_vmx_hardware_setup()`, `nested_vmx_hardware_unsetup()`, `nested_vmx_setup_ctls_msrs()`, `nested_vmx_set_vmcs_shadowing_bitmap()`), migration/restore validation (`nested_vmx_check_restored_vmcs12()`), VM-entry/exit (`nested_vmx_enter_non_root_mode()`, `nested_vmx_reflect_vmexit()`, `__nested_vmx_vmexit()`, inline `nested_vmx_vmexit()`), VMCS sync (`nested_sync_vmcs12_to_shadow()`), virtual VMX MSRs (`vmx_set_vmx_msr()`, `vmx_get_vmx_msr()`), VMX memory operand decoding (`get_vmx_mem_address()`), and I/O bitmap checks (`nested_vmx_check_io_bitmaps()`). It also declares `extern struct kvm_x86_nested_ops vmx_nested_ops`.

Control flow: The header itself has no heavyweight control flow, but its inline `nested_vmx_vmexit()` wraps `__nested_vmx_vmexit()` and decides whether to read `VM_EXIT_INSTRUCTION_LEN` from the current VMCS. Failed VM-entry, unknown exit reason, and `to_vmx(vcpu)->fail` paths pass instruction length zero; normal exits pass the hardware-reported instruction length. The rest of the inlines are predicates or value computations used throughout VMX entry, exit, event, and validation paths.

State and persistence behavior: `get_vmcs12()` and `get_shadow_vmcs12()` return KVM's cached VMCS12 buffers and assert that callers hold `vcpu->mutex` or the VM is being destroyed. `vmx_has_valid_vmcs12()` treats either a normal current VMPTR or an enlightened VMCS pointer as indicating that nested state must include VMCS12. `nested_get_vpid02()` returns the L2-specific VPID when allocated, otherwise the L1 VPID. `nested_ept_get_eptp()` and `nested_ept_ad_enabled()` read the active nested EPTP from VMCS12. `nested_read_cr0()` and `nested_read_cr4()` reconstruct the values L2 would read by combining guest CR values with VMCS12 read-shadow bits and guest/host masks.

Capability predicates: The header centralizes common tests for virtual VMX features advertised to L1 and enabled in VMCS12. Examples include `nested_cpu_has_vmwrite_any_field()`, zero-length injection, monitor trap flag support, VMCS shadowing capability, primary and secondary execution-control bits, preemption timer, NMI exiting, virtual NMIs, EPT, XSAVES, PML, virtual x2APIC, VPID, APIC register virtualization, virtual interrupt delivery, posted interrupts, VMFUNC, EPTP switching, shadow VMCS, save-preemption-timer, external interrupt exiting, and ENCLS exiting. These helpers keep the implementation aligned with Intel's distinction between "available in capability MSRs" and "enabled in this VMCS12."

Validation helpers: `fixed_bits_valid()` implements the VMX fixed0/fixed1 rule for CR0/CR4. `nested_guest_cr0_valid()` relaxes CR0.PE and CR0.PG fixed0 requirements only when unrestricted guest is both exposed in virtual VMX MSRs and enabled in VMCS12. `nested_host_cr0_valid()` applies host CR0 fixed bits without the unrestricted guest relaxation. `nested_cr4_valid()` combines VMX fixed-bit checks with `__kvm_is_valid_cr4()`, and the header aliases guest/host CR4 validation to that helper. `nested_cpu_has_no_hw_errcode_cc()` exposes the VMX basic capability bit that changes VM-entry error-code consistency checks.

Dependencies and integration points: The header includes `kvm_cache_regs.h`, `hyperv.h`, `vmcs12.h`, and `vmx.h`, so it depends on VMX vCPU state, Hyper-V eVMCS helpers, VMCS12 field definitions, VMX control bits, and common register-cache helpers. It is included by nested VMX implementation code and by VMX core paths that need to detect nested exits, nested EPT, valid VMCS12 state, or nested capability constraints.

Risks: Because many helpers are inline policy predicates, a subtle bit-test error can affect VM-entry validation, exit routing, or CR legality across the whole nested VMX backend. The lockdep assertions on VMCS12 access are important: callers that bypass the vCPU mutex while userspace can mutate nested state risk stale or torn VMCS12 reads. The unrestricted guest CR0 relaxation must match both virtual capability exposure and VMCS12 controls, or KVM can accept invalid guest state or reject legal L2 real-mode entries. The `nested_vmx_vmexit()` instruction-length shortcut must stay aligned with failed-entry behavior so L1 sees architecturally correct exit information.

Test signals: Build coverage should catch declaration drift with `nested.c` and VMX core users. Runtime/selftest signals include nested VM-entry outcome classification, VMCS12 serialization requirements, nested EPT enablement, VPID selection, CR0/CR4 fixed-bit validation with and without unrestricted guest, VM-exit instruction-length fields for normal and failed entries, and Hyper-V eVMCS migration paths that rely on `vmx_has_valid_vmcs12()`.
