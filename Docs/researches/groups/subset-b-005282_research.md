# sources/distributed-fs/ceph-client/drivers/scsi/lpfc/lpfc_attr.c

Purpose: implements the Broadcom/Emulex `lpfc` driver's module-parameter, sysfs, and Fibre Channel transport-attribute surface. It turns adapter/vport configuration fields into readable and sometimes writable `/sys/class/scsi_host/host*/` files, exposes FC transport callbacks to the SCSI FC transport class, and provides operational controls for link state, HBA reset, SR-IOV, firmware update/reset/dump, Express Lane/OAS, RAS logging, congestion/VMID/NVMe/SCSI statistics, and legacy register access.

Important APIs/functions: public entry points include `lpfc_get_cfgparam()`, `lpfc_get_vport_cfgparam()`, `lpfc_nvme_mod_param_dep()`, `lpfc_alloc_sysfs_attr()`, `lpfc_free_sysfs_attr()`, `lpfc_selective_reset()`, `lpfc_emptyq_wait()`, and `lpfc_sli4_pdev_status_reg_wait()`. The file exports `lpfc_hba_groups`, `lpfc_vport_groups`, `lpfc_transport_functions`, and `lpfc_vport_transport_functions`. The local macro families `lpfc_param_*` and `lpfc_vport_param_*`, paired with `LPFC_ATTR*` macros from `lpfc_attr.h`, generate most show/init/set/store functions and `DEVICE_ATTR` declarations. Major hand-written sysfs handlers include `lpfc_cmf_info_show()`, `lpfc_vmid_info_show()`, `lpfc_nvme_info_show()`, `lpfc_scsi_stat_show()`, `lpfc_link_state_store()`, `lpfc_board_mode_store()`, `lpfc_issue_reset()`, `lpfc_poll_store()`, `lpfc_topology_store()`, `lpfc_link_speed_store()`, `lpfc_sriov_nr_virtfn_store()`, `lpfc_fcp_imax_store()`, `lpfc_cq_max_proc_limit_store()`, `lpfc_fcp_cpu_map_show()`, the OAS `lpfc_oas_*` handlers, RAS firmware-log handlers, and binary `sysfs_ctlreg_*` accessors.

Control flow: driver probe calls `lpfc_get_cfgparam()` to copy module globals into `struct lpfc_hba`, validate ranges, force dependency-derived values, configure FCoE/NVMe/FCP/BlockGuard constraints, size queues/interrupt channels, and initialize SLI4-only features. Vport creation calls `lpfc_get_vport_cfgparam()` for per-vport options such as logging, queue depth, devloss timeout, discovery threads, and scan direction. The SCSI host class registers `lpfc_hba_groups` or `lpfc_vport_groups`, causing show/store functions to be called from sysfs. Many show paths format cached state only; others issue mailbox reads such as `MBX_READ_CONFIG`, `MBX_READ_STATUS`, or `MBX_READ_LNK_STAT`. Writable controls parse ASCII values, validate ranges, update `cfg_*` fields, and may issue link initialization/down mailbox commands, post offline/online events to the work queue, modify interrupt/CQ hardware state, invoke PCI/SR-IOV helpers, or call firmware update/reset helpers. The FC transport class calls `lpfc_transport_functions` to refresh dynamic host/rport/starget attributes and statistics.

State and persistence: most state is runtime kernel state in `struct lpfc_hba` and `struct lpfc_vport` `cfg_*` fields, with initial values coming from module parameters. Sysfs writes generally affect the live driver instance and are not persisted by this file across module reloads. Some actions change external persistent or hardware-visible state: firmware upgrade/dump/reset requests, PCI bus reset, SR-IOV VF enablement, RAS firmware logging registration/buffer allocation, OAS LUN table updates, FC fabric symbolic-name registration, and link topology/speed changes through mailbox commands. Statistics reset persists offset baselines in `psli->lnk_stat_offsets` and clears congestion/FPIN counters. Devloss timeout writes also update existing SCSI and NVMe remote ports. `lpfc_fcp_cpu_map_show()` uses `curr_disp_cpu` as a paged display cursor across reads.

Dependencies and integration: depends on the Linux module-parameter API, device/sysfs APIs, SCSI host and FC transport classes, PCI/AER/SR-IOV helpers, NVMe-FC conditionally, mailbox/mempool routines, workqueue event paths, spinlocks/completions/timers, per-CPU statistics, and many lpfc internal headers for SLI3/SLI4, discovery, vport, NVMe, logging, and hardware registers. Attribute groups are consumed by SCSI host registration; FC transport templates are registered with the SCSI FC transport layer. OAS handlers integrate with `lpfc_enable_oas_lun()`, `lpfc_find_next_oas_lun()`, and `lpfc_disable_oas_lun()`. Binary `ctlreg`/`mbox` files are physical-port-only and keep legacy user-space integration, though mailbox access is now refused in favor of BSG.

Important behavior details: `lpfc_link_state_store()` only accepts `up` or `down` and calls HBA link callbacks. `lpfc_issue_lip()` is a historical name; it brings the link down and reinitializes it with mailbox commands. `lpfc_do_offline()` posts prep/offline events and waits up to about five seconds for outstanding transmit-completion queues. `lpfc_board_mode_store()` multiplexes high-impact commands: online/offline/warm/error, firmware dump/reset, device reset, PCI bus reset, heartbeat, and trunking. `lpfc_sli4_pdev_reg_request()` temporarily disables SR-IOV VFs, offlines the port for reset-like commands, writes SLI4 physical-device control registers, waits for readiness, onlines as needed, then restores VFs. `lpfc_get_stats()` and `lpfc_reset_stats()` issue mailbox reads and convert firmware counters into `fc_host_statistics`. `lpfc_update_rport_devloss_tmo()` synchronizes both FC rports and NVMe remote ports. `lpfc_nvme_mod_param_dep()` removes FCP when NVMe target mode owns the port and clamps MRQ/queue counts to CPU and hardware limits.

Risks: this file exposes many privileged sysfs writes that directly affect link availability, PCI topology, firmware state, and queue/interrupt behavior, so validation and privilege/mode checks are critical. Several generic stores only accept digit-leading inputs, so negative values and hex-style values are rejected before range checks except where custom handlers use `kstrtoul()` or `%i`. PAGE_SIZE-bounded diagnostic show functions build long strings with mixed `strlcat()` and `scnprintf()`; some include explicit overflow fallback text, while others rely on incremental lengths. `lpfc_vmid_info_show()` emits per-VMID data into one page and uses `sprintf()` into a fixed hex buffer based on VMID string length. `lpfc_fcp_cpu_map_show()` mutates display cursor state from a read path, which can interleave across readers. Reset paths rely on completions and mailbox timeout conventions; failures can leave ports offline or SR-IOV disabled unless cleanup paths run. `sysfs_ctlreg_write()` writes adapter registers on pre-SLI4 hardware, guarded by offline state, alignment checks, and the `EMLX` write key, but remains a sharp diagnostic interface. OAS state is spread across target/vport WWPN, priority, LUN state, status, and iterator fields, so users must update files in the expected order.

Test signals: useful coverage includes module-parameter range tests for every `LPFC_ATTR*` generated initializer; sysfs read/write tests for invalid input, boundary values, and permission modes; link speed/topology writes with and without `nolip`; devloss/nodev timeout propagation to existing FC and NVMe rports; SLI3 versus SLI4 behavior for polling, `ctlreg`, NVMe, BBCR, OAS, queue counts, and reset commands; SR-IOV enable/disable and restoration across firmware dump/reset; FC transport attribute refresh and stat reset; RAS logging enable/disable/resize; long-output checks for `nvme_info`, `cmf_info`, `vmid_info`, `scsi_stat`, and CPU-map pagination; and failure injection around mailbox allocation, mailbox timeouts, workqueue post failure, PCI reset rejection, and sysfs binary-file creation cleanup.

# sources/distributed-fs/ceph-client/drivers/scsi/lpfc/lpfc_attr.h

Purpose: macro header that defines the declarative attribute DSL used by `lpfc_attr.c` for `lpfc` module parameters, initialization functions, show/store handlers, and `DEVICE_ATTR` objects.

Important APIs/macros: HBA-scoped macros are `LPFC_ATTR`, `LPFC_ATTR_R`, `LPFC_ATTR_RW`, `LPFC_BBCR_ATTR_RW`, `LPFC_ATTR_HEX_R`, and `LPFC_ATTR_HEX_RW`. Vport-scoped variants are `LPFC_VPORT_ATTR`, `LPFC_VPORT_ATTR_R`, `LPFC_VPORT_ULL_ATTR_R`, `LPFC_VPORT_ATTR_RW`, `LPFC_VPORT_ATTR_HEX_R`, and `LPFC_VPORT_ATTR_HEX_RW`. Each macro creates a static `lpfc_<name>` module-parameter variable, declares it with `module_param()` and `MODULE_PARM_DESC()`, then invokes helper-generation macros from `lpfc_attr.c` such as `lpfc_param_init()`, `lpfc_param_show()`, `lpfc_param_set()`, `lpfc_param_store()`, and their vport/hex equivalents.

Control flow: the header has no standalone runtime flow. Its expansion determines which functions and sysfs attributes exist when included after the helper macros in `lpfc_attr.c`. Read-only forms generate a show function and init function; read-write forms add set/store functions and `S_IWUSR` write permission. Non-sysfs forms generate only the module parameter and init function. Hex forms format show output as hexadecimal. `LPFC_VPORT_ULL_ATTR_R` uses a `uint64_t` backing variable and `ullong` module parameter type for vport values such as maximum LUN ID.

State and persistence: the generated static module variables hold module-load defaults. The generated init functions copy validated values into `phba->cfg_<name>` or `vport->cfg_<name>` during driver/vport setup. Runtime sysfs writes update only live driver configuration through the generated set/store functions unless the caller adds a hand-written setter with extra side effects in `lpfc_attr.c`.

Dependencies and integration: this header depends on helper macros being defined by the including C file before the declarative `LPFC_ATTR*` invocations are used. It also depends on Linux module parameter and device attribute APIs plus conventional `cfg_<name>` fields in `struct lpfc_hba` or `struct lpfc_vport`. The macros are tightly coupled to `lpfc_attr.c`; they are not a general exported interface.

Risks: macro expansion hides many generated functions and static objects, so name collisions or missing `cfg_<name>` fields become compile-time failures that can be hard to trace. Permission constants are embedded in the macro choice, making accidental use of an RW macro a user-visible ABI change. `LPFC_BBCR_ATTR_RW` passes `0444 | 0644`, effectively writable by owner, while relying on a custom setter in `lpfc_attr.c` because it omits the generic `lpfc_param_set()` generation. Because all module variables are file-static, cross-file users must go through generated init paths or explicit globals.

Test signals: compile coverage is the primary signal: every macro use should expand to valid module parameter declarations, helper functions, and device attributes. Sysfs mode inspection should confirm intended read/write permissions. Boundary-value tests should exercise generated init/set/store paths for decimal, hex, HBA, vport, and `ullong` attributes, plus a negative compile or static-analysis check when a new attribute lacks a matching `cfg_*` field.
