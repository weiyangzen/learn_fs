# sources/distributed-fs/ceph-client/drivers/media/i2c/imx219.c

Purpose: V4L2 sub-device driver for the Sony IMX219 CSI-2 Bayer image sensor. It exposes one source pad, 8-bit and 10-bit Bayer media bus formats, four fixed output sizes, runtime power management, sensor controls, and DT/fwnode validation for 2-lane or 4-lane MIPI CSI-2 operation.

Important APIs/types/functions: `struct imx219` owns the `v4l2_subdev`, media pad, CCI regmap, clock, optional reset GPIO, regulators, controls, and lane count. `struct imx219_mode` defines supported width, height, and default frame length. Register programming is done through `devm_cci_regmap_init_i2c()`, `cci_write()`, and `cci_multi_reg_write()`. Format and crop handling is centered on `imx219_set_pad_format()`, `imx219_set_framefmt()`, `imx219_get_binning()`, and `imx219_get_format_code()`. Streaming is implemented with modern pad stream callbacks `imx219_enable_streams()` and `imx219_disable_streams()`, with `v4l2_subdev_s_stream_helper()` for legacy `.s_stream`. Probe and PM are handled by `imx219_probe()`, `imx219_remove()`, `imx219_power_on()`, `imx219_power_off()`, `imx219_check_hwcfg()`, and `imx219_identify_module()`.

Control flow: probe allocates state, initializes the subdev, parses the endpoint, validates 2 or 4 CSI-2 lanes and link frequencies, creates the CCI regmap, validates the 24 MHz xclk, acquires regulators and optional reset GPIO, powers the sensor, reads the chip ID, forces a streaming-to-standby transition to enter LP-11, initializes controls, finalizes the subdev state, enables runtime PM with autosuspend, and registers the sensor. Setting a format selects the nearest fixed mode, derives centered crop and analog binning, updates vblank/hblank/exposure/pixel-rate control ranges, and stores the active state. Stream start resumes runtime PM, writes common register tables, writes lane-specific PLL and CSI lane registers, applies crop/format registers, synchronizes controls, writes `MODE_SELECT = STREAMING`, and grabs flip controls. Stream stop writes standby, releases flip controls, and schedules autosuspend.

State and persistence behavior: persistent state is kernel object state only: active subdev format/crop, control values, lane count, and PM status. The hardware state is rewritten on each stream start from common tables, lane tables, active format/crop, and controls. No on-disk persistence exists. VBLANK updates exposure range even while the device is off; actual register writes are skipped unless `pm_runtime_get_if_in_use()` succeeds. H/V flip values affect both Bayer code reporting and orientation register programming and are locked during streaming.

Dependencies and integration points: integrates with the Linux media controller, V4L2 subdev active-state API, CCI helpers, fwnode endpoint parsing, regulator framework, clock framework, GPIO descriptors, runtime PM, and async sensor registration. It depends on DT compatible `sony,imx219`, endpoint `link-frequencies`, 2 or 4 MIPI data lanes, and exactly 24 MHz input clock. Test-pattern color component controls assume contiguous V4L2 test-pattern color control IDs.

Risks: lane/link-frequency validation has legacy compatibility behavior for an unsupported 4-lane frequency, so platform descriptions can appear valid while being silently remapped. Reset GPIO polarity is documented as historically misinterpreted and should not be copied. Pixel-rate scaling depends on binning-derived `rate_factor`; errors here affect exposure and frame timing. Mode changes preserve previous line length when possible, which can surprise tests that expect mode defaults. Flip changes alter Bayer order and are grabbed only once streaming has started.

Test signals: useful checks include probe success with valid and invalid endpoint lane/link-frequency combinations, chip-ID mismatch handling, runtime PM suspend/resume around stream start/stop, `v4l2-ctl --list-subdev-mbus-codes`, frame-size enumeration for the four modes, set-format control range updates, exposure/vblank/hblank register writes while streaming, flip Bayer-order changes, and test-pattern/color component controls. Kernel build coverage should include media/i2c with CCI helpers enabled and DT binding validation for `sony,imx219`.

# sources/distributed-fs/ceph-client/drivers/media/i2c/imx258.c

Purpose: V4L2 sub-device driver for Sony IMX258 sensors, including standard and PDAF-compatible variants. It supports three fixed 10-bit Bayer modes, 2-lane or 4-lane CSI-2, 19.2 MHz or 24 MHz input clocks, runtime PM, HDR/WDR control, test patterns, and static crop reporting for the active pixel array.

Important APIs/types/functions: `struct imx258` stores device, subdev, CCI regmap, variant config, controls, current mode, link-frequency tables, lane mode index, CSI-2 flags, mutex, clock, and regulators. `struct imx258_mode`, `struct imx258_link_freq_config`, and `struct imx258_link_cfg` describe mode timing, per-clock link configuration, and lane-specific PLL tables. `link_freq_to_pixel_rate()` converts menu link frequency to pixel rate. Control programming is in `imx258_set_ctrl()`, `imx258_update_digital_gain()`, and `imx258_adjust_exposure_range()`. Format and crop operations are `imx258_set_pad_format()`, `imx258_get_pad_format()`, `imx258_get_selection()`, and enumeration helpers. Streaming and lifecycle are `imx258_start_streaming()`, `imx258_stop_streaming()`, `imx258_set_stream()`, `imx258_power_on()`, `imx258_power_off()`, `imx258_identify_module()`, and `imx258_probe()`.

Control flow: probe initializes the CCI regmap, regulators, legacy sensor clock, clock-specific link-frequency tables, fwnode endpoint, link-frequency bitmap, lane mode, CSI-2 clock flags, and variant config from OF match data. It powers the sensor, validates chip ID `0x0258`, sets the default full-resolution mode, initializes controls under a mutex, creates the media entity, registers the subdev, and enables runtime PM. Setting a format locks the mutex, chooses the nearest supported mode, updates `cur_mode`, link frequency, pixel rate, vblank range/default, and fixed hblank value. Streaming resumes runtime PM, resets the sensor, waits 12 ms, writes PLL registers for the current link/lane mode, common mode registers, variant registers, noncontinuous-clock setting, mode-specific registers, user controls, and then sets `MODE_SELECT = STREAMING`.

State and persistence behavior: `cur_mode`, link-frequency selection, lane mode, CSI-2 flags, flip controls, and V4L2 controls are persistent in driver memory. The sensor hardware is treated as volatile across power cycles; stream start replays PLL/common/variant/mode/control state. Control writes are skipped when the device is not runtime-active. The mutex serializes format, crop, and stream operations. Digital gain is mirrored to GR, GB, R, and B gain registers.

Dependencies and integration points: depends on V4L2 subdev and control frameworks, media entity pads, fwnode endpoint parsing, CCI register helpers, runtime PM, regulators, sensor clock helpers, ACPI ID `SONY258A`, and OF compatibles `sony,imx258` and `sony,imx258-pdaf`. The endpoint must provide supported link frequencies for the selected 19.2 or 24 MHz clock table and 2 or 4 CSI-2 data lanes. Noncontinuous MIPI clock is passed through to `IMX258_CLK_BLANK_STOP`.

Risks: the format list only exposes 10-bit Bayer with flip-adjusted order, so integrations expecting 8-bit or other Bayer orders will fail enumeration. `ARRAY_SIZE(link_freq_menu_items_19_2)` is used when validating link frequencies even for the 24 MHz menu; currently both menus have equal size, but this is a maintenance trap. WDR/HDR programming writes a hard-coded ratio expression and is easy to regress without sensor-specific tests. Stop-streaming deliberately returns success even if standby write fails. Clock and lane combinations change effective maximum frame rate, especially full resolution on 2 lanes.

Test signals: validate probe on 19.2 MHz and 24 MHz boards, 2-lane and 4-lane endpoints, both OF variants, and ACPI matching. Exercise mode switching among 4208x3120, 2104x1560, and 1048x780, confirm link-freq/pixel-rate/vblank/hblank ranges, verify flip-dependent Bayer code reporting, and test stream start register sequencing after runtime suspend. Controls to test include analogue gain, four-channel digital gain, exposure with vblank changes, test pattern, WDR, hflip/vflip, and noncontinuous clock endpoint flag behavior.

# sources/distributed-fs/ceph-client/drivers/media/i2c/imx274.c

Purpose: V4L2 sub-device driver for the Sony IMX274 CMOS sensor. It supports four 10-bit raw CSI-2 readout modes derived from crop/compose selection, frame interval control, exposure/gain/vflip/test-pattern controls, runtime PM, and a 4-lane CSI-2 endpoint.

Important APIs/types/functions: `struct stimx274` owns the V4L2 subdev, pad, I2C client, control bundle, active crop/format/frame interval, regmap, reset GPIO, regulators, input clock, mutex, and selected `struct imx274_mode`. Register access uses `devm_regmap_init_i2c()`, `imx274_write_table()`, `imx274_write_reg()`, `imx274_read_mbreg()`, and `imx274_write_mbreg()`; table writes coalesce consecutive registers and honor wait sentinels. Mode and selection logic lives in `__imx274_change_compose()`, `imx274_set_fmt()`, `imx274_set_selection_crop()`, `imx274_apply_trimming()`, and `imx274_mode_regs()`. Streaming is `imx274_s_stream()` plus `imx274_start_stream()`. Timing and control math is in `imx274_set_frame_interval()`, `__imx274_set_frame_interval()`, `imx274_get_frame_length()`, `imx274_set_exposure()`, `imx274_set_gain()`, `imx274_set_digital_gain()`, and `imx274_set_test_pattern()`.

Control flow: probe validates that the endpoint is CSI-2 with exactly 4 data lanes, obtains optional `inck`, regulators and reset GPIO, initializes default crop/format/frame interval, creates a regmap, powers the sensor, initializes four controls, loads default control values, registers the subdev, and enables runtime PM. Format and compose requests choose the best binning mode by scoring requested output size against crop size and selection flags. Crop requests clamp and align the rectangle, update active or try crop, and reset compose when size changes. Stream start resumes PM, writes start-step-1 and selected mode registers, applies trimming/crop registers, recalculates frame interval and exposure, applies controls, performs the datasheet standby-cancel delay sequence, and writes final streaming registers. Stream stop writes the standby table and releases PM.

State and persistence behavior: active crop, format, selected mode, frame interval, and controls are stored in `struct stimx274`; try state is partially supported for format/crop but frame interval explicitly rejects try formats. Hardware state is rebuilt at stream start and not persisted across power-off. Exposure values are expressed in microseconds at the V4L2 control but converted to coarse lines/SHR based on current HMAX and frame length. Gain control stores a fixed-point value, splits it into digital gain steps and analog register value, then writes back the quantized actual gain to `ctrl->val`.

Dependencies and integration points: depends on V4L2 controls/subdev/media entity, fwnode endpoint parsing, regmap with 16-bit register/8-bit value configuration, runtime PM, regulators `vddl`, `vdig`, `vana`, optional reset GPIO, and optional `inck`. The driver registers OF compatible `sony,imx274` and I2C ID `IMX274`. It exposes crop/compose semantics rather than only fixed frame sizes, which makes it sensitive to media-graph users that expect selection API behavior.

Risks: reset polarity is documented as historically misinterpreted and should not be reused. Frame interval math uses integer division ordering that can lose precision and only supports active state. `imx274_get_fmt()` always returns active `imx274->format`, ignoring TRY state, which may surprise userspace. Streaming failure paths call `pm_runtime_put()` even when failure happens after resume, but stop failure also goes through the shared fail path; state should be audited when changing this code. Numerous mode and start tables contain undocumented sensor registers, increasing regression risk for cleanup refactors. The driver lacks chip-ID verification.

Test signals: validate endpoint rejection for non-4-lane configurations, power sequencing with optional reset GPIO, crop alignment/clamping, compose mode selection across 3840x2160, 1920x1080, 1280x720, and 1280x540 derived outputs, frame interval clamping between 5 fps and per-mode max fps, exposure range updates after frame interval changes, fixed-point gain quantization, vflip crop sign handling, and all test-pattern menu values. Streaming tests should check the three-step standby-cancel sequence and trimming register writes.

# sources/distributed-fs/ceph-client/drivers/media/i2c/imx283.c

Purpose: V4L2 sub-device driver for the Sony IMX283 Type 1 image sensor. It supports 12-bit full and binned modes plus one 10-bit full mode, 4-lane CSI-2, selectable link frequencies, multiple input clocks, runtime PM with autosuspend, exposure/gain/blanking/vflip/test-pattern controls, and active-state based pad operations.

Important APIs/types/functions: `struct imx283` keeps device, CCI regmap, selected input-frequency table, subdev, pad, clock, reset GPIO, supplies, controls, MIPI clock mode, link-frequency bitmap, and current HMAX/VMAX timing state. `struct imx283_mode` describes readout mode, bpp, dimensions, HMAX/VMAX limits/defaults, crop and vertical crop constants. `get_mode_table()` selects 10-bit or 12-bit mode arrays from the media bus code. Timing helpers `imx283_pixel_rate()`, `imx283_internal_clock()`, `imx283_iclk_to_pix()`, `imx283_exposure()`, `imx283_exposure_limits()`, and `imx283_shr()` translate V4L2 controls into 72 MHz internal timing units. Streaming is handled by `imx283_enable_streams()`, `imx283_disable_streams()`, `imx283_standby_cancel()`, and `imx283_start_streaming()`.

Control flow: probe initializes the subdev and CCI regmap, gets xclk, maps the clock to one of the supported 6/12/18/24 MHz PLL tables, obtains regulators, parses the endpoint, enforces 4 data lanes, derives noncontinuous-clock and link-frequency bitmap, gets optional reset GPIO, powers on, validates chip ID, enables runtime PM with autosuspend, initializes controls, finalizes active state, registers the sensor, and drops the PM usage count. Setting format chooses a mode from the table associated with the requested code, writes normalized raw format fields to active/try state, and updates framing limits on active formats. Stream start cancels standby, configures input PLL, MIPI clock mode, selected link-speed register table, readout mode registers with vertical-crop bits, SVR, crop/output/optical-black registers, embedded data disable, controls, master-start, and sync drive. Stream stop writes master stop and standby.

State and persistence behavior: the active subdev state stores code, size, and crop; `hmax` and `vmax` in `struct imx283` mirror current timing for exposure calculations. Hardware is programmed on stream start from active state and controls. VBLANK control updates `vmax` and exposure range even when hardware is inactive, while register writes are skipped unless runtime PM is active. The link-frequency control is read-only and initialized from the first set bit in the endpoint bitmap.

Dependencies and integration points: depends on media/V4L2 subdev active state, CCI helpers, fwnode endpoint parsing, runtime PM, regulators `vadd`, `vdd1`, `vdd2`, optional reset GPIO, and sensor clock helpers. It requires OF compatible `sony,imx283`, 4 CSI-2 data lanes, supported link frequency 720 or 360 MHz, and one of the supported input clock rates. It exposes both `MEDIA_BUS_FMT_SRGGB12_1X12` and `MEDIA_BUS_FMT_SRGGB10_1X10`.

Risks: `get_mode_table()` can return no modes for unsupported codes; callers rely on format enumeration or valid input to avoid empty nearest-size lookups. Only 4-lane operation is implemented. Global shutter and SVR are explicitly unsupported but timing formulas include placeholders; future support must revisit exposure limits. HMAX/VMAX conversions intentionally pre-divide to avoid overflow, so changing pixel-rate ranges can affect precision. Vertical crop calculations depend on per-mode constants and vflip sign handling. A TODO notes crop containment validation for native area.

Test signals: check probe with each supported xclk table and link-frequency endpoint, reject non-4-lane endpoints, validate chip-ID failure, enumerate 12-bit and 10-bit frame sizes, switch between 5472x3648, 2736x1824, 1824x1216, and 10-bit full mode, confirm hblank/vblank/exposure range changes, stream with continuous and noncontinuous MIPI clock flags, verify vflip changes `HTRIMMING` and vertical crop positioning, and exercise all test-pattern menu entries. Runtime PM autosuspend and resume around repeated stream cycles are important.

# sources/distributed-fs/ceph-client/drivers/media/i2c/imx290.c

Purpose: V4L2 sub-device driver for Sony IMX290-family CSI-2 sensors, covering color and monochrome IMX290, IMX327, and IMX462 variants. It exposes 1080p and 720p modes, 10-bit and 12-bit formats, 2-lane or 4-lane CSI-2 operation, runtime PM, test patterns, blanking, exposure, analogue gain, and flip controls.

Important APIs/types/functions: `struct imx290` stores device resources, CCI regmap, xclk selection, lane count, model info, subdev, current mode, regulators, reset GPIO, and controls. `struct imx290_model_info` carries variant color/mono type, model-specific init table, max analogue gain, and name. `struct imx290_mode`, `struct imx290_csi_cfg`, `struct imx290_clk_cfg`, and `struct imx290_format_info` describe mode dimensions, link timing, clock setup, and format-specific registers. Key functions include `imx290_parse_dt()`, `imx290_check_link_freqs()`, `imx290_init_clk()`, `imx290_ctrl_init()`, `imx290_ctrl_update()`, `imx290_set_ctrl()`, `imx290_start_streaming()`, `imx290_stop_streaming()`, `imx290_set_fmt()`, and `imx290_subdev_init()`.

Control flow: probe creates the CCI regmap, parses OF match data and endpoint, validates 2 or 4 data lanes and that all driver-required link frequencies are present, acquires regulators/reset/xclk, validates 37.125 MHz or 74.25 MHz input clock, powers on, enables runtime PM, forces standby/not-streaming, initializes the V4L2 subdev and controls, sets the subdev name from the model, and registers it. Setting format chooses the nearest lane-specific mode, validates or defaults the media bus code according to color/mono variant, updates active current mode and blanking/link controls, and stores active state. Stream start writes global and model-specific init tables, clock registers, lane registers, CSI timing, bit-depth format registers, black level, mode registers, controls, leaves standby, waits 30 ms, and clears `XMSTA`. Stop writes standby, waits, and sets `XMSTA`.

State and persistence behavior: active state stores format; `current_mode` and controls remain in driver memory. Hardware state is rebuilt for every stream start. VBLANK updates the exposure range before any runtime PM check, and when VMAX changes during streaming the driver immediately reprograms exposure because SHS1 is relative to VMAX. H/V flip controls are clustered, program `CTRL_07` with the current mode window bits, and are grabbed during streaming to avoid invalid frames. Test pattern mode temporarily changes black level and restores it when disabled.

Dependencies and integration points: depends on OF match data for model selection, fwnode endpoint parsing, media entity validation, CCI helpers, V4L2 subdev active-state helpers, runtime PM, regulators `vdda`, `vddd`, `vdddo`, reset GPIO, and legacy sensor clock lookup. Supported compatibles include deprecated `sony,imx290`, plus `sony,imx290lqr`, `sony,imx290llr`, `sony,imx327lqr`, `sony,imx462lqr`, and `sony,imx462llr`.

Risks: the driver requires the DT endpoint to list all link frequencies for the selected lane count, not just the active one, which can break partial platform descriptions. There is no chip-ID read; model identity comes from DT match data. CCI timing tables and model-specific undocumented registers are sensor-sensitive. Pixel rate is fixed at 148.5 MHz even though link frequency changes by mode/lane. Stop-streaming result is ignored by `imx290_set_stream()` on disable. Flip-dependent crop shifts by one pixel to preserve Bayer order, so crop tests must account for current flip state.

Test signals: validate every compatible, color versus mono media bus code enumeration, 2-lane and 4-lane link-frequency requirements, both supported xclk rates, 10-bit/12-bit format register programming, mode switching between 1920x1080 and 1280x720, hblank/vblank/exposure interactions, black-level behavior around test-pattern enable/disable, clustered hflip/vflip grab behavior during streaming, and runtime PM autosuspend across repeated stream cycles.

# sources/distributed-fs/ceph-client/drivers/media/i2c/imx296.c

Purpose: V4L2 sub-device driver for Sony IMX296 global shutter sensors, including color IMX296LQ and monochrome IMX296LL detection/forcing. It supports full-resolution or binned/cropped 10-bit output, runtime PM, exposure/gain/blanking/test-pattern controls, sensor temperature/model identification, and source-pad crop/format operations.

Important APIs/types/functions: `struct imx296` stores device resources, clock, supplies, reset GPIO, regmap, selected clock parameters, mono flag, subdev, pad, controls, and hblank/vblank handles. Register helpers `imx296_read()` and `imx296_write()` encode 8/16/24-bit register width in the upper bits of the register constant and use raw regmap access. Control setup is `imx296_ctrls_init()` and control writes are `imx296_s_ctrl()`. Hardware setup and streaming are `imx296_setup()`, `imx296_stream_on()`, `imx296_stream_off()`, and `imx296_s_stream()`. Format/crop state is managed by `imx296_set_format()`, `imx296_set_selection()`, `imx296_init_state()`, and enumeration helpers. Probe support includes `imx296_identify_model()`, `imx296_read_temperature()`, `imx296_subdev_init()`, and runtime PM callbacks.

Control flow: probe verifies SMBus byte-data support, allocates state, gets supplies/reset/input clock, matches the clock against 37.125/54/74.25 MHz parameter tables, creates a regmap with sensor-info marked unreadable for generic cache access, powers on, identifies model either from OF match data or by temporarily leaving standby and reading sensor info plus temperature, initializes subdev/controls/media entity, enables runtime PM, registers the subdev, then enables autosuspend and drops the usage count. Stream start locks active state, resumes PM, writes a large vendor-derived init table, applies ROI registers if cropped, configures binning/window mode from crop versus format size, programs HMAX/VMAX, input-clock timing registers, gain delay and black level, synchronizes controls, exits standby, and starts master mode. Stream stop writes master-stop and standby and schedules autosuspend.

State and persistence behavior: active subdev state stores crop and format. The mono flag determines whether the single exposed code is `MEDIA_BUS_FMT_Y10_1X10` or `MEDIA_BUS_FMT_SBGGR10_1X10`. Control values persist in the V4L2 handler and are replayed on stream start. HBLANK is read-only and derived from fixed HMAX and nominal pixel rate; VBLANK affects VMAX. Exposure is clamped to current VMAX before writing `SHS1`. No file-backed persistence exists.

Dependencies and integration points: depends on regmap raw I2C access, V4L2 controls/subdev/media entity, fwnode device properties, runtime PM, regulator framework, GPIO descriptors, and sensor clock helper for `inck`. OF compatibles are `sony,imx296`, `sony,imx296ll`, and `sony,imx296lq`; the latter two bypass auto-detection. It assumes 10-bit output and a nominal MIPI bit rate around 1188 Mbps reported through pixel-rate controls.

Risks: many initialization registers are undocumented vendor data, making simplification risky. Auto-detection must take the sensor out of standby because sensor-info cannot be read in standby, so probe touches streaming-related state before registration. `v4l2_subdev_init_finalize()` return is not checked in `imx296_subdev_init()`. Binning is documented as allowed only without cropping and marked for double-checking. The regmap access table blocks generic reads of sensor info addresses, and direct raw reads bypass normal typed helpers. Exposure control mutates `ctrl->val` during `s_ctrl`, which can surprise control tests.

Test signals: cover forced and auto-detected color/mono variants, unsupported clock rejection, model/temperature read path, crop alignment to 4 pixels and minimum ROI size, full-frame versus ROI register programming, binning format choices for full-frame 1456x1088 and half sizes, exposure clamping when VBLANK changes, test-pattern enable/disable black-level and auto-black-level behavior, runtime PM error recovery on setup failure, and repeated stream on/off with active-state locking.
