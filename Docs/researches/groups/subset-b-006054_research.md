# sources/distributed-fs/ceph-client/kernel/sched/ext.h

Purpose: declares the scheduler-core entry points for the BPF extensible scheduler class and provides no-op fallbacks when `CONFIG_SCHED_CLASS_EXT` or optional group scheduling support is disabled. It is the narrow integration header consumed by generic scheduler code such as `core.c`, `idle.c`, and debug paths, keeping sched_ext hooks callable without scattering Kconfig conditionals across the scheduler.

Important APIs and types: with `CONFIG_SCHED_CLASS_EXT`, the header exposes lifecycle and task hooks including `scx_tick()`, `init_scx_entity()`, `scx_pre_fork()`, `scx_fork()`, `scx_post_fork()`, `scx_cancel_fork()`, `init_sched_ext_class()`, `scx_rq_activate()`, and `scx_rq_deactivate()`. Scheduling-policy helpers include `scx_check_setscheduler()`, `task_should_scx()`, `task_on_scx()`, `scx_allow_ttwu_queue()`, and `scx_cpuperf_target()`. The idle bridge is `scx_update_idle()`, which calls `__scx_update_idle()` only while sched_ext is enabled. Under `CONFIG_CGROUP_SCHED` plus `CONFIG_EXT_GROUP_SCHED`, it also exports task-group and cgroup callbacks such as `scx_tg_init()`, `scx_tg_online()`, `scx_tg_offline()`, `scx_cgroup_can_attach()`, `scx_cgroup_move_task()`, `scx_cgroup_cancel_attach()`, `scx_group_set_weight()`, `scx_group_set_idle()`, and `scx_group_set_bandwidth()`.

Control flow: generic scheduler code calls these declarations at stable scheduler transition points. Fork setup passes through pre-fork, fork, post-fork, and cancel-fork hooks. Periodic ticks call `scx_tick()`. CPU hotplug paths call runqueue activation/deactivation hooks. Idle-class transitions call `scx_update_idle()`, which guards the implementation behind `scx_enabled()` so early boot, disabled sched_ext, and teardown paths do not enter the ext idle machinery. When the feature is compiled out, every hook either returns a permissive default or no-ops, preserving generic scheduler flow.

State and persistence: this header owns no storage. The only state read inline is `cpu_rq(cpu)->scx.cpuperf_target` when sched_ext is active, and task class identity through `p->sched_class == &ext_sched_class`. All persistent runtime state lives in scheduler runqueues, tasks, task groups, and `ext.c` or `ext_idle.c`.

Dependencies and integration points: depends on scheduler-internal types such as `struct rq`, `struct task_struct`, `struct kernel_clone_args`, `struct task_group`, and cgroup taskset types. It integrates with the generic scheduler in `kernel/sched/core.c`, the idle class in `kernel/sched/idle.c`, scheduler debug code, sched_core priority comparison when `CONFIG_SCHED_CORE` is set, and cgroup CPU controller paths when group scheduling is enabled.

Risks: inline fallback behavior is part of the scheduler ABI for disabled configurations, so wrong return defaults can silently change boot, fork, wakeup, cgroup, or scheduler-policy behavior. `task_on_scx()` must remain cheap and accurate because generic scheduler and debug paths can call it frequently. `scx_update_idle()` must remain guarded because idle transitions happen in core scheduler paths and can occur during enable/disable windows.

Test signals: build both `CONFIG_SCHED_CLASS_EXT=y` and `n`, with and without `CONFIG_EXT_GROUP_SCHED`, `CONFIG_CGROUP_SCHED`, and `CONFIG_SCHED_CORE`. Runtime signals include successful scheduler boot initialization, fork/exit stress under sched_ext, CPU hotplug callbacks, idle transition accounting, cgroup attach/move/weight/bandwidth updates, and `sched/debug` reporting for ext-enabled tasks.

# sources/distributed-fs/ceph-client/kernel/sched/ext_idle.c

Purpose: implements sched_ext built-in idle CPU tracking, default idle CPU selection, and BPF kfuncs that let sched_ext BPF schedulers observe or claim idle CPUs. It maintains global or per-NUMA-node idle CPU masks, optional SMT-full-core masks, topology-aware LLC/NUMA selection hints, and BTF kfunc registration for idle and select-cpu helper APIs.

Important APIs and types: `struct scx_idle_cpus` holds two cpumasks: `cpu` for idle logical CPUs and `smt` for fully idle SMT sibling groups. Static keys `scx_builtin_idle_enabled`, `scx_builtin_idle_per_node`, `scx_selcpu_topo_llc`, and `scx_selcpu_topo_numa` dynamically enable built-in idle tracking, per-node masks, LLC-aware selection, and NUMA-aware selection. Initialization and scheduler-core APIs are `scx_idle_init_masks()`, `scx_idle_enable()`, `scx_idle_disable()`, `scx_idle_update_selcpu_topology()`, `scx_select_cpu_dfl()`, `__scx_update_idle()`, and `scx_idle_init()`. BPF-facing kfuncs include `scx_bpf_cpu_node()`, `scx_bpf_select_cpu_dfl()`, `__scx_bpf_select_cpu_and()`, compatibility `scx_bpf_select_cpu_and()`, idle-mask getters, `scx_bpf_put_idle_cpumask()`, `scx_bpf_test_and_clear_cpu_idle()`, `scx_bpf_pick_idle_cpu_node()`, `scx_bpf_pick_idle_cpu()`, `scx_bpf_pick_any_cpu_node()`, and `scx_bpf_pick_any_cpu()`.

Control flow: boot-time sched_ext initialization calls `scx_idle_init_masks()` from `init_sched_ext_class()` to allocate global, per-node, and per-CPU temporary cpumasks. Later `scx_init()` calls `scx_idle_init()` to register BTF kfunc sets. When a BPF scheduler instance is enabled, `scx_idle_enable()` selects whether built-in idle tracking remains active based on `ops.update_idle` and `SCX_OPS_KEEP_BUILTIN_IDLE`, enables per-node tracking when `SCX_OPS_BUILTIN_IDLE_PER_NODE` is set, and calls `reset_idle_masks()`. `scx_idle_update_selcpu_topology()` runs during enable and hotplug to toggle LLC and NUMA optimization static keys after inspecting `sd_llc` and `sd_numa` scheduling domains. Idle-class transitions call `__scx_update_idle()`, which updates built-in masks first and then calls `ops.update_idle()` for real state transitions unless the scheduler is bypassing on that CPU.

Idle selection flow: `scx_select_cpu_dfl()` computes the usable `allowed` mask from an optional caller mask and `p->cpus_ptr`, handles affinity-constrained and migration-disabled tasks through the kfunc wrapper, then under RCU prefers wake-sync locality, full-idle SMT cores, previous CPU reuse, SMT siblings, same LLC, same NUMA node, and finally any allowed idle CPU. `pick_idle_cpu_in_node()` claims a CPU by calling `scx_idle_test_and_clear_cpu()`; the test-and-clear operation removes the logical CPU from idle masks and clears the entire SMT sibling group from the full-idle mask to avoid double claims. With per-node tracking, `scx_pick_idle_cpu()` starts in the previous CPU's node and can expand to online nodes by NUMA distance unless `SCX_PICK_IDLE_IN_NODE` is set. `SCX_PICK_IDLE_CORE` limits selection to fully idle SMT cores.

State and persistence: runtime state is in allocated cpumasks: global idle masks, an array of per-node idle masks sized by `nr_node_ids`, per-CPU temporary masks for allowed/LLC/NUMA intersections, and per-CPU NUMA nodemasks used while searching nodes. The state is volatile, recalculated from scheduler idle transitions and reset during scheduler enable. BPF idle-mask getters return global kernel cpumask pointers with artificial acquire/release semantics only to satisfy verifier trusted-pointer rules; the masks are not reference-counted or persistent outside the running kernel.

Dependencies and integration points: depends on scheduler domains (`sd_llc`, `sd_numa`), cpumask APIs, NUMA node state, SMT topology helpers, runqueue `rq->scx.local_dsq`, sched_ext root scheduler state, BPF struct_ops and kfunc registration, BTF ID sets, and sched_ext context filters from `ext.c`. It is called by `ext.c` during sched_ext class initialization, root scheduler enable, hotplug, and kfunc verifier filtering; by `idle.c` during idle task transitions; and by BPF schedulers through registered kfuncs.

Risks: idle masks are intentionally racy optimizations, so callers must tolerate false negatives and must kick a CPU when they need guaranteed future dispatch. The SMT mask must be cleared on both successful and failed claims to avoid infinite retry loops, especially when CPUs go offline and are no longer in their sibling mask. Per-node access requires strict validation because global and per-node modes are mutually exclusive for several kfuncs. `select_cpu_from_kfunc()` has lock-context-sensitive behavior: it trusts `p->pi_lock` inside `ops.select_cpu()`, uses `scx_locked_rq()` for rq-locked callbacks, and otherwise takes `p->pi_lock`; cross-task use under the wrong rq lock is rejected. Topology optimization depends on scheduler-domain RCU protection and can misplace locality if domain weights or hotplug state are stale.

Test signals: exercise sched_ext selftests and BPF schedulers that call default select-cpu helpers, idle mask getters, pick-idle, and pick-any kfuncs. Cover SMT on/off, single-CPU, multiple LLC domains, multiple NUMA nodes, per-node tracking, hotplug online/offline, wake-sync wakeups, migration-disabled tasks, restricted affinity masks, and schedulers that implement `ops.update_idle` with and without `SCX_OPS_KEEP_BUILTIN_IDLE`. Useful failure signals include `scx_error()` messages for disabled built-in tracking or invalid nodes, stalled runnable tasks with idle CPUs, repeated select-cpu fallback events, and verifier rejection of kfuncs in invalid BPF program contexts.

# sources/distributed-fs/ceph-client/kernel/sched/ext_idle.h

Purpose: provides the private sched_ext idle-tracking interface shared between `ext.c` and `ext_idle.c`. It declares BTF kfunc ID sets used by sched_ext verifier filtering, idle-mask initialization, topology updates, default CPU selection, enable/disable hooks, and late BPF kfunc registration.

Important APIs and types: forward-declares `struct sched_ext_ops` so callers can pass scheduler operation tables without including the full internal header through this file. Exports `scx_kfunc_ids_idle` and `scx_kfunc_ids_select_cpu` for context filtering in `ext.c`. Declares `scx_idle_update_selcpu_topology()`, `scx_idle_init_masks()`, `scx_select_cpu_dfl()`, `scx_idle_enable()`, `scx_idle_disable()`, and `scx_idle_init()`.

Control flow: `init_sched_ext_class()` calls `scx_idle_init_masks()` during scheduler class initialization. `scx_init()` calls `scx_idle_init()` after enough BPF/BTF infrastructure exists to register kfunc sets. Root scheduler enable calls `scx_idle_enable()` before `ops.init()` and updates topology after hotplug validation; root disable calls `scx_idle_disable()`. The scheduler wakeup path in `ext.c` calls `scx_select_cpu_dfl()` when the BPF scheduler lacks `ops.select_cpu()` or when bypassing requires the built-in path.

State and persistence: the header contains no storage beyond extern declarations. All state is owned by `ext_idle.c` static keys and cpumasks, or by `ext.c` scheduler instances and BTF registration tables.

Dependencies and integration points: couples the sched_ext implementation file with the idle helper implementation. The `btf_id_set8` externs are used by `scx_kfunc_context_filter()` logic in `ext.c` to distinguish idle kfuncs from select-cpu kfuncs, and the function declarations let `ext.c` manage idle tracking without exposing implementation internals to the rest of the scheduler.

Risks: this header is small but ABI-sensitive inside the sched_ext subsystem. Prototype drift between `ext_idle.c`, `ext.c`, and BPF kfunc registration would break builds or verifier filtering. The select-cpu declaration includes an optional `cpus_allowed` mask and flags; mismatched semantics would directly affect wakeup CPU placement and BPF kfunc behavior.

Test signals: build sched_ext with BTF and BPF struct_ops enabled, verify kfunc registration succeeds, load BPF schedulers that use both idle and select-cpu helper sets, and exercise enable/disable plus CPU hotplug so all declared entry points are called.

# sources/distributed-fs/ceph-client/kernel/sched/ext_internal.h

Purpose: defines the internal sched_ext contract shared across the scheduler implementation and BPF struct_ops registration. It contains constants, exit metadata, scheduler operation flags, callback argument containers, the full `struct sched_ext_ops` ABI, event counters, per-CPU and per-node scheduler state, enqueue/dequeue/kick flag enums, task-group flags, enable states, task ownership state encoding, and inline helpers for resolving scheduler instances.

Important APIs and types: `SCX_OP_IDX()` and `SCX_MOFF_IDX()` convert operation-table members or byte offsets to function-pointer indexes for operation presence tracking. `enum scx_consts` defines default dispatch batch limits, watchdog timeouts, exit dump sizes, CPU capacity scale, task-iteration batch sizes, bypass load-balance defaults, reenq limits, and sub-scheduler depth. Exit-related types are `enum scx_exit_kind`, `enum scx_exit_code`, `enum scx_exit_flags`, and `struct scx_exit_info`. `enum scx_ops_flags` exposes scheduler behavior flags including built-in idle retention, enqueue-last behavior, exiting-task handling, partial switching, migration-disabled enqueue behavior, queued wakeup allowance, per-node built-in idle, always-immediate local enqueues, and internal CPU-preempt capability.

`struct sched_ext_ops` is the central BPF scheduler ABI. It defines callbacks for CPU selection, enqueue/dequeue, dispatch, tick, task state notifications, yield, core scheduling order, task weight and cpumask updates, idle updates, CPU acquire/release, task init/exit/enable/disable, debug dumps, optional cgroup callbacks, sub-scheduler attach/detach, CPU hotplug, init, and exit. It also includes data fields such as `dispatch_max_batch`, `flags`, `timeout_ms`, `exit_dump_len`, `hotplug_seq`, `sub_cgroup_id`, `name`, and internal `priv`.

Scheduler runtime state includes `struct scx_event_stats`, `struct scx_dsp_buf_ent`, `struct scx_dsp_ctx`, `struct scx_deferred_reenq_local`, `struct scx_sched_pcpu`, `struct scx_sched_pnode`, and `struct scx_sched`. `struct scx_sched` embeds the user operation table, operation presence bitmap, DSQ hash, per-node global DSQs, per-CPU state, slice defaults, bypass state, warning flags, optional sub-scheduler links, watchdog timeout, exit info, kobject, helper work items, bypass load-balance masks, RCU work, and ancestor scheduler array.

Control flow: `ext.c` uses the operation-index ranges in `enum scx_opi` to decide which callbacks are normal, CPU-hotplug-sensitive, or unavailable after init. Load-time validation and BPF struct_ops conversion use the operation table layout and flags. Runtime enqueue, dequeue, dispatch, selection, tick, hotplug, cgroup, and dump paths consult `struct scx_sched`, per-CPU state, and `SCX_HAS_OP` style operation presence. BPF-facing kfuncs use `scx_prog_sched()` to map an implicit `bpf_prog_aux` to the owning scheduler instance, while scheduler task paths use `scx_task_sched()` or `scx_task_sched_rcu()` to resolve the scheduler associated with a task.

State and persistence: all state described here is in-memory kernel scheduler state. The root scheduler pointer is `scx_root` under RCU. `scx_locked_rq_state` is per-CPU and records an rq lock held while running sched_ext callbacks. Event counters live per CPU and are aggregated on demand. The task ownership state is encoded in `p->scx.ops_state` using low bits for `enum scx_ops_state` and high bits for a queue sequence number. Release/acquire memory ordering is required when leaving transitional states so dispatch and dequeue paths observe valid ownership.

Task ownership behavior: `SCX_OPSS_NONE` means the core scheduler owns the task, `SCX_OPSS_QUEUEING` transfers it to the BPF scheduler while the rq lock is held, `SCX_OPSS_QUEUED` means the BPF scheduler owns it and the qseq brands this queued instance, and `SCX_OPSS_DISPATCHING` transfers it back to the core. The documented state machine lets BPF dispatch attempts race with dequeues safely: stale qseq dispatches are ignored, queueing and dispatching waiters use acquire/release ordering, and cross-CPU movement during dispatch uses a `holding_cpu` lock-dancing protocol to avoid rq-lock deadlocks.

Dependencies and integration points: depends on core scheduler structures, BPF struct_ops, cgroups, runqueue locking, RCU, rhashtable DSQ lookup, kobjects, kthread work, timers, IRQ work, cpumasks, and optional sub-scheduler support. It is consumed heavily by `ext.c`, `ext_idle.c`, and cgroup scheduler integration, and it defines many enum constants deliberately kept visible to BPF schedulers through generated `vmlinux.h`.

Risks: this header is both internal implementation glue and ABI description for BPF schedulers, so layout or semantic changes can break verifier expectations, struct_ops compatibility, or existing scheduler programs. Operation flag validation must keep user-settable flags separate from high internal bits. Incorrect `SCX_OPSS_*` memory ordering, qseq masking, or lock-context assumptions can cause lost tasks, invalid dispatch acceptance, stalls, or rq-lock deadlocks. Sub-scheduler resolution has compatibility logic for unassociated pre-sub-scheduler programs; changing it can misattribute kfunc calls. Event counters and bypass state are diagnostic and safety-critical because they reveal scheduler malfunction and support forward progress under errors or power-management transitions.

Test signals: compile with and without `CONFIG_EXT_SUB_SCHED`, `CONFIG_EXT_GROUP_SCHED`, and core scheduling. Load BPF schedulers implementing different subsets of `sched_ext_ops`, including schedulers with `update_idle`, cgroup callbacks, queued wakeup, partial switching, sub-scheduler attach, CPU hotplug callbacks, and immediate local DSQ insertion. Stress enqueue/dequeue/dispatch races, affinity changes, migration-disabled tasks, CPU hotplug, cgroup moves, bypass activation, watchdog stalls, scheduler unload, and verifier context filtering. Inspect event counters for select-cpu fallback, local DSQ offline fallback, keep-last dispatch, reenq-immediate recursion, skipped exiting or migration-disabled enqueues, and insert-not-owned signals.
