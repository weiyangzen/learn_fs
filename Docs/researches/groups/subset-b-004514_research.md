# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_cpt.c

Purpose: implements the RVU Admin Function side of CPT crypto/block management. It registers CPT AF MSI-X interrupt handlers, allocates and frees CPT logical functions for PF/VF requesters, configures inline IPsec use of CPT LFs, exposes tightly filtered CPT register read/write mailbox access, gathers CPT status/performance counters, flushes CPT context cache state, tears down active CPT queues, and initializes CPT-related RVU capability state.

Important APIs/functions: `rvu_cpt_register_interrupts()` and `rvu_cpt_unregister_interrupts()` cover CPT0/CPT1 interrupt lifecycle. Mailbox handlers include `rvu_mbox_handler_cpt_lf_alloc`, `cpt_lf_free` through `rvu_mbox_handler_cpt_lf_free`, `rvu_mbox_handler_cpt_inline_ipsec_cfg`, `rvu_mbox_handler_cpt_rd_wr_register`, `rvu_mbox_handler_cpt_sts`, `rvu_mbox_handler_cpt_rxc_time_cfg`, `rvu_mbox_handler_cpt_ctx_cache_sync`, `rvu_mbox_handler_cpt_lf_reset`, and `rvu_mbox_handler_cpt_flt_eng_info`. Shared helpers include `get_cpt_pf_num`, `is_cpt_pf`, `is_cpt_vf`, `validate_and_get_cpt_blkaddr`, `validate_and_update_reg_offset`, `cpt_rxc_teardown`, `cpt_lf_disable_iqueue`, `rvu_cpt_lf_teardown`, `cpt_inline_inb_lf_cmd_send`, `rvu_cpt_ctx_flush`, and `rvu_cpt_init`.

Control flow: interrupt registration first checks whether each CPT block is implemented, reads `CPT_PRIV_AF_INT_CFG` for the vector base, then selects OTX2-style fixed FLT/RVU/RAS vectors or CN10K-style dynamic FLT vector count based on engine count. FLT handlers read `CPT_AF_FLTX_INT`, map set bits to engine IDs, briefly disable and re-enable the faulting engine, record faulted/recovered bits under `rvu->cpt_intr_lock`, then clear the interrupt. LF allocation validates block address, engine group mask, local LF ownership, optional NIX/SSO PF_FUNC mappings, then writes each assigned `CPT_AF_LFX_CTL` and `CPT_AF_LFX_CTL2`. LF free and LF reset preserve or reset the right register state while invoking queue teardown. Inline IPsec configuration chooses inbound or outbound, rejects simultaneous inbound/outbound enable on the same LF, validates NIX/SSO mappings, sets CPT LF control bits, selects NIX0/NIX1 routing, and on newer silicon programs X2P link config. Register access first proves the sender is the discovered CPT PF or one of its VFs, then translates local LF offsets to global LF offsets and restricts PF-only access to an explicit register allowlist. Context flush on non-OTX2 submits a CPT instruction to the CPT PF through the AF-PF mailbox, waits for RXC drain, scans context CAM entries matching `pcifunc`, and writes `CPT_LF_CTX_FLUSH` through BAR2 aliasing.

State and persistence: persistent driver state is held in `rvu->cpt_pf_num`, `rvu->hw->cap.cpt_rxc`, `rvu->cpt_intr_lock`, `rvu->irq_allocated[]`, per-block `cpt_flt_eng_map[]` and `cpt_rcvrd_eng_map[]`, LF ownership maps in `rvu_hwinfo`, and hardware registers. Mailbox handlers mostly mutate CPT AF registers rather than heap state. RXC teardown temporarily lowers RXC aging thresholds and restores the previous config. BAR2 alias access is serialized with `rvu->alias_lock`; context flush resource checks use `rvu->rsrc_lock`; fault maps use the CPT spinlock. No disk persistence exists.

Dependencies and integration: depends on RVU register helpers (`rvu_read64`, `rvu_write64`, `rvu_bar2_sel_write64`), resource mapping helpers (`rvu_get_lf`, `rvu_get_rsrc_mapcount`, `rvu_get_blkaddr_from_slot`, `is_pffunc_map_valid`), PCI IRQ APIs, AF/PF mailbox APIs, DMA mapping APIs, CPT/NIX/NPA register definitions, and silicon detection helpers (`is_rvu_otx2`, `is_cn10ka_a0`, `is_cn10ka_a1`, `is_cn10kb`). It integrates with CPT PF/VF mailbox contracts, NIX inline IPsec paths, SSO mapping, RVU block reset, AF interrupt setup/teardown, and debug/devlink paths that consume CPT state.

Risks: hardware-facing polling loops can time out but generally only warn, so callers may continue after incomplete drain. `validate_and_update_reg_offset` is security-critical because it gates PF/VF register access; missing allowlist constraints would expose AF registers. Inline IPsec enables are mutually exclusive only per CPT LF, so invalid cross-block or stale LF mapping assumptions could affect traffic. `cpt_inline_inb_lf_cmd_send` returns `0` even after a result timeout, which makes timeout detection advisory. FLT recovery assumes engine disable/enable is sufficient and only marks recovered if status becomes free or busy. Divide-by-zero and bounds risks are mostly mitigated by constants and resource checks, but hardware register values still drive loop sizes and vector counts.

Test signals: useful signals include CPT AF IRQ registration/unregistration on OTX2 and CN10K hardware, injected FLT/RVU/RAS interrupts with fault/recovered bitmap reads, mailbox LF alloc/free/reset for CPT0 and CPT1, invalid PF/VF access checks for CPT register read/write, inline IPsec inbound/outbound mutual exclusion, context flush under active inline inbound traffic, RXC teardown timeout logging, and debugfs/devlink status matching CPT hardware counters after traffic.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_debugfs.c

Purpose: builds the `debugfs` diagnostics tree for the OcteonTX2/CN10K/CN20K RVU Admin Function when `CONFIG_DEBUG_FS` is enabled. It exposes read-mostly hardware and driver state for MCS MACsec, LMTST map tables, RVU resource attachment, firmware data, NPA/NIX queue and context state, NDC cache counters, NIX transmit scheduler topology, ingress policer state, CGX/RPM port statistics and firmware data, NPC MCAM/exact-match state, and CPT engine/LF/counter state. A small set of files accept writes to select which LF or queue context subsequent reads should dump.

Important APIs/functions: exported entry points are `rvu_dbg_init()` and `rvu_dbg_exit()`. File-operation generator macros `RVU_DEBUG_SEQ_FOPS` and `RVU_DEBUG_FOPS` create many `struct file_operations`. Major initializers are `rvu_dbg_mcs_init`, `rvu_dbg_npa_init`, `rvu_dbg_nix_init`, `rvu_dbg_cgx_init`, `rvu_dbg_npc_init`, and `rvu_dbg_cpt_init`. Common parsing/validation helpers include `rvu_dbg_is_valid_lf`, `rvu_dbg_qsize_write`, `parse_cmd_buffer_ctx`, `write_npa_ctx`, and `write_nix_queue_ctx`. Major readers include MCS stats displays, `rvu_dbg_lmtst_map_table_display`, `rvu_dbg_rsrc_attach_status`, `rvu_dbg_rvu_pf_cgx_map_display`, `rvu_dbg_rvu_fwdata_display`, NPA/NIX context display functions, NDC cache/hit/miss displays, `rvu_dbg_nix_tm_tree_display`, `rvu_dbg_nix_tm_topo_display`, CGX/RPM stat and filter displays, NPC MCAM/rule/exact-match displays, and CPT status displays.

Control flow: `rvu_dbg_init()` creates a root directory named by silicon family (`octeontx2`, `cn10k`, or `cn20k`), creates top-level RVU files, then conditionally initializes NPA, NIX0/NIX1, CGX/RPM, NPC, CPT0/CPT1, and MCS subtrees. Each debugfs file either calls a `seq_file` reader with private data set to `rvu`, `nix_hw`, `mcs`, `cgx`, or `cpt_ctx`, or uses simple read operations for buffer-copy dumps. Selector writes parse numeric LF and optional queue/context IDs, validate ownership and queue context availability, then store the selection in `rvu->rvu_dbg`; subsequent reads use those stored selectors to issue admin queue reads or walk software maps. `rvu_dbg_exit()` removes the whole tree recursively.

State and persistence: the debugfs tree and selection fields under `rvu->rvu_dbg` persist for the driver lifetime, not across unload. Read paths observe live hardware registers, firmware shared data, bitmaps, resource maps, and lists. Several readers lock subsystem state while walking it: MCS stats use `mcs->stats_lock`, NPC MCAM/rule and exact-match paths use their locks, while other readers rely on existing RVU ownership maps and hardware access serialization. Files generally allocate temporary buffers per read; no persistent files or on-disk state are written.

Dependencies and integration: depends on Linux `debugfs`, `seq_file`, PCI helpers, CGX/RPM MAC ops, LMAC helpers, NPC/NIX/NPA/CPT register definitions, CN20K-specific debug helpers, MCS APIs, RVU resource maps, admin queue handlers (`rvu_npa_aq_enq_inst`, `rvu_mbox_handler_nix_aq_enq`, `nix_aq_context_read`), and firmware shared structures. It is a diagnostic integration layer across almost every RVU AF subsystem rather than a data-plane component.

Risks: debugfs is privileged but still directly exposes hardware-derived state and some firmware data, including MAC addresses and EEPROM bytes. Several fixed-size formatting buffers (`2048`, `10240`, small directory-name arrays) rely on bounded hardware counts and careful `scnprintf`; expanding PF/VF counts or output widths could truncate data. `ndc_cache_stats()` computes average latency as `lat / req` without checking `req`, so an idle port can divide by zero. Selector writes mutate global per-driver debug selection fields, so concurrent readers/writers can race and produce mixed output. Some read paths use PCI lookup helpers and hardware register reads without deep failure recovery, appropriate for diagnostics but risky if reused for control flow. MCS and NPC walkers use locks, but many other readers observe live mutable state without snapshot consistency.

Test signals: mount debugfs and verify root/subtree creation on OTX2, CN10K, and CN20K; confirm `rvu_dbg_exit()` removes all entries. Exercise selector write/read cycles for NPA aura/pool, NIX SQ/RQ/CQ, NIX qsize, TM tree/topology, and invalid LF/queue paths. Compare CGX/RPM, NPC, CPT, MCS, and NDC debug counters against traffic and subsystem APIs. Check CN20K-only NPC debug hooks, CN10K/NDC exclusion behavior, exact-match file presence only when enabled, and absence of crashes on idle NDC counters, uninitialized queue contexts, no CGX devices, and missing firmware data.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_devlink.c

Purpose: provides the RVU AF `devlink` integration. It registers the AF as a devlink instance, wires NPA and NIX AF hardware interrupt classes into devlink health reporters with dump and recovery callbacks, exposes runtime devlink parameters for scheduler/MCAM/NPC/NIX behavior, and implements devlink eswitch mode get/set for legacy versus switchdev operation.

Important APIs/functions: public entry points are `rvu_register_dl()` and `rvu_unregister_dl()`. Health reporter setup flows through `rvu_health_reporters_create`, `rvu_npa_health_reporters_create`, `rvu_nix_health_reporters_create`, matching destroy functions, and reporter registration helpers. IRQ handlers include NIX `rvu_nix_af_rvu_intr_handler`, `rvu_nix_af_rvu_gen_handler`, `rvu_nix_af_rvu_err_handler`, `rvu_nix_af_rvu_ras_handler` and NPA `rvu_npa_af_rvu_intr_handler`, `rvu_npa_af_gen_intr_handler`, `rvu_npa_af_err_intr_handler`, `rvu_npa_af_ras_intr_handler`. Dump/recover callbacks are generated via `RVU_REPORTERS` for `hw_nix_*` and `hw_npa_*`. Devlink params are implemented by `rvu_af_dl_dwrr_mtu_*`, `rvu_af_npc_defrag_*`, `rvu_af_npc_exact_feature_*`, `rvu_af_dl_npc_mcam_high_zone_percent_*`, `rvu_af_dl_npc_def_rule_cntr_*`, and `rvu_af_dl_nix_maxlf_*`. Eswitch ops are `rvu_devlink_eswitch_mode_get` and `rvu_devlink_eswitch_mode_set`.

Control flow: registration allocates a devlink object with private `struct rvu_devlink`, links it to `rvu->rvu_dl`, creates NPA and NIX health reporters, registers the base parameter table, conditionally registers CN20K defrag and exact-match parameters, then calls `devlink_register()`. Each NPA/NIX interrupt handler reads the relevant AF interrupt register, stores the value in the reporter event context, clears and disables that interrupt source, then queues work on `rvu_dl->devlink_wq`. The work item calls `devlink_health_report()`, allowing devlink to invoke dump/recover callbacks. Dump callbacks format decoded interrupt bits into `devlink_fmsg`; recover callbacks re-enable the interrupt source if the saved event bitfield is nonzero. Unregister reverses devlink registration, parameter registration, reporter/interrupt setup, and frees the devlink object.

State and persistence: persistent state is the `struct rvu_devlink` attached to `rvu`, allocated NPA/NIX reporter containers, per-subsystem event contexts holding the last interrupt register values, work structs, the devlink workqueue, `rvu->irq_allocated[]`, devlink parameters backed by live RVU state, `rvu->def_rule_cntr_en`, `rvu->rswitch.mode`, and mutable resource fields such as NIX LF maxima and MCAM priority-zone counts. State lasts for the PCI driver lifetime and is not persisted across unload. Health handling intentionally disables an interrupt until recovery re-enables it.

Dependencies and integration: depends on Linux devlink, devlink health reporters, PCI IRQs, workqueues, netlink extack reporting, RVU register helpers, NPA/NIX/NPC register definitions, NPC exact-match/defrag code, NIX scheduler/resource helpers, and switchdev functions (`rvu_switch_enable`, `rvu_switch_disable`). It integrates with user-visible `devlink health`, `devlink dev param`, and `devlink dev eswitch` controls.

Risks: reporter allocation error paths can leak earlier allocations/reporters because some helper failures return immediately without local cleanup until higher-level destroy paths are reached, and destroy helpers assume reporter containers are initialized. Both NPA and NIX reporter registration create `rvu_dl->devlink_wq`; the second assignment can replace the first pointer, risking a leaked workqueue and ambiguous ownership. Interrupt handlers disable sources before asynchronous reporting, so failed or delayed recovery can suppress later events. The NIX RAS handler reads `NIX_AF_ERR_INT` but clears `NIX_AF_RAS`, which is a suspicious register mismatch. Devlink parameter setters mutate global hardware/resource policy at runtime and rely on validators to prevent active-resource changes; missing validation would affect active PF/VF users. Some registration helpers ignore interrupt registration failures and still report success.

Test signals: validate `devlink dev show`, health reporter presence, interrupt injection/report/dump/recover for all NPA/NIX classes, and interrupt re-enable after recovery. Exercise devlink params with valid/invalid values: `dwrr_mtu`, `npc_mcam_high_zone_percent`, `npc_def_rule_cntr`, `nix_maxlf`, CN20K `npc_defrag`, and exact-match disable. Confirm active MCAM/NIXLF users block resizing. Toggle eswitch legacy/switchdev and verify `rvu_switch_enable`/`rvu_switch_disable` effects. Run driver probe/remove with fault injection at each allocation/registration point to catch leaked reporters, IRQs, or workqueues.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_devlink.h

Purpose: declares the RVU AF devlink support structures and public registration functions used by `rvu_devlink.c` and the wider RVU driver. It centralizes health reporter operation boilerplate and defines the event-context layout for NPA and NIX devlink health reporting.

Important APIs/types/functions: `RVU_REPORTERS(_name)` expands to a static `struct devlink_health_reporter_ops` with `.name`, `.recover`, and `.dump` tied to the conventional `rvu_<name>_recover` and `rvu_<name>_dump` functions. `enum npa_af_rvu_health` and `enum nix_af_rvu_health` define reporter classes for RVU, general, error, and RAS interrupt groups. `struct rvu_npa_event_ctx` and `struct rvu_nix_event_ctx` store the last captured interrupt register values. `struct rvu_npa_health_reporters` and `struct rvu_nix_health_reporters` hold event context pointers, four devlink health reporter pointers, and four work items. `struct rvu_devlink` binds the devlink instance, owning `struct rvu`, devlink workqueue, and NPA/NIX reporter containers. Public prototypes are `rvu_register_dl(struct rvu *rvu)` and `rvu_unregister_dl(struct rvu *rvu)`.

Control flow: this header does not execute logic itself; it defines the structure that `rvu_register_dl()` fills, interrupt handlers update, work items report, and `rvu_unregister_dl()` tears down. The macro enforces a naming convention so each reporter declaration in the C file can be one line once matching dump/recover functions exist.

State and persistence: the structures describe runtime-only state attached to the PCI driver instance. Event contexts persist the most recent NPA/NIX interrupt values until overwritten or freed. Work structs are embedded in reporter containers and queued on the shared devlink workqueue. No persistent storage is represented.

Dependencies and integration: depends on devlink health reporter types, workqueue types, and the forward declaration/definition of `struct rvu` from RVU headers included by users. It is included by RVU devlink implementation code and indirectly shapes AF probe/remove behavior through `rvu_register_dl` and `rvu_unregister_dl`.

Risks: the macro relies on exact function naming and only supports `.recover` and `.dump`; adding reporter callbacks needs macro changes or manual ops. The NPA/NIX reporter container layouts are parallel but independent, so changes must be kept symmetric where intended. `struct rvu_devlink` has a single `devlink_wq` shared by both NPA and NIX paths, so ownership must be clear in implementation to avoid leaks or use-after-free.

Test signals: compile coverage catches macro naming mismatches and missing dump/recover functions. Runtime probe/remove tests should verify all embedded work items are initialized before IRQs can queue them and that event contexts/reporters are allocated and freed consistently for both NPA and NIX.
