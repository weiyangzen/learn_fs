# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dcache.c

This file is the Windows cache manager data-cache implementation for OpenAFS file contents. It binds the generic buffer package to AFS FetchData/StoreData RPCs through `cm_bufOps`, manages bulk I/O descriptors for groups of cache buffers, implements background store and prefetch work, handles direct `cm_GetData` reads into caller memory, and optionally verifies stores by reading data back from the file server. It is a central integration point among `cm_buf`, `cm_scache`, Rx, file-server connection selection, callback/status merging, freelance-root data, redirector error reporting, and background daemon retry policy.

Important APIs are `cm_BufWrite`, `cm_StoreMini`, `cm_BufStabilize`, `cm_BufUnstabilize`, `cm_InitDCache`, `cm_HaveBuffer`, `cm_CheckFetchRange`, `cm_BkgStore`, `cm_BkgPrefetch`, `cm_ConsiderPrefetch`, `cm_SetupStoreBIOD`, `cm_SetupFetchBIOD`, `cm_ReleaseBIOD`, `cm_GetBuffer`, `cm_GetData`, and `cm_VerifyStoreData`. `cm_BufWrite` serializes StoreData operations with `CM_SCACHESYNC_STOREDATA_EXCL`, builds a `cm_bulkIO_t` over contiguous dirty buffers, selects 64-bit or legacy StoreData RPCs based on server capability and offsets, streams buffer data with Rx iovecs, merges returned status, clears dirty/write state via `cm_ReleaseBIOD`, and reports fatal write errors to the redirector. `cm_StoreMini` sends a zero-length StoreData for truncation and dirty metadata updates.

The fetch path is split between setup and transfer. `cm_SetupFetchBIOD` first ensures buffer objects exist without holding reservations, then tries to reserve a chunk and collects current-missing non-dirty buffers while setting fetch synchronization state. `cm_GetBuffer` handles already-current buffers, EOF/truncation zero-fill, freelance-root fake directory data, 64-bit FetchData fallback, old file-server offset bug mitigation, read-while-fetching wakeups, buffer data-version updates, and status merge. `cm_GetData` mirrors the RPC path without allocating cache buffers. Background prefetch scans for missing ranges, queues `cm_BkgPrefetch`, and updates `scp->prefetch` only for successfully fetched ranges. Background store marks async-store complete only for non-retryable results.

Persistent state is mostly in shared cache structures, not on disk in this file: `cm_scache_t` length/mask/flags/dataVersion/activeRPCs/prefetch, `cm_buf_t` dirty/error/dataVersion/cmFlags, reserved buffer counts, and optional disk-cache update hooks. Correctness depends on `scp->rw`, buffer mutexes, SyncOp flags, and strict lock dropping around Rx and buffer reservation. Risks include deadlock if buffer reservation or `buf_Get` is called with the wrong locks, stale cache use if data-version ranges are mishandled, 32-bit server fallback errors for large offsets, memory allocation failure in verification, and incorrect async retry classification. Test signals include StoreData/FetchData 64-bit fallback, EOF zero-fill, truncation, dirty contiguous buffer coalescing, redirector status on quota/space/noaccess failures, background prefetch wakeups, freelance root reads, and `buf_ValidateBuffers` / checksum verification paths.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dcache.h

This header declares the public data-cache interface used by the Windows OpenAFS cache manager and buffer package. Its central type is `cm_bulkIO_t`, a descriptor for one fetch or store operation over a list of held `cm_buf_t` buffers. The descriptor records the target scache, user and request pointers, starting offset, transfer length, reserved buffer count, and head/tail queue pointers. The queue ordering matters: the lowest offset buffer is at the end of the list, matching the scan and Rx streaming logic in `cm_dcache.c`.

The exported functions divide into initialization, buffer validity, fetch/store setup, background work, lifecycle, and verification. `cm_InitDCache` installs `cm_bufOps` into the buffer subsystem; `cm_ValidateDCache` delegates validation to the buffer package; `cm_ShutdownDCache` is the current shutdown hook. `cm_HaveBuffer` answers whether an existing buffer can satisfy a read based on callback and data-version state. `cm_GetBuffer` fetches cache-backed data into a `cm_buf_t`, while `cm_GetData` bypasses cache buffers and reads into caller memory. `cm_SetupFetchBIOD` and `cm_SetupStoreBIOD` prepare the buffer lists that the transfer routines consume, and `cm_ReleaseBIOD` unwinds SyncOp state, reservations, and buffer references after success or failure.

The header also exposes background-daemon rock structures. `rock_BkgFetch_t` carries a prefetch base and length to `cm_BkgPrefetch`; `rock_BkgStore_t` carries an async store offset and length to `cm_BkgStore`. `cm_ConsiderPrefetch` is the caller-facing trigger that decides whether to queue background fetch after a foreground read. `cm_BufWrite` is exported because it is both a buffer callback and reused by background store. `cm_StoreMini` supports metadata/truncate StoreData calls, and `cm_VerifyStoreData` supports optional read-back validation.

Dependencies are intentionally forward-declared against `cm_scache_t`, `cm_buf_t`, `cm_user_t`, `cm_req_t`, and `osi_hyper_t`, with concrete semantics implemented in `cm_dcache.c`. State and persistence are indirect: consumers must preserve the scache and user lifetimes promised by comments and must call `cm_ReleaseBIOD` for descriptors that hold buffers or reservations. Risks are API-contract risks: queue ordering, lock preconditions, and ownership are not enforced by the type system. Test signals are compile-time integration with `afsd.h`, buffer-operation registration, and runtime coverage of fetch/store setup followed by release on both success and failure.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dir.c

This file implements classic AFS directory-page manipulation for the Windows cache manager, plus the transactional `cm_dirOp_t` wrapper that coordinates directory buffer locks, scache status, data-version checks, and optional B+ tree acceleration. It operates on the AFS3 on-disk/wire directory format from `cm_dir.h`: 2 KiB pages, 32-byte chunks, a page-zero header with allocation map and hash table, and directory entries threaded through hash buckets. It is used by higher-level lookup, create, remove, enumeration, and ioctl/share enumeration code when local directory buffers need to be read or updated.

Public APIs include `cm_BeginDirOp`, `cm_EndDirOp`, `cm_CheckDirOpForSingleChange`, `cm_NameEntries`, `cm_DirCreateEntry`, `cm_DirDeleteEntry`, `cm_DirMakeDir`, `cm_DirLookup`, `cm_DirLookupOffset`, `cm_DirApply`, `cm_DirIsEmpty`, `cm_DirLength`, `cm_DirHash`, `cm_DirEntryListAdd`, `cm_DirEntryListFree`, `cm_DirDumpStats`, and `cm_MemDumpDirStats`. Internal helpers include `cm_DirGetPage`, `cm_DirReleasePage`, `cm_DirGetBlob`, `cm_DirFindItem`, `cm_DirFindBlobs`, `cm_DirAddPage`, `cm_DirFreeBlobs`, `cm_DirOpAddBuffer`, `cm_DirOpDelBuffer`, `cm_DirCheckStatus`, and `cm_DirPrefetchBuffers`.

Control flow starts with `cm_BeginDirOp`, which holds the scache/user, obtains the directory lock in read or write mode, obtains current status/callback via `cm_DirCheckStatus`, snapshots length and dataVersion, and, when `USE_BPLUS` is enabled, builds or validates `scp->dirBplus`. Directory reads and writes then use `cm_DirGetPage`, which maps a directory page index to the containing cache buffer, fetches it through `buf_Get` and `cm_SyncOp`, and records the buffer in the dirOp table. Lookup hashes the name with the same 173 multiplier used by AFS dirs, walks the hash chain, and prefetches all directory buffers on `CM_ERROR_NOTINCACHE`. Create finds duplicate entries, allocates contiguous free chunks, writes the entry, and links it into the hash table. Delete unthreads the hash chain and frees the occupied chunks. `cm_EndDirOp` releases all locks and, if pages were modified, force-updates data versions for touched buffers and marks the scache local.

State behavior centers on directory buffer data versions. Modified pages are not individually versioned at release; `dirtyBufCount` drives a single `buf_ForceDataVersion` at operation end from the original to the new dataVersion. `cm_CheckDirOpForSingleChange` permits local directory updates only when exactly one server-side change occurred since the op began. Dependencies include `cm_buf`, `cm_scache`, `cm_dcache` fetch checks, `cm_btree` under `USE_BPLUS`, OSI locks/queues, Rx byte order helpers, and logging/performance counters. Risks include the fixed `CM_DIROP_MAXBUFFERS` assertion, stale B+ trees after races, hash-chain corruption, incorrect lock conversion, and local updates after multi-change server races. Test signals include create/delete/lookup round trips, large directory page allocation past old-style limits, empty directory checks ignoring `.` and `..`, prefetch recovery from `CM_ERROR_NOTINCACHE`, B+ rebuild after data-version mismatch, and stats counters/timing output.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dir.h

This header defines the AFS3 directory layout and the Windows cache-manager directory-operation API. The file is explicit that these structures derive from `src/dir/dir.h` and describe wire/protocol layout, so structure sizes and field meanings are compatibility-sensitive. Key constants are `CM_DIR_PAGESIZE` at 2048 bytes, `CM_DIR_NHASHENT` at 128 hash buckets, old and big page limits, 64 entries per page, 32-byte entry chunks, and `CM_DIR_DHE`, the number of reserved chunks in the first page header.

Protocol structures include `cm_dirFid_t` for vnode/unique pairs, `cm_pageHeader_t` for per-page allocation metadata, `cm_dirHeader_t` for page-zero metadata including the allocation map and hash table, and `cm_dirEntry_t` for hash-chain entries with network-order fid values and a variable-length name. The unused `cm_dirXEntry_t`, `cm_dirPage0_t`, and `cm_dirPage1_t` document the physical page shapes but are compiled out. Directory entry flags `CM_DIR_FFIRST` and `CM_DIR_FNEXT` represent first/continuation chunks.

The operation wrapper types are local-cache specific. `cm_dirOpBuffer_t` tracks buffers participating in a transaction-like directory operation, including refcount and in-use flags. `cm_dirOp_t` holds lock type, scache/user/request ownership, the directory length and data versions captured at operation start, adjusted versions after accepted local changes, dirty buffer count, and a small fixed array of operation buffers. Lock constants distinguish no lock, read lock, and write lock; `CM_DIROP_FLAG_NOBUILDTREE` suppresses B+ tree construction for callers that need classic-buffer behavior only.

The exported API provides begin/end lifecycle, safety check for single-change local mutation, classic directory create/delete/make/lookup/apply/empty/length/hash functions, temporary name-list management, and stats dump hooks. `dir_enums` is exported for enumeration telemetry. Dependencies include `cm_scache_t`, `cm_buf_t`, `cm_user_t`, `cm_req_t`, `cm_fid_t`, `osi_hyper_t`, and the B+ directory layer through implementations. Risks are mostly ABI and contract risks: changing structure packing breaks directory compatibility, and callers must respect lock preconditions listed in `cm_dir.c`. Test signals include binary layout assumptions, compile integration with AFS directory consumers, and runtime local directory operations that span multiple buffers.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_direct.c

This file implements direct write support for the Windows cache manager: writing a contiguous caller memory region to the AFS file server without using `cm_buf_t` data storage as the primary source. It exists to support cache-bypass paths while still preserving scache synchronization, StoreData serialization, status merge semantics, retry policy, and asynchronous background write behavior. It shares the StoreData RPC structure with `cm_dcache.c` but bypasses buffer lock and dirty-buffer collection for the data transfer itself.

The main implementation is the static `int_DirectWrite`, wrapped by public `cm_DirectWrite`, background callback `cm_BkgDirectWrite`, completion hook `cm_BkgDirectWriteDone`, and the currently unused `cm_SetupDirectStoreBIOD`. `int_DirectWrite` prepares `AFSStoreStatus` from the scache, respects `CM_DIRECT_SCP_LOCKED`, computes truncation position, increments `activeRPCs`, drops the scache lock around Rx, selects StoreData64 or legacy StoreData depending on `SERVERHAS64BIT`, writes the whole supplied memory region with `rx_Write`, ends the RPC, maps errors, merges status with `CM_MERGEFLAG_STOREDATA | CM_MERGEFLAG_CACHE_BYPASS`, and updates out-of-space or over-quota flags on failure. It also falls back from 64-bit RPCs on `RXGEN_OPCODE`.

`cm_DirectWrite` performs the caller-facing asynchronous path. It checks deleted scache state, allocates a `rock_BkgDirectWrite_t` and private copy of the memory region, obtains `CM_SCACHESYNC_STOREDATA_EXCL | CM_SCACHESYNC_ASYNCSTORE`, queues the background daemon request, and reports the full length as written before the network write completes. The background function calls `int_DirectWrite`, lets retryable network/server conditions remain queued for daemon retry, and frees memory plus clears async-store state on terminal results. `cm_BkgDirectWriteDone` provides a separate cleanup hook that also releases store synchronization and frees the copied memory.

`cm_SetupDirectStoreBIOD` is not currently used, but it can collect all cache buffers overlapping a direct store range, regardless of dirty state, using buffer reservation and `bufCreateLock`. It documents intended cache coherency support for partial cache overlap, but direct writes currently rely on cache-bypass status merge and external invalidation behavior. Dependencies include `cm_dcache.h` for `cm_bulkIO_t`, `cm_conn`, Rx, `cm_scache` masks/flags, background daemon queueing, and buffer APIs for the unused BIOD path. Risks include asynchronous success reporting before durable server write, memory pressure from copying large writes, the apparent `require_64bit_ops` variable never being set in `int_DirectWrite`, retry cleanup paths that must not double-free rocks, and cache coherence with existing cached buffers. Test signals include direct-write retryable error handling, deletion rejection, large offset behavior against non-64-bit servers, quota/space flagging, status merge with cache-bypass, and memory cleanup after terminal and retry paths.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_direct.h

This header declares the direct-write interface for cache-bypass StoreData operations in the Windows OpenAFS cache manager. It depends on `cm_bulkIO_t` from the data-cache layer and on common cache-manager types such as `cm_scache_t`, `cm_user_t`, `cm_req_t`, and `osi_hyper_t`. The public surface is intentionally narrow: setup of direct BIODs, direct write submission, background write execution, and background cleanup.

`cm_DirectWrite` is the primary caller API. It takes a scache, file offset, length, flags, user/request context, a caller memory region, and an output byte count. `CM_DIRECT_SCP_LOCKED` tells the implementation that the caller already holds `scp->rw`, altering lock acquire/release behavior. The function queues background write work in the implementation, so the `bytesWritten` result is an accepted-byte count for the queued memory copy rather than proof that StoreData reached the file server.

`rock_BkgDirectWrite_t` is the background-daemon payload. It stores the target offset and length, a `bypass_cache` marker, and the copied memory region. `cm_BkgDirectWrite` consumes that payload by issuing the StoreData RPC, while `cm_BkgDirectWriteDone` releases store synchronization and frees allocated memory when a background request completes or is discarded. `cm_SetupDirectStoreBIOD` is also declared for collecting buffers overlapping a direct write; the implementation notes it is unused but retained to prevent code rot.

State and persistence are indirect. This header defines no persistent storage, but callers must understand that direct writes affect server-side file contents and scache status while bypassing normal dirty buffer state. Integration points are redirector/write paths, the background daemon, `cm_dcache` bulk descriptors, and StoreData synchronization in `cm_scache`. Risks include misuse of `CM_DIRECT_SCP_LOCKED`, assuming queued bytes are durable bytes, and forgetting that the background rock owns dynamically allocated memory. Test signals are compile-time consumers of `cm_DirectWrite`, background daemon execution, and cleanup behavior when requests are retried or completed.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dnlc.c

This file implements the directory name lookup cache (DNLC) for Windows OpenAFS. The DNLC maps a directory scache plus normalized name to a target scache, speeding pathname lookup before falling back to directory contents. Entries are not scache-refcounted while resident in the cache; lookup takes a hold only on the returned scache. The cache is fixed-size, stored under `cm_data` as an array of `cm_nc_t` entries plus a hash table and freelist, and protected by the global `cm_dnlcLock`.

Important functions are `cm_dnlcInit`, `cm_dnlcEnter`, `cm_dnlcLookup`, `cm_dnlcRemove`, `cm_dnlcPurgedp`, `cm_dnlcPurgevp`, `cm_dnlcPurge`, `cm_dnlcPurgeVol`, `cm_dnlcValidate`, and `cm_dnlcShutdown`. Internal helpers `GetMeAnEntry`, `InsertEntry`, and `RemoveEntry` manage freelist/hash movement. `cm_dnlcEnter` ignores disabled cache, null names, `.` and `..`, names exceeding `CM_AFSNCNAMESIZE`, and either updates an existing entry or evicts the oldest entry from a hash bucket. `cm_dnlcLookup` supports case-sensitive and case-folded search through `cm_lookupSearch_t`, filling exact/lowercase/uppercase/mixed-case match flags and fid fields before holding the target scache. Remove and purge variants clear by directory, target scache, or whole cache.

Control flow uses read locks for lookup and initial enter scans, converting to write when insertion is required. Hash buckets are circular doubly linked lists, with explicit safety counters to detect cycles. On structural anomalies, the code increments cycle stats and purges the whole cache to recover. Initialization reads `UseDNLC` and `DebugDNLC` from the OpenAFS client registry key, initializes the lock, and, for new cache files, lays out `nameCache`, `nameHash`, and `ncfreelist` inside the persistent `cm_data.dnlcBaseAddress` region.

State behavior is semi-persistent because the cache arrays live in `cm_data`, which is part of the cache manager's shared cache data, but entries are opportunistic and safely purgeable. Dependencies include normalized string helpers, scache magic validation, registry APIs, OSI locks/queues, and lookup search structures. Risks include stale unrefcounted scache pointers if purge hooks are missed, circular list corruption, fixed 40-character normalized-name limit, and global purge on volume-specific purge. Test signals include registry enable/disable, exact and case-folded lookup ambiguity flags, purge on scache recycle or directory callback loss, validation recovering from corrupted links, and lookup miss/enter/remove counters.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dnlc.h

This header defines the directory name lookup cache data structures and public API. The cache is deliberately small and fixed-size: `NCSIZE` is 512 entries and `NHSIZE` is 256 hash buckets. `CM_AFSNCNAMESIZE` limits cached normalized names to 40 `normchar_t` values, chosen as a multiple of eight for 64-bit alignment. `CM_DNLC_MAGIC` tags entries so `cm_dnlcValidate` can detect corruption or stale memory.

`cm_nc_t` is the cache entry. It contains a magic value, precomputed hash key, circular-list links, directory scache pointer, target scache pointer, and normalized name. Entries in active hash buckets use `next` and `prev` as circular doubly linked list links; entries on the freelist are identified by null `prev`. `cm_dnlcstats_t` collects operational counters for enters, lookups, misses, removes, purges, cycle detection, and lookup races. The `dnlcHash` macro hashes normalized names case-insensitively by uppercasing each normalized character and applying the AFS directory hash multiplier of 173.

The exported functions support insert, remove by directory/name, purge by directory, purge by target vnode, whole-cache purge, volume purge, initialization, shutdown, lookup, and validation. `cm_dnlcLookup` takes a `cm_lookupSearch_t` because it needs to report more than a boolean hit: exact and case-folded match classifications feed Windows pathname semantics and ambiguous-name handling. Initialization and storage are implemented in `cm_dnlc.c`; this header exposes the shape because the cache arrays are part of broader cache-manager shared state.

Dependencies include `cm_scache_t`, `cm_lookupSearch_t`, `AFSFid`, `normchar_t`, and normalized string helpers from the surrounding afsd code. There is no durable correctness requirement for DNLC contents; it is an opportunistic accelerator and must be purgeable at any time. Risks are compile-time ABI coupling to `cm_data` layout, stale pointer exposure if callers forget purge hooks, and hash macro side effects because it advances the `ts` pointer. Test signals include cache hit/miss behavior for exact and case-insensitive names, long-name bypass, purge functions, and validation of magic/list invariants.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dns.c

This file implements DNS discovery of AFS database servers for the Windows cache manager. It supports two environments. On modern Windows with `DnsQuery` available (`DNSAPI_ENV`), it queries SRV records for `_<service>._<protocol>.<cell>` and falls back to AFSDB records. Without the DNS API, it contains a manual UDP DNS client that builds and parses DNS packets for AFSDB and A records using the structures in `cm_dns_private.h`. Public entry points are `cm_InitDNS`, `getAFSServer`, `getAFSServerW` under DNS API builds, `DNSlowerCase`, and legacy helper `putQName`; `cm_dns.h` also declares `DNSgetHostByName`, though this file does not define it in the visible build path.

Manual-DNS control flow reads a name-server address from `AFS_NS` or `afsdns.ini`, builds recursive queries with fixed IDs, encodes QNAMEs via `putQName`, sends UDP packets to port 53, receives into a 2048-byte buffer, parses compressed names, filters AFSDB class/preference 1, resolves returned hostnames to A records, and fills server address/name/port/rank arrays. DNS API control flow uses `DnsQuery_A` or `DnsQuery_W`, first for SRV, then AFSDB. For each server name it records priority/admin rank, network-byte-order port, TTL from the first record, and attempts to find or separately query matching A records, including simple CNAME-to-A matching. `Freelance.Local.Root` is intentionally excluded from DNS lookup.

State is minimal: static `dns_addr` for legacy UDP mode and static `cm_dnsEnabled` for initialization state. Results are caller-provided arrays with `numServers` and `ttl` out parameters. Integration points include cell configuration discovery in `cm_config`/ioctl paths, Windows DNS APIs, winsock, UTF-8/UTF-16 string comparison helpers, and `AFSMAXCELLHOSTS`/`MAXHOSTCHARS` limits from AFS headers. Ports are stored in network byte order; SRV uses the advertised port, while AFSDB uses the caller-provided fallback.

Risks include manual parser bounds assumptions, fixed 2048-byte packet buffer, fixed query IDs, lack of TCP fallback, partial CNAME handling when additional records are absent, output-array overflow if API results exceed caller limits in paths not checking every increment, and DNS API dependence hidden behind compile macros. The legacy `putQName` mutates its input by lowercasing it. Test signals include SRV success, SRV absent with AFSDB fallback, CNAME target resolution, no-address server names, TTL propagation, Unicode `getAFSServerW`, disabled DNS initialization, missing `AFS_NS`/INI behavior, and freelance-root rejection.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dns.h

This header declares the public DNS lookup interface used by the Windows OpenAFS cache manager to discover AFS cell servers. It defines `DNS_PORT` as 53 and exposes ANSI and Unicode server-discovery functions. The ANSI `getAFSServer` takes service, protocol, cell name, default AFSDB port, output arrays for IPv4 addresses, hostnames, ports, ranks, server count, and TTL. The Unicode `getAFSServerW` mirrors that contract with `cm_unichar_t` hostnames and is only implemented when the Windows DNS API environment is available.

The output contract is important. `cellHostAddrs` receives IPv4 addresses when resolvable, but DNS SRV or AFSDB discovery may still produce names with address zero if A record resolution fails. `cellHostNames` is bounded by `MAXHOSTCHARS`, ports are in network byte order, ranks reflect SRV priority or zero for AFSDB fallback, and `ttl` captures the DNS TTL used by higher-level configuration caching. The caller provides `afsdbPort` so AFSDB records can be mapped to the correct VLDB service port.

`DNSgetHostByName` is declared as a supplement for older resolver environments that did not call DNS for `gethostbyname`; it is not implemented in `cm_dns.c` on the modern DNS API path, so consumers must be conditioned by platform/build expectations. Dependencies include `cm_unichar_t`, `afs_uint32`, `MAXHOSTCHARS`, and the surrounding AFS cell configuration headers.

This file does not persist state. Its integration role is to decouple cell discovery callers from the implementation choice of Windows `DnsQuery` versus legacy packet code. Risks are header/implementation signature drift: the header uses `afs_uint32 *cellHostAddrs`, while the C implementation's visible signature uses `int *` for the same array, relying on compatible 32-bit representation. Test signals include successful compilation across DNS API and non-DNS API builds, correct network-byte-order ports, and callers handling zero returned servers with `-1`.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dns_private.h

This private header supports the non-`DNSAPI_ENV` manual DNS client in `cm_dns.c`. It defines socket aliases for kernel versus user builds, packet buffer size, AFS server list limits, DNS packet header structures, query-tail structures, resource-record header structures, numeric DNS RR types/classes, and helper prototypes for QNAME encoding and parsing. These structures model RFC 1034/1035 packet layouts closely enough for AFSDB and A record lookup in legacy Windows environments.

Key types are `DNS_HDR`, `DNS_QTAIL`, `DNS_RR_HDR`, `DNS_AFSDB_RR_HDR`, and `DNS_A_RR_HDR`, each with pointer typedefs used by packet parser code. Constants include `BUFSIZE` at 2048 bytes, `MAX_AFS_SRVS` at 20, `DNS_FLAG_RD` for recursive queries, common RR types (`A`, `CNAME`, `MX`, `AFSDB`, etc.), and IN/CS/CH/HS/wildcard classes. `AFS_SRV_LIST` is a simple count plus hostname array for legacy service lists, though the current code fills caller arrays directly.

The control-flow role is purely structural: `send_DNS_AFSDB_Query` and `send_DNS_Addr_Query` cast the raw buffer to these headers, `putQName` writes encoded names, `skipRRQName` advances across compressed or uncompressed names, and `processReplyBuffer_*` casts answer sections to the RR header types to extract class, TTL, preference, hostnames, and IPv4 addresses. The header also hardcodes `DNS_A_RR_HDR_LEN` as 10 rather than using `sizeof`, acknowledging packet packing/alignment mismatch.

There is no persistent state. Dependencies are C networking types, stdio/string headers, and the manual parser in `cm_dns.c`; modern DNS API builds largely bypass this header except for include availability. Risks include C structure padding if used incorrectly, insufficient bounds checking in callers, only partial DNS compression handling, and assumptions about IPv4-only records. Test signals are legacy builds that disable `DNSAPI_ENV`, manual AFSDB query parsing, compressed-name responses, and A record extraction from packets.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_eacces.c

This file implements a small cache of `EACCES` outcomes keyed by user and fid, with secondary indexes by parent fid and user. The purpose is to remember access-denied events so later path handling can distinguish authorization problems from missing objects and clear those remembered failures when relevant parent callbacks or user tokens change. Entries store the denied fid, parent fid, user pointer, and timestamp. They are heap allocated, recycled through a freelist, and protected by `cm_eaccesLock`.

Public APIs are `cm_EAccesInitCache`, `cm_EAccesAddEntry`, `cm_EAccesFindEntry`, `cm_EAccesClearParentEntries`, `cm_EAccesClearUserEntries`, and `cm_EAccesClearOutdatedEntries`. Initialization uses `osi_once_t` for lock setup, then allocates head/tail arrays for fid, parent, and user hash tables. Table sizes are derived from `cm_data.stats * 2` for fid and parent indexes and fixed at 32 for user indexes. Add first searches the fid hash for an existing `(userp,fid)` entry, allocates or reuses an entry if absent, holds the user, adds it to fid and user indexes, updates `errorTime`, removes the old parent index if the parent changes, and inserts into the new parent index.

Find scans the fid hash and returns a raw entry pointer without taking an additional reference, so callers must treat it as protected only by cache lifetime and invalidation discipline. Clear-by-parent removes all entries whose parent matches a callback/recycle event, unlinking from all three indexes, releasing the held user, and moving entries to the freelist. Clear-by-user removes entries for a user, optionally limited by cell ID, and is used when tokens expire or are replaced. Clear-outdated removes entries older than four hours.

State is process memory only and can be rebuilt from future errors. Dependencies include OSI queues, `opr_jhash`, fid comparison, user hold/release, `cm_data.stats`, and lock hierarchy constants. A notable risk is that several mutation routines obtain a read lock while removing from queues; correctness depends on the OSI lock semantics or is a potential concurrency defect if read locks permit concurrent readers/writers. Other risks include allocation failures not checked during initialization/add, hash macros relying on power-of-two table sizes, raw pointer returns from find, and stale entries if invalidation hooks are missed. Test signals include add/find for same user/fid, parent change reindexing, parent callback clearing, token/cell clearing, four-hour expiry, freelist reuse, and concurrent lookup during clearing.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_eacces.h

This header defines the EACCES cache entry type and API for the Windows OpenAFS cache manager. The cache records access-denied events by fid and user, with the parent fid included so the error can be invalidated when parent directory knowledge changes. The comments specify the intended lifecycle: entries are removed when the parent fid callback expires or is replaced, when the parent scache is recycled, or when the user's tokens expire or are replaced; recycling the denied fid's scache alone does not remove the entry.

`cm_eacces_t` contains a primary queue node, magic value, secondary queue nodes for parent and user indexes, the denied fid, parent fid, held user pointer, and error timestamp. `CM_EACCES_MAGIC` is used for validation/debugging. The `parentq_to_cm_eacces_t` and `userq_to_cm_eacces_t` macros recover the containing entry from embedded queue nodes using `offsetof`. Hash macros compute fid, parent, and user buckets with `opr_jhash` and table-size masks; their table-size symbols are defined in the C file.

The exported API initializes the cache, finds an entry by `(user,fid)`, adds or refreshes an entry with parent fid, clears entries for a parent fid, clears entries for a user and optional cell, and clears outdated entries. The API returns a raw pointer from find and a numeric status from add, with invalidation handled by explicit clear calls from callback/token paths.

Dependencies include `osi.h`, `cm_scache.h`, `cm_fid_t`, `cm_user_t`, queue layout, and jhash availability. There is no durable persistence; this is a runtime advisory cache. Risks are macro coupling to static table-size variables, power-of-two table-size assumptions, raw pointer lifetime after find, and the need for every relevant callback/token transition to call the appropriate clear routine. Test signals include compilation of container macros, add/find/clear behavior under multiple parents and users, and expiration after the configured time window in the implementation.

# sources/distributed-fs/openafs/src/WINNT/afsd/cm_error.h

This header defines the Windows cache manager's internal `CM_ERROR_*` code range. `CM_ERROR_BASE` is `0x66543200`, and the file assigns stable numeric offsets for cache-manager conditions that are not represented directly by platform errors or raw Rx/AFS protocol errors. These codes are consumed throughout `afsd` by connection analysis, SMB/redirector mapping, ioctl handling, buffer store/fetch logic, directory logic, DNS fallback, and user-visible status conversion.

The error set covers object discovery (`NOSUCHCELL`, `NOSUCHVOLUME`, `NOSUCHFILE`, `NOSUCHPATH`, `PATH_NOT_COVERED`, `NOT_A_DFSLINK`), retry and server state (`TIMEDOUT`, `RETRY`, `ALLBUSY`, `ALLOFFLINE`, `ALLDOWN`, `EMPTY`), authorization/token failures (`NOACCESS`, `NOMORETOKENS`, `BADPASSWORD`, `BADLOGONTYPE`, `GSSCONTINUE`), filesystem semantics (`TOOBIG`, `EXISTS`, `CROSSDEVLINK`, `NOTDIR`, `ISDIR`, `READONLY`, `QUOTA`, `SPACE`, `NOTEMPTY`), SMB/RPC integration (`BADSMB`, `BADTID`, `NOIPC`, `TIDIPC`, `RPC_MOREDATA`), filename/path interpretation (`BADNTFILENAME`, `AMBIGUOUS_FILENAME`, `INEXACT_MATCH`, `TOO_MANY_SYMLINKS`), byte-range and sharing behavior (`LOCK_CONFLICT`, `SHARING_VIOLATION`, `RANGE_NOT_LOCKED`, `LOCK_NOT_GRANTED`), cache/buffer state (`TOOFEWBUFS`, `TOOMANYBUFS`, `NOTINCACHE`, `BUFFERTOOSMALL`, `BUFFER_OVERFLOW`), and protocol/data integrity (`INVAL_NET_RESP`, `BADFORMAT`, `BULKSTAT_FAILURE`).

There is no control flow or persisted state in this file, but the numeric assignments are persistent ABI within the client: logs, error mappers, retry policy, and callers switch on these constants. Integration points include `cm_MapRPCError`, `smb_MapNTError`, `cm_Analyze`, background daemon retry lists, buffer error marking, and directory/cache lookup special cases. Risks include changing numeric values, adding duplicates, or omitting new codes from mapping and retry switch statements. Test signals are compile-time switch coverage, correct NT/SMB/POSIX mapping, retry classification for transient codes, and log readability through `cm_conn` error string conversion.
