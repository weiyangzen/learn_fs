# sources/distributed-fs/ceph-client/net/sched/cls_api.c

Purpose: implements the core Linux traffic-control classifier API for this source tree. It registers classifier kinds, creates and destroys `tcf_proto` instances, owns TC filter blocks/chains, handles rtnetlink filter and chain commands, runs classifier chains on packets, manages classifier action extensions, and bridges classifier/action state to hardware offload callbacks.

Important APIs/types/functions: `register_tcf_proto_ops`, `unregister_tcf_proto_ops`, and `tcf_proto_lookup_ops` maintain the global classifier kind registry guarded by `cls_mod_lock`. `struct tcf_block`, `struct tcf_chain`, `struct tcf_proto`, `struct tcf_filter_chain_list_item`, and `struct tcf_net` are the main state carriers. Block and chain lifecycle is handled by `tcf_block_get_ext`, `tcf_block_put_ext`, `tcf_block_lookup`, `tcf_chain_get_by_act`, `tcf_chain_put_by_act`, `tcf_get_next_chain`, `tcf_get_next_proto`, `tcf_chain_flush`, and `tcf_chain_tp_*`. Packet execution runs through `tcf_classify` and `__tcf_classify`. Netlink command handlers are `tc_new_tfilter`, `tc_del_tfilter`, `tc_get_tfilter`, `tc_dump_tfilter`, `tc_ctl_chain`, and `tc_dump_chain`. Filter serialization and notification use `tcf_fill_node`, `tfilter_notify`, `tfilter_del_notify`, `tc_chain_fill_node`, and `tc_chain_notify`. Extension/action helpers include `tcf_exts_init_ex`, `tcf_exts_destroy`, `tcf_exts_validate_ex`, `tcf_exts_dump`, `tcf_exts_dump_stats`, `tc_setup_action`, `tc_setup_offload_action`, and `tcf_exts_num_actions`. Offload integration is exposed through `tc_setup_cb_call`, `tc_setup_cb_add`, `tc_setup_cb_replace`, `tc_setup_cb_destroy`, and `tc_setup_cb_reoffload`. Queue event support is provided by `tcf_qevent_init`, `tcf_qevent_destroy`, `tcf_qevent_validate_change`, `tcf_qevent_handle`, and `tcf_qevent_dump`.

Control flow: classifier modules register a `tcf_proto_ops` object, which is later looked up by filter creation. `tc_new_tfilter` parses `RTM_NEWTFILTER`, finds the target qdisc/class or shared block, conditionally takes RTNL depending on qdisc/classifier unlocked support, gets or creates the target chain, finds or creates the `tcf_proto`, then calls the classifier's `change` op. Deletion mirrors that path in `tc_del_tfilter`: it can flush a whole chain, remove a whole proto, or delete a concrete filter handle through `ops->delete`, and then delete the proto if the classifier reports it is empty. `tc_get_tfilter` and `tc_dump_tfilter` traverse block, chain, proto, and classifier walker callbacks to produce netlink output. Chain commands use `tc_ctl_chain` to create, delete, get, and optionally attach classifier templates.

Packet classification starts at `tcf_classify`, which optionally consumes `TC_SKB_EXT` metadata for hardware misses or chain resumes, locates the requested chain, and delegates to `__tcf_classify`. The inner loop walks `tcf_proto` nodes, checks protocol unless resuming an action miss by cookie, calls the classifier-specific `classify` function, and handles `TC_ACT_RECLASSIFY` and `TC_ACT_GOTO_CHAIN` with a 16-iteration loop guard. On misses with skb extension support enabled, it stores the last executed chain and post-ct metadata back into a skb extension so later pipeline stages can resume or report miss context.

State and persistence behavior: all state is in-kernel runtime state. Per-net shared blocks live in `struct tcf_net`'s IDR; classifier kinds live in the process-global `tcf_proto_base` list; action miss cookies live in `tcf_exts_miss_cookies_xa`; deferred destruction uses the ordered `tc_filter_wq`; block hardware callbacks live in `block->flow_block.cb_list`; chain-zero head-change callbacks keep qdisc-visible filter-chain heads synchronized. Lifetimes are guarded by block mutexes, chain `filter_chain_lock`, `cb_lock`, RTNL when required, RCU list updates, `kfree_rcu`, refcounts on blocks/protos/chains, module refcounts, and action net namespace refs via `tcf_exts_get_net`/`tcf_exts_put_net`. No persistent on-disk state is written.

Dependencies/integration points: this file is the central integration layer between rtnetlink (`RTM_*TFILTER`, `RTM_*CHAIN`), qdisc/class operations (`Qdisc_class_ops::tcf_block`, class find/bind callbacks), classifier modules (`struct tcf_proto_ops`), tc actions (`act_api`, `tcf_action_*`), ematch users through classifier-specific trees, skb extensions, net namespaces, netdev offload APIs (`ndo_setup_tc`, `flow_block`, `flow_action`, `flow_indr_dev_setup_offload`), and qevent users in qdiscs. It exports many helpers consumed by classifier modules such as basic, bpf, flower, u32, route, matchall, fw, and by qdisc code.

Risks: the code is concurrency-sensitive. Incorrect lock ordering between RTNL, `cb_lock`, block lock, and chain lock can deadlock, and unlocked classifier paths must preserve block/proto refs carefully. Chain/proto deletion is split across RCU and destroy-in-progress tracking; missing `tcf_proto_signal_destroying` or `tcf_proto_signal_destroyed` can allow duplicate priority/protocol insertion races. Hardware miss cookies deliberately avoid hard refs and rely on revalidation; stale cookies cause packet drop with `SKB_DROP_REASON_TC_COOKIE_ERROR`. Offload counters and flags are updated under `cb_lock` plus proto spinlock; inconsistent updates would expose wrong `in_hw`/`not_in_hw` reporting or block offload state. Netlink dump consistency is best-effort because dumps can release RTNL between skb fills. qevent handling can drop, steal, or redirect packets based on attached filters, so action return handling is a packet-loss-sensitive path.

Test signals: exercise `tc filter add/change/replace/del/get/show` against qdisc-attached and shared-block filters, including auto priority allocation, chain selection, chain create/delete/get/dump, whole-chain flush, and classifier module autoload. Run with classifiers that have and lack `TCF_PROTO_OPS_DOIT_UNLOCKED`. Validate RCU lifetime with repeated replace/delete while traffic is classifying. Cover action extension validation, legacy police compatibility, terse dumps, hardware offload add/replace/destroy/reoffload, skip-sw/skip-hw behavior in classifier modules, and skb-extension hardware miss resume paths. qevent users should verify drop/stolen/redirect return mapping. Kernel selftests under `tools/testing/selftests/tc-testing` and `tc`/`iproute2` integration tests are the practical signal sources.

# sources/distributed-fs/ceph-client/net/sched/cls_basic.c

Purpose: implements the `basic` TC classifier, a simple ordered list of filters that match using the generic ematch tree and then execute TC actions/extensions or return a bound class result. It is useful when classification logic can be expressed entirely through ematches rather than a specialized key parser.

Important APIs/types/functions: `struct basic_head` owns the RCU filter list and handle IDR. `struct basic_filter` stores the handle, `tcf_exts`, `tcf_ematch_tree`, `tcf_result`, parent `tcf_proto`, list node, per-CPU packet counters, and deferred RCU work. Main ops are `basic_classify`, `basic_init`, `basic_get`, `basic_change`, `basic_delete`, `basic_destroy`, `basic_walk`, `basic_dump`, and `basic_bind_class`. `basic_policy` accepts `TCA_BASIC_CLASSID` and nested `TCA_BASIC_EMATCHES`; actions and police are initialized through `tcf_exts_init(..., TCA_BASIC_ACT, TCA_BASIC_POLICE)`.

Control flow: `basic_init` allocates the head and installs it in `tp->root`. `basic_change` parses options, allocates or replaces a filter, allocates a handle through the IDR when needed, initializes extensions and per-CPU counters, validates actions and ematches in `basic_set_parms`, binds any classid to the qdisc class, and inserts or RCU-replaces the filter in the list. `basic_classify` walks filters in list order under RCU, increments `rcnt`, evaluates the ematch tree, increments `rhit` on match, copies the stored result, and calls `tcf_exts_exec`; a negative action result means continue to the next filter, otherwise return the action/classification verdict. Delete and destroy unlink filters with `list_del_rcu`, unbind class results, remove handles, and defer freeing if action net refs require it.

State and persistence behavior: filter state is memory-only under `tp->root`. Handles are tracked in an `idr`; packet and hit counters are per-CPU `struct tc_basic_pcnt` values aggregated during dump; filter replacement uses `list_replace_rcu`; old filters are freed by `basic_delete_filter_work` through `tcf_queue_work` after RCU grace period and with RTNL held. The classifier writes no persistent data.

Dependencies/integration points: relies on the core classifier API in `cls_api.c`, `tcf_exts` action/police validation and execution, ematch validation/matching/dumping, class binding helpers `tcf_bind_filter`, `tcf_unbind_filter`, and `tc_cls_bind_class`, netlink attributes from `include/uapi/linux/pkt_cls.h`, and module registration through `register_tcf_proto_ops`. It does not implement hardware offload or custom protocol parsing.

Risks: counter increments happen on every candidate filter before match, so counter semantics are "evaluated" and "matched", not packet verdicts. Error cleanup must remove newly allocated handles only for newly created filters; otherwise replacement could corrupt the IDR. `basic_set_parms` binds classids after validation, and replacement unbinds only the old filter, so class binding regressions are possible if error paths change. Lifetime depends on pairing `tcf_exts_get_net` with deferred work and `tcf_exts_put_net`; freeing too early would race RCU classifiers or actions.

Test signals: add filters with only ematches, with actions, and with bound classids; verify ordered matching and continue-on-negative-extension behavior. Replace existing handles and ensure the old filter disappears from dumps after grace period. Dump counters after traffic to confirm `TCA_BASIC_PCNT` aggregates per-CPU `rcnt` and `rhit`. Delete one filter and destroy the containing proto/block to validate IDR cleanup, class unbinds, and action stats dumping.

# sources/distributed-fs/ceph-client/net/sched/cls_bpf.c

Purpose: implements the `bpf` TC classifier, allowing classic socket-filter bytecode or eBPF `BPF_PROG_TYPE_SCHED_CLS` programs to classify packets and optionally return direct TC action verdicts. It also supports TC hardware offload callbacks for BPF classifier programs.

Important APIs/types/functions: `struct cls_bpf_head` owns the program list and handle IDR. `struct cls_bpf_prog` stores the `bpf_prog`, old classic-BPF ops copy, optional eBPF name, handle, class result, action extensions, direct-action flag (`exts_integrated`), generic flags (`skip_sw`, `skip_hw`, in-hardware reporting), hardware count, and deferred work. Core functions are `cls_bpf_classify`, `cls_bpf_change`, `cls_bpf_delete`, `cls_bpf_destroy`, `cls_bpf_get`, `cls_bpf_dump`, `cls_bpf_walk`, `cls_bpf_reoffload`, `cls_bpf_prog_from_ops`, `cls_bpf_prog_from_efd`, `cls_bpf_offload`, `cls_bpf_offload_cmd`, and `cls_bpf_offload_update_stats`. Netlink policy covers classid, classic BPF ops, eBPF fd/name, direct-action flags, and generic skip flags.

Control flow: `cls_bpf_change` parses options, allocates a handle, validates actions, enforces exactly one of classic-BPF bytecode or eBPF fd, validates direct-action and skip flags, builds the program with `bpf_prog_create` or `bpf_prog_get_type_dev`, binds an optional classid, attempts hardware offload, marks `NOT_IN_HW` if needed, updates software-use accounting, and inserts or RCU-replaces the program. `cls_bpf_classify` walks programs in list order. For skip-sw programs it avoids running the BPF program; for ingress packets it temporarily pushes the MAC header before running so BPF sees expected data pointers. In direct-action mode, the BPF return is sanitized by `cls_bpf_exec_opcode` and used as a TC action verdict, while the classid comes from `qdisc_skb_cb(skb)->tc_classid` combined with the major class. In non-direct-action mode, return `0` means no match, return `-1` means use the configured `prog->res`, and any other nonzero value becomes the classid before actions execute.

State and persistence behavior: program state is runtime-only under `tp->root`. Classic programs own a copied `sock_filter` array and a `bpf_prog` destroyed with `bpf_prog_destroy`; eBPF programs hold a fd-acquired ref released by `bpf_prog_put` and may own a duplicated name. Handles live in an IDR. Program replacement uses `list_replace_rcu`; old programs are freed through `cls_bpf_delete_prog_work` after extension net refs and RCU work. Offload state is tracked by `gen_flags` and `in_hw_count`, with stats refreshed before dump.

Dependencies/integration points: integrates with BPF core (`bpf_prog_run_data_pointers`, `bpf_prog_get_type_dev`, `BPF_PROG_TYPE_SCHED_CLS`), TC core action extension helpers, class binding, qdisc ingress helpers, hardware offload callbacks using `TC_SETUP_CLSBPF`, and `tcf_block_netif_keep_dst` when a BPF program needs destination metadata. Module registration exposes kind `bpf`.

Risks: direct-action and non-direct-action modes have different return semantics; confusing them can silently turn BPF return values into classids or TC verdicts. `skip_sw` requires successful hardware presence, and offload failure attempts rollback by calling the opposite offload command; rollback gaps would leave driver state inconsistent. Ingress MAC push/pull must remain balanced around BPF execution. Replacement deliberately unbinds the old class result and queues old program destruction; premature free would race classification. Dumping classic bytecode copies the saved user instructions, while eBPF dumps id/tag/name only, so tooling must handle both representations.

Test signals: load classic-BPF and eBPF classifiers; verify invalid combinations of fd and ops are rejected. Test direct-action returns for `OK`, `SHOT`, `STOLEN`, `TRAP`, `REDIRECT`, `UNSPEC`, and unsupported return values. Test non-direct-action return `0`, `-1`, and explicit classid values. Exercise `skip_sw`, `skip_hw`, hardware offload add/replace/destroy/reoffload, stats update on dump, ingress execution, class binding, replacement by handle, and deletion cleanup under traffic.

# sources/distributed-fs/ceph-client/net/sched/cls_cgroup.c

Purpose: implements the `cgroup` TC classifier, which maps packets to the classid associated with the originating task/socket cgroup and optionally gates that mapping through ematches and actions.

Important APIs/types/functions: `struct cls_cgroup_head` stores the single filter handle, action extensions, ematch tree, owning proto, and deferred work. Main ops are `cls_cgroup_classify`, `cls_cgroup_change`, `cls_cgroup_destroy`, `cls_cgroup_walk`, `cls_cgroup_dump`, and the unsupported `cls_cgroup_delete`. `cgroup_policy` accepts nested `TCA_CGROUP_EMATCHES`; actions and police use `TCA_CGROUP_ACT` and `TCA_CGROUP_POLICE`. The classification key comes from `task_get_classid(skb)`.

Control flow: `cls_cgroup_init` leaves `tp->root` empty. The first `cls_cgroup_change` requires an explicit handle when no head exists, validates options, initializes extensions, parses actions and ematches, assigns the new head to `tp->root`, and queues any old head for destruction. `cls_cgroup_classify` returns no match if no head exists, if `task_get_classid` returns zero, or if ematches fail; otherwise it sets `res->classid` to the cgroup classid, clears `res->class`, and executes extensions. Delete is unsupported, so removal happens by replacing the whole classifier instance or destroying the proto.

State and persistence behavior: there is at most one runtime head per `tcf_proto`; no IDR or list is used. Replacement is an RCU pointer swap through `rcu_assign_pointer(tp->root, new)`, with old state freed through `cls_cgroup_destroy_work` when action net refs require deferred cleanup. The cgroup classid itself is external kernel/cgroup state, not persisted here. This file writes no persistent data.

Dependencies/integration points: depends on `net/cls_cgroup.h` for `task_get_classid`, the core TC classifier API, ematch helpers, TC action extension helpers, and netlink attributes from `pkt_cls.h`. It registers kind `cgroup` with the shared classifier registry.

Risks: `cls_cgroup_dump` assumes the caller supplies a valid `head`; dump paths should not pass NULL handles for this classifier because `tp->root` can be NULL after init. Since `delete` returns `-EOPNOTSUPP`, generic filter deletion behavior differs from list-based classifiers. Classification depends on skb/task association; packets without cgroup classid always miss. Replacement must not free the old head until RCU/action users are done.

Test signals: create a cgroup classifier with an explicit handle, set cgroup `net_cls` classid, send traffic from a classified task, and verify selected qdisc class/action behavior. Check zero classid miss behavior, ematch gating, action stats dumping, replacement with the same handle, rejection of missing first handle or wrong replacement handle, and `tc filter del` returning unsupported for a single filter delete.

# sources/distributed-fs/ceph-client/net/sched/cls_flow.c

Purpose: implements the `flow` TC classifier, which maps packets into classids by extracting one or more flow keys and either hashing them or applying a map transform. It supports ematch gating, TC actions, periodic hash perturbation, and class selection based on headers, skb metadata, route/class metadata, socket credentials, VLAN, rxhash, and optional conntrack tuples.

Important APIs/types/functions: `struct flow_head` owns the filter list. `struct flow_filter` stores filter handle, key configuration (`nkeys`, `keymask`, mode, mask/xor/rshift/addend/divisor/baseclass), random hash seed, perturb timer, ematches, extensions, proto pointer, and deferred work. Key extractors include `flow_get_src`, `flow_get_dst`, `flow_get_proto`, `flow_get_proto_src`, `flow_get_proto_dst`, `flow_get_iif`, `flow_get_priority`, `flow_get_mark`, `flow_get_nfct*`, `flow_get_rtclassid`, `flow_get_skuid`, `flow_get_skgid`, `flow_get_vlan_tag`, and `flow_get_rxhash`; `flow_key_get` dispatches by `FLOW_KEY_*`. Main classifier ops are `flow_classify`, `flow_change`, `flow_delete`, `flow_init`, `flow_destroy`, `flow_get`, `flow_dump`, and `flow_walk`.

Control flow: `flow_change` parses `TCA_FLOW_*` options, validates baseclass, keymask, mode, perturbation, and namespace constraints for socket UID/GID keys, allocates a new filter, validates ematches and actions, copies old settings on replacement, and applies changed options. New filters require a nonzero handle and `TCA_FLOW_KEYS`; replacement can partially update an existing filter. If no major baseclass is supplied for a non-shared block, it derives one from the qdisc handle; shared blocks must specify baseclass explicitly. Hash mode can use multiple keys and optional perturbation, while map mode allows only one key. The filter is inserted or RCU-replaced, and old filters are queued for deferred destruction.

During `flow_classify`, each filter first checks ematches. It dissects packet flow keys only when the selected keymask needs header-derived keys, fills a compact key array in bit order, computes either `jhash2(keys, nkeys, hashrnd)` for hash mode or a single-key map transform using mask, xor, right shift, and addend, then applies divisor if configured. The result classid is `TC_H_MAKE(baseclass, baseclass + classid)`, and action extensions decide the final verdict; negative extension return continues to the next filter.

State and persistence behavior: filter state is runtime-only in the RCU list under `tp->root`. Each filter owns a deferrable perturb timer that periodically refreshes `hashrnd`. `timer_shutdown_sync` runs before freeing. Deferred destruction uses `flow_destroy_filter_work` through the TC filter workqueue after action net refs are acquired. No IDR is used; handles are found by linear list scan. No state is persisted beyond kernel memory.

Dependencies/integration points: integrates with TC core, ematch/action helpers, qdisc block metadata, `skb_flow_dissect_flow_keys`, skb fields (`priority`, `mark`, `skb_iif`), socket ownership via `skb_to_full_sk`, route classid when `CONFIG_IP_ROUTE_CLASSID` is enabled, VLAN helpers, conntrack tuple access when `CONFIG_NF_CONNTRACK` is enabled, and flow/hash helpers (`jhash2`, random seed generation). It calls `tcf_block_netif_keep_dst` so destination metadata remains available for key extraction.

Risks: key extraction falls back to folded pointer-derived values for missing headers or ports, so classification may depend on kernel object addresses in those cases. Conntrack keys fall back to ordinary flow keys when no conntrack entry is present, which can change class distribution. Socket UID/GID keys are rejected outside `init_user_ns`; namespace handling changes could affect compatibility. Hash perturbation intentionally changes class mapping over time, which can reorder flows. Baseclass handling is strict for shared blocks; omitting it is an error. Timer, RCU, and action-extension lifetimes must remain synchronized on replacement and destroy.

Test signals: create flow filters in hash and map mode with representative keymasks for src/dst/proto/ports, mark, priority, VLAN, rxhash, and conntrack keys. Verify multi-key map mode is rejected, zero keymask is rejected, invalid key indexes are rejected, shared blocks require explicit baseclass, and socket UID/GID keys are rejected outside init user namespace. Test divisor, mask/xor/rshift/addend math, perturb timer behavior, ematch gating, action execution, dumps of every configured attribute, replacement preserving unspecified fields, and destroy/delete while traffic is active.
