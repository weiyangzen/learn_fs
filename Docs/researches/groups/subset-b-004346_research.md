# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_llh.c

Purpose: Implements the low-level hardware access layer for Atlantic NIC registers. Each exported helper converts a named hardware operation into `aq_hw_read_reg()`, `aq_hw_write_reg()`, `aq_hw_read_reg_bit()`, `aq_hw_write_reg_bit()`, or `aq_hw_read_reg64()` calls using the address, mask, and shift definitions from `hw_atl_llh_internal.h`.

Important APIs, types, and functions: The file exports register wrappers for temperature sensor control (`hw_atl_ts_*`), SMBus status/data (`hw_atl_smb0_*`), global CPU semaphores/scratchpads/reset (`hw_atl_reg_glb_cpu_sem_*`, `hw_atl_glb_soft_res_*`, `hw_atl_scrpad*`), DMA/stat counters, interrupt status/mapping/masking, RX descriptor DMA (`hw_atl_rdm_*`, `hw_atl_reg_rx_dma_*`), RX packet buffer and receive filters (`hw_atl_rpb_*`, `hw_atl_rpf*`), RX offload and LRO (`hw_atl_rpo_*`), TX descriptor DMA/offload/buffer/scheduler (`hw_atl_tdm_*`, `hw_atl_tpb_*`, `hw_atl_tpo_*`, `hw_atl_tps_*`), indirect MSM MAC/PHY register access, PCI reset-disable, PTP clock reads, L3/L4 filters, firmware semaphores, and MDIO interface registers. Indexed helpers such as `hw_atl_itr_irq_map_*()`, `hw_atl_rpf_rpb_user_priority_tc_map_set()`, and `hw_atl_rpo_lro_max_num_of_descriptors_set()` use static address/mask/shift tables where the hardware packs multiple queue or LRO fields into shared registers.

Control flow: There is almost no algorithmic flow; calls are direct register access transactions. Setters perform read-modify-write through `aq_hw_write_reg_bit()` when touching a bitfield, or full-register writes when the hardware field owns the whole register. Getters read either raw registers or masked bitfields. A few helpers loop across fixed word counts, notably IPv6 L3/L4 address clear/set helpers, which write four 32-bit source or destination words in reverse array order for IPv6 programming. `hw_atl_rdm_rx_dma_desc_cache_init_tgl()` is one of the few stateful operations in this file: it reads the descriptor cache init bitfield and writes the opposite value to toggle hardware initialization.

State and persistence behavior: The file itself has no durable software state. All persistent effects are hardware register effects on the Atlantic device: descriptor base/tail pointers, interrupt routing/masks, packet buffer thresholds, filter entries, offload enables, reset bits, semaphores, and firmware-visible scratch registers. Static lookup arrays inside functions are constant metadata. Ordering and synchronization are delegated to higher layers and the MMIO helpers; callers are responsible for programming sequences, polling, and lock context.

Dependencies and integration points: Includes `hw_atl_llh.h` for prototypes, `hw_atl_llh_internal.h` for register metadata, and `../aq_hw_utils.h` for MMIO helper primitives. It is the shared hardware primitive layer consumed by Atlantic generation-specific files, firmware utilities, filter setup, ring setup, interrupt setup, reset code, PTP logic, and diagnostics. `hw_atl_utils.c` depends on its global reset, semaphore, scratchpad, MAC/PHY, and statistic helpers.

Risks: The largest risk is register metadata drift. A wrong address, mask, shift, or indexed-table entry silently writes the wrong hardware bit, which can misroute interrupts, corrupt descriptor rings, disable offloads, or break reset/firmware handshakes. Indexed functions do not bounds-check queue/filter/LRO indices; callers must enforce the documented ranges. Read-modify-write helpers can race if multiple call sites touch different fields in the same register without serialization. Full-register writes, such as interrupt masks, RSS data, descriptor base/tail, and LRO enable words, require callers to preserve unrelated bits when needed. IPv6 address ordering is intentionally reversed relative to the input array and should be kept aligned with upper-layer filter encoding.

Test signals: Build coverage should catch prototype drift with `hw_atl_llh.h`. Hardware or emulation tests should cover reset, link bring-up, interrupt routing for RX/TX queues, descriptor ring enable/tail updates, RSS key/table programming, VLAN/L2/L3/L4 filter programming, checksum/LRO/LSO toggles, loopback modes, PTP clock reads, and MDIO/firmware semaphore paths. Register dump comparisons before and after programming are useful because this file is a thin mapping layer.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_llh.h

Purpose: Declares the low-level Atlantic register accessor API implemented by `hw_atl_llh.c`. It gives the rest of the driver named hardware operations instead of exposing raw MMIO addresses, masks, and shifts.

Important APIs, types, and functions: The header forward-declares `struct aq_hw_s` and declares accessors grouped by hardware block: temperature sensor, SMBus, global semaphores/reset/scratchpads, statistics, interrupts, RX descriptor manager, generic register programming, RX packet buffer, RX packet filter, RX packet offload/LRO, TX descriptor manager, TX header manager, TX packet buffer, TX packet offload, TX scheduler/rate limiting, MSM indirect register access, PCI reset control, PCS PTP clock read, firmware up-force interrupt, L3/L4 filter data programming, MDIO interface registers, and firmware semaphore getters.

Control flow: There is no executable control flow in this header. Its structure reflects the hardware block order used by `hw_atl_llh.c` and the generated register metadata in `hw_atl_llh_internal.h`. Callers include this header and invoke block-specific setters/getters as part of higher-level configuration sequences such as reset, ring setup, filter setup, link handling, interrupt setup, and PTP operations.

State and persistence behavior: The declarations imply operations on `struct aq_hw_s` and hardware MMIO state but carry no state themselves. Effects persist in device registers until reset, deinit, power transition, or later programming changes them. The `void *context` signatures for outer VLAN tag mode are looser than most functions and permit integration through generic callback contexts.

Dependencies and integration points: Includes `<linux/types.h>` and forward-declares `struct aq_hw_s`, keeping the API usable across Atlantic driver modules without pulling in the full hardware struct definition. It is the public local contract between generated-style low-level register accessors and higher-level Atlantic modules such as `hw_atl_utils.c`, generation-specific `hw_atl_b0.c`/`hw_atl_b0_internal.c`, PTP, filters, and MACSec/firmware support.

Risks: Prototype drift between this header and `hw_atl_llh.c` breaks builds or, worse, encourages duplicate raw register access elsewhere. The API does not encode valid index ranges for queues, descriptors, traffic classes, filters, LRO contexts, scratchpad numbers, or MDIO interfaces, so range validation must stay in callers. Some naming is historical and inconsistent (`*_addresslswset`, mixed casing, `context` vs `aq_hw`), which increases the chance of calling the wrong accessor when adding features. Because this header exposes very granular operations, higher-level code must still preserve programming order and register sharing rules.

Test signals: Compile coverage across the Atlantic driver is the primary signal. Functional signals include successful NIC probe/reset, queue allocation, interrupt moderation, RSS, VLAN/L2/L3/L4 filters, checksum/LRO/TSO offloads, traffic class scheduler programming, PTP clock reads, and firmware semaphore/MDIO paths using only these accessors instead of raw duplicated MMIO.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_llh_internal.h

Purpose: Provides the internal Atlantic register map used by `hw_atl_llh.c`. It defines MMIO addresses, bit masks, inverse masks, shifts, widths, defaults, and indexed address macros for hardware blocks in the Atlantic NIC.

Important APIs, types, and functions: This header is macro-only. Important families include temperature sensor registers (`HW_ATL_TS_*`), SMBus registers (`HW_ATL_SMB0_*`), global CPU semaphores and scratchpads (`HW_ATL_GLB_CPU_SEM_ADR`, `HW_ATL_GLB_CPU_SCRATCH_SCP_ADR`), DMA statistic counters, interrupt mask/status/map/throttle registers, RX descriptor manager fields, RX/TX DMA descriptor base/tail/status macros, RX packet buffer thresholds and flow-control fields, L2 multicast/unicast/broadcast filters, VLAN filters, ethertype filters, L3/L4 address and port filter registers, RX checksum/offload/LRO fields, TX descriptor manager/DCA/LSO fields, TX packet buffer and TX offload fields, TX packet scheduler/rate/traffic-class fields, MSM indirect MAC/PHY access registers, PCS PTP timestamp registers, global/reset/PCI reset-disable bits, MDIO operation fields, and firmware semaphore IDs (`HW_ATL_FW_SM_*`).

Control flow: There is no runtime flow. Macros are expanded by LLH accessors and utility code to produce MMIO operations. Parameterized address macros encode hardware strides and valid conceptual ranges, for example descriptors and queues `[0, 31]`, traffic classes `[0, 7]`, VLAN filters `[0, 15]`, L2 unicast filters `[0, 37]`, L3/L4 locations `[0, 7]`, and MDIO interfaces starting at one.

State and persistence behavior: The file describes hardware state but stores none. Defaults document reset expectations for many fields, while actual persistence is on the device across normal writes until a hardware reset or power state transition. Reset-disable and soft-reset fields in this header are especially important because they determine whether other register blocks retain state across reset sequences.

Dependencies and integration points: It is private to the Atlantic hardware abstraction layer and is included by `hw_atl_llh.c` and `hw_atl_utils.c`. The definitions are coupled to `aq_hw_utils` bitfield helper semantics: every `_MSK` and `_SHIFT` pair must match the helper's extraction/write convention. Higher-level modules indirectly depend on this register map through `hw_atl_llh.h` accessors, while diagnostics and firmware reset flows use a few macros directly.

Risks: This is a high-blast-radius generated register contract. Any typo in address, mask, inverted mask, shift, width, default, stride, or range comment can cause hard-to-debug hardware failures. Some duplicate or alias definitions exist for TX DCA/descriptor fields, which must stay semantically consistent. Several full-width masks have inverse masks of zero or, for source/destination address macros, comments that are not used by current helpers; future users should not infer write safety from comments alone. Range comments are not enforced by C macros. Register names with `DEFALT` typos and mixed uppercase/lowercase are harmless for current use but signal that automated generation artifacts should be handled carefully.

Test signals: Hardware register dump validation is the strongest signal: compare expected addresses and bitfields against vendor datasheets or known-good programming traces. Driver-level signals include successful initialization of descriptors, filters, offloads, interrupts, reset, PTP, MDIO, and firmware mailbox paths. Static checks can find duplicate macros, unused metadata, and inconsistent alias values. Any port to new silicon should verify all revision-sensitive definitions before reusing this map.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_utils.c

Purpose: Implements common Atlantic hardware utility logic above the raw register accessor layer. It handles firmware-version detection and operation selection, FLB/RBL soft reset sequences, firmware mailbox and RPC data transfers, MPI state/speed control, link status decoding, permanent MAC retrieval, chip-feature detection, statistics accumulation, register dump support, and firmware 1.x Wake-on-LAN power handling.

Important APIs, types, and functions: `hw_atl_utils_initfw()` initializes chip feature flags, reads firmware version, selects `aq_fw_1x_ops` or `aq_fw_2x_ops`, and invokes the selected firmware init method. `hw_atl_utils_soft_reset()` detects boot mode, handles firmware 1.x power-state workaround and firmware 4.x reset semaphores, then dispatches to `hw_atl_utils_soft_reset_flb()` or `hw_atl_utils_soft_reset_rbl()`. `hw_atl_utils_fw_downld_dwords()` reads firmware/MCP memory via the MIF path under the RAM semaphore. `hw_atl_write_fwcfg_dwords()` and `hw_atl_write_fwsettings_dwords()` upload configuration/settings through revision-specific B0/B1 mailbox flows. `hw_atl_utils_fw_rpc_call()` and `hw_atl_utils_fw_rpc_wait()` implement firmware RPC transaction ID and length handshaking. `hw_atl_utils_mpi_read_mbox()`, `hw_atl_utils_mpi_read_stats()`, `hw_atl_utils_mpi_set_state()`, `hw_atl_utils_mpi_get_link_status()`, `hw_atl_utils_get_mac_permanent()`, `hw_atl_utils_update_stats()`, and `hw_atl_utils_hw_get_regs()` are the main utility entry points. The file also defines the firmware 1.x ops table `aq_fw_1x_ops`.

Control flow: Firmware init reads `HW_ATL_MPI_FW_VERSION` and accepts 1.x, 2.x, 3.x, or 4.x ranges through `hw_atl_utils_ver_match()`, using 2.x ops for 2.x through 4.x. Reset first waits for either FLB/RBL startup evidence, records `self->rbl_enabled`, optionally forces firmware 1.x to `MPI_DEINIT`, optionally acquires reset semaphores for firmware 4.x, then executes a long sequence of direct register writes and polling loops. The FLB path kickstarts MAC/FW, resets SPI around possible interrupted bursts, performs global software reset, clears RX/TX reset-disable, releases the MAC/PHY MPI reset bit, and waits for firmware version to appear. The RBL path marks boot status with `0xDEAD`, triggers reset, waits for a replacement boot code, rejects flashless missing-FW status, and waits for firmware. Mailbox downloads poll the RAM semaphore, program MIF address/command, use revision-specific completion checks, read `HW_ATL_MIF_VAL`, and release the semaphore. Uploads use either B1 scratchpad/interrupt protocol or B0 MIF write command protocol. RPC wait loops until firmware transaction ID and length indicate completion, optionally reissues a call when firmware reports `len == 0xffff`, then downloads response data.

State and persistence behavior: The file mutates `struct aq_hw_s` fields including `chip_features`, `fw_ver_actual`, `aq_fw_ops`, `rbl_enabled`, `mbox_addr`, `rpc_addr`, `settings_addr` via mailbox data, `rpc_tid`, `rpc`, `aq_link_status`, `curr_stats`, `last_stats`, and hardware-visible MPI state/speed. It writes firmware control registers, scratchpads, semaphores, reset bits, MIF registers, and RPC control/state registers. Stats are accumulated in software as deltas from mailbox counters, with hardware DMA counters read directly every update. No disk persistence exists; state is reconstructed on probe/reset/open.

Dependencies and integration points: Includes `../aq_nic.h`, `../aq_hw_utils.h`, `hw_atl_utils.h`, `hw_atl_llh.h`, `hw_atl_llh_internal.h`, and `<linux/random.h>`. It depends on Linux polling macros (`readx_poll_timeout_atomic`), endian helpers (`__swab32`), `get_random_bytes()`, Ethernet address helpers, kernel error codes, `aq_hw_err_from_flags()`, chip-feature macros, the firmware ops ABI (`struct aq_fw_ops`), and the raw LLH accessors. It integrates with higher-level Atlantic probe/reset/link/stat/power code through the firmware ops table and utility prototypes in `hw_atl_utils.h`.

Risks: Reset sequencing is hardware- and firmware-revision-sensitive; reordering writes or changing delays/poll timeouts can leave the MAC, SPI, PHY, or firmware processor wedged. RAM semaphore handling is fragile: the download path forcibly writes the semaphore if polling fails, and both upload/download must release it correctly. The B1 mailbox protocol relies on scratchpad top bits changing away from the selected area after forcing a uP interrupt. RPC transaction length and TID validation prevent oversized copies into `self->rpc`; changes must preserve those bounds. `hw_atl_utils_update_stats()` suppresses mailbox delta accumulation if any counter appears to regress while link is up, so corrupted mailbox reads can freeze software counter deltas until the next clean baseline. Permanent MAC fallback synthesizes an address from random/UCP data when efuse data is invalid; this avoids multicast/zero addresses but may not be stable across all failure modes. Some declarations in `hw_atl_utils.h` (`hw_atl_utils_mpi_set`, `hw_atl_utils_hw_set_power`, `hw_atl_utils_hw_deinit`, `hw_atl_utils_fw_set_wol`) are not implemented in this file, so their definitions must come from other Atlantic firmware modules or be legacy prototypes.

Test signals: Exercise probe/init across firmware 1.x, 2.x, 3.x, and 4.x devices; both FLB and RBL reset paths; firmware 4.x reset semaphore timeouts; link speed transitions for 100M/1G/2.5G/5G/10G; mailbox read/write under B0 and B1 revisions; RPC request/response including oversized-length rejection; WoL magic enable/disable through firmware 1.x power path; stats update under traffic and after link down/up; efuse MAC read failure fallback; and register dump count/address consistency. Fault injection around MIF command timeout, scratchpad timeout, semaphore acquisition, and firmware version absence is particularly valuable.

# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_utils.h

Purpose: Defines the Atlantic hardware utility ABI: packed hardware descriptors, firmware mailbox/RPC payload layouts, firmware capability/control enums, filter request structs, MPI state/rate constants, and prototypes for common hardware utility functions.

Important APIs, types, and functions: Descriptor types include `hw_atl_txd_s`, `hw_atl_txc_s`, `hw_atl_rxd_s`, `hw_atl_rxd_wb_s`, and `hw_atl_rxd_hwts_wb_s`. Firmware/management data types include `hw_atl_stats_s`, `hw_atl_utils_mbox_header`, `hw_atl_info`, `hw_atl_utils_mbox`, WoL message structs, `offload_info` substructures, `hw_atl_utils_fw_rpc`, PTP request structs, `hw_fw_request_iface`, `hw_atl_utils_settings`, SMBus/MACSec request structs, and filter descriptors (`aq_rx_filter_vlan`, `aq_rx_filter_l2`, `aq_rx_filter_l3l4`). Enumerations and masks describe GPIO pin functions, RX actions, L3/L4 protocol/control bits, MPI states, legacy rates, firmware 2.x rates, low/high capability bits, control bits, and extended capabilities. Function prototypes cover firmware init/reset, mailbox/stats, MPI link/status, permanent MAC lookup, register dumps, power/deinit, firmware memory download/upload, WoL/RPC, version matching, and exported `aq_fw_1x_ops`/`aq_fw_2x_ops`.

Control flow: This header has no executable flow. It defines the shared binary layouts and constants that `hw_atl_utils.c`, generation-specific firmware code, and higher-level Atlantic modules use to exchange data with firmware and to interpret mailbox capabilities/status. The `HW_ATL_FLUSH()` macro performs a read from register `0x10` through the ambient `self` pointer to flush posted writes where used by callers.

State and persistence behavior: Packed structures model DMA descriptors, descriptor writebacks, mailbox memory, firmware RPC/config payloads, settings, and filters. These layouts are written to or read from device memory/register-backed firmware regions and therefore function as firmware/hardware ABIs. The header does not own state, but field order, width, packing, and enum bit positions are persistent compatibility contracts with Atlantic firmware and silicon.

Dependencies and integration points: Relies on kernel types and constants supplied by including contexts, including `u8/u16/u32/u64`, `__le16`, `ETH_ALEN`, `BIT()`, and networking structures declared elsewhere. It forward-declares `struct aq_hw_s`, `struct aq_fw_ops`, `struct aq_hw_caps_s`, and `struct aq_hw_link_status_s`. It is included by `hw_atl_utils.c` and many Atlantic hardware/firmware modules, and forms the bridge between firmware ops implementations, ethtool/stat paths, Wake-on-LAN, PTP, MACSec, SMBus, filters, and descriptor ring code.

Risks: Because many structs are `__packed` firmware or hardware ABIs, changing field order, size, alignment, signedness, or enum bit positions can break firmware communication or descriptor interpretation. Several unions intentionally overlay firmware 1.x and 2.x payloads, so message ID and size calculation must match the active firmware protocol. Capability bits are positional enums, not arbitrary values; using them without `BIT()` where required would be wrong. `HW_ATL_FLUSH()` depends on an in-scope variable named `self`, which is convenient but brittle. Some prototypes are implemented outside `hw_atl_utils.c`, so consumers must keep linkage with the rest of the Atlantic firmware modules.

Test signals: Compile with structure users across the Atlantic driver, validate descriptor sizes and writeback parsing on RX/TX traffic, verify mailbox and RPC sizes against firmware expectations, check capability/control bit decoding for firmware 2.x/3.x/4.x, exercise WoL/offload/PTP/MACSec/SMBus message paths where supported, and test VLAN/L2/L3/L4 filter programming from these structs into LLH accessors. ABI-size assertions would be useful for packed descriptors and firmware payloads if added.
