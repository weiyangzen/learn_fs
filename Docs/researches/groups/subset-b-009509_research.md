## sources/test-tools/syzkaller/sys/linux/init_alg_test.go

Purpose: Linux-only AF_ALG validation tests for the static crypto algorithm catalog defined by `init_alg.go`. Most tests are opt-in manual probes against the running kernel's `AF_ALG` socket implementation, while `TestAlgDups` always checks catalog duplicate descriptors in normal `go test` runs.

Important APIs/types/functions: `flagRunAlgTests`, `algTest`, `TestAlgDescriptions`, `TestSingleAlg`, `TestTemplateAlg1`, `TestTemplateAlg2`, `sockaddrAlg`, `testAlg`, and `TestAlgDups`. The tests consume `allTypes`, `allAlgs`, and `algDesc` from `init_alg.go`; they use `syscall.Socket`, raw `SYS_BIND`, and `unsafe.Sizeof` to form and bind a Linux `sockaddr_alg`.

Control flow: `algTest` skips unless `-algtests` is supplied, then marks the test parallel. `TestAlgDescriptions` walks algorithms by type, detects duplicate names within each type, records descriptor entries with arguments as templates, and verifies concrete names such as `foo(bar)` have a standalone `foo` template entry unless they are internal `__` names. `TestSingleAlg` binds every non-template algorithm name for every declared type. `TestTemplateAlg1` samples up to ten concrete algorithms from every source type, builds `template(arg)` names, and expects successful binds to match exactly the one argument type claimed by the descriptor. `TestTemplateAlg2` precomputes sampled concrete pairs for every type pair, builds `template(arg1,arg2)` names, and logs combinations that bind successfully. `testAlg` constructs the C-compatible address structure, rejects too-long type/name strings as skips, opens an `AF_ALG` sequenced-packet socket, and binds it to report kernel acceptance.

State and persistence: no persistent state is written. The only global state is the `-algtests` flag and the static algorithm catalog imported from `init_alg.go`. Tests allocate local maps and random selections; the random source is the package-level `math/rand` default, so sampled template coverage is intentionally nondeterministic across runs unless the process seed is controlled.

Dependencies and integration points: integrates tightly with Linux kernel crypto availability, CPU instruction support, and architecture-dependent algorithm names. It validates the syzkaller AF_ALG generator catalog used by Linux target special types. The test file is guarded by `//go:build linux`, so non-Linux hosts do not compile or run it. The raw syscall layout must match Linux `sockaddr_alg`, including `typ[14]` and `name[64]` fixed-size fields.

Risks: the opt-in tests are environment-sensitive and the comments explicitly state that they generally do not pass without a fresh kernel, broad crypto configuration, and modern SIMD hardware. `TestAlgDescriptions` builds an `allall` map but does not read it, so it does not actually enforce cross-type global uniqueness despite the comment wording. `TestTemplateAlg2` is mostly diagnostic because it logs successful pairs but does not fail when a two-argument template cannot be matched. Random sampling can miss valid or invalid combinations. Raw `unsafe` binding is intentionally low-level and will fail hard if socket creation itself is unavailable.

Test signals: default test runs get the reliable `TestAlgDups` duplicate descriptor check. Manual `go test -tags linux ./sys/linux -algtests` style runs provide live kernel smoke coverage for AF_ALG names, template metadata, string-size limits, and socket bind compatibility, but failures need to be interpreted as possible kernel/config/hardware drift rather than purely syzkaller regressions.

## sources/test-tools/syzkaller/sys/linux/init_iptables.go

Purpose: Linux special generators and neutralization support for iptables, ip6tables, arptables, and ebtables replacement structures. The code repairs generated or mutated netfilter table arguments so hook offsets, underflow offsets, jump targets, entry counts, physical hook addresses, and setsockopt lengths are internally consistent enough for kernel netfilter parsers.

Important APIs/types/functions: `arch.generateIptables`, `arch.generateArptables`, `arch.generateNetfilterTable`, `arch.generateEbtables`, and `arch.neutralizeEbtables`. These functions operate on `prog.Gen`, `prog.Type`, `prog.Dir`, `prog.Arg`, `prog.Call`, `prog.GroupArg`, `prog.UnionArg`, `prog.PointerArg`, `prog.ConstArg`, `prog.ConstType`, and `prog.FlagsType`; they also use `prog.CloneArg`, `Gen.GenerateSpecialArg`, `Gen.MutateArg`, `Target.ArgContainsAny`, `Target.PhysicalAddr`, and `prog.ForeachSubArg`.

Control flow: iptables and arptables are thin wrappers over `generateNetfilterTable`, differing by union wrapping and hook count. `generateNetfilterTable` generates a fresh special argument or clones and mutates the old one, unwraps the table, checks the expected field count, computes byte offsets for every entry, randomly assigns used hook offsets to entry offsets or rarely to the underflow position, sets all used underflow fields to the end position, then walks nested args to rewrite standard target jump offsets while preserving negative verdict constants recognized by the target flags type. `generateEbtables` similarly generates or mutates, bails out on ANY-containing args, accounts for 32-bit versus 64-bit struct padding, computes per-chain offsets and total entry counts, stores the total into the table, and assigns valid hook pointers to physical addresses of the generated entries. `neutralizeEbtables` runs on a finished `setsockopt` call and rewrites its length argument to `sizeof(ebt_replace)+entries size` when the table and entries pointers are present.

State and persistence: all state is in-memory mutation of `prog.Arg` graphs and call arguments. No files, kernel state, or global caches are written. The code does alter cloned old arguments during mutation, including hook offsets and target jump offsets, and returns any support calls produced by special generation or argument mutation.

Dependencies and integration points: registered by `init.go` as special generators for `ipt_replace`, `ip6t_replace`, `arpt_replace`, and `ebt_replace`; `neutralizeEbtables` is invoked by Linux target neutralization for `setsockopt$EBT_SO_SET_ENTRIES`. The logic depends on syzlang struct field order, union shape, pointer-size-specific padding, netfilter sentinel values, target physical address calculation, and standard target type names beginning with `xt_target_t["", `. It also relies on `slices.Contains` to distinguish negative verdict flags from jump offsets that should be rewritten.

Risks: this code is highly shape-dependent: a syzlang layout change can panic through failed type assertions, wrong field counts, or field order assumptions. `genOffset` assumes at least one table entry; empty entry arrays would make `Intn(len(offsets))` invalid unless the generated descriptions prevent that. The wrappers intentionally discard old hook order after mutation, which may reduce mutation locality. Ebtables target jump offsets remain a TODO, so generated ebtables programs can still have internally inconsistent target jumps. Physical address assignment depends on pointer resources being present; nil entry pointers cause early returns and less repaired output.

Test signals: indirect coverage comes from Linux target generation, mutation, deserialization, serialization, and neutralization tests, especially `init_test.go` for neutralization plumbing and broader `prog` generation tests for special type validity. There is no direct focused test in this file, so regressions in field layout assumptions may surface as panics during generation or as kernel-side netfilter rejects rather than as clear unit failures.

## sources/test-tools/syzkaller/sys/linux/init_test.go

Purpose: black-box tests for Linux target neutralization and unsafe deserialization modes. The file verifies that deserializing Linux programs through syzkaller's target layer rewrites dangerous, invalid, or nondeterministic syscall arguments into safer forms while preserving raw programs when `StrictUnsafe` is explicitly requested.

Important APIs/types/functions: `TestNeutralize`, `TestDeserializeStrictUnsafe`, and `TestDeserializeNonStrictUnsafe`. The tests use `prog.TestDeserializeHelper`, `prog.DeserializeTest`, `prog.GetTarget`, `Target.Deserialize`, `Prog.Serialize`, `prog.StrictUnsafe`, `prog.NonStrictUnsafe`, `targets.Linux`, and `targets.AMD64`; the blank import of `github.com/google/syzkaller/sys` ensures generated targets are registered.

Control flow: `TestNeutralize` feeds a table of serialized Linux programs into `TestDeserializeHelper` for linux/amd64. Each case either expects unchanged output or an exact rewritten serialization, including syslog command clamping, ptrace request neutralization, arch_prctl request fixup, ioctl command masking, fanotify flag cleanup, invalid Bluetooth init socket domain repair, mmap flag enforcement, mremap flag expansion, unsafe mknod mode replacement, exit status normalization, tty device open normalization, and sched_setattr structure cleanup or pointer replacement. One sched_setattr case also asserts a strict deserialization error while documenting the sanitized output. `TestDeserializeStrictUnsafe` deserializes a raw program with a global filename, non-fixed `mmap`, and disabled `clone`, then requires serialization to be byte-for-byte unchanged. `TestDeserializeNonStrictUnsafe` confirms permissive non-strict unsafe mode accepts even an incomplete `clone()` form.

State and persistence: no persistent state. The tests create in-memory targets and programs and compare serialized text. They exercise target initialization hooks, neutralizers, call-specific sanitizers, and serializer behavior, but do not execute programs against the kernel.

Dependencies and integration points: depends on generated Linux syscall descriptions, Linux `InitTarget` registration, Unix neutralization from `targets`, and specific neutralizer implementations in `init.go` and `init_iptables.go`. Expected strings are coupled to current linux/amd64 type layouts, syscall variants, default argument values, and serializer formatting. The unsafe-mode tests integrate with the deserializer's strictness policy and target registry.

Risks: exact-output tests can become noisy when syzlang descriptions, default values, or serializer formatting change even if behavior remains acceptable. The table is broad but not exhaustive: it covers representative dangerous cases rather than every neutralizer branch. It is linux/amd64-specific, so architecture-specific neutralizer gaps may need separate tests. Because programs are only deserialized and serialized, the tests do not prove the rewritten calls are accepted by the kernel, only that syzkaller's sanitization contract fires.

Test signals: strong regression signal for host-safety rewrites in Linux target initialization. It directly guards high-risk neutralization around syslog, ptrace, arch_prctl, ioctl, fanotify, networking pseudo-syscalls, mmap/mremap, device nodes, exits, tty opening, and sched_setattr. The unsafe-mode tests guard an important integration contract: raw modes must allow preserving otherwise unsafe corpus or repro programs when the caller requested that behavior.

## sources/test-tools/syzkaller/sys/linux/init_vusb.go

Purpose: Linux virtual USB special generation for device descriptors, printer descriptors, audio descriptors, and HID descriptors. It patches generated descriptor trees with USB/HID IDs from auto-extracted driver match tables and hand-maintained quirk IDs so syzkaller can trigger realistic kernel driver binding paths instead of producing only syntactically valid but rarely matched descriptors.

Important APIs/types/functions: USB match constants `USB_DEVICE_ID_MATCH_*`, `BytesPerUsbID`, `BytesPerHidID`, `UsbDeviceID`, `HidDeviceID`, `arch.generateUsbDeviceDescriptor`, `arch.generateUsbPrinterDeviceDescriptor`, `audioQuirksIDs`, `arch.generateAudioDeviceDescriptor`, `patchUsbDeviceID`, `randUsbDeviceID`, `arch.generateUsbHidDeviceDescriptor`, and `patchGroupArg`. The code consumes generated data tables `usbIds`, `usbIdsAll`, `hidIds`, and `hidIdsAll` from `init_vusb_ids.go`, and mutates `prog.GroupArg`/`prog.ConstArg` descriptor trees.

Control flow: each generator first creates a fresh special arg or clones and mutates the old arg, then returns early if the target still contains ANY data. Generic USB generation always calls `patchUsbDeviceID` with `usbIdsAll` and `patchNonMatching=true`, which fills both matched and otherwise-randomized descriptor fields. Printer generation randomly chooses among leaving syzlang defaults intact, injecting hardcoded `usblp` quirk vendor/product pairs, or applying auto-extracted `usblp` match IDs without patching non-matching fields. Audio generation follows the same pattern but uses a large `audioQuirksIDs` table or concatenated IDs for selected USB audio drivers. `patchUsbDeviceID` picks an ID record, patches top-level device fields according to match flags or `patchNonMatching`, descends through the generated descriptor hierarchy to the first configuration's interfaces, and patches interface class/subclass/protocol/number; interfaces after the first receive freshly sampled IDs. `randUsbDeviceID` decodes one fixed-width little-endian record and, when requested, fills fields not covered by match flags with random values/ranges. HID generation decodes a fixed-width HID record and patches only device vendor/product. `patchGroupArg` verifies the expected struct field name before writing the const value.

State and persistence: all state is local in-memory mutation of generated `prog.Arg` structures. The static `audioQuirksIDs` list is package-level read-only data. Random choices come from `prog.Gen.Rand()`, so descriptor patching participates in syzkaller's deterministic seeded generation/mutation model. No persistent files or kernel state are changed.

Dependencies and integration points: registered by `init.go` for Linux special types such as `usb_device_descriptor`, `usb_device_descriptor_printer`, and `usb_device_descriptor_hid`; audio descriptor registration is also part of Linux target initialization. The file depends on exact syzlang struct nesting and field order for USB descriptors: top-level device fields at indices 3-9 and descriptor/config/interface paths through indices 14 and 9. It depends on fixed binary record widths matching Go struct layout expectations, little-endian decoding, and non-empty ID strings from generated tables. It integrates with kernel USB driver matching behavior by respecting match flags when `patchNonMatching` is false.

Risks: field-index assumptions are fragile; `patchGroupArg` catches wrong field names, but nested path type assertions can still panic if descriptor layouts change. `randUsbDeviceID` divides by fixed record sizes and calls `Intn(totalIds)`, so empty or malformed ID strings would panic. The `bcdDevice` random range assumes `BcdDeviceHi >= BcdDeviceLo`. Quirk lists can drift from kernel sources, and auto-extracted IDs may omit hardcoded driver quirks, which is why this file carries manual printer and audio tables. When non-matching fields are randomized, descriptors may bind unexpected drivers or explore invalid combinations, which is useful for fuzzing but can reduce reproducibility of driver-specific coverage.

Test signals: indirect signals come from Linux target generation, mutation, serialization, `TestSpecialStructs`, and any tests that instantiate Linux special types. There is no direct unit test for USB descriptor patching, so the most important regression signals are panics from struct-shape mismatches, ANY early returns reducing patch coverage, generated descriptor acceptance in executor-based fuzzing, and coverage changes in USB, printer, audio, and HID driver binding.
