# sources/distributed-fs/ceph-client/drivers/power/supply/qcom_smbb.c

Purpose: implements the Qualcomm PM8226/PM8941 SMBB charger and OTG boost integration for a single-cell Li-ion battery. It exposes three power supplies, `smbb-bif` battery, `smbb-usbin` USB input, and optional `smbb-dcin` mains input, plus an `otg-vbus` regulator and USB extcon state.

Important APIs, types, and functions: `struct smbb_charger` holds regmap/base address, cached DT/programmed charger attributes, status bits, power supplies, extcon, and regulator descriptors. `enum smbb_attr` plus `smbb_charger_attrs[]` define writable hardware settings such as fast-charge current/voltage, USB/DC input current, weak-battery voltage, recharge threshold, and minimum input voltage. `smbb_charger_attr_parse()`, `smbb_charger_attr_write()`, and `smbb_charger_attr_read()` bridge DT properties and power-supply writes into register encodings. IRQ handlers update `STATUS_*` bits from named charger IRQs and call `power_supply_changed()`. `smbb_chg_otg_*()` maps the boost enable bit to regulator operations.

Control flow: probe allocates state, obtains the parent PMIC regmap and child `reg` base, validates hardware revision, parses DT booleans such as `qcom,disable-dc` and `qcom,jeita-extended-temp-range`, applies or reads all charger attributes, registers the battery and input power supplies, registers USB extcon, requests all named IRQs after first invoking each handler to seed status, registers the OTG regulator, applies JEITA comparator range, then runs a fixed hardware setup sequence that disables timers/watchdog, selects charger EOC, configures buck behavior, stops USB enumeration timer, and enables charging. Remove disables charger control.

State and persistence behavior: runtime status is cached in `status` under `statlock`; hardware configuration lives in PMIC registers and cached `attr[]` values. DT-sourced current/voltage settings are applied at probe and later user writes update hardware immediately through power-supply properties. No persistent storage is managed; values survive only as long as PMIC register state does.

Dependencies and integration points: depends on the SPMI/MFD parent exposing a regmap, OF child nodes with named IRQ resources, `power_supply`, `extcon-provider`, and regulator core. It supplies battery consumers through `supplied_to = "smbb-bif"` and exposes USB attach state with `EXTCON_USB`.

Risks: register encoding has clamp and rounding behavior that userspace may not expect. The checked-out source contains duplicated lines in `ATTR_BAT_VMAX`, `smbb_usbin_set_property()`, and `smbb_chg_otg_is_enabled()`, which are compile-quality signals to review before building this tree. Status bit updates are IRQ-line-level based, so missing/incorrect named IRQs can make power-supply state stale. `smbb_bat_temp_handler()` clears `STATUS_BAT_OK` but only sets `STATUS_BAT_HOT` when hot; cold state is inferred, not separately tracked. Test signals include DT property boundary tests, boot with DC disabled/enabled, IRQ-driven USB/DC/battery transitions, extcon state updates, writable current/voltage property round trips, OTG regulator enable/disable, and remove-time charger disable.

# sources/distributed-fs/ceph-client/drivers/power/supply/qcom_smbx.c

Purpose: implements a Qualcomm PMI8998/PM660 SMB2-style USB charger power-supply driver. It reports charger online state, USB charger type, charge status, health, current limit, and IIO-backed USB input current/voltage, while programming conservative charger defaults and automatic input current limit behavior.

Important APIs, types, and functions: `struct smb_chip` stores the device, register base, parent regmap, battery info, delayed work, wake IRQ, IIO channels, and charger power supply. `smb_init_seq[]` is the central initialization table for Type-C/APSD/AICL/watchdog/precharge/fast-charge registers. `smb_get_prop_usb_online()`, `smb_apsd_get_charger_type()`, `smb_get_prop_status()`, `smb_get_prop_health()`, `smb_get_current_limit()`, and `smb_set_current_limit()` implement the power-supply property surface. IRQ handlers cover battery overvoltage, USB plug, USB input-current-limit changes, and watchdog bark.

Control flow: probe allocates state, gets the parent regmap and child `reg` base, obtains `usbin_v` and `usbin_i` IIO channels, applies `smb_init_hw()`, clones and renames the power-supply descriptor based on match data, registers the USB power supply, reads battery info, initializes delayed charger-type work, programs float voltage from battery design max, requests named IRQs, enables wakeup on the USB plug IRQ, stores driver data, and schedules immediate status work. USB plug work polls APSD up to three times, reruns APSD on timeout, maps SDP/CDP/DCP to 500 mA or 1.5 A, updates the input current limit, and notifies userspace.

State and persistence behavior: the driver keeps little cached state beyond battery info and work scheduling; most state is live PMIC register state. User writes to `CURRENT_MAX` program `USBIN_CURRENT_LIMIT_CFG`; writes to `STATUS` set or clear USB suspend. Probe-time float-voltage and current-limit defaults write hardware but are not persisted outside the PMIC.

Dependencies and integration points: depends on a parent Qualcomm PMIC regmap, OF compatibles `qcom,pmi8998-charger` and `qcom,pm660-charger`, named IRQs, `power_supply`, `iio/consumer`, wake IRQ helpers, and delayed work. It integrates with battery DT data through `power_supply_get_battery_info()` and with analog telemetry through IIO channels.

Risks: health decoding switches on the full status register value rather than masked bits, so combined error/temperature flags can fall through to GOOD. `smb_handle_wdog_bark()` writes `BARK_BITE_WDOG_PET` without adding `chip->base`, unlike most other register accesses. `smb_set_property(STATUS)` writes `!val->intval` into a bitmask field; non-boolean status values from userspace need careful interpretation. The checked-out source has duplicated lines in the Type-C define block, status default branch, and init table. Test signals include build coverage, IIO missing/deferred behavior, APSD retry/rerun behavior, charger-type current limit updates, watchdog-bark petting on real hardware, suspend/wake through USB plug IRQ, and battery-info-derived float voltage programming.

# sources/distributed-fs/ceph-client/drivers/power/supply/rk817_charger.c

Purpose: implements the Rockchip RK817 PMIC charger and fuel-gauge driver. It registers separate `rk817-battery` and `rk817-charger` power supplies, initializes charger limits from battery metadata, periodically samples fuel-gauge registers, calibrates ADC/current/coulomb-counter values, and stores BSP-compatible state-of-charge/full-capacity values in PMIC NVRAM registers.

Important APIs, types, and functions: `struct rk817_charger` is the main state object, including battery/charger power supplies, plug and battery-present state, voltage calibration coefficients, SOC and full-charge capacity, immutable DT/battery-info parameters, sampled readings, and delayed work. Conversion macros translate ADC counts to current or charge. `rk817_bat_calib_vol()`, `rk817_bat_calib_cur()`, `rk817_bat_calib_cap()`, `rk817_read_props()`, `rk817_read_or_set_full_charge_on_boot()`, and `rk817_battery_init()` own fuel-gauge calibration and initialization. `rk817_bat_get_prop()` and `rk817_chg_get_prop()` expose battery and charger properties; plug IRQs update online state.

Control flow: probe locates the `charger` child node under the parent RK808/RK817 node, allocates state, reads sense resistor and sleep-current DT properties, registers battery and charger power supplies, obtains required battery information and OCV table data, initializes charger/fuel-gauge hardware, requests plug-in and plug-out IRQs, initializes delayed work, and forces an immediate property read. The periodic monitor runs every eight seconds, reading charge, voltage, current, charge status, present state, and USB input voltage, then performing capacity calibration. Suspend cancels the work item; resume restarts it immediately.

State and persistence behavior: this driver is unusually stateful. It writes SOC, remaining capacity, and full charge capacity to PMIC NVRAM-compatible locations to interoperate with BSP kernels and boot firmware. It initializes the coulomb counter from first-boot OCV or saved NVRAM values, corrects drift when fully charged, and allows userspace to write `CHARGE_FULL`, updating `fcc_mah` and recalibrating. Runtime sampled values live in `struct rk817_charger` and are refreshed periodically and on plug IRQs.

Dependencies and integration points: depends on the RK808 MFD/regmap definitions, OF battery/charger child data, `power_supply_get_battery_info()`, OCV-to-capacity tables, platform IRQs, delayed work helpers, and PM sleep ops. The charger input is reported as USB type DCP, reflecting the tested hardware assumptions.

Risks: many regmap reads/writes in calibration paths ignore return values, so hardware I/O failures can propagate stale or zeroed state. Capacity math mixes mAh, uAh, ADC counts, and thousandths-of-percent SOC, making overflow and unit regressions likely. The checked-out file has duplicated text/lines in comments and a few statements, including one duplicated write argument and a duplicated `dev_emerg()` argument line, so build and lint gates matter. The driver assumes 10 mOhm or 20 mOhm sense resistor handling by reducing it to divisor 1 or 2, without rejecting other values. Test signals include first-boot versus saved-NVRAM boot, OCV table behavior, full-charge drift correction, plug/unplug IRQ reprogramming of input limits, suspend/resume work cancellation, invalid battery-info rejection, `CHARGE_FULL` writes, and long-run SOC stability.

# sources/distributed-fs/ceph-client/drivers/power/supply/rn5t618_power.c

Purpose: implements power-supply support for Ricoh RN5T618/RC5T619 PMIC family battery, USB input, and adapter input. It reports fuel-gauge telemetry, charger status, current limits, USB charger type on RC5T619, and input voltages from IIO channels.

Important APIs, types, and functions: `struct rn5t618_power_info` stores the parent MFD state, registered battery/USB/ADP power supplies, IIO channels, and charger IRQ. `rn5t618_battery_read_doublereg()` performs stable two-byte reads by retrying until consecutive samples match. Battery helpers decode status, presence, voltage, signed current, capacity, temperature, time-to-empty/full, charge-full, and charge-now. `rn5t618_battery_set_current_limit()`, `rn5t618_adp_set_property()`, and `rn5t618_usb_set_property()` program charge/input current limit registers. `rn5t618_charger_irq()` clears interrupt request registers and notifies all supplies.

Control flow: probe allocates state, binds the parent MFD data, gets `vusb` and `vadp` IIO channels, enables the fuel gauge if the parent control register indicates it is off, registers battery/adapter/USB power supplies, maps the MFD regmap IRQ to a virtual IRQ when available, and requests a threaded charger IRQ. Property reads are live register or IIO reads; property writes validate current ranges and write the corresponding limit register.

State and persistence behavior: runtime state is minimal and mostly stored in the PMIC. Enabling `FG_ENABLE` changes hardware state and may begin fuel-gauge recalibration after vendor firmware disabled it. Current-limit writes persist as PMIC register state. No driver-owned nonvolatile state is maintained.

Dependencies and integration points: depends on the RN5T618 MFD core and register definitions, regmap, optional regmap IRQ data, IIO channels named `vusb` and `vadp`, and `power_supply`. RC5T619-specific USB type detection is gated on the parent variant.

Risks: the checked-out source contains duplicated function signature lines for `rn5t618_battery_temp()` and `rc5t619_usb_get_type()`, which would be immediate compile risks in this tree. The battery charge-control setter rejects values greater than or equal to `CHG_MAX_CUR`, making the nominal 1.8 A max unreachable. IIO channel acquisition treats `-ENODEV` as probe defer but returns other errors directly, so missing optional voltage channels are not tolerated. Interrupt clear writes use zero values; tests should confirm this matches the PMIC's clear semantics. Test signals include stable double-register reads, signed current and temperature scaling, RC5T619 USB type decoding, current-limit boundary values for battery/ADP/USB, fuel-gauge-enable boot path, IRQ notification of all supplies, and probe behavior with missing IIO or IRQ resources.

# sources/distributed-fs/ceph-client/drivers/power/supply/rt5033_battery.c

Purpose: implements a small Richtek RT5033 fuel-gauge driver. It registers an I2C battery power supply that reports voltage, average voltage, open-circuit voltage, battery presence, capacity, and status.

Important APIs, types, and functions: `struct rt5033_battery` stores the I2C client, fuel-gauge regmap, and registered power supply. `rt5033_battery_get_watt_prop()` selects high/low fuel-gauge voltage registers and converts 12-bit values to microvolts. `rt5033_battery_get_capacity()` reads SOC high byte as percentage-like capacity. `rt5033_battery_get_present()` checks the fuel-gauge config battery-present bit. `rt5033_battery_get_status()` obtains charging status from a supplier power supply rather than local fuel-gauge state.

Control flow: probe checks SMBus byte functionality, allocates state, creates an 8-bit regmap over the I2C fuel gauge address, stores client data, and registers `rt5033-battery` with fwnode and driver data. All property reads are synchronous regmap reads or supplier property lookups.

State and persistence behavior: the driver maintains no persistent state and no periodic cache. It is a read-only power supply surface over hardware fuel-gauge registers. Status is dynamically inherited from the charger supplier when available; otherwise UNKNOWN is returned.

Dependencies and integration points: depends on I2C, regmap, RT5033 private register definitions, and the power-supply supplier mechanism. It binds by I2C ID `rt5033-battery` or OF compatible `richtek,rt5033-battery`.

Risks: most `regmap_read()` return values are ignored, so failed reads can leave uninitialized local values. Capacity uses only the SOC high byte and ignores any fractional low byte. Supplier status lookup can report UNKNOWN if the charger supply is absent or not linked in DT. Test signals include I2C functionality rejection, regmap init failure, supplier status linkage, voltage conversion against known register samples, present-bit polarity, and behavior when reads fail.

# sources/distributed-fs/ceph-client/drivers/power/supply/rt5033_charger.c

Purpose: implements the Richtek RT5033 charger block as a USB power supply with optional extcon-driven mode switching. It initializes precharge, fast-charge, constant-voltage, and end-of-charge limits from battery information, reports charger state, and switches between charging, SDP/MIVR, OTG boost, and disconnected modes based on connector events.

Important APIs, types, and functions: `struct rt5033_charger` holds regmap, power supply, parsed charger limits, extcon state, notifier/work item, lock, online/OTG/MIVR flags, and cached constant-voltage register value. `rt5033_charger_dt_init()` reads battery info; `rt5033_init_pre_charge()`, `rt5033_init_fast_charge()`, `rt5033_init_const_charge()`, and `rt5033_charger_reg_init()` program charger registers. `rt5033_charger_set_otg()`, `rt5033_charger_unset_otg()`, `rt5033_charger_set_charging()`, `rt5033_charger_set_mivr()`, and `rt5033_charger_set_disconnect()` manage connector-dependent modes. `rt5033_charger_extcon_work()` serializes extcon state into hardware behavior.

Control flow: probe allocates and initializes state, obtains the parent RT5033 regmap, registers the power supply, reads battery information, initializes charging registers, then optionally finds a USB connector extcon parent. If extcon is present, it initializes autocancel work and registers a notifier for all extcon events. The work item scans extcon states, waits 100 ms for chip readiness, selects SDP/MIVR, charging, OTG, or disconnect behavior, and notifies the power supply.

State and persistence behavior: `online`, `otg`, and `mivr_enabled` are in-memory mirrors of connector mode; hardware registers hold actual operation mode, MIVR, charge limits, and CV. `cv_regval` is cached so OTG boost voltage can temporarily repurpose the CV bits and later restore the charge voltage. The driver has no nonvolatile storage.

Dependencies and integration points: depends on the RT5033 MFD/regmap, battery-info properties, `power_supply`, extcon, device tree phandle `richtek,usb-connector`, workqueue helpers, and mutex protection around mode transitions. It binds as platform device `rt5033-charger` or OF compatible `richtek,rt5033-charger`.

Risks: nested locking is risky: `rt5033_charger_set_charging()` holds `lock` and calls `rt5033_charger_unset_otg()`, which writes registers without taking the lock, while other paths call unset under the lock; behavior is intentional but fragile. `rt5033_charger_set_mivr()` calls `rt5033_charger_set_charging()` after releasing the lock, creating a small interleaving window. Extcon scanning assumes numeric connector order from `EXTCON_USB_HOST` through `EXTCON_CHG_USB_PD`. The checked-out source has duplicated lines in the precharge range check and charge-type getter. Test signals include battery-info boundary validation, CV restore after OTG, extcon transitions across SDP/DCP/host/disconnect, MIVR enable/disable, no-extcon probe path, and power-supply property reads after each mode.

# sources/distributed-fs/ceph-client/drivers/power/supply/rt9455_charger.c

Purpose: implements the Richtek RT9455 charger over I2C, including register-field abstractions, charger property reporting, hardware reset/default programming, interrupt handling, optional USB PHY role notifications for boost/charge transitions, and delayed safety work for power-ready, max charging time, and battery presence.

Important APIs, types, and functions: `enum rt9455_fields` and `rt9455_reg_fields[]` define bitfield access across control, IRQ, and mask registers. `struct rt9455_info` stores regmap fields, power supply, optional USB PHY notifier, delayed work, and configured charge/boost voltages. Table helpers `rt9455_find_idx()`, `rt9455_get_field_val()`, and `rt9455_set_field_val()` map physical units to register selectors. `rt9455_hw_init()` resets the chip and programs termination, battery detection, safety-timer policy, charge current, EOC percentage, MIVR, IAICR, and voltage settings. IRQ helper functions decode three IRQ registers and decide whether to notify userspace.

Control flow: probe checks SMBus byte-data support, creates regmap and regmap fields, reads mandatory/optional firmware properties, optionally registers a USB PHY notifier, initializes deferrable work items, registers the charger power supply, requests the threaded IRQ, and applies hardware initialization. IRQ handling reads status, processes IRQ1/2/3 faults and warnings, may switch from boost to charge mode on boost faults, masks battery-absent IRQs and schedules presence polling, and calls `power_supply_changed()` if user-visible state changed. USB PHY events adjust IAICR and switch between charge and boost modes. Remove resets the chip, unregisters the USB notifier, and cancels work.

State and persistence behavior: configured `voreg` and `boost_voltage` persist in driver memory and PMIC registers. Delayed work tracks power-source and battery-presence safety policy. Register state is reset on probe and remove, so this driver intentionally reinitializes hardware rather than preserving prior firmware settings. No nonvolatile state is written.

Dependencies and integration points: depends on I2C, regmap with cache, regmap fields, power-supply, OF or ACPI properties, optional USB PHY notifier support, IRQ line, and system power-efficient workqueue. Firmware properties such as `richtek,output-charge-current`, `richtek,end-of-charge-percentage`, `richtek,battery-regulation-voltage`, and `richtek,boost-output-voltage` are mandatory.

Risks: the driver disables the hardware safety timer and replaces part of that protection with delayed work, so workqueue cancellation and long suspend/offline cases are safety-sensitive. IRQ register reads also clear or reflect latched fault state depending on hardware semantics, requiring real-device validation. The checked-out source includes several duplicated lines in comments and code, including a duplicated return and a duplicated `regmap_field_write()` line in USB ID handling. Property programming rounds to table entries; tests should confirm acceptable charge voltages/currents. Test signals include OF and ACPI probe, required-property rejection, register reset timeout, USB PHY events for NONE/VBUS/ID/CHARGER, IRQ fault injection for all three IRQ registers, battery-absent polling, max-charging-time cutoff, and remove-time reset/notifier cleanup.

Purpose: implements the Richtek RT9466/RT9467 charger over I2C. It exposes a USB charger power supply, an OTG VBUS regulator, sysfs ship-mode control, ADC-backed voltage/current telemetry, BC1.2 charger-type detection, AICL measurement, watchdog handling, and charger configuration through regmap fields.

Important APIs, types, and functions: `enum rt9467_fields`, `rt9467_chg_fields[]`, `enum rt9467_ranges`, and `rt9467_ranges[]` map charger registers to typed controls. `struct rt9467_chg_data` stores regmap fields, IRQ chip data, power supply, ADC/attach/charge-current locks, OTG regulator, AICL completion, USB type, old status, vendor ID, and cached charge/termination currents. `rt9467_get_adc_raw_data()` and `rt9467_get_adc()` serialize ADC conversions and scale channels. `rt9467_psy_get_property()` and `rt9467_psy_set_property()` implement a large writable charger property surface. `rt9467_run_aicl()` starts hardware AICL and waits for an IRQ completion.

Control flow: probe configures an optional charge-enable GPIO, initializes regmap and regmap fields, verifies RT9466/RT9467 vendor ID, resets the chip, adds a regmap IRQ chip, initializes mutexes and AICL completion cleanup, applies charger initialization, registers the OTG regulator, registers the power supply with `sysoff_enable`, and requests variant-specific threaded IRQs. Charger init resets ADC, caches ICHG/IEOC, unmasks status bits, selects AICR for input-current limiting, disables hardware ILIM, sets OCP and termination defaults, sets the fast-charge timer, and toggles BC1.2 detection. IRQs handle status changes, watchdog petting, attach/detach USB type updates, and AICL completion.

State and persistence behavior: runtime state includes cached USB type, old status bits, cached ICHG/IEOC, and completion state. Hardware register fields hold charger enable, high-impedance state, charge limits, ADC/AICL settings, ship mode, and OTG regulator state. The `sysoff_enable` sysfs file writes ship mode directly; no driver-owned nonvolatile state exists.

Dependencies and integration points: depends on I2C, optional GPIO, regmap, regmap IRQ, regmap fields, power-supply, regulator core, sysfs attribute groups, completions, and mutexes. RT9467 gets attach/detach USB state IRQs; RT9466 uses a reduced IRQ set without USB attach classification.

Risks: ADC conversion and AICL waits are blocking paths reachable through power-supply property reads/writes, so timeouts and lock ordering matter. `POWER_SUPPLY_PROP_ONLINE` writes the raw value into `F_HZ`, whereas other drivers often invert online/high-impedance semantics; userspace expectations need validation. `RT9467_NUM_VOTG` is computed as a voltage delta plus one instead of selector count, which is suspicious for the regulator descriptor. The checked-out source has duplicated enum/signature lines and an extra closing brace after `rt9467_usb_state_handler()`, plus duplicated `int ret;`, making compile validation essential. Test signals include vendor-ID rejection, reset/init sequence, regulator registration and GPIO-controlled OTG, ADC channel scaling, AICL completion and timeout, attach/detach USB type reporting, sysfs ship-mode writes, watchdog IRQ handling, and RT9466 versus RT9467 IRQ selection.

Test signals include supported and unsupported device IDs, init patch verification, BC1.2 port mapping for Apple/Samsung/SDP/CDP/DCP/NSTD states, detach clearing current/type, watchdog reset IRQ, OTG regulator failure notification, sysfs writes for BATFET and port detection, power-supply writable property boundaries, and shutdown register reset.
