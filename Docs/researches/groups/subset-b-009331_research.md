# sources/test-tools/strace/src/linux/32/ioctls_inc_align64.h

## Purpose

`sources/test-tools/strace/src/linux/32/ioctls_inc_align64.h` is a generated strace build-time ioctl table fragment for 32-bit Linux personalities whose ioctl structure-size encoding uses 64-bit alignment for relevant UAPI structs. It is generated by `ioctls_gen.sh` from definitions found under a Linux `$linux/include` tree and records common Linux UAPI ioctl symbols after resolving command numbers and ABI-specific argument sizes.

The file is not a standalone C header with declarations or include guards. It is a raw initializer fragment: one generator comment plus 3,384 table rows. Rows cover 276 UAPI header paths, including large families from DRM, ALSA, v4l2/media, btrfs, binder, vhost, wireless, terminal, filesystem, USB, vfio, Xen, and soundcard headers.

## Important APIs, Types, And Data Shape

Each row has the five-field build-time shape consumed by `src/ioctlsort.c`:

```c
{ "header/path.h", "IOCTL_SYMBOL", _IOC_DIRECTION, 0xTYPE_NR, 0xSIZE },
```

The fields map to `ioctlsort.c`'s private `struct ioctlent`: provenance header path, symbol name, direction bits, type/number portion, and encoded size. `ioctlsort.c` computes the final ioctl command code as `type_nr | (size << _IOC_SIZESHIFT) | (dir << _IOC_DIRSHIFT)` and emits the smaller runtime `struct_ioctlent` shape declared in `src/defs.h`:

```c
typedef struct ioctlent {
	const char *symbol;
	unsigned int code;
} struct_ioctlent;
```

The direction distribution in this align64 table is: 932 `_IOC_READ|_IOC_WRITE` entries, 913 `_IOC_WRITE` entries, 580 `_IOC_READ` entries, 558 `_IOC_NONE` entries, and 401 legacy literal `0` direction entries.

## Control Flow

There is no runtime control flow in this file. Its behavior is entirely through preprocessor inclusion and build-time table generation.

`src/linux/32/ioctls_inc.h` selects this file for 32-bit ioctl layouts that are neither the `M68K` align16 case nor the align32 branch for `X86_64`, `X32`, or `SIZEOF_STRUCT_I64_I32 < SIZEOF_LONG_LONG * 2`. The build then concatenates the selected common include with architecture-specific ioctl fragments into `ioctls_all%.h`; compiles an `ioctlsort%` helper; sorts, deduplicates, and code-computes the five-field rows; writes generated `ioctlent%.h`; and includes those generated rows into `src/syscall.c`.

At runtime, `src/ioctl.c` binary-searches the selected read-only `ioctlent` array by numeric ioctl code and walks adjacent equal-code aliases. Entries from this file therefore affect symbolic fallback printing for `ioctl(fd, op, arg)` on the personalities that select the align64 32-bit layout.

## State And Persistence Behavior

The source file has no mutable state, I/O, locks, allocations, or persistence side effects. It persists as checked-in generated source data.

Derived state is created later by the build and the compiled binary. `ioctlent*.h` becomes read-only compiled data, while multi-personality builds keep global `ioctlent` and `nioctlents` pointers/counts that `src/syscall.c` switches when the traced task personality changes.

## Dependencies

Key dependencies are the Linux UAPI header set used during generation, `maint/ioctls_gen.sh`, `maint/ioctls_hex.sh`, `maint/ioctls_sym.sh`, `src/linux/32/ioctls_inc.h`, architecture-specific `ioctls_arch*.h` fragments, `src/ioctlsort.c`, `src/ioctl_iocdef.c`/`ioctl_iocdef.h`, `src/ioctls_zfs.h`, `src/Makefile.am` rules for `ioctlsort%` and `ioctlent%.h`, and the runtime consumers in `src/syscall.c` and `src/ioctl.c`.

## Integration Points

The main integration point is strace ioctl name decoding. If a specialized ioctl decoder does not handle a command first, the generated table lets strace print known symbolic names instead of only raw numbers. The table also integrates with source maintenance: regenerating against a newer kernel can add, remove, rename, resize, or collide rows, so generated updates need review for ABI and backwards-decoding effects.

## Risks

The main correctness risk is ABI mismatch. Many ioctl numbers include encoded structure sizes; choosing the align64 table for an ABI that needs align16 or align32, or changing a size in this table incorrectly, can make strace miss a known ioctl or print the wrong alias. Structure-size-heavy families such as DRM, v4l2/media, ALSA, btrfs, vfio, vhost, binder, USB, and time/pointer-size variants are especially sensitive.

Duplicate numeric codes are expected because Linux ioctl namespaces overlap. Correct behavior depends on `ioctlsort.c` preserving useful aliases and sorting by code so `ioctl.c` can find adjacent matches. Literal `0` direction entries are valid legacy commands but are more collision-prone and carry less semantic information than modern `_IOC_*` entries. Since this is a generated initializer fragment, small syntax changes such as a missing comma, unknown `_IOC_*` token, or reordered fields break the build or silently corrupt generated lookup data.

## Test Signals

Useful signals after touching this file are a successful strace build that regenerates `ioctlsort%` and `ioctlent%.h`, generated ioctl tables sorted by numeric code, known align64-sensitive commands resolving to expected names, ioctl decoder tests still printing expected symbolic aliases, and multi-personality tests covering a 32-bit target that selects the align64 branch through `src/linux/32/ioctls_inc.h`.

# sources/test-tools/strace/src/linux/32/subcallent.h

## Purpose

`sources/test-tools/strace/src/linux/32/subcallent.h` adapts the generic Linux indirect socket/IPC subcall table for 32-bit time32 personalities. It temporarily maps the generic `sys_recvmmsg` and `sys_semtimedop` decoder names to the 32-bit time variants before including `../generic/subcallent.h`, then undefines the mappings.

This keeps the generic subcall numbering and metadata while ensuring legacy indirect `socketcall`/`ipc` subcalls that pass timeout structures use `recvmmsg_time32` and `semtimedop_time32` decoders on 32-bit ABIs.

## Important APIs, Types, And Data Shape

The file defines two preprocessor aliases:

```c
#define sys_semtimedop sys_semtimedop_time32
#define sys_recvmmsg sys_recvmmsg_time32
```

The included generic table emits `struct_sysent` initializer rows using `SEN(recvmmsg)` and `SEN(semtimedop)`. Because `SEN` ultimately references `sys_...` decoder symbols, these aliases redirect only the two timeout-bearing indirect subcalls. After inclusion, both aliases are undefined to avoid affecting later syscall table fragments.

The generic dependency requires `SYS_socket_subcall` to be defined by the including architecture table and uses `TRACE_INDIRECT_SUBCALL` plus normal syscall flags such as `TN`, `TI`, `TM`, and `SI`.

## Control Flow

There is no runtime control flow in this wrapper. The compile-time flow is: define aliases, include the generic subcall table, then undefine aliases. The generic table emits entries for socket subcalls 1 through 20 and IPC subcalls, with `SYS_ipc_subcall` derived from `SYS_socket_subcall + SYS_socket_nsubcalls`.

At runtime, the resulting table rows are used by strace syscall dispatch when a traced 32-bit architecture exposes indirect socket or IPC multiplexing. `src/syscall.c` contains subcall handling paths guarded by `SYS_socket_subcall`.

## State And Persistence Behavior

This file has no mutable state or persistence. Its only lasting effect is compiled read-only syscall table data where the two affected indirect subcalls point at time32 decoders instead of the generic names.

## Dependencies

Dependencies are `../generic/subcallent.h`, architecture syscall tables that define `SYS_socket_subcall`, decoder symbols for `sys_recvmmsg_time32` and `sys_semtimedop_time32`, syscall table macros such as `SEN`, and trace classification flags from the surrounding strace syscall table infrastructure.

## Integration Points

Several 32-bit architecture tables include this wrapper after defining `SYS_socket_subcall`, including i386, arm, m68k, s390, sparc, powerpc, sh, and mips o32/n32 variants. It integrates with time32 decoder implementations in `mmsghdr.c` and `ipc_sem.c`, and with the generic indirect-subcall dispatch logic in `src/syscall.c`.

## Risks

The primary risk is leaking the temporary macro aliases beyond the include; the explicit `#undef` lines prevent that. If an architecture includes this file without defining `SYS_socket_subcall`, the generic table deliberately raises a preprocessor error. If a 32-bit ABI actually needs time64 indirect decoding for these legacy subcalls, this wrapper would route it incorrectly; the contract is that this is the 32-bit time32 subcall wrapper. Changes to names in `generic/subcallent.h` or `SEN` expansion can also break the aliasing trick.

## Test Signals

Useful signals are successful builds for 32-bit architectures that include this file, `tests/nsyscalls.c` coverage of `SYS_socket_subcall + 1`, syscall decoding tests for indirect `recvmmsg` and `semtimedop` with 32-bit timeout structures, and compile checks showing no `sys_recvmmsg`/`sys_semtimedop` macro leakage into following table includes.

# sources/test-tools/strace/src/linux/32/syscallent-common-32.h

## Purpose

`sources/test-tools/strace/src/linux/32/syscallent-common-32.h` defines common Linux syscall table entries for 32-bit architectures at syscall numbers 403 through 423. These are the post-y2038 time64 syscalls that were added to 32-bit architectures while keeping older time32 syscall numbers available separately.

The file is a `struct_sysent` initializer fragment, not a standalone header. It provides shared rows for 32-bit architecture tables after architecture-specific syscalls and before the generic common syscall list.

## Important APIs, Types, And Data Shape

The file ensures `BASE_NR` has a default value of `0`, then emits indexed syscall table rows such as:

```c
[BASE_NR + 403] = { 2, TCL, SEN(clock_gettime64), "clock_gettime64" },
```

Rows use the standard strace syscall table tuple: argument count, trace/classification flags, decoder selector through `SEN(...)`, and printable syscall name. The entries cover `clock_*time64`, `timer_*time64`, `timerfd_*time64`, `utimensat_time64`, `pselect6_time64`, `ppoll_time64`, `io_pgetevents_time64`, `recvmmsg_time64`, POSIX message-queue timed calls, `semtimedop_time64`, `rt_sigtimedwait_time64`, `futex_time64`, and `sched_rr_get_interval_time64`.

Trace flags classify file-descriptor/path syscalls (`TD`, `TF`), clock/time syscalls (`TCL`), networking (`TN`), IPC (`TI`), and signal-related behavior (`TS`) where applicable.

## Control Flow

There is no executable control flow in this source. Inclusion flow is controlled by architecture syscall tables. The shared 32-bit `syscallent.h` includes `syscallent-time32.h` when `HAVE_ARCH_TIME32_SYSCALLS` is true, leaves reserved slots 295 through 402, then includes this file and `syscallent-common.h`. Other 32-bit architecture tables include it in a similar position.

`BASE_NR` allows tables with nonzero syscall bases, such as mips ABI tables, to reuse the same logical Linux syscall numbers while offsetting the actual index.

## State And Persistence Behavior

The file has no mutable state or persistence. Its rows become compiled read-only `sysent` table entries. Runtime syscall dispatch reads those entries to select decoders and names, and multi-personality builds switch between compiled syscall table arrays when traced task personality changes.

## Dependencies

Dependencies are the surrounding `struct_sysent` initializer context, `BASE_NR` when an architecture needs an offset, `SEN` decoder declarations generated by the strace build, decoder implementations for each `*_time64` syscall, and trace flag definitions. It also depends on nearby architecture table layout preserving the reserved range between old 32-bit syscalls and the common time64 block.

## Integration Points

This file integrates with 32-bit architecture syscall tables for arm, i386, m68k, microblaze, mips o32/n32, powerpc, s390, sh, sparc, hppa, and other architectures that reuse the common 32-bit table fragments. It pairs with `syscallent-time32.h`: the older syscall names remain mapped to time32 decoders, while numbers 403 through 423 expose the explicit time64 names and decoders.

## Risks

Off-by-one or wrong `BASE_NR` usage would put decoders at the wrong syscall numbers, which is a serious tracing regression. Missing entries are intentional where Linux left gaps, for example number 415 is absent; filling such gaps incorrectly would make strace claim nonexistent or architecture-reserved syscalls. Decoder name mismatches are also risky because time64 syscalls require different structure decoding from older time32 variants. Trace flags must remain accurate because they drive filtering, summary classes, fault injection categories, and path/fd-specific output behavior.

## Test Signals

Useful signals are successful builds for representative 32-bit architectures, `strace -e trace=clock_gettime64`, `ppoll_time64`, `futex_time64`, and `recvmmsg_time64` decoding with correct names and argument formats, nsyscall table size checks, and regression tests verifying that old time32 syscall numbers still decode through `syscallent-time32.h` while numbers 403 through 423 use time64 decoders.

# sources/test-tools/strace/src/linux/32/syscallent-time32.h

## Purpose

`sources/test-tools/strace/src/linux/32/syscallent-time32.h` overrides legacy 32-bit syscall table slots whose ABI passes 32-bit time-related structures. It maps old syscall names such as `ppoll`, `utimensat`, `clock_gettime`, and `futex` to explicit `*_time32` decoders while preserving the user-visible syscall names.

The file is included only when `HAVE_ARCH_TIME32_SYSCALLS` is true. It keeps old 32-bit syscall decoding separate from the newer time64 rows in `syscallent-common-32.h`.

## Important APIs, Types, And Data Shape

The file emits indexed `struct_sysent` initializer rows for legacy syscall numbers. Each row uses the standard strace table shape: argument count, trace flags, `SEN(decoder)`, and printable syscall name.

Covered groups include AIO and polling (`io_getevents_time32`, `pselect6_time32`, `ppoll_time32`, `io_pgetevents_time32`), timer and clock syscalls (`timerfd_*time32`, `timer_*time32`, `clock_*time32`, `nanosleep_time32`, `sched_rr_get_interval_time32`), filesystem timestamp updates (`utimensat_time32`), futex and signal waits (`futex_time32`, `rt_sigtimedwait_time32`), message queues (`mq_timedsend_time32`, `mq_timedreceive_time32`), SysV semaphores (`semtimedop_time32`), networking (`recvmmsg_time32`), and legacy time-of-day/timex calls (`gettimeofday`, `settimeofday`, `adjtimex32`).

Rows preserve trace flags such as `TD`, `TF`, `TCL`, `TN`, `TI`, `TS`, and `TP` so filtering and classification remain consistent with the base syscall table.

## Control Flow

There is no executable control flow in this file. The inclusion flow is conditional: `src/linux/32/syscallent.h` includes it under `#if HAVE_ARCH_TIME32_SYSCALLS` before including `syscallent-common-32.h` and `syscallent-common.h`. The entries replace commented placeholder slots in the base table, for example clock/timer/poll/futex slots that would otherwise be generic comments or architecture-specific rows.

At runtime, the compiled syscall table directs legacy syscall numbers to time32-specific decoders. Newer time64 syscall numbers are handled separately by `syscallent-common-32.h`.

## State And Persistence Behavior

The file has no mutable state, allocation, I/O, or persistence. Its effect is compiled read-only syscall table state. Runtime persistence is limited to the process-wide selected `sysent` pointer/count in multi-personality builds.

## Dependencies

Dependencies are `HAVE_ARCH_TIME32_SYSCALLS` from `arch_defs.h` or architecture overrides, `SEN` decoder declarations for all listed time32 handlers, the corresponding decoder implementations in files such as `time.c`, `poll.c`, `futex.c`, `mmsghdr.c`, `mq.c`, `ipc_sem.c`, `aio.c`, `signal.c`, `sched.c`, `utimes.c`, and `wait.c`, plus trace flag definitions used by syscall filtering and reporting.

## Integration Points

This fragment integrates with the shared 32-bit syscall table and with architecture-specific 32-bit syscall tables that reuse it. It is the legacy counterpart to `syscallent-common-32.h`: old syscall numbers keep names like `clock_gettime` and `futex` but use time32 decoding, while added y2038-safe syscall numbers carry explicit `*_time64` names and decoders.

## Risks

The central risk is mixing time32 and time64 decoders. A wrong decoder would read timeout, timespec, timeval, or timex arguments with the wrong layout and produce bad output or memory reads. Conditional inclusion must match architecture reality; enabling it for a no-time32 ABI or disabling it for a legacy 32-bit ABI would misdecode many common syscalls. Trace flag drift is also risky because these rows affect `-e trace=` classes, path/fd handling, and syscall summaries.

## Test Signals

Useful signals are 32-bit builds with `HAVE_ARCH_TIME32_SYSCALLS=1`, decoder tests for representative legacy calls such as `clock_gettime`, `ppoll`, `utimensat`, `futex`, `recvmmsg`, and `semtimedop`, y2038 boundary fixtures showing 32-bit time fields decoded as time32, and paired tests confirming that `clock_gettime64`/`futex_time64` use the separate time64 entries rather than these legacy rows.
