# sources/distributed-fs/lustre-release/lnet/lnet/lib-msg.c

Purpose: implements LNet message event construction, active-message accounting, transmit/receive commit and decommit, MD attachment/detachment, finalization, health accounting, resend scheduling, and per-CPT message container setup. It is the central lifecycle file for `struct lnet_msg` after send, receive, route, ACK, reply, or failure paths hand ownership back to the core.

Important APIs/types/functions: `lnet_build_unlink_event()` and `lnet_build_msg_event()` populate user-visible `struct lnet_event` fields from MDs and headers. `lnet_msg_commit()`, `lnet_msg_decommit_tx()`, `lnet_msg_decommit_rx()`, and `lnet_msg_decommit()` manage active-list membership, counters, credits, and routed messages committed in both directions. `lnet_msg_attach_md()` and `lnet_msg_detach_md()` transfer MD ownership to a message, decrement thresholds, handle auto-unlink, detach response trackers, and invoke MD handlers. `lnet_finalize()` is the exported completion entry point. Health support is split across `lnet_health_check()`, `lnet_incr_hstats()`, `lnet_handle_local_failure()`, `lnet_handle_remote_failure[_locked]()`, `lnet_attempt_msg_resend()`, `lnet_resend_msg_locked()`, `lnet_health_error2str()`, and exported `lnet_send_error_simulation()`. Container lifecycle uses `lnet_msg_container_setup()`, `lnet_msg_container_cleanup()`, `lnet_msg_containers_create()`, and `lnet_msg_containers_destroy()`.

Control flow: send/receive code commits a message to a CPT container and places it on `msc_active`; commit also derives `msg_deadline` from the LND timeout when available, otherwise the global transaction timeout. When an LND or parser completes a message it calls `lnet_finalize()`, which first records `msg_ev.status`, optionally runs health logic, detaches the MD and handler, then enters a recursion-limited finalizer queue. `lnet_complete_msg_locked()` may transform a successful passive PUT into an ACK send, forward a routed message with `lnet_send()`, or decommit/free the message. Decommit returns TX/RX credits, fixes temporary message-type rewrites used for ACK/REPLY optimized paths, updates common and per-NI/peer stats, removes the active-list entry, and decrements `lcc_msgs_alloc`.

State and persistence behavior: all state is in-memory kernel state under `the_lnet`: per-CPT `ln_msg_containers`, active/finalizing/resending lists, common/health counters, recovery queues, late-message counters, retry counters, and MD flags/refcounts. There is no disk persistence. MD state is persistent only until finalization/unlink: `md_refcount`, `md_threshold`, `LNET_MD_FLAG_HANDLING`, `LNET_MD_FLAG_ABORTED`, and auto-unlink behavior determine whether callbacks run before or after unlink. Health changes persist in NI/peer health values and recovery queues until monitor recovery adjusts them.

Dependencies/integration points: depends on LNet core globals and locks (`lnet_net_lock`, `lnet_res_lock`), MD helpers, credit return helpers, peer and NI health/recovery helpers, LND timeout callbacks, message send/parse code, drop-rule fault simulation, delayed-rule replay checks, and libcfs debug/assertion infrastructure. It exports `lnet_finalize()` for LND completion and `lnet_send_error_simulation()` for send-side fault hooks.

Risks: lock ordering is delicate because routed messages can be committed on different TX and RX CPTs and `lnet_msg_decommit()` may temporarily switch locks. Finalization and resend recursion breakers rely on per-container process-pointer slots; regressions can leave messages stuck on `msc_finalizing` or `msc_resending`. Health status and numeric status must remain consistent or health handling is skipped. MD handler invocation races are avoided by `LNET_MD_FLAG_HANDLING`; missing waits or incorrect refcount drops can cause use-after-free. ACK and optimized GET/REPLY paths temporarily rewrite `msg_type`, so counters can be wrong if decommit order changes.

Test signals: exercise active PUT/GET/ACK/REPLY event fields, routed messages committed on two CPTs, successful PUT ACK generation, failed ACK/forward send returning to `lnet_finalize()`, MD auto-unlink and aborted-MD timeout status, `lnet_retry_count` boundaries, local/remote/network timeout health transitions, resend queueing and successful resend counters, message deadline late counters, drop-rule health injection, and container cleanup detecting no active messages on shutdown.

# sources/distributed-fs/lustre-release/lnet/lnet/lib-ptl.c

Purpose: implements LNet portal matching. It maps incoming PUT/GET requests to per-CPT match tables, enforces unique versus wildcard portal modes, attaches/detaches MDs to MEs, delays or drops unmatched lazy-portal PUTs, and wakes delayed messages when new buffers are posted.

Important APIs/types/functions: module parameter `portal_rotor` controls wildcard portal CPU partition selection. `lnet_ptl_match_type()` fixes a portal as unique or wildcard based on the first ME pattern. `lnet_mt_of_attach()` selects an attach-side match table, while `lnet_mt_of_match()` selects a receive-side match table using unique hash, current CPT, round-robin, or routed-message hash behavior. `lnet_try_match_md()` checks MD exhaustion, operation mask, match bits, PID, NID/peer equivalence, remote offset, max-size/truncate rules, attaches the MD, advances offset, and auto-unlinks exhausted MDs. `lnet_mt_match_md()`, `lnet_ptl_match_md()`, and `lnet_ptl_match_delay()` perform normal, stealing, delayed, or drop decisions. `lnet_ptl_attach_md()` binds a new MD to an ME and tries to resume queued delayed/stealing messages. `LNetSetLazyPortal()`, `lnet_clear_lazy_portal()`, and `LNetClearLazyPortal()` manage lazy portal behavior.

Control flow: an incoming message calls `lnet_ptl_match_md()`. Invalid portal indexes drop immediately. A portal that has not yet been typed may drop or delay early messages unless lazy; otherwise the selected match table is locked and searched. Matching first checks the ignore-bits bucket, then the normal hash bucket. On match, the message gets an MD and returns OK; on oversize without truncate it returns DROP; on no match a GET or non-lazy portal drops, while lazy PUTs may be queued. For wildcard portals, exhausted hash buckets disable their CPT table and later `lnet_ptl_attach_md()` clears exhausted bits and re-enables the table when a new MD arrives. Delayed messages are moved to caller-provided `matches` or `drops` lists for receive processing outside the portal lock.

State and persistence behavior: portal state lives in `the_lnet.ln_portals`: `ptl_mtables`, `ptl_mt_maps`, `ptl_mt_nmaps`, `ptl_rotor`, `ptl_msg_delayed`, `ptl_msg_stealing`, portal flags, and per-table hash/exhausted bitmaps. ME/MD lists and message queues are in-memory only. Lazy portal queues can persist indefinitely while the module runs until a matching MD arrives, a portal is cleared, an NI-specific clear removes matching delayed messages, or shutdown drops them.

Dependencies/integration points: integrates with ME/MD resource management, peer lookup for Multi-Rail NID equivalence, CPT helpers, `lnet_msg_attach_md()`, lazy portal consumers, delayed-message drop helpers, `lnet_parse_*` receive paths, and `portal_rotor` debugfs/proc control in `lnet_debugfs.c`.

Risks: first-use portal typing rejects later ME patterns of the opposite kind; tests must catch accidental mixed unique/wildcard use. Lazy portals are explicitly a DoS risk because unmatched PUTs can accumulate and stall underlying connections. `ptl_mt_maps` is intentionally read without full locking in the fast path, so invariants around `mt_enabled` and map ordering are important. Stealing path lock nesting spans resource locks and portal locks; incorrect queue removal can let another thread handle or drop the same message. Match with same-peer but different NID logs a warning and accepts; peer ref handling must remain balanced.

Test signals: cover unique and wildcard portal classification, attach-side CPT selection for `LNET_INS_BEFORE`, `AFTER`, and `LOCAL`, wildcard rotor modes (`OFF`, `ON`, `RR_RT`, `HASH_RT`), ignore-bits bucket precedence, MD threshold exhaustion and auto-unlink, oversize/truncate behavior, lazy portal delayed queueing and clearing, stealing from other CPTs, re-enabling exhausted tables when MDs are posted, invalid portal drops, and same-peer Multi-Rail NID mismatch acceptance.

# sources/distributed-fs/lustre-release/lnet/lnet/lib-socket.c

Purpose: provides exported kernel socket helpers for LNet transports and setup code: reliable blocking-ish read/write loops with timeouts, socket creation/bind/connect/listen, buffer sizing, local/remote address query, IPv4 source selection, and enumeration of usable IPv4/IPv6 interfaces with CPU partition affinity.

Important APIs/types/functions: exported `lnet_sock_write()` and `lnet_sock_read()` loop over `kernel_sendmsg()`/`kernel_recvmsg()` until all bytes are transferred or timeout/error occurs. `choose_ipv4_src()` selects the best local IPv4 address on an interface for a destination. Internal `lnet_sock_create()` creates AF_INET6 by default with AF_INET fallback for listeners, handles namespace refs under compatibility macros, sets reuseport, chooses local bind addresses, and handles IPv6-v4 dual-stack. Exported `lnet_sock_setbuf()`, `lnet_sock_getaddr()`, and `lnet_sock_getbuf()` manage socket parameters. `lnet_sock_listen()` and `lnet_sock_connect()` wrap bind/listen/connect. `lnet_inet_enumerate()` and its IPv4/IPv6 helpers build `struct lnet_inetdev` arrays.

Control flow: write and read helpers update socket send/receive timeouts to the remaining jiffies before each kernel I/O call, detect zero progress as abort/reset, and return `-EAGAIN` or `-ETIMEDOUT` on deadline expiry. Socket creation chooses the address family from the remote or explicit local address, binds if an interface or port is requested, and for IPv6 forces dual-stack behavior when possible. Interface enumeration holds RTNL, skips loopback/down devices, maps VLAN devices to real devices for NUMA/CPT affinity, and calls IPv6 or IPv4 enumeration in caller-requested order.

State and persistence behavior: state is kernel socket state, socket buffer lock flags, socket timeout fields, and transient allocated interface arrays returned to callers. No persistent storage exists. Enumerated device records include interface name/index, master flag, address size, address, netmask for IPv4, and CPT. IPv6 enumeration intentionally keeps only the first non-temporary, non-link-local address per interface.

Dependencies/integration points: uses Linux kernel socket APIs, net namespaces, RCU/RTNL device traversal, IPv4/IPv6 address helpers, VLAN helpers, Lustre compatibility wrappers, CPT mapping, and LNet NI configuration code that consumes interface enumeration. It exports helpers for LNDs such as socklnd.

Risks: timeout arithmetic depends on jiffies deltas and can return quickly under partial progress. `lnet_sock_connect()` passes `sizeof(struct sockaddr_in6)` for connect, relying on kernel tolerance for IPv4-compatible storage. Compatibility blocks for IPv6 `IPV6_V6ONLY` cover multiple kernel eras and are easy to regress. Enumeration realloc failure frees the partially built list and returns `-ENOMEM`; callers must respect that ownership transfer. IPv6 source selection errors are not checked after `ipv6_dev_get_saddr()`, so bound addresses may remain unspecified in some cases.

Test signals: simulate partial sends/receives, zero-length kernel returns, send timeout with nonblocking mode, receive timeout, bind conflicts on listen, IPv6 disabled fallback to IPv4 listener, IPv4 source selection by subnet, v4-mapped `lnet_sock_getaddr()` conversion, explicit local bind address, public IPv6 source preference on connect, VLAN CPT mapping, filtering of down/loopback/temp/link-local interfaces, and allocation failure in enumeration.

# sources/distributed-fs/lustre-release/lnet/lnet/lnet-crypto.c

Purpose: wraps the Linux async hash API for Lustre/LNet checksum use, supports one-shot and incremental hashing over buffers/pages, registers the Lustre adler32 implementation, and benchmarks available algorithms into `cfs_crypto_hash_speeds`.

Important APIs/types/functions: exported `cfs_crypto_hash_speeds[]` stores MB/s or negative error values per algorithm. Internal `cfs_crypto_hash_alloc()` resolves `cfs_crypto_hash_type()`, allocates plain or HMAC `crypto_ahash`, allocates an `ahash_request`, sets optional/default keys, and initializes the request. Exported `cfs_crypto_hash_digest()` performs one-shot buffer hashing. Exported `cfs_crypto_hash_init()`, `cfs_crypto_hash_update_page()`, `cfs_crypto_hash_update()`, and `cfs_crypto_hash_final()` implement incremental hashing and cleanup. `cfs_crypto_hash_speed()` lazily benchmarks a single algorithm under a static mutex. `cfs_crypto_register()` requests `crc32c`, registers adler32, and benchmarks startup algorithms; `cfs_crypto_unregister()` unregisters adler32.

Control flow: one-shot digest validates inputs, allocates and initializes the hash request, reports required digest size with `-ENOSPC` if needed, sets a one-entry scatterlist, runs `crypto_ahash_digest()`, and frees request plus transform. Incremental callers allocate with `cfs_crypto_hash_init()`, call update helpers for page or buffer chunks, and must finish via `cfs_crypto_hash_final()`, which optionally only frees when hash output is omitted. Benchmarking allocates one page, repeatedly hashes a 1 MiB logical workload for about a quarter second, and stores computed throughput or the first error.

State and persistence behavior: algorithm speeds and the `adler32` registration flag are process/module memory only. Crypto transforms and requests are allocated per operation and freed in final/digest paths. No persistent key or digest state survives beyond an active `ahash_request` unless callers retain the request.

Dependencies/integration points: depends on Linux `crypto_ahash`, scatterlists, page mapping, libcfs hash type metadata from `lnet_crypto.h`, the local `adler.h` registration API, module lifecycle in `module.c`, and consumers that choose checksum algorithms based on measured speed.

Risks: every successful `cfs_crypto_hash_init()` must be paired with `cfs_crypto_hash_final()` to avoid leaking transform/request memory. HMAC algorithm names are dynamically allocated and depend on kernel crypto provider availability. `cfs_crypto_hash_update_page()` masks the page offset with `~PAGE_MASK`; tests should ensure the intended offset within the page is passed. Benchmark speed is approximate and can be negative when provider allocation fails. `cfs_crypto_hash_digest()` uses `-ENOSPC` for both NULL hash and short buffer, updating `hash_len`.

Test signals: unsupported algorithm returns `-EINVAL`/`-ENOENT` as appropriate, one-shot NULL or too-small digest reports required size, keyed HMAC and default-key paths work, incremental buffer and page updates match one-shot digest, final-without-output frees cleanly, lazy speed computation happens once under concurrency, startup registers/unregisters adler32, and provider allocation failures propagate without leaks.

# sources/distributed-fs/lustre-release/lnet/lnet/lnet_debugfs.c

Purpose: registers LNet debugfs/proc-style control table entries for CPU partition topology, counters, routes, routers, peers, router buffers, local NIs, portal rotor tuning, and LND timeout. It exposes read-only diagnostics plus a few write paths that reset minimum/aggregate counters or update portal rotor mode.

Important APIs/types/functions: `proc_cpt_table()` and `proc_cpt_distance()` print CPU partition data with dynamically grown buffers. `proc_lnet_stats()` reads or resets common LNet counters. `proc_lnet_routes()`, `proc_lnet_routers()`, and `proc_lnet_peers()` iterate versioned route/router/peer state using packed `loff_t` cursor fields. `proc_lnet_buffers()` reports router buffer pools. `proc_lnet_nis()` prints NI TX credit state and resets minimum credits on write. `proc_lnet_portal_rotor()` reads/writes the `portal_rotor` mode names. `lnet_router_debugfs_init()`, `lnet_router_debugfs_fini()`, and `lnet_router_exit()` connect the `lnet_table` to LNet debugfs infrastructure.

Control flow: read handlers build one record or a small table in a temporary buffer, copy to user from the requested offset, and update `*ppos` for iterative readers. Route/router/peer handlers store version bits in `*ppos`; if the underlying list version changes mid-iteration they return `-ESTALE`. Write handlers are narrow: stats writes call `lnet_counters_reset()`, peers/NIs writes reset observed minimum credit fields, and portal rotor writes parse a string against the known rotor table under `lnet_res_lock(0)`.

State and persistence behavior: debugfs entries expose live kernel state in `the_lnet` and libcfs CPU partition state. Persistent state is only in memory: counter resets mutate LNet counters/minimum credit tracking, and portal rotor writes update the module parameter used by `lib-ptl.c`. No disk state is written. Cursor packing encodes CPT, version, hash bucket, and offset into `loff_t`.

Dependencies/integration points: integrates with libcfs debugfs/sysctl wrappers (`lnet_insert_debugfs`, `cfs_proc_handler`, `debugfs_doint`), LNet counters, route/router/peer tables, NI and router buffer pools, portal rotor constants from `lib-ptl.c`, and module cleanup via `lnet_router_exit()`.

Risks: packed `loff_t` cursor sizing depends on compile-time bit macros; overflow or version-mask mistakes can break large peer tables. Several handlers allocate fixed 256-byte buffers per row and assert enough room; new wider fields can overflow assumptions. The peers handler directly reads peer table internals with a TODO noting missing accessor APIs. Write paths mutate diagnostic minima and must not be exposed without intended permissions. Portal rotor parsing uses prefix-style `strncasecmp()` against mode names, so ambiguous prefixes would be accepted if introduced.

Test signals: read every entry with small and large user buffers, verify stats reset and NI/peer minimum reset writes, mutate route/peer versions during iteration and expect `-ESTALE`, cover multiple CPT peer hash traversal, router and non-router buffer output, all portal rotor string modes and invalid strings, CPU partition buffer growth on `-EFBIG`, and init/fini/remove ordering with `debugfs_state`.

# sources/distributed-fs/lustre-release/lnet/lnet/lnet_rdma.c

Purpose: provides an optional bridge from LNet RDMA paths to NVIDIA FS/GDS DMA callbacks. It lets an external NVFS provider register scatterlist preparation/DMA/page/device-priority operations, then exposes helpers for device priority, GPU page device index, DMA map/unmap, and RDMA-only page detection.

Important APIs/types/functions: global `nvfs_ops`, `nvfs_shutdown`, and `nvfs_n_ops` track registered callbacks and in-flight users. `REGISTER_FUNC()` validates feature bits, initializes the percpu counter, installs callbacks, and clears shutdown. `UNREGISTER_FUNC()` sets shutdown, waits until the in-flight counter drains, clears callbacks, and destroys the counter. `lnet_get_dev_prio()`, `lnet_get_dev_idx()`, `lnet_rdma_map_sg_attrs()`, `lnet_rdma_unmap_sg()`, and `lnet_is_rdma_only_page()` wrap provider callbacks and are exported as appropriate.

Control flow: callers use `nvfs_get_ops()` to reject absent/shutting-down providers and increment the in-flight counter, call the provider, then `nvfs_put_ops()` when ownership ends. DMA map returns `-EIO` for `NVFS_IO_ERR`, falls back to normal CPU mapping when `NVFS_CPU_REQ` is returned, or returns the provider map count while intentionally keeping the operation counted until `lnet_rdma_unmap_sg()` drops it. Unregister loops with a one-second sleep until `nvfs_count_ops()` reaches zero.

State and persistence behavior: state is module-global and volatile. Registration is single-provider, without persistence across module reload. `ERROR_PRINT_DEADLINE` throttles missing-feature console messages through a static timestamp. The in-flight percpu counter doubles as shutdown coordination and lifetime protection for `nvfs_ops`.

Dependencies/integration points: depends on `linux/lnet/lnet_rdma.h`, NVFS callback feature macros, Linux DMA/scatterlist/page/device types, libcfs logging, and LNet RDMA-capable LNDs that can pass GPU pages or SG lists through these wrappers.

Risks: `REGISTER_FUNC()` has no explicit locking around `nvfs_ops`, so concurrent register/unregister or caller races need external serialization assumptions. `lnet_rdma_unmap_sg()` calls `nvfs_put_ops()` once after provider unmap and again when `count` is nonzero; this matches the map path only if nonzero represents a previously held map operation, but it is a fragile lifetime contract. Unregister waits indefinitely for leaked operation counts. Missing feature log text for device priority says "not missing" while marking unsupported, suggesting a diagnostic typo.

Test signals: register rejects NULL or incomplete feature sets, successful register enables all wrappers, unregister blocks until map-held operations unmap, `NVFS_IO_ERR` maps to `-EIO`, `NVFS_CPU_REQ` falls back with balanced counts, provider map count is returned and later drained by unmap, absent provider returns neutral defaults (`UINT_MAX`, false, 0), device priority ignores NULL devices, and concurrent lookup during shutdown never dereferences cleared callbacks.

# sources/distributed-fs/lustre-release/lnet/lnet/lo.c

Purpose: implements the loopback LNet LND (`the_lolnd`). It delivers local messages back into the LNet parser without a real network transport and copies payload data directly between kernel IO vectors.

Important APIs/types/functions: `lolnd_send()` asserts the message is not routed or targeting a router and calls `lnet_parse()` with the local NI NID and original message. `lolnd_recv()` copies send message payload into the receive iterator with `lnet_copy_kiov2iter()`, finalizes the receive message if present, and always finalizes the original send message. `lolnd_startup()` and `lolnd_shutdown()` enforce a single `lolnd_instanced` instance. `the_lolnd` fills `struct lnet_lnd` operations for type `LOLND`.

Control flow: when LNet sends to loopback, `lolnd_send()` immediately re-enters receive parsing. If a matching receive buffer exists, `lolnd_recv()` copies data and finalizes both receive and send messages with status zero; if receiving is a discard path, it skips the receive copy/finalize and still completes the send. Startup/shutdown only toggle the instance flag.

State and persistence behavior: only `lolnd_instanced` persists in memory to prevent multiple loopback instances. No device, socket, or disk state exists. Message and MD state is delegated to core parser/finalizer code.

Dependencies/integration points: integrates with LNet LND registration, `lnet_parse()`, `lnet_copy_kiov2iter()`, `lnet_finalize()`, and NID string/type handling for `LOLND`.

Risks: this code assumes loopback messages never route and never target routers; violating those assertions is a core logic bug. Direct copy length uses `iov_iter_count(to)` and the send message offset/kiov fields, so parser setup must supply valid iterators. The single-instance flag is not separately locked and relies on LNet startup serialization.

Test signals: configure loopback once, reject/detect duplicate startup by assertion in debug builds, send local PUT/GET paths through parser, verify payload copy and both finalizers run, exercise discard receive path, and ensure shutdown clears the instance flag.

# sources/distributed-fs/lustre-release/lnet/lnet/lock.c

Purpose: implements libcfs per-CPU-partition spinlock aggregation used by LNet to reduce cacheline contention while still supporting an exclusive all-partitions lock mode.

Important APIs/types/functions: exported `cfs_percpt_lock_create()` allocates a `struct cfs_percpt_lock` and a per-CPT spinlock array, optionally assigning lockdep classes. `cfs_percpt_lock_free()` frees the lock after asserting no exclusive lock is held. `cfs_percpt_lock()` acquires either one partition lock or all locks for `CFS_PERCPT_LOCK_EX`. `cfs_percpt_unlock()` releases the matching lock set in reverse order for exclusive mode.

Control flow: non-exclusive callers spin while `pcl_locked` is set, then lock only their indexed partition. Exclusive callers lock CPT 0 first, set `pcl_locked` to prevent new private lock attempts, then lock all remaining partitions. Unlock clears `pcl_locked` just before releasing CPT 0 after all higher locks have been released. A one-CPT system maps all lock modes to lock index 0.

State and persistence behavior: the only state is the allocated lock object, per-CPT spinlock array, optional CPT table pointer, and `pcl_locked` flag. It is volatile and freed by `cfs_percpt_lock_free()`.

Dependencies/integration points: depends on libcfs CPT allocation/iteration helpers, spinlocks, lockdep class keys, and LNet code using `lnet_net_lock()`/resource locks over per-CPT data structures.

Risks: the exclusive barrier uses a plain `pcl_locked` flag with busy-waiting, so correctness depends on lock ordering and memory semantics from the spinlock sequence. Exclusive locking can starve if new private lockers repeatedly pass before `pcl_locked` is set, though the code sets it after the first lock to narrow that window. Missing lockdep keys can produce false recursive-lock warnings, called out by the warning. Freeing while any partition lock is held is catastrophic and only guarded by assertions/ownership discipline.

Test signals: create/free with single and multiple CPTs, per-CPT independent locking, exclusive lock excludes private locks, unlock order restores private access, NULL lockdep keys only warn, invalid indexes assert in debug builds, and high-contention stress does not deadlock.

# sources/distributed-fs/lustre-release/lnet/lnet/module.c

Purpose: owns LNet module initialization/exit, `/dev/lnet` miscdevice registration, privileged ioctl dispatch, dynamic network/NI configure/unconfigure operations, optional configure-on-load, and integration with libcfs CPU/crypto/LNet library setup.

Important APIs/types/functions: module parameters `config_on_load` and `enable_sysctl_setup` control load-time behavior. `lnet_configure()` and `lnet_unconfigure()` serialize self-initialization with `lnet_config_mutex`, take/drop the module ref, and call `LNetNIInit()`/`LNetNIFini()`. Dynamic helpers call `lnet_dyn_add_net()`, `lnet_dyn_del_net()`, `lnet_dyn_add_ni()`, and `lnet_dyn_del_ni()`. `lnet_ioctl()` handles core IOC commands and delegates other commands through `LNetCtl()` under a temporary `LNetNIInit(LNET_PID_ANY)` reference. `lnet_psdev_ioctl()` validates capability, ioctl type/range, copies user headers, adjusts legacy packed buffers, calls core/deprecated/notifier handlers, and copies results back. `lnet_init()` and `lnet_exit()` perform module lifecycle.

Control flow: `late_initcall(lnet_init)` sets up libcfs, CPU partitioning, crypto, LNet library state, and miscdevice registration. If `config_on_load` is set, a kernel thread calls `lnet_configure()` to avoid module-load deadlock. User ioctl calls require `CAP_SYS_ADMIN`, pass header version and length validation, optionally map legacy inline buffers, then go to deprecated libcfs debug-marker handlers, LNet core handlers, or blocking notifier subscribers. Exit deregisters the miscdevice, tears down router debugfs, exits LNet library state, unregisters crypto, and finalizes CPU state.

State and persistence behavior: state is in module globals and `the_lnet`: `ln_niinit_self`, `ln_nis_from_mod_params`, module refcount, LNet library state, miscdevice registration, notifier list, and dynamic net/NI configuration. No file persistence exists. User ioctl payloads are copied into temporary kernel memory and freed after each call.

Dependencies/integration points: integrates with libcfs setup/debug, CPU partition setup, LNet crypto registration, LNet library init/exit, UAPI ioctl structures, DLC config structures, dynamic LNet config code, notifier clients, miscdevice `/dev/lnet`, Linux capability checks, and Lustre version compatibility guards.

Dynamic NI deletion checks `the_lnet.ln_niinit_self` before locking and again after locking; races are mitigated by the mutex. Init failure paths must unwind in exact reverse order. `enable_sysctl_setup` is declared but not used in this file, so behavior may live elsewhere or be stale.

# sources/distributed-fs/lustre-release/lnet/lnet/net_fault.c

Purpose: implements LNet network fault simulation. It supports message drop rules, health-error injection rules, and delay rules with timers/daemon replay so tests and operators can simulate lost, failed, or delayed PUT/GET/ACK/REPLY traffic by source/destination/local NID, portal, message type, rate, interval, random mode, and latency.

Important APIs/types/functions: `struct lnet_drop_rule` stores match attributes, drop schedule, lock, and stats on `the_lnet.ln_drop_rules`. `struct lnet_delay_rule` stores match attributes, refcount, schedule, delayed message list, stats, and timer on `the_lnet.ln_delay_rules`. Attribute helpers convert old NID4 ioctl format to large NIDs and validate masks. Drop APIs include `lnet_drop_rule_add()`, `lnet_drop_rule_del()`, `lnet_drop_rule_collect()`, `lnet_drop_rule_reset()`, and `lnet_drop_rule_match()`. Delay APIs include `lnet_delay_rule_add()`, `lnet_delay_rule_del()`, `lnet_delay_rule_collect()`, `lnet_delay_rule_reset()`, `lnet_delay_rule_match_locked()`, `lnet_delay_rule_check()`, and daemon/timer helpers. `lnet_fault_ctl()` is the legacy ioctl dispatcher, and `lnet_fault_init()`/`lnet_fault_fini()` initialize and clean up.

Control flow: rule add validates that exactly one of rate or interval is provided and, for delays, that latency is nonzero. Drop matching scans rules under the LNet net lock, filters by source/local/destination NID, message bit, and optional portal, then uses either drop-all, random, time-based, or rate-based scheduling to decide. If a health-error mask is present, only health-injection callers match, and a random/nearest status bit is chosen. Delay matching is called with the net lock already held, uses similar filters/scheduling, appends the message to the rule list, stamps `msg_delay_send`, and arms a timer. Timer callbacks enqueue rules on a daemon schedule list; `lnet_delay_rule_check()` drains due messages and replays sends, local receives, or routed receives, or drops/finalizes on failure. Removing delay rules cancels timers, drains delayed messages, and optionally cancels them during shutdown.

State and persistence behavior: all rule, statistic, timer, delayed-message, and daemon state is volatile kernel memory. Drop and delay counters persist until reset/delete/module shutdown. Delay rules hold messages on in-memory lists and use `msg_ev.hdr_data` as `msg_delay_send`. The delay daemon state (`delay_dd`) persists while at least one rule exists and is stopped when the last delay rule is removed.

Dependencies/integration points: integrates with `the_lnet` rule lists, LNet net locks, message parser/finalizer/drop helpers, `lnet_ni_send()`, `lnet_parse_local()`, `lnet_parse_forward_locked()`, `lnet_ni_recv()`, health handling in `lib-msg.c`, generic netlink fault rule collection, legacy ioctl control, timers, wait queues, kthreads, and random number helpers.

Risks: `lnet_drop_rule_del(NULL, NULL)` relies on `LNET_NID_IS_ANY()` accepting NULL-like inputs through macro behavior; if that assumption changes, shutdown cleanup can break. Delay rules keep live `struct lnet_msg` objects out of normal flow; incorrect refcount/timer/list handling can leak, double-process, or finalize messages under the wrong lock. Time/rate scheduling uses random values below configured intervals/rates, so zero validation is critical. Health-error matching intentionally rejects normal drops when a health mask exists and rejects health callers when no mask exists; tests must distinguish both lanes. Removing all delay rules shuts the daemon through wait queues and can block if state flags are mishandled.

Test signals: add/delete/list/reset drop and delay rules through both ioctl and netlink collection, validate rate-vs-interval exclusivity and delay latency checks, match ANY NID and network wildcard NIDs, portal filtering only for PUT/GET, drop-all/random/rate/time schedules, health-error mask selection and stats, delayed send replay, delayed local receive replay, delayed routed receive credit outcomes, cancellation on shutdown returning `-ECANCELED`, timer rescheduling for later delayed messages, daemon start/stop on first/last rule, and final `lnet_fault_fini()` empty-list assertions.

# sources/distributed-fs/lustre-release/lnet/lnet/nidstrings.c

Purpose: implements LNet NID, process ID, network, address-range, and NID-list string parsing/printing/matching. It supports legacy 32-bit NIDs, larger `struct lnet_nid` addresses, IPv4/IPv6 CIDR masks, bracketed numeric ranges with strides, wildcard address lists, and LND type/name/module mappings.

Important APIs/types/functions: temporary string buffers are managed by `libcfs_next_nidstring()`. Range parsing uses `struct cfs_range_expr`, `struct cfs_expr_list`, `cfs_expr_list_parse()`, `cfs_expr_list_match()`, `cfs_expr_list_values()`, and free helpers. NID-list parsing uses `struct nidrange`, `struct addrrange`, `struct nidmask`, `cfs_parse_nidlist()`, `cfs_match_nid()`, `cfs_print_nidlist()`, `cfs_nidmask_get_length()`, and `cfs_nidmask_get_base_nidstr()`. IP/numeric address helpers parse/print/match IPv4, IPv6, and decimal/hex numeric addresses. `libcfs_netstrfns[]` maps LND types (`lo`, `tcp`, `o2ib`, `gni`, `gip`, `ptlf`, `kfi`, `efa`, `bxi3f`) to parser/printer/matcher functions and module names. Public conversion APIs include `libcfs_isknown_lnd()`, `libcfs_lnd2modname()`, `libcfs_str2lnd()`, `libcfs_lnd2str_r()`, `libcfs_net2str_r()`, `libcfs_nid2str_r()`, `libcfs_nidstr_r()`, `libcfs_str2net()`, `libcfs_str2nid()`, `libcfs_strnid()`, `libcfs_id2str()`, `libcfs_idstr()`, `libcfs_strid()`, `libcfs_str2anynid()`, and `libcfs_stranynid()`.

Control flow: expression parsing duplicates input, accepts either a single value/range or a bracketed comma list, and builds linked range expressions. NID-list parsing splits tokens on spaces, splits each token into address range and network at `@`, resolves or creates a network range, then parses either wildcard, CIDR/IP mask, IPv4 component ranges, or numeric address ranges through the network's function table. Matching checks LND type and net number first, then wildcard, CIDR masks, then address-range lists. Printing reverses these structures into canonical strings. NID conversions split at `@`, default missing network to `tcp`, parse network number suffixes, and build either legacy `lnet_nid_t` or full `struct lnet_nid`.

State and persistence behavior: parser outputs are caller-owned linked structures that persist until `cfs_free_nidlist()` or `cfs_expr_list_free()` is called. Temporary string APIs use a global ring of `LNET_NIDSTR_COUNT` buffers protected only for allocation; returned strings are intentionally volatile under high concurrency. LND metadata is static. No disk state exists.

Dependencies/integration points: depends on Linux RPC address parse/print helpers, inet mask helpers, endian conversion, libcfs allocation/list/logging helpers, LNet NID/net macros and UAPI names, LND module loading logic through module names, config parsing code, route/fault/debug output, and peer/match code that compares NID strings or compiled NID lists.

Risks: `libcfs_namenum2netstrfns()` matches by prefix, so LND names must remain unambiguous (`gni` before `gip` is safe because `gip` does not match `gni`, but future prefixes can break parsing). The temporary string ring is documented as racey; callers must not retain returned pointers long term. `libcfs_strid()` uses `strscpy(pid, str, tmp - str)`, which treats the third argument as destination size and can truncate unexpectedly if PID substrings approach buffer limits. Full long-address matching in `cfs_match_nid_net()` has a FIXME and currently coerces through NID4 address extraction. CIDR parsing treats IPv6 without prefix as `/128` but IPv4 requires explicit prefix for netmask form.

Test signals: parse/print/match single numbers, ranges, strides, wildcard ranges, IPv4 component lists, IPv4 and IPv6 CIDR masks, multiple space-separated NID ranges, invalid empty tokens and malformed `@`, net number suffix parsing, default `tcp` network for NIDs without `@`, all known LND string/module mappings, legacy and full NID round trips, ANY NID/string variants (`*`, `<?>`), process ID strings with user flag and `LNET_PID_ANY`, expression value expansion max enforcement, volatile string buffer wrap behavior under concurrency, and the long-address FIXME path for IPv6/non-NID4 matching.
