## Chunk Scope

This chunk is the opening portion of SQLite's generated command-line shell amalgamation. The file header states that `shell.c` is generated by SQLite's `tool/mkshellc.tcl` from `src/shell.c.in` plus included extension sources, so local edits should normally be made upstream in the canonical SQLite sources and regenerated rather than patched directly here.

Lines 1-8933 cover platform setup, shell-wide globals, prompt/input helpers, formatted UTF-8 output helpers, and many built-in extension modules that the shell registers later: memory/page-cache tracing, SHA3/SHA1 hashing, `uint` and `decimal` collations/functions, percentile window aggregates, base64/base85 codecs, IEEE754 inspection helpers, `generate_series`, `regexp`, and most of `fileio`/`fsdir`. The chunk ends inside `fsdirBestIndex()`, so fileio registration and any subsequent shell-level integration continue in later chunks.

## Purpose And Responsibilities

The code in this range provides the support library that makes the SQLite shell portable and feature-rich before the main command interpreter is fully defined:

- Establishes build-time compatibility macros for MSVC, WinRT, VxWorks, WASI, readline/editline/linenoise, large files, and browser fiddle builds.
- Wraps standard I/O as `sqlite3_fopen()`, `sqlite3_popen()`, `sqlite3_fgets()`, `sqlite3_fputs()`, `sqlite3_fprintf()`, and `sqlite3_fsetmode()` so Windows console and filesystem paths can use UTF-8.
- Defines shell global state used across later command processing: timers, interactivity flags, prompts, `globalDb`, interrupt state, program name, and dynamic continuation prompt state.
- Implements reusable shell helpers for UTF-8 display width, numeric parsing, line input, SQL identifier quoting, schema rewriting, and C-library float conversion test functions.
- Embeds loadable-extension code directly into the shell so common SQLite shell builds expose diagnostic and utility SQL functions without requiring external shared libraries.
- Adds virtual tables/table-valued functions (`generate_series`, `fsdir`) that integrate with SQLite's query planner through `sqlite3_module` callbacks.

## Important APIs, Types, And Functions

### Platform and shell support

- `sqlite3_stdio` wrappers:
  - Non-Windows builds map directly to C stdio.
  - Windows builds convert UTF-8 paths/modes to UTF-16 for `_wfopen()` and `_wpopen()`, read console input as wide text, and write console output as UTF-16 or simulated binary/text mode.
  - `simBinaryStdout` and `simBinaryOther` remember simulated binary mode for streams where Unicode console output still needs special handling.
- Timer support:
  - Unix uses `getrusage()` plus `sqlite3_vfs` wall-clock time.
  - Windows dynamically resolves `GetProcessTimes()` and stores `HANDLE`/`FILETIME` snapshots.
  - Public macros in this chunk are `BEGIN_TIMER`, `END_TIMER(X)`, and `HAS_TIMER`.
- Global shell flags:
  - `bail_on_error`, `stdin_is_interactive`, `stdout_is_console`, `globalDb`, `seenInterrupt`, `Argv0`, `mainPrompt`, and `continuePrompt`.
- Prompt scanner support:
  - `DynaPrompt` tracks open lexemes and parenthesis nesting for continuation prompts.
  - `trackParenLevel()`, `setLexemeOpen()`, and `dynamicContinuePrompt()` produce context-sensitive prompts when `SQLITE_OMIT_DYNAPROMPT` is not set.
- Input/display helpers:
  - `local_getline()` grows a reusable heap buffer and strips `\n`/`\r`.
  - `one_input_line()` selects file input, local stdin input, or readline-like input and handles false EOF caused by interrupts.
  - `cli_wcwidth()`, `decodeUtf8()`, `isVt100()`, and `utf8_width_print()` support aligned UTF-8 output while preserving VT100 escape sequences.
  - `integerValue()` accepts decimal, hex, and size suffixes such as `KiB`, `MB`, and `G`.
  - `ShellText` plus `appendText()` builds dynamically quoted SQL fragments.
  - `quoteChar()` uses `sqlite3_keyword_check()` to decide whether identifiers need quoting.
  - `shellFakeSchema()` queries `PRAGMA table_info` to synthesize a display schema for virtual tables/table-valued functions.

### Diagnostic allocators

- `sqlite3MemTraceActivate()` / `sqlite3MemTraceDeactivate()` wrap `SQLITE_CONFIG_MALLOC` with `memtraceMalloc()`, `memtraceFree()`, and `memtraceRealloc()` logging calls.
- `sqlite3PcacheTraceActivate()` / `sqlite3PcacheTraceDeactivate()` wrap `SQLITE_CONFIG_PCACHE2` and trace all page-cache lifecycle methods through `pcachetrace*()` callbacks.
- Both mechanisms store the original method table globally and must be activated before SQLite initialization/configuration is frozen.

### Hashing extensions

- SHA3:
  - `SHA3Context` stores Keccak state, rate, loaded byte count, endian mask, and output size.
  - `KeccakF1600Step()`, `SHA3Init()`, `SHA3Update()`, and `SHA3Final()` implement the SHA3 engine.
  - `sha3Func()`, `sha3AggStep()`, `sha3AggFinal()`, and `sha3QueryFunc()` expose `sha3`, `sha3_agg`, and `sha3_query`.
  - `sha3_query` rejects non-read-only statements through `sqlite3_stmt_readonly()`.
- SHA1:
  - `SHA1Context`, `SHA1Transform()`, `hash_init()`, `hash_step()`, and `hash_finish()` implement the digest engine.
  - `sha1Func()` returns hex or binary output depending on `sqlite3_user_data()`.
  - `sha1QueryFunc()` hashes read-only query text and row values with type markers.

### Collations and decimal math

- `uintCollFunc()` compares digit runs numerically without converting to fixed-width integers, avoiding overflow for long embedded integer strings.
- `Decimal` represents arbitrary-precision base-10 numbers as sign, null/OOM flags, digit count, fractional digit count, and a digit array.
- Decimal constructors and converters:
  - `decimalNewFromText()` parses signs, decimal points, leading zeros, and scientific notation.
  - `decimal_new()` accepts SQLite text/integer directly, floats via `decimalFromDouble()`, and 8-byte blobs as binary64.
  - `decimal_result()` and `decimal_result_sci()` render fixed and scientific notation.
- Arithmetic and comparisons:
  - `decimal_cmp()`, `decimal_expand()`, `decimal_add()`, `decimalMul()`, `decimalPow2()`, and `decimalFromDouble()`.
  - SQL functions include `decimal`, `decimal_exp`, `decimal_cmp`, `decimal_add`, `decimal_sub`, `decimal_mul`, `decimal_pow2`, plus the `decimal_sum` window aggregate and `decimal` collation.

### Percentile functions

- `Percentile` tracks allocated/used slots, sorted state, whether to keep the array sorted for window use, a validated percentile fraction, and the double array.
- `PercentileFunc` describes `median`, `percentile`, `percentile_cont`, and `percentile_disc`.
- `percentStep()` validates P consistency, P range, numeric Y values, and infinity handling, then appends or sorted-inserts values.
- `percentInverse()` removes values for sliding windows and switches to sorted maintenance.
- `percentCompute()` sorts if needed and computes continuous interpolation or discrete selection.
- Registered via `sqlite3_create_window_function()` with `SQLITE_SELFORDER1`.

### Encoding extensions

- `base64()` converts blobs to RFC 4648-style base64 text with line wrapping and text back to blobs. It enforces `SQLITE_LIMIT_LENGTH` before allocating.
- `base85()` converts blobs to a custom base85 representation and back. `OMIT_BASE85_CHECKER` is defined in this amalgamation slice, so `is_base85()` is omitted here.
- Both codecs use lookup tables/macros and return SQL errors for unsupported input types or oversize output.

### IEEE754 helpers

- `ieee754func()` exposes binary64 decomposition and construction:
  - One argument returns `ieee754(mantissa,exponent)` or just mantissa/exponent based on `sqlite3_user_data()`.
  - Two arguments construct a double from mantissa and exponent with bounded exponent handling.
- `ieee754func_to_blob()` and `ieee754func_from_blob()` convert between big-endian 8-byte blobs and doubles.
- `ieee754inc()` increments the raw binary64 bit pattern by an integer quantum.

### `generate_series` virtual table

- `SequenceSpec` stores original and effective start/stop/step, current/max sequence indexes, current value, EOF state, and reverse-generation state.
- `genSeqMember()`, `setupSequence()`, and `progressSequence()` generate signed 64-bit sequences while carefully avoiding undefined signed overflow.
- `series_cursor` embeds `sqlite3_vtab_cursor` and `SequenceSpec`.
- `seriesConnect()` declares `CREATE TABLE x(value,start hidden,stop hidden,step hidden)` and configures the vtab as innocuous.
- `seriesBestIndex()` builds an `idxNum` bitmask for constraints on hidden args, rowid/value ranges, `LIMIT`, `OFFSET`, and ordering. It requires a start/value constraint unless `ZERO_ARGUMENT_GENERATE_SERIES` is defined, rejects unusable input constraints, sets argv order, cost, rows, and order consumption.
- `seriesFilter()` applies hidden column constraints, value bounds, float-to-integer edge handling, limit/offset, NULL constraint detection, and reverse ordering before calling `setupSequence()`.
- `seriesModule` is eponymous-only (`xCreate == NULL`) and read-only.

### `regexp` extension

- Implements a compact UTF-8 NFA engine with opcodes including match, any, anystar, fork, goto, accept, character class include/exclude, word/digit/space classes, boundary, and start anchor.
- Types:
  - `ReInput` reads UTF-8 characters.
  - `ReStateSet` tracks active NFA states.
  - `ReCompiled` stores input, error text, opcode/argument arrays, case mode, initial literal prefix, and allocation state.
- `re_compile()` parses regex text into bytecode, adds an implicit leading `.*` unless anchored, and computes a prefix optimization in `zInit`.
- `re_match()` executes the NFA in O(pattern * input) time and uses stack storage for small state sets, heap for large ones.
- `re_sql_func()` caches compiled regexes with `sqlite3_get_auxdata()`/`sqlite3_set_auxdata()`.
- `sqlite3_regexp_init()` registers `regexp` and case-insensitive `regexpi`; debug builds also register `regexp_bytecode`.

### `fileio` and `fsdir` partial implementation

- File functions in this chunk:
  - `readFileContents()` reads a full file into a blob subject to `SQLITE_LIMIT_LENGTH`.
  - `readfileFunc()` exposes `readfile(X)`.
  - `writeFile()` creates/writes regular files, directories, and on Unix symlinks, applies mode and optional mtime.
  - `writefileFunc()` exposes `writefile(FILE,DATA[,MODE[,MTIME]])`, creates missing parent directories via `makeDirectory()`, and reports richer errors when optional arguments are present.
  - `lsModeFunc()` renders `stat.st_mode` as `ls -l`-style mode text.
- Portability:
  - Windows-specific `fileio_chmod()`, `fileio_mkdir()`, `fileTimeToUnixTime()`, `statTimesToUtc()`, and UTF-16 path conversion normalize UTF-8 path operations and timestamps.
  - Unix paths use `stat`, `lstat`, `utimes`, `readlink`, and `symlink`.
- `fsdir` virtual table:
  - Schema is `(name,mode,mtime,data,path HIDDEN,dir HIDDEN)`.
  - `fsdir_cursor` keeps a recursive directory stack, base path offset, current `stat` buffer, current path, and rowid.
  - `fsdirNext()` performs depth-first traversal, skips `.` and `..`, stats entries with `fileLinkStat()`, and descends into directories.
  - `fsdirColumn()` returns relative names, modes, mtimes, directory NULL data, symlink target text on Unix, or regular file blobs.
  - `fsdirFilter()` requires a non-NULL path argument and optionally joins it to a base directory argument.
  - `fsdirBestIndex()` is partially visible in this chunk. It discovers usable equality constraints for hidden `path` and `dir`, rejects plans with unusable inputs, requires `path`, and begins assigning argv indexes/costs. The function body continues beyond this chunk.

## Control Flow Notes

- Shell startup code in later chunks will use these helpers after parsing command-line options and opening `globalDb`.
- Extension initialization functions follow the SQLite loadable-extension pattern: `SQLITE_EXTENSION_INIT2(pApi)`, then a sequence of `sqlite3_create_function()`, `sqlite3_create_window_function()`, `sqlite3_create_collation()`, or `sqlite3_create_module()` calls.
- Query-hashing functions compile SQL in a loop using the tail pointer returned by `sqlite3_prepare_v2()`, reject mutating statements, step all rows, encode row/value type markers, and finalize each statement before continuing.
- Virtual table control flow is standard SQLite:
  - `xConnect` declares schema and allocates the vtab object.
  - `xBestIndex` maps constraints to bitmasks/argv positions and planner costs.
  - `xOpen` allocates a cursor.
  - `xFilter` initializes cursor state from constraints.
  - `xNext`, `xColumn`, `xRowid`, and `xEof` expose row iteration.
  - `xClose` and `xDisconnect` free cursor/table state.
- Aggregate/window functions keep state in `sqlite3_aggregate_context()` and free owned buffers in finalizers.

## Risks And Edge Cases

- `shell.c` is generated; direct local patches risk being overwritten or diverging from upstream SQLite.
- Windows console I/O is subtle: mode switching, simulated binary behavior, and UTF-8/UTF-16 conversions can affect redirected output, non-MS runtimes, and newline translation.
- `decodeUtf8()` in the shell display helper appears to use `z[4]` while decoding a four-byte sequence; this is in generated upstream code and should be treated carefully before any local change. The separate regexp UTF-8 decoder uses a different implementation.
- `local_getline()` exits the process on OOM through `shell_check_oom()`, while many extension functions report SQL errors instead; callers must account for mixed fatal/nonfatal OOM behavior.
- `integerValue()` does not report malformed suffixes; unmatched trailing text leaves the parsed numeric prefix value.
- Hash query functions execute caller-provided read-only SQL. They reject non-read-only statements but still may be expensive or observe database state.
- SHA1/SHA3 encode numeric values using raw host double/int bit copies plus explicit byte emission; cross-platform determinism depends on IEEE binary64 and two's complement assumptions already common in SQLite targets.
- Decimal math prioritizes correctness/simplicity over performance; very large inputs or exponent expansion can allocate large digit arrays. `decimalPow2()` caps exponent range to `[-20000,20000]`.
- Percentile functions accumulate all non-NULL numeric inputs in memory and sort them; large groups/windows can consume significant RAM. Window inverse handling assumes numeric/infinity validation was done in the step path.
- Base64/base85 buffer sizing and decode len estimates are bounded by SQLite's length limit, but malformed text is treated permissively in places by skipping non-digits/delimiters.
- `generate_series` contains extensive overflow avoidance but still produces enormous scans when boundaries are missing or wide; planner cost tries to discourage bad join order. Compile-time `ZERO_ARGUMENT_GENERATE_SERIES` changes required-argument behavior.
- `regexp` supports only a subset of POSIX/Perl-like syntax and rejects POSIX character classes. `{m,n}` expansion can grow bytecode size.
- `readfile`, `writefile`, and `fsdir` expose filesystem access from SQL. Registration flags such as `SQLITE_DIRECTONLY` and virtual table direct-only settings reduce attack surface, but host filesystem permissions and shell use remain security-sensitive.
- `fsdirNext()` sets an error message using `pCur->zPath` immediately after transferring it to `pLvl->zDir` and nulling `pCur->zPath`; that path may be lost in the error string if `opendir()` fails. This is visible in this chunk and should be checked against upstream behavior before patching.
