## Scope And Purpose

This chunk is the first 4,820 lines of `pvr_rogue_cr_defs.h`, an autogenerated register-definition header for Imagination Rogue GPU control registers. It does not define executable C logic; it exposes the register offsets, full-register masks, field shifts, clear masks, enum-like field values, enable bits, repeat counts, and alignment metadata that the rest of the PowerVR DRM driver uses to perform MMIO reads and writes safely.

The visible chunk covers the core bring-up and runtime-control register map: indirect register-window selectors, clock gating control and status, core identity/revision fields, soft reset registers, global event status/clear bits, timer and idle/status registers, VDM/CDM context-store descriptors, MIPS/Meta/RISC-V firmware control windows, MTS scheduling, ISP render controls, BIF/MMU page-table and fault registers, scratch registers for global and per-OS state, firmware-core address remapping and watchdog/DMI stubs, SLC control and status, checksum/signature counters, generic performance counters, AXI ACE-Lite coherency configuration, power estimate result, and the start of per-block performance counter selection blocks through `ROGUE_CR_USC_PERF_SELECT0`.

Because the file is generated, its purpose is contractual rather than algorithmic. The macro names and values are the ABI between the driver and the hardware/firmware register layout. A single incorrect offset, mask, or alignment constant can turn an otherwise correct driver operation into writes to reserved bits, invalid DMA page-table base programming, broken firmware boot, missed interrupts, or misreported GPU faults.

## Macro API Shape

The header exports plain preprocessor macros only. The naming scheme is highly regular:

- `ROGUE_CR_<REGISTER>`: MMIO register byte offset, usually 32-bit aligned and often spaced 8 bytes apart for 64-bit registers.
- `ROGUE_CR_<REGISTER>_MASKFULL`: full valid-bit mask for the default hardware variant.
- `ROGUE_CR_<REGISTER>__<FEATURE>__MASKFULL`: variant-specific masks, for example `__PBE2_XE__`, `__S7_TOP__`, `__ROGUEXE__`, `__SIGNALS__`, `__TEMPSIZE8__`, and `__XE_MEM__`.
- `ROGUE_CR_<REGISTER>_<FIELD>_SHIFT`: field shift used when packing or extracting a value.
- `ROGUE_CR_<REGISTER>_<FIELD>_CLRMSK`: mask with the field cleared. Driver code commonly combines `value & CLRMSK` or `~CLRMSK` with shifted values.
- `ROGUE_CR_<REGISTER>_<FIELD>_EN`: single-bit enable value for boolean fields.
- `ROGUE_CR_<REGISTER>_<FIELD>_<ENUM>`: pre-shifted value for enumerated fields such as clock `OFF/ON/AUTO`, render modes, MTS priorities, DMs, page-region sizes, or SLC address-decode modes.
- `ROGUE_CR_<REGISTER>_<FIELD>_ALIGNSHIFT` and `_ALIGNSIZE`: required address/size alignment for encoded physical or device addresses.
- `ROGUE_CR_<GROUP>_REPEATCOUNT`: number of repeated hardware register instances where the generator emits a first register and, for many groups, all explicit numbered offsets.

The chunk starts with `ROGUE_CR_DEFS_REVISION 1`, which downstream code can use to detect the generated register schema revision.

## Important Register Families

### Indirect Windows

The first definitions provide indirect address selectors for rasterisation, PBE, TPU, USC, Blackpearl, Texas, and BX/TU performance/control windows. These registers use compact low-bit address fields with `ADDRESS_CLRMSK` values such as `0xFFFFFFF0`, `0xFFFFFFF8`, or `0xFFFFFFFC`, encoding the alignment of the indirect target. They are integration points for later per-block register blocks that are not always mapped directly in the top-level aperture.

### Clocks, Identity, And Resets

`ROGUE_CR_CLK_CTRL` and `ROGUE_CR_CLK_STATUS` describe the main clock gating controls for BIF/TEXAS, IPP, FBC/FBDC, FB_TLCACHE, USCS, PBE, MCU L1/L0, CDM, sidekick, BIF, TPU, USC, TLA, SLC, UVS, PDS, VDM, PM, GPP, TE, TSP, and ISP. Control fields use `OFF`, `ON`, and `AUTO` values, while status fields report `GATED` or `RUNNING`. Variant masks (`__PBE2_XE__`, `__S7_TOP__`) restrict which bits exist on specific GPU families.

`ROGUE_CR_CORE_ID__PBVNC`, `ROGUE_CR_CORE_ID`, `ROGUE_CR_CORE_REVISION`, `ROGUE_CR_DESIGNER_REV_FIELD1/2`, and `ROGUE_CR_CHANGESET_NUMBER` provide hardware identity, branch/version/config, scalable-unit count, and revision metadata. These are read-only integration points for feature detection and logging.

`ROGUE_CR_CLK_XTPLUS_CTRL` and `_STATUS` extend clock control to XTPLUS-style domains such as TDM, ASTC, IPF, compute, pixel, vertex, USCPS, PDS shared, BIF Blackpearl, USC shared, and geometry.

`ROGUE_CR_SOFT_RESET` and `ROGUE_CR_SOFT_RESET2` are the central reset masks. They include core, phantom, tiling, TE/VCE/VBS, DPX, FBA, FB CDC, SH, VRDM, MCU FBTC, IPP, BIF/TEXAS, Tornado, Dust cores A-H, MMU, BIF1, Garten/CPU, RASCAL, FB_TLCACHE, SLC, TLA, UVS, TE, GPP, FBDC/FBC, PM, PBE, USC shared, MCU L1, BIF, CDM, VDM, TESS, PDS, ISP, TSP, SYSARB, TPU/MCU, TPU, USC, and newer XTPLUS blocks. `pvr_rogue_defs.h` builds composite reset masks from these bits, and `pvr_fw_startstop.c` writes them during firmware reset/boot sequences.

### Events, Timers, Idle, And Context Store

`ROGUE_CR_EVENT_STATUS` and `ROGUE_CR_EVENT_CLEAR` define the shared GPU interrupt/event bitmap. Visible events include TDM fence and buffer stalls, compute signal failure, DPX/RPM/PM out-of-memory, DPX and main MMU page faults, FBA/RDM finished signals, safety/slave request aliases, TDM context-store finished, SHG/SPFILTER updates, compute buffer stalls, USC triggers, ZLS finished, GPIO, power complete/abort, TA terminate/finished, ISP end macrotile, pixel backend end render, compute/kernel finished, and TLA complete. The local driver reads `ROGUE_CR_EVENT_STATUS` in `pvr_device.c` to detect the `SAFETY` event and clear paths use the mirrored `EVENT_CLEAR` definitions.

`ROGUE_CR_TIMER`, `ROGUE_CR_TLA_STATUS`, `ROGUE_CR_SIDEKICK_IDLE`, and `ROGUE_CR_MARS_IDLE` provide runtime status counters and idle bits. `ROGUE_CR_PM_PARTIAL_RENDER_ENABLE` exposes a one-bit enable for partial render.

VDM context store/resume registers (`ROGUE_CR_VDM_CONTEXT_STORE_STATUS`, `STORE_TASK0/1/2`, `RESUME_TASK0/1/2`) and CDM context-store/load/terminate PDS registers provide packed PDS code/data addresses, stream-out state, resume-needed/complete bits, target/fence flags, and PDS/USC/common/temp/data sizes. Address fields are explicitly 16-byte aligned. These definitions support firmware or driver flows that save and restore in-flight vertex/compute work around preemption or reset.

### Firmware CPU Wrappers

The chunk includes both legacy MIPS/Meta firmware controls and newer firmware-core/RISC-V controls.

MIPS wrapper definitions cover `ROGUE_CR_MIPS_WRAPPER_CONFIG`, five remap entries (`MIPS_ADDR_REMAP1..5_CONFIG1/2`), unmapped-address status/clear, range-config readback, IRQ/NMI enable/status/clear, debug config, exception status, outstanding request status, and XPU broadcast masking. Remap config fields encode input/output base addresses, OS ID, trusted bit, region size, and enable. `pvr_fw_mips.c` and start/stop code use these families to route firmware memory and configure wrapper behavior.

Meta slave-port definitions (`ROGUE_CR_META_SP_MSLVDATAX/T`, `MSLVCTRL0/1`, `MSLVHANDSHKE`, thread kick and kick interrupt registers, reset, IRQ status/enable/level) provide the host-visible access path to a Meta firmware core. The fields include address, auto-increment, read request, deferred transaction metadata, interlocks, idle/ready state, thread selection, transaction size, and thread kick masks.

Firmware-core address remap definitions (`ROGUE_CR_FWCORE_ADDR_REMAP_CONFIG0..15`) are the RISC-V-era equivalent for code/data windows. Each entry encodes trusted, load/store enable, fetch enable, size, catalog base, and 4 KiB-aligned device virtual address. `pvr_rogue_riscv.h` computes the indexed offset from `ROGUE_CR_FWCORE_ADDR_REMAP_CONFIG0`, and `pvr_fw_riscv.c` packs code and data remap entries using these shift and enable macros.

`ROGUE_CR_FWCORE_BOOT`, reset/NMI address/event registers, firmware-core memory fault status/request, MMU invalidation/status/read counters, wrapper fence, firmware memory catalog bases, watchdog reset/control/count, and DMI/debug placeholders are also in this chunk. The DMI registers mostly have `MASKFULL 0`, signaling reserved or opaque debug access where this driver should not attempt field-level writes.

### MTS Scheduling And Interrupt Routing

`ROGUE_CR_MTS_SCHEDULE` plus `SCHEDULE1..7` repeat the same packed command format at per-OS/virtualization offsets. Fields select host source, priority `PRT0..PRT3`, background vs interrupt context, counted vs non-counted task, and data master `DM0..DM7` or `DM_ALL`. `pvr_fw.c` writes `ROGUE_CR_MTS_SCHEDULE` to kick firmware work, and `pvr_ccb.c` uses `ROGUE_CR_MTS_SCHEDULE_DM_CLRMSK` when preparing kick masks.

MTS context association/status registers map background and interrupt context threads to DMs, configure Garten wrapper fence behavior, enable per-DM interrupts, report active/scheduled DMs, expose counted schedule counters, and provide per-OS IRQ event status/clear registers. `pvr_fw_meta.c`, `pvr_fw_mips.c`, and `pvr_fw_riscv.c` all program `ROGUE_CR_MTS_GARTEN_WRAPPER_CONFIG` to select idle control and fence settings.

### ISP, BIF, MMU, And Tiling

`ROGUE_CR_ISP_RENDER` and `ROGUE_CR_ISP_CTL` define ISP render direction and mode (`NORM`, `FAST_2D`, `FAST_SCALE`), protected/unprotected tile processing, resume/EOMT behavior, sample-position mode, pipe count up to sixteen pipes, tile-pairing, valid ID, and upass start. `ROGUE_CR_ISP_STATUS`, XTP resume/store repeat counts, and first XTP register definitions provide tile coordinates and active/EOR/last-tile state.

The BIF/MMU block defines eight `ROGUE_CR_BIF_CAT_BASE<n>` catalog base registers with 4 KiB alignment, a `BIF_CAT_BASE_INDEX` register mapping workloads (TA, pixel, CDM, TDM, TLA, host, ray/RVTX) to catalog bases, and PM catalog bases for VCE/TE/ALIST with init-page, wrap, and valid bits. `pvr_rogue_defs.h` derives indexed catalog-base offsets from these definitions, and `pvr_fw_startstop.c` uses the address alignment macros to program page catalog addresses.

MMU control includes entry status, entry enable/pending, TLB/PC/PD/PT invalidation, MMU pause controls, queue bypass/prefetch controls, two fault banks with MMU and request status, aggregate MMU busy/paused/stalled state, read counters, PM-specific read counters, generic fault-read address, and Texas-specific BIF fault registers. Fault request status fields include read/write direction, tag sideband, tag ID, and 16-byte-aligned fault address. These are the primary macros for decoding GPU page faults and for synchronizing MMU invalidation during VM changes.

`ROGUE_CR_BIF_TILING_CFG0..7` encode eight tiling windows with enable, X stride, and 4 KiB-aligned min/max addresses. Any driver code that sets tiling must preserve these alignment and range semantics.

### Scratch, SPFilter, SLC, Coherency, And Counters

General scratch registers `ROGUE_CR_SCRATCH0..15` expose 32-bit writable data. Per-OS scratch registers `ROGUE_CR_OS0_SCRATCH*` through `ROGUE_CR_OS7_SCRATCH*` appear at large per-OS offset strides (`0x1A80`, `0x11A80`, ... `0x71A80`), providing virtualization or multi-OS mailbox storage. The repeat-count comments say two repeats, but four explicit scratch registers are emitted for each OS family; this mismatch is worth preserving in merge-time analysis.

SPFilter signal descriptor registers define a descriptor size and a 16-byte-aligned minimum address.

SLC control definitions include `ROGUE_CR_SLC_CTRL_MISC` for scramble bits, lazy writeback override, address decode mode (`INTERLEAVED_64_BYTE`, `INTERLEAVED_128_BYTE`, `SIMPLE_HASH1/2`, `PVR_HASH1`, `PVR_HASH2_SCRAMBLE`), pause, response priority, line-use limit, PSG hazard checking, and burst-combiner bypass. `pvr_fw_startstop.c` writes this register during initialization, preserving hazard-check state, selecting PVR hash mode, and enabling special workarounds.

`ROGUE_CR_SLC_CTRL_FLUSH_INVAL` provides lazy/global/per-DM flush-invalidate control bits. `ROGUE_CR_SLC_STATUS0/1/2`, `ROGUE_CR_SLC_IDLE`, `ROGUE_CR_SLC_CTRL_BYPASS`, `ROGUE_CR_SLC_CTRL_MISC2`, and `ROGUE_CR_SLC_CROSSBAR_LOAD_BALANCE` expose pending flush/invalidate state, read counters, pause state, idle sub-blocks, and a large set of request/DM cache-bypass bits. The bypass register has an `__XE_MEM__` mask with additional high request-source bits that must not be assumed present on all hardware.

Checksum/signature registers capture USC UVS/UVB, PPP, TE, VCE, ISP PDS/TPF, TFPU, PBE, PDS DOUTM STM, IFPU ISP, and PPP clip values. Generic performance phase/cycle/stall/spinup counters follow, then `ROGUE_CR_AXI_ACE_LITE_CONFIGURATION` exposes AXI coherency/cache/domain attributes and an OSID security field. `ROGUE_CR_POWER_ESTIMATE_RESULT` exposes a 32-bit power estimate.

The chunk ends in performance counter control/select definitions for TA, rasterisation, hub BIF PM cache, TPU MCU L0, and the start of USC. Each block uses the same structure: a control register with clear bits and enable, one or more select registers with batch min/max, mode, group select, and bit select, selected-bits readback, and counter registers.

## Control Flow And Runtime Behavior

There is no local control flow in this header. Runtime behavior emerges when other driver code combines these macros with MMIO helpers such as `pvr_cr_read32`, `pvr_cr_read64`, `pvr_cr_write32`, and `pvr_cr_write64`.

Typical patterns visible in dependent files are:

- Read-modify-write or direct writes to control registers using `MASKFULL`, `CLRMSK`, `SHIFT`, and enum/enable constants.
- Polling status registers after writes, especially around clocks, resets, MMU/SLC invalidation, firmware boot, and idle detection.
- Packing physical/DMA addresses by shifting down by `_ALIGNSHIFT`, shifting up into the register field, and masking against `~CLRMSK`.
- Choosing variant masks based on feature bits, such as `__PBE2_XE__`, `__S7_TOP__`, or `__XE_MEM__`.
- Deriving repeated register offsets from emitted first/second offsets, as done for BIF catalog bases, FWCORE memory catalog bases, FWCORE remap entries, and MTS schedule aliases.

The state represented by these macros is hardware state: register contents, pending events, fault latches, reset/clock gates, firmware remap configuration, page-catalog pointers, SLC control bits, and performance counter accumulators. The header itself persists nothing in memory or storage.

## Risks And Edge Cases

- Autogenerated constants are easy to treat as inert, but they are high-risk ABI data. Offsets or masks are not self-validating at compile time.
- Variant-specific masks matter. Writing the default `MASKFULL` to hardware that expects `__S7_TOP__`, `__PBE2_XE__`, `__ROGUEXE__`, `__SIGNALS__`, `__TEMPSIZE8__`, or `__XE_MEM__` behavior can write reserved bits or omit live bits.
- Several field aliases share bit positions, for example event-status aliases such as `SAFETY`/`RDM_FC2_FINISHED`, `SLAVE_REQ`/`RDM_FC1_FINISHED`, and `TDM_CONTEXT_STORE_FINISHED`/`RDM_FC0_FINISHED`. Consumers must interpret bits in the context of the active core/features.
- Address fields carry strict alignment metadata. Failing to validate DMA/device addresses against `_CLRMSK` or `_ALIGNSHIFT` can silently truncate low bits and program the wrong page catalog, remap window, fault address, or PDS code/data pointer.
- Some comments say a group repeats while the emitted explicit registers look broader, notably per-OS scratch groups reporting two repeats while four OS scratch registers are present. Downstream indexed helpers should be checked against real register spacing instead of blindly trusting the comment.
- `MASKFULL 0` DMI/debug placeholder registers should be treated as opaque/reserved. Field-level writes are not supported by this generated view.
- Reset and clock masks cover many independent GPU domains. Using a broad mask in the wrong phase can reset the firmware core, MMU, SLC, or active data masters unexpectedly.
- Event clear mirrors event status. Clearing a bit usually acknowledges an interrupt source; code must avoid clearing bits before collecting diagnostic status such as fault-bank state.
- SLC bypass/flush controls can affect coherency and performance. Incorrect use can hide data corruption under cache effects or make fault/recovery flows nondeterministic.
- Performance counter select registers have repeated layouts but different block offsets. Copy/paste mistakes in consumers could select the wrong counter bank.
