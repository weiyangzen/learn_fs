## Purpose

The chunk defines the bit layout for NBIO 6.1 host-interface and PCIe configuration registers. These macros let driver code compose, update, and decode 32-bit MMIO/SMN/PCIe register values without open-coded bit positions. Although the repository path is under a Ceph client source tree, this file is AMDGPU hardware-description data for GPU NBIO/NBIF programming.

Covered register families include:

- BIFC performance counters for MMIO and DMA traffic.
- SMN master endpoint controls for zero-byte-enable reads/writes and error-response data policy.
- Self-ring/vector and GMI request arbitration controls.
- RCC PFC LTR, PME, sticky error restore, and auxiliary-power controls for AMDGFX and AMDGFXAZ blocks.
- BIF reset controls, soft reset controls, function-level reset controls, D3hot-to-D0 reset controls, and reset/power/D-state interrupt status/mask/request registers.
- BIF RAS leaf controls and IOHUB RAS interrupt steering.
- PCI configuration-space fields for endpoint device 0, PF0 instance 1, including command/status, IDs, BARs, capabilities, MSI/MSI-X, PCIe capabilities, AER, virtual channels, DPA, lane equalization, ACS, ATS, PRI/page request, PASID, TPH, multicast, LTR, ARI, and the beginning of SR-IOV control.

## Important Macro Families

`BIFC_PERF_CNTL_0`, `BIFC_PERF_CNTL_1`, `BIFC_PERF_CNT_MMIO_RD`, `BIFC_PERF_CNT_MMIO_WR`, `BIFC_PERF_CNT_DMA_RD`, and `BIFC_PERF_CNT_DMA_WR` expose performance-counter enable, reset, selector, and 32-bit count fields. The MMIO counter family begins before this chunk, so this range starts with the tail of `BIFC_PERF_CNTL_0` masks and then provides complete DMA counter control and value fields.

`NBIF_REGIF_ERRSET_CTRL` defines a policy bit for suppressing set-error behavior when dropping non-PF MMREG requests. This is a virtualization/isolation-sensitive path because non-PF register traffic may be generated by guests or auxiliary functions.

`SMN_MST_EP_CNTL3`, `SMN_MST_EP_CNTL4`, `SMN_MST_CNTL1`, and `SMN_MST_EP_CNTL5` define per-PF SMN master behavior. They cover zero-byte-enable write/read allowance for PF0-PF7 and whether error-response data is forced to all-ones for upstream, downstream, or endpoint functions.

`BIF_SELFRING_BUFFER_VID` and `BIF_SELFRING_VECTOR_CNTL` describe self-ring/doorbell-monitor interrupt routing fields: client IDs for doorbell monitor and IOHUB RAS interrupt traffic, a miscellaneous doorbell-monitor interrupt disable bit, and a timestamp-source selector.

`BIF_GMI_WRR_WEIGHT` configures weighted round-robin behavior for GMI requests. It separates realtime, normal posted, and normal non-posted request weights and has a WRR mode bit. Misprogramming can shift PCIe/NBIO traffic fairness or latency.

`RCC_PFC_AMDGFX_RCC_PFC_*` and `RCC_PFC_AMDGFXAZ_RCC_PFC_*` provide two nearly identical PFC register sets. Each includes snoop and non-snoop LTR latency value/scale/requirement fields, PME restore enable/status fields, sticky restore controls for AER-like status bits, full-width TLP header/prefix restore fields, and auxiliary-power current/detected override fields.

`HARD_RST_CTRL`, `RSMU_SOFT_RST_CTRL`, `SELF_SOFT_RST`, `BIF_GFX_DRV_VPU_RST`, `BIF_RST_MISC_CTRL`, `BIF_RST_MISC_CTRL2`, and `BIF_RST_MISC_CTRL3` define coarse reset controls for BIF, BIF PHY, IOHC, SYSHUB, SMU, display, PCIE core, PSP, audio, SDMA, IH, and related reset gating/trigger behavior. Several fields control whether reset requests propagate from one block to another or whether certain reset outputs are enabled.

`DEV0_PF0_FLR_RST_CTRL` through `DEV0_PF7_FLR_RST_CTRL` define per-physical-function FLR behavior. PF0 has the richest field set, including config reset, private reset, self reset, FLR FSM selection, function select, FLR graceful mode, FLR timeout, dummy-response status, and register-config reset masking; PF1-PF7 carry the subset needed for per-function FLR behavior.

`BIF_INST_RESET_INTR_STS`, `BIF_PF_FLR_INTR_STS`, `BIF_D3HOTD0_INTR_STS`, `BIF_POWER_INTR_STS`, `BIF_PF_DSTATE_INTR_STS`, and `BIF_PF0_VF_FLR_INTR_STS` expose reset, FLR, D3hot/D0, PME-turnoff, D-state, and VF FLR interrupt status bits. `BIF_DEV0_PF*_DSTATE_VALUE`, `DEV0_PF*_D3HOTD0_RST_CTRL`, and `BIF_PORT0_DSTATE_VALUE` encode per-PF D-state target/acknowledge values and D3hot-to-D0 reset behavior. These fields are relevant to suspend/resume, runtime power management, and reset recovery paths.

## Control Flow and State

This header has no direct control flow. The implicit hardware workflows encoded by the fields are:

1. Initialization and PCI enumeration code reads config header, capability-list, device/link, MSI/MSI-X, BAR, and power-management fields to identify exposed endpoint capabilities.
2. NBIO setup or diagnostics code enables, selects, resets, and reads BIFC performance counters for MMIO and DMA traffic.
3. Reset and recovery code observes transaction/reset/D-state/PME interrupt status, masks or unmasks those interrupt sources, and writes FLR or D3hot-to-D0 reset controls for PFs and VFs.
4. Power-management code uses LTR, PME restore, D-state, DPA, power-budget, and link-control fields to coordinate PCIe low-power behavior with NBIO state.
5. RAS and AER handling code reads error status/log fields, applies masks/severity policy, preserves or restores sticky TLP header/prefix state, and routes IOHUB RAS events to the interrupt handler.
6. Virtualization and IOMMU-facing paths rely on PF/VF FLR, ACS, ATS, PRI, PASID, ARI, SR-IOV, MSI-X, and BAR fields for isolation, address translation, interrupt delivery, and reset semantics.

Register state is stored in hardware, not in this header. Strap/configuration fields often reflect ASIC or firmware defaults and may be read-only or reset-derived. Status, interrupt, reset, performance-counter, PME, RAS, AER, and capability-control fields are live hardware state whose persistence depends on reset domain, power state, firmware action, and explicit driver writes.

## Risks

Bitfield mistakes are high impact because these constants drive direct hardware register accesses. A wrong shift or mask can reset the wrong function, mask the wrong interrupt, misreport PCIe capabilities, corrupt AER/RAS status handling, alter PCIe traffic ordering, or break SR-IOV isolation.

The reset families are especially sensitive. PF and VF FLR fields are repetitive and differ subtly between PF0, PF1-PF7, and VF0-VF15. A copy or generation error can compile cleanly while targeting the wrong function, leaving stale DMA state or a partially reset guest.

The ACS, ATS, PRI, PASID, ARI, SR-IOV, MSI-X, and BAR fields define isolation, translation, and interrupt-delivery contracts. Bad definitions or misuse can expose peer-to-peer traffic incorrectly, break IOMMU translation, lose interrupts, or mis-size VF apertures.

AER and RAS fields often use write-one-to-clear or mask/severity semantics in hardware. Treating a status field as an ordinary persistent bit can either drop evidence during error recovery or leave interrupts storming.

Power and reset controls intersect with PCIe link state. Incorrect D-state, PME, LTR, DPA, or D3hot-to-D0 reset programming can cause resume failures, link retraining surprises, or devices that appear present but do not respond correctly.
