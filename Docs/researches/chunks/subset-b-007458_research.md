## Purpose and Major Areas

The XML preserves the Hadoop HDFS 2.6.0 public compatibility contract. The covered APIs fall into several layers:

- Filesystem-facing helpers for block volume locality and extended attributes: `BlockStorageLocation`, `VolumeId`, `HdfsVolumeId`, `CacheFlag`, and `XAttr` builder/namespace types.
- HDFS client internals and public wrappers: block readers, corrupt-file iteration, DFS client configuration, hedged-read metrics, inotify streams, read statistics, HA utilities, NameNode proxy factories, remote peer creation, storage media enums, and crypto exception types.
- Public administrative/client API: `HdfsAdmin`, `HdfsDataInputStream`, `HdfsDataOutputStream`, stream sync flags, and `HdfsUtils`.
- Inotify event model: append, close, create, metadata update, rename, unlink, event-type enums, builders, and `MissingEventsException`.
- Protocol value objects for cache directives, cache pools, corrupt-file listing, encryption zones, layout versions, rolling upgrades, snapshots, datanode report/safemode/rolling-upgrade enums, and filesystem limit exceptions.
- Data transfer trust policy APIs for identifying trusted channels and whitelist-backed trust configuration.
- Protobuf RPC adapter layer and conversion helpers: server-side translators for DataNode and NameNode protocols plus the beginning of `PBHelper`, which maps between Java HDFS/domain objects and generated protobuf messages.

The package-level `org.apache.hadoop.hdfs` doc states the central filesystem model: HDFS is a distributed `FileSystem` loosely modeled after GFS, but with strictly one writer at a time and an append-only byte stream ordering guarantee.

## Important APIs and Types

### `org.apache.hadoop.fs`

`BlockStorageLocation` wraps `BlockLocation` with per-replica `VolumeId[]` data. Its constructor accepts a base `BlockLocation` plus volume IDs and may throw `IOException`; `getVolumeIds` returns the IDs corresponding to block replicas.

`VolumeId` is an opaque disk-location identifier contract. Implementations must be comparable and should implement stable `equals` and `hashCode`. `HdfsVolumeId` is the HDFS implementation backed by a byte array, comparable only on a per-DataNode basis; it exposes `compareTo`, `equals`, `hashCode`, and `toString`.

`CacheFlag` is an enum for cache directive operation semantics, passed as `EnumSet`s elsewhere. `XAttr.Builder` constructs `XAttr` instances via namespace, name, and byte-value setters; `XAttr.NameSpace` exposes the extended attribute namespace enum.

### `org.apache.hadoop.hdfs`

`BlockReader` is the low-level interface for reading one block from one DataNode. It extends `ByteBufferReadable` and exposes byte-array `read`, `skip`, `available`, `close`, `readFully`, `readAll`, locality checks (`isLocal`, `isShortCircuit`), and optional zero-copy mmap access through `getClientMmap(EnumSet)`. The docs distinguish normal reads from local and short-circuit reads, and note that `readAll` fills available data without throwing on EOF the way `readFully` does.

`CorruptFileBlockIterator` implements `RemoteIterator<Path>` for `listCorruptFileBlocks`, used by `DistributedFileSystem` and `Hdfs`. It tracks the number of DFSClient calls through `getCallsMade`, which is explicitly for debugging and tests.

`DFSClient.Conf` exposes client-side settings for legacy local reads, domain socket path, short-circuit local reads, and domain socket data traffic. `DFSClient.DFSDataInputStream` is deprecated in favor of `org.apache.hadoop.hdfs.client.HdfsDataInputStream`.

`DFSHedgedReadMetrics` holds publicly accessible `AtomicLong` counters for hedged read operations, hedged reads served in the current thread, and hedged read wins, plus increment/getter methods. This is a test and client-observability surface, called out as useful to clients such as HBase.

`DFSInotifyEventInputStream` provides single-threaded access to NameNode edit-log-derived events. It supports non-blocking `poll`, timed `poll`, blocking `take`, and `getEventsBehindEstimate`. Its methods may throw `IOException` for network/edit-log/journal issues and `MissingEventsException` when the stream has fallen behind retained edits.

`DFSInputStream.ReadStatistics` snapshots read path accounting: total, local, short-circuit, zero-copy, and remote bytes read. The documented invariant is that total bytes read is at least the specific categories, and local bytes include short-circuit bytes.

`DFSUtil.ConfiguredNNAddress` represents a configured NameNode in a cluster with nameservice ID, namenode ID, socket address, and string form. `ExtendedBlockId` is an immutable key of block ID plus block pool ID, with construction from `ExtendedBlock` and equality/hash behavior.

`HAUtil` is the major high-availability utility surface. It detects HA enablement and shared edits, resolves local/other NameNode IDs from configuration and addresses, checks standby-read test settings, detects logical URIs and failover proxy configuration, determines when logical URIs are required, parses and builds token service names for logical HA services, clones logical delegation tokens to physical NameNode addresses, resolves the current active NameNode address, obtains proxies for all NameNodes in a nameservice, and checks that at least one proxy is active.

`NameNodeProxies` centralizes client proxy creation for remote NameNode access. `createProxy` chooses HA or non-HA behavior based on whether the URI is logical; overloads thread through secure-auth fallback state. `createProxyWithLossyRetryHandler` is a test-oriented HA-only helper that drops RPC responses. `createNonHAProxy`, `getFailoverProxyProviderClass`, and `createFailoverProxyProvider` expose lower-level construction. `NameNodeProxies.ProxyAndInfo` bundles a proxy, delegation-token service, and NameNode address.

`RemotePeerFactory` abstracts creation of a connected `Peer` to a DataNode address with block token and DataNode ID, allowing socket/encrypted-stream setup to vary behind the interface.

`StorageType` is the public enum for HDFS storage media, with `DEFAULT`, `EMPTY_ARRAY`, `isTransient`, `isMovable`, `asList`, and `getMovableTypes`. The docs state that the default medium is `DISK`. `UnknownCipherSuiteException` and `UnknownCryptoProtocolVersionException` are `IOException` subclasses for unsupported crypto metadata.

### `org.apache.hadoop.hdfs.client`

`HdfsAdmin` is the preferred public administrative API over direct `DistributedFileSystem` or `DFSClient` access. It is created from a filesystem URI and `Configuration`, then supports namespace quota and space quota changes, snapshot enable/disable, cache directive add/modify/remove/list with `CacheFlag`s, cache pool add/modify/remove/list, encryption zone creation and lookup/listing, inotify stream creation, and setting storage policy. Inotify docs identify edit retention tuning keys and recommend local edit journaling to avoid shared-journal transfers.

`HdfsDataInputStream` extends `FSDataInputStream` and wraps either `DFSInputStream` or `CryptoInputStream`. It exposes the underlying stream, current DataNode, current block, already-located blocks, visible file length including an under-construction last block, and synchronized read statistics. The docs warn buffered reads can make statistics larger than bytes read through the wrapper.

`HdfsDataOutputStream` extends `FSDataOutputStream` and wraps `DFSOutputStream` or `CryptoOutputStream`. It reports current block replication, which can differ from the file replication factor while a block is under construction, and exposes `hsync(EnumSet<SyncFlag>)` for detailed sync semantics. `SyncFlag` is the associated enum.

`HdfsUtils.isHealthy(URI)` reports whether HDFS is up and not in safemode; the URI path is ignored.

### `org.apache.hadoop.hdfs.inotify`

`Event` is the abstract base for edit-log-derived inotify events. It records `EventType` and notes that reads do not necessarily produce events unless metadata such as atime changes.

Concrete events model namespace and metadata changes: `AppendEvent` for opening an existing file for append; `CloseEvent` for close after append/create, including path, file size, and timestamp; `CreateEvent` for file/directory/symlink creation or overwrite, including inode type, path, ctime, replication, owner, group, permissions, symlink target, and overwrite flag; `MetadataUpdateEvent` for atime/mtime, replication, owner/group, permissions, ACL, and xattr changes; `RenameEvent` for source/destination/timestamp; and `UnlinkEvent` for deletes.

`CreateEvent.Builder` and `MetadataUpdateEvent.Builder` provide fluent construction. `CreateEvent.INodeType`, `Event.EventType`, and `MetadataUpdateEvent.MetadataType` are enums. `MissingEventsException` carries expected and actual transaction IDs and signals a retained-edit gap.

### `org.apache.hadoop.hdfs.protocol`

Cache directive APIs model centralized HDFS cache management. `CacheDirectiveInfo` describes a path directive with ID, path, replication, pool, and expiration; its builder supports partial construction and copying. `CacheDirectiveInfo.Expiration` can be relative or absolute, has `NEVER` and `MAX_RELATIVE_EXPIRY_MS`, and converts relative values using the local clock for getter display while server-side clock determines actual expiry. `CacheDirectiveStats` and its builder report bytes/files needed, bytes/files cached, and whether the directive expired. `CacheDirectiveEntry` pairs directive info with stats.

Cache pool APIs group and govern cache directives. `CachePoolInfo` carries pool name, owner, group, permissions, byte limit, and maximum relative expiry; it validates pool info/names and documents that it is used in RPCs, serializable, and stored in the edit log. Constants include unlimited limits and relative-expiry defaults. `CachePoolStats` and builder report aggregate bytes/files needed, cached, and over-limit. `CachePoolEntry` pairs pool info with stats.

`CorruptFileBlocks` contains corrupt file path arrays plus a cookie for iterative NameNode `listCorruptFileBlocks` calls. `DatanodeInfo.AdminStates` converts admin states to/from strings. `EncryptionZone` records encryption zone ID, path, cipher suite, crypto protocol version, and key name; the ID supports batched listing. `FSConstants` is deprecated in favor of `HdfsConstants` but retained for ecosystem compatibility.

`FSLimitException.MaxDirectoryItemsExceededException` and `PathComponentTooLongException` are specialized limit exceptions with message construction and `serialVersionUID`. `HdfsConstants.DatanodeReportType`, `RollingUpgradeAction`, and `SafeModeAction` expose user-visible operation enums; rolling-upgrade actions can be parsed from strings.

`LayoutVersion.Feature`, `FeatureInfo`, and `LayoutFeature` model namespace/storage layout compatibility. The docs instruct maintainers adding layout versions to define enum constants with layout version, description, and optionally explicit ancestors or special features.

Snapshot and rolling upgrade data objects include `RollingUpgradeInfo.Bean`, `SnapshotInfo.Bean`, `SnapshotAccessControlException`, `SnapshotException`, `SnapshotDiffReport`, `SnapshotDiffReport.DiffReportEntry`, `SnapshotDiffReport.DiffType`, `SnapshottableDirectoryStatus`, and `SnapshottableDirectoryStatus.Bean`. Snapshot diffs expose root, from/to snapshot names, and a compact list of changed paths typed as create/modify/delete/rename with labels `+`, `M`, `-`, and `R`. Snapshottable directory status provides snapshot count/quota, parent path, directory status, full path, comparator by full path, and a static print helper.

### Data Transfer and `protocolPB`

`ReplaceDatanodeOnFailure.Policy` enumerates write-pipeline DataNode replacement policies. `TrustedChannelResolver` is a configurable extension point for deciding if a client or peer channel is trusted; by default channels are not trusted. `WhitelistBasedTrustedChannelResolver` adds fixed and variable whitelist files for server/client sides plus enable and cache-seconds configuration keys.

`DatanodeProtocolServerSideTranslatorPB` implements `DatanodeProtocolPB` and forwards protobuf service calls to a `DatanodeProtocol` server implementation. The visible methods cover DataNode registration, heartbeats, block reports, cache reports, block received/deleted notifications, error reports, version requests, block recovery report commits, and rolling-upgrade status. `NamenodeProtocolServerSideTranslatorPB` similarly adapts `NamenodeProtocolPB` to a `NamenodeProtocol` server, covering block listing, block keys, transaction/checkpoint IDs, edit-log rolling, error reporting, subordinate NameNode registration, checkpoint start/end, edit-log manifests, and version requests.

## Control Flow and Lifecycle

Client read flow is represented as layered contracts. `HdfsDataInputStream` delegates to `DFSInputStream` or crypto streams; `DFSInputStream.ReadStatistics` records local, remote, short-circuit, and zero-copy read paths; `BlockReader` reads individual DataNode blocks and optionally exposes mmap buffers. The control distinction between remote, local, short-circuit, and zero-copy reads is visible through API flags and statistics rather than implementation bodies in this XML.

Administrative flow starts with `HdfsAdmin` constructed for a URI and configuration. Calls go through HDFS client/NameNode RPCs to change quota, snapshots, cache pools/directives, encryption zones, inotify streams, or storage policy. Iterative list methods return `RemoteIterator`s, so large cache directive, cache pool, and encryption zone scans fetch in batches and may not represent a consistent full snapshot.

HA flow is configuration-driven. `HAUtil` detects whether a nameservice is HA, determines logical versus physical URIs, builds token services for logical URIs, clones delegation tokens to concrete NameNode addresses, creates proxies for all NameNodes when an operation must be sent to every peer, and checks active/standby state. `NameNodeProxies` is the proxy factory that selects failover-aware or direct proxy behavior.

Inotify flow is edit-log driven. `HdfsAdmin.getInotifyEventStream` creates a stream from the current point or from a caller-provided transaction ID. `DFSInotifyEventInputStream` then polls or blocks for the next event. If retained edits no longer include the needed transaction, `MissingEventsException` reports the expected and actual transaction IDs, after which clients may continue from the next available event.

Cache management flow uses value objects as RPC/edit-log payloads: clients create or modify `CacheDirectiveInfo` and `CachePoolInfo`; NameNode-side state tracks directive and pool stats; listings return entry objects that combine mutable policy information with current cache accounting.

Data transfer trust flow instantiates a `TrustedChannelResolver` from `Configuration`. The default says no channel is trusted; whitelist-backed implementations read fixed and optionally variable subnet/IP files and refresh variable whitelists according to cache-second configuration.

Protobuf RPC flow is adapter-based. Server-side translator classes receive protobuf request messages and forward to Java protocol implementations, translating checked failures into `ServiceException`. `PBHelper` is the shared conversion layer that keeps wire-format protobufs and in-memory HDFS protocol/server objects aligned.

## State and Persistence Behavior

The XML itself is a generated persistent API baseline for compatibility checks. It records not just names but behavioral compatibility indicators such as thrown exceptions, synchronization, deprecations, and Javadoc constraints.

HDFS persistent state surfaces appear in several protocol objects. Cache pools are explicitly serializable and stored in the edit log; cache directives and expirations also participate in RPC and cache-manager state. Encryption zone IDs are persistent identifiers used for batched listing. Inotify events are derived from NameNode edit logs, and retention settings determine how far behind clients can fall before `MissingEventsException`.

Filesystem state and metadata objects carry user-visible values: snapshot diff reports store root/from/to snapshot names and diff entries; snapshottable directory status wraps `HdfsFileStatus`, parent path bytes, snapshot count/quota, owner/group/permission data, and comparator order; corrupt-file listings persist a cookie for paginated iteration.

Client runtime state includes open input/output streams, current DataNode/block, buffered read statistics, hedged-read `AtomicLong` metrics, NameNode proxy and token service tuples, and connected `Peer` instances. Some methods are synchronized where stream state or located block lists are exposed.

Configuration is a major state source. DFS client read behavior, HA nameservice/NameNode identity, failover proxy providers, standby read test mode, domain sockets, storage policies, data transfer trust resolvers, whitelist files, and whitelist cache intervals all derive from `Configuration` keys.

Protobuf state is the wire contract for HDFS RPC. `PBHelper` conversions cover block, token, ACL, xattr, cache, snapshot, storage, rolling-upgrade, and encryption-zone objects, so field presence/default handling in these conversions is a compatibility risk even though the XML only lists signatures.

## Risks and Edge Cases

- This is a JDiff API artifact, not implementation code. Research consumers should not infer internal algorithms beyond Javadoc and signatures, but should treat all visible methods, fields, deprecations, and exceptions as compatibility surface.
- `DFSInotifyEventInputStream` is documented as not shareable between threads. Clients that fall behind retained edits will see `MissingEventsException`; QJM/network errors can surface as `IOException`, and retry logic is expected.
- Inotify list and encryption-zone listing APIs fetch in batches and may not be consistent snapshots while NameNode state changes.
- `HdfsDataInputStream` read statistics can exceed bytes returned to the caller because buffering and underlying stream behavior are counted at a lower layer.
- `HdfsDataOutputStream.getCurrentBlockReplication` can differ from intended file replication during writes because under-construction blocks are not maintained by the NameNode like completed blocks.
- HA utilities can return logical or physical token services and clone tokens across NameNode addresses. Incorrect URI detection, proxy provider configuration, or direct use of the active address can break failover semantics.
- `NameNodeProxies.createProxyWithLossyRetryHandler` is HA-only and intentionally drops responses; it should remain test-only.
- Cache directive expiration mixes relative and absolute forms. Display conversion uses a local clock, while actual expiration uses server-side clock, so tests and clients must account for clock differences.
- Cache pool info is stored in the edit log; validation, default limits, and max relative expiry behavior are persistence-compatibility concerns.
- `CachePoolInfo` exposes mutable fluent setters and equality/hash methods; mutating an object after using it as a key or expected test value can cause surprising behavior.
- `TrustedChannelResolver` defaults to untrusted. Misconfigured whitelist files, disabled variable whitelists, stale cache intervals, or DNS/address mismatch can change whether encryption/SASL shortcuts are allowed.
- Snapshot diff entries use byte-array paths and compact labels; conversion, equality, and printing must handle rename source/target paths and byte-array identity versus content.
- Deprecated `DFSClient.DFSDataInputStream` and `FSConstants` remain present for ecosystem compatibility; removing them would be a binary/API compatibility break.
- `PBHelper` is a dense conversion hub. Missing optional fields, enum mismatches, null arrays/lists, token kind confusion, bitmask conversion for create/cache/xattr flags, and ordering differences in storage/report conversions are high-risk areas.
