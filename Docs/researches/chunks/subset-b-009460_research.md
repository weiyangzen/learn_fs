## Risks And Maintenance Notes

Descriptor accuracy is the main risk. An incorrect `Opcode`, `Mask`, `OpcodeSuffix`, `MaskSuffix`, field name, or bit run can silently produce invalid machine code or make the decoder reject valid bytes. This is especially relevant for the dense VSX/MMA region, where many mnemonics differ only by a few fixed bits or by a record-form dot suffix.

Suffix entries are higher risk than ordinary entries. A mismatch between the prefix word and suffix word for `xxblendv*`, `xxeval`, `xxpermx`, or `xxsplti*` can make `Encode` and `Decode` disagree about instruction length or validity. These entries also include fields split across the prefix and suffix words, such as `imm0`/`imm1` and `UIM` plus register-extension fields.

Field names are not just documentation. `TX`, `AX`, `BX`, and `CX` encode high register bits for VSX operands; `BF` selects condition-register fields; `AT`/`AS` identify accumulator operands; and pair-like names such as `Ap` interact with encoder constraints. Renaming fields while preserving bit positions can still change testability or consumer behavior.

The generated nature of the file means fixes should normally land in the generator or ISA extraction source, not as local table edits. Manual edits will be overwritten on regeneration and can desynchronize this chunk from surrounding generated descriptors.
