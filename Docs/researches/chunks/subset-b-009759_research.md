## Generator Control Flow

`bisync_debug_test.go` drives this file:

1. `parseConfig()` reads `../../fstest/test_all/config.yaml` into `Config{Tests, Backends}` with `gopkg.in/yaml.v3`.
2. `generateDebuggers()` scans `b.dataRoot` and builds `testList` from non-empty directories whose names start with `test_`.
3. It iterates configured backends, defaulting an empty backend remote to `local`.
4. For every testcase, it loops over `LocalRemote`, `RemoteLocal`, and `RemoteRemote`.
5. For the `local` backend, it skips `LocalRemote` and `RemoteLocal` because those would duplicate `local` against `local`.
6. It formats each entry using `debugFormat`, wraps all entries with `docFormat`, and writes `./testdata/bisync_vscode_debuggers_launch.json` with `bilib.PermSecure`.

The JSON itself has no executable control flow; its behavior is entirely determined by VS Code's Go debugger and the bisync test harness that receives the command-line arguments.
