# sources/test-tools/pynfs/setup.py

Purpose: top-level pynfs packaging shim that fans out the active setup command into subdirectories rather than building one conventional setuptools project.

Important APIs and functions: it imports setuptools' `setup` and then shadows that name with a local `setup(*args, **kwargs)` function. `DIRS = ["xdr", "rpc", "nfs4.1", "nfs4.0"]` controls traversal order. The local function reconstructs the invoking command from `sys.argv`, changes into each subdirectory, and runs `python<major> <command>` with `os.system`.

Control flow: because the local function overrides `setup`, the final metadata-looking `setup(name="pynfs", ...)` actually triggers subdirectory command execution and ignores the supplied metadata arguments.

State and persistence: mutates cwd through each package directory and restores the original cwd after the loop. Persistence is entirely in sub-build outputs generated by each child command.

Dependencies and integration: integrates four sibling pynfs packages, relies on matching `setup.py` files in each directory, and uses `sys.version[0]` to pick `python2` or `python3`.

Risks: command construction via `" ".join(sys.argv)` loses shell quoting and uses `os.system`. Return statuses from child builds are not checked, so partial failures can be hidden. Name shadowing is surprising to packaging tools. Test signals: run a harmless command such as `python3 setup.py --name` or `build` and verify each subdirectory command runs in order and failures are surfaced externally.
