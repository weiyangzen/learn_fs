# sources/test-tools/xfstests-bld/fstests-bld/popt/ltmain.sh

## Purpose
`ltmain.sh` is the generated GNU Libtool 2.2.6 driver embedded in the vendored `popt` package under `xfstests-bld`. It is invoked by generated makefiles as `libtool` to normalize compile, link, install, execute, clean, finish, and uninstall operations across Unix, Darwin, Cygwin, MinGW, OS/2, and related hosts. Its job is not filesystem-test logic directly; it is build-system infrastructure that creates and consumes libtool metadata so the `popt` library can be built in a portable way inside the xfstests build tree.

## Important APIs, types, and functions
The script's public API is command-line mode selection: `--mode=compile`, `--mode=link`, `--mode=install`, `--mode=execute`, `--mode=finish`, `--mode=clean`, `--mode=uninstall`, and internal `--mode=relink`. Global options include `--config`, `--debug`, `--dry-run`/`-n`, `--features`, `--help`, `--preserve-dup-deps`, `--quiet`, `--tag`, `--verbose`, and `--version`.

The central mode handlers are `func_mode_compile`, `func_mode_link`, `func_mode_install`, `func_mode_execute`, `func_mode_finish`, and `func_mode_uninstall`, with `clean` sharing the uninstall implementation. Major support functions include message/error helpers (`func_echo`, `func_warning`, `func_fatal_error`, `func_fatal_help`), filesystem helpers (`func_dirname_and_basename`, `func_mkdir_p`, `func_mktempdir`), command execution helpers (`func_show_eval`, `func_show_eval_locale`, `func_execute_cmds`), quoting helpers (`func_quote_for_eval`, `func_quote_for_expand`), libtool metadata recognizers (`func_lalib_p`, `func_lalib_unsafe_p`, `func_ltwrapper_*`), and tag/configuration helpers (`func_enable_tag`, `func_infer_tag`, `func_check_version_match`).

Several helper functions are generated into the script by Libtool macro expansion and are used heavily even though their definitions are not adjacent to the call sites, including basename/dirname transforms, arithmetic/string-length helpers, suffix transforms, and append/strip helpers. The script also embeds host-specific generated configuration variables from `configure`, such as compiler/linker commands, PIC flags, archive commands, `objdir`, shared-library path variables, hardcode policy, dependency checking policy, and tag overrides. At the end, the built-in tags `disable-shared` and `disable-static` mutate `build_libtool_libs` and `build_old_libs`.

## Control flow
Startup first forces Bourne-compatible shell behavior, normalizes locale variables to `C`, establishes tool defaults (`CP`, `ECHO`, `GREP`, `SED`, `SHELL`, and others), computes its own absolute path, and validates that echo behavior is usable, re-executing through `$SHELL` or using a fallback echo path if needed. It then parses global options and the mode, supports abbreviated first-argument mode names, handles `--tag` by extracting embedded tag configuration from the script itself, and verifies that the generated libtool macro revision matches the driver revision.

In compile mode, the script parses the compiler command, source, `-o`, PIC/static preferences, `-Wc,`/`-Xcompiler` pass-through flags, and PIE flags. It computes the `.lo` libtool object name, the real object name, and the `.libs` PIC object path. Depending on `build_libtool_libs`, `build_old_libs`, `pic_mode`, `compiler_c_o`, and `need_locks`, it may compile a PIC object into `.libs`, compile a non-PIC object into the build directory, serialize compilers that cannot combine `-c` and `-o`, and finally write the `.lo` metadata file with `pic_object` and `non_pic_object`.

In link mode, the script performs the most complex flow. It classifies the output as an old archive, reloadable object, libtool library, or executable; parses libtool-specific options such as `-rpath`, `-version-info`, `-release`, `-module`, `-no-undefined`, `-export-symbols`, `-dlopen`, `-dlpreopen`, `-static`, and `-shared`; reads `.lo` and `.la` files by sourcing them; performs several dependency passes (`conv`, `scan`, `dlopen`, `dlpreopen`, `link`); and computes compile/finalize dependency lists, rpaths, library search paths, weak libraries, and relink requirements. It can create shared libraries through generated `archive_cmds`, static archives through `old_archive_cmds`, reloadable objects through `reload_cmds`, wrapper scripts or C wrapper executables for uninstalled programs, import libraries and definition files for Windows-like hosts, and `.la` pseudo-archives describing the final library.

Install mode parses a BSD-style install/cp command and destination, distinguishes static archives, `.la` libraries, `.lo` objects, wrapper executables, and ordinary files, and may relink libraries or programs before installation when the platform requires final install paths to be encoded. Execute mode resolves `-dlopen` inputs, sources wrapper scripts or wrapper-executable dump scripts, extends the platform shared-library search variable, restores saved user locale, and `exec`s the real command. Finish mode runs configured post-install administrative commands and prints dynamic-loader guidance. Clean and uninstall modes locate the companion files described by `.la`, `.lo`, and wrapper metadata, remove shared-library symlinks, static archives, generated symbol objects, wrapper scripts/executables, and optionally remove empty `.libs` directories.

## State and persistence behavior
The script persists libtool state mainly through generated files. Compile mode creates `.lo` files and object files in both the source build directory and `$objdir` (normally `.libs`). Link mode creates `.la` files, installed-form `.lai` files, static archives, shared libraries and symlinks, import libraries, export-symbol files, generated `S.c`/`S.o` symbol-table artifacts, wrapper scripts, and on Cygwin/MinGW C wrapper source/executables such as `lt-*.c` and `*.exe`. It also creates temporary extraction directories under `$objdir`, temporary relink outputs, lock files for non-`-o` compilers, and temporary files for symbol/export generation.

Runtime state is communicated through environment variables such as `LANG`, `LC_*`, `shlibpath_var`, `runpath_var`, `PATH`, `BIN_SH`, `DUALCASE`, `libtool_execute_magic`, and `libtool_install_magic`. The `.la` and `.lo` files are shell fragments that are later sourced, so they act as persistent build metadata: library names, dependency libraries, install directories, relink commands, dlopen/preopen sets, version triplets, and object-file mappings are all stored there.

## Dependencies and integration points
`ltmain.sh` is integrated with Autoconf/Automake generated makefiles and configure output. It expects many configure-time variables to be inserted into the script before use: compiler/linker commands, archive commands, `macro_version`, `macro_revision`, `host`, `build`, `objext`, `libext`, `objdir`, `pic_flag`, `archive_cmds`, `postinstall_cmds`, `finish_cmds`, `global_symbol_pipe`, `hardcode_*`, `sys_lib_*`, and many platform policies.

External tool dependencies include a POSIX shell, compiler and linker (`CC`, `LTCC`, `LD`), archive tools (`AR`, `RANLIB`), object/symbol tools (`NM`, `OBJDUMP`, `STRIP`), text utilities (`sed`, `grep`, `egrep`, `fgrep`, `sort`, `uniq`, `expr`, `awk` in Darwin paths), filesystem commands (`cp`, `mv`, `rm`, `mkdir`, `ln`, `chmod`, `find`, `file`, `ldd`), and platform tools such as `lipo`, `otool`, or Windows import-library helpers when configured. In this repository, it is consumed by the vendored `popt` build under `sources/test-tools/xfstests-bld/fstests-bld/popt`, which supports building xfstests-related tooling.

## Risks and edge cases
The main risk is that this is generated, legacy shell code that relies on `eval`, sourcing generated metadata files, and host-specific command strings. Paths or arguments with shell metacharacters are quoted through helper functions, but `.la`, `.lo`, wrapper scripts, and relink commands remain executable shell fragments; corrupted or untrusted metadata can execute code during build, install, clean, or execute modes.

Link mode has high behavioral complexity. Dependency ordering, duplicate-library elimination, static-versus-shared fallback, `-module` portability, inter-library dependencies, rpath hardcoding, and relinking all depend on platform probes embedded at configure time. This makes regressions host-sensitive and difficult to catch on one platform. Parallel builds are another risk: compilers without reliable `-c -o` support use lock files, and failures around stale lock files produce explicit warnings about avoiding `make -j`.

The script mutates or depends on environment variables and locale. Execute mode intentionally restores user locale before running the wrapped program, while build commands generally run under the safe `C` locale. Wrapper scripts must remain in the build directory because they compute their real program path relative to `$objdir`; moving them breaks execution. Clean/uninstall can remove broad sets of companion files inferred from metadata, so malformed metadata or incorrect `objdir`/destination values can remove unexpected build artifacts.

## Test signals
Useful validation signals are build-system actions rather than unit tests. `make` in the `popt` directory should exercise compile and link modes, producing `.lo`, `.libs/*.o`, `.la`, static archives, shared libraries if enabled, and wrapper scripts only where expected. `libtool --config`, `--features`, and `--version` should succeed and report the generated configuration. `--mode=compile` should write valid `.lo` files whose `pic_object` and `non_pic_object` match the generated objects. `--mode=link` should produce valid `.la` metadata and correctly ordered link commands under `--dry-run`.

Install and cleanup behavior can be checked with staged installation into a temporary absolute directory, confirming that relink commands, `.lai` files, library symlinks, static archives, and finish messages are correct. `--mode=execute` can be tested with an uninstalled wrapper program and `-dlopen` `.la` inputs to confirm shared-library search path setup. `make clean`, `make uninstall`, or explicit `--mode=clean` should remove the generated companion files without touching unrelated sources.
