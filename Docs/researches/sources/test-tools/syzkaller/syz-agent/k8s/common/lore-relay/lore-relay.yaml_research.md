# sources/test-tools/syzkaller/syz-agent/k8s/common/lore-relay/lore-relay.yaml

Purpose: Kubernetes deployment for the syz-lore-relay service.

Important APIs/types/functions: `Deployment` named `lore-relay` with one container and config/PVC volumes.

Control flow: runs `gcr.io/syzkaller/lore-relay:latest` with `-config=/config/lore-relay-config.yaml`, mounts config map and lore repo PVC, and sets `GIT_DISCOVERY_ACROSS_FILESYSTEM=1`.

State and persistence: persistent lore checkout lives on `lore-relay-pvc`; config is injected by ConfigMap.

Dependencies and integration points: service account is expected from Terraform; image and config are patched/generated by overlays.

Risks: resource requests are sizable; no service object is defined here because relay is outbound-worker style. Missing service account/config map prevents pod startup.

Test signals: deployment readiness and relay logs.
