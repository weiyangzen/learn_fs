## sources/test-tools/syzkaller/sys/linux/init_iptables.go

Purpose: Linux special generators and neutralization support for iptables, ip6tables, arptables, and ebtables replacement structures. The code repairs generated or mutated netfilter table arguments so hook offsets, underflow offsets, jump targets, entry counts, physical hook addresses, and setsockopt lengths are internally consistent enough for kernel netfilter parsers.

Important APIs/types/functions: `arch.generateIptables`, `arch.generateArptables`, `arch.generateNetfilterTable`, `arch.generateEbtables`, and `arch.neutralizeEbtables`. These functions operate on `prog.Gen`, `prog.Type`, `prog.Dir`, `prog.Arg`, `prog.Call`, `prog.GroupArg`, `prog.UnionArg`, `prog.PointerArg`, `prog.ConstArg`, `prog.ConstType`, and `prog.FlagsType`; they also use `prog.CloneArg`, `Gen.GenerateSpecialArg`, `Gen.MutateArg`, `Target.ArgContainsAny`, `Target.PhysicalAddr`, and `prog.ForeachSubArg`.

Control flow: iptables and arptables are thin wrappers over `generateNetfilterTable`, differing by union wrapping and hook count. `generateNetfilterTable` generates a fresh special argument or clones and mutates the old one, unwraps the table, checks the expected field count, computes byte offsets for every entry, randomly assigns used hook offsets to entry offsets or rarely to the underflow position, sets all used underflow fields to the end position, then walks nested args to rewrite standard target jump offsets while preserving negative verdict constants recognized by the target flags type. `generateEbtables` similarly generates or mutates, bails out on ANY-containing args, accounts for 32-bit versus 64-bit struct padding, computes per-chain offsets and total entry counts, stores the total into the table, and assigns valid hook pointers to physical addresses of the generated entries. `neutralizeEbtables` runs on a finished `setsockopt` call and rewrites its length argument to `sizeof(ebt_replace)+entries size` when the table and entries pointers are present.

State and persistence: all state is in-memory mutation of `prog.Arg` graphs and call arguments. No files, kernel state, or global caches are written. The code does alter cloned old arguments during mutation, including hook offsets and target jump offsets, and returns any support calls produced by special generation or argument mutation.

Dependencies and integration points: registered by `init.go` as special generators for `ipt_replace`, `ip6t_replace`, `arpt_replace`, and `ebt_replace`; `neutralizeEbtables` is invoked by Linux target neutralization for `setsockopt$EBT_SO_SET_ENTRIES`. The logic depends on syzlang struct field order, union shape, pointer-size-specific padding, netfilter sentinel values, target physical address calculation, and standard target type names beginning with `xt_target_t["", `. It also relies on `slices.Contains` to distinguish negative verdict flags from jump offsets that should be rewritten.

Risks: this code is highly shape-dependent: a syzlang layout change can panic through failed type assertions, wrong field counts, or field order assumptions. `genOffset` assumes at least one table entry; empty entry arrays would make `Intn(len(offsets))` invalid unless the generated descriptions prevent that. The wrappers intentionally discard old hook order after mutation, which may reduce mutation locality. Ebtables target jump offsets remain a TODO, so generated ebtables programs can still have internally inconsistent target jumps. Physical address assignment depends on pointer resources being present; nil entry pointers cause early returns and less repaired output.

Test signals: indirect coverage comes from Linux target generation, mutation, deserialization, serialization, and neutralization tests, especially `init_test.go` for neutralization plumbing and broader `prog` generation tests for special type validity. There is no direct focused test in this file, so regressions in field layout assumptions may surface as panics during generation or as kernel-side netfilter rejects rather than as clear unit failures.
