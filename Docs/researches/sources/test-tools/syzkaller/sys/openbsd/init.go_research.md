# sources/test-tools/syzkaller/sys/openbsd/init.go

Purpose: installs OpenBSD-specific target hooks and neutralizes syscalls that can destabilize a VM, corrupt disks, interfere with executor file descriptors, or destroy fuzzing signal.

Important APIs/types/functions: `InitTarget` captures OpenBSD constants and assigns `MakeDataMmap`, `Neutralize`, and `AnnotateCall`. The `arch` type stores constants for clocks, sysctl MIBs, ioctl requests, modes, memory locking, and rlimits. Helpers include `devmajor`, `devminor`, `isExecutorFd`, `neutralize`, `neutralizeClockSettime`, `neutralizeRlimit`, `neutralizeSysctl`, `neutralizeSysctlKern`, and `annotateCall`.

Control flow: `neutralize` switches on `c.Meta.CallName`. It clears immutable/append flags for `chflags*`, rewrites `CLOCK_REALTIME` in `clock_settime`, blocks dangerous PF ioctls, sanitizes `mknod/mknodat` modes and device numbers, removes `MCL_FUTURE`, clamps selected rlimits, clears dangerous `kern.*` sysctl MIBs, and delegates everything else to `targets.UnixNeutralizer`.

State and persistence: no durable state; it mutates in-memory `prog.Call` arguments before execution or serialization.

Dependencies and integration points: integrates with `prog.Target` target hooks, shared Unix neutralization, and OpenBSD syscall descriptions/constants generated by syz-sysgen.

Risks: argument indexing depends on syscall signatures. Incorrect constants would silently miss a hazard. The sysctl neutralizer only handles currently known dangerous `CTL_KERN` knobs, so new OpenBSD knobs may need additions.

Test signals: `openbsd/init_test.go` covers chflags, PF ioctl, mknod device rewrites, mlockall, rlimit clamping, sysctl clearing, and clock_settime rewriting.
