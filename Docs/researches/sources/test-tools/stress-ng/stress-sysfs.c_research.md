# sources/test-tools/stress-ng/stress-sysfs.c

Purpose: implements the Linux `sysfs` stressor, recursively walking `/sys` and exercising readable sysfs files through open, read, zero-length read/write, mmap, select/poll/ppoll, lseek, ioctl, and a few controlled write probes. It is designed to stress kernel sysfs handlers while avoiding known-dangerous paths and adapting when accesses generate excessive kernel log output or fatal signals.

Important APIs/types/functions: `stress_ctxt_t` holds shared state for stressor args, `/dev/kmsg` fd, `CAP_SYS_ADMIN` status, current `sysfs_path`, and an opened-file counter. `stress_sysfs_wr_func_t` maps special writable paths to guarded handlers; currently `/sys/power/disk` writes `test_resume`. Key helpers are `path_sum`, `mixup_sort`, `stress_kmsg_drain`, `stress_sys_add_bad`, `stress_sys_bad`, `stress_sys_rw`, `stress_sys_rw_thread`, `stress_sys_skip`, `stress_sys_dir`, `stress_sysfs_bad_signal`, and `stress_sysfs`. Shared synchronization uses `shim_pthread_spinlock_t` locks for current path, open counter, and bad-path hash table.

Control flow: `stress_sysfs` maps a shared context, scans and prunes `/sys`, parses the kernel major/minor from `uname`, creates a hash table for bad paths, opens `/dev/kmsg` nonblocking, records whether the worker has `CAP_SYS_ADMIN`, initializes spinlocks, and enters the synchronized stress run. The main loop forks a child supervisor. The child starts up to four pthreads running `stress_sys_rw_thread`; these threads block signals and repeatedly operate on the current `ctxt->sysfs_path`. The child recursively traverses top-level `/sys` entries in a prime-step order, calling `stress_sys_dir` for each subtree. `stress_sys_dir` scans directories in hash-mixed order, skips dot entries, known bad paths, unreadable/unwritable mode combinations, and overly deep recursion; for each regular file it publishes the path under a spinlock, waits until either the per-file operation budget or time budget is reached, then increments bogo ops. Directories are recursed after regular files.

`stress_sys_rw` opens the published path with a timed `stress_try_open`, marks failing paths bad, and performs multiple random-sized reads until EOF, error, the per-file time threshold, or kmsg-drain pressure. It verifies `fstat` under `--verify`, performs a zero-length read, tries a one-page `mmap` and consumes one byte via `stress_put_uint8`, calls `select`, `poll`, and `ppoll`, seeks to offset zero, and issues simple `FIGETBSZ`/`FIONREAD` ioctls when available. If not running with `CAP_SYS_ADMIN`, it attempts only zero-length write opens; if privileged, it avoids broad writes except for explicit safe special cases. The parent waits for child exit and, if the child dies from SIGBUS/SIGILL/SIGSEGV/SIGTRAP/SIGSYS, reports the active path, adds it to the bad-path hash, and returns failure.

State and persistence behavior: persistent state is limited to the shared context mapping, pthread spinlocks, `/dev/kmsg` descriptor, and in-memory bad-path hash. It never creates files under `/sys`. It may read and mmap sysfs files, issue ioctls, and perform zero-length writes; the only nonzero write is the special `/sys/power/disk` `test_resume` probe. It throttles when `/dev/kmsg` output exceeds the drain threshold and records skipped path count via `hash_items`. Threads are canceled and joined by the child when traversal stops; the parent destroys locks, deletes the hash table, closes kmsg, frees dirents, and unmaps context.

Dependencies and integration points: compiled implementation requires Linux and pthread support; otherwise `stress_sysfs_info` registers `stress_unimplemented`. It depends on stress-ng core helpers for capabilities, hash tables, process killing, mmap, pthread shims, prime stepping, put sinks, signal names, temp/open retries, dirent pruning/freeing, filenames, and metrics. It uses Linux/sysfs-visible kernel behavior, `/dev/kmsg`, `uname`, `scandir`, `stat`, pthreads, fork/wait, `poll`, `select`, `mmap`, `ioctl`, and capability checks. It registers as `CLASS_OS` with optional verification and the `sysfs`/`sysfs-ops` help entries.

Risks: sysfs files are kernel driver entry points, so reads can block, produce large log volume, or trigger kernel/driver faults. The stressor mitigates with per-file timeouts, bad-path hashing, signal-supervised child restart, skip rules for zram hot-add, debugfs, Azure VMBUS paths, old TPM securityfs paths, and kmsg draining, but the design still intentionally probes fragile kernel surfaces. Privileged runs have more read/write visibility and therefore higher risk. Fork/pthread cancellation and shared spinlock state make cleanup correctness important if a child exits mid-operation.

Test signals: normal runs should report bogo ops as paths are exercised and set the metric `sysfs files exercised per sec`. Debug output reports skipped bad paths versus total accessed. Under `--verify`, failed `fstat` after a successful open is a failure signal. Severe signals should produce an informational line naming the signal and current sysfs path and should add that path to the bad hash. Skip behavior is expected on systems without `/sys`, without Linux pthread support, or where no usable entries remain after pruning.
