# sources/test-tools/stress-ng/stress-syscall.c

Purpose: implements the `syscall` stressor, a broad timing and throughput benchmark that exercises a large compile-time-selected table of system call wrappers. It uses safe local fixtures, short-lived children, temporary files, sockets, IPC objects, timers, memory mappings, and signal handlers to measure individual call latency (`t1`/`t2`) and full wrapper cost, then filters to the fastest or geomean-selected non-failing calls for the main stress loop.

Important APIs/types/functions: central types are `syscall_method_t`, `syscall_rank_t`, `syscall_func_t`, `syscall_t`, `syscall_shared_info_t`, and `syscall_stats_t`. Global fixture state includes `syscall_filename`, `syscall_tmp_filename`, `syscall_symlink_filename`, `syscall_fd`, `syscall_dir_fd`, `syscall_2_pages`, `syscall_mmap_page`, `syscall_brk_addr`, saved uid/gid/pid/session/umask/current-directory data, and the shared child timing page. Timing and ranking helpers are `syscall_time_now`, `syscall_shared_error`, `stress_syscall_reset_index`, `stress_syscall_reset_ignore`, `stress_syscall_shuffle_calls`, `stress_syscall_rank_calls_by_sort`, `stress_syscall_rank_calls_by_geomean`, `stress_syscall_rank_calls`, `stress_syscall_benchmark_calls`, and `stress_syscall_report_syscall_top`. `syscall_socket_measure` is a generic AF_UNIX parent/child benchmark for `accept`, `accept4`, `bind`, `connect`, `listen`, send/receive variants, `getpeername`, and `shutdown`. Signal helpers are `syscall_sigsegv_handler` and `syscall_sigusr1_handler`; `sigsetjmp` protects the benchmark loop from syscall tests that fault.

Control flow: `stress_syscall` resolves settings (`syscall-method`, `syscall-rank`, `syscall-top`), captures process identity and cwd, installs SIGSEGV/SIGUSR1/SIGXFSZ handlers, creates a stress-ng temp directory, opens a fixture file, writes two pages of randomized data, creates an optional symlink, maps shared timing state, and initializes per-syscall stats. After stress-ng synchronization it first benchmarks every non-ignored call once to identify calls that succeed and to capture maximum wrapper duration. It then ranks/filters by method: all, fastest 10/25/50/75/90 percent by wrapper duration, or geomean thresholds scaled 1/2/3. The main loop repeatedly calls `stress_syscall_benchmark_calls`, shuffles the syscall index, and stops on the common stress-ng continue/time-end checks. Instance zero reports how many calls were exercised and prints a configurable top-N timing table.

The syscall wrappers are grouped around real kernel interfaces: filesystem and descriptor calls (`open`, `openat`, `creat`, `close`, `dup*`, `stat*`, `chmod*`, `chown*`, `truncate`, `ftruncate`, `link*`, `symlink*`, `rename*`, `unlink*`, xattrs); buffered and vector I/O (`read`, `write`, `pread*`, `pwrite*`, `readv`, `writev`, `sendfile`, `copy_file_range`, `readahead`, `splice`, `tee`, `vmsplice`); memory and NUMA (`brk`, `mmap`, `munmap`, `mremap`, `mprotect`, `msync`, `mlock*`, `mincore`, `madvise`, `mbind`, `move_pages`, `migrate_pages`, `memfd_create`, `map_shadow_stack`, `userfaultfd`); process, signal, and scheduler APIs (`fork`, `vfork`, `clone`, `clone3`, `execve`, `execveat`, `exit`, wait variants, `kill`, `pause`, `sigsuspend`, `sigaction`, `sigaltstack`, `signalfd`, `sigprocmask`, `sched_*`, `set*uid/gid`, `setsid`, `setpgid`, `get*id`, `prctl`, `seccomp`, `rseq`); time and timer APIs (`clock_gettime`, `clock_getres`, `clock_nanosleep`, `clock_adjtime`, `clock_settime`, `nanosleep`, `gettimeofday`, `time`, `times`, POSIX timers, timerfd, itimers); IPC and message APIs (System V sem/shm/msg, POSIX mqueue, AIO, io_uring setup, eventfd, inotify/fanotify); and platform-specific direct syscalls such as keyrings, LSM attributes, `kcmp`, `lookup_dcookie`, `quotactl_fd`, RISC-V probes, ioperm/iopl, and cache flushes. Riskier or disruptive kernel interfaces are intentionally omitted in the table comments, including accounting, module load/unload, mount/pivot/root changes, reboot, swap, ptrace/perf interactions, deprecated sysfs/sysctl, and several time or hostname setters.

State and persistence behavior: the stressor creates only temporary files and symlinks under the stress-ng temp directory and removes them during cleanup. Most mutating wrappers restore state immediately: chmod/chown use saved uid/gid and reset modes; xattr calls remove test attributes; rename/link/symlink/unlink calls use the temp paths; rlimit, scheduler, pkey, timer, IPC, AIO, eventfd, inotify/fanotify, pipe/socket, and file-handle tests close or delete created resources. Some tests fork or clone to isolate side effects (`chroot`, `execve`, `exit`, wait-family calls, socket benchmark, `pause`, `sigsuspend`, `unshare`). `umask` is saved and restored, and cwd changes are restored to `syscall_cwd`. Persistent machine-wide effects are deliberately avoided where possible, though calls such as `sync`, `fsync`, `fdatasync`, `syslog`, keyring operations, quota sync, memory policy calls, and capability/system-time-sensitive setters can still interact with global kernel state or policy.

Dependencies and integration points: this file is heavily gated by build-time `HAVE_*`, architecture, libc, and kernel syscall-number macros. It depends on stress-ng core shims and helpers from `stress-ng.h`, `core-arch.h`, `core-cpu-cache.h`, `core-builtin.h`, `core-io-priority.h`, `core-signal.h`, and `core-clocks.h`; it also uses optional Linux headers for audit/filter/futex/io_uring/membarrier/mempolicy/rseq/seccomp/sysctl/userfaultfd, libaio, keyutils, POSIX mqueue, xattrs, fanotify/inotify, timerfd, SysV IPC, quota, and capabilities. It registers `stress_syscall_info` as `CLASS_OS` with options `syscall-method`, `syscall-rank`, and `syscall-top`; it uses stress-ng temp-dir, process-state, synchronization, random, metrics/logging, shim, and stress-loop infrastructure.

Risks: runtime behavior is intentionally platform- and privilege-sensitive. Many wrappers succeed only with capabilities or specific kernel features, while seccomp, namespaces, containers, LSMs, cgroups, rlimits, key quotas, IPC limits, syslog restrictions, and filesystem support can change success rates. The SIGSEGV long-jump path avoids process termination but means wrapper bugs may be recorded as skipped/segv rather than hard failures. Several tests fork/clone frequently and can hit PID or process limits. Some paths call `sync`/`fsync` or filesystem metadata operations and may perturb system I/O. The `syscall_mbind` wrapper references `syscall_pages_size`, while the file defines `syscall_page_size`; if that configuration path is compiled, it is a build risk unless another macro supplies the name. A few timing records depend on child/parent shared memory and signal delivery, so interrupted calls and scheduler delays can skew rankings.

Test signals: successful startup creates the temp directory, fixture file, data pages, shared timing mapping, and optional symlink. During execution, bogo ops increment once per wrapper attempt; instance zero logs the selected method, total compiled syscall tests, percentage exercised, and top fastest syscall table with average/min/max nanoseconds plus SIGSEGV notes. Failures surface as skip messages for temp/mmap/file setup, fewer successful/exercised calls, unexpectedly empty timing tables, persistent SIGSEGV annotations, or nonzero exit from resource setup. Good validation should cover multiple `--syscall-method` settings, `--syscall-rank`/`--syscall-top`, unprivileged and privileged/container runs, and builds with optional syscall families enabled.
