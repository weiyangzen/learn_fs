# sources/test-tools/stress-ng/stress-sysinfo.c

Purpose: implements the `sysinfo` stressor, repeatedly fetching global system and filesystem information through `sysinfo`, Linux `statfs`/`fstatfs`, POSIX `statvfs`, legacy `ustat`, filesystem-label ioctls, and `times`. It stresses read-only kernel information paths across all currently discovered mount points and deliberately exercises some invalid inputs to cover error paths.

Important APIs/types/functions: the single stressor entry point is `stress_sysinfo`; registration is `stress_sysinfo_info`. It uses `stress_mount_get`/`stress_mount_free` for a bounded array of mount path strings, `stress_fs_bad_fd_get` for invalid-fd probes, `shim_stat`, `shim_ustat`, `sysinfo`, `statfs`, `fstatfs`, `statvfs`, `ioctl(FS_IOC_GETFSLABEL)`, `makedev`, and `times`. Verification is controlled by `OPT_FLAGS_VERIFY`.

Control flow: `stress_sysinfo` initializes a 128-entry mount array, fetches current mount points, logs the count on instance zero, synchronizes with other workers, and loops while stress-ng says to continue. In each iteration it conditionally calls `sysinfo`, then for each mount point calls `statfs`; if a mount disappears with `ENOENT`, it frees and clears that entry. It also probes invalid paths (`/invalid_stress_ng` and `""`), opens mount directories to optionally request the filesystem label via ioctl, calls `fstatfs`, and probes `fstatfs` on a known bad fd. Next it stats each mount to get `st_dev`, calls `shim_ustat`, and exercises an invalid `ustat` device using a likely-invalid major/minor. When available, it repeats the mount walk with `statvfs` and an invalid path. Finally it calls `times`, increments bogo ops, and exits on failure or stop conditions.

State and persistence behavior: the stressor is intended to be read-only. It allocates and later frees mount-point strings returned by `stress_mount_get`; it mutates only the local mount list by removing entries that disappear. It opens mount directories transiently and closes them after `fstatfs`. It does not create files, mount/unmount filesystems, or alter system limits. Invalid probes are intentionally ignored via `VOID_RET` except where verification treats unexpected errors as failures.

Dependencies and integration points: this file depends on stress-ng mount helpers and portability shims plus optional platform headers for Linux filesystem ioctls, `sysmacros`/`mkdev`, `statfs`, and `statvfs`. It is registered as `CLASS_OS` with `VERIFY_OPTIONAL`, and it follows stress-ng process-state transitions (`SYNC_WAIT`, `RUN`, `DEINIT`) and bogo-op accounting. The behavior is shaped by platform feature macros such as `HAVE_SYS_SYSINFO_H`, `HAVE_SYSINFO`, `HAVE_SYS_STATFS_H`, `HAVE_SYS_STATVFS_H`, and label ioctl availability.

Risks: results depend on a changing mount namespace. Mount points can disappear, become inaccessible, return network-filesystem errors, or require permissions while the loop runs. Verification allows expected transient/platform errors (`ENOSYS`, `EOVERFLOW`, `EACCES`, `ENOTCONN`, `EPERM`, selected `ustat` errors), but unexpected errno values cause failures. The fixed 128 mount array means very large mount namespaces are sampled rather than exhaustive. Opening mount roots and issuing label ioctls may be slow or unsupported on some filesystems.

Test signals: startup should find mount points or fail with an error. Instance zero debug logs the number of mounts. Under `--verify`, unexpected failures from `sysinfo`, `statfs`, `ustat`, `statvfs`, or `times` produce `pr_fail` messages and set `EXIT_FAILURE`; accepted invalid-input errors are ignored. Normal progress is bogo-op increments per full information-gathering pass and clean `DEINIT` with mount-list cleanup.
