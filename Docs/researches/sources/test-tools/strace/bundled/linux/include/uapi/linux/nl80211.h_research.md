## Scope

This chunk covers the opening 5,950 lines of the bundled Linux UAPI header for the `nl80211` generic netlink family. It is a public ABI contract, not executable implementation code. The covered range defines the generic netlink family name, multicast group names, kernel-doc protocol semantics, the complete `enum nl80211_commands`, the complete `enum nl80211_attrs`, and many supporting attribute enums and packed structs through the beginning of `enum nl80211_attr_cqm`. Line 5,950 ends mid-documentation for CQM attributes, so the rest of CQM and later nl80211 sub-APIs must be reconciled from following chunks.

## Purpose

`nl80211.h` is the userspace API surface for Linux wireless stack operations via generic netlink. In this repository it is bundled under strace test tools, so its practical consumer is decoder/test code that needs exact numeric command and attribute values to trace nl80211 messages accurately. The file itself warns that enum ordering is ABI-sensitive: existing entries must not be moved, and new commands/attributes are appended before the internal `*_AFTER_LAST` sentinels.

The header models most cfg80211/mac80211 user-visible behavior as numbered commands and nested netlink attributes. This chunk documents station management, management frame registration and TX, virtual interface concurrency, packet coalescing, handshake/authentication offloads, VLAN and TID configuration, FILS crypto, Multi-Link Operation, OWE offload, NAN scheduling, regulatory state, scan results, mesh state, BSS descriptions, key material, rates, channel widths, bands, and power save.

## Important APIs, Types, and Constants

## Protocol and Control Flow

There is no local C control flow in this chunk. The control flow is protocol-level:

1. Userspace opens a generic netlink socket and resolves the `nl80211` family.
2. Userspace sends an `enum nl80211_commands` value with a command-specific set of top-level `NL80211_ATTR_*` attributes.
3. Kernel cfg80211/mac80211 and driver code validate attributes against policy, device capabilities, interface type, regulatory state, and feature flags.
4. The kernel replies synchronously, emits multicast/unicast events, or both. Dump commands use `NL80211_ATTR_GENERATION` so userspace can detect inconsistent snapshots and retry.
5. Many long-lived operations return or later emit `NL80211_ATTR_COOKIE`, allowing userspace to correlate asynchronous completion/status events such as remain-on-channel, management frame TX, station probe, NAN functions, and peer measurements.

The kernel-doc comments describe several stateful command flows:

- TDLS external setup creates a temporary station entry, updates it once after setup, enables the link, and later tears it down.
- Management frame registration is per interface and persists until the registering netlink socket closes. Interface type changes make registrations dormant until the type changes again.
- `NL80211_ATTR_SOCKET_OWNER` binds lifetimes of created interfaces, scheduled scans, indoor regulatory state, associations, IBSS, mesh, AP, and NAN notifications to the owning socket.
- Connect/roam/external-auth paths exchange SSID, BSSID/frequency hints, auth data, PMK/PMKSA material, control-port behavior, MLO support/link IDs, and status/timed-out events.
- AP/channel operations require beacon/probe/assoc response templates, CSA/countdown offsets, DFS/radar handling, color changes, MBSSID/EMA/RNR data, and optionally FILS discovery or unsolicited broadcast probe response templates.
- NAN has explicit start/stop, function add/delete, configuration changes, match notifications, cluster events, local schedule update, peer schedule configuration, ULW update, and channel evacuation events. Some NAN events are unicast to the socket owner.

## State and Persistence Behavior

This header does not store state, but it defines which state is exposed or controlled:

- Persistent-until-socket-close state includes frame registrations and socket-owned interfaces/scans/AP/mesh/IBSS/association/NAN resources.
- Per-connection state includes PMK/PMKSA, FILS ERP-derived material, QoS maps, TID configuration, control-port settings, MLO link setup, hardware timestamp configuration, and BSS association status. Many of these are explicitly cleared on disassociation, AP restart, interface down, roaming, or socket close.
- Regulatory state is global or per-wiphy depending on initiator/type and self-managed-reg flags. Frequency attributes and regulatory rule flags expose derived channel availability, DFS state/timers, indoor/no-IR/6 GHz/VLP/AFC/UHR restrictions, CAC start time, and power limits.
- Scan and BSS state is snapshot-like. `NL80211_ATTR_GENERATION` protects list dumps, BSS entries carry age and `CLOCK_BOOTTIME` timestamps, and BSS usability flags/reasons report device-specific restrictions.
- Statistics enums expose accumulated counters for station bytes/packets/retries/failures, per-TID counters, TXQ backlog/drops/ECN/overlimit/overmemory/collisions, survey channel time/noise/busy/RX/TX/scan, and mesh path changes.
- Security material handling is ABI-defined but opaque to the header: key data, PMK, PMKID, SAE password, FILS KEK/nonces, ERP keys, and PMKR0 names are transported as attributes and must be treated as sensitive by userspace and decoders.

The only direct include in this chunk is `<linux/types.h>`, providing fixed-width UAPI types such as `__u16` and `__u32`. Several structs are wire-layout data and must retain exact size and packing; `struct nl80211_sta_flag_update` is explicitly `__attribute__((packed))`, and TX rate structs use fixed arrays indexed by NSS.

Kernel integration points:

- cfg80211/mac80211 and individual wireless drivers provide device capabilities, interface combinations, feature flags, channel/regulatory information, scan results, station stats, key offload support, MLO/NAN/FTM/SAR support, and command-specific behavior.
- Wireless-regdb/CRDA-style regulatory data and country IE processing inform the regulatory enums and frequency attributes.

Userspace integration points:

- `wpa_supplicant`, `hostapd`, `iw`, NetworkManager/iwd, and vendor tools consume these command/attribute numbers for wireless control and event handling.
- strace can include this header so nl80211 netlink traces decode numeric command and attribute IDs into symbolic names. ABI aliases in this chunk matter for older userspace and older kernel trace compatibility.
- Security/authentication consumers rely on documented command combinations for PMKSA caching, 4-way handshake offload, FILS, SAE, OWE, external authentication, control-port-over-nl80211, and port authorization events.

## Risks and Edge Cases

- ABI ordering is the largest risk. Reordering existing enum values, inserting in the middle, or changing aliases would break existing binaries and strace decoders.
- Numeric sentinel use must be careful. `*_MAX` values are for validation and iteration bounds, while `NUM_*` values are not always stable for userspace assumptions.
- Some attributes are deprecated, obsolete, or compatibility-only but still ABI-visible. Decoders and tests should preserve old symbolic names where expected.
- Attribute typing is implicit in comments and kernel policy, not encoded in C types. Incorrect parser assumptions about `u8`, `u16`, `u32`, `u64`, signed values, binary blobs, nested attributes, or flag attributes can misdecode traffic.
- Nested attributes are common and sometimes deeply structured: station info contains rate info/TID stats/TXQ stats; BSS data contains raw IEs and timestamps; regulatory data contains rules and frequency attributes; NAN schedule data uses channels, maps, slots, and raw availability blobs.
- 64-bit values require padding/alignment attributes in several families (`NL80211_ATTR_PAD`, BSS pad, survey pad, station info pad, TID stats pad). Netlink decoders must tolerate padding and preserve alignment.
- Several protocol flows depend on socket lifetime and asynchronous events. Tests that only inspect the request path can miss cleanup behavior or event-only command use.
- MLO and NAN additions introduce multiple identifiers for a peer/interface: MLD address, link ID, NMI/NDI addresses, peer schedule sequence IDs, and channel entries. Confusing link address with MLD address can produce incorrect traces or user-facing diagnostics.
- Regulatory names evolved from UHB to 6 GHz and from passive/no-IBSS to no-IR. Compatibility macros hide this in C but string decoders may need expected old/new names.
- The chunk ends before `enum nl80211_attr_cqm` is complete, so any final per-file synthesis must merge subsequent CQM definitions before making whole-file claims.

## Important APIs, Types, and Constants

Connection quality and transmit policy:

- `enum nl80211_attr_cqm` defines nested attributes under `NL80211_ATTR_CQM`: RSSI threshold/hysteresis, RSSI threshold events, packet loss events, TX error rate/packet/interval configuration, beacon loss events, and the RSSI level that triggered a notification.
- `enum nl80211_cqm_rssi_threshold_event` reports low/high RSSI threshold crossings; the beacon-loss event value is reserved and documented as never sent.
- `enum nl80211_tx_power_setting`, `enum nl80211_tid_config`, and `enum nl80211_tx_rate_setting` encode automatic, limited, fixed, enabled, or disabled modes for TX power/rate and TID behavior.
- `enum nl80211_tid_config_attr` carries per-VIF and per-peer TID configuration support bitmaps and settings: override behavior, TID bitmask, no-ACK policy, short/long retry counts, AMPDU/RTS-CTS/AMSDU controls, and TX rate type/rate mask via `NL80211_ATTR_TX_RATES`.

Packet pattern, WoWLAN, TCP wake, and coalescing:

- `enum nl80211_packet_pattern_attr` describes nested packet match rules using a pattern blob, little-endian-style bit mask, and packet offset. Matching is described against converted 802.3/MSDU payloads rather than raw 802.11 frames.
- `struct nl80211_pattern_support` is a packed capability structure with max pattern count, min/max pattern length, and max packet offset. Compatibility macros map older WoWLAN packet-pattern names to the generic packet-pattern namespace.
- `enum nl80211_wowlan_triggers` defines wake triggers such as any activity, disconnect, magic packet, packet patterns, GTK rekey failure/support, EAP identity request, 4-way handshake, rfkill release, wakeup packet reporting for 802.11/802.3 frames, TCP connection wake, net-detect wake, and unprotected deauth/disassoc wake reporting.
- The TCP wake DOC block defines a stateful offload in which firmware establishes a TCP connection, sends keepalive payloads, optionally writes a little-endian payload sequence number and token stream into those payloads, compares inbound payloads with a wake mask, and wakes the host on match, connection loss, setup failure, or token exhaustion. It explicitly depends on ARP offload.
- `struct nl80211_wowlan_tcp_data_seq`, `struct nl80211_wowlan_tcp_data_token`, and `struct nl80211_wowlan_tcp_data_token_feature` define TCP wake sequence/token wire data.
- `enum nl80211_wowlan_tcp_attrs` carries source/destination IPv4 addresses, destination MAC, source/destination ports, keepalive payload, optional sequence/token config, data interval, wake payload, and wake mask.
- `struct nl80211_coalesce_rule_support`, `enum nl80211_attr_coalesce_rule`, and `enum nl80211_coalesce_condition` advertise and configure packet coalescing limits, pattern support, delay, and match/no-match behavior.

Interface, mesh, key, station, and TDLS support:

- `enum nl80211_iface_limit_attrs` and `enum nl80211_if_combination_attrs` describe supported interface combinations, including per-type limits, total max interfaces, number of channels, beacon interval matching, radar-detection channel width/region bitmaps, and minimum beacon interval GCD.
- `enum nl80211_plink_state` and `enum nl80211_plink_action` model mesh peer-link FSM states and userspace actions such as open or block.
- GTK rekey constants define KCK/KEK/replay counter sizes: `NL80211_KCK_LEN`, `NL80211_KEK_LEN`, extended KCK/KEK sizes, and `NL80211_REPLAY_CTR_LEN`.
- `enum nl80211_rekey_data` transports GTK rekey offload material: KEK, KCK, replay counter, and AKM suite data.
- `enum nl80211_hidden_ssid` selects whether AP beacons expose the SSID normally, with a zero-length SSID IE, or with zeroed contents.
- `enum nl80211_sta_wme_attr` carries station U-APSD queue bitmaps and max service period.
- `enum nl80211_pmksa_candidate_attr` reports PMKSA caching candidates with priority index, BSSID, and pre-authentication support.
- `enum nl80211_tdls_operation` and `enum nl80211_tdls_peer_capability` describe TDLS discovery/setup/teardown/enable/disable operations and peer HT/VHT/WMM/HE capability flags.
- `enum nl80211_ap_sme_features` currently advertises AP SA Query offload support, tied to the userspace `NL80211_AP_SETTINGS_SA_QUERY_OFFLOAD_SUPPORT` flag defined later.

Feature and protocol capability bitmaps:

- `enum nl80211_feature_flags` is the original 32-bit feature bitmap. It covers TX status reflection, HT IBSS, inactivity timer, cellular regulatory hints, SAE, scan flush and low-priority scan, AP scan, per-VIF TX power, OBSS scan expectations, P2P GO powersave controls, full AP client state, userspace MPM, active monitor, AP mode channel-width changes, probe request IE insertion, quiet/TPC/dynack support, SMPS support, WMM admission, MAC-on-create, TDLS channel switch, and scan/sched-scan/net-detect random MAC support. Bit 13 is reserved and bit 31 uses `1U << 31`.
- `enum nl80211_ext_feature_index` extends capability reporting as bit indexes in `NL80211_ATTR_EXT_FEATURES`. It covers VHT IBSS, RRM, MU-MIMO sniffer, scan start time and parent TSF reporting, dwell-time controls, beacon rate support through EHT, FILS station/SK/crypto offloads, randomized management/auth/deauth TA, sched-scan RSSI behavior, CQM RSSI lists, station/AP 4-way handshake offloads, OCE/FILS scan behavior, MFP optional, DFS offload/concurrent/background support, control-port-over-nl80211 and TX status, ACK signal support, TXQs, random probe sequence numbers, minimal probe request contents, FTM responder, PTK0 replacement safety, Extended Key ID, airtime fairness/AQL, AP PMKSA caching, station TX power, SAE offloads, VLAN offload, beacon protection, protected TWT, IBSS STA deletion, multicast management registrations, kHz scan frequencies, OCV, FILS discovery, unsolicited broadcast probe response, secure LTF/RTT/ranging negotiation, BSS color, powered address change, puncturing, secure NAN, OWE offloads, SPP A-MSDU, EPPKE, association frame encryption, and IEEE 802.1X authentication via authentication frames.
- `NL80211_EXT_FEATURE_DATA_ACK_SIGNAL_SUPPORT` is an alias of `NL80211_EXT_FEATURE_ACK_SIGNAL_SUPPORT`; `NL80211_EXT_FEATURE_SCHED_SCAN_BAND_SPECIFIC_RSSI_THOLD` is marked obsolete but remains ABI-visible.
- `enum nl80211_probe_resp_offload_support_attr` is a bitmap for probe-response offload protocol support: WPS, WPS2, P2P, and 802.11u.
- `enum nl80211_protocol_features` currently defines split wiphy dump support with optional wiphy/interface/wdev filtering.

Connection, scan, channel, and management-frame controls:

- `enum nl80211_connect_failed_reason` reports AP-side failures such as max clients reached or ACL rejection.
- `enum nl80211_timeout_reason` distinguishes scan, authentication, and association timeouts.
- `enum nl80211_scan_flags` controls scan/scheduled-scan behavior: low priority, cache flush, AP scan, random MAC, FILS max channel time, broadcast probe responses, OCE high-rate/deferral behavior, low-span/low-power/high-accuracy modes, randomized sequence numbers, minimal probe request content, kHz frequency reporting, and collocated 6 GHz scanning through RNR information.
- `enum nl80211_acl_policy` encodes allow-all-except-listed or deny-all-except-listed MAC ACL behavior for AP commands.
- `enum nl80211_smps_mode` selects AP SMPS off/static/dynamic modes.
- `enum nl80211_radar_event` and `enum nl80211_dfs_state` define DFS event/state reporting: radar detected, CAC started/finished/aborted, NOP finished, pre-CAC expired, and channel states usable/unavailable/available.
- `enum nl80211_crit_proto_id` and `NL80211_CRIT_PROTO_MAX_DURATION` describe critical protocol protection windows for DHCP, EAPOL, and APIPA, limited to 5000 ms.
- `enum nl80211_rxmgmt_flags` reports whether a received management frame was answered by the device/driver and whether external authentication handling is intended.

Vendor, scheduled scan, and BSS selection:

- `NL80211_VENDOR_ID_IS_LINUX` reserves the top bit of vendor IDs to distinguish Linux nl80211 IDs from 24-bit OUIs, although the comment says no such Linux IDs are allocated yet.
- `struct nl80211_vendor_cmd_info` contains a `vendor_id` and vendor subcommand. Decoders must treat the vendor ID top bit specially.
- `enum nl80211_sched_scan_plan` carries scheduled-scan interval and iteration count. The last scan plan omits iterations and runs indefinitely; zero iterations is invalid.
- `struct nl80211_bss_select_rssi_adjust` is a packed two-byte band/delta tuple for driver-side BSS selection.
- `enum nl80211_bss_select_attr` requires exactly one nested BSS selection policy for connect: RSSI-only, preferred band, or band-specific RSSI adjustment.

NAN discovery, configuration, and capabilities:

- `enum nl80211_nan_function_type`, `enum nl80211_nan_publish_type`, and `enum nl80211_nan_func_term_reason` encode publish/subscribe/follow-up function types, solicited/unsolicited publish mode flags, and termination reasons.
- NAN constants define a 6-byte service ID hash and 255-byte maxima for service-specific info and service receive filters.
- `enum nl80211_nan_func_attributes` models NAN function configuration and event data: type, service ID, publish/subscribe/follow-up parameters, destination, close-range flag, TTL in discovery windows, service info, service receive filter, RX/TX match filters, instance ID, and termination reason.
- `enum nl80211_nan_srf_attributes` describes service response filters. It supports an include flag and either a bloom filter with index or a nested MAC address list, but not both.
- `enum nl80211_nan_match_attributes` reports local and peer NAN functions involved in a match.
- `enum nl80211_nan_band_conf_attributes` carries per-band NAN discovery configuration: band, optional 5 GHz discovery frequency, close/middle RSSI thresholds, wake discovery window cadence, and scan disable flag. The comments constrain frequencies, threshold ordering, and 2.4 GHz wake/scan behavior.
- `enum nl80211_nan_conf_attributes` configures NAN cluster ID, extra beacon attributes, vendor elements, per-band configs, scan period, scan dwell time, discovery beacon interval, and discovery-window notifications. The cluster ID is ignored on `NL80211_CMD_CHANGE_NAN_CONFIG` after NAN start because the cluster cannot change live.
- `enum nl80211_nan_capabilities` advertises configurable synchronization, userspace Discovery Engine mode, operation modes, antenna counts, max channel switch time, Wi-Fi Aware capability bits, and PHY capabilities. In userspace-DE mode, add/delete/match NAN function commands should not be used; discovery window notifications and SDF frame TX/RX via `NL80211_CMD_FRAME` are expected instead.
- `enum nl80211_nan_peer_map_attrs` defines nested peer schedule maps with a map ID and 32 time slots. `NL80211_NAN_SCHED_NOT_AVAIL_SLOT` (`0xff`) marks an unavailable slot.

Authentication, FTM responder, and peer measurement:

- `enum nl80211_external_auth_action` starts or aborts an external authentication exchange.
- `enum nl80211_ftm_responder_attributes` enables FTM responder operation and carries LCI/Civic measurement report contents.
- `enum nl80211_ftm_responder_stats` reports responder session counters and total duration, with a padding attribute for 64-bit alignment.
- `enum nl80211_preamble` defines legacy, HT, VHT, DMG, and HE preamble types for measurement/rate contexts.
- `enum nl80211_peer_measurement_type` currently defines FTM as the only peer measurement type.
- `enum nl80211_peer_measurement_status` reports success, local refusal, timeout, or failure.
- `enum nl80211_peer_measurement_req`, `enum nl80211_peer_measurement_resp`, `enum nl80211_peer_measurement_peer_attrs`, and `enum nl80211_peer_measurement_attrs` form the generic peer measurement nesting: global capabilities, peer list, per-peer address/channel/request/response, type-indexed request/response data, status, host time, AP TSF, final-result flag, and padding.
- `enum nl80211_peer_measurement_ftm_capa` advertises FTM modes and limits: ASAP/non-ASAP, LCI/Civic requests, preamble bitmap, bandwidth bitmap, burst/FTM-per-burst limits, trigger/non-trigger support, 6 GHz support, LTF repetition and STS maxima, total LTF limits, and RSTA support.
- `enum nl80211_peer_measurement_ftm_req` carries FTM request parameters: ASAP, preamble, bursts exponent, burst period/duration, FTMs per burst, FTMR retries, LCI/Civic requests, trigger/non-trigger flags, LMR feedback, BSS color, and RSTA mode. Trigger-based and non-trigger-based flags are mutually exclusive; if neither is set, EDCA-based ranging is used.
- `enum nl80211_peer_measurement_ftm_failure_reasons` reports no response, rejection, wrong channel, peer not capable, invalid timestamp, peer busy, and changed unsupported parameters.
- `enum nl80211_peer_measurement_ftm_resp` returns failure reason, burst index, FTMR attempts/successes, busy retry time, responder-selected burst parameters, RSSI metrics, TX/RX rates using `enum nl80211_rate_info`, RTT and distance metrics, LCI/Civic payloads, padding, and burst period.

HE/6 GHz, AP, regulatory exposure, and radio capability:

- `enum nl80211_obss_pd_attributes` carries HE OBSS packet detection settings: min/max offsets, non-SRG max offset, BSS color bitmap, partial BSSID bitmap, and SR control.
- `enum nl80211_bss_color_attributes` reports BSS color value, disabled state, and partial AID equation.
- `enum nl80211_iftype_akm_attributes` maps interface types to supported AKM suite arrays.
- `enum nl80211_fils_discovery_attributes` configures FILS discovery intervals and action-frame template data; `NL80211_FILS_DISCOVERY_TMPL_MIN_LEN` is 42 bytes.
- `enum nl80211_unsol_bcast_probe_resp_attributes` configures 6 GHz unsolicited broadcast probe response interval and template; interval zero disables the feature.
- `enum nl80211_sae_pwe_mechanism` selects unspecified, hunting-and-pecking, hash-to-element, or both SAE PWE derivation mechanisms for WPA3-Personal SAE.
- `enum nl80211_sar_type`, `enum nl80211_sar_attrs`, and `enum nl80211_sar_specs_attrs` define SAR power-limit requests and capability dumps. Power units are 0.25 dBm. SET operations provide power and range index; capability dumps provide start/end frequency ranges in kHz. Every SET overwrites the previous one, must include at least one range, and must not duplicate ranges.
- `enum nl80211_mbssid_config_attributes` configures MBSSID/EMA AP operation and advertises support: max interfaces, max EMA profile periodicity, BSS index, transmitted-profile ifindex, EMA enable flag, and transmitted-profile link ID for MLD cases.
- `enum nl80211_ap_settings_flags` advertises userspace AP support for external authentication and SA Query offload.
- `enum nl80211_wiphy_radio_attrs` and `enum nl80211_wiphy_radio_freq_range` describe per-radio capability exposure: radio index, repeated frequency ranges, repeated interface combinations, antenna mask, RTS threshold, and kHz start/end frequencies.
- `enum nl80211_s1g_short_beacon_attrs` carries S1G short beacon head and tail binary templates.

## Protocol and Control Flow

This chunk has no C control flow, but it defines multiple protocol flows over nested netlink attributes:

1. CQM flow: userspace configures `NL80211_ATTR_CQM` with RSSI, packet-loss, TX error, or beacon-loss monitoring thresholds. The kernel/driver later emits `NL80211_CMD_NOTIFY_CQM` with the relevant nested event attributes and, for RSSI, the current level.
2. Per-TID policy flow: userspace sends `NL80211_CMD_SET_TID_CONFIG` with TID masks, override flags, and per-peer or per-VIF settings. Drivers advertise supported per-VIF/per-peer attributes in capability dumps. The header makes overwrite-vs-preserve behavior explicit through `NL80211_TID_CONFIG_ATTR_OVERRIDE`.
3. WoWLAN flow: userspace configures supported trigger attributes before suspend. Firmware may wake on fixed events, packet patterns, net-detect matches, TCP wake pattern matches, connection failures, or security events. Wake reporting reuses the same nested trigger namespace but includes reason-specific report-only attributes such as wake packet data, original lengths, TCP result flags, and net-detect result arrays.
4. TCP wake subflow: firmware establishes a TCP connection, sends keepalive payloads at an interval, mutates payload sequence/token fields if configured, compares inbound payload data using a wake mask, and wakes the host on match or connection/token failure. ARP offload is a documented prerequisite for correct response handling.
5. Interface-combination flow: `GET_WIPHY` capability dumps expose nested combinations and limits; userspace must choose interface sets and channel/beacon interval plans that fit one advertised combination.
6. DFS flow: channels move among usable, unavailable, and available states. CAC and radar events notify userspace whether it must vacate a channel, may begin using it, or must repeat CAC. With DFS offload, hardware/driver may emit CAC-started and other DFS progress events without userspace initiating every step.
7. Scan flow: trigger and scheduled scans use bitmask flags to request privacy, power/latency/accuracy tradeoffs, frequency unit reporting, and 6 GHz colocated AP discovery. Some flags are mutually exclusive or require corresponding feature bits.
8. NAN flow: userspace starts NAN with `NL80211_NAN_CONF_*`, then either uses kernel/firmware-offloaded publish/subscribe/follow-up functions or, if `NL80211_NAN_CAPA_USERSPACE_DE` is set, handles Discovery Engine logic in userspace using DW notifications and SDF frames. NAN match and termination events carry nested function attributes.
9. FTM/PMSR flow: userspace reads peer measurement capabilities, sends a peer list with per-peer channel and type-specific request data, and receives one or more responses. The top-level response can mark partial results vs final result; FTM-specific data supplies RTT/distance, rates, RSSI, responder parameters, and failure details.
10. SAR flow: drivers advertise SAR frequency ranges; userspace sends power limits by range index. A new SET operation replaces the previous SAR configuration rather than merging with it.
11. MBSSID/EMA flow: the kernel advertises maximum MBSSID/EMA support, while userspace configures BSS indexes, transmitted-profile ifindex/link ID, and EMA enablement when starting/configuring AP interfaces.

## State and Persistence Behavior

The header itself does not allocate or persist state, but the ABI describes stateful behavior in the kernel, firmware, and userspace:

- CQM, per-TID settings, scan plans, WoWLAN triggers, coalesce rules, AP settings, SAR limits, MBSSID/EMA settings, NAN configuration, FTM responder state, and peer measurement requests all represent kernel/driver state that persists beyond a single netlink message until changed, canceled, connection state changes, suspend/resume completes, or the owning interface/device is torn down.
- WoWLAN trigger state is specifically suspend-oriented. The active trigger set is evaluated while the host is asleep, and wake-report attributes describe why the device resumed.
- TCP wake maintains connection state, keepalive payload sequence/token state, and wake pattern state inside the device/firmware during suspend.
- Scheduled scan plans persist across iterations. The final plan can be infinite by omitting the iteration attribute.
- NAN started configuration persists for the lifetime of the NAN instance. Cluster ID cannot be changed through `CHANGE_NAN_CONFIG` after start, while scan period, dwell time, band config, beacon interval, and DW notification behavior are configuration state.
- NAN functions have individual lifetimes controlled by TTL, user deletion, error, or match-related events. Instance ID zero is invalid.
- Peer measurement responses may be incremental. `NL80211_PMSR_RESP_ATTR_FINAL` distinguishes partial burst results from final/composite results.
- SAR SET operations overwrite previous SAR power-limit state, skipped advertised ranges are treated as unrestricted by userspace SAR limits, and duplicated ranges in a single operation are invalid.
- MBSSID index assignment is userspace-owned; userspace is responsible for unique indices within the advertised range.
- Feature bitmaps and capability nested attributes are mostly read-only snapshots of driver/wiphy capabilities, but they gate which stateful commands userspace may safely request.

## Dependencies and Integration Points

Direct type dependencies are inherited from the earlier include of `<linux/types.h>`: this range uses `__u8`, `__s8`, `__u16`, `__u32`, and flexible arrays. Wire structs requiring exact layout include `struct nl80211_pattern_support`, `struct nl80211_coalesce_rule_support`, and `struct nl80211_bss_select_rssi_adjust`, all marked packed. TCP token data uses a flexible `__u8 token_stream[]` tail and therefore requires length-aware parsing.

Kernel integration points:

- `net/wireless/nl80211.c` validates these nested attributes against policy, command context, feature flags, and interface type. The `*_MAX` sentinels in this chunk are natural policy bounds.
- cfg80211/mac80211 and device drivers implement or advertise the described capabilities: WoWLAN, coalescing, interface combinations, DFS, TDLS, FILS, SAE/OWE offloads, NAN, FTM/PMSR, SAR, MBSSID/EMA, radio-level constraints, S1G beacon support, and HE spatial reuse/BSS color support.
- Firmware is often the actual executor for WoWLAN, TCP wake, GTK rekey, scan offloads, FTM responder, NAN, and SAR enforcement.
- IEEE 802.11 family specifications are referenced throughout for FILS discovery, FTM measurement reports, ranging parameters, NAN role/state transitions, Wi-Fi Aware capabilities, 6 GHz unsolicited probe responses, SAE PWE behavior, and association-frame encryption/authentication features.

Userspace and local repository integration points:

- `wpa_supplicant`, `hostapd`, `iw`, iwd/NetworkManager, and vendor tools consume these attributes for wireless configuration and event handling.
- strace decoders need the enum names, bit positions, aliases, and nested attribute maxima to turn captured generic netlink data into meaningful symbolic traces.
- Tests for this repository should treat these declarations as ABI inputs rather than implementation logic. The important local behavior is correct decoding of numeric constants, bitmasks, nested attributes, packed structs, and compatibility aliases.

## Risks and Edge Cases

- ABI ordering is critical. Adding entries anywhere other than the documented append-before-sentinel locations, renumbering flags, or changing aliases would break userspace and strace xlat expectations.
- Some enum families are bit positions (`nl80211_ext_feature_index`), some are bit masks (`nl80211_feature_flags`, scan flags, publish type flags), and some are ordinary integer values. Confusing these categories is a common decoder bug.
- `*_MAX`, `NUM_*`, and `*_AFTER_LAST` sentinels are validation/iteration helpers, not real wire values in normal messages. Decoders should avoid reporting sentinel values as normal operational states unless tracing malformed input.
- Attribute types are documented in comments, not enforced by C declarations: many values are `u8`, `s8`, `u16`, `u32`, signed `s32`/`s64`, `u64`, binary blobs, nested arrays, flag attributes, or packed structs. Incorrect typing will corrupt traces.
- Packed structs and 64-bit alignment matter. FTM responder stats and PMSR responses include pad attributes; pattern/coalesce/BSS-selection structs are packed wire records.
- Packet pattern masks use a little-endian-like bit layout, and matching is against converted 802.3/MSDU data. Decoders or tests that assume raw 802.11 frame offsets can misrepresent behavior.
- WoWLAN trigger attributes are dual-use: the same nested namespace advertises support, configures triggers, and reports wake reasons. Attribute meaning can change with context, such as packet pattern support struct vs wake pattern index.
- `NL80211_WOWLAN_TRIG_ANY` is incompatible with other WoWLAN modes; a validator or test should expect rejection if combined with other triggers.
- TCP wake payload sequence numbers are not TCP header sequence numbers; they are little-endian values written into the keepalive payload.
- Sensitive data appears in rekey offload and wake/offload contexts. KCK, KEK, replay counters, token streams, and authentication/offload material should not be logged casually by higher-level tools.
- Scan flags have feature dependencies and mutual exclusions: low-span, low-power, and high-accuracy are exclusive; random MAC/SN and kHz frequency behavior require advertised support.
- NAN SRF bloom filter and MAC address list forms are mutually exclusive. NAN RSSI close/middle thresholds should be configured together and obey ordering. NAN 2.4 GHz band restrictions make some wake/scan-disable combinations invalid.
- FTM request flags have mutual exclusions and dependent validity: trigger and non-trigger modes are exclusive; LMR feedback and RSTA have additional constraints.
- SAR range handling is overwrite-based, requires at least one range, rejects duplicate ranges, and treats skipped ranges as unrestricted by userspace SAR. Merge logic must not infer incremental updates.
- MBSSID/EMA uses indexes, ifindexes, and, in MLD cases, link IDs. Confusing transmitted and non-transmitted profile identifiers can produce invalid AP configuration traces.
- Vendor IDs require top-bit interpretation. A value with `NL80211_VENDOR_ID_IS_LINUX` clear is a 24-bit OUI; with it set, it is a Linux nl80211 ID space that the comment says currently has no allocated IDs.
