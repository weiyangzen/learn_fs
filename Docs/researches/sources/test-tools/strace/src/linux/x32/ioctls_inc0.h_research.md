# sources/test-tools/strace/src/linux/x32/ioctls_inc0.h

## Purpose
Provides the generated x32 ioctl catalogue used by strace's ioctl-name lookup tooling. It is generated by `ioctls_gen.sh` from Linux kernel include definitions and contains 3,385 initializer rows mapping kernel header provenance, ioctl symbol names, direction bits, encoded request numbers, and encoded argument sizes.

## Important APIs, Types, And Data
The file is not a standalone C header with declarations; it is an include fragment intended to be included inside an initializer list. Each row has the generated shape `{ "header/path.h", "SYMBOL", direction, request_code, size }`. The consumers normalize this into `struct ioctlent`/ioctl sorting data, whose exported compact form uses `const char *symbol` plus an encoded unsigned integer request code. Direction values include `_IOC_NONE`, `_IOC_READ`, `_IOC_WRITE`, `_IOC_READ|_IOC_WRITE`, and legacy zero-direction entries. The table covers broad Linux UAPI families: 2,392 entries from `linux/*`, 468 from `drm/*`, 218 from `sound/*`, 83 from `asm-generic/*`, plus mtd, misc, scsi, net, video, xen, rdma, media, fwctl, and acpi headers.

## Control Flow
There is no executable control flow in the fragment. Build/test utilities include it while constructing a static array, then sorting/deduplicating that array by ioctl code and symbol prefix. At runtime, the generated lookup output lets strace translate raw ioctl request numbers observed in tracees into stable symbolic names. Collisions and architecture-dependent layouts are represented directly as multiple rows; the sorter chooses the compact emitted representation after comparing encoded codes and names.

## State And Persistence
The file persists generated kernel ABI knowledge in source form. It has no mutable state, allocation, I/O, or side effects. Its important persistence behavior is reproducibility: changes should come from rerunning the generator against a specific Linux header tree, not hand-editing individual rows.

## Dependencies And Integration Points
Depends on the ioctl-generation pipeline and Linux UAPI header definitions. It integrates with `ioctlsort.c`, `ioctls_arch.h`, `ioctls_inc.h`, and the architecture include arrangement used by x86_64/x32/i386. `sources/test-tools/strace/src/linux/x86_64/ioctls_inc2.h` includes this x32 table, while `ioctls_inc1.h` in the x32 directory reuses the i386 table for the adjacent personality. The encoded rows rely on `_IOC_*` macros being visible in the including translation unit.

## Risks
The main risk is ABI drift: stale generated rows cause strace to misname or omit new ioctl commands. A second risk is architecture-size skew, especially for commands whose encoded size differs between 32-bit, x32, and 64-bit personalities. Generated duplicate request numbers are expected for aliases and versioned structs, but accidental reordering or hand edits could change which name survives compact sorting. Very large rows such as sound and DRM structs also make size-field correctness important for decoder selection and tests.

## Test Signals
Useful signals include rerunning the ioctl generator/sorter, comparing generated output against the current kernel UAPI headers, building the strace ioctl tables for x32/x86_64, and exercising ioctl decoding tests that expect symbolic names for tty, socket, DRM, sound, filesystem, and xen request families. A high-value regression check is that table counts and direction buckets remain explainable after regeneration; this copy has 556 `_IOC_NONE`, 582 read-only, 913 write-only, 933 read/write, and 401 zero/legacy-direction rows.
