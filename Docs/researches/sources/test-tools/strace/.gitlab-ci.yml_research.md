# sources/test-tools/strace/.gitlab-ci.yml

Purpose: GitLab CI definition for strace build and test coverage across compilers, bitness, stack unwinding providers, and kernel header modes.

Important jobs: all jobs run `ci/run-build-and-tests.sh` after `ci/install-dependencies.sh` in an `ubuntu:18.04` container. Variables set `GIT_DEPTH` to a large value, `SLEEP_A_BIT`, and `VERBOSE`. Job variants include gcc and clang, x86_64 and x86, libdw/libunwind/no stacktrace, and a mainline kernel headers lane.

Control flow: declarative per-job variables drive the shared CI script. There is no explicit stage list beyond each job's `stage: test`.

State and persistence: build outputs and logs are GitLab runner-local unless configured globally outside this file.

Dependencies and integration: integrates with the same `ci/` scripts as GitHub Actions, giving a second CI provider route.

Risks: Ubuntu 18.04 is old and may drift from GitHub's newer runner coverage. There is duplication with GitHub matrix semantics, so adding variants requires changes in multiple files. Test signals: GitLab pipelines should show each named compiler/target lane and fail in the common build script rather than in dependency installation.
