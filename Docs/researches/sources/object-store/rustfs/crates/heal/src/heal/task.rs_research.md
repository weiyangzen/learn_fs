# sources/object-store/rustfs/crates/heal/src/heal/task.rs

`task.rs` implements heal work units. It defines `HealType`, `HealPriority`, `HealOptions`, `HealTaskStatus`, `HealRequest`, and `HealTask`. A task owns async-locked status, progress, result items, timestamps, a monotonic timeout instant, cancellation token, and `Arc<dyn HealStorageAPI>`. `execute` marks the task running, records queue-delay/start metrics, dispatches by heal type, then records completed/cancelled/timeout/failed state.

The key helper is `await_with_control`, which wraps storage futures with cancellation and remaining-timeout handling. Object healing checks existence, skips transient existence errors as completed work, optionally recreates missing objects, calls storage `heal_object`, treats not-found races as deleted, optionally deletes corrupted objects, records `HealResultItem`, and updates progress. Bucket healing verifies bucket existence, calls `heal_bucket`, and in recursive mode pages through objects and heals each one. Metadata, MRF, and EC decode use specialized `HealOpts`. Erasure-set healing performs format repair, resolves a resume disk, heals bucket structures, creates `ErasureSetHealer`, and executes resumable healing.

State is in-memory; persistent repair happens in storage and erasure-set components. Integration points include `HealProgress`, `HealStorageAPI`, `ErasureSetHealer`, ECStore metadata constants, `metrics`, `tracing`, and `CancellationToken`. Risks include string-based error classification, long sequential recursive bucket scans, and careful interpretation of progress counters. Tests cover recursive behavior, metadata remove suppression, data-usage-cache transient skips, and transient existence precheck skips.
