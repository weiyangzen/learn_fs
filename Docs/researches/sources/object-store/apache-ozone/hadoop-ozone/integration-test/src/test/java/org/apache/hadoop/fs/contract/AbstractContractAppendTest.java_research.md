# sources/object-store/apache-ozone/hadoop-ozone/integration-test/src/test/java/org/apache/hadoop/fs/contract/AbstractContractAppendTest.java

Purpose: `AbstractContractAppendTest` is an abstract JUnit 5 contract suite for filesystems that declare `SUPPORTS_APPEND`. It validates both the legacy `FileSystem.append(Path)` API and the builder-style `FileSystem.appendFile(Path).build()` API against empty, existing, missing, and renamed files.

Important APIs/types/functions: the class extends `AbstractFSContractTestBase`; uses `FSDataOutputStream`, `Path`, `CommonPathCapabilities.FS_APPEND`, `ContractTestUtils.touch`, `createFile`, `dataset`, `readDataset`, `compareByteArrays`, `validateFileContent`, and `assertHasPathCapabilities`. The shared `setup()` calls `skipIfUnsupported(SUPPORTS_APPEND)` and initializes `testPath` and `target`.

Control flow: each test creates or probes `target` under a method-scoped test directory. The empty-file tests touch a file, append generated bytes, close the stream, then read the exact length back. Existing-file tests write an original block, append a second block, and verify concatenated byte segments. Missing-target tests expect an exception and pass it through `handleExpectedException`. `testRenameFileBeingAppended` opens an append stream, optionally sleeps for delayed visibility filesystems, writes bytes, renames the target while the stream is open, closes the stream, then verifies content lives at the renamed path.

State and persistence behavior: the tests mutate filesystem objects through stream lifecycle boundaries. The rename-while-appending case is the strongest persistence signal: data written through an already-open append stream must be committed to the inode/object represented by the renamed destination rather than recreating the old source path.

Dependencies and integration points: depends on contract flags (`SUPPORTS_APPEND`, `CREATE_VISIBILITY_DELAYED`) and path-capability reporting. Concrete Ozone contract subclasses provide the `AbstractFSContract` and filesystem binding.

Risks and test signals: these tests catch append implementations that silently create missing files, lose appended bytes, mishandle builder append, report append capability incorrectly, or bind open append streams to path names rather than file identities. Object-store-like visibility delays are tolerated only in the rename test via the contract flag.
