# sources/object-store/apache-ozone/hadoop-ozone/integration-test/src/test/java/org/apache/hadoop/fs/contract/ContractTestUtils.java

Purpose: `ContractTestUtils` is a broad, static utility class used by filesystem contract and Ozone integration tests. It centralizes byte-pattern file generation, write/read verification, cleanup, path existence assertions, listing conversion, recursive tree construction/scanning, capability assertions, vectored-read validation, and simple timing/bandwidth diagnostics. In this subset it is the shared assertion and fixture layer used by both `OzoneFileSystem` and `RootedOzoneFileSystem` tests.

Important APIs and types: The class exposes helpers around Hadoop `FileSystem`, `FileContext`, `FSDataInputStream`, `FSDataOutputStream`, `FileStatus`, `LocatedFileStatus`, `RemoteIterator`, `FileRange`, `ByteBufferPool`, `StreamCapabilities`, and `PathCapabilities`. Key APIs include `writeAndRead`, `writeDataset`, `readDataset`, `verifyFileContents`, `compareByteArrays`, `createFile`, `touch`, `appendFile`, `assertDeleted`, `assertRenameOutcome`, `assertIsFile`, `assertIsDirectory`, `assertPathExists`, `assertPathDoesNotExist`, `dataset`, `validateVectoredReadResult`, `returnBuffersToPoolPostRead`, `createAndVerifyFile`, `createSubdirs`, `treeWalk`, iterator-to-list helpers, and capability assertion helpers. Nested `TreeScanResults` stores categorized path lists, and `NanoTimer` records elapsed time and bandwidth.

Control flow: Most helpers follow an execute-and-assert pattern: create parents, write bytes, read back exactly, compare every byte, then optionally delete and verify absence. Assertion failures add context by listing parents, dumping file statuses, or logging nearby bytes around the first mismatch. Root-sensitive operations call `rejectRootOperation` before delete or rename unless explicitly allowed. Listing helpers normalize Hadoop `RemoteIterator` results into lists and include a `next()`-only path to test iterator correctness without prior `hasNext()` calls. Tree helpers recursively create deterministic directory/file layouts and recursively scan depth-first to compare actual listings with expected structures.

State and persistence behavior: The utilities do not own persistent state, but they create, mutate, and delete files and directories in the target filesystem under test. They also read filesystem configuration for buffer/modulus sizing, use generated UUID names for large-file tests, and may return pooled buffers after vectored reads. `TreeScanResults` holds in-memory snapshots of files, directories, and other statuses; equality intentionally compares counts while `assertEquivalent` checks exact path membership and duplicates. `NanoTimer` holds only start and end timestamps.

Dependencies and integration points: The file depends on AssertJ, Hadoop filesystem APIs, `RemoteIterators`, `FutureIO`, and SLF4J. Ozone tests call these helpers to avoid duplicating common touch/create/delete/list assertions. Capability helpers integrate with stream and path capability contracts such as `StreamCapabilities.UNBUFFER`; vectored-read helpers integrate with Hadoop asynchronous range-read APIs.

Risks: These helpers are assertion-heavy and can shape test semantics across many suites. Root-operation guards are important because a mistaken path can delete an entire test filesystem. `readDataset` expects the requested length to be readable and throws EOF if not. `compareByteArrays` assumes equal length and logs only a small error window. `TreeScanResults.dump` labels files and directories in a confusing order, which can affect diagnostics but not behavior. Vectored read validation depends on bounded future timeouts and returns buffers only when callers invoke the pool-return helper.

Test signals: Strong signals are exact byte equality, file length equality, successful path existence/non-existence checks, expected delete/rename return values, duplicate-free listing equivalence, expected recursive tree counts, correct vectored-read ranges, explicit presence or absence of stream/path capabilities, and bandwidth/timer logs for large-file exercises.
