# sources/object-store/apache-ozone/hadoop-ozone/integration-test/src/test/java/org/apache/hadoop/fs/ozone/AbstractRootedOzoneFileSystemTest.java

Purpose: This abstract suite validates `RootedOzoneFileSystem` (`ofs`) behavior across the full namespace rooted at `/`, where paths include `/volume/bucket/key` and may also reference special mounts such as `/tmp`. It covers volume and bucket creation/deletion, bucket-level listings, recursive adapter listings, ACL-sensitive root listing, trash across buckets, link buckets, symlink-like shell semantics, replication inheritance, content summary disk usage, snapshots and snapshot diff, linked-bucket `setTimes`, and DistCp replication behavior.

Important APIs and types: The suite uses `RootedOzoneFileSystem`, `BasicRootedOzoneClientAdapterImpl`, `OFSPath`, `MiniOzoneCluster`, `OzoneClient`, `ObjectStore`, `ClientProtocol`, `OzoneVolume`, `OzoneBucket`, `BucketArgs`, `VolumeArgs`, `OzoneAcl`, `OMMetrics`, `Trash`, `OzoneFsShell`, `DistCp`, `DistCpOptions`, `CopyMapper.Counter`, `SnapshotDiffReport`, `ContentSummary`, `QuotaUtil`, `ECReplicationConfig`, `RatisReplicationConfig`, and common Hadoop `FileSystem` types. It inherits shared filesystem behavior checks from `OzoneFileSystemTestBase`.

Control flow: `initClusterAndEnv` builds a five-datanode cluster, configures trash, hsync, ACL authorizer, bucket layout defaults, list batch size, snapshot diff page size, and `ofs://` default filesystem, then opens both admin and non-privileged OFS instances. `createVolumeAndBucket` creates a fresh test volume/bucket before each test and `cleanup` deletes it after each test. Tests often create additional random volumes/buckets, use public OFS paths to mutate them, then verify through both `FileSystem` and object-store APIs. Recursive listing tests compare adapter-level DFS results with a simulated recursive `FileSystem.listStatus` traversal.

State and persistence behavior: Persistent state includes real Ozone volumes, buckets, keys, link buckets, trash directories, snapshots, EC/Ratis key metadata, ACLs, and temporary mount buckets. Tests validate deletion ordering from key to bucket to volume, non-recursive failure on non-empty directories/volumes, root deletion failure, owner propagation for volume and bucket listings, shared and per-user `/tmp` mount creation, trash checkpoints and OM trash metrics, snapshot contents, snapshot diff pagination aggregation, and DistCp-created keys. Runtime state includes the current bucket path, cluster metrics, adapter listing continuation state, and UGI-derived user paths.

Dependencies and integration points: The suite spans the Hadoop FS surface, Ozone object-store admin APIs, OM ACL enforcement, shell commands via `ToolRunner`, snapshot APIs, MapReduce DistCp, and low-level adapter listing continuations. It also checks Ozone-specific features such as link bucket loop/target behavior, non-admin bucket creation under permissive ACLs, OFS shared temp directory policy, and storage-space accounting for EC and Ratis replication.

Risks: The suite is environment- and timing-sensitive because it starts a real cluster, waits for trash emptier behavior, and uses random names. ACL-enabled and ACL-disabled modes produce different root listing counts. Several tests are skipped for FSO or filesystem-path-enabled layouts where semantics differ. Link bucket delete semantics intentionally distinguish deleting the link from deleting target contents and rely on shell path trailing-slash behavior. DistCp tests depend on MapReduce counters and checksum skip behavior. Snapshot diff assertions assume deterministic diff ordering for created keys.

Test signals: Signals include exact home directory path, volume/bucket auto-creation via `mkdirs`, `OMException` result codes for missing volume/bucket/key or permission denied, listing sizes at bucket, volume, and root levels, recursive adapter/listStatus equivalence, continuation page counts, owner/group fields, successful and failed deletes/renames, trash root counts and OM metric deltas, link bucket source preservation, root delete returning false, replication type and factor expectations, `UNBUFFER` capability, content-summary space consumed for EC/Ratis, snapshot listing and diff sizes, linked-bucket mtime update, DistCp copy counters, and skipped-copy behavior on matching checksums.
