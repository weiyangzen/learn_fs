# sources/object-store/apache-ozone/hadoop-ozone/ozone-manager/src/main/java/org/apache/hadoop/ozone/om/OzoneAclUtils.java

Purpose: `OzoneAclUtils` centralizes ACL helper logic for OM request paths. It maps multi-tenant access IDs back to user principals and performs owner-aware ACL checks across volume, bucket, key, and prefix resources.

Important APIs/types/functions: `setOMMultiTenantManager` installs the static `OMMultiTenantManager` used by `accessIdToUserPrincipal`. `checkAllAcls` applies hierarchical ACL checks through an `OmMetadataReader`. `getParentNativeAcl` converts a child ACL operation into the required parent ACL when the native authorizer is enabled. The private `isOwner` helper compares the caller short user name to an owner name.

Control flow: `accessIdToUserPrincipal` returns the access ID unchanged when no multi-tenant manager is installed or when lookup misses; otherwise it returns the principal from `getUserNameGivenAccessId`. `checkAllAcls` switches on resource type. For volumes it checks the target volume directly with owner substitution against the volume owner. For bucket, key, and prefix resources, volume owners are checked directly against the child resource using the volume owner as `{OWNER}`; non-volume owners must first pass a parent volume ACL check and then pass the child ACL check using the bucket owner as `{OWNER}`. For native authorizer bucket checks, the parent right is computed by `getParentNativeAcl`; otherwise the parent right defaults to `READ`.

State and persistence behavior: The only mutable state is the process-static multi-tenant manager reference. The file does not persist anything. ACL decisions are delegated to the supplied `OmMetadataReader`, which reads OM metadata and authorizer state.

Dependencies/integration points: It depends on `OMMultiTenantManager`, `OmMetadataReader.checkAcls`, `OmMetadataReader.isNativeAuthorizerEnabled`, `IAccessAuthorizer.ACLType`, `OzoneObj.ResourceType`, `OzoneObj.StoreType`, Hadoop `UserGroupInformation`, and caller network identity fields. The utility is used by OM handlers that need consistent ACL behavior for active metadata and snapshot metadata readers.

Risks: The static tenant manager is global process state, so tests and multi-OM lifecycles must reset or set it carefully. Owner comparison uses `getShortUserName`, which means Kerberos realm-qualified names are reduced before comparison. The parent ACL mapping is policy-sensitive: bucket creation maps to parent `WRITE`, most bucket operations map to volume `READ`, and key/prefix create/write map to bucket `WRITE` while delete/read/list/ACL operations map to bucket `READ`. Changes to native authorizer semantics must update this function and its callers together. An unexpected resource type throws `OMException(INVALID_REQUEST)`.

Test signals: Direct test references were not found in the searched subset, but snapshot ACL integration tests and OM ACL request tests exercise this helper through `checkAcls` paths. Useful targeted tests would cover access-ID fallback, volume-owner bypass behavior, non-owner parent plus child checks, native parent ACL mappings for bucket/key/prefix operations, and invalid resource types.
