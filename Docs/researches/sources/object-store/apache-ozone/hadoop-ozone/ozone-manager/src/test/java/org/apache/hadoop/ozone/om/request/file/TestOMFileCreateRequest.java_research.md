# sources/object-store/apache-ozone/hadoop-ozone/ozone-manager/src/test/java/org/apache/hadoop/ozone/om/request/file/TestOMFileCreateRequest.java

Tests default-layout `OMFileCreateRequest` for preExecute block allocation, open key table insertion, namespace quota, encryption metadata, missing volume/bucket, recursive and non-recursive path behavior, overwrite handling, ACL inheritance, client ACL filtering, reserved snapshot names, and block allocation for zero or unspecified data size.

The class extends `TestOMKeyRequest`. Key helpers are `createFileRequest`, `getOMFileCreateRequest`, `testNonRecursivePath`, `createFileWithInheritAcls`, and `verifyInheritAcls`. It uses SCM block allocation mocks, `OmKeyInfo`, `OmKeyLocationInfo`, `BucketEncryptionKeyInfo`, KMS `KeyProviderCryptoExtension`, `OzoneLockProvider`, `AllocatedBlock`, `Pipeline`, `ExcludeList`, and filesystem path utilities.

Control flow for successful creation is create request -> preExecute allocates a block and sets client ID/modification time -> validateAndUpdateCache inserts an open key table row. Blank key preExecute is special: no client ID, modification time, or key locations are set. Path tests seed parent directory markers or files, toggle recursive and overwrite flags, and assert success or one of `NOT_A_FILE`, `FILE_ALREADY_EXISTS`, or `DIRECTORY_NOT_FOUND`.

State behavior is open key table insertion keyed by key name and client ID, with block locations matching the preExecuted protobuf. Recursive creation can create parent directory state and update bucket namespace. Encryption tests seed bucket encryption key and expect file encryption info in the response. ACL tests verify default ACL inheritance and `ignoreClientACLs`. Risks include no block allocation for empty files, accepting `.snapshot` reserved roots, overwrite mistakes, quota miscounting, file/directory confusion, and lost encryption/ACL metadata. Signals are key locations, `Status.OK`, open key rows, matching block IDs, response key name, namespace usage, ACLs, encryption info, and SCM allocateBlock verification.
