# sources/object-store/apache-ozone/hadoop-ozone/ozone-manager/src/test/java/org/apache/hadoop/ozone/om/request/file/TestOMRecoverLeaseRequest.java

Tests `OMRecoverLeaseRequest` for FSO files: recovery initiation, init idempotency, non-idempotent recovery commit, recovered file length/client ID, rejection of allocate block and hsync while under recovery, closed/open/absent file behavior, and lease soft-limit enforcement.

The class extends `TestOMKeyRequest` and returns `BucketLayout.FILE_SYSTEM_OPTIMIZED`. `populateNamespace` seeds volume/bucket, parent directories, key table rows, open key table rows, block locations, and optional `HSYNC_CLIENT_ID` metadata. `validateAndUpdateCache` preExecutes and validates `OMRecoverLeaseRequest`. `validateAndUpdateCacheForCommit` drives `OMKeyCommitRequestWithFSO`. `getNewKeyArgs` rebuilds commit `KeyArgs` from recovered `OmKeyInfo` and can adjust final block length. `createAllocateBlockRequest` is used with `OMAllocateBlockRequestWithFSO` to verify writes are blocked during recovery.

State behavior spans FSO `keyTable` and `openKeyTable`: recovery returns key info and marks the file under recovery; successful recovery commit leaves a closed key row, removes the open key row, preserves adjusted data size/final block length, and removes `HSYNC_CLIENT_ID` and `LEASE_RECOVERY` metadata. Closed files return `KEY_ALREADY_CLOSED`; open non-hsync or absent files return `KEY_NOT_FOUND`. Soft-limit tests set `OZONE_OM_LEASE_SOFT_LIMIT`, with forced recovery bypassing the limit and non-forced recovery rejected until after sleep.

Dependencies include FSO key commit and allocate block requests, key location groups, replication config serialization, client-version protobuf conversion, OM lease config, and Ozone metadata constants. Risks are stale open keys, accepting writes under recovery, wrong idempotency boundary, timing-sensitive soft limits, and incorrect block length/data size during commit. Signals include `OK`, `KEY_ALREADY_CLOSED`, `KEY_NOT_FOUND`, `KEY_UNDER_LEASE_RECOVERY`, `KEY_UNDER_LEASE_SOFT_LIMIT_PERIOD`, table presence/absence, metadata cleanup, and non-null response key info.
