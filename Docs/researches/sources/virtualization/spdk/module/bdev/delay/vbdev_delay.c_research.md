# File Research: sources/virtualization/spdk/module/bdev/delay/vbdev_delay.c

This file implements the `delay` virtual bdev, which claims a base bdev and delays completion of selected IOs to emulate average and p99 read/write latency. It forwards real IO to the base bdev first, then places the original IO context on per-channel completion queues until the configured delay expires.

Configured associations are stored in `g_bdev_associations` as base name, virtual name, optional UUID, and four latency values in microseconds. Active virtual devices are stored in `g_delay_nodes`; each `vbdev_delay` keeps base bdev/descriptor, embedded virtual bdev, latency values converted to SPDK ticks, and the thread that opened the base. Per-channel state stores the base channel, four delayed-IO STAILQs, a poller, and a random seed. Per-IO state stores completion status, completion tick, selected delay type, channel, IO wait entry, and zcopy base IO state.

Creation validates that p99 latencies are not lower than average latencies, records the association, and attempts registration immediately. Registration opens and claims the base bdev, copies block geometry, write cache, alignment, optimal boundary, metadata/DIF fields, and NUMA, sets delay tick values, generates a namespace-derived UUID if no explicit UUID is provided, registers an IO device, claims the base bdev, registers the delay bdev, and stores it in the active list. If the base bdev does not exist, creation is deferred until examine.

IO submission chooses p99 behavior with a 1% random sample (`rand_r() % 100 == 0`) and sets the delay type for reads, writes, and zcopy populate/commit. READ uses `spdk_bdev_io_get_buf()` and then submits `spdk_bdev_readv_blocks_ext()` with memory-domain and metadata options preserved. WRITE submits `spdk_bdev_writev_blocks_ext()`. WRITE_ZEROES, UNMAP, FLUSH, and RESET/ABORT are forwarded to the base with completion callback. The module queues IO waits on `-ENOMEM` and resubmits through `vbdev_delay_resubmit_io()`.

Completion callback `_delay_complete_io()` copies base IO status to the original IO, handles zcopy start by preserving the base IO until zcopy end, frees ordinary base IOs, and enqueues delayed completions in the appropriate average/p99 read/write queue. `_delay_finish_io()` polls all four queues and completes IOs whose `completion_tick` has passed. The queue walk intentionally stops at the first not-ready IO, preserving FIFO behavior except after dynamic latency reductions.

RESET aborts all delayed IOs on all channels before resetting the base device. ABORT first searches delayed queues and completes the abort successfully if the target is still delayed; otherwise it forwards abort to the base bdev. Zcopy abort paths call `spdk_bdev_zcopy_end(..., false, ...)` when a delayed zcopy base IO is still held.

Runtime latency updates find an active delay bdev by name and update one of the four tick values based on `spdk_bdev_delay_io_type`. The module reports memory domains and domain types directly from the base bdev because it does not inspect or transform buffers. Base removal unregisters dependent delay vbdevs. Config and info JSON include virtual name, base bdev name, optional UUID, and current latencies converted back to microseconds.
