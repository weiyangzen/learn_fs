# sources/user-network-fs/rclone/backend/oracleobjectstorage/oracleobjectstorage.go

Purpose: primary rclone backend implementation for Oracle Cloud Infrastructure Object Storage on supported platforms. It registers `oracleobjectstorage` with prefix `oos`, exposes bucket-based filesystem behavior, and bridges rclone `fs.Fs`/`fs.Object` operations to the OCI Go SDK `objectstorage.ObjectStorageClient`.

Important APIs/types/functions: `Fs` stores name/root, parsed `Options`, global config, feature table, OCI client, root bucket/directory, bucket creation cache, and pacer. `NewFs` parses config, validates SSE-C options, creates the OCI client, configures a low-retry pacer around OCI SDK retries, fills features, and implements rclone's file-root detection convention. `List`, `ListP`, `ListR`, `list`, `listDir`, and `listBuckets` implement bucket root and prefix listing. `Mkdir`, `makeBucket`, `bucketExists`, and `Rmdir` manage buckets. `Put`/`PutStream` delegate to `Object.Update`. Multipart cleanup is handled by `CleanUp`, `cleanUp`, `cleanUpBucket`, and `abortMultiPartUpload`. `Object.Metadata` exposes OCI metadata through rclone.

Control flow: paths are parsed with `bucket.Split` after encoding conversion. Listing either enumerates buckets or calls `ListObjects` with prefix, delimiter, pagination, and selected fields. Recursive listing removes the delimiter. Bucket creation runs through `bucket.Cache.Create`, treating already-owned/already-existing service errors as success. Cleanup lists outstanding multipart uploads and aborts old ones unless rclone destructive-operation policy skips them.

State and persistence: local state is process-only: root split, bucket cache, pacer, and object metadata snapshots. Persistent state is remote OCI buckets, objects, object metadata, tiers, and multipart upload records. Metadata maps swift-style internal mtime and OCI content type/birth time into rclone metadata.

Dependencies/integration: integrates rclone `fs`, `list`, `operations`, `bucket.Cache`, `pacer`, and Oracle `oci-go-sdk/v65/objectstorage`. Several helpers are in adjacent files: auth/client creation, retry classification, storage tier mapping, metadata key conversion, object update/open, copy, and backend commands.

Risks/test signals: root bucket listing hides wrong-region buckets as empty when no bucket root is configured. No-auth cannot list buckets. Directory markers are skipped. The MD5 assignment branch in `newObjectWithInfo` is suspicious because it assigns decoded MD5 only when the decode helper returns an error. `cleanUp` appears to check `err` instead of `cleanErr` when logging per-bucket cleanup failures. Integration coverage comes from `oracleobjectstorage_test.go`, and compile-time assertions cover the main rclone optional interfaces.
