## sources/user-network-fs/nfs-ganesha/src/FSAL/FSAL_KVSFS/kvsfs_ds.c

Purpose: This file implements KVSFS pNFS data-server operations. It allows NFSv4.1 DS filehandles to be created from wire handles and services direct data-server read, write, commit, permission, and release operations using the KVSNS API.

Important functions: `kvsfs_release` frees the private `struct kvsfs_ds`. `kvsfs_ds_read` opens the KVSNS file read-only using `op_ctx` credentials, performs `kvsns_read` at the requested offset and length, closes the KVSNS open handle, fills supplied length and EOF, and returns NFSv4 status. `kvsfs_ds_write` opens write-only, writes the buffer through `kvsns_write`, closes, zeroes the write verifier, and reports the requested stability as the achieved stability. `kvsfs_ds_commit` is a no-op that zeroes the verifier and returns `NFS4_OK`. `make_ds_handle` validates a wire handle length, allocates `struct kvsfs_ds`, copies `struct kvsfs_file_handle`, and leaves `connected = false`. `pds_permissions` delegates request authorization to `nfs4_export_check_access`. `kvsfs_pnfs_ds_ops_init` copies default DS ops then installs KVSFS methods.

Control flow and state: The DS handle is a lightweight wrapper around a serialized KVSFS inode handle. Read/write operations do not use cached mdcache object handles; each operation opens and closes a KVSNS file handle using the caller's current UID/GID. Error paths translate negative KVSNS errno-style returns with `posix2nfs4_error`. The `connected` flag is initialized but not otherwise used in this file, matching the comment that lazy connection may be needed for FILE_SYNC4-style behavior.

Persistence behavior: Persistent file content is read and written through KVSNS. Commit does not flush or persist anything beyond what KVSNS writes already do, and write verifiers are all zero. DS handle allocation itself is ephemeral and freed by release.

Dependencies and integration points: The file depends on FSAL pNFS DS interfaces, `pnfs_utils.h`, NFS export/credential helpers, `op_ctx`, KVSFS private handle types from `kvsfs_fsal_internal.h`, KVSNS calls (`kvsns_open`, `kvsns_read`, `kvsns_write`, `kvsns_close`), and POSIX-to-NFS error translation.

Risks: Stateid validation is not performed locally; the stateid parameters are unused. EOF is set only when `amount_read == 0`, so short reads before EOF may not indicate EOF. Stability and commit semantics are weak: `kvsfs_ds_write` returns whatever stability was requested without explicit fsync, and `kvsfs_ds_commit` is a no-op. Close errors override successful read/write, while close errors after a failed read/write are ignored. Test signals should include DS handle length validation, read/write with caller credential changes, negative KVSNS error mapping, short read/EOF behavior, FILE_SYNC4/commit durability expectations, and export access checks.
