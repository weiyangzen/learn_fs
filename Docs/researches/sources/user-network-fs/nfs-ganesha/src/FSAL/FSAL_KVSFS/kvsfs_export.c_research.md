## sources/user-network-fs/nfs-ganesha/src/FSAL/FSAL_KVSFS/kvsfs_export.c

Purpose: This file implements KVSFS FSAL export creation, export operation initialization, filehandle digest validation, state allocation/freeing, supported-attribute filtering, pNFS export configuration, and optional DS/MDS enablement during export setup.

Important functions and data: `kvsfs_export_release` detaches the export and frees ops/private export storage. `get_dynamic_info` currently returns success without filling dynamic filesystem info. `kvsfs_wire_to_host` validates non-null handle buffers and exact `struct kvsfs_file_handle` size. `kvsfs_supported_attrs` returns FSAL-supported attributes minus `ATTR_ACL`. `kvsfs_free_state` destroys the embedded `fsal_fd` and frees the state. `kvsfs_alloc_state` allocates `struct kvsfs_state_fd`, initializes generic state, and initializes a KVSFS fd for stateful opens. `get_fsal_obj_hdl` maps an FSAL fd back to its containing KVSFS object handle. `kvsfs_export_ops_init` installs release, lookup, handle creation, dynamic info, supported attrs, state allocation, and fd-to-object callbacks. The config blocks define `kvsns_config` and PNFS settings including stripe unit, enable flag, DS count, and up to four DS addresses/ports. `kvsfs_create_export` parses config, starts KVSNS, attaches the export, sets `op_ctx->fsal_export`, computes pNFS DS/MDS enablement, creates/registers a pNFS DS if needed, and enables MDS export ops if needed.

Control flow and state: Export creation allocates the private export first, initializes ops, parses config into the object, starts the global KVSNS API with the configured file, and attaches the export to the FSAL. pNFS DS insertion uses the current export ID as the DS server ID and links the DS back to `op_ctx->ctx_export`. Error paths detach an attached export and free the allocation, but KVSNS shutdown is not visible here. Runtime state allocation is per open/share state and anchored to `op_ctx->fsal_export`.

Persistence behavior: The file starts the KVSNS API using a persistent config path, but it does not itself persist namespace data. Export objects and state objects are in-memory. pNFS DS registration mutates process-global pNFS DS tables.

Dependencies and integration points: It depends on Ganesha FSAL core, config parsing, pNFS utilities, `kvsfs_methods.h`, KVSNS startup, export lists, `op_ctx`, `pnfs_ds_insert`, and module ops that create FSAL pNFS DS instances. The supported-attribute function intentionally disables ACLs despite the broader FSAL framework having ACL concepts.

Risks: `get_dynamic_info` returns success without filling `infop`, which can mislead callers expecting dynamic space or filesystem state. On KVSNS startup success followed by later export creation failure, this file frees the export but does not show corresponding KVSNS stop/cleanup. `fsal_error` remains initialized to `ERR_FSAL_INVAL`, so some errors lose specificity. `op_ctx->fsal_export` mutation during creation can be sensitive in concurrent config paths. pNFS server ID is special-cased to the export ID, so duplicate IDs cause insertion failure. Test signals include config parse defaults, invalid KVSNS config handling, pNFS enable/disable matrix, duplicate DS server ID, handle size mismatch, state allocation/free leak checks, and dynamic-info caller behavior.
