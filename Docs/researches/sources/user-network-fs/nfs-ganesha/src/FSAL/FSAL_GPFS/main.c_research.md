## sources/user-network-fs/nfs-ganesha/src/FSAL/FSAL_GPFS/main.c

Purpose: This file is the GPFS FSAL module entry point. It declares the singleton `GPFS` module object, default filesystem capability metadata, module-level configuration, GPFS trace logging integration, and the load/unload hooks that register GPFS with NFS-Ganesha.

Important APIs and functions: `struct gpfs_fsal_module GPFS` embeds `struct fsal_module` and initializes `fs_info` with high limits, link/symlink/lock/xattr/ACL support, pNFS MDS and DS support, trace support, grace flag, supported attributes, and cache-expiry behavior. `gpfs_params` exposes configuration for link/symlink support, timestamp setting, umask, cross-device export authorization, delegations, pNFS MDS/DS, FSAL trace, and FSAL grace. `log_to_gpfs` packages Ganesha log component text into `struct trace_arg` and invokes `gpfs_ganesha(OPENHANDLE_TRACE_ME, &targ)`. `init_config` prepares stats, loads the GPFS config block into `fs_info`, creates a GPFS log facility, and enables or disables that facility according to `fsal_trace`. `gpfs_init` registers the module and installs module operations, while `gpfs_unload` releases the log facility and unregisters the FSAL.

Control flow and state: On shared-object load, `gpfs_init` registers `myname = "GPFS"` with `FSAL_ID_GPFS`, assigns operation pointers for DS ops, export creation, configuration, device info, device-address sizing, optional DBus stats extraction, and stats reset, then initializes base and pNFS-enhanced object operation tables. During configuration, Ganesha calls `init_config`; parse errors abort initialization with `ERR_FSAL_INVAL`, while successful parse configures logging and returns no error. On unload, logging is released before module unregistration.

Persistence behavior: This file persists no user data. It mutates process-global module state: the singleton `GPFS.module`, its `fs_info`, log facility registry state, and operation vectors. The configured capability flags influence later exports and client-visible NFS behavior, including whether pNFS and trace integration are advertised.

Dependencies and integration points: The file integrates `fsal.h`, `fsal_internal.h`, `FSAL/fsal_init.h`, `gpfs_methods.h`, `gsh_config.h`, and the GPFS NFS trace opcode contract from `gpfs_nfs.h` through `trace_arg` and `OPENHANDLE_TRACE_ME`. It depends on FSAL core registration, config parsing, logging facility management, stats setup, GPFS export creation, GPFS handle ops, and pNFS helper hooks.

Risks: The config block is `CONFIG_UNIQUE`, so multiple GPFS FSAL global blocks are intentionally disallowed. Trace logging only sends `compstr` with `strlen(compstr)`, not the full log message; if GPFS trace users expect message text, this is surprising. `log_to_gpfs` silently ignores nonpositive levels. Failure to create/enable/disable the log facility aborts config. Capability defaults advertise broad GPFS and pNFS support, so incorrect build/runtime GPFS support can produce client-visible failures later. Test signals include module load/unload tests, config parsing tests for each GPFS parameter, logger enable/disable behavior, `gpfs_ganesha(OPENHANDLE_TRACE_ME)` error propagation, pNFS capability toggles, and stats hook availability with and without DBus.
