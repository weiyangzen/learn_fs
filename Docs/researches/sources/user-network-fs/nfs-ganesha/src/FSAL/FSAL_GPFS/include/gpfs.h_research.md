## sources/user-network-fs/nfs-ganesha/src/FSAL/FSAL_GPFS/include/gpfs.h

Purpose: This is the imported IBM GPFS user-library public ABI header used by the GPFS FSAL. It is explicitly marked as taken directly from GPFS source and should not be modified beyond license notices, so its role is compatibility: it gives Ganesha source code the exact types, constants, function declarations, errno extensions, and 32/64-bit inode mappings expected by libgpfs and GPFS kernel services.

Important APIs and types: The file starts with platform abstraction for `GPFS_API` and `gpfs_file_t`, then defines GPFS scalar types, timestamp types, stat-lite masks, ACL formats, Windows attribute flags, share/lease constants, GPFS inode/stat types, directory entry formats, inode attribute formats, fssnap/iscan/ifile/restore opaque handle types, quota structures, clone operations, lightweight event structures, QoS calls, encryption helpers, and trace functions. High-importance function families include ACL calls (`gpfs_getacl`, `gpfs_putacl`), exact and lite stat calls (`gpfs_fstat`, `gpfs_stat_x`, `gpfs_statlite`), backup/restore-by-inode flows (`gpfs_get_fssnaphandle_*`, `gpfs_open_inodescan*`, `gpfs_next_inode*`, `gpfs_iopen*`, `gpfs_iread`, `gpfs_iwrite`, `gpfs_iclose`), quota and fileset calls (`gpfs_quotactl`, `gpfs_getfilesetid`), clone management (`gpfs_clone_snap`, `gpfs_clone_copy`, `gpfs_declone`, `gpfs_clone_split`, `gpfs_clone_unsnap`), lightweight events (`gpfs_lwe_*`), and trace bridging (`gpfs_init_trace`, `gpfs_query_trace`, `gpfs_add_trace`, `gpfs_fini_trace`).

Control flow and state: This header has no executable control flow, but it encodes many stateful protocols. ACL buffers are variable-length and caller-owned. Fssnap handles are volatile objects that must be freed with `gpfs_free_fssnaphandle`; scan handles are consumed by seek/next/stat calls and must be closed with `gpfs_close_inodescan`; inode file handles are opened by inode and closed with `gpfs_iclose`; restore sessions move through enable, start, write/attribute restore, sync, and end states. Lightweight event sessions maintain kernel-side queues, access-right tokens, event responses, and token invalidation after release. The `GPFS_64BIT_INODES` block remaps public names to 64-bit variants and changes default structure versions.

Persistence behavior: The declared calls directly expose persistent GPFS metadata and data operations: ACL updates, file times, Windows attributes, share/lease state, file truncation, extended attributes, storage-pool placement, quota accounting, snapshot/incremental restore identifiers, inode content reads/writes, clone parent/child state, encryption key wrapping, and trace output. Many APIs distinguish volatile handles from non-volatile snapshot IDs; backup/restore logic must persist fssnap IDs rather than in-memory handles.

Dependencies and integration points: Consumers must compile in an environment where GPFS headers, system stat/statfs structures, errno values, and open flags are compatible. The header is a boundary with libgpfs and GPFS kernel services rather than local Ganesha code. GPFS FSAL files use it alongside `gpfs_nfs.h` to translate NFS-Ganesha behavior to GPFS-specific handles, attributes, pNFS, tracing, and callback semantics.

Risks: ABI drift is the dominant risk; local edits or mismatched GPFS library versions can corrupt variable-length structs, wrong ioctl payloads, or 32/64-bit inode selection. The backup/restore APIs require superuser privilege and careful lifecycle management. Many calls return `-1` with errno, including GPFS-specific errno ranges, so wrappers must preserve errno semantics. Variable-length ACL, xattr, and scan buffers require exact size handling. Several comments document behavior that is version-dependent or experimental, including directory preallocation, clone support, QoS, encryption, and LWE. Test signals should include compile checks against target GPFS headers/libraries, runtime smoke tests for stat/handle/open paths, ACL/xattr round trips, 64-bit inode builds, and failure injection for privilege, stale handle, ENOSPC, ENOSYS, and buffer-too-small cases.
