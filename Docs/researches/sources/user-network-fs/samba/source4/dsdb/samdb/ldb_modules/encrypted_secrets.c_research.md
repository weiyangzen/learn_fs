# sources/user-network-fs/samba/source4/dsdb/samdb/ldb_modules/encrypted_secrets.c

Purpose: `encrypted_secrets.c` encrypts configured DSDB secret attributes before they are written to disk and decrypts them on search results. It mitigates disclosure of `sam.ldb` content and memory-read exposure by wrapping secret values in NDR `EncryptedSecret` blobs using AES-128-GCM through GnuTLS.

Important APIs, types, and functions: `struct es_data` stores whether encryption is active, the key array, and GnuTLS algorithm ID. Key handling is in `get_key_directory()` and `load_keys()`. Encryption helpers include `makeEncryptedSecret()`, `makePlainText()`, `gnutls_encrypt_aead()`, `encrypt_value()`, `encrypt_element()`, and `encrypt_secret_attributes()`. Decryption helpers include `check_header()`, `gnutls_get_algorithm()`, `gnutls_decrypt_aead()`, `decrypt_value()`, `decrypt_element()`, and `decrypt_secret_attributes()`. Ldb hooks are `es_search()`, `es_callback()`, `es_add()`, `es_modify()`, `es_delete()`, `es_rename()`, and `es_init()`.

Control flow: init checks `@SAMBA_DSDB` for `SAMBA_ENCRYPTED_SECRETS_FEATURE`; if present, it loads `encrypted_secrets.key` from the same directory as `sam.ldb` and enables encryption. Add/modify hooks pass through when encryption is disabled or no secret attrs are present. Otherwise they copy the message, encrypt each secret attribute value, rebuild the downstream add/modify request, and forward it. Search wraps results with a callback; each entry has secret attributes decrypted before being sent upward. Delete and rename pass through unchanged.

State and persistence: the persistent artifact is `encrypted_secrets.key`, a 16-byte AES key stored beside the database. Secret attribute values are persisted as NDR `EncryptedSecret` structures with magic/version/algorithm header, IV, authenticated associated data over the header, and ciphertext/tag. Missing or zero-length key files disable encryption/decryption with warnings; invalid short reads fail init. Existing encrypted values require the same key to decrypt.

Dependencies and integration points: this module depends on DSDB secret attribute lists, `@SAMBA_DSDB` required feature metadata, ldb module wrapping, NDR structures from `drsblobs`, GnuTLS AEAD APIs, ldb URL opaque `ldb_url`, and Samba data-blob/talloc helpers. It should be ordered so writes are encrypted before reaching storage and reads are decrypted before higher layers inspect attributes.

Risks and edge cases: key storage beside `sam.ldb` is explicitly a mitigation rather than strong key isolation. If the feature is required but the key is missing or zero length, the module disables encryption/decryption, which can expose plaintext or make encrypted data unreadable depending on existing DB state. AEAD IV generation depends on `gnutls_rnd()`. Header/version/algorithm mismatches fail decryption rather than treating data as plaintext. Error comments note messages can be inconsistent after partial encryption/decryption failure, though rebuilt requests reduce caller mutation. Memory ownership is delicate because encrypted/decrypted elements are inserted into copied ldb messages.

Test signals: selftest registration includes Python `samba.tests.encrypted_secrets` and C binaries `test_encrypted_secrets_tdb` and `test_encrypted_secrets_mdb` built from `tests/test_encrypted_secrets.c`. Good coverage includes feature disabled/enabled, missing/empty/short key files, add/modify/search round trip, multiple values, corrupt header/tag/ciphertext, special DN pass-through, tdb and mdb backends, and behavior when plaintext secret values exist before enabling the feature.
