# sources/user-network-fs/samba/source4/dsdb/samdb/ldb_modules/descriptor.c

Purpose: `descriptor.c` is the DSDB security descriptor module. It computes initial `nTSecurityDescriptor` values on object creation, enforces owner-write invariants, recalculates descriptors on security descriptor modifications and moves, filters returned descriptors according to SD flags, and schedules/executes security descriptor inheritance propagation at transaction prepare time.

Important APIs, types, and functions: transaction state is held in `struct descriptor_data` and `struct descriptor_transaction`, including an in-memory dbwrap map of registered changes and processed objects. `struct descriptor_changes` records NC root, object GUID, parent GUID, force-self/children flags, and list bookkeeping. Descriptor construction flows through `get_default_ag()`, `get_sd_unpacked()`, `get_default_group()`, `descr_handle_sd_flags()`, `get_new_descriptor_nonlinear()`, and `get_new_descriptor()`. Request hooks are `descriptor_add()`, `descriptor_modify()`, `descriptor_search()`, `descriptor_rename()`, `descriptor_extended()`, and transaction hooks. Propagation is handled by `descriptor_extended_sec_desc_propagation()`, `descriptor_sd_propagation_object()`, and `descriptor_sd_propagation_recursive()`.

Control flow: add requests ignore special DNs, detect NC heads, fetch parent SD when needed, locate the structural class, validate any supplied owner SID, compute a new descriptor from class default, parent descriptor, supplied descriptor, token, default owner/group, and inheritance rules, then forwards a modified add request plus `DSDB_CONTROL_CALCULATED_DEFAULT_SD_OID`. Modify requests pass through unless they target `nTSecurityDescriptor` or internal propagation control. They validate propagation-control shape, reject unsupported descriptor delete, optionally validate owner changes, fetch current object/parent descriptors and class, compute the replacement descriptor, and schedule child propagation if the descriptor changed. Search requests wrap only when SD flags or requested attributes require descriptor filtering. Rename wraps the downstream request and schedules force-self propagation after a successful move. Extended propagation operations register object GUID work items into transaction maps; prepare commit sorts changes parent-first and recursively recalculates affected subtrees.

State and persistence: descriptor values are persisted by rewriting `nTSecurityDescriptor` attributes in ldb operations. The module keeps transaction-local talloc memory and in-memory rb-tree maps to de-duplicate propagation registrations and processed objects; these are freed on transaction end or rollback. No separate on-disk state is kept by this module. It relies on ldb transaction boundaries so prepare-commit propagation sees a stable tree.

Dependencies and integration points: it uses Samba security descriptor/NDR APIs, SDDL parsing, schema class defaults, DSDB NC/root lookups, extended DN GUID extraction, ACL security tokens, `create_security_descriptor()`, `map_generic_rights_ds`, dbwrap rbt maps, `DSDB_CONTROL_SEC_DESC_PROPAGATION_OID`, `DSDB_EXTENDED_SEC_DESC_PROPAGATION_OID`, `LDB_CONTROL_SD_FLAGS_OID`, and helper scheduling from DSDB module utilities. It is intentionally positioned above `repl_meta_data`, and comments in that module refer to descriptor interactions.

Risks and edge cases: this is security-critical code; mistakes can grant or hide access. Owner validation depends on token privileges and default-administrator-group logic. Partial SD flag handling must preserve unspecified old descriptor parts exactly. Propagation can be expensive for large subtrees, so de-duplication and parent-first sorting are important. Internal propagation control has strict validation and uses the control `critical` bit as a local unchanged marker, which is subtle. `can_write_owner()` computes `default_owner` but then checks `security_token_is_sid(security_token, owner_sid)` again instead of comparing with `default_owner`, which deserves scrutiny. Any failure during prepare commit aborts the transaction.

Test signals: selftest registration references LDAP security descriptor Python tests and general `samba.tests.security_descriptors`. High-value coverage includes add with/without explicit SD, invalid owner SID, SD flags search filtering, modify owner/group/DACL/SACL subsets, rejected descriptor delete, rename propagation, recursive inherited ACE updates, replication-triggered extended propagation de-duplication, and rollback cleanup of transaction maps.
