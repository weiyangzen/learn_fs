# sources/user-network-fs/samba/source4/dsdb/samdb/ldb_modules/repl_meta_data.c

Purpose: `repl_meta_data.c` implements Samba AD's `repl_meta_data` LDB module. It sits in the `sam.ldb` module stack to synthesize and maintain Active Directory replication metadata for originating local writes and to merge inbound DRS replication updates. Its responsibilities include object GUID creation, `whenCreated`/`whenChanged`, `uSNCreated`/`uSNChanged`, `replPropertyMetaData`, linked-attribute metadata embedded in extended DNs, backlink maintenance, tombstone/recycle-bin transitions, conflict DN handling, up-to-date vector and `repsFrom` updates, and per-partition replication-change notification state.

Important APIs and types: The module registers `ldb_repl_meta_data_module_ops` with add, modify, rename, delete, extended, transaction start, prepare-commit, and transaction abort hooks. Core state lives in `struct replmd_private`, which holds per-transaction linked-attribute groups, modified naming-context USNs, schema DN, sorted-link feature state, originating-update state, and cached recycle-bin state. `struct replmd_replicated_request` carries one local or inbound replication operation through asynchronous LDB callbacks, including schema, invocation ID, controls, current object index, current search result, local parent GUID, sequence number, urgent flag, deletion flag, and dbcheck repair flags. Linked-attribute batching uses `struct la_group`, `struct la_entry`, and `struct la_backlink`.

Control flow: Module initialization checks the `SAMBA_SORTED_LINKS_FEATURE`, records the schema base DN, and installs private state. Local `add` requests are copied, forbidden auto-generated attributes are stripped, a GUID and sequence number are assigned, `replPropertyMetaData` is built for replicated non-constructed attributes, linked forward attributes are converted to extended DN values, backlinks are deferred, and the down-stack add runs with a callback that records partition USNs and processes deferred backlinks. Local `modify` rejects objectGUID changes, handles dbcheck repair controls, updates `replPropertyMetaData` only for real replicated changes, processes linked attributes into full replace operations, and only adds `whenChanged`/`uSNChanged` when a sequence number was actually allocated. Local `rename` first performs the rename, then performs a modify to update RDN/name metadata and timestamps. Local `delete` maps deletion to AD-compatible rename-and-modify behavior, moves objects under Deleted Objects when allowed, applies `isDeleted` or `isRecycled`, preserves only tombstone-required attributes, removes or vanishes links, and prevents hard deletion of tombstones unless relaxed/dbcheck controls explicitly allow it.

Inbound DRS replication enters through `DSDB_EXTENDED_REPLICATED_OBJECTS_OID`. `replmd_extended_replicated_objects()` validates `dsdb_extended_replicated_objects`, adds replicated-update and apply-links controls, then iterates objects with `replmd_replicated_apply_next()`. Each incoming object is searched by `objectGUID`; missing objects go through add flow after resolving the local parent by `parent_guid`, while existing objects go through merge flow. Merge compares incoming and local `replPropertyMetaData` by version, originating change time, and invocation ID, discards older attribute updates, assigns a new local USN for accepted changes, handles replicated renames and name conflicts, schedules security descriptor propagation when needed, writes updated `whenChanged`, `uSNChanged`, and metadata, and then invokes deletion cleanup when `isDeleted` wins. After all objects, linked attributes are verified and queued, then the NC root's `replUpToDateVector` and `repsFrom` are merged.

State and persistence behavior: Persistent object state is stored in normal LDB attributes plus NDR-encoded blobs: `replPropertyMetaData`, `replUpToDateVector`, and `repsFrom`. Linked-attribute state is embedded in extended DN components such as `RMD_FLAGS`, `RMD_ADDTIME`, `RMD_INVOCID`, `RMD_CHANGETIME`, `RMD_ORIGINATING_USN`, `RMD_LOCAL_USN`, and `RMD_VERSION`. Local writes allocate backend sequence numbers and update per-partition `@REPLCHANGED` state in `replmd_notify_store()` during prepare-commit via `dsdb_module_save_partition_usn()`, also triggering schema reload for schema NC changes. Transaction-local linked-attribute and recycle-bin cache state is cleaned at transaction start, prepare-commit, and abort. Inbound linked attributes are intentionally stored until prepare-commit so a replication chunk can create source or target objects before applying links.

Dependencies and integration points: The file depends heavily on LDB module APIs, Samba DSDB helpers, schema lookup, DRSUAPI/NDR generated types, security descriptor propagation, partition controls, sequence numbers, `talloc`, DLIST helpers, sorted-link helpers, and binary-search utilities. It integrates with `samdb_ntds_invocation_id()`, `dsdb_functional_level()`, `dsdb_module_search*()`, `dsdb_module_modify()`, `dsdb_module_rename()`, `dsdb_module_extended()`, `dsdb_recyclebin_enabled()`, `dsdb_get_deleted_objects_dn()`, `dsdb_wellknown_dn()`, `dsdb_module_schedule_sd_propagation()`, and many DSDB request controls such as replicated update, current partition, apply links, dbcheck, vanish links, partial replica, changereplmetadata, and forced RODC local change. It also mediates RODC behavior by returning referrals to a writable DC when local replicated-attribute changes are forbidden.

Important algorithms: Attribute freshness is decided by `replmd_update_is_newer()`: higher metadata version wins, then later originating change time, then higher invocation GUID. `replmd_update_rpmd()` searches the old object with extended DNs and reveal-internals flags, updates or adds per-attribute metadata, sorts by ATTID, and rejects corrupt metadata lacking objectClass. Linked-attribute local add/delete/replace paths parse DNs into sorted `parsed_dn` arrays, use GUID/extra-part comparisons, preserve deleted link values instead of removing them except under vanish controls, and maintain backlinks through the reverse `linkID`. Inbound link processing groups updates by source object and ATTID, verifies source and target existence, handles missing target retry/ignore/partial-link rules, detects single-valued link conflicts, and applies only fresher link metadata. Conflict handling creates `CNF:` DNs and deletion creates `DEL:` DNs by appending the object GUID to the RDN value.

Risks: This module is correctness-critical and sensitive to AD protocol edge cases. Metadata ordering matters: `replPropertyMetaData` must be ATTID-sorted and contain objectClass, while linked values must remain sorted for fast lookup and duplicate detection. Error codes are part of replication protocol behavior: missing parents and missing link targets deliberately map to retry signals such as `WERR_DS_DRA_MISSING_PARENT` and `WERR_DS_DRA_RECYCLED_TARGET`. Tombstone handling must preserve exactly the AD-required attributes and avoid hard deletion too early, or replication can resurrect partial objects. Linked-attribute backlink inconsistencies are tolerated in some paths but require dbcheck repair signals. RODC, partial replica, schema partition, functional-level-2000, recycle-bin, and dbcheck controls all fork behavior, so small changes can create regressions only visible in mixed-version or repair scenarios. The code also relies on careful talloc ownership because asynchronous LDB callbacks and transaction-deferred linked attributes retain copied blobs and identifiers.

Test signals: Useful regression signals include local adds receiving generated `objectGUID`, timestamps, USNs, and sorted `replPropertyMetaData`; modify operations not bumping metadata for no-op replaces but bumping for forced or real changes; rename operations updating both RDN/name metadata and `uSNChanged`; RODC writes returning referrals unless explicitly allowed; delete operations creating `DEL:` DNs, `lastKnownParent`, `msDS-LastKnownRDN`, tombstone/recycled attribute pruning, and link cleanup; inbound replication discarding older attribute stamps while accepting newer ones; conflict adds and renames creating `CNF:` objects based on name metadata freshness; missing parent/target cases returning the expected DRS retry errors; linked attributes preserving sorted extended-DN values, RMD fields, backlinks, single-valued conflict resolution, and vanish-link semantics; prepare-commit processing queued link groups and updating `@REPLCHANGED`; and NC-root replication updating `replUpToDateVector` and `repsFrom` only for NC heads.
