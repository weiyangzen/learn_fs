# sources/user-network-fs/samba/source4/torture/ndr/krb5pac.c

Purpose: this file defines Samba torture NDR coverage for Kerberos PAC structures. It parses captured PAC buffers from Windows domains, validates selected UPN/DNS and PKINIT credential fields, decrypts a PKINIT PAC credential payload with a known reply key, and tests nested credential NDR/NTLM supplemental package decoding.

Important APIs, types, and functions: the exported entry point is `ndr_krb5pac_suite(TALLOC_CTX *ctx)`. The suite uses generated `ndr_krb5pac.h`, `torture_suite_add_ndr_pull_validate_test()`, `torture_suite_add_ndr_pull_test()`, and Kerberos helpers from `lib/krb5_wrap/krb5_samba.h`. `PAC_DATA_check()` and `PAC_DATA_check2()` walk decoded `PAC_DATA` buffers and validate `PAC_TYPE_UPN_DNS_INFO` for Administrator accounts in `W2K8DOM.BER.REDHAT.COM` and `W2K12DOM.BER.REDHAT.COM`. They assert `num_buffers == 5`, UPN string sizes, UPN strings, DNS domain string sizes, and DNS domain strings.

The PKINIT validator `PAC_DATA_pkinit()` is the most involved checker. It asserts PAC version `0`, six buffers, buffer types and `_ndr_size` values for logon info, credential info, logon name, UPN/DNS info, server checksum, and KDC checksum. It validates credential info version `0`, encryption type `ENCTYPE_AES256_CTS_HMAC_SHA1_96`, and encrypted-data equality against an offset in `PAC_DATA_pkinit_AS`. It builds a known AES256 reply key from hex, initializes a Kerberos context/keyblock, decrypts the credential info with `krb5_c_decrypt(..., KRB5_KU_OTHER_ENCRYPTED, ...)`, checks the plaintext length, and compares the plaintext to `PAC_DATA_pkinit_PAC_CREDENTIAL_DATA_NDR`. It then validates logon name `pkinit1`, logon time `130966349430000000`, UPN `pkinit1@w4edom-l4.base`, DNS domain `W4EDOM-L4.BASE`, and checksum types/signature lengths.

`PAC_CREDENTIAL_DATA_NDR_check()` validates a nested credential-data NDR blob containing one `NTLM` package and checks the credential bytes match `PAC_DATA_pkinit_PAC_CREDENTIAL_NTLM_SECPKG`. `PAC_CREDENTIAL_NTLM_SECPKG_check()` validates version `0`, `PAC_CREDENTIAL_NTLM_HAS_NT_HASH`, and LM/NT hash byte slices from the fixture.

Control flow: the suite registers raw and typed PAC tests for three general PAC fixtures plus PKINIT fixtures. For the first two PACs, raw validation is registered separately, while typed `PAC_DATA` uses `torture_suite_add_ndr_pull_test()` with custom callbacks because comments state validate-test cannot be used where unique pointer values inside `PAC_LOGON_INFO` do not match for extra SID cases. The third fixture uses validate tests for both `PAC_DATA_RAW` and `PAC_DATA`. PKINIT AS data is validated as raw and typed with `PAC_DATA_pkinit()`. PKINIT TGS data is validated as raw, but the following typed registration uses `PAC_DATA_pkinit_AS` again with `PAC_DATA_pkinit()`, which looks intentional or historical in code but means typed TGS-specific coverage is not actually distinct. Finally, credential-data and NTLM package fixtures are registered as their own decoded types.

State and persistence behavior: there is no filesystem, network, KDC, or account persistence. The only nontrivial runtime state is transient Kerberos crypto state allocated inside `PAC_DATA_pkinit()`: a `krb5_context`, keyblock, encrypted input wrapper, malloc-backed plaintext buffer, and talloc `DATA_BLOB`. The function frees Kerberos data/key/context after decryption. Test fixtures are static byte arrays.

Dependencies and integration points: this file is a dense integration point between generated PAC NDR code, PAC buffer offset/size handling, Kerberos crypto wrappers, checksum/enctype constants, Unicode string decoding, SID/logon info parsing, and credential package structures. It tests both `PAC_DATA_RAW` and interpreted `PAC_DATA`, plus nested credential types that consumers use after decrypting PKINIT credential info.

Risks: crypto validation depends on Kerberos library behavior and the Heimdal/MIT keyblock API conditional (`SAMBA4_USES_HEIMDAL`). The manual `malloc()` in `PAC_DATA_pkinit()` is protected by an assertion but would need careful cleanup if future assertions were inserted before the existing free calls. The typed PKINIT TGS registration appears to reuse `PAC_DATA_pkinit_AS`; if that is accidental, TGS interpreted parsing is under-covered. Several fixtures are large and callback coverage focuses on selected high-value fields, so many logon-info details are only covered by generic pull/push validation.

Test signals: failures identify PAC layout, pointer, offset, Unicode, checksum, credential, or Kerberos decryption regressions. Strong signals include wrong PAC buffer count/type/size, missing `info` pointers, incorrect UPN/DNS names, credential info encrypted bytes changing, inability to decrypt with the known reply key, plaintext mismatch against nested credential NDR, wrong logon-name time/name values, checksum type/length mismatches, or NTLM package hash extraction errors.
