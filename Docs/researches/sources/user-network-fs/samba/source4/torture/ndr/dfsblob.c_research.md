# sources/user-network-fs/samba/source4/torture/ndr/dfsblob.c

Purpose: this file defines the Samba torture NDR suite for standalone DFS referral blobs. It tests decoding of a DFS referral request and two referral response fixtures, and it also performs a targeted push-back check for referral response termination behavior.

Important APIs, types, and functions: the exported entry point is `ndr_dfsblob_suite(TALLOC_CTX *ctx)`. It uses generated DFS blob bindings from `librpc/gen_ndr/ndr_dfsblobs.h` plus public DFS blob structures from `librpc/gen_ndr/dfsblobs.h`. The fixture types under test are `dfs_GetDFSReferral_in` and `dfs_referral_resp`. `dfs_referral_out_check(struct torture_context *tctx, struct dfs_referral_resp *r)` validates that the first decoded referral's v3/r2 `special_name` is `\\msw2k3.tst`, then calls `ndr_push_struct_blob()` with `ndr_push_dfs_referral_resp` and checks that the last two bytes in the re-encoded blob are zero.

Control flow: static byte arrays represent one referral input and two referral responses. `ndr_dfsblob_suite()` registers the input fixture with `torture_suite_add_ndr_pull_test()` and no checker, registers `dfs_get_ref_out2` as a response decode-only fixture, and registers `dfs_get_ref_out` with `dfs_referral_out_check()`. The checker combines normal pull validation with a push validation: decode the fixture, inspect a high-value nested string, re-encode the decoded structure, and verify the expanded-name tail is null terminated.

State and persistence behavior: the file has no external persistence. It declares a global `DATA_BLOB blob`, which is assigned in the checker when re-pushing the decoded referral response. That global is only test scratch state; its allocation parent is the current torture context. No SMB server, DFS namespace, or filesystem is contacted.

Dependencies and integration points: this test sits in the NDR torture family and exercises generated DFS referral blob parsers and pushers. It depends on generated union selection for referral version 3, nested referral layout for the `r2` form, UTF-16 string conversion, offset handling inside packed referral buffers, and `ndr_push_struct_blob()` preserving the expected wire-compatible string terminator. It is an integration point between the IDL definitions, generated NDR code, and DFS referral marshalling used by SMB DFS client/server code.

Risks: the final two-byte terminator assertion indexes `blob.data[blob.length - 2]` and `blob.data[blob.length - 1]`, so it assumes push succeeds and produces at least two bytes; the code does not explicitly assert push status or length before indexing. The global `blob` is harmless in normal serial torture execution but is not a clean per-test local. Coverage is limited to these captured layouts and does not deeply validate every referral field in `dfs_get_ref_out2`.

Test signals: failures point to DFS referral blob compatibility regressions. The most meaningful signals are inability to pull the request/response blobs, incorrect nested `special_name` decoding, re-pushed responses lacking a UTF-16 null terminator, or generated DFS blob changes that alter offsets/string expansion enough to break round-trip validation.
