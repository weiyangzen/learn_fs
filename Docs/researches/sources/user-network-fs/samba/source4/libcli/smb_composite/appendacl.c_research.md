# sources/user-network-fs/samba/source4/libcli/smb_composite/appendacl.c

Purpose: composite SMB1 workflow that opens a path, reads its DACL, appends ACEs from an input security descriptor, writes the updated DACL, reads it again, and closes the file. APIs are `smb_composite_appendacl_send()`, `smb_composite_appendacl_recv()`, and `smb_composite_appendacl()`. Control flow is an async state machine with stages `APPENDACL_OPENPATH`, `GET`, `SET`, `GETAGAIN`, and `CLOSEPATH`, advanced by `appendacl_handler()`. It uses raw open, raw fileinfo security descriptor query, raw setfileinfo security descriptor set, and raw close. State is `appendacl_state`, including stage, IO pointers, current raw request, and output security descriptor copied to caller memory on recv. Dependencies include raw SMB client APIs, composite contexts, security descriptor helpers, and SMB composite interfaces. Integration points are higher-level ACL manipulation paths and tests. Risks include calling synchronous `smb_raw_setfileinfo()` before also sending async setfileinfo, which appears duplicated; maximum-allowed open rights may be broader than needed; DACL append lacks deduplication/canonicalization; and cleanup on intermediate failure may leave handles open. Test signals include appending one/multiple ACEs, null input DACL, permission denied, set failure cleanup, verifying final DACL, close failure, and ensuring no duplicate set occurs unexpectedly.
