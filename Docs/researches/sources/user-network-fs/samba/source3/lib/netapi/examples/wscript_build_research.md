# sources/user-network-fs/samba/source3/lib/netapi/examples/wscript_build

## Purpose

This waf build fragment defines the command-line example binaries shipped for Samba's `libnetapi` surface. It was read as a complete 72-line file. The file groups example programs by topic (`getdc`, `join`, `user`, `group`, `localgroup`, `server`, `share`, `file`, `shutdown`, `netlogon`) and builds each one as a non-installed `SAMBA_BINARY`.

## Important APIs, Types, and Functions

The key build declarations are `bld.SAMBA_SUBSYSTEM('LIBNETAPI_EXAMPLES_COMMON', source='common.c', deps='netapi popt')` and the loop over `names` that calls `bld.SAMBA_BINARY('%s/%s' % (subdir, name), source='%s/%s.c' % (subdir, name), deps='netapi popt LIBNETAPI_EXAMPLES_COMMON', install=False)`. The `names` list is the manifest for examples including `getdc`, `dsgetdc`, `netdomjoin`, `getjoinableous`, `group_add`, `localgroup_addmembers`, `file_enum`, and `nltest`.

## Control Flow

At configure/build-script evaluation time, waf first registers the shared `common.c` subsystem and then iterates the tuple list. Each tuple maps a subdirectory and C basename to a generated binary target. There is no runtime application logic in this file.

## State and Persistence Behavior

The file has no runtime state. Its persistent effect is build graph metadata: example targets are available in the tree but marked `install=False`, so they are developer/test utilities rather than installed products.

## Dependencies and Integration Points

It integrates with Samba's waf helpers, the `netapi` library target, `popt` option parsing, and example source files under `source3/lib/netapi/examples/*`. The commented GTK note indicates a deferred GUI example dependency that is not part of the active build graph.

## Risks and Edge Cases

The tuple list is hand-maintained, so adding/removing an example source without updating this list will silently omit or break a target. Because paths are generated by string interpolation, source placement must match `<subdir>/<name>.c`. The examples depend on the public `libnetapi` ABI, so they are useful canaries for wrapper/header drift.

## Test Signals

Build signals are successful waf target generation for every tuple, compile/link coverage against `netapi`, `popt`, and `LIBNETAPI_EXAMPLES_COMMON`, and smoke execution of representative examples such as `getdc`, `group_enum`, `localgroup_enum`, and `file_enum` against a test server.
