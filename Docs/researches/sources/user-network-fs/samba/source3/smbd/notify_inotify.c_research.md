# sources/user-network-fs/samba/source3/smbd/notify_inotify.c

## Purpose
This file implements Samba's `sys_notify_watch_fn` backend using Linux inotify. It converts SMB/Windows change-notify filters into kernel inotify masks, receives kernel events from a tevent fd handler, repairs Linux-specific event shapes into SMB notify semantics, and invokes the higher-level notify callback supplied by notifyd.

## Important APIs, Types, and Functions
The main exported API is `inotify_watch(...)`, which registers a directory watch and returns a talloc-owned handle. `struct inotify_private` owns the inotify fd and all active `struct inotify_watch_context` entries. Each watch stores the kernel watch descriptor, requested SMB filters, computed inotify mask, callback, caller-private data, watched path, and transient rename/mkdir state. `inotify_map()` consumes SMB filter bits that inotify can handle and returns the inotify mask; `inotify_map_mask_to_filter()` converts kernel events back into possible SMB filters. `filter_match()` is the key selector that compensates for inotify watch coalescing and SMB's split between file and directory name filters.

## Control Flow
`inotify_watch()` lazily calls `inotify_setup()` to create the inotify fd and register `inotify_handler()` with tevent. It maps filters, adds `IN_MASK_ADD | IN_ONLYDIR`, allocates a watch context, calls `inotify_add_watch()`, links the watch into `in->watches`, and installs `watch_destructor()`. `inotify_handler()` reads one buffer of inotify events and walks it defensively by event length. `inotify_dispatch()` ignores non-interesting kernel events, stores `IN_MOVED_FROM` events briefly, pairs matching `IN_MOVED_TO` events into old/new-name notifications, records directory creates for Samba mkdir special cases, maps create/delete/move/modify into `notify_event`, and fans matching events out to all watch contexts sharing the same watch descriptor.

## State and Persistence
State is in process memory only. The inotify fd lives under the notify context's talloc tree and is closed by `inotify_destructor()`. Multiple Samba watches can share one kernel watch descriptor; `watch_destructor()` only removes the kernel watch when no remaining context uses the same wd. Rename state is transient: `moved_from_event` is copied with talloc and has a 100 ms timer that converts an unpaired move-from into a remove event. `last_mkdir` suppresses or rewrites events generated by Samba's own temporary-name mkdir logic.

## Dependencies and Integration Points
The file depends on Linux `<sys/inotify.h>`, Samba talloc/tevent infrastructure, notify NDR constants, `sys_read()`, list macros, and `IS_SMBD_TMPNAME()`. It integrates below `notifyd.c` through the `sys_notify_watch_fn` callback signature; `notifyd_apply_rec_change()` can pass `notifyd_sys_callback()` as the callback and store the returned handle inside `struct notifyd_watcher`.

## Risks and Edge Cases
The code relies on kernel event ordering and a short timer to infer orphaned renames, so delayed `IN_MOVED_TO` delivery may become a remove plus add rather than a rename. `IN_MASK_ADD` means events for coalesced watches must be filtered carefully; mistakes can leak events to uninterested clients. The inotify fd is removed from tevent after read errors or malformed buffers, leaving existing watches ineffective. `filter_match()` maps several Windows concepts to `IN_ATTRIB`, so clients may receive broader notifications than the exact underlying change.

## Test Signals
No direct unit test in this group exercises `notify_inotify.c`. Coverage is indirect through notifyd tests and any Samba integration tests using real file change notify. Useful test signals include rename pairs, orphaned `IN_MOVED_FROM`, temporary Samba mkdir names, multiple watches on one path with different filters, and cleanup of one watch when another shares the same kernel wd.
