# sources/user-network-fs/samba/source3/smbd/smb2_create.c

Purpose: implements SMB2 CREATE in source3 `smbd`: request decoding, create-context parsing, IPC/printer/file open paths, durable handles, leases, replay-cache handling, POSIX create context support, symlink/reparse error responses, and CREATE response marshalling.

Important APIs and types: `smbd_smb2_request_process_create()` validates body/dynamic buffers, converts the name, parses create blobs, and queues `smbd_smb2_create_send()`. `struct smbd_smb2_create_state` carries decoded input contexts, durable/replay fields, lease state, VFS result fsp, output fields, and symlink error data. `smbd_smb2_create_fetch_create_ctx()`, `smbd_smb2_create_before_exec()`, `smbd_smb2_create_after_exec()`, and `smbd_smb2_create_finish()` split context collection, execution setup, response context construction, and final output capture. Deferred-open helpers include `push_deferred_open_message_smb2()`, `open_was_deferred_smb2()`, and `schedule_deferred_open_message_smb2()`.

Control flow: the packet handler verifies the `0x39` fixed body, bounds-checks name and context ranges against the dynamic iovec, converts UTF-16 to Unix charset, rejects embedded NUL/name-size mismatches, parses create blobs, and starts the tevent operation. The send path creates a fake SMB1 request, strips DFS prefixes, disables ignored alert options, handles IPC named pipes and printer shares, checks trailing slash rules, parses durable/lease/EA/security/allocation/timestamp/QFID/POSIX contexts, then chooses replay, durable reconnect, or fresh `SMB_VFS_CREATE_FILE()`. After backend open it builds max-access, durable, QFID, lease, and POSIX response contexts, detects symlink reparse behavior, updates open records, and finalizes timestamps, allocation, EOF, attributes, and persistent/volatile file IDs. The done callback builds the `0x58` response or special SMB2 symlink error context.

State and persistence: durable/replay state is stored in `smbXsrv_open` globals, backend cookies, create GUIDs, replay-cache entries, and durable timeout fields. Lease state persists through `files_struct->lease`. Deferred opens retain request time, file ID, `deferred_open_record`, cancel state, and redispatch callbacks. Filesystem state changes are delegated to VFS create, durable reconnect, EA, security descriptor, allocation, and reparse helpers.

Dependencies and integration: depends on create-context marshalling, `smbXsrv_open`, leases/oplocks, DFS path stripping, filename conversion, `SMB_VFS_CREATE_FILE()`, durable VFS hooks, EA/security NDR, reparse helpers, print and pipe open helpers, deferred-open messaging, and `smbd_smb2_fake_smb_request()`.

Risks: dynamic name/context ranges may overlap by design, so downstream parsers must be robust. Durable/replay status mapping is delicate, especially lease-key validation and replay flags. Symlink error buffers differ before/after SMB 3.1.1. Deferred-open redispatch clears callbacks to avoid double completion. POSIX create context changes path syntax and EA validation.

Test signals: cover SMB2 basic/create, path slash, DFS path, durable-open/v2/replay/delay, create-no-streams, TWRP, lease/dirlease, fileid, streams, EA, symlink traversal, IPC/printer non-durable paths, stopped-on-symlink errors, deferred-open cancellation/redispatch, and compound create error propagation.
