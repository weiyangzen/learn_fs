# sources/compression/xz/src/liblzma/check/crc32_x86.S

Purpose: optional 32-bit x86 assembly implementation of the generic CRC32 fast path, optimized for i686-era processors using slicing-by-eight tables.

Important APIs/types/functions: exports hidden symbol `lzma_crc32_generic` under platform label-prefix rules and references `lzma_crc32_table`. Assembly macros handle CET `ENDBR`, symbol prefixing, alignment, function type/size metadata, PIC addressing, Mach-O indirect pointers, and GNU-stack notes.

Control flow: the function saves callee-saved registers, loads `buf`, `size`, and `crc`, resolves the table address with platform-specific PIC/non-PIC code, complements the CRC, byte-steps until the input pointer is 8-byte aligned or fewer than 16 bytes remain, then processes aligned chunks using eight table slices. Remaining bytes use the single-byte update loop before complementing and returning.

State and persistence: stateless except for reading the global CRC table. It does not initialize the table; callers/build configuration must provide the generated table.

Dependencies/integration: selected by `HAVE_CRC_X86_ASM` in fast CRC builds. `crc64_fast.c` mirrors the pattern for CRC64, while `crc_common.h` decides whether this coexists with generic C or arch-optimized dispatch.

Risks: ABI portability is the main risk: stack offsets, PIC table addressing, symbol prefixing, and platform assembler directives must match the target. It is 32-bit x86 specific and can underperform on very old i586 processors. Table layout mismatches corrupt results.

Test signals: build on ELF, Mach-O, and Windows/Cygwin 32-bit targets when supported; compare `lzma_crc32()` vectors across C and assembly backends and run header/index/lzip checksum tests.
