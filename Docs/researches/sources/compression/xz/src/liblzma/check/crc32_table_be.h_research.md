# sources/compression/xz/src/liblzma/check/crc32_table_be.h

Purpose: generated big-endian CRC32 lookup table for the fast slicing-by-eight implementation. It provides precomputed constants for `lzma_crc32_table[8][256]` when `WORDS_BIGENDIAN` is selected.

Important APIs/types/functions: defines `const uint32_t lzma_crc32_table[8][256]`. There are no functions; the header is included directly by CRC implementation files so the table definition is compiled into exactly the selected translation unit.

Control flow: no runtime control flow exists in this generated artifact. The eight slices correspond to repeated applications of the reversed IEEE CRC32 polynomial, then byte-swapped for big-endian word processing. The fast CRC code indexes the slices by bytes extracted from aligned 32-bit or 64-bit loads.

State and persistence: the table is immutable static program data. It persists for the lifetime of the process and has no initialization ordering concerns.

Dependencies/integration: generated by `crc32_tablegen.c` compiled with `WORDS_BIGENDIAN`. Used by `crc32_fast.c` on big-endian builds and must stay in sync with the table generator and endian helper macros in `crc_common.h`.

Risks: any mismatch between this table and the generator polynomial/endian transform silently produces incompatible CRC32 values on big-endian systems. Because it is generated source, manual edits are high risk and should be replaced by regenerating. Multiple inclusion in the wrong build path can create duplicate definitions.

Test signals: big-endian coverage is primarily build/architecture dependent; cross-endian known-vector tests for `lzma_crc32()` and XZ header CRC validation are the key signals.
