# sources/compression/xz/src/liblzma/check/crc32_table_le.h

Purpose: generated little-endian CRC32 lookup table for the fast slicing-by-eight CRC32 backend, the common path on x86 and most supported targets.

Important APIs/types/functions: defines `const uint32_t lzma_crc32_table[8][256]`. It is a data-only header included by the fast CRC32 implementation rather than a separately compiled object.

Control flow: no active control flow. The first slice is the standard reversed IEEE CRC32 byte table; the later slices precompute additional byte positions so fast code can fold four or eight bytes per iteration with table lookups and XORs.

State and persistence: immutable read-only data. Unlike `crc32_small.c`, no constructor or lazy initialization is needed, trading binary size for startup simplicity and speed.

Dependencies/integration: generated by `crc32_tablegen.c` without `WORDS_BIGENDIAN`; consumed by `crc32_fast.c`, optional i386 assembly, and indirectly any code using `lzma_crc32()`. The LZ encoder has its own generated hash table relationship to slice zero.

Risks: stale constants break all CRC32 validation in little-endian fast builds. The table is large enough to affect small-library footprint, so it must be excluded in small or arch-only builds according to `crc_common.h` feature decisions. It must not be included from more than one object.

Test signals: standard CRC32 vectors, XZ stream header/footer CRC tests, block header tests, and lzip decoder checksum tests provide useful coverage.
