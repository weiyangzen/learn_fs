## sources/compression/zstd/tests/fuzzer.c

Purpose: standalone zstd regression and randomized test harness. Despite the filename, this is not a libFuzzer target; it is a command-line tester that first runs broad deterministic unit/regression coverage, optionally runs longer stress tests, and then runs seeded randomized compression/decompression trials. It exercises public APIs, static-linking-only APIs, dictionary training and attachment, sequence APIs, block APIs, streaming APIs, multithreaded paths, malformed input defenses, memory sizing behavior, and historical bug cases.

Important APIs/types/functions: `main()` parses `-i`, `-T`, `-s`, `-t`, `-P`, `-v`, `-q`, `--memtest`, `--no-big-tests`, and `--long-tests`, derives a seed, and dispatches to `basicUnitTests()`, `longUnitTests()`, `fuzzerTests()`, or `FUZ_mallocTests()`. `FUZ_rand()`, `FUZ_highbit32()`, `FUZ_rLogLength()`, and `FUZ_randomLength()` provide deterministic pseudo-random choices from the seed. `CHECK`, `CHECK_Z`, `CHECK_VAR`, and related macros are hard-stop assertions that print the failing expression and exit or jump to cleanup. `basicUnitTests()` is the main fixed regression suite. `longUnitTests()` contains slow index-overflow, LDM, and CDict attachment stress cases. `fuzzerTests()` is the randomized loop. Helper routines `FUZ_decodeSequences()`, `FUZ_getLitSize()`, and `FUZ_transferLiterals()` validate sequence-generation and external-sequence compression APIs. Under `ZSTD_MULTITHREAD`, `threadPoolTests()` and `threadPoolTests_compressionJob()` validate shared thread-pool reuse and concurrent compression jobs. On macOS, `FUZ_mallocTests()` uses `ZSTD_customMem` plus `malloc_size()` counters to observe allocation volume for one-shot, streaming, and multithreaded compression.

Control flow: startup reports the zstd version and bitness, chooses either the requested seed or a time-derived seed, converts compressibility from percent to a float, and handles the special memory-test-only mode. With the default starting test `0`, `basicUnitTests(0, probfloat)` runs on a constant seed for stable fixed-regression inputs. If `--long-tests` is enabled and basic tests pass, `longUnitTests(0, probfloat)` runs. Finally `fuzzerTests(seed, nbTests, startTest, maxDuration, probfloat, bigTests)` runs either for the requested count or until the requested duration expires. Any detected error sets a nonzero result and stops subsequent stages.

`basicUnitTests()` allocates 5 MB source, compressed, and decoded buffers, generates compressible random data with `RDG_genBuffer()`, and then executes a large ordered set of assertions. The early tests cover version/error APIs, compression/decompression bounds, `HIST_count_wksp()`, parameter validation, one-shot round trips, missing/extra byte errors, checksum handling, content-size metadata, DCtx size reduction, magicless format exclusion from legacy APIs, max block-size enforcement, long-distance matching corner cases, deterministic prefixes, in-place decompression margins, block splitting, superblock regressions, empty frames, context reuse, parameter get/set/reset, static CCtx/DCtx sizing, multithreaded compression, skippable frames, and context copying. The later tests cover dictionary builders (`ZDICT_trainFromBuffer`, COVER, FASTCOVER), CDict/DDict/static dictionary modes, dictionary/prefix/CDict precedence and persistence across resets, multi-DDict decompression, malformed-frame defense, negative compression levels, decompression parameters, direct block APIs, RLE detection, sequence generation/merging/compression, zero-filled inputs, many short-sequence inputs, skippable-frame header queries, FSE edge cases, and bit intrinsic fallback equivalence.

`longUnitTests()` is intentionally slower. It uses a large static compression context to force internal index growth, index reduction, and table cleanliness across all compression levels, compares LDM versus non-LDM output size for optimal parsing, and iterates CDict compression over decreasing dictionary sizes, compression levels 4 through 12, attach preferences, and dedicated-dictionary-search settings.

`fuzzerTests()` builds five 8 MB source corpora with different compressibility profiles, then advances the PRNG to `startTest` so failures can be reproduced by seed and test number. Each iteration selects a corpus, copies a random sample into a dedicated allocation to expose read overruns under sanitizers, compresses it with a random positive or occasional negative level, verifies frame metadata and one-shot decompression by `XXH64`, checks too-small destination and truncated source failures without overwriting sentinel bytes, corrupts compressed input with random noise to ensure decompression does not overrun output, then performs bufferless streaming compression over scattered chunks with a random dictionary and parameters. The streaming result is decoded with `ZSTD_decompressContinue()` using `ZSTD_nextSrcSizeToDecompress()` and checked against a mirror buffer and hash.

State/persistence behavior: most state is transient heap state owned by each test: `ZSTD_CCtx`, `ZSTD_DCtx`, `ZSTD_CDict`, `ZSTD_DDict`, static context workspaces, thread pools, generated dictionaries, and source/output buffers. The harness deliberately tests zstd context persistence rules: compression parameters survive `ZSTD_reset_session_only` but not parameter resets; loaded dictionaries and referenced CDicts/prefixes clear each other according to API contract; DCtx dictionaries and DDicts persist across decompression calls until parameter/session reset, while prefixes are consumed; copied contexts preserve initialized dictionary state and pledged-size metadata. The randomized loop's reproducibility is persisted only in the seed and test number printed on failures. There is no repository or filesystem persistence except optional disabled golden-file generation code inside an `if (0)` block and normal process output.

Dependencies: this file depends on zstd public and internal headers (`zstd.h`, `zstd_errors.h`, `zdict.h`, `zstd_internal.h`, `compress/zstd_compress_internal.h`, `compress/hist.h`, `fse.h`, `mem.h`), test utilities (`datagen.h`, `timefn.h`, `debug.h`, `threading.h`), and xxHash (`xxhash.h`). It requires static-linking-only definitions for internal and deprecated APIs under test. Multithreaded coverage is compiled only when `ZSTD_MULTITHREAD` is available. The macOS allocation tests depend on `<malloc/malloc.h>` and `malloc_size()`.

Integration points: this is a test executable in the zstd test suite and is meant to be driven by build/test scripts with deterministic seeds, counts, durations, and verbosity. It integrates with sanitizers and Valgrind-style tooling by allocating exact-size temporary buffers and placing sentinel bytes around too-small destinations. It also acts as a broad compatibility surface for deprecated and static APIs, so compressor internals, dictionary builders, block compressors, sequence APIs, frame utilities, and threading implementations can break this harness even when normal public one-shot APIs still work.

Risks: the suite is large, memory-heavy, and partly configuration-dependent, so failures can vary with `ZSTD_MULTITHREAD`, excluded block compressors, architecture, endian mode, macOS-only allocation instrumentation, and compression-level limits. Several tests assert exact compressed sizes or hashes for generated data, making them sensitive to intended compression-ratio changes and `RDG_genBuffer()` behavior. Some loops intentionally simulate multi-gigabyte logical progress or many context reuses, so running `--long-tests`, high `-i`, or duration mode can be expensive. Many checks use `assert()`, but the file undefines `NDEBUG` to keep them active. Because the harness imports internal headers and static APIs, internal refactors can require coordinated test updates even when ABI behavior is unchanged.

Test signals: success is process exit `0` after fixed tests and the randomized loop print completion. Failure signals include immediate `exit(1)` from basic macros, `Error detected in Unit tests !`, or an `Error => ... (seed X, test nb Y)` line from randomized tests, which gives the reproduction tuple for `-sX -tY`. Useful targeted invocations are default `fuzzer`, deterministic bounded runs with `-s# -i#`, time-bounded runs with `-T#s` or `-T#m`, focused replay with `-t#`, reduced expensive coverage with `--no-big-tests`, long stress coverage with `--long-tests`, and macOS allocation instrumentation with `--memtest` or `--memtest=#`.
