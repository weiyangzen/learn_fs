# Research: sources/compression/zstd/lib/legacy/zstd_v03.c

Purpose: Implements the standalone legacy decoder for zstd v0.3 frames (`0xFD2FB523`). The file is a frozen compatibility snapshot: it embeds low-level little-endian memory helpers, a backward bitstream reader, local error helpers, Finite State Entropy decompression, Huff0 literal decompression, and the v0.3 frame/block/sequence decoder. Its public surface is the `ZSTDv03_*` wrapper layer consumed by `zstd_legacy.h`.

Important APIs, types, and functions: Public wrappers defined in this C file are `ZSTDv03_decompress()`, `ZSTDv03_findFrameSizeInfoLegacy()`, `ZSTDv03_isError()`, `ZSTDv03_createDCtx()`, `ZSTDv03_freeDCtx()`, `ZSTDv03_resetDCtx()`, `ZSTDv03_nextSrcSizeToDecompress()`, and `ZSTDv03_decompressContinue()`. The decoder context `ZSTDv03_Dctx_s` stores FSE decode tables for literal lengths, offsets, and match lengths, prefix history pointers (`base`, `previousDstEnd`), streaming state (`expected`, `phase`, `bType`), and a 128 KiB literal buffer with an 8-byte wildcopy margin. Core helpers include `ZSTD_getcBlockSize()`, `ZSTD_decodeLiteralsBlock()`, `ZSTD_decodeSeqHeaders()`, `ZSTD_decodeSequence()`, `ZSTD_execSequence()`, `ZSTD_decompressSequences()`, `ZSTD_decompressBlock()`, and the internal static `ZSTD_decompressDCtx()`. Embedded entropy code exposes local `BIT_*`, `FSE_*`, and `HUF_*` helpers but they are file-local implementation details.

Control flow: One-shot decompression validates a 4-byte frame header, then loops over 3-byte block headers until an end block. Compressed blocks decode a literal section first, using Huff0 for compressed literals, direct references or copies for raw literals, and memset for RLE literals. Sequence headers then build three FSE tables for literal length, offset code, and match length, initialize three FSE states from a backward bitstream, and repeatedly decode sequences into the caller's destination. Each sequence copies literals, resolves repeat offsets, checks match bounds against `base`, and copies matches with special handling for offsets below eight. Raw blocks are copied directly. RLE blocks are recognized but return a generic error in v0.3. The direct streaming API is a strict pull model: `nextSrcSizeToDecompress()` returns exactly the number of bytes expected for the next call, `decompressContinue()` alternates frame header, block header, and block content phases, and returns zero for metadata-only steps.

State and persistence behavior: There is no persistent external state. A one-shot call uses a stack context and sets `base` to the output buffer. A heap context created by `ZSTDv03_createDCtx()` persists entropy tables, literal buffer, phase, and prefix tracking across streaming calls until reset or free. Streaming history depends on output contiguity: if `dst` is not exactly `previousDstEnd`, the decoder resets `base` to the new destination, so callers using non-contiguous buffers lose access to prior block history. `findFrameSizeInfoLegacy()` does not decompress; it walks block headers, returns the compressed frame size, and estimates a decompressed upper bound as `nbBlocks * BLOCKSIZE`.

Dependencies and integration points: Includes `zstd_v03.h`, `../common/compiler.h`, and `../common/error_private.h`; also uses standard `stddef.h`, `stdint.h` or fallback typedefs, `string.h`, `stdlib.h`, and compiler intrinsics for byte/bit operations. `sources/compression/zstd/lib/legacy/zstd_legacy.h` dispatches magic version 3 to `ZSTDv03_decompress()` and `ZSTDv03_findFrameSizeInfoLegacy()`. Generic legacy streaming intentionally does not support versions 1-3, so this file's direct streaming functions are available to specialized callers but are not used by the modern `ZSTD_decompressLegacyStream()` wrapper.

Risks: This decoder uses performance-oriented wildcopy and pointer arithmetic from an old format implementation; correctness depends on conservative prechecks before copying. Some comments explicitly acknowledge late corruption detection around dump overreads. RLE data blocks are not implemented even though RLE literals are. The v0.3 frame has no content size, so frame-size reporting is only an upper bound by block count. `ZSTDv03_decompressDCtx()` is declared in the header but this source only defines the internal static `ZSTD_decompressDCtx()`, so external callers expecting the header symbol would fail to link unless another compatibility layer supplies it. Error-code naming in comments still references older helper names, but actual error detection routes through local `ERR_isError()` from `error_private.h`.

Test signals: Exercise magic mismatch, too-small frame headers, truncated block headers, compressed-size-over-remaining errors, end block with trailing bytes, raw blocks, compressed blocks with raw/RLE/Huff0 literals, unsupported RLE blocks, malformed FSE/Huff0 tables, offset-before-base corruption, too-small destination buffers, non-contiguous streaming buffers, exact `expected` sizes in streaming mode, and frame-size-info results for complete and truncated frames. Integration tests should verify `ZSTD_isLegacy()` dispatch for magic `0xFD2FB523` and `ZSTD_findFrameSizeInfoLegacy()` conversion of `nbBlocks * BLOCKSIZE` into the common legacy metadata.
