# sources/compression/zstd/lib/legacy/zstd_v07.c

Purpose: Implements the legacy Zstandard v0.7 decompressor as a mostly self-contained compatibility unit. It embeds old MEM, bitstream, FSE, and Huffman decoding support, then layers v0.7 frame/block decompression, dictionary loading, direct context decompression, and buffered streaming APIs exposed by `zstd_v07.h`. This file is selected only when legacy support asks for v0.7 frames, allowing the current library to decode historical streams without mixing old format rules into the main decoder.

Important APIs and types: Public entry points include `ZSTDv07_decompress()`, `ZSTDv07_decompressDCtx()`, `ZSTDv07_createDCtx()`, `ZSTDv07_freeDCtx()`, `ZSTDv07_decompress_usingDict()`, `ZSTDv07_createDDict()`, `ZSTDv07_freeDDict()`, `ZSTDv07_decompress_usingDDict()`, `ZSTDv07_getFrameParams()`, `ZSTDv07_getDecompressedSize()`, `ZSTDv07_findFrameSizeInfoLegacy()`, the buffer-less streaming pair `ZSTDv07_nextSrcSizeToDecompress()` and `ZSTDv07_decompressContinue()`, and the buffered `ZBUFFv07_*` API. Internal state is centered on `ZSTDv07_DCtx_s`, which owns FSE tables for literal length, match length, and offsets, a Huffman table, prior-output history pointers, repeat offsets, frame parameters, checksum state, decode stage, literal buffers, and frame header buffers. `ZSTDv07_DDict_s` stores an owned dictionary copy and a prepared reference decompression context.

Control flow: One-shot decompression creates or reuses a `ZSTDv07_DCtx`, initializes it with an optional dictionary, verifies the v0.7 frame header, then loops over 3-byte block headers until `bt_end`. Compressed blocks run `ZSTDv07_decompressBlock_internal()`, which decodes the literal section, builds or reuses sequence FSE tables, decodes sequence states from a reverse bitstream, executes literal/match copies, and appends the last literal run. Raw blocks copy directly, and RLE blocks generate repeated bytes in the one-shot path. Header parsing supports skippable frames in the streaming path, validates magic numbers, reserved bits, window size, content size, dictionary ID, and checksum flag. The buffer-less streaming API is stage-driven: read the minimal frame header, complete the full frame header, read block headers, decode block payloads, optionally skip skippable frame content, and reset to the initial stage when a frame completes. The `ZBUFFv07_*` wrapper buffers partial input and output around this exact-size streaming core.

State and persistence behavior: All persistent decode state lives in allocated contexts, not global mutable storage. `ZSTDv07_decompressBegin()` resets stage, history pointers, entropy flags, dictionary ID, Huffman table descriptor, and repeat offsets. Dictionary initialization may load entropy tables and repeat offsets from a v0.7 dictionary header, or reference raw dictionary content as external history. History continuity is tracked through `previousDstEnd`, `base`, `vBase`, and `dictEnd`; non-contiguous output forces external-dictionary style address translation. `DDict` creation copies dictionary bytes and precomputes a reusable reference context. No file or external persistence is performed.

Dependencies and integration points: Includes the legacy public header, `../common/xxhash.h` for content checksum verification, `../common/compiler.h` for compiler helpers and `MEM_STATIC`, and `../common/error_private.h` for shared error-code encoding. It is pulled into libzstd through `libzstd.mk` when `ZSTD_LEGACY_SUPPORT` is nonzero and less than 8. The exported names are version-suffixed (`ZSTDv07_`, `ZBUFFv07_`, `FSEv07_`, `HUFv07_`) to avoid collisions with the modern implementation and other legacy decoders.

Risks: This is security-sensitive parser and decompressor code for untrusted legacy inputs. The code relies on exact input sizes, reverse bitstream end marks, bounded FSE/Huffman table logs, window limits, and careful wildcopy overlength padding. Some paths intentionally permit fast over-copy into internal buffers after capacity checks, so off-by-one changes are high risk. `ZSTDv07_freeDDict()` assumes `ddict` is non-null. The buffer-less streaming path returns `ERROR(GENERIC)` for RLE data blocks, while the one-shot frame path handles RLE blocks; this difference is an integration compatibility hazard. `ZSTDv07_decompressBlock()` updates `previousDstEnd` using the returned size even when the returned value is an encoded error, so callers must treat block API errors immediately. Checksum verification is implemented in the streaming block-header end path; one-shot frame decompression updates the checksum but does not compare a checksum value at frame end in this legacy implementation, which should be preserved or deliberately tested before changing.

Test signals: Use v0.7 golden frames for one-shot, DCtx reuse, dictionary, DDict, buffer-less streaming, and ZBUFF streaming. Cover skippable frames, truncated minimal and full headers, bad magic, reserved frame bits, unsupported oversized windows, dictionary-ID mismatch, raw-content dictionaries, dictionary header entropy failures, repeat literal blocks without prior entropy, raw/RLE/compressed/end blocks, malformed literal sizes, sequence-table modes, long sequence counts, offset-before-history corruption, non-contiguous output buffers, checksum success/failure in streaming mode, exact-size source requirements, and memory-allocation failure through custom allocators where reachable.
