# Research: sources/compression/zstd/lib/legacy/zstd_v04.c

Purpose: Implements the standalone legacy decoder for zstd v0.4 frames (`0xFD2FB524`). It carries the same embedded MEM/bitstream/FSE/Huff0 decoder stack as v0.3, adds a v0.4 frame-parameter header with `windowLog`, supports dictionary/prefix continuity in the block decoder, and provides both direct `ZSTDv04_*` streaming and buffered `ZBUFFv04_*` streaming APIs used by the generic legacy streaming bridge.

Important APIs, types, and functions: Public zstd wrappers defined in this C file are `ZSTDv04_decompress()`, `ZSTDv04_decompressDCtx()`, `ZSTDv04_createDCtx()`, `ZSTDv04_freeDCtx()`, `ZSTDv04_resetDCtx()`, `ZSTDv04_nextSrcSizeToDecompress()`, and `ZSTDv04_decompressContinue()`, plus `ZSTDv04_findFrameSizeInfoLegacy()`. Exported buffered APIs are `ZBUFFv04_createDCtx()`, `ZBUFFv04_freeDCtx()`, `ZBUFFv04_decompressInit()`, `ZBUFFv04_decompressWithDictionary()`, `ZBUFFv04_decompressContinue()`, `ZBUFFv04_isError()`, `ZBUFFv04_getErrorName()`, `ZBUFFv04_recommendedDInSize()`, and `ZBUFFv04_recommendedDOutSize()`. `ZSTDv04_Dctx_s` stores FSE tables, prefix/dictionary pointers (`base`, `vBase`, `dictEnd`, `previousDstEnd`), frame params, stage, block type, literal state, and a 5-byte header buffer. `ZBUFFv04_DCtx_s` wraps a `ZSTD_DCtx`, input/output ring buffers, dictionary reference, header assembly state, and buffered-decompression stage.

Control flow: The v0.4 frame header is five bytes: magic plus a descriptor byte. `ZSTD_decodeFrameHeader_Part1()` validates magic and returns the fixed header size; `ZSTD_getFrameParams()` extracts `windowLog` from the low nibble and rejects reserved high bits; part 2 rejects overly large windows on 32-bit builds. One-shot decompression resets the context, optionally inserts a dictionary as an external prefix, decodes the frame header, then loops over block headers and content. Compressed block flow is literals then FSE-coded sequences, as in v0.3. The sequence executor can satisfy matches from the current prefix or an external dictionary segment by translating through `vBase` and `dictEnd`. Direct streaming is a four-stage state machine: get frame header size, decode frame header, decode block header, decompress block. Buffered streaming first accumulates enough header bytes to determine `windowLog`, allocates or grows `inBuff` to one block and `outBuff` to `1 << windowLog`, optionally inserts a dictionary, then alternates direct reads, buffered loads, and flushing decoded output to the caller.

State and persistence behavior: One-shot calls can allocate the decode context on heap when `ZSTD_HEAPMODE == 1`, otherwise on stack. Direct contexts persist frame stage, expected byte count, entropy tables, literal buffer, and dictionary/prefix history across calls. `ZSTD_checkContinuity()` updates prefix bookkeeping when the destination pointer is not contiguous with prior output, allowing matches across an external dictionary and current prefix. `ZBUFFv04_DCtx` persists heap buffers across frames and only grows them; `ZBUFFv04_freeDCtx()` releases the wrapped zstd context and both buffers. `ZBUFFv04_decompressWithDictionary()` stores a borrowed dictionary pointer, so the dictionary must remain valid through decompression. Frame-size-info again scans block headers and reports `nbBlocks * BLOCKSIZE` as a decompressed bound, not an exact size.

Dependencies and integration points: Includes `zstd_v04.h`, `../common/compiler.h`, `../common/error_private.h`, and `../common/debug.h`, plus standard allocation and memory headers. `zstd_legacy.h` dispatches one-shot version 4 decompression to `ZSTDv04_decompress()`, frame-size queries to `ZSTDv04_findFrameSizeInfoLegacy()`, and generic legacy streaming to the `ZBUFFv04_*` buffered API. The generic streaming bridge creates/reuses `ZBUFFv04_DCtx`, initializes it with the caller's dictionary, passes `ZSTD_inBuffer`/`ZSTD_outBuffer` windows into `ZBUFFv04_decompressContinue()`, and propagates the returned input-size hint.

Risks: RLE blocks are still rejected even though RLE literals are decoded. The buffered path allocates output history based on untrusted `windowLog`, bounded only by format checks and 32-bit restrictions. Dictionary support is borrowed-reference based and has no lifetime enforcement. The direct streaming API requires exact input sizes; the buffered API hides that but has more state transitions and partial-consumption behavior to test. Pointer arithmetic in prefix/dictionary match resolution is subtle, especially when matches span dictionary and current output. `ZSTDv04_isError()` is declared in the header but no matching definition appears in this source, while `ZBUFFv04_isError()` is defined. Some static analyzer appeasement changes differ from v0.3, so maintaining both snapshots mechanically can introduce behavior drift.

Test signals: Cover frame-header reserved-bit rejection, 32-bit large-window rejection, `windowLog`-driven buffer sizing, magic mismatch, truncated header/block cases, end block with trailing input, raw blocks, compressed blocks, unsupported RLE blocks, dictionary-only matches, matches spanning dictionary and prefix, non-contiguous direct streaming output, buffered streaming with tiny input and output slices, header split across calls, output flush backpressure, dictionary lifetime assumptions in integration tests, and `ZSTD_decompressLegacyStream()` dispatch for version 4.
