# sources/compression/zstd/lib/legacy/zstd_v05.c

## Purpose
This file is a self-contained legacy Zstandard v0.5 decompressor. It embeds the old memory helpers, bitstream reader, FSE decoder, Huffman decoder, v0.5 frame/block decoder, dictionary loader, direct streaming API, and buffered `ZBUFFv05` wrapper in one translation unit. Its role is compatibility: callers can decode frames with magic `ZSTDv05_MAGICNUMBER` (`0xFD2FB525`) and old dictionary format `ZSTDv05_DICT_MAGIC` without depending on current zstd frame internals.

## Important APIs, Types, And Functions
The public zstd-facing entry points are `ZSTDv05_decompress()`, `ZSTDv05_decompressDCtx()`, `ZSTDv05_decompress_usingDict()`, `ZSTDv05_decompress_usingPreparedDCtx()`, `ZSTDv05_decompressBlock()`, `ZSTDv05_getFrameParams()`, `ZSTDv05_findFrameSizeInfoLegacy()`, `ZSTDv05_decompressBegin()`, `ZSTDv05_decompressBegin_usingDict()`, `ZSTDv05_nextSrcSizeToDecompress()`, `ZSTDv05_decompressContinue()`, `ZSTDv05_createDCtx()`, `ZSTDv05_freeDCtx()`, `ZSTDv05_copyDCtx()`, `ZSTDv05_isError()`, and `ZSTDv05_getErrorName()`.

`struct ZSTDv05_DCtx_s` is the main decoder state. It owns FSE decode tables for literal length, match length, and offset codes; a Huffman X4 table; history pointers (`previousDstEnd`, `base`, `vBase`, `dictEnd`); streaming expectations; parsed frame parameters; current block type; literal buffers; and a small frame-header buffer. `ZSTDv05_dStage` drives the direct streaming state machine.

The embedded entropy APIs include `FSEv05_readNCount()`, `FSEv05_buildDTable()`, `FSEv05_buildDTable_raw()`, `FSEv05_buildDTable_rle()`, `FSEv05_decompress_usingDTable()`, `HUFv05_readDTableX2()`, `HUFv05_readDTableX4()`, `HUFv05_decompress1X2()`, `HUFv05_decompress1X4()`, `HUFv05_decompress4X2()`, `HUFv05_decompress4X4()`, and `HUFv05_decompress()`. These are not merely declarations; the decompressor uses their local implementations to rebuild Huffman and FSE tables from legacy block payloads and dictionaries.

The buffered streaming API is implemented around `struct ZBUFFv05_DCtx_s` and exposes `ZBUFFv05_createDCtx()`, `ZBUFFv05_freeDCtx()`, `ZBUFFv05_decompressInit()`, `ZBUFFv05_decompressInitDictionary()`, `ZBUFFv05_decompressContinue()`, `ZBUFFv05_isError()`, `ZBUFFv05_getErrorName()`, `ZBUFFv05_recommendedDInSize()`, and `ZBUFFv05_recommendedDOutSize()`.

## Control Flow
One-shot decompression starts in `ZSTDv05_decompress()`, allocates or stack-allocates a `ZSTDv05_DCtx` depending on `ZSTDv05_HEAPMODE`, initializes it through `ZSTDv05_decompressDCtx()`, optionally loads a dictionary, and enters `ZSTDv05_decompress_continueDCtx()`. That function validates the v0.5 frame header, loops over 3-byte block headers via `ZSTDv05_getcBlockSize()`, and dispatches each block to compressed, raw, RLE, or frame-end handling. Raw blocks copy through `ZSTDv05_copyRawBlock()`. RLE blocks are recognized but return `ERROR(GENERIC)`, so legacy v0.5 RLE block support is incomplete here. Compressed blocks flow through `ZSTDv05_decompressBlock_internal()`.

Compressed block decoding first calls `ZSTDv05_decodeLiteralsBlock()`. Literal sections can be Huffman-compressed (`IS_HUFv05`), dictionary-precomputed Huffman (`IS_PCH`), raw (`IS_RAW`), or RLE (`IS_RLE`). Huffman literals rebuild or reuse decode tables and write to `dctx->litBuffer`, while raw literals may either reference the source buffer directly or copy into `litBuffer` when wildcopy padding would otherwise read beyond the compressed input. After literals, `ZSTDv05_decompressSequences()` parses sequence headers with `ZSTDv05_decodeSeqHeaders()`, initializes three FSE states plus a backward bitstream, repeatedly calls `ZSTDv05_decodeSequence()`, and materializes each sequence with `ZSTDv05_execSequence()`. The sequence executor copies literal runs, resolves match references against the current prefix or external dictionary, handles close-offset overlap copies, and appends any final literal tail.

Direct streaming is a strict pull state machine. `ZSTDv05_decompressBegin()` initializes `expected` to the minimum frame header size and sets the stage to `ZSTDv05ds_getFrameHeaderSize`. Callers must alternate `ZSTDv05_nextSrcSizeToDecompress()` and `ZSTDv05_decompressContinue()` with exactly the requested input size. `ZSTDv05_decompressContinue()` transitions through frame header size, frame header decode, block header decode, and block body decode. It returns zero for metadata-only steps and returns regenerated bytes for block bodies. When a frame-end block is seen, `expected` becomes zero and the stage resets for a future frame.

Dictionary flow is split from frame flow. `ZSTDv05_decompressBegin_usingDict()` resets the context, then `ZSTDv05_decompress_insertDictionary()` either treats a non-magic dictionary as pure match history or, for `ZSTDv05_DICT_MAGIC`, loads a Huffman table plus offset, match-length, and literal-length FSE tables with `ZSTDv05_loadEntropy()`, marks `flagStaticTables`, and then references the remaining dictionary bytes as external content. `ZSTDv05_decompress_usingPreparedDCtx()` copies a preloaded context with `ZSTDv05_copyDCtx()` before decoding.

Buffered streaming (`ZBUFFv05_decompressContinue()`) wraps the direct streaming API. Its stages read or complete the frame header, allocate an input buffer of `BLOCKSIZE` and an output history buffer sized from `windowLog`, decode directly from caller input when enough bytes are available, otherwise accumulate into `inBuff`, then flush decoded data from `outBuff` to the caller. When the output history window nears the end of `outBuff`, it preserves the last `windowSize` bytes with `memmove()` so future back-references remain valid.

## State, Persistence, And Dependencies
`ZSTDv05_DCtx` is persistent across streaming calls and across dictionary-prepared decodes. Its entropy tables, static-table flag, history pointers, literal buffer, expected input size, and state-machine stage determine correctness. The code assumes the caller preserves decoded output history according to the direct streaming contract; otherwise `ZSTDv05_checkContinuity()` switches to an external-dictionary view using `dictEnd`, `base`, and `vBase`.

`ZBUFFv05_DCtx` owns heap buffers and a nested `ZSTDv05_DCtx`. It persists partial header bytes, partial block input, output-history positions, and current stage between calls. `ZBUFFv05_freeDCtx()` frees the nested context and both buffers and tolerates a null wrapper pointer.

Dependencies are intentionally minimal but tightly coupled to zstd internals. The file includes `zstd_v05.h` and `../common/error_private.h`, embeds old `mem.h` functionality, and uses C library allocation and memory routines (`malloc`, `calloc` include, `free`, `memcpy`, `memmove`, `memset`). Error values and names are delegated through `ERR_isError()` and `ERR_getErrorName()`.

## Integration Points
This implementation backs the declarations in `zstd_v05.h` and is expected to be called by the repository's legacy frame dispatcher when it detects the v0.5 magic number. `ZSTDv05_findFrameSizeInfoLegacy()` integrates with frame-size probing: it scans block headers without decoding payloads, returns the compressed frame length in `cSize`, and returns a decompressed upper bound as `nbBlocks * BLOCKSIZE`.

The file intentionally mirrors old internal APIs (`FSEv05_*`, `HUFv05_*`, `ZBUFFv05_*`) so the legacy decoder can build without linking the current entropy implementation. It also exports error helper wrappers for zstd, FSE, Huffman, and ZBUFF naming families, all sharing the current `error_private.h` backend.

## Risks
This code is compatibility-critical and parser-heavy. The largest risks are malformed legacy inputs causing over-read, overwrite, integer wrap, or corrupted history references. There are many explicit bounds checks around compressed sizes, literal sizes, bitstream completion, FSE table logs, and destination capacity, but several hot paths intentionally use wildcopy and then rely on earlier capacity checks and padding decisions. `ZSTDv05_execSequence()` is especially sensitive because it computes literal and match end pointers and supports both prefix and external-dictionary matches.

RLE frame blocks are parsed in `ZSTDv05_getcBlockSize()` but return `ERROR(GENERIC)` in both one-shot and streaming block dispatch. That means v0.5 streams containing RLE data blocks are unsupported even though RLE literals are supported. The buffered wrapper also has allocation and state risks: after freeing an undersized buffer, it assigns the new size before checking whether `malloc()` succeeds, so a failed allocation leaves the context in a partially updated state. Direct streaming requires exact input sizes; callers that pass arbitrary chunks will get `srcSize_wrong`.

The dictionary path trusts the legacy dictionary layout after the magic number and maps any entropy-table parse failure to `dictionary_corrupted`. Static entropy tables are available only after a valid dictionary load; compressed data that requests static tables without `flagStaticTables` fails. Context copying deliberately skips the large literal workspace and header buffer, so it is suitable for prepared table/history state, not for cloning an in-progress block workspace.

## Test Signals
High-value test signals are golden v0.5 frame round trips, malformed frame fuzzing, dictionary and prepared-context compatibility tests, and streaming chunk-boundary tests that obey exact `nextSrcSize` values. Coverage should include raw blocks, compressed blocks with Huffman and raw/RLE literal sections, static dictionary tables, external dictionary references crossing into current output, non-contiguous direct streaming destinations, frame-size probing, unsupported RLE data blocks, short headers, oversized block sizes, invalid FSE/Huffman table logs, and output buffers that are exactly full or one byte too small. Sanitizers are particularly valuable around `ZSTDv05_decodeLiteralsBlock()`, `ZSTDv05_decompressSequences()`, `ZSTDv05_execSequence()`, and `ZBUFFv05_decompressContinue()`.
