# sources/compression/zstd/lib/legacy/zstd_v01.c

Purpose: self-contained decoder implementation for Zstandard legacy frame format v0.1.x. It exists so the legacy dispatch layer can decode the oldest supported zstd streams without depending on current-format internals. The file embeds historical FSE, Huff0, bitstream, block, sequence, frame-size, one-shot decompression, and streaming decompression logic for this format generation.

Important APIs/types/functions: exported entry points are `ZSTDv01_isError()`, `ZSTDv01_decompressDCtx()`, `ZSTDv01_decompress()`, `ZSTDv01_findFrameSizeInfoLegacy()`, `ZSTDv01_resetDCtx()`, `ZSTDv01_createDCtx()`, `ZSTDv01_freeDCtx()`, `ZSTDv01_nextSrcSizeToDecompress()`, and `ZSTDv01_decompressContinue()`. Internally, the decoder is built around `FSE_DStream_t`, `FSE_DState_t`, `FSE_decode_t`, `HUF_DElt`, `blockProperties_t`, `seq_t`, `seqState_t`, and `ZSTDv01_Dctx_s`/`dctx_t`. Key helpers include `FSE_readNCount()`, `FSE_buildDTable()`, `FSE_decompress_usingDTable_generic()`, `HUF_readDTable()`, `HUF_decompress_usingDTable()`, `ZSTDv01_getcBlockSize()`, `ZSTDv01_decodeLiteralsBlock()`, `ZSTDv01_decodeSeqHeaders()`, `ZSTD_decodeSequence()`, `ZSTD_execSequence()`, `ZSTD_decompressSequences()`, and `ZSTD_decompressBlock()`.

Control flow: one-shot decode starts in `ZSTDv01_decompress()`, initializes a stack context with `base = dst`, and calls `ZSTDv01_decompressDCtx()`. The frame decoder requires the 4-byte big-endian v0.1 magic, then iterates 3-byte block headers until a `bt_end` block. Each compressed block first decodes a literals sub-block, then sequence headers, then an FSE-coded bitstream of sequences. Sequence execution copies literals, resolves repeat offsets through `prevOffset`, and copies matches from the current history base. Raw blocks are direct `memcpy()`. Top-level RLE blocks return `ERROR(GENERIC)`, while RLE literals and RLE FSE sequence tables are supported. Frame-size discovery mirrors block walking without decompression and reports `nbBlocks * BLOCKSIZE` as the decompressed bound.

State and persistence: the reusable context stores FSE decode tables for LL, offset, and ML symbols, plus streaming fields `previousDstEnd`, `base`, `expected`, `bType`, and `phase`. `ZSTDv01_decompressContinue()` is a strict pull state machine: phase 0 consumes exactly the frame header, phase 1 consumes exactly a block header, and phase 2 consumes exactly the announced block payload. If caller-provided output is contiguous with the previous output end, matches may refer to prior blocks; otherwise `base` is reset to the new destination. No dictionary state is accepted and no durable state is persisted outside the caller-owned context.

Dependencies and integration points: includes `zstd_v01.h`, `../common/compiler.h`, and `../common/error_private.h`, while carrying its own historical FSE/HUF/MEM-compatible code. `sources/compression/zstd/lib/legacy/zstd_legacy.h` includes this header when `ZSTD_LEGACY_SUPPORT <= 1`, recognizes `ZSTDv01_magicNumberLE`, dispatches version 1 frames to `ZSTDv01_decompress()`, and calls `ZSTDv01_findFrameSizeInfoLegacy()` for legacy frame-size probing. Build project files and CMake legacy lists compile this file as part of the zstd legacy library.

Risks: this is safety-sensitive decompression code that manually handles untrusted lengths, pointer arithmetic, overlapping copies, and reverse bitstreams. Notable risk points include comments around 32-bit address-space overflow, match underflow checks, `ZSTD_wildcopy()` copying past requested lengths by design, v0.1-specific literal layout reading bits from `ip[-3]`, and the need for exact `srcSize` accounting. Error-code conversion is mixed: historical FSE errors are sometimes collapsed to generic zstd errors. Top-level RLE block rejection is intentional in code but can surprise compatibility callers. Streaming callers must obey exact `nextSrcSizeToDecompress()` sizes and provide output buffers that preserve block history when cross-block matches are expected.

Test signals: useful tests include golden v0.1 frames covering compressed, raw, end, compressed literals, raw literals, RLE literals, raw/RLE/FSE sequence tables, repeat-offset cases, multi-block history, non-contiguous streaming output, truncated headers, wrong magic, malformed FSE/HUF tables, too-small destinations, top-level RLE block rejection, and frame-size probing on complete and incomplete frames. Fuzz tests should emphasize block header sizes, dumps lengths, max LL/ML extension paths, offset underflow, and 32-bit overflow-sensitive pointer math.
