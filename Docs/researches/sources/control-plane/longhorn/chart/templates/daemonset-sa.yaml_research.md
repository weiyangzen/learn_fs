# sources/control-plane/longhorn/chart/templates/daemonset-sa.yaml

Purpose: Renders the Longhorn manager DaemonSet plus the `longhorn-backend` Service. The DaemonSet runs one privileged `longhorn-manager` pod per eligible node, passes the manager all required component image references, mounts host paths needed for storage operations, exposes manager and webhook ports, and pre-pulls the share-manager image.

Important APIs/types/functions: Kubernetes types are `apps/v1` `DaemonSet` and `v1` `Service`. Helm helpers include `longhorn.labels`, `release_namespace`, `registry_url`, and `longhorn.timezoneEnv`. Key values include `image.longhorn.manager/engine/instanceManager/shareManager/backingImageManager/supportBundleKit`, `global.imageRegistry`, `privateRegistry.registrySecret`, `image.pullPolicy`, `longhornManager.log.format`, `preUpgradeChecker.upgradeVersionCheck`, `longhornManager.resources`, `longhornManager.priorityClass`, `longhornManager.tolerations`, `global.tolerations`, `global.nodeSelector`, `longhornManager.nodeSelector`, `global.cattle.windowsCluster.*`, `enableGoCoverDir`, `annotations`, `longhornManager.updateStrategy`, `service.manager.type`, and `service.manager.nodePort`.

Control flow: Helm builds the manager image from registry precedence `global.imageRegistry`, private/system `registry_url`, then image-specific registry, and injects the final repository/tag into the container. The manager command runs `longhorn-manager -d [ -j ] daemon` with flags for engine, instance manager, share manager, backing image manager, support bundle manager, manager image, service account, and optional upgrade version check. Kubernetes schedules the DaemonSet with optional tolerations/node selectors and update strategy. The service selects pods with `app: longhorn-manager` and exposes port 9500 as `manager`; the pod also opens ports 9502 and 9503 for admission webhook and recovery backend.

State and persistence behavior: The DaemonSet itself is desired cluster state. Manager pods mount host `/boot`, `/dev`, `/proc`, `/etc`, and `/var/lib/longhorn` into the container; `/var/lib/longhorn` uses bidirectional mount propagation, so pod operations affect host storage state. Optional `/go-cover-dir` persists coverage data on the host. Environment variables inject pod name, namespace, IP, node name, optional distro, optional coverage directory, and optional timezone. The optional `longhorn-grpc-tls` secret is mounted at `/tls-files/` and marked optional.

Dependencies and integration points: Requires `longhorn-service-account` and the RBAC from `clusterrole.yaml`/`clusterrolebinding.yaml`. It integrates with registry helper logic, private registry secrets, Longhorn default settings and image values, admission webhook clients, backend service consumers, CSI deployer behavior, support bundle generation, OpenShift/Windows scheduling values, and Kubernetes hostPath/mount-propagation support.

Risks: The manager container is privileged and mounts sensitive host paths, so node compromise risk is inherent. Incorrect image registry precedence or missing image tags prevents startup or later system-managed component creation. Optional TLS secret behavior means the workload can start without gRPC TLS material, which must match manager expectations. Service type and nodePort values can expose the backend more broadly than intended. The pre-pull share-manager sidecar sleeps forever; resource and security policy must account for it. Windows-cluster toleration/nodeSelector merging is complex and should be tested whenever scheduling defaults change.

Test signals: `helm template` should cover default, JSON log format, private registry, global image registry, imagePullSecrets as string and list, OpenShift/Windows scheduling, coverage, priorityClass, nodeSelector/tolerations, and service nodePort branches. Runtime tests should verify manager pod readiness on `/v1/healthz` over port 9502, backend service selection on port 9500, hostPath/mount propagation behavior, and successful creation of dependent Longhorn system pods with the image flags provided here.
