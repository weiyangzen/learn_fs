# sources/control-plane/rook/pkg/operator/ceph/cluster/osd/update_test.go

Purpose: unit coverage for OSD update orchestration and cephx key rotation. The tests replace package-level hooks for deployment updates, OSD deployment creation, status conditions, and ok-to-stop checking to isolate control flow. Major cases verify no-op empty queues, one-at-a-time and multi-OSD ok-to-stop batches, filtering of OSDs outside the queue or existence list, requeue when ok-to-stop fails, forced progress with `ContinueUpgradeAfterChecksEvenIfNotHealthy`, PG cleanliness gates, deployment update failures, malformed existing deployments, removed storage nodes, skip-reconcile labels, and node label/CR device-class conflicts. Additional tests cover `getOSDUpdateInfo()` label selection and error accumulation, `updateQueue` FIFO/remove behavior, `existenceList`, and `rotateCephxKey()` status semantics. Persistence signals are fake Kubernetes Deployments and Ceph auth command mocks. Risks covered include queue correctness, missed OSD IDs, update failure accounting, and brownfield/greenfield cephx status transitions.
