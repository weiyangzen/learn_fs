# sources/control-plane/rook/deploy/examples/monitoring/grafana/Ceph OSD Single Dashboard.json

Purpose: defines the bundled Grafana "Ceph - OSD (Single)" dashboard for inspecting one selected Ceph OSD. It narrows the cluster view to a template-selected `ceph_daemon` and shows OSD up/in status, total OSD count, PG count compared with cluster average, storage availability/usage, utilization, latency heatmaps, and average read/write/apply/commit latency.

Important APIs/types/functions: this is Grafana dashboard JSON. Its API surface is the dashboard import contract plus PromQL queries: top-level `uid` `Fj5fAfzik`, title `Ceph - OSD (Single)`, schema version `36`, tags `ceph` and `osd`, refresh `5m`, browser timezone, default time range `now-3h` to `now`, datasource template `DS_PROMETHEUS`, interval template `interval`, and query template variable `osd` populated by `label_values(ceph_osd_up, ceph_daemon)`. The dashboard has 15 titled panel objects: status/total rows and stat panels, an OSD-specific row, PG and storage timeseries, utilization gauge, latency row, four OSD latency heatmaps, read/write operation latency timeseries, and apply/commit latency timeseries.

Control flow: Grafana first resolves the Prometheus datasource, interval choices, and selected `$osd`. Status panels query `ceph_osd_up{ceph_daemon="$osd"}` and `ceph_osd_in{ceph_daemon="$osd"}` while the total count queries all `ceph_osd_up` series. The PG panel compares `ceph_osd_numpg{ceph_daemon=~"$osd"}` with the cluster average. Storage panels query `ceph_osd_stat_bytes` and `ceph_osd_stat_bytes_used`; most panels filter by `$osd`, but the available-storage and utilization expressions are hard-coded to `ceph_daemon="osd.0"`. Latency heatmaps and timeseries filter apply/commit metrics or read/write latency sum/count ratios to the selected daemon and aggregate away `instance` and sometimes `ceph_daemon`.

State and persistence behavior: the file is declarative and has no direct runtime state. Grafana persists the imported dashboard definition and browser/session selections for datasource, time range, interval, and `$osd`. Prometheus persists the OSD metric series. The dashboard performs no mutation of Ceph or Kubernetes resources.

Dependencies and integration points: depends on Grafana 9-era panel support, the Prometheus datasource plugin, and Ceph mgr Prometheus metrics for `ceph_osd_up`, `ceph_osd_in`, `ceph_osd_numpg`, `ceph_osd_stat_bytes`, `ceph_osd_stat_bytes_used`, `ceph_osd_apply_latency_ms`, `ceph_osd_commit_latency_ms`, and read/write latency sum/count metrics. It integrates with Rook's monitoring examples as an importable focused dashboard, typically linked operationally from cluster-level OSD investigations even though this JSON does not define dashboard links.

Risks: the available-storage and utilization panels contain `ceph_daemon="osd.0"` rather than the `$osd` variable, so selecting any other OSD can still show OSD 0 storage availability and utilization. Two row panels carry a concrete datasource UID `PBFA97CFB590B2093` instead of `${DS_PROMETHEUS}` even though row targets are effectively empty; this can confuse import diffs or validation in Grafana instances without that UID. The row title spells "Varience", which is cosmetic but can affect automated snapshot comparisons. The dashboard assumes `ceph_daemon` label values match strings such as `osd.0`; label changes or absent metrics will leave the variable and panels empty. Rate-based latency ratios can disappear when operation counts are zero, making idle OSDs look blank rather than explicitly zero.

Test signals: validate JSON syntax and import into Grafana, then confirm the `osd` variable populates from `label_values(ceph_osd_up, ceph_daemon)`. In a cluster with at least two OSDs, select a non-`osd.0` daemon and verify status, PGs, used storage, heatmaps, and average latencies follow the selected OSD; the hard-coded availability/utilization queries should be tested and likely corrected if the dashboard is expected to be fully variable-driven. Also test idle OSDs with no read/write counts, down/out OSDs, and import into Grafana instances where the fixed row datasource UID does not exist.
