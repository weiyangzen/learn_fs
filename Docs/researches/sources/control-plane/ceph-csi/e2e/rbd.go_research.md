# sources/control-plane/ceph-csi/e2e/rbd.go

Purpose: defines the main Ginkgo end-to-end suite for Ceph-CSI RBD. It deploys or targets the RBD provisioner/nodeplugin, creates the required ConfigMaps, StorageClasses, Secrets, Ceph users, Vault/KMS support, topology labels, and then exercises dynamic RBD provisioning, metadata, snapshots, clones, static PVs, migration, encryption, rbd-nbd, topology-constrained pools, rados namespaces, trash cleanup, resize, QoS, cgroup QoS, and volume group snapshots.

Important APIs/types/functions: `RBDDeployment` wraps `DriverInfo` and is returned by `NewRBDDeployment`; operator mode swaps in `NewRBDOperatorDeployment`. `deployRBDPlugin`, `deleteRBDPlugin`, and `createORDeleteRbdResources` apply/delete the RBD CSI driver object, ceph.conf ConfigMap, provisioner RBAC/deployment, and nodeplugin RBAC/daemonset. `validateRBDSnapshotCount`, `validateRBDImageCount`, `formatImageMetaGetCmd`, `checkGetKeyError`, and `checkClusternameInMetadata` are local assertion helpers around toolbox `rbd` commands and cluster metadata. `ItFileAndBlockEncryption` and `ByFileAndBlockEncryption` duplicate encryption cases across block encryption and fscrypt file encryption when `testRBDFSCrypt` is enabled.

Control flow: the top-level `Describe("RBD")` creates a privileged Kubernetes e2e framework and an ordered `Context`. `BeforeEach(..., OncePerOrdered)` gates on `testRBD`/`upgradeTesting`, initializes the deployment adapter, optionally creates the Ceph-CSI namespace, labels nodes for topology and CRUSH location, deploys RBD manifests when requested, creates the RBD config map and default StorageClass, creates provisioner/node Ceph users and Kubernetes Secrets, deploys Vault, waits for CSI pods, captures kernel version, adjusts NBD map options for old kernels, and configures domain labels, fencing, and cluster name. `AfterEach(..., OncePerOrdered)` dumps CSI pod logs and namespace details on failure, then removes config maps, secrets, storage class, Vault, plugin manifests, namespace, and node labels.

State and persistence: tests create persistent Kubernetes resources and verify the corresponding Ceph-side state. PVCs create RBD images and CSI omap entries under `defaultRBDPool`; snapshots create backing RBD images and snap omap entries; clones can add temporary images; deletes are checked through image/omap counts and trash-drain waits. Several cases mutate StorageClass parameters and then restore the default class. Tests directly patch PV reclaim policy and claim refs for reattach coverage, modify PVC `VolumeAttributesClassName`, create/delete Ceph users with scoped caps, update the global `radosNamespace` and recreate the ConfigMap, and restart CSI pods to force configuration reload.

Dependencies/integration: this suite depends on Kubernetes e2e framework/client-go, Ginkgo/Gomega, Kubernetes core APIs, Ceph toolbox execution helpers, Ceph-CSI e2e helper functions in the same package, deployment YAML under `deploy/rbd/kubernetes`, examples under `examples/rbd`, templates under `e2e/templates`, Vault/KMS helpers, Ceph user/caps helpers, RBD image/snapshot/journal helpers, kernel feature gates from `pkg/util/kernel`, and encryption type constants from `pkg/util/crypto`. It integrates with CSI external provisioner metadata keys, VolumeSnapshot/VolumeSnapshotContent, VolumeAttributesClass, cgroup v2 QoS paths, topology labels, RBD trash, rbd-nbd processes, and optional Helm/operator deployment modes.

Major test coverage: the suite validates helm-installed RBD binding; userId and client address metadata; read affinity and SELinux mount options; PVC/PV metadata and cluster name in RBD image metadata; PV reattachment metadata updates; snapshot metadata and absence of stale PVC metadata on snapshot images; generic ephemeral volumes; migration and migrated static PVCs; image owner tracking; normal-user PVC access; RWOP filesystem/block exclusivity; erasure-coded data pools; cross-pool snapshot restore and clone between replica and EC pools; ext4/xfs and mkfs inode options; rbd-nbd attach, resize, multipod ROX/RWX block behavior, nodeplugin restart, and encrypted NBD volumes; image feature combinations including fast-diff, deep-flatten, journaling, temp clone inheritance, and empty features; KMS variants for Vault, tenant token, tenant service account, and secrets metadata; encrypted snapshot restore and PVC-PVC clones across KMS classes; static filesystem/block PVs and expected static-PV validation failure without image features; topology-constrained provisioning and data pool selection; invalid mount options; clones in a different pool; ROX snapshot and PVC clones mounted to multiple pods; deleted parent/snapshot clone chains; rados namespace operation; readonly mounts; map/unmap options; controller behavior; trash cleanup; service account volume restrictions; bigger snapshot restores and PVC clones; image stripe parameters; RBD image QoS through VolumeAttributesClass; cgroup-v2 QoS through VAC across filesystem, block, RWOP, multipvc pods, modifications, partial updates, snapshot/clone non-propagation, RWX/ROX deployments, expansion, and encrypted volumes; default encryption type; volume group snapshots; Ceph user deletion; and PVC deletion when the backend pool is removed.

Risks: this file is a very broad, ordered integration suite, so failures can cascade when setup, StorageClass restoration, secrets, or backend cleanup is incomplete. Many tests depend on exact image/omap counts in shared pools, making leaked images, trash lag, parallel tests, or previous failures visible as later failures. Several paths are environment-sensitive: kernel version gates fast-diff, deep-flatten, NBD resize, and zero I/O timeout behavior; `testNBD`, `testRBDFSCrypt`, Helm, operator, Kubernetes version, ceph-csi version, and librbd volume-group-snapshot support all change coverage. The suite mutates global `radosNamespace` and `nbdMapOptions`, node labels, Ceph users, and StorageClasses, so cleanup bugs affect subsequent specs. Some tests use direct `rbd` CLI output and string matching for errors, read-only failures, metadata, and process state; changes in Ceph/Kubernetes wording or toolbox images can break assertions without product regressions. The reattach, trash, deleted-parent clone, and pool-deletion cases intentionally exercise unusual lifecycle states and require careful recovery on failure.

Test signals: successful execution is signaled by all specs completing with backend RBD image counts returning to zero, CSI omap counts returning to zero for volumes/snaps, expected metadata present or absent on images, snapshot and clone data checksums matching, ROX/readonly writes failing with expected errors, resize checks observing updated filesystem/device sizes, rbd-nbd processes surviving nodeplugin restart, topology PV selectors and pool placement matching node labels, KMS/encryption validators confirming encrypted volumes, QoS validators observing expected RBD image options or cgroup metadata, trash drains completing, and final pool-deletion cleanup succeeding. On failure, the `AfterEach` hook collects Helm/provisioner/nodeplugin logs and dumps the Ceph-CSI namespace, which is the primary diagnostic signal for this suite.
