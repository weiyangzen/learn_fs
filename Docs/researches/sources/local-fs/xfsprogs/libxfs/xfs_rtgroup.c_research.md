# File Research: sources/local-fs/xfsprogs/libxfs/xfs_rtgroup.c

This file implements incore realtime group lifecycle, per-rtgroup metadata inode management, rtgroup locking/transaction joining, realtime group geometry reporting, and realtime superblock buffer verification/logging.

The geometry helpers compute the usable blocks and realtime extents for each group. `xfs_rtgroup_min_block` reserves the first realtime extent of group 0 when the realtime superblock feature exists. `__xfs_rtgroup_extents` handles the tail group specially because the last group can be shorter than `sb_rgextents`. `xfs_rtgroup_calc_geometry` stores the extent count, block count, and minimum group block number into the embedded `xfs_group`.

The lifecycle functions allocate and insert `struct xfs_rtgroup` objects into the generic group table. `xfs_rtgroup_alloc`, `xfs_rtgroup_free`, `xfs_initialize_rtgroups`, and `xfs_free_rtgroups` are the rtgroup analogues of per-AG setup/teardown. `xfs_update_last_rtgroup_size` exists for growfs recovery: if replay changes the realtime section size, the previous final rtgroup's incore extent and block counts are recomputed.

Locking is metadata-inode based. `xfs_rtgroup_lock` and `xfs_rtgroup_unlock` lock bitmap/summary inodes for non-zoned free space accounting and optionally rmap/refcount inodes. Bitmap shared and exclusive modes are mutually exclusive. Zoned filesystems skip bitmap/summary locking because they do not use bitmap free-space metadata. `xfs_rtgroup_trans_join` joins the selected locked rtgroup metadata inodes to a transaction so commit releases the locks.

The `xfs_rtginode_ops` table defines all per-rtgroup metadata inode kinds: bitmap, summary, rmap, and refcount. Each entry maps a short name, metafile type, sickness flag, accepted data fork formats, feature predicate, and create callback. Bitmap and summary require non-zoned rt. Rmap uses `xfs_has_rmapbt` rather than `xfs_has_rtrmapbt` because growfs must create metadata inodes before an rt volume is attached. Refcount similarly uses `xfs_has_reflink`.

`xfs_rtginode_load` supports both legacy non-rtgroup filesystems and metadir rtgroups. Without rtgroups, only the global realtime bitmap and summary inode numbers from the superblock are loaded. With rtgroups, the parent metadir inode `m_rtdirip` must exist, and each per-rtgroup inode is loaded by generated path `<rgno>.<name>`. The loader validates the inode fork format and `i_projid == rgno`; failures mark the relevant rtgroup sickness flag. `xfs_rtginode_create` creates a metadir regular file, initializes its project id to the rtgroup number, runs the type-specific btree/bitmap initializer, commits the metadir update, and stores the inode in `rtg_inodes`.

The realtime superblock verifier covers only the realtime superblock structure, not the primary superblock. `xfs_rtsb_verify_common` checks magic, pad zeroing, and zeroed trailing block bytes. `xfs_rtsb_verify_all` additionally matches filesystem name, fs uuid, and metadata uuid against the mounted superblock. `xfs_rtsb_read_verify` checks CRC before structural validation, while `xfs_rtsb_write_verify` validates and updates the checksum. `xfs_update_rtsb` copies current primary superblock identity into an rt superblock, selecting `sb_meta_uuid` only when the meta-uuid feature is enabled. `xfs_log_rtsb` logs the rt superblock when present; it tolerates rtgroups being enabled without an attached rt section as long as `sb_rblocks == 0`.

Important dependencies are `xfs_group` for generic group storage, metadir/metafile helpers for rtgroup inode discovery, `xfs_rtbitmap` for bitmap and summary inode creation, realtime rmap/refcount btree creation callbacks, `xfs_health` sickness flags, and transaction buffer/inode APIs.
