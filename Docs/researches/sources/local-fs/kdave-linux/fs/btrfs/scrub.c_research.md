# File Research: sources/local-fs/kdave-linux/fs/btrfs/scrub.c

Read completely: 3330 lines.

This file implements the Btrfs scrub and device-replace verification engine. It walks device extents, finds the corresponding logical block groups and extent items, reads allocated sectors, verifies data checksums and metadata headers/checksums/generations, attempts repair from alternate mirrors, writes repaired sectors back when allowed, validates superblocks, and reports progress/error statistics through the scrub ioctl-facing API declared in `scrub.h`.

Core state is organized around `struct scrub_ctx` and `struct scrub_stripe`. A scrub context owns a fixed pool of 128 scrub stripes, reusable Btrfs paths for extent and checksum tree lookups, cancellation/throttle/dev-replace state, writeback synchronization for zoned devices, progress counters, and a reference count protecting worker lifetime. Each scrub stripe represents one `BTRFS_STRIPE_LEN` logical range, its folios, per-sector verification metadata, device/logical/physical/mirror identity, pending I/O count, repair wait queues, packed bitmaps for extent/error state, optional data checksum buffer, and repair work item.

The bitmap layer packs several per-sector maps into one `unsigned long` array: sectors covered by extent items, metadata sectors, aggregate errors, I/O errors, checksum errors, metadata header/checksum errors, and metadata generation errors. Macro-generated helpers set, clear, test, read, check emptiness, and count bits for each sub-bitmap. This keeps per-stripe state compact while allowing the read, verification, repair, and report phases to communicate sector status precisely.

Context setup allocates all stripe folios, sector verification arrays, checksum buffers, wait queues, locks, and dev-replace target state. Cleanup releases stripe memory and uses `scrub_put_ctx()` refcounting so asynchronous workers cannot wake waiters after the main scrub context has been freed.

Error reporting resolves corrupted logical addresses back to metadata tree references or data inode paths. `scrub_print_common_warning()` uses extent/backref helpers to identify tree blocks or affected inodes, while `scrub_print_warning_inode()` resolves filesystem paths and logs root/inode/offset/path details. Reporting is rate-limited for repeated detailed warnings. Device stats and `btrfs_scrub_progress` fields are updated from the initial error bitmap, remaining unrepaired bitmap, extent counts, no-checksum data sectors, read/csum/verify errors, corrected errors, and uncorrectable sectors.

Verification has separate metadata and data paths. Metadata verification checks tree block bytenr, metadata UUID, chunk tree UUID, checksum over the full tree block, and expected generation from the extent item. Data verification checks per-sector checksums when available and trusts NODATASUM sectors. I/O failures are marked by bio endio before checksum verification. Metadata tree blocks spanning a scrub stripe boundary are warned about and skipped because old filesystems may not be stripe-aligned.

The read/repair pipeline starts with `scrub_submit_initial_read()`. Normal chunks read the whole initialized stripe; stripe-tree-update cases submit extent-sector reads with explicit mapping boundaries. `scrub_read_endio()` marks I/O failures and queues `scrub_stripe_read_repair_worker()` when all initial reads finish. The repair worker verifies the initial read, records initial errors, tries alternate mirrors with large reads, then falls back to sector-sized reads across all mirrors. Repaired sectors are written back for ordinary scrub unless the filesystem is zoned, in which case the affected zone is queued for relocation. Dev-replace writeback is deferred to the flush phase so it can copy only verified good sectors and abort on unrepaired metadata.

Writeback uses `btrfs_submit_repair_write()` rather than the normal write path, allowing scrub to target the selected mirror or dev-replace target. Write bios are built from contiguous bits in a write bitmap. `scrub_write_endio()` records write errors under a spinlock and increments device write error stats. Zoned-device support serializes writeback, fills write-pointer gaps with zeroout, updates the cached write pointer only after successful writes, synchronizes the device write pointer after a stripe, and waits for ordered/NOCOW writes before dev-replace copies.

Extent discovery is driven from commit roots. `find_first_extent_item()` locates the first metadata or data extent overlapping a range, including extents that start before the searched range. `scrub_find_fill_first_stripe()` uses extent and checksum trees to initialize a scrub stripe: it chooses the `BTRFS_STRIPE_LEN`-aligned logical stripe, maps logical to physical for the target device, records metadata/data extents and generations, marks covered sectors, and attaches checksum pointers for data sectors returned by `btrfs_lookup_csums_bitmap()`.

Stripe batching improves I/O behavior. `queue_scrub_stripe()` fills stripes into the context pool, submits each group of 8 stripes together, and flushes when the pool is full. `flush_scrub_stripes()` submits any partial group, waits for all repair workers, performs dev-replace writes for good sectors, waits for writeback, advances `last_physical`, resets stripes, and returns any fatal error.

The scrub walker handles multiple block group profiles. Simple mirrored profiles (`SINGLE`, `DUP`, `RAID1`, `RAID1C*`) scrub a logical range directly with mirror numbers derived from chunk stripe index. RAID0 and RAID10 split the block group into simple stripes and reuse the simple mirror path per device stripe. RAID5/6 uses physical iteration, computes data/parity rotation with `get_raid56_logic_offset()`, scrubs data stripes normally, and for parity stripes reads/verifies all data stripes, aborts if any allocated data sector remains unrepaired, then asks raid56 code to verify/regenerate cached parity. RAID56 data-stripe scrub uses temporary `raid56_data_stripes` with `SCRUB_STRIPE_FLAG_NO_REPORT` so data checks are not double-counted while parity validation is in progress.

`btrfs_scrub_dev()` is the main public entry point. It rejects closing filesystems, allocates the context, starts/refcounts the shared scrub workqueue, finds the target device, enforces writable-device rules for non-readonly scrub, prevents concurrent scrub/device-replace conflicts, installs `dev->scrub_ctx`, honors pause state, switches to `GFP_NOFS`, optionally scrubs superblocks, enumerates chunks, copies final progress, clears device state, releases workers/context, and commits a transaction after scrub if superblock errors were found and repair may require writing new superblocks. Error exits release workers and context.

`srcub_enumerate_chunks()` walks `BTRFS_DEV_EXTENT_KEY` items for the device between requested physical offsets. For each device extent it resolves the block group, skips stale/deleted/reused block groups, handles zoned dev-replace `TO_COPY` filtering, freezes the block group, pauses around read-only conversion to avoid transaction deadlocks, marks block groups read-only when required, waits for NOCOW/ordered writes for dev-replace, updates dev-replace cursors, scrubs the chunk, finishes block-group copy state, restores read-write state if needed, unfreezes/releases the block group, requeues unused block groups for discard/cleanup, and stops on cancellation, write errors, or allocation failures.

Superblock scrub validates all superblock mirrors that fit on the device. `scrub_one_super()` reads the superblock, checks checksum, checks generation, and calls `btrfs_validate_super()`. `scrub_supers()` chooses the expected generation from the seed device or current committed transaction, increments `super_errors` for failed mirrors, and does not directly commit because committing would need to pause the currently running scrub.

Pause/cancel/progress APIs coordinate with transaction commits, filesystem freeze, PM freeze, signals, and user ioctl cancellation. `btrfs_scrub_pause()` waits until all running scrubs have observed the pause request. `btrfs_scrub_continue()` releases them. `btrfs_scrub_cancel()` cancels all active scrubs and waits for `scrubs_running` to reach zero. `btrfs_scrub_cancel_dev()` cancels one device by incrementing its context cancellation counter and waiting for `dev->scrub_ctx` to clear. `btrfs_scrub_progress()` copies live stats if a scrub is active on the requested device.

Important dependencies include Btrfs extent/checksum/backref trees, block group lifetime and read-only conversion, chunk mapping, raid56 parity helpers, zoned-device write pointer helpers, dev-replace state, ordered extent/NOCOW write synchronization, folio allocation, bios through `btrfs_bio`, workqueues, freeze/signal handling, and device statistics.

Reliability notes: scrub intentionally operates against commit roots and read-only/frozen block groups to avoid racing relocation/deletion and dev-replace overwrites. It has explicit handling for missing devices during dev-replace, stripe-tree `-ENODATA` preallocated extents, active swapfile block groups, superblock generation differences on seed devices, zoned sequential write constraints, and RAID56 parity corruption avoidance. Remaining risk is mostly inherent concurrency complexity: correctness depends on precise pause/read-only/freezing discipline, bitmap alignment to sectorsize/nodesize, all async read/write completions reaching their wait queues, and aborting dev-replace when metadata or write errors are detected.
