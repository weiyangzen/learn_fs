# File Research: sources/local-fs/ntfs-3g/ntfsprogs/ntfsrecover.c

This file implements the `ntfsrecover` command-line utility. It reads an NTFS `$LogFile`, displays log records forward or backward, and can replay committed metadata updates to bring an NTFS volume back to a synced state. It supports two input modes: a full NTFS device mounted through libntfs-3g, and a standalone copied `$LogFile` opened as a regular file for analysis-only use.

Important global state tracks volume/log geometry, restart metadata, LSN boundaries, options, attribute-name tables, replay counters, and cached log blocks. `CONTEXT` carries either an `ntfs_volume *` or a `FILE *`, plus a linked list of queued log actions. The code depends heavily on NTFS-3G library structures and helpers from `logfile.h`, `volume.h`, `attrib.h`, `mft.h`, and `ntfsrecover.h`.

Block I/O is centered on `loclogblk`, `replaceusa`, and `read_buffer`. Log blocks are mapped through the `$LogFile` data attribute in full-volume mode, or through byte offsets in copied-log mode. `read_buffer` maintains a circular cache with special handling for restart/base blocks, applies NTFS update-sequence-array fixups, and handles NTFS log version 2.0 temporary-block redirection through `redirect[]`.

Restart-page handling is split across `read_restart`, `showrest`, and `dorest`. The utility reads or receives a selected restart page, extracts `current_lsn`, `client_restart_lsn`, `oldest_lsn`, page size, block size, sequence-number layout, and dirty/clean state. It rejects wiped, CHKD-obsoleted, invalid, or unsupported logs; NTFS `$LogFile` version 2.0 is treated as fast-restart mode and requires `--kill-fast-restart`.

Log parsing is built around `likelyop`, `firstrecord`, `findprevious`, `forward_rcrd`, `backward_rcrd`, `overlapshow`, and `backoverlap`. The parser validates record types, redo/undo operation ranges, alignment, transaction IDs, data lengths, and redo/undo layout. It can reconstruct records spanning two or many log blocks, including backward traversal across wrapped logs.

Display logic decodes both generic log headers and many NTFS action payloads. `actionname`, `mftattrname`, `showname`, `showdate`, `hexdump`, `showheadrcrd`, `showlogr`, `detaillogr`, and `fixup` print record metadata and selected payload interpretations: MFT record creation/deallocation, attribute creation, resident/nonresident value updates, mapping-pair updates, attribute-size updates, directory index operations, bitmap bit changes, opened nonresident attributes, attribute table dumps, and attribute-name dumps.

The file builds and refreshes an in-memory attribute table through `getattrentry`, `copy_attribute`, `refresh_attributes`, and `attrname`. This table maps logged target-attribute keys to MFT attribute type, inode, LSN, and optional UTF-16 name, allowing later log actions to be shown or replayed with better context.

Replay behavior is driven by `enqueue_action`, `mark_transactions`, and external functions declared in the header: `play_undos`, `play_redos`, `show_redos`, and `freeclusterentry`. Backward traversal queues actions until checkpoints or sync boundaries, marks committed transactions by walking from `ForgetTransaction` records, then plays redos or undos depending on `--sync`, `--play`, or `--undo`. `--no-action` suppresses actual writes while preserving traversal and reporting.

Full-volume setup uses `open_volume`, `getboot`, `getvolumedata`, and `locatelogfile`. The code first probes whether the input is a copied `$LogFile`; otherwise it mounts the NTFS volume read-only or forensic-writable depending on recovery options. After successful replay, `reset_logfile` marks `$LogFile` clean, updates restart/client metadata, forces version 1.1, applies MST fixups, and writes both restart pages.

The main traversal entry point is `walk`. It reads restart blocks, optionally walks full/ranged logs forward, computes version-2 block sequencing via `block_sequence`, finds the newest record block via `best_start`/`find_latest_block`, then walks backward when recovery or backward display is needed. Options are parsed in `getoptions`; default behavior is sync mode when no display/replay mode is specified.

Risks and invariants: this file manipulates on-disk NTFS metadata when sync/play/undo are requested without `--no-action`, so correctness depends on conservative record validation and exact structure layouts. `checkstructs` hard-fails if packed NTFS structures do not match expected sizes. Many parsing paths tolerate stale/free-space records during display but become stricter when syncing. Standalone `$LogFile` mode cannot safely replay because it lacks the full volume. The code uses many global variables and fixed-size assumptions, so option compatibility checks and block-size/page-size validation are central safety gates.
