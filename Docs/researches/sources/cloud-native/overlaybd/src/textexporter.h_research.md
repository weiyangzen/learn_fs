## sources/cloud-native/overlaybd/src/textexporter.h

Purpose: implements a header-only, mostly compile-time Prometheus text exporter formatter for OverlayBD metrics. It turns macro-style metric declarations such as `OverlayBD_QPS : gauge{node, type, mode}` into typed metric objects that can render `# HELP`, `# TYPE`, and sample lines with label values, numeric values, and Photon timestamps.

Important APIs/types/functions: `photon::exporter::Label<TSName>` renders one label template as `name="`placeholder`"`; `LabelGroup<...>` renders all labels inside `{...}` or an empty suffix for unlabeled metrics. `MType<S>` and `MHelp<S>` render metadata lines from compile-time strings. `PrometheusMetric<Name, Labels, MType, MHelp>` is the main metric object: `tpl()` builds the sample-line template, `render(double, Args&&...)` fills label placeholders and appends the value plus timestamp, while `type_str()` and `help_str()` expose metadata strings. `parse_metric_define(TS)` parses the `PROMMETRIC(...)` macro expansion into name, type, labels, and trailing help comment. Convenience helpers include `label`, `metric`, `split_labels`, and `label_helper`, though the observed integration path uses `PROMMETRIC`.

Control flow: `PROMMETRIC(...)` stringifies the metric declaration through `TSTRING`, then `parse_metric_define` slices it at `:`, `{}`, and `#` at compile time using Photon `ConstString` utilities. Rendering starts from `PrometheusMetric::render`, allocates an 8 KiB stack buffer, splits `tpl()` around backtick delimiters, and recursively alternates literal template fragments with caller-provided label values. Once no label arguments remain, the terminal `_render` appends `std::to_string(val)`, a space, and `photon::now / 1000`, then null-terminates the buffer. The final `std::string` is built from the C string.

State and persistence behavior: the header has no owned persistent state, file I/O, heap caches, or background work. Metric definitions are encoded in types and static local objects at call sites. Runtime state is limited to a per-render stack buffer and the global Photon clock value used for timestamps. The metric counters themselves live outside this header; in `exporter_handler.h`, `ExposeRender` stores pointers to Photon metric-meter counters and passes their current `val()` results into `render`.

Dependencies: depends on Photon `alog.h` for logging availability through included code paths, `conststr.h` for compile-time string construction/splitting, and `thread.h` for `photon::now`. It also uses C/C++ standard library facilities: `memcpy`, `std::string`, `std::string_view`, forwarding, and type traits support. It assumes the Photon `TSTRING` and `ConstString::TSpliter` APIs provide stable static string storage with accessible `.chars` and `.views`.

Integration points: `exporter_handler.h` is the direct include site. Its `EXPOSE_TEMPLATE` macro creates static `PROMMETRIC` objects for OverlayBD liveness, throughput, QPS, max latency, and byte-count metrics. `ExposeRender::render()` calls `help_str()`, `type_str()`, and `render()` to assemble the HTTP body. `exporter_server.h` registers this handler with Photon HTTP/TCP servers at the configured exporter URI prefix, so this header controls the final Prometheus wire text for the OverlayBD exporter endpoint.

Risks: buffer handling silently skips fragments when `view.size() < space` fails and still null-terminates at the current pointer, so oversized label values or metric templates can produce truncated or malformed samples without an error signal. Label values are inserted without Prometheus escaping, so quotes, backslashes, newlines, or other invalid label characters in tags or hostnames can corrupt exposition output. The recursive renderer does not validate that the number of runtime label arguments matches the number of template placeholders; too few arguments cause the terminal renderer to emit the numeric value where a label placeholder may still exist, while too many are not naturally consumed by the terminal overload. `std::to_string(double)` fixes formatting to the C++ library default, including trailing zeros and possible special-value spellings for NaN/Inf. Timestamp precision is derived from `photon::now / 1000`; consumers need this to match Prometheus millisecond timestamp expectations.

Test signals: there are no direct tests for `textexporter.h` in the observed source tree. Useful coverage would compile sample `PROMMETRIC` declarations with zero, one, and multiple labels; assert exact `HELP`, `TYPE`, and sample-line output; verify timestamp units with a controlled Photon clock; cover empty help/type fields; and exercise escaping/truncation edge cases. Existing integration signals are the exporter HTTP rendering path in `exporter_handler.h` and the server registration path in `exporter_server.h`, which can be tested by registering counters and scraping the configured metrics endpoint.
