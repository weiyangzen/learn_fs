# sources/cloud-native/ostree/src/libostree/ostree-sysroot-deploy.c

## Purpose
`ostree-sysroot-deploy.c` implements the sysroot deployment lifecycle for libostree. It checks out commits into `ostree/deploy/<stateroot>/deploy/<checksum>.<serial>`, prepares `/etc` and `/var`, computes and installs kernel artifacts into `/boot`, writes BLS/bootloader state atomically, supports staged deployments finalized at shutdown, updates kernel arguments, toggles deployment mutability, supports kexec loading, and prepares or clears systemd soft reboot state.

## Important APIs, Types, And Functions
The main public APIs implemented here are `ostree_sysroot_write_origin_file`, `ostree_sysroot_write_deployments`, `ostree_sysroot_write_deployments_with_options`, `ostree_sysroot_deploy_tree`, `ostree_sysroot_deploy_tree_with_options`, `ostree_sysroot_stage_overlay_initrd`, `ostree_sysroot_stage_tree`, `ostree_sysroot_stage_tree_with_options`, `ostree_sysroot_change_finalization`, `_ostree_sysroot_finalize_staged`, `_ostree_sysroot_boot_complete`, `ostree_sysroot_deployment_set_kargs`, `ostree_sysroot_deployment_set_kargs_in_place`, `ostree_sysroot_deployment_set_mutable`, `ostree_sysroot_deployment_can_soft_reboot`, `ostree_sysroot_deployment_set_soft_reboot`, `ostree_sysroot_clear_soft_reboot`, and `ostree_sysroot_deployment_kexec_load`.

Important internal helpers include `checkout_deployment_tree`, `prepare_deployment_etc`, `merge_configuration_from`, `prepare_deployment_var`, `sysroot_initialize_deployment`, `sysroot_finalize_deployment`, `install_deployment_kernel`, `get_kernel_from_tree`, `get_kernel_from_tree_usrlib_modules`, `get_kernel_from_tree_legacy_layouts`, `write_deployments_bootswap`, `write_deployments_finish`, `auto_early_prune_old_deployments`, `_ostree_sysroot_finalize_impl_staged_deployment`, `_ostree_sysroot_run_in_deployment`, `sysroot_finalize_selinux_policy`, and the bootlink helpers `create_new_bootlinks`, `swap_bootlinks`, `prepare_new_bootloader_link`, and `swap_bootloader`. The local `OstreeKernelLayout` structure tracks kernel/initramfs/device-tree/aboot/HMAC source paths, installed names, an open boot artifact fd, and the computed `bootcsum`.

## Control Flow
The deploy path starts in `ostree_sysroot_deploy_tree_with_options`: ensure the sysroot is writable, call `sysroot_initialize_deployment`, then finalize immediately through `sysroot_finalize_deployment`. Initialization resolves the target stateroot, allocates a deploy serial, checks out the commit with `ostree_repo_checkout_at`, optionally creates composefs metadata, creates an `OstreeDeployment`, discovers the kernel layout and boot checksum, prepares an empty bootconfig with requested kernel args, copies `/usr/etc` to `/etc`, and initializes the stateroot `/var` if it is empty. Finalization inherits kernel args from the merge deployment when needed, performs the `/etc` merge, refreshes SELinux policy if supported, removes `.updated` stamps, relabels legacy `/var` when needed, creates backing overlay directories, writes the origin file, and makes the deployment immutable unless debug flags request mutable deployments.

Writing deployments is a separate transaction. `ostree_sysroot_write_deployments_with_options` ensures writable state and `/boot`, optionally auto-prunes old bootcsum directories when bootfs space is tight, filters staged deployments out unless retained as the leading pending item, clears soft reboot state if the target disappears, assigns boot serials, decides whether bootloader entries must be regenerated, and either swaps only subbootversion bootlinks or writes a new bootversion. The full bootswap path removes and recreates `boot/loader.<new>/entries`, installs kernels for each deployment, creates `ostree/boot.<version>.<subversion>` symlink farms, writes bootloader config, prepares `boot/loader.tmp`, syncs `/ostree` and `/boot`, atomically renames loader links, emits journal messages, reloads sysroot state, and optionally runs cleanup.

The staged path in `ostree_sysroot_stage_tree_with_options` requires a booted deployment, clears soft reboot state, starts `ostree-finalize-staged.service`, initializes but does not finalize the deployment, writes a preliminary origin file, then serializes the target deployment, merge deployment, optional locked state, kernel args, overlay initrds, and extra BLS keys into `/run/ostree/staged-deployment`. At shutdown `_ostree_sysroot_finalize_staged` loads sysroot state, checks finalization lock metadata and the legacy lock file, unlinks the staged state before merging `/etc`, finalizes the staged deployment, converts it to a normal deployment, writes it through `ostree_sysroot_simple_write_deployment` with no repo prune, and writes a failure stamp under `/boot/ostree/finalize-failure.stamp` if finalization fails. `_ostree_sysroot_boot_complete` reports and clears that failure stamp at boot, or completes soft reboot run-state handoff.

Kernel installation discovers modern `/usr/lib/modules/<kver>/vmlinuz` first, with legacy `/usr/lib/ostree-boot` or `/boot` fallback. It computes boot checksums from kernel/initramfs/device-tree content, hardlinks or copies artifacts into `/boot/ostree/<osname>-<bootcsum>`, installs overlay initrds from `/run/ostree/staged-initrds`, writes BLS keys including `title`, `version`, `linux`, `initrd`, `devicetree` or `fdtdir`, `aboot`, and the generated `ostree=` kernel argument, and handles boot counting filename syntax.

## State And Persistence
Persistent sysroot state includes checked-out deployment directories, deployment `.origin` files, bootloader entry files under `/boot/loader.<version>/entries`, loader symlinks, bootlink symlink farms under `/ostree/boot.<version>.<subversion>`, installed kernel artifacts under `/boot/ostree/<osname>-<bootcsum>`, overlay initrds under `/boot/ostree/initramfs-overlays`, stateroot `/var`, deployment backing directories, and immutable flags. Transient state includes `/run/ostree/staged-deployment`, `/run/ostree/staged-deployment-locked`, `/run/ostree/staged-initrds`, soft reboot `/run/nextroot` state, and boot-complete handoff files from otcore. The file carefully uses fd-relative operations, temporary files, atomic symlink replacement, `fdatasync`, repo syncfs, fsfreeze/thaw cycles, and mtime bumps to make deployment and bootloader state observable and crash-tolerant.

`/etc` persistence is merge-based: differences between the merge deployment's `/usr/etc` and `/etc` are applied to the new deployment's `/etc`, with removed paths deleted and modified or added regular files, symlinks, and directories copied from the previous `/etc`. Xattrs are ignored for diffing because SELinux labels differ between `/usr/etc` and `/etc`. `/var` is not merged; if the stateroot var is empty, initial commit `/var` content is copied once, with legacy initialization when tmpfiles configuration is absent.

## Dependencies And Integration Points
This file depends on GLib/GIO, libglnx fd utilities, OSTree repo/deployment/bootconfig/kernel-args/sepolicy internals, Linux fs ioctls, optional systemd journal IDs, optional composefs, optional SELinux, optional soft reboot, and the Linux `kexec_file_load` syscall. It integrates with `ostree-sysroot.c` for loading, cleanup, merge deployment selection, and `ostree_sysroot_simple_write_deployment`; with bootloader backends through `_ostree_sysroot_query_bootloader`, `_ostree_bootloader_write_config`, `_ostree_bootloader_post_bls_sync`, and BLS parser helpers; with `ostree-prepare-root` through generated `ostree=` and `init=` kernel args; with `ostree-finalize-staged.service` and `ostree-boot-complete.service`; and with rpm-ostree/bootc-style callers through staged deployments, extra BLS keys, overlay initrds, and retained cleanup control.

## Risks
The highest-risk areas are atomicity and crash consistency around bootloader swaps, especially on separate or VFAT `/boot`; staged deployment finalization because it intentionally unlinks staged state before doing the `/etc` merge; preserving booted deployment invariants while pruning or rewriting deployment lists; correctness of bootconfig equivalence when deciding to avoid a new bootversion; kernel layout detection across modern and legacy layouts; SELinux labeling and policy refresh inside a partially prepared root; and space handling on constrained boot filesystems. The `/etc` merge is not a true conflict-resolving three-way merge: previous administrator changes win over new defaults when a file is modified, and xattr-only changes do not persist. `ostree_sysroot_deployment_set_kargs_in_place` directly edits staged metadata or current BLS files and does not perform the full deployment write transaction. Soft reboot and kexec paths are compile/runtime dependent and rely on kernel, namespace, and systemd behavior.

## Test Signals
Useful test signals include admin deploy/upgrade tests that verify new deployments boot and rollback; staged deployment tests covering locked/unlocked finalization, failure stamps, `/run/ostree/staged-deployment` serialization, and boot-complete error reporting; bootloader/BLS tests covering bootversion swaps, boot counting filenames, `ostree=` args, overlay initrds, and extra `x-` keys; `/etc` merge tests for added/modified/removed files, directories, symlinks, SELinux labels, and xattr edge cases; constrained bootfs tests for early prune behavior; kernel layout tests for `/usr/lib/modules`, legacy `/usr/lib/ostree-boot`, device-tree directories, HMAC, aboot, and no-initramfs handling; mutability tests for immutable flags; soft reboot tests gated by `HAVE_SOFT_REBOOT`; and kexec tests gated by `SYS_kexec_file_load` and privilege.
