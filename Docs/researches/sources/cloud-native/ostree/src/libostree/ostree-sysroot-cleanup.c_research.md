# sources/cloud-native/ostree/src/libostree/ostree-sysroot-cleanup.c

Purpose: implements sysroot cleanup and post-copy repair: discovering deployment/boot directories, removing inactive boot/deployment state, cleaning bootfs overlays, regenerating deployment refs, pruning unreachable repository objects safely, and reapplying fs-verity after file-level copy.

Important APIs/types/functions: `_ostree_sysroot_list_deployment_dirs_for_os` and `list_all_deployment_directories` discover deployment dirs. `_ostree_sysroot_parse_bootdir_name` and `_ostree_sysroot_list_all_boot_directories` handle boot checksum directories. `cleanup_other_bootversions`, `_ostree_sysroot_rmrf_deployment`, `cleanup_old_deployments`, and `_ostree_sysroot_cleanup_bootfs` remove inactive state. `cleanup_ref_prefix` and `generate_deployment_refs` rewrite deployment refs. `ostree_sysroot_cleanup_prune_repo` locks the repo, builds reachability from refs and active deployments, and calls `ostree_repo_prune_from_reachable`. `ostree_sysroot_cleanup`, `ostree_sysroot_prepare_cleanup`, `_ostree_sysroot_cleanup_internal`, and `ostree_sysroot_update_post_copy` orchestrate public behavior.

Control flow: cleanup requires a loaded, writable sysroot. It removes inactive bootversion directories, removes deployment directories not referenced by active deployments, cleans bootfs directories and overlay initrds not referenced by bootconfigs, regenerates deployment refs for the active bootversion/subbootversion while deleting inactive refs, then optionally prunes the repository using a reachable set seeded from refs and every active deployment commit. Repository pruning is protected by an exclusive lock. Post-copy update skips if fs-verity is not wanted, then ensures fs-verity on loose objects and deployment composefs files until unsupported.

State/persistence: deletes filesystem directories under loader/boot/deploy paths, deployment origin/backing paths, bootfs checksum dirs, and inactive overlay initrd files. Rewrites repository refs under `ostree/<bootversion>/<subbootversion>/`, prunes repository objects, logs freed space, and may set fs-verity metadata. It avoids deleting the currently booted deployment by comparing device/inode.

Dependencies/integration: depends on sysroot private state, deployment parsing/path helpers, bootconfig parser overlay initrd access, repo traversal/prune/transactions/locks, libglnx recursive removal, linuxfs immutable flag helper, fs-verity helper, journal logging, and OSTree object path serialization. Called by `ostree admin cleanup`, deployment transactions, prepare cleanup, and update flows.

Risks: cleanup is destructive, so correctness of active deployment lists and bootdir/ref parsing is critical. Orphaned origin/work dirs are only deleted when their deployment path is deleted; standalone orphan detection is absent. Ref regeneration and pruning must stay ordered. Post-copy fs-verity stops after first unsupported object/deployment, so mixed filesystem support may leave later files untreated.

Test signals: `tests/test-admin-deploy-2.sh`, installed destructive staged-deploy tests, `test-prune.sh`, `test-prune-collections.sh`, basic prune invocations, and composefs/fs-verity paths exercise cleanup, pruning, refs, and post-copy expectations indirectly.
