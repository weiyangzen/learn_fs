# File Research: sources/os/plan9/9front/sys/src/cmd/audio/libFLAC/FLAC/stream_encoder.h

## Purpose

This header is the public libFLAC stream encoder interface. It defines the opaque `FLAC__StreamEncoder` type, encoder state and initialization status enums, callback status enums, callback function pointer types, constructor/destructor prototypes, configuration setters/getters, initialization entry points, finishing, and sample submission functions.

The file is documentation-heavy and describes the intended encoder lifecycle: allocate with `FLAC__stream_encoder_new()`, set stream parameters while uninitialized, initialize for native FLAC or Ogg FLAC through callbacks or files, submit channel-separated or interleaved signed samples, finish to flush final frames and update metadata, then reuse or delete the encoder.

## Public API Surface

- `FLAC__StreamEncoderState` exposes runtime states including OK, uninitialized, Ogg errors, verify decoder errors, verify mismatches, client callback errors, file I/O errors, framing errors, and allocation failures.
- `FLAC__StreamEncoderInitStatus` reports validation and setup failures such as unsupported container, invalid callbacks, invalid channels/bits/sample rate/block size/LPC order/QLP precision, block size too small for LPC order, subset violations, invalid metadata, and already-initialized misuse.
- Callback status enums define read, write, seek, and tell outcomes.
- `FLAC__StreamEncoder` is opaque and contains protected/private pointers so ABI users cannot inspect encoder internals.
- Callback typedefs define the integration contract for client I/O: read, write, seek, tell, final STREAMINFO metadata, and progress callbacks.
- Constructor/destructor: `FLAC__stream_encoder_new()` and `FLAC__stream_encoder_delete()`.
- Setters configure Ogg serial number, verification, streamable subset, channel count, bits per sample, sample rate, compression level, block size, stereo mid/side behavior, apodization, LPC/QLP search, residual partition order, deprecated escape/Rice search controls, total sample estimate, metadata blocks, and minimum bitrate limiting.
- Getters expose state, verify decoder state, resolved state string, verify mismatch stats, and current encoder settings.
- Initialization entry points cover native callback streams, Ogg callback streams, native `FILE *`, Ogg `FILE *`, native filename, and Ogg filename variants.
- Processing entry points are `FLAC__stream_encoder_process()` for channel-separated buffers and `FLAC__stream_encoder_process_interleaved()` for interleaved buffers.

## Important Contracts

Setters are only valid in `FLAC__STREAM_ENCODER_UNINITIALIZED`; validation is deferred to initialization because settings are interdependent. The caller must provide right-justified signed integer samples matching the configured bits per sample. File/callback outputs that support seeking allow the encoder to rewrite STREAMINFO, seektable offsets, and other final metadata after audio encoding completes.

The metadata contract is subtle. User-supplied metadata blocks must outlive `FLAC__stream_encoder_finish()`, STREAMINFO is always generated by the encoder, SEEKTABLE templates may be filled in during encoding if seeking is supported, and Ogg FLAC may reorder or synthesize VORBIS_COMMENT placement to satisfy mapping requirements.

## Integration Points

This header depends on `export.h`, `format.h`, and `stream_decoder.h`. It is consumed by libFLAC clients and by implementation files such as stream encoder internals, bitwriter code, and tools in the 9front audio tree.

## Risks and Notes

The API permits many combinations that are invalid only at initialization. Callers must check `FLAC__StreamEncoderInitStatus` and later `FLAC__stream_encoder_get_state()` on process/finish failures. Callback implementations must avoid reentrant state-changing encoder calls, must report accurate tell offsets when buffering output, and must not free metadata blocks too early. Ogg FLAC seeking requires both read and seek support for post-encode metadata rewrite.
