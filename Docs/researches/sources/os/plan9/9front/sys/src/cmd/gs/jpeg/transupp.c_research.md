# File Research: sources/os/plan9/9front/sys/src/cmd/gs/jpeg/transupp.c

IJG `jpegtran` support module for lossless coefficient-domain transforms and optional marker copying. It is not part of the core JPEG library API, but it uses `JPEG_INTERNALS` for helper access.

Transform implementation:
- `do_flip_h` mirrors DCT blocks in place and negates odd-column coefficients; right-edge partial iMCUs are left untouched unless trimming has adjusted dimensions.
- `do_flip_v` writes to workspace arrays, reversing block rows and negating odd-row coefficients; bottom partial iMCUs are copied verbatim.
- `do_transpose` transposes DCT coefficients and block positions into workspace arrays.
- `do_rot_90`, `do_rot_180`, `do_rot_270`, and `do_transverse` merge transpose/flip operations to avoid separate passes, with special handling for untransformable partial edge iMCUs.

Public workflow:
- `jtransform_request_workspace` must run after `jpeg_read_header` and before `jpeg_read_coefficients`; it determines component count, honors force-grayscale, and requests any virtual block arrays required by the selected transform.
- `jtransform_adjust_parameters` must run after `jpeg_copy_critical_parameters`; it applies force-grayscale, transposes dimensions/sampling/quant tables when needed, trims partial right/bottom iMCU edges when requested, and returns the coefficient arrays to write.
- `jtransform_execute_transformation` must run after `jpeg_write_coefficients`; it dispatches the selected transform.

Marker support:
- `jcopy_markers_setup` asks the decompressor to save COM markers or all APPn markers depending on `JCOPY_OPTION`.
- `jcopy_markers_execute` writes saved markers to the destination while suppressing duplicate JFIF APP0 and Adobe APP14 markers already generated by the encoder.

Important constraints:
- Some transforms mutate source coefficient arrays, especially horizontal flip.
- Workspace is allocated from the source decompression object's memory manager so memory planning accounts for source and destination virtual arrays.
- Trim is intentionally lossy at odd image dimensions but avoids exposed padded DCT garbage.

Filesystem relevance:
- Pure JPEG coefficient/metadata transform support; file IO is handled by callers.
