# File Research: sources/os/plan9/9front/sys/src/cmd/auth/secstore/secstored.c

Network daemon for secstore. It listens on TCP port 5356 by default, authenticates clients with PAK, optionally requires SecureID/STA, and serves per-user encrypted file blobs from `/adm/secstore/store/<user>`.

Important behavior:
- `getdir()` returns directory listing generated by external `dirls()`.
- `getfile()` validates plain file size/mode and streams file bytes to the client.
- `putfile()` receives a size then file bytes and creates `/adm/secstore/store/<id>/<file>` with mode `0660`.
- `removefile()` rejects missing files and directories before removal.
- `dologin()` drives the protocol: reads first PAK message, calls `PAKserver`, optionally sends `STA`, then loops over `GET`, `PUT`, `RM`, `CHPASS`, and `BYE`.
- `main()` daemonizes unless verbose, announces a listener, forks per client, opens NDB auth/local databases in the child, applies a 30-minute alarm, logs remote address, and runs `dologin()`.

Interfaces/dependencies:
- Uses `validatefile()` for path/name safety.
- Uses `secureidcheck()` from the auth tree.
- Uses `/lib/ndb/auth` and `/lib/ndb/local`.

Risks/notes:
- Server trusts client-side encryption; it stores opaque encrypted payloads but still controls files and metadata.
- Protocol errors generally terminate the session and log via `syslog`.
