# File Research: sources/os/plan9/9front/sys/src/cmd/audio/libvorbis/codebook.h

This header defines the shared static and runtime codebook data structures used by the Plan 9/9front import of libvorbis, plus prototypes for packing, unpacking, initialization, lookup, quantization, encode, decode, and cleanup helpers. It includes `ogg/ogg.h` for Ogg integer and bitpacking types.

Key types:
- `static_codebook` is the compact, declarative codebook form used in generated book headers and Vorbis setup packets. It stores vector dimension, entry count, a codeword-length list, map type, quantization parameters, quant list, and an `allocedp` ownership flag.
- `codebook` is the initialized runtime form. It stores dimensions, entry counts, a pointer back to the static descriptor, generated value/codeword lists, decode lookup structures, first-table metadata, maximum decode length, and encoder lattice helper fields.

Important fields:
- `static_codebook.lengthlist` is the canonical-code source; zero lengths mean unused entries.
- `static_codebook.maptype` selects no mapping, implicit lattice mapping, or explicit value mapping.
- `q_min`, `q_delta`, `q_quant`, and `q_sequencep` define value dequantization semantics.
- `codebook.valuelist` holds dequantized float vectors.
- `codebook.codelist`, `dec_index`, `dec_codelengths`, `dec_firsttable`, `dec_firsttablen`, and `dec_maxlength` are generated by initialization and consumed by encode/decode operations.

Declared functions fall into these groups:
- Lifecycle/init: `vorbis_staticbook_destroy()`, `vorbis_book_init_encode()`, `vorbis_book_init_decode()`, `vorbis_book_clear()`.
- Quantization/value helpers: `_book_unquantize()`, `_book_logdist()`, `_float32_unpack()`, `_float32_pack()`, `_book_maptype1_quantvals()`, `_best()`, `vorbis_book_besterror()`.
- Runtime encode helpers: `vorbis_book_codeword()`, `vorbis_book_codelen()`, `vorbis_staticbook_pack()`, `vorbis_book_encode()`.
- Runtime decode helpers: `vorbis_staticbook_unpack()`, `vorbis_book_decode()`, `vorbis_book_decodevs_add()`, `vorbis_book_decodev_set()`, `vorbis_book_decodev_add()`, `vorbis_book_decodevv_add()`.

Integration points:
- Generated headers such as `books/uncoupled/res_books_uncoupled.h` instantiate `static_codebook` objects using this layout.
- `sharedbook.c` implements initialization, dequantization, and cleanup routines declared here.
- `codebook.c` implements setup-packet pack/unpack and decode/encode routines declared here.
- Floor/residue codec backends call the decode helpers through this API after `block.c` has initialized `codec_setup_info.fullbooks`.

Risk and maintenance notes:
- The structure layout is ABI-significant inside this libvorbis source tree because generated static tables use positional initializers rather than named fields.
- Changing field order or type width would break generated book headers and setup serialization.
- Ownership is mixed: generated static books set `allocedp` to 0, while unpacked books set it to 1; cleanup must respect that distinction.
- Several helpers are internal by naming convention (`_book_*`, `_float32_*`) but are declared here for cross-file use within the library.

Testing/review signals:
- Compile-time breakage is likely if field layout and generated books diverge.
- Runtime tests should initialize generated maptype 0 and maptype 1 books, verify clear/destroy ownership behavior, and cover all public prototypes through floor/residue encode/decode paths.
