## Include Handling

Include support is mostly defined here, although the actual include directive rules are just beyond the chunk boundary.

`struct inc_state` stores the suspended parse context for an include:

- previous `cfg_parser->filename`
- previous `cfg_parser->line`
- previous flex `YY_BUFFER_STATE`
- linked-list `next`
- previous `inc_toplevel`

`config_start_include()` enforces a maximum include depth of 100000, rejects empty names, allocates an include state, strips the configured chroot prefix from the filename when applicable, duplicates the effective filename for parser diagnostics, opens the file, pushes the current filename/line/buffer/top-level state, updates `cfg_parser->filename` and `cfg_parser->line`, sets `inc_toplevel`, and switches to a new flex buffer for the include file.

`config_start_include_glob()` optionally expands wildcard include patterns when `HAVE_GLOB` is enabled. It treats `*`, `?`, `[`, `{`, and `~` as wildcard indicators, uses sorted `glob()` results, pushes matches in reverse order so scanner processing occurs in sorted order, ignores `GLOB_NOMATCH`, and falls back to `config_start_include()` for non-glob paths or glob errors.

`config_end_include()` pops one include state, frees the current parser filename, restores the previous filename/line/buffer/top-level flag, deletes the current flex buffer, switches back to the saved buffer, and frees the include-state node. ## Control Flow

The visible `yylex()` control path is the standard flex loop:

1. On first call, initialize scanner state, default `yyin` to `stdin`, default `yyout` to `stdout`, create the initial buffer if none exists, and load the buffer state.

## Risks and Edge Cases

- This generated lexer is non-reentrant. Global scanner state, `cfg_parser`, `yylval`, include state, and flex buffers mean concurrent config parses would interfere unless externally serialized.
- Include depth is capped at 100000, which prevents unbounded recursion but is still high enough that malicious configs can consume significant memory/file descriptors before the cap.
- Include chroot stripping is prefix-based (`strncmp(filename, cfg_parser->chroot, strlen(chroot)) == 0`) and does not verify a path boundary. A filename sharing the same byte prefix as the chroot can be rewritten unexpectedly.
- `config_start_include_glob()` with `GLOB_NOMATCH` silently succeeds without including anything. That may be intended, but it can hide typoed wildcard includes.
- `config_start_include_glob()` pushes all glob matches by repeatedly calling `config_start_include()` but does not stop if one match fails. Partial include stacks can result after mixed success/failure.
- `config_end_include()` decrements `inc_depth` before checking whether a saved include state exists. If called with an empty stack, `inc_depth` can underflow logically.
- In double-quoted string completion, `strdup()` failure reports `yyerror("out of memory")` but still returns `STRING_ARG` with a null `yylval.str`; parser actions must tolerate that.
- Newline inside a quoted string reports an error and returns to `INITIAL`, not to `val`, so the remainder of a directive line may be parsed as fresh top-level input.
- The generated scanner uses fixed-size numeric tables and flex internals; manual edits to generated code are risky and should normally be made in `configlexer.lex` followed by regeneration.

## Control Flow

Single-quoted string parsing starts when the lexer sees the opening quote and switches to `singlequotedstr`. Interior text is appended with `yymore()`. A newline before the closing quote reports `newline inside quoted string, no end '`, increments `cfg_parser->line`, and returns to `INITIAL`. For `include:`, the lexer saves the current start state in `inc_prev`, enters `include`, skips whitespace, tracks newlines, and accepts either an unquoted include name or a double-quoted include name. For `include-toplevel:`, the same path is used with a `toplevel` flag of `1`. The flex buffer runtime moves unmatched text to the beginning of the buffer, grows owned buffers when needed, reads additional bytes through `YY_INPUT`, appends two end-of-buffer sentinels, and resumes the DFA.
