# File Research: sources/os/bsd/netbsd-src/sys/fs/nfs/server/nfs_nfsdserv.c

Implements the protocol-level service routines for NetBSD's newer kernel NFS server. The file handles individual NFSv2, NFSv3, NFSv4.0, and NFSv4.1 operations after RPC parsing has selected a vnode/current file handle. Each routine decodes request XDR from `nfsrv_descript`, validates protocol-specific arguments, calls lower `nfsvno_*` vnode/export/state helpers, and appends the XDR reply.

The NFSv2/v3 file and directory operations include `nfsrvd_access()`, `nfsrvd_getattr()`, `nfsrvd_setattr()`, `nfsrvd_lookup()`, `nfsrvd_readlink()`, `nfsrvd_read()`, `nfsrvd_write()`, `nfsrvd_create()`, `nfsrvd_mknod()`, `nfsrvd_remove()`, `nfsrvd_rename()`, `nfsrvd_link()`, `nfsrvd_symlink()`, `nfsrvd_mkdir()`, `nfsrvd_commit()`, `nfsrvd_statfs()`, `nfsrvd_fsinfo()`, and `nfsrvd_pathconf()`. Common subroutines `nfsrvd_symlinksub()` and `nfsrvd_mkdirsub()` are shared by NFSv3 and NFSv4 create paths.

The NFSv4 stateful operations include byte-range lock handling (`nfsrvd_lock()`, `nfsrvd_lockt()`, `nfsrvd_locku()`), open/close lifecycle (`nfsrvd_open()`, `nfsrvd_close()`, `nfsrvd_openconfirm()`, `nfsrvd_opendowngrade()`), delegation operations (`nfsrvd_delegpurge()`, `nfsrvd_delegreturn()`), file-handle/security/attribute helpers (`nfsrvd_getfh()`, `nfsrvd_secinfo()`, `nfsrvd_verify()`, `nfsrvd_openattr()`), client identity and lease operations (`nfsrvd_setclientid()`, `nfsrvd_setclientidcfrm()`, `nfsrvd_renew()`, `nfsrvd_releaselckown()`), and NFSv4.1 session operations (`nfsrvd_exchangeid()`, `nfsrvd_createsession()`, `nfsrvd_sequence()`, `nfsrvd_reclaimcomplete()`, `nfsrvd_destroyclientid()`, `nfsrvd_destroysession()`, `nfsrvd_freestateid()`, `nfsrvd_notsupp()`).

The implementation is built around careful vnode lifetime and lock ownership. Many handlers receive locked vnodes, choose shared or exclusive locks via the dispatcher, then explicitly `vput()`, `vrele()`, or `NFSVOPUNLOCK()` depending on whether a new current file handle must be returned. Directory-modifying operations collect weak cache consistency data before and after updates for NFSv3 and emit change-info records for NFSv4.

NFSv4 support adds attrbit parsing, ACL hooks under `NFS4_ACL_EXTATTR_NAME`, current/saved file-handle semantics, referrals, cross-mount handling, delegation return/purge, open-owner and lock-owner sequence handling, stateid validation, reclaim handling, and NFSv4.1 client/session setup. Several operations enforce root export checks with `nfsd_checkrootexp()` before accepting client or session control requests.

Important dependencies are the NFS XDR mbuf macros, `nfsvno_*` VFS wrappers from `nfs_nfsdport.c`, NFSv4 state helpers such as `nfsrv_openctrl()`, `nfsrv_openupdate()`, `nfsrv_lockctrl()`, `nfsrv_setclient()`, `nfsrv_getclient()`, `nfsrv_checksequence()`, and `nfsrv_delegupdate()`, plus export/security helpers, vnode operations, mount/vfs reference handling, and duplicate-request state via `nd->nd_rp`.

Notable risk areas are protocol decode error cleanup, mixed locked/unlocked vnode ownership, manually managed path buffers and ACL allocations, write verifier behavior controlled by `vfs.nfsd.async`, NFSv4 clientid consistency checks, reply bitmap correctness on partial NFSv4 `SETATTR`, and session-slot caching interactions for NFSv4.1.
