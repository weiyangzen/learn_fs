## Purpose
Implements `librumphijack`, an `LD_PRELOAD`/symbol-interposition layer that routes selected libc/syscall-style operations either to the host kernel or to a connected rump kernel via `librumpclient`.

## Main Responsibilities
- Builds a dual syscall table mapping each intercepted operation to both the host symbol and the `rump_sys_*` symbol resolved with `dlsym(RTLD_NEXT, ...)`.
- Parses `RUMPHIJACK` configuration for path prefix routing, blanket path routing, socket protocol-family routing, VFS operation routing, sysctl/modctl routing, and the rump fd offset.
- Classifies paths as host, rump-prefixed, or rump blanket paths, translating configured rump prefixes such as `/rump` back to rump-internal paths.
- Maintains a file descriptor namespace split: host fds must stay below `hijack_fdoff`, while rump fds are presented as `rumpfd + hijack_fdoff`.
- Tracks special `dup2()` mappings for standard descriptors 0-2 so programs can redirect stdin/stdout/stderr to rump-backed descriptors.
- Interposes common socket, file, directory, VFS, metadata, polling, process, and descriptor operations.
- Preserves rump current-working-directory and dup2 mapping state across `execve()` using internal `RUMPHIJACK__*` environment variables.

## Key Implementation Notes
- Default hijack policy is `path=/rump,socket=all:nolocal`, meaning paths under `/rump` and non-local sockets are routed to the rump kernel unless overridden.
- `rcinit()` is a constructor. It resolves all host/rump call targets, initializes the rump client, parses environment variables, sets retry policy, and restores exec-inherited state.
- The macro wrappers `FDCALL`, `PATHCALL`, `ATCALL`, and `VFSCALL` generate most simple routing functions after the hand-written special cases.
- `open()`, `socket()`, `accept()`, and `paccept()` translate newly returned descriptors into the host-visible fd namespace; host returns are checked for collisions with the rump fd range and dup2 aliases.
- `chdir()`, `fchdir()`, and NetBSD `__getcwd()` keep `pwdinrump` coherent so relative paths route to the currently selected kernel.
- `link()` and `rename()` reject cross-host/rump moves with `EXDEV`; NetBSD `linkat()` only supports a limited `AT_FDCWD` + `AT_SYMLINK_FOLLOW` case.
- `fcntl()` handles `F_DUPFD`, `F_DUPFD_CLOEXEC`, `F_CLOSEM`, and `F_MAXFD` specially because descriptor ranges span two kernels.
- `close()` notifies `librumpclient` before host close/dup2/closem paths and carefully tears down dup2 aliases for rump descriptors.
- `sendmsg()` and `recvmsg()` convert `SCM_RIGHTS` descriptors between external and raw fd values, rejecting attempts to pass descriptors belonging to the other kernel.
- `select()` is implemented on top of `pollts`/`ppoll`; mixed host+rump `poll()` splits descriptors into two vectors, runs host poll in a helper thread and rump poll in the caller, wakes the losing side with notification pipes, and merges results.
- `kevent()` rejects filters that target rump fds because split host/rump kqueue handling is not implemented.
- `mmap()` refuses `MAP_FILE` mappings from rump fds with `ENOSYS`.
- NetBSD-specific hooks cover versioned syscall names, file handles, statvfs/getvfsstat, mount/unmount, `nfssvc`, `__sysctl`, `modctl`, quota, chflags, and fsync_range where available.

## Filesystem Relevance
High. This file is the userspace bridge that lets unmodified programs access rump-kernel filesystems and VFS services through normal libc entry points. Its path and fd routing rules directly determine whether operations hit the host VFS or the rump VFS.

## Reliability Notes
- The fd namespace split relies on host fd values remaining below `hijack_fdoff`; host descriptors at or above the offset are closed and reported as `ENFILE`.
- Mixed-kernel polling is inherently approximate: whichever side wakes first can suppress activity from the other side in that call.
- `sendmsg()` mutates caller-supplied control messages when converting rump fds for send, with an in-code comment noting a safer copy-and-restore design.
- Linux support is explicitly described as lower quality than NetBSD support and omits many NetBSD-only calls.
- The intercepted symbol list is manually maintained and includes comments noting it would benefit from autogenerated synchronization with libc/rump symbols.

## Dependencies
- Internal header: `hijack.h`.
