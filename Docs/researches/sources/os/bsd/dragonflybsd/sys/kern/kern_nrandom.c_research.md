# File Research: sources/os/bsd/dragonflybsd/sys/kern/kern_nrandom.c

This file implements DragonFlyBSD's kernel random subsystem. It owns per-CPU random generator state, early and SMP initialization, entropy injection from timing/interrupt/keyboard/generic sources, the `read_random()` kernel API, `getrandom(2)`, and `kern.random`/`kern.rand_mode` sysctls.

Core design:
- `csprng_pcpu` points at either `csprng_boot` during early single-CPU boot or a later `kmalloc`ed per-CPU array of `struct csprng_state`.
- Each CPU state combines DragonFly's `csprng_state` with legacy IBAA and L15 generators. `rand_mode` selects CSPRNG only, IBAA only, or mixed output.
- `rand_initialize()` is called early and again after SMP setup. It seeds each CPU from `nanotime()`, `nanouptime()`, globaldata contents, and chained random bytes from prior CPU state.
- `iterate_csprng_state()` round-robins entropy sources across CPUs unless the caller explicitly requests per-CPU source handling.

Important functions:
- `add_buffer_randomness_state()` serializes on the per-state spinlock and alternates how incoming data is injected: both L15/IBAA/CSPRNG, only L15/IBAA, or only CSPRNG depending on a per-source counter.
- `add_buffer_randomness()` and `add_buffer_randomness_src()` are public feeder APIs. `RAND_SRCF_PCPU` keeps source data on the current CPU; otherwise large buffers are intended to be split across CPU states.
- `add_keyboard_randomness()` mixes scan codes into L15 and then calls `add_interrupt_randomness()`.
- `add_interrupt_randomness()` accumulates low-grade interrupt/TSC-derived data into `rand_thread_value` without locking.
- `read_random()` locks the current CPU's state and emits bytes using the selected mode, XORing CSPRNG and IBAA output in mixed mode.
- `sys_getrandom()` loops in 256-byte chunks, copies to userland, yields between chunks, and periodically checks for pending signals.
- `rand_thread_loop()` periodically rotates through CPU states, injects timing/globaldata counters, adjusts its systimer period with L15 output, and chains generated bytes to force CPU-state divergence.
- `NANOUP_EVENT()` injects delta nanoseconds, accumulated interrupt randomness, and low TSC bits.

Concurrency and lifecycle:
- Generator mutation is protected by each state's spinlock.
- `rand_thread_value` intentionally races; it is a lossy accumulator for timing noise.
- The helper thread sleeps on `rand_td` and is awakened by `systimer_rand`.
- `SYSINIT(rand1, SI_BOOT2_POST_SMP, ...)` performs the post-SMP initialization; `SYSINIT(rand2, SI_SUB_HELPER_THREADS, ...)` starts the random helper thread.

Filesystem/storage relevance:
- This is not filesystem code, but it is a kernel service likely used by filesystems, block layers, and VFS-adjacent code for IDs, cookies, cryptographic salts, and randomized behavior.

Notable risk/quirk:
- In `add_buffer_randomness_src()`, the loop computes a chunk length `n` but passes `bytes` rather than `n` to `add_buffer_randomness_state()`. If intentional, the comment about splitting large generic data is misleading; if not, this could over-inject the remaining buffer into each selected CPU state.
