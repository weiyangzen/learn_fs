# File Research: sources/os/darwin/xnu/bsd/vfs/vnode_if.sh

## Scope And Role

`vnode_if.sh` is the historical Berkeley/XNU generator for Darwin vnode operation front-end artifacts. Given one source specification file, currently documented as `bsd/vfs/vnode_if.src`, it emits:

- `vnode_if.h`: per-operation argument structures, descriptor declarations, and inline `VNOP_*`/`VOP_*`-style call wrappers.
- `vnode_if.c`: `struct vnodeop_desc` definitions, vnode argument offset arrays, a default operation descriptor, and the global `vfs_op_descs[]` descriptor table.

The script is not itself VFS runtime code. Its purpose is to keep the vnode operation ABI, operation descriptors, and generated call thunks consistent with the declarative vnode operation list.

## Inputs And Outputs

The script requires exactly one command-line argument. If invoked with any other argument count, it prints `usage: vnode_if.sh srcfile` and exits with status `1`.

Primary variables:

- `src`: input vnode operation specification path.
- `out_c`: generated C file name, fixed as `vnode_if.c`.
- `out_h`: generated header file name, fixed as `vnode_if.h`.
- `awk`: AWK implementation, selected from `$AWK` or defaulting to `awk`.
- `SCRIPT_ID`: embedded Berkeley source identifier used in generated-file warnings.

Both generated files receive the Apple/NeXT/BSD copyright block and an explicit warning that edits may be lost because the files are generated by this script.

## AWK Compatibility Layer

The generator depends on AWK, with an optional compatibility shim for implementations lacking `toupper()`.

It probes the selected AWK by running a tiny `BEGIN` program that prints `toupper("true")`. If the output is `TRUE`, the script assumes native `toupper()`. Otherwise it injects an AWK function named `toupper(str)` that shells out through `echo ... | tr a-z A-Z`.

This keeps the generator usable with older non-GNU AWK variants, at the cost of invoking the shell for uppercase conversion when no native function exists.

## Source Preprocessing And Parsing

Before AWK parsing, the input file is preprocessed by `sed`:

- inserts a space between `*` and a following non-comment character, normalizing pointer declarators such as `struct vnode *vp`;
- replaces semicolons with spaces.

The shared AWK parser then reads a simple operation-description grammar:

- lines beginning with `#` are ignored;
- lines beginning with `vop_` start an operation, setting `name`, resetting `argc`, and capturing the third field as `ubc`;
- a line beginning with `}` ends the current operation and calls `doit()`;
- intervening argument lines populate `argdir[]`, `argtype[]`, `argname[]`, and `willrele[]`.

Argument records support an optional `WILLRELE` token immediately after the direction field. The parser stores this as `willrele[i]`, used later to mark vnode descriptor flags for vnodes that the operation will release.

The parser intentionally treats the final field on an argument line as the argument name and all preceding type fields as the type string. This allows multi-token types such as `struct componentname *` and `kauth_credential_t`.

## Header Generation

The first generated artifact is `vnode_if.h`. The script redirects stdout to this path, writes header guards, includes `sys/appleapiopts.h` and `sys/ubc.h`, and emits most declarations under `__APPLE_API_UNSTABLE`.

For every parsed operation, header generation emits:

- `struct <name>_args`, beginning with `struct vnodeop_desc * a_desc`;
- one `a_<argname>` field per declared operation argument;
- `extern struct vnodeop_desc <name>_desc`;
- a public uppercase macro wrapper that forwards to a static inline helper;
- `static __inline int _<UPPERCASE_NAME>(...)` that builds the args structure and dispatches through `VCALL()`.

The inline helper assigns `a.a_desc = VDESC(<name>)` and copies every passed argument into the generated argument structure before invoking the vnode operation vector slot selected by `VOFFSET(<name>)`.

For operations whose source header line marks the third field as `UBC`, the generated inline body stores the `VCALL()` result in `_err` and returns it through an explicit local block. For all others, it returns the `VCALL()` expression directly. In this script version both paths return the error value; the distinction preserves a generation hook for UBC-marked operations.

After processing the source file, the header generator appends two special cases:

- `vop_strategy`
- `VNOP_BWRITE`

Both are generated as one-argument operations taking `struct buf *bp`, with call dispatch using the first argument's vnode via `bp->b_vp`.

The header special-case section also includes `sys/buf.h` and `sys/vm.h`.

## C Descriptor Generation

The second generated artifact is `vnode_if.c`. The script redirects stdout to this path, includes `sys/param.h`, `sys/mount.h`, `sys/vm.h`, and `sys/vnode.h`, then defines `vop_default_desc`.

`vop_default_desc` is initialized as the default descriptor with:

- offset `0`;
- printable name `"default"`;
- no flags;
- no vnode pointer offsets;
- all singleton offsets set to `VDESC_NO_OFFSET`;
- no transport metadata.

For every parsed operation, C generation emits:

- `int <name>_vp_offsets[]`, containing offsets of all arguments whose type is exactly `struct vnode *`, terminated by `VDESC_NO_OFFSET`;
- `struct vnodeop_desc <name>_desc`, containing operation metadata used by vnode operation-vector initialization and dispatch.

The helper `do_offset(typematch)` searches parsed arguments for exact type-string matches and emits either a `VOPARG_OFFSETOF(struct <name>_args, a_<argname>)` entry or `VDESC_NO_OFFSET`. It is used for:

- output vnode pointer argument: `struct vnode **`;
- credential argument: `kauth_credential_t`;
- process argument: `struct proc *`;
- pathname component argument: `struct componentname *`.

The descriptor's vnode-offset array and singleton offsets let generic VFS code inspect operation arguments without knowing each generated argument struct by hand.

## WILLRELE Flag Encoding

During descriptor generation, the script scans arguments whose type string begins with `struct vnode *`. If the corresponding parsed argument included `WILLRELE`, it adds descriptor flags:

- `VDESC_VPP_WILLRELE` when the argument direction matches `OUT`;
- otherwise `VDESC_VP<num>_WILLRELE`, where `<num>` is the ordinal among vnode-pointer arguments.

This records vnode lifecycle semantics in the operation descriptor, allowing common vnode dispatch/support code to know when an operation consumes or releases vnode references.

## Descriptor Table Generation

After generating all per-operation descriptors, the script appends the global descriptor table:

```c
struct vnodeop_desc *vfs_op_descs[] = {
	&vop_default_desc,
	&vop_strategy_desc,
	&VNOP_BWRITE_desc,
	...
	NULL
};
```

`vop_default_desc` is deliberately first. The two hand-added buffer-operation special cases are inserted before the descriptors generated from the source file. XNU VFS initialization code uses this table to assign descriptor offsets and validate vnode operation vectors against the known descriptor set.

## Formatting Cleanup

Generated output is piped through a small `sed` cleanup expression:

- `space_elim='s:\([^/]\*\) :\1:g'`

This removes unwanted spaces after pointer asterisks in most generated declarations and offset expressions while avoiding matches that look like comment delimiters.

## Runtime And Build Dependencies

The generated files depend on XNU vnode infrastructure rather than this shell script at runtime. The generated header assumes definitions such as `VCALL`, `VDESC`, `VOFFSET`, `struct vnodeop_desc`, and vnode argument offset helpers are available through the included kernel headers.

The generated C file feeds `vfs_op_descs[]`, which is referenced by VFS initialization code to enumerate operations, assign offsets, and check operation-vector coverage. Other VFS sources include the generated `sys/vnode_if.h` interface to call filesystem VNOP implementations through typed wrappers.

## Error Handling And Limitations

The script performs only minimal validation:

- it validates argument count for the script invocation;
- it assumes the input specification is syntactically well formed;
- it relies on exact string matches for special argument types;
- it assumes the first generated call argument identifies the dispatch vnode, except for the special buffer operations where `->b_vp` is appended;
- it does not check whether file writes to `vnode_if.h` or `vnode_if.c` fail after stdout redirection.

Because operation metadata is generated from string-parsed source declarations, small formatting changes in `vnode_if.src` can affect descriptor offsets or special-type recognition.

## Notable Implementation Details

- The script uses repeated `sed | awk` passes over the same source file: one for header wrappers, one for descriptor definitions, and one for `vfs_op_descs[]`.
- The generated inline wrappers uppercase operation names and preserve the public vnode-operation calling convention while hiding the argument-structure boilerplate.
- `arg0special` is normally empty but becomes `->b_vp` for `vop_strategy` and `VNOP_BWRITE`, making buffer-backed operations dispatch through the buffer's vnode.
- Operation descriptor names are printable strings matching the source operation name.
- Descriptor flags are generated from source annotations rather than inferred from C code.
- The generated header exposes internals only under `__APPLE_API_UNSTABLE`, matching the private/unstable nature of vnode operation interfaces.
