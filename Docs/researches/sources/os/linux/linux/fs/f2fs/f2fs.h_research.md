# File Research: sources/os/linux/linux/fs/f2fs/f2fs.h

Read completely: 5141 lines.

This is the central private header for Linux F2FS. It defines most in-memory F2FS types, mount/feature flags, constants, lock wrappers, helper macros, inline accounting paths, and cross-file function prototypes used by `file.c`, `inode.c`, `dir.c`, `node.c`, `segment.c`, `checkpoint.c`, `data.c`, `gc.c`, `recovery.c`, `debug.c`, `inline.c`, `shrinker.c`, `extent_cache.c`, `sysfs.c`, `verity.c`, and `compress.c`.

Core state structures: `f2fs_mount_info` stores mount policy, quota, compression, fault injection, and allocation settings; `f2fs_inode_info` extends the VFS inode with F2FS flags, dirty accounting, extent trees, atomic/COW write state, xattr/inline metadata, compression state, and encryption state; `f2fs_sb_info` is the filesystem-wide object tying together node manager, segment manager, writeback bio state, checkpoint state, inode tracking, extent caches, allocation counters, GC, sysfs/stat objects, multi-device metadata, error state, atomic-write statistics, lock-priority tuning, compression cache, and optional iostat tracking.

Major subsystem definitions: checkpoint and discard control (`cp_control`, `ckpt_req_control`, `discard_cmd_control`), NAT/SIT journal helpers, inline dentry/data layout helpers, filename handling for encrypted/casefolded directories, extent cache records for read and block-age caches, map-block return state, inode advisory and internal flags, node manager state (`f2fs_nm_info`), dnode access state (`dnode_of_data`), log/curseg types, flush command control, segment manager state (`f2fs_sm_info`), IO/writeback types (`f2fs_io_info`, `f2fs_bio_info`), multi-device state, ATGC/GC state, page-private layout, and compression/decompression contexts.

Key inline behavior:
- Provides typed accessors such as `F2FS_I`, `F2FS_SB`, `F2FS_CKPT`, `F2FS_NODE`, `NM_I`, `SM_I`, `SIT_I`, `META_MAPPING`, and `NODE_MAPPING`.
- Wraps checkpoint flag mutation under `cp_lock`, chooses checkpoint reasons, manages NAT bits, and locates current/next checkpoint packs and bitmap regions.
- Implements F2FS-specific rwsem wrappers, including optional unfair reader behavior and traced lock entry points for latency/priority accounting.
- Accounts valid data blocks, node blocks, inode counts, dirty pages, atomic write counts, reserved-root blocks, quota reservations, and `SBI_IS_DIRTY` transitions.
- Encodes F2FS folio/page private bits for migration, inline inode pages, resource references, and atomic-write pages while distinguishing pointer and non-pointer `private` values.
- Calculates inline xattr/data/dentry capacity from inode extra size and compression cluster alignment.
- Maps and validates node block addresses, handles F2FS big-endian-style bitmap bit ordering, masks on-disk inode flags by inode type, and synchronizes inline flags back to raw inode fields.
- Provides allocation wrappers that integrate fault injection for kmalloc/kvmalloc/vmalloc/slab/page allocation and filemap folio lookup.
- Detects idle/in-flight IO for background GC/discard policy, handles repeated page EIO by stopping checkpoint after retry threshold, and invalidates internal meta/compression caches over block ranges.
- Defines compression enable/disable policy, per-inode compression defaults, compressed-block accounting, backend-readiness stubs when compression is disabled, and feature-test helpers generated by `F2FS_FEATURE_FUNCS`.

Important interactions: this header is effectively the F2FS internal ABI. Changing fields in `f2fs_inode_info` or `f2fs_sb_info` affects nearly every F2FS source file. The function prototype sections reveal the main flow boundaries: VFS operations in `file.c`/`inode.c`/`dir.c`, metadata lookup and NAT in `node.c`, allocation/discard/flush and segment selection in `segment.c`, checkpoint/orphan/dirty inode handling in `checkpoint.c`, read/write/mapping in `data.c`, cleaning in `gc.c`, roll-forward in `recovery.c`, statistics in `debug.c`, inline-file operations in `inline.c`, shrinker hooks, extent cache operations, sysfs registration, fs-verity operations, and compression.

Concurrency and reliability notes: the file concentrates F2FS locking conventions (`cp_global_sem`, `cp_rwsem`, `node_write`, `node_change`, `gc_lock`, `i_gc_rwsem`, `i_xattr_sem`, bio locks, extent locks, NAT/free-NID locks). Many helpers assume callers already hold the correct folio, inode, checkpoint, or segment locks; misuse can corrupt counters or race raw inode state. Several consistency failures set `SBI_NEED_FSCK` instead of panicking unless `CONFIG_F2FS_CHECK_FS` routes `f2fs_bug_on` to `BUG_ON`. Fault injection hooks cover allocation, IO, checkpoint, discard, lock, and metadata-validity paths.

Security/reliability notes: this header exposes policy for encryption, verity, compression, quota, project quota, casefolding, readonly devices, zoned devices, discard support, atomic writes, and checkpoint shutdown on persistent EIO. Block-address validation helpers distinguish generic metadata/data checks and enhanced data checks; callers must use the correct validation type. The compressed read/write context reference-counting comments are important because compressed pages can outlive submitting code while still attached to bios. The page-private layout is delicate because it multiplexes bit flags and wrapped pointers in `folio->private`.
