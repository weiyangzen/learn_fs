# File Research: sources/os/linux/linux/fs/ecryptfs/crypto.c

## Purpose
Implements core eCryptfs cryptographic operations: file content encryption/decryption, per-inode cryptographic context initialization, metadata header read/write, cipher-code mapping, cached cipher transform lookup, and filename encryption/decryption helpers.

## Main Responsibilities
- Convert signatures and binary data between hex and raw bytes.
- Maintain and destroy `ecryptfs_crypt_stat` and mount crypt state.
- Encrypt and decrypt regular-file folios one extent at a time.
- Read/write eCryptfs metadata either in the lower file header or in `user.ecryptfs` xattr.
- Parse and emit eCryptfs header flags, marker, header extent metadata, and key packet sets.
- Encode encrypted filenames into filesystem-safe names and decode them back.
- Cache shared key cipher transforms in `key_tfm_list`.

## Key Interfaces
- `ecryptfs_encrypt_page()` and `ecryptfs_decrypt_page()` transform upper folios to/from lower file data.
- `ecryptfs_new_file_context()` initializes new-file crypt state from mount policy.
- `ecryptfs_write_metadata()` writes new-file metadata and key packets.
- `ecryptfs_read_metadata()` reads metadata from lower header first, then xattr.
- `ecryptfs_read_and_validate_header_region()` and `ecryptfs_read_and_validate_xattr_region()` cheaply validate marker and initialize upper size.
- `ecryptfs_encrypt_and_encode_filename()` and `ecryptfs_decode_and_decrypt_filename()` implement encrypted filename presentation.
- `ecryptfs_get_tfm_and_mutex_for_cipher_name()` returns a cached crypto transform plus its serialization mutex.
- `ecryptfs_set_f_namelen()` estimates the maximum plaintext filename length available under filename encryption.

## Control Flow and Data Model
A new encrypted file starts in `ecryptfs_new_file_context()`, which copies mount flags into inode flags, copies mount-wide non-FNEK key signatures into the inode `keysig_list`, selects the mount default cipher/key size, generates a random file encryption key, derives a root IV from that key, and allocates a CBC skcipher context.

For page I/O, `ecryptfs_encrypt_page()` allocates a temporary page, encrypts each extent with `crypt_extent()`, then writes the encrypted page to the lower file at `metadata_size + page_index * PAGE_SIZE`. `ecryptfs_decrypt_page()` reads from the same lower offset into the upper folio, then decrypts each extent in place. IVs are derived by MD5 over `root_iv || decimal_extent_index`.

File metadata is formatted as:
- cleartext upper file size,
- randomized marker pair where `m1 ^ MAGIC_ECRYPTFS_MARKER == m2`,
- crypt-stat flags plus file-format version,
- header extent size and number of header extents,
- packet set generated by `ecryptfs_generate_key_packet_set()` in `keystore.c`.

`ecryptfs_read_metadata()` copies mount-wide flags, reads the lower header, and parses it. On failure it retries `user.ecryptfs`; if metadata is found only in xattr but the mount lacks xattr metadata support, it rejects the file as encrypted.

Filename encryption is enabled by mount flags. Plain names are wrapped into tag-70 packets by `keystore.c`, encoded with a custom 64-character portable alphabet, and prefixed with `ECRYPTFS_FNEK_ENCRYPTED.`. Decode reverses the alphabet encoding and parses tag 70 unless encrypted-view mode is active.

## Dependencies
- Linux crypto skcipher API for CBC and ECB transforms.
- MD5 helper for root IV and filename prefix generation.
- eCryptfs keystore functions for packet generation/parsing.
- Lower file read/write helpers declared in `ecryptfs_kernel.h`.
- Lower xattr helpers from `inode.c`.

## State and Locking
- Per-inode `crypt_stat->cs_tfm_mutex` serializes per-file skcipher context setup/use.
- `key_tfm_list_mutex` protects the module-wide cached key transform list.
- Cached `ecryptfs_key_tfm` entries each include their own mutex to serialize users.
- Metadata buffers are explicitly zeroed before returning to slab caches where sensitive data may exist.

## Error Handling and Edge Cases
- Rejects missing/invalid eCryptfs marker and unsupported file format versions.
- Rejects invalid header sizes when validating header metadata.
- Falls back from file-header metadata to xattr metadata.
- Returns plaintext copy for filenames when filename encryption is disabled or encrypted-view is enabled.
- Uses `BUG_ON()` for internal invariants such as invalid IV size or missing encryption flag during page crypto.

## Risks and Notes
- Uses MD5 for IV derivation and compatibility structures; this reflects legacy eCryptfs design.
- Filename encryption support in this file is effectively FNEK/tag-70 oriented; FEK filename prefix paths are mostly unsupported.
- Verbose logging can dump secret key material when `ecryptfs_verbosity > 0`; `main.c` emits a critical warning for this.
- Page crypto assumes `crypt_stat->extent_size` divides `PAGE_SIZE` in normal configurations.
