## Scope

This chunk covers almost all of Linux's BFQ multi-queue I/O scheduler implementation except the sysfs attribute table and module registration tail after line 7379. It defines BFQ's per-request and per-queue lifecycle, low-latency heuristics, cooperative/stable queue merging, dispatch/idling/injection policy, request completion handling, per-IO-context queue management, and queue initialization/teardown.

## Core APIs and Entry Points

- Elevator/block-mq hooks implemented in this chunk:

## Control Flow

### Request Preparation and Queue Selection

1. `bfq_prepare_request()` runs early and only attaches `rq->elv.icq` via `ioc_find_get_icq()` and clears `rq->elv.priv[]`.
2. Actual BFQ association is delayed until insertion/merge through `bfq_init_rq()`, because a request may still become non-BFQ/pass-through after preparation.
3. `bfq_init_rq()`:
   - Rejects requests without `elv.icq`.
   - Converts `io_cq` to `bfq_io_cq`.
   - Applies ioprio/cgroup updates with `bfq_check_ioprio_change()` and `bfq_bic_update_cgroup()`.
   - Picks or allocates a `bfq_queue` with `bfq_get_bfqq_handle_split()`.
   - Increments entity allocation, queue refcount, and bic request count.
   - Stores `RQ_BIC(rq)` and `RQ_BFQQ(rq)` in `rq->elv.priv[]`.
   - May run burst detection for just-created sync queues.

### Queue Allocation

- `bfq_get_queue()` maps async I/O to shared per-group/per-priority/per-actuator async queues and sync I/O to per-process queues.
- New queues are allocated from `bfq_pool`, initialized by `bfq_init_bfqq()`, attached to a `bfq_group` by `bfq_init_entity()`, and given a process ref.
- On allocation failure, requests use permanent `bfqd->oom_bfqq`.
- Sync queues may be early-stably-merged or scheduled for delayed stable merge through `bfq_do_or_sched_stable_merge()`.

### Insertion and Merge

- `bfq_insert_request()` initializes the request, attempts generic insert merge, traces insertion, then:
  - Inserts at head into `bfqd->dispatch` for `BLK_MQ_INSERT_AT_HEAD`.
  - Inserts non-BFQ requests into `bfqd->dispatch`.
  - Otherwise calls `__bfq_insert_request()`.
- `__bfq_insert_request()`:
  - Attempts cooperative queue setup with `bfq_setup_cooperator()`.
  - If a merge is scheduled, transfers request allocation/ref state to the target queue and calls `bfq_merge_bfqqs()` while the issuing bic still points to the old queue.
  - Updates think time, short-think classification, seekiness, and request-position state.
  - Calls `bfq_add_request()` to add to `sort_list` and update `next_rq`.
  - Sets FIFO expiry and appends to the FIFO list.
  - Calls `bfq_rq_enqueued()` to handle idling/timer effects.
- Merge hooks use `bfqd->bio_bfqq` and `bfqd->bio_bic` to remember the queue that the current bio would enter. Front merges may reposition requests in the queue rb-tree and recompute `next_rq`. Merged-away requests are removed from BFQ lists and stats are updated.

### Request Ordering

- Each `bfq_queue` has:
  - `sort_list`, an rb-tree ordered by request sector.
  - `fifo`, a FIFO list with per-request `fifo_time`.
  - `next_rq`, selected by `bfq_choose_req()`.
- `bfq_choose_req()` prefers sync over async, metadata over non-metadata, then uses an anticipatory-elevator seek-distance rule:
  - Forward seeks are preferred.
  - Small backward seeks are allowed with `bfq_back_penalty`.
  - Wrapped requests are ordered to reduce future backward seek cost.
- `bfq_find_next_rq()` first checks FIFO expiry via `bfq_check_fifo()`, then compares rb-tree predecessor/successor around the last request.

### Activation and Low-Latency Heuristics

- `bfq_bfqq_handle_idle_busy_switch()` handles idle-to-busy transitions:
  - Computes whether the queue is interactive, soft real-time, in a large burst, and whether it deserves weight raising.
  - Updates budget for activation through `bfq_bfqq_update_budg_for_activation()`.
  - Clears stale burst flags after long idle periods.
  - Updates weight-raising state through `bfq_update_bfqq_wr_on_rq_arrival()`.
  - Adds the queue to the busy set with `bfq_add_bfqq_busy()`.
  - May expire the in-service queue for preemption if the new queue needs service-hole recovery, has higher class/weight, or idling is no longer useful.
- `bfq_update_bfqq_wr_on_rq_arrival()` starts, extends, converts, or ends interactive/soft-RT weight raising.
- `bfq_update_wr_data()` enforces max weight-raising duration, early ending after `max_service_from_wr`, large-burst suppression, and immediate entity weight update when raising state changes.

### Burst, Cooperative Merge, and Stable Merge

- `bfq_handle_burst()` tracks rapid queue creation in a shared parent entity. Large bursts suppress low-latency treatment to favor throughput for workloads such as boot or parallel search.
- Close cooperation:
  - `bfq_pos_tree_add_move()` keeps active candidate queues in a per-group request-position tree unless device queueing makes merging unnecessary.
  - `bfq_find_close_cooperator()` searches nearby queues.
  - `bfq_setup_cooperator()` tries delayed stable merge first, skips merging on non-rotational queueing devices, filters by creation age, idle class, ioprio class, sync status, parent entity, seekiness, and OOM queue.
  - `bfq_setup_merge()` creates a redirection chain through `bfqq->new_bfqq` and pre-adds process refs to the target queue.
  - `bfq_merge_bfqqs()` saves old/new queue state, transfers IO-bound/waker/weight-raising state, redirects the bic, marks shared queues, releases the old process ref, and returns the target.
- Stable merge:
  - `bfq_do_or_sched_stable_merge()` uses the last-created queue per group/entity to merge flows likely belonging to the same application/task.
  - Non-rotational queueing devices merge early.
  - Rotational/non-queueing devices may delay the stable merge to see if the new queue has sequential I/O, because not merging may improve throughput there.
- Split:
  - Seeky cooperative queues are marked `split_coop` at expiration.
  - `bfq_get_bfqq_handle_split()` may call `bfq_split_bfqq()`, restore saved state, preserve waker state when safe, and resume burst flags.

### Dispatch and Idling

- `bfq_dispatch_request()` locks `bfqd->lock`, calls `__bfq_dispatch_request()`, then updates cgroup debug stats.
- `__bfq_dispatch_request()`:
  - First drains `bfqd->dispatch` for at-head/pass-through/direct requests.
  - Enforces `strict_guarantees` by dispatching only when no request is already in driver.
  - Selects a BFQ queue through `bfq_select_queue()`.
  - Dispatches from that queue with `bfq_dispatch_rq_from_bfqq()`.
  - Increments per-actuator and total in-driver counters and marks the request `RQF_STARTED`.
- `bfq_select_queue()`:
  - Keeps the current in-service queue if it has budget and requests.
  - Expires it on budget timeout, budget exhaustion, or no-more-requests when idling is not justified.
  - Finds underused-actuator work first for multi-actuator devices.
  - While the in-service queue is empty but should idle, may inject:
    - Async I/O from the same bic.
    - I/O from a detected waker queue.
    - I/O from a queue woken by the in-service queue.
    - A budget-compatible active queue selected by `bfq_choose_bfqq_for_injection()`.
- `bfq_better_to_idle()` permits idling only when:
  - `strict_guarantees` is set, or
  - `bfq_slice_idle` is nonzero, queue is sync and not idle-class, and idling either boosts throughput or is needed for service guarantees.
- `idling_boosts_thr_without_issues()` detects throughput-positive idling on rotational/no-queueing devices or sequential I/O-bound queues, but disables it when weight-raised queues are busy.
- `idling_needed_for_service_guarantees()` forces idling in asymmetric scenarios, for weight-raised queues with competing non-weight-raised work or substantial foreign in-flight I/O, or when this is the only busy queue.
- `bfq_arm_slice_timer()` starts the idle hrtimer and adjusts idle duration for seeky or weight-raised queues.
- `bfq_idle_slice_timer()` and `bfq_idle_slice_timer_body()` expire idling queues for timeout or too-idle, then schedules dispatch.

### Budgeting and Rate Estimation

- Budgets are measured in sectors; async requests can be charged by `bfq_async_charge_factor` unless the queue is sync, weight-raised, or scenario is asymmetric.
- `bfq_max_budget()` uses a default budget until enough samples exist; then it uses dynamic `bfqd->bfq_max_budget`.
- `bfq_bfqq_update_budg_for_activation()` preserves remaining budget for queues that quickly return after non-blocking wait, enabling service-hole recovery.
- `__bfq_bfqq_recalc_budget()` adapts `bfqq->max_budget` on expiration:
  - Reduces budget after too-idle with no outstanding requests.
  - Increases budget on budget timeout or budget exhaustion.
  - Sets budget to recent service for no-more-requests.
  - Gives async queues maximum budget.
- `bfq_update_peak_rate()`, `bfq_update_rate_reset()`, and `bfq_reset_rate_computation()` estimate device peak rate from dispatch/completion timing and sequentiality, then `update_thr_responsiveness_params()` recomputes dynamic max budget.
- `bfq_bfqq_is_slow()` uses service-slot duration, seekiness, and budget consumption to decide whether to charge slow queues by time through `bfq_bfqq_charge_time()`.

### Completion and Injection Feedback

- `bfq_finish_requeue_request()` is the central completion/requeue cleanup path:
  - Updates completion stats for started requests.
  - Locks `bfqd->lock`.
  - If the request was started, optionally updates injection limit if it was the sampled request, then calls `bfq_completed_request()`.
  - Decrements allocated counters, queue refcount, and bic request count.
  - Clears `rq->elv.priv[]`.
- `bfq_completed_request()`:
  - Updates hardware-tag/queueing detection.
  - Decrements in-driver counters and queue dispatch count.
  - If the queue is now inactive with no dispatched requests, removes pending-group and weight-counter accounting.
  - Updates think-time end timestamp and peak-rate reset conditions.
  - Tracks last completed non-shared queue for waker detection.
  - Performs delayed soft-RT update if an isochronous batch is recognized.
  - If the completed queue is in service, arms idling, expires for budget timeout, or expires for no-more-requests as appropriate.
  - Schedules dispatch when the driver becomes empty.
- `bfq_update_inject_limit()` adapts per-queue `inject_limit` by comparing sampled total service time with and without injected requests.

## Risks and Invariants

- Locking:
  - Most queue/device state is protected by `bfqd->lock`; several stats updates after dispatch/insertion use `q->queue_lock` in cgroup debug mode.
  - `bfqd->queued` is written under `bfqd->lock` but read locklessly in `bfq_has_work()`; comments explicitly accept benign false-positive dispatch attempts.
  - `bfq_exit_icq()` handles the case where scheduler data already exited by cycling over `BFQ_MAX_ACTUATORS` without taking `bfqd->lock`.
- Reference accounting is delicate:
  - Queue references come from process ownership, allocated requests, weight counters, async group pins, stable-merge pins, and merge redirections.
  - `bfqq_process_refs()` subtracts non-process refs and is used to prevent unsafe merges/splits.
  - `bfq_setup_merge()` pre-adds process refs to the merge target; `bfq_put_cooperator()` must unwind `new_bfqq` chains.
  - `bfq_put_queue()` must only free queues with empty FIFO/rb request lists and no dispatched requests.
- Merge/split hazards:
  - `bic_set_bfqq()` clears stale `bfqq->bic` and cancels self-stable-merge candidates.
  - Stable merges intentionally keep extra refs; missed `bfq_put_stable_ref()` would leak queues.
  - Cooperative merging can impair fairness; the code filters aggressively by parent, class, seekiness, age, sync status, OOM queue, and device queueing capability.
  - Waker state is intentionally lost on some queue merges; comments call this out as an issue.
- Timer/idling races:
  - `bfq_idle_slice_timer()` may see an in-service queue changed since timer arm; body rechecks `bfqq == bfqd->in_service_queue`.
  - Expiring an idling queue can create timestamp misalignment, so budget-timeout expiration is avoided while `bfq_bfqq_must_idle()` is true.
- Device model heuristics:
  - `hw_tag` detection is sampled and approximate; `nonrot_with_queueing` drives major policy choices including merge/idling suppression.
  - Multi-actuator support depends on `disk->ia_ranges`; out-of-range bio sectors warn and fall back to actuator 0.
  - Only `active_list[0]` and `active_list[1]` are initialized in this chunk, while loops use `num_actuators`; this is safe only if allocation/init elsewhere or constants ensure relevant active lists are initialized for supported actuator count. This is a cross-file point to verify.
- Accounting assumptions:
  - The dispatch direct-list path with no `bfqq` intentionally does not increment `tot_rq_in_driver`, accepting temporary inaccuracy.
  - `bfq_finish_requeue_request()` assumes requeued requests reinserted into BFQ queues are re-prepared, otherwise clearing `elv.priv[]` would break insertion logic.
  - `bfq_completed_request()` updates `last_completed_rq_bfqq` only for non-shared queues to reduce false waker detection.

## Scope

This chunk is the BFQ multi-queue elevator's sysfs tuning surface, elevator registration record, module initialization, and module teardown. It wires earlier BFQ request scheduling, queue lifecycle, cgroup, and weight-raising logic into the Linux block elevator framework.

## APIs and Entry Points

- `bfq_var_show()` formats an unsigned tunable as a newline-terminated decimal string for sysfs.
- `bfq_var_store()` parses a base-10 unsigned long from a sysfs write using `kstrtoul()`.
- Macro-generated `*_show()` / `*_store()` handlers expose and update BFQ per-device fields from `struct bfq_data`, with conversions between raw values, jiffies, milliseconds, nanoseconds, and microseconds.
- Custom stores update coupled state:
  - `bfq_max_budget_store()` handles auto mode when user value is `0`.
  - `bfq_timeout_sync_store()` updates timeout and recomputes auto budget when needed.
  - `bfq_strict_guarantees_store()` can raise `bfq_slice_idle` to at least `8 ms`.
  - `bfq_low_latency_store()` calls `bfq_end_wr()` before disabling low-latency heuristics.
- `bfq_attrs[]` publishes the elevator sysfs knobs: `fifo_expire_sync`, `fifo_expire_async`, `back_seek_max`, `back_seek_penalty`, `slice_idle`, `slice_idle_us`, `max_budget`, `timeout_sync`, `strict_guarantees`, and `low_latency`.
- `iosched_bfq_mq` registers BFQ as elevator name `"bfq"`.
- `bfq_init()` and `bfq_exit()` define module lifetime setup and teardown.

## Control Flow

Sysfs reads go through the elevator sysfs layer into BFQ show handlers, fetch `e->elevator_data` as `struct bfq_data`, convert the selected field if needed, and format it through `bfq_var_show()`.

Sysfs writes parse the input, clamp ranges, convert user units to internal units, then update scheduler state. Budget and timeout writes can recompute `bfq_max_budget`; disabling low latency clears active weight raising.

`iosched_bfq_mq` binds earlier functions into the block-mq scheduler ABI: request depth limiting, request prepare/finish/requeue, insertion, dispatch, merge handling, work detection, depth updates, and queue init/exit.

`bfq_init()` registers the BFQ blkcg policy when configured, creates the BFQ queue slab cache, initializes `ref_wr_duration[]`, then calls `elv_register()`. Failure paths unwind in reverse order. `bfq_exit()` unregisters the elevator, unregisters blkcg policy when present, and destroys the slab cache.

## State and Dependencies

Touched `struct bfq_data` fields include `bfq_fifo_expire[]`, `bfq_back_max`, `bfq_back_penalty`, `bfq_slice_idle`, `bfq_max_budget`, `bfq_user_max_budget`, `bfq_timeout`, `strict_guarantees`, and `low_latency`.

- `bfq_pool` is managed through adjacent slab setup/kill helpers.
- `blkcg_policy_bfq` comes from `bfq-cgroup.c` under `CONFIG_BFQ_GROUP_IOSCHED`.

## Risks and Edge Cases

- Generated show handlers use a `u64` temporary but pass through `bfq_var_show(unsigned int)`, so very large displayed values can truncate.
- Store handlers silently clamp out-of-range inputs instead of rejecting them.
- `bfq_slice_idle` is a `u32`; large millisecond or microsecond inputs are converted to nanoseconds and can overflow/truncate on assignment.
- Enabling `strict_guarantees` mutates `bfq_slice_idle`; disabling it does not restore the old value.
- Disabling `low_latency` has a side effect beyond flag assignment: it tears down weight raising via `bfq_end_wr()`.
- Module init cleanup ordering must stay aligned with setup ordering: blkcg policy, slab cache, then elevator registration.
