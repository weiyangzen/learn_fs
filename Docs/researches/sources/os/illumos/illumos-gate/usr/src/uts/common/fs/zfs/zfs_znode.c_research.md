# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_znode.c

This file implements core ZFS znode lifecycle and metadata handling for the illumos ZPL. A znode is the ZFS-specific in-core representation backing a vnode, and this file bridges vnode operations, DMU/SA object metadata, object allocation/freeing, filesystem creation, truncate/free-space behavior, and object-to-path/stat helpers.

The kernel-only opening portion defines the znode kmem cache, vnode operation table globals, the global `zfsvfs_lock`, and the znode move callback used by kmem memory pressure relocation. `zfs_znode_cache_constructor()` allocates and initializes the embedded vnode, znode locks, rangelock, list node, and cached ACL state. `zfs_znode_cache_destructor()` asserts the znode has been detached from any filesystem and tears down the same resources. `zfs_znode_init()` creates the cache and installs `zfs_znode_move()` as the cache move callback; `zfs_znode_fini()` removes ZFS VFS/vnode ops and destroys the cache.

The znode move path is deliberately conservative. `zfs_znode_move()` first validates that the `z_zfsvfs` pointer is still valid, closes an unmount/free race with `zfsvfs_lock`, enters the filesystem teardown reader lock, holds `z_znodes_lock`, takes the per-object hold, locks the vnode, and only moves znodes whose vnode is referenced solely by the DNLC. `zfs_znode_move_impl()` then swaps vnodes, copies identity and cached fields, rebinds the SA handle user pointer, invalidates the old znode's back-pointers, and replaces the filesystem list link. This keeps movable znodes limited to idle cache entries and avoids races with `zfs_zget()` and unmount.

The vnode operation table helpers `zfs_create_op_tables()` and `zfs_remove_op_tables()` create/free the vnode ops vectors for directories, regular/special files, symlinks, xattr directories, error vnodes, and share files. `zfs_create_share_dir()` creates the hidden shares directory in the master node object using a temporary znode, creates its ACL ids, inserts the new object id under `ZFS_SHARES_DIR`, and then destroys the temporary in-core znode.

Device-number helpers `zfs_expldev()` and `zfs_cmpldev()` provide ZFS-private expansion/compaction for 32-bit and 64-bit device encodings. They avoid the standard `expldev()`/`cmpldev()` behavior mismatch that would otherwise affect on-disk `SA_ZPL_RDEV` values across ILP32/LP64 environments.

`zfs_znode_sa_init()` attaches or creates the SA handle for a znode and marks root vnodes with `VROOT`. `zfs_znode_alloc()` constructs an in-core znode from an existing DMU object: it initializes vnode state, loads bulk SA attributes such as mode, generation, size, links, flags, parent, atime, uid, gid, and optional project id, selects vnode ops based on vnode type and xattr/share-directory status, inserts the znode into `zfsvfs->z_all_znodes`, and only then publishes `z_zfsvfs` so the move callback can see a complete object.

`zfs_mknode()` creates new ZPL objects. It handles replay-supplied object ids/generation/dnodesize, chooses old znode bonus format versus SA format, allocates or claims either a ZAP directory object or plain file object, derives initial size/link count/parent/rdev/project id/pflags, encodes timestamps, writes the ordered SA bulk attribute template, stores inline or external ACL data as appropriate, optionally calls `zfs_znode_alloc()` for the new in-core znode, applies xvattrs, writes legacy ACLs when needed, and releases the object hold. The ordering for `DMU_OT_ZNODE` attributes is explicitly part of the old on-disk layout contract.

Lookup and reload are handled by `zfs_zget()` and `zfs_rezget()`. `zfs_zget()` takes a per-object hold, validates the bonus type, reuses an existing SA user znode if present, rejects unlinked znodes, or allocates a new znode from the object. `zfs_rezget()` reloads SA state for an existing znode after DMU state has been dropped, invalidates cached ACLs, checks generation consistency, reloads size/link/flag/time/owner/mode/project state, updates block size, and marks zero-link received objects as unlinked while dropping their DMU handle to avoid stale access.

Deletion and inactive handling are split by lifecycle state. `zfs_znode_delete()` frees an external ACL object when present, frees the main object, tears down the SA handle, and frees the znode. `zfs_zinactive()` is called when vnode references drain: it takes the object hold, drops the vnode reference, defers if references or cached pages remain, removes unlinked files via `zfs_rmnode()` when writable, otherwise destroys the SA handle and frees the znode. `zfs_znode_free()` invalidates the vnode, removes the znode from the filesystem list, frees cached ACLs, returns it to the cache, and releases the held VFS reference.

The file also implements timestamp and size-changing helpers. `zfs_tstamp_update_setup()` updates in-core atime/mtime/ctime encodings and archive/AV flags. `zfs_grow_blocksize()` grows the DMU object block size only while the file still fits in one block. `zfs_extend()`, `zfs_free_range()`, and `zfs_trunc()` coordinate rangelocks, DMU transaction holds, blocksize growth, `SA_ZPL_SIZE` updates, sparse flag clearing on truncate-to-zero, and page-cache invalidation/zeroing outside the transaction. `zfs_freesp()` is the public free-space/truncate path: it checks mandatory locks, extends as needed, truncates or frees a range, updates timestamps/flags, and logs the truncate with `zfs_log_truncate()` when requested.

`zfs_xvattr_set()` applies extended system attributes from an `xvattr_t` to ZFS pflags and SA attributes, including create time, readonly/hidden/system/archive/immutable/nounlink/appendonly/nodump/opaque, AV quarantine/modified/scanstamp, reparse, offline, sparse, and project inheritance flags. It uses `ZFS_ATTR_SET()` for bit-backed attributes and marks return bits in the xva.

`zfs_create_fs()` initializes a new ZPL objset. It creates the master node, records ZPL properties, creates the SA master object for SA-capable versions, creates the unlinked set, builds a temporary minimal `zfsvfs_t` and root znode so `zfs_mknode()` can create the root directory, records `ZFS_ROOT_OBJ`, creates the shares directory, then tears down the temporary zfsvfs and root in-core objects. This is filesystem birth-time code and assumes the empty objset cannot produce I/O read failures for the asserted operations.

The non-kernel/shared tail provides SA-handle and object introspection helpers usable by libzpool-like consumers. `zfs_sa_setup()` loads the SA table from the master node. `zfs_grab_sa_handle()` validates object bonus type and creates a private SA handle, with `zfs_release_sa_handle()` undoing it. `zfs_obj_to_pobj()` reads parent/flags/mode and validates parent directory or xattr-directory semantics. `zfs_obj_to_path_impl()` walks parent pointers upward, checking the unlinked set first, resolving child names with `zap_value_search()`, inserting `<xattrdir>` for xattr directories, and building a path from the end of the caller buffer. `zfs_obj_to_path()` and `zfs_obj_to_stats()` expose path and stat lookup wrappers.

Important dependencies are the vnode layer, DMU object allocation/freeing, SA bulk lookup/update, ZAP directories, ZFS ACL/FUID/project-quota helpers, ZIL truncate logging, range locks, page cache invalidation, and per-zfsvfs object-hold locks. The main correctness risks are around lifecycle ordering: `z_zfsvfs` publication controls kmem move eligibility, object holds serialize with `zfs_zget()`, truncate must avoid page/transaction deadlocks, and unlinked/received zero-link objects must avoid stale SA handle use.
