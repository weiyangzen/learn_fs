# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/sys/zone.h

`zone.h` is the central private zone contract for illumos. It exposes user/kernel shared constants for zone IDs, zone syscall subcommands, attributes, status/event strings, subprocess exit codes, zone creation arguments, and network attribute payloads. Under `_KERNEL`, it also defines the full `zone_t` structure, zone reference tracking, zone-specific data, visibility macros, and zone management APIs.

The shared namespace defines zone ID limits and special IDs: `GLOBAL_ZONEID` is 0, user-created zones start at 1, `MAX_ZONEID` is 9999, and `ALL_ZONES` is the special token for operations spanning every zone. Zone syscall subcodes cover create, destroy, get/set attributes, enter, list, shutdown, lookup, boot, and datalink add/delete/check/list operations. Zone attributes cover root, name, status, privilege set, unique ID, pool ID, init PID/name/restart policy, boot arguments, brand, physical memory cap, scheduling class, flags, hostid, allowed filesystems, network data, and security flags. Brand-specific attributes begin at `ZONE_ATTR_BRAND_ATTRS`.

The event constants define the sysevent channel/class/subclass for zone status changes and the status strings used in those events. Callback attribute names include zone name, old/new state, timestamp, and zone ID. Subprocess exit values distinguish success, usage failure, incomplete-but-no-recovery-needed failure, and fatal failure requiring recovery, matching zoneadm/zoneadmd orchestration needs.

`zone_def` and its 32-bit variant describe zone creation input: name, root, privilege set, resource-control buffer, extended error output, ZFS dataset buffer, label matching, DOI, sensitivity label, and creation flags. Extended errors include unknown, chrooted creation attempt, existing mounts under the zone path, and duplicate label. `zone_status_t` enumerates the lifecycle from uninitialized through initialized, ready, booting, running, shutting down, empty, down, dying, and dead. A comment warns that mdb's `zone_status_names` must be kept in sync. `zone_cmd_arg_t` and `zone_cmd_rval_t` define the door protocol used to communicate with zoneadmd for commands such as ready, boot, reboot, halt, mount, unmount, and shutdown.

Name and path constants constrain zone names to 64 bytes because they are embedded in AF_UNIX socket paths. `GLOBAL_ZONENAME`, `ZONENAME_REGEXP`, `ZONES_TMPDIR`, and `ZONE_DOOR_PATH` define the public naming and zoneadmd door path conventions. Zone flags distinguish logged reference counts, uniquely hashed Trusted Extensions labels, scratch zones, and exclusive-IP zones. `ZCF_NET_EXCL` is the corresponding create flag. `zone_net_data_t` carries network attribute records for zone network address or default-router data, including datalink ID and variable payload.

The kernel-only section defines reference tracking and accounting support. `zone_ref_subsys_t` assigns subsystem buckets for tracked holds from NFS, NFSv4, SMBFS, MNTFS, LOFI, VFS, and IPC. Each tracked `zone_ref_t` links into a zone's reference list for debugger visibility. `zone_dataset_t` records ZFS datasets exported to a zone. Kstat structures cover generic zone resource values, memory-cap paging statistics, CPU microstate/load/fork-failure/init/boot statistics, and other per-zone counters.

`zone_t` is the in-kernel zone object. Immutable identity fields include name, nodename/domain strings, hostid behavior, root vnode/path, zone ID, unique generation ID, brand, root path length, and selected creation flags. `zone_lock` protects reference counts, credential holds, subsystem reference counts, the reference list, task count, flags, zone-specific data list, and `zone_pfexecd`. Other fields have dedicated lock domains: `zone_linkage` is protected by `zonehash_lock`; status and zone kernel-thread list by `zone_status_lock`; LWP counts by `zone_nlwps_lock`; memory reservation/caps by `zone_mem_lock`; LOFI caps by `zone_rctl_lock`; mounted filesystems by `vfs_list_lock`; pool binding by `pool_lock`; processor set binding by `cpu_lock`; datalink list by `zone_lock`; mntfs private data by `zone_mntfs_db_lock`; memory-cap stats by `zone_mcap_lock`; misc stats by `zone_misc_lock`; and mount/create/destroy synchronization by `zone_mount_lock` plus `zone_mount_cv`.

The `zone_t` fields span process/task/LWP accounting, System V IPC and shared memory usage, zone-wide rctls, locked-memory and swap limits, LOFI limits, zone-specific data, zsched and init process state, boot errors and arguments, physical memory caps, privilege set, mounted VFS list, zone kcred, pool/processor-set binding, boot time, visible CPU counts, exported datasets, Trusted Extensions label and MLP state, init restart policy, scheduling class, swap/locked-memory/process kstats, datalink list, netstack pointer, CPU caps, audit context, mntfs state, pfexec daemon registration, allowed filesystem list, memory-cap paging stats, default security flags, microstate aggregation, fork-failure counters, load average state, FSS usage counters, DTrace private counters, and mount-in-progress state.

The exported kernel API covers initialization, the `zone()` syscall implementation, zone holds/releases, tracked reference holds/releases, credential/task holds, lookup by ID/label/name/path, current zone ID retrieval, datalink walking and checks, load-average updates, zone-specific data key creation/deletion/get/set, zone-scoped kernel thread creation and exit, status waits with timeout/signal variants, status retrieval, hostid and kcred lookup, pool and pset get/set, visible CPU counts, dataset visibility checks, zone-aware `kadmin()`, global shutdown, mount-progress bracketing, and zone walking. Global state includes `zone0`, `global_zone`, `maxzones`, and rctl handles for LWPs, processes, locked memory, swap, and LOFI.

Zone-specific data (`ZSD`) lets subsystems register per-zone keys with create, shutdown, and destroy callbacks. `struct zsd_entry` is nominally private to `zone.c` but exposed for mdb. Its flags track needed, in-progress, and completed phases for create/shutdown/destroy. Comments explain this avoids holding locks while invoking callbacks, preventing deadlocks.

The visibility macros implement zone isolation rules: `INGLOBALZONE()` tests whether a process is in the global zone; `HASZONEACCESS()` allows access to same-zone objects or global-zone observers; `ZONE_PATH_VISIBLE()` checks whether a resolved global path lies under a zone root; `ZONE_PATH_TRANSLATE()` maps a visible global path into the zone's path view; and `ZONE_SPECIALPID()` treats PIDs 0 and 1 as visible in all zones. `ZONE_ROOTVP()` and `VN_IS_CURZONEROOT()` are vnode helpers, with comments warning that active ZSD initialization can make `curzone` assumptions unsafe.

This header is a high-blast-radius kernel interface. Changes to enum ordering, `zone_t` field semantics, lock ownership, or ZSD callback state require coordinated updates in zone.c, mdb, resource controls, networking, VFS, process accounting, and zoneadmd-facing userland.
