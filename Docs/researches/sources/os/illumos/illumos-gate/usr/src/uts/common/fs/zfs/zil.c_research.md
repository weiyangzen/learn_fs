# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zil.c

This file implements the ZFS Intent Log core. The ZIL records filesystem-modifying system calls as in-memory intent transactions (`itx_t`) and, when synchronous semantics require it, writes them into on-disk log write blocks (`lwb_t`) chained from the dataset's ZIL header. It also claims logs at pool import, destroys obsolete logs, commits synchronous operations, suspends/resumes logs, and replays records after a crash.

The file defines global ZIL controls: `zfs_commit_timeout_pct` for how long an open LWB may wait before forced issue, `zil_replay_disable`, `zil_nocacheflush`, and `zil_slog_bulk` for switching large SLOG writes to lower priority. It creates kmem caches for LWBs and commit waiters. Duplicate block-pointer tracking uses `zl_bp_tree` keyed by DVA identity so claiming/freeing logic does not process the same physical log/data block twice.

Log parsing starts with `zil_parse()`. It walks the block chain beginning at `zh_log`, stops at holes, invalid blocks, claimed sequence limits, or callback errors, calls a block callback for each valid block pointer, reads and validates each log block with `zil_read_log_block()`, then calls a record callback for each `lr_t`. Validation checks checksum sequence continuity and block-chain linkage, handling both `ZIO_CHECKSUM_ZILOG2` slim-ZIL layout and the older trailing-chain layout. `zil_read_log_data()` reads payload blocks referenced by `TX_WRITE` records, optionally in raw mode when only validating.

Claim, check, clear, and free operations are implemented as parse callbacks. `zil_claim_log_block()` claims ZIL blocks born in or after the first claim txg, or just verifies claimability when no transaction is supplied. `zil_claim_log_record()` additionally validates and claims indirect write payload blocks. `zil_clear_log_block()` is used during checkpoint rewind to free invalid post-rewind ZIL blocks. `zil_free_log_block()` and `zil_free_log_record()` free log-chain blocks and previously claimed write payload blocks during log destruction.

`zil_claim()` owns an objset during pool load, handles `SPA_LOG_CLEAR` and checkpoint-rewind cases, zeroes unsafe headers when needed, and otherwise parses and claims the log if `zh_claim_txg` is still zero. It records the highest claimed block and record sequence numbers in the header, sets `ZIL_REPLAY_NEEDED` when useful log content exists, sets `ZIL_CLAIM_LR_SEQ_VALID`, marks encrypted objsets for raw rewrite, and dirties the dataset. `zil_check_log_chain()` verifies whether an existing chain is claimable, with special handling for dead log vdevs and checkpointed unclaimed headers.

`zil_create()` creates or reuses the first on-disk log block for a dataset. It waits for prior destroys, allocates a minimum-size log block when the header is empty or byte-swapped, initializes log-chain checksum words, creates the first LWB, commits the allocation transaction, and waits for sync so the MOS-backed header receives the block pointer. `zil_destroy()` schedules destruction of all log blocks and header state, optionally preserving the first block for faster future use after replay. `zil_destroy_sync()` does the parse-time freeing in syncing context.

LWB write handling is the center of synchronous commit performance. `zil_alloc_lwb()` allocates an in-memory LWB, initializes its buffer and used-size layout based on checksum format, and appends it to `zl_lwb_list`. `zil_lwb_write_open()` lazily creates the root zio and write zio for an LWB, chooses sync or async write priority based on SLOG usage, installs zio dependency ordering against the previous opened LWB, and records it as `zl_last_lwb_opened`. `zil_lwb_write_issue()` allocates the next on-disk ZIL block, writes its pointer into the current block's chain record, chooses the next block size from bucket and recent-history heuristics, shrinks slim-ZIL writes to used size, zeroes unused buffer bytes, registers vdevs to flush, and issues the root/write zios.

Flush correctness is tracked by per-LWB vdev trees. `zil_lwb_add_block()` records top-level vdev ids for written blocks unless cache flushes are disabled. `zil_lwb_write_done()` runs when the LWB write zio finishes: it marks the LWB write done, frees the ABD, defers flushes to the next LWB when no waiter needs this LWB immediately, or issues `zio_flush()` to all recorded vdevs. `zil_lwb_flush_vdevs_done()` runs after flush zios complete, frees the LWB buffer, marks the LWB flush done, records latency, wakes all commit waiters attached to the LWB with the zio error status, and commits the allocation transaction whose block pointer is now safely linked.

`zil_lwb_set_zio_dependency()` enforces ordered completion while allowing concurrent I/O. Each newer LWB root zio depends on the prior LWB root zio, and when deferred flushes require it, the newer write zio also depends on the previous write zio. This ensures commit waiters are signaled in log order and prevents flushing a vdev for deferred previous data before that previous write has actually landed.

Intent transactions are represented by `itx_t`. `zil_itx_create()` allocates a padded log-record container and defaults it to synchronous. `zil_itx_assign()` assigns an itx to the current txg's sync list or per-object async tree, converts rename-related async records to sync first, records the real txg in the log record, and dirties the zilog. `zil_remove_async()` removes async records for a given object, and `zil_async_to_sync()` moves async records for one object or all objects into sync lists when a commit must force them stable. `zil_clean()` detaches synced txg itx lists after spa sync and frees them through a taskq when possible; `zil_itxg_clean()` handles both sync and async list/tree destruction and skips any commit waiters that raced with spa sync.

The commit path uses synthetic `TX_COMMIT` itxs and waiters to define a precise queue boundary for `zil_commit()`. `zil_commit_impl()` first moves required async records to sync, allocates a commit waiter, assigns a commit itx, calls `zil_commit_writer()` to process pending records, waits in `zil_commit_waiter()`, falls back to `txg_wait_synced()` on LWB write error, then frees the waiter. The public `zil_commit()` rejects snapshots, returns immediately when sync is disabled, verifies no pending state on read-only SPAs, uses txg sync while suspended, and otherwise delegates to the implementation.

`zil_commit_writer()` serializes commit-list processing with `zl_issuer_lock`. It gathers sync itxs from active txgs via `zil_get_commit_list()`, prunes leading commit waiters onto the last pending LWB when possible, then `zil_process_commit_list()` creates/reuses LWBs and copies log records into them. `zil_lwb_commit()` handles normal records and `TX_WRITE` payloads: direct-copy writes may split data over multiple LWBs, indirect writes ask the filesystem callback for a blkptr, EIO waits for txg sync, and each real on-disk record receives a monotonically increasing ZIL record sequence. `zil_commit_writer_stall()` handles next-LWB allocation failure by waiting for all existing LWBs to sync and forcing a new chain later.

`zil_commit_waiter()` waits for the waiter to be marked done. If its LWB is still open, it waits only for a timeout derived from recent LWB latency and `zfs_commit_timeout_pct`; on timeout, `zil_commit_waiter_timeout()` drops/reacquires locks in the safe order, issues the open LWB, resets `zl_cur_used` to bias future block-size selection smaller, and stalls on allocation failure without deadlocking against LWB completion. This delayed issue mechanism lets active workloads pack LWBs while still bounding fsync latency.

`zil_sync()` runs in syncing context. On the first sync pass, it updates replayed sequence numbers in the header, processes pending destroy state by zeroing or regenerating the header chain GUID when preserving the first block, advances `zh_log` across completed LWBs, frees committed old LWB blocks whose `lwb_max_txg` is synced and whose buffers are gone, and zeroes `zh_log` after allocation-failure cleanup leaves no LWBs.

Lifecycle helpers include `zil_init()`/`zil_fini()` for caches, `zil_alloc()`/`zil_free()` for per-objset zilog allocation and lock/list/cv initialization, `zil_open()` to install the filesystem `zl_get_data` callback, and `zil_close()` to commit outstanding work, wait long enough for dirty ZIL state and pending LWBs to sync, clear the callback, and remove any remaining unissued LWB. `zil_set_sync()` and `zil_set_logbias()` update runtime properties.

`zil_suspend()` temporarily disables on-disk ZIL use for operations such as log-device removal or old-pool snapshot handling. It holds the objset/dataset, rejects unplayed logs, increments suspend state, waits for concurrent suspenders, ensures encryption keys stay mapped if required, forces all LWBs to stable storage with `zil_commit_impl()`, waits for txg sync, destroys the log, wakes waiters, removes key mapping, and either resumes immediately or returns a cookie for `zil_resume()`. While suspended, public commits preserve sync semantics with `txg_wait_synced()`.

Replay is implemented by `zil_replay()`, `zil_replay_log_record()`, and `zil_replaying()`. `zil_replay()` skips/destroys logs without `ZIL_REPLAY_NEEDED`; otherwise it allocates a large replay buffer, waits for in-progress removes, sets replay state, parses the claimed log with decryption enabled, and destroys the log afterward. Each replay record skips already replayed or already committed records, strips the case-insensitive bit, ignores missing out-of-order target objects, reads indirect write data when needed, undo-byteswaps before dispatch, invokes the record-specific replay vector, and retries once after syncing if replay failed due to pending removes. `zil_replaying()` lets replay functions mark the dataset dirty and persist replay sequence progress per txg.

Key dependencies are SPA/ZIO allocation and rewrite/flush APIs, ARC reads, DMU txg and dataset dirtying, DSL pool dirty-zilog lists and taskqs, objset ownership, vdev state checks, ABD buffers, ZAP header fields, and filesystem-provided replay/get-data callbacks. The main correctness risks are ordering and durability: LWB zio dependency ordering, vdev flush deferral, commit waiter lifetime, `zl_issuer_lock` serialization, txg sync races, next-block allocation failure, checkpoint rewind handling, encrypted raw header rewrites, and replay sequence persistence all interact to preserve synchronous filesystem semantics across crashes.
