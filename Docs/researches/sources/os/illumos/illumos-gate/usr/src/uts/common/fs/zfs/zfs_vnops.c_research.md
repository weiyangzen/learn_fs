# File Research: sources/os/illumos/illumos-gate/usr/src/uts/common/fs/zfs/zfs_vnops.c

This file is the main ZPL vnode-operation implementation for illumos ZFS. It implements regular-file, directory, symlink, xattr-directory, share-file, and error vnode operation tables, plus the supporting logic for data I/O, namespace mutation, attributes, ACLs, mmap/page-cache integration, zero-copy buffers, ZIL replay data extraction, and file identity.

The opening comment documents the core ordering rules: each vnode op must enter the filesystem with `ZFS_ENTER()`, verify znodes, acquire range/ZPL locks before `dmu_tx_assign()`, avoid blocking transaction assignment while holding ZPL locks unless using NOWAIT/retry, log successful operations before dropping locks, always commit or abort DMU transactions, and commit the ZIL after locks are released when synchronous semantics require it. Much of the file follows this retry-on-`ERESTART` transaction pattern.

Basic operations include `zfs_open()` and `zfs_close()`, which enforce append-only opens, vscan policy, synchronous-open accounting, and process lock/share cleanup. `zfs_ioctl()` supports sync, directio compatibility, seek-data/seek-hole, filled-block count, and project-xattr get/set. `zfs_access()` delegates ACL/RWX checks to ZFS access helpers. `zfs_seek()`, `zfs_frlock()`, `zfs_pathconf()`, `zfs_fid()`, `zfs_getsecattr()`, and `zfs_setsecattr()` provide VFS-facing metadata, locking, pathconf, fid, and ACL services.

Read/write paths are centered on `zfs_read()` and `zfs_write()`. Reads validate offsets, mandatory locks, quarantine state, optional FRSYNC behavior, acquire a reader rangelock, limit reads to EOF, support zero-copy xuio initialization, and choose between mapped-page reads and DMU dbuf reads. Writes validate readonly/immutable/append-only state, mandatory locks, resource limits, append semantics, block and project quotas, then write in block-sized transactions. The write path can borrow ARC buffers for full-block writes, assign loaned buffers, grow znode block size under an over-wide range lock, update cached pages, update size and timestamps, clear setuid/setgid when required, and log TX_WRITE records.

`zfs_get_data()` is the ZIL callback used to obtain data for write log records. It handles immediate writes by range-locking and reading file data into the log buffer. For indirect writes it locks the full file block, holds a dbuf, calls `dmu_sync()`, and defers cleanup to `zfs_get_done()`. It also handles truncation, removed znodes, debug fault injection, and the `EALREADY` case that converts a TX_WRITE into TX_WRITE2 with a zeroed block pointer.

Namespace operations include `zfs_lookup()`, `zfs_create()`, `zfs_remove()`, `zfs_mkdir()`, `zfs_rmdir()`, `zfs_rename()`, `zfs_symlink()`, `zfs_readlink()`, and `zfs_link()`. Lookup uses a DNLC fast path for case-sensitive non-xattr names, supports xattr-directory lookup, validates UTF-8 when configured, and returns specfs vnodes for device files. Create handles both new object creation and existing-file open/truncate, including ACL/FUID creation, quota checks, xattr-directory restrictions, ZAP insertion, and TX_CREATE logging.

Removal distinguishes immediate deletion from placing objects in the unlinked set. `zfs_remove()` decides based on link count, vnode holds, cached pages, file size, xattr object, and external ACL state; it may remove xattr references, delete the znode immediately, or add it to the unlinked set. `zfs_rmdir()` locks the target directory’s name and parent locks, rejects cwd removal and non-directories, destroys the directory entry, and logs TX_RMDIR. Both paths account for `.zfs`, xattrs, DNLC invalidation, vnode events, and synchronous dataset policy.

`zfs_rename()` is one of the most sensitive paths. It enforces same-ZFS-instance and non-control-node constraints, validates UTF-8 and case-folding behavior, orders source/target directory-entry locks by object id/name, blocks moves between normal and xattr space, enforces project-inheritance compatibility, performs access checks, prevents moving a directory into its own descendant via `zfs_rename_lock()`, handles replacement target removal, creates the target link, destroys the source link, repairs failed partial renames, updates path information, emits vnode events, and logs TX_RENAME.

Attribute handling is implemented by `zfs_getattr()`, `zfs_setattr()`, and `zfs_setattr_dir()`. `zfs_getattr()` maps FUID IDs, bulk-loads timestamps, performs optimized ACL checks, fills standard vnode attributes, and returns optional xvattrs such as archive, readonly, hidden, immutable, append-only, quarantine, scanstamp, createtime, generation, sparse, project inherit, and project ID. `zfs_setattr()` validates masks, readonly state, immutable constraints, timestamp limits, project quota support, permissions, ownership changes, mode/ACL updates, size truncation through `zfs_freesp()`, xattr-directory ownership/project propagation, FUID dirtiness, SA layout upgrades for project IDs, timestamps, xvattr flags, ZIL setattr logging, and synchronous commit policy.

Page-cache and mmap integration is handled by `zfs_map_page()`, `zfs_unmap_page()`, `update_pages()`, `mappedread()`, `zfs_putapage()`, `zfs_putpage()`, `zfs_inactive()`, `zfs_fillpage()`, `zfs_getpage()`, `zfs_map()`, `zfs_addmap()`, and `zfs_delmap()`. Writes keep mapped pages coherent with DMU data, reads prefer mapped pages when present, putpage clusters dirty pages to file block boundaries, getpage fills page clusters from DMU reads, mmap rejects immutable/append-only writable mappings and quarantined readable/executable mappings, and map counts are maintained for mandatory-lock checks. Forced-unmount inactive paths drop pages with `zfs_null_putapage()`.

Space and directory enumeration support includes `zfs_space()` for `F_FREESP` truncate/free behavior, `zfs_freesp()` integration through setattr/create/space, and `zfs_readdir()` for translating ZAP directory entries into `dirent64` or extended dirent records. Readdir reserves cookies for `.`, `..`, and `.zfs`, serializes ZAP cursors into offsets, supports access filtering, normalization-conflict flags, sysattr conflict checks, and prefetches child znodes.

Zero-copy support is exposed through `zfs_reqzcbuf()` and `zfs_retzcbuf()`. For writes, ZFS loans ARC buffers when the write is large enough and aligned to the current max block size, splitting preamble/full-block/postamble regions. For reads, it permits loaned buffers only above tunable block-size thresholds and when no cached pages are present. `zfs_retzcbuf()` returns unused ARC buffers and finalizes xuio state.

The vnode operation templates at the end map directories, regular files, symlinks, share files, xattr directories, and error vnodes to the appropriate handlers. Regular files get read/write/page/mmap/zero-copy operations; directories get namespace operations and readdir; symlinks get readlink; xattr directories intentionally reject mkdir and symlink while reusing most directory behavior. The main risk surfaces are transaction retry lock ordering, rename/link/unlink consistency, SA upgrade holds, ACL/FUID/project quota propagation, mmap/page-cache coherency, and ZIL logging order.
