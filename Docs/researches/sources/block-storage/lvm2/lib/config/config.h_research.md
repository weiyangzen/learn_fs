# File Research: sources/block-storage/lvm2/lib/config/config.h

## Purpose

`config.h` is the public interface and shared type definition header for LVM2 configuration handling. It defines configuration source types, profile structures, config definition metadata, flags, validation handles, tree generation modes, and the accessor/loader/writer APIs implemented in `config.c`.

## Key Types

`config_source_t` identifies where a config tree came from:
- undefined;
- single file;
- merged files;
- command-line string;
- command profile;
- metadata profile;
- special-purpose file.

`struct profile` represents an LVM profile with a list node, source type, name, and loaded config tree.

`struct profile_params` tracks profile directories, global command/metadata profiles, pending profiles, loaded profiles, and shell-mode profile state.

`cfg_def_type_t` defines accepted configuration value types:
- section;
- array;
- boolean;
- integer;
- float;
- string.

`cfg_def_value_t` and `cfg_def_unconfigured_value_t` store static default values or function pointers for runtime defaults.

`cfg_def_item_t` is the central per-setting definition record. It stores:
- generated ID;
- parent ID;
- config node name;
- type mask;
- flags;
- introduction and deprecation versions;
- default value and unconfigured default;
- deprecation comment;
- normal comments and file preamble text.

`cfg_def_tree_t` describes generated config output modes:
- current, missing, full, default;
- new or new since a version;
- profilable subsets;
- diff;
- flat list.

`struct config_def_tree_spec` parameterizes generated config trees and output with command context, current tree, version filters, comment/version/list/value-only options, local-section filtering, and check status.

`struct cft_check_handle` stores validation context and result bits for every config definition item.

## Flags and Invariants

Definition flags control behavior such as:
- variable section names (`CFG_NAME_VARIABLE`);
- empty values (`CFG_ALLOW_EMPTY`);
- advanced or unsupported visibility;
- profile eligibility;
- metadata-profile eligibility;
- undefined or commented defaults;
- runtime default evaluation;
- disabled settings;
- octal integer formatting;
- disabling subtree validation;
- disallowing use in interactive mode.

Validation status flags are:
- `CFG_USED`: setting appeared in the checked tree;
- `CFG_VALID`: setting was valid;
- `CFG_DIFF`: setting differs from default.

`vsn()` packs LVM versions into 16 bits using 3 bits major, 4 bits minor, and 9 bits patchlevel. The comment notes a maximum representable version of 7.15.511.

## Generated IDs

The config ID enum is generated by including `config_settings.h` with macros that emit only IDs. `CFG_COUNT` is therefore generated as the sentinel final entry and sizes arrays such as validation status.

This makes the declaration order in `config_settings.h` ABI-like inside the config subsystem: IDs, default table indexes, validation status indexes, and lookup helpers all depend on the same order.

Profile management:
- `add_profile()`
- `load_profile()`
- `load_pending_profiles()`

Validation:

File and tree lifecycle:
- `config_open()`

- `config_file_read_from_file()`

- `config_write()`
- `config_def_create_tree()`

## Dependencies

The header depends on:
- `libdm/libdevmapper.h` for config tree, config node/value, memory pool, and list types;
- `lib/device/device.h` for device-backed config reads;
- `config_settings.h` for generated IDs.

## Risk and Maintenance Notes

- Adding a new runtime config item requires a matching `get_default_<id>` declaration/definition unless it is macro-defined as `NULL`.
- Changing `CFG_PATH_MAX_LEN` or the path-generation model affects validation and output.
- Profile flags are security/behavior boundaries: settings not marked profilable are rejected in profiles.
- The `CFG_PROFILABLE_METADATA` value intentionally includes `CFG_PROFILABLE`; code depends on this bit composition.
