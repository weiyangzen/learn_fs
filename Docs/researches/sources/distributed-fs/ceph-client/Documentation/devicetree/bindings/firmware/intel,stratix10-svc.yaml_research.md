# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/firmware/intel,stratix10-svc.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Intel Service Layer Driver for Stratix10 SoC`. In this tree it is a firmware interface binding used to describe secure monitor, system controller, mailbox, or service-layer communication with platform firmware; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Intel Stratix10 SoC is composed of a 64 bit quad-core ARM Cortex A53 hard processor system (HPS) and Secure Device Manager (SDM). When the FPGA is configured from HPS, there needs to be a way for HPS to notify SDM the location and size of the configuration data. **Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/firmware/intel,stratix10-svc.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `intel,stratix10-svc`, `intel,agilex-svc`, `intel,agilex5-svc`. Required properties are `compatible`, `method`, `memory-region`. Important properties include `compatible`, `method`, `memory-region`, `iommus`, `fpga-mgr`. Referenced schemas are `/schemas/types.yaml#/definitions/string-array`, `/schemas/fpga/intel,stratix10-soc-fpga-mgr.yaml`. Property roles include `compatible` for driver match key and hardware ABI identifier; `method` for firmware call transport selection; `memory-region` for reserved-memory phandles; `iommus` for IOMMU stream mapping. The top-level closure rule is `additionalProperties: false`. Maintainers: Dinh Nguyen <dinguyen@kernel.org>, Mahesh Rao <mahesh.rao@altera.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/string-array`, `/schemas/fpga/intel,stratix10-soc-fpga-mgr.yaml`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as IOMMU stream bindings, reserved-memory carveouts, FPGA manager child binding. Conditional/schema-composition points include `allOf`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `method`, `fpga-mgr`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with firmware, mailbox, shared-memory, secure-monitor, system-controller, clock, reset, power, and FPGA manager drivers. Direct schema dependencies are `/schemas/types.yaml#/definitions/string-array`, `/schemas/fpga/intel,stratix10-soc-fpga-mgr.yaml`; resource dependencies visible in the property set include IOMMU stream bindings, reserved-memory carveouts, FPGA manager child binding. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
