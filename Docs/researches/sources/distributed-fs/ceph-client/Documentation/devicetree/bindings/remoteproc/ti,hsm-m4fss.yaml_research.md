# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/remoteproc/ti,hsm-m4fss.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/remoteproc/ti,hsm-m4fss.yaml` is a Linux devicetree YAML schema for the `TI K3 HSM M4F processor subsystems` remote processor subsystem binding. Some K3 family SoCs have a HSM (High Security Module) M4F core in the Wakeup Voltage Domain which could be used to run secure services like Authentication. Some of those are J721S2, J784S4, J722S, AM62X. It is not executable Ceph or kernel logic; it is a hardware-description ABI used by DTS authors, dt-schema, and Linux subsystem drivers so that board descriptions match what the driver will parse at probe or early boot.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses `enum` list and covers 1 compatible token: `ti,hsm-m4fss`. Top-level properties are `compatible`, `reg`, `reg-names`, `resets`, `firmware-name`. Across nested schemas and child nodes this file mentions 5 distinct property names; required properties observed at all levels include `compatible`, `firmware-name`, `reg`, `reg-names`, `resets`, `ti,sci`, `ti,sci-dev-id`, `ti,sci-proc-ids`. Node naming is constrained by no explicit node-name constraint. Remoteproc-facing properties define firmware loading and processor-control resources: address ranges `reg`, `reg-names`, memory-carveout links `reg`, mailbox/interrupt/IPC hooks `firmware-name`, and clock/reset/power controls `resets`. Required properties are `compatible`, `reg`, `reg-names`, `resets`, `firmware-name`, `ti,sci`, `ti,sci-dev-id`, `ti,sci-proc-ids`; these values are consumed by Linux remoteproc drivers before firmware boot, crash handling, and virtio/rpmsg setup.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation. `dt-doc-validate`, `dt_binding_check`, and `dtbs_check` load the YAML, expand `$ref` links, match nodes by `compatible` or referenced common-schema use, enforce required properties, evaluate composition/conditional keywords, and validate inline DTS examples. At runtime, platform bus probing hands the validated node to a remoteproc driver, which maps resources, obtains clocks/resets/power domains, reserves memory, starts firmware, and may expose rpmsg/virtio endpoints. The YAML itself stores no mutable runtime state and writes no persistent data; persistence is the source-controlled devicetree ABI and the DTB blobs built from DTS. External references used in evaluation are `/schemas/arm/keystone/ti,k3-sci-common.yaml#`; schema composition/conditional keywords present are none.

## Risks
Risks are ABI and integration risks. Changing compatible ordering, required keys, resource names, child-node patterns, cell counts, or strictness can reject existing DTS files or let invalid hardware descriptions reach runtime probe. This schema has 5 top-level properties, 5 distinct property names across nested schemas, and this strictness profile: composition is closed with `unevaluatedProperties: false`.
