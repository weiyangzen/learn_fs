# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/fsl,imx8mq-dwc3.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/fsl,imx8mq-dwc3.yaml` defines `NXP iMX8MQ Soc USB Controller`, a Synopsys DesignWare USB3 glue-controller binding. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Important APIs, Types, and Functions
The exported API is the Devicetree node contract. `$id` is `http://devicetree.org/schemas/usb/fsl,imx8mq-dwc3.yaml#` and `$schema` is `http://devicetree.org/meta-schemas/core.yaml#`. `compatible` uses ordered fallback `items` sequence and exposes 2 compatible tokens: `fsl,imx8mq-dwc3`, `snps,dwc3`. Top-level properties are `compatible`. Top-level required properties are none declared; required properties discovered in nested branches are `compatible`. Patterned child schemas are none; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry. Across the full schema there are 1 distinct property name and collected const/enum/min/max/item signals include `enum=[fsl,imx8mq-dwc3]`, `const=fsl,imx8mq-dwc3`, `const=snps,dwc3`.

## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (`select`, `allOf`); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: DWC3 core mode, xHCI/gadget state, runtime PM, event buffers, PHY power, role switching, wakeup state, and glue-register setup. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around glue compatible order, wrapper and core register ranges, child-node layout, clock/reset naming, PHY linkage, DRD role properties, and SoC-specific conditionals; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile closes composed schemas with `unevaluatedProperties: false`.
