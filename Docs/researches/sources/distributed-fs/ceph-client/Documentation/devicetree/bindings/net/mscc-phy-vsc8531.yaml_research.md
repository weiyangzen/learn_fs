# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/mscc-phy-vsc8531.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/mscc-phy-vsc8531.yaml` defines the Linux Devicetree YAML schema for `Microsemi VSC8531 Gigabit Ethernet PHY`, a Ethernet PHY binding. The schema description says: The VSC8531 is a Gigabit Ethernet PHY with configurable MAC interface drive strength and LED modes. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an ordered fallback `items` sequence with 3 tokens: `ethernet-phy-id0007.0570`, `ethernet-phy-id0007.0772`, `ethernet-phy-ieee802.3-c22`. Top-level properties are `compatible`, `vsc8531,vddmac`, `vsc8531,edge-slowdown`, `vsc8531,led-0-mode`, `vsc8531,led-1-mode`, `vsc8531,led-2-mode`, `vsc8531,led-3-mode`, `load-save-gpios`. Top-level required properties are `compatible`, `reg`; required properties collected from nested branches include `compatible`, `reg`. Patterned child schemas are none. Numeric and collection constraints include `minimum=0`, `maximum=15`, `maxItems=1`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `load-save-gpios` describes board GPIO control/status wiring. The highest-risk ABI details are PHY `reg` addresses, compatible fallbacks, reset/interrupt timing, RGMII delays, LED definitions, package topology, and vendor tuning flags.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, `dependencies`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including PHY link autonegotiation, EEE, cable diagnostics, interrupt state, reset state, per-port LEDs, and package shared state.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema closes composed schemas with `unevaluatedProperties: false`. It has 8 top-level properties and 8 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.
