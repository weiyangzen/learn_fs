# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dpll/dpll-pin.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `DPLL Pin`. In this tree it is a digital phase-locked loop binding used to describe DPLL devices, pins, references, and frequency capabilities; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: The DPLL pin is either a physical input or output pin that is provided by a DPLL( Digital Phase-Locked Loop) device. The pin is identified by its physical order number that is stored in reg property and can have an additional set of properties like supported (allowed) frequencies, label, type and may support embedded sync. **Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/dpll/dpll-pin.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are none declared. Required properties are `reg`. Important properties include `reg`, `connection-type`, `esync-control`, `label`, `ref-sync-sources`, `supported-frequencies-hz`. Referenced schemas are `/schemas/types.yaml#/definitions/string`, `/schemas/types.yaml#/definitions/phandle-array`. Property roles include `reg` for MMIO, I2C/SPI address, or child register address. The top-level closure rule is `additionalProperties: false`. Maintainers: Ivan Vecera <ivecera@redhat.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/string`, `/schemas/types.yaml#/definitions/phandle-array`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as platform driver `of_match_table` binding through the compatible string. It has no nested conditional schema branches beyond direct property validation. Nested or patterned child schema surfaces include `connection-type`, `label`, `ref-sync-sources`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with DPLL framework consumers and board clocking descriptions. Direct schema dependencies are `/schemas/types.yaml#/definitions/string`, `/schemas/types.yaml#/definitions/phandle-array`; resource dependencies visible in the property set include platform driver `of_match_table` binding through the compatible string. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
