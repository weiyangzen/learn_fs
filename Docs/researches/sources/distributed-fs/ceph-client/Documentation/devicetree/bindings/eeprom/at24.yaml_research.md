# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/eeprom/at24.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `I2C EEPROMs compatible with Atmel's AT24`. In this tree it is a EEPROM or FRAM/NVMEM binding used by nonvolatile memory drivers and NVMEM cell consumers; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/eeprom/at24.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `rohm,br24g01`, `rohm,br24t01`, `atmel,24c01`, `nxp,se97b`, `renesas,r1ex24002`, `atmel,24c02`, `belling,bl24c04a`, `giantec,gt24c04a`, `onnn,cat24c04`, `onnn,cat24c05`, `rohm,br24g04`, `atmel,24c04`, and 23 more. Required properties are `compatible`, `reg`. Important properties include `$nodename`, `compatible`, `label`, `reg`, `pagesize`, `read-only`, `size`, `no-read-rollover`, `wp-gpios`, `address-width`, `num-addresses`, `vcc-supply`. Referenced schemas are `/schemas/nvmem/nvmem.yaml`, `/schemas/nvmem/nvmem-deprecated-cells.yaml`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/flag`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `wp-gpios` for write-protect GPIO; `vcc-supply` for regulator supply dependency. The top-level closure rule is `unevaluatedProperties: false`. Maintainers: Bartosz Golaszewski <bgolaszewski@baylibre.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/nvmem/nvmem.yaml`, `/schemas/nvmem/nvmem-deprecated-cells.yaml`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/flag`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as platform driver `of_match_table` binding through the compatible string. Conditional/schema-composition points include `allOf`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `pagesize`, `read-only`, `size`, `no-read-rollover`, `address-width`, `num-addresses`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with I2C/SPI EEPROM, FRAM, NVMEM, regulator, and GPIO consumers. Direct schema dependencies are `/schemas/nvmem/nvmem.yaml`, `/schemas/nvmem/nvmem-deprecated-cells.yaml`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/flag`; resource dependencies visible in the property set include platform driver `of_match_table` binding through the compatible string. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `unevaluatedProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/eeprom/at24.yaml` and `make dtbs_check` against DTS users of every compatible family. Verify inline examples compile, required-property failures are reported, compatible-specific branches are exercised, inherited schemas resolve, and drivers still probe with the resources described here. The file includes 1 example block(s), which are part of the dt-schema validation signal.
