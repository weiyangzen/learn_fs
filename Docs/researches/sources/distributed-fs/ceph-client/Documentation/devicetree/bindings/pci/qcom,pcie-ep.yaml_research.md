# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/qcom,pcie-ep.yaml

**Purpose:** Defines the Devicetree YAML/JSON-schema contract for `Qualcomm PCIe Endpoint Controller`. It is a endpoint controller or endpoint-bus binding in the Qualcomm DesignWare-derived PCIe host/endpoint family; it constrains how DTS/DTB nodes identify the PCI hardware, describe register windows, interrupts, clocks, resets, PHYs, address translation, DMA/IOMMU reachability, and optional child/root-port layout for Linux PCI probing.

**Important APIs/types/functions:** This file is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/pci/qcom,pcie-ep.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, the `properties` block, `required` list, schema-composition keywords, inline examples, and the compatible strings consumed by kernel OF match tables. Compatible strings covered here: `qcom,sa8775p-pcie-ep`, `qcom,sar2130p-pcie-ep`, `qcom,sdx55-pcie-ep`, `qcom,sdx65-pcie-ep`, `qcom,sm8450-pcie-ep`. Directly declared properties are `compatible`, `reg`, `reg-names`, `clocks`, `clock-names`, `qcom,perst-regs`, `interrupts`, `interrupt-names`, `iommus`, `reset-gpios`, `wake-gpios`, `interconnects`, `interconnect-names`, `dma-coherent`, `resets`, `reset-names`, `power-domains`, `phys`, `phy-names`, `num-lanes`. Required properties are `compatible`, `reg`, `reg-names`, `clocks`, `clock-names`, `interrupts`, `interrupt-names`, `reset-gpios`, `interconnects`, `interconnect-names`, `resets`, `reset-names`, `power-domains`. Maintainers: Manivannan Sadhasivam <mani@kernel.org>.

**Control flow:** Validation flow is handled by dt-schema: the core meta-schema loads this YAML, resolves references (`/schemas/types.yaml#/definitions/phandle-array`, `pci-ep.yaml#`), applies direct property constraints, evaluates top-level `allOf` composition, and then applies conditional branches. Conditional behavior: for qcom,sar2130p-pcie-ep, adds/restricts property cardinalities/names; for qcom,sdx55-pcie-ep, adds/restricts property cardinalities/names and has an else branch; for qcom,sdx55-pcie-ep, adds/restricts property cardinalities/names; for qcom,sm8450-pcie-ep, adds/restricts property cardinalities/names; for qcom,sa8775p-pcie-ep, adds/restricts property cardinalities/names. At runtime the compiled DTB has no code from this file; the kernel matches `compatible`, maps `reg` resources, programs PCI ranges, requests interrupts/MSI mappings, enables clocks/resets/regulators/PHYs/power domains, and creates host bridge/root-port or endpoint objects according to the described node.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability for board DTS files and shipped DTBs: compatible ordering, resource names, cell counts, interrupt maps, address ranges, and child-node layout become the long-lived contract that drivers and firmware rely on. For this file, the top-level and composed unknown-property policy is: unevaluatedProperties: false.

**Dependencies:** Direct schema dependencies are `/schemas/types.yaml#/definitions/phandle-array`, `pci-ep.yaml#`. Resource dependencies visible in the binding include `compatible` (driver OF match key and binding ABI identifier); `reg` (MMIO/config/address-space resource tuples); `reg-names` (stable names used by drivers to request register windows); `clocks` (clock provider phandles); `clock-names` (stable clock input names); `interrupts` (controller, MSI, PME, AER, DMA, or legacy interrupt inputs); `interrupt-names` (stable interrupt resource names); `iommus` (direct IOMMU attachment); `reset-gpios` (PERST# or device reset GPIO); `wake-gpios` (WAKE# GPIO); `dma-coherent` (coherency attribute for DMA transactions); `resets` (reset-controller phandles); `reset-names` (stable reset line names); `power-domains` (genpd domain phandles); `phys` (PHY phandles for PCIe lanes); `phy-names` (stable PHY names); `num-lanes` (link width constraint) The binding also depends on the broader Devicetree PCI schemas, dt-schema tooling, and matching Linux PCI host/endpoint drivers for the compatible strings above.

**Integration points:** Integrates with Linux OF platform matching through `compatible`, PCI core setup through `device_type`, `bus-range`, `ranges`, `dma-ranges`, `#address-cells`, and `#size-cells`, interrupt infrastructure through `interrupt-map`, `interrupts`, MSI controllers or `msi-map`, and SoC resource managers through clocks, resets, PHY, regulator, power-domain, and IOMMU properties. Nested integration surface: no nested child schema declared directly.

**Risks:** Main risks are ABI drift in required properties, accepting a DTS shape that the driver cannot probe, rejecting valid legacy boards, stale examples, wrong `reg-names`/`clock-names`/`reset-names` ordering, incomplete compatible coverage, and conditional branches whose `contains`/`enum` logic does not match real fallback-compatible ordering. PCI-specific risk is high around address translation and interrupts: bad `ranges`, `dma-ranges`, `iommu-map`, `msi-map`, or `interrupt-map-mask` can validate syntactically while producing unprobeable devices or broken DMA/MSI at runtime.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/qcom,pcie-ep.yaml` to validate this schema and its 1 inline example block(s). Run `make dtbs_check` for DTS users of each compatible string to exercise conditional branches, referenced schemas, child-node validation, closure policy, and resource-name ordering. Runtime smoke signals are successful PCI host bridge or endpoint probe, enumerated downstream devices/functions, working INTx/MSI/MSI-X, correct DMA/IOMMU mappings, and no missing-clock/reset/PHY/regulator errors in boot logs.
