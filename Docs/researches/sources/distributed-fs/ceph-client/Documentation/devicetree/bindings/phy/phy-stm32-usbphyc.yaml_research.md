# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/phy/phy-stm32-usbphyc.yaml

**Purpose:** `sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/phy/phy-stm32-usbphyc.yaml` is a Linux Devicetree YAML schema for `STMicroelectronics STM32 USB HS PHY controller`, a USB PHY or USB dual-role PHY binding. The STM32 USBPHYC block contains a dual port High Speed UTMI+ PHY and a UTMI switch. It controls PHY configuration and status, and the UTMI+ switch that selects either OTG or HOST controller for the second PHY port. It also sets PLL configuration. USBPHYC |_ PLL | |_ PHY port#1 _________________ HOST controller | __ | | / 1|________________| |_ PHY port#2 ----| |________________ | \_0| | |_ UTMI switch_______| OTG controller It is declarative firmware ABI documentation and dt-schema validation input, not executable kernel code. Its role is to make board DTS/DTB nodes describe PHY blocks, lanes, pads, ports, supplies, clocks, resets, and phandle provider contracts in the form the matching Linux PHY or controller driver expects.

**Important APIs/types/functions:** The exported API is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `patternProperties`, local definitions, `required`, examples, and composition constraints. `compatible` uses single `const` and covers 1 compatible token: `st,stm32mp1-usbphyc`. Top-level properties are `compatible`, `reg`, `clocks`, `resets`, `#address-cells`, `#size-cells`, `vdda1v1-supply`, `vdda1v8-supply`, `#clock-cells`, `access-controllers`. Top-level required properties are `compatible`, `reg`, `clocks`, `#address-cells`, `#size-cells`, `vdda1v1-supply`, `vdda1v8-supply`, `usb-phy@0`, `usb-phy@1`; required properties discovered across nested schemas include `#address-cells`, `#phy-cells`, `#size-cells`, `clocks`, `compatible`, `phy-supply`, `reg`, `usb-phy@0`, `usb-phy@1`, `vdda1v1-supply`, `vdda1v8-supply`. The binding acts as a parent provider with addressable child PHY/lane nodes. Provider/cell contracts are `#address-cells=const 1`, `#size-cells=const 0`, `#clock-cells=const 0`, `#phy-cells=enum [0, 1]`, `#phy-cells=const 0`, `#phy-cells=const 1`. Important property roles: `compatible` selects the OF match table entry and stable hardware ABI; `reg` carries MMIO ranges, syscon offsets, port numbers, or bus addresses; `clocks` binds reference, pipe, APB, PLL, or tracking clocks; `resets` models reset controller lines; `#address-cells` enables addressable child PHY, lane, or port nodes; `#size-cells` enables addressable child PHY, lane, or port nodes; `vdda1v1-supply` links analog/digital rails to regulator providers; `vdda1v8-supply` links analog/digital rails to regulator providers. Patterned child schemas are `^usb-phy@[0|1]$`; nested topology or child names discovered from properties are no explicit nested pad/lane/port names discovered. Local reusable definitions are none. Numeric/item constraints include `maxItems=1`, `minItems=1`, `maxItems=2`, `minimum=0`, `maximum=3`, `maximum=15`; selected enum/const literals include `st,stm32mp1-usbphyc`, `1`, `0`, `1000`, `2000`.

**Control flow:** Control flow is dt-schema evaluation. `dt_binding_check` parses the YAML, validates it against the core meta-schema, resolves `$ref` dependencies, applies `properties` and `patternProperties`, evaluates `allOf`/`oneOf`/`anyOf`/conditional branches, checks `required` lists and item counts, compiles examples, and enforces the closure rule. At boot the YAML is not interpreted; firmware supplies a compiled DTB node, the kernel matches `compatible` in the relevant OF table, and the PHY/provider driver reads `reg`, clocks, resets, supplies, child lanes/ports, and `#phy-cells` to register PHYs. Consumer controllers later resolve `phys` phandles and invoke the generic PHY framework for init, power-on, mode setting, calibration, and power-off.

**State and persistence behavior:** The file stores no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, valid enum values, provider cell counts, child-node naming, lane or port numbering, and allowed topology. Runtime state such as PLL lock, link training, lane muxing, PHY mode, impedance tuning, analog calibration, reset sequencing, and power transitions lives in the matching kernel driver and hardware registers; this schema only constrains how those resources and modes are represented in firmware.

Integration points are Devicetree common schemas, the Linux generic PHY framework, controller bindings that consume `phys`/`phy-names`, platform/MMIO or syscon buses, regulator supplies, reset controllers, clock providers, GPIO descriptors, power domains, and SoC-specific lane mux drivers. Compatible scan signals found driver-side files: `sources/distributed-fs/ceph-client/drivers/phy/st/phy-stm32-usbphyc.c`. In-tree DTS scan signals found board users: `sources/distributed-fs/ceph-client/arch/arm/boot/dts/st/stm32mp131.dtsi`, `sources/distributed-fs/ceph-client/arch/arm/boot/dts/st/stm32mp151.dtsi`. The file includes 1 example block for validation.

**Risks:** Primary risks are PHY ABI drift and resource lookup mismatch. Removing or reordering compatible fallbacks can break legacy DTBs; changing `#phy-cells`, child `reg` numbering, lane names, or port names can break consumers that already reference the provider; renaming clocks, resets, supplies, GPIOs, or power domains can break driver probe even when the hardware block is unchanged. Multi-protocol SerDes and pad-controller schemas are especially sensitive because lane mux enums, protocol names, and companion USB2/USB3 or PCIe/SATA relationships must align with driver tables and board wiring. The closure profile is: top-level unknown properties are rejected by `additionalProperties: false`. Because this schema has 10 top-level properties and 28 distinct nested property names, broad edits should be checked against every compatible variant, examples, and existing DTS users.

**Test signals:** Primary validation signals are `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/phy/phy-stm32-usbphyc.yaml` in a kernel tree with dt-schema installed and `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/phy/phy-stm32-usbphyc.yaml` for boards using these compatibles. Useful negative checks omit required clocks/resets/supplies, use invalid `#phy-cells`, bad child-node names, wrong lane `reg` values, or unsupported enum values. Runtime integration signals are successful driver probe, registered PHY providers with expected phandle arguments, consumers resolving `phys`, clocks and regulators balanced across suspend/resume, link bring-up for the relevant USB/PCIe/SATA/UFS/MIPI/SerDes protocol, and no new schema warnings for examples or in-tree DTS files.
