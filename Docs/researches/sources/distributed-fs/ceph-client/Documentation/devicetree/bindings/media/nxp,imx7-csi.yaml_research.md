# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/nxp,imx7-csi.yaml

**Purpose:** Defines the Devicetree JSON-schema ABI for `i.MX7 and i.MX8 CSI bridge (CMOS Sensor Interface)`. It is a camera capture interface media graph binding in the Ceph client Linux source snapshot, constraining how board DTS/DTB files describe media hardware so Linux media, V4L2 mem2mem, platform, clock, reset, power-domain, IOMMU, and graph helpers can bind the correct driver resources. The source description says: This is device node for the CMOS Sensor Interface (CSI) which enables the chip to connect directly to external CMOS image sensors.

**Important APIs/types/functions:** This is declarative schema, so the exported API is the binding contract rather than C functions. Public surfaces include `$id` `http://devicetree.org/schemas/media/nxp,imx7-csi.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, examples, and dt-schema references. The `compatible` property uses `oneOf` with 2 accepted forms and accepts `fsl,imx8mq-csi`, `fsl,imx7-csi`, `fsl,imx6ul-csi`, `fsl,imx8mm-csi`. Top-level required properties are `compatible`, `reg`, `interrupts`, `clocks`, `clock-names`, `port`; required names across nested/conditional schemas include `clock-names`, `clocks`, `compatible`, `interrupts`, `port`, `power-domains`, `reg`. Top-level properties are `compatible`, `reg`, `interrupts`, `clocks`, `clock-names`, `power-domains`, `port`; all nested property names include `clock-names`, `clocks`, `compatible`, `interrupts`, `port`, `power-domains`, `reg`. Resource constraints visible in the schema include `compatible`, `reg` (maxItems=1), `interrupts` (maxItems=1), `clocks` (maxItems=1), `clock-names` (names=mclk), `power-domains` (maxItems=1), `port`. Closure is `additionalProperties: False`.

**Control flow:** Runtime control flow is supplied by dt-schema and kernel probing. `dt_binding_check` loads the core meta-schema, resolves references, validates the compatible form, applies required lists and `minItems`/`maxItems`/`const` restrictions, evaluates conditionals, and compiles the inline examples. At boot the DTB node is matched by `compatible`; the platform or media driver then reads MMIO ranges, named interrupts, clocks, resets, power domains, IOMMU streams, DMA/interconnect paths, firmware or reserved-memory phandles, and graph endpoints. Schema composition uses `allOf`, `if`, `oneOf`, `then`. Validation can therefore change by compatible string, for example by tightening clock/reset counts, requiring SoC-specific helper phandles, or allowing/deprecating child codec nodes. Media graph integration is explicit through `port`; the schema references graph/video interface rules and mentions `endpoint` 2 time(s). Endpoint validation covers remote links, lane descriptions, bus type, bus width, and synchronization/pixel-clock polarity where the hardware exposes those signals.

**State and persistence behavior:** The file stores no mutable runtime state and performs no persistence itself. Its persistent effect is ABI stability for DTS files and shipped DTBs: compatible strings, child-node names, phandle relationships, address ranges, cell counts, and media graph topology are long-lived hardware descriptions. Any change to required properties, resource ordering, child object schemas, or unknown-property policy can invalidate existing board descriptions even though no kernel state is written by the YAML.

**Dependencies and integration points:** Direct schema references are `/schemas/graph.yaml#/properties/port`. Runtime dependencies are V4L2 async/media-controller graph links through `ports`, `port`, and `endpoint` nodes, genpd power domains, clock provider phandles and fixed clock-name ordering. No nested object nodes are defined beyond common schema references. Maintainers listed in the binding are `Rui Miguel Silva <rmfrfs@gmail.com>`.

**Risks:** Key risks: compatible-string or fallback-order drift can break OF matching and dtbs_check expectations; resource array ordering is ABI-sensitive for `reg-names`, `clock-names`, `interrupt-names`, `power-domain-names`, and `reset-names`; media graph mistakes in `remote-endpoint`, lane numbering, bus type, or required ports can leave cameras disconnected even when the platform device probes; SoC-specific power-domain count differences are easy to regress in fallback compatibles. The closure policy is `additionalProperties: False`, so unknown properties are intentionally rejected after referenced schemas are evaluated.

Run `make dtbs_check` against DTS users of `fsl,imx8mq-csi`, `fsl,imx7-csi`, `fsl,imx6ul-csi`, `fsl,imx8mm-csi` to exercise compatible-specific branches, graph endpoint requirements, resource counts, and referenced schemas. Useful negative tests remove required properties such as `compatible`, `reg`, `interrupts`, `clocks`, `clock-names`, `port`, alter named resource ordering, exceed item counts, and inject unknown properties to confirm the closure rule catches mistakes.
