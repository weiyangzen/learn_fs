# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/loongson,ls1c-emac.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/loongson,ls1c-emac.yaml` defines the Linux Devicetree YAML schema for `Loongson-1C Ethernet MAC Controller`, a Ethernet MAC/controller binding. The schema description says: Loongson-1C Ethernet MAC Controller is based on Synopsys DesignWare MAC (version 3.50a). Main features - 10/100Mbps - Full-duplex operation (IEEE 802.3x flow control automatic transmission) - Half-duplex operation (CSMA/CD Protocol and back-pressure support) - IEEE 802.1Q VLAN tag detection for reception frames - MII interface - RMII interface It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an ordered fallback `items` sequence with 2 tokens: `loongson,ls1c-emac`, `snps,dwmac-3.50a`. Top-level properties are `compatible`, `reg`, `clocks`, `clock-names`, `interrupts`, `interrupt-names`, `loongson,ls1-syscon`, `phy-mode`. Top-level required properties are `compatible`, `reg`, `clocks`, `clock-names`, `interrupts`, `interrupt-names`, `loongson,ls1-syscon`; required properties collected from nested branches include `clock-names`, `clocks`, `compatible`, `interrupt-names`, `interrupts`, `loongson,ls1-syscon`, `reg`. Patterned child schemas are none. Numeric and collection constraints include `maxItems=1`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, MDIO child addresses, SPI/I2C addresses, or port selectors; `clocks` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `clock-names` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `interrupts` routes link/status, RX/TX, error, or management IRQs; `interrupt-names` routes link/status, RX/TX, error, or management IRQs; `phy-mode` connects the MAC/switch port to PHY, PCS, SFP, or fixed-link infrastructure. The highest-risk ABI details are compatible fallback ordering, register/interrupt ordering, clock/reset names, DMA/coherency flags, PHY or fixed-link connection modelling, and vendor resource properties.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including netdev registration, DMA rings, NAPI scheduling, runtime PM, link mode negotiation through phylink/phylib, MAC address assignment, and PTP/TSN state where supported.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema closes composed schemas with `unevaluatedProperties: false`. It has 8 top-level properties and 8 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.
