# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/ti,pruss-intc.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `TI PRU-ICSS Local Interrupt Controller`. In this tree it is an interrupt controller binding: it constrains how board DTS files describe the hardware block, what phandle provider/client ABI is exposed, and how Linux discovers the device through OF matching and common DT resource helpers. The source description says: Each PRU-ICSS has a single interrupt controller instance that is common to all the PRU cores. Most interrupt controllers can route 64 input events which are then mapped to 10 possible output interrupts through two levels of mapping. The input events can be triggered by either the PRUs and/or various other PRUSS internal and external peripherals. The first 2 output interrupts (0, 1) are fed exclusively to the internal PRU cores, with the remaining 8 (2 through 9) connected to external interrupt controllers including the MPU and/or other PRUSS instances, DSPs or devices. The property "ti,irqs-reserved" is used for denoting the connection differences on the output interrupts 2 through 9. If this property is not defined, it implies that all the PRUSS INTC output interrupts 2 through 9 (host_intr0 through host_intr7) are connected exclusively to the Arm interrupt controller. The K3 family of SoCs can handle 160 input events that can be mapped to 20 different possible output interrupts. The additional output interrupts (10 through 19) are connected to new sub-modules within the ICSSG instances. This interrupt-controller node should be defined as a child node of the corresponding PRUSS node. The node should be named "interrupt-controller".

**Important APIs/types/functions:** This YAML is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/interrupt-controller/ti,pruss-intc.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and any referenced dt-schema fragments. Compatible strings or compatible-pattern values are `ti,pruss-intc`, `ti,icssg-intc`. Required properties are `compatible`, `reg`, `interrupts`, `interrupt-names`, `interrupt-controller`, `#interrupt-cells`. Important top-level properties are `$nodename`, `compatible`, `reg`, `interrupts`, `interrupt-names`, `interrupt-controller`, `#interrupt-cells`, `ti,irqs-reserved`. Direct and nested `$ref` dependencies are `/schemas/types.yaml#/definitions/uint8`. Property roles include `$nodename` for binding-specific property constrained by the schema; `compatible` for driver match key and stable hardware ABI identifier; `reg` for MMIO range, bus address, or child register selector; `interrupts` for interrupt parent specifier array for wired IRQ inputs or outputs; `interrupt-names` for semantic labels for interrupt lines; `interrupt-controller` marks the node as an interrupt domain provider; `#interrupt-cells` for interrupt specifier cell count consumed by child/client nodes; `ti,irqs-reserved` for binding-specific property constrained by the schema. The top-level unknown-property policy is `additionalProperties: false`. Maintainers are `Suman Anna <s-anna@ti.com>`.

**Control flow:** Runtime control flow is supplied by dt-schema tooling and the kernel subsystem that consumes the resulting DTB. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, `required`, enum/const/items limits, and composition keywords, then validates the examples. At boot, a DT node satisfying this schema is matched by `compatible`; resource helpers read `reg`, clocks, resets, power domains, interrupts, MSI/IOMMU cells, and child nodes; then the relevant IRQ-domain, MSI-domain, or IOMMU driver registers provider state for clients. The file has no nested conditional schema composition beyond direct property validation. It does not define nested child-node schemas.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, register layout, interrupt or translation-domain topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though the YAML itself stores no kernel state.

**Dependencies and integration points:** Linux IRQ domain code uses it to translate DT interrupt specifiers into Linux IRQs and route them to an upstream parent domain. Schema-level dependencies are the core Devicetree meta-schema plus the `$ref` targets listed above. Resource integration is through properties such as `reg`, `interrupts`. Driver integration is through `compatible`; provider/client integration is through cell-count properties, phandle arrays, child schemas, and any common binding references inherited by dt-schema.

**Risks:** Main risks are Devicetree ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, overly broad or overly strict conditional branches, missing required clocks/resets/interrupt parents/power domains, and stale examples. Closure policy matters because false unknown-property settings catch misspellings but can reject legitimate board extensions. For interrupt/MSI/IOMMU providers, incorrect parent-domain links or specifier widths can pass schema validation yet fail at boot with lost interrupts, bad affinity, MSI allocation failure, or DMA translation faults.
