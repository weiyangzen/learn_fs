# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dsp/fsl,dsp.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `NXP i.MX8 DSP core`. In this tree it is a DSP remote processor binding used to describe DSP cores, firmware, mailboxes, memory regions, clocks, resets, and power domains; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Some boards from i.MX8 family contain a DSP core used for advanced pre- and post- audio processing.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/dsp/fsl,dsp.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `fsl,imx8qxp-dsp`, `fsl,imx8qm-dsp`, `fsl,imx8mp-dsp`, `fsl,imx8ulp-dsp`, `fsl,imx8qxp-hifi4`, `fsl,imx8qm-hifi4`, `fsl,imx8mp-hifi4`, `fsl,imx8ulp-hifi4`. Required properties are `compatible`, `reg`, `clocks`, `clock-names`, `power-domains`, `mboxes`, `mbox-names`, `memory-region`. Important properties include `compatible`, `reg`, `clocks`, `clock-names`, `power-domains`, `mboxes`, `mbox-names`, `memory-region`, `firmware-name`, `fsl,dsp-ctrl`, `resets`, `reset-names`, `access-controllers`. Referenced schemas are `/schemas/types.yaml#/definitions/phandle`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `clocks` for clock provider phandles; `clock-names` for clock input names; `power-domains` for power-domain attachment; `mboxes` for mailbox channels; `mbox-names` for mailbox channel names; `memory-region` for reserved-memory phandles; `resets` for reset controller phandles; `reset-names` for reset line names. The top-level closure rule is `additionalProperties: false`. Maintainers: Daniel Baluta <daniel.baluta@nxp.com>, Shengjiu Wang <shengjiu.wang@nxp.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/phandle`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as clock provider phandles, reset controller phandles, genpd power domains, mailbox channels, reserved-memory carveouts. Conditional/schema-composition points include `allOf`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `fsl,dsp-ctrl`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with remoteproc, mailbox, reserved-memory, clock, reset, and power-domain drivers. Direct schema dependencies are `/schemas/types.yaml#/definitions/phandle`; resource dependencies visible in the property set include clock provider phandles, reset controller phandles, genpd power domains, mailbox channels, reserved-memory carveouts. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dsp/fsl,dsp.yaml` and `make dtbs_check` against DTS users of every compatible family. Verify inline examples compile, required-property failures are reported, compatible-specific branches are exercised, inherited schemas resolve, and drivers still probe with the resources described here.
