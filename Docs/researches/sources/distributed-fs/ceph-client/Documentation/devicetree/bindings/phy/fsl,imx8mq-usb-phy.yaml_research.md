# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/phy/fsl,imx8mq-usb-phy.yaml

**Purpose:** `sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/phy/fsl,imx8mq-usb-phy.yaml` is a Linux Devicetree YAML schema for `Freescale i.MX8MQ USB3 PHY`, a USB PHY or USB dual-role PHY binding. It is declarative firmware ABI documentation and dt-schema validation input, not executable kernel code. Its role is to make board DTS/DTB nodes describe PHY blocks, lanes, pads, ports, supplies, clocks, resets, and phandle provider contracts in the form the matching Linux PHY or controller driver expects.

**Important APIs/types/functions:** The exported API is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `patternProperties`, local definitions, `required`, examples, and composition constraints. `compatible` uses `oneOf` with 2 accepted compatible forms and covers 3 compatible tokens: `fsl,imx8mq-usb-phy`, `fsl,imx8mp-usb-phy`, `fsl,imx95-usb-phy`. Top-level properties are `compatible`, `reg`, `#phy-cells`, `clocks`, `clock-names`, `power-domains`, `vbus-supply`, `fsl,phy-tx-vref-tune-percent`, `fsl,phy-tx-rise-tune-percent`, `fsl,phy-tx-preemp-amp-tune-microamp`, `fsl,phy-tx-vboost-level-microvolt`, `fsl,phy-comp-dis-tune-percent`, `fsl,phy-pcs-tx-deemph-3p5db-attenuation-db`, `fsl,phy-pcs-tx-swing-full-percent`. Top-level required properties are `compatible`, `reg`, `#phy-cells`, `clocks`, `clock-names`; required properties discovered across nested schemas include `#phy-cells`, `clock-names`, `clocks`, `compatible`, `orientation-switch`, `reg`. The binding acts as a MMIO or bus-addressed PHY provider node. Provider/cell contracts are `#phy-cells=const 0`. Important property roles: `compatible` selects the OF match table entry and stable hardware ABI; `reg` carries MMIO ranges, syscon offsets, port numbers, or bus addresses; `#phy-cells` defines the phandle argument contract for PHY consumers; `clocks` binds reference, pipe, APB, PLL, or tracking clocks; `clock-names` binds reference, pipe, APB, PLL, or tracking clocks; `power-domains` links the PHY to runtime PM domain providers; `vbus-supply` links analog/digital rails to regulator providers. Patterned child schemas are none; nested topology or child names discovered from properties are no explicit nested pad/lane/port names discovered. Local reusable definitions are none. Numeric/item constraints include `minItems=1`, `maxItems=2`, `maxItems=1`, `minimum=90`, `maximum=124`, `maximum=120`, `minimum=0`, `maximum=1800`, `minimum=91`, `maximum=115`, `maximum=36`, `maximum=100`, `minimum=94`, `minimum=97`, `maximum=103`, `maximum=108`, `maximum=104`; selected enum/const literals include `fsl,imx8mq-usb-phy`, `fsl,imx8mp-usb-phy`, `fsl,imx95-usb-phy`, `0`, `phy`, `alt`, `844`, `1008`, `1156`.

**Control flow:** Control flow is dt-schema evaluation. `dt_binding_check` parses the YAML, validates it against the core meta-schema, resolves `$ref` dependencies, applies `properties` and `patternProperties`, evaluates `allOf`/`oneOf`/`anyOf`/conditional branches, checks `required` lists and item counts, compiles examples, and enforces the closure rule. At boot the YAML is not interpreted; firmware supplies a compiled DTB node, the kernel matches `compatible` in the relevant OF table, and the PHY/provider driver reads `reg`, clocks, resets, supplies, child lanes/ports, and `#phy-cells` to register PHYs. Consumer controllers later resolve `phys` phandles and invoke the generic PHY framework for init, power-on, mode setting, calibration, and power-off.

**State and persistence behavior:** The file stores no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, valid enum values, provider cell counts, child-node naming, lane or port numbering, and allowed topology. Runtime state such as PLL lock, link training, lane muxing, PHY mode, impedance tuning, analog calibration, reset sequencing, and power transitions lives in the matching kernel driver and hardware registers; this schema only constrains how those resources and modes are represented in firmware.

Top-level composition/conditional keys are `allOf`. Integration points are Devicetree common schemas, the Linux generic PHY framework, controller bindings that consume `phys`/`phy-names`, platform/MMIO or syscon buses, regulator supplies, reset controllers, clock providers, GPIO descriptors, power domains, and SoC-specific lane mux drivers. In-tree DTS scan signals found board users: `sources/distributed-fs/ceph-client/arch/arm64/boot/dts/freescale/imx8mp.dtsi`, `sources/distributed-fs/ceph-client/arch/arm64/boot/dts/freescale/imx8mq.dtsi`, `sources/distributed-fs/ceph-client/arch/arm64/boot/dts/freescale/imx94.dtsi`, `sources/distributed-fs/ceph-client/arch/arm64/boot/dts/freescale/imx95.dtsi`. The file includes 1 example block for validation.

**Risks:** Primary risks are PHY ABI drift and resource lookup mismatch. Removing or reordering compatible fallbacks can break legacy DTBs; changing `#phy-cells`, child `reg` numbering, lane names, or port names can break consumers that already reference the provider; renaming clocks, resets, supplies, GPIOs, or power domains can break driver probe even when the hardware block is unchanged. Multi-protocol SerDes and pad-controller schemas are especially sensitive because lane mux enums, protocol names, and companion USB2/USB3 or PCIe/SATA relationships must align with driver tables and board wiring. The closure profile is: composition is closed by `unevaluatedProperties: false`. Because this schema has 14 top-level properties and 14 distinct nested property names, broad edits should be checked against every compatible variant, examples, and existing DTS users.

**Test signals:** Primary validation signals are `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/phy/fsl,imx8mq-usb-phy.yaml` in a kernel tree with dt-schema installed and `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/phy/fsl,imx8mq-usb-phy.yaml` for boards using these compatibles. Useful negative checks omit required clocks/resets/supplies, use invalid `#phy-cells`, bad child-node names, wrong lane `reg` values, or unsupported enum values. Runtime integration signals are successful driver probe, registered PHY providers with expected phandle arguments, consumers resolving `phys`, clocks and regulators balanced across suspend/resume, link bring-up for the relevant USB/PCIe/SATA/UFS/MIPI/SerDes protocol, and no new schema warnings for examples or in-tree DTS files.
