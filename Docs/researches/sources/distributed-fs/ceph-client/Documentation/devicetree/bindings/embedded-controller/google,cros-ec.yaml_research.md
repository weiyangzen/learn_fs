# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/embedded-controller/google,cros-ec.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `ChromeOS Embedded Controller`. In this tree it is a embedded controller or board-management controller binding used to model management firmware and its child functions; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Google's ChromeOS EC is a microcontroller which talks to the AP and implements various functions such as keyboard and battery charging. The EC can be connected through various interfaces (I2C, SPI, and others) and the compatible string specifies which interface is being used.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/embedded-controller/google,cros-ec.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `google,cros-ec-i2c`, `google,cros-ec-spi`, `google,cros-ec-fp`, `google,cros-ec-rpmsg`, `google,cros-ec-uart`. Required properties are `compatible`. Important properties include `compatible`, `controller-data`, `google,cros-ec-spi-pre-delay`, `google,cros-ec-spi-msg-delay`, `google,has-vbc-nvram`, `mediatek,rpmsg-name`, `spi-max-frequency`, `reg`, `interrupts`, `reset-gpios`, `boot0-gpios`, `vdd-supply`, `wakeup-source`, `#address-cells`, `#size-cells`, `#gpio-cells`, and 8 more. Referenced schemas are `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/string`, `/schemas/chrome/google,cros-ec-typec.yaml#`, `/schemas/pwm/google,cros-ec-pwm.yaml#`, `/schemas/input/google,cros-ec-keyb.yaml#`, `/schemas/iio/proximity/google,cros-ec-mkbp-proximity.yaml#`, `/schemas/sound/google,cros-ec-codec.yaml#`, `/schemas/i2c/google,cros-ec-i2c-tunnel.yaml#`, `/schemas/regulator/google,cros-ec-regulator.yaml#`, `/schemas/extcon/extcon-usbc-cros-ec.yaml#`, and 1 more. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `interrupts` for interrupt line routing; `wakeup-source` for system wake capability; `#address-cells` for child-node address cell width; `#size-cells` for child-node size cell width; `#gpio-cells` for GPIO specifier width; `gpio-controller` for GPIO provider role. The top-level closure rule is `additionalProperties: false`. Maintainers: Benson Leung <bleung@chromium.org>, Guenter Roeck <groeck@chromium.org>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/string`, `/schemas/chrome/google,cros-ec-typec.yaml#`, `/schemas/pwm/google,cros-ec-pwm.yaml#`, `/schemas/input/google,cros-ec-keyb.yaml#`, `/schemas/iio/proximity/google,cros-ec-mkbp-proximity.yaml#`, `/schemas/sound/google,cros-ec-codec.yaml#`, `/schemas/i2c/google,cros-ec-i2c-tunnel.yaml#`, `/schemas/regulator/google,cros-ec-regulator.yaml#`, `/schemas/extcon/extcon-usbc-cros-ec.yaml#`, and 1 more, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as GPIO provider registration. Conditional/schema-composition points include `allOf`, `patternProperties`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `google,cros-ec-spi-pre-delay`, `google,cros-ec-spi-msg-delay`, `mediatek,rpmsg-name`, `typec`, `ec-pwm`, `pwm`, `keyboard-controller`, `proximity`, `codecs`, `cbas`, and 2 more.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with MFD, EC, GPIO, interrupt, connector, PWM, watchdog, hwmon, and board-management drivers. Direct schema dependencies are `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/string`, `/schemas/chrome/google,cros-ec-typec.yaml#`, `/schemas/pwm/google,cros-ec-pwm.yaml#`, `/schemas/input/google,cros-ec-keyb.yaml#`, `/schemas/iio/proximity/google,cros-ec-mkbp-proximity.yaml#`, `/schemas/sound/google,cros-ec-codec.yaml#`, `/schemas/i2c/google,cros-ec-i2c-tunnel.yaml#`, `/schemas/regulator/google,cros-ec-regulator.yaml#`, `/schemas/extcon/extcon-usbc-cros-ec.yaml#`, and 1 more; resource dependencies visible in the property set include GPIO provider registration. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
