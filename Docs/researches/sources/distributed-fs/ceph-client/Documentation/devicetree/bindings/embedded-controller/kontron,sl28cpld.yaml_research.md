# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/embedded-controller/kontron,sl28cpld.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Kontron's sl28cpld board management controller`. In this tree it is a embedded controller or board-management controller binding used to model management firmware and its child functions; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: The board management controller may contain different IP blocks like watchdog, fan monitoring, PWM controller, interrupt controller and a GPIO controller.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/embedded-controller/kontron,sl28cpld.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `kontron,sl28cpld`. Required properties are `#address-cells`, `#size-cells`, `compatible`, `reg`. Important properties include `compatible`, `reg`, `#address-cells`, `#size-cells`, `#interrupt-cells`, `interrupts`, `interrupt-controller`. Referenced schemas are `/schemas/gpio/kontron,sl28cpld-gpio.yaml`, `/schemas/hwmon/kontron,sl28cpld-hwmon.yaml`, `/schemas/interrupt-controller/kontron,sl28cpld-intc.yaml`, `/schemas/pwm/kontron,sl28cpld-pwm.yaml`, `/schemas/watchdog/kontron,sl28cpld-wdt.yaml`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `#address-cells` for child-node address cell width; `#size-cells` for child-node size cell width; `#interrupt-cells` for interrupt specifier width; `interrupts` for interrupt line routing; `interrupt-controller` for interrupt provider role. The top-level closure rule is `additionalProperties: false`. Maintainers: Michael Walle <michael@walle.cc>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/gpio/kontron,sl28cpld-gpio.yaml`, `/schemas/hwmon/kontron,sl28cpld-hwmon.yaml`, `/schemas/interrupt-controller/kontron,sl28cpld-intc.yaml`, `/schemas/pwm/kontron,sl28cpld-pwm.yaml`, `/schemas/watchdog/kontron,sl28cpld-wdt.yaml`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as interrupt provider registration. Conditional/schema-composition points include `patternProperties`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `^gpio(@[0-9a-f]+)?$`, `^hwmon(@[0-9a-f]+)?$`, `^interrupt-controller(@[0-9a-f]+)?$`, `^pwm(@[0-9a-f]+)?$`, `^watchdog(@[0-9a-f]+)?$`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with MFD, EC, GPIO, interrupt, connector, PWM, watchdog, hwmon, and board-management drivers. Direct schema dependencies are `/schemas/gpio/kontron,sl28cpld-gpio.yaml`, `/schemas/hwmon/kontron,sl28cpld-hwmon.yaml`, `/schemas/interrupt-controller/kontron,sl28cpld-intc.yaml`, `/schemas/pwm/kontron,sl28cpld-pwm.yaml`, `/schemas/watchdog/kontron,sl28cpld-wdt.yaml`; resource dependencies visible in the property set include interrupt provider registration. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
