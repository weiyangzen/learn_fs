# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/mediatek,vcodec-subdev-decoder.yaml

**Purpose:** Defines the Devicetree JSON-schema ABI for `MediaTek Video Decode Accelerator With Multi Hardware`. It is a video codec accelerator binding in the Ceph client Linux source snapshot, constraining how board DTS/DTB files describe media hardware so Linux media, V4L2 mem2mem, platform, clock, reset, power-domain, IOMMU, and graph helpers can bind the correct driver resources. Public surfaces include `$id` `http://devicetree.org/schemas/media/mediatek,vcodec-subdev-decoder.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, examples, and dt-schema references. Top-level required properties are `compatible`, `reg`, `iommus`, `mediatek,scp`, `ranges`; required names across nested/conditional schemas include `assigned-clock-parents`, `assigned-clocks`, `clock-names`, `clocks`, `compatible`, `interrupts`, `iommus`, `mediatek,scp`, `power-domains`, `ranges`, `reg`. Top-level properties are `compatible`, `reg`, `iommus`, `mediatek,scp`, `#address-cells`, `#size-cells`, `ranges`; all nested property names include `#address-cells`, `#size-cells`, `assigned-clock-parents`, `assigned-clocks`, `clock-names`, `clocks`, `compatible`, `interrupts`, `iommus`, `mediatek,scp`, `power-domains`, `ranges`, `reg`. Resource constraints visible in the schema include `compatible`, `reg` (minItems=1), `iommus` (minItems=1; maxItems=32), `mediatek,scp`, `#address-cells` (const=2), `#size-cells` (const=2), `ranges`. Closure is `additionalProperties: False`.

**Control flow:** Runtime control flow is supplied by dt-schema and kernel probing. `dt_binding_check` loads the core meta-schema, resolves references, validates the compatible form, applies required lists and `minItems`/`maxItems`/`const` restrictions, evaluates conditionals, and compiles the inline examples. At boot the DTB node is matched by `compatible`; the platform or media driver then reads MMIO ranges, named interrupts, clocks, resets, power domains, IOMMU streams, DMA/interconnect paths, firmware or reserved-memory phandles, and graph endpoints. Schema composition uses `allOf`, `if`, `then`. Validation can therefore change by compatible string, for example by tightening clock/reset counts, requiring SoC-specific helper phandles, or allowing/deprecating child codec nodes. This binding has no media graph endpoint surface; integration is by platform device resources and codec-specific child nodes.

**State and persistence behavior:** The file stores no mutable runtime state and performs no persistence itself. Its persistent effect is ABI stability for DTS files and shipped DTBs: compatible strings, child-node names, phandle relationships, address ranges, cell counts, and media graph topology are long-lived hardware descriptions. Any change to required properties, resource ordering, child object schemas, or unknown-property policy can invalidate existing board descriptions even though no kernel state is written by the YAML.

**Dependencies and integration points:** Direct schema references are `/schemas/types.yaml#/definitions/phandle`. Runtime dependencies are IOMMU/SMMU stream mappings for video DMA, MediaTek SCP remoteproc/rpmsg control path. Nested schema surfaces include `^video-codec@[0-9a-f]+$`. These child nodes are part of the ABI, not driver-private data; their compatible values, required clocks, power domains, IOMMU entries, or codec-core markers must stay aligned with the driver. Maintainers listed in the binding are `Yunfei Dong <yunfei.dong@mediatek.com>`.

**Risks:** Key risks: compatible-string or fallback-order drift can break OF matching and dtbs_check expectations; resource array ordering is ABI-sensitive for `reg-names`, `clock-names`, `interrupt-names`, `power-domain-names`, and `reset-names`; wrong IOMMU stream IDs can cause video DMA faults or silent memory corruption; SCP phandle and split parent/child placement must match the hardware pipeline or V4L2 decode scheduling will address the wrong block. The closure policy is `additionalProperties: False`, so unknown properties are intentionally rejected after referenced schemas are evaluated.
