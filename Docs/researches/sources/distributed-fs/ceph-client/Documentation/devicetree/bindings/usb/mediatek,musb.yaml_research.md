# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/mediatek,musb.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/mediatek,musb.yaml` defines `MediaTek MUSB DRD/OTG Controller`, a USB2 OTG/host/device controller binding. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Important APIs, Types, and Functions
The exported API is the Devicetree node contract. `$id` is `http://devicetree.org/schemas/usb/mediatek,musb.yaml#` and `$schema` is `http://devicetree.org/meta-schemas/core.yaml#`. `compatible` uses ordered fallback `items` sequence and exposes 4 compatible tokens: `mediatek,mt8516-musb`, `mediatek,mt2701-musb`, `mediatek,mt7623-musb`, `mediatek,mtk-musb`. Top-level properties are `$nodename`, `compatible`, `reg`, `interrupts`, `interrupt-names`, `clocks`, `clock-names`, `phys`, `usb-role-switch`, `dr_mode`, `power-domains`, `connector`. Top-level required properties are `compatible`, `reg`, `interrupts`, `interrupt-names`, `phys`, `clocks`, `clock-names`; required properties discovered in nested branches are `clock-names`, `clocks`, `compatible`, `interrupt-names`, `interrupts`, `phys`, `reg`. Patterned child schemas are none; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry; `reg` describes MMIO windows, bus addresses, or register resources; `interrupts` maps controller, GPIO, or Type-C events into IRQ domains; `interrupt-names` maps controller, GPIO, or Type-C events into IRQ domains; `clocks` integrates with the clock framework; `clock-names` integrates with the clock framework; `phys` connects USB/UFS controllers to PHY providers or exposes a PHY provider; `usb-role-switch` models USB dual-role, Type-C, or graph topology; `dr_mode` models USB dual-role, Type-C, or graph topology; `power-domains` models generic power-domain dependencies; `connector` models USB dual-role, Type-C, or graph topology. ## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (`dependencies`); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: USB host/peripheral/OTG mode, endpoint FIFOs, DMA queues, VBUS/ID detection, suspend/resume wakeup, PHY power, and controller reset state. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around compatible fallback order, MMIO and IRQ resources, PHY/transceiver phandles, `dr_mode`, FIFO/endpoint tuning, VBUS/ID GPIOs, clocks/resets, and child-port layout; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile rejects undeclared top-level properties with `additionalProperties: false`.
