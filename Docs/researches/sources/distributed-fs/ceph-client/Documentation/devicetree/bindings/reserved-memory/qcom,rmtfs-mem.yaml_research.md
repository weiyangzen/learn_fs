# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/reserved-memory/qcom,rmtfs-mem.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/reserved-memory/qcom,rmtfs-mem.yaml` is a Linux devicetree YAML schema for the `Qualcomm Remote File System Memory` firmware/secure-world reserved-memory binding. This binding describes the Qualcomm remote filesystem memory, which serves the purpose of describing the shared memory region used for remote processors to access block device data using the Remote Filesystem protocol. It is not executable Ceph or kernel logic; it is a hardware-description ABI used by DTS authors, dt-schema, and Linux subsystem drivers so that board descriptions match what the driver will parse at probe or early boot.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses single `const` and covers 1 compatible token: `qcom,rmtfs-mem`. Top-level properties are `compatible`, `qcom,client-id`, `qcom,use-guard-pages`, `qcom,vmid`. Across nested schemas and child nodes this file mentions 4 distinct property names; required properties observed at all levels include `qcom,client-id`. Node naming is constrained by no explicit node-name constraint. Reserved-memory properties describe physical address ranges and firmware-visible buffers rather than driver methods. Addressing and placement keys are none, with provider-specific metadata `qcom,client-id`, `qcom,use-guard-pages`, `qcom,vmid`. Required properties are `qcom,client-id`; the ABI controls whether Linux maps, preserves, exposes, or hands the region to another subsystem.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation. `dt-doc-validate`, `dt_binding_check`, and `dtbs_check` load the YAML, expand `$ref` links, match nodes by `compatible` or referenced common-schema use, enforce required properties, evaluate composition/conditional keywords, and validate inline DTS examples. At runtime, early devicetree reserved-memory parsing claims the region before ordinary memory management; later drivers or firmware interfaces look it up by compatible string or phandle. The YAML itself stores no mutable runtime state and writes no persistent data; persistence is the source-controlled devicetree ABI and the DTB blobs built from DTS. External references used in evaluation are `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-array`, `reserved-memory.yaml`; schema composition/conditional keywords present are `allOf`.

## Risks
Risks are ABI and integration risks. Changing compatible ordering, required keys, resource names, child-node patterns, cell counts, or strictness can reject existing DTS files or let invalid hardware descriptions reach runtime probe. This schema has 4 top-level properties, 4 distinct property names across nested schemas, and this strictness profile: composition is closed with `unevaluatedProperties: false`.
