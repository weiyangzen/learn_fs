# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/mmc/synopsys-dw-mshc-common.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Synopsys Designware Mobile Storage Host Controller Common Properties`. In this tree it is a MMC/SD/SDHCI storage host controller binding: it constrains how DTS authors describe hardware, and it gives Linux OF/platform code a stable ABI for matching drivers, acquiring resources, and validating board descriptions with dt-schema.

**Important APIs/types/functions:** This is declarative schema, not executable C code. The public interface is the binding ABI exposed through `$id` `http://devicetree.org/schemas/mmc/synopsys-dw-mshc-common.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `description`, `maintainers`, `properties`, `required`, schema composition keywords, and inline `examples`. Compatible strings or match identifiers include none directly enumerated; this file is primarily common schema or child-node infrastructure. Top-level required properties are none at the top level. Important properties include `resets`, `reset-names`, `clock-frequency`, `fifo-depth`, `card-detect-delay`, `data-addr`, `fifo-watermark-aligned`, `dmas`, `dma-names`. Property roles include `resets`: reset controller phandles; `reset-names`: reset line names; `dmas`: DMA channel phandles; `dma-names`: DMA channel names; `clock-frequency`: Should be the frequency (in Hz) of the ciu clock. If this is specified and the ciu clock is specified then we'll try to set the ciu clock to this at probe time.; `fifo-depth`: The maximum size of the tx/rx fifo's. If this property is not specified, the default value of the fifo size is determined from the controller registers.; `card-detect-delay`: Delay in milli-seconds before detecting card after card insert event. The default value is 0.; `data-addr`: Override fifo address with value provided by DT. The default FIFO reg offset is assumed as 0x100 (version < 0x240A) and 0x200(version >= 0x240A) by driver. If the controller does not follow this rule, please use this property to set fifo address in device tree.; `fifo-watermark-aligned`: Data done irq is expected if data length is less than watermark in PIO mode. But fifo watermark is requested to be aligned with data length in some SoC so that TX/RX irq can be generated with data done irq. Add this watermark quirk to mark this requirement and force fifo watermark setting accordingly.. Direct or nested schema references include `mmc-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/flag`. The top-level closure policy is `additionalProperties: true`. Maintainers: Ulf Hansson <ulf.hansson@linaro.org>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and Linux subsystem drivers. `dt_binding_check` loads the core meta-schema, resolves references, evaluates `properties`, `required`, enum/const/items limits, and composition rules, then validates the examples. `dtbs_check` applies the same contract to compiled board DTBs. At boot, the flattened DT node is matched through `compatible` or inherited child-node context, the relevant driver parses resources such as MMIO ranges, interrupts, clocks, resets, regulators, PHYs, muxes, ECC engines, partitions, or child buses, and subsystem helpers enforce the generic parts of the contract. Schema composition/control branches in this file: allOf=1. Nested schema surface: no nested child-node schemas detected at the top level.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted DTS/DTB nodes encode hardware identity, resource topology, child-node layout, and phandle cell widths for long-lived boards. Tightening `required`, changing compatible ordering, changing cell counts, or altering `additionalProperties`/`unevaluatedProperties` can break existing DTBs even though no state is stored by the YAML itself.

**Dependencies and integration points:** Integrates with MMC core, SDHCI/DW-MSHC host-controller drivers, regulator, clock, reset, power-domain, and card-detect/write-protect bindings. Devicetree/dt-schema dependencies are the core meta-schema plus `mmc-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/flag`. Driver integration is through OF match tables and subsystem parsers; board integration is through phandles, address/size cells, interrupts, clocks, resets, regulators, power domains, child flash/partition nodes, MDIO/PHY links, mux specifiers, and examples that document expected DTS shape.

**Risks:** Main risks are ABI drift, under-specified compatibles, required resources that do not match real SoC integration, wrong `#*-cells` counts, stale examples, and conditional branches that validate one variant while rejecting another valid one. For storage bindings, partition/ECC/timing mistakes can silently corrupt flash or make media unprobeable. For network bindings, PHY mode, MDIO, reset, MAC-address, or clock mistakes can leave links down. For mux and common schemas, over-permissive closure can hide misspelled properties while over-tight closure can reject legitimate inherited properties.
