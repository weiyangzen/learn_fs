# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/mtd/cdns,hp-nfc.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Cadence NAND controller`. In this tree it is a MTD flash memory controller, flash chip, ECC engine, or common flash schema binding: it constrains how DTS authors describe hardware, and it gives Linux OF/platform code a stable ABI for matching drivers, acquiring resources, and validating board descriptions with dt-schema.

**Important APIs/types/functions:** This is declarative schema, not executable C code. The public interface is the binding ABI exposed through `$id` `http://devicetree.org/schemas/mtd/cdns,hp-nfc.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `description`, `maintainers`, `properties`, `required`, schema composition keywords, and inline `examples`. Compatible strings or match identifiers include `cdns,hp-nfc`. Top-level required properties are `compatible`, `reg`, `reg-names`, `interrupts`, `clocks`, `clock-names`. Important properties include `compatible`, `reg`, `reg-names`, `interrupts`, `clocks`, `clock-names`, `dmas`, `dma-coherent`, `iommus`, `cdns,board-delay-ps`. Property roles include `compatible`: driver match key and stable hardware ABI identifier; `reg`: MMIO, bus address, flash-chip select, or child register window; `interrupts`: interrupt line routing; `clocks`: clock provider phandles; `clock-names`: clock input names; `dmas`: DMA channel phandles; `iommus`: IOMMU stream mappings; `reg-names`: names for register regions consumed by the driver; `dma-coherent`: schema-constrained Devicetree property; `cdns,board-delay-ps`: Estimated Board delay. The value includes the total round trip delay for the signals and is used for deciding on values associated with data read capture. The example formula for SDR mode is the following. board delay = RE#PAD delay + PCB trace to device + PCB trace from device + DQ PAD delay. Direct or nested schema references include `nand-controller.yaml`. The top-level closure policy is `unevaluatedProperties: false`. Maintainers: Niravkumar L Rabara <niravkumar.l.rabara@intel.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and Linux subsystem drivers. `dt_binding_check` loads the core meta-schema, resolves references, evaluates `properties`, `required`, enum/const/items limits, and composition rules, then validates the examples. `dtbs_check` applies the same contract to compiled board DTBs. At boot, the flattened DT node is matched through `compatible` or inherited child-node context, the relevant driver parses resources such as MMIO ranges, interrupts, clocks, resets, regulators, PHYs, muxes, ECC engines, partitions, or child buses, and subsystem helpers enforce the generic parts of the contract. Schema composition/control branches in this file: allOf=1. Nested schema surface: no nested child-node schemas detected at the top level.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted DTS/DTB nodes encode hardware identity, resource topology, child-node layout, and phandle cell widths for long-lived boards. Tightening `required`, changing compatible ordering, changing cell counts, or altering `additionalProperties`/`unevaluatedProperties` can break existing DTBs even though no state is stored by the YAML itself.

**Dependencies and integration points:** Integrates with MTD core, raw NAND/SPI-NOR/SPI-NAND/OneNAND/physmap drivers, ECC-engine providers, partition parsers, and nvmem/UBI consumers. Devicetree/dt-schema dependencies are the core meta-schema plus `nand-controller.yaml`. Driver integration is through OF match tables and subsystem parsers; board integration is through phandles, address/size cells, interrupts, clocks, resets, regulators, power domains, child flash/partition nodes, MDIO/PHY links, mux specifiers, and examples that document expected DTS shape.

**Risks:** Main risks are ABI drift, under-specified compatibles, required resources that do not match real SoC integration, wrong `#*-cells` counts, stale examples, and conditional branches that validate one variant while rejecting another valid one. For storage bindings, partition/ECC/timing mistakes can silently corrupt flash or make media unprobeable. For network bindings, PHY mode, MDIO, reset, MAC-address, or clock mistakes can leave links down. For mux and common schemas, over-permissive closure can hide misspelled properties while over-tight closure can reject legitimate inherited properties.
