# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/remoteproc/st,stm32-rproc.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/remoteproc/st,stm32-rproc.yaml` is a Linux devicetree YAML schema for the `STMicroelectronics STM32 remote processor controller` remoteproc controller binding. This document defines the binding for the remoteproc component that loads and boots firmwares on the ST32MP family chipset. It is not executable Ceph or kernel logic; it is a hardware-description ABI used by DTS authors, dt-schema, and Linux subsystem drivers so that board descriptions match what the driver will parse at probe or early boot.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses single `const` and covers 1 compatible token: `st,stm32mp1-m4`. Top-level properties are `compatible`, `reg`, `resets`, `reset-names`, `st,syscfg-holdboot`, `st,syscfg-tz`, `interrupts`, `wakeup-source`, `mboxes`, `mbox-names`, `memory-region`, `st,syscfg-pdds`, `st,syscfg-m4-state`, `st,syscfg-rsc-tbl`, `st,auto-boot`, `firmware-name`. Across nested schemas and child nodes this file mentions 16 distinct property names; required properties observed at all levels include `compatible`, `reg`, `resets`, `st,syscfg-holdboot`. Node naming is constrained by no explicit node-name constraint. Remoteproc-facing properties define firmware loading and processor-control resources: address ranges `reg`, memory-carveout links `reg`, `memory-region`, mailbox/interrupt/IPC hooks `interrupts`, `mboxes`, `mbox-names`, `firmware-name`, and clock/reset/power controls `resets`, `reset-names`. Required properties are `compatible`, `reg`, `resets`; these values are consumed by Linux remoteproc drivers before firmware boot, crash handling, and virtio/rpmsg setup.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation. `dt-doc-validate`, `dt_binding_check`, and `dtbs_check` load the YAML, expand `$ref` links, match nodes by `compatible` or referenced common-schema use, enforce required properties, evaluate composition/conditional keywords, and validate inline DTS examples. At runtime, platform bus probing hands the validated node to a remoteproc driver, which maps resources, obtains clocks/resets/power domains, reserves memory, starts firmware, and may expose rpmsg/virtio endpoints. The YAML itself stores no mutable runtime state and writes no persistent data; persistence is the source-controlled devicetree ABI and the DTB blobs built from DTS. External references used in evaluation are `/schemas/types.yaml#/definitions/flag`, `/schemas/types.yaml#/definitions/phandle-array`; schema composition/conditional keywords present are `allOf`, `else`, `if`, `then`.

## Risks
Risks are ABI and integration risks. Changing compatible ordering, required keys, resource names, child-node patterns, cell counts, or strictness can reject existing DTS files or let invalid hardware descriptions reach runtime probe. This schema has 16 top-level properties, 16 distinct property names across nested schemas, and this strictness profile: unknown top-level properties are rejected. Conditional branches and shared `$ref` schemas should be checked against all in-tree users because schema-only edits can still break board builds or driver binding.
