# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/fsl,layerscape-pcie.yaml

**Purpose:** Defines the Devicetree YAML/JSON-schema contract for `Freescale Layerscape PCIe Root Complex(RC) controller`. It is a host/root-complex controller binding in the NXP/Freescale Layerscape DesignWare PCIe family; it constrains how DTS/DTB nodes identify the PCI hardware, describe register windows, interrupts, clocks, resets, PHYs, address translation, DMA/IOMMU reachability, and optional child/root-port layout for Linux PCI probing. The source description says: This PCIe RC controller is based on the Synopsys DesignWare PCIe IP This controller derives its clocks from the Reset Configuration Word (RCW) which is used to describe the PLL settings at the time of chip-reset. Also as per the available Reference Manuals, there is no specific 'version' register available in the Freescale PCIe controller register set, which can allow determining the underlying DesignWare PCIe controller version information.

**Important APIs/types/functions:** This file is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/pci/fsl,layerscape-pcie.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, the `properties` block, `required` list, schema-composition keywords, inline examples, and the compatible strings consumed by kernel OF match tables. Compatible strings covered here: `fsl,ls1012a-pcie`, `fsl,ls1021a-pcie`, `fsl,ls1028a-pcie`, `fsl,ls1043a-pcie`, `fsl,ls1046a-pcie`, `fsl,ls1088a-pcie`, `fsl,ls2080a-pcie`, `fsl,ls2085a-pcie`, `fsl,ls2088a-pcie`, `fsl,lx2160ar2-pcie`. Directly declared properties are `compatible`, `reg`, `reg-names`, `fsl,pcie-scfg`, `big-endian`, `dma-coherent`, `msi-parent`, `iommu-map`, `interrupts`, `interrupt-names`, `num-viewport`. Required properties are `compatible`, `reg`, `reg-names`, `#address-cells`, `#size-cells`, `device_type`, `bus-range`, `ranges`, `interrupts`, `interrupt-names`, `#interrupt-cells`, `interrupt-map-mask`, `interrupt-map`. **Control flow:** Validation flow is handled by dt-schema: the core meta-schema loads this YAML, resolves references (`/schemas/pci/pci-bus.yaml#`, `/schemas/types.yaml#/definitions/flag`, `/schemas/types.yaml#/definitions/phandle-array`, `/schemas/types.yaml#/definitions/uint32`), applies direct property constraints, evaluates top-level `allOf` composition, and then applies conditional branches. Conditional behavior: for fsl,ls1028a-pcie, fsl,ls1046a-pcie, fsl,ls1043a-pcie, fsl,ls1012a-pcie, adds/restricts property cardinalities/names; for fsl,ls2080a-pcie, fsl,ls2085a-pcie, fsl,ls2088a-pcie, adds/restricts property cardinalities/names; for fsl,ls1088a-pcie, adds/restricts property cardinalities/names. At runtime the compiled DTB has no code from this file; the kernel matches `compatible`, maps `reg` resources, programs PCI ranges, requests interrupts/MSI mappings, enables clocks/resets/regulators/PHYs/power domains, and creates host bridge/root-port or endpoint objects according to the described node.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability for board DTS files and shipped DTBs: compatible ordering, resource names, cell counts, interrupt maps, address ranges, and child-node layout become the long-lived contract that drivers and firmware rely on. For this file, the top-level and composed unknown-property policy is: unevaluatedProperties: false.

**Dependencies:** Direct schema dependencies are `/schemas/pci/pci-bus.yaml#`, `/schemas/types.yaml#/definitions/flag`, `/schemas/types.yaml#/definitions/phandle-array`, `/schemas/types.yaml#/definitions/uint32`. Resource dependencies visible in the binding include `compatible` (driver OF match key and binding ABI identifier); `reg` (MMIO/config/address-space resource tuples); `reg-names` (stable names used by drivers to request register windows); `dma-coherent` (coherency attribute for DMA transactions); `msi-parent` (external MSI provider reference); `iommu-map` (PCI requester-ID to IOMMU stream mapping); `interrupts` (controller, MSI, PME, AER, DMA, or legacy interrupt inputs); `interrupt-names` (stable interrupt resource names) The binding also depends on the broader Devicetree PCI schemas, dt-schema tooling, and matching Linux PCI host/endpoint drivers for the compatible strings above.

**Integration points:** Integrates with Linux OF platform matching through `compatible`, PCI core setup through `device_type`, `bus-range`, `ranges`, `dma-ranges`, `#address-cells`, and `#size-cells`, interrupt infrastructure through `interrupt-map`, `interrupts`, MSI controllers or `msi-map`, and SoC resource managers through clocks, resets, PHY, regulator, power-domain, and IOMMU properties. Nested integration surface: no nested child schema declared directly.

**Risks:** Main risks are ABI drift in required properties, accepting a DTS shape that the driver cannot probe, rejecting valid legacy boards, stale examples, wrong `reg-names`/`clock-names`/`reset-names` ordering, incomplete compatible coverage, and conditional branches whose `contains`/`enum` logic does not match real fallback-compatible ordering. PCI-specific risk is high around address translation and interrupts: bad `ranges`, `dma-ranges`, `iommu-map`, `msi-map`, or `interrupt-map-mask` can validate syntactically while producing unprobeable devices or broken DMA/MSI at runtime.
