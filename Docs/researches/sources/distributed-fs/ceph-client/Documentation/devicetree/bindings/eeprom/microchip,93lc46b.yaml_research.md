# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/eeprom/microchip,93lc46b.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Microchip 93xx46 SPI compatible EEPROM family`. In this tree it is a EEPROM or FRAM/NVMEM binding used by nonvolatile memory drivers and NVMEM cell consumers; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/eeprom/microchip,93lc46b.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `atmel,at93c46`, `atmel,at93c46d`, `atmel,at93c56`, `atmel,at93c66`, `eeprom-93xx46`, `microchip,93lc46b`. Required properties are `compatible`, `reg`, `data-size`, `spi-max-frequency`. Important properties include `compatible`, `data-size`, `reg`, `read-only`, `select-gpios`. Referenced schemas are `/schemas/types.yaml#/definitions/uint32`, `/schemas/spi/spi-peripheral-props.yaml#`, `/schemas/nvmem/nvmem.yaml`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address. The top-level closure rule is `unevaluatedProperties: false`. Maintainers: Cory Tusar <cory.tusar@pid1solutions.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/uint32`, `/schemas/spi/spi-peripheral-props.yaml#`, `/schemas/nvmem/nvmem.yaml`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as platform driver `of_match_table` binding through the compatible string. Conditional/schema-composition points include `allOf`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `data-size`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with I2C/SPI EEPROM, FRAM, NVMEM, regulator, and GPIO consumers. Direct schema dependencies are `/schemas/types.yaml#/definitions/uint32`, `/schemas/spi/spi-peripheral-props.yaml#`, `/schemas/nvmem/nvmem.yaml`; resource dependencies visible in the property set include platform driver `of_match_table` binding through the compatible string. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `unevaluatedProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/eeprom/microchip,93lc46b.yaml` and `make dtbs_check` against DTS users of every compatible family. Verify inline examples compile, required-property failures are reported, compatible-specific branches are exercised, inherited schemas resolve, and drivers still probe with the resources described here. The file includes 1 example block(s), which are part of the dt-schema validation signal.
