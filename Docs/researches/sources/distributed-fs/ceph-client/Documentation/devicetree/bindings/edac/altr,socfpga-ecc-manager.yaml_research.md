# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/edac/altr,socfpga-ecc-manager.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Altera SoCFPGA ECC Manager`. In this tree it is a EDAC binding for memory controllers or ECC-management blocks that report correctable and uncorrectable memory errors; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: This binding describes the device tree nodes required for the Altera SoCFPGA ECC Manager for the Cyclone5, Arria5, Arria10, Stratix10, and Agilex chip families.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/edac/altr,socfpga-ecc-manager.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `altr,socfpga-s10-ecc-manager`, `altr,socfpga-a10-ecc-manager`, `altr,socfpga-ecc-manager`. Required properties are none declared. Important properties include `compatible`, `#address-cells`, `#size-cells`, `interrupts`, `interrupt-controller`, `#interrupt-cells`, `ranges`, `altr,sysmgr-syscon`, `sdramedac`. Referenced schemas are `/schemas/types.yaml#/definitions/phandle`. Property roles include `compatible` for driver match key and hardware ABI identifier; `#address-cells` for child-node address cell width; `#size-cells` for child-node size cell width; `interrupts` for interrupt line routing; `interrupt-controller` for interrupt provider role; `#interrupt-cells` for interrupt specifier width. The top-level closure rule is `additionalProperties: false`. Maintainers: Niravkumar L Rabara <niravkumarlaxmidas.rabara@altera.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/phandle`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as interrupt provider registration. Conditional/schema-composition points include `if`, `then`, `else`, `patternProperties`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `altr,sysmgr-syscon`, `sdramedac`, `^ocram-ecc@[a-f0-9]+$`, `^usb[0-9]-ecc@[a-f0-9]+$`, `^emac[0-9]-[t,r]x-ecc@[a-f0-9]+$`, `^sdmmc[a-f]-ecc@[a-f0-9]+$`, `^l2-ecc@[a-f0-9]+$`, `^dma-ecc@[a-f0-9]+$`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with EDAC drivers and platform interrupt/error-reporting paths. Direct schema dependencies are `/schemas/types.yaml#/definitions/phandle`; resource dependencies visible in the property set include interrupt provider registration. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
