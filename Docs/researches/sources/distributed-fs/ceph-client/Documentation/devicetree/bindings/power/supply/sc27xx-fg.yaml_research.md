# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/power/supply/sc27xx-fg.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/power/supply/sc27xx-fg.yaml` defines the Linux Devicetree YAML schema for `Spreadtrum SC27XX PMICs Fuel Gauge Unit Power Supply`, a battery, fuel-gauge, or battery-monitor binding. It is declarative ABI documentation and validation input, not executable driver code. Its job is to keep DTS/DTB nodes aligned with the resources, child nodes, and electrical or timing constraints expected by the matching kernel subsystem before a driver probes hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `patternProperties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an `enum` with 5 tokens: `sprd,sc2720-fgu`, `sprd,sc2721-fgu`, `sprd,sc2723-fgu`, `sprd,sc2730-fgu`, `sprd,sc2731-fgu`. Top-level properties are `compatible`, `reg`, `battery-detect-gpios`, `bat-detect-gpio`, `interrupts`, `io-channels`, `io-channel-names`, `nvmem-cells`, `nvmem-cell-names`, `sprd,calib-resistance-micro-ohms`, `monitored-battery`. Top-level required properties are `compatible`, `reg`, `battery-detect-gpios`, `interrupts`, `io-channels`, `io-channel-names`, `nvmem-cells`, `nvmem-cell-names`, `sprd,calib-resistance-micro-ohms`, `monitored-battery`; required properties collected from nested branches include `battery-detect-gpios`, `compatible`, `interrupts`, `io-channel-names`, `io-channels`, `monitored-battery`, `nvmem-cell-names`, `nvmem-cells`, `reg`, `sprd,calib-resistance-micro-ohms`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` gives MMIO, I2C, SPI, child address, or selector placement; `battery-detect-gpios` describes board GPIO control/status wiring; `bat-detect-gpio` describes board GPIO control/status wiring; `interrupts` routes alert, status, protection, capture, timer, or controller IRQs; `monitored-battery` connects battery, charger, or supply provider relationships. The highest-risk ABI details are compatible identity, I2C/MMIO address, battery phandle, monitor resistor/calibration values, alert/IRQ wiring, charge/voltage/current limits, and vendor battery profile data.

## Control Flow
Control flow is dt-schema evaluation rather than imperative execution. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties` and `patternProperties`, evaluates `allOf`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime this YAML does not execute: the compiled DTB node is matched through a kernel OF table or subsystem-specific child-node parser, then helpers for power-supply, regulator, PWM, PTP, PPS, PowerPC platform, clocks, resets, interrupts, GPIOs, pinctrl, power domains, and MFD parents consume the validated resources.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. ## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource-shape changes that still compile but break driver probe, power sequencing, clock setup, IRQ delivery, or consumer phandle resolution. Tightening required properties can reject existing board files; loosening them can hide missing supplies, clocks, resets, interrupts, current/voltage limits, PWM cell counts, PTP/PPS GPIOs, or regulator child constraints. This schema rejects unknown top-level properties with `additionalProperties: false`. It has 11 top-level properties and 11 distinct nested property names, so broad edits should be checked against all compatibles, examples, and in-tree DTS users rather than only the filename's nominal device.
