**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/firmware/google,gs101-acpm-ipc.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `google,gs101-acpm-ipc`. Required properties are `compatible`, `#clock-cells`, `mboxes`, `shmem`. Important properties include `compatible`, `#clock-cells`, `mboxes`, `pmic`, `pmic-1`, `pmic-2`, `shmem`. Referenced schemas are none declared. Property roles include `compatible` for driver match key and hardware ABI identifier; `#clock-cells` for clock provider specifier width; `mboxes` for mailbox channels; `shmem` for shared-memory regions. The top-level closure rule is `additionalProperties: false`. Maintainers: Tudor Ambarus <tudor.ambarus@linaro.org>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as none declared, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as mailbox channels, shared-memory mailboxes, clock provider registration. It has no nested conditional schema branches beyond direct property validation. Nested or patterned child schema surfaces include `pmic`, `pmic-1`, `pmic-2`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with firmware, mailbox, shared-memory, secure-monitor, system-controller, clock, reset, power, and FPGA manager drivers. Direct schema dependencies are none declared; resource dependencies visible in the property set include mailbox channels, shared-memory mailboxes, clock provider registration. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
