# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/mtd/mtd-physmap.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `CFI or JEDEC memory-mapped NOR flash, MTD-RAM (NVRAM...)`. In this tree it is a MTD flash memory controller, flash chip, ECC engine, or common flash schema binding: it constrains how DTS authors describe hardware, and it gives Linux OF/platform code a stable ABI for matching drivers, acquiring resources, and validating board descriptions with dt-schema. The source description says: Flash chips (Memory Technology Devices) are often used for solid state file systems on embedded devices.

**Important APIs/types/functions:** This is declarative schema, not executable C code. The public interface is the binding ABI exposed through `$id` `http://devicetree.org/schemas/mtd/mtd-physmap.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `description`, `maintainers`, `properties`, `required`, schema composition keywords, and inline `examples`. Compatible strings or match identifiers include `amd,s29gl01gp`, `amd,s29gl032a`, `amd,s29gl256n`, `amd,s29gl512n`, `arm,versatile-flash`, `arm,vexpress-flash`, `cortina,gemini-flash`, `cypress,hyperflash`, `ge,imp3a-firmware-mirror`, `ge,imp3a-paged-flash`, `gef,ppc9a-firmware-mirror`, `gef,ppc9a-paged-flash`, `gef,sbc310-firmware-mirror`, `gef,sbc310-paged-flash`, `gef,sbc610-firmware-mirror`, `gef,sbc610-paged-flash`, `intel,28f128j3`, `intel,dt28f160`. Top-level required properties are `compatible`, `reg`. Important properties include `compatible`, `reg`, `clocks`, `power-domains`, `bank-width`, `device-width`, `no-unaligned-direct-access`, `linux,mtd-name`, `use-advanced-sector-protection`, `erase-size`, `addr-gpios`, `#address-cells`, `#size-cells`, `ranges`, `big-endian`, `little-endian`. Property roles include `compatible`: driver match key and stable hardware ABI identifier; `reg`: MMIO, bus address, flash-chip select, or child register window; `clocks`: clock provider phandles; `power-domains`: generic power-domain attachment; `#address-cells`: child address cell width; `#size-cells`: child size cell width; `bank-width`: Width (in bytes) of the bank. Equal to the device width times the number of interleaved chips.; `device-width`: Width of a single mtd chip. If omitted, assumed to be equal to 'bank-width'.; `no-unaligned-direct-access`: Disables the default direct mapping of the flash. On some platforms (e.g. MPC5200) a direct 1:1 mapping may cause problems with JFFS2 usage, as the local bus (LPB) doesn't support unaligned accesses as implemented in the JFFS2 code via memcpy(). By defining "no-unaligned-direct-access", the flash will not be exposed directly to the MTD users (e.g. JFFS2) any more.; `linux,mtd-name`: Allows specifying the mtd name for retro capability with physmap-flash drivers as boot loader pass the mtd partition via the old device name physmap-flash.; `use-advanced-sector-protection`: Enables support for the advanced sector protection (Spansion: PPB - Persistent Protection Bits) locking.. Direct or nested schema references include `mtd.yaml#`, `/schemas/memory-controllers/mc-peripheral-props.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/string`, `/schemas/types.yaml#/definitions/phandle`. The top-level closure policy is `unevaluatedProperties: false`. Maintainers: Rob Herring <robh@kernel.org>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and Linux subsystem drivers. `dt_binding_check` loads the core meta-schema, resolves references, evaluates `properties`, `required`, enum/const/items limits, and composition rules, then validates the examples. `dtbs_check` applies the same contract to compiled board DTBs. At boot, the flattened DT node is matched through `compatible` or inherited child-node context, the relevant driver parses resources such as MMIO ranges, interrupts, clocks, resets, regulators, PHYs, muxes, ECC engines, partitions, or child buses, and subsystem helpers enforce the generic parts of the contract. Schema composition/control branches in this file: if=1, then=1, allOf=1, oneOf=1. Nested schema surface: no nested child-node schemas detected at the top level.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted DTS/DTB nodes encode hardware identity, resource topology, child-node layout, and phandle cell widths for long-lived boards. Tightening `required`, changing compatible ordering, changing cell counts, or altering `additionalProperties`/`unevaluatedProperties` can break existing DTBs even though no state is stored by the YAML itself.

**Dependencies and integration points:** Integrates with MTD core, raw NAND/SPI-NOR/SPI-NAND/OneNAND/physmap drivers, ECC-engine providers, partition parsers, and nvmem/UBI consumers. Devicetree/dt-schema dependencies are the core meta-schema plus `mtd.yaml#`, `/schemas/memory-controllers/mc-peripheral-props.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/string`, `/schemas/types.yaml#/definitions/phandle`. Driver integration is through OF match tables and subsystem parsers; board integration is through phandles, address/size cells, interrupts, clocks, resets, regulators, power domains, child flash/partition nodes, MDIO/PHY links, mux specifiers, and examples that document expected DTS shape.

**Risks:** Main risks are ABI drift, under-specified compatibles, required resources that do not match real SoC integration, wrong `#*-cells` counts, stale examples, and conditional branches that validate one variant while rejecting another valid one. For storage bindings, partition/ECC/timing mistakes can silently corrupt flash or make media unprobeable. For network bindings, PHY mode, MDIO, reset, MAC-address, or clock mistakes can leave links down. For mux and common schemas, over-permissive closure can hide misspelled properties while over-tight closure can reject legitimate inherited properties.
