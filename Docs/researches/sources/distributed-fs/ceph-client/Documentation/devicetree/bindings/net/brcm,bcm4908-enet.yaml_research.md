# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/brcm,bcm4908-enet.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/brcm,bcm4908-enet.yaml` defines the Ethernet MAC/controller binding titled `Broadcom BCM4908 Ethernet controller`. Broadcom's Ethernet controller integrated into BCM4908 family SoCs It is a Linux Devicetree YAML schema used to validate DTS/DTB nodes and to document the firmware ABI consumed before the kernel creates the corresponding Ethernet network interface.

## Important APIs, Types, and Functions
The public interface is the YAML/dt-schema ABI, not C-callable functions. `compatible` uses a single `const` with 1 token: `brcm,bcm4908-enet`. Top-level properties are `compatible`, `reg`, `interrupts`, `interrupt-names`. Top-level required properties are `reg`, `interrupts`, `interrupt-names`; required keys found in nested schemas include `reg`, `interrupts`, `interrupt-names`. Pattern properties are none. Collected numeric/item constraints include `maxItems=1`, `minItems=1`. The highest-risk API details are register and interrupt ordering, `phy-mode`, PHY/fixed-link selection, DMA/clock/reset names, MAC address sources, compatible fallback ordering, and optional queue or port child nodes. Important property roles: `compatible` selects the OF match table and stable hardware ABI; `reg` carries MMIO ranges, bus addresses, chip selects, or switch port indexes; `interrupts` routes controller, wake, link, or error IRQs; `interrupt-names` routes controller, wake, link, or error IRQs.

## Control Flow
Control flow is declarative schema evaluation. During `make dt_binding_check` or `make dtbs_check`, dt-schema loads the YAML, resolves `$ref` entries, matches by `$id`, `$nodename`, `compatible`, or fragment inclusion, checks required properties, evaluates `allOf`, validates examples, and enforces `additionalProperties` or `unevaluatedProperties`. At runtime the YAML itself does not execute. Firmware provides a DTB node for the Ethernet MAC/controller binding; Linux driver core or bus code matches a driver, then subsystem helpers consume the validated resources. Child schemas such as `ports`, `ethernet-ports`, MDIO children, or CAN transceiver links guide later parsing by DSA, phylink, PHYLIB, Bluetooth, or SocketCAN drivers.

## State and Persistence Behavior
The schema stores no mutable kernel state and writes no persistent data. Persistence is the Devicetree ABI: compatible strings, property names, array order, phandle cell counts, child-node names, and example layouts are contracts carried by DTS sources and deployed DTBs. Runtime state is owned by drivers after probe, including netdev registration, DMA descriptor ownership, PHY/phylink state, MAC address selection, link mode, NAPI polling, and queue statistics; this file only constrains how hardware and board wiring are represented.

## Risks
Primary risks are incompatible ABI changes to register and interrupt ordering, `phy-mode`, PHY/fixed-link selection, DMA/clock/reset names, MAC address sources, compatible fallback ordering, and optional queue or port child nodes, mismatches between documented compatibles and driver OF match tables, resource-order changes that pass schema review but break probe, and stale examples. This schema closes composed schemas with `unevaluatedProperties: false`. Additional risk signals: conditional branches can validate one silicon variant while rejecting another.
