# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/qcom,pcie-common.yaml

**Purpose:** Defines the Devicetree YAML/JSON-schema contract for `Qualcomm PCI Express Root Complex Common Properties`. It is a common reusable schema binding in the Qualcomm DesignWare-derived PCIe host/endpoint family; it constrains how DTS/DTB nodes identify the PCI hardware, describe register windows, interrupts, clocks, resets, PHYs, address translation, DMA/IOMMU reachability, and optional child/root-port layout for Linux PCI probing.

**Important APIs/types/functions:** This file is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/pci/qcom,pcie-common.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, the `properties` block, `required` list, schema-composition keywords, inline examples, and the compatible strings consumed by kernel OF match tables. This common schema does not declare a concrete top-level `compatible`; concrete bindings include it by `$ref`. Directly declared properties are `reg`, `reg-names`, `interrupts`, `interrupt-names`, `iommu-map`, `clocks`, `clock-names`, `dma-coherent`, `interconnects`, `interconnect-names`, `phys`, `phy-names`, `power-domains`, `required-opps`, `resets`, `reset-names`, `perst-gpios`, `wake-gpios`, `vddpe-3v3-supply`, `operating-points-v2`, and 1 more. Required properties are `reg`, `reg-names`, `interrupt-map-mask`, `interrupt-map`, `clocks`, `clock-names`. Maintainers: Bjorn Andersson <andersson@kernel.org>, Manivannan Sadhasivam <mani@kernel.org>.

**Control flow:** Validation flow is handled by dt-schema: the core meta-schema loads this YAML, resolves references (`/schemas/pci/pci-host-bridge.yaml#`, `/schemas/pci/pci-pci-bridge.yaml#`), applies direct property constraints, evaluates top-level `allOf` composition, and then applies conditional branches. Conditional behavior: no explicit `if`/`then` branches; validation is direct plus referenced schemas. At runtime the compiled DTB has no code from this file; the kernel matches `compatible`, maps `reg` resources, programs PCI ranges, requests interrupts/MSI mappings, enables clocks/resets/regulators/PHYs/power domains, and creates host bridge/root-port or endpoint objects according to the described node.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability for board DTS files and shipped DTBs: compatible ordering, resource names, cell counts, interrupt maps, address ranges, and child-node layout become the long-lived contract that drivers and firmware rely on. For this file, the top-level and composed unknown-property policy is: additionalProperties: true, unevaluatedProperties: false.

**Dependencies:** Direct schema dependencies are `/schemas/pci/pci-host-bridge.yaml#`, `/schemas/pci/pci-pci-bridge.yaml#`. Resource dependencies visible in the binding include `reg` (MMIO/config/address-space resource tuples); `reg-names` (stable names used by drivers to request register windows); `interrupts` (controller, MSI, PME, AER, DMA, or legacy interrupt inputs); `interrupt-names` (stable interrupt resource names); `iommu-map` (PCI requester-ID to IOMMU stream mapping); `clocks` (clock provider phandles); `clock-names` (stable clock input names); `dma-coherent` (coherency attribute for DMA transactions); `phys` (PHY phandles for PCIe lanes); `phy-names` (stable PHY names); `power-domains` (genpd domain phandles); `resets` (reset-controller phandles); `reset-names` (stable reset line names); `perst-gpios` (deprecated host-side PERST# GPIO); `wake-gpios` (WAKE# GPIO) The binding also depends on the broader Devicetree PCI schemas, dt-schema tooling, and matching Linux PCI host/endpoint drivers for the compatible strings above.

**Integration points:** Integrates with Linux OF platform matching through `compatible`, PCI core setup through `device_type`, `bus-range`, `ranges`, `dma-ranges`, `#address-cells`, and `#size-cells`, interrupt infrastructure through `interrupt-map`, `interrupts`, MSI controllers or `msi-map`, and SoC resource managers through clocks, resets, PHY, regulator, power-domain, and IOMMU properties. Nested integration surface: pattern `^pcie@`, child/object property `opp-table`.

**Risks:** Main risks are ABI drift in required properties, accepting a DTS shape that the driver cannot probe, rejecting valid legacy boards, stale examples, wrong `reg-names`/`clock-names`/`reset-names` ordering, incomplete compatible coverage, and conditional branches whose `contains`/`enum` logic does not match real fallback-compatible ordering. PCI-specific risk is high around address translation and interrupts: bad `ranges`, `dma-ranges`, `iommu-map`, `msi-map`, or `interrupt-map-mask` can validate syntactically while producing unprobeable devices or broken DMA/MSI at runtime.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/qcom,pcie-common.yaml` to validate this schema and its 0 inline example block(s). Run `make dtbs_check` for DTS users of each compatible string to exercise conditional branches, referenced schemas, child-node validation, closure policy, and resource-name ordering. Runtime smoke signals are successful PCI host bridge or endpoint probe, enumerated downstream devices/functions, working INTx/MSI/MSI-X, correct DMA/IOMMU mappings, and no missing-clock/reset/PHY/regulator errors in boot logs.
