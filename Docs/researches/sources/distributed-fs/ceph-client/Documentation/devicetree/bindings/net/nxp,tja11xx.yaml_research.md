# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/nxp,tja11xx.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/nxp,tja11xx.yaml` defines the Linux Devicetree YAML schema for `NXP TJA11xx PHY`, a Ethernet PHY binding. The schema description says: Bindings for NXP TJA11xx automotive PHYs It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an `enum` with 12 tokens: `ethernet-phy-id0180.dc40`, `ethernet-phy-id0180.dc41`, `ethernet-phy-id0180.dc48`, `ethernet-phy-id0180.dd00`, `ethernet-phy-id0180.dd01`, `ethernet-phy-id0180.dd02`, `ethernet-phy-id0180.dc80`, `ethernet-phy-id0180.dc82`, `ethernet-phy-id001b.b010`, `ethernet-phy-id001b.b013`, `ethernet-phy-id001b.b030`, `ethernet-phy-id001b.b031`. Top-level properties are `compatible`. Top-level required properties are none declared at the top level; required properties collected from nested branches include `reg`. Patterned child schemas are `^ethernet-phy@[0-9a-f]+$`. Numeric and collection constraints include `minimum=0`, `maximum=31`. Important resource roles: `compatible` is the stable hardware ABI and OF match key. The highest-risk ABI details are PHY `reg` addresses, compatible fallbacks, reset/interrupt timing, RGMII delays, LED definitions, package topology, and vendor tuning flags.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including PHY link autonegotiation, EEE, cable diagnostics, interrupt state, reset state, per-port LEDs, and package shared state.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema closes composed schemas with `unevaluatedProperties: false`. It has 1 top-level properties and 4 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.

## Test Signals
Run `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/nxp,tja11xx.yaml` for targeted schema validation and `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/nxp,tja11xx.yaml` against boards using these nodes. High-value negative checks remove required `reg`, interrupts, clocks, resets, PHY links, MDIO children, switch ports, or GPIOs; use invalid child `reg` values; misspell vendor properties; and exercise every compatible-specific branch. Runtime integration signals are successful driver probe, correct netdev/PHY/MDIO/DSA/NFC/802.15.4 registration, clean link or controller bring-up, valid interrupt/reset/power sequencing, and no dtbs_check regressions in embedded examples or in-tree DTS users.
