# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/amlogic,axg-pcie.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/amlogic,axg-pcie.yaml` defines the Linux Devicetree YAML schema for `Amlogic Meson AXG DWC PCIe SoC controller`, a PCIe host or endpoint controller binding. The schema description says: Amlogic Meson PCIe host controller is based on the Synopsys DesignWare PCI core. It is declarative ABI documentation and validation input rather than executable kernel code; its practical role is to make DTS/DTB hardware descriptions match the resources, topology, and compatible strings expected by the relevant kernel subsystem before probe.

## Important APIs, Types, and Functions
The public API is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an ordered fallback `items` sequence and exposes 3 tokens: `amlogic,axg-pcie`, `amlogic,g12a-pcie`, `snps,dw-pcie`. Top-level properties are `compatible`, `reg`, `reg-names`, `interrupts`, `clocks`, `clock-names`, `phys`, `phy-names`, `resets`, `reset-names`, `num-lanes`, `power-domains`. Top-level required properties are `compatible`, `reg`, `reg-names`, `interrupts`, `clocks`, `clock-names`, `#address-cells`, `#size-cells`, `#interrupt-cells`, `interrupt-map`, `interrupt-map-mask`, `ranges`, `bus-range`, `device_type`, `num-lanes`, `phys`, `phy-names`, `resets`, `reset-names`; required properties collected from nested schema branches include `#address-cells`, `#interrupt-cells`, `#size-cells`, `bus-range`, `clock-names`, `clocks`, `compatible`, `device_type`, `interrupt-map`, `interrupt-map-mask`, `interrupts`, `num-lanes`, `phy-names`, `phys`, `ranges`, `reg`, `reg-names`, `reset-names`, `resets`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, bus child addresses, port selectors, or cell offsets; `reg-names` fixes resource ordering visible to drivers; `interrupts` routes status, error, RX/TX, MSI, or completion IRQs; `clocks` integrates with common clock, reset, PM, DMA/IOMMU, or reserved-memory providers; `clock-names` fixes resource ordering visible to drivers; `resets` integrates with common clock, reset, PM, DMA/IOMMU, or reserved-memory providers; `reset-names` fixes resource ordering visible to drivers; `num-lanes` is a PCIe address/window or link capability contract; `power-domains` integrates with common clock, reset, PM, DMA/IOMMU, or reserved-memory providers. The highest-risk ABI details are compatible fallback ordering, `reg`/`reg-names`, `ranges`, bus-range, MSI and interrupt-map wiring, PHY/reset/clock ordering, PERST#/wake GPIOs, link-generation and lane-count properties, and endpoint vs root-complex mode constraints.

## Control Flow
Runtime control flow is supplied by dt-schema and kernel subsystem code, not by this YAML file. `dt_binding_check` loads the meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, checks required fields, validates `minItems`/`maxItems` and enum/const constraints, validates embedded examples, and applies the closure rule. During boot, the compiled DTB node is matched by `compatible`; then platform, PCI, SDIO, SPI, MDIO, NVMEM, OPP, PCIe, netdev, wireless, accelerator, storage, clock, reset, regulator, IRQ, GPIO, IOMMU, and power-domain helpers consume the phandles and resource arrays that this schema validates. Child nodes are discovered declaratively through fixed names, pattern properties, address cells, and referenced child schemas.

## State and Persistence Behavior
The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: compatible strings, required resource names, register and interrupt ordering, phandle and cell counts, child-node names, fallback ordering, and example layouts become long-lived contracts in board DTS files and shipped DTBs. Runtime state belongs to the matching drivers and hardware after probe, including PCI host bridge registration, ECAM/config-space access, link training state, MSI domain state, DMA/IOMMU windows, endpoint BAR/function configuration, reset recovery, and runtime PM.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource-shape changes that still compile but break driver probe, link training, calibration lookup, OPP selection, NVMEM cell reads, or bus enumeration. Tightening required properties can reject existing boards; loosening them can hide missing clocks, resets, interrupts, supplies, PHY links, PCIe windows, memory regions, OPP fields, or NVMEM cells. Child-node schemas need special care because address cells, port IDs, PCI interrupt maps, wireless calibration cells, NVMEM layouts, and OPP tables must match driver-side assumptions. This schema closes composed schemas with `unevaluatedProperties: false`. It has 12 top-level properties and 12 distinct nested property names, so broad edits should be checked against all compatible variants and DTS users, not just the nominal filename.
