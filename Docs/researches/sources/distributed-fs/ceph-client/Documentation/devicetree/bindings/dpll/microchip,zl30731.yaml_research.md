# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dpll/microchip,zl30731.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Microchip Azurite DPLL device`. In this tree it is a digital phase-locked loop binding used to describe DPLL devices, pins, references, and frequency capabilities; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Microchip Azurite DPLL (ZL3073x) is a family of DPLL devices that provides up to 5 independent DPLL channels, up to 10 differential or single-ended inputs and 10 differential or 20 single-ended outputs. These devices support both I2C and SPI interfaces.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/dpll/microchip,zl30731.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `microchip,zl30731`, `microchip,zl30732`, `microchip,zl30733`, `microchip,zl30734`, `microchip,zl30735`. Required properties are `compatible`, `reg`. Important properties include `compatible`, `reg`. Referenced schemas are `/schemas/dpll/dpll-device.yaml#`, `/schemas/spi/spi-peripheral-props.yaml#`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address. The top-level closure rule is `unevaluatedProperties: false`. Maintainers: Ivan Vecera <ivecera@redhat.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/dpll/dpll-device.yaml#`, `/schemas/spi/spi-peripheral-props.yaml#`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as platform driver `of_match_table` binding through the compatible string. Conditional/schema-composition points include `allOf`, so different compatibles or child-node shapes can activate different required-property sets. It does not define nested child-node schemas.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with DPLL framework consumers and board clocking descriptions. Direct schema dependencies are `/schemas/dpll/dpll-device.yaml#`, `/schemas/spi/spi-peripheral-props.yaml#`; resource dependencies visible in the property set include platform driver `of_match_table` binding through the compatible string. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `unevaluatedProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
