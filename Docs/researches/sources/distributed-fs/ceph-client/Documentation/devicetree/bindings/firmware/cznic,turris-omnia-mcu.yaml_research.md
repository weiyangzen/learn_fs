# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/firmware/cznic,turris-omnia-mcu.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `CZ.NIC's Turris Omnia MCU`. In this tree it is a firmware interface binding used to describe secure monitor, system controller, mailbox, or service-layer communication with platform firmware; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: The MCU on Turris Omnia acts as a system controller providing additional GPIOs, interrupts, watchdog, system power off and wakeup configuration.

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/firmware/cznic,turris-omnia-mcu.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `cznic,turris-omnia-mcu`. Required properties are `compatible`, `reg`, `interrupts`, `interrupt-controller`, `gpio-controller`. Important properties include `compatible`, `reg`, `interrupts`, `interrupt-controller`, `#interrupt-cells`, `gpio-controller`, `#gpio-cells`. Referenced schemas are none declared. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `interrupts` for interrupt line routing; `interrupt-controller` for interrupt provider role; `#interrupt-cells` for interrupt specifier width; `gpio-controller` for GPIO provider role; `#gpio-cells` for GPIO specifier width. The top-level closure rule is `additionalProperties: false`. Maintainers: Marek Behún <kabel@kernel.org>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as none declared, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as GPIO provider registration, interrupt provider registration. It has no nested conditional schema branches beyond direct property validation. It does not define nested child-node schemas.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with firmware, mailbox, shared-memory, secure-monitor, system-controller, clock, reset, power, and FPGA manager drivers. Direct schema dependencies are none declared; resource dependencies visible in the property set include GPIO provider registration, interrupt provider registration. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
