# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/dsa/mediatek,mt7530.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/dsa/mediatek,mt7530.yaml` defines the DSA Ethernet switch binding titled `Mediatek MT7530 and MT7531 Ethernet Switches`. There are three versions of MT7530, standalone, in a multi-chip module and built-into a SoC. It is a Linux Devicetree YAML schema used to validate DTS/DTB nodes and to document the firmware ABI consumed before the kernel creates the corresponding distributed switch architecture node.

## Important APIs, Types, and Functions
The public interface is the YAML/dt-schema ABI, not C-callable functions. `compatible` uses `oneOf` with 6 branches with 6 tokens: `mediatek,mt7530`, `mediatek,mt7531`, `mediatek,mt7621`, `mediatek,mt7988-switch`, `airoha,en7581-switch`, `airoha,an7583-switch`. Top-level properties are `compatible`, `reg`, `core-supply`, `#gpio-cells`, `gpio-controller`, `#interrupt-cells`, `interrupt-controller`, `interrupts`, `io-supply`, `mdio`, `mediatek,mcm`, `reset-gpios`, `reset-names`, `resets`. Top-level required properties are `compatible`, `reg`; required keys found in nested schemas include `ethernet`, `compatible`, `reg`, `mediatek,mcm`, `resets`, `reset-names`, `core-supply`, `io-supply`. Pattern properties are `^(ethernet-)?ports$`. Collected numeric/item constraints include `maxItems=1`. The highest-risk API details are port numbering, CPU/DSA/user port roles, fixed-link and PHY phandles, MDIO child buses, compatible fallback ordering, interrupt/reset lines, and any vendor LED or management subnodes. Important property roles: `compatible` selects the OF match table and stable hardware ABI; `reg` carries MMIO ranges, bus addresses, chip selects, or switch port indexes; `core-supply` links a regulator supply; `#gpio-cells` fixes child-node or provider cell layout; `interrupts` routes controller, wake, link, or error IRQs; `io-supply` links a regulator supply; `mdio` defines nested network topology; `reset-gpios` controls reset, shutdown, enable, or wake sequencing; `reset-names` controls reset, shutdown, enable, or wake sequencing; `resets` controls reset, shutdown, enable, or wake sequencing.

## Control Flow
Control flow is declarative schema evaluation. During `make dt_binding_check` or `make dtbs_check`, dt-schema loads the YAML, resolves `$ref` entries, matches by `$id`, `$nodename`, `compatible`, or fragment inclusion, checks required properties, evaluates `allOf`, validates examples, and enforces `additionalProperties` or `unevaluatedProperties`. At runtime the YAML itself does not execute. Firmware provides a DTB node for the DSA Ethernet switch binding; Linux driver core or bus code matches a driver, then subsystem helpers consume the validated resources. Child schemas such as `ports`, `ethernet-ports`, MDIO children, or CAN transceiver links guide later parsing by DSA, phylink, PHYLIB, Bluetooth, or SocketCAN drivers.

## State and Persistence Behavior
The schema stores no mutable kernel state and writes no persistent data. Persistence is the Devicetree ABI: compatible strings, property names, array order, phandle cell counts, child-node names, and example layouts are contracts carried by DTS sources and deployed DTBs. Runtime state is owned by drivers after probe, including switch tree registration, port bridge/VLAN/FDB state, phylink state, MDIO transactions, CPU-port tagging, and hardware forwarding tables; this file only constrains how hardware and board wiring are represented.

## Risks
Primary risks are incompatible ABI changes to port numbering, CPU/DSA/user port roles, fixed-link and PHY phandles, MDIO child buses, compatible fallback ordering, interrupt/reset lines, and any vendor LED or management subnodes, mismatches between documented compatibles and driver OF match tables, resource-order changes that pass schema review but break probe, and stale examples. This schema closes composed schemas with `unevaluatedProperties: false`. Additional risk signals: conditional branches can validate one silicon variant while rejecting another; regex child schemas can over-match or under-match real nodes; GPIO polarity or naming mistakes can invert reset, shutdown, wake, or interrupt behavior.
