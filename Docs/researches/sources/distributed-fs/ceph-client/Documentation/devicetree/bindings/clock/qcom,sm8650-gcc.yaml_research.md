## sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/qcom,sm8650-gcc.yaml

**Purpose:** Defines the devicetree JSON-schema binding for `Qualcomm Global Clock & Reset Controller on SM8650`. This is a Qualcomm global clock controller binding; it validates clock-controller nodes rather than implementing runtime clock logic. Qualcomm global clock control module provides the clocks, resets and power domains on SM8650 See also: include/dt-bindings/clock/qcom,sm8650-gcc.h

**Important APIs/types/functions:** The schema contract is expressed through YAML/dt-schema properties, not callable functions. Key exported interface points are `compatible` accepts `qcom,sm8650-gcc`; `clocks`. Required properties are `compatible`, `clocks`, `#power-domain-cells`. The compatible contract covers `qcom,sm8650-gcc`. Provider cells are no provider cell property is declared at top level; downstream DTS consumers reference the exported clock/reset/power-domain IDs through phandles and dt-binding macros.

**Control flow:** During `dt_binding_check` or kernel devicetree validation, dt-schema loads this file under the core meta-schema, matches nodes by `compatible`, applies top-level property constraints, then evaluates 0 conditional compatibility branches from `allOf` to specialize clock names, register ranges, required inputs, or SoC-specific limits. The `examples` section supplies 1 example block that is compiled by the schema test harness as a representative DTS fragment. At boot, the matching Linux clock driver consumes the validated node, maps `reg`, acquires named parent clocks, registers common-clock providers, and optionally exposes reset or power-domain providers according to the cell properties documented here.

**State and persistence behavior:** The file persists no runtime state; it is a declarative ABI for devicetree source and compiled DTB data. Stable state is the binding contract itself: compatible strings, property names, cell counts, register tuple expectations, parent clock order, reset names, and output clock identifiers referenced from headers. DTS files that conform to this schema become firmware/kernel interface data and must remain backward compatible because existing boards may ship these nodes in firmware or bootloader-provided DTBs.

**Dependencies and integration points:** Depends on the devicetree schema toolchain, `/schemas/clock` and `/schemas/types.yaml` helpers where referenced, and Linux common clock/reset/power-domain framework drivers selected by the compatible string. Integration details include dt-binding headers `include/dt-bindings/clock/qcom`; schema references `qcom,gcc.yaml#`. Header references are `include/dt-bindings/clock/qcom`. The binding also integrates with board DTS files, SoC `.dtsi` clock topology, and client peripheral nodes that consume clock specifiers using `clocks` and clock ID macros.

**Risks:** Binding drift is the main risk: changing a compatible string, cell count, parent clock order, or required property can break existing DTS users or driver probe assumptions. Conditional schemas are easy to under-specify, especially when several SoC variants share a file but need different `clock-names`, `reg`, reset, or power-domain requirements. Loose limits such as `not specified` for `additionalProperties` should be reviewed so unknown properties are either intentionally rejected or intentionally delegated. Example fragments can become stale when headers, parent clock providers, or SoC register maps change.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/qcom,sm8650-gcc.yaml` from the kernel tree to validate this schema and compile its examples. Run `make dtbs_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/qcom,sm8650-gcc.yaml` against affected board DTS files to confirm real nodes satisfy the required properties and conditional branches. Useful review checks are that every compatible has a matching clock driver/of-match entry, every referenced dt-binding header macro exists, parent `clock-names` match driver lookup names, and reset/power-domain cell counts match consumer usage.
