# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/ethernet-phy-package.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/ethernet-phy-package.yaml` defines the Linux Devicetree YAML schema for `Ethernet PHY Package Common Properties`, a Ethernet PHY binding. The schema description says: PHY packages are multi-port Ethernet PHY of the same family and each Ethernet PHY is affected by the global configuration of the PHY package. Each reg of the PHYs defined in the PHY package node is absolute and describe the real address of the Ethernet PHY on the MDIO bus. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses a composed compatible schema with 0 tokens: no explicit compatible constants. Top-level properties are `$nodename`, `reg`, `#address-cells`, `#size-cells`. Top-level required properties are `reg`, `#address-cells`, `#size-cells`; required properties collected from nested branches include `#address-cells`, `#size-cells`, `reg`. Patterned child schemas are `^ethernet-phy@[a-f0-9]+$`. Numeric and collection constraints include `minimum=0`, `maximum=31`. Important resource roles: `reg` describes MMIO ranges, MDIO child addresses, SPI/I2C addresses, or port selectors; `#address-cells` fixes child-node or phandle specifier shape; `#size-cells` fixes child-node or phandle specifier shape. The highest-risk ABI details are PHY `reg` addresses, compatible fallbacks, reset/interrupt timing, RGMII delays, LED definitions, package topology, and vendor tuning flags.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates no top-level conditionals, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema allows unknown top-level properties. It has 4 top-level properties and 4 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.
