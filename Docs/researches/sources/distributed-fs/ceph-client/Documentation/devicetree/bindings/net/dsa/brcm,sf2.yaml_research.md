# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/dsa/brcm,sf2.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/dsa/brcm,sf2.yaml` defines the DSA Ethernet switch binding titled `Broadcom Starfighter 2 integrated switch`. It constrains compatible strings, required resources, common schema references, and optional child nodes before Linux network, Bluetooth, CAN, MDIO, Ethernet, or DSA drivers consume the node at probe time.

## Important APIs, Types, and Functions
The public interface is the YAML/dt-schema ABI, not C-callable functions. `compatible` uses an ordered fallback `items` sequence with 4 tokens: `brcm,bcm4908-switch`, `brcm,bcm7278-switch-v4.0`, `brcm,bcm7278-switch-v4.8`, `brcm,bcm7445-switch-v4.0`. Top-level properties are `compatible`, `reg`, `reg-names`, `interrupts`, `interrupt-names`, `resets`, `reset-names`, `clocks`, `clock-names`, `brcm,num-gphy`, `brcm,num-rgmii-ports`, `brcm,fcb-pause-override`, `brcm,acb-packets-inflight`, `ports`. Top-level required properties are `reg`, `interrupts`; required keys found in nested schemas include `reg`, `interrupts`, `clocks`, `clock-names`. Pattern properties are none. Collected numeric/item constraints include `minItems=6`, `maxItems=6`, `minItems=2`, `maxItems=2`, `maxItems=1`, `minItems=1`. The highest-risk API details are port numbering, CPU/DSA/user port roles, fixed-link and PHY phandles, MDIO child buses, compatible fallback ordering, interrupt/reset lines, and any vendor LED or management subnodes. Important property roles: `compatible` selects the OF match table and stable hardware ABI; `reg` carries MMIO ranges, bus addresses, chip selects, or switch port indexes; `interrupts` routes controller, wake, link, or error IRQs; `interrupt-names` routes controller, wake, link, or error IRQs; `resets` controls reset, shutdown, enable, or wake sequencing; `reset-names` controls reset, shutdown, enable, or wake sequencing; `clocks` connects clock providers and names; `clock-names` connects clock providers and names; `ports` defines nested network topology.

## Control Flow
Control flow is declarative schema evaluation. During `make dt_binding_check` or `make dtbs_check`, dt-schema loads the YAML, resolves `$ref` entries, matches by `$id`, `$nodename`, `compatible`, or fragment inclusion, checks required properties, evaluates `allOf`, validates examples, and enforces `additionalProperties` or `unevaluatedProperties`. At runtime the YAML itself does not execute. Firmware provides a DTB node for the DSA Ethernet switch binding; Linux driver core or bus code matches a driver, then subsystem helpers consume the validated resources. Child schemas such as `ports`, `ethernet-ports`, MDIO children, or CAN transceiver links guide later parsing by DSA, phylink, PHYLIB, Bluetooth, or SocketCAN drivers.

## State and Persistence Behavior
The schema stores no mutable kernel state and writes no persistent data. Persistence is the Devicetree ABI: compatible strings, property names, array order, phandle cell counts, child-node names, and example layouts are contracts carried by DTS sources and deployed DTBs. Runtime state is owned by drivers after probe, including switch tree registration, port bridge/VLAN/FDB state, phylink state, MDIO transactions, CPU-port tagging, and hardware forwarding tables; this file only constrains how hardware and board wiring are represented.

## Risks
Primary risks are incompatible ABI changes to port numbering, CPU/DSA/user port roles, fixed-link and PHY phandles, MDIO child buses, compatible fallback ordering, interrupt/reset lines, and any vendor LED or management subnodes, mismatches between documented compatibles and driver OF match tables, resource-order changes that pass schema review but break probe, and stale examples. This schema rejects unknown top-level properties with `additionalProperties: false`. Additional risk signals: conditional branches can validate one silicon variant while rejecting another; port and PHY topology mistakes may compile but break link bring-up.
