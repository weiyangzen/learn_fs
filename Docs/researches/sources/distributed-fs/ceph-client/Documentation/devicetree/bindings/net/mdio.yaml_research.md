# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/mdio.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/mdio.yaml` defines the Linux Devicetree YAML schema for `MDIO Bus Common Properties`, a MDIO bus/controller binding. The schema description says: These are generic properties that can apply to any MDIO bus. Any MDIO bus must have a list of child nodes, one per device on the bus. These should follow the generic ethernet-phy.yaml document, or a device specific binding document. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses a composed compatible schema with 0 tokens: no explicit compatible constants. Top-level properties are `$nodename`, `#address-cells`, `#size-cells`, `reset-gpios`, `reset-delay-us`, `reset-post-delay-us`, `clock-frequency`, `suppress-preamble`. Top-level required properties are none declared at the top level; required properties collected from nested branches include `reg`. Patterned child schemas are `@[0-9a-f]+$`. Numeric and collection constraints include `maxItems=1`, `minimum=0`, `maximum=31`. Important resource roles: `#address-cells` fixes child-node or phandle specifier shape; `#size-cells` fixes child-node or phandle specifier shape; `reset-gpios` defines reset-controller or GPIO reset sequencing. The highest-risk ABI details are MDIO address cells, child PHY `reg` values, controller register/clock/reset resources, and scan suppression or reset timing properties.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates no top-level conditionals, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including MDIO bus registration, PHY discovery/cache state, clause 22/45 transactions, reset sequencing, and link polling/IRQ state.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema allows unknown top-level properties. It has 8 top-level properties and 12 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.

## Test Signals
Run `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/mdio.yaml` for targeted schema validation and `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/mdio.yaml` against boards using these nodes. High-value negative checks remove required `reg`, interrupts, clocks, resets, PHY links, MDIO children, switch ports, or GPIOs; use invalid child `reg` values; misspell vendor properties; and exercise every compatible-specific branch. Runtime integration signals are successful driver probe, correct netdev/PHY/MDIO/DSA/NFC/802.15.4 registration, clean link or controller bring-up, valid interrupt/reset/power sequencing, and no dtbs_check regressions in embedded examples or in-tree DTS users.
