# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/extcon/wlf,arizona.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Cirrus Logic/Wolfson Microelectronics Arizona class audio SoCs`. In this tree it is a external connector binding used by extcon, USB Type-C, MUIC, and cable-detection drivers; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: These devices are audio SoCs with extensive digital capabilities and a range of analogue I/O. This document lists Extcon specific bindings, see the primary binding document ../mfd/arizona.yaml

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/extcon/wlf,arizona.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are none declared. Required properties are none declared. Important properties include `wlf,hpdet-channel`, `wlf,use-jd2`, `wlf,use-jd2-nopull`, `wlf,jd-invert`, `wlf,micd-software-compare`, `wlf,micd-detect-debounce`, `wlf,micd-pol-gpio`, `wlf,micd-bias-start-time`, `wlf,micd-rate`, `wlf,micd-dbtime`, `wlf,micd-timeout-ms`, `wlf,micd-force-micbias`, `wlf,micd-configs`, `wlf,gpsw`. Referenced schemas are `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-matrix`. Property roles include the schema is mostly identified by `compatible` plus bus-standard properties inherited through referenced schemas. The top-level closure rule is `additionalProperties: true`. Maintainers: patches@opensource.cirrus.com.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-matrix`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as platform driver `of_match_table` binding through the compatible string. It has no nested conditional schema branches beyond direct property validation. Nested or patterned child schema surfaces include `wlf,hpdet-channel`, `wlf,micd-detect-debounce`, `wlf,micd-bias-start-time`, `wlf,micd-rate`, `wlf,micd-dbtime`, `wlf,micd-configs`, `wlf,gpsw`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with extcon, USB, Type-C connector, MUIC, I2C, GPIO, interrupt, and OF graph code. Direct schema dependencies are `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-matrix`; resource dependencies visible in the property set include platform driver `of_match_table` binding through the compatible string. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: true` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/extcon/wlf,arizona.yaml` and `make dtbs_check` against DTS users of every compatible family. Verify inline examples compile, required-property failures are reported, compatible-specific branches are exercised, inherited schemas resolve, and drivers still probe with the resources described here. The file has no inline example block, so coverage depends on real DTS users and dtbs_check rather than schema-local examples.
