# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dma/xilinx/xlnx,axi-dma.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Xilinx AXI VDMA, DMA, CDMA and MCDMA IP`. In this tree it is a DMA engine, DMA router, or DMA-capable IP binding used by dmaengine providers and DMA client phandle specifiers; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Xilinx AXI VDMA engine, it does transfers between memory and video devices. It can be configured to have one channel or two channels. If configured as two channels, one is to transmit to the video device and another is to receive from the video device. **Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/dma/xilinx/xlnx,axi-dma.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `xlnx,axi-cdma-1.00.a`, `xlnx,axi-dma-1.00.a`, `xlnx,axi-mcdma-1.00.a`, `xlnx,axi-vdma-1.00.a`. Required properties are `#dma-cells`, `reg`, `xlnx,addrwidth`, `dma-ranges`, `clocks`, `clock-names`. Important properties include `compatible`, `reg`, `#dma-cells`, `#address-cells`, `#size-cells`, `interrupts`, `clocks`, `clock-names`, `dma-ranges`, `xlnx,addrwidth`, `xlnx,num-fstores`, `xlnx,flush-fsync`, `xlnx,sg-length-width`, `xlnx,irq-delay`, `xlnx,axistream-connected`. Referenced schemas are `/schemas/types.yaml#/definitions/uint32`, `../dma-controller.yaml#`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `#dma-cells` for DMA client specifier width; `#address-cells` for child-node address cell width; `#size-cells` for child-node size cell width; `interrupts` for interrupt line routing; `clocks` for clock provider phandles; `clock-names` for clock input names. The top-level closure rule is `unevaluatedProperties: false`. Maintainers: Radhey Shyam Pandey <radhey.shyam.pandey@amd.com>, Abin Joseph <abin.joseph@amd.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/types.yaml#/definitions/uint32`, `../dma-controller.yaml#`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as clock provider phandles. Conditional/schema-composition points include `allOf`, `patternProperties`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `xlnx,addrwidth`, `xlnx,num-fstores`, `xlnx,sg-length-width`, `xlnx,irq-delay`, `^dma-channel(-mm2s|-s2mm)?$`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with dmaengine and Devicetree DMA client code. Direct schema dependencies are `/schemas/types.yaml#/definitions/uint32`, `../dma-controller.yaml#`; resource dependencies visible in the property set include clock provider phandles. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `unevaluatedProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
