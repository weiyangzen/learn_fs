# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/i2c/sony,imx258.yaml

**Purpose:** `sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/i2c/sony,imx258.yaml` is a Linux Devicetree YAML schema for `Sony IMX258 13 Mpixel CMOS Digital Image Sensor`, a camera image sensor binding. IMX258 is a diagonal 5.867mm (Type 1/3.06) 13 Mega-pixel CMOS active pixel type stacked image sensor with a square pixel array of size 4208 x 3120. It is programmable through I2C interface. Image data is sent through MIPI CSI-2. The sensor exists in two different models, a standard variant (IMX258) and a variant with phase detection autofocus (IMX258-PDAF). The camera module does not expose the model through registers, so the exact model needs to be specified. It is declarative ABI documentation and validation input, not executable driver code. Its job is to constrain how board DTS files describe media hardware so V4L2, media-controller, remote-control, codec, bridge, sensor, clock, regulator, GPIO, DMA, and platform/I2C driver code can discover the expected resources.

**Important APIs/types/functions:** The public API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and any OF graph or child-node patterns. `compatible` uses `enum` list and covers 2 compatible tokens: `sony,imx258`, `sony,imx258-pdaf`. Top-level properties are `compatible`, `clocks`, `reg`, `reset-gpios`, `vana-supply`, `vdig-supply`, `vif-supply`, `port`. Top-level required properties are `compatible`, `reg`, `clocks`, `port`; required properties found across nested schemas include `clocks`, `compatible`, `data-lanes`, `link-frequencies`, `port`, `reg`. The node acts as a I2C client node selected by parent bus address cells. Important property roles: `compatible` selects the OF match table entry and stable hardware ABI; `clocks` binds clock inputs, outputs, or rates; `reg` carries the I2C address or MMIO register range; `reset-gpios` controls hardware reset, enable, or power-down sequencing; `vana-supply` links power rails or power-domain providers; `vdig-supply` links power rails or power-domain providers; `vif-supply` links power rails or power-domain providers; `port` describes media-controller OF graph links and endpoint topology. Patterned child schemas are none; graph or child-node properties discovered in nested schemas are `endpoint`, `port`. Numeric/item constraints include no explicit numeric min/max/item limits collected.

**Control flow:** Control flow is dt-schema evaluation rather than imperative logic. `dt_binding_check` loads the core meta-schema, resolves every `$ref`, applies `properties`, `required`, item/count limits, and composition branches, validates inline examples, and enforces the unknown-property policy. At runtime the YAML is not executed: the compiled DTB node is matched through the driver's OF table, and media graph parsing follows `port`/`ports` endpoints to connect sensors, bridges, serializers, deserializers, receivers, codecs, and SoC capture or processing blocks. Resource acquisition then proceeds through standard helpers for I2C/platform devices, regulators, clocks, resets, GPIOs, IRQs, DMA/IOMMU, firmware, and child remote buses when those properties are present.

**State and persistence behavior:** The schema has no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted compatible strings, required supplies/clocks/resets/IRQs, endpoint lane layouts, child-node names, remote-I2C topology, and MMIO or I2C address shapes become long-lived DTB contracts. Runtime state such as video streaming, link training, sensor mode selection, codec sessions, remote serializer state, radio tuning, frame buffers, and power sequencing belongs to the matching kernel drivers and hardware.

**Risks:** Risks center on Devicetree ABI drift and media graph mismatches. Changing compatible values or fallback order can break driver binding; renaming supplies, clocks, GPIOs, interrupts, reset lines, `#*-cells`, or child nodes can break probe-time resource lookup; tightening endpoint lane counts or port numbering can reject valid boards or silently disconnect media links. Serializer/deserializer bindings add risk around remote I2C aliases, PoC supplies, GPIO forwarding, and link topology. Codec and SoC processing bindings add risk around clocks, power domains, IOMMU/DMA resources, and firmware/mailbox style dependencies.
