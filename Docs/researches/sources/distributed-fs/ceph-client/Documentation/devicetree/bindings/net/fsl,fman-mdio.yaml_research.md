# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/fsl,fman-mdio.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/fsl,fman-mdio.yaml` defines the Linux Devicetree YAML schema for `Freescale Frame Manager MDIO Device`, a MDIO bus/controller binding. The schema description says: FMan MDIO Node. The MDIO is a bus to which the PHY devices are connected. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an `enum` with 3 tokens: `fsl,fman-mdio`, `fsl,fman-xmdio`, `fsl,fman-memac-mdio`. Top-level properties are `compatible`, `reg`, `clocks`, `interrupts`, `fsl,fman-internal-mdio`, `fsl,erratum-a009885`, `fsl,erratum-a011043`, `little-endian`. Top-level required properties are `compatible`, `reg`; required properties collected from nested branches include `compatible`, `reg`. Patterned child schemas are none. Numeric and collection constraints include `maxItems=1`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, MDIO child addresses, SPI/I2C addresses, or port selectors; `clocks` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `interrupts` routes link/status, RX/TX, error, or management IRQs. The highest-risk ABI details are MDIO address cells, child PHY `reg` values, controller register/clock/reset resources, and scan suppression or reset timing properties.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including MDIO bus registration, PHY discovery/cache state, clause 22/45 transactions, reset sequencing, and link polling/IRQ state.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema closes composed schemas with `unevaluatedProperties: false`. It has 8 top-level properties and 8 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.

High-value negative checks remove required `reg`, interrupts, clocks, resets, PHY links, MDIO children, switch ports, or GPIOs; use invalid child `reg` values; misspell vendor properties; and exercise every compatible-specific branch. Runtime integration signals are successful driver probe, correct netdev/PHY/MDIO/DSA/NFC/802.15.4 registration, clean link or controller bring-up, valid interrupt/reset/power sequencing, and no dtbs_check regressions in embedded examples or in-tree DTS users.
