## sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/renesas,cpg-clocks.yaml

**Purpose:** Defines the devicetree JSON-schema binding for `Renesas Clock Pulse Generator (CPG)`. This is a Renesas clock generator binding; it validates clock-controller nodes rather than implementing runtime clock logic. The Clock Pulse Generator (CPG) generates core clocks for the SoC. It includes PLLs, and fixed and variable ratio dividers. The CPG may also provide a Clock Domain for SoC devices, in combination with the CPG Module S...

**Important APIs/types/functions:** The schema contract is expressed through YAML/dt-schema properties, not callable functions. Key exported interface points are `compatible` accepts `renesas,r8a73a4-cpg-clocks`, `renesas,r8a7740-cpg-clocks`, `renesas,r8a7778-cpg-clocks`, `renesas,r8a7779-cpg-clocks`, `renesas,r7s72100-cpg-clocks`, `renesas,rz-cpg-clocks`, `renesas,sh73a0-cpg-clocks`; `reg` (maxItems=1); `clocks` (minItems=1, maxItems=3); `#clock-cells` (const=1); `#power-domain-cells` (const=0); `clock-output-names` (minItems=3, maxItems=17); `renesas,mode`. Required properties are `compatible`, `reg`, `clocks`, `#clock-cells`, `clock-output-names`. The compatible contract covers `renesas,r8a73a4-cpg-clocks`, `renesas,r8a7740-cpg-clocks`, `renesas,r8a7778-cpg-clocks`, `renesas,r8a7779-cpg-clocks`, `renesas,r7s72100-cpg-clocks`, `renesas,rz-cpg-clocks`, `renesas,sh73a0-cpg-clocks`. Provider cells are `#clock-cells`=1, `#power-domain-cells`=0; downstream DTS consumers reference the exported clock/reset/power-domain IDs through phandles and dt-binding macros.

**Control flow:** During `dt_binding_check` or kernel devicetree validation, dt-schema loads this file under the core meta-schema, matches nodes by `compatible`, applies top-level property constraints, then evaluates 7 conditional compatibility branches from `allOf` to specialize clock names, register ranges, required inputs, or SoC-specific limits. The `examples` section supplies 1 example block that is compiled by the schema test harness as a representative DTS fragment. At boot, the matching Linux clock driver consumes the validated node, maps `reg`, acquires named parent clocks, registers common-clock providers, and optionally exposes reset or power-domain providers according to the cell properties documented here.

**State and persistence behavior:** The file persists no runtime state; it is a declarative ABI for devicetree source and compiled DTB data. Stable state is the binding contract itself: compatible strings, property names, cell counts, register tuple expectations, parent clock order, reset names, and output clock identifiers referenced from headers. DTS files that conform to this schema become firmware/kernel interface data and must remain backward compatible because existing boards may ship these nodes in firmware or bootloader-provided DTBs.

**Dependencies and integration points:** Depends on the devicetree schema toolchain, `/schemas/clock` and `/schemas/types.yaml` helpers where referenced, and Linux common clock/reset/power-domain framework drivers selected by the compatible string. Integration details include schema references `/schemas/types.yaml#/definitions/uint32`; generic power-domain provider/consumer bindings. Header references are none declared. The binding also integrates with board DTS files, SoC `.dtsi` clock topology, and client peripheral nodes that consume clock specifiers using `clocks` and clock ID macros.

**Risks:** Binding drift is the main risk: changing a compatible string, cell count, parent clock order, or required property can break existing DTS users or driver probe assumptions. Conditional schemas are easy to under-specify, especially when several SoC variants share a file but need different `clock-names`, `reg`, reset, or power-domain requirements. Loose limits such as `False` for `additionalProperties` should be reviewed so unknown properties are either intentionally rejected or intentionally delegated. Example fragments can become stale when headers, parent clock providers, or SoC register maps change.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/renesas,cpg-clocks.yaml` from the kernel tree to validate this schema and compile its examples. Run `make dtbs_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/renesas,cpg-clocks.yaml` against affected board DTS files to confirm real nodes satisfy the required properties and conditional branches. Useful review checks are that every compatible has a matching clock driver/of-match entry, every referenced dt-binding header macro exists, parent `clock-names` match driver lookup names, and reset/power-domain cell counts match consumer usage.
