# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/brcm,iproc-pcie.yaml

**Purpose:** Defines the Devicetree YAML/JSON-schema contract for `Broadcom iProc PCIe controller with the platform bus interface`. It is a host/root-complex controller binding in the Broadcom PCIe host-controller family; it constrains how DTS/DTB nodes identify the PCI hardware, describe register windows, interrupts, clocks, resets, PHYs, address translation, DMA/IOMMU reachability, and optional child/root-port layout for Linux PCI probing.

**Important APIs/types/functions:** This file is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/pci/brcm,iproc-pcie.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, the `properties` block, `required` list, schema-composition keywords, inline examples, and the compatible strings consumed by kernel OF match tables. Compatible strings covered here: `brcm,iproc-msi`, `brcm,iproc-pcie`, `brcm,iproc-pcie-paxb-v2`, `brcm,iproc-pcie-paxc`, `brcm,iproc-pcie-paxc-v2`. Directly declared properties are `compatible`, `reg`, `ranges`, `phys`, `phy-names`, `dma-coherent`, `brcm,pcie-ob`, `brcm,pcie-ob-axi-offset`, `msi`, `msi-parent`. Required properties are `compatible`, `reg`, `ranges`. Maintainers: Ray Jui <ray.jui@broadcom.com>, Scott Branden <scott.branden@broadcom.com>.

**Control flow:** Validation flow is handled by dt-schema: the core meta-schema loads this YAML, resolves references (`/schemas/interrupt-controller/msi-controller.yaml#`, `/schemas/pci/pci-host-bridge.yaml#`, `/schemas/types.yaml#/definitions/uint32`), applies direct property constraints, evaluates top-level `allOf` composition, and then applies conditional branches. Conditional behavior: for brcm,iproc-pcie, adds/restricts `interrupt-map`, `interrupt-map-mask`. At runtime the compiled DTB has no code from this file; the kernel matches `compatible`, maps `reg` resources, programs PCI ranges, requests interrupts/MSI mappings, enables clocks/resets/regulators/PHYs/power domains, and creates host bridge/root-port or endpoint objects according to the described node.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability for board DTS files and shipped DTBs: compatible ordering, resource names, cell counts, interrupt maps, address ranges, and child-node layout become the long-lived contract that drivers and firmware rely on. For this file, the top-level and composed unknown-property policy is: unevaluatedProperties: false.

**Dependencies:** Direct schema dependencies are `/schemas/interrupt-controller/msi-controller.yaml#`, `/schemas/pci/pci-host-bridge.yaml#`, `/schemas/types.yaml#/definitions/uint32`. Resource dependencies visible in the binding include `compatible` (driver OF match key and binding ABI identifier); `reg` (MMIO/config/address-space resource tuples); `ranges` (PCI address translation windows exposed by the host bridge); `phys` (PHY phandles for PCIe lanes); `phy-names` (stable PHY names); `dma-coherent` (coherency attribute for DMA transactions); `msi-parent` (external MSI provider reference) The binding also depends on the broader Devicetree PCI schemas, dt-schema tooling, and matching Linux PCI host/endpoint drivers for the compatible strings above.

**Integration points:** Integrates with Linux OF platform matching through `compatible`, PCI core setup through `device_type`, `bus-range`, `ranges`, `dma-ranges`, `#address-cells`, and `#size-cells`, interrupt infrastructure through `interrupt-map`, `interrupts`, MSI controllers or `msi-map`, and SoC resource managers through clocks, resets, PHY, regulator, power-domain, and IOMMU properties. Nested integration surface: child/object property `msi`.

**Risks:** Main risks are ABI drift in required properties, accepting a DTS shape that the driver cannot probe, rejecting valid legacy boards, stale examples, wrong `reg-names`/`clock-names`/`reset-names` ordering, incomplete compatible coverage, and conditional branches whose `contains`/`enum` logic does not match real fallback-compatible ordering. PCI-specific risk is high around address translation and interrupts: bad `ranges`, `dma-ranges`, `iommu-map`, `msi-map`, or `interrupt-map-mask` can validate syntactically while producing unprobeable devices or broken DMA/MSI at runtime.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/brcm,iproc-pcie.yaml` to validate this schema and its 2 inline example block(s). Run `make dtbs_check` for DTS users of each compatible string to exercise conditional branches, referenced schemas, child-node validation, closure policy, and resource-name ordering. Runtime smoke signals are successful PCI host bridge or endpoint probe, enumerated downstream devices/functions, working INTx/MSI/MSI-X, correct DMA/IOMMU mappings, and no missing-clock/reset/PHY/regulator errors in boot logs.
