# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/clock/qcom,gpucc.yaml

Purpose: YAML Devicetree schema for `Qualcomm Graphics Clock & Reset Controller`. It documents and validates nodes with compatibles `qcom,qcs8300-gpucc`, `qcom,sdm845-gpucc`, `qcom,sa8775p-gpucc`, `qcom,sc7180-gpucc`, `qcom,sc7280-gpucc`, `qcom,sc8180x-gpucc`, `qcom,sc8280xp-gpucc`, `qcom,sm6350-gpucc`, `qcom,sm8150-gpucc`, `qcom,sm8250-gpucc`, `qcom,sm8350-gpucc`. Qualcomm graphics clock control module provides the clocks, resets and power domains on Qualcomm SoCs. See also:: include/dt-bindings/clock/qcom,gpucc-sdm845.h include/dt-bindings/clock/qcom,gpucc-sa8775p.h include/dt-bindings/clock/qcom,gpucc-sc7180.h include/dt-bindings/clock/qcom,gpucc-sc7280.h include/dt-bindings/clock/qcom,gpucc-sc8280xp.h include/dt-bindings/clock/qcom,gpucc-sm6350.h include/dt-bindings/clock/qcom,gpucc-sm8150.h include/dt-bindings/clock/qcom,gpucc-sm8250.h include/dt-bindings/clock/qcom,gpucc-sm8350.h include/dt-bindings/clock/qcom,qcs8300-gpucc.h

Important APIs/types/functions: This file is a schema contract rather than runtime code. Its externally visible API is the accepted `compatible` set (`qcom,qcs8300-gpucc`, `qcom,sdm845-gpucc`, `qcom,sa8775p-gpucc`, `qcom,sc7180-gpucc`, `qcom,sc7280-gpucc`, `qcom,sc8180x-gpucc`, `qcom,sc8280xp-gpucc`, `qcom,sm6350-gpucc`, `qcom,sm8150-gpucc`, `qcom,sm8250-gpucc`, `qcom,sm8350-gpucc`), required properties (`compatible`, `clocks`, `clock-names`, `#power-domain-cells`), and provider/consumer ABI described by `compatible`, `clocks`, `clock-names`, `power-domains` max 1 item(s), `vdd-gfx-supply`. provider cell count is inherited or not the main contract for this binding.

Control flow: There is no executable control flow. Validation flows through `dt-schema`: the YAML document is loaded against the core meta-schema, a DTS node's `compatible` selects this binding, `required` enforces mandatory fields, and allOf handle variant-specific shape. The examples exercise nodes such as clock-controller and provide schema smoke coverage.

State and persistence behavior: The binding persists hardware description in DTS and compiled DTB files. Clock, reset, and power-domain identifiers referenced by consumers become stable ABI between board DTS files, dt-binding headers, and Linux providers. The schema stores no runtime state; boot-time state appears when the matched driver maps `reg`, registers providers, and applies any parent clock, assigned-clock, reset, or power-domain relationships encoded in the node.

Dependencies and integration points: Depends on dt-binding headers `dt-bindings/clock/qcom,gcc-sdm845.h`, `dt-bindings/clock/qcom,gpucc-sa8775p.h`, `dt-bindings/clock/qcom,gpucc-sc7180.h`, `dt-bindings/clock/qcom,gpucc-sc7280.h`, `dt-bindings/clock/qcom,gpucc-sc8280xp.h`, `dt-bindings/clock/qcom,gpucc-sdm845.h`, `dt-bindings/clock/qcom,gpucc-sm6350.h`, `dt-bindings/clock/qcom,gpucc-sm8150.h`, and 4 more; schema refs `qcom,gcc.yaml#`; composition/conditional keys `allOf`. Integration is primarily with Qualcomm common clock framework drivers match these `qcom,*` compatibles and expose GCC/MMCC/GPUCC/DISPCC/CAMCC/RPM/RPMh or PLL clock IDs from matching dt-bindings headers. Downstream device nodes consume the exported resources through phandles, so `#clock-cells`, `#reset-cells`, `#power-domain-cells`, `clock-names`, and header-defined IDs must remain synchronized with provider drivers and DTS users. Key control inputs modeled here are parent input clocks, named parent inputs, power-domain attachment.

Risks: The main risk is ABI drift: changing compatible strings, provider cell counts, required properties, or header IDs can break existing DTS files or driver probing. A wrong `reg` range can bind the driver to the wrong MMIO block, and missing parent clocks, power domains, resets, supplies, or assigned-clock data can defer probe or leave hardware ungated. Because this schema forbids unknown properties, new board-specific properties need explicit schema support.

Test signals: Run Devicetree schema checks such as `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/clock/qcom,gpucc.yaml` and DTS validation for boards using `qcom,qcs8300-gpucc`, `qcom,sdm845-gpucc`, `qcom,sa8775p-gpucc`, `qcom,sc7180-gpucc`, `qcom,sc7280-gpucc`, `qcom,sc8180x-gpucc`, and 5 more. Good signals include clean example validation, no unresolved `$ref` or include paths, provider cell counts matching dt-binding headers, and boot logs showing the matching clock/reset driver registering expected providers without probe deferral.
