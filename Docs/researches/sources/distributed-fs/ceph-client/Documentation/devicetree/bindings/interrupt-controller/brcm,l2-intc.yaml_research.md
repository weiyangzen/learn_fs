# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/brcm,l2-intc.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/brcm,l2-intc.yaml` is a Linux devicetree YAML schema for the `Broadcom Generic Level 2 Interrupt Controller` interrupt-controller binding. It is not executable kernel code; it is the hardware-description ABI that DTS authors, dt-schema, and the relevant kernel subsystem rely on so the runtime driver can parse the node without board-specific ambiguity.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses `oneOf` with 4 accepted compatible forms and covers 5 compatible tokens: `brcm,hif-spi-l2-intc`, `brcm,upg-aux-aon-l2-intc`, `brcm,l2-intc`, `brcm,bcm2711-l2-intc`, `brcm,bcm7271-l2-intc`. Top-level properties are `compatible`, `reg`, `interrupt-controller`, `#interrupt-cells`, `interrupts`, `interrupt-names`, `brcm,irq-can-wake`. Across nested schemas and child nodes this file mentions 7 distinct property names; nested/all required properties include `#interrupt-cells`, `compatible`, `interrupt-controller`, `interrupts`, `reg`. Node naming is constrained by no explicit node-name constraint. Interrupt-controller-facing properties define how child devices encode interrupt specifiers and how the kernel irqchip or MSI domain driver maps them: addressing resources `reg`, domain declarations `interrupt-controller`, `#interrupt-cells`, `interrupts`, `interrupt-names`, clock/reset/power hooks none, and any GPIO or parent-domain links none. Required properties are `compatible`, `reg`, `interrupt-controller`, `#interrupt-cells`, `interrupts`; the shape of `#interrupt-cells` and parent interrupt wiring is the main ABI exposed to DTS consumers.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation rather than executable branching. `dt-doc-validate` and `dt_binding_check` load the YAML, expand `$ref` links, apply composition and conditional keywords, validate the DTS example blocks, and later `dtbs_check` applies the same contract to compiled board devicetrees. For irqchip and MSI providers, validation ensures the interrupt domain, specifier cell count, parent interrupt lines, MSI doorbells, and child-node encoding match what the kernel interrupt-controller driver will parse during early boot or bus enumeration. The schema itself stores no mutable state and writes no persistent data; its persistence is the stable source-controlled hardware ABI. External references used in evaluation are `/schemas/interrupt-controller.yaml#`; top-level/nested conditional keywords present are `allOf`, `oneOf`.

## Risks
Risks are mostly ABI and validation risks rather than algorithmic failures. Tightening required properties, changing compatible ordering, renaming resources, altering cell counts, or closing extra properties can reject existing DTS users; loosening constraints can allow nodes that later fail driver probe or misdescribe hardware. This schema has 7 top-level properties and 7 distinct nested property names, with strictness profile: unknown top-level properties are rejected. Conditional branches and shared `$ref` schemas should be checked against all in-tree users before edits, because a schema-only patch can still break board builds.

## Test Signals
Primary validation is `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/interrupt-controller/brcm,l2-intc.yaml` plus `make dtbs_check` on in-tree boards using `brcm,hif-spi-l2-intc`, `brcm,upg-aux-aon-l2-intc`, `brcm,l2-intc`, `brcm,bcm2711-l2-intc`, `brcm,bcm7271-l2-intc`. The 1 example block in this file should compile under dt-schema and remain representative of the required properties. Useful integration signals include irqchip/MSI domain registration during boot, correct parent IRQ routing, valid child interrupt specifier lengths, interrupt delivery tests from devices below the domain, and no early-boot warnings about missing cells, ranges, or register resources.
