# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/mediatek,mtu3.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/mediatek,mtu3.yaml` defines `MediaTek USB3 DRD Controller`, a USB3/xHCI or dual-role controller binding. The DRD controller has a glue layer IPPC (IP Port Control), and its host is based on xHCI. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (`allOf`, `dependencies`); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: host/gadget/OTG role, endpoint/transfer rings, event interrupts, runtime PM, PHY state, wakeup behavior, and controller reset/recovery state. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around controller compatible strings, register and interrupt ordering, PHY arrays, `dr_mode`, role-switch wiring, clock/reset names, child-port layout, and vendor quirk properties; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile rejects undeclared top-level properties with `additionalProperties: false`.
