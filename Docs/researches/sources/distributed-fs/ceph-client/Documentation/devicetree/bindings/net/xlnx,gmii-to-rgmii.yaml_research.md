# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/xlnx,gmii-to-rgmii.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/xlnx,gmii-to-rgmii.yaml` defines the Linux Devicetree YAML schema for `Xilinx GMII to RGMII Converter`, a Xilinx Ethernet datapath binding. The schema description says: The Gigabit Media Independent Interface (GMII) to Reduced Gigabit Media Independent Interface (RGMII) core provides the RGMII between RGMII-compliant ethernet physical media devices (PHY) and the Gigabit Ethernet controller. This core can be used in all three modes of operation(10/100/1000 Mb/s). The Management Data Input/Output (MDIO) interface is used to configure the speed of operation. This core can switch dynamically between the three different speed modes by configuring the converter register through mdio write. The core cannot function without an external phy connected to it. It is declarative ABI documentation and validation input rather than executable kernel code; its practical role is to make DTS/DTB hardware descriptions match the resources, topology, and compatible strings expected by the relevant kernel subsystem before probe.

## Important APIs, Types, and Functions
The public API is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses a single `const` and exposes 1 token: `xlnx,gmii-to-rgmii-1.0`. Top-level properties are `compatible`, `reg`, `phy-handle`, `clocks`. Top-level required properties are `compatible`, `reg`, `phy-handle`; required properties collected from nested schema branches include `compatible`, `phy-handle`, `reg`. Patterned child schemas are none. Numeric and collection constraints include `minimum=0`, `maximum=31`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, bus child addresses, port selectors, or cell offsets; `phy-handle` connects Ethernet datapath, PHY, PCS, MDIO, or stream topology; `clocks` integrates with common clock, reset, PM, DMA/IOMMU, or reserved-memory providers. The highest-risk ABI details are AXI register windows, DMA/stream connection modelling, PHY or converter phandles, clock/reset ordering, interrupt mapping, and Xilinx-specific capability flags.

## Control Flow
Runtime control flow is supplied by dt-schema and kernel subsystem code, not by this YAML file. `dt_binding_check` loads the meta-schema, resolves `$ref` entries, applies `properties`, evaluates no top-level conditionals, checks required fields, validates `minItems`/`maxItems` and enum/const constraints, validates embedded examples, and applies the closure rule. During boot, the compiled DTB node is matched by `compatible`; then platform, PCI, SDIO, SPI, MDIO, NVMEM, OPP, PCIe, netdev, wireless, accelerator, storage, clock, reset, regulator, IRQ, GPIO, IOMMU, and power-domain helpers consume the phandles and resource arrays that this schema validates. Child nodes are discovered declaratively through fixed names, pattern properties, address cells, and referenced child schemas.

## State and Persistence Behavior
The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: compatible strings, required resource names, register and interrupt ordering, phandle and cell counts, child-node names, fallback ordering, and example layouts become long-lived contracts in board DTS files and shipped DTBs. Runtime state belongs to the matching drivers and hardware after probe, including netdev registration, DMA descriptor/ring state, NAPI scheduling, MDIO transactions, PHY link state, MAC address configuration, and runtime PM.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource-shape changes that still compile but break driver probe, link training, calibration lookup, OPP selection, NVMEM cell reads, or bus enumeration. Tightening required properties can reject existing boards; loosening them can hide missing clocks, resets, interrupts, supplies, PHY links, PCIe windows, memory regions, OPP fields, or NVMEM cells. Child-node schemas need special care because address cells, port IDs, PCI interrupt maps, wireless calibration cells, NVMEM layouts, and OPP tables must match driver-side assumptions. This schema closes composed schemas with `unevaluatedProperties: false`. It has 4 top-level properties and 4 distinct nested property names, so broad edits should be checked against all compatible variants and DTS users, not just the nominal filename.
