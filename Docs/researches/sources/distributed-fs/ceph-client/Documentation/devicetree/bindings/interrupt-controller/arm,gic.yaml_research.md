# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/arm,gic.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/arm,gic.yaml` is a Linux devicetree YAML schema for the `ARM Generic Interrupt Controller v1 and v2` ARM interrupt-controller binding. ARM SMP cores are often associated with a GIC, providing per processor interrupts (PPI), shared processor interrupts (SPI) and software generated interrupts (SGI). Primary GIC is attached directly to the CPU and typically has PPIs and SGIs. Secondary GICs are cascaded into the upward interrupt controller and do not have PPIs or SGIs. It is not executable kernel code; it is the hardware-description ABI that DTS authors, dt-schema, and the relevant kernel subsystem rely on so the runtime driver can parse the node without board-specific ambiguity.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses `oneOf` with 5 accepted compatible forms and covers 18 compatible tokens: `arm,arm11mp-gic`, `arm,cortex-a15-gic`, `arm,cortex-a7-gic`, `arm,cortex-a5-gic`, `arm,cortex-a9-gic`, `arm,eb11mp-gic`, `arm,gic-400`, `arm,pl390`, `arm,tc11mp-gic`, `qcom,msm-8660-qgic`, `qcom,msm-qgic2`, `arm,arm1176jzf-devchip-gic`, `brcm,brahma-b15-gic`, `nvidia,tegra210-agic`, `nvidia,tegra186-agic`, `nvidia,tegra194-agic`, `nvidia,tegra234-agic`, `nvidia,tegra264-agic`. Top-level properties are `compatible`, `interrupt-controller`, `#address-cells`, `#size-cells`, `#interrupt-cells`, `reg`, `ranges`, `interrupts`, `cpu-offset`, `clocks`, `clock-names`, `power-domains`, `resets`. Across nested schemas and child nodes this file mentions 16 distinct property names; nested/all required properties include `compatible`, `msi-controller`, `reg`. Node naming is constrained by no explicit node-name constraint. Interrupt-controller-facing properties define how child devices encode interrupt specifiers and how the kernel irqchip or MSI domain driver maps them: addressing resources `#address-cells`, `#size-cells`, `reg`, `ranges`, domain declarations `interrupt-controller`, `#interrupt-cells`, `interrupts`, clock/reset/power hooks `clocks`, `clock-names`, `power-domains`, `resets`, and any GPIO or parent-domain links none. Required properties are `compatible`, `reg`; the shape of `#interrupt-cells` and parent interrupt wiring is the main ABI exposed to DTS consumers.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation rather than executable branching. `dt-doc-validate` and `dt_binding_check` load the YAML, expand `$ref` links, apply composition and conditional keywords, validate the DTS example blocks, and later `dtbs_check` applies the same contract to compiled board devicetrees. For irqchip and MSI providers, validation ensures the interrupt domain, specifier cell count, parent interrupt lines, MSI doorbells, and child-node encoding match what the kernel interrupt-controller driver will parse during early boot or bus enumeration. The schema itself stores no mutable state and writes no persistent data; its persistence is the stable source-controlled hardware ABI. External references used in evaluation are `/schemas/interrupt-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`; top-level/nested conditional keywords present are `allOf`, `oneOf`.

## Dependencies and Integration Points
Maintainers: Marc Zyngier <marc.zyngier@arm.com>. Integration points include the Linux devicetree schema meta-schema, common bindings referenced through `$ref`, DTS/DTSI board files in the Ceph-client kernel tree, and subsystem drivers that match the compatible strings. Pattern properties are `^v2m@[0-9a-f]+$`; the file provides 3 example blocks. Runtime dependencies commonly include early irqchip initialization, hierarchical interrupt domains, MSI/MSI-X domains where present, parent interrupt controllers, and bus/device nodes that consume the domain through `interrupts`, `interrupts-extended`, or MSI-parent links.

## Risks
Risks are mostly ABI and validation risks rather than algorithmic failures. Tightening required properties, changing compatible ordering, renaming resources, altering cell counts, or closing extra properties can reject existing DTS users; loosening constraints can allow nodes that later fail driver probe or misdescribe hardware. This schema has 13 top-level properties and 16 distinct nested property names, with strictness profile: unknown top-level properties are rejected. Conditional branches and shared `$ref` schemas should be checked against all in-tree users before edits, because a schema-only patch can still break board builds.

## Test Signals
Primary validation is `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/interrupt-controller/arm,gic.yaml` plus `make dtbs_check` on in-tree boards using `arm,arm11mp-gic`, `arm,cortex-a15-gic`, `arm,cortex-a7-gic`, `arm,cortex-a5-gic`, `arm,cortex-a9-gic`, `arm,eb11mp-gic`, `arm,gic-400`, `arm,pl390`, and 10 more. The 3 example blocks in this file should compile under dt-schema and remain representative of the required properties. Useful integration signals include irqchip/MSI domain registration during boot, correct parent IRQ routing, valid child interrupt specifier lengths, interrupt delivery tests from devices below the domain, and no early-boot warnings about missing cells, ranges, or register resources.
