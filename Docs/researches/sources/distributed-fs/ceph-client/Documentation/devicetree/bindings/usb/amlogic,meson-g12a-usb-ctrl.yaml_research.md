# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/amlogic,meson-g12a-usb-ctrl.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/amlogic,meson-g12a-usb-ctrl.yaml` defines `Amlogic Meson G12A DWC3 USB SoC Controller Glue`, a Synopsys DesignWare USB3 glue-controller binding. The Amlogic G12A embeds a DWC3 USB IP Core configured for USB2 and USB3 in host-only mode, and a DWC2 IP Core configured for USB2 peripheral mode only. A glue connects the DWC3 core to USB2 PHYs and optionally to an USB3 PHY. One of the USB2 PHYs can be re-routed in peripheral mode to a DWC2 USB IP. The DWC3 Glue controls the PHY routing and power, an interrupt line is connected to the Glue to serve as OTG ID change detection. The Amlogic A1 embeds a DWC3 USB IP Core configured for USB2 in host-only mode. The Amlogic GXL, GXM & AXG SoCs doesn't embed an USB3 PHY. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Risks
Main risks are ABI drift around glue compatible order, wrapper and core register ranges, child-node layout, clock/reset naming, PHY linkage, DRD role properties, and SoC-specific conditionals; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile rejects undeclared top-level properties with `additionalProperties: false`.
