# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/intel,ixp4xx-udc.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/intel,ixp4xx-udc.yaml` defines `Intel IXP4xx SoC USB Device Controller (UDC)`, a USB device-controller binding. The IXP4xx SoCs has a full-speed USB Device Controller with 16 endpoints and a built-in transceiver. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

The exported API is the Devicetree node contract. `$id` is `http://devicetree.org/schemas/usb/intel,ixp4xx-udc.yaml#` and `$schema` is `http://devicetree.org/meta-schemas/core.yaml#`. `compatible` uses single `const` and exposes 1 compatible token: `intel,ixp4xx-udc`. Top-level required properties are `compatible`, `reg`, `interrupts`; required properties discovered in nested branches are `compatible`, `interrupts`, `reg`. Patterned child schemas are none; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry; `reg` describes MMIO windows, bus addresses, or register resources; `interrupts` maps controller, GPIO, or Type-C events into IRQ domains. ## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (none); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. ## State and Persistence Behavior

## Risks
Main risks are ABI drift around device-controller compatible strings, endpoint/port child resources, interrupt layout, clocks/resets, VBUS or pull-up GPIOs, and gadget mode constraints; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile rejects undeclared top-level properties with `additionalProperties: false`.
