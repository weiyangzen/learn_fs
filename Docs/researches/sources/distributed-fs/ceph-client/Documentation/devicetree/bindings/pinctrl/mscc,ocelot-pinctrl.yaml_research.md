# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pinctrl/mscc,ocelot-pinctrl.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pinctrl/mscc,ocelot-pinctrl.yaml` defines the Microsemi Ocelot pin controller and GPIO binding titled `Microsemi Ocelot pin controller`. It is a Linux devicetree YAML schema for pin-controller validation. The binding is part of the kernel devicetree ABI for describing hardware pin muxing, GPIO exposure, interrupt routing, and electrical pin configuration before the corresponding drivers probe.

## Important APIs, Types, and Functions
The API surface is the devicetree schema, not callable code. Supported compatible values are `microchip,lan96455f-pinctrl`, `microchip,lan966x-pinctrl`, `microchip,lan9691-pinctrl`, `microchip,sparx5-pinctrl`, `mscc,jaguar2-pinctrl`, `mscc,luton-pinctrl`, `mscc,ocelot-pinctrl`, `mscc,serval-pinctrl`, `mscc,servalt-pinctrl`, `microchip,lan9698-pinctrl`, `microchip,lan9696-pinctrl`, `microchip,lan9694-pinctrl`, and 4 more. Top-level properties are `compatible`, `reg`, `gpio-controller`, `#gpio-cells`, `gpio-ranges`, `interrupts`, `interrupt-controller`, `#interrupt-cells`, `resets`, `reset-names`. Required top-level properties are `compatible`, `reg`, `gpio-controller`, `#gpio-cells`, `gpio-ranges`. Nested required keys include `function`, `pins`, `compatible`, `reg`, `gpio-controller`, `#gpio-cells`, `gpio-ranges`. The important child-node contracts are: child patterns `-pins$`; configuration keys include `output-low`, `output-high`, `drive-strength`. The highest-risk ABI surface is SoC compatible selection, GPIO range exposure, interrupt-controller cells, reset naming, mux groups, output-high/low, and drive-strength.

## Control Flow
Control flow is declarative schema evaluation. `dt_binding_check` loads the YAML, validates extracted examples against referenced common schemas, and then `dtbs_check` matches real DTS nodes by `compatible` or by inclusion from another schema. The validator checks required properties, constants, enum values, array sizes, pattern-matched child nodes, and composition branches such as `allOf`. Runtime flow begins later when the compiled DTB is handed to Linux: the driver core matches the compatible, maps `reg` resources, registers GPIO or interrupt providers where present, and applies selected pinctrl states requested by device nodes.

## State and Persistence Behavior
The YAML file stores no mutable runtime state and writes no persistent data. Its persistent behavior is ABI-level: once compatibles, pin names, group names, register ordering, GPIO/interrupt cell counts, and child-node names are accepted into DTS files, those strings and shapes become long-lived DTB contracts. Runtime state is owned by the matched kernel drivers after probe, including GPIO chip registration, IRQ domain state, mux selection, reset deassertion, and output/drive configuration.

## Dependencies and Integration Points
Schema dependencies include `pincfg-node.yaml`, `pinctrl.yaml#`, `pinmux-node.yaml`. Integration points include Ocelot/Luton/Serval/ServalT pinctrl and GPIO drivers, reset resources, interrupt consumers, and board pinctrl state nodes. The file also integrates with `pinctrl.yaml`, `pinmux-node.yaml`, `pincfg-node.yaml`, `/schemas/types.yaml`, GPIO and interrupt-controller bindings where referenced, Linux `make dt_binding_check`, Linux `make dtbs_check`, board DTS pinctrl state phandles, and driver `of_match_table` review.

## Risks
Primary risks are incompatible edits to SoC compatible selection, GPIO range exposure, interrupt-controller cells, reset naming, mux groups, output-high/low, and drive-strength; drift between documented compatibles and driver match tables; incorrect `reg` or `reg-names` ordering; mismatched GPIO/interrupt cell counts; over-broad or under-broad child regexes; stale pin/function/group enumerations compared with the driver tables; and electrical settings that validate but are unsupported on a specific pad. This schema's local closure behavior is: top-level unknown properties are rejected; child nodes are admitted only through regex patterns. Regressions normally surface as dtbs_check failures, unbound pinctrl drivers, missing GPIO/IRQ providers, or devices booting with the wrong mux or bias state.
