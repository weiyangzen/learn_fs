# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/wireless/marvell,sd8787.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/wireless/marvell,sd8787.yaml` defines the Linux Devicetree YAML schema for `Marvell 8787/8897/8978/8997 (sd8787/sd8897/sd8978/sd8997/pcie8997) SDIO/PCIE devices`, a wireless controller binding. The schema description says: This node provides properties for describing the Marvell SDIO/PCIE wireless device. The node is expected to be specified as a child node to the SDIO/PCIE controller that connects the device to the system. It is declarative ABI documentation and validation input rather than executable kernel code; its practical role is to make DTS/DTB hardware descriptions match the resources, topology, and compatible strings expected by the relevant kernel subsystem before probe.

## Important APIs, Types, and Functions
The public API is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses an `enum` and exposes 7 tokens: `marvell,sd8787`, `marvell,sd8897`, `marvell,sd8978`, `marvell,sd8997`, `nxp,iw416`, `pci11ab,2b42`, `pci1b4b,2b42`. Top-level properties are `compatible`, `reg`, `interrupts`, `wakeup-source`, `marvell,caldata-txpwrlimit-2g`, `marvell,caldata-txpwrlimit-5g-sub0`, `marvell,caldata-txpwrlimit-5g-sub1`, `marvell,caldata-txpwrlimit-5g-sub2`, `marvell,caldata-txpwrlimit-5g-sub3`, `marvell,wakeup-pin`. Top-level required properties are `compatible`, `reg`; required properties collected from nested schema branches include `compatible`, `reg`. Patterned child schemas are none. Numeric and collection constraints include `maxItems=1`, `maxItems=566`, `maxItems=502`, `maxItems=688`, `maxItems=750`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, bus child addresses, port selectors, or cell offsets; `interrupts` routes status, error, RX/TX, MSI, or completion IRQs. The highest-risk ABI details are compatible identity, bus address, interrupt or wake wiring, calibration and OTP/NVMEM references, firmware names, frequency limits, power limits, and vendor board-data properties.

## Control Flow
Runtime control flow is supplied by dt-schema and kernel subsystem code, not by this YAML file. `dt_binding_check` loads the meta-schema, resolves `$ref` entries, applies `properties`, evaluates no top-level conditionals, checks required fields, validates `minItems`/`maxItems` and enum/const constraints, validates embedded examples, and applies the closure rule. During boot, the compiled DTB node is matched by `compatible`; then platform, PCI, SDIO, SPI, MDIO, NVMEM, OPP, PCIe, netdev, wireless, accelerator, storage, clock, reset, regulator, IRQ, GPIO, IOMMU, and power-domain helpers consume the phandles and resource arrays that this schema validates. Child nodes are discovered declaratively through fixed names, pattern properties, address cells, and referenced child schemas.

## State and Persistence Behavior
The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: compatible strings, required resource names, register and interrupt ordering, phandle and cell counts, child-node names, fallback ordering, and example layouts become long-lived contracts in board DTS files and shipped DTBs. Runtime state belongs to the matching drivers and hardware after probe, including wireless device probe, firmware boot, regulatory/channel capability selection, calibration selection, IRQ/wake state, netdev/wiphy registration, and runtime PM.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource-shape changes that still compile but break driver probe, link training, calibration lookup, OPP selection, NVMEM cell reads, or bus enumeration. Tightening required properties can reject existing boards; loosening them can hide missing clocks, resets, interrupts, supplies, PHY links, PCIe windows, memory regions, OPP fields, or NVMEM cells. Child-node schemas need special care because address cells, port IDs, PCI interrupt maps, wireless calibration cells, NVMEM layouts, and OPP tables must match driver-side assumptions. This schema rejects unknown top-level properties with `additionalProperties: false`. It has 10 top-level properties and 10 distinct nested property names, so broad edits should be checked against all compatible variants and DTS users, not just the nominal filename.
