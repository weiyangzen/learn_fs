# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pwm/atmel,hlcdc-pwm.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pwm/atmel,hlcdc-pwm.yaml` defines the Linux Devicetree YAML schema for `Atmel's HLCDC's PWM controller`, a PWM controller binding. The schema description says: The LCDC integrates a Pulse Width Modulation (PWM) Controller. This block generates the LCD contrast control signal (LCD_PWM) that controls the display's contrast by software. LCDC_PWM is an 8-bit PWM signal that can be converted to an analog voltage with a simple passive filter. LCD display panels have different backlight specifications in terms of minimum/maximum values for PWM frequency. If the LCDC PWM frequency range does not match the LCD display panel, it is possible to use the standalone PWM Controller to drive the backlight. It is declarative ABI documentation and validation input, not executable driver code. Its job is to keep DTS/DTB nodes aligned with the resources, child nodes, and electrical or timing constraints expected by the matching kernel subsystem before a driver probes hardware.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource-shape changes that still compile but break driver probe, power sequencing, clock setup, IRQ delivery, or consumer phandle resolution. Tightening required properties can reject existing board files; loosening them can hide missing supplies, clocks, resets, interrupts, current/voltage limits, PWM cell counts, PTP/PPS GPIOs, or regulator child constraints. This schema rejects unknown top-level properties with `additionalProperties: false`. It has 2 top-level properties and 2 distinct nested property names, so broad edits should be checked against all compatibles, examples, and in-tree DTS users rather than only the filename's nominal device.
