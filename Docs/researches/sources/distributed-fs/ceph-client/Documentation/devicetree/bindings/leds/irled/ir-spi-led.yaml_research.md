# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/leds/irled/ir-spi-led.yaml

**Purpose:** Defines the Linux Devicetree JSON-schema contract for `IR LED connected through SPI bus`. In this source tree it is a infrared LED transmitter binding; it constrains board DTS/DTB nodes so kernel OF matching and subsystem code can discover the hardware resources consistently. This is declarative ABI documentation, not executable Ceph client code, but it is part of the imported kernel documentation corpus that protects hardware-description compatibility. The source description says: IR LED switch is connected to the MOSI line of the SPI device and the data is delivered through that.

**Important APIs/types/functions:** The public surface is the schema itself: `$id` `http://devicetree.org/schemas/leds/irled/ir-spi-led.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, composition keywords, closure rules, and `examples` consumed by `dt-schema`. Compatible strings are `ir-spi-led`. Required properties are `compatible`, `reg`. Important top-level properties include `compatible`, `reg`, `duty-cycle`, `led-active-low`, `power-supply`. Patterned or child-node surfaces include none declared. Direct schema references are `/schemas/spi/spi-peripheral-props.yaml#`, `/schemas/types.yaml#/definitions/uint8`. Maintainers: Sean Young <sean@mess.org>. Top-level property policy is `unevaluatedProperties: false`.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel drivers rather than by this YAML. `dt_binding_check` loads the core meta-schema, resolves `$ref` dependencies, applies constants/enums/cardinality/range checks, evaluates composition and conditional branches (`allOf`), and validates the embedded examples. At boot, the compiled DTB node is matched by `compatible`; the relevant IR LED driver or common subsystem reads resource properties, phandles, child nodes, and cells before registering devices or provider relationships. Child/provider surfaces to watch here are `power-supply`.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistence is ABI persistence: accepted DTS nodes encode hardware identity, register windows, interrupts, power/clock/reset topology, phandle cell widths, channel indexes, and child LED/IOMMU/IPMI layout for long-lived boards. Tightening `required`, changing compatible fallback order, altering cell counts, or changing closure policy can reject existing DTBs or make drivers parse resources differently.

**Dependencies and integration points:** Integrated with IR transmitter devices, PWM/GPIO/SPI carrier generation, and LED/rc-core integration. Schema dependencies include `/schemas/spi/spi-peripheral-props.yaml#`, `/schemas/types.yaml#/definitions/uint8`; examples may also include dt-bindings headers. Resource integration is through properties such as `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address. Driver integration is through `compatible`, while subsystem integration is through phandle arrays, provider cell counts, common schemas, and child-node schemas inherited or declared here.

**Risks and edge cases:** Main risks are schema ABI drift, missing or stale compatible coverage, incorrect min/max item constraints, wrong `#*-cells` values, resource names that diverge from driver expectations, conditionals that validate one SoC or chip variant while rejecting another valid one, and examples that no longer reflect real DTS users. Closure policy (`unevaluatedProperties: false`) is useful for catching misspellings but can also block legitimate extensions. For LED/backlight children, channel numbering and `reg`/`led-sources` constraints are common failure points; for IOMMU bindings, stream IDs and cell widths are especially sensitive; for IPMI bindings, host/BMC address and register-resource shape must match the driver.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/leds/irled/ir-spi-led.yaml` and `make dtbs_check` against DTS files using every compatible listed here. The 1 embedded example block(s) should compile through `dtc` and validate against referenced schemas. Useful negative tests remove each required property, add an unknown property under the declared closure policy, exercise compatible-specific conditionals, and verify the matching Linux driver still probes with the resources, child nodes, and phandle specifiers described by this binding.
