# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/dma/snps,dw-axi-dmac.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Synopsys DesignWare AXI DMA Controller`. In this tree it is a DMA engine, DMA router, or DMA-capable IP binding used by dmaengine providers and DMA client phandle specifiers; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: Synopsys DesignWare AXI DMA Controller DT Binding

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/dma/snps,dw-axi-dmac.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `snps,axi-dma-1.01a`, `intel,kmb-axi-dma`, `sophgo,cv1800b-axi-dma`, `starfive,jh7110-axi-dma`, `starfive,jh8100-axi-dma`, `altr,agilex5-axi-dma`. Required properties are `compatible`, `reg`, `clocks`, `clock-names`, `interrupts`, `#dma-cells`, `dma-channels`, `snps,dma-masters`, `snps,data-width`, `snps,priority`, `snps,block-size`. Important properties include `compatible`, `reg`, `reg-names`, `interrupts`, `iommus`, `clocks`, `clock-names`, `#dma-cells`, `dma-channels`, `dma-noncoherent`, `dma-coherent`, `resets`, `snps,dma-masters`, `snps,data-width`, `snps,priority`, `snps,block-size`, and 1 more. Referenced schemas are `dma-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-array`. Property roles include `compatible` for driver match key and hardware ABI identifier; `reg` for MMIO, I2C/SPI address, or child register address; `interrupts` for interrupt line routing; `iommus` for IOMMU stream mapping; `clocks` for clock provider phandles; `clock-names` for clock input names; `#dma-cells` for DMA client specifier width; `dma-channels` for number of DMA channels; `resets` for reset controller phandles. The top-level closure rule is `additionalProperties: false`. Maintainers: Eugeniy Paltsev <Eugeniy.Paltsev@synopsys.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `dma-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-array`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as clock provider phandles, reset controller phandles, IOMMU stream bindings. Conditional/schema-composition points include `allOf`, `if`, `then`, `else`, `conditional branches`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `snps,dma-masters`, `snps,data-width`, `snps,priority`, `snps,block-size`, `snps,axi-max-burst-len`.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with dmaengine and Devicetree DMA client code. Direct schema dependencies are `dma-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32`, `/schemas/types.yaml#/definitions/uint32-array`; resource dependencies visible in the property set include clock provider phandles, reset controller phandles, IOMMU stream bindings. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `additionalProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
