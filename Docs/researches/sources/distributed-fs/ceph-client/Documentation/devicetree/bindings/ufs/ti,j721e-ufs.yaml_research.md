# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/ufs/ti,j721e-ufs.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/ufs/ti,j721e-ufs.yaml` defines `TI J721e UFS Host Controller Glue Driver`, a UFS host-controller binding. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

Top-level required properties are `compatible`, `reg`, `clocks`, `power-domains`; required properties discovered in nested branches are `clocks`, `compatible`, `power-domains`, `reg`. Patterned child schemas are `^ufs@[0-9a-f]+$`; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry; `reg` describes MMIO windows, bus addresses, or register resources; `clocks` integrates with the clock framework; `power-domains` models generic power-domain dependencies; `assigned-clocks` integrates with the clock framework; `#address-cells` controls child-node address translation and bus layout; `#size-cells` controls child-node address translation and bus layout; `ranges` controls child-node address translation and bus layout. ## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (none); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: UFS link startup, host controller capabilities, runtime PM, power mode changes, command queues, error recovery, and PHY calibration state. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around compatible strings, MMIO windows, interrupt resources, PHY phandles, clock/reset ordering, power supplies, and vendor-specific controller quirks; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile rejects undeclared top-level properties with `additionalProperties: false`.
