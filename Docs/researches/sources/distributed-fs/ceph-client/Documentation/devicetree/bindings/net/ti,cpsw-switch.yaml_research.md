# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/ti,cpsw-switch.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/ti,cpsw-switch.yaml` defines the Linux Devicetree YAML schema for `TI SoC Ethernet Switch Controller (CPSW)`, a Ethernet switch/DSA binding. The schema description says: The 3-port switch gigabit ethernet subsystem provides ethernet packet communication and can be configured as an ethernet switch. It provides the gigabit media independent interface (GMII),reduced gigabit media independent interface (RGMII), reduced media independent interface (RMII), the management data input output (MDIO) for physical layer device (PHY) management. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses `oneOf` with 4 branches with 4 tokens: `ti,cpsw-switch`, `ti,am335x-cpsw-switch`, `ti,am4372-cpsw-switch`, `ti,dra7-cpsw-switch`. Top-level properties are `compatible`, `reg`, `#address-cells`, `#size-cells`, `ranges`, `clocks`, `clock-names`, `interrupts`, `interrupt-names`, `pinctrl-names`, `syscon`, `ethernet-ports`, `cpts`. Top-level required properties are `compatible`, `reg`, `ranges`, `clocks`, `clock-names`, `interrupts`, `interrupt-names`, `#address-cells`, `#size-cells`; required properties collected from nested branches include `#address-cells`, `#size-cells`, `clock-names`, `clocks`, `compatible`, `interrupt-names`, `interrupts`, `phys`, `ranges`, `reg`. Patterned child schemas are `^mdio@`. Numeric and collection constraints include `maxItems=1`, `minimum=1`, `maximum=1024`. Important resource roles: `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, MDIO child addresses, SPI/I2C addresses, or port selectors; `#address-cells` fixes child-node or phandle specifier shape; `#size-cells` fixes child-node or phandle specifier shape; `clocks` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `clock-names` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `interrupts` routes link/status, RX/TX, error, or management IRQs; `interrupt-names` routes link/status, RX/TX, error, or management IRQs. The highest-risk ABI details are port numbering, CPU port linkage, MDIO/PHY/fixed-link topology, interrupt resources, register regions, and vendor switch block constraints.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates no top-level conditionals, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including switch fabric configuration, port link state, bridge/VLAN/FDB offload state, PTP/traffic management state, and per-port phylink state.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema rejects unknown top-level properties with `additionalProperties: false`. It has 13 top-level properties and 18 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.

High-value negative checks remove required `reg`, interrupts, clocks, resets, PHY links, MDIO children, switch ports, or GPIOs; use invalid child `reg` values; misspell vendor properties; and exercise every compatible-specific branch. Runtime integration signals are successful driver probe, correct netdev/PHY/MDIO/DSA/NFC/802.15.4 registration, clean link or controller bring-up, valid interrupt/reset/power sequencing, and no dtbs_check regressions in embedded examples or in-tree DTS users.
