# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/pcs/renesas,rzn1-miic.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/pcs/renesas,rzn1-miic.yaml` defines the Linux Devicetree YAML schema for `Renesas RZ/N1, RZ/N2H and RZ/T2H MII converter`, a Ethernet PCS binding. The schema description says: This MII converter is present on the Renesas RZ/N1, RZ/N2H and RZ/T2H SoC families. It is responsible to do MII passthrough or convert it to RMII/RGMII. It is declarative ABI documentation and validation input, not executable networking code. Its purpose is to keep DTS/DTB nodes aligned with the resources and topology expected by the matching kernel subsystem before drivers probe hardware.

## Important APIs, Types, and Functions
The API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and referenced common schemas. `compatible` uses `oneOf` with 3 branches with 4 tokens: `renesas,r9a06g032-miic`, `renesas,rzn1-miic`, `renesas,r9a09g077-miic`, `renesas,r9a09g087-miic`. Top-level properties are `#address-cells`, `#size-cells`, `compatible`, `reg`, `clocks`, `clock-names`, `resets`, `reset-names`, `renesas,miic-switch-portin`, `power-domains`. Top-level required properties are `#address-cells`, `#size-cells`, `compatible`, `reg`, `clocks`, `clock-names`, `power-domains`; required properties collected from nested branches include `#address-cells`, `#size-cells`, `clock-names`, `clocks`, `compatible`, `power-domains`, `reg`, `renesas,miic-input`, `reset-names`, `resets`. Patterned child schemas are `^mii-conv@[0-5]$`. Numeric and collection constraints include `maxItems=1`. Important resource roles: `#address-cells` fixes child-node or phandle specifier shape; `#size-cells` fixes child-node or phandle specifier shape; `compatible` is the stable hardware ABI and OF match key; `reg` describes MMIO ranges, MDIO child addresses, SPI/I2C addresses, or port selectors; `clocks` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `clock-names` binds MAC/MDIO/PHY/PTP/SerDes clock inputs; `resets` defines reset-controller or GPIO reset sequencing; `reset-names` defines reset-controller or GPIO reset sequencing; `power-domains` integrates the device with SoC PM, DMA, or IOMMU topology. The highest-risk ABI details are PCS register placement, protocol mode selection, phandle use by MAC nodes, and in-band status/AN expectations.

## Control Flow
Control flow is dt-schema evaluation. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, evaluates `allOf`, checks required fields and min/max constraints, validates examples, and enforces the closure policy. At runtime the YAML does not execute: a compiled DTB node is matched through the driver's OF table, then netdev, phylib/phylink, MDIO, DSA/switchdev, NFC, IEEE 802.15.4, regulator, clock, reset, GPIO, IRQ, DMA, IOMMU, and platform-bus helpers consume the validated resources. Child-node control flow is declarative too: MDIO children, switch ports, PHY packages, connector/LED nodes, and graph/fixed-link nodes are discovered by common Devicetree helpers according to the schema shape.

## State and Persistence Behavior
The file stores no mutable runtime state and writes no persistent data. Its persistence is ABI stability: compatible strings, required resource names, phandle/cell counts, child-node names, port IDs, PHY addresses, fallback ordering, and example layouts become long-lived contracts in DTS and DTB artifacts. Runtime state belongs to drivers and hardware after probe, including PCS link negotiation state, SerDes mode state, phylink callbacks, and carrier status.

## Risks
Primary risks are Devicetree ABI drift, incomplete compatible coverage, wrong fallback ordering, and resource shape changes that still compile but break driver probe or link bring-up. Tightening required properties can reject existing board files; loosening them can hide missing clocks, resets, interrupts, PHY links, port nodes, or MDIO addresses. Child-node schemas need special care because port numbering, PHY package topology, MDIO mux selectors, NFC transport GPIOs, and switch CPU/user-port layout must match driver tables. This schema rejects unknown top-level properties with `additionalProperties: false`. It has 10 top-level properties and 12 distinct nested property names, so broad edits should be checked against all compatibles and DTS users, not just the filename's nominal device.

## Test Signals
Run `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/pcs/renesas,rzn1-miic.yaml` for targeted schema validation and `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/net/pcs/renesas,rzn1-miic.yaml` against boards using these nodes. High-value negative checks remove required `reg`, interrupts, clocks, resets, PHY links, MDIO children, switch ports, or GPIOs; use invalid child `reg` values; misspell vendor properties; and exercise every compatible-specific branch. Runtime integration signals are successful driver probe, correct netdev/PHY/MDIO/DSA/NFC/802.15.4 registration, clean link or controller bring-up, valid interrupt/reset/power sequencing, and no dtbs_check regressions in embedded examples or in-tree DTS users.
