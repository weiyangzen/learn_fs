# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/fsl,usb2.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/fsl,usb2.yaml` defines `Freescale SOC USB controllers`, a USB2 OTG/host/device controller binding. The device node for a USB controller that is part of a Freescale SOC is as described in the document "Open Firmware Recommended Practice: Universal Serial Bus" with the following modifications and additions. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Important APIs, Types, and Functions
The exported API is the Devicetree node contract. `$id` is `http://devicetree.org/schemas/usb/fsl,usb2.yaml#` and `$schema` is `http://devicetree.org/meta-schemas/core.yaml#`. `compatible` uses `oneOf` with 2 accepted forms and exposes 4 compatible tokens: `fsl-usb2-mph`, `fsl-usb2-dr`, `fsl-usb2-dr-v2.2`, `fsl-usb2-dr-v2.5`. Top-level properties are `compatible`, `reg`, `interrupts`, `phy_type`, `port0`, `port1`, `fsl,invert-drvvbus`, `fsl,invert-pwr-fault`. Top-level required properties are `compatible`, `reg`, `interrupts`, `phy_type`; required properties discovered in nested branches are `compatible`, `interrupts`, `phy_type`, `reg`. Patterned child schemas are none; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry; `reg` describes MMIO windows, bus addresses, or register resources; `interrupts` maps controller, GPIO, or Type-C events into IRQ domains. Across the full schema there are 8 distinct property names and collected const/enum/min/max/item signals include `enum=[fsl-usb2-mph, fsl-usb2-dr]`, `enum=[fsl-usb2-dr-v2.2, fsl-usb2-dr-v2.5]`, `const=fsl-usb2-dr`, `maxItems=1`, `enum=[ulpi, serial, utmi, utmi_wide]`.

## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (`allOf`); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: USB host/peripheral/OTG mode, endpoint FIFOs, DMA queues, VBUS/ID detection, suspend/resume wakeup, PHY power, and controller reset state. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around compatible fallback order, MMIO and IRQ resources, PHY/transceiver phandles, `dr_mode`, FIFO/endpoint tuning, VBUS/ID GPIOs, clocks/resets, and child-port layout; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile closes composed schemas with `unevaluatedProperties: false`.

## Test Signals
Use `make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/usb/fsl,usb2.yaml` for this schema and its examples, then `make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/usb/fsl,usb2.yaml` against boards using these compatibles. Useful negative tests remove each required property, scramble compatible fallback order, use bad child-node names, provide too many/few clocks, resets, interrupts, PHYs, or register windows, and add undeclared properties when the schema is closed. Runtime signals are clean driver probe, expected PHY/role-switch/provider registration where applicable, correct device enumeration, suspend/resume without resource leaks, and no new schema warnings.
