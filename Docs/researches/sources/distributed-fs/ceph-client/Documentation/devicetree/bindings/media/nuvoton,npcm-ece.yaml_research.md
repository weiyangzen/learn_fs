# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/nuvoton,npcm-ece.yaml

**Purpose:** Defines the Devicetree JSON-schema ABI for `Nuvoton NPCM Encoding Compression Engine`. It is a media hardware binding in the Ceph client Linux source snapshot, constraining how board DTS/DTB files describe media hardware so Linux media, V4L2 mem2mem, platform, clock, reset, power-domain, IOMMU, and graph helpers can bind the correct driver resources. The source description says: Video Encoding Compression Engine (ECE) present on Nuvoton NPCM SoCs.

**Important APIs/types/functions:** This is declarative schema, so the exported API is the binding contract rather than C functions. Public surfaces include `$id` `http://devicetree.org/schemas/media/nuvoton,npcm-ece.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, examples, and dt-schema references. The `compatible` property uses `enum` list and accepts `nuvoton,npcm750-ece`, `nuvoton,npcm845-ece`. Top-level required properties are `compatible`, `reg`, `resets`; required names across nested/conditional schemas include `compatible`, `reg`, `resets`. Top-level properties are `compatible`, `reg`, `resets`; all nested property names include `compatible`, `reg`, `resets`. Resource constraints visible in the schema include `compatible`, `reg` (maxItems=1), `resets` (maxItems=1). Closure is `additionalProperties: False`.

**Control flow:** Runtime control flow is supplied by dt-schema and kernel probing. `dt_binding_check` loads the core meta-schema, resolves references, validates the compatible form, applies required lists and `minItems`/`maxItems`/`const` restrictions, evaluates conditionals, and compiles the inline examples. At boot the DTB node is matched by `compatible`; the platform or media driver then reads MMIO ranges, named interrupts, clocks, resets, power domains, IOMMU streams, DMA/interconnect paths, firmware or reserved-memory phandles, and graph endpoints. There are no compatible-specific conditional branches beyond direct property validation. This binding has no media graph endpoint surface; integration is by platform device resources and codec-specific child nodes.

**State and persistence behavior:** The file stores no mutable runtime state and performs no persistence itself. Its persistent effect is ABI stability for DTS files and shipped DTBs: compatible strings, child-node names, phandle relationships, address ranges, cell counts, and media graph topology are long-lived hardware descriptions. Any change to required properties, resource ordering, child object schemas, or unknown-property policy can invalidate existing board descriptions even though no kernel state is written by the YAML.

**Dependencies and integration points:** Direct schema references are none. Runtime dependencies are reset-controller phandles. No nested object nodes are defined beyond common schema references. Maintainers listed in the binding are `Joseph Liu <kwliu@nuvoton.com>`, `Marvin Lin <kflin@nuvoton.com>`.

**Risks:** Key risks: compatible-string or fallback-order drift can break OF matching and dtbs_check expectations; resource array ordering is ABI-sensitive for `reg-names`, `clock-names`, `interrupt-names`, `power-domain-names`, and `reset-names`. The closure policy is `additionalProperties: False`, so unknown properties are intentionally rejected after referenced schemas are evaluated.

**Test signals:** Run `make dt_binding_check DT_SCHEMA_FILES=sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/nuvoton,npcm-ece.yaml` to validate the schema and its 1 inline example block(s). Run `make dtbs_check` against DTS users of `nuvoton,npcm750-ece`, `nuvoton,npcm845-ece` to exercise compatible-specific branches, graph endpoint requirements, resource counts, and referenced schemas. Useful negative tests remove required properties such as `compatible`, `reg`, `resets`, alter named resource ordering, exceed item counts, and inject unknown properties to confirm the closure rule catches mistakes.
