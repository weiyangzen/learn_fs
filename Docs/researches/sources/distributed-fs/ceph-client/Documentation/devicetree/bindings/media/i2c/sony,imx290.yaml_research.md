# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/i2c/sony,imx290.yaml

**Purpose:** `sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/media/i2c/sony,imx290.yaml` is a Linux Devicetree YAML schema for `Sony IMX290 1/2.8-Inch CMOS Image Sensor`, a camera image sensor binding. The Sony IMX290 is a 1/2.8-Inch CMOS Solid-state image sensor with Square Pixel, available in either mono or colour variants. It is programmable through I2C and 4-wire interfaces. The sensor output is available via CMOS logic parallel SDR output, Low voltage LVDS DDR output and CSI-2 serial data output. The CSI-2 bus is the default. No bindings have been defined for the other busses. imx290lqr is the full model identifier for the colour variant. "sony,imx290" is treated the same as this as it was the original compatible string. imx290llr is the mono version of the sensor. It is declarative ABI documentation and validation input, not executable driver code. Its job is to constrain how board DTS files describe media hardware so V4L2, media-controller, remote-control, codec, bridge, sensor, clock, regulator, GPIO, DMA, and platform/I2C driver code can discover the expected resources.

**Important APIs/types/functions:** The public API surface is the schema contract: `$id`, `$schema`, `title`, `maintainers`, `properties`, `required`, composition keys, examples, and any OF graph or child-node patterns. `compatible` uses `oneOf` with 2 accepted compatible forms and covers 0 compatible tokens: no explicit compatible values. Top-level properties are `compatible`, `reg`, `clocks`, `clock-names`, `clock-frequency`, `vdda-supply`, `vddd-supply`, `vdddo-supply`, `reset-gpios`, `port`. Top-level required properties are `compatible`, `reg`, `clocks`, `clock-names`, `vdda-supply`, `vddd-supply`, `vdddo-supply`, `port`; required properties found across nested schemas include `clock-names`, `clocks`, `compatible`, `data-lanes`, `link-frequencies`, `port`, `reg`, `vdda-supply`, `vddd-supply`, `vdddo-supply`. The node acts as a I2C client node selected by parent bus address cells. Important property roles: `compatible` selects the OF match table entry and stable hardware ABI; `reg` carries the I2C address or MMIO register range; `clocks` binds clock inputs, outputs, or rates; `clock-names` binds clock inputs, outputs, or rates; `vdda-supply` links power rails or power-domain providers; `vddd-supply` links power rails or power-domain providers; `vdddo-supply` links power rails or power-domain providers; `reset-gpios` controls hardware reset, enable, or power-down sequencing; `port` describes media-controller OF graph links and endpoint topology. **Control flow:** Control flow is dt-schema evaluation rather than imperative logic. `dt_binding_check` loads the core meta-schema, resolves every `$ref`, applies `properties`, `required`, item/count limits, and composition branches, validates inline examples, and enforces the unknown-property policy. At runtime the YAML is not executed: the compiled DTB node is matched through the driver's OF table, and media graph parsing follows `port`/`ports` endpoints to connect sensors, bridges, serializers, deserializers, receivers, codecs, and SoC capture or processing blocks. Resource acquisition then proceeds through standard helpers for I2C/platform devices, regulators, clocks, resets, GPIOs, IRQs, DMA/IOMMU, firmware, and child remote buses when those properties are present.

**State and persistence behavior:** The schema has no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted compatible strings, required supplies/clocks/resets/IRQs, endpoint lane layouts, child-node names, remote-I2C topology, and MMIO or I2C address shapes become long-lived DTB contracts. Runtime state such as video streaming, link training, sensor mode selection, codec sessions, remote serializer state, radio tuning, frame buffers, and power sequencing belongs to the matching kernel drivers and hardware.

**Risks:** Risks center on Devicetree ABI drift and media graph mismatches. Changing compatible values or fallback order can break driver binding; renaming supplies, clocks, GPIOs, interrupts, reset lines, `#*-cells`, or child nodes can break probe-time resource lookup; tightening endpoint lane counts or port numbering can reject valid boards or silently disconnect media links. Serializer/deserializer bindings add risk around remote I2C aliases, PoC supplies, GPIO forwarding, and link topology. Codec and SoC processing bindings add risk around clocks, power domains, IOMMU/DMA resources, and firmware/mailbox style dependencies. The closure profile is: composition is closed by `unevaluatedProperties: false`.
