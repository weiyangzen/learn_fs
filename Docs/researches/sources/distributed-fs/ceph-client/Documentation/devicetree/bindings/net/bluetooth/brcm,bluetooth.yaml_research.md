# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/bluetooth/brcm,bluetooth.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/bluetooth/brcm,bluetooth.yaml` defines the Bluetooth controller binding titled `Broadcom Bluetooth Chips`. This binding describes Broadcom UART-attached bluetooth chips. It is a Linux Devicetree YAML schema used to validate DTS/DTB nodes and to document the firmware ABI consumed before the kernel creates the corresponding Bluetooth HCI controller.

## Important APIs, Types, and Functions
The public interface is the YAML/dt-schema ABI, not C-callable functions. `compatible` uses `oneOf` with 2 branches with 14 tokens: `infineon,cyw43439-bt`, `brcm,bcm4329-bt`, `brcm,bcm20702a1`, `brcm,bcm4330-bt`, `brcm,bcm4334-bt`, `brcm,bcm43430a0-bt`, `brcm,bcm43430a1-bt`, `brcm,bcm43438-bt`, `brcm,bcm4345c5`, `brcm,bcm43540-bt`, `brcm,bcm4335a0`, `brcm,bcm4349-bt`, `cypress,cyw4373a0-bt`, `infineon,cyw55572-bt`. Top-level properties are `compatible`, `shutdown-gpios`, `reset-gpios`, `device-wakeup-gpios`, `host-wakeup-gpios`, `clocks`, `clock-names`, `vbat-supply`, `vddio-supply`, `brcm,bt-pcm-int-params`, `brcm,requires-autobaud-mode`, `interrupts`, `interrupt-names`. Important property roles: `compatible` selects the OF match table and stable hardware ABI; `shutdown-gpios` controls reset, shutdown, enable, or wake sequencing; `reset-gpios` controls reset, shutdown, enable, or wake sequencing; `device-wakeup-gpios` controls reset, shutdown, enable, or wake sequencing; `host-wakeup-gpios` controls reset, shutdown, enable, or wake sequencing; `clocks` connects clock providers and names; `clock-names` connects clock providers and names; `vbat-supply` links a regulator supply; `vddio-supply` links a regulator supply; `interrupts` routes controller, wake, link, or error IRQs; `interrupt-names` routes controller, wake, link, or error IRQs.

## Control Flow
Control flow is declarative schema evaluation. During `make dt_binding_check` or `make dtbs_check`, dt-schema loads the YAML, resolves `$ref` entries, matches by `$id`, `$nodename`, `compatible`, or fragment inclusion, checks required properties, evaluates `allOf`, `dependencies`, validates examples, and enforces `additionalProperties` or `unevaluatedProperties`. At runtime the YAML itself does not execute. Firmware provides a DTB node for the Bluetooth controller binding; Linux driver core or bus code matches a driver, then subsystem helpers consume the validated resources. Child schemas such as `ports`, `ethernet-ports`, MDIO children, or CAN transceiver links guide later parsing by DSA, phylink, PHYLIB, Bluetooth, or SocketCAN drivers.

## State and Persistence Behavior
The schema stores no mutable kernel state and writes no persistent data. Persistence is the Devicetree ABI: compatible strings, property names, array order, phandle cell counts, child-node names, and example layouts are contracts carried by DTS sources and deployed DTBs. Runtime state is owned by drivers after probe, including HCI registration, firmware download, controller power state, wake signaling, runtime PM, and Bluetooth stack state; this file only constrains how hardware and board wiring are represented.

## Risks
Primary risks are incompatible ABI changes to compatible strings, wake/shutdown GPIO polarity, required power rails, clock names, transport-specific properties, and whether common Qualcomm/Broadcom/Realtek fragments stay aligned with chip-specific bindings, mismatches between documented compatibles and driver OF match tables, resource-order changes that pass schema review but break probe, and stale examples. This schema closes composed schemas with `unevaluatedProperties: false`. Additional risk signals: conditional branches can validate one silicon variant while rejecting another; large compatible lists are prone to missing or misordered fallback entries; GPIO polarity or naming mistakes can invert reset, shutdown, wake, or interrupt behavior.
