# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/apple,dwc3.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/usb/apple,dwc3.yaml` defines `Apple Silicon DWC3 USB controller`, a Synopsys DesignWare USB3 glue-controller binding. Apple Silicon SoCs use a Synopsys DesignWare DWC3 based controller for each of their Type-C ports. It is declarative firmware ABI documentation and dt-schema validation input; Linux does not execute this YAML at runtime, but the schema controls which DTS nodes are accepted for the corresponding hardware or bus-attached device.

## Important APIs, Types, and Functions
The exported API is the Devicetree node contract. `$id` is `http://devicetree.org/schemas/usb/apple,dwc3.yaml#` and `$schema` is `http://devicetree.org/meta-schemas/core.yaml#`. `compatible` uses `oneOf` with 2 accepted forms and exposes 4 compatible tokens: `apple,t6000-dwc3`, `apple,t6020-dwc3`, `apple,t8112-dwc3`, `apple,t8103-dwc3`. Top-level properties are `compatible`, `reg`, `reg-names`, `interrupts`, `iommus`, `resets`, `power-domains`. Top-level required properties are `compatible`, `reg`, `reg-names`, `interrupts`, `iommus`, `resets`, `power-domains`, `usb-role-switch`; required properties discovered in nested branches are `compatible`, `interrupts`, `iommus`, `power-domains`, `reg`, `reg-names`, `resets`, `usb-role-switch`. Patterned child schemas are none; local definitions are none. Resource/provider roles: `compatible` selects schema applicability and the kernel OF match-table entry; `reg` describes MMIO windows, bus addresses, or register resources; `reg-names` fixes semantic ordering for multiple register windows; `interrupts` maps controller, GPIO, or Type-C events into IRQ domains; `iommus` describes DMA/IOMMU integration; `resets` integrates with reset-controller providers or consumers; `power-domains` models generic power-domain dependencies. Across the full schema there are 7 distinct property names and collected const/enum/min/max/item signals include `enum=[apple,t6000-dwc3, apple,t6020-dwc3, apple,t8112-dwc3]`, `const=apple,t8103-dwc3`, `const=dwc3-core`, `const=dwc3-apple`, `maxItems=1`, `maxItems=2`.

## Control Flow
Control flow is schema evaluation. `dt_binding_check` parses the YAML, validates the meta-schema, resolves `$ref` links, applies `properties`, `patternProperties`, required lists, item counts, const/enum checks, and composition or conditional blocks (`allOf`); it also compiles the embedded examples. `dtbs_check` applies the same rules to compiled board DTBs. During boot the kernel only consumes the DTB: OF matching selects the driver, platform/bus code maps resources, phandles are resolved, and the driver performs hardware setup.

## State and Persistence Behavior
The file has no mutable runtime state and performs no persistence. Its durable state is ABI shape: compatible strings, property names, child-node names, phandle cell counts, register and interrupt ordering, resource names, and example topology. Runtime behavior is owned by matched drivers and hardware: DWC3 core mode, xHCI/gadget state, runtime PM, event buffers, PHY power, role switching, wakeup state, and glue-register setup. Schema edits therefore persist as compatibility commitments for existing DTS files even though no code path is stored here.

## Risks
Main risks are ABI drift around glue compatible order, wrapper and core register ranges, child-node layout, clock/reset naming, PHY linkage, DRD role properties, and SoC-specific conditionals; changing compatible ordering or removing fallback strings; broadening a schema so invalid board nodes pass; tightening a schema so existing DTBs fail; and mismatches between YAML clock/reset/regulator/PHY names and driver lookup tables. Multi-role USB and Type-C bindings are especially sensitive to graph endpoints, role-switch dependencies, connector children, and wakeup semantics. UFS bindings are sensitive to per-SoC clock arrays, ICE register resources, PHY lane counts, and reset/power sequencing. The closure profile closes composed schemas with `unevaluatedProperties: false`.
