# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/brcm,bcm7038-l1-intc.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/brcm,bcm7038-l1-intc.yaml` is a Linux devicetree YAML schema for the `Broadcom BCM7038-style Level 1 interrupt controller` interrupt-controller binding. This block is a first level interrupt controller that is typically connected directly to one of the HW INT lines on each CPU. Every BCM7xxx set-top chip since BCM7038 has contained this hardware. Key elements of the hardware design include: - 64, 96, 128, or 160 incoming level IRQ lines - Most onchip peripherals are wired directly to an L1 input - A separate instance of the register set for each CPU, allowing individual peripheral IRQs to be routed to any CPU - Atomic mask/unmask operations - No polarity/level/edge settings - No FIFO or priority encoder logic; software is expected to read all 2-5 status words to determine which IRQs are pending If multiple reg ranges and interrupt-parent entries are present on an SMP system, the driver will allow IRQ SMP affinity to be set up through the /proc/irq/ interface. It is not executable kernel code; it is the hardware-description ABI that DTS authors, dt-schema, and the relevant kernel subsystem rely on so the runtime driver can parse the node without board-specific ambiguity.

## Important APIs, Types, and Functions
The public API surface is the schema's accepted node shape. `compatible` uses single `const` and covers 1 compatible token: `brcm,bcm7038-l1-intc`. Top-level properties are `compatible`, `reg`, `interrupt-controller`, `#interrupt-cells`, `interrupts`, `brcm,irq-can-wake`, `brcm,int-fwd-mask`. Across nested schemas and child nodes this file mentions 7 distinct property names; nested/all required properties include `#interrupt-cells`, `compatible`, `interrupt-controller`, `interrupts`, `reg`. Node naming is constrained by no explicit node-name constraint. Interrupt-controller-facing properties define how child devices encode interrupt specifiers and how the kernel irqchip or MSI domain driver maps them: addressing resources `reg`, domain declarations `interrupt-controller`, `#interrupt-cells`, `interrupts`, clock/reset/power hooks none, and any GPIO or parent-domain links none. Required properties are `compatible`, `reg`, `interrupt-controller`, `#interrupt-cells`, `interrupts`; the shape of `#interrupt-cells` and parent interrupt wiring is the main ABI exposed to DTS consumers.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation rather than executable branching. `dt-doc-validate` and `dt_binding_check` load the YAML, expand `$ref` links, apply composition and conditional keywords, validate the DTS example blocks, and later `dtbs_check` applies the same contract to compiled board devicetrees. For irqchip and MSI providers, validation ensures the interrupt domain, specifier cell count, parent interrupt lines, MSI doorbells, and child-node encoding match what the kernel interrupt-controller driver will parse during early boot or bus enumeration. The schema itself stores no mutable state and writes no persistent data; its persistence is the stable source-controlled hardware ABI. External references used in evaluation are `/schemas/interrupt-controller.yaml#`, `/schemas/types.yaml#/definitions/uint32-array`; top-level/nested conditional keywords present are `allOf`.

## Risks
Risks are mostly ABI and validation risks rather than algorithmic failures. Tightening required properties, changing compatible ordering, renaming resources, altering cell counts, or closing extra properties can reject existing DTS users; loosening constraints can allow nodes that later fail driver probe or misdescribe hardware. This schema has 7 top-level properties and 7 distinct nested property names, with strictness profile: unknown top-level properties are rejected. Conditional branches and shared `$ref` schemas should be checked against all in-tree users before edits, because a schema-only patch can still break board builds.
