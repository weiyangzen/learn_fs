# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/actions,owl-emac.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Actions Semi Owl SoCs Ethernet MAC Controller`. In this tree it is a network controller, MDIO bus, Ethernet PHY, DSA-adjacent, or MAC/PHY integration binding binding: it constrains how DTS authors describe hardware, and it gives Linux OF/platform code a stable ABI for matching drivers, acquiring resources, and validating board descriptions with dt-schema. The source description says: This Ethernet MAC is used on the Owl family of SoCs from Actions Semi. It provides the RMII and SMII interfaces and is compliant with the IEEE 802.3 CSMA/CD standard, supporting both half-duplex and full-duplex operation modes at 10/100 Mb/s data transfer rates.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted DTS/DTB nodes encode hardware identity, resource topology, child-node layout, and phandle cell widths for long-lived boards. Tightening `required`, changing compatible ordering, changing cell counts, or altering `additionalProperties`/`unevaluatedProperties` can break existing DTBs even though no state is stored by the YAML itself.

**Dependencies and integration points:** Integrates with network core, phylink/PHY/MDIO subsystems, stmmac or vendor Ethernet drivers, reset/clock/regulator/PHY providers. Devicetree/dt-schema dependencies are the core meta-schema plus `ethernet-controller.yaml#`, `/schemas/types.yaml#/definitions/phandle`, `mdio.yaml#`. **Risks:** Main risks are ABI drift, under-specified compatibles, required resources that do not match real SoC integration, wrong `#*-cells` counts, stale examples, and conditional branches that validate one variant while rejecting another valid one. For storage bindings, partition/ECC/timing mistakes can silently corrupt flash or make media unprobeable. For network bindings, PHY mode, MDIO, reset, MAC-address, or clock mistakes can leave links down. For mux and common schemas, over-permissive closure can hide misspelled properties while over-tight closure can reject legitimate inherited properties.
