# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/firmware/arm,scmi.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `System Control and Management Interface (SCMI) Message Protocol`. In this tree it is a firmware interface binding used to describe secure monitor, system controller, mailbox, or service-layer communication with platform firmware; it constrains how board DTS files describe the hardware and how Linux drivers discover it through OF matching, phandles, and common binding references. The source description says: The SCMI is intended to allow agents such as OSPM to manage various functions that are provided by the hardware platform it is running on, including power and performance functions. This binding is intended to define the interface the firmware implementing the SCMI as described in ARM document number ARM DEN 0056 ("ARM System Control and Management Interface...

**Important APIs/types/functions:** This is declarative schema rather than executable code. The public ABI surface is `$id` `http://devicetree.org/schemas/firmware/arm,scmi.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and the referenced schemas used by dt-schema. Compatible strings are `arm,scmi`, `arm,scmi-smc`, `arm,scmi-smc-param`, `qcom,scmi-smc`, `arm,scmi-virtio`, `linaro,scmi-optee`. Required properties are `compatible`. Important properties include `$nodename`, `compatible`, `interrupts`, `interrupt-names`, `mbox-names`, `mboxes`, `shmem`, `#address-cells`, `#size-cells`, `atomic-threshold-us`, `arm,max-rx-timeout-ms`, `arm,max-msg-size`, `arm,max-msg`, `arm,no-completion-irq`, `arm,smc-id`, `linaro,optee-channel-id`, and 9 more. Referenced schemas are `/schemas/firmware/nxp,imx95-scmi.yaml`, `/schemas/types.yaml#/definitions/uint32`, `#/$defs/protocol-node`, `/schemas/regulator/regulator.yaml#`, `/schemas/pinctrl/pinctrl.yaml`, `/schemas/firmware/nxp,imx95-scmi-pinctrl.yaml`, `/schemas/pinctrl/pincfg-node.yaml#`, `/schemas/pinctrl/pinmux-node.yaml#`. Property roles include `compatible` for driver match key and hardware ABI identifier; `interrupts` for interrupt line routing; `interrupt-names` for semantic interrupt labels; `mbox-names` for mailbox channel names; `mboxes` for mailbox channels; `shmem` for shared-memory regions; `#address-cells` for child-node address cell width; `#size-cells` for child-node size cell width. The top-level closure rule is `unevaluatedProperties: false`. Maintainers: Sudeep Holla <sudeep.holla@arm.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and kernel subsystems, not by this YAML file. `dt_binding_check` loads the core meta-schema, resolves references such as `/schemas/firmware/nxp,imx95-scmi.yaml`, `/schemas/types.yaml#/definitions/uint32`, `#/$defs/protocol-node`, `/schemas/regulator/regulator.yaml#`, `/schemas/pinctrl/pinctrl.yaml`, `/schemas/firmware/nxp,imx95-scmi-pinctrl.yaml`, `/schemas/pinctrl/pincfg-node.yaml#`, `/schemas/pinctrl/pinmux-node.yaml#`, applies `properties`, `required`, enum/const/items limits, and any `allOf` or conditional branches, then validates the inline examples. During boot, a matching DT node is compiled into the DTB, the kernel matches `compatible`, subsystem code reads cells and phandles, and the bound driver consumes resources such as mailbox channels, shared-memory mailboxes. Conditional/schema-composition points include `anyOf`, `if`, `then`, `else`, `conditional branches`, `$defs`, so different compatibles or child-node shapes can activate different required-property sets. Nested or patterned child schema surfaces include `arm,max-msg-size`, `arm,max-msg`, `arm,smc-id`, `linaro,optee-channel-id`, `protocol@11`, `protocol@12`, `protocol@13`, `protocol@14`, `protocol@15`, `protocol@16`, and 2 more.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, resource topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though no kernel state is stored here.

**Dependencies and integration points:** Integrated with firmware, mailbox, shared-memory, secure-monitor, system-controller, clock, reset, power, and FPGA manager drivers. Direct schema dependencies are `/schemas/firmware/nxp,imx95-scmi.yaml`, `/schemas/types.yaml#/definitions/uint32`, `#/$defs/protocol-node`, `/schemas/regulator/regulator.yaml#`, `/schemas/pinctrl/pinctrl.yaml`, `/schemas/firmware/nxp,imx95-scmi-pinctrl.yaml`, `/schemas/pinctrl/pincfg-node.yaml#`, `/schemas/pinctrl/pinmux-node.yaml#`; resource dependencies visible in the property set include mailbox channels, shared-memory mailboxes. Driver integration is through `compatible`, while client/provider integration is through cell properties, phandle arrays, child schemas, and bus-standard properties declared or inherited here.

**Risks:** Main risks are schema ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, missing required clocks/resets/interrupts/power domains, stale examples, and conditional branches that accept one SoC variant while rejecting another valid one. Unknown-property policy also matters: `unevaluatedProperties: false` can either catch misspelled DTS properties or allow legacy extension points. For bindings with child nodes or graph/connector references, parent-child address-cell and port layout mistakes can pass driver review only if dtbs_check coverage is weak.
