# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/pci/fsl,imx6q-pcie-common.yaml

**Purpose:** Defines the Devicetree YAML/JSON-schema contract for `Freescale i.MX6 PCIe RC/EP controller`. It is a endpoint controller or endpoint-bus binding in the NXP/Freescale i.MX DesignWare PCIe family; it constrains how DTS/DTB nodes identify the PCI hardware, describe register windows, interrupts, clocks, resets, PHYs, address translation, DMA/IOMMU reachability, and optional child/root-port layout for Linux PCI probing. The source description says: Generic Freescale i.MX PCIe Root Port and Endpoint controller properties.

**Important APIs/types/functions:** This file is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/pci/fsl,imx6q-pcie-common.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, the `properties` block, `required` list, schema-composition keywords, inline examples, and the compatible strings consumed by kernel OF match tables. This common schema does not declare a concrete top-level `compatible`; concrete bindings include it by `$ref`. Directly declared properties are `clocks`, `clock-names`, `num-lanes`, `fsl,imx7d-pcie-phy`, `power-domains`, `power-domain-names`, `resets`, `reset-names`, `fsl,tx-deemph-gen1`, `fsl,tx-deemph-gen2-3p5db`, `fsl,tx-deemph-gen2-6db`, `fsl,tx-swing-full`, `fsl,tx-swing-low`, `fsl,max-link-speed`, `phys`, `phy-names`, `vpcie-supply`, `vph-supply`. Required properties are `clocks`, `clock-names`, `num-lanes`. Maintainers: Lucas Stach <l.stach@pengutronix.de>, Richard Zhu <hongxing.zhu@nxp.com>.

**Control flow:** Validation flow is handled by dt-schema: the core meta-schema loads this YAML, resolves references (`/schemas/types.yaml#/definitions/phandle`, `/schemas/types.yaml#/definitions/uint32`), applies direct property constraints, evaluates top-level `allOf` composition, and then applies conditional branches. At runtime the compiled DTB has no code from this file; the kernel matches `compatible`, maps `reg` resources, programs PCI ranges, requests interrupts/MSI mappings, enables clocks/resets/regulators/PHYs/power domains, and creates host bridge/root-port or endpoint objects according to the described node.

**State and persistence behavior:** The schema owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability for board DTS files and shipped DTBs: compatible ordering, resource names, cell counts, interrupt maps, address ranges, and child-node layout become the long-lived contract that drivers and firmware rely on. For this file, the top-level and composed unknown-property policy is: additionalProperties: true.

**Dependencies:** Direct schema dependencies are `/schemas/types.yaml#/definitions/phandle`, `/schemas/types.yaml#/definitions/uint32`. Resource dependencies visible in the binding include `clocks` (clock provider phandles); `clock-names` (stable clock input names); `num-lanes` (link width constraint); `power-domains` (genpd domain phandles); `power-domain-names` (stable power-domain names); `resets` (reset-controller phandles); `reset-names` (stable reset line names); `phys` (PHY phandles for PCIe lanes); `phy-names` (stable PHY names); `vpcie-supply` (endpoint/slot regulator supply) The binding also depends on the broader Devicetree PCI schemas, dt-schema tooling, and matching Linux PCI host/endpoint drivers for the compatible strings above.

**Integration points:** Integrates with Linux OF platform matching through `compatible`, PCI core setup through `device_type`, `bus-range`, `ranges`, `dma-ranges`, `#address-cells`, and `#size-cells`, interrupt infrastructure through `interrupt-map`, `interrupts`, MSI controllers or `msi-map`, and SoC resource managers through clocks, resets, PHY, regulator, power-domain, and IOMMU properties. Nested integration surface: no nested child schema declared directly.

**Risks:** Main risks are ABI drift in required properties, accepting a DTS shape that the driver cannot probe, rejecting valid legacy boards, stale examples, wrong `reg-names`/`clock-names`/`reset-names` ordering, incomplete compatible coverage, and conditional branches whose `contains`/`enum` logic does not match real fallback-compatible ordering. PCI-specific risk is high around address translation and interrupts: bad `ranges`, `dma-ranges`, `iommu-map`, `msi-map`, or `interrupt-map-mask` can validate syntactically while producing unprobeable devices or broken DMA/MSI at runtime.
