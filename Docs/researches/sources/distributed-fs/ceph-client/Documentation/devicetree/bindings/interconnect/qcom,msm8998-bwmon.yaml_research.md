# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interconnect/qcom,msm8998-bwmon.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interconnect/qcom,msm8998-bwmon.yaml` is a Linux devicetree YAML schema for the `Qualcomm Interconnect Bandwidth Monitor` Qualcomm interconnect provider binding. Bandwidth Monitor measures current throughput on buses between various NoC fabrics and provides information when it crosses configured thresholds. Certain SoCs might have more than one Bandwidth Monitors, for example on SDM845:: - Measuring the bandwidth between CPUs and Last Level Cache Controller - called just BWMON, - Measuring the bandwidth between Last Level Cache Controller and memory (DDR) - called LLCC BWMON. It is not executable kernel code; it is the hardware-description ABI that DTS authors, dt-schema, and the relevant kernel subsystem rely on so the runtime driver can parse the node without board-specific ambiguity.

## Control Flow, State, and Persistence
Control flow is declarative JSON-schema evaluation rather than executable branching. `dt-doc-validate` and `dt_binding_check` load the YAML, expand `$ref` links, apply composition and conditional keywords, validate the DTS example blocks, and later `dtbs_check` applies the same contract to compiled board devicetrees. For interconnect providers, validation ensures that provider cells, register banks, clocks, power domains, BCM voter links, and OPP or devfreq relationships are well-formed before Linux interconnect providers register bandwidth paths consumed by other device nodes. The schema itself stores no mutable state and writes no persistent data; its persistence is the stable source-controlled hardware ABI. External references used in evaluation are none; top-level/nested conditional keywords present are `allOf`, `else`, `if`, `oneOf`, `then`.

## Risks
Risks are mostly ABI and validation risks rather than algorithmic failures. Tightening required properties, changing compatible ordering, renaming resources, altering cell counts, or closing extra properties can reject existing DTS users; loosening constraints can allow nodes that later fail driver probe or misdescribe hardware. This schema has 8 top-level properties and 8 distinct nested property names, with strictness profile: unknown top-level properties are rejected. Conditional branches and shared `$ref` schemas should be checked against all in-tree users before edits, because a schema-only patch can still break board builds.
