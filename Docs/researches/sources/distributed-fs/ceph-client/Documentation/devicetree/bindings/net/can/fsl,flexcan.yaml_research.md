# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/can/fsl,flexcan.yaml

## Purpose
`sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/net/can/fsl,flexcan.yaml` defines the CAN controller binding titled `Flexcan CAN controller on Freescale's ARM and PowerPC system-on-a-chip (SOC).`. It constrains compatible strings, required resources, common schema references, and optional child nodes before Linux network, Bluetooth, CAN, MDIO, Ethernet, or DSA drivers consume the node at probe time.

The public interface is the YAML/dt-schema ABI, not C-callable functions. `compatible` uses `oneOf` with 6 branches with 20 tokens: `fsl,imx95-flexcan`, `fsl,imx93-flexcan`, `fsl,imx8qm-flexcan`, `fsl,imx8mp-flexcan`, `fsl,imx6q-flexcan`, `fsl,imx28-flexcan`, `fsl,imx25-flexcan`, `fsl,p1010-flexcan`, `fsl,vf610-flexcan`, `fsl,ls1021ar2-flexcan`, `fsl,lx2160ar1-flexcan`, `nxp,s32g2-flexcan`, `fsl,imx53-flexcan`, `fsl,imx35-flexcan`, `fsl,imx7d-flexcan`, `fsl,imx6ul-flexcan`, `fsl,imx6sx-flexcan`, `fsl,ls1028ar1-flexcan`, and 2 more. Top-level properties are `compatible`, `reg`, `interrupts`, `interrupt-names`, `clocks`, `clock-names`, `clock-frequency`, `power-domains`, `xceiver-supply`, `phys`, `big-endian`, `can-transceiver`, `fsl,stop-mode`, `fsl,clk-source`, `wakeup-source`, `fsl,scu-index`, `termination-gpios`, `termination-ohms`. Important property roles: `compatible` selects the OF match table and stable hardware ABI; `reg` carries MMIO ranges, bus addresses, chip selects, or switch port indexes; `interrupts` routes controller, wake, link, or error IRQs; `interrupt-names` routes controller, wake, link, or error IRQs; `clocks` connects clock providers and names; `clock-names` connects clock providers and names; `xceiver-supply` links a regulator supply; `phys` binds MAC/switch ports to PHY or fixed-link mode; `can-transceiver` models CAN controller or transceiver capability; `termination-gpios` describes board GPIO wiring.

## Control Flow
Control flow is declarative schema evaluation. During `make dt_binding_check` or `make dtbs_check`, dt-schema loads the YAML, resolves `$ref` entries, matches by `$id`, `$nodename`, `compatible`, or fragment inclusion, checks required properties, evaluates `allOf`, validates examples, and enforces `additionalProperties` or `unevaluatedProperties`. At runtime the YAML itself does not execute. Firmware provides a DTB node for the CAN controller binding; Linux driver core or bus code matches a driver, then subsystem helpers consume the validated resources. Child schemas such as `ports`, `ethernet-ports`, MDIO children, or CAN transceiver links guide later parsing by DSA, phylink, PHYLIB, Bluetooth, or SocketCAN drivers.

## State and Persistence Behavior
The schema stores no mutable kernel state and writes no persistent data. Persistence is the Devicetree ABI: compatible strings, property names, array order, phandle cell counts, child-node names, and example layouts are contracts carried by DTS sources and deployed DTBs. Runtime state is owned by drivers after probe, including netdev registration, bit-timing programming, bus-off/error counters, transceiver enablement, RX/TX mailboxes, and SocketCAN state; this file only constrains how hardware and board wiring are represented.

## Risks
Primary risks are incompatible ABI changes to clock and interrupt ordering, `can-transceiver` links, bit-rate capability properties, controller-specific compatible fallbacks, register windows, and optional timestamp/DMA resources, mismatches between documented compatibles and driver OF match tables, resource-order changes that pass schema review but break probe, and stale examples. This schema rejects unknown top-level properties with `additionalProperties: false`. Additional risk signals: conditional branches can validate one silicon variant while rejecting another; large compatible lists are prone to missing or misordered fallback entries; GPIO polarity or naming mistakes can invert reset, shutdown, wake, or interrupt behavior; CAN timing and transceiver capability units must match driver expectations.
