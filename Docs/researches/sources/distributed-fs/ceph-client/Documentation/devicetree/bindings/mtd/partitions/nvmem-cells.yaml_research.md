# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/mtd/partitions/nvmem-cells.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Nvmem cells`. In this tree it is a MTD flash partition parser or partition subnode binding: it constrains how DTS authors describe hardware, and it gives Linux OF/platform code a stable ABI for matching drivers, acquiring resources, and validating board descriptions with dt-schema. The source description says: Any partition containing the compatible "nvmem-cells" will register as a nvmem provider. Each direct subnodes represents a nvmem cell following the nvmem binding. Nvmem binding to declare nvmem-cells can be found in: Documentation/devicetree/bindings/nvmem/nvmem.yaml

**Important APIs/types/functions:** This is declarative schema, not executable C code. The public interface is the binding ABI exposed through `$id` `http://devicetree.org/schemas/mtd/partitions/nvmem-cells.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `description`, `maintainers`, `properties`, `required`, schema composition keywords, and inline `examples`. Compatible strings or match identifiers include none directly enumerated; this file is primarily common schema or child-node infrastructure. Top-level required properties are `compatible`. Important properties include `compatible`. Property roles include `compatible`: driver match key and stable hardware ABI identifier. Direct or nested schema references include `/schemas/mtd/partitions/partition.yaml#`, `/schemas/nvmem/nvmem.yaml#`, `/schemas/nvmem/nvmem-deprecated-cells.yaml#`. The top-level closure policy is `unevaluatedProperties: false`. Maintainers: Ansuel Smith <ansuelsmth@gmail.com>.

**Control flow:** Runtime control flow is supplied by Devicetree tooling and Linux subsystem drivers. `dt_binding_check` loads the core meta-schema, resolves references, evaluates `properties`, `required`, enum/const/items limits, and composition rules, then validates the examples. `dtbs_check` applies the same contract to compiled board DTBs. At boot, the flattened DT node is matched through `compatible` or inherited child-node context, the relevant driver parses resources such as MMIO ranges, interrupts, clocks, resets, regulators, PHYs, muxes, ECC engines, partitions, or child buses, and subsystem helpers enforce the generic parts of the contract. Schema composition/control branches in this file: allOf=1. Nested schema surface: no nested child-node schemas detected at the top level.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: accepted DTS/DTB nodes encode hardware identity, resource topology, child-node layout, and phandle cell widths for long-lived boards. Tightening `required`, changing compatible ordering, changing cell counts, or altering `additionalProperties`/`unevaluatedProperties` can break existing DTBs even though no state is stored by the YAML itself.

**Dependencies and integration points:** Integrates with MTD partition parsers, flash map/NAND/SPI-NOR parents, UBI/NVMEM consumers, and bootloader-specific layout discovery. Devicetree/dt-schema dependencies are the core meta-schema plus `/schemas/mtd/partitions/partition.yaml#`, `/schemas/nvmem/nvmem.yaml#`, `/schemas/nvmem/nvmem-deprecated-cells.yaml#`. Driver integration is through OF match tables and subsystem parsers; board integration is through phandles, address/size cells, interrupts, clocks, resets, regulators, power domains, child flash/partition nodes, MDIO/PHY links, mux specifiers, and examples that document expected DTS shape.

**Risks:** Main risks are ABI drift, under-specified compatibles, required resources that do not match real SoC integration, wrong `#*-cells` counts, stale examples, and conditional branches that validate one variant while rejecting another valid one. For storage bindings, partition/ECC/timing mistakes can silently corrupt flash or make media unprobeable. For network bindings, PHY mode, MDIO, reset, MAC-address, or clock mistakes can leave links down. For mux and common schemas, over-permissive closure can hide misspelled properties while over-tight closure can reject legitimate inherited properties.
