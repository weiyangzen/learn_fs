# sources/distributed-fs/ceph-client/Documentation/devicetree/bindings/interrupt-controller/fsl,ls-extirq.yaml

**Purpose:** Defines the Devicetree JSON-schema contract for `Freescale Layerscape External Interrupt Controller`. In this tree it is an interrupt controller binding: it constrains how board DTS files describe the hardware block, what phandle provider/client ABI is exposed, and how Linux discovers the device through OF matching and common DT resource helpers. The source description says: Some Layerscape SOCs (LS1021A, LS1043A, LS1046A LS1088A, LS208xA, LX216xA) support inverting the polarity of certain external interrupt lines.

**Important APIs/types/functions:** This YAML is declarative schema, not executable code. Its public ABI surface is `$id` `http://devicetree.org/schemas/interrupt-controller/fsl,ls-extirq.yaml#`, `$schema` `http://devicetree.org/meta-schemas/core.yaml#`, `title`, `maintainers`, `properties`, `required`, and any referenced dt-schema fragments. Compatible strings or compatible-pattern values are `fsl,ls1021a-extirq`, `fsl,ls1043a-extirq`, `fsl,ls1088a-extirq`, `fsl,ls1046a-extirq`, `fsl,ls2080a-extirq`, `fsl,lx2160a-extirq`. Required properties are `compatible`, `#interrupt-cells`, `#address-cells`, `interrupt-controller`, `reg`, `interrupt-map`, `interrupt-map-mask`. Important top-level properties are `compatible`, `#interrupt-cells`, `#address-cells`, `interrupt-controller`, `reg`, `interrupt-map`, `interrupt-map-mask`. Direct and nested `$ref` dependencies are none declared. Property roles include `compatible` for driver match key and stable hardware ABI identifier; `#interrupt-cells` for interrupt specifier cell count consumed by child/client nodes; `#address-cells` for child bus address cell width; `interrupt-controller` marks the node as an interrupt domain provider; `reg` for MMIO range, bus address, or child register selector; `interrupt-map` for binding-specific property constrained by the schema; `interrupt-map-mask` for binding-specific property constrained by the schema. The top-level unknown-property policy is `additionalProperties: false`. Maintainers are `Shawn Guo <shawnguo@kernel.org>`.

**Control flow:** Runtime control flow is supplied by dt-schema tooling and the kernel subsystem that consumes the resulting DTB. `dt_binding_check` loads the core meta-schema, resolves `$ref` entries, applies `properties`, `required`, enum/const/items limits, and composition keywords, then validates the examples. At boot, a DT node satisfying this schema is matched by `compatible`; resource helpers read `reg`, clocks, resets, power domains, interrupts, MSI/IOMMU cells, and child nodes; then the relevant IRQ-domain, MSI-domain, or IOMMU driver registers provider state for clients. Schema composition/conditional keywords present: `allOf`, `if`, `oneOf`, `then`. It does not define nested child-node schemas.

**State and persistence behavior:** The file owns no mutable runtime state and writes no persistent data. Its persistent effect is ABI stability: DTS and DTB nodes that satisfy this contract encode hardware identity, register layout, interrupt or translation-domain topology, phandle specifier widths, and child-node layout for long-lived board files. Changing required fields, compatible ordering, cell counts, or closure policy can break existing DTBs even though the YAML itself stores no kernel state.

**Dependencies and integration points:** Linux IRQ domain code uses it to translate DT interrupt specifiers into Linux IRQs and route them to an upstream parent domain. Schema-level dependencies are the core Devicetree meta-schema plus the `$ref` targets listed above. Resource integration is through properties such as `#address-cells`, `reg`. Driver integration is through `compatible`; provider/client integration is through cell-count properties, phandle arrays, child schemas, and any common binding references inherited by dt-schema.

**Risks:** Main risks are Devicetree ABI drift, incomplete compatible coverage, wrong `#*-cells` counts, overly broad or overly strict conditional branches, missing required clocks/resets/interrupt parents/power domains, and stale examples. Closure policy matters because false unknown-property settings catch misspellings but can reject legitimate board extensions. For interrupt/MSI/IOMMU providers, incorrect parent-domain links or specifier widths can pass schema validation yet fail at boot with lost interrupts, bad affinity, MSI allocation failure, or DMA translation faults.
