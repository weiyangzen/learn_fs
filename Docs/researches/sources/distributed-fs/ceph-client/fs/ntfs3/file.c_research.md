# sources/distributed-fs/ceph-client/fs/ntfs3/file.c

Purpose: implements the NTFS3 regular-file VFS surface: stat attributes, ioctl handling, mmap admission, truncate/extend, fallocate, read/write/splice, open/release, fiemap, fsync, and llseek. The file is the bridge between Linux VFS/iomap operations and NTFS-specific inode state such as valid data length, resident/nonresident data, sparse/compressed allocation, delayed allocation, and volume dirty/shutdown flags.

Important APIs/functions: exports `ntfs_ioctl`, `ntfs_compat_ioctl`, `ntfs_getattr`, `ntfs_setattr`, `ntfs_file_open`, `ntfs_fiemap`, `ntfs_file_fsync`, `ntfs_file_inode_operations`, and `ntfs_file_operations`. Key private helpers include `ntfs_should_use_dio`, `ntfs_ioctl_fitrim`, `ntfs_force_shutdown`, `ntfs_extend_initialized_size`, `ntfs_file_mmap_prepare`, `ntfs_extend`, `ntfs_truncate`, `ntfs_fallocate`, `check_read_restriction`, `ntfs_file_read_iter`, `ntfs_compress_write`, `check_write_restriction`, `ntfs_file_write_iter`, `ntfs_file_release`, and `ntfs_llseek`.

Control flow: ioctl dispatch validates the inode and routes FITRIM, label get/set, and forced shutdown commands through capability and user-copy checks. `getattr` augments generic stat data with NTFS creation time, cluster blksize, immutable/append/compressed/encrypted flags. Size-changing paths call `setattr_prepare`, wait for direct I/O, then either truncate through `attr_set_size_ex` or extend via `ntfs_set_size` plus valid-size zeroing. `fallocate` handles punch, collapse, insert, and preallocation by serializing with inode locks, direct-I/O wait, page-cache invalidation, and lower attribute range helpers.

Read control flow first rejects bad, shutdown, encrypted, unsupported external-compressed, and deduplicated inodes. Buffered reads delegate to `generic_file_read_iter`; aligned direct reads use `iomap_dio_rw`, force delayed allocations out of the way, and zero any range beyond `ni->i_valid` but within `i_size`. Splice reads reuse the same restriction helper and then `filemap_splice_read`. Write control flow locks the inode, runs generic write checks, removes privileges/updates timestamps through `file_modified`, extends allocation/size before data copy, then chooses compressed-frame writing, buffered iomap writing, or aligned direct iomap writing with buffered fallback on residual data or invalidation failure. Open rejects direct I/O for compressed/encrypted files and optionally decompresses WOF/LZX/Xpress files before write/truncate opens. Release of the last writer materializes delayed allocations and trims preallocation.

State and persistence: the file updates `ni->i_valid`, `i_size`, `ni->std_fa`, `NI_FLAG_UPDATE_PARENT`, delayed-allocation runs, and superblock dirty/shutdown bits. It marks inodes dirty after metadata-visible changes and uses `ntfs_sync_inode`, `write_inode_now`, `ni_write_parents`, `ntfs_update_mftmirr`, `sync_blockdev`, and block-device flushes to persist fsync/dirsync paths. mmap write-close can advance initialized size when the mapped range extends past the prior valid length. Forced shutdown freezes the block device, sets `NTFS_FLAGS_SHUTDOWN_BIT`, and thaws it.

Dependencies and integration points: depends on Linux VFS, iomap, folio/page-cache, direct I/O, fstrim, fileattr/statx, splice, block-device flush/discard, and capability/user-copy APIs. NTFS integration comes from `ntfs_iomap_ops`, `ntfs_iomap_folio_ops`, `attr_data_get_block`, `attr_set_size[_ex]`, `attr_punch_hole`, `attr_collapse_range`, `attr_insert_range`, `attr_force_nonresident`, `ni_allocate_da_blocks`, `ni_read_frame`, `ni_write_frame`, `ni_decompress_file`, `ni_seek_data_or_hole`, `ntfs_set_state`, `ntfs_set_label`, and ACL/xattr hooks. Operation tables wire the file into inode and file methods used by the VFS.

Risks: valid-data-length handling is security-sensitive because reads beyond initialized data must zero-fill and writes extending a file must zero gaps before exposing data. Direct I/O has alignment and delayed-allocation constraints; incorrect fallback can violate O_DIRECT expectations or leave stale page-cache state. Fallocate range operations combine page-cache invalidation, cluster deallocation/allocation, and i_size/valid-size changes, so ordering bugs can corrupt sparse/compressed files. Compressed writes operate a full compression frame at a time and depend on page-cache state, frame-size assumptions, and `ni_write_frame` correctness. Forced shutdown and fsync paths alter persistent volume state and can affect crash recovery semantics.

Test signals: exercise generic xfstests for truncate/extend, direct I/O alignment and fallback, mmap write faults, `SEEK_DATA`/`SEEK_HOLE`, splice, fsync, fallocate punch/collapse/insert/keep-size, FITRIM, label ioctls, immutable/append mode changes, and last-writer preallocation cleanup. NTFS-specific coverage should include resident-to-nonresident transitions, sparse holes, native compressed files, external compressed open-for-write decompression, delayed allocation materialization before DIO/release, forced shutdown returning `-EIO`, and verification that reads past valid size return zeroes.
