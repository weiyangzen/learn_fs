# sources/distributed-fs/ceph-client/fs/ntfs3/fslog.c

Purpose: implements NTFS `$LogFile` restart parsing and crash replay. It validates restart pages and log-record pages, reconstructs restart tables, analyzes transaction and dirty-page state, reopens affected attributes, performs redo for dirty pages, performs undo for active transactions, updates the MFT mirror, and writes a clean restart area so the mounted volume can proceed after an unclean shutdown.

Important APIs/types/functions: defines on-disk LFS structures such as `RESTART_HDR`, `CLIENT_REC`, `RESTART_AREA`, `LOG_REC_HDR`, `RESTART_TABLE`, `OPEN_ATTR_ENRTY`, `DIR_PAGE_ENTRY`, `TRANSACTION_ENTRY`, `NTFS_RESTART`, `LFS_RECORD_HDR`, `LFS_RECORD`, and `RECORD_PAGE_HDR`; runtime helpers `struct ntfs_log`, `struct lcb`, `struct OpenAttr`; and operation enum `NTFS_LOG_OPERATION`. The public entry point is `log_replay`; exported validation helper is `check_index_header`. Key internals include restart-table allocation/enumeration helpers, `read_log_page`, `log_read_rst`, `log_create`, `log_create_ra`, `last_log_lsn`, `read_log_rec_buf`, `read_rst_area`, `read_log_rec_lcb`, `read_next_log_rec`, record/index validators, `attr_create_nonres_log`, `update_oa_attr`, and the replay operation dispatcher `do_action`.

Control flow: `log_replay` allocates an `ntfs_log`, normalizes page/file sizing, reads one or two restart pages, chooses the newest valid restart area, or creates a new one for an uninitialized log. It initializes LSN arithmetic, calculates oldest/current/next log positions, scans log pages via `last_log_lsn`, validates supported log versions, ensures the `NTFS` client exists, and reads the client restart area. It then loads restart tables for transactions, dirty pages, attribute names, and open attributes, converting older table layouts where needed.

Replay has three major passes. The analysis pass starts at the checkpoint LSN, walks forward through client records, updates/allocates transaction table entries, records dirty page table LCNs, handles deleted dirty clusters and hotfixes, and tracks open nonresident attributes. It computes the redo LSN from dirty pages and transactions. The redo setup reopens all attributes named in the open-attribute table, builds runlists from actual inodes or fake attributes, merges dirty-page LCNs into those runs, and skips replay entirely on read-only mounts after setting `NTFS_FLAGS_NEED_REPLAY`. The redo pass walks forward from the redo LSN and applies only dirty-page-affecting operations whose page mappings still matter. The undo pass walks active transactions by `undo_next_lsn` and applies undo records until each transaction can be freed.

`do_action` is the central mutation engine. For MFT-record operations it loads the affected MFT record or parent-owned child record, validates LSN and record shape, then initializes/deallocates records, creates/deletes/resizes attributes, updates resident values, mapping pairs, nonresident sizes, root index entries, filename duplicates, and record tails. For allocation/index-buffer operations it reads the target run into memory, validates index buffers and offsets, mutates nonresident data/index pages/bitmaps, reapplies USA fixups, and writes the run back. Redo updates target page LSNs; undo passes `NULL` as the replay LSN. Validation failure marks `log->set_dirty` so the volume is dirtied for repair.

State and persistence: persistent state includes `$LogFile` restart pages, log-record pages, MFT records, index buffers, nonresident attribute data, bitmaps, transaction/dirty/open-attribute restart tables, client restart LSNs, `sbi->flags` (`NTFS_FLAGS_NEED_REPLAY`, log replaying elsewhere), MFT mirror state, and volume dirty/error state. In-memory state includes LSN sequence arithmetic, restart-area image, open attribute table entries with `OpenAttr` runlists and copied attribute headers, restart-table allocations, and log read-ahead. Successful replay clears `NTFS_FLAGS_NEED_REPLAY`, updates the MFT mirror, and writes two restart pages with no active client. Errors preserve `NEED_REPLAY`; read-only replay-needed mounts suppress `-EROFS` at exit but leave replay required.

Dependencies and integration points: depends on NTFS low-level run I/O (`ntfs_read_run_nb_ra`, `ntfs_read_run_nb`, `ntfs_sb_write_run`), USA fixup helpers, MFT load/write helpers (`mi_get`, `mi_write`, `mi_format_new`), inode lookup/loading (`ilookup`, `ntfs_iget5`, `iput`), runlist operations, bitmap bit operations, index validators/mutators, `$MFTMirr` update, dirty-state management, random open-log counts, and Linux allocation/byteorder APIs. It is invoked during mount against the `$LogFile` inode and coordinates with normal inode/file-record code by loading affected inodes and child MFT records.

Risks: this file parses attacker/corruption-controlled on-disk structures, so every size, offset, LSN, runlist, and restart-table calculation is security-sensitive. Multi-page log records, wraparound LSN arithmetic, restart-page selection, tail-copy repair, and version-0 table conversion are complex and easy to regress. `do_action` performs many `memmove` operations in MFT records and index buffers; missing validation can cause memory corruption or on-disk corruption. Fake open attributes allow replay to continue when target inodes are unavailable, but can hide mapping inconsistencies. Read-only mounts that need replay keep the volume unreplayed; callers must respect `NTFS_FLAGS_NEED_REPLAY`. Failure handling intentionally dirties the volume, so tests must distinguish recoverable dirty-volume paths from silent replay success.

Test signals: use crafted and real NTFS images with clean logs, uninitialized logs, CHKD restart signatures, one-page and two-page restart areas, v1.0/v1.1/v2.0 logs, wrapped logs, multi-page records, tail-copy replacement, dirty-page table duplicates, deleted dirty clusters, hotfix records, active and committed transactions, and older restart-table layouts. Operation-level replay tests should cover MFT record initialize/deallocate, attribute create/delete/update/mapping-pair/size changes, root and allocation index entry edits, bitmap set/clear, filename duplicate updates, redo LSN skip behavior, undo of active transactions, read-only replay-needed mounts, invalid offsets/sizes causing dirty-error state, and successful restart-page rewrite plus MFT mirror update.
