## sources/distributed-fs/ceph-client/fs/smb/client/compress/lz77.h

Purpose: declares the SMB compression LZ77 encoder and exposes the destination-buffer sizing contract required by the encoder's bounds-check-free hot loop.

Important APIs, types, and functions: `lz77_compressed_alloc_size(u32 size)` returns `size + (size >> 3) + 8`, accounting for worst-case all-literal data plus 4-byte flag metadata at the start, every 32 tokens, and possible stream end. `lz77_compress(const void *src, u32 slen, void *dst, u32 *dlen)` compresses into a caller-provided destination buffer and updates `*dlen` with the actual compressed length.

Control flow: callers compute the allocation size with `lz77_compressed_alloc_size()`, allocate at least that many bytes, set `*dlen` to the allocation size, and call `lz77_compress()`. The C implementation checks this contract once at entry, writes the compressed stream, and reports success only when compression shrinks the payload.

State and persistence behavior: no state is defined by the header. The inline sizing helper directly affects allocation and safety for every compression call because `lz77_compress()` relies on the exact overprovisioning guarantee.

Dependencies and integration points: used by `fs/smb/client/compress.c` for outbound SMB3 write compression. It includes only kernel types and intentionally keeps the algorithm details private to `lz77.c`.

Risks: changing the allocation formula without proving the encoder's maximum output can reintroduce buffer overruns, while excessive overprovisioning increases memory pressure for large writes. The helper uses `u32`; callers must keep source lengths within SMB/client limits that fit this type. Consumers must treat `-EMSGSIZE` from `lz77_compress()` as a non-fatal "not worth compressing" result.

Test signals: allocation-size unit checks for zero, small, page-sized, and large SMB write lengths; compression calls with exactly the helper's returned size; incompressible all-literal data near 32-token boundaries; and build coverage that the header remains independent of SMB transport internals.
