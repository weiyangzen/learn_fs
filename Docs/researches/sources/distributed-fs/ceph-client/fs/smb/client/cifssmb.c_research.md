## sources/distributed-fs/ceph-client/fs/smb/client/cifssmb.c

Purpose: implements the SMB1/CIFS wire-PDU construction and response parsing layer for the Linux SMB client. It covers negotiate, tree connect/disconnect, echo/logoff, path and handle based create/open/read/write/lock/close, rename/link/symlink, reparse point FSCTLs, SMB1 file compression FSCTL, POSIX and CIFS ACL helpers, path/file/fs queries, directory enumeration, DFS referrals, EOF/allocation updates, attributes, Unix extension metadata, and EA get/set. The file is the SMB1 counterpart to the SMB2 PDU layer and is wired through `smb1proto.h` and the SMB1 ops tables.

Important APIs, types, and functions: public entry points include `CIFSSMBNegotiate()`, `CIFSTCon()`, `CIFSSMBTDis()`, `CIFSSMBEcho()`, `CIFSSMBLogoff()`, `CIFSPOSIXCreate()`, `SMBLegacyOpen()`, `CIFS_open()`, `cifs_async_readv()`, `CIFSSMBRead()`, `CIFSSMBWrite()`, `cifs_async_writev()`, `CIFSSMBWrite2()`, `cifs_lockv()`, `CIFSSMBLock()`, `CIFSSMBPosixLock()`, `CIFSSMBClose()`, `CIFSSMBFlush()`, `CIFSSMBRename*()`, `CIFSUnixCreate*Link()`, `CIFSCreateHardLink()`, `CIFSSMBUnixQuerySymLink()`, `cifs_query_reparse_point()`, `cifs_create_reparse_inode()`, `CIFSSMB_set_compression()`, ACL helpers, `CIFSSMBQ*Info()` query families, `CIFSFindFirst()`, `CIFSFindNext()`, `CIFSFindClose()`, `CIFSGetDFSRefer()`, `CIFSSMBSet*()` metadata mutators, `CIFSSMBQAllEAs()`, and `CIFSSMBSetEA()`. Core local helpers are `cifs_reconnect_tcon()`, `small_smb_init()`, `small_smb_init_no_tc()`, `smb_init()`, `smb_init_no_reconnect()`, `validate_t2()`, `smb_init_nttransact()`, `validate_ntransact()`, and conversion helpers for open disposition, access mode, ACLs, and Unix set-info payloads.

Control flow: most operations first call `small_smb_init()` or `smb_init()`, which perform reconnect handling, allocate a small or large CIFS buffer, assemble the SMB header, and increment per-tree sent counters. The caller then fills SMB word parameters, byte count, path strings in Unicode or local codepage form, transaction offsets, data areas, and command-specific flags before sending with `SendReceive()`, `SendReceive2()`, `SendReceiveNoRsp()`, or `cifs_call_async()`. Many path operations use a retry label on `-EAGAIN`, while handle based operations generally return `-EAGAIN` to the caller because the file/search handle may be stale after reconnect. Response parsing validates Trans2 or NT_TRANSACT offsets and byte counts, copies payloads into VFS-facing structs, and releases the CIFS buffer unless ownership is intentionally transferred to a search or reparse caller.

State and persistence behavior: the file updates in-memory session/server/tree state during negotiate and tree connect, including dialect, security mode, max request/IO sizes, capabilities, signing, crypt keys or extended security blobs, `tcon->tid`, share flags, native filesystem strings, Unix/fs/device/attribute info caches, and stats counters. Reconnect flow serializes session setup under `session_mutex`, marks opens invalid before reconnecting a tree, can swap to an alternate password on authentication-related reconnect failures, and returns `-EAGAIN` for handle-sensitive commands. Server-persistent effects include create/delete/rename/link/symlink, writes, locks, ACL/EA/attribute/time/EOF/Unix metadata changes, reparse point creation, and `FSCTL_SET_COMPRESSION`; the code itself writes no local persistent storage.

Dependencies and integration points: depends on CIFS core headers (`cifsglob.h`, `cifsproto.h`, `smb1proto.h`, `smb1pdu.h` transitively), SMB FSCTL constants, VFS inode/dentry/statfs/ACL/xattr types, Linux netfs subrequest APIs, fscache/smbdirect plumbing, DFS referral parsing, signing helpers, NLS conversion, tracepoints, and CIFS buffer/transport helpers. It is consumed through SMB1 operation tables in `smb1ops.c`, by higher-level VFS paths in inode/file/xattr/acl code, and by transport/session code for negotiate, reconnect, and async MID completion.

Risks: this is security-sensitive wire parsing code. Offset, ByteCount, data-count, and Unicode padding mistakes can lead to out-of-bounds reads/writes or malformed SMBs, so `validate_t2()` and `validate_ntransact()` checks are critical. Retry behavior is subtle because path commands can usually reissue after reconnect but handle commands must not silently reuse stale FIDs. Async read/write callbacks must release MIDs and credits exactly once, update netfs subrequest state, and preserve signature verification semantics. Directory search state transfers ownership of response buffers across calls and can leak, double-free, or expose stale entries if `psrch_inf` fields are mishandled. Protocol fallback paths, such as set-path-info falling back to open-by-handle, must not change access rights or object lifetime unexpectedly. SMB1 file compression here is `FSCTL_SET_COMPRESSION` on an opened file and is unrelated to SMB3 message compression in `compress.c`.

Test signals: negotiate against SMB1 servers with and without extended security/signing/Unicode/Unix extensions; reconnect tests that cover path retry versus stale-handle `-EAGAIN`; sync and async read/write with large-file offsets, short writes, signing, malformed responses, and credit accounting; Trans2/NT_TRANSACT fuzzing of offsets/counts/BCC; create/open disposition and access-mode matrix tests; lock, oplock-break, and POSIX lock flows; directory enumeration resume-name corruption and close behavior; DFS referral parsing over IPC tcon; reparse point get/create including cleanup on failure; `FSCTL_SET_COMPRESSION`; POSIX and CIFS ACL get/set; xattr list/get/set, including named EA misses and buffer-size `-ERANGE`; statfs/fs-attribute/device/Unix info queries; and Unix metadata set paths for uid/gid/mode/device/time.
