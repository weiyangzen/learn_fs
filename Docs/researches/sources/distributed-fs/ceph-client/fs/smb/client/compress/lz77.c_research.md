## sources/distributed-fs/ceph-client/fs/smb/client/compress/lz77.c

Purpose: implements the "plain" LZ77 compression algorithm used by SMB compression according to MS-XCA. It is a performance-oriented in-kernel encoder that produces an SMB-compatible compressed byte stream using 32-bit literal/match flags, match-distance/length encodings, and a hash table for recent positions.

Important APIs, types, and functions: exported function is `lz77_compress(const void *src, u32 slen, void *dst, u32 *dlen)`. Local helpers include unaligned little-endian read/write helpers (`lz77_read8/32/64()`, `lz77_write8/16/32()`), `lz77_match_len()`, `lz77_encode_match()`, `lz77_encode_literals()`, and `lz77_hash()`. Key constants are `LZ77_MATCH_MAX_DIST` (8 KiB), `LZ77_HASH_LOG`/`LZ77_HASH_SIZE` (32K entries), 4-byte read step/minimum match, 8-byte match-extension step, `LZ77_SKIP_TRIGGER`, and 32 tokens per flag word.

Control flow: `lz77_compress()` first validates that `*dlen` is at least `lz77_compressed_alloc_size(slen)`, sets source/end/read-limit pointers, reserves the first flag word, allocates a zeroed hash table, seeds the first hashes, and enters a hot main loop. The loop uses adaptive skipping to search for a recent hash match within the 8 KiB window, flushes pending literals, measures the full match length, emits a match code and any extra length nibbles/bytes, advances the anchor, and writes a flag word after every 32 literals/matches. At exit, it emits remaining literals, finalizes the last flag word with terminal one bits, stores the compressed length in `*dlen`, frees the hash table, returns 0 only if the output is smaller than the input, and otherwise returns `-EMSGSIZE`.

State and persistence behavior: all state is per-call and temporary: source/destination cursors, current flag accumulator/count/address, pending nibble pointer for packed match lengths, and a `kvcalloc()` hash table of source offsets. No global or persistent state is modified. The destination buffer is intentionally written without per-write bounds checks after the initial allocation-size contract is verified.

Dependencies and integration points: included by `compress.c` through `compress/lz77.h`; depends on kernel allocation, size constants, count-zero helpers, and unaligned access helpers. The caller supplies source and destination buffers and interprets `-EMSGSIZE` as "send the original uncompressed request." The emitted format must match SMB/MS-XCA consumers on the server side.

Risks: the implementation is intentionally order- and branch-sensitive; small changes to the hot loop can cause major performance regressions or alter compression ratio. Safety depends on the worst-case destination size calculation in `lz77_compressed_alloc_size()` and the caller honoring it. The function assumes the input is large enough for initial 32-bit and match-limit reads; current call paths only compress writes at least `PAGE_SIZE`, but direct unit tests must avoid tiny inputs or add guards. Match distance and length encoding must remain protocol-compatible, including the alternating extra-length nibble packing. Returning `-EMSGSIZE` for larger output is part of normal control flow and must not be logged as a hard failure by callers.

Test signals: known-answer LZ77 streams for literals, short matches, long matches requiring nibble/byte/16-bit/32-bit length encodings, alternating match/literal flag boundaries at 32 tokens, match distances near 1 and 8 KiB, incompressible data returning `-EMSGSIZE`, small and exact allocation-size validation, allocation-failure injection, cross-server decompression interoperability, and performance regression tests on repeated, sparse, text, and random data.
