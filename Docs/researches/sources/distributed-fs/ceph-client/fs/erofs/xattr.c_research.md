# sources/distributed-fs/ceph-client/fs/erofs/xattr.c

Purpose: Implements EROFS extended attribute lookup, listing, long-prefix tables, POSIX ACL retrieval, xattr-name filtering, and optional inode fingerprint extraction for page-cache sharing.

Important APIs, types, and functions: `struct erofs_xattr_iter` carries the metadata buffer, current on-disk position, destination buffer, lookup key, and dentry context. `erofs_init_inode_xattrs()` lazily reads the per-inode xattr ibody header and shared xattr ID array. `erofs_xattr_iter_inline()` scans inline xattr entries; `erofs_xattr_iter_shared()` scans shared entries from the global xattr block area. `erofs_getxattr()` and `erofs_listxattr()` are the primary VFS-facing operations. `erofs_xattr_prefixes_init()` loads long-prefix descriptors at mount time, while `erofs_xattr_prefixes_cleanup()` frees them. Optional `erofs_get_acl()`, `erofs_inode_has_noacl()`, and `erofs_xattr_fill_inode_fingerprint()` support ACL and page-cache-share configurations.

Control flow: First access to an inode's xattrs calls `erofs_init_inode_xattrs()`. It returns `-ENODATA` if no xattrs exist, otherwise serializes initialization with `EROFS_I_BL_XATTR_BIT`, validates `xattr_isize` and shared-count bounds, reads `h_name_filter`, allocates `xattr_shared_xattrs`, fills shared IDs, then publishes initialized fields with an `smp_mb()` before setting `EROFS_I_EA_INITED_BIT`. Lookup uses the optional xattr-name Bloom-style filter to skip impossible names, then scans inline entries and falls back to shared entries. Each entry validates index/long-prefix infix/name length, compares names across block boundaries, and either reports value length, copies the value, or returns `-ENODATA`. Listing builds full VFS xattr names from base prefixes, optional long-prefix infixes, and entry names while enforcing caller buffer size.

State and persistence behavior: On-disk state includes per-inode inline xattr areas, shared xattr references, global shared xattr entries, and optional long-prefix metadata. Runtime state is cached per inode in `xattr_name_filter`, `xattr_shared_count`, and `xattr_shared_xattrs`, guarded by inode flag bits. Superblock-level `xattr_prefixes` stores heap-allocated prefix records until unmount. Data remains read-only; mutation paths only allocate/free caches and produce ACL/fingerprint objects.

Dependencies and integration points: Installs handlers through `erofs_xattr_handlers` for user, trusted, and optional security namespaces. Uses VFS xattr handler helpers, Linux capabilities for trusted listing, POSIX ACL conversion, `xxhash` filtering, metadata-buffer helpers from EROFS core, metabox/packed-inode selection, and optional page-cache-sharing fingerprint fields. `super.c` installs the handler array and initializes prefix tables after mount.

Risks: On-disk bounds checks are critical: malformed `xattr_isize`, shared counts, long-prefix indices, and entry sizes can otherwise overrun metadata. Lazy initialization relies on memory barriers and bit locks; missing the barrier can expose partially filled per-inode fields. The xattr filter is inverted by format convention, so false rejection would hide real attributes. Listing silently skips unsupported or unauthorized prefixes, which is correct but can mask malformed long-prefix indices. Fingerprint extraction treats unexpected value lengths as corruption.

Test signals: Cover inodes with no xattrs, inline-only xattrs, shared-only xattrs, cross-block names/values, long-prefix xattrs, unknown long-prefix IDs, xattr-name filter hits and misses, buffer-size probes versus `-ERANGE`, user-xattr mount option disabled, trusted xattrs with and without `CAP_SYS_ADMIN`, POSIX ACL access/default retrieval, malformed shared counts and entry sizes, metabox/packed prefix storage, and inode-share fingerprint success and corruption cases.
