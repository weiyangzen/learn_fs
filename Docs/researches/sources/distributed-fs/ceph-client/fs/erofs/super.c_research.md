# sources/distributed-fs/ceph-client/fs/erofs/super.c

Purpose: Implements EROFS filesystem registration, mount-context parsing, superblock loading, device-table setup, internal inode lifetime, export support, sysfs/shrinker/xattr integration, and module init/exit. This file is the main bridge between VFS mount operations and the EROFS on-disk format.

Important APIs, types, and functions: `_erofs_printk()` formats device-aware messages. `erofs_read_metadata()` reads variable-length 4-byte-aligned metadata records across block boundaries. `erofs_read_superblock()` validates the primary superblock magic, block size, feature bits, checksum, root nid, 48-bit fields, metabox fields, xattr-prefix fields, compression config, and device table. `erofs_fc_parse_param()` handles mount options such as `user_xattr`, `acl`, `cache_strategy`, `dax`, extra `device`, `fsid`, `domain_id`, `directio`, `fsoffset`, and `inode_share`. `erofs_fc_fill_super()` builds the active `super_block`; `erofs_fc_get_tree()` selects block-device, fscache nodev, or file-backed mount paths; `erofs_put_super()` and `erofs_kill_sb()` tear down mounted state. `erofs_module_init()` creates the inode slab, shrinker, compressed-data subsystem, sysfs, inode-share subsystem, and filesystem registration.

Control flow: Mounting starts with `erofs_init_fs_context()`, which allocates `struct erofs_sb_info` plus an `erofs_dev_context` IDR and installs `erofs_context_ops`. Parameter parsing mutates only the pending context. `erofs_fc_get_tree()` first tries normal block-device mounting, optionally retries file-backed mounting after `-ENOTBLK`, or uses nodev mode for fscache on-demand mounts. `erofs_fc_fill_super()` sets read-only/noatime VFS flags, validates DAX/inode-sharing constraints, configures backing device information, reads the superblock, adjusts block size, initializes compression cache state, loads packed/metabox/root inodes, registers the shrinker, initializes xattr prefixes, registers per-superblock sysfs, and publishes the root dentry. Teardown unregisters sysfs, shrinker, xattr prefixes, internal inodes, fscache cookies, DAX references, opened device files, and heap strings.

State and persistence behavior: Persistent state comes from the EROFS superblock and optional device/xattr/compression metadata. Runtime state lives in `erofs_sb_info`: mount options, feature flags, device IDR, DAX handles, fscache cookies, file-backed source, total block count, root/packed/metabox inodes, sysfs kobject, shrinker list node, and optional fsid/domain strings. Inodes are allocated from `erofs_inode_cachep`; `erofs_free_inode()` releases fast-symlink storage and per-inode shared xattr arrays. The filesystem is always mounted read-only, but runtime caches and kobjects persist until unmount.

Dependencies and integration points: Integrates with fs_context, VFS super operations, exportfs file handles, block devices, file-backed IO, fscache, DAX, sysfs, EROFS xattr/ACL handlers, compressed EROFS (`z_erofs_*`), shrinker registration, tracepoints, and optional page-cache sharing/on-demand features. Export operations encode 64-bit EROFS nids and generation numbers for NFS-style lookup.

Risks: Superblock parsing is security-critical because feature flags, 48-bit block counts, xattr prefix indices, metabox nid, and device-table slots come from disk. Cleanup paths are split between failed fs_context setup, `put_super`, and `kill_sb`, so leaks or double releases are possible if ownership transfer changes. DAX is disabled dynamically when unsupported; tests must cover fallback behavior. File-backed mounts intentionally avoid stacked filesystems to prevent recursion and stack-depth problems.

Test signals: Exercise valid and corrupted superblocks, checksum mismatch, unsupported incompatible features, non-page block sizes, fsoffset alignment, extra device count mismatches, file-backed mount rejection on stacked filesystems, DAX fallback, fscache/nodev mode, xattr-prefix init failure, packed/metabox inode loading, export handle round trips, remount/reconfigure of ACL options, module init failure unwinding, and unmount cleanup under active cached compressed data.
