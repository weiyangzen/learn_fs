# sources/distributed-fs/ceph-client/fs/btrfs/compression.h

Purpose: declares the Btrfs compression interface shared by the core filesystem, algorithm backends, read/write IO paths, and defrag. It defines compression size limits, the compressed bio wrapper, workspace manager ABI, compression level metadata, and public entry points for compression, decompression, workspace lifetime, folio caching, and heuristic decisions.

Important APIs/types/functions: constants `BTRFS_MAX_COMPRESSED`, `BTRFS_MAX_COMPRESSED_PAGES`, `BTRFS_COMPRESSION_CHUNK_SIZE`, and `BTRFS_MAX_UNCOMPRESSED` cap on-disk compressed payloads, per-worker input chunks, and in-memory decompressed ranges. `struct compressed_bio` embeds `struct btrfs_bio` and stores the inode offset, uncompressed length, compression type, writeback flag, and original read bio. `struct workspace_manager` tracks idle workspaces, free/total counts, locking, and waiters. `struct btrfs_compress_levels` describes algorithm min/max/default levels. Public functions include init/exit (`btrfs_init_compress()`, `btrfs_exit_compress()`), per-fs workspace allocation/free, type and level helpers, compressed read/write submission, inline decompression, buffer-to-page decompression copy, heuristic evaluation, folio allocation/free, workspace get/put, and backend hooks for zlib/lzo/zstd.

Control flow: callers allocate or receive `compressed_bio` objects through this API, fill algorithm-specific compressed pages, and submit them through Btrfs bio plumbing. Read paths pass an original `btrfs_bio` to `btrfs_submit_compressed_read()`, while write paths call `btrfs_compress_bio()` or `btrfs_alloc_compressed_write()` plus `btrfs_submit_compressed_write()`. Algorithm backends implement the declared `*_compress_bio()`, `*_decompress_bio()`, `*_decompress()`, workspace allocation, and workspace release hooks. `cleanup_compressed_bio()` is the common error cleanup helper for callers that allocated compressed folios but did not submit successfully.

State and persistence: the header exposes the layout of transient in-memory state only. `compressed_bio` persists for one compressed IO and owns the embedded bio plus compressed folio references until completion or cleanup. Workspace managers persist for the mounted filesystem lifetime, not on disk. Constants here influence durable extent layout indirectly by limiting compressed extent sizes to 128 KiB and default zlib level to 3, but no on-disk structures are defined in this header.

Dependencies and integration: includes Linux memory, list, workqueue, waitqueue, pagemap, and size headers plus Btrfs `bio.h`, `fs.h`, and `btrfs_inode.h`. It is consumed by compression backends, read/write file paths, defrag, inline extent readers, and mount-option parsing. It also relies on UAPI/metadata compression type values such as `BTRFS_COMPRESS_ZLIB`, `BTRFS_COMPRESS_LZO`, and `BTRFS_COMPRESS_ZSTD`.

Risks: size-limit constants are part of broad IO behavior, so changing them affects memory pressure, random-read amplification, compressed extent compatibility, and backend assumptions. `cleanup_compressed_bio()` assumes all folios in the embedded bio came from `btrfs_alloc_compr_folio()`. The workspace-manager contract promises forward progress rather than propagating allocation errors, so backend workspace hooks must avoid unbounded or reclaim-unsafe behavior. The `BTRFS_NR_WORKSPACE_MANAGERS` definition maps the heuristic to compression type 0, making enum order significant.

Test signals: compile all compression backend combinations, run compressed read/write tests for zlib/lzo/zstd, validate level parsing and clamping, verify compressed extents never exceed declared limits, and run error cleanup paths under kmemleak or folio leak detection. Header/API changes should be checked by building algorithm backends, defrag, inline extent reads, and encoded write support together.
