# sources/distributed-fs/ceph-client/fs/btrfs/super.c

Purpose: Implements Btrfs VFS superblock integration: mount option parsing, fs-context lifecycle, subvolume mounting, remount/reconfigure, sync/statfs/freeze/shutdown operations, `/dev/btrfs-control` ioctls, and module init/exit sequencing. It is the front door from VFS and userspace into Btrfs filesystem state.

Important APIs/types/functions: Core types are `struct btrfs_fs_context`, `btrfs_super_ops`, `btrfs_fs_type`, `btrfs_ctl_fops`, and `mod_init_seq`. Mount parsing is handled by `btrfs_fs_parameters`, `btrfs_parse_param()`, and `btrfs_parse_compress()`. Mount/open flow uses `btrfs_init_fs_context()`, `btrfs_get_tree_subvol()`, `btrfs_get_tree_super()`, `btrfs_fill_super()`, `mount_subvol()`, and `btrfs_kill_super()`. Reconfiguration uses `btrfs_check_options()`, `btrfs_reconfigure()`, `btrfs_remount_rw()`, `btrfs_remount_ro()`, and option copy helpers. Runtime super operations include `btrfs_sync_fs()`, `btrfs_show_options()`, `btrfs_statfs()`, `btrfs_freeze()`, `btrfs_unfreeze()`, `btrfs_remove_bdev()`, and `btrfs_shutdown()`.

Control flow: `btrfs_init_fs_context()` allocates the private context, initializes defaults, and installs fs-context operations. Parameter parsing mutates the context, handling option interactions such as compression disabling nodatacow/nodatasum, nodatacow disabling compression and datasum, rescue aliases, discard modes, free-space-cache versions, ACL flags, device scans, and debug options. `btrfs_get_tree_subvol()` creates a temporary duplicated fs context with a newly initialized `btrfs_fs_info`, gets or creates the real superblock via `sget_fc()`, opens devices and calls `open_ctree()` on first mount, reconfigures a reused read-only superblock if a writable subvolume mount requires it, then mounts the requested subvolume path or object id.

Remount/reconfigure flow: `btrfs_reconfigure()` snapshots old options, synchronizes the filesystem, marks remounting, validates read-only-only rescue options and feature compatibility, applies parsed context into `fs_info`, resizes worker pools, limits free-space-tree toggling to RO-to-RW, transitions RW/RO as needed, updates POSIX ACL flags, emits changed options, wakes the transaction thread, cleans up discard/defrag/free-space-cache side effects, clears one-shot options, and restores old state on failure. `btrfs_remount_ro()` drains reclaim workers, discard, uuid rescan, cleaner, delayed iputs, device replace, scrub, balance, qgroup rescan, and commits the superblock. `btrfs_remount_rw()` rejects error states, missing writable devices, non-degradable profiles, and pending log replay before opening RW state.

State and persistence behavior: The file bridges ephemeral mount context into persistent filesystem state. `open_ctree()` populates on-disk-derived settings; `btrfs_set_free_space_cache_settings()` translates superblock features and user options into active free-space-cache mode, forcing free-space-tree for subpage sector/page mismatches and clearing v1 cache generation on zoned filesystems. `btrfs_sync_fs()` flushes btree mappings for non-wait sync and commits transactions for wait sync. Freeze commits the current transaction and sets `BTRFS_FS_FROZEN`; unfreeze rereads primary device superblocks, validates checksum/fsid/generation, and forces filesystem error state if devices changed while frozen.

Dependencies and integration points: This file integrates with nearly every Btrfs subsystem: disk-io/open-close, transactions, delayed inodes, direct I/O, compression, dev replace, free-space cache/tree, qgroups, scrub, discard, zoned support, raid56, export operations, xattrs, verity, ioctl feature reporting, sysfs, shrinkers, workqueues, and tracepoints. It also depends heavily on VFS fs_context, superblock, mount, dentry, freeze, statfs, miscdevice, and block-device APIs.

Risks: Mount option interactions are user-visible ABI and can regress compatibility, especially deprecated `norecovery/usebackuproot`, empty `subvol=`, and per-subvolume ro/rw behavior under the new mount API. The duplicated fs-context handoff carefully transfers `source`, `fs_info`, and `fs_devices` ownership; mistakes can leak or double-free devices. Reconfigure paths must clear `BTRFS_FS_STATE_REMOUNTING` on every failure, preserve old options, and avoid writes before RW safety checks. Statfs is approximate for mixed RAID and must avoid over-reporting when metadata/global reserve is exhausted. Freeze/unfreeze must detect external modification without preventing VFS thaw.

Test signals: Cover mount option matrix parsing, compression levels and force behavior, nodatacow/nodatasum interactions, device option scanning, rescue options requiring read-only, free-space-cache v1/v2 transitions, zoned mount options, default subvolume lookup, subvol path/id mismatch races, repeated subvolume mounts with different ro/rw mount flags, remount RO and RW failure paths, ACL remount toggling, discard async toggles, statfs on RAID/mixed/metadata-full filesystems, freeze/hibernate-style external modification detection, `/dev/btrfs-control` ioctls, missing-device removal degradability, shrinker callbacks, and module init unwind after partial failure.
