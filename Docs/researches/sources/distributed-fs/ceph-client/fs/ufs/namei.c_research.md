# sources/distributed-fs/ceph-client/fs/ufs/namei.c

`namei.c` implements UFS VFS namespace operations: lookup, create, mknod, symlink, hard link, mkdir, unlink, rmdir, and rename. It is the bridge between VFS dentries/inodes and lower UFS directory primitives, inode allocation, and file/inode operation setup.

Important APIs are `ufs_dir_inode_operations`, `ufs_lookup()`, `ufs_create()`, `ufs_mknod()`, `ufs_symlink()`, `ufs_link()`, `ufs_mkdir()`, `ufs_unlink()`, `ufs_rmdir()`, and `ufs_rename()`. Create-like paths allocate with `ufs_new_inode()`, initialize operation vectors or special-device/fast-symlink state, mark the inode dirty, then insert a directory entry through `ufs_add_link()`. `ufs_add_nondir()` centralizes rollback by decrementing the link count and discarding a failed new inode. Rename finds the old entry, optionally finds `..`, replaces or adds the destination entry, updates ctime/link counts, deletes the old entry, and fixes parent links for moved directories.

Persistent state changes include directory records, link counts, inode ctime/size, device encodings, fast symlink bytes in `UFS_I(inode)->i_u1.i_symlink`, and dirty inode metadata. Dependencies include `ufs_find_entry()`, `ufs_delete_entry()`, `ufs_set_link()`, `ufs_empty_dir()`, `ufs_dotdot()`, `ufs_iget()`, `ufs_aops`, and VFS dentry/link-count helpers. Risks are directory rename corner cases, rollback correctness, and symlink length selection. Tests should cover create/link/unlink/rmdir/rename, cross-directory directory rename, long names, fast/slow symlinks, special files, and injected directory insertion/deletion failures.
