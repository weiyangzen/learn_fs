# sources/distributed-fs/ceph-client/fs/eventfd.c

Purpose: Implements the Linux `eventfd` counter file descriptor, including syscall creation, read/write semantics, poll readiness, kernel-side signaling APIs, waitqueue integration, fdinfo reporting, and context reference management.

Important APIs, types, and functions: `struct eventfd_ctx` contains a kref, wait queue, 64-bit counter, flags, and an IDA-assigned id. `eventfd_signal_mask()` is the exported non-sleeping kernel producer API. `eventfd_ctx_do_read()` consumes either one token in semaphore mode or the full count. `eventfd_ctx_remove_wait_queue()` atomically removes a wait entry and drains the counter for in-kernel users. `eventfd_read()`, `eventfd_write()`, and `eventfd_poll()` implement file operations. `eventfd_fget()`, `eventfd_ctx_fdget()`, and `eventfd_ctx_fileget()` validate and pin eventfd objects for other kernel subsystems. `do_eventfd()` backs `eventfd2()` and legacy `eventfd()`.

Control flow: Creation validates flags, allocates and initializes the context, creates an anonymous inode file with `eventfd_fops`, assigns an ID, and publishes the fd. Writes copy one `u64` from userspace, reject `ULLONG_MAX`, wait unless nonblocking when the counter lacks space, add to `count`, and wake readers with `EPOLLIN`. Reads wait unless nonblocking when `count` is zero, drain according to semaphore mode, wake writers with `EPOLLOUT`, then copy the result to userspace. Poll registers with the waitqueue and reports readable, writable, and overflow/error states based on a lock-ordered counter read. Release wakes waiters with `EPOLLHUP` and drops the context kref.

State and persistence behavior: The only durable per-fd state is the in-memory counter and flags; it persists while the anonymous file or exported context references exist. All counter mutations happen under `ctx->wqh.lock`. The IDA id is used for fdinfo diagnostics and is freed when the final kref drops. `current->in_eventfd` guards against recursive waitqueue wakeups during eventfd signaling and read/write wakeups.

Dependencies and integration points: Exports GPL APIs used by kernel producers such as AIO, io_uring, KVM, and other notification paths. Integrates with anon inodes, fd allocation helpers, poll/epoll waitqueues, proc fdinfo, user-copy helpers, krefs, and IDA allocation.

Risks: Wakeup recursion can deadlock or overflow stacks if callers signal eventfds from nested wake paths without checking `eventfd_signal_allowed()`. Counter saturation has special semantics: kernel signaling may leave the counter at `ULLONG_MAX` and poll reports `EPOLLERR`, while userspace writes reject `ULLONG_MAX` and block before overflow. Poll relies on waitqueue locking barriers to avoid missed wakeups. Copy-to-user failures after draining the counter are observable and must match ABI expectations.

Test signals: Cover `eventfd` and `eventfd2` flag validation, semaphore versus normal reads, blocking and nonblocking reads/writes, write rejection of `ULLONG_MAX`, near-overflow behavior and `EPOLLERR`, poll readiness transitions, epoll integration, fdinfo count/id/semaphore output, exported fdget/fileget error paths, release `EPOLLHUP`, signal interruption, NOWAIT reads, and recursive signal warning behavior.
