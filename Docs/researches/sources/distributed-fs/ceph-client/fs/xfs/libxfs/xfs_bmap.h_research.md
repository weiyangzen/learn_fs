# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap.h

Purpose: Declares the public interface, flags, special values, allocation argument structure, and deferred-intent types for XFS block mapping operations implemented mostly by `xfs_bmap.c`. It is the contract used by inode, iomap, reflink, attribute, truncate, repair, and transaction code to request file-block mapping changes.

Important APIs, types, and functions: Defines `struct xfs_bmalloca` for allocation state, `XFS_BMAP_MAX_NMAP`, `XFS_BMAPI_*` request flags, `DELAYSTARTBLOCK`, `HOLESTARTBLOCK`, `BMAP_*` internal extent-manipulation state bits, `enum xfs_bmap_intent_type`, and `struct xfs_bmap_intent`. Inline helpers include `xfs_bmapi_aflag()`, `xfs_bmapi_whichfork()`, `xfs_bmap_is_real_extent()`, `xfs_bmap_is_written_extent()`, `xfs_valid_startblock()`, and `xfs_bmap_fork_to_state()`. Declared operations cover attribute fork creation, local fork conversion, maxlevel calculation, extent search, read/write mapping, unmapping, delayed/CoW extent deletion, extent shifting and splitting, delalloc conversion, remapping, deferred map/unmap completion, extent validation, btree range query callbacks, and extent-size hint extraction.

Control flow: Callers choose a target fork with `XFS_BMAPI_ATTRFORK` or `XFS_BMAPI_COWFORK`, derive the fork with `xfs_bmapi_whichfork()`, and pass flags to `xfs_bmapi_read()`, `xfs_bmapi_write()`, `xfs_bmapi_remap()`, or `xfs_bunmapi()`. The implementation uses `struct xfs_bmalloca` across allocation, btree cursor, neighbor extent, accounting, and logging stages. Deferred users enqueue `struct xfs_bmap_intent` through `xfs_bmap_map_extent()` or `xfs_bmap_unmap_extent()` and later finish the operation with `xfs_bmap_finish_one()`.

State and persistence: The header itself owns no runtime or persistent state except the exported `xfs_bmap_intent_cache` declaration. Its constants encode state conventions that are persisted indirectly in transactions: special startblock sentinels distinguish holes and delayed allocations, `XFS_BMAPI_REMAP` suppresses normal quota/free/refcount behavior for block ownership transfers, and fork state bits select data, attr, or CoW extent-cache handling.

Dependencies and integration points: Depends on XFS core types such as `xfs_inode`, `xfs_trans`, `xfs_ifork`, `xfs_btree_cur`, and `xfs_bmbt_irec`. The API is consumed throughout XFS by iomap writeback and reads, quota-aware allocation, xattr and directory conversion, truncation and punch-hole paths, reflink remap and CoW completion, deferred operation logging, scrub/repair btree queries, and mount initialization.

Risks and test signals: Risk concentrates in flag combinations and sentinel interpretation. Invalid combinations such as zeroing metadata, remapping with allocation conversion, using CoW fork in btree-only paths, or treating delayed/null startblocks as real can corrupt accounting or metadata. Test public entry points with each fork selector, all meaningful `XFS_BMAPI_*` combinations, sentinel startblocks, deferred bmap intent replay, and extent validation for data, attr, CoW, and realtime files.
