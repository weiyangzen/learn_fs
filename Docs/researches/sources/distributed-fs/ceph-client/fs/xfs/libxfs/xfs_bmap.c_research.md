# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap.c

Purpose: Implements the core XFS block mapping engine for inode forks. It translates file offsets to filesystem blocks, allocates and frees mapped extents, converts delayed allocations and unwritten extents, manages transitions between local, extent-list, and bmap-btree fork formats, maintains reverse mappings and quota/block accounting, and provides deferred map/unmap intent processing used by reflink and metadata repair style operations.

Important APIs, types, and functions: The file centers on `struct xfs_bmalloca`, `struct xfs_bmap_intent`, bmbt cursor helpers, and the `xfs_bmbt_irec` extent record shape. Public entry points include `xfs_bmap_compute_maxlevels()`, `xfs_bmap_compute_attr_offset()`, `xfs_bmap_add_attrfork()`, `xfs_bmap_local_to_extents_empty()`, `xfs_bmap_local_to_extents()`, `xfs_iread_extents()`, `xfs_bmap_first_unused()`, `xfs_bmap_last_before()`, `xfs_bmap_last_offset()`, `xfs_bmapi_read()`, `xfs_bmapi_write()`, `xfs_bmapi_convert_delalloc()`, `xfs_bmapi_remap()`, `xfs_bunmapi()`, `xfs_bunmapi_range()`, `xfs_bmap_collapse_extents()`, `xfs_bmap_can_insert_extents()`, `xfs_bmap_insert_extents()`, `xfs_bmap_split_extent()`, `xfs_bmap_map_extent()`, `xfs_bmap_unmap_extent()`, `xfs_bmap_finish_one()`, `xfs_bmap_validate_extent_raw()`, `xfs_bmap_validate_extent()`, `xfs_bmap_query_all()`, `xfs_get_extsz_hint()`, and `xfs_get_cowextsz_hint()`. Key internal routines are `xfs_bmap_extents_to_btree()`, `xfs_bmap_btree_to_extents()`, `xfs_bmap_add_extent_delay_real()`, `xfs_bmap_add_extent_unwritten_real()`, `xfs_bmap_add_extent_hole_real()`, `xfs_bmap_btalloc()`, `xfs_bmap_del_extent_delay()`, `xfs_bmap_del_extent_real()`, and `__xfs_bunmapi()`.

Control flow: Mount setup calls `xfs_bmap_compute_maxlevels()` to size future bmap btrees from extent-count limits and btree fanout. Lookup-only callers use `xfs_bmapi_read()`, which validates the fork, loads btree extents into the in-core extent tree with `xfs_iread_extents()`, scans `xfs_iext` records, synthesizes holes, trims records to the requested range unless `XFS_BMAPI_ENTIRE` is set, and coalesces adjacent returned mappings. Write callers use `xfs_bmapi_write()`, which scans from the requested logical offset, detects holes or delayed allocations, calls `xfs_bmapi_allocate()` for real block allocation, optionally converts unwritten extent state, updates the return map, and finally shrinks btree forks back to extent format when possible. Allocation chooses data versus realtime allocators, applies extent-size and CoW-size hints, tries locality and EOF/stripe alignment, falls back to low-space algorithms, then inserts or merges the new extent through one of the add-extent helpers.

State and persistence: Persistent fork state is the dinode fork format and its extent records or bmap btree root; real btree blocks and freed extents are logged through transactions and deferred free items. In-memory state is the inode fork extent cache (`xfs_iext`), the optional bmbt cursor, delayed allocation counters, inode block counts, transaction block reservations, and quota reservations. Delayed allocation is represented by null startblocks carrying reserved indirect-block counts; real mappings use physical startblocks; holes use `HOLESTARTBLOCK`; caller-visible delayed mappings are normalized to `DELAYSTARTBLOCK`. Functions update `if_nextents`, `i_nblocks`, `i_delayed_blks`, dquot counters, free-block counters, rmap/refcount records, and inode log flags together so the logged dinode and metadata btrees remain synchronized.

Dependencies and integration points: This file integrates with XFS transaction logging, inode locking, the generic XFS btree engine, bmap btree format helpers from `xfs_bmap_btree.c`, allocation groups and realtime groups, filestream allocator policy, reverse mapping (`xfs_rmap_*`), refcount/reflink CoW tracking, quota accounting, deferred operation infrastructure, buffer verification, health marking, iomap conversion, directory/symlink local-to-remote conversion, superblock feature bits, error tags, and tracepoints. It is reached from buffered and direct write paths through iomap, truncation and hole punching through `bunmapi`, fallocate/collapse/insert operations through extent shifting, attribute creation through attr-fork addition, and repair/remap flows through deferred bmap intents.

Risks and test signals: Highest risks are extent tree and btree divergence, wrong `if_nextents` changes after merge/split cases, stale or missing rmap/refcount updates, quota and delayed-indirect reservation leaks, realtime extent alignment mistakes, partial transaction error paths that fail to log dirty inode state, and corruption handling that leaves a cursor positioned on invalid metadata. Test signals should include mapping holes, real extents, unwritten extents, delayed extents, and CoW fork extents; ENOSPC and low-space allocation with btree splits; local-to-extent and extent-to-btree/btree-to-extent format transitions; attr fork addition to local, extent, and btree data forks; realtime files with partial unmaps; reflink remap/unmap without quota or refcount double accounting; collapse/insert range shifting across mergeable and non-mergeable extents; large extent-count inodes; shutdown and error-tag injection; fsync after unwritten conversion; and scrub/repair validation of returned bmap records.
