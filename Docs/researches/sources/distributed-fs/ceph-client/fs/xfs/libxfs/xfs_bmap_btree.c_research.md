# sources/distributed-fs/ceph-client/fs/xfs/libxfs/xfs_bmap_btree.c

Purpose: Implements the XFS block mapping btree (`bmbt`) format and its binding to the generic XFS btree engine. It packs and unpacks extent records, converts inode-root formats, allocates and frees bmbt blocks, verifies bmbt buffers, manages in-core root resizing, initializes btree cursors, commits staged btrees, changes btree owners, computes geometry, and manages the cursor slab cache.

Important APIs, types, and functions: Exports `xfs_bmbt_init_block()`, `xfs_bmdr_to_bmbt()`, `xfs_bmbt_disk_get_all()`, `xfs_bmbt_disk_get_blockcount()`, `xfs_bmbt_disk_get_startoff()`, `xfs_bmbt_disk_set_all()`, `xfs_bmbt_to_bmdr()`, `xfs_bmbt_get_maxrecs()`, `xfs_bmap_broot_realloc()`, `xfs_bmbt_init_cursor()`, `xfs_bmbt_commit_staged_btree()`, `xfs_bmbt_maxrecs()`, `xfs_bmbt_maxlevels_ondisk()`, `xfs_bmdr_maxrecs()`, `xfs_bmbt_change_owner()`, `xfs_bmbt_calc_size()`, `xfs_bmbt_init_cur_cache()`, and `xfs_bmbt_destroy_cur_cache()`. It defines `xfs_bmbt_ops` for the generic btree layer and `xfs_bmbt_buf_ops` for metadata buffer verification.

Control flow: Record conversion routines translate between the compact two-word disk `xfs_bmbt_rec` and unpacked `xfs_bmbt_irec` fields for start offset, start block, block count, and unwritten state. Root conversion routines copy keys and pointers between the on-disk dinode root (`xfs_bmdr_block`) and the in-memory long-format btree root (`xfs_btree_block`). Generic btree operations call the local callbacks to duplicate/update cursors, allocate new one-block bmbt nodes near a start pointer, free bmbt nodes later through deferred frees, compute min/max records, initialize keys from records, compare keys, test ordering, and resize inode roots. Cursor initialization sizes the cursor by fork or staging fork and records inode/fork context; staged commit destroys the old fork, installs the fake fork, logs the correct root or extent fields, and asks the staging layer to commit root metadata.

State and persistence: Persistent state includes bmbt blocks on disk, the dinode btree root, record bit layout, block owners, sibling pointers, CRC-enabled metadata UUIDs, and btree block frees scheduled by transactions. In-memory state includes cursor allocation from `xfs_bmbt_cur_cache`, cursor allocation counts used by bmap accounting, root buffer sizing (`if_broot_bytes`), and staging fake-root state. Allocating a bmbt block increments inode `i_nblocks` and dquot block counts; freeing decrements both and schedules block release, preserving transaction ordering.

Dependencies and integration points: Builds on the generic XFS btree engine (`xfs_btree_ops`, staging cursors, record/key callbacks), allocation and free-extent code, inode fork utilities, transactions, quota accounting, reverse-map owner information, buffer verifiers, CRC helpers, tracepoints, and mount geometry calculated in `xfs_bmap.c`. It is used directly by `xfs_bmap.c` when loading btree-format forks, inserting or deleting extent records, converting fork formats, and rebuilding/committing staged block maps.

Risks and test signals: Key risks are bitfield packing overflows, wrong root pointer offsets when root size changes, incorrect max-record calculations for CRC versus non-CRC formats, owner verification gaps, lost quota/accounting updates for bmbt block allocation or free, low-space btree split behavior, and staged commit losing old fork resources. Test bmbt record pack/unpack boundaries, CRC and non-CRC filesystems, tiny inode fork roots, btree growth and shrink, allocation with `t_highest_agno` and low-space mode, owner changes for fork swaps and recovery, staged rebuild commit, verifier rejection of bad magic/level/numrecs/CRC, and mount-time `xfs_bmbt_maxlevels_ondisk()` sizing.
