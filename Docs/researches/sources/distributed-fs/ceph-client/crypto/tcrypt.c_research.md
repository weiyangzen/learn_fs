# sources/distributed-fs/ceph-client/crypto/tcrypt.c

`tcrypt.c` is a late-init benchmarking and smoke-test module for Crypto API algorithms. It allocates scratch pages, runs selected correctness tests through `alg_test()`, and benchmarks AEAD, ahash/shash, skcipher, async skcipher, and multibuffer request patterns.

Module parameters are `alg`, `type`, `mask`, `mode`, `sec`, `num_mb`, and `klen`. Core helpers include `testmgr_alloc_buf()`, `sg_init_aead()`, `do_one_aead_op()`, `do_mult_aead_op()`, `test_aead_speed()`, `test_mb_aead_speed()`, `test_hash_sg_init()`, `test_ahash_speed_common()`, `test_skcipher_speed()`, `test_mb_skcipher_speed()`, `tcrypt_test()`, `do_test()`, and `tcrypt_mod_init()`.

Init allocates `TVMEMSIZE` pages, clamps `num_mb`, then dispatches by mode. Correctness modes call `alg_test()` via `tcrypt_test()` with FIPS skip handling. Speed modes allocate transforms and requests, set keys/auth sizes/IVs, build scatterlists, optionally pre-encrypt AEAD decrypt buffers to make valid tags, and measure with either jiffies for `sec` seconds or fixed `get_cycles()` loops. Non-FIPS init intentionally returns `-EAGAIN` after work so the module does not stay resident. State is global parameters and scratch pages plus per-test transforms/requests/waits/buffers. Risks include cleanup across many goto paths, invalid setup for unusual algorithms, benchmark bias from fixed data, request reuse in multibuffer paths, and mode table drift. Test signals are expected logs, expected non-FIPS `-EAGAIN`, leak/fault-injection cleanliness, and targeted modes for SM3, SM4, Streebog, TEA, hash speed, skcipher speed, and AEAD multibuffer tests.
