# sources/distributed-fs/ceph-client/include/linux/jbd2.h

## Purpose
Declares the JBD2 journaling core contract used by ext4 and other filesystem clients. It covers on-disk journal structures, transaction and handle state, journal runtime state, revoke/checkpoint machinery, fast commits, feature bits, checksums, and public transaction APIs.

## Important APIs, Types, And Functions
The major public types are `handle_t`, `journal_t`, `journal_header_t`, `commit_header`, `journal_block_tag_t`, `journal_block_tag3_t`, `journal_superblock_t`, `struct jbd2_inode`, `struct jbd2_journal_handle`, `transaction_t`, and `struct journal_s`. Feature helpers are generated by `JBD2_FEATURE_*_FUNCS()` for checksum, revoke, 64-bit, async commit, checksum v2/v3, and fast commit. Public entry points include `jbd2_journal_start()`, restart/extend/stop helpers, write/create/undo access helpers, dirty/forget/invalidate/free-buffer helpers, journal init/load/recover/wipe/destroy, abort/error handling, force commit, inode ordered-data helpers, revoke helpers, commit wait helpers, checkpoint helpers, and fast commit helpers.

## Control Flow
Filesystem operations start a handle with reserved metadata and revoke credits, attach buffers to the running transaction, mark metadata dirty, and stop or restart the handle. Transactions progress through `T_RUNNING`, `T_LOCKED`, `T_SWITCH`, `T_FLUSH`, commit sub-states, callback, and `T_FINISHED`; older finished transactions are checkpointed before log tail advancement. Recovery scans descriptor, revoke, and commit records using transaction IDs with wrap-aware `tid_gt()` and `tid_geq()`.

## State And Persistence
Persistent state is the big-endian journal superblock, descriptor tags, commit blocks, revoke blocks, checksums, sequence numbers, and optional fast commit blocks. Runtime state lives in `journal_s`, transaction lists, journal heads, revoke tables, wait queues, timers, per-transaction statistics, and callback hooks. `jbd2_inode` tracks ordered data ranges by page offsets and publishes non-empty ranges by storing the end page before the start page.

## Dependencies And Integration Points
Depends on buffer heads, `journal-head.h`, block devices, timers, mutexes, spinlocks, bit spinlocks, CRC32C, folios, shrinkers, procfs, lockdep, and VFS inode/address-space infrastructure. Filesystems integrate through journal handles, inode callbacks for ordered data, `j_bmap`, fast commit replay/cleanup callbacks, and fs-private `j_private`.

## Risks
Lock ordering is strict: `j_list_lock`, `j_state_lock`, buffer state locks, and journal-head bit locks must be taken in documented order. Credit underestimation can deadlock log space or corrupt transactions. On-disk feature and checksum mismatches can make recovery unsafe. The header intentionally allows continued operation after some IO failures unless paranoid checking is enabled.

## Test Signals
Signals include ext4 journal replay tests, forced abort/error propagation, checksum v1/v2/v3 compatibility, 64-bit journal tag coverage, transaction ID wrap tests, revoke replay tests, ordered-data writeback tests, checkpoint shrinker behavior, fast commit fallback/replay, lockdep under stress, and fault injection for metadata IO.
