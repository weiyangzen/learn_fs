# sources/distributed-fs/ceph-client/include/linux/mfd/wm8400-private.h

Purpose: this private header defines the WM8400 core state structure, register count, register addresses, and non-audio/PMIC-side field map used by the MFD core, regulator driver, and codec support. It is private to in-kernel WM8400 drivers rather than a board-facing API.

Important APIs, types, and constants: `WM8400_REGISTER_COUNT` defines the regmap maximum register span. `struct wm8400` contains the parent `device`, shared `regmap`, and an array of six regulator `platform_device` objects. Register-address macros cover identity, audio, GPIO, LDO/DCDC regulator, interface, power-management, interrupt, shutdown, and line-comparator registers. Field macros cover chip revision, GPIO/GPI debounce/IRQ/pull/function/status fields, regulator enable/voltage/ramp/current-limit fields, interface and PM bits, interrupt status/mask/levels, shutdown reasons, and line-comparator thresholds.

Control flow: the MFD core uses `WM8400_RESET_ID`, `WM8400_ID`, `WM8400_CHIP_REV_MASK`, `WM8400_REGISTER_COUNT`, and volatile interrupt/shutdown register constants during probe and regmap setup. The regulator driver uses `struct wm8400.regulators[]`, regulator IDs from `wm8400.h`, LDO/DCDC register constants, and voltage/ramp masks to create software-controlled regulator platform devices and operate them through regmap. The codec driver combines register addresses from this header with audio field macros from `wm8400-audio.h`.

State and persistence: persistent driver state is the devres-managed `struct wm8400` allocated by the I2C MFD probe. The `regmap` caches 8-bit register, 16-bit value hardware state; interrupt status, interrupt levels, and shutdown reason are volatile. The regulator platform-device array persists inside `struct wm8400` so `wm8400_register_regulator()` can register each regulator at most once and keep platform-device storage alive for the platform bus.

Dependencies and integration points: includes `wm8400.h`, mutex/platform-device/regmap headers, and connects the MFD core, regulator driver, ASoC codec driver, I2C probe path, MFD child registration, and Linux regulator framework. It is also tied to `wm8400-core.c` cache configuration and the public `wm8400_register_regulator()` API.

Risks: this header is the single source of truth for many numeric hardware fields; off-by-one register count or address errors can make regmap reject valid registers or permit invalid ones. Private state includes platform-device objects directly, so duplicate regulator registration is guarded by checking `.name` but still relies on caller discipline. Volatile-register classification is implemented in the core, not encoded here, so adding new status registers requires core updates. The header mixes audio, regulator, GPIO, interrupt, and shutdown definitions, increasing the chance that unrelated changes have cross-driver effects.

Test signals: build `CONFIG_MFD_WM8400`, `CONFIG_REGULATOR_WM8400`, and the WM8400 codec. Probe should reject non-`0x6172` reset IDs, log revision from `WM8400_ID`, register the codec child, and allow board `platform_init()` to register regulator children. Regulator tests should verify LDO/DCDC voltage selection, enable/disable, suspend-mode programming, duplicate registration rejection, and correct regmap accesses to `LDO*_CONTROL` and `DCDC*_CONTROL_*`. Cache tests should confirm volatile interrupt/shutdown registers are not treated as stable cached state.
