# sources/distributed-fs/ceph-client/include/linux/mfd/wm8994/pdata.h

Purpose: this header defines board/platform configuration for WM8994-family MFD and codec drivers. It covers GPIO defaults, LDO regulator constraints, IRQ bases/flags, codec tuning tables, microphone/jack detection timing and thresholds, line-output topology, pull policies, microphone-bias setup, and audio-interface clocking limits.

Important APIs, types, and constants: sizing constants include `WM8994_NUM_LDO`, `WM8994_NUM_GPIO`, `WM8994_NUM_AIF`, DRC/EQ/MBC/VSS/enhanced-EQ register counts, and `WM8994_CONFIGURE_GPIO`. Data types include `wm8994_ldo_pdata`, `wm8994_drc_cfg`, `wm8994_retune_mobile_cfg`, `wm8958_mbc_cfg`, `wm8958_vss_hpf_cfg`, `wm8958_vss_cfg`, `wm8958_enh_eq_cfg`, `wm8958_micd_rate`, and the aggregate `wm8994_pdata`. The aggregate includes GPIO and IRQ bases, GPIO default register values, LDO init data, DSP tuning table arrays and counts, mic-detect rates, mic-bias delays, lineout differential/feedback flags, mic/jack detect delays and IRQ, mic-bias levels/configuration, jack thresholds, external-capacitor mode, LDO enable drive policy, pull policy for SPKMODE and CS/ADDR, max clocked channels per AIF, and optional IRQ GPIO.

Control flow: the MFD core copies platform data into `struct wm8994`, overlays selected OF properties, registers LDO children, uses `irq_base`/`gpio_base`, writes non-zero GPIO defaults, records `ldo_ena_always_driven`, applies pull policy, and passes the data to child drivers. The LDO regulator driver reads `pdata->ldo[id].init_data` unless defaults/OF are used. The codec driver builds ALSA enumerated controls from DRC/ReTune tables, writes selected tuning register arrays at runtime, applies lineout topology and mic-bias delays through WM hubs helpers, clamps AIF clocking to `max_channels_clocked[]`, and uses mic/jack detect timing, rates, thresholds, external-capacitor, and optional micdet IRQ settings in accessory detection.

State and persistence: platform data is copied into `struct wm8994.pdata`, so scalar values persist for device lifetime. Pointer members still refer to caller-owned tuning arrays, names, and rate tables; those must remain valid. Runtime selections such as active DRC or ReTune configuration are held in codec-private state, while the static arrays here define valid choices. Regulator init data is consumed by regulator registration and affects persistent regulator constraints.

Dependencies and integration points: depends on regulator machine constraints and fixed-width `u16` register arrays from kernel types. It integrates with MFD core, regulator framework, gpiolib, regmap IRQ, ASoC codec controls, WM hubs analogue handling, accessory detection, DT property parsing for selected fields, and board files using legacy platform data.

Risks: count/pointer mismatches for DRC/EQ/MBC/VSS/enhanced-EQ/micd arrays can cause invalid reads in the codec driver. Register arrays are written directly to hardware, so bad WISCE-generated or hand-authored values can break audio processing. Pointer lifetime is not owned by the core copy. `WM8994_CONFIGURE_GPIO` is a sentinel outside the 16-bit GPIO register field and must be interpreted correctly by consumers. Delay and threshold values are board-specific and can cause jack/mic detection flakiness or power regressions. LDO policy flags affect leakage and suspend behavior; setting `ldo_ena_always_driven` incorrectly can leave pins floating or waste power. Several fields are legacy platform-data only while OF parsing covers only a subset, so DT and non-DT systems can diverge.

Test signals: verify platform-data and DT probe paths produce expected `wm8994->pdata` values; LDO children use supplied or default constraints; GPIO defaults are written; IRQ base and optional edge `irq_gpio` paths deliver interrupts; codec enumerates DRC/ReTune controls with the configured names; selecting each tuning profile writes the expected number of registers; mic/jack detection honors delays/rates/external-cap mode; lineout single-ended/differential and feedback flags alter analogue routing; and `max_channels_clocked[]` clamps AIF channel clocks with a visible diagnostic.
