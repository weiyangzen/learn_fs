# Research: sources/distributed-fs/ceph-client/include/net/llc_pdu.h

Purpose: `llc_pdu.h` defines LLC PDU wire-format constants, packed header structures, decode helpers, and builders for Type 1 UI/XID/TEST PDUs plus declarations for Type 2 I/S/U command and response constructors.

Important APIs/types/functions: the header defines PDU lengths, well-known SAP values, DSAP/SSAP bit masks, command/response masks, PDU type tests, U-format commands (`UI`, `XID`, `TEST`, `SABME`, `DISC`, `UA`, `DM`, `FRMR`), S-format commands (`RR`, `REJ`, `RNR`), sequence helpers, XID constants, and FRMR info macros. Wire structs are `struct llc_pdu_sn`, `struct llc_pdu_un`, `struct llc_xid_info`, and `struct llc_frmr_info`. Inline helpers include `llc_pdu_header_init()`, MAC/SAP decode helpers, UI/TEST/XID builders, and header accessors. Declared builders cover DISC, I, REJ, RNR, RR, SABME, DM, FRMR, and UA variants.

Control flow: transmit code reserves LLC header space with `skb_push()`, resets the network header, sets DSAP/SSAP command-response bits, then initializes the control field and optional information fields. Receive code reads `skb_network_header()` as U or sequence-numbered headers, classifies type using low control bits, decodes P/F and sequence numbers, and drives SAP or connection events.

State and persistence behavior: no persistent state is stored here. The functions mutate skb packet bytes and length. XID/FRMR data becomes wire-visible protocol state; sequence numbers are read from or written into control bytes.

Dependencies and integration points: it depends on Ethernet header access, skb network-header manipulation, byte-order helpers, LLC state machines, and PDU constructors implemented in LLC source files. It integrates with SAP Type 1 actions, connection Type 2 actions, and packet receive classification.

Risks: packed wire structures require exact byte layout. Several macros manipulate unaligned control fields, and `FRMR_INFO_SET_REJ_CNTRL()` reads rejected control bytes as `u8` or `u16`; unaligned/endian assumptions must be validated. `PDU_GET_NEXT_Vr()` and modulo sequence behavior are subtle. TEST response copies payload length from the Ethernet length field, so malformed lengths can stress skb bounds if not validated earlier.

Test signals: decode/build round-trip tests for UI/XID/TEST and Type 2 PDUs, P/F bit variants, DSAP/SSAP masking, XID information fields, FRMR rejected-control encoding, malformed short skb handling, sequence-number wrap, and packet captures comparing generated bytes to IEEE 802.2 expectations.
