# Research: sources/distributed-fs/ceph-client/include/net/lwtunnel.h

Purpose: `lwtunnel.h` defines the kernel lightweight tunnel state and encapsulation-operations interface used by routes and nexthops. It lets tunnel modules build per-route state, redirect dst input/output/xmit paths, serialize encap attributes to netlink, compare states, and provide config-dependent stubs when lightweight tunnels are disabled.

Important APIs/types/functions: `struct lwtunnel_state` stores tunnel type, redirect flags, needed headroom, refcount, original dst output/input callbacks, RCU node, and variable-length private data. `struct lwtunnel_encap_ops` provides callbacks for `build_state`, `destroy_state`, `output`, `input`, `fill_encap`, `get_encap_size`, `cmp_encap`, and `xmit`, plus module owner. Helpers include `lwtstate_get()`, `lwtstate_put()`, redirect tests, `lwtunnel_headroom()`, ops registration, encap validation/build/fill/compare, `lwtunnel_state_alloc()`, `lwtunnel_output()`, `lwtunnel_input()`, `lwtunnel_xmit()`, `bpf_lwt_push_ip_encap()`, `lwtunnel_set_redirect()`, and `MODULE_ALIAS_RTNL_LWT()`.

Control flow: tunnel modules register encap ops by type. Route/nexthop netlink parsing validates an encap type and asks the module to build an `lwtunnel_state`. When the state requests redirect, `lwtunnel_set_redirect()` saves the original dst callbacks and replaces them with lwtunnel wrappers. Packet output/input/xmit then dispatch through the registered ops, which may consume the skb or return `LWTUNNEL_XMIT_CONTINUE` to continue normal forwarding. Netlink dump paths ask ops for encap size and fill attributes.

State and persistence behavior: lwtunnel state is per-route/nexthop in-memory state refcounted with `atomic_t` and freed through RCU-aware `lwtstate_free()`. Original dst callbacks are saved in the state so redirect wrappers can chain or restore behavior. No disk persistence exists; route configuration persists only as long as networking configuration does.

Dependencies and integration points: it depends on UAPI lwtunnel definitions, netdevice/skbuff/types, route/dst entries, netlink attributes/extack, module ownership, static keys for netfilter hooks, and optional BPF LWT encapsulation support. It integrates with rtnetlink route creation, IPv4/IPv6 route output/input, nexthops, MPLS/IP tunnels, BPF LWT programs, and netfilter LWT hooks.

Risks: refcount and RCU lifetime bugs can leave route dst entries pointing at freed state. Redirect callback replacement must preserve original callbacks exactly and use `READ_ONCE`/`WRITE_ONCE` safely. Headroom calculation must avoid exceeding MTU assumptions. Config-disabled stubs return success for some dump/validation helpers but `-EOPNOTSUPP` for build/xmit, so callers must handle both. Encapsulation comparison must be exact enough to share routes safely without merging different tunnel states.

Test signals: validate route add/delete with each lwt encap type, netlink dump/compare round trips, refcounting under route replacement and namespace teardown, packet output/input/xmit through redirect wrappers, BPF LWT push encap, CONFIG_LWTUNNEL=n builds, module unload after ops unregister, and KASAN/RCU stall checks during concurrent route lookup and delete.
