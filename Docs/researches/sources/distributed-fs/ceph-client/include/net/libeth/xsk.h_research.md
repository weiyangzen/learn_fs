# Research: sources/distributed-fs/ceph-client/include/net/libeth/xsk.h

Purpose: `xsk.h` extends libeth XDP support for AF_XDP zero-copy sockets. It provides shared helpers for XSk `XDP_TX`, XSk user-space Tx descriptor submission, XSk Rx buffer processing, XDP program execution on zero-copy buffers, fill-queue refilling, wakeups, and pool setup.

Important APIs/types/functions: XSk Tx helpers include `libeth_xsk_tx_queue_head()`, `libeth_xsk_tx_queue_frag()`, `libeth_xsk_tx_queue_bulk()`, `libeth_xsk_tx_fill_buf()`, and `libeth_xsk_tx_flush_bulk()`. User-space Tx xmit helpers include `libeth_xsk_xmit_fill_buf()`, `libeth_xsk_xmit_do_bulk()`, and metadata support through `libeth_xsktmo_req_csum()` and `libeth_xsktmo`. Rx helpers include `libeth_xsk_tx_init_bulk()`, `libeth_xsk_process_buff()`, `libeth_xsk_run_prog()`, `libeth_xsk_run_pass()`, and `libeth_xsk_finalize_rx()`. `struct libeth_xskfq` and `libeth_xskfqe_alloc()` model/refill the XSk fill queue. Setup and wakeup entry points are `libeth_xskfq_create()`, `destroy()`, `libeth_xsk_init_wakeup()`, `libeth_xsk_wakeup()`, and `libeth_xsk_setup_pool()`.

Control flow: on XSk Rx, the driver allocates zero-copy buffers from an XSk pool, attaches received buffers as a head or frags, syncs DMA for CPU, runs the attached XDP program, and most often redirects the buffer back to AF_XDP. Non-redirect verdicts are handled by the slow path or by building an skb with `xdp_build_skb_from_zc()`. XSk `XDP_TX` mirrors the generic XDP bulk path but stores `libeth_xdp_buff` pointers for completion. User-space Tx uses `xsk_tx_peek_release_desc_batch()` to borrow descriptors from the pool, casts pool descriptors to `libeth_xdp_tx_frame`, fills hardware descriptors in an unrolled batch, finalizes the driver queue, and manages the need-wakeup bit around lazy cleaning.

State and persistence behavior: all state is transient queue and pool state: XSk pool descriptors, zero-copy buffer ownership, DMA addresses, need-wakeup flags, FQ `ntu`, pending refill counts, thresholds, NUMA node, and SQE completion state. It persists only for socket/queue lifetime, but incorrect ownership can leak UMEM frames or return buffers to the wrong pool.

Dependencies and integration points: the header depends on `net/libeth/xdp.h`, AF_XDP driver APIs in `xdp_sock_drv.h`, XDP Tx metadata ops, XSk need-wakeup semantics, and driver descriptor callbacks shared with generic XDP. It integrates with XSk pool attach/detach, NAPI poll loops, `.ndo_xsk_wakeup`, zero-copy skb building, and checksum-offload metadata.

Risks: metadata support assumes the caller passes compatible `xsk_tx_metadata_ops`; `libeth_xsktmo` uses a sentinel pointer and compile-time constant expectations. Multi-frag XSk frames need exact first/last SQE marking for completion accounting. `libeth_xsk_xmit_do_bulk()` assumes the queue is already locked and cleaned, and that the prep callback returns `U32_MAX`; violating that contract can race queue state. Need-wakeup transitions are subtle because lazy cleaning and interrupts are disabled for the queue.

Test signals: test AF_XDP zero-copy bind/unbind, Rx redirect, XSk `XDP_TX`, user-space Tx with and without metadata checksum requests, need-wakeup behavior, fill-queue wrap/refill thresholds, multi-buffer packets, skb fallback from XSk buffers, queue teardown with outstanding buffers, and DMA API/debug-page-owner signals for UMEM frame lifetime.
