# Research: sources/distributed-fs/ceph-client/include/net/libeth/xdp.h

Purpose: `xdp.h` is the generic libeth XDP framework header. It gives Ethernet drivers a shared fast path for XDP buffer representation, XDPSQ selection and locking, `XDP_TX`, `.ndo_xdp_xmit()`, Rx-side XDP program execution, redirect flushing, metadata helpers, queue cleanup timers, and Tx completion. The header is heavily inline/macro based so driver-specific descriptor filling can compile down to direct ring writes.

Important APIs/types/functions: key verdict bits are `LIBETH_XDP_PASS`, `DROP`, `ABORTED`, `TX`, and `REDIRECT`. `struct libeth_xdp_buff` extends `struct xdp_buff` with a descriptor pointer and driver-private scratch area while remaining layout-compatible with `xdp_buff_xsk`. Stack helpers include `LIBETH_XDP_ONSTACK_BUFF()` and `LIBETH_XDP_ONSTACK_BULK()`. XDPSQ helpers include `libeth_xdpsq_num()`, `libeth_xdpsq_id()`, queue share locking helpers, and timer helpers. `struct libeth_xdp_tx_frame`, `struct libeth_xdp_tx_bulk`, `struct libeth_xdpsq`, and `struct libeth_xdp_tx_desc` are the central Tx abstractions. `libeth_xdp_tx_xmit_bulk()` is the generic ring-fill engine. Rx helpers include `libeth_xdp_init_buff()`, `libeth_xdp_process_buff()`, `libeth_xdp_run_prog()`, `libeth_xdp_run_pass()`, and `libeth_xdp_finalize_rx()`. Driver boilerplate is generated by `LIBETH_XDP_DEFINE_*` macros. Completion is handled by `libeth_xdp_complete_tx()`, and netdev feature publication by `libeth_xdp_set_features()` / `_noredir()`.

Control flow: for Rx, a driver initializes an on-stack bulk under RCU, builds a `libeth_xdp_buff` from page-pool FQEs, optionally stores descriptor metadata, runs the attached BPF program, and either returns/recycles the buffer, queues it to an XDPSQ for `XDP_TX`, redirects it, or converts it to an skb for GRO. At poll end, `libeth_xdp_finalize_rx()` flushes any queued `XDP_TX`, kicks the driver queue, flushes redirect maps, and releases the RCU read lock. For `.ndo_xdp_xmit()`, frames are DMA mapped, queued into a bulk, flushed through the same generic `libeth_xdp_tx_xmit_bulk()` path, and finalized depending on `XDP_XMIT_FLUSH`. The ring-fill engine asks the driver to prepare/clean a queue, writes descriptors linearly or in unrolled batches, wraps `next_to_use`, updates pending counters, and unlocks the XDPSQ.

State and persistence behavior: state is in memory and hardware-visible rings only. The header manipulates `xdp_buff` data pointers, page-pool ownership, DMA mapping/sync state, Tx SQEs, `next_to_use`, pending counts, XDP Tx counters, queue-share spinlocks, delayed cleanup work, and per-poll action masks. It deliberately nulls consumed buffer pointers to avoid double returns. No durable storage is touched, but mistakes affect packet ownership, DMA correctness, and device queue progress.

Dependencies and integration points: it depends on BPF/XDP core APIs, `xsk_buff_pool`, page pool/netmem helpers, libeth Rx/Tx queue types, `sk_buff` fragment metadata, DMA mapping, static keys, workqueues, NAPI/GRO, XDP metadata ops, and tracepoints such as `trace_xdp_bulk_tx`. Drivers integrate by supplying queue prep, descriptor xmit, completion polling, skb population, and finalization callbacks.

Risks: the highest-risk areas are layout compatibility with `xdp_buff_xsk`, flexible private-data sizing, correct DMA sync/unmap pairing, queue wrap handling, RCU lifetime for BPF programs, distinguishing head and fragment SQE types, and cleanup when only part of a multi-frag frame is queued. Queue sharing depends on a static key and per-queue `share` flag; missing locks can corrupt shared XDPSQs while unnecessary locks hurt hot-path performance. The `__LIBETH_WORD_ACCESS` packing path is endian-sensitive and must match descriptor consumers.

Test signals: useful signals include XDP_PASS/DROP/TX/REDIRECT functional tests, multi-frag XDP frames, `.ndo_xdp_xmit()` with and without `XDP_XMIT_FLUSH`, ring wrap and low-free-descriptor cases, page-pool recycling under NAPI and non-NAPI returns, DMA API debugging, KASAN/KCSAN/lockdep, redirect-map flush coverage, XDP metadata hash tests, and driver descriptor inspection for first/last/multi/checksum flags.
