# sources/distributed-fs/ceph-client/include/dt-bindings/clock/qcom,ipq5332-gcc.h

Purpose: Defines the Devicetree binding ID ABI for the Qualcomm `ipq5332-gcc` clock controller provider. Device trees use these macros in `clocks`, `resets`, CSR, and power-domain-style properties where the matching binding exposes those cells, so board descriptions and the Qualcomm controller driver agree on stable integer indexes.

Important APIs, types, and functions: This header exports preprocessor constants only; it declares no C types, functions, or storage. Include guard `_DT_BINDINGS_CLK_QCOM_GCC_IPQ5332_H` protects the namespace. Parsed surface: 326 numeric macros, id range 0..172, contiguous, 153 duplicate numeric assignments across separate binding namespaces; category counts are clock=252, reset=44, pll=10, other=20. The first exported symbol is `GPLL0_MAIN`, and the highest numeric ID is `GCC_USB0_PIPE_CLK_SRC` at `172`. Representative clock or PLL IDs: `GCC_ADSS_PWM_CLK`, `GCC_ADSS_PWM_CLK_SRC`, `GCC_AHB_CLK`, `GCC_APSS_AXI_CLK_SRC`, `GCC_BLSP1_AHB_CLK`, `GCC_BLSP1_QUP1_I2C_APPS_CLK`, `GCC_BLSP1_QUP1_SPI_APPS_CLK`, `GCC_BLSP1_QUP1_SPI_APPS_CLK_SRC`, `GCC_BLSP1_QUP2_I2C_APPS_CLK`, `GCC_BLSP1_QUP2_SPI_APPS_CLK`, and 252 more. Representative reset IDs: `GCC_ADSS_BCR`, `GCC_APC0_VOLTAGE_DROOP_DETECTOR_BCR`, `GCC_BLSP1_BCR`, `GCC_BLSP1_QUP1_BCR`, `GCC_BLSP1_QUP2_BCR`, `GCC_BLSP1_QUP3_BCR`, `GCC_BLSP1_UART1_BCR`, `GCC_BLSP1_UART2_BCR`, `GCC_BLSP1_UART3_BCR`, `GCC_CE_BCR`, and 34 more. Representative power-domain/GDSC IDs: none. Representative CSR or auxiliary IDs: `GCC_Q6SS_DBG_ARES`, `GCC_WCSS_DBG_BDG_ARES`, `GCC_WCSS_DBG_ARES`, `GCC_WCSS_AXI_S_ARES`, `GCC_WCSS_AXI_M_ARES`, `GCC_WCSSAON_ARES`, `GCC_PCIE3X2_PIPE_ARES`, `GCC_PCIE3X2_CORE_STICKY_ARES`, `GCC_PCIE3X2_AXI_S_STICKY_ARES`, `GCC_PCIE3X2_AXI_M_STICKY_ARES`, and 10 more.

Control flow: There is no executable control flow. The C preprocessor substitutes these names with integers when compiling DTS-derived data or kernel code. At runtime the OF clock, reset, CSR, and power-domain frameworks pass those integers to the registered Qualcomm provider, which indexes its local descriptor arrays and hardware registers.

State and persistence: The file stores no runtime state. Its numeric assignments are persistent ABI: once used in DTBs, changing or reordering IDs can make old firmware descriptions request the wrong clock, reset line, or GDSC. Explicit source sections include `SPDX-License-Identifier: (GPL-2.0-only OR BSD-2-Clause)`.

Dependencies and integration points: Consumers include SoC `.dtsi` files, board DTS files, and drivers that include `dt-bindings/clock/qcom,ipq5332-gcc.h`. The producer side is the corresponding Qualcomm controller driver under the kernel clock tree, with clock, reset, CSR, and GDSC descriptors using the numeric contract in their own provider namespaces. The header is also tied to YAML Devicetree bindings for the same compatible strings, which document valid `#clock-cells`, `#reset-cells`, CSR cells, and power-domain cells when present.

Risks and test signals: Main risks are ABI drift from renumbering, accidental duplicate values inside a single provider namespace, missing driver descriptors for newly added IDs, DTS references to a symbol from the wrong SoC, and stale section comments that hide reset, CSR, or GDSC additions. Test by compiling DTBs that include this header, enabling `dtbs_check` against the matching Qualcomm binding, booting with common peripherals that request these IDs, checking `/sys/kernel/debug/clk/clk_summary`, exercising reset controls, checking CSR-backed clock-reference enables where present, and verifying power-domain attach/detach paths for any GDSC IDs.
