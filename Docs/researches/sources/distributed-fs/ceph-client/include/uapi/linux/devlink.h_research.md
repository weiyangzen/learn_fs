# sources/distributed-fs/ceph-client/include/uapi/linux/devlink.h

Purpose: defines the `devlink` generic-netlink ABI for managing and observing network physical devices, ports, shared buffers, eswitches, resources, params, regions, health reporters, flash updates, traps, rates, line cards, selftests, reloads, and function capabilities. Important APIs include family names, multicast group, command enum with strict ABI ordering, port/eswitch/rate/param/flash/trap/reload/linecard enums, the large `enum devlink_attr`, nested rate-TC attrs, dpipe field/header/action enums, resource unit/scope masks, and port-function capability/state attrs. Control flow is netlink command/attribute driven: userspace identifies a device by bus/dev name or index, dumps/sets objects, receives notifications, requests reload/flash/health operations, reads regions, and configures rates or port functions. State is kernel devlink instance state, driver resources, firmware/config params, snapshots, health dumps, traps/policers, eswitch mode, port hierarchy, and hardware linecard/function state. Dependencies include `linux/const.h`, netlink generated specs, netdev drivers, switchdev, firmware flashing, health reporters, and userspace `devlink`. Risks include changing enum order, missing spec regeneration, partial attribute policy validation, destructive reload/flash actions, stale snapshots, nested object lifetime, and hardware-specific semantic gaps. Test signals include devlink netlink selftests, dump/set round trips for each object family, notification filters, reload/flash progress, region reads, trap stats, port split/function lifecycle, 32-bit attribute parsing, and YAML regeneration consistency.
