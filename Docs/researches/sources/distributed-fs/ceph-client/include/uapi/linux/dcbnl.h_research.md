# sources/distributed-fs/ceph-client/include/uapi/linux/dcbnl.h

Purpose: defines the netlink ABI for Data Center Bridging configuration, including IEEE 802.1Qaz, CEE DCBX, priority flow control, enhanced transmission selection, congestion notification, application priority, buffers, and feature negotiation. Important APIs and types include `struct ieee_ets`, `ieee_maxrate`, `ieee_qcn`, `ieee_qcn_stats`, `ieee_pfc`, `dcbnl_buffer`, `cee_pg`, `cee_pfc`, `dcb_app`, `dcbmsg`, command enums, top-level and nested attribute enums, DCBX capability/feature flags, and PFC/PG/TC/capability/BCN/app attrs. Control flow is rtnetlink/generic DCB requests selecting a network interface, querying or setting feature-specific nested attributes, and applying negotiated or static parameters to hardware/LLDP-managed state. State is per-netdevice DCB configuration, peer-negotiated TLVs, traffic-class mapping, buffer allocation, and hardware offload status. Dependencies include `linux/types.h`, networking DCB core, NIC drivers, LLDP/DCBX agents, and userspace tools like `dcb`/`lldptool`. Risks include enum ABI ordering, invalid bandwidth sums, selector ambiguity, peer vs local TLV confusion, hardware capability mismatch, and partial nested attribute validation. Test signals include netlink policy tests, IEEE and CEE get/set round trips, PFC/ETS/app table validation, DCBX mode transitions, buffer/QCN stats queries, unsupported driver behavior, and LLDP negotiation interoperability.
