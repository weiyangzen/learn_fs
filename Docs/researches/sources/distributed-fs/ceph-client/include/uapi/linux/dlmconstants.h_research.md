# sources/distributed-fs/ceph-client/include/uapi/linux/dlmconstants.h

Purpose: centralizes DLM lockspace/resource size limits, lock modes, lock flags, and DLM-specific return codes. Important APIs are `DLM_LOCKSPACE_LEN`, `DLM_RESNAME_MAXLEN`, lock modes `IV/NL/CR/CW/PR/PW/EX`, lock flags such as `NOQUEUE`, `CANCEL`, `CONVERT`, `VALBLK`, `QUECVT`, `IVVALBLK`, `CONVDEADLK`, `PERSISTENT`, `EXPEDITE`, `NOQUEUEBAST`, `HEADQUE`, `NOORDER`, `ORPHAN`, `ALTPR`, `ALTCW`, `FORCEUNLOCK`, deprecated `TIMEOUT`, and `DLM_ECANCEL`/`DLM_EUNLOCK`. Control flow impact is policy selection for lock requests, conversions, queue placement, deadlock behavior, LVB handling, and unlock/cancel result reporting. State affected is cluster lock queues and LVB validity for resources; this header itself has none. Dependencies are `dlm.h`, `dlm_device.h`, libdlm, and clustered filesystems. Risks include invalid mode compatibility assumptions, reserved/deprecated flag use, alternate mode surprises, forced unlock misuse, and resource name length truncation. Test signals include compatibility matrix tests for every lock mode pair, flag-specific queue behavior, cancel/unlock return paths, deadlock handling, LVB invalidation, persistent/orphan lock recovery, and max-name boundary coverage.
