# sources/distributed-fs/ceph-client/include/uapi/linux/comedi.h

Purpose: defines the COMEDI user ABI for control and measurement devices, including synchronous instructions, asynchronous acquisition commands, buffer cursors, range tables, subdevice discovery, and many hardware routing constants. Important APIs and types include `CR_PACK` helpers, instruction and trigger constants, command flags, subdevice flags/types, configuration IDs, digital trigger ops, support/status enums, `COMEDI_*` ioctls, `struct comedi_insn`, `comedi_cmd`, `comedi_subdinfo`, `comedi_devinfo`, `comedi_bufconfig`, `comedi_bufinfo`, range structs, NI terminal/routing constants, and counter/timer mode enums. Control flow is ioctl-driven: configure or discover a device, inspect subdevices/channels/ranges, run single instructions or instruction lists, validate/start asynchronous commands, and coordinate ring-buffer progress. State is per-device/subdevice configuration, locks, running acquisition buffers, route state, and hardware counters; no file data is persisted here. Dependencies include ioctl/user pointer ABI, COMEDI core and drivers, NI/Amplicon/Kolter hardware conventions, and userspace comedilib. Risks include pointer-size compatibility, invalid trigger combinations, buffer cursor wraparound, route constant confusion, deprecated firmware init data, and driver-specific config interpretation. Test signals include ioctl ABI compatibility, command-test normalization, instruction list copyin/out, buffer read/write pointer advancement, route validation, 32-bit compat, and hardware/emulator coverage for AI/AO/DIO/counter subdevices.
