# sources/distributed-fs/ceph-client/arch/arm64/kvm/at.c

## Purpose
`at.c` implements trapped ARM64 address-translation instruction emulation for KVM, especially for nested virtualization and guest EL2 contexts. It provides fast paths that temporarily execute hardware AT instructions under the guest translation context, slow paths that software-walk guest stage-1 page tables, PAR_EL1 synthesis, optional stage-2 composition for S12 translations, guest descriptor Access Flag updates, and helper translation APIs used by other KVM code.

## Important APIs, Types, and Functions
The core inputs and outputs are `struct s1_walk_info` and `struct s1_walk_result`, supplied by common ARM64 KVM headers. `fail_s1_walk` records architectural fault status, PTW/stage-2 markers, and failure state. `setup_s1_walk` derives a full translation walk configuration from guest sysregs and the target virtual address: regime, page size, TnSZ, start level, TTBR base, address size limits, endianness, HA/HPD, S1PIE, S1POE, stage-2-on-page-table-walk state, and disabled-MMU handling. `walk_s1` reads and validates guest descriptors, optionally translates page-table accesses through nested stage-2, applies HA Access Flag updates, and returns the final IPA/PA and descriptor metadata.

Translation entry points include `__kvm_at_s1e01`, `__kvm_at_s1e2`, `__kvm_at_s12`, and `__kvm_translate_va`. `__kvm_find_s1_desc_level` walks until a caller-specified descriptor IPA is found and reports its level. Descriptor updates use `__kvm_at_swap_desc`, which chooses LSUI, LSE CAS, or LL/SC depending on CPU capabilities. Attribute and permission synthesis is handled by `compute_par_s1`, `compute_par_s12`, `compute_s1_permissions`, `compute_s1_direct_permissions`, `compute_s1_hierarchical_permissions`, `compute_s1_indirect_permissions`, and `compute_s1_overlay_permissions`.

## Control Flow
For S1E0/S1E1 operations, `__kvm_at_s1e01` first calls `__kvm_at_s1e01_fast`. The fast path takes `kvm->mmu_lock` with interrupts disabled, saves host EL1 MMU registers when it must context-switch a nested L2 translation context, loads guest TTBR/TCR/MAIR/SCTLR/TCR2/PIR/PIRE0/POR and stage-2 state, switches HCR to the guest view, executes the matching hardware AT instruction, reads PAR_EL1 on success, restores host HCR and MMU state, and returns either a valid PAR or a failure marker. If hardware AT failed for anything other than a definitive S1 permission/access fault, `handle_at_slow` performs the software walk and writes the synthesized PAR_EL1 back to the vCPU.

The slow path computes the translation regime from the AT opcode and virtual EL2 `{E2H,TGE}` state. `setup_s1_walk` reads the applicable EL1 or EL2 control registers, selects TTBR0/TTBR1 from VA bit 55, decodes TG0/TG1, computes 52-bit PA support, checks TBI/address-size and translation-size constraints, handles disabled MMU cases, validates EPD/E0PD, derives output size from TCR IPS/PS and KVM IPA limits, aligns TTBR base addresses including LPA2 high bits, and records HA. `walk_s1` then iterates levels from the computed start level, derives the descriptor index from the VA, translates page-table descriptor accesses through nested stage-2 if required, invokes an optional filter, reads descriptors using guest endianness, validates invalid/table/block/page descriptors, records table permissions unless HPD disables hierarchy, checks output address size, updates AF when HA is enabled, and produces final output address, descriptor, level, nG, and ASID metadata.

After a successful walk, `compute_s1_permissions` calculates direct or indirect S1 permissions, applies hierarchical APTable/PXNTable/UXNTable restrictions when enabled, applies permission overlays, enforces WXN and PAN/PAN3, and lets `handle_at_slow` decide whether the requested read/write/EL0/EL1 access should become a permission fault. `compute_par_s1` converts success, disabled-MMU, or failure state to PAR_EL1. `__kvm_at_s12` first performs the S1 translation, then, when the regime and HCR require it, walks nested stage-2 for the resulting IPA, checks read/write permission, combines memory attributes/shareability, and writes a final S12 PAR.

## State and Persistence Behavior
The file is mostly stateless across calls. It temporarily mutates CPU system registers in fast paths and restores them before returning. It may persistently update guest memory by setting `PTE_AF` when hardware access flag management is architecturally enabled for the guest walk. That update is done through atomic compare-and-swap on the userspace backing page, under KVM SRCU and with writable memslot validation, and then marks the page dirty. The code also writes the emulated PAR result into the vCPU `PAR_EL1` sysreg.

## Dependencies and Integration Points
The walker depends on guest sysreg accessors, CPU feature predicates, ARM64 page-table encodings, ESR/PAR/TCR/SCTLR/HCR definitions, nested stage-2 walkers (`kvm_walk_nested_s2`), stage-2 MMU loading, KVM memslot/HVA translation, SRCU, dirty logging, privileged uaccess helpers, LSUI/LSE/LLSC atomic mechanisms, and hyp helper `__kvm_at`. It integrates with nested virtualization because AT instructions trapped from virtual EL2 need the L1-controlled translation regime and may require L2 stage-2 context lookup via `lookup_s2_mmu`.

## Risks and Edge Cases
The biggest risk is architectural drift: the software walker mirrors many ARM ARM rules for LPA2, 52-bit PA, TBI, EPD/E0PD, HPD, HA, S1PIE, S1POE, PAN3, WXN, disabled MMU, attribute composition, and stage-2 fault reporting. Any mismatch can expose incorrect PAR_EL1 results to a nested hypervisor. Fast paths are sensitive because they switch MMU context behind the host's back under interrupt-disabled locking. Descriptor AF updates can race with userspace or another vCPU; `-EAGAIN` intentionally restarts the walk. Endianness and 52-bit descriptor address extraction are easy bug points. The S12 path must distinguish S1 failures from S2 failures and avoid composing a bogus PAR when only one translation stage applies.

## Test Signals
Good coverage comes from ARM64 KVM selftests that execute AT S1E0, S1E1, S1E2, and S12 instructions from nested guests across 4K/16K/64K granules, TTBR0/TTBR1, disabled MMU, TBI on/off, EPD/E0PD, 48-bit and 52-bit PAs, LPA2, big-endian descriptors, AF set/clear, read/write/user/privileged permission failures, PAN/PAN3, WXN, HPD hierarchy, S1PIE/S1POE, nested stage-2 read/write faults, and memslot read-only/error paths. Fault tests should assert PAR_EL1 `F`, `S`, `PTW`, and `FST` fields rather than only return codes.
