# sources/distributed-fs/ceph-client/arch/riscv/purgatory/entry.S

Purpose: is the RISC-V purgatory entry point executed between the old and new kernels during kexec. Important symbols are `purgatory_start`, `.Lstack`, and `riscv_kernel_entry`. Control flow sets a private stack, saves incoming hart ID and FDT physical address in saved registers, calls the C `purgatory` verifier, restores arguments, loads the patched new-kernel entry address, and jumps to it. State consists of the embedded stack area and writable `riscv_kernel_entry` data symbol patched by kexec loading; no persistence. Dependencies include RISC-V calling convention, `asm/asm.h`, kernel linkage macros, and `purgatory.c`. Integration is through the embedded `kexec_purgatory` blob and kexec segment relocation. Risks include stack size insufficiency, ABI mismatch for `a0/a1`, unpatched or misrelocated `riscv_kernel_entry`, and verifier returning after failed digest only if its infinite loop is broken. Test signals: kexec boot with FDT handoff, relocation tests, symbol patch validation, and digest-failure hang behavior.
