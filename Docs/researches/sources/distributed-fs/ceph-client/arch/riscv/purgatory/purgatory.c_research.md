# sources/distributed-fs/ceph-client/arch/riscv/purgatory/purgatory.c

Purpose: verifies kexec-loaded segments before transferring control to the new RISC-V kernel. Important data/functions are `purgatory_sha256_digest`, `purgatory_sha_regions`, `verify_sha256_digest`, and `purgatory`. Control flow initializes a SHA-256 context, iterates all `KEXEC_SEGMENT_MAX` regions, updates the digest from each `start/len`, compares with the patched expected digest, and loops forever on mismatch. State is the `.kexec-purgatory` data patched by the kexec loader; there is no persistence beyond the loaded image. Dependencies include freestanding SHA-256, `linux/purgatory.h`, string/memcmp support, and the assembly entry. Risks include trusting malformed region descriptors, lack of diagnostics on failure, digest mismatch causing an intentional silent hang, and region list entries with zero length still being processed. Test signals: kexec with valid/invalid segment hashes, maximum segment count, purgatory relocation patching, and failure-path observation under emulation.
