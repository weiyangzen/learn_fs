# sources/distributed-fs/ceph-client/arch/x86/kvm/vmx/x86_ops.h

Purpose: declares the Intel VMX implementation entry points that populate KVM's generic `kvm_x86_ops` and `kvm_x86_init_ops` interfaces, plus optional TDX overrides. It is the contract between the common x86 KVM core and VMX-specific lifecycle, run-loop, state access, interrupt, MMU, APIC, MSR, nested, timer, and ioctl behavior.

Important APIs and functions: initialization declarations include `vmx_hardware_setup()`, `vmx_hardware_unsetup()`, `vmx_check_processor_compat()`, CPU virtualization enable/disable/emergency-disable, and exported init/runtime ops `vt_init_ops` and `vt_x86_ops`. VM/vCPU lifecycle hooks include `vmx_vm_init()`, `vmx_vm_destroy()`, `vmx_vcpu_precreate()`, `vmx_vcpu_create()`, `vmx_vcpu_free()`, `vmx_vcpu_reset()`, load/put, pre-run, run, and exit handling. State hooks cover MSRs, segments, CPL, CR0/CR4/EFER validation and writes, descriptor tables, DR7/debug registers, RFLAGS, interrupt shadow, TLB flushing, MMU root loading, hypercall patching, exception/IRQ/NMI injection, APICv operations, TSS/identity-map setup, memory type masks, exit/entry info, TSC offset/scaling, dirty logging, VMX preemption timer, and MCE setup. Under `CONFIG_KVM_SMM`, SMM entry/exit and SMI-window hooks are declared. Under `CONFIG_KVM_INTEL_TDX`, TDX VM/vCPU lifecycle, run/exit, interrupt, MSR, ioctl, TLB, MMU, and private memory helpers are declared.

Control flow and behavior: `main.c` builds `vt_x86_ops` from these VMX functions so generic KVM x86 code can call through a stable backend interface. Hardware setup probes capabilities and may adjust function pointers for features such as APICv, Hyper-V remote TLB flushes, timers, nested VMX, or TDX. The vCPU run path flows from common KVM into `vmx_vcpu_pre_run()`, `vmx_vcpu_run()`, irqoff exit handling, and `vmx_handle_exit()`. State accessors translate generic KVM requests into VMCS, MSR bitmap, APICv, EPT, VPID, and nested VMX operations.

State and persistence: this header has no storage, but it declares functions that manipulate persistent in-memory VM and vCPU state in `struct kvm_vmx`, `struct vcpu_vmx`, generic `struct kvm_vcpu`, VMCS pages, MSR autoload/autostore lists, APICv/PI descriptors, EPT roots, TSC scaling fields, and optional TDX private state. Function-pointer tables initialized from these declarations persist while the KVM module is loaded.

Dependencies and integration points: depends on generic KVM host structures, VMX private `x86.h`, x86 instruction decode/intercept structures, LAPIC, SMM, MMU, TDX, and common KVM x86 backend registration. Integrates with `vmx.c`, `main.c`, `nested.c`, `tdx.c`, `pmu_intel.c`, APIC/interrupt code, Hyper-V enlightenment paths, and KVM userspace ioctls.

Risks and correctness concerns: declarations must match the definitions and `kvm_x86_ops` expected signatures exactly; mismatches break builds or, worse, callback semantics. Because `vt_x86_ops` can be patched at hardware setup time, consumers must handle NULL feature hooks correctly. TDX and VMX share a VT ops surface but have different VMCS access rules, interrupt behavior, and private-memory constraints. Lifecycle ordering is sensitive: CPU virtualization enablement, VMCS allocation, vCPU load/put, and emergency disable paths must remain consistent with generic KVM locking and CPU hotplug.

Test signals: build coverage across SMM, TDX, Hyper-V, nested VMX, x86-64-only timer paths, and minimal configs validates the declaration surface. Runtime signals include KVM unit/selftests for vCPU creation/run/reset, MSR and segment state ioctls, CR/EFER validation, interrupt/NMI/window injection, APICv and posted interrupts, TLB flush hooks, dirty logging, nested virtualization, suspend/emergency virtualization disable, and TDX-specific VM/vCPU ioctls when enabled.
