# sources/distributed-fs/ceph-client/arch/x86/kernel/sys_x86_64.c

## Purpose
`sys_x86_64.c` implements native x86 mmap handling and arch-specific unmapped-area selection, covering AMD virtual-address alignment, `MAP_32BIT`, `MAP_ABOVE4G`, huge pages, top-down fallback, and shadow-stack guard placement.

## Important APIs, Types, And Functions
Key functions are `mmap`, `arch_get_unmapped_area()`, `arch_get_unmapped_area_topdown()`, `control_va_addr_alignment()`, `find_start_end()`, `get_align_mask()`, `get_align_bits()`, and `stack_guard_placement()`.

## Control Flow
`mmap` validates page-aligned offsets and calls `ksys_mmap_pgoff()`. Bottom-up search computes the allowed window, honors a valid hint, then calls `vm_unmapped_area()` with alignment and guard information. Top-down search validates hints, handles `MAP_32BIT`, expands high limits for high native hints, and falls back to bottom-up on `-ENOMEM`.

## State, Persistence, Dependencies, Integration
Persistent state is `va_align` policy and per-boot alignment bits. Dependencies include the current mm VMA tree, hugepage helpers, mmap base randomization, task-size helpers, and VM flags such as `VM_SHADOW_STACK`. `shstk.c` relies on the guard-gap behavior for shadow-stack mappings.

## Risks And Test Signals
Window mistakes affect ASLR, x32/IA32 limits, and legacy `MAP_32BIT`. Alignment must remain CPU-family gated. Shadow-stack guard gaps must affect availability. Test fixed/hinted/random mappings, native/x32/IA32, `MAP_32BIT`, `MAP_ABOVE4G`, huge pages, alignment boot options, top-down fallback, and shadow-stack gaps.
