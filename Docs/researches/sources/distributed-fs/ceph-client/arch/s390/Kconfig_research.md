# sources/distributed-fs/ceph-client/arch/s390/Kconfig

Purpose: defines the s390 architecture feature model, compiler/toolchain gates, processor-generation choices, memory/I/O/virtualization options, APPLDATA modules, and selftest toggles. Important symbols include `S390`, `MARCH_Z10` through `MARCH_Z17`, `TUNE_*`, `COMMAND_LINE_SIZE`, `NR_CPUS`, `CERT_STORE`, `EXPOLINE`, `RANDOMIZE_BASE`, `KERNEL_IMAGE_BASE`, `MAX_PHYSMEM_BITS`, `QDIO`, `AP`, `APPLDATA_*`, `S390_GUEST`, and KUnit selftests. Control flow is Kconfig dependency resolution: `S390` selects broad kernel capabilities, machine choices select facility feature tiers, compiler probes guard inline asm and stack protector options, and menus group CPU, memory, I/O, virtualization, and tests. State is build-time configuration, not runtime persistence. Dependencies include compiler version tests, tool scripts, generic kernel Kconfig files, s390 KVM Kconfig, and architecture docs. Risks are over-selecting capabilities without implementation support, stale compiler version gates, machine-generation configs that produce unbootable kernels on older systems, and APPLDATA/sysctl dependency drift. Test signals: randconfig/all*config, olddefconfig migration, minimum z10 build, expoline compiler detection, APPLDATA module builds, and KUnit selftest symbol resolution.
