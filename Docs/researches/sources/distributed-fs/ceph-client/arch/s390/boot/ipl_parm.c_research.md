# sources/distributed-fs/ceph-client/arch/s390/boot/ipl_parm.c

Purpose: stores and parses IPL parameter data, early command-line options, and facility/debug boot controls for s390. Important data/functions include `parmarea`, `early_command_line`, preserved `ipl_block`, `zlib_dfltcc_support`, `__kaslr_enabled`, `cmma_flag`, `memory_limit`, `vmalloc_size`, `store_ipl_parmblock`, `is_ipl_block_dump`, `ipl_block_get_ascii_scpdata`, `append_ipl_block_parm`, `setup_boot_command_line`, `modify_fac_list`, and `parse_boot_command_line`. Control flow stores DIAG 308 IPL data, converts EBCDIC command lines to ASCII, appends VM/SCP IPL parameters, parses early options such as `mem`, `vmalloc`, `dfltcc`, `facilities`, `debug-alternative`, `nokaslr`, `cmma`, `prot_virt`, logging options, and lowcore relocation. State is boot-data and preserved boot-data sections consumed later by startup and decompressor code. Dependencies include DIAG 308, IPL block formats for CCW/FCP/NVMe/ECKD, EBCDIC conversion, ctype, facility list modification, machine features, protected virtualization checks, and boot logging globals. Risks include command-line buffer boundary mistakes, uppercase/lowercase SCP interpretation, invalid facility clearing preventing boot, protected-virtualization restrictions, and preserved data section mismatch. Test signals: IPL type matrix, EBCDIC and ASCII parameters, command-line truncation, KASLR/nokaslr, dfltcc modes, facility ranges/exclusions, CMMA/prot_virt options, and bootdata section comparison.
