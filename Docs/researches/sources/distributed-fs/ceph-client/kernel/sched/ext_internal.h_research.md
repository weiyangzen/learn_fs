# sources/distributed-fs/ceph-client/kernel/sched/ext_internal.h

Purpose: defines the internal sched_ext contract shared across the scheduler implementation and BPF struct_ops registration. It contains constants, exit metadata, scheduler operation flags, callback argument containers, the full `struct sched_ext_ops` ABI, event counters, per-CPU and per-node scheduler state, enqueue/dequeue/kick flag enums, task-group flags, enable states, task ownership state encoding, and inline helpers for resolving scheduler instances.

Important APIs and types: `SCX_OP_IDX()` and `SCX_MOFF_IDX()` convert operation-table members or byte offsets to function-pointer indexes for operation presence tracking. `enum scx_consts` defines default dispatch batch limits, watchdog timeouts, exit dump sizes, CPU capacity scale, task-iteration batch sizes, bypass load-balance defaults, reenq limits, and sub-scheduler depth. Exit-related types are `enum scx_exit_kind`, `enum scx_exit_code`, `enum scx_exit_flags`, and `struct scx_exit_info`. `enum scx_ops_flags` exposes scheduler behavior flags including built-in idle retention, enqueue-last behavior, exiting-task handling, partial switching, migration-disabled enqueue behavior, queued wakeup allowance, per-node built-in idle, always-immediate local enqueues, and internal CPU-preempt capability.

`struct sched_ext_ops` is the central BPF scheduler ABI. It defines callbacks for CPU selection, enqueue/dequeue, dispatch, tick, task state notifications, yield, core scheduling order, task weight and cpumask updates, idle updates, CPU acquire/release, task init/exit/enable/disable, debug dumps, optional cgroup callbacks, sub-scheduler attach/detach, CPU hotplug, init, and exit. It also includes data fields such as `dispatch_max_batch`, `flags`, `timeout_ms`, `exit_dump_len`, `hotplug_seq`, `sub_cgroup_id`, `name`, and internal `priv`.

Scheduler runtime state includes `struct scx_event_stats`, `struct scx_dsp_buf_ent`, `struct scx_dsp_ctx`, `struct scx_deferred_reenq_local`, `struct scx_sched_pcpu`, `struct scx_sched_pnode`, and `struct scx_sched`. `struct scx_sched` embeds the user operation table, operation presence bitmap, DSQ hash, per-node global DSQs, per-CPU state, slice defaults, bypass state, warning flags, optional sub-scheduler links, watchdog timeout, exit info, kobject, helper work items, bypass load-balance masks, RCU work, and ancestor scheduler array.

Control flow: `ext.c` uses the operation-index ranges in `enum scx_opi` to decide which callbacks are normal, CPU-hotplug-sensitive, or unavailable after init. Load-time validation and BPF struct_ops conversion use the operation table layout and flags. Runtime enqueue, dequeue, dispatch, selection, tick, hotplug, cgroup, and dump paths consult `struct scx_sched`, per-CPU state, and `SCX_HAS_OP` style operation presence. BPF-facing kfuncs use `scx_prog_sched()` to map an implicit `bpf_prog_aux` to the owning scheduler instance, while scheduler task paths use `scx_task_sched()` or `scx_task_sched_rcu()` to resolve the scheduler associated with a task.

State and persistence: all state described here is in-memory kernel scheduler state. The root scheduler pointer is `scx_root` under RCU. `scx_locked_rq_state` is per-CPU and records an rq lock held while running sched_ext callbacks. Event counters live per CPU and are aggregated on demand. The task ownership state is encoded in `p->scx.ops_state` using low bits for `enum scx_ops_state` and high bits for a queue sequence number. Release/acquire memory ordering is required when leaving transitional states so dispatch and dequeue paths observe valid ownership.

Task ownership behavior: `SCX_OPSS_NONE` means the core scheduler owns the task, `SCX_OPSS_QUEUEING` transfers it to the BPF scheduler while the rq lock is held, `SCX_OPSS_QUEUED` means the BPF scheduler owns it and the qseq brands this queued instance, and `SCX_OPSS_DISPATCHING` transfers it back to the core. The documented state machine lets BPF dispatch attempts race with dequeues safely: stale qseq dispatches are ignored, queueing and dispatching waiters use acquire/release ordering, and cross-CPU movement during dispatch uses a `holding_cpu` lock-dancing protocol to avoid rq-lock deadlocks.

Dependencies and integration points: depends on core scheduler structures, BPF struct_ops, cgroups, runqueue locking, RCU, rhashtable DSQ lookup, kobjects, kthread work, timers, IRQ work, cpumasks, and optional sub-scheduler support. It is consumed heavily by `ext.c`, `ext_idle.c`, and cgroup scheduler integration, and it defines many enum constants deliberately kept visible to BPF schedulers through generated `vmlinux.h`.

Risks: this header is both internal implementation glue and ABI description for BPF schedulers, so layout or semantic changes can break verifier expectations, struct_ops compatibility, or existing scheduler programs. Operation flag validation must keep user-settable flags separate from high internal bits. Incorrect `SCX_OPSS_*` memory ordering, qseq masking, or lock-context assumptions can cause lost tasks, invalid dispatch acceptance, stalls, or rq-lock deadlocks. Sub-scheduler resolution has compatibility logic for unassociated pre-sub-scheduler programs; changing it can misattribute kfunc calls. Event counters and bypass state are diagnostic and safety-critical because they reveal scheduler malfunction and support forward progress under errors or power-management transitions.

Test signals: compile with and without `CONFIG_EXT_SUB_SCHED`, `CONFIG_EXT_GROUP_SCHED`, and core scheduling. Load BPF schedulers implementing different subsets of `sched_ext_ops`, including schedulers with `update_idle`, cgroup callbacks, queued wakeup, partial switching, sub-scheduler attach, CPU hotplug callbacks, and immediate local DSQ insertion. Stress enqueue/dequeue/dispatch races, affinity changes, migration-disabled tasks, CPU hotplug, cgroup moves, bypass activation, watchdog stalls, scheduler unload, and verifier context filtering. Inspect event counters for select-cpu fallback, local DSQ offline fallback, keep-last dispatch, reenq-immediate recursion, skipped exiting or migration-disabled enqueues, and insert-not-owned signals.
