# sources/distributed-fs/ceph-client/kernel/sched/ext_idle.c

Purpose: implements sched_ext built-in idle CPU tracking, default idle CPU selection, and BPF kfuncs that let sched_ext BPF schedulers observe or claim idle CPUs. It maintains global or per-NUMA-node idle CPU masks, optional SMT-full-core masks, topology-aware LLC/NUMA selection hints, and BTF kfunc registration for idle and select-cpu helper APIs.

Important APIs and types: `struct scx_idle_cpus` holds two cpumasks: `cpu` for idle logical CPUs and `smt` for fully idle SMT sibling groups. Static keys `scx_builtin_idle_enabled`, `scx_builtin_idle_per_node`, `scx_selcpu_topo_llc`, and `scx_selcpu_topo_numa` dynamically enable built-in idle tracking, per-node masks, LLC-aware selection, and NUMA-aware selection. Initialization and scheduler-core APIs are `scx_idle_init_masks()`, `scx_idle_enable()`, `scx_idle_disable()`, `scx_idle_update_selcpu_topology()`, `scx_select_cpu_dfl()`, `__scx_update_idle()`, and `scx_idle_init()`. BPF-facing kfuncs include `scx_bpf_cpu_node()`, `scx_bpf_select_cpu_dfl()`, `__scx_bpf_select_cpu_and()`, compatibility `scx_bpf_select_cpu_and()`, idle-mask getters, `scx_bpf_put_idle_cpumask()`, `scx_bpf_test_and_clear_cpu_idle()`, `scx_bpf_pick_idle_cpu_node()`, `scx_bpf_pick_idle_cpu()`, `scx_bpf_pick_any_cpu_node()`, and `scx_bpf_pick_any_cpu()`.

Control flow: boot-time sched_ext initialization calls `scx_idle_init_masks()` from `init_sched_ext_class()` to allocate global, per-node, and per-CPU temporary cpumasks. Later `scx_init()` calls `scx_idle_init()` to register BTF kfunc sets. When a BPF scheduler instance is enabled, `scx_idle_enable()` selects whether built-in idle tracking remains active based on `ops.update_idle` and `SCX_OPS_KEEP_BUILTIN_IDLE`, enables per-node tracking when `SCX_OPS_BUILTIN_IDLE_PER_NODE` is set, and calls `reset_idle_masks()`. `scx_idle_update_selcpu_topology()` runs during enable and hotplug to toggle LLC and NUMA optimization static keys after inspecting `sd_llc` and `sd_numa` scheduling domains. Idle-class transitions call `__scx_update_idle()`, which updates built-in masks first and then calls `ops.update_idle()` for real state transitions unless the scheduler is bypassing on that CPU.

Idle selection flow: `scx_select_cpu_dfl()` computes the usable `allowed` mask from an optional caller mask and `p->cpus_ptr`, handles affinity-constrained and migration-disabled tasks through the kfunc wrapper, then under RCU prefers wake-sync locality, full-idle SMT cores, previous CPU reuse, SMT siblings, same LLC, same NUMA node, and finally any allowed idle CPU. `pick_idle_cpu_in_node()` claims a CPU by calling `scx_idle_test_and_clear_cpu()`; the test-and-clear operation removes the logical CPU from idle masks and clears the entire SMT sibling group from the full-idle mask to avoid double claims. With per-node tracking, `scx_pick_idle_cpu()` starts in the previous CPU's node and can expand to online nodes by NUMA distance unless `SCX_PICK_IDLE_IN_NODE` is set. `SCX_PICK_IDLE_CORE` limits selection to fully idle SMT cores.

State and persistence: runtime state is in allocated cpumasks: global idle masks, an array of per-node idle masks sized by `nr_node_ids`, per-CPU temporary masks for allowed/LLC/NUMA intersections, and per-CPU NUMA nodemasks used while searching nodes. The state is volatile, recalculated from scheduler idle transitions and reset during scheduler enable. BPF idle-mask getters return global kernel cpumask pointers with artificial acquire/release semantics only to satisfy verifier trusted-pointer rules; the masks are not reference-counted or persistent outside the running kernel.

Dependencies and integration points: depends on scheduler domains (`sd_llc`, `sd_numa`), cpumask APIs, NUMA node state, SMT topology helpers, runqueue `rq->scx.local_dsq`, sched_ext root scheduler state, BPF struct_ops and kfunc registration, BTF ID sets, and sched_ext context filters from `ext.c`. It is called by `ext.c` during sched_ext class initialization, root scheduler enable, hotplug, and kfunc verifier filtering; by `idle.c` during idle task transitions; and by BPF schedulers through registered kfuncs.

Risks: idle masks are intentionally racy optimizations, so callers must tolerate false negatives and must kick a CPU when they need guaranteed future dispatch. The SMT mask must be cleared on both successful and failed claims to avoid infinite retry loops, especially when CPUs go offline and are no longer in their sibling mask. Per-node access requires strict validation because global and per-node modes are mutually exclusive for several kfuncs. `select_cpu_from_kfunc()` has lock-context-sensitive behavior: it trusts `p->pi_lock` inside `ops.select_cpu()`, uses `scx_locked_rq()` for rq-locked callbacks, and otherwise takes `p->pi_lock`; cross-task use under the wrong rq lock is rejected. Topology optimization depends on scheduler-domain RCU protection and can misplace locality if domain weights or hotplug state are stale.

Test signals: exercise sched_ext selftests and BPF schedulers that call default select-cpu helpers, idle mask getters, pick-idle, and pick-any kfuncs. Cover SMT on/off, single-CPU, multiple LLC domains, multiple NUMA nodes, per-node tracking, hotplug online/offline, wake-sync wakeups, migration-disabled tasks, restricted affinity masks, and schedulers that implement `ops.update_idle` with and without `SCX_OPS_KEEP_BUILTIN_IDLE`. Useful failure signals include `scx_error()` messages for disabled built-in tracking or invalid nodes, stalled runnable tasks with idle CPUs, repeated select-cpu fallback events, and verifier rejection of kfuncs in invalid BPF program contexts.
