# sources/distributed-fs/ceph-client/kernel/rcu/refscale.c

Purpose: this file implements the RCU reference-acquisition scalability benchmark module. Unlike `rcutorture.c`, it focuses on measuring read-side/reference-acquisition overhead rather than proving grace-period correctness. It compares normal RCU, SRCU variants, Tasks/Trace RCU where configured, atomic reference counts, per-CPU increment forms, rwlocks/rwsems/spinlocks, acquire-release memory operations, clock/jiffies reads, preemption/BH/IRQ disable sections, and `SLAB_TYPESAFE_BY_RCU` lookup patterns.

Important APIs/types/functions: `struct ref_scale_ops` abstracts each benchmarked mechanism with optional `init`/`cleanup`, `readsection`, `delaysection`, `enable_irqs`, and `name`. `struct reader_task` tracks each reader kthread, start flag, wait queue, and measured duration. `ref_scale_init()` selects an ops vector by `scale_type`, creates readers and the main orchestrator, and registers optional shutdown. `main_func()` drives experiments and prints per-run averages. `ref_scale_reader()` performs synchronized reader-side timing. `rcu_scale_one_reader()`, `rcu_scale_warm_cool()`, `process_durations()`, and `reset_readers()` implement the measurement loop. Typesafe tests use `struct refscale_typesafe`, `typesafe_init()`, `typesafe_cleanup()`, `typesafe_delay_section()`, and acquisition/release variants based on refcount, spinlock, or seqlock.

Control flow: initialization calls `torture_init_begin()`, matches `scale_type` against a static `scale_ops[]` table, runs the selected init hook, prints parameters, sets shutdown handling, normalizes `nreaders`, `loops`, and `nruns`, allocates `reader_tasks`, starts one reader kthread per reader, then starts `main_func()`. The main task waits for all readers, performs warm/cool loops, and for each run sets shared atomics (`nreaders_exp`, `n_started`, `n_warmedup`, `n_cooleddown`), publishes each reader's `start_reader` flag with release ordering, wakes readers, waits for completion, collects durations, and prints average nanoseconds per loop. Readers bind to deterministic CPUs, wait for the start flag, synchronize start/warm/cool phases through atomics, optionally disable interrupts around the timed region, execute the selected read section once for timing, store `last_duration_ns`, and keep doing load-maintenance work until all readers cool down.

Benchmark mechanisms: RCU and SRCU sections loop over lock/unlock pairs, with delay variants inserting micro/nanosecond waits. Refcount tests use `atomic_inc/atomic_dec`; per-CPU tests cover `this_cpu_inc/dec`, raw `this_cpu_ptr` updates, preempt-disabled updates, BH-disabled updates, and IRQ-save updates. Lock tests cover read-side rwlock, rwsem, raw spinlock, and raw spinlock with IRQ save/restore. Other comparison points measure acquire-release stores, `sched_clock()`, `ktime_get_real_fast_ns()`, `jiffies`, preempt disable/enable, BH disable/enable, IRQ disable/enable, and IRQ save/restore overhead. Typesafe tests allocate a `SLAB_TYPESAFE_BY_RCU` cache, keep an RCU-protected pointer array, retry when validation fails, and verify stable object fields while using refcount, lock, or seqlock acquisition.

State and persistence behavior: all benchmark state is in memory and exists only during the module run. Module parameters control scale type, verbosity, holdoff, guest OS delay, lookup instance count, loop count, reader count, run count, read delay, and shutdown behavior. Results are emitted to the kernel log with per-reader durations and per-run averages; there is no file output. `reader_tasks`, `result_avg`, temporary print buffers, and typesafe slab/pointer arrays are dynamically allocated and freed in cleanup. The selected `cur_ops` may hold global helper state such as `srcu_ctlp`, `refcnt`, `test_acqrel`, locks, or `typesafe_kmem_cachep`.

Dependencies and integration points: the module uses the RCU/SRCU/Tasks Trace APIs, atomic/per-CPU primitives, scheduler CPU affinity and clock APIs, raw spinlocks/rwlocks/rwsems, `seq_buf` formatting, slab allocation with `SLAB_TYPESAFE_BY_RCU`, and the torture framework for parameters, thread creation, lifecycle, and optional shutdown. Its output is intended for `rcuscale`/torture automation and kernel log parsing rather than a formal pass/fail result.

Risks: benchmark validity depends on synchronized start, CPU affinity, interruption control, and avoiding measurement skew during warmup/cooldown. Disabling interrupts around timed sections reduces noise but is unsafe for mechanisms that require IRQs, so `enable_irqs` must be correct. Integer normalization protects against `nreaders * loops` overflow, but extreme parameters can still create long-running or noisy tests. Typesafe tests are intentionally subtle: stale or recycled objects must be validated correctly with refcount/lock/seqlock acquisition, and cleanup must destroy every allocated slab object and cache. Some per-CPU variants explicitly can lose counts on preemptible kernels; they are comparison baselines, not safe generic reference algorithms.

Test signals: expected signals are startup parameter logs, per-experiment `THREAD-NUM:Total loop time in ns` lines, final `Runs Time(ns)` average output, and clean module cleanup. Useful validation includes running several `scale_type` values, checking that invalid names list available types with `-EINVAL`, verifying that `loops`, `nreaders`, and `nruns` are clamped when nonpositive, confirming no negative durations, and enabling typesafe variants under stress to catch `WARN_ONCE(a != b)` or `WARN_ON_ONCE(a * a != b)` consistency failures.
