# sources/distributed-fs/ceph-client/kernel/trace/fgraph.c

Purpose: implements function graph tracing infrastructure: allocation and management of per-task shadow return stacks, registration of `struct fgraph_ops` clients, dispatch of entry and return callbacks, direct static-call optimization for the single-client case, PID filtering, sleep-time accounting, CPU/task lifecycle support, and unwinder helpers that recover original return addresses.

Important APIs and types: exported or externally used entry points include `function_graph_enter_regs()`, `ftrace_return_to_handler()`, `ftrace_graph_get_ret_stack()`, `ftrace_graph_top_ret_addr()`, `ftrace_graph_ret_addr()`, `fgraph_reserve_data()`, `fgraph_retrieve_data()`, `fgraph_retrieve_parent_data()`, `fgraph_get_task_var()`, `fgraph_init_ops()`, `ftrace_graph_init_idle_task()`, `ftrace_graph_init_task()`, `ftrace_graph_exit_task()`, `register_ftrace_graph()`, and `unregister_ftrace_graph()`. Core state includes `fgraph_array`, `fgraph_array_bitmask`, LRU index allocation, `fgraph_stack_cachep`, global `ftrace_graph_active`, static keys/calls for direct dispatch, and task fields `ret_stack`, `curr_ret_stack`, `curr_ret_depth`, `trace_overrun`, and sleep timestamps.

Control flow: registration takes `ftrace_lock`, creates the shadow-stack slab cache, initializes CPU hotplug support and `fgraph_array`, assigns the client an index, optionally enables the direct static-call path, allocates return stacks for idle and existing tasks, registers the sched-switch probe, and starts ftrace graph subops. Function entry calls `function_graph_enter_regs()`, recursion-checks, pushes an `ftrace_ret_stack` frame, runs either the direct `entryfunc` or all active `fgraph_ops`, lets entry callbacks reserve data, and records a bitmap of clients that need return callbacks. Function return reaches `ftrace_return_to_handler()`, pops the frame, restores the original return address, updates pt_regs, dispatches `retfunc` callbacks selected by the bitmap, then moves `curr_ret_stack` and depth back. Unregistration removes the client from arrays/filter subops, switches direct/non-direct mode as client count changes, unregisters sched/PM hooks when the last client leaves, and clears graph flags.

State and persistence: state is runtime-only but long-lived while graph tracing is active. Each task has a 4 KiB shadow stack from `fgraph_stack_cachep`; idle stacks are per-CPU cached. The stack encodes frame offsets, callback bitmaps, reserved data blocks, and per-client task variables. Barriers protect interrupt/unwinder views of partially updated stacks. Hibernation pauses graph tracing because task stack state is unstable across suspend/resume. Sleep-time accounting persists in task fields only for tracing duration.

Dependencies and integration points: integrates with dynamic ftrace, `struct ftrace_ops`, arch return-to-handler glue, static calls/jump labels, scheduler tracepoints, PM notifier, CPU hotplug, task lifecycle hooks, stack unwinders, and optional function return-value tracing. `fprobe.c` is a major in-tree client through `register_ftrace_graph()`.

Risks and test signals: high-risk areas are stack offset encoding, interrupt-visible ordering around `curr_ret_stack`, overrun handling, direct-dispatch transitions when the active client count changes, client index reuse, PID filter wrapping, module/client unregister while callbacks are in flight, hibernation pause behavior, and unwinder reconstruction of tail calls. Test signals include function_graph tracer smoke tests, fprobe return-handler tests, stack unwinder tests under active graph tracing, task fork/exit and CPU hotplug coverage, sched-switch sleep-time accounting, PM hibernation pause/resume, recursion stress, and configurations with/without dynamic ftrace, static calls, ftrace regs, and return-value support.
