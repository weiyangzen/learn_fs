# sources/distributed-fs/ceph-client/kernel/trace/bpf_trace.c

Purpose: implements the kernel tracing side of BPF: helper function bodies for tracing program types, verifier/prog ops for kprobe, tracepoint, raw tracepoint, tracing, writable raw tracepoint, and perf-event programs, perf-event attachment to trace events, raw tracepoint registration, multi-kprobe and multi-uprobe BPF links, session kfunc registration, and dynptr-based probe-read/copy helpers. It is the main bridge between BPF programs and ftrace, perf, tracepoints, kprobes, uprobes, BTF, modules, and security lockdown policy.

Important APIs and types: exported helper prototypes include `bpf_probe_read_user`, `bpf_probe_read_kernel`, string variants, `bpf_probe_write_user`, `bpf_trace_printk`, `bpf_trace_vprintk`, `bpf_seq_printf`, `bpf_seq_write`, `bpf_seq_printf_btf`, perf-event read/output helpers, `bpf_get_current_task`, `bpf_task_pt_regs`, signal helpers, `bpf_d_path`, `bpf_snprintf_btf`, `bpf_get_func_ip`, attach-cookie helpers, branch-record helpers, and function-argument helpers. Verifier/program operation tables include `kprobe_verifier_ops`, `tracepoint_verifier_ops`, `raw_tracepoint_verifier_ops`, `tracing_verifier_ops`, `raw_tracepoint_writable_verifier_ops`, and `perf_event_verifier_ops`. Link state is represented by `struct bpf_kprobe_multi_link`, `struct bpf_uprobe_multi_link`, per-run contexts for kprobe/uprobe/session execution, and `struct bpf_trace_module` for module-provided raw tracepoints.

Control flow: trace-event BPF execution starts at `trace_call_bpf()`, rejects recursive per-CPU BPF execution, then runs the trace event's RCU-protected program array. Helper dispatch flows through per-program-type `*_prog_func_proto()` switches that gate helpers by attach type, capability token, lockdown mode, sleepability, and config options. Perf-event attachment serializes on `bpf_event_mutex`, copies `tp_event->prog_array`, enforces `BPF_TRACE_MAX_PROGS`, records event cookies, and frees old arrays after RCU-safe replacement. Raw tracepoint lookup scans the built-in `__bpf_raw_tp` linker range and, with modules enabled, the notifier-maintained module list; registration validates maximum context and writable access before calling tracepoint registration. Multi-kprobe attach accepts either user addresses or symbol names, optionally sorts cookies with addresses, pins target modules, configures `fprobe` entry/exit callbacks, and settles a `BPF_LINK_TYPE_KPROBE_MULTI` link. Multi-uprobe attach resolves a user path, optional target pid, offsets, ref-counter offsets, and cookies, then registers `uprobe_consumer` handlers for a `BPF_LINK_TYPE_UPROBE_MULTI` link. Runtime callbacks set `current->bpf_ctx`, run the BPF program under the proper RCU flavor and migration/preemption rules, and expose entry IP, cookie, return/session state, and per-session data through helpers or kfuncs.

State and persistence: all state is kernel-lifetime or link-lifetime runtime state, not durable storage. Persistent-looking objects are BPF links, perf events, tracepoint program arrays, module references, path/task references for uprobes, per-CPU nesting buffers for perf output and raw tracepoint pt_regs, per-CPU signal irq_work, and workqueue state used to enable the `bpf_trace_printk` event. Memory-safety behavior is stateful through RCU, tasks-trace RCU for sleepable programs, module reference counts, `bpf_prog_active` recursion counters, and cleanup paths in link release/deallocation.

Dependencies and integration points: depends on BPF core/verifier/BTF APIs, perf events, tracepoints, ftrace/fprobe, kprobes, uprobes, module notifiers, kallsyms/ftrace symbol lookup, security lockdown, LSM sleepability checks, path/namei, signal delivery, seq_file, BPF iterators, network tracing helper prototypes, and arch support for pt_regs/ftrace regs. `bpf_trace.h` supplies the trace event used by `bpf_trace_printk`.

Risks and test signals: high-risk areas are recursion and nesting limits in NMI/IRQ contexts, RCU flavor mismatches for sleepable vs non-sleepable programs, user pointer copy/zeroing semantics, lockdown/capability helper exposure, stale module references for multi-kprobes, uprobe task/path lifetime, address/cookie sorting correctness, context write restrictions, and perf-event array replacement races. Test signals include BPF selftests for trace helpers, raw tracepoints, tracepoints, perf-event output/read, `bpf_trace_printk`, BTF snprintf/seq output, kprobe_multi/uprobe_multi links with cookies and returns, session programs/kfuncs, module unload while probes are attached, lockdown-denied helpers, recursion/missed counters, and 32-bit/config-disabled fallback builds returning `-EOPNOTSUPP`.
