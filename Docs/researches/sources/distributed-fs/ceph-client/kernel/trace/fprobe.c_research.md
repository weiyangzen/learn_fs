# sources/distributed-fs/ceph-client/kernel/trace/fprobe.c

Purpose: implements fprobe, a higher-level wrapper that registers function entry and optional return probes on top of ftrace and function graph tracing. It supports registration by filter glob, symbol list, or address list; tracks probes in RCU-safe hash tables; dispatches entry and exit callbacks; stores per-entry data on fgraph's shadow stack; and handles module unload cleanup.

Important APIs and types: public APIs are `fprobe_count_ips_from_filter()`, `register_fprobe()`, `register_fprobe_ips()`, `register_fprobe_syms()`, `fprobe_is_registered()`, `unregister_fprobe_async()`, and `unregister_fprobe()`. Core state includes `fprobe_table` keyed by `struct fprobe *`, `fprobe_ip_table` keyed by ftrace IP, `fprobe_mutex`, shared `fprobe_ftrace_ops` for entry-only probes, shared `fprobe_graph_ops` for probes with exit handlers, and counters/registered flags for each backend. `struct fprobe_hlist` and `struct fprobe_hlist_node` are the registered-node storage referenced by both hash tables.

Control flow: registration resolves target IPs from kallsyms/module kallsyms, symbol arrays, or caller-provided addresses, canonicalizes each address through `ftrace_location()`, validates `entry_data_size`, allocates `hlist_array`, installs ftrace filters, registers either ftrace entry ops or fgraph ops, and inserts nodes into both the per-fprobe and per-IP lookup tables. Entry-only probes use `fprobe_ftrace_entry()`: after ftrace recursion protection it RCU-walks all nodes for the IP and calls the entry handler unless the probe is disabled or has an exit handler. Return-capable probes use `fprobe_fgraph_entry()`: it precomputes required fgraph storage, reserves it, invokes entry handlers, and records headers plus optional entry data only for probes whose entry callback allowed the exit callback. `fprobe_return()` retrieves that fgraph data, verifies the fprobe is still registered and enabled, then calls each exit handler. Unregister removes nodes, updates ftrace filters only for IPs no longer used by a same-backend probe, unregisters shared backends when counters drop to zero, and frees node storage after RCU; synchronous unregister waits for a grace period.

State and persistence: registered probes are runtime kernel state owned by caller-provided `struct fprobe` plus allocated `hlist_array`. The IP table is RCU-readable from ftrace callback context while updates are mutex-protected. Return-probe per-invocation state is transient data encoded on fgraph's shadow stack with either an arch-specific one-word header or generic packed header. Module references are taken during filter matching and released after registration; module-going notifications remove nodes that point into the unloading module.

Dependencies and integration points: depends on ftrace filters and callbacks, function graph tracing, kallsyms and module kallsyms, kprobe busy tracking for callbacks shared with kprobes, rhashtable/rhltable, RCU, module notifiers, and arch optional fprobe header encoding. It is consumed by BPF multi-kprobe links in `bpf_trace.c` and by kernel users of `<linux/fprobe.h>`.

Risks and test signals: risks include RCU lifetime mistakes during unregister/module unload, stale ftrace filters when allocation of removal IP lists fails, mismatched ftrace vs fgraph backend counters, entry-data size/header overflow, recursion behavior when sharing handlers with kprobes, missed-counter accounting, duplicate IP handling, and races where a probe is unregistered between entry and return. Test signals include `lib/tests/test_fprobe.c`, BPF kprobe_multi selftests, registration by glob/symbol/IP, overlapping probes on the same IP with mixed entry-only and return handlers, module unload with active probes, async vs sync unregister, disabled probes, entry handlers that suppress exit callbacks, and config matrices without ftrace regs/args or without modules.
