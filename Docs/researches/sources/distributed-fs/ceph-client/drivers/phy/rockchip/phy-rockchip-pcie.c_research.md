# sources/distributed-fs/ceph-client/drivers/phy/rockchip/phy-rockchip-pcie.c

Purpose: this legacy Rockchip PCIe PHY driver supports the RK3399 PCIe PHY through GRF syscon registers. It exposes either one legacy PHY or up to four lane PHY instances, depending on `#phy-cells`, and coordinates shared reset/PLL state across those lane instances.

Important APIs, types, and functions: `struct rockchip_pcie_data` stores GRF offsets for config, status, and lane-off registers. `struct rockchip_pcie_phy` stores the syscon regmap, four `phy_pcie_instance` children, shared mutex, reset, ref clock, and two counters: `pwr_cnt` and `init_cnt`. `rockchip_pcie_phy_of_xlate()` maps optional phandle lane indexes to PHY instances. `phy_wr_cfg()` performs the three-step write-enable pulse into the PHY config interface. PHY operations are `.init`, `.exit`, `.power_on`, and `.power_off`.

Control flow: probe gets the parent syscon regmap, match data, reset named `phy`, and enabled `refclk`; reads `#phy-cells`; creates one or four PHY objects; attaches each instance index; then registers the provider. Init is shared: under `pcie_mutex`, the first init asserts the PHY reset and increments `init_cnt`; later inits are no-ops. Power-on clears lane idle for the requesting lane, increments `pwr_cnt`, deasserts reset only for the first active lane, selects `PHY_CFG_PLL_LOCK`, waits for `PHY_PLL_LOCKED`, writes clock-test and SCC configuration for 100 MHz output, waits for PLL output state, then waits for relock. Power-off idles the lane, decrements `pwr_cnt`, and asserts reset when the last lane powers off.

State and persistence behavior: state is in the shared `rockchip_pcie_phy` object and RK3399 GRF registers. The mutex serializes lane operations and protects counters. The counters implement shared-lifetime semantics, but `rockchip_pcie_phy_exit()` currently decrements `init_cnt` and returns without extra hardware changes once initialized, making reset/power state primarily governed by power-on/off. The enabled refclk is acquired with `devm_clk_get_enabled()` and remains enabled for the device lifetime.

Dependencies and integration points: this driver depends on the PHY framework, parent syscon node, reset framework, clock framework, and RK3399 GRF bit layout. Consumers may use legacy zero-cell phandles or lane-indexed phandles. It integrates with PCIe host/controller code through generic PHY power sequencing, not through a Rockchip-specific exported API.

Risks: counter underflow is possible if consumers call power-off/exit without balanced calls; there is no explicit guard against negative `pwr_cnt` or `init_cnt`. Power-off idles a lane before confirming the shared reset assert succeeds; on assert failure it attempts to restore lane state and counter but only for the current lane. PLL polling timeouts are large but fixed and can mask board-level clock or power issues. The `#phy-cells` interpretation is unusual: a nonzero value means four PHYs, not the literal number of cells. The lane idle write uses shifted write-mask data; mistakes in bit placement would affect adjacent lanes.

Test signals: validate single-PHY legacy and four-lane DT configurations, lane-index phandle rejection for indexes >= 4, balanced multi-lane power sequencing, reset failure injection, PLL lock and output timeout logs, and PCIe link training after repeated suspend-like power cycles. Runtime traces around `pwr_cnt` are useful when multiple PCIe consumers share the PHY.
