# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_bin_error.c

Purpose: validates `.bin` parser error handling for `cs_dsp` while preserving one positive behavior: unknown block types are skipped and later valid payload blocks still load. It focuses on malformed WMDR/bin headers, truncated files, invalid core versions, truncated blocks, and impossible block payload lengths.

Important APIs/types/functions: `struct cs_dsp_test_local` stores the bin builder, XM header, WMFW builder, generated WMFW firmware, and WMFW version. `struct cs_dsp_bin_test_param` parameterizes block type for block-level corruption tests. `cs_dsp_bin_err_test_mock_algs` defines the single mock algorithm needed by the generated XM header. Main cases are `bin_load_with_unknown_blocks()`, `bin_err_wrong_magic()`, `bin_err_too_short_for_header()`, `bin_err_bad_header_length()`, `bin_err_bad_core_type()`, `bin_too_short_for_block_header()`, `bin_too_short_for_block_payload()`, and `bin_block_payload_len_garbage()`.

Control flow: common init allocates the fixture, registers a KUnit device, initializes the mock regmap, creates a mock XM header and places its data block in a mock WMFW, creates a bin builder tied to the XM header firmware version, initializes ADSP2 or Halo `cs_dsp`, and suppresses production error logging through a static stub. Most negative tests first sanity-check that `cs_dsp_power_up()` succeeds with the WMFW alone, power the DSP down, mutate the generated bin firmware, and then require `cs_dsp_power_up()` with the bad bin to return a negative error. Truncation tests repeatedly shrink `bin->size` to sweep all shorter lengths around the header or block boundary.

State and persistence behavior: all mutated firmware objects are KUnit-owned and intentionally modified in place, including `bin->data`, `bin->size`, `struct wmfw_coeff_hdr`, and `struct wmfw_coeff_item` fields. This file does not persist DSP runtime state beyond a single case; the DSP is powered down after the positive WMFW sanity load before corrupt bins are tried. The static message hook avoids excessive error logs unless `DEBUG` is enabled.

Dependencies and integration points: depends on KUnit, static stubs, firmware/regmap APIs, Cirrus mock WMFW/bin/XM-header builders, WMFW coefficient header/item layouts, and `cs_dsp_power_up()` parser behavior. The block-type parameter set includes normal metadata/info-like values shifted into coefficient block space, real memory block types (`WMFW_ADSP2_PM`, `WMFW_ADSP2_XM`), and illegal values such as `0x33`, `0xf500`, and `0xc000`.

Positive parser behavior: `bin_load_with_unknown_blocks()` prepends unknown raw blocks, then appends a YM payload for the mock algorithm. It expects power-up success and verifies that the valid payload is written to the YM base address. This test is the signal that unsupported block types are not fatal when the file still contains valid patch content.

Negative parser behavior: wrong magic tests corrupt each byte of the expected `WMDR` marker plus all-zero magic. Header length tests sweep lengths below the real header length, just above it, and extreme values including `0xffffffff`, `0x80000000`, and `0x7fffffff`. Core type tests reject zero, one, a mismatched type relative to `priv->dsp->type`, and `0xff`. Block truncation tests distinguish files too short for a block header from files too short for the declared payload. Garbage length tests overwrite `wmfw_coeff_item.len` with large positive and sign-bit values that must be rejected.

Risks: direct mutation of `struct firmware` size and data relies on the mock builder returning writable KUnit memory, which is valid here but not representative of real firmware storage. The test asserts only negative return for malformed bins, not a specific errno, so it detects rejection but not error classification regressions. Because logging is suppressed outside `DEBUG`, diagnostic coverage must come from KUnit failures rather than emitted parser messages.

Test signals: the registered suites are `cs_dsp_bin_err_halo`, `cs_dsp_bin_err_adsp2_32bit`, and `cs_dsp_bin_err_adsp2_16bit`, each marked `KUNIT_SPEED_SLOW`. Passing signals are successful WMFW-only sanity loads, success for unknown-block skipping with valid YM payload readback, and negative `cs_dsp_power_up()` results for every malformed header, core type, truncation, block type, and payload-length parameter.
