# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_callbacks.c

Purpose: verifies that `cs_dsp` invokes optional client callbacks at the right lifecycle points and safely handles empty or NULL callback tables. It covers coefficient-control add/remove callbacks, run/stop callbacks, and watchdog-expired callbacks for ADSP2v2 and Halo.

Important APIs/types/functions: `struct cs_dsp_test_local` records the mock WMFW builder, callback counters, passed coefficient-control pointers, and last passed DSP pointer. `struct cs_dsp_callbacks_test_param` parameterizes the client ops table. Callback implementations include `cs_dsp_test_control_add_callback()`, `cs_dsp_test_control_remove_callback()`, `cs_dsp_test_pre_run_callback()`, `cs_dsp_test_post_run_callback()`, `cs_dsp_test_pre_stop_callback()`, `cs_dsp_test_post_stop_callback()`, and `cs_dsp_test_watchdog_expired_callback()`. The full ops table is `cs_dsp_callback_test_client_ops`; `cs_dsp_callback_test_empty_client_ops` exercises an all-empty table.

Control flow: common init allocates fixture state, creates a dummy KUnit device, initializes the mock regmap, writes a mock XM header to the regmap, builds a WMFW with matching XM header data, assigns `dsp->client_ops` from the current parameter, initializes the DSP type, and registers `cs_dsp_remove()` cleanup. Runtime tests call `cs_dsp_power_up()`, `cs_dsp_run()`, `cs_dsp_stop()`, and `cs_dsp_remove()` and then inspect callback counters and captured pointers. Watchdog tests run the DSP, synthesize a watchdog condition, and call the ADSP2 or Halo watchdog/bus-error entry point.

State and persistence behavior: callback state is held in per-test counters and pointer arrays. Control callbacks store up to 16 `struct cs_dsp_coeff_ctl *` values so tests can compare callback order with `priv->dsp->ctl_list`. `passed_dsp` is reset between run/stop phases to verify that each callback supplies the active DSP pointer. Tests that explicitly call `cs_dsp_remove()` remove the registered KUnit cleanup action afterward to prevent double removal.

Dependencies and integration points: depends on KUnit, `kunit_get_current_test()` from callback context, KUnit device helpers, mock WMFW/XM-header builders, regmap, `cs_dsp` lifecycle APIs, and production interrupt helpers `cs_dsp_adsp2_bus_error()` and `cs_dsp_halo_wdt_expire()`. Coefficient control tests build WMFW algorithm-info blocks and coefficient descriptors using `cs_dsp_mock_wmfw_start_alg_info_block()`, `cs_dsp_mock_wmfw_add_coeff_desc()`, and `cs_dsp_mock_wmfw_end_alg_info_block()`.

Callback coverage: `cs_dsp_test_run_stop_callbacks()` verifies pre-run/post-run are called once per successful run and pre-stop/post-stop once per stop over two cycles. `cs_dsp_test_ctl_v1_callbacks()` creates ZM, YM, and XM controls for WMFW v1 and expects add/remove callbacks for each. `cs_dsp_test_ctl_v2_callbacks()` creates 16 short-named controls for WMFW v2/Halo and validates add/remove callback counts and order. `cs_dsp_test_no_callbacks()` runs power-up, run, stop, and remove with either an empty ops table or NULL ops and expects no counters to change. Watchdog tests verify callback dispatch when an ops table provides `watchdog_expired` and no dispatch when callbacks are absent.

Platform coverage: suites cover Halo with WMFW v3, ADSP2v2 32-bit with WMFW v2, ADSP2v1 32-bit with WMFW v2, ADSP2 16-bit with WMFW v1, ADSP2v2 watchdog handling, and Halo watchdog handling. ADSP2 watchdog synthesis writes `ADSP2_WDT_TIMEOUT_STS_MASK` to `base + ADSP2_LOCK_REGION_CTRL` before calling `cs_dsp_adsp2_bus_error()`. Halo watchdog synthesis calls `cs_dsp_halo_wdt_expire()` directly.

Risks: callbacks use `kunit_get_current_test()`, so these tests assume callbacks execute synchronously in the KUnit test context. The pointer-order checks depend on `ctl_list` traversal order and current control insertion behavior, making them useful regression signals but sensitive to intentional list-order refactors. The fixed `passed_ctl[16]` array matches the generated v2 control count; adding more controls without resizing would corrupt test-local state.

Test signals: registered suites are `cs_dsp_callbacks_halo`, `cs_dsp_callbacks_adsp2v2_32bit_wmfwv2`, `cs_dsp_callbacks_adsp2v1_32bit_wmfwv2`, `cs_dsp_callbacks_adsp2_16bit_wmfwv1`, `cs_dsp_watchdog_adsp2v2_32bit`, and `cs_dsp_watchdog_halo`. Passing signals include exact callback counts, correct DSP/control pointers, no callbacks for empty or NULL ops, successful lifecycle transitions, and one watchdog callback only when the client ops table supplies it.
