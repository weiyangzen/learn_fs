# sources/distributed-fs/ceph-client/drivers/firmware/cirrus/test/cs_dsp_test_bin.c

Purpose: validates normal `.bin` coefficient patch loading for `cs_dsp` across ADSP2 and Halo DSP address models. The file builds mock WMFW and WMDR/bin firmware, powers up a mock DSP, and verifies that coefficient patch blocks land in the expected cached regmap addresses without extra writes.

Important APIs/types/functions: the local fixture is `struct cs_dsp_test_local`, holding the mock bin builder, mock WMFW builder, and generated WMFW firmware. `struct bin_test_param` parameterizes memory type, word offset, algorithm index, and the patch-builder function. `bin_test_mock_algs` defines four mock algorithms used to exercise algorithm lookup. Core helpers include `_num_words_to_num_packed_regs()`, `cs_dsp_bin_test_common_init()`, the Halo/ADSP2 suite init functions, and KUnit parameter description functions. The test cases cover `bin_patch_one_word()`, `bin_patch_one_multiword()`, ordered and unordered multi-payload tests, sparse writes, multi-memory and multi-algorithm writes, many packed-memory boundary combinations, mixed packed/unpacked random writes, and `bin_patch_name_and_info()`.

Control flow: each case starts from a KUnit fixture whose init path allocates `struct cs_dsp_test`, registers a dummy KUnit device, initializes the mock regmap, writes a mock XM header into the regmap, creates a bin builder with a WMDR version, creates a minimal WMFW, initializes `cs_dsp` through `cs_dsp_adsp2_init()` or `cs_dsp_halo_init()`, and registers `cs_dsp_remove()` cleanup. Test bodies generate random payload data, compute the target algorithm base from the XM header, add one or more bin patch blocks through `cs_dsp_mock_bin_add_patch()` or `cs_dsp_mock_bin_add_patch_off32()`, convert the builder to a `struct firmware`, and call `cs_dsp_power_up()`. After load, they read back cached mock regmap content at computed addresses and compare it with expected payload bytes, then drop expected cache ranges and check `cs_dsp_mock_regmap_is_dirty()` to detect unexpected writes.

State and persistence behavior: all state is KUnit-scoped and memory-resident. The mock regmap is intentionally cache-only so test results are visible as cached writes. The XM header represents persistent DSP algorithm layout for the duration of one test. Random payloads make each run independent of fixed constants while equality checks preserve deterministic pass/fail behavior. Cleanup is registered with KUnit actions for device reference release and `cs_dsp_remove()`. The static stub for `cs_dsp_can_emit_message()` suppresses most logging unless built with `DEBUG`, which keeps the very large parameter matrix from flooding KUnit output.

Dependencies and integration points: depends on KUnit, KUnit devices/resources/static stubs, Linux firmware and regmap APIs, `cs_dsp` public and private headers, WMFW/WMDR format constants, and the Cirrus test utility builders from `cs_dsp_test_utils.h`. It integrates directly with the production load path through `cs_dsp_power_up()` and checks production address conversion through the mock memory-region helpers. It also exercises WMDR v1 and v3 behavior, including the v3 long-offset block builder.

Addressing coverage: the file explicitly distinguishes DSP-word offsets, regmap register addresses, unpacked register windows, and Halo packed register windows. ADSP2 suites cover 16-bit stride, 32-bit stride, and ZM availability. Halo suites cover unpacked XM/YM and packed XM/YM, including the packed conversion rule of three 32-bit registers for four DSP words. Packed tests verify aligned packed blocks, one/two/three trailing unpacked words, one/two/three leading unpacked words, contiguous and sparse packed blocks, unordered payload order, multiple algorithms, multiple memory regions, and mixed packed/unpacked offsets chosen by packed-boundary alignment.

Risks: because payloads are random, failures show up as equality mismatches but are not tied to stable fixture bytes for postmortem unless the failing KUnit log captures the values. The tests rely heavily on mock address helpers matching production assumptions; a shared bug in both helper and implementation could reduce detection. Cache cleanliness checks are a strong signal for unexpected writes, but each case must drop the correct expected ranges, so off-by-one errors in the test's drop range could either hide or falsely report dirty state. The long-offset cases intentionally use large offsets such as `0x10000` and `0x2f000`, so mock region sizing and address arithmetic must remain compatible.

Test signals: the registered suites are `cs_dsp_bin_halo`, `cs_dsp_bin_halo_wmdr_v3`, `cs_dsp_bin_adsp2_32bit`, and `cs_dsp_bin_adsp2_16bit`, all marked `KUNIT_SPEED_SLOW`. Passing signals include successful `cs_dsp_power_up()`, correct `regmap_raw_read()` values for every generated payload, clean mock regmap after expected writes and XM header cache entries are removed, correct handling of name/info blocks before patch data, and identical behavior for short and long offset patch encodings where applicable.
