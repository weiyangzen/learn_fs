# sources/distributed-fs/ceph-client/drivers/firmware/arm_scmi/pinctrl.c

Purpose: implements the SCMI Pinctrl protocol provider. It discovers counts of pins, groups, and functions, lazily fetches names and associations, exposes mux/config/request/free operations to SCMI pinctrl clients, and registers itself as `SCMI_PROTOCOL_PINCTRL`.

Important APIs/types/functions: command ids include attributes, list associations, settings get/configure, request/release, name get, and permissions. `struct scmi_pinctrl_info` stores counts and arrays of `scmi_group_info`, `scmi_function_info`, and `scmi_pin_info`. Groups cache name, present flag, pin list, and pin count; functions cache name, present flag, associated group list, and group count; pins cache name and present flag. The `pinctrl_proto_ops` table exposes count, name, group pins, function groups, mux set, settings get one/all, settings configure, pin request, and pin free.

Control flow: `scmi_pinctrl_protocol_init()` reads protocol attributes, rejects zero-pin firmware, allocates the pins/groups/functions arrays, and stores private state. Metadata is fetched lazily: group and function info functions call `PINCTRL_ATTRIBUTES`, allocate association arrays, then iterate `PINCTRL_LIST_ASSOCIATIONS` through the common iterator. Pin info fetches attributes only. Extended names are retrieved with `PINCTRL_NAME_GET` when the attribute flag advertises them.

Settings and request flow: `scmi_pinctrl_settings_get()` uses the iterator abstraction for either one config type or all configs, validating selector type and id before issuing `PINCTRL_SETTINGS_GET`. `scmi_pinctrl_settings_conf()` chunks configuration pairs according to the core max message size, sends repeated `PINCTRL_SETTINGS_CONFIGURE` commands, and stops on first error. `scmi_pinctrl_function_select()` configures a function on a group. `scmi_pinctrl_request_free()` wraps pin/group request and release commands and treats firmware `-EOPNOTSUPP` as success for optional request/release support.

State and persistence behavior: protocol counts and top-level arrays are devm-managed. Association arrays for lazily populated groups/functions are allocated with `kmalloc_array()` and freed explicitly in `scmi_pinctrl_protocol_deinit()`. Present flags prevent repeated metadata fetches. There is no persistent state outside current firmware pinctrl configuration changes made through SCMI commands.

Dependencies and integration points: depends on SCMI common xfer and iterator helpers, Linux bitfield helpers, and public pinctrl protocol types in `linux/scmi_protocol.h`. It does not register SCMI notification events. It is consumed by SCMI pinctrl client glue that maps generic pinctrl operations onto `scmi_pinctrl_proto_ops`.

Risks and test signals: lazy metadata population is not protected by a local mutex, so concurrent first access to the same group/function/pin could duplicate fetches or allocations depending on caller serialization. `settings_conf()` relies on max message size being large enough for at least one config pair; malformed small limits could stall progress. Tests should cover invalid selector/type combinations, zero-pin rejection, extended names, multi-part association iteration, settings get one/all, chunked settings configure, request/release optional support, deinit freeing only populated arrays, and concurrency expectations from the consuming pinctrl driver.
