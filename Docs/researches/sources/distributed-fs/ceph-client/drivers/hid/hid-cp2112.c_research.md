# sources/distributed-fs/ceph-client/drivers/hid/hid-cp2112.c

## Purpose
`hid-cp2112.c` is a HID transport driver for the Silicon Labs CP2112 USB-to-SMBus bridge. The chip exposes SMBus/I2C master operations and eight GPIO pins through raw HID feature and output reports, so the driver bridges one HID device into three Linux integration surfaces: an `i2c_adapter`, a sleeping `gpio_chip` with nested IRQ support, and programmable USB descriptor attributes in sysfs.

## Important APIs, Types, And Functions
The central state is `struct cp2112_device`, which owns the `i2c_adapter`, `hid_device`, wait queue, read/status response buffers, atomics used as response latches, GPIO chip, shared HID report buffer, mutex, GPIO polling work item, IRQ mask, and previous GPIO state. Report wire formats are modeled by packed structs such as `cp2112_smbus_config_report`, `cp2112_usb_config_report`, read/write request structs, `cp2112_xfer_status_report`, and `cp2112_string_report`.

GPIO operations are implemented by `cp2112_gpio_direction_input()`, `cp2112_gpio_direction_output()`, `cp2112_gpio_set_unlocked()`, `cp2112_gpio_set()`, `cp2112_gpio_get_all()`, and `cp2112_gpio_get()`. HID report helpers `cp2112_hid_get()` and `cp2112_hid_output()` isolate allocation-safe transfers because HID core may mutate supplied buffers. SMBus/I2C functionality is implemented through `cp2112_i2c_xfer()`, `cp2112_xfer()`, `cp2112_read_req()`, `cp2112_write_read_req()`, `cp2112_write_req()`, `cp2112_i2c_write_req()`, and `cp2112_i2c_write_read_req()`, all wired into `smbus_algorithm`. Device EEPROM/sysfs programming is generated by `CP2112_CONFIG_ATTR` and `CP2112_PSTR_ATTR`, with `chmod_sysfs_attrs()` exposing lock-byte state through file permissions. IRQ emulation uses `cp2112_gpio_irqchip`, `cp2112_gpio_poll_callback()`, and the startup/shutdown/mask/unmask hooks.

## Control Flow
`cp2112_probe()` allocates driver state and a 64-byte report buffer, initializes the mutex, parses the HID descriptor, starts HID with only hidraw connected, opens the hardware, powers it fully, reads version and SMBus config, sets retry time to one, then publishes the I2C adapter. It registers the GPIO chip with a nested IRQ chip, creates sysfs config files, applies lock-byte-based permissions, and returns the HID device to normal power. `cp2112_remove()` removes sysfs, unregisters I2C, cancels GPIO polling when active, removes the GPIO chip, closes HID, and stops HID.

I2C/SMBus transfers build an output report, raise HID power to `PM_HINT_FULLON`, send the report, poll transfer status up to `XFER_STATUS_RETRIES`, cancel on timeout, then read data chunks through forced read reports when needed. `cp2112_raw_event()` is the asynchronous completion path: transfer status responses are translated into Linux errors or byte counts, data responses are copied into `read_data`, atomics are set, and waiters are awakened.

GPIO reads/writes serialize through `dev->lock` around feature reports. GPIO IRQs are not hardware-interrupt-backed; enabling any GPIO IRQ starts a delayed work poll loop, compares current state with `gpio_prev_state`, and calls `handle_nested_irq()` when configured level or edge conditions match.

## State And Persistence
Runtime state lives in `cp2112_device`, including the shared HID buffer, pending read/status latches, GPIO IRQ mask, polling flag, and previous GPIO state. Sysfs writes can program CP2112 USB configuration fields and strings in device nonvolatile PROM; `chmod_sysfs_attrs()` reads `CP2112_LOCK_BYTE` and reflects one-time programmable lock status as read-only or writable sysfs permissions. The module parameter `gpio_push_pull` persists only for the loaded module and controls GPIO output mode bits used when directions are changed.

## Dependencies And Integration Points
The file depends on HID core/raw reports, hidraw minor naming, I2C core, GPIO and gpiolib IRQ helpers, debug logging through HID helpers, USB string encoding helpers, NLS UTF-8/UTF-16 conversion, and Linux power management hints. User-visible integration points are `/dev/hidraw*`, an I2C adapter named `CP2112 SMBus Bridge on hidrawN`, a `cp2112_gpio` GPIO controller, nested GPIO IRQs, and sysfs attributes for VID/PID/power/release/manufacturer/product/serial.

## Risks
The driver relies on strict report lengths; short positive HID results are converted to `-EIO` in most paths, but unexpected device behavior can still stall transfers until timeout. `cp2112_wait()` assumes only one matching response is in flight and acknowledges that a later response after timeout may race with state. GPIO IRQ support is polling-based with a hardcoded delay of 10 jiffies, so it can miss short pulses and adds periodic HID traffic. Sysfs programming touches nonvolatile, potentially one-time-programmable fields, and permissions are advisory because the device enforces locking. I2C support is limited: rev 1 hardware does not support repeated-start write-read, arbitrary multi-message I2C returns `-EOPNOTSUPP`, and block-length validation must remain exact to avoid protocol corruption.

## Test Signals
Useful test signals include successful probe logs with part number and device version, creation of the I2C adapter, `i2cdetect`/SMBus byte-word-block transactions against known slaves, GPIO direction/read/write through gpiod tools, edge/level IRQ delivery under controlled pin changes, sysfs readback after VID/PID/string writes on expendable hardware, timeout/cancel behavior with absent SMBus slaves, and disconnect tests during active GPIO polling or I2C transfers.
