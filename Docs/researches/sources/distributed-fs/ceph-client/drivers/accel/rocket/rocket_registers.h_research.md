# sources/distributed-fs/ceph-client/drivers/accel/rocket/rocket_registers.h Research

## Purpose
`rocket_registers.h` is an autogenerated hardware register ABI header for the Rocket accelerator driver. It was generated from Mesa `registers.xml` by `gen_header.py` and exposes MMIO register offsets, bit masks, shifts, and static inline value packers for programming accelerator blocks. The file contains no runtime logic, allocation, or persistence; its value is the exactness of the register map consumed by driver code that writes and reads the device.

## APIs, Types, And Register Families
The exported API is preprocessor symbols plus `static inline uint32_t FIELD(uint32_t val)` helpers. Each helper left-shifts a caller-supplied field value and masks it into the register bit range. Important register families are: `REG_PC_*` for version, interrupts, task control, and DMA base; `REG_CNA_*` for convolution/neural-array status, tensor dimensions, CBUF, conversion, padding, DMA, decompression, and clock gates; `REG_CORE_*` for core enable, MAC gating, output size, and truncation; `REG_DPU_*` and `REG_DPU_RDMA_RDMA_*` for post-processing, LUTs, output conversion, surfaces, and read DMA; `REG_PPU_*` and `REG_PPU_RDMA_RDMA_*` for pooling/post-processing and source DMA; `REG_DDMA_*` and `REG_SDMA_*` for DMA arbitration, QoS, AXI attributes, FIFO clear, and idle status; and `REG_GLOBAL_OPERATION_ENABLE` for global block enables.

## Control Flow
There is no executable control flow beyond inline field packing. Driver control flow will typically compose a 32-bit register value with helpers, write it to an offset with MMIO accessors, poll status registers such as `*_S_STATUS` or `*_CFG_STATUS`, and clear or mask interrupts using the PC interrupt registers.

## State And Persistence
The header itself has no state. It defines hardware state addresses. The persistent contract is source compatibility: register names, offsets, masks, and shifts must match the accelerator RTL and firmware expectations. Regeneration from changed XML can silently alter kernel driver behavior.

## Dependencies And Integration Points
The helpers require `uint32_t` to be visible before inclusion. Integration is with the Rocket accelerator driver, Linux MMIO helpers, interrupt handling, command submission, DMA setup, and any firmware or userspace ABI that assumes the same register layout.

## Risks
The helpers mask overflow rather than validating field ranges, so callers can truncate too-large values. Reserved-field helpers can encourage writing nonzero reserved bits. Because the file is generated, manual edits are high risk and likely to be lost. Register-map drift between XML, kernel driver, and hardware would cause difficult accelerator failures.

## Test Signals
Useful signals include compile coverage of all including translation units, MMIO trace comparison against known-good programming sequences, interrupt-mask/status tests, register readback tests where hardware supports it, and accelerator smoke tests exercising CNA, DPU, PPU, RDMA, and DMA paths.
