# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/gaudi/asic_reg/sif_rtr_ctrl_0_regs.h

## Purpose
`sif_rtr_ctrl_0_regs.h` is the autogenerated register-address map for SIF router controller instance 0. It exposes 438 symbols, with `mmSIF_RTR_CTRL_0_*` offsets from `0x306108` through `0x306CBC`. The register families mirror the common router-control prototype: security/privilege ranges, SRAM/HBM scrambling, rate limiting, E2E credit and counters, nonlinear SRAM/HBM routing, and RGL latency/token controls.

## Important APIs, types, and functions
- The public surface is the `mmSIF_RTR_CTRL_0_*` macro set.
- Security and privilege APIs include 16-entry AW/AR base and mask arrays and hit registers for secure and privileged windows.
- Initialization-facing controls include `SCRAM_SRAM_EN`, `SCRAM_HBM_EN`, `E2E_HBM_*`, and `E2E_PCI_*`.
- Telemetry and tuning symbols include AW/AR HBM/PCI counters, counter wrap/set controls, RGL expected-latency/token/bank registers, and rate-limit saturation/timeout/reset controls.
- Address translation symbols include nonlinear enable, SRAM/HBM offsets, SRAM bank selection, HBM selection, and HBM PC selection.

## Control flow
This header has no executable logic. During Gaudi initialization, SIF router 0 is programmed by scrambler setup and by `gaudi_init_e2e()`, which writes instance-specific E2E HBM/PCI sizes before enabling E2E. Security setup uses the SIF router 0 range macros in arrays that configure secure and privileged AW/AR windows. `gaudiP.h` also derives `SIF_RTR_CTRL_OFFSET` from SIF router block bases, so symmetric SIF layout is a driver assumption.

## State and persistence
The header owns no software state. Hardware state persists in SIF router 0 registers until reset or firmware/driver reprogramming. It includes protected range configuration, scrambler enablement, E2E sizing/enables, nonlinear routing tables, counters, and rate-limit status. Driver-level capability bits track only broader feature initialization, not each individual register.

## Dependencies and integration points
The file integrates through Gaudi generated register bundles, `gaudi.c`, `gaudi_security.c`, and `gaudiP.h`. `gaudi_blocks.h` lists `mmSIF_RTR_CTRL_0_BASE` as `0x7FFC306000ull`. The field encodings for shared router registers come from separate mask headers, while this file supplies only instance-0 addresses.

## Risks and edge cases
- SIF router instances are highly symmetric; one wrong instance prefix or base offset can program the wrong fabric path.
- Security ranges split by AW/AR and low/high base/mask halves require exact indexing.
- E2E tuning constants in `gaudi_init_e2e()` are instance-specific. Reusing another instance's values can reduce throughput or break credit behavior.
- Firmware security mode may own or skip programming, so direct register expectations vary by boot mode.
- The header cannot express register access semantics such as sticky counters or write-one-to-clear bits.

## Test signals
Positive signals include successful SIF0 HBM/PCI traffic, no secure/privileged range false positives, initialized scrambler and E2E paths, and expected traffic counters. Negative signals include access violations from SIF0 ranges, traffic stalls isolated to SIF0 paths, unexpected counter wrap/saturation, or reset/init logs pointing to router configuration errors.
