# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/gaudi/asic_reg/psoc_global_conf_regs.h

## Purpose
`psoc_global_conf_regs.h` is the autogenerated register-offset map for the Gaudi PSOC global configuration block. It exposes 521 macros, 520 of which are `mmPSOC_GLOBAL_CONF_*` register offsets from `0xC4B000` through `0xC4BCD4`. This block is a central driver/firmware control surface for boot sequencing, reset control, scratchpads, semaphores, CPU messaging, trace address context, interrupts, pad configuration, ADC, memory repair, and reset controller programming.

## Important APIs, types, and functions
- Boot and firmware registers include `NON_RST_FLOPS_*`, `PCI_FW_FSM`, `BOOT_SEQ_RE_START`, `BTM_FSM`, `SW_BTM_FSM`, `SW_BOOT_SEQ_FSM`, `BOOT_SEQ_TIMEOUT`, `SPI_MEM_EN`, `SPI_IMG_STS`, `BOOT_SEQ_FSM`, `BOOT_SEQ_EXT_LD`, and `BOOT_STATE`.
- Driver/firmware communication registers include `SCRATCHPAD_0..31`, `SEMAPHORE_0..31`, `CPU_BOOT_STATUS`, `KMD_MSG_TO_CPU`, and `SPL_SOURCE`.
- Trace and MMU context registers include `TRACE_ADDR`, `ARUSER`, `AWUSER`, `TRACE_AWUSER`, and `TRACE_ARUSER`.
- Reset registers include watchdog/manual/PRSTN/software-all/soft-reset config low/high registers, `SW_ALL_RST`, `SOFT_RST`, `UNIT_RST_N*`, `PRSTN_MASK`, `WD_MASK`, `RST_SRC`, and `RST_CTRL_*`.
- Peripheral/status groups include RAZWI/protection/ADC/timeout/peripheral/AXI error interrupts, target id, eMMC voltage, bootstrap pins, memory repair, outstanding transactions, pad 1.8 V/3.3 V config/input arrays, ADC timing/config, pad defaults, pad selection, and bank mode selection.

## Control flow
The header itself does not execute code. It is used heavily by Gaudi control paths. Firmware loading descriptors store `mmPSOC_GLOBAL_CONF_KMD_MSG_TO_CPU` and `mmPSOC_GLOBAL_CONF_CPU_BOOT_STATUS`. Hard reset setup writes reset configuration registers, sets `mmPSOC_GLOBAL_CONF_BOOT_SEQ_RE_START`, writes `mmPSOC_GLOBAL_CONF_SW_ALL_RST`, waits, then checks `mmPSOC_GLOBAL_CONF_BTM_FSM`. CoreSight ETR writes `mmPSOC_GLOBAL_CONF_TRACE_ADDR` alongside PSOC ETR DBA registers. MMU setup calls `gaudi_mmu_prepare_reg()` for `TRACE_ARUSER` and `TRACE_AWUSER`. `gaudi_reg_map.h` aliases scratchpads for polling registers such as `mmHW_STATE`.

## State and persistence
Hardware state in this block persists according to PSOC reset domains. Scratchpads and semaphores are shared state between host driver and firmware. Boot and reset fields can be latched across parts of initialization and reset. Trace address and ARUSER/AWUSER settings persist while debug capture or MMU context programming is active. Pad, ADC, and memory repair registers represent board/SoC configuration state and may be firmware-owned.

## Dependencies and integration points
This header is paired with `psoc_global_conf_masks.h` for bit encodings. It is included through generated Gaudi register bundles and integrated with `gaudi.c`, `gaudi_coresight.c`, `gaudi_reg_map.h`, boot interface structures, reset handling, firmware loader/static loader setup, MMU programming, and debug flushing via `mmHW_STATE`. The block base is listed in `gaudi_blocks.h` as `mmPSOC_GLOBAL_CONF_BASE` (`0x7FFCC4B000ull`).

## Risks and edge cases
- This is a high-blast-radius register map. Incorrect offsets can break boot, reset, debug tracing, interrupt handling, or firmware messaging.
- Some registers are shared with firmware; driver writes must respect ownership and sequencing.
- Scratchpad aliases in `gaudi_reg_map.h` depend on stable scratchpad numbering. Reassigning scratchpads can break polling or interrupt-control conventions.
- Reset-control registers are split into low/high halves and multiple reset classes. Writing the wrong half or wrong class can reset unintended hardware.
- Trace address state is split between global config and ETR registers, creating a cross-header consistency requirement.
- The header does not mark volatile, read-only, write-one-to-clear, or pulse semantics.

## Test signals
Positive signals include clean firmware load, CPU boot status updates, successful hard and soft resets, stable scratchpad polling, working debug trace capture, correct MMU trace ASID programming, and expected pad/ADC behavior if exercised. Negative signals include bootloader stalls, reset timeouts, unresponsive CPUCP messaging, unexpected RAZWI or AXI errors, broken `mmHW_STATE` flush behavior, or trace writes landing outside the selected buffer/context.
