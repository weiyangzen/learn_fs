# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/goya/asic_reg/psoc_emmc_pll_regs.h

Purpose: defines the PSOC eMMC PLL register map. The 41 macros cover PLL divider numerators/factors, output divider and feedback controls, lock/loss interrupts and bypass, reset/data-change triggers, divider factor command/busy registers, clock gating/relaxation, and frequency calibration thresholds.

Important APIs/types/functions: no executable API exists. The public contract is `mmPSOC_EMMC_PLL_*`, from `mmPSOC_EMMC_PLL_NR` at `0xC70100` to `mmPSOC_EMMC_PLL_FREQ_CALC_EN` at `0xC70440`.

Control flow: firmware or low-level driver code programs `NR/NF/OD/NB`, toggles data-change/reset controls, waits for lock/busy indicators, then enables dividers and clock gating. This file supplies addresses for that sequence but does not implement the sequence.

State and persistence: PLL programming is persistent hardware clock state. It affects eMMC and related PSOC clock domains until reset or reconfiguration.

Dependencies and integration: included by `goya_regs.h`. It shares the same autogenerated PLL prototype as `psoc_mme_pll_regs.h` and `psoc_pci_pll_regs.h`, so common PLL programming code can reuse offsets by namespace.

Risks: PLL misprogramming can destabilize a clock domain and block boot, flash, or firmware interactions. Busy and lock indications must be honored; changing divider factors while active can produce clock glitches.

Test signals: boot on hardware, eMMC access, PLL lock polling, clock-frequency measurement, and suspend/resume or warm-reset paths indicate whether these register definitions still match hardware.
