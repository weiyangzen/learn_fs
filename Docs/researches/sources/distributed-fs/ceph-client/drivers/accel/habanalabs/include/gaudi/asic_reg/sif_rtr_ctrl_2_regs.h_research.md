# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/gaudi/asic_reg/sif_rtr_ctrl_2_regs.h

## Purpose
`sif_rtr_ctrl_2_regs.h` is the autogenerated register-address map for SIF router controller instance 2. It provides 438 `mmSIF_RTR_CTRL_2_*` offsets from `0x326108` through `0x326CBC`. The map covers the standard Gaudi router-control prototype: security and privilege ranges, SRAM/HBM scramblers, E2E sizing/enables/counters, nonlinear routing configuration, RGL tuning, and rate-limit controls.

## Important APIs, types, and functions
- Public interface is the `mmSIF_RTR_CTRL_2_*` macro namespace.
- Security/privilege register groups provide AW/AR hit bits plus 16 indexed base and mask pairs for secure and privileged ranges.
- Initialization macros include `SCRAM_SRAM_EN`, `SCRAM_HBM_EN`, `E2E_HBM_WR_SIZE`, `E2E_HBM_RD_SIZE`, `E2E_PCI_WR_SIZE`, `E2E_PCI_RD_SIZE`, `E2E_HBM_EN`, and `E2E_PCI_EN`.
- Counter and rate-limit groups include HBM/PCI AW/AR counter count/wrap/set registers and `RL_*` controls for HBM, PCI, and SRAM.
- Nonlinear routing and RGL groups include `NON_LIN_EN`, SRAM/HBM offsets and selection registers, RGL config, tokens, bank ids, expected latency, shift, and watchdog.

## Control flow
No code executes in the header. Gaudi initialization consumes these symbols when enabling SIF2 scramblers and E2E behavior. In `gaudi_init_e2e()`, SIF2 is programmed with minimal HBM/PCI size values compared with some neighboring instances, then enabled. Security code includes SIF2 in the arrays used to program protected AW/AR windows across SIF routers.

## State and persistence
State is hardware-local to SIF router 2. Register contents persist until reset or reprogramming and include access windows, traffic counters, scrambler state, routing maps, and E2E/rate-limit settings. No C object in this header tracks those values; driver state reflects only coarse initialization and error status.

## Dependencies and integration points
The file is consumed through generated Gaudi register bundles by `gaudi.c` and `gaudi_security.c`. Its block base in `gaudi_blocks.h` is `mmSIF_RTR_CTRL_2_BASE` (`0x7FFC326000ull`). It shares field encodings with the IF router mask definitions and shares layout assumptions with the other SIF router instances.

## Risks and edge cases
- SIF2's E2E size constants in current driver code are notably small; accidental reuse for other instances or accidental change can affect fabric credit behavior.
- Security window programming depends on matching AW/AR arrays and 16-entry index order.
- Nonlinear routing registers can redirect traffic incorrectly if offsets, bank selection, or HBM selection are wrong.
- Raw generated macros cannot prevent writes while firmware owns the fabric configuration.
- Counter wrap behavior can hide high traffic or error bursts if tests only sample count registers.

## Test signals
Positive signals include clean probe/reset, valid SIF2 traffic under memory and PCI workloads, no unexpected range hit bits, and expected E2E/counter behavior. Negative signals include fabric stalls isolated to SIF2, data corruption after scrambler enablement, protected-range faults for valid accesses, or mismatched counter behavior versus sibling SIF instances.
