# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/gaudi/asic_reg/sif_rtr_ctrl_1_regs.h

## Purpose
`sif_rtr_ctrl_1_regs.h` is the autogenerated register-address map for SIF router controller instance 1. It exposes 438 `mmSIF_RTR_CTRL_1_*` register offsets from `0x316108` through `0x316CBC`. Like the other SIF router maps, it names registers for access control ranges, SRAM/HBM scrambling, E2E HBM/PCI programming, nonlinear routing, rate limiting, and counters.

## Important APIs, types, and functions
- Public macros are prefixed `mmSIF_RTR_CTRL_1_`.
- Range-control families include secure and privileged AW/AR hit, base-low/high, and mask-low/high registers.
- Fabric initialization controls include `SCRAM_SRAM_EN`, `SCRAM_HBM_EN`, `E2E_HBM_EN`, `E2E_PCI_EN`, and per-target read/write size registers.
- Counter/tuning groups include HBM/PCI AW/AR counter count/wrap/set registers, RGL token and expected-latency registers, and rate-limit status/reset/timeout registers.
- Nonlinear routing groups include SRAM and HBM offset/bank/select/PC-select registers.

## Control flow
The file contains no runtime code. Driver control flow reaches these definitions through initialization functions in `gaudi.c` and security setup in `gaudi_security.c`. `gaudi_init_e2e()` writes SIF1-specific HBM and PCI sizing constants before enabling E2E for the router. Scrambler initialization writes the SRAM and HBM scrambler enable registers if firmware/security conditions allow driver programming.

## State and persistence
The only state is hardware state addressed by the macros. It persists until reset or explicit reconfiguration and includes SIF1 security windows, scrambler bits, E2E credit settings, nonlinear routing configuration, counters, and rate-limiter values. Software observes the result through broader device capability state and traffic/error behavior rather than through a dedicated SIF1 software structure.

## Dependencies and integration points
The header integrates with generated Gaudi register includes, `gaudi.c`, `gaudi_security.c`, and block-base definitions. `gaudi_blocks.h` lists `mmSIF_RTR_CTRL_1_BASE` as `0x7FFC316000ull`; `gaudiP.h` uses the SIF0/SIF1 base delta as `SIF_RTR_CTRL_OFFSET`, making this file part of the symmetric SIF-router layout contract.

## Risks and edge cases
- If instance spacing or generated offsets drift, code that computes or assumes SIF router symmetry can misprogram subsequent instances.
- Directional security registers are easy to mix because AW and AR families are parallel.
- SIF1 E2E sizes differ from SIF0/SIF2/SIF3, so instance-specific constants matter.
- Hardware counters may wrap; consumers must use wrap/set controls correctly.
- Security firmware can make some direct writes inappropriate or redundant.

## Test signals
Positive signals include normal SIF1 memory/PCI traffic, clean security-window setup, expected E2E enablement, and no SIF1-specific protection errors. Negative signals include E2E throughput anomalies, AW/AR range hit bits during valid traffic, scrambler-related data errors, or only instance 1 diverging from sibling SIF routers.
