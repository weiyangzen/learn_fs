# sources/distributed-fs/ceph-client/drivers/accel/habanalabs/include/gaudi/asic_reg/psoc_etr_regs.h

## Purpose
`psoc_etr_regs.h` is the autogenerated register-address map for the PSOC Embedded Trace Router/Trace Buffer sink used by Gaudi CoreSight debug capture. It exposes 47 symbols, 46 of which are `mmPSOC_ETR_*` offsets from `0x2C43004` through `0x2C43FFC`. These names let `gaudi_coresight.c` configure trace buffer size, mode, AXI attributes, data buffer address, formatter state, lock/unlock, status, and device identity registers.

## Important APIs, types, and functions
- Capture buffer controls include `RSZ`, `MODE`, `BUFWM`, `DBALO`, `DBAHI`, `RWP`, `RWPHI`, `RRP`, `RRPHI`, and buffer level registers.
- Runtime control/status registers include `CTL`, `STS`, `FFSR`, `FFCR`, `PSCR`, and `AXICTL`.
- Integration-test and CoreSight management registers include `ITMISCOP0`, `ITTRFLIN`, `ITATBDATA0`, `ITATBCTR*`, `ITCTRL`, `CLAIMSET`, `CLAIMCLR`, `LAR`, `LSR`, and `AUTHSTATUS`.
- Identification symbols include `DEVID`, `DEVTYPE`, `PERIPHID0..7`, and `COMPID0..3`.

## Control flow
The header has no control flow, but its symbols are central to `gaudi_config_etr()` in `gaudi_coresight.c`. On enable, the driver unlocks the ETR through `LAR`, validates the user-provided trace buffer, writes the MSB in PSOC global config, programs `BUFWM`, `RSZ`, `MODE`, `AXICTL` when security permits, writes `DBALO/DBAHI`, sets `FFCR` and `PSCR`, and starts capture with `CTL`. On disable, it requests formatter flush/stop through `FFCR`, polls `FFCR` and `STS`, clears `CTL`, resets buffer registers, and optionally reads `RWP/RWPHI` plus the global trace MSB to return the current write pointer.

## State and persistence
No software state is stored in the header. ETR hardware state persists while debug mode is active: buffer base, size, write pointer, formatter state, AXI attributes, and capture enable. `gaudi_halt_coresight()` disables ETR when leaving debug mode. The ETR write pointer is observable state returned to userspace on disable when an output buffer is supplied.

## Dependencies and integration points
The header integrates with `gaudi_coresight.c`, CoreSight debug ioctl handling, the PSOC global config trace-address register, device memory validation, and common `WREG32()`/`RREG32()` accessors. The block base is listed in `gaudi_blocks.h` as `mmPSOC_ETR_BASE` (`0x7FFEC43000ull`). It is also mirrored by later ASIC support such as Gaudi2 CoreSight code, so symbol semantics are part of a broader HabanaLabs debug convention.

## Risks and edge cases
- ETR register sequencing is strict. Misordered `FFCR`, `STS`, and `CTL` operations can leave trace capture partially enabled or lose buffered data.
- Buffer address handling is split between ETR registers and `mmPSOC_GLOBAL_CONF_TRACE_ADDR`; both definitions must stay aligned.
- `AXICTL` programming differs under secure firmware, so default firmware attributes become part of the capture contract.
- Timeout polling depends on these exact status bit locations; wrong offsets can report success or failure against the wrong register.
- Buffer size and address validation lives in code, not this header, so raw macros can be misused by new consumers.

## Test signals
Positive signals include successful `HL_DEBUG_OP_ETR` enable/disable cycles, no CoreSight timeout logs, trace data written to SRAM/DRAM or host PMMU buffers, plausible returned write pointers, and clean ETR shutdown during debug-mode exit. Negative signals include timeout while waiting for `FFCR` or `STS`, invalid trace buffer behavior, zero or stale write pointers, and trace capture failures that are isolated to the PSOC ETR path.
