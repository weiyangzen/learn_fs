# sources/distributed-fs/ceph-client/drivers/iio/adc/palmas_gpadc.c

TI Palmas/TWL603x GPADC IIO driver exposing 16 PMIC ADC channels as voltage or temperature channels, with software-triggered conversions and two hardware auto-conversion threshold event slots. It supports platform data and device-tree current source settings, processed calibrated voltage output for most voltage channels, raw temperature-like channels, and wake-capable threshold IRQs.

Important state centers on `struct palmas_gpadc`: parent `struct palmas`, IRQs, current-source settings, calibration table, threshold state, two `struct palmas_adc_event` slots, completion, and mutex. `palmas_gpadc_info[]` stores ideal points and trim registers per channel. IIO entry points are `palmas_gpadc_read_raw`, event config/value callbacks, and the channel/event specs. Conversion helpers are `palmas_gpadc_enable`, `palmas_gpadc_read_prepare`, `palmas_gpadc_start_conversion`, and `palmas_gpadc_get_calibrated_code`; event programming is in `palmas_adc_configure_events` and `palmas_adc_reset_events`.

Probe obtains parent Palmas data, parses optional DT properties, requests the software EOC IRQ plus two auto-conversion IRQs, registers the IIO device, then calibrates trimmed channels by reading PMIC trim registers. Direct reads take `adc->lock`, enable realtime GPADC unless the channel is already freerunning, unmask EOC, start conversion, wait up to five seconds, bulk-read the 12-bit result, optionally calibrate it, and then mask/disable again. Auto IRQs disable auto conversion using the documented force/shutdown workaround and push IIO threshold events.

State is runtime-only: event slots, thresholds, calibration gains/offsets, and current source choices. Hardware GPADC registers are programmed per read or event update; suspend/resume only toggles wake on auto IRQs. Dependencies are the Palmas MFD register/IRQ APIs, IIO direct/event interfaces, platform IRQ layout, and DT bindings such as `ti,palmas-gpadc`.

Risks include the two-event-slot limit, fixed datasheet threshold tolerances, calibration fields left at defaults if trim reads fail, and the critical AUTO-mode hardware lockup workaround. Test signals should cover raw/processed reads, timeout behavior, event enable/disable, threshold updates, third event rejection, wakeup suspend/resume, and DT current-source boundary mapping.
