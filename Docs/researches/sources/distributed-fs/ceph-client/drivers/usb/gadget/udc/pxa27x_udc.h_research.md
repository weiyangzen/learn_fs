# Research: sources/distributed-fs/ceph-client/drivers/usb/gadget/udc/pxa27x_udc.h

Purpose: private hardware and data-model header for the PXA27x UDC gadget driver. It defines register offsets and bit fields, register access macros, endpoint definition macros, physical/logical endpoint structures, request structures, ep0 states, controller state, and logging helpers used by `pxa27x_udc.c`.

Important APIs, types, and symbols: register definitions cover global UDC registers (`UDCCR`, `UDCICR0/1`, `UDCISR0/1`, `UDCFNR`, `UDCOTGICR`, `UP2OCR`, `UP3OCR`) and per-endpoint registers (`UDCCSRn`, `UDCBCRn`, `UDCDRn`, `UDCCRn`). Bit masks define UDC enable/active/resume/OTG support, endpoint interrupt enable/status, control endpoint status, data endpoint status, endpoint configuration fields, write masks, frame/byte-count masks, and OTG/port control bits. Access macros `udc_readl`, `udc_writel`, `udc_ep_readl`, `udc_ep_writel`, `udc_ep_readb`, and `udc_ep_writeb` map structure state to raw MMIO. Endpoint macros build logical USB endpoints (`USB_EP_*`) and static physical PXA endpoints (`PXA_EP_*`) with config/interface/alt metadata.

Important structures: `struct udc_usb_ep` is the logical gadget-visible endpoint, containing `usb_ep`, a descriptor template, controller pointer, and cached matching `pxa_ep`. `struct pxa_ep` is a physical hardware endpoint with queue, spinlock, enabled/recursion flags, index/name, direction/address/config/interface/alternate/fifo/type fields, PM-saved registers, and stats. `struct pxa27x_request` wraps `usb_request`, records the logical endpoint, tracks whether it is already queued, and links into a physical endpoint queue. `struct pxa_udc` holds MMIO, IRQ, clock, gadget, driver, device, pullup mechanisms, PHY, ep0 state, stats, logical endpoint array, physical endpoint array, enable/pullup/VBUS/config/interface/alternate state, and PM save state. `to_pxa()` and `to_gadget_udc()` map gadget pointers back to the controller.

Control flow represented by the header: endpoint definition macros encode the static workaround for hardware that freezes endpoint configuration once enabled. Logical endpoints can map to different physical endpoints depending on `config`, `interface`, and `alternate`, and the C file's `find_pxa_ep` consumes exactly these fields. Ep0 state names are defined here for debug output and state-machine dispatch. Register access macros centralize address calculation from `ep->idx` and `dev->regs`.

State and persistence: no on-disk state. The header defines the complete in-memory controller state model and the static sizing constants `NR_USB_ENDPOINTS` and `NR_PXA_ENDPOINTS`. PM-only fields preserve endpoint control/status values across suspend. The `ep0_state_name` array is static debug state in the translation unit.

Dependencies and integration points: includes Linux types, spinlocks, I/O accessors, and USB OTG definitions; expects USB gadget/chapter 9 types and platform data to be visible where included. It integrates with the gadget core through embedded `usb_ep`/`usb_gadget`, with debugfs/logging through helper macros, and with PXA hardware through raw MMIO register definitions.

Risks: the static endpoint macro design is easy to extend incorrectly; config/interface/alt values must match real gadget descriptors or endpoint enable will fail at runtime. The header exposes many raw bit masks, so incorrect write-mask use can alter status bits or acknowledge interrupts. `struct udc_usb_ep` stores `struct pxa_udc *dev` in the code but the header declaration names `struct pxa_udc` only after a forward declaration typo-like mismatch with `struct pxa27x_udc`; build coverage is needed to catch type drift. `ep0_state_name` is a non-const static array in the header and would be duplicated if included by multiple C files.

Test signals: compile all configurations that include this header, especially PM and debug builds. Validate that generated endpoint CSR values from `PXA_EP_*` macros match hardware documentation, logical endpoint capabilities match descriptors, register access offsets match the PXA27x manual, and state-name indexing remains aligned with `enum ep0_state`.
