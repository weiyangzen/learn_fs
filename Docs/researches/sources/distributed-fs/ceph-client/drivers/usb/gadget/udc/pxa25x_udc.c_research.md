# Research: sources/distributed-fs/ceph-client/drivers/usb/gadget/udc/pxa25x_udc.c

Purpose: implements the platform USB gadget UDC driver for Intel PXA25x/PXA26x and similar IXP4xx full-speed USB device controllers. It virtualizes the fixed PXA endpoint hardware for Linux gadget drivers, handles ep0 control traffic, PIO-only data transfers, D+ pullup/VBUS decisions, suspend/resume/reset interrupts, debugfs reporting, and platform probe/remove/PM.

Important APIs, types, and functions: the companion header defines `struct pxa25x_udc`, `struct pxa25x_ep`, `struct pxa25x_request`, ep0 state, stats, endpoint constants, and debug macros. This C file defines MMIO register offsets and bit fields, static controller instance `memory`, gadget ops `pxa25x_udc_ops`, endpoint ops `pxa25x_ep_ops`, platform driver `udc_driver`, and chip revision handling. Endpoint API entry points include `pxa25x_ep_enable`, `pxa25x_ep_disable`, `pxa25x_ep_alloc_request`, `pxa25x_ep_free_request`, `pxa25x_ep_queue`, `pxa25x_ep_dequeue`, `pxa25x_ep_set_halt`, `pxa25x_ep_fifo_status`, and `pxa25x_ep_fifo_flush`. Device-level entry points include `pxa25x_udc_get_frame`, `pxa25x_udc_wakeup`, `pxa25x_udc_vbus_session`, `pxa25x_udc_pullup`, `pxa25x_udc_vbus_draw`, `pxa25x_udc_start`, and `pxa25x_udc_stop`.

Control flow: probe validates the XScale chip revision, maps registers, gets the UDC clock and platform data, requests the optional pullup GPIO, initializes the watchdog timer, disables hardware, reinitializes software endpoint lists, requests the UDC IRQ, creates optional debugfs, and registers the gadget UDC. Binding a gadget driver records `dev->driver`, enables logical pullup, and optionally registers with an OTG transceiver. Actual hardware visibility is controlled by `pullup()`, which enables the clock and UDC only when VBUS, gadget pullup, and non-suspended state all agree. `udc_enable` clears stale interrupt state, configures PXA255 `UDCCFR` when available or old PXA250 test-mode registers otherwise, unmasks reset/suspend/resume and ep0 interrupts, and asserts the board pullup. `udc_disable` masks interrupts, disconnects pullup, clears UDE, and marks speed unknown.

Endpoint and request flow: non-ep0 endpoints are statically described in `memory`; endpoint enable only validates descriptor type/address/maxpacket against fixed hardware, records `ep.desc`, resets software state, and flushes FIFO. Queued requests are PIO-only. IN transfers use `write_packet`/`write_fifo` to fill the FIFO until the request completes or the FIFO cannot accept more, then endpoint IRQs continue the transfer. OUT transfers use `read_fifo` to drain complete packets, detect short packets, record overflow, and complete requests. Isochronous requests are constrained to one packet. Completion uses `done`, temporarily marks the endpoint stopped around `usb_gadget_giveback_request`, and preserves prior status when already set.

Control endpoint flow: `handle_ep0` is the ep0 state machine for `EP0_IDLE`, `EP0_IN_DATA_PHASE`, `EP0_OUT_DATA_PHASE`, `EP0_END_XFER`, and `EP0_STALL`. It reads setup packets from `UDDR0`, handles PXA errata where RNE may be unreliable, records standard/config request flags, and forwards most requests to the gadget driver. Hardware automagic for SET_ADDRESS, SET_CONFIGURATION, and SET_INTERFACE is special-cased; configuration changes clear all non-control endpoint queues and, when `UDCCFR` exists, are acknowledged through `AREN|ACM`. Failed gadget setup results normally stall ep0 using `FST|FTF` and a watchdog that restalls if hardware clears stall bits. `ep0start` coordinates clearing setup/OUT bits and acknowledging the ep0 interrupt.

Interrupt and reset flow: `pxa25x_udc_irq` loops while it handles work. It acknowledges suspend/resume/reset bits from `UDCCR`, calls gadget suspend/resume callbacks when appropriate, resets or marks enumeration completion based on `UDA`, and services endpoint interrupt status from `USIR0/USIR1` masked by `UICR0/UICR1`. Ep0 is handled first to reduce protocol latency; other endpoint IRQs call `handle_ep`, then acknowledge the endpoint bit. `reset_gadget` and `stop_activity` stop all endpoints, nuke queued requests, delete the watchdog timer, notify gadget reset or disconnect, and reinitialize driver-visible endpoint structures.

State and persistence: state is in the singleton `memory`, hardware registers, endpoint queues, `gadget.speed`, `ep0state`, stats, flags such as `vbus`, `pullup`, `has_cfr`, `req_pending`, `req_std`, `req_config`, `suspended`, and `active`, plus platform pullup/transceiver pointers. No persistent storage exists. `CONFIG_USB_PXA25X_SMALL` reduces exported endpoint count from 16 to 3. PM suspend intentionally disconnects and disables the 48 MHz clock, then resume restores pullup policy.

Dependencies and integration points: depends on platform device resources, platform data `pxa2xx_udc_mach_info`, GPIO or board `udc_command` pullup control, optional USB PHY/OTG `otg_set_peripheral` and `usb_phy_set_power`, clocks, debugfs/seq_file, ARM/IXP register access and CPU revision checks, Linux USB gadget core, USB chapter 9 constants, and IRQ handling. The platform alias is `pxa25x-udc`.

Risks: the driver relies on many documented and observed PXA hardware quirks: SET_INTERFACE is effectively broken, hardware configuration automagic can race gadget setup, ep0 stall bits may need watchdog restalling, and some revisions lie about RNE. DMA is deliberately unused, so throughput is bounded by PIO and interrupt latency. Endpoint definitions are fixed; gadget drivers needing dynamic endpoint reconfiguration or non-default iso altsettings are poor fits. Request completion can run gadget callbacks with local IRQs disabled/restored rather than a normal spinlock discipline. The UDCCR helper call ordering should be reviewed carefully because writing mask/status registers incorrectly can acknowledge interrupts or write the wrong offset. Suspend behavior requires reliable software pullup control for hosts to see disconnect.

Test signals: build with full and `CONFIG_USB_PXA25X_SMALL` endpoint sets, PXA and IXP configurations, debugfs enabled/disabled, and PM enabled. Runtime tests should exercise platform probe chip-revision acceptance/rejection, GPIO and `udc_command` pullup paths, gadget bind/unbind, VBUS session changes, suspend/resume disconnect/reconnect, reset start/end, GET_DESCRIPTOR, SET_ADDRESS, SET_CONFIGURATION, SET_INTERFACE limitations, deferred ep0 IN/OUT requests, unsupported setup stalls and watchdog restall, bulk IN/OUT transfers across multiple packets, short packets, ZLPs, overflow on undersized OUT buffers, dequeue, halt behavior including inability to clear halt, FIFO status/flush, and disconnect/reset while queues are active.
