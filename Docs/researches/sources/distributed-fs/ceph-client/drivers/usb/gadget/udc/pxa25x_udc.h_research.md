# Research: sources/distributed-fs/ceph-client/drivers/usb/gadget/udc/pxa25x_udc.h

Purpose: private header for the PXA25x/IXP4xx full-speed UDC driver. It supplies PXA25x-specific register bit definitions not provided by common architecture headers, endpoint/request/controller data structures, ep0 state definitions, FIFO sizing constants, optional endpoint-count selection, global controller declaration, and debug/logging helpers used by `pxa25x_udc.c`.

Important APIs, types, and symbols: `struct pxa25x_ep` wraps `usb_ep` with a controller pointer, request queue, PIO IRQ count, fixed FIFO/address/attribute metadata, stopped and DMA-fixup flags, and register offsets for `UDCCS`, `UBCR`, and `UDDR`. `struct pxa25x_request` wraps `usb_request` with queue linkage. `enum ep0_state` defines `EP0_IDLE`, IN/OUT data phases, end-transfer, and stall. `struct udc_stats` tracks ep0 read/write ops and bytes plus IRQs. `struct pxa25x_udc` holds the gadget, bound gadget driver, ep0 state, stats, flags for VBUS/pullup/CFR/config/request/suspend/active state, watchdog timer, device/clock/platform data/USB PHY pointers, DMA mask, endpoint array, MMIO base, and IRQ numbers. `to_pxa25x()` maps a `usb_gadget` back to the controller.

Control flow represented by the header: the header has no independent runtime flow, but its structures shape every path in the C file. Endpoint queues are per `pxa25x_ep`; ep0 state constrains queue handling and interrupt dispatch; the controller flags decide when `pullup()` enables hardware; `start_watchdog(dev)` schedules the timer used to repair ep0 stall behavior. `PXA_UDC_NUM_ENDPOINTS` is either 3 under `CONFIG_USB_PXA25X_SMALL` or 16 otherwise, which changes both the endpoint array and interrupt-servicing range.

State and persistence: no persistence. The declared structures are the runtime state containers for the singleton controller. The header also declares `static struct pxa25x_udc *the_controller`, which is shared within the translation unit after inclusion and is used by pullup/debug helpers.

Dependencies and integration points: includes `linux/types.h` and expects `usb_ep`, `usb_gadget`, `usb_gadget_driver`, `timer_list`, `device`, `clk`, `pxa2xx_udc_mach_info`, `usb_phy`, and Linux list definitions to be visible from the C file include order. Register bit definitions such as `UFNRH_*` and `UDCCFR_*` integrate with the PXA/IXP MMIO layout defined in the C file. Debug helpers use `pr_debug`, `pr_err`, `pr_warn`, and `pr_info`.

Risks: because this is a private header included after many C-file definitions, it depends on include-order context rather than being self-sufficient. The `the_controller` definition in a header would be unsafe if included by more than one C file, though here it is private to the driver. Debug dump helpers directly read hardware registers and the global controller, so enabling DEBUG can add register access and log volume. Endpoint count changes under `CONFIG_USB_PXA25X_SMALL` alter ABI-visible gadget endpoint availability and interrupt loops.

Test signals: compile both small and normal endpoint configurations, DEBUG and non-DEBUG builds, PXA and IXP architecture selections, and W=1 style builds for include-order and unused-symbol warnings. Runtime validation should confirm debug dumps match real register state, endpoint arrays match the configured endpoint count, and watchdog scheduling works with the `timer` field.
