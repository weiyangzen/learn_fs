# Research: sources/distributed-fs/ceph-client/drivers/usb/gadget/udc/pch_udc.c

Purpose: implements the PCI USB device controller driver for Intel EG20T/PCH, Intel Quark X1000, and ROHM/LAPIS ML7213/ML7831 UDC hardware. It exposes the controller through the Linux USB gadget UDC framework, manages high/full-speed gadget operation, endpoint enable/disable, request queuing, DMA descriptor chains, ep0 setup/control handling, VBUS GPIO detection, PCI probe/remove/PM, and hardware interrupt dispatch.

Important APIs, types, and functions: `struct pch_udc_dev` is the device-wide state with `usb_gadget`, bound gadget driver, PCI device, endpoint array, global spinlock, stall/config/ZLP flags, DMA pools, ep0 setup data, MMIO base/BAR, current configuration tuple, and optional VBUS GPIO state. `struct pch_udc_ep` wraps `usb_ep` plus setup/data DMA descriptors, register offset, queue, endpoint number/direction, halted state, and cached endpoint status. `struct pch_udc_request` wraps `usb_request` with data descriptor chain pointers, queue linkage, DMA progress flags, and chain length. Gadget operations are `pch_udc_pcd_get_frame`, `pch_udc_pcd_wakeup`, `pch_udc_pcd_selfpowered`, `pch_udc_pcd_pullup`, `pch_udc_pcd_vbus_session`, `pch_udc_pcd_vbus_draw`, `pch_udc_start`, and `pch_udc_stop`. Endpoint operations are `pch_udc_pcd_ep_enable`, `pch_udc_pcd_ep_disable`, `pch_udc_alloc_request`, `pch_udc_free_request`, `pch_udc_pcd_queue`, `pch_udc_pcd_dequeue`, `pch_udc_pcd_set_halt`, `pch_udc_pcd_set_wedge`, and `pch_udc_pcd_fifo_flush`. Core hardware helpers cover CSR access, endpoint control/status, DMA enable bits, interrupt masks, NAK/stall/fifo handling, device init/exit, and disconnect/reconnect.

Control flow: PCI probe allocates `pch_udc_dev`, enables and maps the selected BAR, runs platform hooks for Quark or MinnowBoard GPIO lookup, initializes hardware and endpoint software state via `pch_udc_pcd_init`, enables MSI, requests the shared IRQ, initializes the spinlock and gadget ops, creates DMA pools/descriptors, sets the device disconnected, and registers the gadget UDC. `pch_udc_start` binds the gadget driver, enables ep0/device interrupts, and clears disconnect if VBUS is present or no VBUS IRQ exists. Endpoint enable validates descriptors, programs endpoint type/buffer/maxpacket and CSR endpoint mapping using the current config/interface/alt tuple, clears halt, and unmasks the endpoint interrupt. Queueing maps the request for DMA, builds a descriptor chain split on endpoint maxpacket, sets request state to `-EINPROGRESS`, immediately handles ZLPs, starts OUT DMA through `pch_udc_start_rxrequest`, or arms IN interrupts so a later IN token calls `pch_udc_start_next_txrequest`.

Control endpoint flow: reset/enum interrupts clear DMA, mask endpoint interrupts, clear endpoint CSRs/status, empty queues, report gadget reset, then `pch_udc_svc_enum_interrupt` sets the detected speed, activates ep0, enables ep0 interrupts, enables DMA, and marks ep0 OUT receive-ready. Control OUT setup interrupts copy `ep0out` setup DMA data into `dev->setup_data`, select `gadget.ep0` based on request direction, call gadget `setup` outside the spinlock via `pch_udc_gadget_setup`, then clear NAK or stall depending on the result. Hardware-generated set-configuration and set-interface interrupts synthesize USB control requests for the gadget driver, update `cfg_data`, clear stalls, set `set_cfg_not_acked`, and rely on a later ZLP path to set `CSR_DONE`.

State and persistence: there is no on-disk persistence. Runtime state is held in MMIO registers, endpoint request queues, DMA pools/descriptors, `cfg_data`, VBUS work items, and flags such as `stall`, `prot_stall`, `vbus_session`, `set_cfg_not_acked`, and `waiting_zlp_ack`. `gadget.speed` transitions from unknown to full/high/low at enumeration and back to unknown on reinit/reset/stop. Request buffers are DMA-mapped per queue operation and unmapped in `complete_req`. Endpoint descriptor chains are reused per request and extended/freed as needed. VBUS GPIO work polls for stable rise/fall before reconnect/disconnect actions.

Dependencies and integration points: depends on PCI core, MMIO accessors, DMA mapping and `dma_pool`, Linux USB gadget core, USB chapter 9 definitions, IRQ/MSI support, GPIO descriptor and lookup-table APIs, workqueues, PM ops, and board-specific PCI IDs. It registers `MODULE_DEVICE_TABLE(pci)` for Intel Quark, Intel EG20T, CircuitCo MinnowBoard, ROHM ML7213, and ROHM ML7831 devices. It integrates with gadget drivers through UDC registration and `usb_gadget_udc_reset`, with VBUS detection through optional GPIO, and with board glue through `driver_data` platform init callbacks.

Risks: DMA lifetime and pool ownership are sensitive. In remove, the ep0 OUT data descriptor allocated from `data_requests` is freed through `stp_requests`, which is a pool mismatch risk. In queue error paths after `usb_gadget_map_request`, a later `prepare_dma` failure does not visibly unmap the request before returning. `pch_udc_free_dma_chain` uses `phys_to_virt` on descriptor addresses stored in hardware descriptors, so assumptions about DMA/CPU address identity matter. `complete_req` drops `dev->lock` around gadget callbacks and mutates `ep->halted`, so request completion reentrancy must be considered. Several wait loops use fixed busy/udelay budgets and only log on timeout. VBUS work uses `mdelay` in workqueue context and calls gadget disconnect/reconnect paths outside the main IRQ path. Control-transfer acknowledgement depends on `set_cfg_not_acked` and `waiting_zlp_ack`; missed ZLP completion can leave hardware waiting for `CSR_DONE`. The `speed_fs` module parameter changes device speed at init only.

Test signals: build-test PCI gadget configurations with `CONFIG_USB_GADGET`, GPIO, MSI, and PM enabled. Runtime tests should cover probe/remove for each PCI ID path, Quark BAR selection, MinnowBoard GPIO lookup, optional/no VBUS GPIO, gadget bind/unbind, pullup and VBUS session toggles, high-speed and full-speed enumeration including `speed_fs=1`, ep0 standard/vendor/class requests, SET_CONFIGURATION and SET_INTERFACE ack paths, unsupported setup STALL, bulk/interrupt/iso endpoint enable validation, IN/OUT DMA transfers larger than one maxpacket, 64 KiB OUT transfer accounting, ZLP requests, dequeue during active DMA, set_halt/set_wedge, reset during active queues, suspend/resume interrupt masking, and remove after queued traffic has drained.
