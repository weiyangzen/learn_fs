# sources/distributed-fs/ceph-client/drivers/infiniband/core/device.c

## Purpose
This file is the central RDMA/InfiniBand core device registry and lifecycle implementation. It owns allocation, naming, registration, unregister fencing, client callback dispatch, net namespace exposure, compat devices, per-port metadata, netdev association, public query helpers, event dispatch, device-op composition, sub-device management, module initialization, and cleanup for the kernel RDMA core.

## Important APIs, Types, And Functions
Global registries are held in xarrays: `devices`, `clients`, and `rdma_nets`. Marks such as `DEVICE_REGISTERED`, `DEVICE_GID_UPDATES`, `CLIENT_REGISTERED`, and `CLIENT_DATA_REGISTERED` encode lifecycle visibility. Key exported lifecycle APIs are `_ib_alloc_device()`, `ib_dealloc_device()`, `ib_register_device()`, `ib_unregister_device()`, `ib_unregister_device_and_put()`, `ib_unregister_device_queued()`, `ib_unregister_driver()`, `ib_device_get_by_index()`, and `ib_device_put()`. Client APIs include `ib_register_client()`, `ib_unregister_client()`, `ib_set_client_data()`, `ib_get_client_nl_info()`, and event-handler registration/dispatch. Network and port APIs include `ib_query_port()`, `ib_device_set_netdev()`, `ib_device_get_netdev()`, `ib_device_get_by_netdev()`, `ib_enum_all_roce_netdevs()`, `ib_device_enable_gid_updates()`, `ib_query_pkey()`, `ib_modify_port()`, `ib_find_gid()`, `ib_find_pkey()`, and `ib_get_net_dev_by_params()`.

## Control Flow
Allocation initializes core driver-model state, xarrays, locks, completions, work items, CQ pool lists, cache lock, default uverbs command mask, and net namespace ownership. Registration assigns a unique name and index, validates provider ops, creates per-port immutable state, queries device attributes, sets up cache/sysfs/rdmacg/counters, adds the driver-model device with uevents suppressed, creates port attrs, marks the device registered, enables the provider, adds registered clients, creates compat devices, emits uevents/netlink notifications, and drops the temporary get. Unregistration removes sub-devices, clears registered visibility, removes clients in reverse order, cleans CQ pools, waits for references to drain, removes compat devices and netdev hashes, tears down device-model/sysfs/cache/cgroup state, and optionally deallocates provider resources.

## State And Persistence
All state is runtime kernel memory and driver-model/sysfs/netlink state. Device and client lifetimes are governed by reference counts, kobject references, xarray marks, and completions. Per-port state includes immutable attributes, security P_Key lists, GID cache data, netdev pointers, and netdev hash links. Synchronization is split across `devices_rwsem`, `clients_rwsem`, `client_data_rwsem`, `rdma_nets_rwsem`, `unregistration_lock`, `compat_devs_mutex`, `subdev_lock`, per-port `netdev_lock`, and `ndev_hash_lock`; RCU protects netdev hash lookup and delayed frees.

## Dependencies And Integration Points
This file integrates address resolution, MAD, SA, cache, counters, cgroups, security, nldev, RDMA netlink, RoCE GID management, sysfs, net namespaces, netdevice notifications, workqueues, xarrays, driver core, and provider `ib_device_ops`. Upper-layer clients such as uverbs, CM/CMA, MAD agents, SA query, and counters depend on the client callback and client-data contracts.

## Risks And Test Signals
Primary risks are lifecycle races between registration, unregistration, client registration, namespace moves, netdev unregister, and provider module unload. Mark semantics can expose half-registered objects if changed incorrectly. Netdev reference handling must balance legacy `get_netdev()` and `ib_device_set_netdev()` paths. Useful tests include provider probe/remove stress with concurrent client registration, async unregister plus `ib_unregister_driver()`, namespace moves, netdev attach/detach/rename/up/down events, RoCE GID update ordering, sysfs/nldev enumeration during unregister, LSM policy refresh, sub-device add/remove, and lockdep/KASAN/KCSAN coverage.
