# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/iowait.h

Purpose: declares the HFI1 I/O wait abstraction embedded in QP/PQ/IPoIB state to manage waits for SDMA ring space, PIO credits, queued transmit requests, workqueue restarts, drain synchronization, and fairness priority across the normal IB and TID RDMA send engines.

Important APIs and types: `struct iowait_work` wraps a work item, queued `sdma_txreq` list, and parent pointer for one send engine. `struct iowait` owns the waiter list node, sleep/wakeup/drained/priority callbacks, waitqueues, SDMA/PIO busy counters, queued descriptor/request counters, flags, priority/starvation fields, and two `iowait_work` entries (`IOWAIT_IB_SE`, `IOWAIT_TID_SE`). Public functions from `iowait.c` initialize, set/test/clear flags, cancel work, and set pending-work flags. Inline helpers schedule work, wait for drains, increment/decrement busy counters, wake drains, inspect tx heads/descriptors, update priority, queue overflow requests, clear starvation, test queued packets, account wait count, and convert between child and parent structures.

Control flow: transmit paths try to send immediately; on SDMA/PIO shortage they call `iowait_queue()` or callback-specific sleep paths to put the containing object on a wait list, append txreqs to the relevant send-engine list, increment descriptor/request counts, and set pending work. Resource-available paths call the waiter's `wakeup()` or schedule the relevant work item on a target CPU. Completion paths decrement SDMA/PIO busy counters and call `iowait_drain_wakeup()` when all pending work drains. Priority helpers let wait-list selection account for static priority plus starvation.

State and persistence: all state is memory-resident and embedded in a larger owner object. `sdma_busy` and `pio_busy` are atomics used by drain waitqueues. `count` tracks total queued descriptors; `tx_count` tracks queued tx entries; each `iowait_work.tx_head` holds prebuilt packets for that engine. `lock` records the seqlock protecting the wait-list head so destroy/unwait code can remove entries safely. Flags encode pending IB/TID work and any caller-defined wait bits.

Dependencies and integration points: depends on Linux list/workqueue/wait/sched primitives and `sdma_txreq.h`. It is used by verbs/TID RDMA/IPoIB transmit code that supplies callbacks and workqueue functions. The helper does not own the SDMA engine or QP; it is a coordination object between HFI1 send scheduling and upper-layer protocol state.

Risks: callbacks are documented as potentially invoked with locks held, so they must not sleep or submit txreqs directly if that would deadlock. `iowait_pio_drain()` uses a one-second timeout, unlike SDMA drain which waits indefinitely; callers must tolerate possible timeout return behavior hidden by the void helper. The descriptor accounting assumes every queued txreq eventually decrements through the same abstraction. Queueing with `pkts_sent` changes starvation behavior, so wrong values can reduce fairness. TID work may be absent and must be checked before cancellation/scheduling.

Test signals: compile coverage for all inline users, SDMA and PIO drain tests, wait-list removal under teardown, descriptor/count accounting under queue overflow, two-engine scheduling for IB and TID RDMA, starvation priority evolution, and lockdep coverage of sleep/wakeup callbacks.
