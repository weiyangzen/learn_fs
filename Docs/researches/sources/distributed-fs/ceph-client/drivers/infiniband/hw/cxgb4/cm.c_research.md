# sources/distributed-fs/ceph-client/drivers/infiniband/hw/cxgb4/cm.c

Purpose: Chelsio T4/T5/T6 iWARP connection manager. It bridges RDMA CM/IWCM operations to cxgb4 TCP offload CPLs and firmware work requests, manages active and passive connection setup, negotiates MPA v1/v2 attributes, binds endpoints to QPs, drives disconnect/abort state transitions, and defers interrupt/offload receive events to an ordered workqueue.

Important APIs, types, and functions: exported entry points are `c4iw_connect()`, `c4iw_create_listen()`, `c4iw_destroy_listen()`, `c4iw_accept_cr()`, `c4iw_reject_cr()`, `c4iw_ep_disconnect()`, `c4iw_ofld_send()`, `c4iw_cm_init()`, `c4iw_cm_term()`, and the global `c4iw_handlers[]` CPL dispatch table. Endpoint allocation and lifetime are handled by `alloc_ep()`, `c4iw_get_ep`/`c4iw_put_ep`, `_c4iw_free_ep()`, `release_ep_resources()`, and xarray mappings for `hwtids`, `atids`, and `stids`. Active-open flow is built by `c4iw_connect()`, `import_ep()`, `send_connect()`, `act_open_rpl()`, `act_establish()`, `send_flowc()`, and `send_mpa_req()`. Passive-open flow uses `c4iw_create_listen()`, `create_server4()`/`create_server6()`, `pass_accept_req()`, `accept_cr()`, `pass_establish()`, `process_mpa_request()`, `c4iw_accept_cr()`, and `send_mpa_reply()`. MPA handling lives in `process_mpa_reply()`, `process_mpa_request()`, `send_mpa_reject()`, and IWCM upcall helpers. Teardown uses `peer_close()`, `peer_abort_intr()`, `peer_abort()`, `abort_rpl()`, `close_con_rpl()`, `terminate()`, `read_tcb()`/`read_tcb_rpl()`, and `complete_cached_srq_buffers()`.

Control flow: hardware and firmware CPLs enter through `c4iw_handlers[]`; most are queued by `sched()` into `rxq` and processed by `process_work()` under an ordered workqueue so endpoint freeing and upper-layer callbacks happen in sleepable context. Active connects allocate an endpoint, copy IWCM addresses/private data, reference the CM ID and QP, allocate an ATID, find an IPv4/IPv6 route, acquire an L2T entry, choose queues/window/MSS, send a CPL active-open request, handle `CPL_ACT_ESTABLISH`, send FLOWC, then transmit the MPA request. MPA reply data is accumulated across `CPL_RX_DATA` packets; once a full valid reply is available, the QP is modified to RTS with negotiated ORD/IRD and MPA attributes, and IWCM gets a connect-reply upcall. Passive listens allocate an STID/SFTID and install a server or filter; SYN/offload events allocate a child endpoint, route it, respond with pass-accept, wait for `CPL_PASS_ESTABLISH`, accumulate the MPA request, then deliver an IWCM connect-request upcall. ULP accept binds the QP, sends MPA reply, enters FPDU mode, and delivers established; reject sends MPA reject or aborts.

State and persistence: all state is runtime-only. Persistent-looking data is held in endpoint structures and cxgb4 hardware TID/L2T/CLIP/server-filter tables until released. `struct c4iw_ep_common` stores CM ID, QP, device, state, mutex, kref, address pair, flags, history, preallocated skb list, and `wr_waitp`. `struct c4iw_ep` adds ATID/HWTID, TCP sequence/window parameters, route, L2T, MPA packet accumulation buffer, ORD/IRD, retry flags, timer, and SRQ abort cleanup fields. State transitions cover `IDLE`, `LISTEN`, `CONNECTING`, `MPA_REQ_WAIT`, `MPA_REQ_SENT`, `MPA_REQ_RCVD`, `MPA_REP_SENT`, `FPDU_MODE`, `ABORTING`, `CLOSING`, `MORIBUND`, and `DEAD`. Timers take an endpoint reference and enqueue timed-out endpoints to `timeout_list`.

Dependencies and integration points: integrates with RDMA IWCM, cxgb4 lower-layer driver, Linux route/neighbour/VLAN/IPv6 APIs, TCP option parsing, sk_buffs, timers, workqueues, xarrays, and local driver helpers in `iw_cxgb4.h`, `qp.c`, `cq.c`, and `ev.c`. Module parameters control MPA revision, CRC/markers, read depth, TCP options, ECN, delayed ACKs, windows, peer-to-peer RTR behavior, congestion handling, and endpoint timeout.

Risks: this file has high concurrency and lifetime risk because CPLs, timers, ARP callbacks, user accept/reject calls, and QP teardown all manipulate the same endpoints. The `ep->mpa_attr.crc_enabled = (mpa->flags & MPA_CRC) | crc_enabled ? 1 : 0` expression is precedence-sensitive and effectively enables CRC whenever the global `crc_enabled` is nonzero. MPA packet `plen` is stored in a `u8` even though MPA v2 private data size includes the v2 parameter block and can exceed 255, so boundary behavior depends on earlier `MPA_MAX_PRIVATE_DATA` checks. ARP failure paths synthesize fake CPLs to free endpoints in process context; missing references or skb ownership mistakes there can leak or double-free. Retry-with-MPA-v1 reuses the same endpoint and requires careful replenishment of the preallocated skb list. IPv6 CLIP get/release, ATID/HWTID xarray erase ordering, and TCB reread guard limits are important teardown edge cases.

Test signals: cover active IPv4 and IPv6 connect success, MPA v1 fallback from v2 reset, ORD/IRD negotiation including relaxed paths and insufficient-IRD TERM generation, private-data boundary and fragmented MPA headers, ARP failure on active open/accept/abort, TCAM full fallback to firmware offload connection WRs, connection-exists retry exhaustion, passive listen create/destroy with server and filter modes, peer close half-close transitions, peer abort with SRQ cached buffer completion, timeout while MPA request/reply is in flight, fatal-device disconnect behavior, and xarray/TID cleanup under rapid connect/disconnect stress.
