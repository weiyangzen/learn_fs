# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/ipoib.h

Purpose: defines HFI1 IP-over-InfiniBand netdev private structures and function prototypes. It connects RDMA netdev/IPoIB operations to HFI1 SDMA transmit queues, receive preparation, NAPI, and per-device queue state.

Important APIs and types: `union hfi1_ipoib_flow` packs transmit queue and 5-bit service-channel flow data. `struct ipoib_txreq` wraps an `sdma_txreq`, SDMA header/status/completion state, owning private data, tx queue, and skb. `struct hfi1_ipoib_circ_buf` is a cacheline-conscious circular buffer for completed/sent txreq accounting with stop/full/no-desc counters. `struct hfi1_ipoib_txq` owns a NAPI object, SDMA engine pointer, pending tx list, flow tracking, queue index, packet-sent flag, embedded `struct iowait`, and tx ring. `struct hfi1_ipoib_dev_priv` owns HFI1 device/netdev/IB device pointers, tx queues, original netdev ops, QP, Q_Key, PKEY/index, and port number. `struct hfi1_ipoib_rdma_netdev` embeds `struct rdma_netdev` first followed by HFI1 private data. Prototypes cover send, txreq init/deinit, rxq init/deinit, TX NAPI enable/disable, SKB preparation, RDMA netdev parameter reporting, and tx timeout handling.

Control flow: RDMA netdev allocation uses `hfi1_ipoib_rn_get_params()` to size/configure the netdev. The inline `hfi1_ipoib_priv()` converts from `net_device` private memory to HFI1 private state. TX setup allocates per-queue tx request/ring state, send paths build `ipoib_txreq` objects and submit them through SDMA/iowait, NAPI reaps completed txreqs from `hfi1_ipoib_circ_buf`, and RX paths convert HFI1 netdev receive queue data into SKBs via `hfi1_ipoib_prepare_skb()`.

State and persistence: per-netdev state persists in `hfi1_ipoib_dev_priv` for the netdev lifetime. Per-TX-queue state includes SDMA engine assignment, flow-change tracking, wait state, NAPI state, and circular completion ring indices/counters. Per-request state is held in `ipoib_txreq` until SDMA completion and NAPI cleanup. Q_Key/PKEY/port fields mirror RDMA/IPoIB addressing configuration.

Dependencies and integration points: includes Linux netdevice, skb, slab, list, if_infiniband, RDMA verbs, and HFI1 `hfi.h`, `iowait.h`, and `netdev.h`. It integrates with `ipoib_main.c`, `ipoib_tx.c`, `ipoib_rx.c`, HFI1 SDMA engines, RDMA core `rdma_netdev`, and netdev NAPI/timeout hooks.

Risks: `struct hfi1_ipoib_rdma_netdev` requires `struct rdma_netdev` to remain first for core casting. Ring head/tail and cacheline layout are performance-sensitive and must be updated with correct producer/consumer ordering. Flow packing uses a small union with a packed struct; users must preserve endian/layout expectations. The tx queue's embedded `iowait` inherits the locking/callback constraints documented in `iowait.h`. PKEY/Q_Key mismatches can produce network-level drops rather than local errors.

Test signals: IPoIB netdev creation/destruction, TX queue allocation and NAPI completion, SDMA descriptor shortage handling through iowait, tx timeout recovery, RX SKB preparation, multi-queue flow selection, PKEY/Q_Key configuration, and RDMA netdev parameter validation.
