# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/file_ops.c

Purpose: implements the user-space character device for HFI1 PSM contexts. It provides `/dev/hfi1_<unit>` file operations for context assignment, SDMA request submission, mmap token generation/validation, receive polling, expected receive TID ioctls, PKEY selection, context reset, and device node creation/removal.

Important APIs and functions: `hfi1_file_ops` wires `.open`, `.release`, `.write_iter`, `.unlocked_ioctl`, `.poll`, and `.mmap`. `hfi1_file_open()` allocates `struct hfi1_filedata`, initializes SRCU and locks, and takes `dd->user_refcount`. `hfi1_file_ioctl()` dispatches `HFI1_IOCTL_ASSIGN_CTXT`, context/base info, SDMA credit update, expected receive setup/free/invalidate, receive control, poll type, event ack, PKEY set, context reset, and user ABI version. `hfi1_write_iter()` submits user SDMA requests through `hfi1_user_sdma_process_request()`. `hfi1_file_mmap()` maps PIO buffers, PIO credit pages, receive header/eager buffers, user registers, event/status pages, receive tail, subcontext shared memory, and SDMA completion queues. `assign_ctxt()`, `allocate_ctxt()`, `find_sub_ctxt()`, `setup_base_ctxt()`, and `complete_subctxt()` implement user context allocation and sharing. `hfi1_set_uevent_bits()` broadcasts user event bits to active contexts. `hfi1_device_create()` and `hfi1_device_remove()` expose/remove the unit character device.

Control flow: open only validates device presence and prepares per-file state; the real hardware allocation is deferred until `HFI1_IOCTL_ASSIGN_CTXT`. Assignment validates the user ABI major version and subcontext count, serializes under `hfi1_mutex`, either attaches to a matching base context by UUID/J_KEY/subcontext metadata or allocates a new receive context, send context, CPU affinity, and shared-subcontext metadata. Base context setup initializes PIO, receive header queue, eager buffers, optional subcontext vmalloc areas, receive groups, user SDMA queues, expected receive state, and receive control bits. Subcontexts wait for `HFI1_CTXT_BASE_UNINIT` to clear, then allocate their per-file queues and expected receive state. Runtime operations then use ioctl, write, poll, and mmap against `fd->uctxt`; close drains SDMA, releases CPU affinity and expected receive state, clears event bits and subcontext membership, disables receive/send context state when the last subcontext exits, clears J_KEY/PKEY state, frees receive groups, and drops the context kref.

State and persistence: persistent per-open state is `struct hfi1_filedata`, including SRCU-protected SDMA packet queue, completion queue, context pointer, subcontext id, CPU affinity, expected receive pinning/accounting, and invalid TID array. Shared hardware/software state lives in `struct hfi1_ctxtdata`: receive header queue, eager buffers, send context, flags, J_KEY, UUID, subcontext bitmaps, event flags, and waitqueue. User-visible mmap cookies encode magic/type/context/subcontext/offset; mapped pages remain valid while the context exists. Device state affected here includes `dd->freectxts`, ASPM enable state, `hfi1_stats.sps_ctxts`, receive control CSR bits, context PKEY/J_KEY tables, and `dd->events` bitmaps.

Dependencies and integration points: depends on `hfi.h`, PIO/send-context helpers, receive context allocation from `init.c`, user SDMA (`user_sdma.h`), expected receive/TID logic (`user_exp_rcv.h`), MMU notifier/RB support, ASPM controls, RDMA user ABI structs, Linux `mmap`, `poll`, `iov_iter`, DMA coherent mapping, vmalloc fault handling, and cdev registration in `device.h`. It integrates with interrupt handling through `event_flags` and `handle_user_interrupt()`, with link events through `hfi1_set_uevent_bits()`, and with PCI removal through `dd->user_refcount`/`user_comp`.

Risks: ioctl size and ABI-version checks must stay exact or user libraries can corrupt kernel interpretation. mmap token validation prevents mapping another context's resources; any token or size mistake can expose device memory. Context sharing relies on serialized assignment plus bitmap updates under `uctxt_lock`; errors must clear bits and drop krefs. `ctxt_reset()` explicitly trusts user space to quiesce writers, so misuse can damage that context. Close ordering is critical because cleanup helpers use `fdata->uctxt` before it is nulled. Expected receive invalidation has multiple copy-to-user rollback paths that must not leak pinned pages or stale TIDs.

Test signals: open/close under concurrent users, assignment failures for bad ABI and exhausted contexts, shared subcontext attach/detach, mmap size/protection checks for every token type, SDMA write request queue saturation, poll wakeups for urgent and receive-available interrupts, link-down event bit delivery and ack, PKEY rejection/acceptance, context reset after halted/frozen send contexts, and remove waiting for `user_refcount` to drain.
