# sources/distributed-fs/ceph-client/drivers/infiniband/hw/hfi1/init.c

Purpose: owns HFI1 module initialization, PCI probe/remove/shutdown, device allocation/free, port initialization, receive context allocation, kernel context setup, workqueue creation, chip initialization/reinitialization, orderly shutdown, and receive buffer allocation. It is the lifecycle spine that turns a PCI function into a registered RDMA/HFI1 device with kernel/user receive contexts and device nodes.

Important APIs and functions: module parameters define user context count, kernel receive queues, receive array split, eager buffer size, receive header count, header entry size, and user credit threshold. Public functions include `hfi1_create_kctxts()`, `hfi1_create_ctxtdata()`, `hfi1_free_ctxt()`, `set_link_ipg()`, `hfi1_init_pportdata()`, `hfi1_init()`, `hfi1_lookup()`, `hfi1_free_ctxtdata()`, `hfi1_free_devdata()`, `hfi1_disable_after_error()`, `hfi1_create_rcvhdrq()`, and `hfi1_setup_eagerbufs()`. PCI/module functions include `hfi1_mod_init()`, `hfi1_mod_cleanup()`, `init_one()`, `remove_one()`, and `shutdown_one()`. Internal helpers manage context krefs, RCD array allocation, reset initialization, chip enablement, workqueues, timers, shutdown, ASIC-data release, and post-init cleanup.

Control flow: module init validates global parameters, initializes common device infrastructure, OPFN/debug support, and registers the PCI driver. Probe locks capabilities, validates PCI IDs and module parameters, allocates `hfi1_devdata` through `rvt_alloc_device()`, initializes PCI/chip-specific state, creates per-port workqueues, runs `hfi1_init()`, registers the IB device, creates debugfs and `/dev` nodes, and starts SDMA. `hfi1_init()` sets send handlers and A0 drop behavior, clears linkup state, performs reset/load-time setup, allocates kernel receive header/eager buffers and expected receive state, allocates user event/status pages, initializes MTU/status, enables kernel receive contexts and PIO, enables interrupts, initializes QSFP interrupts, and starts SerDes. Remove tears down in reverse: debugfs, cdev, wait for users, IB unregister, netdev RX free, hardware shutdown, workqueue/timer cleanup, postinit cleanup, and devdata free.

State and persistence: `hfi1_dev_table` xarray maps unit numbers to `hfi1_devdata`. `hfi1_devdata` persists for the PCI device lifetime and owns locks, counters, per-cpu counters, receive contexts, send contexts, SDMA state, status/event pages, and shared ASIC data. Receive contexts are kref-counted; `dd->rcd[]` is protected by `uctxt_lock` and entries are nulled in `hfi1_rcd_free()`. `hfi1_create_ctxtdata()` computes receive array bases, eager/expected TID counts, header queue geometry, NUMA placement, and kernel-context opcode stats. `hfi1_setup_eagerbufs()` allocates coherent eager buffers, may repartition to smaller TID sizes on allocation failure, programs RcvArray TIDs, and records thresholds/base/counts. Shutdown clears initialized flags/status bits, masks interrupts, flushes send contexts, disables receive/PIO, quiets SerDes, flushes workqueues, and exits SDMA without freeing all structures until cleanup.

Dependencies and integration points: depends on PCI, netdevice, vmalloc, xarray, module/param APIs, hrtimers, NUMA, RDMA VT allocation/registration, HFI1 device/common/chip/PIO/SDMA/MAD/debugfs/verbs/ASPM/affinity/expected-receive/netdev helpers. It integrates firmware/chip init through `hfi1_init_dd()`, PCIe helpers, MSI-X cleanup, IB registration, `/dev` creation in `file_ops.c`, user refcount waiting, and work items used by link/freeze/QSFP handlers.

Risks: probe has many staged resources; unwind ordering must match initialization or leave cdevs, IB devices, workqueues, IRQs, DMA buffers, or xarray entries live. `hfi1_init()` allocates user event/status pages even on some error paths to support diagnostics, so cleanup must handle partially initialized devices. Receive context krefs and `dd->rcd[]` updates must be correct under concurrent interrupts/user close. Eager buffer allocation dynamically halves/repartitions buffers; off-by-one or group-size mistakes corrupt TID programming. Shutdown uses hardware delays and flushes to let sends drain; insufficient ordering can race DMA/interrupt handlers. Module parameter validation protects hardware limits and interrupt mitigation from invalid combinations.

Test signals: module load/unload, PCI probe/remove/shutdown, failed-probe injection at each stage, reset/reinit, kernel context receive setup, user context allocation via `file_ops.c`, SDMA start/exit, cdev creation/removal, IB registration/unregistration, xarray lookup, workqueue flush/destroy, eager buffer allocation under memory pressure, context kref leak checks, and status/event page visibility to diagnostics after partial init failures.
