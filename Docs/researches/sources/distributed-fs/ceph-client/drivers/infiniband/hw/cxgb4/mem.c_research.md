# sources/distributed-fs/ceph-client/drivers/infiniband/hw/cxgb4/mem.c

Purpose: memory registration and STAG/TPT/PBL management for `iw_cxgb4`. It writes adapter memory through ULP TX work requests, programs TPT entries, writes PBLs, registers user and DMA memory regions, allocates fast-registration MRs, maps scatterlists to fast-reg page lists, deregisters MRs, and invalidates local MR state after remote/local invalidate completions.

Important APIs, types, and functions: exported verbs hooks are `c4iw_get_dma_mr()`, `c4iw_reg_user_mr()`, `c4iw_alloc_mr()`, `c4iw_map_mr_sg()`, `c4iw_dereg_mr()`, and `c4iw_invalidate_mr()`. Adapter-memory writers are `_c4iw_write_mem_dma_aligned()`, `_c4iw_write_mem_inline()`, `_c4iw_write_mem_dma()`, and `write_adapter_mem()`. Registration helpers are `write_tpt_entry()`, `write_pbl()`, `dereg_mem()`, `allocate_stag()`, `finish_mem_reg()`, `register_mem()`, `alloc_pbl()`, and `c4iw_set_page()`. Module parameters `use_dsgl` and `inline_threshold` select DSGL/DMA versus inline memory writes.

Control flow: TPT writes allocate or reset a STAG index, fill `fw_ri_tpte` fields for validity, key, state, type, PD, permissions, bind enable, address type, page size, PBL address, length, and VA/FBO, then write it into adapter STAG memory. User MR registration validates unsupported DMA handles, length wrap and hardware size limits, pins pages with `ib_umem_get()`, allocates PBL space, iterates DMA blocks into page-sized chunks of big-endian PBL entries, writes those PBL chunks to adapter memory, then writes a valid TPT entry and inserts the MR into the device `mrs` xarray. DMA MR registration creates an all-memory STAG with no PBL. Fast-reg MR allocation reserves coherent memory for the memory page list, allocates PBL space and an initially invalid STAG, and inserts the MR. Deregistration removes the MR from the xarray, frees coherent MPL memory, writes a reset TPT entry, frees PBL pool memory, releases umem and wait object, and frees the MR.

State and persistence: MR state is in `struct c4iw_mr`: RDMA core MR, optional `ib_umem`, driver device, deregistration skb, TPT attributes, coherent fast-reg MPL, DMA address, MPL lengths, and WR wait object. Hardware state persists in adapter TPT and PBL memory until deregistration resets the TPT entry and frees PBL pool space. A static atomic STAG key provides changing low-byte keys across allocations. Device stats track STAG usage in 32-byte TPT units.

Dependencies and integration points: depends on RDMA core memory APIs, DMA mapping/coherent allocation, Chelsio firmware/TPT/ULPTX structures, resource and PBL pools, `c4iw_ref_send_wait()` and `c4iw_ofld_send()` from CM/device glue, `c4iw_ib_to_tpt_access()` from the header, xarray MR table used by CQ/event invalidation and debugfs, and QP fast-register send paths outside this work item.

Risks: `_c4iw_write_mem_dma()` does pointer arithmetic on `void *data`, which is a GNU C extension and should stay within kernel build assumptions. `_c4iw_write_mem_dma_aligned()` allocates with `GFP_KERNEL | __GFP_NOFAIL` when no skb is supplied, so memory pressure behavior can be severe. `write_tpt_entry()` frees a STAG resource whenever `reset_tpt_entry` is set, regardless of whether the adapter write succeeded, which could desynchronize software and hardware on write failure. `c4iw_alloc_mr()` error path calls `dereg_mem()` with `mhp->dereg_skb`, but this allocation path never initializes `dereg_skb`, so reset writes may allocate internally only if downstream supports NULL skb safely; this deserves focused review. User registration uses a fixed `PAGE_SHIFT` instead of larger umem page sizes, potentially losing optimization.

Test signals: register and deregister DMA MR, zero-length-like and all-memory cases, user MR with invalid length/wrap/too-large T4/T5 range, multi-page PBL writes across page-sized chunks, DMA write fallback to inline when DSGL mapping fails, fast-reg MR allocation with maximum allowed SG count, scatterlist mapping overflow past `max_num_sg`, failed TPT/PBL write rollback, repeated STAG key reuse/invalidation, remote invalidate completion causing `c4iw_invalidate_mr()`, and fault injection for allocation, DMA mapping, firmware reply timeout, and xarray insertion failures.
