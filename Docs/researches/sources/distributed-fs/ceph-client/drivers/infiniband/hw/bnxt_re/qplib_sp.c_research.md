# sources/distributed-fs/ceph-client/drivers/infiniband/hw/bnxt_re/qplib_sp.c

Purpose: slow-path firmware command implementation for bnxt_re qplib. It translates RDMA driver operations into RCFW command queue messages for device discovery, function resource setup, SGID table programming, address-handle lifecycle, memory-region/window allocation and registration, fast-registration page-list allocation, RoCE statistics, extended statistics, congestion-control modification/query, context reads, and RoCE mirror flow enable/disable.

Important APIs, types, and functions: `bnxt_qplib_query_version()` sends `QUERY_VERSION` and stores four firmware version bytes in `bnxt_qplib_dev_attr`. `bnxt_qplib_get_dev_attr()` sends `QUERY_FUNC`, allocates a coherent side buffer, parses max QP/CQ/MR/MW/SRQ/GID/DPI/TQM/rate-limit values, caps or adjusts several fields by chip generation and WQE mode, and records atomic support from PCIe device control. `bnxt_qplib_set_func_resources()` programs per-function and per-VF QP/MRW/SRQ/CQ/GID resource limits from `struct bnxt_qplib_ctx`. SGID APIs `bnxt_qplib_get_sgid()`, `bnxt_qplib_add_sgid()`, and `bnxt_qplib_del_sgid()` manage software table entries and optionally send `ADD_GID`/`DELETE_GID` commands with VLAN, MAC, stats context, and firmware HW ID handling. `bnxt_qplib_create_ah()` and `bnxt_qplib_destroy_ah()` wrap `CREATE_AH`/`DESTROY_AH`. MRW APIs include `bnxt_qplib_alloc_mrw()`, `bnxt_qplib_free_mrw()`, `bnxt_qplib_reg_mr()`, and `bnxt_qplib_dereg_mrw()`, covering key allocation/deallocation, PBL HWQ allocation for user memory, unified-MR handling, access flags, VA/size, and cleanup on failure. `bnxt_qplib_alloc_fast_reg_page_list()` and `bnxt_qplib_free_fast_reg_page_list()` allocate/free page-list HWQs. Stats APIs `bnxt_qplib_get_roce_stats()` and `bnxt_qplib_qext_stat()` query base and extended counters through coherent side buffers. Congestion-control helpers `bnxt_qplib_fill_cc_gen1()`, `bnxt_qplib_modify_cc()`, `bnxt_qplib_read_cc_gen1()`, and `bnxt_qplib_query_cc_param()` map base and P5/P7 TLV-extended CC parameters. `bnxt_qplib_read_context()` reads arbitrary firmware contexts into caller memory. `bnxt_qplib_create_flow()` and `bnxt_qplib_destroy_flow()` toggle RoCE mirror configuration.

Control flow: every firmware operation prepares a command structure with `bnxt_qplib_rcfw_cmd_prep()`, fills a `bnxt_qplib_cmdqmsg` with request/response/optional side buffer metadata, and calls `bnxt_qplib_rcfw_send_message()`. Query operations allocate DMA-coherent side buffers, pass response size in command units, parse little-endian firmware fields, then always free the buffer on the exit path. SGID add scans for duplicates and the first zero GID slot, optionally programs firmware, then updates the software table, VLAN marker, active count, and returned software index. SGID delete scans for matching GID/VLAN, optionally deletes the firmware HW ID, zeroes the slot, clears VLAN state, decrements active count, and invalidates the HW ID. MR registration allocates or reuses an MR PBL HWQ when `num_pbls` is nonzero, builds level/page-size fields, sends the register command, updates unified keys when requested, and frees the HWQ on command failure. Congestion-control modification first builds the legacy command payload, then on P5/P7 wraps it in a primary TLV plus a Gen1 extension TLV and sends the larger request. Congestion-control query chooses legacy or TLV-extended response size by chip generation and merges high inactivity-threshold bits from the extension.

State and persistence: this file updates in-memory qplib resource state (`dattr`, SGID table contents, `hw_id`, VLAN markers, active count, MRW keys, MRW HWQ, CC parameter structs, RCFW out-of-sequence counter baseline). It allocates temporary DMA-coherent side buffers for firmware responses and frees them within each call. Firmware-visible state persists until explicitly removed: added GIDs, AH IDs, allocated keys, registered MRs, function resource limits, congestion-control settings, stats contexts, and RoCE mirror enablement. Base RoCE stats maintain `rcfw->oos_prev` and `rcfw->init_oos_stats` so `res_oos_drop_count` can be reported as a masked delta across calls.

Dependencies and integration points: depends on `roce_hsi.h` command/response formats, qplib RCFW message submission, qplib resource helpers, qplib TLV helpers, Linux DMA-coherent allocation, PCIe capability access, endian conversion helpers, and RDMA user memory passed into MR registration. Upper-layer call sites include `ib_verbs.c` for SGID/AH/MR/FRPL operations, `main.c` and `debugfs.c` for CC query/modify and context dumping, `qplib_rcfw.c` for RoCE mirror setup, and resource/context allocation code for function resources. Chip-generation helpers from `qplib_res.h` gate legacy versus P5/P7 behavior, P7 CQ sizing, P7 VF extended stats function-ID encoding, and TLV CC paths.

Risks: SGID add/delete contain comments asking whether a lock is needed; concurrent GID table updates could race active counts, duplicate detection, and slot reuse unless higher layers serialize calls. In `bnxt_qplib_add_sgid()`, duplicate detection compares `&sgid_tbl->tbl[i]` to `gid` for `sizeof(*gid)`, relying on `gid` being the first field of `struct bnxt_qplib_gid_info`; this is layout-sensitive. SGID add returns `-EALREADY` after setting `*index`, so callers must treat that as nonfatal where appropriate. `is_ugid` is accepted but unused, which may signal a stale API or missing behavior. MR registration frees any existing HWQ before re-registration and must be paired carefully with upper-layer state to avoid losing old mappings on partial failures. `bnxt_qplib_reg_mr()` initializes `pg_size` in both no-PBL and normal branches, then overwrites it with `buf_pg_size ? buf_pg_size : PAGE_SIZE`; this is intended but easy to misread when changing no-PBL behavior. Many commands accept a `block` parameter but most slow-path calls pass nonblocking zero; completion semantics depend on RCFW internals. Extended stats encode VF function IDs differently for P7 VFs, so fid validation is critical. RoCE mirror destroy zero-initializes the request then clears an already-zero enable bit, which relies on firmware interpreting zero flags as disable.

Test signals: mock or hardware-run RCFW command paths for success, timeout, and firmware error status; verify coherent side-buffer allocation failures return `-ENOMEM` and free all resources on later errors; test `QUERY_FUNC` parsing across legacy, P5, P7, PF, and VF devices; exercise SGID duplicate, full-table, invalid-HW-ID, VLAN/prio-tagged, and no-update paths; create/destroy AH with blocking and nonblocking calls; allocate/free PMR and MW type1/type2 keys; register/deregister MRs with zero PBLs, one-level, multi-level, unified-MR, and re-registration failure cases; validate FRPL limits above `MAX_PBL_LVL_1_PGS`; compare RoCE and extended stats against firmware counters, including out-of-sequence wrap; query/modify CC on legacy and P5/P7 TLV devices; read MRW/QPC/SRQ/CQ contexts from debug paths; and test RoCE mirror enable/disable only when capability flags advertise support.
