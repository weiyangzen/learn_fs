# sources/distributed-fs/ceph-client/drivers/power/supply/bq27xxx_battery.c

Purpose: provides the shared TI BQ27xxx fuel-gauge core for many battery monitor chips. Bus-specific adapters supply read/write callbacks, while this file maps chip variants to registers/properties, maintains cached capacity/status flags, exposes battery properties, optionally updates data-memory battery parameters from firmware battery info, and provides suspend/resume/polling support.

Important APIs/types/functions: `bq27xxx_chip_data[]` binds each `enum bq27xxx_chip` to register maps, data-memory register metadata, unseal key, options, and property arrays. Core exported entry points are `bq27xxx_battery_setup()`, `bq27xxx_battery_teardown()`, `bq27xxx_battery_update()`, and `bq27xxx_battery_battery_pm_ops`. Bus abstraction is through `di->bus.read`, `write`, `read_bulk`, and `write_bulk`. Data-memory helpers include `bq27xxx_battery_unseal()`, `bq27xxx_battery_read_dm_block()`, `bq27xxx_battery_update_dm_block()`, `bq27xxx_battery_write_dm_block()`, and `bq27xxx_battery_set_config()`. Property helpers convert SOC, current, voltage, temperature, time-to-empty/full, energy, health, capacity level, and design voltage/capacity.

Control flow: setup initializes delayed polling work and locks, assigns chip-specific register/property tables, registers a battery power supply, optionally applies `power_supply_battery_info` into supported gauge data memory, performs an initial update, and links the device into a global list used by the `poll_interval` module parameter. Updates read flags and SOC, derive status from signed current for non-BQ27000 devices, notify userspace when capacity/flags/status changed, cache the snapshot, and requeue polling when enabled. `get_property()` refreshes stale cache entries older than five seconds, rejects most properties when flags indicate a read failure, and dispatches to direct register reads or cached values. External power changes schedule a half-second delayed update. Teardown removes the device from the global list, marks it removed to prevent requeue, and cancels delayed work.

State and persistence: runtime state lives in each `bq27xxx_device_info`: register cache, last status, last update timestamp, cached design voltages/capacity, chip options, data-memory tables, delayed work, and removal flag. The global device list and `poll_interval` module parameter coordinate polling for all instances. Data-memory updates can persist to gauge RAM or NVM/flash depending on chip option and `dt_monitored_battery_updates_nvm`; the code explicitly warns and refuses flash/NVM updates when configured not to write them. Cache state is transient, while successful data-memory writes and optional reset/soft-reset affect the gauge.

Dependencies and integration: depends on power_supply core, device firmware battery info, delayed work on `system_percpu_wq`, jiffies, module parameters, and the bus-specific I2C/HDQ files through exported symbols. It includes `linux/power/bq27xxx_battery.h` for shared structures and chip IDs.

Risks and test signals: this file spans many chips with different register layouts and flag meanings, so variant coverage is essential. Data-memory writes unseal gauges, rely on checksums, avoid checksum verification for BQ27425 corruption risk, and can permanently update NVM if enabled. The driver caches some design values forever after first successful read. `get_property()` performs on-demand refresh under lock but then does direct register reads outside the lock for many properties, so bus removal and concurrent updates are relevant. Test with each bus adapter, representative legacy BQ27000 and modern BQ274xx/BQ27Z561 chips, missing registers (`INVALID_REG_ADDR`), bad flags reads, `poll_interval` changes, external-power-triggered updates, suspend/resume work cancellation, battery-info data-memory update allowed/refused paths, and health/status flag decoding.
