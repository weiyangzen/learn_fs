# sources/distributed-fs/ceph-client/drivers/power/supply/rt9455_charger.c

Purpose: implements the Richtek RT9455 charger over I2C, including register-field abstractions, charger property reporting, hardware reset/default programming, interrupt handling, optional USB PHY role notifications for boost/charge transitions, and delayed safety work for power-ready, max charging time, and battery presence.

Important APIs, types, and functions: `enum rt9455_fields` and `rt9455_reg_fields[]` define bitfield access across control, IRQ, and mask registers. `struct rt9455_info` stores regmap fields, power supply, optional USB PHY notifier, delayed work, and configured charge/boost voltages. Table helpers `rt9455_find_idx()`, `rt9455_get_field_val()`, and `rt9455_set_field_val()` map physical units to register selectors. `rt9455_hw_init()` resets the chip and programs termination, battery detection, safety-timer policy, charge current, EOC percentage, MIVR, IAICR, and voltage settings. IRQ helper functions decode three IRQ registers and decide whether to notify userspace.

Control flow: probe checks SMBus byte-data support, creates regmap and regmap fields, reads mandatory/optional firmware properties, optionally registers a USB PHY notifier, initializes deferrable work items, registers the charger power supply, requests the threaded IRQ, and applies hardware initialization. IRQ handling reads status, processes IRQ1/2/3 faults and warnings, may switch from boost to charge mode on boost faults, masks battery-absent IRQs and schedules presence polling, and calls `power_supply_changed()` if user-visible state changed. USB PHY events adjust IAICR and switch between charge and boost modes. Remove resets the chip, unregisters the USB notifier, and cancels work.

State and persistence behavior: configured `voreg` and `boost_voltage` persist in driver memory and PMIC registers. Delayed work tracks power-source and battery-presence safety policy. Register state is reset on probe and remove, so this driver intentionally reinitializes hardware rather than preserving prior firmware settings. No nonvolatile state is written.

Dependencies and integration points: depends on I2C, regmap with cache, regmap fields, power-supply, OF or ACPI properties, optional USB PHY notifier support, IRQ line, and system power-efficient workqueue. Firmware properties such as `richtek,output-charge-current`, `richtek,end-of-charge-percentage`, `richtek,battery-regulation-voltage`, and `richtek,boost-output-voltage` are mandatory.

Risks: the driver disables the hardware safety timer and replaces part of that protection with delayed work, so workqueue cancellation and long suspend/offline cases are safety-sensitive. IRQ register reads also clear or reflect latched fault state depending on hardware semantics, requiring real-device validation. The checked-out source includes several duplicated lines in comments and code, including a duplicated return and a duplicated `regmap_field_write()` line in USB ID handling. Property programming rounds to table entries; tests should confirm acceptable charge voltages/currents. Test signals include OF and ACPI probe, required-property rejection, register reset timeout, USB PHY events for NONE/VBUS/ID/CHARGER, IRQ fault injection for all three IRQ registers, battery-absent polling, max-charging-time cutoff, and remove-time reset/notifier cleanup.
