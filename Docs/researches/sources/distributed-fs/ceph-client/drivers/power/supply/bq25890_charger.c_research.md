# sources/distributed-fs/ceph-client/drivers/power/supply/bq25890_charger.c

Purpose: implements the Texas Instruments BQ25890/BQ25892/BQ25895/BQ25896 switch-mode charger as an I2C power-supply driver. It exposes charger status, limits, ADC-backed voltage/current/temperature values, charger enable/HiZ control, optional USB OTG VBUS regulator support, USB PHY ID notifications, and BQ25892 Pump Express high-voltage request handling.

Important APIs/types/functions: `struct bq25890_device` owns the I2C client, regmap fields, power supplies, optional USB PHY, work items, firmware-derived `bq25890_init_data`, cached `bq25890_state`, and the state mutex. `bq25890_reg_fields` maps bitfields to `regmap_field` handles; `bq25890_find_idx()` and `bq25890_find_val()` translate hardware table encodings. Power-supply operations are `bq25890_power_supply_get_property()`, `bq25890_power_supply_set_property()`, and `bq25890_power_supply_property_is_writeable()`. Runtime hardware paths include `bq25890_get_chip_state()`, `__bq25890_handle_irq()`, `bq25890_hw_init()`, `bq25890_pump_express_work()`, `bq25890_usb_work()`, and regulator ops for `usb_otg_vbus` and `vsys`.

Control flow: probe allocates device state, initializes regmap and fields, reads chip ID/revision, parses firmware properties, resets or enables charging, disables the watchdog, writes or reads initial limits, reads initial state, configures ADC conversion, obtains IRQ from the client or a named GPIO, registers optional regulators, registers a `bq25890-charger-%d` power supply, requests a threaded falling-edge IRQ, and optionally registers a USB PHY notifier. Property reads refresh state under `bq->lock`, compensate for lost interrupts by calling `__bq25890_handle_irq()`, and trigger a one-shot ADC conversion for offline/HiZ ADC properties. IRQ handling refreshes cached online/HiZ/status/fault bits, restores forced HiZ across cable replug, toggles continuous ADC conversion when online state changes, and emits `power_supply_changed()`. External power changes on BQ25892 derive input current from supplier USB type and may queue Pump Express work for DCP chargers. Remove unregisters USB notifications and optionally resets the chip; shutdown disables OTG boost unless the legacy USB PHY path is active.

State and persistence: runtime state lives in `bq25890_state`, `force_hiz`, regulator/USB work state, and the IDR-assigned name. Initial charge current/voltage, termination/precharge, boost, thermal, ILIM, compensation, Pump Express, secondary charger, and reset behavior are sourced from device properties. Register values are volatile hardware state; `force_hiz` is remembered only in memory and re-applied after cable replug. `linux,read-back-settings` turns firmware or bootloader-programmed register values into the driver's init cache instead of overwriting them.

Dependencies and integration: depends on I2C, regmap fields, GPIO descriptors for `bq25890_irq`, power_supply core, optional regulator framework, optional USB PHY notifier, firmware properties from OF/ACPI, and the system power-efficient workqueue. It can coordinate with a named secondary charger by driving its `POWER_SUPPLY_PROP_ONLINE` property during OTG boost and Pump Express.

Risks and test signals: ADC reads depend on conversion-rate transitions and one-shot polling; failures are mostly logged but can leave stale sysfs values. `bq25890_update_state()` invokes IRQ logic during property reads, so state locking and regmap side effects need coverage. Pump Express temporarily disables a secondary charger and must always clear `F_PUMPX_EN`; error paths currently do not re-enable the secondary charger. Firmware tables silently clamp values to nearest hardware encoding. Shutdown has a documented USB PHY compatibility exception that can leave boost enabled. Test with chip ID variants, DT/ACPI property combinations, IRQ loss, cable replug with forced HiZ, supplier USB type changes, Pump Express success/failure, regulator enable/disable, suspend/resume ADC behavior, and optional secondary charger probe deferral.
