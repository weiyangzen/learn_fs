# sources/distributed-fs/ceph-client/drivers/power/supply/rt5033_charger.c

Purpose: implements the Richtek RT5033 charger block as a USB power supply with optional extcon-driven mode switching. It initializes precharge, fast-charge, constant-voltage, and end-of-charge limits from battery information, reports charger state, and switches between charging, SDP/MIVR, OTG boost, and disconnected modes based on connector events.

Important APIs, types, and functions: `struct rt5033_charger` holds regmap, power supply, parsed charger limits, extcon state, notifier/work item, lock, online/OTG/MIVR flags, and cached constant-voltage register value. `rt5033_charger_dt_init()` reads battery info; `rt5033_init_pre_charge()`, `rt5033_init_fast_charge()`, `rt5033_init_const_charge()`, and `rt5033_charger_reg_init()` program charger registers. `rt5033_charger_set_otg()`, `rt5033_charger_unset_otg()`, `rt5033_charger_set_charging()`, `rt5033_charger_set_mivr()`, and `rt5033_charger_set_disconnect()` manage connector-dependent modes. `rt5033_charger_extcon_work()` serializes extcon state into hardware behavior.

Control flow: probe allocates and initializes state, obtains the parent RT5033 regmap, registers the power supply, reads battery information, initializes charging registers, then optionally finds a USB connector extcon parent. If extcon is present, it initializes autocancel work and registers a notifier for all extcon events. The work item scans extcon states, waits 100 ms for chip readiness, selects SDP/MIVR, charging, OTG, or disconnect behavior, and notifies the power supply.

State and persistence behavior: `online`, `otg`, and `mivr_enabled` are in-memory mirrors of connector mode; hardware registers hold actual operation mode, MIVR, charge limits, and CV. `cv_regval` is cached so OTG boost voltage can temporarily repurpose the CV bits and later restore the charge voltage. The driver has no nonvolatile storage.

Dependencies and integration points: depends on the RT5033 MFD/regmap, battery-info properties, `power_supply`, extcon, device tree phandle `richtek,usb-connector`, workqueue helpers, and mutex protection around mode transitions. It binds as platform device `rt5033-charger` or OF compatible `richtek,rt5033-charger`.

Risks: nested locking is risky: `rt5033_charger_set_charging()` holds `lock` and calls `rt5033_charger_unset_otg()`, which writes registers without taking the lock, while other paths call unset under the lock; behavior is intentional but fragile. `rt5033_charger_set_mivr()` calls `rt5033_charger_set_charging()` after releasing the lock, creating a small interleaving window. Extcon scanning assumes numeric connector order from `EXTCON_USB_HOST` through `EXTCON_CHG_USB_PD`. The checked-out source has duplicated lines in the precharge range check and charge-type getter. Test signals include battery-info boundary validation, CV restore after OTG, extcon transitions across SDP/DCP/host/disconnect, MIVR enable/disable, no-extcon probe path, and power-supply property reads after each mode.
