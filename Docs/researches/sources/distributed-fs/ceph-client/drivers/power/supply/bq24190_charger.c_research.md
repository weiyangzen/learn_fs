# sources/distributed-fs/ceph-client/drivers/power/supply/bq24190_charger.c

Purpose: implements a TI bq24190/bq24192/bq24192i/bq24193/bq24196/bq24296/bq24297 I2C charger driver. It exposes a USB charger power supply, an optional deprecated battery power supply, optional sysfs access to detailed register fields, optional VBUS regulator support, extcon USB OTG state, IRQ-based status/fault notifications, runtime PM, and suspend/resume reinitialization.

Important APIs/types/functions: `struct bq24190_dev_info` stores I2C, extcon, charger/battery power supplies, delayed input-current-limit work, cached model/configuration, fault/status registers, runtime flags, and the selected `struct bq24190_chip_info`. `struct bq24190_chip_info` selects chip-family operations for PN checking, charge-config bit layout, OTG VBUS control, NTC fault mask, and charge-current table size. Register helpers are `bq24190_read()`, `bq24190_write()`, `bq24190_read_mask()`, `bq24190_write_mask()`, `bq24190_get_field_val()`, and `bq24190_set_field_val()`. Major behavior lives in `bq24190_get_config()`, `bq24190_register_reset()`, `bq24190_set_config()`, `bq24190_hw_init()`, `bq24190_check_status()`, charger/battery property handlers, and PM callbacks.

Control flow: probe validates SMBus byte-data support, allocates state, selects chip info from I2C/OF match data, requires an IRQ, registers an extcon device, enables runtime PM, registers the charger and optional battery supplies, reads DT/battery configuration, resets the charger unless `disable-reset` is present, disables the watchdog to force host mode, applies system-minimum/precharge/termination/current/voltage configuration, reads initial system status, configures extcon OTG state, requests the IRQ, optionally registers a VBUS regulator, enables IRQ wake, and drops the runtime PM reference. IRQ handling resumes the device, calls `bq24190_check_status()`, then autosuspends. `bq24190_check_status()` reads system status and fault registers, retries once to clear latched faults, masks a disconnect-related voltage fault, compares cached fields to decide whether charger and/or battery changed, clears HIZ after power removal, updates extcon USB state, and emits `power_supply_changed()` notifications.

State and persistence: cached configuration comes from DT and `power_supply_battery_info`; runtime user writes change hardware registers directly but are not persisted in driver config. Suspend and remove call `bq24190_register_reset()`, and resume resets/reapplies only cached config, so runtime property writes can be lost across sleep. The fault register is guarded by `f_reg_lock`; status is cached in `ss_reg`. The watchdog value seen before host-mode disable is cached in `watchdog`, but the driver normally keeps the WDT disabled.

Dependencies and integration: integrates I2C SMBus, power-supply core, firmware properties, `power_supply_get_battery_info()`, supplier current-limit propagation through `external_power_changed`, extcon, runtime PM, wake IRQs, optional sysfs register-field attributes, optional regulator framework support for OTG VBUS, and OF/I2C match tables. The charger supply is marked as supplying `"main-battery"`; the optional battery class can be suppressed with `omit-battery-class`.

Risks and test signals: the driver requires `client->irq > 0`; boards without IRQ cannot use polling fallback. System suspend resets registers, which can surprise users relying on runtime-tuned limits. `bq24190_check_status()` deliberately rereads the fault register because faults may clear-on-read, so tests need to cover latched fault behavior. The bq24296 family uses different OTG/config/NTC bit layouts through chip-info hooks; wrong match data produces bad property reporting. Useful tests include all chip IDs, `disable-reset`, `omit-battery-class`, DT battery-info boundaries, supplier `CURRENT_MAX` delayed work, OTG regulator enable/disable, extcon transitions, runtime resume on wake IRQ, suspend/resume reconfiguration, and sysfs field read/write when `CONFIG_SYSFS` is enabled.
