## sources/distributed-fs/ceph-client/drivers/hwmon/dme1737.c

### Purpose

`dme1737.c` supports SMSC DME1737, Asus A8000, SMSC SCH5027, SCH311x, and SCH5127 hardware-monitoring blocks. It is a hybrid I2C/ISA driver exposing voltages, temperatures, fans, PWM controls, automatic fan-control zones, alarms, optional VID, and chip-specific optional channels.

### Important APIs, types, and functions

`struct dme1737_data` stores the bus access method, hwmon device, chip type/name, lock, cache timestamps, feature flags, nominal voltage table, config registers, and cached input/temp/fan/PWM/zone/alarm values. Conversion helpers cover voltage, temperature, fan RPM/TPC/type/max, PWM mode, auto-zone mapping, frequency, ramp rate, and hysteresis. I/O is abstracted by `dme1737_read()` and `dme1737_write()`. Runtime and sysfs logic centers on `dme1737_update_device()`, `show_in()`/`set_in()`, `show_temp()`/`set_temp()`, `show_zone()`/`set_zone()`, `show_fan()`/`set_fan()`, `show_pwm()`/`set_pwm()`, `dme1737_init_device()`, and `dme1737_create_files()`.

### Control flow

Module init registers the I2C driver, then probes Super-I/O config ports for ISA SCH311x/SCH5127 devices. I2C detection checks SMBus byte support, company ID, and revision/step. ISA detection enters Super-I/O config mode, validates device IDs, selects logical device A, and maps runtime access through base+0x70. Probe initializes chip state, creates dynamic sysfs groups according to `has_features`, and registers the hwmon device.

`dme1737_update_device()` refreshes Vbat roughly every ten minutes and most data every second. It reads voltage/temp MSBs before shared LSB registers for coherent values, skips absent optional features, reads alarms, and clears ISA alarm latches after capture. `dme1737_init_device()` validates monitoring/ready bits, optionally starts monitoring, determines optional features from config/Super-I/O/chip type, warns on nonstandard fan-to-PWM mappings, converts disabled PWMs to manual zero-duty mode on unlocked chips, and initializes default zone assignments.

### State and persistence behavior

The driver maintains a one-second cache and a ten-minute Vbat trigger. Thresholds, PWM settings, fan types, zone curves, and VRM persist in hardware or driver state after sysfs writes. `has_features` is fixed at probe and controls sysfs shape. PWM mode changes also mutate sysfs permissions; `pwm[1-3]` is writable only in manual mode on unlocked chips. ISA alarm reads clear hardware latches.

### Dependencies and integration points

Dependencies include I2C SMBus, platform devices/resources, raw I/O port access, ACPI resource conflict checks, hwmon sysfs helpers, `hwmon-vid`, mutexes, and Super-I/O conventions. It integrates with I2C class probing at `0x2c-0x2e` and platform devices for ISA runtime ports.

### Risks

The file combines two buses, raw port I/O, many chip variants, and dynamic sysfs permissions. Incorrect feature detection can expose nonexistent registers. Shared LSB read order is required for coherent values. Permission changes must track PWM mode and hardware lock state. `force_id` and Super-I/O probing can target the wrong hardware. Some low-level write failures are not propagated. ISA alarm clearing changes latch state.
