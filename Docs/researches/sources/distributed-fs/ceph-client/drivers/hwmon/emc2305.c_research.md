## sources/distributed-fs/ceph-client/drivers/hwmon/emc2305.c

### Purpose

`emc2305.c` supports Microchip EMC2301/2302/2303/2305 fan controllers. It exposes fan tachometer readings, fault bits, and PWM drive controls through hwmon, and can register thermal cooling devices that drive one common PWM state or separate per-channel states.

### Important APIs, types, and functions

`struct emc2305_data` stores the I2C client, hwmon device, cooling max state, channel count, output/polarity masks, common/separate mode, minimum PWM values, configured frequencies, and per-channel cooling state. Important functions are `emc2305_identify()`, `emc2305_show_fault()`, `emc2305_show_fan()`, `emc2305_show_pwm()`, `emc2305_set_pwm()`, `__emc2305_set_cur_state()`, `emc2305_set_cur_state()`, `emc2305_set_single_tz()`, `emc2305_set_tz()`, `emc2305_read()`, `emc2305_write()`, `emc2305_of_parse_pwm_child()`, and `emc2305_probe()`.

### Control flow

Probe requires SMBus byte/word support, validates vendor ID `0x5d`, identifies product ID to determine channel count, parses optional DT child nodes or platform data/defaults, registers hwmon, optionally registers thermal cooling devices, and writes output mode, polarity, and minimum drive registers. Hwmon reads perform direct I2C accesses. Hwmon PWM writes either set raw PWM or, with thermal support, update a low-limit state and only drive hardware if it is not below the last thermal state. Thermal writes clamp to max state and enforce the hwmon minimum.

### State and persistence behavior

PWM drive, minimum drive, polarity, and output mode persist in controller registers. Driver state tracks current cooling state and last hwmon/thermal requests but does not read them back from hardware after probe. In common mode, channel zero represents all fans.

### Dependencies and integration points

Dependencies include I2C SMBus, hwmon info API, thermal cooling devices, PWM polarity constants, OF parsing, platform data, and util macros. Integration points are hwmon fan/PWM attributes, thermal zone cooling bindings, I2C IDs for EMC2301/2/3/5, and OF compatible `"microchip,emc2305"`.

### Risks

Shared `cdev_data` has no mutex, so hwmon and thermal writes can race. The low-limit policy is subtle. DT child `reg` values are used for indexing and need bounds validation. Output configuration validation is permissive. Tach conversion depends on datasheet edge-count assumptions.

### Test signals

Test all product IDs, platform-data and DT paths, common versus separate PWM mode, thermal registration, hwmon low-limit behavior, PWM min bounds, tach/fault reads, malformed DT `reg`/`pwms`, and reprobe defaults.
