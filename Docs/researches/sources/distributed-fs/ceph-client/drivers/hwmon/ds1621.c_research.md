## sources/distributed-fs/ceph-client/drivers/hwmon/ds1621.c

### Purpose

`ds1621.c` supports Maxim/Dallas DS1621-family I2C temperature sensors and thermostats: DS1621, DS1625, DS1631, DS1721, and DS1731. It exposes current temperature, min/max thresholds, alarms, aggregate alarm bits, and for higher-resolution variants an adjustable conversion/update interval.

### Important APIs, types, and functions

`struct ds1621_data` contains the I2C client, cache lock, validity timestamp, chip kind, cached temperature registers, config, resolution zero-bit count, and update interval. `polarity` is a module parameter for thermostat output polarity. Key functions are `DS1621_TEMP_FROM_REG()`, `DS1621_TEMP_TO_REG()`, `ds1621_init_client()`, `ds1621_update_client()`, `temp_show()`, `temp_store()`, `alarms_show()`, `alarm_show()`, `update_interval_show()`, `update_interval_store()`, `ds1621_attribute_visible()`, and `ds1621_probe()`.

### Control flow

Probe allocates state, stores match-data chip kind, initializes continuous conversion, and registers hwmon groups. Init clears one-shot mode, optionally applies output polarity, computes update interval and resolution by chip kind, and starts conversion. Reads refresh when cache age exceeds `update_interval` or cache is invalid, reading config and three word-swapped temperature registers. Threshold writes convert millidegrees to the current register resolution. Update-interval writes choose a supported DS1721-style conversion rate and rewrite resolution bits.

### State and persistence behavior

Readings are cached for the conversion interval. Threshold, resolution, and polarity settings persist in chip registers. Alarm bits are latched in config and may be cleared by reads once the current temperature is back inside limits. `update_interval` is hidden for DS1621/DS1625.

### Dependencies and integration points

Dependencies are I2C SMBus byte/word-swapped accesses, hwmon sysfs helpers, jiffies, mutexes, and I2C ID match data. The I2C driver exposes `temp1_input`, `temp1_min`, `temp1_max`, alarms, `alarms`, and conditionally `update_interval`.

### Risks

Several init/refresh SMBus returns are not fully checked, so bus errors can become cached values. Resolution changes affect threshold encoding. Alarm-clearing logic compares raw values and must preserve family semantics. The module-level `polarity` parameter affects all devices.

### Test signals

Probe each supported ID, verify update-interval visibility by chip kind, threshold clamp/write/readback behavior, resolution changes, alarm set/clear behavior, continuous conversion start, and SMBus failure injection.
