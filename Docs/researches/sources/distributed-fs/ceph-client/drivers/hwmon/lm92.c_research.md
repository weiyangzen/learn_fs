# sources/distributed-fs/ceph-client/drivers/hwmon/lm92.c

## Purpose
`lm92.c` is a compact hwmon I2C driver for National LM92 and Maxim MAX6635 local temperature sensors. It exposes one temperature channel with input, min, max, critical threshold, hysteresis-derived threshold values, individual alarms, and aggregate chip alarms through the modern `hwmon_device_register_with_info` interface.

## APIs, Flow, State, And Risks
`struct lm92_data` stores the regmap and limit-register resolution, which differs between LM92 and MAX6635. `TEMP_FROM_REG`, `TEMP_TO_REG`, and `ALARMS_FROM_REG` translate the LM92 left-justified signed register format and alarm bits. The hwmon callbacks dispatch to `lm92_temp_read`, `lm92_temp_write`, and `lm92_chip_read`; visibility makes thresholds and critical hysteresis writable while input, derived hysteresis, and alarms are read-only.

Probe creates a custom regmap because config is an 8-bit SMBus byte while temperature registers are swapped 16-bit words, records match-data resolution, clears shutdown in config, and registers hwmon. Reads fetch one register, combine threshold plus common hysteresis with `regmap_multi_reg_read`, or read live temperature alarm bits. Writes update min, max, critical, or compute the shared hysteresis delta from the current critical limit.

Hardware persists config and thresholds; regmap caches non-volatile registers with live temperature volatile. Dependencies are I2C SMBus byte/word, regmap, hwmon, and I2C class scanning. Risks are mixed register width/endian handling, shared hysteresis semantics, no restore of previous config, and LM92-only auto-detection. Test signals are probe/init, detection aliases, hwmon reads/writes, and resolution-specific rounding for LM92 versus MAX6635.
