# sources/distributed-fs/ceph-client/drivers/hwmon/lm93.c

## Purpose
`lm93.c` is a legacy hwmon driver for National LM93/LM94 system hardware monitors. It exposes a large fixed sysfs attribute group for sixteen voltage inputs, three temperature zones with automatic fan-control parameters, four fans, two PWM outputs, VID, PROCHOT/VRDHOT status and override controls, GPIO state, and a compact 32-bit alarm view derived from wider hardware status.

## Important APIs, Types, And Functions
The driver uses `devm_hwmon_device_register_with_groups` with a manually declared `lm93_attrs` array rather than the newer `hwmon_chip_info` callback model. `struct lm93_data` is the central cache, organized around the chip's fixed block-read groups: alarm block, temperatures, VINs, PROCHOT, fan tach counts, limits, PWM control registers, auto-temperature base/offset registers, config, VID, GPIO, PROCHOT override/interval, boost and hysteresis registers, and saved PWM override duty values.

Conversion helpers encode the hardware units and bit layouts: `LM93_IN_FROM_REG`, `LM93_IN_TO_REG`, `LM93_IN_REL_FROM_REG`, `LM93_IN_REL_TO_REG`, `LM93_TEMP_FROM_REG`, `LM93_TEMP_TO_REG`, auto-offset helpers, PWM duty/frequency maps, `LM93_FAN_FROM_REG`, `LM93_FAN_TO_REG`, spinup/ramp/prochot interval conversions, `LM93_GPI_FROM_REG`, and `LM93_ALARMS_FROM_REG`. Bus helpers wrap SMBus operations with retry logging. Update paths are `lm93_update_client_full`, `lm93_update_client_min`, `lm93_update_client_common`, and `lm93_update_device`.

## Control Flow
Probe selects block or byte/word update mode from adapter functionality and `disable_block`, allocates state, initializes the mutex, initializes the chip, and registers all attributes. `lm93_update_device` refreshes after 1.5 seconds or when invalid. Full update uses SMBus block commands; minimum update individually reads the same data. Common update reads registers not covered by block commands and writes previous alarm bytes back to clear them. Store callbacks lock `update_lock`, parse input, clamp/map values, update cache, and write packed registers.

## State And Persistence
Hardware persists thresholds, fan-control tables, smart tach mappings, PWM mode/frequency/duty, PROCHOT override/interval, VCCP mode, GPIO/VID threshold setup, alert/status settings, and monitor state. Runtime cache persists all block values for up to 1.5 seconds. Module parameters `disable_block`, `init`, `vccp_limit_type`, and `vid_agtl` globally alter behavior. `pwm_override[]` is driver-only state preserving user-commanded PWM because hardware can read back a different override duty field.

## Dependencies And Integration Points
The driver depends on I2C SMBus byte/word and optional block support, hwmon sysfs helpers, `hwmon-vid`, jiffies, mutexes, and delay APIs. It integrates with I2C hwmon class scanning at 0x2c-0x2e and detects LM93/LM94 by manufacturer/version registers. User-space ABI is legacy fixed sysfs names.

## Risks And Test Signals
Read helpers return zero after repeated failures, so failed transactions can become plausible cached data. Block read failures can leave old cache values. Several stores ignore write errors and return success. Packed bitfields are fragile, PWM frequency can disable smart tach, alarm conversion drops some hardware bits, and `pwm_auto_vrdhot_ramp_store` returns `0` on success. Test full and minimum update paths, retry/error behavior, sysfs permissions, packed writes, VIN/VID scaling, fan edge cases, alarm clearing, and LM93/LM94 detection.
