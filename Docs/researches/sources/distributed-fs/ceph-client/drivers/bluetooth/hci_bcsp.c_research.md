# sources/distributed-fs/ceph-client/drivers/bluetooth/hci_bcsp.c

Purpose: This file implements the BCSP Bluetooth HCI UART protocol. BCSP is a SLIP-framed, optionally CRC-protected, sequence/acknowledgement transport with reliable and unreliable channels. It maps HCI command and ACL traffic to reliable BCSP channels, SCO to an unreliable channel, handles link-establishment messages, and optionally converts vendor HCI extension channels into HCI vendor events.

Important APIs, types, and functions: `struct bcsp_struct` tracks `unack`, `rel`, and `unrel` queues, RX reassembly state, escape state, CRC state, txack and rxack values, retransmission timer, and the next reliable TX sequence. Main protocol callbacks are `bcsp_open`, `bcsp_close`, `bcsp_enqueue`, `bcsp_dequeue`, `bcsp_recv`, and `bcsp_flush`. Helpers include `bcsp_prepare_pkt`, `bcsp_pkt_cull`, `bcsp_complete_rx_pkt`, `bcsp_handle_le_pkt`, `bcsp_unslip_one_byte`, and `bcsp_timed_event`. Module parameters `txcrc` and `hciextn` control transmitted CRC and HCI extension channel conversion.

Control flow: Enqueue classifies outgoing HCI command/ACL packets as reliable and SCO packets as unreliable, rejecting payloads larger than 12 bits. Dequeue gives priority to unreliable traffic, then sends reliable packets while the unacknowledged queue is below `BCSP_TXWINSIZE`, placing original skbs on `unack` and starting a retransmission timer. If no data can be sent but an ACK is pending, it emits an empty BCSP ACK packet. RX is a byte-wise state machine that waits for delimiters, unslips escaped bytes, reads and validates the 4-byte BCSP header checksum, collects payload and optional CRC, then dispatches complete packets. Reliable RX packets advance the expected sequence and request an ACK; all packets carry peer ACK information that culls the unack queue.

State and persistence behavior: BCSP state is entirely volatile and bound to the open HCI UART instance. It persists across incoming bytes through `rx_skb`, `rx_state`, `rx_count`, and CRC fields, and across transmit attempts through the reliable sequence, peer ACK, and retransmission timer. No filesystem or device NVM is changed. On close, the timer is shut down synchronously and all queues plus the partial RX skb are freed.

Dependencies and integration points: The file integrates with the HCI UART protocol registry via `hci_uart_register_proto`, queues TX through `hci_uart_tx_wakeup`, and delivers complete frames through `hci_recv_frame`. It depends on skbuff queues, timers, `bitrev16`, unaligned access helpers, and HCI packet definitions. It is selected through line-discipline IOCTL as `HCI_UART_BCSP`.

Risks and edge cases: Sequence and ack handling is sensitive to wraparound modulo 8 and the fixed transmit window. `bcsp_pkt_cull` logs invalid ACKs but still removes based on the computed count, so corrupt headers that pass checksum could disturb retransmission state. Out-of-order reliable packets are ACKed/cull peer acks but payloads are dropped. CRC is optional and only protects packets that request it. The RX state machine must recover from short packets, bad escape sequences, bad header checksum, and CRC mismatch without leaking skbs. HCI extension conversion rewrites unknown BCSP channels into vendor events and depends on the `hciextn` module setting.

Test signals: Good coverage includes reliable command/ACL sequencing, SCO priority as unreliable traffic, ACK-only emission, timeout retransmission with sequence rewind, modulo-8 ACK culling, link-establishment conf response and sync reset logging, SLIP escaping for `0xc0` and `0xdb`, header checksum failure, CRC success/failure, short-packet recovery, unknown channel handling with and without `hciextn`, and cleanup during close while the retransmission timer is pending.
