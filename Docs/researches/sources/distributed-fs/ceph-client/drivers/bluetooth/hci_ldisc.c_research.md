# sources/distributed-fs/ceph-client/drivers/bluetooth/hci_ldisc.c

Purpose: This file is the core tty line discipline for Bluetooth HCI UART devices. It registers the `N_HCI` line discipline, manages protocol selection through IOCTLs, owns the transmit workqueue from HCI core into tty writes, forwards tty RX bytes into the selected protocol, creates and registers `hci_dev` instances, exposes common baud-rate and flow-control helpers, and initializes all compiled HCI UART protocol modules.

Important APIs, types, and functions: The global `hup[]` protocol table is managed by `hci_uart_register_proto`, `hci_uart_unregister_proto`, and `hci_uart_get_proto`. TX and registration helpers include `hci_uart_tx_wakeup`, `hci_uart_write_work`, `hci_uart_init_work`, `hci_uart_init_ready`, `hci_uart_wait_until_sent`, `hci_uart_register_dev`, and `hci_uart_set_proto`. HCI callbacks are `hci_uart_open`, `hci_uart_close`, `hci_uart_flush`, `hci_uart_send_frame`, and `hci_uart_setup`. TTY callbacks are `hci_uart_tty_open`, `hci_uart_tty_close`, `hci_uart_tty_receive`, `hci_uart_tty_wakeup`, and `hci_uart_tty_ioctl`.

Control flow: Opening the line discipline requires `CAP_NET_ADMIN`, allocates `struct hci_uart`, initializes `proto_lock`, stores it in `tty->disc_data`, sets receive room and default alignment, captures current tty speed as `oper_speed`, and flushes pending tty output. Userspace then sets flags and protocol through IOCTL. Protocol selection allocates an HCI device, attaches HCI callbacks and quirks, calls the selected protocol `open`, and registers the HCI device unless initialization is deferred. HCI sends call protocol `enqueue`, then schedule TX. TX work repeatedly asks the protocol for skbs, writes to tty, handles partial writes through `hu->tx_skb`, updates stats, and wakes waiters. TTY receive calls protocol `recv` under `proto_lock` and updates RX byte stats.

State and persistence behavior: State is per-line-discipline and volatile: selected protocol, flags, HCI device pointer, TX state bits, outstanding partial TX skb, work structs, proto lock, alignment/padding, init and operational speeds, and HCI device flags. No persistent storage is used. Closing detaches `disc_data`, closes/unregisters/frees the HCI device if registered, cancels work, closes protocol state, frees the percpu rwsem, and frees `hci_uart`.

Dependencies and integration points: The file sits between tty/serdev-adjacent protocol modules and the Bluetooth HCI core. It calls tty APIs for line discipline registration, termios baud/CRTSCTS changes, modem-control RTS manipulation, driver buffer flushing, and write callbacks. It conditionally initializes protocol modules for H4, BCSP, LL, ATH3K, H5, Intel, BCM, QCA, AG6XX, Marvell, and AML. Vendor detection in `hci_uart_setup` can install Intel or Broadcom BDADDR handlers after reading local version.

Risks and edge cases: Concurrency is central. `proto_lock` allows protocol callbacks from tty, HCI send, TX work, and close to be coordinated; `hci_uart_tx_wakeup` uses a trylock because it may run in IRQ context. Partial tty writes leave `hu->tx_skb` for the next wakeup. Close must cancel init and write work after clearing readiness to avoid use-after-free. Flow-control helper semantics are inverted for serdev (`enable` means stop controller traffic) and manually alter CRTSCTS/RTS for tty devices. IOCTL flag setting is only allowed before protocol selection. Deferred initialization via `HCI_UART_INIT_PENDING` is used by protocols such as H5 and must not register the HCI device until `hci_uart_init_ready`.

Test signals: Validation should include line-discipline open permission and missing-write-op failure, IOCTL protocol selection and busy behavior, flag validation, HCI device registration and deferred registration, protocol close cleanup, TX partial-write retry, concurrent TX wakeups, flush behavior with partial skb and protocol queue, RX forwarding under proto lock, tty wakeup scheduling, baud-rate termios changes, flow-control RTS/CRTSCTS transitions, vendor-detect local-version path, and module init/exit ordering for compiled protocols.
