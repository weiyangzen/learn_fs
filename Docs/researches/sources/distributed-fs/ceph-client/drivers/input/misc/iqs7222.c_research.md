# sources/distributed-fs/ceph-client/drivers/input/misc/iqs7222.c

Purpose: I2C input driver for Azoteq IQS7222A/B/C/D capacitive controllers, combining buttons, sliders/wheels, and trackpad/gesture reporting in one input device.

Important APIs/types/functions: `struct iqs7222_dev_desc` captures product/firmware support, register group geometry, offsets, links, and quirks. `struct iqs7222_private` caches all register groups and input mappings. Key functions include `iqs7222_force_comms`, burst read/write helpers, `iqs7222_ati_trigger`, `iqs7222_dev_init`, `iqs7222_dev_info`, property/channel/slider/trackpad parsers, `iqs7222_report`, IRQ, and probe.

Control flow: probe allocates state/input, gets RDY GPIO and optional reset GPIO, hard-resets, identifies the device, bulk-reads supported setup groups, parses firmware children/properties into cached registers, bulk-writes them, triggers ATI, reports initial status, registers input, maps RDY GPIO to IRQ, and requests a threaded IRQ. Communication is guarded by forced-communication commands, RDY polling, retries, `0xEEEE` invalid-read detection, and optional stop-bit hold.

State/persistence: no durable storage. Cached register arrays are the active setup image. Report-time reset and ATI errors replay configuration or retry ATI. Input key/axis mappings are built from firmware.

Dependencies/integration: GPIO descriptors, raw I2C, firmware-node groups (`cycle-%d`, `channel-%d`, `slider-%d`, `trackpad`, `gpio-%d`), touchscreen helpers, EV_KEY/EV_SW/EV_ABS input.

Risks: descriptor offsets are firmware-sensitive. RDY timing races, slider/trackpad variant differences, GPIO link conflicts, and event-mask setup are fragile. Report failures surface as `IRQ_NONE`.

Test signals: all product families, RDY/reset GPIO behavior, communication retries, ATI timeout/error recovery, channel prox/touch, slider ABS and gestures, trackpad coordinates/gestures, GPIO conflicts, invalid selections, and reset replay.
