# sources/distributed-fs/ceph-client/drivers/dma/arm-dma350.c

Purpose: implements the Arm DMA-350 dmaengine driver for memory-to-memory copy and, when all channels support wrap/fill, memset. It uses per-channel command-link descriptors represented as register write command arrays and virtual DMA channels.

Important APIs and functions: `d350_probe()` verifies IIDR implementer/product, discovers channel count, data width, address width, trigger count, DMA coherency, and per-channel capabilities, then registers a dmaengine device. `d350_prep_memcpy()` builds a command array that writes CTRL, source/destination addresses, transfer size, memory attributes, increments, and link termination. `d350_prep_memset()` builds a fill transfer command when memset is enabled. `d350_start_next()` loads the command array into channel registers and enables the channel. `d350_irq()` handles DONE/ERR interrupts, maps AXI error info into dmaengine result codes, completes the current cookie, and starts queued work.

Control flow: probe clears each channel, skips channels without command-link support, records IRQ and feature bits, initializes `virt_dma_chan`, and optionally enables DMA_MEMSET only if every usable channel has wrap support. A client prepares memcpy/memset; `vchan_tx_prep()` queues a `d350_desc`. `d350_issue_pending()` moves pending descriptors into the issued list and starts the next descriptor when idle. Completion IRQ reads/acknowledges channel status, completes the active descriptor, updates status/residue, and chains to the next queued descriptor.

State and persistence behavior: `struct d350` stores the dmaengine device and discovered channel/request counts. Each `struct d350_chan` stores a virtual channel, active descriptor pointer, channel MMIO base, IRQ, dmaengine status, active cookie, residue, transfer size shift, feature flags, and coherency. `struct d350_desc` stores the command array and transfer size metadata. State is volatile and probe-time only; remove unregisters dmaengine but there are no explicit PM suspend/resume hooks.

Dependencies and integration points: uses dmaengine memcpy/memset APIs, `virt-dma`, OF compatible `arm,dma-350`, platform per-channel IRQs, MMIO register access, and DMA mask/coherency discovery. Memory attributes in command descriptors are chosen from device coherency (`TRANSCFG_WB` versus `TRANSCFG_NC`) and Arm shareability/memory attribute encodings.

Risks and edge cases: the driver is intentionally narrow and does not expose slave/cyclic/triggered transfers despite hardware trigger-related fields. `d350_irq()` assumes `dch->desc` is valid when an interrupt fires; unexpected shared IRQs before a descriptor could be hazardous. `d350_get_residue()` retries split high/low transfer-size reads only three times. `d350_tx_status()` calls `dma_set_residue(state, residue)` without a local null check after `dma_cookie_status()`, relying on normal dmaengine usage. Channels without command-link support are skipped, but the registered `chancnt` behavior depends on `vchan_init()` only for usable channels.

Test signals: probe should reject non-DMA-350 IIDR values, set DMA mask from address width, and expose DMA_MEMSET only when wrap/fill is available. Functional tests should verify memcpy across byte/halfword/word/dword-aligned sizes, memset pattern byte replication, chained descriptor execution, pause/resume state changes, terminate-all completion cleanup, read/write/abort error result mapping from `CH_ERRINFO`, and residue accuracy while running and paused.
