# sources/distributed-fs/ceph-client/drivers/dma/sprd-dma.c

Purpose: implements the Spreadtrum/Unisoc DMA controller as a DMAengine provider. It supports memcpy, slave SG, optional link-list mode supplied by clients, two-stage channel trigger configuration, pause/resume, optional controller IRQs, runtime PM clock management, and OF simple DMA channel translation.

Important APIs/types/functions: key types are `struct sprd_dma_dev`, `struct sprd_dma_chn`, `struct sprd_dma_desc`, and `struct sprd_dma_chn_hw`. DMAengine hooks include `sprd_dma_alloc_chan_resources`, `sprd_dma_free_chan_resources`, `sprd_dma_tx_status`, `sprd_dma_issue_pending`, `sprd_dma_prep_dma_memcpy`, `sprd_dma_prep_slave_sg`, `sprd_dma_slave_config`, `sprd_dma_pause`, `sprd_dma_resume`, and `sprd_dma_terminate_all`. Important internal functions are `sprd_dma_set_chn_config`, `sprd_dma_start`, `sprd_dma_stop`, `sprd_dma_fill_desc`, `sprd_dma_fill_linklist_desc`, `sprd_dma_set_2stage_config`, `sprd_dma_set_uid`, `sprd_dma_set_pending`, `sprd_dma_clear_int`, and `dma_irq_handle`.

Control flow: probe sets a 36-bit coherent DMA mask with 32-bit fallback, reads `dma-channels` or deprecated `#dma-channels`, allocates a controller object with a flexible channel array, gets mandatory `enable` and optional `ashb_eb` clocks, optionally requests the controller IRQ, maps the global register block, initializes DMAengine hooks and each virt-dma channel, enables clocks, enables runtime PM, registers the DMAengine device, and registers `of_dma_simple_xlate` with `sprd_dma_filter_fn`. Allocation takes a runtime PM reference. Memcpy prep allocates one descriptor and fills channel hardware fields with aligned width/step choices. Slave SG prep records optional `struct sprd_dma_linklist` context, decodes channel mode, trigger mode, request mode, and interrupt type from flags, builds link-list entries for multi-entry SG when supplied, and fills the initial descriptor. `issue_pending` starts the next virt descriptor when idle by programming all channel registers, UID, pending request bits, channel enable, and software request for software-triggered channels. IRQ handling scans masked global status bits, clears per-channel interrupts, runs cyclic callbacks for link-list mode, otherwise completes descriptors when the interrupt type satisfies the request mode, then starts the next descriptor.

State and persistence: controller state includes clocks, optional IRQ, global MMIO base, total channel count, and a flexible channel array. Each channel stores channel register base, current descriptor, slave config, link-list context, channel number, device UID, two-stage channel mode, trigger mode, and interrupt type. Descriptors store a complete hardware register image and transfer direction. No state persists beyond live kernel memory and hardware registers.

Dependencies and integration points: depends on DMAengine, `virt-dma`, OF DMA simple translation, Spreadtrum public header `linux/dma/sprd-dma.h` for flags/link-list contracts, clocks, runtime PM, platform resources, and MMIO. Client drivers pass a DMA request UID through OF filter data and may pass link-list memory through the prep context. The driver handles AP/AON/AGCP variants, with optional IRQ and optional ASHB clock for AGCP.

Risks: residue reporting sets `txstate` residue to a hardware address for the current descriptor rather than remaining bytes, which may be a semantic mismatch for DMAengine clients. Slave SG without link-list uses only the last SG length but first SG start address in the initial descriptor, so multi-entry SG behavior depends on client-provided link-list context. `sprd_dma_enable` does not undo the mandatory clock if enabling optional `ashb_clk` fails. The OF filter always returns true after storing `dev_id`, with no channel/request exclusivity. Cyclic detection is based solely on `linklist.phy_addr`, so any link-list transfer is treated as cyclic for IRQ callbacks. Optional no-IRQ controllers cannot complete non-cyclic cookies unless clients use polling/status semantics. Two-stage configuration mutates global group registers and needs strong tests for paired source/destination channels.

Test signals: run memcpy with different alignments and lengths above `SPRD_DMA_MEMCPY_MIN_SIZE`, slave SG single-entry and multi-entry with/without link-list context, two-stage source/destination channel combinations, all request and interrupt modes, optional IRQ absence, pause/resume timeouts, runtime PM clock enable failure, 36-bit address programming through wrap registers, terminate/free current descriptor handling, and OF request UID mapping. Static checks should focus on residue units, SG/link-list assumptions, clock error unwinding, and global two-stage register masks.
