# sources/distributed-fs/ceph-client/drivers/dma/sh/shdma-base.c

Purpose: provides a reusable DMAengine base library for SH-style DMA controllers. Hardware-specific drivers embed `struct shdma_dev`, `struct shdma_chan`, and `struct shdma_desc`, supply `struct shdma_ops`, and receive common descriptor allocation, cookie handling, queueing, slave filtering, IRQ threading, cyclic support, runtime PM handoff, and DMAengine registration setup.

Important APIs/types/functions: exported APIs are `shdma_chan_filter`, `shdma_reset`, `shdma_request_irq`, `shdma_chan_probe`, `shdma_chan_remove`, `shdma_init`, and `shdma_cleanup`. Internal DMAengine hooks include `shdma_alloc_chan_resources`, `shdma_free_chan_resources`, `shdma_prep_memcpy`, `shdma_prep_slave_sg`, `shdma_prep_dma_cyclic`, `shdma_config`, `shdma_terminate_all`, `shdma_issue_pending`, and `shdma_tx_status`. Descriptor state is represented by `enum shdma_desc_status` with `DESC_IDLE`, `DESC_PREPARED`, `DESC_SUBMITTED`, `DESC_COMPLETED`, and `DESC_WAITING`.

Control flow: `shdma_init` validates required hardware callbacks, allocates the per-device channel pointer table, initializes DMAengine hook pointers, and leaves channel registration to the hardware driver. `shdma_chan_probe` initializes one channel, list heads, cookies, locks, PM state, and adds it to the DMAengine channel list. Channel allocation optionally binds a legacy or filtered slave ID, allocates a fixed descriptor array, initializes all embedded descriptors through the hardware callback, and adds them to `ld_free`. Prep code builds descriptor chains from memcpy, SG, or cyclic inputs; `shdma_add_desc` delegates hardware register fields to `ops->desc_setup`, splits transfers by `max_xfer_len`, assigns visible and hidden cookie sentinel values, and temporarily splices prepared descriptors back onto the free list as a chain. `tx_submit` assigns a cookie, moves all chunks in the prepared chain to `ld_queue`, powers the channel when the queue transitions from empty, calls `ops->setup_xfer`, and may start work immediately. `issue_pending` starts the first submitted descriptor when PM state is established. The hard IRQ delegates event detection to `ops->chan_irq`; the thread marks the first completed submitted descriptor, starts the next descriptor, and runs cleanup/callback logic.

State and persistence: `shdma_slave_used` is a module-global bitmap sized by the `slave_num` module parameter and prevents duplicate slave allocations. Each channel owns `ld_queue`, `ld_free`, a descriptor array, `slave_id`, `real_slave_id`, `hw_req`, `pm_state`, and max transfer size. Descriptor state includes cookie, chunk count, partial residue after termination, cyclic flag, and mark. Runtime PM references are taken when queues become active and put when queues drain. There is no disk persistence.

Dependencies and integration points: depends on Linux DMAengine, async_tx callbacks, runtime PM, IRQ threading, scatterlist helpers, and the public `linux/shdma-base.h` contract. Hardware drivers must implement callbacks for descriptor setup, transfer setup/start, halt, busy check, slave binding/address, IRQ interpretation, and descriptor completion. `shdmac.c` is the direct in-tree user in this subset.

Risks: descriptor chain ownership is subtle because prepared descriptors live on `ld_free` until submit, and hidden chunks use special negative cookie sentinels. Cleanup drops the lock around callbacks and loops until callbacks are drained, which can expose reentrancy or ack-order bugs. `shdma_tx_submit` powers up hardware and briefly drops the lock, so reset or free paths can race with PM state transitions. Slave allocation uses a global bitmap and comments warn the generic filter does not distinguish multiple DMAC drivers with `DMA_SLAVE`. `shdma_tx_status` reports `DMA_ERROR` for non-complete cookies not found on the queue, which makes aborted and invalid cookies indistinguishable to clients.

Test signals: exercise multi-chunk memcpy and SG chains, cyclic descriptors, callback-on-last-chunk behavior, async_tx ack recycling, terminate with partial residue callback support, PM get/put balance, IRQ hard/thread sequencing, reset from error/NMI paths, legacy `chan->private` slave binding, OF filter binding, and allocation failure after partial descriptor setup. Useful static checks include lock coverage for queue mutation and `pm_state` transitions.
