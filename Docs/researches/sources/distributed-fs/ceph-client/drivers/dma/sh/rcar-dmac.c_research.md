# sources/distributed-fs/ceph-client/drivers/dma/sh/rcar-dmac.c

Purpose: implements the Renesas R-Car Gen2/Gen3/Gen4 DMAC as a Linux DMAengine provider. It supports memory copy, slave scatter-gather, and cyclic slave transfers, exports channels through OF DMA translation, handles per-channel interrupts, and manages runtime PM for the controller.

Important APIs/types/functions: central types are `struct rcar_dmac`, `struct rcar_dmac_chan`, `struct rcar_dmac_desc`, `struct rcar_dmac_xfer_chunk`, and `struct rcar_dmac_hw_desc`. Public DMAengine hooks include `rcar_dmac_alloc_chan_resources`, `rcar_dmac_free_chan_resources`, `rcar_dmac_prep_dma_memcpy`, `rcar_dmac_prep_slave_sg`, `rcar_dmac_prep_dma_cyclic`, `rcar_dmac_device_config`, `rcar_dmac_chan_pause`, `rcar_dmac_chan_terminate_all`, `rcar_dmac_tx_status`, `rcar_dmac_issue_pending`, and `rcar_dmac_device_synchronize`. Hardware-facing helpers include `rcar_dmac_chan_start_xfer`, `rcar_dmac_fill_hwdesc`, `rcar_dmac_map_slave_addr`, `rcar_dmac_chan_halt`, `rcar_dmac_chan_reinit`, and `rcar_dmac_init`. IRQ handling is split between `rcar_dmac_isr_channel` and the threaded `rcar_dmac_isr_channel_thread`.

Control flow: probe reads OF match data for channel register layout, parses `dma-channels` and optional `dma-channel-mask`, maps global and per-channel register windows, disables channel 0 when an IOMMU group is present, initializes runtime PM, registers each channel IRQ, registers the OF DMA controller, then registers the DMAengine device. Channel resource allocation preallocates pages of software descriptors and transfer chunks and takes a runtime PM reference. Transfer preparation obtains one `rcar_dmac_desc`, builds a list of chunks from an SG list or cyclic periods, splits chunks at `DMATCR` and 4 GiB boundaries, configures CHCR fields for direction and bus width, and optionally creates a coherent hardware descriptor table when there are multiple chunks and the addresses do not cross high-address regions. `tx_submit` assigns a cookie and moves the descriptor to `pending`; `issue_pending` splices `pending` to `active` and starts the first descriptor if no transfer is running. The hard IRQ clears channel/error/transfer bits, handles address errors by clearing and reinitializing the channel, advances chunk or descriptor state, and wakes the thread when callbacks or done-list processing are needed. The IRQ thread completes cookies, invokes callbacks outside the lock, moves descriptors to `wait`, and recycles descriptors whose async_tx ack has arrived.

State and persistence: state is volatile driver and hardware state only. Each channel owns descriptor lists `free`, `pending`, `active`, `done`, `wait`, a `running` pointer, reusable chunk descriptors, descriptor pages, current slave source/destination settings, a cached resource mapping, and an allocated `mid_rid`. Hardware descriptor memory is per software descriptor and coherent DMA memory, resized page-aligned and released on channel free. The controller has a `modules` bitmap to prevent duplicate MID/RID allocations and a `channels_mask` to suppress unusable channels. No persistent on-disk state is used.

Dependencies and integration points: depends on Linux DMAengine, DMA mapping/resource mapping, OF DMA, platform IRQ/resources, runtime PM, spinlocks, and R-Car DMAC register definitions. It includes `../dmaengine.h` and registers compatibles `renesas,rcar-dmac`, `renesas,rcar-gen4-dmac`, and legacy `renesas,dmac-r8a779a0`. Slave clients request channels through one-cell OF DMA specs carrying MID/RID; `dma_slave_config` supplies FIFO addresses and bus widths. Integration with IOMMU is explicit through a 40-bit DMA mask and the channel-0 avoidance workaround.

Risks: descriptor/chunk list transitions are lock-sensitive and callbacks intentionally drop the channel lock; regressions can lose descriptors or double recycle wait-list entries. Hardware descriptor mode has address-region restrictions and an IOMMU erratum workaround that manually initializes `DMADAR`. Residue reads sample two registers with only three consistency attempts, so boundary races can produce warnings or approximate residue. `terminate_all` notes that an IRQ thread may still be running after halt. Runtime PM and channel setup interact in resource allocation/free; missed PM puts would keep the controller powered. OF channel count rejects `>= 32`, which is tied to the channel-clear mask width.

Test signals: useful signals are successful DT probe for both Gen2/Gen3 and Gen4 register layouts, `dmatest` memcpy with multi-chunk lengths, slave SG with multiple periods, cyclic audio-style callbacks, residue queries during and after descriptor-mode transfers, pause/terminate/reissue while IRQs fire, runtime suspend/resume, IOMMU-mapped transfers, and address-error IRQ recovery. Static checks should cover list manipulation, coherent descriptor allocation failures, and 64-bit DMA address boundary splitting.
