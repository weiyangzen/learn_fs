# sources/distributed-fs/ceph-client/drivers/dma/sh/shdmac.c

Purpose: implements the Renesas SuperH DMA Engine hardware driver using the generic SHDMA base library. It programs SAR/DAR/TCR/CHCR/DMAOR/DMARS registers, handles platform IRQ layouts, supports memcpy and slave DMA through the base hooks, resets on address errors and NMI, and registers a platform DMAengine device.

Important APIs/types/functions: hardware operation callbacks are collected in `sh_dmae_shdma_ops`: `sh_dmae_desc_completed`, `sh_dmae_halt`, `sh_dmae_channel_busy`, `sh_dmae_slave_addr`, `sh_dmae_desc_setup`, `sh_dmae_set_slave`, `sh_dmae_setup_xfer`, `sh_dmae_start_xfer`, `sh_dmae_embedded_desc`, `sh_dmae_chan_irq`, and `sh_dmae_get_partial`. Other key functions are `sh_dmae_rst`, `sh_dmae_ctl_stop`, `dmae_set_reg`, `dmae_start`, `dmae_init`, `dmae_set_chcr`, `dmae_set_dmars`, `dmae_find_slave`, `sh_dmae_reset`, `sh_dmae_err`, `sh_dmae_nmi_handler`, `sh_dmae_chan_probe`, `sh_dmae_probe`, and PM callbacks.

Control flow: module init registers a die notifier for NMI handling and probes the platform driver. Probe obtains platform or OF match data, maps channel and optional DMARS resources, initializes DMAengine capabilities, calls `shdma_init`, enables runtime PM, adds the device to a global RCU list for NMI scanning, resets the controller, requests an address-error IRQ when relevant, expands platform IRQ resources into per-channel IRQs, probes each channel through `shdma_chan_probe` and `shdma_request_irq`, drops the runtime PM reference, and registers the DMAengine device. During transfer setup, the base library calls `sh_dmae_setup_xfer` to set DMARS and CHCR for slave transfers or initialize MEMCPY CHCR. Starting a descriptor writes SAR/DAR/TCR and sets CHCR `DE` plus the configured interrupt bit. Channel IRQ handling checks transfer end, halts the channel, and lets the base threaded handler mark descriptors complete and queue the next descriptor. Error IRQ and NMI reset stop DMAOR, reset all base channels, then reinitialize DMAOR.

State and persistence: global state is `sh_dmae_devices` protected by `sh_dmae_lock` and read under RCU for NMI handling. Device state is platform data, channel register base, optional DMARS mapping, channel pointers, CHCR offset, and CHCR IE bit. Channel state includes register base, selected slave config, transfer shift, slave address, IRQ name, and inherited SHDMA queues. Hardware register state is restored on runtime and system resume. No persistent storage exists.

Dependencies and integration points: depends on SH DMA platform data (`linux/sh_dma.h`), the base library in `shdma-base.c`, Linux DMAengine, runtime/system PM, platform resources, raw MMIO accessors, IRQ resource flags, RCU, and die notifier/NMI infrastructure. It supports both platform-data and OF-backed slave selection. The driver registers under platform name `sh-dma-engine`.

Risks: IRQ resource parsing is complex and must match platform data channel counts; shared IRQ and error IRQ combinations are easy to misconfigure. The global NMI notifier scans all devices and resets any controller with NMIF set, which is correct for hardware but broad in blast radius. Address-error reset cannot identify a single channel and resets all channels. `sh_dmae_desc_completed` infers completion by comparing current SAR/DAR against expected end address, which can be fragile if hardware updates registers differently. Raw MMIO access and platform-data bit fields require exact SoC definitions. Probe error paths combine PM, RCU list removal, and channel cleanup.

Test signals: validate platform probe with single shared IRQ, ranges of channel IRQs, and separate error IRQ; memcpy and slave SG via `dmatest`; cyclic operation through the base library; DMARS programming for OF and non-OF slave configs; suspend/resume register restoration; runtime PM reset; address-error IRQ recovery; NMI notifier behavior; channel clear variants; and max transfer splitting at 16 MiB. Static analysis should inspect channel array bounds and RCU/list cleanup on probe failure.
