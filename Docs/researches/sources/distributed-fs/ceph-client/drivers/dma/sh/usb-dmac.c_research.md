# sources/distributed-fs/ceph-client/drivers/dma/sh/usb-dmac.c

Purpose: implements the Renesas USB-DMAC as a slave-only DMAengine provider using virt-dma. It is intended for fixed USB controller FIFO transfers with 32-byte bus width, per-channel IRQs, SG sequencing in software, residue reporting, and runtime PM integration.

Important APIs/types/functions: key types are `struct usb_dmac`, `struct usb_dmac_chan`, `struct usb_dmac_desc`, and `struct usb_dmac_sg`. DMAengine hooks are `usb_dmac_alloc_chan_resources`, `usb_dmac_free_chan_resources`, `usb_dmac_prep_slave_sg`, `usb_dmac_chan_terminate_all`, `usb_dmac_tx_status`, and `usb_dmac_issue_pending`. Internal helpers include `usb_dmac_chan_start_sg`, `usb_dmac_chan_start_desc`, `usb_dmac_calc_tend`, `usb_dmac_desc_get`, `usb_dmac_desc_put`, `usb_dmac_chan_halt`, `usb_dmac_soft_reset`, `usb_dmac_isr_channel`, and `usb_dmac_isr_transfer_end`.

Control flow: probe parses `dma-channels`, maps the register block, enables runtime PM, initializes DMAOR, initializes each virt-dma channel and per-channel IRQ, registers an OF DMA provider, fills DMAengine slave-only capabilities, registers the engine, then drops the PM reference. Channel resource allocation preallocates 16 descriptors each initially sized for 8 SG entries and takes a runtime PM reference. `prep_slave_sg` obtains or allocates a flexible descriptor large enough for the SG count, records direction and SG DMA addresses/lengths, and returns a virt-dma prepared descriptor. `issue_pending` marks descriptors issued and starts the first descriptor if idle. Hardware can transfer one SG entry at a time; completion IRQ advances `sg_index` and starts the next SG entry, or records final residue, completes the virt cookie, and starts the next descriptor. Termination halts hardware, clears current descriptor, returns all in-use descriptors to the free list, and frees virt-dma issued descriptors.

State and persistence: each channel owns a current descriptor pointer, IRQ number, MMIO base, descriptor allocation count, and two descriptor pools: `desc_got` for descriptors checked out by prep/issue and `desc_freed` for reusable descriptors. A completed descriptor stores `done_cookie` and final `residue` so clients can query residue after `DMA_COMPLETE`. The controller tracks channel count, engine object, and MMIO base. State is volatile only.

Dependencies and integration points: uses Linux DMAengine, `virt-dma`, OF DMA, platform resources, runtime PM, DMA mapping types, and MMIO. The OF spec is one cell selecting a channel index, and the filter requires the requested index to match the virt channel. Bus widths are fixed to `DMA_SLAVE_BUSWIDTH_32_BYTES`; directions are only MEM_TO_DEV and DEV_TO_MEM.

Risks: `usb_dmac_soft_reset` loops over channel count but checks the same `uchan` each time instead of `dmac->channels[i]`, so it may reset while another channel is busy or unnecessarily skip reset based only on the current channel. Residue calculation uses 32-bit low addresses and subtracts live SAR/DAR from the SG memory address, so high-address and wrap scenarios need scrutiny. Descriptor pools are manually managed outside normal virt-dma allocation; leaks or double moves are possible around terminate and free. There is no `device_config` hook because device FIFO addresses are implicit zero-side registers, so clients must match this hardware's fixed USB FIFO integration. The interrupt path handles NULL/FTE behavior and TE/SP bits in a hardware-specific way that can regress short-packet handling.

Test signals: run slave SG transfers for both directions, multiple SG entries, short final packets, residue during active transfer and after completion, terminate while descriptor is active, descriptor allocation growth beyond 8 SG entries, runtime suspend/resume, shutdown, and concurrent channels to expose the soft-reset channel iteration issue. Static checks should focus on list movement between `desc_got` and `desc_freed` and 32-bit address assumptions.
