# sources/distributed-fs/ceph-client/drivers/dma/apple-admac.c

Purpose: implements the Apple ADMAC audio DMA controller driver for Apple SoCs such as t8103. It exposes private cyclic DMA channels to audio clients, with hardwired even-channel TX and odd-channel RX directions, small hardware descriptor/report rings, and per-channel SRAM cache carveouts.

Important APIs and functions: `admac_probe()` reads `dma-channels`, maps MMIO, obtains an optional shared reset, initializes dmaengine cyclic callbacks, creates one `struct admac_chan` per channel, resets hardware, requests the selected IRQ output, registers the DMA device, and registers OF translation. `admac_prep_dma_cyclic()` creates an `admac_tx` with buffer and period metadata. `admac_issue_pending()` moves submitted work to issued, starts the current cyclic transfer, writes initial descriptors, and starts the hardware channel. `admac_device_config()` programs bus word width, frame width, and FIFO threshold/limit. `admac_interrupt()`, `admac_handle_status_desc_done()`, `admac_drain_reports()`, and `admac_chan_tasklet()` drain period reports and invoke cyclic callbacks.

Control flow: clients obtain a specific channel through `admac_dma_of_xlate()`, configure port width/frame size, prepare one cyclic buffer, submit it, then issue pending. The driver resets descriptor/report rings, writes one descriptor before start, enables per-channel descriptor-done/error interrupts, starts TX or RX using the channel pair bit, and writes up to four ring slots as space allows. On descriptor-done IRQ, it clears status, drains up to four report entries, advances reclaimed position, writes more descriptors to keep the cyclic ring full, and schedules a tasklet to issue one callback per acknowledged period.

State and persistence behavior: `struct admac_data` stores the dmaengine device, MMIO base, reset control, selected IRQ output index, channel count, and TX/RX SRAM allocation bitmaps. `struct admac_chan` stores lock-protected current transfer, submitted/issued/to-free lists, period-ack count, and SRAM carveout value. `struct admac_tx` stores cyclic buffer address range, length, period length, submitted and reclaimed positions. State is volatile; remove unregisters OF/dmaengine, frees IRQ, and rearms reset. There is no system PM handling.

Dependencies and integration points: depends on dmaengine cyclic APIs, OF DMA controller registration, platform IRQ/MMIO helpers, reset framework, tasklets, spinlocks, and Apple ADMAC device-tree compatibles `apple,t8103-admac` and `apple,admac`. It is tailored to audio peripheral use through `DMA_PRIVATE`, cyclic-only capability, and bus/frame controls derived from `dma_slave_config`.

Risks and edge cases: only cyclic transfers are supported, and the usual path assumes one long-lived cyclic transaction per channel. SRAM cache allocation uses one 2 KiB block per channel and a 32-bit bitmap, so cache sizes above the documented 64 KiB field assumption would not be representable. Residue calculation samples report-ring and residue registers non-atomically and uses heuristics around descriptor-load races. Error handling logs and clears ring errors but does not mark the active dmaengine transaction failed. `admac_synchronize()` splices `to_free` before killing the tasklet, so callers must follow terminate/synchronize ordering. No suspend/resume means active audio DMA is not preserved across power loss.

Test signals: useful signals include OF channel index bounds, reset/IRQ registration success, TX and RX cyclic playback/capture with period callbacks matching hardware reports, correct residue monotonicity during cyclic operation, pause/resume stop/start behavior, terminate-all followed by synchronize freeing descriptors, SRAM allocation exhaustion returning `-EBUSY`, bus width rejection for unsupported widths/window sizes, and ring-error interrupt logging without interrupt storms.
