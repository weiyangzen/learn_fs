# sources/distributed-fs/ceph-client/drivers/dma/st_fdma.c

Purpose: implements the STMicroelectronics STi FDMA engine as a DMAengine provider backed by an ST SLIM remote processor firmware. It supports memcpy, slave SG, cyclic slave transfers, request-line allocation, pause/resume/terminate commands, residue reporting, IRQ completion, and OF DMA translation that boots the firmware on channel request.

Important APIs/types/functions: key functions are `st_fdma_of_xlate`, `st_fdma_dreq_get`, `st_fdma_dreq_put`, `st_fdma_xfer_desc`, `st_fdma_irq_handler`, `st_fdma_alloc_desc`, `st_fdma_alloc_chan_res`, `st_fdma_free_chan_res`, `st_fdma_prep_dma_memcpy`, `config_reqctrl`, `st_fdma_prep_dma_cyclic`, `st_fdma_prep_slave_sg`, `st_fdma_desc_residue`, `st_fdma_tx_status`, `st_fdma_issue_pending`, `st_fdma_pause`, `st_fdma_resume`, `st_fdma_terminate_all`, `st_fdma_slave_config`, and `st_fdma_probe`. Data layout and register macros are defined in `st_fdma.h`.

Control flow: probe derives the firmware name from compatible-specific driver data, reads `dma-channels`, allocates channel state, requests the shared FDMA IRQ, allocates the SLIM remoteproc wrapper, initializes virt-dma channels, reserves DREQ lines 0 and 31, fills DMAengine capabilities and hooks, registers the DMAengine device through `dmaenginem_async_device_register`, and registers an OF DMA controller. OF translation validates the DMA provider node, boots the SLIM remote processor, allocates any slave channel, stores request-line/control/type arguments, and reserves a DREQ line for paced channels. Channel resource allocation creates a DMA pool for 32-byte-aligned hardware nodes. Prep functions allocate one flexible software descriptor with one DMA-pool hardware node per SG/period, fill node control/address/length fields, and return a virt-dma descriptor. `issue_pending` starts the first issued descriptor by writing the first node pointer to channel DMEM and issuing a START command in peripheral registers. IRQ handling scans two status bits per channel, updates channel status, completes non-cyclic descriptors or invokes cyclic callbacks, starts the next descriptor if idle, and clears interrupt status.

State and persistence: state is split across Linux memory, coherent DMA-pool node memory, SLIM DMEM, and FDMA peripheral registers. The device tracks the SLIM remoteproc object, IRQ, DREQ bitmap, firmware name, and channel array. Each channel stores a DMA pool, last slave config, OF/request config, allocated DREQ line, current descriptor, and last DMA status. Software descriptors own an array of hardware node pointers and physical addresses. No disk persistence exists, but firmware boot/shutdown is tied to OF channel allocation/free.

Dependencies and integration points: depends on DMAengine, `virt-dma`, OF DMA, platform IRQs, device properties, DMA pools, and `remoteproc/st_slim_rproc.h`. It uses SLIM remote processor memory and peripheral register windows through macros in `st_fdma.h`. OF DMA args are request line, optional request-control bits masked by `FDMA_REQ_CTRL_CFG_MASK`, and optional transfer type (`FREE_RUN` or `PACED`). Compatible strings select STiH407 MPE31 firmware IDs.

Risks: `st_fdma_dreq_get` only accepts the configured request line and returns error on retry, so there is no fallback despite comments suggesting allocation. Access to `dreq_mask` is not protected by the declared `dreq_lock`; atomic bitops help individual bits but not the `fdev->dreq_mask == ~0L` check. `st_fdma_desc_residue` takes a `vdesc` argument but uses `fchan->fdesc`, so queued descriptor residue may be wrong or unsafe when no current descriptor exists. `st_fdma_prep_slave_sg` does not call `config_reqctrl`, unlike cyclic prep, so paced request-control setup depends on prior config or may be missing. Non-cyclic SG nodes form a circular `next` chain and rely on interrupt-on-last-node to stop. Remove does not explicitly unregister the DMAengine device in this file, relying on devm-style registration semantics if available. Firmware boot/shutdown balance is tied to channel allocation/free paths.

Test signals: test OF translation with one, two, and three DMA args; firmware probe deferral and boot failure; DREQ allocation conflicts; memcpy node execution; slave SG and cyclic transfers for both directions and supported bus widths; pause/resume/terminate commands; residue for active and queued cookies; IRQ error status; remoteproc shutdown on channel free; and probe/remove resource cleanup. Static analysis should check DREQ locking, `st_fdma_desc_residue` use of current descriptor, and whether `dmaenginem_async_device_register` gives intended lifecycle cleanup.
