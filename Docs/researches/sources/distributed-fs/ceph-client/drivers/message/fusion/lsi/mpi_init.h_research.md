# sources/distributed-fs/ceph-client/drivers/message/fusion/lsi/mpi_init.h

Purpose: defines the LSI Fusion MPT MPI initiator-mode message ABI for SCSI IO, extended 32-byte/EEDP-capable SCSI IO, SCSI task management, and SCSI Enclosure Processor slot-status operations. It is the central request/reply contract used by the Fusion SCSI host path when translating Linux `scsi_cmnd` objects and error-handling requests into firmware message frames.

Important APIs, types, and structures: `MSG_SCSI_IO_REQUEST` is the standard initiator IO request with target ID, bus, CDB length, sense length, message flags, context, 8-byte LUN, `Control`, 16-byte CDB, data length, sense buffer address, and IO SGL. `MSG_SCSI_IO_REPLY` returns SCSI status, SCSI state, IOC status/log info, transfer count, sense count, response info, and task tag. Macros define sense width/location, command-determined data direction, LUN addressing masks, control bits for read/write/no-data, additional CDB length, task attributes, and embedded task-management bits. Status macros include SAM status codes plus FC-specific extended statuses such as device logged out and no link. `MSG_SCSI_IO32_REQUEST` extends the request format for 32-byte CDB/EEDP and bidirectional cases, including CDB/EEDP unions, bidirectional length, reference/application tags, EEDP flags, block size, SCSI ID or WWID device address forms, SGL offsets, and sense address; `MSG_SCSIIO32_IO_REPLY` adds bidirectional transfer count. `MSG_SCSI_TASK_MGMT` and `MSG_SCSI_TASK_MGMT_REPLY` define abort task, abort task set, target reset, bus reset, logical unit reset, clear task set, query task, and clear ACA flows with response codes and termination counts. `MSG_SEP_REQUEST` and `MSG_SEP_REPLY` define enclosure slot status read/write operations and the large slot-status bitmaps used for fault, rebuild, identify, insert/remove, bypass, power, and swap state.

Control flow: the normal SCSI command path in `mptscsih.c` allocates a message frame, casts it to `SCSIIORequest_t`, fills target, bus, LUN, CDB, data length, direction/task attribute bits, sense buffer location, and SGL, then posts the frame to firmware. Completion handlers cast replies to `SCSIIOReply_t`, inspect `IOCStatus`, `SCSIStatus`, `SCSIState`, `TransferCount`, `SenseCount`, and `ResponseInfo`, and map them back to Linux SCSI result and sense handling. Error handling paths in `mptscsih.c`, `mptsas.c`, and `mptctl.c` allocate `SCSITaskMgmt_t`, set `TaskType`, target/bus/LUN, optional task message context, and wait for `SCSITaskMgmtReply_t`. SEP control in `mptscsih.c` fills `SEPRequest_t` to push slot status such as predicted fault or identify state to enclosure management. `mptctl.c` can also build SCSI IO and task-management frames for control passthrough, applying the same direction and qtag constants.

State and persistence behavior: this header declares transient initiator messages only. Per-command state is correlated through `MsgContext`, firmware request indexes, sense buffer DMA addresses, SGL chains, and optional `TaskTag`. SCSI IO replies expose device and transport state for a single command, while task-management replies report how many commands were terminated. SEP slot status represents enclosure-visible state and may persist in enclosure hardware or firmware until changed, but this header itself contains no storage or policy. EEDP fields in SCSI IO32 describe per-request protection-information behavior, not a global setting.

Dependencies and integration points: depends on base MPI types, `MPI_POINTER`, `SGE_IO_UNION`, and `SGE_SIMPLE_UNION`. It is included by `mptbase.h` and used heavily by `mptscsih.c`, `mptsas.c`, `mptspi.c`, `mptfc.c`, and `mptctl.c`. The Linux SCSI mid-layer provides `scsi_cmnd`, queue tags, CDBs, data direction, sense buffers, and error-handler entry points; the Fusion base layer provides message frames, DMA SGL construction, reply dispatch, and timeout handling. FC initiator mode uses these SCSI IO messages for FCP commands, while FC-specific link management is separated into `mpi_fc.h`.

Risks and edge cases: `Control` bit packing is central to IO correctness; an incorrect data direction or task attribute can cause DMA in the wrong direction or bad queue semantics. Sense buffer width/location bits must match the allocated sense DMA address size and firmware expectation. Additional CDB length, SCSI IO32 large-CDB mode, SGL offset chains, bidirectional IO, and EEDP flags all expand the ABI surface and are easy to under-test. Task-management requests are disruptive and must target the correct LUN, target, bus, or message context; soft reset/LIP reset options have transport-specific effects. Reply interpretation must distinguish IOC transport failures from SCSI device statuses and from valid autosense. SEP request/reply slot-status bits are similar but not identical, so using request constants on replies or vice versa can misreport enclosure state. As with all MPI headers, struct layout and endian handling are firmware ABI critical.

Test signals: compile and boot-test Fusion SCSI host paths with SPI, SAS, and FC variants enabled. Runtime IO tests should cover read, write, no-data commands, tagged and untagged queueing, CHECK CONDITION with valid autosense, queue full, residual/short transfer behavior, and FC extended status cases where applicable. Error-injection or fault tests should cover abort task, LUN reset, target reset, bus reset, query task, and timeout handling with correct termination counts. SEP tests should verify identify, predicted-fault, rebuild, hot-spare, insert/remove, and bypass indicators on supported enclosures. If SCSI IO32/EEDP is enabled by hardware, add large CDB, bidirectional, protection check/strip/insert/replacement, and SGL-offset chain coverage.
