# sources/distributed-fs/ceph-client/drivers/message/fusion/lsi/mpi_cnfg.h

Purpose: defines the LSI Fusion MPT MPI configuration-message ABI and the full set of standard and extended configuration page layouts used by the legacy Fusion SCSI, FC, SAS, LAN, RAID, BIOS, and manufacturing paths. It is a protocol contract header rather than executable code: driver code fills `MSG_CONFIG`, sends it through `mpt_config()`, and interprets the returned page buffers using the `CONFIG_PAGE_*` structures and `MPI_*` bit definitions in this file.

Important APIs, types, and structures: the common page wrappers are `CONFIG_PAGE_HEADER`, `CONFIG_PAGE_HEADER_UNION`, and `CONFIG_EXTENDED_PAGE_HEADER`. `MSG_CONFIG` and `MSG_CONFIG_REPLY` define the request/reply envelope, including action, function, context, page address, normal or extended header fields, and an SGE pointing at the page buffer. Action constants cover page header fetch, current/default/NVRAM reads, current writes, and NVRAM writes. Page type constants cover IO Unit, IOC, BIOS, SCSI Port, SCSI Device, FC Port, FC Device, LAN, RAID Volume, Manufacturing, RAID PhysDisk, Inband, and Extended pages; extended page types cover SAS IO Unit, SAS Expander, SAS Device, SAS PHY, Log, and Enclosure. Page-address macros encode SCSI bus/target and target-mode forms, FC port and device addressing, physical disk numbers, SAS expander/device/PHY/enclosure handles or table indexes, and get-next traversal forms. The page families include `CONFIG_PAGE_MANUFACTURING_0` through `_10`, `CONFIG_PAGE_IO_UNIT_0` through `_4`, `CONFIG_PAGE_IOC_0` through `_6`, `CONFIG_PAGE_BIOS_1`, `_2`, and `_4`, `CONFIG_PAGE_SCSI_PORT_0` through `_2`, `CONFIG_PAGE_SCSI_DEVICE_0` through `_3`, `CONFIG_PAGE_FC_PORT_0` through `_10`, `CONFIG_PAGE_FC_DEVICE_0`, `CONFIG_PAGE_RAID_VOL_0` and `_1`, `CONFIG_PAGE_RAID_PHYS_DISK_0` and `_1`, `CONFIG_PAGE_LAN_0` and `_1`, `CONFIG_PAGE_INBAND_0`, `CONFIG_PAGE_SAS_IO_UNIT_0` through `_3`, `CONFIG_PAGE_SAS_EXPANDER_0` and `_1`, `CONFIG_PAGE_SAS_DEVICE_0` through `_2`, `CONFIG_PAGE_SAS_PHY_0` and `_1`, `CONFIG_PAGE_SAS_ENCLOSURE_0`, and `CONFIG_PAGE_LOG_0`.

Control flow: this header does not execute control flow itself, but it defines the firmware transaction sequence used throughout the Fusion driver. Callers normally initialize a page header with page type, page number, and optionally extended page type, issue `MPI_CONFIG_ACTION_PAGE_HEADER` through `mpt_config()` to learn the page length/version, allocate or point `cfg.physAddr` at a page buffer, then issue `MPI_CONFIG_ACTION_PAGE_READ_CURRENT`, `READ_NVRAM`, `READ_DEFAULT`, `WRITE_CURRENT`, or `WRITE_NVRAM`. In `mptbase.c`, `mpt_config()` copies these fields into `MSG_CONFIG`, special-cases extended headers by filling `ExtPageLength` and `ExtPageType`, writes `PageAddress`, sets the SGE, and waits for the reply. Protocol drivers use the resulting page types directly: `mptspi.c` reads and writes SCSI device/port pages for negotiation settings, `mptsas.c` reads SAS IO Unit, PHY, Device, Expander, Enclosure, RAID Volume, and RAID PhysDisk pages for topology and RAID state, `mptfc.c` reads FC Device and FC Port pages for rport registration and link information, `mptctl.c` exposes manufacturing and SCSI device page access to control paths, and `mptbase.c` reads IO Unit, IOC, LAN, manufacturing, RAID, and SCSI inventory pages during adapter bring-up.

State and persistence behavior: the header defines firmware state surfaces, not kernel-owned state. Page attributes identify read-only, changeable, persistent, and read-only persistent pages. Runtime reads observe current IOC state such as discovered SAS topology, negotiated SCSI parameters, FC link counters, LAN status, RAID volume/physical disk state, and log entries. Persistent/NVRAM writes can change adapter behavior across resets, including IO Unit flags, BIOS boot preferences, manufacturing RAID policy defaults, SCSI negotiation policy, FC port behavior, and SAS persistent mapping settings. Several variable-length pages intentionally declare one-element arrays or flexible arrays with `__counted_by`; host code is repeatedly instructed to leave local maximum defines at one and trust `Header.PageLength`, `NumPhys`, `NumActiveVolumes`, `NumPhysDisks`, `NumPersistentIDsUsed`, or similar runtime counts when allocating and parsing buffers.

Dependencies and integration points: depends on base MPI scalar types (`U8`, `U16`, `U32`, `U64`), `MPI_POINTER`, MPI SGE unions (`SGE_IO_UNION`, `SGE_SIMPLE_UNION`), version structs, and protocol constants from sibling Fusion headers such as `mpi.h`, `mpi_ioc.h`, and `mpi_sas.h`. It is included by `mptbase.h`, which makes the page definitions available to the base adapter layer and all Fusion protocol drivers. It integrates with kernel DMA/SGL handling through config page buffers, with libata/SAS/SCSI/FC transport integration through the protocol drivers that consume SAS/FC/SCSI pages, and with RAID management through IOC, RAID Volume, RAID PhysDisk, manufacturing, BIOS, enclosure, and SEP-related config data.

Risks and edge cases: structure layout is a firmware ABI, so field type, order, width, and implicit padding changes can break hardware communication even if the C compiler accepts them. Endianness conversion is the responsibility of callers when filling request fields and parsing page data; the header's raw integer fields are not self-converting. Page length and count fields must be trusted over local placeholder array sizes to avoid truncating variable-length pages. Extended pages require `PageType` set to `MPI_CONFIG_PAGETYPE_EXTENDED` and the correct `ExtPageType`; confusing normal and extended headers produces invalid requests. Page-address bit packing is easy to get wrong, especially get-next forms for FC/SAS discovery and bus/target forms for SCSI and FC devices. Persistent writes are high impact because `WRITE_NVRAM` can alter boot, mapping, RAID, and negotiation behavior across resets. Some definitions contain historical/legacy aliases and misspellings that are part of the ABI surface; cleanups must not change numeric values or names used by old code. Flexible arrays and `__counted_by` annotations improve bounds reasoning but require allocation from firmware-reported lengths in all callers.

Test signals: build coverage should include the Fusion base, SPI, SAS, FC, and ctl paths that include `mptbase.h`. Runtime signals include successful `mpt_config()` header/read cycles for normal pages, extended SAS pages, and variable-length pages; correct handling of zero or larger-than-one counts; successful SCSI negotiation reads/writes in `mptspi`; SAS topology discovery and enclosure/PHY/device page reads in `mptsas`; FC rport discovery from FC Device Page 0 and link speed logging from FC Port Page 0 in `mptfc`; and RAID volume/physdisk inventory through IOC and RAID pages. Negative tests should include invalid page addresses, unsupported page numbers, timeout paths in `mpt_config()`, and ensuring NVRAM write paths are not reached except through explicit configuration changes.
