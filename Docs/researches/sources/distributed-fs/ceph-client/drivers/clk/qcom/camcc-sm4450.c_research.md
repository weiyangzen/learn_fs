# sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm4450.c

Purpose: implements the SM4450 camera clock controller. It registers SM4450 CAM_CC clocks, resets, and the top camera GDSC for BPS, CAMNOC, CCI 0/1, CRE, ICP, MCLKs, OPE, TFE 0/1, CSI PHY timers, CSIPHYs, CPAS/core AHB, and system timer clocks.

Important APIs/types/functions: this driver uses Lucid Evo and Rivian Evo PLL support. PLL0, PLL1, PLL3, and PLL4 are Lucid Evo PLLs; PLL2 is a Rivian Evo PLL. `alpha_pll_config` constants program nominal PLL rates including 1200 MHz PLL0, 600 MHz PLL1, 960 MHz PLL2, 600 MHz PLL3, and 700 MHz PLL4. PLL postdivs expose even and, for PLL0, odd outputs. Eight parent maps describe hardware mux values for XO and PLL outputs. `clk_rcg2` sources cover BPS, CAMNOC AXI, CCI, CPHY, CRE, CSI timers, fast/slow AHB, ICP, MCLK, OPE, and TFE clocks. Branch gates use `clk_branch2_ops` and halt registers. `cam_cc_camss_top_gdsc` models the single top power domain. `cam_cc_sm4450_resets` maps reset IDs to BCR offsets. `cam_cc_sm4450_probe()` configures all five PLLs and registers the descriptor.

Control flow: the platform driver binds to `qcom,sm4450-camcc`. Probe maps the CAM_CC MMIO range with `qcom_cc_map()`, configures PLLs using `clk_lucid_evo_pll_configure()` and `clk_rivian_evo_pll_configure()`, then calls `qcom_cc_really_probe()`. After registration, the clock framework handles rate requests by selecting the RCG entry, parent source, and divider. Most RCGs use `clk_rcg2_shared_ops`, reflecting a design where camera RCGs are shared and may need coordinated parent switching during disable.

State and persistence behavior: state is hardware register state only. Static tables define legal rates, mux values, enable registers, reset registers, and the descriptor arrays. The top GDSC at `0x14004` includes wait values and `POLL_CFG_GDSCR | RETAIN_FF_ENABLE`; it can retain flip-flop state across power collapse. Reset state is exposed through `qcom_reset_map` offsets and managed by the common reset support. No runtime PM state is explicitly acquired in this file.

Dependencies/integration points: depends on `dt-bindings/clock/qcom,sm4450-camcc.h`, Linux CCF/regmap/platform infrastructure, Qualcomm clock helpers, `gdsc.h`, and `reset.h`. Camera and media drivers consume the named clock IDs, reset IDs, and the `CAM_CC_CAMSS_TOP_GDSC` power domain from device tree. The regmap maximum is `0x16024`, matching the highest CRE/reset area used by the descriptors.

Risks: SM4450 has a dense reset map and multiple PLL types, so using the wrong configure helper or PLL register type would produce bad rates. MCLK entries depend on PLL2 main/even parents and fractional M/N settings, making sensor-clock accuracy sensitive to table mistakes. Several branch clocks use `BRANCH_HALT_DELAY` or regular halt polling; wrong halt policy can create false probe/runtime failures. Since only a top GDSC is exposed, consumers that expect per-block GDSCs must align with the binding. Reset offsets are hand-coded and can affect unrelated camera blocks if incorrect.

Test signals: compile coverage should include the SM4450 CAMCC object and binding header consistency. Runtime checks include probe on a `qcom,sm4450-camcc` node, successful reset controller registration, `clk_summary` rates matching BPS/OPE/TFE/MCLK tables, camera sensor MCLK measurement for 19.2/24/64 MHz paths, TFE/OPE/BPS enable-disable cycles without halt timeouts, and GDSC retention behavior during camera suspend/resume.
