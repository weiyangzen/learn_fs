# sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sa8775p.c

Purpose: Qualcomm CAMCC driver for SA8775P and the closely related QCS8300 camera clock controller. It registers camera clocks, resets, and the Titan top GDSC for a larger camera subsystem including four CCI instances, CSI PHY timers, CSID, IFEs, IPE, SFE lite blocks, CPAS bridge clocks, debug/observe clocks, sleep/XO roots, and MCLKs.

Important APIs/types/functions: The file defines Lucid EVO and Rivian EVO VCO tables, alpha PLL configs for PLL0/PLL2/PLL3/PLL4/PLL5, postdivs for even/odd outputs, parent maps for TCXO, TCXO_AO, sleep, and internal PLL outputs, `freq_tbl` instances for every RCG, branch gates for all exported clocks, `cam_cc_titan_top_gdsc`, `cam_cc_sa8775p_clocks`, `cam_cc_sa8775p_gdscs`, `cam_cc_sa8775p_resets`, `cam_cc_sa8775p_regmap_config`, and `cam_cc_sa8775p_desc`. `cam_cc_sa8775p_probe()` is the central function because it manually handles runtime PM, maps the regmap, configures PLLs, applies QCS8300-specific register/table mutations, enables a few always-on branches, and then calls `qcom_cc_really_probe()`.

Control flow: the platform driver matches both `qcom,qcs8300-camcc` and `qcom,sa8775p-camcc`. Probe enables runtime PM, resumes the device, maps CAMCC registers with `qcom_cc_map()`, configures all PLLs with the proper Lucid/Rivian helper, and then branches on `device_is_compatible(..., "qcom,qcs8300-camcc")`. For QCS8300, it rewrites selected `cmd_rcgr`, branch halt, and enable registers to the QCS8300 layout, moves the Titan GDSC register, nulls unsupported fourth-lane CCI/CSI/MCLK clocks, exposes the Titan top accumulator shift clock, and enables QCS8300-specific CAMNOC_XO/GDSC/SLEEP CBCRs. For SA8775P, it enables the corresponding SA8775P always-on CBCRs without mutating the table. It then registers clocks/GDSCs/resets with `qcom_cc_really_probe()` and releases the runtime PM reference.

State and persistence: static descriptors are mutated at probe time for the QCS8300 compatible, so the effective clock table is runtime-selected and process-global for the module instance. Hardware register state contains PLL programming, branch enables, reset lines, and GDSC state. The driver holds no persistent storage. Runtime PM is used only to keep the register block accessible during probe and registration; the final provider state is managed by CCF/GDSC consumers.

Dependencies and integration: depends on Linux runtime PM, regmap, platform devices, Qualcomm common clock helpers, GDSC/reset support, and the binding header `dt-bindings/clock/qcom,qcs8300-camcc.h`. It integrates with camera and CPAS clients through clock IDs, reset IDs, and the CAM_CC_TITAN_TOP_GDSC power domain. It also depends on Device Tree compatible selection to distinguish SA8775P and QCS8300 register layouts.

Risks: probe mutates static global clock descriptors for QCS8300, which is acceptable for a single CAMCC instance but risky if multiple compatibles were ever instantiated in one kernel lifetime. The QCS8300 path nulls unsupported clock indices; consumers using those binding IDs should receive missing clocks rather than touching invalid registers, so DT and consumer drivers must be compatible-specific. Always-on branch offsets differ between SA8775P and QCS8300; using the wrong compatible can enable the wrong CBCRs. Many branches share similar names but different offsets and halt modes, including a `BRANCH_HALT_SKIP` observe/debug clock, so offset regressions can be hard to spot without hardware testing. Runtime PM error paths must keep `pm_runtime_put()` balanced after successful resume.

Test signals: boot both `qcom,sa8775p-camcc` and `qcom,qcs8300-camcc` DTs if hardware is available. Verify qcs8300 hides CCI3/CSI3/CSIPHY3/MCLK3 resources and exposes Titan top accumulator shift, while SA8775P keeps the full table. Check clk debugfs for PLL0/2/3/4/5 and RCG rates, confirm CAMNOC_XO/GDSC/SLEEP CBCRs are enabled at the compatible-specific offsets, exercise IFE/IPE/SFE lite/CSID/CPAS/MCLK clocks, assert resets, toggle the Titan top GDSC, and run suspend/resume with camera clients to catch runtime PM or always-on clock mistakes.
