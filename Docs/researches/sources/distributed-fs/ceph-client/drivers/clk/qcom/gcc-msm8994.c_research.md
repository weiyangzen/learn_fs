# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-msm8994.c

Purpose: Qualcomm global clock controller driver for MSM8994 and the closely related MSM8992 variant. It publishes GCC clocks, resets, and several GDSC power domains for storage, USB3, PCIe, BLSP, SDCC, PDM, TSIF, low-power/audio/modem fabric, and general-purpose clocks.

Important APIs, types, and functions: this file uses Qualcomm common clock data structures rather than custom runtime logic. GPLL0 and GPLL4 are modeled as `struct clk_alpha_pll` early clocks plus `struct clk_alpha_pll_postdiv` exported outputs. Parent selection is represented by `gcc_xo_gpll0_map`, `gcc_xo_gpll0_gpll4_map`, and matching `clk_parent_data` arrays. RCGs use `struct clk_rcg2` and per-clock `freq_tbl` tables for UFS AXI, USB3 master/mock UTMI/PHY aux, BLSP I2C/SPI/UART, GP1-3, PCIe aux/pipe, PDM2, SDCC1-4, TSIF, and USB HS system clocks. Branch gates use `struct clk_branch`; resets use `struct qcom_reset_map`; power domains use `struct gdsc`. `gcc_msm8994_desc` is the controller descriptor passed to `qcom_cc_probe()`.

Control flow: `core_initcall(gcc_msm8994_init)` registers the platform driver. The match table accepts `"qcom,gcc-msm8992"` and `"qcom,gcc-msm8994"`. Probe checks for the MSM8992 compatible before registration. On MSM8992, it mutates `gcc_msm8994_desc.clks[]` entries to remove unsupported UFS, LPASS Q6 AXI, and PCIe1-related clocks; it also replaces SDCC1 and many BLSP QUP frequency tables with MSM8992-specific tables. After this compatibility adjustment, probe delegates to `qcom_cc_probe()`, which maps registers, registers clock providers, reset controllers, and GDSCs using `gcc_msm8994_desc`.

State and persistence: hardware state is the GCC MMIO register block with a maximum register offset of `0x2000`. Software state is static descriptor data; the probe mutates the shared `gcc_msm8994_desc.clks` array and several RCG `freq_tbl` pointers for MSM8992. There is no persistent storage beyond hardware register state. Some clock slots are deliberately `NULL` to preserve ABI for dt-binding IDs that should no longer be managed by this driver, including `CONFIG_NOC_CLK_SRC`, `PERIPH_NOC_CLK_SRC`, `SYSTEM_NOC_CLK_SRC`, and the nonexistent aggregate `PCIE_GDSC`.

Dependencies and integration points: depends on the common clock framework, Qualcomm alpha PLL/RCG/branch helpers, qcom CC common probe, reset support, GDSC support, regmap, platform driver infrastructure, and `dt-bindings/clock/qcom,gcc-msm8994.h`. Consumers use the dt-binding IDs in `gcc_msm8994_clocks[]`, `gcc_msm8994_resets[]`, and `gcc_msm8994_gdscs[]`. External clock parents are primarily firmware clocks named `xo` and `sleep`, plus in-driver GPLL outputs. Major integration surfaces are BLSP1/2 serial controllers, SDCC1-4, USB HS/USB3, PCIe0/1, UFS, TSIF, PDM, PRNG/boot ROM, LPASS/MSS fabric, and PHY LDO pseudo-clocks.

Notable data model details: the PLL exports use early alpha PLL objects (`gpll0_early`, `gpll4_early`) feeding post-dividers (`gpll0`, `gpll4`). Many BLSP and SDCC roots use fractional M/N/D frequency entries, and SDCC clocks use floor ops to avoid over-clocking consumers. PCIe and UFS symbol or pipe clocks use delayed or skipped halt checks where hardware cannot provide immediate normal halt semantics. Several PHY LDO controls are represented as branch clocks with `BRANCH_HALT_SKIP`. GDSCs cover PCIe0, PCIe1, USB30, and UFS power domains with simple off/on power states.

Risks and edge cases: MSM8992 probe mutates shared static clock descriptors in place, so the driver is effectively designed for one GCC instance; binding mixed compatibles in one kernel instance would leave global state altered. Because unsupported MSM8992 clocks are nulled at runtime, consumers requesting those IDs should fail cleanly but may expose board DTS mistakes. ABI-preserving `NULL` slots are intentional and must not be compacted. Register offsets are dense and low-level; branch halt policy changes can create enable timeouts or false-success states for PCIe/UFS/USB PHY clocks. Some comments note that PCIe1 may exist on unusual MSM8992 boards but is disabled by default, so board support that needs it would require careful compatible-specific changes. Parent names `xo` and `sleep` must be provided by firmware/DT clock providers.

Test signals: boot an MSM8994 board and confirm UFS, USB3, PCIe0/1, BLSP, SDCC, and GDSCs register and operate. Boot an MSM8992 board and confirm UFS and PCIe1 clocks are absent, MSM8992-specific BLSP/SDCC rates are selected, and no consumer incorrectly references removed IDs. Inspect `/sys/kernel/debug/clk/clk_summary` for GPLL0/GPLL4, SDCC, BLSP, USB, PCIe, UFS, and GP rates. Functional validation should cover UART/I2C/SPI on both BLSP blocks, SD card/eMMC timing modes, USB HS and USB3 enumeration, PCIe link training where present, UFS only on MSM8994, reset control for USB3/PCIe/MSS/QUSB2, and repeated runtime PM or suspend/resume cycles across the PCIe/USB30/UFS GDSCs.
