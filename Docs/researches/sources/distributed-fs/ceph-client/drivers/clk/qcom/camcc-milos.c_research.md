# sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-milos.c

Purpose: Qualcomm CAM_CC clock controller driver for the Milos platform. It describes the camera clock controller's PLLs, root clock generators, branch gates, reset lines, critical always-on CBCRs, and the CAMSS top GDSC so Device Tree camera consumers can request stable clock, reset, and power-domain resources through the common clock framework.

Important APIs/types/functions: The file is data-driven around `struct clk_alpha_pll`, `struct clk_alpha_pll_postdiv`, `struct clk_rcg2`, `struct clk_branch`, `struct gdsc`, `struct qcom_reset_map`, `struct qcom_cc_driver_data`, and `struct qcom_cc_desc`. `cam_cc_pll0` through `cam_cc_pll6` use Lucid OLE and Rivian EVO register layouts with fixed alpha PLL configurations and even/odd postdiv outputs where exposed. Parent maps connect DT clocks `bi_tcxo`, `sleep_clk`, and `iface` plus internal PLL outputs to the RCGs. Frequency tables cover BPS, CAMNOC AXI, CCI, CPHY RX, CRE, CSI PHY timers, fast/slow AHB, ICP, five MCLKs, OPE, TFE/TFE CSID, sleep, and XO sources. The final registration data is `cam_cc_milos_clocks`, `cam_cc_milos_resets`, `cam_cc_milos_gdscs`, `cam_cc_milos_plls`, `cam_cc_milos_critical_cbcrs`, `cam_cc_milos_regmap_config`, `cam_cc_milos_driver_data`, and `cam_cc_milos_desc`. `cam_cc_milos_probe()` is intentionally small and delegates to `qcom_cc_probe()`.

Control flow: module loading registers a platform driver matching `qcom,milos-camcc`. Probe calls `qcom_cc_probe(pdev, &cam_cc_milos_desc)`, which maps the MMIO range described by the DT node, initializes/configures alpha PLLs from `driver_data`, enables the listed critical CBCRs, registers all `clk_regmap` clocks, exposes reset controls, and registers the GDSC power domain. Runtime clock operations are then handled by the common Qualcomm clock drivers: RCGs select parents and divisors from the `F(...)` tables, branches program CBCR enable bits and poll halt registers, PLL postdivs adjust fixed divisors while propagating rate changes through `CLK_SET_RATE_PARENT`, and reset requests toggle the mapped BCR offsets.

State and persistence: there is no persistent software state. Static tables encode SoC register offsets, parent topology, PLL programming values, rate tables, reset offsets, and power-domain metadata. Runtime state lives in hardware registers and in CCF/GDSC registrations established during probe. The descriptor sets `.use_rpm = true`, so integration must account for RPM-managed handoff/voting behavior. `cam_cc_milos_critical_cbcrs` keeps CAM_CC_GDSC_CLK and CAM_CC_SLEEP_CLK enabled to preserve controller/power-domain infrastructure.

Dependencies and integration: depends on Linux CCF, regmap MMIO, platform bus probing, Qualcomm `clk-alpha-pll`, `clk-rcg`, `clk-branch`, `clk-regmap`, `gdsc`, `reset`, and `common` helpers, plus the DT binding IDs from `dt-bindings/clock/qcom,milos-camcc.h`. Camera stack consumers obtain clocks and resets by the binding indices in `cam_cc_milos_clocks` and `cam_cc_milos_resets`; power-domain users reference `CAM_CC_CAMSS_TOP_GDSC`.

Risks: the clock table must exactly match the DT binding enum ordering and supported hardware topology; a wrong index can silently hand a consumer the wrong clock. PLL register layout selection is mixed (`CLK_ALPHA_PLL_TYPE_LUCID_OLE` tables but Lucid EVO ops for base PLLs), so future edits need to preserve the known-compatible combination. Frequency table entries include fractional divisors and parent choices; incorrect values can overclock camera blocks or break sensor timing. Branch halt mode selection varies between normal, delay, and voted gates, and wrong polling can cause enable/disable timeouts. Critical CBCR and RPM settings affect power collapse, so removing them can break suspend or camera bring-up.

Test signals: build with the Milos CAMCC binding enabled and boot a `qcom,milos-camcc` DT node. Verify `/sys/kernel/debug/clk/clk_summary` exposes PLLs, RCGs, branch clocks, five MCLKs, TFE/OPE/BPS/ICP/CRE paths, and CAMNOC clocks at expected rates. Exercise camera sensor probe, MCLK rate changes, CSI PHY timer clocks, TFE capture paths, reset assertions for each BCR, CAMSS top GDSC on/off transitions, suspend/resume, and absence of branch halt warnings. Compare debugfs register-backed rates against the frequency tables and confirm CAM_CC_GDSC_CLK/CAM_CC_SLEEP_CLK stay enabled.
