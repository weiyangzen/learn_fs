# sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sm8150.c

Purpose: implements the SM8150 camera clock controller. It exposes the CAM_CC clock tree, resets, and GDSCs for BPS, CAMNOC, CCI 0/1, CPAS, CSI PHYs and timers, FD, ICP, IFE 0/1, IFE lite 0/1, IPE 0/1, JPEG, LRME, MCLK0-3, slow AHB, and PLL outputs.

Important APIs/types/functions: this driver uses Trion PLLs for PLL0/1/3/4 and a Regera PLL for PLL2. It defines VCO tables, `alpha_pll_config` data, even/odd/main postdivs, and five parent maps. RCG tables cover BPS, CAMNOC AXI, CCI, CPHY, CSI timers, fast/slow AHB, FD core, ICP, IFE/IFE lite, IPE, JPEG, LRME, and MCLK. Branch clocks use `clk_branch2_ops` with halt registers; most high-level clocks set `CLK_SET_RATE_PARENT`. GDSCs cover titan top plus BPS, IFE0/1, and IPE0/1. `cam_cc_sm8150_resets` maps many camera block reset IDs. `cam_cc_sm8150_probe()` includes runtime-PM handling, PLL setup, an always-on GDSC clock, descriptor registration, and PM release.

Control flow: the platform driver matches `qcom,sm8150-camcc`. Probe enables runtime PM, resumes the device, maps CAM_CC registers, configures PLL0/1/3/4 with `clk_trion_pll_configure()` and PLL2 with `clk_regera_pll_configure()`, keeps `cam_cc_gdsc_clk` enabled through `qcom_branch_set_clk_en(regmap, 0xc1e4)`, registers clocks/resets/GDSCs through `qcom_cc_really_probe()`, then drops the runtime-PM reference. Normal clock control is then handled by CCF and the Qualcomm reset/GDSC frameworks.

State and persistence behavior: static tables define the entire topology and binding-visible ID arrays. Runtime hardware state includes PLL configuration, RCG choices, branch enable bits, reset lines, and GDSC state. The driver explicitly holds the device active during probe using runtime PM because register access depends on the device being powered. All GDSCs use `POLL_CFG_GDSCR` and are parented under `titan_top_gdsc` where appropriate. Resets are volatile register writes through the common reset controller.

Dependencies/integration points: depends on `<linux/pm_runtime.h>`, CCF, regmap, platform infrastructure, `dt-bindings/clock/qcom,camcc-sm8150.h`, Qualcomm Trion/Regera PLL helpers, branch/RCG helpers, reset support, and GDSC support. Camera/media drivers reference the clocks, resets, and power domains from SM8150 device trees. The regmap maximum is `0xe004`, which must cover all clock, reset, and GDSC offsets.

Risks: runtime-PM error handling is part of probe correctness; failed mapping must release the PM reference, and later register access assumes clocks/power are available. The always-on GDSC branch at `0xc1e4` is necessary for power-domain control. Reset offsets touch many camera blocks and can create broad failures if shifted. Trion/Regera PLL configuration fields are detailed and hardware-specific; wrong VCO/config values can destabilize rates. Shared RCGs and `CLK_SET_RATE_PARENT` affect multiple camera consumers, so parent retuning needs real hardware validation.

Test signals: build coverage with PM runtime enabled, dt-binding validation for `qcom,sm8150-camcc`, successful probe with balanced runtime-PM usage, reset-controller registration, `clk_summary` rates for Trion/Regera-derived outputs, confirmation that `cam_cc_gdsc_clk` is enabled, camera bring-up across IFE/IFE lite/IPE/BPS/JPEG/LRME, reset toggling for camera blocks, and suspend/resume tests that verify GDSCs and runtime PM interact correctly.
