# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-ipq806x.c

## Purpose
`gcc-ipq806x.c` is the Qualcomm GCC provider for IPQ8064/IPQ8065-era SoCs. It registers legacy qcom PLLs, HFPLLs, RCG and dynamic-RCG roots, branch gates, and reset lines for the `qcom,gcc-ipq8064` compatible. It exposes the clock and reset IDs defined by `qcom,gcc-ipq806x.h` to platform devices covering GSBI serial blocks, SD controllers, TSIF, DMA/BAM/ADM, PMIC/RPM interfaces, PCIe, SATA, USB, EBI2, GMAC, NSS/UBI32, and CE5 crypto.

## Important APIs, Types, And Functions
The file uses the older qcom clock object set: `struct clk_pll`, `struct clk_regmap` PLL vote clocks, `struct hfpll_data`, `struct clk_hfpll`, `struct clk_rcg`, `struct clk_dyn_rcg`, and `struct clk_branch`. It registers board PXO/CXO clocks at probe with `qcom_cc_register_board_clk()`, selects the correct NSS UBI32 frequency table based on `of_machine_is_compatible("qcom,ipq8065")`, registers descriptors with `qcom_cc_probe()`, then obtains the regmap with `dev_get_regmap()` for post-registration hardware setup.

Key arrays are `gcc_ipq806x_clks[]`, mapping binding IDs to every PLL, RCG, branch, HFPLL, NSS, GMAC, USB, storage, and CE5 object; `gcc_ipq806x_resets[]`, mapping reset IDs to registers and bits; and `gcc_ipq806x_desc`, which passes clocks and resets to the common qcom CC layer. `gcc_ipq806x_probe()` is the only custom control function, and `of_platform_populate()` is used after clock registration so child devices under the GCC node can bind.

## Control Flow
Initialization is platform-driver based from `core_initcall(gcc_ipq806x_init)`. Probe first creates fixed 25 MHz `cxo` and `pxo` board clocks, then assigns `clk_tbl_nss_ipq8064` or `clk_tbl_nss_ipq8065` to both UBI32 core dynamic RCGs. `qcom_cc_probe()` maps and registers the provider. After successful provider registration, the driver writes PLL18 static configuration bits and GMAC footswitch sleep/wakeup values, then populates child platform devices below the GCC device-tree node.

The clock tree is otherwise declarative. Early descriptors define PLL0, PLL3, PLL8, PLL11, PLL14, PLL18, voted PLL0/4/8/14 paths, and CPU HFPLLs for two cores plus L2. RCG tables then derive GSBI UART/QUP rates, GP rates, PRNG, SD card rates, TSIF, PCIe and SATA 100 MHz references, USB 60/125 MHz roots, GMAC/NSS/UBI32 dynamic roots, and CE5 crypto roots. Branch clocks gate the leaves and optionally use hardware clock gating (`hwcg_reg`/`hwcg_bit`) or voted halt checks. The dynamic RCGs provide dual-bank rate switching for GMAC, NSS TCM, UBI32 cores, and CE5 paths.

## State And Persistence
Persistent state is limited to static descriptors and live GCC register values; no disk or NVRAM state is used. Probe-time board clock registration creates fixed parent clocks for this boot. The IPQ8065 compatibility check mutates the two UBI32 dynamic-RCG `freq_tbl` pointers before registration, making the supported NSS rates SoC-specific. PLL18 static register writes and GMAC footswitch writes persist until reset. HFPLLs are marked `CLK_IGNORE_UNUSED` to keep CPU/L2 PLLs from unused-clock cleanup, and selected GSBI/QUP clocks also carry `CLK_IGNORE_UNUSED` because board firmware or early console paths may rely on them.

## Dependencies And Integration Points
The driver depends on qcom common clock/reset helpers, the legacy PLL/RCG/HFPLL implementations, Linux CCF, OF platform population, and the IPQ806x binding headers. It integrates with board DT through the GCC compatible and fixed parent names `pxo`, `cxo`, `pxo_board`, and `cxo_board`. Consumers include serial/I2C/SPI drivers on GSBI1/2/4/5/6/7, SDHCI for SDC1/SDC3, PRNG, TSIF, BAM/ADM DMA, PMIC arbiter and RPM message RAM, PCIe controllers 0/1/2, SATA, USB HS/FS/USB3 controllers, EBI2, GMAC ports 1 through 4, NSS/UBI32 firmware, and CE5 crypto. Reset-controller integration covers fabric, QDSS, PCIe, SATA, USB, GSBI, SD, NSS, GMAC, crypto, and UBI32 reset lines.

## Risks
This file is sensitive to legacy hardware encodings. Parent maps reuse the same logical PLL parents with different selector values for PCIe, SATA, GMAC, NSS, and CE5, so a copied parent map with the wrong selector can produce a plausible but incorrect clock. Dynamic RCGs have two banks and a `mux_sel_bit`; incorrect bank registers or shared `bank_reg` values can glitch GMAC/NSS rates. The IPQ8064 versus IPQ8065 NSS table switch is global for both UBI32 core clocks and must happen before registration. Several clocks use `CLK_IGNORE_UNUSED`, so cleanup behavior differs from ordinary demand-gated clocks and can hide missing consumers. Probe writes PLL18 and GMAC footswitch registers after qcom CC registration; failures in those writes are not checked. Reset map breadth is large, and several reset names have active-low or hardware-specific semantics around NSS and UBI32 clamps, making bit polarity and register choice important.

## Test Signals
Expected boot signals include successful registration of `gcc-ipq806x`, creation of 25 MHz PXO/CXO board clocks, and successful population of GCC child devices. `clk_summary` should show PLL0/3/8/11/14/18, voted PLLs, HFPLL0/HFPLL1/HFPLL_L2, GSBI UART/QUP rates, SDC rates, PCIe/SATA 100 MHz references, USB 60/125 MHz roots, GMAC dynamic sources, NSS TCM and UBI32 dynamic sources, and CE5 crypto clocks. Hardware validation should cover UART console, GSBI I2C/SPI, SDC1/SDC3, PCIe ports 0 through 2, SATA, USB HS/FS/USB3, GMAC networking on all enabled ports, NSS firmware at IPQ8064 and IPQ8065-specific rates, CE5 crypto, and assert/deassert testing of representative reset lines. Regression signals include boot hangs from HFPLL cleanup, missing PXO/CXO parents, incorrect IPQ8065 NSS max rates, failed PCIe/SATA link clocks, and GMAC traffic loss around dynamic rate changes.
