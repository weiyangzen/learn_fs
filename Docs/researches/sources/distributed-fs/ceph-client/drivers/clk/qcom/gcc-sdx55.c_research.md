# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-sdx55.c

## Purpose
`gcc-sdx55.c` is the Qualcomm GCC provider for the SDX55 modem/platform SoC. It registers central clocks, resets, and GDSC power domains for BLSP1 serial controllers, CPUSS support clocks, Ethernet/EMAC, PCIe, USB3, SDCC1, crypto engine CE1, PDM, general-purpose clocks, and a small set of always-on/fabric paths. Compared with the SDM phone SoC drivers in this group, SDX55 is narrower and modem/networking oriented, with explicit EMAC and PCIe support and only one USB3/SDCC path.

## Important APIs, Types, And Functions
The driver uses `struct clk_alpha_pll` and `struct clk_alpha_pll_postdiv` with LUCID PLL ops for GPLL0, GPLL4, GPLL4 even, and GPLL5, plus a `pll_vco` table defining the supported LUCID VCO range. `struct clk_rcg2` and `struct freq_tbl` define rate roots for BLSP I2C/SPI/UART, CPUSS AHB/RBCPR, EMAC/RGMII/PTP, GP clocks, PCIe auxiliary/refchange PHY, PDM, SDCC1, USB3 master/mock/AUX, and related paths. `struct clk_branch` gates leaf clocks with normal, voted, delayed, or rate-parent-aware behavior. The provider is described through `gcc_sdx55_clocks[]`, `gcc_sdx55_resets[]`, `gcc_sdx55_gdscs[]`, and `gcc_sdx55_desc`.

The only custom function is `gcc_sdx55_probe()`. It maps the GCC regmap with `qcom_cc_map()`, forces selected system NoC/CPUSS clocks on with `qcom_branch_set_clk_en()` and `regmap_update_bits()`, and then registers the provider through `qcom_cc_really_probe()`. Driver registration is via `subsys_initcall(gcc_sdx55_init)`, and matching is for `qcom,gcc-sdx55`.

## Control Flow
At boot, the platform driver probes the GCC node, maps registers with a `regmap_config` covering 32-bit registers up to `0x9b040`, and performs three keep-on writes at register `0x6d008`: branch enable for `GCC_SYS_NOC_CPUSS_AHB_CLK`, bit 21 for `GCC_CPUSS_AHB_CLK`, and bit 22 for `GCC_CPUSS_GNOC_CLK`. These writes preserve critical CPU/fabric connectivity before the clock framework begins unused-clock management. After registration, CCF consumers drive all rate, parent, and gate changes through the shared qcom clock ops.

The declarative clock tree starts with `bi_tcxo`, `bi_tcxo_ao`, sleep, GPLL0 main/even, GPLL4 even, and GPLL5 parents. RCGs provide selectable rates for serial buses, Ethernet, PCIe, SDCC, USB3, and general-purpose outputs. Branches gate BLSP QUP/UART clocks, CE1, EMAC/ETH AXI/PTP/RGMII/AHB, PCIe link/master/slave/pipe/ref clocks, PDM, SDCC1, USB30 master/mock/AXI/AHB/sleep/PHY clocks, and XO/NoC helper clocks.

## State And Persistence
There is no persistent state outside hardware registers and CCF registration. Static descriptors define the clock topology; live hardware state tracks PLL enable, post-divider selection, RCG parent and divider programming, branch gates, reset lines, and GDSC power domains. Probe-time keep-on writes persist for the current boot and are not re-applied after a full hardware reset except by a new probe. GDSCs for USB30, PCIe, and EMAC use `PWRSTS_OFF_ON`, allowing power-domain consumers to sequence those blocks through Linux. Reset lines cover EMAC, PCIe core/link/PHY/PHY common, QUSB2PHY, USB30, USB3 PHY, USB3PHY PHY, and USB PHY CFG AHB2PHY.

## Dependencies And Integration Points
The driver depends on Linux platform, module, regmap, CCF, `dt-bindings/clock/qcom,gcc-sdx55.h`, and qcom common headers `common.h`, `clk-alpha-pll.h`, `clk-branch.h`, `clk-pll.h`, `clk-rcg.h`, `clk-regmap.h`, `gdsc.h`, and `reset.h`. Parent clocks are firmware-provided `bi_tcxo`, `bi_tcxo_ao`, and `sleep_clk`, plus in-file GPLLs. Integration points include BLSP1 I2C/SPI/UART controllers, CPUSS low-level bus support, CE1 crypto, EMAC/Ethernet MAC and PTP/RGMII clock consumers, PCIe controller and PHY, SDCC1, USB3 controller/PHY, PDM audio, and reset-controller clients for the same high-speed peripheral blocks.

## Risks
The explicit keep-on sequence is boot-sensitive. Removing or moving the `0x6d008` writes can allow unused-clock cleanup or early handoff to disable CPU/fabric clocks needed by the SoC. Parent-map encodings are sparse, with GPLL4 even and GPLL5 occupying different selector values from GPLL0 main/even; copying SDM-style maps into SDX55 can select incorrect Ethernet, PCIe, or USB rates. Ethernet has distinct source, PTP, RGMII, AXI, and AHB clocks plus an EMAC GDSC/reset, so partial enablement may probe but fail traffic or timestamping. Several PCIe and USB branches use voted or delayed halt checks; stricter polling can create false failures during PHY/link transitions. Reset offsets include PCIe link-down and PHY common resets, which are easy to misuse from consumers if binding IDs drift.

## Test Signals
Expected signals are successful `qcom,gcc-sdx55` probe, visible GPLL0/GPLL4/GPLL5 clocks, and no errors from `qcom_cc_really_probe()`. `clk_summary` should show the always-on system NoC/CPUSS paths enabled, BLSP1 QUP/UART roots, CPUSS RBCPR, EMAC source/PTP/RGMII/AXI/AHB clocks, PCIe aux/refchange/pipe/master/slave/link clocks, SDCC1 clocks, USB30 master/mock/sleep/AXI/AHB/PHY clocks, PDM, and CE1. Hardware validation should cover serial buses, Ethernet link and PTP timestamping, PCIe link training and link-down reset behavior, USB3 enumeration, SDCC1, CE1 crypto, suspend/resume with USB30/PCIe/EMAC GDSCs, and reset assert/deassert tests for EMAC, PCIe, and USB PHY/controller lines.
