# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-msm8976.c

Purpose: Qualcomm global clock controller driver for MSM8956/MSM8976-class SoCs. It describes the GCC register map, PLLs, root clock generators, branch gates, reset lines, and GDSC power domains that Linux exposes to device-tree consumers through the common clock, reset, and genpd frameworks.

Important APIs, types, and functions: the driver is almost entirely declarative data consumed by Qualcomm clock-controller helpers. PLL state is represented with `struct clk_pll`, `struct clk_regmap`, `struct pll_freq_tbl`, and `struct pll_config` for `gpll0`, `gpll2`, `gpll3`, `gpll4`, `gpll6`, and vote clocks. Clock parents are encoded by `struct parent_map`, `struct clk_parent_data`, and selected `clk_hw` parent arrays for in-driver PLL references plus firmware clocks such as `xo`, `xo_a`, DSI PLL, and DSI byte PLL inputs. Rate roots use `struct clk_rcg2` with `freq_tbl` tables and ops such as `clk_rcg2_ops`, `clk_rcg2_floor_ops`, `clk_byte2_ops`, and `clk_pixel_ops`. Leaf gates use `struct clk_branch` with `clk_branch2_ops`, branch halt policy fields, vote registers, and `CLK_SET_RATE_PARENT` where child rate changes must propagate to their root generator. Reset outputs use `struct qcom_reset_map`; power domains use `struct gdsc`. The exported aggregate is `gcc_msm8976_desc`, consumed by `qcom_cc_map()` and `qcom_cc_really_probe()`.

Control flow: module initialization registers a platform driver at `core_initcall()`. Device-tree matching accepts `"qcom,gcc-msm8976"` and `"qcom,gcc-msm8976-v1.1"`. Probe first applies the v1.1-specific SDCC1 source override when that compatible is present: it swaps the SDCC1 parent map from GPLL4 to GPLL2, changes the frequency table to `ftbl_sdcc1_8976_v1_1_apps_clk_src`, and replaces the `clk_init_data` with `sdcc1_apps_clk_src_8976v1_1_init`. It then maps the GCC register range with `qcom_cc_map()`, clears sleep/wakeup cycle fields for the GMEM clock, programs GPLL3 with `clk_pll_configure_sr_hpm_lp()`, enables the APSS AUX2 bit at `0x60000`, clears OXILI clock sleep cycles, and finally registers clocks, resets, and GDSCs through `qcom_cc_really_probe()`. Runtime enable, disable, rate, parent, reset, and GDSC control is delegated to the common clock, reset-controller, and Qualcomm GDSC frameworks using the static descriptors.

State and persistence: persistent state is hardware register state under the GCC MMIO block plus GDSC power-domain registers. Software state is file-scope static clock/GDSC descriptor data and the mapped regmap held by the qcom CC core after probe. The driver mutates a few static descriptors at probe for the v1.1 SDCC1 variant, so this module assumes only one compatible instance is bound in practice. Critical state includes `gpll0_vote` marked `CLK_IS_CRITICAL` and `apss_ahb_clk_src` marked critical because APSS fabric communication depends on it. No filesystem, NVRAM, or user-space persistence is used.

Dependencies and integration points: depends on Linux common clock provider APIs, Qualcomm clock helpers (`common.h`, `clk-pll.h`, `clk-rcg.h`, `clk-branch.h`), GDSC support, reset support, regmap, platform device probing, and dt-bindings IDs from `qcom,gcc-msm8976.h`. It integrates with consumers by stable clock IDs in `gcc_msm8976_clocks[]`, reset IDs in `gcc_msm8976_resets[]`, and GDSC IDs in `gcc_msm8976_gdscs[]`. External firmware clock names include `xo`, `xo_a`, `dsi0pll`, `dsi1pll`, `dsi0pllbyte`, and `dsi1pllbyte`. Major consumer domains include BLSP I2C/SPI/UART, CAMSS CSI/VFE/JPEG/CPP/MCLK, MDSS byte/pixel/MDP/vsync, GPU/OXILI, Venus video, SDCC/ICE, USB FS/HS, crypto, modem, APSS, and SMMU/TBU clocks.

Notable data model details: the clock array intentionally exposes both RCG sources and branch clocks by dt-binding index. Many branch clocks reference their associated RCG and set `CLK_SET_RATE_PARENT`, which lets peripheral drivers request rates on leaf clocks while the core updates the root generator. Display pixel and byte clocks use specialized pixel/byte ops and external DSI PLL parents. Some AHB/AXI/TBU clocks are vote clocks using shared vote registers (`0x45004`, `0x4500c`) rather than direct local gate bits. GDSCs include Venus core domains, MDSS, JPEG, VFE0/VFE1, CPP, and OXILI CX/GX; OXILI GX uses `supply = "vdd_gfx"` and `CLAMP_IO`, while OXILI CX is votable.

Risks and edge cases: all register offsets, parent map indexes, and dt-binding array indexes must exactly match downstream hardware documentation; a single wrong offset can disable the wrong fabric or return misleading rates. Probe-time mutation of static descriptors for v1.1 is not reentrant across multiple device instances. The `MODULE_DESCRIPTION` says `"QTI MSM8996 Global Clock Controller"` despite this being an MSM8956/8976 driver, which is likely a copy/paste metadata error. Critical clock annotations are important; removing them can hang the system. The GMEM/OXILI sleep-cycle and APSS AUX2 writes are undocumented side effects in this file and should be validated against hardware behavior before changing. External DSI parent names must match the display clock provider names or MDSS pixel/byte clocks will fail to resolve. GDSC CXC lists and clamp/supply metadata affect power sequencing and can cause GPU, camera, display, or video failures if incomplete.

Test signals: useful validation starts with booting an MSM8956/MSM8976 board and checking that `qcom,gcc-msm8976` or `qcom,gcc-msm8976-v1.1` probes without unresolved parent clocks or duplicate provider errors. Clock summary should show exported IDs, critical GPLL0/APSS clocks, and sane rates for BLSP, SDCC, USB, CAMSS, MDSS, Venus, and GPU paths. Functional tests should exercise UART/I2C/SPI transfers, SDCC1 high-speed modes on both base and v1.1 compatibles, USB FS/HS enumeration, display pixel-clock modes using DSI parents, camera capture paths through CSI/VFE/JPEG/CPP, Venus encode/decode, GPU power up/down, crypto, and reset consumers for USB/CAMSS/MSS. Suspend/resume and repeated power-domain cycling are important for GDSC and halt-check coverage.
