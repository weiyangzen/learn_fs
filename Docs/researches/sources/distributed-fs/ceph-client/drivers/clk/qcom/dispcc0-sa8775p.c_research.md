# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc0-sa8775p.c

Purpose: first SA8775P display clock-controller instance driver, binding `qcom,sa8775p-dispcc0`. It exposes one MDSS display clock island with two Lucid EVO PLLs, two DSI PHY inputs, two DP PHY inputs, DP crypto/link/pixel paths, MDP/pixel/vsync/AHB roots, resets, and two MDSS core GDSCs.

Important APIs/types/functions: the namespace is `mdss_0_disp_cc_*`. `mdss_0_disp_cc_pll0` and `mdss_0_disp_cc_pll1` use `CLK_ALPHA_PLL_TYPE_LUCID_EVO` and `clk_alpha_pll_lucid_evo_ops`; PLL0 is configured around the high MDP rates while PLL1 feeds AHB and other display roots. Parent data includes DT interface clock placeholder `DT_IFACE`, TCXO/AO TCXO, sleep, DP0/DP1 link and VCO-div clocks, and DSI0/DSI1 byte/DSI outputs. RCGs cover AHB, byte0/1, DPTX0/1 AUX/crypto/link/pixel0-3 where applicable, ESC0/1, MDP, pclk0/1, vsync, sleep, and XO. Dividers expose byte and read-only DPTX link divides. Branches gate the complete MDSS set plus `mdss_0_disp_cc_sm_obs_clk`. `disp_cc_0_sa8775p_desc` registers the clock table, two reset lines, and two GDSCs.

Control flow: `disp_cc_0_sa8775p_probe()` enables runtime PM, resumes hardware, maps registers with the descriptor, configures PLL0 and PLL1, forces the sleep and XO branches on by register offset, calls `qcom_cc_really_probe()`, drops the runtime PM reference, and returns the framework registration result. If mapping fails, it puts runtime PM and returns the mapped error. Unlike some newer DISPCC drivers, this probe does not explicitly set an MDP gating bit.

State and persistence: the driver stores no instance-private state. Hardware state persists in the mapped register block through PLL programming, RCG/divider registers, branch enable bits, reset registers, and GDSC registers at `0x9000` and `0xd000`. The regmap allows up to `0x12414`. The two GDSCs use `PWRSTS_OFF_ON`, `POLL_CFG_GDSCR`, `RETAIN_FF_ENABLE`, and `HW_CTRL`, so power switching is delegated to hardware and genpd after registration. The always-on sleep/XO writes keep low-frequency roots available for downstream display and retention behavior.

Dependencies and integration: depends on `dt-bindings/clock/qcom,sa8775p-dispcc.h`, compatible `qcom,sa8775p-dispcc0`, runtime PM, regmap, Qualcomm clock helpers, reset and GDSC frameworks, and parent clocks from GCC/TCXO/sleep, DSI PHYs, and DP PHYs. Consumers use shared `MDSS_DISP_CC_*` binding IDs, so this instance is distinguished by provider phandle rather than unique numeric IDs.

Risks: `dispcc0` and `dispcc1` are almost identical source files, so fixes can easily land in only one instance. Shared binding IDs require DT to reference the correct provider; swapping phandles can make a display pipeline control the wrong clock island. Several DPTX0 pixel roots expose four pixel clocks while DPTX1 exposes two; consumers must match the hardware lane/stream layout. The probe's map-failure path uses `pm_runtime_put()` rather than `pm_runtime_put_sync()`, unlike some neighboring drivers. Parent-map and static-name copy-paste errors are the main maintenance risk.

Test signals: boot SA8775P with the `dispcc0` node enabled, verify all `mdss_0_disp_cc_*` clocks in `clk_summary`, test MDP rates at 375/500/575/650 MHz, DSI byte/pixel roots, DP0 four-pixel and DP1 two-pixel paths, DP crypto/link clocks, reset lines for MDSS core and RSCC, and both GDSCs. Cross-test with `dispcc1` active to ensure providers remain independent and clock names do not collide unexpectedly.
