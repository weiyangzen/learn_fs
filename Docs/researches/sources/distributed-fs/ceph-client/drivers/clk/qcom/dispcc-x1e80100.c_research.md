# sources/distributed-fs/ceph-client/drivers/clk/qcom/dispcc-x1e80100.c

Purpose: display clock-controller driver for Qualcomm X1E80100 platforms. It registers the MDSS display clock tree for laptop-class Snapdragon hardware, including two Lucid-style display PLLs, DSI and DP roots for up to four DP PHY paths, MDP/pixel/vsync/AHB clocks, reset controls, and MDSS power domains.

Important APIs/types/functions: `disp_cc_pll0` and `disp_cc_pll1` are defined as Lucid OLE register layouts but are configured in probe with `clk_lucid_evo_pll_configure()`, with a shared VCO range up to 2.3 GHz. Parent maps include TCXO, always-on TCXO, sleep, DSI byte/DSI outputs, DP0-DP3 link clocks, DP VCO-div clocks, and PLL0/PLL1 main/even outputs. RCGs expose MDSS AHB, byte, DPTX AUX/link/pixel, ESC, MDP, pclk, vsync, sleep, and XO roots. Dividers model byte and read-only DPTX link dividers. Branch clocks gate ACCU, AHB, byte, DP link/pixel/USB-router, ESC, MDP/LUT, pclk, RSCC, and vsync outputs. `disp_cc_x1e80100_resets` additionally provides ARES resets for DPTX0/1/2 USB-router link interface clocks.

Control flow: `disp_cc_x1e80100_probe()` enables runtime PM, resumes the controller, maps registers, configures both PLLs with `clk_lucid_evo_pll_configure()`, enables the MDP clock-gating bit in `DISP_CC_MISC_CMD`, forces sleep and XO branches on, then registers the descriptor with `qcom_cc_really_probe()`. The platform driver is registered with `subsys_initcall()` rather than `module_platform_driver()`, making it available earlier in boot; module exit unregisters the driver if built as a module.

State and persistence: persistent state is hardware register programming plus static CCF/reset/GDSC registrations. The controller regmap uses 32-bit registers, stride 4, maximum register `0x11008`, and fast I/O. The GDSCs at `0x9000` and `0xa000` retain flip-flop state and are hardware-controlled with CFG polling. The driver forces sleep and XO clocks on at offsets `0xe074` and `0xe054` before registration. No private runtime data is allocated beyond framework-managed registrations.

Dependencies and integration: depends on `dt-bindings/clock/qcom,x1e80100-dispcc.h`, platform DT compatible `qcom,x1e80100-dispcc`, runtime PM, regmap, Qualcomm clock helpers, reset framework, and GDSC/genpd. It integrates with X1E display consumers, DSI/DP PHY clock providers, USB-router DP interface reset consumers, and MDSS power-domain consumers.

Risks: the PLL declaration names Lucid OLE register arrays while probe uses Lucid EVO configuration helpers; this may be intentional for shared register layout, but it is easy to break during cleanup. Early `subsys_initcall()` ordering can expose more probe-deferral paths if parent PHY clocks are not available. DPTX USB-router ARES reset entries are bit-level resets inside clock branch registers, so incorrect register offsets can impact active display links. The X1E DP parent maps differ from phone SoCs by allowing DP0 link on more paths; copy-paste from SM8550/SM8750 would be unsafe.

Test signals: boot X1E80100 with display DT, verify early driver registration, inspect `clk_summary` for all MDSS, DPTX0-DPTX3, MDP, pclk, sleep, and XO clocks, exercise DP USB-router interface resets, validate the MDSS core/INT2/RSCC resets, and confirm `MDSS_GDSC`/`MDSS_INT2_GDSC` power-domain control. Runtime PM error paths and parent-clock deferral should be covered because the driver probes early.
