# sources/distributed-fs/ceph-client/drivers/clk/qcom/camcc-sdm845.c

Purpose: implements the Qualcomm SDM845 camera clock controller platform driver. It exposes the CAM_CC clock tree and camera GDSC power domains used by SDM845 camera blocks: BPS, IPE 0/1, IFE 0/1/lite, JPEG, LRME, ICP, CCI, CSI PHY timers, CSIPHY, MCLKs, CAMNOC, and shared AHB/system clocks.

Important APIs/types/functions: the file is built from static common-clock-framework descriptors. `clk_alpha_pll` objects define four Fabia PLLs at offsets `0x0`, `0x1000`, `0x2000`, and `0x3000`, with even postdiv outputs. `parent_map`, `clk_parent_data`, and `freq_tbl` arrays describe mux selectors and legal rates for each RCG. `clk_rcg2` sources such as `cam_cc_bps_clk_src`, `cam_cc_ife_0_clk_src`, `cam_cc_ipe_0_clk_src`, `cam_cc_mclk0_clk_src`, and `cam_cc_slow_ahb_clk_src` feed `clk_branch` gates. `gdsc` instances model `bps_gdsc`, `ipe_0_gdsc`, `ipe_1_gdsc`, `ife_0_gdsc`, `ife_1_gdsc`, and `titan_top_gdsc`. `cam_cc_sdm845_clocks`, `cam_cc_sdm845_gdscs`, `cam_cc_sdm845_regmap_config`, and `cam_cc_sdm845_desc` form the registration contract. `cam_cc_sdm845_probe()` maps registers, configures PLLs, and calls `qcom_cc_really_probe()`.

Control flow: device-tree matching on `qcom,sdm845-camcc` binds the platform driver. Probe calls `qcom_cc_map()` with the descriptor, programs Fabia PLL alpha/L values for PLL0 through PLL3, then registers all clocks and GDSCs with the Qualcomm common clock controller core. After registration, runtime clock operations are table-driven through CCF callbacks: RCGs choose parents and dividers from their `freq_tbl`, branch clocks toggle enable bits and poll halt registers, and GDSCs manage power-domain state. The file explicitly uses `clk_rcg2_shared_ops` for several camera RCGs that must switch to XO during disable so camera memories power down gracefully; other RCGs use normal `clk_rcg2_ops`.

State and persistence behavior: the driver has no persistent filesystem state. Static descriptors encode all clock topology, register offsets, parent choices, frequencies, halt checks, and GDSC topology. Runtime state persists only in hardware registers accessed through regmap: PLL configuration, RCG command registers, branch enable registers, halt status, and GDSC control/status. Child GDSCs are parented to `titan_top_gdsc`; BPS/IPE domains use `HW_CTRL | POLL_CFG_GDSCR`, while IFE domains and top use `POLL_CFG_GDSCR`.

Dependencies/integration points: depends on Linux CCF, regmap, platform device matching, `dt-bindings/clock/qcom,camcc-sdm845.h`, and Qualcomm helpers from `common.h`, `clk-alpha-pll.h`, `clk-branch.h`, `clk-rcg.h`, `clk-regmap.h`, and `gdsc.h`. Consumers are camera/media drivers and device-tree nodes that reference CAM_CC clock IDs and GDSC IDs. The regmap range is capped at `0xd004`, so all encoded offsets must stay within that MMIO region.

Risks: most behavior is hardware-table driven, so wrong register offsets, mux values, divider values, parent maps, or binding IDs can silently expose unusable clocks. `CLK_SET_RATE_PARENT` is needed only where PLL rates must follow child requests; missing it can cause rate failures, while overusing it can retune shared parents unexpectedly. The shared-RCG disable path is important for graceful camera-memory power-down. GDSC parent/flag mistakes can break camera power sequencing. Probe reuses one local `alpha_pll_config`; missed field clearing would matter if more than `l` and `alpha` were programmed later.

Test signals: build coverage should include this file with `CONFIG_SDM_CAMCC_845` or equivalent kernel config coverage, plus dt-binding checks for `qcom,sdm845-camcc`. Runtime signals are successful probe, registered clock names under debugfs, expected PLL rates via `clk_summary`, successful camera pipeline bring-up, clean enable/disable cycles for IFE/IPE/BPS/JPEG/LRME/ICP clocks, and GDSC transitions without timeout or halt-poll warnings.
