# sources/distributed-fs/ceph-client/drivers/clk/qcom/gcc-ipq6018.c

## Purpose
`gcc-ipq6018.c` is the Qualcomm global clock controller provider for IPQ6018-class networking SoCs. It describes the GCC register block as Linux common clock framework objects and exposes clocks and resets through the device-tree IDs in `dt-bindings/clock/qcom,gcc-ipq6018.h` and `dt-bindings/reset/qcom,gcc-ipq6018.h`. The modeled topology covers the always-on XO and sleep sources, GPLL0/GPLL2/GPLL4/GPLL6, UBI32 Huayra PLL, NSS crypto PLL, NoC and APSS roots, NSS/PPE/EDMA/UNIPHY Ethernet paths, BLSP serial buses, PCIe, USB, SDCC/ICE, QPIC, QDSS tracing, WCSS, LPASS, and many reset lines.

## Important APIs, Types, And Functions
The file is structured around static clock descriptors consumed by the Qualcomm clock controller helpers. The parent selector enum defines hardware parent IDs such as `P_XO`, `P_GPLL0`, `P_GPLL0_DIV2`, `P_GPLL2`, `P_GPLL4`, `P_GPLL6`, `P_UBI32_PLL`, `P_NSS_CRYPTO_PLL`, UNIPHY RX/TX parents, pipe clocks, and firmware-provided bias/sleep sources. Parent arrays combine in-file `clk_hw` parents with firmware-named parents such as `xo`, `sleep_clk`, `uniphy*_gcc_*_clk`, `bias_pll_cc_clk`, `bias_pll_nss_noc_clk`, `pcie20_phy0_pipe_clk`, and `usb3phy_0_cc_pipe_clk`.

Major CCF object types are `struct clk_alpha_pll`, `struct clk_alpha_pll_postdiv`, `struct clk_fixed_factor`, `struct clk_rcg2`, `struct clk_regmap_div`, `struct clk_regmap_mux`, and `struct clk_branch`. The provider arrays `gcc_ipq6018_hws[]`, `gcc_ipq6018_clks[]`, and `gcc_ipq6018_resets[]` are gathered into `gcc_ipq6018_desc`. Probe uses `qcom_cc_map()` to obtain a regmap, applies several boot-time register updates, configures `ubi32_pll_main` and `nss_crypto_pll_main` with `clk_alpha_pll_configure()`, then calls `qcom_cc_really_probe()`.

## Control Flow
The driver registers a platform driver from `core_initcall(gcc_ipq6018_init)`, matching `qcom,gcc-ipq6018`. At probe, the GCC MMIO region is mapped through the shared qcom CC path. Before registering clocks, the probe disables USB0/USB1 GDSCR `SW_COLLAPSE`, enables USB GDSCR `SW_OVERRIDE`, sets a UBI Huayra PLL workaround bit, and programs the UBI32 and NSS crypto alpha PLL static configurations. After that, `qcom_cc_really_probe()` registers the regmap clocks, standalone hardware clocks, and reset controller.

Most runtime behavior is table-driven. RCG2 frequency tables describe supported rates and hardware parent encodings for PCNOC, System NoC, SNOC-NSSNOC, APSS AHB/AXI, WCSS/Q6/LPASS buses, BLSP I2C/SPI/UART, GP clocks, crypto, SDCC, USB, PCIe, QDSS, NSS PPE/CE/crypto/UBI, and Ethernet port RX/TX roots. Branch clocks then gate leaf domains from those roots. Clock framework consumers drive parent/rate/gate changes through the generic qcom regmap clock ops, not through custom per-consumer functions in this file.

## State And Persistence
State is static descriptor data plus live GCC register state. There is no filesystem persistence. The probe-time register updates persist for the current boot until reset or later register writes. PLL configuration is programmed into hardware and then represented through read-only or normal PLL/post-divider clock ops. Several branches use voted halt checks through shared vote registers, while UBI and pipe clocks use delayed halt checks where hardware may not report instantaneous state. `gcc_xo_clk_src` is marked `CLK_IS_CRITICAL`, and `gcc_blsp1_qup6_i2c_apps_clk` is critical because RPM/PMIC communication depends on QUP6 I2C.

## Dependencies And Integration Points
The driver depends on Qualcomm common clock controller helpers in `drivers/clk/qcom`: `common.h`, `clk-regmap.h`, `clk-pll.h`, `clk-rcg.h`, `clk-branch.h`, `clk-alpha-pll.h`, `clk-regmap-divider.h`, `clk-regmap-mux.h`, and `reset.h`. Device-tree consumers bind by numeric IDs from the IPQ6018 clock and reset binding headers. External providers must supply firmware-named parents for XO, sleep, pipe, UNIPHY, and bias PLL inputs. Integration points include PCIe and USB PHY pipe clock selection, NSS/PPE/EDMA and UNIPHY Ethernet drivers, BLSP serial drivers, SDHCI/ICE, QPIC NAND, WCSS and LPASS remoteproc/audio paths, QDSS trace/debug, and reset-controller consumers.

## Risks
The highest risk is parent-map correctness. Many parent arrays intentionally use sparse hardware selector values, and several selectors have similar names but different encoding orders, especially GPLL0 versus GPLL0_DIV2, USB/PCIe pipe muxes, and UNIPHY RX/TX alternatives. Ethernet port 5 uses `freq_multi_tbl` entries that can choose UNIPHY0 or UNIPHY1 parents for the same target rate, so wrong parent availability or DT naming can silently select the wrong MAC/PHY path. The UBI32 PLL is dynamically updated and receives a probe-time workaround bit; regression there can break NSS firmware or high-rate networking. USB GDSCR override writes are unguarded beyond regmap success, so offset mistakes can affect power-domain behavior. Reset entries include both single-bit and bitmask resets, including NSS port and PPE composite resets; a wrong mask can reset neighboring hardware. Critical-clock flags are sparse and should be changed conservatively because RPM, XO, bus, or fabric clocks can hang boot if disabled.

## Test Signals
Useful signals are clean probe of `qcom,gcc-ipq6018`, no qcom CC registration errors, and populated clock/reset providers in device tree. Runtime checks should inspect `/sys/kernel/debug/clk/clk_summary` for GPLL/UBI/NSS crypto PLL registration, expected APSS/NoC rates, BLSP UART/I2C/SPI rates, SDCC and ICE roots, USB mock UTMI and pipe parents, PCIe pipe parent selection, and QDSS trace clocks. Hardware validation should cover serial console, PMIC/RPM access through QUP6 I2C, SD/eMMC including ICE if used, USB0/USB1 enumeration, PCIe link training, QPIC NAND if present, WCSS/LPASS boot, and NSS/EDMA/PPE Ethernet traffic across ports 1 through 5 at 25/125/156.25/312.5 MHz related rates. Reset-controller tests should assert/deassert PCIe, USB, NSS, UNIPHY, WCSS, LPASS, BLSP, and SDCC resets without collateral device loss.
