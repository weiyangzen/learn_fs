# sources/distributed-fs/ceph-client/drivers/clk/rockchip/clk-rk3562.c

Purpose: RK3562 clock-controller driver for the Rockchip common clock framework. It describes the RK3562 CRU, PMU0/PMU1, DDR/sub-DDR, peripheral, media, GPU/NPU, PHY, and display clock topology as static PLL/rate/branch tables and wires that topology into OF clock providers, reset handling, and restart support.

Important APIs, types, and functions: the driver is almost entirely data-driven through Rockchip clock helper types from `clk.h`: `rockchip_pll_rate_table`, `rockchip_pll_clock`, and `rockchip_clk_branch`. `rk3562_pll_rates` lists supported RK3036/RK3328-style PLL parameters. `rk3562_pll_clks` registers APLL/GPLL/VPLL/HPLL/CPLL/DPLL, with DPLL marked critical and APLL/VPLL/HPLL allowing power-down. `PNAME()` arrays define parent mux names. `rk3562_clk_branches` uses `COMPOSITE`, `COMPOSITE_NODIV`, `COMPOSITE_NOMUX`, `COMPOSITE_FRACMUX`, `MUX`, `GATE`, `FACTOR`, `FACTOR_GATE`, and `MMC` macros to describe all child clocks. `rk3562_clk_init()` is the OF init entry, and `clk_rk3562_probe()` lets the same init run through the built-in platform driver.

Control flow: early init or platform probe calls `rk3562_clk_init()`. It computes `clk_nr_clks` from the maximum branch ID, maps the CRU register range with `of_iomap()`, allocates a Rockchip clock provider, registers PLLs with `rockchip_clk_register_plls()`, registers all branch clocks with `rockchip_clk_register_branches()`, initializes resets with `rk3562_rst_init()`, registers the global soft-reset restart notifier, and finally publishes the OF clock provider. Runtime clock operations are delegated to generic Rockchip/common-clock implementations created from the static branch descriptors.

State and persistence: persistent state is hardware register state in CRU/PMU/DDR clock select, gate, PLL, reset, GRF, and MMC tuning registers. The software state is the provider context and registered `clk_hw` objects. There is no filesystem or NVRAM persistence and no local suspend/resume syscore implementation despite including `syscore_ops.h`. `CLK_IS_CRITICAL` and `CLK_IGNORE_UNUSED` entries preserve clocks required for boot, buses, PMU, DDR, GRF, GIC, timers, and selected always-on/debug paths.

Dependencies and integration points: depends on `dt-bindings/clock/rockchip,rk3562-cru.h`, Rockchip clock/reset helpers, common clock framework, OF address mapping, and the RK3562 reset implementation. Device-tree compatible `"rockchip,rk3562-cru"` is served both by `CLK_OF_DECLARE()` and `builtin_platform_driver_probe()`. Consumers use the generated clock IDs for UART, SAI/SPDIF, I2C/SPI/PWM/CAN, SDMMC/eMMC/SFC, USB/PCIe PHY, GMAC, GPU/NPU, RGA/VPU/VENC/VDEC, VI/VO/display, PMU, and DDR domains.

Risks and test signals: most risk is descriptor accuracy: parent lists, register offsets, mux widths, divider widths, gate bits, and clock IDs must match the RK3562 TRM and DT binding. Critical-clock flags are safety-sensitive because disabling bus/PMU/DDR/reset/GRF paths can hang the system. Fractional muxes for SAI, SPDIF, UARTs, and RTC32K need rate-change tests because they combine parent propagation and fractional registers. Test signals include boot without clock lookup failures, `/sys/kernel/debug/clk/clk_summary` parent/rate sanity, successful reset-controller users, UART baud accuracy, audio sample-rate generation, SD/MMC tuning clocks, GMAC reference clocks, display pixel clocks with `CLK_SET_RATE_NO_REPARENT`, and restart notifier behavior.
