# sources/distributed-fs/ceph-client/drivers/mtd/nand/raw/denali.h

Purpose: this header is the Denali NAND controller hardware contract shared by the core, Device Tree wrapper, and PCI wrapper. It defines register offsets and bitfields, per-CS and per-controller state structures, capability flags that cannot always be discovered at runtime, and the exported core API used by wrapper drivers.

Important APIs, types, and functions: the register map covers reset, spare/OOB behavior, wait counters, timing registers, geometry registers, ONFI parameter mirrors, feature bits, per-bank interrupt/status registers, ECC error reporting, DMA registers, and active channel state. `struct denali_chip_sel` caches per-bank timing register values. `struct denali_chip` wraps a `nand_chip`, list node, number of selected banks, and flexible array of selections. `struct denali_controller` carries all wrapper-provided and core-maintained state: raw NAND controller, device, chip list, clock rates, register/host MMIO bases, completion and IRQ state, DMA/OOB/multidevice flags, active bank, revision, caps, ECC caps, host read/write callbacks, and DMA setup callback. Exported prototypes are `denali_calc_ecc_bytes()`, `denali_chip_init()`, `denali_init()`, and `denali_remove()`.

Control flow: wrappers include this header, allocate/populate a `struct denali_controller`, set resource pointers and capability metadata, call `denali_init()` once, then create `struct denali_chip` instances with one or more `struct denali_chip_sel` bank entries and register them through `denali_chip_init()`. The core writes and reads the register offsets defined here for all subsequent timing, ECC, DMA, interrupt, and geometry operations.

State and persistence: this header does not execute logic, but it defines the persistent state shape used across Denali files. The most important persistent fields are `chips`, `clk_rate`, `clk_x_rate`, `reg`, `host`, IRQ status/mask, `dma_avail`, `devs_per_cs`, `oob_skip_bytes`, `active_bank`, `nbanks`, `revision`, `caps`, and `ecc_caps`. Hardware persistence is represented by the register definitions for geometry, timing, ECC, spare marker, DMA, and interrupts.

Dependencies and integration points: it depends on Linux bit macros, completions, lists, raw NAND types, spinlock type declarations, and fixed-width integer types. The capability flags `DENALI_CAP_HW_ECC_FIXUP` and `DENALI_CAP_DMA_64BIT` bridge wrapper-specific knowledge into generic core decisions.

Risks: the header encodes revision-sensitive register semantics, especially interrupt bit reuse and timing field widths, so incorrect capability/revision data in wrappers can lead the core to interpret status incorrectly. Flexible-array allocation for `denali_chip` must use `struct_size()` or equivalent with a correct `nsels`; underallocation would corrupt state. `struct denali_controller` expects wrappers to populate mandatory fields before `denali_init()`, but the type itself cannot enforce that `dev`, `irq`, `reg`, `host`, and `ecc_caps` are valid.

Test signals: build coverage should include both Denali wrappers to validate shared declarations. Runtime validation comes indirectly from correct feature decoding, interrupt handling, ECC fixup mode selection, DMA width selection, timing register programming, and multi-chip registration through the core API.
