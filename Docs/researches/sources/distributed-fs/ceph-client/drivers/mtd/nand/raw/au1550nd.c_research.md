# sources/distributed-fs/ceph-client/drivers/mtd/nand/raw/au1550nd.c

Purpose: board/platform glue for NAND flash on Alchemy Au1550/Pb1550 systems. It maps the static-memory NAND window, detects chip-select, implements raw NAND operations using command/address/data register offsets, and registers MTD partitions from platform data.

Important APIs/types/functions: `struct au1550nd_ctx` owns `nand_controller`, `nand_chip`, CS number, and mapped base. `au_write_buf`, `au_read_buf`, `au_write_buf16`, and `au_read_buf16` implement PIO with `wmb()`. `find_nand_cs` decodes static-memory controller ranges. `au1550nd_exec_instr` and `au1550nd_exec_op` implement `exec_op`; `au1550nd_attach_chip` defaults software ECC to Hamming.

Control flow: probe requires platform data, allocates context, claims/maps memory, detects NAND CS, initializes the controller, configures 16-bit width when requested, defaults to software ECC, scans one target, and registers partitions. Runtime operations assert chip enable through `AU1000_MEM_STNDCTL`, execute instructions, then deassert.

State and persistence: state is the context, mapped IO base, CS, and MTD/NAND registration. Remove unregisters MTD, cleans NAND, unmaps IO, releases memory, and frees context.

Dependencies/integration: MIPS Alchemy headers, `struct au1550nd_platdata`, platform resources, raw NAND core, and platform partition registration.

Risks/test signals: the memory-region claim check deserves scrutiny, platform-data dependency, CS decode assumptions, wait-ready timeout, and 16-bit length handling. Test probe, CS detection, 8/16-bit read/write/erase, soft-Hamming ECC, partition registration, and remove.
