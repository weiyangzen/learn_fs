# sources/distributed-fs/ceph-client/drivers/mmc/host/sdhci_am654.c

Purpose: this platform driver supports TI AM654/J721E/AM64/AM62 SDHCI 5.1 controllers. It wraps the generic SDHCI platform core with TI PHY programming, output/input tap delays, DLL setup, SoC-specific quirks, CQHCI integration, runtime PM, and device-tree property parsing.

Important APIs, types, and functions: `struct sdhci_am654_data` stores regmap, per-timing OTAP/ITAP values, clock-buffer and DLL trim settings, driver strength, strobe select, flags, quirks, DLL state, and tuning retry count. `struct sdhci_am654_driver_data` selects per-compatible `sdhci_pltfm_data`, flags, and quirks. Key routines are `sdhci_am654_set_clock()`, `sdhci_j721e_4bit_set_clock()`, `sdhci_am654_setup_dll()`, `sdhci_am654_setup_delay_chain()`, `sdhci_am654_platform_execute_tuning()`, `sdhci_am654_cqhci_irq()`, `sdhci_am654_init()`, `sdhci_am654_probe()`, runtime suspend/resume, and restore.

Control flow: probe selects driver data from OF compatible, then overrides it for AM65x SR1.0 via `soc_device_match()`. It initializes an SDHCI platform host, records TI flags/quirks, gets `clk_xin`, maps the second MMIO resource as a syscon-like regmap for PHY/CTL_CFG registers, reads TI properties, parses MMC DT properties, applies HS400 descoping for affected SoCs, overrides MMC ops for voltage switch and tuning, enables runtime PM and the clock, and calls `sdhci_am654_init()`. Init resets PHY delays, optionally calibrates IO lines, enables IOMUX, sets embedded/removable slot type, enables SDR50 tuning, calls `sdhci_setup_host()`, initializes CQHCI, reads tap-delay DT properties, applies HS400 quirk filtering, and calls `__sdhci_add_host()`.

State and persistence: parsed OTAP/ITAP arrays persist per timing mode and are used whenever the SDHCI core changes clock/timing. Tuning updates `itap_del_sel[timing]`, so a successfully discovered input tap is retained for later clock programming. Runtime suspend disables CQHCI, SDHCI runtime state, and the input clock; runtime resume reenables the clock, restores PHY/CTL_CFG settings, resumes SDHCI, and then CQHCI. `dll_enable` affects whether tuning treats the ITAP search space as circular.

Dependencies and integration points: the driver uses `sdhci-pltfm`, `sdhci-cqhci`, `cqhci`, common clock APIs, regmap MMIO, runtime PM, device properties, OF matching, and SoC revision matching. It delegates most MMC request handling to `sdhci.c` through `sdhci_ops`, while CQE interrupts are bridged through `sdhci_cqe_irq()` and `cqhci_irq()`. Device-tree bindings provide `ti,otap-del-sel-*`, optional `ti,itap-del-sel-*`, `ti,trm-icp`, `ti,driver-strength-ohm`, `ti,strobe-sel`, `ti,clkbuf-sel`, and card-detect quirks.

Risks: PHY timing is board- and mode-specific; missing mandatory legacy OTAP fails probe, while missing optional timing properties remove corresponding MMC capabilities. The tuning algorithm searches failing ITAP windows and chooses the center of the largest passing window; all-pass or all-fail results trigger retries and can still fail. Runtime resume must restore CTL_CFG and PHY state before SDHCI resumes. CQE and SDHCI IRQ handling share the same interrupt path, so masking errors can misroute completions. Some variants require suppressing SDHCI's 1.8 V enable bit or forcing card-detect test bits.

Test signals: validate each compatible string and SoC revision path, mandatory and optional DT property handling, HS400 descoping on AM62Px SR1.0/SR1.1, clock changes for legacy through HS400 modes, DLL ready polling, delay-chain fallback below 50 MHz, tuning retry and chosen ITAP logs, CQE task operation, runtime autosuspend/resume, and card-detect behavior on boards needing forced CD test mode.
