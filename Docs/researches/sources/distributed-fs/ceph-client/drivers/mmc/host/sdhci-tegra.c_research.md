# sources/distributed-fs/ceph-client/drivers/mmc/host/sdhci-tegra.c

Purpose: this is the NVIDIA Tegra SDHCI platform driver. It adapts the generic SDHCI core to Tegra SDMMC controller generations from Tegra20 through Tegra234, covering SoC-specific capability quirks, tap/trim programming, pad voltage control, pad drive-strength autocalibration, CQHCI/eMMC command queue support, timeout-clock handling, IOMMU stream ID programming, runtime PM, and system suspend/resume.

Important APIs, types, and functions: `struct sdhci_tegra_soc_data` selects the `sdhci_pltfm_data`, DMA mask, NV quirk bitmap, and tap-delay calibration bounds for each compatible. `struct sdhci_tegra` is the live private state: power GPIO, optional `tmclk`, pinctrl states, reset control, autocal offsets, default tap/trim/DQS trim, CQE enablement, current clock rate, tuned tap delay, and stream ID. Register hooks include `tegra_sdhci_readw()`, `tegra_sdhci_writew()`, `tegra210_sdhci_writew()`, and `tegra_sdhci_writel()`. Timing and signal paths center on `tegra_sdhci_set_clock()`, `tegra_sdhci_set_uhs_signaling()`, `tegra_sdhci_execute_tuning()`, `tegra_sdhci_execute_hw_tuning()`, `tegra_sdhci_post_tuning()`, `tegra_sdhci_tap_correction()`, `tegra_sdhci_hs400_enhanced_strobe()`, `tegra_sdhci_hs400_dll_cal()`, and `tegra_sdhci_set_timeout()`. Platform lifecycle is `sdhci_tegra_probe()`, `sdhci_tegra_add_host()`, `sdhci_tegra_remove()`, runtime PM callbacks, and system sleep callbacks.

Control flow: probe selects match data, initializes the SDHCI platform host, sets static capabilities such as alternate Android GPT and busy-response support, optionally installs Tegra pad-control voltage switching and periodic autocalibration hooks, installs HS400 enhanced-strobe handling, parses MMC DT properties and Tegra-specific `supports-cqe`, default tap/trim, DQS trim, and pad autocal offset properties, obtains optional power GPIO and timeout clock, gets the core clock and reset control, initializes OPP support, runtime-resumes the device, pulses the SDHCI reset line, then registers either plain SDHCI or SDHCI plus CQHCI. After successful registration, Tegra234-style stream IDs are written into `SDHCI_TEGRA_CIF2AXI_CTRL_0`.

State and persistence: software state is mostly cached hardware configuration used to recover after full resets or clock changes: default tap/trim, tuned tap, DQS trim, DDR signaling flag, pad calibration requirement, last calibration timestamp, pinctrl availability, CQE flag, and current clock rate. Full SDHCI reset reapplies vendor capability overrides, default tap/trim, SDR/DDR mode advertisements, VREF, and pad-calibration-needed state. Runtime suspend disables the core clock; runtime resume reenables it. System suspend suspends CQHCI when active, suspends SDHCI, force-suspends runtime PM, and arms GPIO card-detect wake; resume reverses wake, runtime PM, stream ID programming, SDHCI resume, and CQHCI resume.

Dependencies and integration points: the file integrates with the MMC and SDHCI platform cores, `sdhci-cqhci`/`cqhci`, common clock and OPP frameworks, GPIO descriptors, pinctrl, regulators, reset controls, runtime PM, DMA masks, Tegra IOMMU stream ID helpers, and OF compatibles `nvidia,tegra20-sdhci` through `nvidia,tegra234-sdhci`. `mmc_of_parse()` supplies card-detect, bus-width, regulator, and timing policy. CQHCI is exposed only when `supports-cqe` is present and host setup succeeds.

Risks: the driver is quirk dense, so wrong compatible data can advertise unsupported UHS modes, DMA widths, timeout behavior, or CQE behavior. Pad voltage switching depends on both regulator capabilities and complete pinctrl states; missing states disable safe dual-voltage operation. Pad autocalibration runs periodically and around timing changes, and timeout fallback writes fixed drive strengths or selects drive-strength pinctrl states, so board DT values are timing-critical. Tuning correction uses tap-delay bounds, tuning status windows, and current clock rate arithmetic; bad bounds or clock rates can select marginal taps. CQHCI paths work around Tegra block-size write restrictions and DCMD R1B timing, making CQE resume/unhalt ordering fragile. The write hook suppresses timeout/CRC signal bits and relies on software timers for real errors.

Test signals: useful validation is successful probe per compatible, correct advertised capabilities and DMA mask, no `tmclk` or reset-control probe failures, voltage switching with the expected pinctrl state, recurring pad autocalibration without "Pad autocal timed out", SDR104/HS200 tuning and post-tuning tap selection, HS400 DQS trim and DLL calibration, enhanced strobe toggling, long busy operations using erase-timeout-limit behavior, CQHCI enable/disable/resume and DCMD status traffic, stream ID programming on Tegra234, card-detect wake from suspend, and stable runtime autosuspend/resume.
