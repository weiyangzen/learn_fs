# sources/distributed-fs/ceph-client/drivers/mmc/host/sdhci-xenon.c

Purpose: this is the platform SDHCI driver for Marvell Xenon SDHC controllers used on Armada AP806/AP807/CP110/3700 and AC5 variants. It wraps generic SDHCI with Xenon slot enablement, clock gating policy, tuning policy, voltage-switch pad control, SDIO interrupt indication, eMMC/SD/SDIO PHY integration, variant-specific quirks, runtime PM, and OF/ACPI matching.

Important APIs, types, and functions: `sdhci_xenon_ops` supplies custom `.voltage_switch`, `.set_power`, `.reset`, `.set_uhs_signaling`, and `.get_max_clock` while using generic SDHCI clock and bus-width helpers. MMC host ops are replaced by `xenon_set_ios()`, `xenon_start_signal_voltage_switch()`, `xenon_init_card()`, `xenon_execute_tuning()`, and `xenon_enable_sdio_irq()`. Platform setup flows through `xenon_probe()`, `xenon_probe_params()`, `xenon_sdhc_prepare()`, `xenon_remove()`, `xenon_runtime_suspend()`, and `xenon_runtime_resume()`. Helper functions program `XENON_SYS_OP_CTRL`, `XENON_SYS_EXT_OP_CTRL`, retuning registers, slot enable bits, SDCLK-off-while-idle, ACG, and command-conflict masking.

Control flow: probe initializes an SDHCI platform host with Xenon quirks, records hardware variant from OF/ACPI match data, replaces MMC ops, enables core and optional AXI clocks on DT systems, parses MMC properties, applies SDHCI properties, disables ACG early, parses Xenon-specific properties and PHY parameters, prepares the SDHC slot, enables runtime PM autosuspend, and registers the host. Parameter parsing validates `marvell,xenon-sdhc-id` against hardware slot count, parses `marvell,xenon-tun-count`, disables HS200 on AP806, and on AC5 with more than 2 GB RAM disables ADMA/64-bit DMA so generic SDHCI bounce buffering is used; after registration it may restore a 34-bit DMA mask for AC5 DDR addressing.

State and persistence: `struct xenon_priv` from the shared header stores slot ID, tuning count, initial card type, cached IOS state for PHY decisions, AXI clock, PHY type/params/register table, restore-needed flag, and hardware variant. Full SDHCI reset clears vendor state, so `xenon_reset_exit()` reapplies retune setup, disables ACG initially, disables SDCLK-off-while-idle, and masks command-conflict errors. Runtime suspend suspends the SDHCI host, requests retuning unless tuning mode 3 is active, disables the core clock, and clears cached PHY clock. System suspend force-suspends runtime PM and marks restore needed; runtime resume reenables the clock and re-prepares the slot if needed before resuming SDHCI.

Dependencies and integration points: the driver depends on generic SDHCI platform helpers, `sdhci-xenon.h`, the companion PHY file through `xenon_phy_parse_params()`, `xenon_phy_adj()`, and `xenon_soc_pad_ctrl()`, common clock APIs, runtime PM, DMA mask APIs, sysinfo memory sizing, OF properties, and optional ACPI IDs `MRVL0002` through `MRVL0004`. It uses MMC DT parsing for regulators and card properties, then custom voltage switching to keep the internal clock enabled while SoC pad control and generic voltage switching occur.

Risks: the driver deliberately forces tuning mode 1 and disables retuning interrupts, so tuning regressions may show up only under high-speed transfer testing. Preset values are disabled for HS, HS200, and HS400 to avoid invalid preset reads, and this dynamic quirk manipulation must remain aligned with generic SDHCI behavior. SDCLK-off-while-idle is enabled after clocks rise above 400 kHz; early enablement could interfere with initialization. AC5 DMA behavior depends on total memory size and crossbar limits, with a non-obvious post-registration DMA mask adjustment. Fixed-vqmmc platforms skip generic signal-voltage switching, relying on SoC pad control.

Test signals: validate probe over OF and ACPI variants, core/AXI clock enable and autosuspend, slot ID validation, SDHC enable/disable and parallel transfer bits, command-conflict masking after reset and resume, AP806 HS200 suppression, AC5 bounce-buffer/DMA mask behavior above 2 GB RAM, voltage switching with fixed and regulator-backed vqmmc, PHY adjustment on IOS changes, tuning mode 1 execution, SDIO async IRQ indication bits, runtime/system suspend-resume with retune needed, and host removal cleanup.
