# sources/distributed-fs/ceph-client/drivers/mmc/host/sdhci-uhs2.c

Purpose: this file is a reusable UHS-II extension layer for SDHCI hosts. It is not a standalone platform driver; instead, `sdhci_uhs2_add_host()` wraps generic SDHCI registration, detects SDHCI v4 UHS-II capability, installs UHS-II MMC host operations when enabled, and supplies UHS-II-specific reset, power, timeout, PHY initialization, command packet, transfer, completion, and interrupt handling.

Important APIs, types, and functions: exported entry points are `sdhci_uhs2_dump_regs()`, `sdhci_uhs2_reset()`, `sdhci_uhs2_set_power()`, `sdhci_uhs2_set_timeout()`, `sdhci_uhs2_clear_set_irqs()`, `sdhci_uhs2_irq()`, `sdhci_uhs2_add_host()`, and `sdhci_uhs2_remove_host()`. `sdhci_uhs2_host_ops_init()` replaces `mmc_host_ops.uhs2_control` and `.request`. Low-level helpers handle UHS-II timers, power sequencing, interface detect, capability parsing, settings programming, dormant checks, clock enable/disable, command packet construction, response extraction, DMA/data setup, request completion, and threaded IRQ continuation.

Control flow: registration calls `sdhci_setup_host()`, interprets `SDHCI_SUPPORT_UHS2` and `SDHCI_CAN_VDD2_180`, optionally sets `MMC_CAP2_SD_UHS2`, and only keeps UHS-II support if SDHCI v4 mode is active. During card initialization the MMC core calls `uhs2_control`; `UHS2_PHY_INIT` performs optional host pre-detect work, polls `SDHCI_PRESENT_STATE` for interface detect and lane sync, reads UHS-II caps through `SDHCI_UHS2_CAPS_PTR`, resets the SD UHS-II block, reenables SDHCI interrupts, and enables UHS-II error interrupts. `UHS2_SET_CONFIG` writes selected lane, LSS, FCU, retry, and data-gap settings through `SDHCI_UHS2_SETTINGS_PTR`.

State and persistence: the layer reuses `struct sdhci_host` state (`host->cmd`, `host->data`, `host->ier`, `host->mrqs_done`, timers, deferred command, DMA flags) and fills `mmc->uhs2_caps` from hardware. UHS-II power state is cached in `host->pwr`. A full UHS-II reset clears `host->clock`; SD-only resets clear UHS-II block state, so the code restores SDHCI interrupt enables and UHS-II error enables afterward. Request completion records errors in `cmd->error` or `data->error`, unmaps DMA when needed, and resets UHS-II command/data state machines after command or data failures.

Dependencies and integration points: the file depends on generic `sdhci.h`, the register definitions in `sdhci-uhs2.h`, MMC UHS-II command structures (`cmd->uhs2_cmd`), regulator helpers for `vmmc` and `vqmmc2`, SDHCI v4 capability bits, generic SDHCI request/data/DMA/completion helpers, and MMC core UHS-II operations such as `enum sd_uhs2_operation`. Platform drivers must call `sdhci_uhs2_add_host()` and usually route their IRQ hook through `sdhci_uhs2_irq()`.

Risks: UHS-II behavior is active only when `mmc_card_uhs2()` is true, so mixed UHS-I/UHS-II paths must stay consistent. Timer programming depends on `host->timeout_clk`; bad or zero clock data can produce wrong command-response and deadlock timeouts. Power sequencing currently assumes 1.8 V VDD2 support and delays with fixed 5 ms waits. Command packet writes rely on `cmd->uhs2_cmd` payload layout already being in transmission byte order. Error IRQ classification maps many packet errors to `-EILSEQ`, with special cases for timeout, deadlock, and ADMA errors. The request path strips stop/SBC fields because UHS-II handles transfer semantics differently; generic MMC callers must have prepared compatible requests.

Test signals: test SDHCI v4 registration with and without `SDHCI_SUPPORT_UHS2`, regulator-backed and fixed VDD2 power on/off, interface-detect and lane-sync timeout handling, capability parsing into `mmc->uhs2_caps`, settings writes for speed A/B and half/full duplex, native abort and dormant commands, single and multi-block data paths with DMA, command/data error IRQ injection, deferred-command retry after inhibit release, card insert/remove threaded IRQ handling, and full remove/reset on live UHS-II cards.
