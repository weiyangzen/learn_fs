# sources/distributed-fs/ceph-client/drivers/mmc/host/sdhci-uhs2.h

Purpose: this header defines the SDHCI Category B/C UHS-II register map, bit fields, error masks, capability/settings offsets, and exported helper prototypes consumed by `sdhci-uhs2.c` and platform SDHCI drivers that opt into UHS-II support.

Important APIs, types, and functions: the register constants cover UHS-II block size/count, command packet area, transfer mode, command register, response buffer, message selection, device interrupt status/select/code, UHS-II software reset, timer control, UHS-II interrupt status/enable/signal registers, settings pointer, capabilities pointer, embedded-control pointer, and vendor pointer. Composite masks such as `SDHCI_UHS2_INT_ERROR_MASK`, `SDHCI_UHS2_INT_CMD_ERR_MASK`, and `SDHCI_UHS2_INT_DATA_ERR_MASK` define how the implementation separates command and data errors. Public prototypes expose register dumping, reset, power, timeout, host add/remove, IRQ-mask update, and IRQ filtering.

Control flow: the header itself has no runtime control flow, but it encodes the contract used by the C file. `SDHCI_UHS2_CMD_PACKET` and `SDHCI_UHS2_CMD_PACK_MAX_LEN` describe how command packets are staged before writing `SDHCI_UHS2_CMD`. Transfer mode bits drive DMA, block-count mode, byte mode, write direction, busy wait, and half-duplex operation. Software reset bits distinguish full UHS-II reset from SD block reset. Capability and settings offsets are relative to hardware-provided pointers, so drivers read `SDHCI_UHS2_CAPS_PTR` and `SDHCI_UHS2_SETTINGS_PTR` before accessing the corresponding tables.

State and persistence: the constants describe persistent hardware register state, not software-owned storage. Settings fields program negotiated lane counts, speed range, synchronization/direct LSS values, retry counts, FCU count, and data gap. Capability fields expose DAP, GAP, lane modes, 64-bit addressing, boot support, device type/count, topology, PHY revision/range, link revision, host type, block length, and transport data-gap support.

Dependencies and integration points: the header includes `<linux/bits.h>` for `BIT()` and `GENMASK()`, forward-declares `struct sdhci_host`, `struct mmc_command`, and `struct mmc_request`, and relies on surrounding SDHCI/MMC headers for common register and type definitions. It is included by `sdhci-uhs2.c`; platform drivers include it when they need exported UHS-II helpers or register definitions.

Risks: the file is a register ABI, so incorrect offsets or masks would silently corrupt UHS-II command, response, interrupt, or capability handling. Several settings are pointer-relative, which means callers must validate hardware pointers before using them. Error masks intentionally omit `SDHCI_UHS2_INT_VENDOR_ERR` from the aggregate error mask, so vendor-specific errors require platform-specific handling if needed. The `SDHCI_UHS2_MAKE_BLKSZ()` helper exists but the current implementation writes block size/count directly, so future users should confirm DMA boundary semantics.

Test signals: validate compile coverage for all exported prototypes, register dump output matching hardware manuals, capability/settings pointer bounds, interrupt mask behavior for command versus data errors, full and SD resets, and command packet length programming up to the 20-byte maximum.
