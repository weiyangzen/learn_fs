# sources/distributed-fs/ceph-client/drivers/mfd/cs47l85-tables.c

## Purpose
`cs47l85-tables.c` provides the CS47L85-specific regmap tables, revision patches, register defaults, access predicates, and SPI/I2C regmap configurations for the Madera MFD framework. It is the larger sibling of the CS47L35 table file: the same regmap pattern is expanded for additional FLLs, async clocks, AIF4, more input/output paths, more DSPs, ASRC/ISRC blocks, ANC/FCL/FCR coefficient ranges, more GPIOs, and wider ADSP memory coverage.

## Important APIs, Types, And Functions
The exported entry point is `cs47l85_patch(struct madera *madera)`. Exported configs are `cs47l85_16bit_spi_regmap`, `cs47l85_16bit_i2c_regmap`, `cs47l85_32bit_spi_regmap`, and `cs47l85_32bit_i2c_regmap`. Patch data is split by revision and value width: `cs47l85_reva_16_patch[]`, `cs47l85_revc_16_patch[]`, `cs47l85_reva_32_patch[]`, and `cs47l85_revc_32_patch[]`. The main default table is `cs47l85_reg_default[]`. Access helpers are `cs47l85_is_adsp_memory()`, `cs47l85_16bit_readable_register()`, `cs47l85_16bit_volatile_register()`, `cs47l85_32bit_readable_register()`, and `cs47l85_32bit_volatile_register()`.

## Control Flow
The patch path first selects data from `madera->rev`: revisions `0` and `1` use the Rev A 16-bit and 32-bit patch arrays, while all other revisions use the Rev C arrays. It then applies the selected 16-bit patch through `madera->regmap`; if that fails it logs `"Error in applying 16-bit patch"` and returns immediately. On success it applies the selected 32-bit patch through `madera->regmap_32bit`; failure logs `"Error in applying 32-bit patch"` and returns the error. Only after both patch writes succeed does the function return `0`. Subsequent regmap access uses the readable and volatile callbacks. The 16-bit readable callback allowlists a broad codec control surface. The 16-bit volatile callback narrows this to reset/revision, write sequencer controls, haptics/sample/async status, HP and DCS controls, mic/headphone detect status, input/output status, SPDIF/SLIMbus status, FX status, ASRC status, clock control, and IRQ status/raw ranges. The 32-bit callbacks allow write sequencer sequence space, OTP HPDET calibration, DSP1-DSP7 config/scratch ranges, and all ADSP memory windows known to `cs47l85_is_adsp_memory()`.

## State, Persistence, And Dependencies
Runtime state lives outside this file in `struct madera`, the regmap core, and the hardware. The persistent effects are the patch writes and the reset/cache defaults represented by `cs47l85_reg_default[]`. That default table covers clocking, sample rates, three FLLs, power and mic bias, jack/mic/headphone detect, six input pairs, six output pairs, PDM speakers, AIF1-AIF4, SLIMbus/SPDIF, PWM/output/AIF/SLIM/DSP/ASRC/ISRC mixers, EQ/DRC/HPLPF processing coefficients, ASRC and ISRC controls, ANC and filter coefficient memory, GPIO1-GPIO40, IRQ masks, debounce, and IRQ control. Dependencies include the Linux regmap/device/module APIs, Madera core/register headers, CS47L85 register constants, `REGCACHE_MAPLE`, `ARRAY_SIZE`, `dev_err()`, and two initialized regmaps in `struct madera` for patching both 16-bit and 32-bit spaces.

## Integration Points
Bus drivers use the exported configs to create big-endian 16-bit and 32-bit regmaps with 32-bit register addresses. SPI configs include 16 pad bits; I2C configs do not. The 16-bit maps have `max_register = 0x2fff` and include the default array for cache seeding. The 32-bit maps use `reg_stride = 2`, extend to `MADERA_DSP7_SCRATCH_2`, and are used for write sequencer, OTP, DSP, and ADSP memory access. The MFD core needs `cs47l85_patch()` to run after both `madera->regmap` and `madera->regmap_32bit` exist. Audio codec, DSP firmware, IRQ, GPIO, clock, jack detection, ANC, ASRC/ISRC, and routing components all rely on this file's access policy for safe register I/O and correct cache coherency.

## Risks
The revision switch treats every revision other than `0` or `1` as Rev C-compatible; new silicon that needs a different patch could silently receive the wrong sequence unless the selector is updated. Patch ordering matters because the function stops after a failed 16-bit patch and only writes the 32-bit patch after success. The Rev A 32-bit patch is large and appears to program a dense sequencer/control table, so address/value transcription errors would be hard to detect without hardware comparison. The readable and volatile allowlists are much larger than CS47L35, increasing the chance of drift when register definitions change. DSP/ADSP memory is marked volatile in the 32-bit map, which is conservative for firmware/shared memory correctness but prevents normal caching. Cache defaults for status-like or patch-mutated registers must remain aligned with volatile classification to avoid stale regcache state after resume.

## Test Signals
High-value tests include probe on Rev A/B and later CS47L85 silicon, verifying that the selected 16-bit and 32-bit patch arrays are applied to the correct regmaps and that injected regmap failures produce the expected early returns. Regmap tests should sample boundaries for the `0x2fff` 16-bit space, write sequencer sequence ranges through `MADERA_WSEQ_SEQUENCE_508`, DSP1-DSP7 scratch/config ranges, OTP HPDET calibration, and each ADSP memory window including start/end addresses. Functional smoke tests should cover AIF1-AIF4 playback/capture routing, FLL1-FLL3 and async sample-rate status, six output paths, six input pairs, PDM speaker controls, GPIO1/GPIO40, IRQ mask/status behavior, jack/mic/headphone detection, ASRC/ISRC controls, DSP firmware load/readback, and ANC/FCL/FCR coefficient access. Suspend/resume tests should validate regcache sync while volatile IRQ, status, clock, ASRC, and DSP-status registers continue to read fresh values.
