# sources/distributed-fs/ceph-client/drivers/mfd/cs47l35-tables.c

## Purpose
`cs47l35-tables.c` supplies the regmap data and access policy for the Cirrus Logic CS47L35 Madera-family audio codec. It is not an active device driver by itself; it is a data/control companion for the MFD core and bus glue that need chip-specific register defaults, patch programming, readable/volatile register filtering, ADSP memory windows, and 16-bit/32-bit regmap configurations.

## Important APIs, Types, And Functions
The file exports `cs47l35_patch()` plus four `struct regmap_config` instances: `cs47l35_16bit_spi_regmap`, `cs47l35_16bit_i2c_regmap`, `cs47l35_32bit_spi_regmap`, and `cs47l35_32bit_i2c_regmap`. Static data includes `cs47l35_reva_16_patch[]`, a short `struct reg_sequence` patch written through the normal 16-bit regmap, and `cs47l35_reg_default[]`, the 16-bit register cache baseline. Static predicates are `cs47l35_is_adsp_memory()`, `cs47l35_16bit_readable_register()`, `cs47l35_16bit_volatile_register()`, `cs47l35_32bit_readable_register()`, and `cs47l35_32bit_volatile_register()`.

## Control Flow
Probe-time integration is expected to instantiate the appropriate SPI or I2C regmaps from the exported configs, then call `cs47l35_patch()` after the `struct madera` has a valid `regmap` and `dev`. The patch function has one path: call `regmap_register_patch(madera->regmap, cs47l35_reva_16_patch, ARRAY_SIZE(...))`, log `dev_err()` on failure, and return the regmap status. Normal register I/O then flows through regmap callbacks. For 16-bit accesses, regmap asks `cs47l35_16bit_readable_register()` and `cs47l35_16bit_volatile_register()` whether a register can be read or should bypass/stale the cache. For 32-bit accesses, regmap accepts write sequencer, OTP headphone-detect calibration, DSP1-DSP3 control/scratch ranges, and the explicit ADSP memory windows returned by `cs47l35_is_adsp_memory()`.

## State, Persistence, And Dependencies
The file owns no runtime state. Persistent hardware effects are limited to register writes made by the patch and later by users of the exported regmaps. `cs47l35_reg_default[]` is persistent only as regcache initialization metadata: it seeds cache values for clocks, FLL1, charge pumps, mic bias/detect, input and output paths, AIF1-AIF3, SLIMbus/SPDIF controls, mixers, EQ/DRC/HPLPF/ISRC coefficients, GPIO1-GPIO16, IRQ masks, debounce, and IRQ control. The 16-bit regmaps use `REGCACHE_MAPLE` with these defaults; the 32-bit regmaps also use maple caching but have no default array. Dependencies are Linux `regmap`, `device`, and `module` APIs, Madera core state from `struct madera`, register constants from `linux/mfd/madera/registers.h`, CS47L35-specific constants from the local Madera headers, and GNU C switch range cases.

## Integration Points
The MFD core and SPI/I2C bus drivers consume the exported regmap configs to build device register maps with 32-bit register addresses, big-endian register/value formatting, and bus-specific SPI padding. The 16-bit maps cover the main control register space up to `0x1b00`; the 32-bit maps use stride 2 and extend through `MADERA_DSP3_SCRATCH_2`. Downstream codec, interrupt, GPIO, clock, jack-detect, DSP, and audio-routing code depends on this file classifying registers correctly so that regmap cache, debugfs, patching, suspend/resume synchronization, and volatile status reads behave correctly.

## Risks
The register allowlists are large and hand-maintained, so an omitted readable register can make legitimate users fail through regmap, while an omitted volatile register can leave cached status, IRQ, jack-detect, sample-rate, or DSP state stale. Marking too many registers volatile or readable weakens cache efficiency and may expose undefined hardware addresses. The 32-bit readable and volatile predicates are intentionally identical for their explicit ranges and ADSP windows; this avoids stale DSP memory but means those regions are never treated as stable cacheable data. The patch has no revision switch despite being named `reva`, so any future non-compatible CS47L35 revision would need a new selector before this function is reused. The SPI configs include `pad_bits = 16` while I2C configs do not; bus glue must choose the matching config.

## Test Signals
Useful validation includes boot/probe on CS47L35 over both SPI and I2C, confirming the 16-bit patch succeeds and failure paths log the regmap error. Regmap-debugfs or targeted read tests should verify representative readable and unreadable registers, including FLL1, AIFs, mixers, IRQ status/mask ranges, GPIO1/GPIO16, DSP1-DSP3 scratch, OTP HPDET calibration, and ADSP memory boundary addresses. Suspend/resume and cache sync tests should exercise volatile status registers so IRQ, jack-detect, sample-rate, output/input status, and DSP-related status are refreshed from hardware. Audio smoke tests should cover input capture, output playback, AIF1-AIF3 routing, SLIMbus/SPDIF controls where present, haptics/tone paths, and DSP firmware memory access.
