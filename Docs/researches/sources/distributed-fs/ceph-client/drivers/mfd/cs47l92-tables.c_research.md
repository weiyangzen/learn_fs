# sources/distributed-fs/ceph-client/drivers/mfd/cs47l92-tables.c

### Purpose
`cs47l92-tables.c` provides the CS47L92 Madera-family codec register defaults, access predicates, patch programming, ADSP memory map, and exported regmap configurations. It is chip data consumed by MFD and bus code; it does not bind a device itself.

### Important APIs, Types, And Functions
The exported function is `cs47l92_patch(struct madera *madera)`. It applies `cs47l92_reva_16_patch[]` to `madera->regmap` and `cs47l92_reva_32_patch[]` to `madera->regmap_32bit`. Exported configs are `cs47l92_16bit_spi_regmap`, `cs47l92_16bit_i2c_regmap`, `cs47l92_32bit_spi_regmap`, and `cs47l92_32bit_i2c_regmap`. `cs47l92_reg_default[]` seeds the 16-bit regcache. Static helpers are `cs47l92_is_adsp_memory()`, `cs47l92_16bit_readable_register()`, `cs47l92_16bit_volatile_register()`, `cs47l92_32bit_readable_register()`, and `cs47l92_32bit_volatile_register()`.

### Control Flow
`cs47l92_patch()` first registers the 16-bit Rev A patch and returns immediately on failure after logging a 16-bit patch error. If the 16-bit patch succeeds, it registers the 32-bit Rev A patch and similarly logs/returns any failure. Only both successful patch registrations produce a `0` return. The 16-bit readable callback covers the main control surface: reset/revision, write sequencer controls, tone/PWM/haptics, clock and sample-rate controls, CS47L92-specific FLL register ranges, mic bias/detect, HP/headphone/jack detection, four input pairs, output paths, PDM speaker, AIF1-AIF3, SPDIF/SLIMbus, PWM/output/AIF/SLIM/SPDIF/EQ/DRC/HPLP/DSP/ASRC/ISRC/DFC mixers, EQ/DRC/HPLPF processing controls, ASRC/ISRC, AUXPDM, DFC controls, GPIO1-GPIO16, and IRQ status/mask/raw ranges. The volatile callback keeps live reset/revision, write sequencer, haptics, sample-rate, async, HP/mic/headphone detect, input/output, SPDIF/SLIMbus, FX, ASRC, DFC, and IRQ status/raw registers out of stable cache assumptions. The 32-bit callbacks allow write sequencer sequence entries, OTP HPDET calibration, DSP1 config/error ranges, and four ADSP memory windows in `cs47l92_is_adsp_memory()`.

### State, Persistence, And Dependencies
This file has no private runtime state. Hardware state changes come from the 16-bit and 32-bit patches; cached state comes from `cs47l92_reg_default[]`. The default table initializes clocks, sample rates, FLL1/FLL2 values, charge pump/LDO/mic bias, accessory/headphone/mic/jack detection, input and output controls, PDM speaker and short-circuit controls, AIF1-AIF3, SLIMbus/SPDIF, mixer routing, DSP1 and ASRC/ISRC/DFC routing, EQ/DRC/HPLPF controls, AUXPDM, DFC word controls, GPIO1-GPIO16, IRQ masks, debounce, and IRQ control. Dependencies include Linux `regmap`, `device`, and `module` facilities; `struct madera`; Madera and CS47L92 register constants; `REGCACHE_MAPLE`; `ARRAY_SIZE`; and range-case switch syntax.

### Integration Points
Madera bus drivers use the exported SPI/I2C configs to create big-endian 16-bit and 32-bit maps. The 16-bit SPI config has 16 pad bits while the I2C config does not; both use `MADERA_INTERRUPT_RAW_STATUS_1` as `max_register`, the CS47L92 readable/volatile callbacks, maple cache, and the default table. The 32-bit maps use `reg_stride = 2`, extend only through `MADERA_DSP1_PMEM_ERR_ADDR___XMEM_ERR_ADDR`, and are the path for write sequencer, OTP, DSP1, and ADSP memory access. The codec, interrupt, GPIO, audio-routing, jack detection, DSP firmware, suspend/resume, and regmap-debug paths rely on this file to describe valid and live registers accurately.

### Risks
The patch function is named for Rev A data and does not branch on hardware revision, so later incompatible revisions need explicit dispatch before using different sequences. The 32-bit patch is applied only after the 16-bit patch succeeds; partial initialization failure leaves the caller responsible for aborting probe or recovery. Readable/volatile allowlists are dense and easy to drift from the register header. CS47L92 has fewer DSP/ADSP ranges than CS47L90, so copying assumptions from a larger Madera part could expose invalid addresses. The volatile treatment of DSP/ADSP memory is conservative but cache-expensive. Incorrect IRQ mask defaults or volatile status classification can cause missed interrupts, spurious cached status, or bad resume behavior.

### Test Signals
Probe tests should validate both 16-bit and 32-bit patch registration on CS47L92 and inject failures in each stage to verify logging and early returns. Regmap tests should cover boundaries for the 16-bit control space, GPIO1/GPIO16, IRQ1 status/mask/raw ranges, AIF1-AIF3, CS47L92 FLL-specific registers, DSP1 config/error ranges, OTP HPDET calibration, write sequencer entries, and each ADSP memory window. Suspend/resume should check that volatile IRQ, detect, sample-rate, output/input, bus, FX, ASRC, and DFC status reads bypass stale cache. Functional tests should exercise playback/capture, PDM speaker, jack/mic/headphone detection, AIF/SLIMbus/SPDIF routing, DSP1 firmware access, AUXPDM, DFC, ASRC/ISRC, and IRQ mask/status behavior.
