# sources/distributed-fs/ceph-client/drivers/pinctrl/tegra/pinctrl-tegra20.c

Purpose: Provides the static pinctrl data and small Tegra20-specific glue for the NVIDIA Tegra20 pinmux. Unlike the newer Tegra186/Tegra194 files, Tegra20 uses multi-pin functional groups, explicit GPIO numbering alignment, legacy mux/pull/tristate register banks, drive-group tables, and read-only clock mux registration for a few clock-output pin groups.

Important APIs, types, and functions: The file defines GPIO-backed pin IDs with `_GPIO(offset)` so the first 224 pins match the Tegra20 GPIO driver numbering, then defines non-GPIO pins with `_PIN(offset)` after `NUM_GPIOS`. `tegra20_pins[]` exposes all GPIO and non-GPIO pin descriptors, including display, GMI/NAND/IDE, SDIO, UART, SPI, ULPI, keyboard, camera/video, DDR, JTAG, clock, and power pins. Large `*_pins[]` arrays group pins by mux group (`ata`, `dap1`, `lcd`, `sdio1`, `spia`, `uad`, etc.), pull-only group (`ck32`, `ddrc`, `xm2c`, etc.), and drive group (`drive_ao1`, `drive_lcd2`, `drive_xm2d`, etc.). `enum tegra_mux` and `tegra20_functions[]` define the function namespace. `MUX_PG`, `PULL_PG`, `DRV_PG_EXT`, and `DRV_PG` build `struct tegra_pingroup` entries. `tegra20_pinctrl` sets `.ngpios = NUM_GPIOS` and `.gpio_compatible = "nvidia,tegra20-gpio"`. `tegra20_pinctrl_register_clock_muxes()` registers read-only `cdev1_mux`, `cdev2_mux`, and `csus_mux` clocks with `clk_register_mux()`. `tegra20_pinctrl_probe()` calls `tegra_pinctrl_probe()` and then registers those clock muxes. The platform driver matches `"nvidia,tegra20-pinmux"` and is registered with `arch_initcall`.

Control flow: During probe, the shared Tegra pinctrl core receives `tegra20_pinctrl` and maps the controller resources into a `struct tegra_pmx`. The Tegra20 wrapper then reads that driver data and registers clock-provider muxes for the `cdev1`, `cdev2`, and `csus` pinmux fields, using the same mux register bank (`pmx->regs[1] + 0x8`) and marking them `CLK_MUX_READ_ONLY`. Pinctrl operations are table-driven: mux groups encode four function choices, tristate register offset/bit, mux register offset/bit, and optional pull-up/down fields; pull-only groups expose only pull configuration; drive groups expose high-speed mode, Schmitt, low-power mode, drive-down/up, and slew-rising/falling fields.

State and persistence behavior: All pin definitions and group metadata are immutable. Runtime state is in the common Tegra pinctrl driver and in the clock framework objects registered by `tegra20_pinctrl_register_clock_muxes()`. Hardware pinmux, pull, tristate, and drive register values persist until changed by pinctrl state selection, clock/pin firmware setup, suspend/resume, or another driver. The clock muxes are read-only views of pinmux-selected clock parents, so they expose existing hardware selection to the clock framework without making the clock framework responsible for changing the pinmux bits.

Dependencies and integration points: Depends on Linux clock-provider APIs in addition to platform, OF, and pinctrl/pinmux headers. It integrates with the shared `pinctrl-tegra.h` core, the Tegra20 GPIO driver via exact GPIO pin numbering and `gpio_compatible`, the common clock framework via `cdev1_mux`, `cdev2_mux`, and `csus_mux`, and device-tree pinctrl states for Tegra20 boards. Peripheral dependencies include display/HDMI/CRT, GMI/NAND/IDE, SDIO, UART, SPI, I2C/DDC, ULPI USB, audio DAP/SPDIF, keyboard controller, video input/camera, DDR pad controls, power-management pins, JTAG/test pins, and system clock request.

Risks: GPIO numbering is a hard contract: moving or renumbering the first `NUM_GPIOS` pin descriptors would break GPIO/pinctrl coordination. Multi-pin groups mean a mux change can affect many pads at once, so a single wrong pin-array member or mux choice can disrupt a bus. Register offsets are expressed as deltas from `TRISTATE_REG_A`, `PIN_MUX_CTL_REG_A`, `PULLUPDOWN_REG_A`, and `PINGROUP_REG_A`; wrong base arithmetic or `-1` handling affects many groups. Some descriptor names carry historical quirks, such as `"VD_D10 PT2"` for `TEGRA_PIN_VI_D10_PT2`, which may surprise string-based diagnostics. DDR, clock, reset, power, and JTAG groups are boot-sensitive and may have limited safe runtime configurability. `clk_register_mux()` return values are ignored, so failed clock registration would not fail pinctrl probe.

Test signals: Compile with Tegra20 pinctrl and clock-provider support. Boot a Tegra20 device tree with `"nvidia,tegra20-pinmux"` and confirm pinctrl plus GPIO registration, with GPIO numbers aligned to the GPIO driver. Debugfs should show expected functions and groups, including mux, pull-only, and drive groups. Exercise board pin states for SDIO, display, UART, SPI, I2C/DDC, ULPI, audio DAP, keyboard, and GMI/NAND/IDE where available. Verify pull/tristate/mux/pinconf writes on mux groups, pull-only behavior on pull groups, drive-strength/slew/high-speed/Schmitt settings on drive groups, and absence of unsupported-feature writes where fields are `-1`. Clock tests should confirm `cdev1_mux`, `cdev2_mux`, and `csus_mux` appear as read-only clock muxes with parent selection reflecting pinmux register bits. Suspend/resume, early boot pin state, and GPIO request/mux handoff are important regression signals.
