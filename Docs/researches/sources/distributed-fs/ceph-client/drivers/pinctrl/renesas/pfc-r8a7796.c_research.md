# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a7796.c

## Purpose

This file is the Renesas R-Car Gen3 `r8a7796` PFC description used by the shared `sh_pfc` pinctrl/GPIO driver. It is data-heavy rather than algorithmic: it declares the pins, mux functions, pin groups, module-select alternatives, configuration registers, drive-strength registers, bias registers, IO-voltage control hook, and exported SoC descriptors for related R-Car M3-W/M3-W+ variants.

The descriptor covers `r8a774a1`, `r8a77960`, and `r8a77961` builds. The `r8a774a1` descriptor exposes only the common group/function catalog, while `r8a77960` and `r8a77961` add automotive-specific DRIF and MLB+ groups/functions when the relevant Kconfig symbols are enabled. Board device tree pinctrl states consume the function and group names defined here to route peripherals such as AVB, CAN/CAN-FD, DU, HSCIF/SCIF, I2C, MSIOF, QSPI, SDHI, SSI, USB, VIN4/VIN5, DRIF, and MLB.

## Important APIs, Types, and Data

- `CFG_FLAGS` marks most pins as supporting drive-strength and pull-up/down configuration. `CPU_ALL_GP(fn, sfx)` generates GPIO-capable banks GP0-GP7 and adds IO-voltage support for banks GP3[0:11] and GP4[0:17]. `CPU_ALL_NOGP(fn)` defines non-GPIO pins such as QSPI, RPC, AVB MII pins, DU dot clock inputs, reset/JTAG/debug pins, and MLB reference pins.
- The initial `GPSR*`, `IP*`, and `MOD_SEL*` macros model the hardware selector encodings. `GPSR` entries map GPIO pins to either GPIO or peripheral mode. `IPSR` entries list up to 16 alternatives per 4-bit field. `MOD_SEL0..2` entries describe secondary route selectors used by peripherals with several package routes.
- `PINMUX_GPSR`, `PINMUX_IPSR`, `PINMUX_MOD_SELS`, `PINMUX_STATIC`, and `PINMUX_PHYS` feed the anonymous enum. That enum creates the integer spaces for data IDs, function IDs (`FN_*`), and mux marks (`*_MARK`) consumed by the `sh_pfc` macro layer.
- `pinmux_data[]` is the central mark-to-register mapping. It starts with `PINMUX_DATA_GP_ALL()`, adds `PINMUX_SINGLE()` entries for simple pins such as `AVS1`, `AVS2`, `CLKOUT`, selected `MSIOF0` and `SSI5` signals, and then maps every IPSR alternative through `PINMUX_IPSR_GPSR()`, `PINMUX_IPSR_MSEL()`, `PINMUX_IPSR_PHYS()`, or `PINMUX_IPSR_PHYS_MSEL()`. Static non-muxable pins are appended as marks with no function so the core can still apply pin configuration without trying to mux them.
- `pinmux_pins[]` is the SoC pin list, generated by `PINMUX_GPIO_GP_ALL()` and `PINMUX_NOGP_ALL()`.
- Per-group `<name>_pins[]` and `<name>_mux[]` arrays define concrete pin groups. The arrays must be same-length and order-aligned; group construction macros use them to build `struct sh_pfc_pin_group` entries.
- `pinmux_groups` is split into `common[324]` and optional `automotive[31]`. Common groups include audio clocks, AVB, CAN/CAN-FD, DU, HSCIF, I2C, INTC-EX, MSIOF, PWM, QSPI, SCIF, SDHI, SSI, TMU, TPU, USB, VIN4, and VIN5. Automotive groups add DRIF0-DRIF3 and `mlb_3pin`.
- `<function>_groups[]` string arrays define the public groups for each pinctrl function. `pinmux_functions` exposes `common[52]` functions and optional `automotive[5]` functions.
- `pinmux_config_regs[]` maps GPSR0-GPSR7, IPSR0-IPSR18, and MOD_SEL0-MOD_SEL2 registers in the PFC register block. It uses `PINMUX_CFG_REG()` for uniform fields and `PINMUX_CFG_REG_VAR()` where reserved holes or mixed field widths must be represented explicitly.
- `pinmux_drive_regs[]` maps DRVCTRL0-DRVCTRL24 to pins and bit positions. Most entries use 2-bit or 3-bit drive fields depending on the pad family.
- `pinmux_ioctrl_regs[]` exposes POCCTRL and TDSELCTRL addresses. `r8a7796_pin_to_pocctrl()` maps only GP3[0:11] and GP4[0:17] to POCCTRL bits, matching the pins flagged with `SH_PFC_PIN_CFG_IO_VOLTAGE_18_33`.
- `pinmux_bias_regs[]` maps PUEN0-PUEN6 and PUD0-PUD6 registers to pins. `SH_PFC_PIN_NONE` marks reserved or unsupported bias-control bits.
- `r8a7796_pfc_ops` wires SoC-specific operations to `r8a7796_pin_to_pocctrl`, `rcar_pinmux_get_bias`, and `rcar_pinmux_set_bias`.
- Exported descriptors `r8a774a1_pinmux_info`, `r8a77960_pinmux_info`, and `r8a77961_pinmux_info` are `struct sh_pfc_soc_info` instances. Each sets `.unlock_reg = 0xe6060000` for PMMR-protected writes and points the shared driver at the pin, group, function, register, and pinmux data tables.

## Control Flow

This file has no probe routine and only one small local helper. Runtime behavior is descriptor-driven:

1. The platform PFC driver selects one of the exported `sh_pfc_soc_info` descriptors based on the SoC/Kconfig match.
2. The shared `sh_pfc` core registers pins, groups, functions, GPIO ranges, pinmux operations, pin configuration operations, and debugfs views from the tables in the descriptor.
3. A board pinctrl state requests a function/group pair such as `sdhi2` plus `sdhi2_data8`, `scif4` plus `scif4_data_c`, or `vin4` plus `vin4_data16_b`.
4. The core resolves the group to mux marks, resolves those marks through `pinmux_data[]`, and computes GPSR/IPSR/MOD_SEL writes from `pinmux_config_regs[]`.
5. Register writes are made through the shared PMMR unlock flow using `0xe6060000`.
6. Drive-strength requests are resolved through `pinmux_drive_regs[]`; pull-up/down requests use `r8a7796_pfc_ops.get_bias`/`.set_bias` and the PUEN/PUD tables.
7. IO-voltage requests on supported SDHI-related banks call `r8a7796_pin_to_pocctrl()` to obtain the POCCTRL bit to modify.

The only executable branch in this file is `r8a7796_pin_to_pocctrl()`: it initializes the target register to POCCTRL, returns GP3 pin bits directly for GP3[0:11], returns bit number plus 12 for GP4[0:17], and otherwise returns `-EINVAL`.

## State and Persistence

The C data is immutable after compilation. Persistent effects are hardware register effects made by the common pinctrl layer:

- GPSR registers switch GPIO-capable pins between GPIO and peripheral-function ownership.
- IPSR registers select the primary alternate function for each 4-bit field.
- MOD_SEL0-MOD_SEL2 registers select route families for multiplexed alternatives such as MSIOF, SCIF/HSCIF, I2C, DRIF, TSIF, SSI, PWM, SDHI2, SIM, VIN4, CAN/CAN-FD, and audio clocks.
- DRVCTRL registers persist drive-strength selections until changed by another pin configuration state or reset.
- PUEN/PUD registers persist bias enable and pull direction for supported pins.
- POCCTRL persists 1.8 V versus 3.3 V IO-voltage selection for GP3[0:11] and GP4[0:17].

Suspend/resume save/restore and conflict handling are outside this file. A bad table entry can still leave a real board in a wrong hardware state until reset or reconfiguration because the shared driver trusts these descriptors as authoritative SoC metadata.

## Dependencies and Integration Points

- Includes `<linux/errno.h>` for `-EINVAL` and `<linux/kernel.h>` for helpers such as `ARRAY_SIZE`.
- Includes `"sh_pfc.h"`, which defines the Renesas PFC descriptor types and macros: `struct sh_pfc_soc_info`, `struct sh_pfc_pin`, `struct sh_pfc_pin_group`, `struct sh_pfc_function`, `struct pinmux_cfg_reg`, `struct pinmux_drive_reg`, `struct pinmux_bias_reg`, `struct pinmux_ioctrl_reg`, `RCAR_GP_PIN`, `PINMUX_*`, `SH_PFC_*`, `PORT_GP_*`, and shared R-Car bias helpers.
- Integrates with Linux pinctrl indirectly through the common Renesas `sh_pfc` implementation. This file supplies SoC-specific tables; the common implementation performs parsing, validation, locking, register I/O, PMMR unlock writes, GPIO integration, and pinconf callbacks.
- Integrates with device tree as a naming contract. Function and group strings such as `avb_mii`, `qspi0_data4`, `sdhi3_data8`, `vin4_data24_a`, or `drif0_ctrl_b` are used by board pinctrl states and should be treated as ABI-like names.
- Integrates with peripheral drivers through pinctrl state application. Peripheral drivers do not call this file directly, but they rely on board states selecting the correct groups before hardware I/O begins.
- Kconfig affects the exported surface. `CONFIG_PINCTRL_PFC_R8A774A1` builds the RZ/G2M-compatible common descriptor; `CONFIG_PINCTRL_PFC_R8A77960` and `CONFIG_PINCTRL_PFC_R8A77961` include additional automotive groups and functions.

## Hardware Coverage Notes

The table set covers several large mux families:

- Audio: `audio_clk_*`, `audio_clkout*`, SSI shared clocks/data, and audio clock selectors in ADG-related MOD_SEL fields.
- Networking: AVB management, MII data/control/static pins, AVTP PPS/match/capture routes, CAN0/CAN1, CAN-FD0/CAN-FD1, and CAN clock.
- Display/video: DU RGB666/RGB888, DU clock/sync/control lines, VIN4 data widths from 8 to 24 bits with A/B routes, VIN4 high-byte subset, and VIN5 data/sync/control groups.
- Serial/control: SCIF0-SCIF5, HSCIF0-HSCIF4, SCIF clock, INTC-EX IRQ0-IRQ5, I2C0/I2C1/I2C2/I2C3/I2C5/I2C6 including physical I2C alternatives, MSIOF0-MSIOF3, PWM0-PWM6, TMU and TPU outputs.
- Storage/flash: QSPI0/QSPI1 static pins, SDHI0-SDHI3 bus-width groups, SDHI card-detect/write-protect/data-strobe groups, and NAND-function alternatives on SDHI-related pins.
- Automotive-only coverage: DRIF0-DRIF3 control/data groups and MLB 3-pin groups are present only for R8A77960/61 builds.

## Risks

- Table alignment is the main failure mode. Every `<group>_pins[]` array must match its `<group>_mux[]` array in count and signal order; otherwise the core can program a valid mark onto the wrong physical pin with no compile-time warning.
- Register field ordering is dense and manually encoded. A missing reserved slot in `PINMUX_CFG_REG_VAR()`, a wrong field width, or a misplaced `F_(0, 0)` alternative can shift subsequent alternatives and corrupt unrelated mux settings.
- `PINMUX_IPSR_MSEL()` and `PINMUX_IPSR_PHYS_MSEL()` entries must agree with MOD_SEL encodings. The visible function can look correct while a secondary selector silently chooses the wrong route.
- Static non-muxable pins still carry configuration. Omitting them from `PINMUX_STATIC`, `CPU_ALL_NOGP`, drive, or bias tables can break drive/bias control even though no mux change is needed.
- IO-voltage support is intentionally limited. `CPU_ALL_GP()` flags GP3[0:11] and GP4[0:17], and `r8a7796_pin_to_pocctrl()` maps exactly those ranges. Expanding flags without updating the helper would make pinconf return `-EINVAL`; expanding the helper incorrectly could modify the wrong POCCTRL bit.
- Conditional group/function counts must remain consistent. The `pinmux_groups` and `pinmux_functions` structs use fixed common/automotive array sizes, and the exported `nr_groups`/`nr_functions` values depend on Kconfig. Adding or removing a group requires keeping the declared sizes and descriptor counts synchronized.
- Public group names are stable binding names. Renaming an entry can break existing device trees even if the hardware register values remain correct.
- Some groups intentionally share pins across unrelated peripherals, for example SCIF/HSCIF/CAN/MSIOF/I2C/AVB alternatives. Hardware conflicts are expected, so regressions often appear as one board peripheral failing after another pin state is added.

## Test Signals

- Build all relevant configurations: `CONFIG_PINCTRL_PFC_R8A774A1`, `CONFIG_PINCTRL_PFC_R8A77960`, and `CONFIG_PINCTRL_PFC_R8A77961`. Treat enum reference failures, initializer count mismatches, section-size warnings, or missing mark/function symbols as descriptor regressions.
- Static consistency checks should verify that each pin group has equal pin/mux lengths, every string in a `<function>_groups[]` array resolves to a `pinmux_groups` entry, every mux mark used by a group exists in `pinmux_data[]`, and every fixed-size common/automotive array size matches its initializer count.
- Register-map review should compare GPSR0-GPSR7, IPSR0-IPSR18, MOD_SEL0-MOD_SEL2, DRVCTRL0-DRVCTRL24, PUEN/PUD0-PUD6, POCCTRL, and TDSELCTRL addresses/field widths against the R-Car M3-W/M3-W+ hardware manual.
- Runtime smoke tests on target hardware should request representative groups from each mux family: `avb_mii`, `canfd0_data_a/b`, `du_rgb888`, `hscif*_data`, `i2c*_a/b/c`, `msiof*_clk/sync/txd/rxd`, `qspi*_data4`, `sdhi*_data4/8`, `ssi*`, `usb*`, `vin4_data24_a/b`, `vin5_data16`, and automotive `drif*`/`mlb_3pin` where available.
- Pinconf tests should set and read drive strength and pull-up/down for pins present in the drive and bias tables, and should verify unsupported/reserved `SH_PFC_PIN_NONE` slots fail or report unsupported cleanly.
- IO-voltage tests should exercise GP3[0:11] and GP4[0:17] pins through pinconf and verify POCCTRL bit mapping, while checking that pins outside those ranges return an error for voltage selection.
- Debugfs inspection after applying board pinctrl states should show the expected function/group ownership and no unexpected mux conflicts.
