# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a77990.c

## Purpose

`pfc-r8a77990.c` is the Renesas R-Car E3 / RZ/G2E Pin Function Controller
description consumed by the shared `sh-pfc` pinctrl driver. It is not a
standalone driver entry point. Instead, it exports SoC data structures that
describe the R8A77990 and R8A774C0 pin banks, mux options, pin groups,
functions, register layouts, pull bias support, drive-strength support, and
I/O-voltage control wiring.

The file is declarative for most of its length. Its tables let the common
Renesas pinctrl core translate Linux pinctrl requests into writes to PFC
registers such as GPSR, IPSR, MOD_SEL, DRVCTRL, POCCTRL, PUEN, and PUD. The
same base tables are shared by both supported SoCs, while R8A77990 gains extra
automotive-only DRIF and MLB groups/functions behind `CONFIG_PINCTRL_PFC_R8A77990`.

## Main APIs, Types, and Exports

- `const struct sh_pfc_soc_info r8a774c0_pinmux_info`: exported when
  `CONFIG_PINCTRL_PFC_R8A774C0` is enabled. It names `"r8a774c0_pfc"` and uses
  only `pinmux_groups.common` and `pinmux_functions.common`.
- `const struct sh_pfc_soc_info r8a77990_pinmux_info`: exported when
  `CONFIG_PINCTRL_PFC_R8A77990` is enabled. It names `"r8a77990_pfc"` and adds
  the `.automotive` group/function tail to the common tables.
- `static const struct sh_pfc_soc_operations r8a77990_pfc_ops`: wires
  `.pin_to_pocctrl`, `.get_bias`, and `.set_bias` into the shared pinctrl code.
- `static int r8a77990_pin_to_pocctrl(unsigned int pin, u32 *pocctrl)`: the only
  real function in this file. It maps voltage-configurable pins to a POCCTRL
  register address and bit index, returning `-EINVAL` for pins without voltage
  control.
- `pinmux_pins`, `pinmux_data`, `pinmux_groups`, `pinmux_functions`,
  `pinmux_config_regs`, `pinmux_drive_regs`, `pinmux_ioctrl_regs`, and
  `pinmux_bias_regs`: static data arrays referenced by the SoC descriptors.

The local table types and helper macros come from `sh_pfc.h`: `struct
sh_pfc_pin`, `struct sh_pfc_pin_group`, `struct sh_pfc_function`, `struct
pinmux_cfg_reg`, `struct pinmux_drive_reg`, `struct pinmux_ioctrl_reg`, `struct
pinmux_bias_reg`, `SH_PFC_PIN_GROUP()`, `SH_PFC_FUNCTION()`,
`PINMUX_CFG_REG()`, `PINMUX_CFG_REG_VAR()`, `PINMUX_DRIVE_REG()`, and
`PINMUX_BIAS_REG()`.

## Pin and Function Model

`CFG_FLAGS` enables pull-up/down capability for most pins. `CPU_ALL_GP()` emits
GPIO-backed pins across banks GP0 through GP6. Most GPIO pins get pull
up/down support; GP3 low pins and GP4 SD pins also advertise 1.8/3.3 V
I/O-voltage switching and drive strength. GP6_9 is pull-up only. `CPU_ALL_NOGP()`
adds non-GPIO pins such as AVB static pins, reset/test pins, MLB_REF, and
VDDQ_AVB0.

The file defines GPSR macros for the primary function of each GPIO-backed pin,
IPSR macros for alternate function fields, and MOD_SEL macros for route
selection between function variants. `PINMUX_STATIC` covers pins that cannot be
muxed but still require pin configuration entries. The central enum expands
these macros into data IDs, function IDs, and mark IDs. `pinmux_data[]` then
links each mark to the register field and optional module-select constraint
needed to realize it.

The table covers many SoC interfaces: audio clocks and SSI, AVB, CAN/CAN-FD,
DU display output, HSCIF/SCIF, I2C, INTC external IRQs, MSIOF, PWM, QSPI/RPC,
SDHI0/1/3, TMU clock inputs, USB0/USB3 pins, VIN4/VIN5, plus R8A77990-only DRIF
and MLB. Bus-width variants are expressed with `BUS_DATA_PIN_GROUP()` and
`SH_PFC_PIN_GROUP_SUBSET()`, for example SDHI data1/data4/data8, QSPI data2/4,
RPC clock widths, and VIN data-width slices.

## Control Flow and Registration

There is no probe function in this file. The control flow starts in the common
Renesas PFC platform driver:

1. `core.c` matches device-tree compatibles such as `"renesas,pfc-r8a774c0"` and
   `"renesas,pfc-r8a77990"` to the exported `sh_pfc_soc_info` objects.
2. The shared core initializes the PFC device from the selected descriptor,
   including pin ranges, functions, groups, and register windows.
3. Pinctrl and pinconf requests from consumers select groups/functions by name.
   The common code searches `pinmux_data[]` and `pinmux_config_regs[]` to derive
   GPSR/IPSR/MOD_SEL writes.
4. Bias requests flow through `r8a77990_pfc_ops.get_bias` and `.set_bias`, which
   are the shared `rcar_pinmux_get_bias()` / `rcar_pinmux_set_bias()` helpers
   using `pinmux_bias_regs[]`.
5. I/O voltage requests call `r8a77990_pin_to_pocctrl()` from the common pinconf
   path to resolve the POCCTRL register and bit.

The SoC descriptor also sets `.unlock_reg = 0xe6060000`, the PMMR write-protect
unlock register used by the shared core before protected PFC register writes.

## Register and State Behavior

Persistent state is entirely hardware register state; this source file keeps no
runtime mutable state. Important register tables are:

- `pinmux_config_regs[]`: describes GPSR0-6 at `0xe6060100..0xe6060118`,
  IPSR0-15 at `0xe6060200..0xe606023c`, and MOD_SEL0/1 at
  `0xe6060500..0xe6060504`. GPSR entries select GPIO versus peripheral
  function, IPSR entries select one of the alternate functions for a pin, and
  MOD_SEL entries disambiguate alternate route variants.
- `pinmux_drive_regs[]`: exposes drive-strength fields only for SDHI-related
  GP3 and GP4 pins through DRVCTRL8-10 at `0xe6060320..0xe6060328`.
- `pinmux_ioctrl_regs[]`: lists POCCTRL0 (`0xe6060380`), POCCTRL2
  (`0xe6060388`), and TDSELCTRL (`0xe60603c0`). TDSELCTRL is listed as an
  I/O-control register but this file does not provide a helper that uses it
  directly.
- `r8a77990_pin_to_pocctrl()`: maps GP3_0 through GP3_11 to POCCTRL0 bits 0-11,
  GP4_0 through GP4_10 to POCCTRL0 bits 19-29, and `PIN_VDDQ_AVB0` to POCCTRL2
  bit 0.
- `pinmux_bias_regs[]`: describes PUEN0-5 and PUD0-5 pairs at
  `0xe6060400..0xe6060414` and `0xe6060440..0xe6060454`. Entries bind each bit
  to a GPIO or non-GPIO pin, with `SH_PFC_PIN_NONE` marking unused/reserved
  positions.

Because all arrays are `static const` except the exported descriptors, runtime
changes happen only when the common pinctrl core reads these tables and writes
the PFC registers.

## Dependencies and Integration Points

The file includes only `<linux/errno.h>`, `<linux/kernel.h>`, and `sh_pfc.h`.
It depends heavily on macro definitions from the local Renesas PFC framework,
including GPIO pin numbering (`RCAR_GP_PIN()`), no-GPIO pin numbering
(`PIN_NOGP_CFG()`), pin/function enum generation, compile-time array-size
checks, and group/function descriptors.

The direct integration points are:

- `core.c`: OF match table selects `r8a774c0_pinmux_info` or
  `r8a77990_pinmux_info`; the core consumes `pinmux_data`, pin arrays, register
  tables, and the PMMR unlock register.
- `pinctrl.c`: pinconf paths call `.pin_to_pocctrl()` for
  `PIN_CONFIG_POWER_SOURCE` style voltage configuration and use the bias ops.
- Device tree board files: consumers reference function and group names such as
  `"sdhi3_data8"`, `"scif0_data_a"`, `"avb_mii"`, `"vin4_data24_a"`, or
  `"rpc_data"`.
- Kconfig/build system: `CONFIG_PINCTRL_PFC_R8A774C0` and
  `CONFIG_PINCTRL_PFC_R8A77990` determine which descriptor exports and which
  automotive-only tables are compiled.

## SoC Variant Split

R8A774C0 and R8A77990 share the same pins, register descriptions, pinmux data,
drive-strength table, bias table, I/O-control table, and ops. Their key
difference in this file is group/function exposure:

- R8A774C0 exposes 261 common groups and 50 common functions.
- R8A77990 exposes the same common tables plus 22 automotive groups and 5
  automotive functions for DRIF0-3 and MLB.

This split means a board using the R8A774C0 compatible cannot request DRIF or
MLB groups even though many underlying mark definitions exist in the shared
enum/data machinery.

## Risks and Maintenance Concerns

- Table consistency is the main correctness risk. A mismatch between a
  `*_pins[]` array and its `*_mux[]` array would map the wrong function mark to
  a pad; `SH_PFC_PIN_GROUP()` catches length mismatch at build time but not
  semantic pin/order errors.
- Register field ordering is fragile. GPSR/IPSR/MOD_SEL macros rely on exact
  bit positions, and the file explicitly notes that MOD_SEL bit numbering is
  reversed through `REV4()` and `REV8()`. A wrong field order can select an
  unrelated peripheral route.
- The R8A77990/R8A774C0 split is easy to regress. Adding a group to the common
  arrays when it is automotive-only would expose unsupported pinctrl names for
  R8A774C0; adding a shared group under the R8A77990 guard would hide it from
  R8A774C0.
- Voltage support must stay synchronized across `CPU_ALL_GP()` pin config flags,
  `pinmux_drive_regs[]`, and `r8a77990_pin_to_pocctrl()`. The shared core warns
  if a voltage-configurable pin lacks a valid POCCTRL mapping or if a mapping
  exists without the advertised voltage flag.
- Bias entries include non-GPIO and reserved positions. Wrong `SH_PFC_PIN_NONE`
  placement or wrong no-GPIO pin IDs can make pull configuration affect the
  wrong physical signal.
- Several physical pins intentionally appear in multiple alternate groups, such
  as SDHI0 CD/WP versus SDHI3 CD/WP, USB0 versus USB30 pins, QSPI versus RPC,
  and SCIF/HSCIF variants. This is expected but means board pinctrl selections
  must avoid impossible simultaneous use.

## Test and Validation Signals

Useful validation signals are mostly compile-time and hardware/DT driven:

- Build with `CONFIG_PINCTRL_PFC_R8A774C0=y` and `CONFIG_PINCTRL_PFC_R8A77990=y`
  to exercise both descriptor exports and the guarded automotive tables.
- Compile with `CONFIG_DEBUG_FS`/pinctrl debug enabled and inspect pinctrl groups
  and functions to confirm common versus automotive group exposure.
- Boot an R8A77990 and R8A774C0 board with device-tree pinctrl states covering
  representative buses: SDHI0/1/3, RPC/QSPI, SCIF/HSCIF, AVB, USB, VIN, and
  R8A77990-only DRIF/MLB.
- Exercise pinconf bias on GPIO and no-GPIO pins listed in `pinmux_bias_regs[]`;
  verify PUEN/PUD register updates and expected electrical pull behavior.
- Exercise drive-strength configuration on SDHI GP3/GP4 pins and confirm writes
  target DRVCTRL8-10 fields.
- Exercise I/O voltage configuration for GP3_0-11, GP4_0-10, and VDDQ_AVB0;
  check that POCCTRL0/2 bits match the documented mapping and that unsupported
  pins return an error path rather than changing registers.
- Watch kernel logs from the shared PFC core for warnings about invalid
  `.pin_to_pocctrl()` mappings, missing voltage flags, unknown group names, or
  pinmux lookup failures.
