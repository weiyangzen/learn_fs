# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a77980.c

## Purpose

This file provides the Renesas R-Car V3H/R8A77980 PFC hardware description for the shared `sh_pfc` pinctrl driver. Like neighboring R-Car Gen3 PFC sources, it is a dense, table-driven SoC data file rather than an algorithmic driver. It enumerates pins, alternate functions, groups, functions, GPSR/IPSR/MOD_SEL register fields, pull-up/down mappings, and IO-voltage POCCTRL mappings for R8A77980.

## Important APIs, Types, And Functions

The exported object is `r8a77980_pinmux_info`, a `const struct sh_pfc_soc_info` named `r8a77980_pfc`. It exposes the pin, group, function, register, bias, IO-control, and pinmux-data arrays to the Renesas PFC core and uses PMMR at `0xe6060000` as the protected-write unlock register.

`CPU_ALL_GP()` defines six GPIO banks with counts 22, 28, 30, 17, 25, and 15. GP0, GP2, and GP3 advertise 1.8/3.3 V switching plus pull support; the other GPIO banks advertise pull support. `CPU_ALL_NOGP()` adds non-GPIO pads including DCUT/JTAG-style pads, `DU_DOTCLKIN`, reset/clock status pins, and voltage-control pseudo-pins `VDDQ_AVB` and `VDDQ_GE`. Enum and data generation use `PINMUX_GPSR`, `PINMUX_IPSR`, `PINMUX_MOD_SELS`, `GP_ALL()`, `F_()`, and `FM()` in the shared Renesas macro style.

The central data arrays are `pinmux_data`, `pinmux_pins`, all per-group `*_pins` and `*_mux` arrays, `pinmux_groups`, `pinmux_functions`, `pinmux_config_regs`, `pinmux_ioctrl_regs`, and `pinmux_bias_regs`. The only local function is `r8a77980_pin_to_pocctrl()`, which translates pins capable of IO-voltage selection into a POCCTRL register and bit. `r8a77980_pfc_ops` combines that helper with common `rcar_pinmux_get_bias` and `rcar_pinmux_set_bias`.

## Control Flow

Probe and registration are handled outside this source by the common Renesas PFC platform code. When the SoC match selects `r8a77980_pinmux_info`, the shared core consumes its static tables, registers the pinctrl device and GPIO ranges, and uses the GPSR/IPSR/MOD_SEL descriptors for mux programming.

At runtime, a peripheral driver or board state selects a named function/group pair. The core resolves the group to pins and mark ids, maps those marks to GPSR/IPSR/MOD_SEL fields through `pinmux_data` and `pinmux_config_regs`, writes protected PFC registers through PMMR, and exposes GPIO mode through generated GP function ids. `PINMUX_IPSR_MSEL()` entries additionally drive `MOD_SEL0` for alternate placements such as CANFD0, GEther, HSCIF0, PWM0-4, RSP/SPEEDIN, SCIF1, and TMU.

Pull-up/down configuration is handled through the PUEN/PUD tables in `pinmux_bias_regs`. IO-voltage changes route through `r8a77980_pin_to_pocctrl()`, which returns `-EINVAL` for pins not described as voltage-switchable.

## State And Persistence

All data in this file is static and immutable after build. Runtime state is owned by the shared Renesas PFC driver, generic pinctrl/GPIO objects, and hardware registers. Pinmux, bias, and IO-voltage settings persist only as MMIO-programmed hardware state until reset, power loss, sleep-state loss, or later reconfiguration. This file does not allocate memory, schedule work, hold locks, or implement custom PM callbacks.

## Dependencies And Integration Points

The direct dependencies are `linux/errno.h`, `linux/io.h`, `linux/kernel.h`, and `sh_pfc.h`. The file integrates with Linux pinctrl, pinmux, pinconf, GPIO, device-tree pin states, and R-Car peripheral drivers via the shared Renesas PFC core.

Peripheral coverage is broader than the R8A77970 table. It includes AVB RGMII/AVTP, CANFD0/1 and CANFD clock choices, DU RGB666 and RGB888, a separate GEther block with RGMII/RMII and A/B MDIO/link/PHY interrupt placement, HSCIF0 A/B and HSCIF1-3, I2C0-5, external IRQ0-5, MMC data/control plus CD/WP/DS, MSIOF0-3, PWM0-4 A/B, QSPI0/1 and RPC flash groups, SCIF0/1/3/4 plus SCIF clock choices, TMU and TPU outputs, VIN0 up to 24-bit data including an explicit 18-bit subset, and VIN1 up to 12-bit data.

The hardware register description covers GPSR0-5 at `0xe6060100` through `0xe6060114`, IPSR0-10 at `0xe6060200` through `0xe6060228`, `MOD_SEL0` at `0xe6060500`, POCCTRL0-3 at `0xe6060380` through `0xe606038c`, `TDSELCTRL` at `0xe60603c0`, and PUEN/PUD pairs from `0xe6060400`/`0xe6060440` through `0xe6060410`/`0xe6060450`.

## Risks

Descriptor correctness is the dominant risk. The table has many multiplexed pads where a typo can silently route a board peripheral to the wrong register field. High-risk areas include GEther RGMII/RMII because it spans both dedicated GP4 pins and alternate GP0 pins, VIN0 extended data because it uses GP2 pins 17-28 and special 18/20/24-bit group forms, and MMC because R8A77980 adds CD/WP/DS relative to simpler variants.

The file contains a notable review hot spot in `gether_rgmii_mux[]`: the RD1 and RD3 entries use `AVB_RD1_MARK` and `AVB_RD3_MARK` while neighboring entries use GEther marks. That may reflect shared mark definitions in this kernel snapshot, but it is suspicious enough to validate against `sh_pfc.h` definitions and the hardware manual before changing or relying on it.

The IO-voltage helper has multiple non-contiguous mappings: GP0 plus GP2 low bits in POCCTRL0, GP2 middle bits and GP3 in POCCTRL1, GP2 high bits in POCCTRL2, and `VDDQ_AVB`/`VDDQ_GE` in POCCTRL3. Errors here affect electrical compatibility, not just logical muxing. Bias tables also contain explicit `SH_PFC_PIN_NONE` holes and non-GPIO pads, so sparse bits must remain aligned with PUEN/PUD register documentation.

There is also a likely table-maintenance risk around dense IPSR definitions. For example, one HSCIF0 B entry in `pinmux_data` is associated with an `IP1_23_20` selector while it appears in the IP7 area; such cases should be treated as high-value cross-checks against upstream and datasheet sources.

## Test Signals

Useful validation includes a successful kernel build, successful R8A77980 PFC probe, and pinctrl debugfs entries showing the expected functions and group names. Board tests should exercise AVB, GEther RGMII and RMII, DU RGB888, VIN0 8/10/12/16/18/20/24-bit modes, MMC data/control/CD/WP/DS, RPC/QSPI flash, I2C0-5, HSCIF0 A/B placement, CANFD0 A/B, PWM/TMU alternates, and TPU outputs.

Pinconf and electrical tests should cover PUEN/PUD registers PUEN0-4/PUD0-4, confirm `SH_PFC_PIN_NONE` holes are ignored, verify unsupported voltage requests return `-EINVAL`, and measure or otherwise confirm POCCTRL behavior for GP0, GP2, GP3, `VDDQ_AVB`, and `VDDQ_GE`. Regression work should compare GPSR/IPSR/MOD_SEL/POCCTRL offsets and group membership with a known-good upstream R8A77980 table and with board schematics for peripherals that share pads.
