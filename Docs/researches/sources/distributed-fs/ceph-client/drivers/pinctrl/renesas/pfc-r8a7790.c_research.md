# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a7790.c

## Purpose

This file is the Renesas SH PFC pin-control description for the R-Car H2/R8A7790 family and the closely related RZ/G1H/R8A7742 build target. It is almost entirely declarative: it enumerates pins, mux function IDs, pin groups, functions, register fields, pull bias registers, and a small SoC operation table consumed by the generic Renesas `sh-pfc` pinctrl/GPIO core.

The exported objects are `r8a7790_pinmux_info` when `CONFIG_PINCTRL_PFC_R8A7790` is enabled and `r8a7742_pinmux_info` when `CONFIG_PINCTRL_PFC_R8A7742` is enabled. Both point at the same core pin/mux/register tables; R8A7790 additionally exposes the automotive-only MLB group/function.

## Important APIs, Types, and Data

- `CPU_ALL_GP()` and `CPU_ALL_NOGP()` define the SoC's GPIO-backed and non-GPIO pins. GPIO bank 3 is marked with `SH_PFC_PIN_CFG_IO_VOLTAGE_18_33` because the SD/MMC-capable pins support 1.8 V/3.3 V switching through POCCTRL. Most pins are also marked pull-up capable; ASEBRK is pull-down capable and JTAG pins are pull-up capable.
- The large top-level enum defines all pinmux enum IDs: data IDs, GPIO function IDs, GPSR/IPSR selector symbols, peripheral function marks, and module-select alternatives such as `SEL_SCIF*`, `SEL_VI*`, `SEL_IIC*`, `SEL_CAN*`, `SEL_FM*`, and others.
- `pinmux_data[]` maps marks to register-selector IDs. It uses common SH PFC macros such as `PINMUX_SINGLE`, `PINMUX_IPSR_GPSR`, `PINMUX_IPSR_MSEL`, and `PINMUX_DATA` to connect a named mux mark to a GPSR/IPSR field and, where needed, a module-select setting.
- `pinmux_pins[]` is the complete `struct sh_pfc_pin` table generated from GPIO pins plus non-GPIO pins.
- Hundreds of `<name>_pins[]` / `<name>_mux[]` arrays define concrete pin groups. Examples include audio clocks, AVB GMII/MII, CAN, display unit RGB/sync/clock pins, ETH RMII, HSCIF/SCIF/SCIFA/SCIFB serial variants, I2C/IIC buses, MMCIF, MSIOF, PWM, QSPI, SDHI, SSI, TPU, USB, and VIN capture buses.
- `pinmux_groups` aggregates 311 common `struct sh_pfc_pin_group` entries and, only for R8A7790, one automotive `mlb_3pin` group. Groups are built with `SH_PFC_PIN_GROUP`, `SH_PFC_PIN_GROUP_SUBSET`, and `BUS_DATA_PIN_GROUP`, which compile-check that pin and mux arrays match and expose narrower data widths such as `sdhi*_data1`, `sdhi*_data4`, `mmc*_data1/4/8`, `qspi_data2/4`, and many VIN widths.
- `pinmux_functions` groups pin groups into 58 common public pinctrl functions plus optional `mlb`. These names are the selectors board/device-tree users request through the Renesas pinctrl binding.
- `pinmux_config_regs[]` describes GPSR0-5, IPSR0-16, MOD_SEL, MOD_SEL2, and MOD_SEL3 register layouts at the PFC MMIO addresses. Fixed-width `PINMUX_CFG_REG` records describe GPSR GPIO/function selection; variable-width `PINMUX_CFG_REG_VAR` records describe packed IPSR/MOD_SEL fields and reserved holes.
- `pinmux_bias_regs[]` maps pins to PUPR0-PUPR6 pull-up/pull-down control bits. Most entries are pull-up-only; one `PUPR1` pull-down mapping covers `ASEBRK#/ACK`.
- `r8a7790_pin_to_pocctrl()` implements the SoC operation that maps GPIO bank 3 pins to POCCTRL at `0xe606008c`, returning bit `31 - (pin & 0x1f)` and rejecting all non-bank-3 pins with `-EINVAL`.
- `r8a7790_pinmux_soc_init()` performs a revision-specific hardware initialization: on `soc_id = r8a7790`, `revision = ES1.0`, it writes `0x00155554` to TDSEL at `0xe6060088`.
- `r8a7790_pfc_ops` wires SoC-specific operations into the core: `.init`, `.pin_to_pocctrl`, and the shared R-Car bias helpers `rcar_pinmux_get_bias` / `rcar_pinmux_set_bias`.

## Control Flow

There is no standalone driver probe in this file. Control starts in the generic Renesas PFC platform driver after a compatible SoC selects one of the exported `struct sh_pfc_soc_info` objects declared in `sh_pfc.h`.

At initialization, the core receives the SoC info, maps/unlocks the PFC MMIO block through `unlock_reg = 0xe6060000` (PMMR), registers the pin list, pin groups, and functions, then uses `pinmux_config_regs` and `pinmux_data` to program GPSR/IPSR/MOD_SEL fields when clients request a mux function. During SoC initialization, `.init` calls `soc_device_match()` and optionally programs TDSEL for R8A7790 ES1.0. Bias configuration requests flow through the shared R-Car bias helpers, which walk `pinmux_bias_regs` to find the relevant PUPR bit. IO-voltage switching requests for supported SD-bank pins call `.pin_to_pocctrl` to translate a pin number into the POCCTRL register and bit.

## State and Persistence Behavior

The file defines static, read-only hardware description tables plus two exported constant SoC descriptors. It has no dynamic allocations and no persistent state of its own. Runtime state lives in the PFC core and in hardware registers:

- GPSR/IPSR/MOD_SEL writes persist in the PFC hardware until reset or reconfiguration.
- PUPR writes persist pull bias state in hardware.
- POCCTRL writes for bank 3 pins persist SD signaling-voltage selection in hardware.
- The TDSEL write is one-time initialization for old R8A7790 revisions.

Suspend/resume save/restore, locking, register write ordering, and pinctrl consumer lifetime are handled outside this file by the generic `sh-pfc` infrastructure.

## Dependencies and Integration Points

This file depends on Linux kernel headers for errors, MMIO helpers, kernel macros, and SoC revision matching. Its main internal dependencies are `core.h` and `sh_pfc.h`, which provide `struct sh_pfc`, `struct sh_pfc_soc_info`, `struct sh_pfc_soc_operations`, `struct sh_pfc_pin_group`, `struct sh_pfc_function`, `struct pinmux_cfg_reg`, `struct pinmux_bias_reg`, the `RCAR_GP_PIN()` numbering scheme, and all table-construction macros.

The descriptor integrates with:

- The Renesas SH PFC core, which consumes `.pins`, `.groups`, `.functions`, `.cfg_regs`, `.bias_regs`, `.pinmux_data`, and `.ops`.
- Pinctrl and GPIO consumers through group/function names exposed by `pinmux_functions`.
- Device-tree board descriptions that select groups such as `sdhi0_data4`, `avb_gmii`, `qspi_data4`, `vin*_data*`, serial alternatives, or USB control pins.
- The SoC bus/sysfs identification layer through `soc_device_match()` for ES1.0 TDSEL handling.
- Kconfig: `CONFIG_PINCTRL_PFC_R8A7742` exports only common groups/functions, while `CONFIG_PINCTRL_PFC_R8A7790` exports common plus automotive MLB.

## Risks and Maintenance Notes

- Table correctness is the primary risk. A wrong enum ordering, mux mark, MOD_SEL alternative, GPSR/IPSR field width, or register address can route a peripheral to the wrong pad or program reserved bits.
- Group arrays must remain aligned: each `<name>_pins[]` entry must correspond to the same-index `<name>_mux[]` entry. The PFC macros catch array-size mismatches, but they cannot validate the electrical or package-level correctness of each mapping.
- The `pinmux_groups.common[311]` and `pinmux_functions.common[58]` fixed sizes must match the initializer counts. Adding or removing groups/functions requires updating these sizes or changing the structure pattern.
- Shared physical pins appear in multiple mutually exclusive groups and function alternatives. Incorrect board configuration can request conflicting functions; conflict detection is handled by pinctrl ownership, but board authors still need valid SoC mux choices.
- Bank 3 voltage handling is special. `CPU_ALL_GP()` advertises 1.8/3.3 V only on bank 3, and `r8a7790_pin_to_pocctrl()` rejects other banks. Any future change to bank numbering or SD-capable pins must update both the pin capabilities and the POCCTRL mapping.
- Revision-specific TDSEL initialization is hard-coded for R8A7790 ES1.0. If additional revisions need different TDSEL values, this callback is the integration point.
- R8A7742 and R8A7790 share most data but intentionally differ in exposed automotive MLB support. Accidental leakage of the automotive group into the R8A7742 descriptor would change the public pinctrl surface.

## Test Signals

Useful validation signals include:

- Build coverage with both `CONFIG_PINCTRL_PFC_R8A7790` and `CONFIG_PINCTRL_PFC_R8A7742`, with warnings enabled, to catch missing enum marks, bad macro use, or group/function count mismatches.
- Boot logs from the `sh-pfc` driver showing successful registration of the expected SoC descriptor name (`r8a77900_pfc` or `r8a77420_pfc`) and no pinctrl group/function lookup failures.
- Device-tree pinctrl smoke tests for representative peripherals: SDHI/MMC voltage-capable bank 3 pins, AVB/ETH, serial ports with MOD_SEL alternatives, I2C/IIC alternatives, VIN bus widths, DU RGB/sync, USB power/over-current pins, and QSPI.
- Runtime pinctrl debugfs inspection to confirm expected group names, function names, mux ownership, and pin bias settings are visible.
- Electrical or board-level tests for bank 3 POCCTRL switching between 3.3 V and 1.8 V on SD interfaces.
- Regression tests around R8A7790 ES1.0 systems confirming TDSEL is initialized, and non-ES1.0 or R8A7742 systems confirming the write is not incorrectly applied.
