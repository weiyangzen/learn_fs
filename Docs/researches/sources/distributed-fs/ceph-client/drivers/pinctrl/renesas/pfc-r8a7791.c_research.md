# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a7791.c

## Purpose

This file is the Renesas PFC (Pin Function Controller) SoC data description for the R-Car M2/Gen2 family variants covered by `r8a7791`, `r8a7793`, `r8a7743`, and `r8a7744`. It does not implement a standalone driver probe path. Instead it exports `struct sh_pfc_soc_info` descriptors consumed by the shared Renesas PFC core, describing:

- every GPIO-capable and non-GPIO pin known to this SoC family,
- pin function enum IDs and mark IDs used by the PFC core's pinmux tables,
- peripheral pin groups and function names exposed to device tree pinctrl consumers,
- hardware register encodings for GPSR, IPSR, MOD_SEL, pull-up/down, and POC voltage control,
- the small set of SoC-specific operations needed by the generic core.

The file is almost entirely declarative data. Runtime behavior comes from `drivers/pinctrl/renesas/core.c`, `pfc.c`, and helpers declared in `sh_pfc.h`; this file supplies the tables those shared paths interpret.

## Important APIs, Types, And Data

The file includes only `<linux/errno.h>`, `<linux/kernel.h>`, and local `"sh_pfc.h"`. The local header supplies the core table types and macros: `struct sh_pfc_pin`, `struct sh_pfc_pin_group`, `struct sh_pfc_function`, `struct pinmux_cfg_reg`, `struct pinmux_bias_reg`, `struct sh_pfc_soc_operations`, and `struct sh_pfc_soc_info`.

Important top-level macros:

- `CPU_ALL_GP(fn, sfx)` enumerates GPIO banks 0 through 7 using `PORT_GP_*` macros. Most GPIO pins receive `SH_PFC_PIN_CFG_PULL_UP`; GPIO bank 6 pins 0-23 additionally receive `SH_PFC_PIN_CFG_IO_VOLTAGE_18_33` because they may be SD pins with 1.8 V or 3.3 V signaling.
- `CPU_ALL_NOGP(fn)` enumerates non-GPIO pins such as `ASEBRK#/ACK`, `AVS1`, `AVS2`, and JTAG pins, with their pull-up or pull-down capabilities.
- The large anonymous `enum` defines the contiguous pinmux ID namespace: data IDs, function IDs, register field IDs, mode-select IDs, and exported `*_MARK` IDs.

Core static tables:

- `pinmux_data[]` maps marks and register field selections to enum IDs using `PINMUX_SINGLE`, `PINMUX_IPSR_GPSR`, and `PINMUX_IPSR_MSEL`. Plain `GPSR` entries model alternatives selected only by GPSR/IPSR fields; `MSEL` entries also require a `MOD_SEL*` selector value, such as `SEL_SCIF0_*`, `SEL_CAN0_*`, or `SEL_I2C*_*`.
- `pinmux_pins[]` exposes all GPIO and non-GPIO pins through `PINMUX_GPIO_GP_ALL()` and `PINMUX_NOGP_ALL()`.
- Hundreds of `static const unsigned int <group>_pins[]` and `<group>_mux[]` arrays define physical pin lists and corresponding mark lists for each pin group. `SH_PFC_PIN_GROUP()` later binds each pair into a `struct sh_pfc_pin_group`; the macro enforces matching array sizes at compile time.
- `pinmux_groups` contains 346 common groups and, when building `R8A7791` or `R8A7793`, 9 automotive groups (`adi_*` and `mlb_3pin`).
- `pinmux_functions` contains 58 common functions and, for `R8A7791` or `R8A7793`, 2 automotive functions (`adi`, `mlb`). Each function is a list of group names visible to pinctrl consumers.
- `pinmux_config_regs[]` describes GPSR0-GPSR7, IPSR0-IPSR16, and MOD_SEL/MOD_SEL2/MOD_SEL3/MOD_SEL4 register layouts. `PINMUX_CFG_REG()` handles fixed-width GPSR fields; `PINMUX_CFG_REG_VAR()` handles variable-width fields and reserved holes in IPSR and mode-select registers.
- `pinmux_bias_regs[]` describes pull-up and pull-down-capable pins across PUPR0-PUPR7. Most entries are pull-up-only; the final PUPR7-backed entry describes the pull-down control for `ASEBRK#/ACK`.
- `r8a7791_pfc_ops` wires this SoC data to `r8a7791_pin_to_pocctrl()`, `rcar_pinmux_get_bias`, and `rcar_pinmux_set_bias`.

Exported descriptors:

- `r8a7743_pinmux_info` (`CONFIG_PINCTRL_PFC_R8A7743`) and `r8a7744_pinmux_info` (`CONFIG_PINCTRL_PFC_R8A7744`) expose only the common group/function sets.
- `r8a7791_pinmux_info` (`CONFIG_PINCTRL_PFC_R8A7791`) and `r8a7793_pinmux_info` (`CONFIG_PINCTRL_PFC_R8A7793`) expose common plus automotive group/function sets.
- All descriptors use `unlock_reg = 0xe6060000` for PMMR, the same config and bias register tables, and the same `pinmux_data`.

## Functional Coverage

The peripheral groups cover audio clocks, AVB/ETH, CAN, display unit outputs and clock inputs, HSCIF, SCIF, SCIFA, SCIFB, I2C/IIC, interrupt inputs, MMC/SDHI, MSIOF, PWM, QSPI, SSI, TPU, USB power/overcurrent pins, and VIN0/VIN1/VIN2 capture pins. Several interfaces have alternate pin placements with `_b`, `_c`, `_d`, or `_e` suffixes; those alternatives are represented both in the group lists and in `MOD_SEL*` dependencies through `PINMUX_IPSR_MSEL`.

Bus-width variants are modeled by `BUS_DATA_PIN_GROUP()`, for example `mmc_data1`, `mmc_data4`, `mmc_data8`, `qspi_data2`, `qspi_data4`, `sdhi*_data1`, `sdhi*_data4`, and VIN data-width groups. This lets board device trees request only the subset of pins needed for a narrower bus.

## Control Flow

There is no direct probe or interrupt control flow inside this file. The effective flow is data-driven:

1. A platform/OF match in the Renesas PFC core selects one of the exported `sh_pfc_soc_info` objects for the compatible SoC.
2. The core uses `.pins`, `.groups`, `.functions`, `.cfg_regs`, `.bias_regs`, and `.pinmux_data` to register Linux pinctrl and GPIO ranges.
3. A device tree pinctrl state names a function and one or more groups.
4. The core resolves the group to physical pin numbers and mux marks, then resolves marks through `pinmux_data[]` to the needed GPSR/IPSR and, if applicable, MOD_SEL selections.
5. Register writes go through the shared PFC register paths, using PMMR unlock semantics at `0xe6060000`.
6. Pin bias requests call `rcar_pinmux_get_bias` or `rcar_pinmux_set_bias`, which use `pinmux_bias_regs[]`.
7. IO-voltage requests on bank 6 pins 0-23 call `r8a7791_pin_to_pocctrl()` to find the POCCTRL register and bit.

The only local function with branching is:

```c
static int r8a7791_pin_to_pocctrl(unsigned int pin, u32 *pocctrl)
```

It rejects pins outside `RCAR_GP_PIN(6, 0)` through `RCAR_GP_PIN(6, 23)` with `-EINVAL`, sets `*pocctrl` to `0xe606008c`, and returns bit index `31 - (pin & 0x1f)`. This reverse bit mapping must stay aligned with the hardware manual and with the `SH_PFC_PIN_CFG_IO_VOLTAGE_18_33` flags in `CPU_ALL_GP`.

## State And Persistence

The file itself holds no mutable state. All arrays are `static const` except for the exported `const struct sh_pfc_soc_info` descriptors. Runtime state lives in the shared PFC core and in hardware registers. Persistent effects are hardware register values programmed by the kernel:

- GPSR registers select GPIO-vs-function routing.
- IPSR registers select one function among alternatives on each pin field.
- MOD_SEL registers select route variants shared by multiple IPSR choices.
- PUPR registers persist pull-up/down settings while the SoC remains powered.
- POCCTRL at `0xe606008c` controls IO voltage mode for bank 6 pins 0-23.

These settings are not persisted by this source file across reboot or reset. They are reconstructed from compiled SoC tables plus board device tree pinctrl states during boot and driver binding.

## Dependencies And Integration Points

This file depends tightly on the Renesas PFC framework:

- `sh_pfc.h` provides all data structure contracts and table-construction macros.
- The shared core validates pin conflicts, group/function references, bias coverage, and IO-voltage coverage during initialization.
- Bias operations are shared R-Car helpers (`rcar_pinmux_get_bias`, `rcar_pinmux_set_bias`).
- Device tree consumers depend on the exact function and group names in `pinmux_functions`, such as `sdhi0` with `sdhi0_data4`, `avb` with `avb_mii` or `avb_gmii`, and compatibility-retained CAN clock groups under `can0` and `can1`.
- Kconfig symbols gate exported SoC descriptors and automotive-only groups. R8A7743/R8A7744 intentionally omit `adi` and `mlb`; R8A7791/R8A7793 include them.

The table is also coupled to hardware documentation. Register addresses, bit widths, field order, alternate-function encodings, and pull/voltage support must match the SoC manual; the generic core can catch structural inconsistencies but cannot prove that a numeric field value selects the intended electrical signal.

## Risks And Edge Cases

- Table mismatch risk is high: a wrong `RCAR_GP_PIN()` number, mark, or `SEL_*` mode silently routes board signals incorrectly even though the code compiles.
- Alternate routes require both IPSR and MOD_SEL correctness. Missing or wrong `PINMUX_IPSR_MSEL()` entries can make a group name appear valid while selecting a different route.
- `pinmux_groups.common` and `pinmux_functions.common` have hard-coded array sizes. Adding or removing a group/function requires updating those counts, or compilation will fail or leave initializer issues.
- Function/group names are ABI-like for device tree users. Renaming a group such as `can_clk_b` or `sdhi0_data4` can break existing board DTS files.
- Compatibility comments for CAN clock groups matter: `can_clk*` remains in `can0_groups` and `can1_groups` for older DTS users, while new designs should use the independent `can_clk` function.
- The POCCTRL mapper is intentionally limited to bank 6 pins 0-23. Adding `SH_PFC_PIN_CFG_IO_VOLTAGE_*` to any other pin without updating `pin_to_pocctrl()` will trigger core validation errors.
- Bias configuration relies on complete PUPR coverage for every pin flagged with pull-up/down support. A missing entry causes init-time validation complaints and can leave pinconf requests unsupported.
- Conditional automotive sections can create subtle build-matrix problems: references to `adi_*` or `mlb_3pin` must remain inside the same `CONFIG_PINCTRL_PFC_R8A7791 || CONFIG_PINCTRL_PFC_R8A7793` guards.

## Test Signals

Useful verification signals for this file are mostly compile-time and boot-time:

- Build with `CONFIG_PINCTRL_PFC_R8A7743`, `CONFIG_PINCTRL_PFC_R8A7744`, `CONFIG_PINCTRL_PFC_R8A7791`, and `CONFIG_PINCTRL_PFC_R8A7793` combinations to catch conditional descriptor and array-size issues.
- Compile-time macro checks from `SH_PFC_PIN_GROUP()` catch mismatched `<group>_pins[]` and `<group>_mux[]` lengths.
- `PINMUX_CFG_REG()` fixed-width registers include build-time sizing checks for enum count vs register width. Variable-width `PINMUX_CFG_REG_VAR()` tables are more dependent on core validation and careful review.
- Boot with PFC core diagnostics enabled and watch for `sh_pfc_check_info()` errors about duplicate pins, duplicate enum IDs, missing bias registers, invalid `pin_to_pocctrl()`, or valid POCCTRL mappings on pins that lack IO-voltage config flags.
- Exercise representative device tree states for common buses: SDHI0/1/2 including 1-bit and 4-bit data groups, MMC 8-bit and `_b` variants, AVB MII/GMII, CAN data and independent clock groups, VIN width variants, and serial route suffixes.
- Pinconf tests should request pull-up/down on flagged pins and IO voltage changes on bank 6 pins 0-23, confirming the expected PUPR and POCCTRL register bits are touched.
- Regression tests should include older DTS files that use CAN clock groups through `can0` or `can1`, since the file intentionally preserves those names for backward compatibility.
