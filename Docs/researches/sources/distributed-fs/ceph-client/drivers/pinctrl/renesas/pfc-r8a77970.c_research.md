# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a77970.c

## Purpose

This file supplies the Renesas R-Car V3M/R8A77970 pin-function-controller data consumed by the shared `sh_pfc` pinctrl driver. It is primarily a SoC descriptor: it names the GPIO and non-GPIO pads, maps pads to alternate functions, declares pin groups and public pinmux functions, describes the PFC register layout, and wires R8A77970-specific pull/bias and IO-voltage support into the common Renesas PFC core.

## Important APIs, Types, And Functions

The exported integration object is `r8a77970_pinmux_info`, a `const struct sh_pfc_soc_info` named `r8a77970_pfc`. It points at `pinmux_pins`, `pinmux_groups`, `pinmux_functions`, `pinmux_config_regs`, `pinmux_bias_regs`, `pinmux_ioctrl_regs`, and `pinmux_data`, and sets `.unlock_reg = 0xe6060000` for PMMR-protected writes.

The file's local data model is built with shared `sh_pfc.h` macros. `CPU_ALL_GP()` declares six GPIO banks with counts 22, 28, 17, 17, 6, and 15, including IO-voltage capability on GP0, GP2, and GP3 and pull capability on all GPIO banks. `CPU_ALL_NOGP()` adds non-GPIO pads such as `DU_DOTCLKIN`, reset/clock/test pins, and `VDDQ_AVB0`. `PINMUX_GPSR`, `PINMUX_IPSR`, and `PINMUX_MOD_SELS` feed enum generation for data ids, function ids, and mark ids.

Important static arrays include `pinmux_data`, which links GPIO/function ids to marks and register selections; `pinmux_pins`, which combines all GPIO and non-GPIO pins; per-group `*_pins` and `*_mux` arrays; `pinmux_groups`, which publishes those groups to pinctrl; and `pinmux_functions`, which groups them by peripheral function. The only local executable helper is `r8a77970_pin_to_pocctrl()`, used by `r8a77970_pfc_ops` to map a pin supporting configurable IO voltage to a POCCTRL register address and bit index. Bias is delegated to `rcar_pinmux_get_bias` and `rcar_pinmux_set_bias`.

## Control Flow

There is no platform-driver probe in this file. The broader Renesas PFC platform code selects `r8a77970_pinmux_info` for the matching SoC and passes the static descriptor to the common `sh_pfc` initialization path. That path uses `.function = { PINMUX_FUNCTION_BEGIN, PINMUX_FUNCTION_END }`, `pinmux_data`, and the config-register descriptors to register pins, groups, mux functions, GPIO ranges, and pinconf operations.

Runtime pinmux requests are table-driven. A client selects a group such as `avb0_rgmii`, `i2c3_b`, `mmc_data8`, or `vin0_data12`; the common core looks up the group pins and mux marks, finds the GPSR/IPSR/MOD_SEL encodings through `pinmux_data` and `pinmux_config_regs`, unlocks protected writes through PMMR, and programs GPSR/IPSR/MOD_SEL registers. GPIO mode is selected through the GP function ids generated by `GP_ALL(FN)`.

Pin configuration follows two secondary paths. Pull enable and pull direction use `pinmux_bias_regs`, which map PUEN/PUD register bits to pins. IO-voltage configuration calls `r8a77970_pin_to_pocctrl()` and then writes POCCTRL bits for eligible GP0, GP2, GP3, and `PIN_VDDQ_AVB0` pads; unsupported pins return `-EINVAL`.

## State And Persistence

The file owns only immutable static metadata. Mutable state lives in the common Renesas PFC device, pinctrl core structures, GPIO subsystem state, and PFC hardware registers. Register programming persists as hardware state until reset, power loss, suspend-state loss, or a later pinctrl/GPIO/pinconf operation changes it. There is no local allocation, reference counting, file persistence, or custom suspend/resume code in this source.

## Dependencies And Integration Points

The direct code dependencies are Linux kernel headers `errno.h`, `io.h`, and `kernel.h`, plus Renesas `sh_pfc.h`. Conceptually it integrates with the generic Linux pinctrl, pinmux, pinconf, and GPIO frameworks through the shared `drivers/pinctrl/renesas` core. Board device trees and peripheral drivers depend on the function/group names published here.

Peripheral coverage includes AVB0 RGMII and AVTP pins, CAN-FD clock and channels, display unit RGB666 plus sync/control outputs, HSCIF0-3, I2C0-4 with two I2C3 placements, external interrupt pins IRQ0-5, MMC data/control groups, MSIOF0-3, PWM0-4 A/B choices, QSPI0/1 and RPC flash pins, SCIF clock plus SCIF0/1/3/4, TMU clock inputs, and VIN0/VIN1 8/10/12-bit data groups plus sync/field/clock pins.

The register map is the hardware contract. GPSR0-5 live at `0xe6060100` through `0xe6060114`, IPSR0-8 at `0xe6060200` through `0xe6060220`, `MOD_SEL0` at `0xe6060500`, POCCTRL0-2 at `0xe6060380` through `0xe6060388`, `TDSELCTRL` at `0xe60603c0`, and PUEN/PUD bias pairs at `0xe6060400`/`0xe6060440` through `0xe606040c`/`0xe606044c`.

## Risks

The primary risk is descriptor accuracy. A single wrong GP pin, mux mark, IPSR field, MOD_SEL selector, or register bit silently programs the wrong pad or selects the wrong alternate function. Multi-location functions such as I2C3, SCIF1, CANFD0, TMU, PWM, and RFSO/SPEEDIN rely on both IPSR fields and `MOD_SEL0`; inconsistent `PINMUX_IPSR_MSEL()` and MOD_SEL definitions can make valid board pin groups fail.

The IO-voltage helper is range-sensitive. `r8a77970_pin_to_pocctrl()` maps GP0 bits 0-21 and GP2 bits 0-9 into POCCTRL0, GP2 bits 10-16 and GP3 bits 0-16 into POCCTRL1, and `PIN_VDDQ_AVB0` into POCCTRL2 bit 0. Any off-by-one here changes electrical voltage for the wrong bank. Bias coverage is similarly table-sensitive: PUEN/PUD entries include several non-GPIO pins and leave unused slots as `SH_PFC_PIN_NONE`, so gaps should match the hardware manual.

Because this is static data, compiler success is not enough. Many mistakes only show when a board requests the affected group, when a peripheral shares a pad with another function, or when pinconf tries pull/voltage settings on a sparse pad range.

## Test Signals

Useful signals include a kernel build with this PFC object enabled, successful boot/probe on an R8A77970 board with `r8a77970_pfc`, and pinctrl debugfs showing expected pins, groups, and functions. Board-level tests should exercise AVB0 RGMII, MMC data widths, QSPI/RPC flash boot pins, VIN0/VIN1 capture widths, SCIF/HSCIF channels, I2C buses including both I2C3 placements, CANFD0 A/B, and PWM/TMU alternate placements.

Pinconf-specific checks should verify pull enable/direction on representative PUEN0-3 entries, confirm unsupported pins return an error rather than programming an arbitrary bit, and validate 1.8/3.3 V switching only on GP0/GP2/GP3 and `VDDQ_AVB0`. Regression review should also compare all register offsets and selectors against the R8A77970 hardware manual or a known-good upstream table.
