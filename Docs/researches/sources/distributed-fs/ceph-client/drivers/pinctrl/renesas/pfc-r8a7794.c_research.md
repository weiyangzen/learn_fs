# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a7794.c

## Purpose

This file is the Renesas PFC/pinmux description for the R-Car E2 `r8a7794` and compatible `r8a7745` SoCs. It is almost entirely static SoC metadata: pin IDs, pin-function marks, GPIO/function mux mappings, named pin groups, named pin functions, hardware register layouts, pull-up/pull-down bias mappings, and SoC operation hooks. The Renesas `sh_pfc` core consumes these tables through `struct sh_pfc_soc_info` to expose Linux pinctrl, GPIO muxing, bias, and voltage-control behavior.

The file covers the SoC's GP banks 0 through 6 plus several non-GPIO pins such as JTAG/debug pins. It describes peripheral routes for audio clocks, AVB, CAN, DU, Ethernet, HSCIF/SCIF/SCIFA/SCIFB, I2C/IIC, interrupt pins, MMC/SDHI, MSIOF, PWM, QSPI, SSI, TPU, USB, and VIN.

## Important APIs, Types, and Data

- `CPU_ALL_GP()` and `CPU_ALL_NOGP()` define the complete pin universe used by the macro-generated `GP_ALL()`, `PINMUX_GPIO_GP_ALL()`, and `PINMUX_NOGP_ALL()` expansions. Most GPIO-capable pins advertise `SH_PFC_PIN_CFG_PULL_UP`; bank 6 carries additional `SH_PFC_PIN_CFG_IO_VOLTAGE_18_33` flags on voltage-switchable storage pins.
- The main anonymous enum defines all pinmux tokens: data pins, function selectors (`FN_*`), mark IDs (`*_MARK`), and module selector values (`SEL_*`). These values become the internal IDs used by the tables below.
- `pinmux_data[]` links marks to IP selector fields and module-selector dependencies. Simple entries use `PINMUX_SINGLE()` or `PINMUX_IPSR_GPSR()`. Alternate routes that also need a module select register use `PINMUX_IPSR_MSEL()`.
- `pinmux_pins[]` exposes all GPIO and non-GPIO pins as `struct sh_pfc_pin` records.
- Hundreds of `<group>_pins[]` and `<group>_mux[]` arrays define the physical pins and required mux marks for each named pin group. Examples include bus-width variants such as `du0_rgb666`/`du0_rgb888`, `mmc_data1`/`mmc_data4`/`mmc_data8`, `sdhi*_data1`/`sdhi*_data4`, `qspi_data2`/`qspi_data4`, and `vin*_data*`.
- `pinmux_groups[]` collects all `struct sh_pfc_pin_group` entries with `SH_PFC_PIN_GROUP()` and `BUS_DATA_PIN_GROUP()` macros.
- `<function>_groups[]` arrays define the group names offered by each logical pinctrl function. `pinmux_functions[]` wraps those arrays with `SH_PFC_FUNCTION()`.
- `pinmux_config_regs[]` describes the memory-mapped mux registers: `GPSR0`-`GPSR6` at `0xe6060004` through `0xe606001c`, `IPSR0`-`IPSR13` at `0xe6060020` through `0xe6060054`, and `MOD_SEL`, `MOD_SEL2`, `MOD_SEL3` at `0xe6060090`, `0xe6060094`, and `0xe6060098`.
- `pinmux_bias_regs[]` maps bias-capable pins to `PUPR0`-`PUPR6` registers at `0xe6060100` through `0xe6060118`. It also models the `PUPR1` pull-down-only entry for `ASEBRK#/ACK`.
- `r8a7794_pin_to_pocctrl()` maps supported bank-6 pins to the POC control register at `0xe606006c` and returns the bit controlling that pin's I/O voltage.
- `r8a7794_pinmux_soc_init()` performs the only SoC-init side effect in this file: for `r8a7794` revision `ES1.0`, detected by `soc_device_match()`, it writes `0x55555500` to `0xe6060068` to initialize TDSEL.
- `r8a7794_pfc_ops` connects the SoC hooks to the shared core: `.init`, `.pin_to_pocctrl`, `.get_bias = rcar_pinmux_get_bias`, and `.set_bias = rcar_pinmux_set_bias`.
- `r8a7745_pinmux_info` and `r8a7794_pinmux_info` are the exported `struct sh_pfc_soc_info` instances, gated by `CONFIG_PINCTRL_PFC_R8A7745` and `CONFIG_PINCTRL_PFC_R8A7794`.

## Control Flow

Runtime control is data-driven. The platform-specific PFC driver selects either `r8a7745_pinmux_info` or `r8a7794_pinmux_info` at probe time, then the shared `sh_pfc` core walks the provided pin, group, function, pinmux-data, config-register, and bias-register tables. There are no per-group functions in this file; selecting a device-tree pinctrl function resolves a function name to a group, a group to pins plus mux marks, and mux marks to GPSR/IPSR/MOD_SEL register writes.

Initialization enters through `r8a7794_pfc_ops.init`. The helper checks for `r8a7794` ES1.0 only and writes the TDSEL register for that old revision. Bias reads/writes enter the generic `rcar_pinmux_get_bias()` and `rcar_pinmux_set_bias()` helpers with this file's `pinmux_bias_regs[]`. I/O voltage control enters `r8a7794_pin_to_pocctrl()`, which rejects pins outside `RCAR_GP_PIN(6, 0)` through `RCAR_GP_PIN(6, 23)` and otherwise computes the POCCTRL bit from the low five pin bits.

## State and Persistence

All driver-owned data in this file is `static const` except for executable helper functions, so the source itself maintains no mutable software state. Persistent effects are hardware-register effects:

- GPSR/IPSR/MOD_SEL writes choose GPIO or peripheral functions and persist until changed by another pinctrl operation or reset.
- PUPR writes set pull-up or pull-down bias where supported and persist in the PFC hardware.
- POCCTRL writes, routed through the shared core using `r8a7794_pin_to_pocctrl()`, select 1.8 V or 3.3 V operation for supported bank-6 pins.
- The ES1.0 TDSEL write in `r8a7794_pinmux_soc_init()` initializes a hardware timing/selection register during PFC setup.

There is no filesystem persistence and no dynamic allocation in this file.

## Dependencies and Integration Points

The file depends on Linux kernel headers `linux/errno.h`, `linux/kernel.h`, and `linux/sys_soc.h`, plus local Renesas PFC headers `core.h` and `sh_pfc.h`. Most behavior is delegated to macros and shared helpers from the Renesas PFC framework: `PORT_GP_CFG_*`, `PIN_NOGP_CFG`, `PINMUX_*`, `SH_PFC_PIN_GROUP`, `BUS_DATA_PIN_GROUP`, `SH_PFC_FUNCTION`, `PINMUX_CFG_REG*`, `PINMUX_BIAS_REG`, `RCAR_GP_PIN`, `sh_pfc_write`, `rcar_pinmux_get_bias`, and `rcar_pinmux_set_bias`.

Device-tree pinctrl users integrate by naming the functions and groups exposed by `pinmux_functions[]` and the `<function>_groups[]` arrays. The `can0_groups` and `can1_groups` arrays still include `can_clk*` groups for backward compatibility, while comments direct new designs to the independent `can_clk` function. Conditional compilation allows the same table body to serve both `r8a7745` and `r8a7794` with different `.name` strings but identical operations and register data.

## Risks and Maintenance Notes

- The file is table-heavy and compile-time validation is limited. A typo in an enum token, IP field, group name string, or mux mark can silently expose a wrong pin route or make a valid route unusable.
- `PINMUX_IPSR_MSEL()` entries must match both `pinmux_data[]` and `pinmux_config_regs[]`. One suspicious entry maps `CAN0_RX_C` through `IP7_8_6` in `pinmux_data[]`, while the register table places `FN_CAN0_RX_C` under `IP5_8_6`; this should be cross-checked against the SoC manual or upstream history before relying on that alternate CAN0 route.
- `scifa4_data_pins[]` lists `RCAR_GP_PIN(4, 12)` for both RXD and TXD. If intentional, it needs hardware-manual justification; if not, it can make the base `scifa4_data` group unusable or misleading.
- Bank-6 voltage control is range-limited to pins 6.0 through 6.23, but `CPU_ALL_GP()` marks bank-6 pins 24 and 25 only with pull-up capability. Consumers expecting voltage switching on all bank-6 pins must use the advertised pin configuration flags, not the bank number alone.
- The PUPR tables contain many `SH_PFC_PIN_NONE` holes and special non-GPIO pins. Bias support must be tested per pin, not inferred from neighboring register bits.
- Backward-compatible CAN clock grouping means older device trees may request clocks via `can0` or `can1`, while newer descriptions may request `can_clk`. Changes to those arrays risk device-tree ABI regressions.

## Test Signals

- Build coverage: compile with `CONFIG_PINCTRL_PFC_R8A7794=y` and `CONFIG_PINCTRL_PFC_R8A7745=y` to ensure both `struct sh_pfc_soc_info` definitions and all table references compile.
- Pinctrl registration: boot on supported hardware or an integration test harness and verify the PFC core registers the expected pins, groups, and functions without unresolved group names.
- Device-tree smoke tests: request representative groups from each large family, such as SDHI, MMC, I2C, SCIF, Ethernet/AVB, DU, VIN, SSI, and CAN including `can_clk`.
- Register-level tests: verify selected groups produce expected GPSR/IPSR/MOD_SEL writes, especially routes using `PINMUX_IPSR_MSEL()` selectors.
- Bias tests: exercise pull-up and pull-down settings on pins covered by `PUPR0`-`PUPR6`, including rejection for `SH_PFC_PIN_NONE` holes and unsupported pull direction.
- Voltage tests: request 1.8 V/3.3 V switching on supported bank-6 storage pins and verify `r8a7794_pin_to_pocctrl()` rejects unsupported pins with `-EINVAL`.
- Revision-specific test: on or emulating `r8a7794` ES1.0, confirm `r8a7794_pinmux_soc_init()` writes `0x55555500` to `0xe6060068`; on later revisions and on `r8a7745`, confirm the TDSEL write is not performed unless the SoC match table says so.
