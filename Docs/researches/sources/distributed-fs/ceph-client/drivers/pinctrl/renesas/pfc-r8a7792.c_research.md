# sources/distributed-fs/ceph-client/drivers/pinctrl/renesas/pfc-r8a7792.c

## Purpose
`pfc-r8a7792.c` is the Renesas R-Car V2H/R8A7792 Pin Function Controller SoC description. It does not probe hardware directly; instead it exports `r8a7792_pinmux_info`, a static `struct sh_pfc_soc_info` consumed by the shared Renesas `sh_pfc` pinctrl/GPIO driver. The file describes the chip's GPIO-capable pins, non-GPIO pins, alternate-function enum IDs, GPSR/IPSR register fields, pull-up/pull-down registers, and named pin groups/functions exposed to device-tree pinctrl consumers.

## Important APIs, Types, And Data
- `CPU_ALL_GP()` and `CPU_ALL_NOGP()` expand the R8A7792 physical pin namespace. GPIO banks 0 through 11 contain 29, 23, 32, 28, six 17-pin banks, 32, and 30 pins respectively, with pull-up capability. The non-GPIO pins are DU dot clocks, debug/JTAG pins, and `EDBGREQ`; all are pull-up capable except `EDBGREQ`, which is pull-down capable.
- The main enum declares the `PINMUX_DATA`, `PINMUX_FUNCTION`, and `PINMUX_MARK` ranges used by the `sh_pfc` core. It includes GP data/function enum IDs, GPSR field enum IDs, IPSR field enum IDs, alternate-function names, and marks for pin-group mux arrays.
- `pinmux_data[]` maps each user-visible `*_MARK` to the enum IDs that must be selected to realize it. Simple single-function pins use `PINMUX_SINGLE()`, GPIO plus IPSR functions use `PINMUX_IPSR_GPSR()`, and the alternate VIN1 routing uses `PINMUX_IPSR_MSEL()` with `SEL_VI1_0` or `SEL_VI1_1`.
- `pinmux_pins[]` is built from `PINMUX_GPIO_GP_ALL()` and `PINMUX_NOGP_ALL()`, giving the core pin names, numeric pin IDs, enum IDs, and advertised pinconf capabilities.
- Per-peripheral `*_pins[]` and `*_mux[]` arrays define concrete pin groups. Covered functions include AVB Ethernet, CAN0/1, DU0/1 display, INTC IRQs, LBSC external bus, MSIOF0/1, QSPI, SCIF0-3, SDHI0, and VIN0-5 capture.
- `pinmux_groups[]` publishes groups with `SH_PFC_PIN_GROUP()` and width-specific `BUS_DATA_PIN_GROUP()` entries such as `qspi_data2`, `qspi_data4`, `sdhi0_data1`, `sdhi0_data4`, and VIN data-width variants.
- `pinmux_functions[]` groups those pin groups into pinctrl functions named `avb`, `can0`, `can1`, `du0`, `du1`, `intc`, `lbsc`, `msiof0`, `msiof1`, `qspi`, `scif0`, `scif1`, `scif2`, `scif3`, `sdhi0`, and `vin0` through `vin5`.
- `pinmux_config_regs[]` describes the MMIO mux programming model: GPSR0-GPSR11 at `0xe6060004` through `0xe6060030`, IPSR0-IPSR7 at `0xe6060040` through `0xe606005c`, and a sentinel terminator. Fixed-width GPSR entries select GPIO vs peripheral routing, while variable-width IPSR entries encode alternate function choices and reserved fields.
- `pinmux_bias_regs[]` describes PUPR0-PUPR12 at `0xe6060100` through `0xe6060130`. Most entries are pull-up mappings for GPIO banks; PUPR12 is split into a pull-up view for DU/JTAG pins and a pull-down view for `EDBGREQ`.
- `r8a7792_pfc_ops` wires bias callbacks to `rcar_pinmux_get_bias()` and `rcar_pinmux_set_bias()`.
- `r8a7792_pinmux_info` sets `.name = "r8a77920_pfc"`, `.unlock_reg = 0xe6060000` for PMMR-protected register writes, and passes all static pin, group, function, config-register, bias-register, and pinmux-data tables to the core.

## Control Flow
At build time this file contributes data to the Renesas PFC driver selected for the R8A7792 SoC. At boot, the common Renesas pinctrl platform driver matches the SoC and receives `r8a7792_pinmux_info`. The core registers the listed pins, groups, and functions with the Linux pinctrl subsystem. When a consumer selects a device-tree pinctrl state, the core resolves requested function/group names, follows the group's `mux[]` marks through `pinmux_data[]`, and writes the matching GPSR/IPSR fields through the protected register-write path using PMMR at `0xe6060000`. Pin bias requests are routed through `r8a7792_pfc_ops` into the common R-Car bias helpers, which use `pinmux_bias_regs[]` to find the PUPR bit for the requested pin.

## State And Persistence Behavior
The file's state is static and immutable after compilation: enum IDs, pin descriptors, group arrays, function arrays, register descriptors, and exported SoC metadata. Runtime state lives in the shared `sh_pfc` core, including MMIO mappings, locks, GPIO state, saved registers when supported, pinctrl ownership, and any parsed device-tree state. Hardware state persists in the SoC PFC registers until reset, suspend/resume restore, or a later pinctrl/GPIO/bias operation overwrites it. There is no filesystem or distributed-storage persistence.

## Dependencies And Integration Points
- Depends on `sh_pfc.h` for the Renesas pinmux macros, `struct sh_pfc_soc_info`, pin-group/function/register types, and `SH_PFC_PIN_CFG_*` capability bits.
- Integrates with the Linux pinctrl core through the shared Renesas `sh_pfc` driver rather than through local probe/remove functions.
- Integrates with gpiolib for GPIO-capable banks generated by the `GP_ALL()`/`PORT_GP_CFG_*()` macros.
- Device-tree consumers reference the function and group names published here in pinctrl states; mismatches leave peripheral drivers unable to select their pins.
- Peripheral integration is broad but declarative: AVB, CAN, DU, INTC, LBSC, MSIOF, QSPI, SCIF, SDHI, and VIN drivers depend on these groups matching the board routing and hardware manual.

## Risks And Edge Cases
- The pin, mark, function, and config-register enum IDs are position-sensitive. Reordering or inserting entries without updating `pinmux_data[]`, GPSR/IPSR fields, and group mux arrays can compile but program the wrong mux value.
- `*_pins[]` and `*_mux[]` arrays must have identical lengths. The `SH_PFC_PIN_GROUP()` macro catches size mismatches at build time, but it cannot prove that each pin is paired with the correct mark.
- GPSR/IPSR register descriptors use MSB-to-LSB field ordering with explicit reserved fields. A wrong field width, reserved count, or enum order can shift every later function in the register.
- VIN1 has duplicate route variants selected by `SEL_VI1_0` and `SEL_VI1_1`; incorrect module-select data can make a valid-looking group select the wrong physical pins.
- Pull configuration is constrained by the advertised pin capabilities and `pinmux_bias_regs[]`. Missing or wrong PUPR mappings can make pinconf bias requests silently affect the wrong pad or report unsupported behavior.
- The PMMR unlock register is security-critical for writes to protected PFC registers; an incorrect `.unlock_reg` would prevent mux changes or corrupt unrelated protected writes.
- Function/group names are ABI-like for DTS files. Renaming `qspi_data4`, `vin*_data*`, `scif*_data`, and similar groups breaks board descriptions even if C compilation succeeds.

## Test Signals
- Build the Renesas PFC driver with this SoC enabled and treat compiler/`BUILD_BUG_ON_ZERO()` failures in `PINMUX_CFG_REG*()`, `SH_PFC_PIN_GROUP()`, and bus-width group macros as table-integrity failures.
- Boot an R8A7792/R-Car V2H board or emulator configuration that selects `r8a7792_pinmux_info`; `/sys/kernel/debug/pinctrl/` should show `r8a77920_pfc`, the expected pins, function names, and group names.
- Exercise DTS pinctrl states for representative peripherals: SCIF console, SDHI0, QSPI, CAN, AVB MII/GMII plus MDIO/link pins, DU0/DU1 display groups, and VIN data-width variants.
- Verify bias operations for GPIO-bank pins and non-GPIO PUPR12 pins, including pull-up on DU/JTAG pins and pull-down on `EDBGREQ`.
- Inspect GPSR/IPSR register changes around state selection and confirm PMMR-protected writes land at the intended `0xe60600xx` registers with no reserved-field drift.
- Test suspend/resume or reselect default/sleep states where available, because persistence is hardware-register based and restoration is handled outside this file.
