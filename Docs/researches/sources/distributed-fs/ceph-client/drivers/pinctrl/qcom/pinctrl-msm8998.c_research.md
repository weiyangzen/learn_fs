# sources/distributed-fs/ceph-client/drivers/pinctrl/qcom/pinctrl-msm8998.c

## Purpose
This file describes the Qualcomm MSM8998 TLMM pin controller for the shared `pinctrl-msm` core. It provides the SoC-specific pin inventory, tile/register base choices, mux function catalog, per-pin mux group table, SDC2 special groups, UFS reset control, and MPM wake IRQ map.

## Important APIs, types, and functions
The key data structures are `msm8998_pins`, `msm8998_functions`, `msm8998_groups`, `msm8998_mpm_map`, and `msm8998_pinctrl`. Normal GPIOs are generated by `PINGROUP(id, base, ...)`, where `base` is one of `NORTH`, `WEST`, or `EAST`; offsets are `base + 0x1000 * id` with standard TLMM bit fields. `SDC_QDSD_PINGROUP()` covers SDC2 clock/command/data pads, and `UFS_RESET()` covers the dedicated UFS reset output with pull, drive, and output value fields but no mux or IRQ support.

The probe path is `msm8998_pinctrl_probe()` -> `msm_pinctrl_probe(pdev, &msm8998_pinctrl)`. The platform driver is registered by `arch_initcall(msm8998_pinctrl_init)` and matches `qcom,msm8998-pinctrl`.

## Control flow
The driver is bound from device tree, then immediately delegates to the common Qualcomm pinctrl core. After registration, all operations are data-driven: function selection indexes into the `PINGROUP()` mux array, pin configuration uses the bit positions in `struct msm_pingroup`, GPIO operations use `io_reg`, and IRQ operations use `intr_cfg_reg`/`intr_status_reg` plus the target value. Wake IRQ setup uses `msm8998_mpm_map`.

## State and persistence behavior
Runtime state is in the shared core and hardware registers, not in this file. The descriptor exposes 150 GPIOs and four non-GPIO special pins: SDC2 CLK/CMD/DATA and UFS_RESET. `.ngpios = 150` is therefore an important boundary between GPIO-exportable pins and special-function-only descriptors.

## Dependencies and integration points
The file depends on `pinctrl-msm.h`, platform driver registration, and OF matching. It integrates with DT pinctrl states for BLSP, CCI, camera clocks, HDMI/eDP, PCIe, audio, QDSS, UIM, TSIF, MDP vsync, qlink, and storage-related pads. The NORTH/WEST/EAST base constants model the physical register tile split, while the MPM map connects TLMM GPIOs to low-power wake interrupt numbers.

## Risks and edge cases
Tile base selection is a major correctness risk: a valid GPIO id with the wrong base writes a different register window. The `_` unavailable mux sentinel must line up with `msm_mux__` and with mux slot numbering expected by device trees. The UFS reset group has a custom register shape and can be broken by treating it like a normal GPIO. Wake map ordering is not semantically important, but wrong pairs are hard to detect until suspend/resume tests. SDC2 groups have no IRQ/GPIO fields, so clients must not expect them to behave like regular GPIOs.

## Test signals
Check boot binding for `qcom,msm8998-pinctrl`, pinctrl debugfs function/group visibility, GPIO line count of 150, successful muxing of BLSP, display, camera, QDSS, and audio pins, UFS reset behavior during storage initialization, SDC2 operation under pinconf changes, interrupt tests on GPIOs in each tile, and wake-from-suspend for representative MPM-mapped GPIOs across NORTH/WEST/EAST.
