# sources/distributed-fs/ceph-client/drivers/crypto/talitos.h

Purpose: defines the Talitos/SEC descriptor ABI, software request/channel/private data structures, feature bits, register offsets, and descriptor-header constants consumed by `talitos.c`.

Important APIs and types: `struct talitos_ptr` models a hardware descriptor pointer in SEC2 format with length, jump/extent byte, extended address byte, and low pointer, or SEC1 format with `len1`. `struct talitos_desc` contains the high/low header words, seven pointer slots, and a SEC1 `next_desc`. `struct talitos_edesc` extends a hardware descriptor with source/destination scatter counts, IV DMA address, link-table DMA metadata, and a flexible link-table or SEC1 bounce-buffer area. `struct talitos_request` stores the in-flight descriptor DMA address and callback. `struct talitos_channel` holds each channel's MMIO base, software FIFO, head/tail locks, FIFO indices, and atomic submit counter. `struct talitos_private` is the whole device state: global and execution-unit register bases, IRQs, locks, geometry/capability fields, channels, tasklets, algorithm list, and hwrng data. `has_ftr_sec1()` resolves SEC1 behavior from build options and runtime feature bits.

Control flow encoded by constants: global register definitions cover master reset/remap, interrupt mask/status/clear, channel base/stride, channel config/status/fetch FIFO/current descriptor/descriptor-buffer registers, and execution-unit bases for SEC1.0, SEC1.2, and SEC2. Descriptor bits select primary and secondary execution units, modes for AES/DEU/MDEU, HMAC/pad/init/continue/auth-check behavior, direction, done notification, descriptor type, and link-table jump/return markers. Macros such as `DESC_TYPE()`, `PRIMARY_EU()`, and `SECONDARY_EU()` let probe-time code compare algorithm templates against DT capability masks.

State and persistence behavior: the header itself owns no mutable state but fixes the binary layout of DMA descriptors and the in-memory driver state used by interrupt handlers, tasklets, Crypto API callbacks, and hwrng code. Endianness annotations and `cpu_to_be32()` constants are part of the hardware contract; changing them would alter on-wire descriptor values. Feature flags persist in `talitos_private.features` and gate runtime paths for SEC1, hardware auth check, SHA224 hardware init, HMAC support, and source link-table extent rules.

Dependencies and integration points: depends on Linux types such as `__be32`, `dma_addr_t`, `scatterlist`, `tasklet_struct`, `hwrng`, atomics, spinlocks, and flexible-array helpers. It is tightly integrated with Freescale/NXP SEC hardware documentation and with the Crypto API templates in `talitos.c`.

Risks and test signals: risks include layout drift breaking DMA descriptors, SEC1/SEC2 union misuse, big-endian constant mistakes, feature-bit mismatches versus compatible strings, and register-offset assumptions that vary by SEC revision. Test signals are successful compilation for `CONFIG_CRYPTO_DEV_TALITOS1`, `CONFIG_CRYPTO_DEV_TALITOS2`, and combined builds; correct descriptor sizes; hardware completion writeback to `DESC_HDR_DONE`; capability filtering matching DT masks; and no sparse/endian warnings in descriptor construction.
