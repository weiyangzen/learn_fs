# sources/distributed-fs/ceph-client/drivers/crypto/tegra/tegra-se-key.c

Purpose: manages NVIDIA Tegra SE keyslots and key insertion command streams shared by AES, AEAD, CMAC, and HMAC code.

Important APIs and control flow: global keyslot state is a `u16` bitmap protected by `kslt_lock`; keyslot 0 and reserved slots 14/15 are pre-marked unavailable for normal allocation. `tegra_keyslot_alloc()` finds the first zero bit with `ffz()`, marks it in use, and returns 0 on exhaustion. `tegra_keyslot_free()` clears a bit. `tegra_key_prep_ins_cmd()` emits a host1x command stream that stalls/dummies the SE op register, writes a key manifest, selects a destination slot, writes each 32-bit key word through key address/data registers, configures insert mode, starts the operation, and appends a syncpoint increment. `tegra_key_insert()` serializes command-buffer use under `kslt_lock` and submits the keybuf through `tegra_se_host1x_submit()`.

State and persistence behavior: `tegra_se_keyslots` persists module-wide across all SE instances, not per device. Normal allocated keyslots remain occupied until transform exit calls `tegra_key_invalidate()`, which overwrites the slot with zeros and frees the bit. Reserved keyslots are overwritten by `tegra_key_invalidate_reserved()` but are never freed for normal allocation. `tegra_key_submit()` reuses an existing valid slot if the caller's `keyid` is already allocated; otherwise it allocates a slot before insertion. If insertion fails after allocation, the allocated bit is not freed in this file.

Dependencies and integration points: depends on host1x opcode helpers and register offsets in `tegra-se.h`, AES key-size constants for zeroing with `AES_MAX_KEY_SIZE`, and the device-specific `se->manifest()` callback installed by AES or hash initialization. AES uses normal and reserved submit helpers, while hash/HMAC uses normal key submission and key invalidation.

Risks and test signals: risks include global keyslot accounting across multiple SE devices, allocation leaks when insertion fails, `tegra_keyslot_free()` accepting reserved or invalid slots without validation, key casting to `u32 *` assuming alignment and native word order, no keylen multiple-of-4 guard in this file, serialized key insertion reusing a shared keybuf, and returning 0 as both exhaustion sentinel and reserved slot number. Test signals include repeated setkey/exit cycles leaving the bitmap at reserved-only state, failure injection for host1x key insertion, concurrent transforms across AES/hash devices, reserved-slot fallback overwrite behavior, invalid key length rejection by callers, and KAC manifest values for ENC/XTS/GCM/CMAC/HMAC purposes.
