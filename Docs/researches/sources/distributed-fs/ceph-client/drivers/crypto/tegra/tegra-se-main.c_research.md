# sources/distributed-fs/ceph-client/drivers/crypto/tegra/tegra-se-main.c

Purpose: provides the platform, host1x, DMA command-buffer, and hardware-descriptor glue for the NVIDIA Tegra Security Engine crypto driver.

Important APIs and control flow: command buffers are wrapped as `host1x_bo` objects by `tegra_se_cmdbuf_ops`. `tegra_se_host1x_bo_alloc()` allocates a DMA buffer from the parent device, initializes refcounted BO state, and returns it for command or key streams. Pin/unpin convert the coherent buffer to an sg table, DMA-map it for host1x, and expose the physical address to the job. `tegra_se_host1x_submit()` allocates a serialized host1x job, attaches a gather from the command BO, pins/submits it, waits indefinitely for the syncpoint end value, and releases the job.

Probe flow allocates `struct tegra_se`, maps MMIO, sets a 39-bit coherent DMA mask, enables the device clock, reads the IOMMU stream ID, programs `SE_STREAM_ID`, creates and starts a `crypto_engine`, and registers a host1x client. Host1x client initialization requests a channel and syncpoint, allocates 4 KiB command and key buffers, then calls the hardware-specific `init_alg()` callback. Compatible data selects either Tegra234 AES registers/class `0x3b` and `tegra_init_aes()`, or Tegra234 hash registers/class `0x3d` and `tegra_init_hash()`. Module init registers a host1x driver first and the platform driver second; module exit unregisters both.

State and persistence behavior: persistent per-device state includes host1x client/channel/syncpoint, shared command/key buffers, crypto engine, clock, stream ID, MMIO base, owner ID, and hardware data. Command buffers are reused across queued crypto requests and key insertions; correctness depends on crypto-engine serialization and keyslot mutex serialization. Host1x completion is synchronous from each crypto-engine worker. Removal exits the crypto engine and unregisters the host1x client; client deinit unregisters algorithms and releases buffers/channel/syncpoint.

Dependencies and integration points: depends on platform DT compatibles `nvidia,tegra234-se-aes` and `nvidia,tegra234-se-hash`, host1x client/job/syncpoint APIs, Tegra IOMMU stream ID lookup, Linux clocks, coherent DMA, crypto engine, and register definitions from `tegra-se.h`. AES/hash/key files call `tegra_se_host1x_submit()` to execute generated command streams.

Risks and test signals: risks include `tegra_se_host1x_bo_alloc()` leaking the wrapper if DMA allocation fails, `tegra_se_host1x_submit()` returning on syncpoint wait timeout without unpinning or putting the job, command/key buffer size fixed at 4 KiB with no explicit command length bound, `map->chunks = err` after successful `dma_map_sgtable()` leaving zero chunks, removal ordering where crypto engine exit occurs before host1x client unregister, and host1x client registration ignoring a return value. Test signals include platform probe for both compatibles, stream ID programmed correctly, host1x job pin/submit/wait success, timeout/error injection without leaked jobs, algorithm registration during client init, request serialization under load, module unload after active requests, and DMA mask/IOMMU operation above 32-bit addresses.
