# sources/distributed-fs/ceph-client/drivers/crypto/tegra/tegra-se-aes.c

Purpose: implements NVIDIA Tegra Security Engine AES-family algorithms: skcipher `cbc(aes)`, `ecb(aes)`, `ctr(aes)`, `xts(aes)`, AEAD `gcm(aes)` and `ccm(aes)`, and ahash-style `cmac(aes)`.

Important APIs and control flow: skcipher state is held in `struct tegra_aes_ctx` and per-request `struct tegra_aes_reqctx`. `tegra_aes_setkey()` and `tegra_xts_setkey()` validate AES/XTS keys, try to insert them into SE keyslots, and cache key bytes for later reserved-slot insertion if normal allocation fails. `tegra_aes_crypt()` validates request length, marks encrypt/decrypt, and queues to the shared crypto engine. `tegra_aes_do_one_req()` copies the request scatterlist to a coherent buffer, pads non-XTS hardware input to block size, prepares config and crypto config, ensures keyslot IDs, emits a host1x command stream with `tegra_aes_prep_cmd()`, waits for host1x completion, updates CBC/CTR IVs, copies output back, invalidates reserved keyslots, and finalizes the skcipher request.

AEAD control flow decomposes authenticated modes into several SE jobs. GCM initializes IV words from the 96-bit GCM nonce, optionally runs `tegra_gcm_do_gmac()` over AAD, runs `tegra_gcm_do_crypt()` over payload, runs `tegra_gcm_do_final()` to generate a 128-bit tag, and verifies tags in software on decrypt with `crypto_memneq()`. CCM validates the RFC3610/NIST IV format, zeroes the counter field, formats B0/AAD/plaintext blocks in `tegra_ccm_format_blocks()`, computes CBC-MAC with `tegra_ccm_compute_auth()`, then encrypts/decrypts payload and tag through CTR in `tegra_ccm_do_ctr()`, with decrypt doing CTR before MAC verification. CMAC uses `struct tegra_cmac_reqctx` to stage update/final tasks, preserve intermediate result registers across updates, reserve the last block for finalization, and uses a shash fallback for zero-length digest edge cases.

State and persistence behavior: transform state stores keyslot IDs, cached key bytes, key length, algorithm ID, IV size, auth size, and fallback shash for CMAC. Request state stores coherent input/output buffers, scatterlist pointers, lengths, operation config words, IV/counter words, temporary auth data, residue buffers, and saved CMAC result registers. Hardware state is in SE keyslots, result registers, linear counter registers, and host1x command execution; normal keyslots persist across transform lifetime until `cra_exit`, while reserved keyslots 14/15 are overwritten after each fallback use. The code copies all request data through DMA-coherent bounce buffers rather than mapping caller scatterlists directly.

Dependencies and integration points: depends on `tegra-se.h` register/opcode/key APIs, the shared `tegra_se_host1x_submit()`, crypto engine registration/finalization, Linux AES/GCM/XTS helpers, scatterwalk copy helpers, coherent DMA allocation, result-register MMIO reads/writes, and keyslot management from `tegra-se-key.c`. `tegra_init_aes()` sets the KAC manifest callback, registers skcipher, AEAD, and CMAC algorithms, and unwinds partial registration on failure; `tegra_deinit_aes()` unregisters them.

Risks and test signals: risks include several error-path issues: `tegra_aes_setkey()`, `tegra_xts_setkey()`, and `tegra_aead_setkey()` return success even when key insertion fails, relying on cached-key reserved-slot fallback later; `tegra_ccm_do_one_req()` appears to pass `outbuf` to the inbuf free call and `inbuf` to the outbuf free call, which is a serious DMA-free mismatch; GCM allocates zero-sized buffers when both AAD/payload are absent; CMAC export/import copies DMA pointers and transient buffer addresses, making imported state unsafe across lifetimes; command-buffer sharing relies on crypto-engine serialization; and bounce-buffer allocation caps/size checks are limited despite `SE_MAX_MEM_ALLOC`. Test signals include crypto self-tests for AES modes, XTS key validation, GCM/CCM tag verification failures returning `-EBADMSG`, empty CMAC using fallback correctly, DMA-API debug for CCM frees, repeated setkey/exit invalidating slots, IV copyback for CBC/CTR, large scatterlist requests, and host1x timeout/error paths finalizing requests exactly once.
