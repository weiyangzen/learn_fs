# sources/distributed-fs/ceph-client/drivers/tty/serial/pch_uart.c

Purpose: PCI UART driver for Intel EG20T PCH and ROHM/LAPIS ML7213/ML7223/ML7831 devices. It exposes up to four `ttyPCH` serial ports, supports FIFO variants, optional PCH DMA, MSI, debugfs register dumps, DMI/OF/module-parameter UART clock selection, console, and polling.

Important APIs/types/functions: `struct eg20t_port` wraps `uart_port` with PCI device, mapped register addresses, FIFO size/trigger state, RX staging buffer, cached modem/FCR/MCR state, optional DMA channels/descriptors/scatterlists, coherent RX DMA buffer, and IRQ name. `drv_dat[]` maps PCI IDs to port type and line number. HAL helpers such as `pch_uart_hal_set_line()`, `pch_uart_hal_set_fifo()`, `pch_uart_hal_read()`, and interrupt enable/disable functions encapsulate 16550-like register accesses. `pch_uart_interrupt()` decodes IIR causes and dispatches to PIO/DMA RX/TX, line-status, and modem-status logic. `pch_uart_init_port()` enables MSI/mastering, allocates buffers, initializes `uart_port`, installs console lookup, registers the port, and creates debugfs.

Control flow: module init registers the serial driver then the PCI driver. PCI probe enables the device and calls `pch_uart_init_port()`. Serial-core open invokes `pch_uart_startup()`, which disables interrupts, sets default baud/8N1, configures FIFO/trigger level, requests a shared IRQ, optionally requests DMA, enables RX and RX error interrupts, and updates timeout. Interrupt RX can read directly into a page buffer and push to TTY, or arm a DMA slave transfer and push in `pch_dma_rx_complete()`. TX can write the FIFO in PIO or build scatterlists from `xmit_fifo`, map them, and advance the FIFO in `pch_dma_tx_complete()`. Shutdown masks interrupts, resets/disables FIFOs, frees DMA, and frees the IRQ. Remove unregisters the port, removes debugfs, disables MSI/device, and frees allocations.

State and persistence: persistent software state includes `start_tx`, `start_rx`, `tx_empty`, `trigger_level`, DMA-in-use flags, cached `fcr`/`mcr`, and module globals `default_baud` and `user_uartclk`. Hardware line/FIFO/modem registers persist until shutdown or device reset. `port_show_regs()` exposes a debugfs snapshot, temporarily toggling DLAB to read divisor latches. DMA state is dynamically allocated and released around startup/shutdown or verify-port DMA mode changes.

Dependencies and integration points: PCI core and ID table, serial core, TTY, optional `CONFIG_PCH_DMA`/DMAengine with `pch_dma_slave`, DMI board matching for UART clocks, optional OF `clock-frequency`, debugfs, console and poll console code, MSI, and module parameters. Supported devices are keyed by Intel and ROHM PCI vendor/device IDs.

Risks: DMA TX has several partial-failure paths after allocation/mapping/prep where `tx_dma_use`, allocated scatterlists, or mappings may not be unwound immediately. `pch_request_dma()` assigns `chan_rx` before checking coherent RX allocation success. `pch_uart_set_mctrl()` writes MCR only when `mctrl` is nonzero, which may make clearing outputs surprising. DMI clock assumptions and module overrides directly affect baud accuracy. Debugfs creation is not checked and names are global. FIFO/trigger math must remain aligned with port type; only UART0-like 256-byte FIFOs get auto hardware flow.

Test signals: PCI ID to line/type mapping, DMI and `user_uartclk` clock selection, startup/shutdown in PIO and DMA mode, DMA request failure fallback, RX timeout and RX error paths, TX wakeup and `tx_empty` behavior, `verify_port()` low-latency toggle semantics, debugfs register dump around DLAB restore, suspend/resume through `uart_suspend_port()`, console setup before/after PCI probe, and cleanup after `uart_add_one_port()` or IRQ request failures.
