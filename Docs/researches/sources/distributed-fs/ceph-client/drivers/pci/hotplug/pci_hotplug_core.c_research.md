# sources/distributed-fs/ceph-client/drivers/pci/hotplug/pci_hotplug_core.c

Purpose: Provides the generic PCI hotplug core interface for hotplug controller drivers. It initializes and publishes `struct hotplug_slot` objects as `struct pci_slot` sysfs entries, creates optional hotplug attributes based on driver ops, dispatches sysfs reads/writes to controller callbacks, and exposes helpers to bracket intentionally spurious link changes.

Important APIs and functions: Exported APIs include `__pci_hp_register()`, `__pci_hp_initialize()`, `pci_hp_add()`, `pci_hp_deregister()`, `pci_hp_del()`, `pci_hp_destroy()`, `pci_hp_ignore_link_change()`, `pci_hp_unignore_link_change()`, and `pci_hp_spurious_link_change()`. Internal sysfs functions include `power_read_file()`, `power_write_file()`, `attention_read_file()`, `attention_write_file()`, `latch_read_file()`, `presence_read_file()`, `test_write_file()`, feature predicates `has_*_file()`, and `fs_add_slot()`/`fs_remove_slot()`.

Control flow: Drivers call `pci_hp_register()` or the split `pci_hp_initialize()` plus `pci_hp_add()` flow. Initialization validates the slot and ops, stores owner/module name, creates or references a `pci_slot`, and links the hotplug slot to it. Add creates the module symlink and optional `power`, `attention`, `latch`, `adapter`, and `test` sysfs files, then emits a `KOBJ_ADD` uevent. Sysfs writes parse numeric values and call driver callbacks such as `enable_slot`, `disable_slot`, `set_attention_status`, and `hardware_test`. Deregistration removes sysfs files and destroys the PCI slot reference. Link-change helpers set bits in `pdev->priv_flags` and coordinate with a waitqueue so hotplug drivers can ignore changes caused by resets, D3cold, firmware updates, or FPGA reconfiguration.

State and persistence: Persistent state is mostly attached to `struct hotplug_slot` and `struct pci_slot`; this file keeps only the `debug` module parameter and `pci_hp_link_change_wq`. Sysfs files persist while a slot is published. `PCI_LINK_CHANGING` and `PCI_LINK_CHANGED` bits persist in the bridge device private flags until cleared by `pci_hp_spurious_link_change()`.

Dependencies and integration points: Used by pciehp, IBM PHP, OCTEON hotplug, CompactPCI, and other hotplug drivers through `<linux/pci_hotplug.h>`. Integrates with PCI slot core (`pci_create_slot()`/`pci_destroy_slot()`), kobject/sysfs/module infrastructure, waitqueues, and `cpci_hotplug_init()` at device init time.

Risks: Sysfs write parsing uses `simple_strtoul()` and masks to narrow integer types, so malformed trailing text is not rejected. Hotplug callbacks are invoked directly from sysfs context and must handle their own locking and runtime power. `fs_add_slot()` cleanup removes the module symlink unconditionally on some error exits even if it was never created, which is generally harmless but assumes sysfs remove tolerance. The link-change bracketing protocol depends on callers pairing ignore/unignore and hotplug drivers performing their own sanity checks afterward.

Test signals: Slot registration should create the expected sysfs files only for implemented ops and emit uevents. `power` writes should call enable/disable callbacks and reject values other than 0/1. Attention, latch, adapter, and test attributes should reflect callback availability. Link-change tests should verify wait behavior while `PCI_LINK_CHANGING` is set and one-shot true return from `pci_hp_spurious_link_change()` after unignore.
