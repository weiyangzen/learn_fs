# sources/distributed-fs/ceph-client/drivers/pci/hotplug/ibmphp_res.c

Purpose: Maintains the IBM PHP driver's private PCI resource allocator. It converts EBDA POST resource descriptors into per-bus IO, memory, and prefetchable-memory ranges, tracks resources already consumed by devices, finds aligned holes for hot-added devices and bridges, and frees resources during hot-removal.

Important APIs and functions: Public APIs are `ibmphp_rsrc_init()`, `ibmphp_add_resource()`, `ibmphp_remove_resource()`, `ibmphp_check_resource()`, `ibmphp_remove_bus()`, `ibmphp_find_resource()`, `ibmphp_free_resources()`, `ibmphp_add_pfmem_from_mem()`, `ibmphp_find_res_bus()`, and `ibmphp_print_test()`. Internal helpers include `alloc_bus_range()`, `add_bus_range()`, `update_resources()`, `fix_resources()`, `find_range()`, `remove_ranges()`, `once_over()`, `range_exists_already()`, `update_bridge_ranges()`, and `find_bus_wprev()`.

Control flow: `ibmphp_rsrc_init()` walks `ibmphp_ebda_pci_rsrc_head`. Primary-bus descriptors create sorted range lists on `gbuses`; device descriptors create allocated resource nodes and insert them into the matching bus/type list, using temporary error buses and `rangeno = -1` when device records appear before range records. After EBDA import, `update_bridge_ranges()` scans existing PCI-to-PCI bridges to add secondary-bus windows missing from EBDA and mirror those bridge windows as resources on the parent bus. `once_over()` handles EBDA prefetchable allocations that actually came from memory ranges. At runtime, `ibmphp_check_resource()` finds the smallest aligned hole in the relevant bus range list, `ibmphp_add_resource()` inserts the allocation, and removal functions unlink and free matching nodes.

State and persistence: The private `gbuses` list persists all bus nodes, range nodes, resource nodes, and `firstPFMemFromMem` fallback nodes. Range numbering is persistent within each bus and is updated when ranges are inserted. The allocator state mirrors but does not own generic PCI core resources; it is freed by `ibmphp_free_resources()`.

Dependencies and integration points: Consumes EBDA resources produced by `ibmphp_ebda.c` and services allocation/removal calls from `ibmphp_pci.c`. Uses Linux list/slab/Pci config APIs and `ibmphp.h` resource masks and constants. It also reads live PCI bridge config registers while reconstructing windows for boot-time bridges.

Risks: This allocator is complex and pointer-heavy, with separate `next` and `nextRange` chains plus range numbers that must stay synchronized. Several cleanup paths free nodes without list reinitialization because teardown is assumed. `ibmphp_check_resource()` temporarily decrements `res->len` and restores it only on many return paths; future edits could easily introduce length corruption. Address math is 32-bit in many places, while bridge prefetchable upper 32 bits are conditionally folded only on 64-bit builds. Concurrency is not local to this file; callers must hold higher-level operation locks when mutating resources.

Test signals: Initialization should produce correct bus/range/resource dumps with no lingering `rangeno = -1`. Allocation tests should cover first resource on a bus, holes before/between/after existing nodes, bridge alignment requirements, PFMEM fallback to MEM, and multiple ranges. Removal tests should cover ordinary resources, PFMEM-from-MEM coupled removal, bridge bus removal, and module cleanup after partial initialization.
