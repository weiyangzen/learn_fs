# sources/distributed-fs/ceph-client/drivers/pci/hotplug/pciehp_core.c

Purpose: Registers PCIe hotplug as a PCIe port service driver and bridges the generic PCI hotplug core sysfs interface to PCIe hotplug controller operations. It handles service probe/remove, slot initialization/publication, runtime and system PM interrupt handling, and presence reconciliation after probe or resume.

Important APIs and functions: Public module init entry is `pcie_hp_init()`. Key internal functions are `init_slot()`, `cleanup_slot()`, sysfs callback adapters `set_attention_status()`, `get_power_status()`, `get_latch_status()`, `get_adapter_status()`, `pciehp_check_presence()`, service callbacks `pciehp_probe()`/`pciehp_remove()`, PM helpers `pme_is_native()`, `pciehp_disable_interrupt()`, `pciehp_suspend()`, `pciehp_resume_noirq()`, `pciehp_resume()`, `pciehp_runtime_suspend()`, and `pciehp_runtime_resume()`.

Control flow: `pcie_hp_init()` registers `hpdriver_portdrv` for `PCIE_PORT_SERVICE_HP`. Probe rejects non-hotplug services or bridges without subordinate buses, allocates/initializes a controller via `pcie_init()`, initializes a hotplug slot and operations, enables notifications via `pcie_init_notification()`, publishes the slot with `pci_hp_add()`, then calls `pciehp_check_presence()` to synthesize a presence-change event if hardware and state disagree. Remove unpublishes the slot, shuts down notifications, destroys slot resources, and releases the controller. PM paths disable interrupts before suspend/runtime suspend, restore command-busy bookkeeping after config restore, clear stale hotplug events, detect device replacement across sleep, and re-enable interrupts/rescan presence on resume.

State and persistence: Exports module parameters `pciehp_poll_mode` and `pciehp_poll_time`. Per-controller state lives in `struct controller`: hotplug ops, state machine, cached command state, pending events, Device Serial Number, and notification status. Sysfs slot objects persist from successful `pci_hp_add()` until remove.

Dependencies and integration points: Uses PCIe port service registration, generic PCI hotplug core, controller/HPC functions from `pciehp_hpc.c`, state machine functions from `pciehp_ctrl.c`, runtime PM config access wrappers, PCI bus walking, and host bridge native PME policy. It integrates with the PCIe port bus, not direct PCI device driver matching.

Risks: Probe unwind must balance controller allocation, slot initialization, notification setup, and publication; future edits need to preserve that order. Resume paths deliberately synthesize events and mark old devices disconnected when DSN changes, which can surprise drivers if replacement detection is wrong. Sysfs status callbacks runtime-resume the port around config reads/writes and rely on lower layers to tolerate inaccessible hardware. Poll mode behavior depends on module parameters that retain bootarg compatibility.

Test signals: Hotplug-capable port probe should produce one `/sys/bus/pci/slots/<PSN>` entry, working `power` and status files, and immediate enable for an occupied slot. PM tests should cover system suspend/resume with unchanged, removed, and replaced devices; runtime suspend/resume; native versus non-native PME; and polling mode. Removal should leave no sysfs slot or IRQ/poll resources.
