# sources/distributed-fs/ceph-client/drivers/pci/hotplug/pciehp_ctrl.c

Purpose: Implements the PCIe hotplug state machine for attention-button, sysfs, presence, and data-link events. It powers slots on/off, configures or unconfigures downstream devices, controls indicators, handles safe versus surprise removal, and coordinates synchronous sysfs requests with the IRQ thread.

Important APIs and functions: Public event handlers are `pciehp_request()`, `pciehp_queue_pushbutton_work()`, `pciehp_handle_button_press()`, `pciehp_handle_disable_request()`, `pciehp_handle_presence_or_link_change()`, `pciehp_sysfs_enable_slot()`, and `pciehp_sysfs_disable_slot()`. Internal helpers include `set_slot_off()`, `board_added()`, `remove_board()`, `__pciehp_enable_slot()`, `pciehp_enable_slot()`, `__pciehp_disable_slot()`, and `pciehp_disable_slot()`.

Control flow: IRQ/HPC code calls `pciehp_request()` to OR event/action bits into `pending_events` and wake the IRQ thread. Attention-button events toggle between stable states and five-second blinking states, scheduling or canceling `button_work`. Delayed button work translates blinking-on to a synthetic presence-change request and blinking-off to `DISABLE_SLOT`. Presence/link change handling first powers off and unconfigures an already-on slot because the device identity cannot be trusted after link/presence changes, then rechecks presence/link and powers on/configures if occupied. Sysfs enable/disable requests submit events to the IRQ thread and wait on `requester` until pending work and interrupt-thread execution complete.

State and persistence: Mutates `ctrl->state`, `ctrl->pending_events`, `ctrl->request_result`, indicator state, slot power, downstream PCI device enumeration, and hardware LBMS indications. `state_lock` serializes state transitions and delayed-work cancellation. Runtime PM references keep the port accessible while enabling/disabling slots.

Dependencies and integration points: Calls hardware helpers from `pciehp_hpc.c` for power, indicators, latch, presence, link, and power-fault status. Calls `pciehp_configure_device()` and `pciehp_unconfigure_device()` for downstream PCI enumeration/removal, generic PM runtime APIs, tracepoints, and PCI link-bandwidth reset helper. It is invoked by the IRQ thread/polling code and by hotplug core sysfs callbacks installed in `pciehp_core.c`.

Risks: Correctness depends on careful state-lock coverage around delayed work, sysfs waiters, and IRQ-thread actions. Presence/link handling intentionally removes a slot before deciding whether to re-add because same-card identity cannot be assumed; changing that would risk driver access to replaced hardware. `__pciehp_disable_slot()` returns `-EINVAL` when already powered off, which sysfs callers surface as failure even though the end state is off. If IRQ thread wakeups are lost, sysfs enable/disable can wait until `pending_events` and `ist_running` clear. Indicator updates must remain balanced on failure paths so user-visible LEDs match state.

Test signals: Exercise attention-button press, cancel within five seconds, delayed power-on/off, sysfs `power` writes, safe removal, surprise removal on DLLSC/PDC, failed link training, power fault, already-enabled/disabled cases, and PM-runtime suspended ports. Tracepoints `PCI_HOTPLUG_CARD_PRESENT`, `CARD_NOT_PRESENT`, `LINK_UP`, and `LINK_DOWN` plus final `ctrl->state` values provide strong validation.
