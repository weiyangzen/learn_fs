# sources/distributed-fs/ceph-client/drivers/pci/pci-sysfs.c

## Purpose
`pci-sysfs.c` builds the sysfs control and inspection surface for PCI devices and buses. It exposes stable text attributes such as IDs, power state, local CPU affinity, resources, MSI policy, bridge bus numbers, PCIe link status, reset controls, and resize controls, plus binary attributes for config space, ROM contents, legacy I/O or memory windows, and mmap-capable BAR resources. The file sits at the boundary between user space and the core PCI device model, so most operations either present cached `struct pci_dev` state or carefully bracket hardware config-space access with runtime-PM and security checks.

## Important APIs, Types, and Functions
The file is organized around sysfs `struct attribute_group`, `struct device_attribute`, `struct bus_attribute`, and `struct bin_attribute` definitions. `pci_dev_groups`, `pci_dev_attr_groups`, `pcibus_groups`, and `pci_bus_groups` are the exported group arrays consumed by the PCI bus/device registration path.

Important read-only text attributes are generated by `pci_config_attr()` for `vendor`, `device`, `subsystem_vendor`, `subsystem_device`, `revision`, and `class`. Additional show helpers expose `irq`, `power_state`, `resource`, `local_cpus`, `local_cpulist`, `dma_mask_bits`, `consistent_dma_mask_bits`, `modalias`, PCIe `current_link_speed`, `current_link_width`, `max_link_speed`, `max_link_width`, bridge `secondary_bus_number`, `subordinate_bus_number`, `ari_enabled`, VGA `boot_vga`, OF `devspec`, and DSN-backed `serial_number`.

Important writable controls include `enable_store()`, `broken_parity_status_store()`, `numa_node_store()`, `msi_bus_store()`, bus and device `rescan` stores, `remove_store()`, `reset_subordinate_store()`, `d3cold_allowed_store()`, `reset_store()`, `reset_method_store()`, and `resourceN_resize_store()` generated for BARs 0-5.

Binary entry points are `pci_read_config()` and `pci_write_config()` for the `config` file, `pci_read_rom()` and `pci_write_rom()` for `rom`, legacy file handlers under `HAVE_PCI_LEGACY`, and resource mmap/read/write helpers under `HAVE_PCI_MMAP` or `ARCH_GENERIC_PCI_MMAP_RESOURCE`. Dynamic BAR files are allocated by `pci_create_attr()` and torn down by `pci_remove_resource_files()`.

## Control Flow
Basic attributes are registered through group arrays. Visibility callbacks gate optional attributes: bridge attributes require `pci_is_bridge()`, PCIe link attributes require `pci_is_pcie()`, hotplug remove/rescan attributes are hidden for virtual functions, reset attributes require `pci_reset_supported()`, resource resize attributes require a valid current ReBAR size, ROM binary visibility requires a ROM resource, and DSN/boot-VGA attributes are exposed only when supported by the device.

The late init path `pci_sysfs_init()` sets `sysfs_initialized`, iterates all existing PCI devices to create resource files, then iterates all buses to create legacy I/O and memory files. Devices added after late init call `pci_create_sysfs_dev_files()`, which returns `-EACCES` before sysfs initialization and otherwise delegates to dynamic resource-file creation. Removal calls `pci_remove_sysfs_dev_files()`.

Config-space reads clamp unprivileged users to the first 64 bytes, except CardBus gets 128 bytes, while CAP_SYS_ADMIN can read `dev->cfg_size`. Reads and writes split transfers into byte, word, and dword accesses aligned to the requested offset; both hold a runtime-PM reference through `pci_config_pm_runtime_get()` and `pci_config_pm_runtime_put()`. Config writes are blocked by kernel lockdown and warn/taint on writes into `driver_exclusive_resource`.

Resource file creation walks standard BARs, skips empty or non-mappable resources, creates `resourceN` files, and creates `resourceN_wc` for prefetchable BARs when write-combining mmap is supported. Resource mmap checks lockdown, rejects exclusive iomem resources, validates the VMA with `pci_mmap_fits()`, and calls `pci_mmap_resource_range()`. I/O BAR byte/word/dword access is implemented through inb/inw/inl and outb/outw/outl when `CONFIG_HAS_IOPORT` is enabled.

Reset and resize sysfs paths are explicitly state-changing. `reset_store()` only accepts `1`, takes a runtime-PM reference, and calls `pci_reset_function()`. `reset_method_store()` can disable all reset methods, restore defaults with `default`, or parse a space-separated priority list validated by probing each candidate reset function. `resourceN_resize_store()` requires no bound driver and no VFs, disables memory decoding, removes BAR sysfs files, calls `pci_resize_resource()`, reassigns bus resources, recreates resource files, restores the command register, and releases the runtime-PM and device locks.

## State and Persistence Behavior
The file mutates in-kernel PCI device state but has no durable storage. Stateful fields include `pdev->broken_parity_status`, `atomic_t enable_cnt`, `dev->numa_node`, `pdev->no_msi` or subordinate `bus_flags`, `pdev->d3cold_allowed`, `pdev->rom_attr_enabled`, `pdev->reset_methods[]`, and `pdev->res_attr[]`/`res_attr_wc[]`. Hardware-visible state changes include enabling/disabling devices, PME/D3cold bridge policy updates, reset execution, BAR size changes, config-space writes, resource mmap, I/O port access, and legacy I/O exposure.

Dynamic sysfs state is owned by the device or bus object. BAR binary attributes are allocated with the attribute name trailing the `struct bin_attribute`; cleanup removes files and frees the allocation. Legacy `legacy_io` and `legacy_mem` attributes are allocated as a two-element block attached to `struct pci_bus` and freed together.

## Dependencies and Integration Points
The file depends on the Linux driver core sysfs APIs, PCI core helpers from `include/linux/pci.h` and `drivers/pci/pci.h`, runtime PM, lockdown security, capability checks, NUMA/topology helpers, MSI policy, VGA arbitration, Open Firmware, ACPI/PM conditionals, aperture conflict removal for VGA BAR resizing, and architecture hooks for legacy and resource mmap. It integrates with other PCI sysfs groups such as VPD, SMBIOS, ACPI, SR-IOV, AER, ASPM, DOE, and TSM by including their group pointers in `pci_dev_groups` or `pci_dev_attr_groups`.

## Risks
This file exposes privileged hardware mutation to user space. Risks include machine instability from `enable`, `reset`, `remove`, BAR resize, or arbitrary config writes on active devices. The code mitigates some paths with CAP_SYS_ADMIN, `device_lock()`, runtime-PM references, lockdown checks, driver-bound checks, VF checks, and resource exclusivity warnings, but callers can still disrupt hardware by design.

Config-space and resource accesses rely on device presence and stable topology. Runtime-PM bracketing prevents D3cold config access, but surprise removal can still cause read failures or error responses handled by lower-level PCI accessors. Resource resize is especially sensitive because it temporarily removes sysfs files, disables memory decoding, reallocates resources, and recreates files; failure to recreate files is only warned.

Visibility and capability checks are important compatibility contracts. Exposing reset methods, ReBAR resize controls, ROM files, or PCIe link attributes when unsupported would produce broken user-space behavior, while hiding them incorrectly removes administrative functionality. Legacy I/O and mmap paths are architecture-dependent and may be unavailable.

## Test Signals
Useful signals include sysfs layout checks under `/sys/bus/pci/devices/...` for normal devices, bridges, PCIe devices, VFs, VGA devices, devices with ROMs, and devices with DSN. Config binary tests should verify unprivileged size limiting, CAP_SYS_ADMIN extended access, lockdown denial, and alignment-preserving byte/word/dword transfers. Resource tests should validate `resource`, dynamic `resourceN`, optional `resourceN_wc`, mmap fit rejection, exclusive iomem rejection, and cleanup after device removal.

State-changing tests should cover `enable` reference count behavior, refusal while a driver is bound, device and bus rescans under the rescan/remove lock, `remove` self-removal, reset success and unsupported reset visibility, `reset_method` invalid input rollback, `d3cold_allowed` bridge propagation, MSI policy changes only affecting future drivers, and ReBAR resize failure paths. Boot or late-init tests should confirm existing devices gain dynamic files after `late_initcall(pci_sysfs_init)`.
