# sources/distributed-fs/ceph-client/drivers/md/md-bitmap.c

Purpose: Implements the original MD bitmap submodule (`ID_BITMAP`) plus the `none` bitmap placeholder. It tracks dirty/resync-needed MD regions with in-memory 16-bit counters and persists one bit per chunk either in an internal metadata-adjacent bitmap or in a file-backed bitmap when `CONFIG_MD_BITMAP_FILE` is enabled. The bitmap lets MD avoid full resync after crashes, drive failures, re-adds, and clustered slot handoff.

Important APIs/types/functions: Local `struct bitmap` owns `bitmap_counts`, `bitmap_storage`, event state, flush wait queues, write-behind accounting, sysfs nodes, and clustered slot number. `struct bitmap_page` stores per-counter pages, including a low-memory "hijacked pointer" fallback. Core operations are exposed through `struct bitmap_operations bitmap_ops`: `bitmap_create()`, `bitmap_load()`, `bitmap_destroy()`, `bitmap_resize()`, `bitmap_start_write()`, `bitmap_end_write()`, `bitmap_start_sync()`, `bitmap_end_sync()`, `bitmap_cond_end_sync()`, `bitmap_close_sync()`, `bitmap_dirty_bits()`, `bitmap_unplug()`, `bitmap_daemon_work()`, `bitmap_update_sb()`, `bitmap_get_from_slot()`, and `bitmap_copy_from_slot()`. Module lifecycle is `md_bitmap_init()`/`md_bitmap_exit()`.

Control flow: Creation rejects journaled arrays, opens/caches any bitmap file, reads or creates the bitmap superblock, then calls `__bitmap_resize(..., init=true)` to allocate storage pages and counter pages. Loading creates serial pools, loads clustered slot bitmaps if needed, resets stale sync state, imports on-disk bits through `md_bitmap_init_from_disk()`, clears `BITMAP_STALE`, schedules recovery, and updates the bitmap superblock. For write I/O, `bitmap_start_write()` obtains or allocates the counter for each covered chunk, sets the persistent bit before data is submitted, handles counter overflow by waiting on `overflow_wait`, and increments the 14-bit counter. `bitmap_end_write()` updates `events_cleared` on clean arrays, marks degraded chunks `NEEDED`, decrements the counter, and marks pages pending for daemon cleanup. Resync uses `NEEDED_MASK` and `RESYNC_MASK`: `bitmap_start_sync()` reports chunks needing recovery, `bitmap_end_sync()` either clears active resync or re-marks aborted chunks needed, and `bitmap_close_sync()` sweeps any remaining active bits.

State and persistence: In-memory counters encode `NEEDED`, `RESYNC`, and pending write count in one `u16`. A counter value of 0 means the disk bit is clear, 1 means only the on-disk bit remains, 2 is the daemon-clearing threshold, and higher values include outstanding writes. `bitmap_storage` caches the bitmap superblock page, bitmap data pages, and per-page attributes (`DIRTY`, `PENDING`, `NEEDWRITE`). `bitmap_update_sb()` persists MD event counters, state flags, daemon sleep, write-behind limit, sync size, chunksize, nodes, and reserved sectors. File-backed bitmaps map file blocks via `bmap()` and bypass the filesystem on later writes; internal bitmaps write pages to active rdev metadata areas with overlap checks. `BITMAP_WRITE_ERROR` triggers `md_bitmap_file_kick()`, setting `BITMAP_STALE` and forcing conservative recovery.

Dependencies/integration: Depends on MD core (`mddev`, `md_rdev`, personality quiesce, serial pools, recovery flags, sysfs), block-device metadata I/O (`sync_page_io()`, `md_write_metadata()`, `md_super_wait()`), optional file-backed bitmap support (`buffer_head`, `bmap()`), clustered MD (`md_setup_cluster()`, `md_cluster_stop()`, slot bitmap copy), and the shared declarations in `md-bitmap.h`. The sysfs `bitmap/` group exposes location, space, time_base, backlog, chunksize, metadata, can_clear, and max_backlog_used.

Risks and test signals: Test counter overflow and wakeup behavior, low-memory page hijacking, degraded write paths preserving `NEEDED`, daemon clearing over multiple runs, superblock event mismatch forcing stale recovery, internal bitmap overlap rejection around metadata/data boundaries, file-backed bitmap block mapping failures, clustered slot offset math, resize rollback after cluster preallocation failure, and sysfs add/remove error unwinds. Pay close attention to lock transitions in `md_bitmap_checkpage()` because it deliberately drops `counts.lock` while allocating, and to `bitmap_copy_from_slot()` because it both imports remote dirty bits and optionally clears the donor bitmap.
