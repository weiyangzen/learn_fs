# sources/distributed-fs/ceph-client/drivers/md/md-linear.c

Purpose: Implements the deprecated MD linear personality, which concatenates member devices into one address space without redundancy. It maps incoming bios to the rdev whose cumulative end sector contains the bio sector, splitting bios that cross device boundaries.

Important APIs/types/functions: `struct dev_info` stores an rdev and its cumulative `end_sector`. `struct linear_conf` stores array size, a copy of `raid_disks`, RCU head, and the flexible array of devices. `which_dev()` binary-searches `conf->disks`. `linear_conf()` builds and validates the mapping. `linear_run()` initializes the personality. `linear_add()` hot-adds a new tail device by building a replacement config and swapping it with RCU. `linear_make_request()` remaps bios. `linear_error()` marks the whole array broken. The module registers `linear_personality` under `ID_LINEAR`.

Control flow: `linear_run()` rejects bitmaps with `md_check_no_bitmap()`, builds a configuration from rdev raid slots, sets array sectors, and registers integrity. `linear_conf()` validates every expected disk is present exactly once, optionally rounds member sectors down to `chunk_sectors`, computes cumulative end sectors, and stacks queue limits unless running under dm-raid. For I/O, `linear_make_request()` handles flushes through MD, finds the target rdev, validates bounds and device health, splits crossing bios at `end_sector`, accounts the bio, remaps `bi_bdev` and sector by subtracting the device start and adding `data_offset`, ignores unsupported discards, checks write-zeroes, and submits without accounting. `linear_add()` requires the new rdev's saved raid slot to equal the old disk count, then swaps in a new config and updates capacity.

State and persistence: Runtime mapping state is in `mddev->private` as `struct linear_conf`. Hot-add uses RCU so old mappings survive until readers drain. Persistent array layout is still from MD metadata/rdev raid slots; this file only builds the in-memory concatenation view. There is no bitmap or recovery state because linear arrays have no redundancy.

Dependencies/integration: Uses MD personality registration, MD rdev iteration, queue-limit stacking, MD flush/accounting/error helpers, block trace remap events, bio split/submission, integrity registration, RCU free, and module aliases for the linear level.

Risks and test signals: Test out-of-order or duplicate raid slots, missing devices, zero/odd `chunk_sectors` rounding, queue-limit failures, bio splits exactly at boundaries, out-of-bounds bios after hot-add, unsupported discard completion, broken rdev error handling, RCU lifetime during concurrent hot-add and I/O, and capacity notification after growth. Since failure of one disk marks the whole linear array broken, error-path tests should verify no silent remap to later devices occurs.
