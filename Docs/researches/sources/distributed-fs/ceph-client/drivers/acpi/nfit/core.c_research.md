# sources/distributed-fs/ceph-client/drivers/acpi/nfit/core.c

`core.c` is the main ACPI NFIT driver and libnvdimm bridge. It discovers NFIT data from the ACPI NFIT table or `_FIT`, parses NFIT subtables, assembles per-DIMM `nfit_mem` state, registers libnvdimm DIMMs and regions, dispatches ACPI `_DSM`/label commands, exposes NFIT sysfs attributes, runs ARS poison scans, and handles root/DIMM ACPI notifications.

Important APIs and state include module parameters for DIMM enabling, vendor command policy, DSM mask override, default DSM family, initial ARS, and label forcing; global `acpi_descs`/`acpi_desc_lock` for active NFIT buses; `nfit_wq` for scrub work; `acpi_nfit_ctl()` as the libnvdimm `ndctl` callback; `acpi_nfit_init()` and `acpi_nfit_desc_init()` for descriptor setup; `acpi_nfit_probe()` for `ACPI0012`; `__acpi_nfit_notify()` and `__acpi_nvdimm_notify()` for ACPI events; and `acpi_nfit_shutdown()` for teardown. Table parsing is split across `add_spa()`, `add_memdev()`, `add_dcr()`, `add_bdw()`, `add_idt()`, `add_flush()`, and `add_platform_cap()`. Registration flows through `nfit_mem_init()`, `acpi_nfit_add_dimm()`, `acpi_nfit_register_dimms()`, `acpi_nfit_register_region()`, and `acpi_nfit_register_regions()`. ARS flows through `ars_get_cap()`, `ars_start()`, `ars_get_status()`, `ars_status_process_records()`, `ars_register()`, `acpi_nfit_scrub()`, and `acpi_nfit_ars_rescan()`.

Control flow starts at module init by parsing UUIDs, creating the workqueue, registering MCE handling, and binding the platform driver. Probe installs root notifications, reads NFIT data, creates an `acpi_nfit_desc`, and calls `acpi_nfit_init()`. That routine initializes bus DSM support and the libnvdimm bus once, then under `init_mutex` parses incoming NFIT records, rejects unsupported deletions on updates, assembles DIMM state, registers DIMMs, and registers regions. Runtime update notification evaluates `_FIT` again and merges additions. Command dispatch validates libnvdimm commands, maps `ND_CMD_CALL` to family/function IDs, selects bus or DIMM handles and GUIDs, calls `_DSM` or `_LSI/_LSR/_LSW`, copies firmware output, and translates status.

Persistent runtime state is stored in `struct acpi_nfit_desc` lists and ARS fields, plus per-DIMM `struct nfit_mem` provider data for ACPI child devices, DSM masks, label-method flags, flush hints, dirty shutdown state, security ops, and firmware activation state. Dependencies include ACPICA, ACPI device notifications, libnvdimm, ndctl descriptors, sysfs/kernfs, kernel resources, NUMA PXM translation, workqueues, and Intel-specific ops from `intel.c`.

Key risks are firmware table malformation, `_FIT` deletion rejection, command-mask and deny-mask safety, ARS/userspace/shutdown races, static mapping limits, and label access policy differences between Intel DSMs and `_LS*` methods. Test signals include synthetic NFIT/nfit_test tables, malformed lengths, DSM probing, label read/write, ARS busy/interrupted/overflow handling, MCE-triggered poison paths, sysfs attributes, `_FIT` hot-add, DIMM notifications, firmware activation visibility, namespace cookie compatibility, and teardown race coverage.
