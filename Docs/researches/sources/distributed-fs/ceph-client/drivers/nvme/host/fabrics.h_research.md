# sources/distributed-fs/ceph-client/drivers/nvme/host/fabrics.h

Purpose: Declares the common NVMe over Fabrics host contract shared between the fabrics library, the NVMe core, and individual fabrics transports. It defines queue defaults, reconnect defaults, parsed controller options, target-visible host identities, transport registration operations, inline matching/utility helpers, and the exported common fabrics APIs.

Important APIs, types, and functions: Constants include `NVMF_MIN_QUEUE_SIZE`, `NVMF_MAX_QUEUE_SIZE`, `NVMF_DEF_QUEUE_SIZE`, `NVMF_DEF_RECONNECT_DELAY`, `NVMF_DEF_CTRL_LOSS_TMO`, and `NVMF_DEF_FAIL_FAST_TMO`. `struct nvmf_host` stores a refcounted Host NQN and UUID. The `NVMF_OPT_*` enum defines parser mask bits for transport, NQN, addresses, queue counts, KATO, host identity, duplicate connect, SQ flow control, TCP digests/TOS/TLS/keyring, discovery, DH-CHAP secrets, and secure concatenation. `struct nvmf_ctrl_options` stores all parsed connection policy and security state. `struct nvmf_transport_ops` is the registration ABI for transport modules, including required/allowed option masks and `create_ctrl()`. Inline helpers include `nvmf_ctlr_matches_baseopts()`, `nvmf_ctrl_subsysnqn()`, `nvmf_complete_timed_out_request()`, `nvmf_nr_io_queues()`, and `nvmf_get_virt_boundary()`.

Control flow: This header has no standalone execution, but it shapes fabric connection flow. Userspace options parsed in `fabrics.c` populate `struct nvmf_ctrl_options`, transport modules register a static `struct nvmf_transport_ops`, and `ops->create_ctrl()` receives validated options. Matching helpers allow duplicate-connect detection by comparing subsystem NQN, host NQN, host ID, and controller state. Queue count helpers sum requested default/read/write/poll queue counts while capping each group at online CPUs. Timed-out request completion sets host-aborted status and completes a started, not-yet-completed block request.

State and persistence behavior: The header describes volatile in-kernel state only. Host identities can provide cross-controller continuity while the module is loaded, but persistence across boot must come from userspace-provided hostnqn/hostid options or another layer. `struct nvmf_ctrl_options` owns allocated strings, key references, secret buffers, and a host reference until `nvmf_free_options()` releases them. The registered transport ops are expected to be statically allocated so module references keep their memory valid.

Dependencies and integration points: Includes Linux IPv4/IPv6 address headers and depends on NVMe core types from including translation units. It is consumed by `core.c`, `fabrics.c`, and fabric transports. It also exposes optional security/TLS/auth configuration fields used by NVMe TCP/TLS and NVMe host authentication code, plus blk-mq mapping helpers used during transport tagset setup.

Risks: The option mask enum is a shared ABI between parser, transport allowed/required masks, and user-facing token display; changing bits or forgetting to update masks can silently alter accepted connection syntax. `struct nvmf_ctrl_options` contains sensitive secret pointers, so ownership and cleanup must remain clear. `nvmf_ctlr_matches_baseopts()` intentionally rejects deleting/dead controllers and requires host identity equality; loosening it can create duplicate or unsafe connections. Queue count calculations cap by online CPUs per queue class, so transports must still validate against controller-provided queue counts. `nvmf_get_virt_boundary()` currently returns zero for fabrics, which is part of the DMA mapping contract exposed to queue limits.

Test signals: Build all fabrics transports against this header; validate parser token masks against displayed `/dev/nvme-fabrics` syntax; test duplicate connection matching for state, subsystem NQN, host NQN, host ID, address, and interface combinations; exercise timeout completion on started versus already completed requests; verify queue count totals for default, write, and poll combinations on systems with varying online CPU counts; run auth/TLS builds to catch missing key/secret field handling.
