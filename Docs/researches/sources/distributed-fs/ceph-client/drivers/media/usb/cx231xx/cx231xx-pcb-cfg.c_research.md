# sources/distributed-fs/ceph-client/drivers/media/usb/cx231xx/cx231xx-pcb-cfg.c

Purpose: board PCB scenario resolver for cx231xx devices. It defines known self-powered and bus-powered endpoint/source layouts, reads the hardware board-configuration register, selects the matching scenario, stamps runtime USB speed/source fields, and copies the selected `struct pcb_config` into the device.

Important APIs/types/functions: module parameter `pcb_debug` enables scenario logging. `cx231xx_Scenario[]` is the core static table of `struct pcb_config` entries. Implemented scenarios cover self-powered digital-only, dual-digital, analog-only, dual, triple, compressor, plus bus-powered digital-only, analog-only, and DIF-only layouts. Each scenario supplies high-speed and full-speed `CONFIG_INFO` arrays with endpoint interface indices for interrupt, TS1, TS2, audio, video, VANC, HANC, and IR. `initialize_cx231xx()` is the only function and the external entry point declared in the header.

Control flow: `initialize_cx231xx()` reads four bytes from `BOARD_CFG_STAT` with `cx231xx_read_ctrl_reg(VRT_GET_REGISTER)`, converts them to `config_info`, and extracts USB speed from bit 0. If `BUS_POWER` is set, it masks with `BUSPOWER_MASK` and selects digital-only for `TS1_PORT | BUS_POWER`, analog-only for `AVDEC_ENABLE | BUS_POWER`, or DIF-only for `AVDEC_ENABLE | BUS_POWER | TS1_PORT`; unknown bus-powered combinations log an error and return 1. If self-powered, it masks with `SELFPOWER_MASK` and selects among digital-only, dual-digital, analog-only, dual, triple, and compressor scenarios based on TS and AV decoder bits. Selected scenarios have `speed`, TS source, and analog source fields patched from local defaults, then are copied to `dev->current_pcb_config`; `dev->current_scenario_idx` records the table index.

State and persistence: persistent runtime state is `dev->current_scenario_idx` and `dev->current_pcb_config`, which later core code uses to choose USB interface numbers for alternate settings and streaming. The source table itself is static global data and is mutated when `initialize_cx231xx()` writes scenario `speed` and source fields before copying, so those values persist in the module across devices. Hardware state is only read from `BOARD_CFG_STAT`.

Dependencies and integration: depends on `cx231xx.h`, `cx231xx-conf-reg.h`, the PCB types/macros from `cx231xx-pcb-cfg.h`, and `cx231xx_read_ctrl_reg()` from core. The selected config is consumed by `cx231xx_set_video_alternate()`, `cx231xx_set_alt_setting()`, and setup paths that need endpoint/interface layout. It also informs analog/DVB feature availability through `mode`, `ts*_source`, and `analog_source`.

Risks: `p_pcb_info` is not initialized before the switch; current branches return on unknown scenarios, but future edits must preserve that guarantee. The static scenario table is modified per device, so two devices initialized concurrently or sequentially with different speeds/source defaults can race or leave shared table state changed; copying from a local const table would be safer. Header enum values define more bus-powered scenario names than the C table implements, which can mislead callers into expecting external/combined bus-powered layouts. Unknown bus-powered configs return positive `1` instead of a negative errno, unlike self-powered unknown configs returning `-ENODEV`. Interface indices use `NOT_SUPPORTED` (`0xff`) sentinels that later code often adds 1 to after selecting a field; callers must avoid using unsupported endpoints. Some default `analog_source` local value is `0`, so selected analog scenarios may not explicitly carry `SOURCE_ANALOG`/`SOURCE_DIF` unless already encoded in the table.

Test signals: mock or run hardware with `BOARD_CFG_STAT` values for every implemented scenario and verify selected `current_scenario_idx`, speed, mode, sources, and high/full-speed interface indices; enable `pcb_debug` and compare logs; test unsupported bus/self-powered bit combinations and expected errno behavior; probe two cx231xx devices with different speed/scenario combinations under KCSAN to catch static table races; validate subsequent `usb_set_interface()` calls never use `NOT_SUPPORTED + 1`; compare endpoint layouts against USB descriptors on high-speed and full-speed operation.
