# sources/distributed-fs/ceph-client/drivers/media/usb/cx231xx/cx231xx-dvb.c

Purpose: DVB extension module for cx231xx USB capture devices. It attaches board-specific demodulator/tuner frontends over cx231xx I2C adapters, registers Linux DVB adapter/demux/network/media-controller objects, starts TS1 USB streaming when demux feeds are active, and tears everything down through the cx231xx extension framework.

Important APIs/types/functions: `struct cx231xx_dvb` stores up to two frontends, feed-count lock/state, `dvb_adapter`, `dvb_demux`, `dmxdev`, hardware/memory demux frontends, `dvb_net`, and I2C module clients for demods/tuners. Static config blocks describe S5H1432, S5H1411, LGDT3305/LGDT3306A, TDA18271, MB86A20S, R820T, Si2165/Si2168/Si2157, and MN88473 attachment parameters. URB copy callbacks are `dvb_isoc_copy()` and `dvb_bulk_copy()`. Stream lifecycle is `start_streaming()`, `stop_streaming()`, `start_feed()`, and `stop_feed()`. Registration lifecycle is `dvb_init()`, `register_dvb()`, `unregister_dvb()`, `dvb_fini()`, and module init/exit functions registering `dvb_ops`.

Control flow: module init registers a `cx231xx_ops` extension. For every DVB-capable device, `dvb_init()` allocates state, installs analog tuner helper callbacks, resolves tuner/demod I2C adapters from board data, locks the device, switches to digital mode, resets the demod, then dispatches on `dev->model`. Each model branch attaches or probes a demod, optionally sets `frontend[0]->callback`, attaches or probes a tuner, and stores I2C clients for module-managed devices. Dual-frontend Hauppauge 975 setup attaches LGDT3306A and Si2168 demods, registers MFE sharing, attaches one Si2157 tuner, then copies tuner private state and ops to the second frontend. `register_dvb()` registers the adapter, media-controller hooks, frontends, software demux, dmxdev, hardware/memory demux frontends, network device, and media graph. On failure it unwinds in reverse order.

Streaming flow: a demux feed start increments `nfeeds` under `dvb->lock`; the first feed starts TS1 streaming. ISO mode selects TS1 alt setting 5, enters digital mode, marks `mode_tv`, and calls `cx231xx_init_isoc()` with `dvb_isoc_copy()`. Bulk mode selects alt 0, enters digital mode, marks `mode_tv`, and calls `cx231xx_init_bulk()` with `dvb_bulk_copy()`. Copy callbacks ignore disconnected devices, log URB or packet errors, and pass payload bytes to `dvb_dmx_swfilter()`. Feed stop decrements `nfeeds`; the last feed tears down ISO/bulk URBs and suspends the device.

State and persistence: persistent runtime state is in `dev->dvb`, frontend objects and their tuner private data, I2C clients loaded through `dvb_module_probe()`, DVB demux filter tables, feed count, adapter media graph state, and cx231xx mode/TS endpoint state. Analog helper callbacks `dev->cx231xx_set_analog_freq` and `dev->cx231xx_reset_analog_tuner` point into this file when a shared tuner can be used for analog. There is no durable persistence outside kernel/device state.

Dependencies and integration: depends on Linux DVB core (`dvbdev`, `dmxdev`, `dvb_demux`, `dvb_frontend`, `dvb_net`), V4L2 tuner support, many demod/tuner modules, cx231xx core exports for I2C adapters, mode switching, demod reset, alternate settings, and URB setup/teardown, plus board definitions for model IDs, I2C masters, addresses, and DVB capability. It integrates with media-controller support through `dvb_register_media_controller()` and `dvb_create_media_graph()`.

Risks: `start_feed()` increments `nfeeds` before `start_streaming()` and does not decrement it if streaming fails, so a failed first feed can leave feed count inconsistent and prevent later starts/stops from balancing. `stop_feed()` blindly decrements `nfeeds`, so duplicate or out-of-order stop calls could underflow and skip teardown. Many tuner attach calls are not checked after frontend attach, meaning a DVB adapter can register with a demod but missing tuner on some boards. In the Hauppauge 975 path, copying tuner ops/private data to the second frontend creates shared tuner lifetime assumptions that must match DVB core expectations. Failure paths in `dvb_init()` free `dvb` but do not detach all frontends created through `dvb_attach()` unless they were module clients, so branch-specific attach failures need leak checks. `cx231xx_dvb_bus_ctrl()` can suspend the whole device on frontend bus release while other analog/DVB users may need mode coordination.

Test signals: build with every referenced frontend/tuner as built-in and module; probe each supported board model and verify the expected demod/tuner appears in logs; run `dvbv5-scan`, tune, and capture TS packets over ISO and bulk modes; start multiple demux filters and ensure only the first starts URBs and the last stops them; force frontend/tuner attach failures to verify unwind; test dual-frontend Hauppauge 975 simultaneous and serialized use; disconnect during active DVB capture; run media graph validation when media-controller DVB is enabled; exercise analog frequency/reset helpers on shared XC5000/TDA18271 boards.
