# sources/distributed-fs/ceph-client/drivers/media/i2c/imx219.c

Purpose: V4L2 sub-device driver for the Sony IMX219 CSI-2 Bayer image sensor. It exposes one source pad, 8-bit and 10-bit Bayer media bus formats, four fixed output sizes, runtime power management, sensor controls, and DT/fwnode validation for 2-lane or 4-lane MIPI CSI-2 operation.

Important APIs/types/functions: `struct imx219` owns the `v4l2_subdev`, media pad, CCI regmap, clock, optional reset GPIO, regulators, controls, and lane count. `struct imx219_mode` defines supported width, height, and default frame length. Register programming is done through `devm_cci_regmap_init_i2c()`, `cci_write()`, and `cci_multi_reg_write()`. Format and crop handling is centered on `imx219_set_pad_format()`, `imx219_set_framefmt()`, `imx219_get_binning()`, and `imx219_get_format_code()`. Streaming is implemented with modern pad stream callbacks `imx219_enable_streams()` and `imx219_disable_streams()`, with `v4l2_subdev_s_stream_helper()` for legacy `.s_stream`. Probe and PM are handled by `imx219_probe()`, `imx219_remove()`, `imx219_power_on()`, `imx219_power_off()`, `imx219_check_hwcfg()`, and `imx219_identify_module()`.

Control flow: probe allocates state, initializes the subdev, parses the endpoint, validates 2 or 4 CSI-2 lanes and link frequencies, creates the CCI regmap, validates the 24 MHz xclk, acquires regulators and optional reset GPIO, powers the sensor, reads the chip ID, forces a streaming-to-standby transition to enter LP-11, initializes controls, finalizes the subdev state, enables runtime PM with autosuspend, and registers the sensor. Setting a format selects the nearest fixed mode, derives centered crop and analog binning, updates vblank/hblank/exposure/pixel-rate control ranges, and stores the active state. Stream start resumes runtime PM, writes common register tables, writes lane-specific PLL and CSI lane registers, applies crop/format registers, synchronizes controls, writes `MODE_SELECT = STREAMING`, and grabs flip controls. Stream stop writes standby, releases flip controls, and schedules autosuspend.

State and persistence behavior: persistent state is kernel object state only: active subdev format/crop, control values, lane count, and PM status. The hardware state is rewritten on each stream start from common tables, lane tables, active format/crop, and controls. No on-disk persistence exists. VBLANK updates exposure range even while the device is off; actual register writes are skipped unless `pm_runtime_get_if_in_use()` succeeds. H/V flip values affect both Bayer code reporting and orientation register programming and are locked during streaming.

Dependencies and integration points: integrates with the Linux media controller, V4L2 subdev active-state API, CCI helpers, fwnode endpoint parsing, regulator framework, clock framework, GPIO descriptors, runtime PM, and async sensor registration. It depends on DT compatible `sony,imx219`, endpoint `link-frequencies`, 2 or 4 MIPI data lanes, and exactly 24 MHz input clock. Test-pattern color component controls assume contiguous V4L2 test-pattern color control IDs.

Risks: lane/link-frequency validation has legacy compatibility behavior for an unsupported 4-lane frequency, so platform descriptions can appear valid while being silently remapped. Reset GPIO polarity is documented as historically misinterpreted and should not be copied. Pixel-rate scaling depends on binning-derived `rate_factor`; errors here affect exposure and frame timing. Mode changes preserve previous line length when possible, which can surprise tests that expect mode defaults. Flip changes alter Bayer order and are grabbed only once streaming has started.

Test signals: useful checks include probe success with valid and invalid endpoint lane/link-frequency combinations, chip-ID mismatch handling, runtime PM suspend/resume around stream start/stop, `v4l2-ctl --list-subdev-mbus-codes`, frame-size enumeration for the four modes, set-format control range updates, exposure/vblank/hblank register writes while streaming, flip Bayer-order changes, and test-pattern/color component controls. Kernel build coverage should include media/i2c with CCI helpers enabled and DT binding validation for `sony,imx219`.
