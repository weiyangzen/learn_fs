# sources/distributed-fs/ceph-client/drivers/media/i2c/imx274.c

Purpose: V4L2 sub-device driver for the Sony IMX274 CMOS sensor. It supports four 10-bit raw CSI-2 readout modes derived from crop/compose selection, frame interval control, exposure/gain/vflip/test-pattern controls, runtime PM, and a 4-lane CSI-2 endpoint.

Important APIs/types/functions: `struct stimx274` owns the V4L2 subdev, pad, I2C client, control bundle, active crop/format/frame interval, regmap, reset GPIO, regulators, input clock, mutex, and selected `struct imx274_mode`. Register access uses `devm_regmap_init_i2c()`, `imx274_write_table()`, `imx274_write_reg()`, `imx274_read_mbreg()`, and `imx274_write_mbreg()`; table writes coalesce consecutive registers and honor wait sentinels. Mode and selection logic lives in `__imx274_change_compose()`, `imx274_set_fmt()`, `imx274_set_selection_crop()`, `imx274_apply_trimming()`, and `imx274_mode_regs()`. Streaming is `imx274_s_stream()` plus `imx274_start_stream()`. Timing and control math is in `imx274_set_frame_interval()`, `__imx274_set_frame_interval()`, `imx274_get_frame_length()`, `imx274_set_exposure()`, `imx274_set_gain()`, `imx274_set_digital_gain()`, and `imx274_set_test_pattern()`.

Control flow: probe validates that the endpoint is CSI-2 with exactly 4 data lanes, obtains optional `inck`, regulators and reset GPIO, initializes default crop/format/frame interval, creates a regmap, powers the sensor, initializes four controls, loads default control values, registers the subdev, and enables runtime PM. Format and compose requests choose the best binning mode by scoring requested output size against crop size and selection flags. Crop requests clamp and align the rectangle, update active or try crop, and reset compose when size changes. Stream start resumes PM, writes start-step-1 and selected mode registers, applies trimming/crop registers, recalculates frame interval and exposure, applies controls, performs the datasheet standby-cancel delay sequence, and writes final streaming registers. Stream stop writes the standby table and releases PM.

State and persistence behavior: active crop, format, selected mode, frame interval, and controls are stored in `struct stimx274`; try state is partially supported for format/crop but frame interval explicitly rejects try formats. Hardware state is rebuilt at stream start and not persisted across power-off. Exposure values are expressed in microseconds at the V4L2 control but converted to coarse lines/SHR based on current HMAX and frame length. Gain control stores a fixed-point value, splits it into digital gain steps and analog register value, then writes back the quantized actual gain to `ctrl->val`.

Dependencies and integration points: depends on V4L2 controls/subdev/media entity, fwnode endpoint parsing, regmap with 16-bit register/8-bit value configuration, runtime PM, regulators `vddl`, `vdig`, `vana`, optional reset GPIO, and optional `inck`. The driver registers OF compatible `sony,imx274` and I2C ID `IMX274`. It exposes crop/compose semantics rather than only fixed frame sizes, which makes it sensitive to media-graph users that expect selection API behavior.

Risks: reset polarity is documented as historically misinterpreted and should not be reused. Frame interval math uses integer division ordering that can lose precision and only supports active state. `imx274_get_fmt()` always returns active `imx274->format`, ignoring TRY state, which may surprise userspace. Streaming failure paths call `pm_runtime_put()` even when failure happens after resume, but stop failure also goes through the shared fail path; state should be audited when changing this code. Numerous mode and start tables contain undocumented sensor registers, increasing regression risk for cleanup refactors. The driver lacks chip-ID verification.

Test signals: validate endpoint rejection for non-4-lane configurations, power sequencing with optional reset GPIO, crop alignment/clamping, compose mode selection across 3840x2160, 1920x1080, 1280x720, and 1280x540 derived outputs, frame interval clamping between 5 fps and per-mode max fps, exposure range updates after frame interval changes, fixed-point gain quantization, vflip crop sign handling, and all test-pattern menu values. Streaming tests should check the three-step standby-cancel sequence and trimming register writes.
