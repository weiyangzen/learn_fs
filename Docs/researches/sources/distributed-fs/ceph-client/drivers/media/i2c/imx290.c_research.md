# sources/distributed-fs/ceph-client/drivers/media/i2c/imx290.c

Purpose: V4L2 sub-device driver for Sony IMX290-family CSI-2 sensors, covering color and monochrome IMX290, IMX327, and IMX462 variants. It exposes 1080p and 720p modes, 10-bit and 12-bit formats, 2-lane or 4-lane CSI-2 operation, runtime PM, test patterns, blanking, exposure, analogue gain, and flip controls.

Important APIs/types/functions: `struct imx290` stores device resources, CCI regmap, xclk selection, lane count, model info, subdev, current mode, regulators, reset GPIO, and controls. `struct imx290_model_info` carries variant color/mono type, model-specific init table, max analogue gain, and name. `struct imx290_mode`, `struct imx290_csi_cfg`, `struct imx290_clk_cfg`, and `struct imx290_format_info` describe mode dimensions, link timing, clock setup, and format-specific registers. Key functions include `imx290_parse_dt()`, `imx290_check_link_freqs()`, `imx290_init_clk()`, `imx290_ctrl_init()`, `imx290_ctrl_update()`, `imx290_set_ctrl()`, `imx290_start_streaming()`, `imx290_stop_streaming()`, `imx290_set_fmt()`, and `imx290_subdev_init()`.

Control flow: probe creates the CCI regmap, parses OF match data and endpoint, validates 2 or 4 data lanes and that all driver-required link frequencies are present, acquires regulators/reset/xclk, validates 37.125 MHz or 74.25 MHz input clock, powers on, enables runtime PM, forces standby/not-streaming, initializes the V4L2 subdev and controls, sets the subdev name from the model, and registers it. Setting format chooses the nearest lane-specific mode, validates or defaults the media bus code according to color/mono variant, updates active current mode and blanking/link controls, and stores active state. Stream start writes global and model-specific init tables, clock registers, lane registers, CSI timing, bit-depth format registers, black level, mode registers, controls, leaves standby, waits 30 ms, and clears `XMSTA`. Stop writes standby, waits, and sets `XMSTA`.

State and persistence behavior: active state stores format; `current_mode` and controls remain in driver memory. Hardware state is rebuilt for every stream start. VBLANK updates the exposure range before any runtime PM check, and when VMAX changes during streaming the driver immediately reprograms exposure because SHS1 is relative to VMAX. H/V flip controls are clustered, program `CTRL_07` with the current mode window bits, and are grabbed during streaming to avoid invalid frames. Test pattern mode temporarily changes black level and restores it when disabled.

Dependencies and integration points: depends on OF match data for model selection, fwnode endpoint parsing, media entity validation, CCI helpers, V4L2 subdev active-state helpers, runtime PM, regulators `vdda`, `vddd`, `vdddo`, reset GPIO, and legacy sensor clock lookup. Supported compatibles include deprecated `sony,imx290`, plus `sony,imx290lqr`, `sony,imx290llr`, `sony,imx327lqr`, `sony,imx462lqr`, and `sony,imx462llr`.

Risks: the driver requires the DT endpoint to list all link frequencies for the selected lane count, not just the active one, which can break partial platform descriptions. There is no chip-ID read; model identity comes from DT match data. CCI timing tables and model-specific undocumented registers are sensor-sensitive. Pixel rate is fixed at 148.5 MHz even though link frequency changes by mode/lane. Stop-streaming result is ignored by `imx290_set_stream()` on disable. Flip-dependent crop shifts by one pixel to preserve Bayer order, so crop tests must account for current flip state.

Test signals: validate every compatible, color versus mono media bus code enumeration, 2-lane and 4-lane link-frequency requirements, both supported xclk rates, 10-bit/12-bit format register programming, mode switching between 1920x1080 and 1280x720, hblank/vblank/exposure interactions, black-level behavior around test-pattern enable/disable, clustered hflip/vflip grab behavior during streaming, and runtime PM autosuspend across repeated stream cycles.
