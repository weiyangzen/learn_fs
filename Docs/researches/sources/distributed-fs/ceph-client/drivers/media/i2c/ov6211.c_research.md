# sources/distributed-fs/ceph-client/drivers/media/i2c/ov6211.c

Purpose: implements an OmniVision OV6211 monochrome/global-shutter-style sensor driver using V4L2 subdev streams APIs and CCI regmap access. It supports a single 400x400 mode at 120 fps, 8-bit greyscale `MEDIA_BUS_FMT_Y8_1X8`, a 24 MHz master clock, one 480 MHz link-frequency entry, reset GPIO, three supplies (`avdd`, `dovdd`, `dvdd`), and one source media pad.

Important APIs, types, and functions: `struct ov6211` holds the device, CCI regmap, clock, reset GPIO, supplies, subdev, pad, controls, and saved `pre_isp` register value. The only mode is described by `struct ov6211_mode` and `ov6211_400x400_120fps_mode`. Controls are built by `ov6211_init_controls()` and applied by `ov6211_set_ctrl()`, with `ov6211_set_test_pattern()` preserving non-test-pattern bits from the saved pre-ISP register. Streaming uses the modern pad stream callbacks `ov6211_enable_streams()` and `ov6211_disable_streams()`, with `.s_stream = v4l2_subdev_s_stream_helper`. Firmware and power setup are handled by `ov6211_check_hwcfg()`, `ov6211_power_on()`, `ov6211_power_off()`, `ov6211_identify_sensor()`, and `ov6211_probe()`.

Control flow: probe initializes the subdev and CCI regmap, obtains and validates XVCLK when a nonzero rate is reported, checks endpoint link frequencies via `v4l2_link_freq_to_bitmap()`, obtains reset GPIO and regulators, powers the sensor to read chip ID and the current pre-ISP register, initializes controls, assigns the subdev state lock to the control handler lock, sets internal state ops, initializes pads, finalizes subdev active state, enables runtime PM, registers asynchronously, then enables autosuspend and idles the device. Stream enable resumes PM, writes software reset, writes the single mode's CCI register sequence, replays controls, and writes mode-select streaming. Stream disable writes standby and schedules autosuspend.

State and persistence behavior: V4L2 subdev state stores the current pad format, but because there is only one mode, format setting always resolves to 400x400 Y8. Controls cache vblank, exposure, analogue gain, and test-pattern values; they are skipped while runtime PM is inactive and replayed on stream enable. `pre_isp` is captured once during probe and used as the base value for test-pattern toggling, preserving unrelated bits across control changes. Register state is not expected to survive suspend; stream enable rewrites the full mode table and controls.

Dependencies and integration points: depends on CCI regmap, I2C, V4L2 stream-aware subdev helpers, media entity link validation, fwnode endpoint parsing, `v4l2_link_freq_to_bitmap()`, runtime PM with autosuspend, clocks, GPIOs, regulators, and OF matching for `ovti,ov6211`. The mode uses raw colorspace metadata even though the bus code is greyscale Y8, which matters to receiver and userspace interpretation.

Risks: pixel-rate calculation is `link_freq / bpp` and does not multiply by two edges or lane count, so metadata should be checked against the sensor/receiver timing model. `ov6211_set_ctrl()` uses `pm_runtime_get_if_active()` and then `pm_runtime_put()`; this is intentional for active-only writes but should be checked under concurrent stream transitions. The control handler lock is not explicitly initialized before being assigned to `sd.state_lock`; if the V4L2 core leaves it NULL, state locking assumptions differ from drivers with an explicit mutex. Only link frequency is validated in `ov6211_check_hwcfg()`; lane count is not explicitly checked in this file. `pre_isp` is sampled only at probe, so any later firmware or mode-table change to that register outside the test-pattern bit can be overwritten by test-pattern toggles.

Test signals: validate endpoint link-frequency rejection, optional zero-rate clock behavior, chip ID mismatch, saved `pre_isp` preservation, stream enable/disable through both pad stream callbacks and legacy s_stream helper, runtime autosuspend/resume, exposure/vblank range coupling, analogue gain writes, test pattern on/off, `v4l2-compliance` for subdev state and stream APIs, and captured 400x400 Y8 frames at expected timing.
