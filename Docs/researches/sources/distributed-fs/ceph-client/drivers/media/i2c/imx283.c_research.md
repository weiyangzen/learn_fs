# sources/distributed-fs/ceph-client/drivers/media/i2c/imx283.c

Purpose: V4L2 sub-device driver for the Sony IMX283 Type 1 image sensor. It supports 12-bit full and binned modes plus one 10-bit full mode, 4-lane CSI-2, selectable link frequencies, multiple input clocks, runtime PM with autosuspend, exposure/gain/blanking/vflip/test-pattern controls, and active-state based pad operations.

Important APIs/types/functions: `struct imx283` keeps device, CCI regmap, selected input-frequency table, subdev, pad, clock, reset GPIO, supplies, controls, MIPI clock mode, link-frequency bitmap, and current HMAX/VMAX timing state. `struct imx283_mode` describes readout mode, bpp, dimensions, HMAX/VMAX limits/defaults, crop and vertical crop constants. `get_mode_table()` selects 10-bit or 12-bit mode arrays from the media bus code. Timing helpers `imx283_pixel_rate()`, `imx283_internal_clock()`, `imx283_iclk_to_pix()`, `imx283_exposure()`, `imx283_exposure_limits()`, and `imx283_shr()` translate V4L2 controls into 72 MHz internal timing units. Streaming is handled by `imx283_enable_streams()`, `imx283_disable_streams()`, `imx283_standby_cancel()`, and `imx283_start_streaming()`.

Control flow: probe initializes the subdev and CCI regmap, gets xclk, maps the clock to one of the supported 6/12/18/24 MHz PLL tables, obtains regulators, parses the endpoint, enforces 4 data lanes, derives noncontinuous-clock and link-frequency bitmap, gets optional reset GPIO, powers on, validates chip ID, enables runtime PM with autosuspend, initializes controls, finalizes active state, registers the sensor, and drops the PM usage count. Setting format chooses a mode from the table associated with the requested code, writes normalized raw format fields to active/try state, and updates framing limits on active formats. Stream start cancels standby, configures input PLL, MIPI clock mode, selected link-speed register table, readout mode registers with vertical-crop bits, SVR, crop/output/optical-black registers, embedded data disable, controls, master-start, and sync drive. Stream stop writes master stop and standby.

State and persistence behavior: the active subdev state stores code, size, and crop; `hmax` and `vmax` in `struct imx283` mirror current timing for exposure calculations. Hardware is programmed on stream start from active state and controls. VBLANK control updates `vmax` and exposure range even when hardware is inactive, while register writes are skipped unless runtime PM is active. The link-frequency control is read-only and initialized from the first set bit in the endpoint bitmap.

Dependencies and integration points: depends on media/V4L2 subdev active state, CCI helpers, fwnode endpoint parsing, runtime PM, regulators `vadd`, `vdd1`, `vdd2`, optional reset GPIO, and sensor clock helpers. It requires OF compatible `sony,imx283`, 4 CSI-2 data lanes, supported link frequency 720 or 360 MHz, and one of the supported input clock rates. It exposes both `MEDIA_BUS_FMT_SRGGB12_1X12` and `MEDIA_BUS_FMT_SRGGB10_1X10`.

Risks: `get_mode_table()` can return no modes for unsupported codes; callers rely on format enumeration or valid input to avoid empty nearest-size lookups. Only 4-lane operation is implemented. Global shutter and SVR are explicitly unsupported but timing formulas include placeholders; future support must revisit exposure limits. HMAX/VMAX conversions intentionally pre-divide to avoid overflow, so changing pixel-rate ranges can affect precision. Vertical crop calculations depend on per-mode constants and vflip sign handling. A TODO notes crop containment validation for native area.

Test signals: check probe with each supported xclk table and link-frequency endpoint, reject non-4-lane endpoints, validate chip-ID failure, enumerate 12-bit and 10-bit frame sizes, switch between 5472x3648, 2736x1824, 1824x1216, and 10-bit full mode, confirm hblank/vblank/exposure range changes, stream with continuous and noncontinuous MIPI clock flags, verify vflip changes `HTRIMMING` and vertical crop positioning, and exercise all test-pattern menu entries. Runtime PM autosuspend and resume around repeated stream cycles are important.
