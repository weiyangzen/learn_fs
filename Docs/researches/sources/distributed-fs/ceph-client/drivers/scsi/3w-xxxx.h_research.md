# sources/distributed-fs/ceph-client/drivers/scsi/3w-xxxx.h

Purpose: defines the hardware ABI, protocol constants, lookup tables, command packet layouts, queue state, and per-adapter runtime structure for the legacy 3ware `3w-xxxx` SCSI storage-controller driver. It is a header-only contract consumed by the corresponding implementation file for PCI register access, firmware command formatting, asynchronous event reporting, ioctl payloads, and SCSI command bookkeeping.

Important APIs/types/functions: there are no functions, but the file exposes core driver data contracts. `tw_aen_string[]` maps firmware AEN codes to operator-facing messages. `tw_sense_table[][4]` maps ATA/3ware error bytes to SCSI sense key/ASC/ASCQ tuples. Register bit definitions cover control, status, response queue, PCI cleanup, command opcodes, and AEN codes. Register access macros such as `TW_CONTROL_REG_ADDR`, `TW_CLEAR_ALL_INTERRUPTS`, `TW_ENABLE_AND_CLEAR_INTERRUPTS`, `TW_SOFT_RESET`, and `TW_STATUS_ERRORS` are the implementation's low-level hardware operations. Packed structures include `TW_SG_Entry`, `TW_Command`, `TW_Ioctl`, `TW_New_Ioctl`, `TW_Param`, `TW_Response_Queue`, `TW_Passthru`, and the central `TW_Device_Extension`.

Control flow: the header does not execute by itself, but it dictates the driver's runtime flow. Commands are built in `TW_Command` or `TW_Passthru`, assigned request IDs from the extension queues, DMA addresses are written into SGL entries, and the command queue register is poked. Completion paths read `TW_Response_Queue` values and decode response IDs through `TW_RESPONSE_ID_MASK`/`TW_RESID_OUT`. Reset and interrupt paths use the control/status macros to mask/unmask interrupts, clear host/attention/error bits, and issue soft resets. Ioctl paths use `TW_Ioctl` and `TW_New_Ioctl` to wrap firmware parameter commands and user data buffers.

State and persistence: persistent state lives in hardware/firmware and on attached disks; this header only declares in-memory runtime state. `TW_Device_Extension` tracks MMIO/PIO base address, DMA command/alignment pools, unit presence, free and pending queues, per-slot `struct scsi_cmnd *`, slot states, posted/pending counters, SGL limits, reset and sector counters, AEN circular queue, ioctl lock/wait state, and adapter flags. Queue heads/tails are `unsigned char`, intentionally matching `TW_Q_LENGTH` 256 wraparound. Static lookup tables have internal linkage in each including translation unit.

Dependencies and integration: depends on Linux integer types and on kernel SCSI/PCI types used in `TW_Device_Extension`. It integrates with the SCSI midlayer through `struct Scsi_Host` and `struct scsi_cmnd`, with PCI through `struct pci_dev`, with wait queues/mutexes for ioctl serialization, and with architecture I/O through `outl()` used by macros. Constants such as `TW_MAX_SGL_LENGTH`, `TW_MAX_SECTORS`, `TW_MAX_CMDS_PER_LUN`, and `TW_MAX_IOCTL_SECTORS` are integration limits visible to queueing and ioctl behavior.

Risks: packed hardware structures and bit-masking macros are firmware ABI sensitive; field reordering or size changes can break I/O. The AEN and sense tables are `static` in a header and not `const`, so every includer gets mutable copies. Several hardware addresses and DMA fields are 32-bit, which reflects the controller generation but is a portability boundary. Queue counters rely on wraparound and fixed 256-entry arrays. Error mapping coverage is finite; unknown firmware codes need defensive fallback in the implementation.

Test signals: build coverage for the 3ware driver, probe/reset on supported PCI IDs, command completion under load, ioctl firmware commands, AEN queue decode, induced drive errors mapping to SCSI sense, interrupt masking/unmasking around reset, and SGL boundary tests near `TW_MAX_SGL_LENGTH`, `TW_ATA_PASS_SGL_MAX`, `TW_MAX_SECTORS`, and ioctl sector limits.
