# sources/distributed-fs/ceph-client/drivers/scsi/aacraid/linit.c

Purpose: is the Linux SCSI/PCI entry module for the aacraid driver. It declares PCI IDs and adapter identity/quirk tables, registers the PCI driver and legacy `/dev/aac` char device, defines the SCSI host template, implements queueing and device configuration policy, exposes sysfs attributes, handles SCSI error recovery, probe/remove/shutdown, power management, and PCI error recovery.

Important APIs/types/functions: `aac_pci_tbl[]`, `aac_drivers[]`, `aac_queuecommand()`, `aac_get_driver_ident()`, `aac_biosparm()`, `aac_sdev_configure()`, `aac_change_queue_depth()`, `aac_ioctl()`, `aac_eh_abort()`, `aac_eh_dev_reset()`, `aac_eh_target_reset()`, `aac_eh_bus_reset()`, `aac_eh_host_reset()`, `aac_probe_one()`, `aac_acquire_resources()`, `aac_suspend()`, `aac_resume()`, `aac_remove_one()`, PCI AER callbacks, and module `aac_init()`/`aac_exit()`. It wires `struct scsi_host_template aac_driver_template` to the SCSI midlayer and selects miniport init functions such as `aac_rx_init`, `aac_rkt_init`, `aac_nark_init`, `aac_sa_init`, `aac_src_init`, and `aac_srcv_init`.

Control flow: module init registers the PCI driver, then registers the char device. Probe disables low-power PCIe link states, enables the PCI device, sets DMA masks according to quirks, allocates a `Scsi_Host` plus `struct aac_dev`, allocates FIB metadata, initializes locks/work, maps and initializes the adapter through the selected miniport, starts `aac_command_thread`, queries adapter information and containers, sets SCSI host limits, adds the host, scans devices, and saves PCI state. Runtime queueing marks command ownership and delegates CDB building/transport to `aac_scsi_cmd()`. Remove/shutdown block or remove SCSI devices, stop the AIF thread, send shutdown, disable interrupts, free IRQ/DMA/queue/FSA resources, unmap registers, delete the device list entry, and unregister the char device after the last adapter.

State and persistence: module-global state includes `aac_devices`, `aac_mutex`, `aac_cfg_major`, and the adapter identity tables. Per-host state includes `aac_dev` fields initialized during probe: PCI handle, card type, FIB array, queue and FSA state from miniport init, adapter info, quirk-derived limits, work items, command thread pointer, and flags for reset/shutdown/PCI error. Sysfs exposes adapter metadata derived from firmware and table entries. No durable disk metadata is written here; persistence is hardware and firmware-owned.

Dependencies and integration: depends on PCI core, SCSI host/device midlayer, block queue timeout/depth APIs, Linux PM and PCI AER, character device ioctls, capability checks, and numerous common aacraid helpers from `commsup.c`, `dpcsup.c`, and SCSI command-building files not in this work item. Adapter tables couple specific PCI IDs to miniport init functions and quirks such as 31-bit coherent DMA, 17/34 SG limits, SRC, master/slave, and SCSI-32 behavior.

Risks and test signals: the PCI ID driver-data index must stay aligned with `aac_drivers[]`; a mismatch selects the wrong miniport and quirks. Probe error unwinding spans char-device registration, SCSI host allocation, DMA memory, IRQs, kthreads, and register mappings. SCSI EH has separate native-HBA TMF paths and legacy FIB timeout marking, with several 15-second polling windows. Queue-depth policy depends on container counts, physical/JBOD exposure, SAFW `hba_map`, and target type. PCI AER recovery tears down interrupts and MMIO, then remaps and reacquires resources. Test signals include every miniport family probe, 31-bit and 32-bit DMA mask failures, SG quirk limits, char-device ioctl permission and hot-remove behavior, sysfs reset, suspend/resume, AER frozen/permanent paths, native abort/LUN reset/target reset, legacy abort of inquiry/read-capacity/TUR, host reset capability flags, and scan behavior for exposed physicals, JBOD, containers, and SAFW firmware.
