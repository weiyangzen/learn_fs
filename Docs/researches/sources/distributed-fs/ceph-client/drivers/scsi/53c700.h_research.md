# sources/distributed-fs/ceph-client/drivers/scsi/53c700.h

Purpose: declares the public interface and low-level hardware contract for the 53c700 core driver. It defines command slot geometry, scatter/gather script fragments, per-device and per-host state structures, SCSI/SPI negotiation flags, DMA script memory layout, endian-aware register accessors, chip register offsets, and script patching macros used by `53c700.c` and board wrapper drivers.

Important APIs/types/functions: external entry points are `NCR_700_detect()`, `NCR_700_release()`, and `NCR_700_intr()`. Major types include `enum NCR_700_Host_State`, `struct NCR_700_SG_List`, `struct NCR_700_Device_Parameters`, `enum NCR_700_tag_neg_state`, `struct NCR_700_command_slot`, and `struct NCR_700_Host_Parameters`. Inline helpers manage the per-device sense command and depth, SPI flag bits, tag negotiation state, and register access: `NCR_700_readb()`, `NCR_700_readl()`, `NCR_700_writeb()`, and `NCR_700_writel()`. Script patch macros `script_patch_32`, `script_patch_32_abs`, `script_patch_ID`, and `script_patch_16` mutate generated script instruction words and synchronize them for DMA.

Control flow: board code fills the top portion of `NCR_700_Host_Parameters` with clock, MMIO base, device pointer, optional 710 bus settings, differential flag, and endian wiring. `NCR_700_detect()` then fills everything below the "nothing below here needs altering" boundary. Queueing code uses `NCR_700_command_slot` state transitions from FREE to BUSY or QUEUED, with `host_scribble` pointing back to the slot. Script patch macros are invoked before each command start and on reselection to update target ID, command buffer, message count, and SG script entry points.

State and persistence: this header describes volatile runtime state only. `TOTAL_MEM_SIZE` lays out one DMA allocation containing the generated script, message-out buffer, message-in buffer, status byte, and all command slots on cacheline boundaries. `NCR_700_Host_Parameters` stores current host state, active command, free list, slot count, reselection ID, negotiated tag bitmap, revision, sync clock, min period, and reset completion pointer. `NCR_700_Device_Parameters` is allocated per `scsi_device` and freed at device teardown.

Dependencies and integration: includes Linux interrupt and I/O APIs plus SCSI device/command types. It integrates with generated script symbols from `53c700_d.h`, endian configuration options `CONFIG_53C700_LE_ON_BE` and `CONFIG_53C700_BE_BUS`, architecture byte order, the SPI transport's `spi_flags`, `spi_period`, and `spi_offset` fields, and board-specific wrappers that know the physical register mapping.

Risks: the header is dense with register constants and ABI-sized structures; small mistakes can corrupt scripts or program the chip incorrectly. Register access uses XOR byte-lane adjustment and optional bus-endian swaps, so platform wiring assumptions must match the actual board. `BUG_ON((reg & 0x3) != 0)` in long accessors catches invalid register alignment but can panic. `to32bit`-style script addresses and `__u32 pScript` reflect 32-bit DMA script engines. The tag and sync flags share `spi_flags`, so bit allocation must not collide with transport changes.

Test signals: compile across little-endian, big-endian, and `CONFIG_53C700_LE_ON_BE`/`CONFIG_53C700_BE_BUS` combinations; inspect generated object sizes/layout assumptions; validate script patching with command start/reselection; test per-device depth accounting via `active_tags`; and run reset, sync-negotiation, and DMA paths on both coherent and noncoherent architectures.
