# sources/distributed-fs/ceph-client/drivers/scsi/mpt3sas/mpi/mpi2_sas.h

Purpose: defines MPI Serial Attached SCSI status values, SAS device-info flags, SMP passthrough, SATA passthrough, and pre-MPI-v2.6 SAS IO Unit Control messages. These layouts are the protocol bridge between Linux SAS transport/SCSI management operations and firmware-controlled SAS/SATA links.

Important APIs/types/functions: `MPI2_SASSTATUS_*` constants describe firmware SAS protocol outcomes. `MPI2_SAS_DEVICE_INFO_*` flags classify device type and roles such as SSP/STP/SMP target or initiator, SATA device/host, ATAPI, enclosure processor, expander, direct attach, and LSI device. `Mpi2SmpPassthroughRequest_t`/`Reply_t` carry SMP request and response buffers through an SGE, optionally using immediate mode. `Mpi2SataPassthroughRequest_t`/`Reply_t` carry ATA FIS command/status data, transfer direction, DMA/PIO/FPDMA flags, data length, and an MPI/IEEE SGE union. `Mpi2SasIoUnitControlRequest_t`/`Reply_t` cover link reset, hard reset, clear error log, force full discovery, remove device, mapping lookup, IOC parameter setting, fast-path enable/disable, NCQ enable/disable, and persistent clearing for MPI v2.5 and earlier.

Control flow: the header is declarative. Runtime consumers include `mpt3sas_transport.c`, which builds SMP passthrough frames for SAS expander access and sends IO Unit Control link resets from transport PHY reset operations; `mpt3sas_base.c`, which sizes request frames and synchronously issues SAS IO Unit Control operations; and `mpt3sas_scsih.c`, which sends remove-device IO Unit Control messages during topology cleanup. `mpt3sas_ctl.c` validates passthrough ioctl functions for SMP, SATA, and SAS IO Unit Control and treats PHY link/hard reset as reset-sensitive operations.

State and persistence: no local state is stored. Requests affect live SAS/SATA link state, firmware discovery tables, NCQ/fast-path settings, and device presence. Clear-all-persistent and remove-device operations can alter firmware persistence or cached topology state. SMP/SATA passthrough data buffers are transient DMA mappings.

Dependencies and integration: depends on MPI SGE unions from the common MPI headers. It integrates with the Linux SAS transport class, libsas-like expander access paths, SCSI error handling and target reset flow, config pages for SAS device/PHY/IO unit data, event structures from `mpi2_ioc.h`, and user passthrough ioctls.

Risks: passthrough requests expose low-level link/device operations, so malformed FIS/SMP lengths, SGE direction mismatches, or missing reset serialization can disrupt buses. The SAS IO Unit Control section is explicitly replaced by MPI v2.6 IO Unit Control in `mpi2_ioc.h`; version-aware callers must choose the right operation constants. Flexible SGE union members differ between MPI v2.0 and v2.5, which is an ABI risk when building request frames.

Test signals: transport-layer tests should exercise SMP expander access, PHY hard/link reset, SATA passthrough read/write and FPDMA cases, NCQ toggle behavior, remove-device cleanup, timeout/reset handling, and firmware responses for each `MPI2_SASSTATUS_*` class. Hotplug and topology-change events are important end-to-end signals because they verify these control messages and event/config refreshes agree.
