# sources/distributed-fs/ceph-client/drivers/scsi/esas2r/esas2r_disc.c

Purpose: implements device discovery for the `esas2r` adapter. It waits for firmware/device readiness, issues VDA management scans, discovers RAID partitions and pass-through devices, handles LU async-event changes, and reconciles deferred requests against the target database after topology changes.

Important APIs/types/functions: external entry points are `esas2r_disc_initialize()`, `esas2r_disc_start_waiting()`, `esas2r_disc_check_for_work()`, `esas2r_disc_check_complete()`, `esas2r_disc_queue_event()`, `esas2r_disc_start_port()`, and `esas2r_disc_local_start_request()`. Internal state handlers include `esas2r_disc_continue()`, `esas2r_disc_block_dev_scan()`, `esas2r_disc_raid_grp_info()`, `esas2r_disc_part_info()`, `esas2r_disc_passthru_dev_info()`, `esas2r_disc_passthru_dev_addr()`, `esas2r_disc_dev_remove()`, `esas2r_disc_dev_add()`, and `esas2r_disc_fix_curr_requests()`.

Control flow: initialization clears discovery flags, derives wait time/count from NVRAM, and extends waits after chip reset or power management. Completion checks either wait for a target count/time or schedules a full scan. `disc_queue_event()` records `DCDE_DEV_SCAN` or `DCDE_DEV_CHANGE`, and `disc_start_port()` starts a serialized state machine using `a->general_req`. Scan flow is `DCS_BLOCK_DEV_SCAN` to get a scan generation, then iterates RAID groups, partitions, and pass-through device records. RAID partitions call `esas2r_targ_db_add_raid()`. Pass-through devices first query management device info, then tunnel an HBA IOCTL to retrieve SAS and unique identifiers before calling `esas2r_targ_db_add_pthru()`. Device-change flow removes targets marked not-present, then adds targets marked present from saved LU events. Interrupt-driven discovery continues from callbacks; polled discovery waits in init code and calls `disc_check_for_work()`.

State and persistence behavior: mutable discovery state lives in `a->disc_ctx`, `a->disc_buffer`, `a->general_req`, `AF_DISC_*`, `AF2_DEV_SCAN`, `AF2_DEV_CNT_OK`, `disc_wait_*`, and target database entries. It has no disk persistence, but it mirrors firmware-visible topology and controls SCSI target reporting. Deferred SCSI requests are fixed after discovery by rewriting their firmware virtual target IDs or completing them with selection failure if their target disappeared.

Dependencies and integration points: depends on VDA management requests built by `esas2r_build_mgt_req()`, HBA IOCTL requests built by `esas2r_build_ioctl_req()`, request submission in `esas2r_io.c`, completion in `esas2r_int.c`, target database helpers in `esas2r_targdb.c`, async LU events from `esas2r_int.c`, and NVRAM wait policy. It coordinates with reset/flashing by deferring discovery requests while `AF_CHPRST_PENDING` or `AF_FLASHING` is set.

Risks and test signals: scan-generation changes restart portions of discovery, so stale topology and loops are key risks. Deadlock risk exists around polled discovery and ISR-driven starts, which is why work is deferred through flags and locks. Other risks include mis-handled pass-through identifier lengths, missing `VDAAE_LU_PHYS_ID`, target ID changes after hibernate, and completing deferred requests incorrectly. Test signals include initial boot with delayed devices, reset/power-management rediscovery, full scan with invalid groups/partitions/devices, pass-through address failures, LU present/not-present events, timeouts that trigger local reset, and deferred I/O during topology change.
