# sources/distributed-fs/ceph-client/drivers/scsi/BusLogic.h

Purpose: defines the BusLogic driver protocol and runtime data model. It contains adapter limits, firmware command opcodes, packed firmware reply/request structures, mailbox and CCB layouts, target statistics, option structures, the main `blogic_adapter` hostdata structure, I/O port access helpers, FlashPoint interface definitions, and internal function prototypes used by `BusLogic.c`.

Important APIs/types/functions: key constants include `BLOGIC_MAX_ADAPTERS`, `BLOGIC_MAXDEV`, `BLOGIC_SG_LIMIT`, tag-depth defaults, bus-settle time, mailbox count, and message-buffer sizes. Important enums model message levels, adapter type, bus type, BIOS geometry, firmware opcodes, ISA I/O ports, strict round-robin requests, CCB format, mailbox actions, completion codes, CCB opcodes, data direction, adapter status, target status, queue tag type, and CCB status. Major structures include `blogic_probeinfo`, `blogic_probe_options`, `blogic_global_options`, register unions, firmware reply structs, `blogic_autoscsi`, `blogic_ccb`, `blogic_outbox`, `blogic_inbox`, `blogic_drvr_options`, `blogic_tgt_flags`, `blogic_tgt_stats`, `fpoint_info`, and `blogic_adapter`.

Control flow: `BusLogic.c` uses this header to move through adapter discovery, firmware interrogation, command construction, mailbox execution, completion processing, and statistics reporting. Inline I/O helpers write reset bits and command parameters, read status/data/interrupt/geometry registers, issue mailbox execute commands, delay after resets, and update counters. CCB and mailbox structs are the shared memory protocol: outgoing mailboxes point firmware at CCB DMA addresses, incoming mailboxes return completion status, and CCBs carry CDBs, SGLs, sense DMA addresses, tag fields, and driver-owned linkage.

State and persistence: the header defines both transient driver state and firmware-reflected configuration. `blogic_adapter` is the durable in-kernel state for a registered host: PCI identity, bus resources, firmware strings, feature flags, queue depths, target masks, CCB free/all lists, mailbox rings, target flags/stats, reset counters, and config message buffer. The underlying adapter firmware persists its own AutoSCSI and BIOS settings, but these structures merely cache what was read during initialization.

Dependencies and integration: relies on packed C layout matching BusLogic firmware, Linux I/O port operations, PCI devices, SCSI host/device/command types, kernel lists, DMA-coherent memory, and optional FlashPoint SCCB manager callbacks. The header also declares the driver-facing SCSI template callbacks implemented in `BusLogic.c`.

Risks: many structs use C bitfields in packed firmware layouts, which are compiler and endian sensitive but historically tied to supported Linux targets. `virt_to_32bit_virt()` and multiple `u32` address fields assume 32-bit firmware-visible addresses. Static arrays such as message-level names and bus names live in the header, so every includer would get definitions. Limits such as `BLOGIC_CDB_MAXLEN` 12 and `BLOGIC_SG_LIMIT` 128 must align with midlayer expectations. The main adapter struct is large and mixes interrupt-time state, init-time configuration, proc text, and statistics, so locking discipline is critical.

Test signals: compile-time layout and warning checks, probe/resource tests on each adapter type, command submission with SGL counts near `BLOGIC_SG_LIMIT`, tagged queue enable/disable behavior, mailbox wraparound, reset and completion status translation for all firmware status enums, proc statistics formatting, and option-driven queue depth/tag masks across all 16 target IDs.
