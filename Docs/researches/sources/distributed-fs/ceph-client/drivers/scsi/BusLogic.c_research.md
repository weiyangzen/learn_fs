# sources/distributed-fs/ceph-client/drivers/scsi/BusLogic.c

Purpose: implements the BusLogic MultiMaster and optional FlashPoint SCSI host adapter driver. It discovers adapters, parses `BusLogic=` options, interrogates firmware, configures queueing and transfer capabilities, allocates CCB/mailbox resources, registers SCSI hosts, submits SCSI commands, handles interrupts and completions, reports `/proc/scsi/BusLogic` statistics, and performs host-adapter reset recovery.

Important APIs/types/functions: module entry/exit are `blogic_init()` and `blogic_exit()`. The SCSI template uses `blogic_qcmd`, `blogic_sdev_configure`, `blogic_diskparam`, `blogic_hostreset`, `blogic_write_info`, `blogic_show_info`, and `blogic_drvr_info`. Detection/configuration functions include `blogic_init_probeinfo_list()`, `blogic_init_mm_probeinfo()`, `blogic_init_fp_probeinfo()`, `blogic_probe()`, `blogic_hwreset()`, `blogic_checkadapter()`, `blogic_rdconfig()`, `blogic_reportconfig()`, `blogic_getres()`, `blogic_initadapter()`, and `blogic_inquiry()`. I/O lifecycle functions include `blogic_alloc_ccb()`, `blogic_dealloc_ccb()`, `blogic_write_outbox()`, `blogic_scan_inbox()`, `blogic_qcompleted_ccb()`, `blogic_process_ccbs()`, `blogic_inthandler()`, `blogic_qcmd_lck()`, and `blogic_resetadapter()`.

Control flow: initialization parses module/boot options, builds a probe list from PCI devices and legacy addresses, probes each candidate I/O range, hard-resets and verifies the adapter, allocates a `Scsi_Host`, reads firmware configuration, acquires IRQs, allocates initial CCBs, initializes mailboxes/strict round-robin/extended LUN mode, performs target inquiry, registers the host, and scans devices. Command submission allocates a CCB, maps the SCSI data and sense buffer, fills CDB, target, LUN, data direction, SGL pointer, tag fields, and stats, then either writes a MultiMaster outgoing mailbox or calls the FlashPoint SCCB manager. Interrupt handling acknowledges hardware, scans incoming mailboxes or FlashPoint completions, queues completed CCBs, translates result codes, updates target state/statistics, unmaps DMA, calls `scsi_done()`, and initiates adapter resets for external bus resets or internal errors.

State and persistence: module globals store parsed options, probe list, global trace flags, and the registered adapter list. Each `struct blogic_adapter` in `hostdata` stores firmware-derived capabilities, queue limits, target flags, active command counters, reset timestamps, CCB lists, mailbox rings, DMA handles, statistics, and accumulated config text for proc output. Runtime statistics can be cleared through `write_info`. Hardware/firmware settings such as AutoSCSI, BIOS geometry translation, termination, and queue support are read but not persisted by this driver, except normal SCSI I/O changes device media.

Dependencies and integration: depends on PCI discovery, I/O port regions, shared IRQs, DMA mapping, SCSI midlayer, SCSI tagged command support, proc/seq reporting via the host template, MSDOS partition parsing for BIOS geometry inference, and `FlashPoint.c` when `CONFIG_SCSI_FLASHPOINT` is enabled. `MODULE_DEVICE_TABLE(pci, blogic_pci_tbl)` advertises supported BusLogic PCI IDs even though the driver uses its own module init probe loop rather than a modern `pci_driver`.

Risks: the driver is old hardware code with many synchronous polling loops and firmware-version branches. `blogic_inbox_to_ccb()` linearly scans all CCBs for each completion, which is inefficient and assumes CCB list integrity. DMA addresses and firmware fields are 32-bit. Some error handling deallocates active CCBs during reset without completing every command in the same function, relying on upper-layer reset behavior. Abort handling is compiled out. Option parsing mutates the option string and has limited validation. `blogic_msg()` uses static formatting state and appends to a fixed adapter message buffer, so message length and concurrency assumptions matter. FlashPoint support is tightly coupled through direct inclusion of `FlashPoint.c`.

Test signals: compile with and without `CONFIG_SCSI_FLASHPOINT`; test module and boot `BusLogic=` option parsing; probe PCI MultiMaster, non-compliant PCI, FlashPoint, and legacy-address cases; verify firmware config reporting, mailbox initialization, strict round-robin, and extended LUN setup; run tagged and untagged I/O with queue-depth changes; trigger REQUEST SENSE, selection timeout, external bus reset, internal error reset, and host reset paths; validate `/proc/scsi/BusLogic` statistics and clearing; and check BIOS geometry output for disks with and without partition-table geometry hints.
