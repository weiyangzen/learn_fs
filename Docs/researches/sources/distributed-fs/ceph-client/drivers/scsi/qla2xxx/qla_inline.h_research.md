# sources/distributed-fs/ceph-client/drivers/scsi/qla2xxx/qla_inline.h

Purpose: provides small, performance-sensitive inline helpers shared across the qla2xxx Fibre Channel driver. The file covers IOCB sizing, register polling, byte-order conversion, SRB allocation/release, fcport discovery state tracking, mailbox completion, retry-delay throttling, qpair CPU affinity, firmware resource accounting, PCI-disconnect detection, and miscellaneous queue/resource predicates.

Important APIs/types/functions: `qla24xx_calc_iocbs()` sizes type-7 command plus continuation IOCBs for DSD counts. `qla2x00_debounce_register()`, `qla2x00_poll()`, `host_to_fcp_swap()`, and `host_to_adap()` wrap hardware reads and wire-format conversions. `qla2xxx_init_sp()`, `qla2xxx_get_qpair_sp()`, `qla2xxx_rel_qpair_sp()`, `qla2x00_get_sp()`, and `qla2x00_rel_sp()` manage `srb_t` lifetime through qpair/base-vha busy markers and mempools. `qla2x00_set_fcport_disc_state()` atomically records discovery-state transitions. `qla2x00_hba_err_chk_enabled()`, `qla2x00_reset_active()`, and `qla2x00_chip_is_down()` gate protection and queueing behavior. `qla_get_fw_resources()` and `qla_put_fw_resources()` account IOCB and exchange usage per qpair and optionally per HBA.

Control flow: most helpers are leaf routines called from SCSI/NVMe/target paths. Allocation first marks the qpair busy, takes an SRB from the qpair mempool, initializes common SRB fields and a `kref`, and clears the busy mark on allocation failure. Base-vha allocation also marks the VHA busy and unwinds it if qpair allocation fails. Release reverses this order by clearing VHA busy state, resetting SRB callbacks to warning stubs, freeing to the mempool, and marking the qpair idle. Firmware resource acquisition checks per-qpair, aggregate qpair, and optional HBA-global limits before incrementing counters; release decrements with saturation for global atomics and qpair counters.

State and persistence: this header mutates runtime-only driver state: queue busy flags, `fcport->disc_state`, `fcport->shadow_disc_state`, retry-delay timestamps in jiffies, qpair CPU IDs and hint records, qpair/HBA firmware-resource counters, `ha->qp_cpu_map`, and DSD tracking lists. No durable storage is written. The discovery shadow packs historical states by shifting four bits per transition, so it is a compact runtime trace rather than a persistent log.

Dependencies and integration: depends on qla2xxx core definitions from `qla_target.h` and surrounding driver headers, Linux atomics, lists, DMA pools, PCI IRQ affinity, MMIO register helpers, SCSI protection helpers, and module parameters such as `ql2xenablehba_err_chk` and `ql2xenforce_iocb_limit`. It integrates directly with `qla_iocb.c` queue submission, `qla_nvme.c` qpair selection and IOCB sizing, target mode qpair hints, EEH recovery scheduling, and mailbox interrupt completion.

Risks: inline code runs in atomic and interrupt-sensitive paths, so lock ordering and balanced busy/resource accounting matter. `qla2x00_set_fcport_disc_state()` assumes discovery states fit in four bits and indexes `port_dstate_str[state]` without validating the new state. `qla_get_fw_resources()` uses rough unlocked aggregate qpair totals before incrementing under the caller's queue lock, so it is a throttle rather than a precise reservation protocol. `qla_put_fw_resources()` defensively saturates counters, which prevents underflow but can hide mismatched acquire/release paths. CPU mapping uses `raw_smp_processor_id()` and affinity hints, so hotplug and affinity changes need careful coverage.

Test signals: build with multiple qla2xxx hardware families enabled; exercise SRB allocation failure, qpair busy rejection, and release paths with debug warnings enabled; run SCSI/NVMe I/O while forcing `ql2xenforce_iocb_limit` modes; validate DIF/T10 PI combinations against `qla2x00_hba_err_chk_enabled()`; check mailbox interrupt wait completion; simulate PCI disconnect reads of `0xffffffff`; and confirm CPU-affinity qpair mapping is populated and freed across queue creation/removal.
