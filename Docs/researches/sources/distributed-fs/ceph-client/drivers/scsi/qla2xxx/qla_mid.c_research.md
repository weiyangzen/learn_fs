# sources/distributed-fs/ceph-client/drivers/scsi/qla2xxx/qla_mid.c

Purpose: implements qla2xxx NPIV virtual-port management, vport DPC handling, multi-queue request/response queue creation and deletion, vport-to-host map maintenance, and per-qpair FCP command buffer pooling. It is the glue between the Linux FC transport vport object, the physical adapter `qla_hw_data`, firmware VP control/config IOCBs from `qla_mbx.c`, and the driver's request/response queue machinery.

Important APIs/types/functions: vport lifecycle starts with `qla24xx_vport_create_req_sanity_check()`, `qla24xx_create_vhost()`, `qla24xx_enable_vp()`, `qla24xx_disable_vp()`, `qla2x00_vp_stop_timer()`, `qla24xx_allocate_vp_id()`, and `qla24xx_deallocate_vp_id()`. Lookup and state helpers include `qla24xx_find_vhost_by_name()`, `qla2x00_mark_vp_devices_dead()`, `qla24xx_configure_vp()`, `qla2x00_alert_all_vps()`, `qla2x00_vp_abort_isp()`, `qla2x00_do_dpc_all_vps()`, and the internal `qla2x00_do_dpc_vp()`. Queue APIs include `qla25xx_create_req_que()`, `qla25xx_create_rsp_que()`, `qla25xx_delete_req_que()`, `qla25xx_delete_rsp_que()`, `qla25xx_delete_queues()`, `qla25xx_free_req_que()`, `qla25xx_free_rsp_que()`, and `qla_do_work()`. Firmware-facing VP control uses `qla24xx_control_vp()` with completion callback `qla_ctrlvp_sp_done()`. Mapping helpers include `qla_find_host_by_vp_idx()`, `qla_update_vp_map()`, and `qla_update_host_map()`. Buffer-pool APIs include `qla_create_buf_pool()`, `qla_free_buf_pool()`, `qla_get_buf()`, `qla_put_buf()`, `qla_adjust_buf()`, and internal trim/snapshot helpers.

Control flow: vport creation first validates FC role, NPIV capability, fabric support, WWPN uniqueness against the physical port and existing vports, and maximum supported vports. `qla24xx_create_vhost()` allocates a SCSI host private area with the qla2xxx host template, binds it to `fc_vport->dd_data`, copies node/port WWNs, allocates a VP index, reserves a management server loop ID, seeds DPC flags for FDMI/FC4 registration, marks SCR needed, starts the vport timer, inherits request queue and NVMe state from the base vhost, initializes host limits and transport template, and increments current vport count under `vport_lock`. VP enable checks that the physical port is up and fabric topology is present, then calls `qla24xx_modify_vp_config()` while holding `vport_lock`; firmware ID acquisition later sets `VP_IDX_ACQUIRED`, and `qla24xx_configure_vp()` sends SCR registration, configures the vHBA, marks the vport online/active, and updates FC transport state.

Disable and recovery flow: `qla24xx_disable_vp()` optionally posts EDIF vport-down AEN work and waits for session deletion, sends firmware control-vp disable/logout when firmware is running, marks the loop down, sets each vport fcport `logout_on_delete`, removes the AL_PA mapping under `hardware_lock`, marks devices lost/unconfigured, clears management-server login state, and sets the FC transport state to disabled or failed. `qla2x00_vp_abort_isp()` logs the vport out unless an ISP abort is already active, marks local loop/device state down, and schedules re-enable. `qla2x00_do_dpc_vp()` runs per-vport deferred work once the base vhost advertises `VP_CONFIG_OK`: it completes VP configuration after ID acquisition, processes PUREX IOCBs when loop-ready, posts relogin work after a delay, clears reset marker requests, and performs loop resync with active-bit serialization. `qla2x00_do_dpc_all_vps()` walks `ha->vp_list` from the physical host, increments `vref_count` while dropping the list lock around per-vport work, and skips non-fabric topology.

Queue and buffer control flow: request/response queue creation allocates `req_que` or `rsp_que`, allocates coherent ring memory, allocates outstanding command arrays for request queues, chooses a free queue ID from `req_qid_map` or `rsp_qid_map` under `mq_lock`, populates queue-to-adapter maps, initializes hardware register pointers, MSI-X response queue fields, shadow indices, queue options, VP/rid/qos metadata, and optionally starts the queue through mailbox initialization in `qla25xx_init_req_que()` or `qla25xx_init_rsp_que()`. Response queues request an IRQ through `qla25xx_request_irq()` and initialize response entries; workqueue processing for qpair responses calls `qla24xx_process_response_queue()` under the qpair lock. Deletion either removes qpair objects when MQ/NVMe support is enabled or iterates queue maps, asks firmware to delete queues by setting `BIT_0` in options and reissuing the init mailbox, then frees IRQs, coherent rings, bitmaps, outstanding command arrays, and queue structures.

State and persistence behavior: all state is runtime kernel/firmware state. VP indexes are tracked in `ha->vp_idx_map`, `ha->vp_map`, `ha->vp_list`, `ha->num_vhosts`, and `ha->cur_vport_count`; `qla_update_vp_map()` also maintains `ha->host_map`, a btree keyed by 24-bit port ID, for routing firmware events to the right `scsi_qla_host`. Vport lifecycle mutates `vha->vp_idx`, `vp_flags`, `dpc_flags`, `loop_state`, `loop_down_timer`, `flags.online`, `flags.management_server_logged_in`, `vp_state`, `vp_err_state`, and FC transport vport state. Queue state is persisted in `ha->req_q_map`, `ha->rsp_q_map`, queue ID bitmaps, queue ring pointers, DMA addresses, queue register pointers, MSI-X ownership, and vhost flags `qpairs_req_created`/`qpairs_rsp_created`. Buffer pools keep per-qpair bitmaps, pointer arrays, DMA arrays, active/allocated counters, high-water marks, and snapshot state; `qla_adjust_buf()` periodically trims unused DMA pool entries only from the physical host.

Dependencies and integration points: includes local driver definitions (`qla_def.h`, `qla_gbl.h`, `qla_target.h`) and Linux module, VM, slab, list, delay, and SCSI transport headers. It calls mailbox/IOCB functions from `qla_mbx.c` such as `qla24xx_modify_vp_config()`, `qla24xx_control_vp()`, `qla2x00_send_change_request()`, `qla25xx_init_req_que()`, and `qla25xx_init_rsp_que()`. It integrates with the FC transport (`struct fc_vport`, `fc_vport_set_state()`), SCSI host allocation/limits, timers, DPC flags, target session deletion and locks, EDIF AEN/session cleanup, purex processing, relogin work, loop resync, response queue processing, MSI-X interrupt allocation, DMA coherent APIs, DMA pools, and qpair management.

Risks and edge cases: VP ID allocation/deallocation and list traversal require careful `vport_lock`, `vport_slock`, `hardware_lock`, and `vref_count` ordering. `qla24xx_deallocate_vp_id()` waits up to about 10 seconds for references and then removes the vport anyway, so a leak or stuck traversal becomes a forced teardown risk. `qla24xx_control_vp()` rejects `vp_index == 0` and indexes at or beyond `max_npiv_vports`; off-by-one assumptions must match firmware and bitmap sizing. `qla24xx_create_vhost()` does not free the just-allocated host on the local `create_vhost_failed` path shown here, so callers or adjacent code must be checked for cleanup responsibility if VP ID allocation fails. Queue create failure unwinds through free helpers, but paths that set bitmap/map entries before firmware initialization must clear them consistently; response queue IRQ ownership also has to be released exactly once. `qla_update_vp_map()` assumes callers hold the right lock and uses GFP_ATOMIC btree insertion; insertion failure leaves event routing incomplete. Buffer-pool operations assume the qpair lock is held, reserve tag 0, and trim from the highest allocated slot only if inactive; misuse can race active DMA buffers or underflow accounting.

Test signals: validation should include NPIV creation rejection for unsupported role, missing NPIV firmware support, missing switch MID support, duplicate physical/vport WWPN, and exceeding max vports. Positive tests should create, enable, acquire ID for, configure, disable, and delete vports while checking FC transport states, `vp_idx_map`, `vp_map`, `host_map`, timers, loop state, SCR registration, FDMI/FC4 DPC flags, and session deletion behavior. Recovery tests should inject ISP aborts, loop-down/up async events, RSCN/port-update events targeted by VP index, PUREX work, relogin delays, and loop resync. Queue tests should create/delete request and response queues with and without `startqp`, with MQ/NVMe qpair mode and legacy queue-map mode, verify MSI-X request/free symmetry, firmware queue delete failures, qid bitmap cleanup, ring DMA cleanup, and response workqueue processing. Buffer-pool tests should exercise allocation, reuse, release, out-of-buffer behavior, high-water accounting, snapshot/trim after idle periods, and lockdep coverage for `qla_put_buf()`.
