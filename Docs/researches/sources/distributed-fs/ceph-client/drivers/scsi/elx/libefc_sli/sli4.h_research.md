# sources/distributed-fs/ceph-client/drivers/scsi/elx/libefc_sli/sli4.h

Purpose: defines the SLI-4 hardware/software contract used by `sli4.c` and the EFC driver stack. It contains register offsets, bit masks, queue/CQE/WQE/mailbox layouts, feature/resource enums, runtime state structures, inline formatting/parsing helpers, and public prototypes for common SLI-4 operations.

Important APIs/types/functions: register and doorbell definitions cover `SLI4_INTF_REG`, BMBX, port control/status/error, IF_TYPE_2 and IF_TYPE_6 EQ/CQ/MQ/RQ/WQ doorbells, and PHYDEV reset/dump control. Important data structures include `struct sli4`, `struct sli4_queue`, `struct sli4_params`, `struct sli4_queue_info`, `struct sli4_extent`, `struct sli4_sge`, `struct sli4_bde`, EQE/MCQE/ACQE/CQE variants, FC WQE formats, mailbox command/response formats, common SLI_CONFIG request/response headers, resource descriptors, and parameter blocks for BLS/ELS/CT/FCP target WQE builders. Inline helpers format doorbell writes, compute page counts, fill request headers, read SLI registers, convert queue-count masks, query max SGL/SGE, set topology, extract RQE lengths/FCFI, and set WQ id association.

Control flow: the header itself has no runtime loop, but it encodes the control flow expected by the implementation. Callers initialize `struct sli4` with PCI/register handles, use mailbox command structs to negotiate features/configuration, allocate `struct sli4_queue` objects for EQ/CQ/MQ/WQ/RQ, construct WQEs from parameter structs, parse completions into `SLI4_QENTRY_*` events, and manage hardware resource identifiers through `enum sli4_resource`. The prototypes at the end form the exported local API from the SLI layer to `efct_hw`, queue handling, and EFC command code.

State and persistence behavior: state definitions are in-memory only. `struct sli4` caches firmware/configuration identity, WWPN/WWNN, topology, timing, queue/resource capabilities, resource allocation bitmaps, negotiated features, callback pointers, the bootstrap mailbox DMA buffer, optional non-embedded mailbox payload pointer, and VPD DMA storage. `struct sli4_queue` stores coherent DMA backing, queue indices, firmware queue id, doorbell address, phase state, posted counts, processing limits, and queue flags. The header also defines hardware-visible command structures; correctness depends on matching firmware layout and little-endian fields rather than any disk persistence.

Dependencies and integration points: includes Linux PCI/delay support, Fibre Channel ELS/frame constants, and `../include/efc_common.h` for driver-common types such as `struct efc_dma` and logging. It is the central shared contract for `libefc_sli/sli4.c`, `efct/efct_hw.c`, `efct/efct_hw_queues.c`, and `libefc/efc_cmds.c`. FC constants and ELS command ids from the SCSI FC headers feed WQE builder decisions, while Linux MMIO helpers are used by inline register readers and doorbell formatting consumers.

Risks and test signals: this is ABI-sensitive code. Risks include struct layout drift, missing `__le*` conversions in users, masks that overlap or are reused with different meanings, IF_TYPE-specific doorbell mismatches, flexible-array payload sizing mistakes, resource enum/order assumptions, and queue/CQE phase semantics getting out of sync with firmware. Compile coverage with `W=1`, sparse endian checks, structure size/offset assertions where practical, and hardware or emulated mailbox tests should focus on every command layout consumed by `sli4.c`, CQE code parsing, SGL/page descriptor limits, `sli_get_max_sgl()` behavior for unsupported page-size bitmaps, and reset/resource lifetime interactions.
