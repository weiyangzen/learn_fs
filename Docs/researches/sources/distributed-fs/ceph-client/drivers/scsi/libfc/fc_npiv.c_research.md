# sources/distributed-fs/ceph-client/drivers/scsi/libfc/fc_npiv.c

Purpose: implements libfc helper functions for NPIV virtual ports. It allocates VN_Port local-port instances, associates them with `fc_vport`, resolves received fabric IDs to the parent N_Port or a VN_Port, and propagates parent link/fabric capability changes to child virtual ports.

Important APIs/types/functions: exported `libfc_vport_create()` allocates a child `fc_lport` through `libfc_host_alloc()`, stores it in `vport->dd_data`, and links it onto the parent N_Port `vports` list. `fc_vport_id_lookup()` maps an FC_ID to the parent N_Port, the fabric-login ID in point-to-point mode, or a matching VN_Port. `fc_vport_setlink()` updates one VN_Port from its parent. `fc_vports_linkchange()` updates all children when the parent changes. Internal `__fc_vport_setlink()` handles state decisions while both mutexes are held. `enum libfc_lport_mutex_class` gives lockdep a nested class for VN_Port locking.

Control flow: virtual port creation starts from a transport `fc_vport`, obtains the parent host/lport, allocates the VN_Port host-private object, sets back-pointers, then appends it under the parent `lp_mutex`. When the parent enters READY, `fc_vports_linkchange()` locks each VN_Port with the nested class and either calls `__fc_linkup()` with `FC_VPORT_INITIALIZING` if NPIV was accepted by the fabric, or marks `FC_VPORT_NO_FABRIC_SUPP` and drives linkdown. When the parent is not READY, children are marked linkdown and `__fc_linkdown()` is called. `fc_vport_setlink()` performs the same update for a single child.

State and persistence: state is in the parent `fc_lport->vports` list, each VN_Port `fc_lport`, and the `fc_vport` transport object state. There is no persistent storage. Parent `npiv_enabled`, lport state, child disabled state, and FC_ID assignments determine runtime behavior.

Dependencies and integration: depends on the SCSI FC transport vport API, libfc host allocation, lport mutex/link helpers from `fc_lport.c`, and kernel list/mutex facilities. It is invoked by low-level drivers or transport callbacks that create/delete virtual ports and by lport state transitions.

Risks and test signals: nested locking must always use the VN_Port lock class to avoid false lockdep recursion and real inversion. `libfc_vport_create()` links the VN_Port before full driver-specific initialization may be complete, so callers must finish setup carefully. `fc_vport_id_lookup()` returns the parent for `FC_FID_FLOGI`, which is point-to-point-specific behavior. Test NPIV accepted versus not accepted after FLOGI, parent linkdown/reset/logoff propagation, disabled VN_Port no-op behavior, FC_ID lookup collisions, concurrent vport creation with link changes, and correct cleanup by caller-owned vport teardown.
