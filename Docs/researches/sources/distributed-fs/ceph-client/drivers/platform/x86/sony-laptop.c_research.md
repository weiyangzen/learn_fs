# sources/distributed-fs/ceph-client/drivers/platform/x86/sony-laptop.c

Purpose: Implements Sony VAIO laptop extras for two ACPI device families. The SNY5001 "SNC" path exposes notebook-control features such as hotkeys, jog dial events, backlight, battery-care limits, thermal profile, lid-resume policy, hybrid graphics switch status, rfkill radios, keyboard backlight, touchpad, fan, USB charge, panel ID, and smart connect. The SNY6001 "SPIC" path manages older programmable I/O hardware by selecting ACPI I/O and IRQ resources, decoding interrupt events, exposing radio/fan sysfs attributes, and optionally providing the legacy `/dev/sonypi` ABI.

Important APIs and types: Module parameters `debug`, `no_spic`, `compat`, `mask`, `camera`, `kbd_backlight`, and `kbd_backlight_timeout` control probing, event masks, and defaults. Shared input state is held in `struct sony_laptop_input_s` with key and jog input devices, a release FIFO, spinlock, timer, and user count. SNC command data is modeled by `struct sony_nc_value`, `struct sony_nc_handles`, `struct sony_backlight_props`, and small per-feature controls such as `kbd_backlight`, `battery_care_control`, `snc_thermal_ctrl`, `snc_lid_resume_control`, `snc_gfx_switch_control`, and `touchpad_control`. SPIC state is in global `spic_dev` (`struct sony_pic_dev`) with selected ACPI resources, model type, event tables, lock, and cached radio power. Core entry points include `sony_laptop_init/exit`, `sony_nc_probe/remove`, `sony_pic_probe/remove`, `sony_nc_notify`, `sony_pic_irq`, `sony_laptop_setup_input`, `sony_nc_function_setup/cleanup`, and `sony_pic_enable/disable`.

Control flow: Module init registers the SPIC platform driver only on Sony VAIO DMI matches unless `no_spic` is set, then registers the SNC platform driver. SNC probe checks ACPI presence, creates the shared `sony-laptop` platform device, creates input devices, optionally enables `ECON`, caches SNC handles through `SN00`, sets up handle-dependent features, registers a vendor backlight when ACPI video policy selects vendor control, creates generic SNC sysfs attributes by discovering getter/setter methods, and installs an ACPI notify handler. SNC notifications either decode new-style handle events above `0x90` or old-style events directly, report input events, update rfkill or graphics status, clear events via `SN05`, and emit ACPI netlink events. SPIC probe detects model type by Intel southbridge PCI IDs, parses `_PRS` resources, allocates shared input and optional sonypi compatibility state, requests an I/O resource pair and IRQ, programs `_SRS`, initializes the device with low-level port calls, creates SPIC sysfs attributes, and later decodes IRQ bytes against model-specific event tables.

State and persistence: Most state is runtime-only global state because these are single-laptop ACPI devices. SNC sysfs writes cache the last written generic `sony_nc_value` for resume replay, while actual settings persist in ACPI/EC firmware. Keyboard-backlight, thermal, lid-resume, battery-care, rfkill, and SPIC radio/fan values are cached in per-feature globals but authoritative state is firmware. Input key release uses a FIFO and timer so press-only firmware events become normal press/release sequences. SPIC compatibility queues events in a FIFO for `/dev/sonypi` readers and supports fasync/poll. Suspend/resume replays valid SNC settings, re-enables `ECON`, hotkeys, events, rfkill status, thermal profile, and SPIC resources.

Dependencies and integration points: Depends on ACPI platform matching for `SNY5001` and `SNY6001`, DMI matching for old VAIO SPIC systems, ACPI namespace/resource APIs, backlight, input, kfifo, timers, rfkill, PCI ID probing, I/O port access, IRQs, EC read/write helpers, miscdevice compatibility, and ACPI video backlight policy. User-visible surfaces include `/sys/devices/platform/sony-laptop/*`, backlight class device `sony`, input devices "Sony Vaio Keys" and "Sony Vaio Jogdial", rfkill devices `sony-wifi`, `sony-bluetooth`, `sony-wwan`, `sony-wimax`, and optional `/dev/sonypi`.

Risks: This driver is broad and heavily reverse engineered, with many global singleton controls and firmware-specific magic handles. Handle setup is best effort, so partial feature failures may leave only some sysfs surfaces present. Sysfs stores validate short numeric input but write opaque bitfields to firmware; wrong handle or bitfield assumptions can change power, thermal, or charging behavior. SPIC resource parsing assumes specific ACPI `_PRS` layouts and low-level port timing; incorrect resource selection can break interrupts or collide with hardware. Event decoding relies on model-specific masks and the user-supplied `mask` parameter. Optional sonypi compatibility exposes old ioctls that read EC addresses directly. Cleanup and resume ordering are important because shared input/platform devices are reference-counted by both SNC and SPIC users.

Test signals: Build with `CONFIG_SONYPI_COMPAT` on and off. On SNY5001 hardware, confirm probe logs "SNC setup done", input events for Fn/media/jog-related keys, expected sysfs files only for advertised handles, ACPI netlink events, backlight registration only when vendor backlight is selected, rfkill state updates when hardware switch changes, and resume restores cached settings. On SNY6001 hardware, confirm `_PRS` parsing, I/O/IRQ request success, "SPIC setup done", interrupt-driven input events, SPIC sysfs radio/fan controls, optional `/dev/sonypi` read/poll/ioctl behavior, suspend/resume reprogramming, and clean module unload without leaked I/O regions or IRQs.
