# sources/distributed-fs/ceph-client/drivers/platform/x86/toshiba_acpi.c

Purpose: Implements the main Toshiba laptop ACPI extras driver for ACPI IDs `TOS6200`, `TOS6207`, `TOS6208`, and `TOS1900`. It provides HCI/SCI firmware access, hotkeys, vendor backlight, legacy `/proc/acpi/toshiba` files, LEDs, fan and hwmon support, accelerometer IIO channels, touchpad and USB charging controls, keyboard-backlight controls, WWAN rfkill, cooling method, panel power, USB3, battery charge threshold support, and a miscdevice ioctl bridge for Toshiba SMM/SCI commands.

Important APIs and types: `struct toshiba_acpi_dev` is the central singleton state and tracks ACPI device, HCI method name, input/backlight/LED/misc/rfkill/IIO/hwmon devices, feature flags, cached keyboard-backlight and USB state, hotkey status, and firmware quirks. Firmware calls use `tci_raw`, `hci_read/write`, `sci_open/close`, and `sci_read/write`, with six-word TCI command buffers and Toshiba result codes. Public surfaces are built from `toshiba_attr_group`, proc ops for `lcd`, `video`, `fan`, `keys`, and `version`, `toshiba_acpi_fops` for `TOSH_SMM` and `TOSHIBA_ACPI_SCI`, `wwan_rfk_ops`, `toshiba_iio_accel_info`, and `toshiba_acpi_battery_hook`.

Control flow: Init applies DMI quirks for panel resume and quickstart hotkeys, creates `/proc/acpi/toshiba`, and registers the platform driver. Probe enforces singleton state, discovers `GHCI` or `SPFC`, registers `/dev/toshiba_acpi`, stores drvdata, probes feature support one by one, sets up hotkeys unless disabled or WMI owns the event GUID, registers backlight only if firmware read/write works and ACPI video selects vendor backlight, registers LEDs for illumination, eco mode, and keyboard backlight as supported, registers IIO accelerometer, optional hwmon fan RPM, WWAN rfkill, sysfs group, ACPI notify handler, proc entries, and finally assigns global `toshiba_acpi` before registering the battery hook. Notify handles hotkey/system events, dock/thermal/SATA notices, keyboard-backlight mode changes, and emits ACPI netlink events. Remove deregisters all user-visible devices and hooks, removes filters/work, clears globals, and frees state.

State and persistence: Runtime state records which firmware capabilities succeeded at probe, current forced fan flag, hotkey readiness/last event, keyboard-backlight mode/time/type, USB sleep-charge base and battery level, maximum cooling method, and killswitch state. Hardware state persists in Toshiba firmware through HCI/SCI writes. Legacy proc files reflect and update the same firmware state. The i8042 filter and work item can synthesize ACPI `NTFY` hotkey notifications on systems whose firmware does not send them. Battery threshold state maps Linux `charge_control_end_threshold` to Toshiba battery charge mode: below 90 selects 80 percent, otherwise 100 percent.

Dependencies and integration points: Depends on ACPI, DMI, procfs, seq_file, backlight, input sparse-keymap, LEDs, workqueue, i8042 filtering, miscdevice/uaccess, rfkill, hwmon, IIO, platform devices, Toshiba SMM UAPI, ACPI battery hooks, ACPI video policy, and the WMI GUID used to avoid duplicate hotkey handling. User-visible integration includes `/dev/toshiba_acpi`, `/proc/acpi/toshiba/*`, `/sys/devices/.../toshiba_acpi/*`, LEDs `toshiba::illumination`, `toshiba::kbd_backlight`, `toshiba::eco_mode`, backlight `toshiba`, WWAN rfkill, IIO accelerometer axes, and battery threshold attributes.

Risks: The driver contains many firmware-specific result-code paths and optional capabilities; feature probing must tolerate unsupported or broken methods without aborting unrelated functionality. Some legacy proc parsers use fragile `sscanf` validation, and changes need care to avoid accepting malformed writes or rejecting valid ones. The miscdevice exposes raw HCI/SCI command bridging to userspace and must preserve copy and command validation. Hotkey ownership is split with the WMI driver, so the WMI GUID check is critical. Singleton global `toshiba_acpi` is used by hwmon, IIO, battery hooks, work, rfkill, and ioctl paths, making remove ordering and hook unregistering important. LED registration return values are not always fatal, so later unconditional unregister paths assume safe zeroed classdev state.

Test signals: Build with and without HWMON and PM sleep. On Toshiba hardware, verify feature printout matches actual sysfs/proc/LED/IIO/rfkill surfaces; hotkeys through `INFO` and `HCI_SYSTEM_EVENT`; WMI GUID machines suppress ACPI hotkeys; i8042 `NTFY` fallback; backlight register/write/read and resume panel quirk; keyboard-backlight mode/time sysfs updates and event `0x92`; fan RPM via hwmon; accelerometer signed axis conversion; WWAN rfkill hardware and software block; battery threshold hook on ACPI batteries; `TOSH_SMM` and SCI ioctl validation; suspend disables/re-enables hotkeys and refreshes WWAN/panel state; partial probe failure unwinds all registered resources.
