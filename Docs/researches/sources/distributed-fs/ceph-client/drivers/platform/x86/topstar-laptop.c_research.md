# sources/distributed-fs/ceph-client/drivers/platform/x86/topstar-laptop.c

Purpose: Implements Topstar ACPI extras for `TPS0001` and `TPSACPI01` devices. It enables hotkey notifications, maps ACPI event codes to Linux input keys, and provides a DMI-gated software WLAN LED workaround for Topstar U931/RVP7 systems where the firmware WLAN switch/LED behavior is defective.

Important APIs and types: `struct topstar_laptop` holds the ACPI companion, synthetic platform device, input device, and optional LED class device. `topstar_keymap` maps brightness, volume, display switch, touchpad, WLAN, browser/mail/media, and 3G events through sparse-keymap. LED functions `topstar_led_get`, `topstar_led_set`, `topstar_led_init`, and `topstar_led_exit` read `GETX(0x83)` and toggle `FNCX(0x83)` as needed. ACPI functions `topstar_acpi_fncx_switch`, `topstar_acpi_notify`, `topstar_acpi_init`, and `topstar_acpi_exit` control notification enablement.

Control flow: Module init registers a minimal platform driver for the synthetic `topstar` device, then registers the ACPI platform driver. Probe checks the DMI LED workaround table, allocates state, renames the ACPI device/class, enables FNCX notifications with `FNCX(0x86)`, creates the synthetic platform device, registers the sparse-keymap input device, installs an ACPI notify handler, and optionally registers `topstar::wlan` LED. Notify suppresses duplicated `0x83` and `0x84` events by toggling per-event static booleans, then reports the remaining event through sparse-keymap. Remove unwinds LED, notify handler, input, platform device, ACPI notification disable `FNCX(0x87)`, and state allocation.

State and persistence: The driver keeps only runtime pointers and a global `led_workaround` flag set by DMI. LED brightness is not read from `led->brightness`; `topstar_led_set` reads firmware status before deciding whether to toggle. ACPI/firmware owns the actual WLAN LED/switch state. Duplicate-event suppression state is static inside the notify handler and persists for the module lifetime.

Dependencies and integration points: Depends on ACPI platform matching, DMI matching, sparse-keymap input, LED class, and platform device registration. User-visible surfaces are the "Topstar Laptop extra buttons" input device and, on the DMI-matched model, LED `topstar::wlan` with default trigger `rfkill0`.

Risks: The LED control uses a toggle-only ACPI method, so stale status or concurrent firmware changes can invert the intended state. The DMI workaround is intentionally narrow; unsupported but affected models would lack LED control. Static duplicate suppression can get out of phase if firmware event ordering changes. Probe uses a synthetic platform device in addition to the ACPI platform device, so cleanup ordering matters on partial failures.

Test signals: Probe on `TPS0001` or `TPSACPI01`; `FNCX(0x86)` enable and `FNCX(0x87)` disable paths; input events for all mapped hotkeys; duplicate suppression for volume events `0x83/0x84`; unknown-event logging for unmapped events; DMI U931/RVP7 LED registration and LED state transitions matching `GETX` status; unload without leaked input or platform devices.
