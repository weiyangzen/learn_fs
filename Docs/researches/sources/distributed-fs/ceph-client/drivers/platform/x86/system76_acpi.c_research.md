# sources/distributed-fs/ceph-client/drivers/platform/x86/system76_acpi.c

Purpose: Provides System76 ACPI platform support for laptops exposing ACPI HID `17761776`. It initializes the firmware interface, registers airplane-mode and keyboard-backlight LEDs, reports the screen-lock hotkey, exposes open-EC thermal sensors through hwmon, and adds battery charge threshold sysfs attributes through the ACPI battery hook.

Important APIs and types: `struct system76_data` stores the ACPI device, two LED class devices, cached keyboard-backlight brightness/color, hwmon object name packages, input device, open-EC flag, and keyboard LED type. ACPI helpers `system76_get`, `system76_get_index`, `system76_get_object`, `system76_name`, and `system76_set` wrap integer, indexed integer, package, and setter methods. LED handlers include `ap_led_get/set`, `kb_led_get/set`, `kb_led_color_show/store`, and hotkey helpers for hardware read, toggle, brightness up/down, and color cycling. Thermal integration is through `thermal_ops`, `thermal_channel_info`, and `devm_hwmon_device_register_with_info`. Battery integration is through `system76_battery_hook`.

Control flow: Probe allocates device state, stores the ACPI companion, detects open EC support by checking `NFAN`, and calls `INIT`. It always registers the airplane LED and then configures keyboard-backlight behavior from newer `GKBK/GKBB/SKBB` methods or older `GKBL/SKBL/SKBC` methods. If a keyboard backlight exists, probe registers it with optional RGB `color` sysfs group. It allocates and registers an input device for `KEY_SCREENLOCK`, installs an ACPI notify handler, and, on open-EC systems, reads `NFAN` and `NTMP` packages, registers hwmon, and installs the battery hook. Notify events `0x80` through `0x84` update keyboard LED state, while `0x85` emits a screen-lock key press. Remove unregisters the open-EC battery hook, frees ACPI package buffers, removes the notify handler, and calls `FINI`.

State and persistence: LED brightness and color are cached in `system76_data` so software and hotkey changes can be reported consistently to the LED core. Firmware remains authoritative for actual LED, fan, temperature, and battery-threshold state. Battery threshold reads and writes use EC methods `GBCT` and `SBCT`, with `BATTERY_THRESHOLD_INVALID` treated as invalid. The ACPI package objects returned by `NFAN` and `NTMP` persist in allocated memory until remove or probe error cleanup.

Dependencies and integration points: Integrates with ACPI device matching, ACPI EC lookup via `ec_get_handle`, LED class, input, hwmon, sysfs attribute groups, power-supply ACPI battery hooks, and standard platform-driver lifetime. User-visible surfaces are LEDs `system76_acpi::airplane` and `system76_acpi::kbd_backlight`, optional keyboard LED `color`, hwmon fan/pwm/temp channels labeled by firmware strings, `KEY_SCREENLOCK` input events, and battery `charge_control_start_threshold`/`charge_control_end_threshold` on `BAT0`.

Risks: Most functionality depends on model-specific ACPI methods and object package shapes; invalid package indexes or non-string names hide hwmon channels. `system76_name()` uses `index <= count`, so the boundary check is suspicious because valid package indexes are less than count. Keyboard-backlight behavior has two firmware generations and must keep method selection separate. The battery hook assumes only `BAT0` is supported and global registration is performed from probe for open-EC systems. Probe error cleanup must free ACPI buffers and remove notify handlers on all open-EC registration failures.

Test signals: Boot/probe on supported System76 hardware; `INIT` and `FINI` method success; LED read/write round trips for airplane and keyboard backlight; ACPI hotkey notifications updating LED hardware-changed state; RGB color sysfs validation for hex values above `0xFFFFFF`; hwmon channel visibility and label correctness for up to eight fans and temperatures; `BAT0` threshold show/store behavior for 0-100 values and invalid firmware returns; removal or module unload without leaked ACPI package buffers.
