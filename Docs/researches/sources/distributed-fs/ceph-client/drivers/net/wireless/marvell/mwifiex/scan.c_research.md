# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/scan.c

Purpose: Implements mwifiex scan command construction, scan response parsing, BSS descriptor update, security compatibility checks, cfg80211 scan completion, hidden-SSID follow-up scans, background scheduled scan configuration/query, and current-BSS beacon persistence.

Important APIs and functions: Public entry points include `mwifiex_scan_networks()`, `mwifiex_request_scan()`, `mwifiex_cmd_802_11_scan()`, `mwifiex_cmd_802_11_scan_ext()`, `mwifiex_ret_802_11_scan()`, `mwifiex_ret_802_11_scan_ext()`, `mwifiex_handle_event_ext_scan_report()`, `mwifiex_cmd_802_11_bg_scan_config()`, `mwifiex_cmd_802_11_bg_scan_query()`, `mwifiex_stop_bg_scan()`, `mwifiex_queue_scan_cmd()`, `mwifiex_cancel_scan()`, `mwifiex_update_bss_desc_with_ie()`, `mwifiex_check_network_compatibility()`, `mwifiex_cmd_append_vsie_tlv()`, `mwifiex_save_curr_bcn()`, and `mwifiex_free_curr_bcn()`. Internal helpers build channel/rate/SSID/random-MAC TLVs, split large scans into firmware-sized channel groups, parse legacy and extended scan buffers, track hidden SSID channels, and update channel survey statistics.

Control flow: `mwifiex_request_scan()` serializes with `priv->async_mutex` and delegates either a specific SSID scan or a full scan. `mwifiex_scan_networks()` rejects concurrent/blocked/bad-state scans, marks `adapter->scan_processing`, allocates a max-sized scan config union and channel list, calls `mwifiex_config_scan()`, then `mwifiex_scan_channel_list()` queues one or more firmware scan commands. That splitter limits channels per command, avoids CSA-closed channels, enforces `MWIFIEX_MAX_TOTAL_SCAN_TIME`, appends a band-appropriate rates TLV, and chooses legacy or extended scan command based on `adapter->ext_scan`. Scan responses parse firmware BSS records into cfg80211 BSS entries through `mwifiex_parse_single_response_buf()`. Completion logic in `mwifiex_check_next_scan_command()` drains queued scan commands, handles abort/block cases, triggers active scans for hidden SSIDs found on passive channels, completes internal waits, and calls `cfg80211_scan_done()`.

State and persistence: Adapter-level state includes `scan_processing`, `scan_pending_q`, command queues, `scan_wait_q_woken`, `survey_idx`, `chan_stats`, `active_scan_triggered`, `nd_info`, and extended scan support. Per-interface state includes `scan_request`, `scan_aborting`, `scan_block`, `hidden_chan`, `sched_scanning`, saved vendor-specific IEs, current BSS parameters, and `curr_bcn_buf`. `mwifiex_save_curr_bcn()` copies the current BSS beacon buffer into persistent storage and rewrites all internal IE pointers to offsets in the saved buffer so the descriptor remains valid after temporary parse buffers are freed.

Dependencies and integration points: The file depends on cfg80211 for scan requests/results, channel definitions, BSS lifetime, scheduled scan notification data, and scan completion. It depends on mwifiex command infrastructure for queuing and waiting on firmware commands, 11h helpers for CSA-closed channels, band/rate helpers, HT capability filling, and common BSS descriptor helpers. The PCIe backend advertises `adapter->ext_scan`, which changes command format and completion flow.

Parsing and compatibility behavior: `mwifiex_update_bss_desc_with_ie()` walks beacon/probe IEs with bounds checks and stores pointers/offsets for SSID, rates, FH/DS/CF/IBSS, ERP, 11h, WPA/WMM vendor IEs, RSN/RSNX/WAPI, HT/VHT, 20/40 coexistence, extended capabilities, and operating mode. Security matching checks WAPI, open, static WEP, WPA, WPA2, ad-hoc AES, and dynamic WEP. WPA/WPA2 HT compatibility disables 11n when only TKIP is present and rejects networks without acceptable pairwise cipher. Scan parsing validates returned AP counts, BSS descriptor sizes, TLV lengths, per-entry beacon lengths, and channel presence before calling `cfg80211_inform_bss()`.

Risks and edge cases: Firmware response parsing is the most sensitive area because malformed lengths can otherwise desynchronize pointer arithmetic. Legacy scan TLV size is computed from firmware response size and BSS descriptor size, so underflow or bad firmware sizes must be guarded by the existing length checks. Extended scan events contain nested TLVs and update both global `bytes_left` and per-entry `bytes_left_for_tlv`; changes here can easily break multi-result parsing. Scan completion is stateful and can race with aborts, association scan blocking, hidden-SSID follow-up scans, and queued command promotion. Background scan command building writes variable TLVs into firmware command space and depends on caller-provided maximum array sizes. Current beacon pointer persistence relies on saved offsets being correct for every pointer field.

Test signals: Exercise normal, specific SSID, BSSID-filtered, random-MAC, current-channel-only, passive, DFS/radar, CSA-closed-channel, and hidden-SSID follow-up scans. Test both legacy and extended scan command/response paths, multiple queued scan command chunks, scan abort while commands remain pending, scan blocked during association, internal synchronous scans, cfg80211 scan completion status, scheduled/background scan start/stop/query, WoWLAN network-detect match allocation, malformed TLV and beacon-length responses, missing DS channel IE, too many APs, WPA/WPA2 TKIP-only compatibility, WEP disabling HT, vendor IE passthrough length limits, channel statistics overflow protection, and current-BSS beacon save/free pointer adjustment.
