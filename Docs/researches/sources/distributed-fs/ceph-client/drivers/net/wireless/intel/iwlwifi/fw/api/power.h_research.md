## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/power.h

`power.h` defines a broad set of firmware power, latency, TX-power, SAR, antenna-gain, beacon-filter, and 6 GHz AP power-constraint ABIs. It includes `nvm-reg.h` for BIOS configuration headers and values reused by TAS/PPAG/geo power payloads. The file is a dependency of PHY operations and regulatory power handling, not a standalone implementation.

Power-management structures include LTR flags and `iwl_ltr_config_cmd_v1/current`, legacy `iwl_powertable_cmd`, device-wide `iwl_device_power_cmd`, per-MAC `iwl_mac_power_cmd`, and `iwl_uapsd_misbehaving_ap_notif`. These cover latency tolerance, memory retention/no-sleep flags, keepalive, RX/TX idle timeouts, DTIM skipping, LPRX threshold, uAPSD snoozing, QNDP TID, per-AC UAPSD flags, heavy traffic thresholds, SMPS, BT SCO coexistence, and misbehaving AP detection.

TX power reduction is versioned through `iwl_dev_tx_power_common`, v3/v4/v5/v8 structures, `iwl_dev_tx_power_cmd_v3_v8`, v9/v10/v11 structures, and current `iwl_dev_tx_power_cmd`. Modes select link/device/chains/ACK/SAR timer/default-table behavior. Versions differ in chain-table count, sub-band count, ACK reduction support, SAR timer fields, flags, and VLP backoff. Geo power and antenna gain are represented by `iwl_geo_tx_power_profiles_cmd_v1` through v6 plus `iwl_geo_tx_power_profiles_resp`, `union iwl_geo_tx_power_profiles_cmd`, `enum iwl_ppag_flags`, and `union iwl_ppag_table_cmd`. These encode per-chain/per-band offsets, profile counts, table revision, BIOS source metadata, and PPAG gains for ETSI/China/US/Canada/UHB cases.

Beacon filtering is configured with `iwl_beacon_filter_cmd` and default/D0I3 macros. The macro `IWL_BF_CMD_CONFIG(mode)` produces endian-converted defaults for RSSI energy delta, roaming threshold, temperature filters, debug flag, escape timers, and beacon abort timers. `iwl_sar_offset_mapping_cmd` maps MCCs to SAR groups. `iwl_txpower_constraints_cmd` encodes 6 GHz LPI/SP/VLP AP type plus EIRP and PSD constraints per 20 MHz channel, with `DEFAULT_TPE_TX_POWER` representing no limit.

Control flow spans initialization and association: configure LTR/device PM, configure per-MAC PM after association, react to uAPSD misbehavior, load SAR/geo/PPAG/TAS regulatory limits from BIOS/NVM, send TX power restrictions or timers as regulatory/thermal state changes, configure beacon filtering for normal/D0I3, and apply 6 GHz constraints from AP TPE/AFC information. Persistent state is in driver power state, association parameters, BIOS/NVM regulatory tables, timers, and firmware; this header encodes the payloads.

Risks are unit mistakes (seconds, TU, usec, milliseconds, 1/8 dBm, 0.5 dB), version mismatches in TX power tables, overbroad power-save causing missed beacons or latency regressions, regulatory noncompliance from wrong SAR/PPAG/TPE values, incorrect endian handling in default macros, and stale SAR timers. Test signals include suspend/resume and D0I3 behavior, uAPSD AP misbehavior notifications, SAR/PPAG table version tests, 6 GHz AP constraint parsing, beacon filter pass/escape behavior, regulatory country transitions, and thermal-driven power changes.
