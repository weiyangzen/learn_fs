# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/calib.c

Purpose: Implements DVM initialization-calibration result storage/replay and runtime receiver calibration. Runtime calibration has two main responsibilities: tune receiver sensitivity from firmware statistics so false alarms stay in target ranges, and run one-time chain-noise calibration after association to detect disconnected antennas and balance RX-chain gain.

Important APIs and functions: `iwl_send_calib_results()` replays saved `REPLY_PHY_CALIBRATION_CMD` payloads from `priv->calib_results`. `iwl_calib_set()` stores or replaces an opaque calibration result by operation code using `kmalloc_flex()`. `iwl_calib_free_results()` releases the saved list. `iwl_init_sensitivity()` initializes `priv->sensitivity_data` from `priv->hw_params.sens` and sends either a legacy or enhanced `SENSITIVITY_CMD`. `iwl_sensitivity_calibration()` consumes firmware statistics and updates sensitivity. `iwl_chain_noise_calibration()` accumulates beacon signal/noise samples and sends chain-noise gain calibration. `iwl_reset_run_time_calib()` clears runtime calibration state and requests fresh statistics. Static helpers include `iwl_sens_energy_cck()`, `iwl_sens_auto_corr_ofdm()`, `iwl_prepare_legacy_sensitivity_tbl()`, `iwl_sensitivity_write()`, `iwl_enhance_sensitivity_write()`, `find_first_chain()`, `iwl_find_disconn_antenna()`, and `iwlagn_gain_computation()`.

Control flow: Init calibration results are captured as opaque firmware commands, keyed by `cmd.hdr.op_code`, and later replayed in list order with `iwl_dvm_send_cmd()`. Runtime sensitivity begins with `iwl_init_sensitivity()`, which aborts if sensitivity calibration is disabled or no sensitivity range table is present, initializes OFDM/CCK thresholds, zeroes rolling histories, and writes the starting table. During association, `iwl_sensitivity_calibration()` checks that the device is associated, locks `priv->statistics.lock`, validates `INTERFERENCE_DATA_AVAILABLE`, copies RX enable time, false alarm, PLCP error, beacon RSSI, and beacon energy fields, unlocks, differences monotonic counters with wrap/reset handling, computes normalized OFDM/CCK false alarms, updates OFDM auto-correlation thresholds, updates CCK energy and auto-correlation thresholds, then sends a changed sensitivity table asynchronously.

State and persistence: Calibration results persist in memory on `priv->calib_results` until freed, surviving firmware image transitions long enough to be replayed. Sensitivity state is stored in `priv->sensitivity_data`, including last false-alarm/PLCP counters, auto-correlation thresholds, energy threshold, rolling 10-beacon energy and 20-beacon silence histories, and current/previous false-alarm state. Cached command tables in `priv->sensitivity_tbl` and `priv->enhance_sensitivity_tbl` suppress duplicate firmware writes. Chain-noise state is stored in `priv->chain_noise_data`, including accumulated beacon signal/noise, disconnected-chain flags, active chain mask, delta gain codes, radio-write flag, and calibration state. Firmware statistics are shared under `priv->statistics.lock`.

Dependencies and integration points: Depends on firmware ABI definitions from `commands.h`, private driver state from `dev.h`, command helpers from `agn.h`, Linux allocation/list helpers, mac80211 association state through `iwl_is_any_associated()`, NVM antenna masks, Bluetooth coexistence config, RXON context state, power management via `iwl_power_update_mode()`, chain flag update via `iwl_update_chain_flags()`, and transport command submission. Calibration command IDs, sensitivity table indexes, false-alarm thresholds, and antenna masks all come from the DVM firmware contract.

Risks: The sensitivity algorithms depend on monotonically increasing firmware counters and correct endian conversion. Bad `rx_enable_time` handling can cause divide/scale errors, so zero RX time is explicitly ignored. CCK energy values are inverted, making min/max use easy to break. `iwl_calib_set()` uses `GFP_ATOMIC`, so large or frequent calibration results can fail under memory pressure. Chain-noise calibration assumes a single BSS RXON context and only accumulates statistics from the associated channel; multi-channel operation is explicitly marked as needing fixes. Incorrect active-chain detection can disable usable antennas or enable absent ones, so the result is masked by `valid_rx_ant` and forced to keep at least one valid TX chain connected. Command writes are asynchronous in several paths, so callers must tolerate delayed firmware application.

Test signals: Verify init-calibration storage replacement by op code, replay ordering, and free paths. Exercise sensitivity init for legacy and enhanced tables, disabled calibration masks, missing ranges, duplicate table suppression, too-many/too-few/good false-alarm paths for OFDM and CCK, firmware counter wrap/reset behavior, zero RX enable time, and statistics unavailable. For chain noise, test accumulation over exactly `IWL_CAL_NUM_BEACONS`, channel/band mismatch rejection, advanced-BT bypass, all-zero RSSI handling, disconnected-chain detection, gain-code sign/magnitude encoding, one-time radio write, RXON chain update, and power mode refresh.
