# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/ctxt-info.c

Purpose: Implements the original PCIe context-info firmware self-load setup and shared DMA helpers used by both context-info generations. It allocates 4 GB-boundary-safe coherent memory, copies firmware LMAC/UMAC/paging sections into DMA, initializes context-info RX/TX/DRAM descriptors, kicks firmware load, and frees context/paging/firmware DMA memory.

Important APIs/functions: `iwl_pcie_ctxt_info_dma_alloc_coherent()` wraps coherent allocation with retry logic to avoid crossing a 2^32 boundary. `iwl_pcie_ctxt_info_alloc_dma()` allocates and copies one firmware/data block into `struct iwl_dram_data`. `iwl_pcie_ctxt_info_free_paging()` frees self-init paging blocks. `iwl_pcie_init_fw_sec()` splits a `fw_img` into LMAC, UMAC, and paging sections using separator markers and populates `trans->init_dram` plus firmware-visible DRAM pointer arrays. `iwl_pcie_ctxt_info_init()` builds the legacy `iwl_context_info`; `iwl_pcie_ctxt_info_free()` tears it down.

Control flow: The DMA allocator recursively retries at most two levels when a coherent allocation crosses a 4 GB boundary, freeing the unsuitable allocation after a replacement is obtained. Firmware section initialization counts LMAC sections until `CPU1_CPU2_SEPARATOR_SECTION`, UMAC sections after one separator, and paging sections after two separators, then allocates arrays for firmware and paging DMA records and copies each section. Legacy context init allocates the context, writes version/MAC/size, encodes RX buffer and completion-buffer sizes, points RBD/used/status addresses at the initialized RX queue, points the command queue address/size at the transport TX command queue, initializes firmware sections, enables load interrupts, applies debug destination if present, and writes `CSR_CTXT_INFO_BA`.

State and persistence: Mutates `trans->init_dram.fw`, `fw_cnt`, `paging`, and `paging_cnt`; `trans_pcie->ctxt_info`, `ctxt_info_dma_addr`; and hardware CSR registers. Firmware section DMA is freed at alive or failure by `iwl_pcie_ctxt_info_free_fw_img()` from `internal.h`; paging memory has different lifetime and is freed by `iwl_pcie_ctxt_info_free_paging()`.

Dependencies/integration: Depends on Linux DMA coherent APIs, firmware image section layout, context-info firmware structs, RX/TX queue DMA addresses in `iwl_trans_pcie`, `iwl_pcie_get_num_sections()` and `iwl_txq_crosses_4g_boundary()` from `internal.h`, interrupt/debug helpers, and CSR/PRPH register writes.

Risks: If `dram->paging` allocation fails after `dram->fw` allocation, the function returns without local cleanup; callers must later clean partially initialized state. Similar partial failures during section copy can leave DMA allocations in `trans->init_dram`. The retry allocator can still fail if repeated allocations cross the boundary. RX buffer size mapping treats 12K as 16K context encoding. Command queue and RX queue pointers must already be allocated and DMA mapped. Section counting assumes separators exist in the expected order.

Test signals: Exercise 4 GB boundary retry, allocation failure after each stage, firmware images with expected and missing separators, LMAC/UMAC/paging counts, RX buffer sizes 2K/4K/8K/12K/default warning, completion-buffer size clamp, debug destination application, CSR context base write, freeing context twice, paging free with null/non-null arrays, and leak checks after partial init failures.
