# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/trans-gen2.c

Purpose: Provides the gen2-specific PCIe transport lifecycle for Intel iwlwifi devices. It starts and stops basic NIC/APM functionality, performs firmware reset handshakes, initializes gen2 RX/TX command queues, handles context-info based firmware boot, configures boot latency workarounds, processes firmware-alive transition, and coordinates opmode leave for newer hardware families.

Important APIs, types, and functions: Exported entry points include `iwl_pcie_gen2_apm_init()`, `iwl_trans_pcie_fw_reset_handshake()`, `iwl_trans_pcie_gen2_stop_device()`, `iwl_trans_pcie_gen2_fw_alive()`, `iwl_trans_pcie_gen2_start_fw()`, and `iwl_trans_pcie_gen2_op_mode_leave()`. Key internal helpers are `iwl_pcie_gen2_apm_stop()`, `_iwl_trans_pcie_fw_reset_handshake()`, `_iwl_trans_pcie_gen2_stop_device()`, `iwl_pcie_gen2_nic_init()`, `iwl_pcie_get_rf_name()`, `iwl_pcie_set_ltr()`, and `iwl_pcie_spin_for_iml()`. The file manipulates `struct iwl_trans`, `struct iwl_trans_pcie`, `fw_reset_state`, `is_down`, `opmode_down`, interrupt masks, RX/TX queues, context-info allocations, and RF-name cache.

Control flow: `iwl_trans_pcie_gen2_start_fw()` is the primary boot path. It locks the transport mutex, prepares/owns the card, enables then disables interrupts to quiesce pending RF-kill handling, checks RF-kill policy, clears firmware handshake bits, initializes the NIC through `iwl_pcie_gen2_nic_init()`, allocates/kicks context information depending on AX210-or-newer versus older context-info format, applies LTR/IML boot workaround, starts ROM/CPU execution, handles optional TOP reset completion/retry, and rechecks RF-kill before returning. `iwl_pcie_gen2_nic_init()` performs APM init, opmode NIC config, software RX init without RFH programming, command queue init through gen2 TX, and shadow register enablement. Firmware-alive flow calls `iwl_pcie_reset_ict()`, clears queue stopped/used bitmaps, frees context-info boot memory while preserving paging, enables interrupts, updates RF-kill, caches RF name, and reads BZ URM state. Stop flow optionally performs a firmware reset handshake if firmware is running, marks the device down, disables interrupts/ICT, synchronizes IRQs and NAPI, frees gen2 TX queues, stops RX DMA, frees context/paging info, stops APM, retakes ownership, reconfigures MSI-X IVAR after reset, clears status bits, and leaves RF-kill interrupt enabled.

State and persistence behavior: This file mainly transitions runtime state rather than storing persistent data. `STATUS_DEVICE_ENABLED`, `STATUS_INT_ENABLED`, `STATUS_SYNC_HCMD_ACTIVE`, `STATUS_TPOWER_PMI`, `STATUS_RFKILL_*`, `is_down`, `opmode_down`, `fw_reset_state`, `do_top_reset`, `request_top_reset`, and `step_urm` are the important state flags. `rf_name` is cached after first construction from `hw_rf_id` and optional CNVI version. Context-info, paging, RX, TX, and ICT allocations are created elsewhere but freed or reset here at firmware/stop boundaries. Firmware reset and TOP reset state is synchronized with wait queues and interrupt handlers in `rx.c`.

Dependencies and integration points: The file relies on common PCIe transport helpers from `trans.c` (`iwl_pcie_prepare_card_hw()`, `iwl_trans_activate_nic()`, `iwl_pcie_apm_config()`, `iwl_pcie_apm_stop_master()`, `iwl_trans_pcie_sw_reset()`, `iwl_pcie_conf_msix_hw()`, `iwl_pcie_check_hw_rf_kill()`, `iwl_trans_pcie_handle_stop_rfkill()`), RX helpers from `rx.c`, and TX helpers from `tx-gen2.c`. It integrates with context-info v1/v2 code, firmware debug timepoints, opmode RF-kill/error callbacks, interrupt reset handling, and device-family specific CSR/UMAC registers. Firmware reset ACKs are delivered by interrupt paths that update `fw_reset_state` and wake `fw_reset_waitq`.

Risks and edge cases: Start and stop run under `trans_pcie->mutex`; violating that would race opmode, RF-kill, interrupt, and firmware-reset paths. The start path has multiple family-specific boot mechanisms: legacy UREG CPU run, AX210 UMAC CPU init, and BZ CSR ROM start. TOP reset retry intentionally loops back through hardware start and context setup; failure to reset state correctly could recursively boot stale context. `iwl_pcie_set_ltr()` returns false for AX210 devices that need the IML polling workaround; missing this can expose boot latency ROM issues. Stop flow accesses hardware only while `STATUS_DEVICE_ENABLED` is valid and must synchronize NAPI/IRQs before freeing queues. RF-kill is re-enabled after stop even though most interrupts are disabled, so masking and IVAR restoration order matters.

Test signals: Exercise firmware boot on 22000, AX210, and BZ-family devices, including RF-kill boot refusal versus `run_in_rfkill`, context-info allocation failures, IML polling path, TOP reset requests, firmware reset handshake timeout/error, and opmode leave. Useful logs include `"Init card's basic functions"`, reset-handshake timeout diagnostics, `"TOP reset successful"`, RF name detection, shadow register enablement, and firmware-alive interrupt progression. Integration tests should confirm TX/RX queues are freed on stop and reinitialized on restart without stale queue-used bits.
