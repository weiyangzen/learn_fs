# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/debugfs_htt_stats.h

Purpose: Defines the debugfs-facing HTT extended statistics ABI for ath12k. It is a large schema header for target-to-host HTT stats confirmations, debugfs request bookkeeping, reset bitmaps, and the packed TLV payload structures used by the debugfs stats parser/formatter.

Important APIs and types: `ath12k_debugfs_htt_stats_register()` registers per-radio HTT stats controls, and `ath12k_debugfs_htt_ext_stats_handler()` is the T2H stats confirmation entry point when debugfs is enabled, with a no-op inline stub otherwise. `struct debug_htt_stats_req` tracks one debugfs stats request: completion, type, pdev, config words, optional peer address, output buffer length, and flexible text buffer. `struct ath12k_htt_extd_stats_msg` describes the HTT extended-stats confirmation framing with echoed cookie and stats length/done bits. The core enums are `ath12k_dbg_htt_ext_stats_type` for requested stats families and `ath12k_dbg_htt_tlv_tag` for returned TLV tags. The remaining packed structs model firmware counters for TX/RX pdev, HW queues, scheduler, TQM, DE classification, self-generated frames, SRNG, SFM, MU/OFDMA, CCA, sounding, latency profiles, UL trigger/MUMIMO, FSE, TXBF, DL pager, PHY counters/resets/TPC, AST, puncturing, scheduling algorithms, TDMA, MLO, RTT, RX firmware, channel-switch, and related areas.

Control flow: This header has no executable control flow, but it defines the wire contracts consumed by `debugfs_htt_stats.c` and reached from `dp_htt.c` on `HTT_T2H_MSG_TYPE_EXT_STATS_CONF`. A userspace debugfs read/write request selects an `ath12k_dbg_htt_ext_stats_type`, optional config parameters, and a cookie. Firmware returns one or more `ath12k_htt_extd_stats_msg` segments. The handler uses `ATH12K_HTT_T2H_EXT_STATS_INFO1_LENGTH` to bound the segment payload and `ATH12K_HTT_T2H_EXT_STATS_INFO1_DONE` to complete `debug_htt_stats_req.htt_stats_rcvd`.

State and persistence: The header defines transient request state and firmware counter snapshots. No state is persisted beyond debugfs request lifetime, but the statistics describe persistent target-side counters until firmware reset or an explicit `ATH12K_DBG_HTT_EXT_STATS_RESET` request. All TLV structs are `__packed` and mostly little-endian, so parser code must convert fields before presentation.

Dependencies and integration points: Includes `dp_htt.h` for HTT transport definitions and shares cookies/config structures with `ath12k_dp_tx_htt_h2t_ext_stats_req()`. It depends on kernel bitfield helpers, flexible arrays, sk_buff declarations through included driver headers, debugfs support, and the firmware HTT ABI. The reset bitmap helpers and default config constants line up with firmware reset/config parameter expectations.

Risks: This file is firmware-ABI dense: a wrong enum value, field size, endian conversion expectation, array bound, or `__packed` layout will corrupt parsing or display misleading diagnostics. Many structs contain flexible arrays where the caller must validate HTT length before indexing. Several counters have large dimensional arrays, so output formatting can overflow smaller buffers if it ignores `ATH12K_HTT_STATS_BUF_SIZE`. Naming typos such as `DGB`/`FLASG`-style symbols are part of the local ABI surface and should not be silently "fixed" unless every user is updated. Debugfs-only stubbing means callers must not assume stats handling exists in non-debugfs builds.

Test signals: Build with and without `CONFIG_ATH12K_DEBUGFS`; request representative stats families from debugfs, including pdev TX/RX, TX rate, RX rate/ext, SRNG, TQM, scheduler, PHY, AST, RTT, MLO, and reset; inject multi-segment responses and verify done/cookie matching; fuzz/truncate TLV lengths; validate endian-decoded counters against firmware logs; verify large outputs do not exceed the 512 KiB buffer; and confirm non-debugfs builds compile with the inline handler.
