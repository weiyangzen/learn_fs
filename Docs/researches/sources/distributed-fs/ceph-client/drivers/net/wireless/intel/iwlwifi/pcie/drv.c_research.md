# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/drv.c

Purpose: Provides the top-level Linux PCI driver binding for Intel iwlwifi PCIe devices. It defines the supported PCI ID table, maps hardware IDs/subsystem/RF characteristics to detailed device configs and marketing names, probes/removes gen1/gen2 PCIe transports, handles sleep/resume/restore, exposes coredump forwarding, and registers/unregisters the `pci_driver`.

Important APIs/data: `iwl_hw_card_ids[]` is the PCI device-id match table used by the kernel module loader. `iwl_dev_info_table[]` is the richer device-info table used after hardware/RF discovery to select `struct iwl_cfg`, name, device/subdevice masks, RF type/id, CDB, bandwidth limit, and discrete/integrated matching. `iwl_pci_find_dev_info()` searches that table from the end so more specific or newer entries override earlier fallbacks. `iwl_pci_probe()`, `iwl_pci_remove()`, `_iwl_pci_resume()`, `iwl_pci_register_driver()`, and `iwl_pci_unregister_driver()` are the lifecycle entry points.

Table/macro behavior: `IWL_PCI_DEVICE()` stores a compile-time type-checked pointer to `struct iwl_mac_cfg` in `driver_data`. `IWL_DEV_INFO()` defaults device/subdevice to wildcard and subdevice mask to all 16 bits. `SUBDEV_MASKED()` includes compile-time checks for contiguous masks and stores low/high mask bit positions. Match macros represent RF type, RF id, CDB capability, bandwidth limit, and discrete/integrated form-factor constraints. Conditional compilation divides legacy DVM, MVM, and MLD devices.

Probe/control flow: `iwl_pci_probe()` repairs invalid BAR0 caused by possible runtime PM races, enables the PCI device with managed APIs, sets bus mastering, requests all BARs, maps BAR0, reads `CSR_HW_REV` directly before a transport exists, rejects `0xffffffff`, and delegates to `iwl_pci_gen1_2_probe()` with the selected `mac_cfg`, mapped base, and hardware revision. Remove fetches the transport from PCI driver data and delegates to `iwl_pcie_gen1_2_remove()`.

Power-management flow: Suspend intentionally does nothing because WoWLAN may need the NIC alive. Resume/restore clears PCI retry timeout, skips work when no opmode exists, detects whether the device was powered off using BZ+ scratch bits or older NIC-access probing, resets transport state and notifies opmode on restore/power loss, leaves WoWLAN-enabled devices to D3 resume if still enabled, otherwise reconfigures MSI-X mapping and reenables RF-kill interrupts under the transport mutex.

State and persistence: Static tables persist for module lifetime and are exported for KUnit where configured. Probe stores transport state through downstream gen1_2 setup, maps BAR memory with device-managed lifetime, and sets PCI master. Resume mutates PCI config byte `PCI_CFG_RETRY_TIMEOUT`, `trans->state`, NIC activation state, MSI-X masks, RF-kill interrupt state, and opmode power-loss notification state.

Dependencies/integration: Integrates with Linux PCI/module/PM/coredump APIs, ACPI firmware helpers indirectly through included headers, iwlwifi config objects declared elsewhere, CSR register definitions, PCIe gen1_2 transport probe/remove and resume helpers, opmode callbacks, RF-kill handling, NIC access helpers, and KUnit visibility macros.

Risks: The correctness of device identification depends on enormous manually maintained tables and reverse-order matching. Wildcard entries can shadow specific entries if ordering is wrong. Mask macros assume nonzero contiguous masks. Resume power-loss detection is family-specific and must avoid disrupting WoWLAN. Direct BAR0 reassignment is a workaround for runtime PM races but can fail early. `iwl_pci_dump()` assumes a valid transport/opmode path from coredump invocation.

Test signals: KUnit table tests for `iwl_pci_find_dev_info()` precedence, wildcard fallback, subdevice masks, RF/CDB/BW/discrete filters, and empty table behavior. Probe tests should cover BAR0 invalid reassignment, enable/request/iomap/read failures, `CSR_HW_REV=0xffffffff`, and delegation arguments. PM tests should cover BZ scratch powered-off/alive states, old NIC access success/failure, restore vs resume, WoWLAN status enabled, MSI-X reconfiguration, RF-kill interrupt rearm, and retry-timeout register writes.
