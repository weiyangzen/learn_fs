# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp.h

Purpose: Defines the common ath12k data-path object model, ring sizing, cookie-converter layout, monitor state, descriptor metadata, per-pdev data-path state, architecture operation callbacks, device statistics, inline dispatch wrappers, and exported DP setup APIs.

Important APIs and types: Core structs include `dp_srng`, `dp_tx_ring`, `dp_rxdma_ring`, `dp_rxdma_mon_ring`, `dp_link_desc_bank`, `ath12k_mon_data`, `ath12k_pdev_dp`, `ath12k_rx_desc_info`, `ath12k_tx_desc_info`, `ath12k_spt_info`, `ath12k_reo_q_addr_lut`, `ath12k_dp_arch_ops`, `ath12k_device_dp_stats`, and `ath12k_dp`. Important macros define ring sizes, RX/TX buffer sizes, WBM link descriptor cookies, RXDMA buffer cookies, TX descriptor ID bitfields, PPT/SPT cookie-converter geometry, REOQ LUT size, and bank/profile constants. Inline wrappers dispatch through `dp->ops` for service SRNG, TX bank config, REO commands, PN check setup, RX TID deletion, cache flush, link descriptor return, fragment cleanup, TID REO update, REO queue assignment, qref setup/reset, and TID delete handling. Public prototypes expose vdev TX attach, pdev alloc/free, peer setup/cleanup, SRNG/link-descriptor setup/cleanup, and RX/TX cookie lookup.

Control flow: The header's executable content is inline dispatch and pointer conversion. Most DP control flow is implemented by `dp.c` and architecture-specific RX/TX files through `ath12k_dp_arch_ops`. `ath12k_dp_to_pdev_dp()` requires an RCU read-side critical section and dereferences `dp->dp_pdevs[pdev_idx]`. `ath12k_dp_get_mac_addr()` reconstructs a MAC address from HTT low/high words.

State and persistence: `struct ath12k_dp` is the long-lived per-device DP root containing DMA rings, descriptor memory references, peer table/list state, REO command queues, TX bank profiles, RX/TX descriptor lists, monitor rings, optional REOQ LUTs, hardware params, device pointers, MLO group pointers, and aggregate device stats. `ath12k_pdev_dp` stores per-radio queue counters, ppdu stats state, monitor data, rx status, and RCU-published backpointers. None is durable across driver teardown, but most fields mirror hardware-visible DMA state and must remain coherent while firmware owns descriptors.

Dependencies and integration points: Includes `hw.h`, `dp_htt.h`, `dp_cmn.h`, and `linux/rhashtable.h`. It is a high-fanout header used by DP TX/RX, HTT, monitor, peer, debugfs, and mac80211 integration code. Its op table is the boundary between common DP code and hardware-generation-specific behavior.

Risks: Ring-size and descriptor-count macros pull from runtime profile params, so invalid profile values can under-size rings or descriptor tables. Cookie-converter constants define a hardware ABI; changing page counts, offsets, or masks can break TX/RX completion lookup. The comment says SPT pages are divided RX first and TX remaining, while macros place TX at offset 0 and RX after TX; readers must follow the macros, not the stale comment. Inline op wrappers do not guard `dp->ops` or individual function pointers. `ath12k_dp_to_pdev_dp()` warns without RCU and can return NULL during teardown. Packed/bitfield stats and counters need care on endian and atomicity.

Test signals: Compile all files that include this high-fanout header; boot/probe with different `profile_param->dp_params`; validate RX/TX descriptor counts are multiples of `ATH12K_MAX_SPT_ENTRIES`; exercise all architecture op wrappers; run RCU lockdep for `ath12k_dp_to_pdev_dp()`; check ring occupancy and low-threshold interrupts with configured sizes; and inspect debugfs/device stats for expected increment paths under traffic and error injection.
