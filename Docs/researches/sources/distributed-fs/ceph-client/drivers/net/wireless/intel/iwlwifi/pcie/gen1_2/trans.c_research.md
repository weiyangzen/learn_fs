# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/trans.c

Purpose: Implements the main PCIe transport layer for gen1/gen2 iwlwifi devices. It covers PCI transport allocation/free, hardware preparation/activation, classic firmware loading, APM and power-management sequencing, interrupt capability selection, MSI-X cause mapping, NIC access locking, suspend/resume handshakes, RF-kill handling, reset/removal orchestration, debugfs surfaces, firmware error dump collection, product reset ACPI integration, CRF/RF ID discovery, and PCI probe/remove glue.

Important APIs, types, and functions: Public transport entry points include `iwl_trans_pcie_sw_reset()`, `iwl_pcie_apm_config()`, `iwl_pcie_apm_stop_master()`, `iwl_pcie_prepare_card_hw()`, `iwl_pcie_apply_destination()`, `iwl_pcie_check_hw_rf_kill()`, `iwl_pcie_conf_msix_hw()`, `iwl_pcie_synchronize_irqs()`, `iwl_trans_pcie_start_fw()`, `iwl_trans_pcie_fw_alive()`, `iwl_trans_pcie_stop_device()`, `iwl_trans_pcie_rf_kill()`, D3 suspend/resume, `_iwl_trans_pcie_start_hw()`, `iwl_trans_pcie_start_hw()`, opmode enter/leave, CSR/PRPH read/write wrappers, PNVM/DRAM cleanup, `iwl_trans_pcie_free()`, reset functions, NIC access functions, memory/config reads, TX queue wait helpers, dump/debugfs functions, IMR copy helpers, `iwl_pci_gen1_2_probe()`, `iwl_pcie_gen1_2_remove()`, and `iwl_pcie_gen1_2_activate_nic()`. Core state is `struct iwl_trans`, `struct iwl_trans_pcie`, `struct iwl_trans_info`, `struct iwl_mac_cfg`, PCI/MSI-X entries, TX/RX queue arrays, DMA pools, wait queues, firmware monitor buffers, and status/reset bitfields.

Control flow: Probe calls `iwl_trans_pcie_alloc()` to allocate the transport, command pool, TSO per-CPU pages, byte-count pool, dummy NAPI netdev, locks, wait queues, RX allocator workqueue, DMA masks, IRQ mode, invalid command buffer, and debug TLV state. It then checks product reset ACPI state, prepares/activates the card enough to read CRF/RF IDs, maps RF ID if OTP is blank, resolves the device configuration, computes RX buffer count and PCIe link info, checks ME ownership, starts the higher driver with `iwl_drv_start()`, and registers debugfs. Hardware start (`_iwl_trans_pcie_start_hw()`) prepares ownership, clears persistence, software-resets, optionally force power-gates integrated 22000, runs APM init, configures MSI-X, enables RF-kill interrupts, marks opmode up, and reports RF-kill state. Classic firmware start (`iwl_trans_pcie_start_fw()`) prepares hardware, masks interrupts, checks RF-kill, initializes NIC/RX/TX, enables firmware-load interrupt, loads firmware sections through FH DMA, starts the CPU, and rechecks RF-kill. Stop disables interrupts/ICT, synchronizes IRQ/NAPI if not from IRQ, stops TX and RX DMA, powers down DMA clocks, releases MAC access requests, stops APM, retakes ownership, restores IVAR, clears status bits, and re-enables RF-kill interrupt.

State and persistence behavior: The file maintains transport runtime state across opmode operations: `is_down`, `opmode_down`, RF-kill flags, `csme_own`, `me_present`, `pm_support`, `ltr_enabled`, MSI-X masks, IRQ vector allocation, `sx_state`, `imr_status`, `ucode_write_complete`, TX/RX memory pools, firmware monitor DMA, PNVM/reduced-table DRAM regions, and debugfs monitor read cursors. D3 suspend uses persistence bits and VAUX power selection; resume reactivates NIC, reconfigures IVAR/ICT, restores power source, optionally resets TX/RX queues, and detects NEVO reset. Product reset state is mediated through ACPI DSM and scheduled removal work; once reset is scheduled, `STATUS_TRANS_DEAD` prevents further use.

Dependencies and integration points: This file is the central integration point among Linux PCI/MSI/MSI-X/ACPI/debugfs/DMA APIs, iwlwifi opmode callbacks, firmware image descriptors, TX/RX implementations, context-info code, MEI ownership detection, device configuration lookup, debug TLV/error-dump code, and platform reset mechanisms. It calls into `rx.c` for RX allocation/stop/NAPI sync/ICT, into non-gen2 and gen2 TX code for queue lifecycle, into firmware debug helpers for monitor destinations and dumps, and into opmode for NIC config, RF-kill, reset/error notifications, and driver start/stop.

Risks and edge cases: Hardware-family branching is dense: pre-8000 firmware loading differs from 8000 secured loading and gen2 context-info loading; BZ changes reset, MAC-access, SW-error, byte-count, and RF/CNV step handling. Register access must hold NIC access or `reg_lock` where required, and `iwl_trans_pcie_release_nic_access()` intentionally keeps bottom halves disabled across the access window. Firmware loading relies on FH_TX interrupts and wait queues; if interrupts are masked incorrectly the load times out. Stop and D3 paths must avoid accessing PRPH after APM stop and must synchronize interrupts before freeing NAPI/queues. Product reset work removes PCI devices asynchronously and may also remove BT sibling functions; module references and bus locks are essential. Debugfs monitor reads can go out of sync with firmware wrap counters and deliberately restart at buffer beginning.

Test signals: Probe/remove tests should cover MSI-X and MSI fallback, DMA mask fallback, blank OTP RF-ID mapping, ME-present product-reset downgrade, config lookup failure, WiFi7-without-IWLMLD rejection, and debugfs registration. Runtime tests should cover classic firmware load success/timeout, RF-kill during start and stop, D3 suspend/resume with and without reset, NEVO reset detection, queue flush timeout logging, firmware error dump generation with TXCMD/CSR/FH/RB/paging/monitor masks, IMR copy completion/error, and reset modes through debugfs. Diagnostic outputs include CSR dumps, host monitor dump on wake failure, interrupt/debugfs counters, firmware monitor data, and `iwl_trans_pcie_dump_regs()` on DMA/FH timeouts.
