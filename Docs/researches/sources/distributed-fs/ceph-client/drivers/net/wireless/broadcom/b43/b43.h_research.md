# sources/distributed-fs/ceph-client/drivers/net/wireless/broadcom/b43/b43.h

`b43.h` is the central private header for the Broadcom b43 driver. It defines the main register/shared-memory ABI, host flags, IRQ masks, firmware metadata, DMA/PIO top-level containers, key/QoS/statistics structures, and the driver’s two main runtime objects: `struct b43_wldev` for one 802.11 core and `struct b43_wl` for the mac80211-facing wireless device.

Important contents include MMIO constants for DMA, PIO, MAC, PHY, radio, GPIO, TX FIFO, WEP, RNG, and TSF registers; SHM offsets for firmware metadata, host flags, channel state, crypto tables, WME/QoS, beacon/probe templates, and rate maps; firmware structures (`b43_fw_header`, `b43_iv`, `b43_firmware_file`, `b43_firmware`); and device status constants accessed by `b43_status()` and `b43_set_status()`. Inline wrappers dispatch bus power, enable, read/write, block I/O, and mac80211 queue control through `struct b43_bus_dev`.

Runtime state is split between `b43_wldev` and `b43_wl`. `b43_wldev` stores bus device, firmware, PHY, DMA/PIO union, IRQ state, MAC suspend count, periodic/restart work, key table, and debug counters. `b43_wl` stores the active core, mac80211 hardware, global mutex, hardirq lock, interface/BSSID/MAC state, beacon state, QoS parameters, TX queues, firmware-load work, LEDs, optional HWRNG, and PIO scratch buffers.

Dependencies include Linux locking/interrupt/completion/HWRNG APIs, BCMA, SSB, mac80211, and other b43 private headers. Risks are hardware ABI mistakes in register/SHM constants, invalid bus vtable initialization, misuse of the DMA/PIO union, queue stop/wake mismatches between QoS and non-QoS modes, and incorrect status memory ordering. Test signals are compile coverage across optional configs, register access on BCMA/SSB, correct status transitions, firmware parsing, DMA/PIO mode separation, and queue behavior under load.
