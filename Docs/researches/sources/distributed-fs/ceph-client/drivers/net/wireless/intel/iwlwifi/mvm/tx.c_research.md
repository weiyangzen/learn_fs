# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/mvm/tx.c

Purpose: Implements the iwlwifi MVM mac80211 transmit path. It builds firmware TX commands for legacy and new TX APIs, chooses rates/antennas/queues, handles checksum and crypto offload metadata, segments TSO traffic into MPDUs or A-MSDUs, submits frames through the transport, consumes TX/BA firmware notifications, updates mac80211 TX status, and reclaims transport queue entries.

Important APIs/functions: `iwl_mvm_set_tx_cmd()` fills old `iwl_tx_cmd_v6_params` fields such as ACK policy, TID, PM timeout, RTS/protection, lifetime, station id, and offload assist. `iwl_mvm_set_tx_cmd_rate()` and helpers convert mac80211 rate control or injected rates into firmware `rate_n_flags`. `iwl_mvm_set_tx_params()` allocates an `iwl_device_tx_cmd` and writes either old v6 or new v9/v10-style TX command payloads. `iwl_mvm_tx_skb_non_sta()` sends management/control/non-station frames through aux/P2P/AP/monitor queues. `iwl_mvm_tx_skb_sta()` is the station data entry point and delegates to `iwl_mvm_tx_mpdu()` or `iwl_mvm_tx_tso()`. Completion and reclaim are handled by `iwl_mvm_rx_tx_cmd()`, `iwl_mvm_rx_ba_notif()`, `iwl_mvm_tx_reclaim()`, and flush helpers `iwl_mvm_flush_tx_path()`, `iwl_mvm_flush_sta_tids()`, and `iwl_mvm_flush_sta()`.

Key helper behavior: `iwl_mvm_tx_csum()` translates `CHECKSUM_PARTIAL`, IPv4/IPv6 TCP/UDP, A-MSDU, MAC-header padding, and IV placement into `offload_assist`, falling back to `skb_checksum_help()` for unsupported protocols or IPv6 extension headers. `iwl_mvm_set_tx_cmd_crypto()` inserts IV/PN state for CCMP/TKIP/WEP/GCMP/CCMP-256 paths and can use firmware key table slots for stronger ciphers. `iwl_mvm_get_tx_ant()` honors BT shared-antenna restrictions, station TX antenna state, and `mvm->mgmt_last_antenna_idx`. `iwl_mvm_probe_resp_set_noa()` appends P2P notice-of-absence data from RCU-protected probe-response state.

Control flow: outgoing non-station frames first classify the vif/offchannel mode to pick aux, P2P, AP/IBSS broadcast/multicast, or monitor queues, then build a TX command and call `iwl_trans_tx()`. Station frames copy the skb control block, reject invalid stations and forbidden probe/nullfunc cases, optionally segment GSO traffic, then for each MPDU take `mvmsta->lock`, derive TID and AMPDU state, update old-API sequence control, select `tid_data[tid].txq_id`, prepare status driver data, copy data to CSME when needed, and submit to transport. On success, per-TID sequence numbers and TCM packet counters advance; on failure the TX command is freed and the skb is consumed/dropped according to path.

Completion flow: single-frame TX responses reclaim up to the firmware SSN, free TX command allocations stored in `info->driver_data[1]`, translate firmware status to `IEEE80211_TX_STAT_ACK`, `TX_FILTERED`, or `AMPDU_NO_BACK`, update retry/rate/antenna/airtime fields, toggle management or pre-authorized station antennas on failures, handle time-sync frames specially, and notify mac80211. Aggregate TX responses cache rate/time/color in `mvmsta->tid_data`. BA notifications differ by API: new compressed BA notifications may reclaim multiple TFD entries across TIDs, while old notifications reclaim one queue/TID using `scd_flow` and `scd_ssn`.

State and persistence: Mutates per-station `tid_data` fields (`seq_number`, `next_reclaimed`, `state`, `rate_n_flags`, `tx_time`, `lq_color`, `txq_id`), queue timestamps and shared queue status in `mvm->queue_info`, TCM counters in `mvm->tcm`, sleep/EOSP counters, `mvm->mgmt_last_antenna_idx`, and skb status/control memory. Crypto PN state persists in `keyconf->tx_pn`. Probe-response NoA data is read under RCU. Firmware-facing persistent state includes transport queue write/read indexes and firmware TX/BA queues.

Dependencies/integration: Depends on mac80211 skb control blocks, station/vif/private structures from `mvm.h` and `sta.h`, transport APIs (`iwl_trans_alloc_tx_cmd`, `iwl_trans_tx`, `iwl_trans_reclaim`, `iwl_trans_free_tx_cmd`), rate conversion helpers in `utils.c`, firmware API constants for TX status and rate formats, BT coexistence, MEI/CSME mirroring, time-sync, debug trigger collection, and firmware capability checks for old/new TX APIs.

Risks: The file sits on hot TX paths, so locking and ownership mistakes are high impact. Risks include unsupported checksum offload silently changing skb contents via software fallback, PN/key race noted for table-based GCMP/CCMP-256 rekeying, old/new TX API divergence, invalid TID/queue ids, BA notifications arriving after station RCU invalidation, compressed BA code writing `mvmsta->tid_data[i].lq_color` using loop index instead of TID-shaped data, sequence/SSN wrap differences across generations, skb ownership on TSO partial failure, and queue-empty/AddBA state transitions depending on exact reclaim indexes.

Test signals: Build both `CONFIG_INET` and non-INET paths, old and new TX API firmware, station and non-station TX, injected fixed rates, 2.4 GHz no-CCK/no-shared-antenna cases, P2P probe response NoA insertion with small tailroom, CCMP/TKIP/WEP/GCMP encryption, TSO with and without A-MSDU in A-MPDU, invalid aggregation state warnings, single TX success/failure/filter/flush statuses, compressed and legacy BA notifications, station removal during BA, flush response validation, AddBA empty-queue continuation, EOSP/uAPSD handling, and debug trigger firing for BAR/TX failures.
