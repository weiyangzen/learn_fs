# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_hw.c

Purpose: Provides AR9003-family hardware attachment setup for ath9k. It selects revision-specific INI register tables, chooses EEPROM-driven TX/RX gain tables, configures PCIe power-save SerDes settings, enables hardware hang checks, detects MAC hangs, and attaches AR9003 PHY, calibration, MAC, and AIC operation sets.

Important APIs and functions: The external entry point is `ar9003_hw_attach_ops(struct ath_hw *ah)`. Important internal helpers are `ar9003_hw_init_mode_regs()`, `ar9003_hw_init_mode_gain_regs()`, `ar9003_tx_gain_table_apply()`, `ar9003_rx_gain_table_apply()`, the per-mode gain table selectors, `ar9003_hw_configpcipowersave()`, `ar9003_hw_init_hang_checks()`, `ath9k_hw_verify_hang()`, and `ar9003_hw_detect_mac_hang()`. The file sets private ops `init_mode_gain_regs`, `init_hang_checks`, `detect_mac_hang` and public op `config_pci_powersave`.

Control flow: During attach, `ar9003_hw_attach_ops()` first calls `ar9003_hw_init_mode_regs()` to bind `ath_hw` INI arrays based on silicon revision. The large revision cascade covers AR9330 1.1/1.2, AR9340, AR9485, AR9462 2.0/2.1, AR9550, QCA9531, QCA9561, AR9580, AR9565 1.0/1.1, and default AR9300 2.2. It selects MAC, baseband, radio, SOC, fast-clock, DFS, Japan CCK FIR, PCIe SerDes, additional crystal, and default gain tables. Later reset/init paths call `init_mode_gain_regs`, which reads EEPROM tx/rx gain indexes through `ar9003_hw_get_tx_gain_idx()` and `ar9003_hw_get_rx_gain_idx()` and swaps in the matching gain table. PCIe power-save writes selected SerDes rows, with an AR9462 ASPM L1 fix and restore/power-off distinction. Hang detection samples DMA debug registers for queues stuck in `WAIT_FRDONE` with complete state `0x1`, then re-reads up to `NUM_STATUS_READS` times to verify a stable signature.

State and persistence: Mutates many `ath_hw` INI array descriptors (`iniMac`, `iniBB`, `iniRadio`, `iniSOC`, `iniModesRxGain`, `iniModesTxGain`, fast-clock/DFS/additional/SerDes arrays), operation tables, `ah->config.hw_hang_checks`, `ah->bb_watchdog_timeout_ms`, `ah->WARegVal` application, and PCIe/SerDes registers. The state is runtime hardware configuration, reconstructed on attach/reset, not durable persistence.

Dependencies and integration points: Includes all AR9003-family initval headers for supported revisions plus `hw.h` and `ar9003_mac.h`. It depends on silicon revision macros, `INIT_INI_ARRAY`, EEPROM gain index helpers from `ar9003_eeprom.c`, register access macros, PCIe power-save config flags, DMA debug register definitions, and attach functions from PHY, calibration, MAC, and AIC modules. It is the bridge that binds this family into common ath9k hardware ops.

Risks: Revision ordering is critical; a broader `AR_SREV_*` branch before a narrower one would load wrong init tables. Missing `iniPcieSerdes` arrays for PCOEM chips are guarded only by warnings. Gain table indexes outside the mode array fall back to mode 0 for TX but RX uses a switch default; bad EEPROM gain fields can silently select conservative defaults. PCIe power-save writes raw init arrays and the AR9462 ASPM fix rewrites a magic config register. MAC hang detection relies on debug-state signatures and can false-positive if sampled during a legitimate long TX state, although repeated reads reduce that risk.

Test signals: Probe/reset each supported silicon revision and verify selected INI arrays, crystal-frequency additional arrays, fast-clock/DFS/Japan FIR tables, and PCIe SerDes arrays. Test EEPROM tx/rx gain modes 0-7 and fallback handling. Exercise PCIe power-save enter/restore with PLL power-save flags. For hang detection, inject or observe DMA debug states for stuck and non-stuck TX queues, including queues 0-5 from `AR_DMADBG_4` and 6-9 from `AR_DMADBG_5`.
