## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/phy.h

`phy.h` defines the PHY operation command group for thermal sensing, CT kill, CTDP power budget management, temperature reporting thresholds, and also enumerates command IDs for per-chain limit offset, PPAG, and AP TX power constraints whose payloads are defined in `power.h`. It includes Linux integer and bit helpers.

`enum iwl_phy_ops_subcmd_ids` maps PHY operations to firmware subcommands and notifications: DTS measurement trigger, CTDP config, temperature threshold reporting, per-chain limit offset, per-platform antenna gain, AP TX power constraints, CT kill notification, and wide DTS measurement notification. DTS measurement has both a compact `iwl_dts_measurement_cmd`, selecting temperature and/or voltage through `enum iwl_dts_measurement_flags`, and an extended `iwl_ext_dts_measurement_cmd`, selecting automatic/request/overwrite/direct modes, sensor, average factor, bit mode, and step duration. Notifications are versioned: `iwl_dts_measurement_notif_v1` reports temp/voltage, current `iwl_dts_measurement_notif` adds threshold index, and `iwl_dts_measurement_resp` returns command response temperature.

Thermal protection and budget management are represented by `ct_kill_notif`, `enum iwl_ctdp_cmd_operation`, `iwl_ctdp_cmd`, and `temp_report_ths_cmd`. `ct_kill_notif` reports temperature plus, in newer firmware, the triggering DTS bitmap and SW/HW scheme. CTDP commands start, stop, or report a current milliwatt budget. Temperature threshold configuration accepts up to `IWL_MAX_DTS_TRIPS` thresholds.

Control flow is firmware thermal management: host requests readings or threshold reporting, firmware sends DTS/CT-kill notifications, host may adjust power budgets or enter recovery paths, and related TX power/SAR/PPAG commands from `power.h` are sent under the same PHY command group. State is maintained by thermal and power-management layers: configured threshold list, current CTDP budget, latest sensor readings, and CT-kill mode. This header is just the wire format.

Risks include using the wrong DTS command structure for a firmware version, treating the threshold index as valid for v1 notifications, unit confusion between Celsius, milliwatts, and voltage units, exceeding `IWL_MAX_DTS_TRIPS`, and delayed CT-kill response. Test signals include thermal read command/response, threshold crossing notifications, CT kill simulation or firmware debug triggers, CTDP start/stop/report paths, and command-version negotiation around extended DTS support.
