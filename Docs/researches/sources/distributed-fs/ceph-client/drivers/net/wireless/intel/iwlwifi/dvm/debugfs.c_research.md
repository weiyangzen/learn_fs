# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/debugfs.c

Purpose: Implements DVM debugfs support. It creates `data`, `debug`, and `rf` debugfs directories and exposes runtime driver state, firmware SRAM/NVM snapshots, station/TID state, firmware statistics, calibration internals, power-save state, Bluetooth coexistence state, and multiple debug/control knobs for diagnostics and fault injection.

Important APIs and functions: `iwl_dbgfs_register()` is the public registration entry point and installs all files with `debugfs_create_file()`. Macro-generated file operations wrap read, write, and read/write handlers. Data readers include `iwl_dbgfs_sram_read/write()`, `iwl_dbgfs_wowlan_sram_read()`, `iwl_dbgfs_nvm_read()`, `iwl_dbgfs_stations_read()`, `iwl_dbgfs_channels_read()`, `iwl_dbgfs_status_read()`, `iwl_dbgfs_rx_handlers_read/write()`, `iwl_dbgfs_qos_read()`, `iwl_dbgfs_thermal_throttling_read()`, `iwl_dbgfs_temperature_read()`, `iwl_dbgfs_sleep_level_override_read/write()`, and `iwl_dbgfs_current_sleep_command_read()`. Statistics readers include `iwl_dbgfs_ucode_rx_stats_read()`, `iwl_dbgfs_ucode_tx_stats_read()`, `iwl_dbgfs_ucode_general_stats_read()`, `iwl_dbgfs_ucode_bt_stats_read()`, and `iwl_dbgfs_reply_tx_error_read()`. Calibration/RF/debug knobs include `iwl_dbgfs_sensitivity_read()`, `iwl_dbgfs_chain_noise_read()`, `iwl_dbgfs_clear_ucode_statistics_write()`, `iwl_dbgfs_ucode_tracing_read/write()`, `iwl_dbgfs_missed_beacon_read/write()`, `iwl_dbgfs_plcp_delta_read/write()`, `iwl_dbgfs_rf_reset_read/write()`, `iwl_dbgfs_txfifo_flush_write()`, `iwl_dbgfs_protection_mode_read/write()`, `iwl_dbgfs_echo_test_write()`, `iwl_dbgfs_calib_disabled_read/write()`, `iwl_dbgfs_fw_restart_write()`, and optional `iwl_dbgfs_log_event_read/write()`.

Control flow: Registration stores `priv->debugfs_dir`, creates the three subdirectories, then adds files with permissions matching read-only status views, writable knobs, and read/write controls. Read handlers generally allocate a formatted buffer, snapshot driver or firmware state, and return via `simple_read_from_buffer()`. SRAM reads require `iwl_is_ready_rf()`, default to the firmware data section when no offset/length is configured, handle unaligned byte extraction from `iwl_trans_read_mem32()`, and use a special single-word device format when the write side provides only an offset. Statistics readers require firmware alive state, lock `priv->statistics.lock`, format current/cumulative/delta/max values, and unlock before returning. Write handlers parse small numeric inputs from userspace and mutate debug settings or invoke driver actions such as statistics clear, power-mode update, RF reset, TX FIFO flush, echo command, event-log tracing timer toggles, calibration disable masks, or firmware restart fault injection.

State and persistence: The file reads and mutates many `struct iwl_priv` fields: SRAM debug offset/length, WoWLAN SRAM buffer, EEPROM blob/NVM data, station tables and TID aggregation state, RX handler counters, QoS data, thermal throttle state, `disable_ht40`, temperature, power debug override and sleep command, firmware statistics snapshots and accumulated/delta/max statistics, BT state, TX error counters, sensitivity and chain-noise calibration state, missed beacon and PLCP thresholds, RF reset counters, event-log tracing state and timer, RXON active flags, calibration disable mask, and global `iwlwifi_mod_params.fw_restart` during firmware restart injection. Most changes are runtime-only debug state; some writes immediately command firmware or alter driver behavior until reset or later debug writes.

Dependencies and integration points: Depends on Linux debugfs, user-copy helpers, memory allocation, mac80211 channel structures, iwl transport memory/register access, command submission, DVM status helpers from `agn.h`, firmware ABI structures from `commands.h`, calibration state from `dev.h`, power management, RF reset, TX FIFO flush, event-log dump support under `CONFIG_IWLWIFI_DEBUG`, and optional advanced Bluetooth coexistence. The symlink to mac80211 debugfs depends on `priv->mac80211_registered` and `hw->wiphy->debugfsdir`.

Risks: Debugfs write handlers are privileged but can change live behavior: disabling HT40, overriding sleep level, clearing statistics, forcing RF reset, flushing TX FIFOs, changing aggregation protection, disabling calibrations, triggering echo commands, and injecting firmware restart. Several handlers parse tiny fixed buffers, so input is intentionally narrow but malformed input returns `-EFAULT` or `-EINVAL` inconsistently. SRAM reads touch device memory and depend on readiness and correct offset/length; bad offsets can produce misleading diagnostics or transport failures. Statistics snapshots may already be stale by design. Some readers allocate buffers sized by current station/NVM/stat structures and must avoid overflow by consistent `scnprintf()` use. The mac80211 symlink is explicitly not robustly removed by this file and relies on broader teardown ordering.

Test signals: Build with `CONFIG_IWLWIFI_DEBUGFS` and with/without `CONFIG_IWLWIFI_DEBUG`; verify directory and file permissions under `data`, `debug`, and `rf`; read SRAM default/custom/single-word forms; read WoWLAN SRAM absent/present; dump NVM with valid and invalid lengths; inspect station/TID, channel, status, QoS, thermal, temperature, power-save, RXON, sensitivity, chain-noise, BT, and TX-error outputs; reset RX handler counters; reject HT40 changes while associated; apply sleep override and confirm `iwl_power_update_mode()`; clear statistics; toggle uCode tracing timer; set missed-beacon and PLCP thresholds inside/outside ranges; force RF reset; flush TX FIFO with and without RF-kill; switch protection mode; run echo test; read/write event log in debug builds; set calibration disable masks; trigger firmware restart injection and validate reset recovery.
