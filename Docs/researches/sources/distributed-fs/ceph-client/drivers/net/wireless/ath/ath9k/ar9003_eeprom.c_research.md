# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar9003_eeprom.c

Purpose: Implements the AR9300/AR9003 EEPROM backend for ath9k. It owns compiled-in EEPROM templates, restore/decompression from flash/EEPROM/OTP, EEPROM parameter accessors, board-value programming, regulatory target power calculation, open-loop calibration, PAPRD power adjustment, debugfs EEPROM dumping, and the `eep_ar9300_ops` vtable consumed by common ath9k hardware code.

Important APIs and functions: The exported integration surface is `const struct eeprom_ops eep_ar9300_ops`, with callbacks for `check_eeprom`, `get_eeprom`, `fill_eeprom`, `dump_eeprom`, version/revision, `set_board_values`, `set_addac`, `set_txpower`, `get_spur_channel`, and `get_eepmisc`. Externally visible helpers include `ar9003_hw_ant_ctrl_common_get()`, `ar9003_hw_ant_ctrl_common_2_get()`, `ar9003_get_spur_chan_ptr()`, `ar9003_get_paprd_rate_mask_ht20()`, `ar9003_get_paprd_rate_mask_ht40()`, `ar9003_get_paprd_scale_factor()`, `ar9003_hw_internal_regulator_apply()`, `ar9003_hw_tx_power_regwrite()`, `ar9003_hw_get_tx_gain_idx()`, and `ar9003_hw_get_rx_gain_idx()`. Major internal paths include `ar9300_eeprom_restore_internal()`, `ar9300_compress_decision()`, `ath9k_hw_ar9300_set_board_values()`, `ath9k_hw_ar9300_set_txpower()`, `ar9003_hw_set_power_per_rate_table()`, and `ar9003_hw_calibration_apply()`.

Control flow: EEPROM fill starts in `ath9k_hw_ar9300_fill_eeprom()`, which calls `ar9300_eeprom_restore_internal()` into `ah->eeprom.ar9300_eep`. If flash-backed storage is selected, the restore path reads the raw structure and accepts it when `txrxMask` is neither zero nor all ones. Otherwise it seeds the destination with `ar9300_default`, probes EEPROM base addresses and then OTP base addresses, walks compressed blocks backward, validates each header and checksum, and either copies uncompressed payloads or applies block deltas against a referenced compiled-in template. `ath9k_hw_ar9300_get_eeprom()` maps common `enum eeprom_param` queries to MAC address, regulatory domain, op flags, masks, PAPRD, antenna diversity, and antenna gain fields. Board-value setup is channel driven: `ath9k_hw_ar9300_set_board_values()` selects 2 GHz or 5 GHz modal data, then programs XPA timing/bias, antenna switch tables, drive strength, XLNA bias, attenuation, quick-drop, internal regulator, tuning capacitors, min CCA power thresholds, TX end-to-XPA timing, thermometer, and OTP therm calibration. TX power setup first interpolates target powers from EEPROM frequency piers, applies CTL/regulatory/MCI limits per rate class, adjusts PAPRD rate masks and scale, updates regulatory max power, writes PHY TX power registers, applies calibration, stores PAPRD target power, sets self-generated frame power, and optionally enables TPC tables.

State and persistence: Persistent source data comes from device EEPROM, OTP, or flash and is restored into `ah->eeprom.ar9300_eep`; compiled-in templates (`ar9300_default`, `ar9300_x112`, `ar9300_h116`, `ar9300_h112`, `ar9300_x113`) are fallback/reference state for compressed deltas. Runtime hardware state is written through register macros for PHY, RTC, PMU, antenna, TPC, PAPRD, and power tables. Driver state mutations include `ah->nf_2g`/`ah->nf_5g` calibration and power arrays, `ah->paprd_target_power`, `ah->paprd_ratemask`, `ah->paprd_ratemask_ht40`, `ah->paprd_table_write_done`-dependent power choices, and `ath_regulatory(ah)->max_power_level`. No durable state is written by this file, but the restored EEPROM image and register programming must remain coherent across channel resets.

Dependencies and integration points: Depends on `hw.h`, `ar9003_phy.h`, `ar9003_eeprom.h`, `ar9003_mci.h`, unaligned access helpers, ath9k register macros (`REG_READ`, `REG_WRITE`, `REG_RMW_FIELD`), EEPROM/NVRAM access (`ath9k_hw_nvram_read`, `ath9k_hw_use_flash`), OTP registers, regulatory helpers (`ath9k_hw_get_scaled_power`, `ath9k_hw_update_regulatory_maxpower`), channel helpers, MCI coexistence power limits, PAPRD predicates, and debugfs print macros. `ar9003_hw.c` uses the tx/rx gain index accessors to choose init tables, PHY calibration code consumes spur and PAPRD getters, and common ath9k init/reset code calls the EEPROM ops.

Risks: The compressed EEPROM parser trusts compact hardware blobs; header length, checksum, and bounds checks are critical because bad `length` or `reference` values can select wrong templates or write outside expected restore regions. Several callbacks are stubs or placeholders (`ath9k_hw_ar9300_check_eeprom()` always succeeds, `ath9k_hw_ar9300_get_eeprom_rev()` returns zero, `ath9k_hw_ar9300_get_spur_channel()` returns no spur, `set_addac` is empty), so callers must not assume full validation or spur filtering from this layer. Power-limit logic combines EEPROM targets, CTL edges, regulatory scaled power, MCI caps, PAPRD adjustments, and TPC; off-by-one rate indexes or wrong 2 GHz/5 GHz center frequencies can violate regulatory constraints. Register programming is silicon-revision-specific and many paths branch on `AR_SREV_*`, making unsupported revision combinations risky. Some PMU/internal regulator waits loop until fields change and can delay if hardware does not settle.

Test signals: Exercise EEPROM restore from flash, EEPROM, and OTP; compressed-none and compressed-block records; bad headers, bad checksums, invalid template references, and length boundaries including AR9485's shorter data length. Validate `get_eeprom` parameters, tx/rx gain index extraction, antenna switch programming for 1/2/3-chain and BT antenna diversity configurations, internal regulator paths across AR9330/AR9485/AR9462/AR9550/AR9565/QCA9561, and tuning/quick-drop/min-CCA feature bits. For TX power, test 2 GHz CCK/OFDM/HT20/HT40 and 5 GHz OFDM/HT20/HT40 channels, CTL exact and inband edge matches, `SD_NO_CTL`, MCI caps, PAPRD enabled/disabled, TPC enabled/disabled, and calibrated noise floor updates.
