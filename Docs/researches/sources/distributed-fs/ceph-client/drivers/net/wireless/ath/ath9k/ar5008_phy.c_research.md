# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath9k/ar5008_phy.c

Purpose: Implements the shared PHY operations for AR5008, AR9001, and AR9002-class ath9k hardware. It programs channel frequency synthesis, external radio banks, spur mitigation, INI register application, baseband and RF mode setup, chain masks, ANI controls, noise-floor extraction, radar configuration, PLL selection, and per-rate transmit-power cache layout. The file is the pre-AR9003 PHY vtable provider used by `ar9002_hw_attach_ops()`.

Important APIs and functions: `ar5008_hw_attach_phy_ops()` is the public attachment point and fills `struct ath_hw_private_ops` callbacks including `rf_set_freq`, `spur_mitigate_freq`, `set_rf_regs`, `set_channel_regs`, `init_bb`, `process_ini`, `set_rfmode`, `mark_phy_inactive`, `set_delta_slope`, `rfbus_req`, `rfbus_done`, `restore_chainmask`, `do_getnf`, `set_radar_params`, `ani_control`, `ani_cache_ini_regs`, and `compute_pll_control`. `ar5008_hw_set_channel()` converts 2 GHz and 5 GHz channel centers into synthesizer bit fields and handles the 2484 MHz Japan CCK bit. `ar5008_hw_process_ini()` applies mode, common, BB/RF gain, fast-clock, ADDAC, gain, channel, power, and RF-register tables during reset/channel setup. `ar5008_hw_set_rf_regs()` prepares and writes external radio banks for pre-AR9280 devices, including EEPROM OB/DB swizzling in `analogBank6Data`. `ar5008_hw_spur_mitigate()` and `ar5008_hw_cmn_spur_mitigate()` program pilot, channel, Viterbi, and spur masks from EEPROM spur entries. `ar5008_hw_ani_control_new()` implements OFDM weak signal, firstep, and spur immunity tuning. `ar5008_hw_init_rate_txpower()` maps EEPROM-derived rate power entries into `ah->tx_power`.

Control flow: Attach time calls `ar5008_hw_rf_alloc_ext_banks()` for legacy external radios, installs the callback table, selects the AR9160 PLL calculator for AR9100/AR9160-like chips, sets default NF bounds, initializes radar defaults, and copies the CCA NF register list. Reset/channel bring-up flows through `process_ini`: choose `modesIndex` and `freqIndex` from band and HT width, expose the external radio bus, allow EEPROM-specific ADDAC customization, write mode arrays with analog-shift delays where needed, write RX/TX gain arrays for supported silicon, write common arrays, optional BB/RF gain and fast-clock arrays, apply revision workarounds, set channel registers, chain masks, open-loop power-control state, TX power, and finally RF bank programming. Frequency tuning calls `rf_set_freq`, which calculates reversed-bit synthesizer fields, forces the AR5416 2 GHz bias workaround, writes `AR_PHY(0x37)`, and updates `ah->curchan`. ANI and calibration consumers later call the installed callbacks to update thresholds, read NF registers, or restore chain masks after special flows.

State and persistence: The file mutates hardware registers extensively and also updates persistent driver-side state in `struct ath_hw`: `ah->analogBank6Data` caches mutable bank-6 contents for external radios; `ah->curchan` records the active channel; `ah->ani.iniDef` snapshots post-INI ANI defaults; `ah->ani` levels track current noise-immunity state; `ah->tx_power[]` holds the per-rate power table; `ah->nf_2g`, `ah->nf_5g`, `ah->nf_regs`, and `ah->radar_conf` retain device defaults. Register writes persist until reset, channel reconfiguration, power-state transition, or a later calibration/ANI operation overwrites them. No filesystem or disk state is touched.

Dependencies and integration points: Includes `hw.h`, `hw-ops.h`, `../regd.h`, and `ar9002_phy.h`; it relies on register macros, silicon revision predicates, EEPROM callbacks, INI array helpers, and common ath9k helpers such as `ath9k_hw_get_channel_centers()`, `ath9k_hw_synth_delay()`, `ath9k_hw_wait()`, `ath9k_hw_set11nmac2040()`, `ath9k_olc_init()`, and `ath9k_hw_apply_txpower()`. `ar9002_hw.c` calls `ar5008_hw_attach_phy_ops()`. Reset, channel change, ANI, DFS/radar, TX power, and NF calibration paths consume the callbacks through `ath9k_hw_private_ops()`. The RF-bank tables are paired with initval data selected in `ar9002_hw_init_mode_regs()`.

Risks: This file is dominated by hardware ABI constants and timing-sensitive register order. Incorrect `modesIndex` or `freqIndex` selection can program the wrong band/width column. RF-bank swizzling depends on exact bit offsets and is only valid for legacy external radios; using it on single-chip devices or with a bad bank allocation would corrupt RF programming. Spur mitigation uses dense mask construction with fixed array indexes, so off-by-one errors alter pilot/channel/Viterbi masks. `ar5008_hw_force_bias()` intentionally `BUG_ON`s if called on AR9280+ despite being in a common path, making revision guards critical. Chainmask setup has special fallthrough behavior for 5416 1.0 and alternate 0x5 masks. ANI default restoration depends on caching INI values after full reset. Many writes are buffered, so missing flushes or added reads in the wrong place can change hardware sequencing.

Test signals: Build coverage should include ath9k with all referenced revision predicates and no sparse/compiler warnings around fallthrough or array bounds. Runtime signals include successful probe/reset on AR5416/AR9100/AR9160 and AR9280+ families, valid tuning on 2 GHz, 5 GHz, HT20, HT40, half-rate, and quarter-rate channels, correct handling of 2484 MHz, RF bus grant acquisition, no `ar5416SetRfRegs failed` logs, stable RX/TX after chainmask changes, expected noise-floor readings for HT20 and HT40, ANI debug counters changing under noisy conditions, spur EEPROM entries producing register mask writes without RX regressions, DFS radar registers enabled/disabled as configured, and rate TX power matching EEPROM-derived rate arrays.
