# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtw88/rtw8821c.c

`rtw8821c.c` implements the RTL8821C rtw88 chip profile. It handles HCI-specific efuse parsing, MAC and PHY initialization, channel/bandwidth programming, RX PHY status parsing, TX power index programming, false-alarm counters, firmware-driven IQK, coexistence, thermal power tracking, beamformee support, LED control, power sequences, interface PHY parameters, page/RQPN tables, RFE definitions, and exported `rtw8821c_hw_spec`.

`rtw8821c_ops` wires local callbacks into the core. Bring-up parses `struct rtw8821c_efuse`, derives RFE/BTG/package data, initializes MAC protocol/EDCA/WMAC registers, enables BB/RF, loads tables, applies crystal cap, records baseline channel filter parameters, initializes power tracking, and sets beamforming PHY state. Channel changes program BB band and bandwidth, regulatory SRRC CCK filter behavior, MAC channel state, RF register 0x18, RF front-end switch state, and RX DFIR.

RX status parses page 0 for CCK LNA/VGA power and page 1 for OFDM/HT/VHT reports. IQK is firmware-driven: `rtw_fw_do_iqk()` runs, the driver polls `RF_DTXLOK` for `0xabcde`, clears it, and logs reload/fail-mask bits. Power tracking uses a trigger/read thermal-meter sequence, EWMA thermal state, TXAGC/swing limits, and optional IQK reruns.

State lives in efuse, `hal->pkg_type`, `hal->rfe_btg`, `hal->ch_param[]`, `dm_info`, coexistence RFE data, and beamforming structures; register writes persist in hardware. Dependencies include rtw88 core, firmware, PHY, MAC, BF, regulatory, coexistence, and `rtw8821c_table.h`. Risks include HCI-specific efuse layout mistakes, a suspicious `.n_usb3_para = ARRAY_SIZE(usb2_param_8821c)`, up to 6 seconds of IQK polling, complex coexistence RFE branching, and many magic register values. Test PCIe/USB/SDIO efuse parsing, firmware load, all bands/bandwidths, SRRC channel behavior, RX status decoding, IQK logs, thermal tracking, CCK PD, beamforming, coexistence RFE variants, and power sequencing.
