# sources/distributed-fs/ceph-client/drivers/net/wireless/broadcom/brcm80211/brcmsmac/mac80211_if.c

## Purpose
`mac80211_if.c` is the Linux-facing glue for the Broadcom `brcmsmac` soft-MAC driver. It registers the BCMA driver, allocates/registers `ieee80211_hw`, exposes `ieee80211_ops`, loads firmware, initializes supported bands/rates/capabilities, bridges mac80211 callbacks into the common `brcms_c_*` core, manages IRQ/tasklet flow, wraps timers, handles rfkill, and performs module/probe/remove lifecycle work.

## Important APIs, Types, and Functions
- Registration: `brcms_coreid_table`, `brcms_bcma_driver`, `brcms_module_init()`, `brcms_module_exit()`, and scheduled `brcms_driver_work`.
- Capability tables: `brcms_2ghz_chantable`, `brcms_5ghz_nphy_chantable`, `legacy_ratetable`, `brcms_band_2GHz_nphy_template`, `brcms_band_5GHz_nphy_template`, `ieee_hw_rate_init()`, and `ieee_hw_init()`.
- Attach/remove: `brcms_bcma_probe()`, `brcms_attach()`, `brcms_remove()`, and `brcms_free()`.
- Firmware helpers: `brcms_request_fw()`, `brcms_release_fw()`, `brcms_ucode_init_buf()`, `brcms_ucode_init_uint()`, `brcms_ucode_free_buf()`, and `brcms_check_firmwares()`.
- mac80211 ops: TX/start/stop, add/remove interface, config, BSS changes, filters, scan start/complete, WME params, STA add, AMPDU action, rfkill poll, flush, TSF get/set, and TIM update.
- Interrupt path: `brcms_isr()` and `brcms_dpc()`.
- Common callbacks: `brcms_init()`, `brcms_reset()`, `brcms_fatal_error()`, `brcms_intrson()`, `brcms_intrsoff()`, `brcms_intrsrestore()`, `brcms_up()`, `brcms_down()`, `brcms_txflowcontrol()`, and `brcms_rfkill_set_hw_state()`.
- Timer wrappers: `brcms_init_timer()`, `brcms_add_timer()`, `brcms_del_timer()`, `brcms_free_timer()`, and private `_brcms_timer()`.

## Control Flow
Module init initializes debugfs and schedules BCMA driver registration. Probe validates the BCMA 802.11 core, allocates `ieee80211_hw` with `struct brcms_info` private data, stores drvdata, and calls `brcms_attach()`. Attach initializes locks, tasklet, waitqueue, common driver state, IRQ, hardware capabilities, regulatory data, permanent MAC address, mac80211 registration, and debugfs. Probe then attempts optional LED registration.

mac80211 start lazily loads firmware if needed, wakes queues, checks rfkill, mutes TX until an interface is added, calls `brcms_up()` when unblocked, and enables PCI power save. Stop stops queues, validates chip identity, disables PCI power save, and calls `brcms_down()`. TX callbacks take `wl->lock`, drop packets while down, and otherwise call `brcms_c_sendpkt_mac80211()`.

Configuration callbacks translate mac80211 state into common-driver calls for listen interval, TX power, channel, retry limits, association, slot timing, HT protection, basic rates, beacon interval, BSSID, SSID, beacon/probe response templates, filters, scan state, WME parameters, TSF, and TIM. Some features are logged as not implemented. The interrupt path uses `brcms_isr()` for first-level handling and `brcms_dpc()` for deferred common processing, interrupt re-enable, rescheduling, and TX flush wakeups. Remove unregisters LED/rfkill/mac80211 state, frees common resources, clears drvdata, and frees hardware.

## State and Persistence
`struct brcms_info` is the main runtime object and stores public/common pointers, IRQ, locks, waitqueue, callback count, timer list, tasklet, reschedule flag, firmware metadata, wiphy, ucode, mute state, and LED state. `n_adapters_found` and `brcms_driver_work` are global runtime state. Firmware blobs are requested from userspace storage, copied into ucode data, and released; copied ucode persists until detach. There is no driver-owned on-disk persistence.

## Dependencies and Integration Points
The file integrates with BCMA, mac80211, cfg80211/wiphy, firmware loader, IRQ APIs, tasklets, delayed work, wait queues, debugfs, rfkill, module init/exit, optional LED support, and local brcmsmac common code (`brcms_c_*`, `pub.h`, `main.h`, `scb.h`, `channel.h`, `ucode_loader.h`, `debug.h`, `led.h`). It also coordinates TX/RX, AMPDU, regulatory hints, and firmware section loading.

## Risks and Edge Cases
- BCMA driver registration is asynchronous from module init.
- LED registration failure is ignored by probe.
- Locking is subtle: `wl->lock` and `isr_lock` are used across mac80211, ISR, tasklet, timer, rfkill, and down paths; some helpers intentionally drop and reacquire locks.
- `brcms_ops_start()` enables PCI power save even when bring-up returns an error.
- Suspend only clears `hw_up`; resume is a no-op.
- Several mac80211 features are logged as unimplemented.
- Firmware parsing depends on header/bin consistency and little-endian fields.
- Timer callback accounting must stay balanced for down/free waits.
- STA/AMPDU handling uses a primary SCB/global AMPDU pointer, limiting multi-station behavior.
