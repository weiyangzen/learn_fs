# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/ipw2x00/ipw2100.h

## Purpose
`ipw2100.h` is the private driver contract for the Intel PRO/Wireless 2100 PCI 802.11b driver. It defines the firmware-visible command, buffer-descriptor, status, notification, ordinal, register, interrupt, and firmware-image formats used by `ipw2100.c`, plus the driver's central `struct ipw2100_priv` runtime state.

This header is not a generic wireless API. It is the hardware/firmware ABI for queue DMA, host commands, status notifications, firmware download, RF-kill handling, association/security configuration, and legacy Wireless Extensions/libipw integration.

## Important APIs, Types, And Functions
- Debug categories and macros (`IPW_DL_*`, `IPW_DEBUG_*`) gate per-subsystem logging for command, firmware, scan, association, TX/RX, interrupt, WEP, RF-kill, ioctl, state, and low-level I/O paths.
- DMA descriptor formats include `struct ipw2100_bd`, `struct bd_status`, `struct ipw2100_bd_queue`, and `struct ipw2100_status_queue`. These back the 256-entry TX/RX rings and the per-RX status sideband queue shared with firmware.
- Firmware command/data wire formats include `struct ipw2100_cmd_header`, `struct ipw2100_data_header`, and `struct host_command`. `ipw2100.c` fills these before pushing descriptors to firmware.
- Packet wrappers `struct ipw2100_tx_packet` and `struct ipw2100_rx_packet` connect list management, DMA addresses, libipw TX buffers, SKBs, and ring indexes.
- `struct ipw2100_priv` is the main per-device object. It stores MMIO base, PCI/net/libipw pointers, status/config/capability bitmasks, association context, queues, firmware ordinal metadata, delayed works, tasklet, locks, waitqueue, interrupt counters, RF-kill/hang flags, firmware error history, and sysfs/proc-facing state.
- Host command IDs (`HOST_COMPLETE`, `SYSTEM_CONFIG`, `SSID`, `PORT_TYPE`, `WEP_KEY_INFO`, `BROADCAST_SCAN`, `CARD_DISABLE`, `GROUP_ORDINALS`, `SET_WPA_IE`, `HOST_PRE_POWER_DOWN`, etc.) are the firmware control API used for setup, scanning, association, power, security, and statistics.
- Hardware register and SRAM offsets (`IPW_REG_*`, `IPW_MEM_HOST_SHARED_*`, `IPW_HOST_FW_SHARED_AREA*`) define where the driver publishes descriptor ring bases, indexes, status queues, ordinal tables, interrupts, GPIO, reset, firmware version, and indirect memory access.
- Status/config/state flags (`STATUS_*`, `IPW_STATE_*`, `CFG_*`, `CAP_*`) encode driver lifecycle, RF-kill state, scan/reset/security work, firmware state notifications, association constraints, and privacy/auth capabilities.
- Ordinal enums (`ORDINALTABLE1`, `ORDINALTABLE2`) name firmware statistics and variable-length records such as MAC address, BSSID, SSID, country data, firmware version/date, station tables, RSSI, RTC time, retry/error counters, and RF-switch state.
- Firmware loading types (`struct ipw2100_fw_chunk`, `struct ipw2100_fw_chunk_set`, `struct ipw2100_fw`) describe hotplug firmware and microcode payloads consumed by the implementation's firmware download routines.

## Control Flow
Probe allocates `struct ipw2100_priv`, initializes defaults, locks, work items, packet lists, and tasklet state, then allocates TX/RX/status queues. Queue initialization writes the coherent DMA addresses and read/write indexes into the shared SRAM offsets declared here.

Startup downloads firmware/microcode, initializes the BD/status rings, releases firmware reset, waits for `IPW2100_INTA_FW_INIT_DONE`, marks `STATUS_RUNNING`, then sends host commands such as `HOST_COMPLETE`, scan options, and broadcast scan. Adapter setup batches firmware commands for MAC address, port type, system config, rates, power mode, RTS threshold, mandatory BSSID, ESSID, and security.

TX control flow uses `host_command` input, copies it into an `ipw2100_cmd_header`, places a command packet on `msg_pend_list`, emits a one-BD command descriptor, advances `IPW_MEM_HOST_SHARED_TX_QUEUE_WRITE_INDEX`, and waits on `wait_command_queue` until RX command status clears `STATUS_CMD_ACTIVE`. Data TX builds an `ipw2100_data_header`, maps payload fragments into TBDs, enforces descriptor spare space, appends to `fw_pend_list`, and relies on firmware advancing the TX read index before completion cleanup.

RX control flow reads firmware RX indexes, synchronizes the DMA buffer, checks the `ipw2100_status` type mask, and dispatches command completion, status-change notifications, 802.11 management frames, data frames, or monitor-mode frames. Processed RX slots are cleared and the host write index is moved back to firmware.

Interrupt flow is keyed by `IPW2100_INTA_*` bits: TX/RX transfer/completion, event/status changes, firmware init, command-done, fatal error, and parity error. The tasklet path uses these bits to drive queue processing, status changes, resets, and wakeups.

Shutdown and reset paths use reset/GPIO/control constants to disable the card, issue PHY-off or pre-power-down commands when possible, stop master, assert software reset, clear running/enabled/associated state, cancel delayed works, and recycle queues.

## State And Persistence
Most state is volatile kernel memory in `struct ipw2100_priv`: association identity, ESSID/BSSID/channel, mode, TX rates/power, retry/RTS/fragment thresholds, status/config flags, error history, counters, and DMA queue bookkeeping. Firmware state is also mirrored in hardware SRAM registers and ordinal tables.

Persistent device identity and capabilities are read from firmware/EEPROM-backed ordinals, including adapter MAC address, EEPROM version/SKU/channel masks, firmware version strings, country information, and RF-switch state. Firmware images are requested from userspace firmware storage at runtime and are not embedded in this header.

DMA-coherent BD/status rings and command/data headers persist for the lifetime of the device instance and are reinitialized across resets. RX SKBs and TX libipw buffers are transient and must be unmapped or freed when ring ownership returns to the driver.

Delayed work items persist scheduled recovery behavior: `reset_work`, `security_work`, `wx_event_work`, `hang_check`, `rf_kill`, and `scan_event`. `reset_backoff`, `last_rtc`, `fatal_errors`, `hangs`, and `suspend_time` provide recovery history and health signals across runtime events.

## Dependencies And Integration Points
- Linux kernel subsystems: PCI, DMA mapping/coherent allocation, netdevice, Wireless Extensions (`iw_handler`), workqueues, tasklets, waitqueues, mutexes, spinlocks, firmware loader, sysfs/proc, SKBs, and MMIO helpers.
- Local wireless stack: `libipw.h` supplies 802.11 frame structs, TX buffer abstraction, management/data RX handling, security state, and `alloc_libipw`/`libipw_priv` ownership.
- Firmware ABI: host commands, ordinals, descriptor rings, status queue entries, interrupt bits, and shared memory addresses must match the IPW2100 firmware's expectations exactly.
- Optional monitor mode: `CONFIG_IPW2100_MONITOR` adds radiotap integration, monitor port type, CRC checking configuration, and monitor firmware selection.
- Security integration: WEP/TKIP/CCMP capability constants, WEP command formats, WPA association IE framing, auth mode flags, and libipw security callbacks bridge user configuration to firmware commands.
- User-visible integration: netdev ops, ethtool info/link status, Wireless Extensions handlers, RF-kill/sysfs/proc diagnostics, scan/association events, and module firmware declarations all depend on structures and constants from this header.

## Risks And Edge Cases
- The descriptor and command structs are firmware ABI and marked packed. Field size, alignment, endianness, bitfield layout, and descriptor count changes can break DMA or firmware parsing.
- Ring index arithmetic is fragile. TX and RX require spare descriptors, wraparound handling, and exact coordination with firmware read/write indexes. Off-by-one errors can leak buffers, corrupt packets, or wedge firmware.
- `host_command_parameters` is a fixed 100-u32 region. Commands that copy WPA IEs, WEP keys, SSIDs, or structured parameters must obey the computed limits such as `IPW_MAX_VAR_IE_LEN`.
- Status flags in `priv->status` are shared across interrupt/tasklet/workqueue/ioctl/netdev paths. Locking mistakes around `low_lock`, `action_mutex`, `adapter_mutex`, or command wait wakeups can produce stale association state, double command submission, missed resets, or queue races.
- Firmware fatal/parity errors and command timeouts feed the reset path. Incorrect handling can leave `STATUS_CMD_ACTIVE`, `STATUS_RESET_PENDING`, or RF-kill bits stuck and block future commands.
- RX status type and frame-size trust boundaries matter. Corrupt descriptors, CRC-error monitor frames, short 802.11 headers, or firmware memory corruption need validation before handing data to libipw.
- Power and RF-kill transitions combine firmware commands, GPIO bits, reset registers, and delayed polling. Hardware switch changes during startup/shutdown can race adapter enablement and association events.
- Legacy Wireless Extensions, libipw security semantics, and old firmware formats constrain behavior; modern cfg80211/mac80211 assumptions should not be projected onto this header.

## Test Signals
- Build coverage should compile `ipw2100.c` with and without `CONFIG_IPW2100_DEBUG`, `CONFIG_PM`, and `CONFIG_IPW2100_MONITOR`; packed structs, conditional fields, and debug macros are sensitive to configuration.
- Probe/startup signals: successful PCI mapping, queue allocation, firmware request for the selected mode, firmware/microcode download, `IPW2100_INTA_FW_INIT_DONE`, `STATUS_RUNNING`, `HOST_COMPLETE`, and `STATUS_ENABLED`.
- Queue health signals: TX/RX read/write indexes remain within 0..255, `txq.available` never underflows, `fw_pend_list` drains on TX completion, command wait does not hit `HOST_COMPLETE_TIMEOUT`, and RX statuses dispatch to the expected frame types.
- Wireless behavior signals: scan completion, association transition from `STATUS_ASSOCIATING` to `STATUS_ASSOCIATED`, BSSID ordinal fetch, carrier wake/stop, WEP/WPA command success, and disassociation recovery.
- Recovery signals: RF-kill activation/deactivation schedules the expected work, firmware RTC hang detection schedules reset, fatal/parity interrupts populate `fatal_errors`, and reset clears running/enabled/associated state before reinitializing queues.
- Diagnostics: debug categories, ethtool firmware version, sysfs/proc attributes, wireless stats, and ordinal reads should report coherent values after association and after reset.
