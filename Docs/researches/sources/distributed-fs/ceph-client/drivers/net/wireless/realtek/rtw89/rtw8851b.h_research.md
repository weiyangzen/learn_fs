# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtw89/rtw8851b.h

## Purpose

`rtw8851b.h` declares the RTL8851B efuse layout and exports the chip descriptor symbol. It is the shared contract that lets `rtw8851b.c` cast logical efuse bytes into chip-specific fields.

## Important APIs, Types, And Functions

`RF_PATH_NUM_8851B` and `BB_PATH_NUM_8851B` declare a one-path chip. `struct rtw8851bu_efuse` and `struct rtw8851be_efuse` describe USB vs PCIe MAC address placement. `struct rtw8851b_tssi_offset` stores TSSI efuse offsets. `struct rtw8851b_efuse` is the packed logical efuse map. The only exported symbol declaration is `extern const struct rtw89_chip_info rtw8851b_chip_info`.

## Control Flow

There is no executable control flow. Runtime parsing happens in `rtw8851b_read_efuse()`, which casts the logical efuse buffer to `struct rtw8851b_efuse` and copies fields into generic rtw89 state.

## State And Persistence Behavior

The structures model persistent efuse/OTP data: country code, XTAL trim, IQK/LCK flag, customer and EEPROM metadata, RFE type, thermal value, RX gain offsets, per-rate power indices, TSSI offsets, and bus-specific MAC addresses. `__packed` is required to preserve hardware offsets.

## Dependencies And Integration Points

The header includes `core.h` for core constants and types. It is included by the chip implementation and bus-facing code that needs `rtw8851b_chip_info`.

## Risks

Any field/layout change can corrupt efuse parsing. The end union must be selected by HCI type. Packed bitfields for power-index deltas are hardware-format sensitive.

## Test Signals

Compare parsed PCIe and USB MAC addresses, country code, RFE type, XTAL trim, thermal/TSSI values, and RX gain offsets against known efuse dumps. Build failures catch missing constants or chip-info prototype drift.
