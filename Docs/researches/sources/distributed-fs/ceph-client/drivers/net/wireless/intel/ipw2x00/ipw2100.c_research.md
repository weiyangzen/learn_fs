# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/ipw2x00/ipw2100.c

## Purpose
`ipw2100.c` is the monolithic Linux PCI network driver for the Intel PRO/Wireless 2100 802.11b adapter. It owns PCI probe/remove, firmware and microcode loading, MMIO and indirect NIC memory access, DMA descriptor ring setup, transmit and receive paths, interrupt handling, RF-kill and hang recovery, suspend/resume, sysfs diagnostics, Wireless Extensions handlers, and bridge points into `libipw`.

The driver talks to firmware through shared host memory, buffer descriptor rings, firmware "ordinals" for statistics/configuration, and host command packets. It exposes a normal Ethernet-like `net_device` in infrastructure/ad-hoc mode, optionally a radiotap monitor interface under `CONFIG_IPW2100_MONITOR`, and legacy Wireless Extensions controls for ESSID, BSSID, channel, rates, WEP/WPA, power management, scans, and private controls.

## Important APIs, Types, And Functions
- Module and PCI entry points: `ipw2100_init()`, `ipw2100_exit()`, `ipw2100_pci_driver`, `ipw2100_pci_id_table`, `ipw2100_pci_init_one()`, `ipw2100_pci_remove_one()`, `ipw2100_suspend()`, `ipw2100_resume()`, and `ipw2100_shutdown()`.
- Netdev integration: `ipw2100_alloc_device()` allocates `alloc_libipw()` state and wires `libipw` callbacks. `ipw2100_netdev_ops` provides open, stop, transmit through `libipw_xmit`, TX timeout, MAC address setting, and address validation. `ipw2100_tx()` is the driver's `libipw` hard-start callback.
- Driver state: `struct ipw2100_priv` in `ipw2100.h` is the central object. It holds MMIO base, `libipw_device`, `net_device`, PCI device, status/config/capability bitfields, association context, firmware and hardware metadata, TX/RX/message queues, status queue, delayed works, tasklet, counters, locks, and the command waitqueue.
- Descriptor and packet types: `struct ipw2100_bd_queue`, `struct ipw2100_bd`, `struct ipw2100_status_queue`, `struct ipw2100_status`, `struct ipw2100_tx_packet`, `struct ipw2100_rx_packet`, `struct ipw2100_cmd_header`, `struct host_command`, and `struct ipw2100_data_header` define the shared DMA and command protocol.
- Low-level register/NIC memory helpers: `read_register()`, `write_register()`, byte/word variants, `read_nic_*()`, `write_nic_*()`, `read_nic_memory()`, and `write_nic_memory()` abstract MMIO and indirect SRAM/control-store access.
- Firmware loading: `ipw2100_get_firmware()` selects `ipw2100-1.3.fw`, `ipw2100-1.3-i.fw`, or monitor firmware `ipw2100-1.3-p.fw`; `ipw2100_mod_firmware_load()` parses the packed firmware header; `ipw2100_ucode_download()` programs Symbol microcode; `ipw2100_fw_download()` writes firmware runs into NIC memory; `ipw2100_download_firmware()` sequences reset, verification, microcode, firmware, and shared-memory clearing.
- Adapter lifecycle: `sw_reset_and_clock()`, `ipw2100_verify()`, `ipw2100_start_adapter()`, `ipw2100_enable_adapter()`, `ipw2100_disable_adapter()`, `ipw2100_hw_stop_adapter()`, `ipw2100_power_cycle_adapter()`, `ipw2100_up()`, `ipw2100_down()`, and `ipw2100_reset_adapter()`.
- Command path: `ipw2100_hw_send_command()` serializes firmware commands using `STATUS_CMD_ACTIVE`, message buffers, `msg_*` lists, the TX ring, and `wait_command_queue`. Completion is delivered by RX command-status frames in `isr_rx_complete_command()`.
- TX path: `ipw2100_tx()` queues `libipw_txb` packets; `ipw2100_tx_send_data()` maps fragments and builds data TBDs; `ipw2100_tx_send_commands()` builds command TBDs; `__ipw2100_tx_process()` and `__ipw2100_tx_complete()` reclaim firmware-completed packets and DMA mappings.
- RX and ISR path: `ipw2100_interrupt()` masks and defers IRQ handling to `ipw2100_irq_tasklet()`. The tasklet acknowledges interrupt bits, handles fatal/parity conditions, processes RX frames through `__ipw2100_rx_process()`, reclaims TX completions, and restarts pending TX work. RX frame handlers include `isr_rx_complete_command()`, `isr_status_change()`, `isr_rx()`, and monitor-mode `isr_rx_monitor()`.
- Configuration commands: `ipw2100_adapter_setup()`, `ipw2100_set_mac_address()`, `ipw2100_set_port_type()`, `ipw2100_set_channel()`, `ipw2100_system_config()`, `ipw2100_set_tx_rates()`, `ipw2100_set_power_mode()`, `ipw2100_set_rts_threshold()`, retry setters, BSSID/ESSID setters, security setters, WEP key setters, WPA IE setter, scan option setter, and scan start function.
- Diagnostics and controls: sysfs attributes expose PCI config, MMIO registers, NIC hardware locations, ordinals, stats, internals, BSS info, memory dump mode/snapshot reset, scan age, fatal error reset trigger, RF kill, config/status/capability, and debug level when enabled.
- Wireless Extensions: `ipw2100_wx_handler_def`, `ipw2100_wx_handlers`, and `ipw2100_private_handler` implement standard and private ioctls for name, frequency, mode, range, AP, scan, ESSID, nick, rate, RTS, fragmentation, TX power/RF kill, retry, encode, power, WPA auth/genie, MLME, monitor, manual reset, private power mode, preamble, and monitor CRC checking.

## Control Flow
Module load registers the PCI driver and adds a PM QoS request. Probe maps BAR0, allocates a `libipw` netdev/private object, enables PCI bus mastering and 32-bit DMA, requests regions and IRQ, disables hardware interrupts, allocates TX/RX/status/message queues, initializes queue state, starts firmware with `ipw2100_up(priv, 1)`, registers the wiphy and netdev, creates sysfs files, and if RF kill is clear completes adapter enablement plus an initial scan.

Firmware bring-up is explicit and multi-stage. `ipw2100_up()` updates CPU latency QoS, disables interrupts under `low_lock`, resets prior fatal state, optionally power-cycles a powered/reset-pending adapter, calls `ipw2100_start_adapter()`, initializes firmware ordinal table addresses, detects EEPROM/RF-kill capability, sets geography/channel data for `libipw`, clears the firmware persistent database lock ordinal, checks RF-kill state, enables interrupts, sends adapter setup commands, and either defers enablement or sends `HOST_COMPLETE` followed by scan configuration and `BROADCAST_SCAN`.

`ipw2100_start_adapter()` downloads firmware and reinitializes descriptor queues. It releases ARC execution and polls for `IPW2100_INTA_FW_INIT_DONE`, clears pending interrupt state, sets GPIO ownership bits, marks `STATUS_RUNNING`, and clears association state. Commands cannot be sent until this state is reached.

The host-command flow is synchronous from the caller's point of view. `ipw2100_hw_send_command()` takes `low_lock`, rejects fatal/non-running/concurrent-command states, moves one command packet from `msg_free_list` to `msg_pend_list`, fills its coherent `ipw2100_cmd_header`, marks `STATUS_CMD_ACTIVE`, sends command and data queues, then drops the lock and waits up to `HOST_COMPLETE_TIMEOUT`. The firmware later emits a command-status RX frame; `isr_rx_complete_command()` updates `STATUS_ENABLED` for `HOST_COMPLETE`, clears it for `CARD_DISABLE`, clears `STATUS_CMD_ACTIVE`, and wakes the waiter. Timeout records `IPW2100_ERR_MSG_TIMEOUT`, clears active state, and schedules reset.

The TX data path starts with `libipw_xmit` calling `ipw2100_tx()`. The driver only accepts data while `STATUS_ASSOCIATED` is set and a free TX packet exists. It moves a `struct ipw2100_tx_packet` from `tx_free_list` to `tx_pend_list`, then `ipw2100_tx_send_data()` consumes pending packets if the firmware TBD ring has enough spare descriptors. Each data packet uses one coherent `ipw2100_data_header` TBD plus one TBD per `libipw_txb` fragment after the 802.11 header. Payload fragments are DMA-mapped, synced for device, and the TX write index is written to firmware. TX interrupts or RX interrupts call `__ipw2100_tx_complete()`, which checks firmware read/write indexes, unmaps finished fragments, frees `libipw_txb`, returns packets to free lists, updates ring availability and watchdog timestamps, and wakes the netdev queue when associated.

The RX path is ring-index driven. Firmware fills RBDs and status entries, advances the RX read index, and interrupts. `__ipw2100_rx_process()` starts after the driver's cached write index and loops until firmware's read index. It syncs each RX buffer for CPU, validates status/frame sizes with `ipw2100_corruption_check()`, derives RSSI/frequency stats, and dispatches by `STATUS_TYPE_MASK`: command completions, status changes, 802.11/802.3 data, management frames to `libipw_rx_mgt()`, and monitor frames to radiotap wrapping when enabled. Consumed data SKBs are passed to `libipw_rx()` and replaced with a freshly allocated DMA-mapped SKB; the RBD host address is updated and the RX write index is backtracked to the last processed entry.

Status changes are decoded through `status_handlers`. Association status reads SSID, current TX rate, channel, and BSSID ordinals, updates cached context, enters `STATUS_ASSOCIATING`, and schedules `wx_event_work`. That work rereads BSSID, promotes to `STATUS_ASSOCIATED`, starts carrier and queue, or sends a disassociation event and nudges ESSID configuration for reassociation. Scan complete clears `STATUS_SCANNING`, increments `libipw` scan count, and emits delayed or immediate scan events depending on whether userspace requested the scan. RF-kill status marks hardware RF kill and starts periodic GPIO polling.

Removal and shutdown reverse the lifecycle. Remove clears initialized state, removes sysfs files, releases cached firmware under PM builds, calls `ipw2100_down()`, unregisters netdev, cancels delayed work, frees queues and debug snapshots, frees IRQ, unmaps MMIO, unregisters wiphy, frees `libipw`, releases PCI regions, and disables the device.

## State And Persistence
Most state is volatile per-device state in `struct ipw2100_priv`: status flags, configuration flags, cached ESSID/BSSID/channel/nick, firmware version, EEPROM version, RF-kill support, current power/rate/retry/RTS/fragmentation values, statistics counters, firmware fatal-error ring, and suspend timing. Queue state is split between host-owned list heads/statistics and coherent DMA rings shared with firmware.

Firmware state is persisted only for the active device session. The driver loads firmware from the kernel firmware API, and with `CONFIG_PM` it caches the firmware object globally in `ipw2100_firmware` so resume can avoid disk access during suspend/resume sequencing. Non-PM builds release firmware immediately after download. The driver also accesses firmware "ordinals", which are firmware-maintained tables for MAC address, association data, counters, EEPROM SRAM location, current rates, RTC, power mode, and other runtime facts.

User-visible settings persist only while the module/device instance exists unless userspace reapplies them. Module parameters (`debug`, `mode`, `channel`, `associate`, `disable`) set initial driver behavior. Sysfs writes can change scan age, memory dump mode, fatal-error reset trigger, and software RF kill. Wireless Extensions update in-memory config and usually push matching firmware commands. No durable on-disk config is written by this file.

The driver has several asynchronous state machines. Delayed work tracks resets, security resync, wireless association events, firmware hang checks, RF-kill polling, and scan event delivery. `schedule_reset()` applies backoff up to `MAX_RESET_BACKOFF`, stops carrier/queue, marks `STATUS_RESET_PENDING`, and wakes command waiters. `ipw2100_reset_adapter()` clears association/security state, cancels reset work, stops hang checks, signals disassociation if needed, and calls `ipw2100_up()` under `action_mutex`.

Locking state is explicit. `low_lock` protects low-level queues, ring indexes, interrupt enable state, and internal device status touched from interrupt/tasklet paths. `action_mutex` serializes external operations such as Wireless Extensions, resets, suspend/resume, RF-kill toggles, and MAC address changes. `adapter_mutex` serializes adapter enable/disable transitions. `wait_command_queue` coordinates synchronous firmware command completion.

## Dependencies And Integration Points
- Kernel PCI/MMIO/DMA APIs: `pci_enable_device()`, `pci_iomap()`, `pci_request_regions()`, `request_irq()`, `dma_alloc_coherent()`, `dma_map_single()`, DMA sync/unmap/free calls, and config-space reads/writes.
- Kernel networking: `net_device`, `net_device_ops`, carrier and queue helpers, stats fields, `eth_hw_addr_set()`, `register_netdev()`, `unregister_netdev()`, ethtool `get_drvinfo` and `get_link`, and MTU bounds.
- Wireless stack compatibility layer: `libipw` owns 802.11 framing, encryption helpers, scan result formatting, management RX, TXB lifetime, wiphy allocation storage, and security callbacks. The driver fills `libipw_device` callbacks and state but still uses legacy Wireless Extensions as the main userspace control surface.
- cfg80211/wiphy: `ipw2100_wdev_init()` registers 2.4 GHz channels/rates and cipher suites, sets permanent address, binds the device, and manages `wiphy_rfkill_set_hw_state()`.
- Firmware loader: `request_firmware()`, `release_firmware()`, and `MODULE_FIRMWARE()` names for the BSS, IBSS, and optional monitor images.
- Workqueues and tasklets: delayed work items run resets, security, association events, RF-kill checks, hang checks, and scan events; interrupts are handled through a tasklet after masking device IRQs.
- PM QoS and power management: the driver uses `cpu_latency_qos_*` to keep CPU latency under 175 usec while active because the hardware is sensitive to long delays, and implements suspend/resume via `SIMPLE_DEV_PM_OPS`.
- Userspace integration: sysfs attributes under the PCI device, Wireless Extensions ioctls, private iwpriv controls, `/proc/net/wireless` stats through `get_wireless_stats`, netdev open/close/transmit, and ethtool.

## Risks And Edge Cases
- Command completion is fragile. Only one firmware command may be active; if a command-status RX frame is lost or interrupts are disabled at the wrong time, callers block until timeout and then schedule a reset. Several configuration paths disable/enable the adapter around commands, increasing the number of command dependencies.
- DMA/ring correctness is critical. TX data can use multiple fragments but the driver only warns when `1 + nr_frags > IPW_MAX_BDS`; if mapping fails after some descriptors were filled, the path breaks out without a full local rollback in that loop. RX corruption detection treats malformed frame sizes or status types as PCI latency/C3 corruption and schedules a reset.
- Interrupt ordering matters. The top-half masks interrupts and defers to a tasklet; the tasklet processes fatal, parity, RX, TX, and other interrupt bits under `low_lock`, then reenables interrupts. Any path that needs firmware command completion must avoid disabling interrupts too early.
- The code has legacy assumptions and APIs: Wireless Extensions, `libipw`, tasklets, module parameters, manual sysfs debug dumps, hand-rolled firmware protocols, and optional monitor support. Modern kernel API changes can break build or behavior even if driver logic is unchanged.
- Firmware image parsing has limited validation. Major version is checked, but `ipw2100_get_firmware()` ignores the return value from `ipw2100_mod_firmware_load()`. Firmware download trusts packed run records except for a maximum run length of 32 bytes and does not comprehensively validate that the buffer contains whole records.
- Firmware and hardware state are tightly coupled to magic registers and timing delays. Reset/clock stabilization, Symbol microcode load, GPIO RF-kill sampling, PHY-off polling, and firmware init polling use fixed loops and delays; slow, absent, or wedged hardware maps to `-EIO` and reset paths.
- Association state is eventually consistent. Initial association status may provide an all-zero BSSID, so the driver uses delayed `wx_event_work` to reread it. During that window the device is `STATUS_ASSOCIATING`, and RX/TX behavior differs from fully associated state.
- RF kill has both software and hardware flags. Software RF kill calls `ipw2100_down()`, while hardware RF kill defers startup and polls GPIO. Re-enabling while hardware RF kill remains active schedules polling instead of immediate restart.
- Sysfs diagnostic reads touch live hardware and sometimes use static loop cursors (`memory_show()`, `ordinals_show()`), so repeated reads stream through device memory/ordinal arrays rather than representing atomic snapshots. Debug snapshot support only exists under selected debug builds.
- Security support is split. Firmware receives authentication/cipher capability and WEP key commands, while actual data encryption/decryption is host-based through `libipw` crypto. WPA support is wired through Wireless Extensions and contains compatibility workarounds for supplicant behavior.
- Removal/probe failure paths must account for partial initialization. The file does attempt staged cleanup, but the lifecycle crosses PCI, netdev, wiphy, sysfs, firmware, IRQ, DMA queues, and work items, making ordering regressions high impact.

## Test Signals
- Build coverage with relevant configs: compile the driver with `CONFIG_IPW2100`, `CONFIG_IPW2100_DEBUG`, `CONFIG_IPW2100_MONITOR`, `CONFIG_PM`, and IPv6 on/off variants because conditional code changes command paths, monitor RX, debug sysfs/driver attributes, and firmware lifetime.
- Probe/remove smoke: on matching PCI hardware or emulation capable of this device, verify BAR mapping, IRQ request, queue allocation, firmware request names, wiphy registration, netdev registration, sysfs group creation, and clean remove without leaked work or DMA warnings.
- Firmware load path: boot with correct and missing firmware files for infrastructure, ad-hoc, and monitor mode. Expected signals are successful firmware init, meaningful firmware version in ethtool, or clear `Firmware ... not available` / compatibility failures without crashes.
- Command path: exercise ESSID, BSSID, channel, mode, rate, RTS, retry, power, WEP/WPA, scan, and RF-kill toggles. Watch for `STATUS_CMD_ACTIVE` timeouts, reset scheduling, and command completion through RX command-status frames.
- TX/RX data path: associate to an 802.11b AP, pass traffic, monitor netdev stats, verify no queue stalls, no DMA mapping errors, no `Queue mismatch` warnings, and no repeated reset/hang counters. Include fragmented frames if possible to stress multi-TBD TX.
- Interrupt and reset recovery: trigger or simulate TX timeout, firmware fatal error, stalled firmware RTC, and manual sysfs fatal-error write. Passing behavior is carrier/queue stop, bounded reset backoff, firmware reload, reassociation, and command waiters waking.
- RF kill and suspend/resume: toggle hardware/software RF kill and perform suspend/resume. Confirm wiphy RF-kill state, scan result aging via `suspend_time`, PCI retry-timeout rewrite on resume, firmware reload/cached firmware handling, and no traffic while radio is disabled.
- Wireless Extensions/userspace: validate `iwconfig`, `iwlist scan`, WPA supplicant interactions, private power/preamble/monitor commands where configured, and `/proc/net/wireless` quality values based on RSSI/retry/beacon ordinals.
- Sysfs diagnostics: read `pci`, `registers`, `hardware`, `ordinals`, `stats`, `internals`, `bssinfo`, `memory`, `scan_age`, `fatal_error`, `rf_kill`, `cfg`, `status`, and `capability` while associated, unassociated, RF-killed, and during reset. The main signal is no oops or lockup from hardware reads and sensible empty output when RF-kill prevents ordinal access.
- Static analysis focus: lock ordering (`action_mutex`, `adapter_mutex`, `low_lock`), DMA map/unmap balance, firmware buffer bounds, work cancellation vs. IRQ/tasklet lifetime, sysfs show buffer limits, and probe failure cleanup ordering are the highest-value review targets.
