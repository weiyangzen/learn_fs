## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/mac-cfg.h

`mac-cfg.h` defines the newer MLD-oriented MAC configuration command group used by `iwlwifi` firmware. It includes `mac.h` and reuses shared MAC types, QoS structures, HE/EHT packet-extension structures, and access-category constants. The file covers MAC context configuration, link context configuration, station table configuration, low-latency mode, channel switch lifecycle, EMLSR/ESR notifications, TWT operations, NAN configuration, and related notifications.

`enum iwl_mac_conf_subcmd_ids` is the dispatch table for this command group. Host-to-firmware commands include `LOW_LATENCY_CMD`, `CHANNEL_SWITCH_TIME_EVENT_CMD`, `CANCEL_CHANNEL_SWITCH_CMD`, `MAC_CONFIG_CMD`, `LINK_CONFIG_CMD`, `STA_CONFIG_CMD`, `AUX_STA_CMD`, `STA_REMOVE_CMD`, `STA_DISABLE_TX_CMD`, `ROC_CMD`, `TWT_OPERATION_CMD`, and `NAN_CFG_CMD`. Firmware notifications include missed VAP/beacon, channel switch start/error, ROC/session protection, EMLSR transition failure, probe-response data, NAN cluster join, and NAN discovery-window end.

The MAC configuration ABI is split between `iwl_mac_config_cmd_v3` and current `iwl_mac_config_cmd`. Both carry context ID/color, action, MAC type, local MLD address, filter flags, generation support (`iwl_mac_wifi_gen_support_v2` or current `iwl_mac_wifi_gen_support`), and type-specific data. Current versions add NAN data (`iwl_mac_nan_data`) for NDI addresses. Link configuration is driven by `iwl_link_config_cmd`, whose `modify_mask` gates which fields are meaningful during modify operations. It binds link ID, MAC ID, PHY ID, local link address, active/listen/block state, optional bandwidth modification, basic rates, protection/QoS settings, HE/EHT/UHR parameters, beacon timing, BSS color, multi-BSSID identifiers, IBSS BSSID, NPCA parameters, priority EDCA, and reserved version space.

Station configuration is similarly versioned: `iwl_sta_cfg_cmd_v1` uses a single `link_id`; v2 adds LDPC/ICF and DPS/MIC timing fields; current `iwl_sta_cfg_cmd` uses a `link_mask` and adds DPS enable plus NAN peer mapping fields. `enum iwl_fw_sta_type` distinguishes peer, broadcast-management, multicast, NAN NMI/NDI, and driver-only AUX stations. Removal and TX-disable commands are small station-ID payloads. TWT uses `iwl_twt_operation_cmd` to encode negotiation type, wake time, interval, trigger/protection/flow fields, restricted TWT bitmaps, and AP/STA request direction. NAN uses `iwl_nan_config_cmd` with variable beacon data containing NAN attributes and vendor elements.

Control flow is a firmware-context lifecycle: add/modify/remove a MAC context, add links under it, bind/update station entries, configure timing/power-adjacent features such as TWT/NAN, and consume asynchronous notifications for beacon loss, channel switch, EMLSR, and probe response metadata. The header stores no state itself; persistence belongs to driver objects that must track context IDs/colors, link IDs, station IDs, active link masks, NAN beacon-data lengths, and EMLSR recommendations. Risks include using MAC IDs where a newer ABI expects link IDs, failing to honor `modify_mask`, sending active-link immutable fields such as PHY/local address changes, variable-length NAN beacon data bounds errors, and ABI drift across versions. Test signals include MLD association with multiple links, channel switch cancel/error handling, station add/remove/disable sequencing, NAN cluster join and DW end events, TWT negotiation behavior, and notification parsing with exact payload-size checks.
