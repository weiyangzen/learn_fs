# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtw89/rtw8851b_rfk_table.c

Purpose: Provides the RTW8851B RFK table payloads consumed by the RTW89 common RF calibration parser. The file is a data-only catalog of `struct rtw89_reg5_def` arrays for DADCK/DACK, IQK clock and TXK setup, TSSI system and tracking setup, and NCTL post-initialization. Each static array is exported as a `const struct rtw89_rfk_tbl` through `RTW89_DECLARE_RFK_TBL()`, making the tables callable by 8851B calibration code without exposing the raw arrays.

Important APIs, types, and tables: The important type is `struct rtw89_reg5_def`, whose fields encode an RFK parser operation flag, RF path, address, mask, and data. The file uses `RTW89_DECL_RFK_WM()` for masked BB/MAC register writes, `RTW89_DECL_RFK_WRF()` for masked RF register writes, and `RTW89_DECL_RFK_DELAY()` for microsecond delay entries. Exported `rtw89_rfk_tbl` symbols include `rtw8851b_dadck_setup_defs_tbl`, `rtw8851b_dadck_post_defs_tbl`, `rtw8851b_dack_s0_1_defs_tbl`, `rtw8851b_dack_s0_2_defs_tbl`, `rtw8851b_dack_manual_off_defs_tbl`, `rtw8851b_iqk_rxclk_80_defs_tbl`, `rtw8851b_iqk_rxclk_others_defs_tbl`, `rtw8851b_iqk_txk_2ghz_defs_tbl`, `rtw8851b_iqk_txk_5ghz_defs_tbl`, `rtw8851b_iqk_afebb_restore_defs_tbl`, `rtw8851b_iqk_macbb_defs_tbl`, `rtw8851b_iqk_macbb_bh_defs_tbl`, the TSSI setup/slope/alignment/tracking tables, and `rtw8851b_nctl_post_defs_tbl`.

Control flow: There are no local functions or branches. Runtime control flow is table-driven: `rtw8851b_rfk.c` selects a table or a 2 GHz versus 5 GHz pair, then passes it to `rtw89_rfk_parser()`. The parser walks from `tbl->defs` to `tbl->defs + tbl->size` and dispatches each entry by `flag` to a register write, RF write, set/clear, or delay handler. Ordering is therefore the main behavior in this file. Examples include DADCK setup toggling 0x032c and 0x030c fields before a delay and post table restore, IQK 80 MHz versus other RX clock tables programming different 0x5670/0xc0ec values, band-specific IQK TXK RF writes, and TSSI band-specific system/slope/alignment tables.

State and persistence: The arrays themselves are immutable `static const` data. Persistent state is created only by the hardware side effects of parsing them: masked register fields, RF path A register fields, DACK/IQK/TSSI control registers, cleared DAC-gain memory ranges, moving-average controls, and NCTL post state remain in the device until a later calibration step, reset, power transition, or explicit restore table changes them. The file does not store driver state, allocate memory, or synchronize access; sequencing and locking are owned by callers such as `rtw8851b_rfk_channel()` and the common RTW89 RFK paths.

Dependencies and integration points: Includes `rtw8851b_rfk_table.h`, which includes `phy.h` for `struct rtw89_rfk_tbl` and the table declaration macros. The object is built with `rtw8851b_rfk.o` by the RTW89 Makefile. `rtw8851b_rfk.c` parses these tables during DACK, IQK, and TSSI setup, including channel calibration and scan/band-change flows. `rtw8851b.c` installs `rtw8851b_nctl_post_defs_tbl` in the chip info `nctl_post_table`, which `phy.c` parses during common NCTL post configuration. The data also depends on common constants such as `RF_PATH_A`, `BIT()`, and `MASKDWORD`.

Risks: These are vendor-derived hardware programming sequences with little compiler-visible semantics. A wrong address, mask, value, path, or entry order can silently miscalibrate TX power, IQ compensation, ADC/DAC behavior, or NCTL state. Delay entries are part of the hardware handshake and can produce intermittent failures if removed or shortened. The single-path nature of 8851B means the TSSI and RF entries target path A; copying data from dual-path parts could accidentally introduce path B or 0x78xx register writes that do not belong. The long zeroing sequence in `rtw8851b_tssi_dac_gain_defs_a` and full-mask writes can overwrite calibration state if called at the wrong phase. Since tables are exported by symbol name, C/header mismatches cause link failures, while semantic mismatches generally appear only as RF performance regressions.

Test signals: Basic build and module link validate that every declared table symbol is defined and that the table macros still match `struct rtw89_rfk_tbl`. Runtime signals include successful 8851B probe, channel change RFK, 2 GHz and 5 GHz association, 80 MHz and non-80 MHz IQK paths, scan/band-change TSSI handling, TSSI enable and tracking debug output, NCTL post parsing, absence of RFK timeout or calibration error logs, stable reported TX power, and throughput/EVM/regulatory power behavior across temperature and band changes. Register trace/debug reads around 0x030c/0x032c, 0x5670, 0x58xx/0x5axx, and RF path A registers are the most direct validation points.
