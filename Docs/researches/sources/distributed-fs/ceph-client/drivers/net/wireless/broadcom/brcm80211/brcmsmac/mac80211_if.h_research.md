# sources/distributed-fs/ceph-client/drivers/net/wireless/broadcom/brcm80211/brcmsmac/mac80211_if.h

## Purpose
`mac80211_if.h` declares private Linux-interface types and cross-file callbacks for the `brcmsmac` mac80211 bridge. It defines `struct brcms_info`, timer wrappers, firmware bookkeeping, a minimal interface wrapper, and the functions common code uses to call back into the Linux integration layer.

## Important APIs, Types, and Functions
- `BRCMS_LEGACY_5G_RATE_OFFSET` marks the first 5 GHz rate in the shared legacy rate table.
- `BRCMS_SET_SHORTSLOT_OVERRIDE` is a softmac ioctl definition.
- `struct brcms_timer` wraps delayed work and stores owner, callback, argument, delay, periodic/active flags, list linkage, and optional debug name.
- `struct brcms_if` stores subunit and PCI device identity compatibility fields.
- `MAX_FW_IMAGES` bounds firmware arrays.
- `struct brcms_firmware` stores firmware binaries, header blobs, header entry counts, and firmware count.
- `struct brcms_info` stores the main per-device Linux-side state: public/common pointers, IRQ, locks, TX flush waitqueue, callback count, timers, tasklet, reschedule flag, firmware/ucode/wiphy state, mute flag, radio LED state, and LED class device.
- Declared callbacks include init/reset/up/down/fatal error, interrupt on/off/restore, TX flow control, rfkill state update, DPC, and timer allocation/control/free.

## Control Flow
The header has no executable flow. It defines the object and callback surface used by `mac80211_if.c` and common `brcms_c_*` code. `struct brcms_info` is allocated as `ieee80211_hw` private data, initialized during probe, used by mac80211 callbacks and ISR/tasklet/timer paths, and freed during remove.

## State and Persistence
All state defined here is runtime-only. `struct brcms_info` persists for the lifetime of the registered hardware object. Firmware references exist during request/ucode initialization, copied ucode data persists until detach, and timers are linked from `wl->timers` for unload cleanup.

## Dependencies and Integration Points
The header includes Linux timer, interrupt, workqueue, and LED headers, plus local `ucode_loader.h` and `led.h`. It is shared by `mac80211_if.c`, `led.c`, common driver modules, firmware loader code, timer users, and interrupt handlers. The prototypes form the Linux-side callback surface consumed by common brcmsmac code.

## Risks and Edge Cases
- `struct brcms_info` is broad shared state; field changes can affect probe, callbacks, timers, interrupts, firmware, and LED behavior.
- Locking requirements are mostly documented in implementation comments rather than enforced by types.
- Timer correctness depends on balanced `set`, `periodic`, and callback-count transitions.
- `MAX_FW_IMAGES` must stay aligned with firmware name arrays and module firmware declarations.
- `void brcms_timer(struct brcms_timer *t);` is declared here but not implemented in the reviewed `mac80211_if.c`, so references should be checked before use.

## Test Signals
Compile all includers, test timer callback accounting and cleanup, verify firmware array bounds, run locking/static analysis around declared callbacks, and exercise probe/remove to confirm every embedded `struct brcms_info` field is initialized and torn down safely.
