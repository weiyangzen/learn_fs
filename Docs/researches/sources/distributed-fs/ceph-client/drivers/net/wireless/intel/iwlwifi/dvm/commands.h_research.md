# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/commands.h

Purpose: Defines the legacy iwlwifi DVM firmware/uCode ABI. The file is intentionally limited to command IDs, packed command payloads, notification payloads, bit masks, endian-tagged fields, and protocol documentation for AGN firmware interactions; implementation state belongs in `dev.h` and hardware register definitions belong in hardware-specific headers.

Important APIs and definitions: The top-level command enum assigns IDs for alive/error, RXON, QoS, station, TX/RX, coexistence, calibration, 802.11h, power, scan, beacon, statistics, RF-kill, Bluetooth coexistence, PAN/WiPAN, and WoWLAN commands. Queue/FIFO constants define command queue selection, PAN queues, AUX scan TX queue, and SCD masks. Common rate fields are described by `RATE_MCS_*` masks and antenna masks. Firmware lifecycle structures include `struct iwl_alive_resp`, `struct iwl_error_event_table`, and `struct iwl_error_resp`. RXON/channel structures include `struct iwl_rxon_cmd`, `struct iwl_rxon_assoc_cmd`, `struct iwl_rxon_time_cmd`, channel switch commands for 5000/6000, and CSA notifications. Station/security structures include `struct iwl_addsta_cmd`, `struct iwl_keyinfo`, WEP key commands, add/remove station responses, and TID/aggregation flags. TX structures include `struct iwl_tx_cmd`, `struct iwl_tx_cmd_hdr`, `struct iwlagn_tx_resp`, `struct iwl_compressed_ba_resp`, and `struct iwl_link_quality_cmd`. RX/statistics structures include `struct iwl_rx_phy_res`, `struct iwl_rx_mpdu_res_start`, `struct iwl_notif_statistics`, `struct iwl_bt_notif_statistics`, and the nested RX/TX/general statistics layouts. Calibration structures include sensitivity commands, calibration config, generic calibration headers, crystal/temperature commands, and chain-noise reset/gain commands. Later sections define LED, WiMAX coexistence, Bluetooth coexistence, D3/WoWLAN security material, WiPAN slots, P2P channel switch, and NoA notifications.

Control flow: This header describes firmware-driven workflows rather than executing them. RXON commands tune channel/radio state and, when sent without association, clear firmware station and TX power tables, forcing the driver to rebuild station and power state before normal TX. TX commands are DMA-owned firmware descriptors; firmware retries according to flags and link-quality tables, reports TX status, and sends compressed block-ack notifications for aggregation. Scan commands drive a firmware scan state machine that leaves and returns to the service channel, emits start/result/complete notifications, and enforces timing constraints. Statistics commands and notifications feed runtime calibration and debugfs reporting. Calibration config selects firmware and driver calibrations, while sensitivity and chain-noise commands apply driver-derived RX thresholds and gain codes. Power, RF-kill, CT-kill, BT/WiMAX coexistence, WoWLAN, and WiPAN command structures define side-channel state machines used by other DVM modules.

State and persistence: The file owns no C runtime state, but it defines firmware-resident state that persists until firmware reset, RXON retune, RF-kill, or explicit commands: station tables, key tables, TX power tables, rate retry tables, scheduler queues, scan ownership, statistics counters, calibration tables, power-save configuration, coexistence tables, WoWLAN replay counters/patterns, and WiPAN schedules. Many fields are `__le16`, `__le32`, or `__le64`, and many structures are `__packed`, so byte layout and endian conversion are part of the persistent hardware/firmware contract.

Dependencies and integration points: Includes Linux IEEE 802.11 and type definitions, and is consumed by DVM modules for RXON, TX, scan, station, power, Bluetooth coexistence, WoWLAN suspend, debugfs statistics, calibration, and event handling. It integrates with mac80211 concepts such as EDCA access categories, QoS TIDs, A-MPDU block ack, channel flags, beacon timing, security ciphers, and WoWLAN pattern/rekey state. Transport command senders use these structures as payloads for `iwl_dvm_send_cmd()` and `iwl_dvm_send_cmd_pdu()`.

Risks: This is an ABI header; changing field order, packing, widths, endian annotations, command IDs, or bit positions can break firmware communication. Several command IDs are shared or versioned, such as old TX power and TX antenna configuration on `0x98`, so call sites must select the correct payload for device family. RXON side effects can silently wipe station and TX power tables. Firmware statistics counters are documented as monotonic with wrap/reset behavior, and consumers must compute deltas carefully. Flexible-array command structures require correct allocation and length calculation. Rate, TX status, aggregation, sensitivity, WoWLAN key material, and BT UART bitfields are dense and easy to mis-mask.

Test signals: Compile with all DVM device families and static layout assertions where available. Exercise firmware boot alive/error parsing, RXON/association transitions and table rebuilds, station add/remove/key commands, WEP/TKIP/CCMP paths, normal TX and aggregation status decoding, compressed BA handling, link-quality table updates, scan start/result/complete/abort, statistics request/notification parsing, missed-beacon handling, sensitivity and chain-noise command emission, power-save commands and notifications, RF-kill/CT-kill, BT/WiMAX coexistence commands and notifications, WoWLAN pattern/rekey/status flows, and WiPAN/NoA handling.
