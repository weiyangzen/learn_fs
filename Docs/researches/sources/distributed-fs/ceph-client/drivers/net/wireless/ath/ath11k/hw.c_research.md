# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath11k/hw.c

Purpose: Implements the ath11k hardware-specific behavior tables and constants used to adapt the shared driver to IPQ8074, IPQ6018, QCA6390, QCN9074, WCN6855, WCN6750, and IPQ5018 device families. It is mostly a hardware ABI map: WMI target resource presets, RX descriptor field accessors, REO routing setup, TCL ring selection, interrupt ring masks, firmware Copy Engine service maps, HAL register offsets, TCL-to-WBM return-buffer-manager maps, and WCN6855 SAR ranges.

Important APIs and functions: The exported objects are `ipq8074_ops`, `ipq6018_ops`, `qca6390_ops`, `qcn9074_ops`, `wcn6855_ops`, `wcn6750_ops`, `ipq5018_ops`, `ath11k_hw_ring_mask_*`, `ath11k_target_ce_config_wlan_*`, `ath11k_target_service_to_ce_map_wlan_*`, `*_regs`, `ath11k_hw_hal_params_*`, `ath11k_ce_ie_addr_*`, `ath11k_ce_remap_ipq5018`, and `ath11k_hw_sar_capa_wcn6855`. The main executable helpers are `ath11k_init_wmi_config_ipq8074()` and `ath11k_init_wmi_config_qca6390()` for firmware resource sizing; SoC-specific RX descriptor getters such as `ath11k_hw_ipq8074_rx_desc_get_msdu_len()`, `ath11k_hw_qcn9074_rx_desc_get_mpdu_tid()`, and `ath11k_hw_wcn6855_rx_desc_get_encrypt_type()`; `ath11k_hw_ipq8074_reo_setup()`, `ath11k_hw_wcn6855_reo_setup()`, and `ath11k_hw_ipq5018_reo_setup()` for REO destination routing; and ring selection callbacks `ath11k_hw_ipq8074_get_tcl_ring_selector()` and `ath11k_hw_wcn6750_get_tcl_ring_selector()`.

Control flow: Device selection happens outside this file in `core.c`, where the matching `ath11k_hw_params` row points at one of these ops, ring masks, CE maps, register maps, and HAL parameters. Firmware startup calls the selected `wmi_init_config` callback to populate `target_resource_config`; IPQ-style devices scale vdev/peer/TID resources by radio count and raw-mode state, while QCA6390/WCN-style devices use smaller single-device limits. Datapath RX code calls the selected `hw_ops` descriptor accessors to decode the `hal_rx_desc` union variant for the active silicon, avoiding conditionals in hot RX paths. DP setup calls `reo_setup` to enable REO aging/flush and program fragment and hash-destination rings. TX setup and enqueue use `hal_params->tcl2wbm_rbm_map`, `num_tx_rings`, and `hw_ops->get_ring_selector` to choose TCL rings and return-buffer managers; WCN6750 hashes by SKB flow to reduce packet reordering, while IPQ-style devices default to CPU-based selection.

State and persistence: The file owns no mutable long-lived state. Its constant tables become runtime configuration after `ab->hw_params` is copied from the static hardware parameter table in `core.c`. The only direct mutations are register writes in REO setup and bitfield writes to RX descriptors when `rx_desc_set_msdu_len` adjusts descriptor metadata. Hardware-visible effects persist until device reset or reconfiguration: CE/service maps are passed to firmware, REO routing changes register state, SAR capability is exposed through cfg80211, and register offsets determine all subsequent MMIO ring programming.

Dependencies and integration points: Includes `core.h`, `ce.h`, `hif.h`, `hal.h`, and `hw.h`. It depends on HAL descriptor layouts and bit masks for IPQ8074/QCN9074/WCN6855 descriptor unions, WMI resource flags from `wmi.h`, CE pipe/service types from `ce.h`, and bus register access through `ath11k_hif_read32()`/`ath11k_hif_write32()`. Consumers include `core.c` for hardware parameter selection, `ahb.c` and `pci.c` for QMI/CE startup, `pcic.c` and `ahb.c` for external IRQ grouping from ring masks, `hal.c`/`hal.h` for register offsets, `dp_tx.c` for TCL ring and RBM selection, `dp_rx.c`/`hal_rx.c` for RX descriptor decoding, `mac.c` for pdev/MAC mapping and SAR publication, and `qmi.c` for firmware/board-data capabilities encoded in the broader hardware parameter model.

Risks: The most important risk is table/descriptor skew. A device assigned the wrong ops table will read the wrong RX descriptor union fields, causing bogus lengths, encryption state, peer IDs, or metadata. Register offsets and CE service maps are hardware ABI constants; a bad value can break DMA rings, WMI/HTT control paths, MSI/MSI-X routing, firmware boot, or interrupt delivery. REO hash-map programming differs between IPQ/IPQ5018 and WCN devices, including fragment destination register placement. Ring mask arrays are indexed by external IRQ group; off-by-one placement can silently route rings to the wrong interrupt group. The file also contains copied-but-slightly-divergent SoC tables, so adding new hardware requires checking every coupled table: ops, ring mask, CE config, service map, regs, HAL params, and core hardware params.

Test signals: Build coverage should include all enabled ath11k buses and SoC variants so every exported table has a consumer. Runtime signals include successful firmware boot/QMI memory negotiation, WMI service availability, CE interrupt activity, TX traffic across all configured TCL rings, RX packet delivery with correct lengths/decap/encryption metadata, monitor-mode RX status parsing, mesh TX on each silicon family, REO timeout/aging behavior, no packet reordering regressions on WCN6750 flow-hash ring selection, SAR capability visible on WCN6855, and reset/reprobe surviving register and CE reinitialization.
