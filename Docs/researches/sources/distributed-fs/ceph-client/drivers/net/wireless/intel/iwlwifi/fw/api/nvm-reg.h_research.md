## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/nvm-reg.h

`nvm-reg.h` defines firmware ABIs for non-volatile memory access and regulatory configuration. It covers NVM section read/write, NVM capability query, MCC/LAR regulatory updates, TAS configuration, BIOS-origin configuration headers, LARI regulatory override bitmaps, PNVM completion notification, MCC-to-AP-type tables, and SAR offset mapping used by other power/PHY code.

`enum iwl_regulatory_and_nvm_subcmd_ids` maps the group to `NVM_ACCESS_COMPLETE`, `LARI_CONFIG_CHANGE`, `NVM_GET_INFO`, `TAS_CONFIG`, `SAR_OFFSET_MAPPING_TABLE_CMD`, `MCC_ALLOWED_AP_TYPE_CMD`, and `PNVM_INIT_COMPLETE_NTFY`. NVM access is represented by `iwl_nvm_access_cmd` and `iwl_nvm_access_resp`, with opcode, target (cache/OTP/EEPROM), section type, offset/length, status, and flexible data payload. `iwl_nvm_get_info_rsp_v3` and current `iwl_nvm_get_info_rsp` return general flags/version/board/MAC count, MAC SKU flags, PHY chain masks, and regulatory channel profiles.

Regulatory country handling uses `iwl_mcc_update_cmd`, response versions v3/v4/v8, and `iwl_mcc_chub_notif`. The command carries a two-letter MCC, source ID, test key, and reserved padding. Responses return status, applied MCC, capabilities, elapsed test time, geo information, source, and a variable channel-control array. `enum iwl_mcc_update_status` and `enum iwl_mcc_source` are critical for policy decisions and prioritization.

Transmit antenna selection and regulatory overrides are represented by `iwl_tas_config_cmd_common`, v3/v4/v5 TAS payloads, and `enum iwl_tas_uhb_allowed_flags`. BIOS data is normalized through `iwl_bios_config_hdr` and `bios_value_u32`, which are reused by power APIs. LARI evolves from a single `config_bitmap` in v1 through v6/v8 to current `iwl_lari_config_change_cmd`, which adds UHB, 11ax, UNII-4, channel active-state, force-disable, energy detection, 320 MHz, 11be, 11bn, UNII-9, and BIOS header fields. UATS/MCC allowed AP type commands map country rows/columns to 6 GHz and UNII-9 AP-type permissions.

Control flow is initialization and regulatory refresh: read or query NVM, signal access completion, load PNVM, apply BIOS/OEM regulatory tables, process MCC changes from host/firmware/communication hub, then update channel capability maps used by mac80211. Persistence is in firmware NVM/OTP/EEPROM and host-side cached regulatory/NVM state, not in this header. Risks include flexible-array bounds, accepting mismatched response versions, treating requested MCC as applied MCC, incorrect source-priority handling, regulatory compliance mistakes in LARI/TAS bitmaps, and stale PNVM/TAS/BIOS metadata. Test signals include NVM read/write mock responses, MCC update status matrix, invalid/low-priority/test-mode handling, country table size validation, PNVM completion parsing, LARI bitmap version coverage, and regulatory channel list comparison against expected mac80211 regdomain output.
