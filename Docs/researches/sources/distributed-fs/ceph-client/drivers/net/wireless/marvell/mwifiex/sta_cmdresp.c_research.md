# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_cmdresp.c

Purpose: Parses station-mode firmware command responses and commits returned state into `mwifiex_private`, `mwifiex_adapter`, caller data buffers, cfg80211-visible state, and bus-specific hooks. It is the response half of `sta_cmd.c` and the central station command-result dispatcher.

Important APIs, types, and functions: Public entry point is `mwifiex_process_sta_cmdresp()`. Error handling is centralized in `mwifiex_process_cmdresp_error()`. Response handlers include RSSI info, SNMP MIB, get-log stats, TX rate configuration/query, TX power/RF antenna, MAC address, deauthentication/adhoc stop, key material v1/v2, 11d domain info, version extension, remain-on-channel, P2P mode, memory/register/EEPROM access, IBSS coalescing, TDLS operation, event subscription, UAP station list, config data, SDIO RX aggregation config, robust coexistence, channel-region regulatory data, packet aggregation control, and STA channel info. It delegates scan, association, adhoc, 11n, WMM, host-sleep, wakeup reason, and hardware-spec responses to helpers in neighboring files.

Control flow: `mwifiex_process_sta_cmdresp()` retrieves `adapter->curr_cmd->data_buf`, checks `resp->result`, routes failures through `mwifiex_process_cmdresp_error()`, and switches on the command number for success parsing. Many handlers convert little-endian firmware fields to CPU values, copy values into output buffers, and update cached driver state. Some response handlers queue follow-up commands: rate config can issue a TX rate query when fixed-rate mode is active, RSSI threshold events resubscribe after a low/high threshold event, and bad hardware revision detection in version extension sends an auto-deep-sleep disable command. Reconfigure-TX-buffer responses update adapter buffer sizing and call `if_ops.update_mp_end_port()` so SDIO can adjust the port window.

State and persistence: Persistent updates include RSSI/NF averages, rate bitmaps and fixed/auto data-rate flags, current TX rate/HT info, TX power min/max/current levels, RF antenna modes, current MAC address, WPA GTK/port-open/scan-block state, cached AES key material, memory/register readback caches, IBSS BSSID/beacon/ERP/adhoc state, TDLS node setup status, UAP station RSSI, SDIO RX aggregation enable/block size, custom regulatory domain pointer in `adapter->regd`, bus aggregation parameters and interface header length, TX buffer size/current size, UAP BSS started flag, power-save and host-sleep state through delegated handlers, and command wait status on failures.

Dependencies and integration points: Depends on the current command node owned by common command/event code, cfg80211 scheduled scan notifications, regulatory structures (`ieee80211_regdomain` and reg rules), mwifiex station tables, TDLS helpers, WMM/11n/11ac/scan/join response helpers, and bus `if_ops` for MP end-port updates. It directly integrates with `sdio.c` through `HostCmd_CMD_SDIO_SP_RX_AGGR_CFG` response parsing and through `HostCmd_CMD_RECONFIGURE_TX_BUFF`, which changes SDIO TX buffer and port mask behavior.

Risks: Response parsing trusts firmware-provided sizes enough to walk TLVs, so underflow/overflow checks around `resp->size`, TLV lengths, key lengths, EEPROM byte counts, and channel lists are critical. Regulatory-domain synthesis groups channel rules from firmware attributes; malformed or excessive channel data can fail allocation or produce wrong cfg80211 restrictions. Error handling recycles `adapter->curr_cmd` and clears it; callers must not use command data after failure. Key response handling only caches AES material for certain key types and opens the port on multicast key set, so security state depends on firmware flags matching expectations. Reconfigure-TX-buffer has bus-specific behavior and can affect SDIO aggregation immediately.

Test signals: Exercise success and failure responses for scan, PS mode, SDIO aggregation unsupported, key installation, TX rate fixed versus auto, TX power query/set, EEPROM length limits, channel-region TLV parsing, TX buffer reconfiguration and MP end-port update, TDLS failure reasons, UAP station list RSSI updates, RSSI CQM threshold resubscription, and command wait queue status on firmware errors. Integration traces should show `adapter->curr_cmd` cleanup on errors and expected follow-up commands after rate/RSSI/version responses.
