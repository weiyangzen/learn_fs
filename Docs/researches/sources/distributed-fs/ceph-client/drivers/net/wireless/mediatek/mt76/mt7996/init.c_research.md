# sources/distributed-fs/ceph-client/drivers/net/wireless/mediatek/mt76/mt7996/init.c

Purpose: Initializes and registers the MediaTek mt7996/mt7992/mt7990 Wi-Fi device family with mt76 and mac80211. It publishes wiphy/mac80211 capabilities, configures per-band PHY capability data, initializes DMA/MCU/EEPROM/RRO/WED/NPU-facing resources, sets thermal and LED integration, and tears those resources down on unregister.

Important APIs, types, and functions: `mt7996_register_device()` is the main device registration path after PCI/MMIO setup. `mt7996_init_hardware()` performs low-level bring-up: interrupt cleanup, work/list/lock initialization, variant detection, DMA initialization, MCU initialization, RRO allocation, FEM/eeprom parsing, and global WCID allocation. `mt7996_init_wiphy()` and `mt7996_init_wiphy_band()` populate `struct ieee80211_hw`, `struct wiphy`, `struct wiphy_radio`, and supported band data. `mt7996_register_phy()` allocates and registers secondary radios. `mt7996_mac_init()`, `mt7996_txbf_init()`, `mt7996_init_txpower()`, `mt7996_set_stream_vht_txbf_caps()`, and `mt7996_set_stream_he_eht_caps()` configure MAC registers and advertised HT/VHT/HE/EHT capabilities. Thermal entry points expose hwmon attributes and `thermal_cooling_device_ops`. RRO/WED helpers include `mt7996_wed_rro_init()`, `mt7996_rro_hw_init()`, `mt7996_wed_rro_work()`, and `mt7996_wed_rro_free()`.

Control flow: Registration initializes embedded `dev->phy`, work items (`init_work`, reset/dump work elsewhere), rate-control and TWT lists, reset waitqueue, and dump mutex. Hardware bring-up first prepares DMA and MCU, then allocates host-side RRO memory before reading EEPROM and reserving global WCID 0. Wiphy setup advertises interface combinations, MLO, multi-BSSID, scan limits, offloads, radiotap timestamps, hardware queue counts, and per-band frequency ranges. Secondary PHY registration validates band availability, chooses HIF/WED context for the band, allocates an mt76 radio, derives MAC address from EEPROM with local fallback, configures band capabilities, initializes TX rings or shares an existing ring in selected mt7996/NPU modes, and registers with mt76. After device registration, thermal devices are attached per PHY, `init_work` pushes EEPROM, MAC, TXBF, and duplicate WTBL setup to firmware, and debugfs/coredump registration completes the path. Unregister cancels work, removes thermal/coredump hooks, unregisters mt76, frees RRO memory, exits MCU, releases tokens, cleans DMA, frees RRO page maps when needed, disables IRQ tasklet, and frees the mt76 device.

State and persistence behavior: The file mutates durable runtime driver state in `struct mt7996_dev`, `struct mt7996_phy`, and nested mt76 structures: variant type/FEM, `has_eht`, radio arrays, chain/antenna masks, wiphy feature flags, iface combinations, txpower per channel, WCID masks, WED RRO coherent allocations, RRO page cache/list heads, thermal throttle thresholds/states, cooling-device pointer, and LED callbacks. EEPROM-derived MAC addresses and power limits are read from device storage but only cached in runtime structures. DMA coherent RRO buffers persist until explicit unregister/free. Thermal sysfs writes update `phy->throttle_temp[]` and immediately send MCU thermal protection state.

Dependencies and integration points: The implementation sits between Linux mac80211/cfg80211 (`ieee80211_hw`, `wiphy`, bands, interface combinations, EHT/HE/VHT capabilities), mt76 core allocation/registration/DMA/token helpers, MediaTek WED/NPU acceleration, MCU command helpers from `mcu.h`, EEPROM accessors from `eeprom.h`, coredump support, hwmon/thermal subsystems, OF property parsing, and register macros in mt7996 headers. WED RRO setup passes physical addresses to WED/NPU when active and programs RRO host registers directly. Regulatory changes flow through `mt7996_regd_notifier()`, which updates alpha2/DFS region, tx power, DFS state, and radar detector programming.

Risks and edge cases: Bring-up is heavily ordered: DMA, MCU, WED RRO allocation, EEPROM, and WCID reservation must succeed before registration can continue. Error unwinds in `mt7996_register_phy()` clear `phys[band]` but rely on caller/device teardown for previously allocated resources. Capability publication is variant- and band-dependent; wrong `is_mt7996/is_mt7992/is_mt7990` branches can advertise unsupported MLO, EHT, 320 MHz, TXBF, or ring topology. RRO coherent allocation has multiple optional arrays whose hardware programming differs by HWRRO v3/v3.1, WED, and NPU mode. Thermal threshold validation enforces a 10 degree margin, so sysfs boundary tests matter. `mt7996_wed_rro_work()` resets session memory under spin/list coordination and must not race unregister or hardware reset. Global and per-phy interface combination limits must match firmware WTBL/resource limits.

Test signals: Useful validation includes probe/register/unregister on mt7996, mt7992, and mt7990 variants; secondary PHY registration for all valid/invalid band masks; WED active/inactive and NPU active/inactive paths; HWRRO v3 and v3.1 allocation and register programming; thermal hwmon reads/writes and cooling state changes; regulatory notifier with DFS unset/FCC/ETSI/JP; TX power recalculation from EEPROM/regulatory limits; LED blink/brightness callbacks; coredump/debugfs registration failure unwind; and module remove after active RRO sessions/tokens.
