# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/carl9170/debug.c

## Purpose

`debug.c` implements the carl9170 driver's debugfs surface. It exposes live USB, TX, aggregation, power-save, virtual interface, PHY noise, register, and firmware restart diagnostics, and it provides controlled writable debug hooks for register reads/writes, ERP mode, and forced restart/reset actions.

## Important APIs, Types, and Functions

The central adapter is `struct carl9170_debugfs_fops`, which records buffer sizing, permissions, callbacks, and the minimum device state for a debugfs file. `carl9170_debugfs_read()` and `carl9170_debugfs_write()` are the common file operations used by `debugfs_create_file_aux()`. Read helpers include `mem_usage`, `qos_stat`, `ampdu_state`, queue dumps, `sta_psm`, `tx_stuck`, `phy_noise`, `vif_dump`, and hardware register/tally files generated by macros. Writable paths are `hw_ioread32`, `hw_iowrite32`, `bug`, and `erp`. Public lifecycle functions are `carl9170_debugfs_register()` and `carl9170_debugfs_unregister()`.

## Control Flow

Registration creates a debugfs directory under the wiphy debugfs root, then instantiates all static files through `DEBUGFS_ADD()`. A read validates `file->private_data`, finds aux ops, allocates an optional vmalloc buffer, locks `ar->mutex`, checks the requested device state, runs the per-file callback, and copies the result to userspace. A write caps payloads at one page, copies from userspace, uses `mutex_trylock()` to avoid blocking debug writers behind driver work, checks state, and invokes the write callback. Register reads queue results into `ar->debug.ring`; the read side drains that ring.

## State and Persistence Behavior

Most files are observational but several mutate state. Hardware tally reads add current counters into `ar->debug.stats.*_sum`. `tx_stuck` clears `max_queue_stop_timeout[]` after reporting. `hw_ioread32` advances debug ring head/tail; `hw_iowrite32` writes arbitrary aligned device registers in an allowed address range. `bug` can set `needs_full_reset`, clear it, trigger MAC reset, reinitialize PHY/channel, or schedule restart. `erp` updates `ar->erp_mode`.

## Dependencies and Integration Points

This file depends on carl9170 core state in `struct ar9170`, command helpers from `cmd.h`, queue/aggregation structures from TX paths, PHY noise collection, MAC reset/channel helpers, and register tables declared in `debug.h`. It integrates with Linux debugfs, userspace read semantics, VM allocation, user-copy helpers, mutexes, spinlocks, RCU, SKB queues, and mac80211 queue state.

## Risks and Edge Cases

The writable register interface is intentionally powerful and can destabilize hardware despite range/alignment checks. The read path warns if a fixed-buffer callback returns a different buffer, but dynamically allocated hardware-register/tally callbacks return their own vmalloc buffer and rely on the common free path. `bug` is available from the stopped state and can request resets during fragile lifecycle phases. Debug queue formatting walks live SKB data and aggregation state, so locking discipline around SKB lifetime is important.

## Test Signals

Build with `CONFIG_CARL9170_DEBUGFS`; mount debugfs and verify every registered file appears. Exercise reads while started and stopped to confirm `req_dev_state` behavior. Validate `hw_ioread32` rejects oversized, unaligned, and out-of-range requests. Confirm tally reads accumulate, `tx_stuck` resets maxima, `phy_noise` updates survey noise, and `bug` actions schedule expected restart or MAC/PHY operations without deadlocking `ar->mutex`.
