# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtw89/rtw8851b.c

## Purpose

`rtw8851b.c` is the RTL8851B chip descriptor and chip-operation implementation for rtw89. It defines hardware queue and memory geometry, firmware naming, interrupt/register layouts, efuse and phycap parsing, power sequencing, channel programming, baseband setup/reset, TX power setup, Bluetooth coexistence hooks, PPDU reporting, and the exported `rtw8851b_chip_info`.

## Important APIs, Types, And Functions

The central public object is `const struct rtw89_chip_info rtw8851b_chip_info`, which points to `rtw8851b_chip_ops`. Important ops include power on/off, BB/RF enable/disable, efuse/phycap parsing, channel setup, RFK init/channel/scan/track callbacks, TX power callbacks, BTC callbacks, RX descriptor/TX descriptor helpers, and PPDU query. Static data tables describe HFC/DLE layouts for PCIe and USB, IMR/page registers, RF-kill GPIO, DIG/EDCCA registers, BTC thresholds, and firmware metadata.

## Control Flow

Power-on clears suspend/LPS gates, waits for system power readiness, toggles platform enable, configures XTAL SI paths, releases isolation, reads chip version when needed, and enables DMAC/CMAC blocks. Power-off reverses RF/XTAL state and diverges for PCIe vs USB low-power behavior.

Efuse parsing fills country code, TSSI, RX gain offsets, bus-specific MAC address, RFE type, and XTAL trim. Phycap parsing fills TSSI trim, thermal/PA bias trims, gain compensation, and ADC timing. Channel setup calls MAC, BB, and RF setup in order. RFK orchestration initializes LCK/DPK/AACK/RCK/DACK/RX-DCK, runs per-channel RX-DCK/IQK/TSSI/DPK with BTC notifications, and tracks DPK/LCK periodically.

## State And Persistence Behavior

The file populates `rtwdev->efuse`, `rtwdev->tssi`, `rtwdev->efuse_gain`, `rtwdev->pwr_trim`, `rtwdev->hal`, `rtwdev->btc`, baseband gain caches, and `is_tssi_mode`. Persistent inputs are efuse and phycap data; most outputs are volatile hardware register state that lasts until reset, retune, or power-cycle.

## Dependencies And Integration Points

It includes common rtw89 core, MAC, PHY, firmware, efuse, txrx, utility, and coexistence helpers. It consumes RFK wrappers from `rtw8851b_rfk.h` and register tables from `rtw8851b_table.h`/`rtw8851b_rfk_table.h`. The exported chip info is the bus-driver integration point.

## Risks

Power sequencing is order- and timeout-sensitive. Efuse MAC parsing depends on HCI type. Much code assumes one RF/BB path. Channel switching relies on stop/restore ordering for TX scheduler, PPDU status, TSSI, ADC, and BB reset. BTC RFE interpretation depends on versioned structures and `rfe_type` semantics. Spur/NBI/CSI logic has hard-coded channel cases.

## Test Signals

Probe and power-cycle logs, firmware load, efuse/phycap dump comparison, channel switching across 2G/5G and 20/40/80 MHz, TX power programming, WoWLAN exposure under `CONFIG_PM`, BTC behavior for shared/dedicated antenna RFE types, PPDU signal/frequency reporting, RFK logs, and suspend/resume or USB/PCIe power-off paths are strong signals.
