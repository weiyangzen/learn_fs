# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/ctxt-info-v2.c

Purpose: Builds, kicks, and frees PCIe context-info v2 firmware self-load structures for newer Intel devices, including PRPH scratch/control data, PRPH info, IML image DMA, debug monitor destinations, PNVM payload DRAM, and reduced-power payload DRAM.

Important APIs/functions: `iwl_pcie_ctxt_info_v2_alloc()` allocates and initializes PRPH scratch, firmware sections, PRPH info, context-info v2, and IML DMA. `iwl_pcie_ctxt_info_v2_kick()` writes context/IML addresses and size to CSR registers and enables automatic boot. `iwl_pcie_ctxt_info_v2_free()` tears down IML, firmware image DMA, and optionally context/scratch/info memory depending on whether firmware is alive. PNVM/reduced-power paths are `iwl_trans_pcie_ctx_info_v2_load_pnvm()`, `iwl_trans_pcie_ctx_info_v2_set_pnvm()`, `iwl_trans_pcie_ctx_info_v2_load_reduce_power()`, and `iwl_trans_pcie_ctx_info_v2_set_reduce_power()`.

Debug and allocation behavior: `iwl_pcie_ctxt_info_dbg_enable()` chooses early debug destination from legacy destination TLVs or INI allocation config, supporting internal SRAM, NPK/TB22DTF, or DRAM monitor buffers, and sets scratch debug flags plus DRAM base/size/token when applicable. A DMI allowlist for Dell/Alienware gates `IWL_PRPH_SCRATCH_SCU_FORCE_ACTIVE` on GL MAC type. Control flags encode RX buffer size, MTR mode/format, IMR debug, top reset, URM policy, and external 32 kHz clock validity.

Control flow: Allocation rejects default RX buffer size, derives command queue size, allocates scratch first, fills version/control/RBD/STEP/debug fields, calls shared `iwl_pcie_init_fw_sec()` to copy LMAC/UMAC/paging firmware sections into DMA and write scratch DRAM pointers, allocates a page for PRPH info plus dummy tail pointers, allocates context-info v2 and points it to scratch/info/RX/TX command ring structures, then allocates and copies the IML image. Kick enables context-info load interrupts, writes `CSR_CTXT_INFO_ADDR`, `CSR_IML_DATA_ADDR`, `CSR_IML_SIZE_ADDR`, and sets `CSR_AUTO_FUNC_BOOT_ENA`.

PNVM/reduced-power flow: Payloads are loaded only once and only for AX210 or newer. Fragmented-capable firmware gets a descriptor-array DMA object plus one DMA block per chunk; non-fragmented firmware expects exactly two payload chunks and concatenates them into one DMA block with overflow checks. Setters write either descriptor-array base plus total region size or contiguous base/size into PRPH scratch `pnvm_cfg` or `reduce_power_cfg`.

State and persistence: Mutates `trans_pcie->ctxt_info_v2`, `prph_info`, `prph_scratch`, `iml`, associated DMA addresses/lengths, `trans->init_dram`, `trans_pcie->pnvm_data`, `trans_pcie->reduced_tables_data`, and flags `trans->pnvm_loaded`/`trans->reduce_power_loaded`. When firmware reaches alive, context-info v2 and PRPH scratch are intentionally retained for later PNVM load; non-alive free releases them. PRPH info is documented as lifetime-needed.

Dependencies/integration: Uses shared DMA helpers from `ctxt-info.c`, context-info v2 firmware structs, PCIe transport private state from `gen1_2/internal.h`, firmware capabilities, PNVM image structures, DMI matching, debug/INI state, CSR/PRPH register helpers, and firmware image section layout.

Risks: Error paths in allocation free the top-level scratch/info/context objects but rely on later shared cleanup for firmware-section DMA already allocated by `iwl_pcie_init_fw_sec()`. PNVM setters assume successful prior load and valid scratch. Fragmented descriptor arrays must be large enough for `n_chunks` as defined by firmware structs. The non-fragmented path hard-requires two chunks. `control_flags_ext` is tested for `IWL_PRPH_SCRATCH_EXT_EXT_FSEQ` but this file does not set that bit. Lifetime split in `iwl_pcie_ctxt_info_v2_free(alive)` is subtle and can leak or use-after-free if call sites pass the wrong alive state.

Test signals: Cover RX buffer sizes, AX210 gating, DMI SCU force-active match/non-match, top reset, debug destinations for legacy and INI configs, allocation failures at each DMA stage, IML copy, CSR kick register writes, alive vs non-alive free, fragmented PNVM/reduced-power load with multiple chunks, contiguous two-chunk load and overflow, no-payload `-EINVAL`, duplicate-load no-op, busy scratch config `-EBUSY`, and PRPH scratch base/size fields after setters.
