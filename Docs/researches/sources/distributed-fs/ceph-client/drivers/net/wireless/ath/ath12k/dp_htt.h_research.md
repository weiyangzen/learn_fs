# sources/distributed-fs/ceph-client/drivers/net/wireless/ath/ath12k/dp_htt.h

Purpose: Defines the ath12k HTT host-target protocol constants, bitfields, command/event structs, PPDU stats TLVs, RX/TX monitor filter formats, peer map/unmap messages, MLO timestamp offset message, extended stats request format, and function prototypes implemented by `dp_htt.c`.

Important APIs and types: H2T definitions include TCL metadata fields, `htt_h2t_msg_type`, version request options, `htt_srng_ring_type`, `htt_srng_ring_id`, `htt_srng_setup_cmd`, `htt_ppdu_stats_cfg_cmd`, `htt_rx_ring_selection_cfg_cmd`, `htt_rx_ring_tlv_filter`, `htt_tx_ring_selection_cfg_cmd`, `htt_tx_ring_tlv_filter`, and `htt_ext_stats_cfg_cmd`. T2H definitions include `htt_t2h_msg_type`, version/peer map/unmap messages, `htt_resp_msg`, vdev periodic stats structs, `ath12k_htt_ppdu_stats_msg`, generic `htt_tlv`, PPDU common/user/rate/completion/ack-BA structs, `htt_ppdu_stats_info`, and `ath12k_htt_mlo_offset_msg`. Public prototypes expose HTT connect, SRNG setup, T2H handler, TLV iterator, version/PPDU/ext stats requests, RX/TX filter setup, and monitor ring config.

Control flow: The header itself is declarative. It provides the binary layouts that `dp_htt.c` packs before `ath12k_htc_send()` and unpacks after HTC RX. Message IDs drive dispatch: H2T setup/config messages go host-to-firmware, while T2H version, peer map/unmap, PPDU stats, ext stats, and MLO offset messages return to host handlers. Bitfield macros are used to encode/decode little-endian dwords without ad hoc shifts.

State and persistence: No direct runtime state is owned here. The structures model firmware-visible persistent configuration for rings and filters, transient HTT request/response packets, and PPDU/vdev stats snapshots. TCL metadata constants influence every transmitted frame's metadata and therefore must remain stable with firmware expectations.

Dependencies and integration points: Used by `dp.h`, `dp.c`, `dp_htt.c`, TX/RX datapath code, debugfs stats, monitor setup, peer mapping, and mac80211 rate reporting. It depends on kernel bitfield helpers, endian types, sk_buff/base type declarations from including files, and the Qualcomm firmware HTT ABI.

Risks: This is another firmware ABI header; bit positions, enum values, struct packing, and endian annotations are critical. Several filter macro names contain legacy misspellings (`FLASG`) that are referenced by code. Ring size in `htt_srng_setup_cmd` is encoded in 4-byte words and loop-count disabling differs for SW-to-HW rings; confusing bytes versus words breaks target setup. `HTT_PPDU_STATS_MAX_USERS` and PPDU tag bitmasks must match firmware or parser list indexing fails. Duplicate macro definitions for TX ring info0 fields increase maintenance risk. The HTT target major version is pinned to 3.

Test signals: Compile all HTT users; static assert or runtime validate struct sizes against firmware interface docs where possible; run SRNG setup and RX/TX filter setup on supported chips; verify TCL metadata version negotiation for normal and FTM modes; parse PPDU stats with all supported tag combinations; confirm peer map v1/v2/v3 decode; exercise MLO offset events; and compare HTT command dumps against firmware traces.
