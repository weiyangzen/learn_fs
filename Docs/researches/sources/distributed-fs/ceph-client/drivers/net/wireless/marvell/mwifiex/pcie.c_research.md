# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/pcie.c

Purpose: Implements the mwifiex PCIe bus backend for Marvell/NXP Wi-Fi devices. It binds PCI IDs for 88W8766P, 88W8897, and 88W8997 devices, maps BARs, allocates DMA rings, downloads firmware, moves command/data/event traffic between the common mwifiex core and firmware, handles power-management wake/suspend, supports PCI reset recovery, and exposes PCIe-specific firmware/register dump hooks.

Important APIs and functions: The file installs `pcie_ops`, a `struct mwifiex_if_ops` consumed by the common core. Core lifecycle entry points are `mwifiex_init_pcie()`, `mwifiex_cleanup_pcie()`, `mwifiex_register_dev()`, `mwifiex_unregister_dev()`, `mwifiex_pcie_up_dev()`, and `mwifiex_pcie_down_dev()`. PCI driver callbacks are `mwifiex_pcie_probe()`, `mwifiex_pcie_remove()`, suspend/resume hooks, shutdown, coredump, and PCI error reset callbacks. Data path helpers include `mwifiex_pcie_host_to_card()`, `mwifiex_pcie_send_data()`, `mwifiex_pcie_send_data_complete()`, `mwifiex_pcie_process_recv_data()`, `mwifiex_pcie_send_cmd()`, `mwifiex_pcie_process_cmd_complete()`, `mwifiex_pcie_process_event_ready()`, and `mwifiex_pcie_event_complete()`. Firmware/reset helpers include `mwifiex_prog_fw_w_helper()`, `mwifiex_extract_wifi_fw()`, `mwifiex_check_fw_status()`, `mwifiex_pcie_card_reset()`, `mwifiex_pcie_reg_dump()`, and `mwifiex_pcie_fw_dump()`.

Control flow: Probe allocates `struct pcie_service_card`, copies chip-specific register/device metadata from `driver_data`, validates an optional device-tree compatible string, initializes platform quirks, and calls `mwifiex_add_card()` with `pcie_ops`. Interface init enables PCI, sets bus mastering and 32-bit coherent DMA, requests/iomaps BAR 0 and BAR 2, allocates TX/RX/event rings plus command response and optional sleep-cookie buffers, then records 8897 Bluetooth coexistence behavior. Firmware download disables host interrupts, polls boot-helper command size, maps a staging skb, writes command DMA address/size scratch registers, rings `CPU_INTR_DOOR_BELL`, waits for acknowledgement, retries CRC-indicated blocks, and handles the FLR scratch marker by extracting the Wi-Fi subimage from combo firmware. Runtime IRQ handling records interrupt status in `adapter->int_status`, queues mwifiex main work, then `mwifiex_process_int_status()` dispatches download completion, upload data, events, and command responses.

State and persistence: `pcie_service_card` owns all PCIe state: PCI device, adapter pointer, chip register profile, completion for firmware load, coherent ring bases, software ring pointers, skb arrays, command/response buffers, sleep cookie DMA memory, BAR mappings, MSI/MSI-X state, deferred work flags, reset state, and DMI quirk bits. Ring ownership is split with firmware: the driver advances TX write/RX read/event read pointers while firmware advances the complementary pointers. TX and RX descriptors use either legacy `mwifiex_pcie_buf_desc` or PFU `mwifiex_pfu_buf_desc` layout based on chip metadata. DMA mappings are stored in skb control metadata and are unmapped only when firmware consumes or returns the buffer. Adapter state touched here includes `data_sent`, `cmd_sent`, `cmd_resp_received`, `event_received`, `event_skb`, `tx_hw_pending`, `rx_pending`, power-save state, firmware dump buffers, and scan capability advertised via `adapter->ext_scan`.

Dependencies and integration points: This backend depends on Linux PCI, DMA, IRQ, firmware, PM sleep, and cfg80211-facing mwifiex core infrastructure. It uses mwifiex common helpers from `decl.h`, `main.h`, `fw.h`, `wmm.h`, `11n.h`, and `util.h`; common core calls into `pcie_ops` for bus work while this file calls back into core functions such as `mwifiex_add_card()`, `mwifiex_remove_card()`, `mwifiex_send_cmd()`, `mwifiex_write_data_complete()`, `mwifiex_handle_rx_packet()`, `mwifiex_process_sleep_confirm_resp()`, `mwifiex_shutdown_sw()`, and `mwifiex_reinit_sw()`. PCI reset integrates with `pcie_quirks.c` through `QUIRK_FW_RST_D3COLD` and `mwifiex_pcie_reset_d3cold_quirk()`.

Risks and edge cases: The highest-risk areas are ring pointer wrap semantics differing by chip, DMA mapping lifetime for skb buffers handed to firmware, command-response buffer ownership transfer to `curr_cmd`, and event buffer recycling delayed until event completion. Several paths return after allocation or mapping failures with partially consumed ring entries, so cleanup symmetry matters. The wake path relies on firmware interrupts appearing after writing `fw_status`, with a long retry path for 88W8897 firmware. Firmware parsing has overflow guards, but malformed combo images and command-size values are fatal. Reset cleanup avoids `cancel_work_sync()` during reset failure because it can deadlock. The MSIX error unwind appears delicate because it frees previous vectors while indexing context storage, and firmware dump reallocation must avoid overrunning preallocated memory.

Test signals: Build with PCI, PM sleep, MSI, and non-MSI paths. Exercise probe/remove for each PCI ID, firmware name selection by revision/magic/version, firmware download retry and FLR combo-image extraction, suspend/resume host-sleep transitions, wake from sleep-cookie and non-cookie devices, shared IRQ/MSI/MSI-X interrupt processing, TX ring full and flush behavior, RX invalid-length rejection, command completion with and without `curr_cmd`, event recycling, coredump work, firmware dump for 8897/8997 memory maps, PCI FLR reset, D3cold Surface quirk reset, and cleanup after every ring/buffer allocation failure.
