## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/location.h

`location.h` defines the firmware ABI for Wi-Fi location features, especially 802.11mc/11az FTM/ToF ranging, FTM responder mode, LCI/Civic location data, MCSI debug capture, responder statistics, and CSI chunk notifications. It depends on Linux 802.11 and Ethernet constants (`IEEE80211_CCMP_PN_LEN`, `ETH_ALEN`), common integer/bit helpers, and `rs.h` for antenna mask definitions used in responder flags.

The central API surface starts with `enum iwl_location_subcmd_ids`, mapping the location command group to firmware commands and notifications: range request/config/abort/extended request, responder static and dynamic configuration, LCI/Civic notification, responder stats, MCSI debug, CSI header/chunk notifications, and range response notification. The command structures are heavily versioned. Responder configuration progresses from `iwl_tof_responder_config_cmd_v6` through the current `iwl_tof_responder_config_cmd`, adding `format_bw`, NDP/LTF parameters, BSS color, band, and min/max non-triggered measurement timing. Dynamic responder configuration similarly evolves from variable LCI/Civic data in `iwl_tof_responder_dyn_config_cmd_v2` to fixed LCI/Civic buffers plus secure PASN/HGTK/cipher station data in `iwl_tof_responder_dyn_config_cmd`.

Initiator ranging is modeled as a top-level `iwl_tof_range_req_cmd*` containing up to `IWL_TOF_MAX_APS` per-AP entries. Per-AP entries evolve from basic channel/BSSID/FTM parameters in `iwl_tof_range_req_ap_entry_v2` to the current `iwl_tof_range_req_ap_entry`, which carries band, packed format/bandwidth, BSSID, burst settings, station/cipher IDs, HLTK/TK keys, calibration per bandwidth, beacon interval, PMF packet numbers, NDP negotiation parameters, and minimum measurement interval. Flags in `enum iwl_initiator_ap_flags` select ASAP, LCI/Civic, dynamic ACK, LR/FFT algorithms, MCSI reporting, trigger/non-trigger ranging, secure LTF, LMR feedback, calibration override, PMF, and negative test behavior.

There are no in-file functions; runtime flow is driver-selected ABI construction: configure global ToF state, optionally configure responder/static/dynamic state, send a range request with a unique `request_id`, optionally abort with `iwl_tof_range_abort_cmd`, then parse `TOF_RANGE_RESPONSE_NOTIF` using the notification version advertised by firmware. Response structures carry session status, per-AP measurement status, RTT/range/variance/spread, RSSI, refusal periods, timing clocks, calibration values, rate fields, confidence, and PMF PNs. State is not persisted by this header, but it defines state identifiers that higher layers must persist while a measurement is active: request IDs, per-AP station IDs, BSSID keys, PMF PN state, responder valid-field masks, and LCI/Civic/PASN credentials.

Integration points are `iwl_mvm` location/ranging code, mac80211 FTM APIs, firmware command-version dispatch, and debug/trace code that decodes MCSI/CSI/stat notifications. Risks are ABI mismatch between firmware command versions, packed bitfield mistakes in `format_bw` and NDP/LTF fields, off-by-one or length validation errors around variable CSI/data buffers, leaking or mishandling 11az keys/PNs, and confusing similarly named v8/v9 comments. Test signals include compile-time struct layout checks where available, firmware API version negotiation tests, FTM initiator/responder interoperability, abort/timeout paths, multi-AP result parsing, PMF/secure ranging replay counter tests, and malformed notification length handling.
