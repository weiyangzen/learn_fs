## sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/fw/api/mac.h

`mac.h` is the common, older MAC-context firmware ABI used directly by legacy commands and indirectly by newer MLD APIs such as `mac-cfg.h` and `rs.h`. It defines MAC indices, station-count constants, access-category indexes, MAC types, TSF timer IDs, MAC-role-specific data unions, filtering/protection/QoS flags, HE/EHT station context payloads, missed beacon notifications, and HE monitor configuration.

Core types include `enum iwl_ac`, `enum iwl_mac_types`, and `enum iwl_tsf_id`. Role-specific state is described through `iwl_mac_data_ap`, `iwl_mac_data_ibss`, `iwl_mac_data_sta`, `iwl_mac_data_go`, `iwl_mac_data_p2p_sta`, `iwl_mac_data_p2p_dev`, and `iwl_mac_data_pibss`. These carry beacon/DTIM timing, TSF values, association state, listen interval, data-policy bits, CT window, opportunistic power save, and beacon template IDs. `iwl_mac_ctx_cmd` combines the common MAC fields with a union of these role-specific structures for `MAC_CONTEXT_CMD`.

Filtering and QoS are represented by `enum iwl_mac_filter_flags`, `enum iwl_mac_qos_flags`, and `struct iwl_ac_qos`. These encode which frame classes are passed to the host, whether decryption/FCS/probe/beacon handling is altered, whether EDCA should be updated, and per-access-category contention windows, AIFSN, FIFO mask, and TXOP. `iwl_nonqos_seq_query_cmd` exposes get/set of non-QoS sequence state by MAC ID/color. Missed beacon notifications exist in v3 MAC-ID form and v4 link-ID form.

The HE/EHT portion defines MU EDCA backoff (`iwl_he_backoff_conf`), packet extension thresholds (`iwl_he_pkt_ext_v1` and v2), station context flags (`iwl_he_sta_ctxt_flags`), HTC flags, and versioned HE station context commands. These contexts pack data from multiple 802.11 information elements: multiple-BSSID, HE capabilities, PPE thresholds, HE operation, random access parameters, MU EDCA, EHT puncturing, and multi-BSSID profile metadata. `iwl_he_monitor_cmd` configures an HE air sniffer using BSSID and AID.

There is no executable control flow in this header. Runtime flow is context assembly: driver code computes role-specific timing/filter/QoS/HE state from mac80211 configuration, fills packed little-endian ABI structs, sends add/modify/remove actions, then interprets missed-beacon and related notifications. State and persistence are external but keyed by MAC ID/color, TSF ID, station IDs, beacon timing, HE capability flags, and AC parameters. Dependencies include Linux bit helpers, endian conversion in consumers, and shared `iwlwifi` context-action enums outside this file.

Risks are layout and version mismatches, union misuse for the wrong MAC type, confusion between legacy MAC and newer link-oriented identifiers, unvalidated EDCA/PPE/capability values from IEs, and subtle power/roaming behavior changes from filter or data-policy flags. Test signals include legacy STA/AP/P2P/IBSS context setup, HE/EHT association with PPE and BSS color, missed beacon notification decoding, non-QoS sequence query behavior, monitor/sniffer setup, and cross-checks that `mac-cfg.h` users still match shared structure sizes.
