# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/rx.c

Purpose: Implements the PCIe receive path and interrupt receive-side handling for Intel `iwlwifi` gen1/gen2 transport. It owns receive-buffer descriptor lifecycle, page allocation/reuse, RX DMA setup for legacy single-queue and RFH multi-queue hardware, NAPI polling, firmware response dispatch, command-completion reclaim, ICT interrupt-table support, RF-kill/error interrupt handling, and MSI-X shared-vector receive interrupt routing.

Important APIs, types, and functions: The core state is `struct iwl_rxq`, `struct iwl_rx_mem_buffer`, `struct iwl_rb_allocator`, `struct iwl_trans_pcie`, NAPI state, DMA coherent descriptor tables, and `trans->status` bits. Public transport entry points include `iwl_pcie_rx_stop()`, `iwl_pcie_rxq_alloc_rbs()`, `iwl_pcie_rx_allocator_work()`, `iwl_pcie_rx_init()`, `iwl_pcie_gen2_rx_init()`, `iwl_pcie_rx_free()`, `iwl_pcie_rx_napi_sync()`, `iwl_pcie_irq_rx_msix_handler()`, `iwl_pcie_irq_handler()`, `iwl_pcie_isr()`, `iwl_pcie_msix_isr()`, `iwl_pcie_irq_msix_handler()`, and ICT helpers `iwl_pcie_alloc_ict()`, `iwl_pcie_reset_ict()`, `iwl_pcie_disable_ict()`, `iwl_pcie_free_ict()`. Internal helpers split along hardware generation: `iwl_pcie_rx_hw_init()` programs legacy FH single-queue registers; `iwl_pcie_rx_mq_hw_init()` programs RFH multi-queue descriptors; `iwl_pcie_restock_bd()`, `iwl_pcie_rxmq_restock()`, and `iwl_pcie_rxsq_restock()` publish fresh buffers to firmware. `iwl_pcie_rx_handle()` is the NAPI receive engine, and `iwl_pcie_rx_handle_rb()` parses one receive buffer into one or more `iwl_rx_packet` objects.

Control flow: Initialization starts in `_iwl_pcie_rx_init()`, which allocates queue descriptors if needed, resets allocator counters/lists, frees old pool pages, initializes each RX queue, attaches/enables NAPI, assigns virtual RB IDs into `global_table`, and allocates pages into the default queue. `iwl_pcie_rx_init()` then programs FH/RFH hardware and restocks queue 0; `iwl_pcie_gen2_rx_init()` only initializes software state because gen2 firmware later configures RFH and the alive interrupt triggers restock. On receive interrupt, legacy IRQ handling disables/acknowledges interrupt causes, schedules queue 0 NAPI, and leaves final re-enable to poll completion. MSI-X routes per-RSS queues to `iwl_pcie_irq_rx_msix_handler()` and shared/default vectors to `iwl_pcie_irq_msix_handler()`. The NAPI poll function calls `iwl_pcie_rx_handle()`, which reads the closed read index from shared status, loops until the hardware index or budget is reached, maps used descriptors back to `iwl_rx_mem_buffer` objects, drops unsupported multi-RB fragments, dispatches packets to opmode via `iwl_op_mode_rx()` or `iwl_op_mode_rx_rss()`, completes host commands through `iwl_pcie_hcmd_complete()`, recycles or re-allocates pages, and finally restocks descriptors.

State and persistence behavior: RX state is mostly volatile kernel/PCIe runtime state backed by DMA memory. Descriptor rings (`bd`, `used_bd`, `rb_stts`) are coherent DMA allocations; actual packet pages are DMA-mapped and recycled through `rx_free`, `rx_used`, allocator `rbd_empty`, and allocator `rbd_allocated` lists. `rxb->vid` is the stable firmware-facing virtual buffer ID and indexes `global_table`; `rxb->invalid` prevents stale completion descriptors from reusing an already consumed buffer. Queue pointers (`read`, `write`, `write_actual`) persist across interrupt processing until reset/reinitialization. The background allocator persists pending/ready request counters in atomics and posts work to `rba.alloc_wq`. The ICT table is a coherent 4 KiB interrupt cause ring with `ict_index` and `use_ict` state. Interrupt statistics persist in `trans_pcie->isr_stats` until reset/debugfs clear.

Dependencies and integration points: The file depends on Linux DMA, pages, NAPI, IRQ threading, spinlocks, workqueues, wait queues, and the iwlwifi opmode/transport contracts. Hardware register access goes through CSR, FH, RFH, UMAC PRPH, and HBUS helpers from `iwl-io.h`, `iwl-prph.h`, and local transport internals. RX packet delivery integrates with mac80211-facing opmode callbacks; command responses integrate with the TX command queue and `wait_command_queue`. Error paths call `iwl_trans_fw_error()`, `iwl_force_nmi()`, `iwl_trans_schedule_reset()`, and opmode rfkill/error hooks. Gen2 startup in `trans-gen2.c` relies on `iwl_pcie_gen2_rx_init()` and alive-time restock; non-gen2 startup in `trans.c` relies on `iwl_pcie_rx_init()`.

Risks and edge cases: The code is highly sensitive to descriptor ring arithmetic, power-management races, and device-family register differences. `rxq->lock`, `rba->lock`, `irq_lock`, and NAPI context must be respected because buffers can move among queue, allocator, firmware, and opmode ownership. Page-stealing by opmode is tracked through `rxcb._page_stolen`; incorrect handling would double-free pages or reuse buffers still owned by upper layers. Emergency allocation paths exist when allocator backlog reaches half the queue; mistakes there can leak RBDs or strand them outside allocator accounting. Invalid VIDs force NMI because they indicate firmware or descriptor corruption. Multi-RB fragments are intentionally discarded because upper layers are not prepared for them. Interrupt handlers must avoid device access after APM stop, must re-enable the right interrupt subset depending on firmware-load/RF-kill/alive state, and must handle hardware-gone values without dereferencing invalid device state.

Test signals: Useful validation comes from RX traffic under legacy MSI and MSI-X/RSS modes, firmware boot alive notification with gen2 RFH restock, RF-kill toggles while opmode is up/down, suspend/resume wake interrupts, forced firmware/hardware error interrupts, and high-throughput receive with allocator pressure. Debug signals include `IWL_DEBUG_RX`, `IWL_DEBUG_ISR`, `IWL_DEBUG_TPT`, `isr_stats`, debugfs RX queue counters from `trans.c`, NAPI budget behavior, command response completion wakeups, ICT table index movement, and absence of DMA mapping/unmapping warnings or invalid VID NMIs.
