# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/pcie/gen1_2/tx-gen2.c

Purpose: Implements gen2 PCIe transmit queues for data frames and host commands. It builds TFH transmit frame descriptors, maps skb/head/fragments/TSO pages to DMA transfer buffers, handles a 4 GiB boundary hardware workaround, maintains scheduler byte-count tables, advances hardware write pointers, allocates/frees dynamic firmware-managed queues, and enqueues firmware host commands on the command queue.

Important APIs, types, and functions: Key public functions are `iwl_txq_space()`, `iwl_txq_gen2_set_tb()`, `iwl_txq_gen2_tfd_unmap()`, `iwl_txq_gen2_tx()`, `iwl_txq_dyn_alloc()`, `iwl_txq_dyn_free()`, `iwl_txq_gen2_tx_free()`, `iwl_txq_gen2_init()`, and `iwl_pcie_gen2_enqueue_hcmd()`. Internal helpers include `get_workaround_page()`, `iwl_txq_gen2_set_tb_with_wa()`, A-MSDU builders, fragment builders, `iwl_pcie_gen2_update_byte_tbl()`, `iwl_txq_gen2_free_tfd()`, `iwl_txq_gen2_unmap()`, queue DMA allocation/free helpers, and firmware queue-allocation response parsing. Core types are `struct iwl_txq`, `struct iwl_tfh_tfd`, `struct iwl_tfh_tb`, `struct iwl_cmd_meta`, `struct iwl_device_tx_cmd`, `struct iwl_host_cmd`, `struct iwl_tx_queue_cfg_cmd`, `struct iwl_scd_queue_cfg_cmd`, skb fragments, and TSO page metadata.

Control flow: Data TX enters `iwl_txq_gen2_tx()`, validates queue range/use, linearizes excessive fragments, locks the queue, stops it when free space drops below high watermark, optionally parks packets in `overflow_q` if fewer than three slots remain, assigns skb/cmd metadata and firmware sequence, builds a TFD through `iwl_txq_gen2_build_tfd()`, updates byte-count table with command length and number of TBs, starts the stuck timer when transitioning from empty, advances `write_ptr`, and writes `HBUS_TARG_WRPTR`. TFD building splits into regular frame and GSO A-MSDU paths. Regular frames map first-TB command memory, command/header remainder, skb head payload, skb frags, and nested skb frags. GSO A-MSDU builds per-subframe Ethernet/SNAP/IP/TCP headers in TSO pages and maps payload pieces from the scatter-gather table. Host commands enter `iwl_pcie_gen2_enqueue_hcmd()`, calculate copied versus NOCOPY/DUP chunks, reserve command queue space, fill a wide command header, copy the debug-visible payload prefix, map copied and nocopy command buffers into TBs, set metadata, trace the command, and advance the command queue write pointer under `reg_lock`.

State and persistence behavior: TX queue state persists in circular `read_ptr`/`write_ptr`, `n_window`, `entries`, `tfds`, `first_tb_bufs`, byte-count table DMA memory, stopped/used bitmaps, overflow queue, watchdog timer, and per-entry `meta`/`skb`/`cmd`/`free_buf`. DMA mappings are recorded implicitly in each TFD TB plus metadata bits distinguishing page mappings from single mappings; `meta->sg_offset` marks TSO/SG ownership. `get_workaround_page()` chains temporary workaround pages through `skb->cb` using per-page `iwl_tso_page_info` reference counts. Dynamic queues are firmware-visible only after an SCD queue config command responds with a queue number/write pointer; `queue_used` prevents duplicate ownership. Command queue entries own allocated command buffers and sensitive duplicate buffers until reclaim/free.

Dependencies and integration points: The file depends on Linux skb, TCP segmentation offload helpers, DMA mapping APIs, queue timers, and iwlwifi transport internals. It integrates with `iwl_pcie_prep_tso()`, `iwl_pcie_free_tso_pages()`, shared TX queue allocation/init helpers, firmware SCD queue config APIs, opmode skb free callbacks, tracepoints, reset/error scheduling, and command completion from the RX path. Queue write pointers are written through HBUS target registers and byte-count tables consumed by firmware scheduler hardware.

Risks and edge cases: The biggest correctness risks are DMA lifetime and descriptor shape. The first TB is bidirectional command memory and is never unmapped by `iwl_txq_gen2_tfd_unmap()`, while later TBs require correct single/page unmap decisions. The 4 GiB boundary workaround copies small TBs to a separate page and has different cleanup semantics depending on whether the original mapping should be unmapped immediately or later. `iwl_txq_gen2_set_tb()` warns on boundary crossing and enforces `max_tbs`; callers that ignore errors can corrupt cleanup, so most paths unwind immediately. Host command NOCOPY chunks must not be followed by normal copied chunks, and DUP is allowed only once. Queue space logic reserves an empty slot and uses overflow behavior under pressure; incorrect high/low watermark behavior can stop queues permanently or overrun the ring. BZ A-step forces 4096-entry dynamic queues, while other hardware retries with smaller power-of-two queue sizes.

Test signals: Validate normal data TX, fragmented skb TX, nested skb frags, GSO A-MSDU, DMA mapping failure unwinds, 4 GiB boundary workaround path, queue high-water stop and overflow queue behavior, watchdog timer start/cancel, dynamic queue allocation command versions 0 and 3, queue allocation response validation, command queue full reset scheduling, NOCOPY/DUP host commands, and TX queue free while non-empty. Useful signals include `IWL_DEBUG_TX`, `IWL_DEBUG_TX_QUEUES`, `IWL_DEBUG_HC`, tracepoints for TX/TB/HCMD, byte-count table contents, queue-used bits, and absence of DMA unmap or too-many-TB warnings during teardown.
