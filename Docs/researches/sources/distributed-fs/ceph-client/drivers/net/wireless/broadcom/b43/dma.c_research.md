# sources/distributed-fs/ceph-client/drivers/net/wireless/broadcom/b43/dma.c

This file implements b43 DMA data transfer support: DMA engine detection, descriptor ring allocation, controller setup/reset, TX submission, TX status cleanup, RX polling/recycling, overflow handling, suspend/resume, and direct FIFO RX mode toggling for PIO interactions.

Important functions include 32/64-bit descriptor ops (`op32_*`, `op64_*`), `b43_engine_type()`, `b43_setup_dmaring()`, `dmacontroller_setup()`, `b43_dma_init()`, `b43_dma_free()`, `dma_tx_fragment()`, `b43_dma_tx()`, `b43_dma_handle_txstatus()`, `dma_rx()`, `b43_dma_rx()`, `b43_dma_handle_rx_overflow()`, `b43_dma_tx_suspend()`, `b43_dma_tx_resume()`, and `b43_dma_direct_fifo_rx()`. It also handles DMA address translation, mapping/unmapping, GFP_DMA fallback, RX buffer poisoning, TX cookies, and queue stop/wake decisions.

Initialization chooses 30/32/64-bit DMA, sets the DMA mask, computes bus translation, configures parity, creates five TX rings and one RX ring, allocates coherent ring memory, and pre-populates RX descriptors with mapped skbs. TX maps a generated firmware header plus payload into two descriptors, writes multicast cookies for DTIM traffic, pokes the controller, and stops mac80211 queues when slots run low. TX status parses the cookie, verifies in-order completion, can recover from one missed status pair, unmaps DMA buffers, frees bounce buffers, reports status to mac80211, updates slots, and schedules TX work. RX syncs buffers for CPU, validates length and poison markers, replaces descriptors, strips firmware offset, and passes frames to `b43_rx()`.

State lives in `struct b43_dmaring`: descriptor memory/cache, DMA base, slot counters, RX sizes, controller index/base/type, stopped state, queue priority, and per-descriptor metadata. Dependencies include Linux DMA APIs, mac80211 skb/status APIs, b43 MMIO, xmit helpers, RX/main helpers, BCMA/SSB DMA translation, and debugfs dynamic flags.

Risks are high: exact slot accounting, DMA mapping cleanup, bounce-buffer handling, RX recycling under allocation failure, poisoned-buffer handling, out-of-order TX statuses, queue stop/wake correctness, and hardware-specific ring alignment. Notable suspicious areas are the metadata poison initialization loop writing `ring->meta->skb` instead of each slot and queue wake logic that clears `tx_queue_stopped[prio]` without waking when it was true. Test signals include TX/RX under each AC queue, ring wrap/full recovery, constrained DMA-mask paths, multicast DTIM, RX overflow, poisoned/oversized RX drops, suspend/resume ordering, and teardown after partial init failure.
