# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_cmd.c

Purpose: Builds station-mode firmware commands for the mwifiex core. It translates driver, cfg80211, security, power-save, regulatory, TDLS, scan, aggregation, and device-tree/calibration requests into little-endian `host_cmd_ds_command` payloads and provides the station firmware initialization sequence.

Important APIs, types, and functions: Public entry points are `mwifiex_sta_prepare_cmd()`, `mwifiex_sta_init_cmd()`, `mwifiex_dnld_dt_cfgdata()`, and `mwifiex_send_rgpower_table()`. Command builders cover RSSI (`mwifiex_cmd_802_11_rssi_info()`), MAC control/address/multicast, SNMP MIBs, get-log, TX rate/power/RF antenna, host sleep, deauthentication and adhoc stop, key material v1/v2, 11d domain info, IBSS coalescing, memory/register/EEPROM access, PCIe descriptor setup, event subscription, MEF filters, calibration/config data, multi-channel policy, robust coexistence, GTK rekey offload, channel-region query, coalescing filters, TDLS config/oper, SDIO single-port RX aggregation, wakeup reason, and channel info. Module parameters `drcs` and `disable_auto_ds` affect multi-channel policy and auto deep sleep setup.

Control flow: `mwifiex_sta_prepare_cmd()` first rejects adhoc-only commands if firmware capability bits do not support adhoc, then dispatches by command number to a specific builder or inline payload fill. Builders set `cmd->command`, `cmd->size`, action fields, TLV headers, and endian-converted values. Many builders append variable TLVs by advancing a byte pointer and increasing `cmd->size`; examples include rate scope/drop pattern, host-sleep PS parameters and ARP filter, subscribe-event RSSI thresholds, coalescing rules, TDLS peer capabilities, config/calibration data, and key material. `mwifiex_sta_init_cmd()` issues the post-firmware sequence: optional PCIe host descriptors, function init, device-tree wake/caldata and firmware config data, hardware spec query, optional SDIO single-port RX aggregation command, TX buffer reconfiguration, station power save, optional DRCS policy, channel-region query, TX rate/power queries, AMSDU enable, MAC control, optional auto deep sleep, 11d enablement, optional packet aggregation, and 11n TX config.

State and persistence: This file mostly writes transient command buffers, but it also deliberately mutates driver state that persists beyond command submission. It resets RSSI averages before RSSI queries; updates `adapter->hw_status` for function init/shutdown; reads device-tree wakeup GPIO into `adapter->hs_cfg.gpio`; releases `adapter->cal_data` after config download; sets `adapter->ps_mode`, `adapter->drcs_enabled`, and requested auto deep sleep behavior during init; records WAPI group-key state in `priv->sec_info.wapi_key_on`; sets `adapter->hs_activated_manually` for manual host sleep activation; and uses `priv->sta_params`, security fields, WEP slots, and rate bitmaps as sources for outgoing firmware state.

Dependencies and integration points: Depends heavily on host command structures and constants from `fw.h`, mwifiex adapter/private state in `main.h`, helper command builders from scan/join/11n/11ac/WMM code, Linux cfg80211 types for keys and TDLS station parameters, device-tree property access for calibration data, and firmware command submission via `mwifiex_send_cmd()`. SDIO integration appears in `HostCmd_CMD_SDIO_SP_RX_AGGR_CFG`, which cooperates with `sdio.c` RX aggregation and `sta_cmdresp.c` response parsing. PCIe-specific setup is also present, so this station command dispatcher is shared across bus backends.

Risks: Variable-length TLV construction is sensitive to command buffer size, endian conversions, and exact firmware ABI layout. Key material handling has multiple branches for WEP, WAPI, TKIP, AES, CMAC/IGTK, unicast/multicast/default keys, UAP versus STA behavior, and firmware key API versions; subtle flag mistakes can break association or leak traffic before port opening. `mwifiex_send_rgpower_table()` parses raw hostcmd text and sends opaque firmware commands, so syntax and size checks are important. Some builders assume non-null `data_buf` for SET actions. Station initialization order is significant: MAC control is intentionally last among core init commands, and SDIO aggregation depends on firmware capability plus host allocation fallback state.

Test signals: Good signals include successful firmware initialization on SDIO and non-SDIO buses, expected command sizes and endian fields under sparse or maximal TLV input, key installation for WEP/WPA/WPA2/WAPI/IGTK paths, host-sleep configuration with and without ARP filters, device-tree and config-file calibration download, DRCS enablement only when supported, SDIO single-port RX aggregation command only when capability and host memory permit, TDLS create/config/delete commands with complete station parameters, and command rejection for adhoc operations when firmware lacks adhoc support.
