# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/dvm/agn.h

Purpose: Central public header for the legacy iwlwifi DVM/AGN opmode. It collects device constants, status-bit definitions, mac80211 entry points, firmware command send helpers, RXON/channel/scan/station/rate/calibration prototypes, small inline helpers, and debugfs registration stubs used across the DVM implementation.

Important APIs and definitions: The file exports `iwlagn_hw_ops`, DVM configuration objects for 1000/2000/5000/6000 families, queue constants such as `IWLAGN_FIRST_AMPDU_QUEUE`, `IWL_AUX_QUEUE`, and `IWL_INVALID_STATION`, and status bit indexes including `STATUS_READY`, `STATUS_ALIVE`, `STATUS_SCANNING`, `STATUS_FW_ERROR`, and `STATUS_POWER_PMI`. `iwl_set_calib_hdr()` initializes firmware calibration command headers. Command APIs are `iwl_dvm_send_cmd()` and `iwl_dvm_send_cmd_pdu()`. Runtime/probe APIs include `iwl_alloc_all()`, `iwlagn_mac_setup_register()`, `iwlagn_mac_unregister()`, `iwl_down()`, `iwl_cancel_deferred_work()`, `iwlagn_prepare_restart()`, and `iwl_rx_dispatch()`. RXON and association configuration are exposed through `iwl_connection_init_rx_config()`, `iwlagn_commit_rxon()`, `iwlagn_set_rxon_chain()`, `iwlagn_mac_config()`, `iwlagn_bss_info_changed()`, `iwl_set_rxon_ht()`, and related band/channel helpers. TX and aggregation entry points include `iwlagn_tx_skb()`, `iwlagn_tx_agg_start()`, `iwlagn_tx_agg_oper()`, `iwlagn_tx_agg_stop()`, `iwlagn_tx_agg_flush()`, `iwlagn_rx_reply_tx()`, and `iwlagn_rx_reply_compressed_ba()`. Station/key/rate helpers include `iwl_add_station_common()`, `iwl_send_add_sta()`, `iwl_remove_station()`, `iwl_set_dynamic_key()`, `iwl_remove_dynamic_key()`, `iwl_send_lq_cmd()`, `iwl_sta_rx_agg_start()`, `iwl_sta_rx_agg_stop()`, `iwl_sta_id()`, `iwl_ant_idx_to_flags()`, `iwl_hw_get_rate()`, and `iwl_hw_set_rate_n_flags()`.

Control flow: This header does not implement the driver lifecycle, but it defines the call graph shared by probe, mac80211 callbacks, firmware boot, scan, station management, TX/RX completion, calibration, and debugfs code. Status helpers gate operations on `priv->status`: `iwl_is_ready()` requires `STATUS_READY` and no `STATUS_EXIT_PENDING`, `iwl_is_alive()` checks firmware alive state, `iwl_is_rfkill()` and `iwl_is_ctkill()` distinguish hardware RF kill and critical-temperature kill, and `iwl_is_ready_rf()` combines readiness with RF-kill exclusion. `iwl_tx_status_to_mac80211()` maps firmware TX status codes to mac80211 ACK/filtered reporting, while `iwl_is_tx_success()` centralizes the firmware success predicate.

State and persistence: The header defines symbolic access to runtime state stored in `struct iwl_priv`: status bits, station IDs, NVM/EEPROM data, hardware bands, transport PMI state, RXON contexts, and per-station private data. `iwl_dvm_set_pmi()` mutates both `STATUS_POWER_PMI` and transport PMI state through `iwl_trans_set_pmi()`. No durable persistence is implemented here, but declared EEPROM/NVM parsing routines shape how persistent device configuration is imported into runtime state.

Dependencies and integration points: Includes `iwl-config.h`, `dev.h`, and indirectly the DVM private structures and firmware ABI from `commands.h`. The APIs bridge Linux mac80211, cfg80211 WoWLAN, transport command submission, firmware image loading, EEPROM/NVM parsing, station/key management, scan scheduling, Bluetooth coexistence, rate scaling, power management, and optional `CONFIG_IWLWIFI_DEBUGFS` registration. The inline debug helpers depend on `CONFIG_IWLWIFI_DEBUG` and route RF-kill-sensitive errors to quieter log modes.

Risks: Because this is a high-fanout header, prototype drift can break many DVM translation units. Status-bit constants must remain consistent with code that sets and tests `priv->status`. The TX status mapping intentionally treats only destination power-save and passive-no-RX failures as filtered; changing it can affect mac80211 retry/accounting behavior. `iwl_sta_id()` trusts mac80211 station private data after a `WARN_ON(!sta)`, so callers must not pass stale station pointers. `iwl_dvm_set_pmi()` has side effects beyond the bitset and must be used only when the transport can accept PMI changes.

Test signals: Build all DVM-supported device families with and without `CONFIG_IWLWIFI_DEBUG` and `CONFIG_IWLWIFI_DEBUGFS`; exercise mac80211 registration/unregistration, firmware alive/restart, RF-kill and CT-kill transitions, scan start/cancel/timeout, RX dispatch, normal TX and aggregation, station add/remove/key update, rate table updates, calibration result replay, EEPROM/NVM parsing, and PMI toggles.
