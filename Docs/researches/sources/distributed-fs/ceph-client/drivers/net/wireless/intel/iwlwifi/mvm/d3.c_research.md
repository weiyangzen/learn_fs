# sources/distributed-fs/ceph-client/drivers/net/wireless/intel/iwlwifi/mvm/d3.c

## Purpose

Implements MVM D3 suspend/resume, WoWLAN, fast suspend/resume, and net-detect. It programs wake triggers, key/replay material, protocol offload, patterns, D3 firmware state, and on resume parses wake status, restores key counters, reports wake reasons, keeps or drops the connection, and requests restart when needed.

## Important APIs, Types, and Functions

Public callbacks include `iwl_mvm_set_rekey_data()`, `iwl_mvm_ipv6_addr_change()`, `iwl_mvm_set_default_unicast_key()`, `iwl_mvm_suspend()`, `iwl_mvm_resume()`, `iwl_mvm_set_wakeup()`, `iwl_mvm_fast_suspend()`, and `iwl_mvm_fast_resume()`. Core helpers cover key programming (`iwl_mvm_wowlan_config_key_params()`), RSC/TSC/TKIP/rekey material, wake configuration (`iwl_mvm_get_wowlan_config()`), D3 transition/reprogramming, net-detect, status parsing, wake-packet storage, wake reporting, and connection preservation. `struct iwl_wowlan_status_data` is the normalized status container.

## Control Flow

Suspend pauses TCM/runtime debug, finds the BSS VIF, marks D3, and branches between net-detect and associated WoWLAN. Associated suspend ensures the offload TID queue, builds wake filters, switches/reprograms D3 firmware for non-unified images, configures keys/counters/rekey data, sends `WOWLAN_CONFIGURATION`, patterns, protocol offload, power updates, `D3_CONFIG_CMD`, and transport D3 suspend.

Resume checks D3 state and firmware error tables, resumes firmware either with notification waits or status queries, handles D3-end reset flags, refreshes regulatory/PPAG/SAR state where possible, queries/report wake reasons, restores sequence counters and rekeyed GTK/IGTK/BIGTK state, decides whether to keep the connection, disconnects other station VIFs as needed, and either avoids restart on successful unified-image D3 exit or requests hardware restart.

Fast suspend/resume is a shorter mutex-held path that sends D3 config and waits only for `D3_END_NOTIFICATION` on resume.

## State and Persistence Behavior

Stores rekey material in `mvmvif->rekey_data`, IPv6 targets/tentative bits, default TX key index, IV/ICV lengths, net-detect match/channel copies, D3 status bits, offloaded TID, net-detect/fast-resume flags, non-QoS sequence state, and restored key RX sequence numbers including per-RXQ PN mirrors for the new RX API.

## Dependencies and Integration Points

Integrates with cfg80211 WoWLAN/net-detect, mac80211 key iteration/rekey APIs, station queues, firmware version/capability negotiation, D3/D0 transport hooks, scheduled scan, protocol offload, regulatory/PPAG/SAR, firmware debug/error collection, notification waits, and PM wakeup reporting.

## Risks

Version-dependent command/status layouts are subtle. Key counter endian/per-TID conversion can cause replay failures. Wake packet reconstruction must handle IV/ICV/FCS/truncation correctly. Non-unified D3 reprogramming manually recreates PHY/MAC/binding/STA/quota state. Net-detect allocations must be freed on all paths.
