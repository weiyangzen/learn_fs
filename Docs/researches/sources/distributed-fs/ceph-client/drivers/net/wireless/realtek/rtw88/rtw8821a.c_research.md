# sources/distributed-fs/ceph-client/drivers/net/wireless/realtek/rtw88/rtw8821a.c

`rtw8821a.c` implements the RTL8821A/RTL8811A rtw88 chip profile. It defines `rtw8821a_ops`, local IQK calibration, RX PHY status handling, thermal power tracking, LED control, TX descriptor checksum handling, Bluetooth coexistence hooks, queue/page data, RFE definitions, coexistence tables, and exported `rtw8821a_hw_spec`.

The operation table combines 88xxA common helpers with local callbacks. Bring-up through the bus layer uses `rtw8821a_hw_spec` to load tables from `rtw8821a_table.c`, firmware `rtw88/rtw8821a_fw.bin`, descriptor sizing, power flows, and coexistence parameters. RX status delegates to `rtw88xxa_query_phy_status()` with a local CCK LNA/VGA power calculator. Power tracking is two-phase: trigger RF thermal measurement, then read and call `rtw88xxa_phy_pwrtrack()` with `rtw8821a_do_iqk()`.

IQK is the core control path. `rtw8821a_do_iqk()` backs up MAC/BB/AFE/RF registers, configures MAC state, runs `rtw8821a_iqk()`, and restores backups. `rtw8821a_iqk()` performs up to three path-A LOK/TX/RX calibration attempts, optionally uses VDF for 80 MHz, averages successful samples, and writes TX/RX imbalance coefficients.

State lives in `rtwdev->hal`, `rtwdev->efuse`, `rtwdev->dm_info`, and `rtwdev->coex`; final calibration and coexistence writes persist in hardware. Important dependencies are `main.h`, `coex.h`, `phy.h`, `reg.h`, `rtw88xxa.h`, `tx.h`, and `rtw8821a_table.h`. Risks include forced-success IQK readiness/TX-failure overrides, no-op coexistence/ldo hooks, and copied 8821C coexistence tables with a documented A2DP TDMA adjustment. Test signals include firmware load, table load, RSSI accuracy, 2.4/5 GHz channel changes, IQK logs/coefs, thermal tracking, LED polarity, TX checksum, Bluetooth coexistence, and LPS/card disable flows.
