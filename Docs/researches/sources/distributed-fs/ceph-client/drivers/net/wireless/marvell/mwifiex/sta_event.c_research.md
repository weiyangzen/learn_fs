# sources/distributed-fs/ceph-client/drivers/net/wireless/marvell/mwifiex/sta_event.c

Purpose: Handles asynchronous station-mode firmware events for mwifiex. It converts firmware event causes and event bodies into driver state transitions, cfg80211 notifications, queued commands, TDLS/11n/WMM/coexistence updates, power-save transitions, disconnect handling, and firmware dump collection.

Important APIs, types, and functions: Public functions are `mwifiex_reset_connect_state()`, `mwifiex_process_multi_chan_event()`, `mwifiex_process_tx_pause_event()`, `mwifiex_bt_coex_wlan_param_update_event()`, and `mwifiex_process_sta_event()`. Internal helpers include `mwifiex_check_ibss_peer_capabilities()`, `mwifiex_parse_tdls_event()`, `mwifiex_process_uap_tx_pause()`, `mwifiex_process_sta_tx_pause()`, and `mwifiex_fw_dump_info_event()`. Event families covered include link/deauth/disassoc/link-loss, power-save sleep/awake/deep-sleep/host-sleep activation, MIC failures, background and extended scan reports, RSSI/SNR/CQM thresholds, IBSS coalescing and peer connect/disconnect, ADDBA/DELBA/BA timeout, AMSDU control, remain-on-channel expiry, channel switch/radar/channel reports, TDLS, TX pause/status, multi-channel info, Bluetooth coexistence parameter change, RXBA sync, and firmware dump info.

Control flow: `mwifiex_process_sta_event()` switches on `adapter->event_cause`, with event payloads already stored in `adapter->event_body`/`adapter->event_skb` by the bus layer. Link and disconnect events update carrier/queues or call `mwifiex_reset_connect_state()`. Power-save events transition `adapter->ps_state`, clear wakeup flags, delete wake timers, and may send null packets or host-sleep activation commands. Scan and WMM events queue query commands. RSSI threshold events notify cfg80211 and request RSSI info so response handling can resubscribe thresholds. IBSS peer events add/remove station records and parse HT/VHT capabilities from embedded management-frame TLVs. TDLS and TX pause events parse TLVs and update station/RA-list pause state. Firmware dump info events accumulate USB dump chunks until an end marker or buffer limit, then upload the dump.

State and persistence: `mwifiex_reset_connect_state()` clears media/security/rate/TDLS/RSSI/current-BSS state, saves previous SSID/BSSID for reassociation, stops queues, drops carrier, clears power-save TX locks, optionally notifies host-MLME or cfg80211 disconnect, zeroes `cfg_bssid`, and removes GTK rekey offload when firmware supplicant support is present. Event handling updates `adapter->ps_state`, `tx_lock_flag`, `pps_uapsd_mode`, wake flags, coexistence window and scan timing, USB multi-channel status and port assignment, devdump buffer and length, TDLS node states, station `tx_pause` flags, IBSS peer 11n/11ac capabilities, `adapter->tx_buf_size`, scheduled-scan state, CSA state, and debug event counters.

Dependencies and integration points: Integrates with cfg80211 notifications (`cfg80211_disconnected`, CQM RSSI, MIC failure, scheduled scan, remain-on-channel, TDLS requests), netdev carrier/queue control, mwifiex command submission, WMM RA-list management, TDLS helpers, 11n BA/reorder helpers, 11h channel/radar handlers, host MLME workqueues, firmware dump upload, USB multi-channel resync, and bus wakeup completion through `adapter->if_ops.wakeup_complete()`. It relies on bus files such as `sdio.c` to deliver event skbs and cause/body fields correctly.

Risks: Event payload parsing is length-sensitive; TLV loops must reject short or inconsistent buffers before touching embedded fields. Disconnect handling has many side effects and must not run during command-timeout states where current command cleanup is pending. Host MLME link-loss handling defers disconnect through workqueue state and can diverge from direct cfg80211 reporting. Power-save awake/sleep transitions depend on `data_sent`, port readiness, last-packet indication, and wake timers, so races can leave traffic locked or the card asleep. Firmware dump accumulation can overflow fixed dump buffers and intentionally uploads partial data on timeout or end marker. IBSS capability parsing manipulates skb headroom with pull/push and assumes the fixed event layout.

Test signals: Useful event tests include deauth/disassoc/link-loss with and without host MLME, WPS-session suppression, PS_SLEEP/PS_AWAKE/deep-sleep awake transitions, host-sleep activation request command, background scan report and stopped notifications, RSSI low/high CQM resubscription path, IBSS peer connect/disconnect with HT/VHT capability TLVs, ADDBA/DELBA/BA timeout, AMSDU buffer-size change, remain-on-channel expiry during host MLME auth and normal ROC, CSA-triggered deauth, TDLS channel switch result/status changes, TX pause TLVs for STA/UAP/multicast/TDLS peers, USB multi-channel resync, coexistence TLVs, RXBA sync, and firmware dump chunk upload on end or timeout.
