# Research: sources/distributed-fs/ceph-client/drivers/net/can/usb/peak_usb/pcan_usb_pro.c

Purpose: this file implements the two-channel classic CAN PEAK PCAN-USB Pro adapter protocol. It provides the device-specific command builder, firmware/bootloader/vendor-request handling, shared per-interface timestamp state, per-channel bus/bit timing/control operations, RX record decoding, TX record encoding, LED identification, and the `pcan_usb_pro` adapter descriptor consumed by the common PEAK USB core.

Important APIs, types, and functions: `struct pcan_usb_pro_interface` stores two channel device pointers, one shared `peak_time_ref`, timestamp calibration ignore count, and opened-channel count. `struct pcan_usb_pro_device` extends `struct peak_usb_device` with the shared interface pointer and cached CCBT bit timing value. `struct pcan_usb_pro_msg` abstracts record-list command buffers. `pcan_msg_init()`, `pcan_msg_init_empty()`, and `pcan_msg_add_rec()` build variable-size records. `pcan_usb_pro_send_cmd()`, `pcan_usb_pro_wait_rsp()`, and exported `pcan_usb_pro_send_req()` perform bulk and vendor control transfers. Device callbacks include timestamp enable, bitrate, bus, silent, filter, LED, channel-ID, bit timing, restart, driver-loaded notification, RX handlers, TX encoder, start/stop/init/exit/free, interface endpoint probe, and ethtool physical ID.

Control flow: the common core validates endpoints through `pcan_usb_pro_probe()` and creates two sibling netdevs. First-channel initialization allocates the shared interface object, firmware info, and bootloader info; reads FW/BL metadata through vendor requests; tells the device the driver is loaded; logs hardware revision and serial; and sets LEDs back to device-default. The second channel reuses the shared interface. Opening a channel programs listen-only mode, enables bypass filtering, and on first open initializes timestamp state and enables timestamp records. The core then sets the bus on; `pcan_usb_pro_set_bus()` re-sends the cached CCBT before enabling the bus. RX decoding reads a record count from the message header and dispatches CAN data records, status records, and timestamp calibration records. CAN data records choose the channel from the encoded length nibble, build classic CAN skbs, add EFF/RTR flags, copy payload, update stats, convert the shared 32-bit timestamp, and deliver with `netif_rx()`. Status records synthesize CAN error skbs for bus-off, warning, passive, overrun, and queue-overrun states. TX encoding selects TXMSG0/4/8 based on RTR and payload length, encodes the channel in the length nibble, adds EFF/RTR/single-shot flags, and returns the actual record-list length. Stop disables timestamp records on last close; exit turns off bus and clears driver-loaded state for channel 0.

State and persistence: the shared interface object persists until both sibling devices are freed. Shared timestamp state is valid only after enough calibration messages have been ignored for clock stabilization. `cached_ccbt` preserves the last bit timing register value so bus-on can reapply it. `dev_opened_count` gates timestamp message enable/disable across channels. Device-persistent CAN channel IDs are read and written through GETDEVID/SETDEVID records.

Dependencies and integration points: the file uses the shared PEAK core, `pcan_usb_pro.h` record definitions, Linux USB bulk/control APIs, SocketCAN classic CAN/error helpers, ethtool physical ID and common EEPROM/channel-ID helpers, and the core timestamp conversion functions. `pcan_usb_fd.c` also reuses the exported vendor-request helper and restart completion callback from this file/header family.

Risks: command/response matching only retries a small number of bulk responses and filters by data type/channel, so unsolicited records can cause control operations to fail. `pcan_msg_add_rec()` uses varargs and a static record-size table; incorrect argument ordering or record lengths can corrupt messages. Error-state handling suppresses duplicate state reports but must still account for overrun-only records. Timestamp state is shared by both channels, so first-open/last-close logic must stay balanced. Cached bit timing must be initialized before bus-on or reactivation after bus-off can use stale zero settings.

Test signals: verify two netdevs appear for one adapter, firmware and bootloader info are logged once, both channels can open independently and together, timestamp records are enabled only while at least one channel is open, bit timing CCBT is reapplied on bus-on, channel-specific CAN RX/TX and error status records route to the correct netdev, warning/passive/bus-off and overrun reports generate expected CAN error frames, single-shot/listen-only modes are encoded, ethtool identify blinks and restores LEDs, and channel-ID ethtool operations work for both channels.
