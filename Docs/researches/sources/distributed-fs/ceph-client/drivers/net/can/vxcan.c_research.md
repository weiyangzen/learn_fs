# Research: sources/distributed-fs/ceph-client/drivers/net/can/vxcan.c

Purpose: this file implements the virtual CAN tunnel link type `vxcan`, modeled after veth for CAN. It creates paired CAN netdevices, optionally across network namespaces, and forwards CAN skbs transmitted on one end to the peer while supporting classic CAN, CAN FD, and CAN XL MTUs/capability reporting.

Important APIs, types, and functions: `struct vxcan_priv` stores an RCU-protected peer netdev pointer. `vxcan_xmit()` forwards skbs to the peer and resets CAN gateway hop state. `vxcan_open()`/`vxcan_close()` manage carrier state based on peer availability. `vxcan_get_iflink()` reports peer ifindex. `vxcan_change_mtu()` and `vxcan_set_cap_info()` mirror vcan MTU/capability behavior. `vxcan_setup()` initializes netdev fields and CAN ML private data. `vxcan_newlink()` creates and registers the peer and local devices from RTNL attributes. `vxcan_dellink()` unregisters both ends and clears peer pointers. `vxcan_get_link_net()` reports the peer namespace for link display semantics, and `vxcan_link_ops` wires the RTNL API.

Control flow: module init registers the `vxcan` RTNL link kind. `vxcan_newlink()` parses optional `VXCAN_INFO_PEER` nested attributes, chooses peer name and name assignment type, creates the peer in the requested peer net namespace, optionally sets peer ifindex, registers and configures the peer, then names/registers the requested device, turns carrier off on both ends, and cross-links peer pointers with RCU assignment. TX validates the CAN skb, looks up the peer under RCU, drops and counts `tx_dropped` if no peer exists, timestamps the original skb, clones it, consumes the original on clone success, forces a separate CAN skb extension with `skb_ext_add()`, resets `can_gw_hops`, assigns packet type/device/checksum fields for receive, and calls `netif_rx()`. On successful receive, source TX stats and peer RX stats are updated. Deleting either end clears both RCU peer pointers and queues both netdevices for unregister.

State and persistence: runtime state is the RCU peer pointer in each device and carrier state. There is no persistent hardware state. Netdev private memory includes aligned `vxcan_priv` followed by `can_ml_priv`, and peer namespace/name/ifindex are established at link creation.

Dependencies and integration points: the driver integrates with RTNL pair creation, nested netlink attributes from `linux/can/vxcan.h`, network namespaces, RCU pointer access, netdevice carrier and iflink APIs, SocketCAN skb validation/data-length helpers, CAN gateway skb extension state, CAN ML private helpers, and ethtool timestamp fallback.

Risks: `vxcan_xmit()` depends on clone and skb extension allocation in atomic context; allocation failures drop silently except for lack of stat increments in some clone/extension failure cases. Peer pointers must remain RCU-safe across namespace teardown and paired unregister. The TX path intentionally resets `can_gw_hops` when crossing the tunnel; tests should cover CAN gateway loop-prevention behavior. As with vcan, MTU/capability changes are blocked while running and default to CAN XL MTU.

Test signals: create vxcan pairs with and without explicit peer attributes, create peers in another network namespace, verify `iflink` and `get_link_net` behavior, bring both ends up and observe carrier on/off transitions, send classic CAN/CAN FD/CAN XL frames across the pair, confirm stats on both ends, verify CAN gateway hop counter reset, reject invalid MTUs and MTU changes while up, delete either end and confirm both peers unregister cleanly, and exercise transmit after peer removal to check drop accounting.
