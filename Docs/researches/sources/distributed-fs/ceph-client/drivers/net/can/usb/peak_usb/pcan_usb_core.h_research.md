# Research: sources/distributed-fs/ceph-client/drivers/net/can/usb/peak_usb/pcan_usb_core.h

Purpose: this header defines the shared PEAK USB CAN adapter contract. It centralizes vendor/product IDs, driver limits, the adapter callback table, generic per-channel device state, timestamp conversion state, TX URB context state, and helper prototypes used by the PCAN-USB, PCAN-USB Pro, and PCAN-USB FD family implementations.

Important APIs, types, and functions: `struct peak_usb_adapter` is the key abstraction. It describes adapter name, product ID, control mode support, CAN clock, arbitration/data bit timing constants, channel count, ethtool operations, interface probe hook, lifecycle hooks, bus/bit timing/channel-ID operations, RX decoder, TX encoder, restart handler, berr-counter hook, endpoint addresses, timestamp scaling parameters, buffer sizes, and private allocation size. `struct peak_time_ref` stores host/device timestamp bases and adapter scaling. `struct peak_tx_urb_context` binds a TX URB to a PEAK device and CAN echo index. `struct peak_usb_device` embeds `struct can_priv` and stores adapter, controller index, state flags, USB/netdev pointers, URB anchors, command buffer, cached channel ID, revision, endpoints, and sibling links. Public helpers cover memory dumps, timestamp setup/conversion, 64-bit hardware timestamp RX, async completion, restart completion, timestamp ethtool reporting, and common ethtool EEPROM access.

Control flow: protocol-specific files declare a `const struct peak_usb_adapter` and fill this table. `pcan_usb_core.c` consumes the table during USB probe, netdev allocation, open/close, TX/RX URB callbacks, CAN bit timing changes, CAN mode restarts, and ethtool operations. Timestamp helpers use the `ts_used_bits`, `us_per_ts_shift`, and `us_per_ts_scale` fields from the active adapter descriptor.

State and persistence: the header itself stores no state, but defines the long-lived objects that hold runtime state. `PCAN_USB_STATE_CONNECTED` gates synchronous USB commands after unplug; `PCAN_USB_STATE_STARTED` gates RX decoding after netdev open. The channel ID field is a cached mirror of device-persistent configuration and is exposed through sysfs and ethtool.

Dependencies and integration points: the types assume Linux USB, netdevice, SocketCAN, ethtool, and skb timestamp APIs included by implementation files. The external adapter descriptors are the registration points that make individual protocol files visible to the common USB ID table.

Risks: callback contracts are implicit; mismatched buffer sizes, endpoint arrays, `sizeof_dev_private`, or timestamp scaling values can break multiple core paths. `PCAN_USB_MAX_CHANNEL` is two, while newer PEAK devices may have more physical channels in product naming, so adapter descriptors must accurately reflect what this core can instantiate per USB interface. The first member embedding pattern used by private structs requires `sizeof_dev_private` to be at least `sizeof(struct peak_usb_device)` and container casts to match the concrete private type.

Test signals: compile coverage should catch missing callbacks/prototypes, while runtime validation should instantiate each exported adapter descriptor, verify channel counts and endpoint arrays, confirm private struct sizing, and exercise timestamp and EEPROM helpers through at least one classic, Pro, and FD-family device.
