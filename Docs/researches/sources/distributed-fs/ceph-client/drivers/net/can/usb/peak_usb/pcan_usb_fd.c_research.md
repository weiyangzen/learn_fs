# Research: sources/distributed-fs/ceph-client/drivers/net/can/usb/peak_usb/pcan_usb_fd.c

Purpose: this file implements PEAK's CAN FD capable USB family: PCAN-USB FD, PCAN-Chip USB, PCAN-USB Pro FD, and PCAN-USB X6. It plugs into the shared PEAK USB core while using PEAK's uCAN/PUCAN command and message formats for CAN FD frames, data bit timing, ISO/non-ISO FD mode, hardware timestamps, error counters, overrun reporting, LED control, and firmware-provided endpoint discovery.

Important APIs, types, and functions: `struct pcan_ufd_fw_info` mirrors firmware/bootloader/device-ID/endpoint metadata. `struct pcan_usb_fd_if` is shared per USB interface and contains channel pointers, firmware info, timestamp reference, calibration ignore count, and open-channel count. `struct pcan_usb_fd_device` extends the generic PEAK device with a cached berr counter, shared interface pointer, and shared command buffer. Command helpers include `pcan_usb_fd_send_cmd()`, `pcan_usb_fd_read_fwinfo()`, `pcan_usb_fd_build_restart_cmd()`, `pcan_usb_fd_set_bus()`, `pcan_usb_fd_set_filter_std()`, `pcan_usb_fd_set_options()`, `pcan_usb_fd_set_can_led()`, `pcan_usb_fd_set_clock_domain()`, nominal/data bit timing setters, channel-ID get/set, and async restart. RX handlers include `pcan_usb_fd_decode_canmsg()`, `pcan_usb_fd_decode_status()`, `pcan_usb_fd_decode_error()`, `pcan_usb_fd_decode_overrun()`, `pcan_usb_fd_decode_ts()`, and `pcan_usb_fd_decode_buf()`. TX encoding is in `pcan_usb_fd_encode_msg()`. Four adapter descriptors at the bottom define product-specific names, channel counts, bit timing constants, endpoints, and callbacks.

Control flow: PEAK core probe calls `pcan_usb_fd_probe()` to accept only interface 0 for the FD-family path. First channel initialization allocates shared interface state and a 512-byte command buffer, reads firmware info, logs versions, derives ISO/non-ISO FD support from firmware major version, fills default command endpoints when old firmware lacks endpoint metadata, notifies the device that the driver is loaded, and later channels reuse that shared state. If firmware includes extended endpoint metadata, channel netdevs override the default data endpoints. Initialization selects a device clock-domain command matching the adapter clock and restores default LED mode. Open calls `pcan_usb_fd_start()`, which accepts all standard IDs, initializes shared time reference on first open, enables error and USB calibration messages, increments open count, resets cached berr counters, then the core sets bus on with a command list that resets error counters, toggles ISO/non-ISO FD option as needed, and enters normal or listen-only mode. RX URBs contain aligned records; decoder dispatches CAN/CAN FD frames, calibration timestamps, error-counter messages, status transitions, and USB overrun messages. TX builds one PUCAN CAN_TX record with classic or FD flags, BRS/ESI, RTR, extended ID, single-shot, channel DLC, aligned payload, and a zero-size terminator. Stop disables special messages on last close; exit turns bus and LEDs off and clears driver-loaded state.

State and persistence: shared interface state persists across sibling channel netdevs and is freed only when the last sibling is removed. Firmware info caches device IDs and endpoint numbers. `pcan_usb_fd_device::bec` stores the latest error counters received from PUCAN error records and is consumed by status-change handling and `do_get_berr_counter`. Device-persistent channel IDs are read through firmware info and written with `PCAN_UFD_CMD_DEVID_SET`. Control mode persistence is per netdev, with firmware versions before 2.x forced to non-ISO FD because they cannot switch dynamically.

Dependencies and integration points: this file depends on `pcan_usb_core.h`, `pcan_usb_pro.h` vendor request helpers, and `<linux/can/dev/peak_canfd.h>` for PUCAN commands, message layouts, and bitfield macros. It integrates with the PEAK shared core's adapter contract, SocketCAN CAN FD skb allocation, CAN FD data bit timing, CAN error state APIs, ethtool physical ID and EEPROM helpers, and hardware timestamp delivery through `peak_usb_netif_rx_64()`.

Risks: command sending has a full-speed USB workaround that slices command buffers to 64-byte packets; regressions here can affect older or low-speed negotiated devices. Firmware metadata controls endpoints and FD ISO support, so both old and extended response formats need coverage. The adapter descriptors expose only up to two channels through this core even for X6 naming, making descriptor semantics important. Status messages rely on previously received error-counter messages to choose TX/RX state direction. Decoder bounds checks must be correct for firmware-provided `size` fields. Shared open-count and command-buffer state span multiple netdevs and require open/close/unplug tests across sibling channels.

Test signals: validate all four product descriptors probe, firmware info parsing with and without extended endpoint fields, CAN and CAN FD TX/RX including BRS/ESI and RTR classic frames, nominal and data bit timing commands, listen-only/one-shot/FD non-ISO toggles, full-speed command chunking, calibration timestamp messages after the ignore window, standard filter setup, overrun/error/status frame generation, berr-counter reporting, LED identify/default/off behavior, channel-ID read/write, multi-channel open/close ordering, and unplug during active traffic.
