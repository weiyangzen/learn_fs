# Research: sources/distributed-fs/ceph-client/drivers/net/can/usb/peak_usb/pcan_usb_core.c

Purpose: this is the shared USB and SocketCAN framework for the PEAK-System USB adapter family. It matches PEAK USB product IDs, creates one CAN netdev per controller/channel, owns the generic URB transmit/receive lifecycle, delegates protocol-specific encoding, decoding, timing, and control operations through `struct peak_usb_adapter`, and exposes common timestamp and CAN channel ID facilities.

Important APIs, types, and functions: the USB ID table maps product IDs to adapter descriptors such as `pcan_usb`, `pcan_usb_pro`, `pcan_usb_fd`, `pcan_usb_chip`, `pcan_usb_pro_fd`, and `pcan_usb_x6`. `peak_usb_create_dev()` allocates and registers a `struct peak_usb_device`-backed CAN netdev. `peak_usb_start()`, `peak_usb_ndo_open()`, `peak_usb_ndo_stop()`, and `peak_usb_unlink_all_urbs()` own RX/TX URB setup and teardown. `peak_usb_ndo_start_xmit()`, `peak_usb_read_bulk_callback()`, and `peak_usb_write_bulk_callback()` provide the shared data path around adapter `dev_encode_msg()` and `dev_decode_buf()` callbacks. Timestamp helpers include `peak_usb_init_time_ref()`, `peak_usb_set_ts_now()`, `peak_usb_update_ts_now()`, `peak_usb_get_ts_time()`, and `peak_usb_netif_rx_64()`. Common ethtool/sysfs helpers include `peak_usb_get_eeprom_len()`, `peak_usb_get_eeprom()`, `peak_usb_set_eeprom()`, `pcan_get_ts_info()`, and `can_channel_id_show()`.

Control flow: module init registers a `usb_driver`; USB probe selects the adapter descriptor from `driver_info`, optionally lets the adapter reject non-CAN interfaces, and creates `ctrl_count` netdevices as a sibling chain on the USB interface. Device creation initializes CAN clock and bit timing callbacks, CAN FD data bit timing when present, mode restart callback, berr-counter callback, endpoint addresses, ethtool operations, sysfs groups, echo contexts, and anchors, then registers the CAN device and runs adapter-specific initialization. Opening a netdev calls `open_candev()`, allocates and submits up to four RX URBs, preallocates ten TX URBs with buffers and contexts, runs adapter `dev_start()`, sets the bus on through `dev_set_bus()`, and starts the queue. TX picks a free echo context, asks the adapter to encode an skb into the URB buffer, anchors and submits it, and stops the queue when all TX URBs are active. RX completion checks USB status, invokes adapter decoding only after the started flag is set, and resubmits the URB. Stop clears started state, stops the net queue, kills RX/TX URBs, calls adapter stop, sets bus off, and closes CAN state. Disconnect unregisters every sibling netdev, clears connected state, frees command buffers and adapter-private shared state, and frees candevs.

State and persistence: `struct peak_usb_device` tracks connection/started flags, USB device, netdev, active TX URB count, TX echo contexts, anchors, command buffer, cached CAN channel ID, hardware revision, selected endpoints, and sibling links. `struct peak_time_ref` converts device tick domains to kernel time while handling wrap and periodically resetting the host/device base after long intervals. CAN channel ID is cached early and refreshed after ethtool reads/writes; actual persistence is device firmware/flash via adapter callbacks.

Dependencies and integration points: the file sits between Linux USB core, netdevice operations, SocketCAN `alloc_candev()`/`register_candev()`/`open_candev()`/`close_candev()`, CAN echo skb helpers, ethtool EEPROM and timestamp APIs, sysfs attributes, and all PEAK protocol-specific files. It depends on adapter descriptors exported by `pcan_usb.c`, `pcan_usb_pro.c`, and `pcan_usb_fd.c`.

Risks: adapter callbacks run under common URB and netdev assumptions; a protocol encoder must respect the preallocated buffer size and set the actual `size`, while a decoder must fully validate firmware-controlled record lengths. `peak_usb_start()` tolerates partial RX/TX URB allocation with performance warnings, which should be intentional for low-memory behavior. Sibling management is stack-like through `prev_siblings` and `next_siblings`, so error paths must restore interface data correctly. The common EEPROM helpers rely on every adapter implementing get/set channel ID and on little-endian byte slicing to make partial ethtool writes architecture-independent. Timestamp conversion is subtle around device counter wrap and long host uptime.

Test signals: device-family smoke tests should verify one netdev per channel, expected `can_channel_id` sysfs values, clean open/close cycles, URB kill/free behavior on unplug while up and down, TX queue stop/wake under full echo-context pressure, adapter decode errors causing hex dumps rather than memory misuse, bus-off restart through `CAN_MODE_START`, ethtool EEPROM partial-byte channel ID updates, and RX hardware timestamp monotonicity across device timestamp wrap.
