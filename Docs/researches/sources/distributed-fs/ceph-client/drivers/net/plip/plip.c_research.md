# sources/distributed-fs/ceph-client/drivers/net/plip/plip.c

Purpose: Implements the Linux PLIP network driver for LapLink-style parallel-port cables. It exposes an Ethernet-like point-to-point netdev over parport and transfers packet length, payload, and checksum through the Crynwr two-nibble handshake protocol.

Important APIs, types, and functions: `struct net_local` stores per-device parport ownership, work items, send/receive protocol state, timeout tunables, connection state, and locking. `struct plip_local` tracks packet and nibble state, length, checksum, byte index, and active SKB. Core protocol functions are `plip_receive()`, `plip_send()`, `plip_receive_packet()`, `plip_send_packet()`, `plip_connection_close()`, `plip_error()`, and `plip_bh_timeout_error()`. Netdev and parport integration is through `plip_open()`, `plip_close()`, `plip_tx_packet()`, `plip_interrupt()`, `plip_preempt()`, `plip_wakeup()`, `plip_attach()`, and `plip_cleanup_module()`.

Control flow: Module init registers a `parport_driver`; each selected port gets an allocated Ethernet netdev and parport device model. Open claims the port, clears data lines, enables IRQs or starts polling when no IRQ exists, initializes send/receive state, and starts the queue. TX claims the parport if necessary, stops the queue, stores the SKB in `snd_data`, marks a trigger state, and schedules work. The workqueue sends the trigger, length bytes, payload bytes, and checksum as nibbles, or receives the same sequence after an interrupt/poll trigger. Received packets are checksum-verified, typed with `plip_type_trans()`, and delivered through `netif_rx()`.

State and persistence behavior: All state is volatile. Module parameters `parport[]` and `timid`, static `dev_plip[]`, and the attach unit counter control device binding. `snd_data` and `rcv_data` hold partial packet state across deferred work retries. `SIOCDEVPLIP` exposes runtime timeout get/set, with set requiring `CAP_NET_ADMIN` and compat syscalls rejected. Parport preemption is cooperative and can defer release until an on-wire transfer ends.

Dependencies and integration points: Depends on parport callbacks/IRQs, netdev/Ethernet helpers, IPv4 address state for fake MAC rewriting, SKBs, workqueues, completions, spinlocks, and `linux/if_plip.h`. It integrates with userspace as `plipN` point-to-point/no-ARP netdevs and with parport sharing through preempt/wakeup callbacks.

Risks and test signals: The timing-sensitive nibble protocol can fail under slow/noisy ports, missed IRQs, or unbalanced IRQ disable/enable paths. Error recovery must free partial SKBs, reset data lines, and return to idle without losing parport ownership. Test IRQ and IRQ-less modes, collision where receive interrupts send, checksum/length errors, over-MTU TX, preempt/wakeup while active, open/close timer teardown, timeout ioctls, IPv4 address/header cache rewrite, module parameter selection, unload after open devices, and compile the snapshot because it contains duplicated source lines.
