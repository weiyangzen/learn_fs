# sources/distributed-fs/ceph-client/drivers/net/dsa/microchip/ksz9477_i2c.c

Purpose: provides the I2C bus front end for KSZ9477-family switches. It allocates a common `ksz_device`, initializes the regmap instances over I2C, binds OF compatible strings to chip-data entries, and hands the device to the common KSZ DSA registration path.

Important APIs, types, and functions: `KSZ_REGMAP_TABLE(ksz9477, not_used, 16, 0, 0)` declares the register map layout for 16-bit register addresses. `ksz9477_i2c_probe()` allocates and registers the switch. `ksz9477_i2c_remove()` calls `ksz_switch_remove()`. `ksz9477_i2c_shutdown()` calls `ksz_switch_shutdown()` and clears client data. `ksz9477_i2c_id[]`, `ksz9477_dt_ids[]`, `ksz_i2c_pm_ops`, and `ksz9477_i2c_driver` provide device matching, PM hooks, and module registration via `module_i2c_driver()`.

Control flow: the I2C core invokes probe for a matching device. Probe calls `ksz_switch_alloc(&i2c->dev, i2c)`, obtains `struct ksz_chip_data` from `device_get_match_data()`, stores the chip ID before common probing, initializes every `dev->regmap[i]` from `ksz9477_regmap_config[i]` with `dev->regmap_mutex` as the lock argument, copies optional platform data, stores the IRQ, and calls `ksz_switch_register()`. Only after successful registration does it set I2C client data. Remove and shutdown retrieve that client data and delegate lifecycle cleanup to the common driver.

State and persistence: persistent software state is the allocated `ksz_device`, its regmap pointers, chip ID, platform data pointer, IRQ number, and I2C client data association. Hardware state is not directly programmed here beyond regmap-mediated accesses performed later by the common switch driver.

Dependencies and integration points: depends on Linux I2C, regmap, module, device-tree matching, simple PM ops, and common KSZ functions from `ksz_common.h`. The compatible table maps `microchip,ksz9477`, `ksz9896`, `ksz9897`, `ksz9893`, `ksz9563`, `ksz8563`, `ksz8567`, `ksz9567`, and `lan9646` to entries in `ksz_switch_chips[]`.

Risks: probe fails with `-EINVAL` if no match data is present, so non-DT or mismatched ID-table-only use needs scrutiny. Regmap initialization must match chip register width and endian expectations; an incorrect regmap config breaks all later switch access. `i2c_set_clientdata()` is called only after successful registration, so partial probe failures rely on devm cleanup and common registration failure behavior. Shutdown clears client data after common shutdown, which prevents later remove from double-removing if the shutdown path ran first.

Test signals: OF modalias autoload for every compatible string, successful creation of all `__KSZ_NUM_REGMAPS` regmaps, clean error from intentionally bad match data, probe deferral or failure propagation from `ksz_switch_register()`, suspend/resume through `ksz_switch_suspend()` and `ksz_switch_resume()`, and shutdown/remove sequences without duplicate cleanup.
