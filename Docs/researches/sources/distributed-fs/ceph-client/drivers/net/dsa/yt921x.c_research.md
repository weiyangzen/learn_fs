# sources/distributed-fs/ceph-client/drivers/net/dsa/yt921x.c

## Purpose
This file implements the Linux DSA switch driver for Motorcomm YT921x switches. It covers MDIO register transport, internal/external MDIO child buses, phylink MAC operations, DSA switch callbacks, MIB polling, bridge/VLAN/FDB/MDB/LAG/mirror/STP/MST/DCB offloads, chip detection/reset/setup, and MDIO-driver lifecycle.

## Important APIs, Types, and Functions
- `yt921x_info` and `yt921x_infos[]` identify supported chip variants by major ID, chip mode, embedded data extmode, and internal/external port masks.
- `yt921x_reg_*` and `yt921x_reg64_*` provide locked register read/write/update/wait helpers.
- `yt921x_reg_mdio_read/write()` implement the four-halfword SMI-over-MDIO protocol.
- `yt921x_mbus_int_*` and `yt921x_mbus_ext_*` expose switch-mediated MDIO buses for PHY access.
- `yt921x_read_mib()` and `yt921x_poll_mib()` maintain per-port counters and wrap protection.
- DSA callbacks implement EEE, MTU, mirror, LAG, FDB/MDB, VLAN, bridge flags, STP/MST, DCB, DSCP priority, tag protocol, port setup, and global setup.
- `yt921x_phylink_mac_config/link_up/link_down` configure internal and external port MAC/SERDES state.
- `yt921x_mdio_probe/remove/shutdown` bind the switch to MDIO and DSA.

## Control Flow
Probe allocates private state and MDIO transport context, initializes locking and delayed MIB work, fills `struct dsa_switch`, and registers the switch. DSA setup resets and detects the chip, optionally registers the internal `mdio` bus, rejects the currently untested external bus path, then enables MIBs, CPU tagging/copy/trap behavior, VLAN 0 handling, optional QoS defaults, MIB counter clear, and temperature sensing.

All hardware access goes through `reg_lock`. For switch registers the MDIO SMI path writes address high/low words and reads or writes data high/low words under the MDIO bus lock. For internal/external PHY MDIO accesses the driver programs MBUS control registers, starts an operation, waits for completion, and transfers 16-bit data.

Switch behavior is callback-driven. Standalone ports disable learning and isolate traffic toward CPU. Bridge joins clear learning disable and recompute isolation masks; bridge leaves restore standalone mode. VLAN operations update 64-bit table rows and per-port PVID/drop/TPID state. FDB/MDB operations share the hardware FDB engine. Phylink config selects supported SERDES modes and link-up writes port, SERDES, XMII, and MDIO-polling status.

## State and Persistence
`struct yt921x_priv` stores DSA state, chip info, cached CPU ports, register transport, optional MDIO buses, per-port state, and EEE mask. Each `yt921x_port` stores hairpin/isolated flags, delayed MIB work, accumulated MIB values, and frame totals. Hardware state includes VLAN/FDB/LAG/QoS/STP/isolation/MIB/EEE/SERDES/CPU-tag registers. MIB reads are not globally consistent, but 32-bit wrap is handled by accumulating values into 64-bit fields.

## Dependencies and Integration Points
The driver integrates with DSA, phylink, OF MDIO, ethtool, bridge/switchdev, DCB, DSCP/802.1Q helpers, and the YT921x tag protocol. It relies on register definitions and private structs from `yt921x.h`.

## Risks and Edge Cases
Only YT9215+SGMII is stated as tested. External MDIO returns `-ENODEV`; XMII support is left for future work; several MBUS fields are marked as guesses. The FDB iterator must avoid GET_NEXT at index 4095 because hardware can hang. Native bridging is emulated with port isolation and software trapping of unknown traffic, which is correctness-sensitive for multiple bridges. VLAN rows require 64-bit writes, and all SMI operations require serialization.

## Test Signals
Validate chip detection, CPU tag EtherType, DSA setup, internal PHY MDIO, phylink for internal and SGMII/1000BASE-X/2500BASE-X ports, bridge isolation across multiple bridges, VLAN PVID/filtering, FDB/MDB operations, LAG hash/membership, MIB wrap, EEE, STP/MST, DCB/DSCP when enabled, and remove/shutdown delayed-work cancellation.
