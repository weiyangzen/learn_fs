# sources/distributed-fs/ceph-client/drivers/net/dsa/yt921x.h

## Purpose
This header defines the register map, bit fields, constants, MIB layout, and private state structures for the Motorcomm YT921x DSA switch driver.

## Important APIs, Types, and Functions
- SMI macros encode switch ID, address/data phase, and read/write phase.
- Registers cover reset, chip ID/mode, CPU tag TPID, PVID, SERDES/XMII, port control/status, MIB, embedded data, MBUS, TPID, priority maps, VLAN filtering, STP, learning, FDB, flood/trap actions, VLAN rows, LAG, and mirroring.
- Hardware limits include FDB size, MSTI count, LAG count/member count, priority count, frame size max, tag length, and total port count.
- `struct yt921x_mib` mirrors the MIB descriptor table in `yt921x.c`.
- `struct yt921x_port`, `struct yt921x_reg_ops`, and `struct yt921x_priv` describe runtime state.

## Control Flow
The header is declarative. `yt921x.c` uses these macros to compose per-port, per-VLAN, FDB, MIB, and QoS register accesses, and uses port predicate macros for internal/external handling.

## State and Persistence
The described hardware state persists until reset or reprogramming: VLAN rows, FDB entries, LAG membership, QoS maps, port isolation, MIB counters, EEE, CPU tag settings, and SERDES/XMII modes. Driver structures persist for the MDIO device lifetime.

## Dependencies and Integration Points
The header includes DSA definitions and expects kernel bitfield helpers. It is tightly coupled to `yt921x.c`; MIB field ordering must match `yt921x_mib_descs[]`.

## Risks and Edge Cases
Some MBUS fields are explicitly marked as guesses. `yt921x_port_is_external()` only recognizes port 8 even though masks and comments discuss two external ports. Wide VLAN fields require 64-bit helpers. Most macros do not enforce bounds.

## Test Signals
Compile coverage, chip ID/mode validation, register trace comparison, MIB offset correctness, VLAN/FDB/LAG behavior, and SERDES/XMII mode programming.
