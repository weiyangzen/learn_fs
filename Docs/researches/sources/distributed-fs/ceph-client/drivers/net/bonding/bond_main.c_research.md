# sources/distributed-fs/ceph-client/drivers/net/bonding/bond_main.c

## Purpose
`bond_main.c` is the main Linux bonding driver implementation. It creates and initializes bond netdevices, validates module defaults, enslaves and releases lower devices, handles link monitoring and failover, dispatches receive and transmit traffic according to the selected bonding mode, and integrates bonding with VLAN, netpoll, XDP, IPsec/XFRM offload, ethtool, ioctl, rtnetlink, sysfs/proc/debugfs, and per-network-namespace teardown. The file is the behavioral center of the bonding subsystem; companion files such as `bond_netlink.c`, `bond_options.c`, `bond_3ad.c`, and `bond_alb.c` expose configuration or implement mode-specific details that are orchestrated here.

## Important APIs, Types, and Functions
- Module/default configuration is held in file-scope module parameters and copied into `bonding_defaults` by `bond_check_params()`. It parses string options through the shared bonding option table, validates mutual exclusions such as `miimon` versus `arp_interval`, normalizes delays to monitor ticks, and initializes 802.3ad, ALB/TLB, peer notification, ARP/NS, and transmit hashing defaults.
- Lifecycle entry points are `bonding_init()`, `bonding_exit()`, pernet callbacks `bond_net_init()`, `bond_net_pre_exit()`, `bond_net_exit_rtnl()`, `bond_net_exit_batch()`, `bond_create()`, `bond_setup()`, `bond_init()`, `bond_uninit()`, and `bond_destructor()`.
- `bond_netdev_ops` exposes the bonding netdevice interface: open/stop, TX, queue selection, stats, legacy bonding ioctls, private ioctls, multicast/promiscuity changes, MTU/MAC changes, neighbour setup, VLAN propagation, netpoll, slave add/delete, feature fixups, lower-device lookup, native XDP, and hardware timestamp forwarding.
- Enslave/release paths are centered on `bond_enslave()`, `__bond_release_one()`, `bond_release()`, and `bond_release_and_destroy()`. They manage device type compatibility, MAC/MTU changes, rx-handler registration, upper/lower netdev links, sysfs slave entries, VLAN propagation, XDP propagation, netpoll, active slave selection, and staged rollback.
- Active slave and failover functions include `bond_choose_primary_or_current()`, `bond_find_best_slave()`, `bond_change_active_slave()`, `bond_select_active_slave()`, `bond_do_fail_over_mac()`, `bond_hw_addr_swap()`, and `bond_set_carrier()`.
- Monitoring is split between MII and ARP/NS paths: `bond_mii_monitor()`, `bond_miimon_inspect()`, `bond_miimon_commit()`, `bond_loadbalance_arp_mon()`, `bond_activebackup_arp_mon()`, `bond_ab_arp_inspect()`, `bond_ab_arp_commit()`, and `bond_ab_arp_probe()`.
- Receive handling uses `bond_handle_frame()` as the registered lower-device rx handler. It delegates monitor/protocol probes through `bond->recv_probe`, suppresses duplicate delivery from inactive slaves, rewrites `skb->dev` to the bond master, and special-cases ALB bridge traffic.
- Transmit handling uses `bond_start_xmit()` and `__bond_start_xmit()` to select the mode-specific path: round-robin, active-backup, 802.3ad/XOR hash, broadcast, ALB, or TLB. Helpers include `bond_dev_queue_xmit()`, `bond_xmit_hash()`, `bond_update_slave_arr()`, `bond_xmit_roundrobin_slave_get()`, `bond_xmit_3ad_xor_slave_get()`, `bond_xmit_broadcast()`, and queue-id override handling.
- XDP support is provided by `__bond_xdp_check()`, `bond_xdp_set_features()`, `bond_xdp_set()`, `bond_xdp_xmit()`, and `bond_xdp_get_xmit_slave()`. It supports round-robin, active-backup, 802.3ad, and XOR, but rejects unsupported modes and the VLAN+srcmac hash policy.
- Optional IPsec offload support under `CONFIG_XFRM_OFFLOAD` is implemented by `bond_xfrmdev_ops` and helpers such as `bond_ipsec_add_sa()`, `bond_ipsec_del_sa_all()`, and `bond_ipsec_add_sa_all()`, limited to active-backup semantics.
- User-visible compatibility APIs include legacy `SIOCBOND*` ioctls, old private ioctl aliases, MII register emulation through `bond_eth_ioctl()`, ethtool link settings and timestamp queries, and hwtstamp forwarding to the active slave.

## Control Flow
Module load runs `bond_check_params()` first, then creates debugfs, registers pernet state, registers rtnetlink link ops through `bond_netlink_init()`, optionally creates `max_bonds` initial devices in `init_net`, initializes the flow dissector used by transmit hashing, and registers the netdevice notifier. Per-network-namespace init creates the bond proc/sysfs containers. `bond_create()` allocates a multi-queue netdevice, assigns `bond_link_ops`, registers it, marks carrier off, and initializes delayed work.

Device setup proceeds in two layers. `bond_setup()` installs static netdevice capabilities and operation tables and seeds `struct bonding` from `bonding_defaults`. `bond_init()` allocates the ordered workqueue, initializes stats locking, adds the bond to the namespace's `bond_net.dev_list`, prepares sysfs/debug state, and ensures a nonzero hardware address. On unregister, `bond_uninit()` cleans netpoll, releases all slaves, clears slave arrays, removes the bond from the namespace list, and unregisters debug state; `bond_destructor()` destroys the workqueue and frees the per-CPU round-robin counter.

Enslaving is a long staged control path under RTNL. `bond_enslave()` rejects unsuitable devices, including already-used rx-handler devices, self-enslave, dissimilar device types, unsupported InfiniBand modes, up lower devices, and VLAN-challenged conflicts. For the first slave it may change the master type and copy the slave MAC. It allocates `struct slave`, stores original MTU and permanent MAC, aligns slave MTU/MAC, disables IPv6 addrconf, opens the slave, initializes ALB/TLB state if needed, copies VLAN IDs, computes initial link state from miimon/ARP/carrier, records primary matches, initializes mode-specific state, enables netpoll if needed, registers `bond_handle_frame()` as the rx handler, links the lower device as a master upper, creates sysfs slave files, propagates promisc/allmulti and address filters, increments `slave_cnt`, recomputes features/carrier, updates neighbour multicast handling, chooses an active slave for primary modes, propagates any active XDP program, refreshes slave arrays for hash/broadcast modes, and publishes XDP features. Every stage has reverse cleanup labels for sysfs, upper-link, rx-handler, VLAN IDs, active pointers, netpoll, ALB/TLB, close, MAC/MTU restore, kobject release, and first-slave master rollback.

Release reverses those integrations in `__bond_release_one()`. It blocks netpoll TX, removes sysfs state, folds stats before detaching the slave, unloads bond XDP from the lower device, unregisters the rx handler, unbinds 802.3ad state, unlinks upper/lower netdevs, updates hash arrays while skipping the removed slave, clears active and primary pointers, updates ALB/TLB state, selects a replacement active slave when needed, recomputes carrier and features, removes VLAN IDs, drops promisc/allmulti/address filters, disables netpoll, closes the slave, restores addrconf, MAC, MTU, and bonding flags, refreshes XDP features, then releases the slave kobject. If a slave unregister event leaves a non-Ethernet bond empty, `bond_release_and_destroy()` can unregister the master too.

Open and close arm and quiesce runtime workers. `bond_open()` allocates the per-CPU round-robin counter on demand, marks slaves active or inactive according to mode, initializes ALB/TLB, queues MII/ARP/ALB/802.3ad workers as appropriate, sets `recv_probe` to ARP/NS validation or LACP receive, joins LACP multicast on slaves, enables the broadcast-neighbour static key if configured, and builds transmit arrays for hash modes. `bond_close()` cancels all delayed work, clears peer notifications and `recv_probe`, waits for in-flight RX handlers with `synchronize_net()`, deinitializes ALB/TLB, decrements the 802.3ad neighbour static key, and flushes hardware address filters from active or all slaves.

Link monitoring has a two-phase pattern. MII monitoring inspects slave carrier under RCU, proposing `BOND_LINK_*` changes and delay countdowns, then attempts RTNL and commits changes with mode-specific callbacks, failover, peer notification, and carrier recomputation. ARP/NS monitoring sends validation probes to configured IPv4/IPv6 targets and validates received ARP/NA packets in `bond_rcv_validate()`. Load-balancing ARP mode checks per-slave TX/RX timestamps and updates all active links; active-backup ARP mode separately inspects current link health, commits active/backup state changes, and probes candidate slaves until one validates.

TX starts in `bond_start_xmit()` under RCU. It first handles netpoll blocking and empty bonds, then mode dispatch in `__bond_start_xmit()`. Round-robin uses a per-CPU counter and preserves IGMP traffic on the current active slave when possible. Active-backup sends to `curr_active_slave`. 802.3ad/XOR uses a prebuilt RCU `usable_slaves` array and `bond_xmit_hash()` over the selected L2/L3/L4/encap/VLAN+srcmac policy. Broadcast clones the skb to all selected slaves and frees the original if no copy used it. ALB/TLB delegate selection and transmit to `bond_alb.c`. Queue-id override and TLS device offload can bypass the normal mode selection when a recorded queue or TLS lower device is valid.

RX is driven by lower-device `rx_handler` registration. `bond_handle_frame()` makes a private skb if shared, looks up the slave from the lower device, lets `recv_probe` consume monitoring or LACP frames, suppresses exact-match duplicate delivery from inactive slaves except link-local packets, rewrites `skb->dev` to the bond master for normal delivery, and in ALB bridge host traffic rewrites the destination MAC to the bond address.

## State and Persistence
The main persistent-in-memory objects are `struct bonding`, `struct slave`, RCU-protected slave lists/arrays, delayed works, and namespace-local `struct bond_net`. There is no disk persistence. Configuration persists only while module/netdevices live: `bond->params`, `bonding_defaults`, slave permanent MACs/original MTUs, link timestamps, link failure counts, active/primary/current ARP slave pointers, peer notification counters, IPsec SA list, XDP program references, ALB/TLB state, and accumulated stats.

Concurrency relies heavily on RTNL for configuration and slave list mutation, RCU for datapath readers, ordered per-bond workqueues for monitors, spinlocks for mode/stats paths, mutexes for IPsec SA tracking, kobject reference lifetimes for slaves, and `synchronize_rcu()`/`synchronize_net()` around detach and close. Transmit arrays (`usable_slaves` and `all_slaves`) are RCU-swapped so the datapath can avoid walking mutable lists. Delayed work requeues with short delays when RTNL cannot be acquired.

Hardware and lower-device state is intentionally mutated and later restored: slave MTU, MAC, promiscuity, allmulti, VLAN filter state, multicast/unicast filters, LACP multicast membership, XDP programs, netpoll hooks, addrconf flags, and master/lower linkage. The release path records original MTU and permanent MAC so detach can restore the lower device close to pre-enslave state.

## Dependencies and Integration Points
`bond_main.c` depends on core networking infrastructure: `net_device`, rtnetlink, notifier chains, upper/lower device stacking, rx handlers, ethtool, MII ioctls, neighbour setup, VLAN APIs, flow dissector, routing, IPv4 ARP, IPv6 neighbour discovery, netpoll, XDP/BPF, TLS device offload, XFRM offload, pernet operations, proc/sysfs/debugfs helpers, and kernel module parameters. Its local bonding dependencies include `net/bonding.h`, `bond_3ad.h`, `bond_alb.h`, `bond_options.c`'s option setters, sysfs helpers, proc/debug helpers, and `bond_netlink.c`'s `bond_link_ops`.

Important integration contracts are bidirectional. `bond_netlink.c` and sysfs call the shared option engine that changes `bond->params`; `bond_main.c` enforces the resulting behavior. `bond_3ad.c` owns LACP state machines, aggregator selection, and 802.3ad stats, while this file calls its bind/unbind/link-change/TX-array/carrier functions. `bond_alb.c` owns ALB/TLB balancing and MAC learning, while this file calls its init/deinit/link-change/TX helpers. The netdev notifier path observes master and slave events and refreshes proc/debug entries, speed/duplex, slave arrays, features, primary slave name mapping, XDP features, and forced detach on unregister.

## Risks
The file is high risk because it spans control plane, datapath, workqueues, and lower-device state. Enslave/release rollback ordering is delicate; a missed reverse step can leave rx handlers, upper links, XDP programs, VLAN filters, MAC/MTU changes, or kobjects behind. Active slave changes must coordinate MAC failover, ALB/TLB state, IPsec offload migration, IGMP/peer notifications, carrier state, and RCU-visible pointers. Monitor workers avoid deadlock by using `rtnl_trylock()` and requeueing, so delayed commits and races with close/unregister are expected design points.

Datapath risks include stale or empty RCU slave arrays, hash-policy parsing differences between skb and XDP paths, broadcast clone failures, queue-id override selecting a down slave if state changes concurrently, and netpoll deadlock prevention returning `NETDEV_TX_BUSY`. ARP/NS validation is timing-sensitive and can misdiagnose links when targets/routes/VLAN paths are wrong or when switches suppress replies. IPsec offload is active-backup only and must migrate SAs during failover without double-delete/free races. XDP program propagation has multi-slave rollback and BPF reference-count risk.

Configuration risks include module parameter coercion, obsolete `use_carrier` rejection, forced `miimon` for modes needing speed/duplex, `miimon` and `arp_interval` exclusion, primary and fail_over_mac options that only affect some modes, and capability-dependent exposure of 802.3ad actor settings elsewhere. Device type mutation for first non-Ethernet slave and InfiniBand active-backup-only behavior are also compatibility-sensitive.

## Test Signals
Useful test signals include module load/unload with multiple `max_bonds` values, rtnetlink and ioctl creation/destruction, pernet namespace teardown, sysfs/proc/debugfs visibility, and clean notifier unregister. Enslave/release tests should cover first and later slaves, rollback failures at MTU/MAC/VLAN/rx-handler/upper-link/sysfs/XDP stages, VLAN-challenged slaves, non-Ethernet and InfiniBand slaves, devices without MAC setting, devices already up, and unregister events.

Runtime tests should exercise every mode: round-robin packet distribution and IGMP affinity; active-backup primary reselection, priority selection, fail_over_mac policies, peer notifications, and IGMP resend; XOR and 802.3ad hash distribution and slave-array refresh; broadcast clone/drop behavior; ALB/TLB delegation and link-change handling. Monitoring evidence should include MII updelay/downdelay transitions, ARP/NS validation with and without VLAN upper paths, missed target behavior, and carrier changes. Datapath/offload tests should cover skb TX, RX duplicate suppression/link-local pass-through, netpoll, XDP set/xmit/rollback, TLS lower-device TX, XFRM SA migration on failover, ethtool speed/timestamp reporting, hardware timestamp get/set, stats folding across slave resets, MTU/MAC rollback, multicast/allmulti/promisc propagation, and feature recomputation after slave feature changes.
