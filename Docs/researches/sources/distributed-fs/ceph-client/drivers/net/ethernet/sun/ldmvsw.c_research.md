# sources/distributed-fs/ceph-client/drivers/net/ethernet/sun/ldmvsw.c

Purpose: Implements the Sun4v LDOM virtual switch port driver. It binds VIO devices of type `vsw-port`, creates one Ethernet netdev per virtual switch port, and delegates most data-path and VIO protocol behavior to `sunvnet_common.c`.

Important APIs and functions: Module metadata identifies `ldmvsw` version 1.2. `vsw_versions[]` lists supported VIO protocol versions from 1.8 down to 1.0. Ethtool hooks `vsw_get_drvinfo()`, `vsw_get_msglevel()`, and `vsw_set_msglevel()` expose driver info and per-virtual-network debug level. Netdev hooks in `vsw_ops` wire open, stop, RX mode, MAC address, validation, TX timeout, transmit, queue selection, and optional netpoll to common helpers. `vsw_tx_port_find()` returns the current port for transmit routing, while `vsw_select_queue()` maps packets to `port->q_index`. `ldmvsw_open()` resets the VIO channel, resets port state, and brings the VIO port up. `vsw_get_vnet()` finds the parent `virtual-network-switch` machine-description node, extracts `local-mac-address` and `cfg-handle`, then finds or allocates a shared `struct vnet`. `vsw_alloc_netdev()` allocates an Ethernet device with `VNET_MAX_TXQS`, sets the static switch-port MAC, name, feature flags, MTU bounds, and ops. `vsw_port_probe()` performs full port discovery/allocation/registration. `vsw_port_remove()` tears the port down. `vsw_cleanup()` releases the global `vnet_list` after VIO driver unregister.

Control flow: Module init calls `vio_register_driver()` with `vsw_port_driver`. On probe, the driver grabs the machine description, reads the remote MAC and port ID, locates/creates the shared virtual network record, allocates a netdev named `vif<cfg-handle>.<port-id>`, fills `struct vnet_port`, initializes VIO protocol state via `vio_driver_init()`, allocates the LDC channel using `vsw_ldc_cfg`, installs NAPI, links the port onto `vp->port_list` under `vp->lock`, initializes the clean timer, registers the netdev, adds its TX queue to common vnet state, enables NAPI, raises the VIO port, and forces carrier off until an LDC up event arrives. Open repeats the reset/up sequence for the channel. TX enters `sunvnet_start_xmit_common()` with a port selector that always returns the current switch port. RX/event handling, attribute negotiation, close, polling, timeout, buffer cleanup, and MAC/RX-mode handling are delegated to `sunvnet_common`.

State and persistence behavior: `vnet_list` is a module-global list of shared `struct vnet` objects protected by `vnet_list_mutex` and keyed by the parent switch `local_mac`. Each `struct vnet_port` lives in the netdev private area and is stored as VIO device driver data. Per-port state includes the remote MAC, `vp` back-pointer, netdev pointer, `switch_port` marker, disabled TSO fields, `vsw` marker that changes the common `VNET_PORT_TO_NET_DEVICE` mapping, VIO state, NAPI object, clean timer, and queue index. No durable state is written to disk; all state is rebuilt from the hypervisor machine description at probe and released on remove/module exit.

Dependencies and integration points: The driver depends on Linux netdev/ethtool/NAPI APIs, SPARC sun4v VIO and LDC interfaces (`asm/vio.h`, `asm/ldc.h`), machine-description accessors (`mdesc_*`), and the common Sun virtual network implementation in `sunvnet_common.h`. It integrates with the VIO bus through `vio_device_id` type `vsw-port`, with the hypervisor through LDC unreliable mode events, and with bridge/network stack behavior by exposing per-port netdevs rather than a single aggregate `sunvnet` device. Device properties required from firmware are `remote-mac-address`, `id`, parent `local-mac-address`, and parent `cfg-handle`.

Risks and edge cases: Probe has a multi-step lifetime sequence spanning machine-description handles, shared vnet allocation, netdev allocation, VIO init, LDC allocation, NAPI registration, RCU list insertion, timers, and netdev registration; failures must unwind in the correct order. `vsw_get_vnet()` allocates a `struct vnet` before all later probe steps are known to succeed, so a probe failure after vnet creation leaves the empty vnet until module cleanup. The static `FE:FF:FF:FF:FF:FF` MAC is used for all port netdevs, making the netdev identity depend heavily on `vif<handle>.<port_id>` and common-code behavior. RCU list deletion in remove happens before taking `vp->lock` for queue removal, so common-code readers must respect RCU/list locking. Carrier is deliberately forced off after `vio_port_up()` until LDC signals link up, so tests that force carrier during config may be overridden.

Test signals: Useful tests include VIO probe with missing `remote-mac-address`, `id`, parent `local-mac-address`, or `cfg-handle`; multiple ports sharing one parent virtual switch; probe failure injection after VIO init, LDC alloc, list add, and register_netdev; remove while NAPI/timers/events are active; module unload after all ports are removed; VIO protocol negotiation across versions 1.8, 1.7, 1.6, and 1.0; TX queue selection through `q_index`; bridge operation with TSO disabled; carrier behavior before and after LDC up/reset/down events; netpoll builds; and ethtool message-level updates reflecting the shared `struct vnet`.
