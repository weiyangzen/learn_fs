# sources/distributed-fs/ceph-client/drivers/net/ethernet/sun/cassini.h

Purpose: Defines the hardware contract and driver-private state for the Sun Cassini, Cassini+, and Saturn Ethernet driver. The file is mostly a register map, bit-field catalog, DMA descriptor ABI, header-parser microcode description, and runtime `struct cas` layout consumed by the Cassini driver implementation.

Important APIs, types, and constants: Revision IDs (`CAS_ID_REV2`, `CAS_ID_REVPLUS`, `CAS_ID_REVPLUS02u`, `CAS_ID_REVSATURNB2`) identify device variants. Register groups cover global PCI/BIM arbitration and reset (`REG_CAWR`, `REG_INTR_STATUS`, `REG_SW_RESET`, `REG_BIM_CFG`), TX DMA (`REG_TX_CFG`, descriptor base/kick/complete/writeback registers), RX DMA (`REG_RX_CFG`, page size, kick, completion head/tail, blanking, almost-empty thresholds), header parser (`REG_HP_CFG`, instruction/data/FDB RAM), MAC (`REG_MAC_*` config, status, counters, address filters, hash table), MIF/MDIO (`REG_MIF_*`), PCS/SERDES (`REG_PCS_*`), expansion ROM/local bus/entropy device, and special PHY IDs/registers. Ring sizing macros (`DESC_RING_I_TO_S`, `COMP_RING_I_TO_S`, `TX_DESC_RING_SIZE`, `RX_DESC_RING_SIZE`, `RX_COMP_RING_SIZE`) encode the supported alignment-sensitive ring sizes. `struct cas_tx_desc`, `struct cas_rx_desc`, and `struct cas_rx_comp` describe the little-endian DMA descriptor and completion formats. `struct cas_init_block` lays out the physically contiguous aligned rings and TX completion writeback. `struct cas` is the driver's core private state: locks, MMIO base, ring indices, NAPI state, power/open state, DMA rings, SKB/page ownership arrays, spare page lists, tiny TX buffers for target-abort avoidance, PHY/link state, timers/work, PCI/device metadata, tuning counters, firmware image pointers, and feature flags.

Control flow and hardware programming model: The implementation using this header programs device bring-up by resetting TX/RX DMA through `REG_SW_RESET`, configuring bus/DMA behavior, allocating the aligned `cas_init_block`, writing TX/RX descriptor and completion base registers, setting ring sizes through `REG_TX_CFG` and `REG_RX_CFG`, posting RX descriptors with `REG_RX_KICK`, and enabling MAC/PCS/MIF paths after PHY negotiation. TX flow advances software `tx_new[]` indices, writes descriptors with `TX_DESC_*` fields, and kicks the matching `REG_TX_KICKN()` register; hardware advances `REG_TX_COMPN()` and optionally writes the 8-byte `tx_compwb` area. RX flow posts page descriptors in `struct cas_rx_desc`, hardware writes four-word `struct cas_rx_comp` entries, and software consumes `REG_RX_COMP_HEAD`/tail state while decoding packet length, offsets, checksum/hash status, release bits, and BAD/length-mismatch flags. Link flow uses MIF frame or bit-bang registers for external PHYs and PCS registers for 1000Base-X/SERDES. Optional HP firmware tables provide state-machine programs for IPv4/IPv6 TCP parsing, batching, fragmentation, workaround, and encryption/IPsec packet tagging.

State and persistence behavior: The header defines volatile hardware-visible state rather than persistent storage. DMA rings, completion writeback, page descriptors, and tiny buffers persist only while the netdev instance is open or the device is allocated. `struct cas` persists per PCI/netdev instance and tracks runtime link state (`enum link_state`, `link_transition` fields), power/open state (`hw_running`, `opened`, `pm_mutex`), ring producer/consumer cursors, spare/in-use RX page lists, cached PCI config bytes for suspend/resume, and firmware data staged for header parser programming. Hardware counters and interrupt status registers are read/clear or overflow-driven; several status registers auto-clear on read, so ordering matters.

Dependencies and integration points: This header assumes Linux kernel networking, PCI DMA, NAPI, timers/workqueues, sk_buffs, pages, spinlocks/mutexes, Open Firmware device nodes when `CONFIG_OF` is enabled, and little-endian descriptor fields. It is integrated by the Cassini driver C file that performs MMIO reads/writes using these offsets, allocates DMA-coherent init blocks, advertises netdev offloads based on checksum/parser features, manages PHY/MII/PCS negotiation, and exposes diagnostics/statistics. It also encodes hardware variant differences: `REG_PLUS_*` and `CAS_FLAG_REG_PLUS` for Cassini+, `REG_MINUS_*` for original Cassini, Saturn pin configuration, optional entropy/local-bus region, and multiple header-parser firmware defaults selected by build macros.

Risks and edge cases: The highest-risk areas are ABI layout and alignment: RX completion rings must be 8 KB aligned, TX descriptors 2 KB aligned by hardware comments but placed in the larger init block, and ring-size macros must match the index fields encoded in registers and RX descriptor index bits. Register read side effects can lose interrupts if status/mask/alias accesses are reordered. TX and RX descriptor bit fields are packed into 64-bit little-endian words and must not be decoded with host-endian assumptions. Variant-specific registers can be invalid on the wrong chip generation. Header-parser microcode tables are compile-time selected and easy to desynchronize from `REG_HP_INSTR_RAM_*` field widths. Link handling has many hardware workarounds, including target abort flags, minimum frame size, forced/autoneg transitions, and Cassini rev2 descriptor-corruption workaround firmware. RX page-size, MTU stride, jumbo support, and `RX_INDEX_*` encoding are coupled and should be changed together.

Test signals: Build coverage should include the Cassini driver with and without Open Firmware and any header-parser firmware macro combinations that are still supported. Runtime validation should exercise probe/reset, suspend/resume PCI config restoration, TX descriptor wraparound, TX completion writeback and direct completion register paths, RX descriptor posting and completion release paths, small/jumbo MTUs, checksum/hash status decoding, interrupt mask/status alias behavior, RX blanking/threshold interrupts, multicast exact/hash filtering, PHY MDIO reads/writes on both MDIO buses, PCS/SERDES link changes, and error paths for PCI, MAC, RX/TX tag, length mismatch, FIFO, and BIST diagnostics.
