# sources/distributed-fs/ceph-client/drivers/net/ethernet/intel/e1000/e1000_hw.c

## Purpose

`e1000_hw.c` is the hardware access and configuration layer for the legacy Intel PRO/1000 `e1000` Ethernet driver in this source tree. It translates the driver's higher-level lifecycle, link, ethtool, EEPROM, PHY, VLAN, address-filter, LED, and bus-information requests into direct MAC register, PHY register, EEPROM, and CE4100 flash/MDIO operations.

The file is intentionally hardware-revision-heavy. Most branches select behavior by `hw->mac_type`, `hw->phy_type`, `hw->media_type`, EEPROM type, and known device IDs. It supports early 82542/82543/82544 parts, 82540/82545/82546 variants, 82541/82547 IGP PHY variants, SERDES/fiber paths, and the Intel CE4100 special MDIO/flash access path.

## Important APIs, Types, and Data

The public API is declared in `e1000_hw.h` and implemented here. Key entry points are:

- Initialization and identification: `e1000_set_mac_type()`, `e1000_set_media_type()`, `e1000_reset_hw()`, `e1000_init_hw()`, `e1000_get_bus_info()`.
- Link and flow control: `e1000_setup_link()`, `e1000_phy_setup_autoneg()`, `e1000_config_collision_dist()`, `e1000_check_for_link()`, `e1000_get_speed_and_duplex()`, `e1000_force_mac_fc()`.
- PHY access and diagnostics: `e1000_read_phy_reg()`, `e1000_write_phy_reg()`, `e1000_phy_hw_reset()`, `e1000_phy_reset()`, `e1000_phy_get_info()`, `e1000_validate_mdi_setting()`.
- EEPROM/NVM access: `e1000_init_eeprom_params()`, `e1000_read_eeprom()`, `e1000_validate_eeprom_checksum()`, `e1000_update_eeprom_checksum()`, `e1000_write_eeprom()`, `e1000_read_mac_addr()`.
- Receive filters and LEDs: `e1000_hash_mc_addr()`, `e1000_rar_set()`, `e1000_write_vfta()`, `e1000_setup_led()`, `e1000_cleanup_led()`, `e1000_led_on()`, `e1000_led_off()`.
- Runtime helpers: `e1000_reset_adaptive()`, `e1000_update_adaptive()`, `e1000_enable_mng_pass_thru()`.

The central data structure is `struct e1000_hw`, defined in `e1000_hw.h`. This file reads and mutates its MMIO bases (`hw_addr`, `flash_address`, CE4100 MDIO base), hardware identity (`device_id`, `revision_id`, `mac_type`, `phy_type`, `phy_id`, `phy_revision`), link policy (`fc`, `original_fc`, `autoneg`, `autoneg_advertised`, `forced_speed_duplex`, `mdix`, `master_slave`), EEPROM parameters (`struct e1000_eeprom_info`), LED modes, MAC addresses, adaptive IFS counters, and many state flags such as `get_link_status`, `serdes_has_link`, `autoneg_failed`, `tbi_compatibility_on`, `phy_reset_disable`, `speed_downgraded`, `dsp_config_state`, and `ffe_config_state`.

Two file-scope locks serialize shared hardware buses:

- `e1000_eeprom_lock`, a mutex around public EEPROM read/write wrappers.
- `e1000_phy_lock`, a spinlock around public PHY read/write wrappers, including IGP page selection.

Other important static data includes the IGP cable-length lookup table and DSP register arrays used for cable diagnostics and IGP DSP/FFE tuning.

## Control Flow

The normal probe/init flow starts outside this file in `e1000_main.c`, which populates `struct e1000_hw`, calls `e1000_set_mac_type()`, `e1000_get_bus_info()`, `e1000_init_eeprom_params()`, `e1000_reset_hw()`, `e1000_read_mac_addr()`, and later `e1000_init_hw()`.

`e1000_reset_hw()` masks interrupts, disables RX/TX, optionally resets the PHY before the MAC on selected 82541/82547 parts, asserts a MAC global reset through either MMIO, `CTRL_DUP`, or port I/O depending on revision, waits for EEPROM autoread/reload behavior, disables ASF hardware ARP handling on newer parts, runs the IGP PHY init script for selected devices, restores MWI if needed, and leaves pending interrupts cleared.

`e1000_init_hw()` initializes ID LED state, media type, VLAN filter table, receive address registers, multicast table, PCI-X workarounds, link setup, transmit descriptor writeback policy, statistics counters, and selected quad-port relaxed-ordering workarounds. It deliberately leaves TX/RX units disabled for the main driver to configure descriptor rings later.

`e1000_setup_link()` resolves default flow control from EEPROM word `EEPROM_INIT_CONTROL2_REG`, stores `original_fc`, applies old-MAC fixups, programs 82543 software-defined pins from EEPROM, dispatches to copper or fiber/SERDES link setup, and writes flow-control address/type/timer and watermarks.

The copper link path is layered:

1. `e1000_copper_link_preconfig()` sets `CTRL` link/force bits, resets older PHYs, detects the expected PHY ID, and applies class-A or revision-specific PHY mode tweaks.
2. PHY-specific setup chooses IGP (`e1000_copper_link_igp_setup()`), M88 (`e1000_copper_link_mgp_setup()`), or Realtek/CE4100 (`gbe_dhg_phy_setup()`).
3. Autonegotiated links call `e1000_copper_link_autoneg()`, which bounds advertised speeds, writes advertisement registers through `e1000_phy_setup_autoneg()`, restarts autonegotiation, and optionally waits. Forced links call `e1000_phy_force_speed_duplex()`.
4. The setup path polls PHY link status briefly and, if link is up, runs `e1000_copper_link_postconfig()` to sync MAC speed/duplex where needed, resolve flow control, and tune IGP DSP after gigabit link.

The fiber/SERDES path uses `e1000_setup_fiber_serdes_link()`: it computes signal polarity, optionally applies SERDES amplitude from EEPROM, clears link reset, applies VCO tweaks on selected M88 PHYs, programs collision distance and TX configuration word (`TXCW`) based on `hw->fc`, restarts autonegotiation, and polls `STATUS.LU`. If autoneg fails but signal exists, it delegates to `e1000_check_for_link()` to force link against non-autonegotiating partners.

Runtime link checks run through `e1000_check_for_link()`. For copper, it uses `hw->get_link_status` as a gate, double-reads sticky PHY status, handles downshift and forced 10 Mbps polarity workarounds, updates IGP DSP/FFE state on up/down transitions, syncs MAC speed/duplex, resolves flow control after autoneg, and toggles TBI compatibility receive behavior for 82543 gigabit copper. For fiber/SERDES, it delegates to `e1000_check_for_serdes_link_generic()`, which can switch between autonegotiation and forced link based on received code words, synchronization, invalid code words, and `TXCW`.

PHY register access goes through `e1000_read_phy_reg()` and `e1000_write_phy_reg()`. These wrappers serialize access, select IGP register pages when needed, and call `_ex` helpers. Newer MACs use the hardware `MDIC` register, CE4100 uses `E1000_MDIO_CMD`/`E1000_MDIO_STS`, and older MACs bit-bang MII over `CTRL` MDIO/MDC pins.

EEPROM access is similarly layered. `e1000_init_eeprom_params()` derives Microwire vs SPI parameters from MAC type and `EECD`, with SPI size refined by reading `EEPROM_CFG`. Public read/write functions lock `e1000_eeprom_lock`, then `_do_` helpers perform bounds checks, acquire EEPROM ownership via `EECD_REQ/GNT` on newer parts, bit-bang SPI or Microwire protocols, release ownership, and route CE4100 through flash macros. Checksum helpers sum the first 64 words against `EEPROM_SUM` and can rewrite the checksum word.

Address/filter helpers program hardware tables directly. `e1000_read_mac_addr()` reads the permanent address from EEPROM and adjusts function 1 on dual-port 82546 devices. `e1000_init_rx_addrs()` writes RAR0 and clears the rest. `e1000_hash_mc_addr()` computes the 12-bit multicast hash based on `mc_filter_type`. `e1000_write_vfta()` contains a specific 82544 odd-offset workaround before writing VLAN filter entries.

LED helpers read EEPROM LED policy, save default/mode registers, program LEDCTL on newer copper devices, and use software-defined pins on older or fiber devices. Adaptive IFS helpers update the AIT register based on transmit/collision deltas supplied by the main watchdog path.

## State and Persistence Behavior

The file has no filesystem persistence. Persistent hardware state lives in EEPROM/flash and is accessed through `e1000_read_eeprom()`, `e1000_write_eeprom()`, checksum helpers, MAC-address reads, LED configuration words, flow-control defaults, PHY class words, and SERDES amplitude words. EEPROM writes can permanently alter adapter configuration and require checksum maintenance by callers.

Volatile hardware state is maintained in MMIO/PIO registers such as `CTRL`, `STATUS`, `RCTL`, `TCTL`, `TXCW`, `RXCW`, `MDIC`, `EECD`, `LEDCTL`, `MANC`, `VET`, `VFTA`, receive address registers, multicast table, flow-control registers, statistics counters, and CE4100-specific MDIO/flash windows. Many status registers are sticky or clear-on-read, so this code frequently double-reads PHY status and clears statistics by reading counters.

Driver runtime state is stored in `struct e1000_hw`. Important examples include cached EEPROM geometry, current and original flow-control policy, cached LED modes, bus type/speed/width, permanent/current MAC addresses, autoneg failure tracking, `get_link_status`, SERDES link state, TBI compatibility state, adaptive IFS state, downshift and DSP/FFE tuning state, and selected errata flags.

## Dependencies and Integration Points

This file depends on Linux kernel primitives and driver headers through `e1000.h`: MMIO/PIO helpers (`er32`, `ew32`, `E1000_WRITE_REG_ARRAY`, `E1000_WRITE_FLUSH`, `readl`, `writel`), sleeps/delays (`msleep`, `udelay`, `cond_resched`), locking (`mutex`, `spin_lock_irqsave`), PCI helpers, endian/bitfield helpers, and many register/bit definitions from `e1000_hw.h`.

Primary in-tree callers are:

- `e1000_main.c`: probe/open/reset/watchdog paths call initialization, EEPROM parameter setup, MAC address read, link checks, speed/duplex reporting, PHY info refresh, adaptive IFS updates, receive address programming, VLAN updates, and management pass-through checks.
- `e1000_ethtool.c`: ethtool settings, diagnostics, EEPROM read/write, PHY register inspection, self-tests, and physical ID blinking use the link, EEPROM, PHY, and LED routines.
- `e1000_param.c`: validates MDI/MDIX policy through `e1000_validate_mdi_setting()`.
- `e1000_osdep.h` and architecture-specific I/O paths provide the register access macros and port-I/O functions used by the reset workaround.

The file is also tightly coupled to hardware-managed subsystems: PHY autonegotiation, EEPROM/flash ownership, BMC/ASF manageability, PCI/PCI-X bus configuration, and clear-on-read statistics.

## Risks and Edge Cases

- Hardware errata dominate the implementation. Reset method, EEPROM reload delay, MWI handling, PCI-X MMRBC clamping, VLAN odd-offset writes, LED polarity, TBI compatibility, forced 10 Mbps polarity, IGP DSP/FFE tuning, SERDES VCO/amplitude changes, and quad-port relaxed-ordering behavior are all revision-specific.
- Timing is critical. PHY/EEPROM bit-banging, MDIC polling, EEPROM grant polling, autoneg waits, forced-link waits, reset delays, and DSP transmitter-disable windows depend on fixed `udelay()`/`msleep()` loops. Shortening or reordering these can cause silent link or NVM failures.
- PHY status contains sticky bits. Several paths intentionally read status registers twice; simplifying these reads can break link detection and autoneg completion checks.
- EEPROM access is persistent and shared with firmware/other functions. Missing `e1000_release_eeprom()`, incorrect `EECD_REQ` handling, or failed checksum maintenance can leave hardware or NVM in a bad state.
- PHY page selection is serialized under `e1000_phy_lock`; bypassing public wrappers risks page races, especially for IGP multi-page registers.
- Some functions return success even when link is not established (`e1000_setup_copper_link()` logs inability to establish link but returns success), because the main driver continues to poll link asynchronously. Tests must not assume setup success means carrier up.
- CE4100 paths use different MDIO/flash mechanisms and different PHY address handling. Changes tested only on PCI e1000 hardware can regress CE4100.
- `e1000_check_for_link()` returns `-E1000_ERR_CONFIG` when a forced copper link is detected after status polling, which callers must tolerate according to existing behavior.
- Counter clearing is destructive by design because statistics registers are clear-on-read.

## Test Signals

Useful validation signals for this file are mostly integration and hardware-observable:

- Probe/reset succeeds across representative MAC families; `e1000_reset_hw()` and `e1000_init_hw()` complete without EEPROM, PHY, or reset errors.
- EEPROM checksum validates, MAC address reads correctly, and ethtool EEPROM read/write paths continue to serialize and maintain checksum expectations.
- Copper autoneg advertises the configured speed/duplex/flow-control modes, reaches link, reports correct speed/duplex, and resolves pause settings correctly for symmetric, asymmetric, none, and half-duplex cases.
- Forced 10/100 links configure MAC and PHY consistently, disable flow control, and handle M88 polarity workaround cases without leaving interrupts or link state broken.
- Fiber/SERDES links autonegotiate when possible and force link against non-autonegotiating partners without false `serdes_has_link` state.
- PHY diagnostics report cable length, polarity, downshift, MDIX mode, and local/remote receiver status correctly for M88 and IGP PHYs.
- VLAN filter writes, RAR programming, multicast hash programming, and receive-address initialization produce expected packet acceptance/rejection behavior.
- LED identify operations through ethtool restore `LEDCTL` and IGP smart-power-down state after blinking.
- Watchdog paths using `e1000_check_for_link()`, `e1000_update_adaptive()`, and `e1000_phy_get_info()` behave correctly after link up/down, cable swaps, downshift, and gigabit IGP DSP changes.
- Static analysis should check lock pairing, EEPROM release on every error path after acquisition, register page restoration where required, and absence of sleeps in spinlocked sections beyond the existing PHY access design.
