# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_utils.c

Purpose: Implements common Atlantic hardware utility logic above the raw register accessor layer. It handles firmware-version detection and operation selection, FLB/RBL soft reset sequences, firmware mailbox and RPC data transfers, MPI state/speed control, link status decoding, permanent MAC retrieval, chip-feature detection, statistics accumulation, register dump support, and firmware 1.x Wake-on-LAN power handling.

Important APIs, types, and functions: `hw_atl_utils_initfw()` initializes chip feature flags, reads firmware version, selects `aq_fw_1x_ops` or `aq_fw_2x_ops`, and invokes the selected firmware init method. `hw_atl_utils_soft_reset()` detects boot mode, handles firmware 1.x power-state workaround and firmware 4.x reset semaphores, then dispatches to `hw_atl_utils_soft_reset_flb()` or `hw_atl_utils_soft_reset_rbl()`. `hw_atl_utils_fw_downld_dwords()` reads firmware/MCP memory via the MIF path under the RAM semaphore. `hw_atl_write_fwcfg_dwords()` and `hw_atl_write_fwsettings_dwords()` upload configuration/settings through revision-specific B0/B1 mailbox flows. `hw_atl_utils_fw_rpc_call()` and `hw_atl_utils_fw_rpc_wait()` implement firmware RPC transaction ID and length handshaking. `hw_atl_utils_mpi_read_mbox()`, `hw_atl_utils_mpi_read_stats()`, `hw_atl_utils_mpi_set_state()`, `hw_atl_utils_mpi_get_link_status()`, `hw_atl_utils_get_mac_permanent()`, `hw_atl_utils_update_stats()`, and `hw_atl_utils_hw_get_regs()` are the main utility entry points. The file also defines the firmware 1.x ops table `aq_fw_1x_ops`.

Control flow: Firmware init reads `HW_ATL_MPI_FW_VERSION` and accepts 1.x, 2.x, 3.x, or 4.x ranges through `hw_atl_utils_ver_match()`, using 2.x ops for 2.x through 4.x. Reset first waits for either FLB/RBL startup evidence, records `self->rbl_enabled`, optionally forces firmware 1.x to `MPI_DEINIT`, optionally acquires reset semaphores for firmware 4.x, then executes a long sequence of direct register writes and polling loops. The FLB path kickstarts MAC/FW, resets SPI around possible interrupted bursts, performs global software reset, clears RX/TX reset-disable, releases the MAC/PHY MPI reset bit, and waits for firmware version to appear. The RBL path marks boot status with `0xDEAD`, triggers reset, waits for a replacement boot code, rejects flashless missing-FW status, and waits for firmware. Mailbox downloads poll the RAM semaphore, program MIF address/command, use revision-specific completion checks, read `HW_ATL_MIF_VAL`, and release the semaphore. Uploads use either B1 scratchpad/interrupt protocol or B0 MIF write command protocol. RPC wait loops until firmware transaction ID and length indicate completion, optionally reissues a call when firmware reports `len == 0xffff`, then downloads response data.

State and persistence behavior: The file mutates `struct aq_hw_s` fields including `chip_features`, `fw_ver_actual`, `aq_fw_ops`, `rbl_enabled`, `mbox_addr`, `rpc_addr`, `settings_addr` via mailbox data, `rpc_tid`, `rpc`, `aq_link_status`, `curr_stats`, `last_stats`, and hardware-visible MPI state/speed. It writes firmware control registers, scratchpads, semaphores, reset bits, MIF registers, and RPC control/state registers. Stats are accumulated in software as deltas from mailbox counters, with hardware DMA counters read directly every update. No disk persistence exists; state is reconstructed on probe/reset/open.

Dependencies and integration points: Includes `../aq_nic.h`, `../aq_hw_utils.h`, `hw_atl_utils.h`, `hw_atl_llh.h`, `hw_atl_llh_internal.h`, and `<linux/random.h>`. It depends on Linux polling macros (`readx_poll_timeout_atomic`), endian helpers (`__swab32`), `get_random_bytes()`, Ethernet address helpers, kernel error codes, `aq_hw_err_from_flags()`, chip-feature macros, the firmware ops ABI (`struct aq_fw_ops`), and the raw LLH accessors. It integrates with higher-level Atlantic probe/reset/link/stat/power code through the firmware ops table and utility prototypes in `hw_atl_utils.h`.

Risks: Reset sequencing is hardware- and firmware-revision-sensitive; reordering writes or changing delays/poll timeouts can leave the MAC, SPI, PHY, or firmware processor wedged. RAM semaphore handling is fragile: the download path forcibly writes the semaphore if polling fails, and both upload/download must release it correctly. The B1 mailbox protocol relies on scratchpad top bits changing away from the selected area after forcing a uP interrupt. RPC transaction length and TID validation prevent oversized copies into `self->rpc`; changes must preserve those bounds. `hw_atl_utils_update_stats()` suppresses mailbox delta accumulation if any counter appears to regress while link is up, so corrupted mailbox reads can freeze software counter deltas until the next clean baseline. Permanent MAC fallback synthesizes an address from random/UCP data when efuse data is invalid; this avoids multicast/zero addresses but may not be stable across all failure modes. Some declarations in `hw_atl_utils.h` (`hw_atl_utils_mpi_set`, `hw_atl_utils_hw_set_power`, `hw_atl_utils_hw_deinit`, `hw_atl_utils_fw_set_wol`) are not implemented in this file, so their definitions must come from other Atlantic firmware modules or be legacy prototypes.

Test signals: Exercise probe/init across firmware 1.x, 2.x, 3.x, and 4.x devices; both FLB and RBL reset paths; firmware 4.x reset semaphore timeouts; link speed transitions for 100M/1G/2.5G/5G/10G; mailbox read/write under B0 and B1 revisions; RPC request/response including oversized-length rejection; WoL magic enable/disable through firmware 1.x power path; stats update under traffic and after link down/up; efuse MAC read failure fallback; and register dump count/address consistency. Fault injection around MIF command timeout, scratchpad timeout, semaphore acquisition, and firmware version absence is particularly valuable.
