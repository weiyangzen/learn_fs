# sources/distributed-fs/ceph-client/drivers/net/ethernet/pensando/ionic/ionic_lif.h

Purpose: This header declares the core LIF state model, QCQ container, per-queue software statistics, PHC state, queue reconfiguration parameters, inline helpers, and cross-file LIF APIs used by the Ionic Ethernet driver, PTP hardware timestamping, datapath, ethtool, RX filter, and RDMA/auxiliary integration code.

Important APIs/types: `struct ionic_qcq` wraps queue, completion queue, interrupt info, NAPI, DIM, debugfs, DMA/CMB ring backing, SG backing, and optional doorbell work. `struct ionic_lif` is the central per-netdev object containing netdev pointer, state bitmap, locks, admin/notify/Tx/Rx QCQs, timestamp queues, deferred work, doorbell page, queue counts/descriptors, feature masks, RX filter state, RSS table/key, coalescing config, PHC, debugfs, and XDP program. `struct ionic_phc` holds cyclecounter/timecounter, PTP clock info, timestamp config, and synchronization for hardware clock operations. `struct ionic_queue_params` captures mutable queue settings used by ethtool/XDP/timestamp reconfiguration. Inline helpers include `ionic_init_queue_params()`, `ionic_set_queue_params()`, `ionic_coal_usec_to_hw()`, and `ionic_txq_hwstamp_enabled()`. Public prototypes expose LIF lifecycle, link checks, address filters, queue reconfiguration, RSS, RX mode, PHC/hwtstamp, and timestamp queue operations.

Control flow: The header does not execute major logic but codifies state transitions used in `ionic_lif.c`. Queue parameters are snapshotted before reconfiguration, mutated, and then either applied or restored. Conditional PTP stubs compile hwtstamp operations to `-EOPNOTSUPP` or no-ops when `CONFIG_PTP_1588_CLOCK` is disabled, allowing netdev ops to remain present without requiring PHC support.

State and persistence behavior: `enum ionic_lif_state_flags` defines the lifecycle and recovery flags persisted in `lif->state`: initialized, queues up, link check requested, filter sync needed, firmware reset/stopping, split interrupts, broken state, DIM enablement, and CMB Tx/Rx rings. Per-queue stats persist separately from firmware stats and include Tx offload, DMA-map, timestamp, and XDP counters. `struct ionic_phc` persists the requested hwtstamp configuration so it can be replayed after firmware reset and queue recreation after stop/open.

Dependencies: The header depends on Linux PTP/timecounter APIs, net timestamp config, DIM, PCI, BPF forward declarations through included driver headers, `ionic_rx_filter.h`, and the queue/API types in `ionic_api.h`. It assumes `struct ionic`, `struct ionic_queue`, `struct ionic_cq`, and `struct ionic_intr_info` definitions from included Ionic internals.

Integration points: `q_to_qcq()`, `napi_to_qcq()`, and related macros link datapath queue callbacks back to the LIF container. `ionic_get_stats64()` is wired into netdev ops. PHC prototypes are consumed by `ionic_phc.c` and netdev hwtstamp ops. `ionic_reconfigure_queues()` is used by ethtool queue settings, XDP attach/detach, CMB changes, and hardware timestamp RX-all mode. RX mode and RSS APIs are used by netdev callbacks and ethtool.

Risks: Because `struct ionic_lif` is shared across many files, field lifetime assumptions must remain stable. State bits are concurrency gates; adding or reusing bits without auditing worker, NAPI, firmware reset, and netdev paths can produce races. Conditional PTP stubs can hide timestamp feature paths in builds without `CONFIG_PTP_1588_CLOCK`, so callers must still handle `-EOPNOTSUPP`. Queue parameter helpers change state bits directly and need to stay aligned with allocation/reconfiguration unwind logic.

Test signals: Build with and without `CONFIG_PTP_1588_CLOCK`, with XDP and SR-IOV enabled. Exercise queue reconfiguration, PHC hwtstamp set/get, RX/TX stats accumulation, DIM coalescing updates, and firmware reset replay to validate state held in these structures. Static analysis should check lock coverage around `queue_lock`, `config_lock`, `adminq_lock`, PHC locks, and deferred work list use.
