# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hw_comm.c

This file wraps common firmware commands used by initialization, teardown, interrupts, queue contexts, and diagnostics. APIs include interrupt config get/set, function reset, common feature negotiation, global attributes, service-used state, DMA attributes, work-queue page size, command queue depth, RX/TX flush, BDF context, time sync, root context setup/cleanup, and management firmware version. Control flow is command-struct assembly followed by `hinic3_send_mbox_to_mgmt` or no-ack mailbox send; status in the returned `mgmt_msg_head` is treated as failure. `hinic3_func_rx_tx_flush` is the most complex path: stop cmdqs, disable doorbells, flush doorbells, mark FLR start, notify firmware, wait for PF FLR finish, reenable doorbells, and reinitialize cmdq contexts. State touched includes `hwdev->features`, `cmdqs->status`, PF status register, doorbell enable, command queue contexts, and firmware time. Dependencies are mailbox transport, hwif status/doorbell helpers, cmdq helpers, and firmware ABI structs from `hinic3_hw_intf.h`. Risks are timeout handling, no-ack flush ordering, power/link loss via `chip_present_flag`, and `ilog2` assumptions for queue depths/page sizes. Test signals are probe/reset, remove flush, ethtool firmware version, interrupt moderation changes, and root context setup under traffic.
