# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hwif.h

This header declares the low-level hardware-interface object and helpers. It defines PF/VF function types, doorbell allocation state, parsed function attributes, hwif BAR pointers, outbound/doorbell control enums, PF status values, MSI-X mask and auto-mask enums, PF/VF predicate macros, MMIO read/write APIs, doorbell allocation/free, PF status get/set, hwif init/free, MSI-X control helpers, and identity accessors for global function ID, VF's PF ID, PF/VF offset, and PPF index. State represented here is per-function hardware identity and BAR resource ownership. Dependencies are Linux build assertions and spinlock types; implementation depends on CSR macros and PCI BAR mapping. Integration points include every firmware command wrapper, EQ setup, mailbox data access, queue doorbells, interrupt handling, and PCI probe. Risks include using helpers before `hinic3_init_hwif`, relying on fixed `struct hinic3_func_attr` size, and caller responsibility for doorbell lifetime. Test signals are probe logs showing parsed attributes, queue setup doorbells, MSI-X state toggles, and PF/VF-specific code paths.
