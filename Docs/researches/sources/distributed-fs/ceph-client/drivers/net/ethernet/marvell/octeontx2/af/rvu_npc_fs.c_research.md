# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_npc_fs.c

Purpose: implements NPC flow steering on top of the raw MCAM manager. It scans the active key extraction profile to discover which packet fields can be matched, translates `npc_install_flow` mailbox requests into MCAM keywords/actions, maintains the ordered rule list, handles default-rule append semantics, manages optional counters, and exposes mailbox handlers for flow install/delete and field capability queries.

Important APIs and functions: `npc_flow_steering_init()` initializes `mcam->mcam_rules` and calls `npc_scan_verify_kex()`. `npc_is_feature_supported()` and `rvu_mbox_handler_npc_get_field_status()` report field support. `npc_update_entry()` writes a field value/mask into `struct mcam_entry_mdata` according to scanned keyword masks. `npc_update_flow()` handles L2/L3/L4/MPLS/IPsec/VLAN field translation and delegates IPv6 hash replacement to `npc_update_field_hash()`. `npc_populate_mcam_mdata()` abstracts normal versus CN20K entry layouts. `rvu_mbox_handler_npc_install_flow()` is the main flow-install mailbox entry point, while `rvu_mbox_handler_npc_delete_flow()`, `npc_mcam_enable_flows()`, `npc_mcam_disable_flows()`, and `npc_install_mcam_drop_rule()` manage lifetime and exact-match drop rules.

Control flow: initialization reads `NPC_AF_INTFX_KEX_CFG` parse-nibble enables and LDATA extractor registers for RX and TX. It records keyword masks for parse-result nibbles such as channel, error, layer types, LXMB, and exact-match result, then scans layer data for DMAC/SMAC, ethertype, VLAN, IPv4/IPv6, TCP/UDP/SCTP, ICMP, IPsec SPI, MPLS, and PF_FUNC. It validates that mandatory RX channel extraction exists and is not overwritten, derives `rx_features` and `tx_features`, and checks multi-layer ethertype/VLAN positions. Flow installation validates interface and supported features, optionally allocates a CN20K entry with the correct key width, resolves target pcifunc from AF/PF/VF/representor context, fills missing default DMAC, checks NIXLF state, then under `rswitch->switch_lock` constructs the MCAM entry. RX entries match channel and produce `nix_rx_action`; TX entries match PF_FUNC and produce `nix_tx_action`. The rule object is inserted in entry order, written through the raw MCAM mailbox handler, and later deleted or disabled by owner/range/entry.

State and persistence: scanned key positions persist in `mcam->rx_key_fields`, `mcam->tx_key_fields`, `mcam->rx_features`, and `mcam->tx_features`. Installed flows persist as `struct rvu_npc_mcam_rule` list nodes containing packet/mask copies, RX/TX action union, VLAN tag action, feature bits, owner, entry, counter metadata, default-rule flag, enable flag, VF VLAN marker, channel/mask, LXMB value, and CN20K hardware priority. Default unicast rules are also referenced from `rvu_pfvf->def_ucast_rule`. Hardware persistence is the MCAM entry/action/tag/counter state written by `rvu_npc.c` or CN20K handlers.

Dependencies and integration: depends on `rvu_npc.c` for raw MCAM writes, entry ownership validation, counter helpers, default entry indexing, and MCAM enable/disable; on `rvu_npc_hash.c` for hashed IPv6 field insertion; on NIX for LF lookup, multicast group index resolution, MCE updates, rate-limit aggregation, and channel numbers; on representor/switchdev state for VF MAC handling; and on CN20K helpers for extractor and MCAM entry format differences.

Risks: feature support is profile-derived, so an incompatible MKEX profile can silently make flow types unavailable or force fallback to the default profile. Overlap checks are essential because higher layers can overwrite earlier fields in the key; skipping them would install misleading filters. Default-rule append merges missing fields from the existing default unicast rule and can produce unexpected matches if feature masks are wrong. Locking alternates between `mcam->lock` and `rswitch->switch_lock`, and `npc_update_dmac_value()` temporarily drops `mcam->lock` before writing entries. CN20K allocation must free freshly allocated entries on every validation error. Counter handling differs between pre-CN20K explicit counters and CN20K per-entry counters.

Test signals: validate `npc_get_field_status` for every supported/unsupported field under default and custom MKEX profiles. Install and delete RX/TX flows for DMAC/SMAC, VLAN, IPv4/IPv6, ports, ICMP, TCP flags, IPsec, MPLS, broadcast/multicast LXMB fallback, default-rule append, counters, MCAST actions, representor targets, PF-set VF MAC, uninitialized VF behavior, and CN20K key-width allocation. Verify entry ordering, hardware counters, delete range/all paths, flow reenable after NIXLF init, flow disable on detach, and exact-match drop rule behavior.
