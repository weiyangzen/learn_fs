# sources/distributed-fs/ceph-client/drivers/net/ethernet/freescale/gianfar_ethtool.c

## Purpose
`gianfar_ethtool.c` implements the Gianfar driver's ethtool interface. It exposes driver information, register dumps, coalescing, ring sizing, pause parameters, private/RMON statistics, message level, wake-on-LAN, RX classifier rules, RX hash-field programming, RX ring count, timestamping capabilities, and phylib link settings.

## Important APIs, types, and functions
The exported operation table is `gfar_ethtool_ops`. Stats support uses `stat_gstrings`, `gfar_gstrings()`, `gfar_fill_stats()`, and `gfar_sset_count()`. Register and driver identity support uses `gfar_gdrvinfo()`, `gfar_reglen()`, and `gfar_get_regs()`. Coalescing uses `gfar_gcoalesce()`, `gfar_scoalesce()`, `gfar_usecs2ticks()`, and `gfar_ticks2usecs()`. Ring and pause operations use `gfar_gringparam()`, `gfar_sringparam()`, `gfar_gpauseparam()`, and `gfar_spauseparam()`. Feature reconfiguration is exported as `gfar_set_features()`. WOL uses `gfar_get_wol()` and `gfar_set_wol()` when PM is enabled. RX flow classification and filer programming use `gfar_set_nfc()`, `gfar_get_nfc()`, `gfar_add_cls()`, `gfar_del_cls()`, `gfar_get_cls()`, `gfar_get_cls_all()`, `gfar_process_filer_changes()`, `gfar_convert_to_filer()`, `gfar_write_filer_table()`, and many field translation helpers. RX hash-field programming uses `gfar_set_rxfh_fields()`, `gfar_ethflow_to_filer_table()`, and `ethflow_to_filer_rules()`. Timestamp reporting uses `gfar_get_ts_info()`.

## Control flow
Read-only ethtool operations mostly copy current software or hardware state: stats combine atomic extra counters with optional RMON registers, register dumps iterate over `struct gfar`, coalescing reads queue interrupt-coalescing fields, ring parameters read queue sizes, pause reads stored pause flags, NFC queries walk the software classifier list, and timestamp info locates the QorIQ PTP device when available.

Mutating operations validate capabilities and inputs, serialize against resets or classifier mutations, update in-memory driver state, and then either reset/restart the hardware or rewrite the relevant registers. Coalescing validates max usecs and frames, updates all queue `rxic`/`txic` values, then stops/starts a running device or resets MAC config when down. Ring changes require power-of-two sizes, update all queue ring sizes, and rebuild rings if running. Feature changes for VLAN and RX checksum stop/start or reset to rebuild RX FCB expectations. Pause changes update phylib advertised pause and optionally write MACCFG1 immediately for forced pause.

RX classifier insertion copies the ethtool rule, inverts masks into the form expected by local conversion code, checks support, inserts the rule in location order, converts the full ordered list into a temporary filer table, and writes the hardware table. Deletion removes the list node and rewrites the table. RX hash-field changes find the parse-rule cluster for a flow class and splice hash rules into the cached hardware filer arrays.

## State and persistence behavior
Ettool state persists only while the driver instance exists. Coalescing values live in each queue. Ring sizes live in each queue and take effect on the next ring allocation. Pause and WOL settings live in `struct gfar_private`. RX classifier rules persist in `priv->rx_list` and are replayed into hardware whenever rules change. The active hardware filer image is cached in `priv->ftp_rqfpr` and `priv->ftp_rqfcr`; this cache is also used by PM WOL restore. Stats are split between atomic software counters and volatile hardware RMON counters. There is no on-disk persistence or firmware storage.

## Dependencies and integration points
This file integrates ethtool core, phylib link settings, PHY pause validation, netdev feature toggles, the main driver's stop/start/reset helpers, the Gianfar receive filer hardware, VLAN field definitions, OF platform lookup, and the `fsl,etsec-ptp` QorIQ PTP driver. It depends on `gianfar.h` for register bits, filer PIDs, queue structures, stats lengths, and private state. Its classifier support is tightly coupled to the default filer table initialized by `gfar_init_filer_table()` in the main driver.

## Risks and edge cases
The classifier path is the most complex and highest risk. It rewrites the entire hardware filer table from a software list, uses inverted ethtool masks, has limited hardware table capacity, and supports only selected flow types and fields. Unsupported masks are often warned rather than rejected, so user expectations can differ from hardware behavior. `gfar_ethflow_to_filer_table()` must find expected parse-rule clusters in the cached filer table; if default filer initialization changes, hash-field programming can fail. Coalescing conversions depend on current PHY speed, so reported usecs can shift with link speed. Ring changes and feature toggles stop/start live hardware and must not race with reset or classifier changes. WOL accepts magic packet preferentially over unicast filer WOL when both are requested.

## Test signals
Useful tests include `ethtool -S`, `-d`, `-c/-C`, `-g/-G`, `-a/-A`, `-s` through phylib link settings, `-k/-K` for VLAN and RX checksum toggles, `-sopass`-free WOL magic/unicast settings, `-n/-N` classifier insert/delete/list for TCP/UDP/SCTP/IP_USER/ETHER with VLAN extension, RX hash-field changes for supported IPv4/IPv6 TCP/UDP classes, and `ethtool -T` with and without the QorIQ PTP device. Negative tests should cover overlarge coalescing values, non-power-of-two ring sizes, invalid ring cookies, full filer tables, unsupported flow types, missing PHY, and concurrent reset-state rejection.
