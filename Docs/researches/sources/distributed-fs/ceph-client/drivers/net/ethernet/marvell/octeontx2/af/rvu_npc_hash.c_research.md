# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_npc_hash.c

Purpose: implements two related NPC hash features. The first programs and emulates field-hash extraction so IPv6 source/destination addresses can be reduced to 32-bit MCAM key fields on hardware that supports hash extract. The second implements the optional NPC exact-match table used for MAC address filtering, including hardware table programming, software entry lists, drop-on-non-hit MCAM rules, promisc transitions, and CGX MAC mailbox handlers.

Important APIs and functions: field-hash support includes `npc_config_secret_key()`, `npc_program_mkex_hash()`, `npc_update_field_hash()`, `npc_field_hash_calc()`, and `rvu_mbox_handler_npc_get_field_hash_info()`. Hash math is implemented by `rvu_npc_toeplitz_hash()`, `rvu_npc_wide_extract()`, and `rvu_npc_lshift_key()`. Exact-match setup is handled by `rvu_npc_exact_init()`, `rvu_exact_config_secret_key()`, `rvu_exact_config_search_key()`, `rvu_exact_config_table_mask()`, and `rvu_exact_config_result_ctrl()`. Runtime table management uses `rvu_npc_exact_add_table_entry()`, `rvu_npc_exact_del_table_entry_by_id()`, `rvu_npc_exact_update_table_entry()`, MEM/CAM alloc/free helpers, and CGX-facing handlers `rvu_npc_exact_mac_addr_set/add/del/reset/update()`. Promisc and feature lifetime are handled by `rvu_npc_exact_promisc_enable()`, `rvu_npc_exact_promisc_disable()`, `rvu_npc_exact_reset()`, `rvu_npc_exact_can_disable_feature()`, and `rvu_npc_exact_disable_feature()`.

Control flow: during normal NPC initialization, `npc_config_secret_key()` writes Toeplitz secret keys if hash extraction is available. `npc_program_mkex_hash()` detects IPv6 source/destination LDATA extractors configured as 4-byte fields at offsets 8 and 24, marks them hash-enabled, updates KEX LDATA config to `use_hash`, and writes HASH_CFG, HASH_MASK, and HASH_RESULT_CTRL registers. Later `npc_update_flow()` calls `npc_update_field_hash()`, which reads hash configuration, computes the same Toeplitz result in software, applies hardware mask/offset, and writes a 32-bit hash into the SIP/DIP MCAM field. Exact-match initialization reads `NPC_AF_CONST3`, checks exact-match capability and exact-result nibble enablement, allocates the `npc_exact_table`, initializes bitmaps and ordered lists, programs exact-match key/mask/result-control registers, then installs one disabled drop MCAM rule per CGX LMAC. Adding a MAC first tries a hashed multi-way MEM slot, falls back to CAM, writes the hardware entry, records a global/list node with seq_id, and enables the corresponding drop rule when the first command rule appears. Delete removes list state, disables drop rules when counts reach zero, clears hardware MEM/CAM entries, and frees the seq_id.

State and persistence: field-hash configuration is stored in NPC AF hash and secret-key registers and mirrored in `rvu->kpu.mkex_hash`. Exact-match state is held in `rvu->hw->table`: table lock, id bitmap, command rule counts, drop-rule counter indexes, promisc mode flags, MEM table ways/depth/bitmap/mask/hash mask/offset, CAM depth/bitmap, per-way ordered lists, CAM list, and global list. Each `npc_exact_table_entry` stores seq_id, MEM/CAM index, MCAM index, op type, channel, pcifunc, way, MAC, CGX/LMAC, channel type, and whether it came from a command. Hardware persistence includes exact MEM/CAM entries, exact secret/search/mask/result registers, and the MCAM drop rules installed through `rvu_npc_fs.c`.

Dependencies and integration: depends on `rvu_npc_fs.h` for field insertion and drop-rule programming, `rvu_npc.c` for MCAM enable-by-index/default indexing, CGX mailbox request types, RVU PF-to-CGX/LMAC mapping, NIX channel helpers, and debugfs-visible table lists. CN20K returns early for both MKEX hash programming and exact-match initialization, so this file primarily services pre-CN20K hardware.

Risks: the software Toeplitz implementation must match hardware bit ordering exactly or hashed IPv6 filters will miss. Hash extraction intentionally replaces full IPv6 matching with a 32-bit value under specific profiles, increasing collision risk and requiring masks to be understood by users. Exact-match update can only rewrite a MEM entry in place if the new MAC hashes to the same index; otherwise it must delete and add, which can fail if tables are full. Several exact-match paths hold `table->lock` while coordinating with MCAM enable state, so lock ordering must remain consistent. Drop-rule bookkeeping assumes CGX-only support and rejects LBK/SDP. Error paths after hardware writes and list insertion must avoid leaking table bitmap bits or seq_ids.

Test signals: validate `npc_get_field_hash_info`, IPv6 SIP/DIP filters under hash-enabled and non-hash profiles, and hardware/software hash agreement with known vectors. Exact-match tests should cover init with/without capability and exact nibble, MEM slot allocation across all ways, CAM fallback, full-table failure, MAC set/add/update/delete/reset, update that changes hash index, per-PF drop rule enable/disable as command counts cross zero, promisc enable/disable, reset by pcifunc, and debugfs table visibility. Traffic should confirm accepted programmed DMACs, dropped unknown unicast when drop rule is enabled, and no drops in promisc mode.
