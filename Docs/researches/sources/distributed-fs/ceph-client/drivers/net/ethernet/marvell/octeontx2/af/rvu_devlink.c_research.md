# sources/distributed-fs/ceph-client/drivers/net/ethernet/marvell/octeontx2/af/rvu_devlink.c

Purpose: provides the RVU AF `devlink` integration. It registers the AF as a devlink instance, wires NPA and NIX AF hardware interrupt classes into devlink health reporters with dump and recovery callbacks, exposes runtime devlink parameters for scheduler/MCAM/NPC/NIX behavior, and implements devlink eswitch mode get/set for legacy versus switchdev operation.

Important APIs/functions: public entry points are `rvu_register_dl()` and `rvu_unregister_dl()`. Health reporter setup flows through `rvu_health_reporters_create`, `rvu_npa_health_reporters_create`, `rvu_nix_health_reporters_create`, matching destroy functions, and reporter registration helpers. IRQ handlers include NIX `rvu_nix_af_rvu_intr_handler`, `rvu_nix_af_rvu_gen_handler`, `rvu_nix_af_rvu_err_handler`, `rvu_nix_af_rvu_ras_handler` and NPA `rvu_npa_af_rvu_intr_handler`, `rvu_npa_af_gen_intr_handler`, `rvu_npa_af_err_intr_handler`, `rvu_npa_af_ras_intr_handler`. Dump/recover callbacks are generated via `RVU_REPORTERS` for `hw_nix_*` and `hw_npa_*`. Devlink params are implemented by `rvu_af_dl_dwrr_mtu_*`, `rvu_af_npc_defrag_*`, `rvu_af_npc_exact_feature_*`, `rvu_af_dl_npc_mcam_high_zone_percent_*`, `rvu_af_dl_npc_def_rule_cntr_*`, and `rvu_af_dl_nix_maxlf_*`. Eswitch ops are `rvu_devlink_eswitch_mode_get` and `rvu_devlink_eswitch_mode_set`.

Control flow: registration allocates a devlink object with private `struct rvu_devlink`, links it to `rvu->rvu_dl`, creates NPA and NIX health reporters, registers the base parameter table, conditionally registers CN20K defrag and exact-match parameters, then calls `devlink_register()`. Each NPA/NIX interrupt handler reads the relevant AF interrupt register, stores the value in the reporter event context, clears and disables that interrupt source, then queues work on `rvu_dl->devlink_wq`. The work item calls `devlink_health_report()`, allowing devlink to invoke dump/recover callbacks. Dump callbacks format decoded interrupt bits into `devlink_fmsg`; recover callbacks re-enable the interrupt source if the saved event bitfield is nonzero. Unregister reverses devlink registration, parameter registration, reporter/interrupt setup, and frees the devlink object.

State and persistence: persistent state is the `struct rvu_devlink` attached to `rvu`, allocated NPA/NIX reporter containers, per-subsystem event contexts holding the last interrupt register values, work structs, the devlink workqueue, `rvu->irq_allocated[]`, devlink parameters backed by live RVU state, `rvu->def_rule_cntr_en`, `rvu->rswitch.mode`, and mutable resource fields such as NIX LF maxima and MCAM priority-zone counts. State lasts for the PCI driver lifetime and is not persisted across unload. Health handling intentionally disables an interrupt until recovery re-enables it.

Dependencies and integration: depends on Linux devlink, devlink health reporters, PCI IRQs, workqueues, netlink extack reporting, RVU register helpers, NPA/NIX/NPC register definitions, NPC exact-match/defrag code, NIX scheduler/resource helpers, and switchdev functions (`rvu_switch_enable`, `rvu_switch_disable`). It integrates with user-visible `devlink health`, `devlink dev param`, and `devlink dev eswitch` controls.

Risks: reporter allocation error paths can leak earlier allocations/reporters because some helper failures return immediately without local cleanup until higher-level destroy paths are reached, and destroy helpers assume reporter containers are initialized. Both NPA and NIX reporter registration create `rvu_dl->devlink_wq`; the second assignment can replace the first pointer, risking a leaked workqueue and ambiguous ownership. Interrupt handlers disable sources before asynchronous reporting, so failed or delayed recovery can suppress later events. The NIX RAS handler reads `NIX_AF_ERR_INT` but clears `NIX_AF_RAS`, which is a suspicious register mismatch. Devlink parameter setters mutate global hardware/resource policy at runtime and rely on validators to prevent active-resource changes; missing validation would affect active PF/VF users. Some registration helpers ignore interrupt registration failures and still report success.

Test signals: validate `devlink dev show`, health reporter presence, interrupt injection/report/dump/recover for all NPA/NIX classes, and interrupt re-enable after recovery. Exercise devlink params with valid/invalid values: `dwrr_mtu`, `npc_mcam_high_zone_percent`, `npc_def_rule_cntr`, `nix_maxlf`, CN20K `npc_defrag`, and exact-match disable. Confirm active MCAM/NIXLF users block resizing. Toggle eswitch legacy/switchdev and verify `rvu_switch_enable`/`rvu_switch_disable` effects. Run driver probe/remove with fault injection at each allocation/registration point to catch leaked reporters, IRQs, or workqueues.
