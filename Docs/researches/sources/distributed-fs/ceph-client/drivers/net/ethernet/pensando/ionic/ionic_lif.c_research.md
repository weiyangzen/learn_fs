# sources/distributed-fs/ceph-client/drivers/net/ethernet/pensando/ionic/ionic_lif.c

Purpose: This is the main Logical Interface implementation for the Ionic Ethernet driver. It owns netdev allocation and registration, LIF initialization, admin/notify/Tx/Rx queue lifecycle, interrupt/NAPI setup, link-state handling, netdev operations, feature negotiation, RSS, RX filters, SR-IOV VF controls, XDP setup, hardware timestamp queue plumbing, queue reconfiguration, and firmware reset recovery.

Important APIs/functions: Public entry points include `ionic_lif_alloc()`, `ionic_lif_init()`, `ionic_lif_register()`, `ionic_lif_unregister()`, `ionic_lif_deinit()`, `ionic_lif_free()`, `ionic_lif_identify()`, `ionic_lif_size()`, `ionic_restart_lif()`, `ionic_qcqs_free()`, `ionic_txrx_free()`, `ionic_stop_queues_reconfig()`, `ionic_reconfigure_queues()`, `ionic_lif_rss_config()`, `ionic_lif_rx_mode()`, `ionic_lif_deferred_enqueue()`, `ionic_link_status_check_request()`, and hardware timestamp helpers exported to `ionic_phc.c`. Internal key paths include `ionic_qcq_alloc()`, `ionic_qcq_enable()`, `ionic_qcq_disable()`, `ionic_lif_txq_init()`, `ionic_lif_rxq_init()`, `ionic_txrx_alloc()`, `ionic_txrx_init()`, `ionic_txrx_enable()`, `ionic_start_queues()`, `ionic_stop_queues()`, `ionic_open()`, `ionic_stop()`, `ionic_lif_handle_fw_down()`, and `ionic_lif_handle_fw_up()`. `ionic_netdev_ops` binds the implementation to Linux netdev callbacks.

Control flow: Probe sizing starts with `ionic_lif_size()`, which reads firmware queue/interrupt capacity, reserves timestamp queues when supported, and allocates IRQ vectors while falling back to fewer notify, event, or Tx/Rx queues. `ionic_lif_alloc()` allocates the netdev, LIF identity, DMA LIF info block, affinity masks, admin/notify QCQs, Tx/Rx QCQ arrays, RSS table, PHC state, locks, work items, and debugfs nodes. `ionic_lif_init()` issues a LIF devcmd, maps the kernel doorbell page, initializes adminq and notifyq, negotiates netdev features, initializes RX filters, programs the station MAC, and marks `IONIC_LIF_F_INITED`. `ionic_lif_register()` registers PHC, netdevice notifier, and netdev, then requests an initial link check.

Queue flow: `ionic_open()` allocates Tx/Rx QCQs, initializes firmware queues, sets real netdev queue counts, starts queues only if carrier is already up, and recreates timestamp queues if needed. Tx/Rx queue allocation builds DMA rings, CQ rings, SG rings, optional CMB rings, page pools for RX, NAPI structs, debugfs mappings, IRQs, and coalescing defaults. Queue initialization sends `IONIC_CMD_Q_INIT`, stores firmware hardware queue IDs/types, sets doorbell values, and adds NAPI callbacks. Enabling fills RX rings, sends `IONIC_Q_ENABLE`, enables NAPI, unmasks interrupts, and wakes netdev Tx queues. Stop/deinit/free reverse these stages by disabling netdev Tx, masking interrupts, synchronizing IRQs, disabling NAPI, quiescing the LIF, unregistering XDP RXQ info, emptying rings, freeing page pools, DMA memory, CMB mappings, IRQs, and QCQ shells.

Event and deferred control flow: Adminq NAPI services notifyq events, admin completions, and special timestamp queues, then returns interrupt credits and optionally pokes doorbells for the workaround path. Notifyq link events enqueue or perform `ionic_link_status_check()`, which starts queues and carrier on link up or stops queues and carrier on link down. Notifyq reset events enqueue `IONIC_DW_TYPE_LIF_RESET`; the worker runs either firmware-down teardown or firmware-up restart. Deferred RX mode work syncs kernel UC/MC lists and firmware filters outside atomic netdev callbacks.

State and persistence behavior: `struct ionic_lif` is the durable per-netdev state: state bits, locks, QCQ pointers, firmware identity, coherent LIF info, RSS key/table, RX filter database, queue dimensions, coalescing settings, PHC pointer, XDP program, and doorbell state. `IONIC_LIF_F_INITED`, `IONIC_LIF_F_UP`, `IONIC_LIF_F_FW_RESET`, `IONIC_LIF_F_FW_STOPPING`, `IONIC_LIF_F_BROKEN`, split-interrupt and CMB flags gate lifecycle transitions. Coherent `lif->info` persists firmware status/statistics across queue lifetimes until LIF free. RSS key/indirection and VF attributes are replayed after firmware reset. XDP program pointers are installed with `READ_ONCE`/`WRITE_ONCE` and released with `bpf_prog_put()`.

Dependencies: The implementation depends on Linux netdevice, NAPI, IRQ affinity, PCI/MSI, DMA coherent allocation, page pool, XDP RXQ info, DIM interrupt moderation, rtnetlink-safe netdev callbacks, workqueues, timers, and debugfs. Internal dependencies include `ionic_dev.h` devcmd helpers, `ionic_txrx.h` datapath functions, `ionic_rx_filter.h`, `ionic_ethtool.h`, `ionic_bus.h`, `ionic_aux.h`, CMB helpers, heartbeat/watchdog logic, and the ABI in `ionic_if.h`.

Integration points: Netdev callbacks expose open/stop/xmit/BPF/XDP xmit/stats/rx mode/features/MAC/MTU/VLAN/VF/hwtstamp operations. Firmware integration uses devcmds for LIF/adminq init and adminq commands for queue control, features, filters, RSS, MTU, MAC, and timestamp mode. PTP integration uses special hardware timestamp Tx/Rx queues and filter steering. RDMA/auxbus integration unregisters during firmware down and re-registers after restart. Debugfs exposes LIF and QCQ state, and ethtool consumes queue/coalescing/RSS facilities.

Risks: Queue lifecycle ordering is delicate: IRQ/NAPI enablement, adminq availability, DMA ring ownership, and firmware queue state must stay synchronized on normal open/stop, reconfiguration, timeout recovery, and firmware reset. `ionic_reconfigure_queues()` swaps live queue resources and can leak or miswire interrupts if unwind paths diverge. CMB reconfiguration frees before reallocating because device memory is scarce, raising restore risk. Link and reset work crosses atomic/worker contexts and must respect state bits. XDP is incompatible with split interrupts and constrained by MTU/frags. Firmware command failures during stop/restart can leave queues disabled or the LIF marked broken. VF replay intentionally ignores many return values, so failed replay may only show indirectly.

Test signals: Exercise probe/remove, `ip link set up/down`, carrier transitions, surprise firmware reset/down/up, Tx timeout recovery, queue count/descriptor/coalescing reconfiguration, split-interrupt toggling, CMB rings, RSS changes, VLAN filter add/delete, promiscuous/allmulti/filter overflow, MAC changes on PF/VF, SR-IOV VF set/get stats/config, XDP attach/detach with MTU limits and redirects, hardware timestamp queue creation, and kdump minimal queue sizing. Runtime signals include netdev carrier messages, debugfs QCQ entries, adminq errors, DIM coalescing changes, IRQ affinity masks, and `rtnl_link_stats64` counters.
