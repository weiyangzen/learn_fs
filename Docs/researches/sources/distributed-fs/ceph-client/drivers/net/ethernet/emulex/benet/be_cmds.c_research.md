# sources/distributed-fs/ceph-client/drivers/net/ethernet/emulex/benet/be_cmds.c

Purpose: implements the Emulex/Broadcom BladeEngine `benet` firmware command layer. It is the driver's control-plane bridge between Linux netdev/ethtool/probe code and adapter firmware, using mailbox WRBs before MCC queues exist and synchronous or asynchronous MCC WRBs afterward. It creates and destroys hardware queues, configures interfaces, MACs, VLANs, RSS, flow control, link state, SR-IOV resources, VXLAN offload, WOL, diagnostics, firmware logging, dump handling, and firmware download for BE2/BE3/Skyhawk/Lancer generations.

Important APIs/types/functions: command transport helpers include `embedded_payload`, `be_mcc_notify`, `be_mcc_compl_is_new`, `be_mcc_compl_process`, `be_mcc_event_process`, `be_process_mcc`, `be_mcc_notify_wait`, `be_mbox_notify_wait`, `be_wrb_cmd_hdr_prepare`, `be_cmd_notify_wait`, `wrb_from_mbox`, and `wrb_from_mccq`. Initialization and readiness APIs are `be_cmd_fw_init`, `be_cmd_fw_clean`, `be_POST_stage_get`, and `be_fw_wait_ready`. Queue and interface APIs include `be_cmd_eq_create`, `be_cmd_cq_create`, `be_cmd_mccq_create`, `be_cmd_txq_create`, `be_cmd_rxq_create`, `be_cmd_q_destroy`, `be_cmd_rxq_destroy`, `be_cmd_if_create`, and `be_cmd_if_destroy`. Network configuration APIs include `be_cmd_mac_addr_query`, `be_cmd_pmac_add`, `be_cmd_pmac_del`, `be_cmd_get_mac_from_list`, `be_cmd_set_mac_list`, `be_cmd_set_mac`, `be_cmd_vlan_config`, `be_cmd_rx_filter`, `be_cmd_rss_config`, `be_cmd_set_flow_control`, `be_cmd_get_flow_control`, `be_cmd_link_status_query`, `be_cmd_set_logical_link_config`, and `be_cmd_set_vxlan_port`. Diagnostics and management include `be_cmd_get_stats`, `lancer_cmd_get_pport_stats`, `be_cmd_get_fat_dump_len`, `be_cmd_get_fat_dump`, `lancer_initiate_dump`, `lancer_delete_dump`, `dump_present`, `be_cmd_loopback_test`, `be_cmd_ddr_dma_test`, `be_cmd_get_seeprom_data`, `be_cmd_read_port_transceiver_data`, `be_cmd_query_sfp_info`, `be_cmd_query_cable_type`, `be_cmd_get_phy_info`, `be_cmd_get_fw_log_level`, and `be_cmd_set_fw_log_level`. Firmware and resource/profile paths include `be_fw_download`, `lancer_fw_download`, `be_cmd_get_func_config`, `be_cmd_get_profile_config`, `be_cmd_set_sriov_config`, `be_cmd_config_qos`, `be_cmd_get_fn_privileges`, `be_cmd_set_fn_privileges`, `be_cmd_get_active_profile`, `be_cmd_enable_vf`, and exported `be_roce_mcc_cmd`.

Control flow: early probe uses mailbox commands guarded by `mbox_lock`: firmware init/clean, POST readiness, EQ/CQ/MCCQ creation, firmware config, function config, active profile, interrupt enable, and function reset. Once the MCC queue is created, most runtime commands allocate a WRB with `wrb_from_mccq`, fill an embedded or non-embedded payload, ring `DB_MCCQ_OFFSET`, and either wait synchronously through `be_mcc_wait_compl` or return after posting an asynchronous request. Completion processing pulls MCC CQ entries, dispatches async events by event code, processes command completions, decrements queue usage, and rearms the CQ. Async event handlers update cached link speed, link status, QoS speed, VLAN priority, PVID, OS-to-BMC filtering, QnQ VID, and SFP/port-misconfiguration state. Flashing flows parse UFI sections, check current flash CRCs, skip matching regions, stream 32 KiB chunks, and handle chip-specific fallback paths for older firmware or offset-based flashing. Lancer uses firmware objects (`/prg`, `/dbg/dump.bin`, VPD files) rather than legacy flashrom/FAT commands.

State and persistence behavior: runtime state is primarily in `struct be_adapter`: MCC queue occupancy, CQ rearm policy, cached firmware versions, function mode/caps, port/HBA/PF/VF numbers, physical link/PHY info, RSS tables and hash key, WOL capability/enabled state, privilege masks, port name, SFP state, cached statistics, error-recovery timers, and resource limits. The code updates hardware/firmware state persistently for flash images, NCSI/PHY/option ROM sections, WOL settings, function privileges, profile/SR-IOV resources, VF enablement, logical link state, HSW/VEPA/VEB configuration, QoS, VXLAN port config, firmware log level, and MAC lists. Many operations use DMA-coherent command buffers whose contents are firmware ABI data and require explicit endian conversion. Error state is persisted in adapter flags via `be_set_error`, `be_detect_error`, and UE recovery feature negotiation.

Dependencies and integration points: depends on `be.h`, `be_cmds.h`, `be_hw.h` register definitions, Linux PCI/MMIO/DMA APIs, completions, spinlocks, mutexes, netdev carrier/link helpers, firmware loading, and ethtool callers in `be_ethtool.c`. It integrates with probe/open/close queue setup, NAPI interrupt servicing through MCC completions, multicast/VLAN filter programming from netdev state, SR-IOV VF management, RoCE via exported `be_roce_mcc_cmd`, hwmon die temperature polling, ethtool flash/dump/self-test/WOL operations, and Lancer physical-device reset/dump control.

Risks: this file is high risk because it encodes firmware ABI layout, command sequencing, timeout behavior, DMA addresses, and endian conversion. Incorrect WRB tags can cause completions to write through stale pointers; wrong embedded/non-embedded selection or command size can corrupt firmware command buffers; and queue accounting mistakes can stall the MCC ring. Several paths hold `mcc_lock` while building commands and then drop it before waiting on completions, so timeout and completion ordering must remain consistent with `adapter->et_cmd_compl` and `adapter->flash_status`. Flashing code can leave adapters partially updated, and the Skyhawk fallback explicitly returns `-EAGAIN` when a reboot is required to finish. Resource descriptor parsing trusts firmware-provided descriptor lengths with only defaulting for zero length, so malformed descriptor lists can misdirect SR-IOV or QoS configuration. Privilege gating is command-specific; missing an opcode in `cmd_priv_map` can expose operations to insufficiently privileged functions. Some functions return raw MCC status while callers expect Linux errno via `be_cmd_status`.

Test signals: probe should progress through POST, mailbox init, EQ/CQ/MCCQ creation, firmware config query, and interface creation on BE2, BE3, Skyhawk, and Lancer. Runtime signals include successful RX/TX traffic, link up/down async events, `ethtool -S` stats updates, RSS indirection/hash changes, VLAN and multicast filtering, pause control, WOL programming, `ethtool -p` beacon toggling, and SR-IOV VF creation/configuration. Diagnostic tests should cover firmware dump length/read/delete/initiate, self-tests for loopback and DDR DMA, SFP EEPROM reads, firmware log-level changes, privilege-denied VF commands, MCC timeout injection, flash CRC skip behavior, signature errors, and Lancer firmware-object download/reset behavior.
