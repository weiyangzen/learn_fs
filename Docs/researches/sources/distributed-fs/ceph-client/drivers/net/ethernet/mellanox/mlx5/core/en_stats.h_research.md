# sources/distributed-fs/ceph-client/drivers/net/ethernet/mellanox/mlx5/core/en_stats.h

Purpose: defines the mlx5e statistics ABI used internally by the Ethernet driver. It provides counter descriptor/read macros, the stats-group callback interface, public stats function prototypes, concrete software and hardware stats structures, accessors for firmware register layouts, representor stats copying, and extern declarations for stats groups implemented in `en_stats.c` and optional acceleration modules.

Important APIs/types/functions: `struct counter_desc` maps an ethtool string format to a byte offset. `struct mlx5e_stats_grp` defines the group operations `get_num_stats`, `fill_strings`, `fill_stats`, `update_stats`, and an `update_stats_mask`. `mlx5e_stats_grp_t` is the group pointer type. Macros `MLX5E_DECLARE_STAT`, `MLX5E_DECLARE_RX_STAT`, `MLX5E_DECLARE_TX_STAT`, `MLX5E_DECLARE_XDPSQ_STAT`, `MLX5E_DECLARE_RQ_XDPSQ_STAT`, `MLX5E_DECLARE_XSKRQ_STAT`, `MLX5E_DECLARE_XSKSQ_STAT`, `MLX5E_DECLARE_CH_STAT`, `MLX5E_DECLARE_PTP_*`, and `MLX5E_DECLARE_QOS_TX_STAT` build descriptor entries. `MLX5E_DECLARE_STATS_GRP_OP_*` and `MLX5E_DEFINE_STATS_GRP` enforce group naming conventions. Public prototypes cover generic ethtool stats update/fill plus pause, FEC, Ethernet PHY/MAC/control, RMON, timestamp, and link extended stats.

Important structures: `struct mlx5e_sw_stats` is the aggregate software counter block for RX/TX, LRO/GRO/HDS, checksum, XDP, queue events, page_pool, TLS, AF_XDP, and channel events. `struct mlx5e_rq_stats`, `struct mlx5e_sq_stats`, `struct mlx5e_xdpsq_stats`, `struct mlx5e_ch_stats`, and `struct mlx5e_ptp_cq_stats` are per-queue/channel data-path counter layouts consumed by `en_stats.c` and updated elsewhere. Hardware/raw query containers are `struct mlx5e_qcounter_stats`, `struct mlx5e_vnic_env_stats`, `struct mlx5e_vport_stats`, `struct mlx5e_pport_stats`, and `struct mlx5e_pcie_stats`. `struct mlx5e_rep_stats` stores representor/vport counters, and top-level `struct mlx5e_stats` groups all persistent sampled stats under `priv->stats`.

Control flow: this header has no runtime control flow, but it shapes `en_stats.c` heavily. Descriptor macros combine string names and `offsetof()` so fill functions can iterate descriptor arrays and read the matching field from a stats structure. Register access macros wrap `MLX5_GET64`/byte offsets for PPCNT, VPORT, VNIC, and MPCNT layouts. `MLX5E_DEFINE_STATS_GRP` creates a `const struct mlx5e_stats_grp` whose function pointers point to the conventional generated names for a group. `mlx5e_stats_copy_rep_stats()` converts stored representor stats into `rtnl_link_stats64` fields for VF/vport reporting.

State and persistence: the header defines in-memory state layouts only. Counter fields are plain integer accumulators or raw firmware output buffers and persist for the lifetime of the owning `mlx5e_priv`, channel, queue, or representor object. Several fields are conditional on `CONFIG_MLX5_EN_ARFS` and `CONFIG_MLX5_EN_TLS`, so binary layout varies with kernel configuration. Cacheline alignment markers in SQ/XDPSQ stats separate completion-dirtied counters from transmit fast-path counters. No on-disk persistence is represented.

Dependencies and integration: depends on kernel networking types such as `ETH_GSTRING_LEN`, `rtnl_link_stats64`, and ethtool stats structs, mlx5 firmware layout macros and constants, and data-path structures declared elsewhere through `struct mlx5e_priv`. It integrates with `en_stats.c`, ethtool ops, representor/vport reporting, RX/TX/XDP/TLS/PTP data paths that update the counter fields, and optional stats groups from IPsec, MACsec, and PCIe congestion modules.

Risks: descriptor offsets are type-dependent; changing a counter structure without updating matching descriptor arrays in `en_stats.c` can silently expose wrong values. Conditional fields under ARFS/TLS must match conditional descriptors and aggregation code exactly across compile configurations. Plain 64-bit counters are updated by data paths and read by aggregation without a universal locking primitive in this header, so consumers must tolerate approximate snapshots. Raw firmware buffers are declared as `__be64` arrays but accessed via generated offsets for 32-bit and 64-bit fields; incorrect offset macros would yield endian or alignment errors. The group macro convention is rigid and can hide missing functions until compile time.

Test signals: compile with ARFS and TLS both enabled and disabled, and with optional acceleration groups enabled, to verify structure layouts and extern group declarations match implementations. Run ethtool stats on devices with different capabilities to validate descriptor offsets and names. Exercise representor stats copy into `rtnl_link_stats64`. Use build warnings/static analysis to catch wrong `offsetof()` target types, missing group op symbols, and raw register accessor type mismatches.
