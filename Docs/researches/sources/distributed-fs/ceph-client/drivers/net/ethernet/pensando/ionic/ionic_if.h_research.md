# sources/distributed-fs/ceph-client/drivers/net/ethernet/pensando/ionic/ionic_if.h

Purpose: This header is the firmware and hardware ABI for the Ionic network device. It defines the command opcodes, status codes, queue descriptor formats, identity/configuration blocks, notification events, statistics layouts, and BAR register structures shared by the Ethernet driver, RDMA support, firmware update path, and low-level device helpers.

Important APIs/types: `enum ionic_cmd_opcode` is the central command namespace for device, port, LIF, queue, VF, CMB, QoS, RDMA, and firmware commands. `enum ionic_status_code` is translated by `ionic_error_to_errno()` in `ionic_main.c`. `struct ionic_admin_cmd` and `struct ionic_admin_comp` are the generic admin queue wire format, with `color_match()` checking CQ ownership. Identity/configuration contracts include `union ionic_drv_identity`, `union ionic_dev_identity`, `union ionic_lif_identity`, `union ionic_lif_config`, `union ionic_port_identity`, `union ionic_q_identity`, `union ionic_discover_cmb_identity`, and the deprecated aggregate `struct ionic_identity`. Queue formats include `struct ionic_q_init_cmd`, `struct ionic_q_init_comp`, Tx/Rx descriptors, SG descriptors, and completions. `encode_txq_desc_cmd()` and `decode_txq_desc_cmd()` pack and unpack Tx descriptor opcode, flags, SG count, and 52-bit DMA address fields. `union ionic_dev_cmd`, `union ionic_dev_cmd_comp`, `union ionic_adminq_cmd`, and `union ionic_adminq_comp` provide typed views over fixed-size MMIO/admin ring command slots. Hardware register maps include `union ionic_dev_info_regs`, `union ionic_dev_cmd_regs`, `union ionic_dev_regs`, `struct ionic_hwstamp_regs`, `struct ionic_doorbell`, and `struct ionic_intr_status`.

Control flow: The file itself has no runtime control flow beyond inline bit packing and `color_match()`. Its declarations drive the runtime flows in `ionic_main.c` and `ionic_lif.c`: driver identify writes `union ionic_drv_identity` into devcmd side data, firmware returns `union ionic_dev_identity`, LIF init passes a DMA address for `struct ionic_lif_info`, queue init supplies ring bases and features, and admin completions return typed command results. Notify queue events use `union ionic_notifyq_comp` so `ionic_notifyq_service()` can switch on event code and enqueue link or reset work.

State and persistence behavior: Most structures describe firmware-owned or DMA-shared state rather than persistent kernel state. `struct ionic_lif_info` and `struct ionic_port_info` are coherent DMA memory populated by firmware and later read by the driver for link status, configuration, and statistics. Identity unions are snapshots captured during probe or reset recovery. Descriptor rings and completions are persistent while queues are initialized and are interpreted with color bits and ring indices. Firmware status, heartbeat, serial, firmware version, and current timestamp are exposed via BAR0 device info registers.

Dependencies: The header assumes Linux bit macros, endian types, DMA-address conventions, and IO register access performed by callers. It is included by Ionic device, queue, LIF, Tx/Rx, ethtool, PHC, firmware, and RDMA support. It is the bridge between Linux netdev/PTP concepts and the device firmware contract.

Integration points: Netdev offload negotiation maps `enum ionic_eth_hw_features` to `NETIF_F_*` flags. Hardware timestamping uses `enum ionic_txstamp_mode`, `enum ionic_pkt_class`, `struct ionic_lif_setphc_cmd`, and `struct ionic_hwstamp_regs`. SR-IOV netdev ops use `struct ionic_vf_setattr_cmd` and related VF enums. RSS uses `IONIC_RSS_HASH_KEY_SIZE`, `enum ionic_rss_hash_types`, and the RSS payload in `struct ionic_lif_setattr_cmd`. RDMA consumes LIF/RDMA identity, RDMA reset/create queue commands, and doorbell/CMB layout.

Risks: ABI drift is the primary risk: structure sizes, packing, endian annotations, bit assignments, queue feature versions, and BAR offsets must remain synchronized with firmware. Descriptor bitfield mistakes can corrupt DMA addresses or offload flags. The 52-bit address mask and packed unions require care on new hardware. Feature bits are shared across netdev, timestamping, CMB, and RDMA paths, so adding a bit without updating all consumers can silently disable or misconfigure capabilities.

Test signals: Compile-time coverage should catch missing enum/field consumers, but ABI correctness needs probe tests against supported firmware, queue bring-up, Tx/Rx traffic with checksum/TSO/VLAN/RSS, link event handling, SR-IOV VF configuration, CMB discovery, firmware update commands, and PTP hardware timestamp tests. Dynamic debug dumps in admin/dev command paths help verify exact command bytes and completions.
