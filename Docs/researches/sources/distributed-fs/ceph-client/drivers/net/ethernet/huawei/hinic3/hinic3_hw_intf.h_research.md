# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hw_intf.h

This header defines the common/config firmware ABI used over mailbox and command queues. It provides `mgmt_msg_head`, `mgmt_msg_params`, the default initializer, management module IDs, configuration command IDs and `cfg_cmd_dev_cap`, common command IDs, reset bits, feature negotiation payloads, global attributes, service-used state, DMA attributes, CEQ control payload, page-size/root/cmdq context commands, clear-resource/time/BDF/version commands, and the supported-service enum. Control flow is external: command wrappers fill these structs, send them to firmware, then inspect `head.status`. State modeled here is wire-format state rather than local driver ownership; fields must match firmware layout and endian expectations. Dependencies are Linux fixed-width types and bit macros. Integration points span `hinic3_hw_cfg.c`, `hinic3_hw_comm.c`, `hinic3_eqs.c`, `hinic3_hwdev.c`, and `hinic3_mbox.c`. Risks are ABI drift, structure padding/layout changes, command ID mismatch, and using `mgmt_msg_params_init_default` when input and output sizes differ. Test signals include firmware capability retrieval, common feature negotiation, CEQ control setup, firmware version reads, and reset/flush behavior.
