# sources/distributed-fs/ceph-client/drivers/net/ethernet/emulex/benet/be_ethtool.c

Purpose: implements the `ethtool_ops` front end for the `benet` network driver. It exposes driver/firmware identity, statistics, coalescing, link settings, ring sizing, pause control, physical port identify, firmware dump operations, WOL, offline diagnostics, firmware flashing, EEPROM/VPD/module EEPROM reads, message level, RSS hash/indirection controls, channel counts, and private flags.

Important APIs/types/functions: `struct be_ethtool_stat` plus `et_stats`, `et_rx_stats`, and `et_tx_stats` define exported counter names and offsets into driver stats. `be_get_drvinfo`, `be_get_ethtool_stats`, `be_get_stat_strings`, and `be_get_sset_count` implement identity and string/stat reporting. Coalescing uses `be_get_coalesce` and `be_set_coalesce`. Link and media reporting uses `be_get_link_ksettings`, `be_get_port_type`, `convert_to_et_setting`, and `be_pause_supported`. WOL and pause paths are `be_get_wol`, `be_set_wol`, `be_get_pauseparam`, and `be_set_pauseparam`. Diagnostics include `be_self_test`, `be_loopback_test`, `be_test_ddr_dma`, `be_set_phys_id`, `be_set_dump`, `be_get_dump_flag`, and `be_get_dump_data`. Firmware/NVM paths include `be_do_flash`, `be_get_eeprom_len`, `be_read_eeprom`, `be_get_module_info`, and `be_get_module_eeprom`. RSS/channel controls are `be_get_rxfh_fields`, `be_set_rxfh_fields`, `be_get_rxfh`, `be_set_rxfh`, `be_get_channels`, and `be_set_channels`. The exported table is `const struct ethtool_ops be_ethtool_ops`.

Control flow: ethtool invokes a table method, the method reads cached adapter state when possible, and calls `be_cmds.c` firmware commands when hardware state must be queried or changed. Link settings lazily refresh `adapter->phy.link_speed` and PHY capabilities when the cached speed is invalid, then convert BE speed/interface bits into legacy ethtool link-mode masks. Coalescing updates per-EQ AIC settings and, on Skyhawk with adaptive coalescing disabled, forces an EQD firmware update. Stats are copied by offset from global driver stats and per-queue stats, using `u64_stats_fetch_begin/retry` for 64-bit queue counters. Offline tests enable loopback modes, run firmware loopback commands, disable loopback, run DDR DMA tests except on Lancer, and poll link recovery. RSS control validates requested hash fields and Toeplitz settings, maps ethtool indirection entries to firmware RSS IDs, then calls `be_cmd_rss_config`. Channel changes validate combined/RX/TX constraints, store requested IRQ counts, and call `be_update_queues`.

State and persistence behavior: most ethtool methods are views over runtime `adapter` state: `msg_enable`, `priv_flags`, `aic_enabled`, queue counts, RSS tables/hash key/flags, link cache, flow-control cache, WOL enablement, and firmware dump length. Some operations persist settings into adapter firmware or PCI power state: WOL magic MAC and PCI wake settings, pause control, firmware log level, RSS hash configuration, channel-driven queue reconfiguration, firmware image flashing, Lancer dump creation/deletion, and beacon state toggling during physical identification. Private flag `disable-tpe-recovery` only updates driver runtime policy and logs the resulting recovery state.

Dependencies and integration points: depends on `be.h`, `be_cmds.h`, Linux ethtool APIs, PCI wake APIs, DMA allocation, netdev carrier state, queue update helpers, RSS constants, and firmware command wrappers. It integrates with user-space `ethtool`, module EEPROM/SFP readers, firmware flashing tools, dump collection workflows, SR-IOV/privilege policy through `check_privilege`, and hardware diagnostics. Several features require privileged PF-level command rights and return `-EOPNOTSUPP` for VFs or restricted functions.

Risks: ethtool is user-facing, so raw firmware statuses must be consistently mapped with `be_cmd_status`; missed mappings can expose confusing errors. EEPROM and module reads must respect offsets and lengths; the page A0/A2 split in `be_get_module_eeprom` is sensitive to pointer advancement and range calculations. RSS setters update cached indirection entries before the firmware command completes, so failed commands must leave cache in a coherent state; this file resets only `rss_flags` on one failure path. Channel changes can reconfigure queues and IRQs, creating risk if requested counts exceed firmware resource descriptors. Offline tests alter loopback state and depend on completion signaling from async MCC commands; timeout or failure paths must restore normal loopback. WOL persists PCI wake state and firmware magic MAC, so incorrect capability detection can break suspend/resume behavior. Stats arrays depend on struct offsets and assumed first fields in per-queue stats.

Test signals: `ethtool -i`, `-S`, `-c/-C`, `-k`-adjacent RSS commands, `-x/-X`, `-l/-L`, `-a/-A`, `-p`, `-s`-style link queries through netlink, `--test`, `--flash`, `--get-dump/--set-dump`, `-e`, `-m`, and `-s wol g` should exercise this surface. Verify stats string count equals data count across queue-count changes, 64-bit counters do not tear under traffic, link settings cache refreshes after async link events, pause setting denies autoneg changes, RSS rejects unsupported UDP L4 hashing on BEx, channel changes survive traffic restart, restricted VFs cannot read privileged dump/module data, and WOL persists across suspend/resume on capable devices.
