# sources/distributed-fs/ceph-client/drivers/net/ethernet/microchip/vcap/vcap_model_kunit.c

## Purpose
`vcap_model_kunit.c` is an autogenerated static VCAP hardware model used by Microchip VCAP KUnit tests. It describes the layout of IS0, IS2, and ES2 VCAP blocks: key fields, action fields, keyset/actionset metadata, typegroup encodings, and printable enum names. It does not execute packet or rule logic; it gives the VCAP API test code a deterministic model that mimics hardware table geometry and field packing.

## Important APIs, Types, and Data
- Includes `vcap_api.h` and exports data declared by `vcap_model_kunit.h`.
- Uses `struct vcap_field`, `struct vcap_set`, `struct vcap_typegroup`, `struct vcap_info`, and `struct vcap_statistics`.
- Keyfield arrays cover IS0 (`LL_FULL`, normal and pure tuple formats, ETAG), IS2 (`MAC_ETYPE`, `ARP`, IPv4/IPv6 tuple formats), and ES2 (MAC/ARP/IP tuple and VID-oriented formats).
- Actionfield arrays include IS0 classification/full/reduced actions plus base-type actions for IS2 and ES2.
- Set arrays describe type IDs and slice usage with `sw_per_item` and `sw_cnt`; map arrays connect enum keysets/actionsets to field arrays and companion size arrays use `ARRAY_SIZE()`.
- Typegroup arrays define fixed type bits for slice widths such as x12, x6, x3, x2, and x1.
- Exported globals are `kunit_test_vcaps[]` and `kunit_test_vcap_stats`.

## Control Flow
There is no runtime control flow beyond constant initialization. Consumers index `kunit_test_vcaps[VCAP_TYPE_*]` to discover rows, widths, sticky/action widths, supported fieldsets, typegroups, and name tables. The VCAP API then uses those structures to encode, decode, validate, and display synthetic test rules.

## State and Persistence
All state is compile-time constant data in the kernel image or test object. The file has no mutable static state, no allocations, no locks, and no persistent storage. Correctness depends on the generated tables staying synchronized with the enum values and struct contracts in the VCAP API headers.

## Dependencies and Integration Points
- Depends on Linux `types.h` and `kernel.h` for basic types and `ARRAY_SIZE`.
- Integrates with Microchip VCAP API tests through `vcap_api.h`.
- The companion header exposes only the two top-level model symbols, keeping the large generated tables private.
- The test model supports TC and rule-building code indirectly because KUnit can validate VCAP packing against the same key/action field names used by production clients.

## Risks and Edge Cases
- Generated designated initializers are tightly coupled to enum numeric values. Enum insertions, deletions, or reordering in `vcap_api.h` can silently invalidate maps if the model is not regenerated.
- `type_id = -1` is used for some fieldsets/actionsets; consumers must treat this as a valid sentinel for formats without a concrete type ID.
- Sparse arrays rely on absent entries being zero/NULL. Tests should catch accidental lookups of unsupported keysets.
- The model encodes bit offsets and widths by generated constants; stale hardware definitions change rule packing without compiler errors.

## Test Signals
- KUnit tests that instantiate `kunit_test_vcaps` should verify supported keyset/actionset lookup, field bounds, typegroup selection by slice count, and name table coverage.
- Useful regression signals include failed VCAP encode/decode tests, unexpected NULL fieldset maps, mismatched field widths, and array-index warnings from new enum values.
