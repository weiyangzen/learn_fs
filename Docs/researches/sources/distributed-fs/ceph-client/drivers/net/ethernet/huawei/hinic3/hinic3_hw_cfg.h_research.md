# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hw_cfg.h

This header defines configuration-management state shared across the driver. Important types are `struct hinic3_irq`, `hinic3_irq_info`, `hinic3_nic_service_cap`, `hinic3_dev_cap`, and `hinic3_cfg_mgmt_info`. It exports lifecycle and query functions for configuration management, IRQ allocation/free, capability initialization, NIC service support, max queue count, and physical port ID. State represented here is persistent for the lifetime of `hinic3_hwdev`: MSI-X vector inventory, device service capability bitmap, physical port, COS maps, max VF count, and NIC queue limits. Dependencies include Linux mutex and PCI types, while implementation depends on `hinic3_hw_cfg.c` and firmware command structs. Integration points are hardware-device initialization, EQ/queue IRQ setup, auxiliary device attachment, NIC probe max queue sizing, and port/link commands. Risks center on ownership: callers must pair allocated IRQs with `hinic3_free_irq`, and capability values must be initialized before NIC service probing. Test signals include IRQ exhaustion, auxiliary NIC suppression when the service bitmap lacks NIC, and stable `hinic3_func_max_qnum` results.
