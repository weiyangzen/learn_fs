# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hwdev.c

This file orchestrates the hardware-device lifecycle after PCI BARs are mapped. Initialization allocates `hinic3_hwdev`, initializes hwif, workqueue, config management, AEQs, mailbox, PF-to-management channel, common attributes, CEQs, cmdqs, capability discovery, PPF time-sync work, and common feature publication. It registers AEQ callbacks for mailbox and firmware messages and CEQ callback for cmdq completions. Teardown reverses the sequence: clear features, stop PPF work, flush RX/TX, uninit comm channels, free config management, destroy workqueue, free hwif, release device ID, and free memory. State includes `func_state` bits for mgmt/mbox/cmdq, `chip_present_flag`, common feature qwords, WQ page size, max cmdq count, AEQ/CEQ/mbox/cmdq/pf_to_mgmt pointers, and delayed time-sync work. Dependencies include hwif, cfg, eqs, mailbox, mgmt, cmdq, and common firmware wrappers. Risks are teardown ordering across asynchronous work/interrupts, missing `chip_present_flag` wakeups, partial init rollback, and PPF-only delayed work. Test signals are PCI probe/remove, shutdown setting API stop, function reset, feature negotiation, and absence of stalled mailbox/cmdq waiters during removal.
