# sources/distributed-fs/ceph-client/drivers/net/ethernet/aquantia/atlantic/hw_atl/hw_atl_llh_internal.h

Purpose: Provides the internal Atlantic register map used by `hw_atl_llh.c`. It defines MMIO addresses, bit masks, inverse masks, shifts, widths, defaults, and indexed address macros for hardware blocks in the Atlantic NIC.

Important APIs, types, and functions: This header is macro-only. Important families include temperature sensor registers (`HW_ATL_TS_*`), SMBus registers (`HW_ATL_SMB0_*`), global CPU semaphores and scratchpads (`HW_ATL_GLB_CPU_SEM_ADR`, `HW_ATL_GLB_CPU_SCRATCH_SCP_ADR`), DMA statistic counters, interrupt mask/status/map/throttle registers, RX descriptor manager fields, RX/TX DMA descriptor base/tail/status macros, RX packet buffer thresholds and flow-control fields, L2 multicast/unicast/broadcast filters, VLAN filters, ethertype filters, L3/L4 address and port filter registers, RX checksum/offload/LRO fields, TX descriptor manager/DCA/LSO fields, TX packet buffer and TX offload fields, TX packet scheduler/rate/traffic-class fields, MSM indirect MAC/PHY access registers, PCS PTP timestamp registers, global/reset/PCI reset-disable bits, MDIO operation fields, and firmware semaphore IDs (`HW_ATL_FW_SM_*`).

Control flow: There is no runtime flow. Macros are expanded by LLH accessors and utility code to produce MMIO operations. Parameterized address macros encode hardware strides and valid conceptual ranges, for example descriptors and queues `[0, 31]`, traffic classes `[0, 7]`, VLAN filters `[0, 15]`, L2 unicast filters `[0, 37]`, L3/L4 locations `[0, 7]`, and MDIO interfaces starting at one.

State and persistence behavior: The file describes hardware state but stores none. Defaults document reset expectations for many fields, while actual persistence is on the device across normal writes until a hardware reset or power state transition. Reset-disable and soft-reset fields in this header are especially important because they determine whether other register blocks retain state across reset sequences.

Dependencies and integration points: It is private to the Atlantic hardware abstraction layer and is included by `hw_atl_llh.c` and `hw_atl_utils.c`. The definitions are coupled to `aq_hw_utils` bitfield helper semantics: every `_MSK` and `_SHIFT` pair must match the helper's extraction/write convention. Higher-level modules indirectly depend on this register map through `hw_atl_llh.h` accessors, while diagnostics and firmware reset flows use a few macros directly.

Risks: This is a high-blast-radius generated register contract. Any typo in address, mask, inverted mask, shift, width, default, stride, or range comment can cause hard-to-debug hardware failures. Some duplicate or alias definitions exist for TX DCA/descriptor fields, which must stay semantically consistent. Several full-width masks have inverse masks of zero or, for source/destination address macros, comments that are not used by current helpers; future users should not infer write safety from comments alone. Range comments are not enforced by C macros. Register names with `DEFALT` typos and mixed uppercase/lowercase are harmless for current use but signal that automated generation artifacts should be handled carefully.

Test signals: Hardware register dump validation is the strongest signal: compare expected addresses and bitfields against vendor datasheets or known-good programming traces. Driver-level signals include successful initialization of descriptors, filters, offloads, interrupts, reset, PTP, MDIO, and firmware mailbox paths. Static checks can find duplicate macros, unused metadata, and inconsistent alias values. Any port to new silicon should verify all revision-sensitive definitions before reusing this map.
