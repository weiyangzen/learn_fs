# Research: sources/distributed-fs/ceph-client/drivers/net/ethernet/microchip/sparx5/sparx5_vcap_ag_api.h

## Purpose
`sparx5_vcap_ag_api.h` is the small exported header for the autogenerated Sparx5 VCAP model. It declares the Sparx5-specific `vcap_info` table and statistics object that are defined in `sparx5_vcap_ag_api.c` and selected by the Sparx5 driver constants.

## Important APIs, Types, and Functions
- Include guard `__SPARX5_VCAP_AG_API_H__`.
- Includes `vcap_api.h` for the model structures.
- Declares `extern const struct vcap_info sparx5_vcaps[]`.
- Declares `extern const struct vcap_statistics sparx5_vcap_stats`.

## Control Flow
The header has no runtime control flow. Its declarations allow Sparx5 platform data and VCAP implementation code to reference the generated model at compile/link time.

## State and Persistence Behavior
It owns no state. The declared objects are immutable model data. The hardware rule state derived from that model is maintained by the VCAP API and Sparx5 hardware programming callbacks.

## Dependencies and Integration Points
The header is included by `sparx5_vcap_ag_api.c`, `sparx5_vcap_impl.c`, `sparx5_vcap_debugfs.c`, and likely Sparx5 platform constant definitions. It is Sparx5-specific, unlike `drivers/net/ethernet/microchip/vcap/vcap_ag_api.h`, which declares the shared enum namespace for the VCAP API.

## Risks and Edge Cases
- The file is generated and uses a BSD-3-Clause SPDX tag while implementation files are GPL-2.0+, so license metadata should be preserved during regeneration.
- Any rename of the exported symbols must be synchronized with Sparx5 constants and implementation code.
- It does not expose enum definitions itself; consumers must also include the common generated VCAP API header through `vcap_api.h` or related headers.

## Test Signals
- Compile Sparx5 with `CONFIG_VCAP=y` to ensure both externs resolve.
- Regeneration tests should verify that this header and its matching `.c` are produced together.
