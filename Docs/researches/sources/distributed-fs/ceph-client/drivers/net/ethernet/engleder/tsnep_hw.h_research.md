# sources/distributed-fs/ceph-client/drivers/net/ethernet/engleder/tsnep_hw.h

Purpose: this header is the TSNEP/EtherCAT MAC hardware contract. It defines register offsets, bit masks, queue address calculations, hardware limits, gate-control list encoding, descriptor layouts, descriptor ownership bits, timestamp/writeback formats, and RX inline metadata.

Important APIs, types, and data: ECM definitions cover type/revision/version/queue count/gate-control capability, system time registers, clock-rate adjustment, interrupt enable/active/acknowledge bits, reset bits, counters, interrupt delay encoding, link status/mode, MDIO control/status, and packed MAC statistics. TSNEP definitions cover MAC and per-queue register window sizes, `TSNEP_QUEUE(n)` address calculation, maximum queues, frame size, descriptor size/offset, queue control bits, descriptor base registers, RX statistics, MAC address/filter registers, gate control registers, GCL memory offsets, RX assignment registers, and EtherType filter slots. Hardware structures include `struct tsnep_gcl_operation`, `struct tsnep_tx_desc`, `struct tsnep_tx_desc_wb`, `struct tsnep_rx_desc`, `struct tsnep_rx_desc_wb`, and `struct tsnep_rx_inline`.

Control flow and integration: runtime code uses these constants to map hardware capabilities, reset common/channel/TX/RX blocks, program system time and clock rate, configure interrupts and interrupt delay, access MDIO, set MAC address and RX filters, program traffic-control gate lists, assign RX flows to queues, initialize TX/RX descriptor rings, and parse descriptor writebacks for counters, timestamps, DMA delay, and errors.

State and persistence: no software state is stored here, but the definitions describe hardware state that persists in MMIO registers and DMA descriptor memory. Descriptor ownership is encoded with owner-counter bits in properties; TX writeback can include a counter, timestamp, DMA delay, and underrun flag; RX inline metadata carries a counter and timestamp. Gate-control state persists in two hardware GCL banks with explicit active/change/open bits.

Dependencies and integration points: includes Linux integer types and is included by `tsnep.h`. It must match the hardware IP exactly and coordinate with `tsnep_main.c`, `tsnep_ptp.c`, `tsnep_tc.c`, `tsnep_rxnfc.c`, `tsnep_xdp.c`, and `tsnep_ethtool.c`. `TSNEP_MAC_SIZE`, `TSNEP_QUEUE_SIZE`, `TSNEP_MAX_QUEUES`, and descriptor constants are consumed by both register dump and ring-management code.

Risks: incorrect offsets or masks can cause silent hardware misprogramming. `TSNEP_DESC_SIZE` and `TSNEP_DESC_OFFSET` are defined twice with the same values; future edits must keep duplicates consistent or remove them carefully across all users. `TSNEP_MAX_FRAME_SIZE` is set to 2 KiB even though the comment says hardware supports 16 KiB, so MTU-related changes must account for driver policy versus hardware capacity. The statement-expression `TSNEP_QUEUE(n)` is GNU C specific and evaluates to queue 0 at offset 0 while later queues live after the MAC window; callers must pass a side-effect-safe queue index despite the local temporary. Descriptor ownership/counter bit handling is sensitive to endianness and wrap behavior.

Test signals: validate probe capability parsing from `ECM_TYPE`, MMIO register dumps sized by queue count, MDIO reads/writes, interrupt enable/ack/delay programming, link mode reporting, PTP clock read/rate adjustment, MAC address/filter programming, gate control/taprio list activation, RX assignment filters, TX/RX descriptor ring DMA under load, timestamp writebacks, RX inline metadata, and descriptor error bits such as TX underrun, TX/RX DMA error, and descriptor error.
