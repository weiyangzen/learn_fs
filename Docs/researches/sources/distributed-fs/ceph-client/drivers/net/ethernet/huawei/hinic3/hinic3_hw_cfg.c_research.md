# sources/distributed-fs/ceph-client/drivers/net/ethernet/huawei/hinic3/hinic3_hw_cfg.c

This file manages device capability discovery and MSI-X vector allocation. `hinic3_init_cfg_mgmt` allocates `cfg_mgmt`, initializes IRQ metadata from hardware attributes, calls `pci_alloc_irq_vectors`, and records each vector/entry as initially unallocated. `hinic3_init_capability` sends `CFG_CMD_GET_DEV_CAP`, parses public resource capability and L2 NIC queue limits, and stores them in `hwdev->cfg_mgmt->cap`. `hinic3_alloc_irqs` and `hinic3_free_irq` provide a mutex-protected vector allocator used by AEQ/CEQ and queue-pair IRQ setup. State includes the IRQ table, allocation bits, hardware/actual vector counts, service bitmap, physical port ID, max VF, COS bitmaps, and NIC service queue caps. Dependencies include PCI MSI-X APIs, hwif function attributes, management mailbox commands, and `hinic3_support_nic` for conditional L2 parsing. Risks are partial IRQ allocation semantics, vector shortage reducing queue counts, trusting firmware capability fields, and freeing vectors still bound to IRQ handlers. Test signals are probe with limited MSI-X vectors, queue count capping at 256, PF/VF capability differences, and remove-time `pci_free_irq_vectors`.
