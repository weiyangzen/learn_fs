# sources/distributed-fs/ceph-client/drivers/net/ethernet/pensando/ionic/ionic_phc.c

Purpose: This file implements Ionic PTP Hardware Clock and Linux hardware timestamp configuration support. It maps Linux hwtstamp requests to Ionic firmware capabilities, creates dedicated timestamp queues and RX steering filters, registers a PHC, reads hardware timestamp registers, maintains cyclecounter/timecounter state, and sends PHC synchronization commands to firmware.

Important APIs/functions: Netdev hwtstamp entry points are `ionic_hwstamp_set()` and `ionic_hwstamp_get()`. Reset/open replay helpers are `ionic_lif_hwstamp_replay()` and `ionic_lif_hwstamp_recreate_queues()`. PHC lifecycle functions are `ionic_lif_alloc_phc()`, `ionic_lif_register_phc()`, `ionic_lif_unregister_phc()`, and `ionic_lif_free_phc()`. PTP clock callbacks include `ionic_phc_adjfine()`, `ionic_phc_adjtime()`, `ionic_phc_settime64()`, `ionic_phc_gettimex64()`, and `ionic_phc_aux_work()`. `ionic_lif_phc_ktime()` converts raw hardware ticks from Tx/Rx completions to `ktime_t`.

Control flow: `ionic_hwstamp_set()` takes `lif->queue_lock`, then `ionic_lif_hwstamp_set_ts_config()` serializes timestamp configuration with `phc->config_lock`. TX modes are mapped from `HWTSTAMP_TX_*` to `IONIC_TXSTAMP_*` and checked against firmware capability bits. RX filters are mapped from `HWTSTAMP_FILTER_*` to Ionic packet-class masks; unsupported specific filters fall back to `HWTSTAMP_FILTER_ALL` and RX-all queue feature reconfiguration. Enabling TX or specific RX timestamping creates special hardware timestamp queues through LIF helpers, sets firmware TX timestamp mode, installs RX steering filters, and stores the requested config for later get/replay. On partial failure it reverts changed RX filter and TX mode but leaves special queues allocated.

PHC flow: `ionic_lif_alloc_phc()` validates hardware timestamp registers and feature bits, allocates `struct ionic_phc`, initializes a `cyclecounter` from firmware mask/mult/shift, optionally scales multiplier/shift for finer adjustment headroom, initializes the `timecounter` to current real time, computes an auxiliary worker delay near one quarter of wrap period, and copies `ionic_ptp_info`. Registration calls `ptp_clock_register()` and schedules auxiliary work. PTP adjustments reject firmware reset state, update the local timecounter under `phc->lock`, post `IONIC_CMD_LIF_SETPHC` through adminq, drop the lock, and then wait for completion. `gettimex64` reads hardware tick registers with system timestamp bracketing and converts to nanoseconds.

State and persistence behavior: `phc->ts_config`, `ts_config_tx_mode`, and `ts_config_rx_filt` persist the user's requested timestamping mode for `SIOCGHWTSTAMP`, firmware reset replay, and queue recreation after stop/open. `phc->cc` and `phc->tc` are protected by a spinlock and represent the current PHC conversion state. Firmware receives synchronized tick/nsec/frac/mult/shift via `LIF_SETPHC` commands. During firmware reset, PHC operations return `-EBUSY` or keep polling without updating basis, so external PTP daemons must restore time afterward.

Dependencies: This file depends on Linux PTP clock APIs, `kernel_hwtstamp_config`, netdev hwtstamp ops, system timestamp helpers, timecounter/cyclecounter math, and Ionic admin queue and LIF queue helpers. It consumes ABI fields `hwstamp_tx_modes`, `hwstamp_rx_filters`, `hwstamp_mask`, `hwstamp_mult`, `hwstamp_shift`, `IONIC_ETH_HW_TIMESTAMP`, packet-class bits, and `struct ionic_hwstamp_regs`.

Integration points: Netdev ops in `ionic_lif.c` call hwtstamp set/get. LIF register/unregister/free call PHC lifecycle routines. LIF firmware-up recovery calls `ionic_lif_hwstamp_replay()`, and netdev open calls `ionic_lif_hwstamp_recreate_queues()`. Tx/Rx completion paths can call `ionic_lif_phc_ktime()` to translate hardware ticks. Firmware integration is through `IONIC_CMD_LIF_SETPHC`, timestamp TX mode setattr, RX filter steering, and RX queue feature reconfiguration.

Risks: Timestamp configuration spans queue allocation, firmware attributes, RX filters, and queue reconfiguration; partial failure can leave allocated but unused timestamp queues by design. RX filter fallback to all timestamp packets may increase traffic to timestamp queues. Hardware tick read assumes high cannot change twice during the reread window. Multiplier/shift scaling must avoid overflow and preserve wrap-period assumptions. PHC state is not maintained across firmware upgrade/reset, so callers must tolerate `-EBUSY` and resynchronize. Lock ordering among `queue_lock`, `config_lock`, `phc->lock`, and adminq waits is important.

Test signals: Build with PTP enabled and disabled. Run `hwstamp_ctl`/`ethtool -T` style checks for supported TX/RX modes, invalid mode rejection, `SIOCGHWTSTAMP`, PHC registration under `/dev/ptp*`, `phc2sys`/`ptp4l` adjustment paths, firmware reset replay, open/stop queue recreation, specific PTP and RX-all filtering, Tx/Rx hardware timestamp counters, and fault injection for adminq failures during TX mode or RX filter changes.
