## sources/distributed-fs/ceph-client/drivers/net/ethernet/intel/Kconfig

Purpose: Kconfig menu for Intel Ethernet drivers under `drivers/net/ethernet/intel`. It provides the vendor gate `NET_VENDOR_INTEL`, includes shared Intel library menus, and declares build/configuration symbols for legacy PCI NICs, PCIe gigabit/10GbE/40GbE/E800 drivers, virtual functions, switchdev, hwmon, DCA, DCB, IPsec offload, hardware timestamping, LED trigger support, and the IDPF subdriver.

Important APIs, types, and functions: the file is declarative Kconfig, so the important surface is symbols and dependency/select relationships. Top-level `NET_VENDOR_INTEL` gates the menu. It sources `libeth/Kconfig`, `libie/Kconfig`, and `idpf/Kconfig`. Driver symbols include `E100`, `E1000`, `E1000E`, `IGB`, `IGBVF`, `IXGBE`, `IXGBEVF`, `I40E`, hidden `IAVF`, user-visible compatibility symbol `I40EVF`, `ICE`, `FM10K`, and `IGC`. Feature symbols include `E1000E_HWTS`, `IGB_HWMON`, `IGB_DCA`, `IXGBE_HWMON`, `IXGBE_DCA`, `IXGBE_DCB`, `IXGBE_IPSEC`, `IXGBEVF_IPSEC`, `I40E_DCB`, `ICE_HWMON`, `ICE_SWITCHDEV`, `ICE_HWTS`, and `IGC_LEDS`.

Control flow: menu visibility starts with `config NET_VENDOR_INTEL`; if enabled, the sourced library Kconfigs and all Intel driver prompts are visible according to their `depends on` expressions. Tristate driver selections propagate to the Makefile through `CONFIG_*` object rules. Several drivers `select` common libraries or subsystems, for example `ICE` selects `DIMLIB`, `LIBETH_XDP`, `LIBIE`, `LIBIE_ADMINQ`, `NET_DEVLINK`, `PACKING`, `PLDMFW`, and `DPLL`, while `I40E` selects `AUXILIARY_BUS`, `LIBIE`, `LIBIE_ADMINQ`, and `NET_DEVLINK`. `I40EVF` selects hidden `IAVF` to preserve the old symbol name while building the `iavf` module.

State and persistence behavior: Kconfig writes selected symbols into the kernel configuration and thereby controls what Kbuild compiles as built-in, module, or omitted. Defaults are conservative per feature: vendor gate defaults on, some optional features default on when dependencies are met, and several high-level drivers default off. No runtime state is stored here, but symbol choices persist in `.config` and affect module names, subsystem dependencies, and user-visible prompts.

Dependencies and integration points: dependencies bind Intel drivers to core kernel facilities: `PCI`, `PCI_MSI`, `HAS_IOPORT`, `PTP_1588_CLOCK_OPTIONAL`, `X86`, `PCIE_PTM`, `HWMON`, `DCA`, `DCB`, `XFRM_OFFLOAD`, `ETHTOOL_NETLINK`, `GNSS`, `NET_SWITCHDEV`, `LEDS_CLASS`, and `LEDS_TRIGGER_NETDEV`. `select` statements integrate with shared Intel libraries (`LIBETH`, `LIBETH_XDP`, `LIBIE`, `LIBIE_ADMINQ`, `LIBIE_FWLOG`) and generic subsystems (`AUXILIARY_BUS`, `CRC32`, `I2C`, `I2C_ALGOBIT`, `MDIO`, `NET_DEVLINK`, `PHYLIB`, `PLDMFW`, `XFRM_ALGO`, `NET_SHAPER`, `DIMLIB`, `PACKING`, `DPLL`).

Risks and edge cases: incorrect `select` or `depends on` rules can create invalid configs, especially when built-in drivers select features that are modules or when optional feature symbols combine built-in and module constraints. Compatibility between `I40EVF` and hidden `IAVF` is important for old configs; breaking it can silently drop VF support. Optional helpers such as hwmon, DCA, DCB, IPsec, switchdev, GNSS, PTP, and LEDs are cross-subsystem and need dependency expressions that avoid link failures. Library source order matters because driver symbols select symbols declared in sourced Kconfigs.

Test signals: run Kconfig olddefconfig/allmodconfig fragments enabling each Intel driver as built-in and module, verify no unmet direct dependency warnings, and confirm expected modules map to Makefile outputs (`e100`, `e1000`, `e1000e`, `igb`, `igbvf`, `ixgbe`, `ixgbevf`, `i40e`, `iavf`, `fm10k`, `ice`, `igc`, `idpf`). Specific regression tests should cover `I40EVF -> IAVF`, hwmon built-in/module constraints, `ICE` with `GNSS=m/y/n`, IPsec symbols requiring `XFRM_OFFLOAD`, and timestamp options requiring architecture/platform support.
