# sources/distributed-fs/ceph-client/drivers/net/ethernet/chelsio/cxgb4vf/cxgb4vf_main.c

Purpose: this is the main Linux PCI/netdevice driver for Chelsio T4/T5/T6 SR-IOV Virtual Functions. It owns module parameters, PCI probe/remove/shutdown, adapter initialization, netdev operations, ethtool operations, debugfs files, interrupt mode selection, queue-set sizing, firmware-event handling, and high-level open/close control. Hardware mailbox details and datapath ring operations are delegated to `t4vf_hw.c` and `sge.c`.

Important entry points: `cxgb4vf_module_init()` validates the `msi` module parameter, creates the top-level debugfs directory, and registers `cxgb4vf_driver`. `cxgb4vf_pci_probe()` enables the PCI device, claims regions, sets 64-bit DMA, maps BAR0 and optionally BAR2, prepares the adapter, initializes firmware-facing state with `adap_init0()`, allocates netdevs and VIs, selects MSI-X or MSI, configures queues, registers netdevs, and creates per-device debugfs files. `cxgb4vf_pci_remove()` and `cxgb4vf_pci_shutdown()` unregister netdevs, stop SGE activity, disable interrupts, free queues and VIs, unmap BARs, free mailbox and MAC-hash state, and release PCI resources.

Runtime netdev operations are collected in `cxgb4vf_netdev_ops`. `cxgb4vf_open()` refuses to run without `CXGB4VF_FW_OK`, calls `adapter_up()` for the first open interface, refreshes port information, starts the link/VI path through `link_start()`, records the VF VLAN ACL, and starts TX queues. `cxgb4vf_stop()` stops TX queues, drops carrier, disables the VI with `t4vf_enable_pi()`, clears the open bitmap, and calls `adapter_down()` for the last close. `t4vf_eth_xmit()` and `t4vf_ethrx_handler()` are supplied by `sge.c`.

Initialization control flow: `adap_init0()` performs a firmware reset to compensate for unreliable or absent PCIe FLR behavior, retrieves device/VPD/SGE/RSS/VF-resource parameters, requires RSS global mode `FW_RSS_GLB_CONFIG_CMD_MODE_BASICVIRTUAL`, initializes SGE software parameters, optionally tells newer firmware it can handle encapsulated `CPL_FW4_MSG`, decodes interrupt timer and packet-counter arrays, validates VF port and VI provisioning, calls `size_nports_qsets()`, and sets `CXGB4VF_FW_OK`. Probe then creates netdevs for the allowed port mask, allocates a VI with `t4vf_alloc_vi()`, initializes per-port state with `t4vf_port_init()`, optionally applies an assigned MAC ACL, enables interrupts, calls `cfg_queues()`, and registers the netdevs.

Adapter-up control flow: the first open calls `adapter_up()`. If full initialization has not happened, it calls `setup_sge_queues()` to allocate the optional MSI forwarded interrupt queue, firmware event queue, per-queue RX response/free-list queues, and TX queues, then builds absolute-to-relative queue reverse maps. It calls `setup_rss()` to map each VI RSS table slice to the active RX queue absolute IDs and, in basic-virtual mode without tunnel-all lookup, writes a default ingress queue. It names MSI-X vectors and sets `CXGB4VF_FULL_INIT_DONE`. Each open then requests IRQs, enables NAPI and response-queue interrupt arming via `enable_rx()`, and starts SGE timers through `t4vf_sge_start()`.

Firmware event and interrupt behavior: `fwevtq_handler()` handles firmware event queue CPLs. `CPL_FW6_MSG` with command replies is passed to `t4vf_handle_fw_rpl()`. `CPL_FW4_MSG` can encapsulate `CPL_SGE_EGR_UPDATE`, which is decoded and falls through to the egress-update path. `CPL_SGE_EGR_UPDATE` validates the absolute egress queue ID, maps it to an Ethernet TX queue, increments restart statistics, and wakes the netdev TX queue. Unexpected CPLs, out-of-range queue IDs, null maps, and mismatched queue IDs are logged. MSI-X uses one vector for firmware events and one per Ethernet RX queue; MSI uses a forwarded interrupt queue armed separately.

MAC, RX mode, VLAN, and MTU behavior: `link_start()` programs receive mode with VLAN extraction enabled, installs the primary MAC filter through `cxgb4vf_change_mac()`, and enables the VI. MAC filter allocation first tries exact TCAM through `t4vf_change_mac()` or `t4vf_alloc_mac_filt()`; if firmware reports no exact entries, the driver maintains `adapter->mac_hlist`, computes a 64-bit hash vector in `cxgb4vf_set_addr_hash()`, and programs hash filtering through `t4vf_set_addr_hash()`. `set_rxmode()` synchronizes unicast and multicast lists and sets promiscuous/all-multicast/broadcast/VLAN extraction flags. `cxgb4vf_change_mtu()` sends the new MTU to firmware before updating `dev->mtu`. `cxgb4vf_fix_features()` keeps VLAN TX and RX acceleration coupled because firmware exposes a combined setting, and `cxgb4vf_set_features()` updates firmware receive mode when VLAN RX state changes.

Ethtool and diagnostics: link settings translate firmware port/module/capability values into ethtool link modes through `from_fw_port_mod_type()` and `fw_caps_to_lmm()`. FEC support is exposed through `cxgb4vf_get_fecparam()`. Driver info reports live firmware and TP microcode versions from `adapter->params.dev`. Ring sizing, coalescing, pause parameters, LED identify, standard stats, private statistics, and register dumps are supported. Ring sizes can be changed only before `CXGB4VF_FULL_INIT_DONE`; coalescing can update live queue context through `t4vf_set_params()` if the response queue already exists. Register dumps avoid reading the mailbox-control register because that can trigger ownership arbitration.

Debugfs behavior: per-adapter debugfs exposes `mboxlog`, `sge_qinfo`, `sge_qstats`, `resources`, and `interfaces`. `mboxlog` dumps the circular mailbox command log without locking, knowingly allowing partially updated entries. Queue info and stats group Ethernet queue sets four per display entry and also show firmware event and MSI interrupt queues. Resource output reflects the firmware-provisioned VF limits (`nvi`, `neq`, `nethctrl`, `niqflint`, `niq`, `tc`, `pmask`, `nexactf`, `r_caps`, `wx_caps`).

State and persistence: major runtime state lives in `struct adapter`, `struct port_info`, and `struct sge`. Persistent hardware state includes allocated VIs, MAC filters or hash vector, queue contexts, RSS table entries, enabled/disabled VI state, and firmware reset side effects. Driver state is bounded by bitmaps (`registered_device_map`, `open_device_map`), flags (`FW_OK`, interrupt mode, full init), debugfs dentries, NAPI state, IRQ registrations, DMA ring allocations, and mailbox logs. Queue parameters and ring sizes persist only until the driver is unloaded or queues are freed, but after full initialization they cannot be changed through ethtool ringparam.

Dependencies and integration points: this file depends on Linux PCI, DMA mapping, netdevice, ethtool, MDIO, debugfs, seq_file, NAPI, MSI/MSI-X, and Chelsio common headers. It calls hardware and firmware helpers from `t4vf_common.h`/`t4vf_hw.c` for reset, parameter discovery, VI allocation, port init/update, MAC filters, RSS, stats, RX mode, identify, mailbox reply handling, and VF ACL queries. It calls SGE helpers from `sge.c` for queue allocation, queue cleanup, transmit, receive, interrupt selection, and timers.

Risks: firmware initialization failures are logged but probe may continue in debug mode, so netdev paths must keep checking `CXGB4VF_FW_OK`. The module-global `msi` variable is modified to `MSI_MSI` on MSI-X fallback, which can affect later devices in the same module instance. Queue reverse-map assumptions are security and stability sensitive because firmware event queue messages drive TX queue wakeups. Hash MAC fallback must keep `mac_hlist` synchronized or multicast/unicast filtering can become stale. Debugfs mailbox log reads are intentionally unlocked. Register dumps avoid one mailbox register but still read many VF-visible registers, so hardware access errors can surface there. Error unwinding must free VIs, netdevs, BAR mappings, interrupts, debugfs nodes, SGE resources, mailbox log memory, and hash list entries in the right order.

Test signals: build with `CONFIG_CHELSIO_T4VF=m/y`, load with `msi=2` and `msi=1`, and probe on T4 and T5/T6 hardware or VF-capable emulation. Probe logs should show firmware resource discovery, interrupt mode, and registered netdevs. Functional tests should cover open/close cycles, link changes, assigned MAC ACL handling, exact MAC exhaustion with hash fallback, multicast list sync, MTU changes, VLAN feature toggles, RSS distribution across queue sets, ethtool stats/register/ring/coalesce output, debugfs file reads, suspend/shutdown/remove, and forced failures in firmware commands, IRQ allocation, netdev registration, and queue allocation. Runtime counters to watch include TX queue stops/restarts, RX checksum/VLAN/GRO counters, free-list allocation failures, and firmware mailbox log entries.
