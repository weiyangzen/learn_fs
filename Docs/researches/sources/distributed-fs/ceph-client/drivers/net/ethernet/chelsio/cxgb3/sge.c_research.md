# sources/distributed-fs/ceph-client/drivers/net/ethernet/chelsio/cxgb3/sge.c

## Purpose

`sge.c` implements the Scatter Gather Engine data path for the Chelsio T3 `cxgb3` Ethernet/offload driver. It owns queue-set allocation, descriptor ring lifecycle, Rx free-list replenishment, Tx work request construction, interrupt/NAPI response processing, periodic reclaim timers, and SGE start/stop/init entry points used by the top-level driver. It bridges Linux networking primitives (`sk_buff`, NAPI, netdev queues, DMA mapping, VLAN/GRO/checksum metadata) to Chelsio T3 hardware contexts programmed by `t3_hw.c`.

## Important APIs, Types, and Functions

- Local descriptor formats: `struct tx_desc`, `struct rx_desc`, `struct rsp_desc`, `struct tx_sw_desc`, and `struct rx_sw_desc` mirror hardware rings and keep software-only ownership metadata such as EOP, fragment indexes, generation bits, skb pointers, and DMA unmap addresses.
- Queue roles: `TXQ_ETH`, `TXQ_OFLD`, and `TXQ_CTRL` are fixed-order Tx queues inside each `struct sge_qset`. Changing that order would break context assignment and stop/restart logic.
- Allocation/lifecycle: `t3_sge_alloc_qset()`, `t3_free_sge_resources()`, `t3_sge_start()`, `t3_sge_stop_dma()`, `t3_sge_stop()`, `t3_sge_init()`, and `t3_sge_prep()` are the main external setup/teardown hooks.
- Ethernet Tx: `t3_eth_xmit()` validates packet length, chooses queue mapping, reclaims completed descriptors, maps packet data if needed, handles stop thresholds, writes `CPL_TX_PKT`/`CPL_TX_PKT_LSO` work requests, and rings the egress context doorbell.
- Offload/control Tx: `t3_offload_tx()`, `ofld_xmit()`, `ctrl_xmit()`, `restart_offloadq()`, and `restart_ctrlq()` transmit already-formed CPL/work-request skbs from upper-layer/offload clients.
- Rx/response processing: `process_responses()`, `napi_rx_handler()`, `ofld_poll()`, `rx_eth()`, `rx_offload()`, `lro_add_page()`, `process_pure_responses()`, and `handle_responses()` consume SGE response descriptors and deliver Ethernet or offload packets.
- Interrupt entry points: `t3_intr_handler()` selects between MSI-X, MSI, and legacy INTx handlers, with NAPI and non-NAPI variants; `t3_sge_err_intr_handler()` handles SGE async/fatal error causes.

## Control Flow

The setup path starts with `t3_sge_prep()`, which seeds default queue sizes, coalescing, polling mode, and `reg_lock`. `t3_sge_init()` programs global SGE registers after chip reset, but it does not create rings. `t3_sge_alloc_qset()` allocates coherent hardware rings and software descriptor arrays, initializes context IDs, configures SGE response/free-list/egress contexts through `t3_sge_init_*()` helpers in `t3_hw.c`, fills Rx free lists, returns response queue credits, and arms the response queue via `A_SG_GTS`.

On Ethernet Tx, `t3_eth_xmit()` calculates descriptor demand with `calc_tx_descs()`, maps skb fragments with `map_skb()` when the packet cannot be inlined, updates queue indices/generation bits, records statistics for checksum/TSO/VLAN insertion, optionally orphans the skb to run socket accounting early, writes the CPL/work request through `write_tx_pkt_wr()`, then rings `A_SG_KDOORBELL`. Immediate packets are copied into a descriptor and the skb is consumed immediately; larger packets use SGLs generated by `write_sgl()` and distributed across descriptors by `write_wr_hdr_sgl()`.

The offload Tx path uses skb priority bits as an internal contract: bit 0 selects control vs offload queue and bits 1-3 select queue set. Control packets must fit in one descriptor as immediate data. Offload packets may carry prebuilt work requests and may use deferred DMA unmapping through `deferred_unmap_destructor()` when platform DMA state requires it.

On Rx, hardware posts response descriptors. Interrupt handlers either process directly, handle pure credit-only responses in hardirq context, or schedule NAPI. `process_responses()` recognizes async notifications, immediate data, free-list backed packets, and pure responses. It selects FL0/FL1, copies small buffers or attaches page chunks, performs GRO for eligible Ethernet TCP traffic, updates Tx processed counters from response control flags, returns response queue credits in batches, and restarts stopped Tx queues when enough descriptors have completed.

## State and Persistence Behavior

State is in memory and hardware registers, not persistent storage. Important mutable state includes ring producer/consumer indexes (`pidx`, `cidx`), generation bits (`gen`), credits, pending free-list credits, Tx descriptor accounting (`in_use`, `processed`, `cleaned`, `unacked`), skb queues for suspended offload/control paths, response queue holdoff settings, and port/qset statistics. DMA mappings persist only until explicit unmap during descriptor reclaim, Rx buffer recycling, or skb destructor execution. Timers (`tx_reclaim_timer`, `rx_reclaim_timer`) periodically recover from traffic patterns that do not naturally trigger reclaim or from Rx allocation failures.

## Dependencies and Integration Points

This file depends on Linux kernel networking, PCI DMA, timers, workqueues, NAPI, VLAN, GRO, and ARP helpers. It depends on `adapter.h` structures, `common.h` hardware abstractions, `regs.h` register definitions, `sge_defs.h` SGE context bit fields, `t3_cpl.h` CPL/work-request structures, `firmware_exports.h` firmware context/TID constants, and `cxgb3_offload.h` offload callbacks. It integrates upward with netdev transmit queues and receive delivery, and sideways with offload clients through `struct t3cdev.send/recv` and workqueue-based queue restarts. It integrates downward with `t3_hw.c` context programming and slow interrupt handling.

## Risks and Edge Cases

- Ring ownership depends on correct generation-bit toggling and memory barriers (`dma_wmb`, `dma_rmb`, `wmb`, `rmb`). Missing ordering can expose partially written descriptors to hardware or stale responses to software.
- DMA mapping and unmapping are split across descriptors, skb metadata, and deferred destructors. Bugs here can leak mappings, unmap too early, or double-free pages/skbs.
- Stop/restart logic uses atomic bit operations, queue locks, and response-credit side effects. Races can stall queues or wake them before enough descriptors are available.
- The Rx page-chunk path shares pages via a counter stored at the reserved page tail; mistakes can leak pages or unmap a shared page while fragments are still attached.
- Low-memory behavior intentionally drops/copies/recycles differently for Ethernet and offload traffic. `NOMEM_INTR_DELAY` and Rx timers are important recovery signals.
- Interrupt handling differs by MSI-X/MSI/legacy and chip revision; shared locking around queue 0 is required in shared-vector modes.

## Test Signals

Useful signals include successful qset allocation and free under repeated open/close, sustained Tx with descriptor reclaim and no netdev queue stalls, Rx under small/large/jumbo packets, GRO/VLAN/checksum/TSO counters, offload packet batching through `tdev.recv`, low-memory refill recovery, interrupt mode coverage for MSI-X/MSI/INTx, and fatal SGE error reporting via `t3_sge_err_intr_handler()`. Kernel validation should watch DMA-debug, skb/page leaks, queue stop/restart counters, response queue starvation counters, and traffic tests across one-port and two-port adapters.
