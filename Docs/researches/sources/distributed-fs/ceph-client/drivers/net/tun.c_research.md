# sources/distributed-fs/ceph-client/drivers/net/tun.c

Purpose: Implements the Linux universal TUN/TAP driver. It exposes `/dev/net/tun` as a misc character device, creates TUN point-to-point or TAP Ethernet netdevices through `TUNSETIFF`, and bridges packet movement between userspace file descriptors, kernel netdevice TX/RX, socket-like operations, XDP, BPF steering/filtering, NAPI, and virtio-net header offload metadata.

Important APIs, types, and functions: `struct tun_file` represents one open file/queue and owns the synthetic socket, `ptr_ring tx_ring`, NAPI state, queue index, XDP RX queue info, and detached-queue state. `struct tun_struct` is the netdevice private state with queue array, flags, owner/group, vnet header size, offload feature mask, TAP filter, classic socket filter state, flow table, disabled queue list, XDP program, eBPF steering/filter programs, ethtool settings, and security blob. Major entry points are `tun_chr_open()`, `tun_chr_close()`, `tun_chr_read_iter()`, `tun_chr_write_iter()`, `__tun_chr_ioctl()`, `tun_set_iff()`, `tun_attach()`, `__tun_detach()`, `tun_net_xmit()`, `tun_get_user()`, `tun_put_user()`, `tun_sendmsg()`, and `tun_recvmsg()`. Exported integration helpers are `tun_get_socket()` and `tun_get_tx_ring()`.

Control flow: Userspace opens `/dev/net/tun`, then `TUNSETIFF` either attaches the file to an existing matching TUN/TAP device or allocates and registers a new multi-queue or single-queue netdevice. Kernel-to-userspace traffic enters `tun_net_xmit()`, selects a queue via flow hashing or eBPF steering, applies TAP multicast and socket/eBPF filters, queues an skb or XDP frame into the selected file's `tx_ring`, then wakes poll/read/fasync waiters. Userspace-to-kernel traffic enters `tun_chr_write_iter()` or `tun_sendmsg()`, parses optional packet information and optional virtio-net metadata, builds an skb from copied, fragmented, zerocopy, or page-frag memory, runs XDP if configured, derives TUN protocol or TAP Ethernet protocol, then injects through GRO/NAPI, batched receive, `netif_receive_skb()`, or `netif_rx()`. Socket `sendmsg` can also accept `TUN_MSG_PTR` arrays of `xdp_buff` objects for XDP-oriented injection.

State and persistence: Device state is runtime kernel state attached to the registered netdevice. Persistent devices set `IFF_PERSIST`, hold a module reference, and survive file close until persistence is cleared or the netdevice is unregistered. Queue attachment state is RCU-published, with disabled queues kept on `tun->disabled` for later `TUNSETQUEUE` reattach. Flow steering state is a timer-aged RCU hash table capped by `MAX_TAP_FLOWS`. The TAP transmit filter and socket filter are stored on `tun_struct` so they can be restored when a file attaches to a persistent device. Owner, group, flags, and queue counts are visible through sysfs and rtnetlink fill-info.

Dependencies and integration: Depends on miscdevice registration, rtnetlink link ops, netdevice operations, `ptr_ring`, Linux socket callbacks, RCU, RTNL locking, NAPI/GRO, XDP, BPF socket-filter programs, LSM hooks (`security_tun_*`), network namespaces, ethtool, proc fdinfo, compat ioctls, virtio-net helpers from `tun_vnet.h`, skb zerocopy, and notifier events for TX queue length and device-up changes. TAP uses Ethernet helpers and supports XDP NDO transmit; TUN uses IP tunnel header ops and point-to-point link metadata.

Risks and test signals: Highest-risk areas are RCU queue publication/detach ordering, persistent device lifetime, queue index rewriting during detach, `ptr_ring` resize and purge correctness, virtio header bounds/endian handling, zerocopy completion paths, NAPI-frags locking, XDP page ownership, eBPF program replacement lifetime, and ioctl permission checks. Test signals should include TUN and TAP create/delete, persistent close/reopen, multi-queue attach/detach, poll/fasync wakeups, read/write truncation, `sendmsg`/`recvmsg`, vnet header size/endian ioctls, TSO/USO/tunnel offloads, BPF steering/filtering, XDP PASS/DROP/TX/REDIRECT, NAPI and NAPI_FRAGS, TX queue length resize, owner/group permissions, compat ioctl paths, and namespace cleanup.
