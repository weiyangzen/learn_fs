# sources/distributed-fs/ceph-client/drivers/net/usb/net1080.c

## Purpose
`net1080.c` is a `usbnet` minidriver for NetChip 1080 USB host-to-host cables. It supports point-to-point Ethernet over NetChip framing: header, Ethernet payload, optional pad byte, and trailer with a repeated packet ID.

## Important APIs, Types, And Functions
`struct nc_header` carries header length, packet length, and packet ID; optional vendor/product fields may follow. `struct nc_trailer` repeats the packet ID. Vendor helpers read/write USBCTL, TTL, and STATUS registers. `net1080_reset()` flushes both sides, programs read TTL, and reports peer connection. `net1080_check_connect()` returns `-ENOLINK` when the peer is absent. `nc_ensure_sync()` flushes after repeated framing errors. `net1080_rx_fixup()` validates odd transfer length, header length, max size, pad byte, payload length, and packet ID. `net1080_tx_fixup()` adds framing and increments `dev->xid`.

## Control Flow
USB probe is generic usbnet via `net1080_info`. `net1080_bind()` expands `hard_header_len`, sizes RX URBs, sets `hard_mtu`, and gets endpoints. usbnet calls reset, check-connect, RX fixup, and TX fixup as needed around its normal data path.

## State And Persistence Behavior
Runtime state is `dev->xid` and `dev->data[1]` as `frame_errors`. Hardware state touched during reset includes USBCTL flush bits and TTL. No nonvolatile state is managed.

## Dependencies And Integration Points
The file depends on usbnet, USB vendor requests, Ethernet/netdevice APIs, and unaligned helpers. It declares `FLAG_POINTTOPOINT | FLAG_FRAMING_NC`.

## Risks And Test Signals
Exact framing is the main risk. Even-length USB frames, bad pad, oversized packet length, short header, length mismatch, and packet-ID mismatch are rejected. Tests should cover pad insertion/removal, odd-length enforcement, packet-ID validation, peer disconnect, reset TTL programming, and sync recovery after repeated malformed frames.
