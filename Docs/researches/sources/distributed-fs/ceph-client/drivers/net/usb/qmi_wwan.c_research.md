# sources/distributed-fs/ceph-client/drivers/net/usb/qmi_wwan.c

Purpose: implements the Linux USB WWAN data driver for Qualcomm MSM Interface (QMI) modems. The driver binds QMI-capable USB interfaces through `usbnet`, exposes modem control traffic to userspace through a `cdc-wdm` subdriver, carries data as either Ethernet-framed packets, raw IP packets, pass-through MAP packets, or QMAP multiplexed child netdevices, and contains a large USB device-id table for Qualcomm, Huawei, Sierra, Telit, Quectel, ZTE, Dell/HP, and related modem variants.

Important types and data: `struct qmi_wwan_state` is stored inside `usbnet->data` and tracks the registered `cdc-wdm` subdriver, an atomic power-management reference count, mode flags, and the control/data USB interfaces. `enum qmi_wwan_flags` records runtime packet mode: `RAWIP`, `MUX`, and `PASS_THROUGH`. `enum qmi_wwan_quirks` currently carries the DTR wakeup quirk. `struct qmimux_hdr` describes the four-byte QMAP header (`pad`, `mux_id`, network-order payload length), and `struct qmimux_priv` binds each virtual mux netdevice to the real USB netdevice and its mux id.

Important APIs/functions: `qmi_wwan_bind()` is the main usbnet bind hook. It parses CDC descriptors, chooses separate control/data interfaces when a CDC union exists, reads CDC Ethernet MTU/MAC metadata when available, claims the data interface, registers the `cdc-wdm` QMI control endpoint, applies DTR power quirks, sanitizes problematic modem MAC addresses, and installs `qmi_wwan_netdev_ops` plus the `qmi` sysfs group. `qmi_wwan_unbind()` disconnects the subdriver, clears DTR for USB3-style devices, releases paired interfaces, and clears cached state. `qmi_wwan_probe()` supplies defaults for dynamic IDs, rejects fixed-interface matches on non-vendor-specific interfaces, skips a Quectel EC20 conflicting function, rejects two-endpoint diagnostic interfaces, then delegates to `usbnet_probe()`. `qmi_wwan_disconnect()` tears down QMAP upper devices before calling `usbnet_disconnect()`.

Packet handling: `qmi_wwan_rx_fixup()` is the ingress classifier. If muxing is enabled, it delegates to `qmimux_rx_fixup()`. If pass-through is enabled, it marks packets as `ETH_P_MAP`. Otherwise it distinguishes raw IPv4/IPv6 by the first nibble, preserves ARP and unknown Ethernet frames in Ethernet mode, drops non-IP packets in raw-IP mode, and synthesizes Ethernet headers when firmware sends raw IP despite the device being configured as Ethernet. `qmi_wwan_mac_addr()` rejects MAC addresses whose first byte could be mistaken for an IP header, preserving the header-detection heuristic.

QMAP muxing: `add_mux` and `del_mux` sysfs stores create and remove upper `qmimux%d` netdevices under RTNL. Mux ids are limited to 1..254 for compatibility with `ip(8)` and rmnet conventions. `qmimux_register_device()` allocates an ARPHRD_NONE point-to-point netdevice, publishes a `qmap/mux_id` sysfs attribute, registers it, takes a reference on the real device, and links it as an upper device. `qmimux_start_xmit()` prepends a QMAP header and queues the skb through the real USB netdevice. `qmimux_rx_fixup()` walks one or more QMAP frames inside a USB receive skb, validates lengths and padding, ignores control frames, finds the matching upper netdevice by mux id, allocates a fresh skb, sets IPv4/IPv6 protocol, and accounts RX stats.

Sysfs control surface: the primary netdevice exports `qmi/raw_ip`, `qmi/add_mux`, `qmi/del_mux`, and `qmi/pass_through`. `raw_ip_store()` requires the device to be down, uses `NETDEV_PRE_TYPE_CHANGE`/`POST_TYPE_CHANGE` notifications, refuses to clear raw-IP while pass-through is set, and calls `qmi_wwan_netdev_setup()` to switch between Ethernet and ARPHRD_NONE raw-IP netdevice shape. `pass_through_store()` is allowed only when raw-IP mode is already set. `add_mux_show()` and `del_mux_show()` list currently linked mux ids.

Power management and control integration: `qmi_wwan_register_subdriver()` gathers bulk endpoints with `usbnet_get_endpoints()`, chooses the interrupt status endpoint from the control interface when control/data are separate, and calls `usb_cdc_wdm_register()` with a 4096-byte QMI buffer and `WWAN_PORT_QMI`. The returned subdriver is retained so suspend/resume/unbind can call into it. `qmi_wwan_manage_power()` merges usbnet and cdc-wdm power requests with `pmcount`, toggling `needs_remote_wakeup` under an autopm get/put. `qmi_wwan_cdc_wdm_manage_power()` adapts cdc-wdm power requests back to usbnet state. `qmi_wwan_suspend()` suspends usbnet first and then cdc-wdm for the control interface; `qmi_wwan_resume()` resumes cdc-wdm first and then usbnet, rolling back the subdriver if usbnet resume fails.

Control flow summary: USB core matches `products[]` and calls `qmi_wwan_probe()`. The probe filters non-QMI functions and invokes `usbnet_probe()`, which eventually calls `qmi_wwan_bind()`. Bind establishes interface ownership, registers the QMI character-device path through cdc-wdm, sets link-layer mode defaults, and prepares the netdevice. Runtime traffic flows through usbnet TX/RX callbacks; RX packets pass through `qmi_wwan_rx_fixup()`, and mux children add/remove QMAP framing at their own netdev boundary. Disconnect first unregisters mux child devices in a batch and then lets usbnet run the normal unbind path.

State and persistence behavior: all mode state is in-memory per USB netdevice. Raw-IP, pass-through, mux membership, pmcount, control/data interface pointers, and the subdriver pointer are lost on disconnect/reprobe. QMAP child netdevices hold an explicit reference on the real device and release it during unregister. The driver does not persist QMI client/session state itself; userspace modem managers own QMI protocol state through `/dev/cdc-wdm*`. The DTR quirk intentionally keeps remote wakeup/DTR asserted across open/close cycles to avoid modem firmware clearing QMI client allocations.

Dependencies and integration points: build is controlled by `CONFIG_USB_NET_QMI_WWAN`, depends on `USB_USBNET`, and selects `USB_WDM`; the Makefile builds `qmi_wwan.o`. Runtime dependencies include USB core matching, CDC descriptor parsing, usbnet endpoint/data-plane helpers, cdc-wdm QMI character-device registration, netdevice upper/lower link APIs, RTNL/RCU protection around child devices, notifier chains for type changes, skb protocol handling, and the WWAN port type namespace. Neighboring `cdc_ether.c` explicitly avoids several devices handled by this driver.

USB matching policy: the `products[]` table is intentionally broad. It supports CDC-ECM-like control-interface matches, combined interfaces matched by vendor-specific class/subclass/protocol, many fixed interface-number matches, Gobi 1000 interface 3, Gobi 2000/3000 interface 0, and a Quectel-style `ff/ff/ff` dynamic-function match with DTR quirk. `QMI_QUIRK_SET_DTR()` and USB3 detection enable the DTR behavior for devices that require it to wake or remain QMI-responsive.

Risks and edge cases: packet-mode transitions are exposed through sysfs and must be serialized correctly; raw-IP type changes while the netdevice is running are rejected, but pass-through changes do not require RTNL and depend on raw-IP already being set. The raw-IP-versus-Ethernet heuristic depends on the MAC address not looking like an IP header, so MAC validation and bind-time randomization are important. `qmimux_rx_fixup()` drops the whole receive path on allocation failure, malformed lengths, or `netif_rx()` failure, which is conservative but can hide per-mux loss. QMAP child teardown uses RTNL plus RCU traversal; changes here need care around upper-dev iteration and batched unregister. The probe table can accidentally claim diagnostic or unrelated vendor-specific functions if endpoint-count or class filters are weakened. DTR/autopm handling is subtle because clearing DTR can reset modem-side QMI state.

Test signals: build with `CONFIG_USB_NET_QMI_WWAN=m` should produce `qmi_wwan.ko` and select `cdc-wdm`. Probe tests should show the network device plus `/dev/cdc-wdm*` on supported QMI interfaces, while two-endpoint diagnostic functions and non-vendor-specific fixed-interface matches are rejected. Sysfs tests should verify `raw_ip` cannot change while the device is up, pass-through requires raw-IP mode, mux ids outside 1..254 fail, duplicate mux ids fail, and mux devices expose `qmap/mux_id`. Data tests should cover Ethernet-mode raw-IP header synthesis, raw-IP IPv4/IPv6 classification, pass-through `ETH_P_MAP`, QMAP demux to multiple child netdevices, malformed QMAP length/padding drops, and child unregister on USB disconnect. Power tests should validate suspend/resume with active cdc-wdm users and DTR quirk devices remaining QMI-responsive across netdevice open/close cycles.
