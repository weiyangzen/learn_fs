# sources/distributed-fs/ceph-client/drivers/net/usb/r8153_ecm.c

Purpose: Provides a small CDC ECM `usbnet` driver for RTL8153-based adapters that expose a standards-based Ethernet control interface instead of, or before, the Realtek vendor-mode `r8152` interface. It binds Realtek and selected Lenovo RTL8153 ECM devices, wires MDIO access through Realtek PLA/OCP vendor requests, and otherwise delegates packet transport and CDC management to the generic `usbnet` CDC helpers.

Important APIs and functions: `pla_read_word()` and `pla_write_word()` issue `usbnet_read_cmd()`/`usbnet_write_cmd()` requests with `RTL8152_REQ_GET_REGS`, `RTL8152_REQ_SET_REGS`, `RTL8152_REQT_READ`, `RTL8152_REQT_WRITE`, `MCU_TYPE_PLA`, and byte-enable masks from `linux/usb/r8152.h`. `r8153_ecm_mdio_read()` and `r8153_ecm_mdio_write()` select OCP base `0xa000` through `OCP_BASE` and then access PHY registers at `0xb400 + reg * 2`. `r8153_bind()` calls `usbnet_cdc_bind()` and installs the MII callbacks, `r8153_info` supplies the `driver_info`, and `rtl8153_ecm_probe()` optionally defers to the vendor driver by calling exported `rtl8152_get_version()` when `CONFIG_USB_RTL8152` is reachable.

Control flow: USB matching accepts CDC Ethernet communication interfaces for Realtek product `0x8153` and Lenovo products `0x721e` and `0xa359`. Probe first asks the vendor driver whether the interface is a recognized RTL8152-family device; if a version is returned, this ECM driver returns `-ENODEV` so `r8152` can claim the better-supported vendor path. Otherwise `usbnet_probe()` binds the device. During bind, the generic CDC parser configures endpoints and the network device, then this file configures `dev->mii` with the netdev, read/write callbacks, five-bit register mask, and GMII support. Runtime RX/TX, status notifications, suspend/resume, disconnect, and power management are generic `usbnet`/CDC paths referenced from `r8153_info` and `r8153_ecm_driver`.

State and persistence: This file stores no private object beyond the `usbnet` state allocated by the core. Persistent runtime state is the `dev->mii` callback table and the USB driver binding. MDIO writes program the adapter's PLA/OCP registers directly; link state, endpoint queues, CDC descriptors, and netdevice lifetime are owned by `usbnet_cdc_bind()`, `usbnet_cdc_status()`, `usbnet_manage_power()`, and the `usbnet` driver core.

Dependencies and integration: Depends on Linux USB, CDC ECM descriptors, `usbnet`, generic MII helpers, netdevice APIs, and Realtek USB request definitions shared with `r8152.c`. Integration is intentionally subordinate to the vendor driver: when `CONFIG_USB_RTL8152` is built in or loadable and recognizes the hardware, ECM probe declines. If the vendor driver is absent or cannot recognize the interface, this driver supplies a standards-based fallback using `module_usb_driver()`.

Risks and test signals: Risks are narrow but important: incorrect byte-enable shifting for word-aligned PLA accesses, ignoring `phy_id` in MDIO callbacks, failed OCP-base writes causing silent MDIO failures, duplicate driver binding if `rtl8152_get_version()` behavior changes, and regressions in Lenovo/Realtek product matching. Test with `CONFIG_USB_RTL8152` built-in, modular, and disabled; verify that recognized vendor-mode devices bind to `r8152` while ECM-only exposure binds here; exercise `mii-tool`/ethtool MII reads and writes; test suspend/resume/autosuspend through `usbnet_manage_power`; and confirm CDC status notifications update carrier through the generic CDC path.
