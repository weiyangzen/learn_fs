# sources/distributed-fs/ceph-client/drivers/net/usb/r8152.c

Purpose: Implements the Realtek vendor-mode USB Ethernet driver for RTL8152, RTL8153, RTL8155, RTL8156, RTL8157, and many dock/vendor rebadges. It owns USB configuration selection, device probing, register access through Realtek OCP/PLA/USB control messages, firmware patch loading, PHY/MAC setup, RX/TX USB bulk aggregation, NAPI delivery, ethtool and MII operations, wake-on-LAN, runtime/system suspend, reset recovery, and netdevice registration.

Important APIs and types: The central runtime object is `struct r8152`, allocated as `netdev_priv()`, holding USB device/interface pointers, `struct napi_struct`, interrupt URB, RX/TX aggregation pools, SKB queues, spinlocks, delayed works, MII state, a hardware-control mutex, TX tasklet, version-selected `rtl_ops`, descriptor operations, firmware state, advertised link modes, WOL state, aggregation/coalescing settings, endpoint pipes, feature quirks, OCP base cache, and reset-failure accounting. Packet formats are represented by `struct rx_desc`, `struct tx_desc`, and RTL8157 v2 descriptors; firmware formats include `struct fw_header`, `struct fw_block`, `struct fw_mac`, `struct fw_phy_nc`, `struct fw_phy_union`, and related PHY patch records. External APIs are the USB driver `rtl8152_driver`, the configuration selector `rtl8152_cfgselector_driver`, netdevice ops in `rtl8152_netdev_ops`, ethtool ops in `ops`, exported `rtl8152_get_version()`, and MII ioctl hooks.

Control flow: Module init first registers a USB device-level configuration selector so supported adapters can be switched to a vendor-specific interface, then registers the interface driver. Probe rejects non-vendor interfaces, validates endpoint numbers 1/2/3, reads the hardware version, retries `rtl8152_probe_once()` up to three times on early control-transfer failures, allocates an Ethernet netdevice, initializes endpoint pipes/features/MTU limits/MII state/quirks, selects chip-family operations in `rtl_ops_init()`, schedules firmware/PHY work, determines the MAC address, adds NAPI, and registers the netdevice. Open allocates RX pages, TX buffers, and URBs, powers the interface through USB autosuspend, runs the chip `up()` sequence, enables work, submits the interrupt URB, enables NAPI and the TX tasklet, and starts with carrier off until a link interrupt/work item observes link. Close unregisters the PM notifier, disables tasklet/work/NAPI, kills the interrupt URB, runs `down()` or drops queues when inaccessible, frees URB memory, and leaves the netdevice registered.

RX and TX data path: TX starts in `rtl8152_start_xmit()`, timestamps and queues the SKB, and schedules the TX tasklet unless selective suspend requires the workqueue to wake the device first. `tx_bottom()` obtains a free `tx_agg`; `r8152_tx_agg_fill()` drains queued SKBs into an aligned USB aggregation buffer, writes descriptor length/checksum/TSO/VLAN metadata, falls back to `skb_gso_segment()` or `skb_checksum_help()` when hardware offset limits are exceeded, submits the bulk OUT URB, and accounts completion in `write_bulk_callback()`. RX starts with submitted bulk IN URBs from `rtl_start_rx()` and `r8152_submit_rx()`. `read_bulk_callback()` moves completed aggregates to `rx_done` and schedules NAPI. `rx_bottom()` parses one or more hardware descriptors per aggregate, validates packet lengths, strips FCS, chooses copy versus page-fragment delivery based on `rx_copybreak` and spare page ownership, applies checksum and VLAN offload metadata, feeds GRO immediately or queues overflow packets in `rx_queue`, recycles or grows RX aggregators up to `rx_pending`, and resubmits URBs.

Control, reset, and link management: All hardware register access funnels through `r8152_control_msg()`, `get_registers()`, `set_registers()`, and OCP helpers. A failed control transfer marks `RTL8152_INACCESSIBLE`; during probe it requests retry, after successful probe it queues USB device reset up to `REGISTER_ACCESS_MAX_RESETS`, and it avoids additional reset recursion during `pre_reset`. Link changes arrive through the interrupt URB and set `RTL8152_LINK_CHG`; `rtl_work_func_t()` serializes work under `tp->control`, updates carrier through `set_carrier()`, applies multicast/promiscuous filters, schedules deferred TX after runtime resume, and drains EPROTO RX retries. Carrier-on enables the chip, starts RX, updates RX filters, and wakes the queue; carrier-off stops queueing, disables NAPI, disables the chip, and re-enables tasklet/NAPI around the transition.

Firmware and hardware-version behavior: `__rtl_get_hw_ver()` maps hardware register values to `RTL_VER_*`; `rtl_ops_init()` selects chip-family init/enable/disable/up/down/unload/EEE/autosuspend/MTU operations, descriptor layouts, RX buffer sizes, and 2.5G/5G support. Firmware names are version-specific under `rtl_nic/`; `rtl8152_request_firmware()` loads the blob and `rtl8152_check_firmware()` verifies SHA-256 checksum, block order, single-instance constraints, version-specific registers, offsets, lengths, breakpoints, and PHY patch records. `rtl8152_apply_firmware()` runs pre/post hooks, applies PLA/USB MAC patches, PHY patch-key sections, NC/union/fixup/speed-up blocks, and records the firmware version for ethtool. Hardware setup functions configure ALDPS/UPS, EEE, flow control, FIFO thresholds, OOB transitions, U1/U2/U2P3 power behavior, BMU reset, VLAN offload, jumbo MTU thresholds, and RTL8156/RTL8157 high-speed parameters.

State and persistence: Persistent runtime state is entirely kernel memory attached to the USB interface and netdevice: hardware accessibility flags, work flags, firmware pointer/version, MAC address, WOL settings, autoneg/speed/duplex/advertising, EEE advertisement, RX copybreak and pending count, coalesce timer, flow-control thresholds, aggregation pools, queued SKBs, and cached `ocp_base`. Device hardware retains programmed MAC, WOL, OOB, firmware patch, PHY, and FIFO register state across active operation, but this file rebuilds it from driver state on probe, open, reset resume, and link transitions. Firmware blobs are requested from userspace firmware storage but not modified; `release_firmware()` drops the reference during disconnect/probe rollback.

Dependencies and integration: Depends on USB core control/bulk/interrupt URBs, `usbnet`-shared Realtek UAPI definitions in `linux/usb/r8152.h`, firmware loader, SHA-256 helper, Linux netdevice/NAPI/GRO/ethtool/MII/MDIO APIs, VLAN and checksum/TSO offload helpers, runtime PM/autosuspend, PM notifier, ACPI-based Lenovo MAC pass-through support, and kernel workqueue/tasklet/list/SKB/page primitives. It integrates with `r8153_ecm.c` through exported `rtl8152_get_version()`: the ECM driver refuses devices that this vendor driver recognizes when reachable, avoiding duplicate binding. USB device IDs cover Realtek plus Microsoft, Samsung, Lenovo, Linksys, NVIDIA, TP-Link, D-Link, Dell, ASUS, and TRENDnet products.

Risks and test signals: High-risk areas are failed USB control reads followed by read/modify/write register programming, reset recursion and `RTL8152_INACCESSIBLE` recovery, probe retry cleanup, firmware block validation and version-specific patch addresses, RX page-fragment lifetime while aggregate pages are recycled, NAPI budget overflow into `rx_queue`, TX aggregation fallback for oversized transport offsets, autosuspend races with queued TX, link-change ordering around NAPI/tasklet disable, WOL/OOB state restoration, jumbo MTU FIFO thresholds, and multi-gig advertisement on USB speeds that cannot support it. Useful tests include bind/unbind and reset-resume on every supported hardware version, vendor-mode configuration selection versus ECM fallback, missing/invalid firmware, repeated control-transfer errors, RX/TX under NAPI budget pressure, TSO/checksum/VLAN offloads, ethtool speed/EEE/coalesce/ring/copybreak/pause/WOL changes, runtime autosuspend with queued packets, system suspend/resume with WOL, link flap storms, jumbo MTU transitions, and builds with firmware built in or modular.
