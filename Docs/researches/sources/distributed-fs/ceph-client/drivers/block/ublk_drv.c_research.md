# sources/distributed-fs/ceph-client/drivers/block/ublk_drv.c

Purpose: This file implements the Linux userspace block device driver (`ublk`). It exposes a control misc device (`/dev/ublk-control`), per-device character devices (`/dev/ublkcN`), and blk-mq disks (`ublkbN`) whose I/O is serviced by userspace daemons through `io_uring` passthrough commands. The driver handles device creation, parameter negotiation, block queue setup, daemon fetch/commit protocol, copy/user-copy/zero-copy data movement, shared-memory zero copy, zoned block operations, integrity metadata, user recovery, quiesce/stop/delete flows, and unprivileged-device permission policy.

Important APIs, types, and functions: Core state is held in `struct ublk_device`, `struct ublk_queue`, `struct ublk_io`, `struct ublk_uring_cmd_pdu`, `struct ublk_batch_fetch_cmd`, and `struct ublk_buf_range`. Public kernel integration points are `ub_fops`, `ublk_mq_ops`, `ublk_batch_mq_ops`, `ublk_ch_fops`, `ublk_ch_batch_io_fops`, and `ublk_ctl_fops`. Control commands are dispatched by `ublk_ctrl_uring_cmd()` into helpers such as `ublk_ctrl_add_dev()`, `ublk_ctrl_start_dev()`, `ublk_ctrl_del_dev()`, `ublk_ctrl_set_params()`, `ublk_ctrl_get_params()`, `ublk_ctrl_start_recovery()`, `ublk_ctrl_end_recovery()`, `ublk_ctrl_quiesce_dev()`, `ublk_ctrl_set_size()`, `ublk_ctrl_reg_buf()`, and `ublk_ctrl_unreg_buf()`. I/O commands are handled by `ublk_ch_uring_cmd_local()` or `ublk_ch_batch_io_uring_cmd()`, with request dispatch through `ublk_queue_rq()`, `ublk_queue_rqs()`, `ublk_batch_queue_rq()`, `ublk_batch_queue_rqs()`, `ublk_dispatch_req()`, `ublk_batch_dispatch()`, and completion through `__ublk_complete_rq()`.

Control flow: Device creation starts at `UBLK_CMD_ADD_DEV`: userspace passes `struct ublksrv_ctrl_dev_info`, the driver validates queue count/depth and feature combinations, allocates an idr id, blk-mq tag set, per-queue command buffers, per-queue `ublk_io` slots, optional batch event FIFOs, and finally adds a per-device character node. Userspace then sets parameters through `UBLK_CMD_SET_PARAMS`, mmaps the per-queue command buffers, and submits one fetch command for each queue/tag. `UBLK_IO_FETCH_REQ` stores the `io_uring_cmd`, daemon task, and buffer metadata into `struct ublk_io`; once all queue slots are ready `ublk_mark_io_ready()` completes `ub->completion`. `UBLK_CMD_START_DEV` waits for that completion, validates the daemon pid, creates a blk-mq disk with negotiated queue limits, applies capacity/zoned attributes, adds the disk, and optionally schedules an async partition scan.

I/O path: blk-mq calls `ublk_queue_rq()` or the batch variant. `ublk_prep_req()` checks fail/quiesce/cancel state, translates the block request into a userspace descriptor in the mmaped `ublksrv_io_desc` array via `ublk_setup_iod()`, and starts the request. Non-batch mode schedules task work on the stored daemon command; `ublk_dispatch_req()` either asks userspace for a write buffer (`UBLK_IO_RES_NEED_GET_DATA`), maps/copies write data into the daemon buffer, performs automatic io_uring bvec registration, or completes the fetch command so userspace sees a new request. Userspace replies with `UBLK_IO_COMMIT_AND_FETCH_REQ`, which records the result, updates the buffer address or zone append LBA, optionally unregisters auto-registered buffers, completes the previous request, and arms the same slot for a later request. Batch mode decouples request tags into a per-queue kfifo; multishot fetch commands pull tag arrays into selected buffers, while batch prep/commit commands walk user-provided element arrays to arm or complete many slots at once.

Data movement and zero-copy behavior: In the default mapped-buffer mode, `ublk_map_io()` copies write request pages into a daemon-provided userspace buffer, while `ublk_unmap_io()` copies read data back from that buffer on completion. `UBLK_F_USER_COPY` exposes `read_iter` and `write_iter` on the character device so the daemon can copy request data directly at encoded offsets; integrity metadata uses the same path with `UBLKSRV_IO_INTEGRITY_FLAG`. `UBLK_F_SUPPORT_ZERO_COPY` lets the daemon register request bvecs into io_uring buffers using `UBLK_IO_REGISTER_IO_BUF`/`UBLK_IO_UNREGISTER_IO_BUF`. `UBLK_F_AUTO_BUF_REG` performs that registration during dispatch and tracks whether the request needs userspace fallback. `UBLK_F_SHMEM_ZC` lets userspace register long-term pinned shared-memory buffers in `ublk_ctrl_reg_buf()`; registered PFN ranges are stored in a maple tree, and `ublk_try_buf_match()` marks matching request pages with a compact `ublk_shmem_zc_addr()` descriptor so no per-I/O page copy is needed.

State and persistence behavior: Persistent user-visible state is the created char device, block disk, sysfs/module parameter state, device number allocation, negotiated disk capacity and queue limits, and any pinned shared-memory registrations held for the device lifetime. Most internal state is volatile kernel state: per-slot command ownership flags (`ACTIVE`, `OWNED_BY_SRV`, `NEED_GET_DATA`, `AUTO_BUF_REG`, `CANCELED`), request references, daemon task pointers, device state (`LIVE`, `QUIESCED`, `FAIL_IO`, `DEAD`), queue cancel/fail/force-abort flags, and batch fetch state (`fcmd_head`, `active_fcmd`, `evts_fifo`). User recovery intentionally preserves the disk while daemon state is reset: daemon exit transitions the device to stopped, quiesced, or fail-I/O depending on recovery flags, then a later daemon can run start/end recovery after all fetch slots are reestablished.

Dependencies and integration points: The file is tightly integrated with blk-mq (`blk_mq_alloc_tag_set`, `blk_mq_alloc_disk`, queue freeze/quiesce, request batching, timeouts), gendisk lifecycle, `io_uring_cmd` passthrough and io_uring provided-buffer registration, kernel task work, block integrity, zoned block APIs (`blk_revalidate_disk_zones`, `disk_report_zone`, `REQ_OP_ZONE_*`), user memory pinning (`pin_user_pages_fast`), maple trees, idr/ida allocation, misc/char device registration, Linux permission checks, and UAPI definitions in `uapi/linux/ublk_cmd.h`. It also includes capability/owner checks for unprivileged devices and a module parameter (`ublks_max`) limiting unprivileged device creation.

Risks and edge cases: The driver is concurrency-sensitive because request completion, io_uring cancel, daemon file release, disk deletion, queue quiesce, recovery, and buffer unregister callbacks all touch the same per-slot state. Reference accounting for user-copy, zero-copy, and auto-buffer registration is subtle: `io->ref` and `task_registered_buffers` must sum to expected values across daemon death and completion, or requests can hang or complete after data structures are freed. Batch mode has extra races around `active_fcmd`, multishot CQE buffer selection, event kfifo reinsertion after partial dispatch failure, and cancellation of active versus queued fetch commands. Shared-memory zero copy pins long-term user pages and relies on queue freeze plus maple-tree locking to avoid PFN-range lookups racing with unregister. Unprivileged devices deliberately disable recovery and zero-copy/user-copy features, kill the daemon on timeout, and permanently suppress some partition scans to avoid deadlocks and privilege traps. Zoned and integrity support depend on precise feature negotiation and correct reuse of the command address field.

Test signals: Useful validation includes creating privileged and unprivileged devices, invalid feature-combination rejection, parameter validation for basic/discard/zoned/integrity/segment/dma limits, mmap size and owner checks, normal read/write/flush/discard/write-zeroes paths, `NEED_GET_DATA` write flow, user-copy read/write and integrity offsets, zero-copy buffer registration/unregistration from daemon and non-daemon tasks, auto-buffer fallback and unregister behavior, shared-memory registration/unregistration plus PFN match/mismatch cases, batch fetch/prep/commit/cancel flows, daemon crash with each recovery mode, quiesce timeout behavior, stop/try-stop/delete while disk is open, zoned report and zone append LBA handling, and request timeout behavior for unprivileged daemons.
