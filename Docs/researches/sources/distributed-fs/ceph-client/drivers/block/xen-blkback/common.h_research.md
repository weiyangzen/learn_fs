# sources/distributed-fs/ceph-client/drivers/block/xen-blkback/common.h

Purpose: This header defines the shared data structures, protocol adapters, constants, and cross-file declarations for the Xen block backend. It bridges Xen blkif wire formats, backend ring state, virtual block device metadata, persistent grant tracking, pending request bookkeeping, and the functions implemented by `blkback.c` and `xenbus.c`.

Important APIs, types, and functions: Protocol definitions include `struct blkif_common_request`, x86_32 and x86_64 packed request variants for rw/discard/other/indirect operations, `DEFINE_RING_TYPES()` instantiations, `union blkif_back_rings`, and `enum blkif_protocol`. Backend state types include `struct xen_vbd`, `struct persistent_gnt`, `struct xen_blkif_ring`, `struct xen_blkif`, `struct seg_buf`, `struct grant_page`, `struct pending_req`, and `struct phys_req`. Cross-file declarations include `xen_blkif_interface_init()`, `xen_blkif_interface_fini()`, `xen_blkif_xenbus_init()`, `xen_blkif_xenbus_fini()`, `xen_blkif_be_int()`, `xen_blkif_schedule()`, `xen_blkbk_free_caches()`, `xen_blkbk_flush_diskcache()`, `xen_blkbk_barrier()`, `xen_blkbk_xenbus()`, and `xen_blkbk_unmap_purged_grants()`.

Control flow: `xenbus.c` uses the declarations and structures here to create/configure a `struct xen_blkif`, open a backend VBD, allocate rings, negotiate protocol/features, and start one backend thread per `struct xen_blkif_ring`. `blkback.c` then consumes the ring union according to `blk_protocol`, turns requests into `pending_req` objects using the segment/grant arrays defined here, submits bios, and uses the declared Xenbus helpers to update feature state and retrieve the Xenbus device for resize notifications.

State and persistence behavior: `struct xen_vbd` stores user-visible backend device state: guest handle, read-only bit, type, physical device id, opened backend file, cached size, flush/discard/persistent-grant feature flags, and persistent-grant overflow status. `struct xen_blkif_ring` stores per-queue runtime state: irq, shared ring, ring lock, request wait queues, in-flight count, backend kthread, pending request pool, persistent grant rb-tree, grant page cache, purge/free work, stats, and shutdown wait queue. `struct xen_blkif` stores per-device state: domid, handle, protocol, VBD, backend pointer, refcount, drain completion, ring count/order, and all rings. `struct pending_req` stores all state needed to complete one frontend request after bios finish, including grant pages, indirect pages, segment geometry, bios, unmap operations, and async unmap callback data.

Dependencies and integration points: The header depends on Linux block, vmalloc, wait queue, rbtree, interrupt, module, and I/O headers; Xen grant table, Xen page, Xenbus, ring, blkif, and protocol headers; and architecture hypervisor setup headers. It defines constants derived from Xen page size, Linux page size, blkif segment limits, and indirect descriptor geometry. The `xen_blkif_get()`/`xen_blkif_put()` macros integrate reference release with scheduled work so final cleanup occurs asynchronously.

Risks and edge cases: The packed x86 protocol structures must match the ABI used by 32-bit and 64-bit frontends, including padding and alignment; mistakes would corrupt request decoding. Indirect segment constants must stay consistent with Xen blkif maximums and the advertised `feature-max-indirect-segments`. `XEN_PAGES_PER_SEGMENT` assumes Linux `PAGE_SIZE` is at least Xen page size and affects segment geometry on non-4K-page kernels. Fixed-size arrays in `pending_req` are sized by `MAX_INDIRECT_SEGMENTS` and `MAX_INDIRECT_PAGES`, so all request validation in `blkback.c` must enforce those bounds before filling arrays. Refcount macros schedule async free work, so code must not assume final destruction is synchronous.

Test signals: Compile coverage across native, x86_32, and x86_64 protocol support is important. Runtime tests should negotiate each protocol, submit normal and indirect requests at maximum segment counts, exercise different Linux page sizes where supported, validate persistent-grant feature negotiation and overflow state, verify refcount release schedules cleanup once, and confirm `xenbus.c` and `blkback.c` agree on ring, VBD, and pending request layouts.
