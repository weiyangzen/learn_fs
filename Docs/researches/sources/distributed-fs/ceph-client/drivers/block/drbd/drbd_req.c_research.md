# sources/distributed-fs/ceph-client/drivers/block/drbd/drbd_req.c

## Purpose
Implements the lifecycle of DRBD primary-node application requests originating from the block layer. It creates `struct drbd_request` objects, decides local versus remote service paths, inserts requests into transfer-log and interval-tree structures, submits cloned local bios, queues network send work, processes all local/network completion events through a centralized state machine, completes upper-layer bios, updates dirty/in-sync bitmap state, manages activity-log references, performs congestion pull-ahead decisions, and enforces request timeouts.

## Important APIs, Types, And Functions
- `drbd_req_new()` allocates and initializes a request from an incoming `bio`, including interval metadata, operation flags (`RQ_WRITE`, `RQ_UNMAP`, `RQ_ZEROES`), lists, completion ref, and kref.
- `drbd_req_destroy()` is the terminal destructor. It validates that no local/network/completion references remain, removes transfer-log and interval-tree membership, updates bitmap state for writes, completes activity-log I/O when needed, and frees the request mempool object.
- `complete_master_bio()` and `drbd_req_complete()` decide when and how to complete the upper bio, including success if either local or remote path succeeded, read retry via `RQ_POSTPONED`, statistics, transfer-log epoch rollover, and marking the interval completed.
- `mod_rq_state()` is the reference-accounting core. It applies state-bit changes, increments or decrements completion refs/krefs/ap counters, updates cached transfer-log cursors, records ack/done timestamps, and calls completion/destruction when possible.
- `__req_mod()` is the request event state machine. It maps events such as `TO_BE_SENT`, `QUEUE_FOR_NET_WRITE`, `HANDED_OVER_TO_NETWORK`, `WRITE_ACKED_BY_PEER`, `BARRIER_ACKED`, `DATA_RECEIVED`, `POSTPONE_WRITE`, `RESEND`, and local I/O completions to state-bit transitions and worker queueing.
- `drbd_request_prepare()`, `drbd_send_and_submit()`, `__drbd_make_request()`, and `drbd_submit_bio()` form the block-layer submission path.
- `do_remote_read()`, `drbd_may_do_local_read()`, `remote_due_to_read_balancing()`, `drbd_should_do_remote()`, and `drbd_process_write_request()` decide whether a request needs local disk, peer I/O, or out-of-sync notification.
- `complete_conflicting_writes()` and `maybe_pull_ahead()` manage multi-primary local write ordering and congestion-driven ahead/behind behavior.
- `do_submit()`, `submit_fast_path()`, `prepare_al_transaction_nonblock()`, and `send_and_submit_pending()` are the submitter worker path for requests that need activity-log transaction preparation or discard/zeroout handling.
- `request_timer_fn()` monitors oldest local and network requests and triggers disk detach or connection timeout state changes.

## Control Flow
The block layer calls `drbd_submit_bio()`, which splits to queue limits, increments application bio accounting, and delegates to `__drbd_make_request()`. `drbd_request_prepare()` allocates the DRBD request, starts I/O accounting, optionally clones a private bio for the local backing device, assigns `drbd_request_endio`, and tries the fast activity-log path for non-empty writes. Discards and write-zeroes, or writes that cannot enter the activity log immediately, are queued to the submit worker with `drbd_queue_write()` and return without synchronous send/submission.

Fast-path requests enter `drbd_send_and_submit()`. Under `resource->req_lock`, writes first wait for overlapping local writes to complete and may trigger congestion handling. Suspended I/O causes `RQ_POSTPONED` and drops any private bio. Reads are failed early if neither local nor remote good data is available; otherwise `do_remote_read()` may drop the local clone for remote-only reads or keep it based on bitmap validity and read-balancing policy. Non-empty requests are added to the transfer log with the current transfer-log epoch; writes increment the current epoch write count. Writes queue remote data, out-of-sync notification, or no remote path via `drbd_process_write_request()`. Reads queue `P_DATA_REQUEST` if remote-only, otherwise local submission is enough. Local private bios are added to pending-completion lists and marked `TO_BE_SUBMITTED` before submission outside the lock.

All significant changes go through `__req_mod()`. Events set intention bits (`RQ_LOCAL_PENDING`, `RQ_NET_PENDING`), queue bits (`RQ_NET_QUEUED`), sent/done/ok bits, protocol expectation bits, and special bits such as `RQ_EXP_BARR_ACK`, `RQ_POSTPONED`, or `RQ_COMPLETION_SUSP`. Network queue events install worker callbacks (`w_send_dblock`, `w_send_read_req`, `w_send_out_of_sync`) on `connection->sender_work`. Handoff events clear queued state and, for protocol A writes, optimistically set `RQ_NET_OK`. Peer ack events clear pending state and set network success; barrier ack finalizes network done for writes. Negative acks and connection loss clear success/pending and/or set done. Frozen I/O restart events requeue disk I/O through `w_restart_disk_io`.

Completion requires both local and network paths to be no longer pending/queued and no completion suspension. `drbd_req_complete()` reports success if either local or remote side succeeded; failed non-readahead reads with transfer-log membership are marked postponed for retry instead of completing the upper bio. Writes may close the current transfer-log epoch before completion. `drbd_req_put_completion_ref()` is the gate that calls completion only when the completion ref hits zero, restarts postponed requests, or drops the final kref.

Slow-path submitter flow batches activity-log work. `do_submit()` drains `device->submit.writes`, tries fast-path AL entry, otherwise waits for nonblocking AL transaction slots, handles busy extents separately, commits the AL transaction, then submits and sends pending requests under a block plug. This keeps AL persistence grouped without starving cold extents behind busy ones.

Timeout flow runs in `request_timer_fn()`. It reads current network timeout/ko-count and disk timeout, identifies oldest pending local read/write and oldest network request waiting for ack or barrier, checks jiffies wrap-safe windows and recent reconnect/reattach grace periods, transitions the connection to `C_TIMEOUT` on peer timeout, forces local detach on disk timeout, and reschedules itself for the nearest relevant deadline.

## State And Persistence
Request state is encoded in `req->rq_state` bits declared in `drbd_req.h`. Important persistent side effects include transfer-log epoch membership (`req->epoch`, `connection->current_tle_nr`, `current_tle_writes`), interval-tree membership in `device->write_requests` or `device->read_requests`, activity-log membership (`RQ_IN_ACT_LOG`), bitmap dirty/in-sync updates in `drbd_req_destroy()`, and pending counters (`ap_pending_cnt`, `ap_in_flight`, `ap_actlog_cnt`, local pending lists, master completion lists).

Reference lifetime is split between `completion_ref` and `kref`. Each local pending, network pending, network queued, completion suspension, and initial caller path owns completion references; `RQ_EXP_BARR_ACK` owns an extra kref until network done. `mod_rq_state()` is intentionally the single place that should change these references. The upper bio pointer is nulled only when completion is handed to `complete_master_bio()` outside the spinlock.

Local persistence safety depends on delaying `drbd_al_complete_io()` until both local and network obligations for mirrored writes are complete. Failed or only partially replicated writes set out-of-sync bits before destruction; successful writes that the peer marked in-sync can clear bits. Suspended or postponed writes avoid bitmap mutation until the request really progresses or fails.

## Dependencies And Integration Points
This file depends on Linux bio APIs, block plugging, timers, mempools, krefs, atomic counters, interval trees, RCU configuration reads, wait queues, workqueues, and jiffies time helpers. DRBD dependencies include `drbd_req.h` state/event definitions, `drbd_int.h` structures and counters, sender callbacks in `drbd_worker.c`, local bio completion `drbd_request_endio()`, transfer-log cleanup/restart in `drbd_main.c`, state helpers in `drbd_state.c`, bitmap and activity-log helpers in `drbd_bitmap.c`/`drbd_actlog.c`, and receiver ack handlers in `drbd_receiver.c` that call `req_mod()` events.

## Risks And Edge Cases
The highest risk is incorrect reference accounting in `mod_rq_state()`, which can leak a request, complete an upper bio too early, or destroy a request while local endio or ack handling can still arrive. Protocol differences are subtle: protocol A marks network success on send handoff, protocol B waits for receive ack plus barrier, and protocol C waits for write ack plus barrier. Suspended I/O, `RQ_POSTPONED`, and read retry paths deliberately keep requests alive without completing the original bio.

Other edge cases include overlapping multi-primary writes, congestion pull-ahead entering `C_AHEAD` and switching from full remote writes to out-of-sync notifications, empty flushes mapped to DRBD barriers, local disk loss after private-bio clone creation, discard/zeroout local errors not detaching the disk, bitmap-valid local reads from otherwise inconsistent disks, and jiffies wrap behavior in timeouts. Any list membership change must stay under `req_lock` because cleanup, sender cancellation, local endio, and ack_receiver can race.

## Test Signals
Useful signals include local-only reads/writes, remote-only reads, mirrored writes under protocols A/B/C, local read error followed by remote retry, failed readahead without retry, local write error with peer success, peer negative ack with local success/failure, empty flush completion through `QUEUE_AS_DRBD_BARRIER`, discard/write-zeroes slow path, AL-busy submitter batching, overlapping primary writes waiting or restarting, suspended I/O then `RESEND`/restart, connection loss transfer-log cleanup, congestion threshold entering ahead/disconnecting behavior, and request timer transitions for peer and disk timeouts.
