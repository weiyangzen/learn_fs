# sources/distributed-fs/ceph-client/drivers/block/drbd/drbd_receiver.c

## Purpose
Implements the DRBD receiver side of the replication protocol. This file owns connection establishment, feature/authentication negotiation, data-socket packet dispatch, meta-socket ack handling, incoming peer write/read/resync I/O, write-ordering epochs, bitmap exchange, UUID based resync decisions, split-brain recovery policy application, and connection teardown cleanup. It is the bridge between the wire protocol in `drbd_protocol.h`, request state transitions in `drbd_req.c`, lower block-device I/O, the resync bitmap/activity log, and the DRBD connection state machine.

## Important APIs, Types, And Functions
- `struct packet_info` is the decoded packet header carrier: command, payload size, volume number, and pointer to packet-specific data in the receive buffer.
- `enum finish_epoch` records whether `drbd_may_finish_epoch()` left an epoch alive, destroyed a non-current epoch, or recycled the current epoch.
- `drbd_alloc_pages()`, `drbd_alloc_peer_req()`, `drbd_free_peer_req()`, and `drbd_submit_peer_request()` allocate and submit peer-originated I/O buffers. Peer requests carry block id, interval, page chain, flags such as `EE_WRITE`, `EE_APPLICATION`, `EE_TRIM`, `EE_ZEROOUT`, `EE_SEND_WRITE_ACK`, and callbacks used after lower I/O completion.
- `drbd_try_connect()`, `prepare_listen_socket()`, `drbd_wait_for_connect()`, `conn_connect()`, `drbd_do_features()`, and `drbd_do_auth()` establish the data and meta sockets, resolve crossed connection attempts, negotiate protocol/features, and optionally run CRAM-HMAC authentication.
- `decode_header()`, `drbd_recv_header_maybe_unplug()`, `drbdd()`, and `drbd_cmd_handler[]` implement data-socket receive framing and command dispatch.
- `receive_Data()`, `receive_DataReply()`, `receive_RSDataReply()`, `receive_DataRequest()`, `receive_Barrier()`, `receive_bitmap()`, `receive_protocol()`, `receive_SyncParam()`, `receive_sizes()`, `receive_uuids()`, `receive_state()`, and `receive_sync_uuid()` are the main data-socket packet handlers.
- `drbd_may_finish_epoch()`, `drbd_flush()`, and `drbd_bump_write_ordering()` enforce or degrade write ordering across mirrored writes.
- `drbd_uuid_compare()`, `drbd_sync_handshake()`, `drbd_asb_recover_0p()`, `drbd_asb_recover_1p()`, and `drbd_asb_recover_2p()` decide whether to connect, resync, full-sync, or drop the link after UUID comparison and split-brain policy evaluation.
- `drbd_ack_receiver()`, `ack_receiver_tbl[]`, `got_BlockAck()`, `got_NegAck()`, `got_BarrierAck()`, `got_OVResult()`, `got_RqSReply()`, and `drbd_send_acks_wf()` process meta-socket pings, write/read acknowledgements, state-change replies, barrier acks, verify results, and delayed peer-request acks.

## Control Flow
The receiver thread starts in `drbd_receiver()`, repeatedly calls `conn_connect()` until a valid connection, unrecoverable incompatibility, or shutdown, then runs `drbdd()` on the data socket. `conn_connect()` opens both outgoing and listening sockets, assigns one to data and one to meta by exchanging `P_INITIAL_DATA` and `P_INITIAL_META`, handles simultaneous crossed connects with random retry, configures socket priorities/timeouts, negotiates features and authentication, sends protocol/configuration/state for every volume, transitions to `C_WF_REPORT_PARAMS`, starts the ack receiver, and creates the ordered ack-sender workqueue.

Data receive dispatch is table driven. `drbd_recv_header_maybe_unplug()` first tries a nonblocking header read; on empty receive buffers it quick-acks TCP and unplugs backend queues to reduce latency, then completes the read. `drbdd()` validates command number, fixed header size, optional payload allowance, and volume lookup before calling the relevant handler. Unknown non-optional packets or inconsistent lengths move the connection to protocol error.

Incoming mirrored writes enter `receive_Data()`. The handler verifies local disk access, receives the payload and optional integrity digest with `read_in_block()`, associates the request with the current write epoch, derives local bio flags from wire flags, sends early receive acks for protocol B semantics, handles two-primary sequence ordering/conflict resolution, queues the peer request on `active_ee` unless it is a synchronous trim/zeroout, waits for overlapping resync writes when sync target, protects local-only data by marking bitmap/activity-log state when peer disk is not usable, and submits the peer request. Completion later calls `e_end_block()` via `drbd_finish_peer_reqs()` to send `P_WRITE_ACK`, `P_RS_WRITE_ACK`, or `P_NEG_ACK`, remove interval-tree entries, restart postponed local conflicts, and release epoch activity.

Remote reads and resync reads are symmetric but distinct. `receive_DataReply()` finds a local application read request by block id and interval tree, receives the data directly into the original `master_bio`, validates optional digest, and raises `DATA_RECEIVED` in the request state machine. `receive_RSDataReply()` writes resync data to the local disk as a `sync_ee` peer request and sends `P_RS_WRITE_ACK` or `P_NEG_ACK` in `e_end_resync_block()`. `receive_DataRequest()` allocates a read peer request, handles application data requests, resync data requests, checksum resync requests, and online-verify requests, optionally throttles based on lower-device activity, calls `drbd_rs_begin_io()` for resync/verify extents, then submits lower read I/O whose worker callback sends the reply.

Write ordering uses epochs. Each incoming write increments `current_epoch->epoch_size` and `active`; `receive_Barrier()` records the peer barrier number and calls `drbd_may_finish_epoch()`. An epoch can be acknowledged only after all active writes complete and a barrier number is known, or during cleanup. Depending on configured ordering, the receiver may wait for all active peer I/O and submit lower-device flushes before acknowledging. If flush fails, `drbd_bump_write_ordering()` falls back from flush to drain or none according to backing-device capabilities.

Handshake and resync setup flow through protocol, sync params, sizes, UUIDs, state, bitmap, and sync-UUID packets. `receive_protocol()` verifies compatible protocol choices and split-brain policies, swaps a new RCU `net_conf`, and installs peer integrity digest state. `receive_SyncParam()` updates resync rate/planning fields and digest algorithms. `receive_sizes()` reconciles peer and local capacity, queue limits, online grow/shrink, and resize-triggered resync. `receive_uuids()` stores peer UUIDs and handles special initial-sync skip cases. `receive_state()` converts peer state into local perspective, invokes `drbd_sync_handshake()` when negotiation is needed, commits state via `_drbd_set_state()`, and persists metadata. `receive_bitmap()` merges plain or compressed peer bitmap data, sends the local bitmap when target, and starts resync when source.

The meta socket runs in `drbd_ack_receiver()`. It manages idle and ping timeouts, sends pings on demand, incrementally reads headers and fixed payloads, decodes commands through `ack_receiver_tbl[]`, and maps acks to request events. `got_BlockAck()` turns peer write/read/resync acks into `WRITE_ACKED_BY_PEER`, `RECV_ACKED_BY_PEER`, `CONFLICT_RESOLVED`, or `POSTPONE_WRITE`; `got_NegAck()` and negative reply handlers fail requests or resync I/O; `got_BarrierAck()` releases transfer-log epochs; state-change reply handlers wake waiters.

Teardown is centralized in `conn_disconnect()` and `drbd_disconnected()`: stop ack threads/workqueues, release sockets, wait for `active_ee`, `sync_ee`, and `read_ee`, cancel resync, flush sender work, finish queued peer requests, clear or keep the transfer log depending on suspension, sync metadata and bitmap, free peer UUIDs, and assert peer-request lists and page-pool counters are empty.

## State And Persistence
Persistent device/connection state touched here includes `connection->agreed_pro_version`, `agreed_features`, data/meta sockets, `net_conf` RCU pointer, digest transform/buffers, `current_epoch`, epoch list, `transfer_log` side effects through acks, `req_next`/ack tracking through request state, `p_uuid`, `p_size`, peer disk/role/connection state, bitmap bits, resync counters, online-verify counters, request timers, and metadata written by `drbd_md_sync()`.

Peer-request state is transient but critical: `active_ee`, `sync_ee`, `read_ee`, and `done_ee` lists track submitted incoming writes, resync writes, lower reads for peer replies, and completed requests awaiting ack-sender context. Page chains use `page->private`; `pp_in_use` counts receiver buffer pages. The code relies on `resource->req_lock`, `epoch_lock`, `peer_seq_lock`, RCU read sections, state mutexes, and workqueue context boundaries to keep these structures coherent.

Persistence-sensitive behavior includes setting out-of-sync bits on failed or unsafely replicated writes, clearing in-sync bits after acknowledged resync writes, writing the bitmap on disconnect, syncing metadata after state/size/UUID changes, preserving activity-log extents until both local and network sides are safe, and preventing thaw/resend when a peer reboot means old transfer-log assumptions are invalid.

## Dependencies And Integration Points
This file depends on kernel sockets, TCP options, bio submission, flush/discard/zeroout helpers, crypto shash/HMAC APIs, block queue limits, partition stats, mempools, workqueues, timers, RCU, wait queues, and DRBD interval trees. Internally it integrates with `drbd_req.c` via `req_mod()`/`__req_mod()` request events, with `drbd_main.c` for send helpers, transfer-log release/clear, bitmap send, socket allocation, and ack packets, with `drbd_worker.c` for lower-I/O completions and send/read callbacks, with `drbd_state.c` for state transitions and resync start/finish, with `drbd_bitmap.c` and `drbd_actlog.c` for bitmap/activity-log persistence, and with debug counters exposed elsewhere.

## Risks And Edge Cases
Packet-size validation, volume lookup, and digest handling are protocol-critical; a short read or malformed packet usually tears down the connection. Two-primary mode is especially sensitive: sequence-number waiting must order data and meta packets without deadlock, and conflict handling must correctly choose supersede, retry, postpone, or fail. Epoch/barrier handling is persistence-sensitive because acknowledging a barrier too early can allow activity-log extents to be dropped before data is stable on the peer.

Memory pressure is deliberate and dangerous: page allocations use `GFP_NOIO`/`GFP_TRY` to avoid recursive writeout in cross-replicated setups, but allocation failure usually forces reconnect. Discard/zeroout support has compatibility branches for older peers and unreliable backends. UUID comparison contains many historical protocol rules; wrong rule ordering can cause unnecessary full sync, missed split-brain, or connection to unrelated data. Teardown must drain multiple work/list paths in the right order or leave stale peer requests, page counters, or transfer-log requests.

## Test Signals
Useful signals include protocol feature negotiation across old/new header formats, authentication success/failure, simultaneous crossed data/meta connects, malformed packet lengths causing protocol error, mirrored write completion under protocols A/B/C, barrier ack after lower flush, fallback from flush to drain ordering, data-integrity digest mismatch, remote read retry completion, resync write ack and negative ack, compressed and plain bitmap receive, UUID rules for no-sync/bitmap-sync/full-sync/split-brain, two-primary conflicting writes producing superseded or retry acks, connection loss while suspended vs not suspended, and post-disconnect assertions that `active_ee`, `sync_ee`, `read_ee`, `done_ee`, `pp_in_use`, and `pp_in_use_by_net` are drained.
