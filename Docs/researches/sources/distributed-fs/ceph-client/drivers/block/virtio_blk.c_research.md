# sources/distributed-fs/ceph-client/drivers/block/virtio_blk.c

Purpose: This file implements the virtio block frontend driver. It binds to `VIRTIO_ID_BLOCK`, negotiates virtio block features, creates a blk-mq disk named with the legacy `vd*` scheme, maps Linux block requests into virtqueue scatter-gather commands, handles completion interrupts and polling, exposes serial/cache sysfs attributes, processes capacity changes, supports discard/write-zeroes/secure-erase/flush and host-managed zoned devices, and tears down or restores virtqueues across device removal, suspend, and virtio reset.

Important APIs, types, and functions: Core state is `struct virtio_blk`, `struct virtio_blk_vq`, and per-request `struct virtblk_req`. Request setup and submission are handled by `virtblk_setup_cmd()`, `virtblk_map_data()`, `virtblk_add_req()`, `virtblk_prep_rq()`, `virtio_queue_rq()`, `virtio_queue_rqs()`, and `virtio_commit_rqs()`. Completion paths are `virtblk_done()`, `virtblk_request_done()`, `virtblk_poll()`, and `virtblk_complete_batch()`. Configuration and lifecycle helpers include `virtblk_read_limits()`, `virtblk_update_capacity()`, `virtblk_config_changed_work()`, `init_vq()`, `virtblk_probe()`, `virtblk_remove()`, `virtblk_freeze_priv()`, and `virtblk_restore_priv()`. Sysfs/block operations are supplied through `virtblk_fops`, `serial_show()`, `cache_type_show()`, and `cache_type_store()`.

Control flow: On probe, the driver allocates an ida index, `struct virtio_blk`, virtqueues, a blk-mq tag set, and queue limits read from virtio configuration. Queue depth defaults to the virtqueue capacity, adjusted when indirect descriptors are unavailable, unless overridden by the `queue_depth` module parameter. The disk is named with `virtblk_name_format("vd", index, ...)`, marked read-only when the host advertises `VIRTIO_BLK_F_RO`, capacity is read, `virtio_device_ready()` enables virtqueue use, optional zoned revalidation runs, and `device_add_disk()` publishes the disk with sysfs attributes. Request submission translates `REQ_OP_*` operations into virtio type codes and sector fields, builds discard/write-zeroes/secure-erase range payloads when needed, maps block segments to an sg table, adds out header, data sg, and in status header to the selected virtqueue, and kicks the queue when the block layer marks the request as the last in a dispatch batch.

I/O and completion behavior: For reads, writes, flushes, discards, write zeroes, secure erase, zone management, zone append, zone report, and get-id commands, the request private data carries an out header, variable in header, sg table, and inline scatterlist storage. The status byte is always treated as the last byte of the in-header, allowing zone append to return a written sector plus status. `virtblk_done()` disables callbacks under the virtqueue lock, drains used descriptors with `virtqueue_get_buf()`, schedules blk-mq completion unless fake timeout is active, and restarts stopped queues. Poll queues have no interrupt callback and are drained by `virtblk_poll()`, which can batch successful completions through `io_comp_batch`. Cleanup frees mapped sg tables and special range payload allocations.

Zoned and limits behavior: With `CONFIG_BLK_DEV_ZONED`, `virtblk_read_zoned_limits()` accepts only host-managed zoned devices, rejects zero/non-power-of-two zone sizes and invalid append/write-granularity limits, sets `BLK_FEAT_ZONED`, zone limits, chunk sectors, and disables discard limits for zoned devices. `virtblk_report_zones()` allocates a bounded vmalloc report buffer, issues internal `REQ_OP_DRV_IN` zone report requests, parses virtio zone type/state descriptors into `struct blk_zone`, and feeds `disk_report_zone()`. `virtblk_setup_cmd()` translates Linux zone open/close/finish/append/reset/reset-all operations into virtio command types and records the append completion sector.

State and persistence behavior: Persistent visible state includes the allocated block major, disk minor range, disk capacity, read-only flag, queue limits, cache mode, serial sysfs value, and negotiated virtio feature set. Runtime state includes virtqueue pointers, per-queue locks, queue mapping counts for default/poll queues, the work item for capacity changes, and `vblk->vdev` guarded by `vdev_mutex` for paths that can run after removal. Capacity changes are processed asynchronously by `virtblk_config_changed_work()` and update the block layer with `set_capacity_and_notify()`. Cache mode sysfs writes modify virtio config WCE and commit updated queue write-cache features.

Dependencies and integration points: The driver depends on virtio core (`register_virtio_driver`, feature negotiation, config reads/writes, virtqueue allocation/reset/notify), blk-mq, gendisk/block queue limits, scatterlist allocation, sysfs device attributes, workqueues, ida minor allocation, zoned block APIs, and block-layer helpers for discard/write-zeroes/secure-erase ranges. It advertises legacy and modern feature tables; legacy excludes zoned support while modern includes `VIRTIO_BLK_F_ZONED`.

Risks and edge cases: Virtqueue locking must serialize add, kick, interrupt completion, and polling. Queue-stop/restart behavior is sensitive to `-ENOSPC` versus `-ENOMEM`: only virtqueue space exhaustion stops the hardware queue. Range payloads for discard/write-zeroes/secure-erase are dynamically allocated under atomic context and must be freed on every failure/completion path. Host-provided config values can be invalid; secure erase rejects zero alignment/sector/segment values, MQ rejects zero queue count, and zoned devices reject unsupported models or geometry. Removal/reset must flush config work, freeze/quiesce queues, reset the virtio device, delete virtqueues, and set `vblk->vdev = NULL` before freeing resources so late geometry or zone report paths return `-ENXIO` rather than dereferencing stale virtio state.

Test signals: Useful tests include single-queue and multi-queue probe, `num_request_queues` and `poll_queues` mapping, read/write/flush/discard/write-zeroes/secure-erase request translation, queue full and allocation-failure paths, interrupt and polling completions, fake timeout behavior, serial get-id success and unsupported `-EIO`, cache sysfs visibility and WCE updates, capacity-change work, host read-only devices, invalid virtio config values, zoned probe/report/append/reset flows, suspend/resume and reset_prepare/reset_done, and removal under concurrent config changes.
