# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/pm/powerplay/hwmgr/vega12_hwmgr.c

`vega12_hwmgr.c` is the main PowerPlay hardware-manager backend for Vega12 GPUs. It installs the Vega12 `pp_hwmgr_func` vtable, owns the Vega12 private backend state allocated at `hwmgr->backend`, translates kernel PowerPlay callbacks into SMU9 firmware messages, and coordinates dynamic power management, clocks, display constraints, fan control, thermal hooks, BACO integration, media block power gating, sensor reads, and GPU metrics export.

Important entry points are `vega12_hwmgr_init()`, `vega12_hwmgr_backend_init()`, `vega12_hwmgr_backend_fini()`, `vega12_enable_dpm_tasks()`, `vega12_disable_dpm_tasks()`, `vega12_power_off_asic()`, `vega12_force_clock_level()`, `vega12_dpm_force_dpm_level()`, `vega12_apply_clocks_adjust_rules()`, `vega12_read_sensor()`, `vega12_get_gpu_metrics()`, `vega12_get_ppfeature_status()`, and `vega12_set_ppfeature_status()`.

Initialization allocates `struct vega12_hwmgr`, fills registry defaults, sets capability flags, initializes SMU feature descriptors, reads the serial number into `adev->unique_id`, copies thermal/fan defaults, and decides whether the driver controls gfxoff. DPM enablement sets the allowed feature mask, uploads the parsed PPTable to SMU, runs ACG BTC, enables SMU features, clamps PCIe parameters to platform masks, applies power control, reads clock ranges, builds DPM tables from SMU-reported levels, and populates UMD pstate clocks. Display paths force UCLK high before reconfiguration, upload watermarks when pending, update display count, and request DCEF/deep-sleep display clocks.

State is volatile in `struct vega12_hwmgr`: DPM tables, golden DPM tables, feature flags, VBIOS boot state, cached metrics, watermarks, clock ranges, power-gating booleans, and registry defaults. Persistent inputs are VBIOS/ATOM tables and SMU firmware state. Integration is through the PowerPlay vtable, `vega12_pptable_funcs`, SMU message helpers, thermal helpers, ATOM firmware helpers, display-manager watermark data, and amdgpu device state.

Risks include firmware message sequencing, MHz/kHz/10 kHz conversions, feature-mask index alignment, unchecked DPM table counts, and `vega12_populate_umdpstate_clocks()` indexing `dpm_levels[count]` for peak clocks. Test signals: Vega12 boot/resume/unload, sysfs `pp_dpm_*` and `pp_features`, display hotplug/multi-monitor memory clocks, UVD/VCE power-gating, gfxoff toggling, GPU metrics, thermal start/stop, and PCIe link reporting.
