# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/gc/gc_9_4_1_offset.h

Purpose: generated AMDGPU GFX9.4.1 GC register-offset catalog. It gives the driver symbolic `mm*` register names and `*_BASE_IDX` segment selectors for the Arcturus-era GFX 9.4.1 graphics core, especially GRBM targeting/status registers and RAS/ECC counter registers used by `amdgpu/gfx_v9_4.c`.

Important APIs, types, and functions: this header exports preprocessor constants only. There are no C functions, types, or inline helpers. The important exported families are `mmGRBM_*` for graphics register bus manager control/status and instance selection, `mm*_EDC_*` registers for ECC/error detection counters across CP, GDS, SPI, SQ/SQC, TA/TD, TCP/TCI/TCC/TCA, GCEA, UTCL2/VML2, and RLC blocks, and the paired `*_BASE_IDX` constants. `mmGRBM_GFX_INDEX` is the key register for selecting SE/SH/instance views before indexed reads. `mmGCEA_ERR_STATUS` is the key fatal/status register consulted before reset. `mmATC_L2_*_DSM_*`, `mmVML2_*_ECC_*`, and `mmUTCL2_MEM_ECC_*` define indexed ECC status windows. The `*_BASE_IDX` values feed `SOC15_REG_ENTRY(ip, inst, reg)`, where `soc15.h` expands them into hardware IP, instance, segment, and register offset fields.

Control flow: the file itself has no executable control flow. Runtime flow is indirect: callers include this header, build `struct soc15_reg_entry` tables with `SOC15_REG_ENTRY(GC, 0, mm...)`, then use `RREG32_SOC15`, `WREG32_SOC15`, `SOC15_REG_ENTRY_OFFSET`, or RLC-shadowed writes to read or write the resolved MMIO address. In `gfx_v9_4.c`, `gfx_v9_4_edc_counter_regs[]` lists these offsets for reset/query walks, `gfx_v9_4_select_se_sh()` writes `mmGRBM_GFX_INDEX` to select a shader engine, shader array, or instance, and the RAS paths iterate the offset table to collect and reset ECC counters. For indexed UTCL2/VML2/ATC memories, the driver writes an `*_INDEX` register, reads the matching `*_CNTL`, then restores the index to 255.

State and persistence behavior: the header stores no state. The persistent state is the hardware MMIO register file and the graphics block counters/status bits those offsets address. Many exported registers are hardware counters for single-correctable and double-uncorrectable errors; writing or reading behavior is defined by the ASIC, not by this header. Software persistence is limited to compiled-in constants. A wrong offset or base index persists as a driver ABI bug until the generated header is fixed.

Dependencies: depends only on C preprocessing and the AMDGPU SOC15 register infrastructure. Consumers rely on `GC_HWIP` and the per-device `adev->reg_offset[hwip][inst][seg]` tables to turn these relative offsets into real addresses. The companion `gc_9_4_1_sh_mask.h` supplies field masks for many of the same registers. The register names are also coupled to AMD's generated ASIC register naming conventions; changing a name breaks `SOC15_REG_ENTRY` and `SOC15_REG_FIELD` users at compile time.

Integration points: directly included by `sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdgpu/gfx_v9_4.c` together with `gc_9_4_1_sh_mask.h`. There it backs GFX RAS ECC counter enumeration, counter reset/query, GRBM broadcast/index selection, UTCL2/VML2 memory ECC sweeps, and GCEA error-status harvesting before GPU reset. The same macro names also match cross-generation AMDGPU register helper patterns, so this file must stay aligned with `soc15.h` macros and with the generated mask header.

Risks and edge cases: register metadata is safety-critical because an incorrect offset can read the wrong hardware block, clear the wrong counter, or target only one segment instead of the intended broadcast/instance view. `mmTA_EDC_CNT` appears twice in two `gc_tpdec` address-block sections with the same value, which is harmless as an identical macro definition but is still a generated-header duplication to watch during regeneration. Base-index `0` versus `1` matters: GRBM scratch and many EDC counters use segment 0, while `gc_gfxudec` scratch/GRBM index and RLC counters use segment 1. Some registers are indexed windows, so tests must verify both index and data register offsets. Because this is generated metadata, manual edits are high-risk and should be avoided unless mirrored from the authoritative register source.

Test signals: strongest signals are build coverage of `gfx_v9_4.c`, compile-time resolution of every `mm*` macro used in `SOC15_REG_ENTRY`, and runtime RAS tests on GFX9.4.1 hardware or emulation. Useful runtime checks include successful GRBM broadcast restore to `0xe0000000`, correct per-instance counter traversal under `adev->grbm_idx_mutex`, ECC counter reset/query paths reading expected nonzero/zero values, and GCEA status warnings when `SDP_RDRSP_STATUS`, `SDP_WRRSP_STATUS`, or data-parity bits are injected. Static checks can diff the 101 register-offset definitions and their base indexes against the vendor-generated register database and against the companion mask file.
