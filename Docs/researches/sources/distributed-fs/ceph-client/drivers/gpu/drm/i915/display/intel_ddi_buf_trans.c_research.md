# sources/distributed-fs/ceph-client/drivers/gpu/drm/i915/display/intel_ddi_buf_trans.c

Purpose: provides the platform-, PHY-, output-, and link-rate-specific DDI buffer translation tables used to program voltage swing, pre-emphasis/de-emphasis, preshoot, cursor coefficients, scaling, and HDMI defaults. It also installs the correct `encoder->get_buf_trans` callback so `intel_ddi.c` and PHY-specific signal programming can translate a CRTC state and DP training set into the right table entry.

Important APIs/types/functions: the main exported API is `intel_ddi_buf_trans_init()`, which assigns the encoder callback. The only other exported helper is `is_hobl_buf_trans()`, used by combo PHY programming to detect the special eDP HOBL table. Static data dominates the file: Haswell/Broadwell/SKL/KBL/BXT tables for HSW-style DDI registers, ICL/EHL/JSL/TGL/RKL/ADL combo PHY tables, ICL MG PHY tables, TGL/ADLP DKL PHY tables, DG2/MTL SNPS tables, MTL C10/C20 tables, and XE3 LPD LT PHY tables. Static selector helpers include `use_edp_hobl()`, `use_edp_low_vswing()`, `intel_get_buf_trans()`, per-platform `*_get_buf_trans()` families, link-rate-specific DP/eDP helpers, HDMI/DP/eDP dispatch, UHBR detection, and the SKL port-entry clamp for DDIA/DDIE.

Control flow: `intel_ddi_buf_trans_init()` inspects display generation, platform flags, PHY type, and encoder type, then stores a function pointer in `encoder->get_buf_trans`. Later callers pass an encoder and `intel_crtc_state`; the selected callback chooses a const `intel_ddi_buf_trans` table and returns its `num_entries`. Selection primarily branches by output type (HDMI versus DP/eDP), eDP VBT policy (`low_vswing`, HOBL, and `hobl_failed`), port clock thresholds such as 270 MHz and 540 MHz, UHBR versus DP 1.4, combo versus Type-C/MG/DKL/SNPS/LT PHY, and platform variants such as SKL/KBL U/Y/H/S, JSL/EHL, TGL-UY, DG1, DG2, ADL-S, ADL-P, MTL C10/C20, and XE3 LPD. HDMI tables carry `hdmi_default_entry`; DP tables map training indices to table rows via `intel_ddi_level()` in `intel_ddi.c`.

State and persistence: all translation tables are static const data. Runtime state changes only through `encoder->get_buf_trans`; the selected table is not copied. HOBL and low-vswing decisions read persistent panel VBT state from `connector->panel.vbt.edp` and the runtime `intel_dp->hobl_failed` flag. The returned table pointer is consumed immediately by DDI/PHY programming and must match the union member expected by that platform's signal-level callback.

Dependencies and integration: integrates tightly with `intel_ddi.c` signal-level code, DP training (`intel_dp_is_uhbr()` and CRTC link parameters), VBT panel policy, encoder PHY classification (`intel_encoder_is_combo()`, C10/C20, LT PHY, Type-C), and platform detection in `intel_display`. The table entry union defined in `intel_ddi_buf_trans.h` lets HSW-style DDI, BXT DPIO, ICL combo, MG, DKL, SNPS, and LT PHY programming share one callback contract despite different register fields.

Risks: table contents are hardware tuning data, so off-by-one table sizes, wrong default HDMI entries, incorrect link-rate thresholds, or using a table with the wrong union member can produce failed link training, marginal signal integrity, HDMI failures, or panel-specific regressions. eDP HOBL/low-vswing decisions depend on VBT correctness and runtime fallback. SKL/KBL entry clamping differs for ports A/E versus other ports. New platforms must be added to both this selector and the corresponding PHY programming path; otherwise `encoder->get_buf_trans` may remain unset or return incompatible data. The final `MISSING_CASE()` only reports unknown PCI IDs and does not provide a safe generic table.

Test signals: validate DP link training across voltage/pre-emphasis combinations, HDMI at low and high TMDS rates, eDP panels with and without low-vswing/HOBL VBT flags, UHBR links, Type-C DP-alt/TBT modes, and all platform PHY families. Check that `intel_ddi_level()` never indexes past `num_entries`, HDMI defaults match expected BSpec presets, and fallback after HOBL failure selects a non-HOBL table. Regression tests should include display bring-up, suspend/resume, hotplug retraining, long cable/high-rate DP, and per-platform register traces confirming the expected union fields are programmed.
