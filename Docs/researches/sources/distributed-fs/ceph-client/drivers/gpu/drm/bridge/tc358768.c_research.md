# sources/distributed-fs/ceph-client/drivers/gpu/drm/bridge/tc358768.c

Purpose: implements the Toshiba TC358768/TC358778 DPI-to-DSI bridge as an I2C device that also registers a local MIPI DSI host. It accepts a parallel DPI input, generates a DSI video stream to a downstream DSI panel/bridge, handles panel command transfers while powered, and programs the bridge PLL and D-PHY timing from the active DRM mode.

Important APIs/types/functions: `struct tc358768_priv` stores device/regmap, reset GPIO, three regulators, refclk, enabled/error flags, local `mipi_dsi_host`, DRM bridge, downstream DSI output, input bus width, DSI lane/bpp parameters, PLL dividers, and cached DSI/pixel clocks. `tc358768_write()`, `tc358768_read()`, and `tc358768_update_bits()` wrap mixed-width regmap bulk accesses and accumulate the first error in `priv->error`; `tc358768_clear_error()` returns and clears it. `tc358768_calc_pll()` searches PRD/FBD/FRS values for the target DSI PLL clock. `tc358768_bridge_atomic_pre_enable()` is the main programming routine, deriving DSI byte timings, VSDLY, D-PHY counters, packet mode, data format, and control register state. `tc358768_dsi_host_transfer()` sends short or up-to-8-byte long write packets through `DSICMD_*` registers.

Control flow: I2C probe obtains regulators, refclk, optional reset GPIO, regmap, initializes the DSI host, sets bridge timings, and registers the host. When a downstream DSI device attaches, `tc358768_dsi_host_attach()` validates lanes, video mode, and RGB888 format, finds the downstream panel/bridge on `port@1`, records DSI bpp/lanes, reads the DPI input bus width from `port@0`, adds the DRM bridge, and waits for an upstream encoder to attach. Atomic pre-enable powers clocks/regulators/reset, software-resets the chip, obtains the adjusted mode from atomic state, programs the PLL, converts DPI horizontal timing into DSI byte counts, computes event or pulse mode timing, sets D-PHY counters and lane enables, starts the DSI transmitter, and configures `DSI_CONTROL`. Atomic enable clears frame stop/reset pointer and enables the parallel port; disable stops frame generation, clears PP enable, resets pointers, and post-disable powers the chip off.

State and persistence: `enabled` tracks power state across bridge and host-transfer paths. `error` batches write/read failures during programming so long register sequences can be checked once. PLL fields (`fbd`, `prd`, `frs`, `dsiclk`, `pclk`) persist after calculation and are used for timing conversions. Hardware state includes PLL registers, D-PHY counters, DSI timing registers, command FIFO registers, and PP/DSI control bits. Regmap has no cache and uses big-endian 16-bit register/value formatting, with helper logic treating some register ranges as 32-bit.

Dependencies and integration points: depends on DRM bridge atomic helpers, MIPI DSI host/device APIs, OF graph panel/bridge lookup, regulator bulk APIs, refclk, reset GPIO, regmap over I2C, Linux unit macros, and videomode conversion. It attaches downstream panels through `drm_bridge_attach()` and exposes input bus format based on `bus-width` or `data-lines`.

Risks: non-continuous DSI clock is warned and silently forced to continuous; only RGB888 is accepted in attach even though pre-enable contains switch cases for other formats. Horizontal timing/VSDLY formulas are explicitly heuristic, with comments noting uncertainty and possible underflows. Host transfers fail unless the bridge is currently enabled, which may affect panel command timing. Error aggregation can hide which individual register write failed. Regulator/clock enable failures are logged but `tc358768_hw_enable()` still sets `enabled = true`, so later register programming may proceed after a partial power-up. Mode support depends on exhaustive PLL search and refclk values.

Test signals: DSI host attach deferral; RGB888 video mode attach; command writes before/after enable; PLL calculation around supported clock ranges; event and sync-pulse DSI modes; VSDLY underflow warnings; regulator/refclk/reset sequencing on enable/disable; input bus format negotiation for 16/18/24-bit DPI; and visual stability across panels with short horizontal blanking.
