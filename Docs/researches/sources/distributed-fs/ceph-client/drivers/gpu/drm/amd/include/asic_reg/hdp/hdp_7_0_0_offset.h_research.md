# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/include/asic_reg/hdp/hdp_7_0_0_offset.h

Purpose: generated AMDGPU HDP 7.0.0 register-offset catalog. It defines the HDP 7 register address map for the `hdp_hdpdec` block at base address `0x3c80`, giving driver code symbolic `regHDP_*` constants and `*_BASE_IDX` values for MMHUB transaction metadata, aperture/flag registers, clock and power controls, XDP busy/error registers, MEMIO, D2H flush controls, P2P BAR/mailbox registers, XDP status, frame-buffer base, and GPU IOV violation logs.

Important APIs, types, and functions: this file exports constants only. There are no C functions, types, or storage. Key offsets include new front-of-block `regHDP_MMHUB_TLVL` at `0x0008` and `regHDP_MMHUB_UNITID` at `0x0009`; shared non-surface registers at `0x0040` through `0x0042`; surface/non-surface flags and clears at `0x00c4` through `0x00c9`; `regHDP_SW_SEMAPHORE`, `regHDP_DEBUG0`, and `regHDP_LAST_SURFACE_HIT`; HDP 7 control/status registers where `regHDP_OUTSTANDING_REQ` is `0x00d1`, `regHDP_HOST_PATH_CNTL` is `0x00d2`, `regHDP_CLK_CNTL` is `0x00d5`, `regHDP_MMHUB_CNTL` is `0x00d6`, `regHDP_XDP_BUSY_STS` is `0x00d7`, `regHDP_XDP_MMHUB_ERROR` is `0x00d8`, `regHDP_XDP_MMHUB_ERROR_CLR` is `0x00da`, and `regHDP_VERSION` is `0x00db`; MEMIO registers at `0x00f6` through `0x00fa`; XDP D2H/P2P registers from `0x0100` through `0x0145`; and GPU IOV violation logs at `0x0148` and `0x0149`. Every base index is `0`.

Control flow: the header itself has no control flow. `amdgpu/hdp_v7_0.c` includes it and uses `regHDP_CLK_CNTL` and `regHDP_MEM_POWER_CTRL` in the HDP clock/power-gating sequence. That runtime sequence reads clock and memory-power registers, sets clock overrides before modifying SRAM power controls, clears all LS/DS/SD enables, optionally enables one supported mode, sets the atomic/RC power control enables, and clears the clock override. The offset header decides which hardware addresses those SOC15 reads and writes reach. Generic HDP flush and diagnostics paths can use the XDP D2H, P2P, busy, error, and IOV offsets.

State and persistence behavior: the constants are compile-time metadata only. They address hardware state in HDP 7.0.0 registers: transaction-level IDs, non-surface aperture state, sticky flags, host-path controls, outstanding request counters, SRAM power modes, clock overrides, MMHUB attribute controls, busy/error/error-clear latches, MEMIO transaction state, D2H flush state, P2P BAR mappings, frame-buffer base location, and IOV violation records. Incorrect offsets persist in the compiled driver and can make otherwise correct field masks operate on the wrong register.

Dependencies: depends on AMDGPU SOC15 HDP register access infrastructure and the companion `hdp_7_0_0_sh_mask.h`. The `regHDP_*` names are consumed by `RREG32_SOC15`, `WREG32_SOC15`, and any `SOC15_REG_ENTRY` users. The header is selected through HDP IP version wiring in the AMDGPU discovery path and assumes `adev->reg_offset[HDP_HWIP][0][0]` points to the proper HDP 7 segment.

Integration points: directly included by `sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdgpu/hdp_v7_0.c`. That consumer uses `regHDP_CLK_CNTL` and `regHDP_MEM_POWER_CTRL` for `hdp_v7_0_update_clock_gating()` and `hdp_v7_0_get_clockgating_state()`, and registers those operations through `hdp_v7_0_funcs`. The offset map also supports the field groups in `hdp_7_0_0_sh_mask.h`, including HDP 7-specific `HDP_XDP_MMHUB_ERROR_CLR` and GPU IOV violation log fields.

Risks and edge cases: HDP 7.0.0 moves several offsets relative to HDP 6.0.0: `OUTSTANDING_REQ`, `HOST_PATH_CNTL`, `CLK_CNTL`, `MMHUB_CNTL`, busy/error, and version registers are not at the same addresses. Using HDP 6 offsets on HDP 7 hardware would direct clock/power or status operations to the wrong registers. `regHDP_XDP_BUSY_STS` is relocated to `0x00d7` rather than the HDP 6/5.2 position around `0x013e`, and HDP 7 adds an explicit error-clear register. Reserved D2H slots are present as named offsets but should not be treated as documented control registers. Since all base indexes are zero, any future split across SOC15 segments would require coordinated generated-header and access-layer validation.

Test signals: compile coverage of `hdp_v7_0.c` verifies the active clock/power register names. Static validation should compare every offset against the HDP 7.0.0 register database and specifically check the moved control/status offsets against HDP 6.0.0 to prevent accidental reuse. Runtime signals include successful HDP LS/DS/SD transitions, correct clock-gating state reporting, readable HDP version at `regHDP_VERSION`, correct XDP busy and MMHUB error/error-clear behavior, and IOV violation log fields matching injected SR-IOV or virtualization fault scenarios.
