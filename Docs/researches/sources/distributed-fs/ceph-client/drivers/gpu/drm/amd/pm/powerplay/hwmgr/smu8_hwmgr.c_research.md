# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/pm/powerplay/hwmgr/smu8_hwmgr.c

Purpose: SMU8 powerplay hardware-manager backend for Carrizo/Stoney APUs. It initializes AtomBIOS-derived platform data, patches and uploads SMU clock tables, manages SCLK/UVD/VCE/ACP DPM limits, handles power-state transitions, exposes clock/sensor callbacks, and registers the backend function table.

Important APIs and functions: `smu8_init_function_pointers()` installs `smu8_hwmgr_funcs`. `smu8_hwmgr_backend_init()` allocates backend state, sets defaults/caps, reads integrated system info, and builds boot state. `smu8_get_system_info_data()` parses AtomBIOS IntegratedSystemInfo revision 9. `smu8_upload_pptable_to_smu()` patches SMU SCLK/GFX/ACP/UVD/VCE breakdown tables from dynamic dependency tables and AtomBIOS PLL dividers. `smu8_setup_asic_task()`, `smu8_enable_dpm_tasks()`, `smu8_set_power_state_tasks()`, and `smu8_disable_dpm_tasks()` are the lifecycle path. Sensor/clock callbacks include `smu8_read_sensor()`, `smu8_emit_clock_levels()`, `smu8_get_clock_by_type()`, and `smu8_get_max_high_clocks()`.

Control flow and state: init allocates `struct smu8_hwmgr`, sets caps, reads BIOS data, and caches boot clocks. ASIC setup uploads tables and initializes DPM ranges. DPM enable programs voting clients, enables SCLK DPM, clamps boot SCLK, and populates UMD pstate clocks. Power-state transitions update SCLK limits from display requirements and stable-pstate policy, set deep-sleep/watermark thresholds, enable NB DPM, and manage low-memory pstate. Backend state tracks system info, DPM limits, power-gate booleans, DPM flags, CC6 settings, thermal limits, and cached max SCLK.

Dependencies and integration: depends on AtomBIOS, PP table helpers, SMU8 firmware messages, `SMU8_Fusion_ClkTable`, AMDGPU IP powergating/clockgating, platform caps, display config, thermal policy, and helper macros. Integrates through `pp_hwmgr_func` callbacks for power states, sensors, clocks, DAL power level, CAC buffer info, and UVD/VCE/ACP gating.

Risks and test signals: dependency-table bounds and firmware-reported levels must stay coherent; backend init can leak on partial failure; `smu8_dpm_get_sclk()` returns `-EINVAL` through `uint32_t`; several SMC send failures are ignored. Test boot/resume, table upload, DPM force levels, sensors, UVD/VCE playback/encode powergating, stable/UMD pstate, CC6 messages, and SMC failure injection.
