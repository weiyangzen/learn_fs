# sources/distributed-fs/ceph-client/drivers/gpu/drm/drm_drv.c

Purpose: implements the DRM core's device-instance lifecycle, minor-node allocation/registration, hot-unplug protection, internal pseudo-filesystem inode support, device wedged uevents, cgroup memory-region registration, and module-level DRM core initialization/exit. It is the central bridge between bus-specific DRM drivers, userspace character devices, sysfs/debugfs, accel nodes, GEM initialization, modeset registration, and managed `drm_device` cleanup.

Important APIs/types/functions: global state includes `drm_minors_xa`, `drm_core_init_complete`, `drm_unplug_srcu`, the pseudo-fs mount counters `drm_fs_cnt`/`drm_fs_mnt`, and the DRM char-device stub fops. Minor helpers `drm_minor_get_xa()`, `drm_minor_get_slot()`, `drm_minor_alloc()`, `drm_minor_register()`, `drm_minor_unregister()`, `drm_minor_acquire()`, and `drm_minor_release()` manage `struct drm_minor` objects for primary, render, and accel nodes. Public lifecycle APIs include `drm_put_dev()`, `drm_dev_enter()`, `drm_dev_exit()`, `drm_dev_unplug()`, `drm_dev_set_dma_dev()`, `__devm_drm_dev_alloc()`, `__drm_dev_alloc()`, `drm_dev_alloc()`, `drm_dev_get()`, `drm_dev_put()`, `drm_dev_register()`, and `drm_dev_unregister()`. Support APIs include `drm_dev_wedged_event()`, `drmm_cgroup_register_region()`, and compat-control symlink creation/removal. Module entry/exit are `drm_core_init()` and `drm_core_exit()`.

Control flow: core init initializes connector IDs and memcpy helpers, creates the DRM sysfs class/debugfs root, registers the DRM major with `drm_stub_fops`, initializes accel/panic/privacy/RAS support, then marks the core ready. Device init requires that flag, takes references on the parent device, initializes krefs/lists/locks/managed resources, rejects drivers that claim both compute accel and graphics features, allocates an anonymous inode from the internal pseudo-fs, allocates required minors, initializes GEM when requested, stores `dev->unique`, and initializes per-device debugfs. Minor allocation reserves legacy primary/render ranges first and falls back to extended minors, while accel uses its own range; registration adds debugfs, adds the sysfs device, then publishes the xarray entry so opens can find it. Device registration validates modeset config for non-legacy load drivers, registers debugfs, registers render/primary/accel minors, creates the legacy `controlD*` symlink for modeset primary nodes, marks the device registered, optionally invokes deprecated `driver->load`, registers all modeset objects, and registers panic/sysrq clients. Unregistration reverses those user-visible registrations, invokes unload when present, unregisters minors, removes links, and finalizes debugfs. The char-device open path acquires a minor by inode minor number, grabs the driver's real fops, replaces the file fops, and delegates to the driver's open callback. Hot-unplug sets `dev->unplugged`, synchronizes SRCU readers, unregisters the device, and invalidates CPU mappings from `dev->anon_inode`.

State and persistence: `struct drm_device` lifetime is kref-managed and commonly embedded in driver-private containers freed through `drmm_add_final_kfree()`. Managed resources attached with `drmm_*` live until final `drm_dev_put()`, which is distinct from bus-device devres lifetime and is important for userspace-visible objects that may outlive physical unbind. Minor objects are allocated as managed resources and stay tied to device lifetime, but their xarray entries are set to `NULL` when inactive. The xarrays, DRM major registration, sysfs/debugfs roots, accel state, panic/privacy/RAS state, pseudo-fs mount, connector ID allocator, and `drm_core_init_complete` are module-global state. `dev->unplugged`, `dev->registered`, `dev->unique`, `dev->anon_inode`, `dev->dma_dev`, minor slots, locks, and lists persist across normal operation until managed release. The pseudo-fs inode gives DRM a real `address_space` for mmap tracking; it is freed in the device init release action.

Dependencies and integration: depends on Linux xarray, kref, device model, sysfs/debugfs, pseudo-fs/VFS, SRCU, cgroup device-memory registration, uevents, module init/exit, and DRM subsystems such as GEM, modeset, connector IDs, panic, privacy screen lookup, RAS generic netlink, accel, sysrq client support, managed resources, and debug logging. Driver-facing integration is through `struct drm_driver` feature bits, fops, optional `load`/`unload`/`release`, GEM and modeset helpers, `devm_drm_dev_alloc()`/Rust allocation wrappers, and bus-specific probe/remove paths. Userspace integration is through `/dev/dri/*` and accel char devices, sysfs minor devices and compatibility control symlinks, debugfs, kobject uevents for wedged devices, and mmap invalidation on unplug.

Risks: registration ordering is security- and race-sensitive because xarray publication makes nodes openable; publishing before full initialization or failing to unpublish on error can expose inconsistent driver state. Deprecated `driver->load` runs after device nodes are visible, so legacy users must tolerate userspace races. Hot-unplug correctness depends on every hardware-touching path using `drm_dev_enter()`/`drm_dev_exit()` and avoiding devres-managed hardware resources outside protected regions. Minor allocation must preserve legacy numbering expectations while handling extended minors and accel-major separation. Error unwinds must remove debugfs/sysfs/minors/control links symmetrically. `drm_dev_wedged_event()` assumes a primary minor/kdev for the uevent target. The pseudo-fs and anonymous inode bookkeeping must pair every pin/allocation with release. Lifetime mistakes around `dev->dev`, `dev->dma_dev`, managed resources, and final kfree can produce use-after-free or leaks, especially with open files during unbind.

Probe/remove representative display, render-only, and accel drivers; verify `/dev/dri/card*`, `/dev/dri/renderD*`, accel minors, sysfs devices, debugfs directories, and `controlD*` symlinks appear and disappear correctly. Exercise open while unregistering, open after unregistering, hot unplug with active mmap/open files, driver probe error unwinds at each minor/debugfs/sysfs stage, deprecated `load` failure, and modeset registration failure. Validate reference leaks with kref/debug object tooling, lockdep/SRCU coverage, `WARN_ON(!xa_empty(&drm_minors_xa))` on module exit, wedged uevent payloads for valid/unknown recovery flags, DMA device reference replacement, and cgroup region unregister on final device release.
