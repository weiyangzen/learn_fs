# sources/distributed-fs/ceph-client/drivers/gpu/drm/amd/amdkfd/kfd_device.c

`kfd_device.c` is the AMD KFD device lifecycle bridge between amdgpu/KGD and the HSA compute runtime. It probes whether an `amdgpu_device` has a supported KFD GFX target, initializes device-wide shared resources, creates one or more `kfd_node` objects for XCP/partitioned devices, starts queue managers, and exposes reset, suspend/resume, interrupt, eviction, scheduler, and debug entry points back to amdgpu.

Important entry points are `kgd2kfd_probe`, `kgd2kfd_device_init`, `kgd2kfd_device_exit`, reset hooks, suspend/resume hooks, `kgd2kfd_interrupt`, MM eviction/resume hooks, scheduler halt/unhalt helpers, and `kgd2kfd_vmfault_fast_path`. Internal helpers fill `kfd->device_info`, select CWSR trap images, initialize per-node interrupts/DQM/GWS/topology/SMI, and provide a bitmap GTT suballocator.

Probe maps ASIC/IP versions to `kfd2kgd_calls` and compiler target versions. Device init validates PCI atomics, derives VMID ranges, handles CPX partition VMID splitting, allocates shared GTT memory, initializes doorbells, CWSR, and nodes, then sets `init_complete`. Reset/suspend uses `kfd_locked` to block process execution while queues are unsafe. Interrupts are filtered by node and queued to IH work. Persistent state includes `kfd->nodes`, shared resources, `gtt_sa_bitmap`, doorbell state, `compute_profile`, firmware versions, and lock counters.

Dependencies include amdgpu firmware/IP helpers, `amdgpu_xcp`, topology, DQM, interrupts, doorbells, SVM, SMI, CWSR trap blobs, GPUVM eviction fences, and debugfs. Risks are stale version tables, VMID partitioning assumptions, lock reference imbalance, GTT fragmentation, interrupt cleanup races, and PCI-atomics gating. Test with supported GC families, multi-XCP modes, reset/suspend with active queues, PCI atomics rejection, allocation failure injection, IH routing, debugfs HWS hang, eviction fence replay, and teardown waiting for process counts.
