# sources/distributed-fs/ceph-client/mm/slab.h

Purpose: internal header for Linux slab/SLUB allocator implementation. It defines the in-memory layout overlay between `struct slab` and `struct page`, cache metadata structures, boot state, kmalloc cache lookup helpers, debug/sysfs hooks, object metadata helpers, memcg slab hooks, initialization-on-alloc/free policy helpers, and internal allocator function prototypes.

Important APIs/types/functions: key structures include `struct freelist_counters`, `struct slab`, `struct kmem_cache_order_objects`, `struct kmem_cache_per_node_ptrs`, `struct kmem_cache`, `enum slab_state`, `struct slabinfo`, and `struct kmem_obj_info`. Important helpers include `slab_folio`, `page_slab`, `slab_page`, `slab_address`, `slab_nid`, `slab_pgdat`, `virt_to_slab`, `slab_order`, `slab_size`, `cache_has_sheaves`, `nearest_obj`, `__obj_to_index`, `obj_to_index`, `objs_per_slab`, `kmalloc_slab`, `is_kmalloc_cache`, `is_kmalloc_normal`, `kmem_cache_debug_flags`, `metadata_access_enable/disable`, `slab_obj_exts`, `get_slab_obj_exts`, `put_slab_obj_exts`, `slab_set_stride`, `slab_get_stride`, `slab_obj_ext`, `cache_vmstat_idx`, `large_kmalloc_order`, `large_kmalloc_size`, `slab_want_init_on_alloc`, `slab_want_init_on_free`, and `slub_debug_orig_size`.

Control flow: allocation code uses `kmalloc_slab` to map request size, bucket set, GFP flags, and caller into a kmalloc cache. Slab/page conversion helpers let allocator and diagnostics move between folio/page/slab/object views. Debug and metadata paths use `metadata_access_enable/disable` to suppress KASAN/KMSAN reports while touching allocator-private bytes. When `CONFIG_SLAB_OBJ_EXT` is enabled, callers read the encoded extension pointer from the slab, bracket access with get/put helpers, compute per-object metadata by index and stride, and rely on `alloc_slab_obj_exts` to provision extension storage. Init-on-alloc/free helpers combine static branch defaults, constructors, RCU-safe slabs, poisoning, and `__GFP_ZERO` to decide when the allocator should clear memory.

State and persistence behavior: this header describes long-lived allocator state owned by slab implementation files: global `slab_state`, `slab_mutex`, `slab_caches`, `kmem_cache`, kmalloc cache tables, and per-cache fields such as object size, alignment, free-pointer offset, sheaves, partial settings, constructors, sysfs object, hardening random value, NUMA nodes, random sequences, KASAN/usercopy/debug/stat metadata, and per-node pointers. `struct slab` reuses first-page fields and is guarded by static assertions so layout changes in `struct page` do not silently break allocator metadata.

Dependencies and integration points: depends on page/folio layout, reciprocal division, list_lru, local locks, random/hardening, kobjects/sysfs, memcg, KFENCE, KASAN/KMSAN, hardened usercopy, SLUB debug, KUnit, RCU freeing, allocation profiling, and vmstat slab counters. It provides prototypes consumed by `slab_common.c`, SLUB implementation files, sysfs/debugfs slab views, memcg hooks, usercopy checks, and kfree_rcu sheaf support.

Risks: layout overlay between `struct page` and `struct slab` is fragile; incorrect offsets or alignment can corrupt allocator state. Freelist ABA protection depends on architecture cmpxchg width and aligned `struct page`; fallback behavior must remain correct. Object index math depends on reciprocal size and tag stripping, with KFENCE special-casing. Metadata extension pointers are encoded with memcg flags and must not be dereferenced without masking and KASAN/KMSAN bracketing. Init-on-free/alloc decisions interact with constructors, poisoning, and RCU-safe caches; clearing at the wrong time can break object lifetime or hide debug signals.

Test signals: build coverage across 32-bit/64-bit, cmpxchg128/cmpxchg64, SLUB debug, KASAN/KMSAN/KFENCE, memcg, object extensions, hardened usercopy, sysfs, and tiny SLUB configurations is important. Runtime signals include slabinfo/sysfs correctness, KUnit slab tests, freelist hardening tests, KASAN/KMSAN absence around metadata access, kmalloc size-class selection checks, memcg slab charging/freeing tests, and boot-time static assertion success for page/slab layout.
