# sources/distributed-fs/ceph-client/mm/mmu_gather.c

Purpose: provides the generic `mmu_gather` implementation used to batch page freeing, rmap removal, page-table freeing, and TLB invalidation during unmap, exit, mprotect/userfaultfd write-protect, and other page-table teardown paths. It amortizes expensive TLB shootdowns while preserving architecture and software page-table-walker safety.

Important APIs/types/functions: `tlb_gather_mmu`, `tlb_gather_mmu_fullmm`, `tlb_gather_mmu_vma`, `tlb_finish_mmu`, `tlb_flush_mmu`, `tlb_flush_rmaps`, `__tlb_remove_folio_pages`, `__tlb_remove_page_size`, `tlb_remove_table`, `tlb_remove_table_sync_one`, and `tlb_remove_table_sync_rcu`. Key types are `mmu_gather`, `mmu_gather_batch`, `mmu_table_batch`, encoded page pointers, `mm_struct`, `vm_area_struct`, `folio`, and page-table descriptor/table pointers.

Control flow: `__tlb_gather_mmu` initializes an on-stack gather, local page batch, table batch, page-size/range metadata, and increments `mm` pending TLB flush state. Page removal encodes pages plus flags such as delayed rmap and multi-page counts into the active batch; when the batch fills, `tlb_next_batch` either advances to an existing batch, allocates another page of batch storage, or forces a flush. `tlb_flush_mmu` performs the architecture TLB flush and then frees batched tables/pages. `tlb_finish_mmu` detects nested batched PTE modifications and forces fullmm/range reset when needed, flushes, frees secondary batches, and decrements pending flush state. Table freeing either batches tables, defers through RCU callbacks, synchronizes via IPI/RCU for lockless walkers, or falls back to immediate single-table freeing when allocation fails.

State and persistence: all state is transient in `mmu_gather` and its allocated batch pages. The visible lasting effects are freed physical pages/page tables, updated rmap state, and cleared pending TLB flush counters in the target `mm`. It does not persist data to disk. RCU callbacks may delay actual freeing beyond the caller's critical section.

Dependencies and integration points: integrates with architecture `asm/tlb.h` hooks, page allocator, swap cache freeing, rmap (`folio_remove_rmap_ptes`), hugetlb page sizes, RCU, SMP IPI synchronization, page poisoning/init-on-free policies, PT reclaim, nested TLB flush detection, and MM unmap paths such as `exit_mmap`, `mprotect`, `munmap`, and userfaultfd operations.

Risks: freeing page tables before all hardware/software walkers are excluded can produce use-after-free; missing a required TLB flush can leave stale translations; delayed rmap batching must not span unsupported batch chains; multi-page encoded entries must stay paired when chunking free batches; and nested gather users can require broader flushes than the original range. Allocation failure in table batching must still make forward progress without weakening synchronization.

Test signals: unmap/exit/mremap/mprotect stress under SMP, lockless GUP and page-table-walker tests, page poisoning/init-on-free configurations, hugetlb and THP unmap workloads, nested page-table modifications from concurrent userfaultfd or mprotect, and architecture TLB selftests. Runtime warnings in `tlb_finish_mmu`, page-size assertions, and KASAN/KCSAN reports are strong signals.
