# sources/distributed-fs/ceph-client/mm/shmem.c

Purpose: implements Linux shmem/tmpfs, the swap-backed in-memory filesystem used for tmpfs mounts, SysV/shared anonymous memory, memfd-style anonymous files, and `/dev/zero` shared mappings. In full `CONFIG_SHMEM` builds it adds resource accounting, quotas, swap-out/swap-in, transparent hugepage and multi-size THP support, NUMA mempolicy, userfaultfd hooks, xattrs/ACLs/casefolding, file operations, and mount option parsing. In `!CONFIG_SHMEM` builds it falls back to tiny-shmem backed by ramfs.

Important APIs/types/functions: key local types are `struct shmem_falloc` for coordinating hole punch/fallocate with faults and `struct shmem_options` for fs-context mount state. Important exported/common APIs include `shmem_mapping`, `vma_is_anon_shmem`, `vma_is_shmem`, `shmem_inode_acct_blocks`, `shmem_recalc_inode`, `shmem_charge`, `shmem_uncharge`, `shmem_add_to_page_cache`, `shmem_truncate_range`, `shmem_unuse`, `shmem_writeout`, `shmem_get_folio`, `shmem_lock`, `shmem_get_unmapped_area`, `shmem_init_fs_context`, `shmem_init`, `shmem_kernel_file_setup`, `shmem_file_setup`, `shmem_file_setup_with_mnt`, `shmem_zero_setup`, `shmem_zero_setup_desc`, `shmem_read_folio_gfp`, and `shmem_read_mapping_page_gfp`. Core operation tables are `shmem_aops`, `shmem_file_operations`, inode op tables for regular/dir/symlink/special inodes, `shmem_ops`, `shmem_vm_ops`, `shmem_anon_vm_ops`, `shmem_fs_context_ops`, and `shmem_fs_type`.

Control flow: file and anonymous mapping faults enter `shmem_fault`, optionally wait on a concurrent punch-hole `shmem_falloc`, then call `shmem_get_folio_gfp`. That central lookup path checks file size, handles userfaultfd minor/missing faults, resolves xarray swap entries through `shmem_swapin_folio`, locks cached folios, or allocates new folios through `shmem_alloc_and_add_folio`. Allocation first chooses allowable hugepage orders using mount policy, sysfs/boot THP policy, VMA hints, and page-cache conflicts, then charges memcg, inserts into the mapping xarray, charges tmpfs blocks/quota, updates inode accounting, and links the folio to LRU. Swap-out flows through `shmem_writeout`: it refuses locked/noswap/no-swap cases, splits large folios when THP swap or EOF constraints require it, allocates swap, increments swapped accounting, adds the inode to `shmem_swaplist`, replaces the file-cache folio with a swap entry, and writes the folio to swap. Swapoff calls `shmem_unuse`, scans `shmem_swaplist`, finds matching swap entries, and pulls them back with `shmem_swapin_folio`.

Control flow continued: truncation and hole punching use `shmem_undo_range` to remove page-cache folios and swap entries, handle partial large-folio boundaries by zeroing or splitting, and reconcile inode block accounting. `shmem_fallocate` supports allocation and punch-hole modes; punch-hole installs a stack `struct shmem_falloc` in `inode->i_private` so racing faults sleep rather than refilling the punched range, while allocation walks the target page indexes with `SGP_FALLOC` and rolls back newly added non-uptodate folios on failure. File reads and splice reads call `shmem_get_folio` with `SGP_READ`, copy real folios or zero-filled holes, and handle hwpoisoned subpages specially for large folios. Writes go through generic write checks plus `shmem_write_begin`/`shmem_write_end`, which enforce seals and mapping freeze, instantiate folios, zero partial new folios, mark dirty, and extend `i_size`.

State and persistence behavior: all file data lives in RAM or swap, not persistent storage. Persistent-in-memory state is split across `struct shmem_sb_info` and `struct shmem_inode_info`: superblocks hold block/inode limits, `used_blocks`, `free_ispace`, uid/gid/mode, `huge` policy, mempolicy, noswap, quota defaults, inode-number batching, and a shrinklist for unused portions of large folios; inodes hold allocated/swapped page counts, seals, flags, fallocate extent end, xattrs, mempolicy, shrinklist/swaplist links, directory offsets, and stop-eviction coordination. The mapping xarray stores either folios or encoded swap/poison entries, with large entries carrying an xarray order. Accounting must keep `info->alloced`, `info->swapped`, `mapping->nrpages`, tmpfs counters, overcommit accounting, memcg charges, and quota reservations synchronized under their respective locks.

Dependencies and integration points: this file integrates with VFS (`fs_context`, superblock/inode/file operation tables, export handles, idmapped mounts), mm (`folio`, xarray page cache, LRU, reclaim, swap cache, memcg, rmap, userfaultfd, NUMA mempolicy, THP/mTHP), security (`security_vm_enough_memory_mm`, LSM xattr initialization), quota (`shmem_quota_operations`, `dquot_*`), writeback/swap (`swap_writeout`, swapoff), sysfs/boot params for THP policy, Unicode/casefold support, simple directory-offset helpers, and ramfs for tiny-shmem fallback. It also exports setup helpers used by IPC, memfd-style users, DRM/GPU memory managers, tmpfs mounts, and shared anonymous mmap paths.

Risks: the highest-risk paths are races between truncate/hole punch, page faults, swapin/swapout, large xarray entries, and inode eviction. Large folio and multi-size THP handling must avoid data corruption when a large swap entry is split, when swapin returns a smaller folio, or when only part of a folio is inside `i_size`. Resource accounting errors can leak or double-charge tmpfs blocks, quota, memcg, swap entries, or overcommit reservations. Mount reconfiguration deliberately rejects retroactive limits and noswap/quota transitions that cannot be made safe. `inode->i_private` fallocate coordination relies on stack lifetime and `i_lock`/wake discipline. Sysfs and boot THP policy changes affect allocation behavior globally, so incorrect policy parsing or mask updates can cause unexpected allocation pressure.

Test signals: useful coverage comes from tmpfs and mm selftests, fstests exercising tmpfs truncate, fallocate, xattrs, ACLs, casefold, quota, rename, tmpfile, and remount behavior, swapoff/swap stress, THP/mTHP tmpfs tests, userfaultfd shmem tests, memfd seal tests, syzkaller-style truncate/fault/write races, and LTP SysV shared memory tests. Runtime signals include `statfs` block/inode accounting, `/proc/meminfo` shmem/swap counters, `VM_FAULT_MAJOR`, THP fallback/allocation events, `THP_SWPOUT_FALLBACK`, `MTHP_STAT_SHMEM_*`, WARNs in inode eviction, and failures from `shmem_add_to_page_cache`/`shmem_confirm_swap` race paths.
