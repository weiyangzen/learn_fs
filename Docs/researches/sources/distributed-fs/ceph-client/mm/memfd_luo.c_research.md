# sources/distributed-fs/ceph-client/mm/memfd_luo.c

Purpose: adds Live Update Orchestrator file preservation support for shmem-backed memfds across kexec handover. It serializes selected memfd properties and page-cache folios into KHO-preserved memory before kexec, freezes the file, and reconstructs a new anonymous memfd with the same contents, size, file position, and supported seals in the next kernel. Hugetlb-backed memfds are intentionally unsupported because `can_preserve` only accepts `shmem_file(file)`.

Important APIs/types/functions: the preservation pipeline is implemented by `memfd_luo_preserve()`, `memfd_luo_freeze()`, `memfd_luo_unpreserve()`, `memfd_luo_finish()`, `memfd_luo_retrieve()`, `memfd_luo_can_preserve()`, and `memfd_luo_get_id()` in `memfd_luo_file_ops`. Folio helpers include `memfd_luo_preserve_folios()`, `memfd_luo_unpreserve_folios()`, `memfd_luo_discard_folios()`, and `memfd_luo_retrieve_folios()`. Serialized ABI structures come from `linux/kho/abi/memfd.h`, notably `struct memfd_luo_ser`, `struct memfd_luo_folio_ser`, `MEMFD_LUO_ALL_SEALS`, `MEMFD_LUO_FOLIO_DIRTY`, and `MEMFD_LUO_FOLIO_UPTODATE`. Registration happens in `memfd_luo_init()` with `liveupdate_register_file_handler()`.

Control flow: preservation locks the inode, calls `shmem_freeze(inode, true)`, allocates preserved metadata with `kho_alloc_preserve()`, reads and validates memfd seals with `memfd_get_seals()`, records file position, size, and seals, rejects files whose page count would exceed `memfd_pin_folios()` limits, and calls `memfd_luo_preserve_folios()`. The folio preserve helper pins all folios from byte 0 to size - 1 using `memfd_pin_folios()`, which also allocates pages for holes and swaps pages back in. It then preserves each folio with `kho_preserve_folio()`, locks it, marks it dirty, zeroes and marks non-uptodate folios uptodate, records PFN/index/flags, preserves the serialized folio array with `kho_preserve_vmalloc()`, and returns the array as private data while leaving it in preserved memory.

Control flow: freeze runs later and updates only `ser->pos`, because file position may have changed after prepare. Unpreserve is the abort path in the old kernel: it unlocks shmem freeze, unpreserves the vmalloc array and every preserved folio, unpins folios, frees serialized metadata, and unlocks the inode. Finish is a post-kexec cleanup path in the new kernel for entries not retrieved; it restores the serialized vmalloc array, discards preserved folios via `kho_restore_folio()` and `folio_put()`, frees the array, and releases serialized metadata.

Control flow: retrieval maps serialized metadata with `phys_to_virt()`, validates seal compatibility, creates a fresh memfd with `memfd_alloc_file("", MFD_ALLOW_SEALING)`, reapplies seals through `memfd_add_seals()`, restores file position with `vfs_setpos()`, and writes inode size. If folios are present, it restores the serialized vmalloc array and calls `memfd_luo_retrieve_folios()`. Retrieval of each folio restores it from its PFN, sets locked and swapbacked state, charges it with `mem_cgroup_charge()`, inserts it into shmem page cache with `shmem_add_to_page_cache()`, restores uptodate/dirty flags, accounts inode blocks via `shmem_inode_acct_blocks()`, adds it to LRU, unlocks and drops the temporary reference, and finally recalculates shmem inode accounting. On error it removes the current folio from cache if inserted and releases not-yet-added preserved folios.

State and persistence: the only preserved properties are file contents, file size, file position, `O_RDWR|O_LARGEFILE` status from the recreated memfd, and seals supported by `MEMFD_LUO_ALL_SEALS`. Sparse holes are not preserved as holes; they are materialized as zeroed folios during preservation. Clean folios are deliberately marked dirty to prevent post-restore reclaim from dropping user data, and non-uptodate folios are zeroed and marked uptodate. `FD_CLOEXEC`, original name, hugetlb backing, link state beyond anonymous shmem, and other file properties are reset. Serialized metadata lives in KHO-preserved memory addressed by physical pointers across kexec.

Dependencies and integration: depends on Live Update/KHO file handler APIs, KHO preserved allocation/vmalloc/folio APIs, shmem freeze and page-cache helpers, memfd creation and sealing helpers from `memfd.c`, memcg charging from `memcontrol.c`, VFS file position/size helpers, folio locking/dirty/uptodate/LRU APIs, dcache flushing for zeroed folios, and the `linux/kho/abi/memfd.h` compatibility contract. It registers a late-init liveupdate file handler with compatibility string `MEMFD_LUO_FH_COMPATIBLE`, and identifies preservable files by inode pointer.

Risks: preservation intentionally densifies sparse files, which can cause memory spikes and alter hole behavior after restore. Dirtying every folio protects data but may increase reclaim/writeback pressure after live update. File mutation windows are subtle: preserve locks and freezes shmem, while freeze updates only position later; any property not explicitly frozen or serialized is reset. Restore must correctly charge memcg and account shmem blocks or the new kernel can see leaked pages, bad memory accounting, or reclaim anomalies. Error paths are complex because ownership transitions from KHO-preserved folios to page cache; failures after partial insertion rely on file teardown for inserted folios and explicit `folio_put()` for the rest. Seal compatibility is versioned and rejects unknown bits with `-EOPNOTSUPP`. The handler currently excludes hugetlb memfds despite generic memfd support elsewhere.

Test signals: targeted tests should preserve and retrieve empty, small, multi-page, sparse, dirty, and fallocated-but-not-uptodate memfds across LUO/kexec; verify file size, contents, position, and supported seals; confirm unsupported seals and huge files fail; confirm hugetlb memfds are rejected by `can_preserve`; inject failures in KHO allocation, folio preservation, memcg charging, page-cache insertion, and block accounting; verify abort paths unfreeze and unpin; and inspect memcg/shmem accounting and LRU state after restore. Runtime diagnostics include `pr_err()` for pin, file setup, seal, folio restore, charge, page-cache, and block-accounting failures plus rate-limited warnings for discard failures.
