# sources/distributed-fs/ceph-client/mm/mprotect.c

Purpose: implements `mprotect`, `pkey_mprotect`, protection-key allocation/free syscalls, and the lower-level page-table/VMA protection update machinery used by mprotect-like operations, NUMA balancing, and userfaultfd write protection. It updates VMA flags, page protections, commit accounting, MMU notifier ranges, and TLB gather state while preserving COW, soft-dirty, uffd-wp, THP, hugetlb, and PFN permission semantics.

Important APIs/types/functions: `can_change_pte_writable`, `change_protection`, `mprotect_fixup`, `mprotect`, `pkey_mprotect`, `pkey_alloc`, and `pkey_free`. Major internal helpers include `change_pte_range`, `change_pmd_range`, `change_pud_range`, `change_p4d_range`, `change_protection_range`, `change_present_ptes`, `change_softleaf_pte`, `mprotect_folio_pte_batch`, `prot_none_walk_ops`, and `do_mprotect_pkey`. Key types are `mmu_gather`, `vm_area_struct`, `vma_iterator`, page-table entries at all levels, `folio`, `page`, `mm_walk`, `pgprot_t`, `vma_flags_t`, and protection-key state.

Control flow: syscall entry normalizes tagged/page-aligned input, growth flags, read-implies-exec, lengths, pkey validity, and architecture protection validation before taking `mmap_write_lock`. It walks contiguous VMAs in the requested range, checks permissions (`VM_MAY*`), W^X denial, architecture flag validity, LSM `security_file_mprotect`, and optional `vm_ops->mprotect`. `mprotect_fixup` rejects sealed VMAs, performs PFN modify checks for PROT_NONE transitions, charges private writable mappings when needed, modifies/splits/merges VMA flags, starts VMA write synchronization, recalculates `vm_page_prot`, and calls `change_protection`. Page-table walkers descend through pgd/p4d/pud/pmd/pte levels, split huge mappings when required for uffd markers, populate page tables for uffd-wp markers, notify secondary MMUs for pud-level changes, batch compatible folio PTEs, handle migration/device-private/marker soft entries, and flush through the supplied `mmu_gather`.

State and persistence: persistent process state includes VMA access flags, pkeys, `vm_page_prot`, soft-dirty/uffd-wp PTE bits and markers, dirty/write PTE state, memory accounting (`VM_ACCOUNT`, `total_vm` category counters), and pkey allocation bits in `mm_struct`. No disk data is written. TLB flush state is transient but required for correctness after PTE permission changes.

Dependencies and integration points: integrates with pagewalk, hugetlb, THP splitting, swap/migration entries, mmu notifiers, perf mmap events, mempolicy, pkeys, LSM hooks, architecture cache/TLB/protection validators, KSM, userfaultfd, PFNMAP/MIXEDMAP permission checks, and `mmu_gather` from `mmu_gather.c`. VMA sealing from `mseal.c` directly blocks changes here.

Risks: PTE writability optimization must not bypass COW, writenotify, soft-dirty, or uffd-wp requirements. Huge-page splitting and uffd marker population can return `-ENOMEM` mid-walk. Commit-accounting transitions for private writable mappings must unwind on VMA modification failure. MMU notifier boundaries must cover changes visible to secondary MMUs. Sealed VMAs must return `-EPERM`. Protection-key syscalls must not expose unallocated pkeys.

Test signals: `mprotect`/`pkey_mprotect` syscall tests, protection-key selftests, W^X policy tests, userfaultfd write-protect tests, soft-dirty tests, NUMA balancing PROT_NONE scanning, THP/hugetlb mprotect tests, PFNMAP/MIXEDMAP device mappings, locked private mapping population, and mmu notifier/KVM invalidation stress. Runtime signals include TLB flush warnings, lockdep, and perf mmap events after VMA changes.
