# sources/distributed-fs/ceph-client/rust/syn/gen/visit.rs

## Purpose
Generated Syn traversal support for walking a shared borrow of a syntax tree. It defines the `Visit<'ast>` trait, default visit methods for each AST node type, and free `visit_*` functions that recursively descend into child nodes. Consumers implement or override selected trait methods to inspect Rust syntax without mutating the AST.

The file is generated by `syn-internal-codegen` and is part of Syn's visitor API rather than Ceph client runtime logic. Its behavior is a schema-level traversal of Syn AST nodes with feature gates matching the `derive` and `full` surfaces.

## APIs, Types, and Functions
The central API is `pub trait Visit<'ast>`. It contains 188 default `fn visit_*(&mut self, i: &'ast ...)` hooks. Most defaults call the corresponding free function, such as `visit_expr(self, i)`, so implementors can override one hook and delegate back to the default traversal when desired.

The module also exposes 187 free `pub fn visit_*<'ast, V>(v: &mut V, node: &'ast ...) where V: Visit<'ast> + ?Sized` traversal functions. These functions cover AST families for ABI declarations, attributes, generics, expressions, fields, files, items, impl items, trait items, statements, patterns, paths, types, literals, macros, visibility, where clauses, and use trees.

Important helper macros are:

- `full!($e)`: evaluates `$e` under `feature = "full"` and becomes `unreachable!()` under `derive` without `full`, used for enum variants that exist in a shared type but should not be visited in derive-only mode.
- `skip!(...)`: intentionally discards punctuation, delimiter, keyword, and some token fields that do not have visitor callbacks.

`Punctuated::pairs` from `crate::punctuated` is used to traverse comma- or separator-delimited lists by value nodes while separators are skipped.

## Control Flow
Traversal is depth-first and read-only. A caller invokes a trait method such as `visitor.visit_file(&file)` or a free function such as `visit_file(&mut visitor, &file)`. The default method forwards to the free function, and the free function visits child AST nodes by calling more trait methods. This callback-through-trait pattern lets overridden methods intercept, stop, count, or customize traversal at any node type.

Struct-like traversal functions visit fields in AST schema order, usually attributes first, then identifiers, generics, paths, types, expressions, blocks, and nested lists. Optional fields are handled with `if let Some(...)`; boxed fields are dereferenced with `&*` or `&**`; punctuated collections iterate over `Punctuated::pairs`; plain vectors iterate by reference.

Enum traversal functions dispatch to the matching visitor hook. Examples include `visit_expr`, `visit_item`, `visit_type`, `visit_pat`, `visit_lit`, `visit_generic_argument`, `visit_trait_item`, `visit_impl_item`, `visit_foreign_item`, and `visit_use_tree`. Verbatim variants call `visit_token_stream`, while identifiers and indexes route to `visit_span` where appropriate. The default `visit_span` and `visit_token_stream` bodies are no-ops, so callers must override them if spans or raw macro tokens matter.

## State and Persistence Behavior
The module has no persistent global state. State lives entirely in the visitor implementor's `&mut self`: counters, symbol tables, diagnostics, collected references, or early-exit flags are all user-owned. The `'ast` lifetime ties visited references to the borrowed AST and prevents visitors from storing invalid references unless their own type encodes the same lifetime.

Because the traversal is shared-borrow based, it does not mutate, allocate, or rewrite the AST. It also intentionally skips many punctuation and keyword tokens via `skip!`, so default traversal state reflects semantic child nodes more than exact token trivia. Macro bodies and other verbatim token streams are not recursively parsed; they are surfaced as token streams only.

## Dependencies and Integration
The file depends on Syn AST definitions, `crate::punctuated::Punctuated`, `proc_macro2::{Ident, Span, TokenStream}`, and feature-gated AST availability. It is compiled differently under:

- `full`, where complete Rust files, items, statements, blocks, patterns, loops, closures, and many expression variants are traversable.
- `derive`, where derive-input structures and shared expression/type fragments are available.
- `derive` without `full`, where `full!` marks full-only enum variants as unreachable.

Consumers integrate by implementing `Visit<'ast>` for their own analysis type and overriding hooks such as `visit_item_fn`, `visit_expr_path`, `visit_type_path`, `visit_attribute`, or `visit_macro`. Generated defaults make it easy to continue recursive descent by calling the corresponding free `visit_*` function from an override.

## Risks and Edge Cases
The visitor only sees what Syn parsed into structured nodes. Macro bodies, verbatim items/types/expressions/patterns, and token streams are opaque unless the visitor overrides `visit_token_stream` and parses or inspects tokens manually. The default no-op span and token-stream hooks can surprise analyses that expect source-location or macro-token coverage.

The traversal is generated from the AST schema, so manual edits risk desynchronization with Syn's actual data model. Feature-gated branches are another risk: a visitor tested only with `full` may not compile or may miss paths in `derive`-only builds. The `full!` macro uses `unreachable!()` for derive-only mode, which is correct only if upstream feature gating prevents those variants from occurring. Very deep syntax trees can recurse deeply through visitor calls and may hit stack limits in pathological inputs.

## Test Signals
Strong signals include compiling Syn with `visit`, `derive`, and `full` combinations, running Syn's visitor tests, and testing custom visitors against representative Rust files. Good targeted tests count visits for nested modules, attributes, generics, where predicates, expression trees, patterns, macro invocations, verbatim nodes, and token streams. Regression checks should verify overridden hooks can delegate to free `visit_*` functions without losing traversal, and that `visit_span` is reached from identifiers and indexes when span collection is expected.
