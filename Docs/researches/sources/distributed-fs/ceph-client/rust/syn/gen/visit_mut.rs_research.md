# sources/distributed-fs/ceph-client/rust/syn/gen/visit_mut.rs

## Purpose

`gen/visit_mut.rs` is generated support code for Syn's in-place mutable AST traversal API. It defines the `VisitMut` trait and a corresponding free `visit_*_mut` function for every supported syntax-tree node. The default trait methods recursively walk child nodes, while callers override selected methods to transform identifiers, spans, expressions, types, items, attributes, generics, or other AST components.

The file is public traversal infrastructure rather than parser logic. It is generated by `syn-internal-codegen`, which keeps the visitor surface aligned with Syn's AST definitions and feature flags. It is used by downstream procedural macros and code transformation tools that need to mutate a parsed `syn` tree without rebuilding it manually.

## Important APIs, Types, and Functions

- `pub trait VisitMut` is the main extension point. Each method receives `&mut self` and `&mut Node`, and defaults to calling the matching free traversal function.
- `visit_*_mut<V>(v: &mut V, node: &mut crate::Node)` functions implement recursive traversal for concrete node types using `V: VisitMut + ?Sized`.
- `visit_attributes_mut` is a trait default method over `Vec<Attribute>` and visits every attribute in place.
- `visit_ident_mut` is one of the few non-feature-gated hooks; it extracts an identifier span, calls `visit_span_mut`, and writes the span back with `set_span`.
- `visit_lifetime_mut` visits both the apostrophe span and inner identifier, which makes lifetime renaming and span rewriting possible.
- `visit_token_stream_mut` and `visit_span_mut` default to no-op hooks. Transformations that need to rewrite verbatim tokens or spans must override them.
- `full!` maps full-only recursive calls to real traversal when `feature = "full"` is enabled and to `unreachable!()` for derive-only builds where those variants should not occur.
- `skip!` documents fields intentionally left untouched, mostly punctuation/token marker fields such as braces, commas, keywords, and delimiters.

Major traversal families include expressions, patterns, types, items, trait and impl items, use trees, attributes/meta, literals, fields, generics, where predicates, paths, ABI/signature nodes, derive `Data`, and full-file/module structures.

## Control Flow

The central control flow is dynamic dispatch through `VisitMut`. A caller invokes a visitor method such as `visitor.visit_file_mut(&mut file)`. Unless overridden, the trait method calls `visit_file_mut(visitor, file)`, which visits attributes and then each item. Enum visitors dispatch on variants and call more specific visitor methods. Struct visitors visit semantically mutable child nodes and skip punctuation.

Traversal is depth-first and in-place. For sequence fields backed by `Punctuated`, the code uses `Punctuated::pairs_mut` and visits each pair value while preserving punctuation. For `Vec` fields it iterates with `for it in &mut node.items` or similar. For boxed nodes it dereferences through `&mut *box_field`, and for optional nodes it guards with `if let Some`.

Generated enum dispatch matters for feature-gated ASTs. `visit_expr_mut` covers common expression variants under `derive` and `full`, while full-only expression forms such as `ExprIf`, `ExprLoop`, `ExprMatch`, and statement/item traversal are guarded by `#[cfg(feature = "full")]`. In derive-only builds, the `full!` macro preserves match completeness for shared enums while asserting that full-only variants are unreachable.

## State and Persistence Behavior

This file does not persist external state, allocate durable data, or perform I/O. All state mutation happens on the caller-provided AST and optional visitor-owned state. Default traversal preserves syntax tokens and punctuation by skipping token marker fields. It mutates spans only if the visitor overrides `visit_span_mut`, and mutates identifiers indirectly by allowing their span to be rewritten.

Because traversal is in-place, visitor overrides can replace subtrees, reorder collections, or mutate child fields before or after delegating to default traversal. The generated functions themselves do not clone or snapshot nodes; changes are immediately visible to later traversal of the same tree.

## Dependencies and Integration Points

The file depends on Syn AST types re-exported under `crate::*`, `crate::punctuated::Punctuated`, and `proc_macro2::{Ident, Span, TokenStream}`. It is part of Syn's visitor module surface and integrates with all AST modules that define items, expressions, types, generics, paths, attributes, literals, and tokens.

Downstream integration is through implementations of `VisitMut` in procedural macros and tooling. Internally, correctness depends on the Syn code generator tracking AST field additions, enum variants, and feature flags. It also integrates with `docsrs` documentation cfg annotations.

## Risks and Edge Cases

- The file is generated. Manual edits are likely to be lost and can desynchronize traversal from the AST definitions.
- Token fields are skipped by design. A visitor that expects keyword, delimiter, comma, or punctuation spans to change will not get that behavior unless it rewrites larger nodes itself.
- `visit_token_stream_mut` is a no-op, so verbatim nodes and macro token bodies are not recursively parsed or transformed by default.
- `visit_ident_mut` only delegates through the identifier span, not the identifier text. Renaming requires overriding `visit_ident_mut` itself.
- Feature-gated traversal must stay aligned with AST availability. A missed `cfg` can break derive-only or full-only builds.
- Mutating collections while recursively iterating them from an override can invalidate assumptions made by default traversal if not done carefully.

## Test Signals

Useful signals include Syn's own feature-matrix build and test suite with `derive`, `full`, `visit-mut`, `parsing`, and `printing` combinations. Procedural macro tests that rename identifiers, rewrite lifetimes, change spans, and mutate nested expressions/types exercise the public behavior. Regenerating the file with `syn-internal-codegen` and diffing it against the checked-in version is the strongest signal that traversal matches current AST definitions.
