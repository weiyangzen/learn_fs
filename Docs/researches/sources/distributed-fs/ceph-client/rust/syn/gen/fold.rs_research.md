# sources/distributed-fs/ceph-client/rust/syn/gen/fold.rs

## Purpose

`fold.rs` is generated by `syn-internal-codegen` and implements syn's owned syntax-tree transformation API. It defines the `Fold` trait plus default `fold_*` functions that consume AST nodes, recursively transform their children, and return rebuilt nodes. It is the owned-tree counterpart to visit-style traversal: callers override selected methods to rewrite identifiers, spans, expressions, types, items, literals, token streams, or other syntax nodes.

The generated default behavior is identity-preserving traversal. A `Fold` implementation that overrides nothing returns an equivalent tree, except it still routes identifiers, lifetimes, literals, spans, and token streams through their default fold hooks.

## Important APIs, Types, and Functions

The central API is `pub trait Fold`. It contains one method per foldable syntax type, for example `fold_expr`, `fold_type`, `fold_item`, `fold_pat`, `fold_generics`, `fold_attribute`, `fold_lit`, `fold_ident`, `fold_lifetime`, `fold_span`, and `fold_token_stream`. Most trait methods default to the free function with the same name, such as `fold_expr(self, i)`.

The generated free functions implement the recursive traversal. Struct node folders rebuild the node while folding child fields and preserving punctuation/token marker fields. Enum node folders match each variant, call the corresponding trait method for payload variants, and reconstruct the same enum variant. Collections are handled through `crate::punctuated::fold` for `Punctuated` fields and the private `fold_vec` helper for `Vec<T>`.

Important leaf hooks include:

- `fold_ident`, which folds an identifier's span through `fold_span` and then calls `set_span`.
- `fold_lifetime`, which folds the lifetime apostrophe span and identifier.
- literal folders such as `fold_lit_str`, `fold_lit_int`, and `fold_lit_bool`, which preserve literal values while routing spans through `fold_span`.
- `fold_span`, whose default returns the span unchanged.
- `fold_token_stream`, whose default returns raw `proc_macro2::TokenStream` unchanged.

The file defines a `full!` macro to bridge feature differences. With `feature = "full"`, `full!(expr)` evaluates `expr`; with `derive` but not `full`, it expands to `unreachable!()`. This lets shared enum dispatch mention full-only variants while still compiling in derive-only builds where those variants are not constructible in practice.

## Control Flow

The normal control flow starts when a caller invokes a trait method on a root node, such as `folder.fold_file(file)`, `folder.fold_derive_input(input)`, `folder.fold_expr(expr)`, or `folder.fold_type(ty)`. The default trait method calls the matching free function. That free function consumes the node, pattern matches or destructures it, calls more `f.fold_*` methods on children, and returns a rebuilt node.

Recursive control is deliberately virtual at every child edge. For example, `fold_expr` dispatches by expression variant and then calls methods like `f.fold_expr_binary`, `f.fold_expr_call`, `f.fold_expr_struct`, or `f.fold_token_stream` for `Expr::Verbatim`. `fold_type` similarly dispatches to `fold_type_array`, `fold_type_path`, `fold_type_reference`, or `fold_token_stream` for `Type::Verbatim`. This allows an override at either a broad enum level or a narrow struct level.

Struct folders preserve syntax markers while transforming semantic children. `fold_impl_item_const` folds attributes, visibility, identifier, generics, type, and expression while preserving tokens such as `const_token`, `colon_token`, `eq_token`, and `semi_token`. `fold_macro` folds macro path, delimiter, and raw tokens. `fold_signature` folds identifiers, generics, function arguments, variadic arguments, and return type.

Optional and boxed fields are handled inline with `map` and `Box::new`, while tuples preserve token components and fold AST components. Vectors and punctuated sequences are consumed and collected into new containers. The traversal order follows field order, so overrides with internal state observe a deterministic pre-order over each node's fields.

## State and Persistence Behavior

The file itself stores no global or persistent state. All state is held by the user-provided `Fold` implementor passed as `&mut F`. That mutable folder can count nodes, maintain rename maps, record diagnostics, or carry configuration while the generated traversal drives it.

The traversal consumes owned syntax nodes and returns new owned syntax nodes. It does not mutate files on disk, perform I/O, allocate beyond normal reconstruction/collection, or persist results except through the returned tree and any side effects intentionally stored in the folder. Boxed children are unboxed, folded, and re-boxed. Vectors and punctuated containers are iterated and collected.

Default span behavior is identity. Span persistence can change only if a folder overrides `fold_span`, `fold_ident`, literal folders, or token-stream handling. Raw `Lit::Verbatim` is notably returned unchanged by the generated `fold_lit` default, while other verbatim AST containers route through `fold_token_stream`.

## Dependencies and Integration Points

`fold.rs` is exposed from `syn/lib.rs` behind the `fold` feature. Many node folders are additionally gated by `derive` or `full`, mirroring the AST availability model. It depends on `proc_macro2` for `Ident`, `Span`, and `TokenStream`; on syn AST types under `crate::*`; and on `crate::punctuated::fold` for comma/plus/pipe separated syntax lists.

The module is an integration point for procedural macro authors and internal syn tooling that need structural rewrites: identifier renaming, span normalization, literal rewriting, type or path substitution, expression lowering, attribute filtering, macro-token rewrites, or whole-item transformations. It also integrates with generated visitor modules by sharing the same AST taxonomy and feature gates.

Because all free functions are public, callers can use them from custom overrides to continue default recursion after making a local change. A typical override mutates one node kind and delegates children back to `fold_*` to avoid reimplementing traversal.

## Risks and Edge Cases

Generated-code drift is the primary maintenance risk. Missing a new AST field in a struct folder would silently drop or fail to transform that field. Missing a new enum variant would break compilation or make a rewrite incomplete. Since the file is generated, fixes should be made in codegen inputs rather than by editing this file directly.

Feature gating is subtle. The `full!` macro relies on full-only variants being unreachable in derive-only builds. Incorrect gating in AST definitions or generated match arms can produce unreachable panics, unavailable methods, or accidental omission of full syntax from traversal.

Ownership semantics are another edge case for users. Folding consumes the tree; callers that need shared or in-place traversal should use other syn traversal APIs. Overrides that replace a node and then call the default folder in the wrong order can accidentally skip children or transform them twice.

Raw token handling requires explicit attention. Most `Verbatim` AST variants and macro/meta token fields use `fold_token_stream`, but `Lit::Verbatim` is returned unchanged by the default literal dispatcher. A folder intended to normalize every raw token must account for that behavior. Span rewrites must also account for identifiers and literals that update spans through `set_span`.

Deep syntax trees recurse through Rust call frames. Extremely deep generated input could stress stack depth. Stateful folders must also be written with traversal order in mind because the generated code makes deterministic but eager child calls as it rebuilds nodes.

## Test Signals

Compile the module with `fold + derive`, `fold + full`, and combined feature sets. Exercising only one feature lane is insufficient because many trait methods and match arms are gated.

Behavioral tests should implement small `Fold` types that rename identifiers, rewrite spans, transform literals, replace selected expressions/types, and rewrite token streams. Run them over parsed derive inputs, full files, macro invocations, attributes, paths, generic arguments, where clauses, patterns, use trees, trait/impl items, and `Verbatim` nodes.

Regression tests should verify that a default folder round-trips to an equivalent AST, that overridden narrow methods still receive nested nodes through default recursion, and that `Punctuated` separators and token marker fields are preserved. Generator tests should ensure every AST field and enum variant has a corresponding fold path.
