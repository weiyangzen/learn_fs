# sources/distributed-fs/ceph-client/rust/syn/gen/hash.rs

## Purpose
Generated Syn support code that implements `std::hash::Hash` for Syn AST node types when the crate is built with `extra-traits`-related surfaces under `derive` and/or `full` feature gates. The implementations make parsed Rust syntax usable in hash-based collections and structural comparisons by hashing the semantic AST fields, enum discriminants, literal values, and token streams where Syn stores unparsed or verbatim syntax.

The file is marked as generated by `syn-internal-codegen`, so its purpose is to mirror the AST schema rather than host hand-maintained business logic. In this Ceph client source snapshot it belongs to the vendored Rust `syn` crate area, not to the kernel or distributed-filesystem runtime path.

## APIs, Types, and Functions
The file imports `std::hash::{Hash, Hasher}` and, under `derive` or `full`, `crate::tt::TokenStreamHelper`. It defines 175 `impl Hash for crate::...` blocks for Syn syntax nodes. Representative covered families are:

- Root and declaration nodes: `File`, `Item`, `ItemFn`, `ItemStruct`, `ItemEnum`, `ItemImpl`, `ItemTrait`, `ForeignItem`, `ImplItem`, `TraitItem`, and derive-only `DeriveInput` / `Data`.
- Expression nodes: `Expr` and variants such as `ExprCall`, `ExprBinary`, `ExprStruct`, `ExprPath`, `ExprClosure`, `ExprMatch`, `ExprTry`, `ExprYield`, plus `Expr::Verbatim`.
- Type and generic nodes: `Type`, `TypePath`, `TypeReference`, `TypeBareFn`, `GenericArgument`, `GenericParam`, `Generics`, `WherePredicate`, `TypeParamBound`, and `QSelf`.
- Pattern, field, literal, attribute, path, visibility, macro, use-tree, operator, and mutability helper nodes.

Struct-like nodes hash their fields in source-schema order, for example attributes, visibility, identifiers, generics, type or expression children, optional delimiters, and punctuation tokens that Syn preserves as AST fields. Enum-like nodes first write a `u8` discriminant with `state.write_u8(...)`, then hash the associated payload when present. Verbatim token stream fields are routed through `TokenStreamHelper` except `Lit::Verbatim`, which hashes `to_string()`. Empty marker nodes such as `TypeInfer`, `TypeNever`, `UseGlob`, and the uninhabited `ImplRestriction` have empty or unreachable-style implementations.

## Control Flow
Each implementation is a direct, non-allocating `hash(&self, state)` method. There are two patterns:

- Field forwarding: `self.field.hash(state)` for child AST nodes, options, vectors, punctuated sequences, tokens, and primitive values.
- Variant dispatch: `match self` writes a stable per-file variant tag and then hashes the contained node or token stream.

Large dispatch implementations, especially `Expr`, `Item`, `Pat`, `Type`, `BinOp`, `TraitItem`, `ImplItem`, `ForeignItem`, and `UseTree`, encode the AST variant identity explicitly. Feature-gated variants are guarded with `#[cfg(feature = "full")]` or `#[cfg(feature = "derive")]`, and some non-full fallback arms use `_ => unreachable!()` for variants that the active feature set should not expose.

## State and Persistence Behavior
The module owns no persistent state. All state is externalized through the caller-provided `Hasher`. Hashing is deterministic for a fixed AST, feature set, dependency versions, token-stream formatting behavior, and hasher implementation, but Rust `Hash` is not a portable serialization contract and should not be treated as stable across Syn versions or codegen changes.

The implementations include syntax trivia that Syn preserves as fields, such as punctuation tokens, optional semicolons, visibility restrictions, macro delimiters, and some grouping tokens. They generally do not hash source spans directly unless downstream token or literal `Hash` implementations do so. For verbatim syntax, `TokenStreamHelper` is the integration point that gives token streams a structural hash representation.

## Dependencies and Integration
The file depends on the Syn crate's AST type definitions, standard `Hash` semantics, `proc_macro2` token and literal hash behavior, and Syn's internal `tt::TokenStreamHelper`. It is compiled conditionally by crate features:

- `derive` exposes derive-input-oriented nodes such as `Data`, `DataEnum`, `DataStruct`, `DataUnion`, and many shared type/expression fragments.
- `full` exposes the complete Rust file/item/statement/expression/pattern surface.
- `docsrs` attributes annotate feature-gated documentation with `doc(cfg(...))`.

The code integrates with users that enable Syn's extra traits and want AST nodes as keys in hash maps/sets, want cached structural fingerprints, or require `Eq`/`Hash` style trait availability in tests and tooling.

## Risks and Edge Cases
Hash output is schema-sensitive. Adding, reordering, or removing AST variants or fields changes hashes and may also require discriminant numbering updates. Because the file is generated, manual edits are at high risk of being overwritten or becoming inconsistent with sibling generated files such as equality, debug, clone, and visitor code.

Feature-gated variant numbering is a compatibility concern: variant tags are fixed in the generated code, but the active set of variants differs under `derive` versus `full`. Code that persists hash outputs across builds could observe changes. `Lit::Verbatim` using `to_string()` may normalize token text differently than `TokenStreamHelper`; consumers should not rely on it for byte-exact source identity. Token-stream hashing also cannot recover semantic information hidden inside unparsed macro bodies.

## Test Signals
Useful validation signals are Syn's own generated-code tests and crate builds across feature combinations: default, `derive`, `full`, `extra-traits`, and docsrs-style cfgs. Targeted regression tests should assert equal ASTs hash equally, distinct enum variants differ even when payloads are empty, verbatim token streams participate in hashes, and feature-gated builds compile without unreachable arms becoming reachable. Since this is generated, the strongest signal is regenerating from `syn-internal-codegen` and verifying the repository diff matches expectations.
