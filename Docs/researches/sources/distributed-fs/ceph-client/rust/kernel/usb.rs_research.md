# Research: sources/distributed-fs/ceph-client/rust/kernel/usb.rs

## sources/distributed-fs/ceph-client/rust/kernel/usb.rs

Purpose: implements Rust abstractions for USB driver registration, device IDs, interfaces, and USB devices. Important APIs/types are `Adapter<T>`, `DeviceId` constructors, `RawDeviceId`/`RawDeviceIdIndex` impls, `IdTable<T>`, `usb_device_table!`, trait `Driver`, `Interface<Ctx>`, internal `Device<Ctx>`, refcount impls, and `module_usb_driver!`.

Control flow: `Adapter<T>` describes `usb_driver` layout and registration ops. Registration fills name, probe, disconnect, and id table, then calls `usb_register_driver`; unregister calls `usb_deregister`. The C probe callback wraps `usb_interface`, casts the matched ID to `DeviceId`, gets per-ID info, calls `T::probe`, and stores pinned driver data in device drvdata. Disconnect retrieves drvdata and calls `T::disconnect`. `DeviceId` constructors build common USB match records with zeroed remaining fields. `Interface` converts to generic `device::Device` and to its parent USB `Device`; both wrappers are `AlwaysRefCounted`. State is kernel-owned USB core objects and driver private data stored in device drvdata. Dependencies include driver/device frameworks, device-id tables, `Opaque`, `PinInit`, `ThisModule`, USB bindings, and refcounting. Integration points are Rust USB modules and modpost alias generation. Risks include ABI/layout offset mistakes, probe storing wrong drvdata type, disconnect assumptions after partial probe failure, `DeviceId` match flag correctness, and private `Device` limiting external USB-device methods. Test signals: module registration/unregistration, modpost table output, probe failure cleanup, disconnect after successful probe, refcount get/put balance, and ID table index mapping.
