# Research: sources/distributed-fs/ceph-client/rust/kernel/types.rs

## sources/distributed-fs/ceph-client/rust/kernel/types.rs

Purpose: collects core FFI and utility types: foreign ownership transfer, scope cleanup, opaque C storage, and not-thread-safe markers. Important APIs/types are unsafe trait `ForeignOwnable`, its unit impl, `ScopeGuard::{new_with_data,new,dismiss}`, `Deref`/`DerefMut`/`Drop`, `Opaque::{new,uninit,zeroed,ffi_init,try_ffi_init,get,cast_into,cast_from}`, `Wrapper<T> for Opaque<T>`, and `NotThreadSafe`.

Control flow: `ForeignOwnable` transfers Rust values to C as aligned non-null `*mut c_void`, with unsafe borrow/reclaim methods. `ScopeGuard` stores `(data, cleanup)` in an `Option`, runs cleanup on drop unless `dismiss` consumes it. `Opaque` wraps `MaybeUninit<T>` in `UnsafeCell` and exposes raw pointers so C-owned invariants are not represented as Rust references; pin initializers call closures with uninitialized storage. State varies by utility: foreign pointers are external, scope guard owns optional cleanup data, opaque storage may be uninitialized/zeroed/initialized. Dependencies include `PinInit`, `Wrapper`, `Zeroable`, `UnsafeCell`, and FFI `c_void`. Integration points are nearly all kernel wrappers around C structs, lock/timer/workqueue initialization, callback data ownership, and current-task non-send markers. Risks include double `from_foreign`, overlapping foreign borrows, scope guard cleanup panics, reading uninitialized opaque storage, assuming `Opaque<T>` is `Sync`, and losing `NotThreadSafe` markers in wrappers. Test signals: ownership round trips, drop/dismiss behavior, pin-init FFI constructors, layout casts, and compile-time Send/Sync expectations.
