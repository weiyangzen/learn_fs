# Research: sources/distributed-fs/ceph-client/rust/kernel/task.rs

## sources/distributed-fs/ceph-client/rust/kernel/task.rs

Purpose: wraps Linux `task_struct`, current-task access, task identity, namespaces, UIDs, and sleep annotations. Important APIs/types are task-state constants, `current!`, `Task`, `CurrentTask`, `Pid`, `Kuid`, `Task::current_raw/current/as_ptr/pid/uid/euid/signal_pending/get_pid_ns/tgid_nr_ns/wake_up`, `CurrentTask::mm/active_pid_ns/group_leader`, `AlwaysRefCounted`, and `might_sleep`.

Control flow: `current!` creates a temporary `CurrentTask` reference from `get_current` and uses `NotThreadSafe` to prevent crossing task contexts. Owned task references use `ARef<Task>` via `get_task_struct` and `put_task_struct`. Current-only accessors skip refcount/RCU where kernel semantics permit it; cross-task namespace access takes a reference. `might_sleep` optionally reports caller location under `CONFIG_DEBUG_ATOMIC_SLEEP`, then calls `might_resched`. State is kernel-owned `task_struct`; Rust stores only transparent wrappers. Dependencies include `MmWithUser`, `PidNamespace`, `ARef`, `Opaque`, UID bindings, and scheduler bindings. Integration points are condvar signal checks, wakeups, user memory via `current` mm, pid namespace reporting, and refcounted task storage in driver state. Risks are using `CurrentTask` after returning to userspace or across `kthread_use_mm` scopes, stale assumptions about group leaders outside current task context, and using task pointers without refcounts. Test signals: compile-time non-`Send` current references, refcount balance, signal pending paths, pid namespace null/non-null behavior, and debug atomic sleep warnings.
