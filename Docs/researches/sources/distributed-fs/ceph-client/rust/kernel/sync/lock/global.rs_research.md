# Research: sources/distributed-fs/ceph-client/rust/kernel/sync/lock/global.rs

## sources/distributed-fs/ceph-client/rust/kernel/sync/lock/global.rs

Purpose: supports statically allocated kernel locks whose C lock state is initialized later by module init. Important APIs/types are `GlobalLockBackend`, `GlobalLock`, `GlobalLock::new`, `init`, `lock`, `try_lock`, `GlobalGuard`, `GlobalLockedBy`, and macros `global_lock!`/`global_lock_inner!`.

Control flow: `global_lock!` creates a zero-variant marker enum implementing `GlobalLockBackend`, then a `static GlobalLock` constructed by unsafe `GlobalLock::new`. Runtime module init must call `init` exactly once, which invokes the selected backend initializer on the embedded `Lock`. Locking delegates to the inner lock and wraps the resulting guard. `GlobalLockedBy` stores data guarded by the globally unique lock, granting access only when a `GlobalGuard` proves the lock is held. State is persistent static data and an embedded uninitialized C lock until explicit init. Dependencies include generic lock backends, `LockClassKey`, `LockedBy` thread-safety rules, `Opaque`, and macro-generated C strings. Integration points are module-level counters, singleton registries, and object fields protected by a global mutex/spinlock. Risks are using the static before `init`, calling `init` twice, reusing the backend marker with another lock, assuming global lock uniqueness incorrectly, and mutable access for pinned/`!Unpin` data through `DerefMut`. Test signals: module init ordering, lockdep class creation, `try_lock` behavior, and owner-guard mismatch tests for `GlobalLockedBy`-like access.
