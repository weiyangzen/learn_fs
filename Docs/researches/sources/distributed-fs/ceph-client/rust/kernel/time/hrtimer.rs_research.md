# Research: sources/distributed-fs/ceph-client/rust/kernel/time/hrtimer.rs

## sources/distributed-fs/ceph-client/rust/kernel/time/hrtimer.rs

Purpose: provides intrusive high-resolution timers without allocation at start time. Important APIs/types are `HrTimer<T>`, `HrTimer::new/raw_cancel/forward/forward_now/expires`, `HrTimerPointer`, `UnsafeHrTimerPointer`, `ScopedHrTimerPointer`, `RawHrTimerCallback`, `HrTimerCallback`, `HrTimerHandle`, `HasHrTimer`, `HrTimerRestart`, `HrTimerExpires`, `HrTimerMode` and absolute/relative/pinned/soft/hard mode types, `HrTimerCallbackContext`, `impl_has_hr_timer!`, and pointer-handle reexports.

Control flow: `HrTimer::new` initializes C `hrtimer` with the callback function supplied by `T::Pointer::run`, selected clock ID, and mode. `HasHrTimer::start` calls `hrtimer_start_range_ns`. Pointer adapters guarantee the containing object lives until cancellation or callback completion. The C callback recovers the containing object with `timer_container_of`, builds a callback target and `HrTimerCallbackContext`, calls `T::run`, and converts `HrTimerRestart` to C. `forward` can run with exclusive access or from callback context. State is the embedded C timer and the enclosing object lifetime represented by the handle. Dependencies include `time::{Instant, Delta, ClockSource}`, `Opaque`, `PinInit`, kernel hrtimer bindings, and adapter modules for `Arc`, `Pin<&T>`, `Pin<&mut T>`, and `Pin<Box<T>>`. Integration points are delayed/repeating driver actions, soft/hard IRQ callbacks, stack-scoped timers, and completion/atomic signaling. Risks include leaking unsafe scoped handles, wrong `HasHrTimer` field offsets, callback context constraints, cancel racing with concurrent start, running sleepful code from hard timer context, and timer mode/expiration type mismatches. Test signals include examples for Arc/Box/stack timers, restart/no-restart loops, cancellation waiting for running callbacks, `forward_now`, and mode-specific compile-time expiration typing.
