# sources/distributed-fs/ceph-client/tools/perf/pmu-events/arch/x86/broadwellde/uncore-interconnect.json

Purpose: Defines Broadwell-DE x86 uncore interconnect PMU event aliases for `perf`. The file is a JSON array of 70 event records for IRP and UBOX interconnect/message behavior, consumed by `jevents.py` into generated perf event tables for the Broadwell-DE model mapping.

Important schema and event surface: Records use the same perf PMU event schema as other `pmu-events` JSON files: `EventName`, `BriefDescription`, `Counter`, `PerPkg`, `Unit`, and usually `EventCode`, `UMask`, and `PublicDescription`. All 70 events are package-scoped with `PerPkg: "1"` and are programmable on counters `0,1`. The file has 48 `IRP` entries and 22 `UBOX` entries. `UNC_I_CLOCKTICKS` intentionally lacks an explicit event code, while every other record provides an event code; all records include a public description.

Important event families: `IRP` events cover aggregate cache total occupancy, coherent operations (`CLFLUSH`, `CRD`, `DRD`, PCI coherent reads/hints, RFO, WbMtoI), miscellaneous fast-path/cache-insert/prefetch timeout and transfer conditions, transaction classes (`ATOMIC`, `CLFLUSH`, `RD`, `WCILF`, `WIL`, `WR`), snoop responses, inbound BL queue inserts/full cycles/occupancy for DRS/NCB/NCS, AK inserts, outbound TxR request occupancy, outbound data inserts, and AD/BL stall-credit cycles. `UBOX` events cover virtual logical wire doorbells, thread-filter match modes, U2C monitor/event messages such as livelock, machine check, trap, and other system-management/PMI classes, PHOLD assert-to-ack cycles, and RACU outstanding register requests.

Control flow and integration: During perf builds, the JSON is parsed by `pmu-events/jevents.py` alongside the rest of `arch/x86/broadwellde`. The generated C table is selected through `arch/x86/mapfile.csv` for the Broadwell-DE CPU ID. Runtime lookup is data-driven: `perf list` and parse-events code expose aliases such as `UNC_I_COHERENT_OPS.RFO` or `UNC_U_U2C_EVENTS.CMC` when the matching PMU unit is present in sysfs. The `Unit` field tells perf which uncore PMU namespace the event belongs to, while `EventCode`, `UMask`, and any user-supplied extra terms form the actual hardware encoding.

State and persistence behavior: There is no in-process state, allocation, or persistence beyond the source-controlled JSON and generated perf event tables. The persistent hardware contract is the pair of unit-scoped event definitions and their counter constraints. Occupancy-style entries accumulate outstanding requests per cycle, so derived latency or pressure analyses require pairing with allocation/insert counters and elapsed clock events rather than treating the raw count as a transaction total.

Dependencies: Depends on the perf PMU event JSON schema, `jevents.py`, the x86 Broadwell-DE mapfile row, generated `pmu-events.c`, and kernel uncore PMU drivers exposing IRP and UBOX PMUs with compatible event/umask/filter formats. Semantics depend on Intel Broadwell-DE uncore documentation for IRP ordering queues, switch paths, snoop response encodings, UBOX thread filters, and U2C event routing.

Risks and edge cases: `UNC_I_CACHE_TOTAL_OCCUPANCY.SOURCE` depends on `IRP_PmonFilter.OrderingQ` selecting one source queue; the alias does not itself encode multi-queue selection and the description states that only one queue can be monitored at a time. UBOX filter-match and doorbell events depend on `NCUPMONCTRLGLCTR.ThreadID`/filter state, so raw alias use can produce broad or empty counts depending on filter programming. The file mixes transaction counters, occupancy counters, and stall-cycle counters; dashboards or metrics must avoid summing unlike units. Because all entries share only two counters, groups with many IRP/UBOX aliases can multiplex heavily or fail scheduling. Typos or stale hardware names in event records are user visible and can silently break metric expressions that match `EventName`.

Test signals: Validate JSON syntax and required fields with `jq` or the perf PMU event tests. Build perf with jevents enabled and confirm generated tables include both `IRP` and `UBOX` event families. On Broadwell-DE hardware, `perf list` should expose representative aliases including `UNC_I_COHERENT_OPS.RFO`, `UNC_I_TRANSACTIONS.RD`, `UNC_I_TxR_REQUEST_OCCUPANCY`, `UNC_U_EVENT_MSG.DOORBELL_RCVD`, and `UNC_U_U2C_EVENTS.UMC`. Runtime smoke tests should pair occupancy with insert/allocation counters, exercise PCIe or device traffic for IRP Tx/Rx queues, and check UBOX filter-dependent events with and without explicit thread/filter settings.
