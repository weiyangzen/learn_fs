## sources/distributed-fs/ceph-client/tools/perf/pmu-events/arch/x86/lunarlake/memory.json

**Purpose:** Lunar Lake memory PMU event metadata for `perf`. The file supplies 42 aliases for Atom load-head stalls, memory-ordering machine clears, Core sampled load/store latency, misaligned page-split references, offcore response demand code/data/RFO accesses, and Core offcore request/outstanding L3-miss demand-data events.

**Important APIs, types, and records:** This is parsed by `jevents.py` into event rows. Required fields are `EventName`, `EventCode`, `UMask`, `Counter`, `Unit`, `SampleAfterValue`, and descriptions; optional fields include `MSRIndex`, `MSRValue`, `Data_LA`, and `CounterMask`. The file has 24 `cpu_atom` records and 18 `cpu_core` records. Cross-unit duplicate names are intentional for `MACHINE_CLEARS.MEMORY_ORDERING`, `OCR.DEMAND_DATA_RD.DRAM`, `OCR.DEMAND_DATA_RD.L3_MISS`, and `OCR.DEMAND_RFO.L3_MISS`, with different Core and Atom event codes or offcore selector values.

**Event families:** Atom `LD_HEAD.*` records share event code `0x05` and classify oldest-load stalls as L1 miss, WCB full, page walk, store-address block, store-data block, other pipeline blocks, and retirement-visible variants using masks such as `0x81`, `0xa0`, `0x84`, `0xc0`, and `0xff`. Memory ordering records include Atom and Core `MACHINE_CLEARS.MEMORY_ORDERING` plus Atom `MACHINE_CLEARS.MEMORY_ORDERING_FAST`. Core `MEM_TRANS_RETIRED.LOAD_LATENCY_GT_*` records use event `0xcd`, `MSRIndex` `0x3F6`, and `MSRValue` thresholds from `0x4` through `0x800`; all have `Data_LA` set for address-capable precise sampling. `MEM_TRANS_RETIRED.STORE_SAMPLE` also has `Data_LA`. Atom OCR records use event `0xB7` with `MSRIndex` `0x1a6,0x1a7`; Core OCR records use event `0x2A,0x2B`. Core offcore request records include `OFFCORE_REQUESTS.L3_MISS_DEMAND_DATA_RD` and `OFFCORE_REQUESTS_OUTSTANDING.*`.

**Control flow and integration:** `jevents.py` converts `MSRIndex` `0x3F6` to `ldlat=` for sampled load-latency thresholds and `0x1A6/0x1A7` to `offcore_rsp=` for OCR selectors. It uses only the first event code from comma-separated `EventCode` strings when canonicalizing the generated event field, while preserving PMU/unit routing. `Data_LA` causes an additional description note that the event supports address collection when precise. Runtime users reach these aliases through `perf list memory` and `perf record/stat -e cpu_core/<event>/` or `cpu_atom/<event>/`. `lnl-metrics.json` uses these records for Atom load/store-bound formulas, Core memory-bound breakdowns, memory latency/bandwidth estimates, machine-clear attribution, and L3-miss/offcore diagnostics.

**State and persistence behavior:** The file persists only hardware alias metadata and default sampling periods. Runtime state is transient counter state, PEBS/sample data, load-latency threshold programming, and offcore response MSR programming. OCR and load-latency events are especially stateful at runtime because they require selector MSRs, but those selectors are derived from static `MSRValue` fields each time perf schedules the event.

**Dependencies:** Depends on Lunar Lake hardware memory-event encodings, hybrid PMU names, `jevents.py` MSR mappings, and sibling metric/event files. `LD_HEAD.*` events are consumed by Atom memory execution metrics. Core sampled latency records depend on PEBS/data-address support and perf's `ldlat=` handling. OCR aliases depend on offcore response MSRs `0x1a6/0x1a7` and on perf preserving selector values for Core and Atom separately.

**Risks and edge cases:** Offcore and load-latency selectors are high risk: a wrong `MSRValue` can silently measure a different response class or latency threshold. Comma-separated `EventCode` and `MSRIndex` values require parser compatibility; `jevents.py` explicitly takes the first event code and maps the first MSR index, so future schema changes need care. `Data_LA` records are sampling-oriented and may not behave like ordinary counting events. Hybrid duplicate OCR names must keep `Unit` correct to avoid duplicate-table assertions or wrong-PMU collection. `SampleAfterValue` values vary widely, from very low store/load-latency sampling periods to million-cycle stall counters; changing them affects overhead and sample representativeness.

**Test signals:** Validate JSON syntax, then run PMU event generation and metric parser tests. Runtime smoke tests on Lunar Lake should include `perf list memory`, `perf stat -e cpu_atom/LD_HEAD.L1_MISS_AT_RET/`, `perf stat -e cpu_core/MACHINE_CLEARS.MEMORY_ORDERING/`, and offcore aliases such as `cpu_core/OCR.DEMAND_DATA_RD.L3_MISS/` where supported. Sampling tests should exercise `cpu_core/MEM_TRANS_RETIRED.LOAD_LATENCY_GT_128/` with precise address capture and confirm that `ldlat=` programming and `Data_LA` behavior are accepted by the kernel.
