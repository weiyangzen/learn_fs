# sources/distributed-fs/ceph-client/tools/perf/pmu-events/arch/x86/cascadelakex/frontend.json

Purpose: Defines Cascade Lake front-end PMU event aliases covering branch resteers, decode stalls, DSB-to-MITE switches, front-end retired latency attribution, instruction cache/tag behavior, IDQ delivery paths, microcode sequencer activity, and uop delivery shortfall. These aliases feed both direct perf event selection and `clx-metrics.json` top-down frontend metrics.

Important event definitions: The file contains 49 events. Major groups include `BACLEARS.ANY` (`0xE6/0x1`), `DECODE.LCP` (`0x87/0x1`), `DSB2MITE_SWITCHES.*` (`0xAB` with umasks `0x1` and `0x2`), `FRONTEND_RETIRED.*` (`0xC6/0x1`) using `MSRIndex=0x3F7` and different `MSRValue` selectors, `ICACHE_16B.IFDATA_STALL`, `ICACHE_64B.IFTAG_*`, `ICACHE_TAG.STALLS`, IDQ source events under event code `0x79`, and `IDQ_UOPS_NOT_DELIVERED.*` under event code `0x9C`. Some aliases use `CounterMask` to count cycles meeting a threshold, and selected aliases use `Invert` or `EdgeDetect` for event qualification.

Control flow: Jevents parses the JSON fields into generated perf encodings. For these events, `MSRIndex` and `MSRValue` are important because `FRONTEND_RETIRED.*` variants share the architectural event selector but program an auxiliary MSR to choose a precise front-end retirement classification. At runtime, perf alias resolution maps names to CPU PMU events, applies cmask/edge/invert/MSR qualifiers, and metric evaluation uses their counts to compute fetch bandwidth, fetch latency, DSB/MITE/MS utilization, icache miss latency, unknown branch rate, and top-down frontend bottleneck leaves.

State and persistence behavior: The JSON has no mutable state, but some event selections imply hardware PMU programming state beyond the event select register, especially the shared `0x3F7` MSR for `FRONTEND_RETIRED.*`. The generated event aliases persist as user-facing names and as dependencies for top-down metric formulas. All listed events target generic core counters 0 through 3.

Dependencies and integration: `clx-metrics.json` references these aliases in metrics such as `percent_uops_delivered_from_decoded_icache`, `percent_uops_delivered_from_legacy_decode_pipeline`, `tma_frontend_bound`, `tma_fetch_latency`, `tma_dsb`, `tma_mite`, `tma_dsb_switches`, `tma_lcp`, `tma_icache_misses`, `tma_itlb_misses`, `tma_info_frontend_*`, and `tma_unknown_branches`. The aliases must line up with perf's MSR lookup/programming support in jevents, kernel CPU PMU constraints, and tests that compare generated pmu-events tables.

Risks: Shared encodings with different cmask, invert, edge, or MSR values are easy to conflate. Case differs for one `FRONTEND_RETIRED.LATENCY_GE_1` event code (`0xc6`) while most use `0xC6`; parsers tolerate this, but consistency checks may flag it. Events marked as aliases, such as `ICACHE_TAG.STALLS` and `ICACHE_64B.IFTAG_STALL`, can double-count if users include both. The `FRONTEND_RETIRED.*` MSR selector state can conflict if perf incorrectly groups incompatible variants. Front-end metrics divide by slots, cycles, DSB miss counts, or branch clear counts, so very small samples can produce noisy or undefined ratios.

Test signals: Build and `perf test pmu-events` should validate encoding generation. Runtime tests should include direct events from each group, especially `FRONTEND_RETIRED.LATENCY_GE_*`, `IDQ_UOPS_NOT_DELIVERED.CORE`, `DSB2MITE_SWITCHES.PENALTY_CYCLES`, `ICACHE_TAG.STALLS`, and IDQ DSB/MITE/MS aliases. Metric smoke tests should run `perf stat -M tma_frontend_bound,tma_fetch_latency,tma_dsb,tma_mite,tma_lcp,tma_icache_misses` against workloads with large code footprints, branch-heavy behavior, and microcode-heavy instructions. Watch for MSR programming conflicts, unsupported precise/front-end-retired variants, and unexpected multiplexing when grouped with other Topdown metrics.
