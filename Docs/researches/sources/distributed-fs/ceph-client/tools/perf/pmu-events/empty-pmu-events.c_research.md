## Scope

This chunk covers the first 1,769 lines of the generated perf PMU event table source `empty-pmu-events.c`. ## Purpose

The source is generated by `jevents.py` for `arch=none model=none`. Its role is to provide perf with a built-in fallback/test PMU event database when no architecture-specific event JSON is present. Instead of storing full `struct pmu_event` and `struct pmu_metric` records directly, the generator emits one `big_c_string` containing null-separated fields plus compact arrays of integer offsets into that string.

Within this chunk, the generated data covers:

- `default_core` legacy cache and hardware aliases for generic perf events.
- `software` events such as `cpu-clock`, `task-clock`, faults, context switches, migrations, and BPF output.
- `tool` pseudo events such as duration, user/system time, topology counts, SMT state, TSC frequency, and target CPU mode.
- Small test uncore PMU groups such as `hisi_sccl,ddrc`, `uncore_cbox`, `hisi_sccl,l3c`, `uncore_imc`, and system uncore PMUs.
- Built-in metric definitions such as CPU utilization, context switches per second, IPC-related ratios, cache/TLB miss rates, cyclic dependency test metrics (`M1`, `M2`, `M3`), and `L1D_Cache_Fill_BW`.

## Important Types And Data Layout

- `struct compact_pmu_event` contains only `int offset`. Every event or metric table entry in this chunk is represented by an offset into `big_c_string`.
- `struct pmu_table_entry` stores a compact entry array, an entry count, and a compact `pmu_name` offset. Later code uses this to group compact event records by PMU name.
- `big_c_string` is a single static string literal composed of many adjacent string fragments. Comments annotate byte offsets and serve as generator/debugging signals.
- The packed records use repeated NUL-delimited fields. In this chunk, event-like records appear to store name, topic/category, description, encoding, optional compatibility/model strings, unit/per-pkg/deprecated flags, and possibly long description fields. Metric-like records store metric name, metric group, expression, threshold, description, unit, and flags.

The field schema is not decoded in this chunk, but the visible include of `<pmu-events/pmu-events.h>` means later decompression code targets public `struct pmu_event` and `struct pmu_metric` APIs from perf's PMU events layer.

## Control Flow

There is no executable control flow in lines 1-1769 beyond static initialization. Runtime behavior is implied by the compact format:

1. Later lookup/iteration functions receive a compact table entry.
2. They iterate the `compact_pmu_event` offsets in sorted order.
3. For each offset, later decompression code reads NUL-delimited fields from `big_c_string`.
4. The decoded fields populate public perf PMU event or metric structures.
5. Callers can search by event/metric name, iterate all entries, or select PMU-specific tables.

Because `pmu_events__common_default_core[]` is sorted by visible event name rather than numeric offset order, later binary-search style lookup is likely possible. Exact lookup mechanics are outside this chunk but line ordering is a strong integration signal.

## Risks And Edge Cases

- Offset integrity is critical. Any change to `big_c_string` without regenerating every compact offset will silently decode the wrong fields.
- The packed field format is dense and weakly self-describing. Missing or extra NUL separators can shift subsequent fields and break decompression without obvious compiler errors.
- Alias-heavy event data increases the chance of duplicate or confusing names. Tests should check lookup behavior for aliases such as `cycles`/`cpu-cycles`, `branches`/`branch-instructions`, and plural/singular cache aliases.
- The generated descriptions include typo-like text, for example the `idle-cycles-frontend` alias description references `stalled-cycles-fronted`. Since generated descriptions are user-visible, fixture updates can change expected output.
- Metric expressions include escaped names, conditional expressions, thresholds, cyclic dependencies, and PMU-qualified event names. Parser/evaluator tests should cover these records because syntax regressions will not be caught by C type checking.
- This chunk ends before `pmu_events__common_default_core[]` closes. Any per-file analysis must be reconciled with later chunks to confirm table sizes, PMU table entries, decompression semantics, and exported API behavior.

## Important Types and Data Structures

`struct pmu_events_table` and `struct pmu_metrics_table` are defined here as opaque table wrappers. Each contains a pointer to an array of `struct pmu_table_entry` plus a PMU count. Callers only see forward declarations from `pmu-events.h`.

`struct compact_pmu_event` stores an `offset` into `big_c_string`. For events, that offset points to a packed sequence of NUL-terminated fields decoded into `struct pmu_event`. For metrics, it points to a different packed sequence decoded into `struct pmu_metric`.

`struct pmu_events_map` maps a CPU identity to one core event table and one metric table. In this chunk it has two real rows and a sentinel:

- `arch="common", cpuid="common"` maps to `pmu_events__common` and `pmu_metrics__common`.
- `arch="testarch", cpuid="testcpu"` maps to the generated test SoC CPU event/metric tables.
- The terminator row has null `arch` and `cpuid`.

`struct pmu_sys_events` maps system PMU table names to event/metric tables. This generated file has a real event table named `pmu_events__test_soc_sys` and a terminating empty row. No system metric table is populated in this chunk.

`metricgroups` is an empty sorted two-column offset table. `describe_metricgroup()` still implements binary search over it, but always returns `NULL` for this generated output.

## Main APIs and Functions

`decompress_event(int offset, struct pmu_event *pe)` decodes a packed event record from `big_c_string`. It assigns pointers directly into the static string blob and converts empty strings to `NULL`. It also decodes `deprecated` and `perpkg` as single ASCII digit fields by subtracting `'0'`.

`decompress_metric(int offset, struct pmu_metric *pm)` does the equivalent for metrics. It decodes ten string fields, then decodes `aggr_mode`, `event_grouping`, and `default_show_events` from single digit characters.

`pmu_events_table__for_each_event()` iterates over every PMU bucket in a table, optionally filtering with `perf_pmu__name_wildcard_match()`, and calls a caller-provided `pmu_event_iter_fn` for every event with a non-null name.

`pmu_events_table__find_event()` searches matching PMU buckets for one event name. The per-PMU helper uses binary search over the compact event array and compares names case-insensitively with `strcasecmp()`. It returns callback status on match, `0` if the caller passed `fn == NULL`, or `PMU_EVENTS__NOT_FOUND` when absent.

`pmu_events_table__num_events()` counts entries in matching PMU buckets. It does not decompress entries, so it counts table rows rather than only rows with non-null event names.

`pmu_metrics_table__for_each_metric()` iterates all metric buckets and calls a `pmu_metric_iter_fn` for rows whose decompressed `metric_expr` is non-null.

`pmu_metrics_table__find_metric()` searches matching PMU metric buckets by exact, case-sensitive `strcmp()` on `metric_name`. Its per-PMU helper also assumes sorted entries and returns `PMU_METRICS__NOT_FOUND` when absent.

`perf_pmu__find_events_table()` returns the event table suitable for a runtime `struct perf_pmu`. It first resolves the CPU/event map through `map_for_pmu()`, then confirms the PMU matches at least one PMU bucket in that table. A null `pmu` asks for the CPU map's event table directly.

`perf_pmu__default_core_events_table()` and `pmu_metrics_table__default()` scan `pmu_events_map` for the `common` CPUID row and return its event or metric table.

`pmu_metrics_table__find()` maps the synthetic CPU `{-1}` to the current CPU's map and returns its metric table.

`find_core_events_table()` and `find_core_metrics_table()` are explicit lookup helpers used by tests and other tooling. They require exact architecture string match and CPUID match through `strcmp_cpuid_str()`.

`pmu_for_each_core_event()` and `pmu_for_each_core_metric()` iterate over all non-sentinel core maps and stop on the first non-zero callback return.

`find_sys_events_table()` finds a named system event table. `pmu_for_each_sys_event()` and `pmu_for_each_sys_metric()` iterate system event/metric tables. In this generated chunk, system metric tables are effectively empty, so system metric iteration has no useful rows.

`describe_metricgroup()` binary-searches `metricgroups` for a description offset. Since `metricgroups` is empty here, every query returns `NULL`.

## Control Flow

Event iteration is a two-level loop. The public table function scans PMU buckets, filters by PMU name when a runtime PMU is supplied, and delegates to a per-PMU iterator. The per-PMU iterator decompresses each compact offset into a stack `struct pmu_event` and invokes the callback. The `pmu` field is initialized once to the table bucket's PMU name and retained while other fields are overwritten for each entry.

Event lookup follows the same outer PMU-bucket scan, but the inner scan is binary search. The correctness of `pmu_events_table__find_event_pmu()` depends on the generated entry arrays being sorted by decompressed event name using the same ordering implied by `strcasecmp()`. Null-name handling is present, although the visible generated tables mostly hold named rows.

Metric iteration and lookup mirror the event paths, with two important differences: metric iteration skips rows without `metric_expr`, and metric lookup uses case-sensitive `strcmp()` instead of `strcasecmp()`.

CPU mapping flows through `map_for_pmu()` and `map_for_cpu()`. Common software/tool PMUs are detected by comparing the runtime PMU name with PMU buckets in `pmu_events__common`; those PMUs force selection of the `common` map. Other PMUs use `perf_cpu_map__min(pmu->cpus)` and then `map_for_cpu()`. `map_for_cpu()` obtains a CPUID string with `get_cpuid_allow_env_override()`, scans `pmu_events_map` with `strcmp_cpuid_str()`, and returns a matching map or `NULL`.

System event lookup is independent of CPU mapping. A named system table is found by linear scan of `pmu_sys_event_tables`, and system iteration walks all named system tables.

## State and Persistence Behavior

Most data in this chunk is immutable static storage generated at build time. `big_c_string` owns the string payload, and compact table offsets point into it. Decompressed `struct pmu_event` and `struct pmu_metric` values only borrow these static string pointers; callers must not free them.

The only mutable state is inside `map_for_cpu()`, which keeps two static caches:

- `last_result` caches the most recent `struct perf_cpu` to map result.
- `last_map_search` caches the most recent CPUID string to map result and owns a heap-allocated `cpuid` string.

`map_for_cpu()` frees stale CPUID strings when the CPUID changes, but the cache is process-global and unsynchronized. It is optimized for repeated perf lookups in a single process, not for concurrent mutation by multiple threads.

There is no disk persistence, runtime file write, or external database update in this chunk. The generated C file is the persisted representation of the PMU event database.

## Risks and Edge Cases

The decompression helpers trust generated offsets and field layouts. A bad offset or malformed packed field sequence would produce invalid pointers, incorrect boolean/enum values, or out-of-bounds reads. There is no runtime bounds checking against `big_c_string`.

Binary search correctness depends on generated arrays being sorted by the same comparison used at runtime. Event lookup uses `strcasecmp()` while metric lookup uses `strcmp()`. A generator-side ordering mismatch can make existing events or metrics unreachable even though full iteration still sees them.

`pmu_events_table__num_events()` calls `perf_pmu__name_wildcard_match(pmu, pmu_name)` without guarding `pmu`. Other APIs treat null `pmu` as "all PMUs"; this function appears to require a non-null PMU. Callers in `util/pmu.c` pass a PMU, but the API signature does not make that precondition obvious.

`pmu_metrics_table__find_metric()` returns `0` for a null table, while event lookup returns `PMU_EVENTS__NOT_FOUND` for a null table. That asymmetric not-found behavior can surprise callers expecting metric lookup to mirror event lookup.

The static caches in `map_for_cpu()` are not thread-safe. Concurrent callers could race on `last_map_search.cpuid`, `last_result`, and the boolean flags. Perf's common use is mostly single-threaded command setup, but this is still a shared mutable global.

The header declares `find_sys_metrics_table()`, but this generated chunk does not define it. The visible code only supports system metric iteration through `pmu_for_each_sys_metric()`, and the generated system metric tables are empty. If a future caller directly references `find_sys_metrics_table()` with this generated file, it may expose a link-time gap unless another object supplies it.

The generated test data includes recursive or cyclic metric expressions such as `M1`, `M2`, and `M3`. These are likely intentional parser test cases, but they are risk signals for metric evaluation paths that fail to detect recursion.
