# sources/distributed-fs/ceph-client/tools/testing/selftests/kvm/riscv/get-reg-list.c

## Purpose
This RISC-V KVM selftest guards the `KVM_GET_REG_LIST` ABI against regressions by comparing the vCPU register list exposed by KVM against blessed per-feature register sublists. It accounts for host-dependent ISA/SBI extension visibility and dynamically adjusts vector register sizes from `vlenb`.

## Important APIs, Types, And Functions
The file uses selftest helpers from `kvm_util.h`, `test_util.h`, and `processor.h`, including `vcpu_get_reg()`, `__vcpu_get_reg()`, `__vcpu_set_reg()`, `__vcpu_has_ext()`, `TEST_ASSERT`, and `__TEST_REQUIRE`. Important local functions are `filter_reg()`, `check_reject_set()`, `override_vector_reg_size()`, `finalize_vcpu()`, and the many `*_id_to_str()` helpers used to print unknown or changed register IDs in C initializer form. The register model is expressed through static `__u64` arrays such as `base_regs`, `sbi_base_regs`, `aia_regs`, `fp_f_regs`, `fp_d_regs`, and `vector_regs`, plus `struct vcpu_reg_list` configurations generated by the `KVM_ISA_EXT_*` and `KVM_SBI_EXT_*` macros.

## Control Flow
The generic get-reg-list harness includes this architecture file and consumes `vcpu_configs[]`. Before validation, `finalize_vcpu()` snapshots current ISA extension state, tries to disable all ISA/SBI extensions, records extensions that cannot be disabled, and then enables each config's required feature. Vector tests call `override_vector_reg_size()` so the expected vector register IDs match the host's vlen. The common harness then compares KVM's reported register list with the active sublists, using `filter_reg()` to suppress expected host-dependent entries.

## State, Dependencies, And Integration
State is process-local: `isa_ext_cant_disable[]` tracks extensions that remain visible after disable attempts, and `vector_regs[]` is rewritten at runtime. There is no persistent storage. The test depends on RISC-V KVM one-reg IDs, generated kernel UAPI constants, host ISA/SBI support, and the shared selftests get-reg-list framework. It integrates at build time by supplying RISC-V-specific hooks and `vcpu_configs`.

## Risks And Test Signals
The main risk is drift between UAPI additions and the blessed arrays, especially for new ISA/SBI extensions that are intentionally filtered or have feature-gated register sets. Incorrect vector size calculation can create false failures on hosts with different VLEN. Strong signals are explicit unknown-register printing, skip behavior for unavailable features, rejection handling through `check_reject_set()`, and coverage across base, SBI, AIA, SMSTATEEN, FP, vector, cache-block, and many simple ISA-extension registers.
