# sources/distributed-fs/ceph-client/tools/testing/selftests/run_kselftest.sh

## Purpose

Top-level shell runner for installed kselftest collections. It locates the installation directory, prepares kselftest output context, parses collection/test selection arguments, and dispatches each selected test through the kselftest runner plumbing.

## Important APIs, Types, and Functions

Uses POSIX shell functions, environment variables such as KSELFTESTS, collections, and summary/output controls, test discovery files generated by kselftest install, and helper scripts in the same selftests tree. It is command-line glue rather than kernel-facing code.

## Control Flow and Integration

The script normalizes its directory, handles options, resolves requested collections or defaults to available collections, then iterates over selected tests and invokes the per-collection run logic. Exit status reflects aggregate failures while preserving skip handling expected by kselftest automation.

## State and Persistence Behavior

It writes no persistent source-tree state. Runtime state is shell variables, process exit codes, and emitted TAP/kselftest logs consumed by CI or callers.

## Dependencies and Integration Points

Depends on /bin/sh-compatible behavior, installed selftest directory layout, executable test files, and the kernel selftest conventions shared by tools/testing/selftests.

## Risks and Edge Cases

Path assumptions and environment differences can hide tests or misreport skips. Aggregated exit code behavior is important for CI; changes can break automation even without changing tests.

## Test Signals

Validation is successful execution over multiple collections, correct handling of explicit selections, and CI-visible pass/fail/skip summaries.
