# sources/distributed-fs/ceph-client/tools/testing/selftests/iommu/iommufd.c

`iommufd.c` is the main functional selftest suite for `/dev/iommu` and the IOMMUFD userspace ABI. It uses kselftest fixtures for base ioctl validation, process ownership transfer, IOAS mapping, mock domains, nested hardware page tables, dirty tracking, VFIO compatibility, vIOMMU objects, virtual event queues, hardware queues, and PASID attach/replace/detach coverage.

Important interfaces include `IOMMU_DESTROY`, `IOMMU_IOAS_ALLOC`, `IOMMU_IOAS_MAP`, `IOMMU_IOAS_MAP_FILE`, `IOMMU_IOAS_UNMAP`, `IOMMU_IOAS_COPY`, `IOMMU_IOAS_IOVA_RANGES`, `IOMMU_IOAS_ALLOW_IOVAS`, `IOMMU_OPTION`, `IOMMU_HWPT_ALLOC`, `IOMMU_HWPT_INVALIDATE`, dirty-bitmap ioctls, `IOMMU_GET_HW_INFO`, fault queue allocation, vIOMMU/vdevice/event/queue allocation, VFIO type1 ioctls, and IOMMUFD selftest commands from `iommufd_utils.h`.

Control flow is fixture-driven. A constructor creates aligned anonymous and memfd-backed buffers, each fixture opens `/dev/iommu`, provisions IOAS and optional mock devices, executes a scenario, and teardown closes the fd then asks the kernel test driver to verify page refs. The IOAS tests cover object lifetime, automatic and fixed IOVA placement, reserved and allowed ranges, copy/unmap behavior, access-object read/write and pin paths, forked-mm handling, huge-page alignment, dmabuf revoke, nested HWPT allocation, IOPF, and invalidation progress. Mock-domain tests verify page mappings, huge/file-backed memory, reference counts, domain replacement, and multi-domain propagation. Later fixtures validate dirty tracking, VFIO compat info and map semantics, vIOMMU cache/event/queue behavior, and PASID domain compatibility.

State lives mostly in kernel IOMMUFD objects: IOAS ids, mock device ids, HWPT ids, vIOMMU/vdevice/event/queue ids, fault queues, PASID associations, pinned pages, dirty bits, and queued events. User-space state includes shared buffers, memfds, child processes, eventfd/pipe synchronization, and temporary mmap regions.

Dependencies are the IOMMUFD driver, `/dev/iommu`, the kernel `iommufd_test` hooks, VFIO UAPI headers, root/capability-sensitive options, hugepage support for huge variants, memfd/dmabuf support, and the kselftest harness. Risks include environment-sensitive hugepage and rlimit behavior, errno contract drift, leaked references, stale IOTLB/cache/dirty state, and VFIO compatibility regressions. Strong test signals are clean TAP completion, expected errno values, correct dirty clear/no-clear behavior, bounded VFIO cap chains, and zero leaked page refs at teardown.
