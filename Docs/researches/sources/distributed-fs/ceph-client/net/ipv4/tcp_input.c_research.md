# sources/distributed-fs/ceph-client/net/ipv4/tcp_input.c

Purpose: Implements Linux TCP receive-side processing for IPv4/IPv6-neutral TCP sockets. It owns established-state fast and slow receive paths, generic RFC793 state processing outside TIME_WAIT, ACK validation and congestion feedback, SACK/DSACK scoreboard maintenance, loss recovery state transitions, receive queue and out-of-order queue management, TCP option parsing, listener SYN request setup, Fast Open receive handling, ECN/AccECN receive feedback, RTT/rate sampling, receive-buffer autotuning, and reset/FIN/urgent-data behavior.

Important APIs, types, and functions: Entry points include `tcp_rcv_established()`, `tcp_rcv_state_process()`, `tcp_conn_request()`, `tcp_get_syncookie_mss()`, `tcp_parse_options()`, `tcp_parse_mss_option()`, `tcp_finish_connect()`, `tcp_init_transfer()`, `tcp_reset()`, `tcp_fin()`, `tcp_simple_retransmit()`, `tcp_enter_loss()`, `tcp_enter_recovery()`, `tcp_enter_cwr()`, `tcp_rcv_space_adjust()`, `tcp_rcvbuf_grow()`, `tcp_initialize_rcv_mss()`, `tcp_rearm_rto()`, `__tcp_check_space()`, `tcp_data_ready()`, and `tcp_send_rcvq()`. Core private workers are `tcp_ack()`, `tcp_clean_rtx_queue()`, `tcp_fastretrans_alert()`, `tcp_sacktag_write_queue()`, `tcp_data_queue()`, `tcp_data_queue_ofo()`, `tcp_ofo_queue()`, `tcp_validate_incoming()`, `tcp_rcv_synsent_state_process()`, `tcp_ack_update_window()`, `tcp_ack_update_rtt()`, `tcp_rate_gen()`, `tcp_cong_control()`, `tcp_xmit_recovery()`, `tcp_prune_queue()`, and `tcp_prune_ofo_queue()`. Key state carriers are `struct sock`, `struct tcp_sock`, `struct inet_connection_sock`, `struct sk_buff`, `struct tcp_sacktag_state`, `struct rate_sample`, `struct tcp_options_received`, `struct request_sock`, `struct tcp_fastopen_cookie`, retransmit-queue skb control bits such as `TCPCB_SACKED_ACKED`, `TCPCB_LOST`, and `TCPCB_SACKED_RETRANS`, and local ACK flags such as `FLAG_DATA_ACKED`, `FLAG_DATA_SACKED`, `FLAG_ECE`, `FLAG_SND_UNA_ADVANCED`, `FLAG_SET_XMIT_TIMER`, and `FLAG_SACK_RENEGING`.

Control flow: Established sockets enter `tcp_rcv_established()`, refresh TCP timestamps, try Van Jacobson-style header prediction, and either take a pure-ACK/data fast path or fall back to full validation. The fast ACK branch parses aligned timestamps, calls `tcp_ack()`, frees the skb, then checks pending sends. The fast data branch verifies checksum/window/memory, queues in-order payload with `tcp_queue_rcv()`, updates receive RTT/MSS/window autotuning, optionally processes an ACK, and schedules an immediate or delayed ACK. The slow path validates options, PAWS, sequence acceptability, RST/SYN rules, and challenge ACKs through `tcp_validate_incoming()`, then runs `tcp_ack()`, urgent handling, `tcp_data_queue()`, send-side push/space checks, and ACK scheduling.

ACK processing flow centers on `tcp_ack()`. It rejects too-old ACKs and ACKs for unsent data with RFC5961 challenge ACK behavior, advances `snd_una`, cleans TLS-device acknowledged data when configured, updates timestamps and sender window, applies SACK blocks with `tcp_sacktag_write_queue()`, accepts ECN/CWR feedback, removes cumulatively acknowledged retransmit-queue skbs with `tcp_clean_rtx_queue()`, updates RACK reordering windows, processes AccECN counters, invokes congestion-control ACK hooks, handles TLP acknowledgments, enters fast retransmit/loss handling via `tcp_fastretrans_alert()` when the ACK is dubious, resets TLP/RTO timers, generates delivery/rate samples, calls congestion control, and finally sends new data or retransmits through `tcp_xmit_recovery()`. SACK handling validates SACK/DSACK ranges against `snd_una`, `snd_nxt`, `undo_marker`, and `max_window`, walks the retransmit RB tree, may split or shift GSO skbs, updates `sacked_out`, `lost_out`, `retrans_out`, `delivered`, DSACK undo state, reordering estimates, and rate samples, and caches received SACK blocks to avoid repeated queue walks.

Loss and congestion control flow is integrated with the ACK path. `tcp_identify_packet_loss()` delegates to NewReno or RACK marking. `tcp_fastretrans_alert()` maintains `TCP_CA_Open`, `TCP_CA_Disorder`, `TCP_CA_CWR`, `TCP_CA_Recovery`, and `TCP_CA_Loss`, handles SACK reneging delays, ECN-driven CWR, DSACK and timestamp undo, MTU-probe failures, F-RTO, PRR cwnd reduction, and recovery entry/exit. `tcp_enter_loss()` marks retransmit-queue data lost after RTO, reduces ssthresh when needed, records undo metadata, resets TLP state, and enables F-RTO when eligible. `tcp_cong_control()` either calls a congestion module's `cong_control()` or combines PRR reduction and `cong_avoid()`, then updates pacing rate.

Receive data flow is split between in-order and out-of-order queues. `tcp_data_queue()` drops empty payload skbs, strips TCP headers, handles MPTCP subflow option checks, accepts in-window in-order data into `sk_receive_queue`, advances `rcv_nxt`, processes FIN, drains any now-contiguous `out_of_order_queue` via `tcp_ofo_queue()`, removes obsolete SACK blocks, re-enables fast path when possible, and wakes readers. Duplicate or old data triggers DSACK and quick ACK. Future in-window data enters `tcp_data_queue_ofo()`, which schedules receive memory, disables header prediction, updates SACK state, inserts/coalesces in an RB tree, maintains `ooo_last_skb`, and may grow receive buffers. Memory pressure paths collapse receive/OFO skbs and prune high sequence OFO packets before dropping data.

Connection-state flow outside established state is handled by `tcp_rcv_state_process()`. LISTEN accepts SYNs through `icsk_af_ops->conn_request()`, SYN_SENT delegates handshake validation to `tcp_rcv_synsent_state_process()`, SYN_RECV completion initializes transfer state and moves to ESTABLISHED, FIN_WAIT/CLOSING/LAST_ACK perform close progression, and data in closing states is accepted or reset according to shutdown state. `tcp_conn_request()` parses SYN options, applies backlog/syncookie policy, allocates and initializes a request socket, routes it through address-family hooks, negotiates timestamp/window/SACK/ECN/AccECN/SMC/AO/Fast Open state, sends SYNACKs, and may attach a Fast Open child socket directly to the accept queue.

State and persistence behavior: Persistent per-connection state lives in `tcp_sock` and `inet_connection_sock`: sequence numbers (`snd_una`, `snd_nxt`, `rcv_nxt`, `copied_seq`, `rcv_wup`), windows (`snd_wnd`, `rcv_wnd`, `window_clamp`, `rcv_ssthresh`, `max_window`), ACK scheduling (`icsk_ack.pending`, quickack counters, delayed ACK timeout, compressed SACK timer), RTT/RTO estimators, pacing rate, congestion state, cwnd/ssthresh/PRR fields, RACK/TLP/F-RTO/undo metadata, delivery and CE counters, SACK caches and selected SACK blocks, retransmit queue tags/counters, receive and out-of-order queues, urgent pointer state, Fast Open request state, AO sequence-number-extension counters, and BPF/SMC/MPTCP/TLS-related flags. State is mutated under the socket lock in normal receive contexts, with `READ_ONCE()`/`WRITE_ONCE()` used for fields observed locklessly by poll, qdisc, timers, sysctl users, or other networking paths. Persistence is in-memory only; there is no disk persistence, but route metrics, tcp metrics, and per-net MIB counters are updated as observable side effects.

Dependencies and integration points: The file depends heavily on `<net/tcp.h>`, `<net/tcp_ecn.h>`, inet connection socket APIs, skb queues/RB trees, retransmit queue helpers from TCP output/recovery code, congestion-control callbacks, RACK/TLP helpers, timer helpers, syncookie/Fast Open code, route/dst metrics, security hooks, BPF sock_ops callbacks, cgroup BPF parse/established hooks, TLS-device cleanup callbacks, MPTCP option ingestion, SMC negotiation, TCP-AO and MD5 option handling, IPv6 flowlabel handling under `CONFIG_IPV6`, net namespaces and sysctls, tracepoints, MIB counters, socket wakeups, memory accounting, and address-family operations (`icsk_af_ops`) supplied by IPv4 and IPv6 TCP front ends. Exported symbols are consumed by other TCP modules and protocol front ends, including option parsing, connection completion, retransmission/loss helpers, and receive-buffer tuning.

Risks and edge cases: Sequence arithmetic and wraparound checks are safety-critical for ACK/SACK validation, PAWS, window updates, and RST acceptance. SACK and DSACK handling can corrupt loss accounting if skb fragmentation, GSO pcount, retransmit tags, or cache skipping are mishandled. Incorrect `snd_una`/`rcv_nxt` updates affect TCP-AO SNE counters and byte counters. ACK rate limiting and challenge ACK limits must balance RFC5961 protection against avoiding ACK loops and not hiding valid recovery signals. Memory-pressure pruning intentionally drops OFO data and resets SACK state, which preserves correctness but can damage throughput. Fast path timestamp updates are delayed until checksum success to avoid poisoning PAWS state. FIN/RST handling has compatibility exceptions, including RST at `rcv_nxt - 1` after FIN. Fast Open and SYN_SENT logic has special accounting for SYN-data, retransmitted SYNs, and active-cookie failures. AccECN option/counter ambiguity, ACK compression, delayed ACK inference, TLP DSACKs, SACK reneging, F-RTO, and spurious recovery undo all have coupled state that can regress congestion control if changed without end-to-end tests.
