# sources/distributed-fs/ceph-client/net/mac80211/rx.c

## Purpose
`rx.c` is the central mac80211 receive path for frames delivered by low-level wireless drivers. It validates driver RX metadata, mirrors frames to monitor interfaces with radiotap metadata, updates scan/BSS state from beacons and probe responses, selects the target virtual interface/link/station, performs duplicate detection, A-MPDU reorder release, decryption, defragmentation, A-MSDU conversion, mesh forwarding, data delivery, management/action dispatch, and optional fast RX/802.3 decapsulation. It also exposes driver-facing entry points for normal NAPI RX, hard-IRQ-safe queued RX, power-save notifications, and BA reorder-buffer maintenance.

## Important APIs, Types, and Functions
Driver-facing receive APIs are `ieee80211_rx_list()`, `ieee80211_rx_napi()`, and `ieee80211_rx_irqsafe()`. `ieee80211_rx_list()` is the main 802.11/802.3 entry point, validates `struct ieee80211_rx_status`, handles monitor delivery, starts KCOV remote coverage, and calls either `__ieee80211_rx_handle_packet()` or `__ieee80211_rx_handle_8023()`. `ieee80211_rx_napi()` wraps receive processing in RCU and forwards the completed skb list through GRO or `netif_receive_skb_list()`. `ieee80211_rx_irqsafe()` queues hard-IRQ RX skbs onto `local->skb_queue` for tasklet processing.

Monitor/radiotap helpers include `ieee80211_rx_radiotap_hdrlen()`, `ieee80211_add_rx_radiotap_header()`, `ieee80211_make_monitor_skb()`, `ieee80211_rx_monitor()`, `ieee80211_clean_skb()`, `should_drop_frame()`, `ieee80211_validate_monitor_radio()`, and `ieee80211_handle_mu_mimo_mon()`. These account for FCS, driver-provided VHT/HE/HE-MU/L-SIG/TLV data, per-chain antenna signals, timestamps, zero-length PSDUs, monitor radio masks, and MU-MIMO follow-address copies.

Core receive state is carried in `struct ieee80211_rx_data`: `local`, `sdata`, `link`, `link_sta`, `sta`, `link_id`, `skb`, `seqno_idx`, `security_idx`, key/decryption fields, and optional output list. Link and station binding is centralized in `ieee80211_rx_data_set_sta()`, `ieee80211_rx_data_set_link()`, `ieee80211_rx_for_interface()`, and `ieee80211_prepare_and_rx_handle()`, with MLO address translation performed before slow-path handlers.

Slow-path handlers are organized through `ieee80211_invoke_rx_handlers()` and `ieee80211_rx_handlers()`. Important handlers are `ieee80211_rx_h_check_dup()`, `ieee80211_rx_h_check()`, `ieee80211_rx_h_check_more_data()`, `ieee80211_rx_h_uapsd_and_pspoll()`, `ieee80211_rx_h_sta_process()`, `ieee80211_rx_h_decrypt()`, `ieee80211_rx_h_defragment()`, `ieee80211_rx_h_michael_mic_verify()` from TKIP support, `ieee80211_rx_h_amsdu()`, `ieee80211_rx_h_data()`, `ieee80211_rx_h_ctrl()`, `ieee80211_rx_h_mgmt_check()`, `ieee80211_rx_h_action()`, `ieee80211_rx_h_userspace_mgmt()`, `ieee80211_rx_h_action_post_userspace()`, `ieee80211_rx_h_action_return()`, `ieee80211_rx_h_ext()`, and `ieee80211_rx_h_mgmt()`.

A-MPDU reorder support is implemented by `ieee80211_rx_reorder_ampdu()`, `ieee80211_sta_manage_reorder_buf()`, `ieee80211_sta_reorder_release()`, `ieee80211_release_reorder_frame()`, `ieee80211_release_reorder_frames()`, `ieee80211_release_reorder_timeout()`, and exported `ieee80211_mark_rx_ba_filtered_frames()`. Fragment cache support is exposed through `ieee80211_init_frag_cache()` and `ieee80211_destroy_frag_cache()` and internally uses `ieee80211_reassemble_add()`, `ieee80211_reassemble_find()`, and `requires_sequential_pn()`.

Data delivery and fast RX are handled by `__ieee80211_data_to_8023()`, `ieee80211_frame_allowed()`, `ieee80211_deliver_skb()`, `ieee80211_deliver_skb_to_local_stack()`, `ieee80211_rx_mesh_data()`, `ieee80211_rx_mesh_fast_forward()`, `ieee80211_check_fast_rx()`, `ieee80211_clear_fast_rx()`, `ieee80211_check_fast_rx_iface()`, `ieee80211_invoke_fast_rx()`, and `ieee80211_rx_8023()`. Power-save exports are `ieee80211_sta_ps_transition()`, `ieee80211_sta_pspoll()`, and `ieee80211_sta_uapsd_trigger()`.

## Control Flow, State, and Persistence
The top-level driver path validates band, bitrate encoding, NSS, GI, link id, local quiescing/suspend/reconfiguration/started state, and then clears `status->rx_flags`. Non-802.3 frames pass through `ieee80211_rx_monitor()`, which can clone frames to all matching monitor interfaces while returning a cleaned original skb for normal processing. Beacons, S1G beacons, and probe responses are handed to `ieee80211_scan_rx()` before interface delivery so scan/BSS tables are updated independently of whether a data or management consumer accepts the frame.

`__ieee80211_rx_handle_packet()` linearizes management frames, ensures headers are pulled, parses QoS into `seqno_idx/security_idx`, then first tries STA-directed delivery for data frames. If a `pubsta` is supplied, it uses that station directly; otherwise it iterates station entries keyed by transmitter address and copies the skb for all but the final consumer. If no station path consumes it, the function iterates running non-monitor, non-AP-VLAN interfaces and calls `ieee80211_rx_for_interface()` for each candidate. Unconsumed frames are freed.

`ieee80211_accept_frame()` is the per-interface admission gate. It enforces BSSID/address/DS-bit rules for station, IBSS, OCB, mesh, AP/AP-VLAN, P2P device, NAN, and NAN data interfaces. It rejects self-originated, malformed, wrong-BSSID, multicast data-to-AP, TDLS-peer, and unexpected robust-management cases, and triggers IBSS/OCB no-STA discovery where appropriate. MLO paths can infer link id from status, link station address, or channel frequency.

The slow path starts with duplicate and class checks, then routes QoS data through the reorder buffer. Reorder state persists in `struct tid_ampdu_rx`: `head_seq_num`, `ssn`, `buf_size`, `stored_mpdu_num`, per-slot `reorder_buf`, `reorder_time`, `reorder_buf_filtered`, timers, timeout values, and flags such as `auto_seq` and `removed`. BAR frames and timeout callbacks release buffered MPDUs into the same handler chain, with `IEEE80211_RX_DEFERRED_RELEASE` marking delayed frames.

Security state is selected before decryption. `ieee80211_rx_h_decrypt()` chooses PTK/STK, GTK, IGTK, or BIGTK according to unicast/multicast, Protected bit, MMIE key id, beacon protection, IV stripping, and MFP rules. It calls cipher-specific helpers for WEP, TKIP, CCMP, GCMP, AES-CMAC, and AES-GMAC, marks frames decrypted, and reports unprotected beacon/MLME events to cfg80211. `ieee80211_drop_unencrypted_mgmt()` then enforces MFP, protected dual action, robust action, encrypted association, and beacon protection policy. Fragment reassembly persists pending fragments in per-sdata or per-station fragment caches and validates sequential CCMP/GCMP PN plus key color to prevent mixed-key fragment attacks.

Data frames are converted to Ethernet by `__ieee80211_data_to_8023()`, checked against authorization/encryption/control-port policy, optionally forwarded in mesh mode, and then delivered locally or bridged back to wireless peers in AP mode. Control port frames may be diverted to `cfg80211_rx_control_port()`, and PAE group destinations are rewritten to the interface address before local stack delivery to avoid bridge leakage. TDLS channel-switch requests/responses are queued to interface work rather than delivered as ordinary data.

Management/action control flow validates frame sizes by category and action. Known actions are either handled immediately, queued to the interface workqueue, passed to userspace through `cfg80211_rx_mgmt_ext()`, answered locally, or returned to the sender as rejected action frames. Covered categories include HT, VHT, BACK/ADDBA/DELBA/NDP BA, spectrum management, self-protected mesh peering, mesh path selection, S1G TWT, protected EHT TTLM/link reconfiguration/EPCS/EML OMN, public/protected dual channel-switch actions, and SA Query.

Fast RX is a cached station optimization. `ieee80211_check_fast_rx()` builds `struct ieee80211_fast_rx` only for supported interface types, authorized stations, compatible powersave/offload settings, no unsupported software reorder requirements, and supported ciphers. `ieee80211_invoke_fast_rx()` requires duplicate validation, PN/decryption validation when keyed, no fragments, expected DS bits, unicast-to-interface address, and ordinary RFC1042 payloads. After it commits past punt points it trims MIC/ICV, handles A-MSDU if needed, converts headers in place, optionally mesh-forwards, updates per-link or per-CPU stats, and delivers without the full handler chain.

Persistent side effects include station/link RX counters, EWMA signal state, last rate/last RX timestamps, duplicate sequence caches, multicast sequence cache for MLD station mode, AP power-save flags and buffered TID bitmaps, reorder buffers/timers, fragment cache entries, mesh path/proxy updates, fast RX RCU pointers, BSS/color-collision notifications, interface skb queues, local dynamic power-save timer, LED triggers, and netdev software RX statistics.

## Dependencies and Integration Points
This file sits between low-level mac80211 drivers, cfg80211/nl80211, the Linux networking stack, and other mac80211 subsystems. It depends on `ieee80211_i.h`, `driver-ops.h`, `led.h`, `mesh.h`, `wep.h`, `wpa.h`, `tkip.h`, `wme.h`, and `rate.h`, plus kernel skb, RCU, timer, bitops, netdevice, radiotap, and unaligned-access helpers.

Driver integration uses `drv_*` callbacks for station notifications, TWT setup/teardown, event callbacks, decap offload, and scan/management side effects in other files. cfg80211 integration includes BSS reporting via scan code, management RX delivery, unprotected MLME reporting, control-port delivery, OBSS beacon reporting, BSS color collision notifications, spurious/unexpected frame notifications, and scheduled userspace management handling. Net stack integration uses `netif_receive_skb()`, `netif_receive_skb_list()`, `napi_gro_receive()`, `eth_type_trans()`, `dev_queue_xmit()`, and software netstats.

`scan.c` is called directly through `ieee80211_scan_rx()`. `s1g.c` is used through `ieee80211_s1g_use_ndp_ba()` and the S1G TWT action queueing path. `spectmgmt.c` is used through `ieee80211_process_measurement_req()` and channel-switch action validation. Mesh behavior integrates with mesh path, proxy, HWMP, MPS, and fast TX helpers. Crypto helpers maintain key replay state and decrypt/verify frame payloads.

## Risks and Test Signals
High-risk areas are skb headroom/tailroom and pull/trim accounting for radiotap, hardware-provided RX TLVs, FCS stripping, A-MSDU offsets, 802.3 decap, and fast RX in-place header conversion. Security-sensitive risks include accepting multicast data in AP mode, wrong BSSID admission, MFP and BIGTK/IGTK handling, MMIE key-index parsing, unprotected robust-management exceptions, mixed-key fragment cache attacks, PN validation assumptions when hardware decrypts, and fast RX bypass conditions.

Concurrency risks include RCU lifetime of stations, links, keys, and interfaces; reorder timer callbacks re-entering RX handlers; `rx_path_lock` contention; AP power-save state changes; fast RX RCU pointer replacement; and driver-provided `pubsta`/link id consistency in MLO. Protocol risks include sequence wrap handling in reorder buffers, BAR release boundaries, A-MSDU validation for mesh-control ambiguity, dynamic PS timer changes during scan/offchannel, management action length checks, and userspace/kernel split of action handling.

Useful tests include monitor-mode radiotap captures for legacy/HT/VHT/HE/HE-MU/UHR metadata, FCS/PLCP/error/zero-PSDU cases, MLO link-address translation, multi-interface skb copy fanout, duplicate detection, A-MPDU reorder wrap/timeouts/BAR/filtered bitmap behavior, encrypted fragmented CCMP/GCMP with non-sequential PN, MFP deauth/disassoc/beacon/action frames, AP powersave PS-Poll/uAPSD, control-port and unauthorized EAPOL paths, mesh forwarding/proxy/TTL/RMC, A-MSDU malformed/cipher cases, fast RX enable/disable transitions, 802.3 decap offload, and cfg80211 management delivery/return paths.
