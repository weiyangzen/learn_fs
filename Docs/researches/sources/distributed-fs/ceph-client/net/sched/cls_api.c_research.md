# sources/distributed-fs/ceph-client/net/sched/cls_api.c

Purpose: implements the core Linux traffic-control classifier API for this source tree. It registers classifier kinds, creates and destroys `tcf_proto` instances, owns TC filter blocks/chains, handles rtnetlink filter and chain commands, runs classifier chains on packets, manages classifier action extensions, and bridges classifier/action state to hardware offload callbacks.

Important APIs/types/functions: `register_tcf_proto_ops`, `unregister_tcf_proto_ops`, and `tcf_proto_lookup_ops` maintain the global classifier kind registry guarded by `cls_mod_lock`. `struct tcf_block`, `struct tcf_chain`, `struct tcf_proto`, `struct tcf_filter_chain_list_item`, and `struct tcf_net` are the main state carriers. Block and chain lifecycle is handled by `tcf_block_get_ext`, `tcf_block_put_ext`, `tcf_block_lookup`, `tcf_chain_get_by_act`, `tcf_chain_put_by_act`, `tcf_get_next_chain`, `tcf_get_next_proto`, `tcf_chain_flush`, and `tcf_chain_tp_*`. Packet execution runs through `tcf_classify` and `__tcf_classify`. Netlink command handlers are `tc_new_tfilter`, `tc_del_tfilter`, `tc_get_tfilter`, `tc_dump_tfilter`, `tc_ctl_chain`, and `tc_dump_chain`. Filter serialization and notification use `tcf_fill_node`, `tfilter_notify`, `tfilter_del_notify`, `tc_chain_fill_node`, and `tc_chain_notify`. Extension/action helpers include `tcf_exts_init_ex`, `tcf_exts_destroy`, `tcf_exts_validate_ex`, `tcf_exts_dump`, `tcf_exts_dump_stats`, `tc_setup_action`, `tc_setup_offload_action`, and `tcf_exts_num_actions`. Offload integration is exposed through `tc_setup_cb_call`, `tc_setup_cb_add`, `tc_setup_cb_replace`, `tc_setup_cb_destroy`, and `tc_setup_cb_reoffload`. Queue event support is provided by `tcf_qevent_init`, `tcf_qevent_destroy`, `tcf_qevent_validate_change`, `tcf_qevent_handle`, and `tcf_qevent_dump`.

Control flow: classifier modules register a `tcf_proto_ops` object, which is later looked up by filter creation. `tc_new_tfilter` parses `RTM_NEWTFILTER`, finds the target qdisc/class or shared block, conditionally takes RTNL depending on qdisc/classifier unlocked support, gets or creates the target chain, finds or creates the `tcf_proto`, then calls the classifier's `change` op. Deletion mirrors that path in `tc_del_tfilter`: it can flush a whole chain, remove a whole proto, or delete a concrete filter handle through `ops->delete`, and then delete the proto if the classifier reports it is empty. `tc_get_tfilter` and `tc_dump_tfilter` traverse block, chain, proto, and classifier walker callbacks to produce netlink output. Chain commands use `tc_ctl_chain` to create, delete, get, and optionally attach classifier templates.

Packet classification starts at `tcf_classify`, which optionally consumes `TC_SKB_EXT` metadata for hardware misses or chain resumes, locates the requested chain, and delegates to `__tcf_classify`. The inner loop walks `tcf_proto` nodes, checks protocol unless resuming an action miss by cookie, calls the classifier-specific `classify` function, and handles `TC_ACT_RECLASSIFY` and `TC_ACT_GOTO_CHAIN` with a 16-iteration loop guard. On misses with skb extension support enabled, it stores the last executed chain and post-ct metadata back into a skb extension so later pipeline stages can resume or report miss context.

State and persistence behavior: all state is in-kernel runtime state. Per-net shared blocks live in `struct tcf_net`'s IDR; classifier kinds live in the process-global `tcf_proto_base` list; action miss cookies live in `tcf_exts_miss_cookies_xa`; deferred destruction uses the ordered `tc_filter_wq`; block hardware callbacks live in `block->flow_block.cb_list`; chain-zero head-change callbacks keep qdisc-visible filter-chain heads synchronized. Lifetimes are guarded by block mutexes, chain `filter_chain_lock`, `cb_lock`, RTNL when required, RCU list updates, `kfree_rcu`, refcounts on blocks/protos/chains, module refcounts, and action net namespace refs via `tcf_exts_get_net`/`tcf_exts_put_net`. No persistent on-disk state is written.

Dependencies/integration points: this file is the central integration layer between rtnetlink (`RTM_*TFILTER`, `RTM_*CHAIN`), qdisc/class operations (`Qdisc_class_ops::tcf_block`, class find/bind callbacks), classifier modules (`struct tcf_proto_ops`), tc actions (`act_api`, `tcf_action_*`), ematch users through classifier-specific trees, skb extensions, net namespaces, netdev offload APIs (`ndo_setup_tc`, `flow_block`, `flow_action`, `flow_indr_dev_setup_offload`), and qevent users in qdiscs. It exports many helpers consumed by classifier modules such as basic, bpf, flower, u32, route, matchall, fw, and by qdisc code.

Risks: the code is concurrency-sensitive. Incorrect lock ordering between RTNL, `cb_lock`, block lock, and chain lock can deadlock, and unlocked classifier paths must preserve block/proto refs carefully. Chain/proto deletion is split across RCU and destroy-in-progress tracking; missing `tcf_proto_signal_destroying` or `tcf_proto_signal_destroyed` can allow duplicate priority/protocol insertion races. Hardware miss cookies deliberately avoid hard refs and rely on revalidation; stale cookies cause packet drop with `SKB_DROP_REASON_TC_COOKIE_ERROR`. Offload counters and flags are updated under `cb_lock` plus proto spinlock; inconsistent updates would expose wrong `in_hw`/`not_in_hw` reporting or block offload state. Netlink dump consistency is best-effort because dumps can release RTNL between skb fills. qevent handling can drop, steal, or redirect packets based on attached filters, so action return handling is a packet-loss-sensitive path.

Test signals: exercise `tc filter add/change/replace/del/get/show` against qdisc-attached and shared-block filters, including auto priority allocation, chain selection, chain create/delete/get/dump, whole-chain flush, and classifier module autoload. Run with classifiers that have and lack `TCF_PROTO_OPS_DOIT_UNLOCKED`. Validate RCU lifetime with repeated replace/delete while traffic is classifying. Cover action extension validation, legacy police compatibility, terse dumps, hardware offload add/replace/destroy/reoffload, skip-sw/skip-hw behavior in classifier modules, and skb-extension hardware miss resume paths. qevent users should verify drop/stolen/redirect return mapping. Kernel selftests under `tools/testing/selftests/tc-testing` and `tc`/`iproute2` integration tests are the practical signal sources.
