# sources/distributed-fs/ceph-client/net/sched/sch_taprio.c

Purpose: implements the Time Aware Priority Scheduler qdisc for IEEE 802.1Qbv-style gate control lists. It maps priorities to traffic classes/TX queues, opens and closes gates on a schedule, optionally assigns transmit timestamps in txtime-assist mode, and can fully offload schedules to hardware.

Important APIs/types/functions: `struct taprio_sched` owns child qdiscs, flags, clock mapping, offload state, RCU operational/admin schedules, hrtimer, current entry, TXQ cursors, queueMaxSDU, frame-preemption data, and txtime delay. `struct sched_gate_list` stores GCL entries, base/cycle times, cycle extension, max gate durations, and max frame lengths. `struct sched_entry` stores gate mask, interval, budgets, gate close times, and next txtime. Core paths include `taprio_enqueue()`, `taprio_enqueue_one()`, `get_packet_txtime()`, `taprio_dequeue()`, `advance_sched()`, parsing helpers, `taprio_change()`, offload helpers, attach/graft/dump/stats/class ops, and exported `taprio_offload_get/free()`.

Control flow: init requires root attachment on a multiqueue device, creates a pfifo child per TX queue, detects mqprio quirks, then applies netlink configuration. Change parses immutable flags, validates mqprio and TC entries, builds a new admin schedule, computes queueMaxSDU and picos-per-byte, validates clock rules, and either programs hardware offload or starts software/txtime scheduling. Software mode advances `current_entry` by hrtimer and dequeue enforces gates, guard bands, and budgets. Txtime-assist computes `skb->tstamp` at enqueue. Full offload bypasses root dequeue by attaching children directly to TX queues.

State and persistence: schedules are in-memory RCU objects with `oper_sched` active and `admin_sched` pending. Hrtimer/current-entry state drives software mode. Full offload relies on hardware for activation but updates oper/admin pointers for dump visibility. Link speed notifier state recomputes duration and queueMaxSDU estimates. Nothing is persisted to disk.

Dependencies/integration: qdisc core, mqprio helper library, netdevice TX queue/class APIs, ethtool link and timestamp APIs, MAC Merge/preemption support, `ndo_setup_tc(TC_SETUP_QDISC_TAPRIO)`, hrtimers, RCU, static keys, GSO segmentation, socket `SO_TXTIME`, and TAPRIO netlink ABI.

Risks: time arithmetic, base-time-in-past handling, cycle extension, and admin-to-oper transitions are subtle; full offload lacks driver state callbacks for exact visibility. Txtime-assist assumes external PHC/system clock synchronization. QueueMaxSDU estimates can be inaccurate without a size table or after link changes. Flags, clockid, and mapping cannot be changed on a running schedule. Oversized GSO segments are dropped after segmentation if still too large.

Test signals: software/txtime/full-offload configurations, invalid flag and clock combinations, too-small intervals/cycle time, preemption and queueMaxSDU capability failures, gate/guard/budget enforcement, TXQ round robin, schedule replacement, base time in past, link-speed notifier recomputation, dump of oper/admin schedules, grafting, and offload stats.
