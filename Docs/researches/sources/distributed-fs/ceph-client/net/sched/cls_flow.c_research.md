# sources/distributed-fs/ceph-client/net/sched/cls_flow.c

Purpose: implements the `flow` TC classifier, which maps packets into classids by extracting one or more flow keys and either hashing them or applying a map transform. It supports ematch gating, TC actions, periodic hash perturbation, and class selection based on headers, skb metadata, route/class metadata, socket credentials, VLAN, rxhash, and optional conntrack tuples.

Important APIs/types/functions: `struct flow_head` owns the filter list. `struct flow_filter` stores filter handle, key configuration (`nkeys`, `keymask`, mode, mask/xor/rshift/addend/divisor/baseclass), random hash seed, perturb timer, ematches, extensions, proto pointer, and deferred work. Key extractors include `flow_get_src`, `flow_get_dst`, `flow_get_proto`, `flow_get_proto_src`, `flow_get_proto_dst`, `flow_get_iif`, `flow_get_priority`, `flow_get_mark`, `flow_get_nfct*`, `flow_get_rtclassid`, `flow_get_skuid`, `flow_get_skgid`, `flow_get_vlan_tag`, and `flow_get_rxhash`; `flow_key_get` dispatches by `FLOW_KEY_*`. Main classifier ops are `flow_classify`, `flow_change`, `flow_delete`, `flow_init`, `flow_destroy`, `flow_get`, `flow_dump`, and `flow_walk`.

Control flow: `flow_change` parses `TCA_FLOW_*` options, validates baseclass, keymask, mode, perturbation, and namespace constraints for socket UID/GID keys, allocates a new filter, validates ematches and actions, copies old settings on replacement, and applies changed options. New filters require a nonzero handle and `TCA_FLOW_KEYS`; replacement can partially update an existing filter. If no major baseclass is supplied for a non-shared block, it derives one from the qdisc handle; shared blocks must specify baseclass explicitly. Hash mode can use multiple keys and optional perturbation, while map mode allows only one key. The filter is inserted or RCU-replaced, and old filters are queued for deferred destruction.

During `flow_classify`, each filter first checks ematches. It dissects packet flow keys only when the selected keymask needs header-derived keys, fills a compact key array in bit order, computes either `jhash2(keys, nkeys, hashrnd)` for hash mode or a single-key map transform using mask, xor, right shift, and addend, then applies divisor if configured. The result classid is `TC_H_MAKE(baseclass, baseclass + classid)`, and action extensions decide the final verdict; negative extension return continues to the next filter.

State and persistence behavior: filter state is runtime-only in the RCU list under `tp->root`. Each filter owns a deferrable perturb timer that periodically refreshes `hashrnd`. `timer_shutdown_sync` runs before freeing. Deferred destruction uses `flow_destroy_filter_work` through the TC filter workqueue after action net refs are acquired. No IDR is used; handles are found by linear list scan. No state is persisted beyond kernel memory.

Dependencies/integration points: integrates with TC core, ematch/action helpers, qdisc block metadata, `skb_flow_dissect_flow_keys`, skb fields (`priority`, `mark`, `skb_iif`), socket ownership via `skb_to_full_sk`, route classid when `CONFIG_IP_ROUTE_CLASSID` is enabled, VLAN helpers, conntrack tuple access when `CONFIG_NF_CONNTRACK` is enabled, and flow/hash helpers (`jhash2`, random seed generation). It calls `tcf_block_netif_keep_dst` so destination metadata remains available for key extraction.

Risks: key extraction falls back to folded pointer-derived values for missing headers or ports, so classification may depend on kernel object addresses in those cases. Conntrack keys fall back to ordinary flow keys when no conntrack entry is present, which can change class distribution. Socket UID/GID keys are rejected outside `init_user_ns`; namespace handling changes could affect compatibility. Hash perturbation intentionally changes class mapping over time, which can reorder flows. Baseclass handling is strict for shared blocks; omitting it is an error. Timer, RCU, and action-extension lifetimes must remain synchronized on replacement and destroy.

Test signals: create flow filters in hash and map mode with representative keymasks for src/dst/proto/ports, mark, priority, VLAN, rxhash, and conntrack keys. Verify multi-key map mode is rejected, zero keymask is rejected, invalid key indexes are rejected, shared blocks require explicit baseclass, and socket UID/GID keys are rejected outside init user namespace. Test divisor, mask/xor/rshift/addend math, perturb timer behavior, ematch gating, action execution, dumps of every configured attribute, replacement preserving unspecified fields, and destroy/delete while traffic is active.
