# sources/distributed-fs/ceph-client/net/sctp/sm_statefuns.c

## Purpose
`sm_statefuns.c` implements the Linux SCTP state-machine handlers selected by `sm_statetable.c`. Each `sctp_sf_*` function receives a network namespace, endpoint, current association, event subtype, event argument, and `struct sctp_cmd_seq`, then validates the event and appends side-effect commands such as state changes, timer operations, packet replies, ULP notifications, association failure, SACK generation, retransmission, and TCB deletion. The file is the behavior core for SCTP association setup, duplicate/restart handling, data/SACK processing, graceful and abortive shutdown, heartbeats, ECN, ADD-IP/ASCONF, RE-CONFIG, PR-SCTP, AUTH, OOTB packet handling, user primitives, and timer expiry.

## Important APIs, Types, And Functions
The exported state functions follow the `enum sctp_disposition sctp_sf_*(...)` convention declared through SCTP state-machine headers. Core setup handlers include `sctp_sf_do_5_1B_init()`, `sctp_sf_do_5_1C_ack()`, `sctp_sf_do_5_1D_ce()`, and `sctp_sf_do_5_1E_ca()`. Collision/restart handlers include `sctp_sf_do_5_2_1_siminit()`, `sctp_sf_do_5_2_2_dupinit()`, `sctp_sf_do_5_2_4_dupcook()`, `sctp_tietags_populate()`, `sctp_tietags_compare()`, and `sctp_sf_check_restart_addrs()`. Data-plane handlers include `sctp_sf_eat_data_6_2()`, `sctp_sf_eat_data_fast_4_4()`, `sctp_sf_eat_sack_6_2()`, `sctp_eat_data()`, `sctp_sf_eat_fwd_tsn()`, and `sctp_sf_eat_fwd_tsn_fast()`.

Shutdown and abort paths are handled by `sctp_sf_do_9_2_shutdown()`, `sctp_sf_do_9_2_start_shutdown()`, `sctp_sf_do_9_2_shutdown_ack()`, `sctp_sf_do_9_2_final()`, `sctp_sf_do_4_C()`, `sctp_sf_do_9_1_abort()`, state-specific abort variants, and user primitive handlers such as `sctp_sf_do_9_1_prm_abort()`. Timer handlers include `sctp_sf_t1_init_timer_expire()`, `sctp_sf_t1_cookie_timer_expire()`, `sctp_sf_do_6_3_3_rtx()`, `sctp_sf_t2_timer_expire()`, `sctp_sf_t4_timer_expire()`, `sctp_sf_t5_timer_expire()`, `sctp_sf_autoclose_timer_expire()`, `sctp_sf_sendbeat_8_3()`, `sctp_sf_send_reconf()`, and `sctp_sf_send_probe()`.

Other important helpers are `sctp_chunk_length_valid()`, `sctp_err_chunk_valid()`, `sctp_sm_pull_sack()`, `sctp_sf_abort_violation()` and its chunk/parameter/CTSN wrappers, `sctp_sf_ootb()`, `sctp_abort_pkt_new()`, `sctp_ootb_pkt_new()`, `sctp_ootb_pkt_free()`, and `sctp_send_stale_cookie_err()`. The code depends heavily on command verbs added through `sctp_add_cmd_sf()`: `SCTP_CMD_NEW_STATE`, `SCTP_CMD_REPLY`, `SCTP_CMD_SEND_PKT`, `SCTP_CMD_EVENT_ULP`, `SCTP_CMD_TIMER_START/STOP/RESTART`, `SCTP_CMD_PROCESS_SACK`, `SCTP_CMD_PROCESS_CTSN`, `SCTP_CMD_CHUNK_ULP`, `SCTP_CMD_ASSOC_FAILED`, `SCTP_CMD_INIT_FAILED`, and many SCTP-specific queue/transport commands.

## Control Flow
Inbound chunk handlers generally follow the same pattern: verify the SCTP verification tag with `sctp_vtag_verify()` or exception-aware variants, validate the minimum chunk length, parse and pull fixed headers from the skb, validate variable parameters if needed, allocate any reply/event objects before issuing state-changing commands, enqueue side-effect commands, and return a disposition such as `CONSUME`, `DISCARD`, `ABORT`, `DELETE_TCB`, or `NOMEM`.

Association establishment is split by RFC 4960 section. Passive INIT handling rejects bundled INITs, nonzero vtags, control-endpoint OOTB packets, closing sockets, malformed INITs, and security-label failures; it builds a temporary association, processes peer INIT parameters, emits an INIT ACK, and then deletes the temporary TCB so the cookie carries state. Active INIT ACK handling verifies the INIT ACK, processes peer parameters, prepares AUTH shared keys, stops T1-init, starts T1-cookie, enters COOKIE-ECHOED, and generates COOKIE ECHO. COOKIE ECHO handling unpacks the signed cookie, processes peer init, authenticates delayed AUTH when present, creates COOKIE ACK and ULP events, installs a new association, enters ESTABLISHED, starts heartbeat/autoclose timers, and queues communication-up/adaptation/auth notifications. COOKIE ACK handling moves the active opener from COOKIE-ECHOED to ESTABLISHED and emits equivalent ULP notifications.

Duplicate INIT and COOKIE ECHO logic protects existing associations. Unexpected INITs share `sctp_sf_do_unexpected_init()`, which reuses existing association parameters, populates tie tags, checks restart address additions, sends INIT ACK, and deletes the temporary association without changing the live TCB. Duplicate COOKIE ECHO handling reconstructs a temporary association from the cookie and uses tie-tag comparison to select action A, B, C, D, or discard. Action A treats a peer restart by stopping retransmit/SACK/T4 timers, purging outqueue and ASCONF state, updating the live association, notifying ULP of restart, and either returning to ESTABLISHED or continuing shutdown for closed sockets. Action B handles setup collision by updating the association and moving to ESTABLISHED. Action C discards. Action D acknowledges a lost duplicate cookie and may complete establishment if still pre-established.

The data path accepts valid DATA through `sctp_eat_data()`, which processes ECN CE markings, TSN map status, receive-window pressure, partial delivery/reneging, zero-length DATA aborts, inbound stream validation, stream-specific data validation, and then queues `SCTP_CMD_CHUNK_ULP` or `SCTP_CMD_RENEGE`. `sctp_sf_eat_data_6_2()` decides delayed or immediate SACK generation, while the shutdown-sent fast path forces SACK plus SHUTDOWN and restarts T2. SACK processing validates the SACK header with `sctp_sm_pull_sack()`, rejects CTSN values beyond `next_tsn`, drops old SACKs, traces the probe, and delegates detailed outqueue processing to `SCTP_CMD_PROCESS_SACK`.

Shutdown paths are explicit. Receiving SHUTDOWN validates the peer's cumulative TSN, notifies ULP, enters SHUTDOWN-RECEIVED, processes CTSN, and if the outbound queue is empty sends SHUTDOWN ACK. Local shutdown enters SHUTDOWN-PENDING until no pending TSNs, then `sctp_sf_do_9_2_start_shutdown()` sends SHUTDOWN, starts T2, restarts T5 guard, stops autoclose and heartbeat timers, and enters SHUTDOWN-SENT. A SHUTDOWN ACK in SHUTDOWN-SENT/ACK-SENT creates SHUTDOWN COMPLETE, stops T2/T5, closes and deletes the TCB. A final SHUTDOWN COMPLETE in SHUTDOWN-ACK-SENT stops timers, emits shutdown complete, closes, updates MIB counters, and deletes the TCB. T2 retransmits SHUTDOWN or SHUTDOWN ACK; T5 aborts after guard expiry.

OOTB handling scans the entire packet's chunk headers with bounds checks. OOTB ABORTs are silently discarded; OOTB COOKIE ACK and stale-cookie ERROR are discarded; OOTB SHUTDOWN ACK gets a reflected SHUTDOWN COMPLETE; other OOTB packets get a reflected ABORT. Protocol violations generally create ABORTs unless AUTH policy requires authenticated ABORT only, in which case malformed packets are discarded without tearing down.

AUTH, ADD-IP, RE-CONFIG, and PR-SCTP paths add extension behavior. `sctp_sf_authenticate()` validates negotiated HMAC id, shared key id, digest length, computes HMAC after zeroing the digest field, compares with `crypto_memneq()`, and marks the chunk authenticated. ASCONF and ASCONF-ACK require peer capability and AUTH unless `addip_noauth` is set; inbound ASCONF serials are processed, replayed from ACK cache, or discarded, while ASCONF-ACK serial violations can abort the association. RE-CONFIG walks reset parameters and delegates to stream reset processors. FORWARD TSN validates peer PR-SCTP capability, TSN-map advancement, and stream interleaving validation, then reports/processes FWDTSN and generates SACK; the shutdown-sent fast path also regenerates SHUTDOWN.

## State And Persistence
This file has no durable persistence. All state lives in memory inside `struct sctp_association`, `struct sctp_endpoint`, `struct sctp_transport`, socket state, skb/chunk parsing cursors, MIB counters, timers, queues, and transient command sequences. The handlers usually avoid direct mutation and instead enqueue commands consumed by SCTP side-effect code; exceptions are temporary association setup before exposure, temporary flags like `new_asoc->temp`, direct fields such as `shutdown_retries`, `new_transport = NULL`, and skb cursor pulls.

Long-lived association state affected here includes association state (`CLOSED`, `COOKIE_WAIT`, `COOKIE_ECHOED`, `ESTABLISHED`, shutdown states), vtags/tie tags, TSN maps, cumulative ack points, receive window, stream state, AUTH active keys, peer capabilities, transport error/heartbeat state, PLPMTUD probe state, ASCONF serials/caches, `addip_last_asconf`, `strreset_chunk`, outqueue contents, and timers T1/T2/T3/T4/T5/SACK/HEARTBEAT/AUTOCLOSE/RECONF/PROBE. Counters such as `SCTP_MIB_CURRESTAB`, `ACTIVEESTABS`, `PASSIVEESTABS`, `ABORTEDS`, `SHUTDOWNS`, timeout counters, and data discard counters are also updated.

## Dependencies And Integration Points
The file integrates with SCTP core data structures from `<net/sctp/sctp.h>`, `<net/sctp/sm.h>`, and `<net/sctp/structs.h>`, skb manipulation, socket memory pressure, routing/transport code, crypto HMAC utilities, security hooks (`security_sctp_assoc_request()` and `security_sctp_assoc_established()`), tracepoints (`trace_sctp_probe`), MIB stats, ULP event creation, stream schedulers/interleaving callbacks, SCTP-AUTH, ADD-IP, RE-CONFIG, PR-SCTP, PLPMTUD, and command interpreter side effects. Its state functions are referenced by name in `sm_statetable.c`; changing a handler signature or disposition contract breaks the dispatch table and side-effect engine.

Packet construction depends on helpers such as `sctp_make_init()`, `sctp_make_init_ack()`, `sctp_make_cookie_echo()`, `sctp_make_cookie_ack()`, `sctp_make_shutdown()`, `sctp_make_shutdown_ack()`, `sctp_make_shutdown_complete()`, `sctp_make_abort()`, `sctp_make_op_error()`, `sctp_make_heartbeat()`, and `sctp_make_heartbeat_ack()`. Association lifecycle depends on `sctp_make_temp_asoc()`, `sctp_unpack_cookie()`, `sctp_process_init()`, `sctp_assoc_update()`, transport lookup/routing helpers, and ULP event factory functions.

## Risks
This is security-sensitive kernel packet parsing. Length checks and skb pulls must stay ordered so malformed chunks cannot drive out-of-bounds reads; `sctp_sm_pull_sack()` and parameter walkers are especially important for variable-length input. Verification-tag exception logic is subtle for INIT, INIT ACK, ABORT, SHUTDOWN COMPLETE, COOKIE ECHO, OOTB packets, and reflected T-bit packets; a wrong check can either drop valid recovery traffic or accept spoofed control chunks. Duplicate-cookie and restart handling must prevent takeover by rejecting new peer addresses while still allowing legitimate restart/collision recovery.

The command-sequence model reduces partial state updates, but many paths allocate replies/events before enqueuing state changes; future edits must preserve this ordering to avoid memory leaks, double frees, or half-applied association transitions. AUTH policy changes affect whether malformed traffic aborts an association. ASCONF serial arithmetic and cached ACK handling are replay-sensitive. Receive-window reneging and memory-pressure behavior can affect delivery ordering and SACK contents. Timer expiry paths delete TCBs and update counters; off-by-one retry behavior can cause premature aborts or infinite retransmission. `sctp_ootb_pkt_new()` creates temporary transports for replies, so all error paths must free OOTB packets with `sctp_ootb_pkt_free()`.

## Test Signals
High-value tests include four-way association setup from both active and passive sides, simultaneous INIT, duplicate INIT, duplicate COOKIE ECHO actions A/B/C/D, stale cookie retry with cookie preservative, malformed INIT/INIT ACK/COOKIE/SHUTDOWN/SACK/DATA lengths, AUTH bad HMAC/key id/signature/length, authenticated-only abort policy, OOTB packets containing ABORT, SHUTDOWN ACK, COOKIE ACK, stale-cookie ERROR, and generic control chunks. Data tests should cover in-order/out-of-order/duplicate/high TSN, invalid stream id, zero-length DATA abort, ECN CE/ECNE/CWR, forced SACK bit, receive-window pressure and partial delivery, shutdown-sent fast DATA handling, SACK CTSN beyond next TSN, gap/duplicate SACK parsing, FORWARD TSN with and without PR-SCTP capability, and interleaving stream validation.

Shutdown tests should exercise local shutdown with pending and empty outqueues, peer SHUTDOWN with valid/old/future CTSN, SHUTDOWN ACK/COMPLETE, T2 retransmits in both shutdown states, T5 guard abort, and user aborts in each association state. Timer tests should cover T1 init/cookie retry limits, T3 retransmission and zero-window shutdown guard behavior, heartbeat timeout and recovery, T4 ASCONF retransmission/abort, autoclose, RECONF resend, and PLPMTUD probe heartbeat. ADD-IP/RE-CONFIG tests should verify AUTH enforcement, serial replay/cache, unexpected ASCONF-ACK abort, queued ASCONF send-next behavior, address-add heartbeat, and stream reset request/response notifications.
