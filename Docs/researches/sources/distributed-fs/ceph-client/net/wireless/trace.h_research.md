# sources/distributed-fs/ceph-client/net/wireless/trace.h

## Purpose
`trace.h` defines the cfg80211 tracepoint surface for the wireless stack. It is a Linux trace-events header, not ordinary runtime logic: it declares reusable event classes, field-assignment macros, and concrete `TRACE_EVENT`/`DEFINE_EVENT` instances that instrument cfg80211 exported functions, `rdev->ops` driver callbacks, wiphy work scheduling, MLME notifications, scan/BSS reporting, regulatory/channel decisions, NAN, MLO, PMSR, TDLS, PMK/PMKSA, radar/CAC, and key-management flows.

The file turns transient kernel structures into trace records that can be consumed through ftrace/perf/tracefs. Its value is observability: it records what cfg80211 asked a driver to do, what results came back, and what asynchronous notifications cfg80211 emitted toward userspace or other kernel subsystems.

## Important APIs, Types, And Macros
The top-level `TRACE_SYSTEM` is `cfg80211`; `TRACE_INCLUDE_FILE` is set to `trace` and the file ends by including `<trace/define_trace.h>`. The include guard permits `TRACE_HEADER_MULTI_READ`, which is required by the Linux tracepoint generation pattern.

Reusable field macros normalize common object identity and nullable pointer handling:

- `WIPHY_ENTRY`, `WIPHY_ASSIGN`, `WIPHY_PR_*` capture `wiphy_name(wiphy)`.
- `WDEV_ENTRY`, `WDEV_ASSIGN`, `WDEV_PR_*` capture a `wireless_dev` identifier, using `0` for null/error pointers.
- `NETDEV_ENTRY`, `NETDEV_ASSIGN`, `NETDEV_PR_*` capture netdev name and ifindex.
- `MAC_ENTRY`/`MAC_ASSIGN` capture MAC addresses and zero-fill absent addresses.
- `CHAN_ENTRY`/`CHAN_ASSIGN` and `CHAN_DEF_ENTRY`/`CHAN_DEF_ASSIGN` capture channels, frequencies, widths, frequency offsets, and puncturing.
- `MESH_CFG_ENTRY`/`MESH_CFG_ASSIGN`, `SINFO_ENTRY`/`SINFO_ASSIGN`, `QOS_MAP_ENTRY`/`QOS_MAP_ASSIGN`, and `FILS_AAD_ASSIGN` snapshot larger cfg80211 structures into trace fields.

Reusable event classes avoid duplicating common layouts: `wiphy_work_event`, `wiphy_only_evt`, `wiphy_enabled_evt`, `wiphy_wdev_evt`, `wiphy_wdev_cookie_evt`, `wiphy_netdev_evt`, `key_handle`, `station_add_change`, `station_del`, `mpath_evt`, `rdev_pmksa`, `cfg80211_netdev_mac_evt`, `cfg80211_wdev_mac_evt`, `netdev_frame_event`, `netdev_mac_evt`, `cfg80211_rx_evt`, `wiphy_id_evt`, `cfg80211_bss_evt`, and `link_station_add_mod`.

Concrete tracepoints cover driver operation calls and returns such as `rdev_suspend`, `rdev_scan`, `rdev_add_virtual_intf`, `rdev_change_virtual_intf`, key operations, AP start/change/stop, mesh and station operations, connect/auth/assoc/deauth/disassoc, power and antenna settings, scheduled scan, TDLS, remain-on-channel, mgmt TX, channel switch, QoS map, SAR, color change, MLO link add/delete, TTL mapping, and EPCS. A second large group covers cfg80211 notifications such as `cfg80211_send_rx_assoc`, `cfg80211_rx_mgmt`, `cfg80211_mgmt_tx_status`, `cfg80211_reg_can_beacon`, channel switch/radar/CAC events, IBSS joined, scan done, get/inform/return BSS, WoWLAN wakeup, FT event, PMSR report/complete, OWE update, link removals, NAN notifications, and incumbent-signal updates.

## Control Flow
There is no direct business flow in this header. Control flow is generated by tracepoint expansion:

1. A cfg80211 or rdev wrapper calls `trace_<event>()`.
2. The tracepoint framework evaluates the `TP_fast_assign` block.
3. Assignment macros copy scalar values, MAC addresses, netdev/wdev identities, dynamic arrays, and selected payload bytes out of live kernel structures into the trace entry.
4. `TP_printk` formats the event for text output when consumers request printable records.

The event definitions are grouped by domain. The first group instruments wiphy work queue lifecycle. The second instruments `rdev->ops` calls and return values. The final group instruments exported cfg80211 notifications and helper outcomes.

Dynamic-array control flow deserves attention. Events such as `rdev_change_beacon`, `rdev_assoc`, `rdev_tdls_mgmt`, `rdev_update_ft_ies`, `cfg80211_scan_done`, and `cfg80211_inform_bss_frame` size trace buffers from the supplied length fields and conditionally copy data only when source pointers are present.

## State And Persistence Behavior
The file does not own persistent state. It snapshots state from live cfg80211 objects at trace time. Captured state includes object identifiers, channel definitions, security settings, station capabilities, mesh configuration, scan metadata, BSS addresses, link IDs, cookies, reason codes, and wakeup flags. Those snapshots persist only in the kernel tracing buffers configured by the tracing subsystem.

Because tracepoints copy data from live structures, correctness depends on callers passing stable objects and valid lengths for the duration of the trace call. The macros generally zero-fill nullable values, which makes trace output deterministic for absent optional data.

## Dependencies And Integration Points
This header depends on Linux tracepoint infrastructure, cfg80211/nl80211 data structures, netdevice and etherdevice helpers, rtnetlink declarations, and local `core.h`. It is closely integrated with rdev operation wrappers in the wireless core: wrapper functions use these tracepoints to log before and after driver callbacks. It also integrates with cfg80211 exported-notification paths so trace consumers can correlate driver requests, asynchronous driver reports, and userspace-visible events.

Downstream consumers include ftrace, perf, trace-cmd, kernel debugging workflows, and test automation that validates ordering or parameters of wireless operations.

## Risks And Edge Cases
Several tracepoints copy dynamic arrays directly from length fields. If a caller provides inconsistent pointer/length pairs, tracepoint execution can become a crash amplifier even though tracing is observational. Some events dereference nested pointers in trace arguments, for example BSS pointers, station parameters, beacon fields, NAN schedule data, or PMK fields; callers must not invoke them with partially initialized data.

Trace records can expose sensitive material. `rdev_set_pmk` copies PMK bytes into a trace dynamic array and prints them with `__print_array`; key and management events expose MAC addresses, cookies, SSIDs, FILS/OWE/FT data, and association IEs. Production tracing policy should account for credential and privacy leakage.

Printed output is intentionally summarized in many places, while the binary trace record may contain more data. Tests that assert only `TP_printk` strings may miss field-copy regressions. New cfg80211 features must keep the tracepoint ABI stable enough for tracing tools while adding fields carefully.

## Test Signals
Useful test signals include successful kernel trace-event generation, enabling individual events under tracefs, and observing expected records for interface creation, scan completion, connect/disconnect, key installation, channel switch, radar/CAC, and MLO link changes. Compile coverage should include `CONFIG_NL80211_TESTMODE` because `rdev_testmode_cmd` and `rdev_testmode_dump` are conditional. Runtime tests should verify nullable arguments produce zeroed MAC/channel fields rather than invalid dereferences, and that dynamic-array events handle zero lengths.
