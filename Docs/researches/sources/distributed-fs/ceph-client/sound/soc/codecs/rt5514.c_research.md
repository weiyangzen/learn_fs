# sources/distributed-fs/ceph-client/sound/soc/codecs/rt5514.c

`rt5514.c` is the main ASoC I2C driver for RT5514, a capture-oriented Realtek codec/DSP. It exposes a four-channel capture DAI, AMIC/DMIC capture routing, PLL/TDM configuration, and an ALSA `DSP Voice Wake Up` control that can load and run DSP firmware via the SPI companion.

The driver uses two regmaps: a raw 32-bit I2C regmap and a cached 16-bit component regmap that forwards reads/writes through `RT5514_DSP_MAPPING`. `struct rt5514_priv` stores platform data, component, regmaps, clocks, sysclk/lrck/bclk, PLL state, DSP enabled state, and PLL3 calibration. Probe parses platform/device properties, initializes both regmaps, retries the device-ID read once for bus-glitch recovery, applies raw I2C and component patches, and registers the component.

Core control flow includes DAPM AMIC/DMIC routes into stereo ADC mixers, DMIC clock divider selection, DAI `hw_params` divider/format programming, DAI format/sysclk/PLL/TDM setup, and bias-level clock/DSP handling. DSP wake-up changes only while bias is OFF: enabling may set a calibration clock, calibrate PLL3, read calibration via SPI, prepare DSP, request two firmware files, burst-write them to DSP memory, run the DSP, and apply calibration; disabling reapplies the normal patch and syncs regcache.

Persistent state includes clock/PLL fields, `dsp_enabled`, `pll3_cal_value`, and cached component registers. Dependencies include I2C, regmap, ASoC, firmware loader, optional clocks, device properties, OF/ACPI matching, `rl6231`, and optional `rt5514-spi` helpers. Risks include conditional SPI support, fixed firmware names, DSP state changes ignored while active, magic bypass/patch sequencing, and permissive TDM defaults. Test signals include probe retry, property parsing, capture paths, rate/format coverage, PLL/TDM setup, firmware-present/absent DSP enable, SPI-disabled build, bias transitions, and resume bogus-read recovery.
