# sources/distributed-fs/ceph-client/sound/soc/codecs/rt5663.c

## Purpose

`rt5663.c` is the complete Linux ASoC codec driver for the Realtek RT5663 family variant handled by this source. It provides the I2C device driver, regmap setup, chip identification, register defaults, calibration sequences, ALSA component registration, DAI operations, DAPM widgets/routes, mixer controls, jack/headset/button detection, optional impedance sensing, runtime bias management, and suspend/resume cache handling.

The driver supports two detected device IDs: `0x6451` maps to `CODEC_VER_1` with the v2 register map and v2-specific controls/routes, while `0x6406` maps to `CODEC_VER_0` with the original RT5663 map plus a small regmap patch. Much of the implementation branches on `codec_ver`.

## Important APIs, Types, and Functions

Important private types and data:

- `struct rt5663_priv`: per-device runtime state. It stores the ASoC component, platform data, regmap, delayed jack/unplug work items, headset jack pointer, an unused-looking `timer_list btn_check_timer`, optional impedance table, regulators, codec version, clock/PLL values, last jack type, and IRQ number.
- `struct impedance_mapping_table`: parsed from platform/device properties for headphone impedance ranges, volume compensation, and DC offset values with and without microphone.
- `rt5663_supply_names`: required regulators `avdd` and `cpvdd`.
- `rt5663_reg[]` and `rt5663_v2_reg[]`: regmap default tables for the two hardware variants.
- `rt5663_regmap`, `rt5663_v2_regmap`, and `temp_regmap`: cached variant maps plus a no-cache temporary map used for early device ID reads.

Key exported or integration-facing functions:

- `rt5663_sel_asrc_clk_src()`: exported GPL API for machine drivers to select system-clock or I2S1-ASRC tracking for DA and AD stereo filters. It programs `RT5663_ASRC_2` and, for v2 AD filters, `RT5663_ASRC_3`.
- `rt5663_i2c_probe()`, `rt5663_i2c_remove()`, `rt5663_i2c_shutdown()`: I2C lifecycle.
- `rt5663_set_jack_detect()`: ASoC component `.set_jack` hook. Stores the `snd_soc_jack` and schedules initial detection.
- DAI ops: `rt5663_hw_params()`, `rt5663_set_dai_fmt()`, `rt5663_set_dai_sysclk()`, `rt5663_set_dai_pll()`, `rt5663_set_tdm_slot()`, `rt5663_set_bclk_ratio()`.
- Component ops: `rt5663_probe()`, `rt5663_remove()`, `rt5663_suspend()`, `rt5663_resume()`, `rt5663_set_bias_level()`.

Important internal behavior functions:

- `rt5663_readable_register()`, `rt5663_volatile_register()`, `rt5663_v2_readable_register()`, `rt5663_v2_volatile_register()`: define regmap access and cache policy.
- `rt5663_v2_jack_detect()` and `rt5663_jack_detect()`: variant-specific headset/headphone detection.
- `rt5663_impedance_sensing()`: optional CODEC_VER_0 impedance measurement and compensation sequence.
- `rt5663_button_detect()`, `rt5663_irq()`, `rt5663_jack_detect_work()`, `rt5663_jd_unplug_work()`: IRQ-to-workqueue jack and inline button reporting path.
- `rt5663_hp_event()`, `rt5663_charge_pump_event()`, `rt5663_bst2_power()`, `rt5663_pre_div_power()`: DAPM event handlers.
- `rt5663_v2_calibrate()` and `rt5663_calibrate()`: long hardware initialization/calibration sequences run during I2C probe with regcache bypassed.
- `rt5663_parse_dp()`: reads optional device properties into platform data.

## Control Flow

Probe flow:

1. `rt5663_i2c_probe()` allocates `rt5663_priv`, copies platform data or parses firmware properties, and obtains regulators `avdd`/`cpvdd`.
2. It sets a 500 mA regulator load for each supply, enables both supplies, and waits `RT5663_POWER_ON_DELAY_MS` before accessing registers.
3. A temporary non-cached regmap reads `RT5663_VENDOR_ID_2`, with one retry after 100 ms if the first read fails or returns an unexpected ID.
4. Device ID selects either `rt5663_v2_regmap` plus `CODEC_VER_1` or `rt5663_regmap` plus `CODEC_VER_0`; unexpected IDs fail probe with `-ENODEV`.
5. The driver resets the codec, bypasses regcache, runs the variant calibration sequence, disables cache bypass, and resets again.
6. CODEC_VER_0 applies `rt5663_patch_list`; both variants configure GPIO1 as IRQ and set inline button debounce. Each variant then programs its own jack-detect, GPIO, bias, and data-swap defaults.
7. Delayed work items are initialized. If an IRQ is present, `request_irq()` registers an edge-triggered handler. Finally `devm_snd_soc_register_component()` registers the component and single DAI.

Audio stream control flow:

1. Machine driver configures DAI format through `set_fmt`, which supports codec provider/consumer clock modes, normal or inverted BCLK, and I2S/left-justified/DSP_A/DSP_B formats.
2. `set_sysclk` records and programs MCLK, PLL1, or RCCLK as system clock.
3. `set_pll` selects PLL input source, uses `rl6231_pll_calc()` to derive M/N/K codes, writes `RT5663_PLL_1` and `RT5663_PLL_2`, and records PLL state. Passing zero input or output disables PLL tracking and moves sysclk back to MCLK.
4. `hw_params` records LRCK, uses `rl6231_get_clk_info(sysclk, lrck)` for the ADDA pre-divider, validates sample width, and writes the I2S data length and pre-divider fields.
5. TDM slot count/slot width and BCLK ratio are programmed through variant-specific TDM registers.

Jack and button flow:

1. Hardware IRQ calls `rt5663_irq()`, which queues `jack_detect_work` after 250 ms.
2. `rt5663_jack_detect_work()` reads the variant JD status bit. On insertion from idle state, it runs the variant jack detect sequence, optionally runs impedance sensing for CODEC_VER_0, waits 30 ms, and reports headset/headphone state.
3. If a jack is already inserted, the same work item interprets `RT5663_IL_CMD_5` inline-button codes and maps groups of three raw behaviors to `SND_JACK_BTN_0` through `SND_JACK_BTN_3`.
4. Button press queues `jd_unplug_work` every 500 ms to avoid missing an unplug while button handling is active. Button release cancels that delayed unplug polling.
5. On removal, the variant detect function powers down related micbias/jack blocks and reports zero.

DAPM/control flow:

- Base widgets cover PLL, MICBIAS1/2, IN1, ADC L, I2S, IF DAC/ADC, ADDA mixers, DACs, headphone charge pump, headphone amp, HPOL/HPOR.
- CODEC_VER_1 adds LDO2, mic-detect power, LDO DAC, ASRC supplies, IN2, BST1 CBJ, BST2, record mixers, ADC R path, ADC muxes, DAC clock, and HPO playback switch.
- CODEC_VER_0 adds pre-divider gating, LDO ADC, ASRC supplies, BST1, stereo ADC source, and analog DAC source muxes.
- Routes use predicates to require PLL when sysclk is PLL, require ASRC supplies when ASRC tracking is selected, and require I2S ASRC only when sysclk exceeds `384 * lrck`.

## State and Persistence Behavior

Persistent software state lives in `struct rt5663_priv` for the lifetime of the I2C device. `sysclk`, `sysclk_src`, `lrck`, `pll_src`, `pll_in`, and `pll_out` gate DAI programming and redundant PLL/sysclk updates. `jack_type` carries the last reported physical state and changes bias-off behavior: if a headset remains inserted, the driver leaves fast VREF bits on instead of fully clearing the analog bias fields.

Hardware register state is cached in regmap using `REGCACHE_MAPLE`. Volatile/readable switch tables define what can be cached. Suspend disables IRQ, cancels delayed jack work, switches the regmap to cache-only, and marks it dirty. Resume reenables hardware access, syncs the cache, schedules a jack detection pass, then reenables IRQ.

The calibration paths deliberately bypass regcache because they perform hardware-only setup sequences and polling. The CODEC_VER_0 impedance-sensing path temporarily overwrites clock, ASRC, mixer, charge pump, depop, DAC/ADC, power, bias, and calibration registers; it saves a small subset of original values (`ASRC_2`, `STO1_ADC_MIXER`, `DUMMY_1`, `HP_CHARGE_PUMP_1`, `RECMIX`, `GLB_CLK`) and writes many fixed restore values for the rest.

Device-property state is parsed once at probe. DC offset manual values may be written during jack detection even without impedance sensing. When impedance sensing is enabled, the table drives both DRE headphone volume and DC offset compensation.

## Dependencies and Integration Points

Kernel subsystems and internal helpers:

- Linux I2C, regulator, ACPI, OF device matching, workqueue, delay, PM, and module infrastructure.
- ASoC component, DAI, DAPM, mixer control, TLV, jack reporting, and PCM params APIs.
- Regmap with 16-bit register and value widths.
- `rl6231_get_clk_info()` and `rl6231_pll_calc()` from the Realtek helper header.
- Public platform data from `<sound/rt5663.h>` and optional DT/device properties documented in `Documentation/devicetree/bindings/sound/rt5663.txt`.

External binding points:

- I2C ID table contains `"rt5663"`.
- OF compatible is `"realtek,rt5663"`.
- ACPI ID is `"10EC5663"`.
- Kconfig `SND_SOC_RT5663` depends on I2C; Makefile builds `snd-soc-rt5663.o`.
- The component exposes one DAI, `"rt5663-aif"`, with playback/capture streams `"AIF Playback"` and `"AIF Capture"`, 1-2 channels, 8 kHz to 192 kHz rates, and S8/S16_LE/S20_3LE/S24_LE formats.
- Machine drivers can call exported `rt5663_sel_asrc_clk_src()` to enable ASRC for non-standard I2S ratios such as Intel-style 100fs clocks.

## Risks and Edge Cases

- `rt5663_parse_dp()` calculates `table_size` in bytes but passes it as the element count to `device_property_read_u32_array()`. Because the table is cast to `u32 *`, that requests four times the expected number of 32-bit cells for a table whose members are all `unsigned int`. This can reject otherwise valid firmware tables or overrun expectations if property data is malformed.
- The impedance-sensing table lookup does not guard against no matching range. If `value` is outside all configured ranges, `i` can equal `impedance_sensing_num` and the code dereferences past the allocated table.
- Before sensing, the function searches for an entry whose `vol == 7` and then immediately uses `imp_table[i]`; if no such row exists, `i` can again equal `impedance_sensing_num`.
- `rt5663_i2c_probe()` uses plain `request_irq()` instead of a devm IRQ registration, so all error paths and remove paths must keep freeing it. The code does free it on `err_enable` and remove when `i2c->irq` is set.
- The delayed work items are canceled on component suspend, but `rt5663_i2c_remove()` only frees IRQ and disables regulators. If remove can race with queued work outside the component suspend/remove sequence, the work items may still reference `component` or regmap state.
- Jack and calibration sequences contain long sleeps and polling loops. Probe may block for hundreds of milliseconds to seconds, especially CODEC_VER_1 calibration with a 500 ms sleep and CODEC_VER_0 calibration with multiple polling loops.
- `rt5663_set_bias_level()` has a mask expression in the OFF case that mixes mask and value macros (`RT5663_PWR_FV1 | RT5663_PWR_FV2` inside the mask expression). The values equal their masks in this header, but the style is fragile.
- Many fixed "magic" register writes are undocumented in source comments. They are likely vendor sequences, but they make regression review difficult.
- `btn_check_timer` is present in `struct rt5663_priv` but not initialized or used in this file, suggesting leftover state or an incomplete button-check design.

## Test Signals

High-value test signals include:

- Build coverage for `CONFIG_SND_SOC_RT5663` and no sparse/smatch warnings around property array sizing and table indexing.
- Probe with both supported vendor IDs, including regulator load/enable, 300 ms power-on delay, regmap selection, calibration completion, and successful component/DAI registration.
- Probe failure paths for missing regulators, bad IDs, bad impedance table properties, failed regmap init, failed IRQ request, and failed component registration; regulators and IRQ should be cleaned up.
- ALSA controls present for base DAC/ADC controls, variant-specific headphone/mic boost controls, CODEC_VER_0 data swap control, and optional headphone volume behavior when impedance table is absent.
- Playback and capture at 8/16/20/24-bit widths where supported, rates from 8 kHz to 192 kHz, PLL from MCLK and BCLK, RCCLK sysclk, TDM slot widths 16/20/24/32, and BCLK ratios 32/40/48/64.
- DAPM route tests for PLL predicate, ASRC predicate, headphone power/depop events, charge pump sequencing, pre-divider gating, and v2-specific ADC R/BST2/CBJ paths.
- Jack tests for no jack, headphone, headset, button press/release, button during unplug, v2 and v0 JD status polarity, and optional impedance sensing with boundary impedance values.
- Suspend/resume with jack inserted and absent: IRQ disable/enable, regcache cache-only/sync, delayed work cancellation, and post-resume jack report should be checked.
