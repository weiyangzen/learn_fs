# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8962.c

## Purpose

`wm8962.c` is the ALSA SoC codec driver for the Wolfson/Cirrus WM8962 audio codec on I2C. It binds to `wlf,wm8962`, exposes a single `wm8962` DAI for playback and capture, registers mixer controls and DAPM routing, programs the codec's register map, handles runtime power management, supports the on-chip FLL, jack/microphone detection, beep generation, thermal/FLL/FIFO interrupts, and optional GPIO output support.

The file is a complete device driver rather than a narrow helper: it owns low-level I2C/regmap setup, ASoC component registration, DAI clock/format negotiation, board-data interpretation, analog power sequencing, DSP2 coefficient/control synchronization, and cleanup paths. The paired local header `sound/soc/codecs/wm8962.h` supplies the codec register and bitfield constants, while `include/sound/wm8962.h` supplies board/platform data and public identifiers consumed by machine drivers.

## Important Data Structures

- `struct wm8962_priv` is the driver's per-device state. It stores copied `struct wm8962_pdata`, the `regmap`, the current ASoC component pointer, SYSCLK/BCLK/LRCLK state, FLL source/reference/output state, the FLL completion, DSP2 enable state and mutex, mic-detect state and delayed work, regulator bulk descriptors and disable notifiers, optional input beep device/work, optional `gpio_chip`, IRQ number, AIF master flag, and TDM slot width/count.
- `wm8962_reg[]` is the regmap default table. It covers the normal analog/digital registers plus large DSP/EQ/filter coefficient spaces and is the source of truth for cache restore after power loss.
- `wm8962_regmap` configures a 16-bit register and 16-bit value map, `WM8962_MAX_REGISTER`, the default table, volatile/readable register callbacks, and `REGCACHE_MAPLE`.
- `wm8962_snd_controls[]`, `wm8962_spk_mono_controls[]`, and `wm8962_spk_stereo_controls[]` expose user-visible ALSA controls for input mixers, capture/playback volumes, HPF/LHPF, sidetone, headphone and speaker paths, EQ, 3D, DF1, DRC, DSP2 effects, ALC, and beep volume.
- `wm8962_dapm_widgets[]` plus mono/stereo speaker widget arrays model the codec's audio power graph. DAPM routes in `wm8962_intercon[]`, `wm8962_spk_mono_intercon[]`, and `wm8962_spk_stereo_intercon[]` connect analog inputs, digital mic input, ADC/DAC paths, sidetone, headphone mixers, speaker mixers, charge pump, SYSCLK/TOCLK, temperature protection, and outputs.
- `struct _fll_div` and `fll_fratios[]` hold computed FLL programming factors: reference divider, FRATIO, output divider, integer N, and fractional theta/lambda.

## Public and Integration APIs

- `wm8962_mic_detect(struct snd_soc_component *component, struct snd_soc_jack *jack)` is exported with `EXPORT_SYMBOL_GPL`. Machine drivers call it to enable or disable codec-driven microphone and short/button detection. When enabled, it unmasks mic IRQs, enables `MICDET_ENA`, forces DAPM `SYSCLK` and `MICBIAS`, and sends an initial empty jack report. Passing `NULL` masks mic IRQs and releases the forced DAPM pins.
- The ASoC component driver `soc_component_dev_wm8962` provides `.probe`, `.remove`, `.set_bias_level`, and `.set_pll`. `.set_pll` routes to `wm8962_set_fll()`.
- The DAI driver `wm8962_dai` exposes playback and capture streams with 1-2 channels, rates 8 kHz through 48 kHz plus 88.2/96 kHz, formats S16_LE, S20_3LE, S24_LE, and S32_LE, and symmetric rates. DAI ops implement `.hw_params`, `.set_sysclk`, `.set_fmt`, `.set_tdm_slot`, and `.mute_stream`.
- The I2C driver `wm8962_i2c_driver` binds by I2C ID `"wm8962"` and OF compatible `"wlf,wm8962"`. Machine drivers in the tree reference DAI name `"wm8962"` and public constants such as `WM8962_SYSCLK_MCLK`, `WM8962_SYSCLK_FLL`, and `WM8962_FLL`.

## Probe and Device Lifetime

`wm8962_i2c_probe()` is the device-level entry point. It allocates `wm8962_priv`, initializes the DSP mutex, delayed mic work, FLL completion, and IRQ state, then copies platform data or fills it from OF properties. The OF path handles `spk-mono`, `mic-cfg`, `gpio-cfg`, and an optional unnamed MCLK via `devm_clk_get_optional()`.

Probe then requests the eight supplies named `DCVDD`, `DBVDD`, `AVDD`, `CPVDD`, `MICVDD`, `PLLVDD`, `SPKVDD1`, and `SPKVDD2`, enables them, initializes the regmap, bypasses the regcache to read the ID/revision, verifies software reset ID `0x6243`, and resets the main and PLL register blocks. Static initialization disables SYSCLK, enables soft clock-register control, disables oscillator/PLLs, applies GPIO platform defaults, sets mono speaker mode when requested, applies mic-detect configuration bits, latches volume update bits, sets independent EQ coefficients, removes debounce requirements for key interrupts, optionally registers an IN4 DC measurement register patch, and requests a threaded IRQ if one is provided.

After hardware setup, probe enables runtime PM, registers the ASoC component/DAI, explicitly disables HP and speaker temperature protection bits, switches regmap to cache-only mode, and disables supplies. From that point, runtime PM resumes the device on demand and the regcache preserves desired state while powered down. Error paths disable runtime PM or regulators as appropriate; there is no manual devm resource unwinding beyond those powered resources.

`wm8962_probe()` is the ASoC component probe. It stores the component pointer, registers regulator disable notifiers for each supply, adds controls/widgets/routes, inspects GPIO function registers to decide whether `DMICDAT` should remain usable, initializes the beep input device/sysfs attribute, and registers optional GPIO lines. `wm8962_remove()` cancels delayed mic work and frees GPIO/beep helpers. `wm8962_i2c_remove()` disables runtime PM.

## Register Cache and Persistence Behavior

The codec is power managed aggressively. Normal register writes go through regmap and can be cached when the device is runtime suspended. Runtime suspend disables AIF master mode if active, clears VMID/bias and anti-pop startup bits, marks regmap cache-only, disables the bulk regulators, and disables MCLK. Runtime resume enables MCLK and supplies, leaves cache-only mode, resets the chip, marks the cache dirty, re-applies safe clock/PLL defaults, syncs the cache, enables startup bias and VMID fast-start settings, restores master mode if needed, and waits 5 ms.

Regulator disable notifiers call `regcache_mark_dirty()` on disable events so unexpected supply drops do not leave stale cache assumptions. `wm8962_reset()` writes both the main software reset register and PLL reset register. `wm8962_dsp2_write_config()` uses `regcache_sync_region()` from `WM8962_HDBASS_AI_1` to `WM8962_MAX_REGISTER`, so DSP2 coefficient/configuration registers written while cached are pushed to hardware before starting DSP2.

State persisted in `wm8962_priv` includes clock choices (`sysclk`, `sysclk_rate`, `bclk`, `lrclk`), FLL identity and rates, TDM geometry, DSP2 enable bitmask, microphone status, current jack pointer, beep target rate, and whether the codec is acting as AIF master. Some hardware state is deliberately mirrored or re-applied: mute uses both `WM8962_CLASS_D_CONTROL_1` and `WM8962_ADC_DAC_CONTROL_1`, output volume-update bits are rewritten when PGAs power up, and master mode is cleared/restored across suspend.

## Audio Controls and DAPM Flow

The control arrays are mostly declarative ASoC mixer controls with TLV volume scales, but several controls have custom behavior:

- DSP2 effect switches are implemented by `WM8962_DSP2_ENABLE()` controls. They update the cached `dsp2_ena` bitmask under `dsp2_ena_lock`; if DSP2 is already running, the handler writes the new enable mask or stops DSP2 when no effects remain enabled.
- `wm8962_put_hp_sw()` and `wm8962_put_spk_sw()` wrap standard volume switch writes and then re-write the active powered output volume register so the codec's volume update bits take effect while a headphone or speaker PGA is enabled.
- Coefficient controls use `SND_SOC_BYTES` or `SND_SOC_BYTES_MASK` for EQ, 3D, DF1, DRC, VSS, HPF, HD Bass, and ALC register blocks.

DAPM models both functional audio routing and power dependencies. Capture can use analog input PGAs/mixers or `DMICDAT` through virtual input-mode muxes. ADCs and DACs require `SYSCLK`, `TOCLK`, and optionally DSP2. Playback can route beep, sidetone, DACs, mixers, bypass paths, headphone outputs, and mono/stereo speaker outputs. Speaker control selection is data-driven by `pdata.spk_mono`: mono mode registers one speaker mixer/PGA feeding tied outputs, while stereo mode registers independent left/right mixers/PGAs.

Important DAPM event handlers:

- `tp_event()` enables or disables HP or speaker temperature-protection bits around DAPM output use and explicitly resumes the device while touching those volatile/protection registers.
- `cp_event()` waits 5 ms after the charge pump powers up.
- `hp_event()` sequences headphone startup and shutdown. On power-up it enables HP output stages, enables delayed stages, starts the DC servo, polls `WM8962_DC_SERVO_6` for both left/right startup completion for up to 200 ms, then enables output drivers and removes shorts. On power-down it reapplies shorts, disables DC servo, and clears HP enable bits.
- `out_pga_event()` rewrites the matching output volume register on PGA power-up to latch volume update bits.
- `dsp2_event()` starts DSP2 on DAPM power-up if any DSP2 effects are enabled, and stops it before power-down.

## Clocking, PCM Setup, and FLL Control

`wm8962_set_dai_sysclk()` selects SYSCLK source as MCLK or FLL and stores the requested frequency. `wm8962_set_dai_fmt()` supports DSP_A, DSP_B, right-justified, left-justified, and I2S formats, handles BCLK/LRCLK inversion combinations, and supports codec master mode (`SND_SOC_DAIFMT_CBP_CFP`) or slave mode (`SND_SOC_DAIFMT_CBC_CFC`). Master mode is saved in `master_flag` for runtime PM restoration.

`wm8962_hw_params()` calculates BCLK from either TDM settings or PCM params. If not in TDM, mono streams double BCLK so the codec still sees a stereo-width frame. It maps sample rates to `WM8962_ADDITIONAL_CONTROL_3`, sets integer sample-rate mode for multiples of 8 kHz, maps sample width to `WM8962_AUDIO_INTERFACE_0`, stores LRCLK, and, if bias is already ON, recalculates hardware BCLK/LRCLK divisors immediately.

`wm8962_configure_bclk()` selects the SYSCLK/LRCLK ratio from a fixed table, temporarily enables SYSCLK when not already in bias ON so the hardware can update the read-only DSPCLK divider, waits 500-1000 us, reads `WM8962_CLOCKING1`, derives DSPCLK, searches the supported BCLK divider table for the closest non-overshooting BCLK, writes `WM8962_CLOCKING2`, and writes the AIF LRCLK divisor in `WM8962_AUDIO_INTERFACE_2`. Unsupported SYSCLK/LRCLK ratios are logged and leave previous hardware settings in place.

`fll_factors()` computes FLL dividers. It scales Fref down to <=13.5 MHz, chooses an Fvco output divider targeting at least 90 MHz, chooses FRATIO by reference range, calculates integer N, and reduces the fractional theta/lambda pair by gcd when necessary. `wm8962_set_fll()` skips redundant programming, disables the FLL when Fout is zero, programs the selected reference source (`MCLK`, `BCLK`, `OSC`, or internal), writes the divider registers, enables runtime power, turns on the FLL, and waits for `fll_lock`. With an IRQ it waits up to 5 ms and treats timeout as fatal; without an IRQ it waits only 1 ms and does not hard-fail solely on missing completion.

One important lifetime detail is that disabling the FLL calls `pm_runtime_put(component->dev)`, while enabling performs `pm_runtime_resume_and_get()` and does not put the reference after a successful lock. That keeps the device active while the FLL is configured/running, but makes balance dependent on the higher-level set-pll disable call.

## Interrupts, Jack Detection, and Beep

`wm8962_irq()` is a threaded IRQ handler. It resumes the device, reads interrupt mask and active status from status block 2, ignores masked/no-active interrupts, acknowledges active bits by writing them back, and handles:

- `WM8962_FLL_LOCK_EINT`: completes `fll_lock`.
- `WM8962_FIFOS_ERR_EINT`: logs an error.
- `WM8962_TEMP_SHUT_EINT`: logs thermal shutdown and reads detailed HP/speaker warning/error bits.
- `WM8962_MICSCD_EINT` or `WM8962_MICD_EINT`: emits an ASoC jack trace when built-in, wakes the system briefly, and schedules `mic_work` after 250 ms.

`wm8962_mic_work()` reads `WM8962_ADDITIONAL_CONTROL_4`, reports `SND_JACK_MICROPHONE` on mic detect and `SND_JACK_BTN_0` on mic short, suppresses microphone reporting when an immediate short looks like a TRS plug in a TRRS socket, stores the current status, reports through `snd_soc_jack_report()`, and flips mic-detect/short interrupt polarity so future IRQs are edge-like.

The beep path creates a devm input device named `"WM8962 Beep Generator"` and a write-only sysfs attribute `beep`. `wm8962_beep_event()` accepts `SND_BELL` and `SND_TONE`, records the requested Hz, and schedules `beep_work`. The worker picks the nearest hardware rate among 500/1000/2000/4000 Hz, enables the DAPM `Beep` pin when nonzero, updates beep enable/rate bits, and syncs DAPM. Cleanup removes the sysfs file, cancels work, nulls the input pointer, and clears beep enable.

## GPIO Support

When `CONFIG_GPIOLIB` is enabled, the driver registers a `gpio_chip` named `"wm8962"`. It exposes linear offsets but only accepts hardware GPIOs 2, 3, 5, and 6; other lines return `-EINVAL`. `wm8962_gpio_request()` sets GPIO mode for lines that are behind multi-function selections, `wm8962_gpio_direction_out()` forces logic-output function and level, and `wm8962_gpio_set()` changes the output level through the codec GPIO register block. The chip is sleepable because accesses go through I2C/regmap.

Without GPIOLIB, GPIO init/free are empty stubs. Board data can still initialize GPIO function registers during I2C probe via `gpio_init[]`.

## Dependencies and Integration Points

This driver depends on Linux kernel ASoC, regmap, I2C, regulator, runtime PM, clocks, input, GPIO, workqueue, mutex/completion, and optional tracepoint infrastructure. It integrates with:

- Codec register definitions and public IDs in `sound/soc/codecs/wm8962.h`.
- Platform data and public GPIO/FLL/SYSCLK constants in `include/sound/wm8962.h`.
- Device tree compatible `wlf,wm8962` plus properties consumed here: `spk-mono`, `mic-cfg`, and `gpio-cfg`; an optional clock is also acquired.
- Machine drivers that set codec SYSCLK/FLL/format and call `wm8962_mic_detect()`, such as Freescale, Samsung Tobermory, and Tegra WM8962 integrations in this source tree.
- Runtime PM and regulator frameworks for power cycling; regmap cache correctness is central to persistence across suspend and supply loss.

## Risks and Edge Cases

- Regcache correctness is high risk because the driver resets hardware on every runtime resume, marks the cache dirty, and relies on `regcache_sync()` to restore all user-visible and machine-programmed state. Missing readable/default entries or untracked volatile bits can cause state loss after suspend.
- Clock configuration can silently leave old settings if `wm8962_configure_bclk()` finds an unsupported SYSCLK/LRCLK ratio; the function logs errors but returns void. Bad machine-driver clock choices may therefore appear later as distorted audio rather than a direct `hw_params()` failure.
- FLL runtime PM reference balance is subtle: enable holds a PM reference and disable drops it. Error exits also drop in some paths. Callers must pair FLL enable/disable and should test repeated stream open/close and suspend paths.
- The headphone DC servo startup path waits up to 200 ms inside DAPM power-up. Hardware, regmap, or IRQ problems can cause visible stream-start latency and only log timeout rather than fail routing.
- `wm8962_mic_detect()` calls `snd_soc_jack_report(wm8962->jack, ...)` after assigning `jack`, including the disable case where `jack` is `NULL`. This relies on the ASoC helper tolerating a null jack pointer.
- GPIO register numbering is non-linear; register 515 is skipped during DMIC detection, and GPIO request rejects unsupported linear offsets. Any extension here needs to preserve that hardware hole.
- DSP2 enable changes mute ADC/DAC paths while switching enable bits. Races are guarded for the bitmask, but audio artifacts are still possible around DAPM DSP2 transitions or userspace coefficient writes.
- Beep cleanup clears the work and hardware bit, but the input device itself is devm-managed. Sysfs and work ordering are the main lifetime concern.
- IRQ-less FLL operation has only a short wait and cannot observe lock completion. Systems without IRQ must rely on hardware behavior and external audio validation.

## Test Signals

Useful validation signals for this file include:

- I2C probe succeeds, logs the customer ID/revision, verifies ID `0x6243`, and registers ASoC component `wm8962` without regulator, clock, or regmap errors.
- `arecord`/`aplay` paths work for supported rates 8 kHz through 96 kHz and formats S16_LE, S20_3LE, S24_LE, and S32_LE, including mono playback/capture and TDM configurations when used by the machine driver.
- DAI format tests cover I2S, left/right justified, DSP_A/B, inversion variants, and both codec-master and codec-slave operation.
- FLL tests cover MCLK, BCLK, oscillator, and internal sources where available, repeated enable/disable, IRQ and no-IRQ boards, lock timeout behavior, and runtime suspend/resume around active FLL use.
- DAPM route tests toggle headphone and speaker outputs, mono/stereo speaker board modes, DMIC present/absent GPIO configurations, sidetone, bypass paths, charge pump, temperature-protection supplies, and DSP2 controls.
- Mixer persistence tests set volumes, EQ/DRC/3D/ALC/DSP coefficients, suspend/resume or runtime-idle the device, and verify settings survive via regmap/cache and audible behavior.
- Jack tests call `wm8962_mic_detect()` from a machine driver, plug/unplug TRS and TRRS headsets, test mic short/button events, and verify polarity flipping does not wedge future IRQs.
- Beep tests exercise `EV_SND` input events and the `beep` sysfs attribute at the supported rate buckets and confirm DAPM enables/disables the `Beep` pin.
- GPIO tests request lines 2, 3, 5, and 6, reject unsupported lines, set output direction and level, and verify I2C sleepable access behaves correctly.
