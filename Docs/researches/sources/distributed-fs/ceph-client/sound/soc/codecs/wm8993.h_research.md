# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8993.h

## Purpose

`wm8993.h` is the private register-definition header for the WM8993 ALSA SoC codec driver. It does not implement runtime logic; instead it defines the symbolic hardware contract consumed by `wm8993.c`: register addresses, register-count bounds, clock/FLL selector IDs, and mask/shift/width triples for fields inside the WM8993's 16-bit registers.

The header covers the codec's full control surface up to `WM8993_MAX_REGISTER` (`0x7e`), including power management, audio interface format and TDM controls, DAC/ADC paths, GPIO and interrupt status/masking, analogue input/output mixers, anti-pop and bias controls, microphone bias and jack-detect thresholds, FLL programming, clocking, write sequencer fields, charge-pump/Class-W controls, DC servo readback/trigger fields, EQ coefficient registers, digital pulls, and DRC controls.

## Important APIs, Types, and Constants

This file exposes preprocessor constants only. The driver-facing selector IDs are:

- `WM8993_SYSCLK_MCLK` and `WM8993_SYSCLK_FLL`, used by `wm8993_set_sysclk()` and `configure_clock()` to select the system clock source.
- `WM8993_FLL_MCLK`, `WM8993_FLL_BCLK`, and `WM8993_FLL_LRCLK`, used by `_wm8993_set_fll()` to encode the FLL reference source into `WM8993_FLL_CONTROL_5`.

The register address block starts with `WM8993_SOFTWARE_RESET` (`0x00`) and ends at `WM8993_DRC_CONTROL_4` (`0x7e`). `WM8993_REGISTER_COUNT` is `0x7f`, and `WM8993_MAX_REGISTER` is `0x7e`; the latter is passed into the driver's `regmap_config` as the hardware-visible register limit.

For each register field, the header generally provides:

- a value macro for single-bit fields, such as `WM8993_BIAS_ENA`, `WM8993_DAC_MUTE`, `WM8993_FLL_ENA`, and `WM8993_EQ_ENA`;
- a `_MASK` macro for clearing/updating fields with `snd_soc_component_update_bits()` or manual read-modify-write;
- a `_SHIFT` macro for packing computed values, for example `WM8993_FLL_OUTDIV_SHIFT`, `WM8993_FLL_FRATIO_SHIFT`, `WM8993_FLL_N_SHIFT`, `WM8993_CLK_SYS_RATE_SHIFT`, `WM8993_SAMPLE_RATE_SHIFT`, and `WM8993_BCLK_DIV_SHIFT`;
- a `_WIDTH` macro documenting field width.

Important register groups include:

- Power and bias: `WM8993_POWER_MANAGEMENT_1` through `WM8993_POWER_MANAGEMENT_3`, `WM8993_BIAS_ENA`, `WM8993_VMID_SEL_MASK`, ADC/DAC/output enable bits, thermal shutdown bits.
- Digital audio interface: `WM8993_AUDIO_INTERFACE_1` through `WM8993_AUDIO_INTERFACE_4`, `WM8993_AIF_FMT_MASK`, `WM8993_AIF_WL_MASK`, BCLK/LRCLK direction and inversion, LRCLK-rate fields, and ADC/DAC TDM fields.
- Clocking and FLL: `WM8993_CLOCKING_1` through `WM8993_CLOCKING_4`, `WM8993_BUS_CONTROL_1`, `WM8993_FLL_CONTROL_1` through `WM8993_FLL_CONTROL_5`.
- Audio controls: digital DAC/ADC volumes, sidetone routing, DRC registers, EQ registers `WM8993_EQ1` through `WM8993_EQ24`.
- Analogue routing: line input volumes, headphone/output/speaker volume fields, input/output mixer route bits, line-output mode/feedback fields, speaker boost fields.
- System/event controls: GPIO status/mask/polarity/debounce registers, write sequencer, charge pump, Class W, anti-pop, micbias/jack detect, DC servo trigger/readback fields, digital pull-up/pull-down fields.

## Control Flow and Usage

Runtime control flow lives in `wm8993.c`, but nearly every hardware operation uses constants from this header:

- Probe validates the chip by reading `WM8993_SOFTWARE_RESET`, resets it by writing `0xffff`, applies a small regmap patch, optionally configures `WM8993_GPIO1` for interrupt output, then registers the ASoC component and DAI.
- `wm8993_readable()` and `wm8993_volatile()` switch over the register-address macros to tell regmap which registers can be read and which should not be cached as stable state.
- Bias sequencing uses `WM8993_POWER_MANAGEMENT_1`, `WM8993_POWER_MANAGEMENT_2`, `WM8993_ANTIPOP1`, and `WM8993_ANTIPOP2` fields to bring VMID/bias up and down, enable thermal shutdown in active states, and manage line-output VMID buffering when single-ended line outputs are configured.
- Clock setup reads/modifies `WM8993_CLOCKING_2`, `WM8993_CLOCKING_1`, `WM8993_CLOCKING_3`, and `WM8993_AUDIO_INTERFACE_4` to choose MCLK/FLL, derive `CLK_SYS`, set sample-rate coding, choose BCLK divisors, and write LRCLK ratio.
- FLL setup computes divider fields in `wm8993.c`, then packs them through this header's masks/shifts into `WM8993_FLL_CONTROL_1` through `WM8993_FLL_CONTROL_5`. The code disables `WM8993_FLL_ENA` before changing dividers, writes N/K/fratio/outdiv/refdiv/source, re-enables the FLL, and optionally waits for `WM8993_FLL_LOCK_EINT`.
- DAI format and TDM setup use `WM8993_BCLK_DIR`, `WM8993_LRCLK_DIR`, `WM8993_AIF_BCLK_INV`, `WM8993_AIF_LRCLK_INV`, `WM8993_AIF_FMT_MASK`, `WM8993_AIFADC_TDM`, `WM8993_AIFADC_TDM_CHAN`, `WM8993_AIFDAC_TDM`, and `WM8993_AIFDAC_TDM_CHAN`.
- ALSA controls and DAPM widgets use register-address macros and bit positions for user-visible controls such as playback/capture volume, DAC mute/deemphasis, ADC high-pass filter, DRC parameters, EQ switch/gains, speaker DAC volume, muxes, clock supplies, ADCs, DACs, and speaker mixers.
- IRQ handling reads `WM8993_GPIO_CTRL_1` as interrupt status, reads `WM8993_GPIOCTRL_2` as interrupt mask, ignores the `WM8993_IRQ` pin-status bit, acts on `WM8993_TEMPOK_EINT` and `WM8993_FLL_LOCK_EINT`, then writes the status bits back to acknowledge handled events.

## State and Persistence Behavior

The header describes hardware state, while persistence behavior is controlled by the driver's regmap setup. `WM8993_MAX_REGISTER` bounds the regmap, and the register macros are used to build the readable and volatile register tables. Volatile registers include reset/status/readback paths such as `WM8993_SOFTWARE_RESET`, `WM8993_GPIO_CTRL_1`, `WM8993_DC_SERVO_0`, and DC-servo readback registers, so their values are not treated as persistent cache state.

Most configuration registers are cached through `REGCACHE_MAPLE` using `wm8993_reg_defaults` in `wm8993.c`. When bias moves from off to standby, regulators are enabled, cache-only mode is disabled, and `regcache_sync()` pushes cached writes back to hardware. When bias moves to off, the driver enters cache-only mode and marks the cache dirty before disabling regulators. This means values written through macros in this header can persist logically across power transitions even though physical codec registers lose state.

Suspend/resume has special FLL handling. Suspend stops the FLL with `_wm8993_set_fll(..., Fout = 0)` but saves the previous FLL reference/output values in `wm8993_priv`. Resume forces standby and restarts the FLL when saved state indicates it was active.

EQ persistence is split between ALSA controls and platform ReTune Mobile configuration. If platform data supplies ReTune profiles, `wm8993_hw_params()` selects the closest profile by sample rate, disables `WM8993_EQ_ENA`, writes `WM8993_EQ2` onward from the selected profile, then restores the previous EQ enable state.

## Dependencies

Directly, this header has no includes and depends only on preprocessor use by C files. It is private to the codec implementation and protected by `WM8993_H`.

Its practical dependencies are the Linux ASoC and regmap subsystems that consume these constants in `wm8993.c`:

- regmap for 8-bit register addresses, 16-bit register values, readable/volatile classification, defaults, cache synchronization, I2C register access, and patch registration;
- ASoC component/DAI/DAPM APIs for controls, routes, power widgets, bias-level transitions, DAI format, TDM, mute, and hardware-parameter callbacks;
- regulator framework for the six codec supplies;
- I2C and IRQ APIs for device probing and interrupt handling;
- `include/sound/wm8993.h` for platform data, including ReTune Mobile settings, lineout topology, micbias timing/level, and jack-detect thresholds;
- `wm_hubs.h` and the shared Wolfson hub helpers for analogue controls, routes, VMID handling, and headphone/DC-servo behavior.

## Integration Points

The strongest integration point is `sound/soc/codecs/wm8993.c`, which includes this private header and relies on it for every hardware register access. Changes to register addresses, masks, or shifts are ABI-like changes for the driver-hardware contract.

Board/platform integration enters through `struct wm8993_platform_data` in the public `include/sound/wm8993.h`, but the effects are applied with private macros here: lineout differential/single-ended behavior affects anti-pop VMID buffer use and `wm_hubs_handle_analogue_pdata()`, micbias levels and jack thresholds map to `WM8993_MICBIAS` fields, and ReTune Mobile profiles are written into the `WM8993_EQ*` register block.

The ASoC machine driver interacts indirectly through standard DAI operations: `.set_sysclk`, `.set_pll`, `.set_fmt`, `.hw_params`, `.set_tdm_slot`, and stream mute. Those callbacks encode machine-level clocking/audio choices into the bitfields defined here.

User-space ALSA mixer controls also map indirectly to this header. Mixer reads/writes eventually manipulate the DRC, EQ, ADC/DAC, sidetone, boost, and route bits represented by these macros.

## Risks and Edge Cases

- The header is generated-style register metadata. A wrong address, mask, or shift silently programs the wrong hardware bit; failures may show up as missing audio, unstable clocks, bad bias sequencing, interrupt storms, or pops/clicks rather than compile errors.
- Several symbolic names intentionally repeat for volume-update bits shared by left/right register pairs, such as `WM8993_DAC_VU`, `WM8993_ADC_VU`, `WM8993_HPOUT1_VU`, `WM8993_SPKOUT_VU`, and input volume-update names. This is valid C because the definitions are identical, but edits must keep duplicate definitions consistent.
- `WM8993_INPUTS_CLAMP_SHIFT` is documented as bit 7 while the mask/value is `0x0040` (bit 6). That mismatch is a research flag: code using the value macro is safe, but code packing from `_SHIFT` would target a different bit. The current driver does not appear to use the shift macro directly.
- Some driver code writes literal field values, such as audio interface format/word-length encodings and VMID selection values, rather than exclusively using named enum values. That makes the masks in this header critical but leaves semantic values implicit.
- FLL programming depends on safe bounds: Fref must be divided down to no more than 13.5 MHz, Fvco target selection must find a valid outdiv, and N/K fields must fit the documented masks. Header changes to FLL masks/shifts would directly affect clock lock.
- Regmap cache correctness depends on readable/volatile lists staying aligned with the register map. If a status/readback register is made cacheable or an ordinary control register is omitted from readable/default handling, suspend/resume and power-off cache replay can misbehave.
- GPIO/IRQ behavior is sensitive to `WM8993_GPIO_CTRL_1`, `WM8993_GPIOCTRL_2`, `WM8993_IRQ`, and event-bit definitions. Incorrect mask/status definitions can prevent FLL lock completion or fail to acknowledge interrupts.
- Analogue pop/click behavior depends on ordering and exact anti-pop/bias bits. Mask mistakes in `WM8993_ANTIPOP1`, `WM8993_ANTIPOP2`, `WM8993_POWER_MANAGEMENT_1`, or headphone/DC-servo fields can cause audible artifacts or unsafe output sequencing.

## Test Signals

Useful validation signals for this header are mostly integration-level:

- Build coverage: compile the WM8993 codec driver with `CONFIG_SND_SOC_WM8993` enabled. Because this header is macro-only, compile failures mostly catch renamed/removed macros, not incorrect values.
- Probe logs: successful I2C probe reads chip ID `0x8993`, writes reset, applies the regmap patch, registers the codec, and either requests the IRQ or runs without IRQ.
- Regmap/debugfs inspection: readable registers should match the address list through `0x7e`; volatile status/readback registers should not be stale across reads.
- Audio smoke tests: playback and capture at supported rates from 8 kHz through 48 kHz and formats S16, S20_3LE, S24, and S32 should configure `CLK_SYS`, BCLK, LRCLK, ADC/DAC enables, and mute without errors.
- Clock tests: `.set_sysclk` with MCLK and `.set_pll` with MCLK/BCLK/LRCLK references should produce FLL lock, or no timeout warning when IRQ is available and `WM8993_FLL_LOCK_EINT` is delivered.
- Mixer tests: ALSA controls for playback/capture volume, DAC mute, ADC HPF, DRC controls, EQ controls/ReTune profiles, sidetone, and speaker DAC volume should update the expected registers and survive bias off/on via regcache sync.
- DAPM route tests: enabling paths to headphones, lineouts, speakers, capture ADCs, and sidetone should toggle the documented power/mixer bits and not leave VMID/bias/clock supplies stuck on unexpectedly.
- Power-management tests: suspend/resume after active FLL/audio use should stop and restart the FLL, restore cached register state, and avoid regulator imbalance.
- IRQ tests: thermal warning and FLL-lock interrupt paths should read, mask, process, and acknowledge `WM8993_GPIO_CTRL_1` correctly.
