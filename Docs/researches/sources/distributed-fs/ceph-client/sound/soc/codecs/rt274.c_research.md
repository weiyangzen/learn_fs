# sources/distributed-fs/ceph-client/sound/soc/codecs/rt274.c

`rt274.c` is the ASoC I2C driver for Realtek RT274. It exposes one bidirectional DAI (`rt274-aif1`) and models the codec through HDA-style verb addresses carried over the Realtek `rl6347a` register transport.

Important state is kept in `struct rt274_priv`: the regmap, component, I2C client, jack object, delayed jack work, sysclk/clock source, BCLK ratio, master/slave flag, and a copied vendor-index cache. Probe verifies `RT274_VENDOR_ID`, resets the codec, applies pad/coefficient/combo-jack/DC-calibration/pin/I2S/IRQ setup writes, programs unsolicited HP/MIC events, requests a threaded IRQ when present, and registers the ASoC component. Component probe schedules an initial jack poll.

Core APIs are the regmap callbacks, jack helpers, DAI ops, PM hooks, DAPM graph, and I2C probe. `rt274_hw_params()` accepts only 44.1/48 kHz, checks sysclk family matching, encodes channel count and sample width into DAC/ADC stream-format verbs, and updates I2S length fields. `rt274_set_dai_fmt()`, `set_sysclk()`, `set_pll()`, `set_bclk_ratio()`, and `set_tdm_slot()` program the interface. Jack IRQ clears the IRQ bit, reads HP/MIC pin sense verbs, reports ALSA jack status, and issues a wakeup event.

State persistence is regcache-based: suspend switches cache-only and marks dirty; resume replays the vendor index cache and syncs cached verb defaults. Risks are mostly hardware sequencing risks: magic coefficient writes, strict clock/rate matching, PLL setup depending on prior BCLK ratio, and jack reporting depending on machine-driver jack registration. Test signals include probe/vendor-ID success, playback/capture at supported rates and widths, HP/line/DMIC/MIC DAPM routes, IRQ jack reports, TDM 2/4 slots, invalid clock/rate handling, and suspend/resume restoration.
