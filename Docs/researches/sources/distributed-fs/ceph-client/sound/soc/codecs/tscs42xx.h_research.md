# sources/distributed-fs/ceph-client/sound/soc/codecs/tscs42xx.h

## Purpose

`tscs42xx.h` is the private register-definition header for the Tempo Semiconductor TSCS42xx ALSA SoC codec driver. It exposes symbolic register addresses, bit offsets, field masks, raw field values, and pre-shifted register values used by `tscs42xx.c` to program codec controls over I2C/regmap. The header is not an API boundary for other kernel subsystems; it is a hardware map that lets the C driver express volume, input routing, digital audio interface, converter, power, PLL, DSP coefficient RAM, and dynamics-processing operations without open-coded constants.

## Important APIs, Types, and Macros

The only C type-like API is an anonymous enum defining `TSCS42XX_PLL_SRC_XTAL`, `TSCS42XX_PLL_SRC_MCLK1`, `TSCS42XX_PLL_SRC_MCLK2`, and `TSCS42XX_PLL_SRC_CNT`. The driver uses these values to iterate possible external clock names and to select PLL reference inputs during component probe.

Register address macros cover the flat TSCS42xx register space, including analog and digital gain registers (`R_HPVOLL`, `R_HPVOLR`, `R_SPKVOLL`, `R_SPKVOLR`, `R_DACVOLL`, `R_DACVOLR`, `R_ADCVOLL`, `R_ADCVOLR`, `R_INVOLL`, `R_INVOLR`), input routing (`R_INMODE`, `R_INSELL`, `R_INSELR`), audio interface setup (`R_AIC1`, `R_AIC2`), converter and sample-rate registers (`R_CNVRTR0`, `R_ADCSR`, `R_CNVRTR1`, `R_DACSR`), power (`R_PWRM1`, `R_PWRM2`), configuration (`R_CTL`, `R_CONFIG0`, `R_CONFIG1`, `R_DMICCTL`), compressor/limiter/expander and effects registers (`R_CLECTL` through `R_FXCTL`), DAC coefficient RAM windows (`R_DACCRWRL` through `R_DACCRSTAT`), PLL registers (`R_PLLCTL9` through `R_PLLREFSEL`), identity/reset (`R_DEVIDL`, `R_DEVIDH`, `R_RESET`), and DAC multiband compressor registers (`R_DACMBCEN` through `R_DACMBCREL3H`).

The `RM(m, b)` and `RV(v, b)` helpers shift masks and values by bit offset. Each register block generally follows a generated pattern: `FB_*` bit offsets, `FM_*` unshifted masks, `FV_*` raw enumerated values, `RM_*` shifted masks, and `RV_*` shifted values. The C driver relies on `RM_*` for `snd_soc_component_update_bits()` masks and on `RV_*`/`FV_*` for register writes and control enumerations.

Major field groups include DAI format and clocking (`FB_AIC1_BCLKINV`, `FB_AIC1_MS`, `FB_AIC1_LRP`, `FB_AIC1_WL`, `FB_AIC1_FORMAT`, plus `RV_AIC1_FORMAT_RIGHT/LEFT/I2S`), converter mute/polarity/high-pass controls (`R_CNVRTR0`, `R_CNVRTR1`), ADC/DAC sample-rate base and multiplier fields (`R_ADCSR`, `R_DACSR`), power enables for ADC, mic bias, digital engine, headphone, speaker, input select, and VREF (`R_PWRM1`, `R_PWRM2`), dynamic processing controls (`R_CLECTL`, `R_MUGAIN`, thresholds, ratios, attack/release registers), coefficient RAM address/data/status macros, and PLL power/reference/lock controls.

## Control Flow and Usage

This header has no executable control flow. Its effective control flow is generated by compile-time substitution in `tscs42xx.c`. The usual call path is: ALSA/ASoC invokes a driver operation or mixer control, `tscs42xx.c` selects a register and mask from this header, then calls regmap or ASoC component helpers to write the device.

Examples visible from the sibling driver are representative: mixer controls use volume and route field definitions such as `R_HPVOLL`, `R_HPVOLR`, `FB_INSELL_MICBSTL`, and related `FV_*` values; DAI setup writes `R_AIC1` with `RM_AIC1_WL`, `RM_AIC1_MS`, and format values; sample-rate setup updates `R_DACSR` and `R_ADCSR` with base-rate and multiplier fields; power and mute paths use `R_CNVRTR0`, `R_CNVRTR1`, `R_PWRM*`, and PLL definitions; coefficient RAM writes use `R_DACCRADDR`, `R_DACCRWRL`, and `R_DACCRSTAT`.

## State and Persistence Behavior

The header itself persists no runtime state. It defines the shape of state held in the physical codec registers and cached by the driver regmap. State categories represented here include analog gain levels, input selection and boost, DAI master/slave and word format, ADC/DAC sample-rate divisors, power rails and block enables, digital mic controls, compressor/limiter/expander coefficients, DAC coefficient RAM, PLL dividers and lock state, device identity, and reset behavior.

The reset value `FV_RESET_ENABLE`/`RV_RESET_ENABLE` is used by the C driver to restore hardware defaults. Coefficient RAM macros describe write/read windows and busy status; the sibling driver keeps a software cache for coefficients and flushes it when PLLs are locked. PLL lock bits and reference-select macros are part of the synchronization contract between driver state and hardware.

## Dependencies and Integration Points

The file is included by `sources/distributed-fs/ceph-client/sound/soc/codecs/tscs42xx.c`. It depends only on the preprocessor and kernel C integer semantics; no kernel headers are included here. The driver is built as `snd-soc-tscs42xx.o` under `CONFIG_SND_SOC_TSCS42XX`, which depends on I2C and selects `REGMAP_I2C`.

Integration is through standard Linux ASoC and regmap paths in the C file: ASoC controls, DAPM widgets/routes, DAI operations, I2C probe, regmap cache, and clock framework calls all consume these constants. The header is not used by `tscs454.c`; TSCS454 has a separate paged register map in `tscs454.h`.

## Risks and Edge Cases

The include guard is named `__WOOKIE_H__`, which is unrelated to the filename and can collide with another accidental guard name or confuse maintenance tooling. The file also contains at least one suspicious generated macro, `RV_ADCSR_ABR_`, that references `FV_ADCSR_ABR_`, which is not defined in this header. That macro appears unused by the current sibling driver, but any future use would fail compilation.

Several macros use raw hex widths and manual bit shifting without static validation. Incorrect `FM_*` or `FB_*` values can silently program the wrong bits. Because much of the file appears generated, typographical drift such as `Fiel Offsets`, unrelated guard naming, and inconsistent macro names should be treated as signals that new register additions need careful compile and hardware review.

Some register masks are unshifted (`FM_*`) while `RM_*` are shifted; call sites must use the right class. Mixing these conventions can produce wrong update masks. The sibling driver already shows a likely typo pattern around ADC sample-rate setup where DAC masks are used against `R_ADCSR`; review work touching this header should verify mask/register pairings against the datasheet.

## Test Signals

Compile coverage should include `CONFIG_SND_SOC_TSCS42XX=m` or `y` with `W=1` if available, because undefined or stale macros only surface when referenced. Runtime smoke tests should probe an I2C TSCS42xx device or regmap-backed test target, confirm reset and device ID reads, enumerate ALSA controls, and exercise representative playback/capture paths at 8 kHz through 96 kHz.

Useful targeted tests include DAI format transitions for I2S/left/right justified modes, BCLK ratio changes of 32/40/64, ADC and DAC mute/unmute, coefficient RAM writes followed by PLL lock and cache flush, and regmap cache sync around reset. Hardware validation should watch for PLL lock, absence of underruns, correct channel routing, and no unexpected pops during power or mute transitions.
