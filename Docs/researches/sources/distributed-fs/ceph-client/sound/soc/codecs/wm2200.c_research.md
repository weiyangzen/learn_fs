# sources/distributed-fs/ceph-client/sound/soc/codecs/wm2200.c

## Purpose
`wm2200.c` is the ALSA SoC codec driver for the Wolfson WM2200 audio codec. It binds over I2C, powers and resets the chip, exposes the codec's controls, DAPM widgets, routes, AIF DAI, FLL, two ADSP1 DSP cores, and runtime-PM behavior, and maps the generated WM2200 register definitions into a regmap cache with paged DSP memory windows.

## Important APIs, Types, and Functions
- `struct wm2200_priv` is the driver-private state: two `struct wm_adsp` DSPs, regmap, component/device pointers, platform data, DBVDD/LDOVDD supplies, optional LDO/reset GPIOs, FLL lock completion and cached FLL parameters, revision, configured SYSCLK rate, and a `symmetric_rates` flag.
- `wm2200_ranges`, `wm2200_dsp1_regions`, and `wm2200_dsp2_regions` describe paged DSP DM/PM/ZM address ranges so regmap and `wm_adsp` can access DSP memories beyond the normal register map.
- `wm2200_reg_defaults`, `wm2200_volatile_register()`, `wm2200_readable_register()`, and `wm2200_regmap` define the 16-bit register cache, readable/volatile policy, DSP range handling, and `REGCACHE_MAPLE` persistence model.
- `wm2200_reva_patch` is registered for revisions A/B before reset so early silicon receives required register patches and default EQ/audio-interface tuning.
- `wm2200_reset()` uses the optional reset GPIO when present, otherwise writes `0x2200` to `WM2200_SOFTWARE_RESET`.
- `wm2200_snd_controls` exposes input/output gains and mutes, OSR switches, EQ and LHPF coefficient bytes, RxANC selection, PDM output mute, and `WM_ADSP_FW_CONTROL()` controls for DSP1/DSP2 firmware.
- The mixer/DSP enum macros generate source-select muxes and volume controls for OUT, AIF TX, EQ, LHPF, and DSP routing blocks.
- `wm2200_dapm_widgets` and `wm2200_dapm_routes` define SYSCLK, charge pumps, MICBIAS, regulators, physical inputs, AIF RX/TX endpoints, EQ/LHPF/DSP blocks, AEC loopback, headphone/earpiece/speaker outputs, and the large internal mixer graph.
- `wm2200_set_fmt()`, `wm2200_hw_params()`, and `wm2200_dai_probe()` implement AIF format, master/inversion, BCLK/LRCLK/sample-rate/word-length programming, and GPIO1-driven symmetric-rate detection.
- `fll_factors()` and `wm2200_set_fll()` compute and program FLL dividers, fractional parameters, source selection, enable/disable sequencing, runtime-PM references, and lock waiting.
- `wm2200_i2c_probe()`, `wm2200_i2c_remove()`, `wm2200_runtime_suspend()`, and `wm2200_runtime_resume()` own device lifecycle, supplies/GPIOs, IRQ, platform-data programming, ASoC registration, and regcache synchronization.

## Control Flow
I2C probe allocates `wm2200_priv`, initializes the FLL completion, creates the I2C regmap, fills the two ADSP descriptors, initializes each DSP with `wm_adsp1_init()`, copies platform data, requests DBVDD/LDOVDD, and enables them. It then enables the optional LDO GPIO, requests the optional reset GPIO, reads and validates the chip ID, reads the revision, registers the A/B silicon patch when needed, and resets the chip.

After reset, probe applies platform defaults: GPIO register values, digital volume update bits, fixed slot assignments for six TX/RX channels, MICBIAS levels/options, and input mode/DMIC supply selections. If an IRQ is available it requests a threaded IRQ and unmasks FLL lock interrupts. Runtime PM is marked active/enabled and the component plus single DAI named `wm2200` are registered.

ASoC component probe only records the component pointer. DAI probe reads GPIO1; if GPIO1 is configured to a nonzero function, it treats LRCLK as shared and sets `symmetric_rates`, causing capture LRCLK programming to follow playback/shared RX register usage. `set_fmt` accepts only DSP_A and I2S, handles codec bit/frame master modes, applies BCLK/LRCLK inversion bits, and writes format selection. `hw_params` derives word length, frame length, BCLK, sample-rate code, BCLK divider table selection based on SYSCLK family, LRCLK divisor, slot length, and sample-rate register programming. SYSCLK must have been set first through `set_sysclk`, and only 22.5792 MHz or 24.576 MHz are accepted.

FLL setup validates the source, computes factors from reference/output rates, disables the FLL while reprogramming, writes outdiv/fratio/N/theta/lambda/ref-divider/source fields, enables fractional/EFS mode when needed, clears stale completions, takes a runtime-PM reference, enables the FLL and SYSCLK, then waits for lock. With an IRQ it waits briefly on `fll_lock` and also reads raw status; without an IRQ it polls raw status for longer. Disabling the FLL clears the enable bit and drops the runtime-PM reference only if the driver believed the FLL was previously running.

The threaded IRQ reads interrupt status and mask, handles unmasked FLL lock by completing `fll_lock`, acknowledges handled status bits, and reports `IRQ_NONE` if nothing unmasked was pending. Remove disables runtime PM, frees the IRQ, asserts reset, disables the optional LDO GPIO, and disables core supplies. Runtime suspend makes regmap cache-only/dirty, disables LDO and core supplies; runtime resume reenables supplies/LDO, leaves cache-only mode, and syncs cached registers.

## State and Persistence Behavior
Persistent driver state is mostly cached hardware configuration: `sysclk`, FLL source/reference/output, silicon revision, platform-data-derived GPIO/MICBIAS/input-mode programming, DSP metadata, and `symmetric_rates`. Register state persists through `REGCACHE_MAPLE`; suspend marks the cache dirty before power removal so resume rewrites cached values after supplies and LDO are restored. DSP memory windows are treated as volatile/readable ranges because their page windows and mapped memory contents should not be trusted as normal cached registers.

FLL runtime state also drives power management. Enabling a nonzero FLL output takes a runtime-PM reference that is released on FLL disable or lock failure. The lock completion is transient and is cleared before each enable attempt. Platform data from `<sound/wm2200.h>` persists only in `wm2200_priv` and programmed registers; there is no devicetree parsing in this file beyond GPIO/regulator lookup names handled by kernel frameworks.

## Dependencies and Integration Points
The driver depends on ALSA ASoC component/DAI/DAPM/control APIs, `wm_adsp`/`cs_dsp` firmware helpers, Linux regmap, I2C, regulators, GPIO descriptors, runtime PM, IRQ completions, and the generated local `wm2200.h` register definitions plus public `<sound/wm2200.h>` platform data. Build integration is through `snd-soc-wm2200-y := wm2200.o` and `obj-$(CONFIG_SND_SOC_WM2200) += snd-soc-wm2200.o` in the codecs Makefile.

Machine drivers integrate by instantiating I2C device ID `wm2200`, supplying DBVDD/LDOVDD and optional `CPVDD`/`AVDD` DAPM regulators, optional GPIOs named `wlf,ldo1ena` and `reset`, optional IRQ, and platform data for GPIO defaults, input modes, DMIC supplies, and MICBIAS configuration. Runtime audio integration is via the single DAI `wm2200` with stereo playback/capture, 8-48 kHz rates, and S16_LE/S20_3LE/S24_LE/S32_LE formats. DSP firmware and controls are integrated through `WM_ADSP1()` widgets and `WM_ADSP_FW_CONTROL()` controls for DSP1 and DSP2.

## Risks and Edge Cases
- `wm2200_hw_params()` requires `set_sysclk()` to have run and accepts only two SYSCLK rates; otherwise stream startup fails with `-EINVAL`.
- DAI format support is narrow: only DSP_A and I2S are accepted, so machine drivers requesting left/right justified or unsupported clocking combinations will fail.
- FLL lock sequencing depends on either a correctly wired IRQ or raw-status polling. Missing/masked/incorrect IRQs can add latency or cause lock timeouts.
- Runtime-PM reference accounting is tied to `wm2200->fll_fout`; error paths and repeated FLL reconfiguration should be tested to avoid stale active references or premature suspend.
- Register cache restore assumes platform reset/LDO/power sequencing leaves the chip receptive before `regcache_sync()`. Bad board timing can surface as resume sync failures, though the current code does not check the return value of `regcache_sync()`.
- Many probe-time `regmap_write()`/`regmap_update_bits()` calls for platform defaults, volume-update bits, slots, MICBIAS, and input mode ignore return values, so partial I/O failures can leave hardware configured differently from expected without aborting probe.
- The DAPM graph and mixer source values are large and macro-generated; route/source mismatches are likely to show up only when exercising specific paths such as DSP auxiliary inputs, AEC loopback, or LHPF/EQ mixers.
- `wm2200_volatile_register()` and `wm2200_readable_register()` use `window_start + window_len` as the inclusive upper bound, which is one past a conventional length-based range.

## Test Signals
Useful validation includes successful I2C probe with correct ID/revision logs, failure on bad ID, A/B revision patch registration, reset via both GPIO and software paths, regulator/LDO/reset unwind on injected failures, component/DAI registration, ALSA control enumeration/read-write for gains, mutes, EQ/LHPF bytes, RxANC, and DSP firmware controls, and DAPM path activation from each input/AIF/tone/DSP/EQ/LHPF/AEC source to OUT1 earpiece pins, OUT2 speaker, AIF TX, and DSP routes.

Audio-interface tests should cover `set_sysclk` rejection and acceptance, DSP_A/I2S formats, master/slave and inversion combinations, all supported PCM formats, sample rates in the declared 8-48 kHz range, BCLK divisor selection for 24.576 MHz and 22.5792 MHz clock families, and symmetric-rate behavior when GPIO1 is configured. FLL tests should cover integer and fractional factors, MCLK1/MCLK2/BCLK sources, no-IRQ polling, IRQ completion, timeout handling, disable/re-enable cycles, and runtime-PM reference behavior. Power tests should exercise idle suspend/resume with regcache sync, FLL-active runtime behavior, remove cleanup, and resume after hardware reset or LDO removal.
