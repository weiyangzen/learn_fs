# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8996.h

## Purpose

`wm8996.h` is the private register definition header for the Wolfson WM8996 ASoC codec driver. It is included by `wm8996.c` together with the public platform header `<sound/wm8996.h>`, and supplies the numeric contract between the driver and the codec's 16-bit I2C/register-map interface.

The header has three roles:

- Define external clock selector IDs used by the driver-facing DAI/FLL paths: `WM8996_SYSCLK_MCLK1`, `WM8996_SYSCLK_MCLK2`, `WM8996_SYSCLK_FLL`, `WM8996_FLL_MCLK1`, `WM8996_FLL_MCLK2`, `WM8996_FLL_DACLRCLK1`, and `WM8996_FLL_BCLK1`.
- Expose the default jack-detection helper declaration `wm8996_detect()` and its polarity callback type.
- Define the full sparse WM8996 register address map, maximum register, register count, and per-field mask/shift/width macros used by regmap defaults, mixer controls, DAPM widgets/routes, clock programming, interrupt handling, GPIO, jack detection, DC servo, DSP/EQ/DRC, and PDM speaker setup.

This file contains no executable code, but it is central to almost every side-effecting operation in `wm8996.c`; incorrect constants would translate directly into incorrect hardware writes.

## Important APIs, Types, And Macros

- `typedef void (*wm8996_polarity_fn)(struct snd_soc_component *component, int polarity)`: board/machine callback used by `wm8996_detect()` when microphone ground polarity is flipped during accessory detection.
- `int wm8996_detect(struct snd_soc_component *component, struct snd_soc_jack *jack, wm8996_polarity_fn polarity_cb)`: exported GPL helper implemented in `wm8996.c`. It enables default headset/headphone/button detection, stores jack state in the codec private data, configures MICBIAS and detection registers, forces required DAPM supplies, and unmasks MICD/HPDET interrupts.
- `WM8996_REGISTER_COUNT` and `WM8996_MAX_REGISTER`: define the sparse register-map size assumptions used by `wm8996_regmap` in `wm8996.c`; `WM8996_MAX_REGISTER` is `0x31FF`, covering the write-sequencer window.
- Register address macros: examples include `WM8996_POWER_MANAGEMENT_1..8`, `WM8996_AIF_CLOCKING_1`, `WM8996_FLL_CONTROL_1..6`, `WM8996_AIF1_*`, `WM8996_AIF2_*`, `WM8996_DSP1_*`, `WM8996_DSP2_*`, `WM8996_GPIO_1..5`, `WM8996_INTERRUPT_STATUS_*`, `WM8996_LEFT_PDM_SPEAKER`, and `WM8996_WRITE_SEQUENCER_0..511`.
- Field macros: each meaningful hardware field usually has a value macro plus `_MASK`, `_SHIFT`, and `_WIDTH` forms. Driver code mainly uses masks and shifts with `snd_soc_component_update_bits()` or `regmap_update_bits()`.

The top-level register groups are organized by hardware block:

- Reset, power, analog input/output, MICBIAS, LDO, accessory/headphone/microphone detect, charge pump, DC servo, analog headphone.
- Control interface and write sequencer.
- AIF/system clocking, FLL, AIF1/AIF2 formatting, BCLK/LRCLK, TDM slot/channel configuration.
- DSP1/DSP2 volume, TX/RX filters, DRC, and RX EQ coefficients.
- DAC and DSP mixer routing, soft mute, oversampling, sidetone.
- GPIO, pull controls, interrupt status/masks/control.
- PDM speaker controls and a 512-entry write-sequencer register space.

## Control Flow And Usage

The header's constants are consumed through several major driver flows in `wm8996.c`:

- Probe and reset: `wm8996_i2c_probe()` initializes `wm8996_regmap`, reads `WM8996_SOFTWARE_RESET` as the chip ID, checks `WM8996_CHIP_REVISION`, optionally writes reset, then applies platform defaults using masks such as `WM8996_INL_MODE_MASK`, `WM8996_GP*_FN_MASK`, `WM8996_MICD_BIAS_SRC`, and volume update bits.
- Regmap validation: `wm8996_readable_register()` lists readable register address macros from this header. `wm8996_volatile_register()` marks reset/status/readback/detection registers volatile, including interrupt status, DC servo readback, FLL status, MIC detect, and headphone detect registers.
- Clock selection: `wm8996_set_sysclk()` accepts the header's `WM8996_SYSCLK_*` IDs, maps them to `WM8996_SYSCLK_SRC_MASK`, toggles `WM8996_SYSCLK_ENA`, and sets rate/divider bits such as `WM8996_SYSCLK_DIV`, `WM8996_SYSCLK_RATE`, and `WM8996_LFCLK_ENA`.
- FLL programming: `wm8996_set_fll()` accepts `WM8996_FLL_*` source IDs, calculates dividers, writes `WM8996_FLL_CONTROL_2..5`, `WM8996_FLL_EFS_1..2`, enables `WM8996_FLL_ENA`, triggers `WM8996_FLL_SWITCH_CLK`, and waits for `WM8996_FLL_LOCK_STS` or the `WM8996_FLL_LOCK_EINT` interrupt.
- Jack/accessory detection: `wm8996_detect()` enables MICD via `WM8996_MICD_ENA`, adjusts MICD rate fields, clears MICBIAS discharge fields, and unmasks `WM8996_IM_MICD_EINT` and `WM8996_IM_HP_DONE_EINT`. IRQ handlers later read `WM8996_MIC_DETECT_3`, `WM8996_HEADPHONE_DETECT_2`, `WM8996_HP_LVL_MASK`, `WM8996_MICD_VALID`, and `WM8996_MICD_STS`, and may flip `WM8996_HPOUT1FB_SRC`, `WM8996_MICD_SRC`, and `WM8996_MICD_BIAS_SRC`.
- Interrupt handling: `wm8996_irq()` reads `WM8996_INTERRUPT_STATUS_2`, applies `WM8996_INTERRUPT_STATUS_2_MASK`, clears handled bits by writeback, completes waits for DC servo/FLL using `WM8996_DCS_DONE_*_EINT` and `WM8996_FLL_LOCK_EINT`, reports FIFO errors, and dispatches MICD/HPDET handlers.
- ALSA controls and routing: SOC control declarations and DAPM definitions use address and bit macros for input gain, DAC/DSP volumes, mute bits, EQ/DRC settings, sidetone, soft mute, oversampling, power bits, mixer route bits, and PDM speaker controls.
- GPIO integration: optional gpiolib support maps GPIO register fields `WM8996_GP*_FN_MASK`, direction/level masks, pull controls, and GPIO register offsets to Linux GPIO operations.

## State And Persistence Behavior

The header itself has no state, but it defines the persisted hardware and regcache state shape:

- Regmap defaults in `wm8996.c` are keyed by the register address macros here. Those defaults seed `REGCACHE_MAPLE`, so the values persist in the software cache while supplies or the external LDO are disabled.
- Volatile macros identify registers whose values should not be trusted from cache, such as status, readback, and detect-result registers.
- Power-management state is distributed across `WM8996_POWER_MANAGEMENT_*`, clock gates, LDO/MICBIAS bits, and DAPM-managed supply widgets. Bad field definitions can leave analog paths powered, clocked incorrectly, or unavailable.
- Runtime state such as FLL lock, DC servo completion, and accessory detection is represented in `wm8996_priv`, but transitions are driven by register fields defined here.
- Platform data is applied once at probe through this register map: input modes, GPIO defaults, speaker mute sequence, and microphone detection default polarity become cached register state before component registration.

## Dependencies And Integration Points

- Linux ASoC component/DAI APIs: `struct snd_soc_component`, `struct snd_soc_jack`, mixer controls, DAPM widgets/routes, DAI ops, and jack reporting.
- Linux regmap: 16-bit register and 16-bit value bus, readable/volatile callbacks, maple cache, and update-bits helpers.
- Linux I2C: the WM8996 device is probed as an I2C codec; interrupt behavior depends on `i2c->irq`.
- Linux regulator and GPIO frameworks: supply enable/disable, cache dirtying on regulator disable, optional `wlf,ldo1ena` GPIO, and optional GPIO chip registration.
- Board/platform data from `<sound/wm8996.h>`: input modes, GPIO defaults, IRQ flags, microphone detection defaults, speaker mute sequence, and ReTune Mobile configuration are all translated into this header's register fields.
- Hardware integration: the macros encode the datasheet contract for external MCLK inputs, FLL references, AIF1/AIF2 serial audio ports, microphone bias/detect circuits, headphone impedance detection, DSP/EQ/DRC blocks, and PDM speaker output.

## Risks And Edge Cases

- This is a generated-style register header with many repeated names. Some macros such as volume update bits are intentionally redefined for multiple registers with the same value; consumers must understand that they are alias-style definitions rather than independent symbols.
- The register map is sparse. `WM8996_MAX_REGISTER` is high because of the write-sequencer window, while `WM8996_REGISTER_COUNT` is much smaller. Readable/volatile lists must stay synchronized with address macros or regmap access may fail or cache invalid state.
- Bit mask/shift mistakes are high impact: they can corrupt adjacent hardware fields, especially in packed AIF TDM channel configuration, FLL divider programming, interrupt masks, and accessory-detection polarity fields.
- FLL and SYSCLK paths depend on valid source IDs from this header. Unsupported or mismatched constants return `-EINVAL`; wrong values could silently select a different physical clock.
- IRQ handling depends on write-1-to-clear status bits and inverse mask logic. Incorrect `*_EINT` or `IM_*` definitions could lose DC servo/FLL completions or leave jack detection unresponsive.
- Jack detection toggles microphone polarity and accessory feedback sources. Wrong `WM8996_HPOUT1FB_SRC`, `WM8996_MICD_SRC`, or `WM8996_MICD_BIAS_SRC` values can misclassify headsets/headphones or interfere with board-level polarity switching.
- Regcache persistence means reset/default definitions are not merely documentation. If defaults or volatile markings drift from silicon behavior, suspend/resume or regulator cycling can restore stale values.

## Test Signals

Useful validation signals for changes touching this header include:

- Build coverage for `sound/soc/codecs/wm8996.c` with `CONFIG_SND_SOC_WM8996`, and with/without `CONFIG_GPIOLIB`, to catch missing macros or duplicate-definition fallout.
- Regmap probe smoke test: I2C probe reads chip ID `0x8915`, reads revision through `WM8996_CHIP_REVISION`, initializes defaults, and registers the ASoC component without regmap readable/volatile errors.
- Clock/FLL tests: DAI `set_sysclk()` accepts MCLK1/MCLK2/FLL at supported rates, `set_pll()` programs FLL sources and observes `WM8996_FLL_LOCK_STS` or `WM8996_FLL_LOCK_EINT` before timeout.
- PCM path tests: AIF1 six-channel and AIF2 two-channel playback/capture at supported rates/formats exercise AIF BCLK/LRCLK, data width, TDM slot, power, and mixer field definitions.
- Mixer control tests: ALSA controls for capture/playback volume, mute, EQ, DRC, sidetone, oversampling, and speaker mute read/write expected registers without adjacent bit changes.
- Jack tests: calling `wm8996_detect()` reports headphone, lineout, headset microphone, removal, and button events; polarity callback fires when MICD measurements require a polarity flip.
- Suspend/resume or regulator-cycle tests: cache-only transitions, regulator-disable dirty marking, and regcache sync restore nonvolatile register state while status registers remain live.
