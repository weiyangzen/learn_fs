# sources/distributed-fs/ceph-client/sound/soc/codecs/rt5663.h

## Purpose

`rt5663.h` is the private register and bit-field contract for the RT5663 ASoC codec driver. It defines the symbolic hardware map consumed by `rt5663.c`, including both original RT5663 and v2/RT5668-style register ranges, common bit masks, variant-specific bit masks, DAI IDs, clock source enums, ASRC filter selectors, and the exported ASRC helper prototype.

The header includes `<sound/rt5663.h>`, the public platform-data header that carries manual DC offset and impedance sensing table configuration. This private header adds all of the low-level constants needed to turn that board data into codec register programming.

## Important APIs, Types, and Definitions

Register address definitions cover:

- Basic identity and output/input controls: reset, vendor ID registers, headphone amp, mono output/gain, AEC boost, IN1/IN2/IN3/IN4, and combo-jack type registers.
- ADC/DAC and mixer registers: DAC digital volume, ADC digital volume, ADC boost, sidetone, mono/stereo ADC mixers, AD/DA mixer, stereo DAC mixer, bypass DAC source, digital side mixer, and record mixers.
- Power, clock, and format registers: digital/analog power blocks, I2S1/I2S34/I2S5, ADDA clock/reset, fractional dividers, TDM registers, global clock, PLL registers, ASRC tracking, pre-divider gating, RC clock, and clock detection.
- Jack, GPIO, IRQ, and inline-command registers: IRQ controls/status, GPIO controls/status, jack detect controls, embedded jack type registers, inline command registers, mic-detect power, and four-button debounce/reset controls.
- Headphone, depop, DRE, impedance, and calibration registers: charge pump, soft volume/zero-cross, DRE, mic/headphone declick/decross, headphone impedance sensing maps and status, calibration status, HP logic, HP bias, combo-jack, and dummy/vendor tuning registers.
- DSP/control-style blocks: DRC, ALC/PGA, ADC EQ recovery/filter coefficients, scan mode, video/customer hidden IDs, and I2C bypass.

Important enum and API definitions:

- `enum { RT5663_SCLK_S_MCLK, RT5663_SCLK_S_PLL1, RT5663_SCLK_S_RCCLK }`: system clock source IDs accepted by `set_sysclk`.
- `enum { RT5663_PLL1_S_MCLK, RT5663_PLL1_S_BCLK1 }`: PLL input source IDs accepted by `set_pll`.
- `enum { RT5663_AIF, RT5663_AIFS }`: single DAI ID and count.
- `enum { RT5663_CLK_SEL_SYS = 0x0, RT5663_CLK_SEL_I2S1_ASRC = 0x1 }`: ASRC tracking source values.
- `enum { RT5663_DA_STEREO_FILTER = 0x1, RT5663_AD_STEREO_FILTER = 0x2 }`: filter mask bits for exported ASRC selection.
- `int rt5663_sel_asrc_clk_src(...)`: exported helper implemented in `rt5663.c` for machine drivers.

Important bit-field groups:

- I2S format fields for master/slave, BCLK polarity, data length, I2S/left/DSP_A/DSP_B/normal variants.
- TDM channel count and slot length fields, including data swap and BCLK-ratio length controls.
- PLL M/N/K fields and source masks, with separate source location for v2 (`RT5663_V2_PLL1_SRC_*`).
- ASRC enable and tracking fields, with v2 AD tracking in `RT5663_ASRC_3`.
- Jack detection and button fields for combo jack detection, external JD, IRQ inline mode, JD IRQ enables, embedded JD reset/normal, 4-button debounce, inline enable, and inline reset.
- Power masks for DAC/ADC, LDO DAC reference, VREF/FV/MB, boosts, JD, record mixers, combo jack, PLL, LDO2, and v2 mic-detect power.

## Control Flow

The header has no executable code except the external function declaration. It supports these control-flow paths in the implementation:

1. Probe reads vendor ID registers and selects one of two regmap configurations whose readable/volatile tables are expressed with these symbols.
2. Calibration and patch sequences write defined registers such as power, RC clock, GLB clock, ADDA clock, depop, headphone calibration, and dummy/vendor tuning registers.
3. DAI operations consume the I2S, PLL, TDM, BCLK, and sysclk definitions.
4. DAPM widgets and routes consume power, mixer, ASRC, ADC/DAC, boost, charge pump, and headphone bits.
5. Jack detection and button reporting consume the combo-jack, GPIO, IRQ, inline command, micbias, and embedded JD fields.
6. Machine drivers can call `rt5663_sel_asrc_clk_src()` with the filter mask and clock-source enums from this header.

## State and Persistence Behavior

This header does not allocate state. It defines register bits that determine persistent hardware state in the codec and software identifiers stored in `struct rt5663_priv` in `rt5663.c`. The state with the longest impact includes system clock source, PLL source and M/N/K codes, ASRC tracking source, TDM mode/slot width, ADC/DAC power, jack detect enable/polarity, micbias and combo-jack power, headphone DRE gain, and DC offset compensation registers.

Because regmap caching uses the readable/volatile classification from `rt5663.c`, each register macro in this header must stay synchronized with those switch tables. If a status register is not marked volatile or a writable persistent register is not readable where needed, suspend/resume and cache sync can restore incorrect state.

## Dependencies and Integration Points

The header depends on `<sound/rt5663.h>` for the public board/platform data. It is tightly coupled to `rt5663.c` and indirectly to:

- Linux ASoC component/DAI/DAPM control code that uses these register constants.
- The Realtek `rl6231` helper through PLL and divider fields used by the C implementation.
- Device tree binding `realtek,rt5663`, which describes the DC offset and impedance sensing properties later written through registers named here.
- Kconfig/Makefile entries for `SND_SOC_RT5663`.
- Machine drivers that include this header to call `rt5663_sel_asrc_clk_src()` and use `RT5663_DA_STEREO_FILTER`, `RT5663_AD_STEREO_FILTER`, and `RT5663_CLK_SEL_I2S1_ASRC`.

## Risks and Edge Cases

- The file intentionally has duplicate macro names for some fields, such as `RT5663_CBJ_DET_MASK`, because original and v2/embedded jack controls share semantics at different address groups. This is risky if future edits assume the first definition remains active; the preprocessor uses the later definition.
- `RT5663_SEL_GPIO1_SHIFT` is defined as `6` while `RT5663_SEL_GPIO1_MASK` is `(0x1 << 2)`. Current code uses the mask/value macros directly and does not shift by `RT5663_SEL_GPIO1_SHIFT`, but the shift constant looks inconsistent and could cause a bug if used later.
- The header exposes both common and variant-specific ASRC/PLL bit locations. Callers must branch on `codec_ver`; programming the wrong mask can silently affect unrelated bits.
- Large groups of "dummy" and vendor-tuning registers are named but not self-documenting. Maintenance depends on vendor sequences in `rt5663.c`.
- Register range differences are significant: original config maxes at `0x03f3`, while v2 maxes at `0x07fa`. Adding new definitions requires matching regmap range and readable/volatile updates.
- The exported ASRC API accepts generic `unsigned int` masks and source values; invalid values are rejected in implementation, but invalid filter combinations are not type-safe.

## Test Signals

Test signals for this header are mostly integration signals: successful compile of `rt5663.c`, no macro redefinition warnings beyond intentional same-value definitions, correct ALSA controls using the expected masks, DAI format/sysclk/PLL/TDM programming verified by regmap traces, ASRC selection via the exported helper on both codec versions, jack/button detection fields toggling the expected IRQ/status bits, and suspend/resume regcache tests showing no stale or incorrectly cached status registers.
