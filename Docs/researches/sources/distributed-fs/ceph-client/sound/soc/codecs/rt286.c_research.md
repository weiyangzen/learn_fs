# sources/distributed-fs/ceph-client/sound/soc/codecs/rt286.c

`rt286.c` drives Realtek RT286/RT288 codecs through HDA-style verbs over `rl6347a` I2C transport. It exposes two DAIs, speaker and headphone outputs, analog/DMIC capture routing, DMI/platform-data combo-jack handling, and an RT288 Dell GPIO quirk.

`struct rt286_priv` owns regmap/component/I2C pointers, `rt286_platform_data`, jack state, delayed work, and sysclk source/rate. Probe verifies RT286 or RT288 vendor ID, writes vendor index defaults and verb defaults, imports platform data, applies DMI combo-jack policy, configures function/node power states, DMIC2/GPIO2 behavior, depop parameters, optional Dell GPIO, IRQ, and component registration. Component probe schedules a short initial jack detect.

Control flow centers on `rt286_jack_detect()`: in combo-jack mode it powers HV/VREF/LDO1, drives MIC1 pin control, waits, checks CBJ status, retries alternate detection, and then releases supplies when unplugged. DAI operations validate 44.1/48 kHz against sysclk families, encode channels and sample widths, and set master/slave plus I2S/left-justified/DSP modes. DAPM events manage speaker EAPD, DMIC pin enable, LDO2, and mic bias.

State persists in platform flags, current clock selection, jack pointer, forced DAPM pins, and index-cache defaults. Suspend/resume uses cache-only regmap and `rt286_index_sync()`. Risks include timing-sensitive combo detection, incomplete DMI coverage, strict clock/rate constraints, and initial jack reporting from cached status. Test signals include both DAIs, combo and discrete jack paths, speaker EAPD, GPIO2/DMIC2 variants, RT288/Dell quirk, invalid clock/rate cases, and suspend/resume.
