# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8995.h

## Purpose

`wm8995.h` is the private hardware-definition header for the Wolfson WM8995 ALSA SoC codec driver. It contains no executable logic of its own; its job is to define the WM8995 register map, per-register bit masks/shifts/widths, and the small set of symbolic IDs that `wm8995.c` uses to program codec power, clocks, audio interfaces, mixers, GPIOs, interrupts, headphone/DC-servo sequencing, FLLs, EQ/DRC blocks, and PDM speaker outputs.

The header is source-tree-local to `sound/soc/codecs`: `wm8995.c` includes it directly, while Kconfig/Makefile build `wm8995.o` under `CONFIG_SND_SOC_WM8995`.

## Important APIs, Types, and Constants

- Register address constants cover the device's sparse 16-bit register space, starting at `WM8995_SOFTWARE_RESET` (`0x00`) and extending through write-sequencer memory (`0x3000` range) with `WM8995_MAX_REGISTER` set to `0x31FF`.
- `WM8995_REGISTER_COUNT` and `WM8995_MAX_CACHED_REGISTER` describe the register-map size expected by the driver; `wm8995.c` passes `WM8995_MAX_REGISTER` to `struct regmap_config`.
- Field definitions are grouped by register comments such as `R1 (0x01) - Power Management (1)`. Each hardware field typically has `_MASK`, `_SHIFT`, and `_WIDTH` forms, with a value macro when the field is a single-bit enable or fixed value.
- The address groups model the codec's functional blocks: power management, line input volume/control, DAC/AIF volume controls, MICBIAS/LDO/accessory/headphone/mic detect, charge pump/Class-W/DC servo/headphone analogue control, chip/control interface, write sequencer, AIF1/AIF2 clocks and serial ports, FLL1/FLL2, digital filters, DRC/EQ coefficient registers, mixer routing, DAC softmute/oversampling/sidetone, GPIO/pull/interrupt registers, and PDM speaker controls.
- `WM8995_CLASS_W_SWITCH(xname, reg, shift, max, invert)` wraps `SOC_SINGLE_EXT()` and binds DAPM mixer controls to `snd_soc_dapm_get_volsw` plus the driver-local `wm8995_put_class_w()` callback. This is the header's only macro that expands into an ASoC control definition instead of a raw hardware constant.
- `struct wm8995_reg_access { u16 read; u16 write; u16 vol; }` describes register access metadata, but in the current driver it is not referenced by `wm8995.c`; the active access policy is implemented by `wm8995_readable()` and `wm8995_volatile()`.
- `enum clk_src` provides IDs for `set_dai_sysclk()`: `WM8995_SYSCLK_MCLK1`, `WM8995_SYSCLK_MCLK2`, `WM8995_SYSCLK_FLL1`, `WM8995_SYSCLK_FLL2`, and `WM8995_SYSCLK_OPCLK`. The driver accepts the first four and rejects OPCLK/default paths.
- `WM8995_FLL1` and `WM8995_FLL2` select which FLL instance `wm8995_set_fll()` configures. `WM8995_FLL_SRC_MCLK1`, `WM8995_FLL_SRC_MCLK2`, `WM8995_FLL_SRC_LRCLK`, and `WM8995_FLL_SRC_BCLK` select the FLL reference source.

## Control Flow and Integration

The header's constants drive almost every control path in `wm8995.c`:

- Regmap setup uses `WM8995_MAX_REGISTER` and all address constants in the readable/volatile switch statements. The regmap is 16-bit register, 16-bit value, `REGCACHE_MAPLE`.
- ALSA controls use register constants in `SOC_DOUBLE_R_TLV`, `SOC_DOUBLE_R`, `SOC_SINGLE_TLV`, and related ASoC macros for DAC/ADC volumes, mute switches, input boosts, sidetone controls, and DAPM routing switches.
- DAPM power events write the power-management, charge-pump, headphone, and DC-servo bits defined here. `hp_event()` sequences `WM8995_CP_ENA`, `WM8995_HPOUT1*` enables/delays/output/short-removal fields, `WM8995_DCS_ENA_CHAN_*`, and `WM8995_DCS_TRIG_*` fields, then polls `WM8995_DC_SERVO_READBACK_0`.
- Class-W dynamic charge-pump selection reads the DAC1 mixer routing bits (`WM8995_AIF2DACL_TO_DAC1L`, `WM8995_AIF1DAC2L_TO_DAC1L`, `WM8995_AIF1DAC1L_TO_DAC1L`) and updates `WM8995_CLASS_W_1` with `WM8995_CP_DYN_PWR_MASK` and `WM8995_CP_DYN_SRC_SEL_MASK`.
- Clock configuration uses the sysclk enum to choose MCLK1/MCLK2/FLL1/FLL2, then programs `WM8995_AIF1_CLOCKING_1` or `WM8995_AIF2_CLOCKING_1` with `WM8995_AIF1CLK_SRC_MASK` and `WM8995_AIF1CLK_DIV_MASK`. `WM8995_CLOCKING_1` and `WM8995_SYSCLK_SRC` select which AIF clock feeds CLK_SYS.
- DAI format and hardware-parameter paths use AIF bitfields such as `WM8995_AIF1_FMT_SHIFT`, `WM8995_AIF1_BCLK_INV`, `WM8995_AIF1_LRCLK_INV`, word length masks, BCLK/LRCLK divisors, and sample-rate register fields.
- FLL setup maps `WM8995_FLL1`/`WM8995_FLL2` to register offsets, gates AIF clocks, disables the selected FLL, writes OUTDIV/FRATIO/K/N/reference-source fields using the FLL masks and shifts, and re-enables the FLL when `freq_out` is nonzero.

## State and Persistence Behavior

The header itself has no runtime state, storage, or locking. Its definitions shape the driver's persistent hardware/cache behavior:

- Hardware state is persisted in the codec registers addressed by this header. Most register writes are cached by regmap and restored/synchronized during bias and regulator events.
- Volatile definitions in `wm8995.c` rely on these address constants to bypass normal caching for reset, DC-servo readback, interrupt status/control, accessory/headphone detect, and rate status registers.
- Regulator disable notifiers mark the regmap cache dirty when supplies are removed, meaning the constants here indirectly define which cached register values can be replayed when power returns.
- The `WM8995_*_MASK` macros are critical to preserving unrelated register bits across `snd_soc_component_update_bits()` calls. A wrong mask/shift can corrupt adjacent codec state even when the caller appears to update a single field.

## Dependencies

- Includes `<asm/types.h>` for `u16`, used by `struct wm8995_reg_access`.
- Depends on Linux ASoC control macros (`SOC_SINGLE_EXT`) and symbols (`snd_soc_dapm_get_volsw`, `wm8995_put_class_w`) at inclusion sites. The callback is implemented in `wm8995.c`; because this is a private driver header, it assumes that inclusion order and file pairing.
- Coupled to Linux regmap, ASoC component/DAI/DAPM APIs, regulator events, I2C/SPI transport setup, and the WM8995 hardware datasheet register layout.
- Built when `CONFIG_SND_SOC_WM8995` is selected; that Kconfig option depends on `SND_SOC_I2C_AND_SPI`.

## Risks and Maintenance Notes

- The file is largely generated-style register metadata. Small numeric mistakes in addresses, masks, shifts, or widths can cause silent hardware misconfiguration, especially around power sequencing, clock routing, FLL programming, and analogue headphone/DC-servo paths.
- Many AIF1 and AIF2 fields share layouts, and the C driver sometimes reuses AIF1 masks/shifts with register offsets. Any future divergence between AIF instances must be reflected in both this header and those offset-based callers.
- `enum clk_src` is named generically (`clk_src`) rather than `wm8995_clk_src`; because this is a private header the collision risk is low, but including it from broader scopes would be risky.
- `WM8995_SYSCLK_OPCLK` is exposed but rejected by the current `set_dai_sysclk()` implementation. Machine drivers using that ID would fail at runtime.
- `struct wm8995_reg_access` appears unused in the active driver. If it is stale generated metadata, future cleanup should verify no out-of-tree consumer depends on it before removing it.
- The `WM8995_CLASS_W_SWITCH` macro depends on the local `wm8995_put_class_w()` symbol. Moving the macro to a public header or including it in a different compilation unit would fail unless that callback is visible.

## Test and Verification Signals

- Compile coverage: build `sound/soc/codecs/wm8995.o` with `CONFIG_SND_SOC_WM8995`, including both I2C and SPI-capable configurations where possible, to catch missing macro/callback/type references.
- Static verification: compare register addresses, masks, shifts, widths, and `WM8995_MAX_REGISTER` against the WM8995 datasheet or any generated vendor register source; focus on fields used by update-bits paths.
- Regmap smoke tests on hardware or emulator: probe over I2C/SPI, confirm readable/volatile register policies do not reject registers used by controls or DAPM, and verify cache sync after regulator disable/enable.
- Audio path tests: exercise DAC/ADC volume and mute controls, DAPM route toggles, AIF1/AIF2 playback/capture at 8 kHz through 96 kHz, and AIF format/word-length combinations to validate the serial-port bitfields.
- Clock tests: call `set_dai_sysclk()` with MCLK1, MCLK2, FLL1, and FLL2, then configure FLL sources MCLK/LRCLK/BCLK and verify lock/status behavior and stable playback/capture.
- Power/pop tests: repeatedly enable/disable headphone outputs and observe DC-servo completion, charge-pump sequencing, and absence of pops or timeouts.
- Interrupt/GPIO tests: verify mask/status/raw-status definitions by triggering supported GPIO, FLL lock, DRC signal-detect, DC-servo, headphone, and microphone-detect events where board wiring permits.
