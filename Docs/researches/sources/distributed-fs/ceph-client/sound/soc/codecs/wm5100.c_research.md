# sources/distributed-fs/ceph-client/sound/soc/codecs/wm5100.c

## Purpose
`wm5100.c` is the ALSA SoC codec driver for the Wolfson WM5100 audio codec on I2C. It registers the codec component, three audio interface DAIs, mixer and coefficient controls, a large DAPM graph for inputs, DSP-style processing blocks, AIF capture/playback endpoints, headphone/speaker/PDM/PWM outputs, clock and FLL programming, jack detection, GPIO exposure, interrupt handling, and runtime power management.

The file is mostly a hardware-integration layer: it maps ASoC controls and DAPM routes onto WM5100 registers, manages the codec's power rails and register cache, and provides machine-driver entry points for clocks, PLL/FLLs, DAI formats, PCM parameters, and headset detection.

## Important APIs, types, and data
- `struct wm5100_priv` is the central runtime state. It owns the `device`, `regmap`, `snd_soc_component`, core regulators, reset/LDO/headphone-polarity GPIOs, revision, SYSCLK and ASYNCCLK rates, per-AIF async/symmetry flags, shared sample-rate slot reference counts, output-enable sequencing flags, jack-detect state, two FLL state records, platform data, and optional `gpio_chip`.
- `struct wm5100_fll` caches each FLL reference/output frequency and source and carries a `completion` used by IRQ-driven FLL lock waits.
- `wm5100_sr_code[]` and `wm5100_sr_regs[]` map supported sample rates onto the three synchronous sample-rate registers. `wm5100_alloc_sr()` reference-counts slots and writes the encoded rate, while `wm5100_free_sr()` attempts to release them.
- Mixer infrastructure is generated by macros such as `WM5100_MIXER_ENUMS`, `WM5100_MIXER_CONTROLS`, `WM5100_MIXER_WIDGETS`, and `WM5100_MIXER_ROUTES`. These expand the many four-input source muxes and per-input mixer volume controls for outputs, AIF transmitters, EQs, DRC, and LHPFs.
- `wm5100_snd_controls[]` exposes ALSA controls for analog/digital input volumes, mute switches, output volumes, PDM speaker switches, EQ/DRC/LHPF coefficient blobs, EQ band gains, LHPF mode enums, and mixer input volumes.
- `wm5100_dapm_widgets[]` and `wm5100_dapm_routes[]` describe supplies, charge pumps, mic biases, physical inputs/outputs, AIF widgets, processing blocks, mixers, and clock/regulator dependencies.
- `wm5100_dai[]` registers `wm5100-aif1`, `wm5100-aif2`, and `wm5100-aif3`, each with stereo playback/capture support, 8-192 kHz rates, 16/20/24/32-bit formats, and common DAI ops.
- `soc_component_dev_wm5100` is the ASoC component driver. It wires in component probe, `set_sysclk`, `set_pll`, the sequence notifier, control arrays, DAPM widgets/routes, power-down timing, and endianness.
- `wm5100_regmap` configures a 16-bit register/16-bit value regmap with defaults and readable/volatile predicates from the generated/local WM5100 register data.

## Control flow
I2C probe allocates `wm5100_priv`, initializes the I2C regmap, initializes both FLL completions, copies optional platform data, obtains and enables the core supplies `DBVDD1` and `LDOVDD`, enables the optional `wlf,ldo1ena` GPIO, requests the optional reset GPIO, verifies the device ID, reads the revision, resets the chip, applies revision-A register patches, registers optional GPIOs, applies platform GPIO defaults and input modes, installs threaded IRQ handling when an IRQ is present, enables runtime PM, and registers the ASoC component plus three DAIs.

Component probe stores the component pointer, enables volume-update bits on all ADC/DAC digital volume registers, disables IRQ debounce, optionally adds the status-checking DAPM post widget, and requests the optional `hp-pol` GPIO used by jack-detect polarity switching.

PCM setup enters through `wm5100_set_fmt()` and `wm5100_hw_params()`. Format setup accepts DSP_A or I2S plus ASoC provider/consumer and inversion flags, then updates AIF BCLK/LRCLK/format registers at the DAI's base register. `hw_params` derives word length, frame length, and target BCLK from ALSA params. For synchronous AIFs it allocates one of the shared sample-rate slots against SYSCLK; for async AIFs it writes the ASYNC sample-rate code and uses ASYNCCLK. It then chooses a BCLK code from either the 48 kHz family or 44.1 kHz family tables, writes BCLK, LRCLK divisor, word/slot length, and the AIF sample-rate selector.

Clock setup enters through `wm5100_set_sysclk()`. Real clock IDs program SYSCLK, ASYNCCLK, 32 kHz clock source, or OPCLK; pseudo clock IDs for AIF1/AIF2/AIF3 only select whether that AIF is synchronous to SYSCLK or asynchronous to ASYNCCLK. SYSCLK/ASYNCCLK accept fixed WM5100-supported frequencies from the 44.1 kHz and 48 kHz families and store the selected rate in private state. SYSCLK setup also allocates the natural primary audio sample-rate slot for the selected clock family.

FLL setup is split between `fll_factors()` and `wm5100_set_fll()`. The factor calculator scales reference clocks down to at most 13.5 MHz, chooses an output divider to put the VCO near or above 90 MHz, selects an FLL_FRATIO bucket, and computes integer/fractional N, theta, and lambda values using `gcd()`. `wm5100_set_fll()` validates FLL ID and source, disables the FLL, writes calculated control fields, clears stale lock completions, takes a runtime PM reference, enables the FLL, enables SYSCLK, then waits for lock either by IRQ completion or polling raw interrupt status. Disabling an FLL clears enable and drops the runtime PM reference if it had been running.

DAPM control is mostly declarative, but output sequencing uses callbacks. `wm5100_out_ev()` marks output-status banks as pending after power-up events. `wm5100_seq_notifier()` later polls output status registers until they match enable registers, logging timeouts. Without reliable interrupt reporting, `wm5100_post_ev()` can read raw status registers after DAPM changes and log clock, speaker, AIF, and underclock conditions.

Jack detection is exported as `wm5100_detect()`. Enabling detection stores the jack, resets detection state, applies platform jack mode 0 through `wm5100_set_detect_mode()`, configures slow accessory detection for debounce, force-enables CP2 and SYSCLK through DAPM so MICBIAS/accessory detection can run, enables accessory detection, and unmasks accessory-detect IRQs. Disabling masks detect IRQs, disables accessory detection, and clears the jack pointer. IRQ handling calls `wm5100_micd_irq()` on accessory events; that routine interprets `MIC_DETECT_3`, reports removal, headset, headphone, and BTN_0 events, flips microphone polarity once using `hp-pol` and platform jack modes when initial impedance suggests the wrong polarity, and increases detection rate after stable headphone/headset detection.

IRQ handling reads status and masks for interrupt banks 3 and 4, filters masked bits, acknowledges active bits by writing them back, logs critical/error conditions, completes FLL lock completions, and dispatches microphone detection. Edge-triggered IRQs use `wm5100_edge_irq()` to repeatedly drain pending interrupt status until no handler reports work.

When `CONFIG_GPIOLIB` is enabled, the driver exposes six codec GPIOs through a sleeping `gpio_chip`. Direction and value operations update the WM5100 GPIO control registers through regmap. Remove and error paths unregister the GPIO chip, free IRQs, assert reset, disable LDO enable, and disable core supplies.

Runtime suspend marks the regmap cache-only and dirty, deasserts the LDO enable GPIO, and disables core supplies. Runtime resume reenables supplies, reasserts LDO enable with a short delay, leaves cache-only mode, and syncs the regcache back to hardware.

## State and persistence behavior
Hardware register state is persisted through regmap's MAPLE cache and synchronized on runtime resume. Runtime suspend deliberately marks the cache dirty because power is removed from the codec rails, so the next resume must rewrite cached configuration.

In-memory state persists values that are not discoverable cheaply from hardware or are needed for sequencing: current SYSCLK/ASYNCCLK rates, per-AIF async-domain selection, sample-rate slot reference counts, output-enable pending flags, jack detection state, jack polarity flips, cached FLL input/output/source values, and copied platform data. FLL runtime PM references are held while FLLs are enabled and dropped on disable or lock failure.

Platform data affects persistent initial hardware setup: GPIO defaults, input analog/digital modes, digital microphone supplies, IRQ trigger flags, and jack-detect mode table entries. These settings are applied during probe or jack detection rather than stored in a separate firmware format.

## Dependencies and integration points
This driver depends on the Linux I2C core, regmap, regulator framework, GPIO descriptor and optional gpiolib APIs, runtime PM, threaded IRQs, ALSA SoC component/DAI/DAPM/control APIs, PCM parameter helpers, jack reporting, `sound/wm5100.h` platform data, and local/generated `wm5100.h` register definitions and defaults.

Machine drivers integrate through the DAI names `wm5100-aif1`, `wm5100-aif2`, and `wm5100-aif3`; component clock callbacks for `WM5100_CLK_*`; component PLL callbacks for `WM5100_FLL1` and `WM5100_FLL2`; DAPM endpoints such as `IN1L`, `HPOUT1L`, `SPKOUTL`, `SPKDAT1`, and `PWM1`; and the exported `wm5100_detect()` jack-detect helper. Board files or firmware must provide the I2C device, supplies, optional reset/LDO/headphone-polarity GPIOs, optional IRQ, and any platform data needed for input modes or jack polarity modes.

## Risks and edge cases
- `wm5100_free_sr()` stores `sr_code = wm5100_sr_code[i]` and then compares that value with masked register contents. `wm5100_alloc_sr()` writes the encoded index, so frees for normal rates may fail to find the slot and leave `sr_ref[]` inflated.
- `wm5100_set_sysclk()` contains `if (0 && *rate_store)` around the old-rate free path, so changing SYSCLK can allocate a new primary sample-rate slot without releasing the previous one.
- The comment before `wm5100_dapm_widgets_noirq` says the DAPM post event is for systems without IRQ support, but `wm5100_probe()` registers it when `i2c->irq` is present. That condition may invert the intended fallback behavior.
- `wm5100_out_ev()` sets `out_ena[0]` for both `WM5100_CHANNEL_ENABLES_1` and `WM5100_OUTPUT_ENABLES_2`; the second case likely should mark `out_ena[1]`, otherwise `wm5100_seq_notifier()` may never poll `OUTPUT_STATUS_2`.
- `wm5100_hw_params()` allocates a synchronous sample-rate slot before later BCLK/LRCLK validation. If a later validation path fails, the slot is not released.
- Source validation in `wm5100_set_sysclk()` rejects SYSCLK/ASYNCCLK as sources for real clocks but does not explicitly whitelist the remaining source values before writing them into clock-source fields.
- OPCLK setup accepts several frequencies but writes the same `OPCLK_SEL` value for all cases, which may be incomplete or placeholder behavior.
- Jack detection assumes platform jack modes exist for at least modes 0 and 1 when polarity flipping is needed; sparse or missing platform data can make polarity switching ineffective or invalid.
- Several probe-time and event-path regmap writes do not check return values, so transient I/O failures can leave hardware partially configured with limited error reporting.
- `wm5100_set_fll()` takes a runtime PM reference with `pm_runtime_get_sync()` but does not check its return value before programming and enabling the FLL.

## Test signals
Useful validation includes I2C probe with and without optional reset/LDO/headphone-polarity GPIOs, bad device ID handling, revision-A patch registration, regulator enable/disable error paths, runtime suspend/resume with regcache sync, GPIO chip registration and direction/value operations, component registration for all three DAIs, DAPM playback/capture routes through each output family, and status logging with and without an IRQ.

Clock and audio tests should cover SYSCLK and ASYNCCLK setup for 5.6448/6.144/11.2896/12.288/22.5792/24.576 MHz, AIF clock-domain switching, synchronous and asynchronous `hw_params`, 44.1 kHz and 48 kHz BCLK families, unsupported rates/formats, repeated stream open/close to check sample-rate slot references, provider/consumer DAI format combinations, and output enable sequencing timeouts.

FLL tests should cover both FLLs, all accepted FLL sources, high reference clocks requiring division, invalid Fref/Fout combinations, IRQ-completion and polling lock paths, lock timeout cleanup, and disable-after-enable runtime PM reference balance. Jack tests should cover insertion/removal, headphone-only detection, headset detection, button press/release, polarity flip behavior, IRQ masking on detect disable, and DAPM force-enable/release behavior around CP2 and SYSCLK.
