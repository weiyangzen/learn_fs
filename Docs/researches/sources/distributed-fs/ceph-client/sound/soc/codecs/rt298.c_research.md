# sources/distributed-fs/ceph-client/sound/soc/codecs/rt298.c

`rt298.c` is the ASoC I2C driver for Realtek RT298, using HDA-style verbs over `rl6347a`. It provides two DAIs, speaker/headphone routing, record mixers, combo-jack support, unsolicited response programming, ADC filter handling, and additional analog supply sequencing.

`struct rt298_priv` stores regmap/component/platform-data/I2C/jack/work state, sysclk/clock source, and `is_hp_in` for duplicate combo-jack suppression. Probe verifies `RT298_VENDOR_ID`, restores vendor index and verb defaults, imports platform or ACPI data, applies DMI combo-jack overrides, programs VREF and power states, configures CBJ or discrete mic detection, sets DMIC2/GPIO2 policy, enables wind filter and unsolicited events, initializes IRQ flags, requests IRQ, and registers the component.

Runtime flow mirrors RT286 with RT298-specific supplies. `rt298_jack_detect()` powers HV/VREF/LDO1 during combo detection, classifies headset mic through CBJ registers, updates `is_hp_in`, and releases supplies based on detected state. `rt298_adc_event()` unmutes/mutes ADC gain and resets ADC filters if MCLK is absent. DAI ops accept 44.1/48 kHz, up to 16 channels, common 8/16/20/24/32-bit widths, and I2S/left-justified/DSP A/B formats.

State persists in platform-data flags, HP-in cache, clock fields, DAPM forced supplies, and regcache/index cache. Risks include stale HP state hiding events, platform-specific combo policy, fixed-delay ADC filter reset, strict sysclk/rate matching, and vendor-ID read error handling that compares the read variable directly. Test signals include IRQ jack reports, repeated plug/unplug, MCLK absent ADC startup, DMI combo mode, two DAI paths, speaker EAPD, and suspend/resume.
