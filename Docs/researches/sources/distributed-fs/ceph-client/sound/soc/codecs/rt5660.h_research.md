# sources/distributed-fs/ceph-client/sound/soc/codecs/rt5660.h

## Purpose

`rt5660.h` is the private ASoC codec-driver header for the Realtek RT5660. It gives the C driver symbolic names for the codec register address map, register bit fields, clock identifiers, PLL source identifiers, DAI identifiers, and private runtime state. It is not a standalone implementation file; its main job is to keep the RT5660 driver's regmap, DAPM, DAI, jack/GPIO, DMIC, power, mixer, and PLL programming code readable and consistent.

The header includes `<sound/rt5660.h>`, which is the public platform-data contract. That public header supplies board configuration such as differential input flags, `use_ldo2`, `poweroff_codec_in_suspend`, and the `dmic1_data_pin` selection. This private header adds the low-level register constants and `struct rt5660_priv` used by the codec implementation.

## Important APIs, Types, and Definitions

The file is mostly macro definitions. The important groups are:

- Register addresses: reset/vendor IDs, speaker and line-out volume, IN1/IN2 and IN3/IN4 input controls, DAC/ADC digital volume, ADC boost, digital and analog mixers, output mixers, power registers, private register index/data, I2S/ADDA/DMIC controls, global clock and PLL controls, class-D amp controls, micbias, dipole microphone controls, EQ/DRC/ALC controls, jack/IRQ/GPIO controls, soft-volume/zero-cross controls, and general controls.
- Bit fields for volume and mute: shared left/right mute and volume fields plus DAC and ADC volume masks.
- Input and mixer controls: boost gain masks for four inputs, ADC mixer mute bits, AD/DA mixer switches, stereo DAC mixer switches, record mixer gains and mutes, speaker/line/output mixer gains and mutes.
- Power fields: `RT5660_PWR_DIG1`, `RT5660_PWR_DIG2`, `RT5660_PWR_ANLG1`, `RT5660_PWR_ANLG2`, `RT5660_PWR_MIXER`, and `RT5660_PWR_VOL` bits for I2S, DAC, ADC, class-D, VREF, bandgap, headphone amp, boost amps, micbias, PLL, output mixers, speaker mixer, record mixers, and volume blocks.
- Audio interface fields: I2S master/slave, compression, BCLK polarity, data length, data format, BCLK ratio divider, ADC/DAC oversampling, and filter reset/high-pass enables.
- DMIC and GPIO fields: DMIC enable and edge selection, DMIC data source, GPIO pin muxes, pin direction/output/polarity, and GPIO interrupt mode.
- Clock and PLL definitions: system-clock sources `RT5660_SCLK_S_MCLK`, `RT5660_SCLK_S_PLL1`, `RT5660_SCLK_S_RCCLK`; PLL sources `RT5660_PLL1_S_MCLK`, `RT5660_PLL1_S_BCLK`; PLL input range and M/N/K masks.
- Jack/IRQ definitions: jack-detect source/trigger bits, IRQ bypass/normal controls, sticky bits, polarity bits, over-temperature and micbias over-current IRQ fields.
- `enum { RT5660_AIF1, RT5660_AIFS }`: indexes the single audio interface plus count.
- `struct rt5660_priv`: runtime driver state with `snd_soc_component`, platform data, regmap, optional `mclk`, per-DAI `lrck`, `bclk`, and master state arrays, plus current `sysclk`, `sysclk_src`, `pll_src`, `pll_in`, and `pll_out`.

## Control Flow

This header has no executable control flow. Its definitions are consumed by the RT5660 codec implementation when handling probe, regmap access, DAPM power events, PCM hardware parameter setup, DAI format setup, PLL programming, bias transitions, suspend/resume, and board-specific setup. The control-flow shape implied by the definitions is:

1. Probe allocates `struct rt5660_priv`, parses `struct rt5660_platform_data`, creates a regmap, and records clock state.
2. Audio stream startup and `hw_params` use `lrck`, `bclk`, I2S width/format masks, and `rl6231`-style divider helpers to program I2S and ADDA clock registers.
3. DAPM widgets and routes use power and mixer bit definitions to turn analog/digital blocks on only when needed.
4. PLL setup uses the source identifiers and M/N/K bit fields to select MCLK or BCLK input and program the PLL registers.
5. Optional board features use public platform data plus these private masks to set differential input mode, LDO2 behavior, suspend power policy, and DMIC data routing.

## State and Persistence Behavior

`struct rt5660_priv` is the central per-device state persisted for the lifetime of the I2C codec device. It stores cached software knowledge that is not automatically recoverable from a single hardware register read: selected system clock source/frequency, PLL source/input/output, and per-interface LRCK/BCLK/master settings. Hardware state itself is held in codec registers and normally mirrored through regmap cache in the implementation.

The header defines reset register `RT5660_RESET`, vendor ID registers, volatile operational registers such as IRQ/GPIO/jack status fields, and many power bits that determine runtime hardware state. Because these are raw hardware contracts, incorrect masks or shifts can cause persistent audible state until the codec is reset or power-cycled.

## Dependencies and Integration Points

Key dependencies are Linux ASoC and device infrastructure types brought in indirectly by the implementation:

- `<linux/clk.h>` for optional MCLK handling.
- `<sound/rt5660.h>` for board/platform data.
- ASoC component, DAI, DAPM, kcontrol, and regmap users in the paired implementation.
- The codec Kconfig entry `SND_SOC_RT5660`, which depends on I2C, and Makefile wiring through `snd-soc-rt5660.o`.
- Common Realtek helpers such as `rl6231` are likely used by the C implementation to calculate clock dividers and PLL codes matching the masks in this header.

## Risks and Edge Cases

- The header has many similarly named masks and shifts. A mismatch between a `_MASK` and `_SFT` pair can silently program the wrong hardware bits.
- Register `0x3d` appears both as `RT5660_REC_R1_MIXER` and private register index `RT5660_CHOP_DAC_ADC`; this is intentional only if the private-register access path uses a separate index/data window. Direct use in normal regmap code would be risky.
- Many macros use plain `0x1 << n` integer expressions. They are conventional in kernel codec headers but still depend on callers passing appropriately typed values to update helpers.
- `struct rt5660_priv` stores per-interface arrays sized by `RT5660_AIFS`; any implementation that adds another DAI must update the enum and all array users together.
- Public platform-data fields can change low-level register programming for differential inputs, LDO2, suspend power, and DMIC data pin selection; tests need board variants, not only default probing.

## Test Signals

Useful validation signals include successful build of `CONFIG_SND_SOC_RT5660`, codec probe and vendor ID read, ALSA mixer controls appearing with expected names, DAPM route power transitions without over-current or pop regressions, stream playback/capture across supported widths and clock sources, PLL enable/disable paths, DMIC data-pin routing, jack/IRQ behavior where supported by the paired driver, and suspend/resume with and without `poweroff_codec_in_suspend`.
