# sources/distributed-fs/ceph-client/sound/soc/codecs/mt6359.c

## Purpose

`mt6359.c` is the Linux ALSA SoC codec driver for the MediaTek MT6359 PMIC audio codec. It registers the `mt6359-sound` platform driver, exposes two ASoC DAIs (`mt6359-snd-codec-aif1` and `mt6359-snd-codec-aif2`), defines mixer controls for analog playback/capture gains, and models codec power/audio routing with DAPM widgets and routes.

The file is almost entirely hardware sequencing. It programs PMIC registers through the parent `mt6397` regmap to bring up and tear down playback paths, capture paths, microphone bias, DMIC/AMIC routing, DAC/ADC clocks, SDM blocks, MTKAIF transmit FIFOs, GPIO pin modes, and boot-time MTKAIF calibration loopback.

## Important APIs, Types, and Functions

- `mt6359_platform_driver_probe()` allocates `struct mt6359_priv`, binds the parent PMIC `regmap`, parses device-tree codec properties, and registers the ASoC component and DAI drivers with `devm_snd_soc_register_component()`.
- `mt6359_soc_component_driver` provides the component name `mtk-codec-mt6359`, probe/remove callbacks, ALSA controls, DAPM widgets, routes, and `endianness = 1`.
- `mt6359_dai_driver[]` exposes AIF1 and AIF2 playback/capture streams. Both DAIs support 1-2 channels and 16/24/32-bit signed/unsigned little-endian samples. AIF1 capture supports 8/16/32/48/96/192 kHz; AIF2 capture supports 8/16/32/48 kHz; both playback DAIs support 8-48/96/192 kHz.
- `mt6359_codec_dai_startup()`, `mt6359_codec_dai_hw_params()`, and `mt6359_codec_dai_shutdown()` are the DAI ops. Startup switches playback or capture pins into audio mode, `hw_params` records `dl_rate[]` or `ul_rate[]`, and shutdown restores pins to GPIO/input-safe states.
- Exported MTKAIF helpers are `mt6359_set_mtkaif_protocol()`, `mt6359_mtkaif_calibration_enable()`, `mt6359_mtkaif_calibration_disable()`, and `mt6359_set_mtkaif_calibration_phase()`. These are intended for machine-driver calibration flows and are exported with `EXPORT_SYMBOL_GPL`.
- `mt6359_put_volsw()` wraps `snd_soc_put_volsw()`, mirrors programmed gain values into `priv->ana_gain[]`, and returns whether a cached gain changed. `mt6359_get_playback_volsw()` returns cached playback gains rather than reading hardware.
- `mt6359_codec_init_reg()` performs initial one-time setup: temporarily enables the audio clock buffer, selects internal DCXO clocking, disables several short-circuit protections, configures audio GPIO Schmitt trigger/driving strength, resets playback/capture pins, defaults `hp_hifi_mode` to normal mode, disables ZCD, then disables the clock buffer.
- DAPM event functions implement hardware bring-up/tear-down for major blocks: `mtk_hp_enable()/mtk_hp_disable()`, `mt_hp_event()`, `mt_rcv_event()`, `mt_lo_event()`, `mt_adc_clk_gen_event()`, `mt_dcc_clk_event()`, `mt_mic_bias_*_event()`, `mt_ul_src_dmic_event()`, `mt_adc_*_event()`, `mt_pga_*_event()`, `mt_sdm_event()`, `mt_sdm_3rd_event()`, `mt_ncp_event()`, and small delay/pull-down/mute/damping helpers.

The private state comes from `mt6359.h`: `struct mt6359_priv` stores the device, shared `regmap`, downlink/uplink sample rates per AIF, cached analog gains, mux selections, `dmic_one_wire_mode`, device counters, headphone mode/gain flags, and selected MTKAIF protocol.

## Control Flow

Probe starts at `mt6359_platform_driver_probe()`. The parent MFD driver supplies `struct mt6397_chip`; this codec driver reuses `mt6397->regmap`, parses the `audio-codec` or `mt6359codec` child node, reads `mediatek,dmic-mode` and `mediatek,mic-type-{0,1,2}`, then registers the component and DAIs. Component probe initializes the component regmap and calls the register initialization sequence.

Runtime audio setup is split between DAI operations and DAPM:

- DAI startup/shutdown only handles pad muxing. Playback uses `mt6359_set_playback_gpio()` and `mt6359_reset_playback_gpio()`; capture uses `mt6359_set_capture_gpio()` and `mt6359_reset_capture_gpio()`.
- `hw_params` records the PCM rate. The headphone enable sequence uses `dl_rate[MT6359_AIF_1]` to choose a high-frequency compensation setting when playback is at least 96 kHz.
- DAPM widgets and routes describe the actual power graph. Enabling a path causes ASoC to sequence supplies, muxes, DACs/ADCs, and outputs in the order defined by the widget subsequence constants.

Playback routes start from `AIF_RX`/`AIF2_RX` or the sine generator, pass through digital clocks and SDM/NCP supplies, then fan out through `DAC In Mux` to `DACL`, `DACR`, or `DAC_3RD`. Output widgets route those DACs through `HP Mux`, `RCV Mux`, or `LOL Mux` to headphones, receiver, external speaker amp outputs, or lineout. Headphone power-up is the most sensitive path: it sets bias currents, damp circuits, feedback caps, stabilizes output stages with delays, ramps main output stages and feedback loop gain, ramps gain from mute to cached volume, enables the decoder clock and DAC, switches the muxes, and releases pull-downs. Power-down reverses much of that order to avoid pops and leakage.

Capture routes start at `AIN*` or `AIN*_DMIC`, enable mic bias/DMIC supplies as needed, route through PGA muxes and ADC muxes into `ADC_L`, `ADC_R`, or `ADC_3`, pass through UL source muxes and MISO muxes, then reach `AIF1TX` or `AIF2TX`. AMIC paths can conditionally connect `DCC_CLK` when any selected microphone type is DCC-based. PGA events precharge and enable DCC only for DCC microphone types and program cached microphone gain after power-up.

MTKAIF transmit enable is shared by normal capture DAPM and calibration helpers. `mt6359_mtkaif_tx_enable()` writes different `AFE_ADDA_MTKAIF_CFG0` and `AFE_AUD_PAD_TOP` values for protocol 1, protocol 2, and protocol 2 clock phase 2; disable returns the TX FIFOs to the disabled value.

## State and Persistence Behavior

The driver has no filesystem persistence. State persists only for the lifetime of the bound platform device in `struct mt6359_priv` and in hardware registers programmed through regmap.

Important runtime state includes:

- `ana_gain[]`, updated by mixer writes and consumed by playback/headset/lineout/receiver and microphone PGA power-up sequences.
- `dl_rate[]` and `ul_rate[]`, set during `hw_params`; only downlink rate is currently used for headphone compensation in this file.
- `mux_select[]`, filled partly by device tree for microphone type and partly by DAPM mux events for PGA input selections.
- `dmic_one_wire_mode`, read from device tree and used by `mt_ul_src_dmic_event()` to choose one-wire or non-one-wire DMIC register setup.
- `dev_counter[DEVICE_HP]`, incremented/decremented by headphone DAPM events and consulted by lineout setup to avoid enabling the left DAC path while headphone is active.
- `hp_hifi_mode`, currently initialized to normal mode and used to alter headphone bias/current/low-noise choices.
- `mtkaif_protocol`, set by the exported API and consumed by MTKAIF TX enable and calibration.

The volume cache is especially important: playback `get` callbacks report cached `ana_gain[]`, not necessarily a fresh hardware read. During init the cache is zero-filled by `devm_kzalloc()` unless userspace writes controls before a path is powered.

## Dependencies and Integration Points

- Kernel subsystems: platform driver core, device tree, regmap, MediaTek MFD `mt6397`, regulator consumer support, and ALSA SoC component/DAI/DAPM/control APIs.
- Header dependency: `mt6359.h` supplies register addresses, bit masks/shifts, enums for AIFs, mux selections, microphone types, gain codes, supply ordering, `struct mt6359_priv`, and exported helper prototypes.
- Parent device dependency: probe expects `pdev->dev.parent` to have `struct mt6397_chip` driver data and a valid `regmap`.
- Device-tree dependency: probe requires an `audio-codec` or `mt6359codec` child node. Missing optional properties fall back to idle/default microphone modes, but a missing codec child node fails probe.
- Machine-driver integration: exported MTKAIF calibration functions allow another driver to select the MTKAIF protocol, enable loopback/calibration clocks and GPIOs, program phase values, and disable calibration afterward.
- ASoC integration: controls, DAIs, stream names, DAPM widgets, and routes are the public surface used by cards and userspace mixers. Route/control names must match machine driver expectations.

## Risks and Edge Cases

- Register sequences are order- and delay-sensitive. Small changes to headphone, lineout, receiver, SDM, DCC, or mic-bias event ordering can cause pops, no audio, leakage, or analog instability.
- Several paths write whole register values rather than masked updates. If later hardware revisions or sibling drivers share bits in those registers, these writes can clobber unrelated state.
- `mt6359_put_volsw()` declares `new_gain[2]` and only initializes indices relevant to the selected control. The current comparison paths are guarded by mono/stereo checks, but changes to control definitions could expose uninitialized comparisons.
- `dev_counter[DEVICE_HP]` is updated in DAPM events without explicit locking. ASoC DAPM serialization normally protects widget transitions, but incorrect external sequencing or future direct calls could make lineout/headphone mutual exclusion fragile.
- Probe fails if the codec child node is absent, even though individual codec properties have defaults. Board DTS compatibility depends on using exactly one of the accepted child names.
- Calibration helpers directly override GPIO, clock, loopback, and MTKAIF TX state. They assume boot-time calibration use and should not race with active playback/capture streams.
- Cached gain defaults come from zeroed memory, not reset register reads. If hardware reset defaults differ from desired ALSA defaults, first power-up before userspace mixer restore may use unintended analog gains.
- The DAPM route condition `mt_dcc_clk_connect()` checks all microphone type muxes, not only the currently selected PGA source, so DCC clock may be enabled more broadly than strictly necessary when any configured mic type is DCC-based.

## Test Signals

Useful validation signals for this driver are hardware/ASoC oriented:

- Driver probe succeeds with a parent MT6397 regmap and an `audio-codec` or `mt6359codec` device-tree node; missing optional mic/DMIC properties should log defaults and continue.
- ALSA card exposes both DAIs with expected stream names and rates, plus mixer controls `Headset Volume`, `Lineout Volume`, `Handset Volume`, `PGA1 Volume`, `PGA2 Volume`, and `PGA3 Volume`.
- Playback startup switches MOSI pads to audio mode and shutdown restores data pins to GPIO/input-safe mode.
- Capture startup switches MISO pads to audio mode and shutdown restores MISO pads to GPIO/input-safe mode.
- DAPM route tests should cover headphone, receiver, lineout via left DAC, lineout via third DAC, AIF1 capture AMIC/DMIC, and AIF2 capture AMIC/DMIC.
- Headphone playback at rates below and at/above 96 kHz should verify the compensation branch in `mtk_hp_enable()`.
- Mixer writes should update `ana_gain[]`; subsequent DAPM power-up should apply the cached gain rather than the reset value.
- Device-tree mic type combinations should be tested for DCC and non-DCC microphones to confirm DCC precharge/enable and `DCC_CLK` routing.
- MTKAIF calibration should be tested for all three protocol enum values, including loopback enable/disable cleanup and calibration phase programming.
- Runtime suspend/resume or repeated stream open/close testing should check that clocks, regulators, GPIO modes, pull-downs, and low-noise/damping bits return to a quiet disabled state after DAPM shutdown.
