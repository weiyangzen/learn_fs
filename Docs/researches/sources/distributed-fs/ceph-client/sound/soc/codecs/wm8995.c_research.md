# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8995.c

## Purpose
`wm8995.c` is the standalone ALSA SoC codec driver for the Wolfson WM8995. Unlike the MFD-backed WM8994-family driver, it owns its I2C/SPI regmap setup directly, manages codec regulators, exposes three DAIs, defines mixer controls and DAPM routes, programs AIF clocking and FLLs, and sequences headphone, Class W, bias, and register-cache behavior.

## Important APIs, Types, and Functions
`struct wm8995_priv` stores the regmap, per-AIF SYSCLK selections, MCLK input rates, derived AIF clocks, live and suspend FLL configs, eight regulators, disable notifiers, and the active component pointer. `wm8995_reg_defaults[]`, `wm8995_readable()`, `wm8995_volatile()`, and `wm8995_regmap` define the 16-bit register map and `REGCACHE_MAPLE` policy. Regulator disable callbacks are generated by `WM8995_REGULATOR_EVENT(n)` and mark the regcache dirty when a supply is disabled.

Audio control and power helpers include `wm8995_update_class_w()`, `wm8995_put_class_w()`, `hp_supply_event()`, `hp_event()`, and `dc_servo_cmd()`. Clocking and DAI callbacks include `configure_aif_clock()`, `configure_clock()`, `clk_sys_event()`, `wm8995_aif_mute()`, `wm8995_set_dai_fmt()`, `wm8995_hw_params()`, `wm8995_set_tristate()`, `wm8995_get_fll_config()`, `wm8995_set_fll()`, `wm8995_set_dai_sysclk()`, and `wm8995_set_bias_level()`. Bus entry points are `wm8995_spi_probe()`, `wm8995_i2c_probe()`, `wm8995_modinit()`, and `wm8995_exit()`.

## Control Flow
Module init registers the I2C driver when I2C is enabled and the SPI driver when SPI master support is enabled. Each bus probe allocates private state, initializes a bus-specific regmap using the shared regmap config, stores driver data, and registers the ASoC component and three DAI drivers. Component probe requests regulator supplies, registers supply-disable notifiers, enables supplies, reads and validates the device ID, resets the chip, latches volume update bits, and initializes Class W state.

Machine drivers configure AIF1 or AIF2 via `.set_sysclk()`, `.set_pll()`, `.set_fmt()`, and `.hw_params()`. `configure_aif_clock()` selects MCLK1/MCLK2/FLL1/FLL2 for an AIF, halves clocks at or above 13.5 MHz, writes AIF clock source/divider bits, and caches the resulting AIF clock. `configure_clock()` updates both AIF clocks and switches `CLK_SYS` to the higher one, then asks DAPM to resync if the source changed. `wm8995_set_fll()` validates FLL ID/source, recomputes dividers, gates both AIF clocks, disables and reprograms the target FLL, optionally enables it, updates cached FLL state, restores previously enabled AIF clocks, and recomputes SYSCLK.

`wm8995_set_dai_fmt()` programs codec/provider mode, I2S/left/right/DSP formats, and legal inversion combinations. `wm8995_hw_params()` chooses register targets for AIF1/AIF2 and playback/capture LRCLK, calculates BCLK from PCM params, validates 16/20/24/32-bit widths and supported sample rates, picks the closest AIFCLK/fs ratio, selects the highest BCLK divisor that does not under-clock the target BCLK, computes LRCLK ratio, and writes word-length, BCLK, LRCLK, and sample-rate fields. DAPM routes connect DMICs, analogue IN1 PGAs, AIF mixers, sidetone, DAC mixers, headphone output, PDM speaker drivers, and clock supplies. Headphone DAPM events enable the charge pump, headphone stages, DC servo startup, output shorts removal, and shutdown sequencing.

## State and Persistence
The regmap cache holds register state while supplies are off; regulator disable notifiers mark it dirty and `wm8995_set_bias_level()` syncs it when transitioning from off to standby after enabling supplies. Bias off disables the bandgap and all supplies. The driver stores live FLL source/input/output but does not implement component suspend/resume restoration despite having `fll_suspend` fields in `struct wm8995_priv`. AIF clocks and MCLK rates are cached in memory and recomputed during DAPM clock events or sysclk/FLL changes. Headphone and DC servo state is programmed directly by DAPM events and observed via a volatile DC servo readback register.

## Dependencies and Integration Points
The driver depends on Linux module, I2C, SPI, regmap, regulator, delay, slab, and ASoC APIs plus the generated local `wm8995.h` register definitions. It integrates with machine drivers through three DAIs named `wm8995-aif1`, `wm8995-aif2`, and `wm8995-aif3`. AIF1/AIF2 support sysclk, format, hw_params, mute, FLL, and tristate callbacks; AIF3 exposes only tristate. It depends on board descriptions providing the eight named regulators and suitable MCLK/FLL clock rates through DAI configuration.

## Risks
`wm8995_set_dai_fmt()` always writes AIF1 format and master registers, even when called for DAI id 1/AIF2, which is a notable behavioral risk if AIF2 format is expected to be independently configurable. `wm8995_hw_params()` divides by `lrclk` for debug output without checking that `bclk_rate / params_rate()` is nonzero; bad or missing AIF clocks can therefore risk divide-by-zero or invalid LRCLK programming. `wm8995_modinit()` can overwrite an I2C registration failure with the SPI registration result, and if SPI registration fails after I2C succeeds it returns failure without unregistering I2C. Component probe error handling disables regulators on ID/reset failure, but if `regcache_sync()` fails in a later standby transition the regulators remain enabled. Capture rates are limited to 48 kHz while playback allows 96 kHz; tests must ensure machine constraints reflect this. The unused `fll_suspend` fields may indicate missing suspend/resume handling or legacy residue.

## Test Signals
Test signals include I2C and SPI probe success/failure, invalid device ID and reset failures, missing regulator handling, regulator disable notifier dirtying and regcache sync after off-to-standby, DAI format calls for both AIF1 and AIF2, all supported sample widths and rates plus unsupported values, zero or unconfigured AIFCLK handling, FLL1/FLL2 start/stop/reconfiguration from MCLK/LRCLK/BCLK, AIF clock restoration after FLL programming, mute and tristate callbacks for all DAIs, headphone DAPM power-up/down with DC servo timeout handling, Class W enable/disable when DAC mixer routes diverge, readable/volatile register coverage, and module init cleanup behavior when only one bus backend is enabled or one registration path fails.
