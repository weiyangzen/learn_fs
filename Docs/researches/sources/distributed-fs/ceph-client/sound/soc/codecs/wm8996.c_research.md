# sources/distributed-fs/ceph-client/sound/soc/codecs/wm8996.c

## Purpose
`wm8996.c` is the ALSA SoC codec driver for the Wolfson WM8996 audio codec. It binds as an I2C device, owns chip power/reset/regmap setup, registers two audio interfaces (`wm8996-aif1` and `wm8996-aif2`), exposes mixer/DSP/EQ/DRC/output controls, describes the DAPM audio routing graph, programs SYSCLK/BCLK/LRCLK/FLL clocks, provides optional GPIO-controller support for the codec GPIO pins, and exports `wm8996_detect()` as the default headset/headphone/button/accessory-detection helper for machine drivers.

## Important APIs, Types, and Functions
- `struct wm8996_priv` is the central driver state: device/regmap/component pointers, optional `wlf,ldo1ena` GPIO, SYSCLK and FLL settings, FLL/DC-servo completions, headphone-output pending/enabled masks, three bulk supplies, regulator notifiers, platform data, per-AIF RX/BCLK rates, ReTune Mobile enum storage, jack-detection state, polarity callback, and optional `gpio_chip`.
- `wm8996_reg[]`, `wm8996_readable_register()`, `wm8996_volatile_register()`, and `wm8996_regmap` define the 16-bit register map, reset defaults, volatile status/readback registers, readable register whitelist, and `REGCACHE_MAPLE` cache policy.
- `wm8996_snd_controls` exposes ALSA controls for capture/playback/output volumes, sidetone, DSP capture/playback filters, DACs, speaker, EQ enable, DRC bytes, soft mute, oversampling, and 3D stereo. `wm8996_eq_controls` adds per-band EQ gain controls when platform ReTune Mobile configs are absent.
- `wm8996_set_retune_mobile()`, `wm8996_put_retune_mobile_enum()`, `wm8996_get_retune_mobile_enum()`, and `wm8996_retune_mobile_pdata()` convert platform ReTune Mobile tables into user-visible DSP1/DSP2 EQ mode controls and choose the closest coefficient set for the active sample rate.
- `wm8996_dapm_widgets` and `wm8996_dapm_routes` describe analogue inputs, DMICs, MICBIAS/LDO2/bandgap/charge-pump supplies, AIF endpoints, DSP/DAC/sidetone mixers, PDM speaker paths, and HPOUT1/HPOUT2 power-up sequencing with DC-servo and remove-short steps.
- `wm8996_set_fmt()`, `wm8996_hw_params()`, `wm8996_set_sysclk()`, `wm8996_update_bclk()`, `fll_factors()`, and `wm8996_set_fll()` implement audio-interface format, PCM word/frame timing, clock-source selection, BCLK divider selection, FLL factor generation, FLL programming, and lock waiting.
- `wm8996_detect()`, `wm8996_micd()`, `wm8996_hpdet_start()`, `wm8996_hpdet_irq()`, `wm8996_irq()`, and `wm8996_edge_irq()` implement accessory detection and interrupt handling for MICD, HP impedance measurement, DC-servo completion, FLL lock, and FIFO errors.
- `wm8996_gpio_*()` and `wm8996_template_chip` register the five codec GPIOs as a sleeping GPIO controller when `CONFIG_GPIOLIB` is enabled.
- `wm8996_i2c_probe()`, `wm8996_probe()`, `wm8996_remove()`, and `wm8996_i2c_remove()` handle device identification, platform defaults, component/DAI registration, IRQ lifecycle, GPIO-controller lifecycle, and power cleanup.

## Control Flow
I2C probe allocates `wm8996_priv`, copies optional `struct wm8996_pdata`, requests the optional `wlf,ldo1ena` GPIO, gets the `DBVDD`, `AVDD1`, and `AVDD2` regulators, registers per-supply disable notifiers that mark the regcache dirty, enables supplies, asserts LDO enable if present, and initializes the I2C regmap. It reads `WM8996_SOFTWARE_RESET` as the chip ID and requires `0x8915`, reads the revision, then either powers the chip down and puts regmap cache-only mode on when an external LDO enable GPIO is used, or issues a software reset when the device remains powered.

After initial identification, probe disables the bulk supplies and programs cached platform defaults: input mode, GPIO defaults, speaker mute sequence, microphone detection polarity defaults, volume-update latches, default TDM slot layouts, and TX LRCLK source mode when the relevant GPIO pin is not functioning as an LRCLK pin. It then registers the optional GPIO chip and calls `devm_snd_soc_register_component()` with the component driver and two DAI drivers.

ASoC component probe records the component pointer, initializes FLL and DC-servo completions, installs either platform ReTune Mobile controls or static EQ controls, and requests a threaded IRQ when the I2C client has one. Level-triggered IRQs use `wm8996_irq()` directly; edge-triggered IRQs use `wm8996_edge_irq()` to drain all pending status. Successful IRQ setup unmasks the top-level interrupt and enables DC-servo, FLL-lock, and FIFO-error reporting.

Runtime audio setup flows through the DAI ops. `set_fmt` selects the register block for AIF1 or AIF2, validates master/slave, BCLK/LRCLK inversion, and DSP_A/DSP_B/I2S/left-justified format bits, then writes AIF control and clock polarity/master bits. `hw_params` selects RX or TX timing registers based on stream direction and GPIO LRCLK configuration, stores the requested BCLK and sample rate, programs word length/slot length, computes LRCLK divisor from BCLK/sample rate, chooses a DSP divider target, updates BCLK dividers from current SYSCLK, and refreshes ReTune Mobile rate-dependent EQ state indirectly through stored `rx_rate[]`.

Power sequencing is DAPM-driven. Bias transition from OFF to STANDBY enables supplies, raises the optional LDO enable, leaves cache-only mode, and syncs cached registers. STANDBY configures MICBIAS for low power; PREPARE returns MICBIAS to regulating mode; OFF switches regmap cache-only, drops the LDO enable, and disables supplies. DAPM events reference-count the bandgap, delay after the charge pump starts, defer headphone DC-servo startup into `wm8996_seq_notifier()`, and apply HPOUT remove-short bits only after pending output state is known.

FLL setup first detects no-op calls and disable requests. Enabling computes divider, N, theta/lambda, reference divider/frequency, outdiv, fratio, and loop gain, writes the FLL registers, enables the bandgap if the FLL was off, clears stale lock completions, enables FLL, triggers live clock switching, and waits for lock by IRQ completion when available or by polling raw status. SYSCLK setup temporarily disables SYSCLK, accepts MCLK1/MCLK2/FLL sources, accepts only the supported 5.6448/6.144/11.2896/12.288/22.5792/24.576 MHz and 32/32.768 kHz rates, updates BCLK dividers, programs source/divider/low-frequency-clock/register-sync bits, and restores the prior SYSCLK enable state.

Accessory detection starts when a machine driver calls exported `wm8996_detect()`. The helper stores the jack and polarity callback, clears MICBIAS discharge, force-enables LDO2 and SYSCLK DAPM pins, enables MICD at a slow debounce rate, and unmasks MICD/HP_DONE interrupts. MICD IRQs report removal, microphone insertion, button up/down, low-impedance headphones, and inverted microphone-ground attempts. Initial microphone/headphone decisions trigger `wm8996_hpdet_start()`, which unclamps HPOUT1, force-enables bandgap, switches jack-detect mode to headphone measurement, and starts HP impedance polling. HP_DONE IRQ then reports headphone versus line-out, optionally with microphone, reclamps idle outputs, returns to microphone detection, and releases the forced bandgap pin.

## State and Persistence Behavior
The main persistent state is hardware configuration cached in regmap plus private mirrors for `sysclk`, `sysclk_src`, `fll_src`, `fll_fref`, `fll_fout`, `rx_rate[]`, `bclk_rate[]`, selected ReTune Mobile modes, pending/enabled headphone output masks, bandgap reference count, and jack-detection state. Register state is intentionally preserved while the chip is powered off through `REGCACHE_MAPLE`; regulator-disable notifiers mark the cache dirty and bias resume performs `regcache_sync()`.

Completions are transient synchronization state. `dcs_done` is completed by DC-servo IRQs or polled by `wait_for_dc_servo()` when no IRQ exists. `fll_lock` is completed by the FLL lock IRQ and is cleared before a new FLL enable attempt. Jack state persists across IRQs in `detecting`, `jack_mic`, and `jack_flips`; public jack state is emitted through `snd_soc_jack_report()`.

Platform data from `<sound/wm8996.h>` is copied into `wm8996_priv` during probe and then materialized into cached registers and optional ALSA controls. The file does not parse device-tree properties beyond standard framework lookups for regulators and the named `wlf,ldo1ena` GPIO. The dynamically allocated `retune_mobile_texts` table is held for the component lifetime.

## Dependencies and Integration Points
The driver depends on ALSA ASoC component, DAI, DAPM, control, PCM, TLV, jack, and trace APIs; Linux I2C, regmap, regulators, GPIO descriptor and GPIO-controller frameworks, IRQ completions, delays, `gcd()`, and kernel allocation helpers; public platform data in `include/sound/wm8996.h`; and local generated register definitions in `sound/soc/codecs/wm8996.h`.

Machine drivers instantiate I2C ID `wm8996`, provide the three core supplies plus the DAPM `CPVDD` regulator supply, optionally provide `wlf,ldo1ena`, an IRQ, GPIO defaults, input modes, speaker mute sequence, MICD polarity defaults, and ReTune Mobile tables. The Samsung Speyside machine driver is a direct in-tree user: it calls `snd_soc_dai_set_sysclk()` with `WM8996_SYSCLK_MCLK2` or `WM8996_SYSCLK_FLL`, calls `snd_soc_dai_set_pll()` with `WM8996_FLL_MCLK2`, calls `wm8996_detect()`, and links to codec DAI names such as `wm8996-aif1`.

ASoC integration is through `soc_component_dev_wm8996`, which supplies the controls, DAPM graph, bias handler, sequence notifier, and `set_pll` hook. Runtime stream integration is through two DAIs: AIF1 supports 1-6 playback/capture channels and AIF2 supports 1-2 playback/capture channels, both at 8/16/32/44.1/48 kHz and S8/S16_LE/S20_3LE/S24_LE/S32_LE formats with 24 significant bits.

## Risks and Edge Cases
- `wm8996_hw_params()` computes the best DSP divider index but writes `i << dsp_shift` after the loop rather than `best << dsp_shift`; this appears to program an out-of-range/constant divider value and should be validated against hardware expectations.
- `wm8996_put_retune_mobile_enum()` bounds the selected item against `pdata->num_retune_mobile_cfgs`, not `num_retune_mobile_texts`; duplicate platform names can make the ALSA enum item count smaller than this bound.
- `wm8996_set_retune_mobile()` uses block 1 base `WM8996_DSP1_RX_EQ_GAINS_2`, which is unusual for a control named `DSP2 EQ Mode`; confirm whether this is intentional register layout handling or a copy/paste issue.
- `retune_mobile_texts` is allocated with `krealloc()` in component probe but no matching free is visible in component or I2C remove.
- Many probe-time platform-default and volume/slot `regmap_update_bits()` calls ignore return values, so I/O failures can leave hardware partially configured while probe still succeeds.
- Several paths assume prior configuration: BCLK updates require a supported non-low SYSCLK, FLL lock depends on correct IRQ mask/polarity or raw-status polling, and `hw_params` relies on sane BCLK/sample-rate ratios from `snd_soc_params_to_bclk()`.
- `wm8996_bg_disable()` decrements `bg_ena` without a floor check, so mismatched DAPM/FLL bandgap enable/disable paths could underflow the reference count and incorrectly clear the hardware bit.
- Accessory detection is stateful and impedance-threshold based; wrong MICD polarity defaults, broken IRQs, or missing forced DAPM supplies can stall detection or misreport headphones, headsets, line-out, and button events.
- GPIO registration uses `gpiochip_add_data()` and manual `gpiochip_remove()`. Probe failure paths remove it, but component/device lifetime ordering should be checked when device-managed component registration fails or unbind happens during active GPIO use.
- The driver supports platform data but no local OF/ACPI parser for WM8996-specific options, which limits board configuration unless another layer supplies `struct wm8996_pdata`.

## Test Signals
Probe tests should cover good and bad chip IDs, revision logging, regulator-get/enable failures, optional LDO-enable GPIO sequencing, software-reset versus LDO-powerdown paths, regcache cache-only/dirty behavior after supply disable, platform input/GPIO/MICD/speaker defaults, default TDM slot programming, GPIO1/GPIO2 LRCLK-mode decisions, GPIO-controller registration and removal, component/DAI registration, and IRQ request/unmask failure handling.

Audio tests should exercise both DAIs, all declared sample rates and PCM formats, AIF1 1-6 channel paths, AIF2 1-2 channel paths, playback and capture register selection, DSP_A/DSP_B/I2S/left-justified formats, master/slave and inversion combinations, supported and rejected SYSCLK rates, MCLK1/MCLK2/FLL source switching, BCLK divisor selection, LRCLK divisor programming, and DAPM routing from analogue/DMIC/AIF sources through DSP, sidetone, DAC, headphone, and PDM speaker outputs.

Clock and power tests should cover integer and fractional FLL factors, MCLK1/MCLK2/DACLRCLK1/BCLK1 sources, FLL disable/re-enable/no-op calls, IRQ and no-IRQ FLL lock paths, timeout handling, low-frequency SYSCLK mode, bias OFF/STANDBY/PREPARE transitions, regcache sync after power cycling, DC-servo startup with IRQ and polling, HPOUT remove-short sequencing, and bandgap reference count balance.

Jack-detection tests should inject MICD and HP_DONE status patterns for no accessory, headphone, line-out, headset microphone, inverted microphone polarity, button press/release, invalid MICD state, HPDET busy/error, removal, and edge-triggered IRQ draining. ALSA control tests should read/write volume, mute, filter, DRC byte, EQ, ReTune Mobile, sidetone, speaker, and oversampling controls and verify expected register updates and DAPM route activation.
