# sources/distributed-fs/ceph-client/sound/pci/es1938.c

## Purpose

This file is the ALSA PCI driver for ESS Solo-1 compatible chips, matching PCI vendor ESS device `0x1969`. It exposes one ALSA card with two playback substreams, one capture substream, mixer controls, optional OPL3 and MPU-401 devices, optional gameport support, interrupt handling, and suspend/resume restoration. The implementation is centered on direct I/O to the Solo-1 PCI, SoundBlaster-compatible mixer, and distributed DMA register windows.

## Important APIs, Types, and Functions

`struct es1938` is the card-private state. It stores I/O base addresses, IRQ, PCI/card/PCM/rawmidi pointers, active stream flags, DMA start/size/shift values, substream pointers, spinlocks, optional gameport, and mixer register save state for PM. Register access helpers include `snd_es1938_mixer_write/read/bits()`, `snd_es1938_write_cmd()`, `snd_es1938_get_byte()`, `snd_es1938_write/read/bits()`, and `snd_es1938_reg_read/bits()`. PCM callbacks are split by hardware engine: `snd_es1938_capture_*`, `snd_es1938_playback1_*` for Audio2, and `snd_es1938_playback2_*` for Audio1/DDMA. Mixer callbacks are generated around `ES1938_SINGLE*` and `ES1938_DOUBLE*` plus special handlers for capture source, spatializer, and hardware volume state.

## Control Flow

Probe allocates an ALSA card, verifies all five PCI I/O BARs, enables the PCI device, enforces a 24-bit DMA mask, requests regions and IRQ, records BAR addresses, sets `ddma_port`, and initializes the chip. It then creates PCM, mixer, OPL3, MPU-401, and optional gameport resources before card registration. PCM open records substream ownership; capture and playback substream 1 cannot coexist with playback substream 2 because capture and playback2 both use Audio1/DDMA. Prepare computes byte counts, format flags, DMA shifts, clock divisors, reload counters, format registers, and DMA registers. Trigger toggles `chip->active` bits and writes Audio2 or Audio1 control registers. The interrupt handler routes Audio1 IRQs to capture or playback2, Audio2 IRQs to playback1, hardware-volume IRQs to ALSA control notifications, and MPU IRQs to the MPU-401 UART layer.

## State and Persistence Behavior

Runtime state lives in `struct es1938`: stream ownership, active engine bits, DMA addresses, last valid capture pointer, mixer-control pointers for notifications, and saved PM registers. Hardware mixer state is mirrored only during suspend by `chip->saved_regs`; normal control reads query device registers. Capture intentionally disables mmap and uses `.copy` because captured data starts at `dma_area + 1` and wraps by one byte. Suspend saves selected registers, disables IRQ generation, frees the IRQ, and marks D3hot. Resume reacquires IRQ, reinitializes hardware, replays saved registers, and marks D0.

## Dependencies and Integration Points

The driver integrates with ALSA card/PCM/control/TLV layers, PCI managed resources, raw MIDI MPU-401, OPL3, gameport, Linux IRQ and PM frameworks, and low-level I/O port access. It depends on ESS Solo-1 register semantics and on a 24-bit coherent DMA mask.

## Risks and Test Signals

Risks include documented playback IRQ timing failures, spurious interrupts, unstable DMA counter reads, the Audio1 capture/playback2 exclusivity rule, hardware-volume notification pointer lifetime, PM IRQ reacquisition, and small DMA buffer limits. Test by probing/removing, playing both substreams, capturing across wraparound, validating capture plus playback1 and rejection of capture plus playback2, exercising mixer controls and hardware volume IRQs, checking OPL3/MPU, and suspending/resuming with mixer state retained.
