# sources/distributed-fs/ceph-client/lib/crypto/x86/poly1305-x86_64-cryptogams.pl

## Purpose
Perl/CRYPTOGAMS generator for x86_64 Poly1305 assembly. It emits scalar base-2^64 Poly1305 plus AVX, AVX2, AVX512F, and non-kernel VPMADD52/AVX512IFMA variants, with Linux `SYM_FUNC_*` output in kernel mode and perlasm/Win64 handling outside the kernel.

## APIs, Control Flow, And Integration
Key emitted entries are `poly1305_init_x86_64`, `poly1305_blocks_x86_64`, `poly1305_emit_x86_64`, `poly1305_blocks_avx`, `poly1305_emit_avx`, `poly1305_blocks_avx2`, and `poly1305_blocks_avx512`; non-kernel builds can also emit radix-2^44 IFMA routines and ChaCha20-Poly1305 XOR/pad helpers. The generator detects output flavor and assembler SIMD capability, builds one large `$code` string, then rewrites syntax for kernel mode. Scalar processing loops over 16-byte blocks with `poly1305_iteration`; SIMD paths convert state to base 2^26, precompute `r^2..r^4`, process long aligned runs in parallel, reduce lazily, and fold lanes back into the context. The AVX2/AVX512 code is generated by a shared `poly1305_blocks_avxN()` helper.

## State, Dependencies, Risks, And Tests
Persistent state is entirely caller-owned context memory: scalar `h[3]/r[2]`, AVX `h[5]/is_base2_26/rn[]`, and IFMA key-power slots. The generated code is tightly coupled to `poly1305.h` offsets and CPU/FPU dispatch. Main risks are context layout drift, mixed scalar/SIMD radix conversion errors, AVX512 feature misuse, and hard-to-review lazy reductions. Test signals are Poly1305 known-answer vectors across all backends, forced AVX-to-scalar update sequences, boundary lengths around 16/32/64/128/288/512 bytes, and kernel crypto selftests on CPUs with different SIMD features.
