# sources/distributed-fs/ceph-client/lib/crypto/x86/sha256.h

## Purpose
x86_64 SHA-256 dispatch and architecture hook header. It selects generic, SSSE3, AVX, AVX2/BMI2, SHA-NI, or Zhaoxin PHE block transforms and exposes a SHA-NI two-message finalization optimization.

## APIs, Control Flow, And Integration
`DEFINE_STATIC_CALL(sha256_blocks_x86, sha256_blocks_generic)` provides the runtime target. `DEFINE_X86_SHA256_FN` wraps assembly transforms with `irq_fpu_usable()` and `kernel_fpu_begin/end()`. `sha256_blocks_phe()` invokes Zhaoxin `REP XSHA256` using an aligned stack buffer. `sha256_finup_2x_arch()` calls `sha256_ni_finup2x` when SHA-NI, length bounds, and FPU availability permit. `sha256_mod_init_arch()` prefers SHA-NI, then PHE, AVX2+BMI2, AVX, SSSE3, and generic fallback.

## State, Dependencies, Risks, And Tests
The static-call target and `have_sha_ni` key persist after init; per-call state is caller-owned. Dependencies include static calls, FPU APIs, CPU features, KMSAN output unpoisoning, `struct __sha256_ctx` offsets, and all SHA-256 assembly files. Risks are feature-check drift, vendor PHE alignment/register assumptions, FPU misuse, and long preemption-disabled windows for finup. Tests should cover backend dispatch, known-answer vectors, PHE when available, `finup2x` generic comparisons, and KMSAN cleanliness.
