# sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-client/src/main/java/org/apache/hadoop/hdfs/DistributedFileSystem.java

`DistributedFileSystem` is the public Hadoop `FileSystem` implementation for `hdfs://`. It adapts generic filesystem APIs and HDFS-specific admin/extension APIs to `DFSClient`, handling path qualification, symlink resolution, operation counters, HA token service identity, snapshots, encryption zones, erasure coding, storage policy, cache administration, ACLs, xattrs, trash roots, and HDFS output-stream builders.

Core APIs include lifecycle and identity (`initialize()`, `initDFSClient()`, `getUri()`, `getPathName()`, `close()`), standard filesystem operations (`open`, `create`, `append`, `rename`, `delete`, `truncate`, listing, mkdir, status, checksum, permission/owner/time, ACL, xattr, access), and HDFS-only operations for lease recovery, safe mode, namespace save/roll, block/DataNode health, storage policies, snapshots and diff listing, cache directives/pools, encryption zones, KMS token issuer support, erasure coding management, inotify streams, open-file listing, slow DataNode stats, located blocks, and enclosing-root lookup. Inner iterators handle directory, batched, and snapshot-diff pagination; `HdfsDataOutputStreamBuilder` implements HDFS-specific create/append options.

The usual control flow increments `FileSystem.Statistics` and `DFSOpsCountStatistics`, fixes relative paths, then uses `FileSystemLinkResolver`. The local `doCall()` path invokes `DFSClient` with validated path strings; `next()` delegates to target filesystems or rejects cross-filesystem symlinks for HDFS-only features. Create/append paths wrap `DFSOutputStream` and close it if wrapping fails. Listing APIs either materialize all batches or lazily fetch NameNode batches through remote iterators.

Instance state is small: working directory, normalized URI, `DFSClient`, checksum verification flag, and operation statistics. Durable state changes are performed by NameNode/DataNode services behind `DFSClient`; favored nodes are a request-time hint. Dependencies include almost all HDFS client protocol records, `DFSClient`, link resolvers, `GlobalStorageStatistics`, `HAUtilClient`, KMS interfaces, snapshot/cache/EC/storage-policy classes, and Hadoop token machinery.

Risks come from broad facade behavior: inconsistent symlink resolution, missing statistics increments, HDFS-only operations crossing non-HDFS symlinks, stream leaks on wrapper failure, trash-root fallback masking IO failures, existing `.Trash` files/permissions, builder flag conflicts, and path-handle validation. Test signals include symlink behavior by operation family, lazy and batched listing cursors, create/append builder options, safe stream cleanup, path handles, trash roots across normal/EZ/snapshot directories, snapshot diff pagination, EC/storage policy calls, ACL/xattr delegation, HA canonicalization, counters, and close behavior.
