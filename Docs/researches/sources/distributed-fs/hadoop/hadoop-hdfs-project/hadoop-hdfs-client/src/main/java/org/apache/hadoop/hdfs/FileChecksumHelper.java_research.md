# sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-client/src/main/java/org/apache/hadoop/hdfs/FileChecksumHelper.java

`FileChecksumHelper` contains package-private strategy classes for computing file checksums for replicated and striped HDFS files. It supports legacy MD5-of-block-CRC checksums and composite CRC checksums through DataNode checksum RPCs.

`FileChecksumComputer` owns source path, requested length, `DFSClient`, `ClientProtocol`, combine mode, derived `BlockChecksumType`, located blocks, remaining length, checksum properties, retry bookkeeping, and a `DataOutputBuffer` of raw per-block checksums. Main methods are `compute()`, subclass `checksumBlocks()`, `makeFinalResult()`, `makeMd5CrcResult()`, `makeCompositeCrcResult()`, `refetchBlocks()`, `extractChecksumProperties()`, and `populateBlockChecksumBuf()`. `ReplicatedFileChecksumComputer` calls `Sender.blockChecksum()` per block; `StripedFileNonStripedChecksumComputer` builds `StripedBlockInfo` and calls `Sender.blockGroupChecksum()` per block group.

Construction maps `ChecksumCombineMode` to block checksum type and initializes remaining bytes. `compute()` returns the historical empty-file checksum for no blocks, otherwise gathers block checksums then combines them. Replicated and striped flows try DataNodes until one succeeds, retry once on invalid block tokens by refetching locations, and retry once on invalid encryption keys by clearing the cached data encryption key. Partial requests shrink the final block/group length.

State is per-computation and memory-only. It may mutate the `ExtendedBlock` length for partial checksum requests and refresh block locations/tokens from `DFSClient`; results are returned as `FileChecksum`. Dependencies include DataTransfer protocol `Sender`, protobuf helpers, `DFSClient`, `ClientProtocol`, checksum classes, `CrcComposer`, `CrcUtil`, and erasure coding records.

Risks include mixed CRC handling, composite CRC rejection of mixed types, tolerance of differing bytes-per-CRC only in composite mode, empty-file compatibility, use of `DataOutputBuffer.getData()` capacity beyond written bytes, loop-index retry bookkeeping, and snapshot/partial-length remaining calculations. Test signals include empty files, partial checksums, replicated multi-block files, token and encryption retry, all replicas failing, composite CRC composition, mixed CRC behavior, striped block groups, and older DataNodes without explicit CRC type.
