## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs/src/main/java/org/apache/hadoop/hdfs/server/namenode/FSImageFormatPBINode.java

Purpose: protobuf FSImage inode-section codec for NameNode namespace persistence. It translates `FsImageProto.INodeSection`, `INodeDirectorySection`, and `FilesUnderConstructionSection` protobuf records into in-memory `INode` objects on load, and serializes the live inode map, directory child links, and leases on save. It is the inode-specific worker used by `FSImageFormatProtobuf`.

Important APIs and constants: the top-level constants define ACL and xattr compact bit layouts that are shared with `AclEntryStatusFormat` and `XAttrFormat`. `Loader.loadPermission`, `loadAclEntries`, `loadXAttrs`, and `loadQuotaByStorageTypeEntries` decode compact protobuf ids through `SerialNumberManager.StringTable`. `Loader.loadINodeDirectory` constructs directories, quota features, ACL features, and xattr features. `Loader.updateBlocksMap` connects file blocks to the `BlockManager`. `Saver.buildINodeFile`, `buildINodeDirectory`, and the section serializers are the corresponding write-side API.

Loader control flow: `loadINodeSection` reads an `INodeSection` header, resets `FSDirectory`'s last inode id, configures startup progress, then repeatedly parses delimited inode records. Root inode attributes are merged into the existing root; other inodes are built, inserted into the inode map under synchronization, and batched for async name-cache and block-map updates. `loadINodeDirectorySection` parses parent-child `DirEntry` records after inode objects exist, adds normal children by inode id, and adds reference children by index into the loader context reference list. `loadFilesUnderConstructionSection` drains records for compatibility because protobuf file UC state is embedded in inode file records and leases are added during inode load.

Parallel load behavior: if `FSImageFormatProtobuf` enables parallel loading and the image has `_SUB` sections, `loadINodeSectionInParallel` and `loadINodeDirectorySectionInParallel` submit subsection readers to an executor. The first inode subsection carries the header and is processed before submitting work. Each worker reads a bounded section stream from the parent loader. A `CountDownLatch` joins all work, exceptions are collected in a synchronized list, and inode totals are checked against the expected header count. Non-thread-safe updates are guarded by synchronization or funneled through single-thread executors for block-map and name-cache mutation.

INode conversion behavior: file loading selects contiguous or striped `BlockInfo` based on protobuf block type and erasure-coding policy id. Striped files require a valid persisted erasure-coding policy and use `BlockInfoStriped`; replicated files use `BlockInfoContiguous` and replication. The loader restores permissions, modification/access times, storage policy, ACLs, xattrs, and file-under-construction data. For UC files, it adds a lease and converts the last block to `UNDER_CONSTRUCTION`. Directory loading restores namespace and storage-space quota, per-storage-type quota, ACLs, and xattrs. Symlink loading restores target, times, and permissions.

Saver control flow: `serializeINodeSection` writes the section header with last inode id and inode-map size, then serializes every inode in map iteration order, committing subsections when the parent saver's `inodesPerSubSection` threshold is reached. `serializeINodeDirectorySection` writes child-link records only for directories with children, validates that every non-reference child exists in the inode map, records reference children into `SaverContext.refList`, and counts dangling-child errors instead of immediately failing. `serializeFilesUCSection` iterates lease-manager inode ids and writes compatibility records after validating the inode exists and is still under construction.

State and persistence behavior: this file persists inode ids, local names, file blocks, block type, replication or erasure-coding policy id, preferred block size, storage policy, directory quotas, type quotas, ACL entries, xattrs, symlink targets, under-construction client metadata, directory tree topology, and inode references. It deliberately separates inode object records from directory child edges, allowing all inodes to be loaded before parent-child topology is attached. It depends on the string table for compact permission, ACL, and xattr identity storage.

Dependencies and integration points: integrates tightly with `FSImageFormatProtobuf.Loader` and `.Saver`, `FSDirectory`, `FSNamesystem`, `BlockManager`, `LeaseManager`, `SerialNumberManager`, `PBHelperClient`, `ErasureCodingPolicyManager`, `Snapshot` reference lists, `QuotaCounts`, ACL/xattr feature classes, and startup progress. Offline image viewers also reuse the public static loader helpers to decode permissions, ACLs, and xattrs from protobuf images without instantiating the full NameNode.

Risks: the parallel path is sensitive to section boundaries and synchronization; incorrect subsection headers or counts throw corruption errors, while missing executor shutdown or delayed async updates could leave maps incomplete if callers skipped `waitBlocksMapAndNameCacheUpdateFinished`. The write path logs and counts dangling child pointers, so callers must treat nonzero image errors as meaningful. String-table mismatch corrupts users, groups, ACL names, or xattr names. Striped-file loading assumes erasure-coding policies have already been loaded before inode sections. Root feature merging must preserve the existing root identity while accurately copying ACL, xattr, quota, and encryption-zone metadata.

Test signals: exercise protobuf image save/load with replicated and erasure-coded files, ACL and xattr round trips, per-storage-type quota persistence, under-construction lease restoration, snapshot/reference child ordering, parallel save/load with subsection thresholds, dangling child detection, root ACL/xattr/encryption zone restoration, and offline image viewer permission/ACL/xattr decoding. Tests should compare inode counts, block map ownership, child order, and lease-manager state after reload.
