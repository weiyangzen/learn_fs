# sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs/src/main/java/org/apache/hadoop/hdfs/server/datanode/ProvidedReplica.java

## Purpose

`ProvidedReplica` is the abstract base for finalized replicas whose block bytes are supplied by an external or "provided" filesystem rather than by normal local DataNode block files. It lets the HDFS dataset expose externally stored file regions as `ReplicaInfo` objects while explicitly rejecting local mutation operations.

## Important APIs, Types, And Functions

- Constructors accept either a full remote `URI`, a `Path` prefix plus suffix, or a copied `ProvidedReplica`; all preserve block id, length, generation stamp, volume, optional `PathHandle`, configuration, and remote `FileSystem`.
- `getDataInputStream(long)` opens the remote file or path handle, seeks to `fileOffset + seekOffset`, and wraps the stream in a bounded stream limited to the replica block length.
- `getMetadataInputStream`, `metadataExists`, and `getMetadataLength` expose a shared null-checksum byte array generated by `FsDatasetUtil`.
- Mutation methods such as output streams, deletes, renames, generation-stamp bumps, truncation, pinning, copy, and recovery-info creation throw `UnsupportedOperationException`.
- `compareWith(FsVolumeSpi.ScanInfo)` compares scanner file-region information against the provided block id, path, offset, length, and generation stamp.

## Control Flow

Construction resolves or reuses a remote filesystem. If no `FileSystem` is passed, the class logs a warning and attempts `FileSystem.get(...)`; later reads fail with `IOException` if that resolution failed. Read flow computes the remote URI from the direct URI or prefix/suffix pair, opens by `PathHandle` when present, falls back to `Path`, seeks to the file-region offset plus caller offset, and bounds reads to `getBlockDataLength()`.

## State And Persistence

The class stores only replica metadata and handles: `fileURI`, `pathPrefix`, `pathSuffix`, `fileOffset`, `conf`, `pathHandle`, and `remoteFS`. It does not own or persist the underlying bytes. Metadata is synthetic and immutable, represented by a shared null-checksum array.

## Dependencies And Integration Points

It extends `ReplicaInfo`, participates in dataset volume and scanner APIs, uses Hadoop `FileSystem`/`FSDataInputStream`/`PathHandle`, and relies on `FileRegion` for provided-storage scan comparisons. `ReplicaBuilder` constructs finalized provided replicas when a volume has `StorageType.PROVIDED`.

## Risks And Edge Cases

Remote filesystem lookup failure is deferred until read/existence checks. `PathHandle` open failures are surfaced as `IOException`, with a misspelled message. `blockDataExists()` checks only path existence and not file offset or length. Mutation paths are deliberately unsupported, so callers must avoid using provided replicas in write, recovery, or truncate workflows.

## Test Signals

Useful tests cover URI versus prefix/suffix construction, path-handle reads, bounded reads from nonzero offsets, null remote-filesystem failures, null checksum metadata, scan-info matching, and every unsupported mutation method throwing consistently.
