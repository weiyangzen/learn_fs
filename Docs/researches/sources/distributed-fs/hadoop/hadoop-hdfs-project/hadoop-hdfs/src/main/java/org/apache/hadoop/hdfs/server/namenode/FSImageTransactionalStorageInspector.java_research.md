## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs/src/main/java/org/apache/hadoop/hdfs/server/namenode/FSImageTransactionalStorageInspector.java

Purpose: storage inspector for transactional NameNode layouts where fsimage filenames carry checkpoint txids such as `fsimage_0000000000000000123`. It discovers valid image files, records the highest seen transaction id from storage metadata, detects unfinalized upgrades, and returns all latest-equivalent image copies.

Important APIs and state: constructors accept either the default `NameNodeFile.IMAGE` type or an `EnumSet<NameNodeFile>` for alternate image-like files used by retention and transfer code. Each target name builds a regex `<name>_(\\d+)`. `inspectDirectory` updates `needToSave`, `maxSeenTxId`, `foundImages`, and `isUpgradeFinalized`. `getLatestImages` returns all images whose txid equals the highest discovered txid. `getFoundImages` exposes an immutable copy for retention logic and tests.

Control flow: inspection first treats a missing version file as a just-formatted directory and marks `needToSave`. It then tries to read the directory's transaction id file with `NNStorage.readTransactionIdFile`; failure logs a warning and skips further inspection of that directory. It lists the `current` directory, matches candidate filenames against configured image patterns, parses the txid, and accepts only files from storage directories configured for images. Malformed txid names are logged and skipped. The finalized flag is the conjunction of all inspected directories lacking a `previous` directory.

State and persistence behavior: the class does not open or validate image contents. Its durable inputs are the storage version file, seen-txid file, `current` directory listing, fsimage-like filenames, storage directory type, and `previous` directory. `maxSeenTxId` is a lower bound that later edit-log selection must honor. `needToSave` only covers freshly formatted directories in this implementation; inconsistent or stale transactional image selection is handled by missing image errors or edit-log recovery elsewhere.

Dependencies and integration points: extends `FSImageStorageInspector`, uses `NNStorage.NameNodeFile`, `NameNodeDirType`, `StorageDirectory`, `FileUtil.listFiles`, and Guava immutable/list helpers. Used by `FSImage` load planning, `BackupImage`, `NNStorageRetentionManager`, `NNStorage`, `FSImageTestUtil`, and tests such as `TestFSImageStorageInspector` and `TestNameEditsConfigs`.

Risks: failure to read a seen-txid file causes the whole directory to be skipped, which can reduce image redundancy. File discovery trusts filename parsing and storage directory type but does not verify image checksum or summary. If `FileUtil.listFiles` fails, the directory contributes no images while only logging a warning. Returning all equal-latest images is useful for redundancy but assumes downstream loaders can choose or validate among them. Regex construction depends on `NameNodeFile.getName()` staying literal enough for safe pattern use.

Test signals: cover multiple directories with different and equal image txids, malformed image filenames, image files in edits-only dirs, missing version files setting `needToSave`, unreadable seen-txid/listing warnings, max-seen-txid aggregation, unfinalized upgrade detection, alternate `NameNodeFile` patterns, and `FileNotFoundException` when no valid images exist.
