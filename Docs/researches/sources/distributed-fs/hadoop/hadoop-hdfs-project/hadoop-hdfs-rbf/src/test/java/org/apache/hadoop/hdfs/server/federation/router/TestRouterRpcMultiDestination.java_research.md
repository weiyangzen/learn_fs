## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-rbf/src/test/java/org/apache/hadoop/hdfs/server/federation/router/TestRouterRpcMultiDestination.java

Purpose: subclass of `TestRouterRpc` that reuses the base Router RPC suite under a mock resolver configuration with multiple destinations for root and same-nameservice paths. It focuses on fallback, union listing, retry metrics, multi-destination file/block operations, partial listing behavior, and caller context propagation.

Important APIs and types include inherited `TestRouterRpc` helpers, `MockResolver`, `FileSubclusterResolver`, `PathLocation`, `RemoteLocation`, `FederationRPCMetrics`, `ClientProtocol`, `RouterRpcServer`, `RouterClientProtocol`, `DistributedFileSystem`, `LocatedBlock`, `CallerContext`, audit logs, and Whitebox access to `FSNamesystem` HA context and Router client settings.

Control flow: overridden `testSetup()` installs base mock locations, adds `/` to both `ns0` and `ns1`, adds `/same` to two destinations in `ns0`, recreates fixtures, chooses Router/NameNode, and creates a file reachable through a path with two destinations. `testListing()` constructs expected entries from mount points plus each destination's filesystem and verifies Router ordering. Overrides of `testProxyListFiles()` and `testProxyRenameFiles()` assert root and `/same` union listing and allow renames from nameservice paths into root. Other tests check proxy operation counts when the first destination throws `RemoteException`, additional-block routing after `previousBlock` becomes non-null, `recoverLease` and `isFileClosed` false cases on open streams, EC policy in content summary, behavior when one subcluster is forced into standby, and caller context/audit propagation through concurrent and sequential multi-destination invocations.

State and persistence behavior is mostly mock-resolver state and MiniDFS filesystem state. The suite mutates HA internals for one NameNode, toggles Router partial-list behavior, captures logs, opens streams, and then restores modified HA/router state. It also depends on inherited cleanup for caller context.

Dependencies and integration points are the base Router RPC cluster, multi-destination path resolution, Router RPC metrics, NameNode logs, audit logs, and local network interface discovery for client IP assertions. Risks covered include duplicate or missing union listing entries, retry/fallback metrics drift, block operations continuing to fan out after a previous block identifies the owning namespace, partial result handling under subcluster failure, and caller context duplication. Test signals include exact listing order, metrics deltas, log substrings, filesystem existence checks, false return assertions for open-file operations, and audit caller-context validation.
