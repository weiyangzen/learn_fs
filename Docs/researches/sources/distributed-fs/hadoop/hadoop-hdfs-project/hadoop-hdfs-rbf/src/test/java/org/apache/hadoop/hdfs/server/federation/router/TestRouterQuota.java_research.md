## sources/distributed-fs/hadoop/hadoop-hdfs-project/hadoop-hdfs-rbf/src/test/java/org/apache/hadoop/hdfs/server/federation/router/TestRouterQuota.java

Purpose: JUnit 5 integration coverage for Router-based Federation quota behavior. It starts a `StateStoreDFSCluster` with two nameservices and a Router configured with state store, admin, quota, and RPC services, then verifies namespace quota, storage space quota, storage-type quota, quota synchronization to backing NameNodes, cache refresh, stale cleanup, and global inherited quota semantics.

Important APIs and types include `StateStoreDFSCluster`, `RouterContext`, `MountTableResolver`, `MountTableManager`, `MountTable`, `RouterQuotaUsage`, `RouterQuotaUpdateService`, `RouterQuotaManager`, `Quota`, `ClientProtocol`, `DFSClient`, `QuotaUsage`, and HDFS exceptions such as `NSQuotaExceededException`, `DSQuotaExceededException`, `QuotaByStorageTypeExceededException`, and `AccessControlException`. Helper methods wrap mount-table admin operations (`addMountTable`, `updateMountTable`, `removeMountTable`, `getMountTable`), append bytes through `DFSClient`, and prepare quota inheritance or storage-type fixtures.

Control flow is fixture-heavy: `setUp()` builds the federated cluster, sets a small quota cache interval and block size, starts routers, and captures two NameNode contexts plus the mount resolver. Each test creates real destination directories, installs mount entries with quotas, calls router or NameNode APIs, invokes `periodicInvoke()` when deterministic quota refresh is needed, and asserts both router-visible and underlying NameNode state. The suite distinguishes direct mount-point operations from non-mount child operations, verifies that unrelated metadata operations are not blocked after quota violations, and tests missing-destination behavior by deleting or omitting backing paths.

State and persistence behavior centers on two stores: the Router local quota cache and mount-table records in the state store. Some tests confirm admin updates persist quota definitions into mount entries and propagate to NameNodes; `testRouterQuotaUpdateService` explicitly asserts that periodic cache refresh updates local `RouterQuotaManager` usage without mutating state-store usage fields. Removal tests assert stale cache entries and remote quota definitions are cleared.

Dependencies and integration points are the Router admin protocol, mount-table resolver cache reloads, HDFS quota APIs, state-store driver reads, and real MiniDFS filesystem mutations. Risks covered include stale quota entries, path-prefix confusion, inherited global quota computation, storage type array handling, failed destination lookups, and quota exceptions leaking into unrelated operations. Test signals are direct exception interception, quota counter equality checks, state-store record inspection, and backend NameNode quota validation.
