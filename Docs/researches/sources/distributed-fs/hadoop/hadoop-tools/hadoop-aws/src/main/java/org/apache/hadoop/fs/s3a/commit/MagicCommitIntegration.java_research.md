## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/commit/MagicCommitIntegration.java

Purpose: isolates magic-committer support from `S3AFileSystem`, mapping magic paths to final destinations and selecting upload trackers. Important APIs are constructor, `keyOfFinalDestination()`, `createTracker()`, `isMagicCommitEnabled()`, `isMagicCommitPath(Path)`, and `isUnderMagicPath()`. Control flow enables magic only when configured and multipart upload is enabled. For a create path, it splits path elements, ignores metadata files, checks magic path status, computes final destination key, increments magic-file statistics, and returns either `S3MagicCommitTracker` or `InMemoryMagicCommitTracker` based on configuration; non-magic paths return plain `PutTracker`, and disabled magic paths log a warning then downgrade. State is owner filesystem reference plus effective enablement flag; persistence occurs through pending `.pending` metadata objects and multipart upload tracking selected by the tracker. Dependencies include `MagicCommitPaths`, magic tracker classes, S3A store context/statistics, and commit constants. Integration points are S3A create/multipart write path and magic committer job commit. Risks include path parsing edge cases, metadata-file exclusion, disabled multipart silently disabling magic, in-memory tracking scalability, and warning-only downgrade when magic-like paths are used without support. Test signals include `TestMagicCommitPaths`, `TestMagicCommitTrackerUtils`, and magic protocol integration/failure tests.
