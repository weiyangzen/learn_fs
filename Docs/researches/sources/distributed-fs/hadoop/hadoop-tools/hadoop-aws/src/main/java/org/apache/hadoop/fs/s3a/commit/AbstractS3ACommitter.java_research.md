## sources/distributed-fs/hadoop/hadoop-tools/hadoop-aws/src/main/java/org/apache/hadoop/fs/s3a/commit/AbstractS3ACommitter.java

Purpose: shared base for S3A output committers that complete multipart uploads instead of relying on S3 rename semantics. Important APIs include constructor validation, path accessors, abstract job/task path hooks, `setupJob()`, `setupTask()`, `commitJob()`, `abortJob()`, `cleanup()`, `commitPendingUploads()`, `precommitCheckPendingFiles()`, `abortPendingUploads*()`, `buildJobUUID()`, `maybeCreateSuccessMarker*()`, `maybeSaveSummary()`, `startOperation()`, `getIOStatistics()`, and nested `ActiveCommit`. Control flow constructs with a required output path, resolves and verifies S3A destination/multipart support, sets audit context, creates shared `CommitOperations`/statistics, then during job setup patches UUID config, creates the destination dir, and warns about active uploads. Job commit creates a `CommitContext`, lists pending uploads, runs subclass precommit, commits each `.pendingset` in parallel, writes `_SUCCESS`/summary data, and cleans up; failures call `jobCompleted(false)`, abort, save failure summary, and rethrow. State includes UUID/source, output/work paths, destination FS, job context, marker flag, stats, operations, audit span source, and `jobSetup`. Persistence involves pending commit metadata, multipart upload completion/abort, `_SUCCESS` `SuccessData`, optional summary reports, and configuration UUID propagation. Dependencies include MapReduce committer APIs, S3A FS/commit files/operations, AWS `MultipartUpload`, audit/statistics APIs, and `TaskPool`. Risks include UUID collision/mis-propagation, self-generated task UUID rejection, concurrent jobs affected by cleanup aborts, partial commits requiring revert/abort, large pending sets, summary-write failures, and S3 multipart settings. Test signals include broad committer integration and failure suites: magic/staging protocols, factory, upload recovery, commit operation cost, and fault injection.
