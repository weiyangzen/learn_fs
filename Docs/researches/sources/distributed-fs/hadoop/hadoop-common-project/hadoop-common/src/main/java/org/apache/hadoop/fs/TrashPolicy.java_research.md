## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/TrashPolicy.java

`TrashPolicy` is the abstract pluggable policy base for trash behavior. It stores protected `FileSystem fs`, `Path trash`, and `deletionInterval`, and defines initialization, enablement, move, checkpoint creation/deletion, immediate deletion, current trash directory, path-specific trash directory, and emptier factory methods. The deprecated initializer takes a home path; the modern initializer takes only configuration and filesystem to support encryption-zone-specific trash roots. Static `getInstance()` methods instantiate the configured `fs.trash.classname` with `ReflectionUtils` and initialize it. State is owned by concrete subclasses after initialization. Dependencies include `Configuration`, `Configured`, `FileSystem`, `Path`, and reflection utilities. Integration is used by `Trash` and filesystem-specific policy extensions. Risks include the default modern `initialize()` and path-specific `getCurrentTrashDir(Path)` throwing `UnsupportedOperationException` unless subclasses override, reflection misconfiguration, and deprecated home-based assumptions. Tests should verify class selection, initialization path, custom policy loading, unsupported method behavior, and default policy compatibility.
