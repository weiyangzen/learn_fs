## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/TrashPolicyDefault.java

`TrashPolicyDefault` implements Hadoop's standard trash layout. Initialization reads deletion interval, checkpoint interval, and whether to clean unexpected trash-root entries; negative deletion intervals are clamped to disabled. `moveToTrash()` normalizes relative paths, verifies existence, rejects items already under trash or containing the trash root, computes `trashRoot/Current/<original path>`, creates parent directories with owner-only permissions, handles parent collisions by suffixing a timestamp, and renames with `Rename.TO_TRASH`, retrying around checkpoint races. Checkpoint APIs rename `Current` to timestamped directories, suffixing after collisions, and delete expired checkpoints by parsing current and old timestamp formats. `Emptier` sleeps to interval boundaries, scans all trash roots, deletes old checkpoints, creates new ones, and closes the filesystem on exit. State includes intervals, clean flag, static date formats synchronized during parse/format, and filesystem trash roots/checkpoint directories. Dependencies include common trash config keys, `Options.Rename`, `FsPermission`, `Time`, `FileStatus`, and `FileSystem` trash-root APIs. Integration includes shell rm/trash commands, NameNode emptier services, encryption-zone-aware trash roots, and ViewFS via `Trash`. Risks include rename atomicity depending on filesystem, timestamp collisions beyond 1000 attempts, cleanup of unexpected entries being destructive when enabled, clock skew affecting expiration, race windows between mkdir/existence/rename, static `DateFormat` requiring synchronization, and path string prefix checks for already-in-trash. Tests should cover disabled/negative intervals, move collision handling, already-in-trash and contains-trash rejection, checkpoint creation/deletion including old formats, immediate expunge, emptier interval adjustment, unexpected-entry cleanup flag, and multiple trash roots.
