# sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/FileSystem.java

Purpose: `FileSystem` is Hadoop's stable public abstract base class for URI-addressed filesystems. It defines the legacy `FileSystem` API used by HDFS, local filesystems, object stores, checksumming wrappers, filters, and third-party implementations. The class owns filesystem instance discovery/caching, default URI handling, path validation/qualification, common operation overloads, capability probing, global statistics registration, builder APIs, and default unsupported implementations for optional features.

Important APIs and types: the required subclass contract centers on `getUri`, `open(Path,int)`, `create(Path,FsPermission,boolean,int,short,long,Progressable)`, `append(Path,int,Progressable)`, `rename(Path,Path)`, `delete(Path,boolean)`, `listStatus(Path)`, `setWorkingDirectory`, `getWorkingDirectory`, `mkdirs(Path,FsPermission)`, and `getFileStatus(Path)`. Static construction APIs include `get(Configuration)`, `get(URI,Configuration)`, `newInstance(...)`, `getLocal`, `newInstanceLocal`, `closeAll`, and `closeAllForUGI`. Common convenience APIs layer defaults for create/open/append overloads, path handles, server defaults, block locations, listing/filtering/globbing, recursive file iteration, local copy helpers, delete-on-exit, content summaries, quota usage, permissions, checksums, symlinks, ACLs, xattrs, snapshots, storage policies, trash roots, multipart upload, and bulk delete.

Control flow: URI resolution first normalizes deprecated names (`local`, unqualified HDFS names), applies the configured default filesystem when scheme or authority is absent, optionally bypasses the cache with `fs.$scheme.impl.disable.cache`, and otherwise delegates to `Cache.get`. Cache misses are serialized by a semaphore sized by `fs.creation.parallel.count`; a filesystem class is found from `fs.$scheme.impl` or `ServiceLoader<FileSystem>`, instantiated by reflection, initialized, inserted into the cache, and optionally registered for automatic shutdown. Most overloads collapse into a small set of abstract core calls; for example create overloads resolve buffer size, replication, block size, umask, flags, and checksum options before calling the abstract create method, while list APIs build iterators from `listStatus` or `listStatusBatch`.

State and persistence behavior: process-global state includes `CACHE`, `statisticsTable`, service-loaded scheme bindings, the symlink-enabled flag, and the daemon statistics cleaner thread. Instance state includes its cache key, per-class/per-scheme `Statistics`, the `deleteOnExit` path set, and the `resolveSymlinks` configuration flag. No file metadata is persisted by this base class; persistence is delegated to implementations. `close()` processes delete-on-exit entries and removes the instance from the cache. The cache's shutdown hook closes automatically closable filesystems at JVM shutdown, and `MultipleIOException` aggregates close failures.

Dependencies and integration points: this class ties together Hadoop `Configuration`, `Path`, `FileStatus`, `FSDataInputStream`, `FSDataOutputStream`, `FsPermission`, `UserGroupInformation`, delegation tokens, `SecurityUtil`, `Credentials`, `GlobalStorageStatistics`, tracing, `ShutdownHookManager`, `FileUtil`, `Globber`, `FSLinkResolver`, builder implementations, and capability constants. It is the compatibility point for `FilterFileSystem`, `ChecksumFileSystem`, `LocalFileSystem`, `DistributedFileSystem`, `FileContext` transition methods, and external ecosystem shims. Implementers must keep new APIs consistent with wrappers and capability probes.

Statistics behavior: nested `Statistics` stores write-heavy counters in per-thread `StatisticsData` instances referenced through weak references. Reads aggregate `rootData` plus all live thread-local data under the statistics lock. A daemon cleaner folds counters from garbage-collected threads into `rootData`. `reset()` avoids mutating other threads' thread-local data by adding the negative aggregate to `rootData`. `getStatistics(scheme, class)` registers a `FileSystemStorageStatistics` provider in `GlobalStorageStatistics`, while `clearStatistics()` resets through the global statistics registry.

Optional feature defaults: many advanced features deliberately throw `UnsupportedOperationException` unless overridden, including path-handle open/create, concat, truncate, msync, symlink operations, snapshots, ACLs, xattrs, storage policies, quotas, corrupt-block listing, multipart upload, and non-recursive create. Other defaults are no-ops or coarse fallbacks, such as `setPermission`, `setOwner`, `setTimes`, checksum toggles, `setReplication` returning true, default status returning unbounded capacity, block locations returning localhost, and bulk delete returning `DefaultBulkDeleteOperation`.

Risks: `createNewFile` is explicitly non-atomic because it checks existence before creating. Default recursive `getContentSummary` and `listFiles` can be expensive and racy on large mutable trees. `exists`, `isFile`, and `isDirectory` add extra metadata calls and can create time-of-check/time-of-use hazards. `checkPath` depends on canonical URI/authority comparison and default URI authority inference, so custom filesystems must override carefully if their authority semantics differ. The cache must avoid leaking duplicate filesystem instances under concurrent creation; the semaphore and duplicate close path are central to that. Global service loading is one-time and logs but skips broken service entries, which can hide classpath issues until scheme lookup fails. Symlinks are globally disabled by default, so per-instance `resolveSymlinks` is not enough to enable traversal.

Test signals: important coverage should exercise default URI fallback, cache hit/miss behavior, cache bypass, duplicate concurrent creation cleanup, UGI-specific cache keys, automatic close and delete-on-exit, service-loader and `fs.$scheme.impl` resolution, path qualification and wrong-FS rejection, create/append builder flag routing, open-file mandatory option rejection, statistics aggregation/reset and thread cleanup, default unsupported optional APIs, list/glob iterator behavior, `hasPathCapability` for bulk delete and symlinks, and delegation token issuer propagation to child filesystems.
