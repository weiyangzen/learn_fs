## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/MultipartUploader.java

`MultipartUploader` is an unstable public async interface for multipart uploads across filesystems and nodes. It extends `Closeable` and `IOStatisticsSource`, with futures for `startUpload(Path)`, `putPart(...)`, `complete(...)`, `abort(...)`, and best-effort `abortUploadsUnderPath(Path)`. Implementations must close part input streams after reading and may upload parts out of order or in parallel. The interface has no state itself; persistent state lives in backend upload sessions and opaque `UploadHandle`, `PartHandle`, and final `PathHandle` values. Dependencies include `CompletableFuture`, `InputStream`, `Map`, and Hadoop path/handle/statistics types. Integration is with object stores and commit protocols that need durable multipart identifiers. Risks include unclear lifecycle ownership when futures fail, eventual-consistency gaps in abort-under-path, validation of part numbers and non-empty handle maps being left to implementations, and resource leaks if streams are not closed. Tests should cover parallel parts, out-of-order completion, abort idempotency, failed future cleanup, statistics exposure, and unsupported bulk abort returning `-1`.
