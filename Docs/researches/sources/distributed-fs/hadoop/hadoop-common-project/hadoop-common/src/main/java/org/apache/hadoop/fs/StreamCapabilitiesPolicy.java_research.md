## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/StreamCapabilitiesPolicy.java

`StreamCapabilitiesPolicy` provides static helper policy for stream capabilities. Its current API is `unbuffer(InputStream)`: if the stream implements `StreamCapabilities` and advertises `UNBUFFER`, it casts to `CanUnbuffer` and calls `unbuffer()`; otherwise it logs at debug. A bad capability claim that lacks `CanUnbuffer` becomes an `UnsupportedOperationException` with a fixed diagnostic. State is limited to a static logger and message constant. Dependencies include `InputStream`, `StreamCapabilities`, `CanUnbuffer`, and SLF4J. Integration is with code that wants opportunistic unbuffering without hard dependencies on every stream type. Risks include the cast-based policy depending on truthful capability advertising, debug-only visibility when unbuffer is unavailable, and no null check before `in.getClass()` paths. Tests should cover non-capable streams, capable-and-implemented streams, false capability streams, bad claims throwing, and null input behavior if callers might pass null.
