## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/Path.java

`Path` is Hadoop's stable serializable URI-like value type for filesystem names. It parses strings into scheme/authority/path, normalizes duplicate slashes and trailing separators, handles Windows drive letters, resolves children against parents, supports suffixing, depth, parent/name access, qualification with filesystem URI and working directory, comparison/equality by normalized `URI`, and deserialization validation. State is a single hierarchical `URI`. Control flow is concentrated in constructors, `initialize()`, `normalizePath()`, `mergePaths()`, and `makeQualified()`. Dependencies include `URI`, regex `Pattern`, Avro `@Stringable`, Commons `StringUtils`, `Configuration`, and `FileSystem`. Integration is pervasive: every filesystem API accepts or returns `Path`, and path-string behavior affects globbing, local path conversion, symlink targets, and path-handle authority checks. Risks include intentionally unescaped `toString()`, platform-dependent Windows normalization, `Path(URI)` trusting the URI more directly than string constructors, fragment preservation without query support, and nullable `getParent()` at root. Tests should cover scheme/authority parsing, relative paths with colons, Windows drive paths, parent-child resolution, qualification, root/empty/null rejection, serialization validation, equality/hash ordering, and path strings with duplicate slashes or trailing separators.
