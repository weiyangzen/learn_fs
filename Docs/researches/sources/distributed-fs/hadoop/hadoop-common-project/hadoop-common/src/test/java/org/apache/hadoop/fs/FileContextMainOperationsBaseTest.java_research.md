# sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/test/java/org/apache/hadoop/fs/FileContextMainOperationsBaseTest.java

## Purpose
`FileContextMainOperationsBaseTest` is the abstract contract suite for `FileContext` implementations. Subclasses initialize the static `fc` with a concrete default filesystem, then inherit broad behavioral checks for status, working directories, create/open/delete/list/glob/rename, stream lifecycle, checksum verification, corruption enumeration, statistics, and async `openFile()` behavior.

## Important APIs, Types, And Functions
The core fixture is `protected static FileContext fc`, with randomized test roots supplied by `FileContextTestHelper`. `createFileContextHelper()`, `getDefaultWorkingDirectory()`, `renameSupported()`, `unwrapException()`, and `listCorruptedBlocksSupported()` are extension points for concrete filesystems. Helper methods `createFile(Path)`, `rename(Path, Path, boolean, boolean, Rename...)`, `path(String)`, and `describe(String)` centralize common operations. It uses `FileContext`, `AbstractFileSystem`, `FSDataInputStream`, `FSDataOutputStream`, `FutureDataInputStreamBuilder`, `Options.CreateOpts`, `Options.Rename`, `CreateFlag`, `PathFilter`, and `RemoteIterator`.

## Control Flow
`setUp()` creates a randomized local root and the suite root under `test`; `tearDown()` deletes both the helper root and local root. Tests first exercise metadata and navigation, then mkdir/list/glob combinations, then data I/O at multiple block-aligned lengths. Create-flag tests validate exception contracts for null/empty flags, `CREATE`, `OVERWRITE`, `APPEND`, and builder-style creation. Rename tests cover nonexistent inputs, missing parents, parent-as-file, self-renames, existing files/directories, empty and non-empty destination directories, and option-dependent overwrite behavior. Later tests cover double-close semantics, unsupported symlink APIs, `open(path, bufferSize)`, checksum verification, corrupt block listing, delete-on-exit, statistics, `FileContext.getFileContext(AbstractFileSystem)`, and future-based `openFile()`.

## State And Persistence Behavior
The suite mutates only test filesystem state under randomized roots. File contents use deterministic byte data generated by `FileContextTestHelper`. Working-directory tests intentionally change process-level `FileContext` working directory state, so cleanup uses absolute helper roots. It also clears and prints global `FileContext` statistics in one test.

## Dependencies And Integration Points
This suite integrates with concrete `FileContext` tests for local, viewfs, HDFS, or other filesystems. It depends on `FileContextTestHelper`, `ContractTestUtils`, `GenericTestUtils`, `LambdaTestUtils`, JUnit 5, and Hadoop filesystem exception classes. Subclass overrides control unsupported rename and corrupt-block behavior.

## Risks
The static shared `fc` makes the base fragile under parallel execution or subclass leakage. Rename exception checks often accept broad `IOException`, so some incompatible implementations can pass if state assertions match. The suite assumes consistent path qualification, parent creation behavior, and deterministic listing counts. `testRenameDirectoryAsNonExistentDirectory()` manually calls `tearDown()` mid-test, which can surprise subclasses with additional teardown state.

## Test Signals
Passing this suite indicates broad `FileContext` contract compatibility: correct create/open/read/write/delete behavior, glob/list filtering, rename semantics, stream close idempotency, checksum toggles, future-based open semantics, and expected failure timing for missing paths and unknown mandatory builder options.
