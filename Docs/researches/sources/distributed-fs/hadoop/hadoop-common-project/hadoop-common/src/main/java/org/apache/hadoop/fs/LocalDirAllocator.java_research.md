## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/LocalDirAllocator.java

`LocalDirAllocator` chooses configured local directories for temporary and local-work files. It maintains one static `AllocatorPerContext` per configuration key, with each context holding an atomic snapshot of parsed directories, `DF` capacity probes, a local filesystem, and an atomic last-directory index. Public APIs allocate write paths with known or unknown size, find existing read paths, iterate all matching read paths, create JVM-delete-on-exit temp files, test existence, and remove deprecated contexts. Control flow refreshes the context whenever the raw config string changes, creates or filters unusable directories through `DiskValidator`, then selects paths by weighted random choice for unknown sizes or round-robin/random-increment scanning for known sizes. State is JVM-local and configuration-driven; no persistent metadata is written besides created directories/temp files. Dependencies include `Configuration`, `FileSystem.getLocal`, `DF`, `DiskValidatorFactory`, `DiskChecker.DiskErrorException`, `StringUtils`, and hostname reporting for errors. Integration points include MapReduce/HDFS local scratch allocation and callers expecting local path search under multiple roots. Risks include races with disk capacity changing after allocation, static context sharing across users/tests, `ifExists()` using stale context without `confChanged()`, path normalization by stripping leading slash, and roulette selection corner cases when availability totals change after validation failures. Test signals should include config reloads, unwritable/missing dirs, no-space errors, known-size versus unknown-size selection, path iteration, temp-file cleanup flags, and concurrent access to the atomic context.
