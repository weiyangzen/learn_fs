## sources/distributed-fs/hadoop/hadoop-common-project/hadoop-common/src/main/java/org/apache/hadoop/fs/LocalFileSystem.java

`LocalFileSystem` is the checksummed `file:///` filesystem wrapper built on `ChecksumFileSystem` with `RawLocalFileSystem` as the default raw implementation. It initializes the raw filesystem once, honors alternate schemes via `swapScheme`, and enables checksum verification from `LOCAL_FS_VERIFY_CHECKSUM`. Important APIs expose `getScheme()`, `getRaw()`, `pathToFile()`, local copy operations, checksum failure handling, and symlink delegation. The most involved control path is `reportChecksumFailure()`: it canonicalizes the bad data file, finds the highest writable parent on the same mount, creates `bad_files`, closes data/checksum streams, and renames both files with a random suffix. State is mostly delegated to the raw filesystem and checksum sidecar files; the random suffix is process-local. Dependencies include `ChecksumFileSystem`, `RawLocalFileSystem`, `DF`, `FileUtil`, and common configuration keys. Risks include best-effort rename failures being logged but ignored, mount-prefix assumptions when finding `bad_files`, and the static `Random` suffix not guaranteeing collision freedom. Tests should exercise checksum verification toggles, bad-file quarantine behavior, symlink delegation, raw path conversion, and copy semantics.
