## sources/distributed-fs/beegfs/client_module/source/common/nodes/Node.c

**Purpose:** Implements client-side node lifetime, alias/type management, interface updates, and display helpers. **Important APIs/functions:** `Node_init/construct`, `Node_uninit/__Node_destruct`, `Node_updateLastHeartbeatT`, `Node_updateInterfaces`, `Node_nodeTypeToStr`, `Node_copyAlias`, `Node_copyAliasWithTypeStr`, and `Node_setNodeAliasAndType`. **Control flow:** initialization sets mutexes/conditions, numeric ID, alias/type RW lock, active flag, heartbeat time, kref, then creates the `NodeConnPool`; heartbeat updates broadcast waiters; interface updates change UDP port under `Node.mutex` and delegate TCP/NIC changes to the connection pool. Alias/type updates duplicate the new alias, build a formatted `alias [type:id]` string with `kasprintf`, then swap owned pointers while holding the write lock. **State/persistence:** node state is volatile and owned by stores; alias strings and formatted display strings are dynamically allocated and freed in `Node_uninit`. **Dependencies/integration:** owns a `NodeConnPool`, participates in `NodeTree`, and is used by logging, `MessagingTk`, and node stores. **Risks/tests:** construction does not visibly handle allocation failure before `Node_init`; alias formatting can truncate through `NodeString`; tests should exercise concurrent alias readers/writers, client vs server formatting, heartbeat waiters, and interface updates invalidating pooled sockets.
