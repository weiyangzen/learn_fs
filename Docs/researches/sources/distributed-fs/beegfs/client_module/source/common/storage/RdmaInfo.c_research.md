## sources/distributed-fs/beegfs/client_module/source/common/storage/RdmaInfo.c

**Purpose:** Implements optional NVFS/GPU-memory RDMA mapping support for client IO. **Important APIs/functions:** `RdmaInfo_acquireNVFS`, `releaseNVFS`, `detectNVFSRequest`, internal page/scatterlist helpers, `RdmaInfo_mapRead`, `mapWrite`, `unmapRead`, and `unmapWrite`. **Control flow:** detection samples the first page from an `iov_iter`, asks NVFS whether it is GPU memory, records the GPU index in `DevicePriorityContext`, and releases the page. Mapping requires an RDMA socket with global rkey, allocates scatterlists sized from `iov_iter_npages`, converts the iterator to page-backed SG entries, calls `nvfs_dma_map_sg_attrs`, coalesces DMA-contiguous entries, rejects more than `RDMA_MAX_DMA_COUNT`, then returns tag/key/device/SG metadata for serialization. Unmap calls NVFS unmap, releases pages, and frees lists. **State/persistence:** `RdmaInfo` owns pinned pages and DMA mappings until unmap; serialized output describes remote DMA addresses/key for one request. **Dependencies/integration:** only built under `BEEGFS_NVFS`; integrates with `RDMASocket`, `Nvfs`, Linux iov/page/DMA APIs, and `NodeConnPool` GPU-aware RDMA NIC choice. **Risks/tests:** page pin/count balance, mixed CPU/GPU page handling, `NVFS_CPU_REQ`, SG coalescing, and map/unmap direction pairing are high risk; tests need kernel/NVFS integration coverage plus fallback when mapping returns NULL or ERR_PTR.
