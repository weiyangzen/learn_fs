## sources/distributed-fs/beegfs/client_module/source/common/nodes/TargetStateStore.c

**Purpose:** Implements target reachability/consistency state storage and atomic refresh with mirror buddy group mappings. **APIs/functions:** construct/destruct, `syncStatesAndGroupsFromLists`, `__syncStatesUnlocked`, state-to-string helpers, `getStatesAsLists`, `setAllStates`, and `getState`. **Control flow:** atomic sync takes the target state write lock, then buddy group write lock, rebuilds states from a list with `__GFP_NOFAIL`, calls buddy group unlocked sync, and unlocks in reverse. State export iterates rb-tree into parallel lists; `setAllStates` updates reachability and reports whether anything changed; missing `getState` returns false with OFFLINE/GOOD defaults. **State/persistence:** volatile management state, keyed by target ID, with consistency and reachability encoded in `CombinedTargetState`. **Dependencies/integration:** consumed by `MessagingTk` request routing to avoid bad/offline targets and by management state refresh messages. **Risks/tests:** lock ordering is critical with `MirrorBuddyGroupMapper`; tests should cover missing-state defaults, atomic group/state switch, list export parallel ordering, and state transition reporting.
