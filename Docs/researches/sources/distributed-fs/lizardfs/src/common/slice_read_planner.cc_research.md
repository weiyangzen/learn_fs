# sources/distributed-fs/lizardfs/src/common/slice_read_planner.cc

Purpose: implements scheduling logic for read operations over standard, XOR, and EC slice parts. Important functions: `prepare`, `buildPlanFor`, `addParts`, `addBasicParts`, `addExtraParts`, and `shouldReadPartsRequiredForRecovery`. Control flow: `prepare` builds a bitset of available parts for the requested slice type, determines whether requested parts are directly available or recoverable, gathers unique available parts, applies optional scores, and sorts descending by score. `buildPlanFor` maps requested parts to output buffer offsets; if recovery is needed it schedules enough parts for recovery in wave 0, otherwise prioritizes requested parts first, then schedules extra parts in later waves. State/persistence: mutates planner fields such as `weighted_parts_to_use_`, `required_parts_available_`, `can_recover_parts_`, and `part_indices_`; resulting `ReadPlan` owns operation state. Dependencies: `slice_traits`, `SliceReadPlan`, `XorReadPlan`, `ECReadPlan`, chunk geometry constants. Integration points: mount/client read pipeline. Risks: relies on asserts for duplicate requested parts, score ordering only considers unique part index, `floor(bandwidth_overuse_ * required)` can under-schedule if inputs are unexpected but is clamped in one branch, and no direct tests in this subset. Test signals: not directly covered here.
