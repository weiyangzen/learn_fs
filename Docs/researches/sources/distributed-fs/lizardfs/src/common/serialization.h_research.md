# sources/distributed-fs/lizardfs/src/common/serialization.h

Purpose: central binary serialization/deserialization framework for primitive types, strings, STL containers, LizardFS small/compact/flat containers, pairs, arrays, unique pointers, and user-defined serializable objects. Important APIs/types: `serializedSize`, pointer-based `serialize`/`deserialize`, vector-buffer `serialize(std::vector<uint8_t>&, ...)`, `deserialize(buffer, ...)`, `deserializeAndIgnore`, and `IncorrectDeserializationException`. Control flow: serialization computes total size, resizes an empty output vector, then writes fields sequentially through datapack `put*` helpers. Deserialization verifies size before primitive reads, rejects invalid booleans, enforces a 32 MiB top-level byte cap and 1M element cap, requires strings to be null-terminated, and expects output strings/containers/pointers to be empty before filling. State/persistence: defines stable packet/storage byte layout for many common types; container sizes are serialized as `uint32_t`. Dependencies: `datapack.h`, `massert`, `small_vector`, `compact_vector`, `flat_set`, `flat_map`, `Exception`. Integration points: packet macros, metadata records, RichACL serialization, tape structs, goals, and many protocol types. Risks: output buffer must be empty, deserialization into non-empty objects asserts or throws, aggregate `serializedSize` can overflow `uint32_t`, and maps/sets silently drop duplicate serialized keys through insert. Test signals: `serialization_unittest.cc` covers strings, vectors, nested maps/sets, custom allocators, unique pointers, arrays, sets, maps, and non-empty string rejection.
