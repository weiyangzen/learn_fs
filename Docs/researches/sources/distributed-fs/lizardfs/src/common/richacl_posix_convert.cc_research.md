# sources/distributed-fs/lizardfs/src/common/richacl_posix_convert.cc

Purpose: translates between POSIX ACLs and RichACLs, including default/inheritable POSIX ACLs. Important APIs/functions: `appendPosixACL`, `appendDefaultPosixACL`, `convertToPosixACL`, `convertToDefaultPosixACL`, and `hasGroupEntry`. Control flow: minimal POSIX ACLs become mask-only RichACLs with `kMasked|kWriteThrough`; extended ACLs create owner/group/named user/named group/everyone allow ACEs, isolate POSIX classes using deny entries, compute masks, and simulate POSIX mask entries through `group_mask_`. Reverse conversion derives mode bits from masks or `allowedToWho`, creates named user/group entries on first occurrence, and optionally emits POSIX mask. State/persistence: mutates the target ACL's masks, flags, and ACE list; no direct disk I/O. Dependencies: `AccessControlList`, `RichACL` helpers from `richacl.cc`, POSIX mode conversion constants. Integration points: metadata ACL storage, client chmod/setfacl behavior, default ACL inheritance. Risks: reverse conversion is approximate by design, duplicate ACEs after first named identity are ignored, and files strip `kDeleteChild` while directories keep it. Test signals: no direct unit test in this subset; should be covered by ACL conversion/integration tests elsewhere.
