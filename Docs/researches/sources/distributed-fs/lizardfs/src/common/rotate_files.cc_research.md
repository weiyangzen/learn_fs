# sources/distributed-fs/lizardfs/src/common/rotate_files.cc

Purpose: implements numbered backup rotation for a base file. Important APIs/functions: public `rotateFiles` and local `rotateFile`. Control flow: `rotateFiles` asserts `byNumber > 0`, then for `storedPreviousCopies > 0` walks from the highest retained copy down to 2, renaming `file.(n-byNumber)` to `file.n`, then renames the base file to `file.byNumber`; individual renames can be skipped if the source does not exist. State/persistence: mutates filesystem entries through `fs::rename`; failures are logged but not thrown. Dependencies: LizardFS filesystem wrapper `cwrap`, `FilesystemException`, `massert`, and `slogger`. Integration points: used by components that rotate changelogs, metadata backups, or logs. Risks: by-number gaps can produce surprising source names, failed renames leave partially rotated sets, and there is no atomic multi-file transaction. Test signals: no direct unit test in this subset.
