# Research: sources/distributed-fs/beegfs-protobuf/rust/beegfs.rs

## Purpose

`beegfs.rs` is generated by `prost-build` from the shared BeeGFS protobuf definitions. It provides Rust data types used across generated service modules. The file contains common entity identity structures and enums for entity kind, node type, reachability, consistency, capacity pool, NIC type, quota id type, and quota type.

## Important APIs, Types, and Functions

`LegacyId` stores a BeeGFS numeric id plus `NodeType`, with comments noting that the combination is not globally unique without entity type context. `EntityIdSet` stores optional globally unique uid, optional alias, and optional legacy id. Generated derives include `Clone`, equality/hash traits where applicable, and `prost::Message` or `prost::Enumeration`.

Enums include `EntityType`, `NodeType`, `ReachabilityState`, `ConsistencyState`, `CapacityPool`, `NicType`, `QuotaIdType`, and `QuotaType`. Each enum has generated `as_str_name()` and `from_str_name()` helpers that map to exact protobuf enum labels. These helpers are important for programmatic conversion, logging, config parsing, or bridging textual representations.

## Control Flow and State Behavior

There is no business control flow. Runtime behavior is limited to prost encoding/decoding and enum string conversion. State is entirely in message instances held by callers. The schema comments define contracts such as `0` being invalid for numeric ids and response messages generally fully populating identifiers, but the generated Rust structs do not enforce those constraints.

## Dependencies and Integration Points

The module depends on `prost` and `prost::alloc` generated conventions. Other generated modules import these shared types, especially `management.rs` and service contracts involving nodes, targets, pools, buddy groups, NICs, and quotas. The enum discriminants are wire-compatible values and should be treated as stable API.

## Risks and Edge Cases

Proto3 enum fields decode as raw `i32`; generated consumers must convert carefully and handle unknown or unspecified values. Optional `EntityIdSet` members allow partially populated identifiers, which is useful for requests but risky in code paths that assume a fully resolved entity. The comments document alias character rules and invalid numeric ids, but validation must live outside this file. Changing enum numeric values or field tags would be a breaking wire-compatibility change.

## Test Signals

Tests should cover encode/decode round trips, `as_str_name()` and `from_str_name()` mappings, unknown enum handling at service boundaries, and validation in higher-level code for invalid ids, unspecified enum variants, and incomplete `EntityIdSet` values.
