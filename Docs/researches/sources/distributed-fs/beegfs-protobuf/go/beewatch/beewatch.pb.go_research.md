# sources/distributed-fs/beegfs-protobuf/go/beewatch/beewatch.pb.go

## Purpose

This is generated Go protobuf code for `beewatch.proto` in the default, non-opaque build (`//go:build !protoopaque`). It defines the public hybrid API representation for BeeGFS Watch events and subscriber acknowledgements. The schema models a versioned event envelope that can carry legacy BeeGFS v7 event payloads or BeeGFS v8 event payloads, plus `Response` messages sent by subscribers to acknowledge completed sequence numbers or request graceful shutdown.

The file is generated by `protoc-gen-go v1.36.2` with `protoc v5.29.2`. It is a data contract and reflection implementation used by gRPC stubs, producers, consumers, serializers, and tests.

## Control Flow

Runtime flow is generated protobuf behavior:

1. `init` calls `file_beewatch_proto_init`.
2. The descriptor init function registers oneof wrappers for `Event.EventData`.
3. `protoimpl.TypeBuilder` constructs a descriptor with 2 enums, 4 messages, and 1 service.
4. Generated message methods use protobuf runtime helpers for reset, reflection, and string rendering.

Event selection is oneof-driven. `SetV1` sets `EventData` to `*Event_V1`, `SetV2` sets it to `*Event_V2`, and nil clears the oneof. `GetV1`, `GetV2`, `HasV1`, `HasV2`, `ClearV1`, `ClearV2`, and `WhichEventData` inspect or mutate the active branch. The `Event_builder` sets V1 first and then V2, so if both are supplied, V2 becomes the final active branch.

## State and Persistence Behavior

This file defines wire state, not local persistence. `SeqId` and `CompletedSeq` form the visible progress/acknowledgement contract for event delivery. `MetaId` and optional `MetaMirror` identify the metadata source. `EventFlags` is a bitmask corresponding to BeeGFS `EVENTFLAG` constants. `V1Event` carries sequence loss indicators (`DroppedSeq`, `MissedSeq`) while `V2Event` carries richer metadata such as link count, user ID, and timestamp.

In the non-opaque file, scalar and pointer fields are exported (`SeqId`, `MetaId`, `MetaMirror`, etc.), so existing code can use direct struct literals and field access. The generated setters/builders are still available and are the most portable path across opaque and non-opaque builds.

## Risks and Edge Cases

- `Event` has no explicit minor-version discriminator; consumers must use the oneof branch and tolerate additive fields.
- `MetaMirror` is optional. `GetMetaMirror` returns `0` for both unset and set-to-zero; callers must use `HasMetaMirror` if that distinction matters.
- Oneof branches are mutually exclusive, and builder behavior silently lets later branch assignment win when both V1 and V2 are populated.
- `V1Event_Type` lacks an `INVALID` zero value: zero means `FLUSH`. This is semantically different from `V2Event_Type`, where zero is `INVALID`.
- `EventFlags` is an untyped bitmask in Go; validation against BeeGFS `EVENTFLAG` definitions must happen outside generated code.
- The generated code does not validate sequence monotonicity, path shape, entry ID consistency, timestamps, or acknowledgement ordering.
- Direct field access works only for this non-opaque build; code compiled with `protoopaque` must use accessors.
