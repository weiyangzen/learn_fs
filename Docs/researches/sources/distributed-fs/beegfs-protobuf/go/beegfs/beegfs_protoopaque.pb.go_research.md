# Research: sources/distributed-fs/beegfs-protobuf/go/beegfs/beegfs_protoopaque.pb.go

**Purpose:** This file is the proto-opaque Go Protocol Buffers output for the same `beegfs.proto` schema as `beegfs.pb.go`, selected by the `protoopaque` build tag. It exposes the same public package, enums, message names, getters, setters, builders, and descriptor variables while hiding message fields behind generated storage names and explicit presence bookkeeping. Its role is API-compatible wire support for code compiled in the newer opaque Go protobuf mode.

**Important APIs/types/functions:** The enum surface is identical to the non-opaque file: `EntityType`, `NodeType`, `ReachabilityState`, `ConsistencyState`, `CapacityPool`, `NicType`, `QuotaIdType`, `QuotaType`, and their generated reflection methods. `LegacyId` provides `GetNumId`, `GetNodeType`, `SetNumId`, `SetNodeType`, and a builder. `EntityIdSet` provides `GetUid`, `GetAlias`, `GetLegacyId`, `SetUid`, `SetAlias`, `SetLegacyId`, `HasUid`, `HasAlias`, `HasLegacyId`, `ClearUid`, `ClearAlias`, `ClearLegacyId`, and a builder. `File_beegfs_proto` and `file_beegfs_proto_init` provide the same runtime descriptor build path as the normal variant.

**Control flow:** Initialization mirrors the normal generated file: `init()` calls an idempotent `file_beegfs_proto_init`, sets oneof wrapper metadata for `EntityIdSet`, and uses `protoimpl.TypeBuilder` to construct the file descriptor from raw descriptor bytes, enum info, message info, Go type metadata, and dependency indexes. The notable runtime flow is in accessor methods. `LegacyId` getters and setters read and write `xxx_hidden_NumId` and `xxx_hidden_NodeType`. `EntityIdSet.SetUid` stores the scalar in `xxx_hidden_Uid` and marks presence with `protoimpl.X.SetPresent`; `SetAlias` stores a string pointer and marks presence; `ClearUid` and `ClearAlias` clear the presence bit and reset storage. Builder code uses `SetPresentNonAtomic` for optional scalar/string fields when builder pointers are non-nil.

**State and persistence behavior:** The protobuf wire contract is the same as the non-opaque build: two messages, eight enums, and the same field numbers and enum numeric values. The in-memory representation differs. `LegacyId` stores fields in hidden members tagged with `protogen:"opaque.v1"`. `EntityIdSet` stores `uid` as a hidden int64 plus an `XXX_presence` bitfield, `alias` as a hidden string pointer plus presence, `legacy_id` as a hidden pointer, and includes `XXX_raceDetectHookData`. This means presence for an explicit `uid = 0` is not inferred from the value; it is carried by the presence bit. Unknown fields and size cache remain part of message state. Descriptor metadata is built once and raw initialization slices are nulled afterward.

**Dependencies and integration points:** The file depends on the same protobuf runtime packages as the normal variant: `protoreflect`, `protoimpl`, and `reflect`. It integrates with callers through generated methods and reflection rather than exported fields. It is mutually exclusive with `beegfs.pb.go` through build constraints, so consumers that only use generated accessors can build in both modes. It provides the same `github.com/thinkparq/protobuf/go/beegfs` Go package path and wire descriptor consumed by other generated packages, cross-language clients, and management/entity identity code.

**Risks:** Opaque generation deliberately hides fields, so code that compiles against direct fields in the normal file, such as `m.Uid` or `m.NumId`, will not compile under `protoopaque`; consumers should consistently use accessors/builders if both modes matter. `SetLegacyId(nil)` simply assigns nil and does not maintain a separate presence bit, while `SetUid` and `SetAlias` do maintain explicit presence; callers must use the matching `Has*` method for semantics. Semantic constraints from comments remain unenforced by generated code. The `SetPresent` helpers mutate internal presence state and are not a concurrency primitive; protobuf messages should not be mutated concurrently without external synchronization. Manual edits are at high risk of being overwritten and of diverging from the non-opaque generated sibling.

**Test signals:** Build the package with `-tags protoopaque` and without that tag to catch code paths that depend on one representation. Round-trip tests should assert wire equivalence between opaque and non-opaque builds for `LegacyId`, `EntityIdSet` with only uid, only alias, only legacy id, all fields, and explicit zero/empty optional values. Presence tests should cover `SetUid(0)`, `ClearUid`, `SetAlias("")`, `ClearAlias`, and builder-created optional fields. Descriptor tests can compare enum/message counts and field numbers against `File_beegfs_proto`. Regeneration/drift testing should confirm this file is produced from `beegfs.proto` by the pinned Go protobuf generator.
