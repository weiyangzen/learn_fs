# sources/distributed-fs/orangefs/src/io/bmi/bmi_wintcp/socket-collection.c

Purpose: implements the default WinSock `WSAPoll` socket collection backend used by `bmi-wintcp.c`. It keeps a dynamic array of sockets and corresponding BMI method addresses, accepts queued add/remove requests under a mutex, polls for readiness, and returns backend-neutral readiness bits to the TCP BMI progress engine.

Important APIs/functions: `BMI_socket_collection_init` allocates the collection, initializes `queue_mutex`, allocates `pollfd_array` and `addr_array`, initializes add/remove queues, stores the server socket, and inserts the server socket as `addr_array == NULL` when present. `BMI_socket_collection_queue` removes a method address from either pending queue if already queued and adds its `tcp_addr.sc_link` to the requested queue. `BMI_socket_collection_finalize` frees arrays and the collection. `BMI_socket_collection_testglobal` drains queued removals, applies queued additions/modifications, grows arrays by `POLLFD_ARRAY_INC` when full, calls `WSAPoll`, maps `POLLERR|POLLHUP|POLLNVAL`, `POLLIN`, and `POLLOUT` into status bits, supplements missing `WSAPoll` socket errors with `getsockopt(SO_ERROR)`, and creates a temporary server-port method address for listen readiness.

Control flow: callers never modify the poll arrays directly. `socket-collection.h` macros enqueue add/remove/write-interest changes; `testglobal` applies those changes at the start of the poll pass. Removal swaps the last active array entry into the removed entry's slot and updates the shifted address's `sc_index`. Addition either updates an existing entry's `events` field or appends a new entry. Read interest is implicit for all registered sockets, while `POLLOUT` is included only when `write_ref_count > 0`. After polling, the function skips addresses still pending in `remove_queue`, then emits up to `incount` ready maps/status values.

State and persistence behavior: state is memory-only. The collection owns the `WSAPOLLFD` array, the parallel method-address array, queue heads, mutex, and listen-socket marker. Each `struct tcp_addr` stores its current `sc_index`, queue link, and `write_ref_count`. The collection explicitly does not own method addresses or sockets, so finalization does not close sockets or free addresses.

Dependencies and integration: depends on WinSock2/`WSAPoll`, `quicklist`, generic locks, BMI method support, `bmi-tcp-addressing.h`, `gossip`, and PVFS debug/error conversion helpers. The backend is used by `bmi-wintcp.c` unless `__PVFS2_USE_EPOLL__` selects the epoll backend. `alloc_tcp_method_addr` is called for listen events, and the resulting temporary map is consumed by `handle_new_connection`.

Risks: `BMI_socket_collection_init` does not check `pollfd_array` allocation before using/freeing it through later paths. Queue coalescing uses a single `sc_link` per address; callers must not enqueue the same address into unrelated lists elsewhere. Removal assumes that after swapping the last entry, `addr_array[tcp_addr_data->sc_index]` is non-NULL; if the last entry is the server socket, dereferencing it would fail, though normal removals should target peer addresses. Array growth uses `assert` instead of a recoverable `ENOMEM` path. Pipe wakeup support is commented out, so queue changes do not actively interrupt a blocking `WSAPoll`; the implementation relies on timeouts and the BMI progress model. The graceful `POLLHUP` expression uses `!(revents & POLLERR+POLLNVAL)`, where operator precedence makes the intent less clear than an explicit mask. `getsockopt(SO_ERROR)` is polled for every socket with no revents, which can add overhead at high socket counts.

Test signals: cover queue coalescing for add/remove races, write-reference updates, array growth and `sc_index` repair after removals, server socket readiness, empty collection polling, timeout behavior after queued changes, error/hangup translation including graceful close with readable data, `SO_ERROR` fallback, and cancellation paths that remove write interest while sends are queued.
