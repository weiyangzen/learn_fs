# sources/distributed-fs/orangefs/src/io/bmi/bmi_wintcp/sockio.c

Purpose: provides a small WinSock socket I/O utility layer for the TCP BMI method. It creates, binds, connects, resolves, configures, and performs nonblocking scalar/vector send and receive operations while translating selected Windows socket errors into BMI/PVFS-style errors for higher layers.

Important APIs/functions: `BMI_sockio_new_sock` creates an IPv4 TCP socket. `BMI_sockio_bind_sock` binds to `INADDR_ANY:service`; `BMI_sockio_bind_sock_specific` resolves a supplied host and binds to that address; `BMI_sockio_connect_sock` resolves and connects to a remote host/port. `BMI_sockio_init_sock` has either a `gethostbyname` implementation with `conv_h_errno` or an `inet_aton` fallback. `BMI_sockio_nbrecv`, `BMI_sockio_nbpeek`, `BMI_sockio_nbsend`, and `BMI_sockio_nbvector` implement nonblocking receive, peek, send, and WinSock vector I/O. `BMI_sockio_get_sockopt`, `BMI_sockio_set_tcpopt`, and `BMI_sockio_set_sockopt` wrap socket option access. An optional `BMI_sockio_nbsendfile` block remains under `__USE_SENDFILE__` but is effectively non-Windows legacy code.

Control flow: scalar nonblocking receive and send loop until the requested byte count completes, an interrupt restarts the call, an error occurs, or `WSAEWOULDBLOCK` returns partial progress. `BMI_sockio_nbpeek` probes with `MSG_PEEK` and returns zero when a nonblocking read would block. `BMI_sockio_nbvector` intentionally issues one `WSARecv` or `WSASend` attempt rather than looping to exhaustion, returns zero on would-block, and returns the transferred byte count on success. Bind/connect wrappers retry on `WSAEINTR`; address initialization defaults `NULL` hostnames to localhost.

State and persistence behavior: no persistent state is stored. The functions operate only on caller-owned sockets and buffers. They sometimes set global `errno` for POSIX-like semantics (`EPIPE` on zero-byte receive), but most Windows errors are left for callers via `WSAGetLastError` or converted directly in bind/connect-specific paths.

Dependencies and integration: includes WinSock2, optional netdb/inet headers, BMI types, `sockio.h`, and `gossip`. `bmi-wintcp.c` uses this layer for server socket creation, binds, connects, nonblocking header/payload movement, `TCP_NODELAY`, `SO_REUSEADDR`, and buffer tuning. Error conversions depend on `bmi_errno_to_pvfs` and BMI error constants.

Risks: error-domain handling is inconsistent: bind-specific/connect convert through `bmi_errno_to_pvfs`, while scalar I/O often returns `-1` and expects the caller to consult `WSAGetLastError`. `BMI_sockio_nbrecv` treats `recv == 0` as `EPIPE` but does not set a WinSock error, so callers that convert `WSAGetLastError` may report a stale code. `BMI_sockio_nbvector` uses `MSG_PARTIAL` as the receive flags input and loops while flags retain `MSG_PARTIAL`; that is WinSock-specific and may not mean the same thing as POSIX partial progress. `typedef unsigned int socklen_t` and casts to `(int *)` for option lengths are portability compromises. The `__USE_SENDFILE__` branch references POSIX `sendfile`/`errno` and should not be enabled in this Windows file without porting. Legacy `gethostbyname` limits IPv6 support and thread-safety.

Test signals: unit tests or socket-pair integration tests should cover bind to any/specific host, failed resolution mapping, nonblocking connect would-block behavior, scalar send/recv partial progress, peek before full BMI headers, zero-byte remote close, vector send/recv with multiple buffers, would-block returns as zero, socket option get/set, localhost default resolution, and stale-error handling after zero-byte receives.
