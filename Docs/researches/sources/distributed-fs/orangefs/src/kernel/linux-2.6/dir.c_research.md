# sources/distributed-fs/orangefs/src/kernel/linux-2.6/dir.c

Purpose: Implements OrangeFS/PVFS2 directory file operations for Linux VFS, including `readdir`, optional `readdirplus`, directory open/release, synthetic `.` and `..` entries, and decoding of userspace client-core directory trailers returned through shared memory.

Important APIs and functions: `pvfs2_readdir` is the main VFS directory iterator, mapped as `.readdir` or `.iterate` depending on kernel feature macros. `decode_dirents`, `readdir_handle_ctor`, and `readdir_handle_dtor` unpack and own `pvfs2_readdir_response_t` trailer data. Under `HAVE_READDIRPLUS_FILE_OPERATIONS`, `pvfs2_readdirplus_common`, `pvfs2_readdirplus`, `pvfs2_readdirplus_lite`, `decode_sys_attr`, and `decode_readdirplus_from_buffer` add attribute-bearing directory reads. `pvfs2_dir_open` allocates a per-open `PVFS_ds_position` token in `file->private_data`; `pvfs2_dir_release` flushes inode metadata and frees it. `pvfs2_dir_operations` exports the VFS operation table.

Control flow: `pvfs2_readdir` reads the current VFS position, exits on `PVFS_READDIR_END`, creates a `PVFS2_VFS_OP_READDIR` operation, populates the parent object reference from `PVFS2_I(inode)->refn` or from inode-derived fallback handle data, obtains a readdir shared-memory index, and calls `service_operation`. If the operation is purged after client restart, it retries with a new buffer index. Successful downcalls are decoded from `downcall.trailer_buf`, `.` and `..` are emitted for positions 0 and 1, and server-provided entries are emitted with inode numbers derived from PVFS handles. Once a batch is fully consumed, the independent PVFS token in `file->private_data` is advanced and `file->f_pos`/`ctx->pos` is set to `PVFS_ITERATE_NEXT`; when the server token reaches `PVFS_READDIR_END`, atime is marked dirty. `readdirplus` follows the same client-core upcall pattern but also decodes per-entry status and attributes, fills or initializes inodes in the VFS inode cache, and passes `kstat`/`kstat_lite` records to the callback.

State and persistence: Persistent filesystem state lives in OrangeFS servers and client-core; this file manages transient kernel state. Per-open directory traversal state is the `PVFS_ds_position` stored in `file->private_data`. Shared-memory buffer ownership is guarded by `readdir_index_get`/`readdir_index_put`, with trailer buffers freed via `vfree`. Decoded arrays are `kmalloc`-owned and freed by handle destructors. Successful reads update in-memory inode atime and mark the inode dirty so OrangeFS time-flush logic can later persist it.

Dependencies and integration points: Depends on `pvfs2-kernel.h`, `pvfs2-bufmap.h`, `pvfs2-sysint.h`, and `pvfs2-internal.h`; uses kernel VFS `file_operations`, `filldir`/`dir_emit`, optional `filldirplus`, inode cache APIs, and OrangeFS helpers such as `op_alloc`, `service_operation`, `op_state_purged`, `PVFS2_I`, `PVFS2_SB`, `PVFS_khandle_from`, `pvfs2_khandle_to_ino`, `copy_attributes_to_inode`, `pvfs2_iget_locked`, `SetAtimeFlag`, and gossip logging. It shares downcall trailer layouts with `downcall.h` and the userspace client protocol.

Risks: Trailer decoding trusts client-provided counts and serialized string layout; malformed trailers can drive large allocations or decode-length mismatches. `kmalloc(HANDLESTRINGSIZE)` debug buffers are not checked before `memset` in the main path. Directory position logic is subtle because VFS positions, `PVFS_ITERATE_NEXT`, and PVFS distributed-directory tokens are intentionally decoupled; partial user buffers and callback failures are high-risk cases. Several `readdirplus` paths appear fragile or stale: the `PVFS_khandle_from(&refn.khandle)` references use an undeclared-looking `refn`, `pvfs2_khandle_to_ino(khandle)` passes a value where the header declares a pointer, `graceful_termination_path` is referenced but not visible in this file, and the `while` statement near the end of `pvfs2_readdirplus_common` appears syntactically incomplete. Because these paths are feature-macro gated, build coverage must include the relevant `readdirplus` variants before relying on them. Readdirplus also admits it is untested for distributed directories and rejects reentry after `pos > 2`.

Test signals: Compile with and without `HAVE_READDIR_FILE_OPERATIONS`, `HAVE_READDIRPLUS_FILE_OPERATIONS`, and `HAVE_READDIRPLUSLITE_FILE_OPERATIONS`. Exercise empty directories, single-batch and multi-batch distributed directories, partial `getdents` buffers, callback-stop paths, client-core restart/purged-op retry, trailer-size mismatch, malformed or huge dirent counts, atime dirtying, `.`/`..` inode values, and readdir after `PVFS_READDIR_END`. For readdirplus, test stat-error entries, symlink link-target attributes, inode-cache population for new and existing inodes, lite masks, and all feature-macro builds.
