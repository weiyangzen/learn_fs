# sources/distributed-fs/orangefs/src/kernel/linux-2.6/file.c

Purpose: Implements OrangeFS/PVFS2 regular-file VFS operations: open, read/write/readv/writev, non-contiguous readx/writex, optional AIO, ioctl flags, mmap, release, fsync, llseek, optional sendfile, and the direct shared-memory I/O path to userspace client-core.

Important APIs and functions: `pvfs2_file_operations` exports the VFS operation table. `pvfs2_file_open`, `pvfs2_file_read`, `pvfs2_file_write`, `pvfs2_file_readv`, `pvfs2_file_writev`, `pvfs2_file_readx`, `pvfs2_file_writex`, `pvfs2_ioctl`, `pvfs2_file_mmap`, `pvfs2_file_release`, `pvfs2_fsync`, `pvfs2_file_llseek`, and `pvfs2_lock` are the externally visible file behaviors. Internal orchestration centers on `struct rw_options`, `do_readv_writev`, `wait_for_direct_io`, `split_iovecs`, `bound_max_iovecs`, `precopy_buffers`, and `postcopy_buffers`. Non-contiguous I/O uses `construct_file_offset_trailer`, `split_xtvecs`, `bound_max_xtvecs`, `wait_for_iox`, and `do_readx_writex`. Optional AIO uses `do_aio_read_write`, `pvfs2_aio_retry`, `pvfs2_aio_cancel`, `pvfs2_aio_dtor`, and `fill_default_kiocb`.

Control flow: Open installs OrangeFS address-space operations and, for `O_APPEND`, refreshes file size before positioning at EOF. Normal read/write wrappers populate `rw_options` and call `do_readv_writev`. That routine validates inode/PVFS state, computes total count and required splits against `pvfs_bufmap_size_query`, runs kernel write checks, splits large iovecs, and loops in chunks. Each chunk goes through `wait_for_direct_io`: allocate a `PVFS2_VFS_OP_FILE_IO`, obtain a bufmap index, stage write data into shared memory, call `service_operation`, retry with a fresh buffer after purged `-EAGAIN`, copy read data back out, return `amt_complete`, and wake the daemon with `wake_up_daemon_for_return`. The readx/writex path mirrors this but also serializes file extents into an upcall trailer and uses `PVFS2_VFS_OP_FILE_IOX`. AIO submits at most one bufmap-sized request asynchronously, stores `pvfs2_kiocb` state in both `iocb->private` and `op->priv`, and completes later through retry/cancel/destructor paths. Fsync waits on pagecache writeback, sends `PVFS2_VFS_OP_FSYNC`, then flushes inode metadata.

State and persistence: File contents persist on OrangeFS servers through client-core operations; this file manages kernel-visible staging and metadata hints. Bufmap indices represent shared-memory slots and must be put exactly once. `pvfs2_kernel_op_t` lifetimes are split between kernel callers and the device daemon; after `wake_up_daemon_for_return`, the synchronous path deliberately stops touching the op. Reads and writes increment `g_pvfs2_stats`; successful reads/writes set atime/mtime flags, update inode timestamps, and mark inodes dirty for later metadata flush. `FS_IOC_GETFLAGS`/`FS_IOC_SETFLAGS` persist Linux file flags through the `user.pvfs2.meta_hint` xattr. Release flushes inode state and drops page/readahead cache pages.

Dependencies and integration points: Depends on Linux VFS file, address-space, pagecache, mmap, ioctl, AIO, sendfile, and locking APIs, with extensive compatibility macros for kernel-version differences. OrangeFS integration points include `pvfs2-bufmap` copy helpers, `op_alloc`/`op_alloc_trailer`, `service_operation`, operation state helpers, `pvfs2_inode_getattr`, `pvfs2_inode_read`, xattr default handlers, `pvfs2_flush_inode`, `pvfs2_truncate_inode`, `pvfs2_cancel_op_in_progress`, gossip logging, and handle conversion utilities.

Risks: This file has complex ownership rules across bufmap slots, operation refs, trailers, and AIO callbacks; cancellation and client-core restart paths are the most race-prone. Several parameter checks compare unsigned segment counts against zero, which does not reject bad counts. Debug buffers allocated with `kmalloc(HANDLESTRINGSIZE)` are generally not checked before `memset`. The cached-read/pagecache path is present but effectively disabled for ordinary reads with comments saying it breaks unless user buffers are page-size multiples. AIO rejects transfers larger than one bufmap block and does not implement the splitting used by synchronous I/O. `do_aio_read_write` has a suspicious overflow test form around `unlikely(((ssize_t)count)) < 0`. Sendfile bypasses the pagecache manually and must be checked carefully for page allocation/free balance. `pvfs2_lock` returns `-ENOSYS`, so POSIX locking is not implemented.

Test signals: Cover open with and without `O_APPEND`, EOF and short I/O, iovec splitting at bufmap boundaries, read/write larger than bufmap size, client-core restart with purged `-EAGAIN`, interrupted operations, bufmap get/copy failures, metadata time dirtying, fsync behavior, llseek `SEEK_END` getattr refresh, mmap readpage integration, release cache truncation, ioctl flag round trips through xattrs, readx/writex with mismatched memory/file lengths, AIO sync versus async paths, AIO cancellation before and during daemon service, sendfile if enabled, and kernel-feature builds for old vector/AIO/ioctl signatures.
