# sources/distributed-fs/openafs/src/viced/host.h

Purpose: declares the fileserver host/client data model, lock macros, host table sizing, callback-facing APIs, protection-server wrappers, enumeration helpers, state-serialization entry points, address helpers, and host/client flag bits used by `host.c`, `callback.c`, and fileserver RPC handlers.

Important APIs/types/macros: `H_LOCK`/`H_UNLOCK` wrap the global `host_glock_mutex`; `h_Lock`, `h_Lock_r`, `h_NBLock_r`, and `h_Unlock` wrap per-host locking. `struct Identity`, `AddrPort`, and `Interface` describe cache-manager identity and addresses. `struct host_to_zero` contains all host fields cleared on allocation, including callback connection, refs, address, flags, CPS, clients, interface list, callback list head, and TMAY cache; `struct host` adds stable index, host lock, and condition variable. `struct client_to_zero`/`struct client` model per-Rx-client authentication and CPS state. Callback add macros map to `AddCallBack1`.

Control flow support: the header documents the lock order and the rule that `H_LOCK` must be dropped before network I/O, `rx_NewCall`, or blocking locks. Refcount macros `h_Hold_r`, `h_Decrement_r`, and `h_Release_r` enforce host lifetime and call `h_TossStuff_r` when a deleted host/client has no references. List macros `h_InsertList_r` and `h_DeleteList_r` maintain `hostList` and `hostCount`. `h_htoi` and `h_itoh` translate between host pointers and stable host indices for callback records and DAFS state.

State and persistence behavior: only the `z` substructures are zeroed/reused for pooled host/client entries; fields outside them, such as locks, condition variables, and host index, survive allocation block setup. Under `AFS_DEMAND_ATTACH_FS`, `h_SaveState`/`h_RestoreState` are declared as package-level state serialization hooks. Host index tables are global so callback restore can translate stored host IDs back to host pointers.

Dependencies and integration: includes `fs_stats.h`, Rx globals, and pthreads. Prototypes expose callback functions implemented in `callback.c`, host functions implemented in `host.c`, and PR wrapper functions used by authentication/CPS code. Fileserver RPC handlers use `GetClient`/`PutClient`, callback add/delete/break routines, host stats accessors, and dump/check functions through this header.

Risks: macros mutate global structures without local locking checks, so callers must already hold the right lock. `h_itoh` performs unchecked pointer arithmetic into `hosttableptrs`, so invalid host indices can crash or corrupt state. `h_Release_r` may synchronously call `h_TossStuff_r`, so callers must understand side effects when decrementing the last reference. Flag bits such as `ALTADDR`, `VENUSDOWN`, `HOSTDELETED`, `HWHO_INPROGRESS`, and `HCBREAK` are shared across host and callback packages; inconsistent semantics between files can produce lost callbacks, VBUSY storms, or stale host mappings.

Test signals: compile and integration tests should cover lock-order-sensitive APIs, host index round trips, reference release/deletion behavior, callback macro expansion paths, flag transitions during host initialization and callback break, and DAFS save/restore declarations in demand-attach builds. Static review should verify all `_r` functions are called with `H_LOCK` as intended.
