# sources/distributed-fs/openafs/src/viced/callback.c

Purpose: implements the OpenAFS fileserver callback manager. It tracks which cache-manager hosts have promises for which file identifiers, breaks those promises when files or volumes change, reclaims callback memory under pressure, times out stale entries, supports alternate client addresses, and, when demand-attach fileserver support is compiled in, saves/restores callback state across restart.

Important APIs/functions: `InitCallBack` allocates indexed `FileEntry` and `CallBack` pools and a dynamically sized file-entry hash table. `AddCallBack1`/`AddCallBack1_r` install normal, volume, bulk, or delayed callbacks and return the client-visible expiration time. `BreakCallBack`, `DeleteCallBack`, `DeleteFileCallBacks`, `DeleteAllCallBacks_r`, `BreakDelayedCallBacks_r`, `BreakVolumeCallBacksLater`, `BreakLaterCallBacks`, and `CleanupTimedOutCallBacks_r` are the main mutation paths. `MultiBreakCallBack_r`, `XCallBackBulk_r`, `MultiBreakCallBackAlternateAddress_r`, and `MultiProbeAlternateAddress_r` perform callback RPCs, including multi-Rx fanout and alternate-interface recovery. `DumpCallBackState` and the `INTERPRET_DUMP` build mode provide binary dump/debug tooling. Under `AFS_DEMAND_ATTACH_FS`, `cb_stateSave`, `cb_stateRestore`, `cb_stateRestoreIndices`, `cb_stateVerify`, `fe_OldToNew`, and `cb_OldToNew` serialize and validate callback records.

Core types/state: live callback state is stored in two one-based arrays, `FE` and `CB`, with `FE[0]`/`CB[0]` intentionally unused so zero can mean null. `struct FileEntry` represents a `(Volume,Vnode,Unique)` object and links into `HashTable` by `fnext`; it owns a per-file singly linked callback list through `firstcb`/`cnext`. `struct CallBack` links simultaneously into the file list, a per-host circular list (`hhead`, `hprev`, `hnext`), and a timeout circular list (`thead`, `tprev`, `tnext`). `timeout[CB_NUM_TIMEOUT_QUEUES]` is a 128-bucket wheel in 128-second units; `tfirst` records the oldest unexpired bucket. `cbstuff` records operational counters, allocation counts, space-reclaim statistics, and active callback breakers.

Control flow: initialization pre-fills free lists and chooses `FEhashsize` so expected chains stay near `FE_CHAIN_TARGET`. Adding a callback first preallocates a callback and file-entry slot, computes a timeout from callback type and existing sharer count, creates a file entry if needed, and either refreshes an existing host callback or links a new callback into the file, host, and timeout lists. Breaking a file callback marks matching callbacks with `CBFLAG_BREAKING`, batches up to `MAX_CB_HOSTS`, removes normal callbacks from local state before RPC, and calls cache managers via `multi_Rx`; failures try alternate addresses, then mark hosts `VENUSDOWN` and re-add delayed callbacks. Volume breaks are staged by marking matching FEs `FE_LATER` and host flags `HFE_LATER`; the fsync thread later unchains one volume's entries and performs batched host notifications.

State and persistence behavior: callback state is memory-resident during normal operation and is reclaimed by timeouts or host purges. When demand-attach serialization is enabled, the file writes callback headers, timeout queues, a placeholder FE-hash header, and each FE plus its CB records. Restore allocates old-to-new index maps, reconstructs FEs/CBs from disk, rebuilds the FE hash table dynamically instead of trusting the on-disk table, then translates all stored FE, CB, host, timeout, and list indices. Verification walks FE hash chains, per-FE CB lists, per-host CB lists, and timeout queues to detect loops, out-of-range indices, broken back-links, and count mismatches. Non-DAFS builds still support an opaque callback dump at `AFSDIR_SERVER_CBKDUMP_FILEPATH`.

Dependencies and integration: depends on `host.h`/`host.c` for host structures, host index mapping, per-host callback lists, alternate-interface mutation, and host enumeration. Uses Rx and generated cache-manager RPCs from `afscbint` (`RXAFSCB_CallBack`, `InitCallBackState`, `ProbeUuid`, etc.). Uses fileserver logging/panic paths (`ViceLog`, `ViceLogThenPanic`, `ShutDownAndCore`), fsync synchronization for deferred volume breaks, and DAFS state helpers from `serialize_state.h`.

Risks: correctness depends on maintaining three intrusive list families in sync under `H_LOCK`; a missed `TDel`, `HDel`, or `CDel` corrupts timeout cleanup, host cleanup, or per-file lookup. Many paths intentionally drop `H_LOCK` around network RPCs and then reacquire/re-find state, so races around deleted hosts, reused entries, and delayed callbacks are the dominant risk. `AddCallBack1_r` has complicated preallocation and host-lock comments; its existing-condition path is subtle because unused preallocated entries must be returned exactly once. `MultiBreakCallBack_r` sorts hosts by index to avoid multi-Rx channel deadlock, so changes to batching/order need lock-order review. Alternate-address recovery mutates callback connections and host address tables after RPC success; stale or malicious client interface data can cause wrong-host risk if UUID checks regress. Serialization compatibility is also sensitive: newer dumps intentionally write an empty FE-hash section, which older tools may not understand.

Test signals: meaningful tests include callback add/delete/break lifecycle, timeout wheel expiry, callback-space exhaustion and `GetSomeSpace_r` host selection, multi-host break failure with delayed callback reinsertion, volume deferred-break processing, alternate address failover with UUID mismatch/removal, DAFS save/restore/index translation/verification, and dump interpreter compatibility for MAGIC/MAGICV2/MAGICV3. Runtime signals include `PrintCallBackStats`, callback/host dumps, `ViceLog` messages for `BCB`, `GSS`, `CCB`, and DAFS verification warnings.
