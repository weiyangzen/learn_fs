# sources/distributed-fs/openafs/src/viced/host.c

Purpose: implements the OpenAFS fileserver host/client registry. It maps Rx connections to cache-manager hosts and authenticated clients, manages callback connections and host identity, resolves address/UUID changes, caches CPS membership, supports host/client enumeration and diagnostics, performs periodic liveness cleanup, and serializes host state for demand-attach restart.

Important APIs/functions: allocation helpers `GetHT`, `FreeHT`, `GetCE`, and `FreeCE` manage pooled host/client entries. Protection-server wrappers `hpr_Initialize`, `hpr_GetHostCPS`, `hpr_GetCPS`, `hpr_NameToId`, and `hpr_IdToName` provide per-thread ubik PR clients. Host lookup and lifecycle APIs include `h_Lookup_r`, `h_LookupUuid_r`, `h_GetHost_r`, `h_Alloc_r`, `h_TossStuff_r`, `h_Enumerate`, `h_Enumerate_r`, `h_CheckHosts`, and hash-table add/delete functions. Address/identity helpers include `initInterfaceAddr_r`, `addInterfaceAddr_r`, `removeInterfaceAddr_r`, `removeAddress_r`, `reconcileHosts_r`, and TMAY cache helpers. Client APIs include `h_FindClient_r`, `GetClient`, `PutClient`, `h_ReleaseClient_r`, `h_UserName`, and `h_EnumerateClients`. DAFS APIs include `h_stateSave`, `h_stateRestore`, `h_stateRestoreIndices`, `h_stateVerify`, and `h_OldToNew`.

Core types/state: global `hostList`, `hostCount`, `hostAddrHashTable`, and `hostUuidHashTable` form the active host registry. `hosttableptrs` supports index-to-host mapping used by callback state. `HTBlocks`/`HTs` and `CEBlocks`/`CEs` account pooled allocations. Each host carries a callback Rx connection, primary address/port, host flags, CPS data, interface list, callback list head, TMAY cache, and clients. Each client records connection id/epoch, ViceId, CPS, token expiration, auth class, deleted bit, and reference count. `rxcon_ident_key` stores probed host identity per Rx connection and `rxcon_client_key` stores the active client.

Control flow: `h_GetHost_r` is the central path. It first looks up by incoming address/port, verifies new connections with `TellMeAboutYourself`/`WhoAreYou` or cached TMAY results, handles UUID mismatch by removing stale addresses and retrying, swaps callback connections when a client moves address/port, merges duplicate hosts by UUID, initializes callback state for new hosts, and marks failures `VENUSDOWN`. `h_FindClient_r` first reuses connection-specific clients when valid, otherwise authenticates the Rx peer, obtains/creates the host, finds or allocates a client by connection id/epoch, refreshes CPS, resolves races with an existing connection-specific client, and attaches the client to Rx-specific data. `h_CheckHosts` periodically probes idle hosts, marks idle clients deleted, and marks long-idle hosts deleted or down.

State and persistence behavior: normal state is in-memory and protected primarily by `H_LOCK`, host locks, and client locks. Host deletion is lazy: `HOSTDELETED`/`CLIENTDELETED` flags are set first, and `h_TossStuff_r` frees callback connections, CPS arrays, TMAY capabilities, callbacks, hash entries, interface lists, clients, and host pool entries once references and locks allow. DAFS serialization skips busy hosts, deletes callbacks for skipped hosts, writes host disk entries plus interface and host-CPS vectors, restores callback connections/hash tables/UUID tables/list membership, and builds old-to-new host index maps. `h_stateVerify` checks address hashes, UUID hashes, and per-host callback lists.

Dependencies and integration: tightly integrated with `callback.c` through host callback list heads, callback connection resets, `DeleteAllCallBacks_r`, `MultiProbeAlternateAddress_r`, and callback state index mapping. Uses generated cache-manager RPCs (`RXAFSCB_TellMeAboutYourself`, `WhoAreYou`, `ProbeUuid`, `InitCallBackState3`), Rx connection-specific storage, ubik PR server RPCs for CPS/name lookup, fileserver config/auth (`afsconf_*`), and xstat/network stats globals from `fs_stats.h`. The host lock order documented in `host.h` is essential: client lock, host lock, then `H_LOCK` for blocking-order reasoning, with explicit drops around network I/O.

Risks: this file is concurrency-sensitive. Many paths drop `H_LOCK` around Rx or PR RPCs and then resume against structures that may have been deleted, rehashed, or had callback connections swapped. Refcount/lock ordering in `h_TossStuff_r`, `h_FindClient_r`, and `h_GetHost_r` is delicate. Address reconciliation must defend against NAT, stale client-reported interfaces, clients changing port, and UUID conflicts; regressions can attach callbacks or clients to the wrong host. CPS caching failures can temporarily deny group-based access or retry under load. `h_UserName` returns a static buffer and is unsuitable for concurrent long-lived use. Demand-attach save skips busy hosts, so callers must tolerate missing restored host/callback state.

Test signals: high-value tests include concurrent new connections from the same host, TMAY caching with waiters, host UUID mismatch and address migration, NAT port changes, duplicate host merge by UUID, alternate address probe success/failure, host/client lazy deletion under references, CPS failure retry behavior, token expiry through `GetClient`, DAFS host save/restore/index verification, and periodic `h_CheckHosts` transitions. Runtime diagnostics include host/client dumps, `ViceLog` messages for `CB`, `FindClient`, `reconcileHosts_r`, and hash verification warnings.
