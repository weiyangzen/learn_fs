# sources/distributed-fs/openafs/src/viced/afsfileprocs.c

## Purpose

`afsfileprocs.c` is the OpenAFS fileserver (`viced`) implementation of the RXAFS file service RPC surface generated by rxgen. It handles client requests for fetching and storing data, ACLs, and status; directory namespace mutation; hard links, symlinks, locks, callbacks, volume status, statistics, capabilities, time, and compatibility stubs. The file is the main request-processing layer between Rx network calls and the volume/vnode, inode, directory, ACL, host/client, callback, audit, and stats subsystems.

The code follows a consistent server-side RPC pattern: validate and authenticate the Rx call through `CallPreamble`, acquire the relevant client/host/volume/vnode state through `GetVolumePackage`, check ACL and Unix-mode permissions, perform inode or directory work, update vnode/volume metadata, convert write locks to read locks before breaking callbacks, release all refs through `PutVolumePackage`, translate errors when the client negotiated that capability, and emit stats/audit records.

## Important APIs, Types, and Globals

- RXAFS entry points: `SRXAFS_FetchData`, `SRXAFS_FetchData64`, `SRXAFS_FetchACL`, `SRXAFS_FetchStatus`, `SRXAFS_BulkStatus`, `SRXAFS_InlineBulkStatus`, `SRXAFS_StoreData`, `SRXAFS_StoreData64`, `SRXAFS_StoreACL`, `SRXAFS_OldStoreACL`, `SRXAFS_StoreStatus`, `SRXAFS_RemoveFile`, `SRXAFS_CreateFile`, `SRXAFS_Rename`, `SRXAFS_Symlink`, `SRXAFS_Link`, `SRXAFS_MakeDir`, `SRXAFS_RemoveDir`, lock RPCs, callback give-up RPCs, volume status RPCs, stats RPCs, `SRXAFS_GetCapabilities`, `SRXAFS_GetTime`, and compatibility/dummy RPCs.
- Core local wrappers: `CallPreamble`/`CallPostamble`, `CheckVnodeWithCall`, `GetVolumePackageWithCall`, `PutVolumePackageWithCall`, `Check_PermissionRights`, `CheckWriteMode`, `GetRights`, `SetAccessList`, `GetStatus`, `SetVolumeSync`, and `SetCallBackStruct`.
- Persistent objects manipulated here: `Volume`, `Vnode`, `IHandle_t`, `FdHandle_t`, `DirHandle`, `AFSFid`, `AFSFetchStatus`, `AFSStoreStatus`, `AFSVolSync`, `AFSCallBack`, ACL blobs, and Rx connection/call objects.
- File data transfer helpers: `FetchData_RXStyle` sends file contents over Rx after length validation; `StoreData_RXStyle` receives bytes, handles truncation/extension, copy-on-write, quota/disk accounting, optional sync, and error rollback.
- Namespace helpers: `Alloc_NewVnode`, `DeleteTarget`, `Update_ParentVnodeStatus`, `Update_TargetVnodeStatus`, `RXFetch_AccessList`, `RXStore_AccessList`, and `FileNameOK`.
- Shared counters/state: `AFSCallStats`, `afs_FullPerfStats`, `afs_perfstats`, `BlocksSpare`, `PctSpare`, `readonlyServer`, `adminwriteServer`, `implicitAdminRights`, `enable_old_store_acl`, `saneacls`, volume package stats, host/client cache stats, and static `sys2et` error translation table.

## Control Flow

The common request path begins with `CallPreamble`, which resolves the Rx connection to a held `host` and `client`, retries protection-server CPS initialization once when needed, updates last-call/activity timestamps, and tries to clear delayed callback state for hosts that were marked down or later. Most RPCs then call a `SAFSS_*` worker that does the actual operation, and the public `SRXAFS_*` wrapper finishes `fsstats` and audit logging.

`GetVolumePackageWithCall` is the central object acquisition routine. It gets a volume with `VGetVolumeWithCall`, handles restart/busy/salvage behavior, gets the target vnode at the requested lock level, validates vnode uniquifiers, optionally enforces directory/non-directory expectations, resolves the ACL from the target or parent directory, obtains the client, and computes caller/anonymous rights. `PutVolumePackageWithCall` releases parent/target vnodes, the volume, and the client in the expected order.

Fetch RPCs use read locks. `common_FetchData64` validates offsets, obtains volume/vnode/client state, checks `CHK_FETCHDATA`, saves and drops the parent vnode when only status context is needed, streams the selected byte range through `FetchData_RXStyle`, returns status, and grants a per-file or volume callback. `FetchACL` externalizes ACLs. `FetchStatus`, `BulkStatus`, and `InlineBulkStatus` fill status structures and callbacks, with `InlineBulkStatus` recording per-file errors instead of aborting the whole batch.

Store RPCs use write locks and callback breaks. `common_StoreData64` verifies non-directory/non-symlink targets, checks `CHK_STOREDATA`, streams data through `StoreData_RXStyle`, updates target vnode status via `Update_TargetVnodeStatus`, returns status, and breaks callbacks inside the store helper before mutating data. `common_StoreACL` validates that the opaque ACL contains a NUL byte, blocks old `OldStoreACL` unless enabled, internalizes the ACL into the directory vnode, and breaks callbacks. `StoreStatus` handles chmod/chown/chgrp/modtime changes, with special symlink-mode rejection.

Directory mutation RPCs share the pattern of locking the parent directory, checking insert/delete rights, copy-on-writing cloned directories, updating directory package contents, then updating vnode metadata and callbacks. `CreateFile`, `Symlink`, and `MakeDir` allocate new vnodes and inodes with `Alloc_NewVnode`. `RemoveFile` and `RemoveDir` call `DeleteTarget`, which validates names, looks up the child, checks type, decrements link counts, removes inodes when needed, adjusts disk usage, and deletes the directory entry. `Rename` is the most complex path: it locks old/new dirs in vnode-number order, rejects cross-volume moves, validates replacement semantics, prevents directory cycles, updates `..` when a directory moves, deletes an existing target when legal, updates both parent directories, adjusts link counts, and breaks callbacks for all affected fids.

Lock RPCs call `HandleLocking`, which stores advisory lock state in `targetptr->disk.lock`. Read locks require `PRSFS_LOCK`, `PRSFS_WRITE`, or owner-with-insert rights and increment nonnegative lock counts. Write locks require write or owner-insert rights and set lock count to `-1`. Extend updates expiry only when a lock exists; release decrements and clears the lock when the count reaches zero. Read-only volumes are treated permissively for read/extend/release cases where state cannot be saved.

Stats and utility RPCs collect in-memory server, Rx, host, callback, vnode, and partition counters. `GetStatistics`/`GetStatistics64` return classic and 64-bit summaries; `XStatsVersion`/`GetXStats` return extended collections; `GetCapabilities` advertises error translation, write-lock ACLs, 64-bit files, and optionally sane ACLs. `GetVolumeStatus` and `SetVolumeStatus` read/write volume label fields. `FlushCPS` requires superuser privileges and marks client or host CPS caches for recomputation.

## State and Persistence Behavior

Persistent file state is split between vnode index fields and inode contents. This file updates vnode fields such as owner, group, mode bits, link count, parent vnode, data version, file length, author, Unix/server modification times, lock state, clone flag, and deletion marker. `VPutVnode` writes changed vnodes back; `VUpdateVolume` persists volume label changes such as owner/quota/name/offline message.

Inode persistence is managed through the `IH_*` and `FDH_*` abstractions. `CopyOnWrite` creates a new inode, copies old bytes, decrements the old inode, swaps the vnode handle/inode number, clears the cloned flag, and forces volumes offline or salvage-needed on corruption-like errors. `StoreData_RXStyle` may truncate, extend by a one-byte write plus truncate for sparse zero-length stores, write incoming Rx data, sync when requested, and reconcile volume disk usage if an error leaves a different on-disk size.

Directory persistence flows through the AFS directory package. `SetDirHandle`, `afs_dir_Create`, `afs_dir_Delete`, `afs_dir_Lookup`, `afs_dir_MakeDir`, `afs_dir_IsEmpty`, `afs_dir_Length`, `DFlush`, `DZap`, `FidZero`, and `FidZap` maintain directory pages and handles. Parent directory data versions, lengths, link counts, author/write statistics, and modification times are updated after namespace changes.

Quota and partition accounting is explicit. `AdjustDiskUsage` pre-charges or adjusts block usage via `VAdjustDiskUsage`, using `SpareComp` to preserve configured spare space. Store and allocation paths roll back or correct accounting on errors where possible; serious mismatch between vnode length and inode size triggers `VTakeOffline` and returns `VSALVAGE`.

Callback state is integrated with persistence semantics. Fetch/status paths grant callbacks with `AddCallBack`, `AddBulkCallBack`, or `AddVolCallBack`; mutation paths convert write locks to read locks before calling `BreakCallBack`, `DeleteFileCallBacks`, `DeleteCallBack`, or `DeleteAllCallBacks_r`. This is how clients are informed that cached data/status/dirs are stale.

## Dependencies and Integration Points

- Rx RPC/runtime: `struct rx_call`, `struct rx_connection`, `rx_Read`, `rx_Write`, vector I/O variants, per-connection client specific data, abort codes, peers, and negotiated host flags.
- Host/client subsystem: `h_FindClient_r`, `GetClient`, `PutClient`, host locks, CPS state, callback connection state, workstation/client counters, delayed callback recovery, and CPS flushing.
- Volume/vnode package: `VGetVolumeWithCall`, `VGetVnode`, `VPutVnode`, `VPutVolumeWithCall`, `VAllocVnode`, `VAdjustDiskUsage`, `VDiskUsage`, `VSetPartitionDiskUsage`, `VUpdateVolume`, demand-attach/restart/salvage error modes, and partition accounting.
- Directory package: `afs_dir_*` functions and `DirHandle` helpers.
- ACL/protection package: `acl_CheckRights`, `acl_Externalize_pr`, `acl_Internalize_pr`, `hpr_NameToId`, `hpr_IdToName`, protection CPS lists, `SystemAnyUserCPS`, `SystemId`, and implicit admin rights.
- Inode abstraction: namei or platform inode link-count paths, `IH_CREATE`, `IH_OPEN`, `IH_DEC`, `IH_RELEASE`, `FDH_SIZE`, `FDH_PREAD`, `FDH_PWRITE`, `FDH_TRUNC`, `FDH_SYNC`, and close variants.
- Callback package: file and volume callback add/break/delete operations and callback counters.
- Observability: `ViceLog`, `osi_auditU`, `fsstats_*`, `AFSCallStats`, `afs_perfstats`, `afs_FullPerfStats`, Rx statistics, host stats, volume stats, and process size.
- Compatibility and protocol integration: old ACL and old lock RPC aliases, DFS translator stubs returning `EINVAL`, `GetRootVolume` returning `EOPNOTSUPP`, token check returning connection refused, and `sys_error_to_et` mapping when `HERRORTRANS` is set.

## Risks and Edge Cases

- Object lifetime is subtle. Many RPCs independently recover `t_client` through `rx_GetSpecific` for logging/auditing after `CallPreamble`; the file itself notes that callback-address handling should pass the chosen connection/client/host consistently to avoid races.
- Length consistency is critical. `CheckLength` treats vnode-index length versus inode-size mismatch as salvage-worthy. Any missing check in new data or directory code could preserve corrupt state or wrongly take a volume offline.
- Error paths mix recoverable user errors with volume-offline decisions. `CopyOnWrite`, `FetchData_RXStyle`, `StoreData_RXStyle`, `DeleteTarget`, and rename/delete paths can call `VTakeOffline`; tests need to distinguish expected ENOSPC/EACCES behavior from salvage-triggering corruption.
- Rename has many invariants: lock order, same-volume restriction, directory cycle detection, replacement type compatibility, hard-link restrictions across directories, `..` updates, link count changes, and callback breaks. It is high risk for regressions.
- ACL storage has historical security handling. `check_acl` explicitly prevents unterminated ACL blobs, and `OldStoreACL` is disabled unless `enable_old_store_acl` is set because of CVE-2018-7168. Any ACL parser changes must preserve this boundary.
- Permission logic combines AFS ACL rights, Unix mode bits, ownership, volume ownership, host CPS rights, implicit admin rights, read-only/admin-write server modes, and special create-after-insert owner behavior. Small changes can alter long-standing semantics.
- Disk accounting and copy-on-write paths have partial rollback behavior. ENOSPC is handled differently from corruption or I/O errors, and partition `PART_DONTUPDATE` flags are toggled during clone copy accounting.
- Several allocation failures panic with `ViceLogThenPanic` instead of returning errors. Bulk/status/stat output allocation behavior should be assessed for denial-of-service exposure if request sizes are large.
- Some RPCs intentionally omit or reduce preamble work (`GetXStats`) to avoid callback/protection side effects for simple stats clients.
- Compatibility stubs and hard-coded feature returns are protocol-visible. Changing return codes for unsupported DFS/root/token operations can affect old clients.

## Test Signals

- Build-level signal: compile `viced` with both normal and platform-specific options such as `HAVE_PIOV`, `AFS_NAMEI_ENV`, demand-attach, and `USE_GROUP_PERMS`, because major branches are compile-time controlled.
- Fetch/store tests should cover 32-bit and 64-bit offsets, negative/overflow rejection, fetch past EOF, zero-length newly created files, truncation, sparse extension by zero-length store, sync stores, Rx short read/write failures, and vnode/inode length mismatch salvage behavior.
- Permission tests should cover anonymous, owner, group/member, system:administrators, implicit admin lookup, volume owner, read-only server, admin-write server, chmod/chown/chgrp, suid/sgid clearing, ACL administer rights, insert-only owner first store, and Unix owner write/read bits.
- Namespace tests should cover invalid names (`/`, trailing `@sys`, `.`, `..`), create/remove file, symlink and mount-point mode rules, hard-link same-directory restriction, mkdir ACL inheritance, rmdir non-empty rejection, rename over file/dir combinations, same-directory rename, cross-directory directory rename, replacement delete, hard-linked file move rejection, and cycle prevention.
- Callback tests should assert that fetch/status grants file or volume callbacks, stores and metadata changes break target callbacks, directory mutations break parent directory callbacks, deletes remove callbacks when link count reaches zero, and lock release breaks callbacks when locks clear.
- Disk/quota tests should exercise quota full, partition full, insufficient inodes, copy-on-write of cloned files/directories, shared inode link count copy, rollback after write error, and partition disk usage recalculation.
- Volume/status/stats tests should verify `GetVolumeStatus` string allocation on errors, admin-only `SetVolumeStatus`, `FlushCPS` superuser enforcement, stats64 version rejection, advertised capability flags, and `sys_error_to_et` translation under `HERRORTRANS`.
