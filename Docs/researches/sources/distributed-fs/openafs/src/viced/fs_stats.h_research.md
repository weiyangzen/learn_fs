# sources/distributed-fs/openafs/src/viced/fs_stats.h

Purpose: defines the fileserver performance-statistics data contract used by the xstat interface and by fileserver request instrumentation. It describes overall counters, detailed per-RPC timing records, transfer-size histograms, time-manipulation macros, global stats objects, server identity globals, and helper function prototypes implemented in `fsstats.c`.

Important APIs/types/macros: `struct afs_PerfStats` is the overall xstat payload, containing vnode-cache, directory, Rx, host/client, sysname, busy, capability, and spare counters. `FS_STATS_RPCIDX_*` assigns stable indices to 28 fileserver RPC operations; `FS_STATS_XFERIDX_*` assigns indices for fetch/store data transfers. `struct fs_stats_opTimingData` records operation counts, successes, sum/square/min/max times. `struct fs_stats_xferData` records transfer counts, byte totals, min/max bytes, timings, and nine byte-size buckets. `struct fs_stats_DetailedStats` and `struct fs_stats_FullPerfStats` combine detailed and overall data. `struct fsstats` is the per-call scratch object passed to start/finish helpers.

Control flow support: the header is mostly declarative, but its time macros are invoked by `fsstats.c` to compute elapsed time, update sums, compare min/max values, and add squared timing samples. The `FS_STATS_RPCIDX_*` constants are used by RPC handlers to select the correct timing slot, while transfer handlers use `FS_STATS_XFERIDX_FETCHDATA` or `FS_STATS_XFERIDX_STOREDATA` plus bucket thresholds from `FS_STATS_MAXBYTES_BUCKET*`.

State and persistence behavior: statistics are process-memory counters exposed through xstat collections, not durable storage. `afs_FullPerfStats` backs `AFS_XSTATSCOLL_FULL_PERF_INFO`; `afs_perfstats` backs `AFS_XSTATSCOLL_PERF_INFO`. `FS_HostName`, `FS_HostAddr_NBO`, and `FS_HostAddr_HBO` provide the fileserver identity/address values consumed by host statistics and classification logic. `struct timeval` fields retain accumulated microsecond-level timing until reset or process restart.

Dependencies and integration: depends on `afs/param.h` for platform and integer definitions. Included by `host.h` for fileserver stats packaging and by `fsstats.c` for helper implementations. The field ordering in `afs_PerfStats` and the RPC index constants are externally visible through xstat clients, so compatibility matters.

Risks: the macros evaluate arguments multiple times and mutate their operands; callers must pass lvalues with care. `fs_stats_GetDiff` modifies its `t2` argument while normalizing microseconds, which is safe for local variables but dangerous if reused unexpectedly. `sumBytes`, min/max bytes, and several counters are 32-bit, so high-throughput servers can wrap. `fs_stats_SquareAddTo` uses mixed integer/floating-point arithmetic and casts to `int`, which can lose precision or overflow for long timings. Adding/removing RPCs without synchronizing `FS_STATS_NUM_RPC_OPS` and xstat consumers would break ABI assumptions.

Test signals: unit tests can exercise time comparison, diff, add, and square macros across microsecond borrow/carry boundaries. Integration tests should verify each fileserver RPC uses the intended index, transfer sizes map to expected buckets, xstat collection sizes remain stable, and counters remain protected by the fileserver stats lock in implementations.
