# sources/distributed-fs/openafs/src/afs/afs_dynroot.h

Purpose: Defines the vnode-number encoding contract used by dynamic `/afs` root support. The header is intentionally small but central: `afs_dynroot.c`, vcache creation, and lookup code depend on these macros to interpret synthetic vnodes as cells, aliases, temporary symlinks, or dynamic mount points.

Important APIs and definitions: Vnode type constants are `VN_TYPE_CELL`, `VN_TYPE_ALIAS`, `VN_TYPE_SYMLINK`, and `VN_TYPE_MOUNT`. `VNUM_TO_VNTYPE` extracts the high 8-bit type, `VNUM_TO_VNID` extracts the low 24-bit payload, and `VNUM_FROM_TYPEID` creates an encoded vnode. Cell/alias helpers map payload bits: `VNUM_TO_CIDX`, `VNUM_TO_RW`, `VNUM_FROM_CIDX_RW`, and `VNUM_FROM_CAIDX_RW`. `AFS_DYNROOT_MOUNTNAME` defines the synthetic mount directory name `.:mount`.

Control flow: Header-only macros have no runtime flow. They define how `afs_RebuildDynroot` assigns vnode numbers for directory entries and how `afs_DynrootNewVnode` decodes those vnode numbers later to construct symlink targets and statuses.

State and persistence: No state is stored here. The encoded vnode format is persistent within live vcaches and directory blobs for the current client runtime. It is not a disk format in this file, but changing it can invalidate assumptions across cached dynroot entries.

Dependencies and integration points: Included by `afs_dynroot.c`; the values correspond to `struct cell` indexes, `struct cell_alias` indexes, dynamic symlink indexes, and dynroot mount handling. The bit layout relies on OpenAFS vnode numbers being wide enough for an 8-bit type plus 24-bit id.

Risks: The macros do not mask inputs in `VNUM_FROM_TYPEID`, so oversized type/id values can overlap fields. Cell and alias indexes are encoded, not stable names; stale vcaches after cell-table changes can decode to missing objects and trigger inconsistency warnings. `VNUM_TO_RW` uses one bit to distinguish readonly/dot entries, limiting future payload expansion unless the layout is revised carefully.

Test signals: Static/unit tests should round-trip type/id, cell index/readwrite flag, and alias index/readwrite flag values. Dynroot integration tests should assert that entries generated by `afs_RebuildDynroot` decode to the expected branch in `afs_DynrootNewVnode`, including `.:mount` and user symlink entries.
