# sources/distributed-fs/openafs/src/afs/afs_dcache.c

Purpose: Implements the OpenAFS client data cache. It manages dcache lookup by fid/chunk, dslot allocation, LRU eviction, split-cache bucket accounting, persistent `CacheItems` slot I/O, memory-cache and UFS-cache backends, network fetch population, dynroot-backed synthetic data reads, write preparation, shadow directories for disconnected mode, and cache truncation/drain behavior.

Important APIs and functions: Hashing and bucket helpers include `DCHash`, `DVHash`, `afs_DCGetBucket`, `afs_DCAdjustSize`, `afs_DCMoveBucket`, and `afs_DCWhichBucket`. Cache pressure is handled by `afs_MaybeWakeupTruncateDaemon`, `afs_MaybeWaitForCacheDrain`, `afs_CacheTruncateDaemon`, `afs_GetDownD`, `afs_FreeDiscardedDCache`, and `afs_MaybeFreeDiscardedDCache`. Public lookup/write paths are `afs_FindDCache`, `afs_GetDCache`, `afs_IsDCacheFresh`, `afs_ObtainDCacheForWriting`, `afs_PopulateDCache`, `afs_TryToSmush`, and `afs_DCacheMissingChunks`. Slot persistence uses `afs_MemGetDSlot`, `afs_UFSGetDSlot`, `afs_WriteDCache`, `afs_WriteThroughDSlots`, `afs_InitCacheFile`, `afs_dcacheInit`, and `shutdown_dcache`. Disconnected helpers are `afs_MakeShadowDir` and `afs_DeleteShadowDir`.

Control flow: `afs_GetDCache` first computes the chunk, tries the vcache hint, then scans the fid/chunk hash chain. On miss it wakes or invokes eviction, allocates from the free or discarded lists, initializes the dcache, links it into both hash tables, and then checks freshness. Stale entries are write-locked, text/pages are flushed when needed, cache-drain thresholds can force retry, expected fetch size is computed from file length/truncation state, and data is fetched either from dynroot memory or via `afs_CacheFetchProc`. Successful fetches update chunk size, data version, status/callback fields, LRU time, and hints; failures zap/truncate the slot and stale the vcache. `afs_ObtainDCacheForWriting` wraps this for writes, marking `IFDataMod` and `DWriting`.

State and persistence: Core state is global: dcache hash tables (`afs_dchashTbl`, `afs_dvhashTbl`), next arrays, index-to-dcache table, unique/time/flag arrays, LRU queue, free and discarded dcache lists, free in-memory dslot list, block counters, discarded block counters, split-cache bucket counters, cache geometry, and the active cache backend. Persistent state is the UFS `CacheItems` file, written by `afs_WriteDCache`, plus per-cache chunk files addressed through `afs_cacheType` operations. Memory cache avoids `CacheItems` writes but shares the same logical dcache state.

Dependencies and integration points: Integrates with vnode operations for reads/writes/directory ops, `afs_segments.c` for stores/truncation, `afs_fetchstore.c` for network fetches, `afs_buffer.c` directory buffer I/O, dynroot for synthetic `/afs` data, disconnected replay for shadow dirs and fake fids, OS VM page invalidation hooks, RX connection analysis, stats/tracing, and OS-specific cache inode/path helpers. `afs_cacheOps` abstracts UFS versus memory cache backends.

Risks: This file is lock-order-sensitive: `afs_xdcache`, dcache `tlock`, dcache data locks, vcache locks, and VM locks are combined in many paths. Eviction drops and reacquires `afs_xdcache` while holding candidate references, so refcount and flag rechecks are essential. Hash corruption is possible if zero-volume or stale-fid entries are written as active. Cache-size sanity checks deliberately ignore some RW/local sparse-file cases; changing them can cause false corruption reports or stale reads. Discarded entries reuse space before truncation, so block accounting and wait wakeups must stay consistent. `afs_MakeShadowDir` allocates and hashes a fresh dcache before copying data; partial-copy failures can leave cleanup-sensitive state. Persistent UFS slot reads tolerate invalid entries differently for `DSLOT_NEW`, `DSLOT_UNUSED`, and `DSLOT_VALID`, and panics are intentional for impossible states.

Test signals: Validate cache initialization for UFS and memory backends, bad cache file detection, `CacheItems` read/write errors, and shutdown cleanup. Exercise hit, hint hit, miss, stale DV, dynroot fetch, network fetch, fetch error, disconnected stale miss, whole-chunk overwrite, sparse write extension, and cache-drain retry paths. Stress eviction with active refs, dirty pages, dirty data, split-cache buckets, discarded lists, and truncate-daemon wake/sleep behavior. Test shadow-dir create/delete and disconnected fake-fid lookup. Add instrumentation or assertions around hash-chain membership, refcounts, `IFDataMod`/`IFDiscarded`/`IFFree`, block counters, and LRU timestamps.
