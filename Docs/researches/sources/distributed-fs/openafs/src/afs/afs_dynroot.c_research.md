# sources/distributed-fs/openafs/src/afs/afs_dynroot.c

Purpose: Implements dynamic `/afs` root support. Instead of requiring a real `root.afs` volume, it synthesizes a dynroot cell/volume, builds an in-memory directory containing configured cells, aliases, a dynamic mount directory, and root-created temporary symlinks, and maps synthetic vnodes to symlink or directory statuses.

Important APIs and functions: Initialization/control functions are `afs_InitDynroot`, `afs_SetDynrootEnable`, `afs_GetDynrootEnable`, and `afs_dynrootCellInit`. Fid/type predicates and constructors include `afs_IsDynrootVolume`, `afs_IsDynrootFid`, `afs_IsDynrootMountFid`, `afs_IsDynrootAnyFid`, `afs_GetDynrootFid`, `afs_GetDynrootMountFid`, `afs_IsDynroot`, `afs_IsDynrootMount`, and `afs_IsDynrootAny`. Directory generation is handled by `afs_RebuildDynroot`, `afs_RebuildDynrootMount`, `afs_dynroot_computeDirEnt`, and `afs_dynroot_addDirEnt`. Consumers call `afs_GetDynroot`, `afs_GetDynrootMount`, `afs_PutDynroot`, and `afs_DynrootNewVnode`. Mutating VOP hooks are `afs_DynrootVOPSymlink` and `afs_DynrootVOPRemove`.

Control flow: Enabling dynroot creates a synthetic `dynroot` cell and records its cell number. `afs_DynrootInvalidate` increments a version/high-version timestamp and stales the root vcache. `afs_GetDynroot` rebuilds the directory lazily when no buffer exists or the directory version lags. Rebuild first computes required pages by walking cells, aliases, and dynamic symlinks, then allocates a directory blob, initializes directory page/header structures, inserts `.`, `..`, `.:mount`, cell names, dot-cell variants, aliases, dot-alias variants, and user symlinks with encoded vnode numbers. `afs_DynrootNewVnode` recognizes root, mount directory, cell/alias/mount/symlink vnode types, fills `AFSFetchStatus`, allocates `linkData` for synthetic symlinks, and sets vcache type.

State and persistence: Process/kernel state includes enable/init flags, synthetic cell number, dynroot directory buffers and lengths, link count, directory version counters, dynroot mount directory buffer, and a linked list of temporary symlinks with monotonically increasing indexes. Locks are split between `afs_dynrootDirLock` and `afs_dynSymlinkLock`. There is no on-disk persistence for user-created dynroot symlinks; they live only in memory until shutdown.

Dependencies and integration points: Integrates with cell/cell-alias registries, volume/root fid discovery (`afs_CheckRootVolume`), dcache fetches for dynroot directory data, vcache creation (`afs_DynrootNewVnode` is called from vcache code), lookup invalidation from cell changes, directory blob layout from `afs/dir.h`, access bits from `prs_fs.h`, and VNOPS symlink/remove paths for privileged temporary entries.

Risks: `afs_InitDynroot` initializes locks but leaves `afs_dynrootInit` as 0, so callers repeatedly run initialization logic; this appears intentional or historical but is worth guarding in refactors. Directory rebuild holds the symlink read lock while allocating/filling the directory and assumes cell/alias indexes stay meaningful between compute and fill passes. Vnode numbers encode cell/alias indexes, so deleted/reordered cell tables can produce stale vnode inconsistencies logged as warnings. Root-only symlink creation/removal checks uid but temporary links are not durable. `afs_DynrootNewVnode` may allocate `linkData`; ownership must match vcache cleanup.

Test signals: Enable/disable dynroot, verify root fid and mount fid, and fetch `/afs` and `.:mount` through dcache. Add/remove cells and aliases and confirm invalidation/version/status changes. Lookup normal and dot-cell entries, aliases with and without real names, user-created symlinks, and mount vnodes by volume id. Test non-root symlink/remove rejection, collisions with cells/aliases, stale vnode indexes, shutdown buffer freeing, and fakestat behavior for symlink-to-directory presentation.
