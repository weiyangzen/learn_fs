# sources/distributed-fs/openafs/src/afs/afs_disconnected.c

Purpose: Implements disconnected-mode dirty-state reconciliation for the OpenAFS cache manager. It tracks dirty vcaches and shadow directories, generates local fake fids/status for offline creates, resolves names and parents from cached directories, replays create/remove/rename/status/store operations to fileservers, and discards or preserves local changes according to conflict policy.

Important APIs and functions: `afs_FindDCacheByFid` locates the first dcache for an exact fid. `afs_ResyncDisconFiles` is the main replay loop. Operation-specific replay is split into `afs_ProcessOpCreate`, `afs_ProcessOpRemove`, `afs_ProcessOpRename`, and `afs_SendChanges`. Local metadata helpers include `afs_GenStoreStatus`, `afs_GetParentDirFid`, `afs_GetVnodeName`, `afs_GetParentVCache`, `afs_CheckDeletedChildren`, `afs_FixChildrenFids`, `afs_GenShadowFid`, `afs_GenFakeFid`, and `afs_GenDisconStatus`. Cleanup APIs are `afs_DisconDiscardAll`, `afs_DisconDiscardAllShadows`, and debug listing via `afs_DbgListDirEntries`.

Control flow: Offline vnode operations mark `ddirty_flags` and may create shadow dirs via dcache code. On reconnection, `afs_ResyncDisconFiles` processes `afs_disconDirty` from the tail while dropping the dirty-list lock to acquire each vcache lock. Removes replay first and terminate further work for that vnode. Creates allocate server objects, then rewrite the parent directory entry, vcache hash membership, dcache hash membership, `afs_indexUnique`, and the vnode fid from fake to server-assigned fid. Renames recover old names from shadow directories and new names from current directories. For existing objects, the code fetches server status, compares data version/modtime, applies `CLIENT_WINS`/`SERVER_WINS`/created-file policy, then sends attributes and data changes.

State and persistence: Dirty state is in process/kernel memory: circular queues `afs_disconDirty` and `afs_disconShadow`, `afs_disconDirtyLock`, per-vcache `ddirty_flags`, old-parent and shadow fid fields, and the fake-vnode counter `afs_DisconVnode`. Shadow directories are persisted as dcache chunks with generated fids until replay/discard. Conflict policy defaults to `SERVER_WINS`. There is no independent durable journal; correctness depends on cached vcache/dcache metadata and shadow directory copies surviving long enough for reconciliation.

Dependencies and integration points: Uses dcache hash tables and slot APIs, directory enumeration/change helpers, vcache hash queues, RXAFS RPCs (`CreateFile`, `MakeDir`, `Symlink`, `RemoveFile`, `RemoveDir`, `Rename`, `FetchStatus`, `StoreStatus`), `afs_Analyze`, `afs_UpdateStatus`, `afs_StoreAllSegments`, and vnode operation code that marks disconnected dirty flags. `discon.h` exposes key entry points to VNOPS code.

Risks: Replay ordering is hard: children of locally created directories must wait for the parent to get a server fid, and removed non-empty directories with dirty deleted children are deferred with `EAGAIN`. Fake-to-real fid promotion rewrites vcache and dcache hash chains while holding global locks; missed dcaches or stale uniques can make data unreachable or alias wrong files. Name recovery depends on cached parent/shadow directory entries, so missing dcaches return network-like errors and abort reconciliation. Conflict handling is incomplete for `LAST_CLOSER_WINS`/`ASK`, and `SERVER_WINS` resets local state. Symlink target extraction reads cached data and caps at 1024 bytes. Several TODO/printf comments indicate partial error handling.

Test signals: Build disconnected scenarios for create file/dir/symlink, write, truncate, chmod/mtime, rename same-dir and cross-dir, remove file/dir, nested creates, and dirty deleted children. Verify fake fid uniqueness, vcache/dcache hash rewrites, parent fid updates in child vcaches and `..` entries, shadow-dir creation/deletion, and queue reordering on `EAGAIN`. Test conflict policies with matching DV, server-changed DV, server-changed mtime, and created files. Simulate missing parent/shadow dcaches and RPC failures to ensure dirty state remains recoverable.
