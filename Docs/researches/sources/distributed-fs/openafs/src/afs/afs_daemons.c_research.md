# sources/distributed-fs/openafs/src/afs/afs_daemons.c

Purpose: Implements long-running OpenAFS cache-manager daemons and the background request queue. It covers periodic client maintenance (`afs_Daemon`), server probing (`afs_CheckServerDaemon`), root volume discovery, queued background fetch/store/path operations, legacy AIX biod handling, and platform-specific SGI dcache-slot flushing.

Important APIs and functions: `afs_CheckServerDaemon` probes down servers at `afs_probe_interval` and all servers at `afs_probe_all_interval`. `afs_Daemon` is the main periodic maintenance loop, coordinating callbacks, dcache truncation wakeups, RX packet checks, token/cache cleanup, interface address changes, volume-name checks, root-volume checks, PAG GC, exporter GC, and shutdown progression. `afs_CheckRootVolume` resolves the root fid from dynroot or the configured/local `root.afs` volume with readonly fallback. `afs_BQueue`, `afs_BRelease`, `afs_BBusy`, and `afs_BackgroundDaemon` implement the `struct brequest` queue. Static workers `BPath`, `BPrefetch`, `BPrefetchNoCache`, `BStore`, `BPartialStore`, and `BInvalidateSegments` execute queued operations.

Control flow: Startup waits for `afs_initState >= 101`; the main daemon then runs timed blocks for sub-minute, 1-minute, 3-minute, 5-minute, 10-minute, and 60-minute work. Root volume initialization is retried until `afs_initState` reaches 300. `afs_CheckServerDaemon` can run separately; when absent, `afs_Daemon` performs server checks itself. Background callers allocate a request with `afs_BQueue`; background daemons select the unstarted request with the smallest timestamp, mark `BSTARTED`, run the matching operation, release held vnode/credential references, and wake waiters through `BUVALID`/`BUWAIT`. Under `AFS_NEW_BKG`, userspace operations such as Darwin `BOP_MOVE` can be returned to afsd and completed on re-entry via timestamp matching.

State and persistence: Global process/kernel state includes `afs_brs`, `afs_xbrs`, waiter counts, daemon counts, request timestamps, wait handles, probe intervals, PAG GC knobs, and init/termination state transitions. Requests hold vcache and credential references until `brequest_release`. No durable on-disk data is owned here; persistence is indirect via dcache writes, volume metadata, callbacks, and cache-manager state maintained in other modules.

Dependencies and integration points: Depends on cache-manager globals from `afsincludes.h`, callback queues, RX, volume lookup, vcache/dcache APIs, vnode lookup, credential reference helpers, exporter ops (`root_exported`, `EXP_GC`), dynamic root (`afs_GetDynrootEnable`, `afs_GetDynrootFid`), and platform OSI layers. `afs_BQueue` is used by vnode read/write/open/remove/rename and pioctl paths for prefetch, store, path prefetch, no-cache fetch, invalidate, and Darwin move work.

Risks: The daemon loops are shutdown-state machines, so incorrect term-state sequencing can hang teardown. Background request lifetime is subtle: vnode and credential refs must pair exactly with release paths, and `BUVALID` waiters need both raw and checked errors. Queue fairness depends on `afs_brs_count` monotonic ordering and bounded `NBRS` capacity. `BPrefetch` assumes the wakeup dcache pointer remains valid until the request releases it. The main daemon performs many unrelated maintenance jobs while holding the global lock except where explicitly dropped, so long-running work can affect latency. Platform-specific AIX/SGI sections have independent locking and signal behavior and are easy to regress accidentally.

Test signals: Exercise root fid discovery with dynroot enabled, explicit root volume, readonly fallback, missing primary cell, and truncated root names. Queue multiple background requests and verify timestamp ordering, waiter wakeups, `dontwait` behavior, vnode/cred reference release, and raw/checkcode propagation for store failures. Test shutdown transitions through AFS, check-server, truncate, background, and RX callback states. Cover separate and non-separate check-server daemon modes, cache-bypass prefetch, Darwin `AFS_NEW_BKG` re-entry, and periodic maintenance hooks with mocked time.
