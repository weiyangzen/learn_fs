# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dir.h

This header defines the AFS3 directory layout and the Windows cache-manager directory-operation API. The file is explicit that these structures derive from `src/dir/dir.h` and describe wire/protocol layout, so structure sizes and field meanings are compatibility-sensitive. Key constants are `CM_DIR_PAGESIZE` at 2048 bytes, `CM_DIR_NHASHENT` at 128 hash buckets, old and big page limits, 64 entries per page, 32-byte entry chunks, and `CM_DIR_DHE`, the number of reserved chunks in the first page header.

Protocol structures include `cm_dirFid_t` for vnode/unique pairs, `cm_pageHeader_t` for per-page allocation metadata, `cm_dirHeader_t` for page-zero metadata including the allocation map and hash table, and `cm_dirEntry_t` for hash-chain entries with network-order fid values and a variable-length name. The unused `cm_dirXEntry_t`, `cm_dirPage0_t`, and `cm_dirPage1_t` document the physical page shapes but are compiled out. Directory entry flags `CM_DIR_FFIRST` and `CM_DIR_FNEXT` represent first/continuation chunks.

The operation wrapper types are local-cache specific. `cm_dirOpBuffer_t` tracks buffers participating in a transaction-like directory operation, including refcount and in-use flags. `cm_dirOp_t` holds lock type, scache/user/request ownership, the directory length and data versions captured at operation start, adjusted versions after accepted local changes, dirty buffer count, and a small fixed array of operation buffers. Lock constants distinguish no lock, read lock, and write lock; `CM_DIROP_FLAG_NOBUILDTREE` suppresses B+ tree construction for callers that need classic-buffer behavior only.

The exported API provides begin/end lifecycle, safety check for single-change local mutation, classic directory create/delete/make/lookup/apply/empty/length/hash functions, temporary name-list management, and stats dump hooks. `dir_enums` is exported for enumeration telemetry. Dependencies include `cm_scache_t`, `cm_buf_t`, `cm_user_t`, `cm_req_t`, `cm_fid_t`, `osi_hyper_t`, and the B+ directory layer through implementations. Risks are mostly ABI and contract risks: changing structure packing breaks directory compatibility, and callers must respect lock preconditions listed in `cm_dir.c`. Test signals include binary layout assumptions, compile integration with AFS directory consumers, and runtime local directory operations that span multiple buffers.
