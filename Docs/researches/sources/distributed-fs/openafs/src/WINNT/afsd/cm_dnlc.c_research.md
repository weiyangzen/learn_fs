# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dnlc.c

This file implements the directory name lookup cache (DNLC) for Windows OpenAFS. The DNLC maps a directory scache plus normalized name to a target scache, speeding pathname lookup before falling back to directory contents. Entries are not scache-refcounted while resident in the cache; lookup takes a hold only on the returned scache. The cache is fixed-size, stored under `cm_data` as an array of `cm_nc_t` entries plus a hash table and freelist, and protected by the global `cm_dnlcLock`.

Important functions are `cm_dnlcInit`, `cm_dnlcEnter`, `cm_dnlcLookup`, `cm_dnlcRemove`, `cm_dnlcPurgedp`, `cm_dnlcPurgevp`, `cm_dnlcPurge`, `cm_dnlcPurgeVol`, `cm_dnlcValidate`, and `cm_dnlcShutdown`. Internal helpers `GetMeAnEntry`, `InsertEntry`, and `RemoveEntry` manage freelist/hash movement. `cm_dnlcEnter` ignores disabled cache, null names, `.` and `..`, names exceeding `CM_AFSNCNAMESIZE`, and either updates an existing entry or evicts the oldest entry from a hash bucket. `cm_dnlcLookup` supports case-sensitive and case-folded search through `cm_lookupSearch_t`, filling exact/lowercase/uppercase/mixed-case match flags and fid fields before holding the target scache. Remove and purge variants clear by directory, target scache, or whole cache.

Control flow uses read locks for lookup and initial enter scans, converting to write when insertion is required. Hash buckets are circular doubly linked lists, with explicit safety counters to detect cycles. On structural anomalies, the code increments cycle stats and purges the whole cache to recover. Initialization reads `UseDNLC` and `DebugDNLC` from the OpenAFS client registry key, initializes the lock, and, for new cache files, lays out `nameCache`, `nameHash`, and `ncfreelist` inside the persistent `cm_data.dnlcBaseAddress` region.

State behavior is semi-persistent because the cache arrays live in `cm_data`, which is part of the cache manager's shared cache data, but entries are opportunistic and safely purgeable. Dependencies include normalized string helpers, scache magic validation, registry APIs, OSI locks/queues, and lookup search structures. Risks include stale unrefcounted scache pointers if purge hooks are missed, circular list corruption, fixed 40-character normalized-name limit, and global purge on volume-specific purge. Test signals include registry enable/disable, exact and case-folded lookup ambiguity flags, purge on scache recycle or directory callback loss, validation recovering from corrupted links, and lookup miss/enter/remove counters.
