# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dcache.h

This header declares the public data-cache interface used by the Windows OpenAFS cache manager and buffer package. Its central type is `cm_bulkIO_t`, a descriptor for one fetch or store operation over a list of held `cm_buf_t` buffers. The descriptor records the target scache, user and request pointers, starting offset, transfer length, reserved buffer count, and head/tail queue pointers. The queue ordering matters: the lowest offset buffer is at the end of the list, matching the scan and Rx streaming logic in `cm_dcache.c`.

The exported functions divide into initialization, buffer validity, fetch/store setup, background work, lifecycle, and verification. `cm_InitDCache` installs `cm_bufOps` into the buffer subsystem; `cm_ValidateDCache` delegates validation to the buffer package; `cm_ShutdownDCache` is the current shutdown hook. `cm_HaveBuffer` answers whether an existing buffer can satisfy a read based on callback and data-version state. `cm_GetBuffer` fetches cache-backed data into a `cm_buf_t`, while `cm_GetData` bypasses cache buffers and reads into caller memory. `cm_SetupFetchBIOD` and `cm_SetupStoreBIOD` prepare the buffer lists that the transfer routines consume, and `cm_ReleaseBIOD` unwinds SyncOp state, reservations, and buffer references after success or failure.

The header also exposes background-daemon rock structures. `rock_BkgFetch_t` carries a prefetch base and length to `cm_BkgPrefetch`; `rock_BkgStore_t` carries an async store offset and length to `cm_BkgStore`. `cm_ConsiderPrefetch` is the caller-facing trigger that decides whether to queue background fetch after a foreground read. `cm_BufWrite` is exported because it is both a buffer callback and reused by background store. `cm_StoreMini` supports metadata/truncate StoreData calls, and `cm_VerifyStoreData` supports optional read-back validation.

Dependencies are intentionally forward-declared against `cm_scache_t`, `cm_buf_t`, `cm_user_t`, `cm_req_t`, and `osi_hyper_t`, with concrete semantics implemented in `cm_dcache.c`. State and persistence are indirect: consumers must preserve the scache and user lifetimes promised by comments and must call `cm_ReleaseBIOD` for descriptors that hold buffers or reservations. Risks are API-contract risks: queue ordering, lock preconditions, and ownership are not enforced by the type system. Test signals are compile-time integration with `afsd.h`, buffer-operation registration, and runtime coverage of fetch/store setup followed by release on both success and failure.
