# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dcache.c

This file is the Windows cache manager data-cache implementation for OpenAFS file contents. It binds the generic buffer package to AFS FetchData/StoreData RPCs through `cm_bufOps`, manages bulk I/O descriptors for groups of cache buffers, implements background store and prefetch work, handles direct `cm_GetData` reads into caller memory, and optionally verifies stores by reading data back from the file server. It is a central integration point among `cm_buf`, `cm_scache`, Rx, file-server connection selection, callback/status merging, freelance-root data, redirector error reporting, and background daemon retry policy.

Important APIs are `cm_BufWrite`, `cm_StoreMini`, `cm_BufStabilize`, `cm_BufUnstabilize`, `cm_InitDCache`, `cm_HaveBuffer`, `cm_CheckFetchRange`, `cm_BkgStore`, `cm_BkgPrefetch`, `cm_ConsiderPrefetch`, `cm_SetupStoreBIOD`, `cm_SetupFetchBIOD`, `cm_ReleaseBIOD`, `cm_GetBuffer`, `cm_GetData`, and `cm_VerifyStoreData`. `cm_BufWrite` serializes StoreData operations with `CM_SCACHESYNC_STOREDATA_EXCL`, builds a `cm_bulkIO_t` over contiguous dirty buffers, selects 64-bit or legacy StoreData RPCs based on server capability and offsets, streams buffer data with Rx iovecs, merges returned status, clears dirty/write state via `cm_ReleaseBIOD`, and reports fatal write errors to the redirector. `cm_StoreMini` sends a zero-length StoreData for truncation and dirty metadata updates.

The fetch path is split between setup and transfer. `cm_SetupFetchBIOD` first ensures buffer objects exist without holding reservations, then tries to reserve a chunk and collects current-missing non-dirty buffers while setting fetch synchronization state. `cm_GetBuffer` handles already-current buffers, EOF/truncation zero-fill, freelance-root fake directory data, 64-bit FetchData fallback, old file-server offset bug mitigation, read-while-fetching wakeups, buffer data-version updates, and status merge. `cm_GetData` mirrors the RPC path without allocating cache buffers. Background prefetch scans for missing ranges, queues `cm_BkgPrefetch`, and updates `scp->prefetch` only for successfully fetched ranges. Background store marks async-store complete only for non-retryable results.

Persistent state is mostly in shared cache structures, not on disk in this file: `cm_scache_t` length/mask/flags/dataVersion/activeRPCs/prefetch, `cm_buf_t` dirty/error/dataVersion/cmFlags, reserved buffer counts, and optional disk-cache update hooks. Correctness depends on `scp->rw`, buffer mutexes, SyncOp flags, and strict lock dropping around Rx and buffer reservation. Risks include deadlock if buffer reservation or `buf_Get` is called with the wrong locks, stale cache use if data-version ranges are mishandled, 32-bit server fallback errors for large offsets, memory allocation failure in verification, and incorrect async retry classification. Test signals include StoreData/FetchData 64-bit fallback, EOF zero-fill, truncation, dirty contiguous buffer coalescing, redirector status on quota/space/noaccess failures, background prefetch wakeups, freelance root reads, and `buf_ValidateBuffers` / checksum verification paths.
