# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dns.c

This file implements DNS discovery of AFS database servers for the Windows cache manager. It supports two environments. On modern Windows with `DnsQuery` available (`DNSAPI_ENV`), it queries SRV records for `_<service>._<protocol>.<cell>` and falls back to AFSDB records. Without the DNS API, it contains a manual UDP DNS client that builds and parses DNS packets for AFSDB and A records using the structures in `cm_dns_private.h`. Public entry points are `cm_InitDNS`, `getAFSServer`, `getAFSServerW` under DNS API builds, `DNSlowerCase`, and legacy helper `putQName`; `cm_dns.h` also declares `DNSgetHostByName`, though this file does not define it in the visible build path.

Manual-DNS control flow reads a name-server address from `AFS_NS` or `afsdns.ini`, builds recursive queries with fixed IDs, encodes QNAMEs via `putQName`, sends UDP packets to port 53, receives into a 2048-byte buffer, parses compressed names, filters AFSDB class/preference 1, resolves returned hostnames to A records, and fills server address/name/port/rank arrays. DNS API control flow uses `DnsQuery_A` or `DnsQuery_W`, first for SRV, then AFSDB. For each server name it records priority/admin rank, network-byte-order port, TTL from the first record, and attempts to find or separately query matching A records, including simple CNAME-to-A matching. `Freelance.Local.Root` is intentionally excluded from DNS lookup.

State is minimal: static `dns_addr` for legacy UDP mode and static `cm_dnsEnabled` for initialization state. Results are caller-provided arrays with `numServers` and `ttl` out parameters. Integration points include cell configuration discovery in `cm_config`/ioctl paths, Windows DNS APIs, winsock, UTF-8/UTF-16 string comparison helpers, and `AFSMAXCELLHOSTS`/`MAXHOSTCHARS` limits from AFS headers. Ports are stored in network byte order; SRV uses the advertised port, while AFSDB uses the caller-provided fallback.

Risks include manual parser bounds assumptions, fixed 2048-byte packet buffer, fixed query IDs, lack of TCP fallback, partial CNAME handling when additional records are absent, output-array overflow if API results exceed caller limits in paths not checking every increment, and DNS API dependence hidden behind compile macros. The legacy `putQName` mutates its input by lowercasing it. Test signals include SRV success, SRV absent with AFSDB fallback, CNAME target resolution, no-address server names, TTL propagation, Unicode `getAFSServerW`, disabled DNS initialization, missing `AFS_NS`/INI behavior, and freelance-root rejection.
