# sources/distributed-fs/openafs/src/WINNT/afsd/cm_eacces.h

This header defines the EACCES cache entry type and API for the Windows OpenAFS cache manager. The cache records access-denied events by fid and user, with the parent fid included so the error can be invalidated when parent directory knowledge changes. The comments specify the intended lifecycle: entries are removed when the parent fid callback expires or is replaced, when the parent scache is recycled, or when the user's tokens expire or are replaced; recycling the denied fid's scache alone does not remove the entry.

`cm_eacces_t` contains a primary queue node, magic value, secondary queue nodes for parent and user indexes, the denied fid, parent fid, held user pointer, and error timestamp. `CM_EACCES_MAGIC` is used for validation/debugging. The `parentq_to_cm_eacces_t` and `userq_to_cm_eacces_t` macros recover the containing entry from embedded queue nodes using `offsetof`. Hash macros compute fid, parent, and user buckets with `opr_jhash` and table-size masks; their table-size symbols are defined in the C file.

The exported API initializes the cache, finds an entry by `(user,fid)`, adds or refreshes an entry with parent fid, clears entries for a parent fid, clears entries for a user and optional cell, and clears outdated entries. The API returns a raw pointer from find and a numeric status from add, with invalidation handled by explicit clear calls from callback/token paths.

Dependencies include `osi.h`, `cm_scache.h`, `cm_fid_t`, `cm_user_t`, queue layout, and jhash availability. There is no durable persistence; this is a runtime advisory cache. Risks are macro coupling to static table-size variables, power-of-two table-size assumptions, raw pointer lifetime after find, and the need for every relevant callback/token transition to call the appropriate clear routine. Test signals include compilation of container macros, add/find/clear behavior under multiple parents and users, and expiration after the configured time window in the implementation.
