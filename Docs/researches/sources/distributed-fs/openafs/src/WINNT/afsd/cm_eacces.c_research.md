# sources/distributed-fs/openafs/src/WINNT/afsd/cm_eacces.c

This file implements a small cache of `EACCES` outcomes keyed by user and fid, with secondary indexes by parent fid and user. The purpose is to remember access-denied events so later path handling can distinguish authorization problems from missing objects and clear those remembered failures when relevant parent callbacks or user tokens change. Entries store the denied fid, parent fid, user pointer, and timestamp. They are heap allocated, recycled through a freelist, and protected by `cm_eaccesLock`.

Public APIs are `cm_EAccesInitCache`, `cm_EAccesAddEntry`, `cm_EAccesFindEntry`, `cm_EAccesClearParentEntries`, `cm_EAccesClearUserEntries`, and `cm_EAccesClearOutdatedEntries`. Initialization uses `osi_once_t` for lock setup, then allocates head/tail arrays for fid, parent, and user hash tables. Table sizes are derived from `cm_data.stats * 2` for fid and parent indexes and fixed at 32 for user indexes. Add first searches the fid hash for an existing `(userp,fid)` entry, allocates or reuses an entry if absent, holds the user, adds it to fid and user indexes, updates `errorTime`, removes the old parent index if the parent changes, and inserts into the new parent index.

Find scans the fid hash and returns a raw entry pointer without taking an additional reference, so callers must treat it as protected only by cache lifetime and invalidation discipline. Clear-by-parent removes all entries whose parent matches a callback/recycle event, unlinking from all three indexes, releasing the held user, and moving entries to the freelist. Clear-by-user removes entries for a user, optionally limited by cell ID, and is used when tokens expire or are replaced. Clear-outdated removes entries older than four hours.

State is process memory only and can be rebuilt from future errors. Dependencies include OSI queues, `opr_jhash`, fid comparison, user hold/release, `cm_data.stats`, and lock hierarchy constants. A notable risk is that several mutation routines obtain a read lock while removing from queues; correctness depends on the OSI lock semantics or is a potential concurrency defect if read locks permit concurrent readers/writers. Other risks include allocation failures not checked during initialization/add, hash macros relying on power-of-two table sizes, raw pointer returns from find, and stale entries if invalidation hooks are missed. Test signals include add/find for same user/fid, parent change reindexing, parent callback clearing, token/cell clearing, four-hour expiry, freelist reuse, and concurrent lookup during clearing.
