# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dns.h

This header declares the public DNS lookup interface used by the Windows OpenAFS cache manager to discover AFS cell servers. It defines `DNS_PORT` as 53 and exposes ANSI and Unicode server-discovery functions. The ANSI `getAFSServer` takes service, protocol, cell name, default AFSDB port, output arrays for IPv4 addresses, hostnames, ports, ranks, server count, and TTL. The Unicode `getAFSServerW` mirrors that contract with `cm_unichar_t` hostnames and is only implemented when the Windows DNS API environment is available.

The output contract is important. `cellHostAddrs` receives IPv4 addresses when resolvable, but DNS SRV or AFSDB discovery may still produce names with address zero if A record resolution fails. `cellHostNames` is bounded by `MAXHOSTCHARS`, ports are in network byte order, ranks reflect SRV priority or zero for AFSDB fallback, and `ttl` captures the DNS TTL used by higher-level configuration caching. The caller provides `afsdbPort` so AFSDB records can be mapped to the correct VLDB service port.

`DNSgetHostByName` is declared as a supplement for older resolver environments that did not call DNS for `gethostbyname`; it is not implemented in `cm_dns.c` on the modern DNS API path, so consumers must be conditioned by platform/build expectations. Dependencies include `cm_unichar_t`, `afs_uint32`, `MAXHOSTCHARS`, and the surrounding AFS cell configuration headers.

This file does not persist state. Its integration role is to decouple cell discovery callers from the implementation choice of Windows `DnsQuery` versus legacy packet code. Risks are header/implementation signature drift: the header uses `afs_uint32 *cellHostAddrs`, while the C implementation's visible signature uses `int *` for the same array, relying on compatible 32-bit representation. Test signals include successful compilation across DNS API and non-DNS API builds, correct network-byte-order ports, and callers handling zero returned servers with `-1`.
