# sources/distributed-fs/openafs/src/WINNT/afsd/cm_dnlc.h

This header defines the directory name lookup cache data structures and public API. The cache is deliberately small and fixed-size: `NCSIZE` is 512 entries and `NHSIZE` is 256 hash buckets. `CM_AFSNCNAMESIZE` limits cached normalized names to 40 `normchar_t` values, chosen as a multiple of eight for 64-bit alignment. `CM_DNLC_MAGIC` tags entries so `cm_dnlcValidate` can detect corruption or stale memory.

`cm_nc_t` is the cache entry. It contains a magic value, precomputed hash key, circular-list links, directory scache pointer, target scache pointer, and normalized name. Entries in active hash buckets use `next` and `prev` as circular doubly linked list links; entries on the freelist are identified by null `prev`. `cm_dnlcstats_t` collects operational counters for enters, lookups, misses, removes, purges, cycle detection, and lookup races. The `dnlcHash` macro hashes normalized names case-insensitively by uppercasing each normalized character and applying the AFS directory hash multiplier of 173.

The exported functions support insert, remove by directory/name, purge by directory, purge by target vnode, whole-cache purge, volume purge, initialization, shutdown, lookup, and validation. `cm_dnlcLookup` takes a `cm_lookupSearch_t` because it needs to report more than a boolean hit: exact and case-folded match classifications feed Windows pathname semantics and ambiguous-name handling. Initialization and storage are implemented in `cm_dnlc.c`; this header exposes the shape because the cache arrays are part of broader cache-manager shared state.

Dependencies include `cm_scache_t`, `cm_lookupSearch_t`, `AFSFid`, `normchar_t`, and normalized string helpers from the surrounding afsd code. There is no durable correctness requirement for DNLC contents; it is an opportunistic accelerator and must be purgeable at any time. Risks are compile-time ABI coupling to `cm_data` layout, stale pointer exposure if callers forget purge hooks, and hash macro side effects because it advances the `ts` pointer. Test signals include cache hit/miss behavior for exact and case-insensitive names, long-name bypass, purge functions, and validation of magic/list invariants.
