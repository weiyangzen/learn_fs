# sources/distributed-fs/openafs/src/WINNT/afsrdr/kernel/lib/AFSFileInfo.cpp

## Purpose
Implements the Windows kernel redirector handlers for `IRP_MJ_QUERY_INFORMATION` and `IRP_MJ_SET_INFORMATION` on OpenAFS file objects. The file translates Windows `FILE_INFORMATION_CLASS` requests into cached AFS metadata reads, local FCB/CCB/directory-entry state updates, cache-manager interactions, redirector service notifications, and filesystem-change notifications. It also handles special share pipe information and pseudo-IOCTL file query behavior.

## Important APIs, Types, and Functions
Top-level dispatch functions are `AFSQueryFileInfo` and `AFSSetFileInfo`. Query fan-out covers `AFSQueryBasicInfo`, `AFSQueryStandardInfo`, `AFSQueryInternalInfo`, `AFSQueryEaInfo`, `AFSQueryPositionInfo`, `AFSQueryNameInfo`, `AFSQueryShortNameInfo`, `AFSQueryNetworkInfo`, `AFSQueryStreamInfo`, `AFSQueryAttribTagInfo`, `AFSQueryRemoteProtocolInfo`, and `AFSQueryPhysicalNameInfo`. Setter fan-out covers `AFSSetBasicInfo`, `AFSSetDispositionInfo`, `AFSSetFileLinkInfo`, `AFSSetRenameInfo`, `AFSSetPositionInfo`, `AFSSetAllocationInfo`, and `AFSSetEndOfFileInfo`. Special-node helpers are `AFSProcessShareSetInfo`, `AFSProcessShareQueryInfo`, and `AFSProcessPIOCtlQueryInfo`.

The code is built around redirector-private objects from `AFSCommon.h`: `AFSFcb`, `AFSNonPagedFcb`, `AFSCcb`, `AFSDirectoryCB`, `AFSObjectInfoCB`, `AFSDeviceExt`, `AFSFileID`, and `AFSFileInfoCB`. It consumes Windows kernel structures such as `IRP`, `IO_STACK_LOCATION`, `FILE_BASIC_INFORMATION`, `FILE_STANDARD_INFORMATION`, `FILE_ALL_INFORMATION`, `FILE_RENAME_INFORMATION`, `FILE_LINK_INFORMATION`, `FILE_NETWORK_OPEN_INFORMATION`, `FILE_STREAM_INFORMATION`, `FILE_ATTRIBUTE_TAG_INFORMATION`, `FILE_REMOTE_PROTOCOL_INFORMATION`, `FILE_NETWORK_PHYSICAL_NAME_INFORMATION`, and `FILE_END_OF_FILE_INFORMATION`.

## Control Flow
`AFSQueryFileInfo` obtains `FsContext` and `FsContext2`, rejects a null FCB, resolves request length/class/buffer, and verifies stale object state when `AFS_OBJECT_FLAGS_VERIFY` is set by retrieving the caller auth group and calling `AFSVerifyEntry`. It then acquires the FCB main resource shared. Special-share FCBs are forwarded to `AFSProcessShareQueryInfo`; PIOCtl FCBs are forwarded to `AFSProcessPIOCtlQueryInfo`; invalid FCBs return access denied. Normal objects switch on `FileInformationClass`, fill one specific structure, or build `FileAllInformation` by invoking the individual query helpers in Windows structure order while manually skipping fields that the I/O manager pre-populates. On exit, `IoStatus.Information` is derived from the original length minus remaining length, the FCB resource is released, failures are traced, and `AFSCompleteRequest` completes the IRP.

The query helpers are mostly bounded buffer writers. Basic, standard, network-open, and attribute-tag queries derive times, allocation size, EOF, attributes, directory status, and reparse tags from `DirectoryCB->ObjectInformation`. For symlink objects, they deliberately release the FCB resource before `AFSRetrieveFileAttributes` to avoid lock inversion while resolving target attributes, then reacquire it shared. The symlink is always reported as a reparse point, and the directory bit is added if the resolved target is a directory. Dot-name hiding is applied when `AFS_DEVICE_FLAG_HIDE_DOT_NAMES` is set. Name and physical-name queries delegate to `AFSGetFullFileName`. Alternate-name returns the short name when present, or the long component otherwise. Stream info exposes only the unnamed `::$DATA` stream for non-directories. Remote protocol info reports OpenAFS protocol identity.

`AFSSetFileInfo` obtains the file object, FCB, and CCB, rejects a null FCB, computes whether an async queue would be possible, then acquires the FCB resource exclusive. PIOCtl FCBs are rejected, special-share FCBs are forwarded to `AFSProcessShareSetInfo`, read-only volumes reject all set classes except current-position changes, and invalid FCBs are accepted only for disposition. Rename is forced synchronous by clearing the queue path. The function snapshots the parent FID, switches on the set class, releases the FCB resource, then, if `AFSSetBasicInfo` marked metadata dirty, calls `AFSUpdateFileInformation` to persist local metadata changes to the service. If that service update fails, it reacquires the FCB, calls `AFSUnwindFileInfo`, and fails the request.

`AFSSetBasicInfo` updates read-only attributes and selected file times in `DirectoryCB->ObjectInformation`, storing old values into `Ccb->FileUnwindInfo` for rollback. It rejects attempts to newly set `FILE_ATTRIBUTE_REPARSE_POINT` or `FILE_ATTRIBUTE_DIRECTORY`; those attributes may only be preserved. It sets FCB update flags such as `AFS_FCB_FLAG_UPDATE_CREATE_TIME`, `AFS_FCB_FLAG_UPDATE_ACCESS_TIME`, `AFS_FCB_FLAG_UPDATE_LAST_WRITE_TIME`, and `AFS_FCB_FLAG_UPDATE_CHANGE_TIME`, records `CCB_FLAG_LAST_WRITE_TIME_SET` for explicit or preserve-last-write requests, and reports parent directory notifications through `AFSFsRtlNotifyFullReportChange`.

`AFSSetDispositionInfo` implements delete-pending state. It blocks root deletion and read-only-object deletion, calls `AFSNotifyDelete` for authorization/service validation, and for directories checks open child counts, forces enumeration if needed, and requires `AFSIsDirectoryEmptyForDelete`. File deletion acquires the FCB resource and section-object resource, calls `MmFlushImageSection(MmFlushForDelete)`, sets `AFS_DIR_ENTRY_PENDING_DELETE`, purges the cache section if possible, and sets `AFS_FCB_FLAG_PURGE_ON_CLOSE` if purge cannot complete. Symlinks, mount points, DFS links, and invalid FCBs only mark the directory entry pending delete. Clearing disposition clears the pending-delete flag. The Windows `FileObject->DeletePending` flag mirrors the requested delete state.

`AFSSetFileLinkInfo` handles hard-link creation and replacement. It resolves the source parent object, requires the source to be a file, limits handle-less target paths to the same directory, rejects alternate-directory handle cases that would violate AFS hard-link support, and rejects cross-volume hard links. It looks up the target by case-sensitive CRC, case-insensitive CRC, and optional short name. A case-insensitive ambiguity returns `STATUS_OBJECT_NAME_COLLISION`. Existing targets are reference-counted, optionally rejected when `ReplaceIfExists` is false, and temporarily removed from the parent tree. The service call is `AFSNotifyHardLink`, which may return a new target directory entry; successful non-reparse results are inserted into the target directory tree. Failure reinserts any removed target and drops directory-entry references.

`AFSSetRenameInfo` handles same-directory renames and some cross-directory moves within the same volume. It rejects root renames, directories with open children, malformed handle-based targets, explicit alternate path moves that are not represented by a target file object, and cross-volume targets. It acquires target and source directory tree locks, looks up target collisions across case-sensitive, case-insensitive, and optional short-name indexes, rejects read-only or open replacement targets under `ObjectInfoLock`, and honors `ReplaceIfExists`. The source directory entry is removed from its parent, `AFSNotifyRename` is sent to the service, and on success the directory entry name, CRC hash indexes, optional short-name hash, file index, parent FID, parent child-open counts, and object-info hash entry are updated before reinsertion. It emits old-name/removed and new-name/added notifications. If a replacement target existed, it is marked deleted, dereferenced, possibly freed, and for open cached files `MmForceSectionClosed` is invoked after dropping tree locks to avoid known filter-manager deadlocks.

`AFSSetAllocationInfo` and `AFSSetEndOfFileInfo` change sizes. Both snapshot existing allocation, file size, and valid-data length for rollback. Truncation first checks mappings under `SectionObjectResource` using `MmCanFileBeTruncated`; user-mapped files return `STATUS_USER_MAPPED_FILE`. Size mutation is performed while holding `PagingResource` and after temporarily releasing the main FCB resource because setting file sizes can recurse through filters. Allocation shrink can also shrink EOF and require a service update. EOF change always calls `AFSUpdateFileInformation` when modified. On success, the code updates cache-manager file sizes with `CcSetFileSizes`, trims extents after truncation through `AFSTrimExtents`, updates change time and FCB flags, and marks `FO_FILE_MODIFIED`; on failure, it restores prior FCB and object-info sizes. `AFSSetPositionInfo` only copies `CurrentByteOffset` to the file object.

Special-share set/query handlers lock the IRP system buffer and forward opaque pipe information to service notifications `AFSNotifySetPipeInfo` and `AFSNotifyQueryPipeInfo`. PIOCtl query support returns synthetic hidden/system basic info, zero-length standard info, zero internal index, and a `\\<AFSServerName><FullFileName>` name for name queries; most other classes are explicitly invalid.

## State and Persistence Behavior
Persistent filesystem state is owned by the AFS service/server and is changed through notification/update calls: `AFSUpdateFileInformation`, `AFSNotifyDelete`, `AFSNotifyHardLink`, `AFSNotifyRename`, `AFSNotifySetPipeInfo`, and `AFSNotifyQueryPipeInfo`. Local kernel state is updated immediately in FCB headers, object-info fields, directory-entry trees, reference counts, name buffers, file indexes, object-info hash tables, CCB unwind fields, and file-object flags. The code carefully tracks whether a remote update is still needed (`bUpdateFileInfo`, `bTellService`, `bModified`) and restores local size/basic-info state if the service rejects an update.

Cache and memory-manager state are also part of the persistence contract. Delete, rename-replace, allocation, and EOF paths interact with `CcPurgeCacheSection`, `CcSetFileSizes`, `MmFlushImageSection`, `MmCanFileBeTruncated`, and `MmForceSectionClosed`. Extent cache state is trimmed when truncation is accepted. Directory change state is pushed to watchers with `AFSFsRtlNotifyFullReportChange`. `Irp->IoStatus.Information` is consistently populated for query results based on consumed buffer length, including partial-copy overflow cases in name, short-name, stream, and PIOCtl name queries.

## Dependencies and Integration Points
The file depends on the Windows kernel I/O manager, cache manager, memory manager, FsRtl notification APIs, `ERESOURCE` locking, structured exception handling, and OpenAFS redirector helpers declared by `AFSCommon.h`. Major OpenAFS integration points include authentication group retrieval, stale-entry verification, path/name helpers, directory enumeration and tree operations, object-info hash operations, file-info rollback/update, service notification calls, extent trimming, and debug tracing.

This file is reached from the redirector dispatch table for file information IRPs. It must cooperate with create/cleanup/close paths through shared FCB/CCB fields, with read/write paths through header sizes and extent state, with directory enumeration through directory-entry trees and content indexes, with reparse/symlink behavior through reported attributes and tags, and with the service process through synchronous notification calls.

## Risks and Edge Cases
The largest risks are lock ordering and partial local mutation before service failure. Several paths intentionally release the main FCB resource around symlink target lookup, cache-manager size updates, and memory-manager section closure; regressions here can recreate deadlocks with filter drivers or recursive cleanup. Rename and hard-link handling mutate directory trees before service calls complete and rely on reinsertion/error unwinds; missed reference-count or tree-lock paths could corrupt directory indexes. Replacement rename has especially complex state because target entries can be removed, marked deleted, dereferenced, cache-closed, or restored on failure.

Buffer accounting is another risk. Many helpers zero the full caller-supplied length, then subtract structure and copied-name lengths; overflow returns must preserve correct `FileNameLength` or `StreamNameLength` while `IoStatus.Information` reflects the bytes actually written. Query helper calls that release and reacquire the FCB assume the original top-level lock mode is compatible; `FileAllInformation` invokes multiple helpers against the same shrinking length and depends on the exact structure order.

Metadata semantics have Windows compatibility edge cases: directory and reparse attributes cannot be newly set, delete of a directory requires forced enumeration, read-only volume rules exempt only position changes, short-name collision handling changes when short names are disabled, and hard links are restricted more tightly than generic NTFS semantics. There is also a visible probable defect in `AFSSetFileLinkInfo`: `uniSourceName` is declared and used in the self-link comparison but is not populated like the rename path does, making same-name hard-link detection suspect.

Exception handling catches memory/cache-manager faults in top-level dispatch, truncation checks, image flushes, and section closure, but many tree and notification helpers are assumed not to throw. Service update failure after a local basic-info mutation relies on `AFSUnwindFileInfo`; other operations may not have equally complete rollback after partially successful remote/local changes.

## Test Signals
Useful query tests cover each supported `FILE_INFORMATION_CLASS`, short buffers for name/short-name/stream/all-information paths, dot-name hidden behavior, symlink and mount-point attributes and reparse tags, directories versus files for stream information, PIOCtl synthetic info, and special-share pipe query passthrough. Stale-object verification should be tested both when `AFSVerifyEntry` succeeds and when it fails but query still proceeds.

Setter tests should cover read-only volume rejection, invalid/PIOCtl/special-share node behavior, basic-info time and read-only changes including rollback on `AFSUpdateFileInformation` failure, explicit `-1` last-write preservation, root/read-only/delete-pending deletion behavior, non-empty and unenumerated directory delete checks, mapped-file delete/truncate rejection, cache purge failure setting `AFS_FCB_FLAG_PURGE_ON_CLOSE`, hard-link collision/replace/cross-volume restrictions, rename same-name no-op, rename replacement of open/read-only targets, cross-directory same-volume moves, object-info FID hash changes after service-assigned FIDs, EOF/allocation grow and shrink with cache-size updates, extent trim on truncation, and notification actions for modified/added/removed/renamed entries. Kernel stress tests should include concurrent opens, cleanup during rename replacement, short-name collisions, and filter-driver recursion around `CcSetFileSizes` and `MmForceSectionClosed`.
