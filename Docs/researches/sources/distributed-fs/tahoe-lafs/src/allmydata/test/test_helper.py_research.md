# sources/distributed-fs/tahoe-lafs/src/allmydata/test/test_helper.py

Purpose: tests assisted CHK upload through Tahoe's offloaded helper and the helper's pre-upload checker/UEB fetcher. It verifies helper discovery, concurrent uploads, cleanup after successful or failed assisted uploads, no-push behavior when enough shares already exist, and detection of existing shares plus URI extension blocks on storage peers.

Important APIs and types include `CHKUploadHelper_fake`, `FakeCHKCheckerAndUEBFetcher`, `FakeClient`, `make_uploader`, `upload_data`, `flush_but_dont_ignore`, `wait_a_few_turns`, `AssistedUpload`, `CHKCheckerAndUEBFetcherTests`, `write_bad_share`, `write_good_share`, and `write_share`. The implementation under test includes `offloaded.Helper`, `offloaded.CHKUploadHelper`, `offloaded.CHKCheckerAndUEBFetcher`, `upload.Uploader`, `upload.Data`, `UploadResults`, storage server wrappers, and immutable layout write-bucket proxies.

Control flow sets up a Foolscap `Tub`, fake client service, storage broker, secret holder, and helper reference. Assisted upload tests wait for helper connection, upload CHK data via the helper URL, inspect resulting CHK URI/results, and assert `CHK_encoding` and `CHK_incoming` directories are empty after completion. The previous-failure test precomputes a convergence key/storage index, writes an encrypted intermediate file into `CHK_encoding`, and then checks a later upload succeeds and cleans up. The already-uploaded test injects a fake checker returning enough existing shares and UEB data so the helper returns a CHK result with zero pushed shares.

State and persistence include helper working directories, intermediate `CHK_encoding`/`CHK_incoming` artifacts, local Foolscap service state, storage broker state, fake storage server directories, allocated bucket data, and packed UEB blocks written into share data. Cleanup is part of the contract: assisted upload must not leave stale intermediate files that poison later attempts.

Dependencies include Twisted Deferreds, Trial, `MultiService`, Foolscap `Tub` and eventual queue utilities, Eliot `inline_callbacks`, attrs, AES encryption, Tahoe storage server/client/broker classes, immutable layout `make_write_bucket_proxy`, offloaded helper/upload modules, URI packing, hash/math/file/dict utilities, no-network wrappers, and testtools matchers.

Risks covered include helper reference not becoming available before upload, concurrent identical uploads diverging, failed upload intermediates blocking retries, uploaded-already path still pushing shares, bad or missing UEBs being treated as successful, too few existing shares satisfying a check, and share/UEB parsing through storage server remote references. Residual risk is that `CHKUploadHelper_fake` lies about pushing shares, so end-to-end network upload throughput and storage allocation are covered elsewhere.

Test signals include CHK URI bytes in upload results, nonzero pushed shares for fake successful upload, identical URIs for concurrent uploads, empty helper work directories after success/retry/already-uploaded paths, zero pushed shares for enough existing shares, `CHKCheckerAndUEBFetcher.check()` returning `False` for no peers/bad UEB/not enough shares, and returning a sharemap, UEB dictionary, and bytes UEB hash when enough valid shares exist.
