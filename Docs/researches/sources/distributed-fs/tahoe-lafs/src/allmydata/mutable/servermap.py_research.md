# sources/distributed-fs/tahoe-lafs/src/allmydata/mutable/servermap.py

Purpose: Maintains and updates the map of mutable shares across storage servers. The map records which server holds which share of which mutable version, distinguishes recoverable and unrecoverable versions, tracks bad shares and server reachability, caches layout read proxies, and drives query policies for read, write, check, and repair modes.

Important APIs and types: `UpdateStatus` implements `IServermapUpdaterStatus` and records mode, storage index, status/progress, finish time, per-server timings, private-key source, and problems. `ServerMap` provides mutation and query APIs such as `mark_server_reachable`, `mark_server_unreachable`, `mark_bad_share`, `add_new_share`, `get_known_shares`, `make_sharemap`, `make_versionmap`, `shares_available`, `highest_seqnum`, `recoverable_versions`, `unrecoverable_versions`, `best_recoverable_version`, `unrecoverable_newer_versions`, `needs_merge`, `version_on_server`, and update-data getters/setters. `ServermapUpdater` is the active scanner with `update`, `_build_initial_querylist`, `_send_initial_requests`, `_do_query`, `_do_read`, `_got_results`, `_got_signature_one_share`, `_check_for_done`, `_send_more_queries`, `_done`, and error/corruption/private-key helper methods.

Control flow: A `ServermapUpdater` starts with a filenode, storage broker, monitor, existing servermap, mode, lease flag, and optional update range. `update` chooses a query strategy: check/repair query all servers; write queries enough servers to discover all existing shares plus an epsilon boundary of empty servers; read/anything starts with existing servers plus a k+epsilon sample. `_do_query` asks each storage server for an initial read vector, optionally adds a lease in parallel, and routes responses to `_got_results`. For each returned share, `_got_results` builds an `MDMFSlotReadProxy` over the prefetched bytes, fetches or validates the public key, obtains verinfo and signature, optionally fetches/validates the encrypted private key, optionally fetches blockhash and boundary segment data for update, caches the proxy, validates the signature once per version, and adds valid shares to the servermap. `_check_for_done` is the state machine that decides whether enough evidence has been gathered for the current mode or whether more servers should be queried.

State and persistence: `ServerMap` is an in-memory authority passed between map update, retrieve, publish, and repair operations. `_known_shares` maps `(server, shnum)` to `(verinfo, timestamp)`, `_bad_shares` maps bad `(server, shnum)` to old checkstrings for repair test vectors, reachability sets track query outcomes, `proxies` caches read proxies keyed by version/server/storage index/share, and `update_data` stores block hash trees plus boundary segment data for partial updates. The updater mutates these fields and finalizes `_last_update_mode`/time on completion. Persistent effects are limited to optional lease addition and best-effort corrupt-share notifications to storage servers; the share map itself is local operation state.

Dependencies and integration points: The servermap layer depends on storage broker permutation via `get_servers_for_psi`, storage-server `slot_readv` and `add_lease`, layout `MDMFSlotReadProxy`, RSA signature verification, Tahoe hash utilities, `DictOfSets`, Foolscap remote failure types, mutable mode constants, private-key decryption, and corruption exceptions. It feeds `Publish` with known/bad shares and update data, feeds `Retrieve` with version/share placement and cached readers, and feeds `Repairer` with recoverability and merge/loss policy signals.

Risks: Completion policies are heuristic outside check/repair modes; read mode may stop after k+epsilon evidence when no newer unrecoverable version is visible, while write mode searches for an epsilon empty-server boundary rather than exhaustively querying. Query state is complex (`_must_query`, outstanding queries, extra servers, empty/good/bad/server-with-shares sets), so missed state transitions can hang or finish early. A corrupt share marks the whole server bad for counting in the updater, even if other shares might be valid. `_make_verinfo_hashable` serializes offset dictionaries using current item order; equality should remain stable for dicts built consistently, but order-sensitive tuples are a subtle contract. Private-key validation is synchronous CPU/crypto work in the callback path. The map is mutable and copied shallowly for some fields, so callers must avoid concurrent mutation after an updater finishes.

Test signals: Tests should cover `ServerMap` recoverability calculations, highest sequence selection, merge detection, unrecoverable-newer-version detection, bad-share removal, copy behavior, update-data storage, and version summaries. Updater tests should cover all modes (`MODE_READ`, `MODE_WRITE`, `MODE_CHECK`, `MODE_REPAIR`, `MODE_ANYTHING`), initial query-list construction, must-query behavior, no-server short circuit, additional query scheduling, lease failure tolerance, pubkey fingerprint mismatch, bad signature/corrupt share reporting, privkey validation, cached proxy insertion, update-range data fetching, read-mode newer-unrecoverable search, write-mode boundary detection, and fatal error propagation.
