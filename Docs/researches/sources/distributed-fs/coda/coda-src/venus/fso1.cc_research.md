# sources/distributed-fs/coda/coda-src/venus/fso1.cc

Purpose: implements most `fsobj` lifecycle, status, rights, mount, priority, binding, data-discard, fake-object, synchronization, reporting, VASTRO selection, shadow-copy, ASR, and iterator behavior. Where `fso0.cc` manages the FSDB, this file defines how one cached filesystem object is allocated, recovered, invalidated, locked, prioritized, linked into directories/volumes, and made safe for replacement.

Important APIs and flow: custom `fsobj::operator new` allocates either new RVM storage or an object from the FSDB freelist. Constructors initialize preallocated slots or active objects; `ResetPersistent` clears recoverable object state, while `ResetTransient` rebuilds volume links, queue handles, locks/counters, replacement state, and bindings. `Recover` validates persistent state at startup, discards runts, queues dying objects, unmounts stale mount points, rebuilds priority, discards garbage from interrupted fetches, backs up unsafe open-for-write files into `SpoolDir`, drops invalid backup/non-root objects, and reconciles cache-file validity by type. `Matriculate`, `Demote`, `Kill`, `GC`, and `Flush` define the state transitions from runt to normal to dying/free-list return.

Status and access APIs include `UpdateStatus`, `StatusEq`, `ReplaceStatus`, replica-control rights (`SetRcRights`, `ClearRcRights`, `IsValid`), ACL cache handling (`CheckAcRights`, `SetAcRights`, `DemoteAcRights`, `PromoteAcRights`, `ClearAcRights`), `SetParent`, `MakeDirty`, and `MakeClean`. Mount support is handled by `TryToCover`, `CoverMtPt`, `UncoverMtPt`, `MountRoot`, and `UnmountRoot`, parsing `#`, `@`, and `$` mountlink formats and wiring mount points to volume roots. Parent/child and hoard bindings are maintained through `AttachChild`, `DetachChild`, `AttachHdbBinding`, `DetachHdbBinding`, and demotion helpers. CML dirty bindings are managed with `AttachMleBinding` and `DetachMleBinding`.

State and persistence: core persistent state includes fid, component, state, `VenusStat`, access rights, flags, parent fid, clean stat, shadow pointer, data descriptors, and the embedded `CacheFile`. Transient state includes volume pointers, linked-list handles, priority queue membership, mount union pointers, parent/child backpointers, locks and active counts, HDB/CML binding lists, active VASTRO segments, and ASR timestamps. `DiscardData` and `DiscardPartialData` update disk accounting and free file, directory, or symlink storage; VASTRO-active files preserve active ranges by extracting them to a `SegmentedCacheFile`, truncating, and injecting the ranges back.

Dependencies and integration points: depends on `FSDB`, `VDB`, `REALMDB`, `repvol`/`reintvol` volume behavior, `CacheFile`/`SegmentedCacheFile`, CML entries, hoard `namectxt` bindings, directory helpers, kernel purge functions, user tokens, server bandwidth/fetch-partial capability, RPC connection management, and ASR launcher configuration. `UpdateVastroFlag` integrates object size, free blocks, server partial-fetch support, bandwidth, and configured whole-file limits to decide whether the embedded cache file should switch into partial-cache mode.

Risks and test signals: risks include RVM/VM state mismatch during recovery, failure to detach all bindings before destruction, parent-child cycles or stale `pfso`, replacement queue corruption, mountpoint recursion and cross-realm rules, access-right promotion after token expiry, dirty-state/CML imbalance, VASTRO partial-data preservation under concurrent reads, shadow refcount leaks, and ASR token/process-group setup. Tests should exercise restart recovery for runt/fetching/owrite objects, mount/unmount/remount paths, callback demotion of hoard bindings, CML dirty attach/detach, lock promote/demote with waiters, `GetVattr` while writing, fake root/repair object creation, VASTRO threshold decisions, partial-data discard preserving active segments, and ASR launch failure cleanup.
