# sources/distributed-fs/lustre-release/lustre/mdt/mdt_handler.c

## Purpose

`mdt_handler.c` is the central Lustre Metadata Target (MDT) kernel module glue layer. It wires MDS/MDT, LDLM, OST-style Data-on-MDT, security, quota, LLOG, FLD, SEQ, LFSCK, and HSM RPC opcodes into target handlers; manages MDT device startup and shutdown; allocates MDT object slices; constructs and saves LDLM locks; packs metadata replies; handles connect/reconnect/export teardown; and implements miscellaneous service helpers such as root lookup, `statfs`, `fid2path`, sync, and ioctl forwarding.

The file does not own most filesystem semantics directly. Instead, it brokers between PTLRPC request capsules, MDT per-thread state, LDLM namespace operations, and lower MDD/OSD `md_ops`, `mo_*`, and `dt_*` methods. Its main responsibility is correctness at protocol, locking, replay, and lifecycle boundaries.

## Control Flow

Incoming RPCs enter through target handler slices registered in `mdt_common_slice[]`. The target layer chooses a `struct tgt_handler`, unpacks request fields through `req_capsule`, and frequently calls `tsi2mdt_info()` to initialize `struct mdt_thread_info` from the current session. `mdt_body_unpack()` attaches the request `mdt_body` and, when a FID is supplied, resolves it to an `mdt_object`. Handlers that need replies pre-size variable buffers, pack the server capsule, then call lower-level helpers. Every normal path must call `mdt_thread_info_fini()` to drop object references and validate that lock handles have been released or saved.

`mdt_get_root()` validates credentials and nodemap mount permissions, optionally resolves a nodemap/fileset root by walking path components with `mdo_lookup()`, enforces read-only filesets against connection flags, then returns the root FID and stores it in the export. `mdt_statfs()` uses a short-lived statfs cache, optionally asks the MDD layer for aggregate/summed statfs data, adjusts available space for dirty and pending grants, handles no-create state, and rewrites large block sizes for old clients without grant-parameter support.

The getattr path is split between object-by-FID and name lookup variants. `mdt_getattr()` estimates reply EA size from symlink, root default EA, or actual xattr length; packs reply buffers; initializes credentials; and calls `mdt_getattr_internal()`. That helper reads inode state, LOV/LMV/default LMV, SOM, HSM, parent FID, and ACL data as requested; packs nodemap-translated IDs; handles released HSM file size, lazy SOM size, DoM size with a DOM lock, symlink bodies, ACLs, fscrypt metadata visibility, layout-generation compatibility for old clients, and directory auto-split/restripe scheduling. `mdt_getattr_name_lock()` adds lookup semantics: it may lock a local parent with a PDO lock, perform `mdo_lookup()`, validate encrypted-name hash lookups through LinkEA, handle cross-MDT references, grant child locks for intent replies, optionally try UPDATE/LAYOUT/DOM bits, and carefully release parent/child references on negative or remote cases.

Modify RPCs flow through `mdt_reint()`. `mdt_reint_opcode()` extends the capsule according to the reintegration opcode, and `mdt_reint_internal()` unpacks operation-specific records, rejects mutable operations on read-only exports except read-only open, sizes reply buffers, initializes reintegration credentials, rewrites UID/GID inputs from the authenticated ucred when appropriate, checks resend/replay reconstruction, then calls `mdt_reint_rec()` from the reint layer. On successful open it may inline-read DoM file data or directory entries into the open reply.

LDLM intent enqueue operations are handled by `mdt_intent_policy()`. It detects the intent opcode, extends the capsule, unpacks the MDT body when needed, runs an intent-specific handler, and converts server status into LDLM reply status. Open/create intents reuse the reint path. Getattr/lookups use `mdt_getattr_name_lock()` and then replace the temporary local lock with the client-visible LDLM lock through `mdt_intent_lock_replace()`. Layout intents resolve the target FID from the lock resource, size the LVB for layout EA, run layout checks or layout changes, handle replay-supplied LOVEA, and downgrade exclusive layout locks when returning them. Glimpse, BRW, and quota intents delegate to the corresponding MDT/target/quota handlers.

Lock construction is centralized around `mdt_object_lock_internal()`, which builds an LDLM inodebits resource name from a FID and chooses local `mdt_fid_lock()` or remote `mo_object_lock()` depending on whether the object is remote. Parent directory operations may take both a whole-directory/PDO lock and a hash-specific regular lock through `mdt_object_pdo_lock()`. Cross-MDT locks use `mdt_remote_blocking_ast()` so cached remote object state can be invalidated and remote object references dropped when the lock is canceled. Unlock paths either drop locks immediately or save write locks into PTLRPC reply state / SLC structures until transaction commit or client acknowledgement. COS and SLC modes may downgrade locks to `LCK_COS` or `LCK_TXN` and trigger async commit on lock conflict.

Startup begins in `mdt_init()` with libcfs, slab cache, MDS module, and OBD type registration. `mdt_init0()` initializes defaults, obtains mount info, builds the MDD and OSD-backed stack, initializes FLD/SEQ servers, creates the MDT LDLM namespace, registers intent policy, initializes the target, local OID storage, HSM coordinator, identity caches, tunables, quota master on MDT0, pinger, and restriper. `mdt_prepare()` prepares the child stack, clones changelog/HSM llog contexts, registers LFSCK namespace, obtains the root FID on MDT0, starts recovery, and enables connections. Teardown reverses that order in `mdt_fini()`, stopping LFSCK, restriper, HSM coordinator, recovery, quota, tunables, identity caches, HSM state, local storage, namespace, SEQ/FLD, and stack links.

Connection handling first waits for target readiness for normal clients, creates or reuses an export, attaches nodemap membership from the request context/NID, and calls `mdt_connect_internal()` to negotiate feature flags. That function masks unsupported flags, enforces readonly backing-device rules, negotiates flags2, ACL/xattr support, BRW size, grant parameters, maxbytes, pingleless behavior, checksum types, max EA size, multi-mod-RPC limit, LSEEK support, DNE MDS-MDS counts, SLC enablement, and DMV implicit-inherit compatibility. Disconnect tears down grants, open file state, HSM copytool registration, client slots, nodemap membership, and old-client counters.

## State and Persistence Behavior

Most state is live kernel state attached to `struct mdt_device`, `struct mdt_object`, `struct mdt_thread_info`, exports, LDLM locks, and target bookkeeping. `mdt_device` owns child/bottom exports, FLD/SEQ sites, LDLM namespace, quota master target, HSM coordinator, identity caches, local OID storage, tunables, statfs caches, grant data, connection counters, root FID, and feature flags. `mdt_object` is a top LU object slice layered over the MDD object and carries mutexes/semaphores, open/write counters, SOM/DOM state, layout-created flags, and restripe linkage. `mdt_thread_info` is per-environment scratch state for request bodies, credentials, reply capsules, lock handles, temp buffers, EA buffers, names/FIDs, and specs.

Persistent filesystem state is accessed through lower layers rather than directly authored here. Attribute state comes from `mo_attr_get()`. LOV/LMV/default LMV, LinkEA, ACL, HSM, security, and encryption contexts are read or written through `mo_xattr_get()`/related helpers. Sync reaches the underlying `dt_device` and `mo_object_sync()`. Quota state is delegated to QMT or slave quota handlers. Changelog/HSM llog contexts are cloned from MDD and exposed at MDT level. SEQ and FLD initialization persists sequence/range state through their server implementations. Local OID storage is initialized on a local namespace FID.

Reply state is intentionally transient but semantically important. Locks may remain referenced after a handler returns because they are saved into PTLRPC reply state or SLC lists until transaction commit, cancellation, or ACK. Statfs data is cached for `OBD_STATFS_CACHE_SECONDS`. Large EA/ACL buffers are cached inside `mdt_thread_info` and freed by the context key destructor. Export cleanup treats still-open write handles as a signal to mark files HSM-dirty before closing them.

## Dependencies and Integration Points

The file depends on Linux kernel module, slab, folio/page, RCU, namespace, and capability machinery; Lustre PTLRPC request capsules and target dispatch; LDLM lock namespaces and callbacks; LU object/device stack; MDD `md_ops`; OSD/DT `dt_ops`; nodemap ID and mount policy; quota/QMT APIs; llog/changelog APIs; LFSCK; HSM coordinator APIs from the surrounding MDT HSM files; Lustre crypto/fscrypt helpers; LOV/LMV layout formats; Data-on-MDT IO helpers from `mdt_io.c`; open/reint/xattr/SOM helpers from sibling MDT files; and fail-injection points throughout.

External integration is broad. Clients see this file through MDS RPC opcodes, LDLM enqueue policy, OST-like DoM data RPCs, connection feature negotiation, and `get_info`/ioctl surfaces. Other MDTs interact via MDS-MDS exports, remote locks, FLD/SEQ, and DNE cross-reference logic. MDD/OSD layers provide actual metadata persistence and low-level object operations. Administrative tools reach it through ioctls, config parameters, changelog, LFSCK, quota, and HSM RPCs.

## Risks and Edge Cases

- Request capsule sizing is delicate. Many handlers estimate reply sizes before packing, then later grow or shrink buffers. Mistakes can surface as protocol errors, truncated ACL/EA data, old-client crashes, or `mdt_fix_reply()` failures.
- Lock lifecycle correctness depends on every path releasing, saving, or zeroing all three lock handles in `struct mdt_lock_handle`. Resend, replay, remote locks, COS/SLC saved locks, and DOM/layout trybits all increase the chance of leaks or stale locks.
- DNE and remote-object paths must split LOOKUP, UPDATE, XATTR, and remote cache invalidation correctly. A wrong lock target can produce cache coherency bugs or deadlocks across MDTs.
- Name lookup under encryption is intentionally indirect: hash-encoded client names are checked against LinkEA entries. Buffer allocation, digest comparison length, and parent-FID matching are security-sensitive.
- `mdt_getattr_internal()` multiplexes inode, HSM, SOM, LOV/LMV, default LMV, ACL, symlink, layout compatibility, and auto-split behavior. Changes in one metadata feature can alter reply flags consumed by old and new clients.
- Export cleanup performs real metadata side effects while a client is being evicted. Dirtying HSM state and orphan-closing open files must work without normal request credentials.
- Device initialization has many partially initialized resources. Error unwinding must mirror successful setup order to avoid leaked namespaces, exports, HSM/QMT state, recovery state, or stack references.
- Quota commands map IDs through nodemap and briefly leave/enter barriers for set operations. Incorrect mapping or barrier handling risks wrong-user quota changes or racing writes.
- `fid2path` reconstructs paths from LinkEA and stops at remote objects or fileset roots. Hardlinks, striped directories, encrypted names, path length limits, and moves during lookup are all edge cases.

## Test Signals

Useful tests include protocol-level `MDS_GET_ROOT` with nodemap deny, read-only filesets, and nested filesets; `MDS_STATFS` cache/grant accounting and old-client block-size compatibility; `MDS_GETATTR` and `MDS_GETATTR_NAME` for symlinks, large LOV/LMV, default LMV, large ACL, HSM released files, DoM files, old clients, encrypted directories, negative lookup, cross-MDT objects, and batch statahead cancellation. Reint/open tests should cover read-only export rejection, replay/resent reconstruction, UID/GID credential rewriting, inline DoM and directory read-on-open, and `mdt_fix_reply()` shrink behavior.

Lock tests should exercise PDO locks, remote locks, COS/SLC save paths, blocking AST commit triggers, DOM trylocks, layout lock replacement, lock resend with destroyed handles, and cleanup assertions in `mdt_thread_info_fini()`. DNE tests should cover parent/child on different MDTs, remote cache invalidation, remote object lookup locks, and old clients without DNE support. Lifecycle tests should inject failures through the existing `CFS_FAIL_CHECK()` sites across stack init, HSM init, quota init, reply packing, statfs, readpage, reint delay, and intent delay. Admin/control tests should cover quota nodemap mapping, changelog permission checks, LFSCK ioctls, readonly ioctls, abort recovery, connection flag negotiation, reconnect, disconnect with open writes, and `fid2path` for hardlinks, encrypted names, fileset roots, remote objects, path overflow, and concurrent rename retry.
