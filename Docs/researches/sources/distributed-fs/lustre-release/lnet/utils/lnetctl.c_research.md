# sources/distributed-fs/lustre-release/lnet/utils/lnetctl.c

Purpose: implements the `lnetctl` command-line utility for configuring, querying, importing, exporting, debugging, and fault-testing Lustre LNet. It maps top-level commands and subcommands to either newer generic-netlink YAML paths or older liblnetconfig ioctl/cYAML APIs when netlink is unsupported.

Important APIs/types/functions: `main()` initializes liblnetconfig with `lustre_lnet_config_lib_init()` and dispatches through `cfs_parser()` using `cmd_list`. Command tables define the CLI surface for `lnet`, `route`, `net`, `routing`, `set`, `import`, `export`, `stats`, `debug`, `global`, `peer`, `ping`, `discover`, `service-id`, `udsp`, `fault`, `setup-mrrouting`, `setup-sysctl`, and `cpt-of-nid`. `check_cmd()` provides common help/minimum-argument handling, and `parse_long()` provides simple integer parsing.

Core netlink builders include `yaml_lnet_route()`, `yaml_lnet_config_ni()`, `yaml_lnet_peer()`, `yaml_lnet_ping()`, `yaml_debug_recovery()`, and `yaml_lnet_cpt_of_nid()`. These allocate a libnl socket, set up a netlink-backed YAML parser for replies, create a netlink-backed YAML emitter for a specific LNet command, emit a YAML request document, close the emitter, parse/display the reply, and fall back to old APIs if setup reports `-EOPNOTSUPP`. Import/export support is centered around `jt_import()`, `jt_export()`, `complete_and_setup_emitter()`, `find_command_mapping()`, `handle_net_config_sequence()`, `handle_udsp_sequences()`, `handle_global_parameter()`, and the tunable/list parsers. Fault injection support uses `yaml_lnet_fault_rule()` through `jt_fault_add()`, `jt_fault_del_common()`, `jt_fault_reset_common()`, and `jt_fault_show_common()`.

Control flow: command dispatch is table driven. Top-level wrappers such as `jt_net()`, `jt_route()`, `jt_peers()`, `jt_fault()`, and `jt_set()` validate and then recurse into a subcommand table. Setter commands parse a single numeric value and call matching `lustre_lnet_config_*` functions. Route commands parse net/gateway/hop/priority, build a route YAML document for netlink, and fall back to `lustre_lnet_config_route()`, `lustre_lnet_del_route()`, or `lustre_lnet_show_route()`. Network commands parse interface/NID/ip2net/CPT/tunable options into `struct lnet_dlc_network_descr`, `struct lnet_ioctl_config_lnd_tunables`, and `cfs_expr_list`, emit netlink YAML, and then optionally run multi-rail Linux route setup. Peer commands parse primary NID, peer NID ranges, Multi-Rail flags, health/state fields, and list/show verbosity, then emit peer YAML or call old peer APIs. Ping and discover expand NID ranges into YAML flow sequences and display kernel replies with enhanced errno descriptions.

Import control flow is the most complex. `jt_import()` reads YAML from a file or stdin, chooses add/delete/show/exec mode, and by default streams the YAML through netlink. It scans scalar events to detect top-level blocks mapped by `cmd_mappings`, starts a command-specific streaming emitter, forwards events into it, and completes the emitter when switching operations. It special-cases `udsp`, `ip2nets`, `net`, `CPT`, and `global` because those need local parsing or old APIs. `handle_net_config_sequence()` parses each net/ip2nets sequence item, enforces first-key expectations (`net type` or `net-spec`), parses interfaces, IP ranges, common tunables, LND tunables, and CPT expressions, resolves ip2nets rules, skips duplicate ip2nets networks, and calls `yaml_lnet_config_ni()` for each resolved network. `--old-api` reads the whole file into memory and calls legacy YAML config/delete/show/exec functions.

Export control flow writes current configuration to stdout or a file. It first tries netlink dumps for nets, routes, and peers, then falls back to old show APIs where needed. It always appends routing, global settings, and UDSP show data through cYAML. Backup mode sets `NLM_F_DUMP_FILTERED` and requests less verbose data needed for reconfiguration.

State and persistence behavior: `lnetctl` keeps no daemon state. It mutates persistent runtime LNet kernel state through netlink and ioctl calls, including LNet configured/unconfigured status, routes, local NIs, peers, UDSP rules, global tunables, routing buffer settings, recovery settings, and fault-injection rules. Import reads YAML files or stdin; export writes YAML to stdout or a user-specified file. In-memory state includes cYAML result trees, libyaml parser/emitter objects, libnl sockets, parsed network/interface lists, NID range expansion lists, CPT expression lists, and transient tunables. Resource cleanup is mostly explicit through `cYAML_free_tree()`, `yaml_parser_cleanup()`, `yaml_emitter_cleanup()`, `yaml_document_delete()`, `nl_socket_free()`, `lustre_lnet_free_list()`, and `cfs_expr_list_free()`.

Dependencies/integration points: depends on libc getopt, libyaml, libnl through the netlink adapter, libcfs parser/ioctl utilities, cYAML, `liblnetconfig.h`, LNet DLC structs, LND-specific tunables, and optional KFILND support. It is the main user-facing integration point for the liblnetconfig library functions implemented across the `lnet/utils/lnetconfig` directory. It integrates with the kernel generic netlink LNet family and legacy LNet ioctls, plus host networking setup helpers `lustre_lnet_setup_mrrouting()` and `lustre_lnet_setup_sysctl()`.

Risks: many command handlers silently ignore unparsable numeric options by resetting to sentinel values, which can hide user mistakes. Several paths use global getopt state and must reset `optind` correctly. Netlink and old-API fallback behavior can produce different output shapes or partial effects if a command succeeds in one path and later setup fails. Import uses event streaming and top-level scalar detection, so malformed YAML or unexpected key ordering can route a block to the wrong handler. `handle_udsp_sequences()` chooses the add action string from `prio ? "priority" : ""`, so priority `0` may be treated as no action despite being documented as highest priority. `fault_attr_ptl_parse()` accepts a `ptl_str` parameter but parses global `optarg`, coupling it to getopt state. In `jt_fault_del_common()`, the `case 'a'` branch lacks a `break` and falls through to the destination handling branch, which is risky for `--all`. File import old-API mode sizes stdin with `fstat()` and assumes a useful `st_size`, which is fragile for pipes. The code contains many manual cleanup branches, so initialization failures need leak testing.

Test signals: CLI tests should cover help/min-argument behavior for every command table, invalid options, parse failures, and sentinel/default behavior. Netlink tests should mock unsupported netlink and verify fallback to old APIs for configure, route, net, peer, ping/discover, recovery, and export. YAML import tests should cover add/delete/show/exec modes, command switching, global parameters, net and ip2nets blocks, duplicate ip2nets networks, tunables, LND tunables, CPT scalar and sequence formats, UDSP blocks, and malformed event sequences. Export tests should cover normal and backup output, file output, partial netlink fallback, and cYAML tree cleanup. Functional integration tests should exercise route add/del/show, NI add/del/show/set with NID/interface/ip2net/CPT/tunables, peer add/del/show/list/set, UDSP add/del/show, ping/discover with NID ranges and source NID, fault drop/delay add/del/reset/show validation, and global show/set round-trips.
