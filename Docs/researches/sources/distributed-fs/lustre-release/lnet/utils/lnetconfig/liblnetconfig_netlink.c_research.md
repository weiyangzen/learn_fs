# sources/distributed-fs/lustre-release/lnet/utils/lnetconfig/liblnetconfig_netlink.c

Purpose: implements the liblnetconfig bridge between libyaml documents and Lustre LNet generic netlink messages. It lets callers read kernel LNet replies as YAML and write YAML requests as netlink operations, while keeping kernel code free of YAML formatting. The file also centralizes netlink socket setup, multicast group subscription, extended ACK handling, parser/emitter cleanup, and richer YAML error logging.

Important APIs/types/functions: `yaml_parser_set_input_netlink()` is the public parser setup entry point; it registers the netlink socket, allocates the receive buffer, and installs libnl callbacks. `yaml_emitter_set_output_netlink()` and `yaml_emitter_set_streaming_output_netlink()` are the public output entry points; they resolve the generic netlink family and attach a custom YAML writer. `yaml_netlink_setup_emitter()` and `yaml_netlink_complete_emitter()` are used by streaming import paths to start/finish one netlink-backed YAML document per command. `yaml_parser_get_reader_error()` and `yaml_parser_get_reader_proto_version()` expose netlink-side failure details and protocol version. `yaml_emitter_cleanup()` and `yaml_parser_cleanup()` must be used instead of raw libyaml delete calls when these adapters are installed.

Key internal types are `struct yaml_netlink_input`, which tracks parser state, input buffer pointers, socket, protocol version, async mode, completion state, and the current key-table tree; `struct yaml_nl_node`, which stores a netlink/YAML key table node and child collection; and `struct yaml_netlink_output`, which stores emitter state, netlink socket/control socket, family id, command, version, flags, and local port. The key-table metadata is represented through `struct ln_key_list` and `struct ln_key_props` from the LNet netlink ABI.

Control flow: the read side starts in `yaml_parser_set_input_netlink()`, which calls `lustre_netlink_register()` to connect generic netlink, enable broadcast errors, enable extended ACK where supported, and disable sequence/auto-ACK behavior for async streams. Libyaml then calls `yaml_netlink_read_handler()` whenever it needs bytes. That handler receives netlink messages through `nl_recvmsgs_report()`, whose `NL_CB_VALID`, `NL_CB_FINISH`, and error callbacks are bound to `yaml_netlink_msg_parse()`, `yaml_netlink_msg_complete()`, and `yaml_netlink_msg_error()`. Messages with `NLM_F_CREATE` carry a nested key table and are parsed by `yaml_parse_key_list()` into the local `yaml_nl_node` tree. Data messages are parsed against the cached key table, converted by `yaml_parse_value_list()` into textual YAML, and copied from the adapter buffer into libyaml's buffer. Completion frees the key tree and, for async mode, appends YAML document markers so multiplexed event streams remain parseable.

The write side starts when libyaml emits bytes into `yaml_netlink_write_handler()`. The handler duplicates the output buffer, normalizes quotes with `yaml_quotation_handling()`, treats top-level YAML keys as netlink multicast groups via `lustre_netlink_add_group()`, creates a generic netlink message, and translates mappings/sequences/scalars into nested `LN_SCALAR_ATTR_LIST` attributes. `yaml_format_type()` classifies block, flow, sequence, and mapping syntax using indentation and delimiters. `yaml_create_nested_list()` recursively builds nested attributes, and `yaml_fill_scalar_data()` encodes key strings or numeric/bool values into scalar netlink attributes. At the end, either a full message is sent with `nl_send_auto()` or an empty/simple command is sent with `genl_send_simple()`.

State and persistence behavior: no durable state is written. Runtime state is held in parser/emitter handler data, the receive buffer, cached key-table tree, libnl socket callbacks, and optional multicast membership. Kernel-side state changes happen only through emitted netlink commands. The input buffer starts at 64 KiB and is doubled when less than 1 KiB remains. The cached key table is replaced when a create message arrives with `NLM_F_REPLACE`, and it is freed at message completion.

Dependencies/integration points: depends on libyaml, libnl generic netlink, Linux netlink options `NETLINK_BROADCAST_ERROR` and `NETLINK_EXT_ACK`, and Lustre headers such as `linux/lnet/lnet-nl.h` and `liblnetconfig.h`. It is consumed by `lnetctl.c` netlink-backed command paths and any liblnetconfig caller that wants YAML import/export over netlink. It integrates with the LNet generic netlink family (`LNET_GENL_NAME`, `LNET_GENL_VERSION`) and commands such as routes, nets, peers, ping, recovery, and CPT-of-NID.

Risks: YAML string generation is pointer-arithmetic heavy and must maintain correct buffer accounting; the `yaml_parse_value_list()` branch that advances `*size` after output appears suspicious because most other branches subtract consumed size. Flow-style parsing uses destructive string edits and `strsep()`, so malformed flow YAML can mis-nest data or produce generic writer errors. `yaml_quotation_handling()` assumes paired quotes and can dereference a missing closing quote if input is malformed. Extended ACK messages obtained with `nla_strdup()` can replace static libnl error strings and need careful ownership expectations. Consumers must use the custom cleanup functions or the handler data leaks. Async streams intentionally disable sequence checking, which is required for events but weaker for strict request/response validation.

Test signals: parser tests should feed synthetic key-table and value netlink messages for mappings, sequences, empty nested lists, flow mappings/sequences, flags, numeric types, null-string key updates, and key-table replacement. Emitter tests should round-trip representative LNet YAML into expected scalar/nested netlink attributes and verify group subscription failures, missing top-level groups, malformed flow syntax, quoted strings, bool/numeric coercion, and empty/simple commands. Error-path tests should cover kernel extended ACK text, normal netlink errors, `-NLE_INTR`, unsupported `NETLINK_EXT_ACK`, buffer growth, async start/end document markers, and cleanup after parser/emitter initialization failures.
