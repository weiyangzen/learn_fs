# sources/distributed-fs/lustre-release/lnet/utils/lnetconfig/liblnetconfig_udsp.c

Purpose: implements liblnetconfig support for LNet UDSPs, user-defined selection policies. It parses user NID/net criteria, marshals UDSP rules into the ioctl ABI used by the kernel, demarshals kernel replies back into userspace structures, and presents show output as cYAML.

Important APIs/types/functions: exported entry points are `lustre_lnet_add_udsp()`, `lustre_lnet_del_udsp()`, and `lustre_lnet_show_udsp()`. `lnet_udsp_alloc()` initializes a `struct lnet_udsp` and all embedded list heads. `lnet_udsp_free()` and `lnet_udsp_nid_descr_free()` release parsed criteria, with separate handling for normal parsed lists versus single bulk allocations created during demarshal. `lnet_get_udsp_size()`, `lnet_size_marshaled_nid_descr()`, `lnet_udsp_marshal()`, and `copy_nid_range()` calculate and write the ioctl bulk layout. `lnet_udsp_demarshal()`, `copy_ioc_udsp_descr()`, and `copy_range_info()` read the kernel bulk layout into ordinary `cfs_expr_list` and `cfs_range_expr` lists. `lustre_lnet_nid_descr2str()` converts a UDSP criterion back to `addr@net[num]` style strings for display. `yaml_add_udsp_action()` adds the action subtree, currently priority.

Control flow: adding a rule starts in `lustre_lnet_add_udsp()`. It validates action type (`priority` or preferred-list alias), requires at least one of src/dst/rte, rejects unsupported src+rte and src+dst+rte combinations, allocates a UDSP, parses each provided criterion through `cfs_parse_nid_parts()`, applies the priority/default-action rules, computes the exact ioctl buffer size, marshals the rule into a contiguous `struct lnet_ioctl_udsp` plus descriptor bulk, and sends `IOC_LIBCFS_ADD_UDSP` to `LNET_DEV_ID`. Deleting initializes `struct lnet_ioctl_udsp`, stores the requested index, and sends `IOC_LIBCFS_DEL_UDSP`.

Showing rules iterates index-by-index unless a specific index was requested. For each rule it first issues `IOC_LIBCFS_GET_UDSP_SIZE`, allocates the returned size, then issues `IOC_LIBCFS_GET_UDSP`. The returned bulk is demarshaled into a temporary `struct lnet_udsp`, converted into a cYAML sequence item with `idx`, optional `src`, `dst`, `rte`, and `action`, and then freed. Iteration stops when the size ioctl reports `ENOENT`; other errors are reported through cYAML.

State and persistence behavior: this file does not persist anything itself. UDSP state lives in the kernel and is modified through ioctls. Userspace state is short-lived: parsed criteria lists, a transient contiguous ioctl buffer, demarshaled display structures, and cYAML output trees. Marshal size calculations are deterministic and based on expression/range list lengths. Demarshal allocates one contiguous userspace block per NID descriptor and links list nodes into it, so the free path must know whether it is freeing parsed lists or a bulk-demarshal allocation.

Dependencies/integration points: depends on Lustre libcfs ioctl helpers, `linux/lnet/lnetctl.h`, `linux/lnet/lnet-dlc.h`, NID expression parsing (`cfs_parse_nid_parts()`, `cfs_expr_list_*`, `cfs_expr2str()`), network-name helpers (`libcfs_net2str()`, `LNET_MKNET()`), cYAML builders, and the LNet kernel ioctl commands `IOC_LIBCFS_ADD_UDSP`, `IOC_LIBCFS_DEL_UDSP`, `IOC_LIBCFS_GET_UDSP_SIZE`, and `IOC_LIBCFS_GET_UDSP`. `lnetctl.c` calls these functions for direct UDSP CLI operations and YAML import/export handling.

Risks: the marshaled layout is manually maintained with pointer increments, explicit sizes, and repeated `bulk_size` decrements; ABI drift between userspace and kernel structs can corrupt parsing. The descriptor type check compares the first four bytes of string literals such as `"SRC"` through `*(__u32 *)type`, which is compact but endian/alignment-sensitive. Demarshal free behavior depends on `net_range->next` or `ud_addr_range.next` pointing to the base of the contiguous allocation. `lustre_lnet_del_udsp()` builds its cYAML error under `ADD_CMD`, which may be a reporting bug for delete failures. `yaml_add_udsp_action()` lacks an explicit `break` after priority but intentionally falls through to default return; new action types could be lost if this is extended carelessly.

Test signals: add tests should cover missing criteria, unsupported criterion combinations, bad action strings, priority defaults for single-ended src/dst rules, explicit insertion index, and parse failures for src/dst/rte. Marshal/demarshal tests should cover empty criteria, net-only criteria, address-only and address+net-range expressions, multiple address expression dimensions, undersized buffers, descriptor type mismatch, and exact size accounting. Show tests should simulate multiple rules, a single index, `ENOENT` termination, non-ENOENT ioctl failures, cYAML tree merging into an existing result, and buffer-too-small output from `lustre_lnet_nid_descr2str()`.
