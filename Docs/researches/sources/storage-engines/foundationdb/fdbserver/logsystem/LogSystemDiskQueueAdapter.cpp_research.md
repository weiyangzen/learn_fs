# sources/storage-engines/foundationdb/fdbserver/logsystem/LogSystemDiskQueueAdapter.cpp

Purpose: Adapts log-system transaction replay and new pushed data to the `IDiskQueue`-style interface expected by transaction logs. It lets recovery read a byte stream from `LogSystem::peekTxs` while collecting pushed blocks and pop positions into commit messages acknowledged by the caller.

Important APIs/types/functions: `LogSystemDiskQueueAdapterImpl::readNext` is the core coroutine. Public methods implement disk queue operations: `readNext`, `getNextReadLocation`, `push`, `pop`, `commit`, `getError`, `onClosed`, `dispose`, `close`, `getCommitMessage`, and factory `openDiskQueueAdapter`.

Control flow: Recovery reads loop until at least the requested byte count is buffered or the log-system end is reached. When the cursor has no message, the adapter races cursor `getMore()`, `peekLocality` changes, and a switch timer. Timer choices rotate among unrestricted, secondary-locality, and primary-locality `peekTxs` cursors. If a cursor reports a popped version or buggify discards data, the adapter resets `recoveryLoc`, clears buffers, recreates the cursor, marks discarded data, and throws `disk_adapter_reset`. Otherwise it appends cursor messages into a recovery queue, concatenates chunks, returns at most the requested byte count, and advances `recoveryQueueLoc`.

State and persistence behavior: In-memory state includes `recoveryLoc`, `startLoc`, `recoveryQueue`, `recoveryQueueDataSize`, `recoveryQueueLoc`, `totalRecoveredBytes`, `cursor`, `localityChanged`, `peekTypeSwitches`, `hasDiscardedData`, `pushedData`, `poppedUpTo`, `nextCommit`, and pending `commitMessages`. `push` stores bytes into arena-backed blocks of `LOG_SYSTEM_PUSHED_DATA_BLOCK_SIZE` and returns the next commit location. `commit` packages pushed blocks and `popTo` into `CommitMessage`, sends it through a promise, and completes when the message's `acknowledge` future is fulfilled. The adapter does not write disk itself.

Dependencies and integration points: Depends on `IDiskQueue` types, `LogSystem::peekTxs`, `PeekTxsInfo`, Flow `race`, `delay`, `yield`, and server knobs for cursor switch timing and block sizing. TLog recovery code uses it as a disk-queue-like source/sink while the log system remains the actual persisted log.

Risks: Reset behavior is correctness-sensitive because discarded or popped data forces replay from a new location. The locality-switch race must not starve progress or read past `logSystem->getEnd()`. Returning empty data at end clears the `logSystem` reference, so later reads rely on adapter state only. `commit` asserts a pending commit-message promise exists, so callers must request commit messages before committing. `close`/`dispose` delete `this`, making ownership conventions important.

Test signals: Tests should cover reading across multiple cursor messages, partial-byte reads, end-of-log empty result, locality change switching, timer-based primary/secondary/unrestricted rotation, cursor popped reset and `disk_adapter_reset`, buggified reset in simulation, `push` block splitting, `pop` max behavior, `commit` message contents and acknowledgement, and disabled recovery returning empty reads.
