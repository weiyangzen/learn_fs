# sources/storage-engines/foundationdb/fdbserver/logsystem/LogSystemConsumer.cpp

Purpose: Implements read/pop consumption of the log system for storage recovery, transaction-system recovery, log routers, and backup workers. It builds peek cursors over current and old log generations, chooses local/all/remote strategies, merges multiple tag streams, and schedules pops to TLogs and log routers.

Important APIs/types/functions: `peekAll`, `peekRemote`, two overloads of `peek`, `peekLocal`, `peekTxs`, `peekSingle`, `peekLogRouter`, `popLogRouter`, `popTxs`, `pop`, `getTxsPoppedVersion`, `getEnd`, and `getPseudoPopTag`. It instantiates cursor types such as `SetPeekCursor`, `ServerPeekCursor`, `BufferedCursor`, `ReplayMultiCursor`, `MultiCursor`, and `MergedPeekCursor`.

Control flow: `peek` dispatches remote-log tags to `peekRemote` and all other tags to `peekAll`; multi-tag peek creates one cursor per tag and buffers/merges them. `peekAll` selects local log sets matching the tag locality and current/old epoch ranges, then returns a single current `SetPeekCursor` or a `ReplayMultiCursor` stitched with epoch-end markers. `peekLocal` tries to use one matching local set and can throw `worker_removed` if a local-only path cannot safely read old generations. `peekTxs` builds transaction-system cursors for all transaction tags, preferring locality-limited merged cursors when a usable `peekLocality` and `localEnd` are supplied and falling back to `peekAll` on worker removal. `peekLogRouter` locates the generation containing the requesting log router or backup worker, chooses current or old local sets, optionally prefers satellite logs, and avoids constructing empty old-range cursors.

State and persistence behavior: The consumer is mostly stateless beyond its reference to `LogSystem`; it observes `tLogs`, `oldLogData`, `recoveredAt`, `knownLockedTLogIds`, `stopped`, tag counts, and recovery endpoints. Pop operations mutate `LogSystem::outstandingPops`, `popActors`, and `logRouterLastPops`, then asynchronously send durable `popMessages` requests to TLogs. `getTxsPoppedVersion` queries TLogs through `LogSystem::getPoppedTxs`. No local disk persistence occurs in this file.

Dependencies and integration points: Depends on `LogSystem`/`LogSet` placement, TLog peek cursor implementations, tag-locality conventions, old-generation metadata, version-vector unicast locked-TLog information, log-router/backup-worker interfaces stored in log sets, and `SERVER_KNOBS` pop delays. Storage servers and transaction logs use these cursors to replay committed messages during recovery; log routers and backup workers use the log-router paths to catch up and then pop.

Risks: Cursor composition across epochs is subtle: begin/end boundaries are exclusive/inclusive in different APIs and are adjusted by `+1` in public peek methods. Missing old generations, special locality transitions, local/remote generations, or worker removal must fail safe rather than silently skip data. Version-vector unicast requires resetting best server to `-1` unless that server is known locked/stopped. Log-router old-range peeking previously risked born-exhausted cursors when `begin >= oldEnd`, which this file explicitly avoids. Pop scheduling keeps only one actor per `(logID, tag)` outstanding; errors leave the outstanding entry filled, preventing further pops from that `LogSystem`.

Test signals: Coverage should exercise current-only and old-generation peeks; remote-log peeks through log routers; multi-tag buffering; local fallback to all peeks on `worker_removed`; transaction-system locality split at `localEnd`; stopped vs live log-router peeks; satellite preference; empty old-range skip; pop scheduling for TLogs and log routers; durable KCV passed with log-router pops; and pseudo pop-tag mapping for backup/log-router process classes.
