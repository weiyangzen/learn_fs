# sources/storage-engines/foundationdb/fdbrpc/FlowTransport.cpp

`FlowTransport.cpp` implements FoundationDB's Flow RPC transport over `IConnection`. It owns endpoint registration, message framing, reliable/unreliable packet queues, peer connection lifecycle, protocol compatibility tracking, public-key lookup for authorization, ping/failure monitoring, and listener setup.

Important internal types include `TransportData`, `EndpointMap`, built-in endpoint receivers, and `ConnectPacket`. `TransportData` stores local addresses, listeners, peers, endpoint maps, metrics, allow-list state, health monitor data, incompatible peer maps, multiversion connection IDs, connection logging, and loaded public keys. `EndpointMap` packs endpoint token indexes and task priorities into a dense table for well-known and dynamically allocated endpoints. Public `FlowTransport` APIs expose binding, reliable/unreliable send, endpoint add/remove, peer protocol lookup, connection reset, degraded state, public-key loading/watching, and current delivery peer metadata.

Control flow starts with `bind()` recording a public address and launching listener actors. Incoming connections pass through accept handshake, `connectionReader()`, connect-packet parsing, and `Peer::onIncomingConnection()`. Outgoing sends open or find a `Peer`, frame bytes through `sendPacket()`, and let `connectionKeeper()` run connect, writer, reader, and monitor actors together. `scanPackets()` validates lengths/checksums, extracts endpoint tokens, and schedules `deliver()`, which switches to endpoint priority, checks endpoint visibility and compatibility, sets current-delivery globals, and invokes `NetworkMessageReceiver::receive`.

State is mostly in-memory. Reliable packets stay linked until sent/cancelled; unreliable queued packets are discarded across reconnects. Connection history can persist as rolling CSV files when enabled. JWKS public keys are loaded from disk by surrounding file APIs and refreshed by a watch actor.

Dependencies include Flow actors, `IConnection`, `INetworkConnections`, `Net2Packet`, object serializers, `FailureMonitor`, `HealthMonitor`, `IPAllowList`, `JsonWebKeySet`, simulator hooks, TD metrics, and xxHash. Risks concentrate in manual framing, unaligned loads, packet-buffer ownership, global delivery metadata, compatibility/multiversion handling, private endpoint authorization, and public-key refresh semantics. Test signals are mostly indirect through simulation, buggify packet corruption/partial I/O, counters, TraceEvents, and higher-level fdbrpc/cluster tests.
