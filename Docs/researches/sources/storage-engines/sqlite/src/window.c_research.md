# sources/storage-engines/sqlite/src/window.c

## Purpose
`window.c` implements SQLite window-function support when `SQLITE_OMIT_WINDOWFUNC` is not defined. It registers built-in window functions, resolves and normalizes `OVER` clauses, rewrites SELECT statements so rows arrive in partition/order sequence, and emits VDBE bytecode that evaluates window frames over ephemeral row buffers. It is the bridge between parser/resolver structures (`Window`, `Select`, `Expr`) and the execution engine (`Vdbe`, aggregate/window opcodes, ephemeral cursors).

## Important APIs, Types, and Functions
- Built-in window callbacks: `row_numberStepFunc`, `dense_rankStepFunc`, `rankStepFunc`, `percent_rankStepFunc/Inv/Value`, `cume_distStepFunc/Inv/Value`, `ntileStepFunc/Inv/Value`, `last_valueStepFunc/Inv/Value/Finalize`, `first_valueStepFunc/Finalize`, and `nth_valueStepFunc/Finalize`.
- Registration API: `sqlite3WindowFunctions()` installs static `FuncDef` entries via `sqlite3InsertBuiltinFuncs()`. Built-ins use pointer-stable name constants such as `row_numberName`, `leadName`, and `lagName` so later code can identify special functions by `pFunc->zName`.
- Window resolution/allocation APIs: `sqlite3WindowUpdate()`, `sqlite3WindowAlloc()`, `sqlite3WindowAssemble()`, `sqlite3WindowChain()`, `sqlite3WindowAttach()`, `sqlite3WindowLink()`, `sqlite3WindowCompare()`, `sqlite3WindowDup()`, `sqlite3WindowListDup()`, `sqlite3WindowDelete()`, and `sqlite3WindowListDelete()`.
- Query rewrite machinery: `WindowRewrite`, `selectWindowRewriteExprCb()`, `selectWindowRewriteSelectCb()`, `selectWindowRewriteEList()`, `exprListAppendList()`, `sqlite3WindowExtraAggFuncDepth()`, `disallowAggregatesInOrderByCb()`, and `sqlite3WindowRewrite()`.
- Code-generation machinery: `WindowCodeArg`, `WindowCsrAndReg`, `sqlite3WindowCodeInit()`, `sqlite3WindowCodeStep()`, `windowAggStep()`, `windowAggFinal()`, `windowFullScan()`, `windowReturnOneRow()`, `windowCodeOp()`, `windowCodeRangeTest()`, `windowIfNewPeer()`, `windowReadPeerValues()`, `windowCheckValue()`, `windowInitAccum()`, and `windowCacheFrame()`.
- Internal aggregate contexts: `CallCount`, `NthValueCtx`, `NtileCtx`, and `LastValueCtx` store per-window-function state behind SQLite aggregate contexts.

## Control Flow
Parsing creates `Window` objects with frame type, start/end boundaries, partition/order lists, base window names, and exclude flags. `sqlite3WindowUpdate()` resolves named windows, chains base definitions, rejects invalid `FILTER` use on built-ins, enforces `RANGE` offset restrictions, and coerces frames for built-ins whose semantics require fixed frames, such as `row_number()` and `rank()`.

When a SELECT contains window functions, `sqlite3WindowRewrite()` disables flattening by moving `FROM`, `WHERE`, `GROUP BY`, and `HAVING` into a subquery. It leaves parent `ORDER BY`, `LIMIT`, and `OFFSET` in place, builds a subquery `ORDER BY` from `PARTITION BY` plus window `ORDER BY`, rewrites parent terminals into columns from an ephemeral table, and appends partition/order/function argument/filter expressions to the subquery select list.

Execution setup in `sqlite3WindowCodeInit()` opens the main ephemeral cursor and duplicates for current/start/end/app cursors. It allocates partition comparison registers, accumulator/result registers, and special per-function cursors for min/max, `lead`/`lag`, `first_value`, and `nth_value`.

`sqlite3WindowCodeStep()` is called after `sqlite3WhereBegin()` on the rewritten subquery. It copies each input row into an ephemeral buffer, detects partition boundaries, initializes aggregate state on the first row of each partition, advances frame cursors according to `ROWS`, `GROUPS`, or `RANGE` rules, emits `OP_AggStep`, `OP_AggInverse`, `OP_AggValue`, and `OP_AggFinal` calls where possible, and invokes the select.c return-row subroutine with `OP_Gosub`. Complex `EXCLUDE` clauses force `windowFullScan()` to rescan the frame for each row.

## State and Persistence Behavior
Runtime state is mostly transient VDBE state: ephemeral tables, duplicated cursors, accumulator registers, partition registers, frame-boundary registers, rowid registers, and application cursors for special built-ins. No persistent database schema is directly modified by this file. However, its generated bytecode reads sorted subquery output, stores rows in temp btrees, and deletes buffered rows early when `eDelete` proves they are no longer needed.

Aggregate context structs hold per-function values across row processing. `nth_value` and `first_value` duplicate `sqlite3_value` objects and free them at finalize. `last_value` replaces and frees saved values as the frame moves. Min/max over sliding frames use a dedicated ephemeral index keyed by argument plus a unique sequence value.

## Dependencies and Integration Points
This file depends on `sqliteInt.h` internals, parser tokens (`TK_ROWS`, `TK_RANGE`, `TK_GROUPS`, `TK_PRECEDING`, etc.), expression walkers, select rewriting, `FuncDef`, aggregate APIs, VDBE opcodes, `WhereInfo`, key-info/collation helpers, and parser cleanup hooks. It integrates tightly with `select.c`: select.c performs the subquery scan and owns the output subroutine, while this file fills window result registers and buffered terminal values.

It also coordinates with `resolve.c` aggregate-depth logic, function registration in core initialization, optimization flags such as `SQLITE_WindowFunc`, test coverage macros, and optional compile-time omission via `SQLITE_OMIT_WINDOWFUNC`.

## Risks and Edge Cases
The highest-risk areas are frame boundary semantics and cursor choreography. `RANGE` offsets depend on numeric coercion, collation, sort direction, and `NULLS FIRST/LAST` behavior. `GROUPS` and `RANGE` process peer groups, not individual rows. `EXCLUDE CURRENT ROW/GROUP/TIES` changes evaluation to rowid-bounded full scans. Built-ins such as `lead` and `lag` are implemented by direct cursor seeks instead of aggregate callbacks, so their cursor positioning must remain consistent with ephemeral rowids.

Memory risks include duplicated `sqlite3_value` lifetimes, temporary `Table` ownership during rewrite errors, expression-tree mutation in `selectWindowRewriteExprCb()`, and temp-register allocation paths. Semantic risks include invalid named-window inheritance, illegal aggregate/window placement in `ORDER BY`, and frame coercions that must match SQL-standard behavior.

## Test Signals
Useful coverage comes from SQL window-function tests covering every frame type, boundary pair, `EXCLUDE` mode, partition change, peer-group comparison, collations, `NULLS FIRST/LAST`, min/max sliding windows, filters on aggregate windows, and built-ins with invalid arguments. VDBE coverage annotations indicate branches expected for value checks, EOF transitions, range tests, and no-test placeholders. Fuzzing and sqllog-style replay are valuable because query rewrite interacts with aggregate resolution, scalar subqueries, and flattening suppression.
