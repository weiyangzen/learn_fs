# sources/storage-engines/rocksdb/db/comparator_db_test.cc research

Purpose: `comparator_db_test.cc` validates RocksDB DB behavior under several comparator implementations and block-based table format versions. It checks that writes, deletes, point lookups, forward/backward iteration, separator generation, and successor detection honor the configured comparator rather than assuming bytewise key order.

Important APIs and types: `KVIter` adapts an in-memory `stl_wrappers::KVMap` into the RocksDB `Iterator` interface so DB iteration can be compared against a reference model ordered by `stl_wrappers::LessOfComparator(kTestComparator)`. `DoRandomIteraratorTest()` performs random puts/deletes/flushes, then runs random `SeekToFirst`, `SeekToLast`, `Seek`, `SeekForPrev`-equivalent behavior through `Prev`, `Next`, and `Get` comparisons. Custom comparators include `DoubleComparator` (numeric double order with string tie-break), `HashComparator` (hash order with string tie-break), and `TwoStrComparator` (two length-prefixed string components). `ComparatorDBTest` owns the DB path, table factory, comparator lifetime, and parameterized block format version.

Control flow: each comparator test installs the comparator into `Options`, recreates the DB, generates deterministic key populations with `Random`, mutates the DB, flushes at configured intervals, and compares DB state against the model iterator. The test suite runs for default and latest block-based table format versions. Later tests target comparator helper methods directly: `IsSameLengthImmediateSuccessor`, `FindShortestSeparator`, and `FindShortSuccessor` for bytewise and reverse bytewise comparators, including randomized byte strings and boundary bytes.

State and persistence behavior: every test creates an isolated per-thread DB path and destroys it in the fixture destructor. Persistent state consists of memtables and flushed block-based SSTs created under the current comparator. The global `kTestComparator` is used only by test helpers and reset to bytewise on teardown. Comparator changes are applied before DB creation; this file does not test reopening an existing DB under an incompatible comparator.

Dependencies and integration points: the file uses public `DB`, `Iterator`, `Comparator`, `Options`, and `BlockBasedTableFactory` APIs, plus test utilities for random keys, fixed-format uint64 comparators, simple suffix reverse comparator, and key-value maps. It integrates comparator semantics with memtable ordering, SST table construction, point lookup, and iterator navigation.

Risks and edge cases covered: comparator bugs can manifest as missed keys, invalid reverse iteration, incorrect lower-bound seek, or inconsistent file/table ordering. Numeric and hash comparators cover non-lexicographic order; `TwoStrComparator` covers binary keys with embedded lengths; `Uint64Comparator` covers little binary keys and the need for stable binary ordering. Separator/successor tests cover equal strings, different lengths, carries across `0xff`, reverse-comparator asymmetry, and randomized strings where the shortened separator must remain inside the comparator interval.

Test signals: the main signal is exact agreement between RocksDB iterators/gets and `KVIter` over hundreds of randomized operations. Helper-method tests assert exact separator strings where deterministic and relational invariants where randomized. Failures point toward comparator contract violations, block index separator issues, memtable/SST ordering inconsistencies, or reverse iteration boundary bugs.
