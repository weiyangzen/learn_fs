# Research: sources/storage-engines/rocksdb/db/db_merge_operand_test.cc

- **Purpose:** Validates `DB::GetMergeOperands()` behavior, lifetime pinning, operand ordering, result-size optimizations, short-circuit callbacks, base value/deletion handling, immutable memtables, read-only DBs, and blob-file-backed values.
- **Important APIs/types/functions:** Defines a local `LimitedStringAppendMergeOp` derived from `StringAppendTESTOperator` whose `ShouldMerge()` forces partial merge when operand count reaches a limit. `DBMergeOperandTest` derives from `DBTestBase`. Tests use `GetMergeOperandsOptions::expected_max_number_of_operands`, `continue_cb`, arrays of `PinnableSlice`, `Merge`, `Put`, `Delete`, `Flush`, `CompactRange`, `MoveFilesToLevel`, `ReadOnlyReopen`, `TEST_SwitchMemtable`, and blob options.
- **Control flow:** Basic coverage writes keys with combinations of puts, deletes, merges, memtable-only operands, L0 files, different levels, immutable memtables, and read-only reopen. It calls `GetMergeOperands()` and verifies operand counts and order from oldest/base to newest operands, or a merged base string when the merge operator's `ShouldMerge()` compacts operands. Capacity tests reduce `expected_max_number_of_operands` and require `Status::Incomplete`. Short-circuit tests install a continuation callback that stops after a fixed number of operands in mutable memtable, SST, or immutable memtable scans.
- **State and persistence behavior:** The test deliberately moves operands between mutable memtable, immutable memtable, flushed SSTs, compacted levels, and blob files. Lifetime regression tests keep returned `PinnableSlice` values alive after cache eviction or after a memtable flush/SuperVersion change. `GetMergeOperandsLargeResultOptimization` expects all returned slices to be pinned and then flushes to challenge resource ownership.
- **Dependencies:** Includes DB test utilities, `rocksdb/merge_operator.h`, `rocksdb/perf_context.h`, debug utilities, block builder, `SyncPoint`, `FaultInjectionEnv`, and multiple merge-operator implementations. Blob coverage depends on `enable_blob_files` with `min_blob_size = 0`.
- **Integration points:** Exercises point lookup internals that gather merge operands from memtables, immutable memtables, table cache, blob values, and multiple LSM levels without performing a full merge unless a base value or merge operator policy requires it. It covers API behavior for writable and read-only DB handles.
- **Risks:** Operand ordering and partial-merge behavior are sensitive to merge-operator semantics and LSM layout; tests use `Flush`, `CompactRange`, and `MoveFilesToLevel` to make layout predictable. Cache and memtable lifetime bugs can manifest as use-after-free, so the tests rely on pinning semantics rather than only value equality. Blob-file paths add configuration-specific risk.
- **Test signals:** Signals are OK or `Incomplete` statuses as appropriate, exact `number_of_operands`, exact operand strings and ordering, `PinnableSlice::IsPinned()` for large results, callback invocation counts, stable values after flush/SuperVersion changes, and successful read-only `GetMergeOperands()`.
