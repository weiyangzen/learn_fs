# Research: sources/storage-engines/rocksdb/db/deletefile_test.cc

- **Purpose:** Regression and behavior tests for RocksDB obsolete file deletion and background purge scheduling, including live iterator retention, `WaitForCompact(wait_for_purge)`, DB close races, purge during open, column-family-drop cleanup, and multiple purge jobs.
- **Important APIs/types/functions:** Defines `DeleteFileTest : DBTestBase` with `numlevels_`, `wal_dir_`, helpers `SetOptions`, `AddKeys`, `numKeysInLevels`, `CreateTwoLevels`, `CheckFileTypeCounts`, `DoSleep`, and `GuardFinish`. Tests include `PurgeObsoleteFilesTest`, `WaitForCompactWithWaitForPurgeOptionTest`, `BackgroundPurgeIteratorTest`, `CloseWaitsForPurgeScheduledDuringClose`, `PurgeDuringOpen`, `BackgroundPurgeCFDropTest`, `BackgroundPurgeCopyOptions`, and `BackgroundPurgeTestMultipleJobs`.
- **Control flow:** The fixture creates predictable SST layouts by writing large key ranges, flushing, and compacting. Tests then hold iterators or column family handles alive, trigger compactions or drops, and assert obsolete SSTs remain until snapshots/iterators/handles release them. Background purge tests schedule sleeping high-priority tasks and use `SyncPoint` dependencies around `DBImpl::BGWorkPurge`, `BackgroundCallPurge`, and `CloseHelper` to force race windows.
- **State and persistence behavior:** Persistent state includes WAL files under a separate `wal_dir_`, table files in `dbname_`, MANIFEST files, dropped-CF files, and an injected stray `.sst` during open. `CheckFileTypeCounts` scans directories and parses RocksDB filenames to verify deletion timing. Options force immediate full purges, large file/memtable thresholds, WAL retention settings, and optional background purge via `avoid_unnecessary_blocking_io`.
- **Dependencies:** Uses DB implementation/test headers, filename parsing, version set metadata, write batch internals, transaction log APIs, `SyncPoint`, sleeping background tasks, environment scheduling, and `ParseFileName`.
- **Integration points:** Exercises `DBImpl::PurgeObsoleteFiles`, iterator cleanup purge hooks, `WaitForCompactOptions::wait_for_purge`, close-time purge draining, open-time obsolete file cleanup, column family drop deletion, and Env background scheduling.
- **Risks:** Race tests rely on internal SyncPoint names and exact close/purge sequencing; DBImpl lifecycle changes can invalidate them. File count assertions assume no unrelated files in the test directories and stable file naming. Background-purge tests can hang if scheduled sleepers are not woken or if dependencies are misordered.
- **Test signals:** Directory file counts by type, OK statuses from compaction/flush/drop/reopen, iterator statuses, `TEST_WaitForPurge`, ordered sync-point progress, and clean thread joins without use-after-free during DB close.
