# Research: sources/storage-engines/rocksdb/db/db_merge_operator_test.cc

- **Purpose:** Broad regression suite for merge-operator semantics during reads, writes, iteration, compaction, block cache eviction, tailing iteration, snapshot visibility, max-successive-merge conversion, direct operand threshold status reporting, and randomized pinning configurations.
- **Important APIs/types/functions:** Defines `TestReadCallback` wrapping a `SnapshotChecker`, `DBMergeOperatorTest::GetWithReadCallback()`, `MergeOperatorPinningTest`, `MergeOperatorHook`, and `PerConfigMergeOperatorPinningTest`. Tests cover `LimitMergeOperands`, merge errors on read/write/iteration, `MergeOperatorFailsWithMustMerge`, `MergeOperandThresholdExceeded`, `DataBlockBinaryAndHash`, operand pinning across multiple blocks and evicted caches, tailing iterators, memtable unref races, snapshot checker integration, randomized merge workloads, and `MaxSuccessiveMergesBaseValues`.
- **Control flow:** Merge limit tests write operand chains in memtable, L0, different files, and different levels and verify `ShouldMerge()` keeps only the newest operands. Error tests use `TestPutOperator` inputs such as `corrupted` and `corrupted_must_merge` to force merge failures and confirm point reads and iterators propagate `Status::Corruption` without breaking neighboring keys. Pinning tests build many operands across files and levels, then verify reads after table cache eviction or block cache shrinking. Tailing iterator tests run writer and reader threads while flushing and compacting.
- **State and persistence behavior:** The suite creates durable SSTs through repeated flushes, manually moves files to levels, compacts bottommost levels, retains snapshots, evicts table cache entries, and varies block cache use. `TailingIteratorMemtableUnrefedBySomeoneElse` pins an old SuperVersion with a separate iterator, flushes during merge-value collection, then releases the old SuperVersion mid-seek to ensure `ForwardIterator` pins operands safely.
- **Dependencies:** Includes DB test utilities, `dbformat`, `forward_iterator`, merge operator APIs, snapshots, debug utilities, `Random`, and string/max/put merge operators. It uses DBImpl internals (`GetImpl`, `SetSnapshotChecker`, `TEST_table_cache`) and table/block-based options.
- **Integration points:** Covers public `Merge`, `Get`, `MultiGet`, iterators, tailing iterators, snapshots, compaction, block cache/table cache, LSM level layout, wide-column `PutEntity` base values, and status subcodes used by callers to identify merge-operator failure or merge-operand threshold exceedance.
- **Risks:** Some tests are heavy and timing-sensitive: large write counts, background flush/compaction, cache eviction during merge, and tailing iterator polling can be resource dependent. Merge semantics are operator-specific, so replacing operator behavior changes expected values. Snapshot checker tests intentionally diverge from normal sequence visibility and depend on internal `ReadCallback` behavior.
- **Test signals:** Expected signals include exact merged values, retained unmerged internal versions after write-time merge errors, corruption status with `kMergeOperatorFailed` subcode for must-merge failures, `IsOkMergeOperandThresholdExceeded()` flags while still returning OK values, exact files-per-level layout, successful map verification under cache eviction, no tailing iterator errors, correct snapshot-filtered values across flush/compaction, and expected key-version types after max-successive-merge conversion to `Put` or `PutEntity`.
