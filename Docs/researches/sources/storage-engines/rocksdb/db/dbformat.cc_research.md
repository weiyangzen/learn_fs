# Research: sources/storage-engines/rocksdb/db/dbformat.cc

- **Purpose:** Implementation for RocksDB internal-key encoding helpers, timestamp key transformations, debug formatting, internal-key comparator overloads, lookup-key construction, and `IterKey` buffer growth.
- **Important APIs/types/functions:** Defines constants `kValueTypeForSeek = kTypeValuePreferredSeqno`, `kValueTypeForSeekForPrev = kTypeDeletion`, and `kDisableUserTimestamp`. Implements `GetEntryType`, `AppendInternalKey`, `AppendInternalKeyWithDifferentTimestamp`, `AppendUserKeyWithDifferentTimestamp`, `AppendInternalKeyFooter`, min/max timestamp append/pad/strip/replace helpers, `ParsedInternalKey::DebugString`, `InternalKey::DebugString`, `InternalKeyComparator::Compare` overloads, `LookupKey::LookupKey`, `IterKey::EnlargeBuffer`, and `IterKey::EnlargeSecondaryBufferIfNeeded`.
- **Control flow:** Encoding functions append user-key bytes and then little-endian fixed64 footers produced by `PackSequenceAndType`. Timestamp helpers split the user key at its suffix and insert supplied, min, or max timestamp bytes before adding or preserving the footer. Comparator overloads first compare extracted user keys through `UserComparatorWrapper`; equal user keys are ordered by descending packed sequence/type footer. `LookupKey` builds a memtable lookup record as varint32 length, user key, optional timestamp, and seek footer.
- **State and persistence behavior:** The file does not persist state itself, but it defines byte layouts embedded in memtables, SST data blocks, metadata blocks, WAL lookup records, and debug logs. `IterKey` methods allocate and release heap buffers for large keys, while inline buffers avoid allocations for short keys.
- **Dependencies:** Depends on `db/dbformat.h`, `db/lookup_key.h`, perf context declarations, `port/port.h`, fixed-width coding helpers, and string escaping utilities. It relies on public comparators for user-key ordering and timestamp stringification.
- **Integration points:** Used by table builders/readers, memtable lookups, iterators, write batch parsing, range tombstone serialization, and any component that sorts or displays internal keys. The choice of `kValueTypeForSeek` determines seek sentinel ordering for the whole storage engine.
- **Risks:** Internal-key byte layout is on-disk compatible state; changing type values, footer packing, timestamp placement, or comparator ordering can corrupt ordering/recovery. The min/max timestamp helpers rely on size assertions and may misbehave in release builds if callers pass malformed keys. Debug formatting must avoid leaking redacted keys unless `log_err_key` is intended.
- **Test signals:** Covered by `dbformat_test.cc` encode/decode, short separator/successor, timestamp pad/strip/replace, range tombstone end-key ordering, `IterKey` operations, and version macro tests.
