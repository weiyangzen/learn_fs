# Research: sources/storage-engines/rocksdb/db/version_util.h

- **Purpose:** Declares version utility helpers and defines `OfflineManifestWriter`, a thin wrapper around `VersionSet` for reading and modifying MANIFEST state without opening a full DB.
- **Important APIs/types/functions:** Declares `LoadTableHandlersHelper`. Defines `OfflineManifestWriter` with constructor, `Recover`, `LogAndApply`, `Versions`, `IOptions`, and private `WithDbPath`. It owns `WriteController`, `WriteBufferManager`, `ImmutableDBOptions`, a small table cache, `EnvOptions`, and `VersionSet`.
- **Control flow:** The constructor sanitizes DB path state, creates a 1 MiB LRU table cache, and initializes `VersionSet` with user DB options and no tracers/error handler. `Recover` forwards to `VersionSet::Recover` with missing-file tolerance enabled. `LogAndApply` creates and locks an `InstrumentedMutex` to satisfy `VersionSet::LogAndApply`'s DB-mutex contract, applies the edit, then unlocks.
- **State and persistence behavior:** `OfflineManifestWriter` can persist new manifest edits through `VersionSet::LogAndApply`, including file removals, CF metadata, and other `VersionEdit` changes. It avoids DB flush/compaction side effects and uses `no_error_if_files_missing=true` during recovery so offline cleanup can target already-missing files.
- **Dependencies and integration points:** Includes `db/version_set.h`, RocksDB options/status/file-system headers, cache creation, write controller/buffer manager, and `FSDirectory`. It is intended for manifest operations tools or APIs that need real option parsing but not full DB lifecycle.
- **Risks:** It imitates the DB mutex locally; callers must avoid concurrent use unless they provide higher-level serialization. Because it bypasses DB open, it will not perform normal DB-side validation, background work, or live-file lifecycle management. `WithDbPath` only fills `db_paths` when empty, matching `SanitizeOptions` expectations.
- **Test signals:** Correctness is visible through successful `Recover`, persisted `LogAndApply` results, and subsequent DB/VersionSet recovery from the modified MANIFEST.
