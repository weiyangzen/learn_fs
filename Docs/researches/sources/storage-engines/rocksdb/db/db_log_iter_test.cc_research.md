# Research: sources/storage-engines/rocksdb/db/db_log_iter_test.cc

- **Purpose:** Tests RocksDB transaction log iteration through `GetUpdatesSince()` across normal WAL replay, column families, archive movement, restart, corruption gaps, batched operations, and `WriteBatch::PutLogData` blobs.
- **Important APIs/types/functions:** Defines `DBTestXactLogIterator`, `OpenTransactionLogIter(SequenceNumber)`, helper `ReadRecords()` returning the last seen sequence and record count, and `ExpectRecords()`. Test cases cover `TransactionLogIterator`, `TransactionLogIteratorRace`, `TransactionLogIteratorCheckWhenArchive`, `TransactionLogIteratorStallAtLastRecord`, `TransactionLogIteratorCheckAfterRestart`, `TransactionLogIteratorCorruptedLog`, `TransactionLogIteratorBatchOperations`, and `TransactionLogIteratorBlobs`. Core APIs are `DBImpl::GetUpdatesSince`, `TransactionLogIterator::Valid/Next/GetBatch/status`, `BatchResult`, `WriteBatch::Handler`, `GetSortedWalFiles`, `FlushWAL`, `TEST_SwitchWAL`, and WAL truncation helpers.
- **Control flow:** Basic tests open a DB with log-iterator options, write records across default and non-default column families, reopen, sleep to cross WAL timestamps, and verify the iterator sees monotonically increasing sequences and expected record counts. Race tests, enabled only outside `NDEBUG`, use sync-point dependencies to interleave WAL listing with purge/archive movement and ensure no record is missed when logs are moved mid-scan. Archive tests invoke a transaction-log iterator from inside `WalManager::PurgeObsoleteFiles`. Corruption tests disable file deletion, truncate the first WAL, re-enable deletion, append a later record, and verify iteration from the beginning stops with non-OK status while iteration after the gap can find the later record.
- **State and persistence behavior:** Durable state is primarily WAL files and archived WAL metadata. The test repeatedly flushes memtables to force log switching and archival, reopens the DB to validate persisted WAL discovery, and directly truncates a WAL file to simulate a physical log gap. Sequence numbers are used as the contract for ordering and resume points.
- **Dependencies:** Includes `db/db_test_util.h`, `env/mock_env.h`, `port/stack_trace.h`, and `util/atomic.h`. It relies on `OptionsForLogIterTest()`, `ChangeCompactOptions()`, DBTestBase column-family helpers, `SyncPoint`, mock environment sleeping, and test file truncation utilities.
- **Integration points:** Exercises the public backup/replication-facing transaction log iterator API against `WalManager`, WAL archive purge logic, flush/switch-WAL behavior, `WriteBatch` decoding, and column-family-aware write batches. The blob test validates `PutLogData()` items remain in the iterator's batch stream and are delivered to a `WriteBatch::Handler` in order.
- **Risks:** The race coverage is debug-build-only because sync points are compiled out in release builds. Record counts depend on WAL retention and archive behavior from `OptionsForLogIterTest()`. The corrupted-log case must preserve enough later WAL data to test seeking past the gap, so file deletion is explicitly disabled during truncation.
- **Test signals:** Expected signals are valid iterators from requested sequence numbers, strictly increasing `BatchResult::sequence`, exact record counts, OK iterator status for normal paths, non-OK status at a truncated WAL gap, successful resume after the gap, and exact handler output for ordered put/log-data/delete batch contents.
