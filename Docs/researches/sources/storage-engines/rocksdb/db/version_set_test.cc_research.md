# Research: sources/storage-engines/rocksdb/db/version_set_test.cc

- **Purpose:** Large regression suite for `db/version_set.h` behavior. It validates version-storage metadata, manifest replay and rewrite, WAL edits persisted through `VersionEdit`, atomic-group semantics, best-effort recovery from incomplete manifests, missing SST/blob-file handling, off-peak time parsing, timestamp history lower bounds, and file-metadata cache charging.
- **Important APIs/types/functions:** Test fixtures include `GenerateLevelFilesBriefTest`, `VersionStorageInfoTestBase`, `VersionStorageInfoTest`, `VersionStorageInfoTimestampTest`, `FindLevelFileTest`, `VersionSetTestBase`, `VersionSetTest`, `VersionSetWithTimestampTest`, `VersionSetAtomicGroupTest`, `AtomicGroupBestEffortRecoveryTest`, `VersionSetTestDropOneCF`, `EmptyDefaultCfNewManifest`, `VersionSetTestEmptyDb`, `VersionSetTestMissingFiles`, `BestEffortsRecoverIncompleteVersionTest`, and `ChargeFileMetadataTestWithParam`. Helpers construct manifests (`PrepareManifest`, `CreateCurrentFile`, `CreateNewManifest`), dummy SST/blob files (`CreateDummyTableFiles`, `WriteDummyBlobFile`), and call `VersionSet::Recover`, `TryRecoverFromOneManifest`, `TryRecover`, `LogAndApply`, `Close`, `AddLiveFiles`, and `GetObsoleteFiles`.
- **Control flow:** The file starts with isolated unit tests for brief level-file generation and range overlap searching, then builds increasingly realistic `VersionSet` fixtures around a temporary DB directory and mock table factory. Manifest tests write `VersionEdit` records directly with `log::Writer`, set `CURRENT`, recover through `VersionSet`, and assert resulting column families, live files, WAL sets, blob metadata, and manifest validation counters. Atomic-group tests use marked `VersionEdit` sequences and sync points to verify buffering, replay, incomplete trailing groups, corrupt groups, incorrect group sizes, and reactive reads. Best-effort recovery tests intentionally create missing table/blob references, then assert which suffixes can be retained.
- **State and persistence behavior:** The suite creates real test directories, MANIFEST files, CURRENT files, SST files through a mock table builder, and valid blob files through `BlobLogWriter`. It checks persistence across `VersionSet` reopen, new MANIFEST creation, MANIFEST truncation/corruption, and DB close. WAL tests confirm WAL additions/deletions are persisted in MANIFEST and replayed into `WalSet` without creating unnecessary `Version` objects for pure WAL edits.
- **Dependencies and integration points:** Depends on `db/version_set.h`, `db/version_edit.h`, `db/manifest_ops.h`, blob metadata/writer classes, `MockTableFactory`, `MockSystemClock`, `SyncPoint`, `DBTestBase`, block-based table cache charging utilities, and filesystem helpers. It is an integration-level guard for manifest format, recovery behavior, table/blob liveness accounting, and DB option interactions.
- **Risks:** These tests encode subtle recovery rules: pure WAL edits must not allocate new versions, smaller WAL synced-size updates must be ignored, dropped column families must be removed from atomic flush groups, MANIFEST validation must rotate only when enabled or size checks fail, and best-effort recovery must not keep unsafe non-L0 or non-suffix missing-file states. Because the suite manually edits manifests, drift in `VersionEdit` encoding, required fields, or CF metadata can break many cases.
- **Test signals:** Uses `ASSERT_OK`, `EXPECT_NOK`, status class checks, live-file counts, WAL map contents, blob-file lists, sync-point counters, statistics ticker `MANIFEST_VALIDATION_FAILURE_COUNT`, and cache charge totals. Running the RocksDB `version_set_test` binary is the direct signal.
