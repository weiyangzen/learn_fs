# Research: sources/storage-engines/rocksdb/db/dbformat.h

- **Purpose:** Central declaration and inline implementation file for RocksDB internal key format: value type enumeration, sequence/type packing, parsed and encoded key abstractions, internal comparators, iterator key storage, write-batch record readers, range tombstones, and predecessor WAL metadata.
- **Important APIs/types/functions:** Declares on-disk `ValueType` values, `kMaxSequenceNumber`, `kDisableGlobalSequenceNumber`, `kNumInternalBytes`, `ParsedInternalKey`, `InternalKeyComparator`, `InternalKey`, `IterKey`, `InternalKeySliceTransform`, `RangeTombstone`, `ParsedInternalKeyComparator`, and `PredecessorWALInfo`. Inline functions include `IsValueType`, `IsExtendedValueType`, `PackSequenceAndType`, `UnPackSequenceAndType`, `ParseInternalKey`, `ExtractUserKey`, timestamp extraction/strip helpers, `ExtractInternalKeyFooter`, `ExtractValueType`, `UpdateInternalKey`, `GetInternalKeySeqno`, comparator overloads, and `PredecessorWALInfo::EncodeTo/DecodeFrom`.
- **Control flow:** `ParseInternalKey` validates minimum length, decodes the last eight bytes as packed sequence/type, exposes the leading bytes as `user_key`, and returns corruption for non-extended value types. `InternalKey` owns an encoded string and delegates encoding/decoding to append/parse helpers. `IterKey` tracks whether its current slice is user or internal key, supports pinned external memory or copied inline/heap buffers, reconstructs delta-encoded keys with optional min timestamp insertion, and swaps ownership while preserving pointer provenance.
- **State and persistence behavior:** Value type enum values are explicitly on-disk and must not be renumbered. Internal keys are stored as `<user key | 8-byte packed sequence/type>`, optionally with user-defined timestamps in the user-key suffix. `RangeTombstone` serializes deletion ranges as internal keys plus end-key values and uses max sequence/type sentinels for exclusive end-key ordering. `PredecessorWALInfo` persists three fixed64 fields: log number, size bytes, and last recorded sequence.
- **Dependencies:** Includes RocksDB public comparator/slice/slice-transform/types APIs, coding helpers, and user comparator wrapper. Forward integration exists with write batch record parsing, table index builders, memtable/block iterators, range deletion handling, WAL metadata, and timestamp-aware comparators.
- **Integration points:** This header is foundational across DB format, table, memtable, compaction, iterator, and WAL code. `InternalKeyComparator` enforces global storage ordering, `InternalKeySliceTransform` adapts user prefix extractors to internal keys, and `IterKey` is used in block/data iteration where allocation and pointer lifetime are performance-sensitive.
- **Risks:** On-disk enum changes, footer packing changes, or comparator changes are compatibility-breaking. Many helpers use `assert` for size/type preconditions; release builds rely on upstream validation. `IterKey::Swap` and timestamp reconstruction are pointer/ownership sensitive and can create use-after-free or corruption if modified without exhaustive inline/heap/pinned coverage. `kTypeMaxValid` is allowed in limited contexts, so validation changes must account for range tombstone iterator sentinels.
- **Test signals:** `dbformat_test.cc` exercises internal key parse/encode, comparator-sensitive short separator/successor, `IterKey` inline/heap/pinned/secondary swap, timestamp padding/stripping, update-in-place, range tombstone end-key ordering, and version macro invariants.
