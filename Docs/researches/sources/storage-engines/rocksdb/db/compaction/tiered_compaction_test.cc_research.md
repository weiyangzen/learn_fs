# sources/storage-engines/rocksdb/db/compaction/tiered_compaction_test.cc research

Purpose: `tiered_compaction_test.cc` is the RocksDB regression suite for tiered storage and "preclude last level" compaction behavior. It validates that data can be split between a proximal/hot level and the last/cold level based on sequence number, preserved write time, `TimedPut` timestamps, snapshots, range tombstones, and compaction style. It also verifies iterator write-time reporting from memtables, SSTs, and merge results.

Important APIs, types, and fixtures: `TieredCompactionTest` extends `DBTestBase` and installs sync-point overrides for `Compaction::SupportsPerKeyPlacement`, `CompactionJob::PrepareTimes():preclude_last_level_min_seqno`, and compaction stats collection. Its helpers read `InternalStats::CompactionStats`, per-key-placement stats, and assert `CompactionJobStats`. `SetColdTemperature()` assigns `Options::last_level_temperature = Temperature::kCold`. `SingleKeySstPartitioner` forces a file boundary after every key, while `ThreeRangesPartitioner` splits output at `Key(20)` and `Key(40)` to exercise range-sensitive placement. `PrecludeLastLevelTestBase` supplies a `MockSystemClock`, composite env, dynamic/static option mutation through `SetOptions`/`SetDBOptions` or reopen, and periodic task scheduler clock injection. Parameterized suites cover dynamic vs reopen config, universal vs leveled compaction, write protection bytes, tailing vs non-tailing iterators, and enabled vs disabled preclude behavior.

Control flow: the early `TieredCompactionTest` cases build overlapping SSTs through repeated `Put`/`Flush`, drive automatic or manual compaction, change the cold cutoff through sync-point-injected sequence numbers, and assert `FilesPerLevel()` plus SST size by `Temperature`. Universal and leveled tests both confirm that cold data lands in the last level, hot data stays in or migrates to the proximal level, and unsafe cold-to-hot migration is blocked when internal key ranges or bottommost sequence-zeroing would lose ordering information. Range deletion cases hold snapshots, add tombstones spanning hot and cold records, compact repeatedly, and verify both logical reads and `COMPACTION_RANGE_DEL_DROP_OBSOLETE` counters.

State and persistence behavior: these tests are heavily stateful. They depend on MANIFEST level metadata, SST temperature, internal sequence numbers, `seqno_to_time_mapping` table properties, snapshots preserving obsolete versions/range tombstones, and compaction statistics accumulated in `InternalStats`. Mock time controls write-time eligibility for `preclude_last_level_data_seconds` and `preserve_internal_time_seconds`. Compaction can rewrite files to L5/L6, move files directly with `MoveFilesToLevel`, split files through partitioners, or avoid output in a level when placement would overlap unsafe ranges.

Dependencies and integration points: the file integrates with `DBTestBase`, `DBImpl` test hooks, `SyncPoint`, `MockSystemClock`, compaction internals (`Compaction`, `CompactionJobStats`, `CompactionReason`, proximal output ranges), table-property collectors (`CompactForTieringCollectorFactory`), range deletion handling, `TimedPut`, `MergeOperators::CreateStringAppendOperator`, and DB iterator properties. It is a black-box/white-box hybrid: most assertions use public DB operations and metadata APIs, but critical timing and placement are forced through internal test hooks.

Risks and edge cases covered: tests defend against data being placed in cold files while a hotter range tombstone in the proximal level would hide it, range deletion endpoints changing file ranges enough to overlap existing files, concurrent last-level-only compactions colliding with proximal-level work, periodic compaction racing with preclude placement, and migration from older preserve-time settings after enabling preclude dynamically. They also cover imprecision in sequence-to-time conversion, `TimedPut` preferred sequence numbers protected by snapshots, seqno-zeroed last-level data returning write time zero, and merged values reporting the base value's write time.

Test signals: pass/fail signals are concrete file-layout strings like `0,0,0,0,0,1,1`, SST byte totals by `Temperature`, live file metadata including `num_deletions`, `num_range_deletions`, file endpoints and levels, stats counters, exact logical reads with and without snapshots, and iterator property values decoded from `rocksdb.iterator.write-time`. Disabled range-based tiering tests document unfinished or unsafe functionality and should be read as design notes rather than active guarantees.
