# Research: sources/storage-engines/rocksdb/db/db_options_test.cc

- **Purpose:** Large dynamic-options regression suite for RocksDB DB and column-family options. It verifies immutable option rejection, mutable option parsing/serialization, runtime option propagation, option-file persistence, compaction and flush scheduling side effects, FIFO/TTL behavior, compression changes, direct-IO validation, and concurrent `SetOptions`/`SetDBOptions` races.
- **Important APIs/types/functions:** Defines `DBOptionsTest` with helpers `GetMutableDBOptionsMap()`, `GetMutableCFOptionsMap()`, randomized mutable option map builders, and static `assert_candidate_files_empty()`. It exercises `SetDBOptions`, `SetOptions`, `EnableAutoCompaction`, `GetDBOptions`, `GetOptions`, `LoadLatestOptions`, `SanitizeOptions`, `SanitizeCfOptions`, `DBImpl::TEST_ValidateOptions`, `OffpeakTimeOption`, `GetDBOptionsFromString`, `MockFileSystem`, `FaultInjectionTestFS`, `NewGenericRateLimiter`, block-based table option mutation, FIFO options, compression options, and direct I/O file options.
- **Control flow:** Early tests prove options such as `track_and_verify_wals_in_manifest`, `async_wal_precreate`, and `verify_sst_unique_id_in_manifest` become immutable after open. Mutable option tests randomize sanitized maps, set them, then compare `GetDBOptions()`/`GetOptions()` to expected string maps. IO tests set bytes-per-sync, WAL bytes-per-sync, writable file buffer sizes, background job counts, delayed write rates, max WAL sizes, stats tasks, and obsolete-file scan periods, using sync points or internal counters to confirm runtime behavior. Compaction tests enable auto compaction, change triggers, alter FIFO TTL/max-size/allow-compaction/temperature thresholds, and verify file counts and statistics.
- **State and persistence behavior:** The suite repeatedly opens, closes, destroys, and reopens DBs; creates multiple column families; writes and flushes data to form L0/L1 files; reads live manifest and options files; and uses mock time and fault-injection filesystems. `SetOptionsAndFileRace` compares in-memory CF options to loaded options from the latest options file after concurrent mutation. `SetOptionsNoManifestWrite` checks that selected option changes do not append to MANIFEST and are installed atomically under DB mutex. `AvoidFlushDuringShutdown` verifies that WAL-disabled writes are either flushed or lost depending on `avoid_flush_during_shutdown`.
- **Dependencies:** Includes internal DB/column-family headers, option helper utilities, mock env/time env, sync points, rate limiter, stats history, options util, fault injection FS, and many DBImpl test hooks. Several tests use environment support checks for compression and direct I/O and bypass or expect not-supported statuses accordingly.
- **Integration points:** This file ties option parsing metadata to live DB behavior: env thread pools, write controller stalls/delays, VersionSet manifest sizing and offpeak options, table cache capacity, periodic task scheduler, file writer range sync, compaction picker compression decisions, FIFO compaction picker, options-file persistence, and file-system direct-IO validation. It also covers multi-column-family option application through vector and map overloads.
- **Risks:** It is broad and uses many internal hooks, so failures can be caused by option metadata drift, sanitization changes, scheduling races, filesystem capabilities, or feature availability such as Snappy/LZ4/direct I/O. Concurrency tests are mini-stress tests that look for indefinite inconsistency rather than proving every interleaving. Some older assertions around immutable table factory sub-options are commented out, signaling known limitations in mutability enforcement.
- **Test signals:** Signals include OK/NOK statuses for mutable and immutable changes, exact option values after set/reopen/load, sync-point callback counts, range-sync counter reductions after increasing sync thresholds, background thread and write-controller state changes, table/cache capacities, file counts after compaction, FIFO statistics counters, validation error messages for malformed offpeak or FIFO temperature settings, absence of temp files after failed options persistence, unchanged manifest file number/size for no-manifest-write changes, and expected direct-IO validation or file-option flags.
