# sources/storage-engines/rocksdb/db/flush_job.cc

Implements RocksDB `FlushJob`, the background job that turns selected immutable memtables into a level-0 table file or, when the experimental mempurge path succeeds, into a smaller immutable memtable. It also builds the `VersionEdit` side effects needed for WAL recovery boundaries, SST metadata, blob metadata, flush statistics, event logging, UDT history cutoff advancement, and tiering metadata.

Important APIs/functions are `GetFlushReasonString()`, the constructor, `PickMemTable()`, `Run()`, `Cancel()`, `WriteLevel0Table()`, `MemPurge()`, `MemPurgeDecider()`, `GetRateLimiterPriority()`, `GetFlushJobInfo()`, `GetEffectiveCutoffUDTForPickedMemTables()`, `GetPrecludeLastLevelMinSeqno()`, and `MaybeIncreaseFullHistoryTsLowToAboveCutoffUDT()`. `PickMemTable()` must run under `db_mutex_`; it selects immutable memtables up to `max_memtable_id_`, initializes `edit_`, sets WAL log numbers, allocates a new file number/epoch, refs the base version, records input size, and precomputes UDT/tiering cutoffs.

The top-level flow is construct, `PickMemTable()`, then `Run()` or `Cancel()`. `Run()` handles empty selections, optionally captures IO/perf baselines, decides whether mempurge applies for write-buffer-full flushes, runs mempurge or writes L0, checks dropped/shutdown state, may advance `full_history_ts_low`, rolls back on failure, and installs results through `TryInstallMemtableFlushResults()` when this job owns manifest writes. `WriteLevel0Table()` releases the mutex, creates memtable and range-tombstone iterators, merges input, builds the table via `BuildTable()`, fsyncs the output directory when needed, then reacquires the mutex to add SST/blob metadata into `edit_` and record stats. `MemPurge()` releases the mutex, compacts visible payload into a new memtable with `CompactionIterator`, transfers range tombstones, aborts if it exceeds one memtable, and can reinsert the compacted memtable without scheduling another flush.

Persistent behavior is concentrated in `VersionEdit`: WAL log-number advancement, L0 file addition, blob additions/garbage, and full-history timestamp updates. `meta_` carries file bounds, sequence range, size, temperature, epoch, creation time, and blob references. Empty SSTs are not added to the manifest, but blob metadata may still be committed. Failed installs after successful table creation evict the uninstalled table from cache. External write-path blob metadata is either consumed into the edit or returned by `TakeExternal...`.

Dependencies include `ColumnFamilyData`, `MemTableList`, `VersionSet`, `VersionEdit`, `TableCache`, `BuildTable`, `CompactionIterator`, range tombstone aggregation, blob callbacks, `ErrorHandler`, `LogsWithPrepTracker`, stats/event logging, thread status, and filesystem directory sync. Atomic flush callers use `write_manifest_=false` and install combined results elsewhere.

Risks: strict mutex/ref lifecycle, experimental mempurge approximations, UDT cutoff permanence, blob/SST edit atomicity, and optional corruption checks hidden behind `flush_verify_memtable_count`. Test signals come from `flush_job_test.cc` for empty/non-empty flushes, selected memtables, atomic multi-CF install, snapshots, rate limiter priority, preferred-seqno rewrite, and UDT behavior; mempurge has sync-point coverage but not a direct test here.
