# sources/storage-engines/rocksdb/java/src/test/java/org/rocksdb/ReadOptionsTest.java

## Purpose

This JUnit suite validates the Java `ReadOptions` wrapper over RocksDB native read options. It covers constructors, copying, scalar option getters/setters, slice-backed bounds and timestamp fields, table filtering, and behavior after the native handle has been closed.

## Important APIs and types

The central type is `ReadOptions`, with `Slice`, `Snapshot`, `ReadTier`, and `AbstractTableFilter` as integration surfaces. `RocksNativeLibraryResource` loads JNI once for the class. `ExpectedException` is used for post-close assertion paths. The nested `AllTablesFilter` implements `AbstractTableFilter.filter(TableProperties)`.

## Control flow

Most tests allocate a `ReadOptions` in try-with-resources, mutate one option, then assert the getter reflects the same value. Slice options use randomly generated byte arrays and verify copied byte content for upper bound, lower bound, timestamp, and iterator start timestamp. The copy-constructor test configures multiple fields, constructs a second `ReadOptions`, and compares all copied fields.

## State and persistence behavior

The file does not persist database state. Its state concern is native handle ownership: `ReadOptions` owns JNI resources, can hold references to `Slice` or callback objects, and must reject access after close. Nullable fields are explicitly covered by setting bounds, timestamps, and snapshots back to `null`.

## Dependencies and integration points

The tests exercise JNI binding code for option conversion, native pointer lifetime, Java callback registration for table filters, and byte-array transfer through `Slice`.

## Risks and test signals

The main risks are dangling native handles, shallow-copying mutable slices, callback lifetime mistakes, and missing closed-handle assertions. Test signals are direct getter equality, byte equality for copied slices, successful table-filter registration, and `AssertionError` on uninitialized `ReadOptions` access.
