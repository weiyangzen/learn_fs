# sources/storage-engines/rocksdb/java/src/main/java/org/rocksdb/PrepopulateBlobCache.java

## Purpose
`PrepopulateBlobCache` is a Java enum mirror for the C++ `PrepopulateBlobCache` option used by RocksDB blob DB/table configuration. It controls whether blobs that are already resident in memtables should be inserted into the blob cache during flush, avoiding an immediate read-back cost after flushing, especially with direct I/O or remote filesystems.

## Important APIs, Types, And Functions
- Enum constants: `PREPOPULATE_BLOB_DISABLE` and `PREPOPULATE_BLOB_FLUSH_ONLY`.
- `getPrepopulateBlobCache(String libraryName)` maps user/library option names such as `prepopulate_blob_flush_only` to enum values and returns disable for null or unknown names.
- `getPrepopulateBlobCache(byte byteIdentifier)` maps JNI/native byte values and throws on unknown values.
- `getFromInternal(String internalName)` maps C++ options string names such as `kDisable` and `kFlushOnly`; it throws on unknown names and is package-private.
- `getValue()` and `getLibraryName()` expose the native byte value and public string name.

## Control Flow
The enum is pure Java lookup logic. String lookup iterates `values()` and compares against `libraryName_`; byte lookup compares against `value_`; internal lookup compares against `internalName_`. Invalid byte/internal inputs fail fast with `IllegalArgumentException`, while invalid public library names silently fall back to `PREPOPULATE_BLOB_DISABLE`.

## State And Persistence Behavior
State is immutable enum metadata: native byte code, external library option name, and internal C++ name. It does not own native memory and persists only as option values copied into `Options`, `ColumnFamilyOptions`, or mutable column-family option structures.

## Dependencies And Integration Points
- Used by `Options.setPrepopulateBlobCache`, `ColumnFamilyOptions.setPrepopulateBlobCache`, and `MutableColumnFamilyOptionsBuilder.setPrepopulateBlobCache`.
- `Options.prepopulateBlobCache()` and `ColumnFamilyOptions.prepopulateBlobCache()` convert byte values back through `getPrepopulateBlobCache(byte)`.
- `AbstractMutableOptions` uses `getFromInternal` when parsing options strings generated by C++.
- C++ option metadata registers `prepopulate_blob_cache` as an enum backed by the same `kDisable`/`kFlushOnly` names.

## Risks And Edge Cases
- The byte and internal-name values must stay synchronized with the C++ enum; drift would misconfigure blob cache behavior or throw while parsing C++ output.
- `getPrepopulateBlobCache(String)` masks unknown public names by returning disable, which is conservative but can hide configuration typos.
- The internal-name exception message includes an extra space before the closing quote, which is cosmetic but can make exact-message assertions brittle.

## Test Signals
- Java tests in `BlobOptionsTest`, `OptionsTest`, and `MutableColumnFamilyOptionsTest` exercise setting/getting prepopulate blob cache on options and mutable options.
- C++ options tests cover `prepopulate_blob_cache=kDisable` parsing/defaults, which indirectly guards the Java internal names when Java parses C++ option strings.
