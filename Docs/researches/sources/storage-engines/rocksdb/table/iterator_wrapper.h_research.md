# Research: sources/storage-engines/rocksdb/table/iterator_wrapper.h

- **Purpose:** Defines `IteratorWrapperBase<TValue>`, a lightweight cache around an `InternalIteratorBase` pointer that stores the latest validity, key, bound-check result, and value-prepared flag to reduce virtual calls and improve locality.
- **Important APIs/types/functions:** Constructors, `Set`, `DeleteIter`, `Valid`, `key`, `value`, `status`, `PrepareValue`, movement methods, `NextAndGetResult`, bound/pinning/readahead/sentinel/multi-scan forwarding, private `Update`, aliases `IteratorWrapper`, and arena declaration `NewEmptyInternalIterator(Arena*)`.
- **Control flow:** `Set` swaps the underlying iterator and updates cached state. Movement methods forward to the child iterator, then either use `NextAndGetResult` or call `Update` to refresh cached validity/key/bound/value-prepared state. `PrepareValue` forwards only once per movement and refreshes cached key if value preparation succeeds. `DeleteIter` deletes or manually destructs the child depending on arena mode and can enforce status-checked-after-invalid assertions under `ROCKSDB_ASSERT_STATUS_CHECKED`.
- **State and persistence behavior:** Stores a non-owning/owning-by-convention iterator pointer, cached `IterateResult`, validity flag, and optional debug status-check flag. It persists no table data and relies on the underlying iterator for cleanup registration and resource ownership.
- **Dependencies:** Depends on `InternalIteratorBase`, `IterateResult`, sync/test point infrastructure, readahead state, pinning manager, and `MultiScanArgs`.
- **Integration points:** Used by merging iterators and other iterator orchestration code to avoid repeated virtual calls to `Valid()`/`key()`. `iter_heap.h` comparators operate on `IteratorWrapper*`.
- **Risks:** Wrapper validity can become stale if the underlying iterator is mutated outside the wrapper. `DeleteIter` must be called with the correct arena flag. Many methods assert `iter_` or `Valid()`, so misuse is fatal in debug builds and undefined in release. `PrepareValue` assumes child invalidates itself and sets non-OK status on failure.
- **Test signals:** Indirectly covered by merging iterator tests, table iterator tests, and debug builds with status-check assertions. Value-preparation and upper-bound caching need dedicated iterator tests in implementations that support them.
