# Research: sources/storage-engines/rocksdb/table/external_table.cc

- **Purpose:** Adapts the public `ExternalTableFactory`, `ExternalTableReader`, `ExternalTableIterator`, and `ExternalTableBuilder` extension interfaces to RocksDB's internal `TableFactory`, `TableReader`, `InternalIterator`, and `TableBuilder` contracts.
- **Important APIs/types/functions:** `NewExternalTableFactory`; file-local adapters `ExternalTableFactoryAdapter`, `ExternalTableReaderAdapter`, `ExternalTableIteratorAdapter`, `ExternalTableBuilderAdapter`; metrics wrappers `ExternalTableMetricsFileSystem` and `ExternalTableMetricsRandomAccessFile`; helper `GetExternalTableFileReadHistogram`.
- **Control flow:** Reader creation rejects ingested files with positive sequence numbers and user-defined timestamps, optionally wraps the filesystem for statistics/listener instrumentation, then asks the inner external factory to open a reader by file name. Iterators convert internal seek targets to parsed user keys and rewrap external user keys as internal value keys with sequence zero. Point `Get` parses the internal key, calls the external reader by user key, maps NotFound to OK/no value, and saves a found value into `GetContext`. Builder creation wraps `WritableFileWriter` as an `FSWritableFile`, parses internal keys in `Add`, rejects non-value records, forwards user-key/value pairs to the external builder, collects table properties, and writes a properties block before `Finish` when supported.
- **State and persistence behavior:** The adapters hold unique ownership of external readers/builders/iterators and a writable-file wrapper. Builder state accumulates `TableProperties`, raw key/value sizes, collector outputs, file checksum information from the external builder, and status. Metrics wrappers do not persist table data but record histogram/ticker stats and notify listeners for each read.
- **Dependencies:** Depends on `rocksdb/external_table.h`, internal key parsing, listener/statistics APIs, block property parsing, property block builder, table builder/reader abstractions, `GetContext`, and `ReifyDbHostIdProperty` from `format.cc`.
- **Integration points:** Used when `NewExternalTableFactory` wraps a plugin-style external table implementation for flush, ingestion, reads, iteration, and property reporting. It bridges RocksDB's sequence-numbered internal key model to external user-key-only tables with sequence zero and value-only support.
- **Risks:** External tables do not support nonzero sequence numbers, timestamps, deletes, merges, blob indexes, or wide-column entities in this adapter. `Clone()` returns null, which can surprise code expecting cloneable factories. `GetTableProperties` falls back to minimal copied properties if raw property block retrieval fails, losing some exact metadata. Metrics `MultiRead` reports one shared start/finish timestamp for all requests. `ExternalTableBuilderAdapter::Finish` returns the external finish status but does not assign it to `status_`, so subsequent `status()` relies on the inner builder. The not-supported message for value type lacks a space before "not supported".
- **Test signals:** No direct test file is listed here. Indirect signals should come from external table factory tests, ingestion tests, table property validation, listener/statistics assertions, and DB Get/iterator behavior over externally built SSTs.
