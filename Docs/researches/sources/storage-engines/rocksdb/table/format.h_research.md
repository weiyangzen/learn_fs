# Research: sources/storage-engines/rocksdb/table/format.h

- **Purpose:** Declares core SST table-format data structures and helpers shared by RocksDB table implementations.
- **Important APIs/types/functions:** Magic constants; `ReadScopedBlockBufferProviderRef`; `ShouldReportDetailedTime`; `BlockHandle`; `EncodedBlockHandle`; `IndexValue`; `ChecksumModifierForContext`; format-version predicates; `Footer`; `FooterBuilder`; `TEST_AllowUnsupportedFormatVersion`; `ReadFooterFromFile`; checksum functions; `BlockContents`; decompression overloads; `ReifyDbHostIdProperty`.
- **Control flow:** The header codifies supported read/write format versions for block-based, plain, and cuckoo tables; whether versions use context checksums, footer index handles, and compression manager names; and how callers pass footer/read/decompression arguments. Inline constructors and helpers provide cheap block-handle initialization and context checksum modifiers.
- **State and persistence behavior:** `BlockHandle`, `IndexValue`, and `Footer` model durable on-disk metadata. `BlockContents` models in-memory block payload ownership or borrowed backing with cleanup. `FooterBuilder` owns a fixed-size serialization buffer backing the returned slice.
- **Dependencies:** Includes random-access file/prefetch/buffer-provider APIs, memory allocator support, options, cleanable, status, slice, table public types, hash helpers, and platform/malloc support.
- **Integration points:** Included by internal iterators, block readers/builders, table factories, footer readers, decompression paths, and SST property code. Its version predicates are central compatibility gates for table readers.
- **Risks:** Header-level inline predicates are compatibility-critical; changing constants can strand existing SSTs or permit unsupported writes. `Footer::GetSlice` assumes `Build` was called. `BlockContents` enforces single ownership by assert only. `ChecksumModifierForContext` intentionally returns zero when disabled, so callers must ensure nonzero base checksums for context-protected formats.
- **Test signals:** Tests should validate block handle/index value round trips, footer build/decode across versions and magic numbers, checksum behavior, decompression ownership paths, and host id reification.
