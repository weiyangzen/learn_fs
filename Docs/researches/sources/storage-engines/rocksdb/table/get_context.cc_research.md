# Research: sources/storage-engines/rocksdb/table/get_context.cc

- **Purpose:** Implements `GetContext`, the point-lookup state machine used by table readers to report found values, deletions, merge operands, blob indexes, wide-column entities, timestamps, replay logs, sequence numbers, and cache/stat counters.
- **Important APIs/types/functions:** Constructors; `appendToReplayLog`; `MarkKeyMayExist`; wide-column helpers `SaveWideColumnEntityToPinnable`, `SaveWideColumnEntityToColumns`, `PushWideColumnEntityDefaultOperand`; `SaveValue` overloads; `ReportCounters`; merge helpers `PostprocessMerge`, `MergeWithNoBaseValue`, `MergeWithPlainBaseValue`, `MergeWithWideColumnBaseValue`; `GetBlobValue`; `push_operand`; `replayGetContextLog`.
- **Control flow:** A table reader calls `SaveValue` for candidate internal keys. The parsed-key overload first checks user-key equality without timestamps and read-callback visibility, records sequence/timestamp state, logs replay entries, folds range tombstones into effective type when applicable, then switches on value type. Plain values, preferred-seqno values, blob indexes, and wide-column entities either populate `PinnableSlice`/`PinnableWideColumns`, append operands for `GetMergeOperands`, or merge with existing operands. Deletions stop lookup as deleted or trigger merge with no base. Merge records push operands and may eagerly full-merge when the merge operator says so. Blob and wide-column paths resolve external blobs when a fetcher is available and convert incomplete IO into key-may-exist state. Replay log decoding rebuilds synthetic internal keys and feeds them back through `SaveValue` until terminal.
- **State and persistence behavior:** `GetContext` mutates `state_`, optional output value/columns, timestamp, sequence, blob-index flag, value-found flag, replay log, merge context, pinned iterator manager, and per-get stats. It does not persist to disk, but replay logs can be stored in row cache and replayed into another context.
- **Dependencies:** Depends on blob fetcher/index, merge helper/operator, pinned iterators, read callbacks, wide-column serialization/helpers, perf/statistics, file-read sampling, system clock, and DB internal key/value-type helpers.
- **Integration points:** Table readers call `SaveValue` during point lookup; table cache/block cache call `MarkKeyMayExist` for no-IO uncertainty; DB Get, MultiGet, GetEntity, GetMergeOperands, row cache replay, blob DB, and wide-column APIs consume its state and outputs.
- **Risks:** Many correctness invariants are assert-only, including timestamp sizing, expected state transitions, non-null merge context for merges, and replay decode success. The simplified `SaveValue(Slice, seq)` assumes no timestamps and put-only data. Blob-backed wide columns require a blob fetcher or return corruption/incomplete. `GetBlobValue` has an explicit FIXME for untested incomplete-IO handling. Merge and timestamp behavior is subtle around range tombstones, callbacks, and `do_merge_`. Replay logs use asserts for parsing rather than returning corruption on malformed logs.
- **Test signals:** Expected signals include DB Get/MultiGet, merge-operator, blob, wide-column, timestamp, row-cache replay, and cache-stat tests elsewhere. This file exposes sync points for simple save and pin-self behavior.
