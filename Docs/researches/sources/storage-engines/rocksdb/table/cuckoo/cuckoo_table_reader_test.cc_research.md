# Research: sources/storage-engines/rocksdb/table/cuckoo/cuckoo_table_reader_test.cc

- **Purpose:** Unit and optional benchmark coverage for `CuckooTableReader` behavior against files built by `CuckooTableBuilder`.
- **Important APIs/types/functions:** Test fixture `CuckooReaderTest`; helpers `AddHashLookups`, `GetSliceHash`, `NumToStr`, `CreateCuckooFileAndCheckReader`, `UpdateKeys`, `CheckIterator`; tests `FileNotMmaped`, `WhenKeyExists`, `WhenKeyExistsWithUint64Comparator`, `CheckIterator`, `CheckIteratorUint64`, `WhenKeyNotFound`, `TestReadPerformance`; benchmark helpers `GetKeys`, `GetFileName`, `WriteFile`, `ReadKeys`.
- **Control flow:** With gflags unavailable, `main` prints a skip message. Otherwise tests build temporary cuckoo SSTs with deterministic fake hash maps, open them through `RandomAccessFileReader`, construct `CuckooTableReader`, and validate point lookup or iterator results. Found-key tests repeat normal and last-level key encodings and collision-heavy layouts. Not-found tests cover collisions, independent hashes, and the reserved empty key. Performance mode optionally writes large last-level files and times random reads with and without `Prepare` batching.
- **State and persistence behavior:** Tests create temporary SST files under per-thread DB paths or `FLAGS_file_dir`; `hash_map` is global mutable test state controlling the hash callback. Benchmark mode can persist very large files for reuse unless `--write` is set or files are missing.
- **Dependencies:** Depends on gflags, RocksDB test harness, `CuckooTableBuilder`, `CuckooTableReader`, `GetContext`, `Random`, `RandomShuffle`, bytewise and uint64 comparators, env/file writer/reader wrappers, and little-endian platform support.
- **Integration points:** Couples reader tests to builder output, table properties, internal-key encoding, and `GetContext` value pinning. It verifies reader behavior through the same `TableReader` and `InternalIterator` APIs used by production callers.
- **Risks:** The deterministic hash callback stores vector entries by `Slice::ToString()` and uses unchecked indexing, so test failures can become undefined behavior if setup drifts. Tests are skipped on big-endian platforms and entirely skipped without gflags. Optional performance test sizes are huge and should remain opt-in. The test primarily covers happy-path metadata and does not directly corrupt table properties or file bounds.
- **Test signals:** Assertions check invalid mmap status text, builder status/entry counts, reader status, returned values, empty not-found values, iterator order in both directions, seek behavior, arena allocation/destruction, and benchmark timing output.
