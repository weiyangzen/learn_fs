# sources/storage-engines/wiredtiger/src/reconcile/reconcile_inline.h

Purpose: provides small inline helpers for reconciliation cell construction, page-image copying, split accounting, time-window/stat tracking, dictionary compression replacement, obsolete time-window cleanup, and delta-key filtering. These helpers are shared by row-store, column-store, internal-page, leaf-page, and delta reconciliation code without turning them into out-of-line functions.

Important APIs and functions: `__rec_cell_addr_stats`, `__rec_delta_cell_addr_stats`, `__rec_cell_tw_stats`, and `__rec_delta_cell_tw_stats` collect time aggregate/window usage into the active `WTI_RECONCILE`. `__rec_page_time_stats`, `__rec_page_time_stats_clear`, `__rec_page_delta_stats_clear`, and `__rec_page_pfx_compression_stats_clear` publish and reset per-page statistics. `__wti_rec_need_split` decides whether the next cell crosses split/minimum boundaries, including saved-update memory pressure for row leaf pages. `__rec_incr`, `__wti_rec_kv_copy`, and `__wti_rec_image_copy` advance the disk-image buffer. `__wti_rec_cell_build_addr` packs child address cells and fast-truncate proxy metadata. `__wti_rec_cell_build_val` packs value cells or delegates oversized values to `__wti_rec_cell_build_ovfl`. `__wti_rec_dict_replace` converts repeated values to dictionary-copy cells. `__wti_rec_time_window_clear_obsolete` removes globally visible start timestamps/txn IDs before cell packing when safe. `__wti_rec_get_row_leaf_key` abstracts row key extraction, and `__rec_selected_key_changed` filters already-durable selected updates for delta construction.

Control flow: page-type reconciliation code builds `WTI_REC_KV` key/value pairs, asks whether the pending length needs a split, optionally rewrites values through dictionary compression, copies cells into the current chunk, and increments `first_free`, `entries`, `space_avail`, and minimum-boundary space through `__rec_incr`. Internal-page code builds address cells from either a fresh `WT_ADDR` or an unpacked on-disk address. Leaf-page update selection can clear obsolete time-window starts before cell construction so disk images omit unnecessary timestamp/txn payloads. Delta builders use the delta stat variants and `__rec_selected_key_changed` to avoid writing keys whose selected on-page update was already marked durable by an earlier successful reconciliation.

State and persistence behavior: these helpers do not write blocks by themselves except when `__wti_rec_cell_build_val` creates an overflow value through `__wti_rec_cell_build_ovfl`; otherwise they mutate only the active in-memory reconciliation buffers and counters. Their output controls persistent page layout: address cell type, value cell encoding, dictionary-copy offsets, time-window contents, page split points, and delta contents. Clearing obsolete time-window starts can permanently reduce future on-disk metadata for globally visible updates, except for garbage-collect ingest tables where timestamps are retained for step-up.

Dependencies and integration points: tightly coupled to `WTI_RECONCILE` and `WTI_REC_KV` from `reconcile_private.h`, WiredTiger cell packing helpers, time aggregate/window macros, btree prefix/dictionary/overflow configuration, row key extraction, collators, and page delta durability flags. `WT_REC_HAS_ON_DISK` and update-selection invariants connect it to `rec_visibility.c`-style update selection logic, while `WT_DELTA_*` callers depend on the durable/prepared durable flag checks.

Risks and sharp edges: `__rec_incr` and copy helpers assume the caller already performed correct split-boundary sizing; otherwise they can overrun the image buffer outside diagnostic builds. Dictionary replacement relies on offsets inside the current page image and avoids tiny values because copy cells could be larger than the original. Clearing time-window fields must not run for prepared updates or ingest/garbage-collect tables because those timestamps have semantic meaning. `__wti_rec_need_split` subtracts per-update overhead from saved-update memory; incorrect `supd_onpage_or_restore` accounting can skew split decisions. Delta filtering around prepared durable flags must distinguish start-prepare and stop-prepare cases to avoid dropping updates still needed after prepared rollback.

Test signals: split-boundary and image-buffer diagnostics should remain clean under large keys/values and update-heavy pages. Statistics tests can observe time-window and time-aggregate counters. Dictionary compression tests should verify repeated values and tiny values. Timestamp visibility tests should show obsolete starts being cleared only when globally visible and never for prepared/ingest cases. Disaggregated delta tests should verify already-durable updates are omitted and newly selected updates are included.
