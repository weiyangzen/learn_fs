# Research: sources/storage-engines/pebble/record/log_writer.go

- **Purpose:** Implements Pebble's asynchronous WAL-oriented record writer, with recyclable/WAL-sync chunk emission, background flushing, sync batching, optional minimum sync intervals, metrics, and failover-oriented external sync notification.
- **Important APIs/types/functions:** `LogWriter`, `LogWriterConfig`, `PendingSync`, `PendingSyncIndex`, `ExternalSyncQueueCallback`, `LogWriterMetrics`, `SyncConcurrency`, and `NoSyncIndex` are the key exported surface. Internal machinery includes `block`, `syncQueue`, `pendingSyncsWithSyncQueue`, `pendingSyncsWithHighestSyncIndex`, `flusherCond`, `NewLogWriter`, `flushLoop`, `flushPending`, `queueBlock`, `Close`, `CloseWithLastQueuedRecord`, `WriteRecord`, `SyncRecord`, `SyncRecordGeneralized`, `emitEOFTrailer`, `emitFragmentRecyclable`, and `emitFragmentSyncOffsets`.
- **Control flow:** Writers append encoded fragments into the current 32 KiB block. Full blocks are queued to a background `flushLoop`; sync requests are enqueued separately and signal the flusher. The flusher snapshots pending blocks, current partial data, and sync waiters in an order that guarantees a requested sync includes all earlier queued data. It writes blocks/data, optionally calls `Sync`, notifies waiters or external callbacks, enforces minimum sync intervals with a timer, and records metrics. `Close` emits an EOF trailer, drains the loop, syncs final data, closes the underlying writer, and returns blocks to a pool.
- **State and persistence behavior:** Persists records to the underlying writer using recyclable or WAL-sync chunk formats. WAL-sync chunks encode the last durable synced offset, enabling readers to distinguish corruption from ambiguous tail EOF. In-memory state includes active block, free/pending block lists, pending sync queue/index, sync-blocked flag, metrics, background goroutine state, accumulated errors, and pooled block buffers.
- **Dependencies:** Depends on `record.go` constants and CRC format, `base` metrics, `crtime`, `errors`, `prometheus`, `pprof`, `sync/atomic`, and writer interfaces `io.Writer`, `io.Closer`, and `Sync() error`.
- **Integration points:** Used by Pebble WAL writing and commit pipeline paths. The external sync callback path integrates with WAL failover, while the wait-group queue path supports standalone WAL sync notifications. `record.Reader` consumes the emitted recyclable and WAL-sync chunks.
- **Risks:** Concurrency ordering is subtle: sync waiters must not be popped before their data is flushed, queue slots must not be reused before semaphores release, and min-sync blocking must not deadlock close. `WriteWALSyncOffsets` is consulted only during construction, despite the config comment about runtime ratcheting, so format changes after construction require careful higher-level handling. EOF trailer emission assumes sufficient room for the recyclable header. Errors propagate asynchronously and may lag writes until the next queue/close boundary.
- **Test signals:** `log_writer_test.go` covers sync queue concurrency, lost wakeup prevention in `flusherCond`, sync error propagation, sync-position guarantees, min-sync interval blocking and close release, metrics, pending block backlog, highest-index callbacks, generalized sync/close errors, WAL-sync offset monotonicity, and allocation/queue benchmarks.
