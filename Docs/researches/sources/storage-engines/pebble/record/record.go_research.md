# Research: sources/storage-engines/pebble/record/record.go

- **Purpose:** Defines Pebble's block/chunk record stream format and implements synchronous `Reader`/`Writer` support for legacy, recyclable, and WAL-sync chunk encodings.
- **Important APIs/types/functions:** Public surface includes `Reader`, `Writer`, `NewReader`, `NewWriter`, `Reader.Next`, `Reader.Offset`, `Writer.Next`, `Writer.WriteRecord`, `Writer.Flush`, `Writer.Close`, `Writer.Size`, `Writer.LastRecordOffset`, `IsInvalidRecord`, and errors `ErrNotAnIOSeeker`, `ErrNoLastRecord`, `ErrZeroedChunk`, `ErrInvalidChunk`, and `ErrUnexpectedEOF`. Internal core includes chunk/wire-format constants, `headerFormatMappings`, `Reader.nextChunk`, `Reader.readAheadForCorruption`, `Reader.seekRecord`, `singleReader.Read`, `Writer.fillHeader`, `Writer.writeBlock`, `Writer.writePending`, and `singleWriter.Write`.
- **Control flow:** The reader scans 32 KiB blocks, validates chunk headers, log numbers, lengths, and CRCs, stitches full/first/middle/last chunks into logical records, and skips to first chunks when needed. On invalid or zeroed chunks, it reads ahead for WAL-sync offsets proving that the invalid offset should have been durable; absent proof, it reports `ErrUnexpectedEOF`. The writer buffers chunks into 32 KiB blocks, fills headers when records end or blocks fill, zero-fills unusable block tails, and flushes/close-finalizes records.
- **State and persistence behavior:** This file defines durable wire formats. Legacy chunks store CRC/size/type, recyclable chunks add a log number for file reuse, and WAL-sync chunks add a synced-offset watermark for corruption disambiguation. Reader state tracks block number, buffer bounds, current record sequence, last-chunk status, accumulated error, and first invalid offset. Writer state tracks buffered ranges, block number, base offset, last record offset, current sequence, pending chunk status, and accumulated error.
- **Dependencies:** Depends on `encoding/binary`, `io`, `math`, `errors`, `base`, `bitflip`, and `crc`. `LogWriter` shares constants and header mappings.
- **Integration points:** Used for MANIFEST records, WAL records, replay/recovery readers, and general record-stream utilities. `recovery.go` relies on `record.IsInvalidRecord` and `ErrUnexpectedEOF` semantics to decide whether log tails are tolerable or corrupt.
- **Risks:** Header parsing is security/corruption sensitive. Off-by-one block-boundary errors can corrupt streams or hide records. WAL recycling depends on low 32-bit log numbers and EOF trailers. Read-ahead must avoid falsely converting ambiguous unclean tails into corruption while still detecting durable corruption when later WAL-sync offsets prove it.
- **Test signals:** `record_test.go` covers round trips through both `Writer` and `LogWriter`, boundary sizes, flush behavior, stale readers, offsets/seeking, corrupt blocks, recyclable log reuse, truncation, log-number mismatch, partial records, WAL-sync datadriven cases, and write benchmarks.
