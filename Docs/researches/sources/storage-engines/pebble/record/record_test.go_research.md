# Research: sources/storage-engines/pebble/record/record_test.go

- **Purpose:** Exercises the record stream reader/writer wire format, including ordinary records, block boundaries, flushing, offsets, seeking, recyclable logs, truncation, and WAL-sync corruption disambiguation.
- **Important APIs/types/functions:** Helpers include `short`, `big`, `recordWriter`, `testGeneratorWriter`, `testGenerator`, `testLiterals`, `testRecords`, `makeTestRecords`, `corruptBlock`, `readerLogger`, `parseRawChunk`, and `describeWALSyncBlocks`. Tests include `TestMany`, `TestRandom`, `TestBasic`, `TestBoundary`, `TestFlush`, `TestNonExhaustiveRead`, `TestStaleReader`, `TestBasicReads`, `TestCorruptBlock`, `TestReaderOffset`, `TestSeekRecordInvalidChunk`, `TestSeekRecordEndOfFile`, `TestLastRecordOffset`, `TestNoLastRecordOffset`, `TestInvalidLogNum`, `TestSize`, `TestRecycleLog`, `TestTruncatedLog`, `TestRecycleLogWithPartialBlock`, `TestRecycleLogNumberOverflow`, `TestRecycleLogWithPartialRecord`, and `TestWALSync`.
- **Control flow:** The generator tests write sequences through both synchronous `Writer` and asynchronous `LogWriter`, then read them back with `Reader`. Boundary tests sweep sizes around `blockSize`. Corruption tests mutate checksums or raw chunks and assert the reader's error classification. Datadriven WAL-sync tests build raw chunk layouts, read them, and optionally describe block/chunk structure.
- **State and persistence behavior:** Uses byte buffers as serialized log files. Tests inspect durable offsets returned by `LastRecordOffset`, `Offset`, and seek behavior, and simulate recycled/preallocated file contents by reusing backing byte slices across log numbers.
- **Dependencies:** Depends on `datadriven`, `require`, `base`, `binfmt`, `crc`, `treeprinter`, `errors`, `math/rand/v2`, and standard IO/binary helpers.
- **Integration points:** Protects the record format consumed by MANIFEST, WAL, recovery, and replay. Tests for `LogWriter` compatibility ensure the asynchronous WAL writer emits streams the synchronous reader can consume.
- **Risks:** The tests intentionally mirror chunk constants and can require updates when the wire format evolves. Some randomized tests use time-derived seeds for recycling cases, which improves coverage but can complicate reproduction if a failure is not logged with enough context.
- **Test signals:** Expected failures include wrong record payloads, incorrect EOF/error classification, stale reader contract breaks, offset mismatches, inability to tolerate recyclable tail bytes, and WAL-sync read-ahead logs differing from datadriven expectations. `BenchmarkRecordWrite` tracks write throughput across payload sizes.
