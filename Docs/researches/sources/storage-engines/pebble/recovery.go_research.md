# Research: sources/storage-engines/pebble/recovery.go

- **Purpose:** Recovers Pebble database state at open time by reading directory metadata, format markers, OPTIONS, manifests, object storage state, WALs, and replaying unflushed WAL records into flushables.
- **Important APIs/types/functions:** `recoverState` and `(*recoveredState).init` discover and validate on-disk state. `recoveredState` stores directories, format marker, manifest marker/number, max file number, obsolete temp/WAL files, object provider, previous options file, recovered version, and WAL sets. `RemoveObsolete` cleans marker leftovers, temp files, and obsolete WAL segments. `checkForLegacyFormatVersion1` rejects old `CURRENT`-based stores. `recoveredVersion` and `recoverVersion` replay MANIFEST records. `DB.replayWAL` replays logical WAL records. `DB.replayIngestedFlushable` reconstructs flushable ingests and excises from WAL batches.
- **Control flow:** Recovery locks directories, lists files, finds format/version markers, opens object storage, locates and replays the current manifest, validates consistency, reads previous OPTIONS for compatibility and WAL failover identity, computes max used file number, scans WAL directories, and partitions WALs into obsolete vs replay-needed. WAL replay reads record batches, tolerates only allowed tail EOF cases, rejects corruption, applies normal batches into memtables, converts large batches to flushable batches, and converts ingest/excise entries to flushable ingests followed by WAL rotation.
- **State and persistence behavior:** `recoverState` is read-only except for opened locks/providers; `RemoveObsolete` later deletes obsolete marker/temp/WAL artifacts. `recoverVersion` reconstructs persisted LSM metadata including virtual backings, blob files, L0 organization, next file number, min unflushed WAL, and next sequence number. `replayWAL` mutates in-memory memtable/flushable queues and, in non-read-only mode, forces replayed memtables to flush for durability.
- **Dependencies:** Depends on batch representation, arena skiplist errors, base, invariants, keyspan, manifest, object storage/provider, record, vfs/atomicfs, WAL scanning/logical logs, ingest loading, options parsing, and DB internals.
- **Integration points:** Invoked during DB open before normal operation. It integrates record-layer tail/corruption semantics with Pebble's durability model, manifest version state, WAL failover directories, object providers, ingested sstables/blob files, and obsolete-file cleanup.
- **Risks:** Recovery is high-stakes: misclassifying WAL tails can lose acknowledged writes or reject healthy stores. File-number ratcheting must avoid collisions with obsolete/ingested objects. Replay of ingests depends on referenced table/blob files still existing. Lock ordering matters because `replayWAL` may drop/reacquire `DB.mu`. Legacy format and option compatibility checks must prevent accidental overwrite or unsafe open.
- **Test signals:** Coverage is distributed across Pebble open/recovery, WAL, ingest, excise, corruption, and format-version tests. Record-layer tests supply important signals for `record.IsInvalidRecord` and `ErrUnexpectedEOF` behavior used here.
