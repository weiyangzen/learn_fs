# Research: sources/storage-engines/pebble/range_keys.go

- **Purpose:** Implements Pebble iterator support for range keys, including construction of the range-key iterator stack, suffix-based range-key masking of point keys, block-property-filter acceleration for masking, and lazy activation of combined point/range iteration.
- **Important APIs/types/functions:** `Iterator.constructRangeKeyIter` wires batch, memtable, L0 sublevel, and lower-level range-key iterators into `keyspan` iterator configuration. `containsAnyRangeKeys` checks L0 sublevels before allocating range-key level iterators. `rangeKeyMasking` implements `keyspan.SpanMask` and `sstable.BoundLimitedBlockPropertyFilter` through `SpanChanged`, `SkipPoint`, `Intersects`, `SyntheticSuffixIntersects`, `KeyIsWithinLowerBound`, and `KeyIsWithinUpperBound`. `lazyCombinedIter`, `combinedIterState`, and `combinedIterState.Trigger` implement on-demand switching from point-only iteration to `keyspan.InterleavingIter`.
- **Control flow:** Iterators normally start point-only. Lower-level iterators may trigger `combinedIterState` when a file containing range keys is observed. `lazyCombinedIter.initCombinedIteration` selects a seek key, allocates `iteratorRangeKeyState`, calls `constructRangeKeyIter`, initializes `InterleavingIter`, and forwards future operations to the combined iterator. Range-key masking is updated on every covering span transition; then point keys are skipped if their suffix is hidden by the active masking suffix.
- **State and persistence behavior:** The file itself persists nothing, but reads persistent range-key metadata from manifests, memtables, batches, and sstables. It mutates iterator-local state: active mask span/suffix, stale range-key flags, stats counters, current iterator implementation, and debug logging wrappers. It respects read-state versions and memtable sequence visibility.
- **Dependencies:** Internal packages include `base`, `invariants`, `keyspan`, `manifest`, and `treesteps`; public integration includes `sstable.BoundLimitedBlockPropertyFilter`. It depends on `Iterator` fields, `IterOptions.RangeKeyMasking`, batch indexes, memtable range-key iterators, L0 sublevels, and manifest range-key level metadata.
- **Integration points:** Used by user-facing `Iterator` operations whenever range keys may be visible, particularly MVCC-style range-key masking. The block-property-filter hooks integrate with sstable block skipping, and lazy switching keeps ordinary point scans cheaper until a range-key file is encountered.
- **Risks:** Correctness is sensitive to suffix comparator semantics, inclusive/exclusive bound handling for block skipping, stable lifetime of triggered file-bound keys, and the seek-key adjustment when range keys may exist before the first surfaced point key. Masking comments and implementation must stay aligned: the implementation skips point keys whose suffix sorts after the selected active range-key suffix. Bugs can manifest as hidden visible points, leaked deleted MVCC versions, or skipped blocks outside the masking span.
- **Test signals:** Direct tests live outside this file. Repository signals include `iterator_test.go` randomized range-key masking, `data_test.go` checks for lazy combined iteration initialization, external iterator and ingest/excise tests configuring `RangeKeyMasking`, and compaction test coverage over range-key behavior.
