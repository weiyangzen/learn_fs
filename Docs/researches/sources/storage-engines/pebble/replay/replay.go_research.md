# Research: sources/storage-engines/pebble/replay/replay.go

- **Purpose:** Implements compaction workload replay: reconstructs flush/ingest/excise steps from captured manifests and sstables, applies them to a test Pebble DB, paces application, waits for compactions to quiesce, and reports benchmark-style metrics.
- **Important APIs/types/functions:** Public types include `Pacer`, `Unpaced`, `PaceByReferenceReadAmp`, `PaceByFixedReadAmp`, `Metrics`, `Plot`, and `Runner`. Key functions/methods include `computeReadAmp`, `waitForReadAmpLE`, `Metrics.Plots`, `Metrics.WriteBenchmarkString`, `Runner.Run`, `refreshMetrics`, `compactionsAppearQuiesced`, `nextCompactionOrFlushCompletes`, `Wait`, `Close`, `eventListener`, `applyWorkloadSteps`, `prepareWorkloadSteps`, `findWorkloadFiles`, `findManifestStart`, `blobFileMap.Lookup`, and `loadFlushedSSTableKeys`.
- **Control flow:** `Run` discovers workload files, finds the manifest start relative to the run DB, opens a staging dir and DB with WAL disabled, installs event listeners, and starts goroutines for preparation, application, and metrics refresh. Preparation reads manifest edits, classifies edits as flush/ingest/compaction/ingest-and-excise, applies version edits to track metadata/read amp, reconstructs flush batches by reading captured sstables, or stages ingested files. Application paces each step, commits flush batches plus `AsyncFlush`, calls `Ingest` or `IngestAndExcise`, and reports progress. Metrics refresh samples DB metrics after workload steps and compaction/flush completions until workload exhaustion and quiescence.
- **State and persistence behavior:** Replays into `RunDir`, creates a staging directory, copies workload sstables for ingest, opens captured sstables/blob files read-only, and writes a new Pebble DB without WAL. In-memory state tracks manifest offsets, workload file sets, metrics samples, write-stall counters, compaction/flush counters, channels, cancellation, and final metrics.
- **Dependencies:** Depends on Pebble public APIs, internal `base`, `manifest`, `rangedel`, `rangekey`, byte allocator, record reader, sstable/blob readers, vfs, errgroup, and benchfmt.
- **Integration points:** Used by benchmarking tooling to evaluate compaction heuristics against captured production-like workloads. It bridges manifest replay, sstable readers, Pebble batch/ingest APIs, event listeners, metrics, and benchstat-compatible output.
- **Risks:** Workload fidelity depends on correctly classifying version edits and reconstructing flushed keys in sequence-number order. Missing captured sstables/blob files abort replay. Quiescence detection is deliberately subtle and event-driven; errors in started/completed accounting can stop too early or hang. `MaxWriteBytes` uses cumulative bytes and may cut after crossing the threshold. Range tombstone/key reconstruction assumes decoded spans contain one key for range-key operations.
- **Test signals:** This file has no adjacent test in the listed set. Indirect signals come from replay tool tests, manifest/record/sstable/rangekey/rangedel tests, and benchmark output sanity. Runtime failures surface as missing workload files, decode errors, Pebble event background errors, or non-quiescing compactions.
