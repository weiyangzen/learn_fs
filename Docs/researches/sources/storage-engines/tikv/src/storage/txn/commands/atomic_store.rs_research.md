# sources/storage-engines/tikv/src/storage/txn/commands/atomic_store.rs

## Purpose
Implements `RawAtomicStore`, a raw-KV write command that atomically applies a prepared set of `Modify` operations. It is used by raw atomic APIs and can cooperate with API V2 timestamped raw keys.

## Important APIs, Types, and Functions
`RawAtomicStore` is generated by `command!` with fields `cf` and `mutations`, returning unit. `CommandExt` supplies the `raw_atomic_store` metric tag, latch generation over mutation keys, and byte accounting via `Modify::size`. `process_write` produces a `WriteResult` containing the mutations.

## Control Flow
The command ignores the snapshot because it only applies caller-supplied mutations. If `WriteContext.raw_ext` exists, it appends the raw timestamp to every `Modify::Put` key in place. It then wraps all mutations in `WriteData`, allows writes on disk-almost-full, and returns `ProcessResult::Res`.

## State and Persistence
All provided mutations are persisted as-is except for timestamp suffixing on puts under raw API V2. Delete mutations are not timestamp-appended here. The command returns raw `key_guard`s from `raw_ext`, preserving scheduler-level key protection until apply completes. Response policy is `OnApplied`.

## Dependencies and Integration Points
Depends on `engine_traits::CfName`, `kv::Modify`, `WriteData`, raw scheduler `RawExt`, and the command dispatcher in `mod.rs`. It is tested with `scheduler::get_raw_ext`, showing integration with causal timestamp providers for API V2.

## Risks and Test Signals
Risks include inconsistent timestamp treatment between puts and deletes and incorrect latch coverage if `Modify::key` semantics change. Tests verify timestamp appending, encoded raw values, and API V2 key guard propagation.
