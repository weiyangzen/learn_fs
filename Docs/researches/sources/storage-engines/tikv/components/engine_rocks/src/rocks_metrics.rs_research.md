# sources/storage-engines/tikv/components/engine_rocks/src/rocks_metrics.rs

## Purpose
`rocks_metrics.rs` maps RocksDB and Titan statistics into TiKV Prometheus metrics. It covers three metric families: ticker counters, histogram snapshots, and DB/CF property gauges. It also updates process-wide Titan compression estimation state that other `engine_rocks` code uses when estimating blob raw sizes.

## Important APIs, Types, and Functions
`flush_engine_ticker_metrics(TickerType, u64, &str)` dispatches RocksDB ticker deltas into static metric label enums. `flush_engine_histogram_metrics(HistType, HistogramData, &str)` exports median, p95, p99, average, standard deviation, and max values as gauge labels. `flush_engine_statistics(&RocksStatistics, name, is_titan)` drains configured ticker counters, reads histograms, handles Titan-only metric sets, and refreshes `TITAN_COMPRESSION_FACTOR` plus `TITAN_MAX_BLOB_SIZE_SEEN`.

`RocksStatisticsReporter` implements `engine_traits::StatisticsReporter<RocksEngine>`. It collects per-CF `CfStats`, per-level `CfLevelStats`, and DB-wide `DbStats`, then flushes gauges such as size, memory, estimated keys, pending compaction, files per level, compression ratio, live/obsolete Titan blobs, snapshot age, cache usage, write-stall reasons, running compactions, and flushes.

The large `lazy_static!` blocks register Prometheus `IntGaugeVec`, `GaugeVec`, `IntCounterVec`, `HistogramVec`, and auto-flush static metric wrappers. Label enums are generated by `make_auto_flush_static_metric!`.

## Control Flow
Ticker flushing first validates `name` as either `kv` or `raft`, then matches each RocksDB `TickerType` to the correct counter vector and label. Unknown or intentionally ignored tickers fall through. Histogram flushing similarly matches `HistType` values and uses the `engine_histogram_metrics!` macro to set six summary gauges per RocksDB histogram.

`RocksStatisticsReporter::collect` walks `db.cf_names()`, resolves CF handles, accumulates RocksDB property integers, parses CF stats maps for write-stall reasons, sizes level arrays from CF options, and reads level file counts/compression ratios/blob file counts. It also reads DB-level running compaction/flush counts, snapshot counts and oldest snapshot duration, and shared block/blob cache usage from the default CF. `flush` writes any populated option fields to Prometheus and leaves missing properties untouched.

`flush_engine_statistics` drains standard ticker counts with `get_and_reset_ticker_count`, reads standard histograms, then optionally handles Titan. Titan compression estimation uses `TitanValueSize.average * TitanBlobFileNumKeysWritten` as estimated raw size divided by compressed bytes, clamps the factor, smooths it, stores it atomically as `f64::to_bits`, updates a gauge, and records max blob size seen.

## State and Persistence Behavior
This module does not persist storage data, but it mutates global metrics and Titan estimation atomics. Ticker counters are reset when flushed; histogram gauges are snapshots. `RocksStatisticsReporter` accumulates statistics across `collect` calls until `flush`; it does not clear itself afterward. Oldest snapshot duration uses the maximum observed age, while many CF properties are summed when multiple `collect` calls occur before flushing.

## Dependencies and Integration Points
It depends on `rocks_metrics_defs.rs` for property names and metric type lists, `RocksStatistics` wrappers around RocksDB statistics, `engine_traits::StatisticsReporter`, RocksDB ticker/histogram enums, Prometheus/static-metric macros, and utility property helpers in `util.rs`. Event listeners and background components can use registered metric vectors directly.

## Risks and Edge Cases
`flush_engine_ticker_metrics` panics for unexpected DB names, so callers must use the established `kv`/`raft` labels. New RocksDB or Titan ticker/histogram variants require updates in both `rocks_metrics_defs.rs` and the dispatch matches; otherwise they are silently ignored. Property availability varies by RocksDB/Titan version, so most fields are optional, but some utility helpers still expect core properties to exist. Compression ratio averaging is weighted by file count and skipped for empty levels.

`RocksStatisticsReporter` accumulates values rather than replacing them, so reuse semantics matter: repeated `collect` before `flush` is aggregation, not refresh. The Titan compression estimator depends on histogram average and ticker counts matching the same collection window.

## Test Signals
`test_flush` opens a Rocks engine over all CFs, exercises every configured standard ticker and histogram, and runs reporter collect/flush. Additional useful tests would cover Titan-enabled paths, unknown DB names, multiple collect cycles, missing properties, and newly added RocksDB statistics variants.
