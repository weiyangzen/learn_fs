# sources/storage-engines/tikv/components/tidb_query_expr/src/impl_compare.rs

Purpose: Implements TiDB/TiKV RPN scalar comparison and extremum builtins: typed relational operators, null-safe equality, `COALESCE`, `GREATEST`, `LEAST`, and `INTERVAL` variants for numeric, string, temporal, JSON, vector, and duration-like values. The file is a central adapter between `tipb::ScalarFuncSig` mappings generated by `#[rpn_fn]` and the concrete comparison semantics supplied by `tidb_query_datatype`.

Important APIs, types, and functions: `compare<C: Comparer>` dispatches ordinary typed comparisons through `Comparer`; `compare_json`, `compare_vector_float32`, and `compare_bytes<C, F>` handle JSON/vector natural ordering and collation-aware byte ordering. `Comparer` abstracts nullable binary comparison over one `EvaluableRet` type. Implementations are `BasicComparer<T, F>` for normal `Ord` types, `UintUintComparer<F>`, `UintIntComparer<F>`, and `IntUintComparer<F>` for MySQL signed/unsigned integer edge cases. `CmpOp` turns `Ordering` into SQL boolean results and provides null behavior; implementations cover `<`, `<=`, `>`, `>=`, `!=`, `=`, and `<=>` via `CmpOpNullEq`. `coalesce`, `coalesce_bytes`, and `coalesce_json` return the first non-null argument, cloning owned representations for varlen types. `greatest_*`, `least_*`, `interval_int`, `interval_real`, and string-as-time/date variants implement MySQL scalar functions. `do_get_extremum` is the generic helper shared by most `GREATEST`/`LEAST` overloads.

Control flow: Nullable binary comparison functions first partition `(None, None)`, partial null, and non-null cases, then delegate either to native `Ord`, collation sort comparison, or explicit signed/unsigned logic. The unsigned comparers avoid interpreting wrapped `u64` values as regular signed integers: `UintIntComparer` treats unsigned values above `i64::MAX` or negative signed RHS as greater; `IntUintComparer` mirrors that for signed LHS. `coalesce*` scans varargs left to right and returns immediately on the first `Some`. `do_get_extremum` requires all arguments non-null; the first `None` returns `None`, otherwise it keeps a borrowed best candidate and returns an owned clone. `INTERVAL` treats null target as `-1`, then binary-searches the remaining sorted arguments and returns MySQL's insertion-position convention. The string-as-time/date variants parse every byte argument as UTF-8 and then as MySQL `Time`; parse or encoding errors are routed through `EvalContext::handle_invalid_time_error`.

State and persistence: The functions are stateless per call. The only mutable state is warning/error policy in `EvalContext` for invalid time/date parsing; no persistent data is written. Results are owned scalar values or writer-backed byte buffers generated by the RPN framework. `#[rpn_fn(nullable, varg)]` and `capture = [ctx]` control generated evaluator state and argument materialization.

Dependencies and integration points: Depends on `tidb_query_codegen::rpn_fn`, `tidb_query_common::Result`, `tidb_query_datatype::codec::data_type::*`, collation `Collator`, JSON/vector ordering, MySQL `Time`, and `EvalContext`. It integrates with scalar-function mapping through generated RPN metadata and with TiDB field-type flags for integer signedness through tests and mapper specialization elsewhere in the module.

Risks and edge cases: Signed/unsigned integer comparison is sensitive because unsigned constants may be carried as negative `i64` bit patterns; using `BasicComparer<Int, _>` in these paths would be wrong. `interval_*` assumes the search list is sorted according to Rust ordering and does not sort or validate it. `greatest_real`/`least_real` rely on `Real` construction/order semantics; NaN inputs can result in `None` because `Real::new(NaN)` fails in tests. String-as-time/date variants return `None` on invalid UTF-8 or invalid temporal strings depending on context SQL mode, so warning handling must stay aligned with TiDB/MySQL. `greatest_string` and `least_string` use raw byte ordering through `Ord` rather than explicit collation, so callers must route collation-sensitive comparisons elsewhere.

Test signals: Unit tests cover all comparison operators over real, duration, decimal, signed integers, and signed/unsigned integer matrices; string comparison across binary, UTF8MB4 bin/no-padding/general/unicode/0900 collations; `COALESCE`; `GREATEST`/`LEAST` for int, real, string, time/date/duration; `INTERVAL`; and string-as-time/date parsing including invalid UTF-8 and invalid temporal values. The tests exercise both ordinary null propagation and `<=>` null-safe equality.
