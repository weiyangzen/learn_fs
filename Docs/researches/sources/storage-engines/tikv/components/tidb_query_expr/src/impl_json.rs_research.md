# sources/storage-engines/tikv/components/tidb_query_expr/src/impl_json.rs

Purpose: Implements a broad set of MySQL/TiDB JSON scalar functions for the RPN evaluator: inspection (`JSON_DEPTH`, `JSON_TYPE`, `JSON_VALID`, `JSON_LENGTH`, `JSON_KEYS`), construction (`JSON_ARRAY`, `JSON_OBJECT`, `JSON_QUOTE`), modification (`JSON_SET`, `JSON_INSERT`, `JSON_REPLACE`, `JSON_ARRAY_APPEND`, `JSON_REMOVE`), extraction (`JSON_EXTRACT`, `JSON_UNQUOTE`), containment/membership (`JSON_CONTAINS`, `MEMBER OF`), and merge operations (`JSON_MERGE`, `JSON_MERGE_PATCH`).

Important APIs, types, and functions: `json_depth` and `json_type` call methods on `JsonRef`. `json_set`, `json_insert`, and `json_replace` share `json_modify(args, ModifyType)`. `json_array_append` appends values into extracted path targets and writes back with `ModifyType::Set`. `json_modify_validator`, `json_object_validator`, `json_with_paths_validator`, `json_with_path_validator`, `json_contains_validator`, and `member_of_validator` enforce raw-vararg type contracts. `json_array` converts SQL null arguments into JSON null. `json_object` builds a `BTreeMap<String, Json>`, rejects null keys, and validates UTF-8 keys. `json_merge` delegates to `Json::merge`; `json_merge_patch` implements RFC 7396-style merge-patch sequencing. `json_quote`, `quote`, `json_unquote`, and `unquote_string` handle JSON string quoting/unquoting. `parse_json_path_list` and `parse_json_path` convert byte path arguments to `PathExpression`.

Control flow: Most nullable raw-vararg functions first validate minimum/maximum arity through `#[rpn_fn]` and explicit `assert!`, then unpack `ScalarValueRef` by expected type. Path-based functions parse every supplied path; a null path short-circuits to `None` through `try_opt!`. Modification functions clone the base JSON, build path/value arrays, and call JSON library methods. `json_array_append` differs by returning null when the base SQL value is null, then for each path extracts the current element, merges/appends the new value, and writes it back only when the path exists. `json_valid` handles both typed JSON and bytes: JSON input is valid when present; byte input is parsed with `serde_json`; other types return 0, null input returns null. `json_contains` optionally extracts a path and rejects wildcard paths by returning null before calling `json_contains`. `json_merge_patch` scans from the right for the last non-object or null input; if that element is null it returns null, otherwise it starts merging from that point to implement MySQL/RFC behavior where later non-object values dominate earlier inputs.

State and persistence: The file is stateless beyond temporary owned JSON clones and path vectors. There is no persistent metadata. Writer-backed functions (`json_type`, `json_quote`) produce byte output through `BytesWriter`. Validators run at expression construction time and prevent runtime type ambiguity for raw varargs.

Dependencies and integration points: Uses `tidb_query_codegen::rpn_fn`, `tidb_query_datatype::codec::mysql::json::*` for `Json`, `JsonRef`, `JsonType`, `ModifyType`, `PathExpression`, parse/merge/extract/contains operations, `serde_json` for validation/unquote syntax checks, and `json_unquote` crate helper for string unescaping. It integrates with `super::function::validate_expr_return_type` and generated scalar signatures for one-arg and two-arg variants such as `JsonKeysSig`/`JsonKeys2ArgsSig`.

Risks and edge cases: Raw vararg functions depend heavily on validators matching exact call shapes; incorrect scalar signature mapping can panic on `assert!` or misborrow values. Several functions distinguish SQL null from JSON null, especially `json_array`, `json_object`, `json_merge`, `json_merge_patch`, and `json_array_append`; regressions here are easy. Path wildcard handling is function-specific: `json_contains` returns null for wildcard paths, while `json_keys` tests expect errors for wildcard paths through JSON library behavior. `json_object` uses `BTreeMap`, so duplicate keys are overwritten and output order is sorted by key, not insertion. `json_unquote` first validates fully quoted strings with `serde_json::IgnoredAny`; invalid quoted JSON strings error, while unquoted strings pass through. The file clones JSON values frequently, so large documents may have allocation costs.

Test signals: Tests cover JSON depth/type, set/insert/replace modification, arrays/objects including null keys and arity errors, merge and merge-patch examples from RFC 7396 and MySQL behavior, quote/unquote escaping and invalid quoted strings, extract/remove/length/valid, contains with and without paths including null and wildcard behavior, keys with path and wildcard errors, member-of semantics, and extensive array-append cases from TiDB/MySQL examples.
