# sources/storage-engines/tikv/components/tidb_query_expr/src/impl_like.rs

Purpose: Implements the SQL `LIKE` predicate for byte-string inputs in the RPN evaluator, with pluggable collation comparison and charset decoding. It supports `%`, `_`, and caller-provided escape characters while preserving MySQL/TiDB behavior across binary and UTF8MB4 collations.

Important APIs, types, and functions: The single exported `like<C: Collator, CS: Charset>(target, pattern, escape)` function is annotated with `#[rpn_fn]` and returns `Option<i64>` as SQL boolean. It uses `CS::decode_one` to advance pattern and target by characters or bytes according to the selected charset and `C::sort_compare(..., true)` to compare one decoded target unit against one decoded pattern unit under the selected collation.

Control flow: The matcher keeps pattern and target offsets (`px`, `tx`) plus backtracking offsets after the most recent `%` (`next_px`, `next_tx`). It decodes the next pattern unit. `_` consumes one target unit if available. `%` advances the pattern, records a backtracking point, and immediately succeeds if it is the final pattern token. For ordinary characters, the code honors escape when the current pattern unit equals the escape code and another pattern unit follows, then compares the current target unit to the current pattern unit via collation. On mismatch, if a previous `%` exists, it advances `next_tx` by one decoded target unit, restores `px` to the token after `%`, and retries. Without a valid backtrack point it returns false. If both pattern and target are exhausted, it returns true.

State and persistence: The algorithm is entirely local to one call. It maintains only offsets and has no external state or metadata. The returned value is always `Some(0)` or `Some(1)` because the function is not annotated nullable; null propagation is handled by generated RPN wrappers/signature selection.

Dependencies and integration points: Depends on `tidb_query_datatype::codec::collation::{Collator, Charset}` and scalar data types. The function is selected by scalar signature `LikeSig`, with the code generator specializing `C` and `CS` from return and argument field collations/charsets. Tests show integration with `FieldTypeBuilder` collation assignment for return, target, and pattern fields.

Risks and edge cases: Correctness depends on matching the intended charset decoder to the pushed-down collation metadata. In binary charset, `_` can match one byte rather than one Unicode scalar, which is expected for binary but surprising for wide characters. Escape handling treats escape as a Unicode code point cast from `i64`; multibyte escape characters work only when decoded consistently by `CS`. The backtracking algorithm is simple and may revisit many positions for patterns with repeated `%` and late mismatches, so worst-case matching can be costly on long strings. `C::sort_compare` errors are treated as ordinary comparison non-match because only `Ok(Equal)` advances.

Test signals: Tests cover exact, prefix, suffix, infix, repeated `%`, `_`, trailing escape-like patterns, custom escape characters, pathological repeated wildcard mismatch, case-sensitive and case-insensitive collations, accent/case behavior, wide characters, emoji, binary-vs-UTF8 charset differences, and scenarios where TiDB does not push new collation metadata and binary comparison must still decode with argument charsets.
