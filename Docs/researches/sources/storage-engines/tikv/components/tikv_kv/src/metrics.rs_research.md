# sources/storage-engines/tikv/components/tikv_kv/src/metrics.rs

Purpose: declares static Prometheus label enums and a local auto-flush counter vector for garbage-collection key operation statistics.

Important APIs: `GcKeyMode` has `txn` and `raw`; `GcKeysCF` has `default`, `lock`, and `write`; `GcKeysDetail` mirrors per-CF scan counters such as processed keys, get/next/prev/seek operations, tombstone counts, raw value tombstones, and missing-range counters. `GcKeysCounterVec` is a `LocalIntCounter` metric with labels `key_mode`, `cf`, and `tag`.

Control flow: there is no runtime logic in this file. The `make_auto_flush_static_metric!` macro generates strongly typed label accessors and auto-flushing local metric wrappers.

State and persistence: metric state is maintained by Prometheus local counters generated by the macro and flushed to the global registry through the metric infrastructure, not by this source file directly.

Dependencies and integration: depends on `prometheus_static_metric`. `stats.rs` uses the generated `GcKeysCF` and `GcKeysDetail` enums to map `CfStatistics` fields into stable metric labels. GC code can use `GcKeysCounterVec` to emit low-overhead per-thread counters.

Risks: enum label names must stay synchronized with `stats.rs` detail arrays and dashboards; changing a label is an observability compatibility break. The broad `txn` mode intentionally combines TiDB and TxnKV because their storage format and GC procedure match.

Test signals: no local tests; compile-time macro expansion and users in `stats.rs` are the main checks.
