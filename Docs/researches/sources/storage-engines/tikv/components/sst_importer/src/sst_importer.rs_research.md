# sources/storage-engines/tikv/components/sst_importer/src/sst_importer.rs

## Purpose
Implements TiKV's `SstImporter`, the component that stages externally supplied SST and KV/log-backup files, verifies and rewrites their key ranges, caches or persists downloaded files, creates import writers, and hands validated SSTs to the engine for ingestion. It is the bridge between backup/restore or import clients, external storage backends, TiKV local import directories, RocksDB SST readers/writers, key rewriting rules, encryption-at-rest metadata, and import-mode switching.

## Important APIs, Types, And Functions
`SstImporter<E: KvEngine>` owns the import directory, optional `DataKeyManager`, import-mode switcher, API version, per-CF compression overrides, cached external storage factories, a small download runtime, `file_locks`, memory quota, and multi-master-key backend. `LoadedFile`, `DownloadExt`, `DownloadFilesExtResult`, and `CacheKvFile` model cached KV file contents, request modifiers, multi-file download return metadata, and duplicate-work/file-cache state. Lifecycle and directory APIs include `new`, `create`, `delete`, `remove_dir`, `validate`, `check_api_version`, `ingest`, `verify_checksum`, `exist`, `list_ssts`, `get_path`, and `get_total_size`. Download APIs include `download_ext`, `download_files_ext_with_ssts`, `download_files_ext_with_latest_mvcc`, `download_kv_file`, `download_kv_file_to_mem_cache`, and `download_kv_file_to_disk`. Rewrite/apply APIs include `rewrite_kv_file`, `do_apply_kv_file`, `do_pre_rewrite`, `do_rewrite_keys`, and `do_rewrite_keys_txn_write_default_merged`. Writer factories are `new_txn_writer` and `new_raw_writer`. Helper functions handle bounds, checksum extraction, keyspace rewriting scratch buffers, local encryption wrapping, external storage cache creation, cleanup, memory quota updates, and cache shrinking.

## Control Flow
Construction chooses import-mode switcher v1 or v2, creates a one-thread Tokio runtime for background download/cache work, starts storage-cache GC, computes a memory quota from system memory and config ratio, and opens an `ImportDir`. Simple SST upload/import flows create an `ImportFile`, append client bytes elsewhere, validate metadata/checksum/API version through `ImportDir`, then ingest into the engine with the configured key manager. Single-SST `download_ext` delegates to `do_download_ext`, which uses a `DashMap` plus `OnceCell` to collapse duplicate downloads for the same temp path, downloads from external storage, verifies the SST checksum, decides whether a direct temp-to-save rename is legal, or iterates and writes a rewritten SST. Multi-SST `download_files_ext_with_ssts` downloads each source SST to temp files, opens readers, builds a `BinaryIterator`, computes pre-rewrite bounds, and writes one merged destination SST through `do_rewrite_keys`. `download_files_ext_with_latest_mvcc` separates write and default CF readers, merges write CF with `BinaryIterator`, exact-seeks default CF values with `DefaultSeekIterator`, and emits write and optional default SST metadata for the latest applicable MVCC records.

KV/log-backup file flow first updates master-key backends, extracts per-file encryption info, and chooses memory or disk based on `download_to_disk_only`. Memory mode allocates quota, reads/decrypts/decompresses/checksums external bytes into a `LoadedFile`, and shares it by `Arc<[u8]>`. Disk mode downloads to a temp path, verifies checksums through `RestoreConfig`, then renames with the key manager when local encryption is enabled; later reads decrypt from disk before returning plaintext bytes. Applying KV files runs a stream event iterator with prefix rewriting, filters by timestamp and region key range, invokes a caller-provided builder for accepted events, and returns the actual written key span.

## State And Persistence Behavior
Durable state is kept in the import directory as temp/save/clone files managed by `ImportDir` and `ImportFile`; successful downloads either rename temp files to save paths or write new SSTs directly to save paths, and ingestion moves validated SSTs into the engine. Local encryption state is persisted alongside local files through `DataKeyManager`, with explicit metadata link/rename/delete paths during direct moves and cleanup. `file_locks` is transient in-memory coordination for memory buffers, disk cache paths, in-progress SST rewrite state, and raw downloads. `MemoryQuota` retains in-memory KV buffers while references exist; `shrink_by_tick` removes expired unreferenced memory buffers after about 60 seconds and disk cache files after about 10 minutes. External storage instances may be cached by `cache_id`, while empty cache keys bypass the cache. Import-mode state is delegated to either global v1 `ImportModeSwitcher` or range-aware v2 `ImportModeSwitcherV2`.

## Dependencies And Integration Points
The file integrates `engine_traits` SST reader/writer/iterator abstractions with `engine_rocks` readers and envs, `external_storage` restore/read/checksum/compression/encryption wrappers, TiKV key encoding and `txn_types` MVCC write parsing, `kvproto` import/backup/encryption messages, `ImportDir` and `ImportFile`, raw and txn SST writers, importer metrics, failpoints, and config management. It depends on `sst_merge_iter::{BinaryIterator, DefaultSeekIterator}` for multi-SST merge and write/default reconciliation. The async download path uses Tokio, `RescheduleChecker`, speed limiters, and cached storage factories. Security-sensitive integration points are local encryption-at-rest, backup file encryption using plaintext data keys or master-key-based data keys, external storage credentials/config, and path validation in `remove_dir`.

## Risks And Edge Cases
The direct-rename fast path is only correct when no prefix rewrite, timestamp rewrite, or timestamp filtering is requested and the source SST's actual key bounds are contained in the requested range. Bound handling must account for unbounded, inclusive, exclusive, keyspace-encoded, RawKV, and MVCC timestamp-encoded keys. Wrong-prefix checks intentionally fail restore early when a rewrite rule does not match source keys. Merged latest-MVCC download only accepts keyspace requests and rejects timestamp rewrite; long `Put` records must have a matching default CF value, while `Lock` and `Rollback` are skipped. Empty-value records from compact-log-backup are treated as delete markers by the merge iterator and can suppress entire duplicate key groups. Duplicate download locks prevent redundant work but rely on matching metadata and request kind; mismatches return internal errors. Disk cleanup must remove both filesystem files and key-manager metadata. `remove_dir` rejects absolute paths, `..`, root-equivalent prefixes, and symlink escapes to avoid deleting outside the import root and to avoid leaking canonical server paths in errors.

## Test Signals
The in-file tests cover import directory/file create, delete, ingest, and encryption metadata; external storage reads, timeouts, checksum mismatch, and backend config use; memory quota updates, cache hits/expiry, disk-only mode, and `DashMap` lock behavior; SST download with no rewrite, prefix rewrite, partial ranges, invalid files, empty output, wrong prefixes, RawKV API versions, exclusive end keys, compression settings, and ingest-after-download; timestamp rewrite and timestamp filtering for default and write CF SSTs; KV/log-backup download with no encryption, plaintext data key encryption, master-key-based encryption, compression, memory and disk modes, and local encryption-at-rest; duplicate external storage initialization under failpoints; multi-SST batch download, encrypted batch download, cleanup on injected error, empty source sets, overlap deduplication, merge order, empty-file-equivalent filtering, RawKV batch variants, and latest-MVCC write/default merge including short values, missing default errors, delete-marker skipping, and default output omission. Dedicated tests also validate `remove_dir` path traversal and Unix symlink escape rejection.
