# sources/storage-engines/tikv/components/sst_importer/src/sst_merge_iter.rs

## Purpose
Provides lightweight iterator adapters used by the SST importer when combining multiple downloaded RocksDB SST files. `BinaryIterator` performs sorted multi-way merge with duplicate-key and delete-marker handling. `DefaultSeekIterator` performs ordered exact lookups over multiple default-CF SST iterators for write/default MVCC reconciliation.

## Important APIs, Types, And Functions
`DefaultSeekIterator<'a>` stores `Vec<RocksSstIterator<'a>>`, per-iterator initialization and validity flags, and the currently matched iterator index. Its public API is `new`, `seek_exact`, `key`, and `value`; `advance_iter_to` advances an iterator by a bounded number of `next` calls before falling back to `seek`. `DEFAULT_SEEK_NEXT_LIMIT` is 32. `BinaryIterator<'a>` stores SST iterators and a binary min-heap of iterator indices in `entry_cache`. It implements heap helpers `iter_key`, `sift_up`, `sift_down`, `push`, `pop`, `heap`, `peek`, and merge helpers `advance_current_key`, `current_key_has_empty_value`, and `skip_empty_value_keys`. It implements the `engine_traits::Iterator` trait for forward-only `seek`, `seek_to_first`, `next`, `key`, `value`, and `valid`; reverse methods are intentionally unimplemented.

## Control Flow
`DefaultSeekIterator::seek_exact` clears the prior match, walks each SST iterator, advances it to at least the requested key, and returns the first iterator whose current key exactly equals the request. The optimization assumes caller keys are requested in non-decreasing order; already-positioned iterators can usually advance with up to 32 `next` calls before a full seek. `BinaryIterator::seek` and `seek_to_first` position every child iterator and heapify the valid ones. The heap top is the current smallest key. `next` calls `advance_current_key`, which pops one iterator, advances and reinserts all entries for the duplicate current key group, then skips any group containing an empty value. The empty-value skip models compact-log-backup physical delete records: if any duplicate entry for a key has an empty value, the entire key group is removed from output.

## State And Persistence Behavior
Both adapters are purely in-memory wrappers over existing `RocksSstIterator` instances and do not own files or persist state. Their mutable state is iterator position plus heap or match bookkeeping. `BinaryIterator` exposes a single sorted, deduplicated forward stream, and `DefaultSeekIterator` preserves child iterator progress across exact seeks for efficient monotonic probes.

## Dependencies And Integration Points
The file depends only on `engine_rocks::RocksSstIterator` and the `engine_traits::Iterator` trait in production code. `sst_importer.rs` uses `BinaryIterator` for merging same-CF batches before rewrite and for write-CF traversal in latest-MVCC merge, and uses `DefaultSeekIterator` to find default-CF values corresponding to write records whose `short_value` is absent. Tests integrate with `RocksSstReader`, SST writer builders, `TestEngineBuilder`, TiKV key encoding, and `txn_types::TimeStamp`.

## Risks And Edge Cases
`DefaultSeekIterator` does not validate monotonic requests; a backward seek can return false negatives because exhausted or advanced child iterators are not reset. `key` and `value` unwrap the matched index, so callers must only use them after a successful `seek_exact`. `BinaryIterator` is forward-only; accidental calls to reverse methods panic through `unimplemented!`. Duplicate keys have deterministic enough but semantically shallow tie-breaking: only one value per key group survives unless an empty value causes the group to be skipped. Heap invariants depend on all child iterators remaining valid for indices present in `entry_cache`. Empty SSTs and iterators exhausted by range seeks are skipped.

## Test Signals
`test_binary_iterator` writes five overlapping write-CF SSTs and verifies the merged stream is strictly increasing and contains exactly the unique key count. `test_binary_iterator_skips_empty_value_key_groups` verifies groups containing empty values are skipped both from the beginning and after a seek. `test_default_seek_iterator_seek_exact` verifies exact hits across two default-CF SSTs, a missing timestamp for an existing user key, and subsequent monotonic hits. The importer tests add integration coverage for multi-SST deduplication, merge ordering, empty-file-equivalent filtering, latest-MVCC write/default merge, missing default values, and empty-value delete-marker handling.
