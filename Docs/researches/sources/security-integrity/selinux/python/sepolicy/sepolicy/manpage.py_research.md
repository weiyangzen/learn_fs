# sources/security-integrity/selinux/python/sepolicy/sepolicy/manpage.py

Purpose: generates SELinux manual pages and optional HTML indexes for policy domains and roles. It exports `ManPage`, `HTMLManPages`, and `gen_domains`, with supporting caches for users, type attributes, entrypoints, module descriptions, and generated date metadata from `SOURCE_DATE_EPOCH`.

Important APIs and control flow: `gen_modules_dict()` parses `policy.xml` summaries through `sepolicy.policy_xml`; `get_all_users_info()`, `get_entrypoints()`, `gen_domains()`, and `_gen_types()` cache expensive policy queries. `HTMLManPages` converts generated roff pages to HTML via `/usr/bin/groff`, writes an index grouped by first letter, and emits a CSS file. `ManPage.__init__()` loads ports, domains, attributes, booleans, file contexts, roles, and users, then dispatches to either user/role or process-domain manpage generation. Domain pages compose headers, entrypoints, process types, booleans, NSSWITCH notes, port types, managed writes, file contexts, public-content guidance, and footers. User pages cover login mapping, sudo/newrole/role transitions, X login, network ability, home execution, booleans, MCS constraints, ports, writes, and transitions.

State and persistence: the module uses global in-process caches (`modules_dict`, `users`, `users_range`, `all_entrypoints`, `domains`, `types`) and writes `.8`, alias `.so`, `.html`, `index.html`, and `style.css` files under the requested output path. It reads live policy state, file-context databases, and `/usr/share/selinux/devel/policy.xml` unless source-file mode points it at a supplied root.

Dependencies and integration points: depends on `selinux`, `sepolicy`, `xml.etree.ElementTree`, `groff`, policy XML, generated file context dictionaries, SELinux boolean/role/type/allow-rule APIs, and `sepolicy.network.get_network_connect()` for user network sections. It is exercised through the `sepolicy manpage` CLI and packaging installs it as part of the `sepolicy` Python package.

Risks and test signals: many broad `except:` blocks hide parse and policy lookup failures, so missing policy data may silently produce incomplete manpages. Output text is generated by string interpolation from policy names and paths; malformed policy data could affect roff/HTML output. The code assumes several sepolicy records exist (`entry_type`, type info for domains) and may raise if policy databases are partial. Tests in `test_sepolicy.py` only check CLI success for `sepolicy manpage -d httpd_t` and `-a`, not content correctness, alias pages, HTML conversion, or source-file mode.
