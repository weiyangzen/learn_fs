# sources/sync-backup/borg/docs/usage/key_export.rst.inc

Purpose: Documents `borg key export`, which backs up the Borg key for encrypted or authenticated repositories. This is safety-critical recovery documentation.

Important APIs/types/functions: CLI contract is `borg [common options] key export [options] [PATH]`. It exposes optional `PATH`, `--paper`, and `--qr-html`; the normal output is a digital key backup, while paper and QR HTML formats are recovery-oriented encodings.

Control flow: The generated page describes choosing an export format, writing to a path or standard output depending on command implementation, and preserving passphrase encryption on the exported key. It is produced from Borg's parser and epilog.

State and persistence: Reads key material from local keyfile or repository key storage and writes an exported backup. It does not persist the passphrase and does not decrypt the key for storage.

Dependencies and integration points: Integrates with `key import`, `repo-create` key-location guidance, and authenticated/encrypted repository modes. The QR mode likely depends at runtime on Borg's QR/paper export implementation, while this file only documents it.

Risks: Lost exported keys can expose encrypted key material to offline passphrase attack; missing exported keys can lock users out after key corruption. The text correctly states both key and passphrase are needed for recovery.

Test signals: Docs should be regenerated by `build_usage`. Behavioral coverage should check all three formats, passphrase preservation, import round trips, and paper line checksums.
