# sources/sync-backup/borg/docs/usage/key_change-location.rst.inc

Purpose: Auto-generated Borg CLI usage documentation for `borg key change-location`, which moves an existing repository key between `keyfile` storage and `repokey` storage. The document is a Sphinx/reStructuredText include, not executable command logic.

Important APIs/types/functions: The exposed contract is the CLI shape `borg [common options] key change-location [options] KEY_LOCATION`, with positional `KEY_LOCATION` and option `--keep`. It relies on `:ref:`common_options`` and standard Sphinx `only:: html` / `only:: latex` variants generated by `scripts/make.py` from the `Archiver` parser.

Control flow: At documentation-build time, `BuildUsage.generate_level` emits the command anchor, synopsis, HTML option table, LaTeX option list, and epilog text. At user-runtime level, the described operation selects a destination key location and either removes the old location or preserves it when `--keep` is set.

State and persistence: The command mutates key storage location, either local Borg keys directory/key file state or repository config/key state. It explicitly does not alter crypto algorithms or secret key material.

Dependencies and integration points: Integrates with Borg's key management subcommands, the repository/keyfile encryption modes described by `repo-create`, and the generated docs pipeline. The page depends on Sphinx references resolving `common_options`.

Risks: Misstating the accepted values would be dangerous because users might think this changes encryption strength; the text correctly warns that only location changes. Operational risk is losing or duplicating key material depending on `--keep`.

Test signals: Regenerate with `python scripts/make.py build_usage` and compare the include. Functional tests should exercise changing between `keyfile` and `repokey`, with and without `--keep`, and verify the old/new key locations and repository unlock behavior.
