# sources/sync-backup/borg/docs/usage/repo-list.rst.inc

Purpose: Documents `borg repo-list`, which lists archives in a repository with filtering, formatting, JSON output, and optional inclusion of soft-deleted archives.

Important APIs/types/functions: CLI contract is `borg [common options] repo-list [options]`. Key options are `--short`, `--format FORMAT`, `--json`, archive filters, sort/first/last/time filters, and `--deleted`. Format keys include archive/name, comment, id, tags, time/start/end, command line, hostname, username, size, and file count.

Control flow: Runtime reads manifest archive metadata, applies filters and sorting, slices with first/last/time selectors, optionally restricts to soft-deleted archives, and renders text or JSON.

State and persistence: Read-only over repository metadata. It observes soft-delete state generated by prune/delete and consumed by undelete/compact workflows.

Dependencies and integration points: Shared archive filter semantics are used by prune, mount, tag, transfer, undelete, and recreate. Format syntax mirrors Python format strings and overlaps with `list`.

Risks: Automation may rely on exact JSON keys or format fields. Time filtering depends on archive timestamps and local interpretation described elsewhere.

Test signals: Cover filtering combinations, sorting keys, `--deleted`, JSON schema, custom formats, tag matching, empty repositories, and archives with comments/tags/metadata.
