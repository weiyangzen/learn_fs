# sources/sync-backup/syncthing/lib/protocol/mocks/connection_info.go

## Purpose
Generated external-package fake for `protocol.ConnectionInfo`, used by tests outside the protocol package to supply connection metadata without importing internal test-only mocks.

## Important APIs, Types, and Functions
`ConnectionInfo` exposes fake methods for `Type`, `Transport`, `IsLocal`, `RemoteAddr`, `Priority`, `String`, `Crypto`, `EstablishedAt`, and `ConnectionID`, plus `...CallCount`, `...Calls`, `...Returns`, `...ReturnsOnCall`, `Invocations`, and `recordInvocation`. It ends with `var _ protocol.ConnectionInfo = new(ConnectionInfo)`.

## Control Flow
Each metadata method records the call under a mutex, records a shared invocation entry, then delegates to an optional stub, per-call return, or default return. Helper methods mutate or inspect the fake's method-specific state under locks.

## State and Persistence Behavior
State is limited to in-memory call history, stubs, and return values. No network, file, or persistent state is touched. The invocations map is rebuilt from method call slices when requested so assertions can inspect aggregate use.

## Dependencies and Integration Points
Depends on `net`, `sync`, `time`, and the protocol package. It is generated by the `go:generate` declarations in `protocol.go`, and external tests can import `lib/protocol/mocks` without creating a package cycle.

## Risks and Edge Cases
Zero-value returns can represent a disconnected or unknown connection unless tests configure them. Like all generated mocks, it must be regenerated after interface changes. Concurrent tests should avoid mutating stubs while the fake is being called.

## Test Signals
Compile-time interface satisfaction is the direct signal. Behavioral confidence comes from tests that configure returns and assert call counts or invocation maps.
