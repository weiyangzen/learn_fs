# sources/sync-backup/syncthing/gui/default/assets/lang/lang-ja.json

Purpose: provides Japanese translations for Syncthing's default AngularJS web GUI. It is a generated static locale table loaded as `assets/lang/lang-ja.json` for locale key `ja`, covering many core navigation labels, device/folder operations, connection status labels, authentication text, versioning text, warning dialogs, and localized theme names.

Important APIs/types/functions: the file is a JSON dictionary consumed by angular-translate rather than code with functions. Translation IDs are English GUI strings and values are Japanese strings. The object has 457 top-level keys and 460 flattened leaves, including nested `theme.name.black`, `theme.name.dark`, `theme.name.default`, and `theme.name.light`. It has 16 interpolation-bearing keys, all preserving placeholder names in Angular form, such as `{{name}}`, `{{label}}`, `{{count}}`, `{{file}}`, `{{device}}`, `{{address}}`, `{{path}}`, `{{receiveEncrypted}}`, `{{version}}`, `{{otherFolder}}`, `{{otherFolderLabel}}`, `{{syncthingInotify}}`, `{{folder}}`, and `{{folderlabel}}`.

Control flow: `syncthing/app.js` installs the static-file translation loader with `assets/lang/lang-` plus `.json`, then uses English as fallback. `LocaleService.autoConfigLocale()` chooses a language from a `lang` query parameter, saved `SYN_LANG`, or browser locales fetched from `/rest/svc/lang`. `ja` appears in `valid-langs.js` and `prettyprint.js` as `Japanese`, so it is a first-class selectable locale. Once `$translate.use('ja')` completes, the HTML root `lang` attribute is set and Angular translates directive/filter lookups from this table, falling back to English for missing entries.

State and persistence behavior: the JSON file contains no mutable runtime state and performs no persistence. The user's language selection can persist in localStorage under `SYN_LANG`; otherwise locale selection is transient. The file is generated from Weblate according to `assets/lang/README.txt`, so local manual edits are fragile and should flow through translation tooling.

Dependencies and integration points: integrated with `valid-langs.js`, `prettyprint.js`, AngularJS, `pascalprecht.translate`, `ngSanitize`, and the Syncthing REST locale endpoint. It also integrates indirectly with `script/translate.go`, which extracts English translation IDs from HTML/JS/theme sources, and `script/weblatedl.go`, which downloads Weblate translation JSON and regenerates language availability metadata.

Risks: coverage is partial: 101 English keys are missing, including several advanced settings and newer features such as block indexing, folder/device group text, debug/logging labels, some watcher and ignore-list actions, crash/reporting and network details, and receive-encrypted explanatory strings. These gaps do not break rendering because English fallback is configured, but they create mixed-language UI and can hide untranslated feature surfaces from review. Seven values equal their English keys (`GUI`, `LDAP`, `OK`, `QUIC LAN`, `QUIC WAN`, `TCP LAN`, `TCP WAN`), mostly protocol/product labels. Placeholder risk is low in the inspected table because all 16 placeholder-bearing translations match expected variable names.

Test signals: JSON parsing succeeds with `jq`. Structural comparison against `lang-en.json` reports 457 top-level keys, 101 missing English keys, zero extra keys, no empty values, and zero placeholder mismatches. UI checks should select `?lang=ja`, walk the settings and advanced dialogs where fallback is likely, and exercise pending device/folder notifications, delete/restore confirmation dialogs, path-warning dialogs, and update buttons to verify interpolation and Japanese line wrapping.
