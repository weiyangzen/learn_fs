# sources/sync-backup/syncthing/gui/default/assets/lang/lang-hi.json

Purpose: Hindi translation catalog for the Syncthing default AngularJS GUI. It maps English translation IDs, mostly literal UI text, to Hindi strings loaded at runtime when the active locale is `hi`.

Important APIs/types/functions: the file is a JSON object consumed by `angular-translate` through `$translateProvider.useStaticFilesLoader({ prefix: 'assets/lang/lang-', suffix: '.json' })` in `gui/default/syncthing/app.js`. It is advertised by `assets/lang/valid-langs.js`, labelled by `prettyprint.js`, and regenerated from Weblate by `script/weblatedl.go`; the English source catalog is regenerated by `script/translate.go` through the `translate` build target.

Data shape and notable entries: the catalog has 546 top-level entries: 545 string translations and one nested `theme.name` object with names for `black`, `dark`, `default`, and `light`. English keys are the stable lookup IDs for `translate` attributes, `| translate` filters, and `$translate.instant(...)` calls. Placeholder-bearing keys use Syncthing's source convention `{%name%}` while translated values use Angular interpolation such as `{{name}}`; the checked placeholder variable sets match for every string entry.

Control flow: during GUI startup, Angular initializes translation services, fetches `assets/lang/lang-hi.json` for Hindi, registers the table, and resolves translation IDs from templates and JavaScript. When an ID is absent from this file, the configured fallback language `en` supplies the English value. Interpolated values are then escaped by the configured `escape` sanitization strategy before rendering.

State/persistence behavior: this file is static client-side state embedded in the GUI asset tree. It does not persist runtime user data; locale choice is handled by the GUI locale service and browser/application settings outside this JSON. Translation edits are intended to come from Weblate and generated pulls, not manual modification in this directory.

Dependencies/integration points: depends on valid JSON syntax, AngularJS, `angular-translate`, the static files loader, `valid-langs.js`, `prettyprint.js`, and the GUI templates/controllers that use English text as translation IDs. It also integrates with the theme selector because `theme.name.*` is a nested namespace rather than a normal English phrase key.

Risks: compared with `lang-en.json` this catalog is missing 12 current keys: `Always turned on when the folder type is "{%foldertype%}".`, `Block Indexing`, `Cannot be enabled when the folder type is "{%foldertype%}".`, `Debug`, `Device Group`, `Folder Group`, `Info`, `Limit Bandwidth in LAN`, `Maintain an index of all blocks in the folder, enabling reuse of blocks from other files when syncing changes. Disable to reduce database size at the cost of not being able to reuse blocks across files.`, `Optional group for the device. Can be different on each device.`, `Optional group for the folder. Can be different on each device.`, and `Starting`. Those labels fall back to English in Hindi sessions. Additional risks are stale product/security wording, oversized translations disrupting fixed UI controls, and accidental conversion of nested `theme` data to a flat string.

Test signals: parse with `jq`, compare keys against `lang-en.json`, verify all placeholder variable names in keys are present in values, and run Syncthing's GUI translation generation path (`go run ../../../../script/translate.go lang-en.json ../../../` from `gui/default/assets/lang`) when source templates change. Browser smoke tests should switch to Hindi and check settings, folder edit, device edit, status, and theme selector surfaces.
