# sources/sync-backup/syncthing/gui/default/assets/lang/lang-ko-KR.json

Purpose: provides Korean translations for Syncthing's default AngularJS web GUI. It is a generated static locale table loaded as `assets/lang/lang-ko-KR.json`, localizing the main GUI, device/folder workflows, connection and discovery text, encryption/password warnings, versioning, rate-limit labels, ignore-pattern text, log/debug text, and theme names.

Important APIs/types/functions: this is a JSON translation table for angular-translate, not executable code. Keys are English translation IDs and values are Korean translations. The table has 556 top-level keys and 559 flattened leaves, almost matching the 558-key English baseline. It contains nested `theme.name.black`, `theme.name.dark`, `theme.name.default`, and `theme.name.light`. It has 25 interpolation-bearing entries, and all inspected placeholder names are preserved in the translated values: examples include `{{foldertype}}`, `{{name}}`, `{{label}}`, `{{count}}`, `{{file}}`, `{{device}}`, `{{address}}`, `{{path}}`, `{{receiveEncrypted}}`, `{{url}}`, `{{devicename}}`, `{{version}}`, `{{otherFolder}}`, `{{otherFolderLabel}}`, `{{syncthingInotify}}`, `{{folder}}`, `{{folderlabel}}`, and `{{reintroducer}}`.

Control flow: the Syncthing Angular app configures angular-translate with static file prefix `assets/lang/lang-` and suffix `.json`, then sets `en` as fallback. `LocaleService.autoConfigLocale()` can select `ko-KR` from an explicit URL parameter, from saved localStorage, or by matching browser locales returned by `/rest/svc/lang` against `validLangs`. `ko-KR` is advertised in `valid-langs.js` and named `Korean` in `prettyprint.js`. After `$translate.use('ko-KR')` loads the table, the HTML `lang` attribute is updated and normal directive/filter translation lookups read this JSON object.

State and persistence behavior: this file has no internal state. Browser persistence is handled outside the file through `SYN_LANG` in localStorage when the selected language should be saved. The file is generated from Weblate and should be treated as build/source data; manual local edits are likely to be overwritten by translation update automation.

Dependencies and integration points: depends on angular-translate's JSON loader, the AngularJS GUI, `ngSanitize` escape strategy, `LocaleService`, `/rest/svc/lang`, `valid-langs.js`, and `prettyprint.js`. Translation maintenance depends on `script/translate.go` for finding English source IDs and `script/weblatedl.go` for pulling Weblate outputs and rebuilding `valid-langs.js`.

Risks: coverage risk is low but not zero. Only 2 English keys are missing: the block-indexing explanatory sentence and `Starting`. Those specific strings will fall back to English in Korean UI. Seven values equal their English keys (`GUI`, `LDAP`, `QUIC LAN`, `QUIC WAN`, `TCP LAN`, `TCP WAN`, `The Syncthing Authors`), which are mostly brand/protocol labels. Placeholder integrity is strong in this snapshot, with zero mismatches, but future Weblate updates should continue checking variable names because missing or renamed interpolation variables can produce literal placeholders or incomplete warnings in security-sensitive dialogs.

Test signals: `jq` parses the file as an object. Comparison against `lang-en.json` found 556 top-level keys, 2 missing English keys, zero extra keys, no empty values, and zero placeholder mismatches. High-value UI tests are `?lang=ko-KR`, advanced folder settings around block indexing and receive-encrypted folders, pending share notifications, device connection prompts, restore/delete confirmations, theme selector display, and compact table columns where Korean strings may wrap differently from English.
