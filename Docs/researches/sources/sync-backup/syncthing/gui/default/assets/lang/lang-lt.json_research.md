# sources/sync-backup/syncthing/gui/default/assets/lang/lang-lt.json

Purpose: provides Lithuanian translations for Syncthing's default AngularJS web GUI. It is a generated static locale table loaded as `assets/lang/lang-lt.json` for locale key `lt`, covering common actions, device and folder configuration, connection/discovery text, security and encryption warnings, versioning text, error/status messages, network labels, and theme names.

Important APIs/types/functions: the file is an angular-translate JSON dictionary; it exports no functions or classes. Keys are English translation IDs and values are Lithuanian translations. The inspected object has 504 top-level keys and 507 flattened leaves. It includes the nested `theme.name.black`, `theme.name.dark`, `theme.name.default`, and `theme.name.light` object. There are 22 interpolation-bearing entries, all preserving expected variable names in values: `{{foldertype}}`, `{{name}}`, `{{label}}`, `{{count}}`, `{{file}}`, `{{device}}`, `{{address}}`, `{{path}}`, `{{receiveEncrypted}}`, `{{url}}`, `{{devicename}}`, `{{version}}`, `{{otherFolder}}`, `{{otherFolderLabel}}`, `{{syncthingInotify}}`, `{{folder}}`, and `{{folderlabel}}`.

Control flow: `app.js` configures the static loader to request `assets/lang/lang-lt.json` when `$translate.use('lt')` is selected, with English fallback. `LocaleService.autoConfigLocale()` can choose `lt` from `?lang=lt`, saved `SYN_LANG`, or a browser-locale match from `/rest/svc/lang`. `lt` appears in `valid-langs.js` and is displayed as `Lithuanian` by `prettyprint.js`, so normal selection and discovery paths reach it. Angular translate directives and filters then resolve GUI text from this object, falling back to English for absent keys.

State and persistence behavior: the JSON table is static data and does not mutate application state. Locale choice may be persisted by `LocaleService.useLocale(language, true)` in localStorage under `SYN_LANG`, and the active HTML language attribute is set externally after successful load. The file is generated from Weblate, so it should be updated through translation automation rather than edited directly.

Dependencies and integration points: relies on valid JSON, angular-translate static loading, AngularJS, `ngSanitize`, `LocaleService`, `/rest/svc/lang`, `valid-langs.js`, and `prettyprint.js`. It is maintained by the same extraction/download path as other GUI locales: `script/translate.go` finds source strings and `script/weblatedl.go` writes `lang-*.json` plus language metadata.

Risks: there are 54 missing English keys, including newer or advanced surfaces such as block indexing, device/folder group text, ownership and extended-attribute explanations, some ignore-rule hints, size-limit strings, status/log-in notices, and WAN/LAN bandwidth text. One value is empty: `GUI / API HTTPS Certificate`, which may render as blank instead of falling back if angular-translate treats the key as present. One value equals its English key (`LDAP`). Placeholder integrity is good in this snapshot with zero mismatches, but the empty string is a concrete runtime quality risk.

Test signals: `jq` parses the file successfully. Structural checks found 504 top-level keys, 54 missing English keys, zero extra keys, one empty value (`GUI / API HTTPS Certificate`), and zero placeholder mismatches. UI tests should load `?lang=lt`, inspect GUI/API TLS certificate settings for blank labels, exercise advanced folder/device dialogs where missing keys fallback to English, and test interpolation-heavy share, path-warning, restore, and upgrade dialogs.
